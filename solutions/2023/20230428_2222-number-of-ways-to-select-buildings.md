# #2222. 选择建筑的方式数 / Number of Ways to Select Buildings

> 难度：中等 · 标签：String、Dynamic Programming、Prefix Sum · [LeetCode 链接](https://leetcode.com/problems/number-of-ways-to-select-buildings/)

---

## 题目（英文原版）

**Description**

You are given a 0-indexed binary string s which represents the types of buildings along a street where:
As a city official, you would like to select 3 buildings for random inspection. However, to ensure variety, no two consecutive buildings out of the selected buildings can be of the same type.
Return the number of valid ways to select 3 buildings.

**Examples**

**Example 1:**

```
Input: s = "001101"
Output: 6
Explanation: 
The following sets of indices selected are valid:
- [0,2,4] from "001101" forms "010"
- [0,3,4] from "001101" forms "010"
- [1,2,4] from "001101" forms "010"
- [1,3,4] from "001101" forms "010"
- [2,4,5] from "001101" forms "101"
- [3,4,5] from "001101" forms "101"
No other selection is valid. Thus, there are 6 total ways.
```

**Example 2:**

```
Input: s = "11100"
Output: 0
Explanation: It can be shown that there are no valid selections.
```

**Constraints**

- 3 <= s.length <= 105
- s[i] is either '0' or '1'.

## 题目（中文翻译）

你得到一个 **0 索引（0-indexed）** 的二进制字符串（binary string）`s`，它表示街道上建筑的类型，其中字符 `'0'` 和 `'1'` 分别对应两种建筑类型。  
作为城市官员，你需要随机挑选 **3** 栋建筑进行检查。但为了保证多样性，所选的 3 栋建筑中**任意相邻的两栋建筑类型不能相同**。  

返回满足条件的挑选方式的数量。

**示例 1**  
Input: `s = "001101"`  
Output: `6`  
Explanation:  
以下下标组合是合法的：  
- `[0,2,4]` 对应的子串为 `"010"`  
- `[0,3,4]` 对应的子串为 `"010"`  
- `[1,2,4]` 对应的子串为 `"010"`  
- `[1,3,4]` 对应的子串为 `"010"`  
- `[2,4,5]` 对应的子串为 `"101"`  
- `[3,4,5]` 对应的子串为 `"101"`  

除此之外没有其他合法的选择。因此总共有 6 种方式。

**示例 2**  
Input: `s = "11100"`  
Output: `0`  
Explanation:  
可以证明不存在满足条件的选择方案。

**约束条件**  
- `3 <= s.length <= 10^5`  
- `s[i]` 只能是 `'0'` 或 `'1'`。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把所有可能的 **三元组**（下标 `i < j < k`）枚举出来，检查它们对应的字符是否满足“相邻两栋楼的类型不同”。  
- **数据结构**：只需要遍历下标，用三个 `for` 循环即可。可以把它想象成在街道上挑选三座楼，然后一个一个检查这三座楼的颜色（0 或 1）是否满足 “红‑蓝‑红” 或 “蓝‑红‑蓝”。  
- **正确性**：因为我们把 **所有** 合法的下标组合都列举了一遍，只要在遍历时把符合要求的计数加一，最终得到的计数必然就是答案。  

#### 代码（Python）

```python
def numberOfWays_bruteforce(s: str) -> int:
    n = len(s)
    ans = 0
    # 第一个楼的下标 i
    for i in range(n - 2):
        # 第二个楼的下标 j，必须在 i 之后
        for j in range(i + 1, n - 1):
            # 第三个楼的下标 k，必须在 j 之后
            for k in range(j + 1, n):
                # 检查相邻两栋楼是否不同
                if s[i] != s[j] and s[j] != s[k]:
                    ans += 1
    return ans
```

#### 复杂度  

- **时间复杂度**：`O(n³)`  
  - 这里的 `n³` 表示“立方级”，也就是如果街道上有 1000 栋楼，程序大概会执行 1000³ = 10⁹ 次内部判断，显然太慢了。  
- **空间复杂度**：`O(1)`  
  - 只用了几个整数计数变量，和输入长度无关。

---

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **三层循环**：我们每次都把所有三元组都枚举了一遍。  
实际上，满足条件的三元组只能是两种模式：

| 模式 | 解释 |
|------|------|
| `010` | 第 1、3 栋是 0，第 2 栋是 1 |
| `101` | 第 1、3 栋是 1，第 2 栋是 0 |

只要统计出有多少个子序列（不要求连续）是 `010`，以及多少个是 `101`，两者相加即为答案。

下面给出两种等价的线性（`O(n)`) 思路，任选其一都能得到最优解。

---

#### 方法一：中间字符视角（前缀/后缀计数）

把三元组想成 “左边的 0（或 1） × 中间的 1（或 0） × 右边的 0（或 1）”。  
例如统计 `010`：

1. 选定中间的 `1`（下标 `j`）。  
2. `j` 左边有多少个 `0`？记为 `left0[j]`。  
3. `j` 右边有多少个 `0`？记为 `right0[j]`。  
4. 以这个 `j` 为中间的所有合法三元组数 = `left0[j] * right0[j]`。  

对所有 `j` 累加即可得到所有 `010` 的数量。`101` 同理，只是把 “0” 换成 “1”。  

**如何快速得到 `left0`、`right0`？**  

- `left0[j]` 可以在一次左→右遍历时累计：`left0[j] = left0[j-1] + (s[j-1] == '0')`。  
- `right0[j]` 可以在一次右→左遍历时累计：`right0[j] = right0[j+1] + (s[j+1] == '0')`。  

这样只需要两次线性扫描，就得到了所有前缀/后缀计数。

---

#### 方法二：递推计数（基于提示的 “01 / 10” 前缀计数）

我们先统计 **长度为 2 的交替子序列**（`01`、`10`），再在此基础上扩展到长度 3。

- `cnt0[i]`：截至下标 `i`（含 `i`）出现的 `'0'` 的数量。  
- `cnt1[i]`：截至下标 `i`（含 `i`）出现的 `'1'` 的数量。  

- `cnt01[i]`：截至下标 `i`，所有形如 `'0'` 在左、 `'1'` 在右的 **子序列** 数量。  
  - 若 `s[i] == '0'`，`cnt01[i] = cnt01[i-1]`（新字符是 `'0'`，不会产生新的 `'01'`）。  
  - 若 `s[i] == '1'`，`cnt01[i] = cnt01[i-1] + cnt0[i-1]`（每个之前的 `'0'` 都可以和这个 `'1'` 组合成 `'01'`）。

- `cnt10[i]` 同理，只是把 `'0'`、`'1'` 互换。

有了 `cnt01`（所有 `'01'`），我们再把它们「再加一个 `'0'`」得到 `'010'`：

- 当遍历到一个 `'0'`（下标 `i`）时，所有以它结尾的 `'010'` = `cnt01[i-1]`（即在它左边已经出现的 `'01'`）。  
- 把这些值累加得到 `total010`。

`'101'` 同理，用 `cnt10` 再加一个 `'1'`。

**这套递推只需要一次遍历**（因为我们可以在遍历时实时累计 `cnt01`、`cnt10`、`total010`、`total101`），空间只需要几个整型变量。

下面给出实现方式二的代码（更省空间）。

---

#### 代码（Python）

```python
def numberOfWays(s: str) -> int:
    """
    统计子序列 010 与 101 的数量，时间 O(n)，空间 O(1)。
    """
    # 前缀计数
    cnt0 = cnt1 = 0          # 到当前字符为止，各自出现的次数
    cnt01 = cnt10 = 0        # 到当前字符为止，所有的 "01"、"10" 子序列数
    total010 = total101 = 0  # 最终答案累计

    for ch in s:
        if ch == '0':
            # 以当前 '0' 结尾的 "010" 数量等于之前出现的所有 "01"
            total010 += cnt01
            # 更新前缀 '0' 数量
            cnt0 += 1
        else:  # ch == '1'
            # 以当前 '1' 结尾的 "101" 数量等于之前出现的所有 "10"
            total101 += cnt10
            # 更新前缀 '1' 数量
            cnt1 += 1

        # 更新 "01" 与 "10" 的计数
        # 当前字符是 '1' 时，它可以和之前的所有 '0' 组成新的 "01"
        # 当前字符是 '0' 时，它可以和之前的所有 '1' 组成新的 "10"
        if ch == '1':
            cnt01 += cnt0
        else:  # ch == '0'
            cnt10 += cnt1

    return total010 + total101
```

**代码要点解释**（每行中文注释已在代码中给出）：

- `cnt0`、`cnt1`：相当于“字典里 0、1 的出现次数”，帮助我们在看到 `'1'` 时快速知道左边有多少 `'0'` 可以配对形成 `'01'`。
- `cnt01`、`cnt10`：类似“已经收集好的两字符子序列”。当新字符出现时，把对应的前缀计数加进去，就得到新的两字符子序列数量。
- `total010`、`total101`：当我们看到第三个字符（即 `'0'` 对应 `010`，`'1'` 对应 `101`）时，直接把已经存在的两字符子序列数量加到答案里。

---

#### 复杂度  

- **时间复杂度**：`O(n)` — 只遍历一次字符串，`n` 是街道上楼的数量。线性时间意味着如果楼的数量从 10 增加到 100，运行时间大约会增长 10 倍，而不是 1000 倍（这就是 `O(n³)` 与 `O(n)` 的本质区别）。
- **空间复杂度**：`O(1)` — 只用了几个整数变量，和 `n` 的大小无关。

---

## 心得

- **核心技巧**：把 “三元交替子序列” 拆成 “先找两字符交替子序列，再在其后加一个相同字符” 的递推过程。利用前缀计数把组合数一次性算出来，避免枚举。
- **适用的题型**：
  1. 统计特定模式的子序列，如 `"abc"`、`"001"` 等。
  2. “只要相邻不同” 的长度为 `k` 的子序列计数（可用类似的 DP 推导）。
  3. 需要在 O(n) 时间内统计所有形如 `XYX`（X 与 Y 不同）的子序列。
- **一句话总结解题钥匙**：**先统计好长度为 2 的交替子序列，再利用它们快速累计长度为 3 的交替子序列**。

## 反思

- **第一反应**：看到 “不相邻相同” 的要求，我立刻想到枚举三元组并逐个检查——这就是暴力思路。
- **最容易踩的坑**：
  - 忽略 “子序列” 与 “子串” 的区别：这里可以跳过中间的建筑，只要顺序对即可。
  - 计数时忘记把 **前缀** 与 **后缀** 的数量分开，导致重复计数或漏计数。
  - 边界条件：字符串最短为 3，若全部相同（如 `"111"`），答案应为 0，代码需要在没有任何 `01`、`10` 时仍能正常返回 0。
- **下次类似题的第一步**：**先思考能否把目标模式拆成“前缀+当前字符”或“已有子序列+新字符”的形式**，如果可以，就尝试用前缀计数或动态规划把组合数一次性算出。这样往往可以把指数级的枚举降到线性时间。
