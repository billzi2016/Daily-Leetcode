# #2522. 将字符串划分为每个子串的值不超过 K 的子串 / Partition String Into Substrings With Values at Most K

> 难度：中等 · 标签：String、Dynamic Programming、Greedy · [LeetCode 链接](https://leetcode.com/problems/partition-string-into-substrings-with-values-at-most-k/)

## 题目（英文原版）

**Description**

You are given a string s consisting of digits from 1 to 9 and an integer k.
A partition of a string s is called good if:
Return the minimum number of substrings in a good partition of s. If no good partition of s exists, return -1.
Note that:

**Examples**

**Example 1:**

```
Input: s = "165462", k = 60
Output: 4
Explanation: We can partition the string into substrings "16", "54", "6", and "2". Each substring has a value less than or equal to k = 60.
It can be shown that we cannot partition the string into less than 4 substrings.
```

**Example 2:**

```
Input: s = "238182", k = 5
Output: -1
Explanation: There is no good partition for this string.
```

**Constraints**

- 1 <= s.length <= 105
- s[i] is a digit from '1' to '9'.
- 1 <= k <= 109

## 题目（中文翻译）

给定一个只包含字符 `'1'` 到 `'9'` 的字符串 `s` 和一个整数 `k`。  
如果把字符串 `s` 划分（partition）成若干子串（substring），且每个子串转换成整数后的数值都 **不大于** `k`，则该划分称为 **好划分**（good partition）。

返回好划分中子串的最小数量；如果不存在满足条件的划分，返回 `-1`。

**示例 1**  
**输入**: `s = "165462", k = 60`  
**输出**: `4`  
**解释**: 我们可以把字符串划分为子串 `"16"`, `"54"`, `"6"` 和 `"2"`。每个子串的整数值都不超过 `k = 60`。可以证明，无法用少于 4 个子串完成划分。

**示例 2**  
**输入**: `s = "238182", k = 5`  
**输出**: `-1`  
**解释**: 该字符串不存在好划分。

**约束条件**  
- `1 <= s.length <= 10^5`  
- `s[i]` 为字符 `'1'` 到 `'9'` 之一  
- `1 <= k <= 10^9`

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**把所有可能的切分方式都枚举一遍**，然后在合法的切分中挑选子串最少的那一种。  
这相当于在字符串的每一个位置都可以选择“切”或“不切”，于是会产生指数级（`2^(n-1)`）的组合——就像把每一根木棍插进或不插进两根板之间的缝隙，组合数会爆炸。

为了让思路更清晰，我们可以把它转化为**动态规划**的形式：

- 用 `dp[i]` 表示前 `i` 个字符（下标 `0 … i-1`）能得到的**最少子串数**。  
- 对于每个 `i`，我们尝试把最后一段子串的起点放在 `j`（`0 ≤ j < i`），即子串 `s[j:i]`。  
- 如果 `int(s[j:i]) ≤ k`，则 `dp[i] = min(dp[i], dp[j] + 1)`。  

这里的 `int(s[j:i])` 就像查字典一样：**哈希表**的 `key` 是子串，`value` 是它对应的整数值。我们只需要判断这个值是否不大于 `k`，如果是，就可以把它接到前面的合法划分后面。

**为什么暴力 DP 能得到正确答案？**  
因为我们枚举了**所有**可能的切分点，只要子串的数值不超过 `k`，就把它算进来；最终 `dp[n]`（`n = len(s)`）自然是最小的合法子串数。

**时间/空间复杂度**  
- 对每个 `i`，我们会尝试所有 `j < i`，最坏情况下要检查 `O(i)` 次；累加下来是 `O(n^2)`（`n` 为字符串长度）。  
- 需要一个长度为 `n+1` 的数组存 `dp`，空间是 `O(n)`。  

> 大白话解释：  
> - `O(n²)` 就像把 `n` 本书两两配对，需要 `n`×`n` 次比较，随着 `n` 增大，工作量会“飞快”增长。  
> - `O(n)` 空间相当于我们只需要和书的页数一样多的纸来记笔记，规模是线性的。

#### 代码（Python）

```python
def min_partitions_bruteforce(s: str, k: int) -> int:
    n = len(s)
    INF = n + 1                     # 一个不可能出现的“大”数
    dp = [INF] * (n + 1)            # dp[i] = 前 i 个字符的最小子串数
    dp[0] = 0                       # 空字符串需要 0 个子串

    for i in range(1, n + 1):
        num = 0                     # 用来累计子串的数值
        # 从后往前尝试子串的起点 j
        for j in range(i - 1, -1, -1):
            # 把 s[j] 加到当前数值的左侧
            num = int(s[j]) * (10 ** (i - j - 1)) + num
            if num > k:             # 已经超过 k，后面的更长子串肯定也超过
                break
            dp[i] = min(dp[i], dp[j] + 1)

    return -1 if dp[n] == INF else dp[n]
```

> 关键点注释已在代码里，用中文解释了每一步的含义。

#### 复杂度  

- **时间复杂度**：`O(n²)` —— 每个位置都要往前检查所有可能的起点。  
- **空间复杂度**：`O(n)` —— 只用了一个 `dp` 数组存每个前缀的最优解。

### 2. 最优解  

#### 思路  

暴力 DP 的瓶颈在于**重复检查相同的子串**。  
观察题目可以发现：

1. 字符都是 `'1'`~`'9'`，没有 `'0'`，所以子串的数值随长度 **单调递增**（每加一位左边的数字会让整体变大）。  
2. `k ≤ 10⁹`，也就是说 **任何合法子串的长度最多是 9 位**（10 位数最小就是 1 000 000 000，已经大于 `k`）。  

基于这两点，我们可以把**“尽量取最长合法子串”**作为贪心策略：

- 从左到右遍历字符串，维护当前正在构造的子串对应的整数 `cur`。  
- 每读进一个新数字 `d`，尝试把它接在 `cur` 的右边，得到 `new = cur * 10 + d`。  
- 如果 `new ≤ k`，说明把 `d` 加进来仍合法，继续向右扩展。  
- 否则，**必须在 `d` 之前切断**，因为再往右放更多数字只会让数值更大，永远不可能满足 `≤ k`。此时：
  - 计数器 `cnt += 1`（完成一个子串）。  
  - 把 `cur` 重置为 `d`（新子串从 `d` 开始）。  
  - 若 `d > k`，说明连单个字符都超出上限，**不存在合法划分**，直接返回 `-1`。  

这样每个字符只会被访问一次，**不需要回溯**，时间线性。  
贪心之所以最优，是因为：

- 把当前子串尽可能拉长，一定不会影响后面的切分（后面的字符不受前面怎么切的限制）。  
- 若我们把一个本可以继续扩展的子串提前切断，那么后面必然需要 **更多** 的子串来覆盖相同的字符，导致总数不可能更少。

因此“每次取最长合法子串”得到的切分必然是子串数最少的。

#### 代码（Python）

```python
def min_partitions_greedy(s: str, k: int) -> int:
    """
    贪心：从左到右尽可能把子串扩长，只要不超过 k。
    若单个字符本身 > k，则不存在合法划分，返回 -1。
    """
    cnt = 0          # 已经切好的子串数量
    cur = 0          # 当前子串对应的整数值

    for ch in s:
        d = int(ch)                     # 当前数字，像查字典一样得到它的“页码”
        # 先检查单个字符是否已经超过上限
        if d > k:                       # 任何子串都必须包含这个字符，却又大于 k
            return -1

        # 试图把 d 接到当前子串后面
        new_val = cur * 10 + d
        if new_val <= k:                # 仍然合法，继续扩展
            cur = new_val
        else:                           # 不能再扩了，必须在 d 前面切断
            cnt += 1                    # 完成一个子串
            cur = d                     # 重新开始新子串，值为 d

    # 循环结束后，cur 里还有最后一个子串（可能已经计数，也可能是空）
    if cur > 0:
        cnt += 1

    return cnt
```

> 代码每行都有中文注释，帮助初学者对“为什么要这样写”有直观认识。

#### 复杂度  

- **时间复杂度**：`O(n)` —— 只遍历一次字符串，`n` 为 `len(s)`。  
  - 与暴力解的 `O(n²)` 相比，快了大约 `n` 倍（比如 `10⁵` 长度时，暴力解根本跑不完）。  
- **空间复杂度**：`O(1)` —— 只用常数个变量 `cnt、cur、d`，不随 `n` 增长。

## 心得  

- **核心技巧**：**贪心 + 长度上限**  
  - 关键是把“**尽量取最长合法子串**”作为决策原则，利用了数字增长的单调性和 `k` 的位数上限。  
- **适用的题型**  
  1. **分割字符串使每段满足数值范围**（如本题、"Split Array into Subarrays with Max Sum ≤ K"）。  
  2. **把序列切成若干段，使每段长度/和/乘积满足约束**（如 “Maximum Number of Non‑Overlapping Subarrays With Sum ≤ K”）。  
  3. **在不允许前导零的情况下，构造数值不超过上限的子串**（如 “Number of Substrings With Value ≤ K”）。  
- **一句话总结**：  
  “只要每一步都把当前子串延伸到最长合法长度，就能保证子串数最少——贪心是本题的解题钥匙”。

## 反思  

- **第一反应**：直接想到枚举所有切分，写出 `dp[i] = min(dp[j] + 1)` 的递推式。  
- **最容易踩的坑**  
  1. **忽略单字符超过 k 的情况**，导致代码在这种输入上无限循环或返回错误答案。  
  2. **没有利用 `k ≤ 10⁹` 的位数限制**，导致时间复杂度仍然是 `O(n²)`，在大数据上超时。  
  3. **忘记在循环结束后计入最后一个子串**，会少算一次。  
- **下次类似题的第一步**：  
  “先检查是否有单个元素已经违背约束（立即返回 -1），然后思考‘是否可以用贪心把当前段尽可能拉长’，利用单调性或上界的位数限制来把复杂度降到线性”。
