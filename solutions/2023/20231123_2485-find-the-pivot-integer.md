## 题目（中文翻译）

给定一个正整数 `n`，找出满足以下条件的枢轴整数（pivot integer） `x`：

- `x` 左侧所有整数的和等于 `x` 右侧所有整数的和，即  
  `1 + 2 + … + (x‑1) = (x+1) + (x+2) + … + n`。

返回该枢轴整数 `x`。如果不存在满足条件的整数，返回 `-1`。题目保证对于给定的输入至多存在一个枢轴整数。

**示例 1**  
**输入**: `n = 8`  
**输出**: `6`  
**解释**: 6 是枢轴整数，因为  
`1 + 2 + 3 + 4 + 5 + 6 = 6 + 7 + 8 = 21`。

**示例 2**  
**输入**: `n = 1`  
**输出**: `1`  
**解释**: 1 是枢轴整数，因为 `1 = 1`。

**示例 3**  
**输入**: `n = 4`  
**输出**: `-1`  
**解释**: 可以证明不存在这样的整数。

**约束条件**  
- `1 <= n <= 1000`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把每一个可能的整数 `x`（1 ≤ x ≤ n）都拿去试一试，看看它左边的所有数之和是否等于右边的所有数之和。  

- **数据结构**：我们只需要一个**前缀和数组**（prefix sum），它类似于一本字典，记录了“从 1 加到 i 的累计和”。前缀和的第 i 项相当于字典里“词 i 对应的页码”。有了前缀和，求任意区间 `[l, r]` 的和只需要一次减法：`sum(l..r) = pre[r] - pre[l-1]`。  
- **正确性**：如果某个 `x` 满足  
  ```
  1 + 2 + … + x   =   x + (x+1) + … + n
  ```  
  那么左边的和等于右边的和，显然它就是题目要求的枢轴整数。遍历所有 `x` 并逐一验证，必然能找到唯一的答案（若存在的话）。  
- **复杂度分析**：  
  - 构造前缀和需要遍历一次 `1..n`，时间 O(n)。  
  - 对每个 `x` 再算两次区间和（左边、右边），每次都是 O(1) 的减法，所以遍历 `x` 也是 O(n)。  
  - 总时间 = O(n) + O(n) = **O(n)**。  
  - 额外空间只用了一个长度为 `n+1` 的数组，**O(n)** 的空间。  
  对于本题的约束 `n ≤ 1000`，这种 O(n) 的做法已经足够快，不过我们仍然可以进一步把空间压到 O(1)。

#### 代码（Python）

```python
def pivotInteger_bruteforce(n: int) -> int:
    # 1. 计算前缀和 pre[i] = 1 + 2 + ... + i
    pre = [0] * (n + 1)          # pre[0] = 0，方便统一公式
    for i in range(1, n + 1):
        pre[i] = pre[i - 1] + i   # 前缀和递推，类似把每本字典的页码累加

    # 2. 逐个检查 x 是否满足左边和等于右边和
    for x in range(1, n + 1):
        left_sum = pre[x]                # 1..x 的和
        right_sum = pre[n] - pre[x - 1]  # x..n 的和 = (1..n) - (1..x-1)
        if left_sum == right_sum:
            return x                     # 找到唯一答案，直接返回

    return -1   # 没有满足条件的整数
```

#### 复杂度

- **时间复杂度**：`O(n)` —— 只遍历了两遍长度为 `n` 的序列，实际运行时间随 `n` 线性增长。  
- **空间复杂度**：`O(n)` —— 前缀和数组占用了 `n+1` 个整数的额外空间。

### 2. 最优解

#### 思路  

从暴力解我们已经知道：  
```
sum_left  = 1 + 2 + … + x
sum_right = x + (x+1) + … + n
```
如果把两边都写成 **总和** 的形式，问题会更清晰。  

1. **总和** `S = 1 + 2 + … + n = n·(n+1)/2`（等差数列求和公式）。  
2. `sum_left` 已经是前缀和 `pre[x] = x·(x+1)/2`。  
3. `sum_right` 可以拆成 `x + (x+1) + … + n = S - (1 + 2 + … + (x-1)) = S - pre[x-1]`。  

于是等式 `sum_left == sum_right` 变为  

```
pre[x] = S - pre[x-1]
```

把 `pre[x]` 与 `pre[x-1]` 用公式展开：

```
x·(x+1)/2 = S - (x-1)·x/2
```

把左边的 `x·(x+1)/2` 移到右边，化简后得到：

```
x·(x+1)/2 + (x-1)·x/2 = S
=> x·x = S
=> x² = S
```

也就是说，**枢轴整数 x 必须是总和 S 的整数平方根**。只要 `S` 是一个完全平方数（即 `sqrt(S)` 为整数），`x = sqrt(S)` 就是答案；否则不存在枢轴整数。

这一步把原本需要遍历的 O(n) 直接压缩到 **O(1)**，只需要做一次求和和一次开方。

> **类比**：想象你有一本厚厚的笔记本，里面每页的页码恰好是从 1 开始递增的数字。要找一个页码 `x`，使得它左边的页码之和等于它右边的页码之和。其实只要算出整本笔记本的页码总和 `S`，再检查 `S` 是否是某个整数的平方，就能直接知道这页码是哪一页。

#### 代码（Python）

```python
import math

def pivotInteger_optimal(n: int) -> int:
    # 1. 计算 1..n 的总和，等差数列公式 n*(n+1)//2
    total = n * (n + 1) // 2

    # 2. 求 total 的整数平方根
    x = int(math.isqrt(total))   # isqrt 返回不大于 sqrt(total) 的整数

    # 3. 检查 x² 是否恰好等于 total
    if x * x == total:
        return x      # 正好是枢轴整数
    return -1         # 不是完全平方数，答案不存在
```

#### 复杂度

- **时间复杂度**：`O(1)` —— 只做了常数次算术运算和一次整数开方。相较于暴力的 `O(n)`，速度提升明显。  
- **空间复杂度**：`O(1)` —— 只用了几个整数变量，没有额外的数组。

## 心得

- **核心技巧**：把“左边和等于右边和”转化为**总和是完全平方数**的判定。利用等差数列求和公式和整数平方根即可在常数时间内求解。  
- **适用场景**：  
  1. 需要比较两段连续子数组和且两段在同一个等差序列中（如本题）。  
  2. 题目中出现“前缀和 = 后缀和”或“左右两边和相等”的情况，往往可以先求整体和再做代数化简。  
  3. 判断某个数是否为完全平方数的技巧（`isqrt` 或 `int(sqrt)` 再平方验证）。  
- **一句话总结**：**枢轴整数 = 整体和的整数平方根（若存在）**。

## 反思

- **第一反应**：直接遍历每个可能的 `x`，计算左右两侧的和，看看是否相等。  
- **最容易踩的坑**：  
  - 忘记把 `x` 本身计入右侧和（题目要求左边是 `1..x`，右边是 `x..n`，`x` 重复一次）。  
  - 在用 `math.sqrt` 时产生浮点误差，导致判断 `sqrt(total)` 是否为整数出错。使用 `math.isqrt`（整数开方）可以避免此类问题。  
- **下次思路**：遇到“前缀和 = 后缀和”或类似的等式时，先**写出整体和的表达式**，尝试代数化简，看看是否能把问题降维到“判断某个数的性质”（如是否为完全平方数、是否为质数等）。这样往往可以把 O(n) 的暴力直接压缩到 O(1)。
