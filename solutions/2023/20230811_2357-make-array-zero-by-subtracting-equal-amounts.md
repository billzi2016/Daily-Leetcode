# #2357. 通过减去相等的数使数组全部为零 / Make Array Zero by Subtracting Equal Amounts

> 难度：简单 · 标签：Array、Hash Table、Greedy、Sorting、Heap (Priority Queue)、Simulation · [LeetCode 链接](https://leetcode.com/problems/make-array-zero-by-subtracting-equal-amounts/)

## 题目（英文原版）

**Description**

You are given a non-negative integer array nums. In one operation, you must:
Return the minimum number of operations to make every element in nums equal to 0.

**Examples**

**Example 1:**

```
Input: nums = [1,5,0,3,5]
Output: 3
Explanation:
In the first operation, choose x = 1. Now, nums = [0,4,0,2,4].
In the second operation, choose x = 2. Now, nums = [0,2,0,0,2].
In the third operation, choose x = 2. Now, nums = [0,0,0,0,0].
```

**Example 2:**

```
Input: nums = [0]
Output: 0
Explanation: Each element in nums is already 0 so no operations are needed.
```

**Constraints**

- 1 <= nums.length <= 100
- 0 <= nums[i] <= 100

## 题目（中文翻译）

给定一个非负整数数组（array）`nums`。在一次操作（operation）中，你必须：

* 选取一个正整数 `x`，并将数组中所有大于 `0` 的元素都减去 `x`。  
* 只能在所有选中的元素中减去相同的数 `x`。

返回使 `nums` 中每个元素都等于 `0` 所需的最少操作次数。

## 示例

### 示例 1
**输入**: `nums = [1,5,0,3,5]`  
**输出**: `3`  
**解释**:  
- 第一次操作，选择 `x = 1`。此时 `nums = [0,4,0,2,4]`。  
- 第二次操作，选择 `x = 2`。此时 `nums = [0,2,0,0,2]`。  
- 第三次操作，选择 `x = 2`。此时 `nums = [0,0,0,0,0]`。

### 示例 2
**输入**: `nums = [0]`  
**输出**: `0`  
**解释**: 数组中的每个元素已经是 `0`，因此不需要任何操作。

## 约束条件
- `1 <= nums.length <= 100`
- `0 <= nums[i] <= 100`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**模拟题目描述的操作**：

1. 每一次我们遍历整个数组，找出当前的最小的非零元素 `x`（可以把它想成“最小的未熄灭的灯泡亮度”）。
2. 用 `x` 去 **同时** 减掉所有大于 `0` 的元素。  
   - 这一步好比我们把所有亮着的灯泡的亮度都调低 `x`，最暗的那盏灯会直接熄灭，其他灯的亮度也相应降低。
3. 重复上述过程，直到所有元素都变成 `0`。

> **为什么这样一定能得到答案？**  
> 因为题目要求每一步必须选取一个正整数 `x` 去 **所有** 正数元素同时减去 `x`。如果我们选的 `x` 不是当前最小的非零数，某些元素会被减得太多（直接变负），而负数在题目中是不允许的。因此只能把 `x` 设为当前最小的非零数，这样保证每次都恰好把至少一个元素降到 `0`，并且不会出现负数。

> **大白话的复杂度解释**  
> - `O(n²)`：想象有 `n` 本书，每本书需要检查 `n` 次才能找出最小的未读页码，总共是 `n` 乘 `n` 次检查，故称为二次方时间。  
> - `O(1)` 空间：我们只用几个临时变量，跟输入规模无关。

#### 代码（Python）

```python
from typing import List

def min_operations_bruteforce(nums: List[int]) -> int:
    """暴力模拟每一次的减法操作，返回最小操作次数"""
    ops = 0                     # 记录已经做了多少次操作
    while True:
        # 找出当前数组中最小的非零元素
        min_pos = None
        for v in nums:
            if v > 0:           # 只考虑正数
                if min_pos is None or v < min_pos:
                    min_pos = v

        # 如果没有正数，说明全部已经是 0，结束循环
        if min_pos is None:
            break

        # 用找到的最小值 x 同时减掉所有正数元素
        for i in range(len(nums)):
            if nums[i] > 0:
                nums[i] -= min_pos

        ops += 1                 # 完成一次操作
    return ops
```

#### 复杂度

- **时间复杂度**：`O(n²)`  
  - 每一次循环要遍历数组一次找最小值（`O(n)`），最多会进行 `k` 次循环，其中 `k` ≤ `n`（最坏情况每次只能把一个不同的数变为 0），于是总时间是 `O(n·k) = O(n²)`。  
  - 用生活中的比喻：如果有 100 本书，每本书都要检查 100 次才能找到下一个要读的章节，总共是 10,000 次检查。

- **空间复杂度**：`O(1)`  
  - 只用了常数个额外变量（`ops`、`min_pos`），不随输入规模增长。

### 2. 最优解

#### 思路  

从暴力解可以看到，每一次操作都会把 **所有** 当前最小的非零元素变为 `0`，而且 **相同数值的元素一定会在同一次操作中一起归零**。于是我们不必真的去模拟减法，只需要统计 **有多少种不同的非零数** 即可。

- **慢的地方**：暴力解在每一步都遍历整个数组寻找最小值，这导致了二次方的时间。
- **关键观察**：  
  1. 只要把数组中出现过的非零数记下来，它们各自需要一次“被选为 x 的机会”。  
  2. 同一个数值不管出现多少次，只需要一次操作就能把所有同值元素变为 `0`（因为一次减去它本身即可）。  
  3. 因此答案 = “不同的非零数的数量”。  

- **使用的数据结构**：**集合（Set）**。集合可以看成“字典的页码本”，把每个出现过的非零数当作“词”，只要记住它出现过一次就行，重复的词会自动被去重。  
  - 类比：把所有不同颜色的球放进一个盒子里，只要数盒子里有几种颜色即可。

实现步骤：

1. 创建一个空集合 `s`。  
2. 遍历 `nums`，把每个 **非零** 的元素加入集合 `s`。  
3. 最终返回集合的大小 `len(s)`，即为最少操作次数。

#### 代码（Python）

```python
from typing import List

def min_operations(nums: List[int]) -> int:
    """
    统计数组中不同的非零数字个数，即为最少操作次数。
    思路：集合会自动去重，只保留出现过的不同数值。
    """
    unique_non_zero = set()          # 用集合记录出现过的非零数
    for v in nums:
        if v != 0:                   # 只关心非零元素
            unique_non_zero.add(v)  # 加入集合，重复的会被自动忽略

    return len(unique_non_zero)      # 集合的大小就是答案
```

#### 复杂度

- **时间复杂度**：`O(n)`  
  - 只需要一次遍历数组（`n` 次），每次把元素放进集合的操作是 **均摊 O(1)**（哈希表的插入），所以整体是线性时间。  
  - 大白话：如果有 100 本书，只需要一次检查每本书的标题，就能知道有多少种不同的标题，花的时间正好和书的数量成正比。

- **空间复杂度**：`O(m)`（`m` 为不同非零数的个数，最坏情况下 `m ≤ n`）  
  - 需要额外的集合来存放这些不同的数值。  
  - 如果所有数都不相同且都非零，集合会占用 `n` 个位置；如果全部是 `0`，集合为空，只占常数空间。

## 心得

- **核心技巧**：利用**集合去重**，把“每种不同的非零数需要一次操作”这一事实转化为“统计不同非零数的数量”。  
- **适用的题型**：  
  1. “统计数组中不同元素的个数”类问题（如 LeetCode 347. Top K Frequent Elements 的预处理）。  
  2. “把相同的东西一次性处理掉”类问题（如把相同颜色的水果一次性装箱）。  
  3. 需要**去重**后再做计数的场景（如找出字符串中不同字符的数量）。
- **一句话总结解题钥匙**：**把操作次数等价为“不同非零数的种类数”，用集合一键去重即可。**

## 反思

- **第一反应**：看到“每次都要选一个正整数 x 同时减去所有正数”，我本能地想到**模拟减法**，于是写出了暴力的循环。
- **最容易踩的坑**：  
  - 忘记排除 `0`，把 `0` 也算进集合会导致答案比实际多。  
  - 误以为需要对每个元素单独计数，而不是按**数值种类**计数。  
  - 对集合的时间复杂度不熟悉，担心会出现 `O(n²)`，其实哈希表的插入是均摊 `O(1)`。
- **下次遇到同类题**：第一步先**思考是否可以把问题抽象为“统计不同的东西”，如果可以，就立刻考虑使用集合或哈希表来去重，往往能把时间从二次方直接降到线性。
