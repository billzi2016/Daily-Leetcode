# #2384. 最大回文数 / Largest Palindromic Number

> 难度：中等 · 标签：Hash Table、String、Greedy、Counting · [LeetCode 链接](https://leetcode.com/problems/largest-palindromic-number/)

---

## 题目（英文原版）

**Description**

You are given a string num consisting of digits only.
Return the largest palindromic integer (in the form of a string) that can be formed using digits taken from num. It should not contain leading zeroes.
Notes:

**Examples**

**Example 1:**

```
Input: num = "444947137"
Output: "7449447"
Explanation: 
Use the digits "4449477" from "444947137" to form the palindromic integer "7449447".
It can be shown that "7449447" is the largest palindromic integer that can be formed.
```

**Example 2:**

```
Input: num = "00009"
Output: "9"
Explanation: 
It can be shown that "9" is the largest palindromic integer that can be formed.
Note that the integer returned should not contain leading zeroes.
```

**Constraints**

- 1 <= num.length <= 105
- num consists of digits.

给定一个仅包含数字字符的字符串 `num`。  
返回可以使用 `num` 中的数字组成的 **最大回文整数**（以字符串形式返回），且结果不能包含前导零。


### 约束

- `1 <= num.length <= 10^5`
- `num` 仅由数字字符组成。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**把所有可能的排列都列出来，挑出其中是回文且数值最大的那个**。  
可以把它想象成把一堆字母（这里是数字字符）全部拿出来，随意排列成各种“单词”，然后检查每个单词：

1. 是否是回文（正着读和倒着读一样）；
2. 是否满足「没有前导零」的要求；
3. 在所有满足条件的单词里挑最大值。

实现上可以：

- 用 `itertools.permutations` 生成 `num` 的所有排列（每个排列都是一个元组）；
- 把元组拼成字符串，检查是否是回文；
- 记录最大的合法回文。

> **为什么会对**  
> 因为我们穷举了**所有**可能的排列，只要答案存在，就一定会在遍历的集合里被找到。

> **时间/空间复杂度**  
> - **时间复杂度**：`O(n! * n)`，其中 `n = len(num)`。`n!` 是全排列的个数，检查每个排列是否是回文需要 `O(n)`。用大白话说，就是「当数字有 10 位时，排列数已经是 3,628,800，计算机几乎要崩溃」。
> - **空间复杂度**：`O(n)`，只需要保存当前排列的字符数组和临时的回文字符串。

> **这套思路只适合** `n ≤ 8` 左右的极小输入，根本不可能在正式评测（`n ≤ 10⁵`）中通过。

#### 代码（Python）

```python
import itertools

def largest_palindromic_bruteforce(num: str) -> str:
    """暴力枚举所有排列，返回最大的合法回文（仅用于教学）"""
    best = ""                     # 当前找到的最大回文
    n = len(num)

    # itertools.permutations 会产生所有不同位置的排列（包括相同字符的重复排列）
    for perm in itertools.permutations(num):
        s = ''.join(perm)         # 把元组转成字符串
        # 1️⃣ 前导零检查（除非整个字符串只有 '0'）
        if s[0] == '0' and any(ch != '0' for ch in s):
            continue
        # 2️⃣ 是否是回文
        if s == s[::-1]:          # Python 的切片逆序很方便
            if s > best:          # 字符串比较天然是数值比较（同长时），因为都是数字字符
                best = s
    return best if best else "0"   # 若没有合法回文，返回 "0"（题目保证至少有一个）
```

> **运行提示**：上面的函数在 `len(num) = 9` 时已经会耗时几分钟，切勿在大数据上直接运行。

#### 复杂度

- **时间复杂度**：`O(n! * n)` —— 随着数字个数的增加，排列数呈阶乘增长，几乎不可能在 10⁵ 长度的数据上完成。
- **空间复杂度**：`O(n)` —— 只保存当前排列和临时字符串，额外空间很小，但时间成本太高。

### 2. 最优解

#### 思路  

从暴力解我们可以看到，**真正的难点不是判断回文，而是如何快速构造最大回文**。  
下面一步步推导出一种 **计数 + 贪心** 的思路：

1. **计数**  
   - 把字符串里每个数字出现的次数记下来。  
   - 这一步相当于把数字放进「字典」里查找，`hash table`（哈希表）就像一本字典，键是数字字符 `'0'~'9'`，值是出现次数。

2. **回文的结构**  
   - 假设我们已经决定了回文的左半部分 `L`，右半部分必然是 `L` 的镜像（倒序）。  
   - 如果回文长度是奇数，还可以在最中间放 **一个** 单独的数字 `M`（这个数字不需要配对）。

3. **如何让回文尽可能大**  
   - **长度越长**，数值越大（因为左边的高位更多）。  
   - 当长度相同，**左边的高位数字越大**，整体数值越大。  
   - 因此我们应该**优先使用出现次数 ≥ 2 的大数字**，把它们各取一对放到左右两端。  
   - 从 `9` 开始往 `0` 遍历，依次把「可以成对」的数字加到 `L` 的末尾。

4. **中心数字的挑选**  
   - 只要还有剩余次数为 **奇数** 的数字，就可以选一个放在中间。  
   - 为了让回文最大，挑 **最大的** 那个数字（仍然从 `9` 向下找）。

5. **特殊情况：全是 `0`**  
   - 如果左半部分全是 `0`，且没有中心数字，答案会是 `"0"`（因为不能出现前导零）。  
   - 如果左半部分有非 `0`，我们必须确保最左边的字符不是 `0`，这在贪心构造时自然满足，因为我们总是先放大的非零数字。

6. **整体构造**  

```
count = [出现次数]  # 长度 10，索引对应数字字符
left = []           # 用来存放左半部分，从高位到低位
for d from 9 downto 0:
    pair = count[d] // 2          # 能配成多少对
    left.append(str(d) * pair)    # 把这对数字的左边全部放进 left
    count[d] -= pair * 2          # 剩下的要么是 0 要么是 1

# 选中心
mid = ''
for d from 9 downto 0:
    if count[d] > 0:              # 还有单个的
        mid = str(d)
        break

right = ''.join(reversed(''.join(left)))   # 左半的镜像
ans = ''.join(left) + mid + right
# 处理全 0 的情况
if ans[0] == '0':
    return '0'
return ans
```

> **核心算法/数据结构解释**  
> - **计数数组**：长度固定为 10（因为只有十种数字），下标直接对应数字，查询/修改都是 `O(1)`，等价于哈希表但更轻量。  
> - **贪心**：每一步都选择当前「看起来最优」的决定——先用最大的可以成对的数字填两侧，最后挑最大的单个数字作中心。因为后面的决定不会影响已经确定的更高位数字，这种局部最优必然导致全局最优。

#### 代码（Python）

```python
def largest_palindromic(num: str) -> str:
    """
    计数 + 贪心构造最大回文
    时间复杂度 O(n + 10) ≈ O(n)      n 为字符串长度
    空间复杂度 O(10)   ≈ O(1)        只用了固定大小的计数数组
    """
    # 1️⃣ 统计每个数字出现的次数
    cnt = [0] * 10               # cnt[0] 对应字符 '0'，cnt[9] 对应 '9'
    for ch in num:
        cnt[ord(ch) - ord('0')] += 1

    # 2️⃣ 构造左半部分（从大到小依次放对称的数字）
    left_parts = []               # 用 list 收集，最后一次性 join，效率更高
    for d in range(9, -1, -1):    # 9 → 0
        pair = cnt[d] // 2        # 能组成多少对
        if pair:
            left_parts.append(str(d) * pair)  # 把这对的左侧全部放进去
            cnt[d] -= pair * 2    # 用掉的数字从计数里减掉

    # 3️⃣ 选取中心字符（如果还有剩余的单个数字）
    mid = ''
    for d in range(9, -1, -1):
        if cnt[d] > 0:           # 只要还有一次出现，就可以当中心
            mid = str(d)
            break

    # 4️⃣ 组合最终答案
    left = ''.join(left_parts)          # 左半部分已经是从高位到低位
    right = left[::-1]                  # 右半是左半的镜像
    ans = left + mid + right

    # 5️⃣ 处理全是 0 的情况（因为不能出现前导零）
    if ans and ans[0] == '0':
        return '0'
    return ans
```

#### 复杂度

- **时间复杂度**：`O(n)`  
  - 统计出现次数遍历一次字符串 `O(n)`。  
  - 随后遍历固定的 10 个数字（常数），构造左右两侧和中心均为 `O(1)`。  
  - 用大白话讲就是「无论输入有多长，只要一次扫过去，时间就和长度成正比」。
- **空间复杂度**：`O(1)`（常数级）  
  - 只用了长度为 10 的计数数组和若干长度不超过原字符串的局部字符串，整体额外空间不随 `n` 增长。

## 心得

- **核心技巧**：**计数 + 贪心**。先统计每个数字的出现次数，再从大到小「配对」放在回文的两端，最后挑最大剩余数字作中心。
- **该技巧适用的题型**  
  1. **最大回文构造**（本题）。  
  2. **重排形成回文**（如 LeetCode 2216: Minimum Deletions to Make Array Beautiful）。  
  3. **使用字符计数构造字典序最大/最小字符串**（如「按字典序最大化字符串」系列）。
- **一句话总结解题钥匙**：**把“出现次数 ≥ 2 的大数字先配对放两侧，剩下的最大单个数字放中间”。**

## 反思

- **第一反应**：看到“最大回文”，第一时间想到“回文的左半+右半是镜像”，于是想到先**统计字符出现次数**。
- **最容易踩的坑**  
  - **前导零**：全是 `0` 时必须返回单个 `"0"`，而不是 `"000"`。  
  - **中心数字的选择**：必须在所有剩余的单个数字中挑最大的，否则可能错失更大的数值。  
  - **计数后未清零**：配对后忘记把计数减掉，会导致同一个数字被错误地再用作中心。
- **下次类似题的第一步**：**先做一次“出现次数统计”，再依据回文结构（配对+中心）进行贪心构造**。这样既保证正确性，又能在 O(n) 时间内完成。
