# #2180. 偶数位和整数计数 / Count Integers With Even Digit Sum

> 难度：简单 · 标签：Math、Simulation · [LeetCode 链接](https://leetcode.com/problems/count-integers-with-even-digit-sum/)

---

## 题目（英文原版）

**Description**

Given a positive integer num, return the number of positive integers less than or equal to num whose digit sums are even.
The digit sum of a positive integer is the sum of all its digits.

**Examples**

**Example 1:**

```
Input: num = 4
Output: 2
Explanation:
The only integers less than or equal to 4 whose digit sums are even are 2 and 4.
```

**Example 2:**

```
Input: num = 30
Output: 14
Explanation:
The 14 integers less than or equal to 30 whose digit sums are even are
2, 4, 6, 8, 11, 13, 15, 17, 19, 20, 22, 24, 26, and 28.
```

**Constraints**

- 1 <= num <= 1000

---

## 题目（中文翻译）

给定一个正整数（positive integer）`num`，返回 **不大于** `num` 的正整数（positive integer）中，数字和（digit sum）为偶数的整数的个数。

正整数的数字和是其所有位上的数字之和。

**示例 1**

``` 
Input: num = 4
Output: 2
Explanation:
不大于 4 且数字和为偶数的整数只有 2 和 4。
```

**示例 2**

``` 
Input: num = 30
Output: 14
Explanation:
不大于 30 且数字和为偶数的 14 个整数是
2, 4, 6, 8, 11, 13, 15, 17, 19, 20, 22, 24, 26, 和 28。
```

**约束条件**

- `1 <= num <= 1000`

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  
最直接的想法就是把 **1 到 num** 的所有整数都枚举一遍，逐个算出它们的“数位和”（把每一位上的数字相加），然后判断这个和是奇数还是偶数，偶数的就计数。  

- **用到的数据结构**：只需要一个普通的整数变量来保存当前的计数，和一个函数来把整数拆成各个位上的数字。把整数拆成数字的过程可以想象成 **查字典**：字典的 key 是“位”，value 是“该位的数字”。我们不真的建字典，只是用取余 `% 10` 把最右边的数字“取出来”，再除以 10 把整数往左“移动”。  
- **为什么正确**：因为我们把 **所有** ≤ num 的正整数都检查了一遍，只要数位和是偶数，就把它计入答案，所以不会漏掉也不会多计。  

#### 代码（Python）  

```python
def countEven(num: int) -> int:
    """
    暴力解：枚举 1~num，每个数求数位和，判断奇偶
    """
    def digit_sum(x: int) -> int:
        """返回整数 x 的数位和"""
        s = 0
        while x:            # 当 x 仍然大于 0 时循环
            s += x % 10      # 取最右边一位，加到 s 上
            x //= 10         # 去掉最右边一位
        return s

    ans = 0
    for i in range(1, num + 1):        # 遍历所有正整数
        if digit_sum(i) % 2 == 0:      # 如果数位和是偶数
            ans += 1                    # 计数
    return ans
```

#### 复杂度  

- **时间复杂度**：`O(num * log10(num))`  
  - 解释：外层循环要跑 `num` 次。每一次我们都要把当前数字的每一位取出来求和，取位的次数大约是数字的位数，即 `log10(num)`（比如 1234 需要 4 次取余）。所以总体时间是两者的乘积。  
- **空间复杂度**：`O(1)`  
  - 只用了常数个整数变量，和输入规模无关。

### 2. 最优解  

#### 思路  
暴力解的主要瓶颈在 **每次都重新遍历所有位**，导致时间是 `num * 位数`。如果我们能够在 **从 i 到 i+1** 的过程中，只用常数时间就更新“数位和”，就可以把整体时间降低到 `O(num)`。  

观察从 `i` 加 `1` 的过程：

1. **普通情况**（最低位不是 9）：  
   - 只会把最低位加 1，数位和也 **+1**，奇偶性会翻转。  

2. **出现进位的情况**（最低位是 9，可能有多个连续的 9）：  
   - 所有连续的 9 会变成 0（每个 9 变成 0，数位和 **-9**），  
   - 第一个非 9 的位会加 1（数位和 **+1**）。  
   - 设有 `k` 个连续的 9，则整体变化是 `-9*k + 1`。  
   - 由于 `-9 ≡ -1 (mod 2)`，变化的奇偶性等价于 `1 - k (mod 2)`。  
   - **如果 k 为偶数**，整体变化是 **奇数** → 奇偶性翻转；  
   - **如果 k 为奇数**，整体变化是 **偶数** → 奇偶性保持不变。  

利用这个规律，我们可以在 **O(1)** 的时间内得到下一个数的数位和奇偶性，而不必重新遍历所有位。  

实现步骤：

1. 先算出 `1` 的数位和（显然是 1），记录其奇偶性。  
2. 用一个循环从 `2` 到 `num`，每次根据上一次的奇偶性和当前数字末尾连续 9 的个数来决定本次奇偶性是否翻转。  
3. 若当前奇偶性是 **偶数**，计数器 `ans` 加一。  

#### 代码（Python）  

```python
def countEven(num: int) -> int:
    """
    最优解：利用相邻整数数位和奇偶性的变化规律，只用 O(1) 更新
    """
    if num < 2:                 # 1 的数位和是 1（奇数），不计数
        return 0

    ans = 0                     # 计数结果
    cur_even = False            # 当前数字（从 1 开始）的数位和奇偶性，False 表示奇数

    # 从 1 开始遍历到 num
    for i in range(1, num + 1):
        if cur_even:            # 若当前数的数位和是偶数，计入答案
            ans += 1

        # 计算 i+1 的奇偶性
        # 看 i 的最低位有多少个连续的 9
        x = i
        trailing_nines = 0
        while x % 10 == 9:      # 只要最低位是 9，就继续向左数
            trailing_nines += 1
            x //= 10

        # 根据前面分析的规律更新奇偶性
        # 若 trailing_nines 为偶数（包括 0），奇偶性翻转；否则保持不变
        if trailing_nines % 2 == 0:
            cur_even = not cur_even   # 翻转奇偶性
        # 若是奇数个 9，cur_even 保持原样，不需要写代码

    return ans
```

> **代码解释**  
> - `cur_even` 保存 **当前 i 的数位和是否为偶数**，初始为 `False`（因为 1 的数位和是 1，奇数）。  
> - 循环结束前先把 `i` 本身的结果计入 `ans`，再准备好 `i+1` 的奇偶性。  
> - `trailing_nines` 用来统计 `i` 末尾连续的 9 有多少个。这个循环最多跑 `log10(i)` 次，但在整体 `O(num)` 里仍然是 **摊销 O(1)**，因为每次进位最多只会遍历一次被 “清零” 的 9。  
> - 根据 “偶数个 9 → 翻转，奇数个 9 → 不翻转” 的规则更新 `cur_even`。  

#### 复杂度  

- **时间复杂度**：`O(num)`  
  - 解释：主循环执行 `num` 次。循环体里除去统计连续 9 的那段，都是常数时间。统计 9 的过程在所有迭代中总共最多遍历每个数字的每一位一次（因为每次遍历的 9 在后面的迭代里已经变成 0），所以摊销下来仍是线性 `O(num)`。  
- **空间复杂度**：`O(1)`  
  - 只用了若干整数变量，和 `num` 大小无关。

## 心得  

- **核心技巧**：利用相邻整数之间“数位和奇偶性”的变化规律（进位时的奇偶性翻转规则），实现 **常数时间更新**。  
- **适用的题型**：  
  1. 需要统计满足某种“数位属性”（奇偶、是否为 0、是否为 5 的倍数等）的整数个数。  
  2. 需要在 **连续区间** 内快速判断数位函数的变化，如“前缀和的奇偶性”“数位异或”等。  
- **一句话总结解题钥匙**：**观察相邻数的数位和如何变化，利用进位的奇偶性规律实现 O(1) 更新**。

## 反思  

- **第一反应**：直接枚举、逐个求数位和——最直观也最安全的办法。  
- **最容易踩的坑**：  
  - 忘记把 **1** 包含进来（题目要求“正整数 ≤ num”）。  
  - 在进位时误以为奇偶性一定翻转，实际上需要区分 **连续 9 的个数** 的奇偶性。  
  - 对 `num` 为极小值（如 1）时的边界处理不当。  
- **下次遇到同类题**：第一步先思考 **“相邻数字的数位属性会怎么改变？”**，如果能找到只依赖常数时间的更新规则，就可以把暴力的 `O(num·位数)` 优化到 `O(num)`。
