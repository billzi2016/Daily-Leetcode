# #2289. **使数组非递减的步数** / Steps to Make Array Non-decreasing

> 难度：中等 · 标签：Array、Linked List、Stack、Monotonic Stack · [LeetCode 链接](https://leetcode.com/problems/steps-to-make-array-non-decreasing/)

## 题目（英文原版）

**Description**

You are given a 0-indexed integer array nums. In one step, remove all elements nums[i] where nums[i - 1] > nums[i] for all 0 < i < nums.length.
Return the number of steps performed until nums becomes a non-decreasing array.

**Examples**

**Example 1:**

```
Input: nums = [5,3,4,4,7,3,6,11,8,5,11]
Output: 3
Explanation: The following are the steps performed:
- Step 1: [5,3,4,4,7,3,6,11,8,5,11] becomes [5,4,4,7,6,11,11]
- Step 2: [5,4,4,7,6,11,11] becomes [5,4,7,11,11]
- Step 3: [5,4,7,11,11] becomes [5,7,11,11]
[5,7,11,11] is a non-decreasing array. Therefore, we return 3.
```

**Example 2:**

```
Input: nums = [4,5,7,7,13]
Output: 0
Explanation: nums is already a non-decreasing array. Therefore, we return 0.
```

**Constraints**

- 1 <= nums.length <= 105
- 1 <= nums[i] <= 109

## 题目（中文翻译）

给定一个下标从 0 开始的整数数组 `nums`。一次操作中，删除所有满足 `nums[i‑1] > nums[i]` 的元素，其中 `0 < i < nums.length`。返回执行上述操作的次数，直至 `nums` 变为非递减数组（non-decreasing array）。

**示例 1**

```text
Input: nums = [5,3,4,4,7,3,6,11,8,5,11]
Output: 3
Explanation: 进行的步骤如下：
- 第 1 步： [5,3,4,4,7,3,6,11,8,5,11] → [5,4,4,7,6,11,11]
- 第 2 步： [5,4,4,7,6,11,11] → [5,4,7,11,11]
- 第 3 步： [5,4,7,11,11] → [5,7,11,11]
得到的数组 [5,7,11,11] 已经是非递减的。因此返回 3。
```

**示例 2**

```text
Input: nums = [4,5,7,7,13]
Output: 0
Explanation: 数组已经是非递减的，所以返回 0。
```

**约束条件**

- `1 <= nums.length <= 10^5`
- `1 <= nums[i] <= 10^9`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是**一次遍历找出所有需要被删除的元素**，然后把它们一起删掉，重复这个过程直到数组已经是「非递减」的（即左边的数永远不大于右边的数）。  

- **数据结构**：只需要原数组 `nums`，不需要额外的数据结构。可以把「把要删的元素标记出来」想象成在课堂上老师让我们把不符合规则的同学举手，所有举手的同学一起离开教室。  
- **为什么正确**：题目本身说「在一步中，删除所有满足 `nums[i‑1] > nums[i]` 的 `i`」。我们每一步都完整地执行这一步骤，所以最终得到的数组一定满足「左边不大于右边」的要求。  
- **时间/空间复杂度**：  
  - 每一步我们要遍历整个数组一次，找出要删的下标，最坏情况下可能会删掉 **一个元素**（比如 `[5,4,3,2,1]` 每一步只删掉最右侧的 `1`），于是需要 **`n` 步** 才能结束。  
  - 每一步遍历 `n` 个元素，`n` 步下来总共是 `n × n = n²` 次操作。  
  - 只用了常数级的额外空间（几个临时变量），所以空间是 **O(1)**。  
  - 大白话解释：如果数组有 10,000 个数，最坏情况下要做 10,000 次遍历，每次遍历 10,000 个数，总共大约 100,000,000 次比较，这就是 **O(n²)** 的意思——随数组长度的平方增长。

#### 代码（Python）

```python
def steps_bruteforce(nums):
    """
    暴力模拟题目描述的每一步删除过程
    """
    steps = 0                     # 记录已经执行了多少步
    while True:
        # 找出本轮需要删除的下标
        to_remove = []            # 用列表收集所有满足 nums[i-1] > nums[i] 的 i
        for i in range(1, len(nums)):
            if nums[i - 1] > nums[i]:
                to_remove.append(i)

        # 如果本轮没有任何元素需要删除，说明已经是非递减数组，结束循环
        if not to_remove:
            break

        # 把要删除的元素一次性移除（从左到右遍历会导致下标错位，倒序删除更安全）
        # 这里用列表推导式重新生成数组也可以，思路更直观
        new_nums = [nums[i] for i in range(len(nums)) if i not in to_remove]
        nums = new_nums
        steps += 1                # 步数加一

    return steps
```

#### 复杂度

- **时间复杂度**：**O(n²)**  
  - 每一步 O(n) 的遍历，最坏需要 O(n) 步才能把数组变为非递减。  
- **空间复杂度**：**O(n)**（若使用 `new_nums` 重新构造数组）  
  - 需要额外的列表保存新数组，大小最多和原数组相同。若在原地用 `pop` 删除，则可以降到 O(1)。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**每一步都要重新遍历整个数组**。我们需要一次遍历就能知道每个元素**到底会在第几步被删掉**，然后答案就是所有元素的最大「删除步数」。  

关键观察（提示已经给出）：

1. **只要左边有一个更大的数，当前元素迟早会被删掉**。  
2. 对每个位置 `i`，它被删掉的步数只取决于**左边比它大的最近的那个元素**以及**那些在它左边、比它小的元素的删除步数**。  

这正好可以用 **单调递减栈**（Monotonic Stack）来维护。栈里只存「**递减**」的元素下标，这样：

- 当我们看到一个新元素 `nums[i]` 时，栈顶（最近的左侧元素）一定是**比它小**的（因为栈是递减的）。  
- 为了找到左侧第一个**大于** `nums[i]` 的位置，需要把栈中所有 **小于等于** `nums[i]` 的元素弹出。弹出的过程顺便把它们的「删除步数」传递给 `i`。  

我们用数组 `dp[i]` 表示「元素 `i` 被删除的步数」：

- 初始时 `dp[i] = 0`（如果它永远不会被删掉）。  
- 当弹出一个下标 `j`（`nums[j] < nums[i]`）时，`i` 必须等 **至少** `dp[j] + 1` 步才能把 `j` 之后的「更小」元素都清除干净，然后再和 `i` 比较。  
- 同时，如果 `i` 的左侧已经有一个更大的元素 `k`（栈中剩下的下一个元素），`i` 只能在 `k` 被删掉的那一步之后才可能被删掉，因此 `dp[i]` 还需要取 **`dp[k] + 1`**。  
- 综合起来，`dp[i] = max( max_{j popped} (dp[j] + 1), 1 )`，其中 `1` 表示如果左侧直接有更大的元素，它至少在第 1 步被删掉。  

实现细节：

1. 用栈 `stack` 保存「仍然可能影响后面元素的下标」——即保持 **递减** 的 `nums[stack[-1]] > nums[stack[-2]] > …`。  
2. 对每个 `i`：
   - `cur = 0` 用来记录弹出元素时的最大 `dp[j] + 1`。  
   - 当栈不为空且 `nums[stack[-1]] < nums[i]` 时，弹出 `stack.pop()`，并更新 `cur = max(cur, dp[popped] + 1)`。  
   - 弹完后，如果栈仍然非空，说明左侧最近的更大元素存在，`dp[i] = max(cur, 1)`（即至少第 1 步）。否则 `dp[i] = 0`（永远不会被删）。  
   - 把 `i` 入栈。  
3. 最后答案是 `max(dp)`，因为所有元素中需要最多步数的那个决定了整个过程的步数。

**类比**：把数组想象成一条河流，水流从左向右冲。每当出现一个更高的堤坝（更大的数），它会把左边低洼的地方冲垮（删除）。我们用单调栈记录「当前最高的堤坝」的位置，弹出比新堤坝低的旧堤坝，同时记录它们被冲垮需要多少轮水（步数）。

#### 代码（Python）

```python
def steps_to_make_non_decreasing(nums):
    """
    单调递减栈 + DP，O(n) 时间一次遍历得到每个元素的删除步数
    """
    n = len(nums)
    dp = [0] * n               # dp[i] 表示 nums[i] 被删除的步数，0 表示永远不删
    stack = []                 # 栈中保存「递减」的下标
    answer = 0                 # 记录所有 dp 的最大值，即最终答案

    for i, x in enumerate(nums):
        cur = 0                 # 记录弹出元素时的最大 dp + 1
        # 弹出所有比当前元素小的下标
        while stack and nums[stack[-1]] < x:
            idx = stack.pop()
            # 弹出的元素在第 dp[idx] 步被删，这一步后它不再阻挡 i
            cur = max(cur, dp[idx] + 1)

        if stack:               # 栈不空说明左侧还有更大的元素
            # i 至少在第 1 步被删（因为左侧有更大的数），
            # 但如果弹出过程产生了更大的 cur，则取最大值
            dp[i] = max(cur, 1)
        else:
            # 左侧没有更大的数，i 永远不会被删
            dp[i] = 0

        stack.append(i)         # 把当前下标加入栈，继续影响后面的元素
        answer = max(answer, dp[i])   # 更新全局最大步数

    return answer
```

#### 复杂度

- **时间复杂度**：**O(n)**  
  - 每个下标最多被压入栈一次、弹出一次，整个过程是线性遍历。相比暴力的 O(n²)，这里的运行时间只随数组长度线性增长。  
- **空间复杂度**：**O(n)**  
  - `dp` 数组和栈最坏情况下都可能存储全部 `n` 个下标，使用的额外空间与输入规模成正比。

## 心得

- **核心技巧**：**单调栈 + 动态规划**，用栈快速找到左侧最近的大于当前元素的位置，同时记录「被删除的轮数」。
- **适用的题型**  
  1. 「每个元素在左侧第一次出现比它大的数」的相关问题（如 LeetCode 901. 股票价格跨度）。  
  2. 「删除元素直到满足某种单调性」的题目（如本题、LeetCode 2289. steps to make array non-decreasing）。  
  3. 「求每个元素的最近更大/更小元素」的经典单调栈题目（如 Next Greater Element）。
- **一句话总结解题钥匙**：**用单调栈一次遍历找出「左侧最近更大」的阻挡者，并把它们的「删除轮数」向右传播**。

## 反思

- **第一反应**：看到「每一步删除所有左侧更大的元素」就想到**模拟**，于是写了暴力循环。  
- **最容易踩的坑**  
  1. **弹出顺序**：在单调栈里弹出比当前元素小的下标时，需要把它们的 `dp` 加 1 再取最大，否则会低估删除步数。  
  2. **没有更大元素的情况**：如果栈空，`dp[i]` 必须设为 0，表示永远不会被删除。忘记这一步会把答案误算成 1。  
  3. **整数溢出/边界**：`dp` 可能达到 `n`（最坏情况每一步只删一个），所以要用足够大的整数类型（Python 自动处理）。  
- **下次类似题的第一步**：先判断「是否可以用单调栈一次遍历把左侧最近的「更大/更小」信息收集起来」，再考虑把这些信息转化为 DP 或计数。这样往往能把 O(n²) 的暴力直接提升到 O(n)。
