## 题目（中文翻译）

给定两个整数 `num1` 和 `num2`，返回它们的和。

示例 1:
Input: num1 = 12, num2 = 5
Output: 17
Explanation: `num1` 为 12，`num2` 为 5，它们的和为 12 + 5 = 17，返回 17。

示例 2:
Input: num1 = -10, num2 = 4
Output: -6
Explanation: `num1` + `num2` = -6，返回 -6。

约束条件：
- -100 ≤ num1, num2 ≤ 100

## 解题过程

### 1. 直觉解（暴力）

#### 思路  
最直接的想法是把“加法”拆成一次一次的**加 1**（或者 **减 1**）来完成。  
- **数据结构**：这里根本不需要额外的数据结构，只要用两个整数变量 `a`、`b`，以及一个计数器 `res`。
- **生活类比**：想象你在数数，从 `num1` 开始，每次往前走一步（+1），走 `num2` 步就到达答案。如果 `num2` 是负数，就往后走（-1）。  
- **正确性**：每走一步就相当于把 `num2` 的值向 0 推进一次，同时把对应的步数累加到 `res`，当 `num2` 变成 0 时，`res` 正好等于 `num1 + num2`。  
- **复杂度分析**：  
  - **时间**：需要循环 `|num2|` 次（即 `num2` 的绝对值），所以是 **O(|num2|)**。如果 `num2` 最大是 100，最多循环 100 次，仍然是线性时间。  
  - **空间**：只用常数个变量，**O(1)**，不随输入大小增长。

#### 代码（Python）

```python
def add_brute(num1: int, num2: int) -> int:
    """
    通过一次一次加/减 1 来实现两数相加
    """
    result = num1          # 先把 num1 当作初始值
    # 当 num2 为正数时，一次加 1；为负数时，一次减 1
    while num2 != 0:       
        if num2 > 0:       # 正数 -> 向前走一步
            result += 1
            num2 -= 1      # 把 num2 向 0 推进
        else:              # 负数 -> 向后走一步
            result -= 1
            num2 += 1
    return result
```

#### 复杂度

- **时间复杂度**：`O(|num2|)`  
  这意味着如果 `num2 = 100`，最多需要跑 100 次循环；如果 `num2 = -50`，最多跑 50 次。时间随 `num2` 的绝对值线性增长。
- **空间复杂度**：`O(1)`  
  只用了几个整数变量，和输入规模无关。

### 2. 最优解

#### 思路  
上面的暴力方法每次只前进一步，显然 **慢在循环次数上**。  
Python（以及大多数编程语言）已经为我们实现了整数的**直接相加**——只需要使用内置的 `+` 运算符。  
- **核心技巧**：利用语言本身提供的算术运算，时间上是常数级别 `O(1)`，因为 CPU 能在一次机器指令内完成整数相加。  
- **为什么可以**：整数相加是底层硬件的基本操作，复杂度与输入大小（这里的 `num1`、`num2` 的值）无关，只和位宽有关（这里都是 32 位以内的整数，LeetCode 已经保证不会溢出）。  

#### 代码（Python）

```python
def add(num1: int, num2: int) -> int:
    """
    直接使用 Python 的加法运算符返回两数之和
    """
    return num1 + num2   # 一行代码搞定
```

#### 复杂度

- **时间复杂度**：`O(1)`  
  不管 `num1`、`num2` 多大，都是一次固定时间的机器指令完成相加。
- **空间复杂度**：`O(1)`  
  只返回一个整数，额外的空间开销为常数。

## 心得

- **核心技巧**：把“数学运算”交给语言本身的算子，而不是自己手动模拟。  
- **适用的题型**：  
  1. 基础数学运算题（如两数相减、两数相乘等）  
  2. 需要利用位运算实现加法/减法的进阶题（如「无加号实现两数相加」）  
  3. 需要快速求和的数组/列表题（如「数组求和」）  
- **一句话总结**：**直接用 `+`，别把本该一次完成的事拆成多次循环**。

## 反思

- **第一反应**：看到“加法”，本能会想到循环累加，因为在没有 `+` 的语言里只能这样实现。  
- **最容易踩的坑**：  
  - 忘记处理 `num2` 为负数的情况（会导致死循环）。  
  - 对于极端输入（如 `-100` 与 `100`），仍需确保不越界，但本题约束已保证安全。  
- **下次遇到同类题的第一步**：先问自己 “语言已经提供了对应的算子吗？如果有，直接使用它；如果没有，再考虑手动模拟”。
