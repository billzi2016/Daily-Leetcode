# #2475. 数组中不相等三元组的数量 / Number of Unequal Triplets in Array

## 题目（英文原版）

**Description**

You are given a 0-indexed array of positive integers nums. Find the number of triplets (i, j, k) that meet the following conditions:
Return the number of triplets that meet the conditions.

**Examples**

**Example 1:**

```
Input: nums = [4,4,2,4,3]
Output: 3
Explanation: The following triplets meet the conditions:
- (0, 2, 4) because 4 != 2 != 3
- (1, 2, 4) because 4 != 2 != 3
- (2, 3, 4) because 2 != 4 != 3
Since there are 3 triplets, we return 3.
Note that (2, 0, 4) is not a valid triplet because 2 > 0.
```

**Example 2:**

```
Input: nums = [1,1,1,1,1]
Output: 0
Explanation: No triplets meet the conditions so we return 0.
```

**Constraints**

- 3 <= nums.length <= 100
- 1 <= nums[i] <= 1000

## 题目（中文翻译）

给定一个 **0 索引（0-indexed）** 的正整数数组（array）`nums`。请统计满足下列条件的三元组（triplet）`(i, j, k)` 的数量：

- `0 <= i < j < k < nums.length`
- `nums[i] != nums[j]` 且 `nums[j] != nums[k]` 且 `nums[i] != nums[k]`

返回满足条件的三元组数量。

## 示例

### 示例 1
**输入**：`nums = [4,4,2,4,3]`  
**输出**：`3`  
**解释**：满足条件的三元组如下：
- `(0, 2, 4)` 因为 `4 != 2 != 3`
- `(1, 2, 4)` 因为 `4 != 2 != 3`
- `(2, 3, 4)` 因为 `2 != 4 != 3`

共计 3 个三元组，返回 `3`。  
注意，`(2, 0, 4)` 不是合法的三元组，因为 `2 > 0`，不满足 `i < j < k`。

### 示例 2
**输入**：`nums = [1,1,1,1,1]`  
**输出**：`0`  
**解释**：没有任何三元组满足条件，返回 `0`。

## 约束条件
- `3 <= nums.length <= 100`
- `1 <= nums[i] <= 1000`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的办法就是把所有可能的三元组枚举一遍。  
- 用 **三层循环**，外层遍历 `i`，中层遍历 `j`，内层遍历 `k`，并且保证 `i < j < k`（就像排队时只能前面的人先出），这样就能遍历到所有合法的下标组合。  
- 对每个组合检查三条“不相等”条件：`nums[i] != nums[j]`、`nums[j] != nums[k]`、`nums[i] != nums[k]`。如果都满足，就把计数器加一。  

**为什么正确？**  
因为题目要求的就是“所有满足 i<j<k 且三数互不相等的三元组”。只要我们把 **所有** 可能的下标组合都尝试一次，并且严格检查条件，就不会漏掉任何合法答案，也不会误计不合法的情况。

**复杂度分析（大白话）**  
- 时间复杂度：三层循环相当于把 `n`（数组长度）**三次方**遍历一遍，用数学记号写成 `O(n³)`。如果 `n = 100`，最多要检查 `100·99·98 / 6 ≈ 1.6 万` 次，这在电脑里几乎是瞬间完成的。  
- 空间复杂度：只用了几个计数变量，和输入规模无关，用 `O(1)` 表示，即“常数级”占用。

#### 代码（Python）

```python
def count_unequal_triplets(nums):
    n = len(nums)
    ans = 0                       # 记录符合条件的三元组数量
    # 第一个下标 i，从 0 到 n-3（因为后面还要留出 j、k）
    for i in range(n - 2):
        # 第二个下标 j，必须在 i 之后
        for j in range(i + 1, n - 1):
            # 第三个下标 k，必须在 j 之后
            for k in range(j + 1, n):
                # 检查三个数是否两两不相等
                if nums[i] != nums[j] and nums[j] != nums[k] and nums[i] != nums[k]:
                    ans += 1      # 符合条件，计数器加一
    return ans
```

#### 复杂度

- **时间复杂度**：`O(n³)` —— 需要遍历所有三元组，`n` 越大，时间会呈立方增长。  
- **空间复杂度**：`O(1)` —— 只用了常数个额外变量，和数组长度无关。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **重复遍历**：很多三元组在数值上是相同的，只是下标不同，却被逐个检查。我们可以利用 **计数** 的思想把它们合并。

观察一下：如果我们知道每个不同数字出现的次数 `cnt[x]`，那么任选三个 **不同** 的数字 `a、b、c`（顺序随意），它们能组成的合法三元组数目等于  

```
cnt[a] * cnt[b] * cnt[c]
```

因为：
- 从出现 `a` 的位置里任选一个下标（`cnt[a]` 种），
- 再从出现 `b` 的位置里任选一个下标（`cnt[b]` 种），
- 再从出现 `c` 的位置里任选一个下标（`cnt[c]` 种），
- 这三个下标自然可以按大小排列成唯一的 `(i, j, k)`（因为我们只关心 **是否存在**，不需要显式排序）。

因此，只要把所有 **不同数字的组合** 枚举一遍并累加乘积，即可得到答案。这里的枚举只在 **不同的数值** 上进行，而不是下标上，数量大幅减少。

实现步骤：

1. **统计频率**：用哈希表（Python 的 `dict` 或 `Counter`）统计每个数出现了多少次。哈希表好比一本“词典”，键（key）是数字，值（value）是出现次数。  
2. 把所有不同的数字放进列表 `unique`，其长度记为 `m`。`m` 最多是 `100`（因为数组长度 ≤ 100），远远小于 `n³`。  
3. 用 **三层循环** 在 `unique` 上枚举 `i < j < k`（这里的 `i、j、k` 是列表下标，不是原数组下标），对每组不同数字累加 `cnt[unique[i]] * cnt[unique[j]] * cnt[unique[k]]`。  
4. 返回累计的结果。

**为什么正确？**  
- 任何合法三元组必然由 **三种不同的数值** 组成。我们遍历了所有不同数值的组合，且对每种组合计入了所有可能的下标选取方式，正好对应题目要求的所有合法三元组。  
- 计数乘积不会产生重复计数，因为我们固定了数值的顺序（`i < j < k`），每组不同数字只算一次。

**复杂度分析（大白话）**  
- 时间复杂度：统计频率是 `O(n)`，枚举不同数字的三元组是 `O(m³)`，而 `m ≤ n ≤ 100`，所以最坏也是 `O(100³)`，但实际 `m` 往往更小（因为会有重复），且常数更低。相较于直接遍历下标的 `n³`，这已经是 **显著优化**。  
- 空间复杂度：哈希表存放至多 `m` 个键值对，用 `O(m)` 额外空间，最多 `O(n)`，在本题规模下也可以看作常数级别。

#### 代码（Python）

```python
from collections import Counter
from itertools import combinations

def count_unequal_triplets(nums):
    # 1️⃣ 统计每个数字出现的次数，类似查字典：key 是数字，value 是出现次数
    freq = Counter(nums)          # Counter 本质是 dict，自动统计

    # 2️⃣ 把所有不同的数字取出来，方便后面组合
    unique = list(freq.keys())
    m = len(unique)

    ans = 0
    # 3️⃣ 在不同数字集合上枚举三元组 (a, b, c)
    # 使用 combinations 可以直接得到 i<j<k 的组合，避免手写三层循环
    for a, b, c in combinations(unique, 3):
        # 对每组不同的数，乘上它们各自的出现次数，即为该组能产生的合法下标三元组数
        ans += freq[a] * freq[b] * freq[c]

    return ans
```

> **提示**：如果不想使用 `itertools.combinations`，也可以手写三层循环，只遍历 `unique` 列表的下标 `i < j < k`，逻辑完全相同。

#### 复杂度

- **时间复杂度**：`O(n + m³)`  
  - `O(n)` 用于一次遍历统计频率。  
  - `O(m³)` 用于在不同数字上枚举三元组（`m` 是不同数字的个数，最大不超过 `n`）。相较于暴力的 `O(n³)`，在有重复元素时会快很多。  
- **空间复杂度**：`O(m)`（哈希表存放频率），最多 `O(n)`，属于线性额外空间。

## 心得

- **核心技巧**：**频率计数 + 组合计数**。先把相同的元素“聚在一起”，再在不同的“种类”上做组合，避免了大量无意义的下标遍历。  
- **适用的题型**  
  1. 统计满足“元素两两不同”或“元素相同”条件的子序列/子数组（如 “不同的三元组数”、 “等值三元组数”）。  
  2. 需要对“出现次数”进行乘法组合的计数问题（如 “好子集数目”）。  
  3. 任何可以先把相同元素合并，然后在“种类”上枚举的组合类问题。  
- **一句话总结解题钥匙**：**先把相同的东西归类，用计数代替枚举**。

## 反思

- **第一反应**：看到 “三元组” 立刻想到三层循环直接遍历。因为约束很小，先写出最直观的暴力解最安心。  
- **最容易踩的坑**  
  1. 忘记检查 **所有三对** 不相等，只检查了两对会产生错误计数。  
  2. 对下标顺序的要求不明确，导致计数时出现重复（如把 `(2,0,4)` 也算进去了）。  
  3. 在最优解里，如果直接把 `cnt[a] * cnt[b] * cnt[c]` 相加，却忘记只枚举 **不同的数值组合**，会把相同数值的组合算进来，导致答案偏大。  
- **下次类似题目第一步**：先思考 “是否可以先统计频率”，把重复元素合并后再在种类上做组合；如果不能合并，再考虑双指针、滑动窗口等更高级的技巧。
