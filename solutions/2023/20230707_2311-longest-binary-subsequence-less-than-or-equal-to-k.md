# #2311. 最长二进制子序列，使其数值 ≤ K / Longest Binary Subsequence Less Than or Equal to K

> 难度：中等 · 标签：String、Dynamic Programming、Greedy、Memoization · [LeetCode 链接](https://leetcode.com/problems/longest-binary-subsequence-less-than-or-equal-to-k/)

## 题目（英文原版）

**Description**

You are given a binary string s and a positive integer k.
Return the length of the longest subsequence of s that makes up a binary number less than or equal to k.
Note:

**Examples**

**Example 1:**

```
Input: s = "1001010", k = 5
Output: 5
Explanation: The longest subsequence of s that makes up a binary number less than or equal to 5 is "00010", as this number is equal to 2 in decimal.
Note that "00100" and "00101" are also possible, which are equal to 4 and 5 in decimal, respectively.
The length of this subsequence is 5, so 5 is returned.
```

**Example 2:**

```
Input: s = "00101001", k = 1
Output: 6
Explanation: "000001" is the longest subsequence of s that makes up a binary number less than or equal to 1, as this number is equal to 1 in decimal.
The length of this subsequence is 6, so 6 is returned.
```

**Constraints**

- 1 <= s.length <= 1000
- s[i] is either '0' or '1'.
- 1 <= k <= 109

## 题目（中文翻译）

给定一个二进制字符串（binary string）`s` 和一个正整数 `k`。  
返回 `s` 中能够组成一个二进制数（binary number）且该数值 **小于等于** `k` 的最长子序列（subsequence）的长度。

---

### 示例

**示例 1**  
Input: `s = "1001010"`, `k = 5`  
Output: `5`  
**解释**：`"00010"` 是 `s` 的一个最长子序列，其组成的二进制数等于十进制的 `2`，满足 ≤ 5。  
同样的，`"00100"`（十进制 4）和 `"00101"`（十进制 5）也符合条件。该子序列的长度为 5，故返回 5。

**示例 2**  
Input: `s = "00101001"`, `k = 1`  
Output: `6`  
**解释**：`"000001"` 是 `s` 的最长子序列，组成的二进制数等于十进制的 `1`，满足 ≤ 1。该子序列的长度为 6，故返回 6。

---

### 约束条件

- `1 <= s.length <= 1000`
- `s[i]` 仅为 `'0'` 或 `'1'`
- `1 <= k <= 10^9`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**把所有可能的子序列都枚举一遍**，然后把每个子序列当作二进制数转成十进制，检查它是否 ≤ k，满足条件的就记录它的长度，最后取最大值。

- **子序列**：把原字符串的若干字符删掉，剩下的字符顺序不变。例如 `"1001010"` 的子序列可以是 `"0010"`、`"101"`、`"0"` ……  
- **枚举子序列**：相当于对每个位置决定“保留”或“删除”。如果字符串长度是 `n`，就有 `2ⁿ` 种决定（每位 2 种选择），所以要遍历 `2ⁿ` 个子序列。  
- **把二进制转十进制**：把子序列看成二进制数，从左到右依次乘以 2 并累加。可以想象查字典的过程：字典的**键**是二进制位，**值**是对应的十进制权值（1、2、4、8…）。

为什么这个方法**一定正确**？因为我们把**所有**合法的子序列都检查了一遍，最长的自然不会漏掉。唯一的缺点是 **时间太长**——`2ⁿ` 在 `n = 1000` 时根本算不完。

#### 代码（Python）

```python
from itertools import product

def longest_subseq_bruteforce(s: str, k: int) -> int:
    n = len(s)
    best = 0                     # 记录目前找到的最长合法长度

    # product([0,1], repeat=n) 会产生 0/1 的所有组合，0 表示删除，1 表示保留
    for mask in product([0, 1], repeat=n):
        # 先把子序列拼成二进制字符串
        subseq = [s[i] for i in range(n) if mask[i] == 1]
        if not subseq:           # 空子序列不算
            continue

        # 把二进制字符串转成十进制整数
        val = 0
        for ch in subseq:
            val = val * 2 + (ch == '1')   # (ch == '1') 会得到 0 或 1

        # 判断是否合法
        if val <= k:
            best = max(best, len(subseq))

    return best
```

> 这段代码只适合**教学演示**，在真实的 LeetCode 数据上会直接超时。

#### 复杂度

- **时间复杂度**：`O(2ⁿ · n)`  
  - `2ⁿ` 是所有子序列的个数，`n` 是把每个子序列转成十进制时的遍历长度。  
  - 用大白话说，就是“随着字符串长度每增加 1，运行时间会翻一倍”，所以即使 `n = 30` 也已经非常慢了，更别说 1000。
- **空间复杂度**：`O(n)`  
  - 只用了几个长度为 `n` 的临时列表（比如 `subseq`），没有额外的递归或记忆化表。

### 2. 最优解

#### 思路  

从暴力解可以看到，**枚举所有子序列是多余的**。我们只需要关心**哪些‘1’需要被删掉**，因为**‘0’永远不会让数值变大**，可以全部保留。

**关键观察 1**：二进制数的数值大小由**位权**决定。位权越大（越左边），对应的十进制贡献越多。  
**关键观察 2**：在保持相对顺序的前提下，**越靠右的字符在最终子序列里越可能出现在低位**（位权小）。所以如果要“省钱”，我们应该**优先保留右边的‘1’**，而把左边的‘1’删掉。

换句话说：  
- 先把所有的 `0` 都算进去（它们不花钱）。  
- 再从字符串最右侧向左遍历，遇到 `1` 时尝试把它加入子序列。加入后它的位权是 `2⁰、2¹、2² …`，依次递增。只要当前已经累计的数值 `cur` 加上这一次的位权 `pow` 不超过 `k`，我们就可以保留这个 `1`，否则只能跳过（相当于把它删掉）。

**关键观察 3**：当位权已经大于 `k` 时，**再往左的任何 `1` 的位权都会更大**，根本不可能加入。此时我们只需要把左边剩余的 `0` 继续计数即可。

> 类比：把每个 `1` 看成一块价值为 `2ⁱ` 的硬币，预算是 `k`。我们想买尽可能多的硬币（因为每买一个硬币就能在子序列里多占一个位置），但只能从最便宜的硬币（右边的 `1`）开始挑。

**步骤概览**  

1. 统计字符串中 `0` 的总数 `zero_cnt`，先把它们全部加入答案。  
2. 从右到左遍历 `s`，维护  
   - `pow = 1` （当前 `1` 的位权，第一次对应最右边的位）  
   - `cur = 0` （已经加入的 `1` 的总价值）  
   - `ans = zero_cnt` （当前最长子序列的长度）  
3. 对每个字符 `c`：  
   - 如果 `c == '1'` 且 `cur + pow ≤ k`，则把它加入子序列：`cur += pow, ans += 1`。  
   - 否则直接跳过（相当于删掉）。  
   - `pow <<= 1`（位权左移一位，翻倍）。  
   - 当 `pow > k` 时，后面的 `1` 再也不可能加入，直接停止循环。  
4. 循环结束后，`ans` 即为答案。

**为什么是最优的？**  

- 我们始终保留所有 `0`（不会浪费位数）。  
- 对于 `1`，只保留**权值最小**且仍在预算内的那些，显然可以取得最多的 `1`，从而使子序列最长。  
- 任何把左边的 `1` 替换成右边的 `0`（或删掉右边的 `1`）都会让位权更大或长度更短，违背“最长”目标。

#### 代码（Python）

```python
def longest_subseq(s: str, k: int) -> int:
    """
    返回最长子序列的长度，使其二进制数 <= k
    思路：保留所有 0，尽可能从右往左保留 1，位权从 1 开始翻倍。
    """
    # 1️⃣ 统计全部 0 的个数，先全部算进答案
    zero_cnt = s.count('0')
    ans = zero_cnt          # 当前答案长度

    cur = 0                 # 已经加入的 1 对应的十进制和
    pow_val = 1             # 当前位权，最右边的位是 2^0 = 1

    # 2️⃣ 从右往左遍历字符
    for ch in reversed(s):
        if ch == '1':
            # 只有在加上当前位权后仍不超过 k，才保留这个 1
            if cur + pow_val <= k:
                cur += pow_val
                ans += 1   # 多占一个位置
        # 3️⃣ 位权左移一位（乘以 2）
        pow_val <<= 1
        # 4️⃣ 如果位权已经超过 k，后面的 1 再也不可能加入，直接停止
        if pow_val > k:
            break

    # 循环结束后，左边剩余的字符只有 0（因为 1 已经不可能加入），
    # 这些 0 已经在 zero_cnt 中计过了，所以直接返回 ans。
    return ans
```

#### 复杂度

- **时间复杂度**：`O(n)`  
  - 只遍历一次字符串（最坏情况下遍历完整个 `s`），每一步的操作是常数时间。  
  - 用大白话说，就是“字符串有多长，就花多少时间”，而不像暴力解那样指数级增长。
- **空间复杂度**：`O(1)`  
  - 只用了几个整数变量 (`zero_cnt, ans, cur, pow_val`)，不随输入规模增大而增加。

## 心得

- **核心技巧**：**从右到左贪心 + 位权递增**。把二进制位的价值视作“钱”，先买最便宜的（右侧的 `1`），在预算 `k` 内尽可能多买。
- **适用题型**  
  1. “最长子序列使其数值 ≤ 给定上限”类（如本题）。  
  2. “在二进制字符串中挑选子集，使得结果 ≤ K”或 “在十进制字符串中挑选子集，使和 ≤ K”。  
  3. “在数组中挑选元素，使加权和 ≤ 限制，且要最大化选取个数”——本质上同样是 **贪心挑最小权重**。
- **一句话总结**：**把每个 `1` 看成价值翻倍的硬币，先买最便宜的，所有 `0` 免费，预算用完后停止**。

## 反思

- **第一反应**：想到枚举所有子序列，马上意识到会超时，于是寻找可以“剪枝”的思路。  
- **最容易踩的坑**  
  1. **位权溢出**：`pow_val` 可能会变得非常大，但只要一旦超过 `k` 就可以直接停止循环。  
  2. **忘记计数左侧的 `0`**：循环提前结束后，左边可能还有未遍历的字符，必须确保这些字符全部是 `0`（因为更大的位权的 `1` 已经不可能加入），而我们已经在一开始把所有 `0` 加进答案。  
  3. **k = 0 的特殊情况**：此时只能保留 `0`，算法仍然有效，因为 `pow_val` 初始为 1，`pow_val > k` 会立即触发 break。  
- **下次遇到同类题**，第一步应该问自己：**“哪些元素对目标值没有影响（比如本题的 0）？”** 然后**“剩下的有代价的元素，如何按代价从小到大挑选？”** 这通常就是贪心的出发点。
