## 题目（中文翻译）

给定一个整数数组 `nums` 和一个整数 `k`，请统计满足以下条件的下标对 `(i, j)` 的数量（`i < j`）：

- `nums[i] == nums[j]`，即两个元素相等；
- `i * j` 能被 `k` 整除（`i * j % k == 0`）。

返回满足条件的数对总数。

**示例 1**  
输入: `nums = [3,1,2,2,2,1,3]`, `k = 2`  
输出: `4`  
解释: 满足所有要求的数对有 4 对：
- `nums[0] == nums[6]`，且 `0 * 6 == 0` 能被 `2` 整除。  
- `nums[2] == nums[3]`，且 `2 * 3 == 6` 能被 `2` 整除。  
- `nums[2] == nums[4]`，且 `2 * 4 == 8` 能被 `2` 整除。  
- `nums[3] == nums[4]`，且 `3 * 4 == 12` 能被 `2` 整除。  

**示例 2**  
输入: `nums = [1,2,3,4]`, `k = 1`  
输出: `0`  
解释: 由于 `nums` 中没有重复的值，不存在满足所有要求的数对 `(i, j)`。  

**约束条件**  
- `1 <= nums.length <= 100`  
- `1 <= nums[i], k <= 100`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是把所有可能的下标对 `(i, j)`（要求 `i < j`）都枚举一遍，逐个检查这两个条件：

1. `nums[i] == nums[j]`  —— 两个位置上的数字相等。  
2. `i * j` 能被 `k` 整除，即 `i * j % k == 0`。

如果这两个条件都满足，就把答案加一。

> **类比**：把数组想象成一排座位，`i`、`j` 是座位号。我们要找出“坐在相同号码的两个人”，并且这两个座位号的乘积能被 `k` 整除。最笨的办法就是把每一对座位号都拿出来检查一次，就像在派对上让每两个人互相打招呼一样。

只要遍历完所有下标对，就一定能得到正确答案，因为没有遗漏任何可能的组合。

#### 代码（Python）

```python
from typing import List

def countPairs(nums: List[int], k: int) -> int:
    n = len(nums)
    ans = 0                     # 计数器，记录满足条件的对数
    # 双层循环遍历所有 i < j 的组合
    for i in range(n):
        for j in range(i + 1, n):
            # 条件 1：数值相等
            if nums[i] != nums[j]:
                continue
            # 条件 2：下标乘积能被 k 整除
            if (i * j) % k == 0:
                ans += 1
    return ans
```

> **代码要点**  
> - 第 5 行的 `for i in range(n)` 固定左边的下标 `i`。  
> - 第 6 行的 `for j in range(i + 1, n)` 确保 `j` 永远在 `i` 右侧，满足 `i < j`。  
> - 第 9 行先判断数值是否相等，若不相等直接 `continue`，省掉后面的乘法运算。  
> - 第 11 行利用取模 `%` 判断能否整除。

#### 复杂度

- **时间复杂度**：`O(n²)`  
  解释：我们用了两层循环，外层遍历 `n` 次，内层最坏情况下也要遍历 `n` 次（实际上是 `n-1、n-2 …`），所以总体大约是 `n × n`，即平方级别。对 `n = 100` 来说最多是 `10,000` 次运算，完全可以接受，但如果 `n` 更大就会慢下来。

- **空间复杂度**：`O(1)`  
  解释：只用了几个常数级别的变量（计数器、下标），不随输入规模增长而增长。

### 2. 最优解

#### 思路  

暴力解的 **瓶颈** 在于我们把所有下标对都列出来检查，即使很多对根本不可能满足第一个条件（数值相等）。  
我们可以利用 **哈希表**（Python 中的 `dict`）把相同数值的下标聚集在一起，只在同一数值内部进行配对。

进一步地，针对第二个条件 `i * j % k == 0`，我们可以把它转化为对 **下标的可整除性** 的要求：

> 对固定的 `i`，只要 `j` 能让 `i * j` 被 `k` 整除，就说明 `j` 必须是 `k / gcd(i, k)` 的倍数。  
> 这里 `gcd` 是 “最大公约数”。举个例子：`k = 12，i = 8`，`gcd(8,12)=4`，于是 `j` 必须是 `12/4 = 3` 的倍数（即 `j = 0,3,6,9,…`）。

因为 `k ≤ 100`，我们可以为每一个数值维护一个长度为 `k+1`（或直接 101）的 **频率数组** `cnt`，其中 `cnt[t]` 表示已经遍历过的、下标恰好等于 `t`（`t` 在 `[0, n-1]` 范围内）的出现次数。  
当我们来到新下标 `i` 时，只需要把所有满足 `i * t % k == 0` 的 `t` 的计数相加，即可得到与 `i` 组成合法对的数量。

整个过程只遍历一次数组，内部最多检查 `k`（≤100）个可能的 `t`，时间复杂度从 `O(n²)` 降到了 `O(n·k)`，在本题的约束下几乎是线性的。

> **类比**：把每个相同数字的座位号记在一本小本子里。每次有新朋友坐下（下标 `i`），我们只翻看本子里“能和他坐在一起（乘积能被 `k` 整除）”的座位号，而不是去看所有座位。

#### 代码（Python）

```python
from typing import List
import math

def countPairs(nums: List[int], k: int) -> int:
    """
    使用哈希表 + 频率数组实现 O(n·k) 的解法
    """
    ans = 0
    # dict: key 为数组中的数值，value 为长度为 k+1 的频率数组
    # freq[v][t] 表示值为 v、下标为 t 的出现次数（t 只会是 0~n-1 之间的整数）
    freq = {}

    for i, val in enumerate(nums):
        # 如果之前已经出现过相同的数值，就尝试与它们配对
        if val in freq:
            # 对于每一个可能的旧下标 t（0 <= t < i），检查是否满足可整除
            # 这里我们只需要遍历 0~i-1 中出现过的 t；但因为 k <= 100，直接遍历 0~k 即可
            for t in range(k + 1):
                if freq[val][t] == 0:          # 该下标 t 没出现过，直接跳过
                    continue
                if (i * t) % k == 0:           # 满足 i*t 能被 k 整除
                    ans += freq[val][t]        # 累加出现次数
        else:
            # 第一次遇到该数值，创建频率数组（全部初始化为 0）
            freq[val] = [0] * (k + 1)

        # 把当前下标 i 加入对应数值的频率表
        # 注意：下标 i 可能大于 k，但我们仍把它放在数组的第 i 位，
        # 为了不越界，这里把频率数组的长度改为 max(k, n) + 1
        # 为简化起见，直接把 freq[val] 扩容到足够大
        if i >= len(freq[val]):                     # 需要扩容
            freq[val].extend([0] * (i - len(freq[val]) + 1))
        freq[val][i] += 1

    return ans
```

> **代码要点**  
> 1. 第 9 行的 `freq` 用来把相同数值的下标集中管理。  
> 2. 第 14‑20 行：遍历已经出现的下标 `t`，只要 `i*t` 能被 `k` 整除，就把对应出现次数加入答案。  
> 3. 第 27‑33 行：把当前下标 `i` 加入频率数组。因为 `i` 可能大于 `k`，我们动态扩容保证不会越界。  

> **为什么是 O(n·k)**  
> - 外层循环遍历 `n` 次（每个元素一次）。  
> - 内层最多检查 `k+1 ≤ 101` 个下标 `t`。  
> - 其余操作都是 O(1) 的字典查找或数组访问。  
> 因此总体时间是 `n * (k+1)`，在最坏情况下约等于 `100 * 101 ≈ 10⁴`，几乎是线性的。

#### 复杂度

- **时间复杂度**：`O(n·k)`  
  解释：每个元素只遍历一次，内部最多检查 `k`（≤100）个可能的旧下标。相比暴力的 `O(n²)`，这里把“遍历所有对”压缩成了“遍历所有元素 × 常数（k）”。  

- **空间复杂度**：`O(m·k)`（`m` 为不同数值的个数，最坏 `m ≤ n`）  
  解释：我们为每个出现过的数值维护一个长度约为 `k`（或稍大）的频率数组。`n ≤ 100`，所以最多也只会占用几千个整数的空间，仍然是线性级别。

## 心得

- **核心技巧**：利用哈希表把相同数值的下标聚集，配合“下标乘积能被 `k` 整除”转化为对 **下标可整除性** 的检查，从而避免枚举所有下标对。  
- **适用的题型**  
  1. “统计满足某种下标关系的相同值对”——如 `countPairs`、`numberOfGoodPairs`（相同数值且下标差是奇数）。  
  2. “下标乘积 / 和 / 差满足模运算条件”——如 `countPairsDivisibleByK`、`pairSumDivisibleByM`。  
  3. “同值下标满足额外约束”——如 `goodPairsWithGCD`、`pairsWithLCMCondition`。  
- **一句话总结解题钥匙**：**先把相同数值的下标“聚在一起”，再用数学化简把乘积可整除的条件转化为对下标的简单可除性检查。**

## 反思

- **第一反应**：直接写双层循环暴力枚举——因为题目要求的两个条件都很直观。  
- **最容易踩的坑**  
  - 忘记 `i < j` 的顺序，导致重复计数。  
  - 下标从 **0** 开始时，`0 * anything = 0`，一定能被 `k` 整除，需要特别注意（示例 1 中的 `(0,6)`）。  
  - 当 `k = 1` 时，所有乘积都能被整除，但仍需满足数值相等的前提。  
- **下次遇到同类题**：第一步先 **用哈希表把相同数值的下标收集起来**，再思考能否把额外的下标关系（乘积、和、差的可整除性）用 **最大公约数 / 余数** 等数学工具化简，从而只遍历一次数组。
