# #2310. 单位数位为 K 的数之和 / Sum of Numbers With Units Digit K

> 难度：中等 · 标签：Math、Dynamic Programming、Greedy、Enumeration · [LeetCode 链接](https://leetcode.com/problems/sum-of-numbers-with-units-digit-k/)

---

## 题目（英文原版）

**Description**

Given two integers num and k, consider a set of positive integers with the following properties:
Return the minimum possible size of such a set, or -1 if no such set exists.
Note:

**Examples**

**Example 1:**

```
Input: num = 58, k = 9
Output: 2
Explanation:
One valid set is [9,49], as the sum is 58 and each integer has a units digit of 9.
Another valid set is [19,39].
It can be shown that 2 is the minimum possible size of a valid set.
```

**Example 2:**

```
Input: num = 37, k = 2
Output: -1
Explanation: It is not possible to obtain a sum of 37 using only integers that have a units digit of 2.
```

**Example 3:**

```
Input: num = 0, k = 7
Output: 0
Explanation: The sum of an empty set is considered 0.
```

**Constraints**

- 0 <= num <= 3000
- 0 <= k <= 9

---

## 题目（中文翻译）

给定两个整数 `num` 和 `k`，考虑满足以下属性的正整数（positive integer）集合：

- 集合中的每个整数的个位数字（units digit）都是 `k`。
- 所有整数的和恰好等于 `num`。

返回满足上述条件的集合的 **最小可能大小**（即集合中整数的最少个数），如果不存在这样的集合则返回 `-1`。

**注意**  
- 当 `num = 0` 时，空集合的和视为 `0`，此时答案为 `0`。

### 示例

**示例 1**  
```
输入: num = 58, k = 9
输出: 2
解释:
一个合法的集合是 [9, 49]，因为它们的和为 58 且每个整数的个位数字都是 9。
另一个合法的集合是 [19, 39]。
可以证明，2 是满足条件的集合的最小大小。
```

**示例 2**  
```
输入: num = 37, k = 2
输出: -1
解释: 无法仅使用个位数字为 2 的整数得到和为 37 的集合。
```

**示例 3**  
```
输入: num = 0, k = 7
输出: 0
解释: 空集合的和被视为 0。
```

### 约束条件

- `0 <= num <= 3000`
- `0 <= k <= 9`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**把所有可能的符合条件的整数列出来**，然后在这些数里挑选若干个，使它们的和恰好等于 `num`，并且挑选的个数最少。  

- **符合条件的整数**  
  每个数的个位必须是 `k`，于是它一定可以写成 `10·a + k`（`a` 为非负整数）。  
  - 如果 `k = 0`，最小的正整数是 `10`（`0` 不是正整数）。  
  - 如果 `k > 0`，最小的正整数就是 `k` 本身（`a = 0` 时得到 `k`）。  

  可以把 `10·a + k` 想象成 **“查字典”**：字典的 **key** 是十位数 `a`，**value** 是对应的完整数字 `10·a + k`。我们只要把所有可能的 `a`（从 0 开始，只要结果不超过 `num`）列出来，就得到所有合法的“单词”。  

- **枚举子集**  
  把这些合法数字当作“硬币”，求最少硬币数凑成金额 `num`。这正是 **完全背包**（unbounded knapsack）的问题——每种硬币可以用无限次。  
  用动态规划（DP）实现：`dp[x]` 表示凑成和 `x` 所需的最少数字个数。状态转移式为  

  ```
  dp[x] = min(dp[x - coin] + 1)   (遍历所有 coin <= x)
  ```

  初始条件 `dp[0] = 0`（空集合的和为 0，个数 0），其余设为无限大表示不可达。

- **正确性**  
  DP 的每一步都尝试把当前和 `x` 拆成「一个合法数字 + 剩余和 `x-coin`」的形式，递归地保证子问题已经得到最优解，所以整体也是最优的。

- **时间/空间复杂度**  
  - **时间**：外层遍历 `x = 1 … num`，内层遍历所有合法数字（约 `num/10` 个），于是时间复杂度约为 `O(num² / 10)`，在最坏情况下相当于 `O(num²)`。  
    - 大白话：如果 `num` 是 3000，算法大约要做 3000×300 次计算，算起来有点慢。  
  - **空间**：只保存一个大小为 `num+1` 的数组，空间复杂度 `O(num)`。

#### 代码（Python）

```python
def min_set_bruteforce(num: int, k: int) -> int:
    # 1. 生成所有合法的整数（硬币）
    coins = []
    if k == 0:
        # 只能是 10, 20, 30, ...
        a = 1
        while 10 * a <= num:
            coins.append(10 * a)
            a += 1
    else:
        a = 0
        while 10 * a + k <= num:
            coins.append(10 * a + k)
            a += 1

    # 2. DP：dp[x] 为凑成 x 所需的最小个数，初始为一个很大的数
    INF = 10 ** 9
    dp = [INF] * (num + 1)
    dp[0] = 0                     # 空集合的和是 0，个数也是 0

    # 3. 完全背包的状态转移
    for x in range(1, num + 1):
        for c in coins:           # 枚举每一种合法数字
            if c <= x:
                dp[x] = min(dp[x], dp[x - c] + 1)

    return -1 if dp[num] == INF else dp[num]
```

#### 复杂度

- **时间复杂度**：`O(num²)`（实际约为 `num × (num/10)`）。  
  - 解释：把 `num` 看成一堆砖块，外层一次放一块，内层遍历所有可能的砖形，砖形的数量跟 `num` 成正比，所以总体是平方级别的工作量。  
- **空间复杂度**：`O(num)`，只用了一个长度为 `num+1` 的数组来记录子问题的答案。

### 2. 最优解

#### 思路  

从暴力解可以看到，**真正的难点在于枚举所有合法数字**，这会导致 `O(num²)` 的时间。我们需要寻找一种只和 `num` 的规模线性相关的办法。

**关键观察 1：个位数的约束只影响余数**  
每个数都形如 `10·a + k`，所以它们的 **个位** 永远是 `k`。把 `m` 个这样的数相加，得到的总和的个位是  

```
(num % 10) = (m * k) % 10
```

换句话说，只要我们决定使用 **m 个数**，它们的和在模 10 意义下只能是 `m*k`（取模 10）。

**关键观察 2：十位可以随意增大**  
`10·a` 部分可以随意增大（只要不超过目标 `num`），相当于我们可以在已有的 `m` 个数上“随意加 10”。也就是说：

- 只要满足 `m*k ≤ num`（因为每个数最小是 `k`，`m` 个最小和就是 `m*k`），
- 并且 `num - m*k` 能被 10 整除（即 `(num - m*k) % 10 == 0`），  

那么我们一定可以把这 `m` 个数的十位调配成恰好等于 `num`。

**由此得到判定条件**  

> 存在一个正整数 `m`（可以为 0），满足  
> 1. `m * k ≤ num`  
> 2. `(num - m * k) % 10 == 0`  

如果满足，上述 `m` 就是一个可行的集合大小。我们要找最小的 `m`。

**特殊情况：k = 0**  
- 每个数的个位是 0，最小的正整数是 10（`10·1`），而不是 0。  
- 这时条件 1 变成 `m * 10 ≤ num`，而且 `num` 必须能被 10 整除。最小 `m` 就是 `num // 10`（`num = 0` 时返回 0）。

**求最小 m 的方法**  
只需从 `m = 0` 开始逐步尝试（最多到 `num // k`，因为 `m*k` 不能超过 `num`），第一个满足条件的 `m` 即为答案。遍历次数至多 `3000`（题目上限），时间复杂度 `O(num)`，空间几乎为 `O(1)`。

#### 代码（Python）

```python
def min_set_optimal(num: int, k: int) -> int:
    """
    返回最小的集合大小，使得每个数的个位是 k，且它们的和恰好等于 num。
    若不存在则返回 -1。
    """
    # 特殊情况：空集合的和是 0
    if num == 0:
        return 0

    # k = 0 的专门处理
    if k == 0:
        # 只能使用 10, 20, 30, ...，所以 num 必须是 10 的倍数
        return -1 if num % 10 != 0 else num // 10

    # 一般情况：k > 0
    # m 的上界可以取 num // k（因为 m*k 不能超过 num）
    max_m = num // k
    for m in range(1, max_m + 1):
        # 条件 1：m*k 已经不超过 num（这里必然满足，因为 m ≤ max_m）
        # 条件 2：剩余部分能被 10 整除
        if (num - m * k) % 10 == 0:
            return m

    # 没有任何 m 能满足条件，说明无解
    return -1
```

#### 复杂度

- **时间复杂度**：`O(num)`，最多遍历 `num // k ≤ 3000` 次。  
  - 大白话：我们只是在数字 `0…num` 上走一遍，每一步只做几次加减运算，速度和遍历一条长度为 3000 的路差不多，几乎是瞬间完成。  
- **空间复杂度**：`O(1)`，只用了常数个变量。

## 心得

- **核心技巧**：利用“个位数固定 → 余数约束 + 十位自由” 的数学特性，把原本的背包问题转化为**一次线性遍历**的判定问题。  
- **适用场景**：  
  1. **固定个位数求最少个数**（如本题、或 “所有数的个位是 5，求最少个数使和为 N”。）  
  2. **只关心模 `m` 的约束**，且每个元素还能自由增加某个公倍数（如 “每个数都能加 7”，求最小个数）。  
- **一句话总结解题钥匙**：**先把个位的约束抽出来变成模 10 的等式，再利用十位可以随意增大来判断是否可行，最小满足的个数就是答案。**

## 反思

- **第一反应**：看到“每个整数的个位是 k”，本能想到“枚举所有形如 10·a + k 的数”，于是想用背包 DP。  
- **最容易踩的坑**：  
  - `k = 0` 时忘记最小正整数是 10，导致把 0 当作合法数错误。  
  - 忽视 `num = 0` 的特殊情况，需要返回 0 而不是 -1。  
  - 只检查 `m*k ≤ num` 而忘记余数 `(num - m*k) % 10 == 0`，会产生错误的可行解。  
- **下次遇到同类题**：第一步先**写出模运算的必要条件**（比如 `sum % 10 = m*k % 10`），再检查**是否可以通过“加上公倍数”**（这里是 10）把剩余的差额填满；随后在满足条件的 `m` 中取最小即可。
