## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  
最直接的想法是先把数组里所有数字相乘，得到一个“大数”，再对这个大数做质因数分解，最后把出现过的质数去重计数。  
- **数据结构**：我们只需要一个普通的整数（用来存放乘积）和一个集合（`set`）来去重。集合可以类比成“字典的目录”，把每个出现的质数当作词条，只要出现一次就记下来，后面再出现就不再增加。  
- **为什么正确**：乘积的质因数就是所有因子里出现的质数的并集。把所有数相乘后整体分解，得到的质数集合一定和把每个数单独分解后取并集是一样的。  
- **时间/空间复杂度**：  
  - 乘所有数的时间是 O(n)，n 为数组长度。  
  - 对乘积做质因数分解需要遍历到 sqrt(乘积)（因为一个数的最大可能质因数不超过它的平方根），这在最坏情况下是 O(√P)，P 为乘积的大小。乘积会非常大（最多 1000^10⁴），根本无法在机器上存下，更别说遍历 sqrt(P) 了。  
  - 空间上我们只用了一个集合来保存质数，最多也就是所有可能质数的个数，记作 O(k)。  

> **大白话解释**：  
> - O(n) 就像排队买票，人数越多排队时间越长。  
> - O(√P) 就像把一本厚厚的字典从头翻到某一页，页数是字典总页数的平方根，页数越大翻得越慢。这里的 P 太大，根本翻不完。  

#### 代码（Python）  

```python
import math

def distinctPrimeFactors_bruteforce(nums):
    # 1️⃣ 把所有数相乘，得到 product
    product = 1
    for x in nums:                 # 遍历数组，每个元素乘进来
        product *= x               # product 可能会非常非常大

    # 2️⃣ 对 product 做质因数分解，收集所有出现的质数
    primes = set()                  # 用集合去重
    d = 2
    while d * d <= product:         # 只需要检查到 sqrt(product)
        if product % d == 0:        # d 能整除 product，说明 d 是质因数
            primes.add(d)           # 把 d 加进集合
            while product % d == 0: # 把所有 d 的幂次都除掉
                product //= d
        d += 1                       # 继续检查下一个可能的质因数

    # 3️⃣ 如果最后 product > 1，说明剩下的 product 本身是质数
    if product > 1:
        primes.add(product)

    return len(primes)              # 集合大小就是不同质因数的个数
```

#### 复杂度  

- **时间复杂度**：`O(n + √P)`  
  - `n` 是数组长度，`√P` 是乘积的平方根。因为 `P` 可能非常大，这一步几乎不可能在实际机器上完成。  
- **空间复杂度**：`O(k)`  
  - `k` 为不同质因数的个数，最坏情况下不过几百（因为 `nums[i] ≤ 1000`），所以空间占用可以接受。

### 2. 最优解  

#### 思路  
从暴力解可以看到，**真正的瓶颈在于把所有数先乘起来**。乘积会爆炸，导致后面的因数分解根本不可行。  
实际上，我们并不需要整个乘积，只需要知道 **所有出现过的质数** 即可。  
**优化思路**：  
1. **逐个分解**：把数组里的每个数字单独做质因数分解。  
2. **统一收集**：把每次分解得到的质数放进同一个集合 `set`，自然就实现了去重。  
3. **无需乘积**：因为集合已经把所有质数合并，最终集合的大小就是答案。  

**核心算法/数据结构**  
- **质因数分解**：对一个不超过 1000 的整数进行分解，只需要检查到它的平方根（最多到 31 左右），非常快。可以把它想象成“把一块巧克力拆成最小的颗粒”。  
- **集合（set）**：类似字典的目录，只记录出现过的“颗粒”，重复的颗粒直接被忽略。  

**一步步推导**  
- 暴力解的第一步是把所有数乘起来，这一步的复杂度是 `O(n)`，但产生了巨大的数。  
- 若改为 **对每个数直接分解**，我们只做 `n` 次小规模的分解，每次分解的时间是 `O(√max(nums[i]))`，而 `max(nums[i]) ≤ 1000`，所以每次最多检查到 31。整体时间就是 `O(n * √1000)`，即 `O(n)`（常数很小）。  
- 空间上只需要一个集合保存质数，最多也就是所有小于 1000 的质数（共 168 个），所以 `O(1)`（相对于输入规模来说是常数）。  

#### 代码（Python）  

```python
def distinctPrimeFactors(nums):
    """
    返回 nums 中所有元素乘积的不同质因数个数
    思路：逐个分解每个数的质因数，统一放进集合即可
    """
    distinct = set()                     # 用集合自动去重

    for x in nums:                       # 遍历数组中的每个数
        v = x
        d = 2
        # 对当前数 v 做质因数分解，只需要检查到 sqrt(v)
        while d * d <= v:                # 当 d 的平方不超过 v 时继续
            if v % d == 0:               # d 能整除 v，说明 d 是质因数
                distinct.add(d)          # 把 d 加进集合
                while v % d == 0:        # 把所有 d 的幂次都除掉，防止重复
                    v //= d
            d += 1                        # 检查下一个可能的质因数
        # 循环结束后，如果 v > 1，说明剩下的 v 本身是质数
        if v > 1:
            distinct.add(v)

    return len(distinct)                 # 集合大小即为不同质因数的数量
```

#### 复杂度  

- **时间复杂度**：`O(n * √M)`，其中 `M = max(nums[i]) ≤ 1000`。因为 `√M ≤ 32`，可以视作常数，所以整体近似为线性 `O(n)`。  
  - 与暴力解相比，省掉了对巨大的乘积做因数分解的 `√P` 步骤，快了几个数量级。  
- **空间复杂度**：`O(1)`（相对于输入规模），因为集合里最多只有 168 个质数，视作常数空间。

## 心得  

- **核心技巧**：把“大数”拆成“小数”分别处理，利用集合去重。  
- **适用的题型**：  
  1. “求数组乘积的不同质因数”这类数论题。  
  2. “统计所有数的不同因子（不一定是质数）”的变形。  
  3. “把多个集合的并集大小求出来”——只要能逐个加入集合即可。  
- **一句话总结**：**不必先得到整体，再分解；直接对每个元素分解并合并结果，既安全又高效。**

## 反思  

- **第一反应**：把所有数相乘后再分解，觉得一步到位。  
- **最容易踩的坑**：  
  - 乘积会溢出（超过 Python 整数的可表示范围，甚至如果语言有整数上限会直接报错）。  
  - 忽视了重复质因数，需要在集合中去重。  
  - 对每个数的分解要记得把同一个质数的所有幂次都除掉，否则会导致无限循环。  
- **下次遇到同类题**：第一步就想到“**逐个分解并使用集合合并**”，避免先做整体乘积的冲动。
