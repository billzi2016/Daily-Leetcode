# #2455. 可被三整除的偶数的平均值 / Average Value of Even Numbers That Are Divisible by Three

## 题目（英文原版）

**Description**

Given an integer array nums of positive integers, return the average value of all even integers that are divisible by 3.
Note that the average of n elements is the sum of the n elements divided by n and rounded down to the nearest integer.

**Examples**

**Example 1:**

```
Input: nums = [1,3,6,10,12,15]
Output: 9
Explanation: 6 and 12 are even numbers that are divisible by 3. (6 + 12) / 2 = 9.
```

**Example 2:**

```
Input: nums = [1,2,4,7,10]
Output: 0
Explanation: There is no single number that satisfies the requirement, so return 0.
```

**Constraints**

- 1 <= nums.length <= 1000
- 1 <= nums[i] <= 1000

## 解题过程

### 1. 直觉解（暴力）

#### 思路  
最直接的想法就是把数组 **一次遍历** 一遍，遇到满足条件的数就把它们挑出来，累加求和并记录数量，最后用总和除以数量得到平均值（向下取整）。  

- **数据结构**：只需要两个整数变量 `total`（存放满足条件的数的和）和 `cnt`（记录满足条件的个数）。可以把它想象成在厨房里准备两只碗：一只装“总重量”，另一只装“个数”。  
- **为什么正确**：题目要求的就是“所有满足条件的数的平均值”。遍历每个元素，**只要**它是偶数且能被 3 整除（即能被 6 整除），就把它计入总和和计数。遍历结束后，`total / cnt` 正好是这些数的平均值。若根本没有满足条件的数，`cnt` 为 0，按照题意返回 0。  

- **时间/空间复杂度**  
  - 时间复杂度：遍历一次数组，**O(n)**（n 是数组长度）。这里的 `O(n)` 可以理解为“如果数组有 1000 个元素，就最多检查 1000 次”。  
  - 空间复杂度：只用了常数个额外变量，**O(1)**，即占用的内存不随输入规模增长。

#### 代码（Python）

```python
def averageValue(nums: list[int]) -> int:
    total = 0   # 累加满足条件的数的和
    cnt = 0     # 统计满足条件的数的个数

    for x in nums:                     # 逐个检查数组中的每个数
        # 同时满足“偶数”和“能被 3 整除”——也就是能被 6 整除
        if x % 6 == 0:                 # 用取模运算判断是否能被 6 整除
            total += x                 # 加到总和里
            cnt += 1                   # 计数加一

    # 如果没有符合条件的数，返回 0；否则返回向下取整的平均值
    return total // cnt if cnt != 0 else 0
```

#### 复杂度

- **时间复杂度**：`O(n)` — 只遍历一次数组，时间随元素个数线性增长。  
- **空间复杂度**：`O(1)` — 只使用了几个整数变量，和数组大小无关。

### 2. 最优解

#### 思路  
对这道 **Easy** 题目来说，暴力解已经是最优的线性遍历方案，无法再进一步降低时间复杂度，因为我们必须检查每个元素才能确认它是否符合条件。  
可以把实现写得更**简洁**一点，利用 Python 的列表推导式或内置函数 `filter`、`sum`，让代码更易读，但本质上仍是一次遍历，时间复杂度不变。  

**关键点**：

1. **“能被 2 且能被 3 同时整除”** 等价于 **“能被 6 整除”**（因为 2 和 3 互质，最小公倍数是 6）。这一步把两个条件合并成一个，减少了判断次数。  
2. 使用 **整数除法 `//`** 自动实现向下取整，省去 `math.floor`。  

#### 代码（Python）

```python
def averageValue(nums: list[int]) -> int:
    # 通过列表推导式一次性筛选出所有能被 6 整除的数
    qualified = [x for x in nums if x % 6 == 0]

    # 如果筛选后列表为空，直接返回 0
    if not qualified:
        return 0

    # sum 求和，len 求数量，// 完成向下取整的平均值
    return sum(qualified) // len(qualified)
```

#### 复杂度

- **时间复杂度**：`O(n)` — 列表推导式仍然要遍历全部 `n` 个元素。相比暴力写法，只是把判断和累加合并在一次遍历中，实际运行时间基本相同。  
- **空间复杂度**：`O(k)` — 这里额外用了一个长度为 `k` 的列表 `qualified`（`k` 为满足条件的元素个数），最坏情况下 `k = n`，因此在最坏情况下是 `O(n)`。如果希望保持 `O(1)` 空间，可以回到第一种实现，只用两个计数器。

## 心得

- **核心技巧**：把 “能被 2 且能被 3 整除” 合并为 “能被 6 整除”，利用取模 `%` 判断可整除性。  
- **适用的题型**  
  1. “找出数组中能被某个数整除的元素并统计”——如求能被 5 整除的数的和。  
  2. “筛选满足多重数值条件的元素”——如同时满足大于 10 且是奇数的数。  
  3. “求满足特定条件的子集的平均值/最大值/最小值”。  
- **一句话总结**：**把多个可整除条件合并为最小公倍数，再一次遍历完成筛选、求和与计数**。

## 反思

- **第一反应**：看到“偶数且能被 3 整除”，立刻想到 **取模** 检查，然后累加计数。  
- **最容易踩的坑**  
  1. **忘记处理没有符合条件的情况**，直接除以 0 会报错；题目要求返回 0。  
  2. **向下取整**：直接使用普通除法 `/` 会得到浮点数，需要 `//` 或 `int()` 来取整。  
  3. **条件合并**：如果不合并成 `% 6`，可能写成 `x % 2 == 0 and x % 3 == 0`，虽然正确，但略显冗余。  
- **下次类似题目第一步**：先**找出最简洁的数学等价条件**（如最小公倍数或最大公约数），再决定是一次遍历还是利用语言特性（filter、list comprehension）实现。
