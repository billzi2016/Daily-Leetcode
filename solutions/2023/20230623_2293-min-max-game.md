# #2293. 最小最大游戏 / Min Max Game

> 难度：简单 · 标签：Array、Simulation · [LeetCode 链接](https://leetcode.com/problems/min-max-game/)

---

## 题目（英文原版）

**Description**

You are given a 0-indexed integer array nums whose length is a power of 2.
Apply the following algorithm on nums:
Return the last number that remains in nums after applying the algorithm.

**Examples**

**Example 1:**

```
Input: nums = [1,3,5,2,4,8,2,2]
Output: 1
Explanation: The following arrays are the results of applying the algorithm repeatedly.
First: nums = [1,5,4,2]
Second: nums = [1,4]
Third: nums = [1]
1 is the last remaining number, so we return 1.
```

**Example 2:**

```
Input: nums = [3]
Output: 3
Explanation: 3 is already the last remaining number, so we return 3.
```

**Constraints**

- 1 <= nums.length <= 1024
- 1 <= nums[i] <= 109
- nums.length is a power of 2.

## 题目（中文翻译）

给定一个下标从 **0** 开始的整数数组 `nums`，其长度是 **2 的幂**。对 `nums` 反复执行以下操作：

- 当数组长度大于 **1** 时，构造一个新数组 `newNums`，长度为原数组长度的一半。对于每个下标 `i`（从 **0** 开始），取原数组中的相邻两个元素 `nums[2*i]` 和 `nums[2*i+1]`。
- 若 `i` 为偶数，则 `newNums[i] = min(nums[2*i], nums[2*i+1])`（取最小值）；若 `i` 为奇数，则 `newNums[i] = max(nums[2*i], nums[2*i+1])`（取最大值）。
- 用 `newNums` 替换原数组，继续上述过程。

返回在上述过程结束后数组中剩余的唯一一个数字。

**示例**

**示例 1**  
输入: `nums = [1,3,5,2,4,8,2,2]`  
输出: `1`  
解释: 下面的数组是重复应用该算法后的结果。  
第一次: `nums = [1,5,4,2]`  
第二次: `nums = [1,4]`  
第三次: `nums = [1]`  
`1` 是最后剩余的数字，所以返回 `1`。

**示例 2**  
输入: `nums = [3]`  
输出: `3`  
解释: `3` 已经是唯一剩余的数字，所以返回 `3`。

**约束条件**

- `1 <= nums.length <= 1024`
- `1 <= nums[i] <= 10^9`
- `nums.length` 是 **2 的幂**。

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  

最直接的想法就是 **一步一步照题目描述去模拟**：  

1. 把数组 `nums` 按照相邻两个元素一组划分。  
2. 第一次遍历时，对每一组取 **较小值**（`min`），把所有得到的最小值按顺序放进一个新数组。  
3. 第二次遍历时，对每一组取 **较大值**（`max`），同样生成新数组。  
4. 第三次再取最小值，第四次再取最大值 …… 交替进行，直到数组只剩下一个元素。  

> **类比**：把数组想象成一排学生，老师让相邻的两人比拼。第一次老师要找“最矮的”，第二次要找“最高的”，如此交替。每轮比赛结束后，只留下获胜者，重新排成一列继续比赛，最后只剩下冠军。  

**为什么正确**  
- 每一轮的规则完全符合题目要求：**相邻两数取 min 或 max**，且轮次交替。  
- 只要一直循环下去，数组必然会每轮长度减半，最终只能剩下唯一的元素，这正是题目要我们返回的答案。  

**复杂度分析（大白话）**  
- 第 1 轮要看 `n/2` 对，花 `n/2` 次比较；第 2 轮看 `n/4` 对，花 `n/4` 次比较…… 所有轮次的比较次数相加是 `n/2 + n/4 + n/8 + … ≤ n`。  
- 所以 **时间复杂度** 是 `O(n)`，这里的 `O(n)` 可以理解为“随着数组长度线性增长，程序跑的时间也线性增长”。  
- 我们每轮都会新建一个长度减半的数组，最多同时保存两层数组（原数组 + 新数组），所以 **空间复杂度** 是 `O(n)`（最坏情况是把原数组复制一遍）。  

#### 代码（Python）

```python
def minMaxGame(nums):
    """
    暴力模拟：交替取 min / max，直到只剩一个数
    :param nums: List[int]，长度是 2 的幂
    :return: int，最后剩下的数
    """
    turn = 0               # 0 表示本轮取最小值，1 表示本轮取最大值
    while len(nums) > 1:   # 只要还有两个以上的元素就继续
        nxt = []            # 用来存放本轮的结果
        # 步长为 2，遍历相邻的两两组合
        for i in range(0, len(nums), 2):
            a, b = nums[i], nums[i + 1]
            if turn == 0:               # 取较小值
                nxt.append(min(a, b))
            else:                       # 取较大值
                nxt.append(max(a, b))
        nums = nxt            # 用新数组替换旧数组，进入下一轮
        turn ^= 1            # 0↔1 切换，交替进行
    return nums[0]            # 只剩一个元素了
```

#### 复杂度  

- **时间复杂度**：`O(n)` — 随着输入长度 `n` 增大，比较次数大约是 `n` 次左右。  
- **空间复杂度**：`O(n)` — 需要额外的数组来保存每轮的结果，最坏情况下占用原数组大小的同等空间。

### 2. 最优解  

#### 思路  

从暴力解我们已经看到，**每轮都要新建一个数组**，这会产生额外的内存开销。  
实际上我们可以 **原地（in‑place）完成**，因为每轮产生的新数组长度恰好是旧数组的一半，只要把结果写回到原数组的前半段即可。  

优化的关键点：

1. **用同一个数组** `nums` 进行写入：第 `i` 对产生的结果直接放到 `nums[i//2]`（即前半段）。  
2. 仍然交替使用 `min` 与 `max`，只需要一个布尔变量 `turn` 来记录当前是取最小还是最大。  
3. 每轮结束后，只需把“有效长度” `size` 缩小为原来的一半，继续在 `nums[:size]` 上操作。  

这样我们 **不再需要额外的数组**，只用了常数级的额外空间（几个变量），时间仍然是 `O(n)`，因为每个元素只会被比较一次。

> **类比**：把学生排成一列后，老师每轮把胜者直接站到左侧的空位上，右侧的空位会被后面的学生填补，最终只剩下左端的冠军。老师不需要另外准备新的一排学生，只是把胜者搬到前面。

#### 代码（Python）

```python
def minMaxGame(nums):
    """
    最优解：原地模拟，空间 O(1)
    """
    turn = 0                # 0 → 取最小值；1 → 取最大值
    size = len(nums)        # 当前有效长度
    while size > 1:         # 只要还有两个以上的元素
        # 对每一对 (i, i+1) 计算结果，写回到前半段
        for i in range(0, size, 2):
            a, b = nums[i], nums[i + 1]
            if turn == 0:
                nums[i // 2] = min(a, b)
            else:
                nums[i // 2] = max(a, b)
        size //= 2          # 长度减半，进入下一轮
        turn ^= 1           # 交替 min / max
    return nums[0]          # 最后剩下的就是答案
```

#### 复杂度  

- **时间复杂度**：`O(n)` — 与暴力解相同，只是没有额外的拷贝开销。  
- **空间复杂度**：`O(1)` — 只用了常数个额外变量（`turn、size、i、a、b`），不随输入规模增长。

## 心得  

- **核心技巧**：**原地模拟 + 交替运算**。  
- **适用的题型**：  
  1. 需要每轮对相邻元素做固定运算并缩减规模的题目（如 “Array Reduction Game”）。  
  2. 需要交替使用不同操作的模拟题（如 “Alternating Subarray Sort”）。  
- **一句话总结**：**把每轮的结果直接写回原数组的前半段，省去额外空间，时间仍是线性**。  

## 反思  

- **第一反应**：看到“数组长度是 2 的幂，循环取 min、max”，立刻想到直接模拟。  
- **最容易踩的坑**：  
  - 忘记 **交替** 取最小值和最大值，导致答案总是最小或最大。  
  - 边界情况：数组只有一个元素时直接返回，不需要进入循环。  
  - 原地写回时索引要写成 `i // 2`，否则会覆盖还未使用的元素。  
- **下次遇到同类题**，第一步应该思考 **是否可以在原数组上就地完成**，避免不必要的额外空间。这样既能保持时间效率，又能把空间复杂度降到 `O(1)`。
