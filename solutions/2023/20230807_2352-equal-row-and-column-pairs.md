## 题目（英文原版）

**Description**

Given a 0-indexed n x n integer matrix grid, return the number of pairs (ri, cj) such that row ri and column cj are equal.
A row and column pair is considered equal if they contain the same elements in the same order (i.e., an equal array).

**Examples**

**Example 1:**

```
Input: grid = [[3,2,1],[1,7,6],[2,7,7]]
Output: 1
Explanation: There is 1 equal row and column pair:
- (Row 2, Column 1): [2,7,7]
```

**Example 2:**

```
Input: grid = [[3,1,2,2],[1,4,4,5],[2,4,2,2],[2,4,2,2]]
Output: 3
Explanation: There are 3 equal row and column pairs:
- (Row 0, Column 0): [3,1,2,2]
- (Row 2, Column 2): [2,4,2,2]
- (Row 3, Column 2): [2,4,2,2]
```

**Constraints**

- n == grid.length == grid[i].length
- 1 <= n <= 200
- 1 <= grid[i][j] <= 105

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把 **每一行** 和 **每一列** 都拿出来，两两比较是否完全相同。

- **数据结构**：  
  - `grid[i]` 本身就是第 `i` 行的数组。  
  - 第 `j` 列可以通过遍历所有行 `grid[k][j]`（`k` 从 `0` 到 `n-1`）收集得到。  
  - 把行和列看成两条 “纸条”，要逐个字符（元素）对比，就像把两本书的每一页对应的文字逐字比对一样。

- **为什么正确**：  
  - 若某行 `ri` 与某列 `cj` 完全相同，那么在我们遍历到这对 `(ri, cj)` 时，逐个元素比较必然全部相等。  
  - 只要把所有可能的 `(ri, cj)` 都检查一遍，就不会漏掉任何符合条件的配对。

- **复杂度分析（大白话）**：  
  - 外层有 `n` 行 × `n` 列 = `n²` 对组合。  
  - 对每一对，我们要比较 `n` 个元素（从左到右、一一对应）。  
  - 所以总共要做 `n² × n = n³` 次比较。  
  - 用大写的 **O** 符号写就是 **O(n³)**，意思是“随着矩阵规模 n 增大，运行时间大约会增长到 n 的三次方”。  
  - 额外空间几乎不需要，只保存几个临时变量，算 **O(1)**。

#### 代码（Python）

```python
def equalPairs_bruteforce(grid):
    """
    暴力解：逐行、逐列比较
    :param grid: List[List[int]]，n×n 矩阵
    :return: int，满足条件的 (row, col) 对数
    """
    n = len(grid)
    ans = 0

    # 遍历每一行 ri
    for ri in range(n):
        # 遍历每一列 cj
        for cj in range(n):
            same = True  # 假设相等，后面若发现不相等就设为 False
            # 逐元素比较第 ri 行和第 cj 列
            for k in range(n):
                if grid[ri][k] != grid[k][cj]:   # 行的第 k 列 与 列的第 k 行
                    same = False
                    break  # 已经不相等，直接结束内层循环
            if same:
                ans += 1
    return ans
```

#### 复杂度

- **时间复杂度**：`O(n³)`  
  - 解释：如果 `n = 200`，大约要比较 `200³ = 8,000,000` 次元素，仍在可接受范围，但不是最优的。

- **空间复杂度**：`O(1)`  
  - 解释：只用了常数个额外变量（`ans、ri、cj、k、same`），不随 `n` 增长。

### 2. 最优解

#### 思路  

从暴力解可以看出，**比较的瓶颈** 在于每次都要把列重新拼出，再和行逐元素比。这一步重复了很多次：同一行会被比较 `n` 次，同一列也会被重建 `n` 次。

**优化思路**：

1. **把每一行直接存起来**，而不是每次都去 `grid[ri][k]` 读取。  
   - 行本身就是一个数组，直接把它“记住”。  
   - 为了能够快速查找，我们把每行转成 **不可变的元组**（`tuple`），在 Python 的字典（哈希表）里作为键。  
   - 哈希表就像一本 **字典**：词（键）是行的内容，页码（值）是这行出现的次数。

2. **遍历每一列**，把列的元素也一次性收集成元组。  
   - 然后直接在字典里查找，看有没有同样的键（即同样的数组）。  
   - 若找到，说明这列等于字典中对应的行；出现次数就直接加到答案里。

3. **整体时间** 只剩下 **构造所有行 + 构造所有列** 两步，每步都是 `n × n`（遍历矩阵一次），即 `O(n²)`。  
   - 空间上，需要保存 `n` 行的元组（每个长度 `n`），所以是 `O(n²)`，这在题目限制 `n ≤ 200` 时完全可以接受。

> **关键概念解释**  
> - **哈希表（字典）**：像是一个“快速查找本”，把“钥匙”（这里是行的内容）对应到“价值”（出现次数）。查找、插入的平均时间都是 **O(1)**，所以整体效率大幅提升。  
> - **元组（tuple）**：Python 中的不可变序列，能够直接作为字典的键。把列表转成元组相当于把一串数字“封装”起来，交给字典保管。

#### 代码（Python）

```python
def equalPairs_optimal(grid):
    """
    最优解：利用哈希表把行存起来，再遍历列直接查找
    :param grid: List[List[int]]，n×n 矩阵
    :return: int，满足条件的 (row, col) 对数
    """
    n = len(grid)

    # 1️⃣ 把每一行转成 tuple，统计出现次数
    row_counter = {}
    for row in grid:                     # 遍历每一行
        t = tuple(row)                   # 转成不可变的 tuple，方便做键
        row_counter[t] = row_counter.get(t, 0) + 1  # 计数，等价于 defaultdict(int)

    # 2️⃣ 遍历每一列，构造对应的 tuple，直接在字典里查找
    ans = 0
    for col in range(n):                 # 对每一列
        col_tuple = tuple(grid[row][col] for row in range(n))  # 收集第 col 列的所有元素
        ans += row_counter.get(col_tuple, 0)   # 若字典里有相同的行，则加上它出现的次数

    return ans
```

#### 复杂度

- **时间复杂度**：`O(n²)`  
  - 解释：  
    - 构造所有行的哈希表：遍历矩阵一次 → `n × n` 次操作。  
    - 构造每一列的元组并查询：同样遍历矩阵一次 → `n × n` 次操作。  
    - 总共约 `2·n²`，量级是 **平方级**，比暴力的立方级快很多。

- **空间复杂度**：`O(n²)`  
  - 解释：需要存储 `n` 行的元组，每个元组长度为 `n`，共计 `n × n` 个整数的拷贝。  
  - 对于 `n ≤ 200`，最多约 40,000 个整数，完全可以接受。

## 心得

- **核心技巧**：把行先“记下来”放进哈希表，再用同样的方式把列转成可比较的键进行查找。  
- **适用场景**（类似题目）  
  1. **找相同的子数组/子序列**（例如 LeetCode 560 — Subarray Sum Equals K）  
  2. **矩阵中相等的行列对**（本题）  
  3. **统计二维数组中相同的行或列**（如 LeetCode 2352 — Equal Row and Column Pairs 的变体）  
- **一句话总结解题钥匙**：**“把可比较的对象统一成哈希键，一次遍历即可完成配对计数”。**

## 反思

- **第一反应**：看到“行”和“列”，立刻想到逐对比较——也就是暴力 O(n³) 的思路。  
- **最容易踩的坑**：  
  - 忘记把行或列转换成 **不可变** 的对象（如 tuple），导致无法作为字典键。  
  - 只统计行出现一次，忽略了同一行可能出现多次的情况（需要计数）。  
  - 对列的构造写成 `grid[col][row]`（坐标弄反）导致错误。  
- **下次类似题的第一步**：先思考“是否可以把一维对象（行/列/子数组）统一成哈希键”，如果可以，就立刻构造哈希表，避免重复遍历。
