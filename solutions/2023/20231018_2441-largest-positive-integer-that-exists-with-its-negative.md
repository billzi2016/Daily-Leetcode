# #2441. 存在对应负数的最大正整数 / Largest Positive Integer That Exists With Its Negative

> 难度：简单 · 标签：Array、Hash Table、Two Pointers、Sorting · [LeetCode 链接](https://leetcode.com/problems/largest-positive-integer-that-exists-with-its-negative/)

---

## 题目（英文原版）

**Description**

Given an integer array nums that does not contain any zeros, find the largest positive integer k such that -k also exists in the array.
Return the positive integer k. If there is no such integer, return -1.

**Examples**

**Example 1:**

```
Input: nums = [-1,2,-3,3]
Output: 3
Explanation: 3 is the only valid k we can find in the array.
```

**Example 2:**

```
Input: nums = [-1,10,6,7,-7,1]
Output: 7
Explanation: Both 1 and 7 have their corresponding negative values in the array. 7 has a larger value.
```

**Example 3:**

```
Input: nums = [-10,8,6,7,-2,-3]
Output: -1
Explanation: There is no a single valid k, we return -1.
```

**Constraints**

- 1 <= nums.length <= 1000
- -1000 <= nums[i] <= 1000
- nums[i] != 0

## 题目（中文翻译）

给定一个 **整数数组**（integer array）`nums`，该数组中不包含任何 `0`。请找出满足 `-k` 也出现在数组中的最大正整数 `k`。  
返回正整数 `k`；如果不存在这样的整数，返回 `-1`。

### 示例

#### 示例 1
**输入**: `nums = [-1,2,-3,3]`  
**输出**: `3`  
**解释**: `3` 是数组中唯一满足条件的 `k`。

#### 示例 2
**输入**: `nums = [-1,10,6,7,-7,1]`  
**输出**: `7`  
**解释**: `1` 和 `7` 都在数组中存在对应的负数，但 `7` 的值更大。

#### 示例 3
**输入**: `nums = [-10,8,6,7,-2,-3]`  
**输出**: `-1`  
**解释**: 数组中不存在任何满足条件的 `k`，因此返回 `-1`。

### 约束条件

- `1 <= nums.length <= 1000`
- `-1000 <= nums[i] <= 1000`
- `nums[i] != 0`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把数组里每一个正数都拿出来，去检查它的负数 `-num` 是否也在数组里。  
如果找到了，就把这个正数和当前已经找到的最大正数做比较，保留更大的那个。  
这个思路只用了最基础的 **遍历**，不需要额外的数据结构，完全可以用两层循环实现。

- **用到的数据结构**：只用到 Python 的列表（`list`），相当于我们平常装东西的盒子。  
- **为什么正确**：只要遍历到了所有正数，并且对每个正数都检查了它的负数是否存在，就一定不会漏掉任何符合条件的 `k`。  
- **时间/空间复杂度**：  
  - 外层循环遍历 `n` 次，内层最坏情况下也要遍历 `n` 次，所以总共是 `n × n = n²`，即 **O(n²)**。可以把它想象成“把每个人都和每个人握手”，随着人数增长，握手次数会呈平方增长。  
  - 只使用了原数组本身，没有额外的存储，空间复杂度是 **O(1)**（常数级别）。

#### 代码（Python）

```python
def findMaximumK_brute(nums):
    """
    暴力解：两层循环检查每个正数的负数是否出现
    :param nums: List[int] 题目给出的数组，保证不含 0
    :return: int  最大的满足条件的正整数，若不存在返回 -1
    """
    max_k = -1                         # 记录目前找到的最大 k，初始为 -1 表示不存在
    n = len(nums)

    for i in range(n):                 # 外层遍历每个元素
        if nums[i] > 0:                # 只关心正数
            # 在剩下的所有元素中找它的负数
            for j in range(n):
                if nums[j] == -nums[i]:
                    # 找到配对，更新最大值
                    if nums[i] > max_k:
                        max_k = nums[i]
                    break               # 已经找到对应的负数，退出内层循环

    return max_k
```

#### 复杂度

- **时间复杂度**：`O(n²)` —— 需要两层循环，最坏情况下每个正数都要遍历整个数组一次。  
- **空间复杂度**：`O(1)` —— 只用了几个额外的变量，没有额外的存储。

---

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**每次都要线性查找负数**，导致出现 `n²` 的时间开销。  
我们可以把“查找是否存在”这一步加速。  

> **哈希表（在 Python 中用 `set`）** 就像一本“词典”，我们把所有出现过的数字当作“词”，它们对应的“页码”就是“是否在集合里”。查找一个词是否在词典里，只需要一次 “看目录”，时间是 **O(1)**（常数时间），远快于遍历整个数组。

**优化步骤**：

1. **一次遍历把所有数字放进集合** `s`。  
2. 再遍历一次数组，只看正数 `x`，检查 `-x` 是否在集合 `s` 中。  
3. 如果配对成功，就更新答案 `max_k = max(max_k, x)`。  

这样我们把 **两层循环** 变成 **两次单层循环**，时间从 `O(n²)` 降到 `O(n)`。  

如果不想使用额外的集合，也可以先把数组 **排序**，再用 **双指针**（一个指向最左边，一个指向最右边）同时向中间逼近，类似 “找两数之和”。这会把时间降到 `O(n log n)`（排序的代价），空间可以做到 `O(1)`（原地排序）。这里我们重点介绍哈希表的解法，因为它最直观、最容易写。

**关键概念解释**：

- **哈希表 / 集合**：把元素直接映射到一个“桶”里，查找、插入、删除的平均时间都是常数。想象成一本超大词典，直接翻到对应的页码，不需要顺序查找。  
- **一次遍历**：只遍历数组一次，把每个数放进集合，时间是 `O(n)`。  
- **两次遍历**：第一次建集合，第二次检查正数，仍然是线性时间。

#### 代码（Python）

```python
def findMaximumK_opt(nums):
    """
    最优解：利用哈希集合实现 O(n) 时间查找
    :param nums: List[int] 不含 0 的整数数组
    :return: int  最大的满足条件的正整数，若不存在返回 -1
    """
    s = set(nums)          # 把所有元素放进集合，后续查找 O(1)
    max_k = -1

    for x in nums:         # 再遍历一次数组
        if x > 0 and -x in s:   # 只关心正数，并且检查它的负数是否在集合中
            if x > max_k:
                max_k = x       # 更新答案

    return max_k
```

#### 复杂度

- **时间复杂度**：`O(n)` —— 两次线性遍历，每次都是 `O(n)`，相加仍是 `O(n)`。  
  - 与暴力解相比，时间从“每个人和每个人握手”降到了“只需要一次登记再一次查询”，快了很多。  
- **空间复杂度**：`O(n)` —— 需要额外的集合存放 `n` 个元素，相当于开了一本“词典”。如果使用排序 + 双指针，则可以做到 `O(1)`（但要付出 `O(n log n)` 的排序时间）。

## 心得

- **核心技巧**：使用哈希集合（或哈希表）实现常数时间的“是否存在”查询。  
- **适用的题型**：  
  1. “找数组中是否有两个数互为相反数” → 本题。  
  2. “判断数组中是否存在两数之和为目标值” → 常用哈希表。  
  3. “找出现次数为 1 的唯一数” → 也是哈希计数或异或的思路。  
- **一句话总结解题钥匙**：**把“是否出现”变成 O(1) 查询，先把所有元素存进哈希表，再用它快速检查配对**。

## 反思

- **第一反应**：看到“正数和它的负数都出现”，立刻想到“配对”，于是想到用**集合**来做快速查找。  
- **最容易踩的坑**：  
  - 忘记题目保证数组不含 `0`，但如果出现 `0`，`-0` 仍是 `0`，需要单独处理。  
  - 只检查正数，防止把负数当成答案。  
  - 当所有数都是负数或没有配对时，需要返回 `-1` 而不是 `0`。  
- **下次类似题的第一步**：先思考“是否需要频繁判断‘某个元素是否在集合中’”，如果是，就立刻把元素放进哈希集合（或哈希计数）再继续。
