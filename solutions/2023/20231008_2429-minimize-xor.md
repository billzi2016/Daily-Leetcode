# #2429. 最小化异或 / Minimize XOR

> 难度：中等 · 标签：Greedy、Bit Manipulation · [LeetCode 链接](https://leetcode.com/problems/minimize-xor/)

---

## 题目（英文原版）

**Description**

Given two positive integers num1 and num2, find the positive integer x such that:
Note that XOR is the bitwise XOR operation.
Return the integer x. The test cases are generated such that x is uniquely determined.
The number of set bits of an integer is the number of 1's in its binary representation.

**Examples**

**Example 1:**

```
Input: num1 = 3, num2 = 5
Output: 3
Explanation:
The binary representations of num1 and num2 are 0011 and 0101, respectively.
The integer 3 has the same number of set bits as num2, and the value 3 XOR 3 = 0 is minimal.
```

**Example 2:**

```
Input: num1 = 1, num2 = 12
Output: 3
Explanation:
The binary representations of num1 and num2 are 0001 and 1100, respectively.
The integer 3 has the same number of set bits as num2, and the value 3 XOR 1 = 2 is minimal.
```

**Constraints**

- 1 <= num1, num2 <= 109

## 题目（中文翻译）

**描述**  
给定两个正整数 `num1` 和 `num2`，求满足以下条件的正整数 `x`：  

- `x` 与 `num2` 的二进制表示中 **1 的个数**（即 **set bits**）相同。  
- `x XOR num1` 的值最小。  

> 注意，**XOR** 是按位异或（bitwise XOR）运算。

返回整数 `x`。测试数据保证满足条件的 `x` 唯一确定。

**示例**  

**示例 1**  
```
输入: num1 = 3, num2 = 5
输出: 3
```
**解释**  
`num1` 和 `num2` 的二进制分别为 `0011` 和 `0101`。  
整数 `3` 的 **set bits** 数量与 `num2` 相同，且 `3 XOR 3 = 0` 为最小可能值。

**示例 2**  
```
输入: num1 = 1, num2 = 12
输出: 3
```
**解释**  
`num1` 和 `num2` 的二进制分别为 `0001` 和 `1100`。  
整数 `3` 的 **set bits** 数量与 `num2` 相同，且 `3 XOR 1 = 2` 为最小可能值。

**约束条件**  
- `1 <= num1, num2 <= 10^9`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**枚举所有可能的正整数 `x`**，挑出满足以下两个条件的 `x`：

1. `x` 的二进制中 `1` 的个数（即**集合位数**）等于 `num2` 的集合位数。  
2. 在所有满足条件的 `x` 中，使 `num1 XOR x` 的值最小。

> **类比**：把 “集合位数相同” 看成 “字典里查词”，`num2` 的集合位数是词条，所有拥有相同词条的 `x` 就像字典里对应同一页码的词。我们要在这些词里挑出和 `num1` “最配”的那个（XOR 最小）。

实现上可以把 `x` 从 `1` 开始一直往上尝试，检查它的集合位数是否等于 `num2` 的集合位数，若相等就计算 `num1 ^ x`，记录最小值对应的 `x`。

**为什么一定能得到正确答案？**  
因为我们遍历了 **所有** 正整数（理论上），只要找到满足条件且 XOR 最小的那一个，就是题目唯一要求的答案。

**时间/空间复杂度**  
- 时间复杂度：`O(上界 * log上界)`。  
  - “上界”指我们要枚举到的最大 `x`。在最坏情况下可能需要遍历到 `2^30`（因为 `num1, num2 ≤ 10^9 < 2^30`），显然不可接受。  
  - `log上界` 是算集合位数的代价（每次要把整数转成二进制并计数），大约是 30 步。  
  - 用大白话说，就是 **“要走几千亿步”**，根本跑不完。
- 空间复杂度：`O(1)`，只用了几个整数变量。

> 暴力解只能帮助我们**理清题意**，但在实际面试或竞赛中根本不可用。下面我们一步步把它优化掉。

#### 代码（Python）

```python
def brute_minimize_xor(num1: int, num2: int) -> int:
    # 统计 num2 有多少个 1（即目标集合位数）
    target_cnt = bin(num2).count('1')
    best_x = None
    best_val = float('inf')          # 用正无穷表示当前最小的 XOR

    x = 1
    # 为了演示，这里只遍历到 2**14（实际要遍历到更大才保证正确），
    # 真实环境下会超时。
    while x < (1 << 14):
        if bin(x).count('1') == target_cnt:      # 1）集合位数相同
            cur = num1 ^ x                       # 2）计算 XOR
            if cur < best_val:                   # 3）更新最小值
                best_val = cur
                best_x = x
        x += 1
    return best_x
```

> 代码里每一行都加了中文注释，帮助你快速定位关键操作。

#### 复杂度

- **时间复杂度**：`O(上界 * log 上界)`，这里的上界取 `2^14` 只是演示，真实情况会更大，导致不可接受的运行时间。  
- **空间复杂度**：`O(1)`，只用了常数个额外变量。

### 2. 最优解

#### 思路  

从暴力解可以看到，**瓶颈在于枚举**——我们不需要把所有可能的 `x` 都尝试一遍，只要**构造出唯一满足“XOR 最小”** 的 `x` 即可。  
下面一步步推导如何直接构造它。

1. **XOR 最小的意义**  
   - 两个二进制数对应位相同，`0 XOR 0 = 0`，`1 XOR 1 = 0`（都产生 0）。  
   - 两个二进制数对应位不同，`0 XOR 1 = 1`（产生 1），这会把结果值往上抬。  
   - 因此，要让 `num1 ^ x` 尽可能小，**尽量让 `x` 的 1 出现在 `num1` 已经是 1 的位置**，而不是 `num1` 为 0 的位置。

2. **我们只能放 `k` 个 1**  
   - `k = popcount(num2)`（`num2` 中 1 的个数）是固定的。  
   - 目标是：在二进制位上挑 `k` 个位置放 1，使得这些位置尽可能和 `num1` 的 1 对齐。

3. **贪心策略**  
   - **第一步**：从最高位到最低位遍历 `num1` 的 1 位（因为高位对数值影响更大），只要还有剩余的 1（`k > 0`），就把该位也设为 1 到 `x` 中。  
   - **第二步**：如果遍历完 `num1` 的所有 1 位后，`k` 仍然大于 0，说明我们还需要再放一些 1。这时只能在 `num1` 为 0 的位上补齐。为了让 XOR 仍然尽量小，**应该把这些额外的 1 放在最低位**（因为低位对整体数值的贡献最小）。

4. **为什么贪心不出错？**  
   - 高位的权值是 2 的幂，**高位的 1 对 XOR 结果的贡献远大于低位**。  
   - 把 1 放在 `num1` 为 1 的高位能把对应的 XOR 位消成 0，收益最大。  
   - 当所有能够“消 0”的高位都用完后，剩下的只能在 `num1` 为 0 的位上放 1，**把它们放在最低位能让增加的数值最小**。  
   - 这两个步骤分别对“最大化消 0”和“最小化新增 1 的价值”做了最优选择，整个过程就是全局最优。

> **类比**：想象你在拼装一块拼图，`num1` 的 1 位是已经有的拼块。你手里只有 `k` 块新拼块（1）。要让最终图案看起来“最接近”原来的图案，你先把新拼块贴到已有拼块上（不产生冲突），如果还剩下，就把剩余的拼块贴到空白最靠底部的地方（影响最小）。

#### 代码（Python）

```python
def minimizeXor(num1: int, num2: int) -> int:
    # 目标 1 的个数
    k = bin(num2).count('1')

    # 记录答案的二进制位
    ans = 0

    # ---------- 第一步：优先使用 num1 中的 1 ----------
    # 从最高位到最低位检查 num1 的每一位
    for i in range(31, -1, -1):                # 因为 num <= 1e9 < 2^30，取 31 位安全
        if (num1 >> i) & 1:                    # 第 i 位是 1 吗？
            if k > 0:                          # 还有剩余的 1 可以放
                ans |= (1 << i)                # 把第 i 位设为 1 到答案里
                k -= 1                         # 用掉一个 1
    # ---------- 第二步：若还有剩余的 1，则从低位补 ----------
    i = 0
    while k > 0:
        if ((num1 >> i) & 1) == 0:              # 第 i 位在 num1 中是 0
            ans |= (1 << i)                    # 把它设为 1
            k -= 1
        i += 1
    return ans
```

**关键行中文解释**：

- `k = bin(num2).count('1')`：统计 `num2` 中有多少个 1，决定我们必须放多少个 1。
- `for i in range(31, -1, -1):`：从最高位向低位遍历（31 → 0），确保先处理“大位”。
- `(num1 >> i) & 1`：右移 `i` 位后与 1 做与运算，判断第 `i` 位是否为 1。
- `ans |= (1 << i)`：把答案的第 `i` 位设为 1（位或操作）。
- `while k > 0:`：如果还有未放的 1，继续在 `num1` 为 0 的位上补。
- `i += 1`：从最低位逐渐往上找，保证补的位尽可能低。

#### 复杂度

- **时间复杂度**：`O(log max(num1, num2))`。  
  - 我们只遍历了至多 31（或 32）个位，常数级别的循环，等价于二进制位数的线性。  
  - 用大白话说，就是 **“最多跑 30‑40 步”，几乎瞬间完成**。
- **空间复杂度**：`O(1)`，只用了几个整数变量，没有额外的数组或递归栈。

> 与暴力解相比，时间从“几千亿步”降到了“几十步”，是一次质的飞跃。

## 心得

- **核心技巧**：**贪心 + 位操作**。先把需要的 `1` 放在 `num1` 已经是 `1` 的高位，再把剩余的 `1` 放在最低的 `0` 位。
- **适用的题型**  
  1. “在满足某个二进制约束的前提下，最小化/最大化 XOR/AND/OR”  
  2. “给定集合位数，构造数使得与另一个数的距离最小”  
  3. “位操作贪心” 典型如 LeetCode 1869 *"Product of Two Run-Length Encoded Arrays"*（思路类似）  
- **一句话总结解题钥匙**：**把 1 放在能“抵消”原数 1 的高位，剩余的 1 放在最右侧的空位**。

## 反思

- **第一反应**：直接暴力枚举所有满足集合位数相同的数，算出 XOR 再取最小。  
- **最容易踩的坑**  
  - 忘记 **只需要正整数**，不考虑 `0`（题目要求正整数）。  
  - 没有考虑 **最高位的影响**，导致把 1 放在低位而不是高位，结果 XOR 不最小。  
  - 边界：`num2` 的集合位数可能大于 `num1` 的 1 位数，需要在 `num1` 为 0 的位上补齐。  
- **下次遇到同类题**，第一步应该想到：**“先把需要的位对齐高位的 1，再在低位补足”**——这就是位操作贪心的通用模板。
