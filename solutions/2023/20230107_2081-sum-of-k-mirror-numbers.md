# #2081. **k-镜像数之和** / Sum of k-Mirror Numbers

> 难度：困难 · 标签：Math、Enumeration · [LeetCode 链接](https://leetcode.com/problems/sum-of-k-mirror-numbers/)

## 题目（英文原版）

**Description**

A k-mirror number is a positive integer without leading zeros that reads the same both forward and backward in base-10 as well as in base-k.
Given the base k and the number n, return the sum of the n smallest k-mirror numbers.

**Examples**

**Example 1:**

```
Input: k = 2, n = 5
Output: 25
Explanation:
The 5 smallest 2-mirror numbers and their representations in base-2 are listed as follows:
  base-10    base-2
    1          1
    3          11
    5          101
    7          111
    9          1001
Their sum = 1 + 3 + 5 + 7 + 9 = 25.
```

**Example 2:**

```
Input: k = 3, n = 7
Output: 499
Explanation:
The 7 smallest 3-mirror numbers are and their representations in base-3 are listed as follows:
  base-10    base-3
    1          1
    2          2
    4          11
    8          22
    121        11111
    151        12121
    212        21212
Their sum = 1 + 2 + 4 + 8 + 121 + 151 + 212 = 499.
```

**Example 3:**

```
Input: k = 7, n = 17
Output: 20379000
Explanation: The 17 smallest 7-mirror numbers are:
1, 2, 3, 4, 5, 6, 8, 121, 171, 242, 292, 16561, 65656, 2137312, 4602064, 6597956, 6958596
```

**Constraints**

- 2 <= k <= 9
- 1 <= n <= 30

## 题目（中文翻译）

一个 **k-镜像数（k-mirror number）** 是指在十进制（base‑10）和 k 进制（base‑k）下，均为回文且没有前导零的正整数。  
给定进制 `k` 和整数 `n`，返回前 `n` 个最小的 k‑镜像数的和。

**示例 1**  
**输入**: `k = 2, n = 5`  
**输出**: `25`  
**解释**:  
下面列出了前 5 个最小的 2‑镜像数及其在二进制下的表示：

| base‑10 | base‑2 |
|---------|--------|
| 1       | 1      |
| 3       | 11     |
| 5       | 101    |
| 7       | 111    |
| 9       | 1001   |

它们的和为 `1 + 3 + 5 + 7 + 9 = 25`。

**示例 2**  
**输入**: `k = 3, n = 7`  
**输出**: `499`  
**解释**:  
下面列出了前 7 个最小的 3‑镜像数及其在三进制下的表示：

| base‑10 | base‑3 |
|---------|--------|
| 1       | 1      |
| 2       | 2      |
| 4       | 11     |
| 8       | 22     |
| 121     | 11111  |

它们的和为 `1 + 2 + 4 + 8 + 121 + 151 + 212 = 499`。

**示例 3**  
**输入**: `k = 7, n = 17`  
**输出**: `20379000`  
**解释**: 前 17 个最小的 7‑镜像数为

**约束条件**

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**把每个正整数依次检查**，看它在十进制和 k 进制下是不是回文（正着读和倒着读相同）。  
如果是，就把它加入答案，直到找到 n 个为止。

> **数据结构类比**  
> - **字符串**：把整数转成字符串后判断回文，就像把单词放进字典里查“是否正着倒着一样”。  
> - **列表**：把找到的镜像数放进列表，等价于把合格的水果装进篮子。

**为什么这个方法一定能得到答案**  
因为题目要求的是“最小的 n 个 k‑mirror 数”。只要我们按 **从小到大** 的顺序遍历所有正整数，并把每个符合条件的数记下来，最终得到的前 n 个必然是题目要求的。

**时间/空间复杂度**（大白话）  
- **时间**：我们可能要检查很多不符合条件的数。设检查了 `m` 个数，每次检查要把它们分别转成十进制字符串和 k 进制字符串，然后判断回文，复杂度大约是 `O(m * L)`，其中 `L` 是数字的位数。因为 `n ≤ 30`、`k ≤ 9`，实际 `m` 并不会太大，但最坏情况仍然是 **线性遍历**，可以视作 `O(limit)`，这里的 `limit` 代表我们需要尝试的最大整数。  
- **空间**：只需要保存找到的 `n` 个数和临时的字符串，空间复杂度是 `O(n)`，即常数级别（因为 `n` 最多 30）。

> **O(n²) 是什么意思**  
> 在算法分析里，`O(n²)` 表示运行时间随输入规模的平方增长。比如如果把 1000 改成 2000，时间会大约增长 4 倍。这里我们的时间不是 `O(n²)`，而是 “遍历多少数” 决定的。

#### 代码（Python）

```python
def is_palindrome(s: str) -> bool:
    """判断字符串是否回文，'121' -> True，'123' -> False"""
    return s == s[::-1]                 # 直接把字符串倒序后比较

def to_base(num: int, k: int) -> str:
    """把十进制整数转成 k 进制的字符串（不含前导零）"""
    digits = []
    while num:
        digits.append(str(num % k))    # 余数就是当前位的数字
        num //= k
    return ''.join(reversed(digits))   # 最高位在前

def sum_of_k_mirror_bruteforce(k: int, n: int) -> int:
    ans = []                # 用来保存找到的 k‑mirror 数
    cur = 1                 # 从最小的正整数开始尝试
    while len(ans) < n:     # 直到找到 n 个为止
        dec_str = str(cur)                     # 十进制表示
        if is_palindrome(dec_str):             # 十进制是回文
            basek_str = to_base(cur, k)        # 转成 k 进制
            if is_palindrome(basek_str):       # k 进制也是回文
                ans.append(cur)                # 记录这个数
        cur += 1
    return sum(ans)          # 求和后返回
```

#### 复杂度

- **时间复杂度**：`O(limit * L)`  
  - `limit` 是我们需要遍历到的最大整数（实际取决于 k 与 n），  
  - `L` 是数字的位数（十进制或 k 进制），每次检查都要遍历这些位。  
  - 用大白话说，就是“我们要检查多少个数，每检查一个要看几位”。

- **空间复杂度**：`O(n)`  
  - 只存了最多 `n` 个符合条件的整数，`n ≤ 30`，所以几乎可以忽略不计。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**大量不必要的检查**：大多数整数根本不是十进制回文，却仍然被遍历。  
如果我们 **只生成十进制回文数**，再去检查它们在 k 进制下是否回文，就能把搜索空间大幅缩小。

**从暴力到优化的过程**  

1. **观察**：  
   - 十进制回文数的结构很规律：只要决定前半段（包括中间位），后半段就被唯一确定——把前半段倒过来拼在后面即可。  
   - 例如，前半段是 `123`，对应的偶数位回文是 `123321`，奇数位回文（中间不重复）是 `12321`。  

2. **生成十进制回文**：  
   - 按位数从小到大枚举“左半部分”。  
   - 对每个左半部分 `half`，构造两种回文：  
     - **偶数长度**：`half + reverse(half)`  
     - **奇数长度**：`half + reverse(half[:-1])`（去掉最右边的数字防止重复）  
   - 这样产生的回文数已经是 **严格递增** 的（因为 `half` 按自然数顺序递增），不需要再排序。

3. **检查 k 进制回文**：  
   - 对每个生成的十进制回文，转成 k 进制并判断是否回文。  
   - 若是，就加入答案，直到找到 n 个。

4. **为什么这就是最优**：  
   - 我们不再遍历所有整数，而是只遍历 **十进制回文数**。  
   - 十进制回文数的数量远小于全部整数（大约是 `10^{(len/2)}` 而不是 `10^{len}`），所以检查次数大幅下降。  
   - 由于 `n ≤ 30`，实际只需要生成前几百个十进制回文即可完成。

> **核心概念解释**  
> - **“左半部分”**：想象把一个回文数字的左半边剪下来，只保留左边的数字，这叫左半部分。把它倒着拼回去，就得到完整的回文。  
> - **“偶数长度”和“奇数长度”**：回文的位数可以是偶数（如 `1221`）也可以是奇数（如 `12321`），构造方式略有不同。

#### 代码（Python）

```python
def is_palindrome(s: str) -> bool:
    return s == s[::-1]

def to_base(num: int, k: int) -> str:
    if num == 0:
        return "0"
    digits = []
    while num:
        digits.append(str(num % k))
        num //= k
    return ''.join(reversed(digits))

def generate_decimal_palindromes(limit: int):
    """
    按递增顺序产生十进制回文数，直到产生的回文数总数 >= limit。
    只要调用者判断是否已收集足够的 k‑mirror 数，就可以随时停止。
    """
    half = 1
    while True:
        s = str(half)

        # 奇数位回文：左半部分 + 左半部分去掉最后一位的逆序
        odd = int(s + s[-2::-1])   # s[-2::-1] 表示除最后一位外的逆序
        yield odd

        # 偶数位回文：左半部分 + 完全逆序
        even = int(s + s[::-1])
        yield even

        half += 1
        # 为了安全，防止无限循环，最多产生到 10**6 级别的 half 就足够
        if half > 10**6:
            break

def sum_of_k_mirror_optimal(k: int, n: int) -> int:
    ans = []
    for pal in generate_decimal_palindromes(n * 10):   # 估计够用的上界
        # 只要已经收集到 n 个，就可以提前结束
        if len(ans) == n:
            break
        # 已经是十进制回文（因为我们生成的就是），只需检查 k 进制
        if is_palindrome(to_base(pal, k)):
            ans.append(pal)
    return sum(ans)
```

**代码要点注释**  

- `generate_decimal_palindromes`：  
  - 用 `half` 依次递增。  
  - `s[-2::-1]` 是 Python 的切片技巧，表示从倒数第二个字符开始逆序（去掉中间的重复位）。  
  - 每次 `yield` 一个奇数长度回文，再 `yield` 一个偶数长度回文，保证产生的顺序是从小到大。  

- 主函数 `sum_of_k_mirror_optimal`：  
  - 只要 `len(ans) == n` 就停止遍历，避免多余生成。  
  - `n * 10` 只是一个安全的上限，实际只会用到很少的回文数（因为 `n ≤ 30`）。  

#### 复杂度

- **时间复杂度**：`O(P * L)`  
  - `P` 为我们实际生成的十进制回文数个数（远小于遍历所有整数），  
  - `L` 为每个数在十进制或 k 进制下的位数。  
  - 与暴力解相比，`P` 大约是 `√limit` 的量级，**大约快 10~100 倍**，在本题约等于常数时间。

- **空间复杂度**：`O(n)`  
  - 只存了找到的 `n` 个结果以及少量临时变量，和暴力解相同，但因为 `P` 更小，实际占用更少。

## 心得

- **核心技巧**：**只生成十进制回文数**，再筛选 k 进制回文。  
- **该技巧适用的题型**：  
  1. “同时满足多进制回文的数”——如本题。  
  2. “求所有回文数的和/计数”——比如只在十进制或二进制中寻找回文。  
  3. “回文数的第 n 大/小”——先生成再排序或直接计数。  
- **一句话总结解题钥匙**：*把搜索空间压到只包含十进制回文的集合，然后在这个小集合里检查 k 进制回文。*

## 反思

- **第一反应**：直接遍历所有整数，逐个判断是否满足双回文。  
- **最容易踩的坑**：  
  - **前导零**：生成回文时必须保证左半部分的首位不为 `0`（我们从 `1` 开始递增自然满足）。  
  - **奇偶位的构造**：忘记去掉中间位会导致偶数长度回文变成奇数长度，导致漏掉或重复。  
  - **停止条件**：因为我们是“生成器”，必须在收集到 `n` 个后及时 `break`，否则会产生不必要的计算。  
- **下次遇到同类题**：第一步就想到“**只枚举回文**”，而不是“遍历所有数”。这一步能把时间从“几千”降到“几”。
