# #2317. **操作后最大异或** / Maximum XOR After Operations 

> 难度：中等 · 标签：Array、Math、Bit Manipulation · [LeetCode 链接](https://leetcode.com/problems/maximum-xor-after-operations/)

## 题目（英文原版）

**Description**

You are given a 0-indexed integer array nums. In one operation, select any non-negative integer x and an index i, then update nums[i] to be equal to nums[i] AND (nums[i] XOR x).
Note that AND is the bitwise AND operation and XOR is the bitwise XOR operation.
Return the maximum possible bitwise XOR of all elements of nums after applying the operation any number of times.

**Examples**

**Example 1:**

```
Input: nums = [3,2,4,6]
Output: 7
Explanation: Apply the operation with x = 4 and i = 3, num[3] = 6 AND (6 XOR 4) = 6 AND 2 = 2.
Now, nums = [3, 2, 4, 2] and the bitwise XOR of all the elements = 3 XOR 2 XOR 4 XOR 2 = 7.
It can be shown that 7 is the maximum possible bitwise XOR.
Note that other operations may be used to achieve a bitwise XOR of 7.
```

**Example 2:**

```
Input: nums = [1,2,3,9,2]
Output: 11
Explanation: Apply the operation zero times.
The bitwise XOR of all the elements = 1 XOR 2 XOR 3 XOR 9 XOR 2 = 11.
It can be shown that 11 is the maximum possible bitwise XOR.
```

**Constraints**

- 1 <= nums.length <= 105
- 0 <= nums[i] <= 108

## 题目（中文翻译）

你得到一个下标从 0 开始的整数数组 `nums`。一次操作可以选择任意**非负整数** `x` 和一个下标 `i`，随后将 `nums[i]` 更新为 `nums[i] AND (nums[i] XOR x)`。  
其中 **AND** 表示按位与（AND）操作，**XOR** 表示按位异或（XOR）操作。

可以对数组执行任意次数的上述操作，返回所有元素的**按位异或（XOR）**的最大可能值。

---

#### 示例 1
**输入**  
`nums = [3,2,4,6]`

**输出**  
`7`

**解释**  
选取 `x = 4`、`i = 3`，得到  
`nums[3] = 6 AND (6 XOR 4) = 6 AND 2 = 2`。  
此时 `nums = [3,2,4,2]`，所有元素的按位异或为  
`3 XOR 2 XOR 4 XOR 2 = 7`。  
可以证明 7 已是能够得到的最大按位异或值。  
（也可以通过其他操作序列得到相同的结果 7。）

---

#### 示例 2
**输入**  
`nums = [1,2,3,9,2]`

**输出**  
`11`

**解释**  
不进行任何操作。所有元素的按位异或为  
`1 XOR 2 XOR 3 XOR 9 XOR 2 = 11`。  
可以证明 11 已是能够得到的最大按位异或值。

---

#### 约束条件
- `1 <= nums.length <= 10^5`
- `0 <= nums[i] <= 10^8`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**把每个元素能变成的所有可能的数都枚举出来**，然后把所有组合的 XOR 结果算一遍，取最大的。  

- **能得到的数**：对 `nums[i]`，我们可以任选一个非负整数 `x`，把 `nums[i]` 变成 `nums[i] & (nums[i] ^ x)`。  
  只要把 `x` 的每一位设成 `0` 或 `1`，就会把 `nums[i]` 的对应位保持不变或变成 `0`。  
  因此 `nums[i]` 最多只能把自己的 `1` 位“关掉”，永远不能把 `0` 位“打开”。  
  换句话说，`nums[i]` 能变成的所有数就是 **它的子集掩码**（submask），比如 `6(110)` 可以变成 `6, 4(100), 2(010), 0`。  

- **暴力枚举**：对每个下标 `i`，把它的所有子集掩码列出来（如果 `nums[i]` 有 `k` 个 `1`，就有 `2^k` 种可能）。  
  然后把每个下标的选择组合起来，得到一整个数组的“改造后”形态，算出它们的 XOR，取最大。  

- **为什么对了**：因为我们把 **所有** 合法的改造都遍历了一遍，自然不会漏掉最优解。  

- **复杂度分析**：  
  - 假设第 `i` 个数有 `k_i` 个 `1`，则它的子集数是 `2^{k_i}`。  
  - 总的组合数是 `Π 2^{k_i} = 2^{Σ k_i}`，也就是 `2^{（所有 1 位的总数）}`。  
  - 在最坏情况下（每个数都是 `111…1`），`k_i` 可能高达 30（因为 `nums[i] ≤ 10^8 < 2^27`），数组长度 `n` 可达 `10^5`，于是组合数天文级别，根本跑不完。  
  - **时间复杂度**：`O(2^{Σk_i})`（指数级） → 实际上不可行。  
  - **空间复杂度**：同样是指数级，需要保存所有组合的 XOR 值。  

> **大白话**：  
> 把每个数字的“开关”全部打开/关闭的方式列出来，然后把所有人的开关组合在一起试一遍。这种办法相当于把所有可能的钥匙都搬进来试锁，钥匙太多根本找不到门。

#### 代码（Python）

```python
from itertools import product

def brute_max_xor(nums):
    # 为每个数生成所有子集掩码
    masks_list = []
    for a in nums:
        # 取出 a 的每一位 1 所在的位置
        ones = [i for i in range(31) if (a >> i) & 1]
        submasks = [0]                     # 从 0 开始
        for bit in ones:                  # 把每个 1 位加进去，形成子集
            submasks += [m | (1 << bit) for m in submasks]
        masks_list.append(submasks)

    # 暴力枚举每个位置选哪个子集
    max_xor = 0
    for combo in product(*masks_list):   # 这里的组合数是指数级的
        cur = 0
        for v in combo:
            cur ^= v
        max_xor = max(max_xor, cur)
    return max_xor
```

> **注意**：这段代码只能在 `len(nums) ≤ 5`、每个数的 `1` 位很少的情况下跑得完。它仅用于说明“最直接的思路”，不是正式解法。

#### 复杂度

- 时间复杂度：`O(2^{Σk_i})`（指数级），实际不可接受。  
- 空间复杂度：`O(2^{Σk_i})`（保存所有子集），同样不可接受。

### 2. 最优解

#### 思路  

从暴力解可以看到：**我们唯一能做的事是把某些 1 位关掉，不能把 0 位打开**。  
于是我们把注意力从“怎么枚举所有可能”转向**每一位到底能不能在最终的 XOR 中出现**。

1. **位的独立性**  
   位运算里每一位互不影响：要想让结果的第 `b` 位为 `1`，只需要保证在所有元素中，第 `b` 位出现 **奇数次**（因为奇数次 XOR 为 1，偶数次为 0）。

2. **我们能控制的只有“关掉”**  
   - 如果原数组里第 `b` 位根本没有出现（所有数的第 `b` 位都是 `0`），我们永远也打不开它，答案的第 `b` 位只能是 `0`。  
   - 如果原数组里第 `b` 位出现了至少一次（出现次数记为 `cnt`），我们可以**把它保留下来一次**，把其它所有出现的同位全部关掉。这样最终出现次数就是 `1`（奇数），第 `b` 位就可以是 `1`。

   关键在于：**只要有一个数原本带有该位，我们就能让它在最终 XOR 中出现一次**。因为我们可以自由地在任意元素上把该位清零，不会影响别的位。

3. **一次性把所有位都设为 1**  
   上面的操作对每一位都是独立的，互不冲突。于是我们可以**同时**把每一位（只要原来出现过）保留一次，得到的 XOR 正好是 **所有数的按位或（OR）**。

   - **按位或**：把所有数的每一位做“有谁有就记 1”，即 `res = nums[0] | nums[1] | … | nums[n-1]`。  
   - 这个 `res` 的第 `b` 位恰好等于“原数组里有没有至少一个 1”。正好对应我们能让最终 XOR 第 `b` 位为 1 的条件。

4. **为什么一定能实现**  
   - 任选一个出现该位的元素 `i`，把 `x` 的第 `b` 位设为 `0`（其余位随意），则 `nums[i]` 的该位保持不变。  
   - 对所有其它出现该位的元素 `j`，把 `x` 的第 `b` 位设为 `1`，则 `nums[j]` 的该位被 `AND` 成 `0`。  
   - 这样整个数组的该位出现恰好一次，XOR 该位为 `1`。  
   - 对所有位重复此过程即可得到整体 XOR = OR。

**结论**：最大可能的整体 XOR = **数组所有元素的按位或**。

> **类比**：  
> 想象每一位是灯泡，原数组里有灯泡亮（1）或灭（0）。我们只能把亮的灯泡关掉，不能把灭的灯泡点亮。目标是让所有灯泡的“奇数亮灯”状态（XOR）尽可能亮。只要某个灯泡原本亮过，我们就保留它亮一次，其余全部关掉，最后每个灯泡都恰好亮一次——这正是把所有亮过的灯泡“打开”一次的意思，也就是 OR。

#### 代码（Python）

```python
def maximumXOR(nums):
    """
    返回在任意次数的操作后，所有元素的异或的最大可能值。
    思路：只要某个位在任意元素中出现过，就可以在最终异或中保留一次，
    因此答案等于所有元素的按位或。
    """
    ans = 0
    for v in nums:          # 逐个累加按位或
        ans |= v            # ans = ans OR v
    return ans
```

> **关键行中文注释**  
> - `ans |= v`：把当前数的每一位“打开”，如果这位在任何数里出现过，`ans` 最终会把它记为 1。

#### 复杂度

- **时间复杂度**：`O(n)`，只遍历一次数组。  
  - **含义**：如果数组有 100,000 个元素，程序只需要对每个元素做一次“或”运算，几乎是瞬间完成。  
- **空间复杂度**：`O(1)`，只使用了常数级别的额外变量（`ans`）。  

> 与暴力解相比：  
> - 暴力解是指数级的，根本不可能在大数据范围内跑完。  
> - 最优解只用线性时间，一次遍历即可得到答案，完美符合题目 10⁵ 规模的限制。

## 心得

- **核心技巧**：**位只能被关闭，不能被打开 → 只要位出现过，就能在最终 XOR 中保留一次 → 答案是所有数的 OR**。  
- **该技巧适用的题型**：  
  1. “可以对每个数进行只能清零位的操作” 类似题（如 “Maximum AND after Operations”）。  
  2. “求在任意子集选择后能得到的最大 XOR/OR” 这类位独立性问题。  
  3. “把数组每个元素变成它的子集掩码后求最大/最小某种位运算” 的题目。  
- **一句话总结解题钥匙**：**只要位曾经出现，就能让它在最终异或里出现奇数次 → 按位或即为最大可能 XOR**。

## 反思

- **第一反应**：看到“任意 x、任意 i”，立刻想把所有可能的 `x` 穷举，结果发现搜索空间无限，思路陷入死循环。  
- **最容易踩的坑**：  
  - 忽略了操作只能 **关闭** 位，而不是随意改变。  
  - 误以为要让每个位都出现 **偶数次** 才能最大化 XOR（实际上是让每个位出现 **奇数次**，且只要出现一次即可）。  
  - 忽视了位之间的独立性，导致尝试用复杂的 DP 而不是直接求 OR。  
- **下次遇到同类题**：第一步先**分析单个操作对每一位的影响**（能增/能减/能保持），再**从全局角度看每位的出现次数能否调成奇数**，往往能直接得出 OR、AND 或者全 1 的答案。
