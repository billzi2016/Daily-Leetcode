# #2348. 零填充子数组的数量 / Number of Zero-Filled Subarrays

## 题目（英文原版）

**Description**

Given an integer array nums, return the number of subarrays filled with 0.
A subarray is a contiguous non-empty sequence of elements within an array.

**Examples**

**Example 1:**

```
Input: nums = [1,3,0,0,2,0,0,4]
Output: 6
Explanation: 
There are 4 occurrences of [0] as a subarray.
There are 2 occurrences of [0,0] as a subarray.
There is no occurrence of a subarray with a size more than 2 filled with 0. Therefore, we return 6.
```

**Example 2:**

```
Input: nums = [0,0,0,2,0,0]
Output: 9
Explanation:
There are 5 occurrences of [0] as a subarray.
There are 3 occurrences of [0,0] as a subarray.
There is 1 occurrence of [0,0,0] as a subarray.
There is no occurrence of a subarray with a size more than 3 filled with 0. Therefore, we return 9.
```

**Example 3:**

```
Input: nums = [2,10,2019]
Output: 0
Explanation: There is no subarray filled with 0. Therefore, we return 0.
```

**Constraints**

- 1 <= nums.length <= 105
- -109 <= nums[i] <= 109

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**枚举所有子数组**，检查它们是否全部为 `0`，如果是就计数。

- **枚举子数组**：把数组的左边界 `i` 从 `0` 到 `n‑1`，右边界 `j` 从 `i` 到 `n‑1`，这样每一对 `(i, j)` 对应一个连续子数组 `nums[i…j]`。  
- **检查是否全为 0**：遍历子数组内部的每个元素，只要出现非 0 就立刻终止，只有全部是 0 才算合法。

可以把 “检查是否全为 0” 想象成 **查字典**——我们要在子数组里逐字查找，只要发现一个不是 “0” 的词，就立刻放弃这本书（子数组）。

这种方法一定能得到正确答案，因为我们把所有可能的子数组都遍历了一遍，且每一次都严格判断是否全为 0。

**时间复杂度**  
- 枚举子数组的次数是 `n·(n+1)/2`，大约是 `O(n²)`。  
- 对每个子数组最坏情况下要遍历它的全部长度，整体仍是 `O(n²)`（因为每个元素在所有子数组里被检查的次数恰好是 `O(n)` 次，总体仍是二次级别）。  
- 用大白话说，**如果数组长度是 10,000，暴力解大概要检查 100,000,000 次**，在实际运行时会超时。

**空间复杂度**  
只用了常数级别的额外变量（计数器、指针等），所以是 `O(1)`。

#### 代码（Python）

```python
def zero_filled_subarray_bruteforce(nums):
    n = len(nums)
    ans = 0                         # 记录满足条件的子数组个数

    # i 为子数组的左端点
    for i in range(n):
        # j 为子数组的右端点（包含 i 本身）
        for j in range(i, n):
            all_zero = True         # 假设子数组全是 0
            # 检查 nums[i..j] 是否全为 0
            for k in range(i, j + 1):
                if nums[k] != 0:    # 只要出现一个非 0，立刻放弃
                    all_zero = False
                    break
            if all_zero:
                ans += 1            # 统计一个合法子数组

    return ans
```

#### 复杂度

- **时间复杂度**：`O(n²)` —— 两层循环遍历所有子数组，内部再遍历子数组本身，最坏情况相当于二次方级别的操作。  
- **空间复杂度**：`O(1)` —— 只用了几个计数变量，没有额外的随输入规模增长的数据结构。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **每次都要重新遍历子数组**，而实际上我们只关心 **连续的 0** 有多长。  
如果把数组中所有连续的 `0` 看成一段段 “零段”，每段长度记为 `len`，那么：

- 长度为 `len` 的零段能够产生多少个只包含 `0` 的子数组？  
- 设 `len = 3`，零段为 `[0,0,0]`，所有合法子数组有：
  - 长度 1 的子数组：`[0]` 出现 3 次  
  - 长度 2 的子数组：`[0,0]` 出现 2 次  
  - 长度 3 的子数组：`[0,0,0]` 出现 1 次  
  - 合计 `3 + 2 + 1 = 6`，这正是等差数列 `1 + 2 + … + len = len·(len+1)/2`。

**关键观察**：  
> 对于每个位置 `i`，如果 `nums[i] == 0`，则以 `i` 结尾的全 0 子数组个数等于 “从 `i` 往左连续的 0 的个数 + 1”。  
> 换句话说，记 `cnt` 为当前连续的 0 的长度，那么以 `i` 为右端点的合法子数组数就是 `cnt`，并把它加入答案。

**一步步推导**：

1. **遍历数组**，维护一个变量 `cnt`，表示**当前**（截至当前位置）连续的 `0` 的个数。  
2. 当 `nums[i] == 0` 时，`cnt += 1`，这意味着以 `i` 结尾的全 0 子数组数是 `cnt`（因为可以选取长度 `1 … cnt` 的子数组）。把 `cnt` 加到答案中。  
3. 当 `nums[i] != 0` 时，连续 0 被打断，`cnt` 重置为 `0`，因为以后再也不能以 `i` 结尾形成全 0 子数组。

整个过程只需要一次线性遍历，**不需要额外的数据结构**，空间是常数级。

**类比**：把 `cnt` 想成 “连续的零雨滴计数器”。每遇到一个 `0`，雨滴计数器就加一，说明可以形成更多的 “零雨滴子数组”。一旦出现非零，雨滴计数器被清空，雨滴重新开始积累。

#### 代码（Python）

```python
def zero_filled_subarray(nums):
    """
    返回数组中所有全 0 子数组的数量
    思路：一次遍历，维护当前连续 0 的长度 cnt，
          以当前位置为右端点的子数组数即为 cnt。
    """
    ans = 0          # 最终答案
    cnt = 0          # 当前连续 0 的个数

    for x in nums:
        if x == 0:               # 遇到 0，连续计数加 1
            cnt += 1
            ans += cnt           # 以当前位置结尾的子数组数是 cnt
        else:                    # 非 0，计数器清零
            cnt = 0

    return ans
```

#### 复杂度

- **时间复杂度**：`O(n)` —— 只遍历一次数组，`n` 是数组长度。相比暴力的 `O(n²)`，快了很多（如果 `n=10⁵`，只需要 10⁵ 次操作，毫秒级就能完成）。  
- **空间复杂度**：`O(1)` —— 只用了常数个变量 (`ans`, `cnt`)，不随 `n` 增长。

## 心得

- **核心技巧**：把“全 0 子数组”转化为“以每个位置为右端点的连续 0 长度”。一次线性扫描即可累计答案。  
- **适用的题型**：  
  1. **统计连续子序列的数量**（如统计连续奇数、连续正数等）。  
  2. **子数组和为特定值的计数**（利用前缀和的思想，类似“连续子数组和为 k”）。  
  3. **最长/最多连续字符**（如字符串中连续相同字符的统计）。  
- **一句话总结**：**把子数组计数拆成“每个位置能贡献多少”，用连续计数器一次遍历完成**。

## 反思

- **第一反应**：直接想枚举所有子数组检查是否全为 0，没想到可以把问题简化为连续计数。  
- **最容易踩的坑**：  
  - 忘记在非零元素出现时把计数器 `cnt` 归零，会导致错误的累计。  
  - 结果可能会很大，虽然题目没有要求取模，但在实际面试中要注意整数溢出（Python 自动大整数，C++/Java 需要 `long long`）。  
- **下次遇到同类题**：第一步先问自己“**有没有可以累加的局部信息**（比如连续长度、前缀和）”，如果有，就尝试用一次遍历把局部信息转化为全局答案。
