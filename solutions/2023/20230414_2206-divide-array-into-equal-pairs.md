# #2206. 划分数组为相等的配对 / Divide Array Into Equal Pairs

> 难度：简单 · 标签：Array、Hash Table、Bit Manipulation、Counting · [LeetCode 链接](https://leetcode.com/problems/divide-array-into-equal-pairs/)

---

## 题目（英文原版）

**Description**

You are given an integer array nums consisting of 2 * n integers.
You need to divide nums into n pairs such that:
Return true if nums can be divided into n pairs, otherwise return false.

**Examples**

**Example 1:**

```
Input: nums = [3,2,3,2,2,2]
Output: true
Explanation: 
There are 6 elements in nums, so they should be divided into 6 / 2 = 3 pairs.
If nums is divided into the pairs (2, 2), (3, 3), and (2, 2), it will satisfy all the conditions.
```

**Example 2:**

```
Input: nums = [1,2,3,4]
Output: false
Explanation: 
There is no way to divide nums into 4 / 2 = 2 pairs such that the pairs satisfy every condition.
```

**Constraints**

- nums.length == 2 * n
- 1 <= n <= 500
- 1 <= nums[i] <= 500

---

## 题目（中文翻译）

给定一个包含 **2 × n** 个整数的整数数组（integer array）`nums`。  
需要将 `nums` 划分成 **n** 对（pair），使得每一对中的两个元素相等。  

如果可以如此划分，则返回 `true`；否则返回 `false`。

**示例 1**  
**输入**: `nums = [3,2,3,2,2,2]`  
**输出**: `true`  
**解释**:  
`nums` 中有 6 个元素，应划分为 `6 / 2 = 3` 对。  
如果将其划分为 `(2, 2)`, `(3, 3)`, `(2, 2)`，则满足所有条件。

**示例 2**  
**输入**: `nums = [1,2,3,4]`  
**输出**: `false`  
**解释**:  
无法将 `nums` 划分为 `4 / 2 = 2` 对，使得每对的两个元素相等。

**约束条件**  
- `nums.length == 2 * n`  
- `1 <= n <= 500`  
- `1 <= nums[i] <= 500`

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  
最直接的想法是：**把每个数字出现的次数全部统计出来，然后检查这些次数是不是都是偶数**。  
- **用到的数据结构**：哈希表（在 Python 里用 `dict`）。可以把它想象成一本**查字典**：  
  - **key** 就像字典里的单词，代表一种数字。  
  - **value** 就像对应的页码，记录这种数字出现了多少次。  
- **为什么这样就对了**：题目要求把数组划分成若干对，且每一对的两个数必须相等。  
  - 如果某个数字出现了奇数次，必然会剩下一个单独的、找不到相同伴侣的数字，划分就不可能完成。  
  - 反之，只要每个数字的出现次数都是偶数，就一定能把它们两两配对（把相同的数字随意两两分组即可）。  
- **复杂度的大白话**：  
  - **时间复杂度 O(n)**：我们只需要遍历一遍数组，`n` 就是数组长度（这里是 `2·n`，但我们仍记作 `n` 方便），每个元素只看一次。  
  - **空间复杂度 O(m)**：`m` 是不同数字的种类数，最坏情况下（数字 1~500 都出现）是 500。相当于我们最多需要准备 500 本“小字典”。  

#### 代码（Python）  
```python
from typing import List

def divideArray(nums: List[int]) -> bool:
    # 1. 统计每个数字出现的次数，用 dict 当“查字典”
    cnt = {}
    for x in nums:                 # 遍历数组，每个元素只看一次
        cnt[x] = cnt.get(x, 0) + 1 # 没有就当 0，加 1

    # 2. 检查所有计数是否为偶数
    for val in cnt.values():       # 只看计数，不关心是哪一个数字
        if val % 2 != 0:           # 出现奇数次就直接返回 False
            return False
    return True                    # 所有计数都是偶数，说明可以配对
```

#### 复杂度  
- **时间复杂度**：`O(n)` — 只遍历一次数组，`n` 为数组长度。  
- **空间复杂度**：`O(m)` — 需要存储每种不同数字的计数，`m ≤ 500`（常数级别）。

### 2. 最优解  

#### 思路  
上面的暴力解已经是 **线性时间**，但它使用了哈希表，需要额外的字典对象。  
观察题目约束：  
- 所有数字都在 **1 到 500** 之间。  
这意味着我们可以**用一个固定大小的数组**（长度 501）直接记录每个数字的出现次数，甚至只记录 **奇偶性**（出现了几次，只关心是奇数还是偶数）。  

**核心技巧：**  
- **计数数组 + 奇偶翻转**：  
  - 创建一个长度为 501 的整数数组 `parity`，全部初始化为 0。  
  - 遍历 `nums`，对当前数字 `x` 执行 `parity[x] ^= 1`（异或 1），相当于“出现一次就把奇偶性翻转”。  
  - 最后只要所有 `parity[i]` 都是 0，说明每个数字出现了偶数次，题目条件成立。  
- **为什么更好**：  
  - **空间是常数**：数组大小固定为 501，无论输入多大都不变，等价于 O(1)。  
  - **操作更轻量**：不需要哈希函数的开销，直接用下标访问，速度更快。  

如果想进一步展示位运算的魅力，还可以把 501 位压在一个 **Python 整数**里，用位运算 `mask ^= 1 << x` 来翻转对应位。但对初学者来说，直接用列表更直观。  

#### 代码（Python）  
```python
from typing import List

def divideArray(nums: List[int]) -> bool:
    # 1. 用固定长度的列表记录奇偶性，索引 i 代表数字 i
    parity = [0] * 501            # 0~500，0 位置我们永远不用（因为数字从 1 开始）

    # 2. 遍历数组，出现一次就翻转一次奇偶性
    for x in nums:
        parity[x] ^= 1            # ^ 是异或，0^1=1，1^1=0，奇偶性翻转

    # 3. 检查是否全部为偶数（即全为 0）
    #    只需要检查 1~500，因为 0 不会出现
    for i in range(1, 501):
        if parity[i]:             # 若为 1，说明该数字出现了奇数次
            return False
    return True
```

#### 复杂度  
- **时间复杂度**：`O(n)` — 仍然只遍历一次数组。  
- **空间复杂度**：`O(1)` — 使用了固定大小的 501 长度列表（常数空间），与输入规模无关。

## 心得  

- **核心技巧**：统计每种数字的出现次数（或奇偶性），只要全部为偶数即可配对。  
- **适用的题型**：  
  1. **“数组中出现奇数次数的数字”**（LeetCode 137）——利用位运算找唯一出现奇数次的数。  
  2. **“检查数组能否两两配对”**（类似本题）——所有元素出现次数必须为偶数。  
  3. **“统计字符出现次数”**（字符串回文排列）——判断字符出现次数的奇偶性。  
- **一句话总结解题钥匙**：**“每个数出现偶数次，才能完整配成相同的对”。**

## 反思  

- **第一反应**：想到把所有可能的配对枚举出来，使用递归/回溯尝试每一种组合。  
- **最容易踩的坑**：  
  - 忘记先检查数组长度是否为偶数（题目已经保证，但实际面试时要自行验证）。  
  - 只统计了出现次数，却忘了判断奇偶性，导致出现奇数次的数字仍被误判为可配。  
  - 边界值：数字可能是 1 或 500，计数数组一定要足够大（下标要对应）。  
- **下次遇到同类题**：第一步就想到 **“统计出现次数并检查奇偶性”**，如果数值范围有限，直接用固定大小的数组或位掩码实现 O(1) 空间。
