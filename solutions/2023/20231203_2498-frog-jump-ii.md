# #2498. 青蛙跳跃 II / Frog Jump II

## 题目（英文原版）

**Description**

You are given a 0-indexed integer array stones sorted in strictly increasing order representing the positions of stones in a river.
A frog, initially on the first stone, wants to travel to the last stone and then return to the first stone. However, it can jump to any stone at most once.
The length of a jump is the absolute difference between the position of the stone the frog is currently on and the position of the stone to which the frog jumps.
The cost of a path is the maximum length of a jump among all jumps in the path.
Return the minimum cost of a path for the frog.

**Examples**

**Example 1:**

```
Input: stones = [0,2,5,6,7]
Output: 5
Explanation: The above figure represents one of the optimal paths the frog can take.
The cost of this path is 5, which is the maximum length of a jump.
Since it is not possible to achieve a cost of less than 5, we return it.
```

**Example 2:**

```
Input: stones = [0,3,9]
Output: 9
Explanation: 
The frog can jump directly to the last stone and come back to the first stone. 
In this case, the length of each jump will be 9. The cost for the path will be max(9, 9) = 9.
It can be shown that this is the minimum achievable cost.
```

**Constraints**

- 2 <= stones.length <= 105
- 0 <= stones[i] <= 109
- stones[0] == 0
- stones is sorted in a strictly increasing order.

## 题目（中文翻译）

你得到一个 **0 索引** 的整数数组 `stones`，数组按严格递增顺序排列，表示河中石头的位置。  
一只青蛙最初站在第一块石头上，需要先到达最后一块石头，再返回到第一块石头。  
但它**至多只能跳到每块石头一次**。

一次跳跃（jump）的长度等于青蛙当前所在石头的位置与它将要跳到的石头位置之差的绝对值。  
一条路径的代价（cost）定义为该路径中所有跳跃长度的最大值。

请返回青蛙完成往返所能达到的**最小代价**。

---

### 示例 1

```
Input: stones = [0,2,5,6,7]
Output: 5
```

**解释**：上图展示了青蛙可以采用的一条最优路径。该路径的代价为 5，即所有跳跃长度中的最大值。由于不可能得到小于 5 的代价，答案返回 5。

### 示例 2

```
Input: stones = [0,3,9]
Output: 9
```

**解释**：青蛙可以直接跳到最后一块石头，然后再返回到第一块石头。此时每次跳跃的长度都是 9，路径的代价为 `max(9, 9) = 9`。可以证明这已经是能够取得的最小代价。

---

- `2 <= stones.length <= 10^5`
- `0 <= stones[i] <= 10^9`
- `stones[0] == 0`
- `stones` 按严格递增顺序排序。

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**把所有可能的跳法都列举出来，找出其中最大跳距最小的那条路径**。  
这类似于我们在玩拼图——把每块拼图（石头）按顺序摆放，尝试所有可能的摆放顺序，然后挑选最好的。

实现上可以使用**回溯（深度优先搜索）**：

1. 从第 0 块石头出发，记当前所在位置 `cur`。  
2. 在未访问过的石头中任选一个 `next`，跳过去，记录这一次的跳距 `abs(stones[next] - stones[cur])`。  
3. 继续向前搜索，直到跳到最后一块石头 `stones[-1]`。  
4. 再从这里开始，继续往回跳，直到回到第 0 块石头。  
5. 整条路径走完后，取这条路径上所有跳距的最大值 `path_cost`。  
6. 在所有合法路径中取最小的 `path_cost` 即为答案。

> **为什么这个方法一定能得到正确答案？**  
> 因为我们枚举了**所有**满足“每块石头最多跳一次”的合法路径，最小的最大跳距必然在其中出现。

> **时间/空间分析（大白话）**  
> - 时间复杂度：`O(n!)`（阶乘），因为每一步都要在剩下的未访问石头里挑一个，等价于全排列的数量。  
> - 空间复杂度：`O(n)`，递归栈需要保存当前路径的长度（最多 `n`）。

显然，这种暴力方法只能在 `n` 很小（比如 ≤ 8）的时候才能跑得完，远远不符合题目 `n ≤ 10⁵` 的要求。

#### 代码（Python）

```python
from typing import List

def min_cost_bruteforce(stones: List[int]) -> int:
    n = len(stones)
    visited = [False] * n          # 记录每块石头是否已经踏过
    best = float('inf')            # 全局最小的最大跳距

    def dfs(cur: int, forward: bool, cur_max: int, steps: int):
        """深度优先搜索
        cur      – 当前所在石头的下标
        forward  – 是否仍在“去往最后一块石头”的阶段
        cur_max  – 当前路径上出现的最大跳距
        steps    – 已经走了多少步（用于剪枝）"""
        nonlocal best

        # 若已经回到起点且走完了所有石头，更新答案
        if not forward and cur == 0 and steps == n:
            best = min(best, cur_max)
            return

        # 剪枝：如果当前最大跳距已经不可能比 best 更好，就直接返回
        if cur_max >= best:
            return

        # 选取下一个可以跳的石头
        for nxt in range(n):
            if visited[nxt]:
                continue
            # 只能往前跳到更大的下标，或在返回阶段往后跳到更小的下标
            if forward and nxt <= cur:
                continue
            if not forward and nxt >= cur:
                continue

            jump = abs(stones[nxt] - stones[cur])
            visited[nxt] = True
            # 是否已经到达最后一块石头，决定是否切换方向
            dfs(nxt, forward and nxt != n - 1, max(cur_max, jump), steps + 1)
            visited[nxt] = False

    visited[0] = True                # 起点已访问
    dfs(0, True, 0, 1)
    return best
```

> 代码里每一行都有中文注释，帮助你快速定位每一步的意义。  

#### 复杂度  

- **时间复杂度**：`O(n!)` —— 想象一下把 `n` 本书排成一排的所有可能顺序，数量会迅速爆炸。  
- **空间复杂度**：`O(n)` —— 递归栈最多保存 `n` 层调用，和石头的数量成线性关系。

### 2. 最优解  

#### 思路  

从暴力解我们已经看到，**瓶颈在于枚举所有路径**。  
实际上，这道题可以用**贪心 + 数学观察**直接得到最优答案，关键在于下面两点：

1. **“每次都跳到下一个石头”一定是可行的**。  
   只要不违反“每块石头最多一次”的限制，最慢的跳距不会比必然会出现的更大。  

2. **最差的那一次跳距一定是“跨过一个石头的距离”**。  
   想象我们把所有石头编号 `0 … n‑1`（已按位置升序）。  
   若我们在**前进**时每次都跨过恰好一个石头（即从 `i` 跳到 `i+2`），  
   那么在**返回**时就可以把被跨过的石头逐一补上（`i+2 → i+1 → i` …）。  
   这样最大的跳距就是所有 “两步之差” 中的最大值：  

   \[
   \max_{0 \le i \le n-3}\bigl(stones[i+2] - stones[i]\bigr)
   \]

   直观类比：**把石头排成一列，先把奇数位的石头走一遍（跳两格），再把偶数位的石头走回来**。  
   这就是“**跳过一块石头**”的策略，也是提示里提到的“跳过每个石头一次再回来”。  

**为什么这一定是最小可能的最大跳距？**  
- 设答案为 `ans`，任意一次跳距都不可能小于 `ans`。  
- 把所有石头分成两组：奇数下标组和偶数下标组（下标从 0 开始）。  
- 前进时要把 **最后一块石头**（下标 `n‑1`）访问到，而每块石头只能用一次，  
  那么必然有一次跳要跨过 **两个相邻石头之间的间隔**，即 `stones[i+2] - stones[i]`。  
- 因此 **任何合法路径的最大跳距** 至少是上述所有两步差的最大值。  
- 我们构造的贪心路径正好把最大跳距压到这个下界，故最优。

**算法步骤**（只需要一次线性扫描）：

1. 初始化 `ans = 0`。  
2. 对所有 `i` 从 `0` 到 `n‑3`，计算 `gap = stones[i+2] - stones[i]`，更新 `ans = max(ans, gap)`。  
3. 返回 `ans`。  

这就是 **O(n)** 的贪心解法，几乎不需要额外空间。

#### 代码（Python）

```python
from typing import List

def minCost(stones: List[int]) -> int:
    """
    贪心解：最大跳距等于相隔两个石头之间的最大距离。
    只需一次线性遍历，时间 O(n)，空间 O(1)。
    """
    n = len(stones)
    # 至少有两块石头，题目保证 n >= 2
    ans = 0
    # 只需要看 i, i+2 这两块石头之间的距离
    for i in range(n - 2):
        gap = stones[i + 2] - stones[i]   # 跨过中间那块石头的距离
        if gap > ans:
            ans = gap                     # 更新当前的最大跳距
    return ans
```

> 代码中每行都写了中文注释，帮助你一步步对照思路。

#### 复杂度  

- **时间复杂度**：`O(n)` —— 只遍历一次石头数组，`n` 最大可达 `10⁵`，完全可以接受。  
  > 大白话：如果你把所有石头排成一条直线，只需要从左到右看一遍，每看一次花 **常数** 时间，整体时间跟石头数量成正比。  
- **空间复杂度**：`O(1)` —— 只用了几个整数变量，不会随 `n` 增大而增长。  

与暴力解相比，时间从 **指数级** 降到了 **线性级**，速度提升了天文数字。

## 心得  

- **核心技巧**：**贪心 + 两步差**。  
  通过观察“跳过一块石头再回来”的结构，把问题转化为“相隔两个石头的距离”。  
- **适用的类似题型**  
  1. *Frog Jump I*（只需要去终点，不返回）——常用二分或贪心。  
  2. *Maximum Gap*（求数组中相邻元素的最大差）——排序后求相邻差。  
  3. *Array Partition*（把数组两两分组，使每组最大值最小）——类似“每隔一个取”。  
- **一句话总结解题钥匙**：  
  **“把所有石头分两层交叉走，最大跳距就是两层之间最宽的缝隙”。**

## 反思  

- **第一反应**：直接想遍历所有路径（回溯），因为题目描述看起来像“旅行商”。  
- **最容易踩的坑**  
  1. 忽略了“每块石头只能踩一次”这一限制，导致写出会重复访问的方案。  
  2. 没有考虑 **奇偶下标交叉** 的结构，导致找不到最小上界。  
  3. 边界情况：当石头数只有 2 或 3 时，`i+2` 可能越界，需要提前处理。  
- **下次遇到同类题**：第一步先**画图**，观察**是否可以把路径拆成两条交错的链**（前进跳过、返回补上），再找出**必须跨过的最远距离**，这通常就是答案的下界。  

祝你在算法的旅程中 “跳”得更远、更稳！
