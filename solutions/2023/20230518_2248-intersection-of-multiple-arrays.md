## 题目（中文翻译）

给定一个二维整数数组 `nums`，其中 `nums[i]` 表示第 `i` 个整数数组，且每个数组内的元素互不相同。请返回一个数组，包含所有同时出现在 **每个** 数组中的整数。返回的结果可以任意顺序排列，如果不存在这样的整数，则返回空数组 `[]`。

**示例 1：**  
**输入：** `nums = [[3,1,2,4,5],[1,2,3,4],[3,4,5,6]]`  
**输出：** `[3,4]`  
**解释：**  
唯一同时出现在 `nums[0] = [3,1,2,4,5]`、`nums[1] = [1,2,3,4]` 和 `nums[2] = [3,4,5,6]` 中的整数是 `3` 和 `4`，因此返回 `[3,4]`。

**示例 2：**  
**输入：** `nums = [[1,2,3],[4,5,6]]`  
**输出：** `[]`  
**解释：**  
不存在同时出现在 `nums[0]` 和 `nums[1]` 中的整数，故返回空列表 `[]`。

**约束条件：**  
- `1 <= nums.length <= 1000`  
- `1 <= sum(nums[i].length) <= 1000`  
- `1 <= nums[i][j] <= 1000`  
- `nums[i]` 中的所有值互不相同。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**把第一个子数组的每个元素，逐个去检查它是否出现在其它所有子数组里**。  
这跟我们在生活中找“共同的爱好”差不多：先把 A 朋友的兴趣列出来，然后一个一个去看 B、C、… 朋友是否也有同样的兴趣。

实现上可以：

1. 取 `nums[0]`（第一个子数组）作为基准集合 `base`。  
2. 对 `base` 中的每个整数 `x`，遍历剩下的所有子数组 `nums[1:]`，使用 `x in subarray`（线性查找）判断是否出现。  
3. 只要 `x` 在 **所有** 子数组里出现，就把它加入答案列表 `res`。

因为题目保证每个子数组内部的元素互不相同（就像每本词典里每个词只出现一次），所以不必担心同一个子数组里会出现多次。

> **为什么一定对？**  
> 如果一个数在每个子数组里都出现过，那么在我们遍历 `base` 时一定会碰到它；相反，如果它缺席了任意一个子数组，我们在检查的过程中就会发现并把它剔除。

#### 代码（Python）

```python
from typing import List

def intersection(nums: List[List[int]]) -> List[int]:
    # 1. 取第一个子数组作为基准集合
    base = nums[0]
    res = []                     # 用来存放最终答案

    # 2. 遍历基准集合中的每个数
    for x in base:
        found_in_all = True      # 假设 x 出现在所有子数组里

        # 3. 检查其余每个子数组是否包含 x
        for sub in nums[1:]:
            if x not in sub:     # 线性查找，O(len(sub))
                found_in_all = False
                break           # 只要有一个子数组不包含，就可以停下来

        # 4. 如果所有子数组都包含，则加入答案
        if found_in_all:
            res.append(x)

    return res
```

#### 复杂度

- **时间复杂度**：`O(k * m)`  
  - `k` 为第一个子数组的长度（最多 1000），  
  - `m` 为其余所有子数组的总元素数（同样不超过 1000）。  
  - 用大白话说，就是“把第一个数组的每个数字，和其它所有数字各比一次”。如果把 `O(k*m)` 想象成“几千次的比较”，在本题的数据范围内还能接受，但不是最省事的做法。

- **空间复杂度**：`O(1)`（不计返回列表）  
  - 只用了常数级别的额外变量 `found_in_all`、`res`（返回值不算额外空间）。

### 2. 最优解

#### 思路  

从暴力解可以看到，**瓶颈在于每次都要在子数组里做线性查找**（`x not in sub`），这会导致重复的比较。  
如果我们能够**把查找的时间降到 O(1)**，整体复杂度自然会下降。

**哈希表（字典）** 正好可以帮我们做到常数时间的查找。  
思路如下：

1. **统计每个整数出现的次数**。遍历所有子数组，把每个整数记进哈希表 `cnt`，键是整数，值是它出现的子数组个数。  
   - 由于同一个子数组内部的数字互不相同，直接把每个数字计一次即可。  
2. **筛选**：遍历哈希表，挑出出现次数等于子数组总数 `len(nums)` 的整数，这些就是在 **所有** 子数组里都出现的公共元素。

> **类比**：把哈希表想象成“登记簿”，每当看到一个数字，就在登记簿上给它的名字旁边画一个勾。最后，只要名字旁边的勾数等于总登记人数（子数组个数），说明每个人都说过这个名字，它就是公共的。

#### 代码（Python）

```python
from typing import List
from collections import defaultdict

def intersection(nums: List[List[int]]) -> List[int]:
    # 1. 用哈希表统计出现次数，defaultdict(int) 会默认值为 0
    cnt = defaultdict(int)

    # 2. 遍历所有子数组
    for sub in nums:
        for x in sub:            # 子数组内部数字唯一，无需去重
            cnt[x] += 1          # 计数加一

    # 3. 只保留出现次数等于子数组个数的数字
    total_arrays = len(nums)
    res = [x for x, c in cnt.items() if c == total_arrays]

    return res
```

#### 复杂度

- **时间复杂度**：`O(N)`  
  - `N` 为所有子数组元素的总数（题目给出的上限是 1000），我们只遍历了一遍并做 O(1) 的哈希操作。  
  - 用大白话说，就是“每个数字只看一次”，比暴力解的“每个数字要比很多次”快很多。

- **空间复杂度**：`O(U)`  
  - `U` 为所有出现过的不同整数的个数。最坏情况下每个数字都不相同，`U = N`，即需要额外的哈希表来存这些数字。  
  - 这相当于“登记簿的大小随出现的不同名字而增大”，在本题的约束下也很小（≤1000）。

## 心得

- **核心技巧**：使用哈希表统计出现次数，然后挑出出现次数等于数组个数的元素。  
- **适用的题型**  
  1. 多个数组的交集（本题）。  
  2. 找出出现次数恰好为 `k` 的元素（如 LeetCode 2299 “强密码检验”。）  
  3. 统计字符/数字出现频率后筛选（如 “出现最多的字符” 系列题目）。  
- **解题钥匙**：**把“是否在每个数组里”转化为“出现次数等于数组个数”。**

## 反思

- **第一反应**：把第一个数组的元素一个个去检查——这就是暴力解的思路。  
- **最容易踩的坑**  
  - 忘记每个子数组内部的元素是唯一的，导致在统计时出现重复计数。  
  - 忽略空数组的情况（本题约束 `nums.length >= 1`，但实际写代码时仍要防御性检查）。  
  - 对哈希表的键值类型不明确，导致误把字符串和整数混在一起。  
- **下次类似题目**：**第一步先想“计数”**——如果可以把“是否出现”转成“出现多少次”，往往就能用哈希表把时间降到线性。
