# #2177. 寻找三个连续整数，使其和等于给定数字 / Find Three Consecutive Integers That Sum to a Given Number

> 难度：中等 · 标签：Math、Simulation · [LeetCode 链接](https://leetcode.com/problems/find-three-consecutive-integers-that-sum-to-a-given-number/)

---

## 题目（英文原版）

**Description**

Given an integer num, return three consecutive integers (as a sorted array) that sum to num. If num cannot be expressed as the sum of three consecutive integers, return an empty array.

**Examples**

**Example 1:**

```
Input: num = 33
Output: [10,11,12]
Explanation: 33 can be expressed as 10 + 11 + 12 = 33.
10, 11, 12 are 3 consecutive integers, so we return [10, 11, 12].
```

**Example 2:**

```
Input: num = 4
Output: []
Explanation: There is no way to express 4 as the sum of 3 consecutive integers.
```

**Constraints**

- 0 <= num <= 1015

## 题目（中文翻译）

**描述**  
给定一个整数 `num`，返回三个连续整数（as a sorted array）使其和等于 `num`。如果 `num` 不能表示为三个连续整数的和，返回空数组（empty array）。

**示例 1**  
**输入**: `num = 33`  
**输出**: `[10,11,12]`  
**解释**: 33 可以表示为 `10 + 11 + 12 = 33`。10、11、12 是 3 个连续整数 (consecutive integers)，因此返回 `[10, 11, 12]`。

**示例 2**  
**输入**: `num = 4`  
**输出**: `[]`  
**解释**: 没有办法将 4 表示为 3 个连续整数的和。

**约束条件**  
- `0 <= num <= 10^15`   (即 `num` 的取值范围为 0 到 10 的 15 次方)

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：把所有可能的“三连数”枚举一遍，看看它们的和是否等于 `num`。  

- **数据结构**：只需要普通的整数变量和一个列表来保存答案。可以把“连续的三个整数”想象成 **排队的三个人**，我们让这三个人依次站在不同的位置，检查他们的年龄总和是否正好等于目标值 `num`。  
- **正确性**：因为我们把 **所有** 合法的三连数（即形如 `a, a+1, a+2`）都尝试了一遍，只要真的存在一组满足 `a + (a+1) + (a+2) = num`，必定会在遍历过程中被找到。  
- **时间/空间分析**：  
  - 我们需要把 `a` 从 `0`（或更小的负数）一直尝试到 `num`，每一次都做一次加法比较。这样大概要进行 `num` 次循环，时间复杂度是 **O(num)**。如果 `num` 最大到 `10^15`，显然不可接受——想象一下要数到一千兆次，需要几千年！  
  - 只用了常数个变量来保存中间结果，空间复杂度是 **O(1)**（常数级）。

> **大白话解释**：`O(num)` 就像说“跑多少步就要看你要跑多远”。如果路程是 10^15 步，显然跑不完。  

#### 代码（Python）

```python
def three_consecutive_bruteforce(num: int) -> list[int]:
    """
    暴力枚举所有可能的起点 a，使得 a + (a+1) + (a+2) == num
    """
    # 为了兼容负数情况，我们从 -num 开始枚举，足够覆盖所有可能
    #（因为 a + a+1 + a+2 = 3a + 3，若 a 过小，和必然小于 num）
    start = -abs(num)          # 负数起点，确保不漏解
    end   = abs(num) + 1       # 正数终点，足够大

    for a in range(start, end):
        s = a + (a + 1) + (a + 2)   # 计算三数之和
        if s == num:                # 找到匹配
            return [a, a + 1, a + 2]   # 已经是递增顺序
    return []                       # 没有解，返回空列表
```

#### 复杂度

- **时间复杂度**：`O(num)`  
  - 意味着循环次数和输入大小 `num` 成正比。`num = 10^6` 时需要大约一百万次循环，已经不算快；`num = 10^15` 时更是不可行。  
- **空间复杂度**：`O(1)`  
  - 只用了常数个整数变量，和 `num` 的大小无关。

### 2. 最优解

#### 思路  

从暴力解可以看到，**瓶颈**在于我们把所有可能的 `a` 都遍历了一遍。其实可以用等式本身直接求解：

1. **把三个连续数写成更易处理的形式**  
   任意三个连续整数可以表示为 `x-1, x, x+1`（这里 `x` 是中间的数）。  
2. **求和**  
   \[
   (x-1) + x + (x+1) = 3x
   \]  
   所以，只要这三个数的和等于 `num`，就必须满足 `3x = num`。  
3. **直接求 `x`**  
   - 如果 `num` 能被 `3` 整除，则 `x = num // 3`（整数除法）。  
   - 否则根本不存在整数 `x` 使得 `3x = num`，题目要求返回空数组。  

这一步把 **遍历** 变成了 **一次算术运算**，时间从 `O(num)` 降到了 `O(1)`，即不管 `num` 多大，都是常数时间。

> **类比**：想象你在找三个人的年龄总和等于 `num`，如果你知道“每个人的年龄相差 1”，那么只要把总和除以 3，就直接得到中间那个人的年龄——不需要逐个试探。

**特殊情况**  
- `num = 0` 时，`x = 0`，返回 `[-1, 0, 1]`（负数也是合法的整数）。  
- 题目并未限制返回的整数必须非负，只要是整数即可。

#### 代码（Python）

```python
def three_consecutive_optimal(num: int) -> list[int]:
    """
    O(1) 时间求解：
    - 若 num 能被 3 整除，则中间数为 x = num // 3，答案为 [x-1, x, x+1]
    - 否则返回空列表
    """
    # 先判断能否整除 3
    if num % 3 != 0:          # 余数不为 0，说明没有整数 x 能满足 3x = num
        return []             # 直接返回空数组

    x = num // 3               # 中间的整数
    return [x - 1, x, x + 1]    # 已经是递增顺序的三个连续整数
```

#### 复杂度

- **时间复杂度**：`O(1)`  
  - 只做了几次算术运算和一次取模判断，和 `num` 的大小毫无关系。相比暴力的 `O(num)`，相当于“一眨眼的功夫”。  
- **空间复杂度**：`O(1)`  
  - 只创建了长度为 3 的固定列表，所需空间不随 `num` 变化。

## 心得

- **核心技巧**：把连续整数转化为“中间数 ± 1”的形式，利用等式直接求解。  
- **适用的题型**：  
  1. “把若干连续整数的和表示为给定数”——如 “找两数连续的和”等。  
  2. “把等差数列的前 n 项和等于某值”——常用等差数列求和公式。  
- **一句话总结**：**只要把“连续”这层约束写成代数式，就能把遍历问题直接化为一次除法检查**。

---

## 反思

- **第一反应**：直接遍历所有可能的起点 `a`，用循环暴力检查。  
- **最容易踩的坑**：  
  - 忽略了负数的可能性（有时题目只要求非负解，需要额外判断 `x-1 >= 0`）。  
  - 对大数（`10^15`）使用 `O(num)` 的算法会超时。  
  - 没有注意到 `3x = num` 必须成立，导致忘记使用取模判断。  
- **下次遇到同类题**：第一步先**写出等式**，看能否把“连续”或“等差”这类约束转化为**代数公式**，再判断是否可以直接求解或只需要常数时间的检查。
