# #2404. 最频繁的偶数元素 / Most Frequent Even Element

## 题目（英文原版）

**Description**

Given an integer array nums, return the most frequent even element.
If there is a tie, return the smallest one. If there is no such element, return -1.

**Examples**

**Example 1:**

```
Input: nums = [0,1,2,2,4,4,1]
Output: 2
Explanation:
The even elements are 0, 2, and 4. Of these, 2 and 4 appear the most.
We return the smallest one, which is 2.
```

**Example 2:**

```
Input: nums = [4,4,4,9,2,4]
Output: 4
Explanation: 4 is the even element appears the most.
```

**Example 3:**

```
Input: nums = [29,47,21,41,13,37,25,7]
Output: -1
Explanation: There is no even element.
```

**Constraints**

- 1 <= nums.length <= 2000
- 0 <= nums[i] <= 105

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**把每一个偶数都“数一遍”，看它在数组里出现了几次**。  
可以这样做：

1. 先遍历一次数组，找到所有偶数，记下来（比如放进一个列表 `evens`）。
2. 对 `evens` 中的每个数 `x`，再遍历一遍原数组，统计 `x` 出现的次数。
3. 把次数最大的偶数记为答案；如果出现次数相同，则取值更小的那个。  
4. 如果遍历完都没有找到偶数，返回 `-1`。

> **类比**：把数组想象成一本书，偶数是我们关心的关键词。暴力解相当于对每个关键词，都去整本书里翻一遍，看看它出现了多少次。虽然能得到正确答案，但效率很低。

#### 代码（Python）

```python
def most_frequent_even_bruteforce(nums):
    # 1️⃣ 先把所有偶数收集起来
    evens = [x for x in nums if x % 2 == 0]

    # 如果根本没有偶数，直接返回 -1
    if not evens:
        return -1

    best_num = -1          # 当前出现次数最多的偶数
    best_cnt = 0           # 对应的出现次数

    # 2️⃣ 对每个偶数，再遍历一次数组统计出现次数
    for x in evens:
        cnt = 0
        for y in nums:            # 这里又遍历了一遍完整的 nums
            if y == x:
                cnt += 1

        # 3️⃣ 更新答案：次数更大，或次数相同但数值更小
        if cnt > best_cnt or (cnt == best_cnt and x < best_num):
            best_cnt = cnt
            best_num = x

    return best_num
```

#### 复杂度

- **时间复杂度**：`O(n²)`  
  解释：`n` 是数组长度。外层遍历所有偶数（最坏情况是 `n` 个），内层又遍历整个数组一次，所以大约是 `n × n` 次比较。用大白话说，就是“每增加一个元素，工作量会像正方形一样快速增长”。
- **空间复杂度**：`O(n)`  
  解释：我们额外用了一个列表 `evens` 来保存所有偶数，最坏情况下它会和原数组等长。除了这份额外空间，其他都是常数级别。

### 2. 最优解

#### 思路  

暴力解的瓶颈在 **“每次都要重新遍历整个数组统计次数”**。  
我们可以把 **“数次数”** 这件事一次性完成，然后再在这些统计结果里挑出答案。

**核心技巧：哈希表（字典）**  
- 哈希表就像一本“词典”，**key** 是我们关心的偶数，**value** 是它出现的次数。  
- 只需要 **一次遍历**，把每个偶数的次数记录进去；随后再遍历哈希表找到出现次数最高、且值最小的那个键。

步骤：

1. 初始化一个空字典 `cnt = {}`。  
2. 遍历 `nums`，如果当前数是偶数，就把它在字典里的计数加一。  
   - `cnt[x] = cnt.get(x, 0) + 1` 的意思是：如果 `x` 之前没有出现过，就把计数设为 0，然后再加 1。  
3. 如果遍历结束后字典为空，说明没有偶数，返回 `-1`。  
4. 否则遍历字典的键值对，维护两个变量：  
   - `max_freq`：当前最高出现次数。  
   - `answer`：对应的最小偶数。  
   对每个 `(num, freq)`，如果 `freq` 更大，或 `freq` 相同但 `num` 更小，就更新这两个变量。  
5. 最终返回 `answer`。

> **类比**：把数组想象成一条流水线，哈希表是旁边的记事本。每当一个偶数经过时，我们就在记事本上把它的计数“打勾”。只需要一次走完流水线，就能得到所有偶数的出现次数。

#### 代码（Python）

```python
def most_frequent_even(nums):
    """
    使用哈希表一次遍历统计偶数出现次数，时间 O(n)，空间 O(k)（k 为不同偶数的个数）。
    """
    # 1️⃣ 建立计数表，只记录偶数
    cnt = {}                         # 键：偶数，值：出现次数
    for x in nums:
        if x % 2 == 0:               # 只关心偶数
            cnt[x] = cnt.get(x, 0) + 1   # 没出现过就当作 0，再加 1

    # 2️⃣ 如果没有任何偶数，直接返回 -1
    if not cnt:
        return -1

    # 3️⃣ 在计数表中找出现次数最多且数值最小的偶数
    answer = -1
    max_freq = 0
    for num, freq in cnt.items():
        # ① 出现次数更大，或者
        # ② 出现次数相同但数值更小
        if freq > max_freq or (freq == max_freq and num < answer):
            max_freq = freq
            answer = num

    return answer
```

#### 复杂度

- **时间复杂度**：`O(n)`  
  解释：我们只遍历了一遍原数组（`n` 次）以及一次遍历哈希表（最多 `k` 次，`k ≤ n`），所以总体是线性增长。用大白话说，就是“每增加一个元素，只会多一次简单的操作”，不会出现指数或平方级的爆炸。
- **空间复杂度**：`O(k)`（`k` 为不同偶数的数量，最坏情况下 `k ≤ n`）  
  解释：哈希表里只存放出现过的偶数及其计数，最多占用与原数组等长的空间。

## 心得

- **核心技巧**：利用哈希表（字典）一次遍历统计频次，然后在统计结果中挑选最优解。  
- **适用的题型**  
  1. “出现次数最多的元素”类（如 LeetCode 169 – Majority Element）。  
  2. “出现次数统计并筛选”类（如 统计字符出现次数的题目）。  
  3. “满足某种属性的最高频元素”类（如只统计奇数、只统计正数等）。  
- **一句话总结解题钥匙**：**“把‘数多少次’这件事提前完成，用哈希表一次记录，后面只需要挑选最优即可”。**

## 反思

- **第一反应**：看到“最常出现的偶数”，自然想到“遍历计数”。一开始可能会直接写两层循环（暴力），因为这是最直观的实现方式。  
- **最容易踩的坑**  
  1. **忘记只统计偶数**：如果把所有元素都计数，最终可能返回一个奇数。  
  2. **平局处理错误**：出现次数相同的情况下，需要返回最小的偶数，容易忘记比较数值大小。  
  3. **空数组/无偶数**：没有偶数时要返回 `-1`，而不是默认的 0 或者其他值。  
- **下次类似题的第一步**：**先判断筛选条件（偶数、奇数、正数…）并在遍历时直接过滤**，随后用哈希表收集频次，再在哈希表里挑选答案。这样可以一步到位避免不必要的重复遍历。
