## 题目（英文原版）

**Description**

You are given an even integer n representing the number of houses arranged in a straight line, and a 2D array cost of size n x 3, where cost[i][j] represents the cost of painting house i with color j + 1.
The houses will look beautiful if they satisfy the following conditions:
Return the minimum cost to paint the houses such that they look beautiful.

**Examples**

**Example 1:**

```
Input: n = 4, cost = [[3,5,7],[6,2,9],[4,8,1],[7,3,5]]
Output: 9
Explanation:
The optimal painting sequence is [1, 2, 3, 2] with corresponding costs [3, 2, 1, 3] . This satisfies the following conditions:
The minimum cost to paint the houses so that they look beautiful is 3 + 2 + 1 + 3 = 9 .
```

**Example 2:**

```
Input: n = 6, cost = [[2,4,6],[5,3,8],[7,1,9],[4,6,2],[3,5,7],[8,2,4]]
Output: 18
Explanation:
The optimal painting sequence is [1, 3, 2, 3, 1, 2] with corresponding costs [2, 8, 1, 2, 3, 2] . This satisfies the following conditions:
The minimum cost to paint the houses so that they look beautiful is 2 + 8 + 1 + 2 + 3 + 2 = 18 .
```

**Constraints**

- 2 <= n <= 105
- n is even.
- cost.length == n
- cost[i].length == 3
- 0 <= cost[i][j] <= 105

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把每一栋房子都尝试所有可能的颜色，然后挑出满足所有约束且费用最小的那种。  
- **数据结构**：我们可以把 `cost` 看成一本“价格字典”。字典的 **键** 是 `(房子编号, 颜色)`，**值** 是对应的油漆费用。  
- **暴力遍历**：从第 0 栋房子开始，枚举它的 3 种颜色；再枚举第 1 栋房子的 3 种颜色……一直枚举到第 `n‑1` 栋。每一次完整的枚举就得到一种“涂色方案”。  
- **合法性检查**：对每种方案，检查两条规则  
  1. 相邻的两栋房子颜色不同；  
  2. 因为 `n` 为偶数，第 `i` 栋房子和第 `i + n/2` 栋（相距 `n/2`）的颜色也必须不同。  
- **费用累计**：如果方案合法，就把它所有房子的费用相加，记录最小值。

> 这就是“穷举所有可能”，在编程里常被叫作 **暴力搜索**（Brute Force）。

#### 代码（Python）

```python
from itertools import product

def paint_house_bruteforce(n: int, cost):
    # 所有颜色的编号 0,1,2（对应题目中的 1,2,3）
    colors = [0, 1, 2]
    best = float('inf')               # 当前找到的最小费用

    # product 会产生 3^n 种颜色组合，类似于嵌套的 n 层 for 循环
    for seq in product(colors, repeat=n):
        ok = True
        # 检查相邻两栋房子颜色是否相同
        for i in range(1, n):
            if seq[i] == seq[i - 1]:
                ok = False
                break
        # 检查相距 n/2 的两栋房子颜色是否相同
        if ok:
            half = n // 2
            for i in range(half):
                if seq[i] == seq[i + half]:
                    ok = False
                    break
        # 如果合法，计算费用
        if ok:
            total = sum(cost[i][seq[i]] for i in range(n))
            best = min(best, total)

    return best
```

> **注意**：上述代码只能在 `n` 很小（比如 `n ≤ 10`）时跑得完，因为它会产生 `3^n` 种可能。

#### 复杂度  

- **时间复杂度**：`O(3^n)`  
  - 这里的 `3^n` 表示“每栋房子有 3 种选择”，所以总共要尝试指数级别的组合。  
  - 用生活化的说法，就是如果有 20 栋房子，你得检查 **3 的 20 次方**（约 3.5 × 10⁹）种涂法，根本不可能在一秒钟内算完。  
- **空间复杂度**：`O(n)`  
  - 只需要保存当前枚举的颜色序列（长度 `n`）和一些常数级别的辅助变量。

### 2. 最优解

#### 思路  

从暴力解可以看到，**瓶颈**在于我们一次性枚举所有房子的颜色。  
实际上，**相邻约束**和 **相距 n/2 约束** 只涉及**相邻的两栋**或**相距固定距离的两栋**，这让我们可以把问题拆分成**局部子问题**，用**动态规划（DP）**来逐步累加最小费用。

---

#### 2.1 为什么要把相距 n/2 的两栋房子放在一起考虑？

因为 `n` 为偶数，房子可以自然地分成 `n/2` 对 “对称的房子”：  

```
0 ----- n/2
1 ----- n/2+1
...
(n/2-1) ----- n-1
```

每一对里的两栋必须颜色不同。  
如果我们一次只处理单个房子，就必须在以后某一步“记住”它的颜色，以便在处理它的对称房子时检查是否冲突。  
这会导致状态需要记住 **两栋房子的颜色**，实现起来稍显繁琐。

**更好的办法**是把每一对房子视为一个**整体**，一次决定这两栋的颜色组合。  
- 每对房子有 `3 × 3 = 9` 种可能的颜色组合（左边颜色 a，右边颜色 b），但其中 `a == b` 的组合是非法的，所以实际上合法组合只有 `3 × 2 = 6` 种。  
- 这样，整个房子序列就变成了 `n/2` 个“块”。块之间的约束只有 **相邻块的左侧颜色必须不同**，以及 **相邻块的右侧颜色必须不同**（因为相邻的实际房子仍然相邻）。  

这正好适合 **一维 DP**：  

- **状态** `dp[i][a][b]` 表示处理到第 `i` 对（0‑based）时，左侧第 `i` 栋房子颜色是 `a`、右侧第 `i` 栋房子颜色是 `b`，且所有约束都满足的最小费用。  
- **转移**：从第 `i‑1` 对的颜色 `(pa, pb)` 转到第 `i` 对的颜色 `(a, b)`，只要 `a != pa` 且 `b != pb`（相邻块左右颜色不能相同）即可。费用则是 `dp[i‑1][pa][pb] + cost[i][a] + cost[i+half][b]`。  
- **初始化**：`i = 0` 时直接把第 0 对的费用算进去。  
- **答案**：`i = n/2 - 1` 时，遍历所有合法 `(a, b)` 取最小值。

因为每个块只有最多 **9** 种状态，转移时最多检查 **9 × 9 = 81** 种组合，整体时间是 `O((n/2) * 81) = O(n)`，空间可以只保留前一行的 DP（`O(9)`）。

---

#### 2.2 动态规划实现细节

1. **把颜色编号改成 0/1/2**（方便数组索引）。  
2. **预处理**：`half = n // 2`。  
3. **合法组合列表**：`valid = [(a, b) for a in range(3) for b in range(3) if a != b]`（6 条）。  
4. **DP 表**：用一个字典或二维列表保存当前块的最小费用。  
5. **转移**时遍历 `prev`、`cur` 两个合法组合，若 `cur[0] != prev[0]` 且 `cur[1] != prev[1]`，则可以转移。  
6. **费用累加**：`cost[cur[0]]` 来自左侧房子 `i`，`cost[cur[1]]` 来自右侧房子 `i+half`。  
7. **最终答案**：遍历最后一块的所有状态，取最小值。

---

#### 代码（Python）

```python
def paintHouse(n: int, cost):
    """
    动态规划 + 把相距 n/2 的房子成对处理
    时间复杂度：O(n)   空间复杂度：O(1)（只保留前一行）
    """
    half = n // 2                     # 每对中左侧房子索引 i，右侧房子索引 i+half

    # 所有合法的颜色组合 (左颜色, 右颜色)，左 != 右
    valid = [(a, b) for a in range(3) for b in range(3) if a != b]   # 长度 6

    # dp_prev[(a,b)] = 到当前块为止的最小费用
    dp_prev = {}

    # 第 0 对的初始化
    for a, b in valid:
        dp_prev[(a, b)] = cost[0][a] + cost[half][b]

    # 从第 1 对遍历到第 half-1 对
    for i in range(1, half):
        dp_cur = {}
        for a, b in valid:                     # 当前块的颜色组合
            cur_cost = cost[i][a] + cost[i + half][b]   # 只加当前两栋的费用
            best = float('inf')
            for pa, pb in valid:               # 前一块的颜色组合
                # 相邻块的左侧颜色、右侧颜色必须不同
                if a != pa and b != pb:
                    cand = dp_prev[(pa, pb)] + cur_cost
                    if cand < best:
                        best = cand
            dp_cur[(a, b)] = best
        dp_prev = dp_cur                       # 把当前行变成下一轮的“前一行”

    # 最后一个块结束后，答案就是所有状态中的最小值
    return min(dp_prev.values())
```

**代码要点说明**（每行中文注释已在代码中给出）：

- `valid` 用来枚举 **合法的颜色对**，省掉了 `a == b` 的非法情况。  
- `dp_prev` 只保存上一对的 6 种状态，空间恒定。  
- 内层的 `for pa, pb in valid` 实际上是 **遍历所有可能的前一个状态**，检查 “左侧颜色不同且右侧颜色不同” 两个条件后再更新最小费用。  
- 最后 `min(dp_prev.values())` 就是把所有合法的结尾状态取最小，得到全局最优。

#### 复杂度  

- **时间复杂度**：`O(n * 9 * 9) ≈ O(n)`  
  - 解释：我们遍历 `n/2` 对，每对有最多 9 种（实际 6 种）状态，转移时最多检查 9×9 = 81 种组合。常数很小，整体随 `n` 线性增长。相较于暴力的 `3^n`，这就像把 **指数级** 的工作量压缩成了 **线性** 的工作量。  
- **空间复杂度**：`O(1)`（实际上是 `O(9)`）  
  - 只保留前一行的 DP 表，大小固定为 9（合法组合数），与 `n` 大小无关。

## 心得

- **核心技巧**：把“相距固定距离的约束”转化为“成对处理”，再使用**状态压缩的动态规划**。  
- **适用的题型**  
  1. **Paint House 系列**（相邻颜色不同）+ 额外“远距离”约束的变形。  
  2. **环形或周期性约束**的 DP（如把首尾视为相邻，或者把第 `i` 与第 `i+k` 关联）。  
  3. **配对 DP**：把两个位置一起决策，如“跳棋”或“棋盘对角线配对”类问题。  
- **一句话总结**：**把能一起决定的房子组合成块，用块之间的局部约束做 DP，既满足所有全局限制，又保持线性时间。**

## 反思

- **第一反应**：直接枚举所有颜色组合（暴力搜索），因为题目看起来只涉及“相邻”和“相距 n/2”两条简单规则。  
- **最容易踩的坑**  
  1. **忘记“相距 n/2 的颜色必须不同”**，只检查相邻会得到错误的最小费用。  
  2. **边界错误**：`n` 是偶数，`half = n // 2` 必须用整数除法；在循环里访问 `i + half` 时要确保不越界。  
  3. **状态重复**：如果直接在 DP 中只保存单个颜色，会丢失对称房子的颜色信息，导致后面无法检查远距离约束。  
- **下次类似题目**：第一步先思考 **约束之间的距离**，看能否把“远距离约束”配对或合并成“同一块”。如果能把问题划分为若干块，每块的内部状态有限且相邻块之间的约束简单，就可以尝试 **块状 DP**（状态压缩 DP）来实现线性或准线性解法。
