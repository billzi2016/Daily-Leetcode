# #3324. 找出屏幕上出现的字符串序列 / Find the Sequence of Strings Appeared on the Screen

> 难度：中等 · 标签：String、Simulation · [LeetCode 链接](https://leetcode.com/problems/find-the-sequence-of-strings-appeared-on-the-screen/)

---

## 题目（英文原版）

**Description**

You are given a string target.
Alice is going to type target on her computer using a special keyboard that has only two keys:
Note that initially there is an empty string "" on the screen, so she can only press key 1.
Return a list of all strings that appear on the screen as Alice types target, in the order they appear, using the minimum key presses.

**Examples**

**Example 1:**

```
Input: target = "abc"
Output: ["a","aa","ab","aba","abb","abc"]
Explanation:
The sequence of key presses done by Alice are:
```

**Example 2:**

```
Input: target = "he"
Output: ["a","b","c","d","e","f","g","h","ha","hb","hc","hd","he"]
```

**Constraints**

- 1 <= target.length <= 400
- target consists only of lowercase English letters.

## 题目（中文翻译）

你得到一个字符串 `target`。  
Alice 要在电脑上输入 `target`，她使用的键盘只有两个键：

1. **键 1**（Increment Key）：如果当前屏幕为空字符串 `""`，按一次会在屏幕上显示字符 `'a'`；否则把屏幕上最后一个字符按字母顺序向后移动一位（即 `'a'→'b'`, `'b'→'c'`, …, `'z'→'a'`），并保持其它字符不变。  
2. **键 2**（Append‑`a` Key）：在屏幕末尾追加一个字符 `'a'`。

> 注意：一开始屏幕上是空字符串 `""`，因此 Alice 只能先按键 1。

请返回 Alice 在以 **最少按键次数** 输入完整 `target` 的过程中，屏幕上出现的所有字符串，按照出现的先后顺序组成的列表。

```text
Input: target = "abc"

Explanation:

3. 按键 1 → "ab"
```

```text
2. 按键 2 在末尾追加 'a' → "ha"
3. 再次按键 1 递增末尾字符 → "hb","hc","hd","he"
```

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  
最直接的想法是把 **两键的所有可能组合** 全部枚举出来，看看哪一种在敲完键以后正好得到 `target`，并把途中出现的每个字符串记录下来。  
- **键 1**：在当前屏幕字符串的末尾*追加*一个字符 `'a'`（就像在纸上写下一个 `'a'`）。  
- **键 2**：把屏幕上**最后一个字符**往后移动一位，例如 `'a' → 'b'`、`'b' → 'c'` ……（可以把它想象成把字典里最后一页的单词改成下一个单词的首字母）。  

我们可以把一次敲键看成一次“状态转移”。从空串 `""` 开始，所有可能的状态形成一棵二叉树：左子树对应按键 1，右子树对应按键 2。遍历这棵树（比如 BFS）并记录每条路径对应的字符串序列，只要路径的最后一个字符串等于 `target`，就把这条路径的所有中间字符串返回。  

**为什么这种方法能得到答案**  
因为我们把**所有**合法的敲键序列都穷举了，必然会包含最短（即最少按键次数）的那条序列。只要在遍历过程中把每一次按键产生的字符串保存下来，就可以得到题目要求的“出现的所有字符串”。  

**时间/空间复杂度**  
- **时间复杂度**：假设我们最多按 `m` 次键（`m` 取决于 `target` 的长度和字符大小），每一步都有 2 种选择，则总的搜索空间是 `2^m`，属于指数级别。  
- **空间复杂度**：同样需要保存整棵搜索树的节点，最坏情况下也是 `O(2^m)`。  

> 用大白话说，指数级的 `2^m` 就像让你在每一步都要同时走左边和右边的路，路数会以每一步翻倍，几分钟就会变成几千甚至几万条路径，根本不可行。

---

### 2. 最优解  

#### 思路  

从暴力解可以看出，**搜索整棵二叉树是浪费的**，因为我们根本不需要尝试所有可能的按键顺序，只要找出一种**必然最短**的方式即可。下面一步步推导出最优策略。

1. **观察键 2 的限制**  
   键 2 只能修改**最后一个字符**，而且只能向后递增（`'a' → 'b' → … → 'z'`）。这意味着一旦某个字符已经确定，它就永远不会再被改动。  

2. **明确每个字符的来源**  
   为了得到目标字符串的第 `i` 个字符 `target[i]`，我们只能在已经得到的前缀 `target[:i]` 基础上再 **追加一个 `'a'`**（键 1），然后用键 2 把这个 `'a'` 逐步递增到 `target[i]`。  
   - 不能直接跳过 `'a'` 而一次性得到 `'c'`，因为键 2 没有“一次性加 2”的操作。  
   - 也不能在已经确定的前缀上再按键 2，因为它只会改动最后一个字符，破坏已经正确的部分。  

3. **最小化按键次数**  
   对于每个目标字符 `c`，从 `'a'` 递增到 `c` 需要恰好 `ord(c) - ord('a')` 次键 2。再加上一键 1 的 “追加 `'a'`”，这就是 **不可再压缩的最少次数**。  

4. **构造完整的出现序列**  
   - 初始化 `cur = ""`（屏幕为空）。  
   - 依次遍历 `target` 中的字符 `c`：  
     1. **键 1** → `cur += 'a'`，把新出现的字符串加入答案。  
     2. **键 2** 循环 `ord(c) - ord('a')` 次：每次把 `cur[-1]` 加 1（即 `chr(ord(cur[-1]) + 1)`），并把每一次的结果加入答案。  
   - 循环结束后，`cur` 正好等于 `target`，答案列表即为题目要求的顺序。  

> **类比**：想象你在拼装一列火车，每次只能往车尾添加一节空车厢（键 1），然后再把这节车厢的颜色从白色一步步涂成目标颜色（键 2）。因为颜色只能一步步往前改，最省力的办法就是每次都先加空车厢，再一步步上色。  

#### 代码（Python）  

```python
def sequenceOfScreen(target: str):
    """
    返回在最少按键次数下，屏幕上出现的所有字符串序列。
    """
    ans = []               # 用来存放每一次按键后出现的字符串
    cur = ""               # 当前屏幕内容

    for ch in target:                     # 逐个处理目标字符
        # 1️⃣ 按键 1：在末尾追加一个 'a'
        cur += 'a'
        ans.append(cur)                  # 记录出现的字符串

        # 2️⃣ 按键 2：把最后一个字符从 'a' 递增到目标字符 ch
        # 需要的次数等于 ch 与 'a' 的字母序差值
        inc_times = ord(ch) - ord('a')
        for _ in range(inc_times):
            # 把最后一个字符加 1
            cur = cur[:-1] + chr(ord(cur[-1]) + 1)
            ans.append(cur)              # 每一次递增后都记录

    return ans
```

**关键行中文注释**  
- `cur += 'a'` ：模拟键 1，向屏幕末尾追加一个 `'a'`。  
- `inc_times = ord(ch) - ord('a')` ：计算从 `'a'` 需要递增多少次才能得到目标字符 `ch`。  
- `cur = cur[:-1] + chr(ord(cur[-1]) + 1)` ：模拟键 2，只改变最后一个字符并把它往后移动一位。  

#### 复杂度  

- **时间复杂度**：`O(total_presses)`，其中  
  `total_presses = Σ (1 + (target[i] - 'a')) ≤ 26 * len(target)`。  
  用大白话说，就是每个字符最多要按 1 次键 1 再按 25 次键 2，整体是线性时间 `O(n)`（`n` 为目标字符串长度）。  

- **空间复杂度**：`O(total_presses)` 用于存放返回的字符串列表。若只关心额外的工作空间（不计输出），则为 `O(1)`，因为我们只维护一个当前字符串 `cur`。

## 心得  

- **核心技巧**：**逐字符构造 + 最小递增**。把目标字符拆成“先加 `'a'` 再递增到目标”。  
- **适用的题型**  
  1. 只能在字符串末尾追加字符且只能递增最后字符的模拟题（如 “Keyboard Typing” 系列）。  
  2. 需要最少操作数的字符转换问题（例如把一个字符串全变成 `'z'`，只能一次递增一个字符）。  
  3. 类似的“单调递增”或“单调栈”思路的最优构造问题。  
- **一句话总结**：**每次只能往后走，最短路径就是“先添 `'a'` 再一步步爬到目标”。**  

## 反思  

- **第一反应**：看到只有两键会立刻想到“二叉树搜索”。但仔细分析键的作用后，发现搜索整棵树是多余的。  
- **最容易踩的坑**  
  - 忘记在每一次 **键 2** 递增后都要把当前字符串加入答案，导致返回的序列缺失中间状态。  
  - 没考虑字符 `'a'` 的特殊情况：如果目标字符本身就是 `'a'`，只需要键 1，不要再多余地递增。  
  - 对字符 `'z'` 以后的递增没有限制（题目保证只出现小写字母），若忘记这一点可能会写出越界代码。  
- **下次遇到同类题**：**先判断每一步的必然操作（如必须先追加 `'a'`），再在此基础上最小化可选操作的次数**。这一步骤往往能直接得到最优解的构造思路。
