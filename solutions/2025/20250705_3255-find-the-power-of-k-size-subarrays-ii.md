## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把每一个长度为 `k` 的子数组都拿出来，**逐个检查**它们是否满足“连续且递增”的条件：

1. 取出子数组 `nums[i … i+k-1]`（这里的 `i` 从 `0` 遍历到 `n‑k`）。  
2. 用一个循环遍历子数组内部的相邻元素，检查 `nums[j] + 1 == nums[j+1]` 是否成立。  
   - 这里的 “哈希表” 类比不适用，我们只需要顺序遍历，就像在检查一本书的章节是否按顺序编号。  
3. 如果全部相邻对都满足，则子数组的 **power** 就是它的最大值（因为是递增的，最大值一定在最右边），即 `nums[i+k‑1]`；否则返回 `-1`。

这个方法**一定能得到正确答案**，因为我们把每一种可能的子数组都完整地检查了一遍。

#### 代码（Python）

```python
def power_of_subarrays_bruteforce(nums, k):
    n = len(nums)
    res = []                           # 用来存放每个窗口的答案
    for start in range(n - k + 1):    # 枚举所有左端点
        ok = True                      # 标记当前窗口是否满足条件
        # 检查窗口内部相邻元素是否递增且差值恰好为 1
        for j in range(start, start + k - 1):
            if nums[j] + 1 != nums[j + 1]:
                ok = False
                break                # 一旦不满足就可以提前结束内部循环
        if ok:
            res.append(nums[start + k - 1])   # 最大值就在最右边
        else:
            res.append(-1)
    return res
```

#### 复杂度

- **时间复杂度**：`O(n * k)`  
  - 这里的 `n` 是数组长度，`k` 是窗口大小。  
  - 可以把它想象成“每走一步（`n` 次），都要检查 `k` 步”，所以整体是 `n` 乘 `k`。  
- **空间复杂度**：`O(1)`（不计返回数组）  
  - 只用了常数个额外变量来保存中间状态。

### 2. 最优解

#### 思路  

暴力解的**瓶颈**在于每个窗口都要重新检查 `k‑1` 对相邻元素，导致 `O(nk)`。  
其实我们只需要**一次遍历**就能判断每个窗口是否满足“连续递增”。关键在于：

1. **前缀信息**：记录以当前位置 `i` 为结尾的、满足 `nums[t] + 1 == nums[t+1]` 的最长连续递增子数组的长度，记作 `dp[i]`。  
   - 如果 `nums[i] == nums[i‑1] + 1`，则 `dp[i] = dp[i‑1] + 1`；否则 `dp[i] = 1`（自己单独成段）。  
   - 这相当于在看“从左边一直向右走，走了多少步还能保持递增”。  
2. 对于以 `i` 为右端点的窗口 `[i‑k+1 … i]`（只在 `i >= k‑1` 时出现），只要 `dp[i] >= k`，说明这 `k` 个元素正好是连续递增的。此时 **power = nums[i]**（最大值在最右侧）。否则 **power = -1**。  
3. 只需要一次线性扫描即可得到所有 `dp[i]`，随后在同一次扫描里直接输出答案——这就是 **滑动窗口 + 前缀 DP** 的思路。  

**为什么只看 `dp[i]` 就够了？**  
因为 `dp[i]` 已经把左边所有满足递增的元素“压缩”进来了。如果它的长度已经 ≥ `k`，那么必然包含了最近的 `k` 个元素，而且它们之间的差都是 `1`，正好构成我们要的子数组。反之若 `< k`，无论左边再往左怎么延伸，都不可能在窗口里得到 `k` 个连续递增的数。

#### 代码（Python）

```python
def power_of_subarrays_optimal(nums, k):
    n = len(nums)
    res = [0] * (n - k + 1)   # 预先分配结果数组
    dp = 1                    # dp[i] 只需要保存当前值即可，省掉额外数组
    # i 表示当前遍历到的下标
    for i in range(n):
        if i > 0 and nums[i] == nums[i - 1] + 1:
            dp += 1           # 继续递增，长度加一
        else:
            dp = 1            # 重新开始计数

        # 当右端点 i 能构成完整窗口时（i >= k-1），判断窗口是否满足条件
        if i >= k - 1:
            if dp >= k:       # 窗口内的 k 个数是连续递增的
                res[i - k + 1] = nums[i]   # 最大值在最右边
            else:
                res[i - k + 1] = -1
    return res
```

**代码要点解释**  

- `dp` 只用一个整数保存当前的连续递增长度，**不需要整条数组**，这样空间降到 `O(1)`。  
- `i >= k - 1` 是窗口首次出现的时刻，之后每移动一步右端点 `i`，左端点自然是 `i - k + 1`。  
- 当 `dp >= k` 时，窗口一定满足要求；否则一定不满足——不必再检查每一对相邻元素。

#### 复杂度

- **时间复杂度**：`O(n)`  
  - 只遍历了一遍数组，每个元素做了常数次操作。相比暴力的 `O(nk)`，快了 **k 倍**。  
- **空间复杂度**：`O(1)`（不计返回数组）  
  - 只用了几个整数变量 `dp、i、res`，没有额外的线性存储。

## 心得

- **核心技巧**：利用 **前缀 DP**（记录以当前位置结尾的最长合法子段长度）配合 **滑动窗口**，一次遍历即可判断每个窗口是否满足特定的“局部”属性。  
- **适用场景**：  
  1. “子数组是否满足某种连续性”类题目（如连续递增、连续递减、等差等）。  
  2. 需要在滑动窗口内快速判断“最近 `k` 个元素是否全满足某个条件”。  
  3. 经典的 “最长递增子序列长度” 在固定窗口内的变形。  
- **一句话总结**：**把局部的“是否递增”信息压缩进一个计数器 `dp`，窗口只看计数器够不够长，就能瞬间得到答案。**

## 反思

- **拿到题目第一反应**：直接想“遍历每个窗口，逐个比较相邻元素”，于是写出暴力解。  
- **最容易踩的坑**：  
  - 忽略 **“连续递增且差值恰好为 1”** 的细节，误以为只要递增就行。  
  - 边界条件：`k = 1` 时每个子数组本身就是递增，答案应全部是对应的元素（因为 `dp >= 1` 永远成立）。  
  - `dp` 的初始化要正确，第一位默认长度为 `1`。  
- **下次遇到同类题**：第一步先思考“能否把局部合法性压缩成一个累计值（如计数器、前缀和）”，再决定是否需要额外的数据结构（哈希表、单调队列等）。如果可以，只要维护这个累计值，就能把 `O(nk)` 降到 `O(n)`。
