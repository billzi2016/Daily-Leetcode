# #3095. **位或至少为 K 的最短子数组 I** / Shortest Subarray With OR at Least K I

> 难度：简单 · 标签：Array、Bit Manipulation、Sliding Window · [LeetCode 链接](https://leetcode.com/problems/shortest-subarray-with-or-at-least-k-i/)

## 题目（英文原版）

**Description**

You are given an array nums of non-negative integers and an integer k.
An array is called special if the bitwise OR of all of its elements is at least k.
Return the length of the shortest special non-empty subarray of nums, or return -1 if no special subarray exists.

**Examples**

**Example 1:**

```
Input: nums = [1,2,3], k = 2
Output: 1
Explanation:
The subarray [3] has OR value of 3 . Hence, we return 1 .
Note that [2] is also a special subarray.
```

**Example 2:**

```
Input: nums = [2,1,8], k = 10
Output: 3
Explanation:
The subarray [2,1,8] has OR value of 11 . Hence, we return 3 .
```

**Example 3:**

```
Input: nums = [1,2], k = 0
Output: 1
Explanation:
The subarray [1] has OR value of 1 . Hence, we return 1 .
```

**Constraints**

- 1 <= nums.length <= 50
- 0 <= nums[i] <= 50
- 0 <= k < 64

如果一个子数组（subarray）中所有元素的按位或（bitwise OR）值不少于 `k`，则称该子数组为 **特殊**（special）。

注意，子数组 `[2]` 也是特殊的。

**示例 2**  
输入：`nums = [2,1,8]`, `k = 10`  
输出：`3`  
解释：子数组 `[2,1,8]` 的按位或值为 `11`，满足 ≥ `k`，因此返回长度 `3`。

**示例 3**  
输入：`nums = [1,2]`, `k = 0`  
输出：`1`  
解释：子数组 `[1]` 的按位或值为 `1`，满足 ≥ `k`，因此返回长度 `1`。

**约束条件**  
- `1 <= nums.length <= 50`  
- `0 <= nums[i] <= 50`  
- `0 <= k < 64`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是把所有可能的「连续子数组」都枚举一遍，逐个计算它们的按位或（OR）值，看看有没有 ≥ k 的。如果有，就记录下它的长度，最后取最小的那一个。

- **枚举子数组**：把数组的左端点 `l` 从 `0` 到 `n‑1`，右端点 `r` 从 `l` 到 `n‑1`，每一对 `(l, r)` 就代表一个子数组 `nums[l…r]`。这就像在一排糖果里，挑选左手和右手的两个位置，中间的糖果全部拿走。
- **计算 OR**：把子数组里的每个数依次做 `|=`（按位或）操作。按位或就像「把所有出现过的 1 合并在一起」，只要某一位出现过一次，结果的那一位就会是 1。
- **判断是否满足**：如果得到的 OR ≥ k，就说明这是一个「特殊」子数组，更新最小长度。

> **为什么正确**  
> 我们遍历了 **所有** 可能的子数组，凡是满足条件的都会被检测到，自然不会漏掉最短的那个。

> **时间/空间复杂度**  
> - 外层循环 `l` 有 `n` 次，内层循环 `r` 最多也有 `n` 次，总共约 `n²/2` 次枚举。每次枚举里我们要遍历子数组内的元素求 OR，最坏情况下子数组长度也是 `n`，于是总体时间复杂度是 `O(n³)`。不过因为我们可以在枚举 `r` 时直接累加 OR（不必重新遍历），实际只需要 `O(n²)`。
> - 只用了常数个额外变量（当前 OR、最小长度），所以空间复杂度是 `O(1)`。

> **大白话解释**  
> - `O(n²)` 就是「如果数组有 1000 个元素，最坏要检查大约 1000 × 1000 = 1 000 000 次」，对机器来说还是可以接受的，尤其是本题 `n ≤ 50`。

#### 代码（Python）

```python
def shortest_subarray_bruteforce(nums, k):
    n = len(nums)
    best = float('inf')               # 用一个很大的数表示“目前还没有找到”

    # l 为子数组左端点
    for l in range(n):
        cur_or = 0                     # 从空窗口开始，OR 为 0
        # r 为子数组右端点，逐步向右扩展窗口
        for r in range(l, n):
            cur_or |= nums[r]          # 把 nums[r] 加进来，按位或一次
            if cur_or >= k:            # 已经满足要求
                best = min(best, r - l + 1)   # 更新最短长度
                break                  # 进一步右移只会让长度更长，直接退出内层循环

    return -1 if best == float('inf') else best
```

#### 复杂度

- **时间复杂度**：`O(n²)`  
  对每个左端点 `l`，我们最多遍历一次右端点 `r`，并且在遍历过程中只做一次按位或运算，整个过程是二重循环。

- **空间复杂度**：`O(1)`  
  只用了几个整数变量，和输入规模无关。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于「每次左端点移动后，都要重新计算窗口的 OR」。如果我们能在 **窗口滑动** 的过程中 **快速更新** OR，就能把时间降到线性级别。

**关键观察**：

1. **按位或的单调性**  
   - 把一个新元素加入窗口，只会让 OR 的某些位从 `0` 变成 `1`，不会把已经是 `1` 的位变回 `0`。这类似于「把更多的灯打开」。
2. **移出左端点的困难**  
   - 当我们把窗口左边的元素踢出时，某些位可能需要恢复为 `0`（如果窗口里再也没有该位为 `1` 的数）。直接用普通的 OR 运算是做不到的，因为 OR 只能“加”，不能“减”。

为了解决第二点，我们用 **位计数**（bit count）来记录窗口里每一位 `1` 出现的次数：

- 用一个长度为 64（因为 `k < 64`）的数组 `cnt[bit]`，`cnt[i]` 表示当前窗口里第 `i` 位为 `1` 的元素个数。
- 当我们 **加入** 一个数 `x` 时，遍历它的二进制位（最多 64 位），如果第 `i` 位是 `1`，就 `cnt[i] += 1`。
- 当我们 **移出** 一个数 `y` 时，同理把对应的计数减一。
- 窗口的 OR 值可以随时由 `cnt` 计算出来：只要 `cnt[i] > 0`，第 `i` 位就是 `1`，否则是 `0`。我们用一个整数 `cur_or` 来保存当前的 OR，更新时只需要检查被改动的位。

**滑动窗口的工作方式**：

1. 右指针 `right` 向右扩张，把 `nums[right]` 加入窗口并更新 `cnt`、`cur_or`。
2. 检查 `cur_or` 是否已经 ≥ k。如果是，就尝试把左指针 `left` 向右收缩——只要收缩后仍然满足 `cur_or ≥ k`，就继续收缩，这样可以得到当前 `right` 对应的最短子数组。
3. 每次收缩都要把 `nums[left]` 从窗口中移除并更新计数、`cur_or`，随后 `left += 1`。
4. 在收缩的过程中记录最小长度。

因为每个元素最多进入窗口一次、离开窗口一次，整个过程是 **线性** 的 `O(n)`，而每次更新计数只遍历该元素的二进制位（最多 64 位），常数很小。

> **类比**  
> 想象窗口是一间房间，里面挂着很多灯（每一位对应一盏灯）。加入新家具时，可能要打开几盏灯（计数加一）。搬走家具时，如果这盏灯再也没有其他家具需要它，就要关掉（计数减到 0）。只要房间里还有灯亮，就说明 OR 已经足够大。

#### 代码（Python）

```python
def shortest_subarray_opt(nums, k):
    n = len(nums)
    INF = n + 1                     # 不可能出现的最大长度
    ans = INF

    # cnt[i] 记录窗口里第 i 位为 1 的元素个数，i = 0~63
    cnt = [0] * 64
    cur_or = 0                      # 当前窗口的 OR 值
    left = 0

    # 遍历右端点
    for right in range(n):
        x = nums[right]

        # 把 x 加入窗口，更新位计数和 cur_or
        bit = 0
        while x:
            if x & 1:               # 第 bit 位是 1
                cnt[bit] += 1
                cur_or |= (1 << bit)    # 这位变成 1
            x >>= 1
            bit += 1

        # 当窗口满足条件时，尽量左移 left 缩小窗口
        while cur_or >= k and left <= right:
            ans = min(ans, right - left + 1)   # 记录最短长度

            # 准备把 nums[left] 移出窗口
            y = nums[left]
            bit = 0
            while y:
                if y & 1:
                    cnt[bit] -= 1
                    if cnt[bit] == 0:         # 这位在窗口里已经没有 1 了
                        cur_or &= ~(1 << bit) # 把第 bit 位清零
                y >>= 1
                bit += 1

            left += 1          # 左指针右移

    return -1 if ans == INF else ans
```

#### 复杂度

- **时间复杂度**：`O(n * B)`，其中 `B` 为整数的位数（本题 ≤ 64），等价于 `O(n)`。  
  每个元素只会进入窗口一次、离开一次，处理每个元素时只遍历它的二进制位，常数非常小。

- **空间复杂度**：`O(B)`，即 `O(1)`（只用了一个长度为 64 的计数数组），与输入规模无关。

> **对比**：暴力解是 `O(n²)`，最优解把「检查所有子数组」的工作压缩到了「每个元素只看两次」的线性时间。

## 心得

- **核心技巧**：**滑动窗口 + 位计数**。  
  - 滑动窗口负责在数组上维护一个「动态子数组」；  
  - 位计数让我们能够在窗口收缩时「撤销」按位或的影响。

- **适用的题型**  
  1. **最短/最长满足某种位运算条件的子数组**（如「按位与 ≥ k」）。  
  2. **需要在窗口内快速统计某些离散属性**（如「子数组中不同元素的个数」常用哈希表计数）。  
  3. **窗口内需要“增/减”可合并的值**（如「窗口内最大值」可以用单调队列维护）。

- **一句话总结**：  
  *当“加入”容易但“移除”困难时，用计数数组记录每个位出现的次数，就能在 O(1) 时间内撤销贡献，从而实现线性滑动窗口。*

## 反思

- **第一反应**：看到「最短子数组」+ 「按位或」立刻想到「枚举所有子数组」——因为 n 很小，暴力解很自然。
- **最容易踩的坑**  
  1. **位数不够**：`k` 可能大于 32，需要准备 64 位的计数数组；  
  2. **移除左端点时忘记清零对应位**，导致 `cur_or` 仍然保留已经被踢出的 1；  
  3. **k = 0** 的特殊情况：任何非空子数组都满足，答案应为 1（代码自然会得到）。
- **下次类似题**：  
  第一步先判断「加入」操作是否单调（只能增不减），如果是，就尝试用 **滑动窗口 + 计数/单调结构** 来实现 O(n)；否则只能回到枚举或 DP。
