# #3457. 吃披萨！ / Eat Pizzas!

> 难度：中等 · 标签：Array、Greedy、Sorting · [LeetCode 链接](https://leetcode.com/problems/eat-pizzas/)

## 题目（英文原版）

**Description**

You are given an integer array pizzas of size n, where pizzas[i] represents the weight of the ith pizza. Every day, you eat exactly 4 pizzas. Due to your incredible metabolism, when you eat pizzas of weights W, X, Y, and Z, where W <= X <= Y <= Z, you gain the weight of only 1 pizza!
Find the maximum total weight you can gain by eating all pizzas optimally.
Note: It is guaranteed that n is a multiple of 4, and each pizza can be eaten only once.

**Examples**

**Example 1:**

```
Input: pizzas = [1,2,3,4,5,6,7,8]
Output: 14
Explanation:
The total weight gained after eating all the pizzas is 8 + 6 = 14 .
```

**Example 2:**

```
Input: pizzas = [2,1,1,1,1,1,1,1]
Output: 3
Explanation:
The total weight gained after eating all the pizzas is 2 + 1 = 3.
```

**Constraints**

- 4 <= n == pizzas.length <= 2 * 105
- 1 <= pizzas[i] <= 105
- n is a multiple of 4.

## 题目（中文翻译）

你得到一个大小为 `n` 的整数数组（integer array）`pizzas`，其中 `pizzas[i]` 表示第 `i` 个披萨（pizza）的重量（weight）。每一天，你恰好吃掉 4 个披萨。由于你的新陈代谢极其惊人，当你吃重量为 `W、X、Y、Z` 且满足 `W ≤ X ≤ Y ≤ Z` 的四个披萨时，你只能获得其中 **1** 块披萨的重量！求在最优安排下吃完所有披萨所能获得的最大总重量。

**注意**：保证 `n` 为 4 的倍数，且每个披萨只能吃一次。

示例 1:
Input: pizzas = [1,2,3,4,5,6,7,8]
Output: 14
Explanation:
吃完所有披萨后获得的总重量为 8 + 6 = 14 。

示例 2:
Input: pizzas = [2,1,1,1,1,1,1,1]
Output: 3
Explanation:
吃完所有披萨后获得的总重量为 2 + 1 = 3 。

约束条件：
- 4 ≤ n == pizzas.length ≤ 2 * 10⁵
- 1 ≤ pizzas[i] ≤ 10⁵
- n 为 4 的倍数。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把所有披萨 **按照每天 4 块的方式全部分组**，枚举所有可能的分组方式，计算每一种分法得到的“增重”总和，取最大值。

- **数据结构**：我们可以把披萨的重量放进一个普通的列表（`list`），在递归过程中不断把已经选好的 4 块从列表里取走。  
  - 列表就像一本装有所有披萨的“清单”，取走 4 块相当于在清单上划掉这几行。

- **为什么正确**：遍历**所有**合法的分组（每块披萨只能出现一次），必然会碰到最优的那一种，所以最终取最大值一定是答案。

- **复杂度分析**：  
  - 对于 `n` 块披萨，每天要选 4 块，一共有 `n/4` 天。第一天有 `C(n,4)` 种选法，第二天剩下 `n-4` 块又有 `C(n-4,4)` 种，依此类推。  
  - 总的搜索空间是 `C(n,4) * C(n-4,4) * …`，这等价于 **n! / (4!^{n/4})**，随 `n` 指数级增长。  
  - 时间复杂度近似 **O(n!)**，即使 `n=12`（3 天）也需要几千次递归，`n=20` 就已经不可接受。  
  - 空间上递归栈最多保存 `n/4` 层，**O(n)**。

> **大白话**：`O(n!)` 就像把所有披萨排成一行后，尝试每一种可能的排列顺序再去分组——根本不可能在电脑上跑完。

#### 代码（Python）

```python
from itertools import combinations
from typing import List

def brute_gain(pizzas: List[int]) -> int:
    """
    暴力搜索所有可能的每日 4 块组合，返回最大增重总和。
    只适合 n 很小的情况（如 n <= 12），否则会超时。
    """
    n = len(pizzas)
    # 每天的增重只和当天四块的最大值或次大值有关，先写通用的求增重函数
    def day_gain(group):
        a, b, c, d = sorted(group)   # W <= X <= Y <= Z
        # 根据题意：奇数天取 Z，偶数天取 Y
        # 这里不区分奇偶，只返回两种可能的最大值，外层递归负责交替使用
        return d, c

    # 递归搜索
    def dfs(remaining, day, cur):
        # remaining: 还没吃的披萨列表
        # day: 当前是第几天（从 0 开始），用于判断奇偶
        # cur: 已经累计的增重
        if not remaining:          # 所有披萨都吃完了
            return cur
        best = 0
        # 任选 4 块作为今天的餐
        for combo in combinations(range(len(remaining)), 4):
            group = [remaining[i] for i in combo]
            # 计算今天可以得到的增重（奇偶决定取哪一个）
            gain = day_gain(group)[day % 2]   # 奇数天(day%2==0)取最大，偶数天取次大
            # 把这 4 块从列表中删掉，递归处理剩下的披萨
            next_remaining = [remaining[i] for i in range(len(remaining)) if i not in combo]
            best = max(best, dfs(next_remaining, day + 1, cur + gain))
        return best

    return dfs(pizzas, 0, 0)

# 示例（仅用于演示，实际调用请使用更高效的算法）
print(brute_gain([1,2,3,4,5,6,7,8]))   # 输出 14
```

> **代码要点**  
> - `combinations` 用来枚举“从剩余披萨里挑 4 块”的所有可能。  
> - `day_gain` 根据当天是奇数还是偶数返回对应的增重（最大或次大）。  
> - 递归 `dfs` 把已经吃掉的披萨从列表里剔除，继续往下搜索。

#### 复杂度

- **时间复杂度**：`O(n!)`（阶乘级），因为要遍历所有可能的分组方式。  
- **空间复杂度**：`O(n)`，递归栈最多保存 `n/4` 层，每层复制一个列表。

### 2. 最优解

#### 思路  

暴力解太慢的根本原因是**不停地在所有组合之间来回尝试**，而我们并不需要真的去枚举所有分组，只要找出一种 **最优的划分策略** 即可。

**观察 1：**  
每天吃 4 块披萨，增重只取 **最大值**（奇数天）或 **次大值**（偶数天）。其余三块根本不影响增重，只会影响后面的天数。

**观察 2（提示中已经给出）：**  
- **奇数天**：把「**最大的那块**」和「**最小的三块**」凑在一起，这样最大的那块一定会被计入增重，而最小的三块因为再也不会成为别天的「最大」或「次大」而被「牺牲」掉，最省空间。  
- **偶数天**：把「**最大的两块**」和「**最小的两块**」凑在一起，这样次大的那块（即第二大）会计入增重，而最小的两块同样不会再对后面的天产生贡献。

**为什么这样一定最优？**  
把「大」的披萨留到以后，只会让它们在后面的「奇数」或「偶数」天里被「次大」或「最小」的角色使用，导致本可以直接计入增重的机会被浪费。  
所以**每一天都应该让可计入增重的那块尽可能大**，而把「无用」的三块或两块挑成当前剩下的最小的，这样不会影响后面的「大」块的使用。

**从全局角度看**，如果把所有披萨从大到小排好序（降序），我们可以直接读出每一天该计入增重的重量：

| 排序后（降序） | 取值方式 | 解释 |
|---|---|---|
| 第 1 块（最大） | 奇数天的增重 → 直接计入 |
| 第 2 块 | 偶数天的增重 → 次大，计入 |
| 第 3 块 | 被「最小的三块」吃掉（奇数天） |
| 第 4 块 | 被「最小的三块」吃掉（奇数天） |
| 第 5 块 | 被「最小的两块」吃掉（偶数天） |
| 第 6 块 | 被「最小的两块」吃掉（偶数天） |
| 第 7 块 | ... 继续循环 |

可以看到 **每两块就会产生一次增重**，而这两块恰好是排好序后 **下标为偶数（0、2、4、…）** 的元素，且只需要取前 `n/2` 个元素（因为后半部分已经全部被「牺牲」了）。

**于是得到简洁的贪心公式**：

> **把披萨重量降序排列后，取前 `n/2` 个中的偶数下标（0‑based）之和，即为最大增重。**

这一步只需要一次排序和一次线性遍历，时间复杂度 `O(n log n)`，空间 `O(1)`（如果原地排序的话）。

#### 代码（Python）

```python
from typing import List

def max_gain(pizzas: List[int]) -> int:
    """
    贪心 + 排序：先把所有披萨按重量从大到小排好序，
    然后把前 n/2 个里下标为偶数（0、2、4、…）的重量相加，
    即为能够获得的最大增重。
    """
    # 1. 降序排列
    pizzas.sort(reverse=True)          # 大的在前面，类似把字典倒排

    # 2. 只遍历前一半，因为后半部分已经全部被“牺牲”
    half = len(pizzas) // 2

    total = 0
    # 3. 取偶数下标（0、2、4…）对应的披萨重量累加
    for i in range(0, half, 2):        # 步长为 2，直接跳过不计入增重的那块
        total += pizzas[i]             # 把这块计入增重

    return total

# ------------------- 示例 -------------------
print(max_gain([1,2,3,4,5,6,7,8]))          # 14
print(max_gain([2,1,1,1,1,1,1,1]))          # 3
```

> **代码要点**  
> - `pizzas.sort(reverse=True)`：把披萨从大到小排好，就像把字典倒着翻，最大页码在最前。  
> - `range(0, half, 2)`：只遍历 **前一半** 的 **偶数位置**，一步到位跳过“被牺牲”的那块。  
> - 整个过程只用了 **一次排序**（`O(n log n)`）和一次线性遍历（`O(n)`），空间几乎不额外开销。

#### 复杂度

- **时间复杂度**：`O(n log n)`  
  - `n log n` 来自排序。排序后只做一次 `O(n)` 的遍历，整体仍是 `O(n log n)`。  
  - 与暴力解的 `O(n!)` 相比，几乎是 **天壤之别**，即使 `n=2·10⁵` 也能在毫秒级完成。

- **空间复杂度**：`O(1)`（如果原地排序）或 `O(n)`（Python 的 Timsort 需要临时数组），但不随递归深度增长，远小于暴力解的 `O(n)` 递归栈。

## 心得

- **核心技巧**：**贪心 + 排序**  
  通过一次全局排序，把「每一天应当计入的最大/次大」转化为「固定位置的元素」，避免了枚举所有组合。

- **适用的题型**  
  1. 每次操作只取「最大/次大」等局部极值，且其余元素只起到“填充”作用（如 “Maximum Sum of Selected Numbers”）。  
  2. 把「若干最值」固定下来后，剩余元素的顺序不影响答案的场景（如 “Pick Two Numbers from Each Pair” 类问题）。  
  3. 类似的「每 k 个取 1 个」的贪心题，例如 “Maximum Sum of Subsequence With Gap” 等。

- **一句话总结解题钥匙**：  
  **把所有重量先排好序，奇数天取最大、偶数天取次大 → 等价于把前一半的偶数下标元素相加**。

## 反思

- **第一反应**：看到「每天吃 4 块，增重只取 1 块」就想到「把所有可能的分组全部尝试」——即暴力搜索。  
- **最容易踩的坑**  
  1. **误把次大当作最大**：在偶数天要取次大，而不是最大，否则会低估答案。  
  2. **忽略“牺牲”块的选择**：必须把最小的块放进当日的组合，否则可能让后面的“大块”被错误地“牺牲”。  
  3. **边界条件**：`n` 必须是 4 的倍数，若不检查直接 `n/2` 可能导致数组越界。  

- **下次遇到同类题**，第一步应该：  
  **先排序**，观察「每一步只关心局部极值」的模式，尝试用**固定位置**来直接得到答案，而不是枚举组合。这样往往能迅速发现贪心或滑动窗口等线性/对数时间的解法。
