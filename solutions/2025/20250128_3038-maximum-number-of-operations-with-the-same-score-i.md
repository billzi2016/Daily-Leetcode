## 题目（中文翻译）

给定一个整数数组 `nums`。考虑以下 **操作**（operation）：

- 选取数组中的任意两个元素，使它们的 **得分**（score）相同，然后将这两个元素从数组中移除。  
- 只要数组中仍然至少有两个元素且每次操作的得分保持相同，就可以继续执行上述操作。

返回在满足上述条件的前提下，你最多可以执行的 **操作**（operation）次数。

**示例 1**

```text
Input: nums = [3,2,1,4,5]
Output: 2
Explanation:
可以先选择 1 与 4，得分为 5；随后选择 2 与 3，得分同样为 5。此时数组只剩下 [5]，无法再进行操作。
```

**示例 2**

```text
Input: nums = [1,5,3,3,4,1,3,2,2,3]
Output: 2
Explanation:
一种可行的做法是先取 (1,4) 得分 5，再取 (2,3) 得分 5，随后数组中剩余的元素无法再配对成相同得分。
```

**示例 3**

```text
Input: nums = [5,3]
Output: 1
Explanation:
唯一的配对是 (5,3)，得分为 8，完成一次操作后数组为空。
```

**约束条件**

- `2 <= nums.length <= 100`
- `1 <= nums[i] <= 1000`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**把所有可能的两两组合枚举出来，看看哪一种组合的和（score）出现的次数最多**。  
可以把数组想象成一堆彩色球，每个球上写着一个数字。一次操作就是把两颗球挑出来，把它们的数字相加得到一个分数。题目要求所有操作的分数必须相同，也就是说我们必须挑选出一种“颜色配对方式”，让每一对球的和都相等，并且能挑出最多的对。

实现方式：

1. 用两层循环遍历数组中的每一对下标 `(i, j)`（`i < j`），计算它们的和 `s = nums[i] + nums[j]`。  
2. 把每个和 `s` 出现的次数记在一个哈希表（`dict`）里，哈希表就像一本“查字典”，键（key）是和 `s`，值（value）是出现的次数。  
3. 最后答案就是哈希表中最大值（即出现次数最多的和对应的操作次数）。

> **为什么正确？**  
> 每一次操作只会产生一个和 `s`，所以只要把所有可能的两数之和统计出来，出现次数最多的那个和就能对应到最多的操作次数（因为我们可以把这些出现的配对全部取走）。

> **时间/空间复杂度**  
> - **时间**：两层循环遍历所有 `n` 个数的两两组合，组合数是 `C(n,2) = n·(n-1)/2`，用大白话说就是 **大约 n²/2 次**，所以时间复杂度记作 **O(n²)**。  
> - **空间**：我们只需要保存每一种和出现的次数，和的取值范围最多是 `2 … 2000`（因为 `1 ≤ nums[i] ≤ 1000`），所以最多存 1999 条记录，记作 **O(1)**（常数空间）。

#### 代码（Python）

```python
from collections import defaultdict
from typing import List

def maxOperations_bruteforce(nums: List[int]) -> int:
    # 用 defaultdict 当“查字典”，key 是两数之和，value 是出现次数
    sum_cnt = defaultdict(int)

    n = len(nums)
    # 两层循环枚举所有 i < j 的组合
    for i in range(n):
        for j in range(i + 1, n):
            s = nums[i] + nums[j]          # 计算这对数的和
            sum_cnt[s] += 1                # 记录一次出现

    # 哈希表里最大的出现次数，就是最多的操作数
    return max(sum_cnt.values())
```

#### 复杂度

- **时间复杂度**：`O(n²)` —— 这里的 `n²` 可以理解为“如果数组有 100 个数，程序大概要跑 10,000 次循环”。  
- **空间复杂度**：`O(1)` —— 只用几千个整数来记和的次数，和数组大小无关。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **每一次都要枚举所有两两组合**，这会导致 `n²` 的循环。  
实际上我们不需要知道每一对具体是哪两个元素，只需要知道 **每个数字出现了多少次**，再根据目标和 `s` 计算能配对出多少对即可。

**关键观察**：

- 设目标和为 `s`，如果我们拿走一个值为 `x` 的元素，必须再找一个值为 `s - x` 的元素才能凑成 `s`。  
- 对于每一种数值 `x`，可以和 `s - x` 配对的次数是 `min(cnt[x], cnt[s-x])`（把出现次数较少的那一方全部配对掉）。  
- 当 `x = s - x`（即 `2*x = s`）时，两个相同的数配对，需要把该数的出现次数除以 2，得到 `cnt[x] // 2` 对。  

于是我们可以：

1. 先统计每个数字的出现次数 `cnt`（哈希表或数组，数字范围只有 1~1000）。这一步是 **O(n)**。  
2. 枚举所有可能的目标和 `s`（从 `2` 到 `2000`），对每个 `s` 计算能够形成多少对：
   - 对所有 `x` 从 `1` 到 `s//2`（只需要遍历到一半，避免重复计数），累加 `min(cnt[x], cnt[s-x])`。  
   - 若 `s` 为偶数，还要额外加上 `cnt[s//2] // 2`（因为此时 `x = s-x`）。  
3. 记录所有 `s` 中得到的最大对数，即为答案。

**为什么快？**  
- 统计次数只遍历一次数组 `O(n)`。  
- 目标和的取值范围是固定的（最多 1999），每个和内部遍历的数值也最多 1000，整体是 **常数级别的循环**（约 2 × 10⁶ 次操作），与 `n` 的大小无关。  
- 所以整体时间是 **O(n + V²)**，其中 `V = 1000` 为数值上限，等价于 **O(n)**（因为 `V²` 是常数）。

#### 代码（Python）

```python
from collections import Counter
from typing import List

def maxOperations(nums: List[int]) -> int:
    # 1️⃣ 统计每个数字出现了多少次，像一本“出现次数字典”
    cnt = Counter(nums)          # 例如 cnt[3] = 2 表示数字 3 出现了两次

    max_ops = 0                   # 用来记录能够得到的最大操作数

    # 2️⃣ 枚举所有可能的目标和 s（最小 2，最大 2000）
    for s in range(2, 2001):
        ops = 0                   # 当前目标和 s 能形成的对数

        # 只遍历到 s//2，防止把同一对算两次
        for x in range(1, s // 2 + 1):
            y = s - x             # 与 x 配对的另一个数
            if y not in cnt:      # 如果 y 从未出现，直接跳过
                continue
            # 对于不同的 x 与 y，能配对的次数是两者出现次数的较小值
            ops += min(cnt[x], cnt[y])

        # 当 s 为偶数时，x == y 的情况需要单独处理
        if s % 2 == 0:
            mid = s // 2
            # 两个相同的数配对，需要把出现次数除以 2（向下取整）
            ops += cnt[mid] // 2

        # 更新全局最大值
        max_ops = max(max_ops, ops)

    return max_ops
```

#### 复杂度

- **时间复杂度**：`O(n + V²)` → 实际上是 `O(n)`，因为 `V = 1000` 是常数。可以理解为“即使数组有 10⁵ 个元素，程序也只会跑大约几百万次循环”。  
- **空间复杂度**：`O(V)` → 只需要存每个数值的出现次数，最多 1000 条记录，属于常数空间。

## 心得

- **核心技巧**：利用**计数 + 枚举目标和**的思路，把“挑配对”转化为“统计每种数出现多少次”，再用 `min(cnt[x], cnt[s-x])` 计算可配对数。  
- **适用的题型**：  
  1. “最大相同和的配对数” 类似题（如 *Maximum Number of Operations With the Same Score II*）。  
  2. “两数之和出现次数最多” 的变体。  
  3. 需要 **相同分数/相同和** 的配对问题（如 “数组分割成相同和的子集”）。  
- **一句话总结**：先把元素出现次数记下来，枚举所有可能的目标和，用最小出现次数来配对，就能一次算出最大操作数。

## 反思

- **第一反应**：看到“相同分数的操作”，立刻想到“枚举所有两数之和”。这导致了最直接的 `O(n²)` 暴力实现。  
- **最容易踩的坑**：  
  - **重复计数**：遍历 `x` 时若不限制到 `s//2`，会把同一对 `(x, y)` 与 `(y, x)` 计两次。  
  - **偶数和的特殊情况**：当 `s` 为偶数时，`x = y` 需要单独用 `cnt[x] // 2` 处理，否则会把同一个元素配对多次。  
  - **边界**：`nums` 长度最小为 2，确保至少有一次操作；但若所有数都相同，仍要正确计算 `cnt[mid] // 2`。  
- **下次遇到同类题的第一步**：**先统计每个数出现多少次**，再在“目标属性”（这里是和）上做枚举，这样往往能把 `n²` 的搜索压缩到常数级别。
