## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把原数组 `nums` 按照「奇数在后、偶数在前」的顺序重新排好。  
可以把每个数的奇偶性当成「标签」：  
- 偶数 → 记作 `0`  
- 奇数 → 记作 `1`  

于是只要遍历一遍 `nums`，把对应的 `0` 或 `1` 放进结果数组即可。  
这一步和「查字典」类似——我们看到一个数，就立刻把它对应的「0/1」写下来。

> 为什么这样一定对？因为题目只要求 **返回** 一个只包含 `0`（偶数个数）和 `1`（奇数个数）的数组，顺序固定：所有 `0` 在前，所有 `1` 在后。只要统计出每个数是偶是奇，就能准确构造出答案。

#### 代码（Python）

```python
def transformArray(nums):
    # 结果数组，先放偶数对应的 0，后放奇数对应的 1
    res = []
    for v in nums:                 # 遍历原数组，每个元素一次
        if v % 2 == 0:             # v % 2 == 0 表示 v 是偶数
            res.append(0)          # 偶数对应 0，放进结果
        else:
            res.append(1)          # 奇数对应 1，放进结果
    # 这里得到的 res 已经是「原顺序」的 0/1，题目要求的是所有 0 在前、1 在后
    # 所以再把它们按照值排序即可（0 会排到前面，1 会排到后面）
    res.sort()                     # O(n log n) 的排序
    return res
```

#### 复杂度

- **时间复杂度**：`O(n log n)`  
  - `n` 是数组长度。遍历一次是 `O(n)`，随后的 `sort` 需要 `O(n log n)`，这就是「log」的含义：每次把数据分成两半再合并，整体比线性稍慢。
- **空间复杂度**：`O(n)`  
  - 需要额外的数组 `res` 来存放 `n` 个 `0/1`，以及排序时 Python 内部可能再申请临时空间。

### 2. 最优解

#### 思路  

从暴力解可以看到，**排序其实是多余的**。我们只需要知道数组里有多少偶数、多少奇数，然后直接把对应数量的 `0` 与 `1` 按顺序写进去。  

**瓶颈**在于 `sort`，它把 `O(n log n)` 的时间浪费在了本不需要的比较上。  

**优化思路**：

1. **一次遍历**统计偶数和奇数的个数  
   - 用两个计数器 `even_cnt`、`odd_cnt`，每看到一个元素就判断奇偶并加 1。  
   - 这一步是线性的，只需要 `O(n)` 时间。

2. **构造结果**  
   - 先把 `even_cnt` 个 `0` 放进结果列表，再放 `odd_cnt` 个 `1`。  
   - Python 的列表乘法 ` [0] * even_cnt` 可以一次性生成多个相同元素，十分简洁。

**核心概念**：**计数**（Counting）。把「有多少」这件事提前算好，就不需要后面再做排序或额外的判断。可以把它想象成「先点数，再排队」——先知道有几个人想坐前排，几个人想坐后排，直接把他们安排好，而不是让每个人自己去找座位。

#### 代码（Python）

```python
def transformArray(nums):
    # 第一步：统计偶数和奇数的个数
    even_cnt = 0      # 偶数的数量
    odd_cnt = 0       # 奇数的数量
    for v in nums:   # 只遍历一次
        if v % 2 == 0:
            even_cnt += 1   # 偶数计数加一
        else:
            odd_cnt += 1    # 奇数计数加一

    # 第二步：直接生成结果数组
    # [0] * even_cnt 会生成一个长度为 even_cnt、全是 0 的列表
    # 同理 [1] * odd_cnt 生成全是 1 的列表
    result = [0] * even_cnt + [1] * odd_cnt
    return result
```

#### 复杂度

- **时间复杂度**：`O(n)`  
  - 只需要一次遍历来计数，`n` 是数组长度。相比 `O(n log n)` 的排序，这里「log」不再出现，执行更快。

- **空间复杂度**：`O(n)`  
  - 仍然需要存放最终答案的数组，长度恰好是 `n`。除了答案本身，没有额外的中间结构。

## 心得

- **核心技巧**：**一次遍历计数 + 列表乘法构造**  
  通过先统计出现次数，再一次性生成对应数量的元素，省掉了排序等不必要的操作。

- **适用题型**  
  1. “统计出现次数后直接输出”类题目，例如 `Sort the Array by Parity`、`Replace Elements with Greatest Element on Right Side`（先统计后填）  
  2. “把数组按照某种属性分块”类题目，如 “将数组分为奇数在前、偶数在后”  
  3. “只需要输出某种标记（0/1、true/false）而不是原始数值”类题目，例如 “Count Good Numbers”  

- **一句话总结**：**先计数，再一次性生成** 是这类 “只关心类别数量” 题目的解题钥匙。

## 反思

- **第一反应**：看到“把偶数变成 0，奇数变成 1，0 在前，1 在后”，本能地想用 `sort` 把 `0/1` 排序。  
- **最容易踩的坑**  
  - **不必要的排序**：会导致 `O(n log n)`，在大数据量时会慢。  
  - **忘记返回结果**：只打印或在循环里直接 `print`，而不是返回列表。  
  - **边界情况**：数组全是偶数或全是奇数时，计数要能得到 `0`，生成的列表仍然合法（比如 `[0]*0` 会得到空列表，拼接后仍然对）。  

- **下次遇到同类题**，第一步应该想到 **“先统计每类的数量”**，然后 **“直接构造结果”**，而不是先做排序或额外的遍历。这样既简洁又高效。
