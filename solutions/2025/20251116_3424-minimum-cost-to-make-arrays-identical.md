# #3424. 使数组相同的最小代价 / Minimum Cost to Make Arrays Identical

> 难度：中等 · 标签：Array、Greedy、Sorting · [LeetCode 链接](https://leetcode.com/problems/minimum-cost-to-make-arrays-identical/)

## 题目（英文原版）

**Description**

You are given two integer arrays arr and brr of length n, and an integer k. You can perform the following operations on arr any number of times:
Return the minimum total cost to make arr equal to brr.

**Examples**

**Example 1:**

```
Input: arr = [-7,9,5], brr = [7,-2,-5], k = 2
Output: 13
Explanation:
The total cost to make the arrays equal is 2 + 2 + 7 + 2 = 13 .
```

**Example 2:**

```
Input: arr = [2,1], brr = [2,1], k = 0
Output: 0
Explanation:
Since the arrays are already equal, no operations are needed, and the total cost is 0.
```

**Constraints**

- 1 <= arr.length == brr.length <= 105
- 0 <= k <= 2 * 1010
- -105 <= arr[i] <= 105
- -105 <= brr[i] <= 105

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**不使用任何“子数组重新排列”**的操作，只把 `arr` 的每个位置上的数直接改成 `brr` 对应位置的数。  
- 这相当于把每个格子里的数字 **单独** 调整到目标值。  
- 调整的代价是每改动一次（+1 或 -1）需要付 **1 元**，所以把 `arr[i]` 变成 `brr[i]` 需要的费用就是 `|arr[i] - brr[i]|`（绝对值），因为我们要走的步数就是两数之间的距离。  

如果不使用“子数组重新排列”，整个数组的最小费用就是所有位置费用的累加：

```
cost = Σ |arr[i] - brr[i]|   (i 从 0 到 n-1)
```

**为什么这个方法一定能得到一个合法的答案？**  
因为我们直接把每个位置的数字改成目标值，显然最后 `arr` 与 `brr` 完全相同，满足题目要求。只是不一定最省钱，因为我们没有利用可以自由调换子数组的机会。

**时间/空间分析（大白话版）**  
- 我们要遍历一次数组，算每一对数的差的绝对值，**一次遍历**就是 `O(n)`（线性时间），这在日常生活里相当于“看一遍所有商品的价格”。  
- 只用了几个整数变量来累计答案，**不需要额外的存储**，空间复杂度是 `O(1)`（常数级），就像只带了一只小钱包。

> **注意**：虽然这已经是线性的，但在本题中它并不是最优解，因为我们还有**子数组重新排列**这一步可以让费用更低。

#### 代码（Python）

```python
def min_cost_bruteforce(arr: list[int], brr: list[int]) -> int:
    """
    暴力思路：不使用子数组重新排列，直接把每个位置的数改成目标数。
    """
    total = 0                         # 用来累计总费用
    for a, b in zip(arr, brr):        # 同时遍历两个数组的对应元素
        total += abs(a - b)           # 费用 = 两数差的绝对值
    return total
```

#### 复杂度  

- **时间复杂度**：`O(n)` —— 只遍历一次数组，n 是数组长度。  
- **空间复杂度**：`O(1)` —— 只使用常数个额外变量。

### 2. 最优解  

#### 思路  

从暴力解可以看到，费用的根源是 **每一对数字之间的距离**。  
如果我们能够 **把 `arr` 中的数字重新排列**，让它们与 `brr` 中的数字“配对得更好”，则每对之间的距离会更小，整体费用自然下降。  

**瓶颈在哪里？**  
- 暴力解把 `arr[i]` 固定在原来的位置，只能与 `brr[i]` 配对。  
- 实际上，题目允许我们对 `arr` 进行 **子数组重新排列**（可以把 `arr` 的任意元素调到任意位置），相当于我们可以 **自由地为 `arr` 选一个排列**。

**关键观察**  
把两个数列分别 **从小到大排好序**，然后一一对应（最小的配最小的、次小的配次小的……），可以得到 **最小的绝对差之和**。  

> **类比**：想象有两排学生站成两行，老师要把第一排的学生和第二排的学生配对做实验，实验的“痛苦值”是两人身高差的绝对值。要让总体痛苦最小，最自然的做法就是把身高相近的学生配在一起——这正是“排序后逐位配对”。  

**为什么排序后配对是最优的？**  
- 绝对值函数是 **凸函数**，在数学上可以用 **交换论证**（exchange argument）证明：如果出现 `a ≤ b`、`c ≤ d`，但我们把 `a` 配 `d`、`b` 配 `c`，则  
  `|a-d| + |b-c| ≥ |a-c| + |b-d|`。  
- 也就是说，把较小的数配给较小的目标，永远不会比把它们交叉配对花更多代价。  
- 通过不断交换交叉的配对，最终可以把所有配对整理成“从小到大对应”，费用只会 **不增**，于是这一定是最小的。

**步骤**  

1. 把 `arr` 排序得到 `arr_sorted`。  
2. 把 `brr` 排序得到 `brr_sorted`。  
3. 逐位计算 `|arr_sorted[i] - brr_sorted[i]|` 并累加，即为答案。  

**复杂度分析（用通俗语言）**  
- 排序需要 “把所有东西从小到大排好”，这在电脑里一般是 **快速排序/归并排序**，时间是 `O(n log n)`，相当于“先把书按字母顺序排好”。  
- 排序后再一次遍历，两数相减取绝对值，时间是 `O(n)`，这一步就像“把排好序的两列学生逐一配对”。  
- 总时间 = `O(n log n) + O(n)` ≈ `O(n log n)`。  
- 额外的空间只需要存放排好序的两个数组，若原地排序可以把空间降到 `O(1)`（这里为了代码简洁使用 `O(n)` 的临时列表）。

#### 代码（Python）

```python
def min_cost_optimal(arr: list[int], brr: list[int]) -> int:
    """
    最优思路：先把两个数组各自排序，再逐位配对求绝对差之和。
    """
    # 1. 对两个数组各自排序（不改变原数组的话可以拷贝后再排序）
    arr_sorted = sorted(arr)          # O(n log n)
    brr_sorted = sorted(brr)          # O(n log n)

    # 2. 逐位计算差的绝对值并累计
    total = 0
    for a, b in zip(arr_sorted, brr_sorted):
        total += abs(a - b)            # 每对配对的费用

    return total
```

#### 复杂度  

- **时间复杂度**：`O(n log n)` —— 两次排序是主要耗时。  
- **空间复杂度**：`O(n)`（若使用原地排序可降为 `O(1)`）——需要存放排序后的数组。

## 心得  

- **核心技巧**：**排序后逐位配对**（即“最小-最小、次小-次小 …”）能够在允许自由排列的情况下，最小化绝对差之和。  
- **适用场景**：  
  1. “最小化两组数对应差的总和” 类题，如 **两个数组的最小匹配成本**。  
  2. “让两组数的对应关系最优” 的贪心/排序问题，例如 **使两个序列的欧氏距离最小**（对应到一维即绝对差）。  
  3. 需要 **配对** 的资源分配问题，如 **任务与机器的最小总完成时间**（在一维成本下同理）。  
- **一句话总结**：**把可以自由调换的数组先排好序，再一一对应，费用自然最小**。

---

## 反思  

- **第一反应**：直接把每个位置的数改成目标数，算每对的绝对差——这是一种最保守的“逐点修改”思路。  
- **最容易踩的坑**：  
  - 忘记题目允许 **任意重新排列**（即可以把元素放到任意位置），从而错失排序配对的机会。  
  - 在实现时误把 `abs(arr[i] - brr[i])` 用在未排序的数组上，导致答案偏大。  
  - 没有考虑 **负数** 的情况，直接使用 `abs` 可以避免符号带来的错误。  
- **下次类似题的第一步**：先思考“是否可以把元素自由移动”。如果可以，**先排序**，因为排序往往是最小化配对成本的关键一步。
