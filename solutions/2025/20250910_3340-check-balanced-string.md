## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**把所有字符一个个遍历一遍**，把下标为偶数的数字相加，另外把下标为奇数的数字相加，最后比较两个和是否相等即可。

- **数据结构**：只需要两个整数变量 `even_sum`、`odd_sum` 来累计和。这里不需要任何高级结构，类似于我们在超市把奇数号货架的商品价钱加在一起，偶数号货架的商品价钱也加在一起，最后看两个小票的总额是否相同。
- **正确性**：因为题目要求“所有偶数下标的数字之和”等于“所有奇数下标的数字之和”。我们遍历一次就把每个数字恰好加到了对应的累计和里，遍历结束后比较两者，恰好对应题意。
- **时间/空间复杂度**：  
  - 时间：我们要看一次字符串的每个字符，字符数记为 `n`，所以是 **O(n)**。这里的 `O(n)` 可以理解为“随着字符串长度的增加，工作量线性增长”，比如 10 个字符要检查 10 次，100 个字符要检查 100 次。  
  - 空间：只用了常数个额外变量 (`even_sum`, `odd_sum`)，不随 `n` 增长，故是 **O(1)**，即“占用的内存几乎不变”。

#### 代码（Python）

```python
def balancedString(num: str) -> bool:
    """
    判断字符串 num 是否 balanced。
    偶数下标的数字之和 == 奇数下标的数字之和
    """
    even_sum = 0   # 偶数下标的累计和
    odd_sum = 0    # 奇数下标的累计和

    for idx, ch in enumerate(num):        # enumerate 同时得到下标和字符
        digit = int(ch)                    # 把字符转成对应的整数
        if idx % 2 == 0:                   # idx % 2 == 0 表示偶数下标
            even_sum += digit
        else:                              # 否则是奇数下标
            odd_sum += digit

    # 最后比较两个和是否相等
    return even_sum == odd_sum
```

#### 复杂度

- **时间复杂度**：O(n) — 随着字符串长度 `n` 增长，循环次数线性增加。
- **空间复杂度**：O(1) — 只用了固定的几个整数变量。

### 2. 最优解

#### 思路  

其实上面的暴力解已经是 **最优** 的，因为我们只能看到每个字符一次，才能把它归类到偶数或奇数下标中。  
唯一可以再“优化”的地方是**代码层面的简化**，例如利用 Python 的切片一次性取出所有偶数位或奇数位，再用 `sum` 直接求和。切片本身也会遍历一次字符，但底层实现同样是 O(n)，只是不显式写循环。

- **慢在哪里？**  
  暴力解的唯一瓶颈是遍历一次字符串，这一步是必须的，无法跳过，因为每个字符都可能影响最终的和。
- **一步步推导**  
  1. 把字符串按下标奇偶分成两组。Python 切片语法 `num[::2]` 可以直接取出所有偶数下标的字符，`num[1::2]` 取奇数下标。  
  2. 对每组字符使用 `map(int, …)` 把字符转成整数，再用 `sum` 累加。  
  3. 比较两组和是否相等。

- **核心技巧**：**切片 + 内置函数**。切片像是把一本书的奇数页和偶数页分别撕下来，`sum` 就是把这些页码相加。

#### 代码（Python）

```python
def balancedString(num: str) -> bool:
    """
    使用切片一次性取出奇偶下标的数字并求和。
    """
    # 取出偶数下标的字符（0、2、4...），并转成整数求和
    even_sum = sum(map(int, num[::2]))
    # 取出奇数下标的字符（1、3、5...），并转成整数求和
    odd_sum = sum(map(int, num[1::2]))
    return even_sum == odd_sum
```

#### 复杂度

- **时间复杂度**：O(n) — 仍然需要遍历全部字符一次，只是交给了 Python 的内部实现。相比手写循环，实际运行速度差别不大，但代码更简洁。
- **空间复杂度**：O(1)（严格来说是 O(k)，k 为切片产生的临时列表长度，但因为切片在 CPython 中会生成新字符串，空间仍然与输入长度同阶），在面试里通常仍写 O(1) 因为我们没有额外的“可变”数据结构，只是临时的只读视图。

## 心得

- **核心技巧**：利用下标的奇偶性分组求和（切片或遍历），是判断“平衡”类问题的通用方法。
- **适用的题型**  
  1. 判断数组/字符串奇偶位和是否相等（如 LeetCode 2420 – Find Array...）。  
  2. “交替求和”或“交替乘积”类题目（如 LeetCode 1669 – Merge In Between Linked Lists 中的交替合并思路）。  
  3. 需要把序列分成两组并分别统计的题目（如奇数位与偶数位字符出现次数的比较）。
- **一句话总结解题钥匙**：**“把问题拆成两组（奇/偶），分别统计后比较”。**

## 反思

- **第一反应**：直接遍历一遍，累加奇偶下标的数字——这几乎是所有人看到 “balanced” 关键字时的直觉。
- **最容易踩的坑**  
  - **下标从 0 开始**：记得 0 是偶数，下标 1 才是奇数，容易写反导致判断错误。  
  - **字符转整数**：直接相加字符会得到字符串拼接，需要 `int(ch)`。  
  - **空字符串或长度为 1 的情况**：虽然约束最小长度为 2，但如果忘记检查，代码仍能正常返回 `False`（因为两边和不相等），但要注意不要出现索引越界。
- **下次第一步**：先**明确分组依据**（本题是奇偶下标），然后决定是**遍历累加**还是**利用切片/内置函数**一次性求和。这样可以快速定位最简实现。
