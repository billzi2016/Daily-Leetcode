# #3290. 最大乘法得分 / Maximum Multiplication Score

> 难度：中等 · 标签：Array、Dynamic Programming · [LeetCode 链接](https://leetcode.com/problems/maximum-multiplication-score/)

---

## 题目（英文原版）

**Description**

You are given an integer array a of size 4 and another integer array b of size at least 4.
You need to choose 4 indices i0, i1, i2, and i3 from the array b such that i0 < i1 < i2 < i3. Your score will be equal to the value a[0] * b[i0] + a[1] * b[i1] + a[2] * b[i2] + a[3] * b[i3].
Return the maximum score you can achieve.

**Examples**

**Example 1:**

```
Input: a = [3,2,5,6], b = [2,-6,4,-5,-3,2,-7]
Output: 26
Explanation: We can choose the indices 0, 1, 2, and 5. The score will be 3 * 2 + 2 * (-6) + 5 * 4 + 6 * 2 = 26 .
```

**Example 2:**

```
Input: a = [-1,4,5,-2], b = [-5,-1,-3,-2,-4]
Output: -1
Explanation: We can choose the indices 0, 1, 3, and 4. The score will be (-1) * (-5) + 4 * (-1) + 5 * (-2) + (-2) * (-4) = -1 .
```

**Constraints**

- a.length == 4
- 4 <= b.length <= 105
- -105 <= a[i], b[i] <= 105

## 题目（中文翻译）

你得到一个长度为 4 的整数数组 `a`，以及另一个长度至少为 4 的整数数组 `b`。  
需要从数组 `b` 中选择 4 个下标 `i0, i1, i2, i3`，满足 `i0 < i1 < i2 < i3`。你的得分定义为

```
a[0] * b[i0] + a[1] * b[i1] + a[2] * b[i2] + a[3] * b[i3]
```

返回能够获得的最大得分。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是把 **所有** 满足 `i0 < i1 < i2 < i3` 的下标组合都枚举一遍，算出对应的分数，取最大的那个。

- **使用的数据结构**：  
  - `for` 循环嵌套四层，像是把 `b` 数组里每一个位置都当成“选不选”的开关。  
  - 这里不需要额外的结构，直接用整数变量保存当前的分数即可。  

- **为什么能得到正确答案**：  
  - 题目要求的约束是“必须选四个且顺序严格递增”。遍历 **所有** 满足这个约束的四元组，自然不会遗漏，也不会产生非法组合，所以最大值一定会被找出来。

- **时间/空间复杂度**：  
  - `b` 的长度记作 `n`。四层循环的时间复杂度是 `O(n³·n) = O(n⁴)`。  
    - “`O(n⁴)`” 的含义可以理解为：如果 `b` 长度是 10，最多要检查 `10⁴ = 10,000` 种可能；如果是 100，则是 `100⁴ = 100,000,000`，很快就会超时。  
  - 只用了常数个额外变量，空间复杂度是 `O(1)`（常数级）。

#### 代码（Python）

```python
from typing import List
import math

def maxScore_bruteforce(a: List[int], b: List[int]) -> int:
    n = len(b)
    best = -math.inf                     # 记录目前找到的最大分数
    # 四层循环枚举所有递增的下标组合
    for i0 in range(n - 3):
        for i1 in range(i0 + 1, n - 2):
            for i2 in range(i1 + 1, n - 1):
                for i3 in range(i2 + 1, n):
                    # 计算当前组合的得分
                    score = (a[0] * b[i0] +
                             a[1] * b[i1] +
                             a[2] * b[i2] +
                             a[3] * b[i3])
                    # 更新最大值
                    if score > best:
                        best = score
    return best
```

#### 复杂度

- **时间复杂度**：`O(n⁴)` — 需要遍历 `b` 中的所有四元组，随 `n` 的四次方增长。  
- **空间复杂度**：`O(1)` — 只用了几个临时整数变量。

### 2. 最优解

#### 思路  

从暴力解可以看出，**“枚举所有组合”** 是慢的根源：我们在每一次循环里都在重复计算已经算过的子问题。  
观察公式：

```
score = a[0]*b[i0] + a[1]*b[i1] + a[2]*b[i2] + a[3]*b[i3]
```

如果我们已经决定了前 `k`（`0 ≤ k ≤ 3`）个下标，并且已经得到最大的部分分数，那么在处理第 `k+1` 个下标时，只需要在后面的 `b` 中挑一个位置继续乘以 `a[k]` 加上已有的最大分数即可。

这正好符合 **动态规划（Dynamic Programming）** 的思路：把大问题拆成若干**状态**，每个状态只和前一个状态有关。

**状态定义**  
- `dp[k]` 表示：遍历到当前 `b` 元素（包括它）时，**已经选了 `k` 个下标**（`k` 从 `0` 到 `4`）能够得到的最大分数。  
  - `dp[0] = 0`（什么都不选，分数为 0）  
  - 其余 `dp[k]` 初始为负无穷，因为还没有合法的选法。

**转移**  
遍历 `b` 中的每个数 `val = b[i]`，我们可以选择把它作为第 `k`（从 0 开始计数）的下标。  
如果之前已经选了 `k` 个下标得到 `dp[k]`，现在选第 `k` 个（对应 `a[k]`）得到的新分数是：

```
new_score = dp[k] + a[k] * val
```

我们把这个新分数和当前 `dp[k+1]` 比较，取较大者。  
注意必须**倒序**更新 `k`（从 3 → 0），否则会把同一个 `val` 用多次，破坏“下标严格递增”的约束。

**为什么正确**  
- 每一次遍历 `b[i]` 时，只考虑把它作为**下一个**要选的下标。所有已经选好的下标必然在它左边（因为我们是从左到右顺序遍历的），所以顺序约束自动满足。  
- `dp[k]` 保存的是**在左侧所有位置**能够得到的最大分数，保证了最优子结构：把局部最优（前 `k` 项）扩展到 `k+1` 项仍然是全局最优。

**类比**  
把 `dp` 想成一本“成绩册”，每翻到一本新页（遍历一个 `b[i]`），我们把这页的分数加入到已有的成绩里，看看能不能把总成绩写得更高。

**时间/空间**  
- 我们只遍历一次 `b`（`n` 次），每次只做常数（4 次）更新，时间是 `O(4·n) = O(n)`。  
- 只需要保存 `dp[0..4]`，空间是 `O(4) = O(1)`。

#### 代码（Python）

```python
from typing import List
import math

def maxScore_dp(a: List[int], b: List[int]) -> int:
    # dp[k]：已经选了 k 个下标时的最大分数，k = 0..4
    dp = [-math.inf] * 5          # 先设为负无穷，表示不可达
    dp[0] = 0                      # 什么都不选的分数是 0

    for val in b:                  # 依次遍历 b 中的每个元素
        # 必须倒序更新，防止同一个元素被重复使用
        for k in range(3, -1, -1): # k = 3,2,1,0
            if dp[k] != -math.inf: # 只有已有合法状态才更新
                candidate = dp[k] + a[k] * val   # 选当前元素作为第 k 个
                if candidate > dp[k + 1]:        # 取更大的分数
                    dp[k + 1] = candidate

    return dp[4]                    # 选满 4 个下标后的最大分数
```

#### 复杂度

- **时间复杂度**：`O(n)` — 只遍历一次 `b`，每次做常数次（4 次）计算。相比暴力的 `O(n⁴)`，速度提升了 **指数级**。  
- **空间复杂度**：`O(1)` — 只用了长度为 5 的 `dp` 数组，大小不随 `n` 增长。

---

## 心得

- **核心技巧**：一维动态规划 + 倒序状态转移（防止重复使用同一元素）。  
- **适用的题型**：  
  1. “从序列中挑选固定个数的元素，求最大/最小加权和”  
  2. “给定若干权重，选择若干位置满足顺序，最大化总得分”  
  3. “在数组里挑选 `k` 条不相交子序列，求最优值”（类似 `Maximum Subsequence Sum with K Elements`）  
- **一句话总结**：**把“选第几个”当作 DP 的维度，用倒序更新保证顺序不冲突，便能线性时间搞定。**

## 反思

- **第一反应**：直接写四层循环暴力枚举，因为题目只有 4 个系数，看起来像是可以穷举。  
- **最容易踩的坑**：  
  - 忘记在 DP 中倒序更新，导致同一个 `b[i]` 被算进多个选位，破坏下标递增的限制。  
  - 初始化 `dp` 为负无穷（`-inf`），否则在所有数都是负数的情况下可能误把 `0` 当成合法答案。  
  - 边界条件：`b` 长度可能恰好是 4，代码仍需能正确返回唯一组合的分数。  
- **下次遇到同类题**：第一步先问自己“是否可以把‘已经选了多少个’作为状态”，如果答案是肯定的，就立刻尝试 **一维 DP + 倒序转移**。这样往往能把指数级暴力降到线性。
