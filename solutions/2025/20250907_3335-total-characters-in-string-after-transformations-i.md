## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是 **把字符串真的变一次再变一次** …… 直到完成 `t` 次转换，然后直接读出最终的长度。

- **每一次转换**  
  - 普通字符 `'a'~'y'` → 它们的下一个字符（比如 `'c'` → `'d'`）  
  - 特殊字符 `'z'` → 两个 `'a'`（即 `"aa"`）  

把上面的规则写成代码，遍历字符串把每个字符都换成对应的字符串，得到新字符串后继续下一轮。  

> **类比**：想象我们在玩“字母接龙”。每个人手里有一张字母卡，轮到他时把卡片上的字母改成下一个字母。如果卡片是 `'z'`，他会把它换成两张 `'a'` 卡。我们把所有人手里的卡片排成一行，就是当前的字符串。暴力做法就是每轮都把所有卡片都换一遍。

**为什么正确**：因为我们严格按照题目给出的转换规则逐步演化，最后得到的长度必然是题目要求的。

**时间/空间分析**  
- 第一次转换把长度 `n` 的字符串变成至多 `2n`（只 `'z'` 会产生两个字符），第二次又可能翻倍……  
- 设 `t` 为转换次数，最坏情况下每一步都把所有字符都变成两倍，长度会是 `O(n·2^t)`。  
- 直接模拟需要把这些巨大的字符串全部存下来，时间是 **指数级**，空间也是 **指数级**，根本不可行。

> **大白话**：如果 `t = 100`，`2^100` 这个数字比宇宙中原子数还大，根本不可能真的把这么长的字符串放进电脑里。

#### 代码（Python）

```python
MOD = 10**9 + 7

def length_bruteforce(s: str, t: int) -> int:
    cur = s
    for _ in range(t):
        nxt = []
        for ch in cur:
            if ch == 'z':
                nxt.append('a')
                nxt.append('a')          # 'z' 变成 "aa"
            else:
                nxt.append(chr(ord(ch) + 1))   # 普通字符变成下一个字母
        cur = ''.join(nxt)               # 生成新字符串
    return len(cur) % MOD               # 只返回长度
```

> **注释**  
> - `chr(ord(ch) + 1)` 把字符的 Unicode 编码加一，得到下一个字母。  
> - `''.join(nxt)` 把列表里的字符拼成字符串。

#### 复杂度

- **时间复杂度**：`O(n·2^t)`（指数级），因为每一次转换都可能把所有字符翻倍。  
- **空间复杂度**：`O(n·2^t)`，需要存放每一步产生的完整字符串。

显然，这种方法只能在 `t` 极小（比如 `t ≤ 5`）时勉强能跑通，远远达不到题目 `t ≤ 10^5` 的要求。

### 2. 最优解

#### 思路  

观察暴力解的 **瓶颈**：我们每一步都在 **构造完整的字符串**，而题目只要求 **长度**。如果能够在不生成字符串的情况下直接算出每个字符在 `t` 步后的长度，就可以把指数级的开销压到 **线性**。

**关键观察**  

1. 每个字符的演化只和它本身有关，互不影响。  
   - 例如，最开始的 `'a'` 走了多少步，完全不受其它字符的干扰。  
2. 只需要知道 **“单个字符在 k 步后会变成多长”**，再把所有字符的贡献相加即可。  
3. 由于字母只有 26 种，我们可以为每一种字母维护一个 **DP 表**  
   - `dp[i][k]`：字母编号 `i`（`0 → 'a'`，`25 → 'z'`）在进行 **恰好** `k` 次转换后对应的 **长度**。  

**递推关系**（把转换规则写成等式）  

- 若 `i < 25`（不是 `'z'`），一次转换后它只会变成下一个字母 `i+1`，所以  
  `dp[i][k] = dp[i+1][k-1]`  

- 若 `i == 25`（是 `'z'`），一次转换后会变成两个 `'a'`，每个 `'a'` 还要继续进行 `k-1` 次转换，故  
  `dp[25][k] = 2 * dp[0][k-1]`

- 基准情况：`dp[i][0] = 1`（0 次转换，长度仍是 1）。

这样只需要 **O(26·t)** 的时间就能算出所有 `dp[i][t]`。  
随后统计原字符串中每个字母出现的次数 `freq[i]`（用哈希表/数组），答案就是  

```
answer = Σ freq[i] * dp[i][t]   (mod 1e9+7)
```

**为什么快**  
- 只遍历 26 个字母，循环 `t` 次 → 约 `2.6·10^6` 次基本操作，轻松在毫秒级完成。  
- 没有任何字符串拼接，空间只需要两个长度为 26 的数组。

**类比**：把每个字母想象成一只“小机器人”。机器人只会按照固定的指令移动或复制自己。我们不需要记录它们走过的每一步，只要知道它们在第 `k` 步时“身长”是多少，就能算出总身长。

#### 代码（Python）

```python
MOD = 10**9 + 7

def totalLength(s: str, t: int) -> int:
    # 1️⃣ 统计每个字符出现次数
    freq = [0] * 26                     # freq[0] 对应 'a', freq[25] 对应 'z'
    for ch in s:
        freq[ord(ch) - ord('a')] += 1

    # 2️⃣ DP：cur[i] = dp[i][已经完成的步数]
    cur = [1] * 26                      # dp[i][0] = 1

    for _ in range(t):
        nxt = [0] * 26
        # a~y 只会变成下一个字母
        for i in range(25):            # 0~24 对应 'a'~'y'
            nxt[i] = cur[i + 1] % MOD
        # z 变成 "aa"
        nxt[25] = (2 * cur[0]) % MOD
        cur = nxt                       # 更新为完成了更多一步的结果

    # 3️⃣ 计算答案
    ans = 0
    for i in range(26):
        ans = (ans + freq[i] * cur[i]) % MOD
    return ans
```

> **关键行注释**  
> - `freq[ord(ch) - ord('a')] += 1`：把字符转成 0~25 的下标，统计出现次数。  
> - `nxt[i] = cur[i + 1]`：对应 “普通字符 → 下一个字符”。  
> - `nxt[25] = (2 * cur[0]) % MOD`：对应 “'z' → 'aa'”，两个 `'a'` 的长度相加。  
> - 最后把每个字母的贡献相加并取模。

#### 复杂度

- **时间复杂度**：`O(26·t) ≈ O(t)`  
  - 只遍历 `t` 次，每次处理 26 个字母。对 `t = 10^5` 来说约 2.6 万次操作，几乎瞬间完成。  
- **空间复杂度**：`O(26) = O(1)`  
  - 只使用两个长度为 26 的数组，常数级空间。

与暴力解相比，时间从指数级降到了线性，空间也从巨大的字符串降到了常数。

## 心得

- **核心技巧**：把“逐字符的演化”抽象为 **状态转移**（DP），只记录**长度**而不是整个字符串。  
- **适用场景**：  
  1. **字符/对象独立演化**，且只关心计数或长度（如“字符扩展”“细胞分裂”类题）。  
  2. **转换规则只涉及固定小集合**（如 26 个字母、4 种方向），可以用数组/哈希表做 DP。  
  3. **需要对大量相同起点进行合并**，利用出现频次一次性计算总贡献。  
- **一句话总结解题钥匙**：**把“每一步生成的字符串”换成“每个字母的长度递推”，利用 DP 把指数爆炸压到线性**。

## 反思

- **第一反应**：直接模拟字符串的每一次转换，写出循环把字符换成新字符。  
- **最容易踩的坑**  
  - **忘记取模**：长度会很快超过 64 位整数，需要在每一步都 `mod 1e9+7`。  
  - **忽视 `'z'` 的特殊规则**：它一次会产生两个 `'a'`，容易写成单个 `'a'`，导致答案偏小。  
  - **没有利用字符频次**：如果每次都对整条字符串遍历，会导致 `O(n·t)`，仍然超时。  
- **下次类似题目第一步**：先问自己“**我真的需要整个结构吗？还是只需要一个汇总量（长度/计数）？**”。如果是前者，考虑 DP/矩阵快速幂；如果是后者，统计频次并用递推公式一次算完。
