## 题目（中文翻译）

**题目描述**

给定一个二维字符矩阵 `grid`，其中 `grid[i][j]` 只能是字符 `'X'`、`'Y'` 或 `'.'`。请返回满足以下条件的子矩阵（submatrix）数量：

- 子矩阵中至少包含一个字符 `'X'`；
- 子矩阵中字符 `'X'` 与字符 `'Y'` 的出现次数相等。

**示例**

示例 1  
输入: `grid = [["X","Y","."],["Y",".","."]]`  
输出: `3`  
解释: 共有 3 个子矩阵满足条件（具体位置可自行枚举）。

示例 2  
输入: `grid = [["X","X"],["X","Y"]]`  
输出: `0`  
解释: 没有子矩阵同时满足至少包含一个 `'X'` 且 `'X'` 与 `'Y'` 出现次数相等。

示例 3  
输入: `grid = [[".","."],[".","."]]`  
输出: `0`  
解释: 所有子矩阵中均不存在 `'X'`，因此不满足条件。

**约束条件**

- `1 <= grid.length, grid[i].length <= 1000`
- `grid[i][j]` 只能是 `'X'`、`'Y'` 或 `'.'`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把 **每一个** 子矩阵都枚举出来，逐个统计其中 `'X'`、`'Y'` 的出现次数，然后检查：

1. `'X'` 的数量 = `'Y'` 的数量  
2. 至少出现一次 `'X'`（否则全是 `'.'` 不算）

> **数据结构类比**：  
> - 把矩阵想象成一张电子表格，枚举子矩阵就像在表格里画出左上、右下两个角的框框，框住的格子就是我们要检查的子矩阵。  
> - 统计字符出现次数相当于在框里用 **“计数器”**（一个普通的 `int`）去数 X、Y、. 的个数。

这种做法一定能得到正确答案，因为我们把所有可能的子矩阵都遍历了一遍，符合题目要求的自然不会漏掉。

#### 代码（Python）

```python
def countSubmatrices_bruteforce(grid):
    m, n = len(grid), len(grid[0])
    ans = 0
    # 枚举左上角 (r1, c1)
    for r1 in range(m):
        for c1 in range(n):
            # 枚举右下角 (r2, c2)（必须在左上角的右下方）
            for r2 in range(r1, m):
                for c2 in range(c1, n):
                    cntX = cntY = 0
                    # 统计这个子矩阵里 X、Y 的个数
                    for i in range(r1, r2 + 1):
                        for j in range(c1, c2 + 1):
                            if grid[i][j] == 'X':
                                cntX += 1
                            elif grid[i][j] == 'Y':
                                cntY += 1
                    # 判断是否满足条件
                    if cntX == cntY and cntX > 0:   # 至少有一个 X
                        ans += 1
    return ans
```

> 关键行解释  
> - 第 4‑7 行：四层循环把所有左上、右下坐标组合枚举出来。  
> - 第 10‑14 行：在当前子矩阵内部再用两层循环计数。  
> - 第 17 行：`cntX == cntY` 保证 X、Y 同等出现，`cntX > 0` 排除全是 `'.'` 的情况。

#### 复杂度

- **时间复杂度**：`O(m² * n²)`  
  - 想象一下如果矩阵是 1000×1000，外层四个循环会产生 `10⁶` 种左上/右下组合，每种组合内部又要遍历子矩阵的格子，最坏情况下是 `10⁶` 次遍历，整体约 `10¹²` 步，显然不可接受。  
  - 大写的 **O** 只是一种“数量级”标记，这里表示随着行数或列数的增大，运行时间会 **平方** 增长。

- **空间复杂度**：`O(1)`  
  - 只用了常数个计数变量，不随输入规模变化。

> 暴力解只能帮助我们 **确认** 思路是对的，随后需要把“慢的地方”给找出来，再想办法加速。

### 2. 最优解

#### 思路  

从暴力解可以看到，**两大瓶颈**：

1. **子矩阵枚举**：四层循环导致 `O(m²·n²)`。  
2. **每个子矩阵内部计数**：又多了一层 `O(area)` 的遍历。

我们要把这两层“遍历”压缩成 **一次** 或 **两次** 线性遍历。  
常用的技巧是 **前缀和 + 哈希表**，把“求子矩阵和”转化为 “求一维数组的子区间和”。  

---

#### 2.1 把字符映射成数字

- `'X' → +1`（相当于正数）  
- `'Y' → -1`（相当于负数）  
- `'.' → 0`（不影响和）

这样，一个子矩阵的 **和** 正好等于 `(#X) - (#Y)`。  
所以 **和为 0** 就等价于 **X 与 Y 出现次数相等**。

> 类比：把矩阵看成一本账本，`+1` 表示“收入 X”，`-1` 表示“支出 Y”，账本结算为 0 时，收入与支出相等。

---

#### 2.2 2D 前缀和的思路

如果我们事先算好 **每一列在任意两行之间的累计和**，就可以把 **子矩阵** 转换为 **某两行之间的 1‑维数组**。  
具体做法：

1. 固定 **上边界** `top`（第几行）。  
2. 从 `top` 向下遍历，维护一个长度为 `n`（列数）的数组 `colSum`，其中 `colSum[c]` 记录 **从 top 行到当前 bottom 行**（含）在第 `c` 列的累计值（+1 / -1 / 0 的和）。  
3. 每当把 `bottom` 向下移动一行，就把该行对应的数值 **加到** `colSum` 上，得到新的 “压缩” 1‑维数组。

此时，**任意子矩阵**（上边界为 `top`、下边界为 `bottom`、左边界为 `l`、右边界为 `r`）的和，就是 `colSum[l..r]` 这段子数组的 **和**。

所以我们只需要解决：**在一个 1‑维数组里，统计所有子数组的和为 0 的个数**。这正是“前缀和 + 哈希表”能高效完成的任务。

---

#### 2.3 统计子数组和为 0 并且至少含一个 X

单纯统计子数组和为 0 的方法：

```text
遍历数组，维护前缀和 prefix
使用哈希表 cnt 统计每个前缀和出现的次数
每次看到新的 prefix 时，答案加上 cnt[prefix]（因为之前出现过相同前缀和的下标，形成和为 0 的子数组）
随后 cnt[prefix] += 1
```

但我们还有额外的约束 **“子矩阵里必须至少出现一次 X”**。  
在 1‑维视角下，这等价于 **子数组里至少有一个非零元素且这个非零元素必须是 +1（即 X）**。  
因为：

- `0` 只来自 `'.'`，不会影响和。  
- `-1` 来自 `Y`，如果子数组只有 `-1` 和 `0`，和不可能为 0（除非配对 +1）。  
- 因此只要子数组 **和为 0**，且 **不全是 0**，就一定至少包含一个 `+1`（X）和一个 `-1`（Y），满足题目。

所以我们可以 **先统计所有和为 0 的子数组**，再 **减去那些全是 0（即全由 '.' 组成）的子数组**。

> **全是 0 的子数组** 在 1‑维数组中表现为连续的零段。长度为 `L` 的零段里，子数组数量为 `L·(L+1)/2`（等差数列求和公式）。

于是：

```
answer_for_this_row_pair = total_zero_sum_subarrays - zero_only_subarrays
```

---

#### 2.4 完整算法步骤

1. **把字符映射成整数**（+1 / -1 / 0）。  
2. 若行数 > 列数，**转置矩阵**（把宽的当成行），保证外层循环的平方部分是最小的维度。  
3. 初始化答案 `ans = 0`。  
4. 对每个上边界 `top`（0 … R‑1）  
   - 创建长度为 `C` 的 `colSum = [0]*C`。  
   - 对每个下边界 `bottom` 从 `top` 到 `R‑1`  
     - 把第 `bottom` 行对应的数值逐列累加到 `colSum`。  
     - **统计当前 `colSum` 中和为 0 的子数组**（哈希表） → `totalZero`。  
     - **统计全零段子数组** → `zeroOnly`（一次线性扫描）。  
     - `ans += totalZero - zeroOnly`。  
5. 返回 `ans`。

> **时间复杂度**：`O(min(R, C)² * max(R, C))`  
> - 外层两层循环遍历 **较小维度** 的所有上/下（或左/右）边界，平方得到 `min²`。  
> - 每次内层遍历时对整条长边（`max`）做一次线性扫描，得到乘积。  
> - 当 `R = C = 1000` 时，约 `10⁶` 次基本操作，完全可以在 Python 中 1‑2 秒内跑完。  

> **空间复杂度**：`O(max(R, C))`  
> - 只保存当前压缩的 1‑维数组 `colSum` 以及哈希表（大小 ≤ 列数），随输入规模线性增长。

---

#### 代码（Python）

```python
from collections import defaultdict
from typing import List

def countSubmatrices(grid: List[List[str]]) -> int:
    # ---------- 1. 把字符映射成数字 ----------
    # X -> 1, Y -> -1, . -> 0
    mat = [[1 if ch == 'X' else -1 if ch == 'Y' else 0 for ch in row] for row in grid]
    R, C = len(mat), len(mat[0])

    # ---------- 2. 若行 > 列，转置，保证外层循环的平方部分最小 ----------
    if R > C:                         # 转成列数更小的情形
        mat = [list(col) for col in zip(*mat)]
        R, C = C, R                  # 交换行列数

    ans = 0

    # ---------- 3. 枚举上边界 ----------
    for top in range(R):
        colSum = [0] * C               # 记录从 top 到当前 bottom 的列累计和
        # ---------- 4. 枚举下边界 ----------
        for bottom in range(top, R):
            # 把第 bottom 行加入累计和
            for c in range(C):
                colSum[c] += mat[bottom][c]

            # ---------- 5. 统计和为 0 的子数组 ----------
            prefix_cnt = defaultdict(int)
            prefix_cnt[0] = 1           # 空前缀和为 0，方便子数组从开头开始计数
            prefix = 0
            totalZero = 0
            for v in colSum:
                prefix += v
                totalZero += prefix_cnt[prefix]   # 之前出现过相同前缀和的下标形成和为0的子数组
                prefix_cnt[prefix] += 1

            # ---------- 6. 统计全零段子数组 ----------
            zeroOnly = 0
            run = 0                     # 当前连续零的长度
            for v in colSum:
                if v == 0:
                    run += 1
                else:
                    zeroOnly += run * (run + 1) // 2
                    run = 0
            zeroOnly += run * (run + 1) // 2   # 处理末尾的零段

            # ---------- 7. 更新答案 ----------
            ans += totalZero - zeroOnly

    return ans
```

> 关键行中文注释  
> - 第 2‑4 行：把字符直接映射为整数，后面所有运算都基于这三个数。  
> - 第 7‑10 行：如果行数比列数多，就 **转置** 矩阵，让外层的 `O(min²)` 更小。  
> - 第 15‑18 行：`colSum` 用来保存当前 `top~bottom` 区间每列的累计和。  
> - 第 22‑28 行：经典的 “前缀和 + 哈希表” 统计子数组和为 0 的个数。  
> - 第 31‑38 行：一次线性扫描统计所有 **全 0** 的子数组（零段）。  
> - 第 41 行：`totalZero - zeroOnly` 正好是满足 “和为 0 且至少含一个 X” 的子矩阵数。

---

#### 复杂度

- **时间复杂度**：`O(min(R, C)² * max(R, C))`  
  - 解释：设 `R ≤ C`（如果不满足会在第 7 行转置），则外层两层循环遍历 `R²` 种上下边界组合。每种组合内部遍历整条长度为 `C` 的 `colSum`（两次线性扫描），所以总步数约为 `R²·C`。  
  - 与暴力解 `O(R²·C²)` 相比，**把一个维度的平方降到了线性**，速度提升约 `C` 倍。

- **空间复杂度**：`O(C)`（或 `O(max(R, C))`）  
  - 只用了 `colSum`、`prefix_cnt` 两个长度不超过列数的数组/字典，随输入规模线性增长。

## 心得

- **核心技巧**：二维前缀和 + 行（列）压缩 + 一维前缀和 + 哈希表  
- **适用题型**  
  1. “子矩阵和等于 target” 系列（LeetCode 1074、1065 等）  
  2. “子矩阵中满足某种统计条件” 如等差子矩阵、颜色均匀子矩阵  
  3. “二维数组中找满足 X 与 Y 同等出现次数的子区域”  
- **一句话总结解题钥匙**：把二维问题压成一维，用前缀和 + 哈希表一次遍历搞定“和为 0”，再剔除全零的情况。

## 反思

- **第一反应**：直接枚举所有子矩阵并逐个计数——虽然能想到，却忽视了规模会爆炸。  
- **最容易踩的坑**  
  - **忘记排除全 '.' 的子矩阵**，导致统计结果偏大。  
  - **没有对矩阵进行转置**，导致在 `1000×1000` 的极限数据上超时。  
  - **前缀和哈希表的初始值**：忘记在字典中放入 `0:1`，会漏掉从第一列开始的子矩阵。  
- **下次类似题的第一步**：  
  - 先把 **二维** “压缩” 成 **一维**（固定上下边界或左右边界），  
  - 再思考 **一维前缀和** 能否一次遍历得到目标计数。  

这样思路就已经从 “暴力枚举” 跳到 “压缩 + 前缀和”，大幅提升效率。祝你玩得开心！
