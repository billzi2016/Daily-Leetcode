## 题目（中文翻译）

**题目描述**  
给定一个大小为 `m x n` 的二维数组（2D array）`grid`，其中所有元素均为正整数。  
要求按照**之字形遍历**（zigzag pattern traversal）的方式遍历 `grid`，并在遍历过程中**跳过每隔一个单元格**（skip every alternate cell）。  

之字形遍历的具体规则如下（必须在遍历时跳过每隔一个单元格）：  
1. 从左上角 `(0, 0)` 开始访问。  
2. 首先沿当前行向右移动，直到到达该行的最右侧单元格。  
3. 然后向下一行移动一个单元格，再沿该行向左移动，直到到达该行的最左侧单元格。  
4. 重复步骤 2、3，直至遍历完整个矩阵。  
5. 在上述移动过程中，**每访问一个单元格后，需要跳过下一个未被访问的单元格**，即只记录访问的单元格的值，未被记录的单元格视为“跳过”。  

返回一个整数数组 `result`，其中按访问顺序存放所有被记录的单元格的值。

---

**示例**

> 示例 1  
> **输入**：`grid = [[1,2],[3,4]]`  
> **输出**：`[1,4]`  
> **解释**：  
> - 从 `(0,0)` 访问 `1`，跳过 `(0,1)`。  
> - 向下移动到 `(1,1)` 访问 `4`，跳过 `(1,0)`（已超出遍历范围），因此结果为 `[1,4]`。

> 示例 2  
> **输入**：`grid = [[2,1],[2,1],[2,1]]`  
> **输出**：`[2,1,2]`  
> **解释**：  
> - 访问 `(0,0)` → `2`，跳过 `(0,1)`。  
> - 向下到 `(1,1)` → `1`，跳过 `(1,0)`。  
> - 向下到 `(2,0)` → `2`，完成遍历，结果为 `[2,1,2]`。

> 示例 3  
> **输入**：`grid = [[1,2,3],[4,5,6],[7,8,9]]`  
> **输出**：`[1,3,5,7,9]`  
> **解释**：  
> - 访问顺序为 `(0,0)`→`1`（跳过 `(0,1)`），`(0,2)`→`3`（跳过 `(1,2)`），`(1,1)`→`5`（跳过 `(1,0)`），`(2,0)`→`7`（跳过 `(2,1)`），`(2,2)`→`9`，得到 `[1,3,5,7,9]`。

---

**约束条件**  

- `2 <= n == grid.length <= 50`  
- `2 <= m == grid[i].length <= 50`  
- `1 <= grid[i][j] <= 2500`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是先把 **整个** “之字形”遍历顺序全部写进一个列表 `order`，  
再把这个列表按照 “跳过每隔一个格子” 的规则取出需要的元素。

- **之字形遍历**：第一行从左往右走，第二行从右往左走，第三行再从左往右……  
  这跟我们在超市里“蛇形”排队非常相似，左走完了就转身从右走，左走右走交替进行。  
- **跳过规则**：访问完一个格子后必须 **跳过** 紧接着的下一个格子，等价于只保留列表中下标为偶数的元素（0、2、4…）。

> 为什么这样一定能得到正确答案？  
> 因为题目要求的遍历顺序已经唯一确定：每行的走向固定且交替；在此顺序上每隔一个格子取一次，就是“跳过每隔一个格子”的完整实现。

**时间/空间分析（大白话）**  

- 我们要把矩阵里的每个格子都走一遍，矩阵大小是 `m × n`，所以需要 **`m·n` 次操作**，这就是时间复杂度 `O(m·n)`（相当于每个格子都“看一眼”）。  
- 暴力实现会额外创建一个长度为 `m·n` 的列表 `order` 来保存完整遍历顺序，这相当于 **再占用一个和原矩阵同样大的盒子**，所以空间复杂度是 `O(m·n)`。

#### 代码（Python）

```python
def zigzagTraversal_bruteforce(grid):
    """
    暴力版：先生成完整的之字形遍历顺序，再挑出每隔一个的元素
    """
    m, n = len(grid), len(grid[0])
    order = []                     # 用来保存完整遍历顺序的列表

    for i in range(m):
        # 根据行号决定遍历方向：偶数行左→右，奇数行右→左
        if i % 2 == 0:             # 左到右
            row_iter = range(n)    # 0,1,2,...,n-1
        else:                      # 右到左
            row_iter = range(n - 1, -1, -1)  # n-1,...,1,0

        for j in row_iter:
            order.append(grid[i][j])   # 把当前格子的值加入完整顺序

    # 只保留下标为偶数（即每隔一个）的元素
    result = [order[k] for k in range(0, len(order), 2)]
    return result
```

#### 复杂度

- **时间复杂度**：`O(m·n)` —— 必须访问矩阵的每一个格子两遍（一次放进 `order`，一次挑选），但仍是线性规模。  
- **空间复杂度**：`O(m·n)` —— 额外用了一个和矩阵同等大小的列表 `order`。

### 2. 最优解

#### 思路  

从暴力解可以看到 **两大“耗材”**：

1. **额外的完整遍历列表** `order`（占用 `O(m·n)` 空间）。  
2. **两次遍历**：一次生成 `order`，一次再挑选。

其实我们在遍历矩阵的过程中 **可以直接决定是否把当前格子加入答案**，根本不需要先把所有格子保存下来。只要维护一个 **布尔变量 `take`**，表示“这一次要取值”，每访问一个格子后就把 `take` 取反（相当于“跳过”下一个格子）。

核心技巧：

- **蛇形遍历**（每行方向交替） → 用行号的奇偶性决定遍历顺序。  
- **跳过每隔一个** → 用 `take` 变量在 `True/False` 之间切换。  
- **空间优化** → 只保留结果列表 `result`（输出本身），不再额外申请 `order`。

下面用类比帮助理解：

> 想象你在一条长长的走廊里，每走一步都要**踩脚印**（记录），但规定**每踩两步才留下脚印**。如果你把每一步都记下来再挑选，那就是暴力做法；如果你在走的过程中直接决定“这一步踩脚印吗？” 那么只需要一块纸记下踩脚印的地方，就是最优做法。

#### 代码（Python）

```python
def zigzagTraversal_optimal(grid):
    """
    最优版：遍历时直接决定是否把当前格子加入答案，省去额外的列表。
    """
    m, n = len(grid), len(grid[0])
    result = []          # 最终返回的答案
    take = True          # True 表示本次要取值，随后会翻转成 False（跳过下一个）

    for i in range(m):
        # 根据行号决定遍历方向
        if i % 2 == 0:                 # 偶数行：左 → 右
            cols = range(n)            # 0,1,2,...,n-1
        else:                          # 奇数行：右 → 左
            cols = range(n - 1, -1, -1)  # n-1,...,1,0

        for j in cols:
            if take:                    # 当前格子需要被访问
                result.append(grid[i][j])
            # 每访问完一个格子，都要翻转一次，确保“跳过”下一个
            take = not take

    return result
```

#### 复杂度

- **时间复杂度**：`O(m·n)` —— 仍然需要遍历每个格子一次，和暴力解一样快，只是少了一遍筛选。  
- **空间复杂度**：`O(1)`（不计输出本身）—— 只用了几个额外的变量 `take`、`result`，没有额外的与矩阵同等规模的存储。

与暴力解对比：**时间相同，空间从 `O(m·n)` 降到 `O(1)`**，在大矩阵时可以显著降低内存占用。

## 心得

- **核心技巧**：**蛇形遍历 + 交替取值（布尔翻转）**。  
- **适用场景**：  
  1. 需要 **交替取值** 的一维或二维序列（如“每隔一个取一次”）。  
  2. **蛇形/之字形遍历** 的矩阵问题（如 LeetCode 498 “对角线遍历” 的变形）。  
  3. 任何可以用 **状态翻转**（`True/False`）来决定是否“采样”的情形。  
- **一句话总结**：**遍历时直接用一个“开关”决定取不取，既省时又省空间**。

## 反思

- **第一反应**：把整条蛇形路径先写出来，再手动挑出每隔一个的元素。  
- **最容易踩的坑**：  
  - 忘记在 **奇数行** 需要倒序遍历，导致顺序错误。  
  - “跳过”是全局的，而不是每行单独重置；如果在每行重新把 `take` 设为 `True`，就会出现 **连续两格被取** 的错误。  
  - 边界情况：矩阵只有一行或一列时，仍需保证方向切换和跳过逻辑一致。  
- **下次思路**：遇到类似“遍历 + 隔位采样”的题目时，第一步就思考 **“是否可以在遍历过程中直接决定采样”**，把 “先遍历再筛选” 的两步合并为一步。这样往往能直接得到最优解。
