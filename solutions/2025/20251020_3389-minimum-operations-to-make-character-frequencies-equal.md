## 解题过程

### 1. 直觉解（暴力）

#### 思路  

1. **把字符串抽象成出现次数数组**  
   - 统计每个字母在 `s` 中出现了多少次，得到长度为 26 的数组 `cnt`，下标 `0~25` 分别对应 `'a'~'z'`。  
   - 这一步可以把“字符串”看成“字典”，字典的 **key** 是字母，**value** 是出现次数——就像查字典时，词是 key，页码是 value。

2. **好字符串的定义**  
   - 对于一个 **好** 的字符串，所有出现的字母要么全部出现 **0 次**（即根本不存在），要么全部出现同一个正整数 `c` 次。  
   - 换句话说，`cnt` 中的每个元素只能是 **0** 或 **c**。

3. **最直接的想法**  
   - 先假设目标频次 `c` 已经知道，然后把每个字母的出现次数改成 `0` 或 `c`，看需要多少操作。  
   - 对于单个字母的出现次数 `x`，我们有两种选择：  
     - **删掉全部**：需要 `x` 次 “删除一次” 操作（把 `x` 变成 `0`）。  
     - **调到 `c`**：如果 `x > c`，需要 `x‑c` 次 “减 1”。如果 `x < c`，需要 `c‑x` 次 “加 1”。  
   - 对每个字母我们取 **较小的那种**，把所有字母的费用加起来，就是在这个 `c` 下的总操作数。

4. **遍历所有可能的 `c`**  
   - `c` 的取值范围显然在 `1 … max(cnt)`（因为如果 `c` 大于所有出现次数，就只能把所有字母删掉，显然不是最优）。  
   - 对每一个 `c` 计算上述费用，最后取最小值。

5. **为什么这个办法是对的？**  
   - 我们枚举了 **所有可能的目标频次**，并且对每个字母都挑了最省操作的方式（要么删掉，要么调到 `c`），所以一定能得到最少操作数。

6. **复杂度的大白话**  
   - `cnt` 长度固定为 26（英文字母个数），遍历 `c` 最多到字符串长度 `n`（`n ≤ 2·10⁴`），每次遍历都要看 26 个字母。  
   - 所以总共做的工作量大约是 `26 × n`，这在程序里写成 **O(n)**。  
   - 这里的 **O(n)** 并不是说程序只跑 `n` 步，而是说工作量随 `n` 成线性增长，和 `n` 成正比。

#### 代码（Python）

```python
from collections import Counter

def minOperations_bruteforce(s: str) -> int:
    # 统计每个字母出现次数，cnt[i] 对应 'a'+i
    cnt = [0] * 26
    for ch in s:
        cnt[ord(ch) - ord('a')] += 1

    max_cnt = max(cnt)                     # 出现次数的最大值
    ans = float('inf')                     # 初始答案设为无穷大

    # 枚举目标频次 c（c 必须是正数，因为“好”字符串里出现的字母次数相同且大于 0）
    for c in range(1, max_cnt + 1):
        cur = 0
        for x in cnt:                      # 对每个字母的出现次数 x
            # 两种选择：删光（费用 x） 或 调到 c（费用 |x-c|）
            cur += min(x, abs(x - c))
        ans = min(ans, cur)                # 取所有 c 中的最小值

    return ans
```

> **关键行注释**  
> - `cnt[ord(ch) - ord('a')] += 1`：把字符 `'a'~'z'` 映射到数组下标 `0~25`，相当于在“查字典”。  
> - `min(x, abs(x - c))`：如果把这个字母全部删掉需要 `x` 次操作；如果把它调到 `c` 需要 `|x‑c|` 次操作，取较小者。

#### 复杂度

- **时间复杂度：O(n)**  
  - `n` 是字符串长度。我们只遍历一次字符串统计次数（O(n)），随后遍历最多 `max_cnt ≤ n` 次的 `c`，每次检查 26 个字母（常数），所以整体仍然随 `n` 线性增长。

- **空间复杂度：O(1)**  
  - 只用了长度固定为 26 的数组 `cnt`，不随 `n` 增长。

### 2. 最优解

#### 思路  

暴力解已经是 **O(n)**，已经很快了，但它仍然在每一次 `c` 的枚举中对每个字母都做一次 `min`，没有利用 **字母出现次数之间的关系**。我们可以把问题再抽象成 **动态规划**（DP），让代码更具结构性，也更容易推广到类似的 “把数组改成只包含 0 或相同正数” 的题目。

1. **重新审视 “好” 的条件**  
   - `cnt` 必须只包含两种数值：`0` 或某个正整数 `c`。  
   - 这等价于：我们把 **若干个字母保留下来**（它们的次数统一为 `c`），其余字母全部删除。

2. **核心观察**  
   - **观察 1**：把相邻的两个字母同时做 “减 1 + 增 1” 的操作（即把一个字母的次数转移给下一个字母）永远不是最优的。我们可以改成“把左边删掉，右边再加一次”，费用一样甚至更低。  
   - **观察 2**：**增后再减**（或 **减后再增**）也没有意义，因为我们可以直接省掉这两步。换句话说，**每个字母要么只增，要么只减，要么直接删光**。

   这两个观察让我们可以把每个字母的处理方式 **固定为三种之一**：  
   - **删除**（费用 = 原始次数）  
   - **调到目标频次 `c`**（只增或只减，费用 = |cnt[i]‑c|）

3. **把字母按出现次数从大到小排序**  
   - 排序后，若我们决定保留前 `k` 个字母，它们的次数会比较接近，调到同一个 `c` 的代价通常更小。  
   - 排序不会改变答案，因为字母之间是互相独立的，只是我们把“挑哪些留下”这件事变得更容易描述。

4. **动态规划的定义**  
   - 设 `a[1…m]` 为排序后的出现次数（`m ≤ 26`，实际只保留出现次数>0 的字母）。  
   - `dp[i]` 表示 **处理前 `i` 个字母（`a[1] … a[i]`）**，使它们满足“要么删掉，要么调到同一个频次”，所需要的最小操作数。  
   - 初始值：`dp[0] = 0`（不处理任何字母，费用为 0）。

5. **状态转移**  
   - **方案 A：把第 `i` 个字母直接删掉**  
     - 费用 = `a[i]`（因为要把它的所有出现次数全部删掉）  
     - 转移式：`dp[i] = dp[i‑1] + a[i]`

   - **方案 B：把第 `j … i`（`j ≤ i`）这段字母合并成同一个频次 `c`**  
     - 这段字母要么全部增，要么全部减，最省操作的 `c` 是这段数的 **中位数**（因为绝对值求和的最小点就在中位数）。  
     - 设 `mid = (j + i) // 2` 为中位数下标，`c = a[mid]`。  
     - 费用 = ` Σ_{t=j}^{i} |a[t] - c|`（把每个数改成 `c` 所需的增/减次数）。  
     - 我们可以用前缀和快速算出这段的费用：  
       - `pre[t] = Σ_{k=1}^{t} a[k]`（普通前缀和）  
       - 对于左侧（≤ c）和右侧（≥ c）分别计算：  
         ```
         left  = c * (mid - j + 1) - (pre[mid]   - pre[j-1])
         right = (pre[i] - pre[mid]) - c * (i - mid)
         cost  = left + right
         ```
     - 转移式：`dp[i] = min(dp[i], dp[j-1] + cost)`

   - 因为 `m ≤ 26`，我们可以 **枚举所有 `j`**，整体复杂度是 `O(m²)`，即最多 `26² = 676` 次计算，几乎可以忽略不计。

6. **答案**  
   - 最终 `dp[m]` 即为把整个 `cnt` 变成好字符串的最少操作数。

7. **为什么比暴力更好？**  
   - 暴力需要遍历所有可能的目标频次 `c`（最多 `n` 次），虽然时间仍是 `O(n)`，但在最坏情况下 `n` 可能达到 `2·10⁴`。  
   - DP 只和 **字母种类**（最多 26）有关，时间是 `O(26²)`，几乎是常数级别，运行更快、更稳。

#### 代码（Python）

```python
from collections import Counter
from itertools import accumulate

def minOperations_dp(s: str) -> int:
    # 1️⃣ 统计出现次数，只保留出现过的字母
    freq = Counter(s)
    a = sorted(freq.values(), reverse=True)   # 从大到小排好
    m = len(a)                                 # 实际出现的字母数，最多 26

    if m == 0:                                 # 空串（题目不可能出现）直接返回 0
        return 0

    # 2️⃣ 前缀和，方便后面快速求区间和
    pre = [0] + list(accumulate(a))            # pre[i] = a[0] + ... + a[i-1]

    # 3️⃣ DP 数组，dp[i] 处理前 i 个字母（1-indexed）
    INF = 10**9
    dp = [INF] * (m + 1)
    dp[0] = 0

    # 4️⃣ 主循环：枚举右端点 i
    for i in range(1, m + 1):
        # 方案 A：把第 i 个字母直接删掉
        dp[i] = dp[i - 1] + a[i - 1]           # a 的索引是 0 基

        # 方案 B：把区间 [j, i] 合并成同一个频次
        # 枚举左端点 j（1-indexed）
        for j in range(1, i + 1):
            # 中位数下标（在 a 中是 0 基）
            mid = (j + i - 1) // 2
            c = a[mid]                         # 取中位数作为目标频次

            # 左侧 (j … mid) 需要把数增到 c
            left_cnt = mid - j + 1
            left_sum = pre[mid + 1] - pre[j]   # 区间和，左闭右开
            left_cost = c * left_cnt - left_sum

            # 右侧 (mid+1 … i) 需要把数减到 c
            right_cnt = i - mid
            right_sum = pre[i + 1] - pre[mid + 1]
            right_cost = right_sum - c * right_cnt

            cost = left_cost + right_cost       # 把 [j,i] 全部变成 c 的费用
            dp[i] = min(dp[i], dp[j - 1] + cost)

    return dp[m]
```

> **关键行注释**  
> - `pre = [0] + list(accumulate(a))`：构造前缀和，`pre[k]` 表示前 `k` 个数的总和，方便 O(1) 求任意区间的和。  
> - `mid = (j + i - 1) // 2`：因为 `a` 用 0 基索引，这里算出 `[j,i]` 区间的中位数下标。  
> - `left_cost = c * left_cnt - left_sum`：左边的数都 **小于等于** 中位数，需要 **增** 到 `c`，所以费用是 “目标值 × 个数” 减去 “原来的和”。  
> - `right_cost = right_sum - c * right_cnt`：右边的数都 **大于等于** 中位数，需要 **减** 到 `c`，费用是 “原来的和” 减去 “目标值 × 个数”。  

#### 复杂度

- **时间复杂度：O(26²) ≈ O(1)**  
  - 主循环枚举 `i`（最多 26 次），内部又枚举 `j`（最多 26 次），每次只做常数级计算。  
  - 与字符串长度 `n` 无关，实际上是常数时间。

- **空间复杂度：O(26) ≈ O(1)**  
  - 只用了长度为 26 左右的几个数组（`a`, `pre`, `dp`），占用的内存不随 `n` 增长。

## 心得

- **核心技巧**：把“字符出现次数相等”抽象为“数组只包含 0 或同一个正数”，利用**排序 + 前缀和 + 动态规划**求最小改动代价。  
- **适用场景**：  
  1. **把数组改成只包含两种数值**（如 0 与某个统一值）的最小修改题。  
  2. **把字符频次统一**的题目，例如 “使所有字符出现次数相同的最小删除次数”。  
  3. **把数列变成等差/等比数列**时，需要对每段进行统一处理的 DP 思路。  
- **一句话总结**：**先把字符频次排序，再用 DP 把相邻的几段统一到同一个中位数，这样既保证最少操作，又只和字母种类数有关。**

## 反思

- **第一反应**：看到“所有字符出现次数相同”，自然想到统计频次，然后枚举目标频次 `c`。这就是暴力思路。  
- **最容易踩的坑**  
  - **忘记可以把字母直接删掉**，导致在某些 `c` 下算出错误的更大代价。  
  - **中位数的概念**：如果不熟悉，可能会随便选一个 `c`，而不是最优的 `c`。  
  - **边界条件**：空字符串或全部相同字符时，DP 初始化和转移必须处理好 `dp[0]`。  
- **下次类似题目第一步**：**先把问题抽象成对“出现次数数组”的操作**，判断是否可以通过**排序 + 前缀和**快速求区间代价，再决定是否需要 DP。这样思路更清晰，代码也更简洁。
