## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是把每个 `nums[i]` 当作**目标值**，从 `0` 开始枚举所有可能的 `ans[i]`，检查是否满足  

```
ans[i] | (ans[i] + 1) == nums[i]
```

如果找到了，就把第一个（即最小的）满足条件的数记下来；如果遍历完都没有找到，就把 `ans[i] = -1`。

> **数据结构**：只需要普通的整数，遍历时用一个 `for` 循环。可以把哈希表想象成 **“查字典”**——这里根本不需要查字典，因为我们只是在**顺序查找**。

> **为什么正确**：暴力遍历把**所有可能的答案**都穷举了一遍，只要答案存在，就一定会被找到。  

> **复杂度**：  
> - 时间复杂度：对每个 `nums[i]` 最差要遍历到 `nums[i]` 本身，所以是 `O(nums[i])`。在最坏情况下（`nums[i]` 接近 `10^9`）显然不可接受。  
> - 空间复杂度：只用了常数级的额外变量，`O(1)`。

> **大白话**：`O(n²)` 里的 `O` 代表“**数量级**”。如果说 `O(10^9)`，那就相当于**十亿次**操作，普通电脑根本跑不完。

#### 代码（Python）

```python
def construct_min_array_bruteforce(nums):
    """
    暴力解：枚举每个可能的 ans[i]，找最小的满足条件的数。
    """
    ans = []
    for num in nums:
        # 只能是奇数才能满足 OR 为奇数，偶数直接-1
        if num % 2 == 0:
            ans.append(-1)
            continue

        found = -1
        # 从 0 开始枚举，最多到 num 本身（超过它就不可能了）
        for cand in range(num + 1):
            if (cand | (cand + 1)) == num:
                found = cand
                break          # 第一个就是最小的
        ans.append(found)
    return ans
```

#### 复杂度

- **时间复杂度**：`O( Σ nums[i] )`，在最坏情况下接近 `O(10^9)`，远远超出时间限制。  
- **空间复杂度**：`O(1)`（不计答案数组的存放）。

### 2. 最优解

#### 思路  

暴力的瓶颈在于**逐个枚举**。我们需要利用位运算的特性，直接从 `nums[i]` 的二进制形式推出最小的 `ans[i]`。

**关键观察 1 – 必须是奇数**  
`ans[i] | (ans[i] + 1)` 的最低位一定是 `1`（因为 `ans[i]` 与 `ans[i]+1` 中必有一个是奇数），所以得到的结果一定是奇数。  
> 因此所有 **偶数** `nums[i]` 都直接返回 `-1`。

**关键观察 2 – 结果的二进制形态**  
设 `x = ans[i]`，`y = x + 1`。`x` 与 `y` 只有**进位**的那一位不同，低位全部是 `1`（在 `x` 中）或 `0`（在 `y` 中）。  
所以 `x | y` 的二进制一定形如  

```
[高位保持不变] 0 111...111
               ^   ^
               |   └─ 连续的 1（至少一个）
               └───── 第一个出现的 0
```

换句话说，**从最低位往左数，先是一段连续的 `1`，紧接着是恰好一个 `0`，其左侧可以是任意 0/1**。  

> 如果整个数都是 `1`（形如 `111…111`），可以把左侧的“隐形 0”想象成在最高位左边的那位。

**关键观察 3 – 如何得到最小的 `ans`**  

1. **全部是 `1` 的情况**（`num = 2^k - 1`）  
   这时把左侧的“隐形 0”当作第一个 `0`。最小的 `ans` 是把最高位左移一位后再全部置 `1`，即  

   ```
   ans = (num - 1) // 2
   ```

   示例：`num = 7 (111)` → `ans = 3 (011)`，因为 `3 | 4 = 111`。

2. **不是全部 `1` 的情况**  
   - 记 **右侧连续 `1` 的个数** 为 `tz`（trailing ones）。  
   - 若 `tz == 1`（只有最右边一个 `1`），最小答案只需要把这唯一的 `1` 清掉：

     ```
     ans = num - 1          # 把最低位的 1 变成 0
     ```

   - 若 `tz > 1`，则右侧的 `0` 出现在第 `p = tz` 位（从 0 开始计数）。  
     设 `high = num >> (p + 1)`（把该 `0` 以及其右侧全部抛掉），
     那么最小的 `ans` 只保留高位不变，并在最低位放一个 `1`，其余低位全部 `0`：

     ```
     ans = (high << (p + 1)) | 1
     ```

     直观解释：把 **“左边的高位”** 完整保留，**右边的所有位** 只留下最小的可能值 `1`，这样 `ans` 已经是最小的满足条件的数。

**完整的判定流程**：

| 情况 | 判定条件 | 计算方式 |
|------|----------|----------|
| 偶数 | `num % 2 == 0` | `-1` |
| 全部 `1` | `num + 1` 是 2 的幂 (`(num + 1) & num == 0`) | `(num - 1) // 2` |
| 右侧仅一个 `1` | `tz == 1` | `num - 1` |
| 右侧连续 `1` ≥ 2 | 其余情况 | `((num >> (tz + 1)) << (tz + 1)) | 1` |

> **为什么这样是最小的**  
> - 高位不变是必须的，否则 `OR` 的高位会变小，达不到 `num`。  
> - 在低位我们只保留一个最小的 `1`（或者直接把唯一的 `1` 清掉），再往下放任何 `1` 都只会让答案更大。  

#### 代码（Python）

```python
def construct_min_array(nums):
    """
    最优解：只用位运算 O(1) 时间得到每个答案。
    """
    def is_all_ones(x):
        # x 为 2^k - 1 当且仅当 x+1 是 2 的幂
        return (x + 1) & x == 0

    ans = []
    for num in nums:
        # 1. 偶数直接 -1
        if num % 2 == 0:
            ans.append(-1)
            continue

        # 2. 全部是 1 的特殊情况，如 3,7,15,...
        if is_all_ones(num):
            ans.append((num - 1) // 2)
            continue

        # 3. 统计最低位连续的 1 的个数（trailing ones）
        tz = 0                     # tz = trailing ones
        tmp = num
        while tmp & 1:            # 只要最低位是 1 就继续计数
            tz += 1
            tmp >>= 1

        # 4. 根据 tz 的不同给出答案
        if tz == 1:                # 仅有一个最低位的 1
            ans.append(num - 1)    # 把它清零即可
        else:                      # tz >= 2
            # 把右边 (tz+1) 位全部抹掉，只保留更高位
            high = num >> (tz + 1)
            # 再把保留下来的高位左移回来，并在最低位放一个 1
            candidate = (high << (tz + 1)) | 1
            ans.append(candidate)

    return ans
```

#### 复杂度

- **时间复杂度**：对每个 `num` 只做常数次位运算（最多遍历一次连续的 `1`），所以是 `O(n)`，其中 `n = len(nums)`（最多 100），几乎可以忽略不计。  
- **空间复杂度**：只用了几个临时整数，`O(1)`（不计返回的答案数组）。

## 心得

- **核心技巧**：**分析二进制的结构**——特别是“从低位起连续的 1 与其左侧的第一个 0”。  
- **适用题型**：  
  1. 需要根据 **位运算** 推导出唯一/最小解的题目（如 “构造满足 `a & b = c` 的最小 `a`”。）  
  2. “**连续 1/0**” 规律出现的题目（如 “找出整数的最低位 0” 或 “把整数变成全 1”。）  
- **一句话总结解题钥匙**：**把 `num` 看成 “高位 + 第一个 0 + 全部 1”，再根据 1 的数量直接写出最小的 `ans`**。

## 反思

- **第一反应**：直接枚举，没想到位运算还能一次算出答案。  
- **最容易踩的坑**：  
  - 忽略 **全部是 1** 的特殊情况（会导致公式出错）。  
  - 把 **偶数** 当成可解，实际上必须返回 `-1`。  
  - 统计 “右侧连续的 1” 时忘记把 `tmp >>= 1` 放在循环里，导致死循环。  
- **下次类似题目**：第一步先**写出目标数的二进制模式**（高位/0/低位全 1），再**从左到右/从右到左**定位关键位，最后用位移/掩码直接构造答案。
