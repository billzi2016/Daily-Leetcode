## 题目（中文翻译）

**题目描述**  
给定一个仅包含数字字符的字符串 `s`。重复执行下列操作，直至字符串恰好剩下两位数字：

- 设当前字符串为 `c₀c₁…c_{n‑1}`（其中 `c_i` 为单个数字字符），构造新字符串 `d₀d₁…d_{n‑2}`，使得  
  `d_i = ( (c_i - '0') + (c_{i+1} - '0') ) mod 10`，即相邻两个数字之和对 10 取模的结果。  
- 用新字符串替换原字符串。

当字符串长度为 2 时，若这两个数字相同则返回 `true`，否则返回 `false`。

---

**示例**

**示例 1**  
```text
Input: s = "3902"
Output: true
Explanation:
"3902" → (3+9)%10=2, (9+0)%10=9, (0+2)%10=2 → "292"
"292"  → (2+9)%10=1, (9+2)%10=1 → "11"
最终得到的两位数字相同，返回 true。
```

**示例 2**  
```text
Input: s = "34789"
Output: false
Explanation:
"34789" → "7157"
"7157"  → "862"
"862"   → "48"
最终得到的两位数字不同，返回 false。
```

---

**约束条件**  

- `3 <= s.length <= 100`
- `s` 仅由数字字符组成。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是 **完全按照题目描述一步步模拟**：  
- 把字符串 `s` 拆成一个数字列表 `a[0] … a[m-1]`（把字符 `'3'` 当成整数 `3`）。  
- 只要列表长度大于 2，就遍历相邻的两位，计算 `(a[i] + a[i+1]) % 10`，把得到的结果放进一个新列表。  
- 用新列表替换旧列表，重复上述过程，直到只剩下 2 位。  

> **类比**：把列表想成一排排的小盒子，每次我们把相邻的两个盒子里的数字相加（只保留个位），再把结果装进一个更短的新排。这个过程一直进行，直到只剩下两盒子。

**为什么一定能得到正确答案**  
题目说“重复进行上述操作直到只剩两位”，我们正是把每一次操作完整、准确地执行了一遍，所以最后得到的两位一定是题目要求的“最终两位”。只要比较这两位是否相同，答案自然正确。

**时间/空间复杂度**  
- 第一次遍历 `n-1` 次，第二次遍历 `n-2` 次……最后一次遍历 1 次。总次数约为  

  \[
  (n-1)+(n-2)+\dots+1 = \frac{n(n-1)}{2}=O(n^2)
  \]

  这里的 `O(n²)` 可以理解为：如果 `n=100`，大约要做 5 000 次加法和取模运算，数量级是平方级的。

- 我们每一步都需要保存当前的列表，列表长度最多是原始长度 `n`，所以额外空间是 `O(n)`（只需要一个临时列表）。

#### 代码（Python）

```python
def checkIfEqual(s: str) -> bool:
    # 把字符转成整数列表，方便后面直接相加
    cur = [int(ch) for ch in s]          # 例：'3902' -> [3,9,0,2]

    # 只要长度大于 2，就继续做“相邻两位相加取个位”这一步
    while len(cur) > 2:
        nxt = []                         # 用来存放本轮运算的结果
        for i in range(len(cur) - 1):
            # (a + b) % 10 只保留个位
            nxt.append((cur[i] + cur[i + 1]) % 10)
        cur = nxt                        # 用新列表替换旧列表

    # 循环结束后，cur 里恰好有两位数字
    return cur[0] == cur[1]              # 两位相等返回 True，否则 False
```

#### 复杂度

- **时间复杂度**：`O(n²)` —— 随着字符串长度的增大，运算次数会呈二次增长。  
- **空间复杂度**：`O(n)` —— 只需要存放当前的数字列表（最多 `n` 个整数）。

### 2. 最优解

#### 思路  

从暴力解可以看到 **瓶颈在于每一次遍历都要重新生成整个列表**，这导致了 `O(n²)` 的时间。  
实际上，这个“相邻相加取个位”的过程恰好对应 **帕斯卡三角（二项式系数）** 的加权求和：

- 第一次操作把 `a[i]` 与 `a[i+1]` 相加；
- 第二次操作把第一次得到的结果再相邻相加；
- ……

等价于把原始的每一位 `a[i]` 乘以某个二项式系数，再把所有乘积求和（并在每一步都对 10 取模）。  
具体来说，设原始长度为 `n`，需要进行 `n‑2` 次操作。  
- 第 1 个最终数字 =  

  \[
  \sum_{i=0}^{n-2} \binom{n-2}{i}\;a_i \pmod{10}
  \]

- 第 2 个最终数字 =  

  \[
  \sum_{i=1}^{n-1} \binom{n-2}{i-1}\;a_i \pmod{10}
  \]

这里的 \(\binom{n-2}{i}\) 就是 **二项式系数**，它们可以一次性用 **帕斯卡三角** 直接算出整行（只需要 `n‑2`+1 个数），并且每一步都对 10 取模，避免大数溢出。

**核心技巧**：  
- **二项式系数**的递推公式：`C[i] = (C[i] + C[i-1]) % 10`（从左到右更新）  
- 只需要保留一行（长度 `n-1`），空间 `O(n)`，时间只遍历一次原始字符串，得到 `O(n)`。

**类比**：把原始数字看成调味料，二项式系数是不同的“勺子”。我们把每个数字倒进对应大小的勺子里，最后把所有勺子里的味道混合（取模 10），一次性得到答案。

#### 代码（Python）

```python
def checkIfEqual(s: str) -> bool:
    n = len(s)
    nums = [int(ch) for ch in s]          # 原始数字列表

    # 计算第 (n-2) 行的二项式系数（模 10），长度为 n-1
    # 初始化第一行：C[0] = 1，其他均为 0
    C = [0] * (n - 1)
    C[0] = 1                               # C(0,0) = 1

    # 逐行构造帕斯卡三角，直到第 (n-2) 行
    for _ in range(n - 2):
        # 从右往左更新，防止覆盖掉左侧尚未使用的值
        for i in range(len(C) - 1, 0, -1):
            C[i] = (C[i] + C[i - 1]) % 10   # C(i) = C(i) + C(i-1) (模10)

    # 第一个最终数字：系数对应到 nums[0 .. n-2]
    first = sum(C[i] * nums[i] for i in range(n - 1)) % 10

    # 第二个最终数字：系数整体左移一位，对应到 nums[1 .. n-1]
    second = sum(C[i] * nums[i + 1] for i in range(n - 1)) % 10

    return first == second
```

> **代码要点解释**  
> 1. `C` 列表始终保存当前帕斯卡行的系数，`%10` 保证每个系数始终在 0‑9 范围内。  
> 2. 外层循环执行 `n-2` 次，即得到第 `n-2` 行（因为第一次操作相当于第 1 行）。  
> 3. `first` 与 `second` 的计算分别对应两组相邻的原始数字，最终取模 10 即为题目要求的两位。

#### 复杂度

- **时间复杂度**：`O(n)` —— 只遍历一次字符串、一次构造二项式系数行，操作次数与 `n` 成线性关系。  
- **空间复杂度**：`O(n)` —— 需要保存一行二项式系数（长度 `n-1`）和原始数字列表。

相较于暴力的 `O(n²)`，这一步提升在 `n` 达到上限 100 时仍然不明显，但它展示了 **数学化简** 的思路，帮助我们在更大规模的数据上也能高效求解。

## 心得

- **核心技巧**：把“相邻相加取个位”的迭代过程映射为二项式系数的加权求和（帕斯卡三角），从而一次性得到最终结果。  
- **适用的题型**  
  1. “相邻运算”类的迭代题（如相邻取差、相邻取和后取模）。  
  2. 需要多次折叠（fold）数组/字符串，结果可以用组合数学表达的题目。  
  3. “Pascal Triangle Mod” 相关的数论或 combinatorial 问题。  
- **一句话总结**：**把连续的局部运算抽象为全局的组合加权，就能从 O(n²) 降到 O(n)。**

## 反思

- **第一反应**：直接把题目说的“相邻相加取个位”写成循环，逐步模拟——这就是暴力解。  
- **最容易踩的坑**  
  - 忘记对每一步的和取模 10，导致数字位数爆炸。  
  - 边界条件：字符串长度恰好为 3 时，只会进行一次运算，需要确保循环能够正常退出。  
  - 在实现二项式系数时，如果从左到右更新会把已经更新的值覆盖，导致系数错误；正确做法是 **从右往左** 更新。  
- **下次类似题**：第一步先问自己“这一次局部运算在多轮后会形成什么全局模式？”如果能写出数学表达式（比如二项式系数、前缀和、滑动窗口），就可以尝试直接计算而不是逐步模拟。
