## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把 **每个元素** 都和后面的所有元素两两比较，看看有没有相同的。如果出现相同的，就说明这两个位置中必须至少进行一次操作（把其中一个改成别的数），于是把需要操作的次数加一。  

- **使用的数据结构**：  
  - **数组** 本身就是我们遍历的对象。  
  - **计数器** 用来记录已经发现了多少次“重复”。可以把它想成一本笔记本，遇到一次重复就往上写一笔。  

- **为什么正确**：  
  - 只要数组里有两个相同的数，就一定要对其中的 **至少一个** 做一次操作，使它们不再相等。遍历所有配对能够把所有重复的情况全部找出来，计数的总和正好等于最少需要的操作次数（因为每次操作只能消除一种重复）。  

- **复杂度分析**：  
  - **时间复杂度**：我们用了两层循环，外层遍历 `n` 次，内层最多遍历 `n‑1` 次，所以大约要做 `n × n` 次比较，记作 **O(n²)**。这里的 “O” 只是一种上限的表示，实际意义是：如果数组长度是 100，最坏情况下要检查大约 10 000 次。  
  - **空间复杂度**：只用了常数个额外变量（计数器、索引），所以是 **O(1)**，即不随输入规模增长而增加额外空间。  

#### 代码（Python）

```python
def min_operations_bruteforce(nums):
    """
    暴力实现：两层循环逐对比较，统计出现的重复次数
    """
    n = len(nums)
    ops = 0                     # 记录需要的最少操作数
    for i in range(n):
        for j in range(i + 1, n):
            if nums[i] == nums[j]:
                # 发现一对相同的元素，说明至少要改动一次
                ops += 1
                # 为了避免同一对被多次计数，后面把后面的那个设成一个不可能出现的值
                # 这里使用 None（因为题目保证 nums[i] 为正整数）
                nums[j] = None
    return ops
```

#### 复杂度  

- **时间复杂度**：O(n²) — 两层循环导致比较次数随 `n` 的平方增长。  
- **空间复杂度**：O(1) — 只用了几个整型变量，没有额外的随 `n` 增长的存储。

### 2. 最优解  

#### 思路  

从暴力解可以看到，**瓶颈** 在于我们把每一对元素都比较了一遍，实际上只要知道 **每个数出现了多少次** 就够了。  

- **关键观察**：如果一个数出现了 `k` 次，只需要保留其中的 **1 次**，其余 `k‑1` 次都必须进行一次操作。  
- 因此，**最少操作数 = 数组长度 - 不同元素的个数**。  

要快速得到不同元素的个数，只需要把所有元素放进 **哈希表**（在 Python 中用 `set`），因为查找/插入的平均时间是 **O(1)**。可以把 `set` 想象成一本 **字典**：单词是数组里的数，页码是“是否出现过”。每遇到一个新数，就在字典里记一笔；如果已经记过了，就说明这是一条需要操作的“重复”。  

- **核心数据结构**：**集合（set）**  
  - 像查字典一样，`x in s` 能在常数时间判断 `x` 是否已经出现。  

- **步骤**  
  1. 建立一个空集合 `seen`。  
  2. 遍历数组 `nums`，把每个数加入 `seen`。  
  3. 遍历结束后，`len(seen)` 就是不同元素的个数。  
  4. 用 `len(nums) - len(seen)` 得到最少操作数。  

- **为什么最优**：  
  - 只遍历一次数组，时间是 **O(n)**。  
  - 只用了一个集合，额外空间是 **O(n)**（最坏情况每个数都不相同）。  

#### 代码（Python）

```python
def min_operations_optimal(nums):
    """
    最优实现：利用集合统计不同元素的个数
    """
    # 把所有元素放进集合，自动去重
    distinct = set(nums)          # O(n) 的时间，O(n) 的空间
    # 需要操作的次数 = 总数 - 不同数的个数
    return len(nums) - len(distinct)
```

#### 复杂度  

- **时间复杂度**：O(n) — 只遍历一次数组，集合的插入/查询均摊为常数时间。  
- **空间复杂度**：O(n) — 最坏情况下集合里要存放 `n` 个不同的数。

## 心得  

- **核心技巧**：利用 **哈希表（集合）** 快速去重，统计不同元素的个数。  
- **适用的题型**：  
  1. “统计数组中不同元素的个数”  
  2. “求最少删除/修改次数使数组满足某种唯一性要求”  
  3. “判断数组是否有重复元素”  
- **一句话总结解题钥匙**：**把“重复次数 = 总数 - 唯一数的个数”。**  

## 反思  

- **第一反应**：看到“让数组元素互不相同”，第一时间会想到“去重”。  
- **最容易踩的坑**：  
  - 忘记把 **空数组** 也算作已经满足条件，直接返回 0。  
  - 把 **操作次数** 误写成 “总增量” 或者 “需要删除的元素个数”。本题要求的是 **每一次改动**（把一个重复元素改成新值）计一次。  
- **下次遇到同类题**：第一步先思考 **“我需要知道每个数出现了几次吗？”**，如果只需要知道是否出现过，就立刻想到 **集合/哈希表**，从而把 O(n²) 的暴力思路压缩到 O(n)。
