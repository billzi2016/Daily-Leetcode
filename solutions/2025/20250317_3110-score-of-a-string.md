# #3110. 字符串得分 / Score of a String

> 难度：简单 · 标签：String · [LeetCode 链接](https://leetcode.com/problems/score-of-a-string/)

## 题目（英文原版）

**Description**

You are given a string s. The score of a string is defined as the sum of the absolute difference between the ASCII values of adjacent characters.
Return the score of s.

**Examples**

**Example 1:**

```
Input: s = "hello"
Output: 13
Explanation:
The ASCII values of the characters in s are: 'h' = 104 , 'e' = 101 , 'l' = 108 , 'o' = 111 . So, the score of s would be |104 - 101| + |101 - 108| + |108 - 108| + |108 - 111| = 3 + 7 + 0 + 3 = 13 .
```

**Example 2:**

```
Input: s = "zaz"
Output: 50
Explanation:
The ASCII values of the characters in s are: 'z' = 122 , 'a' = 97 . So, the score of s would be |122 - 97| + |97 - 122| = 25 + 25 = 50 .
```

**Constraints**

- 2 <= s.length <= 100
- s consists only of lowercase English letters.

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是把字符串里相邻的两个字符拿出来，求它们的 ASCII 码之差的绝对值，然后把所有这些差值加起来。  
- **数据结构**：只需要遍历字符串本身，不需要额外的容器。可以把字符串想象成一排排的信封，依次打开相邻的两封信，比较信封上的编号（ASCII 码），记下差距，最后把所有差距相加。  
- **正确性**：题目要求的“相邻字符的绝对差之和”正好对应我们每次只看一对相邻字符并累加它们的差值。遍历完整个字符串后，所有相邻对都被统计一次，答案自然正确。  
- **复杂度**：我们需要从第 0 位走到倒数第 2 位（因为要和后面的字符配对），每一步做一次常数时间的计算。所以时间是 **O(n)**（n 为字符串长度），空间只用到几个整数，**O(1)**。

> 大白话解释：  
> - **O(n)** 就是“跟字符个数成正比”。如果字符串长 10，算 10 次；长 100，算 100 次。  
> - **O(1)** 就是“占用的额外空间永远是固定的”，不管字符串多长，都只用几块小存储格。

#### 代码（Python）

```python
def scoreOfString(s: str) -> int:
    """
    直接遍历相邻字符，累加它们的 ASCII 差的绝对值
    """
    total = 0                         # 用来累计答案
    for i in range(len(s) - 1):       # 只遍历到倒数第二个字符
        diff = abs(ord(s[i]) - ord(s[i + 1]))   # ord() 把字符转成 ASCII 码，abs 求绝对值
        total += diff                 # 把这一次的差值加到总和里
    return total
```

#### 复杂度  

- **时间复杂度**：O(n) —— 需要遍历一次字符串，字符越多，工作量线性增长。  
- **空间复杂度**：O(1) —— 只使用了常数个整数变量，和字符串长度无关。

### 2. 最优解  

#### 思路  

虽然上面的“暴力”已经是线性时间、常数空间，但我们可以把代码写得更简洁、更具可读性。  
- **瓶颈**：遍历本身已经是最快的，没有可以再削减的循环次数。  
- **优化方向**：利用 Python 的 **内置函数** 与 **迭代器**，一次性把所有相邻字符配对，然后用 `sum` 把差值求和。这样代码更短，逻辑更清晰。  
- **核心技巧**：  
  1. **`zip`**：把两个序列“拉链”在一起。把原字符串 `s` 与去掉第一个字符的子串 `s[1:]` 拉在一起，就得到所有相邻字符对。可以把它想象成把两排信封错开一格后，对应位置的信封一起放进机器里比较。  
  2. **`ord`**：把字符转成 ASCII 码。  
  3. **`abs` + `sum`**：一次性把所有绝对差累加。

#### 代码（Python）

```python
def scoreOfString(s: str) -> int:
    """
    使用 zip 把相邻字符配对，再一次性求和。
    """
    # zip(s, s[1:]) 生成 (s[0], s[1]), (s[1], s[2]), ... 的迭代器
    return sum(abs(ord(a) - ord(b)) for a, b in zip(s, s[1:]))
```

#### 复杂度  

- **时间复杂度**：O(n) —— 仍然只遍历一次字符串，只是把遍历的写法换成了生成器表达式。  
- **空间复杂度**：O(1) —— `zip` 产生的是惰性迭代器，不会额外存储整个配对列表；只使用了常数级别的临时变量。

## 心得  

- **核心技巧**：利用 `zip` 把相邻元素配对，再用 `sum` 与 `abs(ord(...))` 一次性累计。  
- **适用题型**：  
  1. 需要对相邻元素做某种运算的题目（如相邻差、相邻乘积等）。  
  2. “滑动窗口大小为 2”的线性扫描问题。  
  3. 只要涉及**相邻元素配对**的字符串或数组题目。  
- **一句话总结**：**“相邻配对 → 逐对处理 → 一次求和”** 是这类题目的解题钥匙。

## 反思  

- **第一反应**：把字符逐个取出来，用 `ord` 转成 ASCII，算差值累加。  
- **最容易踩的坑**：  
  - 忘记取绝对值，导致正负抵消。  
  - 当字符串长度为 1 时（虽然本题不允许），会出现索引越界，需要提前判断。  
  - 把 `ord` 写在 `abs` 外面或写错顺序，导致类型错误。  
- **下次思路**：遇到“相邻”或“小窗口”时，第一步想到 **“用 zip 把相邻元素配对”**，随后决定是直接遍历还是用生成器表达式一次求和。
