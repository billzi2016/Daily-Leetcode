## 题目（中文翻译）

给定一个整数数组 `nums`、一个整数 `k` 和一个整数 `multiplier`。  
你需要对 `nums` 执行恰好 `k` 次操作。每一次操作的步骤如下：

1. 在当前数组中找到最小的元素。如果有多个最小元素，取下标最小的那个（即 **最小值‑下标对**）。
2. 将该元素乘以 `multiplier`，得到的新值替换原来的元素。

在完成所有 `k` 次操作后，返回表示数组最终状态的整数数组。

---

### 示例

#### 示例 1
**输入**  
`nums = [2,1,3,5,6]`, `k = 5`, `multiplier = 2`

**输出**  
`[8,4,6,5,6]`

**解释**  
- 第 1 次操作：最小元素是 `1`（下标 1），乘以 `2` → `2`，数组变为 `[2,2,3,5,6]`。  
- 第 2 次操作：最小元素是 `2`（下标 0），乘以 `2` → `4`，数组变为 `[4,2,3,5,6]`。  
- 第 3 次操作：最小元素是 `2`（下标 1），乘以 `2` → `4`，数组变为 `[4,4,3,5,6]`。  
- 第 4 次操作：最小元素是 `3`（下标 2），乘以 `2` → `6`，数组变为 `[4,4,6,5,6]`。  
- 第 5 次操作：最小元素是 `4`（下标 0），乘以 `2` → `8`，数组最终为 `[8,4,6,5,6]`。

#### 示例 2
**输入**  
`nums = [1,2]`, `k = 3`, `multiplier = 4`

**输出**  
`[16,8]`

**解释**  
- 第 1 次操作：最小元素 `1`（下标 0） → `4`，数组 `[4,2]`。  
- 第 2 次操作：最小元素 `2`（下标 1） → `8`，数组 `[4,8]`。  
- 第 3 次操作：最小元素 `4`（下标 0） → `16`，数组 `[16,8]`。

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

题目要求对数组 `nums` 进行 `k` 次操作，每一次都把 **当前最小的那个数** 乘以 `multiplier`，并把结果写回原位置。  
最直接的想法就是：

1. **遍历** `nums` 找到最小值及其下标（相当于在一堆数里“挑最小的”——就像在超市里挑最便宜的商品）。  
2. 把找到的那个数乘以 `multiplier`，写回原数组。  
3. 重复上面两步 `k` 次。

因为每一步都要 **线性扫描** 整个数组来找最小值，这就是最笨的做法，但思路最清晰，容易实现。

> **为什么正确？**  
> 每一次我们都把当前最小的数乘以 `multiplier`，这正是题目要求的操作顺序。只要我们每次都准确找到最小值并更新，最终得到的数组必然是题目所求的“最终状态”。

> **时间/空间分析（大白话）**  
> - **时间复杂度**：每一次操作我们都要遍历一次长度为 `n` 的数组来找最小值，`k` 次操作就要 `k·n` 次遍历。用数学符号写成 `O(k·n)`。如果把 `k` 看成常数（本题最多 10），这相当于“每次都把所有东西都检查一遍”。  
> - **空间复杂度**：只用了几个临时变量（最小值、下标），不需要额外的数组或容器，空间是 `O(1)`——常数级的内存。

#### 代码（Python）

```python
def finalArray(nums, k, multiplier):
    n = len(nums)                 # 数组长度
    for _ in range(k):            # 重复 k 次
        # 1️⃣ 找到当前最小的数和它的下标
        min_val = float('inf')    # 先设一个很大的数
        min_idx = -1
        for i in range(n):        # 线性扫描整个数组
            if nums[i] < min_val: # 发现更小的就更新
                min_val = nums[i]
                min_idx = i

        # 2️⃣ 把找到的数乘以 multiplier，写回原位置
        nums[min_idx] = min_val * multiplier

    return nums                    # 最终数组即为答案
```

#### 复杂度  

- **时间复杂度**：`O(k·n)`  
  - 解释：如果 `n = 100，k = 10`，最坏情况下要比较 1000 次，仍然可以接受。  
- **空间复杂度**：`O(1)`  
  - 解释：只用了几个整数变量，和输入规模无关。

### 2. 最优解  

#### 思路  

暴力解的瓶颈在 **每一次都要遍历整个数组** 去找最小值，这一步的时间是 `O(n)`。  
如果我们能把“找最小值”这一步的代价降到 **对数级**（`O(log n)`），整体就会更快。  

**关键工具：最小堆（Min‑Heap）**  

- 堆是一种特殊的完全二叉树，根节点总是**最小（或最大）**的元素。  
- Python 的 `heapq` 模块实现了最小堆，支持 `heappush`（插入）和 `heappop`（弹出最小）这两个操作，时间都是 `O(log n)`。  

**实现步骤**  

1. **把每个元素连同它的下标一起放进堆**。  
   - 这里使用二元组 `(value, index)`，堆会先比较 `value`（因为它是第一个字段），相同值时再比较 `index`，保证唯一性。  
   - 把下标也放进去的原因是：后面我们要把乘积写回原数组，需要知道它在原数组中的位置。  

2. 重复 `k` 次：  
   - 用 `heappop` 取出当前最小的 `(value, idx)`，这一步只要 `O(log n)`。  
   - 计算 `new_val = value * multiplier`，写回 `nums[idx]`。  
   - 把更新后的 `(new_val, idx)` 再 **push** 回堆，保持堆的完整性。  

3. 循环结束后，`nums` 已经是最终状态，直接返回。

> **为什么正确？**  
> 堆始终保存了“每个位置最新的数值”。每一次 `heappop` 取出的正是当前数组中的最小值，乘完再放回堆，相当于在数组里完成了一次乘法并更新了 “最小值的候选”。所以整个过程与题目描述完全一致。

> **时间/空间分析（大白话）**  
> - **时间复杂度**：初始化堆需要把 `n` 个元素放进去，`O(n)`（实际是 `O(n)` 的 `heapify`，更快）。随后每一次操作弹出+插入都是 `O(log n)`，共 `k` 次，所以整体是 `O(n + k·log n)`。  
>   - 对比暴力的 `O(k·n)`，如果 `n` 较大（本题不大，但这种思路在更大数据时优势明显），对数级的操作会快很多。  
> - **空间复杂度**：堆里保存 `n` 个二元组，需要 `O(n)` 的额外空间。除此之外只用了常数级的临时变量。  

#### 代码（Python）

```python
import heapq

def finalArray(nums, k, multiplier):
    # 1️⃣ 把 (value, index) 放进最小堆，heapify 一次即可完成建堆
    heap = [(val, idx) for idx, val in enumerate(nums)]
    heapq.heapify(heap)                 # O(n)

    # 2️⃣ 进行 k 次乘法操作
    for _ in range(k):
        # 取出当前最小的数及其下标
        val, idx = heapq.heappop(heap)  # O(log n)

        # 计算新的值并写回原数组
        new_val = val * multiplier
        nums[idx] = new_val

        # 把更新后的 (new_val, idx) 再放回堆中
        heapq.heappush(heap, (new_val, idx))  # O(log n)

    return nums
```

#### 复杂度  

- **时间复杂度**：`O(n + k·log n)`  
  - 解释：`n` 最多 100，`k` 最多 10，实际运行非常快。  
- **空间复杂度**：`O(n)`  
  - 解释：需要额外的堆来存放 `n` 个 `(value, index)` 对。

## 心得  

- **核心技巧**：使用 **最小堆（Priority Queue）** 动态维护“当前最小元素”。  
- **适用的题型**：  
  1. “每次取最小/最大元素并更新”的模拟题，如 **K 次取最小数并加倍**、**K 次取最大数并减半**。  
  2. “合并最小的两个数” 类的题目，如 **最小代价合并石子**（LeetCode 1000）或 **连接 ropes**。  
  3. “实时获取窗口最小值/最大值” 的滑动窗口问题（使用单调队列或堆实现）。  
- **一句话总结解题钥匙**：**把“找最小值”交给堆，让它帮你在 O(log n) 时间内完成**。

## 反思  

- **第一反应**：看到“每次都对最小元素做乘法”，立刻想到 **先排序或每次遍历找最小**。  
- **最容易踩的坑**：  
  - **忘记把下标一起放进堆**，导致乘完后找不到该更新回原数组的正确位置。  
  - **堆里存的是旧值**：每次弹出后必须把 **新值** 再压回堆，否则后面的操作会继续使用已经被修改的旧值。  
  - **边界条件**：`k` 可能大于数组长度，仍然要每次都取最小的（可能是同一个位置多次被乘）。  
- **下次类似题的第一步**：**判断是否需要频繁取极值**，如果是，就立刻想到使用 **堆**（或单调队列）来维护。
