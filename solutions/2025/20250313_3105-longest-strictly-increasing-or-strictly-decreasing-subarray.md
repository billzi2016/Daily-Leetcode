# #3105. 最长严格递增或严格递减子数组 / Longest Strictly Increasing or Strictly Decreasing Subarray

> 难度：简单 · 标签：Array · [LeetCode 链接](https://leetcode.com/problems/longest-strictly-increasing-or-strictly-decreasing-subarray/)

---

## 题目（英文原版）

**Description**

You are given an array of integers nums. Return the length of the longest subarray of nums which is either strictly increasing or strictly decreasing.

**Examples**

**Example 1:**

```
Input: nums = [1,4,3,3,2]
Output: 2
Explanation:
The strictly increasing subarrays of nums are [1] , [2] , [3] , [3] , [4] , and [1,4] .
The strictly decreasing subarrays of nums are [1] , [2] , [3] , [3] , [4] , [3,2] , and [4,3] .
Hence, we return 2 .
```

**Example 2:**

```
Input: nums = [3,3,3,3]
Output: 1
Explanation:
The strictly increasing subarrays of nums are [3] , [3] , [3] , and [3] .
The strictly decreasing subarrays of nums are [3] , [3] , [3] , and [3] .
Hence, we return 1 .
```

**Example 3:**

```
Input: nums = [3,2,1]
Output: 3
Explanation:
The strictly increasing subarrays of nums are [3] , [2] , and [1] .
The strictly decreasing subarrays of nums are [3] , [2] , [1] , [3,2] , [2,1] , and [3,2,1] .
Hence, we return 3 .
```

**Constraints**

- 1 <= nums.length <= 50
- 1 <= nums[i] <= 50

## 题目（中文翻译）

给定一个整数数组 `nums`，返回 `nums` 中**最长**的子数组（subarray）长度，该子数组要么是**严格递增**（strictly increasing），要么是**严格递减**（strictly decreasing）。

## 示例

### 示例 1
**输入**  
`nums = [1,4,3,3,2]`

**输出**  
`2`

**解释**  
- 严格递增的子数组有 `[1]`、`[2]`、`[3]`、`[3]`、`[4]` 以及 `[1,4]`。  
- 严格递减的子数组有 `[1]`、`[2]`、`[3]`、`[3]`、`[4]`、`[3,2]` 和 `[4,3]`。  
因此最长的满足条件的子数组长度为 `2`。

### 示例 2
**输入**  
`nums = [3,3,3,3]`

**输出**  
`1`

**解释**  
- 严格递增的子数组只有单个元素 `[3]`（出现四次）。  
- 严格递减的子数组同样只有单个元素 `[3]`（出现四次）。  
最长的满足条件的子数组长度为 `1`。

### 示例 3
**输入**  
`nums = [3,2,1]`

**输出**  
`3`

**解释**  
- 严格递增的子数组只有单个元素 `[3]`、`[2]`、`[1]`。  
- 严格递减的子数组包括 `[3]`、`[2]`、`[1]`、`[3,2]`、`[2,1]`、以及 `[3,2,1]`。  
最长的满足条件的子数组长度为 `3`。

## 约束条件
- `1 <= nums.length <= 50`
- `1 <= nums[i] <= 50`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**枚举所有可能的子数组**，判断它是严格递增还是严格递减，记录最长的长度。

- **子数组**：在数组里选一段连续的元素，就像把一根绳子剪成若干段，每段都是子数组。  
- **枚举子数组**：我们可以用两个指针 `i`、`j`（`i ≤ j`）分别表示子数组的左端点和右端点，遍历所有 `(i, j)` 组合。  
- **判断递增/递减**：遍历子数组内部的相邻元素，检查每一对是否满足 `nums[k] < nums[k+1]`（严格递增）或 `nums[k] > nums[k+1]`（严格递减）。如果在遍历过程中出现相等或方向相反，就说明这段子数组不满足要求。

为什么这方法一定能得到答案？因为我们把**所有**合法的子数组都检查了一遍，最长的自然会被记录下来。

**复杂度分析（大白话）**  
- 外层有 `n`（数组长度）个起点 `i`，每个起点又要遍历 `n` 个终点 `j`，所以大约要检查 `n × n = n²` 次子数组。  
- 对每个子数组，我们还要再遍历一次它的长度（最坏情况是 `n`），于是整体时间复杂度是 **O(n³)**。不过因为 `n ≤ 50`，我们可以稍微优化一下：在检查子数组时，一旦发现不满足递增/递减，就可以提前结束，这样实际运行时间会更好，但仍然是 **O(n²)** 级别的。

空间上我们只用了几个整型变量来保存下标和计数，**O(1)**（常数）空间。

#### 代码（Python）

```python
def longest_strict_subarray_bruteforce(nums):
    n = len(nums)
    best = 1                     # 至少有长度为 1 的子数组
    # i 为子数组左端点
    for i in range(n):
        # j 为子数组右端点（包含 i 本身）
        for j in range(i, n):
            # 检查子数组 nums[i:j+1] 是否严格递增或严格递减
            inc = True            # 假设是递增
            dec = True            # 假设是递减
            # k 遍历子数组内部的相邻元素
            for k in range(i, j):
                if nums[k] >= nums[k + 1]:   # 递增要求严格小于
                    inc = False
                if nums[k] <= nums[k + 1]:   # 递减要求严格大于
                    dec = False
                # 两种情况都不可能了，直接退出内层循环
                if not inc and not dec:
                    break
            # 如果任意一种成立，更新答案
            if inc or dec:
                best = max(best, j - i + 1)
    return best
```

#### 复杂度

- **时间复杂度**：`O(n²)`（在最坏情况下，每个子数组都要遍历一次内部元素）。  
  大白话：如果数组有 1000 个元素，算法大概会执行 1,000,000 次左右的比较，随着 `n` 增大，运行时间会呈二次方增长。
- **空间复杂度**：`O(1)`，只用了常数个变量。

### 2. 最优解

#### 思路  

从暴力解可以看到，**瓶颈**在于我们不断地重复比较相同的相邻元素。实际上，只要一次遍历就能知道每个位置向左（或向右）能形成的最长递增或递减子数组的长度。

**核心想法**：  
- 当我们从左到右扫过数组时，**只需要记录当前递增（或递减）序列的长度**。如果下一个元素继续保持严格递增，就把长度加 1；否则，重新从 1 开始计数。  
- 同理，对递减序列也可以用同样的方式维护。  
- 在遍历的过程中，随时把“递增长度”和“递减长度”两者的最大值保存下来，即为答案。

这就是典型的 **一次遍历 + 计数器** 思路，类似于“滑动窗口”但窗口大小不是固定的，只要序列保持单调就不断扩大。

**为什么一次遍历就够了？**  
因为判断一个子数组是否严格递增，只需要检查相邻元素的大小关系。如果我们已经知道 `nums[i-1] < nums[i]` 成立，那么以 `i-1` 结尾的最长递增子数组长度 `inc_len` 已经是已知的。若 `nums[i] < nums[i+1]` 仍然成立，则以 `i` 结尾的最长递增子数组长度就是 `inc_len + 1`。这是一种**递推**关系，避免了重复检查。

**类比**：把数组想象成一条山路，走路时只要前面一直是上坡（递增）或一直是下坡（递减），我们就可以一直往前走；一旦坡度方向改变，就得重新计数从头开始。

#### 代码（Python）

```python
def longest_strict_subarray(nums):
    """
    一次遍历求最长严格递增或递减子数组的长度。
    """
    n = len(nums)
    if n == 0:
        return 0

    # 当前递增子数组的长度，初始为 1（单个元素始终算作递增/递减）
    inc_len = dec_len = 1
    # 记录全局最长长度
    ans = 1

    # 从第二个元素开始向右遍历
    for i in range(1, n):
        # 判断是否继续递增
        if nums[i - 1] < nums[i]:
            inc_len += 1          # 递增长度加 1
        else:
            inc_len = 1           # 方向不对，重新计数

        # 判断是否继续递减
        if nums[i - 1] > nums[i]:
            dec_len += 1          # 递减长度加 1
        else:
            dec_len = 1           # 方向不对，重新计数

        # 更新全局最大值
        ans = max(ans, inc_len, dec_len)

    return ans
```

#### 复杂度

- **时间复杂度**：`O(n)`，只遍历一次数组。  
  大白话：如果数组长度是 10,000，只需要做 10,000 次比较，几乎是线性增长，随 `n` 增大，运行时间几乎和 `n` 成正比。
- **空间复杂度**：`O(1)`，只用了几个计数变量，不随输入规模增长。

## 心得

- **核心技巧**：一次遍历维护**单调计数器**（递增计数器 & 递减计数器），利用相邻元素的比较实现递推。
- **适用的题型**：  
  1. “最长连续递增/递减子序列” 类问题（例如 LeetCode 674 `Longest Continuous Increasing Subarray`）。  
  2. “最长连续相同元素子数组” 这类只需要比较相邻关系的题目。  
  3. “连续子数组满足某种单调条件” 的滑动窗口变形。
- **一句话总结解题钥匙**：**“把局部的单调信息保存下来，遇到符合条件就延伸，不符合就重新计数”。**

---

## 反思

- **第一反应**：先想到枚举所有子数组（暴力），因为最直接、最安全。  
- **最容易踩的坑**：  
  - 忽略**严格**的要求，导致使用 `<=` 或 `>=` 错误。  
  - 边界条件：数组长度为 1 时，答案应为 1。  
  - 在计数器复位时忘记把长度重置为 1（单个元素本身算作合法子数组）。  
- **下次遇到同类题**：第一步先**检查相邻元素的关系**，思考是否可以用“计数器 + 递推”把问题压缩到一次遍历，而不是直接枚举。这样往往能立刻得到 O(n) 的最优解。
