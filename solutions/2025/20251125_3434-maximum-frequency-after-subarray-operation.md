# #3434. 子数组操作后的最大频率 / Maximum Frequency After Subarray Operation

> 难度：中等 · 标签：Array、Hash Table、Dynamic Programming、Greedy、Enumeration、Prefix Sum · [LeetCode 链接](https://leetcode.com/problems/maximum-frequency-after-subarray-operation/)

---

## 题目（英文原版）

**Description**

You are given an array nums of length n. You are also given an integer k.
You perform the following operation on nums once:
Find the maximum frequency of the value k after the operation.

**Examples**

**Example 1:**

```
Input: nums = [1,2,3,4,5,6], k = 1
Output: 2
Explanation:
After adding -5 to nums[2..5] , 1 has a frequency of 2 in [1, 2, -2, -1, 0, 1] .
```

**Example 2:**

```
Input: nums = [10,2,3,4,5,5,4,3,2,2], k = 10
Output: 4
Explanation:
After adding 8 to nums[1..9] , 10 has a frequency of 4 in [10, 10, 11, 12, 13, 13, 12, 11, 10, 10] .
```

**Constraints**

- 1 <= n == nums.length <= 105
- 1 <= nums[i] <= 50
- 1 <= k <= 50

---

## 题目（中文翻译）

给定一个长度为 `n` 的数组 `nums`，以及一个整数 `k`。  
你可以对 `nums` 执行一次如下操作：

- 选择一个子数组（subarray）`nums[l..r]`，对其中的每个元素都加上同一个整数 `x`（`x` 可以为正、负或零）。

在完成一次操作后，求值为 `k` 的元素的最大出现次数（频率）。

---

## 示例

### 示例 1
**输入**  
`nums = [1,2,3,4,5,6], k = 1`

**输出**  
`2`

**解释**  
将 `-5` 加到子数组 `nums[2..5]`，得到 `[1, 2, -2, -1, 0, 1]`，此时 `1` 的频率为 `2`。

**输出**  
`4`

**解释**  
将 `8` 加到子数组 `nums[1..9]`，得到 `[10, 10, 11, 12, 13, 13, 12, 11, 10, 10]`，此时 `10` 的频率为 `4`。

- `1 <= k <= 50`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是 **枚举所有可能的操作**，然后统计操作后 `k` 出现的次数，取最大值。  
一次操作由两部分决定：

1. **选取子数组**：下标区间 `[l, r]`（`0 ≤ l ≤ r < n`），相当于在生活中「挑选一段连续的路段」。
2. **选取要加的整数 `d`**：把这段路上的所有数字都加上同一个 `d`，就像在这段路上统一「升高」或「降低」相同的海拔。

对于固定的 `[l, r]` 与 `d`，我们只需要遍历整个数组，检查每个位置 `i`：

- 如果 `i` 在子数组内，则新的值为 `nums[i] + d`。
- 否则保持不变 `nums[i]`。

随后统计新数组中等于 `k` 的元素个数，即为这次操作的 **频率**。

因为我们要找的是 **最大频率**，所以要把所有可能的 `[l, r]` 与 `d` 都尝试一遍，取最大值即可。

> **为什么暴力一定能得到正确答案？**  
> 暴力把所有合法的操作全部枚举完了，答案必然在其中。只要实现没有遗漏，就一定正确。

#### 代码（Python）

```python
def maxFrequency_bruteforce(nums, k):
    n = len(nums)
    best = 0                               # 记录最大的频率
    # 枚举子数组的左端点
    for l in range(n):
        # 枚举子数组的右端点
        for r in range(l, n):
            # 子数组里所有数需要加的 d，使得某个位置 i 变成 k
            # 为了覆盖所有可能，这里把 d 取遍 [-50, 50]（题目里数值 ≤ 50）
            for d in range(-50, 51):
                cnt = 0                     # 统计本次操作后 k 的个数
                for i in range(n):
                    val = nums[i] + d if l <= i <= r else nums[i]
                    if val == k:
                        cnt += 1
                best = max(best, cnt)      # 更新全局最大
    return best
```

> **关键行解释**  
> - `for l in range(n)`、`for r in range(l, n)`：遍历所有连续子数组。  
> - `for d in range(-50, 51)`：因为 `nums[i]` 与 `k` 的范围都在 `[1, 50]`，所以 `d` 只需要在 `[-50, 50]` 之间尝试即可。  
> - `val = nums[i] + d if l <= i <= r else nums[i]`：模拟一次完整的操作。  

#### 复杂度

- **时间复杂度**：`O(n³ * R)`，其中 `R` 为可能的 `d` 的取值数（这里是 101），因为要三层循环遍历左端点、右端点、以及每个 `d`，每次还要再遍历整个数组统计频率。  
  - 用大白话说：如果数组有 10⁵ 长，暴力需要 **上百亿次**的计算，根本跑不动。  
- **空间复杂度**：`O(1)`，只用了常数级别的额外变量。

### 2. 最优解

#### 思路  

从暴力解可以看到，**枚举所有子数组和所有 `d` 是最耗时的**。我们要找出导致慢的**瓶颈**，并逐步优化。

1. **观察 `d` 的本质**  
   对于任意位置 `i`，若想让它在操作后等于 `k`，必须满足  

   \[
   nums[i] + d = k \quad\Longrightarrow\quad d = k - nums[i]
   \]

   这说明 **每个元素想要变成 `k` 所需的 `d` 是唯一确定的**，它只跟元素本身的原始值有关。  
   换句话说，如果我们决定把子数组整体加上 `d`，那么只能把 **所有原本等于同一个数 `v`** 的元素一起变成 `k`（因为它们的 `d` 相同）。

2. **把问题转化为“挑选一个数 `v` 并找一段不含 `k` 的子数组”**  

   - 若子数组里出现了原本已经是 `k` 的元素，它们会被加上 `d`，结果不再是 `k`，反而会 **降低** 频率。  
   - 因此，**当我们选择把值 `v`（`v ≠ k`）变成 `k` 时，子数组里必须 **不包含任何原始的 `k`**。  
   - 只要子数组不含 `k`，我们可以随意加入其他不等于 `v` 的数，它们不会产生额外的 `k`，也不会影响已经是 `k` 的元素（因为它们都在子数组外）。

3. **最终频率的表达式**  

   - `total_k`：原数组中 `k` 的总个数（这些 `k` 永远保留在最终数组里，因为我们可以把子数组选在不含它们的地方）。
   - 对每个可能的 `v (1 ≤ v ≤ 50, v ≠ k)`，我们要找 **在不含 `k` 的连续段里，`v` 出现的最多次数**，记为 `best_v`。  
   - 把这段子数组加上 `d = k - v`，所有 `v` 都会变成 `k`，于是最终频率 = `total_k + best_v`。  
   - 取所有 `v` 中的最大值，再和仅保留原始 `k`（即 `total_k`）比较，答案就是  

   \[
   \text{ans} = \max\bigl( total_k,\; total_k + \max_{v \neq k} best_v \bigr)
   \]

4. **如何高效求 `best_v`**  

   由于数值范围只有 `1~50`，我们可以 **一次遍历数组**，把数组切成若干段，每段之间被 `k` 隔开。  
   对每段内部：

   - 用一个长度为 `51` 的计数数组 `cnt[value]` 统计该段里每个数出现的次数。  
   - 只要遍历到一个 `k`，就 **重置计数**（因为新段开始了）。  
   - 在遍历的过程中维护当前段里出现次数最多的数 `cur_max`，并用全局变量 `global_max` 保存所有段的最大值。

   这一步只需要 **O(n)** 的时间和 **O(1)**（因为计数数组大小固定）的额外空间。

5. **完整算法概览**

   1. 统计 `total_k`。  
   2. 初始化 `global_max = 0`、`cnt = [0]*51`。  
   3. 从左到右遍历 `nums`：  
      - 若当前元素是 `k`：清空 `cnt`（`cnt = [0]*51`），继续。  
      - 否则：`cnt[nums[i]] += 1`，更新 `global_max = max(global_max, cnt[nums[i]])`。  
   4. 返回 `max(total_k, total_k + global_max)`。

   这样我们只用了两次线性扫描，时间上从 **指数级** 降到了 **线性级**。

#### 代码（Python）

```python
def maxFrequency(nums, k):
    """
    返回在一次子数组加同一个整数的操作后，数组中 k 的最大出现次数。
    思路：统计所有不含 k 的连续段里，出现次数最多的非 k 元素。
    """
    n = len(nums)
    total_k = nums.count(k)          # 原始 k 的个数

    # cnt[v] 记录当前段（自上一次出现 k 之后）里数值 v 的出现次数
    cnt = [0] * 51                    # 题目限制 nums[i]、k ≤ 50，索引直接用值
    best_inside = 0                   # 当前段里出现次数最多的非 k 元素

    for x in nums:
        if x == k:                    # 遇到 k，当前段结束，计数数组清零
            cnt = [0] * 51
            continue
        cnt[x] += 1                   # 统计该值出现一次
        # 更新当前段的最大出现次数
        if cnt[x] > best_inside:
            best_inside = cnt[x]

    # 最终答案：保留原有的 k，或者再加上段内最多的非 k 元素
    return max(total_k, total_k + best_inside)
```

> **关键行解释**  
> - `total_k = nums.count(k)`：直接得到原数组里 `k` 的数量。  
> - `if x == k: cnt = [0] * 51`：遇到 `k` 相当于“把路段切断”，后面的统计只针对新段。  
> - `cnt[x] += 1` 与 `best_inside = max(best_inside, cnt[x])`：在同一段里实时维护出现次数最多的数。  

#### 复杂度

- **时间复杂度**：`O(n)`，只遍历一次数组。  
  - 与暴力的 `O(n³)` 相比，**快了几百亿倍**，在 `n = 10⁵` 时轻松跑完。  
- **空间复杂度**：`O(1)`（计数数组大小固定为 51），不随 `n` 增长。

## 心得

- **核心技巧**：**把“统一加同一个数”转化为“选择一个原始值 `v` 并在不含 `k` 的段里统计其出现次数”。**  
- **适用场景**：  
  1. **子数组统一加/减**，需要让若干元素达到同一个目标值（如 “把若干数字统一变为 0”）。  
  2. **只能一次操作**，且操作对整个子数组施加相同的变换（如 “一次翻转子数组”）。  
  3. **值域有限**（如 `1~50`、`0~100`）时，可利用固定大小的计数数组或哈希表实现 O(1) 额外空间。  
- **一句话总结解题钥匙**：**“先把原本的 k 当作墙，把数组切成若干段，只在每段内部找出现次数最多的其他数字”。**

## 反思

- **第一反应**：看到“一次子数组加同一个整数”，自然想到枚举子数组和加的数——这就是暴力解。  
- **最容易踩的坑**  
  1. **忘记排除子数组里原本的 `k`**：如果子数组包含 `k`，加上 `d` 会把它们变成别的数，导致频率下降。  
  2. **没有利用数值范围的限制**：题目给出 `nums[i] ≤ 50`，若不利用这点会错失 O(1) 计数数组的机会。  
  3. **边界情况**：整个数组全是 `k`（答案就是 `n`），或数组里根本没有 `k`（此时 `total_k = 0`，答案等于某段里出现次数最多的数）。  
- **下次类似题目第一步**：**把“一次全局相同的操作”拆解成“每个元素需要的唯一增量”，再检查哪些元素可以共享同一个增量，从而把子数组的选择限制在不含冲突元素的连续段**。这样往往能快速从暴力想到线性或准线性解法。
