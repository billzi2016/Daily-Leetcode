# #3287. 数组的最大序列值 / Find the Maximum Sequence Value of Array

## 题目（英文原版）

**Description**

You are given an integer array nums and a positive integer k.
The value of a sequence seq of size 2 * x is defined as:
Return the maximum value of any subsequence of nums having size 2 * k.

**Examples**

**Example 1:**

```
Input: nums = [2,6,7], k = 1
Output: 5
Explanation:
The subsequence [2, 7] has the maximum value of 2 XOR 7 = 5 .
```

**Example 2:**

```
Input: nums = [4,2,5,6,7], k = 2
Output: 2
Explanation:
The subsequence [4, 5, 6, 7] has the maximum value of (4 OR 5) XOR (6 OR 7) = 2 .
```

**Constraints**

- 2 <= nums.length <= 400
- 1 <= nums[i] < 27
- 1 <= k <= nums.length / 2

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把 **所有** 长度为 `2·k` 的子序列都枚举一遍，随后把每个子序列分成前 `k` 个数和后 `k` 个数，分别求它们的按位 **或**（OR），再把这两个 OR 的结果做 **异或**（XOR），取最大的那个。

- **子序列**：保持原数组相对顺序，只是把不需要的元素删掉。  
- **组合**：枚举子序列相当于在 `n` 个位置中挑 `2·k` 个位置，数学上记作 `C(n, 2k)`（“从 n 中选 2k”）。  
- **按位或 / 异或**：把每个数看成二进制位的集合，`a OR b` 就是把两者的 1 位都保留下来，`a XOR b` 则是只保留恰好出现一次的 1 位。

> **类比**：把数组想象成一本书的章节，子序列就是在不改变章节顺序的前提下挑选出若干章节；`OR` 像是把挑选章节里出现的所有关键词合并，`XOR` 则是找出只在其中一个关键词集合出现的词。

只要把每一种挑选方式算出来，取最大值就是答案——这就是暴力解。

#### 代码（Python）

```python
from itertools import combinations
from typing import List

def max_sequence_value_bruteforce(nums: List[int], k: int) -> int:
    n = len(nums)
    best = 0

    # 选出所有长度为 2*k 的下标组合（保持顺序）
    for idxs in combinations(range(n), 2 * k):
        # 前 k 个下标对应左半段，后 k 个对应右半段
        left_or = 0
        for i in idxs[:k]:
            left_or |= nums[i]          # 按位或

        right_or = 0
        for i in idxs[k:]:
            right_or |= nums[i]         # 按位或

        best = max(best, left_or ^ right_or)   # 异或后取最大
    return best
```

> **关键行中文注释**  
> - `combinations(range(n), 2 * k)`: 把所有可能的 `2·k` 个位置枚举出来。  
> - `left_or |= nums[i]`: 把左半段的数逐个做 **或**，`|=` 相当于 “左边的结果再加上这个数的 1 位”。  
> - `left_or ^ right_or`: 把左、右两段的 **或** 结果再做 **异或**，`^` 表示 “只保留恰好出现一次的 1 位”。  

#### 复杂度  

- **时间复杂度**：`O(C(n, 2k) * k)`  
  - `C(n, 2k)` 是组合数，表示要枚举多少种子序列。  
  - 对每一种子序列我们要遍历 `2k` 个元素计算 OR，故乘以 `k`（常数因子）。  
  - 对于 `n = 20, k = 5` 这样的规模已经是 **几千万次**的循环，远远超出 1 秒的限制。  
- **空间复杂度**：`O(1)`（只用了常数级别的临时变量）

> **大白话**：时间复杂度里的 `O` 符号只是一种“量级”标记，`C(n, 2k)` 其实是指数级增长，`n` 增加一点点，枚举的次数就会爆炸式增长。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **枚举所有子序列**。我们注意到，子序列的价值只和两段 **各自的 OR** 有关，而 **每段内部的顺序并不影响 OR**（因为 OR 是交换律、结合律的）。因此我们可以把问题拆成两步：

1. **先算出**：从左到右，任选 `j`（`1 ≤ j ≤ k`）个数且**以第 i 个数结尾**的子序列，它们的 OR 最大可能是多少。记作 `L[i][j]`。  
2. **再算出**：从右到左，任选 `j`（`1 ≤ j ≤ k`）个数且**以第 i 个数开头**的子序列，它们的 OR 最大可能是多少。记作 `R[i][j]`。  

有了 `L` 和 `R`，答案只需要在所有可能的“分界点” `i`（左段最后一个元素所在位置）上尝试：

```
ans = max_{i}   ( L[i][k]  XOR  R[i+1][k] )
```

因为左段的所有元素都在位置 `i` 之前，右段的所有元素都在 `i+1` 之后，天然满足子序列的顺序要求。

---

##### 2.1 如何求 `L[i][j]`？

`L[i][j]` 的定义是：在前 `i` 个数里挑 `j` 个，以第 `i` 个数 **作为第 j 个**（即最后一个）时，能得到的最大 OR。  

- 当 `j = 1` 时，显然只能只选第 `i` 个数本身，`L[i][1] = nums[i]`。  
- 当 `j > 1` 时，前 `j-1` 个数必须在 `i` 之前的某个位置 `p (p < i)` 完成。此时我们已经知道 `L[p][j-1]`（即前 `j-1` 个数的最大 OR），再把第 `i` 个数 **或** 进去即可：

```
L[i][j] = max_{p < i} ( L[p][j-1]  OR  nums[i] )
```

这就是一个 **二维动态规划**（DP）公式。我们把所有 `i` 按从左到右的顺序遍历，内部再遍历所有可能的前驱 `p`，于是可以逐步填表。

> **类比**：想象你在做 “挑选 k 本书的阅读清单”。`L[i][j]` 记录的是：**如果第 j 本书必须是第 i 本**，那么这 j 本书里出现过的所有关键词（OR）的集合最多能有多少。我们只需要把第 i 本书的关键词加入之前已经挑好的 `j‑1` 本书的关键词集合里，取最大的结果即可。

---

##### 2.2 如何求 `R[i][j]`？

右侧的 DP 与左侧完全对称，只是遍历方向相反：

- `R[i][1] = nums[i]`（只挑第 i 本书）  
- `R[i][j] = max_{p > i} ( R[p][j-1]  OR  nums[i] )`  

这里 `p` 必须在 `i` 的右边，因为右段的顺序要保持 **从左到右**（即在原数组中先出现的数在左，后出现的在右），我们在逆序遍历时自然满足这一点。

---

##### 2.3 综合答案

遍历所有可能的“分界点” `i`（`0 ≤ i < n-1`），只要 `L[i][k]` 和 `R[i+1][k]` 都是合法（即不为 `-1`），就计算它们的 XOR 并取最大。

---

#### 代码（Python）

```python
from typing import List

def max_sequence_value(nums: List[int], k: int) -> int:
    n = len(nums)
    # 用 -1 表示「不存在」的状态
    L = [[-1] * (k + 1) for _ in range(n)]   # L[i][j]：以 i 为第 j 个元素的最大 OR
    R = [[-1] * (k + 1) for _ in range(n)]   # R[i][j]：以 i 为第 1 个元素的最大 OR（从右往左）

    # ---------- 左侧 DP ----------
    for i in range(n):
        L[i][1] = nums[i]                     # 基础情况：只选自己
        for j in range(2, k + 1):              # 需要选 j 个
            best = -1
            # 前一个元素必须在 i 左侧
            for p in range(i):
                if L[p][j - 1] != -1:          # 前面真的能选出 j-1 个
                    cand = L[p][j - 1] | nums[i]   # 取 OR
                    if cand > best:
                        best = cand
            L[i][j] = best

    # ---------- 右侧 DP（逆序） ----------
    for i in range(n - 1, -1, -1):
        R[i][1] = nums[i]                     # 基础情况
        for j in range(2, k + 1):
            best = -1
            # 前一个元素必须在 i 右侧（因为我们是从右往左构造）
            for p in range(i + 1, n):
                if R[p][j - 1] != -1:
                    cand = R[p][j - 1] | nums[i]
                    if cand > best:
                        best = cand
            R[i][j] = best

    # ---------- 合并左右 ----------
    ans = 0
    for i in range(n - 1):                     # i 为左段最后一个位置
        if L[i][k] != -1 and R[i + 1][k] != -1:
            cur = L[i][k] ^ R[i + 1][k]        # 左 OR XOR 右 OR
            if cur > ans:
                ans = cur
    return ans
```

**代码要点解释**  

| 行号 | 中文解释 |
|------|----------|
| `L = [[-1] * (k + 1) for _ in range(n)]` | 创建二维表，`-1` 表示「还没办法选出这么多元素」 |
| `L[i][1] = nums[i]` | 只选第 `i` 个数时，OR 就是它本身 |
| `cand = L[p][j - 1] | nums[i]` | 把已经得到的 OR（左边 `j‑1` 个数）和第 `i` 个数做 **或** |
| `R[i][1] = nums[i]` | 右侧 DP 的基准同理，只是遍历顺序相反 |
| `for i in range(n - 1):` | 枚举「左段」的结束位置 |
| `cur = L[i][k] ^ R[i + 1][k]` | 左段 OR 与右段 OR 做 **异或**，得到当前子序列的价值 |
| `if cur > ans: ans = cur` | 取最大值 |

---

#### 复杂度  

- **时间复杂度**：`O(n²·k)`  
  - 外层遍历 `i`（`n` 次），内层遍历前驱或后继 `p`（最多 `n` 次），再乘以 `k`（因为我们要填每个 `j`）。  
  - 对于最坏的 `n = 400, k = 200`，大约是 `400 * 400 * 200 = 32,000,000` 次基本操作，完全可以在 1 秒内跑完（Python 速度足够）。  
  - 与暴力的 `C(n,2k)`（指数级）相比，这里是 **多项式** 级别，快得多。  

- **空间复杂度**：`O(n·k)`  
  - 两张 DP 表各占 `n·(k+1)` 的整数空间。`n=400, k=200` 只需要约 80 KB，几乎可以忽略不计。

> **对比**：暴力解的时间随 `n` 的增加呈指数增长，而最优解的时间只随 `n²·k` 增长，量级上差了好几个数量级。

## 心得

- **核心技巧**：**动态规划 + 位运算**  
  - 把 “选 k 个数的 OR 最大化” 分解成「把前一个状态的 OR 与当前数做 OR」的递推。  
  - 通过分别计算左侧和右侧的最优 OR，利用 **XOR** 的特性把两段合并。

- **适用的题型**（类似思路）  
  1. “选 `k` 个数，使它们的 **与**（AND）最大/最小”  
  2. “把数组分成两段，各自做 **或**，再求 **异或** 最大值”  
  3. “在序列中挑 `k` 项，求它们的 **异或** 最大值”（也可以用 DP 记录每一步的异或集合）

- **一句话总结解题钥匙**：  
  **“把整体问题拆成左、右两段的最优子问题，用 DP 记录‘以当前位置结束的 k‑个数的 OR’，再在分界处做 XOR 合并”。**

---

## 反思

- **第一反应**：直接把所有可能的子序列枚举出来，然后逐个算价值。  
- **最容易踩的坑**  
  1. **忘记保持顺序**：子序列必须保持原数组的相对顺序，不能随意打乱。  
  2. **状态初始化**：DP 表中不可达的状态一定要用 `-1`（或 `None`）标记，防止误用未定义的 OR 值。  
  3. **边界条件**：`k = 1` 时左、右段各只需要一个数，仍然适用同样的 DP；`k = n/2` 时左段必须占前半，右段占后半，需要保证分界点合法（`i < n-1`）。  

- **下次遇到同类题**，第一步应该思考：  
  - “价值只和每段内部的 **聚合**（如 OR、AND、XOR）有关吗？”  
  - “如果只关心聚合，是否可以用 DP 记录‘以当前位置为结尾/开头的前 `j` 项的最优聚合值’？”  
  - 再把左、右两段的 DP 结果在合法分界处组合即可。
