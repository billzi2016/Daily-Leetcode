# #3474. 字典序最小的生成字符串 / Lexicographically Smallest Generated String

> 难度：困难 · 标签：String、Greedy、String Matching · [LeetCode 链接](https://leetcode.com/problems/lexicographically-smallest-generated-string/)

---

## 题目（英文原版）

**Description**

You are given two strings, str1 and str2, of lengths n and m, respectively.
A string word of length n + m - 1 is defined to be generated by str1 and str2 if it satisfies the following conditions for each index 0 <= i <= n - 1:
Return the lexicographically smallest possible string that can be generated by str1 and str2. If no string can be generated, return an empty string "".

**Examples**

**Example 1:**

```
Input: str1 = "TFTF", str2 = "ab"
Output: "ababa"
Explanation:
The strings "ababa" and "ababb" can be generated by str1 and str2 .
Return "ababa" since it is the lexicographically smaller string.
```

**Example 2:**

```
Input: str1 = "TFTF", str2 = "abc"
Output: ""
Explanation:
No string that satisfies the conditions can be generated.
```

**Example 3:**

```
Input: str1 = "F", str2 = "d"
Output: "a"
```

**Constraints**

- 1 <= n == str1.length <= 104
- 1 <= m == str2.length <= 500
- str1 consists only of 'T' or 'F'.
- str2 consists only of lowercase English characters.

## 题目（中文翻译）

给定两个字符串 `str1` 和 `str2`，长度分别为 `n` 和 `m`。  
长度为 `n + m - 1` 的字符串 `word` 若满足以下对每个下标 `0 <= i <= n - 1` 的条件，则称其由 `str1` 和 `str2` **生成（generated）**。

返回可以由 `str1` 和 `str2` 生成的字典序（lexicographically）最小的字符串。如果不存在满足条件的字符串，返回空字符串 `""`。

### 示例

**示例 1**  
```text
Input: str1 = "TFTF", str2 = "ab"
Output: "ababa"
Explanation:
字符串 "ababa" 和 "ababb" 都可以由 str1 和 str2 生成。
返回 "ababa"，因为它的字典序更小。
```

**示例 2**  
```text
Input: str1 = "TFTF", str2 = "abc"
Output: ""
Explanation:
不存在满足条件的字符串。
```

**示例 3**  
```text
Input: str1 = "F", str2 = "d"
Output: "a"
```

### 约束条件
- `1 <= n == str1.length <= 10^4`
- `1 <= m == str2.length <= 500`
- `str1` 仅由字符 `'T'` 或 `'F'` 组成
- `str2` 仅由小写英文字母组成

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**把所有可能的 `word` 列举出来**，然后逐个检查它们是否满足题目要求，最后挑出字典序最小的那一个。

- **可能的字符**：题目只说每个未知字符可以从 `['a','b']` 中选（因为 `str2` 只包含小写字母，最小的字符一定是 `'a'`，如果 `'a'` 不行才会考虑 `'b'`）。  
- **枚举方式**：把长度为 `L = n + m - 1` 的字符串看成一棵深度为 `L` 的二叉树，左子树对应字符 `'a'`，右子树对应字符 `'b'`。遍历这棵树（例如深度优先搜索）即可得到 **所有** `2^L` 条候选字符串。  
- **验证**：对每一条候选 `word`，遍历 `i = 0 … n-1`，取子串 `word[i : i+m]` 与 `str2` 比较：
  - 若 `str1[i] == 'T'`，子串必须 **完全相等**；
  - 若 `str1[i] == 'F'`，子串必须 **不相等**。  
  只要有一次不满足，就把这条 `word` 丢掉。

> **为什么能得到正确答案？**  
> 因为我们把**所有**可能的 `word` 都检查了一遍，符合条件的必然在检查过程中被保留下来，最后取字典序最小的自然就是答案。

#### 代码（Python）

```python
def generate_bruteforce(str1: str, str2: str) -> str:
    n, m = len(str1), len(str2)
    L = n + m - 1                 # 目标字符串长度
    best = None                   # 记录当前找到的最小合法串

    def dfs(pos: int, cur: list):
        """深度优先搜索，逐位填字符"""
        nonlocal best
        if pos == L:               # 已经填完全部字符
            word = ''.join(cur)
            # 检查所有约束
            for i in range(n):
                sub = word[i:i+m]
                if str1[i] == 'T' and sub != str2:
                    return
                if str1[i] == 'F' and sub == str2:
                    return
            # 合法！更新最小解
            if best is None or word < best:
                best = word
            return

        # 先尝试字典序更小的字符 'a'，再尝试 'b'
        for ch in ('a', 'b'):
            cur.append(ch)
            dfs(pos + 1, cur)
            cur.pop()               # 回溯

    dfs(0, [])
    return best if best is not None else ""
```

> 代码里每一行都有中文注释，直接跑即可。

#### 复杂度

- **时间复杂度**：`O(2^L * n * m)`  
  - `2^L` 是所有可能的 `word` 数量（指数级爆炸）。  
  - 对每条 `word`，我们要检查 `n` 条约束，每条约束要比较长度为 `m` 的子串。  
  - 用“大白话”解释：如果 `L = 10`，枚举 1024 条；如果 `L = 20`，枚举已经是 **一百万** 条，根本不可接受。
- **空间复杂度**：`O(L)`（递归栈 + 当前构造的字符数组），同样是线性的。

> 暴力解只能用来**验证思路**或在**极小输入**时跑通，面对 `n ≤ 10⁴`、`m ≤ 500` 的限制，它会直接超时。

### 2. 最优解

#### 思路  

暴力的瓶颈在于**枚举所有字符组合**。其实我们可以在构造 `word` 的过程中**提前判断**哪些字符是合法的，从而剪枝掉大量不可能的分支。核心思路是把“子串是否等于 `str2`”的判定抽象为 **状态机**，并结合 **动态规划**（DP）寻找字典序最小的合法路径。

下面一步步推导：

1. **把匹配过程看成 KMP 自动机**  
   - 当我们从左到右逐字符写入 `word` 时，关心的是**当前已经写好的前缀**的**最长后缀**（suffix）有多长与 `str2` 的前缀相同。  
   - 这正是 KMP（Knuth–Morris–Pratt）算法中的 `next`（或 `fail`）数组的含义：  
     > “最长的已经匹配的前缀长度”。  
   - 用一个整数 `k` 表示这个长度，`k` 的取值范围是 `0 … m`。  
   - 当我们往后加一个字符 `c`（`'a'` 或 `'b'`）时，`k` 可以 **快速转移** 到新的匹配长度 `k'`，这一步可以预先用 KMP 的转移表（也叫 **automaton**）算出来。

2. **状态定义**  
   - `dp[i][k] = True/False` 表示：**在已经写完前 `i` 个字符后**，当前最长匹配长度为 `k`，且**所有已经确定的约束**（即已经完整出现的子串）都满足 `str1` 的要求。  
   - `i` 的取值范围是 `0 … L`（`L = n+m-1`），`k` 的取值范围是 `0 … m`。

3. **约束的检查时机**  
   - 当我们写到第 `i` 个字符（`i` 从 `1` 开始计数），如果 `i >= m`，说明已经形成了一个长度为 `m` 的子串，子串的起始位置是 `start = i - m`（0‑based）。  
   - 此时 `str1[start]` 给出了要求：
     - 若 `str1[start] == 'T'`，**必须**恰好匹配 `str2`，也就是 `k == m`（因为 KMP 自动机在匹配完整 `str2` 时会把 `k` 设为 `m`）。  
     - 若 `str1[start] == 'F'`，**不能**匹配 `str2`，即 `k != m`。  
   - 只有满足对应条件的 `dp[i][k]` 才会被保留下来。

4. **转移**  
   - 从 `dp[i][k]` 出发，尝试放 `'a'` 或 `'b'` 两个字符（因为我们只需要字典序最小的答案，后面会优先尝试 `'a'`）。  
   - 用 KMP 自动机得到新匹配长度 `k2 = go[k][c]`。  
   - 检查第 `i` 位形成的子串（如果已形成）是否违背约束，若不违背则把 `dp[i+1][k2]` 设为可达，并记录前驱信息用于后向重建。

5. **贪心取最小字符**  
   - DP 只判断**可达性**，不关心字典序。  
   - 为了得到字典序最小的 `word`，我们在重建答案时**从左到右**，在每一步先尝试 `'a'`，如果这条路径仍然可以到达终点（即 `dp` 中对应的后续状态是可达的），就选 `'a'`；否则选 `'b'`。  
   - 这相当于在所有合法解中做一次**贪心**，因为我们已经保证了后续仍有解，选最小的当前字符自然得到整体最小。

6. **复杂度分析**  
   - 状态数目：`(L+1) * (m+1)`，最多约 `1.05e4 * 501 ≈ 5.3e6`。  
   - 每个状态只转移两次（`'a'`、`'b'`），所以总转移次数约 `1.0e7`，在 Python 中完全可接受。  
   - 空间上我们只需要保存 `dp`（布尔表）和前驱信息（`prev_char`、`prev_k`），同样是 `O(L*m)`。

> **核心技巧**：把“子串是否等于 `str2`”抽象为 KMP 自动机的匹配长度，用 DP 记录每一步的匹配状态，同时在重建阶段贪心选最小字符。

#### 代码（Python）

```python
def smallestGeneratedString(str1: str, str2: str) -> str:
    n, m = len(str1), len(str2)
    L = n + m - 1                     # 目标长度

    # ---------- 1. 构造 KMP 自动机 ----------
    # nxt[i] 为 pattern[0:i] 的最长相等前后缀长度（0-indexed, 不含 i 本身）
    nxt = [0] * (m + 1)
    for i in range(1, m):
        j = nxt[i]
        while j > 0 and str2[i] != str2[j]:
            j = nxt[j]
        if str2[i] == str2[j]:
            j += 1
        nxt[i + 1] = j

    # go[k][c] : 当前已经匹配了 k 个字符（k 为 0..m），再加入字符 c 后的新匹配长度
    go = [[0] * 2 for _ in range(m + 1)]   # 0 -> 'a', 1 -> 'b'
    for k in range(m + 1):
        for idx, ch in enumerate(('a', 'b')):
            if k == m:                     # 已经完整匹配，需要回退到 nxt[m]
                j = nxt[m]
            else:
                j = k
            while j > 0 and ch != str2[j]:
                j = nxt[j]
            if ch == str2[j]:
                j += 1
            go[k][idx] = j

    # ---------- 2. DP 表 ----------
    # dp[i][k] = 是否可以在写完 i 个字符后，当前匹配长度为 k
    dp = [[False] * (m + 1) for _ in range(L + 1)]
    # 前驱信息用于重建答案（只记录第一次到达的最小字符路径）
    pre_char = [[None] * (m + 1) for _ in range(L + 1)]
    pre_k = [[-1] * (m + 1) for _ in range(L + 1)]

    dp[0][0] = True                     # 初始：空串，匹配长度 0

    for i in range(L):                  # 已写 i 个字符，准备写第 i+1 个
        for k in range(m + 1):
            if not dp[i][k]:
                continue
            # 尝试放 'a' (idx=0) 再尝试 'b' (idx=1)
            for idx, ch in enumerate(('a', 'b')):
                k2 = go[k][idx]        # 新的匹配长度
                # 检查如果此时已经形成了完整的长度为 m 的子串，需要满足 str1 的约束
                if i + 1 >= m:         # 子串结束位置是 i (0-indexed)
                    start = i + 1 - m  # 子串在 word 中的起始下标
                    req = str1[start]
                    if req == 'T' and k2 != m:
                        continue      # 必须匹配，却没有匹配成功
                    if req == 'F' and k2 == m:
                        continue      # 必须不匹配，却恰好匹配了
                # 该转移合法，标记 dp
                if not dp[i + 1][k2]:
                    dp[i + 1][k2] = True
                    pre_char[i + 1][k2] = ch
                    pre_k[i + 1][k2] = k   # 记录前一个匹配长度

    # ---------- 3. 找到任意可达的终止状态 ----------
    end_k = -1
    for k in range(m + 1):
        if dp[L][k]:
            end_k = k
            break
    if end_k == -1:                     # 没有合法解
        return ""

    # ---------- 4. 逆向重建最小字典序的答案 ----------
    # 我们已经在 DP 过程中只记录了「第一次」到达每个状态的字符，
    # 由于遍历顺序是先尝试 'a' 再尝试 'b'，这恰好是字典序最小的路径。
    ans = [''] * L
    cur_i, cur_k = L, end_k
    while cur_i > 0:
        ch = pre_char[cur_i][cur_k]
        ans[cur_i - 1] = ch
        cur_k = pre_k[cur_i][cur_k]
        cur_i -= 1

    return ''.join(ans)
```

> **代码要点**  
> - **第 1 部分**：手写 KMP 的 `next` 表并把它扩展成字符转移表 `go`，相当于把 `str2` 编成一个“自动机”。  
> - **第 2 部分**：DP 只判断**可达性**，同时记录从哪个前驱状态转移过来的字符（`pre_char`）和前驱匹配长度（`pre_k`）。  
> - **第 3 部分**：只要最后一层有任意 `True`，就说明存在合法 `word`。  
> - **第 4 部分**：逆向追踪前驱，得到完整字符串。因为在 DP 中我们始终先尝试 `'a'`，所以记录的路径天然是字典序最小的。

#### 复杂度

- **时间复杂度**：`O(L * m)`  
  - `L = n + m - 1 ≤ 10⁴ + 500 - 1 ≈ 1.05×10⁴`，`m ≤ 500`。  
  - 大约 5 × 10⁶ 次状态转移，远小于暴力的指数级。  
  - 与暴力解相比：从“枚举所有字符”降到了“遍历所有合法状态”，提升了 **指数级**。
- **空间复杂度**：`O(L * m)`  
  - DP 表、前驱字符表、前驱匹配长度表共占同样数量的格子。  
  - 对于本题的最大规模，大约几 MB 的内存，完全可以接受。

## 心得

- **核心技巧**：把“子串是否等于 `str2`”抽象为 KMP 自动机的匹配长度，用 DP 记录每一步的匹配状态，再在重建阶段贪心选最小字符。
- **适用场景**  
  1. **带有子串匹配约束的构造题**（如“在满足若干模式出现/不出现的前提下构造最小字符串”）。  
  2. **需要同时判断匹配与不匹配的混合约束**（如本题 `T/F` 的混合要求）。  
  3. **在序列生成过程中，需要维护“已匹配前缀长度”状态**的任何 DP/贪心题（例如“在给定模式出现次数限制下的最小序列”）。
- **一句话总结**：  
  “把子串匹配看成状态机，用 DP 保证约束可行，再贪心恢复最小字典序。”

## 反思

- **第一反应**：直接暴力枚举所有可能的 `word`，因为题目看起来只要求返回一个字符串，想当然地认为搜索空间不大。  
- **最容易踩的坑**  
  - 忘记在每次形成完整子串时立即检查 `str1` 的约束，导致错误的中间状态被保留。  
  - KMP 自动机的转移写错（尤其是已经匹配完 `m` 时需要回退到 `next[m]`），会导致匹配长度不正确。  
  - 在重建答案时没有确保后续仍然可达，可能会在贪心选择 `'a'` 时走进死路。  
- **下次类似题的第一步**：  
  “先把模式匹配抽象为 KMP（或 Aho‑Corasick）状态机，看看约束只在‘完整子串出现时’触发，那就用 DP 记录每一步的匹配状态”。这样可以快速定位问题的核心，避免盲目枚举。
