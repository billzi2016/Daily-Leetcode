## 题目（英文原版）

**Description**

You are given 3 positive integers zero, one, and limit.
A binary array arr is called stable if:
Return the total number of stable binary arrays.
Since the answer may be very large, return it modulo 109 + 7.


## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是 **把所有可能的二进制数组都列举出来**，然后逐个检查它们是否满足 “任意相同元素的连续子段长度不超过 `limit`”。  

- **数据结构**：我们可以用 **列表** 来存放当前正在构造的数组，递归地往里加 `0` 或 `1`。  
- **生活化类比**：把这个过程想象成在拼积木，每块积木只能是黑（0）或白（1），我们把所有的黑块和白块都放进一个盒子里（`zero` 块黑、`one` 块白），然后一次取出一块放到桌面上，直到所有块都用完。每放下一块，就检查最近的几块是否全部是同色且长度已经超过了 `limit`，如果是，就把这条路剪掉（回溯），因为后面再往下也不可能得到合法的数组。

- **为什么正确**：递归会遍历 **所有** 长度为 `zero + one`、恰好包含 `zero` 个 0 和 `one` 个 1 的排列。只要在遍历的过程中把不满足限制的分支全部剪掉，最后留下的就是全部合法的数组，计数即为答案。

- **时间/空间复杂度**：  
  - 暴力枚举的时间复杂度是 `C(z+o, z)`（即从 `z+o` 个位置挑出 `z` 个放 0 的组合数），在最坏情况下会非常大，远远超过 10⁶。可以把它想象成“把所有可能的拼法都列出来”，如果 `z = o = 10`，组合数已经是 184,756。  
  - 递归栈的深度等于数组长度 `z+o`，空间复杂度是 `O(z+o)`，这点倒是比较小。

> **结论**：暴力解能帮助我们理清问题，但在正式提交时会超时，只适合作为验证思路的“小实验”。

#### 代码（Python）

```python
from typing import List

MOD = 10**9 + 7

def brute_force(zero: int, one: int, limit: int) -> int:
    """
    暴力回溯枚举所有可能的数组，统计满足“连续相同元素长度 ≤ limit”的个数。
    """
    ans = 0                     # 最终计数

    def dfs(rem0: int, rem1: int, cur: List[int], last: int, run_len: int):
        """
        rem0 / rem1 : 还剩多少个 0 / 1 没放进去
        cur        : 当前已经构造好的数组（仅用于调试，可省略）
        last       : 上一个放的数（0 / 1），-1 表示还没放任何东西
        run_len    : 当前连续相同元素的长度
        """
        nonlocal ans
        # 所有数字都已经放完，得到一个合法数组
        if rem0 == 0 and rem1 == 0:
            ans = (ans + 1) % MOD
            return

        # 尝试往后放 0
        if rem0 > 0:
            # 如果上一个是 0，需要检查长度是否已到上限
            if last == 0 and run_len == limit:
                pass                     # 已经不能再放 0，直接跳过
            else:
                # 放一个 0，更新状态
                dfs(rem0 - 1, rem1,
                    cur + [0],
                    0,
                    run_len + 1 if last == 0 else 1)

        # 尝试往后放 1（与放 0 的逻辑完全对称）
        if rem1 > 0:
            if last == 1 and run_len == limit:
                pass
            else:
                dfs(rem0, rem1 - 1,
                    cur + [1],
                    1,
                    run_len + 1 if last == 1 else 1)

    # 初始时没有放任何数字，last 用 -1 表示
    dfs(zero, one, [], -1, 0)
    return ans
```

> 运行 `brute_force(1, 2, 1)` 会得到 `1`，与示例 2 的答案一致。  
> 注意：本实现仅用于演示，`zero`、`one` 超过 10 时就会非常慢。

#### 复杂度  

- **时间复杂度**：`O( C(z+o, z) )`，即所有组合的数量。  
  - 用大白话说，就是“把所有可能的排排站，逐个检查”。当 `z+o = 20` 时已经有几万条；`z+o = 30` 时就上千万，根本跑不完。  
- **空间复杂度**：`O(z+o)`，递归栈的深度等于数组长度。

### 2. 最优解  

#### 思路  

从暴力解可以看出，**枚举所有排列是最慢的环节**。  
真正的难点在于：我们只需要统计合法的排列数，而不必真的把每一种排列写出来。  
这正是 **动态规划（DP）** 发挥作用的地方——把大问题拆成“小问题”，用已经算好的子结果来直接得到新状态。

**核心观察**  

1. **状态只与剩余的 0、1 数量以及当前连续段的信息有关**。  
   - 只要知道还有多少个 0、1 没用掉，就能决定后面还能放什么。  
   - 同时我们必须记录“当前最后一段是 0 还是 1”以及“这段已经连续了多少”。这两件事决定了下一步是否还能继续放同样的数字。  

2. **状态转移**  
   - 假设我们已经得到一种合法前缀，状态记作 `dp[z][o][c][len]`：  
     - `z`：已经使用了多少个 0（或等价地，还剩 `zero - z` 个 0）  
     - `o`：已经使用了多少个 1  
     - `c`：前缀最后一个数字是 `0`（记作 0）还是 `1`（记作 1）  
     - `len`：当前这段相同数字的连续长度（`1 … limit`）  
   - **往后放 0**  
     - 如果 `c == 0`（上一个也是 0），只能在 `len < limit` 时继续放 0，新的长度 `len+1`。  
     - 如果 `c == 1`（上一个是 1），放 0 会 **重新开启** 一段新的 0，长度变成 `1`。  
   - **往后放 1** 同理。  

3. **初始状态**  
   - 没放任何数字时，实际上可以把它看成“上一个数字既不是 0 也不是 1”，于是我们用两条 “虚拟” 起点：  
     - `dp[1][0][0][1] = 1`（第一个放的是 0）  
     - `dp[0][1][1][1] = 1`（第一个放的是 1）  
   - 只要 `zero`、`one` ≥ 1，这两条起点都是合法的。  

4. **答案**  
   - 当所有 `zero` 个 0 和 `one` 个 1 都放完时（即 `z = zero` 且 `o = one`），不管最后一段是 0 还是 1、长度是多少，只要状态合法就算进答案。  

5. **复杂度分析**  
   - 状态总数：`(zero+1) * (one+1) * 2 * limit`。  
   - 每个状态最多转移两次（放 0 或放 1），所以总时间是 `O(zero * one * limit)`。  
   - `zero, one, limit ≤ 200` → 最多 `200 * 200 * 200 ≈ 8·10⁶` 次操作，完全可以在 1 秒内跑完。  
   - 空间只需要保存所有状态，大小同样是 `O(zero * one * limit)`，约几 MB。  

**类比**：可以把 DP 想象成“把一个大城堡的建造拆成每层每块砖的铺设”。每放一块砖（0 或 1）只需要看前面已经铺好的状态，而不必把所有可能的城堡一次性画出来。

#### 代码（Python）

```python
from typing import List

MOD = 10**9 + 7

def stableArrays(zero: int, one: int, limit: int) -> int:
    """
    动态规划统计满足“任意相同元素连续长度 ≤ limit”的二进制数组个数。
    dp[z][o][c][l] 表示已经用了 z 个 0、o 个 1，最后一段是 c（0/1），
    长度为 l（1~limit）的合法前缀的数量。
    """
    # 三维列表 + 两个额外维度（c=0/1, l=1..limit），使用 dict 省空间也可，但这里直接用 list
    dp = [[[[0] * (limit + 1) for _ in range(2)] 
            for _ in range(one + 1)] 
            for _ in range(zero + 1)]

    # 初始化：第一位可以是 0 或 1（前提是对应的数量大于 0）
    if zero > 0:
        dp[1][0][0][1] = 1          # 放了一个 0，最后一段是 0，长度 1
    if one > 0:
        dp[0][1][1][1] = 1          # 放了一个 1，最后一段是 1，长度 1

    # 逐步扩展前缀长度
    for z in range(zero + 1):
        for o in range(one + 1):
            for c in (0, 1):
                for l in range(1, limit + 1):
                    cur = dp[z][o][c][l]
                    if cur == 0:
                        continue    # 这个状态不存在，直接跳过

                    # ---------- 往后放 0 ----------
                    if z < zero:                     # 还有 0 可以用
                        if c == 0:                   # 上一位也是 0
                            if l < limit:            # 还能继续延长这段 0
                                dp[z + 1][o][0][l + 1] = (dp[z + 1][o][0][l + 1] + cur) % MOD
                        else:                         # 上一位是 1，开启新的一段 0
                            dp[z + 1][o][0][1] = (dp[z + 1][o][0][1] + cur) % MOD

                    # ---------- 往后放 1 ----------
                    if o < one:                      # 还有 1 可以用
                        if c == 1:                   # 上一位也是 1
                            if l < limit:
                                dp[z][o + 1][1][l + 1] = (dp[z][o + 1][1][l + 1] + cur) % MOD
                        else:                         # 上一位是 0，开启新的一段 1
                            dp[z][o + 1][1][1] = (dp[z][o + 1][1][1] + cur) % MOD

    # 所有数字都用了完，累加两种结尾情况的所有合法长度
    ans = 0
    for c in (0, 1):
        for l in range(1, limit + 1):
            ans = (ans + dp[zero][one][c][l]) % MOD
    return ans
```

#### 复杂度  

- **时间复杂度**：`O(zero * one * limit)`  
  - 大白话：我们把每一种“已经用了多少 0、多少 1、当前结尾是 0 还是 1、连续多少次”这几件事都算一遍，总共约 `8·10⁶` 次简单的加法和取模，计算机跑得飞快。  
- **空间复杂度**：`O(zero * one * limit)`  
  - 需要保存所有中间状态的计数，同样是几百万个整数，几 MB 的内存即可。

## 心得  

- **核心技巧**：**状态压缩的动态规划**——把“剩余资源 + 当前连续段信息”作为状态，利用子问题的计数直接合成更长的前缀。  
- **适用的题型**  
  1. **限制连续相同元素长度**（如本题、LeetCode 1886 “判断矩阵是否满足条件” 的变形）。  
  2. **相邻字符不能相同**、**相邻字符出现次数受限** 的序列计数（如 “统计只含 A、B、C 且每种字符出现不超过 k 次的字符串数”。）  
- **一句话总结解题钥匙**：*把“还能放什么”抽象成“还有多少 0/1 剩余 + 当前段的长度”，用 DP 把所有合法前缀累加即可*。

## 反思  

- **第一反应**：看到 “zero、one、limit”，立刻想到 “枚举所有排列”。这在没有想到 DP 前是最自然的思路。  
- **最容易踩的坑**  
  1. **状态遗漏**：只记剩余的 0/1 而不记录当前连续段的长度，会导致错误地把超过 `limit` 的序列算进来。  
  2. **边界条件**：初始化必须考虑第一位可以是 0 也可以是 1，且当 `zero` 或 `one` 为 0 时只能从唯一的起点开始。  
  3. **取模**：每一次状态转移都要取模，否则整数会爆炸。  
- **下次遇到同类题**：第一步先 **定义状态**——“已经用了多少资源 + 当前约束的剩余/当前长度”，再 **写出转移**（放 0 / 放 1），最后 **遍历所有状态** 得到答案。这样可以快速跳出暴力枚举的思维陷阱。
