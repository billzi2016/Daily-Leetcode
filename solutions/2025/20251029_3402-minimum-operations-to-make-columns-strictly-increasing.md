## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**把每一列单独处理**，把每一列的元素从上往下逐个检查：

1. 取当前行 `i` 与下一行 `i+1` 同一列的两个数 `grid[i][j]`、`grid[i+1][j]`。  
2. 如果 `grid[i+1][j]` 已经严格大于 `grid[i][j]`（即 `grid[i+1][j] > grid[i][j]`），则这两个位置已经满足要求，不需要操作。  
3. 否则，我们必须把 `grid[i+1][j]` 增大到 **恰好** `grid[i][j] + 1`（因为只要比上面的数大 1 即可满足“严格递增”），所需的增量就是 `grid[i][j] + 1 - grid[i+1][j]`。把这个增量加到 `grid[i+1][j]` 上，同时把这个增量计入答案。  

把上述过程对 **每一列**、**每一行**（除了最上面那行）都执行一遍，就能得到一个合法的解。

> **为什么这种方法一定能得到答案？**  
> 我们是从上往下、从左到右逐列检查的。每次只在必要的时候把下方的数提升到 **最小** 合法值（上方数 + 1），所以不会多加任何不必要的操作。因为后面的行只会受到已经处理好的上面行的影响，这样递推下去，所有列最终都会严格递增。

> **时间/空间复杂度大白话**  
> - **时间复杂度 O(m·n)**：我们要遍历矩阵的每一个格子一次，想象成在一个 `m×n` 的棋盘上走遍所有格子，走一步的代价是常数。  
> - **空间复杂度 O(1)**：我们只用了几个临时变量来记录当前值和增量，根本没有开辟额外的数组。  

#### 代码（Python）

```python
def minOperations(grid):
    """
    :type grid: List[List[int]]
    :rtype: int
    """
    m = len(grid)          # 行数
    n = len(grid[0])       # 列数
    ans = 0                # 累计操作次数

    # 对每一列独立处理
    for col in range(n):
        # 从第二行开始向下检查（因为要和上一行比较）
        for row in range(1, m):
            # 上面的数
            up = grid[row - 1][col]
            # 当前行的数
            cur = grid[row][col]

            # 如果当前数已经严格大于上面的数，就不动
            if cur > up:
                continue

            # 需要把当前数提升到 up + 1
            need = up + 1 - cur          # 需要增加的量
            ans += need                  # 累计到答案
            grid[row][col] = up + 1      # 实际在矩阵上做增量（方便后续比较）

    return ans
```

#### 复杂度

- **时间复杂度**：`O(m·n)`  
  这里的 `m` 是行数，`n` 是列数。我们对每个格子检查一次，操作次数随矩阵大小线性增长。  
- **空间复杂度**：`O(1)`  
  只用了常数个额外变量（`ans、up、cur、need`），不随输入规模增长。

### 2. 最优解

#### 思路  

暴力解已经是 **线性** 的 `O(m·n)`，在本题的约束（`m,n ≤ 50`）下已经足够快。  
但我们仍可以把思路写得更「贪心」一点，帮助大家理解为什么 **「从上往下、把下方提升到上方+1」** 是最优的。

1. **瓶颈**：如果我们不从上往下，而是随意挑选格子去增大，可能会出现「后面提升的数又被更上面的数牵制」的情况，导致需要额外的操作。  
2. **贪心原则**：**只在必须的时候才动手**，并且 **把数提升到最小合法值**（即上方数 + 1）。这样每一步的「代价」都是最小的，后面的决策不会因为我们之前「多加」的操作而变得更贵。  
3. **核心算法**：**单次遍历 + 贪心**。我们只需要一次遍历每列，从第二行开始比较，如果不满足 `grid[i][j] > grid[i-1][j]`，就把它提升到 `grid[i-1][j] + 1`。  
   - 这里的 “单调递增” 与 “前缀最大” 思想类似：每一行的数都要 **不小于** 前一行的 **前缀最大 + 1**。  
4. **类比**：想象每一列是一条 **递增的楼梯**，我们只能往上走，不能往下走。要让楼梯每一步都比前一步高，最省力的办法就是把每一步 **恰好** 提升到前一步的高度加一。

#### 代码（Python）

```python
def minOperations(grid):
    """
    贪心一次遍历求最小增量，使每列严格递增
    """
    m, n = len(grid), len(grid[0])
    ops = 0

    for col in range(n):               # 逐列处理
        for row in range(1, m):        # 从第二行往下
            # 前一行的值（已经是处理后的最终值）
            prev = grid[row - 1][col]
            cur = grid[row][col]

            # 若当前值不够大，需要提升
            if cur <= prev:
                inc = prev + 1 - cur   # 需要增加的最小量
                ops += inc
                grid[row][col] = prev + 1   # 直接写回，供后面继续比较

    return ops
```

#### 复杂度

- **时间复杂度**：`O(m·n)` — 与暴力解相同，只是把「暴力」的思路用更明确的贪心语言描述。实际运行时只遍历一次矩阵，常数因子更小。  
- **空间复杂度**：`O(1)` — 仍然只使用常数个额外变量。

## 心得

- **核心技巧**：**贪心**——在必须满足「严格递增」的约束下，每次只把元素提升到「前一个元素 + 1」的最小合法值。  
- **适用的题型**：  
  1. **矩阵/数组单调递增**（如「使数组递增的最小增量」）  
  2. **前缀最大/最小问题**（如「把数组变为递增序列」）  
  3. **需要最小化增量的单调约束**（如「最少操作使数组非递减」）  
- **一句话总结解题钥匙**：**「从上往下，只把数提升到上面那个数的 +1」**。

## 反思

- **第一反应**：看到「每列必须严格递增」立刻想到「遍历每列、比较相邻行」；随后想到只要不满足就把下方提升。  
- **最容易踩的坑**：  
  - **忘记更新矩阵中的值**：如果只累计增量而不把提升后的值写回，后面的比较会用到旧值，导致错误。  
  - **边界条件**：只有一行 (`m = 1`) 时根本不需要任何操作，需要保证循环从 `row = 1` 开始，不会出现负索引。  
- **下次类似题的第一步**：先明确「单调约束」是**向哪个方向**（上/下/左/右），然后**从已确定的基准点**（通常是最上/最左）**逐行/列递推**，每次只做「最小必要的增量」即可。
