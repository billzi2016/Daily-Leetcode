## 题目（英文原版）

**Description**

You are given an integer array nums of length n and a positive integer k.
The power of an array of integers is defined as the number of subsequences with their sum equal to k.
Return the sum of power of all subsequences of nums.
Since the answer may be very large, return it modulo 109 + 7.

**Examples**

**Example 1:**

```
Input: nums = [1,2,3], k = 3
Output: 6
Explanation:
There are 5 subsequences of nums with non-zero power:
Hence the answer is 2 + 1 + 1 + 1 + 1 = 6 .
```

**Example 2:**

```
Input: nums = [2,3,3], k = 5
Output: 4
Explanation:
There are 3 subsequences of nums with non-zero power:
Hence the answer is 2 + 1 + 1 = 4 .
```

**Example 3:**

```
Input: nums = [1,2,3], k = 7
Output: 0
Explanation: There exists no subsequence with sum 7 . Hence all subsequences of nums have power = 0 .
```

**Constraints**

- 1 <= n <= 100
- 1 <= nums[i] <= 104
- 1 <= k <= 100

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是 **枚举所有子序列**，对每一个子序列再枚举它的所有子子序列，统计其中和恰好等于 `k` 的个数（这就是该子序列的 *power*），最后把所有子序列的 power 加起来。

- **枚举子序列**：长度为 `n` 的数组共有 `2ⁿ` 种子序列（每个元素要么选要么不选），这跟我们平时挑选“是否参加派对”的二进制选择一模一样。  
- **子子序列**：对已经选出的子序列再做一次相同的二进制选择，得到它的所有子子序列。  
- **判断和是否为 `k`**：把子子序列里所有元素相加，看看是否等于目标 `k`。

> **为什么正确？**  
> 因为我们把「所有可能的子序列」以及「每个子序列内部的所有可能子子序列」全部遍历了一遍，没漏掉任何一种组合，自然得到的答案就是题目要求的「所有子序列的 power 之和」。

> **时间/空间分析**  
> - 对每个子序列我们都要再遍历一次它的子子序列，最坏情况下两层遍历都是 `2ⁿ`，总共是 `2ⁿ × 2ⁿ = 4ⁿ`，也就是 **指数级** 的时间（`O(4ⁿ)`)。  
> - 只需要保存当前遍历到的子序列和子子序列的临时数组，空间是 `O(n)`（存放一个子序列最多 `n` 个元素）。

> **大白话解释**：  
> `O(4ⁿ)` 就像把所有 100 位二进制数写成表格，先选一列再选另一列，行数会以 **指数** 的速度爆炸，根本跑不完。

#### 代码（Python）

```python
from itertools import combinations
from typing import List

MOD = 10**9 + 7

def brute_force(nums: List[int], k: int) -> int:
    n = len(nums)
    ans = 0

    # 1️⃣ 枚举所有子序列（使用位掩码）
    for mask in range(1, 1 << n):                # 0 代表空序列，题目要求非空
        subseq = [nums[i] for i in range(n) if mask >> i & 1]

        # 2️⃣ 统计该子序列内部和为 k 的子子序列个数（它的 power）
        power = 0
        m = len(subseq)
        for sub_mask in range(1, 1 << m):
            s = 0
            for i in range(m):
                if sub_mask >> i & 1:
                    s += subseq[i]
            if s == k:
                power += 1

        ans = (ans + power) % MOD

    return ans
```

> 代码里每一行都写了中文注释，直接可以跑，只是对 `n` 超过 20 就会超时。

#### 复杂度  

- **时间复杂度**：`O(4ⁿ)` —— 指数级增长，`n` 稍大就不可接受。  
- **空间复杂度**：`O(n)` —— 只存当前子序列和子子序列的临时列表。

### 2. 最优解

#### 思路  

暴力解的 **瓶颈** 在于两层指数遍历：  
1. 先选哪些元素进入子序列；  
2. 再选哪些元素进入子子序列。  

观察提示可以得到关键的 **“计数 + 权重”** 思路：

> **如果一段子序列的长度是 `j`，且它的元素和正好等于 `k`，那么它对答案的贡献是 `2^{n-j}`。**  

原因是：一旦固定了这段子序列（记作 `T`），剩下的 `n-j` 个位置可以**随意**保留或删除，仍然得到一个合法的父子序列。每个位置有两种选择，所以共有 `2^{n-j}` 种父子序列把 `T` 包含进去。

于是我们只需要 **统计**：  
- 对每个可能的长度 `j`（`1 ≤ j ≤ n`），有多少子序列的和恰好是 `k`？记作 `cnt[j]`。  
- 最终答案 = ` Σ_{j=1}^{n} cnt[j] × 2^{n-j}`（模 `1e9+7`）。

**如何得到 `cnt[j]`？**  
这正是**动态规划**（DP）可以帮忙的地方。我们维护一个二维 DP：

```
dp[l][s] = 现在已经处理完前面的若干元素后，
           长度恰好为 l、元素和恰好为 s 的子序列的个数
```

- 初始状态：`dp[0][0] = 1`（空子序列，长度 0，和 0）。
- 对每个数组元素 `num`，我们**倒序**遍历长度 `l`（从大到小），防止同一次迭代中把新加入的元素再次使用。
- 转移方程：

```
dp[l+1][s+num] += dp[l][s]   (取模)
```

即：如果已有一种长度 `l`、和为 `s` 的子序列，我们把当前 `num` 加进去，就得到一种长度 `l+1`、和 `s+num` 的新子序列。

- 只需要维护 `s` 在 `[0, k]` 之间，因为更大的和我们根本不关心。

遍历完所有 `n` 个数后，`dp[l][k]` 就是 `cnt[l]`（长度为 `l`、和为 `k` 的子序列数）。  

最后再预计算 `pow2[i] = 2^i (mod MOD)`，把公式求和即可。

**类比帮助理解**：  
- 把 DP 表想象成一本“账本”，每一行对应一种“子序列的长度”，每一列对应一种“当前的总和”。我们不断往账本里“记账”：当新数字进来时，账本里所有已有的记录都可以生成新的记录（把新数字加入），这就是转移。

#### 代码（Python）

```python
from typing import List

MOD = 10**9 + 7

def sum_of_power(nums: List[int], k: int) -> int:
    n = len(nums)

    # 1️⃣ 预计算 2 的幂次，pow2[i] = 2^i % MOD
    pow2 = [1] * (n + 1)
    for i in range(1, n + 1):
        pow2[i] = (pow2[i - 1] * 2) % MOD

    # 2️⃣ dp[l][s]：长度为 l、和为 s 的子序列个数
    #    只需要保存到 k，因为更大的和不影响答案
    dp = [[0] * (k + 1) for _ in range(n + 1)]
    dp[0][0] = 1                     # 空子序列

    # 3️⃣ 遍历数组，每加入一个数，就把所有已有的记录向右下角“搬家”
    for num in nums:
        # 倒序遍历长度，防止本轮更新后再次使用新产生的状态
        for l in range(n - 1, -1, -1):
            for s in range(k - num, -1, -1):   # 只要 s+num ≤ k
                if dp[l][s]:
                    dp[l + 1][s + num] = (dp[l + 1][s + num] + dp[l][s]) % MOD

    # 4️⃣ 根据提示，把每个长度的计数乘以 2^{n-l} 累加
    ans = 0
    for l in range(1, n + 1):               # 长度为 0 的子序列和 k≥1 不可能
        cnt = dp[l][k]                      # 长度为 l、和为 k 的子序列数
        if cnt:
            ans = (ans + cnt * pow2[n - l]) % MOD

    return ans
```

> 关键行中文注释已经写在代码里，直接复制运行即可。

#### 复杂度  

- **时间复杂度**：`O(n² · k)`  
  - 外层遍历 `n` 个元素；  
  - 内层两层循环分别遍历长度 `0…n` 与和 `0…k`。  
  - 对于本题的限制（`n ≤ 100, k ≤ 100`），最多约 `1,000,000` 次基本操作，毫秒级完成。  

- **空间复杂度**：`O(n · k)`  
  - DP 表大小为 `(n+1) × (k+1)`，约 `10⁴` 个整数，几乎可以忽略不计。

> 与暴力解相比，时间从指数级降到了多项式级，速度提升 **天壤之别**。

## 心得  

- **核心技巧**：**“子序列计数 + 权重 2^{剩余元素数}”**，把原本的双层枚举拆成一次 DP 计数，再乘以一个固定的系数。  
- **适用场景**：  
  1. 需要统计满足某种属性的子序列（或子集），并且每个子序列还有“外延”自由度的题目。  
  2. “子集和 + 长度” 双维度计数的动态规划问题，如  
     - “统计所有子集的和为 `k` 的子集数”  
     - “求和为 `k` 的子序列中最长/最短长度”。  
- **一句话总结**：**先数“核心子序列”，再乘以“其余元素的自由组合数”。**

## 反思  

- **第一反应**：看到“所有子序列的 power 之和”，本能想到两层枚举——先选子序列，再在里面选子子序列。  
- **最容易踩的坑**：  
  - 忘记 **长度** 对答案的影响，直接把所有和为 `k` 的子序列相加会漏掉乘以 `2^{n-j}` 的权重。  
  - DP 转移时如果正向遍历长度，会导致同一个元素被重复计入多次，导致计数错误。  
  - `k` 的上限只有 100，务必把 DP 的“和”维度限制在 `[0, k]`，否则会出现数组越界或不必要的时间浪费。  
- **下次思路**：遇到“子序列/子集统计 + 乘以某个指数” 的题目，第一步就思考 **“把指数部分抽出来，先只计数满足核心条件的子序列”**，再用组合数学（如 `2^{剩余}`）把自由选择的部分乘上去。这样往往可以把指数爆炸的暴力思路压缩成多项式 DP。
