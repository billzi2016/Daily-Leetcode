## 解题过程

### 1. 直觉解（暴力）

#### 思路  

题目要求不断对字符串 `s` 进行一种“相邻相加取个位” 的操作，直到只剩 **两个** 数字，然后判断这两个数字是否相同。  
最直观的做法就是 **一步一步模拟**：

1. 把字符转成整数列表 `a`（比如 `"3902"` → `[3,9,0,2]`）。  
2. 当列表长度大于 2 时，遍历相邻元素 `a[i]` 与 `a[i+1]`，把它们的和取个位 (`(a[i] + a[i+1]) % 10`) 放进新列表。  
3. 用新列表替换旧列表，继续循环。  

> **类比**：把这一步想成“把一排小盒子里装的数字，两两合并成新盒子”，每次盒子的数量会少 1，最终只剩两盒。

因为每一次遍历都要看 **全部** 相邻对，长度从 `n` → `n‑1` → … → 2，时间上是 **等差数列** 的求和，约等于 `n²/2` 步。

#### 代码（Python）

```python
def checkEquality_bruteforce(s: str) -> bool:
    # 把字符转成整数列表
    a = [int(ch) for ch in s]          # 关键：把每个字符变成数字

    # 重复进行相邻相加取个位的操作，直到只剩两位
    while len(a) > 2:                  # 当长度大于 2 时继续循环
        b = []                          # 用来存放本轮的结果
        for i in range(len(a) - 1):    # 遍历所有相邻对
            b.append((a[i] + a[i + 1]) % 10)   # 相邻两数相加后取个位
        a = b                          # 用新列表替换旧列表

    # 此时 a 只剩两位，比较它们是否相同
    return a[0] == a[1]
```

#### 复杂度  

- **时间复杂度**：`O(n²)`  
  这里的 `n` 是字符串长度。想象一次遍历是看 `n‑1` 对，第二次是 `n‑2` 对，……，总共大约是 `1 + 2 + … + (n‑2) ≈ n²/2` 步。  
  **大白话**：如果 `n = 10⁵`，`n²` 就是 `10¹⁰`，根本跑不完。

- **空间复杂度**：`O(n)`  
  需要额外的列表来存放每轮的结果，最大不超过原始长度 `n`。

### 2. 最优解

#### 思路  

暴力解慢的根源在于 **一次一次地把相邻元素合并**，其实我们可以直接算出最终留下的两个数字，而不必真的去合并。

---

#### 2.1 为什么会出现二项式系数？

把相邻相加的过程写成数学式：

- 第一次得到 `b[i] = a[i] + a[i+1]`  
- 第二次再相邻相加：`c[i] = b[i] + b[i+1] = (a[i] + a[i+1]) + (a[i+1] + a[i+2])`  

展开后会出现 **组合数**（也叫二项式系数）`C(k, i)`。事实上，经过 `k` 次操作后，第 `i` 位的贡献是 `C(k, i) * a[i]`（模 10 取个位）。

当我们只进行 `n‑2` 次操作，字符串长度恰好变成 **2**。于是这两个最终数字可以写成：

```
left  = Σ_{i=0}^{n-2} C(n-2, i) * a[i]   (mod 10)
right = Σ_{i=1}^{n-1} C(n-2, i-1) * a[i] (mod 10)
```

两式只相差一个位移，求它们是否相等等价于：

```
Σ_{i=0}^{n-2} C(n-2, i) * (a[i] - a[i+1]) ≡ 0 (mod 10)
```

于是 **任务化简为**：快速算出 `C(m, i) (mod 10)`，其中 `m = n‑2`，并对所有 `i` 加权求和。

---

#### 2.2 如何快速求 `C(m, i) (mod 10)` ？

直接算组合数会涉及大数除法，太慢。提示里说：

- `C(m,i) mod 10` 可以由 `mod 2` 与 `mod 5` 两个结果唯一确定（因为 `10 = 2 × 5`，两者互质）。  
- 用 **Lucas 定理** 可以分别在模 2、模 5 下快速求值。

**Lucas 定理**：把 `m`、`i` 用对应的进制表示（这里是 2 进制或 5 进制），
`C(m,i) (mod p) = Π C(m_j, i_j) (mod p)`，其中 `m_j,i_j` 是第 `j` 位的数字。

- **模 2**：`C(m,i) (mod 2)` 非零（即等于 1）当且仅当 `i` 的二进制位 **不超过** `m` 的对应位。等价判定是 `i & (m-i) == 0`。  
- **模 5**：因为每位数字都在 `[0,4]`，我们只需要预先算出 `C(x,y)`（`x,y ≤ 4`）的 5 模值，存进一个 5×5 的表格，然后按照 Lucas 定理逐位相乘即可。

得到 `c2 = C(m,i) mod 2`、`c5 = C(m,i) mod 5` 后，用 **中国剩余定理** 合成 `mod 10`：

```
x ≡ c2 (mod 2)
x ≡ c5 (mod 5)

解得：x = (5 * c2 + 6 * c5) mod 10
（因为 5 ≡ 1 (mod 2)，2·3 ≡ 1 (mod 5) → 6 = 2·3）
```

于是我们可以在 **O(logₚ n)**（这里是 `log₂ n` 或 `log₅ n`）的时间里得到任意 `C(m,i) mod 10`。

---

#### 2.3 完整算法

1. `n = len(s)`, `m = n‑2`.  
2. 把字符串转成整数列表 `a`.  
3. 预计算 **5×5** 的小组合数表 `smallC[x][y] = C(x,y) % 5`（只需要 0≤x,y≤4）。  
4. 对每个 `i`（`0 … n‑2`）  
   - 计算 `c2 = nCr_mod2(m, i)`  
   - 计算 `c5 = nCr_mod5(m, i)`（Lucas + 小表）  
   - 合成 `coeff = (5*c2 + 6*c5) % 10`  
   - 累加 `diff = (diff + coeff * (a[i] - a[i+1])) % 10`  
5. 最后 `diff == 0` 即为答案。

整个过程只遍历一次原始数组，时间是 `O(n log n)`（对每个 `i` 进行几次取模运算），空间 `O(1)`（只用常数个变量和 5×5 的表）。

---

#### 代码（Python）

```python
def checkEquality(s: str) -> bool:
    """
    高效判断经过“相邻相加取个位”操作后剩下的两位是否相等。
    思路：利用二项式系数的模 10 规律（Lucas 定理 + CRT）。
    """
    a = [int(ch) for ch in s]          # 原始数字列表
    n = len(a)
    m = n - 2                           # 需要的二项式上标

    # ---------- 预计算 C(x, y) % 5，0 <= x, y <= 4 ----------
    smallC = [[0] * 5 for _ in range(5)]
    for x in range(5):
        smallC[x][0] = 1
        for y in range(1, x + 1):
            # 直接用整数算组合数，再取 %5
            # C(x,y) = x! / (y! * (x-y)!)
            # 因为 x <= 4，直接枚举乘除不会产生小数
            num = 1
            den = 1
            for k in range(1, y + 1):
                num *= x - k + 1
                den *= k
            smallC[x][y] = (num // den) % 5

    # ---------- 辅助函数 ----------
    def nCr_mod2(n_: int, r_: int) -> int:
        """返回 C(n_, r_) % 2，利用二进制位的性质"""
        # 当且仅当 r_ 的每一位不超过 n_ 的对应位时为 1
        return 1 if (r_ & (n_ - r_)) == 0 else 0

    def nCr_mod5(n_: int, r_: int) -> int:
        """返回 C(n_, r_) % 5，使用 Lucas 定理（5 进制）"""
        res = 1
        while n_ > 0 or r_ > 0:
            ni = n_ % 5
            ri = r_ % 5
            if ri > ni:                 # 小位上选不到，整个组合为 0
                return 0
            res = (res * smallC[ni][ri]) % 5
            n_ //= 5
            r_ //= 5
        return res

    # ---------- 主循环 ----------
    diff = 0  # Σ C(m,i) * (a[i] - a[i+1]) (mod 10)
    for i in range(n - 1):               # i = 0 … n-2
        c2 = nCr_mod2(m, i)
        c5 = nCr_mod5(m, i)
        coeff = (5 * c2 + 6 * c5) % 10    # CRT 合成模 10 的系数

        diff = (diff + coeff * (a[i] - a[i + 1])) % 10

    return diff % 10 == 0                # 为 0 表示两位相等
```

> **代码要点注释**  
> - `smallC`：只需要 5×5 的表，避免在循环里做除法。  
> - `nCr_mod2`：利用 `i & (n-i) == 0` 的位运算，极快。  
> - `nCr_mod5`：每次把 `n`、`i` 拆成 5 进制位，乘上对应的“小组合数”。  
> - `coeff = (5*c2 + 6*c5) % 10`：这一步是 **中国剩余定理** 的简化写法。

---

#### 复杂度

- **时间复杂度**：`O(n * log₅ n)`（每个 `i` 需要对 `m`、`i` 做若干次取模 / 除 5，次数约为 `log₅ n`）。在最坏情况下 `log₅ 10⁵ ≈ 7`，几乎是线性时间。  
  与暴力的 `O(n²)` 相比，**快了好几个数量级**。  
- **空间复杂度**：`O(1)`（只用常数级别的额外变量，`smallC` 是固定 5×5 的表）。

## 心得

- **核心技巧**：把“相邻相加取个位”视作**帕斯卡三角（二项式系数）**的展开，利用**Lucas 定理**在模 2、模 5 下快速求二项式系数，再用**中国剩余定理**合成模 10。  
- **适用题型**  
  1. 需要多次“相邻合并”或“滑动求和”并且要在大规模数据上求结果的题目。  
  2. 任何出现 **组合数**、**二项式展开**、**模数为非质数**（如 10）时，需要拆成质数模数求解的情形。  
  3. 类似 “把一排数字不断两两相加，求最后的数值” 的变体（如求模 1000、模 7 等）。  
- **一句话总结**：**把重复的相邻相加抽象为二项式系数的加权求和，利用 Lucas+CRT 在模 10 下直接算出权重，省掉所有“逐层合并”的过程。**

## 反思

- **第一反应**：看到“重复相邻相加”，自然想到直接模拟，忽视了背后隐藏的数学结构。  
- **最容易踩的坑**  
  - 忘记对每一步取 **个位**（即模 10），导致数值爆炸。  
  - 在 Lucas 定理中没有处理 “位上选择大于上位数” 的情况，导致错误的非零值。  
  - 合成模 10 时使用错误的系数（CRT 需要正确的逆元），会得到不对的权重。  
- **下次类似题目**：  
  1. 先 **写出几步手算**，观察是否出现 **Pascal 三角** 或 **二项式系数** 的模式。  
  2. 判断模数是否可以拆分成 **质数的乘积**，如果可以，考虑 **Lucas 定理 + CRT**。  
  3. 把“逐层操作”转化为“一次性加权求和”，再实现高效的系数计算。
