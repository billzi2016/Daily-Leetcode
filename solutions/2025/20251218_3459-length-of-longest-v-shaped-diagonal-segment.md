## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**把所有可能的 V 形路径枚举一遍**，然后挑出最长的那条。  
我们可以把每一个格子当作「转折点」：

1. 任选一个格子 `(i, j)` 作为 V 的拐点。  
2. 从左上斜向 (`↘`) 向左上延伸，记录能够走多远（只要格子里不是 `0`，就可以继续）。  
3. 再从同一个拐点沿右上斜向 (`↙`) 向右上延伸，同样记录能够走多远。  
4. 两条斜线的长度相加（拐点本身算一次）就是以 `(i, j)` 为拐点的 V 的长度。  
5. 对所有格子都这样尝试，取最大值。

> **类比**：把矩阵想成一张城市地图，`0` 是河流（不能走），`1/2` 是道路。我们要找一条先往东北走、再在某个十字路口左转（或者右转）继续往东南走的最长道路。暴力做法就是把每个十字路口都当成「左转点」去试一遍。

**为什么正确**  
只要我们把每个格子都当作可能的拐点，并且在两条斜线上尽可能走得最远，就一定能得到所有合法的 V 形路径。最长的那条自然会被遍历到。

**复杂度分析（大白话）**  
- 对每个格子我们都要向两个方向「走」到底。最坏情况下每条斜线长度是 `min(n, m)`，所以一次拐点的检查是 `O(min(n,m))`。  
- 矩阵里有 `n·m` 个格子，总时间就是 `O(n·m·min(n,m))`，在最坏情况下相当于 `O(n·m·max(n,m))`，约等于 `O(n³)`（因为 `n`、`m` 规模相近时）。  
- 只用了原矩阵和几个计数变量，空间是 `O(1)`，即常数级别。

#### 代码（Python）

```python
def longestV_bruteforce(grid):
    n, m = len(grid), len(grid[0])
    best = 0

    # 判断某格子是否可以走（非 0）
    def ok(r, c):
        return 0 <= r < n and 0 <= c < m and grid[r][c] != 0

    for i in range(n):
        for j in range(m):
            if not ok(i, j):
                continue                     # 只能从非 0 的格子出发

            # 向左上方向 (↖) 走多远
            up_len = 0
            r, c = i - 1, j - 1
            while ok(r, c):
                up_len += 1
                r -= 1
                c -= 1

            # 向右上方向 (↗) 走多远
            down_len = 0
            r, c = i + 1, j - 1
            while ok(r, c):
                down_len += 1
                r += 1
                c -= 1

            # V 的总长度 = 左上段 + 右上段 + 拐点本身
            cur_len = up_len + down_len + 1
            best = max(best, cur_len)

    return best
```

> **关键行注释**  
> - `ok` 用来判断格子是否「可以走」，相当于查字典里是否有对应的「页码」——这里的「页码」就是格子是否为 `0`。  
> - 两个 `while` 循环分别沿两条对角线「一步一步」往外走，记录能走的格子数。  

#### 复杂度

- **时间复杂度**：`O(n·m·min(n,m))`  
  - 想象一下：我们把每个格子都当成「灯塔」，从灯塔向两边发射光束，光束最长可能照到矩阵的对角线尽头。灯塔有 `n·m` 个，光束最远走 `min(n,m)` 步，所以总工作量是两者的乘积。  
- **空间复杂度**：`O(1)`  
  - 只用了常数个计数器和指针，不随矩阵大小增长。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**每次都要重新遍历整条对角线**，导致重复计算。  
如果我们事先把「从每个格子出发向左上、向右上能走多远」的结果记下来，以后直接查询，就能把每次的 `while` 循环省掉——这就是**动态规划（DP）/记忆化**的思想。

**核心想法**  
- 对每个格子 `(i, j)`，记两个值  
  - `up[i][j]`：以 `(i, j)` 为起点，沿左上斜方向 (`↖`) 连续非 `0` 的最长长度（包括自身）。  
  - `down[i][j]`：以 `(i, j)` 为起点，沿右上斜方向 (`↗`) 连续非 `0` 的最长长度（包括自身）。  
- 这两个 DP 表可以 **一次遍历** 计算出来：  
  - `up[i][j] = 1 + up[i-1][j-1]`（如果 `grid[i][j] != 0`），否则 `0`。  
  - `down[i][j] = 1 + down[i-1][j+1]`（如果 `grid[i][j] != 0`），否则 `0`。  
- 计算完后，任意格子 `(i, j)` 作为拐点时，V 的长度 = `up[i][j] + down[i][j] - 1`（拐点算了两次，要减掉一次）。  
- 只需要遍历一次矩阵取最大值即可。

> **类比**：把矩阵想成一排排的楼梯，每层楼都有「向左上」和「向右上」的扶手。我们先把每层楼的扶手长度提前测好，后面要查「从这层楼往左上还能走多远？」时，只要看表格就行，省去重新爬楼梯的时间。

**为什么对**  
- `up[i][j]` 的递推式只依赖左上方已经算好的值，保证了「从上往左」的顺序可以一次算完。  
- 同理 `down[i][j]` 只依赖右上方的值。  
- 因为每个格子只被访问常数次，所有可能的 V 都能在 `O(1)` 查询后得到长度，整体最优。

#### 代码（Python）

```python
def longestV(grid):
    n, m = len(grid), len(grid[0])

    # up[i][j] : 向左上方向连续非0的长度（包括 (i,j) 本身）
    up = [[0] * m for _ in range(n)]
    # down[i][j] : 向右上方向连续非0的长度（包括 (i,j) 本身）
    down = [[0] * m for _ in range(n)]

    # 计算 up
    for i in range(n):
        for j in range(m):
            if grid[i][j] != 0:                     # 只有非0格子才可以站在上面
                if i > 0 and j > 0:
                    up[i][j] = up[i-1][j-1] + 1    # 继承左上格子的长度再加 1
                else:
                    up[i][j] = 1                    # 边界格子只能自己算 1

    # 计算 down（从左往右遍历，使得右上格子已经算好）
    for i in range(n):
        for j in range(m-1, -1, -1):
            if grid[i][j] != 0:
                if i > 0 and j < m-1:
                    down[i][j] = down[i-1][j+1] + 1
                else:
                    down[i][j] = 1

    best = 0
    # 以每个格子为拐点，计算 V 长度
    for i in range(n):
        for j in range(m):
            if grid[i][j] != 0:                     # 拐点必须是非0
                cur = up[i][j] + down[i][j] - 1    # 拐点算了两次，减掉一次
                best = max(best, cur)

    return best
```

> **关键行注释**  
> - `up[i][j] = up[i-1][j-1] + 1`：把左上格子的「能走多远」拿来加上自己，等价于「把前面的路延长一步」。  
> - `down[i][j] = down[i-1][j+1] + 1`：同理，只是方向换成右上。  
> - `cur = up[i][j] + down[i][j] - 1`：把左上段长度、右上段长度相加，再减掉拐点的重复计数。

#### 复杂度

- **时间复杂度**：`O(n·m)`  
  - 只遍历矩阵三次（一次算 `up`，一次算 `down`，一次求最大值），每次都是常数时间操作。相当于「一次把所有楼梯扶手的长度都量好」，不需要再重复爬楼梯。  
- **空间复杂度**：`O(n·m)`（存 `up`、`down` 两个表）  
  - 需要额外的二维数组来记忆每个格子的最长斜向长度。若要求**原地**（只用常数空间）也可以把 `up`、`down` 合并到原矩阵里，但这里为了代码可读性保持独立。

## 心得

- **核心技巧**：把「沿对角线的最长连续非零段」预先用 DP 保存，然后在每个格子处合并两段得到 V 的长度。  
- **适用的题型**  
  1. **最长的 “∧” 形或 “∨” 形路径**（需要两条对角线相交）。  
  2. **矩阵中最长的同色斜线**（类似本题，只是没有转折点）。  
  3. **在棋盘上找最长的“马”形路径**（需要先算四个方向的连续长度，再组合）。  
- **一句话总结解题钥匙**：**把局部最优（每格向左上/右上能走多远）缓存起来，所有全局答案都能在 O(1) 内合成。**

## 反思

- **第一反应**：看到“V 形对角线”立刻想到枚举每个拐点并向两侧扩展——这就是暴力思路。  
- **最容易踩的坑**  
  - **边界检查**：对角线延伸时容易越界，记得在 `up/down` 的递推式里先判断 `i>0`、`j>0`、`j<m-1`。  
  - **拐点重复计数**：`up` 与 `down` 都把拐点算进长度，最终需要 `-1`。忘记会把答案多算一。  
  - **0 的处理**：`0` 代表「不能经过」，所有 DP 表格在遇到 `0` 时必须归零，否则会把不合法的路径算进去。  
- **下次遇到同类题的第一步**：先**思考能否把方向上的连续信息预处理**（DP/前缀和/单调栈），再在拐点或交点处**快速合并**这些信息，而不是每次都现场遍历。这样往往可以把指数级或三重循环降到线性时间。
