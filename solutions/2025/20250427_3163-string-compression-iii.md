## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**一次一次地把题目描述的“操作”真实地模拟出来**。  
具体步骤：

1. 维护一个字符串 `comp`，初始为空，用来保存压缩后的结果。  
2. 每次在剩余的 `word` 前面找出**最长的、只包含同一个字符的前缀**，但长度不能超过 9（因为计数只能是 1~9）。  
3. 把这个前缀的长度（记作 `cnt`）和字符本身拼接到 `comp` 里，得到 `comp += str(cnt) + ch`。  
4. 把已经处理掉的前缀从 `word` 中删掉，继续对剩下的部分重复上述操作，直到 `word` 为空。

> **类比**：把 `word` 看成一本书的未读页码，`comp` 就是我们手里已经写好的压缩笔记。每次我们把书的**连续相同文字**（相当于同一章节）一次性抄写（最多 9 页），然后把这几页从书中撕掉，继续抄写后面的章节。

**为什么正确**  
因为题目要求的压缩正好是把**相同字符的连续块**拆成若干个 “`cnt+char`” 形式的片段，且每个片段的计数不能超过 9。只要我们每一步都取 **最长**（但 ≤9）的合法前缀，最终一定能把全部字符覆盖，且不会出现更好的（更短的）表示方式——题目已经说明“总是把更大的前缀切掉更好”。

**复杂度分析（大白话）**  
- **时间**：我们每次都要在 `word` 前面找出最长相同字符的前缀，这一步需要遍历 `word`（最坏情况遍历全部字符），随后又要把前缀从 `word` 中删掉（在 Python 中如果用 `word = word[k:]` 会产生一个新字符串，需要把剩余的字符再拷贝一遍）。如果 `word` 长度是 `n`，第一次拷贝 `n`，第二次拷贝 `n‑k1`，…，总体拷贝次数大约是 `n + (n‑k1) + (n‑k1‑k2) + … ≈ n²/2`，所以时间复杂度是 **O(n²)**，即“随字符数的平方增长”。  
- **空间**：我们额外保存了压缩结果 `comp`（长度最多是原字符串的两倍，因为每个字符最多会被写成 “9a” 这种两字符），再加上每次切片产生的临时字符串，总体是 **O(n)**，即“和原字符串同量级的额外空间”。

#### 代码（Python）

```python
def compress_bruteforce(word: str) -> str:
    comp = ""                     # 最终的压缩结果
    while word:                   # 只要还有字符没处理
        # 1️⃣ 找出最长的相同字符前缀，长度不超过 9
        ch = word[0]              # 前缀的字符一定是第一个字符
        cnt = 0
        # 逐个检查，最多检查 9 次或到字符不相同为止
        while cnt < 9 and cnt < len(word) and word[cnt] == ch:
            cnt += 1

        # 2️⃣ 把计数和字符写入结果
        comp += str(cnt) + ch

        # 3️⃣ 删除已经处理的前缀，留下剩余部分继续循环
        word = word[cnt:]         # 这里会产生一个新的字符串（拷贝），是 O(n) 操作

    return comp
```

#### 复杂度

- **时间复杂度**：O(n²) — 随着字符数的增加，运行时间大约是字符数的平方。想象把 10,000 个字符的字符串压缩，可能要进行约 50,000,000 次基本操作，明显太慢。  
- **空间复杂度**：O(n) — 需要存放压缩后的字符串和每一次切片产生的临时副本，和原始输入规模是同级别的。

### 2. 最优解

#### 思路  

从暴力解出发，我们可以清晰看到**瓶颈**：

- 每一次都要**重新切片**（拷贝）剩余的字符串，导致累计的拷贝次数呈二次增长。  
- 还有一个隐形的循环：在找前缀时我们一次一次比较字符，其实这一步已经是线性的，没问题。

**优化的核心**：**一次遍历（单次线性扫描）就把所有信息全部收集完**，不再对字符串进行切片。思路如下：

1. 用两个指针（`i` 为遍历指针，`j` 为当前连续块的起始位置）在原字符串上一次走到底。  
2. 当 `word[i]` 与 `word[j]` 不相等（或者遍历到了末尾）时，说明从 `j` 到 `i‑1` 这段字符全是同一个字母。  
3. 计算这段的长度 `len = i - j`。  
4. 根据题目要求，把 `len` 按 **每 9 个一组** 拆分：  
   - `while len > 9: comp += "9" + word[j]; len -= 9`  
   - 最后剩下的 `len`（1~9）直接写入 `comp += str(len) + word[j]`。  
5. 把 `j` 移到 `i`，继续向后扫描。

这样我们只遍历一次字符串，**不产生任何拷贝**，时间是线性的。

> **类比**：把 `word` 想成一条生产线，指针 `i` 像是流水线上的检查员，`j` 记住了当前正在加工的相同零件的起点。当检查员发现零件种类变了（字符不相同）时，就把已经加工好的这段零件一次性打包（按照最大 9 件一盒），然后继续下一段。整个过程只需要走一遍生产线。

#### 代码（Python）

```python
def compress_optimal(word: str) -> str:
    n = len(word)
    comp = []                     # 用列表收集字符，最后一次性 join，省去字符串拼接的额外开销
    i = 0                         # 扫描指针

    while i < n:
        j = i                     # 记录当前连续块的起始位置
        # 向右移动 i，直到遇到不同的字符或到达字符串末尾
        while i < n and word[i] == word[j]:
            i += 1

        block_len = i - j         # 这段相同字符的长度

        # 按每 9 个一组拆分，写入结果
        while block_len > 9:
            comp.append('9')
            comp.append(word[j])
            block_len -= 9

        # 剩下的 1~9 个直接写入
        comp.append(str(block_len))
        comp.append(word[j])

    return ''.join(comp)          # 把列表拼成最终字符串
```

#### 复杂度

- **时间复杂度**：O(n) — 我们只遍历一次字符串，所有操作（计数、拆分、拼接）都是常数时间。可以把它想成“字符数翻倍的时间”，比如 200,000 个字符只需要大约 200,000 次基本操作，几乎是瞬间完成。  
- **空间复杂度**：O(n) — 需要存放压缩结果，最坏情况下每个原字符会被写成 “1a” 两个字符，所以结果长度最多是原字符串的两倍。额外的指针和计数变量都是 O(1)。

## 心得

- **核心技巧**：**一次线性扫描 + 按固定上限切块**。这是一种常见的“分块处理”思路，适用于所有需要把连续相同元素拆成固定大小块的题目。  
- **适用的类似题**：  
  1. **String Compression I/II**（把相同字符压缩成计数+字符，计数可以是多位数）  
  2. **Run-Length Encoding**（在图像处理或文件压缩中常见）  
  3. **Divide Array in Sets of K Consecutive Numbers**（把数组分成固定大小的连续块）  
- **一句话总结**：**只要把相同字符的连续段一次性找完，再按“最多 9”切块输出，就能在 O(n) 时间搞定**。

## 反思

- **第一反应**：看到“每次取相同字符的前缀，计数上限 9”，本能想到循环删字符的模拟——这就是暴力解。  
- **最容易踩的坑**：  
  - **计数上限**：忘记把长度大于 9 的块拆成多个 “9+char” 片段，导致输出错误。  
  - **边界条件**：字符串结尾处的最后一段如果不手动处理（比如在循环结束后没有再写入），会漏掉。  
  - **字符串拼接**：在 Python 中频繁使用 `+=` 会导致额外的拷贝，影响性能。  
- **下次遇到同类题**：第一步先**确定“连续块”的范围（用双指针/滑动窗口），然后**判断是否需要按固定大小切分**，最后一次性生成答案。这样就能直接走向线性最优解。
