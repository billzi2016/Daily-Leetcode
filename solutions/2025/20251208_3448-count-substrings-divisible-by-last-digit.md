# #3448. 按末位数字可整除的子串计数 / Count Substrings Divisible By Last Digit

> 难度：困难 · 标签：String、Dynamic Programming · [LeetCode 链接](https://leetcode.com/problems/count-substrings-divisible-by-last-digit/)

---

## 题目（英文原版）

**Description**

You are given a string s consisting of digits.
Return the number of substrings of s divisible by their non-zero last digit.
Note: A substring may contain leading zeros.

**Examples**

**Example 1:**

```
Input: s = "12936"
Output: 11
Explanation:
Substrings "29" , "129" , "293" and "2936" are not divisible by their last digit. There are 15 substrings in total, so the answer is 15 - 4 = 11 .
```

**Example 2:**

```
Input: s = "5701283"
Output: 18
Explanation:
Substrings "01" , "12" , "701" , "012" , "128" , "5701" , "7012" , "0128" , "57012" , "70128" , "570128" , and "701283" are all divisible by their last digit. Additionally, all substrings that are just 1 non-zero digit are divisible by themselves. Since there are 6 such digits, the answer is 12 + 6 = 18 .
```

**Example 3:**

```
Input: s = "1010101010"
Output: 25
Explanation:
Only substrings that end with digit '1' are divisible by their last digit. There are 25 such substrings.
```

**Constraints**

- 1 <= s.length <= 105
- s consists of digits only.

## 题目（中文翻译）

给定一个仅包含数字的字符串 `s`。  
返回 `s` 的子串（substring）中，能够被其非零末位数字整除的子串数量。  
注意：子串可以包含前导零（leading zeros）。

**示例 1**  
**输入**: `s = "12936"`  
**输出**: `11`  
**解释**:  
子串 `"29"`、`"129"`、`"293"` 和 `"2936"` 均不能被它们的末位数字整除。  
总共有 15 个子串，因此答案为 `15 - 4 = 11`。

**示例 2**  
**输入**: `s = "5701283"`  
**输出**: `18`  
**解释**:  
子串 `"01"`、`"12"`、`"701"`、`"012"`、`"128"`、`"5701"`、`"7012"`、`"0128"`、`"57012"`、`"70128"`、`"570128"` 和 `"701283"` 都能被它们的末位数字整除。  
此外，所有仅由一个非零数字组成的子串都能被自身整除。共有 6 个这样的数字，所以答案为 `12 + 6 = 18`。

**示例 3**  
**输入**: `s = "1010101010"`  
**输出**: `25`  
**解释**:  
只有以数字 `'1'` 结尾的子串能够被其末位数字整除。此类子串共有 25 个。

**约束条件**  
- `1 <= s.length <= 10^5`  
- `s` 仅由数字组成。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把字符串的所有子串枚举出来，逐个检查它们是否满足「能被最后一位非零数字整除」的条件。

- **枚举子串**：遍历左端点 `l`（从 `0` 到 `n-1`），再遍历右端点 `r`（从 `l` 到 `n-1`），子串就是 `s[l:r+1]`。  
- **取最后一位**：子串的最后一位就是 `s[r]`，如果它是 `'0'`，根据题意直接跳过，因为「除数不能为 0」。  
- **判断整除**：把子串转成整数 `num = int(s[l:r+1])`，判断 `num % int(s[r]) == 0`。

> **类比**：把所有子串想象成一大堆「小盒子」，我们一个一个打开（转成整数），看里面的数字能不能被盒子盖子（最后一位）整除。

只要遍历完所有 `(l, r)`，计数器 `ans` 加上满足条件的子串数量，即得到答案。

#### 代码（Python）

```python
def count_substrings_bruteforce(s: str) -> int:
    n = len(s)
    ans = 0
    # 枚举左端点
    for l in range(n):
        # 枚举右端点
        for r in range(l, n):
            last_digit = int(s[r])          # 子串的最后一位
            if last_digit == 0:             # 不能除以 0，直接跳过
                continue
            # 把子串转成整数（Python 支持大整数）
            num = int(s[l:r + 1])
            # 判断是否能被最后一位整除
            if num % last_digit == 0:
                ans += 1
    return ans
```

#### 复杂度

- **时间复杂度**：`O(n²)`  
  - 解释：我们有 `n` 个左端点，每个左端点内部又要遍历至多 `n` 次右端点，所以大约会执行 `n × n / 2` 次检查。对于 `n = 10⁵`，`n²` 已经是 10⁰⁰⁰⁰⁰，根本跑不完。
- **空间复杂度**：`O(1)`  
  - 只用了常数级的额外变量（计数器、临时整数），不随 `n` 增长。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**每次都要把子串重新转成整数**，这一步的代价很大。我们需要在遍历字符串一次的过程中，**增量地维护每个可能的除数（1~9）对应的余数计数**，这样就能在 `O(1)` 时间内判断「当前子串是否能被它的最后一位整除」。

关键观察：

1. **除数只可能是 1~9**（因为最后一位是非零数字）。  
2. 对于固定的除数 `d`，只要知道子串在除以 `d` 时的余数 `r`，再把一个新数字 `x` 加到子串右端，就可以用公式快速得到新的余数：  
   \[
   r' = (r \times 10 + x) \bmod d
   \]
   这就是「把旧的余数左移一位再加新数字」的数学写法。
3. 我们可以对每个位置 `i`，维护 **9×9 的表** `dp[d][r]`，表示「以当前位置结尾，余数为 `r`（除以 `d`）的子串数量」。  
   - `d` 取值 1~9（除数），`r` 取值 0~d-1（余数）。
4. 当遍历到新字符 `x = int(s[i])` 时：
   - 先把「只包含这个字符」的子串计入：如果 `x != 0`，它的余数 `0`（因为 `x % x == 0`），所以 `dp[x][0] += 1`。
   - 再遍历所有除数 `d`（1~9），对每个已有余数 `r`，把对应的子串「向右延伸」得到新余数 `r'`，并把计数累加到 `dp[d][r']`。
5. 每次更新完 `dp` 后，把 `dp[d][0]`（余数为 0，即能被 `d` 整除的子串）累加到答案 `ans`。

> **类比**：把每个除数 `d` 想象成一条「流水线」。子串在这条线上会留下「余数标签」。每加一个新数字，就把所有在流水线上的标签「向前推进」并重新打标。只要标签是 `0`，说明这条流水线上的子串已经满足「能被它的最后一位整除」的条件。

因为每次只需要遍历 9 个除数和每个除数最多 `d` 个余数（总共 45 次），时间是线性的 `O(9·n) = O(n)`，空间只需保存当前和上一轮的 `dp`（45 个整数），即 `O(1)`。

#### 代码（Python）

```python
def count_substrings_optimal(s: str) -> int:
    """
    使用增量余数 DP，时间 O(n)，空间 O(1)。
    """
    # dp[d][r] 表示「以当前字符结尾，除以 d 的余数为 r 的子串数量」。
    # 只需要 1~9，余数范围 0~d-1。
    dp = [[0] * d for d in range(10)]   # dp[0] 位置空置，方便下标对应除数
    ans = 0

    for ch in s:
        x = int(ch)                     # 当前字符对应的数字

        # 1️⃣ 先处理只包含当前字符的子串
        if x != 0:                      # 除数不能为 0
            dp[x][0] += 1               # 余数 0，说明它能被自己整除
            ans += 1                    # 立即计入答案

        # 2️⃣ 再把已有的子串「向右延伸」到当前位置
        # 为了不把本轮新加的计数再次延伸，需要先拷贝一份旧的 dp
        old_dp = [row[:] for row in dp]

        for d in range(1, 10):          # 遍历可能的除数 1~9
            if d == x:                  # 已经在上一步把只含当前字符的情况计入，这里可以继续
                pass
            for r in range(d):          # 余数范围 0~d-1
                cnt = old_dp[d][r]      # 之前以 i-1 位置结尾、余数为 r 的子串数量
                if cnt == 0:
                    continue
                # 新余数 = (旧余数 * 10 + 当前数字) % d
                new_r = (r * 10 + x) % d
                dp[d][new_r] += cnt
                # 若新余数为 0，则这些子串在此位置满足条件
                if new_r == 0:
                    ans += cnt

    return ans
```

> **实现细节说明**  
> - `old_dp` 的拷贝是必须的，否则在同一次循环里把新产生的计数再次「向右延伸」，会导致重复计数。  
> - 由于 `dp` 的规模极小（最多 45 个整数），拷贝的代价可以忽略不计。如果想进一步压缩常数，也可以使用两套数组交替更新。

#### 复杂度

- **时间复杂度**：`O(n)`  
  - 解释：对每个字符，只循环 9 次除数，每次除数内部最多遍历 `d`（≤9）个余数，总操作数固定在 45 左右，随 `n` 成线性增长。相比暴力的 `n²`，速度提升了几个数量级。
- **空间复杂度**：`O(1)`  
  - 只用了 9×9（实际 45）个整数的固定表，和常数级的临时变量，与输入长度无关。

## 心得

- **核心技巧**：利用**余数的递推公式**，对每个可能的除数（1~9）维护余数计数，实现**线性时间**的子串整除统计。  
- **适用场景**：  
  1. 「统计满足某种模条件的子串」——如「子串之和能被 k 整除」(前缀和 + 余数计数)。  
  2. 「子串对应的数值在除以固定小整数时的余数」——本题的「除数只可能是 1~9」的特例。  
  3. 「需要在一次遍历中动态维护多种状态」——如「双指针 + 计数」或「滑动窗口 + 余数表」等。  
- **一句话总结**：**把“除以最后一位”转化为“对 1~9 的余数递推”，用小表记状态，一遍扫描即得答案。**

## 反思

- **第一反应**：看到「子串」和「整除」就想到「枚举所有子串」——最直观但最慢的办法。  
- **最容易踩的坑**：  
  - 忘记 **跳过最后一位为 0** 的子串，会导致除以 0 的错误。  
  - 在 DP 更新时 **没有使用旧状态**，导致同一轮中产生的子串被二次延伸，计数翻倍。  
  - 误以为可以直接把 `int(s[l:r+1])` 放进循环，忽视 Python 大整数在 `n=10⁵` 时的性能瓶颈。  
- **下次遇到同类题**：第一步先问自己「除数的取值范围是否有限？」如果是，立刻考虑 **模递推 + 余数计数** 的思路，而不是盲目枚举。
