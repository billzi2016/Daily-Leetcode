# #3270. 找出数字的钥匙 / Find the Key of the Numbers

> 难度：简单 · 标签：Math · [LeetCode 链接](https://leetcode.com/problems/find-the-key-of-the-numbers/)

## 题目（英文原版）

**Description**

You are given three positive integers num1, num2, and num3.
The key of num1, num2, and num3 is defined as a four-digit number such that:
Return the key of the three numbers without leading zeros (if any).

**Examples**

**Example 1:**

```
Input: num1 = 1, num2 = 10, num3 = 1000
Output: 0
Explanation:
On padding, num1 becomes "0001" , num2 becomes "0010" , and num3 remains "1000" .
Hence, the key is "0000" , i.e. 0.
```

**Example 2:**

```
Input: num1 = 987, num2 = 879, num3 = 798
Output: 777
```

**Example 3:**

```
Input: num1 = 1, num2 = 2, num3 = 3
Output: 1
```

**Constraints**

- 1 <= num1, num2, num3 <= 9999

## 题目（中文翻译）

给定三个正整数 `num1`、`num2` 和 `num3`。  
将这三个数分别左侧补零，使其均为四位数（four‑digit number），记为 `s1`、`s2`、`s3`。  
这三个数的 **钥匙** 定义为一个四位数 `k`，其中第 `i` 位（从左到右，`i = 1 ~ 4`）是 `s1`、`s2`、`s3` 在第 `i` 位上的最小数字。  

返回该钥匙对应的整数值，去掉可能的前导零（leading zeros）。

**示例 1**  
> **输入**: `num1 = 1, num2 = 10, num3 = 1000`  
> **输出**: `0`  
> **解释**:  
> - 左侧补零后，`num1` → `"0001"`，`num2` → `"0010"`，`num3` → `"1000"`。  
> - 各位最小值分别为 `0、0、0、0`，得到钥匙 `"0000"`，即整数 `0`。

**示例 2**  
> **输入**: `num1 = 987, num2 = 879, num3 = 798`  
> **输出**: `777`  

**示例 3**  
> **输入**: `num1 = 1, num2 = 2, num3 = 3`  
> **输出**: `1`  

**约束条件**  
- `1 ≤ num1, num2, num3 ≤ 9999`   (所有输入均为正整数且不超过四位数)

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把**所有可能的四位数**（从 `0000` 到 `9999`）一个一个枚举，看看哪个数满足题目给出的“关键数”规则。  
- **枚举**：把四位数想象成四个格子，每个格子里放 0~9 之间的数字。我们从 `0` 开始逐个检查，像在挑选密码一样。
- **验证**：对于每个候选四位数，逐位和 `num1、num2、num3` 的对应位比较。若在该位上出现次数 ≥2 的数字，则候选位必须等于这个数字；如果三位数字全不相同，则候选位必须是这三个数字的 **最小值**。只要全部四位都满足，就找到了答案。

这种办法虽然“慢”——要检查 10 000 个候选数，但因为搜索空间很小（只有四位），在实际运行时仍能接受。它的好处是**逻辑最清晰**，不需要提前想出怎样直接算出答案。

#### 代码（Python）

```python
def key_of_numbers_bruteforce(num1: int, num2: int, num3: int) -> int:
    # 把三个数统一成四位字符串，前面不足的用 '0' 填充
    s1, s2, s3 = str(num1).zfill(4), str(num2).zfill(4), str(num3).zfill(4)

    # 枚举 0 ~ 9999 的每一个四位数（整数形式）
    for cand in range(10000):
        cand_str = str(cand).zfill(4)          # 同样补成四位
        ok = True                              # 标记当前候选是否满足规则

        # 检查每一位（从千位到个位）
        for i in range(4):
            digits = [s1[i], s2[i], s3[i]]      # 这三位的字符
            cnt = {}                           # 统计出现次数，类似字典查词典
            for d in digits:
                cnt[d] = cnt.get(d, 0) + 1

            # 如果有数字出现了两次或三次，候选位必须等于它
            if any(v >= 2 for v in cnt.values()):
                # 找出出现次数≥2的那个数字（必然唯一）
                target = next(k for k, v in cnt.items() if v >= 2)
                if cand_str[i] != target:
                    ok = False
                    break
            else:
                # 三个数字全不相同，候选位必须是最小的那个
                if cand_str[i] != min(digits):
                    ok = False
                    break

        if ok:                     # 找到第一个满足条件的候选数
            return int(cand_str)   # 转成整数自动去掉前导零

    return 0   # 按题意一定能找到，这行只是防止函数缺少返回
```

#### 复杂度

- **时间复杂度**：`O(10000 × 4) ≈ O(1)`  
  实际上只遍历了 10 000 个候选数，每个只检查四位，常数很小。用大 O 记号写成 `O(1)`，因为上界不随输入规模（`num1、num2、num3` 的大小）增长。
- **空间复杂度**：`O(1)`  
  只用了几个长度为 4 的字符串和常数个临时变量，空间使用与输入规模无关。

### 2. 最优解

#### 思路  

暴力解的**慢点**在于“遍历所有候选”。其实我们完全可以**直接算出每一位的答案**，不需要猜。

1. **把三个数都补成四位**（`zfill(4)`），这样每一位都有对应的字符。可以把四位看成四个“列”，每列里有三个数字。  
2. **对每一列**，统计这三个数字出现的次数（相当于在“查字典”：键是数字，值是出现次数）。  
   - 如果有数字出现 **≥2 次**，那它就是关键数该列的数字（因为它是多数）。  
   - 否则说明 **全不相同**，此时题目要求取这三个数字的 **最小值**。  
3. 把四列得到的数字拼成一个四位字符串，再转换为整数即可去掉前导零。

核心的数据结构是 **哈希表（字典）**，它的作用类似查字典：  
- **key** → 某一位的数字（字符 `'0'~'9'`）  
- **value** → 这个数字在该列出现了几次  

因为每列只有三个数字，统计过程非常轻量，整个算法只遍历四列，时间几乎是常数。

#### 代码（Python）

```python
def find_key(num1: int, num2: int, num3: int) -> int:
    # 1. 统一为四位字符串，前面不足补 0
    s1, s2, s3 = str(num1).zfill(4), str(num2).zfill(4), str(num3).zfill(4)

    res = []                     # 用来收集每一位的结果

    # 2. 逐位处理（0 表示千位，1 表示百位，...）
    for i in range(4):
        a, b, c = s1[i], s2[i], s3[i]   # 取出该列的三个字符

        # 用字典统计出现次数
        cnt = {}
        for d in (a, b, c):
            cnt[d] = cnt.get(d, 0) + 1

        # 3. 判断多数或全不相同
        #   any(v >= 2 for v in cnt.values()) → 是否有出现≥2次的数字
        if any(v >= 2 for v in cnt.values()):
            # 出现≥2次的数字必唯一，直接取出来
            key_digit = next(k for k, v in cnt.items() if v >= 2)
        else:
            # 全不相同，取最小的那个
            key_digit = min(a, b, c)

        res.append(key_digit)     # 把得到的字符加入结果列表

    # 4. 合成四位字符串并转成整数（自动去掉前导零）
    return int(''.join(res))
```

#### 复杂度

- **时间复杂度**：`O(4) = O(1)`  
  只遍历了四列，每列做常数次的字典操作，时间不随输入大小变化。相比暴力的 10 000 次遍历，快了几个数量级。
- **空间复杂度**：`O(1)`  
  只用了几个长度为 4 的字符串和一个小字典，空间使用固定。

## 心得

- **核心技巧**：**逐位统计**（使用哈希表）+ **多数或最小值** 的规则。  
- **适用的题型**  
  1. 多个整数的对应位“投票”或“多数”决定结果（如 “Find the Majority Element of Digits”）。  
  2. 按位比较并取 **最小/最大/多数** 的题目（如 “Maximum of Three Numbers per Digit”）。  
- **一句话总结**：**把每一位当成独立的小问题，用字典统计出现次数，最多的就是答案；若没有多数，就取最小值。**

## 反思

- **第一反应**：看到“关键数是四位数，要求每位满足某种规则”，立刻想到把数字补齐成四位，再逐位比较。  
- **最容易踩的坑**  
  - **前导零**：直接把整数转成字符串会丢掉高位的 `0`，必须使用 `zfill(4)` 或 `format(num, '04d')` 保留四位。  
  - **全部相同的情况**：如果三位数字全相同，出现次数≥2，直接返回该数字即可；不要再去取 `min`，否则会出错。  
  - **返回值的格式**：题目要求“去掉前导零”。`int('0000')` 会得到 `0`，符合要求，但直接返回字符串会保留零，需要手动转换。  
- **下次类似题目第一步**：先把所有数统一成相同位数的字符串（或数组），再**逐位**进行统计或比较，而不是一次性处理整个整数。这样思路更清晰，代码也更容易写对。
