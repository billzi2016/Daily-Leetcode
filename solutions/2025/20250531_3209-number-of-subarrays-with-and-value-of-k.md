# #3209. 与值为 K 的子数组个数 / Number of Subarrays With AND Value of K

> 难度：困难 · 标签：Array、Binary Search、Bit Manipulation、Segment Tree · [LeetCode 链接](https://leetcode.com/problems/number-of-subarrays-with-and-value-of-k/)

## 题目（英文原版）

**Description**

Given an array of integers nums and an integer k, return the number of subarrays of nums where the bitwise AND of the elements of the subarray equals k.

**Examples**

**Example 1:**

```
Input: nums = [1,1,1], k = 1
Output: 6
Explanation:
All subarrays contain only 1's.
```

**Example 2:**

```
Input: nums = [1,1,2], k = 1
Output: 3
Explanation:
Subarrays having an AND value of 1 are: [ 1 ,1,2] , [1, 1 ,2] , [ 1,1 ,2] .
```

**Example 3:**

```
Input: nums = [1,2,3], k = 2
Output: 2
Explanation:
Subarrays having an AND value of 2 are: [1, 2 ,3] , [1, 2,3 ] .
```

**Constraints**

- 1 <= nums.length <= 105
- 0 <= nums[i], k <= 109

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把所有子数组枚举出来，逐个计算它们的 **按位与**（bitwise AND），看是否等于 `k`。

- **枚举子数组**：用两个循环，外层固定左端点 `l`，内层把右端点 `r` 从 `l` 往后推进。  
- **计算 AND**：把子数组里的每个数依次做 `&` 运算，得到子数组的 AND 值。  
- **计数**：如果得到的值恰好是 `k`，就把答案加一。

> **类比**：把数组想成一本书，每一页是一个数字。我们要把 **每一段连续的页**（子数组）都读一遍，并把这些页上的文字 **逐字逐句做“与”运算**（相当于把每个字符都变成 0/1 再取交集），看最后的结果是否正好是我们想要的 `k`。

> **为什么一定对**：因为我们把 **所有可能的子数组** 都检查了一遍，遗漏的子数组自然不会出现，符合题目要求。

#### 代码（Python）

```python
def countSubarrays_bruteforce(nums, k):
    n = len(nums)
    ans = 0
    # 外层枚举左端点 l
    for l in range(n):
        cur = nums[l]                 # 当前子数组的 AND 值，先放第一个元素
        # 内层枚举右端点 r
        for r in range(l, n):
            if r > l:                 # r>l 时才需要再做一次 & 运算
                cur &= nums[r]
            if cur == k:              # 如果等于 k，计数
                ans += 1
    return ans
```

- `cur` 用来保存从 `l` 到 `r` 的 AND 结果，避免每次都重新遍历子数组。
- 每一次 `cur &= nums[r]` 都是 **把新加入的页** 和已有的 AND 结果做交集。

#### 复杂度

- **时间复杂度**：`O(n²)`  
  两层循环每层最坏会跑 `n` 次，整体是 `n × n`，即 **平方级**。如果把 `n = 10⁵` 代进去，`n² = 10¹⁰`，在电脑上跑几分钟甚至几小时都来不及。

- **空间复杂度**：`O(1)`  
  只用了常数个额外变量 (`cur`, `ans`)，和数组长度无关。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **每个左端点 `l` 都要遍历到右端点 `r`，导致二次遍历**。  
观察 **按位与的单调性**：

> 对固定的左端点 `l`，当我们把右端点向右移动 (`r` 递增) 时，子数组的 AND 值 **只能保持不变或变小**（因为 `a & b ≤ a`）。

这点和 **求子数组的最小值**、**求子数组的最大值** 时的单调性类似。利用单调性，我们可以在遍历数组的同时 **维护所有以当前元素结尾的子数组的 AND 值**，并记录每种 AND 值出现了多少次。关键在于：

1. **每加入一个新元素 `x = nums[i]`，所有旧的子数组 (ending at i‑1) 的 AND 值都会再与 `x` 做一次 & 运算**。  
2. **由于 AND 只能下降，相同的 AND 值会合并**，所以同一位置最多出现 **bit 位数+1**（约 31~32）种不同的 AND 值。  

这样，我们只需要 **遍历一次数组**，在每一步用一个哈希表（`dict`）保存「**当前 AND 值 → 出现次数**」的映射，更新后把其中等于 `k` 的次数加到答案里。

> **类比**：把每个数字看成一把钥匙，所有钥匙叠在一起按位与后只能变得更「紧」或保持原样。我们把「当前紧度」记在一个小盒子里（字典），每次放进新钥匙，只需要把盒子里的每个紧度再和新钥匙一起再紧一次，重复这个过程即可。

下面把这个思路拆成若干步：

1. 初始化一个空字典 `prev = {}`，表示「上一个位置结束的子数组的 AND 值」。
2. 遍历数组 `nums`，对于每个 `x = nums[i]`：
   - 创建新字典 `curr = {}`。
   - 把只包含 `x` 的子数组加入：`curr[x] = 1`（出现一次）。
   - 对 `prev` 中的每个 `(val, cnt)`，计算 `new_val = val & x`，把 `cnt` 加到 `curr[new_val]` 上（表示把 `x` 接在这些子数组后面）。
   - 把 `curr` 中键值为 `k` 的计数加到答案 `ans`。
   - 将 `curr` 赋值给 `prev`，进入下一轮。
3. 最终 `ans` 即为所有子数组的数量。

因为每一步 `prev` 的键数最多是 31（整数最多 30~31 位），整体时间复杂度是 **`O(n * B)`**，其中 `B` 为整数的位数（常数），实际是线性 `O(n)`。

#### 代码（Python）

```python
def countSubarrays(nums, k):
    """
    返回子数组的个数，使得子数组所有元素的按位与恰好等于 k。
    只遍历一次数组，时间 O(n * 31)，空间 O(31)。
    """
    ans = 0                     # 最终答案
    prev = {}                   # 上一位置结束的子数组的 AND 值 → 次数

    for x in nums:              # 逐个遍历数组
        curr = {}                # 当前位置结束的子数组的 AND 值 → 次数

        # 1）只含当前元素的子数组
        curr[x] = 1

        # 2）把之前的子数组都接上当前元素，重新计算 AND
        for val, cnt in prev.items():
            new_val = val & x    # 再与当前元素做按位与
            # 把相同的 new_val 合并计数
            curr[new_val] = curr.get(new_val, 0) + cnt

        # 3）把 AND 等于 k 的子数组计数加入答案
        ans += curr.get(k, 0)

        # 4）准备进入下一个元素
        prev = curr

    return ans
```

- `curr.get(new_val, 0) + cnt` 用来 **合并相同的 AND 结果**，防止字典里出现重复键。
- `prev`、`curr` 的大小始终 ≤ 31，几乎可以视作常数空间。

#### 复杂度

- **时间复杂度**：`O(n * B)`，这里 `B` 为整数的二进制位数（≤ 30），所以实际是 **线性** `O(n)`。  
  与暴力解的 `O(n²)` 相比，速度提升了 **从平方级到线性级**，即使 `n = 10⁵` 也能在毫秒级完成。

- **空间复杂度**：`O(B)`，只保存当前位置的 AND 值集合，最多约 31 个键，算作 **常数级** `O(1)`。

## 心得

- **核心技巧**：**利用按位与的单调下降特性**，在遍历时维护「所有以当前位置结尾的子数组的 AND 值」的计数。  
- **适用的类似题型**：  
  1. **子数组按位或（OR）等于目标值**（同理，只是 OR 是单调不减）。  
  2. **子数组异或（XOR）等于目标值**（需要前缀异或 + 哈希表）。  
  3. **子数组最小值/最大值计数**（使用单调栈或类似的 “维护所有可能值” 思路）。
- **一句话总结**：**把“所有以 i 结尾的子数组的 AND”压缩成至多 31 种状态，边遍历边统计**。

## 反思

- **第一反应**：直接枚举子数组，写两层循环，感觉最安全。  
- **最容易踩的坑**：  
  - 忘记合并相同的 AND 值，导致字典膨胀到 `O(n²)`。  
  - 忽视 `k = 0` 或 `k` 本身不可能出现的情况（比如所有数的 AND 永远大于 `k`），导致答案错误。  
  - 处理整数的位数时忘记 Python 的整数是无限精度，实际位数受 `nums[i] ≤ 10⁹` 限制，最多 30 位即可。  
- **下次遇到同类题**，第一步就要思考 **“这个运算随区间扩大是单调的么？”**，如果是单调的，就尝试 **“维护以当前位置结束的所有可能值的计数”**，再在遍历过程中直接累计答案。
