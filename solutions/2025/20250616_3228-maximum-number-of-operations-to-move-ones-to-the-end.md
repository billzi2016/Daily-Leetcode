## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**每一次都把最左边可以移动的 `1` 往右搬**。  
这里的“搬”指的是把这个 `1` 和它右边紧邻的 `0` 交换位置（相当于一次相邻交换），
这样 `1` 向右走了一步，`0` 向左走了一步。  
只要字符串里还有形如 `10` 的相邻子串，就可以继续操作。

> **类比**：把 `1` 想成一只想跑到队伍末尾的小兔子，`0` 是挡在它前面的石头。  
> 每一次操作就是把小兔子和它左边最近的那块石头互换位置——把石头让给小兔子走一步。

只要把所有可能的相邻 `10 → 01` 都做完，最终的字符串一定会变成所有 `0` 在左，所有 `1` 在右的“有序”形态。

**为什么正确**  
- 只要还有 `10`，就一定可以让左边的 `1` 再往右走一步，最终所有 `1` 必然会被推到最右侧。  
- 每一次相邻交换只能消除 **一个** 逆序对（即一个 `1` 在 `0` 左边的情况），所以把所有逆序对都消除掉，就是操作的最大次数。

**复杂度分析**  
- 暴力模拟每一次相邻交换，需要遍历整个字符串寻找 `10`，最坏情况下每次只能消除一个逆序对，逆序对的数量最多是 `O(n²)`（当所有字符都是 `1…10…0` 时）。  
- 空间上只需要保存原字符串，`O(1)`。

> **大白话**：如果字符串长度是 10⁵，`O(n²)` 相当于 10¹⁰ 次操作，根本跑不完。

#### 代码（Python）

```python
def maxOperations_bruteforce(s: str) -> int:
    s = list(s)                 # 把字符串转成列表，方便原地交换
    n = len(s)
    ops = 0                     # 记录完成的操作次数

    while True:
        made_move = False
        # 从左到右扫描，寻找相邻的 "10"
        for i in range(n - 1):
            if s[i] == '1' and s[i + 1] == '0':
                # 交换位置，等价于一次操作
                s[i], s[i + 1] = s[i + 1], s[i]
                ops += 1
                made_move = True
                break          # 每轮只做一次最左侧的交换
        if not made_move:      # 已经没有 "10" 了，结束
            break
    return ops
```

#### 复杂度

- **时间复杂度**：`O(n²)`  
  - 最坏情况下每次只能消除一个逆序对，逆序对总数可能是 `n/2 * n/2 ≈ n²/4`，所以总体是二次方级别。
- **空间复杂度**：`O(1)`（只用了常数个额外变量）。

### 2. 最优解

#### 思路  

从暴力解可以看到，**每一次操作只消除一个逆序对**（`1` 在 `0` 左边的情况）。  
所以，**最大可以进行的操作次数 = 字符串中所有逆序对的数量**。

> 逆序对的定义：下标 `i < j`，且 `s[i] = '1'`、`s[j] = '0'`。  
> 每出现一次这样的 `(i, j)`，就可以想象一次 `1` 必须跨过这个 `0`，对应一次相邻交换。

于是问题转化为：**统计所有 `1` 左边的 `0` 有多少对**。  
这可以在一次线性遍历中完成：

1. 从左到右遍历字符串。  
2. 维护一个计数 `ones`，表示当前已经看到的 `'1'` 的数量。  
3. 当遍历到 `'0'` 时，所有在它左边的 `'1'` 都需要跨过它一次，  
   因此把 `ones` 累加到答案 `ans` 中。  
4. 当遍历到 `'1'` 时，`ones` 加一，表示后面的 `'0'` 以后会被它“跨过”。

这样 **每个字符只访问一次**，时间是 `O(n)`，空间只用了几个整数，`O(1)`。

> **类比**：把所有已经站好的小兔子（`1`）记在一本小册子里（`ones`）。  
> 当一块石头（`0`）出现时，这本小册子里记的每只小兔子都要踩一次石头才能继续前进，  
> 所以这块石头贡献的操作次数就是“小册子里小兔子的数量”。

#### 代码（Python）

```python
def maxOperations(s: str) -> int:
    """
    统计字符串中所有逆序对的数量，即 1 在左、0 在右 的 (i, j) 对数。
    """
    ones = 0          # 已经出现的 '1' 的数量
    ans = 0           # 累计的逆序对（即最大操作次数）

    for ch in s:
        if ch == '1':
            ones += 1                 # 以后遇到的每个 '0' 都会被这个 '1' 跨过
        else:  # ch == '0'
            ans += ones               # 当前的每个 '1' 都需要一次操作跨过这个 '0'

    return ans
```

#### 复杂度

- **时间复杂度**：`O(n)`  
  - 只需一次遍历，`n` 为字符串长度。  
  - 对比暴力的 `O(n²)`，大幅提升，10⁵ 长度的字符串在毫秒级别即可完成。

- **空间复杂度**：`O(1)`  
  - 只使用了常数个整型变量（`ones`、`ans`），不随输入规模增长。

## 心得

- **核心技巧**：把“最多能做多少次相邻交换”转化为“统计逆序对的数量”。  
- **适用场景**：  
  1. 统计二进制字符串中 `1` 在左、`0` 在右的对数（如本题）。  
  2. 任意数组中统计 “左大右小” 的逆序对数量（常见的 **逆序对计数**），可用于判断数组是否已经有序。  
  3. 类似 “把所有 `a` 移到左边、`b` 移到右边” 的搬运类贪心问题。

> **解题钥匙**：**每一次操作只对应一个逆序对 → 最大操作数 = 逆序对总数**。

---

## 反思

- **第一反应**：看到“把 `1` 移到末尾”，立刻想到相邻交换（冒泡）或把 `1` 直接搬到最右侧。  
- **最容易踩的坑**：  
  - 把“一次搬到最右”误认为只算一次操作，导致答案偏小。  
  - 忽略了每个 `0` 需要被左边所有 `1` 跨过，导致漏算逆序对。  
  - 边界条件：全是 `0` 或全是 `1` 时答案应为 `0`，代码要能自然处理。  
- **下次思路**：遇到“移动 / 排序” 且“只能一步一步移动” 的题目时，先问自己“每一步到底消除/产生了多少个逆序对”，如果是“恰好消除一个”，答案往往是 **逆序对的总数**，可以用一次线性遍历配合计数器完成。
