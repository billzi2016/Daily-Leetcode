# #3363. 收集水果的最大数量 / Find the Maximum Number of Fruits Collected

> 难度：困难 · 标签：Array、Dynamic Programming、Matrix · [LeetCode 链接](https://leetcode.com/problems/find-the-maximum-number-of-fruits-collected/)

## 题目（英文原版）

**Description**

There is a game dungeon comprised of n x n rooms arranged in a grid.
You are given a 2D array fruits of size n x n, where fruits[i][j] represents the number of fruits in the room (i, j). Three children will play in the game dungeon, with initial positions at the corner rooms (0, 0), (0, n - 1), and (n - 1, 0).
The children will make exactly n - 1 moves according to the following rules to reach the room (n - 1, n - 1):
When a child enters a room, they will collect all the fruits there. If two or more children enter the same room, only one child will collect the fruits, and the room will be emptied after they leave.
Return the maximum number of fruits the children can collect from the dungeon.

**Examples**

**Example 1:**

```
Input: fruits = [[1,2,3,4],[5,6,8,7],[9,10,11,12],[13,14,15,16]]
Output: 100
Explanation:

In this example:
In total they collect 1 + 6 + 11 + 16 + 4 + 8 + 12 + 13 + 14 + 15 = 100 fruits.
```

**Example 2:**

```
Input: fruits = [[1,1],[1,1]]
Output: 4
Explanation:
In this example:
In total they collect 1 + 1 + 1 + 1 = 4 fruits.
```

**Constraints**

- 2 <= n == fruits.length == fruits[i].length <= 1000
- 0 <= fruits[i][j] <= 1000

## 题目（中文翻译）

有一个由 n × n 个房间 (room) 组成的 **游戏地下城 (game dungeon)**，房间以网格形式排列。  
给定一个大小为 n × n 的 **二维数组 (2D array)** `fruits`，其中 `fruits[i][j]` 表示房间 `(i, j)` 中的水果数量。  

三个小孩将在游戏地下城中玩耍，初始位置分别在角落房间 `(0, 0)`、`(0, n - 1)` 和 `(n - 1, 0)`。  
他们将按照以下规则恰好移动 `n - 1` 步，到达房间 `(n - 1, n - 1)`：

- 当小孩进入某个房间时，会收集该房间的所有水果。  
- 如果有两个或更多小孩进入同一房间，只有其中一个小孩会收集水果，离开后该房间将被清空。

返回孩子们能够从地下城中收集的水果的最大总数。

**示例 1**  
Input: `fruits = [[1,2,3,4],[5,6,8,7],[9,10,11,12],[13,14,15,16]]`  
Output: `100`  
Explanation:  
在该示例中：他们总共收集了 `1 + 6 + 11 + 16 + 4 + 8 + 12 + 13 + 14 + 15 = 100` 个水果。

**示例 2**  
Input: `fruits = [[1,1],[1,1]]`  
Output: `4`  
Explanation:  
在该示例中：他们总共收集了 `1 + 1 + 1 + 1 = 4` 个水果。

**约束条件**  
- `2 <= n == fruits.length == fruits[i].length <= 1000`  
- `0 <= fruits[i][j] <= 1000`

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把 **三个人的每一步** 都枚举出来，然后把所有合法的走法逐一算分。  
- **每个人的状态** 可以用 `(i, j)` 表示它当前所在的房间坐标。  
- 因为只能向 “下” 或 “右” 前进（题目没有说可以左上方向走），从左上角走到右下角正好需要 `2·(n‑1)` 步。  
- **暴力枚举**：把三个人在每一步的四种组合（每个人向下或向右）全部遍历，记下每一步收集的水果数量。  

> **类比**：把每个人想象成一只小蜜蜂，`(i, j)` 就是它在花园里的坐标。我们要让三只蜜蜂同时在花园里飞，每一步它们只能往右或往下飞。最笨的办法就是把所有可能的飞行路线都写下来，逐个算分。

**为什么暴力是对的**  
只要我们把 **所有** 合法的走法都遍历一遍，必然会找到最优解。只要在遍历时保证：
1. 三只小孩的每一步都合法（只能向下或向右），  
2. 当两只或三只进入同一个房间时，只计一次水果，  

那么遍历完后最大的累计水果数就是答案。

**复杂度分析（大白话）**  
- 每只小孩有 `2·(n‑1)` 步，每一步有 2 种选择（下或右），所以单独一只的走法数是 `2^{2·(n‑1)}`，三只一起就是 `2^{3·2·(n‑1)}`，天哪，根本不可行！  
- 用更实际的说法：我们要维护 **三个人的坐标**，每个人的行坐标 `i` 在 `[0, n-1]`，列坐标 `j` 也在 `[0, n-1]`。所以状态空间大小是 `n·n·n·n·n·n = O(n^6)`，每次转移还有常数倍的分支。  
- **时间复杂度**：`O(n^6)`，这在 `n=1000` 时相当于 `10^{18}` 次操作，根本跑不完。  
- **空间复杂度**：同样是 `O(n^6)`，需要的内存也天文数字。

显然，暴力解只能帮助我们理清问题，却根本不可能通过测试。

#### 代码（Python）

```python
# 仅作思路演示，实际不可运行（会爆内存/时间）
def brute_fruits(fruits):
    n = len(fruits)
    best = 0

    # dfs 用来枚举三个人的所有路径
    def dfs(step, pos1, pos2, pos3, visited, cur):
        nonlocal best
        if step == 2 * (n - 1):                 # 已到终点
            best = max(best, cur)
            return

        # 每个人可以向下或向右
        moves = [(1, 0), (0, 1)]                # (dx, dy)
        for d1 in moves:
            nx1, ny1 = pos1[0] + d1[0], pos1[1] + d1[1]
            if not (0 <= nx1 < n and 0 <= ny1 < n): continue
            for d2 in moves:
                nx2, ny2 = pos2[0] + d2[0], pos2[1] + d2[1]
                if not (0 <= nx2 < n and 0 <= ny2 < n): continue
                for d3 in moves:
                    nx3, ny3 = pos3[0] + d3[0], pos3[1] + d3[1]
                    if not (0 <= nx3 < n and 0 <= ny3 < n): continue

                    # 计算这一步收获的水果（去重）
                    add = 0
                    for (x, y) in {(nx1, ny1), (nx2, ny2), (nx3, ny3)}:
                        if (x, y) not in visited:
                            add += fruits[x][y]
                    # 标记已访问的房间
                    new_visited = visited | {(nx1, ny1), (nx2, ny2), (nx3, ny3)}
                    dfs(step + 1,
                        (nx1, ny1), (nx2, ny2), (nx3, ny3),
                        new_visited, cur + add)

    # 初始位置已收集对应的水果
    start_visited = {(0, 0), (0, n - 1), (n - 1, 0)}
    start_sum = fruits[0][0] + fruits[0][n - 1] + fruits[n - 1][0]
    dfs(0, (0, 0), (0, n - 1), (n - 1, 0), start_visited, start_sum)
    return best
```

> **注释**：代码里用 `set` 保存已经被采集过的房间，以实现“同一房间只能收一次”。但正如上面说的，这种枚举在 `n=1000` 时根本不可能跑完。

#### 复杂度  

- **时间复杂度**：`O(n^6)`（状态数）× 常数（每步 8 种转移）≈ `O(n^6)`。  
  - 大白话：如果 `n=10`，大概要算 `10^6 = 1,000,000` 次；如果 `n=1000`，要算 `10^{18}` 次，根本不可能。  
- **空间复杂度**：`O(n^6)`，因为我们需要存储每一种可能的坐标组合。

### 2. 最优解  

#### 思路  

暴力解慢的根本原因是 **同时记录三个人的完整坐标**，导致状态空间爆炸。  
观察题目可以发现以下关键点：

1. **左上角的孩子 (0,0) 的路径唯一**  
   - 为了让另外两个孩子的路径不与它相交，唯一的安全路径只能是沿着左上到右下的 **主对角线** 前进（每一步同时向下+向右）。  
   - 因此这只孩子的贡献固定为 `∑_{k=0}^{n‑1} fruits[k][k]`（对角线之和），我们可以先把它算出来，后面只需要考虑剩下的两只孩子。

2. **剩下的两只孩子的路径互不相交**  
   - 一个从 **右上角** `(0, n‑1)` 开始，只能向 **下** 或 **左** 移动；  
   - 另一个从 **左下角** `(n‑1, 0)` 开始，只能向 **上** 或 **右** 移动。  
   - 最终它们都要到达 **右下角** `(n‑1, n‑1)`。  
   - 这正好与经典的 “两个人从两端走到终点、同格只能收一次” 的 **Cherry Pickup II**（二维 DP）问题结构相同，只是方向稍有区别。  

3. **把方向统一**  
   - 为了使用熟悉的 “从上往下” DP，我们把左下角的孩子的坐标 **翻转**：把整个网格 **上下翻转**，使得它变成 **从左上角** 出发、只能向 **右或下** 移动的形式。  
   - 翻转后，两个人都在 **同一个方向**（右/下）前进，只是起点不同。  

4. **核心状态**  
   - 设 `dp[i][j]` 表示 **在同一步**（即走了相同的步数 `t = i + j`）时，  
     - 第一个孩子位于 `(i, t‑i)`（行 `i`，列 `t‑i`），  
     - 第二个孩子位于 `(j, t‑j)`（行 `j`，列 `t‑j`），  
     - 两人收集的水果最大值。  
   - 由于同一步的列可以由 `t` 推出，所以只需要记录两个人的行号 `i, j`，**状态数降到 `O(n^2)`**。  

5. **状态转移**  
   - 上一步每个人可能是 **向下**（行号 +1）或 **向右**（列号 +1），对应四种组合：  
     ```
     (i-1, j-1)   (i-1, j)   (i, j-1)   (i, j)
     ```
   - 取这四种情况的最大值，加上本步两人所在格子的水果数（如果同格，只加一次）。  

6. **边界处理**  
   - 行、列必须在 `[0, n-1]` 范围内。  
   - 当某一步的列 `col = t - row` 超出范围时，该状态不可达，设为负无穷。  

7. **最终答案**  
   - 当走完 `2·(n‑1)` 步时，两人都到达右下角 `(n‑1, n‑1)`，即 `i = j = n‑1`。  
   - 加上已经预先算好的 **左上角孩子的对角线贡献**，即为题目要求的最大水果数。

> **类比**：想象两只蚂蚁在一张网格纸上爬，一只从左上角开始，另一只从右上角开始（翻转后也变左上角）。它们每走一步只能往右或往下，且只能踩一次同一个格子。我们只记录它们各自“爬到第几行”，因为列可以直接算出来。这样就把原本需要记 `四个坐标` 的状态压缩成只记 `两个行号`，大幅降低了搜索空间。

#### 代码（Python）

```python
from typing import List

def max_fruits(fruits: List[List[int]]) -> int:
    """
    最优解：动态规划 O(n^2) 时间、O(n) 空间
    """
    n = len(fruits)

    # 1️⃣ 左上角孩子只能走主对角线，先把它的贡献算出来
    diag_sum = sum(fruits[i][i] for i in range(n))

    # 2️⃣ 把左下角的孩子的路径上下翻转，使它也从左上角出发
    #    翻转后 grid2[i][j] = fruits[n-1-i][j]
    grid2 = [fruits[n - 1 - i] for i in range(n)]

    # 3️⃣ DP：dp[i][j] 表示在走了 t 步（t = i + j）后，
    #    第一个孩子在 (i, t-i) ，第二个孩子在 (j, t-j) 的最大水果数
    #    只保留上一行的 dp，空间 O(n)
    NEG = -10**18                     # 负无穷，用于不可达的状态
    dp = [[NEG] * n for _ in range(n)]
    dp[0][0] = fruits[0][0] + grid2[0][0]   # 两只孩子的起点都在 (0,0)，若同格只算一次

    # 总共要走 2*(n-1) 步，步数 t 从 1 到 2*(n-1)
    for t in range(1, 2 * (n - 1) + 1):
        # 新建一张表来存本轮的结果
        new_dp = [[NEG] * n for _ in range(n)]
        # i, j 分别是两只孩子的行号
        for i in range(max(0, t - (n - 1)), min(n, t + 1)):
            for j in range(max(0, t - (n - 1)), min(n, t + 1)):
                # 对应的列号
                col1 = t - i
                col2 = t - j
                if col1 >= n or col2 >= n:          # 超出边界直接跳过
                    continue

                # 取四种上一步的转移
                best_prev = NEG
                for pi in (i - 1, i):               # pi = i-1 (下) 或 i (右)
                    for pj in (j - 1, j):
                        if pi < 0 or pj < 0:
                            continue
                        best_prev = max(best_prev, dp[pi][pj])
                if best_prev == NEG:
                    continue

                # 本步收获的水果：两个格子如果是同一个，只加一次
                cur = fruits[i][col1] + grid2[j][col2]
                if i == j and col1 == col2:          # 同格
                    cur = fruits[i][col1]            # 只算一次
                new_dp[i][j] = best_prev + cur
        dp = new_dp

    # 两只孩子都到达右下角时 i=j=n-1
    two_players = dp[n - 1][n - 1]

    return diag_sum + two_players
```

**代码要点解释**  

| 行号 | 作用 | 中文解释 |
|------|------|----------|
| 7‑9  | 计算左上角孩子的对角线水果总和 | 这一步是“固定路径”，直接把对角线上的水果加进答案 |
| 12‑13| 把左下角孩子的网格上下翻转 | 把它的移动方向统一成“只向右或向下”，方便后面 DP |
| 17‑18| 初始化 DP 表，`dp[0][0]` 为两只孩子起点的水果（若同格只算一次） | 起点已经收集的水果要计入 |
| 22‑32| 主循环：遍历每一步的步数 `t`，并在每一步更新 `dp` | `t` 表示已经走了多少步，行号 `i, j` 决定列号 `col = t - row` |
| 26‑28| 计算当前格子所在的列号，若越界直接跳过 | 保证每一步都在合法的格子里 |
| 31‑35| 四种可能的前驱状态（上一步两人各是向下还是向右）取最大 | 这里相当于“把四种走法合并”，得到最优的前一步分数 |
| 38‑40| 计算本步收获的水果，若两人同格只加一次 | 关键：同一个房间只能收一次 |
| 44‑45| 最终答案是对角线贡献 + 两只孩子的 DP 结果 | 把三个人的贡献合并，得到最大水果数 |

#### 复杂度  

- **时间复杂度**：`O(n^2)`  
  - 主循环走 `2·(n‑1) = O(n)` 步；每一步内部遍历行号 `i`、`j`，每个最多 `n`，所以总体是 `O(n·n·n) = O(n^2)`（实际上常数因 `i,j` 的取值范围受 `t` 限制而更小）。  
  - 大白话：如果 `n = 1000`，大约需要遍历 `1,000,000` 次，完全可以在一秒内跑完。

- **空间复杂度**：`O(n)`（只保留上一轮的 `dp` 表）  
  - 只用了两张 `n×n` 的数组交替更新，实际占用约 `2·1000·1000 ≈ 2 MB`，对机器几乎没有压力。  
  - 大白话：只需要存每一行的几个数字，根本不占内存。

> 与暴力解相比，时间从天文数字 `10^18` 降到 `10^6`，空间也从 `10^18` 降到 `10^3`，提升巨大。

## 心得  

- **核心技巧**：把多人的路径问题转化为 **“同步步数 + 行号” 的二维 DP**，并利用 **路径方向统一（翻转）** 使状态压缩到 `O(n^2)`。  
- **适用场景**：  
  1. “两个人/多个人从不同起点走到同一点，不能重复计分”的 **Cherry Pickup** 系列题目。  
  2. “在网格上两条不相交的最优路径” 如 “两个机器人收集最大价值”。  
  3. “多条路径必须在同一步数上同步前进” 的动态规划模型。  
- **一句话总结**：把“三条路径”拆成“一条固定路径 + 两条可变路径”，再用 **行号同步 DP** 把状态压到 `O(n^2)`，即可得到最优解。

## 反思  

- **第一反应**：看到“三个人、同终点、不能重复计分”，立刻想到 **枚举所有路径**（暴力），但很快发现状态爆炸。  
- **最容易踩的坑**：  
  1. **路径方向不统一**：左下角孩子的移动方向和其他两位不同，直接套 DP 会出错，需要先翻转或旋转网格。  
  2. **同格只计一次**：在 DP 转移时忘记去重，会把同一个格子的水果算两遍，导致答案偏大。  
  3. **边界条件**：`i + j` 的步数 `t` 可能导致列号 `t‑i` 越界，需要仔细检查。  
- **下次遇到同类题**：第一步先 **判断是否存在“唯一路径”**（如对角线），把它固定；随后 **把所有可变路径统一方向**，再用 **同步步数 + 行号** 的二维 DP 思路去做状态压缩。这样既能保证正确性，又能把复杂度控制在 `O(n^2)` 以内。
