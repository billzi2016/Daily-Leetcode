## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**把每一次查询都枚举所有可能的加值**，看能否把数组变成全 0。  
- 每个查询 `queries[i] = [l, r]` 允许我们往下标区间 `[l, r]` 的每个元素**加上同一个整数**（可以是正数、负数，也可以是 0）。  
- 如果把每一次查询的加值记为 `v_i`，那么第 `j` 位最终的数值就是  

```
nums[j] + Σ ( v_i )   （所有 i 满足 l_i ≤ j ≤ r_i）
```

- 我们只需要找一组 `v_i` 使得上式对所有 `j` 都等于 0。

暴力做法就是**遍历所有 `v_i` 的组合**（每个 `v_i` 可以是任意整数），检验是否满足等式。  
这相当于在求解一个线性方程组，方程的个数是 `n`（数组长度），未知数的个数是 `m = len(queries)`。  
在编程里，最直观的实现就是：

1. 对每一个查询的加值 `v_i` 进行穷举（比如从 `-K` 到 `K`，`K` 随便取一个很大的数）。  
2. 用一个循环把所有查询的加值作用到 `nums` 上，得到最终数组。  
3. 检查是否全为 0，若是返回 `True`，否则继续尝试下一个组合。

**为什么这个方法能得到正确答案**  
因为我们把所有可能的加值都枚举了一遍，只要存在一组加值可以让数组全 0，枚举过程必然会碰到它。

**时间/空间复杂度**  

- 时间复杂度：`O( (2K+1)^m * n )`  
  - `m` 是查询的数量，`K` 是我们人为设定的搜索范围。  
  - 这个式子呈指数增长，`m` 只要稍微大一点（比如 10）就会爆炸。  
  - 用大白话说，就是“**每增加一次查询，就要把可能的情况翻几倍**”，根本跑不完。

- 空间复杂度：`O(n)`  
  - 只需要存一份复制的数组来模拟加值的过程。

显然，暴力解在 `n、m ≤ 10⁵` 的规模下根本不可行，只能用来帮助我们理解问题本质。

---

### 2. 最优解

#### 思路  

从暴力解可以看到，**我们并不需要真的去枚举所有加值**，只要能够在每一步“恰好”把当前元素调到 0 即可。  
关键在于：

1. **查询的加值是可以自由选择的**（只要是整数），所以我们可以在需要的时候才决定它的大小。  
2. 对下标 `i`，只有**左端点等于 `i` 的查询**能够在此刻改变 `i` 位置的累计加值；  
   而已经开始、但还没结束的查询会把它们的加值“带进来”。  
3. 因此我们可以**从左到右**遍历数组，维护一个“当前累计加值 `cur`”。  
   - `cur` 表示所有已经打开（左端点 ≤ i 且右端点 ≥ i）的查询对当前位置的总影响。  
4. 当来到位置 `i` 时：
   - 先把**在 `i` 处结束**的查询的影响减掉（因为它们不再作用于后面的元素），这一步可以用**差分数组 + 前缀和**实现。  
   - 此时 `cur` 就是“此刻已经固定在 `i` 的总加值”。  
   - 若**有查询的左端点是 `i`**，我们可以**任选一个**（例如第一个）来补足差值，使得 `nums[i] + cur = 0`。  
     - 设需要的补偿为 `need = -nums[i] - cur`。  
     - 把 `need` 加到这个查询的加值上，同时记住在该查询的右端点 `r+1` 处要把 `need` 减掉（因为它的影响到此为止）。  
   - 若**没有左端点是 `i`** 的查询，说明**我们已经失去调节的机会**，此时 `cur` 必须已经等于 `-nums[i]`，否则无解。  

整个过程只需要一次线性扫描，**不需要枚举**，也不需要求解线性方程组。

> **差分数组 + 前缀和的类比**  
> 想象我们在路上搬箱子，每搬进一个箱子就会在后面的路段一直背着它的重量，直到箱子被搬走（右端点）。  
> 差分数组就像在搬进箱子时在起点记下“+重量”，在搬出箱子时在终点记下“‑重量”。  
> 前缀和则是把这些记号累加起来，得到当前背的总重量 `cur`。

#### 代码（Python）

```python
def canTransform(nums, queries):
    """
    判断在按顺序处理所有区间查询后，是否能把 nums 变成全 0。
    每个查询可以往其区间内的每个元素加上任意整数（正负均可）。
    """
    n = len(nums)

    # 1️⃣ 把所有查询按照左端点收集起来，方便在遍历时快速取得
    from collections import defaultdict
    left_map = defaultdict(list)          # left_map[l] = [r1, r2, ...] 该左端点对应的右端点列表
    for l, r in queries:
        left_map[l].append(r)

    # 2️⃣ 差分数组，用来在右端点处撤销之前加入的加值
    diff = [0] * (n + 1)      # diff[i] 表示在 i 位置需要减去的累计值
    cur = 0                   # 当前累计加值（前缀和）

    for i in range(n):
        # 把在 i 位置应该减去的值加到 cur 上（相当于撤销已经结束的查询的影响）
        cur += diff[i]

        # ---------- 处理左端点为 i 的查询 ----------
        if i in left_map:
            # 需要让 nums[i] + cur 最终等于 0
            need = -nums[i] - cur      # 这一次我们要补足的值

            # 取列表中的第一个右端点作为“真正使用的查询”
            r = left_map[i][0]         # 只给第一个查询分配 need，其他的可以设为 0
            cur += need                # 现在 cur 已经被调到正确的值

            # 在 r+1 位置记下 -need，这样在后面遍历到 r+1 时就会把这份影响撤销
            diff[r + 1] -= need

            # 其余同起点的查询我们把加值设为 0（不做任何操作），不需要额外处理
        else:
            # 没有查询可以在这里调节，cur 必须已经恰好抵消 nums[i]
            if cur != -nums[i]:
                return False

    # 遍历完所有位置都没有冲突，即可成功把数组变成全 0
    return True
```

**代码要点注释**  

- `left_map`：把所有查询按照左端点分组，**相当于把“可以在这里调节的开关”提前准备好**。  
- `diff`：差分数组，**在右端点的下一位记录需要减去的值**，相当于“把重量卸下来”。  
- `cur`：当前累计的加值，**等价于前缀和**，随时告诉我们当前位置已经被多少“加值”影响。  
- `need = -nums[i] - cur`：**恰好把当前位置调到 0 所需的额外加值**。如果有左端点的查询，就把这份 `need` 交给其中的一个查询；如果没有，就只能检查 `cur` 是否已经满足。

#### 复杂度  

- **时间复杂度：`O(n + m)`**  
  - 只遍历一次数组 `O(n)`，以及一次遍历所有查询把它们放进 `left_map`，共 `O(m)`。  
  - 与暴力解的指数级相比，线性时间在 `10⁵` 规模下轻松跑完。  
- **空间复杂度：`O(n + m)`**  
  - `left_map` 保存每个左端点对应的右端点列表，最多存 `m` 条记录。  
  - `diff` 长度为 `n+1`，用于差分。  
  - 只用了线性额外空间。

## 心得

- **核心技巧**：**差分数组 + 前缀和** 配合**贪心的左端点处理**，把区间加值的“自由度”转化为一次线性扫描即可判断可行性。  
- **适用的题型**  
  1. “区间增量能否得到目标数组” 类题（如 LeetCode 1665. Minimum Initial Energy to Finish Tasks）。  
  2. “利用区间操作把数组变成全零/全一” 的问题（如 Zero Array Transformation II、Range Addition Queries）。  
- **解题钥匙**：**只在可以调节的左端点“补足差值”，其余位置必须已经恰好为目标**。

## 反思

- **第一反应**：把每个查询的加值都枚举，尝试所有组合。  
- **最容易踩的坑**  
  - 忘记在右端点 **+1** 位置撤销影响，导致后面的元素累计了不该有的加值。  
  - 误以为所有左端点的查询都必须使用，而实际上只需要给 **任意一个** 赋值即可。  
  - 忽视了 **没有左端点时必须已经满足目标** 的约束，导致错误地返回 `True`。  
- **下次遇到同类题**：第一步先**思考“哪里可以调节”，把问题转化为**前缀和 + 差分**，再用**贪心**在调节点补足差值。这样往往能在一次线性遍历中得到答案。
