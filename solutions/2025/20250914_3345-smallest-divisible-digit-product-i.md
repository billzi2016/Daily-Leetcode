# #3345. 最小可被整除的数字乘积 I / Smallest Divisible Digit Product I

> 难度：简单 · 标签：Math、Enumeration · [LeetCode 链接](https://leetcode.com/problems/smallest-divisible-digit-product-i/)

## 题目（英文原版）

**Description**

You are given two integers n and t. Return the smallest number greater than or equal to n such that the product of its digits is divisible by t.

**Examples**

**Example 1:**

```
Input: n = 10, t = 2
Output: 10
Explanation:
The digit product of 10 is 0, which is divisible by 2, making it the smallest number greater than or equal to 10 that satisfies the condition.
```

**Example 2:**

```
Input: n = 15, t = 3
Output: 16
Explanation:
The digit product of 16 is 6, which is divisible by 3, making it the smallest number greater than or equal to 15 that satisfies the condition.
```

**Constraints**

- 1 <= n <= 100
- 1 <= t <= 10

## 解题过程

### 1. 直觉解（暴力）

#### 思路  
最直接的想法就是**从 n 开始，一直往后检查**，直到找到满足“各位数字的乘积能被 t 整除”的数为止。  

- **要检查的东西**：一个整数的“各位数字乘积”。可以把数字想象成一串珠子，依次取出每颗珠子的数字（0~9），把它们相乘。  
- **数据结构**：只需要几个普通变量，**不需要额外的容器**。在 Python 中，把整数转成字符串遍历每个字符，就像把一本书的每一页（字符）都读一遍。  
- **为什么正确**：我们按照从小到大的顺序逐个尝试，每次都完整检查条件。只要找到第一个满足的数，它必然是“最小的”。  
- **复杂度分析**：  
  - **时间**：设我们最多检查 `k` 个数（题目提示 `k ≤ 10`），每个数需要遍历它的所有位数，位数大约是 `log10(num)`（比如 123 有 3 位）。所以时间是 `O(k·log10(num))`，在本题里常数很小，可以看作 **O(1)**。  
  - **空间**：只用了几个临时变量，和输入规模无关，**O(1)**。

#### 代码（Python）

```python
def digit_product(x: int) -> int:
    """返回整数 x 各位数字的乘积。"""
    prod = 1
    for ch in str(x):          # 把整数转成字符串，逐字符遍历
        prod *= int(ch)        # 把字符再转成数字并相乘
    return prod

def smallest_number(n: int, t: int) -> int:
    """返回 >= n 且各位乘积能被 t 整除的最小整数。"""
    cur = n                    # 从 n 开始尝试
    while True:
        if digit_product(cur) % t == 0:   # 判断能否被 t 整除
            return cur                    # 找到了，直接返回
        cur += 1                           # 否则检查下一个数
```

> **关键行注释**  
> - `str(x)`：把数字当成“文字”，方便逐位读取。  
> - `prod *= int(ch)`：把每位数字乘起来，类似把珠子一个接一个串在一起。  
> - `while True` 循环：不断往后找，直到满足条件为止。

#### 复杂度

- **时间复杂度**：`O(k·d)`，其中 `k` 是最多检查的次数（本题 ≤10），`d` 是数字的位数。因为 `k`、`d` 都很小，整体可以认为是 **O(1)**。  
- **空间复杂度**：`O(1)`，只用了常数个变量。

### 2. 最优解

#### 思路  
在本题的约束下（`1 ≤ n ≤ 100, 1 ≤ t ≤ 10`），**暴力逐个检查已经是最优**，因为：

1. **瓶颈**：唯一的耗时操作是计算数字乘积，这本身只需要遍历最多 3 位（100 以内的数），几乎可以忽略不计。  
2. **进一步优化**：如果把范围放大（比如 `n` 达到 10⁹），仍然可以保持相同思路，只是可能需要检查的次数会更多。但我们可以利用**数学性质**提前跳过一些不可能的数字，例如：  
   - 只要数字里出现 `0`，乘积必为 `0`，而 `0` 能被任意正整数 `t` 整除。于是只要找到包含 `0` 的数，就可以立刻返回。  
   - 对于 `t` 为质数（如 2、3、5、7），只要数字里出现对应因子的倍数（如偶数、3 的倍数、5），乘积就会被 `t` 整除。  

不过在本题的 **Easy** 级别，这些额外的技巧并不会让运行时间有明显提升。于是我们直接沿用上面的循环即可，代码更简洁，也更容易理解。

#### 代码（Python）

```python
def smallest_number_opt(n: int, t: int) -> int:
    """在题目约束下的最优实现——同样是线性搜索，但已充分利用了
    0 的特性，使得大多数情况下能很快结束。"""
    cur = n
    while True:
        # 若当前数字包含 0，则乘积为 0，必然满足可被 t 整除
        if '0' in str(cur):
            return cur
        # 否则普通检查乘积是否可被 t 整除
        if digit_product(cur) % t == 0:
            return cur
        cur += 1
```

> 这里多加了一行 `if '0' in str(cur):`，相当于在“看到零就停下来”，利用了 **0 乘任何数都等于 0** 的性质。

#### 复杂度

- **时间复杂度**：仍然是 `O(k·d)`，但因为出现 `0` 时可以提前返回，实际检查的次数往往更少。  
- **空间复杂度**：`O(1)`，没有额外存储。

## 心得

- **核心技巧**：**逐个枚举 + 位数乘积计算**。把“大数”拆成“一位一位”来看，利用字符串或取模运算遍历每位。  
- **适用题型**：  
  1. “找最小/最大满足某个位数属性的数”——如“各位和能被 k 整除”。  
  2. “位数乘积/和的特殊约束”——如 LeetCode 2585 “Number of Ways to Earn Points”。  
  3. “包含特定数字的最小数”——如“最小包含数字 7 的整数”。  
- **一句话总结**：**把大问题拆成“小位”逐个检查，按顺序搜索必然得到最小解。**

## 反思

- **第一反应**：看到“最小 ≥ n”，自然想到从 n 开始**往后遍历**，一步步验证条件。  
- **最容易踩的坑**：  
  - **位数乘积为 0** 时要记得 0 能被所有正整数整除，别忘了这点。  
  - **循环终止条件**：如果忘记 `return`，会出现无限循环。  
  - **边界**：`n` 可能已经满足条件，需要先检查再递增。  
- **下次类似题**，第一步应该想：**“能否直接枚举？”**，如果枚举范围很小（本题 ≤10 次），就直接用最朴素的遍历方案。这样既简单又可靠。
