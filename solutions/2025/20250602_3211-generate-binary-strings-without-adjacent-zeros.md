# #3211. 生成不含相邻零的二进制字符串 / Generate Binary Strings Without Adjacent Zeros

> 难度：中等 · 标签：String、Backtracking、Bit Manipulation · [LeetCode 链接](https://leetcode.com/problems/generate-binary-strings-without-adjacent-zeros/)

---

## 题目（英文原版）

**Description**

You are given a positive integer n.
A binary string x is valid if all substrings of x of length 2 contain at least one "1".
Return all valid strings with length n, in any order.

**Examples**

**Example 1:**

```
Input: n = 3
Output: ["010","011","101","110","111"]
Explanation:
The valid strings of length 3 are: "010" , "011" , "101" , "110" , and "111" .
```

**Example 2:**

```
Input: n = 1
Output: ["0","1"]
Explanation:
The valid strings of length 1 are: "0" and "1" .
```

**Constraints**

- 1 <= n <= 18

长度为 1 的有效字符串为: `"0"` 和 `"1"`。

**约束条件**  
- `1 <= n <= 18`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  
最直接的想法是**把所有可能的二进制字符串都列举出来**，然后逐个检查它们是否满足“相邻两个字符中至少有一个是 `1`”。  
- **数据结构**：我们可以把每一个候选字符串当成普通的 Python `str`，把所有符合要求的放进一个 `list`。  
- **生活化类比**：想象你手里有一本《二进制全书》，每一页都是一个长度为 `n` 的二进制串。我们把每一页都翻一遍（相当于遍历 `2^n` 种组合），把不符合规则的页撕掉，只留下符合规则的页。  
- **正确性**：因为我们枚举了**所有**可能的二进制串，凡是满足条件的必然被保留下来，凡是不满足的必然被过滤掉，所以答案一定完整且正确。  

#### 代码（Python）
```python
def generateBinaryStrings_bruteforce(n: int):
    """
    暴力枚举所有 2^n 种二进制字符串，然后过滤掉相邻出现两个 0 的情况。
    """
    res = []                     # 用来保存符合要求的字符串
    total = 1 << n               # 2^n，左移相当于 2 的 n 次方

    for mask in range(total):    # 依次取 0 ~ 2^n-1
        # 把整数 mask 转成长度为 n 的二进制字符串，zfill 用来补齐前导 0
        s = bin(mask)[2:].zfill(n)

        # 检查是否出现了 “00”
        if "00" not in s:        # 字符串里没有子串 "00" 就是合法的
            res.append(s)

    return res
```

#### 复杂度
- **时间复杂度**：`O(2^n * n)`  
  - 解释：我们要遍历 `2^n` 种可能，每一种都要检查一次是否含有 `"00"`，检查本身需要遍历整个字符串，长度是 `n`，所以乘起来就是 `2^n * n`。可以把它想象成“先把所有可能的钥匙排好队（`2^n` 把），再逐个用钥匙打开每一道门（每把钥匙要检查 `n` 步）”。  
- **空间复杂度**：`O(2^n * n)`（存放所有合法答案）  
  - 解释：最坏情况下（如 `n = 1`），合法字符串的数量接近 `2^n`，每个字符串占 `n` 个字符的空间。

### 2. 最优解

#### 思路  
暴力解的瓶颈在于**把所有组合都枚举了一遍**，即使很多组合在生成的早期就已经违背规则（出现了相邻的 `0`），我们仍然继续生成后面的字符，导致大量无用的工作。  
优化的关键是**在生成的过程中就把“不合法” 的分支剪掉**，这是一种典型的**回溯（Backtracking）**思路。

1. **从空字符串开始**，逐位往后构造。  
2. **记住上一个字符**：  
   - 如果上一个字符是 `0`，则**只能**在后面接 `1`（否则会出现 `00`）。  
   - 如果上一个字符是 `1`，则可以接 `0` 或 `1`。  
3. 当已经构造出长度为 `n` 的字符串时，把它加入答案列表。  
4. 递归返回时自动回溯，尝试另一条可能的分支。

这样我们只会遍历**所有合法的二进制树枝**，每条合法枝的长度正好是 `n`，而非法枝在出现 `00` 的那一刻就停止，不会继续往下扩展。

- **核心数据结构**：  
  - **列表 `path`**（或字符串）保存当前已经构造好的前缀，类似于“正在写的句子”。  
  - **答案列表 `ans`** 用来收集所有完整的合法句子。  
- **类比**：想象你在写一段只能出现“单个零或连续的多个一”的密码。每写下一个字符，你都要先检查前一个字符是否是 `0`，如果是，你只能写 `1`；如果不是，你可以自由选择 `0` 或 `1`。这样写到第 `n` 位时，你得到的每一段密码都是合规的。

#### 代码（Python）
```python
def generateBinaryStrings_backtrack(n: int):
    """
    使用回溯（深度优先搜索）直接生成所有满足「相邻两个字符中至少有一个 1」的二进制字符串。
    """
    ans = []                     # 最终答案列表

    def dfs(pos: int, path: list):
        """
        pos  : 当前已经填了多少位（0 .. n）
        path : 用列表保存已确定的字符，列表比字符串拼接更高效
        """
        if pos == n:             # 已经写满 n 位，得到一条合法答案
            ans.append(''.join(path))
            return

        # 上一位字符是什么？如果 pos==0 表示还没有字符，两个选择都可以
        if pos == 0 or path[-1] == '1':
            # 前一位是 1（或还没有字符），可以放 0 或 1
            path.append('0')
            dfs(pos + 1, path)   # 递归尝试下一位
            path.pop()           # 回溯，撤销刚才的选择

            path.append('1')
            dfs(pos + 1, path)
            path.pop()
        else:  # 前一位是 0，只能放 1
            path.append('1')
            dfs(pos + 1, path)
            path.pop()

    dfs(0, [])
    return ans
```

#### 复杂度
- **时间复杂度**：`O(F_{n+2})`，其中 `F_k` 为第 `k` 个斐波那契数。  
  - 解释：合法字符串的数量正好等于斐波那契数（因为每个 `0` 必须后面跟 `1`，相当于把问题拆成「以 `1` 结尾」和「以 `01` 结尾」两种情形），所以递归调用的次数与答案个数同阶。斐波那契数的增长速度大约是 `φ^n / √5`（`φ≈1.618`），远小于暴力解的 `2^n`。可以把它想象成“我们只走了森林里少数几条有路的枝杈”。  
- **空间复杂度**：`O(n)`（递归栈深度）+ `O(F_{n+2} * n)`（存放答案）  
  - 解释：递归深度最多是 `n`，每层只保存当前字符，所以额外的临时空间是线性的 `n`。答案本身的存储仍然需要所有合法字符串的空间。

## 心得

- **核心技巧**：回溯（Depth‑First Search） + 剪枝（在出现 `00` 时立即停止该分支）。  
- **适用的题型**  
  1. “生成所有满足特定约束的组合”——如**生成不含相邻相同字符的字符串**、**生成合法括号序列**。  
  2. “路径/序列中有局部约束”——如**不相邻的黑白棋子排布**、**无重复相邻数字的排列**。  
- **一句话总结解题钥匙**：**在构造的过程中把违规的分支提前剪掉，只有合法的枝条会继续生长**。

## 反思

- **第一反应**：直接枚举所有二进制串，然后过滤。虽然能跑通小样例，但很快发现 `n` 稍大（如 18）时会超时。  
- **最容易踩的坑**  
  - 忘记在递归结束条件（`pos == n`）时把当前路径加入答案，导致结果缺失。  
  - 在回溯时没有 `pop()`，导致路径被错误地保留，产生错误的字符串。  
  - 对 `n = 1` 的边界没有单独处理，导致只返回 `["1"]`（因为代码默认上一个字符是 `1`）。  
- **下次遇到同类题**：第一步想到“**能否在生成过程中就判断合法性并剪枝**”，如果可以，就立刻写出基于**回溯/DFS**的框架，再根据具体约束填充转移规则。
