## 题目（英文原版）

**Description**

You are given two positive integers n and k.
An integer x is called k-palindromic if:
An integer is called good if its digits can be rearranged to form a k-palindromic integer. For example, for k = 2, 2020 can be rearranged to form the k-palindromic integer 2002, whereas 1010 cannot be rearranged to form a k-palindromic integer.
Return the count of good integers containing n digits.
Note that any integer must not have leading zeros, neither before nor after rearrangement. For example, 1010 cannot be rearranged to form 101.

**Examples**

**Example 1:**

```
Input: n = 3, k = 5
Output: 27
Explanation:
Some of the good integers are:
```

**Example 2:**

```
Input: n = 1, k = 4
Output: 2
Explanation:
The two good integers are 4 and 8.
```

**Example 3:**

```
Input: n = 5, k = 6
Output: 2468
```

**Constraints**

- 1 <= n <= 10
- 1 <= k <= 9

## 题目（中文翻译）

**题目描述**  
给定两个正整数 `n` 和 `k`。  

- 若一个整数 `x` 的每一位数字在 **k-回文数**（k‑palindromic） 中出现的次数恰好为 `k`，则称 `x` 为 *k‑回文数*。

注意，整数在原始形式和重新排列后都 **不能出现前导零**。例如，`1010` 不能重新排列成 `101`（因为 `101` 只有 3 位且前导零被省略）。

**示例**


*示例 2*  
```
Input: n = 1, k = 4
Output: 2
Explanation:
唯一的两个好整数是 4 和 8。
```

*示例 3*  
```
Input: n = 5, k = 6
Output: 2468
Explanation:
（此处省略具体列举，直接给出结果。）
```

**约束条件**  
- `1 <= n <= 10`  
- `1 <= k <= 9`

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把 **所有** 长度为 `n`、首位不能为 `0` 的整数枚举出来，然后对每个整数：

1. 生成它的所有不同的排列（即所有可能的重新排列）。  
2. 检查这些排列里是否有 **回文且能被 `k` 整除** 的数。  
   - “回文” 就像镜子对称的字符串，正着读和倒着读一样。  
   - “能被 `k` 整除” 就相当于在字典里查“这本书的页码能否被 `k` 整除”。  

如果存在这样的一种排列，就把原整数计入答案。

**为什么可行？**  
因为题目只要求统计满足条件的整数个数，遍历所有可能的整数并逐一验证，必然可以得到正确答案。

**时间/空间复杂度（大白话）**  

- 枚举所有 `n` 位整数的数量是 `9 × 10^{n‑1}`（首位有 9 种选择，后面每位有 10 种）。  
- 对每个整数我们还要枚举它的全排列，最坏情况下要遍历 `n!` 种排列。  
- 所以总的时间大约是 **`O(9·10^{n‑1}·n!)`**，这在 `n = 10` 时已经是 **天文数字**（远远超过计算机的承受能力）。  
- 空间只需要保存几个临时字符串和计数器，属于 **`O(n)`**。

> 简单来说，这种暴力办法在实际运行时会卡死，只有在 `n` 很小（比如 `n ≤ 4`）时才可能跑得完。

#### 代码（Python）

```python
import itertools

def is_palindrome(s: str) -> bool:
    """判断字符串是否回文（正读和倒读相同）"""
    return s == s[::-1]

def good_bruteforce(n: int, k: int) -> int:
    ans = 0
    start = 10 ** (n - 1)          # 首位非 0 的最小 n 位数
    end   = 10 ** n                # 超过 n 位的第一个数

    for num in range(start, end):
        s = str(num)
        # 生成所有不同的排列（去重）
        perms = set(itertools.permutations(s))
        for p in perms:
            if p[0] == '0':               # 重新排列后不能出现前导 0
                continue
            cand = ''.join(p)
            if is_palindrome(cand) and int(cand) % k == 0:
                ans += 1
                break                     # 已找到一个满足条件的排列，计数一次即可
    return ans
```

> 代码里每一行都有中文注释，帮助你快速看懂每一步在干什么。

#### 复杂度  

- **时间复杂度**：`O(9·10^{n‑1}·n!)` — 这意味着“先把所有 n 位数列出来（指数级），再把每个数的所有排列列出来（阶乘级）”。  
- **空间复杂度**：`O(n)` — 只需要存放当前数字的字符数组和若干临时变量。

### 2. 最优解

#### 思路  

暴力解慢的根源在于 **“枚举所有 n 位数 + 枚举所有排列”** 这两层循环。  
我们可以把这两层循环 **合并并剪枝**，只枚举 **真正可能成为回文且能被 k 整除的排列**，再利用组合数学算出对应的原始整数有多少种。

关键观察：

1. **回文的结构非常固定**  
   - 偶数长度 `n = 2·m`：只需要决定前半段 `m` 位，后半段自动是前半段的镜像。  
   - 奇数长度 `n = 2·m + 1`：需要决定前半段 `m` 位和中间的 1 位，后半段同样是前半段的镜像。  

   这把原本 `10^{n}` 种可能压缩到了 `9·10^{⌈n/2⌉‑1}`（首位不能为 0，其他位随意），数量大幅下降。

2. **只要找到一种回文排列满足 “能被 k 整除”，就说明所有拥有同样数字 multiset（出现次数相同）的整数都是 “好整数”。**  
   - 因为这些整数只是在 **位置** 上做重新排列，数字本身没有变化。  
   - 所以我们只需要 **统计每一种数字出现次数的组合**（即一个长度为 10 的计数向量），而不是每一个具体的回文字符串。

3. **如何从一个回文得到它对应的数字计数向量？**  
   - 直接遍历回文字符串，统计每个数字出现了多少次，得到 `cnt[0..9]`。  
   - 这个向量唯一决定了所有可以由这些数字组成的整数（包括原始的好整数）。

4. **避免重复计数**  
   - 不同的回文可能产生相同的计数向量（例如 `1221` 与 `2112`），我们用哈希表（字典）把已经统计过的向量记下来，只算一次。

5. **从计数向量求出“好整数”有多少种**  
   - 设 `cnt[d]` 为数字 `d` 的出现次数，总和为 `n`。  
   - 所有不考虑前导零的全排列数为  

     \[
     \frac{n!}{\prod_{d=0}^{9} cnt[d]!}
     \]

   - 其中有 **前导零** 的排列需要剔除：把一个 `0` 放在首位，其余 `n‑1` 位随意排列，数目为  

     \[
     \frac{(n-1)!}{(cnt[0]-1)!\,\prod_{d=1}^{9} cnt[d]!}
     \]

   - 两者相减即为 **合法的好整数数量**。

综上，最优算法的步骤：

1. **枚举所有可能的回文字符串**（长度 `n`，首位 ≠ 0）。  
2. 检查该回文是否能被 `k` 整除（直接把字符串转成整数 `% k`）。  
3. 统计该回文的数字计数向量 `cnt`，如果这个向量以前没有出现过，则  
   - 用上面的组合公式算出该计数向量对应的合法整数个数，累加到答案。  
   - 把向量加入哈希表防止以后重复计数。  

因为 `n ≤ 10`，枚举的回文数量最多约 `9·10^{4}`（偶数）或 `9·10^{5}`（奇数），完全可以在毫秒级完成。

#### 代码（Python）

```python
import math
from collections import defaultdict

# -------------------------------------------------------------
# 1️⃣ 预计算阶乘，后面会用到组合公式
# -------------------------------------------------------------
fac = [1] * 11          # n 最大是 10，直接把 0!~10! 预算好
for i in range(1, 11):
    fac[i] = fac[i-1] * i

def permutations_count(cnt, n):
    """
    计算使用 cnt[0..9] 这组数字，组成 n 位整数且首位不为 0 的不同排列数
    """
    # 所有排列（不管有没有前导零）
    total = fac[n]
    for c in cnt:
        total //= fac[c]

    # 如果没有 0，前导零的情况根本不存在
    if cnt[0] == 0:
        return total

    # 把一个 0 放在最前面的排列数
    zero_front = fac[n-1]
    zero_front //= fac[cnt[0]-1]          # 0 的剩余个数是 cnt[0]-1
    for d in range(1, 10):
        zero_front //= fac[cnt[d]]

    return total - zero_front

# -------------------------------------------------------------
# 2️⃣ 生成所有回文并统计答案
# -------------------------------------------------------------
def good_count(n: int, k: int) -> int:
    half = n // 2                     # 前半段的长度
    odd  = n % 2                     # 是否有中间位
    seen = set()                     # 用来去重计数向量
    ans  = 0

    # 枚举前半段（首位不能为 0）
    start = 10 ** (half-1) if half > 0 else 0
    end   = 10 ** half
    for left in range(start, end):
        left_str = str(left).zfill(half)   # 补零保证长度一致
        # 生成回文的两种情况
        mids = [''] if odd == 0 else [str(d) for d in range(10)]

        for mid in mids:
            # 构造完整的回文字符串
            rev = left_str[::-1]
            pal = left_str + mid + rev
            if pal[0] == '0':        # 首位 0（虽然左半已经保证，但中间位为 0 时仍可能出现）
                continue
            if int(pal) % k != 0:    # 不能被 k 整除的直接跳过
                continue

            # 统计数字出现次数，得到计数向量
            cnt = [0] * 10
            for ch in pal:
                cnt[ord(ch) - ord('0')] += 1
            key = tuple(cnt)         # 元组可以哈希，用作 set 的元素

            if key in seen:          # 已经统计过的计数向量直接跳过
                continue
            seen.add(key)

            # 依据计数向量算出该组对应的好整数个数
            ans += permutations_count(cnt, n)

    return ans

# -------------------------------------------------------------
# 3️⃣ 简单测试（可以自行修改 n、k 进行验证）
# -------------------------------------------------------------
if __name__ == "__main__":
    print(good_count(3, 5))   # 27
    print(good_count(1, 4))   # 2
    print(good_count(5, 6))   # 2468
```

**代码要点解释（每行中文注释已在代码中给出）：**

- `fac` 数组保存 `0! … 10!`，后面用来快速算组合数，避免重复乘除。  
- `permutations_count` 负责把 **“数字出现次数”** 转成 **“合法排列数”**，核心是 `n! / (cnt[0]!·cnt[1]!·… )` 再减去前导零的情况。  
- 主函数 `good_count` 只枚举 **前半段**（以及可能的中间位），构造完整回文后检查 **“能被 k 整除”**。  
- 用 `set seen` 去重计数向量，保证每一种数字 multiset 只算一次。  

#### 复杂度  

- **时间复杂度**  
  - 枚举的回文数目约为 `9 × 10^{⌈n/2⌉‑1}`（因为首位 9 种，其余位 10 种），每个回文只做常数次操作（取模、计数、查表）。  
  - 所以整体时间是 **`O(9·10^{⌈n/2⌉‑1})`**。  
  - 对比暴力的 `O(9·10^{n‑1}·n!)`，这已经把指数从 `n` 降到了 `n/2`，并且省掉了阶乘的灾难性增长，实际运行在毫秒级。

- **空间复杂度**  
  - `fac`、`cnt`、`seen` 等额外数据结构最多占用 `O(10·10^{⌈n/2⌉})`（哈希表里最多存这么多不同的计数向量），在 `n ≤ 10` 时最多几万条，远小于内存限制。  
  - 简单来说是 **`O(10^{⌈n/2⌉})`**，远小于暴力的 `O(n)` 临时空间。

## 心得  

- **核心技巧**：利用回文的对称结构把搜索空间从 `10^n` 大幅压缩到 `10^{⌈n/2⌉}`，再用**组合数学**把同一数字集合对应的所有排列一次性算出来。  
- **适用场景**：  
  1. 需要统计“可以重新排列成满足某种特殊结构的整数”——如“可重排成回文”“可重排成递增序列”。  
  2. “先枚举结构，再用计数向量去重”的典型组合计数题目，例如 “统计可重排成等差数列的数字”。  
- **一句话总结**：**“把回文的‘半段’枚举出来，再用计数向量+组合公式一次算完所有好整数”。**

## 反思  

- **第一反应**：直接把所有 `n` 位数枚举，然后暴力检查每个数的所有排列是否能形成符合条件的回文。  
- **最容易踩的坑**  
  1. **前导零**：不仅原整数不能有前导零，重新排列后形成的回文也不能有前导零。忘记这点会导致计数错误。  
  2. **重复计数**：不同的回文可能拥有相同的数字出现次数，若不去重会把同一组好整数算多次。  
  3. **整数溢出**：`n` 虽然小，但 `n!` 会很快变大，直接用 `int` 乘除容易出现精度或性能问题，预先存好阶乘并用整数除法是安全做法。  
- **下次类似题**：一看到“可以重新排列成 …”的描述，第一步就应该**思考能否把目标结构的自由度压缩**（比如回文只决定前半段），随后**用计数向量+组合公式**一次性统计所有可能的排列。这样既避免枚举全部排列，又能保证不漏解。
