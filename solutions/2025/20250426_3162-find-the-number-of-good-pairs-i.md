# #3162. 好配对的数量 I / Find the Number of Good Pairs I

> 难度：简单 · 标签：Array、Hash Table · [LeetCode 链接](https://leetcode.com/problems/find-the-number-of-good-pairs-i/)

## 题目（英文原版）

**Description**

You are given 2 integer arrays nums1 and nums2 of lengths n and m respectively. You are also given a positive integer k.
A pair (i, j) is called good if nums1[i] is divisible by nums2[j] * k (0 <= i <= n - 1, 0 <= j <= m - 1).
Return the total number of good pairs.

**Examples**

**Example 1:**

```
Input: nums1 = [1,3,4], nums2 = [1,3,4], k = 1
Output: 5
Explanation:
```

**Example 2:**

```
Input: nums1 = [1,2,4,12], nums2 = [2,4], k = 3
Output: 2
Explanation:
The 2 good pairs are (3, 0) and (3, 1) .
```

**Constraints**

- 1 <= n, m <= 50
- 1 <= nums1[i], nums2[j] <= 50
- 1 <= k <= 50

## 题目（中文翻译）

给定两个整数数组 `nums1` 和 `nums2`，长度分别为 `n` 和 `m`。同时给定一个正整数 `k`。  
如果满足 `nums1[i]` 能被 `nums2[j] * k` 整除（`0 <= i <= n - 1, 0 <= j <= m - 1`），则称配对 `(i, j)` 为**好配对（good pair）**。  
返回好配对的总数。

**示例 1**  
输入: `nums1 = [1,3,4]`, `nums2 = [1,3,4]`, `k = 1`  
输出: `5`  
解释:  
- `(0,0)`: 1 能被 1·1 整除  
- `(1,0)`: 3 能被 1·1 整除  
- `(1,1)`: 3 能被 3·1 整除  
- `(2,0)`: 4 能被 1·1 整除  
- `(2,2)`: 4 能被 4·1 整除  

**示例 2**  
输入: `nums1 = [1,2,4,12]`, `nums2 = [2,4]`, `k = 3`  
输出: `2`  
解释:  
满足条件的好配对为 `(3,0)` 和 `(3,1)`。

**约束条件**
- `1 <= n, m <= 50`
- `1 <= nums1[i], nums2[j] <= 50`
- `1 <= k <= 50`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是把所有可能的下标组合枚举一遍：  
- 对每个 `i`（遍历 `nums1`）再对每个 `j`（遍历 `nums2`）检查  
  `nums1[i]` 是否能被 `nums2[j] * k` 整除。  
- 只要满足 `nums1[i] % (nums2[j] * k) == 0`，计数器就加一。

这里用到的唯一数据结构是 **两个普通的列表**（`nums1`、`nums2`），它们就像我们日常生活中的两个装有数字的盒子，逐个配对检查即可。  

为什么这种方法一定能得到正确答案？因为题目要求“所有满足条件的 (i, j)”，遍历所有 i、j 的组合就能保证不漏掉任何一对。

时间/空间复杂度的“大白话”解释：  
- **时间复杂度 O(n·m)**：如果 `nums1` 长 10，`nums2` 长 5，我们要检查 10×5=50 次；一般来说，检查次数等于两个数组长度的乘积。  
- **空间复杂度 O(1)**：我们只用了几个计数变量，和输入规模无关。

#### 代码（Python）

```python
def countGoodPairs(nums1, nums2, k):
    """
    暴力枚举所有 (i, j) 组合，统计满足 nums1[i] 能被 nums2[j] * k 整除的对数。
    """
    cnt = 0                     # 记录答案
    for i, a in enumerate(nums1):          # 遍历 nums1 的每个元素 a
        for j, b in enumerate(nums2):      # 遍历 nums2 的每个元素 b
            if a % (b * k) == 0:           # 检查可整除条件
                # 满足条件，答案加一
                cnt += 1
    return cnt
```

#### 复杂度

- **时间复杂度**：`O(n·m)` —— 需要检查 `n`（`nums1` 长度）乘以 `m`（`nums2` 长度）的所有配对。  
- **空间复杂度**：`O(1)` —— 只用了常数个额外变量（计数器 `cnt`）。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **每次都要遍历整个 `nums2`**。如果 `nums2` 中有很多相同的数，我们可以把它们“合并”，一次性记住每个数出现了多少次，这样就不必每次都重复检查。

**核心技巧：哈希表（字典）统计出现次数**。  
- 把 `nums2` 中每个数的出现次数放进字典 `freq`，相当于把一摞相同的书合在一起，只记录有多少本。  
- 对每个 `nums1[i]`，只需要遍历字典的 **键**（即不同的 `nums2` 值），判断 `nums1[i] % (key * k) == 0` 是否成立。  
  - 如果成立，说明所有拥有这个键的 `nums2` 元素都可以配对，直接把它们的出现次数 `freq[key]` 加到答案中。

因为题目限制 `nums2[j]`、`k`、`nums1[i]` 都不超过 50，字典的键最多只有 50 种，遍历的次数远小于 `m`（最多 50），所以整体复杂度降到 `O(n·U)`，其中 `U` 为不同数的种类数（ ≤ 50），在最坏情况下仍是线性。

**类比**：想象你在超市找能配对的商品。暴力解相当于每次都去整个货架上逐个比对；哈希表方法相当于先把相同的商品堆在一起，看到一种商品就一次性知道有多少件可以配对。

#### 代码（Python）

```python
def countGoodPairs(nums1, nums2, k):
    """
    使用哈希表统计 nums2 中每个数出现的次数，随后遍历 nums1，
    对每个不同的 nums2 值只检查一次，可直接累加出现次数。
    """
    # 1. 统计 nums2 中每个数的出现次数
    freq = {}                       # key: nums2 的数值, value: 出现次数
    for b in nums2:
        freq[b] = freq.get(b, 0) + 1

    cnt = 0                         # 最终答案
    # 2. 对 nums1 的每个元素，遍历所有不同的 nums2 值
    for a in nums1:
        for b, times in freq.items():   # b 是 nums2 中的不同数值, times 是它的出现次数
            if a % (b * k) == 0:        # 检查整除条件
                cnt += times            # 所有拥有这个 b 的下标都可以配对
    return cnt
```

#### 复杂度

- **时间复杂度**：`O(n·U)`，其中 `U` 为 `nums2` 中不同数的种类数（最多 50）。相较于暴力的 `O(n·m)`，当 `m` 很大且有重复元素时，这个优化可以显著降低实际运行时间。  
- **空间复杂度**：`O(U)`，用哈希表保存不同的 `nums2` 值及其计数，最多保存 50 条记录。

## 心得

- **核心技巧**：利用哈希表（字典）把数组中相同元素的计数合并，避免重复遍历。  
- **适用题型**：  
  1. “计数配对”类题目，如“两个数组的相同元素对数”。  
  2. “满足某种数值关系的配对”类题目，如“两个数组中满足 a + b = target 的对数”。  
- **解题钥匙**：**先把重复的东西压缩成计数，再逐个检查条件**。

## 反思

- **第一反应**：看到 “所有 (i, j) 配对” 立刻想到双层循环暴力枚举。  
- **最容易踩的坑**：  
  - 忘记把 `k` 乘进去，导致检查条件写成 `a % b == 0`。  
  - `nums2[j] * k` 可能会超过整数范围（在本题限制下不会），但在实际编程时要注意溢出。  
  - 边界情况：`nums2` 里出现 `0`（本题不允许），如果出现需要特别处理除零错误。  
- **下次第一步**：先审题看是否有 **重复元素** 或 **数值范围小** 的特征，若有，考虑用 **哈希表计数** 来压缩搜索空间。
