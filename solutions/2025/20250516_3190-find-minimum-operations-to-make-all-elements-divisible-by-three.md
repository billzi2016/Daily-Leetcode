## 题目（英文原版）

**Description**

You are given an integer array nums. In one operation, you can add or subtract 1 from any element of nums.
Return the minimum number of operations to make all elements of nums divisible by 3.

**Examples**

**Example 1:**

```
Input: nums = [1,2,3,4]
Output: 3
Explanation:
All array elements can be made divisible by 3 using 3 operations:
```

**Example 2:**

```
Input: nums = [3,6,9]
Output: 0
```

**Constraints**

- 1 <= nums.length <= 50
- 1 <= nums[i] <= 50

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**把每个数字单独处理**，把它一直加 1 或减 1 ，直到它能被 3 整除为止。  
这相当于我们手里有一把**可调节的尺子**，每次只能把尺子长度调长或调短 1 个单位，目标是把尺子调到**“可以被 3 整除的长度”**（比如 0、3、6…）。  

具体做法：

1. 遍历数组 `nums`，取出当前元素 `x`。  
2. 用一个循环模拟“加 1 或减 1”，记录需要多少次操作才能让 `x % 3 == 0`。  
3. 把每个元素得到的操作次数累加，得到总的最小操作数。

因为每次循环最多只会走 **2 步**（余数为 1 或 2 时，只需要一次加/减；余数为 0 时不需要），所以虽然是“暴力”，其实已经很快。

> **为什么这个方法一定能得到正确答案？**  
> 对于任意整数 `x`，它和最近的 3 的倍数之间的距离只能是 0、1 或 2（因为模 3 的余数只有 0、1、2）。我们每一步只能改动 1，最少的步数自然就是这两个数的差的绝对值，即 `min(r, 3‑r)`，这里的 `r = x % 3`。遍历所有元素并把每个最小步数相加，得到的就是全局的最小操作数。

#### 代码（Python）

```python
def min_operations_bruteforce(nums):
    total_ops = 0                     # 记录所有元素需要的操作次数之和
    for x in nums:                    # 逐个处理数组中的每个数
        ops = 0                        # 当前元素的操作次数
        while x % 3 != 0:              # 只要不是 3 的倍数，就继续加/减 1
            # 为了让代码更直观，这里我们总是把 x 往离 0 最近的方向移动
            # 余数为 1 时减 1，余数为 2 时加 1
            if x % 3 == 1:
                x -= 1                 # 减 1，使余数变成 0
            else:                      # x % 3 == 2
                x += 1                 # 加 1，使余数变成 0
            ops += 1                   # 记录一次操作
        total_ops += ops               # 累加到全局答案
    return total_ops
```

#### 复杂度  

- **时间复杂度：** `O(n * k)`，其中 `n = len(nums)`，`k` 是每个数字最多需要的操作次数。因为余数只会是 0、1、2，`k ≤ 2`，所以实际是 `O(n)`。  
  大白话：我们只需要看一遍数组，每个元素最多检查两次，就能算出答案。
- **空间复杂度：** `O(1)`，只用了常数级别的额外变量（`total_ops、ops、x`），不随输入规模增长。

### 2. 最优解

#### 思路  

从暴力解可以看到，**真正的瓶颈并不是循环次数**（最多两次），而是我们在循环里反复做 “加 1 或减 1” 的判断。  
其实我们可以直接用 **取模**（`%`）算出每个数离最近的 3 的倍数有多远，而不必真的去“走”这几步。

关键点：

1. **余数** `r = x % 3` 只可能是 0、1、2。  
2. 当 `r == 0` 时，已经是 3 的倍数，不需要操作。  
3. 当 `r == 1` 时，只需要 **减 1**（一步）即可；  
   当 `r == 2` 时，只需要 **加 1**（一步）即可。  
4. 这一步数可以统一写成 `min(r, 3 - r)`。  
   - `r` 表示向下（减）到最近倍数的距离；  
   - `3 - r` 表示向上（加）到最近倍数的距离。  
   取两者的最小值，就是**最少的操作次数**。  

于是我们只要遍历一次数组，累加 `min(r, 3 - r)`，即可得到答案。

> **类比**：想象有一排灯泡，每盏灯只能调亮或调暗一步，目标是让所有灯的亮度都是 3 的整数倍。我们只需要看每盏灯当前亮度离最近的 3 的整数有多远，而不必真的去调节灯泡。

#### 代码（Python）

```python
def min_operations(nums):
    """
    返回使所有元素可被 3 整除的最小操作次数。
    思路：对每个数 x，计算其模 3 的余数 r，
          所需操作数 = min(r, 3 - r)。
    """
    total = 0                         # 累计所有元素的操作次数
    for x in nums:
        r = x % 3                     # 余数，只会是 0、1、2
        ops = min(r, 3 - r)           # 最近的 3 的倍数距离
        total += ops                  # 累加到全局答案
    return total
```

#### 复杂度  

- **时间复杂度：** `O(n)`，只遍历一次数组。  
  与暴力解相比，省去了内部的 `while` 循环，真正做到“一眼看出”每个数需要的步数。
- **空间复杂度：** `O(1)`，只用了几个整数变量。

## 心得

- **核心技巧**：利用**取模**（mod）直接得到与目标倍数的距离，`min(r, 3‑r)` 把“向上/向下”两种可能统一起来。  
- **适用场景**：  
  1. “使数组元素满足某个模数条件”的题目（如使所有元素能被 k 整除）。  
  2. “把数调到最近的某个集合”类问题（如最近的偶数、最近的 5 的倍数）。  
- **一句话总结**：**“余数决定距离，取最小的那一步”。**

---

## 反思

- **第一反应**：看到“加或减 1”，第一时间想到**逐个模拟**，即暴力循环。  
- **最容易踩的坑**：  
  - 忘记对余数为 2 的情况也只需要一步（向上加 1），误以为需要两步。  
  - 在实现时写成 `max(r, 3 - r)`，导致计数变大。  
  - 忽略了数组长度可能为 1 的极端情况（代码仍然要能正常工作）。  
- **下次遇到同类题**，第一步应该**先写出余数公式**，判断每个数离目标的最近距离，而不是直接写循环。这样既直观又高效。
