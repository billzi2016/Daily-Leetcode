## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是 **“看到 0 就把它翻转”**，但这里的翻转不是单独把某个位置的 0 变成 1，而是 **把从该位置到数组末尾的所有元素一起翻转**（0 变 1，1 变 0）。  
可以把这个操作想象成 **在一排灯泡前面站着一根棒子**，每次把棒子放在第 `i` 盏灯前面，就会把从第 `i` 盏灯开始往后的所有灯的开关都切换一次。  

暴力做法就是：

1. 从左到右遍历数组。  
2. 遇到 `nums[i] == 0` 时，就执行一次 “翻转后缀” 操作（把 `i … n‑1` 的每个元素都取反）。  
3. 继续向右走，直到所有元素都变成 1。  

> **为什么它一定能得到答案？**  
> 每一次我们在第一个仍然是 0 的位置进行翻转，后面的所有元素都会一起被翻转一次。此时这个位置必然变成 1，且以后再也不会受到更左侧的翻转影响（因为我们已经走到它右边了），所以它一定是最终的 1。重复这个过程，最终数组全为 1。

#### 代码（Python）

```python
def min_operations_bruteforce(nums):
    """
    暴力解：每次在出现 0 的位置翻转整个后缀
    时间复杂度 O(n^2) —— 每次翻转可能遍历 O(n) 的元素，最坏会翻转 O(n) 次
    空间复杂度 O(1)   —— 只使用常数额外空间
    """
    n = len(nums)
    ops = 0                     # 记录操作次数
    i = 0
    while i < n:                # 从左到右扫描
        if nums[i] == 0:        # 如果当前是 0，需要翻转后缀
            ops += 1
            # 翻转 i … n-1
            for j in range(i, n):
                nums[j] ^= 1    # ^=1 等价于取反，0↔1
        i += 1
    return ops
```

#### 复杂度  

- **时间复杂度：** `O(n²)`  
  解释：想象数组长度是 1000，最坏情况下每次都要把剩下的全部元素翻转一次，第一次遍历 1000 次，第二次 999 次……总共大约 500 000 次操作，这就是平方级别的增长，用“大约 n 的平方”来形容更直观。  

- **空间复杂度：** `O(1)`  
  只用了几个计数变量，和数组本身的大小无关，称作“常数级别”。

### 2. 最优解  

#### 思路  

暴力解的瓶颈在 **每次翻转都要遍历整个后缀**，导致 `O(n²)`。  
观察翻转的本质：  
- 翻转一次后，后缀里所有元素的值都会 **取反**。  
- 如果我们已经在左边翻转了 `k` 次，那么从当前位置往右的每个元素实际上已经被翻转了 `k` 次。  

关键点是 **只关心翻转次数的奇偶性**：  
- 翻转偶数次（0、2、4…）等价于 **没有翻转**（因为 0↔1↔0 又回到原值）。  
- 翻转奇数次（1、3、5…）等价于 **翻转一次**。  

因此我们可以用一个布尔变量 `flipped`（或 `parity`）记录 **截至当前索引，后缀被翻转的次数是奇数还是偶数**。  
遍历时：

1. 计算 “实际看到的值” = `nums[i] ^ flipped`（如果已经翻转了奇数次，就取反，否则保持原样）。  
2. 如果实际值是 0，说明在这个位置仍然是 0，需要再 **执行一次翻转**（即在这里再翻转后缀）。  
   - 操作计数 `ans += 1`。  
   - `flipped ^= 1`，把奇偶性切换，因为我们多翻转了一次。  

这样我们 **只遍历一次数组**，每一步都是 `O(1)` 的计算，整体 `O(n)`。  

> **类比**：想象你站在一条路上，路边有灯泡。每次你按下开关，**从当前位置往后**的所有灯都会切换状态。你只需要记住自己已经按了几次开关（奇数还是偶数），而不必真的去把每盏灯都手动切换。  

#### 代码（Python）

```python
def min_operations(nums):
    """
    最优解：贪心 + 记录翻转奇偶性（前缀翻转次数的 parity）
    时间复杂度 O(n) —— 只遍历一次数组
    空间复杂度 O(1) —— 只用常数个变量
    """
    ans = 0          # 操作次数
    flipped = 0      # 0 表示当前没有被奇数次翻转，1 表示已经被翻转奇数次

    for x in nums:   # 从左到右依次检查
        # 实际看到的值 = 原始值 ^ flipped（如果已经翻转了奇数次就取反）
        cur = x ^ flipped
        if cur == 0:               # 仍然是 0，需要在这里再翻转一次
            ans += 1               # 计数加一
            flipped ^= 1          # 翻转奇偶性，等价于 flipped = 1 - flipped
    return ans
```

#### 复杂度  

- **时间复杂度：** `O(n)` — 只需要一次线性遍历，随着数组长度增长，耗时几乎和元素个数成正比。  
- **空间复杂度：** `O(1)` — 只用了 `ans`、`flipped` 两个额外变量，和 `n` 大小无关。  

相较于暴力解，时间从 **“每次都要遍历剩余的元素”** 降到了 **“只看当前元素一次”**，提升非常明显。

## 心得  

- **核心技巧**：**记录翻转次数的奇偶性（贪心）**，把“把后缀真的翻一次”转化为“记一个标记”。  
- **适用的题型**：  
  1. “把前缀/后缀翻转使字符串全为同一个字符”  
  2. “最少翻转次数使二进制数组递增/递减”  
  3. “灯泡开关类问题”（每次操作影响一段连续区间）  
- **一句话总结**：只要知道到当前位置已经被翻转了奇偶多少次，就能在 **O(1)** 时间判断是否还需要再翻一次。

## 反思  

- **第一反应**：看到“只能通过下标 i 翻转后缀”，立刻想到“从左到右一次遍历”。  
- **最容易踩的坑**：  
  - 忘记把 **已经翻转的次数的奇偶性** 加进去，导致把已经被翻转的 0 当成 1 直接跳过。  
  - 没考虑空数组或全是 1 的情况（答案应为 0）。  
- **下次类似题的第一步**：先问自己“**一次操作影响的是前缀还是后缀**”，然后决定用 **奇偶标记** 还是 **前缀和** 来记录累计效果。
