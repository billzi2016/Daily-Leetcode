# #3438. **找到字符串中相邻数字的有效配对** / Find Valid Pair of Adjacent Digits in String

> 难度：简单 · 标签：Hash Table、String、Counting · [LeetCode 链接](https://leetcode.com/problems/find-valid-pair-of-adjacent-digits-in-string/)

## 题目（英文原版）

**Description**

You are given a string s consisting only of digits. A valid pair is defined as two adjacent digits in s such that:
Return the first valid pair found in the string s when traversing from left to right. If no valid pair exists, return an empty string.

**Examples**

**Example 1:**

```
Input: s = "2523533"
Output: "23"
Explanation:
Digit '2' appears 2 times and digit '3' appears 3 times. Each digit in the pair "23" appears in s exactly as many times as its numeric value. Hence, the output is "23" .
```

**Example 2:**

```
Input: s = "221"
Output: "21"
Explanation:
Digit '2' appears 2 times and digit '1' appears 1 time. Hence, the output is "21" .
```

**Example 3:**

```
Input: s = "22"
Output: ""
Explanation:
There are no valid adjacent pairs.
```

**Constraints**

- 2 <= s.length <= 100
- s only consists of digits from '1' to '9'.

## 题目（中文翻译）

给定仅包含数字的字符串 `s`。若两个相邻的数字 `a` 和 `b`（即 `s[i]` 与 `s[i+1]`）满足以下条件，则称它们构成**有效配对**（valid pair）：

- 在整个字符串 `s` 中，数字 `a` 出现的次数恰好等于它的数值（即 `int(a)` 次），且
- 在整个字符串 `s` 中，数字 `b` 出现的次数恰好等于它的数值（即 `int(b)` 次）。

请从左到右遍历字符串 `s`，返回找到的**第一个**有效配对。若不存在任何有效配对，返回空字符串 `""`。

### 示例

**示例 1**  
```text
Input: s = "2523533"
Output: "23"
Explanation:
数字 '2' 在 s 中出现了 2 次，数字 '3' 在 s 中出现了 3 次。配对 "23" 满足条件，因此返回 "23"。
```

**示例 2**  
```text
Input: s = "221"
Output: "21"
Explanation:
数字 '2' 在 s 中出现了 2 次，数字 '1' 在 s 中出现了 1 次。配对 "21" 满足条件，因此返回 "21"。
```

**示例 3**  
```text
Input: s = "22"
Output: ""
Explanation:
不存在满足条件的相邻数字配对，返回空字符串。
```

### 约束

- `2 <= s.length <= 100`
- `s` 只包含字符 `'1'` 到 `'9'` 的数字。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是 **把每一对相邻的字符都检查一遍**，看它们是否满足题目要求。  
具体步骤如下：

1. **枚举所有相邻的下标** `i`（从 `0` 到 `len(s)-2`），取出子串 `s[i:i+2]` 作为候选对。  
2. 为了判断这对数字是否“有效”，我们需要知道 **整个字符串里每个数字出现了多少次**。  
   - 这里可以把字符串当成一本“电话簿”，把每个数字当作**姓名**，把出现的次数当作**电话号码**。我们把所有“姓名‑电话号码”存进一个 **哈希表**（在 Python 里用 `dict`），相当于查字典：给定数字（key），立刻能得到它出现的次数（value）。  
3. 检查候选对 `ab`（`a`、`b` 为字符）：
   - 把字符转成整数 `int(a)`、`int(b)`，分别和哈希表里对应的出现次数比较。
   - 如果两者都相等，则这对就是**第一个**满足条件的有效对，直接返回。  
4. 如果遍历完所有相邻位置仍未找到，返回空字符串 `""`。

> **为什么这个方法一定能找到答案（如果有的话）？**  
> 我们把**所有**相邻位置都检查了一遍，且每一次检查都用**完整的出现次数**来判断。只要有满足条件的对，它必然会在遍历顺序中被发现并返回。

> **时间/空间复杂度的大白话**  
> - 时间复杂度 `O(n²)`：这里的 `n` 是字符串长度。我们在每一次相邻对检查时，都要**重新遍历整条字符串去统计出现次数**（相当于“每次都重新查字典”），这导致总共要做 `n-1` 次 `O(n)` 的统计工作，最终是 `n × n`，即 `n²`。  
> - 空间复杂度 `O(1)`：哈希表里最多只会存 9 个键（'1'~'9'），不随 `n` 增长，算作常数级空间。

#### 代码（Python）

```python
def first_valid_pair_bruteforce(s: str) -> str:
    """
    暴力解：对每一个相邻字符对，都重新统计整个字符串中每个数字出现的次数。
    """
    n = len(s)
    # 枚举所有相邻位置
    for i in range(n - 1):
        a, b = s[i], s[i + 1]

        # 重新统计出现次数（相当于每次都查一次字典）
        cnt = {}                     # 用 dict 当哈希表
        for ch in s:
            cnt[ch] = cnt.get(ch, 0) + 1

        # 把字符转成对应的数值并比较出现次数
        if cnt.get(a, 0) == int(a) and cnt.get(b, 0) == int(b):
            return a + b            # 找到第一个满足条件的对，直接返回

    # 没有任何有效对
    return ""
```

#### 复杂度

- **时间复杂度：** `O(n²)` —— 每检查一次相邻对，都要遍历整条字符串去计数。  
- **空间复杂度：** `O(1)` —— 哈希表最多只保存 9 个键，和 `n` 无关。

---

### 2. 最优解

#### 思路  

从暴力解可以看到，**瓶颈**在于每次检查相邻对时都要重新遍历整条字符串去计数，这会导致 `O(n²)` 的时间。  
其实我们只需要 **一次遍历** 就能得到所有数字的出现次数，然后再 **一次遍历** 检查相邻对。这样总共只走两遍字符串，时间降到线性 `O(n)`。

优化步骤：

1. **一次遍历统计频率**  
   - 使用哈希表（`dict`）记录每个数字出现的次数。  
   - 这一步相当于先把“电话簿”一次性写好，后面查时就能 O(1) 直接得到次数。  

2. **第二次遍历检查相邻对**  
   - 再次从左到右遍历相邻位置 `i`（`0 … n-2`），取出 `a = s[i]`、`b = s[i+1]`。  
   - 直接从已经准备好的哈希表里取出 `cnt[a]`、`cnt[b]`，与 `int(a)`、`int(b)` 比较。  
   - 第一次满足条件的对即为答案，立即返回。  

3. **如果遍历结束仍未找到**，返回空字符串 `""`。

> **核心数据结构——哈希表（字典）**  
> 把它想象成一本**“数字-出现次数”查询手册**，键是数字字符 `'1'…'9'`，值是它们在字符串中出现的次数。查找一次只需要 O(1) 时间。

> **为什么只需要 O(1) 额外空间？**  
> 因为题目限制数字只能是 `'1'` 到 `'9'`，最多只有 9 种不同的键，所以哈希表的大小固定，不会随输入长度增长。

#### 代码（Python）

```python
def first_valid_pair_optimal(s: str) -> str:
    """
    最优解：先一次遍历统计所有数字出现次数，再一次遍历检查相邻对。
    时间 O(n)，空间 O(1)（因为最多只有 9 个不同的数字）。
    """
    # 第一次遍历：统计频率
    freq = {}                       # 哈希表：digit -> count
    for ch in s:
        freq[ch] = freq.get(ch, 0) + 1

    # 第二次遍历：从左到右检查相邻对
    n = len(s)
    for i in range(n - 1):
        a, b = s[i], s[i + 1]
        # 直接在哈希表里取出现次数，和数字本身的值比较
        if freq.get(a, 0) == int(a) and freq.get(b, 0) == int(b):
            return a + b            # 第一个满足条件的对

    # 没有符合要求的相邻对
    return ""
```

#### 复杂度

- **时间复杂度：** `O(n)` —— 两次线性遍历，`n` 为字符串长度。  
  > 与暴力解相比，**把 `n` 次的 `O(n)` 计数工作压缩到一次**，避免了指数级的重复计算。  
- **空间复杂度：** `O(1)` —— 哈希表最多存 9 条记录，常数级空间。

## 心得

- **核心技巧**：先**预处理**（一次遍历统计频率），再**一次遍历**直接利用已知信息做判断。  
- **适用的题型**：  
  1. “出现次数等于数值”类题目（如 LeetCode 2283 “Check if Number Has Equal Digit Count”）。  
  2. 需要**全局信息**（如字符计数、区间和）配合**局部检查**的题目（如 “找出首个满足条件的子数组”）。  
  3. 任意**一次性统计后再遍历**的字符串或数组问题（如 “找出首个出现次数恰好为其值的字符”）。  
- **一句话总结**：**先把全局信息准备好，再用一次线性扫描完成所有局部判断**，是从暴力到线性时间的关键。

## 反思

- **拿到题目第一反应**：直接把每一对相邻字符都检查一次，顺便在检查时重新统计出现次数——这就是暴力思路。  
- **最容易踩的坑**  
  1. **忘记把字符转成整数**再比较出现次数，导致 `'2'` 与 `2` 直接比较出错。  
  2. **边界条件**：字符串长度最小为 2，若只遍历到 `len(s)-1` 会漏掉最后一对。  
  3. **误以为可以直接用 `count()` 方法**在每次检查时调用 `s.count(a)`，虽然代码更简洁，但仍是 `O(n)` 的内部遍历，整体仍是 `O(n²)`。  
- **下次遇到同类题**，第一步应该想到：**先做一次全局预处理（计数、前缀和、哈希映射等）**，再在 **一次线性扫描** 中利用这些信息完成判断。这样可以把时间从 `O(n²)` 降到 `O(n)`。
