# #3473. **长度至少为 M 的 K 个子数组的最大和** / Sum of K Subarrays With Length at Least M

> 难度：中等 · 标签：Array、Dynamic Programming、Prefix Sum · [LeetCode 链接](https://leetcode.com/problems/sum-of-k-subarrays-with-length-at-least-m/)

## 题目（英文原版）

**Description**

You are given an integer array nums and two integers, k and m.
Return the maximum sum of k non-overlapping subarrays of nums, where each subarray has a length of at least m.

**Examples**

**Example 1:**

```
Input: nums = [1,2,-1,3,3,4], k = 2, m = 2
Output: 13
Explanation:
The optimal choice is:
The total sum is 10 + 3 = 13 .
```

**Example 2:**

```
Input: nums = [-10,3,-1,-2], k = 4, m = 1
Output: -10
Explanation:
The optimal choice is choosing each element as a subarray. The output is (-10) + 3 + (-1) + (-2) = -10 .
```

**Constraints**

- 1 <= nums.length <= 2000
- -104 <= nums[i] <= 104
- 1 <= k <= floor(nums.length / m)
- 1 <= m <= 3

## 题目（中文翻译）

给定一个整数数组 `nums` 和两个整数 `k` 与 `m`。  
返回 `nums` 中 **k** 个互不重叠的子数组（subarray）的最大和，且每个子数组的长度必须不少于 **m**。

### 示例

#### 示例 1
**输入**: `nums = [1,2,-1,3,3,4]`, `k = 2`, `m = 2`  
**输出**: `13`  
**解释**:  
最优的选择是取子数组 `[1,2,-1,3]`（和为 5）和子数组 `[3,4]`（和为 8），总和为 `5 + 8 = 13`。  

#### 示例 2
**输入**: `nums = [-10,3,-1,-2]`, `k = 4`, `m = 1`  
**输出**: `-10`  
**解释**:  
最优的选择是把每个元素单独作为一个子数组。结果为 `(-10) + 3 + (-1) + (-2) = -10`。

### 约束条件
- `1 <= nums.length <= 2000`
- `-10^4 <= nums[i] <= 10^4`
- `1 <= k <= floor(nums.length / m)`
- `1 <= m <= 3`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**枚举**所有可能的 k 条不相交子数组，然后挑选满足「每段长度 ≥ m」且总和最大的那一种。

- **枚举方式**  
  - 先在数组里挑出第 1 条子数组的起点 `l1` 与终点 `r1（r1‑l1+1 ≥ m）`。  
  - 接着在 `r1+1` 之后挑第 2 条子数组的起点 `l2` 与终点 `r2`，同样要求长度 ≥ m。  
  - ……一直挑到第 k 条。  
- **数据结构类比**  
  - 把数组想象成一本连续的书页，挑子数组就像在书里划出若干段章节，每段至少要包含 m 页。我们要在所有合法划法中找出章节总页数（即元素和）最大的那一种。  

**为什么正确**  
只要遍历了**所有**合法的划分，最大值自然就会被找到。只要不漏掉任何一种可能，这种「全枚举」的思路一定能得到正确答案。

**时间/空间复杂度（大白话版）**  
- 对每一条子数组，我们都要在剩余的数组里**尝试所有可能的起点和终点**。如果把「起点」和「终点」各自看成一次选择，枚举的次数大约是 `O(n²)`（因为 `l ≤ r`，最多 `n·(n+1)/2` 种区间）。  
- 需要挑 k 条子数组，就相当于在这些区间里**做 k 层嵌套**，时间复杂度大概是 `O(n^{2k})`。  
- 空间上只需要保存递归/循环的栈层，最多 `O(k)`，但时间已经爆炸，根本不可接受。

#### 代码（Python）

```python
def max_sum_bruteforce(nums, k, m):
    n = len(nums)

    # 前缀和，方便快速求区间和
    pre = [0]
    for x in nums:
        pre.append(pre[-1] + x)

    best = -10**18                     # 记录全局最大

    # 递归枚举第 i 条子数组的起点
    def dfs(i, start, cur_sum):
        """i：已经选了多少条子数组（0..k）
           start：下一个子数组必须从这里开始
           cur_sum：已经得到的总和"""
        nonlocal best
        if i == k:                     # 选够 k 条了
            best = max(best, cur_sum)
            return
        # 剩余的元素数不足以再选出 (k-i) 条长度≥m 的子数组，直接剪枝
        if n - start < (k - i) * m:
            return

        # 枚举第 i 条子数组的结束位置 r（长度至少 m）
        for r in range(start + m - 1, n):
            # 子数组和 = pre[r+1] - pre[start]
            seg_sum = pre[r + 1] - pre[start]
            dfs(i + 1, r + 1, cur_sum + seg_sum)

    dfs(0, 0, 0)
    return best
```

> 关键行注释已写在代码里。由于枚举的组合数非常大，这段代码只能在 `n ≤ 15` 左右的小样例上跑得通。

#### 复杂度

- **时间复杂度**：`O(n^{2k})`（指数级），因为每条子数组都要在剩余区间里尝遍所有可能的起点/终点。  
  - 大白话：如果 `n = 20，k = 3`，最坏情况下会尝试几千万次，根本跑不完。
- **空间复杂度**：`O(k)`（递归栈深度），因为我们只保存了递归的层数和若干临时变量。

### 2. 最优解

#### 思路  

从暴力解可以看到，**瓶颈**在于每次都要遍历所有可能的子数组长度。我们需要把「找最优的结束位置」这一步变成 **常数时间**，于是可以把整体降到 `O(k·n)`。

下面一步步推导：

1. **前缀和**  
   设 `pre[i] = nums[0] + … + nums[i‑1]`（`pre[0]=0`）。  
   任意区间 `[l, r]`（左闭右闭）的和等于 `pre[r+1] - pre[l]`。  
   前缀和就像是 **查字典**：给定单词（下标），直接返回对应的“页码”（累计和），省去逐个相加的过程。

2. **动态规划定义**  
   `dp[i][j]` 表示 **在前 `j` 个元素（即 `nums[0…j‑1]`）中，恰好选出 `i` 条满足长度≥m 的不相交子数组时的最大总和**。  
   - `i` 范围 `0…k`，`j` 范围 `0…n`。  
   - 初始化：`dp[0][j] = 0`（不选子数组，和为 0），其余设为极小值（表示“不可能”）。

3. **状态转移**  
   对于 `dp[i][j]`，有两种可能：

   - **不以第 `j‑1` 个元素结尾** → 直接沿用前面的答案  
     `dp[i][j] = dp[i][j‑1]`。

   - **第 `i` 条子数组恰好以 `j‑1` 为右端点**（长度 ≥ m）  
     设子数组的左端点为 `t`，则 `t ≤ j‑m`（保证长度≥m），子数组和为 `pre[j] - pre[t]`。  
     此时前面已经选了 `i‑1` 条子数组，且它们只能使用 `t` 之前的元素 → `dp[i‑1][t]`。  
     所以这条路径的总和是 `dp[i‑1][t] + pre[j] - pre[t]`。  
     我们要在所有合法的 `t` 中取最大值：

     ```
     dp[i][j] = max( dp[i][j‑1],
                    max_{0 ≤ t ≤ j‑m} ( dp[i‑1][t] + pre[j] - pre[t] ) )
     ```

4. **消除二重循环**  
   上式的内部最大值可以改写为：

   ```
   max_{t ≤ j‑m} ( dp[i‑1][t] - pre[t] )  +  pre[j]
   ```

   只要在遍历 `j` 的过程中，**维护一个变量 `best` 保存到目前为止的 `dp[i‑1][t] - pre[t]` 的最大值**（`t` 只会增大），就可以在 **O(1)** 时间内得到内部最大值。  

   具体做法（对固定的 `i`）：

   ```python
   best = -inf
   for j in range(m, n+1):
       # 先把可以成为左端点的 t = j-m 加入 best
       best = max(best, dp[i-1][j-m] - pre[j-m])
       dp[i][j] = max(dp[i][j-1], pre[j] + best)
   ```

   这样整个 DP 的时间就从 `O(k·n·n)` 降到了 **`O(k·n)`**。

5. **答案**  
   最终答案是 `dp[k][n]`（使用全部 `n` 个元素，恰好选了 `k` 条子数组）。

#### 代码（Python）

```python
from math import inf

def max_sum_k_subarrays(nums, k, m):
    """
    返回 k 条长度至少为 m 的不相交子数组的最大总和
    """
    n = len(nums)

    # ---------- 1. 前缀和 ----------
    pre = [0] * (n + 1)               # pre[0] = 0
    for i in range(n):
        pre[i + 1] = pre[i] + nums[i]

    # ---------- 2. DP 表 ----------
    # dp[i][j]：前 j 个元素中恰好选 i 条子数组的最大和
    dp = [[-inf] * (n + 1) for _ in range(k + 1)]
    for j in range(n + 1):
        dp[0][j] = 0                  # 不选子数组，和为 0

    # ---------- 3. 状态转移 ----------
    for i in range(1, k + 1):         # 选第 i 条子数组
        best = -inf                   # best = max_{t ≤ current} (dp[i-1][t] - pre[t])
        for j in range(1, n + 1):    # 考虑前 j 个元素（右端点是 j-1）
            # 只有当 j >= m 时，才可能形成第 i 条子数组
            if j >= m:
                # 把 t = j-m 加入候选集合
                # dp[i-1][j-m] 对应左端点恰好在 j-m 之前（长度至少 m）
                best = max(best, dp[i-1][j-m] - pre[j-m])
                # 以 j-1 为右端点的子数组的最佳总和
                cand = pre[j] + best
                dp[i][j] = max(dp[i][j-1], cand)   # 两种情况取最大
            else:
                # 长度不足 m，不能结束第 i 条子数组，只能沿用 dp[i][j-1]
                dp[i][j] = dp[i][j-1]

    return dp[k][n]
```

> **代码解释**  
> - `pre`：一遍遍历得到前缀和，后面求任意区间和只要 `pre[r] - pre[l]`。  
> - `dp` 初始化为负无穷（`-inf`），表示「不可能」的状态。  
> - 外层循环 `i` 负责「第几条子数组」。  
> - 内层循环 `j` 负责「考虑前多少个元素」。  
> - 变量 `best` 动态维护 `dp[i-1][t] - pre[t]` 的最大值，只要 `j` 向右走，`t` 的取值范围只会增大，故可以 **滚动更新**。  
> - 当 `j < m` 时，根本无法形成长度 ≥ m 的子数组，只能把 `dp[i][j]` 设成 `dp[i][j-1]`（即不选）。

#### 复杂度

- **时间复杂度**：`O(k · n)`  
  - 大白话：如果 `n = 2000，k ≈ n/m ≤ 2000`，最多约 `4 × 10⁶` 次循环，完全可以在毫秒级完成。相比暴力的指数级，这就是“从爬山变成坐电梯”。  
- **空间复杂度**：`O(k · n)`（存整个 DP 表）  
  - 也可以只保留前一行 `dp[i‑1][*]` 和当前行 `dp[i][*]`，把空间压到 `O(n)`，但 `k·n ≤ 4·10⁶` 已经不算大，保持完整表便于理解。

## 心得

- **核心技巧**：**前缀和 + 动态规划 + 滚动最大值**。  
  前缀和把区间求和从线性降到常数；DP 把全局最优拆成子问题；维护 `best` 把原本的 `O(n²)` 转化为 `O(n)`。

- **该技巧适用的题型**  
  1. “选若干不相交子数组，使总和最大/最小”——如 *Maximum Sum of 3 Non‑Overlapping Subarrays*。  
  2. “在数组上做 k 次划分，每段满足某种约束”——如 *Partition Array for Maximum Sum*。  
  3. “带长度下限的区间 DP”——如本题或 *Maximum Subarray Sum with One Deletion*（通过前后缀数组转化）。

- **一句话总结解题钥匙**：  
  **把「选区间」的问题转化为「在前缀和上找最大差」并用 DP 滚动维护最大差**。

## 反思

- **第一反应**：看到「k 条不相交子数组」马上想到「暴力枚举」或「回溯」——直观但很慢。  
- **最容易踩的坑**  
  1. **长度下限**：忘记在 DP 转移时只让左端点 `t ≤ j‑m`，导致非法（长度 < m）的子数组被计入。  
  2. **负数情况**：答案可能全是负数，不能把初始值设成 0（否则会误把“不选”当作合法），要用 `-inf`。  
  3. **边界**：`j` 从 1 开始遍历，`pre` 的下标要对应好（`pre[j]` 表示前 `j` 个元素的和）。  

- **下次遇到同类题的第一步**：  
  1. **写出前缀和**，把区间求和变成常数。  
  2. **设 dp[i][j]** 表示前 `j` 个元素选 `i` 条子数组的最优值。  
  3. **检查转移里是否有 “最大化 (dp[i‑1][t] - pre[t])”**，若有则尝试用滚动最大值降维。  

这样就能从“只能跑几秒的暴力”直接跳到 “毫秒级的最优 DP”。祝你编码愉快！
