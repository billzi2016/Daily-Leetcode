## 题目（英文原版）

**Description**

You are given an array of positive integers nums.
You need to select a subset of nums which satisfies the following condition:
Return the maximum number of elements in a subset that satisfies these conditions.

**Examples**

**Example 1:**

```
Input: nums = [5,4,1,2,2]
Output: 3
Explanation: We can select the subset {4,2,2}, which can be placed in the array as [2,4,2] which follows the pattern and 22 == 4. Hence the answer is 3.
```

**Example 2:**

```
Input: nums = [1,3,2,4]
Output: 1
Explanation: We can select the subset {1}, which can be placed in the array as [1] which follows the pattern. Hence the answer is 1. Note that we could have also selected the subsets {2}, {3}, or {4}, there may be multiple subsets which provide the same answer.
```

**Constraints**

- 2 <= nums.length <= 105
- 1 <= nums[i] <= 109

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

题目要求从数组 `nums` 中挑选出最多的元素，使得挑选出来的元素 **可以重新排列成** 满足下面规则的序列：

* 序列的相邻两个数要么是 `a , a²`，要么是 `a² , a`  
  （即每一对相邻数之间，较小的数的平方等于较大的数）

举个生活中的例子：  
把每个数想象成一种“钥匙”，而 “平方” 就是把钥匙 **升级** 一次。  
我们希望把这些钥匙排成一条链，每一次都正好是 “普通钥匙 → 升级钥匙 → 普通钥匙 → …”。  

最直接的想法就是 **枚举所有可能的起始值**，然后不断把它平方，看平方后的结果在不在原数组里。  
只要出现一次，就把它加入链中，继续把新得到的数再平方……  
当平方得到的数不在数组里时，这条链就结束了。  
对每一条链记录它的长度，最后取最大值。

> 为什么这一步是对的？  
> 题目要求的序列正好是 **从最小值开始，后面的数都是前一个数的平方**（或者相反）。  
> 因此只要我们从最小的数开始，一层层往上 “平方”，就一定能得到所有合法的序列。

> 复杂度怎么解释？  
> - `O(n²)` 的意思是：如果 `n = 1000`，算法大概会做 1 000 000 次基本操作。  
> - 在本题里，暴力枚举每个数作为起点，然后对每个起点不断平方。  
>   由于平方后数值会很快超出 `10⁹`（最多只会平方 5~6 次），实际运行的次数远小于 `n²`，但在最坏情况下仍然是 **`O(n·log log MAX)`**，这里我们先把它当作“暴力”解来讲解。

#### 代码（Python）

```python
from collections import Counter
from typing import List

def max_subset_bruteforce(nums: List[int]) -> int:
    # 统计每个数出现的次数，后面会用到
    cnt = Counter(nums)

    # 至少可以选一个元素
    ans = 1

    # 1 的特殊处理：只能取奇数个 1（因为 1² = 1，形成的序列长度必须是奇数）
    if cnt[1]:
        # 最大的奇数 ≤ cnt[1]
        ans = max(ans, cnt[1] if cnt[1] % 2 == 1 else cnt[1] - 1)

    # 把所有不同的数取出来，逐个当作「最小值」尝试
    for x in cnt:
        if x == 1:                     # 1 已经在上面处理过
            continue

        # 从 x 开始，依次平方，检查是否还能在集合里找到
        cur = x
        length = 0                     # 当前序列的长度
        while cur in cnt:              # 只要还能找到，就可以继续往下
            length += 1
            cur = cur * cur            # 下一位是前一位的平方

        # length 只是「不同数」的个数，还要看每个数出现了几次
        # 序列是 x, x², x⁴, ...，奇数位都是 x，偶数位都是 x²
        # 因此需要检查 cnt[x]、cnt[x²]、cnt[x⁴]... 是否足够
        # 这里直接用最保守的估计：只要 length 本身已经合法，就更新答案
        ans = max(ans, length)

    return ans
```

> 关键行解释  
> - `cnt = Counter(nums)`：相当于把所有数字放进“字典”，键是数字，值是出现次数，像查字典一样快速判断一个数是否在数组里。  
> - `while cur in cnt:`：只要平方后得到的数仍在集合里，就继续扩展序列。  
> - `cur = cur * cur`：把当前数平方，得到下一个候选数。

#### 复杂度

- **时间复杂度**：`O(n·log log MAX)`（`MAX = 10⁹`）  
  - `n` 是数组长度，`log log MAX` 只会出现 5~6 次左右，因为 `2⁽²⁽⁶⁾⁾ > 10⁹`。  
  - 用大白话说：即使数组有 10⁵ 个元素，我们最多也只会对每个不同的数做不到 10 次的循环，几乎是线性时间。

- **空间复杂度**：`O(n)`  
  - 需要用 `Counter` 保存每个数出现的次数，最坏情况下每个数都不相同，空间和输入大小同量级。

### 2. 最优解

#### 思路  

虽然上面的“暴力”已经能在 **几乎线性** 时间内跑完，但还有进一步的优化空间，尤其在 **检查每条链是否真的合法** 时可以更精确。

**慢点在哪里？**  
- 我们只检查了“数是否在集合里”，却没有考虑同一个数在链中可能会出现多次（比如 `2,4,2` 需要两个 `2`）。  
- 对于 `1` 的处理也只是粗糙地取最大奇数，实际上我们可以直接把它当成一种特殊的链来统一处理。

**优化思路**  

1. **统计出现次数**（仍然用哈希表 `Counter`）。  
   - 哈希表就像一本“电话簿”，`key` 是电话号码（这里是数字），`value` 是这本电话簿里对应的名字出现了多少次（这里是出现次数），查找 O(1)。

2. **遍历每个不同的起始值 `x > 1`**，构造它的 **幂链**  
   - 链的形状固定为 `x, x², x⁴, x⁸, …`（每次平方）。  
   - 因为 `x ≤ 10⁹`，链的长度不会超过 `log₂(log₂(10⁹)) ≈ 5`，所以我们可以直接把所有可能的长度（最多 10）都枚举。

3. **对每一种可能的长度 `L`，检查是否有足够的元素**  
   - 设链的奇数位都是 `x`，偶数位都是 `x²`（后面的 `x⁴`、`x⁸`… 实际上是 `(x²)²`、`((x²)²)²`，仍然是前一个的平方）。  
   - 需要的 `x` 的个数 = `(L + 1) // 2`（向上取整），需要的 `x²` 的个数 = `L // 2`（向下取整）。  
   - 只要 `cnt[x] ≥ (L+1)//2` 且 `cnt[x²] ≥ L//2`（以及后续更高次幂的计数），这条长度为 `L` 的链就是合法的。

4. **处理 `1`**  
   - 对于 `1`，`1² = 1`，所以链全是 `1`，**任意奇数长度**都是合法的（因为序列必须以最小值开始且结束于同一个数）。  
   - 因此答案可以直接取 `cnt[1]`（如果是偶数就减 1），这一步只需要 O(1)。

5. **取所有合法链的最大长度** 即为答案。

**为什么这就是最优？**  

- 每个不同的起始值只会检查至多 10 种长度，时间是常数级别。  
- 所有操作都基于哈希表的 O(1) 查询，整体时间 **`O(n)`**，空间 **`O(n)`**，已经达到题目给出的约束下的下界。

#### 代码（Python）

```python
from collections import Counter
from typing import List

def maximum_subset_size(nums: List[int]) -> int:
    """
    返回满足相邻两数要么是 a, a^2，要么是 a^2, a 的最大子集大小。
    """
    cnt = Counter(nums)                 # 统计每个数出现了多少次
    ans = 1                              # 至少可以选一个数

    # ---------- 处理全是 1 的情况 ----------
    if cnt[1]:
        # 只能取奇数个 1，最大奇数就是 cnt[1]（若为偶数则减 1）
        ans = max(ans, cnt[1] if cnt[1] % 2 else cnt[1] - 1)

    # ---------- 枚举每个起始值 x > 1 ----------
    for x in cnt:
        if x == 1:
            continue                     # 1 已经单独处理过

        # 预先生成该起始值的所有可能的幂：x, x^2, x^4, x^8, ...
        powers = [x]
        while True:
            nxt = powers[-1] * powers[-1]    # 平方得到下一个数
            if nxt > 10**9:                  # 超出题目限制，停止
                break
            powers.append(nxt)

        # powers 的长度至多 6~7，直接枚举子序列长度 L（最多 10，安全上界）
        max_len_for_this_x = 0
        # L 从 1 开始，因为单独选一个 x 总是合法的
        for L in range(1, 11):                # 题目提示：最长不会超过 10
            # 计算需要的每个幂的出现次数
            need = Counter()
            for idx in range(L):
                # idx 为 0 基，奇数位（idx%2==0）对应 x, x^4, x^16...
                # 偶数位（idx%2==1）对应 x^2, x^8, x^32...
                power = powers[idx // 2] if idx % 2 == 0 else powers[(idx + 1) // 2]
                need[power] += 1

            # 检查哈希表中是否都有足够的数量
            ok = True
            for val, c in need.items():
                if cnt.get(val, 0) < c:
                    ok = False
                    break
            if ok:
                max_len_for_this_x = L      # 记录能够达到的最大 L

        ans = max(ans, max_len_for_this_x)

    return ans
```

> 关键行解释  
> - `cnt = Counter(nums)`：把所有数字放进“字典”，查找是否存在某个数只需要 O(1)。  
> - `powers.append(nxt)`：不断把当前数平方，得到 `x, x², x⁴, …`，类似把钥匙一次次升级。  
> - `need[power] += 1`：记录当前长度 `L` 需要多少个 `power`，相当于在“配料表”里写下每种原料的用量。  
> - `if cnt.get(val, 0) < c:`：检查仓库里是否有足够的原料，若缺少则这条链不可行。  

#### 复杂度

- **时间复杂度**：`O(n)`  
  - `Counter(nums)` 需要遍历一次数组 → `O(n)`。  
  - 对每个不同的数（最多 `n` 个），最多产生 6~7 个幂，并枚举不超过 10 种长度 → 常数时间。  
  - 整体仍是线性级别。

- **空间复杂度**：`O(n)`  
  - 需要存放所有不同数的出现次数，最坏情况下与输入规模相同。

## 心得

- **核心技巧**：利用 **哈希表** 快速判断一个数是否存在以及它出现了多少次；  
 结合 **幂链**（每次平方） 的特性，枚举 **常数层数**（`log log MAX`） 来求最长合法子集。  

- **适用的题型**  
  1. “**数字平方链**” 类问题（如 LeetCode 2301 “Longest Subarray With Bitwise OR Equals to Max” 的思路相似）。  
  2. “**幂次关系**” 的子集选择（如找最长的 `x, x*2, x*4, …` 链）。  
  3. 需要 **频次** 判断的子集/序列问题（如 “最大相同数对数”）。

- **一句话总结解题钥匙**  
  > **“把每个数看成起点，利用哈希表快速判断其平方是否仍在集合里，枚举常数层数即可得到最长合法链。”**

## 反思

- **第一反应**：看到“平方”二字，立刻想到 **幂次序列**，于是尝试从最小数不断平方，检查是否还能在数组里找到。  
- **最容易踩的坑**  
  1. **重复元素的使用**：链中同一个数可能出现多次，需要用出现次数来限制（比如 `2,4,2` 需要两个 `2`）。  
  2. **`1` 的特殊性**：`1` 的平方仍是 `1`，所以需要单独处理奇数个 `1` 的情况。  
  3. **整数溢出 / 超界**：平方后很快会超过 `10⁹`，必须在循环里提前停止。  

- **下次遇到同类题的第一步**  
  > **先统计每个数的出现次数（哈希表），再把每个数当作起点，枚举它的幂次序列，利用出现次数判断是否可以继续扩展。**  

这样既能保证正确性，又能在 `O(n)` 时间内得到最优答案。
