**Description**

You are given two positive integers x and y, denoting the number of coins with values 75 and 10 respectively.
Alice and Bob are playing a game. Each turn, starting with Alice, the player must pick up coins with a total value 115. If the player is unable to do so, they lose the game.
Return the name of the player who wins the game if both players play optimally.

**Example 1:**

```

Output: "Alice"

```

**Example 2:**

```

```

**Constraints**

- 1 <= x, y <= 100

## 解题过程

### 1. 直觉解（暴力）

#### 思路  
最直接的想法是**把游戏当成树形递归**来模拟：  
- 当前玩家（先是 Alice）遍历所有合法的取法，**每一种合法取法都对应一次递归调用**，轮到对手继续取。  
- “合法取法”指的是从剩余的硬币中挑选若干 75 元硬币和若干 10 元硬币，使它们的价值恰好等于 115。  
- 如果某一步没有任何合法取法，说明当前玩家已经输掉，递归返回 **输**（`False`），否则如果存在一种取法能够让对手在随后**必输**，那么当前玩家就能赢，递归返回 **赢**（`True`）。

> **类比**：这跟我们在玩“取石子”游戏时，枚举每一种可以拿走的石子数非常相似。这里的“硬币组合”就是我们枚举的选项。

因为题目给的硬币价值只有两种（75 和 10），我们可以遍历 `a`（取走的 75 元硬币数量）从 `0` 到 `x`，遍历 `b`（取走的 10 元硬币数量）从 `0` 到 `y`，检查 `75*a + 10*b == 115` 是否成立。只要找到一种合法组合，就递归到下一轮。

**为什么这个方法一定正确？**  
递归把所有可能的游戏进程都穷举了一遍，**如果玩家能赢**，必然在某条分支上能让对手陷入必输状态；**如果玩家一定输**，则所有分支都导致自己在某一步无法继续取硬币。穷举不遗漏，结论必然可靠。

#### 代码（Python）

```python
def can_win(x: int, y: int, memo=None) -> bool:
    """
    递归暴力解：返回当前玩家是否有必胜策略
    x：剩余的 75 元硬币数
    y：剩余的 10 元硬币数
    memo：记忆化搜索，避免重复计算
    """
    if memo is None:
        memo = {}
    # 记忆化：已经算过的状态直接返回
    if (x, y) in memo:
        return memo[(x, y)]

    # 枚举所有可能的取法
    for a in range(0, x + 1):          # 取走 a 枚 75 元硬币
        for b in range(0, y + 1):      # 取走 b 枚 10 元硬币
            if 75 * a + 10 * b == 115: # 必须恰好等于 115
                # 取走后进入对手的回合
                if not can_win(x - a, y - b, memo):
                    # 对手在该局面必输，说明当前玩家必胜
                    memo[(x, y)] = True
                    return True

    # 没有任何合法取法，或者所有合法取法都让对手必胜
    memo[(x, y)] = False
    return False


def find_winner_bruteforce(x: int, y: int) -> str:
    """返回胜者名字（暴力实现）"""
    return "Alice" if can_win(x, y) else "Bob"
```

> 关键行解释  
> - `for a in range(0, x + 1)`：遍历所有可能的 75 元硬币取数。  
> - `if 75 * a + 10 * b == 115`：判断这对 `(a, b)` 是否构成合法的 115 元。  
> - `if not can_win(x - a, y - b, memo)`：如果对手在剩余硬币 `(x-a, y-b)` 的局面**必输**，说明当前玩家可以通过这一步赢。  

#### 复杂度

- **时间复杂度**：在最坏情况下会遍历所有 `(a, b)` 组合，数量约为 `O(x * y)`，而每一次递归又会产生类似的遍历，导致指数级别的递归树。整体是 **指数级**，在本题的约束 `x, y ≤ 100` 下仍然会超时。  
  - 大白话：想象你在每一步都要尝试上百种取法，然后每种取法又要再尝试上百种，如此循环下去，时间会炸裂。

- **空间复杂度**：递归深度最多是能进行的回合数 `min(x, y//4)`，再加上记忆化表占用 `O(x*y)` 空间。  
  - 大白话：记忆表像是一本“已经算过的局面”字典，最坏需要记住所有 `x*y` 种局面。

### 2. 最优解

#### 思路  

从暴力解可以看到**真正的瓶颈**是枚举所有 `(a, b)` 组合。其实我们并不需要枚举——**硬币的价值只有两种**，而且 115 只能用唯一一种组合：

```
115 = 75 * 1 + 10 * 4
```

换句话说，每一回合**必须**拿走 **1 枚 75 元硬币** 和 **4 枚 10 元硬币**，没有其他可能。于是游戏的进程被彻底简化：

- 只要还有至少 1 枚 75 元硬币 **且** 至少 4 枚 10 元硬币，就可以进行一回合。  
- 这等价于**每回合消耗** `1` 个 `x` 和 `4` 个 `y`。  

于是**最大可能的回合数**就是两者能够支撑的最小值：

```
turns = min(x, y // 4)
```

（`y // 4` 是整数除法，表示有多少组 4 枚 10 元硬币）

游戏从 Alice 开始，双方轮流。若 `turns` 为奇数，最后一次合法取法是 Alice 完成的，Bob 没法继续，**Alice 胜**；若 `turns` 为偶数，Bob 完成最后一次取法，Alice 输。

**核心技巧**：把“取硬币满足某价值”的约束**转化为固定的消耗模式**，然后只比较回合数的奇偶性。

> **类比**：这像是两个人轮流喝水，每次必须喝 1 瓶大杯 + 4 瓶小杯。如果只有 3 瓶小杯，根本喝不完一轮；只要算出能喝多少轮，奇数轮的玩家必胜。

#### 代码（Python）

```python
def find_winner(x: int, y: int) -> str:
    """
    最优解：只需要算出能进行的回合数，奇偶决定胜者
    x：75 元硬币数量
    y：10 元硬币数量
    """
    # 每回合需要 1 枚 75 元和 4 枚 10 元
    turns = min(x, y // 4)          # 能进行的最大回合数

    # 回合数为奇数 -> Alice 最后一次取完，Bob 输
    return "Alice" if turns % 2 == 1 else "Bob"
```

> 关键行解释  
> - `y // 4`：把 10 元硬币分成每 4 枚一组，整数除法保证只算完整的组。  
> - `min(x, y // 4)`：取两者的最小值，防止某一种硬币先用完导致无法再继续。  
> - `turns % 2 == 1`：判断奇偶，奇数意味着先手（Alice）拿到最后一次合法取法。

#### 复杂度

- **时间复杂度**：`O(1)`——只做了几次算术运算和一次取模。  
  - 与暴力解相比，从指数级直接跳到常数级，速度提升几百倍以上。

- **空间复杂度**：`O(1)`——只用了几个整数变量，几乎不占用额外空间。

## 心得

- **核心技巧**：把“固定总价值的取法”转化为**唯一的硬币消耗模式**，进而只比较可进行的回合数的奇偶。  
- **适用的题型**  
  1. **固定组合取值**的游戏（如只能用 `2` 与 `5` 组合成 `9`）。  
  2. **资源消耗类**的回合制游戏，只要每回合的消耗是唯一确定的。  
  3. **单调递减**的游戏局面，往往可以用回合数或余数直接判负。  
- **一句话总结解题钥匙**：**先找出每回合唯一的资源消耗方式，再看能进行多少回合，奇偶决定胜负。**

## 反思

- **第一反应**：看到“每回合必须凑到 115”，立刻想枚举所有可能的硬币组合（暴力搜索）。  
- **最容易踩的坑**  
  - 忘记检查 **所有合法组合**，导致漏掉一种可能（其实这里只有一种）。  
  - 边界条件：`y` 小于 4 时根本无法进行任何回合，需要 `y // 4` 的整数除法防止负数或小数。  
  - 把 `y / 4` 当作浮点数使用会导致精度误差，务必使用整数除 `//`。  
- **下次遇到同类题**：第一步先**判断每回合的必备资源组合是否唯一**；若唯一，就直接算能进行的回合数并利用奇偶或余数得出胜负。这样可以立刻把复杂的搜索问题降到 O(1)。
