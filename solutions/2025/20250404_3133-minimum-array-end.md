# #3133. 最小数组末尾 / Minimum Array End

> 难度：中等 · 标签：Bit Manipulation · [LeetCode 链接](https://leetcode.com/problems/minimum-array-end/)

---

## 题目（英文原版）

**Description**

You are given two integers n and x. You have to construct an array of positive integers nums of size n where for every 0 <= i < n - 1, nums[i + 1] is greater than nums[i], and the result of the bitwise AND operation between all elements of nums is x.
Return the minimum possible value of nums[n - 1].

**Examples**

**Example 1:**

```
Input: n = 3, x = 4
Output: 6
Explanation:
nums can be [4,5,6] and its last element is 6.
```

**Example 2:**

```
Input: n = 2, x = 7
Output: 15
Explanation:
nums can be [7,15] and its last element is 15.
```

**Constraints**

- 1 <= n, x <= 108

## 题目（中文翻译）

**描述**  
给定两个整数 `n` 和 `x`。你需要构造一个长度为 `n` 的正整数数组 `nums`，满足以下条件：

- 对于所有 `0 <= i < n - 1`，都有 `nums[i + 1] > nums[i]`（数组严格递增）。
- 所有元素进行位与（bitwise AND）运算的结果等于 `x`。

返回可能的最小的 `nums[n - 1]`（即数组最后一个元素的最小值）。

**示例 1**  
```
输入: n = 3, x = 4
输出: 6
解释:
nums 可以是 [4,5,6]，其最后一个元素为 6。
```

**示例 2**  
```
输入: n = 2, x = 7
输出: 15
解释:
nums 可以是 [7,15]，其最后一个元素为 15。
```

**约束条件**  
- `1 <= n, x <= 10^8`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**把所有满足条件的递增数组都枚举出来**，然后挑选其中最后一个元素最小的那条。  
具体可以这么做：

1. 先把数组的第一个元素固定为 `x`（因为所有元素的按位与必须等于 `x`，所以每个数都必须在 `x` 的每一个 1 位上也为 1）。  
2. 从 `x+1` 开始尝试每一个更大的正整数，判断它加入到数组后，**所有已选元素的按位与**是否仍然是 `x`。  
3. 如果仍然是 `x`，就把它加入数组；否则跳过。一直这样挑选，直到数组长度达到 `n`。  
4. 记录下此时数组的最后一个元素 `nums[n‑1]`，在所有可能的尝试中取最小值。

> **类比**：把 `x` 看成一本字典里已经划好线的词条（每个 1 位必须保留），我们要在字典里找出 `n‑1` 本“更大的书”，每本书的内容只能在 `x` 没划线的地方随意添加（0 位可以随意填 0/1），并且所有书的公共内容仍然是 `x`。

这个思路**一定能得到正确答案**，因为我们遍历了所有合法的递增序列，必然包含最优解。

然而，它的效率极其低下：

- 每次检查 “所有已选元素的按位与是否为 `x`” 都要遍历已有的数组，时间是 `O(current length)`。  
- 为了得到长度为 `n` 的数组，最坏情况下需要尝试的候选数几乎是 **指数级**（因为要找出恰好 `n‑1` 个满足条件的数）。  

#### 代码（Python）

```python
def minArrayEnd_bruteforce(n: int, x: int) -> int:
    # 结果数组，先放入第一个元素 x
    nums = [x]

    # 从 x+1 开始枚举可能的下一个数
    candidate = x + 1
    while len(nums) < n:                     # 还没凑够 n 个数
        # 计算把 candidate 加进来后所有数的 AND
        cur_and = nums[0]
        for v in nums[1:]:
            cur_and &= v
        cur_and &= candidate                 # 加上 candidate

        if cur_and == x:                      # 仍然满足 AND == x
            nums.append(candidate)            # 选进去
        candidate += 1                        # 继续尝试更大的数

    return nums[-1]                           # 返回最后一个元素
```

> **注**：上述代码仅为“暴力”示例，实际运行会在 `n`、`x` 稍大时超时或内存爆炸。

#### 复杂度

- **时间复杂度**：`O(??)`  
  这里的 `??` 不是一个固定的多项式，而是**指数级**的。直观上可以把它想象成“要翻遍所有可能的数”，在最坏情况下接近 `O(2^{n})`，所以根本不可接受。

- **空间复杂度**：`O(n)`  
  需要存储长度为 `n` 的数组 `nums`，这在本题本身是必须的，但相对于时间开销来说已经是“小事”。

### 2. 最优解

#### 思路  

从暴力解我们可以看到，**真正的难点在于如何快速构造出满足条件的递增序列**，而不是去枚举所有可能。  
观察按位与的性质：

- 若所有数的某一位是 `1`，则它们的 AND 在该位必为 `1`。  
- 若某位在 **任意一个** 数里是 `0`，则整体 AND 在该位必为 `0`。  

题目要求 **所有数的 AND 必须恰好等于 `x`**，这等价于：

> 对于 `x` 中为 `1` 的位，**每个数组元素都必须在该位上保持 `1`**（不能随意改成 0）。  
> 对于 `x` 中为 `0` 的位，**只要在任意一个元素里把它设成 0**，整个 AND 就会在该位上是 0。  

因此，**我们只需要确保在每个 “0 位” 上至少有一次把它设为 0**，而其它位可以随意填 1 以让数组递增。

现在把注意力放到 **如何让最后一个元素尽可能小**。  
因为数组是严格递增的，只要前面的 `n‑1` 个数尽可能“小，最后一个数就不会被迫太大**。  

关键观察：

- 对于 `x` 的 **1 位**，所有数都必须保留为 1，**这对大小没有任何影响**（它们已经是 1，后面的数自然更大）。  
- 对于 `x` 的 **0 位**，我们可以把这些位当作“自由位”。只要在前 `n‑1` 个数里把这些位的 **0** 分配完，就能让最后一个数只在“自由位”上填入 **最小可能的组合**。  

把 “自由位” 想成一排空位，我们需要往这排空位里放 `n‑1` 个 **1**（因为要让前 `n‑1` 个数递增，需要在每一步至少把一个空位从 0 变成 1，才能产生更大的数）。  
这正好对应把整数 `n‑1` 的二进制写在这些空位上：**从低位到高位依次填入 `n‑1` 的二进制位**。

于是**合并（merge）**的过程可以描述为：

1. **保留 `x` 的所有 1 位不动**。  
2. 把 `n‑1` 的二进制从右往左（低位到高位）依次填入 `x` 中为 0 的位置。  
3. 填完以后得到的数，就是满足所有条件且 **最后一个元素最小** 的答案。

> **类比**：  
> 想象 `x` 是一张已经在某些格子里写了“★”的棋盘（1 位），空格子（0 位）可以写数字。我们有 `n‑1` 枚棋子（对应二进制的 1），把它们从左到右依次放到空格子里，最左边的空格子先放最小的棋子（低位），这样整体形成的数字最小。

#### 代码（Python）

```python
def minArrayEnd(n: int, x: int) -> int:
    """
    返回长度为 n、严格递增、整体 AND 为 x 的数组的最小可能最后一个元素。
    思路：把 x 的 0 位当作空位，从低位到高位填入 (n-1) 的二进制位。
    """
    v = n - 1                 # 需要填入的“自由位”信息
    ans = x                   # 先把 x 的 1 位保留下来
    bit = 1                   # 当前检查的位（从最低位开始）

    while v:                  # 只要还有要填的 1，就继续
        if (x & bit) == 0:    # 只在 x 的 0 位上进行填充
            if v & 1:         # v 的当前最低位是 1，就把这个位设为 1
                ans |= bit   # 把 ans 的该位设为 1（合并操作）
            v >>= 1          # 把 v 右移，准备处理下一位
        bit <<= 1             # 检查下一位

    return ans
```

> **关键行解释**  
> - `if (x & bit) == 0:` 判断当前位在 `x` 中是否为 0（即是自由位）。  
> - `ans |= bit` 把答案的该位设为 1，相当于“把 `n‑1` 的对应位合并进来”。  
> - `v >>= 1` 把 `v` 右移，表示已经用了 `v` 的最低位。  

整个循环最多遍历 **32（或 64）次**（因为 `x`、`n` ≤ 10⁸），时间几乎是常数。

#### 复杂度

- **时间复杂度**：`O(log max(n, x))` → 在本题的约束下可视作 **O(1)**。  
  只需要遍历 `x` 的二进制位（最多 30 位），每一步都是常数操作。

- **空间复杂度**：`O(1)` → 只使用了几 个整型变量，额外空间几乎为零。  

与暴力解相比，**时间从指数级降到了常数级**，性能提升巨大。

## 心得

- 本题核心在于**按位与的固定位**（`x` 的 1 位）与**自由位**（`x` 的 0 位）之间的区别。  
- 通过把 `n‑1` 的二进制填入自由位，实现了“最小化最后一个数”的目标，这是一种**位合并（bit‑merge）**的技巧。  
- 该技巧适用于：  
  1. **构造满足整体按位与/或条件的序列**（如 LeetCode 1850 “Minimum Adjacent Swaps to Reach the Kth Smallest Number” 中的位操作思路）。  
  2. **在固定若干位的前提下，最小化/最大化一个数**（如 “Maximum XOR With an Element From Array”）。  
  3. **把一个计数（`n‑1`）映射到若干自由位**的场景（如 “Smallest Subset with OR Equal to Goal”）。

> **解题钥匙**：把“必须保持不变的位”与“可以自由分配的位”分离，然后把计数的二进制填进自由位。

## 反思

- **第一反应**：先想到枚举所有递增数组，想通过逐步检查 AND 是否为 `x` 来过滤。  
- **最容易踩的坑**：  
  - 忽略了 **严格递增** 的要求，可能会产生相同的元素导致答案不合法。  
  - 没有注意到 `x` 的 1 位必须在每个数中都保持为 1，导致错误的位合并。  
  - 对大范围的 `n`、`x`（可达 10⁸）直接枚举会导致超时或内存爆炸。  
- **下次遇到同类题**：第一步应该先**分析哪些位是固定的，哪些位是自由的**，再思考如何在自由位上“编码”需要的递增/计数信息。这样往往可以直接得到 O(1) 或 O(log) 的位操作解法。
