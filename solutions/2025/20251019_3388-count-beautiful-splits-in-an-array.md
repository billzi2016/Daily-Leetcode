## 解题过程

### 1. 直觉解（暴力）

#### 思路  

把数组从左到右任选一个位置把它划分成 **左段** 和 **右段**（两段都必须非空）。  
题目要求「美丽的划分」满足：

> 左段的最大值 **等于** 右段的最小值  

最直接的做法就是：  
1. 对每一个可能的切分点 `i`（`0 ≤ i < n‑1`）  
2. 逐个遍历左段 `nums[0…i]` 找出最大值 `max_left`，遍历右段 `nums[i+1…n‑1]` 找出最小值 `min_right`  
3. 若 `max_left == min_right`，计数器 `ans` 加一  

这就是**暴力枚举**。它不需要任何高级的数据结构，只用到了「遍历」和「比较」两个最基础的操作。  

> **类比**：把数组想成一排装有不同重量的箱子，左段的「最大重量」就是这段箱子里最重的那只，右段的「最小重量」就是这段箱子里最轻的那只。我们要找的划分，就是左边最重的箱子正好和右边最轻的箱子重量相同的情况。

**正确性**：  
- 对每一种可能的划分我们都检查了左段的最大值和右段的最小值是否相等。  
- 只要存在这样一种划分，就一定会在遍历中被发现并计数。  
- 由于遍历覆盖了所有合法的切分点，计数的结果必然等于满足条件的划分数目。

**复杂度分析**：  
- 外层循环遍历 `n‑1` 个切分点。  
- 对每个切分点，我们分别遍历左段和右段，最坏情况要遍历 `i+1` 和 `n‑i‑1` 个元素，总共是 `O(n)`。  
- 因此整体时间复杂度是 `O(n²)`（平方级），即「对每个切分点都要线性扫描一次」。  
- 只用了常数级的额外空间 `O(1)`（几个整数变量），不随 `n` 增长。

> **大白话**：`O(n²)` 就像把 5000 件物品两两比较一次，最多要比较 25 000 000 次，虽然能跑通，但会让程序慢很多。

#### 代码（Python）

```python
from typing import List

def count_beautiful_splits_bruteforce(nums: List[int]) -> int:
    n = len(nums)
    ans = 0                         # 记录满足条件的划分数

    # i 为左段的最后下标，右段从 i+1 开始
    for i in range(n - 1):
        # ---------- 求左段的最大值 ----------
        max_left = nums[0]           # 先把第一个元素当作最大值
        for j in range(1, i + 1):
            if nums[j] > max_left:  # 如果发现更大的，就更新
                max_left = nums[j]

        # ---------- 求右段的最小值 ----------
        min_right = nums[i + 1]      # 右段的第一个元素先当最小值
        for j in range(i + 2, n):
            if nums[j] < min_right:  # 发现更小的就更新
                min_right = nums[j]

        # ---------- 判断是否是「美丽划分」 ----------
        if max_left == min_right:
            ans += 1                 # 符合条件，计数器加一

    return ans
```

#### 复杂度

- **时间复杂度**：`O(n²)` — 对每个切分点都要遍历一次左段和右段，等价于「把 `n` 个数两两比较」。
- **空间复杂度**：`O(1)` — 只用了几个整数变量，不随 `n` 增长。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**每次都要重新遍历左段和右段**来求最大/最小值。  
事实上，**左段的最大值**只会随切分点向右移动而**单调不减**（因为我们往左段里加入了新元素，最大值只能保持或变大），同理**右段的最小值**只会随切分点向右移动而**单调不增**（因为右段在不断失去左侧的元素，剩下的元素最小值只能保持或变大）。

因此我们可以一次性预处理：

1. **前缀最大数组 `pref_max[i]`**  
   `pref_max[i]` = `max(nums[0…i])`，从左到右累计求最大值。  
2. **后缀最小数组 `suf_min[i]`**  
   `suf_min[i]` = `min(nums[i…n‑1])`，从右到左累计求最小值。

有了这两个数组，任意切分点 `i`（左段结束于 `i`）的左段最大值就是 `pref_max[i]`，右段最小值就是 `suf_min[i+1]`，只需要 **O(1)** 的时间比较一次即可判断是否是美丽划分。

> **类比**：想象我们在跑马拉松，跑到每个里程碑时都记下目前为止跑过的最高海拔（前缀最大），同时在回程时记下从该点到终点的最低海拔（后缀最小）。这样在任意分界点，只要比较这两个记录，就能立刻知道左边最高海拔是否恰好等于右边最低海拔。

**算法步骤**  

1. 计算 `pref_max`：  
   - `pref_max[0] = nums[0]`  
   - `pref_max[i] = max(pref_max[i‑1], nums[i])`（从左到右遍历）  
2. 计算 `suf_min`：  
   - `suf_min[n‑1] = nums[n‑1]`  
   - `suf_min[i] = min(suf_min[i+1], nums[i])`（从右到左遍历）  
3. 遍历所有合法切分点 `i = 0 … n‑2`，若 `pref_max[i] == suf_min[i+1]`，计数器 `ans` 加一。  
4. 返回 `ans`。

**正确性证明（归纳）**  

- **前缀最大**  
  - *基例*：`i = 0` 时，`pref_max[0] = nums[0]`，显然是左段 `[0]` 的最大值。  
  - *归纳假设*：假设 `pref_max[i‑1]` 正确保存了 `nums[0…i‑1]` 的最大值。  
  - *归纳步骤*：左段扩展到 `i`，新最大值只能是旧最大值 `pref_max[i‑1]` 或者新加入的 `nums[i]`，二者取大即为 `pref_max[i]`。因此 `pref_max[i]` 正确。  

- **后缀最小** 同理，只是方向相反，取小即可得到正确的最小值。  

- **美丽划分判定**  
  对任意切分点 `i`，左段为 `nums[0…i]`，右段为 `nums[i+1…n‑1]`。  
  根据上面的证明，`pref_max[i]` 正是左段的最大值，`suf_min[i+1]` 正是右段的最小值。  
  因此 `pref_max[i] == suf_min[i+1]` 当且仅当该划分满足「左段最大 = 右段最小」的定义。  

- **计数**  
  遍历所有 `i`，每满足一次条件就计数一次，最终计数等于所有美丽划分的数量。

**复杂度**  

- 前缀最大、后缀最小各遍历一次数组，时间 `O(n)`。  
- 再遍历一次检查所有切分点，仍是 `O(n)`。  
- 总体时间 **`O(n)`**，相较暴力的 `O(n²)` 提速数百倍。  
- 需要额外的两个长度为 `n` 的整数数组，空间 **`O(n)`**（如果把其中一个数组复用到原数组中，也可以做到 `O(1)`，但 `O(n)` 已经足够轻量）。

#### 代码（Python）

```python
from typing import List

def count_beautiful_splits(nums: List[int]) -> int:
    n = len(nums)
    if n < 2:                     # 长度不足以划分成两段
        return 0

    # ---------- 1. 前缀最大 ----------
    pref_max = [0] * n
    pref_max[0] = nums[0]
    for i in range(1, n):
        # 前缀最大 = 前一个前缀最大 与 当前元素 的较大者
        pref_max[i] = max(pref_max[i - 1], nums[i])

    # ---------- 2. 后缀最小 ----------
    suf_min = [0] * n
    suf_min[-1] = nums[-1]
    for i in range(n - 2, -1, -1):
        # 后缀最小 = 后一个后缀最小 与 当前元素 的较小者
        suf_min[i] = min(suf_min[i + 1], nums[i])

    # ---------- 3. 统计美丽划分 ----------
    ans = 0
    for i in range(n - 1):        # 切分点只能到 n-2，右段必须非空
        if pref_max[i] == suf_min[i + 1]:
            ans += 1

    return ans
```

#### 复杂度

- **时间复杂度**：`O(n)` — 只需三次线性遍历，远快于暴力的 `O(n²)`。  
  > 大白话：即使数组有 5000 个元素，我们只需要走三遍「数数」的过程，最多 15000 次比较，几乎是瞬间完成。

- **空间复杂度**：`O(n)` — 两个长度为 `n` 的辅助数组 `pref_max`、`suf_min`。  
  若要求严格的 `O(1)`，可以把 `suf_min` 的值直接在遍历时计算并立即比较（把后缀最小值保存在一个变量里），但 `O(n)` 已经足够节省内存。

## 心得

- **核心技巧**：**前缀/后缀预处理**（前缀最大 + 后缀最小）把「每次都要重新遍历」的问题一次性化解。  
- **适用场景**：  
  1. 需要频繁查询「左侧（或前缀）的某种聚合信息」与「右侧（或后缀）的某种聚合信息」的题目。  
  2. 条件涉及「左段最大 / 最小」或「右段最大 / 最小」等单调属性。  
  3. 类似「分割数组后左边最大等于右边最小」的变形题目。  
- **一句话总结**：**把所有“左边的信息”提前算好、把所有“右边的信息”提前算好，比较一次即可。**

## 反思

- **第一反应**：看到“左段最大 = 右段最小”，立刻想到逐个切点重新遍历，这就是最直接的暴力思路。  
- **最容易踩的坑**：  
  - 忘记 **两段必须都非空**，切分点的取值范围是 `0 … n‑2`，否则会出现越界或空段。  
  - 在暴力实现里把 `max_left`、`min_right` 的初始化位置写错（比如把右段最小值初始化为 `nums[i]` 而不是 `nums[i+1]`），会导致错误计数。  
  - 预处理时如果把后缀最小数组写成 `suf_min[i] = min(suf_min[i+1], nums[i+1])`（多取了一个下标）也会出错。  
- **下次类似题的第一步**：先判断是否可以 **一次遍历得到前缀/后缀的聚合信息**（最大、最小、和、异或等），如果可以，就直接用这种「前缀‑后缀」技巧把原本的 `O(n²)` 降到 `O(n)`。
