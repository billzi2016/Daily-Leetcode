# #3464. 最大化正方形上点之间的距离 / Maximize the Distance Between Points on a Square

> 难度：困难 · 标签：Array、Binary Search、Greedy · [LeetCode 链接](https://leetcode.com/problems/maximize-the-distance-between-points-on-a-square/)

## 题目（英文原版）

**Description**

You are given an integer side, representing the edge length of a square with corners at (0, 0), (0, side), (side, 0), and (side, side) on a Cartesian plane.
You are also given a positive integer k and a 2D integer array points, where points[i] = [xi, yi] represents the coordinate of a point lying on the boundary of the square.
You need to select k elements among points such that the minimum Manhattan distance between any two points is maximized.
Return the maximum possible minimum Manhattan distance between the selected k points.
The Manhattan Distance between two cells (xi, yi) and (xj, yj) is |xi - xj| + |yi - yj|.

**Examples**

**Example 1:**

```
Input: side = 2, points = [[0,2],[2,0],[2,2],[0,0]], k = 4
Output: 2
Explanation:

Select all four points.
```

**Example 2:**

```
Input: side = 2, points = [[0,0],[1,2],[2,0],[2,2],[2,1]], k = 4
Output: 1
Explanation:

Select the points (0, 0) , (2, 0) , (2, 2) , and (2, 1) .
```

**Example 3:**

```
Input: side = 2, points = [[0,0],[0,1],[0,2],[1,2],[2,0],[2,2],[2,1]], k = 5
Output: 1
Explanation:

Select the points (0, 0) , (0, 1) , (0, 2) , (1, 2) , and (2, 2) .
```

**Constraints**

- 1 <= side <= 109
- 4 <= points.length <= min(4 * side, 15 * 103)
- points[i] == [xi, yi]
- The input is generated such that:
	
points[i] lies on the boundary of the square.
All points[i] are unique.
- points[i] lies on the boundary of the square.
- All points[i] are unique.
- 4 <= k <= min(25, points.length)

## 题目（中文翻译）

给定一个整数 `side`，表示平面直角坐标系中以四个顶点 \((0,0), (0,side), (side,0), (side,side)\) 构成的正方形的边长。  
同时给定一个正整数 `k` 和一个二维整数数组 `points`，其中 `points[i] = [xi, yi]` 表示位于该正方形边界上的一个点的坐标。

需要从 `points` 中选取 `k` 个点，使得任意两个选中点之间的 **曼哈顿距离（Manhattan distance）** 的最小值最大化。  
返回选取的 `k` 个点能够得到的最大可能的最小曼哈顿距离。

两个格子 \((xi, yi)\) 与 \((xj, yj)\) 之间的曼哈顿距离定义为 \(|xi - xj| + |yi - yj|\)。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**枚举所有可能的选法**，然后计算每一种选法里任意两点的 Manhattan 距离的最小值，取这些最小值的最大者。

- **枚举**：把 `points` 中的每一种取 `k` 个点的组合都列出来。可以把点的下标当作“字典的词”，下标对应的“页码”就是这几个点的坐标集合。
- **计算距离**：对于组合里的每一对点，用公式 `|x1‑x2| + |y1‑y2|` 求 Manhattan 距离，找出组合内部的最小距离。
- **取最大**：所有组合的最小距离里挑出最大的那个，就是答案。

> 这就像把所有可能的排队顺序都写下来，找出每个顺序里最紧挨的两个人之间的最短距离，然后挑出“最不挤”的那个顺序。

**为什么能得到正确答案**  
因为我们把**所有**合法的选法都检查了一遍，最大化最小距离的要求一定会在某一次检查中被满足。

**时间/空间复杂度**  

- 组合的数量是 `C(n, k)`（从 `n` 个点里挑 `k` 个），这里的 `n = len(points)`。  
  当 `n = 15000`、`k = 25` 时，`C(n, k)` 天文数字，根本算不完。  
  所以时间复杂度是 **指数级**的 `O(C(n, k) * k²)`（每个组合内部再算 `k²` 次距离）。
- 只需要保存原始点和临时的一个组合，空间复杂度是 `O(k)`，可以忽略不计。

> 大白话：`O(C(n, k))` 就像是“从 15000 本书里挑 25 本的所有挑法”，根本不可能在电脑里一次遍历完。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**枚举所有组合**。我们需要一种只看**顺序**而不必穷举的办法。  
观察题目可以得到两个关键点：

1. **所有点都在正方形的边界上**。如果把正方形的四条边按顺时针方向“展开成一条直线”，每个点都可以用它在这条线上的“距离”唯一表示。  
   - 想象把正方形的左下角 `(0,0)` 当作起点，顺时针走一圈，走了多少步就记多少。  
   - 这条线的总长度是正方形周长 `L = 4 * side`，每个点对应的坐标记作 `t`（0 ≤ t < L）。
2. **两个边界点的 Manhattan 距离等于它们在这条“周长线上”最短的环形距离**。  
   - 设两点的周长坐标分别是 `t1, t2`，它们的距离是  
     ```
     dist = min(|t1 - t2|, L - |t1 - t2|)
     ```
   - 这正好是“圆上两点的最短弧长”，因为沿着正方形的边走到另一点，要么顺时针，要么逆时针，取较短的那段。

有了上述等价关系，问题就转化为：

> 在圆周（长度 L）上的若干离散点 `t[0…n-1]` 中，选 `k` 个，使得任意相邻选点的环形距离 ≥ d，求最大的 d。

这正是**“在圆上放 k 个球，使得最小间距最大”**的经典模型。  
可以用**二分搜索 + 贪心**来判断某个距离 `d` 是否可行。

**二分搜索**  
- 最小可能的距离是 `0`，最大不超过周长 `L`（因为两点之间的距离不可能超过整圈）。  
- 在 `[0, L]` 上二分，每次取中间值 `mid`，检查是否能选到 `k` 个点，使得相邻点的距离 ≥ `mid`。  
- 如果能，则说明答案至少是 `mid`，把左边界拉到 `mid + 1`；否则把右边界收缩到 `mid - 1`。  
- 最终左边界（或右边界）所在的值就是最大可能的最小距离。

**检查函数 `can(d)`（贪心）**  
- 先把所有点的周长坐标 `t` **排序**（相当于把点按顺时针顺序排成一列）。  
- 为了处理“环形”特性，把这列复制一遍并整体平移 `L`，得到 `t_ext = t + [x + L for x in t]`。这样在 `t_ext` 里选点时，**只需要保证选到的最后一个点的坐标 < 起点坐标 + L**，即可自动满足环形约束。  
- 对每一个可能的起点 `i`（`0 ≤ i < n`），尝试用贪心选点：
  1. 选 `t_ext[i]` 为第一个点，计数 `cnt = 1`，当前坐标 `pos = t_ext[i]`。  
  2. 下一点必须满足 `t_ext[next] ≥ pos + d`。利用二分（`bisect_left`）在 `t_ext` 中快速定位最左侧满足条件的点。  
  3. 重复步骤 2，直到选到 `k` 个点或已经超出 `i + n`（即走过一整圈仍不足 `k`）。  
- 若在某个起点成功选到 `k` 个点，说明距离 `d` 可行，返回 `True`。遍历所有起点都失败则返回 `False`。

**为什么贪心有效**  
在直线（或环形）上，**“离得最近的合法点”**永远是后续选点的最佳选择。  
如果我们在某一步把选择推得更远（不是最左侧满足 `≥ d` 的点），后面的可选点只会更少，绝不可能让原本不可行的情况变成可行。因此只要一种起点能成功，贪心一定能找到；如果所有起点都失败，则不存在任何选法满足距离 `d`。

**复杂度分析**  

- **排序**：`O(n log n)`（一次性）。
- **二分搜索**：循环次数约 `log2(L)`，`L ≤ 4·10⁹` → 至多 32 次。
- **检查函数**：  
  - 对每个起点 `i`（共 `n` 个）最多进行 `k` 次二分查找，每次 `O(log n)`。  
  - 由于 `k ≤ 25` 很小，整体是 `O(n * k * log n)`。  
- 综合：`O(n log n + log L * n * k * log n)`，在最坏情况下约 `15000 * 25 * log 15000 * 32 ≈ 1.5×10⁸` 次基本操作，完全可以在 1‑2 秒内跑完（Python 实际运行更快，因为 `k` 很小，很多起点在早期就会提前退出）。

- **空间**：存储 `t`、`t_ext`、以及二分用的临时变量，都是 `O(n)`。  

> 大白话：我们把正方形“拆成一根绳子”，把每个点想成绳子上的一个标记。然后用“二分法”不断猜测“最小间距”到底能有多大，每猜一次就用“从左到右一次走，尽量把下一个标记放得最近但不小于猜的距离”这种最省力的办法来检查。整个过程只要遍历一遍点、做几次二分查找，就能得到答案。

## 心得

- **核心技巧**：把二维边界点映射到一维“周长坐标”，并利用 **二分搜索 + 环形贪心** 判断可行性。  
- **适用题型**  
  1. “在圆/环上放置 k 个点，使得最小距离最大”  
  2. “在一条直线或环形上选点，要求相邻距离 ≥ 给定值”  
  3. “在离散坐标上做最大化最小距离的优化”  
- **解题钥匙**：**把空间问题转化为“一维顺序问题”，再用二分+贪心**。

## 反思

- **第一反应**：直接想枚举所有组合（暴力），但很快意识到点数太多不可能。  
- **最容易踩的坑**  
  - **环形距离的计算**：忘记取 `min(diff, L‑diff)`，导致误判可行性。  
  - **起点选择**：只从最左侧一个起点尝试会漏掉答案，需要遍历所有起点或使用双指针技巧。  
  - **边界条件**：`k = points.length` 时必须选全部点，距离即所有相邻点的最小环形距离；`d = 0` 永远可行。  
- **下次遇到同类题**：第一步就**把几何/二维约束转化为一维顺序**，随后用 **二分搜索** 检验“是否能满足阈值”，并用 **贪心** 在排序后快速构造选法。这样可以把指数级搜索压到对数级。
