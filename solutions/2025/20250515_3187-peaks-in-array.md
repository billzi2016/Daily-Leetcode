# #3187. 数组中的峰值 / Peaks in Array

> 难度：困难 · 标签：Array、Binary Indexed Tree、Segment Tree · [LeetCode 链接](https://leetcode.com/problems/peaks-in-array/)

## 题目（英文原版）

**Description**

A peak in an array arr is an element that is greater than its previous and next element in arr.
You are given an integer array nums and a 2D integer array queries.
You have to process queries of two types:
Return an array answer containing the results of the queries of the first type in order.
Notes:

**Examples**

**Example 1:**

```
Input: nums = [3,1,4,2,5], queries = [[2,3,4],[1,0,4]]
Output: [0]
Explanation:
First query: We change nums[3] to 4 and nums becomes [3,1,4,4,5] .
Second query: The number of peaks in the [3,1,4,4,5] is 0.
```

**Example 2:**

```
Input: nums = [4,1,4,2,1,5], queries = [[2,2,4],[1,0,2],[1,0,4]]
Output: [0,1]
Explanation:
First query: nums[2] should become 4, but it is already set to 4.
Second query: The number of peaks in the [4,1,4] is 0.
Third query: The second 4 is a peak in the [4,1,4,2,1] .
```

**Constraints**

- 3 <= nums.length <= 105
- 1 <= nums[i] <= 105
- 1 <= queries.length <= 105
- queries[i][0] == 1 or queries[i][0] == 2
- For all i that:
	
queries[i][0] == 1: 0 <= queries[i][1] <= queries[i][2] <= nums.length - 1
queries[i][0] == 2: 0 <= queries[i][1] <= nums.length - 1, 1 <= queries[i][2] <= 105
- queries[i][0] == 1: 0 <= queries[i][1] <= queries[i][2] <= nums.length - 1
- queries[i][0] == 2: 0 <= queries[i][1] <= nums.length - 1, 1 <= queries[i][2] <= 105

## 题目（中文翻译）

**描述**  
数组 `arr` 中的峰值（peak）指的是其值严格大于前一个元素和后一个元素的元素。

给定一个整数数组 `nums` 和一个二维整数数组 `queries`，请按照顺序处理 `queries` 中的查询，查询分为两种类型：

1. **类型 1**：`[1, left, right]`  
   统计并返回子数组 `nums[left … right]` 中的峰值个数。

2. **类型 2**：`[2, index, value]`  
   将 `nums[index]` 的值修改为 `value`。

返回一个数组 `answer`，其中按照出现顺序保存所有 **类型 1** 查询的结果。

---

**示例 1**

```text
输入: nums = [3,1,4,2,5], queries = [[2,3,4],[1,0,4]]
输出: [0]
解释:
第一个查询: 将 nums[3] 改为 4，数组变为 [3,1,4,4,5]。
第二个查询: 子数组 [3,1,4,4,5] 中的峰值个数为 0。
```

**示例 2**

```text
输入: nums = [4,1,4,2,1,5], queries = [[2,2,4],[1,0,2],[1,0,4]]
输出: [0,1]
解释:
第一个查询: nums[2] 已经是 4，无需修改。
第二个查询: 子数组 [4,1,4] 中的峰值个数为 0。
第三个查询: 子数组 [4,1,4,2,1] 中，第二个 4 是一个峰值。
```

---

**约束条件**

- `3 <= nums.length <= 10^5`
- `1 <= nums[i] <= 10^5`
- `1 <= queries.length <= 10^5`
- `queries[i][0] == 1` 或 `queries[i][0] == 2`
- 对于所有 `i`：
  - 若 `queries[i][0] == 1`，则 `0 <= queries[i][1] <= queries[i][2] <= nums.length - 1`
  - 若 `queries[i][0] == 2`，则 `0 <= queries[i][1] <= nums.length - 1`，且 `1 <= queries[i][2] <= 10^5`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

> **最直接的想法**：  
> - 先把数组 `nums` 按照题目要求保存下来。  
> - **查询类型 1**（统计区间 `[l, r]` 内的峰值）时，直接遍历 `l+1 … r-1`，把满足 `nums[i] > nums[i‑1] 且 nums[i] > nums[i+1]` 的元素计数。  
> - **查询类型 2**（把 `nums[pos]` 改成 `val`）时，直接把 `nums[pos] = val`，不需要额外的工作。  

> **用到的数据结构**：只需要一个普通的 Python 列表 `nums`。  
> - 可以把列表想象成一本 **“顺序的笔记本”**，每一页（下标）记录一个数字。我们随时可以翻到任意页查看或修改内容。

> **为什么正确**：  
> - 对于查询 1，题目要求的 “峰值” 正好是我们遍历时逐个检查的条件，只要遍历完整个区间，计数一定是准确的。  
> - 对于查询 2，直接把对应位置的值改掉，后面的查询在遍历时自然会使用最新的值。

#### 代码（Python）

```python
from typing import List

def is_peak(nums: List[int], i: int) -> bool:
    """判断位置 i 是否是峰值（i 必须有左右相邻元素）"""
    if i <= 0 or i >= len(nums) - 1:
        return False          # 边界位置不可能是峰值
    return nums[i] > nums[i - 1] and nums[i] > nums[i + 1]

def solve_bruteforce(nums: List[int], queries: List[List[int]]) -> List[int]:
    ans = []                       # 保存所有类型 1 查询的答案
    for typ, a, b in queries:
        if typ == 1:               # 区间查询 [a, b]
            cnt = 0
            for i in range(a + 1, b):   # 只检查内部位置
                if is_peak(nums, i):
                    cnt += 1
            ans.append(cnt)
        else:                      # typ == 2，点更新 nums[a] = b
            nums[a] = b
    return ans
```

> **关键行中文注释** 已写在代码里，运行时只要把 `nums` 和 `queries` 按题目格式传进去即可。

#### 复杂度  

- **时间复杂度**：  
  - 类型 1 查询需要遍历区间内部，最坏情况是遍历整个数组，记作 **O(n)**（这里的 `n` 是 `nums` 长度）。  
  - 类型 2 查询只做一次赋值，记作 **O(1)**。  
  - 因为查询数量 `q` 也可能达到 `10^5`，最坏总时间是 **O(q·n)**，在最极端的 `n = q = 10^5` 时会达到 `10^10`，远远超时。  
  - “O(n)” 的含义可以理解为：**随着数组长度线性增长，所需的计算时间也会线性增长**，就像把一箱子苹果一个一个数完。

- **空间复杂度**：  
  - 只用了原数组 `nums`（长度 `n`）和常数个额外变量，**O(n)**。  
  - 这里的 `O(n)` 表示我们需要的额外记忆空间和数组本身一样多。

### 2. 最优解

#### 思路  

从暴力解出发，我们发现 **瓶颈** 在于每次区间查询都要线性遍历。  
要想把查询加速到 **对数级别**（`O(log n)`），我们需要一种数据结构，能够：

1. **快速得到任意子区间的“峰值数量之和”**。  
2. **在点更新后，仅用少量时间把相关信息同步**。

这正好符合 **“前缀和 + 动态维护”** 的思路。我们把 **每个位置是否是峰值** 用 `0/1` 记录下来，形成一个新数组 `p`：

```
p[i] = 1  if i 是峰值
p[i] = 0  otherwise
```

> 类比：  
> - `p` 就像一本 **“是否是山峰的字典”**，下标是“单词”，`1` 表示“这是一座山”，`0` 表示“不是”。  
> - 统计区间 `[l, r]` 的峰值数量，就等价于在这本字典里 **求和** `p[l+1] … p[r-1]`。

**关键观察**：

- 当我们把 `nums[pos]` 改成新值时，只有 **`pos` 本身、左邻 `pos‑1`、右邻 `pos+1`** 这三个位置的峰值状态可能会改变。其它位置的 `p` 完全不受影响。  
- 因此在一次点更新后，只需要重新计算这最多 **3 个** `p` 值，然后把它们的差值加到维护前缀和的数据结构中。

**选用的数据结构**：

- **二叉索引树（Fenwick Tree / Binary Indexed Tree, BIT）**  
  - 支持 **单点修改** 和 **前缀和查询**，时间均为 `O(log n)`。  
  - 实现相对简洁，适合本题。  

> 如果你对 BIT 完全陌生，可以把它想象成 **“分层的累计计数器”**：  
> - 第一次层级累计所有前 `2^0=1` 个元素，第二层累计前 `2^1=2` 个元素，依此类推。查询时通过跳跃的方式快速累加需要的区间。

**整体流程**：

1. **预处理**  
   - 根据原数组 `nums` 计算出 `p`（遍历一次 `O(n)`）。  
   - 用 `p` 初始化 BIT（同样是 `O(n log n)`，但可以在 `O(n)` 中完成，代码里直接 `add` 也足够）。

2. **处理查询**  
   - **类型 1**（区间 `[l, r]`）：返回 `prefix_sum(r-1) - prefix_sum(l)`，即 `p[l+1 … r-1]` 的和。  
   - **类型 2**（点更新 `pos, val`）：  
        1. 把 `nums[pos] = val`。  
        2. 对 `j ∈ {pos‑1, pos, pos+1}`（只要在合法范围内）重新计算 `new = is_peak(nums, j)`。  
        3. 用 `delta = new - p[j]` 更新 BIT（`add(j, delta)`），并把 `p[j] = new`。  

这样每一次查询和每一次更新的时间都被压缩到 `O(log n)`，整体复杂度是 `O((n+q)·log n)`，能够轻松通过 `10^5` 规模的限制。

#### 代码（Python）

```python
from typing import List

class BIT:
    """二叉索引树（Fenwick Tree），1-indexed"""
    def __init__(self, n: int):
        self.n = n
        self.bit = [0] * (n + 1)          # 下标 0 不使用

    def add(self, idx: int, delta: int) -> None:
        """在位置 idx（0-indexed）上加 delta"""
        i = idx + 1                      # 转成 1-indexed
        while i <= self.n:
            self.bit[i] += delta
            i += i & -i                  # lowbit，跳到下一个负责区间

    def prefix_sum(self, idx: int) -> int:
        """返回 [0, idx]（含）区间的和，idx 为 0-indexed"""
        i = idx + 1
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l: int, r: int) -> int:
        """返回闭区间 [l, r] 的和，l、r 为 0-indexed，l <= r"""
        if l > r:
            return 0
        return self.prefix_sum(r) - (self.prefix_sum(l - 1) if l else 0)


def is_peak(nums: List[int], i: int) -> int:
    """返回 1 表示 i 是峰值，0 表示不是（i 必须有左右邻居）"""
    if i <= 0 or i >= len(nums) - 1:
        return 0
    return 1 if nums[i] > nums[i - 1] and nums[i] > nums[i + 1] else 0


def solve_optimal(nums: List[int], queries: List[List[int]]) -> List[int]:
    n = len(nums)
    # 1. 计算初始的峰值数组 p
    p = [is_peak(nums, i) for i in range(n)]

    # 2. 用 p 初始化 BIT
    bit = BIT(n)
    for i, val in enumerate(p):
        if val:
            bit.add(i, val)          # 只在是峰值的地方加 1

    ans = []                         # 保存所有类型 1 查询的结果

    for typ, a, b in queries:
        if typ == 1:                 # 区间查询 [a, b]
            # 峰值只能出现在内部位置 a+1 … b-1
            cnt = bit.range_sum(a + 1, b - 1)
            ans.append(cnt)
        else:                        # typ == 2，点更新 nums[a] = b
            pos, new_val = a, b
            nums[pos] = new_val      # 直接修改原数组

            # 只需要重新计算 pos-1、pos、pos+1 三个位置的峰值状态
            for j in (pos - 1, pos, pos + 1):
                if 0 <= j < n:       # 合法下标
                    new_peak = is_peak(nums, j)
                    if new_peak != p[j]:
                        delta = new_peak - p[j]   # -1、0 或 +1
                        bit.add(j, delta)         # 更新 BIT
                        p[j] = new_peak           # 同步 p 数组
    return ans
```

**代码要点解释**：

| 行号 | 关键操作 | 生活化类比 |
|------|----------|------------|
| `BIT.__init__` | 创建长度为 `n` 的累计计数器 | 把一排盒子装上计数器，盒子编号从 1 开始 |
| `add` | 在某个盒子里加或减 `delta`，并把影响传播到上层盒子 | 把一颗小石子放进盒子，盒子会把“多了一个石子”的信息告诉它的上层盒子 |
| `prefix_sum` | 累加从第 1 盒子到第 `idx` 盒子的石子数 | 把从左到右的盒子一个个打开，数里面的石子 |
| `is_peak` | 判断当前位置是否比左右都大 | 想象山峰：只有左右都是山脚时才算真正的峰 |
| 更新循环 `for j in (pos-1, pos, pos+1)` | 只检查受影响的最多 3 个位置 | 改变一个建筑物的高度，只会影响它左边、右边和自己的“是否是最高”状态 |

#### 复杂度  

- **时间复杂度**  
  - **预处理**：遍历一次数组计算 `p`，`O(n)`；向 BIT 插入 `n` 次，每次 `O(log n)`，整体 `O(n log n)`（常数很小）。  
  - **每条查询**：  
    - 类型 1：一次区间求和 `range_sum`，`O(log n)`。  
    - 类型 2：最多检查 3 个位置，每个位置一次 `add`（`O(log n)`），所以也是 `O(log n)`。  
  - **总体**：`O((n + q)·log n)`。  
  - 与暴力解的 `O(q·n)` 相比，对数级别的增长意味着即使 `n = q = 10^5`，也只需要约 `2·10^6` 次基本操作，轻松在一秒内跑完。  

- **空间复杂度**  
  - `nums`、`p` 各占 `O(n)`。  
  - BIT 再占 `O(n)`。  
  - 其余是常数级变量。  
  - 合计 **O(n)**，即随输入规模线性增长。

## 心得

- **核心技巧**：把“峰值”抽象为 **0/1 的标记数组**，并使用 **二叉索引树（或线段树）** 维护其前缀和，实现 **点更新 + 区间求和** 的对数时间解法。  
- **适用的题型**（类似思路）  
  1. **区间求和且只有局部位置受更新影响**：如 “子数组的奇数个数” 或 “子数组的逆序对数量（局部维护）”。  
  2. **统计满足某种局部条件的元素**：比如 “数组中有多少位置是局部最小” / “有多少位置的值等于左侧最大”。  
  3. **需要快速查询区间中满足特定布尔属性的数量**：如 “区间中有多少元素是质数”。  
- **一句话总结解题钥匙**：**把复杂的区间属性转化为 0/1 标记，再用 BIT（或线段树）维护标记的前缀和**。

## 反思

- **拿到题目第一反应**：先写最直观的遍历代码，确保对 “峰值” 的定义没有误解。  
- **最容易踩的坑**  
  1. **边界位置不是峰值**：`i = 0` 或 `i = n‑1` 永远返回 0，忘记会导致数组越界或错误计数。  
  2. **更新时忘记同步相邻的三个位置**：只改了 `pos` 本身会导致 `pos‑1`、`pos+1` 的峰值状态不更新。  
  3. **BIT 索引偏移**：BIT 通常使用 1‑based，写代码时容易把 `0`‑based 索引直接传进去导致错误。  
- **下次遇到同类题，第一步该想到**：  
  - “这道题的查询是**求和**，而**更新只影响局部**，能否把属性抽象成 **0/1 标记** 并用 **BIT/线段树** 维护前缀和？”  

这样一步步把问题抽象、选择合适的数据结构，就能把看似 `O(n·q)` 的暴力解，轻松升级到 `O((n+q)·log n)` 的高效解法。祝你玩得开心，算法路上步步高峰！
