## 解题过程

### 1. 直觉解（暴力）

#### 思路  
最直观的想法是把字符串 **整体向右移动 k 位**，每次只移动 1 位，循环 k 次。  
可以把字符串想象成一条环形的跑道，跑道上每个位置放一个字符。  
- “向右移动 1 位” 就像把跑道上的所有人都往前走一步，最后一个人跑到最前面。  
- 重复这个动作 k 次，就得到最终的加密字符串。

这种做法一定能得到正确答案，因为每一次移动都严格遵守题目要求的“把字符 i 放到 (i+k) % n 的位置”。只不过我们用了很多不必要的重复操作。

#### 代码（Python）

```python
def encrypt_brute(s: str, k: int) -> str:
    n = len(s)
    # 把字符串转成列表，列表的修改更方便
    arr = list(s)

    # 逐次向右移动 1 位，重复 k 次
    for _ in range(k):
        # 记录最后一个字符（跑到最前面的那位）
        last = arr[-1]
        # 把其余字符整体向右移动一位
        for i in range(n - 1, 0, -1):
            arr[i] = arr[i - 1]
        # 把记录的最后一个字符放到最前面
        arr[0] = last

    # 列表转回字符串返回
    return ''.join(arr)
```

#### 复杂度  

- **时间复杂度**：`O(k·n)`  
  解释：每次移动要遍历整个字符串（`n`），而我们要做 `k` 次，所以总共是 `k × n` 次操作。  
  当 `k` 很大（比如 `10^4`）时，这个算法会明显变慢。

- **空间复杂度**：`O(1)`（不计返回值的空间）  
  只用了常数个临时变量 `last`、`i`，没有额外的和输入规模相关的存储。

### 2. 最优解

#### 思路  
从暴力解可以看到，**真正的耗时点在于重复移动**。  
实际上我们不需要一步步搬动，只要一次性把每个字符直接放到它应该去的位置即可。  

- 设字符串长度为 `n`。  
- 题目要求：**新字符串的第 i 位 = 原字符串的第 (i + k) % n 位**。  
- 这正好对应一种“映射”关系：把原来的字符按照下标 **循环右移 k 位**。  

实现时，只需要遍历一次原字符串，计算每个字符的新下标，然后把它写进结果数组。  
因为下标的计算只涉及一次取模运算 `% n`，所以整体只需要 `O(n)` 的时间。

> **类比**：想象一条圆形传送带，上面有 `n` 个格子。我们一次性把每个格子里的物品搬到顺时针 `k` 格的位置，然后把所有格子里的物品收集起来，就是最终的加密字符串。

#### 代码（Python）

```python
def encrypt_optimal(s: str, k: int) -> str:
    n = len(s)
    # 为了避免 k 超过 n，先把 k 缩小到 [0, n-1] 之间
    k %= n                       # 只保留有效的位移

    # 创建一个长度为 n 的空列表，用来存放加密后的字符
    res = [''] * n

    # 按照题目给出的映射关系直接写入
    for i, ch in enumerate(s):
        # 新位置 = (i - k) % n   <-- 这里用减法是因为我们要把原字符搬到“左边”
        # 也可以直接用 (i + k) % n 把字符放到新字符串的对应位置
        new_idx = (i + k) % n
        res[new_idx] = ch       # 把字符放到目标下标

    # 把列表拼成字符串返回
    return ''.join(res)
```

> **注**：上面代码里使用 `new_idx = (i + k) % n`，这正是题目提示的公式。  
> 如果想把字符 **写到新字符串的第 i 位**，则可以使用 `res[i] = s[(i + k) % n]`，两种写法等价。

#### 复杂度  

- **时间复杂度**：`O(n)`  
  只遍历一次字符串，`n` 是字符串的长度。相较于暴力解的 `O(k·n)`，大幅提升，尤其当 `k` 很大时。

- **空间复杂度**：`O(n)`  
  需要额外的长度为 `n` 的数组（或列表）来保存结果。返回的字符串本身也占 `O(n)` 空间，这在所有解法中都是不可避免的。

## 心得

- **核心技巧**：**下标映射 + 取模**。把“循环右移 k 位”抽象成下标的数学关系，用 `(i + k) % n` 直接算出新位置。
- **适用的题型**  
  1. 字符串/数组的循环左/右移（如 LeetCode 189. Rotate Array）。  
  2. 环形队列或环形缓冲区的下标计算。  
  3. 需要把元素按固定步长重新排列的题目（如密码轮换、轮盘游戏等）。
- **一句话总结**：**把循环移动转化为一次性下标映射，取模解决“环形”问题**。

## 反思

- **第一反应**：直接写一个循环把字符一个一个往后搬，甚至用 `s = s[-1] + s[:-1]` 重复 `k` 次。  
- **最容易踩的坑**  
  - 忘记对 `k` 取模，导致在 `k` 大于 `n` 时做了很多无意义的循环。  
  - 直接在原字符串上改动导致下标错位，最好使用额外的数组或先把字符保存下来。  
- **下次思路**：看到“循环右移/左移”这类关键词，立刻想到 **下标映射 + 取模**，先把 `k` 缩小到 `[0, n-1]`，再一次性完成转换。
