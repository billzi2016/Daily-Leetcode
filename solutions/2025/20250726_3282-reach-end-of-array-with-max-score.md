# #3282. 最大得分到达数组末尾 / Reach End of Array With Max Score

> 难度：中等 · 标签：Array、Greedy · [LeetCode 链接](https://leetcode.com/problems/reach-end-of-array-with-max-score/)

---

## 题目（英文原版）

**Description**

You are given an integer array nums of length n.
Your goal is to start at index 0 and reach index n - 1. You can only jump to indices greater than your current index.
The score for a jump from index i to index j is calculated as (j - i) * nums[i].
Return the maximum possible total score by the time you reach the last index.

**Examples**

**Example 1:**

```
Input: nums = [1,3,1,5]
Output: 7
Explanation:
First, jump to index 1 and then jump to the last index. The final score is 1 * 1 + 2 * 3 = 7 .
```

**Example 2:**

```
Input: nums = [4,3,1,3,2]
Output: 16
Explanation:
Jump directly to the last index. The final score is 4 * 4 = 16 .
```

**Constraints**

- 1 <= nums.length <= 105
- 1 <= nums[i] <= 105

## 题目（中文翻译）

给定一个整数数组（integer array）`nums`，长度为 `n`。你的目标是从下标 `0` 开始，最终到达下标 `n - 1`。在跳跃过程中，你只能跳到下标大于当前下标的位置。  
从下标 `i` 跳到下标 `j` 的得分计算公式为 `(j - i) * nums[i]`。返回在到达最后一个下标时可能获得的最大总得分（total score）。

示例 1:
```
Input: nums = [1,3,1,5]
Output: 7
Explanation:
首先跳到下标 1，然后跳到最后一个下标。最终得分为 1 * 1 + 2 * 3 = 7 。
```

示例 2:
```
Input: nums = [4,3,1,3,2]
Output: 16
Explanation:
直接跳到最后一个下标。最终得分为 4 * 4 = 16 。
```

约束条件：
- 1 <= nums.length <= 10^5
- 1 <= nums[i] <= 10^5

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**枚举所有合法的跳法**，计算每一种跳法的总得分，最后取最大值。  
实现上可以把每一次跳的选择看成一次递归或回溯：

1. 从当前位置 `i` 出发，遍历所有 `j>i`（只能往右跳）  
2. 计算本次跳的得分 `(j-i) * nums[i]`，把它加到当前累计得分上  
3. 递归求解从 `j` 开始能够得到的最大后续得分  
4. 把所有 `j` 的结果取最大，即为从 `i` 开始的最优得分  

这里用到的唯一数据结构是 **数组**（存放 `nums`），递归调用相当于在“树”上遍历所有路径。

> **类比**：想象你站在一条直路的起点，每一步都可以往前任意远的地方走一步，走的距离乘以当前路段的“速度” `nums[i]` 就是这一步的得分。要得到最高总分，你必须尝试所有可能的走法，就像在玩“走迷宫”时把每条路都走一遍。

**为什么这个方法能得到正确答案**  
因为我们把**所有**合法的跳法都枚举了，最大值自然就是全局最优。

**时间/空间复杂度**  

- 时间复杂度：`O(n^2)`（最坏情况下，从每个位置都要遍历后面的所有位置）  
  - **大白话**：如果数组有 10,000 个元素，最坏要算大约 10,000 × 10,000 = 1 亿次，这在电脑眼里已经很慢了。  
- 空间复杂度：`O(n)`（递归栈深度最坏会到 `n`）  

#### 代码（Python）

```python
from functools import lru_cache

def maxScore_bruteforce(nums):
    n = len(nums)

    @lru_cache(None)               # 记忆化搜索，避免重复计算
    def dfs(i):
        # 到达最后一个位置时不需要再跳，得分为 0
        if i == n - 1:
            return 0
        best = 0
        # 枚举所有可以跳到的下标 j
        for j in range(i + 1, n):
            cur = (j - i) * nums[i] + dfs(j)   # 本次跳得分 + 以后最优得分
            best = max(best, cur)              # 取最大
        return best

    return dfs(0)


# 示例
print(maxScore_bruteforce([1, 3, 1, 5]))   # 7
print(maxScore_bruteforce([4, 3, 1, 3, 2]))  # 16
```

> 代码里用了 `@lru_cache` 进行记忆化，实际运行时间会从 `O(n^2)` 降到 `O(n^2)`（常数更小），但仍然不是线性时间，无法通过 10⁵ 规模的测试。

#### 复杂度

- **时间复杂度**：`O(n^2)` —— 每个位置都要检查它后面的所有位置。  
- **空间复杂度**：`O(n)` —— 递归栈 + 记忆化表。

### 2. 最优解

#### 思路  

从暴力解可以看到 **瓶颈** 在于：我们每次都要遍历所有后面的 `j`，导致二次方的时间。  
观察得分公式 `(j-i) * nums[i]`，我们发现：

- 对于固定的起点 `i`，**距离越大** 越有利（乘的因子更大），但  
- 只有当 **跳到的终点 `j` 对后面的跳有更大的帮助** 时才值得走得更远。  

直观上，如果在 `i` 右边出现了一个 **更大的 `nums[j]`**，我们更应该把 **`i` 的得分尽可能延伸到这个更大的位置**，因为后面的跳会使用更大的 `nums[j]` 乘以更大的距离，从而产生更高的总分。

这就引出了 **“最近更大的元素”**（Next Greater Element, NGE）的概念：  
从位置 `i` 出发，**最近的**、**右侧的**、且 `nums[j] > nums[i]` 的下标 `j`，记为 `next[i]`。  
如果不存在这样的大于 `nums[i]` 的位置，那么只能直接跳到数组最后一位 `n-1`。

**为什么只需要最近更大的元素**  

设 `i < k < j`，且 `nums[k] > nums[i]`，`nums[j] > nums[i]`。  
如果我们从 `i` 直接跳到 `j`，得分为 `(j-i)*nums[i]`。  
而如果先跳到 `k` 再跳到 `j`，总得分为  
```
(k-i)*nums[i] + (j-k)*nums[k]
```
因为 `nums[k] > nums[i]`，第二段的乘子更大，整体分数 **不小于** 直接跳到 `j`。  
所以 **不必跳过** 第一个更大的位置，直接跳到最近更大的位置就已经是最优的子结构。

因此，**每个位置的最优跳目标** 只和 **最近更大的元素** 有关。  
这让我们可以把原问题转化为：

> 从左到右遍历数组，维护一个 **单调递减栈**（栈顶的值永远不大于栈底）。  
> 当遇到比栈顶更大的 `nums[cur]` 时，说明 `cur` 是栈顶元素的最近更大元素。  
> 弹出栈顶 `idx`，把 `idx` 的得分直接加到答案中：`(cur-idx) * nums[idx]`。  
> 把 `cur` 入栈继续向后扫描。  
> 最后栈里剩下的元素都没有更大的右侧元素，它们只能跳到最后一个下标 `n-1`，把对应得分累加即可。

**核心数据结构：单调栈**  

- **栈**：像一摞盘子，后进的先出来。  
- **单调递减**：从栈底到栈顶，`nums` 的值始终是递减的。  
  - 这保证了栈顶永远是**最近的、还未找到更大元素的下标**。  

**步骤概览**  

1. 初始化空栈 `stack = []`，答案 `ans = 0`。  
2. 遍历下标 `i` 从 `0` 到 `n-1`（包括最后一个下标）。  
   - 当 `stack` 不为空且 `nums[i] > nums[stack[-1]]`：  
        - 弹出 `idx = stack.pop()`  
        - `ans += (i - idx) * nums[idx]`（`i` 就是 `idx` 的最近更大元素）  
   - 把当前下标 `i` 入栈 `stack.append(i)`。  
3. 循环结束后，栈里剩下的下标都没有右侧更大的元素。对每个 `idx`：  
   - `ans += (n-1 - idx) * nums[idx]`（直接跳到数组末尾）。  
4. 返回 `ans`。

**时间复杂度**：每个下标最多进栈一次、出栈一次，整体 `O(n)`。  
**空间复杂度**：栈最多保存 `n` 个下标，`O(n)`，但在最坏情况下仍然是线性。

#### 代码（Python）

```python
def maxScore(nums):
    """
    使用单调递减栈求最近更大的元素，
    并依据题意直接累加每一次跳的得分。
    """
    n = len(nums)
    stack = []          # 存放下标，保持 nums[stack] 单调递减
    ans = 0

    for i in range(n):
        # 当前值比栈顶对应的值大，说明找到了栈顶的最近更大元素
        while stack and nums[i] > nums[stack[-1]]:
            idx = stack.pop()                 # 取出最近更大的左侧下标
            ans += (i - idx) * nums[idx]      # 计算从 idx 跳到 i 的得分
        stack.append(i)                       # 把当前下标压入栈中

    # 栈中剩余的下标没有更大的右侧元素，必须直接跳到最后一个位置
    while stack:
        idx = stack.pop()
        ans += (n - 1 - idx) * nums[idx]      # 跳到数组末尾的得分

    return ans


# ------------------- 测试 -------------------
print(maxScore([1, 3, 1, 5]))          # 7
print(maxScore([4, 3, 1, 3, 2]))      # 16
print(maxScore([5, 5, 5, 5]))         # 15   # 解释：每一步都只能等距跳
```

> 代码每行都加了中文注释，直接复制运行即可得到答案。

#### 复杂度

- **时间复杂度**：`O(n)`  
  - **含义**：只遍历了一遍数组，每个元素最多进栈一次、出栈一次，类似“一次扫过”。相较于暴力的 `O(n²)`，速度提升了 **n 倍**（比如 10⁵ 的数组只需要 ~10⁵ 次操作，几乎瞬间完成）。  
- **空间复杂度**：`O(n)`  
  - **含义**：最坏情况下栈里会保存所有下标（比如严格递减的数组），需要和数组大小同等的额外内存。

## 心得

- **核心技巧**：**单调栈** + **最近更大元素**（Next Greater Element）  
- 该技巧常用于需要“左/右侧第一个满足某种关系的元素”的题目，例如  
  1. **每日温度**（找到右侧第一个更高温度）  
  2. **柱状图中最大的矩形**（利用单调栈求左右边界）  
  3. **子数组最小值之和**（左/右侧第一个更小元素）  
- **一句话总结解题钥匙**：*从每个位置只看最近的、更大的右侧元素，利用单调栈一次扫完即可得到全部跳得分。*

## 反思

- **第一反应**：想到“枚举所有跳法”或“动态规划”，但忽略了得分公式中 “距离 × 当前值” 的特殊结构。  
- **最容易踩的坑**  
  - 忘记把 **最后一个下标**也加入循环，使得栈中残余元素没有机会被弹出，导致答案缺少跳到末尾的得分。  
  - 误以为要比较 “距离” 与 “值” 的大小，实际上只需要比较 **值的大小**（因为距离是由最近更大决定的）。  
- **下次遇到同类题**，第一步应该问自己：*“我只需要找最近满足某个不等式的右侧元素吗？”* 若答案是“是”，就立刻考虑 **单调栈**（或单调队列）来线性求解。
