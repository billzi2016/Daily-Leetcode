## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把 **`zero`** 个 `0` 和 **`one`** 个 `1` 全部排成一列，枚举所有可能的排列，然后把每一种排列逐个检查：

1. 统计相邻相同数字组成的连续块（比如 `[0,0,0,1,1]` 中有块 `000`、`11`）。  
2. 若所有块的长度都 **不超过 `limit`**，则这条排列是 “stable”。  
3. 把所有符合条件的排列计数即可。

> **数据结构类比**  
> - **数组**：我们把要排列的 `0`、`1` 放进一个数组，就像把不同颜色的积木按顺序摆放。  
> - **递归/回溯**：把每一步看成“从剩下的积木里挑一个放到最右边”，类似于我们在写字时每写一个字母就决定了下一步的选择。

只要把所有可能的放置顺序穷举完，就一定能找到所有 stable 数组——因为我们没有遗漏任何一种排列。

#### 代码（Python）

```python
MOD = 10**9 + 7

def brute(zero: int, one: int, limit: int) -> int:
    # 用深度优先搜索枚举所有排列
    def dfs(z, o, last, cnt, ans):
        """
        z   : 还剩多少 0 未使用
        o   : 还剩多少 1 未使用
        last: 上一个放的数字（0 / 1），-1 表示还没放
        cnt : 当前连续块的长度
        ans : 已经得到的 stable 数组数量（全局计数）
        """
        if z == 0 and o == 0:          # 所有数字都用了，合法答案 +1
            ans[0] = (ans[0] + 1) % MOD
            return

        # 尝试放 0
        if z > 0:
            # 如果上一次也是 0，必须检查块长度是否已到 limit
            if last == 0 and cnt == limit:
                pass                    # 不能再放 0 了
            else:
                dfs(z - 1, o,
                    0,
                    cnt + 1 if last == 0 else 1,
                    ans)

        # 尝试放 1（与放 0 完全对称）
        if o > 0:
            if last == 1 and cnt == limit:
                pass
            else:
                dfs(z, o - 1,
                    1,
                    cnt + 1 if last == 1 else 1,
                    ans)

    answer = [0]                     # 用列表装箱，使内部函数可以修改
    dfs(zero, one, -1, 0, answer)
    return answer[0]
```

> **关键行中文注释**  
> - `if last == 0 and cnt == limit:` 判断当前块已经达到上限，若再放同样的数字会违规。  
> - `cnt + 1 if last == 0 else 1` 如果继续放同一个数字，块长度 +1；否则重新开始计数为 1。  

#### 复杂度

- **时间复杂度**：`O(2^{zero+one})`  
  因为每一步都有两种选择（放 `0` 或 `1`），最坏情况下会遍历所有二进制序列，指数级增长。  
  用大白话说，若 `zero+one = 20`，可能的排列就有 `2^20 ≈ 1,048,576` 条；`30` 时已经是十亿级，根本跑不完。

- **空间复杂度**：`O(zero+one)`  
  递归栈的深度等于数组长度，最多保存 `zero+one` 层调用信息。

### 2. 最优解

#### 思路  

暴力解的瓶颈在 **“每一次都重新遍历整条序列”**。  
我们可以把问题拆成**子问题**：  
> “已放了 `x` 个 `0`、`y` 个 `1`，且最后一个数字是 `z`（0 或 1），有多少种合法排列？”

记作 `dp[x][y][z]`。  
如果我们已经知道所有更小的子问题的答案，就可以**快速求出更大的子问题**——这正是**动态规划**的核心思想。

---

#### 2.1 为何可以只关注“最后一块的长度”？

设当前要在数组末尾放一段连续的 `0`（长度为 `k`），那么：

* 这段 `0` 必须 **紧跟在一个 `1`**（因为我们把它当作“一块”来放），
* 前面已经有 `x-k` 个 `0`、`y` 个 `1`，且**最后一个数字是 `1`**。

于是，这种情况的排列数恰好是 `dp[x-k][y][1]`（把前面所有合法排列后面接上 `k` 个 `0`）。

同理，若要在末尾放一段 `1`，则对应 `dp[x][y-k][0]`。

> **类比**：把拼图看成“先拼好左边的部分”，右边再拼一块完整的 `0` 或 `1`，只要左边合法，整体就合法。

---

#### 2.2 直接递推的时间是 `O(zero * one * limit)`  

因为对每个 `(x, y, z)`，我们要枚举 **块的长度 `k`**，`k` 的取值范围是 `1 … limit`（且不能超过剩余的 `0` 或 `1`）。  
若 `limit` 达到 `1000`，三层循环的乘积会达到 `10^9`，仍然超时。

---

#### 2.3 前缀和（Prefix Sum）加速  

观察 `dp[x][y][0]` 的递推式：

```
dp[x][y][0] = Σ_{k=1}^{min(limit, x)} dp[x-k][y][1]
```

这其实是 **对 `dp[*][y][1]` 的前缀和**（只取最近的 `limit` 项）。  
如果我们在遍历 `x` 时，维护一个滚动的前缀和数组 `pre0[x][y]`：

```
pre0[x][y] = pre0[x-1][y] + dp[x][y][1]
```

则：

```
dp[x][y][0] = pre0[x-1][y] - pre0[max(0, x-limit-1)][y]
```

同理可得 `dp[x][y][1]` 的式子。  
这样每个状态只需要 **O(1)** 的时间即可算出，整体时间降到 **`O(zero * one)`**。

---

#### 2.4 初始化

* `dp[0][0][0] = dp[0][0][1] = 1`  
  表示空数组（既没有 `0` 也没有 `1`）可以看作“最后是 0”也可以看作“最后是 1”，方便后续转移。

* 对于只包含 `0`（或只包含 `1`）的情况，需要检查块长度是否超过 `limit`。利用前缀和同样可以直接得到。

---

#### 2.5 代码实现（Python）

```python
MOD = 10**9 + 7

def stable_arrays(zero: int, one: int, limit: int) -> int:
    # dp0[x][y] : 以 0 结尾，使用了 x 个 0、y 个 1 的合法数组数目
    # dp1[x][y] : 以 1 结尾，使用了 x 个 0、y 个 1 的合法数组数目
    dp0 = [[0] * (one + 1) for _ in range(zero + 1)]
    dp1 = [[0] * (one + 1) for _ in range(zero + 1)]

    # 前缀和数组，帮助 O(1) 求区间和
    pre0 = [[0] * (one + 1) for _ in range(zero + 1)]  # 对 dp0 的前缀和（按 x 方向）
    pre1 = [[0] * (one + 1) for _ in range(zero + 1)]  # 对 dp1 的前缀和（按 y 方向）

    # 空数组既可以视作以 0 结尾，也可以视作以 1 结尾
    dp0[0][0] = dp1[0][0] = 1
    pre0[0][0] = dp0[0][0]
    pre1[0][0] = dp1[0][0]

    # 先遍历所有 (x, y) 的组合
    for x in range(zero + 1):
        for y in range(one + 1):
            if x == 0 and y == 0:
                continue    # 已经初始化

            # ---------- 计算以 0 结尾的 dp ----------
            # 需要在前面已经以 1 结尾的状态后面接上一段 0（长度 1~limit）
            # 区间和：pre1[x-1][y] - pre1[max(-1, x-limit-1)][y]
            left = max(0, x - limit)          # 可以取到的最左侧 x 坐标（包含）
            # 前缀和是对 dp1 按 x 方向累加的，所以直接用 pre1
            total = (pre1[x - 1][y] if x > 0 else 0)
            if left - 1 >= 0:
                total = (total - pre1[left - 1][y]) % MOD
            dp0[x][y] = total

            # ---------- 计算以 1 结尾的 dp ----------
            # 与上面对称，只是把 x 换成 y，dp0 换成 dp1
            up = max(0, y - limit)
            total = (pre0[x][y - 1] if y > 0 else 0)
            if up - 1 >= 0:
                total = (total - pre0[x][up - 1]) % MOD
            dp1[x][y] = total

            # ---------- 更新前缀和 ----------
            # pre0 按 x 方向累加：pre0[x][y] = pre0[x-1][y] + dp0[x][y]
            pre0[x][y] = ( (pre0[x - 1][y] if x > 0 else 0) + dp0[x][y] ) % MOD
            # pre1 按 y 方向累加：pre1[x][y] = pre1[x][y-1] + dp1[x][y]
            pre1[x][y] = ( (pre1[x][y - 1] if y > 0 else 0) + dp1[x][y] ) % MOD

    # 最终答案是两种结尾方式的和
    return (dp0[zero][one] + dp1[zero][one]) % MOD
```

> **代码要点中文解释**  
> - `dp0[x][y]` / `dp1[x][y]`：分别记录“**以 0/1 结尾**”的合法排列数。  
> - `pre0`、`pre1`：滚动前缀和，让我们在 **O(1)** 时间内求出 “最近 `limit` 项之和”。  
> - `left = max(0, x-limit)`：确保不越界（不能取负的下标）。  
> - `total = (pre1[x-1][y] - pre1[left-1][y]) % MOD`：实现区间求和，等价于 “把前面以 1 结尾的状态，加上长度为 `k` 的 0 块”。  

#### 复杂度

- **时间复杂度**：`O(zero * one)`  
  每个 `(x, y)` 只做常数次算术运算（前缀和查询），与 `limit` 无关。  
  相比暴力的指数级，这里可以轻松跑完 `1000 × 1000 = 10⁶` 的规模。

- **空间复杂度**：`O(zero * one)`  
  需要存 `dp0、dp1、pre0、pre1` 四个二维表，都是 ` (zero+1) × (one+1)` 大小。  
  对于上限 `1000`，大约占用 4 × 10⁶ 个整数，约 32 MB，完全可接受。

## 心得

- **核心技巧**：用 **三维 DP**（`x、y、最后一个数字`）把全局约束拆解成局部转移，再用 **前缀和** 把每个状态的 `limit` 次枚举压到 `O(1)`。  
- **适用的题型**  
  1. “限定连续块长度” 类的计数问题（如 *Stable Binary Array I*、*Count Binary Strings with No Consecutive 1s of Length > K*）。  
  2. 需要在二维计数格子上做 **区间求和** 的 DP（如 *Number of Ways to Paint Grid*、*Count Paths with Limited Consecutive Moves*）。  
- **一句话总结解题钥匙**：**把“把一段相同数字放进来” 看成一次转移，用前缀和把这段长度的所有可能一次性算完**。

## 反思

- **第一反应**：看到 “zero、one、limit” 这三个参数，我首先想到“枚举所有排列，然后检查每段长度”。这自然导向暴力搜索。  
- **最容易踩的坑**  
  1. **边界条件**：`limit` 可能大于 `zero` 或 `one`，需要在取最小值时防止负数或越界。  
  2. **模数运算**：在前缀和相减时要加上 `MOD` 再取模，防止出现负数。  
  3. **初始化**：空数组要同时计入 `dp0[0][0]` 与 `dp1[0][0]`，否则后续转移会缺少基准。  
- **下次类似题的第一步**：**先写出状态定义**（如 `dp[x][y][last]`），确认转移方程后，再思考如何用前缀和/滚动数组把 “枚举长度” 的循环去掉。这样可以把指数级的思路快速压缩到多项式时间。
