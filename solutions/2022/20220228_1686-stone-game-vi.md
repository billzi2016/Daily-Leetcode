## 题目（英文原版）

**Description**

Alice and Bob take turns playing a game, with Alice starting first.
There are n stones in a pile. On each player's turn, they can remove a stone from the pile and receive points based on the stone's value. Alice and Bob may value the stones differently.
You are given two integer arrays of length n, aliceValues and bobValues. Each aliceValues[i] and bobValues[i] represents how Alice and Bob, respectively, value the ith stone.
The winner is the person with the most points after all the stones are chosen. If both players have the same amount of points, the game results in a draw. Both players will play optimally. Both players know the other's values.
Determine the result of the game, and:

**Examples**

**Example 1:**

```
Input: aliceValues = [1,3], bobValues = [2,1]
Output: 1
Explanation:
If Alice takes stone 1 (0-indexed) first, Alice will receive 3 points.
Bob can only choose stone 0, and will only receive 2 points.
Alice wins.
```

**Example 2:**

```
Input: aliceValues = [1,2], bobValues = [3,1]
Output: 0
Explanation:
If Alice takes stone 0, and Bob takes stone 1, they will both have 1 point.
Draw.
```

**Example 3:**

```
Input: aliceValues = [2,4,3], bobValues = [1,6,7]
Output: -1
Explanation:
Regardless of how Alice plays, Bob will be able to have more points than Alice.
For example, if Alice takes stone 1, Bob can take stone 2, and Alice takes stone 0, Alice will have 6 points to Bob's 7.
Bob wins.
```

**Constraints**

- n == aliceValues.length == bobValues.length
- 1 <= n <= 105
- 1 <= aliceValues[i], bobValues[i] <= 100

## 题目（中文翻译）

Alice 和 Bob 轮流进行游戏，Alice 先手。  
有一堆包含 n 颗石子的石堆。每轮玩家可以从石堆中移除一颗石子，并根据该石子的价值获得相应的分数。Alice 和 Bob 对石子的价值可能不同。  

给定两个长度为 n 的整数数组 `aliceValues` 和 `bobValues`。数组 `aliceValues[i]` 与 `bobValues[i]` 分别表示第 i 颗石子对 Alice 和 Bob 的价值。  

所有石子被选完后，分数最高者获胜；若两人分数相同，则为平局。两位玩家都会进行最优（optimal）策略的选择，并且彼此都知道对方的价值数组。  

请判断游戏的结果，并返回：
- 1，若 Alice 获胜  
- 0，若平局  
- -1，若 Bob 获胜  

示例 1:  
Input: `aliceValues = [1,3]`, `bobValues = [2,1]`  
Output: `1`  
Explanation:  
如果 Alice 先取下下标为 1 的石子，她将获得 3 分。  
Bob 只能选择下标为 0 的石子，只能得到 2 分。  
Alice 获胜。  

示例 2:  
Input: `aliceValues = [1,2]`, `bobValues = [3,1]`  
Output: `0`  
Explanation:  
如果 Alice 取下石子 0，Bob 取下石子 1，双方各得到 1 分。  
平局。  

示例 3:  
Input: `aliceValues = [2,4,3]`, `bobValues = [1,6,7]`  
Output: `-1`  
Explanation:  
不论 Alice 如何选择，Bob 都能取得比 Alice 更多的分数。  
例如，Alice 取下石子 1，Bob 取下石子 2，随后 Alice 取下石子 0，Alice 的总分为 6，Bob 为 7。  
Bob 获胜。  

约束条件:  
- `n == aliceValues.length == bobValues.length`  
- `1 <= n <= 10^5`  
- `1 <= aliceValues[i], bobValues[i] <= 100`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**模拟**两个人交替挑选石头的过程。  
- 把所有石头编号 `0 … n-1` 放进一个列表。  
- 在每一轮，轮到的玩家遍历剩余的石头，挑选**对自己价值最高**的那一块（`aliceValues[i]` 对 Alice，`bobValues[i]` 对 Bob），把对应的分数加入自己的总分，然后把这块石头从列表中删掉。  
- 重复 `n` 次（每次删掉一块），最后比较 Alice 与 Bob 的总分，返回 `1 / 0 / -1`。

> **类比**：把石头想象成超市里的商品，Alice 和 Bob 分别有自己的“喜欢程度”。每个人轮到时，就去货架上挑自己最喜欢的商品买下来。

这种方法**一定能得到正确答案**，因为我们严格按照题目描述的“每回合选自己价值最高的石头”来执行，而且两人都按最优（对自己最有利）策略行动。

然而，这个做法在 **时间** 上非常慢：每轮都要遍历剩余的石头寻找最大值，最坏情况要遍历 `n`、`n-1`、…、`1` 次，总共约 `n²/2` 次比较。

#### 代码（Python）

```python
from typing import List

def stoneGameVI_bruteforce(aliceValues: List[int], bobValues: List[int]) -> int:
    n = len(aliceValues)
    # 剩余石头的下标集合
    remaining = list(range(n))
    alice_score, bob_score = 0, 0
    turn_alice = True                     # True 表示 Alice 这回合

    while remaining:                      # 只要还有石头就继续
        if turn_alice:                     # Alice 选
            # 找出对 Alice 价值最大的石头下标
            best_idx = max(remaining, key=lambda i: aliceValues[i])
            alice_score += aliceValues[best_idx]
        else:                               # Bob 选
            best_idx = max(remaining, key=lambda i: bobValues[i])
            bob_score += bobValues[best_idx]

        remaining.remove(best_idx)         # 这块石头被拿走
        turn_alice = not turn_alice         # 换下家

    # 根据总分返回结果
    if alice_score > bob_score:
        return 1
    if alice_score == bob_score:
        return 0
    return -1
```

#### 复杂度  

- **时间复杂度**：`O(n²)`  
  解释：第一轮要遍历 `n` 块石头找最大值，第二轮遍历 `n‑1`，…，最后一轮遍历 `1`，相加就是 `n + (n-1) + … + 1 = n·(n+1)/2 ≈ n²/2`，即二次方级别。  
- **空间复杂度**：`O(n)`  
  解释：我们用了一个列表 `remaining` 保存剩余石头的下标，最坏需要存 `n` 个下标。

> 对于 `n` 最高可达 `10⁵` 的情况，`O(n²)` 完全不可接受，会超时。

### 2. 最优解

#### 思路  

**从暴力解的瓶颈出发**：每轮都要遍历所有剩余石头寻找最大价值，这一步最慢。  
我们需要一种办法，使得“挑选”这一步可以 **瞬间** 完成。  

观察题目提示：  
> 当一个玩家拿走石头时，不仅自己得分，还**把这块石头从对手手中夺走**（对手以后再也拿不到这块石头对应的分数）。

因此，对每块石头 `i`，它对**局势**的影响其实是 `aliceValues[i] + bobValues[i]`：

- 若 Alice 把它拿走，她得到 `aliceValues[i]`，同时 Bob 再也得不到 `bobValues[i]`，等价于 Alice **相对**提升了 `aliceValues[i] + bobValues[i]` 分。
- 同理，若 Bob 把它拿走，他相对提升 `aliceValues[i] + bobValues[i]` 分。

于是，**双方都希望先抢走“总价值”最大的石头**，因为这块石头对比分差的贡献最大。  
这就把原本的“每回合选自己最高价值”问题转化为：

> 按照 `aliceValues[i] + bobValues[i]` 从大到小排个序，轮流取排好的序列（Alice 先取），累计各自的真实得分即可。

**为什么这样最优？**  
- 假设有两块石头 `x`、`y`，且 `sum_x = a_x + b_x` 大于 `sum_y`。如果 Alice 先拿 `y`，而 Bob later 拿 `x`，则 Alice 实际得到 `a_y`，Bob 得到 `b_x`。如果调换顺序（Alice 先拿 `x`），Alice 会得到 `a_x`，Bob 只能得到 `b_y`。两种情况的分差分别是  
  - 先拿 `y`：`(a_y - b_x)`  
  - 先拿 `x`：`(a_x - b_y)`  
  计算差值：`(a_x - b_y) - (a_y - b_x) = (a_x + b_x) - (a_y + b_y) = sum_x - sum_y > 0`。  
  所以 **先拿总价值大的石头** 能让 Alice（先手）得到更大的分差，Bob 也会有同样的动机。于是**贪心排序**是最优的。

**实现步骤**  

1. 对每个下标 `i` 计算 `total[i] = aliceValues[i] + bobValues[i]`。  
2. 按 `total` 降序排列下标（或直接把 `(total, alice, bob)` 三元组排序）。  
3. 按序遍历：奇数位置（0、2、4…）是 Alice 拿的，累加对应的 `aliceValues[i]`；偶数位置（1、3、5…）是 Bob 拿的，累加对应的 `bobValues[i]`。  
4. 最后比较两人的总分返回 `1 / 0 / -1`。

> **类比**：把每块石头看成一块“价值卡”，卡面上写着两个数字（Alice 的分、Bob 的分），卡的总价值是两数之和。两个人轮流抽卡，大家都会先抢“总价值最高”的卡，因为这张卡对比分的影响最大。

#### 代码（Python）

```python
from typing import List

def stoneGameVI(aliceValues: List[int], bobValues: List[int]) -> int:
    # 1. 计算每块石头的总价值，并一起保存对应的 Alice/Bob 分数
    stones = [(a + b, a, b) for a, b in zip(aliceValues, bobValues)]
    # 2. 按总价值降序排列
    stones.sort(key=lambda x: x[0], reverse=True)

    alice_score, bob_score = 0, 0
    # 3. 按序轮流取石头
    for turn, (_, a, b) in enumerate(stones):
        if turn % 2 == 0:          # Alice 先手，偶数 turn（0、2、4…）属于 Alice
            alice_score += a
        else:                      # Bob 的回合
            bob_score += b

    # 4. 比分判断
    if alice_score > bob_score:
        return 1
    if alice_score == bob_score:
        return 0
    return -1
```

#### 复杂度  

- **时间复杂度**：`O(n log n)`  
  解释：我们需要对 `n` 个石头按照 `total` 排序，排序的代价是 `n log n`（对数级），随后遍历一次 `O(n)`。整体 dominated by 排序。相比暴力的 `O(n²)` 快了很多。  
- **空间复杂度**：`O(n)`  
  解释：我们额外创建了一个长度为 `n` 的列表 `stones` 来保存三元组，除此之外只用了常数级的额外空间。

> 对于 `n = 10⁵`，`O(n log n)` 完全可以在一秒左右跑完。

## 心得

- **核心技巧**：把“对手失去的分数”也算进当前玩家的收益，转化为 **总价值 = Alice 分 + Bob 分**，然后使用 **贪心排序**。  
- **适用场景**：  
  1. 双方得分不同但都想抢占对手的机会（如 *Stone Game VI*、*Pick Gifts* 类题）。  
  2. 两人轮流选取资源，资源对双方的价值已知（如 *Two Player Game with Different Scores*）。  
  3. 需要比较“相对优势”而不是绝对得分的博弈问题。  
- **一句话总结**：**先抢“总价值”最大的石头，才能最大化自己的相对优势。**

## 反思

- **第一反应**：看到“轮流取石头”，自然想到模拟每回合选最大值的暴力过程。  
- **最容易踩的坑**：  
  - 忽略了 **对手失去的分数**，只考虑自己得到的分，导致错误的贪心策略（仅按 `aliceValues` 排序会不对）。  
  - 边界情况：当 `n` 为奇数时，Alice 会比 Bob 多拿一块石头，需要确保遍历时的 `turn % 2` 判定正确。  
- **下次类似题的第一步**：先问自己“拿走这块资源对双方的**相对比分**有什么影响”，如果是 **`value_A + value_B`** 这种线性组合，那么就尝试 **按总价值排序的贪心**。
