# #1847. **最接近的房间** / Closest Room

> 难度：困难 · 标签：Array、Binary Search、Sorting、Ordered Set · [LeetCode 链接](https://leetcode.com/problems/closest-room/)

## 题目（英文原版）

**Description**

There is a hotel with n rooms. The rooms are represented by a 2D integer array rooms where rooms[i] = [roomIdi, sizei] denotes that there is a room with room number roomIdi and size equal to sizei. Each roomIdi is guaranteed to be unique.
You are also given k queries in a 2D array queries where queries[j] = [preferredj, minSizej]. The answer to the jth query is the room number id of a room such that:
If there is a tie in the absolute difference, then use the room with the smallest such id. If there is no such room, the answer is -1.
Return an array answer of length k where answer[j] contains the answer to the jth query.

**Examples**

**Example 1:**

```
Input: rooms = [[2,2],[1,2],[3,2]], queries = [[3,1],[3,3],[5,2]]
Output: [3,-1,3]
Explanation: The answers to the queries are as follows:
Query = [3,1]: Room number 3 is the closest as abs(3 - 3) = 0, and its size of 2 is at least 1. The answer is 3.
Query = [3,3]: There are no rooms with a size of at least 3, so the answer is -1.
Query = [5,2]: Room number 3 is the closest as abs(3 - 5) = 2, and its size of 2 is at least 2. The answer is 3.
```

**Example 2:**

```
Input: rooms = [[1,4],[2,3],[3,5],[4,1],[5,2]], queries = [[2,3],[2,4],[2,5]]
Output: [2,1,3]
Explanation: The answers to the queries are as follows:
Query = [2,3]: Room number 2 is the closest as abs(2 - 2) = 0, and its size of 3 is at least 3. The answer is 2.
Query = [2,4]: Room numbers 1 and 3 both have sizes of at least 4. The answer is 1 since it is smaller.
Query = [2,5]: Room number 3 is the only room with a size of at least 5. The answer is 3.
```

**Constraints**

- n == rooms.length
- 1 <= n <= 105
- k == queries.length
- 1 <= k <= 104
- 1 <= roomIdi, preferredj <= 107
- 1 <= sizei, minSizej <= 107

## 题目（中文翻译）

有一家酒店拥有 `n` 间客房。客房信息用二维整数数组 `rooms` 表示，其中 `rooms[i] = [roomId_i, size_i]` 表示第 `i` 间客房的房间号为 `roomId_i`、面积为 `size_i`。保证每个 `roomId_i` 均唯一。

同时给定 `k` 条查询，存放在二维数组 `queries` 中，`queries[j] = [preferred_j, minSize_j]`。第 `j` 条查询的答案是满足以下条件的房间号 `id`：

* 房间的面积 `size` 必须 **大于等于** `minSize_j`；
* 在所有满足面积条件的房间中，选取 **房间号与 `preferred_j` 的绝对差值最小** 的房间；
* 若存在多个房间的绝对差值相同，则返回 **房间号最小** 的那一间；
* 若不存在满足条件的房间，则答案为 `-1`。

返回长度为 `k` 的数组 `answer`，其中 `answer[j]` 为第 `j` 条查询的答案。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**对每一个查询**，遍历全部房间，挑出满足「房间面积 ≥ 查询要求的最小面积」的候选房间，然后在这些候选房间里找 **房间号** 与 **preferred** 差的绝对值最小的那一个。  
这和日常生活中的「在所有满足条件的商品里挑最接近我想要的价位」完全一样，只是把「商品」换成「房间」，把「价位」换成「房间号」。

- **数据结构**：我们只需要 Python 的 `list` 来存放 `rooms` 和 `queries`，不需要额外的哈希表、堆或树。  
  - `list` 就像一本顺序排列的目录，按下标依次取元素，查找时只能线性遍历。

- **正确性**：因为我们把所有房间都检查了一遍，必然不会漏掉任何满足「size ≥ minSize」的房间；在这些房间中再比较 `abs(roomId - preferred)`，自然就能得到差值最小、且在差值相同的情况下取最小 `roomId` 的答案。

- **时间/空间复杂度**：  
  - 对每个查询我们都要遍历 `n` 个房间，查询有 `k` 条，所以总的时间是 `n × k`，记作 **O(n·k)**。  
    - 这里的 **O** 只是一种“量级”描述，意思是「随着房间数和查询数的增大，运行时间会按它们的乘积快线性增长」。
  - 只使用了常数级别的额外空间（几个计数器），记作 **O(1)**。

#### 代码（Python）

```python
from typing import List

def closestRoom_bruteforce(rooms: List[List[int]],
                           queries: List[List[int]]) -> List[int]:
    """
    暴力解：对每个查询线性扫描所有房间
    rooms[i]   = [roomId, size]
    queries[j] = [preferred, minSize]
    """
    ans = []
    for preferred, minSize in queries:
        best_id = -1          # 暂存当前最好的房间号
        best_diff = float('inf')   # 暂存当前最小的 |roomId - preferred|
        for roomId, size in rooms:
            if size < minSize:          # 房间太小，直接跳过
                continue
            diff = abs(roomId - preferred)
            # 如果差更小，或差相同但房间号更小，就更新答案
            if diff < best_diff or (diff == best_diff and roomId < best_id):
                best_diff = diff
                best_id = roomId
        ans.append(best_id)
    return ans
```

#### 复杂度  

- **时间复杂度**：**O(n·k)**  
  - 举例来说，如果有 10⁵ 个房间、10⁴ 条查询，最坏会进行 10⁹ 次比较，明显会超时。  
- **空间复杂度**：**O(1)**（不计输出数组的空间）

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **每个查询都要遍历所有房间**，导致 `n·k` 的乘积。  
要把时间降下来，需要 **让查询只看「已经满足面积要求」的房间**，而不是所有房间。

##### 关键观察  

- 查询只关心 **size ≥ minSize** 的房间。  
- 如果我们把房间按照 **size 从大到小** 排序，并且把查询也按照 **minSize 从大到小** 排序，那么在处理一个查询时，**所有已经遍历过的房间** 一定都满足当前查询的 `minSize`（因为它们的 size 更大）。  
- 于是我们可以维护一个 **只包含满足当前最小面积要求的房间号集合**，对每个查询只在这个集合里寻找最接近 `preferred` 的房间号。

##### 使用的数据结构  

- **有序集合（Ordered Set）**：在 C++/Java 中有 `TreeSet` / `TreeMap`，可以在 **O(log n)** 时间内完成  
  - “插入一个房间号”  
  - “寻找离 `preferred` 最近的左侧/右侧房间号”（前驱、后继）。  
  - 类比：有序集合像一本 **已按字母顺序排好** 的词典，查找单词只需要二分查找，而不需要从头到尾遍历。

- 在 Python 标准库里没有直接的平衡树实现，最常见的做法是使用第三方库 `sortedcontainers` 的 `SortedList`，它内部采用 **平衡二叉搜索树**，提供 **O(log n)** 的插入和查找。这里的解释和代码都基于 `SortedList`（如果在实际面试中只能使用标准库，可以把它换成自己实现的平衡树或说明思路即可）。

##### 步骤详解  

1. **把房间按 size 降序排列**，得到 `rooms_sorted`。  
2. **把查询按 minSize 降序排列**，同时记录每个查询在原数组中的下标（因为最终答案要恢复原顺序）。得到 `queries_sorted`。  
3. 初始化一个空的有序集合 `ids`（用 `SortedList`）。准备一个指针 `i = 0` 指向 `rooms_sorted` 的开头。  
4. 按 `queries_sorted` 的顺序逐个处理查询：  
   - 把 **所有 size ≥ 当前查询的 minSize** 的房间加入 `ids`（即 while `i < n` and `rooms_sorted[i].size >= query.minSize`: insert `roomId` into `ids`, i++）。因为查询是按 minSize 从大到小处理，这一步只会向集合中 **追加**，不会删除。  
   - 此时 `ids` 中恰好是「所有满足当前查询最小面积」的房间号，且已经保持有序。  
   - 使用二分查找在 `ids` 中找 **最接近 `preferred` 的房间号**：  
     - `pos = ids.bisect_left(preferred)` 得到第一个 **≥ preferred** 的位置。  
     - 候选房间有两种可能：`ids[pos]`（右侧）和 `ids[pos-1]`（左侧），取两者中差值更小的；如果差值相同，取 **roomId 更小** 的。  
   - 将得到的答案写入结果数组对应的原下标位置。  
5. 所有查询处理完后，返回结果数组。

##### 为什么是最优的  

- 每个房间只会被插入一次，插入成本 **O(log n)**。  
- 每个查询只做一次二分查找（`bisect_left`），同样是 **O(log n)**。  
- 整体时间复杂度是 **O((n + k)·log n)**，远远小于暴力的 **O(n·k)**。  
- 只用了一个有序集合保存房间号，额外空间 **O(n)**（存放所有房间号），符合题目约束。

#### 代码（Python）

> **注意**：下面的实现依赖 `sortedcontainers` 第三方库。如果在实际环境中不能使用该库，只需要把 `SortedList` 替换成自己实现的平衡树或使用语言自带的有序集合（如 C++ 的 `std::set`），思路保持不变。

```python
from typing import List
from sortedcontainers import SortedList   # pip install sortedcontainers

def closestRoom(rooms: List[List[int]], queries: List[List[int]]) -> List[int]:
    """
    最优解：离线排序 + 有序集合（Balanced BST）
    时间复杂度 O((n + k) log n) ，空间复杂度 O(n)
    """
    # 1. 按 size 降序排列房间
    rooms_sorted = sorted(rooms, key=lambda x: -x[1])   # x[1] 是 size

    # 2. 把查询也按 minSize 降序排列，同时保存原始下标
    queries_with_index = [(pref, minSize, idx) for idx, (pref, minSize) in enumerate(queries)]
    queries_sorted = sorted(queries_with_index, key=lambda x: -x[1])  # 按 minSize 降序

    # 3. 有序集合，存放已经满足当前 minSize 的房间号
    ids = SortedList()

    ans = [-1] * len(queries)   # 预分配答案数组
    i = 0                       # rooms_sorted 的指针

    # 4. 逐个处理查询
    for pref, minSize, original_idx in queries_sorted:
        # 把所有 size >= minSize 的房间加入集合
        while i < len(rooms_sorted) and rooms_sorted[i][1] >= minSize:
            room_id = rooms_sorted[i][0]
            ids.add(room_id)          # O(log n)
            i += 1

        if not ids:                  # 此时没有任何满足面积要求的房间
            ans[original_idx] = -1
            continue

        # 在有序集合里找最接近 pref 的房间号
        pos = ids.bisect_left(pref)  # 第一个 >= pref 的位置
        best_id = None
        best_diff = float('inf')

        # 检查右侧候选（如果存在）
        if pos < len(ids):
            cand = ids[pos]
            diff = abs(cand - pref)
            if diff < best_diff or (diff == best_diff and cand < best_id):
                best_diff = diff
                best_id = cand

        # 检查左侧候选（如果存在）
        if pos > 0:
            cand = ids[pos - 1]
            diff = abs(cand - pref)
            if diff < best_diff or (diff == best_diff and cand < best_id):
                best_diff = diff
                best_id = cand

        ans[original_idx] = best_id

    return ans
```

#### 复杂度  

- **时间复杂度**：**O((n + k)·log n)**  
  - 插入每个房间号一次 `log n`，查询 `k` 次 `log n`，两者相加即为总耗时。相比暴力的 `n·k`，这在 `n = 10⁵、k = 10⁴` 的极限情况下仍然能在毫秒级完成。  
- **空间复杂度**：**O(n)**  
  - 主要是有序集合 `ids` 最多会存放所有房间号（`n` 个），以及排序后产生的临时数组。

## 心得

- **核心技巧**：**离线排序 + 有序集合（平衡二叉搜索树）**  
  - 通过把「查询」和「数据」统一按照某个单调属性（这里是 `size/minSize`）排序，使得在处理每个查询时，只需要 **增量** 地维护满足条件的元素集合，避免每次重新遍历全部数据。  
- **适用的题型**：  
  1. “在满足某个阈值的元素中找最接近目标值”——如 *Maximum Frequency Stack*、*Closest Pair*。  
  2. “多次查询区间或阈值，要求快速返回满足条件的最优解”——如 *Maximum Subarray Sum After One Operation*（需要有序结构）等。  
- **一句话总结**：**把查询和数据一起排序，只向有序集合中“增添”满足条件的元素，再用二分找最近值**，即可把指数级暴力降到对数级。

## 反思

- **第一反应**：直接遍历所有房间，写出最朴素的实现。  
- **最容易踩的坑**：  
  - 忘记在差值相同的情况下返回 **roomId 更小** 的房间。  
  - 处理 `ids` 为空的情况会导致 `bisect_left` 报错，需要单独判断。  
  - 需要保留查询的原始下标，否则答案顺序会被排序打乱。  
- **下次遇到同类题**，第一步应该先问自己：  
  - “有没有可以把查询按某个阈值排序的思路？”  
  - “是否能维护一个只包含‘当前满足阈值’的有序集合来快速定位最优解？”  
  只要把这两个问题的答案想清楚，往往就能快速构造出 **O((n+k)log n)** 的高效方案。
