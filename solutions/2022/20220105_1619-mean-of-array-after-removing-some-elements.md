## 题目（英文原版）

**Description**

Given an integer array arr, return the mean of the remaining integers after removing the smallest 5% and the largest 5% of the elements.
Answers within 10-5 of the actual answer will be considered accepted.

**Examples**

**Example 1:**

```
Input: arr = [1,2,2,2,2,2,2,2,2,2,2,2,2,2,2,2,2,2,2,3]
Output: 2.00000
Explanation: After erasing the minimum and the maximum values of this array, all elements are equal to 2, so the mean is 2.
```

**Example 2:**

```
Input: arr = [6,2,7,5,1,2,0,3,10,2,5,0,5,5,0,8,7,6,8,0]
Output: 4.00000
```

**Example 3:**

```
Input: arr = [6,0,7,0,7,5,7,8,3,4,0,7,8,1,6,8,1,1,2,4,8,1,9,5,4,3,8,5,10,8,6,6,1,0,6,10,8,2,3,4]
Output: 4.77778
```

**Constraints**

- 20 <= arr.length <= 1000
- arr.length is a multiple of 20.
- 0 <= arr[i] <= 105

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**把数组从小到大排好序**，然后把排在最前面的 5%（最小的元素）和最后面的 5%（最大的元素）直接删掉，剩下的元素求平均值。

- **排序**：把所有数字排成一条有序的“队列”。  
- **切片**：把队首的 `k = n·5%`（这里 `n` 是数组长度）个元素和队尾的 `k` 个元素“踢出去”。  
- **求平均**：把剩下的元素加起来除以剩余的个数。

这里的 **哈希表** 并不需要，用到的唯一数据结构是**列表**（Python 的 `list`），它相当于一本可以随意增删的笔记本，排序后我们只需要把前面几页和后面几页撕掉。

**为什么正确**  
因为题目要求去掉最小的 5% 与最大的 5%——这正好对应排好序后两端的元素。把这两端的元素删掉后，剩下的就是题目要的“中间部分”，直接算平均即可。

**复杂度分析（大白话）**  
- 排序一步相当于把一堆乱糟糟的纸片整理成顺序，需要 **O(n log n)** 的时间（想象把 1000 张纸按照数字顺序摆好，大约需要 1000×log₂1000 次比较）。  
- 把前后 `k` 个元素切掉、求和、求平均都是线性扫描，时间是 **O(n)**。  
- 因为 `O(n log n)` 比 `O(n)` 大，所以总体时间复杂度是 **O(n log n)**。  
- 额外空间只用了一个排好序的新列表，大小是 `n`，所以空间复杂度是 **O(n)**（相当于再准备了一本同样大小的笔记本来装排好序的内容）。

#### 代码（Python）

```python
def trimMean(arr):
    """
    暴力解：先排序，再剔除最小/最大 5% 的元素，最后求平均。
    """
    n = len(arr)                     # 数组长度
    k = n // 20                      # 5% = 1/20，整数除法得到要剔除的个数
    arr_sorted = sorted(arr)         # 排序，得到有序列表

    # 切掉前 k 个和后 k 个元素，得到中间部分
    middle = arr_sorted[k:n - k]

    # 求和并除以元素个数得到平均值
    return sum(middle) / len(middle)
```

#### 复杂度

- **时间复杂度**：`O(n log n)` — 排序需要 `n log n` 次比较，后面的切片、求和是线性 `O(n)`，整体受排序支配。  
- **空间复杂度**：`O(n)` — `sorted` 会创建一个新列表，大小等于原数组。

### 2. 最优解

#### 思路  

从暴力解出发，我们的瓶颈在 **排序**，它的时间是 `O(n log n)`。但是在本题的约束下（`arr.length ≤ 1000`），`O(n log n)` 已经足够快，几乎没有优化的必要。  
不过如果想把时间降到 **线性** `O(n)`，可以利用**计数排序**的思想，因为题目给出了 **元素值的范围是 0 ≤ arr[i] ≤ 10⁵**，这是一个固定且不大的上界。

计数排序的核心是：

1. **统计每个数出现了多少次**（相当于在字典里记录“这个词出现了几页”，这里词是数值，页码是出现次数）。  
2. 依据统计结果，**从小到大遍历**这些计数，累加元素直到跳过最小的 5% 与最大的 5%。  
3. 剩余的部分直接累计求和并计数，最后算平均。

这样我们只需要一次线性遍历来统计（`O(n)`），再一次线性遍历 0~10⁵ 的区间（固定上限 100001），整体时间仍是 **O(n + C)**，其中 `C = 10⁵` 是常数，等价于 **O(n)**。

**关键数据结构：计数数组**  
想象一排格子（下标 0~100000），每个格子里放入对应数字出现的次数。格子本身相当于“字典的页码”，查询、累加都非常快（直接下标访问）。

**步骤细化**  

- **第一遍**：遍历原数组，用 `cnt[x] += 1` 记录每个数出现的次数。  
- **第二遍**：从左到右累加计数，直到累计的元素数 ≥ `k`（要剔除的最小 5%），这一步把左边的 `k` 个元素“跳过”。  
- **第三遍**：同理，从右到左累计，跳过右边的 `k` 个最大元素。  
- **第四遍**：剩余的计数直接乘以对应的数值累加到总和，同时统计剩余元素的个数。  
- **最后**：`average = total_sum / total_cnt`。

#### 代码（Python）

```python
def trimMean(arr):
    """
    最优解：计数排序思路，时间 O(n)（常数 10^5），空间 O(10^5)。
    """
    n = len(arr)
    k = n // 20                     # 需要去掉的元素个数（5%）
    MAX_VAL = 100_000               # 题目给出的最大数值

    # 1️⃣ 统计出现次数
    cnt = [0] * (MAX_VAL + 1)       # 计数数组，长度 100001
    for num in arr:
        cnt[num] += 1

    # 2️⃣ 跳过左侧最小的 k 个元素
    left_removed = 0
    left_idx = 0
    while left_removed < k:
        if cnt[left_idx] == 0:      # 当前数字根本没出现，直接往右走
            left_idx += 1
            continue
        # 还能删多少当前数字
        need = k - left_removed
        if cnt[left_idx] <= need:
            left_removed += cnt[left_idx]
            cnt[left_idx] = 0       # 全部删掉
            left_idx += 1
        else:                       # 只删掉一部分
            cnt[left_idx] -= need
            left_removed = k

    # 3️⃣ 跳过右侧最大的 k 个元素（从右往左）
    right_removed = 0
    right_idx = MAX_VAL
    while right_removed < k:
        if cnt[right_idx] == 0:
            right_idx -= 1
            continue
        need = k - right_removed
        if cnt[right_idx] <= need:
            right_removed += cnt[right_idx]
            cnt[right_idx] = 0
            right_idx -= 1
        else:
            cnt[right_idx] -= need
            right_removed = k

    # 4️⃣ 计算剩余部分的和与个数
    total_sum = 0
    total_cnt = 0
    for val in range(left_idx, right_idx + 1):
        if cnt[val]:
            total_sum += val * cnt[val]
            total_cnt += cnt[val]

    return total_sum / total_cnt
```

#### 复杂度

- **时间复杂度**：`O(n + C)`，其中 `n` 是数组长度，`C = 10⁵` 是计数数组的固定大小。因为 `C` 与输入规模无关，可视作常数，整体等价于 **O(n)**。这比排序的 `O(n log n)` 更快，尤其在 `n` 很大时优势明显。  
- **空间复杂度**：`O(C)`，即计数数组需要 `10⁵ + 1` 个整数的空间（约 0.4 MB），在本题限制下是可以接受的。

## 心得

- **核心技巧**：利用**计数排序**（或桶计数）把原本需要 `O(n log n)` 排序的问题降到线性时间。  
- **适用场景**：  
  1. 元素值范围已知且不大（如 0~10⁵、0~10⁶）。  
  2. 需要对“极值的若干个”进行快速剔除或统计。  
  3. 类似题目：  
     - “统计数组中出现频率最高的前 K 个数”。  
     - “求数组的中位数（当数值范围有限时）”。  
- **解题钥匙**：**把“比较”换成“计数”**——当数值范围受限时，用下标直接记录出现次数，省掉排序这一步。

## 反思

- **第一反应**：直接把数组排序，然后切片求平均——最自然的做法。  
- **最容易踩的坑**：  
  - 计算要剔除的元素个数时一定要使用整数除法 `k = n // 20`（因为 `n` 是 20 的倍数）。  
  - 计数数组实现时要注意不要越界，尤其在从右往左遍历时 `right_idx` 不能小于 0。  
  - 当所有元素相同或全部被剔除后，剩余元素数目一定大于 0（题目保证），但代码仍需防止除以 0。  
- **下次第一步**：先检查 **数值范围** 是否可以使用计数/桶思想；如果可以，就尝试 **计数排序**；如果不行，再回到 **排序+切片** 的常规方案。
