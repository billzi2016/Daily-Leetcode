# #1696. 跳跃游戏 VI / Jump Game VI

## 题目（英文原版）

**Description**

You are given a 0-indexed integer array nums and an integer k.
You are initially standing at index 0. In one move, you can jump at most k steps forward without going outside the boundaries of the array. That is, you can jump from index i to any index in the range [i + 1, min(n - 1, i + k)] inclusive.
You want to reach the last index of the array (index n - 1). Your score is the sum of all nums[j] for each index j you visited in the array.
Return the maximum score you can get.

**Examples**

**Example 1:**

```
Input: nums = [1,-1,-2,4,-7,3], k = 2
Output: 7
Explanation: You can choose your jumps forming the subsequence [1,-1,4,3] (underlined above). The sum is 7.
```

**Example 2:**

```
Input: nums = [10,-5,-2,4,0,3], k = 3
Output: 17
Explanation: You can choose your jumps forming the subsequence [10,4,3] (underlined above). The sum is 17.
```

**Example 3:**

```
Input: nums = [1,-5,-20,4,-1,3,-6,-3], k = 2
Output: 0
```

**Constraints**

- 1 <= nums.length, k <= 105
- -104 <= nums[i] <= 104

给定一个下标从 **0** 开始的整数数组 **nums**（integer array）和一个整数 **k**。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：从左到右依次计算每个位置 `i` 能得到的最高得分 `dp[i]`。  
- `dp[i]` 表示**从起点 0 跳到位置 i 并停在这里时的最大总分**。  
- 要得到 `dp[i]`，我们只能从 `i‑k … i‑1` 这几个前面的格子跳过来（因为一次最多跳 `k` 步），于是  

```
dp[i] = nums[i] + max( dp[i-1], dp[i-2], … , dp[i-k] )
```

这和我们平时查字典的过程类似：要找 `i` 的最大前驱分数，就把前面 `k` 个分数全部“翻出来”，挑出最大的那一个，再加上当前格子的分数 `nums[i]`。

因为我们把每个 `i` 的前 `k` 个值都遍历一次，所以这个方法一定能得到正确答案——它把所有合法的跳法都枚举了，只是把它们的分数都算了一遍。

#### 代码（Python）

```python
from typing import List

def maxResult(nums: List[int], k: int) -> int:
    n = len(nums)
    # dp[i] 保存到达 i 的最大得分，初始化为负无穷，除了起点 0
    dp = [float('-inf')] * n
    dp[0] = nums[0]                 # 起点只能站在自己，得分就是 nums[0]

    for i in range(1, n):
        # 在 i 前面最多看 k 步，找出最大的 dp 值
        best = float('-inf')
        for j in range(1, k + 1):
            if i - j < 0:            # 越界了就不要再往前看
                break
            best = max(best, dp[i - j])
        dp[i] = nums[i] + best       # 加上当前格子的分数

    return dp[-1]                    # 最后一个格子的最大得分即为答案
```

#### 复杂度  

- **时间复杂度：** `O(n * k)`  
  这里的 `n` 是数组长度，`k` 是一次最多能跳的步数。  
  直观来说，如果 `n = 1000`，`k = 100`，我们大约会执行 `1000 × 100 = 100000` 次内部循环。  
  当 `k` 接近 `n`（最坏情况），时间会涨到 `O(n²)`，也就是“平方级”，会明显慢下来。

- **空间复杂度：** `O(n)`  
  只用了一个长度为 `n` 的 `dp` 数组来保存每个位置的最大得分，除了输入本身之外没有额外的大块空间。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于：**每次都要在前 `k` 个位置里找最大值**，这一步是 `O(k)` 的。  
如果我们能在 **常数时间** 内得到这 `k` 个候选值的最大值，整体就可以降到 `O(n)`。

这正是 **单调队列（Monotonic Queue）** 的用武之地。  
- 想象有一条只能向右移动的“滑动窗口”，窗口宽度恰好是 `k`。  
- 窗口里保存的是最近 `k` 个位置的 `dp` 值，且 **从大到小** 排序（单调递减）。  
- 当我们把新位置 `i` 加进来时，先把窗口左边已经超出范围的元素踢出去（`i - k` 以前的），再把 `dp[i]` 插入队列。插入时把所有比 `dp[i]` 小的元素都弹出，这样队首永远是窗口内的最大值。

这样，对于每个 `i`，**只需要 O(1) 就能拿到 `max(dp[i‑k … i‑1])`**，整体时间降为 `O(n)`，空间只需要保存队列里的元素，最多 `k` 个，即 `O(k)`（在最坏情况下 `k` 可能等于 `n`，所以也可以说是 `O(n)`）。

下面用生活化的类比帮助理解：

- **单调队列** 就像排队买票的窗口，只允许“成绩更高的”人站在前面。成绩低的人如果后面来了成绩更高的人，就会被“请出队列”，因为他已经不可能再成为窗口最大值的候选人了。

#### 代码（Python）

```python
from collections import deque
from typing import List

def maxResult(nums: List[int], k: int) -> int:
    n = len(nums)
    dp = [0] * n
    dp[0] = nums[0]

    # dq 存放下标，且对应的 dp 值单调递减
    dq = deque([0])  # 起点下标已经在队列里

    for i in range(1, n):
        # 1️⃣ 取队首的 dp 值，它是窗口内的最大值
        best_idx = dq[0]
        dp[i] = nums[i] + dp[best_idx]

        # 2️⃣ 维护单调性：把所有 dp 值比当前 dp[i] 小的下标踢出队列
        while dq and dp[dq[-1]] <= dp[i]:
            dq.pop()               # 弹出队尾（更小的）

        # 3️⃣ 把当前下标加入队列
        dq.append(i)

        # 4️⃣ 确保队首下标在合法窗口内（i - k 以内），否则踢出
        if dq[0] < i - k:
            dq.popleft()          # 弹出队首（已经超出 k 步范围）

    return dp[-1]
```

> **代码关键行解释**  
> - `dq[0]`：队首始终是窗口内 `dp` 最大的下标。  
> - `while dq and dp[dq[-1]] <= dp[i]`：从队尾开始删除所有 **不可能成为以后最大值** 的下标。  
> - `if dq[0] < i - k`：如果队首已经离得太远（超过 `k` 步），就把它踢出窗口。

#### 复杂度  

- **时间复杂度：** `O(n)`  
  每个下标至多进入队列一次、退出队列一次，所有操作的总次数与 `n` 成线性关系。相比暴力解的 `O(n·k)`，这里即使 `k` 很大也不会导致额外的循环，跑得快得多。

- **空间复杂度：** `O(k)`（最坏 `O(n)`）  
  队列里最多保存最近 `k` 个下标，超过 `k` 的都会被提前弹出。若 `k` 接近 `n`，空间上限就是 `n`，但仍是线性级别。

## 心得

- **核心技巧**：**单调队列**（Monotonic Queue）用于在滑动窗口内快速获取最大（或最小）值。  
- **适用题型**：  
  1. 「滑动窗口最大值」`LeetCode 239`  
  2. 「最长子数组和不超过 K」`LeetCode 862`（使用单调队列或单调栈）  
  3. 「最高分数的跳跃游戏」本题 `Jump Game VI`  
- **解题钥匙**：把“在最近 k 步里找最大值”这一步改成 **“维护一个只保留最大值的窗口”**，即可把时间从 `O(n·k)` 降到 `O(n)`。

## 反思

- **第一反应**：直接写 DP，循环遍历前 `k` 个状态，得到 `O(n·k)`。这在思路上最自然，却忽视了时间瓶颈。  
- **最容易踩的坑**：  
  - 忘记在加入新下标前先 **弹出比它小的元素**，导致队首不再是最大值。  
  - 没有在每次循环结束后检查并踢出 **超出窗口的下标**，会导致使用了非法的跳跃距离。  
  - 边界条件：`k = 1` 时其实退化为普通的线性 DP，队列几乎没有作用，需要确保代码仍然正确。  
- **下次思路**：遇到 “在固定长度窗口内取极值” 的 DP/滑动窗口题目，第一步就想到 **“用单调队列/单调栈维护窗口极值”**，再判断是否需要堆或其他结构。这样可以迅速从 `O(n·k)` 的暴力思路跳到 `O(n)` 的最优解。
