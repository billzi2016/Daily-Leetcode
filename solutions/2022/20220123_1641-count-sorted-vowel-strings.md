# #1641. 计数已排序元音字符串 / Count Sorted Vowel Strings

> 难度：中等 · 标签：Math、Dynamic Programming、Combinatorics · [LeetCode 链接](https://leetcode.com/problems/count-sorted-vowel-strings/)

---

## 题目（英文原版）

**Description**

Given an integer n, return the number of strings of length n that consist only of vowels (a, e, i, o, u) and are lexicographically sorted.
A string s is lexicographically sorted if for all valid i, s[i] is the same as or comes before s[i+1] in the alphabet.

**Examples**

**Example 1:**

```
Input: n = 1
Output: 5
Explanation: The 5 sorted strings that consist of vowels only are ["a","e","i","o","u"].
```

**Example 2:**

```
Input: n = 2
Output: 15
Explanation: The 15 sorted strings that consist of vowels only are
["aa","ae","ai","ao","au","ee","ei","eo","eu","ii","io","iu","oo","ou","uu"].
Note that "ea" is not a valid string since 'e' comes after 'a' in the alphabet.
```

**Example 3:**

```
Input: n = 33
Output: 66045
```

**Constraints**

- 1 <= n <= 50

## 题目（中文翻译）

给定一个整数 `n`，返回只由元音（vowel）`a, e, i, o, u` 组成且字典序排序（lexicographically sorted）的长度为 `n` 的字符串数量。  
如果对于所有合法的下标 `i`，字符 `s[i]` 与 `s[i+1]` 在字母表中的顺序相同或 `s[i]` 在 `s[i+1]` 之前，则称字符串 `s` 为字典序排序。

**示例 1**  
```text
Input: n = 1
Output: 5
Explanation: 只包含元音且已排序的 5 个长度为 1 的字符串为 ["a","e","i","o","u"]。
```

**示例 2**  
```text
Input: n = 2
Output: 15
Explanation: 只包含元音且已排序的 15 个长度为 2 的字符串为
["aa","ae","ai","ao","au","ee","ei","eo","eu","ii","io","iu","oo","ou","uu"]。
注意 "ea" 不是有效字符串，因为字母 'e' 在字母表中位于 'a' 之后。
```

**示例 3**  
```text
Input: n = 33
Output: 66045
```

**约束条件**  
- `1 <= n <= 50`

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**穷举所有长度为 `n` 的元音字符串**，然后检查它们是否满足“字典序不降”。  
- **数据结构**：我们可以用**列表**（list）保存当前正在构造的字符序列，用**递归**来模拟“逐位填字”。递归的过程类似于把每一步当成一次“选词”，就像在查字典时，一次只能看到一个词条，决定是否继续往下看。  
- **正确性**：只要我们把每一种可能的字符（`a, e, i, o, u`）都尝试一次，并且在递归的下一层只允许选取 **不小于当前字符** 的元音，就一定能枚举出所有合法的字符串，且不会漏掉或重复计数。  

#### 代码（Python）

```python
def countVowelStrings_bruteforce(n: int) -> int:
    """暴力递归枚举，返回满足字典序不降的元音字符串数量"""
    vowels = ['a', 'e', 'i', 'o', 'u']          # 元音表，类似字典的“词条”

    def dfs(pos: int, last_idx: int) -> int:
        """
        pos      : 已经填好的字符个数
        last_idx : 上一次选的元音在 vowels 中的下标
                   只允许选取下标 >= last_idx 的元音，保证字典序不降
        """
        if pos == n:                # 已经填满 n 位，算作一种合法方案
            return 1
        total = 0
        # 从 last_idx 开始遍历所有可以放在当前位置的元音
        for i in range(last_idx, len(vowels)):
            total += dfs(pos + 1, i)   # 递归填下一个位置
        return total

    # 第一个字符可以是任意元音，从下标 0 开始
    return dfs(0, 0)
```

> **关键行解释**  
> - `for i in range(last_idx, len(vowels)):` —— 只遍历 **不小于** 前一次选的元音，等价于“只能往后读字典”。  
> - `total += dfs(pos + 1, i)` —— 把当前选的元音记下来，递归处理剩余位置。

#### 复杂度  

- **时间复杂度**：`O(5^n)`  
  - 每一位都有最多 5 种选择，递归树的高度是 `n`，所以最坏情况会遍历 `5^n` 条路径。用大白话说，就是如果 `n=10`，我们大概要检查 **9,765,625** 种可能，明显太慢。  
- **空间复杂度**：`O(n)`  
  - 递归栈的最大深度是 `n`，每层只保存几个整数，所以额外空间随 `n` 线性增长。

### 2. 最优解  

#### 思路  

暴力解的瓶颈在于**大量重复的子问题**：比如在不同的递归路径里，往后剩余的 `k` 位只和“当前最小可选元音”有关，而与前面已经选了什么具体字符无关。  
我们可以把“从当前位置开始还能形成多少合法串”记下来，避免重复计算，这正是**动态规划（DP）**的思想。

**核心观察**  
- 设 `dp[i][j]` 表示「长度为 `i`，且第 `i` 位字符**不小于**第 `j` 个元音」的合法字符串数。  
- 第 `i` 位可以选 `j, j+1, …, 4`（共 `5-j` 种），所以  
  `dp[i][j] = dp[i-1][j] + dp[i-1][j+1] + … + dp[i-1][4]`。  
- 这看起来仍然是 O(5²·n) 的计算，但我们可以利用**前缀和**把转移式化简：  
  `dp[i][j] = dp[i][j+1] + dp[i-1][j]`（从右往左累加）。

**进一步简化**  
实际上只需要一维数组 `cnt[j]` 保存「当前长度下，以元音 `j` 结尾的合法串数」。  
初始时（长度为 1）每个元音都可以单独成串，`cnt = [1,1,1,1,1]`。  
每次把长度加 1 时，新的 `cnt[j]` = `cnt[j] + cnt[j+1]`（从右到左累加），
因为把 `j` 放在最前面，后面的部分可以是 `j` 或更大的元音。

**类比**  
把 `cnt` 想象成 **装满糖果的盒子**，盒子 0 对应 `a`，盒子 4 对应 `u`。  
把长度加 1 相当于 **把右边盒子的糖果全部倒进左边盒子**，于是左边盒子里糖果的总数就变成了「以该元音开头的所有合法串」的数量。

**结束**  
遍历完 `n` 次后，所有盒子里的糖果加起来就是答案。

#### 代码（Python）

```python
def countVowelStrings_dp(n: int) -> int:
    """一维 DP（或组合数学）实现，时间 O(n)，空间 O(1)"""
    # cnt[i] 表示「当前长度下，以第 i 个元音开头」的合法串数
    cnt = [1] * 5          # 长度为 1 时，每个元音各自构成一个合法串

    # 从长度 2 到 n，逐步累加
    for _ in range(1, n):          # 已经有长度 1，故循环 n-1 次
        # 从右往左累加：把右边的数量“倒进”左边
        for i in range(3, -1, -1): # i = 3,2,1,0
            cnt[i] += cnt[i + 1]   # 例如 cnt[2] = cnt[2] + cnt[3]

    # 所有以任意元音开头的合法串数相加即为答案
    return sum(cnt)
```

> **关键行解释**  
> - `cnt = [1] * 5` —— 初始化 5 个盒子，每个盒子里放 1 颗糖（长度 1 的串）。  
> - `for i in range(3, -1, -1): cnt[i] += cnt[i + 1]` —— “倒糖”操作，把右侧盒子的糖全部倒进左侧，保证字典序不降。  
> - `return sum(cnt)` —— 把所有盒子里的糖合在一起，就是所有合法串的总数。

**另一种更数学的写法（组合数）**  
从组合数学的角度，这道题等价于“在 5 种元音中，放入 `n` 个球且允许相同球放在一起”，答案是 **C(n+5-1, 5-1) = C(n+4,4)**。  
如果你已经学过组合公式，可以直接返回 `math.comb(n+4, 4)`，时间 O(1)。

#### 复杂度  

- **时间复杂度**：`O(n)`  
  - 我们只循环 `n-1` 次，每次遍历常数 4 次（元音数-1），所以整体随 `n` 线性增长。比暴力的 `5^n` 快得多。  
- **空间复杂度**：`O(1)`  
  - 只用一个长度为 5 的列表保存计数，大小固定，不随 `n` 变化。

## 心得  

- **核心技巧**：把“字典序不降”转化为“每一步只能选不小于前一步的元音”，进而使用**动态规划 + 前缀和**或**组合数学**一次性求解。  
- **适用题型**：  
  1. “有序组合”类题目，如 “组合总和 II（不降序）”。  
  2. “在有限种类中放置若干个相同物品” 的计数，如 “不同的二进制字符串数（只允许 0 ≤ 1）”。  
- **解题钥匙**：**把约束转化为“只能往右走”**，然后累计右侧的可能性（前缀和）或直接使用“星号与条形”组合公式。

## 反思  

- **第一反应**：直接写递归/回溯，想把所有可能枚举一遍。  
- **最容易踩的坑**：  
  - 忘记在递归/DP 中限制“不能比前一个字符小”，导致计数错误。  
  - 边界条件处理不当，例如 `n=1` 时直接返回 5，或 DP 初始化错误。  
- **下次类似题的第一步**：先思考**“每一步的选择范围只和前一步有关吗？”**，如果答案是“是”，就立刻考虑**DP（或递推）**而不是完整枚举。
