# #2027. 最少移动次数将字符串全部转换为 O / Minimum Moves to Convert String

> 难度：简单 · 标签：String、Greedy · [LeetCode 链接](https://leetcode.com/problems/minimum-moves-to-convert-string/)

---

## 题目（英文原版）

**Description**

You are given a string s consisting of n characters which are either 'X' or 'O'.
A move is defined as selecting three consecutive characters of s and converting them to 'O'. Note that if a move is applied to the character 'O', it will stay the same.
Return the minimum number of moves required so that all the characters of s are converted to 'O'.

**Examples**

**Example 1:**

```
Input: s = "XXX"
Output: 1
Explanation: XXX -> OOO
We select all the 3 characters and convert them in one move.
```

**Example 2:**

```
Input: s = "XXOX"
Output: 2
Explanation: XXOX -> OOOX -> OOOO
We select the first 3 characters in the first move, and convert them to 'O'.
Then we select the last 3 characters and convert them so that the final string contains all 'O's.
```

**Example 3:**

```
Input: s = "OOOO"
Output: 0
Explanation: There are no 'X's in s to convert.
```

**Constraints**

- 3 <= s.length <= 1000
- s[i] is either 'X' or 'O'.

## 题目（中文翻译）

**题目描述**

给定一个长度为 `n` 的字符串 `s`，其中每个字符仅为 `'X'` 或 `'O'`。  
一次 **移动（move）** 被定义为选择 `s` 中的三个连续字符，并将它们全部转换为 `'O'`。若选中的字符本身已经是 `'O'`，则保持不变。  

返回使得 `s` 中所有字符都变为 `'O'` 所需的最小移动次数。

**示例**

- 示例 1  
  **输入**: `s = "XXX"`  
  **输出**: `1`  
  **解释**: `XXX` → `OOO`。我们一次性选取全部 3 个字符并完成转换。

- 示例 2  
  **输入**: `s = "XXOX"`  
  **输出**: `2`  
  **解释**: `XXOX` → `OOOX` → `OOOO`。第一次移动选取前 3 个字符并将它们转换为 `'O'`，第二次移动选取后 3 个字符，使得最终字符串全部为 `'O'`。

- 示例 3  
  **输入**: `s = "OOOO"`  
  **输出**: `0`  
  **解释**: 字符串中不存在需要转换的 `'X'`，无需任何移动。

**约束条件**

- `3 <= s.length <= 1000`
- `s[i]` 仅为 `'X'` 或 `'O'`。

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  

最直接的想法是 **把所有可能的三连字符的选择都枚举一遍**，然后看哪一种可以把所有的 `'X'` 都变成 `'O'`，并统计使用的次数的最小值。  

- **枚举方式**：从左到右，对每一个位置 `i`（`0 ≤ i ≤ n‑3`）决定是否在 `[i, i+1, i+2]` 这三个字符上动手。  
- **数据结构类比**：可以把每一次“动手”想象成在一本字典里标记一页（三连字符），把这页的所有单词（字符）都改成 “O”。  
- **为什么正确**：只要遍历到所有可能的标记方式，必然会包含最优的那一种，所以答案一定会被找到。  

然而，这种“全枚举”会产生 **指数级** 的组合数。  
举个极端：如果字符串全部是 `'X'`，长度为 9，那么我们可以在第 0、3、6 位各自动手，也可以在 1、4、7 位动手……组合数会非常多。  

#### 代码（Python）  

```python
def minMoves_bruteforce(s: str) -> int:
    n = len(s)
    best = float('inf')                     # 用来保存目前找到的最小次数

    def dfs(idx: int, cur: int, cur_s: list):
        """
        idx : 当前检查到的下标
        cur : 已经使用的移动次数
        cur_s: 当前字符串的列表形式，方便原地修改
        """
        nonlocal best
        # 已经比目前的最优解更差，直接剪枝
        if cur >= best:
            return
        # 走到末尾，检查是否全是 'O'
        if idx >= n:
            if all(ch == 'O' for ch in cur_s):
                best = cur                     # 更新最小值
            return

        # 情况1：不在 idx 位置动手，直接往后走
        dfs(idx + 1, cur, cur_s)

        # 情况2：如果还有足够的字符（至少 3 个）可以动手，就尝试一次移动
        if idx + 2 < n:
            # 记录原来的字符，以便回溯
            backup = cur_s[idx:idx+3]
            # 把这三个位置全部改成 'O'
            cur_s[idx] = cur_s[idx+1] = cur_s[idx+2] = 'O'
            dfs(idx + 3, cur + 1, cur_s)       # 跳过这三个位置继续搜索
            # 回溯：恢复原来的字符
            cur_s[idx:idx+3] = backup

    dfs(0, 0, list(s))
    return best if best != float('inf') else 0
```

> **注释**  
> - `dfs` 是深度优先搜索，尝试每一种“动手”或“不动手”的选择。  
> - 为了避免不必要的搜索，当已经用了的次数 `cur` 大于等于当前最好的答案 `best` 时直接返回（**剪枝**）。  
> - 每次动手后把指针向前跳 3 步，因为这三个字符已经确定为 `'O'`，后面再检查它们已经没有意义。

#### 复杂度  

- **时间复杂度**：`O(2^{n})`（指数级）。  
  - 解释：每个位置最多有两种选择（动手 / 不动手），所以组合数大约是 `2^n`，实际会更小一点因为只有长度 ≥3 的位置才可以动手，但仍然是指数级，随着 `n` 增大会非常慢。  
- **空间复杂度**：`O(n)`  
  - 解释：递归深度最坏会达到 `n`，以及保存字符列表需要 `O(n)` 的额外空间。

> 这种暴力解只能在 **非常短** 的字符串（比如 `n ≤ 12`）里跑得完，远远超过题目给出的上限（`n ≤ 1000`），所以我们必须寻找更快的办法。

### 2. 最优解  

#### 思路  

从暴力解可以看到，**左边第一个出现的 `'X'` 必须被一次移动覆盖**，否则它永远改不成 `'O'`。  
因此我们可以采用 **贪心**（Greedy）策略：  

1. 从左到右扫描字符串。  
2. 一旦在位置 `i` 看到 `'X'`，立刻在 `[i, i+1, i+2]` 这三个字符上动手（把它们全部变成 `'O'`）。  
3. 这一步完成后，这三个位置已经是 `'O'`，后面再检查它们是没有意义的，于是把指针直接跳过这三个位置，继续从 `i+3` 开始扫描。  

**为什么贪心是最优的？**  
- 对左边的第一个 `'X'`，唯一能覆盖它的合法区间是长度为 3、且左端点 **不大于** 该 `'X'` 的区间。  
- 如果我们把区间的左端点往左移动（比如从 `i` 移到 `i-1`），那只是浪费了一个已经是 `'O'` 的位置，不能帮助覆盖更多的 `'X'`。  
- 如果把左端点往右移动（比如从 `i` 移到 `i+1`），那么区间就不再覆盖位置 `i`，导致该 `'X'` 永远得不到转换。  
- 所以唯一合理的选择就是**在 `i` 位置开始**这一次移动。  
- 采用这种“尽可能往右推迟” 的方式，每一次移动都能覆盖尽可能多的后续字符（最多 3 个），因此整体移动次数最少。  

这就是题目提示里说的 “**尝试尽可能晚地进行一次移动**” 的思想。  

#### 代码（Python）  

```python
def minMoves_greedy(s: str) -> int:
    """
    贪心扫描：遇到第一个 X，就在它所在的三字符区间动手，
    然后直接跳过这三个字符继续向右扫描。
    """
    n = len(s)
    i = 0          # 当前扫描的下标
    moves = 0      # 记录已经使用的移动次数

    while i < n:
        if s[i] == 'X':          # 发现需要转换的字符
            moves += 1           # 必须在这里动手一次
            i += 3               # 跳过已经被本次移动覆盖的三个位置
        else:
            i += 1               # 当前字符已经是 O，继续向右

    return moves
```

> **关键行中文注释**  
> - `if s[i] == 'X':` —— 找到左边第一个还没有被改成 `'O'` 的位置。  
> - `moves += 1` —— 必须进行一次移动。  
> - `i += 3` —— 因为这一次移动已经把 `i,i+1,i+2` 全部变成 `'O'`，所以可以直接跳过它们。  

#### 复杂度  

- **时间复杂度**：`O(n)` — 只需要一次线性扫描。  
  - 解释：指针 `i` 每次向前移动 1 或 3 步，最多走 `n` 步，所以时间随字符串长度线性增长。  
- **空间复杂度**：`O(1)` — 只用了常数个额外变量。  

> 与暴力解相比，时间从指数级降到了线性级，能够轻松处理 `n = 1000`（甚至更大的）输入。

## 心得  

- **核心技巧**：**贪心**——每次都在最左边出现的 `'X'` 位置立即进行一次长度为 3 的覆盖。  
- **适用的题型**  
  1. “用固定长度的区间覆盖所有目标点” 类问题（如 LeetCode 1245 *Tree Diameter* 的类似思路）。  
  2. “最少次数把数组全部置为 0，每次操作可以把连续 k 个元素设为 0” （如 **Minimum Number of K-Consecutive Bit Flips**）。  
- **一句话总结解题钥匙**：**左边第一个未完成的任务必须立刻用最宽的合法手段完成**，后面的任务自然被覆盖或再继续处理。

## 反思  

- **第一反应**：看到“每次可以把连续 3 个字符都变成 O”，立刻想到“把所有 X 用长度为 3 的区间覆盖”，于是想到枚举所有区间的组合。  
- **最容易踩的坑**  
  1. **忘记跳过已经覆盖的字符**，导致在 `while` 循环里出现重复计数。  
  2. **边界条件**：当 `'X'` 出现在倒数第 1、2 位时，仍然可以在它前面（如果有）或它本身开始的区间里动手，只要保证区间不越界。实现中直接 `i += 3` 而不检查越界，因为我们只在 `s[i]=='X'` 时才移动，而 `i` 本身一定在合法范围内。  
  3. **误以为可以在 `'O'` 上动手来帮助后面的 `'X'`**——其实对已经是 `'O'` 的位置动手没有任何好处，只会浪费一次移动。  
- **下次类似题目第一步**：**定位最左侧仍未被满足的需求**，然后**用能覆盖最多后续需求的操作一次性解决它**，这通常是贪心的出发点。
