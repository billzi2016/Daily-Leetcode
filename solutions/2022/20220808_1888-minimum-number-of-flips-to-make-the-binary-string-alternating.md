# #1888. 最少翻转次数使二进制字符串交替 / Minimum Number of Flips to Make the Binary String Alternating

> 难度：中等 · 标签：String、Dynamic Programming、Sliding Window · [LeetCode 链接](https://leetcode.com/problems/minimum-number-of-flips-to-make-the-binary-string-alternating/)

## 题目（英文原版）

**Description**

You are given a binary string s. You are allowed to perform two types of operations on the string in any sequence:
Return the minimum number of type-2 operations you need to perform such that s becomes alternating.
The string is called alternating if no two adjacent characters are equal.

**Examples**

**Example 1:**

```
Input: s = "111000"
Output: 2
Explanation: Use the first operation two times to make s = "100011".
Then, use the second operation on the third and sixth elements to make s = "101010".
```

**Example 2:**

```
Input: s = "010"
Output: 0
Explanation: The string is already alternating.
```

**Example 3:**

```
Input: s = "1110"
Output: 1
Explanation: Use the second operation on the second element to make s = "1010".
```

**Constraints**

- 1 <= s.length <= 105
- s[i] is either '0' or '1'.

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**把字符串每一种可能的循环左移（或右移）都枚举出来**，然后分别统计把它变成交替字符串需要翻转多少个字符，最后取最小值。  

- **循环左移**可以想象成把一列排好的球（`0`、`1`）从左边搬到右边的操作，搬完后再继续搬，所有可能的搬法就是把球的顺序全部旋转一圈。  
- 对于每一种旋转后的字符串，我们只需要比较它和两种“交替模版”  
  - `010101…`（以 `0` 开头）  
  - `101010…`（以 `1` 开头）  
  哪个模版更接近当前字符串，就把不同位置的字符全部翻转。  
- 统计不同位置的个数，就是**需要的翻转次数**。  

**为什么正确？**  
交替字符串只有两种形式（以 `0` 开头或以 `1` 开头），只要我们把原字符串旋转到任意位置后，与这两种模版逐字符比较，翻转所有不相同的字符就一定能得到交替字符串。遍历所有旋转后取最小值，必然得到全局最优解。

#### 代码（Python）

```python
def minFlips_bruteforce(s: str) -> int:
    n = len(s)
    # 预生成两种交替模版
    pattern0 = ''.join('0' if i % 2 == 0 else '1' for i in range(n))  # 0101...
    pattern1 = ''.join('1' if i % 2 == 0 else '0' for i in range(n))  # 1010...

    ans = float('inf')
    # 枚举所有循环左移 k（0 ≤ k < n）
    for k in range(n):
        # 把字符串左移 k 位，相当于 s[k:] + s[:k]
        rotated = s[k:] + s[:k]

        # 统计与两种模版的不同字符数（即需要翻转的次数）
        diff0 = sum(1 for i in range(n) if rotated[i] != pattern0[i])
        diff1 = sum(1 for i in range(n) if rotated[i] != pattern1[i])

        ans = min(ans, diff0, diff1)   # 取最小的翻转次数

    return ans
```

> **关键注释**  
> - `pattern0`、`pattern1` 就像两本“字典”，告诉我们第 `i` 位理想应该是 `0` 还是 `1`。  
> - `rotated = s[k:] + s[:k]` 把球从左边搬到右边 `k` 次得到的新排列。  
> - `sum(1 for ...)` 逐位比较，遇到不相同就加 1，最后的和就是需要翻转的字符数。

#### 复杂度  

- **时间复杂度：** `O(n²)`  
  - 外层循环 `n` 次（每一种旋转），内层遍历整个字符串 `n` 次统计不同字符。  
  - “`O(n²)`” 可以理解为：如果字符串长度是 10 000，算法大约要做 10 000 × 10 000 = 1 亿次比较，显然太慢。  
- **空间复杂度：** `O(n)`  
  - 需要存放两条模版字符串 `pattern0`、`pattern1`（各 `n` 长），以及临时的旋转字符串 `rotated`。

### 2. 最优解  

#### 思路  

从暴力解我们可以看到，**瓶颈在于每次旋转都要重新遍历整个字符串**。其实，旋转只会把字符的“奇偶位置”整体向前/后平移，而我们关心的只是每个位置上是 `0` 还是 `1`，以及它对应的目标模版是 `0` 还是 `1`。  

下面一步步推导出 `O(n)` 的滑动窗口解法：

1. **把循环左移转化为滑动窗口**  
   - 把原字符串 `s` 拼接到自己后面得到 `t = s + s`。  
   - 在 `t` 中任意长度为 `n` 的连续子串（窗口）正好对应原字符串的某一次循环左移。  
   - 这就把“枚举所有旋转”变成了“在 `t` 上滑动一个固定长度为 `n` 的窗口”。  

2. **预先准备两套交替模版**  
   - `pat0 = "0101..."`（以 `0` 开头）  
   - `pat1 = "1010..."`（以 `1` 开头）  
   - 这两套模版的长度也可以写成 `2n`（因为我们在 `t` 上滑动），这样可以直接对齐比较。  

3. **窗口内的翻转次数如何快速得到？**  
   - 对窗口的每个位置 `i`，如果 `t[i] != pat0[i]` 那么在以 `0` 开头的模版下，需要翻转一次；同理得到 `pat1`。  
   - 如果我们把这些“是否需要翻转”记成 0/1（0 表示相同，1 表示不同），那么窗口内的翻转次数就是这些 0/1 的**和**。  
   - 滑动窗口的经典技巧是：**在窗口右移一步时，只需要把左端离开的值减去，把右端进入的值加上**，这样可以在 `O(1)` 时间内更新窗口的和。  

4. **遍历所有窗口，取最小值**  
   - 对每个窗口分别维护 `cnt0`（对应 `pat0`）和 `cnt1`（对应 `pat1`）的翻转次数。  
   - 最终答案是 `min(cnt0, cnt1)` 在所有窗口中的最小值。  

> **类比**：想象一条跑道上有一串灯（`0/1`），我们手里有两套“理想灯光模式”。把跑道复制两遍后，站在任意起点往前走 `n` 步，就相当于把灯光整体左移。我们只需要把窗口里不符合模式的灯数加起来，滑动时只看进来和出去的灯，省时又省力。

#### 代码（Python）

```python
def minFlips(s: str) -> int:
    n = len(s)
    t = s + s                     # 把字符串复制一次，方便滑动窗口

    # 生成两套交替模式，长度为 2n，直接对应 t 的每个下标
    pat0 = ''.join('0' if i % 2 == 0 else '1' for i in range(2 * n))  # 0101...
    pat1 = ''.join('1' if i % 2 == 0 else '0' for i in range(2 * n))  # 1010...

    # 统计第一个窗口（下标 0~n-1）需要翻转的次数
    cnt0 = sum(1 for i in range(n) if t[i] != pat0[i])   # 与 pat0 的不匹配数
    cnt1 = sum(1 for i in range(n) if t[i] != pat1[i])   # 与 pat1 的不匹配数
    ans = min(cnt0, cnt1)

    # 开始滑动窗口，右端从 n 到 2n-1（共 n-1 次移动）
    for i in range(1, n):
        # 窗口左端离开的位置是 i-1，右端进入的位置是 i+n-1
        left = i - 1
        right = i + n - 1

        # 更新对应 pat0 的计数
        if t[left] != pat0[left]:      # 离开的位置如果之前不匹配，需要减掉
            cnt0 -= 1
        if t[right] != pat0[right]:    # 新进入的位置如果不匹配，需要加上
            cnt0 += 1

        # 同理更新 pat1 的计数
        if t[left] != pat1[left]:
            cnt1 -= 1
        if t[right] != pat1[right]:
            cnt1 += 1

        # 取当前窗口的最小翻转次数
        ans = min(ans, cnt0, cnt1)

    return ans
```

> **关键注释**  
> - `t = s + s` 把灯串复制一遍，相当于把跑道连成环，后面滑动窗口直接在直线里找子串。  
> - `pat0[i]`、`pat1[i]` 就像两本“理想灯光手册”，下标 `i` 告诉我们第 `i` 位应该是 `0` 还是 `1`。  
> - 窗口左端离开时如果原来**不匹配**（需要翻转），我们把计数减 1；右端进入时如果**不匹配**，计数加 1。这样每一步只动常数次操作。  

#### 复杂度  

- **时间复杂度：** `O(n)`  
  - 只遍历了 `2n` 长的字符串一次，窗口每次移动只做 `O(1)` 的更新。  
  - 相比暴力的 `O(n²)`，这里的运行时间几乎是线性的，`n=10⁵` 也能轻松跑完。  
- **空间复杂度：** `O(n)`  
  - 需要额外存放 `t`（长度 `2n`）和两套模式 `pat0、pat1`（各 `2n`），总共 `O(n)`。  
  - 如果想进一步压缩空间，可以在比较时直接用 `i % 2` 判断目标字符，而不显式存模式，空间可降到 `O(1)`，但这里为了可读性保留了模式字符串。

## 心得  

- **核心技巧**：把“循环左移”转化为**在 `s+s` 上的固定长度滑动窗口**，配合**前缀比较（或窗口内差异计数）**实现线性时间。  
- **适用的题型**  
  1. “最小翻转次数使字符串满足某种周期性/交替性”——如本题。  
  2. “在环形数组中找满足条件的子数组最小/最大”——如 LeetCode 713 “子数组长度的最大和”。  
  3. “字符串循环移位后匹配模式”——如 LeetCode 796 “旋转字符串”。  
- **一句话总结解题钥匙**：**把循环移位看成在拼接后的数组里滑动窗口**，窗口内部的统计可以用增量更新做到 `O(1)`。

## 反思  

- **第一反应**：看到“可以循环左移”，立刻想到“把字符串复制两遍后枚举子串”。  
- **最容易踩的坑**  
  - **窗口大小写错**：窗口必须恰好是原字符串长度 `n`，否则会多算或少算字符。  
  - **模版对应错位**：在 `t` 上比较时，模式的下标也要随 `t` 的下标同步（不能只对原 `s` 的下标取模）。  
  - **边界条件**：当 `n = 1` 时，两套模式相同，答案一定是 `0`，代码仍需正常运行。  
- **下次类似题的第一步**：先把“循环/环形”问题转化为“在 `原数组 + 原数组` 上的固定窗口”，再决定用滑动窗口还是前缀和等线性技巧。
