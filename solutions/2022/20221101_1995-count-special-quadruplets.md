# #1995. 计数特殊四元组 / Count Special Quadruplets

> 难度：简单 · 标签：Array、Hash Table、Enumeration · [LeetCode 链接](https://leetcode.com/problems/count-special-quadruplets/)

---

## 题目（英文原版）

**Description**

Given a 0-indexed integer array nums, return the number of distinct quadruplets (a, b, c, d) such that:

**Examples**

**Example 1:**

```
Input: nums = [1,2,3,6]
Output: 1
Explanation: The only quadruplet that satisfies the requirement is (0, 1, 2, 3) because 1 + 2 + 3 == 6.
```

**Example 2:**

```
Input: nums = [3,3,6,4,5]
Output: 0
Explanation: There are no such quadruplets in [3,3,6,4,5].
```

**Example 3:**

```
Input: nums = [1,1,1,3,5]
Output: 4
Explanation: The 4 quadruplets that satisfy the requirement are:
- (0, 1, 2, 3): 1 + 1 + 1 == 3
- (0, 1, 3, 4): 1 + 1 + 3 == 5
- (0, 2, 3, 4): 1 + 1 + 3 == 5
- (1, 2, 3, 4): 1 + 1 + 3 == 5
```

**Constraints**

- 4 <= nums.length <= 50
- 1 <= nums[i] <= 100

## 题目（中文翻译）

给定一个下标从 **0** 开始的整数数组 `nums`，返回满足下列条件的不同四元组 `(a, b, c, d)` 的数量：

- `0 <= a < b < c < d < nums.length`
- `nums[a] + nums[b] + nums[c] == nums[d]`

**示例 1**  
**输入**: `nums = [1,2,3,6]`  
**输出**: `1`  
**解释**: 唯一满足要求的四元组是 `(0, 1, 2, 3)`，因为 `1 + 2 + 3 == 6`。

**示例 2**  
**输入**: `nums = [3,3,6,4,5]`  
**输出**: `0`  
**解释**: 在数组 `[3,3,6,4,5]` 中不存在满足条件的四元组。

**示例 3**  
**输入**: `nums = [1,1,1,3,5]`  
**输出**: `4`  
**解释**: 满足要求的四元组有 4 个：
- `(0, 1, 2, 3)`: `1 + 1 + 1 == 3`
- `(0, 1, 3, 4)`: `1 + 1 + 3 == 5`
- `(0, 2, 3, 4)`: `1 + 1 + 3 == 5`
- `(1, 2, 3, 4)`: `1 + 1 + 3 == 5`

**约束条件**  
- `4 <= nums.length <= 50`
- `1 <= nums[i] <= 100`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  
最直接的想法就是把所有可能的四元组 `(a, b, c, d)` 都枚举一遍，检查它们是否满足  

```
nums[a] + nums[b] + nums[c] == nums[d]      (0 ≤ a < b < c < d < n)
```

- **使用的数据结构**：只需要数组 `nums` 本身。  
  这里不需要额外的容器，遍历时直接取下标对应的数值即可。  
- **为什么一定正确**：我们把「所有」合法的下标组合都检查了一遍，只要有满足条件的组合，就一定会被计数；没有满足的自然不计数。  
- **时间/空间复杂度**：  
  - 我们有四层循环，每层最多遍历 `n` 次（`n` 为数组长度），所以总的遍历次数是 `n × n × n × n = n⁴`。  
  - 用大白话说，`O(n⁴)` 就是「如果 `n` 是 10，程序要跑 10⁴ = 10 000 次；如果 `n` 是 50，要跑 6 250 000 次」，随着 `n` 增大，运算量会非常快地爆炸。  
  - 额外空间只用到常数级的计数变量，记作 `O(1)`。

#### 代码（Python）

```python
def countQuadruplets(nums):
    n = len(nums)
    ans = 0                       # 记录满足条件的四元组个数
    # 四层循环依次枚举 a、b、c、d
    for a in range(n - 3):        # a 最多到 n-4
        for b in range(a + 1, n - 2):
            for c in range(b + 1, n - 1):
                for d in range(c + 1, n):
                    # 检查是否满足等式
                    if nums[a] + nums[b] + nums[c] == nums[d]:
                        ans += 1
    return ans
```

#### 复杂度

- **时间复杂度**：`O(n⁴)` — 四层嵌套循环，每层最多遍历 `n` 次，运算次数随 `n` 的四次方增长。  
- **空间复杂度**：`O(1)` — 只用了几个计数变量，和输入规模无关。

### 2. 最优解

#### 思路  
暴力解的瓶颈在于 **四层循环**，尤其是最内层的 `d` 循环，导致大量重复的计算。  
我们可以把等式

```
nums[a] + nums[b] + nums[c] == nums[d]
```

改写成

```
nums[a] + nums[b] == nums[d] - nums[c]
```

这就把原来四个数的关系拆成 **左边两个数的和** 与 **右边两个数的差** 的比较。  
思路如下：

1. **固定 `c` 和 `d`**（满足 `c < d`），计算右边的目标值 `target = nums[d] - nums[c]`。  
2. **在 `c` 之前的所有下标里**（即 `0 … c‑1`）找出有多少对 `(a, b)`（`a < b < c`）满足 `nums[a] + nums[b] == target`。  
3. 为了快速统计第 2 步，我们维护一个哈希表 `sum_cnt`，键是两数之和，值是出现次数。  
   - 当我们把 `c` 从左向右移动时，`sum_cnt` 只需要把 **新加入的下标**（即 `c‑1`）和它左边的所有下标组成的和加入表中。  
   - 这样在遍历到某个 `c` 时，`sum_cnt` 已经完整记录了所有 `a、b` 且 `b < c` 的和的出现次数。  

这样一来，外层只需要 **两层循环**（遍历 `c`、遍历 `d`），而内部的配对计数通过哈希表 `O(1)` 完成，整体时间降到 `O(n²)`。

> **类比**：把 `sum_cnt` 想象成一本「两数之和」的词典，键是「两个数相加的结果」——就像查字典时先看拼音（这里是和），再看对应的解释（出现次数）。

#### 代码（Python）

```python
def countQuadruplets(nums):
    n = len(nums)
    ans = 0                       # 结果计数
    sum_cnt = {}                  # 哈希表：两数之和 -> 出现次数

    # c 从左到右遍历，c 必须至少是第 2 个元素（因为需要 a、b 在左边）
    for c in range(2, n - 1):
        # 将所有以 (i, c-1) 为结尾的两数之和加入哈希表
        # i 的范围是 0 … c-2，保证 i < (c-1) < c
        for i in range(c - 1):
            s = nums[i] + nums[c - 1]
            sum_cnt[s] = sum_cnt.get(s, 0) + 1   # 计数+1

        # 对每个在 c 右边的 d，计算 target 并查询哈希表
        for d in range(c + 1, n):
            target = nums[d] - nums[c]          # 右边的差值
            ans += sum_cnt.get(target, 0)       # 如果哈希表里有该和，就累加出现次数

    return ans
```

> **代码解释**  
> - 第 5–9 行：`sum_cnt` 记录所有下标对 `(a, b)`，其中 `b = c‑1`，`a < b` 的和。  
> - 第 12–14 行：遍历所有可能的 `d`，计算 `target = nums[d] - nums[c]`。如果之前的某对 `(a, b)` 的和恰好等于 `target`，说明找到了满足条件的四元组，直接把对应的出现次数加到答案里。

#### 复杂度

- **时间复杂度**：`O(n²)`  
  - 外层 `c` 循环 `≈ n` 次，内部的两段循环分别是 `O(c)`（加入哈希表）和 `O(n‑c)`（遍历 `d`），整体相当于 `∑_{c=2}^{n-2} O(c) + O(n‑c) = O(n²)`。  
  - 用通俗的话说：如果 `n = 50`，大概只需要几千次运算，而不是几百万次，速度快很多。  
- **空间复杂度**：`O(n²)` 最坏情况下哈希表会存放所有可能的两数之和，数量上限是 `C(n,2) ≈ n²/2`。在本题的约束（`n ≤ 50`）下，这个空间完全可以接受。

## 心得

- **核心技巧**：把四元组的等式拆成「两数之和」与「两数之差」的比较，利用哈希表统计前缀两数之和的出现次数，从而把四层枚举压缩到两层。  
- **适用的题型**：  
  1. “**计数满足某种线性关系的四元组**” 类题，如 “Count Good Triplets”。  
  2. “**两数之和的变形**” 需要先统计前缀或后缀信息的题，例如 “Number of Pairs With Absolute Difference K”。  
  3. “**前缀/后缀配对**” 的动态规划或哈希表题，如 “Find the Number of Good Subarrays”。  
- **一句话总结**：**把等式左侧的两数之和提前统计，用哈希表快速查找对应的右侧差值**，就是这道题的解题钥匙。

## 反思

- **第一反应**：看到四个下标的约束，立刻想到四层循环暴力枚举。  
- **最容易踩的坑**：  
  - 忘记下标的严格顺序 `a < b < c < d`，导致统计重复或非法组合。  
  - 在更新哈希表时忘记只加入 `b < c` 的对，导致后面查询时计入了不合法的 `(a,b)`。  
  - 边界条件：`c` 必须从 `2` 开始，`d` 必须从 `c+1` 开始，否则会出现空集合或下标越界。  
- **下次思路**：遇到类似 “四元组满足线性关系” 的题目，先尝试把等式改写成两边各两个数的关系，然后考虑 **前缀/后缀统计**（哈希表、计数数组）来把枚举层数削减。这样往往能从 `O(n³)`/`O(n⁴)` 降到 `O(n²)`，性能提升巨大。
