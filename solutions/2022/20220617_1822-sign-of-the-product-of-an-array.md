## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把数组里的所有数都乘起来，得到 `product`，再根据题目给出的 `signFunc` 定义返回答案：

- `signFunc(x) = 1`  当 `x > 0`
- `signFunc(x) = -1` 当 `x < 0`
- `signFunc(x) = 0`  当 `x = 0`

**用到的数据结构**：  
- **列表（list）**：就是我们平时写的“一串数字”。  
- **整数（int）**：直接相乘就行。

可以把乘法想象成“把所有数字放进一个大锅里一起炖”。如果锅里有 **0**，最终的味道一定是 **0**；如果锅里负数的个数是偶数，负负得正，最后的味道是正的；否则是负的。

**为什么这个方法正确**：  
因为乘法本身满足交换律和结合律，先算完所有数的乘积再判断符号，正好对应 `signFunc` 的定义。

**复杂度分析（大白话）**：  
- **时间复杂度 O(n)**：我们要遍历一次数组，`n` 是数组长度。遍历一次就像一次“检查每个数字”，不管 `n` 多大，时间会随 `n` 成线性增长。  
- **空间复杂度 O(1)**：只用几个变量（`product`、`ans`），不随输入大小增多而增多，像是随身带的一个小袋子。

> ⚠️ 这里有个隐藏的坑：如果直接把所有数相乘，乘积可能非常大，超出 Python 整数的范围（在实际面试中很多语言会溢出）。虽然 Python 的 `int` 自动扩容，但在受限语言里会导致错误。因此我们在「最优解」里会改进。

#### 代码（Python）

```python
def arraySign(nums):
    """
    暴力版：直接求乘积，再判断符号
    :param nums: List[int] - 输入数组
    :return: int - 1、-1 或 0
    """
    product = 1                     # 初始化乘积为 1（乘法的中性元）
    for num in nums:                # 遍历每个数字
        product *= num              # 把当前数字乘进去
    # 根据乘积的正负或是否为 0 返回结果
    if product > 0:
        return 1
    elif product < 0:
        return -1
    else:                           # product == 0
        return 0
```

#### 复杂度

- **时间复杂度**：`O(n)` — 需要遍历 `n` 次数组，每次做一次乘法。  
- **空间复杂度**：`O(1)` — 只用了常数个额外变量（`product`）。

### 2. 最优解

#### 思路  

从暴力解可以看到 **瓶颈** 在于**直接求乘积**可能导致整数溢出，且我们其实并不需要真正的乘积，只关心三个信息：

1. **是否出现 0** → 有 0 则答案必为 0。  
2. **负数的个数是奇数还是偶数** → 奇数 → 负；偶数 → 正。  

于是我们可以 **把每个数“压缩”为它的符号**：

- 正数 → `1`（相当于把所有正数都当作 1 乘），
- 负数 → `-1`（相当于把所有负数都当作 -1 乘），
- 零 → 直接返回 `0`（因为乘积里有 0，结果一定是 0）。

这一步相当于把“大锅”里只留下 **“正/负/零” 的标签**，不再真实炖出大数。

**核心技巧**：**计数**（数零的出现、数负数的奇偶），这在很多“只关心符号/正负/是否为 0”的题目里都很有用。

**类比**：想象你在路口观察车辆方向，只需要记录**左转车的数量是奇数还是偶数**，而不必记录每辆车的具体型号。

**一步步推导**：

1. 初始化 `neg_count = 0`（负数计数），`has_zero = False`（是否出现 0）。  
2. 遍历数组：  
   - 遇到 `0` → 直接返回 `0`（因为后面的任何乘积都会被 0 抹掉）。  
   - 遇到负数 → `neg_count += 1`。  
   - 正数 → 什么也不做。  
3. 循环结束后：  
   - 如果 `neg_count` 为偶数 → 负负得正，返回 `1`。  
   - 否则 → 返回 `-1`。

**复杂度**：仍然是一次遍历，**时间 O(n)**，**空间 O(1)**，但避免了大数乘法的风险。

#### 代码（Python）

```python
def arraySign(nums):
    """
    最优解：只统计 0 和负数的个数，避免大数乘积
    :param nums: List[int]
    :return: int
    """
    neg_count = 0            # 负数出现的次数
    for num in nums:
        if num == 0:         # 一旦出现 0，乘积必为 0
            return 0
        if num < 0:          # 负数计数加一
            neg_count += 1

    # 负数个数为偶数 → 正数；奇数 → 负数
    return 1 if neg_count % 2 == 0 else -1
```

#### 复杂度

- **时间复杂度**：`O(n)` — 只遍历一次数组。相比暴力版，没有乘法运算的额外开销，仍然是线性时间。  
- **空间复杂度**：`O(1)` — 只用了两个整数变量 (`neg_count`)，和输入规模无关。

## 心得

- **核心技巧**：**只关心符号/是否为 0**，通过计数负数的奇偶性来决定最终符号。  
- **适用题型**：  
  1. “数组乘积的符号” 类题（如本题）。  
  2. “判断数组中正负数的比例/奇偶性” （如判断数组乘积是否为正）。  
  3. “只需判断是否出现特定元素（如 0）” 的题目。  
- **一句话总结解题钥匙**：**“零 → 直接返回；否则看负数奇偶决定正负”。**

## 反思

- **第一反应**：直接把所有数相乘，然后判断符号。  
- **最容易踩的坑**：  
  - 忽视 **0** 的存在导致错误答案。  
  - 直接乘积可能导致 **整数溢出**（在某些语言中会报错）。  
  - 没考虑 **负数个数的奇偶**，而是尝试保存完整乘积。  
- **下次遇到同类题**：第一步先**检查是否有 0**，如果没有再**统计负数的个数**，用奇偶性直接得到答案。这样既安全又高效。
