# #1871. 跳跃游戏 VII / Jump Game VII

> 难度：中等 · 标签：String、Dynamic Programming、Sliding Window、Prefix Sum · [LeetCode 链接](https://leetcode.com/problems/jump-game-vii/)

## 题目（英文原版）

**Description**

You are given a 0-indexed binary string s and two integers minJump and maxJump. In the beginning, you are standing at index 0, which is equal to '0'. You can move from index i to index j if the following conditions are fulfilled:
Return true if you can reach index s.length - 1 in s, or false otherwise.

**Examples**

**Example 1:**

```
Input: s = "011010", minJump = 2, maxJump = 3
Output: true
Explanation:
In the first step, move from index 0 to index 3. 
In the second step, move from index 3 to index 5.
```

**Example 2:**

```
Input: s = "01101110", minJump = 2, maxJump = 3
Output: false
```

**Constraints**

- 2 <= s.length <= 105
- s[i] is either '0' or '1'.
- s[0] == '0'
- 1 <= minJump <= maxJump < s.length

## 题目（中文翻译）

**题目描述**  
给定一个下标从 0 开始的二进制字符串 `s`，以及两个整数 `minJump` 和 `maxJump`。起始时，你站在下标 `0`（此处字符一定为 `'0'`）。如果满足以下条件，你可以从下标 `i` 跳到下标 `j`：

- `i < j ≤ i + maxJump`
- `j - i ≥ minJump`
- `s[j] == '0'`

如果能够到达字符串的最后一个下标 `s.length - 1`，返回 `true`；否则返回 `false`。

**示例 1**  
```text
Input: s = "011010", minJump = 2, maxJump = 3
Output: true
Explanation:
在第一步，从下标 0 跳到下标 3。 
在第二步，从下标 3 跳到下标 5。
```

**示例 2**  
```text
Input: s = "01101110", minJump = 2, maxJump = 3
Output: false
```

**约束条件**  

- `2 <= s.length <= 10^5`
- `s[i]` 仅为 `'0'` 或 `'1'`
- `s[0] == '0'`
- `1 <= minJump <= maxJump < s.length`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把每一个可以到达的位置 `i` 看作起点，尝试把它跳到所有满足  
`minJump ≤ j - i ≤ maxJump` 且 `s[j] == '0'` 的位置 `j`。  
如果 `j` 正好是最后一个字符的下标，就返回 `True`；遍历完仍未到达则返回 `False`。

- **使用的数据结构**：  
  - `queue`（队列）或 `list` 用来保存已经“到达”的下标。可以把它想象成一列已经打开的门，门后面是可以继续前进的路。  
  - `visited` 数组记录哪些下标已经访问过，防止重复搜索。`visited` 就像一本“足迹日志”，每次走到新位置就把对应页码记下来，后面再遇到同样的页码就不必重新查找。

- **为什么正确**：  
  只要从起点 `0` 能一步步按照题目规定的跳距跳到终点，那么在搜索过程中我们一定会把每一步合法的跳跃都枚举出来。只要找到一次能够抵达最后一位的路径，就说明答案是 `True`。

- **时间/空间复杂度**：  
  - 对每一个已经到达的下标 `i`，我们都要检查它后面 `[i+minJump, i+maxJump]` 这段区间。最坏情况下，这段区间的长度可能接近 `n`（`n = len(s)`），于是总的检查次数会是 `O(n²)`。  
    - **大白话**：如果把 `n` 想成 10 000，`n²` 就是 100 000 000 次操作，显然会很慢。  
  - 需要额外的 `visited` 数组存 `n` 个布尔值，空间是 `O(n)`。

#### 代码（Python）

```python
from collections import deque

def canReach(s: str, minJump: int, maxJump: int) -> bool:
    n = len(s)
    # visited[i] == True 表示下标 i 已经可以到达
    visited = [False] * n
    visited[0] = True

    # 队列保存所有已经确认可以到达的下标
    q = deque([0])

    while q:
        i = q.popleft()                     # 取出一个已经可以站在的下标
        # 枚举从 i 可以跳到的所有位置 j
        for j in range(i + minJump, min(i + maxJump + 1, n)):
            if s[j] == '0' and not visited[j]:   # 只能站在字符为 '0' 的位置
                if j == n - 1:                    # 到达最后一位，成功
                    return True
                visited[j] = True                 # 标记为已访问
                q.append(j)                       # 加入队列继续扩展

    return False    # 队列空了仍未到达终点
```

#### 复杂度

- **时间复杂度**：`O(n²)`  
  - 每个已到达的下标可能会遍历长度接近 `n` 的区间，最坏情况下会出现二次方的检查次数。  
- **空间复杂度**：`O(n)`  
  - 需要 `visited` 数组和队列，最坏情况下两者都会存 `n` 个下标。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**重复遍历同一个区间**。  
例如当我们从下标 `i` 和下标 `i+1` 都可以到达时，它们对应的可跳跃区间 `[i+minJump, i+maxJump]` 与 `[i+1+minJump, i+1+maxJump]` 有大量重叠。我们不需要每次都把整个区间重新扫描一遍，只要知道**区间里有没有已经被标记为可达的下标**，就可以直接把当前下标标记为可达。

这正好可以用**滑动窗口 + 前缀和（或叫差分数组）**来实现：

1. 用一个布尔数组 `dp[i]` 表示下标 `i` 是否可以到达。`dp[0] = True`，其余默认 `False`。  
2. 当我们遍历到下标 `i` 时，若 `dp[i]` 为 `True`，说明从 `i` 可以向前跳 `minJump~maxJump` 的区间。我们不立即把每个位置都设为 `True`，而是把这段区间在 **差分数组** `pre` 上做一次区间加 1 的操作：  
   ```
   pre[l]   += 1
   pre[r+1] -= 1          （l = i+minJump, r = i+maxJump）
   ```
   这样，后面遍历到位置 `j` 时，只要累计 `pre` 的前缀和大于 0，就说明在 `[j-maxJump, j-minJump]` 这段范围内至少有一个已到达的下标可以跳到 `j`，于是 `dp[j] = True`。

3. 为了把 “累计前缀和 > 0” 的判断写得更直观，我们可以直接维护一个 **滑动窗口计数** `cnt`：  
   - `cnt` 表示当前下标 `i` 前面窗口 `[i-maxJump, i-minJump]` 中有多少个 `dp` 为 `True` 的位置。  
   - 当窗口左边界移出时（即 `i - maxJump - 1`），如果那个位置 `dp` 为 `True`，就把 `cnt` 减 1；  
   - 当窗口右边界进入时（即 `i - minJump`），如果那个位置 `dp` 为 `True`，就把 `cnt` 加 1。  
   - 若 `cnt > 0` 且 `s[i] == '0'`，则 `dp[i] = True`。

整个过程只遍历一次字符串，时间线性 `O(n)`，空间 `O(n)`（存 `dp`），或者把 `dp` 本身当作窗口计数的来源，仍然是 `O(n)`。

> **类比**：想象你在排队买票，窗口大小固定为 `maxJump - minJump + 1`。每当有人进入窗口（可以跳到当前位置）就让计数 +1，离开窗口就 -1。只要窗口里还有人（计数 > 0），你就可以站到当前的位置。

#### 代码（Python）

```python
def canReach(s: str, minJump: int, maxJump: int) -> bool:
    n = len(s)
    if s[-1] == '1':          # 最后一位是障碍，直接 false
        return False

    dp = [False] * n          # dp[i] 表示是否能到达 i
    dp[0] = True

    cnt = 0                    # 窗口内可达的下标数量
    # i 从 1 开始遍历每个位置
    for i in range(1, n):
        # ---------- 更新窗口 ----------
        # 新进入窗口的下标是 i - minJump
        if i - minJump >= 0 and dp[i - minJump]:
            cnt += 1          # 有新的可达点加入窗口

        # 旧的离开窗口的下标是 i - maxJump - 1
        if i - maxJump - 1 >= 0 and dp[i - maxJump - 1]:
            cnt -= 1          # 有可达点离开窗口

        # ---------- 判断当前位置 ----------
        # 只有 s[i] 为 '0' 且窗口里还有可达点，才可以站在 i
        if s[i] == '0' and cnt > 0:
            dp[i] = True

    return dp[-1]              # 看最后一个位置是否可达
```

#### 复杂度

- **时间复杂度**：`O(n)`  
  - 只遍历一次字符串，窗口计数的增删都是 `O(1)` 操作。相比暴力的二次方，这个速度快了很多。  
- **空间复杂度**：`O(n)`（`dp` 数组）  
  - 只需要保存每个下标是否可达的布尔值。如果进一步压缩空间，可以直接把 `dp` 改为 `bytearray` 或者只保留最近 `maxJump` 个状态，仍然是线性或常数级别。

## 心得

- **核心技巧**：**滑动窗口 + 前缀和（或差分）** 用来快速判断一个区间里是否存在满足条件的元素。  
- **适用的题型**：  
  1. **Jump Game 系列**（如 Jump Game I、II、III、IV、VII）——需要在限定跳距内判断可达性。  
  2. **区间计数类 DP**（如 “Number of Subarrays with Bounded Maximum”）——判断区间内是否有满足条件的元素。  
  3. **滑动窗口求和/计数**（如 “Longest Substring with At Most K Distinct Characters”）——窗口里维护某种统计信息。  
- **一句话总结**：  
  “把‘能跳到的区间’看成一个滑动窗口，只要窗口里还有一个已到达的点，就能把当前位置标记为可达。”

## 反思

- **第一反应**：立刻想到 BFS/DFS 把每一步的所有可能跳跃都枚举出来，写出暴力代码。  
- **最容易踩的坑**：  
  - 忽略 `s[i] == '1'` 的位置不能站，导致错误地把障碍点标记为可达。  
  - 窗口的左边界和右边界的更新顺序写反，导致计数不准确（比如先减后加会漏掉刚进入窗口的可达点）。  
  - 当 `minJump` 与 `maxJump` 差距很大时，仍然要保持 `O(1)` 的窗口更新，不能在每次循环里遍历整个区间。  
- **下次遇到同类题的第一步**：  
  “先把可达的区间抽象成‘窗口’，思考如何在 O(1) 时间内维护窗口内是否有可达点，而不是把整个区间一次次遍历。”
