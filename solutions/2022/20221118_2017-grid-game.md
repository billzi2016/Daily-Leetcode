# #2017. 网格游戏 / Grid Game

## 题目（英文原版）

**Description**

You are given a 0-indexed 2D array grid of size 2 x n, where grid[r][c] represents the number of points at position (r, c) on the matrix. Two robots are playing a game on this matrix.
Both robots initially start at (0, 0) and want to reach (1, n-1). Each robot may only move to the right ((r, c) to (r, c + 1)) or down ((r, c) to (r + 1, c)).
At the start of the game, the first robot moves from (0, 0) to (1, n-1), collecting all the points from the cells on its path. For all cells (r, c) traversed on the path, grid[r][c] is set to 0. Then, the second robot moves from (0, 0) to (1, n-1), collecting the points on its path. Note that their paths may intersect with one another.
The first robot wants to minimize the number of points collected by the second robot. In contrast, the second robot wants to maximize the number of points it collects. If both robots play optimally, return the number of points collected by the second robot.

**Examples**

**Example 1:**

```
Input: grid = [[2,5,4],[1,5,1]]
Output: 4
Explanation: The optimal path taken by the first robot is shown in red, and the optimal path taken by the second robot is shown in blue.
The cells visited by the first robot are set to 0.
The second robot will collect 0 + 0 + 4 + 0 = 4 points.
```

**Example 2:**

```
Input: grid = [[3,3,1],[8,5,2]]
Output: 4
Explanation: The optimal path taken by the first robot is shown in red, and the optimal path taken by the second robot is shown in blue.
The cells visited by the first robot are set to 0.
The second robot will collect 0 + 3 + 1 + 0 = 4 points.
```

**Example 3:**

```
Input: grid = [[1,3,1,15],[1,3,3,1]]
Output: 7
Explanation: The optimal path taken by the first robot is shown in red, and the optimal path taken by the second robot is shown in blue.
The cells visited by the first robot are set to 0.
The second robot will collect 0 + 1 + 3 + 3 + 0 = 7 points.
```

**Constraints**

- grid.length == 2
- n == grid[r].length
- 1 <= n <= 5 * 104
- 1 <= grid[r][c] <= 105

## 题目（中文翻译）

**题目描述**

给定一个下标从 **0** 开始的 **2 × n** 的二维数组 `grid`，其中 `grid[r][c]` 表示矩阵中位置 `(r, c)` 的分值。两台机器人在该矩阵上进行游戏。

- 两台机器人均从 `(0, 0)` 出发，目标是到达 `(1, n‑1)`。每一步只能向右移动 `((r, c) → (r, c+1))` 或向下移动 `((r, c) → (r+1, c))`。
- 游戏开始时，**第一台机器人**先从 `(0, 0)` 移动到 `(1, n‑1)`，沿途收集该路径上所有格子的分值。对于第一台机器人走过的每个格子 `(r, c)`，将 `grid[r][c]` 置为 **0**。

- 第一台机器人希望 **最小化** 第二台机器人能够收集的分值。  
- 第二台机器人希望 **最大化** 自己收集的分值。  

假设双方都采用最优策略，返回第二台机器人最终收集的分值。

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

- **路径只有两种走法**：因为矩阵只有两行，机器人从左上 `(0,0)` 到右下 `(1,n‑1)` 必须先向右走若干步，再向下一次，最后再向右走剩余的步数。  
- **用「下车点」来唯一确定一条路径**：设机器人在第 `k` 列（`0 ≤ k < n`）从第一行下到第二行，则它走的格子恰好是  
  - 上面那一行的 `0 … k`（含 `k`），  
  - 下面那一行的 `k … n‑1`（含 `k`）。  
  所以只要枚举 `k`，就能得到 **第一只机器人** 的全部可能路径。  

- **第二只机器人** 也只能在某列 `j` 下车。它收集的分数是它走过的格子里 **剩余** 的点数（被第一只机器人清零的格子贡献 0）。  
- **暴力做法**：  
  1. 枚举第一只机器人的下车列 `k`（`O(n)`）。  
  2. 对每个 `k`，枚举第二只机器人的下车列 `j`（`O(n)`），计算它能收集到的点数。  
  3. 在所有 `j` 中取最大（第二只机器人想最大化），在所有 `k` 中取最小（第一只机器人想最小化），得到答案。  

- **用到的数据结构**：  
  - **前缀和**（prefix sum）就像一本“查字典”，字典的 **key** 是列号，**value** 是从左到当前列的点数累计。它可以让我们 **O(1)** 取任意区间的和，避免每次循环都去累加。  

- **为什么正确**：  
  - 每条合法路径一定对应唯一的下车列 `k`（或 `j`），所以遍历所有 `k`、`j` 就覆盖了所有可能的路径组合。  
  - 对每一对 `(k, j)`，我们严格按照题目规则把第一只机器人走过的格子置零，再算第二只机器人的得分，符合游戏的顺序。  

- **复杂度分析（大白话）**：  
  - **时间**：外层 `k` 循环 `n` 次，内层 `j` 循环也 `n` 次，总共大约 `n × n` 次计算。用 **大 O** 记号写成 **O(n²)**，意思是如果 `n` 翻倍，运行时间会变成原来的 **四倍**。  
  - **空间**：我们只需要保存两行的前缀和数组，各占 `n` 长度，外加常数个临时变量，整体是 **O(n)** 的额外空间。  

#### 代码（Python）

```python
from typing import List

def gridGame_bruteforce(grid: List[List[int]]) -> int:
    n = len(grid[0])

    # 计算两行的前缀和，prefix[i] = 前 i+1 列的总和
    pre_up = [0] * n          # 上面那行的前缀和
    pre_down = [0] * n        # 下面那行的前缀和
    cur = 0
    for i in range(n):
        cur += grid[0][i]
        pre_up[i] = cur
    cur = 0
    for i in range(n):
        cur += grid[1][i]
        pre_down[i] = cur

    # 辅助函数：求区间和，左闭右闭
    def range_sum(pre, l, r):
        if l > r:
            return 0
        return pre[r] - (pre[l - 1] if l > 0 else 0)

    ans = float('inf')          # 第一只机器人想让第二只机器人得分最小

    # 枚举第一只机器人下车的列 k
    for k in range(n):
        # 这只机器人把哪些格子置零，用前缀和直接算
        # 上面那行被清零的区间是 [0, k]
        # 下面那行被清零的区间是 [k, n-1]

        best_for_k = 0          # 第二只机器人在固定 k 下的最大得分

        # 枚举第二只机器人下车的列 j
        for j in range(n):
            # 第二只机器人走的格子：
            # 上面那行 [0, j]   （但其中被第一只机器人清零的要算 0）
            # 下面那行 [j, n-1] （同理）

            up_gain   = range_sum(pre_up,   j, j) if j > k else 0   # 只保留 j>k 的上行格子
            up_gain   = range_sum(pre_up,   k + 1, j) if j > k else 0
            down_gain = range_sum(pre_down, j, k - 1) if j < k else 0

            total = up_gain + down_gain
            best_for_k = max(best_for_k, total)   # 第二只机器人想最大化

        ans = min(ans, best_for_k)   # 第一只机器人想最小化

    return ans
```

> **代码要点**  
> - `pre_up`、`pre_down` 用来快速求任意区间的和。  
> - `range_sum` 把「左闭右闭」的区间求和封装成一个函数，避免写重复代码。  
> - 两层 `for` 循环实现了“穷举所有可能的下车列”。

#### 复杂度

- **时间复杂度**：`O(n²)`  
  - 直观解释：如果把列数 `n` 看成 100，算法大约要跑 10,000 次循环；如果 `n` 翻到 200，循环次数会变成 40,000（四倍），这就是平方级增长的特点。  
- **空间复杂度**：`O(n)`  
  - 只用了两条长度为 `n` 的前缀和数组，随 `n` 线性增长。

### 2. 最优解

#### 思路  

**从暴力解出发**，我们发现：

1. **第一只机器人只决定一次「下车列」** `k`。  
2. 对于固定的 `k`，第二只机器人要最大化的得分，其实只跟 **两段未被清零的区域** 有关：  
   - **上行右侧**：列 `k+1 … n-1`（因为上行的 `0 … k` 已被清零）  
   - **下行左侧**：列 `0 … k-1`（因为下行的 `k … n-1` 已被清零）  

   第二只机器人可以选择在任意列 `j` 下车，但它收集的点数 **最多** 只会是这两段中「较大的那一段」的总和。  
   - 如果它在 `j ≤ k-1` 下车，则只能拿到 **下行左侧** 的全部点数。  
   - 如果它在 `j ≥ k+1` 下车，则只能拿到 **上行右侧** 的全部点数。  
   - 当 `j = k` 时，两段都只能取到 0（因为此列在两行都被清零）。  

   因此，对固定的 `k`，第二只机器人的最佳得分 =  

   ```
   max(   sum_up[k+1 … n-1] ,   sum_down[0 … k-1] )
   ```

   这里的 `sum_up`、`sum_down` 分别是上行、下行的 **前缀和**（或后缀和），相当于「从左往右累计」或「从右往左累计」的总分。

3. **第一只机器人想让第二只机器人得分最小**，所以它要在所有可能的 `k` 中挑选一个，使上述「最大值」尽可能小。  

   这正是「**在每个分割点**，取左右两侧的和，取两者的较大者，然后在所有分割点里取最小」的问题。

4. **如何快速得到左右两侧的和**？  
   - 计算 **上行的前缀和** `pref_up[i] = sum(grid[0][0 … i])`。  
   - 计算 **下行的前缀和** `pref_down[i] = sum(grid[1][0 … i])`。  
   - 对于任意 `k`：  
     - 上行右侧的和 = `pref_up[n-1] - pref_up[k]`（总和减去左边已清零的部分）  
     - 下行左侧的和 = `pref_down[k-1]`（左边未被清零的部分）  
   - 这两式都只需要 **O(1)** 时间查询。

5. **整体流程**：  
   - 先算两行的前缀和（一次遍历，`O(n)`）。  
   - 再遍历所有可能的 `k`（`0 … n-1`），对每个 `k` 计算 `max(right_up, left_down)`，并维护最小值。  
   - 最终答案即为最小的「最大值」。  

**关键点的类比**：  
- 把两行看成两条“跑道”。第一只机器人在第 `k` 列把跑道分成左/右两段，左边的上跑道、右边的下跑道都被它“踩平”（得分归零）。第二只机器人只能在剩下的“未被踩平”的跑道上跑，最好的选择就是跑最长的那段——因为跑的越多，点数越多。

#### 代码（Python）

```python
from typing import List

def gridGame(grid: List[List[int]]) -> int:
    """
    最优解：只需要 O(n) 时间和 O(n) 额外空间。
    思路见上文的详细解释。
    """
    n = len(grid[0])

    # 1️⃣ 计算两行的前缀和
    pref_up = [0] * n          # 上面那行的前缀和
    pref_down = [0] * n        # 下面那行的前缀和

    cur = 0
    for i in range(n):
        cur += grid[0][i]
        pref_up[i] = cur

    cur = 0
    for i in range(n):
        cur += grid[1][i]
        pref_down[i] = cur

    total_up = pref_up[-1]     # 上行所有格子的总和，后面会多次使用

    # 2️⃣ 遍历所有可能的下车列 k，求 max(right_up, left_down) 的最小值
    answer = float('inf')

    for k in range(n):
        # 上行右侧的和：从 k+1 到 n-1
        right_up = total_up - pref_up[k]

        # 下行左侧的和：从 0 到 k-1
        left_down = pref_down[k - 1] if k > 0 else 0

        # 第二只机器人在这个 k 下的最佳得分
        worst_for_k = max(right_up, left_down)

        # 第一只机器人想让这个值最小
        answer = min(answer, worst_for_k)

    return answer
```

> **代码要点**  
> - `pref_up[k]` 已经包含了第 `k` 列的分数，所以 `total_up - pref_up[k]` 正好是 **右侧**（不包括 `k`）的总和。  
> - 当 `k = 0` 时，左侧下行没有格子，`left_down` 直接设为 `0`。  
> - 整个循环只做了常数次的算术运算，时间复杂度是线性的。  

#### 复杂度

- **时间复杂度**：`O(n)`  
  - 只遍历两遍数组（一次算前缀和，一次枚举 `k`），如果把 `n` 看成 10,000，算法大约只跑 20,000 步，远远快于平方级的暴力。  
- **空间复杂度**：`O(n)`  
  - 需要保存两条长度为 `n` 的前缀和数组，随 `n` 成线性增长。

## 心得  

- **核心技巧**：**把 2×n 的路径问题转化为「在一条直线上切点」的形式**，利用前缀和快速求左/右两段的和，再取「最大‑最小」得到答案。  
- **适用的题型**（类似思路）：  
  1. **Maximum Score of a Path**（在单行或双行网格中找最优分割点）。  
  2. **Stone Game VI**（两人取石子，求先手最小化后手最大得分）。  
  3. **Partition Array for Maximum Sum**（把数组切成两段，取左段最大或右段最大）。  
- **一句话总结**：  
  > **把机器人只能「下车一次」的限制化为「选一个切点 k」——然后只比较切点左右两侧的未被清零的总和，最小化那个「最大」即是答案。**

## 反思  

- **第一反应**：看到「2 行」就马上想到「每条路径只会下车一次」，于是把路径抽象成「左侧上行 + 右侧下行」的组合。  
- **最容易踩的坑**：  
  - **边界条件**：`k = 0`（左侧下行为空）或 `k = n‑1`（右侧上行为空）时要特别处理，否则会出现索引越界。  
  - **前缀和的「包含」关系**：`pref_up[k]` 已经把第 `k` 列计入，需要在求右侧和时用 `total_up - pref_up[k]`（而不是 `k‑1`），否则会少算或多算一个格子。  
  - **整数溢出**：在 Python 中不存在，但在 C++/Java 中要注意 `int` 可能不够大，需要使用 `long long`。  
- **下次遇到同类题**，第一步应该问自己：  
  - 「这条路径是否只能在某个位置做唯一一次‘转向’或‘切换行/列’？」  
  - 「如果是，能否把整个问题转化为在一维数组上选一个切点，然后只比较切点左右的累计值？」  

这样思路就会自然指向前缀和 + 线性遍历的最优解。
