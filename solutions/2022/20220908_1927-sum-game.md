# #1927. 求和游戏 / Sum Game

> 难度：中等 · 标签：Math、String、Greedy、Game Theory · [LeetCode 链接](https://leetcode.com/problems/sum-game/)

## 题目（英文原版）

**Description**

Alice and Bob take turns playing a game, with Alice starting first.
You are given a string num of even length consisting of digits and '?' characters. On each turn, a player will do the following if there is still at least one '?' in num:
The game ends when there are no more '?' characters in num.
For Bob to win, the sum of the digits in the first half of num must be equal to the sum of the digits in the second half. For Alice to win, the sums must not be equal.
Assuming Alice and Bob play optimally, return true if Alice will win and false if Bob will win.

**Examples**

**Example 1:**

```
Input: num = "5023"
Output: false
Explanation: There are no moves to be made.
The sum of the first half is equal to the sum of the second half: 5 + 0 = 2 + 3.
```

**Example 2:**

```
Input: num = "25??"
Output: true
Explanation: Alice can replace one of the '?'s with '9' and it will be impossible for Bob to make the sums equal.
```

**Example 3:**

```
Input: num = "?3295???"
Output: false
Explanation: It can be proven that Bob will always win. One possible outcome is:
- Alice replaces the first '?' with '9'. num = "93295???".
- Bob replaces one of the '?' in the right half with '9'. num = "932959??".
- Alice replaces one of the '?' in the right half with '2'. num = "9329592?".
- Bob replaces the last '?' in the right half with '7'. num = "93295927".
Bob wins because 9 + 3 + 2 + 9 = 5 + 9 + 2 + 7.
```

**Constraints**

- 2 <= num.length <= 105
- num.length is even.
- num consists of only digits and '?'.

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把所有 `'?'` 都枚举出来，尝试每一种可能的填法，算出左半边和右半边的数字和，看最后是否相等。  

- **使用的数据结构**：  
  - **列表**（list）保存每一次递归/回溯时已经填好的字符序列。  
  - **递归树**：把每一个 `'?'` 当成一个分支点，分支的取值是 `0~9` 十个数字，就像在“字典”里查找每个词的所有可能解释。  

- **为什么这个方法能得到答案**：  
  只要把所有可能的填法都穷举一遍，就一定会碰到最优（即 Alice 能赢或 Bob 能赢）的局面。只要我们在遍历的过程中记录下 Alice 是否能让两边和不相等，就能得到最终答案。  

- **时间/空间复杂度**：  
  - 假设字符串中有 `k` 个 `'?'`，每个 `'?'` 有 10 种取值，那么所有可能的组合数是 `10^k`。这就是时间复杂度 `O(10^k)`，在实际中如果 `k` 超过 5~6，就已经非常慢了。  
  - 递归深度最多是 `k`，每层递归保存当前字符数组，需要 `O(k)` 的额外空间。  

> **大白话解释**：  
> `O(10^k)` 就像把十个水果放进每个盒子里，一共有 `k` 个盒子，所有组合的数量会像指数一样快速增长，根本算不过来。

#### 代码（Python）

```python
def alice_wins_bruteforce(num: str) -> bool:
    """暴力枚举所有 '?' 的填法，返回 Alice 是否能赢。"""
    n = len(num)
    half = n // 2
    chars = list(num)                 # 把字符串转成列表，方便原地修改

    def dfs(pos: int) -> bool:
        """从 pos 开始搜索，返回是否存在一种填法让 Alice 赢。"""
        if pos == n:                   # 所有字符都已确定
            left_sum = sum(int(c) for c in chars[:half])
            right_sum = sum(int(c) for c in chars[half:])
            # Alice 赢的条件是两边和不相等
            return left_sum != right_sum

        if chars[pos] != '?':          # 不是 '?'，直接往下走
            return dfs(pos + 1)

        # 当前是 '?'，尝试 0~9 每一种可能
        for d in map(str, range(10)):
            chars[pos] = d
            # 如果在某个分支里 Alice 能赢，直接返回 True（剪枝）
            if dfs(pos + 1):
                chars[pos] = '?'      # 还原，保持函数的“无副作用”
                return True
        chars[pos] = '?'                # 还原
        return False                    # 所有分支都不能让 Alice 赢

    return dfs(0)
```

#### 复杂度  

- **时间复杂度**：`O(10^k)`，其中 `k` 为 `'?'` 的个数。  
  这表示每多一个 `'?'`，搜索树的宽度就会乘以 10，增长非常快。  
- **空间复杂度**：`O(k)`，递归栈的深度最多等于 `'?'` 的数量。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**枚举所有可能**，而这在 `k` 很大的时候根本不可接受。我们需要 **直接判断** Alice 是否一定能赢，而不必真的去枚举每一种填法。

观察题目可以得到以下关键事实：

1. **已知数字的贡献是确定的**。  
   计算左半边已有数字的和 `left_sum`，右半边的和 `right_sum`，两者的差记为  

   ```
   diff = left_sum - right_sum
   ```

2. **每个 `'?'` 的作用**：  
   - 左半边的 `'?'` 填上 `x`，会让 `diff` 增大 `+x`。  
   - 右半边的 `'?'` 填上 `y`，会让 `diff` 减小 `-y`（因为右边的和增大）。  

   因此，所有 `'?'` 填完以后，最终的差值是  

   ```
   final_diff = diff + (sum of digits placed in left '?') - (sum of digits placed in right '?')
   ```

3. **游戏的本质是“谁能控制最终的 diff 为 0”**。  
   - Bob 想让 `final_diff == 0`（两边和相等）。  
   - Alice 想让 `final_diff != 0`。  

4. **因为两人交替填数，且每次只能填一个 `'?'`，**  
   当所有 `'?'` 填完后，左、右两边各自得到的总和其实只取决于**左边 `'?'` 的个数** 与 **右边 `'?'` 的个数**，而不是谁先填哪个具体位置。  

   设  

   ```
   left_q  = number of '?' in left half
   right_q = number of '?' in right half
   cnt = left_q - right_q          # 左右 '?' 的数量差
   ```

   每个 `'?'` 最大能贡献 `9`（填 9），所以左边比右边多出的 `'?'` 最多能把 `diff` 拉大 `cnt * 9`，最少能把 `diff` 拉小 `cnt * 0`。  
   关键是：**Bob 只在意能否把 diff 调到 0**，而 Alice 想让它永远达不到 0。  

5. **数学化简**  
   把所有 `'?'` 看成一次性一次性填完（因为谁填对最终差值的影响是相同的），则

   ```
   final_diff = diff + 9 * (left_q - right_q) / 2
   ```

   事实上，**Bob 最佳的策略是让左、右两边的 '?' 平均分配成 9 与 0 的配对**，即左边多出的每个 `'?'` 用 9 抵消，右边多出的每个 `'?'` 用 0 抵消（或者相反）。于是能抵消的最大“平衡量”是 `cnt * 9 / 2`。  

   于是判定公式为：

   ```
   Alice 赢  <=>  2 * diff != cnt * 9
   ```

   - 当 `cnt == 0`（左右 '?' 数量相同）时，上式化简为 `diff != 0`，即只要已有数字的差不为 0，Alice 必胜；若 `diff == 0`，Bob 已经赢了。  
   - 当 `cnt != 0` 时，只要 `2*diff` 不等于 `cnt*9`，Alice 也能确保最终两边不相等。

6. **为什么不需要考虑谁先手**  
   因为总的 `'?'` 数量必然是偶数（字符串长度为偶数），所以 Alice 与 Bob 各自填的次数相同。即使 `'?'` 数量是奇数，Alice 先手多一次也不会改变上面的等式——关键在于 **总的贡献差值的可达范围**，而不是具体的填顺序。

#### 代码（Python）

```python
def alice_wins(num: str) -> bool:
    """
    最优解：只用 O(n) 的时间算出两边的已知和以及 '?' 的个数，
    根据公式 2 * diff != cnt * 9 判断 Alice 是否必胜。
    """
    n = len(num)
    half = n // 2

    left_sum = right_sum = 0          # 已知数字的和
    left_q = right_q = 0              # '?' 的个数

    # 统计左半边和右半边
    for i, ch in enumerate(num):
        if ch == '?':
            if i < half:
                left_q += 1
            else:
                right_q += 1
        else:                         # 已知数字，直接累加
            digit = int(ch)
            if i < half:
                left_sum += digit
            else:
                right_sum += digit

    diff = left_sum - right_sum        # 先手前的差值
    cnt = left_q - right_q             # '?' 数量差

    # 关键判定式：Alice 能赢当且仅当 2*diff != cnt*9
    return 2 * diff != cnt * 9
```

#### 复杂度  

- **时间复杂度**：`O(n)`，只需一次遍历统计数字和 `'?'` 的数量。  
  与 `n` 成线性关系，`n` 最大可达 `10^5`，完全可以接受。  
- **空间复杂度**：`O(1)`，只用了常数个整型变量，不随输入规模增长。

## 心得  

- **核心技巧**：把游戏的每一步抽象成“左、右两边的 '?' 数量差”和“已知数字的差”，再用简单的代数式判断是否可以被 Bob “平衡”。  
- **适用的题型**：  
  1. **均分/平衡类游戏**（如 LeetCode 1688 `Count of Matches in Tournament` 的平衡思路）。  
  2. **只关心最终总和而不在乎顺序的数位游戏**（如 2021 年双周赛的 “Game of Stones”）。  
  3. **利用模或线性方程判定胜负的博弈**（如 “Stone Game IV”）。  
- **一句话总结解题钥匙**：**把所有未知的贡献压缩为“左右 '?' 数量差 * 9”，再比较它与已知差值的两倍是否相等**。

## 反思  

- **第一反应**：看到 “?” 立刻想到回溯穷举，想把每个位置都填满再比较。  
- **最容易踩的坑**：  
  - 忘记考虑 **左右半边 '?' 的数量差**，只看总的 `'?'` 数会得到错误结论。  
  - 忽略 **字符串长度是偶数** 这一点，导致对先手次数的误判。  
  - 在实现公式时写成 `diff != cnt * 9`（漏掉乘以 2），会得到相反的答案。  
- **下次遇到同类题**：第一步先**统计已知信息 + 未知信息的分布**（比如左右、上下、前后），再**把未知的最大/最小贡献抽象成一个简单的代数式**，最后用**等式/不等式**直接判断胜负。
