# #1629. 最慢的按键 / Slowest Key

> 难度：简单 · 标签：Array、String · [LeetCode 链接](https://leetcode.com/problems/slowest-key/)

---

## 题目（英文原版）

**Description**

A newly designed keypad was tested, where a tester pressed a sequence of n keys, one at a time.
You are given a string keysPressed of length n, where keysPressed[i] was the ith key pressed in the testing sequence, and a sorted list releaseTimes, where releaseTimes[i] was the time the ith key was released. Both arrays are 0-indexed. The 0th key was pressed at the time 0, and every subsequent key was pressed at the exact time the previous key was released.
The tester wants to know the key of the keypress that had the longest duration. The ith keypress had a duration of releaseTimes[i] - releaseTimes[i - 1], and the 0th keypress had a duration of releaseTimes[0].
Note that the same key could have been pressed multiple times during the test, and these multiple presses of the same key may not have had the same duration.
Return the key of the keypress that had the longest duration. If there are multiple such keypresses, return the lexicographically largest key of the keypresses.

**Examples**

**Example 1:**

```
Input: releaseTimes = [9,29,49,50], keysPressed = "cbcd"
Output: "c"
Explanation: The keypresses were as follows:
Keypress for 'c' had a duration of 9 (pressed at time 0 and released at time 9).
Keypress for 'b' had a duration of 29 - 9 = 20 (pressed at time 9 right after the release of the previous character and released at time 29).
Keypress for 'c' had a duration of 49 - 29 = 20 (pressed at time 29 right after the release of the previous character and released at time 49).
Keypress for 'd' had a duration of 50 - 49 = 1 (pressed at time 49 right after the release of the previous character and released at time 50).
The longest of these was the keypress for 'b' and the second keypress for 'c', both with duration 20.
'c' is lexicographically larger than 'b', so the answer is 'c'.
```

**Example 2:**

```
Input: releaseTimes = [12,23,36,46,62], keysPressed = "spuda"
Output: "a"
Explanation: The keypresses were as follows:
Keypress for 's' had a duration of 12.
Keypress for 'p' had a duration of 23 - 12 = 11.
Keypress for 'u' had a duration of 36 - 23 = 13.
Keypress for 'd' had a duration of 46 - 36 = 10.
Keypress for 'a' had a duration of 62 - 46 = 16.
The longest of these was the keypress for 'a' with duration 16.
```

**Constraints**

- releaseTimes.length == n
- keysPressed.length == n
- 2 <= n <= 1000
- 1 <= releaseTimes[i] <= 109
- releaseTimes[i] < releaseTimes[i+1]
- keysPressed contains only lowercase English letters.

## 题目（中文翻译）

**题目描述**  
在一次新型键盘的测试中，测试员一次按下一个键，形成了长度为 `n` 的按键序列。  
给定字符串 `keysPressed`（长度为 `n`），其中 `keysPressed[i]` 表示第 `i` 次按下的键；以及升序数组 `releaseTimes`，其中 `releaseTimes[i]` 表示第 `i` 次按键的释放时间。两个数组均为 **0-indexed**。第 `0` 次按键在时间 `0` 开始按下，之后的每一次按键恰好在前一次按键释放的同一时刻开始按下。  

测试员想知道 **按键时长（duration）** 最长的那一次按键。第 `i` 次按键的时长为 `releaseTimes[i] - releaseTimes[i‑1]`（第 `0` 次按键的时长为 `releaseTimes[0]`）。同一个键可能会被多次按下，且每次的时长不一定相同。  

返回时长最长的那一次按键对应的字符。如果存在多次按键的时长相同且为最长，则返回 **字典序（lexicographically）** 最大的字符。

**示例 1**  
```
Input: releaseTimes = [9,29,49,50], keysPressed = "cbcd"
Output: "c"
Explanation: 按键过程如下：
- 第一次按键 'c' 的时长为 9（在时间 0 按下，时间 9 释放）。
- 第二次按键 'b' 的时长为 29 - 9 = 20（在时间 9 按下，时间 29 释放）。
- 第三次按键 'c' 的时长为 49 - 29 = 20（在时间 29 按下，时间 49 释放）。
- 第四次按键 'd' 的时长为 50 - 49 = 1（在时间 49 按下，时间 50 释放）。
最长时长为 20，出现了两次，分别对应字符 'b' 与 'c'，其中字典序更大的字符是 'c'，因此返回 "c"。
```

**示例 2**  
```
Input: releaseTimes = [12,23,36,46,62], keysPressed = "spuda"
Output: "a"
Explanation: 按键过程如下：
- 第一次按键 's' 的时长为 12。
- 第二次按键 'p' 的时长为 23 - 12 = 11。
- 第三次按键 'u' 的时长为 36 - 23 = 13。
- 第四次按键 'd' 的时长为 46 - 36 = 10。
- 第五次按键 'a' 的时长为 62 - 46 = 16。
最长时长为 16，对应的字符是 'a'，因此返回 "a"。
```

**约束条件**  
- `releaseTimes.length == n`  
- `keysPressed.length == n`  
- `2 <= n <= 1000`  
- `1 <= releaseTimes[i] <= 10^9`  
- `releaseTimes[i] < releaseTimes[i+1]`（严格递增）  
- `keysPressed` 仅包含小写英文字母。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：先把每一次按键的持续时间算出来，得到一个**持续时间数组**，再在这个数组里找出最长的那一次。如果出现多个相同最长的时间，按照题目要求返回字母**更大的**（在字典序里更靠后）的那个键。

- **数据结构**  
  - `list`（列表）用来存放每一次的持续时间。可以把它想象成一本“时间记事本”，第 *i* 页记的是第 *i* 次按键用了多久。  
  - `str`（字符串）本身就是键盘上被按下的字符序列，像一本“按键日记”。  

- **为什么正确**  
  1. 第 0 次按键的持续时间就是 `releaseTimes[0]`（因为它从时间 0 开始）。  
  2. 第 *i* 次（i≥1）按键的持续时间是 `releaseTimes[i] - releaseTimes[i-1]`，这正是题目给出的定义。  
  3. 把所有持续时间算出来后，比较大小即可得到最长的那一次。如果有平局，比较对应的字符大小（字典序），把更大的字符挑出来。整个过程完整覆盖了题目所有要求。

- **时间/空间复杂度**  
  - **时间**：我们需要遍历两遍 `releaseTimes`（一次算时长，一次找最大），每遍都是 `n` 步，故是 **O(n)**。这里的 `n` 就是按键次数。  
  - **空间**：额外用了一个长度为 `n` 的列表来保存每一次的时长，算是 **O(n)** 的额外空间。可以把它想象成在记事本里额外写了一行 “持续时间”，占用了和原数据同等的空间。

#### 代码（Python）

```python
def slowestKey_bruteforce(releaseTimes, keysPressed):
    """
    暴力思路：先算所有时长，再遍历找最长且字典序最大的键
    :param releaseTimes: List[int]，每次释放的时间点（已升序）
    :param keysPressed: str，按键序列
    :return: str，持续时间最长的键
    """
    n = len(releaseTimes)
    # 1️⃣ 计算每一次按键的持续时间，存进 list
    durations = [0] * n                # 创建一个长度为 n 的空列表
    durations[0] = releaseTimes[0]     # 第 0 次按键的时长
    for i in range(1, n):
        durations[i] = releaseTimes[i] - releaseTimes[i - 1]   # i 次的时长

    # 2️⃣ 在所有时长中找最长的，如果相同则挑字典序更大的键
    max_duration = durations[0]
    answer = keysPressed[0]            # 暂时的答案
    for i in range(1, n):
        if durations[i] > max_duration:          # 时长更大，直接更新
            max_duration = durations[i]
            answer = keysPressed[i]
        elif durations[i] == max_duration:       # 时长相等，比较字符大小
            if keysPressed[i] > answer:          # 'z' > 'a'，字典序更大
                answer = keysPressed[i]

    return answer
```

#### 复杂度

- **时间复杂度**：`O(n)` —— 需要两次线性遍历，每次都是 `n` 步。  
- **空间复杂度**：`O(n)` —— 额外存了一个长度为 `n` 的 `durations` 列表。

---

### 2. 最优解

#### 思路  

从暴力解可以看到，**真正的瓶颈**不是时间，而是额外的空间——我们把所有时长都保存到了 `durations` 列表里。其实我们不需要一次性记住所有时长，只要在遍历的过程中**实时维护**当前的最长时长以及对应的键即可。这样只需要**一次遍历**，且不需要额外的数组，空间降到常数级 `O(1)`。

优化步骤：

1. **初始化**  
   - 第 0 次按键的时长就是 `releaseTimes[0]`，把它设为当前的最大时长 `max_duration`，对应的键设为 `answer`。

2. **单次遍历**（从第 1 次到第 n‑1 次）  
   - 计算本次的时长 `cur = releaseTimes[i] - releaseTimes[i-1]`。  
   - 与 `max_duration` 比较：  
     - 若 `cur > max_duration` → 更新 `max_duration` 与 `answer`。  
     - 若 `cur == max_duration` 且 `keysPressed[i] > answer`（字典序更大） → 只更新 `answer`。  
   - 其余情况保持不变。

3. **返回** `answer`。

**为什么最优**  

- **时间**：仍然只遍历一次，仍是 `O(n)`，不可能更快，因为我们必须看每一次按键才能知道它的时长。  
- **空间**：只用了几个整数和字符变量，**常数空间** `O(1)`，是最小的可能。

#### 代码（Python）

```python
def slowestKey_optimal(releaseTimes, keysPressed):
    """
    最优思路：一次遍历实时维护最长时长和对应键，空间 O(1)
    :param releaseTimes: List[int]
    :param keysPressed: str
    :return: str
    """
    # 第 0 次按键的时长直接作为当前最大时长
    max_duration = releaseTimes[0]
    answer = keysPressed[0]

    # 从第 1 次开始逐个检查
    for i in range(1, len(releaseTimes)):
        cur_duration = releaseTimes[i] - releaseTimes[i - 1]   # 本次时长

        # ① 时长更长 → 直接更新
        if cur_duration > max_duration:
            max_duration = cur_duration
            answer = keysPressed[i]

        # ② 时长相等且字符更大 → 只更新字符
        elif cur_duration == max_duration and keysPressed[i] > answer:
            answer = keysPressed[i]

    return answer
```

#### 复杂度

- **时间复杂度**：`O(n)` —— 只遍历一次，必须查看每一次按键。  
- **空间复杂度**：`O(1)` —— 只用了几个变量，不随 `n` 增长。

## 心得

- **核心技巧**：一次遍历实时维护“最大值 + 记录者”。  
- **适用的题型**  
  1. “找最大/最小/最长/最短 … 并返回对应的下标或字符” 类题（如 LeetCode 1665 `Minimum Initial Energy to Finish Tasks`）。  
  2. “在遍历过程中需要同时比较数值大小和字典序” 的情形（如 1620 `Coordinate With Maximum Network Quality` 的变体）。  
- **一句话总结**：**遍历中把“最大时长”和“对应键”一起带走，省去额外存储，既快又省内存。**

## 反思

- **第一反应**：先把每一次的时长算出来，再找最大——这就是暴力思路。  
- **最容易踩的坑**  
  - **第 0 次的时长**直接是 `releaseTimes[0]`，不能忘记它没有前一个时间点。  
  - **相同时长的比较**必须使用字典序（`'z' > 'a'`），否则会错判。  
  - **数组下标**一定要对应 `keysPressed[i]` 与 `releaseTimes[i]`，别把两者错位。  
- **下次类似题**的第一步：**思考是否可以在一次遍历中同步维护答案**，即“边遍历边比较”。如果可以，就不必额外开数组或多次遍历。
