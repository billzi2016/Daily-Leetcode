# #1952. 三个约数 / Three Divisors

> 难度：简单 · 标签：Math、Enumeration、Number Theory · [LeetCode 链接](https://leetcode.com/problems/three-divisors/)

---

## 题目（英文原版）

**Description**

Given an integer n, return true if n has exactly three positive divisors. Otherwise, return false.
An integer m is a divisor of n if there exists an integer k such that n = k * m.

**Examples**

**Example 1:**

```
Input: n = 2
Output: false
Explantion: 2 has only two divisors: 1 and 2.
```

**Example 2:**

```
Input: n = 4
Output: true
Explantion: 4 has three divisors: 1, 2, and 4.
```

**Constraints**

- 1 <= n <= 104

---

## 题目（中文翻译）

给定一个整数（integer）`n`，如果 `n` 恰好拥有三个正约数（positive divisors），返回 `true`；否则返回 `false`。  
如果存在整数（integer）`k` 使得 `n = k * m`，则整数 `m` 被称为 `n` 的约数（divisor）。

**示例 1**  
**输入**: `n = 2`  
**输出**: `false`  
**解释**: 2 只有两个约数：1 和 2。

**示例 2**  
**输入**: `n = 4`  
**输出**: `true`  
**解释**: 4 有三个约数：1、2 和 4。

**约束条件**  
- `1 <= n <= 10^4`

---

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是**把所有正整数都枚举一遍**，看看哪些能整除 `n`，计数后判断是否恰好为 3。  
这里用到的唯一数据结构是 **计数器**（一个整数），相当于我们在数“有多少个钥匙可以打开这把锁”。  

- **为什么正确**：如果一个数 `d` 能整除 `n`，就一定是 `n` 的一个正因子。把所有可能的 `d`（从 1 到 `n`）都检查一遍，必然能找到全部因子，计数后自然可以判断是否等于 3。  
- **时间/空间分析**：  
  - 我们要检查 `1, 2, …, n` 共 `n` 个数，每一次检查都是一次取模运算（`n % d == 0`），所以时间复杂度是 **O(n)**。  
  - 只用了一个计数器和若干临时变量，空间复杂度是 **O(1)**，即只占常数级别的内存。

> **大白话**：  
> - `O(n)` 就像在排队买票，要等 `n` 个人轮到你；如果 `n` 是 10 000，等的时间会明显感到慢。  
> - `O(1)` 就是说我们只需要一张小纸条来记数，根本不需要额外的大箱子装东西。

#### 代码（Python）

```python
def isThree(n: int) -> bool:
    # 计数器，记录找到的因子个数
    cnt = 0

    # 从 1 遍历到 n（包括 n 本身）
    for d in range(1, n + 1):
        if n % d == 0:          # 能整除说明 d 是 n 的因子
            cnt += 1           # 计数器加一
            if cnt > 3:        # 已经超过 3 个，直接返回 False 提前结束
                return False

    # 循环结束后，cnt 只能是 0~3 之间的数
    return cnt == 3
```

#### 复杂度

- **时间复杂度**：`O(n)` — 需要检查 `1 … n` 共 `n` 次，`n` 越大耗时越长。  
- **空间复杂度**：`O(1)` — 只用了几个整数变量，内存占用几乎不变。

---

### 2. 最优解

#### 思路  

从暴力解可以看到，**遍历到 `n` 本身是最慢的环节**，因为大多数数的因子都出现在 `√n` 之前。  
我们可以利用数论的一个小结论来把检查范围大幅缩小：

> **结论**：一个正整数恰好有 3 个正因子，当且仅当它是 **某个质数的平方**。  
> 解释：设 `n = p²`（`p` 为质数），则因子只有 `1, p, p²` 三个。若 `n` 不是质数的平方，要么它本身是质数（因子 1 与自身，只有 2 个），要么它有至少两个不同的质因子，导致因子数 ≥ 4。

因此，只要判断下面两件事即可：

1. `n` 是否是**完全平方数**（即 `√n` 为整数）。  
2. 这个整数根 `sqrt_n` 是否是**质数**。

这两个检查都可以在 `O(√n)` 时间内完成：

- 判断完全平方数：计算整数平方根 `int(math.isqrt(n))`，检查 `sqrt_n * sqrt_n == n`。`isqrt` 是 Python 3.8+ 提供的整数平方根函数，时间复杂度约为 `O(log n)`，在本题可以视作常数。  
- 判断质数：只需要检查 `sqrt_n` 是否能被 `2 … √sqrt_n` 整除，同样是 `O(√sqrt_n)`，即 `O(n^{1/4})`，对 `n ≤ 10⁴` 完全够快。

> **类比**：  
> - 判断“是否是质数的平方”就像先检查“这颗树是否是圆形的”（完全平方），再检查“圆形的树皮是否光滑且没有裂纹”（是否为质数）。

#### 代码（Python）

```python
import math

def isThree(n: int) -> bool:
    # 1️⃣ 判断 n 是否为完全平方数
    sqrt_n = math.isqrt(n)          # 取整数平方根，例如 isqrt(10) -> 3
    if sqrt_n * sqrt_n != n:        # 若平方后不等于 n，说明 n 不是完全平方数
        return False

    # 2️⃣ 判断 sqrt_n 是否为质数
    if sqrt_n < 2:                  # 1 不是质数，0、负数更不可能
        return False

    # 只需要检查到 sqrt(sqrt_n) 即可
    limit = int(math.isqrt(sqrt_n))
    for d in range(2, limit + 1):
        if sqrt_n % d == 0:         # 能被整除说明不是质数
            return False

    # 通过了两步检查，说明 n 有且仅有 3 个因子
    return True
```

#### 复杂度

- **时间复杂度**：`O(√n)` — 主要花在判断 `sqrt_n` 是否为质数的那段循环。对 `n = 10⁴`，`√n = 100`，循环最多检查到 `√100 = 10`，几乎可以忽略不计。相比暴力的 `O(n)`，快了好几个数量级。  
- **空间复杂度**：`O(1)` — 只用了几个整数变量，内存占用不随 `n` 增长。

## 心得

- **核心技巧**：**“一个数恰好有 3 个因子 ⇔ 是质数的平方”**，把计数因子的问题转化为“完全平方 + 质数判定”。  
- **适用的题型**：  
  1. 判断一个数是否有 **恰好 k 个因子**（如 2、3、4）时，常常可以通过数论性质转化为更易检查的形式。  
  2. “判断是否为完全平方数”类题目（如 LeetCode 367. Valid Perfect Square）。  
  3. “判断是否为质数的幂”类题目（如 342. Power of Four）。  
- **一句话总结**：**先把大问题压缩成小范围的检查，再用最基础的数论工具（平方根、质数）一次性搞定**。

## 反思

- **第一反应**：直接枚举所有因子并计数，写出最朴素的 `O(n)` 代码。  
- **最容易踩的坑**：  
  - 忽略 `n = 1` 的特殊情况：`1` 只有 1 个因子，直接返回 `False`。  
  - 只检查到 `√n` 时忘记把 **配对因子** 计入（但在本题我们用“完全平方”直接规避了）。  
  - 质数判定时没有考虑 `2` 这种最小的质数，导致错误返回。  
- **下次遇到同类题**：第一步先思考**是否存在数学性质可以把“计数因子”转化为“形状或结构”检查**（如完全平方、立方、质数），再决定具体的实现细节。
