# #1864. 最少交换次数使二进制字符串交替 / Minimum Number of Swaps to Make the Binary String Alternating

> 难度：中等 · 标签：String、Greedy · [LeetCode 链接](https://leetcode.com/problems/minimum-number-of-swaps-to-make-the-binary-string-alternating/)

## 题目（英文原版）

**Description**

Given a binary string s, return the minimum number of character swaps to make it alternating, or -1 if it is impossible.
The string is called alternating if no two adjacent characters are equal. For example, the strings "010" and "1010" are alternating, while the string "0100" is not.
Any two characters may be swapped, even if they are not adjacent.

**Examples**

**Example 1:**

```
Input: s = "111000"
Output: 1
Explanation: Swap positions 1 and 4: "111000" -> "101010"
The string is now alternating.
```

**Example 2:**

```
Input: s = "010"
Output: 0
Explanation: The string is already alternating, no swaps are needed.
```

**Example 3:**

```
Input: s = "1110"
Output: -1
```

**Constraints**

- 1 <= s.length <= 1000
- s[i] is either '0' or '1'.

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是「把每一种可能的交换都尝试一次，看看能否得到交替字符串」。  
具体可以这样做：

1. **遍历所有可能的两两交换**  
   - 任意挑选两个下标 `i < j`，把 `s[i]` 与 `s[j]` 交换。  
   - 交换后检查整个字符串是否已经交替（相邻字符不相同）。

2. **记录最少的交换次数**  
   - 如果一次交换就能得到交替，答案就是 `1`。  
   - 如果需要两次交换才能成功，就继续尝试所有两次交换的组合，依此类推，直到找到最小的次数。  

> **类比**：想象你有一堆颜色不同的球，要把它们摆成红蓝交替的顺序。暴力方法就是「把每两个球的颜色换一下，看看能不能一次就摆好」，如果不行就「换两次」……一直穷举下去。

**为什么这个方法正确？**  
因为我们把「所有可能的交换」都枚举了，必然能覆盖最优的那一种（如果存在的话），于是最小的交换次数一定会被找到。

**时间/空间复杂度**  
- **时间复杂度**：  
  - 枚举所有两两下标组合的次数是 `C(n,2) = n·(n‑1)/2`，每次检查交替性需要遍历整个字符串 `O(n)`。  
  - 所以总体是 `O(n³)`，在最坏情况下甚至要继续枚举三次、四次……，实际复杂度更高。  
  - 用大白话说，就是「随着字符串长度增加，运行时间会像立方一样迅速增长」，即使 `n=1000` 也会超时。

- **空间复杂度**：  
  - 只用了常数级的额外变量（几个下标、计数器），所以是 `O(1)`。

> 这里的 `O(n³)` 只是一个粗略的上界，足以说明暴力解在实际中不可行。

#### 代码（Python）

```python
def min_swaps_bruteforce(s: str) -> int:
    """暴力枚举所有可能的交换次数，返回最小次数或 -1（不可达）"""
    n = len(s)
    # 先判断是否有可能成为交替串
    if not _is_possible(s):
        return -1

    # 0 次交换的情况
    if _is_alternating(s):
        return 0

    # 1 次交换的情况
    for i in range(n):
        for j in range(i + 1, n):
            lst = list(s)
            lst[i], lst[j] = lst[j], lst[i]          # 交换两个字符
            if _is_alternating(''.join(lst)):
                return 1

    # 2 次交换的情况（这里演示思路，实际会继续更高次数……）
    # 为了避免代码过长，这里不继续实现
    return -1   # 若更高次数仍未找到，返回 -1（实际上会超时）

def _is_alternating(t: str) -> bool:
    """检查字符串是否交替：相邻字符不相同"""
    for k in range(1, len(t)):
        if t[k] == t[k - 1]:
            return False
    return True

def _is_possible(t: str) -> bool:
    """快速判断是否有可能通过交换得到交替串"""
    cnt0, cnt1 = t.count('0'), t.count('1')
    if len(t) % 2 == 0:
        return cnt0 == cnt1
    return abs(cnt0 - cnt1) == 1
```

> 关键行的中文注释已写在代码里，直接运行即可看到结果（但在大数据上会很慢）。

#### 复杂度

- **时间复杂度**：`O(n³)`（甚至更高），因为要遍历所有两两下标组合并逐个检查交替性。  
  - 大白话：如果 `n=100`，大概要做几百万次比较，`n=1000` 时会是上亿次，几乎不可能在一秒内完成。

- **空间复杂度**：`O(1)`，只用了常数个临时变量。

### 2. 最优解

#### 思路  

从暴力解可以看到，**瓶颈在于枚举所有交换**。其实我们不需要真的去交换，只要**统计不匹配的位置**就能直接算出最少的交换次数。

**核心观察**：

1. 交替字符串只有两种形式（长度 `n` 固定）  
   - 以 `'0'` 开头：`0101…`（记作 `pattern0`）  
   - 以 `'1'` 开头：`1010…`（记作 `pattern1`）  
   对于奇数长度，只会有一种合法的模式，因为出现次数多的字符必须放在奇数位。

2. 交换可以一次解决 **两个** 错位  
   - 假设在 `pattern0` 中，第 `i` 位本该是 `'0'`，但实际是 `'1'`（记作 `1→0` 错位）。  
   - 同时在另一个位置 `j`，本该是 `'1'`，但实际是 `'0'`（记作 `0→1` 错位）。  
   - 把这两个位置互换后，两个错误同时消除。  
   - 因此所需的最少交换次数 = `错位的 0→1（或 1→0）数量`（两者相等），即 `错位总数 / 2`。

3. **可行性判定**  
   - 交替串的 `'0'` 与 `'1'` 数量必须满足：  
     - 若 `n` 为偶数，`cnt0 == cnt1`。  
     - 若 `n` 为奇数，`abs(cnt0 - cnt1) == 1`。  
   - 若不满足，则根本不可能通过任意交换得到交替串，直接返回 `-1`。

**步骤**：

1. 统计原字符串中 `'0'` 与 `'1'` 的个数 `cnt0, cnt1`。  
2. 判断可行性（上面的条件），若不行返回 `-1`。  
3. 生成两种目标模式（`pattern0` 与 `pattern1`），只需要在遍历时用 `(i % 2)` 判断期望字符，无需真的构造完整字符串。  
4. 对每种模式，遍历原字符串，计数两类错位：  
   - `mis0`：原字符是 `'0'` 但目标是 `'1'`（`0→1`）。  
   - `mis1`：原字符是 `'1'` 但目标是 `'0'`（`1→0`）。  
   - 交换次数 = `max(mis0, mis1)`，但因为总错位数相等，实际等于 `mis0`（或 `mis1`）。  
5. 若 `n` 为偶数，取两种模式的最小值；若 `n` 为奇数，只取「多数字符在奇数位」的那一种模式的值。  

> **类比**：把错误的字符看成「穿错颜色的袜子」，每次交换可以把左脚的红袜子和右脚的蓝袜子换位，两个错误一次就好。

#### 代码（Python）

```python
def min_swaps_to_alternating(s: str) -> int:
    """
    返回将二进制字符串 s 通过任意两字符交换后变为交替字符串的最少交换次数；
    若不可能，则返回 -1。
    """
    n = len(s)
    cnt0, cnt1 = s.count('0'), s.count('1')

    # ---------- 可行性判断 ----------
    if n % 2 == 0:
        # 偶数长度必须 0 与 1 等数
        if cnt0 != cnt1:
            return -1
    else:
        # 奇数长度只能相差 1
        if abs(cnt0 - cnt1) != 1:
            return -1

    # ---------- 计算两种目标模式的错位 ----------
    # pattern0: 0,1,0,1,...   (i % 2 == 0 -> '0')
    # pattern1: 1,0,1,0,...   (i % 2 == 0 -> '1')
    mis0_to_1 = mis1_to_0 = 0   # 对 pattern0 的统计
    mis0_to_1_alt = mis1_to_0_alt = 0   # 对 pattern1 的统计

    for i, ch in enumerate(s):
        # 目标字符在 pattern0 中
        expected0 = '0' if i % 2 == 0 else '1'
        if ch != expected0:
            # ch 与 expected0 不同，记录是哪种错位
            if ch == '0':
                mis0_to_1 += 1   # 0 实际在应该是 1 的位置
            else:
                mis1_to_0 += 1   # 1 实际在应该是 0 的位置

        # 目标字符在 pattern1 中
        expected1 = '1' if i % 2 == 0 else '0'
        if ch != expected1:
            if ch == '0':
                mis0_to_1_alt += 1
            else:
                mis1_to_0_alt += 1

    # ---------- 计算所需最少交换次数 ----------
    # 对于任意模式，错位的 0→1 与 1→0 必然相等（因为整体字符数不变），
    # 所以 swaps = mis0_to_1 (或 mis1_to_0)
    swaps_pattern0 = mis0_to_1
    swaps_pattern1 = mis0_to_1_alt

    if n % 2 == 0:
        # 两种模式都合法，取更小的
        return min(swaps_pattern0, swaps_pattern1)
    else:
        # 奇数长度只能选“多数字符在奇数位”的模式
        # 若 0 较多，则 pattern0（0 在奇数位）合法；若 1 较多，则 pattern1 合法
        if cnt0 > cnt1:          # 0 为多数
            return swaps_pattern0
        else:                    # 1 为多数
            return swaps_pattern1
```

**代码要点解释**：

- `cnt0, cnt1 = s.count('0'), s.count('1')`：统计字符出现次数，类似“查字典”，键是字符，值是出现次数。
- `expected0 / expected1`：不真的生成整条模式，只用 `i % 2` 判断该位置应该是 `'0'` 还是 `'1'`，相当于「根据位置奇偶性直接算出答案」。
- `mis0_to_1`、`mis1_to_0`：分别记录「本该是 1 却是 0」和「本该是 0 却是 1」的错位数量。因为每一次交换可以把一对错位一起纠正，所以最终需要的交换次数等于其中任意一个计数。
- 最后根据字符串长度奇偶性决定返回哪一种模式的计数。

#### 复杂度

- **时间复杂度**：`O(n)`。只遍历一次字符串（`n ≤ 1000`），每一步的操作都是常数时间。  
  - 与暴力解的 `O(n³)` 相比，**快了几个数量级**，即使 `n=10⁵` 也能轻松跑完。

- **空间复杂度**：`O(1)`。只用了几个计数变量，不随 `n` 增长。

## 心得

- **核心技巧**：把「最少交换次数」转化为「错位字符的配对计数」；利用交替字符串只有两种模式的特性，只需统计不匹配的位置即可。  
- **该技巧适用的题型**  
  1. **最少交换使字符串相等**（如 LeetCode 2186：Minimum Number of Swaps to Make the String Balanced）  
  2. **最少翻转使二进制数组交替**（类似本题的变体）  
  3. **最少交换使数组成递增/递减序列**（需要配对错误位置）  
- **一句话总结解题钥匙**：  
  > “把每一次交换看成同时纠正两个错误，只要统计错误的种类并配对，它们的数量就是答案。”

## 反思

- **第一反应**：直接想「把错误的字符两两换位」——于是走向了暴力枚举所有可能的交换。  
- **最容易踩的坑**  
  - **可行性判断**：忘记先检查 `0`、`1` 的数量是否满足交替的要求，导致后面计算得到的交换次数其实是无意义的。  
  - **奇数长度的模式选择**：奇数长度时只能选「多数字符在奇数位」的那一种交替模式，若两种都取最小会得到错误答案。  
  - **错位配对的理解**：错误的 0→1 与 1→0 必须配对，否则交换次数的公式 `错位总数 / 2` 不成立。  
- **下次遇到同类题**：  
  1. **先判断是否有解**（计数约束）。  
  2. **列举所有合法目标模式**（通常只有几种）。  
  3. **统计每种模式的错位并配对**，直接得出最少操作数。  

这样一步步把「暴力」压缩成「线性扫描」，效率自然提升。祝你玩得开心！
