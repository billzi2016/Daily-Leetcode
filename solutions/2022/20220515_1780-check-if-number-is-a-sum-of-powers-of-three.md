# #1780. 判断数字是否可以表示为若干不同的三的幂之和 / Check if Number is a Sum of Powers of Three

## 题目（英文原版）

**Description**

Given an integer n, return true if it is possible to represent n as the sum of distinct powers of three. Otherwise, return false.
An integer y is a power of three if there exists an integer x such that y == 3x.

**Examples**

**Example 1:**

```
Input: n = 12
Output: true
Explanation: 12 = 31 + 32
```

**Example 2:**

```
Input: n = 91
Output: true
Explanation: 91 = 30 + 32 + 34
```

**Example 3:**

```
Input: n = 21
Output: false
```

**Constraints**

- 1 <= n <= 107

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：先把所有可能会用到的 3 的幂（`1, 3, 9, 27 …`）列出来，然后在这些幂中挑选若干个，使它们的和恰好等于 `n`。这和我们平时背包问题的“枚举所有子集”是一模一样的。

- **使用的数据结构**：  
  - **列表**（`powers`）保存所有 `3^i`（相当于把所有可能的“硬币面额”装进一个盒子）。  
  - **递归或栈** 用来遍历每一种挑选方式，类似我们在超市挑选商品时把每件商品放进或不放进购物车的过程。  

- **为什么正确**：  
  - 我们枚举了**所有**可能的组合（每个幂要么选要么不选），只要有一种组合的和等于 `n`，就说明 `n` 可以写成若干不同的 `3` 的幂之和。  

- **时间/空间复杂度**（大白话版）：  
  - 假设最大的 `3^k` ≤ `n`，则会产生 `k+1` 个幂。对每个幂我们都有“选”或“不选”两种决定，所以一共有 `2^(k+1)` 种组合要检查。  
  - 对于 `n ≤ 10⁷`，`k` 大约是 15（因为 `3^15 = 14,348,907` 已经超过上限），所以最坏情况下要检查 `2^16 ≈ 65,536` 种组合。虽然看起来不算太大，但随着 `n` 增大（比如 10⁹）这个数会爆炸式增长，变得不可接受。  
  - **时间复杂度**：`O(2^k)`（指数级），实际大约是 `O(2^log₃ n)`。  
  - **空间复杂度**：递归栈最多保存 `k+1` 层，`O(k)`，即 `O(log₃ n)`。

#### 代码（Python）

```python
def check_powers_bruteforce(n: int) -> bool:
    # 1. 先把所有 ≤ n 的 3 的幂装进列表
    powers = []
    p = 1
    while p <= n:
        powers.append(p)      # 类似把每个硬币面额放进盒子
        p *= 3                # 下一种幂

    # 2. 深度优先搜索所有子集
    def dfs(idx: int, cur_sum: int) -> bool:
        # 已经凑到 n 了，说明找到了合法组合
        if cur_sum == n:
            return True
        # 已经超出 n，或者所有幂都检查完了，说明此路不通
        if cur_sum > n or idx == len(powers):
            return False
        # ① 选当前的幂
        if dfs(idx + 1, cur_sum + powers[idx]):
            return True
        # ② 不选当前的幂
        return dfs(idx + 1, cur_sum)

    return dfs(0, 0)
```

#### 复杂度

- **时间复杂度**：`O(2^k)`，其中 `k = ⌊log₃ n⌋`。  
  - 大白话：我们要检查的组合数量随 `n` 增长会翻倍，速度非常快（指数级），所以不适合大数。
- **空间复杂度**：`O(k)`，递归调用栈的深度最多是幂的个数。  
  - 大白话：只需要记住当前在第几层，最多几层而已。

### 2. 最优解

#### 思路  

从暴力解可以看到，**慢的根源在于枚举所有子集**。其实我们不需要枚举，只要观察 `3` 的幂的“加法规则”就能直接判断。

- **关键观察**：  
  - 任意整数都可以写成 **三进制**（即以 3 为基数的表示），就像十进制是把数拆成 `10⁰, 10¹, 10² …` 的线性组合，三进制是把数拆成 `3⁰, 3¹, 3² …` 的线性组合。  
  - 在三进制里，每一位只能是 `0, 1, 2`。如果某一位是 **2**，这就相当于用了 **两个相同的 3 的幂**（比如 `2 * 3⁴ = 2·81 = 162`），而题目要求**幂必须互不相同**，即每个幂只能出现 **0 次或 1 次**。  
  - 因此，只要把 `n` 转成三进制，检查每一位是否出现 `2`，若出现则说明需要重复使用某个幂，答案为 `False`；若所有位都是 `0` 或 `1`，则答案为 `True`。

- **如何实现**（不需要真正把数字转成字符串）：  
  - repeatedly 取 `n % 3`（相当于看最低位），如果等于 `2` 直接返回 `False`。  
  - 然后把 `n //= 3`（相当于右移一位），继续检查下一位。  
  - 当 `n` 变成 `0` 时，说明所有位都合格，返回 `True`。

- **类比**：把 `n` 当成一根长绳子，每次剪掉最右边的 `1/3`、`2/3` 或 `整根`（对应余数 0、1、2），如果在任何一步剪掉了 `2/3`（余数 2），就说明用了两根相同长度的绳子，违背“互不相同”的要求。

#### 代码（Python）

```python
def check_powers_optimal(n: int) -> bool:
    """
    判断 n 能否表示为若干不同的 3 的幂之和。
    思路：若 n 的三进制表示里出现数字 2，则不行。
    """
    while n > 0:
        remainder = n % 3          # 取当前最低位（相当于看这位是 0、1 还是 2）
        if remainder == 2:         # 出现 2，说明需要两个相同的 3 的幂
            return False
        n //= 3                     # 右移一位，继续检查更高位
    return True                     # 所有位都为 0/1，满足条件
```

#### 复杂度

- **时间复杂度**：`O(log₃ n)`，因为每循环一次把 `n` 除以 3，循环次数等于三进制位数。  
  - 大白话：如果 `n` 是 10⁷，大约只需要检查 15~16 次就结束，几乎是瞬间完成。
- **空间复杂度**：`O(1)`，只用了常数个变量。  
  - 大白话：不需要额外的数组或递归栈，内存占用几乎为零。

## 心得

- **核心技巧**：利用进制表示的特性，把“是否能用互不相同的幂相加”转化为“对应进制位是否只有 0/1”。  
- **适用的题型**：  
  1. 判断整数是否能表示为若干不同的 2 的幂之和（检查二进制是否出现 `0`/`1` 之外的位）  
  2. 判断整数是否能表示为若干不同的 5 的幂之和（检查五进制是否出现 `2,3,4`）  
  3. “Power of Four” 系列题目（检查二进制只有一个 `1` 且在偶数位）  
- **一句话总结**：**把求和问题映射到对应进制的位上，只要位上没有超过 1，就一定可以用互不相同的幂来表示。**

## 反思

- **第一反应**：想到枚举所有子集（背包思路），于是写了递归搜索。  
- **最容易踩的坑**：  
  - 忘记 **“幂必须互不相同”**，导致在实现中出现了重复使用同一幂的情况。  
  - 在暴力实现里没有剪枝，导致对大数会超时。  
- **下次遇到同类题**：第一步先思考 **“是否可以用进制特性直接判断？”**，如果答案是肯定的，就直接转化为位检查；否则再考虑 DP 或回溯。
