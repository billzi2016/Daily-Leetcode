## 题目（英文原版）

**Description**

A square triple (a,b,c) is a triple where a, b, and c are integers and a2 + b2 = c2.
Given an integer n, return the number of square triples such that 1 <= a, b, c <= n.

**Examples**

**Example 1:**

```
Input: n = 5
Output: 2
Explanation: The square triples are (3,4,5) and (4,3,5).
```

**Example 2:**

```
Input: n = 10
Output: 4
Explanation: The square triples are (3,4,5), (4,3,5), (6,8,10), and (8,6,10).
```

**Constraints**

- 1 <= n <= 250

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把所有可能的 `(a, b)` 组合都枚举一遍，算出 `a² + b²`，看它的平方根 `c` 是否是整数且 `c ≤ n`。  
- **枚举**：`a` 和 `b` 的取值范围都是 `1 … n`，两层循环即可遍历所有 `(a, b)`。  
- **判断是否为整数**：`c = sqrt(a² + b²)`，如果 `c` 的小数部分为 `0`（即 `c == int(c)`），说明 `c` 是整数。  
- **计数**：满足条件的 `(a, b, c)` 就算一条记录。

> **类比**：把 `a`、`b` 看成两本书的页码，`c` 是它们页码平方和的“根”。我们把每本书的页码都翻一遍，看看能否凑出一本“根页码”在限定范围内的书。

**为什么正确**  
- 题目要求所有满足 `a² + b² = c²` 且 `1 ≤ a, b, c ≤ n` 的整数三元组。  
- 暴力枚举遍历了 **每一个可能的** `(a, b)`，只要对应的 `c` 满足条件，就一定被统计到；反之不满足的自然被过滤掉。  

**时间/空间复杂度**  
- 两层循环各跑 `n` 次，整体是 `n × n = n²`，即 **O(n²)**。  
  - 大白话：如果 `n = 100`，我们要检查 10 000 次；`n` 越大，检查次数会以 **平方** 的速度增长。  
- 只用了常数级别的额外空间（存放计数器和几个临时变量），所以是 **O(1)**。

#### 代码（Python）

```python
import math

def count_square_sum_triples_bruteforce(n: int) -> int:
    """暴力枚举 O(n²)"""
    cnt = 0
    for a in range(1, n + 1):
        for b in range(1, n + 1):
            # 计算 a² + b²
            s = a * a + b * b
            # sqrt 返回浮点数，用 int() 取整后再比较是否相等
            c = int(math.isqrt(s))          # isqrt 直接返回整数的平方根（向下取整）
            if c * c == s and c <= n:       # 判断是否恰好是完全平方且不超过 n
                cnt += 1
    return cnt
```

#### 复杂度

- **时间复杂度**：`O(n²)` —— 两层循环遍历所有 `(a, b)`，每次只做常数时间的算术与比较。  
- **空间复杂度**：`O(1)` —— 只用几个整数变量，不随 `n` 增长。

### 2. 最优解

#### 思路  

暴力解的 **瓶颈** 在于每一次都要对 `a² + b²` 求平方根。其实我们可以把所有可能的 `c²` 预先放进一个「查表」——哈希表（字典）中，这样只需要一次 O(1) 的查找，就能判断 `a² + b²` 是否是合法的 `c²`。

**步骤**  

1. **预计算所有合法的 c²**  
   - 对 `c = 1 … n`，把 `c²` 存进集合 `squares`。  
   - 这一步是 O(n) 的时间，O(n) 的空间。  
   - 类比：把所有可能的「根页码」提前写在一本小册子里，后面查找时只要翻页即可。

2. **枚举 a、b**（仍然是两层循环）  
   - 计算 `s = a² + b²`。  
   - 检查 `s` 是否在 `squares` 中且对应的 `c = sqrt(s)` ≤ n。  
   - 因为 `squares` 是集合，`in` 操作的时间是 **O(1)**（哈希表查找），所以整体仍是 `O(n²)`，但常数更小。

3. **计数**  
   - 与暴力解相同，满足条件的三元组直接计数。

**为什么更好**  
- `math.isqrt` 本身已经是 O(1) 的整数开方，但在 Python 中仍会有一点额外的函数调用开销。使用集合查找可以省去这一步的显式运算，让代码更简洁、执行更快。  
- 这种「预处理 + 快速查找」的思路在很多「是否在集合中」的问题里都非常常用，例如「两数之和」的哈希表做法。

**进一步的优化（可选）**  
- 由于 `(a, b, c)` 与 `(b, a, c)` 被视为不同的三元组，枚举时可以把 `a`、`b` 的范围都设为 `1 … n`（不做去重）。如果只需要不重复计数，可把 `b` 从 `a` 开始遍历，最后乘以 2（除去 `a == b` 的情况）。  
- 由于 `n ≤ 250`，即使是 O(n²) 也只会执行约 62 500 次循环，完全在时限内。这里给出的「最优」主要是教学意义，展示如何利用哈希表把「判断」这一步变得更直接。

#### 代码（Python）

```python
def count_square_sum_triples_optimal(n: int) -> int:
    """利用哈希表预存 c²，仍是 O(n²) 但常数更小"""
    # 1️⃣ 预处理：把所有合法的 c² 放进集合
    squares = {c * c for c in range(1, n + 1)}   # O(n) 时间、O(n) 空间

    cnt = 0
    for a in range(1, n + 1):
        a2 = a * a               # 预先算 a²，避免循环里重复乘法
        for b in range(1, n + 1):
            s = a2 + b * b       # s = a² + b²
            # 2️⃣ 快速判断 s 是否是某个合法 c 的平方
            if s in squares:
                # 只要 s 是平方，c = sqrt(s) 必然 ≤ n，因为我们只存了 ≤ n 的平方
                cnt += 1
    return cnt
```

#### 复杂度

- **时间复杂度**：`O(n²)` —— 仍然是两层循环遍历所有 `(a, b)`，每次只做一次集合查找（O(1)）。与暴力解的数量级相同，但实际运行更快。  
- **空间复杂度**：`O(n)` —— 用集合保存 `1² … n²`，最多存 `n` 个整数（这里 `n ≤ 250`，几乎可以忽略不计）。

## 心得

- **核心技巧**：**枚举 + 哈希表（或集合）快速判断**。把“是否满足条件”转化为“是否在集合中”，可以把一次 O(log n) 或 O(1) 的计算（开方）换成更快的哈希查找。  
- **适用题型**  
  1. “两数之和”类问题：利用哈希表记录已经遍历过的数，快速判断是否存在补数。  
  2. “数对满足某种关系”类：如 `a * b = c`、`a + b = c`，提前把可能的 `c` 放进集合。  
  3. “判定是否为完全平方数”或“是否为立方数”等：预生成所有合法的平方/立方放进集合。  
- **一句话总结**：**把“检查是否满足等式”变成“在预处理好的集合里查找”，既省时又省力。**

## 反思

- **第一反应**：直接两层循环枚举 `a`、`b`，每次算 `sqrt` 看是否为整数。  
- **最容易踩的坑**  
  1. **整数溢出**：在 Python 中整数自动大整数，理论上不会溢出，但在其他语言需要注意 `int` 范围。  
  2. **判断整数平方根**：直接用 `math.sqrt` 会得到浮点数，比较时可能出现精度误差。使用 `math.isqrt`（Python 3.8+）或 `int(sqrt)` 再平方验证更安全。  
  3. **边界条件**：`c` 必须 ≤ `n`，所以即使 `a² + b²` 是完全平方数，也要确认对应的 `c` 没超出上限。  
- **下次类似题目第一步**：**先把所有可能的目标值（这里是 `c²`）预处理成集合或哈希表**，再在枚举过程中做 O(1) 查找，避免每一步都做昂贵的运算。
