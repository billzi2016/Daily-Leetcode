## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：

1. **把所有登录记录读进来**，比如放到一个 Python 列表 `records`，每条记录是 `(user_id, time_stamp)`。  
2. **遍历列表**，把属于 2020 年的记录挑出来，放进另一个列表 `records_2020`。这一步相当于在“日志本”里翻页，只找出 2020 年的那几页。  
3. 对每个用户，**找出最大的时间戳**（也就是最近一次登录）。可以用一个字典 `latest = {}`，遍历 `records_2020`，如果当前记录的时间比字典里保存的更晚，就把它更新进去。  
4. 最后把字典 `latest` 转成 `[(user_id, time_stamp), ...]` 就是答案。

> **类比**：  
> - **哈希表（字典）** 就像是一本“用户-最近登录时间”的小册子，`key` 是用户 ID，`value` 是最新的登录时间。查找和更新都是 O(1) 的速度，就像在字典里快速定位到词条页码。

**为什么正确**：  
- 第 2 步保证我们只考虑 2020 年的登录。  
- 第 3 步对每个用户保留了最大的（即最晚的）时间戳，正好满足 “最新登录”。  
- 第 4 步把内部存储结构转成题目要求的表格形式。

#### 代码（Python）

```python
import datetime
from typing import List, Tuple

def latest_login_brute(records: List[Tuple[int, str]]) -> List[Tuple[int, str]]:
    """
    暴力实现：遍历所有记录，手动筛选 2020 年并找最大时间戳。
    参数 records 形如 [(user_id, "2020-06-30 15:06:07"), ...]
    返回值同样是 [(user_id, "2020-06-30 15:06:07"), ...]
    """
    # 1. 保存 2020 年的登录记录
    records_2020 = []
    for user_id, ts in records:
        # 把字符串转成 datetime，方便比较
        dt = datetime.datetime.strptime(ts, "%Y-%m-%d %H:%M:%S")
        if dt.year == 2020:                 # 只保留 2020 年的
            records_2020.append((user_id, dt))

    # 2. 用字典保存每个用户的最新登录时间
    latest = {}  # key: user_id, value: datetime
    for user_id, dt in records_2020:
        # 如果字典里没有该用户，或当前时间更晚，就更新
        if user_id not in latest or dt > latest[user_id]:
            latest[user_id] = dt

    # 3. 把 datetime 再转回字符串，得到最终结果
    result = [(uid, dt.strftime("%Y-%m-%d %H:%M:%S")) for uid, dt in latest.items()]
    return result


# ------------------- 示例 -------------------
sample = [
    (6, "2020-06-30 15:06:07"),
    (6, "2021-04-21 14:06:06"),
    (6, "2019-03-07 00:18:15"),
    (8, "2020-02-01 05:10:53"),
    (8, "2020-12-30 00:46:50"),
    (2, "2020-01-16 02:49:50"),
    (2, "2019-08-25 07:59:08"),
    (14, "2019-07-14 09:00:00"),
]
print(latest_login_brute(sample))
# 可能输出：[(6, '2020-06-30 15:06:07'), (8, '2020-12-30 00:46:50'), (2, '2020-01-16 02:49:50')]
```

#### 复杂度

- **时间复杂度：** `O(n)`  
  - 我们遍历了 `records` 一遍（`n` 为总记录数），再遍历了过滤后的 `records_2020`（最多也是 `n`），所以总操作次数与记录数成线性关系。  
  - 大白话：如果有 1000 条登录记录，程序大概会跑 1000 次循环；如果记录翻倍，时间也会翻倍。

- **空间复杂度：** `O(k)`（`k` 为 2020 年登录的不同用户数）  
  - 需要一个字典保存每个用户的最新时间，最坏情况下每条记录都是不同用户，空间就和用户数一样多。  
  - 这比把所有记录全部复制一遍（`O(n)`）要省一点空间。

### 2. 最优解

#### 思路  

在 **数据库**（SQL）里，这类“分组后取最大值”的需求可以用一条语句一次性完成，避免把所有数据拉到程序里手动遍历。  
把这个思路映射到 Python：

1. 使用 **SQLite**（或其他内存数据库）把原始表 `Logins` 导入。  
2. 编写一条 **SQL** 语句：  
   - `WHERE time_stamp BETWEEN '2020-01-01' AND '2020-12-31 23:59:59'` 只保留 2020 年的记录（过滤在数据库层完成）。  
   - `GROUP BY user_id` 按用户分组。  
   - `MAX(time_stamp) AS latest_time` 取每组的最大时间戳，即最新登录。  
3. 直接执行这条语句，数据库会在内部使用 **索引**（如果有）和 **聚合算法**，一次扫描完成，时间复杂度约为 `O(n)`，但常数更小，且不需要额外的 Python 循环。  

> **核心概念解释**  
> - **GROUP BY**：把数据按某个字段（这里是 `user_id`）“装进不同的盒子”。同一个用户的所有登录记录会放进同一个盒子。  
> - **MAX()**：在每个盒子里挑出最大的时间戳，就像在每个盒子里找最高的山峰。  

#### 代码（Python）

```python
import sqlite3
from typing import List, Tuple

def latest_login_sql(records: List[Tuple[int, str]]) -> List[Tuple[int, str]]:
    """
    最优实现：利用 SQLite 完全在数据库内部完成过滤、分组、取最大。
    参数和返回值同上，只是内部实现不同。
    """
    # 1. 创建内存数据库并建表
    conn = sqlite3.connect(":memory:")
    cur = conn.cursor()
    cur.execute("""
        CREATE TABLE Logins (
            user_id INTEGER,
            time_stamp TEXT   -- SQLite 用 TEXT 存储 ISO 格式的 datetime
        )
    """)
    # 2. 批量插入数据
    cur.executemany("INSERT INTO Logins (user_id, time_stamp) VALUES (?, ?)", records)
    conn.commit()

    # 3. 用一条 SQL 完成所有工作
    sql = """
        SELECT
            user_id,
            MAX(time_stamp) AS latest_time   -- 取每个用户的最大时间戳
        FROM Logins
        WHERE time_stamp >= '2020-01-01 00:00:00'
          AND time_stamp <  '2021-01-01 00:00:00'   -- 只保留 2020 年
        GROUP BY user_id
    """
    cur.execute(sql)
    result = cur.fetchall()   # [(user_id, latest_time), ...]

    # 4. 关闭连接
    cur.close()
    conn.close()
    return result


# ------------------- 示例 -------------------
sample = [
    (6, "2020-06-30 15:06:07"),
    (6, "2021-04-21 14:06:06"),
    (6, "2019-03-07 00:18:15"),
    (8, "2020-02-01 05:10:53"),
    (8, "2020-12-30 00:46:50"),
    (2, "2020-01-16 02:49:50"),
    (2, "2019-08-25 07:59:08"),
    (14, "2019-07-14 09:00:00"),
]
print(latest_login_sql(sample))
# 可能输出：[(2, '2020-01-16 02:49:50'), (6, '2020-06-30 15:06:07'), (8, '2020-12-30 00:46:50')]
```

#### 复杂度

- **时间复杂度：** `O(n)`（在数据库内部）  
  - 只需要一次全表扫描，过滤、分组、取最大都在同一次遍历中完成。  
  - 与暴力解的遍历次数相同，但数据库内部实现往往更高效（使用索引、批量操作等），实际运行速度更快。

- **空间复杂度：** `O(k)`（`k` 为 2020 年登录的不同用户数）  
  - 数据库会为每个 `user_id` 保存一个聚合结果，和暴力解的字典占用空间相当。  
  - 额外的临时表和索引在内存中占用的空间通常比手动维护的列表更少。

## 心得

- **核心技巧**：**分组聚合（GROUP BY + MAX）**。它可以一次性把“同类数据归类后取极值”的需求解决掉，避免手动遍历。  
- **适用的题型**（类似思路）  
  1. “每个学生的最高成绩” → `GROUP BY student_id, MAX(score)`  
  2. “每个商品最近一次的库存变动” → `GROUP BY product_id, MAX(change_time)`  
  3. “每个部门最近一次的工资发放日期” → `GROUP BY dept_id, MAX(pay_date)`  
- **一句话总结解题钥匙**：**先在数据库层面过滤目标年份，再用 GROUP BY 把同一个用户的记录放进同一个盒子，最后用 MAX 选出盒子里最大的时间戳**。

## 反思

- **第一反应**：把所有记录拉出来，用 Python 循环自己筛选并找最大。虽然能跑通，但不利用数据库的强大聚合能力。  
- **最容易踩的坑**  
  - **日期边界**：忘记把 2020‑12‑31 23:59:59 也算进来，导致最后一天的登录被漏掉。使用 `>= '2020-01-01'` 与 `< '2021-01-01'` 可以避免此类错误。  
  - **时间格式**：如果数据库里是 `datetime` 类型，直接比较即可；若是字符串，需要确保统一的 ISO 格式（`YYYY-MM-DD HH:MM:SS`），否则比较结果会出错。  
  - **空用户**：没有 2020 年登录的用户不应出现在结果中，`WHERE` 子句自然把它们过滤掉。  
- **下次类似题的第一步**：**先在 SQL 中写出 `WHERE` 限制条件，然后思考是否需要 `GROUP BY` + 聚合函数（MAX、MIN、SUM、COUNT）来一次性得到答案**。这样可以最大程度利用数据库的优势，代码更简洁、运行更快。
