# #1955. 计数特殊子序列的数量 / Count Number of Special Subsequences

> 难度：困难 · 标签：Array、Dynamic Programming · [LeetCode 链接](https://leetcode.com/problems/count-number-of-special-subsequences/)

## 题目（英文原版）

**Description**

A sequence is special if it consists of a positive number of 0s, followed by a positive number of 1s, then a positive number of 2s.
Given an array nums (consisting of only integers 0, 1, and 2), return the number of different subsequences that are special. Since the answer may be very large, return it modulo 109 + 7.
A subsequence of an array is a sequence that can be derived from the array by deleting some or no elements without changing the order of the remaining elements. Two subsequences are different if the set of indices chosen are different.

**Examples**

**Example 1:**

```
Input: nums = [0,1,2,2]
Output: 3
Explanation: The special subsequences are bolded [0,1,2,2], [0,1,2,2], and [0,1,2,2].
```

**Example 2:**

```
Input: nums = [2,2,0,0]
Output: 0
Explanation: There are no special subsequences in [2,2,0,0].
```

**Example 3:**

```
Input: nums = [0,1,2,0,1,2]
Output: 7
Explanation: The special subsequences are bolded:
- [0,1,2,0,1,2]
- [0,1,2,0,1,2]
- [0,1,2,0,1,2]
- [0,1,2,0,1,2]
- [0,1,2,0,1,2]
- [0,1,2,0,1,2]
- [0,1,2,0,1,2]
```

**Constraints**

- 1 <= nums.length <= 105
- 0 <= nums[i] <= 2

## 题目（中文翻译）

一个序列（sequence）如果满足：由 **正数个** 0，随后是 **正数个** 1，最后是 **正数个** 2 构成，则称该序列为 **特殊序列**（special sequence）。  

给定一个仅包含整数 0、1、2 的数组 `nums`，返回不同的特殊子序列（subsequence）的数量。由于答案可能非常大，请返回其对 `10^9 + 7` 取模后的结果。  

子序列（subsequence）是指可以通过删除数组中的若干（也可以不删除）元素而得到的序列，且剩余元素的相对顺序保持不变。若两个子序列所选取的下标集合不同，则这两个子序列视为不同。  

**示例 1:**  
Input: nums = [0,1,2,2]  
Output: 3  
Explanation: 特殊子序列为 **[0,1,2,2]**, **[0,1,2,2]**, **[0,1,2,2]**（下标不同）。

**示例 2:**  
Input: nums = [2,2,0,0]  
Output: 0  
Explanation: 在数组 `[2,2,0,0]` 中不存在特殊子序列。

**示例 3:**  
Input: nums = [0,1,2,0,1,2]  
Output: 7  
Explanation: 特殊子序列为  
- **[0,1,2,0,1,2]**  
- **[0,1,2,0,1,2]**  
- **[0,1,2,0,1,2]**  
- **[0,1,2,0,1,2]**  
- **[0,1,2,0,1,2]**  
- **[0,1,2,0,1,2]**  
- **[0,1,2,0,1,2]**（下标集合各不相同）。

**约束条件**  
- `1 <= nums.length <= 10^5`  
- `0 <= nums[i] <= 2`

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**把所有可能的子序列都枚举出来**，检查每一个子序列是否满足「若干 0 → 若干 1 → 若干 2」的形式。  

- **子序列**可以看成从原数组里挑选若干下标，保持下标的相对顺序不变。  
- 为了枚举子序列，我们可以把每个位置当成「取」或「不取」两个选择，于是会得到 `2ⁿ` 种可能（`n` 为数组长度）。  

**为什么这个方法一定能得到答案**  
因为我们把所有合法与不合法的子序列都遍历了一遍，凡是符合「0…0 1…1 2…2」规则的都会被计数。

**时间/空间复杂度分析（大白话）**  
- 时间复杂度：`O(2ⁿ)`，也就是说如果数组有 20 个元素，就要检查大约一百万次；如果有 30 个元素，就要检查十亿次，根本不可接受。  
- 空间复杂度：`O(n)`（递归或位掩码需要保存当前的下标），这在这里不是主要瓶颈，真正的阻塞是指数级的时间。

> **结论**：暴力解只能在 `n` 极小（比如 `n ≤ 20`）时才能跑得动，远远超出本题的约束 `n ≤ 10⁵`，所以必须找更快的方法。

#### 代码（Python）

```python
from itertools import combinations

MOD = 10**9 + 7

def count_special_bruteforce(nums):
    n = len(nums)
    ans = 0
    # 枚举子序列的长度 1~n
    for k in range(1, n + 1):
        # 所有长度为 k 的下标组合
        for idxs in combinations(range(n), k):
            seq = [nums[i] for i in idxs]
            # 检查是否为 0+ 1+ 2+ 的形式
            i = 0
            # 必须先出现 0，且至少一个
            while i < len(seq) and seq[i] == 0:
                i += 1
            if i == 0:          # 没有 0
                continue
            # 接下来必须是 1，且至少一个
            j = i
            while j < len(seq) and seq[j] == 1:
                j += 1
            if j == i:          # 没有 1
                continue
            # 剩下的必须全是 2，且至少一个
            k = j
            while k < len(seq) and seq[k] == 2:
                k += 1
            if k == j:          # 没有 2
                continue
            if k == len(seq):   # 正好走完，说明是合法的 special 子序列
                ans = (ans + 1) % MOD
    return ans
```

> 这段代码仅用于演示「暴力」思路，**不要在正式提交时使用**，因为它会在稍大的测试数据上超时。

#### 复杂度  

- 时间复杂度：`O(2ⁿ)` —— 指数级增长，几乎不可能在 `n = 10⁵` 时跑完。  
- 空间复杂度：`O(n)` —— 主要用于保存当前组合的下标。

### 2. 最优解  

#### 思路  

从暴力解可以看到：**我们只关心子序列的“阶段”**——是只包含 0 的阶段、已经出现 1 的阶段，还是已经出现 2 的完整阶段。  
如果在遍历数组的过程中，能够实时统计出每一种“正在进行的”子序列有多少，就可以在 **一次线性扫描** 中得到答案。  

**关键瓶颈**：暴力解每次都要重新遍历所有已选下标，导致指数级时间。我们需要把“已经选了哪些下标”这件事压缩成几个计数器。

**状态划分**（从左到右逐个处理元素）  

| 状态 | 含义 | 用什么数据结构保存 |
|------|------|-------------------|
| `cnt0`   | 只由若干个 0 组成的子序列的个数（长度 ≥1） | 一个整数 |
| `cnt01`  | 已经出现了 0 且随后出现了若干 1（但还没有 2）的子序列个数 | 一个整数 |
| `cnt012` | 已经完整出现 0→1→2 的“special”子序列的个数 | 一个整数 |

我们把这三个计数器想象成 **三个桶**，每读到一个新元素，就把它可能放进相应的桶里，同时也可以“复制”已有的子序列（因为对每个已有子序列，我们可以选择 **不取** 当前元素或 **取** 当前元素）。

下面逐种数字说明转移公式：

1. **遇到 0**  
   - 之前的 `cnt0` 可以**不取**当前 0（保持不变）或**取**当前 0（形成新的子序列）。于是原来的 `cnt0` 翻倍。  
   - 此外，**单独**把当前这个 0 当作一个新子序列加入（长度为 1）。  
   - 所以：`cnt0 = cnt0 * 2 + 1`  

2. **遇到 1**  
   - 只要已经有了只含 0 的子序列（`cnt0`），我们可以把当前 1 加到它们后面，产生新的「0+1」子序列。  
   - 已经是「0+1」的子序列（`cnt01`）同样可以**不取**或**取**当前 1，导致翻倍。  
   - 所以：`cnt01 = cnt01 * 2 + cnt0`  

3. **遇到 2**  
   - 类似地，已有的「0+1」子序列（`cnt01`）可以把当前 2 加进去，变成完整的「0+1+2」序列。  
   - 已经完整的「0+1+2」子序列（`cnt012`）同样可以**不取**或**取**当前 2，翻倍。  
   - 所以：`cnt012 = cnt012 * 2 + cnt01`  

每一步都要取模 `10⁹+7` 防止整数爆炸。遍历结束后，`cnt012` 就是所有合法特殊子序列的数量。

**为什么这一步一步的计数是对的**  
- **不取当前元素**：对应「保持原来的子序列不变」的情况，这正是我们把计数乘以 2 的原因（原来每个子序列都有一个“不取”的选项）。  
- **取当前元素**：对应「把当前元素加入已有的子序列」或「把当前元素单独当作新子序列」的情况，这正是加上 `cnt0`、`cnt01` 或 `+1` 的来源。  
- 因为我们始终保持 **顺序不变**（只能把 0 放在前面，1 只能接在已经有 0 的序列后，2 只能接在已经有 0、1 的序列后），所以不会产生非法的排列。

**类比**：可以把这三个计数器想成三层流水线的生产线。  
- 第一道工序是「装 0」——每来一个原料 0，生产线的第一个桶里会翻倍并多出一个新产品。  
- 第二道工序是「装 1」——只有已经有了 0 的产品才能继续加入 1，同理会翻倍并新增。  
- 第三道工序是「装 2」——只有已经通过前两道工序的产品才能最终完成。

这样，一趟扫描就把所有可能的组合全部统计完了。

#### 代码（Python）

```python
MOD = 10**9 + 7

def countSpecialSubsequences(nums):
    """
    返回特殊子序列的数量，取模 1e9+7
    """
    cnt0 = cnt01 = cnt012 = 0          # 三个状态的计数器，初始都为 0

    for x in nums:
        if x == 0:
            # 只含 0 的子序列：不取或取当前 0；另外还能新建一个只含当前 0 的子序列
            cnt0 = (cnt0 * 2 + 1) % MOD
        elif x == 1:
            # 0+1 的子序列：不取或取当前 1；还能把所有只含 0 的子序列后面接上当前 1
            cnt01 = (cnt01 * 2 + cnt0) % MOD
        else:  # x == 2
            # 完整的 0+1+2 子序列：不取或取当前 2；还能把所有 0+1 的子序列后面接上当前 2
            cnt012 = (cnt012 * 2 + cnt01) % MOD

    return cnt012
```

**代码说明（逐行注释）**

| 行号 | 代码片段 | 中文解释 |
|------|----------|----------|
| 1    | `MOD = 10**9 + 7` | 题目要求的模数，防止整数过大 |
| 3‑4  | `def countSpecialSubsequences(nums):` | 主函数入口 |
| 6‑8  | `cnt0 = cnt01 = cnt012 = 0` | 初始化三个计数器，分别对应三种“阶段” |
| 10   | `for x in nums:` | 从左到右遍历数组 |
| 11‑13| `if x == 0: cnt0 = (cnt0 * 2 + 1) % MOD` | 处理 0：翻倍 + 新建子序列 |
| 14‑16| `elif x == 1: cnt01 = (cnt01 * 2 + cnt0) % MOD` | 处理 1：翻倍 + 把已有的 0‑序列接上 1 |
| 17‑19| `else: cnt012 = (cnt012 * 2 + cnt01) % MOD` | 处理 2：翻倍 + 把已有的 0‑1‑序列接上 2 |
| 21   | `return cnt012` | 最终答案是完整的 0‑1‑2 子序列数 |

#### 复杂度  

- **时间复杂度**：`O(n)`，只需要一次线性遍历，`n` 为数组长度。  
  - 与暴力解的 `O(2ⁿ)` 相比，**从指数级下降到线性级**，即使 `n = 10⁵` 也能在毫秒级完成。  
- **空间复杂度**：`O(1)`，只使用了固定的三个整数变量，不随 `n` 增长。

## 心得  

- **核心技巧**：**状态压缩动态规划**（把「已经匹配了多少阶段」压成常数个计数器）。  
- **适用题型**  
  1. **只含三段递增字符的子序列计数**（如「a⁺b⁺c⁺」）。  
  2. **统计形如「0⁺1⁺」或「1⁺0⁺」的子序列**（两段式的 DP）。  
  3. **类似的「子序列必须按固定顺序出现」的计数题**（如「a⁺b⁺c⁺d⁺」）。  

- **一句话总结解题钥匙**：**把「子序列的部分完成情况」抽象成几个计数器，遍历一次数组同步更新这些计数器**。

## 反思  

- **拿到题目第一反应**：想到枚举所有子序列，检查合法性——这就是暴力解。  
- **最容易踩的坑**  
  1. **忘记取模**：计数会在 `n = 10⁵` 时爆炸，需要每一步 `% MOD`。  
  2. **边界条件**：必须保证每个阶段的元素数量至少为 1，计数器的初始值为 0 正好能防止「空序列」被算进去。  
  3. **顺序错误**：只能在已有的「0」子序列后加 1，不能直接把 1 当作起始，这点在转移式里通过 `cnt01` 只加 `cnt0` 而不是直接 `+1` 来保证。  

- **下次遇到同类题的第一步**：先**把问题拆成「阶段」**（如 0‑阶段、1‑阶段、2‑阶段），判断每个新元素能把哪些已有阶段「推进」到下一阶段，然后写出对应的**状态转移式**。这样往往能直接得到 O(n) 的线性 DP 解法。
