# #1716. 计算 Leetcode 银行中的存款 / Calculate Money in Leetcode Bank

> 难度：简单 · 标签：Math · [LeetCode 链接](https://leetcode.com/problems/calculate-money-in-leetcode-bank/)

---

## 题目（英文原版）

**Description**

Hercy wants to save money for his first car. He puts money in the Leetcode bank every day.
He starts by putting in $1 on Monday, the first day. Every day from Tuesday to Sunday, he will put in $1 more than the day before. On every subsequent Monday, he will put in $1 more than the previous Monday.
Given n, return the total amount of money he will have in the Leetcode bank at the end of the nth day.

**Examples**

**Example 1:**

```
Input: n = 4
Output: 10
Explanation: After the 4th day, the total is 1 + 2 + 3 + 4 = 10.
```

**Example 2:**

```
Input: n = 10
Output: 37
Explanation: After the 10th day, the total is (1 + 2 + 3 + 4 + 5 + 6 + 7) + (2 + 3 + 4) = 37. Notice that on the 2nd Monday, Hercy only puts in $2.
```

**Example 3:**

```
Input: n = 20
Output: 96
Explanation: After the 20th day, the total is (1 + 2 + 3 + 4 + 5 + 6 + 7) + (2 + 3 + 4 + 5 + 6 + 7 + 8) + (3 + 4 + 5 + 6 + 7 + 8) = 96.
```

**Constraints**

- 1 <= n <= 1000

## 题目（中文翻译）

Hercy 想为他的第一辆车存钱。他每天都向 Leetcode 银行（Leetcode bank）存入一定金额。  

- 第一天（星期一）他存入 $1。  
- 从星期二到星期日，他每天比前一天多存 $1。  
- 在之后的每个星期一，他存入的金额比前一个星期一多 $1。  

给定整数 `n`，返回第 `n` 天结束时他在 Leetcode 银行中累计的总金额。

### 示例

**示例 1**  
输入: `n = 4`  
输出: `10`  
解释: 第 4 天结束时，总额为 $1 + 2 + 3 + 4 = 10。

**示例 2**  
输入: `n = 10`  
输出: `37`  
解释: 第 10 天结束时，总额为  
\((1 + 2 + 3 + 4 + 5 + 6 + 7) + (2 + 3 + 4) = 37\)。  
注意第二个星期一，Hercy 只存入 $2。

**示例 3**  
输入: `n = 20`  
输出: `96`  
解释: 第 20 天结束时，总额为  
\((1 + 2 + 3 + 4 + 5 + 6 + 7) + (2 + 3 + 4 + 5 + 6 + 7 + 8) + (3 + 4 + 5 + 6 + 7 + 8) = 96\)。

### 约束条件

- $1 \le n \le 1000$

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  
最直接的想法就是 **逐天模拟** Hercy 存钱的过程。  
- 用一个整数 `cur` 表示当天要存的金额，第一天 `cur = 1`。  
- 用一个计数 `weekday`（0~6）记录今天是星期几，0 代表星期一，1 代表星期二，依此类推。  
- 每天把 `cur` 加到答案 `total` 中，然后根据星期几决定第二天的 `cur`：  
  - 如果今天不是星期日（`weekday < 6`），第二天的金额就是 `cur + 1`（就像“每天比前一天多 $1”）。  
  - 如果今天是星期日（`weekday == 6`），第二天是下一个星期一，金额要比本周的星期一多 $1，也就是 `cur + 1`（因为本周的星期一已经是 `cur - 6`，下周的星期一就是 `cur - 6 + 1`，等价于 `cur + 1`）。  
- 同时把 `weekday` 循环加 1（`(weekday + 1) % 7`），模拟一周的循环。  

这套模拟过程保证了 **每一步都和题目描述完全一致**，所以一定能得到正确答案。  

**为什么正确**  
- 第一天我们手动设为 $1，符合题意。  
- 之后的每一天，我们严格按照 “前一天的金额 + 1” 来更新 `cur`，而且每逢星期一的递增也自然体现在 `cur` 已经比上一个星期一大 $1。  
- 循环 1…n 天后，`total` 就是第 n 天结束时的累计存款。  

**复杂度**  
- **时间复杂度**：我们要遍历 `n` 天，每天做 O(1) 的工作，所以是 **O(n)**。  
  - 这里的 “O(n)” 可以理解为：如果 `n` 是 1000，代码会执行大约 1000 次简单操作，几乎是瞬间完成的。  
- **空间复杂度**：只用了几个整数变量，和 `n` 的大小无关，**O(1)**（常数空间）。  

#### 代码（Python）  

```python
def totalMoney_bruteforce(n: int) -> int:
    """
    逐天模拟存钱过程，返回第 n 天结束时的总金额。
    """
    total = 0          # 累计总额
    cur = 1            # 当天要存入的金额，第一天是 1
    weekday = 0        # 0 表示星期一，1 表示星期二，...，6 表示星期日

    for day in range(1, n + 1):
        total += cur                 # 把今天存的钱加到总额
        # 为第二天准备金额和星期
        cur += 1                     # 明天比今天多 1 美元
        weekday = (weekday + 1) % 7 # 星期循环：0~6

        # 当今天是星期日时，第二天是新一周的星期一，
        # 这时 cur 已经是本周最后一天的金额 + 1，正好是下周星期一应存的金额。
        # 所以这里不需要额外的处理。

    return total
```

#### 复杂度  

- **时间复杂度**：O(n) — 随着天数 `n` 增大，执行的循环次数线性增长。  
- **空间复杂度**：O(1) — 只用常数个变量，不随 `n` 变化。

### 2. 最优解  

#### 思路  
暴力解的瓶颈在于 **逐天循环**，当 `n` 很大时（虽然本题最多 1000，仍然可以接受），我们仍然可以用数学公式直接算出答案，做到 **O(1)** 时间。  

观察存钱规律：  

| 周数 | 星期一金额 | 星期二金额 | … | 星期日金额 | 本周总和 |
|------|-----------|-----------|---|-----------|----------|
| 第 1 周 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 28 |
| 第 2 周 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 35 |
| 第 3 周 | 3 | 4 | 5 | 6 | 7 | 8 | 9 | 42 |
| … | … | … | … | … | … | … | … | … |

可以看到：  
- 第 `k` 周（从 0 开始计数）的星期一存入的金额是 `1 + k`。  
- 同一周内，后面的每天都比前一天多 $1，形成等差数列。  

**一周的总和**  
第 `k` 周（k 从 0 开始）有 7 天，金额从 `1 + k` 起步，公差为 1。等差数列求和公式：

\[
S_k = 7 \times \frac{(first + last)}{2}
    = 7 \times \frac{(1 + k) + (1 + k + 6)}{2}
    = 7 \times \frac{2k + 8}{2}
    = 7 \times (k + 4)
\]

也就是说，第 `k` 周的存款总额是 `7 * (k + 4)`。  

**拆分 n 天**  
设 `weeks = n // 7` 为完整的周数，`rem = n % 7` 为剩余的天数（0~6 天）。  

- 前 `weeks` 完整周的总和可以直接用等差数列求和：  
  \[
  \text{full} = \sum_{k=0}^{weeks-1} 7 \times (k + 4)
               = 7 \times \left( \sum_{k=0}^{weeks-1} k + 4 \times weeks \right)
               = 7 \times \left( \frac{weeks \times (weeks-1)}{2} + 4 \times weeks \right)
  \]

- 剩余的 `rem` 天位于第 `weeks` 周（因为已经走完 `weeks` 完整周），这周的星期一金额是 `1 + weeks`。  
  前 `rem` 天构成等差数列，首项是 `1 + weeks`，公差 1，项数 `rem`：  

  \[
  \text{partial} = rem \times \frac{2 \times (1 + weeks) + (rem - 1)}{2}
  \]

  这就是 **前 `rem` 天的累计**。  

把两部分相加即得到答案，全部只用几次算术运算，时间 **O(1)**。  

**类比**  
把每周看成一本书的章节，章节号就是周数 `k`，每章节的页数就是那一周的存款总额 `7*(k+4)`。要算前 `weeks` 章节的页数，只需要用等差数列求和公式，就像在图书馆快速查到总页数一样。  

#### 代码（Python）  

```python
def totalMoney_optimal(n: int) -> int:
    """
    用数学公式在 O(1) 时间内算出第 n 天结束时的累计存款。
    """
    weeks = n // 7          # 完整的周数
    rem   = n % 7           # 余下的天数

    # 1. 完整周的总和
    #   sum_{k=0}^{weeks-1} 7 * (k + 4)
    # = 7 * ( weeks*(weeks-1)/2 + 4*weeks )
    full = 7 * (weeks * (weeks - 1) // 2 + 4 * weeks)

    # 2. 余下的天数所在的那一周，星期一的金额是 1 + weeks
    #   前 rem 天构成等差数列，首项 a = 1 + weeks，公差 d = 1
    #   部分和 = rem * (2*a + (rem-1)) / 2
    partial = rem * (2 * (1 + weeks) + (rem - 1)) // 2

    return full + partial
```

#### 复杂度  

- **时间复杂度**：O(1) — 只做常数次算术运算，跟 `n` 的大小无关。  
  - 与暴力解相比，省去了循环，瞬间得到答案。  
- **空间复杂度**：O(1) — 只用几条整数变量，同样是常数空间。

## 心得  

- **核心技巧**：把“每天递增、每周递增”这种**分层递增**的过程抽象为等差数列，再利用等差数列求和公式一次性算出答案。  
- **适用题型**：  
  1. “每 N 天递增一次” 类似的累计求和（如每月工资递增、每季奖金递增）。  
  2. “分段等差求和” 的题目（如把数组按固定长度切块，每块内部递增）。  
  3. “周/月/年循环递增” 的时间序列累计问题。  
- **一句话总结**：**把循环的规律化为等差数列，用公式直接求和，即可把线性遍历压缩成常数时间。**

## 反思  

- **第一反应**：看到“每天比前一天多 1、每周的星期一再多 1”，第一时间想到 **模拟**，因为这最符合直观的“每天算一次”。  
- **最容易踩的坑**：  
  - **边界条件**：`n` 恰好是 7 的倍数时，`rem = 0`，此时不应再加任何“余下天数”的金额。代码里要确保 `partial` 为 0。  
  - **整数除法**：在 Python 中使用 `//` 保证结果是整数，防止出现浮点数导致的精度问题。  
  - **负数或 0**：题目保证 `n ≥ 1`，但如果忘记这点，可能在 `weeks-1` 为负时出现错误。  
- **下次遇到同类题**，第一步应该 **先写出规律的数学表达式**（等差数列、等比数列或前缀和），判断是否能直接用公式求和；如果不容易写出公式，再考虑**模拟**或**前缀和**的线性解法。
