## 题目（英文原版）

**Description**

There are n cars traveling at different speeds in the same direction along a one-lane road. You are given an array cars of length n, where cars[i] = [positioni, speedi] represents:
For simplicity, cars can be considered as points moving along the number line. Two cars collide when they occupy the same position. Once a car collides with another car, they unite and form a single car fleet. The cars in the formed fleet will have the same position and the same speed, which is the initial speed of the slowest car in the fleet.
Return an array answer, where answer[i] is the time, in seconds, at which the ith car collides with the next car, or -1 if the car does not collide with the next car. Answers within 10-5 of the actual answers are accepted.

**Examples**

**Example 1:**

```
Input: cars = [[1,2],[2,1],[4,3],[7,2]]
Output: [1.00000,-1.00000,3.00000,-1.00000]
Explanation: After exactly one second, the first car will collide with the second car, and form a car fleet with speed 1 m/s. After exactly 3 seconds, the third car will collide with the fourth car, and form a car fleet with speed 2 m/s.
```

**Example 2:**

```
Input: cars = [[3,4],[5,4],[6,3],[9,1]]
Output: [2.00000,1.00000,1.50000,-1.00000]
```

**Constraints**

- 1 <= cars.length <= 105
- 1 <= positioni, speedi <= 106
- positioni < positioni+1

## 题目（中文翻译）

有 `n` 辆汽车以不同的速度沿同一方向在单车道上行驶。给定长度为 `n` 的数组 `cars`，其中 `cars[i] = [position_i, speed_i]` 表示第 `i` 辆车的**位置**（`position_i`）和**速度**（`speed_i`）。

为简化起见，汽车可以视作在数轴上移动的点。当两辆车占据相同的位置时即发生碰撞。碰撞后，两车会合并为一支**车队（car fleet）**，该车队中的所有汽车共享同一位置和同一速度，速度取该车队中最慢汽车的初始速度。

返回数组 `answer`，其中 `answer[i]` 为第 `i` 辆车与其前方的下一辆车碰撞的时间（单位：秒），若该车永远不会与前车碰撞，则为 `-1`。答案的误差在 `10^-5` 之内均被视为正确。

**示例 1**

```text
Input: cars = [[1,2],[2,1],[4,3],[7,2]]
Output: [1.00000,-1.00000,3.00000,-1.00000]
Explanation: 在恰好 1 秒时，第一辆车会与第二辆车碰撞，形成速度为 1 m/s 的车队。随后在恰好 3 秒时，第三辆车会与第四辆车碰撞，形成速度为 2 m/s 的车队。
```

**示例 2**

```text
Input: cars = [[3,4],[5,4],[6,3],[9,1]]
Output: [2.00000,1.00000,1.50000,-1.00000]
```

**约束条件**

- `1 <= cars.length <= 10^5`
- `1 <= position_i, speed_i <= 10^6`
- `position_i < position_{i+1}`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**对每一辆车 i，去检查它后面所有的车 j (j>i) ，看哪一辆会先和 i 碰撞**。  
- **遍历**：先固定 i，然后从 i+1 开始逐个比较。
- **碰撞时间公式**：  
  - 位置 `p_i , p_j`，速度 `s_i , s_j`（`p_i < p_j`）  
  - 若 `s_i <= s_j`，i 永远追不上 j，碰撞时间为∞（记为 -1）。  
  - 若 `s_i > s_j`，两车相对距离 `p_j-p_i`，相对速度 `s_i-s_j`，碰撞时间 `t = (p_j-p_i)/(s_i-s_j)`。  
- **考虑已形成车队**：当 j 已经和更右侧的车碰撞并形成了车队后，它的实际速度会变成更慢的那辆车的速度。因此我们需要先算出 j 的碰撞时间 `ans[j]`，如果 `t >= ans[j]`（i 要在 j 已经变慢之前才追上它），则 i 实际上会先和 j 的 **车队** 碰撞，而不是直接和 j 本身碰撞。于是把这种情况排除，继续向右找下一个候选。

把上面的检查全部写出来，就是暴力解。

> **生活化类比**：想象每辆车是一位跑步的选手，赛道是一条单行道。我们把每位选手往后看的“第一位会被追上的选手”当作“最近的前方障碍”。暴力做法就是让每个选手逐个检查前面所有选手，算出追上所需的时间，找出最早的那一次。

#### 代码（Python）

```python
from typing import List

def getCollisionTimes_bruteforce(cars: List[List[int]]) -> List[float]:
    n = len(cars)
    ans = [-1.0] * n                     # 最终答案，默认 -1 表示永远不碰撞
    # 从右往左遍历，这样右侧车的答案已经算好
    for i in range(n - 2, -1, -1):
        p_i, s_i = cars[i]
        # 检查 i 右侧的每一辆车 j
        for j in range(i + 1, n):
            p_j, s_j = cars[j]
            # 如果 i 追不上 j，直接跳过
            if s_i <= s_j:
                continue
            # 计算直接追上的时间
            t = (p_j - p_i) / (s_i - s_j)
            # 如果 j 会在 t 之前与更右侧的车碰撞，说明 i 实际上要追的是 j 的车队
            # ans[j] == -1 表示 j 永远不碰撞，这种情况下直接使用 t
            if ans[j] == -1.0 or t <= ans[j]:
                ans[i] = t
                break          # 找到最近的碰撞对象，退出内层循环
            # 否则 j 已经在更早的时刻变慢，i 需要继续向右找
    return ans
```

#### 复杂度

- **时间复杂度**：`O(n²)`  
  - 想象一下，最坏情况下每辆车都要检查它右边的所有车，就像在一个 10,000 人的队伍里，每个人都要向后数一遍，操作次数会是 `1+2+…+n ≈ n²/2`。对 `n=10⁵` 来说根本跑不完。
- **空间复杂度**：`O(1)`（不计输出数组）  
  - 只用了常数级别的额外变量。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**大量重复的比较**。我们需要一种数据结构，让“向右找最近的会碰撞的车”能够 **快速跳过** 那些根本不可能成为答案的车。这里的关键是**单调栈（Monotonic Stack）**，它可以帮助我们在 O(1) 均摊时间内完成“剔除无效候选”。

下面一步步推导：

1. **从右往左处理**  
   - 与暴力一样，我们从最右边的车开始往左遍历，这样右侧车的碰撞时间已经算好，随时可以使用。

2. **只关心“更慢的车”**  
   - 若 `s_i <= s_j`（i 的速度不大于 j），i 永远追不上 j，j 可以直接 **被忽略**（不放进栈）。  
   - 因此栈中只会保留速度 **严格递减** 的车（从栈底到栈顶，速度从大到小）。

3. **碰撞时间的比较**  
   - 对于当前车 i，栈顶是离它最近且速度更慢的车 k。我们先算出 `t = (pos_k - pos_i) / (speed_i - speed_k)`。  
   - 但是，如果 `k` 本身会在 `t` 之前碰撞（`ans[k] != -1` 且 `t > ans[k]`），说明 i 在 k 变慢之前根本追不到 k，i 实际上应该去追 **k 的车队**，也就是更右侧的那辆车。于是 **弹出 k**，继续检查栈中的下一个候选。

4. **弹出原则**  
   - **速度更快的车**（`speed_i >= speed_top`）直接弹出，因为 i 永远追不上它们。  
   - **会在更早时间碰撞的车**（`t > ans[top]` 且 `ans[top] != -1`）也弹出，因为它们在 i 追上之前已经“消失”。  

   经过这两轮弹出后，栈顶（如果还有）就是 i 第一次会碰撞的车。

5. **把当前车加入栈**  
   - 计算完 i 的答案后，把 i 放进栈，供左侧的车使用。此时栈仍保持速度递减的性质。

> **类比**：想象我们在排队买咖啡，后面的人（速度更快）想追前面慢一点的人。如果前面那个人很快就被更前面更慢的人“合并”（碰撞），后面的人根本追不到他，只能再往前看。栈就像一条“候选链”，我们不断把“已经被合并的”人踢出去，只留下真正可能被追上的人。

#### 代码（Python）

```python
from typing import List

def getCollisionTimes(cars: List[List[int]]) -> List[float]:
    """
    单调栈 + 预先计算的碰撞时间
    时间复杂度 O(n)，空间复杂度 O(n)（栈 + 输出数组）
    """
    n = len(cars)
    ans = [-1.0] * n                # 最终答案
    stack = []                      # 栈中存放候选车的下标，保持速度递减

    # 从右往左遍历
    for i in range(n - 1, -1, -1):
        p_i, s_i = cars[i]

        # ① 删除速度不慢于当前车的候选（i 永远追不上）
        while stack and cars[stack[-1]][1] >= s_i:
            stack.pop()

        # ② 删除会在 i 追上之前就已经碰撞的车
        while stack:
            j = stack[-1]
            p_j, s_j = cars[j]
            # 计算 i 与 j 的直接碰撞时间
            t = (p_j - p_i) / (s_i - s_j)   # 此时 s_i > s_j，分母必然 >0
            # 若 j 永不碰撞，或者 i 能在 j 碰撞前追上，则 t 为答案
            if ans[j] == -1.0 or t <= ans[j] + 1e-12:
                ans[i] = t
                break
            # 否则 j 会更早碰撞，i 追不到 j，弹出 j 继续向前找
            stack.pop()

        # 将当前车加入栈，供左侧车辆使用
        stack.append(i)

    return ans
```

> **关键注释**  
- `while stack and cars[stack[-1]][1] >= s_i:`：把所有**不比我慢**的车踢出，因为我追不上。  
- `t <= ans[j] + 1e-12`：加一点容差避免浮点数精度误差。  
- `stack.append(i)`：把自己加入候选，保持栈的 **单调递减**（速度从大到小）特性。

#### 复杂度

- **时间复杂度**：`O(n)`  
  - 每辆车最多被压入栈一次、弹出一次。类似“每个元素只进出一次”的洗牌过程，总操作数与 `n` 成线性关系。相比 `n²` 的暴力解，快了几个数量级。
- **空间复杂度**：`O(n)`  
  - 需要一个栈来保存候选车的下标，最坏情况下栈里会有所有车（当速度严格递减时），再加上返回的答案数组。

## 心得

- **核心技巧**：**单调栈 + 预先计算的碰撞时间**。通过把“更快的车”和“已经提前碰撞的车”剔除，能够在 O(1) 均摊时间内找到每辆车的最近碰撞对象。
- **适用的题型**  
  1. **Car Fleet** / **Car Fleet II**（本题）——求车队合并时间。  
  2. **Collision Times of Cars**（类似的 “碰撞时间” 题目）。  
  3. **Next Greater Element / Next Smaller Element** 系列——利用单调栈快速寻找右侧满足某种单调关系的第一个元素。  
- **一句话总结**：  
  *“把右侧所有‘比我快’的车和‘已经提前消失’的车剔除，栈顶就是我最先会追上的那辆车。”*

## 反思

- **第一反应**：直接想到暴力枚举所有右侧车辆，算时间后取最小。  
- **最容易踩的坑**  
  - **忽略车队合并后速度的变化**：必须使用已知的 `ans[j]` 判断 i 能否在 j 合并前追上。  
  - **浮点数精度**：比较 `t` 与 `ans[j]` 时要加容差，防止因微小误差导致错误弹出。  
  - **边界条件**：当 `ans[j] = -1`（j 永不碰撞）时，直接使用 `t`；当 `s_i <= s_j` 时必须立刻跳过。  
- **下次遇到同类题**，第一步应该想到：  
  *“从右往左遍历，用单调栈维护‘可能的碰撞对象’，每次弹出不满足条件的候选”。*  

这样就能把原本的 `O(n²)` 暴力转化为线性的高效解法。
