# #2029. 石子游戏 IX / Stone Game IX

## 题目（英文原版）

**Description**

Alice and Bob continue their games with stones. There is a row of n stones, and each stone has an associated value. You are given an integer array stones, where stones[i] is the value of the ith stone.
Alice and Bob take turns, with Alice starting first. On each turn, the player may remove any stone from stones. The player who removes a stone loses if the sum of the values of all removed stones is divisible by 3. Bob will win automatically if there are no remaining stones (even if it is Alice's turn).
Assuming both players play optimally, return true if Alice wins and false if Bob wins.

**Examples**

**Example 1:**

```
Input: stones = [2,1]
Output: true
Explanation: The game will be played as follows:
- Turn 1: Alice can remove either stone.
- Turn 2: Bob removes the remaining stone. 
The sum of the removed stones is 1 + 2 = 3 and is divisible by 3. Therefore, Bob loses and Alice wins the game.
```

**Example 2:**

```
Input: stones = [2]
Output: false
Explanation: Alice will remove the only stone, and the sum of the values on the removed stones is 2. 
Since all the stones are removed and the sum of values is not divisible by 3, Bob wins the game.
```

**Example 3:**

```
Input: stones = [5,1,2,4,3]
Output: false
Explanation: Bob will always win. One possible way for Bob to win is shown below:
- Turn 1: Alice can remove the second stone with value 1. Sum of removed stones = 1.
- Turn 2: Bob removes the fifth stone with value 3. Sum of removed stones = 1 + 3 = 4.
- Turn 3: Alices removes the fourth stone with value 4. Sum of removed stones = 1 + 3 + 4 = 8.
- Turn 4: Bob removes the third stone with value 2. Sum of removed stones = 1 + 3 + 4 + 2 = 10.
- Turn 5: Alice removes the first stone with value 5. Sum of removed stones = 1 + 3 + 4 + 2 + 5 = 15.
Alice loses the game because the sum of the removed stones (15) is divisible by 3. Bob wins the game.
```

**Constraints**

- 1 <= stones.length <= 105
- 1 <= stones[i] <= 104

## 题目（中文翻译）

Alice 和 Bob 继续他们的石子游戏。共有一排 n 颗石子，每颗石子都有一个关联的数值。给定整数数组 `stones`，其中 `stones[i]` 表示第 i 颗石子的数值。  
Alice 和 Bob 轮流进行操作，Alice 先手。每回合，当前玩家可以从 `stones` 中移除任意一颗石子。**如果已移除石子的数值之和能被 3 整除，则移除该石子的玩家立即输掉游戏。** 当没有剩余石子时，Bob 自动获胜（即使轮到 Alice）。  

在双方都采用最优策略的前提下，若 Alice 能获胜返回 `true`，否则返回 `false`。

**示例 1**  
``` 
Input: stones = [2,1]
Output: true
Explanation: 游戏过程如下：
- 第 1 回合：Alice 可以移除任意一颗石子。
- 第 2 回合：Bob 移除剩余的石子。  
已移除石子数值之和为 1 + 2 = 3，能够被 3 整除。因此 Bob 输，Alice 赢。
```

**示例 2**  
``` 
Input: stones = [2]
Output: false
Explanation: Alice 移除唯一的石子，已移除石子数值之和为 2。  
所有石子已被移除且总和不能被 3 整除，Bob 获胜。
```

**示例 3**  
``` 
Input: stones = [5,1,2,4,3]
Output: false
Explanation: Bob 必定获胜。以下是一种 Bob 获胜的可能走法：
- 第 1 回合：Alice 移除数值为 1 的第二颗石子。已移除石子之和 = 1。  
- 第 2 回合：Bob 移除数值为 3 的第五颗石子。已移除石子之和 = 1 + 3 = 4。  
- 第 3 回合：Alice 移除数值为 4 的第四颗石子。已移除石子之和 = 1 + 3 + 4 = 8。  
- 第 4 回合：...（后续省略）
```

**约束条件**  
- `1 <= stones.length <= 10^5`  
- `1 <= stones[i] <= 10^4`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把游戏过程全部枚举出来：  
- 轮到谁，就遍历**所有剩余的石头**，尝试把每一块石头拿走；
- 记录已经拿走的石头的价值之和 `total`，判断 `total % 3 == 0` 时当前玩家是否立刻输；
- 若当前玩家没有立即输，就把局面交给对手继续玩，递归求出对手的胜负情况；
- 如果在某一次选择后，**对手必输**，则说明当前玩家可以通过这一步获胜，返回 `True`；否则返回 `False`。

这相当于在一棵巨大的**决策树**上深度搜索：每一层代表一次出手，每个分支对应拿走的那块石头。

> **类比**：把所有石头想象成一本书的页码，玩家每次随手翻掉一页，记录已翻掉的页码之和。要判断谁会先翻到“和能被 3 整除”的页面。暴力做法就是把每一种翻页顺序都列出来检查。

**为什么正确**  
因为我们把**所有可能的出手顺序**都穷举了，只要有一种出手方式能让 Alice 获胜，递归就会找到并返回 `True`；若所有方式都导致 Alice 输，最终返回 `False`。这与游戏的“最优对局”定义完全吻合。

**时间/空间复杂度**  
- 时间复杂度：设石头数量为 `n`，每一步都有 `O(k)`（`k` 为当前剩余石头数）种选择，递归深度为 `n`，总的搜索树规模约为 `n!`（阶乘），即 **指数级**。  
  - 用大白话说，`n = 10` 时已经要检查 3,628,800 种情况，`n = 15` 时已经是 1.3×10¹²，根本不可接受。  
- 空间复杂度：递归栈深度为 `n`，每层保存当前的 `total` 与剩余石头集合，最坏是 **O(n)**。

#### 代码（Python）

```python
from functools import lru_cache
from typing import List, Tuple

def stoneGameIX_bruteforce(stones: List[int]) -> bool:
    """
    暴力递归搜索所有出手顺序，返回 Alice 是否能获胜。
    只适用于 stones 长度非常小的情况（例如 n <= 10）。
    """
    n = len(stones)

    @lru_cache(maxsize=None)
    def dfs(mask: int, total_mod: int, turn: int) -> bool:
        """
        mask      : 用二进制位表示哪些石头还在（1 表示在）
        total_mod : 已取走石头价值之和对 3 的余数（0/1/2）
        turn      : 0 表示 Alice 的回合，1 表示 Bob 的回合
        返回当前玩家在该局面是否必胜
        """
        # 若已经没有石头，按照题意：Bob 赢
        if mask == 0:
            return turn == 1  # 轮到 Alice 时返回 False，轮到 Bob 时返回 True

        # 如果当前总和已经是 0 (mod 3)，则**刚刚**拿石头的玩家已经输掉了
        # 这里的 total_mod 是拿完上一手后的余数，所以只要 total_mod == 0,
        # 当前玩家已经是**输家**，返回 False
        if total_mod == 0:
            return False

        # 枚举所有还能取的石头
        for i in range(n):
            if mask >> i & 1:                # 第 i 块石头还在
                new_mask = mask ^ (1 << i)   # 把第 i 块石头移除
                new_mod = (total_mod + stones[i]) % 3
                # 如果对手在新局面必输，则当前玩家必胜
                if not dfs(new_mask, new_mod, 1 - turn):
                    return True
        # 所有选择都让对手必胜，说明当前玩家必输
        return False

    # 初始时没有取过石头，sum = 0（但根据规则，刚开始并不算输），所以我们把 total_mod 设为 0
    # 这里把 total_mod 当作“已经取走的石头的和对 3 的余数”，因此先手拿第一块石头后再检查
    full_mask = (1 << n) - 1
    return dfs(full_mask, 0, 0)   # 0 表示 Alice 先手
```

> **注意**：上面的实现使用了 `lru_cache` 做记忆化，能把同一局面重复计算的次数降到最低，但仍然是指数级的，只有在 `n` 很小的时候才会跑得完。

#### 复杂度

- **时间复杂度**：`O(n!)`（阶乘），因为要遍历所有可能的取石顺序。  
  - 直观理解：每一次都要在剩下的石头里挑一个，第一步有 `n` 种，第二步有 `n‑1` 种……相乘就是 `n!`。
- **空间复杂度**：`O(n)`，递归栈的深度最多是石头数量 `n`。

### 2. 最优解

#### 思路  

**从暴力解出发，找瓶颈**  
- 暴力解遍历所有取石顺序，时间爆炸。  
- 观察游戏规则：输赢只和**已经取走的石头之和模 3**有关，而**具体是哪几块石头**并不重要。  

**关键观察 1：只关心余数**  
每块石头的价值 `v` 对 3 取余只有三种可能：`0、1、2`。  
- 余数为 `0` 的石头直接把当前和的余数 **保持不变**，但会立刻让“拿石头后总和为 0(mod 3)”的玩家**输**（因为刚拿完后 sum%3==0）。  
- 余数为 `1` 的石头会把当前余数 `x` 变成 `(x+1) % 3`。  
- 余数为 `2` 的石头会把当前余数 `x` 变成 `(x+2) % 3`（等价于 `x-1`）。

因此，游戏的状态只需要记录三个数字：

| 余数 | 代表的石头数量 |
|------|----------------|
| cnt0  | 价值 %3 == 0 的石头数 |
| cnt1  | 价值 %3 == 1 的石头数 |
| cnt2  | 价值 %3 == 2 的石头数 |

**关键观察 2：先手的第一步决定余数**  
游戏一开始，总和为 `0`，如果 Alice 第一步直接拿走 **余数为 0** 的石头，她立刻让 `sum % 3 == 0`，根据规则 **她会输**（因为“拿石头后如果总和能被 3 整除则该玩家输”）。  
所以 Alice **永远不会** 首先选 `cnt0`，除非 **所有石头都是余数 0**，此时她只能输。

因此，Alice 只能从 `cnt1` 或 `cnt2` 中挑选一种开始。  
接下来，游戏在每一步都只会在 **余数 1** 与 **余数 2** 之间切换（因为取 0 不会改变余数，但会立即导致当前玩家输），所以我们可以把**取 0 的石头视作“保留”**，只在必要时用来延长游戏。

**关键观察 3：只需要比较 cnt1 与 cnt2 的大小**  
设 `a = cnt1`, `b = cnt2`。  
- 如果两者相差 **大于 2**，先手可以通过先拿较多的那类石头来逼迫对手在自己的回合里把余数变成 0，进而获胜。  
- 如果相差 **不超过 2**，则游戏会在两类石头交替取完后进入“只剩余数 0 的石头”阶段。此时轮到谁取第一块 0，谁就输。因为取 0 不会改变余数，取完后仍是同一余数，但已经导致 **当前玩家输**（因为取完后 sum%3 仍为 0），所以**先手是否能在交替阶段结束时把回合权交给对手**决定胜负。

经过系统化的推导（可参考官方题解或下文的状态转移表），最终得到简洁的判定规则：

> **Alice 胜利的充要条件**  
> 1. `cnt0` 为 **偶数** 且 `abs(cnt1 - cnt2) > 2`  
> 2. `cnt0` 为 **奇数** 且 `abs(cnt1 - cnt2) == 0`（即 `cnt1 == cnt2`）  

下面给出更易理解的实现思路：

1. 统计三类石头的数量 `c0, c1, c2`。  
2. 如果 `c1 == 0` 且 `c2 == 0` → 只有余数 0 的石头，Alice 必输。  
3. 令 `diff = abs(c1 - c2)`。  
4. 若 `diff > 2` → Alice 必赢（因为她可以先挑多的那类石头，让对手在余数为 0 时被迫取石）。  
5. 若 `diff <= 2` → 结果取决于 `c0` 的奇偶性：  
   - `c0 % 2 == 1` → Alice 赢（因为她可以在交替阶段结束后让 Bob 在余数为 0 时先手取 0，导致 Bob 输）。  
   - `c0 % 2 == 0` → Alice 输。

> **类比**：把石头看成三种颜色的弹珠（红=余1，蓝=余2，白=余0）。游戏规则相当于：轮流取弹珠，累计颜色编号之和若恰好是 3 的倍数，取弹珠的玩家立刻输。白弹珠不改变累计和，却会让取它的玩家立刻输；红、蓝弹珠会把累计和在 1 与 2 之间切换。于是我们只需要比较红弹珠和蓝弹珠的数量差，以及白弹珠的奇偶性，就能预判谁会先被迫取白弹珠。

#### 代码（Python）

```python
from typing import List

def stoneGameIX(stones: List[int]) -> bool:
    """
    最优解：只统计石头对 3 的余数，依据余数数量的奇偶和差值直接判定胜负。
    时间 O(n) 只遍历一次，空间 O(1)。
    """
    # 统计余数为 0、1、2 的石头数量
    c0 = c1 = c2 = 0
    for v in stones:
        r = v % 3
        if r == 0:
            c0 += 1
        elif r == 1:
            c1 += 1
        else:               # r == 2
            c2 += 1

    # 没有余数 1、2 的石头，Alice 只能拿余数 0 → 必输
    if c1 == 0 and c2 == 0:
        return False

    diff = abs(c1 - c2)        # 两类石头数量的差距

    # 情况 1：差距大于 2，先手可以利用多数那类石头取胜
    if diff > 2:
        return True

    # 情况 2：差距不大于 2，胜负取决于余数 0 的奇偶性
    #   - c0 为奇数时，Alice 能在关键时刻把 “必须取余0” 的局面留给 Bob
    #   - c0 为偶数时，Bob 能把该局面留给 Alice
    return c0 % 2 == 1
```

> **代码解释**  
- 第 5‑12 行：一次遍历统计三类石头的数量。  
- 第 15‑18 行：如果只有余数为 0 的石头，Alice 第一步必输。  
- 第 20‑22 行：`diff > 2` 时，先手必胜。  
- 第 24‑27 行：其余情况依据 `c0` 的奇偶性返回结果。

#### 复杂度

- **时间复杂度**：`O(n)`，只需要一次线性扫描统计余数。  
  - 与暴力解的 `O(n!)` 相比，提升了数十亿倍，即使 `n = 10⁵` 也能在毫秒级完成。  
- **空间复杂度**：`O(1)`，只用常数个整数计数器，不随 `n` 增长。

## 心得

- **核心技巧**：**余数分类 + 计数 + 奇偶性分析**。  
  这道题把“取石头后和是否能被 3 整除”抽象成“当前和的余数”。只要关注余数的变化，就能把原本的指数级搜索压缩到常数状态空间。

- **适用的题型**  
  1. **取数游戏**，如 *Stone Game VII*、*Stone Game III*（利用前缀和或余数）。  
  2. **取子集使和满足某模数条件**，如 *Divisible Subset*、*Partition to K Equal Sum Subsets*（模数归类）。  
  3. **计数+奇偶性决定胜负**，如 *Bulbasaur and the Game*（奇偶 Nim）等。

- **一句话总结解题钥匙**：**把所有数只按 “%3 的余数” 分类，比较余数 1、2 的数量差与余数 0 的奇偶性，即可直接判断先手能否赢。**

## 反思

- **第一反应**：看到“和能被 3 整除就输”，本能想把每一步的和记录下来，尝试递归搜索所有取法——这正是暴力解的思路。  
- **最容易踩的坑**  
  1. **忘记余数为 0 的石头会立刻导致取它的玩家输**，从而误把它当作普通石头处理。  
  2. **边界条件**：全部石头余数为 0 时，先手必输；只有一种余数（如只有余数 1）时，需要特别判断 `c0` 的奇偶性。  
  3. **对 “Bob 自动赢” 的理解**：当石头全部被取完且总和不为 3 的倍数时，胜负已经在最后一次取石时决定，不再需要额外判断。

- **下次遇到同类题**：第一步先**把数值映射到一个小的模数集合**（如 %3、%k），统计每类出现的次数，再思考**状态转移只在这些模数之间切换**，利用计数或奇偶性快速得出结论，而不是直接枚举所有取法。
