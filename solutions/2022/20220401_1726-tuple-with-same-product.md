# #1726. **乘积相同的四元组** / Tuple with Same Product

## 题目（英文原版）

**Description**

Given an array nums of distinct positive integers, return the number of tuples (a, b, c, d) such that a * b = c * d where a, b, c, and d are elements of nums, and a != b != c != d.

**Examples**

**Example 1:**

```
Input: nums = [2,3,4,6]
Output: 8
Explanation: There are 8 valid tuples:
(2,6,3,4) , (2,6,4,3) , (6,2,3,4) , (6,2,4,3)
(3,4,2,6) , (4,3,2,6) , (3,4,6,2) , (4,3,6,2)
```

**Example 2:**

```
Input: nums = [1,2,4,5,10]
Output: 16
Explanation: There are 16 valid tuples:
(1,10,2,5) , (1,10,5,2) , (10,1,2,5) , (10,1,5,2)
(2,5,1,10) , (2,5,10,1) , (5,2,1,10) , (5,2,10,1)
(2,10,4,5) , (2,10,5,4) , (10,2,4,5) , (10,2,5,4)
(4,5,2,10) , (4,5,10,2) , (5,4,2,10) , (5,4,10,2)
```

**Constraints**

- 1 <= nums.length <= 1000
- 1 <= nums[i] <= 104
- All elements in nums are distinct.

## 题目（中文翻译）

给定一个由互不相同的正整数构成的数组 `nums`，返回满足 `a * b = c * d` 的四元组 `(a, b, c, d)` 的数量，其中 `a、b、c、d` 均取自 `nums`，且 `a != b != c != d`。

**示例 1**  
**输入**: `nums = [2,3,4,6]`  
**输出**: `8`  
**解释**: 共有 8 个符合条件的四元组：  
`(2,6,3,4) , (2,6,4,3) , (6,2,3,4) , (6,2,4,3)`  
`(3,4,2,6) , (4,3,2,6) , (3,4,6,2) , (4,3,6,2)`

**示例 2**  
**输入**: `nums = [1,2,4,5,10]`  
**输出**: `16`  
**解释**: 共有 16 个符合条件的四元组：  
`(1,10,2,5) , (1,10,5,2) , (10,1,2,5) , (10,1,5,2)`  
`(2,5,1,10) , (2,5,10,1) , (5,2,1,10) , (5,2,10,1)`  
`(2,10,4,5) , (2,10,5,4) , (10,2,4,5) , (10,2,5,4)`  
`(4,5,2,10) , (4,5,10,2) , (5,4,2,10) , (5,4,10,2)`

**约束条件**  
- `1 <= nums.length <= 1000`  
- `1 <= nums[i] <= 10^4`  
- `nums` 中的所有元素互不相同。

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  

最直接的想法就是把题目里要求的四元组全部枚举一遍：  
1. 从数组 `nums` 中任选 **4** 个不同的下标 `i、j、k、l`（顺序不固定），  
2. 取出对应的数 `a = nums[i]、b = nums[j]、c = nums[k]、d = nums[l]`，  
3. 检查是否满足 `a * b == c * d`，如果相等就把这一个四元组计数。  

这里用到的唯一数据结构是 **列表**（`nums` 本身）和 **四层循环**。可以把它想象成一次“全员点名”：老师把所有同学排成一列，依次让每四个人站到前面，看看他们手里的数字乘积是否相同。  

> 为什么这个方法一定能得到正确答案？  
> 因为我们把 **所有可能的四元组** 都遍历了一遍，凡是满足条件的必然被统计，凡是不满足的必然被过滤掉。

#### 代码（Python）  

```python
from typing import List

def tupleSameProduct_bruteforce(nums: List[int]) -> int:
    n = len(nums)
    ans = 0
    # 四层循环，枚举四个不同的下标 i、j、k、l
    for i in range(n):
        for j in range(n):
            if j == i:               # 不能选到同一个元素
                continue
            for k in range(n):
                if k == i or k == j:
                    continue
                for l in range(n):
                    if l == i or l == j or l == k:
                        continue
                    # 检查乘积相等
                    if nums[i] * nums[j] == nums[k] * nums[l]:
                        ans += 1
    return ans
```

> **关键行解释**  
> - `if j == i: continue` … 以及后面的 `continue` 语句，确保四个下标互不相同（题目要求 a、b、c、d 都是不同的数）。  
> - `if nums[i] * nums[j] == nums[k] * nums[l]:` 这一步就是题目核心的等式检查。  

#### 复杂度  

- **时间复杂度**：`O(n⁴)`  
  - 四层循环，每层最多遍历 `n` 次，整体是 `n × n × n × n = n⁴`。  
  - “O(n⁴)” 可以理解为：如果 `n = 100`，程序大约要执行 `100⁴ = 100,000,000` 次比较，已经很慢了。  

- **空间复杂度**：`O(1)`  
  - 只用了几个计数变量，和 `n` 的大小无关。

### 2. 最优解  

#### 思路  

暴力解的瓶颈在 **四层循环**，每次都要重新算两次乘积。  
观察等式 `a * b = c * d`，我们其实只关心 **“两个数的乘积”**，而不在乎它们是怎么配对的。  

**关键观察**：  
- 如果把数组里所有 **两两组合**（不重复、顺序不计）产生的乘积都记下来，  
- 那么每一种相同的乘积 **p**，只要它出现了 `k` 次（即有 `k` 对不同的数的乘积等于 `p`），  
- 我们就可以从这 `k` 对里任选 **两对**，并且每对内部可以交换顺序，四元组的排列方式就会产生很多。  

**从这里出发的优化步骤**  

1. **遍历所有两数配对**（只需要两层循环），把每个乘积 `p` 的出现次数记在哈希表 `cnt` 中。  
   - 哈希表（Python 的 `dict`）可以类比成 **查字典**：  
     - “键”是乘积 `p`（相当于单词），  
     - “值”是出现次数 `k`（相当于页码）。  
2. 对于哈希表中的每一个键 `p`，设出现次数为 `k`，我们需要计算有多少 **有序四元组** 能由这 `k` 对产生。  
   - 先从 `k` 对中任选 **第一对**（有序），有 `2 * k` 种选择（每对内部可以换位）。  
   - 再从剩下的 `k‑1` 对中任选 **第二对**（同样有序），有 `2 * (k‑1)` 种选择。  
   - 两步相乘得到 `4 * k * (k‑1)`。  
3. 把所有键对应的 `4 * k * (k‑1)` 加起来，就是答案。  

**为什么这样正确？**  
- 每一次选择的两对数 **一定** 满足乘积相等（因为它们对应同一个键 `p`），  
- 通过把每对内部的顺序和两对的先后顺序都枚举进去，恰好覆盖了题目要求的 **有序四元组**。  

#### 代码（Python）  

```python
from typing import List
from collections import defaultdict

def tupleSameProduct(nums: List[int]) -> int:
    """
    最优解：利用哈希表统计每个乘积出现的配对数，
    再根据组合公式计算有序四元组数量。
    """
    product_cnt = defaultdict(int)          # product_cnt[p] = 有多少对数的乘积等于 p
    n = len(nums)

    # 只遍历 i < j，保证每对数只算一次（顺序不计）
    for i in range(n):
        for j in range(i + 1, n):
            prod = nums[i] * nums[j]        # 计算乘积
            product_cnt[prod] += 1          # 记录出现次数

    ans = 0
    # 对每个出现次数为 k 的乘积，计算 4 * k * (k-1) 并累加
    for k in product_cnt.values():
        if k > 1:                            # 至少要有两对才能组成四元组
            ans += 4 * k * (k - 1)

    return ans
```

> **关键行解释**  
> - `for j in range(i + 1, n):` 只遍历一次 unordered pair，避免重复计数（相当于只让每对学生排一次队）。  
> - `product_cnt[prod] += 1` 把乘积 `prod` 当作字典的 **键**，出现次数 `k` 当作 **值**。  
> - `ans += 4 * k * (k - 1)` 正是前面推导出的 “有序四元组数”。  

#### 复杂度  

- **时间复杂度**：`O(n²)`  
  - 两层循环遍历所有 unordered pair，数量是 `C(n,2) = n·(n‑1)/2`，量级是 `n²`。  
  - 与暴力的 `n⁴` 相比，下降了 **平方级**，即使 `n = 1000` 也只需要约 5×10⁵ 次乘法，完全可以接受。  

- **空间复杂度**：`O(m)`，其中 `m` 是不同乘积的种类数，最坏情况 `m = O(n²)`（每对数产生不同乘积），但仍然是 **线性** 级别的额外空间。

## 心得  

- **核心技巧**：利用 **哈希表统计配对乘积**，把 “两两相等” 的约束转化为 “同键出现多次”。  
- **适用场景**：  
  1. **两数乘积相等**（本题）  
  2. **两数和相等**（例如 “Count Good Pairs”）  
  3. **两数异或相等**（例如 “Number of Good Subarrays”）  
- **一句话总结**：先把所有 **二元组合** 的关键值（乘积/和/异或）计数，再用组合公式直接算出满足条件的有序元组数。

## 反思  

- **第一反应**：直接把四层循环写出来，先把能跑通的代码写好。  
- **最容易踩的坑**：  
  - **下标重复**：忘记排除同一个元素出现在同一对或不同对里，会导致错误计数。  
  - **乘积溢出**：在 Python 中整数自动扩容，通常不担心，但在语言限制的环境要注意 `int` 范围。  
  - **统计公式错误**：忘记把每对内部的顺序（2 种）和两对的先后顺序（2 种）都算进去，容易得到 `k*(k-1)` 而不是 `4*k*(k-1)`。  
- **下次类似题的第一步**：  
  - **先把所有二元组合的“特征值”**（和、积、异或等）**统计出来**，再看同一特征值出现了多少次，最后用组合数学把答案算出来。
