# #1636. **按频率递增排序数组** / Sort Array by Increasing Frequency

> 难度：简单 · 标签：Array、Hash Table、Sorting · [LeetCode 链接](https://leetcode.com/problems/sort-array-by-increasing-frequency/)

---

## 题目（英文原版）

**Description**

Given an array of integers nums, sort the array in increasing order based on the frequency of the values. If multiple values have the same frequency, sort them in decreasing order.
Return the sorted array.

**Examples**

**Example 1:**

```
Input: nums = [1,1,2,2,2,3]
Output: [3,1,1,2,2,2]
Explanation: '3' has a frequency of 1, '1' has a frequency of 2, and '2' has a frequency of 3.
```

**Example 2:**

```
Input: nums = [2,3,1,3,2]
Output: [1,3,3,2,2]
Explanation: '2' and '3' both have a frequency of 2, so they are sorted in decreasing order.
```

**Example 3:**

```
Input: nums = [-1,1,-6,4,5,-6,1,4,1]
Output: [5,-1,4,4,-6,-6,1,1,1]
```

**Constraints**

- 1 <= nums.length <= 100
- -100 <= nums[i] <= 100

## 题目（中文翻译）

给定一个整数数组 `nums`，请按照数值出现的频率（frequency）递增的顺序对数组进行排序。如果多个数值的频率相同，则按数值本身的递减顺序排序。返回排序后的数组。

**示例 1**  
输入: `nums = [1,1,2,2,2,3]`  
输出: `[3,1,1,2,2,2]`  
解释: “3”的频率为 1，“1”的频率为 2，“2”的频率为 3。

**示例 2**  
输入: `nums = [2,3,1,3,2]`  
输出: `[1,3,3,2,2]`  
解释: “2”和“3”的频率均为 2，因此按照递减顺序排列。

**示例 3**  
输入: `nums = [-1,1,-6,4,5,-6,1,4,1]`  
输出: `[5,-1,4,4,-6,-6,1,1,1]`

**约束条件**  
- `1 <= nums.length <= 100`  
- `-100 <= nums[i] <= 100`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**把每个数字的出现次数都算出来**，然后再根据这次数来排序。  
我们可以把“出现次数”想象成一本**字典**：  
- **key**（键）是数组里的某个数值，  
- **value**（值）是这个数在数组里出现了多少次。  

暴力实现的步骤：

1. 对数组里的每个元素 `x`，遍历整个数组去统计 `x` 出现了多少次（相当于在字典里查找或插入）。  
2. 把所有元素按照「出现次数从小到大」排好；如果出现次数相同，则「数值从大到小」排好。  
3. 把排好序的元素依次放回结果数组。

**为什么这样一定能得到正确答案**  
因为我们把每个数的出现次数完整记录下来，排序时严格按照题目要求的「频率升序、频率相同则数值降序」进行比较，所以最终顺序必然满足题意。

**时间/空间复杂度**  
- **时间复杂度**：统计每个数的出现次数需要 `O(n)`（遍历一次）× `n`（对每个数都要遍历一次）≈ `O(n²)`。  
  > 大白话：如果数组有 100 个数，最坏情况下要比较 100 × 100 = 10 000 次。  
- **空间复杂度**：需要一个哈希表（Python 的 `dict`）来存放每个不同数的频率，最坏情况下每个数都不相同，需要 `O(n)` 的额外空间。  
  > 大白话：如果数组里全是不一样的数，就要记 100 条「数‑频率」信息。

#### 代码（Python）

```python
def frequencySort_brute(nums):
    # 1. 统计每个数的出现次数（暴力 O(n^2)）
    freq = {}
    for x in nums:                     # 对每个元素 x
        count = 0
        for y in nums:                 # 再遍历一次整个数组统计 x 出现了多少次
            if y == x:
                count += 1
        freq[x] = count                # 把统计结果写进哈希表

    # 2. 按「频率升序、频率相同数值降序」排序
    # Python 的 sorted 可以接受一个 key 函数，这里我们返回一个二元组
    # 第一个元素是频率，第二个元素取负号实现「数值降序」
    sorted_nums = sorted(nums, key=lambda v: (freq[v], -v))

    return sorted_nums
```

#### 复杂度

- **时间复杂度**：`O(n²)` —— 两层循环每层都是 `n`，所以执行次数随 `n` 的平方增长。  
- **空间复杂度**：`O(n)` —— 需要一个字典来保存每个不同数的频率，最坏情况下字典大小和数组长度相同。

---

### 2. 最优解

#### 思路  

从暴力解可以看到 **瓶颈在于每次统计频率都要遍历整个数组**，这一步的时间是 `O(n²)`。  
我们可以把「统计频率」这件事一次性完成，而不是对每个数都重复遍历。  

**关键技巧：哈希表（字典）一次遍历统计所有频率**。  
- 想象把字典看成一本**查字典**的工具书：遇到一个数，就把它对应的「页码」——出现次数——加一。  
- 只需要 **一次** `for x in nums` 循环，就能把所有数的频率全部记下来，时间降到 `O(n)`。

有了频率表后，**排序**仍然是必须的。Python 的 `sorted` 可以接受自定义的排序键（`key`），我们把「频率」和「数值」一起放进键里：

- `key = (freq[x], -x)`  
  - 第一个分量 `freq[x]` 实现「频率升序」  
  - 第二个分量 `-x`（取负号）实现「数值降序」  

这样一次排序（`O(n log n)`）就能得到最终答案。

**为什么这就是最优**  
- 统计频率只需 `O(n)`，而不是 `O(n²)`。  
- 排序是不可避免的，因为我们要把元素重新排列成满足条件的顺序，排序的下界就是 `O(n log n)`（比较排序的理论下限）。  
- 因此整体时间复杂度为 `O(n log n)`，已经达到最优。

#### 代码（Python）

```python
def frequencySort(nums):
    # 1. 用哈希表一次遍历统计所有数的出现次数
    # 类比：字典就像一本“数‑出现次数”的小册子，看到一个数就把对应页码加一
    freq = {}
    for x in nums:
        freq[x] = freq.get(x, 0) + 1   # 若 x 不在字典里，默认频率 0，然后加一

    # 2. 根据「频率升序、频率相同数值降序」进行排序
    # sorted 会返回一个新列表，key 函数返回二元组 (freq, -value)
    # -freq 实现频率升序；-value 实现数值降序（因为 Python 默认升序排列）
    sorted_nums = sorted(nums, key=lambda v: (freq[v], -v))

    return sorted_nums
```

#### 复杂度

- **时间复杂度**：`O(n log n)`  
  - 统计频率一次遍历 `O(n)`，  
  - 排序 `O(n log n)`，两者相加仍是 `O(n log n)`。  
  - 大白话：如果数组有 1000 个数，排序大约需要 1000 × log₂1000 ≈ 10 000 次比较，比起 1 000 000 次的暴力法快很多。

- **空间复杂度**：`O(n)`  
  - 需要一个哈希表存放每个不同数的频率，最坏情况下字典大小和数组长度相同。  
  - 额外的排序过程会使用 `O(n)` 的临时空间（Python 的 `sorted` 会创建新列表），总体仍是线性空间。

## 心得

- **核心技巧**：**哈希表一次遍历统计频率 + 自定义排序键**。  
- **适用的题型**：  
  1. “根据出现次数排序” 类题（如 *Sort Characters By Frequency*）。  
  2. “统计出现次数后取前 K 大/小” 类题（如 *Top K Frequent Elements*）。  
  3. “出现次数相同按其他规则再排序” 的变形题。  
- **一句话总结**：先把「每个元素出现了多少次」记下来，再让排序器一次性完成「频率升序、频率相同数值降序」的工作。

## 反思

- **第一反应**：直接想统计每个数的出现次数，然后手动写双层循环去比较——这就是暴力思路。  
- **最容易踩的坑**：  
  - 忘记在频率相同的情况下要 **数值降序**，容易写成数值升序导致答案错误。  
  - 频率统计时如果直接使用 `list.count`，每次都会遍历一次列表，等价于暴力解，时间会爆炸。  
- **下次思路**：一看到「出现次数」这种统计需求，第一步就想到 **哈希表一次遍历**；如果还有「相同频率再比较」的要求，就准备 **自定义排序键**，把所有规则一次写进键函数里。
