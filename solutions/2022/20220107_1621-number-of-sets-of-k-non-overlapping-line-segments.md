# #1621. K 条不相交线段的集合数目 / Number of Sets of K Non-Overlapping Line Segments

> 难度：中等 · 标签：Math、Dynamic Programming、Combinatorics · [LeetCode 链接](https://leetcode.com/problems/number-of-sets-of-k-non-overlapping-line-segments/)

## 题目（英文原版）

**Description**

Given n points on a 1-D plane, where the ith point (from 0 to n-1) is at x = i, find the number of ways we can draw exactly k non-overlapping line segments such that each segment covers two or more points. The endpoints of each segment must have integral coordinates. The k line segments do not have to cover all n points, and they are allowed to share endpoints.
Return the number of ways we can draw k non-overlapping line segments. Since this number can be huge, return it modulo 109 + 7.

**Examples**

**Example 1:**

```
Input: n = 4, k = 2
Output: 5
Explanation: The two line segments are shown in red and blue.
The image above shows the 5 different ways {(0,2),(2,3)}, {(0,1),(1,3)}, {(0,1),(2,3)}, {(1,2),(2,3)}, {(0,1),(1,2)}.
```

**Example 2:**

```
Input: n = 3, k = 1
Output: 3
Explanation: The 3 ways are {(0,1)}, {(0,2)}, {(1,2)}.
```

**Example 3:**

```
Input: n = 30, k = 7
Output: 796297179
Explanation: The total number of possible ways to draw 7 line segments is 3796297200. Taking this number modulo 109 + 7 gives us 796297179.
```

**Constraints**

- 2 <= n <= 1000
- 1 <= k <= n-1

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

- **所有可能的线段**：在坐标 `0 … n‑1` 上，任意一条合法的线段必须满足  
  `left < right` 且两端都是整数坐标。  
  所以所有线段的集合可以看成「从 `n` 个点中任选两个不同的点并按左端点小于右端点排列」的集合。  
  这相当于 **组合** `C(n, 2)`，大约是 `n²/2` 条。

- **枚举 k 条线段**：把上面得到的 `≈ n²/2` 条线段全部列出来（可以用两层循环），再在这些线段里挑选恰好 `k` 条。  
  挑选的方式可以用 **组合数** `C(total_segments, k)` 来枚举（或者直接用 `itertools.combinations`）。

- **检查「不相交」**：挑出一组 `k` 条线段后，逐对检查是否有「内部交叉」——即两条线段的左端点和右端点的相对顺序是 `a.left < b.left < a.right < b.right`。  
  只要出现一次就说明这组不合法。

- **计数**：把所有合法的组合计数，最后对 `10⁹+7` 取模。

> **类比**：把所有线段想象成一本「字典」里的词条，`left` 是词条的「首字母」，`right` 是「尾字母」。  
> 暴力做法相当于把字典里的每个词都抄下来，随后挑出 `k` 本书，再逐本检查它们的「页码」是否会交叉——显然非常低效。

#### 代码（Python）

```python
from itertools import combinations

MOD = 10**9 + 7

def numberOfSets_bruteforce(n: int, k: int) -> int:
    # 1️⃣ 列出所有合法线段 (left, right)
    segments = [(l, r) for l in range(n) for r in range(l + 1, n)]

    ans = 0
    # 2️⃣ 枚举恰好 k 条线段的所有组合
    for combo in combinations(segments, k):
        ok = True
        # 3️⃣ 两两检查是否出现交叉
        for i in range(k):
            for j in range(i + 1, k):
                a, b = combo[i], combo[j]
                # a 与 b 交叉的条件（假设 a.left < b.left）
                if (a[0] < b[0] < a[1] < b[1]) or (b[0] < a[0] < b[1] < a[1]):
                    ok = False
                    break
            if not ok:
                break
        if ok:
            ans = (ans + 1) % MOD
    return ans
```

> 这段代码可以直接跑通，但只适用于 `n ≤ 10` 左右的极小规模，时间会指数级爆炸。

#### 复杂度

- **时间复杂度**：  
  - 列出所有线段需要 `O(n²)`。  
  - 再枚举 `C(n²/2, k)` 种组合，每种组合内部要做 `O(k²)` 的交叉检查。  
  - 整体是 **指数级**，在最坏情况下大约是 `O( (n²)^k )`，对 `n=1000` 完全不可行。  
  - 用大白话说，就是「先把所有可能的拼图块都摆出来，再把它们一块块地尝试组合」，根本不可能在合理时间内完成。

- **空间复杂度**：  
  - 保存所有线段需要 `O(n²)` 的列表。  
  - 其余只用常数级额外空间。

### 2. 最优解

#### 思路  

暴力解的瓶颈在 **「枚举所有线段组合」** 这一步。  
我们要把「枚举」变成「计数」——用动态规划（DP）直接算出有多少合法方案，而不把每一种方案显式列出来。

**核心观察**  

> 对于一条以点 `i‑1` 为右端点的线段，左端点可以是 `0 … i‑2` 中的任意一点。  
> 当左端点选为 `t` 时，**左边**（即点 `0 … t`）只能再放 `k‑1` 条不相交的线段，**右边**（点 `i … n‑1`）不受影响。  
> 因此，只要知道「前 `p` 个点能组成多少条线段」的答案，就能递推出更长区间的答案。

把「前 `p` 个点能组成 `j` 条线段」记作 `dp[p][j]`（`p` 表示已考虑的点数，**不包括** 点 `p` 本身，等价于只看坐标 `[0, p‑1]`）。

> **类比**：把点看成一本书的页码，`dp[p][j]` 表示「只看前 `p` 页，能画出 `j` 条不相交的线段」的方案数。  
> 当我们把第 `p` 页加入书中（相当于把点 `p‑1` 加进来），有两种可能：  
> 1. 不让它参与任何线段——方案数不变。  
> 2. 把它当作新线段的 **右端点**——左端点可以是任意更早的页 `t`，左边的 `t+1` 页必须已经形成 `j‑1` 条线段。

**递推公式**  

设 `pref[i][j] = Σ_{p=0}^{i} dp[p][j]` 为前缀和，方便快速求「所有可能的左端点」的贡献。

- **不使用第 `i` 个点**（即不让它成为任何线段的右端点）  
  `dp[i][j] ← dp[i‑1][j]`

- **让第 `i` 个点成为右端点**（前提是 `i ≥ 2`，因为线段至少要两个点）  
  左端点可以是 `0 … i‑2`，对应的左侧点数是 `t+1`（`t` 为左端点坐标）。  
  所有合法左侧方案数之和正好是 `pref[i‑1][j‑1] - dp[0][j‑1]`。  
  - 当 `j = 1` 时，`dp[0][0] = 1`，要减去它，避免把「空区间」算进来。  
  - 当 `j > 1` 时，`dp[0][j‑1] = 0`，减去 0 没影响。

  因此  
  `dp[i][j] ← dp[i][j] + (pref[i‑1][j‑1] - dp[0][j‑1])`

把两条转移合在一起：

```
dp[i][j] = dp[i-1][j]                           # 不使用点 i-1
          + (pref[i-1][j-1] - (1 if j==1 else 0))   # 让它成为右端点
```

**边界条件**

- `dp[0][0] = 1`：零个点、零条线段，唯一的空方案。  
- `dp[0][j>0] = 0`：没有点不可能画出正数条线段。  
- `dp[i][0] = 1`：任意 `i` 个点，画 0 条线段，只有一种方式（什么都不画）。

**前缀和的维护**

每算完一行 `dp[i][*]`，立刻更新对应的 `pref[i][*]`：

```
pref[i][j] = (pref[i-1][j] + dp[i][j]) % MOD
```

这样每个 `dp[i][j]` 的求值只需要 **O(1)** 时间，总体时间 `O(n·k)`，空间 `O(n·k)`（也可以滚动数组降到 `O(k)`，这里为方便阅读保留二维表）。

**正确性简述**

- **完整性**：任意合法的 `k` 条线段集合一定有一个「最右端点」`i-1`。把这条线段去掉后，左侧恰好是 `j-1` 条线段，右侧不受影响。递推正好遍历了所有可能的最右端点和对应的左端点。
- **不重叠**：因为递推只在「左侧」计数 `dp[t+1][j-1]`，而左侧的点集合与右侧（当前线段的内部）没有交集，天然保证不相交。共享端点在递推里是允许的，因为左侧可以使用点 `t`（左端点）本身，而右侧的线段从 `t` 开始。
- **覆盖所有情况**：若某个合法集合的最右端点是 `i-1`，递推一定会在计算 `dp[i][j]` 时把它计入（因为左端点遍历了所有 `t ≤ i-2`），所以没有遗漏。

#### 代码（Python）

```python
MOD = 10**9 + 7

def numberOfSets(n: int, k: int) -> int:
    """
    dp[i][j] : 用前 i 个点（坐标 0 .. i-1）恰好画出 j 条非重叠线段的方案数
    """
    # 初始化二维表，额外多一行 0..n，便于直接使用下标 i
    dp   = [[0] * (k + 1) for _ in range(n + 1)]
    pref = [[0] * (k + 1) for _ in range(n + 1)]

    dp[0][0] = 1                # 零点、零条线段
    for j in range(k + 1):
        pref[0][j] = dp[0][j]   # 前缀和的第一行

    for i in range(1, n + 1):          # i 表示「前 i 个点」，即坐标 0..i-1
        dp[i][0] = 1                    # 任意 i，画 0 条线段只有一种方式
        pref[i][0] = (pref[i-1][0] + dp[i][0]) % MOD

        for j in range(1, k + 1):
            # 1) 不使用第 i-1 个点作为右端点
            val = dp[i-1][j]

            # 2) 使用第 i-1 个点作为右端点
            #    所有可能的左端点对应的「左侧」方案数之和 = pref[i-1][j-1] - (1 if j==1 else 0)
            add = pref[i-1][j-1]
            if j == 1:                # 需要减去 dp[0][0] = 1，防止把「空左侧」算进去
                add = (add - 1) % MOD
            val = (val + add) % MOD

            dp[i][j] = val
            pref[i][j] = (pref[i-1][j] + dp[i][j]) % MOD

    return dp[n][k] % MOD
```

**代码要点说明（中文注释）**

| 行号 | 解释 |
|------|------|
| 4‑5  | `dp[i][j]` 的定义：前 `i` 个点恰好画 `j` 条线段的方案数。 |
| 9‑10 | 初始条件：`dp[0][0]=1`（空集合），其余为 0。 |
| 13‑15| `pref` 用来存前缀和，`pref[i][j] = Σ_{p=0}^{i} dp[p][j]`，便于 O(1) 求和。 |
| 18‑22| 对每个 `i`（即考虑到点 `i‑1`）先填 `j=0` 的情况——画 0 条线段只有一种。 |
| 24‑32| 主循环：先把「不使用第 i‑1 点」的方案 `dp[i‑1][j]` 复制过来。 |
| 28‑31| 再把「使用第 i‑1 点做右端点」的贡献加入。`pref[i‑1][j‑1]` 累计了所有左端点的方案数；当 `j==1` 时需要减去 `dp[0][0]=1`，因为左侧不能是「空区间」而应该是「至少包含左端点本身」的区间。 |
| 34‑35| 更新 `dp[i][j]` 与对应的前缀和 `pref[i][j]`。 |
| 38   | 最终答案是 `dp[n][k]`，即使用全部 `n` 个点得到 `k` 条线段的方案数。 |

#### 复杂度

- **时间复杂度**：外层遍历 `i = 1 … n`，内层遍历 `j = 1 … k`，每个状态只做 O(1) 的加法/取模 → **O(n·k)**。  
  对于最坏的 `n = 1000, k = 999`，约为 `10⁶` 次运算，毫秒级可完成。

- **空间复杂度**：存 `dp` 与 `pref` 各 ` (n+1)·(k+1)` 个整数 → **O(n·k)**。  
  若需要进一步压缩，可把 `dp` 与 `pref` 改为两行滚动数组，空间降为 `O(k)`，但这里保留二维表方便理解。

## 心得

- **核心技巧**：把「枚举所有线段」转化为「按最右端点递推」的动态规划。  
- **适用题型**  
  1. 需要统计 **不相交区间/线段** 的组合数（如「不同区间的最大数量」类问题）。  
  2. 计数 **满足某种顺序约束** 的子结构（例如「不相交子数组」或「不相交子序列」）。  
- **一句话总结**：**把「右端点」当成状态的推进器，利用前缀和把所有左端点的贡献一次性算完**。

## 反思

- **第一反应**：看到「非重叠线段」和「点坐标是整数」就想到「组合」或「动态规划」；最先想到的是「暴力枚举」验证可行性，随后寻找去枚举的计数公式。  
- **最容易踩的坑**  
  - 忘记 **线段长度必须 ≥ 2**（左端点不能等于右端点），导致在递推时把 `i‑1` 当作左端点计入。  
  - **共享端点** 允许但「内部交叉」不允许，需要在递推中正确处理——左侧可以使用左端点本身。  
  - 前缀和的减法忘记 `j==1` 时要减去 `dp[0][0]`，会多算出 `i‑1` 条长度为 0 的「虚线段」。  
- **下次思路**：遇到「计数不相交区间」时，第一步立刻问自己「能否把区间的最右端点当作 DP 的时间轴？」——如果能，就尝试写出 `dp[i] = dp[i‑1] + Σ dp[left]` 的形式，再用前缀和把求和降到 O(1)。这样就能快速得到 O(n·k) 的解法。
