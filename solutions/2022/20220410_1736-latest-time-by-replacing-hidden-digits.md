# #1736. 通过替换隐藏数字得到的最晚时间 / Latest Time by Replacing Hidden Digits

> 难度：简单 · 标签：String、Greedy · [LeetCode 链接](https://leetcode.com/problems/latest-time-by-replacing-hidden-digits/)

---

## 题目（英文原版）

**Description**

You are given a string time in the form of  hh:mm, where some of the digits in the string are hidden (represented by ?).
The valid times are those inclusively between 00:00 and 23:59.
Return the latest valid time you can get from time by replacing the hidden digits.

**Examples**

**Example 1:**

```
Input: time = "2?:?0"
Output: "23:50"
Explanation: The latest hour beginning with the digit '2' is 23 and the latest minute ending with the digit '0' is 50.
```

**Example 2:**

```
Input: time = "0?:3?"
Output: "09:39"
```

**Example 3:**

```
Input: time = "1?:22"
Output: "19:22"
```

**Constraints**

- time is in the format hh:mm.
- It is guaranteed that you can produce a valid time from the given string.

输出: `"09:39"`

**示例 3**  
输入: `time = "1?:22"`

**约束条件**  
- `time` 的格式固定为 `hh:mm`。  
- 题目保证一定可以从给定的字符串构造出一个有效时间。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  
最直接的办法是把所有合法的时间枚举一遍，然后挑出能够和输入 `time` 对得上的最大时间。

- **枚举范围**  
  - 小时只能是 `00~23`（共 24 种），  
  - 分钟只能是 `00~59`（共 60 种）。  
  把这两部分组合起来，一共有 `24 × 60 = 1440` 种可能的完整时间，数量非常小，遍历一次毫不费力。

- **匹配规则**  
  把每一种候选时间写成 `"hh:mm"` 的字符串，然后和原始字符串逐字符比较。  
  - 若原字符是 `'?'`，说明可以随意匹配。  
  - 若原字符是数字，则必须完全相同。  
  只要全部字符都匹配，就说明这是一种可行的填法。

- **为什么一定能找到答案**  
  题目保证至少有一种合法的填法，所以在遍历完所有 1440 种时间后，一定会找到至少一个匹配的时间。我们只保留最大的那个，即为所求的“最新合法时间”。

- **时间/空间复杂度的大白话解释**  
  - **时间复杂度** `O(24·60) = O(1)`：虽然写成 `O(1440)`，但这是一条常数——不随输入长度增长。想象你要检查 1440 张彩票，每张只看几秒，整体耗时是固定的。  
  - **空间复杂度** `O(1)`：只用几个整数保存当前最大时间，不会随输入大小而增长。

#### 代码（Python）

```python
def latest_time_brute(time: str) -> str:
    # 保存目前找到的最大合法时间，初始设为最小的 "00:00"
    best = "00:00"

    # 枚举所有可能的小时（00~23）
    for h in range(24):
        hour = f"{h:02d}"          # 把整数 0~23 转成两位字符串，例如 5 -> "05"
        # 枚举所有可能的分钟（00~59）
        for m in range(60):
            minute = f"{m:02d}"    # 同理，0~59 转成两位字符串
            candidate = f"{hour}:{minute}"   # 完整的候选时间字符串

            # 检查 candidate 是否能匹配原始的 time（'?' 可以匹配任何字符）
            ok = True
            for c1, c2 in zip(candidate, time):
                if c2 != '?' and c1 != c2:   # 原字符不是 '?' 且不相等，则不匹配
                    ok = False
                    break
            if ok and candidate > best:      # 只保留更大的合法时间
                best = candidate

    return best
```

#### 复杂度

- **时间复杂度**：`O(1440)`，即 `O(1)`。遍历 1440 种时间，每种只做常数次字符比较。
- **空间复杂度**：`O(1)`。只用了几个临时变量，和输入长度无关。

### 2. 最优解

#### 思路  
暴力解已经足够快，但我们可以直接利用“贪心”思想，一位一位地把 `'?'` 替换成**尽可能大的合法数字**，这样一次遍历就能得到答案。

关键在于每个位置的合法取值范围：

| 位置 | 示例字符 | 合法最大数字 | 说明 |
|------|----------|--------------|------|
| `h1`（第 1 位，小时十位） | `time[0]` | `2`（若 `time[0]` 为 `'?'`） | 小时最高是 23，十位只能是 0、1、2。 |
| `h2`（第 2 位，小时个位） | `time[1]` | <ul><li>若 `h1` 已经是 `'2'`，则最大只能是 `3`（因为 23 是上限）</li><li>否则最大是 `9`</li></ul> | 受前一位的约束。 |
| `m1`（第 4 位，分钟十位） | `time[3]` | `5`（因为分钟最高是 59） | 十位只能是 0~5。 |
| `m2`（第 5 位，分钟个位） | `time[4]` | `9` | 没有额外约束，最大是 9。 |

基于上述规则，只要按顺序检查四个 `'?'` 并填入对应的最大值，就能得到**最新**的合法时间。

#### 步骤细化（从左到右）  

1. **处理小时十位 `h1`**  
   - 若是 `'?'`，直接填 `2`（因为 2 是最大的合法十位）。  
   - 若已经是数字，则保持不变。

2. **处理小时个位 `h2`**  
   - 若是 `'?'`，看 `h1` 的实际值：  
     - 若 `h1 == '2'`，只能填 `3`（否则会超过 23）。  
     - 否则填 `9`（可以随意到 9，因为十位小于 2 时，最大小时是 19、09 等）。  

3. **处理分钟十位 `m1`**  
   - 若是 `'?'`，填 `5`（因为分钟最高 59，十位最大 5）。

4. **处理分钟个位 `m2`**  
   - 若是 `'?'`，填 `9`（没有额外限制）。

这样得到的时间一定合法，而且在每一步都把当前位尽量放大，后面的位再也无法让整体时间更大了——这就是贪心的核心思想。

#### 代码（Python）

```python
def latest_time_greedy(time: str) -> str:
    # 将字符串转成列表，方便原地修改字符
    t = list(time)

    # 1️⃣ 处理小时十位 (index 0)
    if t[0] == '?':
        t[0] = '2'                     # 最大可取 2

    # 2️⃣ 处理小时个位 (index 1)
    if t[1] == '?':
        if t[0] == '2':                # 十位已经是 2，小时上限是 23
            t[1] = '3'
        else:                          # 十位是 0 或 1，个位可以最大到 9
            t[1] = '9'

    # 3️⃣ 处理分钟十位 (index 3)
    if t[3] == '?':
        t[3] = '5'                     # 最大可取 5

    # 4️⃣ 处理分钟个位 (index 4)
    if t[4] == '?':
        t[4] = '9'                     # 最大可取 9

    return "".join(t)
```

#### 复杂度

- **时间复杂度**：`O(1)`（常数时间）。我们只检查并修改最多 5 个字符，和输入长度（固定为 5）无关。  
- **空间复杂度**：`O(1)`。只用了一个长度为 5 的列表来存放字符，空间开销固定。

相比暴力枚举的 `1440` 次循环，贪心解只用了几步算术判断，运行更快且代码更简洁。

## 心得

- **核心技巧**：**贪心**——在每一步都选择当前能做的最大合法选择，整体就能得到全局最优（这里是最新的时间）。  
- **适用的题型**  
  1. “填空”类的最大/最小化问题（如 “Maximum Number After Replacing Digits”）。  
  2. 需要在约束范围内尽可能放大的字符串/数字（如 “Maximum Binary Number After Flip”）。  
  3. 只要每个位置的合法取值只依赖于已经决定的前面几位，贪心往往能直接给出答案。  
- **一句话总结解题钥匙**：**把每个 `'?'` 填成在保持合法的前提下最大的数字**。

## 反思

- **第一反应**：先想到枚举所有可能的时间，因为数字范围很小，直接穷举最安全。  
- **最容易踩的坑**  
  - 忘记 **小时个位** 受 **小时十位** 的限制（比如十位是 `2` 时个位只能到 `3`）。  
  - 把 `:` 当成普通字符处理时忘记跳过，导致索引错误。  
  - 对分钟十位忘记最大只能是 `5`（否则会出现 `6x` 分钟非法）。  
- **下次类似题的第一步**：先**分析每一位的合法取值范围**，看是否可以直接用贪心一次性填完；如果取值相互依赖且范围大，再考虑枚举或 DP。
