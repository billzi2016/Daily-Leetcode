# #1702. **变更后的最大二进制字符串** / Maximum Binary String After Change

> 难度：中等 · 标签：String、Greedy · [LeetCode 链接](https://leetcode.com/problems/maximum-binary-string-after-change/)

---

## 题目（英文原版）

**Description**

You are given a binary string binary consisting of only 0's or 1's. You can apply each of the following operations any number of times:
Return the maximum binary string you can obtain after any number of operations. Binary string x is greater than binary string y if x's decimal representation is greater than y's decimal representation.

**Examples**

**Example 1:**

```
Input: binary = "000110"
Output: "111011"
Explanation: A valid transformation sequence can be:
"000110" -> "000101" 
"000101" -> "100101" 
"100101" -> "110101" 
"110101" -> "110011" 
"110011" -> "111011"
```

**Example 2:**

```
Input: binary = "01"
Output: "01"
Explanation: "01" cannot be transformed any further.
```

**Constraints**

- 1 <= binary.length <= 105
- binary consist of '0' and '1'.

## 题目（中文翻译）

给定一个仅由 `0` 与 `1` 组成的二进制字符串 `binary`。你可以任意次数（包括零次）执行下面的两种操作：

1. 将任意出现的子串 `"00"` 替换为 `"10"`。  
2. 将任意出现的子串 `"01"` 替换为 `"11"`。

返回在执行任意次数上述操作后能够得到的 **最大二进制字符串**。二进制字符串 `x` 大于二进制字符串 `y` 当且仅当 `x` 对应的十进制表示大于 `y` 的十进制表示。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**不停地在字符串上搜索可以进行的操作**，把能改的地方都改一次，直到再也找不到可以改的子串为止。  

- **数据结构**：只需要一个普通的 Python `list`（把字符串转成列表方便原地修改）。可以把它想象成一排 **磁带**，我们在磁带上左手抓住两个相邻的磁块，如果符合规则就把它们换位。  
- **为什么正确**：因为题目说“可以任意次数地使用下面的两种操作”，只要我们把**所有**能改的地方都改完，得到的字符串一定是**一种**可达的结果。  
- **复杂度分析**：  
  - 每一次遍历我们都要检查相邻的两个字符，看是否是 `"01"`（可以变成 `"10"`）或 `"00"`（可以变成 `"01"`）。  
  - 最坏情况下，字符串长度为 `n`，一次遍历需要 `O(n)` 时间。  
  - 但因为一次改动后可能会出现新的可改子串，最坏会需要 **`O(n)` 次遍历**（每次至少把一个 `0` 往右移动一位），于是总时间是 `O(n²)`。  
  - 只用了原来的字符数组，没有额外的容器，空间是 `O(1)`（不计输入本身）。

> **大白话**：`O(n²)` 就像在 1000 本书里找字母表顺序的错误，每找一次要重新读整本书，时间会变得很慢。

#### 代码（Python）

```python
def maximumBinaryString_bruteforce(binary: str) -> str:
    # 把字符串转成列表，方便原地修改
    s = list(binary)
    n = len(s)

    # 是否还有可以进行的操作
    changed = True
    while changed:
        changed = False
        i = 0
        while i < n - 1:
            # 规则 1： "01" -> "10"   （把 0 向右推一格）
            if s[i] == '0' and s[i + 1] == '1':
                s[i], s[i + 1] = '1', '0'
                changed = True
                i += 2          # 已经处理了 i、i+1 两位，直接跳过
                continue
            # 规则 2： "00" -> "01"   （把左边的 0 变成 1，右边的 0 变成 1）
            if s[i] == '0' and s[i + 1] == '0':
                s[i + 1] = '1'   # 把右边的 0 变成 1，等价于 "00" -> "01"
                changed = True
                i += 1
                continue
            i += 1

    return ''.join(s)
```

#### 复杂度

- **时间复杂度**：`O(n²)`  
  - 每次遍历 `O(n)`，最坏需要 `O(n)` 次遍历才能把所有 `0` 推到最右侧。  
- **空间复杂度**：`O(1)`（只用了常数级的额外变量，原地修改列表）。

### 2. 最优解

#### 思路  

从暴力解可以看到 **两个操作的共同点**：

| 操作 | 前后字符 | 产生的效果 |
|------|----------|------------|
| 1    | `"01"`   | 把 `0` 向右移动一格 |
| 2    | `"00"`   | 把左边的 `0` 变成 `1`，相当于 **消掉一个 `0`**，同时把右边的 `0` 向右移动一格 |

> **关键观察**：不管怎样，**`0` 只会向右移动**，而且每出现一次 `"00"` 就会把一个 `0` 永久变成 `1`。  
> 于是，经过足够多次操作后，**整个串中至多只会剩下一个 `0`**（所有多余的 `0` 都会被 `"00"` → `"01"` “吃掉”）。

**目标**：让得到的二进制数最大。二进制数大小由左边的字符决定，左边越多 `1` 越大。  
因此：

1. **尽可能把 `0` 推到最右边**——左边全是 `1`。  
2. 由于只能留下 **一个 `0`**，我们把它放在**最靠左**还能放的位置——也就是在 **所有可以保证是 `1` 的位置** 之后。  
3. 剩下的字符自然全是 `1`（因为所有被 `"00"` 吃掉的 `0` 都已经变成了 `1`）。

> **如何算出 “可以保证是 `1` 的位置”**？  
> 设原串长度为 `n`，原来有 `z` 个 `0`。  
> - `"00"` → `"01"` 能把 `z‑1` 个 `0` 变成 `1`（只留下一个 `0`）。  
> - 这 `z‑1` 个新产生的 `1` 会出现在 **右侧**，但我们只关心左侧的 `1`。  
> - 原来已经是 `1` 的字符数量是 `n‑z`，再加上新产生的 `z‑2`（因为最右边的那个 `0` 必须保留下来），左侧可以排成 `n‑z+1` 个连续的 `1`。  

于是，**最终答案的结构**是：

```
[ 前导 1 的个数 = n - z + 1 ] + '0' + [ 后缀 1 的个数 = z - 2 ]
```

特殊情况：

- `z == 0` → 本来就是全 `1`，直接返回。  
- `z == 1` → 只能保留这唯一的 `0`，已经是最大形式，直接返回原串。  

> **为什么 `z‑2` 会出现在后缀**？  
> 除了左侧的 `n‑z+1` 个 `1`，其余的字符只能是 **一个 `0`** 再加上 **剩下的 `1`**，这些 `1` 的数量恰好是 `z‑2`（因为总长度不变）。

#### 代码（Python）

```python
def maximumBinaryString(binary: str) -> str:
    n = len(binary)
    zeros = binary.count('0')          # 统计原串中 0 的个数

    # 0 的数量 <= 1 时已经是最大形式，直接返回
    if zeros <= 1:
        return binary

    # 前导 1 的个数 = n - zeros + 1
    prefix_ones = '1' * (n - zeros + 1)
    # 中间唯一的 0
    middle_zero = '0'
    # 后缀 1 的个数 = zeros - 2
    suffix_ones = '1' * (zeros - 2)

    return prefix_ones + middle_zero + suffix_ones
```

> **代码注释**  
> - `binary.count('0')` 相当于在字典里查 “0” 出现了多少次。  
> - 字符串乘法 `'1' * k` 就是把 `'1'` 连写 `k` 次，像把 `k` 张 “1 卡” 排成一行。

#### 复杂度

- **时间复杂度**：`O(n)`  
  - 只遍历一次字符串统计 `0` 的个数，随后几次字符串拼接都是 `O(n)`（总长度不超过 `n`）。  
  - 与暴力解的 `O(n²)` 相比，速度提升了一个量级——从“每次都要重新读整本书”变成“一次就能读完”。

- **空间复杂度**：`O(n)`  
  - 需要构造输出字符串，长度正好是 `n`。额外的辅助变量只有常数级，属于线性空间。

## 心得

- **核心技巧**：**贪心 + 统计**。通过观察两种操作只会把 `0` 向右移动并且可以把多余的 `0` 消掉，得出“最多只剩一个 `0`”的结论，然后用零的个数直接写出答案的结构。  
- **适用题型**：  
  1. **只能让字符向一侧移动** 的字符串题（如 “把所有 `a` 移到左边”）。  
  2. **可以把某类字符合并/消除** 的贪心题（如 “把相邻相同字符合并为一个”）。  
- **一句话总结**：**把所有 `0` 推到最右，剩下的唯一 `0` 前面尽量塞满 `1`，答案就出来了**。

## 反思

- **第一反应**：看到两个可以无限次使用的局部替换，立刻想到**模拟**，于是写了暴力循环。  
- **最容易踩的坑**：  
  - 忽略了 `"00" → "01"` 其实是**消掉一个 `0`**，导致误以为最终可能会有多个 `0`。  
  - 边界情况 `zeros == 0` 或 `zeros == 1` 必须单独处理，否则公式会产生负数次数的字符串乘法。  
- **下次思路**：遇到类似“字符只能单向移动且可以合并”的题目，第一步先**思考最终状态的极限**（如“最多剩几个特定字符”），再用**计数**直接写出答案，避免不必要的模拟。
