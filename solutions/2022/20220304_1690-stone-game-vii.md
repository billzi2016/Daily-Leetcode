## 题目（英文原版）

**Description**

Alice and Bob take turns playing a game, with Alice starting first.
There are n stones arranged in a row. On each player's turn, they can remove either the leftmost stone or the rightmost stone from the row and receive points equal to the sum of the remaining stones' values in the row. The winner is the one with the higher score when there are no stones left to remove.
Bob found that he will always lose this game (poor Bob, he always loses), so he decided to minimize the score's difference. Alice's goal is to maximize the difference in the score.
Given an array of integers stones where stones[i] represents the value of the ith stone from the left, return the difference in Alice and Bob's score if they both play optimally.

**Examples**

**Example 1:**

```
Input: stones = [5,3,1,4,2]
Output: 6
Explanation: 
- Alice removes 2 and gets 5 + 3 + 1 + 4 = 13 points. Alice = 13, Bob = 0, stones = [5,3,1,4].
- Bob removes 5 and gets 3 + 1 + 4 = 8 points. Alice = 13, Bob = 8, stones = [3,1,4].
- Alice removes 3 and gets 1 + 4 = 5 points. Alice = 18, Bob = 8, stones = [1,4].
- Bob removes 1 and gets 4 points. Alice = 18, Bob = 12, stones = [4].
- Alice removes 4 and gets 0 points. Alice = 18, Bob = 12, stones = [].
The score difference is 18 - 12 = 6.
```

**Example 2:**

```
Input: stones = [7,90,5,1,100,10,10,2]
Output: 122
```

**Constraints**

- n == stones.length
- 2 <= n <= 1000
- 1 <= stones[i] <= 1000

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

这是一种**两人零和博弈**：每一次轮到某人时，他只能从左端或右端拿走一颗石子，随后得到的分数是**剩余石子价值的总和**。  
最直接的想法是把所有可能的取法都枚举一遍，模拟每一步的得分，最后比较两个人的总分差。

> **数据结构**：我们只需要一个数组 `stones` 来保存当前剩余的石子。  
> 类比：把石子排成一排的游戏就像是 **一根绳子**，每次只能从左边或右边剪掉一段。

**暴力递归**的核心是：  
- 当前局面用区间 `[l, r]` 表示（左端下标 `l`，右端下标 `r`）。  
- 轮到谁，就尝试两种选择：  
  1. 去掉左端 `stones[l]`，本轮得分 = `sum(stones[l+1 … r])`。  
  2. 去掉右端 `stones[r]`，本轮得分 = `sum(stones[l … r-1])`。  
- 对手随后在剩下的区间继续玩，双方都假设“最优”。  
- 递归返回 **当前玩家相对对手的最大分差**（`score_current - score_opponent`），这样最终的答案就是 `dp(0, n-1)`。

为什么这样能得到正确答案？  
因为每一步都枚举了**全部合法的行动**，并且在子问题中递归地假设对手也会采取使自己分差最大的策略。这样符合**极大极小原理**（Minimax），保证得到最优解。

**时间/空间复杂度**  
- 递归的状态由 `(l, r)` 两个下标唯一决定，最多有 `n·n/2 = O(n²)` 种不同区间。若每次都重新遍历求和，时间会是 `O(n³)`（因为每层递归里要 `O(n)` 求和）。  
- 递归深度最坏是 `n`，需要 `O(n)` 的调用栈空间。  

> **大白话**：  
> - `O(n²)` 就像“平方级”，如果 `n=1000`，大约是 1 000 000 次操作，电脑能轻松搞定。  
> - `O(n³)` 则是“立方级”，`1000³ = 10⁹`，会明显卡顿。

#### 代码（Python）

```python
from functools import lru_cache
from itertools import accumulate

def stoneGameVII_bruteforce(stones):
    """
    暴力递归解法（仅用于说明思路，实际会超时）
    """
    n = len(stones)
    # 前缀和，方便 O(1) 求任意区间和
    pref = [0] + list(accumulate(stones))

    # 区间和 sum(stones[l..r]) = pref[r+1] - pref[l]
    def range_sum(l, r):
        return pref[r + 1] - pref[l]

    @lru_cache(None)               # 记忆化搜索，避免重复计算相同区间
    def dp(l, r):
        # 区间为空时，没有人可以得分，分差为 0
        if l > r:
            return 0
        # 只剩一颗石子时，拿走后没有剩余石子，得分为 0
        if l == r:
            return 0

        # 1. 移除左端石子，得到的分数是剩余区间的和
        remove_left = range_sum(l + 1, r) - dp(l + 1, r)
        # 2. 移除右端石子，得到的分数是剩余区间的和
        remove_right = range_sum(l, r - 1) - dp(l, r - 1)

        # 当前玩家想让自己的分差最大
        return max(remove_left, remove_right)

    return dp(0, n - 1)
```

#### 复杂度

- **时间复杂度**：`O(n³)`（每个区间 `O(1)` 求和，但递归调用有 `O(n²)` 种状态，若不做记忆化则会出现指数级爆炸）。  
- **空间复杂度**：`O(n²)` 用于缓存 `dp(l,r)` 的结果，外加递归栈 `O(n)`。

### 2. 最优解

#### 思路  

从暴力解可以看到：

1. **状态**：只需要当前剩余区间的左右端点 `(l, r)`，不需要记录已经得了多少分。  
2. **转移**：在区间 `[l, r]`，玩家可以拿走左端或右端，得到的分数是 **剩余区间的总和**，即 `sum[l+1..r]` 或 `sum[l..r-1]`。随后轮到对手在更小的区间继续游戏。  

暴力解的瓶颈在 **每次递归都要遍历求区间和**（即使用了前缀和也是 `O(1)`，但递归调用次数仍是 `O(n²)`，而且没有利用**子问题的最优子结构**来直接算出答案）。  
其实我们已经把 **“子问题最优解”** 存在 `dp[l][r]` 中了，只需要把递推公式写成**自底向上**的动态规划（DP），就可以在 `O(n²)` 时间内完成。

**核心公式**（记 `total[l][r]` 为区间 `[l,r]` 的所有石子之和）：

```
dp[l][r] = max( total[l+1][r] - dp[l+1][r] ,   # 拿走左端
                total[l][r-1] - dp[l][r-1] )   # 拿走右端
```

解释：

- 当玩家拿走左端 `stones[l]` 时，**本轮得分** = `total[l+1][r]`（因为剩下的石子是 `[l+1, r]`）。  
- 接下来轮到对手，他在区间 `[l+1, r]` 上的 **最优分差** 为 `dp[l+1][r]`（从对手视角看，他的得分减去我们的得分）。  
- 因此 **我们** 在这一步的净收益 = `本轮得分 - 对手的最优分差` = `total[l+1][r] - dp[l+1][r]`。  
- 同理拿走右端得到的净收益是 `total[l][r-1] - dp[l][r-1]`。  
- 我们会挑选两者中更大的那个，使自己的分差最大。

**如何实现**：

1. 先算出前缀和 `pref`，可以在 `O(1)` 取任意区间和。  
2. 建立二维数组 `dp`，大小 `n × n`，全部初始化为 0（因为 `l==r` 时分差必为 0）。  
3. 按照 **区间长度从小到大** 填表。长度为 `len=2` 时直接根据公式算出；随后逐渐扩大到 `len=n`。  
4. 最终答案即 `dp[0][n-1]`（整个数组的最优分差）。

> **类比**：把 `dp[l][r]` 想成“一段路程的净收益”。我们从最短的路（两个相邻的石子）开始算起，一步步往更长的路扩展，像盖楼一样把每层的收益累加起来。

#### 代码（Python）

```python
def stoneGameVII(stones):
    """
    动态规划（自底向上）解法，时间 O(n²)，空间 O(n²)
    """
    n = len(stones)
    # 前缀和，pref[i] = stones[0] + ... + stones[i-1]
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + stones[i]

    # 区间和函数，O(1)
    def range_sum(l, r):
        return pref[r + 1] - pref[l]

    # dp[l][r] 表示在区间 [l, r]（两端都包含）上，**当前玩家**相对对手的最大分差
    dp = [[0] * n for _ in range(n)]

    # 按区间长度从小到大枚举
    for length in range(2, n + 1):          # 最小长度 2，因为长度 1 时分差必为 0
        for l in range(0, n - length + 1):
            r = l + length - 1
            # 拿左端：剩余区间是 [l+1, r]，其和为 range_sum(l+1, r)
            take_left = range_sum(l + 1, r) - dp[l + 1][r]
            # 拿右端：剩余区间是 [l, r-1]，其和为 range_sum(l, r-1)
            take_right = range_sum(l, r - 1) - dp[l][r - 1]
            dp[l][r] = max(take_left, take_right)

    # 整个数组的最优分差即答案
    return dp[0][n - 1]
```

#### 复杂度

- **时间复杂度**：`O(n²)`。  
  - 外层遍历区间长度 `1 … n`（共 `n` 次），内层遍历所有起点 `l`（每层最多 `n` 次），每次只做 `O(1)` 的计算（两次区间和 + 两个已知 `dp`），因此总体是平方级。  
  - 与暴力的 `O(n³)` 相比，快了大约 **n 倍**，在 `n ≤ 1000` 的限制下轻松通过。

- **空间复杂度**：`O(n²)` 用于存 `dp` 表（`n×n` 的二维数组），再加 `O(n)` 的前缀和。  
  - 若想进一步压缩空间，可只保留上一长度的行/列（因为递推只依赖 `dp[l+1][r]` 与 `dp[l][r-1]`），但对本题而言 `O(n²)` 已经足够。

## 心得

- **核心技巧**：把“每一步得分 = 剩余石子之和”转化为“区间和 - 子问题最优分差”，进而使用**区间 DP**（动态规划）求解。  
- **适用的题型**：  
  1. **Stone Game 系列**（如 Stone Game I、II、III、V、VI），都是两人轮流取端点或子数组的博弈问题。  
  2. **最优游戏策略**（如 Predict the Winner、Deque Game），需要用 `dp[l][r] = max(pick_left - dp[l+1][r], pick_right - dp[l][r-1])` 的思路。  
  3. **区间最优子结构**（如 Burst Balloons、Remove Boxes），同样利用子区间的最优解来构造更大区间的答案。  
- **一句话总结**：**把每一步的得分视为“剩余和”，用“当前分差 = 本轮得分 - 对手最优分差”递推，整个游戏转化为区间 DP。**

## 反思

- **第一反应**：看到“左或右取石子”，立刻想到**双指针**或**递归枚举**，于是写了暴力递归。  
- **最容易踩的坑**：  
  - 忘记 **“本轮得分是剩余石子之和”**，而误以为是拿走的石子本身的价值。  
  - 在递归/DP 中使用 **错误的状态定义**（比如把已经得到的分数累加进去），导致无法直接比较双方的差值。  
  - 边界条件：当区间只剩一颗石子时，得分为 0，必须显式返回 0，否则会出现负数或索引错误。  
- **下次思路**：遇到类似“轮流取端点、得分与剩余有关”的博弈题，第一步就构造 **`dp[l][r]` 表示当前玩家相对对手的最大分差**，并写出 **`total - dp`** 的递推式，再决定是自顶向下记忆化还是自底向上填表。这样可以直接跳到最优解的框架，避免不必要的枚举。
