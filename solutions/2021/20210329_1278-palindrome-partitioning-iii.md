# #1278. 回文划分 III / Palindrome Partitioning III

## 题目（英文原版）

**Description**

You are given a string s containing lowercase letters and an integer k. You need to :
Return the minimal number of characters that you need to change to divide the string.

**Examples**

**Example 1:**

```
Input: s = "abc", k = 2
Output: 1
Explanation: You can split the string into "ab" and "c", and change 1 character in "ab" to make it palindrome.
```

**Example 2:**

```
Input: s = "aabbc", k = 3
Output: 0
Explanation: You can split the string into "aa", "bb" and "c", all of them are palindrome.
```

**Example 3:**

```
Input: s = "leetcode", k = 8
Output: 0
```

**Constraints**

- 1 <= k <= s.length <= 100.
- s only contains lowercase English letters.

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是 **把所有可能的切分方式枚举一遍**，然后对每一种切分，统计把每段子串改成回文需要改动的字符数，最后取最小值。

- **枚举切分**：把字符串 `s` 看成一根绳子，在绳子上挑选 `k‑1` 个位置插入刀子，把它分成 `k` 段。  
- **统计改动**：对每一段子串，用两头向中间走的指针比较字符，如果不相同就需要改动其中一个字符，改动次数即为这段子串距离回文的距离。  
- **取最小**：把所有切分方案的改动次数求最小，即为答案。

> **类比**：把 `s` 当成一本书的连续页码，`k‑1` 把书签可以插在任意页之间把书分成 `k` 章节。我们要找一种插书签的方法，使得每章节只需要最少的文字修改就能成为“回文章节”。

**为什么能得到正确答案**：只要遍历了**所有**合法的切分方式，就一定会包含最优的那一种。对每一种切分我们都计算了把每段变成回文的最少改动数，所以最小值必然是全局最优。

**复杂度分析（大白话）**  
- 枚举切分相当于在长度为 `n` 的序列里选 `k‑1` 个位置，组合数是 `C(n‑1, k‑1)`，在最坏情况下（`k≈n/2`）会非常大，指数级别。  
- 对每一种切分，还要遍历每段子串并比较两端字符，最坏需要 `O(n²)` 的时间。  
- 综合下来，时间复杂度约为 **指数级**（`O( C(n‑1,k‑1) * n² )`），在 `n ≤ 100` 时根本跑不完。  
- 空间上只需要保存原字符串和递归栈，`O(n)`。

#### 代码（Python）

```python
def min_changes_bruteforce(s: str, k: int) -> int:
    n = len(s)

    # 计算子串 s[l:r]（左闭右开）变成回文最少需要改动多少字符
    def cost(l: int, r: int) -> int:
        cnt = 0
        i, j = l, r - 1
        while i < j:
            if s[i] != s[j]:
                cnt += 1          # 需要把其中一个字符改成另一个
            i += 1
            j -= 1
        return cnt

    # 递归枚举所有切分，pos 表示当前处理到的位置，parts 已经切了多少段
    ans = float('inf')

    def dfs(pos: int, parts: int, cur: int):
        """遍历所有把前 pos 个字符切成 parts 段的方式"""
        nonlocal ans
        # 已经切完 k 段，却还有剩余字符 → 不合法
        if parts == k and pos < n:
            return
        # 正好切完 k 段且正好用完所有字符 → 更新答案
        if parts == k and pos == n:
            ans = min(ans, cur)
            return
        # 剪枝：如果已经比当前最优更大，就不必继续搜索
        if cur >= ans:
            return
        # 从当前位置往后尝试切下一段子串
        for end in range(pos + 1, n + 1):
            dfs(end, parts + 1, cur + cost(pos, end))

    dfs(0, 0, 0)
    return ans
```

> **注**：上述代码只用于说明思路，实际运行会因为指数级搜索而超时。

#### 复杂度

- **时间复杂度**：`O( C(n‑1, k‑1) * n² )`，指数级别，`n` 只要稍大就会爆炸。  
- **空间复杂度**：`O(n)`，递归栈深度最多 `k ≤ n`。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**大量重复的子问题**：

1. **子串改成回文的代价**被反复计算。  
2. **切分的状态**只关心“已经切了多少段”和“当前到哪了”，而暴力把每一种切法都展开成完整的递归树。

我们可以把这两类子问题 **预先求解并记忆**，把指数级的搜索压缩成多项式时间。

**核心思路**：

1. **预处理**：  
   - 用双指针一次遍历所有子串，算出 `cost[i][j]` —— 把 `s[i..j]`（左闭右闭）变成回文最少需要改动的字符数。  
   - 这一步只需要 `O(n²)` 的时间和空间。  

2. **动态规划**（DP）：  
   - 定义 `dp[i][p]` 为 **把前 `i` 个字符（`s[:i]`）切成 `p` 段后，最小的改动次数**。  
   - 转移方程：  
     ```
     dp[i][p] = min_{0 <= j < i} ( dp[j][p-1] + cost[j][i-1] )
     ```
     解释：最后一段的起点可以是 `j`（第 `j` 个字符是上一段的结尾），  
     那么前面 `j` 个字符已经切成 `p-1` 段的最优代价是 `dp[j][p-1]`，  
     再加上把 `s[j:i]` 变成回文的代价 `cost[j][i-1]`，取所有可能的 `j` 中的最小值。  
   - 初始条件：`dp[0][0] = 0`（空串切成 0 段不需要改动），其余设为无限大。  
   - 最终答案是 `dp[n][k]`，即把全部 `n` 个字符切成 `k` 段的最小改动数。

3. **为什么是最优的**：  
   - DP 把“把前 i 个字符切成 p 段”这个子问题的最优解保存在表格里，后面的计算只会引用已经得到的最优值，不会遗漏更好的方案。  
   - 每一次转移只考虑 **一次** 最后一段的切分位置，避免了指数级的枚举。

**类比**：把 `s` 想象成一块巧克力棒，`cost[i][j]` 是把第 `i`~`j` 块巧克力重新包装成对称形状的费用。我们想把整根棒子切成 `k` 段，每段都包装成对称形状，总费用最小。动态规划相当于一次次记录“前面已经包装好的最小费用”，后面只需要看“从哪儿开始切下一段”即可。

#### 代码（Python）

```python
def minChanges(s: str, k: int) -> int:
    n = len(s)

    # -------------------------------------------------
    # 1. 预处理：cost[i][j] = 把 s[i..j] 变成回文最少需要改动的字符数
    # -------------------------------------------------
    cost = [[0] * n for _ in range(n)]
    # 只需要遍历左边界 i 从右往左，右边界 j 从 i+1 往右
    for i in range(n - 1, -1, -1):
        for j in range(i + 1, n):
            if s[i] == s[j]:
                cost[i][j] = cost[i + 1][j - 1]  # 两端相等，不需要额外改动
            else:
                cost[i][j] = cost[i + 1][j - 1] + 1  # 两端不等，需要改动一次

    # -------------------------------------------------
    # 2. DP：dp[i][p] = 前 i 个字符切成 p 段的最小改动数
    #    i 范围 0~n，p 范围 0~k
    # -------------------------------------------------
    INF = 10 ** 9
    dp = [[INF] * (k + 1) for _ in range(n + 1)]
    dp[0][0] = 0  # 空串切 0 段，费用为 0

    # 外层遍历 i（处理到第 i 个字符），内层遍历已经切好的段数 p
    for i in range(1, n + 1):          # i 表示前 i 个字符（下标 0~i-1）
        for p in range(1, min(k, i) + 1):   # 至少要有 p <= i
            # 枚举最后一段的起点 j（0 <= j < i）
            for j in range(p - 1, i):  # 为了保证前面有 p-1 段，j 至少是 p-1
                # dp[j][p-1] 已经是前 j 个字符切成 p-1 段的最优
                # cost[j][i-1] 是第 p 段（s[j:i]）变回文的费用
                dp[i][p] = min(dp[i][p],
                               dp[j][p - 1] + cost[j][i - 1])

    return dp[n][k]
```

> **关键行中文注释** 已在代码中标注，帮助初学者快速对应算法步骤。

#### 复杂度

- **时间复杂度**：  
  - 预处理 `cost` 需要遍历所有 `i ≤ j`，共 `O(n²)` 次。  
  - DP 三层循环：`i` (1~n) × `p` (1~k) × `j` (最多 `i`)，总共 `O(k·n²)`。  
  - 对于本题 `n ≤ 100`，`k ≤ n`，最坏约 `10⁶` 次运算，毫秒级可接受。  
  - 与暴力解的指数级相比，**快了好几个数量级**。  

- **空间复杂度**：  
  - `cost` 表占 `O(n²)`（约 10⁴ 个整数）。  
  - `dp` 表占 `O(k·n)`，最多也只有 `10⁴` 左右。  
  - 合计 `O(n²)`，在题目限制下完全可以接受。

## 心得

- **核心技巧**：先**预处理所有子串变回文的代价**，再用**二维动态规划**把“切分成 k 段”这个全局问题拆解成“前 i 个字符切成 p 段”的子问题。  
- **适用题型**  
  1. **字符串分割 + 代价**：如 *Palindrome Partitioning II*（最少回文分割数）。  
  2. **区间划分求最小/最大代价**：如 *分割数组的最大和*（Split Array Largest Sum）等。  
  3. **需要先计算区间属性再 DP**：如 *矩阵块划分最小代价*、*石子合并*（Stone Game）等。  
- **一句话总结**：**把每段的改动代价提前算好，用 DP 把“切几段”变成“选哪个切点”即可得到最优解。**

## 反思

- **第一反应**：看到“把字符串分成 k 段，使每段尽可能接近回文”，立刻想到枚举切点。  
- **最容易踩的坑**  
  - **代价重复计算**：若每次都重新遍历子串比较，两端会导致指数级时间。  
  - **边界条件**：`dp` 的初始化必须把 `dp[0][0]=0`，其余设为无穷大，否则会误把未切分的部分计入答案。  
  - **段数与下标的对应**：切第 `p` 段时，起点 `j` 必须保证前面已经有 `p-1` 段（即 `j ≥ p-1`），否则会出现非法状态。  
- **下次类似题的第一步**：先**判断是否可以把区间属性（如改动次数、和、最大值）预处理成 O(1) 查询的表**，如果可以，再设计**基于区间的 DP**，把全局最优拆解为子问题的最优。
