# #1185. 星期几 / Day of the Week

> 难度：简单 · 标签：Math · [LeetCode 链接](https://leetcode.com/problems/day-of-the-week/)

---

## 题目（英文原版）

**Description**

Given a date, return the corresponding day of the week for that date.
The input is given as three integers representing the day, month and year respectively.
Return the answer as one of the following values {"Sunday", "Monday", "Tuesday", "Wednesday", "Thursday", "Friday", "Saturday"}.

**Examples**

**Example 1:**

```
Input: day = 31, month = 8, year = 2019
Output: "Saturday"
```

**Example 2:**

```
Input: day = 18, month = 7, year = 1999
Output: "Sunday"
```

**Example 3:**

```
Input: day = 15, month = 8, year = 1993
Output: "Sunday"
```

**Constraints**

- The given dates are valid dates between the years 1971 and 2100.

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**从一个已知的基准日期出发，逐天往前或往后走，直到到达目标日期**，走了多少天就对应多少个星期偏移。  

- **基准日期**：题目保证年份在 1971~2100 之间，我们可以查表得知 1971‑01‑01 是 **Friday**（星期五）。  
- **数据结构**：只需要一个**整数**来记录已经走了多少天，另外用一个**列表** `week = ["Sunday","Monday","Tuesday","Wednesday","Thursday","Friday","Saturday"]` 把下标 0~6 对应到星期名称。列表就像一本小字典，键（下标）直接映射到值（星期名）。  
- **闰年**：每四年会多出一天（2 月 29 日），但整百的年份不是闰年，整四百的年份又是闰年。这里的范围（1971~2100）只涉及到 2000 年是闰年，其余按“能被 4 整除且不能被 100 整除”判定即可。  

**为什么正确**：我们把日期的顺序完全展开成“一天接一天”的线性序列，只要计数的方式不出错，最终的偏移量必然对应正确的星期。

#### 代码（Python）

```python
def day_of_week_bruteforce(day: int, month: int, year: int) -> str:
    # 基准：1971-01-01 是星期五，对应下标 5
    base_week_index = 5                     # 0=Sun,1=Mon,...,5=Fri,6=Sat
    week = ["Sunday", "Monday", "Tuesday", "Wednesday",
            "Thursday", "Friday", "Saturday"]

    # ------------------- 1. 计算从基准年到目标年之间的天数 -------------------
    days = 0
    for y in range(1971, year):
        # 判断 y 年是否闰年
        if (y % 4 == 0 and y % 100 != 0) or (y % 400 == 0):
            days += 366                     # 闰年 366 天
        else:
            days += 365                     # 平年 365 天

    # ------------------- 2. 计算目标年中已过去的天数 -------------------
    # 各个月的天数（平年），索引从 1 开始方便阅读
    month_days = [0, 31, 28, 31, 30, 31, 30,
                  31, 31, 30, 31, 30, 31]

    # 若目标年是闰年，2 月改为 29 天
    if (year % 4 == 0 and year % 100 != 0) or (year % 400 == 0):
        month_days[2] = 29

    for m in range(1, month):
        days += month_days[m]               # 累加完整月份的天数

    days += day - 1                         # 加上当前月已经过去的天数（不算当天）

    # ------------------- 3. 计算星期下标 -------------------
    week_index = (base_week_index + days) % 7
    return week[week_index]
```

#### 复杂度

- **时间复杂度：O(Y)**  
  这里的 `Y` 是 `year - 1971`，最坏情况约为 130（2100‑1971），即我们需要遍历每一年一次。用大白话说，就是“最多跑一百多次循环”，在电脑眼里几乎是瞬间完成的。

- **空间复杂度：O(1)**  
  只用了固定大小的几个变量和一个长度为 7 的列表，和输入规模无关，算是“常量级别的空间”。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **逐年累加**，虽然本题范围不大，但如果把年份范围放宽到几千年甚至更大，这种线性遍历就会显得“慢”。  
我们可以直接利用 **数学公式**，一次性算出某个日期对应的星期，而不需要逐年、逐月地累加天数。

常用的公式有 **Zeller's Congruence（蔡勒公式）**，它把日期映射到一个整数，然后取模 7 得到星期。公式只涉及加减乘除几步运算，时间是 **O(1)**，即“常数时间”。下面一步步解释公式的来源和使用方法。

1. **把月份 1、2 当成上一年的 13、14**  
   这是因为在公式里把“一年视作从 3 月开始算”可以统一闰年的处理。  
   - 如果 month ≤ 2，则 `month += 12` 并且 `year -= 1`。  
   - 这样 1 月、2 月 就变成了上一年的第 13、14 月，闰年判定自然生效。

2. **分解年份**  
   - `K = year % 100`  → 年份的后两位（比如 1999 的 K 是 99）。  
   - `J = year // 100` → 世纪数（比如 1999 的 J 是 19）。

3. **核心公式**  

\[
h = \bigl( \text{day} + \bigl\lfloor\frac{13(m+1)}{5}\bigr\rfloor + K + \bigl\lfloor\frac{K}{4}\bigr\rfloor + \bigl\lfloor\frac{J}{4}\bigr\rfloor + 5J \bigr) \bmod 7
\]

   - `h` 的取值范围是 0~6，分别对应 **Saturday, Sunday, Monday, Tuesday, Wednesday, Thursday, Friday**。  
   - 这里的 `⌊ ⌋` 表示向下取整（整除），在 Python 里直接用 `//`。

4. **映射到题目要求的顺序**  
   题目希望返回 `["Sunday","Monday","Tuesday","Wednesday","Thursday","Friday","Saturday"]`，而 `h` 的顺序从 **Saturday** 开始。只需要把 `h` 往前平移一位即可：

\[
\text{index} = (h + 6) \% 7
\]

   - 这样 `0`（Saturday）会映射到 `6`（Saturday），`1`（Sunday）映射到 `0`（Sunday），依此类推。

**类比**：把日期看作一把钥匙，公式就是把钥匙“切割”成若干齿（加、乘、除），再放进锁孔（取模 7），恰好打开对应的星期锁。

#### 代码（Python）

```python
def day_of_week_optimal(day: int, month: int, year: int) -> str:
    """
    使用 Zeller's Congruence（蔡勒公式）直接计算星期。
    """
    # 1. 把 1、2 月视为上一年的 13、14 月
    if month <= 2:
        month += 12
        year -= 1

    K = year % 100          # 年份后两位
    J = year // 100         # 世纪数

    # 2. 蔡勒公式，注意 // 是整数除法（向下取整）
    h = (day + (13 * (month + 1)) // 5 + K + K // 4 + J // 4 + 5 * J) % 7

    # 3. 把公式得到的顺序（Saturday 为 0）平移到题目要求的顺序
    week = ["Sunday", "Monday", "Tuesday", "Wednesday",
            "Thursday", "Friday", "Saturday"]
    index = (h + 6) % 7      # 0->Saturday, 1->Sunday, ... => shift

    return week[index]
```

#### 复杂度

- **时间复杂度：O(1)**  
  只做了常数次的加减乘除运算，跟输入的大小完全无关。可以说是“一次算完”，即使跑一亿次也几乎不花时间。

- **空间复杂度：O(1)**  
  使用的变量个数固定，和数据规模无关。

## 心得

- **核心技巧**：**使用数学公式（Zeller's Congruence）把日期直接映射到星期**。  
- **适用的类似题型**：  
  1. **计算两日期之间相差的天数**（同样需要闰年、月份天数的处理）  
  2. **求某年某月的第一天是星期几**（也是日期到星期的映射）  
  3. **公历转农历（或相反）** 中经常需要先知道对应的星期来确定闰月位置。  
- **一句话总结**：**把日期先“搬到 3 月以后”，再套用蔡勒公式，一步算出星期**。

## 反思

- **第一反应**：先想到从已知基准日期逐天累加——最直观但略显“慢”。  
- **最容易踩的坑**：  
  - **闰年规则**：尤其是 2000 年是闰年，而 2100 年（本题不涉及）不是。  
  - **月份转换**：忘记把 1、2 月映射到上一年的 13、14 月，会导致公式出错。  
  - **返回顺序**：公式的星期顺序和题目要求不一致，需要做一次平移。  
- **下次类似题**：第一步先**检查是否有已知的数学公式或基准日期**，如果有就直接使用公式；如果没有，再考虑**逐步累加**的暴力思路。这样可以快速判断是走“公式路线”还是“模拟路线”。
