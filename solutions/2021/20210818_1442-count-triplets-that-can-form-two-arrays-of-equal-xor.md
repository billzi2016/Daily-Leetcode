## 题目（中文翻译）

给定一个整数数组 `arr`。  
我们希望选取满足 `0 <= i < j <= k < arr.length` 的三个下标 `i、j、k`。  
定义  

```
a = arr[i] ^ arr[i+1] ^ ... ^ arr[j-1]
b = arr[j] ^ arr[j+1] ^ ... ^ arr[k]
```

其中 `^` 表示按位异或（bitwise‑xor）操作。  
返回满足 `a == b` 的三元组 `(i, j, k)` 的数量。

### 示例

**示例 1**  
```
输入: arr = [2,3,1,6,7]
输出: 4
解释: 满足条件的三元组为 (0,1,2)、(0,2,2)、(2,3,4) 和 (2,4,4)。
```

**示例 2**  
```
输入: arr = [1,1,1,1,1]
输出: 10
```

### 约束条件

- `1 <= arr.length <= 300`
- `1 <= arr[i] <= 10^8`

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是把题目给出的三个下标 **i、j、k** 全部枚举一遍，逐个检查它们是否满足  

```
arr[i] ^ arr[i+1] ^ … ^ arr[j‑1]   ==   arr[j] ^ arr[j+1] ^ … ^ arr[k]
```

这里用到的唯一数据结构是 **数组** 本身。  
可以把 `^` 想象成“把两个数的每一位进行奇偶消除”，就像把两张纸的图案叠在一起，只有不相同的图案会留下。

暴力解之所以 **一定会得到正确答案**，是因为我们把所有合法的三元组都穷举了，哪怕是最极端的情况也不放过。

**时间复杂度**  
我们有三层循环：

1. `i` 从 `0` 到 `n‑1`（`n` 为数组长度）  
2. `j` 从 `i+1` 到 `n‑1`  
3. `k` 从 `j` 到 `n‑1`

每层最多遍历 `n` 次，整体是 `O(n³)`。  
如果把 `n = 100` 代入，`n³ = 1,000,000`，在电脑里已经算得很慢了。  

**空间复杂度**  
只用了常数级别的额外变量（计数器、临时的 XOR 结果），所以是 `O(1)`，即“几乎不占内存”。

#### 代码（Python）

```python
def countTriplets_bruteforce(arr):
    n = len(arr)
    ans = 0

    # 第三层循环里要不断累积 XOR，避免每次都重新遍历子数组
    for i in range(n):
        xor_i_j = 0                 # arr[i] ^ … ^ arr[j-1]
        for j in range(i + 1, n):
            xor_i_j ^= arr[j - 1]   # 把新加入的元素加入前缀 XOR

            xor_j_k = 0             # arr[j] ^ … ^ arr[k]
            for k in range(j, n):
                xor_j_k ^= arr[k]   # 同理，累积后缀 XOR
                if xor_i_j == xor_j_k:
                    ans += 1

    return ans
```

> **注释**  
> - `xor_i_j` 用来保存 `i` 到 `j‑1` 的异或值，随着 `j` 增大只需要一次 `^=` 即可更新。  
> - `xor_j_k` 同理，随着 `k` 增大实时维护 `j` 到 `k` 的异或值。  

#### 复杂度

- **时间复杂度**：`O(n³)`  
  这里的 `n³` 表示“如果数组有 100 个元素，需要大约一千万次基本运算”。  
- **空间复杂度**：`O(1)`  
  只用了几个整数变量，和输入规模无关。

### 2. 最优解

#### 思路  

**暴力解慢在哪里？**  
主要瓶颈在第三层循环：我们对每一对 `(i, j)` 再遍历所有可能的 `k`，导致 `O(n³)`。  
其实只要 **知道子数组的 XOR 为 0**，我们就可以一次性算出对应的所有 `j`，不必再单独枚举。

**关键等式推导**  

设  
- `pre[x]` 为下标 `x` 前（不包括 `x`）所有元素的前缀异或，`pre[0] = 0`。  
- `XOR(i, j) = arr[i] ^ … ^ arr[j] = pre[i] ^ pre[j+1]`（因为 `a ^ a = 0`，相同的前缀会相互抵消）。

题目要求  

```
arr[i] ^ … ^ arr[j‑1]  ==  arr[j] ^ … ^ arr[k]
```

左边 = `pre[i] ^ pre[j]`，右边 = `pre[j] ^ pre[k+1]`，于是

```
pre[i] ^ pre[j]  ==  pre[j] ^ pre[k+1]
=>  pre[i] == pre[k+1]               (1)
```

所以，只要 **两个前缀异或相等**，它们之间的所有 `j`（i < j ≤ k）都会成立。  

**把 (1) 转化为计数**  
遍历所有前缀位置 `p`（从 `0` 到 `n`），记当前前缀值为 `v = pre[p]`。  
如果之前已经出现过相同的 `v`，设这些出现位置的集合为 `{i₁, i₂, …, i_m}`，则每个 `i` 都能和当前 `p` 组合形成若干合法三元组：

```
对于固定的 i, p（i < p）：
    可选的 j 有 (p - i - 1) 种   （因为 j 必须在 i+1 … p-1 之间）
```

于是对每个 `v`，我们只需要维护两件事：

1. **出现次数** `cnt[v]`（即 `m`）  
2. **出现位置之和** `sumIdx[v] = i₁ + i₂ + … + i_m`

当遍历到新位置 `p` 时，新增的答案贡献为  

```
cnt[v] * p - sumIdx[v] - cnt[v]          (因为每个 i 要减去 1)
```

随后更新 `cnt[v] += 1`，`sumIdx[v] += p`，继续往后走。

这样只需要一次线性遍历，就把原本的 `O(n³)` 降到了 `O(n)`（实际上是 `O(n)` 的哈希表操作，整体是 `O(n)`）。

**类比**  
把前缀异或看成“字典里的单词”。每次看到一个已经出现过的单词，就相当于找到了若干对相同的页码（下标），这些配对之间可以产生若干种“拆分方式”（即不同的 `j`），我们只要把这些方式累加起来。

#### 代码（Python）

```python
def countTriplets(arr):
    """
    最优解：利用前缀异或 + 哈希表统计出现次数和下标之和
    时间复杂度 O(n) ，空间复杂度 O(n)（哈希表保存所有不同的前缀值）
    """
    from collections import defaultdict

    n = len(arr)
    # 前缀异或，pre[0] = 0，pre[i] 表示 arr[0..i-1] 的异或
    pre = [0] * (n + 1)
    for i in range(n):
        pre[i + 1] = pre[i] ^ arr[i]

    # cnt[v] = 前缀值 v 出现的次数（截至当前遍历位置之前）
    # sumIdx[v] = 这些出现位置的下标之和
    cnt = defaultdict(int)
    sumIdx = defaultdict(int)

    ans = 0
    for p, v in enumerate(pre):          # p 从 0 到 n
        if cnt[v]:                        # 之前出现过相同的前缀异或
            # 对每个之前的 i，贡献 (p - i - 1)；累计公式化简如下
            ans += cnt[v] * p - sumIdx[v] - cnt[v]

        # 更新统计信息，供后面的 p 使用
        cnt[v] += 1
        sumIdx[v] += p

    return ans
```

> **关键行中文注释**  
> - `pre[i + 1] = pre[i] ^ arr[i]`：把新元素的异或累加到前缀里。  
> - `if cnt[v]:`：只有当这个前缀值之前出现过，才会产生合法三元组。  
> - `ans += cnt[v] * p - sumIdx[v] - cnt[v]`：把所有可能的 `j` 一次性加进答案。  
> - `cnt[v] += 1`、`sumIdx[v] += p`：维护出现次数和位置之和，准备迎接下一个下标。

#### 复杂度

- **时间复杂度**：`O(n)`  
  只遍历一次数组，哈希表的增删查都是常数均摊时间。相比暴力的 `n³`，即使 `n=300`，也从 27 000 000 次降到 300 次，快得多。  
- **空间复杂度**：`O(n)`  
  最坏情况下每个前缀异或值都不相同，需要在哈希表里保存 `n+1` 条记录，约占 `n` 个整数的空间。

## 心得  

- **核心技巧**：**前缀异或 + 哈希表计数**。把“两个子数组异或相等”转化为“两个前缀异或相同”，再用哈希表一次性统计所有配对。  
- **适用场景**：  
  1. **子数组异或为 0** 的计数（如本题）。  
  2. **子数组和为给定值**（使用前缀和 + 哈希表）。  
  3. **找出满足某种线性关系的子数组**（如前缀乘积、前缀最大最小等）。  
- **一句话总结**：把“区间之间的关系”搬到“区间起点的属性”上，用哈希表把相同属性的起点配对，就能一次性算出所有合法区间。

## 反思  

- **第一反应**：看到 “i、j、k 三个下标” 立刻想到三层枚举，写出暴力代码。  
- **最容易踩的坑**：  
  - 忘记 `j` 必须 **严格在** `i` 与 `k` 之间，导致计数多或少。  
  - 前缀异或数组的长度是 `n+1`（多加一个 `0`），容易把下标对齐弄错。  
  - 哈希表统计时忘记减去 `cnt[v]`（对应 `-1`），导致每对 `(i, p)` 多算了一个不合法的 `j`。  
- **下次第一步**：先写出前缀异或或前缀和，检查能否把原始条件转化为“两个前缀相等”，再决定是否需要哈希表计数。这样可以直接跳过所有不必要的枚举。
