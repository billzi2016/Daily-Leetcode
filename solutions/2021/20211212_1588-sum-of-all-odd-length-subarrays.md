## 题目（英文原版）

**Description**

Given an array of positive integers arr, return the sum of all possible odd-length subarrays of arr.
A subarray is a contiguous subsequence of the array.
Follow up:
Could you solve this problem in O(n) time complexity?

**Examples**

**Example 1:**

```
Input: arr = [1,4,2,5,3]
Output: 58
Explanation: The odd-length subarrays of arr and their sums are:
[1] = 1
[4] = 4
[2] = 2
[5] = 5
[3] = 3
[1,4,2] = 7
[4,2,5] = 11
[2,5,3] = 10
[1,4,2,5,3] = 15
If we add all these together we get 1 + 4 + 2 + 5 + 3 + 7 + 11 + 10 + 15 = 58
```

**Example 2:**

```
Input: arr = [1,2]
Output: 3
Explanation: There are only 2 subarrays of odd length, [1] and [2]. Their sum is 3.
```

**Example 3:**

```
Input: arr = [10,11,12]
Output: 66
```

**Constraints**

- 1 <= arr.length <= 100
- 1 <= arr[i] <= 1000

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是把所有可能的子数组都枚举出来，检查它的长度是不是奇数，若是就把子数组里所有元素的和加到答案中。

- **枚举子数组**：子数组由左边界 `i`（从 0 开始）和右边界 `j`（`i ≤ j`）唯一确定。我们可以两层循环，外层遍历左边界 `i`，内层遍历右边界 `j`。  
- **判断奇偶**：子数组的长度等于 `j - i + 1`。只要这个长度对 2 取余等于 1（`% 2 == 1`），说明是奇数长度。  
- **计算子数组和**：把 `arr[i] … arr[j]` 的所有元素累加。这里可以再套一层循环，也可以在遍历 `j` 的过程中维护一个滚动的累计和 `cur_sum`，每次把 `arr[j]` 加进去即可。

> **类比**：想象你在看一本书的目录，每一章节对应一个左边界 `i`，章节内部的每一页对应一个右边界 `j`。我们把所有可能的「章节 + 起始页」组合都列出来，只挑出「页数是奇数」的章节，然后把章节里所有页码的数字加起来。

**为什么正确**  
因为我们没有遗漏任何子数组，也没有多算任何子数组。只要遍历完所有 `(i, j)` 对，并且只对奇数长度的子数组做求和，最终得到的就是题目要求的“所有奇数长度子数组的和”。

**复杂度分析（大白话）**  
- 外层循环 `i` 有 `n` 次，内层循环 `j` 最多也有 `n` 次，最坏情况下两层循环会产生 `n * n`（即 `n²`）次组合。  
- 对每个合法的奇数长度子数组我们又要遍历一次它的元素来求和（最坏也会是 `n`），所以总体时间复杂度是 **O(n³)**，但我们可以在遍历 `j` 时直接累计，省掉最内层循环，这样时间复杂度降到 **O(n²)**。  
- 只用了几个整数变量（`i, j, cur_sum, ans`），空间上不随 `n` 增长，**O(1)**。

> **O(n²) 是什么意思**：如果数组长度是 10，算法大约会做 10×10 = 100 次基本操作；如果长度是 100，操作次数会变成 10,000 次，规模会随 `n` 的平方增长。

#### 代码（Python）

```python
def sumOddLengthSubarrays_bruteforce(arr):
    """
    暴力解法：枚举所有子数组，长度为奇数时求和
    时间复杂度 O(n^2)   空间复杂度 O(1)
    """
    n = len(arr)
    ans = 0                         # 最终答案

    # i 为子数组的左端点
    for i in range(n):
        cur_sum = 0                  # 累计从 i 到当前 j 的子数组和
        # j 为子数组的右端点，逐步向右扩展
        for j in range(i, n):
            cur_sum += arr[j]        # 把新加入的元素加入累计和
            length = j - i + 1       # 子数组的长度
            if length % 2 == 1:      # 只关心奇数长度
                ans += cur_sum       # 把当前子数组的和加入答案

    return ans
```

#### 复杂度

- **时间复杂度：O(n²)**  
  - `n` 是数组长度。两层循环遍历所有左、右端点组合，内部只做常数次加法和取模判断。  
- **空间复杂度：O(1)**  
  - 只用了固定数量的整型变量，不会随 `n` 增长。

### 2. 最优解

#### 思路  

从暴力解我们可以看到，**瓶颈**在于「每个子数组都要遍历一次」——这导致了二次甚至三次的循环。其实我们并不需要逐个子数组去求和，只要知道每个元素 **在多少个奇数长度子数组里出现**，把它乘以出现次数再相加，就得到答案。

**关键观察**  
- 对于下标 `i`（从 0 开始），左边有 `i` 个元素，右边有 `n-1-i` 个元素。  
- 要构造一个包含 `arr[i]` 的子数组，只需要决定左边选多少个元素（记为 `left_cnt`）以及右边选多少个元素（记为 `right_cnt`）。  
- `left_cnt` 可以是 `0, 1, …, i`（共 `i+1` 种），`right_cnt` 可以是 `0, 1, …, n-1-i`（共 `n-i` 种）。  
- 子数组的总长度 = `left_cnt + 1 + right_cnt`。我们要求这个长度是奇数，即 `left_cnt + right_cnt` 必须是偶数（因为加上中间的 `1` 后才是奇数）。  

**把偶数分解**  
- 两个数相加为偶数，要么两者都是偶数，要么两者都是奇数。  
- 因此我们可以分别统计左边可以取的 **偶数** 个数 `left_even`、**奇数** 个数 `left_odd`，以及右边的 `right_even`、`right_odd`。  
- 出现次数 = `left_even * right_even + left_odd * right_odd`（左偶右偶 或 左奇右奇）。

**如何快速得到偶/奇的个数**  
- 在 `[0, i]` 这段里，偶数个数 = `(i // 2) + 1`（因为包括 0），奇数个数 = `(i + 1) - left_even`。  
- 在 `[i, n-1]` 这段里，元素总数 = `n - i`。偶数个数 = `((n - i - 1) // 2) + 1`，奇数个数 = `(n - i) - right_even`。  

**整体公式**  

```
total = 0
for i, val in enumerate(arr):
    left = i + 1                # 左侧元素个数（包括自己）
    right = n - i               # 右侧元素个数（包括自己）

    left_even = left // 2
    left_odd  = left - left_even
    right_even = right // 2
    right_odd  = right - right_even

    cnt = left_even * right_even + left_odd * right_odd   # arr[i] 出现的奇数子数组个数
    total += val * cnt
```

**为什么是 O(n)？**  
- 只遍历一次数组，每个位置的出现次数可以用常数时间算出来，不需要嵌套循环。  
- 所以时间是 **线性**，即 **O(n)**，空间只用几个整数，**O(1)**。

> **类比**：想象每个元素是一个演员，左边的“观众”可以站在他左边的不同位置，右边的“观众”可以站在他右边的不同位置。要让整场表演（子数组）时长为奇数，左右观众站的人数必须同奇同偶。我们只统计有多少种站法，然后把演员的演出费用（数组值）乘以站法数相加。

#### 代码（Python）

```python
def sumOddLengthSubarrays_opt(arr):
    """
    最优解：统计每个元素在奇数长度子数组中的出现次数
    时间复杂度 O(n)   空间复杂度 O(1)
    """
    n = len(arr)
    total = 0

    for i, val in enumerate(arr):
        # 左侧（包括自身）有多少个位置可以选
        left = i + 1          # 例如 i=0 时 left=1，只有自己
        # 右侧（包括自身）有多少个位置可以选
        right = n - i

        # 左侧选偶数个元素的方案数
        left_even = left // 2
        # 左侧选奇数个元素的方案数
        left_odd = left - left_even

        # 右侧选偶数个元素的方案数
        right_even = right // 2
        # 右侧选奇数个元素的方案数
        right_odd = right - right_even

        # 组成奇数长度子数组的方式 = 左偶右偶 + 左奇右奇
        cnt = left_even * right_even + left_odd * right_odd

        # 该元素在所有奇数子数组中的贡献
        total += val * cnt

    return total
```

#### 复杂度

- **时间复杂度：O(n)**  
  - 只遍历一次数组，对每个元素的出现次数计算是常数时间。  
  - 与暴力解的 `O(n²)` 相比，规模提升了一个数量级：如果 `n=1000`，暴力需要约 1,000,000 次操作，而最优只需要 1,000 次。

- **空间复杂度：O(1)**  
  - 使用的变量数量不随 `n` 增长，只占常数空间。

## 心得  

- **核心技巧**：**贡献计数**（Contribution Counting）——把“所有子结构的和”转化为“每个元素的贡献 × 出现次数”。  
- **适用的题型**：  
  1. “数组中所有子数组的和”或“所有子数组的最小/最大值之和”。  
  2. “统计子数组中满足某种条件的个数”（如奇数长度、奇数和、特定范围等）。  
  3. “求每个元素在所有子序列/子数组中的出现次数”。  

- **一句话总结解题钥匙**：**先想“每个元素到底被加了多少次”，再把它们乘起来求和**。

## 反思  

- **第一反应**：直接想到两层循环枚举子数组，然后再判断奇偶——这就是暴力思路。  
- **最容易踩的坑**：  
  - 忘记子数组必须是 **连续** 的，不能随意挑选元素。  
  - 计算出现次数时容易把左/右边的“包括自身”算错，导致 `left`、`right` 的取值不对。  
  - 取偶数/奇数个数时的整数除法要注意 Python 的向下取整特性（`//`）。  

- **下次遇到同类题**，第一步应该：**先分析每个位置的“左侧有多少种选法，右侧有多少种选法”，再利用奇偶或其他约束把两边的选法配对**，这样往往能直接得到 O(n) 的公式。
