## 题目（英文原版）

**Description**

On a 2D plane, there are n points with integer coordinates points[i] = [xi, yi]. Return the minimum time in seconds to visit all the points in the order given by points.
You can move according to these rules:

**Examples**

**Example 1:**

```
Input: points = [[1,1],[3,4],[-1,0]]
Output: 7
Explanation: One optimal path is [1,1] -> [2,2] -> [3,3] -> [3,4] -> [2,3] -> [1,2] -> [0,1] -> [-1,0]   
Time from [1,1] to [3,4] = 3 seconds 
Time from [3,4] to [-1,0] = 4 seconds
Total time = 7 seconds
```

**Example 2:**

```
Input: points = [[3,2],[-2,2]]
Output: 5
```

**Constraints**

- points.length == n
- 1 <= n <= 100
- points[i].length == 2
- -1000 <= points[i][0], points[i][1] <= 1000

在二维平面上，给定 **n** 个整数坐标点 `points[i] = [xi, yi]`。请返回按照 `points` 中给出的顺序访问所有点所需的最少时间（单位：秒）。

**输出**: `7`

从 `[1,1]` 到 `[3,4]` 的时间为 **3** 秒  
从 `[3,4]` 到 `[-1,0]` 的时间为 **4** 秒  
总时间 = **7** 秒  

**示例 2**  
**输入**: `points = [[3,2],[-2,2]]`  
**输出**: `5`  

**约束条件**  
- `points.length == n`  
- `1 <= n <= 100`  
- `points[i].length == 2`  
- `-1000 <= points[i][0], points[i][1] <= 1000`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  
最直接的想法是把“走路”这个过程**逐秒模拟**出来。  
- 每一秒我们可以向左/右、上/下，或者左上/左下/右上/右下这八个方向中的任意一个走一步（即坐标的每个分量变化 `±1` 或保持不变）。  
- 从当前点 `A(x1, y1)` 移动到下一个目标点 `B(x2, y2)` 时，反复检查 `x1`、`y1` 与 `x2`、`y2` 的关系：  
  - 如果 `x1 < x2`，就把 `x1` 加 1；如果 `x1 > x2`，就把 `x1` 减 1（水平移动）。  
  - 同理处理 `y` 坐标（垂直移动）。  
  - 当水平和垂直方向都需要改变时，就相当于走了对角线（一次同时改动 `x` 与 `y`）。  

把这一步步的移动次数累加，就是访问所有点的总时间。

> **类比**：把哈希表想成字典，`key` 是单词，`value` 是页码。这里的“坐标”就像字典里的单词，**每一次坐标的微调**相当于在字典里查找下一个单词的页码——一步一步、不可跳过。

这种做法一定能得到正确答案，因为我们严格按照题目规定的“每秒只能移动一格”来走，必然得到最短的实际路径（虽然我们没有显式地去“最短”，但一步步逼近的过程本身就是最短的）。

#### 代码（Python）
```python
def minTimeVisitingAllPoints_bruteforce(points):
    """
    暴力模拟每秒的移动过程
    :param points: List[List[int]]
    :return: int
    """
    total_time = 0                      # 累计时间
    # 依次遍历相邻两个目标点
    for i in range(1, len(points)):
        x, y = points[i - 1]             # 当前所在点
        tx, ty = points[i]               # 下一个目标点

        # 一直走到目标点为止
        while x != tx or y != ty:
            # 横向逼近
            if x < tx:
                x += 1
            elif x > tx:
                x -= 1
            # 纵向逼近
            if y < ty:
                y += 1
            elif y > ty:
                y -= 1
            total_time += 1              # 每走一步，时间+1
    return total_time
```

#### 复杂度
- **时间复杂度**：`O(T)`，其中 `T` 是所有点之间的总移动步数。最坏情况下，两点之间的距离可能高达 `2000`（坐标范围 `-1000~1000`），而 `n ≤ 100`，所以 `T` 最多在 `2·10⁵` 级别。用大白话说，就是“随着路径变长，运行时间线性增长”。  
- **空间复杂度**：`O(1)`，只用了常数个额外变量来记录当前位置和计数。

### 2. 最优解

#### 思路  
从暴力解可以看到，**每一步都在尝试把横向和纵向的差距同时缩小**。如果我们把这一步步的过程抽象出来，会发现：

- 当横向差 `dx = |x2 - x1|` 与纵向差 `dy = |y2 - y1|` 同时为正时，我们可以一次对角线走一步，`dx` 与 `dy` 同时各减 1。  
- 当其中一个差距已经为 0，另一个仍然大于 0 时，只能直线走，步数等于剩余差距。

于是，从 `A` 到 `B` 所需的最少秒数恰好是  
```
max(dx, dy)
```
这就是 **Chebyshev 距离**（棋盘上国王走的步数）。

**为什么？**  
- 对角线走一步能同时消掉 `dx` 与 `dy` 各 1，最多可以走 `min(dx, dy)` 步对角线。  
- 剩下的 `|dx - dy|` 步只能单独走横或纵。  
- 总步数 = `min(dx, dy) + |dx - dy| = max(dx, dy)`。

所以只要遍历相邻点，累加它们的 Chebyshev 距离，就得到答案，时间只跟点的数量 `n` 成线性关系。

> **类比**：把点看成城市，横向距离是“东西路程”，纵向距离是“南北路程”。如果你能同时向东走一格又向北走一格（斜对角），那每走一步就把两段路程都压缩掉。最终需要的时间就是“最长的那段路程”，因为另一段总能在它跑完之前一起跑完。

#### 代码（Python）
```python
def minTimeVisitingAllPoints(points):
    """
    使用 Chebyshev 距离一次性算出每段所需时间
    :param points: List[List[int]]
    :return: int
    """
    total = 0
    for i in range(1, len(points)):
        x1, y1 = points[i - 1]
        x2, y2 = points[i]
        dx = abs(x2 - x1)          # 横向距离的绝对值
        dy = abs(y2 - y1)          # 纵向距离的绝对值
        total += max(dx, dy)       # 取两者的较大者，即 Chebyshev 距离
    return total
```

#### 复杂度
- **时间复杂度**：`O(n)`，只遍历一次点数组，和点的数量成正比。相比暴力的 `O(T)`，大幅提升，尤其当坐标跨度很大时更明显。  
- **空间复杂度**：`O(1)`，只用了几个整数变量。

## 心得

- **核心技巧**：把二维格子上的“每秒一步”抽象为 **Chebyshev 距离**（`max(|dx|, |dy|)`），即“走斜线尽可能多，剩余的直线走完”。  
- **适用场景**：  
  1. **国王最短步数**（棋盘上国王从 A 到 B 的最少步数）  
  2. **最小时间移动机器人**（每秒可以在水平、垂直或对角方向移动一格）  
  3. **二维网格上最短路径的 Manhattan 与 Chebyshev 区别**（当对角线允许时使用 Chebyshev）  
- **一句话总结**：**“横竖各差多少，走几步就等于两者的最大值”。**

---

## 反思

- **第一反应**：看到“每秒可以向八个方向走一步”，立刻想到要**逐秒模拟**，因为这样最直观。  
- **最容易踩的坑**：  
  - 忽略对角线的存在，只用 Manhattan 距离（`|dx| + |dy|`），会把答案算得太大。  
  - 处理负坐标时忘记取绝对值，导致 `dx`、`dy` 为负数而出错。  
- **下次遇到同类题**：第一步先**思考是否可以一次性把横向和纵向的差距都缩小**——如果对角线移动被允许，答案往往是 `max(|dx|, |dy|)`，而不是逐步模拟。
