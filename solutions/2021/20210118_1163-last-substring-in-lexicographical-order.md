# #1163. 字典序中最后的子串 / Last Substring in Lexicographical Order

> 难度：困难 · 标签：Two Pointers、String · [LeetCode 链接](https://leetcode.com/problems/last-substring-in-lexicographical-order/)

---

## 题目（英文原版）

**Description**

Given a string s, return the last substring of s in lexicographical order.

**Examples**

**Example 1:**

```
Input: s = "abab"
Output: "bab"
Explanation: The substrings are ["a", "ab", "aba", "abab", "b", "ba", "bab"]. The lexicographically maximum substring is "bab".
```

**Example 2:**

```
Input: s = "leetcode"
Output: "tcode"
```

**Constraints**

- 1 <= s.length <= 4 * 105
- s contains only lowercase English letters.

---

## 题目（中文翻译）

给定一个字符串 `s`，返回 `s` 中字典序（lexicographical order）最大的子串（substring）。

**示例 1**  
**输入**: `s = "abab"`  
**输出**: `"bab"`  
**解释**: 所有子串为 `["a", "ab", "aba", "abab", "b", "ba", "bab"]`。字典序最大的子串是 `"bab"`。

**示例 2**  
**输入**: `s = "leetcode"`  
**输出**: `"tcode"`  
**解释**: 所有子串为 `["l", "le", "lee", "leet", "leetc", "leetco", "leetcod", "leetcode", "e", "ee", "eet", "eetc", "eetco", "eetcod", "eetcode", "t", "te", "tec", "teco", "tecod", "tcode", "c", "co", "cod", "code", "o", "od", "ode", "d", "de", "e"]`（仅列出部分）。字典序最大的子串是 `"tcode"`。

**约束条件**  
- `1 <= s.length <= 4 * 10^5`  
- `s` 仅包含小写英文字母。

---

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  

最直接的想法是把 **所有** 子串都列举出来，随后挑出字典序（lexicographical order）最大的那个。  
- **子串**：可以把字符串想象成一根绳子，任意挑选一个左端点 `i`（从左到右），再挑一个右端点 `j (i ≤ j)`，`s[i…j]` 就是一个子串。  
- **字典序比较**：就像查字典一样，先比较第一个字符，若相同再比较第二个字符，依此类推。  

实现时我们可以两层循环：外层固定左端点 `i`，内层把右端点从 `i` 推到字符串末尾，一边生成子串，一边用 `max` 保存当前最大的子串。

> **为什么正确**  
> 只要遍历了所有可能的 `(i, j)`，就一定会看到真正的最大子串，随后 `max` 会把它挑出来。  

#### 代码（Python）  

```python
def lastSubstring_bruteforce(s: str) -> str:
    """
    暴力枚举所有子串，返回字典序最大的子串。
    """
    n = len(s)
    best = ""                         # 当前字典序最大的子串
    for i in range(n):                # 左端点
        # 逐渐扩展右端点，生成 s[i:j+1]
        for j in range(i, n):
            cur = s[i:j + 1]          # 当前子串
            # 如果当前子串更大，就更新答案
            if cur > best:
                best = cur
    return best
```

#### 复杂度  

- **时间复杂度**：`O(n²)`  
  - 解释：外层循环 `n` 次，内层平均也要遍历约 `n/2` 次，整体大约是 `n * n/2 ≈ n²`。  
  - 对于长度为 `4·10⁵` 的字符串，这几乎是 **不可接受** 的（需要上千亿次比较）。  
- **空间复杂度**：`O(1)`（不计返回值本身）  
  - 只用了常数个临时变量。

### 2. 最优解  

#### 思路  

暴力解的瓶颈在于 **重复比较相同的前缀**。  
比如在 `"abab"` 中，子串 `"ab"` 会被比较很多次。我们需要 **一次遍历** 就能直接定位到答案。  

关键观察：

1. **答案一定是某个后缀**  
   - 假设答案是 `s[i…j]`，如果把右边的字符 `s[j+1]` 加进去仍然不比答案小，那么更长的后缀 `s[i…j+1]` 就更好。  
   - 因此最优子串一定会一直延伸到字符串末尾，即它是一个 **后缀**。  

2. **使用双指针比较两个候选后缀**  
   - 设 `i` 为当前最好的后缀的起始位置，`j` 为正在比较的另一个后缀的起始位置。  
   - 从 `i` 和 `j` 同时向后扫描，逐字符比较：  
     - 若 `s[i+k] == s[j+k]`，继续比较下一个字符 `k+1`。  
     - 若 `s[i+k] > s[j+k]`，说明以 `i` 为起点的后缀更大，`j` 及其之前的所有位置都不可能是答案，直接把 `j` 移到 `j+k+1`。  
     - 若 `s[i+k] < s[j+k]`，则以 `j` 为起点的后缀更大，把 `i` 移到 `i+k+1`（因为 `i` 之前的都不行）。  

3. **跳过已经比较过的字符**  
   - 当发现 `s[i+k] != s[j+k]` 时，已经比较了 `k+1` 个字符，这些字符以后不需要再重复比较，直接把指针向前跳过去。  

4. **最终答案**  
   - 循环结束后，`i`（或 `j`）指向的就是字典序最大的后缀，返回 `s[i:]` 即可。  

这个思路对应的算法叫 **“最大后缀”**（Maximum Suffix），时间复杂度是线性的 `O(n)`，空间 `O(1)`。

下面用生活化的类比帮助理解：

- 想象有两条赛跑的选手站在同一条跑道上，起点分别是 `i` 和 `j`。  
- 他们每一步都跑相同的距离（即比较同一个字符），谁跑到的字符更大，谁就赢。  
- 当出现字符不同的那一步时，输的一方以及他之前的所有起点都“退场”，因为已经确定它们不可能再赢。  
- 只剩下最有潜力的选手继续比赛，直到跑到终点（字符串末尾）。  

#### 代码（Python）  

```python
def lastSubstring(s: str) -> str:
    """
    双指针（最大后缀）算法，线性时间 O(n)。
    返回字典序最大的子串（必为后缀）。
    """
    n = len(s)
    i, j, k = 0, 1, 0          # i：当前最佳后缀起点，j：待比较后缀起点，k：相同前缀的长度

    while j + k < n:           # 只要 j 没跑到末尾，就继续比较
        if s[i + k] == s[j + k]:
            # 前缀仍相同，继续向后比较
            k += 1
            continue

        if s[i + k] > s[j + k]:
            # i 位置的后缀更大，j 以及它之前的所有位置都不可能是答案
            # 跳过已经比较过的 k+1 个字符
            j = j + k + 1
        else:
            # j 位置的后缀更大，i 以及它之前的所有位置都不可能是答案
            i = max(i + k + 1, j)   # 确保 i 永远在 j 右边或等于 j
            j = i + 1               # j 必须在 i 右侧重新开始比较

        k = 0                       # 重新计数相同前缀的长度

    # 循环结束后，i 指向字典序最大的后缀起点
    return s[i:]
```

> **代码要点注释**  
> - `i, j, k` 初始化为 `0, 1, 0`：从字符串最左边的两个位置开始比较。  
> - `while j + k < n` 保证 `j+k` 不会越界。  
> - 当 `s[i+k] == s[j+k]` 时，说明这两个后缀在前 `k+1` 位完全相同，需要继续往后看。  
> - 若 `s[i+k] > s[j+k]`，说明以 `i` 为起点的后缀更“大”，所以把 `j` 往后推到 `j+k+1`（跳过已比较的相同段）。  
> - 若相反，则把 `i` 往后推，并让 `j` 重新指向 `i+1`（因为 `i` 必须总是左边的较小索引）。  
> - 最后返回 `s[i:]`，即从最佳起点到字符串末尾的子串。  

#### 复杂度  

- **时间复杂度**：`O(n)`  
  - 解释：每次循环要么把 `i`、`j` 或 `k` 前进至少一个位置，且每个字符最多被比较几次（最多两次），所以整体线性。  
  - 与暴力 `O(n²)` 相比，**速度提升了指数级**，即使 `n = 4·10⁵` 也能在毫秒级完成。  
- **空间复杂度**：`O(1)`  
  - 只用了常数个变量 `i, j, k, n`，不依赖额外的数组或哈希表。

## 心得  

- **核心技巧**：**最大后缀（Maximum Suffix）双指针**，通过一次线性扫描找出字典序最大的后缀。  
- **适用的题型**  
  1. **LeetCode 1163. Last Substring in Lexicographical Order**（本题）。  
  2. **寻找字典序最小/大的循环移位**（如 “最小字母移位”）。  
  3. **构造字典序最小的子序列/子串**（如 “最小字典序子串”）。  
- **一句话总结**：  
  > “把所有子串都当成后缀来看，用两个指针一次淘汰不可能的起点，最后留下的就是字典序最大的后缀”。

## 反思  

- **第一反应**：直接把所有子串枚举出来，想用 `max` 求最大值。  
- **最容易踩的坑**  
  - **时间限制**：暴力 `O(n²)` 在大数据量下会超时。  
  - **指针跳转时的边界**：`j + k` 必须小于 `n`，否则会访问越界。  
  - **更新 `i` 时需要保证 `i ≥ j`**，否则可能出现死循环。  
- **下次遇到同类题**：第一步先思考“答案是否一定是后缀或前缀”，如果是，就尝试 **双指针/滑动窗口** 或 **单调栈** 等线性技巧，避免完整枚举。
