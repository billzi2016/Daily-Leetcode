# #1497. 检查数组配对是否能被 k 整除 / Check If Array Pairs Are Divisible by k

## 题目（英文原版）

**Description**

Given an array of integers arr of even length n and an integer k.
We want to divide the array into exactly n / 2 pairs such that the sum of each pair is divisible by k.
Return true If you can find a way to do that or false otherwise.

**Examples**

**Example 1:**

```
Input: arr = [1,2,3,4,5,10,6,7,8,9], k = 5
Output: true
Explanation: Pairs are (1,9),(2,8),(3,7),(4,6) and (5,10).
```

**Example 2:**

```
Input: arr = [1,2,3,4,5,6], k = 7
Output: true
Explanation: Pairs are (1,6),(2,5) and(3,4).
```

**Example 3:**

```
Input: arr = [1,2,3,4,5,6], k = 10
Output: false
Explanation: You can try all possible pairs to see that there is no way to divide arr into 3 pairs each with sum divisible by 10.
```

**Constraints**

- arr.length == n
- 1 <= n <= 105
- n is even.
- -109 <= arr[i] <= 109
- 1 <= k <= 105

## 题目（中文翻译）

给定一个整数数组 `arr`，长度为偶数 `n`，以及一个整数 `k`。  
我们希望将数组恰好划分为 `n / 2` 个配对（pair），使得每个配对的和都能被 `k` 整除。  
如果存在一种划分方式返回 `true`，否则返回 `false`。

**示例 1**  
**输入**: `arr = [1,2,3,4,5,10,6,7,8,9]`, `k = 5`  
**输出**: `true`  
**解释**: 配对可以为 `(1,9)`, `(2,8)`, `(3,7)`, `(4,6)` 和 `(5,10)`。

**示例 2**  
**输入**: `arr = [1,2,3,4,5,6]`, `k = 7`  
**输出**: `true`  
**解释**: 配对可以为 `(1,6)`, `(2,5)` 和 `(3,4)`。

**示例 3**  
**输入**: `arr = [1,2,3,4,5,6]`, `k = 10`  
**输出**: `false`  
**解释**: 通过尝试所有可能的配对可以发现，无法将 `arr` 划分为 3 对，每对的和都能被 10 整除。

**约束条件**  
- `arr.length == n`  
- `1 <= n <= 10^5`  
- `n` 为偶数  
- `-10^9 <= arr[i] <= 10^9`  
- `1 <= k <= 10^5`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是**把所有可能的配对都枚举一遍**，看能不能把每个数都配成“和能被 k 整除”的两两组合。  
可以把数组看成一堆小朋友，每次随便挑两个出来，如果他们的和能被 k 整除，就把这两个小朋友配对走人；否则再尝试别的组合。  
只要所有小朋友都能被配对成功，就返回 `true`，否则返回 `false`。

- **用到的数据结构**：普通的 Python `list`（保存数组），以及一个 `used` 布尔列表记录每个元素是否已经被配对。  
  `used` 就像一张“配对签到表”，上面写着谁已经找到了伙伴，谁还在等。

- **为什么正确**：我们穷举了所有可能的配对方式，只要有一种合法的配对方案，遍历过程中必定能碰到它，随后所有元素都会被标记为已使用，最终返回 `true`。相反，如果没有合法方案，遍历完所有组合后仍有未配对的元素，返回 `false`。

- **时间/空间复杂度**：  
  - 每次配对需要在剩下的元素中找伴侣，最坏情况是要检查 `n-1` 次；配对完一对后再对剩下的 `n-2` 个元素继续配对……于是总的比较次数大约是 `n/2 * (n-1) ≈ O(n²)`。  
  - 额外使用的 `used` 数组长度为 `n`，即 `O(n)` 的空间。

> **大白话解释**：`O(n²)` 就是说如果数组有 1000 个数，程序大概要做 1000 × 1000 = 1,000,000 次“检查”。当 n 很大（比如 10⁵）时，这个数字会变得非常庞大，程序会跑得很慢甚至卡死。

#### 代码（Python）

```python
def can_make_pairs_bruteforce(arr, k):
    n = len(arr)
    # 用一个布尔列表记录每个位置的数字是否已经配对
    used = [False] * n

    # 递归尝试配对
    def backtrack(paired):
        # paired 表示已经配好的对数
        if paired * 2 == n:          # 所有元素都配对完毕
            return True

        # 找到第一个还没有配对的下标 i
        i = 0
        while i < n and used[i]:
            i += 1

        # 把 i 配对给后面的每一个未使用的 j
        for j in range(i + 1, n):
            if not used[j] and (arr[i] + arr[j]) % k == 0:
                # 配对成功，标记
                used[i] = used[j] = True
                if backtrack(paired + 1):
                    return True
                # 回溯：撤销配对，继续尝试别的 j
                used[i] = used[j] = False
        # 没有找到合法的配对方式
        return False

    return backtrack(0)


# ------------------- 测试 -------------------
print(can_make_pairs_bruteforce([1,2,3,4,5,10,6,7,8,9], 5))   # True
print(can_make_pairs_bruteforce([1,2,3,4,5,6], 7))           # True
print(can_make_pairs_bruteforce([1,2,3,4,5,6], 10))          # False
```

#### 复杂度

- **时间复杂度**：`O(n²)`  
  - 解释：最坏情况下我们要检查每一对元素是否满足 “和能被 k 整除”，这大概是 `n` × `n` 次比较。

- **空间复杂度**：`O(n)`  
  - 解释：额外用了一个长度为 `n` 的 `used` 列表来记录配对状态，递归栈深度最多 `n/2`，也是 `O(n)` 级别。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**一次一次去找配对**，导致大量重复检查。  
我们注意到“和能被 k 整除”其实只和**两个数的余数**有关：

```
(a + b) % k == 0   ⇔   (a % k + b % k) % k == 0
```

换句话说，如果我们把每个数先取模 `k`（得到余数），只要两数的余数互补（相加等于 `k` 或者等于 `0`），它们就可以配成一对。

于是我们可以：

1. **统计每个余数出现的次数**。这一步相当于把所有数字分类，像是把一堆水果按颜色放进不同的篮子。这里用 **哈希表**（Python 的 `defaultdict`）或者长度为 `k` 的数组来保存频率。  
   - 哈希表就像查字典：`key` 是余数，`value` 是出现次数。

2. **检查频率是否匹配**：  
   - 对余数 `0`（即 `a % k == 0`）的数字，它们只能和同样余数 `0` 的数字配对，所以出现次数必须是 **偶数**。  
   - 对于 `k` 为偶数的情况，余数 `k/2` 同理，也必须出现偶数次。  
   - 其它余数 `r`（`1 ≤ r < k` 且 `r ≠ k-r`）必须和余数 `k-r` 的出现次数相等，因为每个 `r` 需要找一个 `k-r` 来配对。

3. **特殊情况**：  
   - 当 `arr[i]` 为负数时，Python 的 `%` 会返回非负余数，但为了兼容所有语言的实现，我们统一使用 `((x % k) + k) % k` 来确保余数在 `[0, k-1]` 范围。

只要所有余数的频率满足上述条件，就一定能把数组两两配对成功。

> **核心算法**：**余数计数 + 配对检查**（相当于一种“贪心配对”），时间只和数组长度成线性关系。

#### 代码（Python）

```python
from collections import defaultdict

def can_make_pairs(arr, k):
    """
    判断是否可以把数组划分为 n/2 对，使得每对的和能被 k 整除。
    思路：先统计每个数对 k 取余后的频率，然后检查余数的配对关系。
    """
    freq = defaultdict(int)          # 余数 -> 出现次数

    # 1️⃣ 统计余数频率（统一把负数也映射到 0~k-1）
    for x in arr:
        r = ((x % k) + k) % k         # 余数在 [0, k-1] 区间
        freq[r] += 1

    # 2️⃣ 检查每种余数的配对需求
    for r in range(k):
        cnt = freq.get(r, 0)
        if cnt == 0:
            continue                  # 没出现过的余数直接跳过

        # 余数为 0 的情况，只能和自己配对，必须出现偶数次
        if r == 0:
            if cnt % 2 != 0:
                return False
        # 当 k 为偶数时，余数 k/2 也只能和自己配对
        elif k % 2 == 0 and r == k // 2:
            if cnt % 2 != 0:
                return False
        else:
            # 其它余数 r 必须和 k - r 的出现次数相等
            if cnt != freq.get(k - r, 0):
                return False

    # 所有检查都通过，说明可以配对成功
    return True


# ------------------- 测试 -------------------
print(can_make_pairs([1,2,3,4,5,10,6,7,8,9], 5))   # True
print(can_make_pairs([1,2,3,4,5,6], 7))           # True
print(can_make_pairs([1,2,3,4,5,6], 10))          # False
```

#### 复杂度

- **时间复杂度**：`O(n + k)`  
  - 解释：我们遍历数组一次统计余数（`O(n)`），随后遍历 `0 … k-1` 检查配对关系（`O(k)`）。因为 `k ≤ 10⁵`，整体仍然是线性时间，远快于 `O(n²)`。

- **空间复杂度**：`O(k)`（哈希表最坏存 `k` 条记录）  
  - 解释：我们只需要保存每个余数的出现次数，最多 `k` 种不同的余数。相较于暴力解的 `O(n)` 递归栈，这里更节省内存。

## 心得

- **核心技巧**：利用**模运算的余数配对**来转化“和能被 k 整除”的条件，从而用**计数 + 配对检查**实现线性时间解法。  
- **适用的题型**：  
  1. “数组配对，使每对和能被 k 整除”（本题）。  
  2. “判断能否把数组分成两半，使两半和相等”（利用总和 % k 判断）。  
  3. “找出所有满足 (a + b) % k == 0 的数对”（统计余数后配对）。  
- **一句话总结**：**把问题投射到余数空间，配对等价于让余数互补**，就能用一次遍历搞定。

## 反思

- **第一反应**：看到“把数组分成 n/2 对”，自然会想到穷举配对，或是尝试“贪心配对”。  
- **最容易踩的坑**：  
  - **负数取余**：不同语言对负数 `%` 的定义不一致，必须先把余数映射到 `[0, k-1]`。  
  - **特殊余数**：`0` 和 `k/2`（当 `k` 为偶数时）只能和自己配对，必须检查它们的出现次数是否为偶数。  
  - **忘记检查 `k - r` 是否存在**：直接比较 `freq[r]` 与 `freq[k-r]`，如果 `k-r` 没出现会得到 `None`，导致错误。  
- **下次遇到同类题**：第一步先**把每个数对 k 取余并计数**，再依据余数的互补关系检查是否能配对成功。这样思路清晰、实现简洁，几乎不会出错。
