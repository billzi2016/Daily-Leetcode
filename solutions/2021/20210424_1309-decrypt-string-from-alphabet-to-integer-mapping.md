# #1309. 从字母到整数映射的字符串解密 / Decrypt String from Alphabet to Integer Mapping

> 难度：简单 · 标签：String · [LeetCode 链接](https://leetcode.com/problems/decrypt-string-from-alphabet-to-integer-mapping/)

---

## 题目（英文原版）

**Description**

You are given a string s formed by digits and '#'. We want to map s to English lowercase characters as follows:
Return the string formed after mapping.
The test cases are generated so that a unique mapping will always exist.

**Examples**

**Example 1:**

```
Input: s = "10#11#12"
Output: "jkab"
Explanation: "j" -> "10#" , "k" -> "11#" , "a" -> "1" , "b" -> "2".
```

**Example 2:**

```
Input: s = "1326#"
Output: "acz"
```

**Constraints**

- 1 <= s.length <= 1000
- s consists of digits and the '#' letter.
- s will be a valid string such that mapping is always possible.

---

## 题目（中文翻译）

给定一个仅由数字（digits）和字符 ‘#’ 组成的字符串 `s`。我们需要按照以下规则将 `s` 映射为小写英文字母（lowercase characters）：

- 单独的数字 `1`~`9` 对应字母 `a`~`i`（即 `1 → a, 2 → b, …, 9 → i`）。
- 形如 `10#`、`11#`、`12#`、…、`26#` 的三字符子串对应字母 `j`~`z`（即 `10# → j, 11# → k, …, 26# → z`）。

返回完成映射后的字符串。题目保证所有测试用例都有唯一的合法映射。

**示例 1**  
输入: `s = "10#11#12"`  
输出: `"jkab"`  
解释: `"j" -> "10#" , "k" -> "11#" , "a" -> "1" , "b" -> "2"`。

**示例 2**  
输入: `s = "1326#"`  
输出: `"acz"`  

**约束条件**  
- `1 <= s.length <= 1000`  
- `s` 只包含数字和字符 ‘#’。  
- `s` 必为合法字符串，始终可以完成映射。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  
最直接的想法是 **从左往右逐个字符读取**，遇到 `#` 就把前面的两位数字当成一个整体（10~26），否则单独把当前数字当成 1~9。  
这相当于把字符串当成一本 **“密码手册”**，我们一本一本翻：  
- 没有 `#` 的页码就是第几页对应的字母（1 → a，2 → b … 9 → i）。  
- 有 `#` 的两位数加上 `#` 就是第几页对应的字母（10# → j，11# → k … 26# → z）。

只要按照这个规则顺序走，就一定能得到唯一的映射。

#### 代码（Python）

```python
def freq_decrypt_brute(s: str) -> str:
    """
    暴力解法：从左往右遍历字符串，根据是否出现 '#'
    来决定取 1 位数字还是 2 位数字。
    """
    i = 0                     # 当前遍历到的位置
    ans = []                  # 用列表收集字符，最后再 join 成字符串
    while i < len(s):
        # 如果当前字符后面还有两个字符且第 i+2 位是 '#'
        if i + 2 < len(s) and s[i + 2] == '#':
            # 取 i 和 i+1 两位组成的两位数，如 "10#"
            num = int(s[i:i+2])          # 把 "10" → 10
            ans.append(chr(ord('a') + num - 1))  # 10 → 'j'
            i += 3                         # 跳过这三个字符（两位数字+#）
        else:
            # 单独的 1 位数字，如 "3"
            num = int(s[i])
            ans.append(chr(ord('a') + num - 1))  # 3 → 'c'
            i += 1                         # 只移动一步
    return ''.join(ans)
```

#### 复杂度

- **时间复杂度：** `O(n)`  
  这里的 `n` 是字符串长度。我们只遍历一次，每一步的操作都是常数时间（取子串、转整数、字符转换），所以整体线性。

- **空间复杂度：** `O(n)`  
  需要额外的列表 `ans` 来存放结果，最坏情况下会保存 `n` 个字符（全部是单字符映射），因此空间随输入大小线性增长。

### 2. 最优解

#### 思路  
虽然左到右的暴力解已经是 `O(n)`，但还有一种更**直观且代码更简洁**的写法——**从右往左扫描**。  

为什么从右往左更舒服？  
- 当我们看到 `#` 时，立刻知道它前面 **恰好** 两位数字组成一个字母（10~26），不需要再向后查看。  
- 当没有 `#` 时，当前字符一定是单独的 1~9，对应 a~i。  

这样做的 “瓶颈” 在于：左到右的实现需要在每一步检查 `i+2` 是否为 `#`，稍显繁琐；右到左则是 **看到 `#` 就直接处理**，代码结构更自然。

核心技巧是 **“倒着读”**，相当于我们把密码手册倒过来翻页：  
- 若当前字符是 `#` → 取前两位数字 → 转成字母 → 指针左移 3 步。  
- 否则 → 直接把当前单数字转成字母 → 指针左移 1 步。

#### 代码（Python）

```python
def freq_decrypt_opt(s: str) -> str:
    """
    最优解：从右往左遍历，遇到 '#' 就一次性处理两位数字。
    """
    i = len(s) - 1            # 从字符串最后一个字符开始
    ans = []                  # 用列表收集字符，最后逆序拼接
    while i >= 0:
        if s[i] == '#':       # 说明前面两位是 10~26
            # 取 i-2, i-1 两位数字，例如 "10#"
            num = int(s[i-2:i])   # s[i-2:i] 包含 i-2,i-1 两个字符
            ans.append(chr(ord('a') + num - 1))
            i -= 3                # 跳过这三位（两位数字+#）
        else:
            # 单独的 1~9
            num = int(s[i])
            ans.append(chr(ord('a') + num - 1))
            i -= 1                # 只移动一步
    # ans 中的字符是倒序的，翻转后返回
    return ''.join(reversed(ans))
```

#### 复杂度

- **时间复杂度：** `O(n)`  
  同样只遍历一次，只是方向相反。每一步的处理都是常数时间。

- **空间复杂度：** `O(n)`  
  需要存放结果列表，最坏情况下仍然是 `n` 个字符。  

相比左到右的暴力实现，**时间没有提升**（已经是最优的线性），但**代码更简洁、易读**，且避免了在循环体里每次都做 `i+2 < len(s)` 的边界检查。

## 心得

- **核心技巧**：倒着扫描字符串，利用 `#` 的出现直接定位两位数字的映射。
- **适用场景**：  
  1. 需要根据后缀标记决定前面若干字符的组合（如 `10#`、`11#`…）。  
  2. 类似的 “逆向解析” 题目，例如 LeetCode 94 *Binary Tree Inorder Traversal*（用栈逆序遍历）或 541 *Reverse String*（从两端向中间收敛）。
- **解题钥匙**：**“看到特殊标记就往左/右一次性取对应长度的子串”。**

---

## 反思

- **第一反应**：直接想到从左往右按规则读取，写出暴力实现。  
- **最容易踩的坑**：  
  - 边界检查不严谨，尤其是 `i+2` 超出字符串长度会导致索引错误。  
  - 忘记把结果逆序（右到左扫描时）或忘记在左到右时跳过已处理的 `#`。  
- **下次类似题**：第一步先判断是否有 **“标记字符”**（如 `#`、`$`、`)` 等），决定是 **正向遍历** 还是 **逆向遍历**，然后一次性取对应长度的子串进行转换。这样可以快速定位瓶颈并写出最简代码。
