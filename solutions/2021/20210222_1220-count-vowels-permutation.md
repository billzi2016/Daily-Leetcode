## 题目（中文翻译）

给定一个整数 **n**，请计算满足以下规则的、长度为 **n** 的字符串（string）共有多少种可能。  
由于答案可能非常大，请返回 **10^9 + 7** 模（modulo）后的结果。

**规则**  
- 每个字符只能是元音字母 `'a'`, `'e'`, `'i'`, `'o'`, `'u'`。  
- `'a'` 后面只能跟 `'e'`。  
- `'e'` 后面只能跟 `'a'` 或 `'i'`。  
- `'i'` 后面可以跟除 `'i'` 之外的任意元音，即 `'a'`, `'e'`, `'o'`, `'u'`。  
- `'o'` 后面只能跟 `'i'` 或 `'u'`。  
- `'u'` 后面只能跟 `'a'`。

### 示例

**示例 1**  
```
Input: n = 1
Output: 5
Explanation: 所有可能的字符串（string）为："a", "e", "i", "o", "u"。
```

**示例 2**  
```
Input: n = 2
Output: 10
Explanation: 所有可能的字符串为："ae", "ea", "ei", "ia", "ie", "io", "iu", "oi", "ou", "ua"。
```

**示例 3**  
```
Input: n = 5
Output: 68
```

### 约束

- 1 ≤ n ≤ 2 × 10⁴   （即 1 到 20000）

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是把所有可能的长度为 `n` 的字符串全部枚举出来，然后检查每一条转移规则是否满足，满足的就计数。  
- **数据结构**：我们可以把每个字符当成「字母表」里的一个元素，用列表 `['a','e','i','o','u']` 来存放。  
  - 类比：这像是一本只有 5 个字母的「字典」，我们要把每一种可能的「拼写」都写下来。  
- **为什么正确**：因为我们把「所有」合法字符串都列举出来了，只要不漏掉，就一定能得到正确答案。  

**转移规则**（题目给出的）：

| 前一个字母 | 下一个可以接的字母 |
|-----------|-------------------|
| a         | e                 |
| e         | a, i              |
| i         | a, e, o, u        |
| o         | i, u              |
| u         | a                 |

只要在生成过程中严格遵守上表，就一定得到合法字符串。

#### 代码（Python）

```python
from itertools import product

MOD = 10**9 + 7

# 规则表：每个元音后面可以接的元音集合
next_map = {
    'a': ['e'],
    'e': ['a', 'i'],
    'i': ['a', 'e', 'o', 'u'],
    'o': ['i', 'u'],
    'u': ['a']
}

def countVowelPermutation_bruteforce(n: int) -> int:
    """
    暴力枚举所有长度为 n 的字符串，统计合法个数
    """
    vowels = ['a', 'e', 'i', 'o', 'u']
    ans = 0

    # product 会生成所有可能的 n 位元音组合，等价于 5**n 种
    for chars in product(vowels, repeat=n):
        ok = True
        # 检查相邻两个字符是否满足规则
        for i in range(n - 1):
            if chars[i+1] not in next_map[chars[i]]:
                ok = False
                break
        if ok:
            ans += 1

    return ans % MOD   # 题目要求取模

# ------------------- 示例 -------------------
print(countVowelPermutation_bruteforce(1))  # 5
print(countVowelPermutation_bruteforce(2))  # 10
print(countVowelPermutation_bruteforce(5))  # 68
```

> **关键行注释**  
> - `product(vowels, repeat=n)`：把 5 个元音当成「字典」里的词，生成所有可能的「拼写」组合。  
> - `if chars[i+1] not in next_map[chars[i]]`：检查「前后两个字母」是否符合转移规则。

#### 复杂度  

- **时间复杂度**：`O(5^n * n)`  
  - 解释：我们枚举了 `5^n`（因为每个位置有 5 种选择）种可能，每种可能要检查 `n‑1` 次相邻关系。  
  - 对于 `n=10`，已经是 `5^10 ≈ 9.8M`，很快会超时。  
- **空间复杂度**：`O(n)`（存放当前枚举的字符序列）  
  - 只需要保存一个长度为 `n` 的元组，常数级别的额外空间。

> 暴力解虽然思路最直观，但在 `n` 达到几千甚至两万时根本不可行，需要寻找更快的办法。

### 2. 最优解  

#### 思路  

从暴力解可以看出，**每一步只关心前一个字符**，而不需要记住更早的字符。  
这正好符合「**动态规划（DP）**」的思想：把大问题拆成「长度 i、以某个元音结尾」的子问题。

1. **确定状态**  
   - `dp[i][v]` 表示长度为 `i`、且第 `i` 个字符是元音 `v`（`v` 用 0~4 代表 a/e/i/o/u）的合法字符串个数。  
   - 这里的 `dp` 表是一张 **二维表**，行是长度，列是元音。  

2. **写出转移方程**（从规则表直接得到）  

| 当前字符 v | 前一个字符可以是哪些 | 转移式 |
|------------|--------------------|--------|
| a (0)      | u (4)              | `dp[i][0] = dp[i-1][4]` |
| e (1)      | a (0), i (2)       | `dp[i][1] = dp[i-1][0] + dp[i-1][2]` |
| i (2)      | a (0), e (1), o (3), u (4) | `dp[i][2] = dp[i-1][0] + dp[i-1][1] + dp[i-1][3] + dp[i-1][4]` |
| o (3)      | i (2), u (4)       | `dp[i][3] = dp[i-1][2] + dp[i-1][4]` |
| u (4)      | a (0)              | `dp[i][4] = dp[i-1][0]` |

3. **初始化**  
   - 当 `i = 1` 时，任何单个元音都是合法的，所以 `dp[1][*] = 1`。  

4. **求答案**  
   - 长度为 `n` 的所有合法字符串，就是 `dp[n][0] + dp[n][1] + … + dp[n][4]` 的和。  

5. **空间优化**  
   - 观察转移式只依赖 `i-1` 那一行，**不需要整张二维表**。  
   - 用两个一维数组 `prev`（上一行）和 `cur`（当前行）交替更新即可。  
   - 这样空间从 `O(n*5)` 降到 `O(5)`，几乎可以忽略不计。

6. **取模**  
   - 题目要求对 `10^9+7` 取模，所有加法都要在模数下进行，防止整数溢出。  

> **类比**：把每个元音想象成「城市」，规则表是城市之间的「单向道路」。  
> 动态规划就在问：走 `i` 步到达某座城市有多少种路径？只要知道「走 `i‑1` 步到每座城市」的路径数，就能算出「走 `i` 步」的答案。

#### 代码（Python）

```python
MOD = 10**9 + 7

def countVowelPermutation(n: int) -> int:
    """
    动态规划 + 空间压缩
    dp[i][v] 表示长度 i、以元音 v 结尾的合法字符串数目
    """
    # 第 1 步：初始化，长度为 1 时每个元音都有 1 种可能
    prev = [1] * 5      # 下标 0~4 分别对应 a, e, i, o, u

    for step in range(2, n + 1):
        cur = [0] * 5   # 用来存放当前 step 的结果

        # 根据转移表逐个计算
        # a 只能由 u 前来
        cur[0] = prev[4] % MOD

        # e 可以由 a 或 i 前来
        cur[1] = (prev[0] + prev[2]) % MOD

        # i 可以由 a, e, o, u 前来
        cur[2] = (prev[0] + prev[1] + prev[3] + prev[4]) % MOD

        # o 可以由 i 或 u 前来
        cur[3] = (prev[2] + prev[4]) % MOD

        # u 只能由 a 前来
        cur[4] = prev[0] % MOD

        # 把 cur 变成下一轮的 prev
        prev = cur

    # 所有以任意元音结尾的数量相加即为答案
    return sum(prev) % MOD


# ------------------- 示例 -------------------
print(countVowelPermutation(1))   # 5
print(countVowelPermutation(2))   # 10
print(countVowelPermutation(5))   # 68
```

> **关键行注释**  
> - `prev = [1] * 5`：把「第一步」看成 5 条独立的路径，每条路径计数为 1。  
> - `cur[2] = (prev[0] + prev[1] + prev[3] + prev[4]) % MOD`：这里把「所有可以到达 i 的前驱」的计数相加，体现了「路径叠加」的思想。  
> - `prev = cur`：用新算出的数组覆盖旧的，以节约空间。

#### 复杂度  

- **时间复杂度**：`O(n)`  
  - 只循环 `n‑1` 次，每次做常数（5 条）加法。  
  - 与暴力解的指数级 `5^n` 相比，线性时间几乎是瞬间完成。  

- **空间复杂度**：`O(1)`（实际上是 `O(5)`）  
  - 只维护两组长度为 5 的数组，和 `n` 的大小无关。  

> 对比：暴力解 `O(5^n)` → 爆炸式增长；DP 解 `O(n)` → 线性增长，轻松满足 `n ≤ 2·10^4` 的限制。

## 心得  

- **核心技巧**：把「只能看前一个字符」的约束转化为「状态只与上一步有关」的动态规划。  
- **适用题型**：  
  1. **字母/数字序列的转移限制**（如 LeetCode 1220 `Count Vowels Permutation`、466 `Count The Repetitions` 等）。  
  2. **路径计数问题**，尤其是「每一步只能从固定前驱集合转移」的情形（比如「跳格子」或「斐波那契」变形）。  
- **一句话总结**：**把每一步的合法选择看成城市之间的单向道路，用 DP 累计路径数**。

## 反思  

- **第一反应**：直接想「枚举所有可能」——这在没有看到约束时是自然的想法。  
- **最容易踩的坑**：  
  - **忘记取模**：中间加法可能会超过 64 位整数范围，必须在每一步 `% MOD`。  
  - **状态定义不完整**：如果把「以元音结尾」的状态写错，转移式会出错，导致答案不对。  
  - **边界情况**：`n = 1` 时直接返回 5，若循环从 `2` 开始忘记初始化会出错。  
- **下次遇到同类题**：第一步先**抽象成「状态只依赖上一状态」**，写出转移表；再决定是否需要空间压缩。这样可以快速定位 DP 思路，避免盲目枚举。
