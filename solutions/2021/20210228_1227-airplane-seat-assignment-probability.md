# #1227. 飞机座位分配概率 / Airplane Seat Assignment Probability

> 难度：中等 · 标签：Math、Dynamic Programming、Brainteaser、Probability and Statistics · [LeetCode 链接](https://leetcode.com/problems/airplane-seat-assignment-probability/)

---

## 题目（英文原版）

**Description**

n passengers board an airplane with exactly n seats. The first passenger has lost the ticket and picks a seat randomly. But after that, the rest of the passengers will:
Return the probability that the nth person gets his own seat.

**Examples**

**Example 1:**

```
Input: n = 1
Output: 1.00000
Explanation: The first person can only get the first seat.
```

**Example 2:**

```
Input: n = 2
Output: 0.50000
Explanation: The second person has a probability of 0.5 to get the second seat (when first person gets the first seat).
```

**Constraints**

- 1 <= n <= 105

## 题目（中文翻译）

**题目描述**  
有 n 位乘客登上一架恰好有 n 个座位的飞机。第一位乘客遗失了机票，随机选取一个座位坐下。随后，其余乘客依次登机，每位乘客都会：

- 若自己原本预订的座位（own seat）未被占用，则坐在自己的座位上；
- 若自己的座位已被占用，则随机选择剩余的任意一个未被占用的座位坐下。

请返回第 n 位乘客坐到自己座位的概率。

**示例**  

示例 1:  
```
输入: n = 1
输出: 1.00000
解释: 唯一的乘客只能坐在唯一的座位上。
```

示例 2:  
```
输入: n = 2
输出: 0.50000
解释: 当第一位乘客坐在第一位座位时，第二位乘客必定坐到自己的座位；若第一位乘客坐在第二位座位，则第二位乘客只能坐在第一位座位。因此第二位乘客坐到自己座位的概率为 0.5。
```

**约束**  
- 1 ≤ n ≤ 10⁵

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**把所有可能的坐席安排枚举一遍**，然后统计第 n 位乘客坐到自己座位的比例。  
- **数据结构**：我们可以用 **列表** 来表示当前的座位安排，例如 `seats = [0,1,2,…,n-1]`，下标代表乘客编号（0 表示第 1 位乘客），列表的值代表该乘客最终坐的座位。  
- **生活化类比**：把这个过程想象成一次“抽签”。第一位乘客把所有座位的名字写在纸条里，随意抽一张；随后每位乘客如果抽到的座位是自己的，就坐下；否则只能坐到抽到的那张纸条对应的座位。我们把所有抽签的结果（所有可能的抽签顺序）都列出来，看看第 n 位乘客最终坐的是不是自己的座位。  
- **为什么正确**：因为我们遍历了**所有**合法的抽签情况，统计的比例就是题目要求的概率。  

> **注意**：枚举所有可能的抽签顺序本质上是遍历 **全排列**，复杂度会随 n 指数增长。  

#### 代码（Python）

```python
from itertools import permutations

def prob_bruteforce(n: int) -> float:
    """
    暴力枚举所有合法的座位安排，返回第 n 位乘客坐到自己座位的概率。
    只适用于 n 很小（比如 n <= 8）时实验用。
    """
    # 第 1 位乘客可以随意坐任意座位，后面的乘客只能坐自己的或被占用的座位
    # 为了直接枚举，我们生成所有 n! 种排列（每个排列代表乘客坐的座位顺序）
    # 但只有满足“前面乘客已经坐好后，后面乘客若座位被占则只能坐占用者坐的座位”的排列才合法。
    total = 0          # 所有合法排列的数量
    good = 0           # 第 n 位乘客坐到自己座位的合法排列数量

    # 生成 0~n-1 的全排列，perm[i] 表示第 i+1 位乘客坐的座位编号
    for perm in permutations(range(n)):
        occupied = set()      # 已经被占用的座位
        ok = True
        for i in range(n):
            seat = perm[i]
            # 第 i 位乘客只能坐自己的座位（i）或者已经被占用的座位
            if seat != i and seat not in occupied:
                ok = False
                break
            occupied.add(seat)
        if ok:                 # 这是一种合法的抽签结果
            total += 1
            if perm[-1] == n-1:   # 第 n 位乘客坐到自己的座位
                good += 1

    return good / total if total else 0.0
```

#### 复杂度  

- **时间复杂度**：`O(n!)`（阶乘级别）。  
  - 大白话：当乘客人数从 5 增加到 6 时，可能的座位安排会从 120 增加到 720，几乎翻了 6 倍，人数每多一个，复杂度就会乘以当前的 n。  
- **空间复杂度**：`O(n)`，只用到几个长度为 n 的临时列表和集合。

### 2. 最优解  

#### 思路  

从暴力解可以看到，**枚举所有排列是不可行的**，因为 n 可以到 10⁵。我们需要找到一种 **数学归纳** 的思路，直接求出概率，而不真的去枚举。  

**关键观察**  

1. 第 1 位乘客有 `n` 种坐法，等概率。  
2. 只有两种情况会直接决定第 n 位乘客的命运：  
   - 第 1 位坐到了 **自己的座位**（座位 1），那么后面的每位乘客都会按票坐，最后第 n 位必然坐到自己的座位。  
   - 第 1 位坐到了 **第 n 位的座位**，那么第 n 位一定坐不到自己的座位。  
3. 其余情况（第 1 位坐到了第 k 位的座位，`2 ≤ k ≤ n‑1`）会把 **“谁先随机坐”** 的角色交给第 k 位乘客。此时，**子问题**变成：在剩下的 `n‑k+1` 位乘客（包括第 k 位和第 n 位）中，第 n 位坐到自己座位的概率仍然是 `f(n‑k+1)`。  

把上述三点写成递推式（设 `f(m)` 为 m 人情况下第 m 位乘客坐到自己座位的概率）：

```
f(1) = 1                     # 只有一位乘客，必坐自己座位
f(n) = 1/n * 1               # 第1位坐到自己座位的概率
      + 1/n * 0              # 第1位坐到第 n 位座位的概率
      + Σ_{k=2}^{n-1} (1/n) * f(n‑k+1)
```

把求和的下标换成 `t = n‑k+1`（即剩余人数），可以得到：

```
f(n) = 1/n + (1/n) * Σ_{t=2}^{n-1} f(t)
```

对 `f(n‑1)` 同理写出：

```
f(n‑1) = 1/(n‑1) + (1/(n‑1)) * Σ_{t=2}^{n-2} f(t)
```

两式相减，很多项会抵消，最后得到 **简洁的等式**：

```
f(n) = 1/2   (n ≥ 2)
```

也就是说，只要乘客超过两位，**第 n 位乘客坐到自己座位的概率永远是 0.5**，不随 n 增大而变化。  

**为什么是 0.5？**  
直观解释：第 1 位乘客要么直接把第 n 位的座位抢走（概率 1/n），要么把自己的座位抢走（概率 1/n），要么把某位中间乘客的座位抢走。把「抢走中间乘客座位」的情况继续往下递归，最终只能剩下「抢走第 1 位座位」或「抢走第 n 位座位」两种等概率的结局，所以概率是 1/2。  

**实现**：只要判断 n 是否为 1，返回 `1.0`；否则直接返回 `0.5`。时间、空间都是常数级。  

#### 代码（Python）

```python
def nthPersonGetsSeat(n: int) -> float:
    """
    最优解：直接返回概率。
    - 当只有 1 位乘客时，必然坐到自己的座位 → 1.0
    - 当 n ≥ 2 时，概率恒为 0.5
    时间 O(1)，空间 O(1)。
    """
    if n == 1:
        return 1.0
    return 0.5
```

#### 复杂度  

- **时间复杂度**：`O(1)` — 只做一次判断和一次返回，和 n 的大小完全无关。  
- **空间复杂度**：`O(1)` — 只用了几个整数/浮点数的变量。

## 心得  

- **核心技巧**：把看似随机的过程抽象为递归的“谁先随机坐”问题，利用**数学归纳/递推**求出闭式解。  
- **适用场景**：  
  1. “乱序座位”类概率题（如 LeetCode 1227 – **Airplane Seat Assignment Probability** 本题）。  
  2. “随机打乱后恢复原位”类问题（如“随机排列中固定点的期望”）。  
  3. 需要**把大问题拆成子问题**且子问题结构相同的动态规划/递归题。  
- **一句话总结**：**第 n 位乘客坐到自己座位的钥匙是：只要第一位不是直接坐到第 n 位座位，剩下的过程与原问题同构，导致最终概率固定为 1/2。**

## 反思  

- **第一反应**：看到“随机坐”“概率”就想**模拟**或**枚举**，把所有可能列出来。  
- **最容易踩的坑**：  
  - 忽视 **边界**（n = 1 时概率是 1，不能直接返回 0.5）。  
  - 误以为需要 DP 表或递归记忆化，导致时间/空间爆炸。  
  - 在递推推导时忘记把“第 k 位乘客随机坐”转化为子问题的**剩余人数**。  
- **下次遇到同类题**：第一步先**思考“随机过程是否会产生子结构”**，如果可以把问题规模缩小为“同样的概率问题”，就尝试写递推式并寻找闭式解，而不是立刻去模拟。
