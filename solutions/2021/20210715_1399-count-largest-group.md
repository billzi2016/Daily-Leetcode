# #1399. 统计最大分组数 / Count Largest Group

> 难度：简单 · 标签：Hash Table、Math · [LeetCode 链接](https://leetcode.com/problems/count-largest-group/)

---

## 题目（英文原版）

**Description**

You are given an integer n.
We need to group the numbers from 1 to n according to the sum of its digits. For example, the numbers 14 and 5 belong to the same group, whereas 13 and 3 belong to different groups.
Return the number of groups that have the largest size, i.e. the maximum number of elements.

**Examples**

**Example 1:**

```
Input: n = 13
Output: 4
Explanation: There are 9 groups in total, they are grouped according sum of its digits of numbers from 1 to 13:
[1,10], [2,11], [3,12], [4,13], [5], [6], [7], [8], [9].
There are 4 groups with largest size.
```

**Example 2:**

```
Input: n = 2
Output: 2
Explanation: There are 2 groups [1], [2] of size 1.
```

**Constraints**

- 1 <= n <= 104

## 题目（中文翻译）

**题目描述**  
给定一个整数 `n`。  
我们需要根据 **数字之和（digit sum）** 将区间 `[1, n]` 中的所有整数进行分组（group）。例如，数字 `14` 和 `5` 的数字之和相同，属于同一组，而 `13` 和 `3` 的数字之和不同，属于不同的组。  
返回拥有最大规模（即包含元素最多）的组的数量。

**示例**

*示例 1*  
输入: `n = 13`  
输出: `4`  
解释: 从 `1` 到 `13` 的所有数字共可以划分为 9 个组，依据它们的数字之和如下:  
`[1,10]`, `[2,11]`, `[3,12]`, `[4,13]`, `[5]`, `[6]`, `[7]`, `[8]`, `[9]`。  
其中规模最大的组有 4 个。

*示例 2*  
输入: `n = 2`  
输出: `2`  
解释: 共有 2 个组 `[1]`, `[2]`，每个组的规模均为 1。

**约束条件**  
- `1 <= n <= 10^4`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把 **1~n** 这 `n` 个整数一个一个拿出来，求出它们的 **数字之和**（比如 `14 → 1+4=5`），然后把拥有相同数字之和的数放进同一个“组”。  
这一步可以用 **哈希表**（在 Python 里用 `dict`）来实现：

* 哈希表就像一本查字典的工具书，**key** 是“数字之和”，**value** 是出现过这个和的整数的个数。  
* 对每个数 `i`，先算出 `digit_sum(i)`，再把 `cnt[digit_sum(i)] += 1`。  
* 最后遍历哈希表，找到最大的出现次数 `max_cnt`，再统计有多少个 key 的值等于 `max_cnt`，这就是答案。

为什么这样一定对？因为题目要求的“同一组”正好是“数字之和相等”，哈希表恰好把所有拥有相同 key 的元素聚在一起。

**时间/空间复杂度**（大白话）  
* 对每个 `i`（共 `n` 个）我们都要算一次数字之和。算数字之和的过程相当于看 `i` 的每一位数字，最多看 `log10(i)` 位，整体上就是 **O(n·log₁₀n)**，在本题 `n ≤ 10⁴` 时几乎就是线性时间。  
* 哈希表最多会出现 `9·5 = 45`（因为 `10⁴` 的最大数字之和是 `9+9+9+9=36`）几个不同的 key，空间占用是 **O(k)**，这里的 `k` 是不同的数字之和个数，最坏也就是 **O(n)**（每个数的和都不相同），但实际远小于 `n`。

#### 代码（Python）

```python
def count_largest_group(n: int) -> int:
    # 统计每个数字之和出现的次数，key 相当于“组号”
    cnt = {}                         # 哈希表：sum_of_digits -> frequency

    for i in range(1, n + 1):
        # 计算 i 的数字之和，最直观的做法是把 i 转成字符串逐位相加
        s = 0
        x = i
        while x:                     # 逐位取出数字
            s += x % 10              # 加上最低位
            x //= 10                 # 去掉最低位
        # 更新哈希表
        cnt[s] = cnt.get(s, 0) + 1   # 如果 s 不在表里，默认 0 再加 1

    # 找到最大的组大小
    max_size = max(cnt.values())     # 哈希表中最大的 frequency

    # 统计有多少个组的大小正好等于 max_size
    answer = sum(1 for v in cnt.values() if v == max_size)
    return answer
```

#### 复杂度

- **时间复杂度**：`O(n·log₁₀n)`  
  解释：遍历 `1~n`（`n` 次），每次求数字之和要看 `log₁₀i` 位数字，整体就是 `n` 乘以一个很小的常数，实际表现接近线性。

- **空间复杂度**：`O(k)`（`k` 为不同数字之和的种类数，最坏 `O(n)`）  
  解释：我们只用一个哈希表来记录每种数字之和出现的次数，最多存 `n` 条记录，实际远少于 `n`。

### 2. 最优解

#### 思路  

暴力解已经满足题目限制，但我们仍可以把 **求数字之和的过程** 再进一步优化，让它 **只用 O(1) 的时间** 来得到下一个数的数字之和，而不是每次都重新遍历每一位。  

**关键观察**  
设 `f(i)` 为整数 `i` 的数字之和。  
当我们从 `i` 增加到 `i+1` 时，只有最低几位会发生变化：

```
i   = ... d 9 9 9
i+1 = ... (d+1) 0 0 0
```

- 如果最低位不是 `9`，则 `f(i+1) = f(i) + 1`（只多加了 1）。
- 如果最低位是 `9`，则会产生进位，需要把所有连续的 `9` 变成 `0`，并把前面的那一位加 `1`。这相当于 **把原来这些 9 的贡献全部减掉**（每个 9 贡献 9），再加上进位后那一位的新贡献。

用代码实现时，只要把 `i` 按位检查并处理进位，就能在 **均摊 O(1)** 的时间内得到 `f(i+1)`。这相当于 **动态规划**：`f(i+1)` 只依赖 `f(i)`。

**整体步骤**

1. 初始化 `cur = 1`（`f(1) = 1`），并把它计入哈希表。  
2. 从 `2` 到 `n`，使用上面的“增量”方式快速得到 `cur = f(i)`，并更新哈希表。  
3. 最后同暴力解一样，找出最大频率并统计出现次数。

这样做的好处是**避免了每次都遍历整数的每一位**，在极限情况下（如 `n = 10⁶`）会有明显提升；在本题 `n ≤ 10⁴` 时，两者差别不大，但思路更“高级”，对以后遇到更大数据量的类似题目很有帮助。

#### 代码（Python）

```python
def count_largest_group_opt(n: int) -> int:
    # 哈希表：数字之和 -> 出现次数
    cnt = {}

    # f(1) = 1
    cur_sum = 1
    cnt[cur_sum] = 1

    for i in range(2, n + 1):
        # 计算 f(i) 时，只看 i-1 的末尾是否有 9
        x = i - 1                     # 前一个数
        cur_sum += 1                  # 默认 +1（最低位不是 9 的情况）

        # 处理进位：如果 x 的最低位是 9，需要减去 9 并继续向前检查
        while x % 10 == 9:
            cur_sum -= 9              # 把这个 9 的贡献去掉
            x //= 10                  # 去掉已经处理的 9，继续检查更高位

        # 更新哈希表
        cnt[cur_sum] = cnt.get(cur_sum, 0) + 1

    # 找最大组大小
    max_size = max(cnt.values())
    # 统计有多少组的大小等于 max_size
    answer = sum(1 for v in cnt.values() if v == max_size)
    return answer
```

#### 复杂度

- **时间复杂度**：`O(n)`（均摊 O(1)）  
  解释：我们只遍历一次 `1~n`，每次的 “进位处理” 最多检查几位（最多 5 位，因为 `n ≤ 10⁴`），所以整体是线性时间。

- **空间复杂度**：`O(k)`（同上，最多 `O(n)`）  
  解释：仍然只用一个哈希表记录每种数字之和的出现次数。

## 心得

- **核心技巧**：把「相同数字之和」看作一种“分组依据”，使用 **哈希表** 进行计数；进一步的优化是 **利用相邻整数数字之和的递推关系**（类似动态规划）来降低求和的重复工作。  
- **适用场景**：  
  1. “根据某个属性分组并统计最大出现次数”——如 LeetCode 1512. Number of Good Pairs。  
  2. “求区间内所有数的某种函数值并统计频率”——如 1647. Minimum Deletions to Make Character Frequencies Unique（统计字符频率）。  
  3. “利用相邻元素的递推关系快速更新”——如 1012. Numbers With Repeated Digits（递推计数）。  
- **一句话总结解题钥匙**：**哈希表 + 递推求和 = O(n) 统计所有组的大小**。

## 反思

- **第一反应**：直接把每个数的数字之和算出来，用字典计数。  
- **最容易踩的坑**：  
  - 忘记把 `1` 也计入哈希表，导致答案少 1。  
  - 对进位的递推写错，导致 `cur_sum` 计算错误（尤其是连续多个 `9` 的情况）。  
  - 边界条件：`n = 1` 时，答案应该是 `1`，代码必须能处理单个元素的情况。  
- **下次遇到同类题**：第一步先思考“有没有一种属性可以直接用哈希表统计”，第二步检查“相邻元素之间是否有递推关系”，若有则尝试 **增量更新**，否则直接用 **暴力计数**（在约束足够小的情况下也能 AC）。
