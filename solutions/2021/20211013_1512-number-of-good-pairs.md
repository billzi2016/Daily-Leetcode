# #1512. 好数对的数量 / Number of Good Pairs

> 难度：简单 · 标签：Array、Hash Table、Math、Counting · [LeetCode 链接](https://leetcode.com/problems/number-of-good-pairs/)

---

## 题目（英文原版）

**Description**

Given an array of integers nums, return the number of good pairs.
A pair (i, j) is called good if nums[i] == nums[j] and i < j.

**Examples**

**Example 1:**

```
Input: nums = [1,2,3,1,1,3]
Output: 4
Explanation: There are 4 good pairs (0,3), (0,4), (3,4), (2,5) 0-indexed.
```

**Example 2:**

```
Input: nums = [1,1,1,1]
Output: 6
Explanation: Each pair in the array are good.
```

**Example 3:**

```
Input: nums = [1,2,3]
Output: 0
```

**Constraints**

- 1 <= nums.length <= 100
- 1 <= nums[i] <= 100

---

## 题目（中文翻译）

给定一个整数（integer）数组 `nums`，返回好数对的数量。

如果满足 `nums[i] == nums[j]` 且 `i < j`，则称索引对 `(i, j)` 为好数对（good pair）。

## 示例

### 示例 1
**输入**: `nums = [1,2,3,1,1,3]`  
**输出**: `4`  
**解释**: 有 4 对好数对 `(0,3)`, `(0,4)`, `(3,4)`, `(2,5)`（均为 0 起始索引）。

### 示例 2
**输入**: `nums = [1,1,1,1]`  
**输出**: `6`  
**解释**: 数组中任意两元素构成的配对都是好数对。

### 示例 3
**输入**: `nums = [1,2,3]`  
**输出**: `0`

## 约束条件
- `1 <= nums.length <= 100`
- `1 <= nums[i] <= 100`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  
最直接的想法就是把所有下标两两组合，逐个检查它们是否满足“数值相等且左边下标小于右边下标”。  
- **数据结构**：只需要原数组 `nums`，不需要额外的容器。可以把它想象成一排编号的盒子，盒子里装的是数字，我们把每两个盒子拿出来比一比。
- **正确性**：因为我们遍历了所有可能的 `(i, j)`（`i` 从 0 到 `n‑2`，`j` 从 `i+1` 到 `n‑1`），只要两个位置的数字相同，就计数一次，正好对应题目中“好对”的定义。
- **时间/空间复杂度**：  
  - 时间上我们要检查 `C(n,2) = n·(n‑1)/2` 对下标，数量级记作 **O(n²)**，即“平方级”。如果 `n=100`，最多检查 4950 次，仍在可接受范围。  
  - 空间上只用了常数级的临时变量 **O(1)**，不随 `n` 增长。

#### 代码（Python）

```python
def numIdenticalPairs(nums):
    """
    暴力枚举所有 i < j 的组合，计数相等的情况
    """
    n = len(nums)
    good = 0                         # 记录好对的数量
    for i in range(n - 1):           # i 从第 0 位遍历到倒数第 2 位
        for j in range(i + 1, n):    # j 必须在 i 的右边
            if nums[i] == nums[j]:   # 两个位置的数相等，就算一个好对
                good += 1
    return good
```

#### 复杂度

- **时间复杂度：O(n²)** — “平方级”，随着数组长度增长，运算次数会呈二次方增长。  
- **空间复杂度：O(1)** — 只用了几个计数器，和输入规模无关。

### 2. 最优解

#### 思路  
暴力解的瓶颈在于 **重复比较**：同一个数出现多次时，我们会一次又一次地把它和已经遍历过的相同数比较。  
优化的关键是 **把相同的数聚在一起统计出现次数**，然后直接用组合数学公式算出它能组成多少对。

1. **统计出现次数**  
   - 用一个哈希表（在 Python 中是 `dict`）记录每个数字出现了多少次。哈希表可以类比为一本词典，**key** 是单词（这里是数字），**value** 是对应的页码（这里是出现次数）。查找、插入的时间都是 **O(1)**，非常快。

2. **根据出现次数算对数**  
   - 如果一个数字出现了 `k` 次，那么从这 `k` 个位置中任选两个组成 `(i, j)` 的方式有 `C(k,2) = k·(k‑1)//2` 种。把所有数字的这种组合数相加，就是答案。

这样我们只需要一次遍历数组（统计次数）和一次遍历哈希表（计算组合），时间降到线性 **O(n)**，空间使用一个哈希表，最多存 `nums` 中不同数字的种类数（本题 ≤100），记作 **O(m)**，其中 `m` ≤ `n`。

#### 代码（Python）

```python
def numIdenticalPairs(nums):
    """
    哈希表计数 + 组合公式
    """
    freq = {}               # 用字典统计每个数字出现的次数
    for x in nums:          # 只遍历一次数组
        freq[x] = freq.get(x, 0) + 1   # get(x,0) 相当于“查词典，如果没有返回 0”

    good = 0
    for count in freq.values():        # 对每个出现次数
        # C(count, 2) = count * (count - 1) // 2
        good += count * (count - 1) // 2
    return good
```

#### 复杂度

- **时间复杂度：O(n)** — 只需要一次线性遍历，`n` 为数组长度。相比暴力的平方级，速度提升显著。  
- **空间复杂度：O(m)** — `m` 为不同数字的种类数，最坏情况下等于 `n`，但本题数字范围只有 1~100，实际占用非常小。

## 心得

- **核心技巧**：利用哈希表统计频次，再用组合数学直接求解。  
- **适用场景**：  
  1. “计数相同元素对” 类问题，如 LeetCode 1512. Number of Good Pairs。  
  2. “出现次数大于 1 的元素统计”，如统计数组中出现超过两次的数。  
  3. “子数组/子序列满足某种相等条件” 的计数问题，常用频次哈希表配合组合公式。  
- **一句话总结**：**把相同的东西先聚在一起，再用组合公式一次算完**。

## 反思

- **第一反应**：看到“i < j 且 nums[i] == nums[j]”，自然想到双层循环枚举所有下标对。  
- **最容易踩的坑**：  
  - 忘记 `i < j` 的顺序限制，导致计数两次（会把 `(i,j)` 与 `(j,i)` 都算进去）。  
  - 组合公式写成 `k*(k+1)//2`（那是求前 `k` 个自然数之和），正确的是 `k*(k-1)//2`。  
  - 对空数组或只有一个元素的情况忘记返回 0。  
- **下次思路**：遇到“相等计数”或“出现次数决定答案”的题目时，第一步就想到 **用哈希表统计频次**，随后检查是否可以用 **组合/数学公式** 直接求解，避免不必要的遍历。
