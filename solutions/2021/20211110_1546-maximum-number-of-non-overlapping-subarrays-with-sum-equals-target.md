## 题目（英文原版）

**Description**

Given an array nums and an integer target, return the maximum number of non-empty non-overlapping subarrays such that the sum of values in each subarray is equal to target.

**Examples**

**Example 1:**

```
Input: nums = [1,1,1,1,1], target = 2
Output: 2
Explanation: There are 2 non-overlapping subarrays [1,1,1,1,1] with sum equals to target(2).
```

**Example 2:**

```
Input: nums = [-1,3,5,1,4,2,-9], target = 6
Output: 2
Explanation: There are 3 subarrays with sum equal to 6.
([5,1], [4,2], [3,5,1,4,2,-9]) but only the first 2 are non-overlapping.
```

**Constraints**

- 1 <= nums.length <= 105
- -104 <= nums[i] <= 104
- 0 <= target <= 106

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**枚举所有可能的子数组**，检查它们的和是否等于 `target`，然后在这些满足条件的子数组里挑出最多的、互不重叠的组合。

- **枚举子数组**：可以用两个循环，外层 `i` 表示子数组的左端点，内层 `j` 表示右端点（`i ≤ j`），子数组就是 `nums[i..j]`。
- **判断和是否等于 target**：把子数组里的每个元素相加，得到它的和。这里可以直接累加，也可以在每次循环时维护一个 `cur_sum`，把 `nums[j]` 加进去。
- **挑选不重叠的子数组**：得到所有满足 `sum == target` 的子数组后，问题就变成 **在这些区间里挑出最多的不相交区间**。这其实是经典的“区间调度问题”，贪心地按照右端点从小到大选就能得到最优解。

> **生活化类比**：把数组想成一条道路，子数组就是道路上的一段路段。我们要找尽可能多的、互不重叠的“等长路段”，每段路段的“长度”（这里是元素之和）必须恰好等于目标值 `target`。

**为什么暴力方法能得到正确答案**  
因为它遍历了 **所有** 可能的子数组，确保没有漏掉任何满足条件的区间；随后使用区间调度的最优贪心策略，必然得到最大数量的非重叠子数组。

**复杂度分析（大白话）**  
- 两层循环遍历每一对 `(i, j)`，最坏情况下会检查 `n*(n+1)/2`（约 `n²/2`）个子数组。  
- 对每个子数组我们只做常数时间的加法和比较，所以时间复杂度是 **O(n²)**。  
- 只用了几个整数变量和一个存放所有满足条件子数组的列表，列表里最多有 `n` 个区间，空间复杂度是 **O(n)**。

#### 代码（Python）

```python
def maxNonOverlapping_bruteforce(nums, target):
    n = len(nums)
    intervals = []                         # 用来存所有满足 sum == target 的子数组区间

    # 枚举左端点 i
    for i in range(n):
        cur_sum = 0                         # 当前子数组的累加和
        # 枚举右端点 j，逐步扩展子数组
        for j in range(i, n):
            cur_sum += nums[j]              # 把 nums[j] 加进来
            if cur_sum == target:           # 找到一个满足条件的子数组
                intervals.append((i, j))    # 记录它的左右下标

    # ----- 区间调度：挑选最多的不重叠区间 -----
    # 按右端点从小到大排序，右端点越早的子数组越“抢先”，更有利于后面还能挑到更多
    intervals.sort(key=lambda x: x[1])

    cnt = 0          # 已经挑选的子数组数量
    last_end = -1    # 上一个被挑选子数组的右端点，初始设为 -1 表示还没有子数组

    for l, r in intervals:
        if l > last_end:          # 当前子数组的左端点在上一个子数组右端点的右侧，说明不重叠
            cnt += 1
            last_end = r          # 更新最近一次选中的右端点

    return cnt
```

#### 复杂度

- **时间复杂度**：`O(n²)` — 大概是 “如果数组长度是 10,000，程序要跑大约 100,000,000 次循环”，会比较慢。
- **空间复杂度**：`O(n)` — 只存了满足条件的子数组区间，最坏情况下每个元素都能形成一个子数组，所以最多 `n` 条。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **重复遍历子数组**：每次都要从左端点重新累加，导致二次方的时间。我们可以利用 **前缀和 + 哈希表** 在一次遍历中快速判断“以当前位置结尾的子数组是否满足 sum == target”。随后，结合 **贪心** 的“**一旦找到一个合法子数组就立刻截断**”的策略，就能得到最优解。

**关键概念解释**

| 概念 | 类比 | 说明 |
|------|------|------|
| 前缀和（prefix sum） | 把走过的路程累计起来，随时知道从起点到当前位置的总距离 | `pre[i]` 表示 `nums[0] + … + nums[i-1]`，长度为 `n+1`，`pre[0]=0` |
| 哈希表（字典） | 查字典：键是“已经走过的总距离”，值是对应的下标 | 用 `{prefix_sum : 最后一次出现该前缀和的下标}`，帮助我们在 O(1) 时间内判断是否存在 `pre[j] - target` |
| 贪心 “尽早截断” | 把道路划分成最短的、符合条件的段，后面的路段不受前面已划分的影响 | 当我们在遍历时发现 **当前下标 i 能构成一个满足条件的子数组**，就立即计数并把“已使用”的区间抹掉（把哈希表清空或重置），这样后面的子数组一定不会和它重叠，且不会错过更好的组合 |

**推导过程**

1. **从左到右扫描**数组，维护 `cur_sum`（到当前位置的前缀和）。
2. 假设我们在位置 `i`，想知道是否存在一个左端点 `j`（`j ≤ i`），使得 `nums[j..i]` 的和等于 `target`。  
   依据前缀和的定义：  
   `sum(j..i) = pre[i+1] - pre[j] = target` → `pre[j] = pre[i+1] - target`。  
   换句话说，只要在哈希表里能找到 `cur_sum - target`，就说明找到了一个合法子数组。
3. 为了实现 **非重叠**，一旦找到了子数组就立刻把计数加 1，并且**重置哈希表**：把 `cur_sum` 设为 0，重新开始记录后面的前缀和。这样后面的子数组必然从下一个位置开始，天然不与已选子数组重叠。
4. 为什么这种“一旦找到就截断”是最优的？  
   - 若我们把一个合法子数组推迟到更后面才选，必然会占用更多的元素，导致后面可选的子数组数量不增反减。  
   - 通过**贪心**的“最早结束”原则，保留下来的空间最多，后面还能继续找子数组。数学上可以用“交换论证”证明：任何最优解都可以改造成和贪心解相同的形式而不降低子数组数量。

**整体算法**：

- `cur_sum = 0`，`cnt = 0`，`seen = {0: -1}`（前缀和 0 出现在下标 -1，方便计算从开头的子数组）。
- 遍历 `i, num`：
  - `cur_sum += num`
  - 若 `cur_sum - target` 在 `seen` 中，说明找到了一个子数组，计数 `cnt += 1`，**重置**：`seen = {0: i}`（把当前下标设为新的“起点”，`cur_sum` 重新从 0 开始），`cur_sum = 0`。
  - 否则，把当前 `cur_sum` 加入 `seen`（`seen[cur_sum] = i`），继续向后扫描。

**类比**：把数组想成一条河流，`target` 是要收集的“水量”。我们在河流上设置一个“水量计”，每当累计的水量正好等于 `target`，就立即在这里建一座水坝，截断河流，后面的水再重新累计。这样建的每座水坝都是最早能建的，保证后面还能建更多。

#### 代码（Python）

```python
def maxNonOverlapping(nums, target):
    """
    贪心 + 前缀和 + 哈希表
    返回最多的、互不重叠且和为 target 的子数组个数
    """
    cnt = 0                 # 已经找到的子数组数量
    cur_sum = 0             # 当前前缀和（从上一个已截断位置开始累计）
    seen = {0: -1}          # 哈希表：前缀和 -> 最近出现的下标
    # 这里把 0 映射到 -1，等价于“在数组左侧的虚拟位置”已经出现过前缀和 0

    for i, num in enumerate(nums):
        cur_sum += num                     # 累计到当前位置的前缀和

        # 检查是否存在之前的前缀和，使得两者之差恰好等于 target
        if (cur_sum - target) in seen:
            cnt += 1                       # 找到一个合法子数组
            # 关键：一旦选中，立刻“截断”——从下一个位置重新开始计数
            cur_sum = 0                    # 重置累计和
            seen = {0: i}                  # 把当前位置视作新的起点（前缀和 0 出现在 i）
        else:
            # 没找到合法子数组，继续记录当前前缀和，以备将来使用
            seen[cur_sum] = i

    return cnt
```

#### 复杂度

- **时间复杂度**：`O(n)` — 只遍历一次数组，每一步的哈希表查询/插入都是常数时间。  
  > 大白话：如果数组有 100,000 个元素，程序只会跑 100,000 次循环，速度非常快。
- **空间复杂度**：`O(n)`（最坏情况）— 哈希表里可能存放每个前缀和一次，最多 `n+1` 条记录。  
  实际上因为我们在找到子数组后会 **清空** 哈希表，空间通常会更小。

## 心得

- **核心技巧**：**前缀和 + 哈希表** 用来在 O(1) 时间内判断“是否存在以当前元素结尾的合法子数组”，结合 **贪心的最早截断** 能得到全局最优。
- **适用的题型**  
  1. “子数组和为 K” 这类只要求出现一次的计数题（LeetCode 560、974 等）。  
  2. “最多不重叠的子数组” 系列问题（如本题、Maximum Number of Non-Overlapping Subarrays With Sum Equals Target）。  
  3. “最短子数组长度 ≥ K 的和”等需要快速定位满足条件的左端点的题目。
- **一句话总结解题钥匙**：  
  **“用前缀和把子数组求和转化为两数差，用哈希表 O(1) 检查差是否出现；一旦出现就立刻截断，贪心保证最多”。**

## 反思

- **第一反应**：先想“枚举所有子数组”，然后挑不重叠的最大集合——这自然会想到 O(n²) 的暴力做法。
- **最容易踩的坑**  
  - **忘记重置哈希表**：找到一个合法子数组后，如果不清空哈希表，后面的子数组可能会与已经选中的区间重叠，导致计数错误。  
  - **处理负数**：因为数组里可能有负数，单纯的滑动窗口（只能处理正数）会失效，必须用前缀和。  
  - **边界条件**：目标值 `target = 0` 时，需要把初始的前缀和 0 记在哈希表里，否则会漏掉从开头就满足的子数组。
- **下次遇到同类题**：第一步立刻想到 **“前缀和 + 哈希表”**，再判断是否需要 **“贪心截断”**（即要求子数组互不重叠）。如果题目只要计数或判断是否存在，就不必截断；若要求**最大数量的非重叠子数组**，则必须在找到后立即截断。
