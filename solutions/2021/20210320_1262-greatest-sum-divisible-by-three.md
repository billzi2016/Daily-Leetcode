## 题目（英文原版）

**Description**

Given an integer array nums, return the maximum possible sum of elements of the array such that it is divisible by three.

**Examples**

**Example 1:**

```
Input: nums = [3,6,5,1,8]
Output: 18
Explanation: Pick numbers 3, 6, 1 and 8 their sum is 18 (maximum sum divisible by 3).
```

**Example 2:**

```
Input: nums = [4]
Output: 0
Explanation: Since 4 is not divisible by 3, do not pick any number.
```

**Example 3:**

```
Input: nums = [1,2,3,4,4]
Output: 12
Explanation: Pick numbers 1, 3, 4 and 4 their sum is 12 (maximum sum divisible by 3).
```

**Constraints**

- 1 <= nums.length <= 4 * 104
- 1 <= nums[i] <= 104

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把数组里的每一种“挑不挑”的情况都枚举一遍，也就是遍历 **所有子集**，计算每个子集的和，挑出能被 3 整除且和最大的那个。

- **用到的数据结构**：  
  - `list`（数组）存放原始数字。  
  - `int` 累计子集的和。  
  - **枚举子集** 可以用二进制掩码来实现：把每个位置的 0/1 当成“不要/要”。二进制掩码就像一本字典的“查找表”，键（mask）对应的值是“这几个位置被选了”。

- **为什么正确**：  
  因为我们把 **所有可能的选取方式** 都尝试了一遍，只要答案在某个合法子集中，就一定会被我们找到。

- **复杂度分析（大白话）**：  
  - 对于长度为 `n` 的数组，子集的个数是 `2ⁿ`（每个元素有选或不选两种可能）。  
  - 对每个子集我们要遍历 `n` 次来算和，所以时间是 `O(n·2ⁿ)`，这在 `n=20` 左右已经不可接受，更别说题目最高 `n=4·10⁴` 了。  
  - 只用了常数级的额外空间 `O(1)`（不计输入数组本身）。

#### 代码（Python）

```python
from itertools import product

def max_sum_divisible_by_three_bruteforce(nums):
    """
    暴力枚举所有子集（不推荐用于大数据）
    """
    n = len(nums)
    best = 0                     # 记录目前找到的最大合法和
    # 0/1 组合的笛卡尔积，相当于二进制掩码
    for mask in product([0, 1], repeat=n):
        cur_sum = 0
        for i, take in enumerate(mask):
            if take:               # take == 1 表示选第 i 个数
                cur_sum += nums[i]
        if cur_sum % 3 == 0:       # 只关心能被 3 整除的情况
            best = max(best, cur_sum)
    return best
```

#### 复杂度

- **时间复杂度**：`O(n·2ⁿ)` —— 解释：`2ⁿ` 是子集数量，`n` 是每个子集里要遍历的元素个数。  
- **空间复杂度**：`O(1)` —— 只用了几个整数变量，和输入规模无关。

### 2. 最优解

#### 思路  

暴力解的 **瓶颈** 在于“枚举所有子集”。我们其实不需要记住每一种选法，只要知道**在遍历到当前位置时，当前和对 3 的余数**（即 `sum % 3`）的最大可能值就行。  

这正好可以用 **动态规划（DP）** 把问题压缩到 **3 种状态**：

- `dp[0]`：当前已选元素的和 **模 3 等于 0** 时的最大和。  
- `dp[1]`：当前已选元素的和 **模 3 等于 1** 时的最大和。  
- `dp[2]`：当前已选元素的和 **模 3 等于 2** 时的最大和。

> 类比：把 `dp` 想成三格小抽屉，每格里放的数字是“到目前为止，余数对应的最大和”。  
> 每遍历一个新数字 `x`，我们可以 **把它放进已有的每个抽屉**（即把 `x` 加到原来的和上），得到新的余数和新和。如果新和比抽屉里已有的更大，就把抽屉更新。

**具体步骤**：

1. 初始化 `dp = [0, -inf, -inf]`。因为空集合的和是 0，余数 0 的最大和是 0；余数 1、2 暂时不可达，用负无穷表示。  
2. 对数组中的每个数 `num`：  
   - 先拷贝一份当前的 `dp`（防止在同一次循环里使用已经更新的值）。  
   - 对每个余数 `r`（0、1、2），计算新余数 `new_r = (r + num) % 3`，并尝试更新 `dp[new_r] = max(dp[new_r], old_dp[r] + num)`。  
3. 循环结束后，`dp[0]` 就是答案——最大且能被 3 整除的和。

**为什么这一步比暴力快**：

- 我们只维护 **3 条信息**，而不是指数级的所有子集。  
- 每个元素只遍历一次，且内部只循环 3 次，所以整体是线性 `O(n)`。

> 还有一种 **贪心+排序** 的思路：先把所有数相加得到总和 `S`，如果 `S % 3 == 0` 直接返回；否则把余数为 `S%3` 的最小数删掉，或者删掉两个余数为 `3 - S%3` 的最小数。该思路同样是 `O(n log n)`（排序），但 DP 更直观且不需要排序，代码更简洁。

#### 代码（Python）

```python
def max_sum_divisible_by_three(nums):
    """
    动态规划：只保留余数为 0/1/2 时的最大和
    时间 O(n)  空间 O(1)
    """
    INF_NEG = -10**9            # 代表 “不可能的” 很小的数
    dp = [0, INF_NEG, INF_NEG] # dp[0] = 0, dp[1] = dp[2] = -inf

    for num in nums:
        # 先把当前 dp 复制一份，防止同一次循环里使用已更新的值
        old = dp[:]             
        for r in range(3):       # r 代表原来的余数
            if old[r] == INF_NEG:
                continue          # 这个余数目前不可达，跳过
            new_r = (r + num) % 3
            dp[new_r] = max(dp[new_r], old[r] + num)
            # 上面这行的意义：把 num 加到原来余数为 r 的最大和上，
            # 得到新的余数 new_r，若新和更大就更新抽屉
    return dp[0]                  # 余数为 0 时的最大和即为答案
```

#### 复杂度

- **时间复杂度**：`O(n)` —— 解释：遍历一次数组，每个元素只做常数次（3 次）更新。相比暴力的 `O(n·2ⁿ)`，快了几何级别。  
- **空间复杂度**：`O(1)` —— 只用了固定大小的 `dp` 列表，和数组长度无关。

## 心得

- **核心技巧**：使用“余数 DP”。把“能被 3 整除”这个全局约束转化为“当前和对 3 的余数”这 3 种局部状态。  
- **适用的题型**：  
  1. “最大和能被 k 整除” 类似题（如 `Greatest Sum Divisible by K`）。  
  2. “最小移除使数组和满足某余数” 或 “子集和同余” 的 DP/贪心问题。  
- **一句话总结解题钥匙**：**只维护 3 种余数对应的最大和，循环一次即可得到答案**。

## 反思

- **第一反应**：直接想把所有子集枚举出来检查合法性。  
- **最容易踩的坑**：  
  - 初始化时忘记把不可达的余数设为负无穷，导致后面 `max` 操作把错误的 0 覆盖。  
  - 更新 `dp` 时直接在原数组上修改会导致同一个 `num` 被使用多次，需要先拷贝或使用临时变量。  
- **下次遇到同类题**：第一步先思考“能否把全局约束（可被 k 整除）转化为余数状态”，然后用 **状态压缩 DP**（只保留 k 条信息）来线性遍历。
