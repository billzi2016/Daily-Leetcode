# #1144. 降低元素使数组呈锯齿形 / Decrease Elements To Make Array Zigzag

## 题目（英文原版）

**Description**

Given an array nums of integers, a move consists of choosing any element and decreasing it by 1.
An array A is a zigzag array if either:
Return the minimum number of moves to transform the given array nums into a zigzag array.

**Examples**

**Example 1:**

```
Input: nums = [1,2,3]
Output: 2
Explanation: We can decrease 2 to 0 or 3 to 1.
```

**Example 2:**

```
Input: nums = [9,6,1,6,2]
Output: 4
```

**Constraints**

- 1 <= nums.length <= 1000
- 1 <= nums[i] <= 1000

## 题目（中文翻译）

给定一个整数数组 `nums`，一次操作指选择任意下标的元素并将其减小 1。  
如果数组 `A` 满足以下任意一种情况，则称其为**锯齿数组（zigzag array）**：

* 对所有奇数下标 `i`（`i` 为 1, 3, 5, …），都有 `A[i] < A[i‑1]` 且 `A[i] < A[i+1]`；  
* 对所有奇数下标 `i`（`i` 为 1, 3, 5, …），都有 `A[i] > A[i‑1]` 且 `A[i] > A[i+1]`。

返回将给定数组 `nums` 转换成锯齿数组所需的最少操作次数。

**示例 1**  
**输入**: `nums = [1,2,3]`  
**输出**: `2`  
**解释**: 我们可以将 `2` 减小到 `0`，或将 `3` 减小到 `1`，共需要 2 步。

**示例 2**  
**输入**: `nums = [9,6,1,6,2]`  
**输出**: `4`

**约束条件**  

- `1 <= nums.length <= 1000`  
- `1 <= nums[i] <= 1000`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**把数组不停地改，直到满足锯齿形**。  
具体可以这么做：

1. 先判断当前数组是否已经是锯齿形（两种模式都可以）。
2. 若不是，就遍历所有下标 `i`，检查 `i` 是否满足“比左右邻居都大”或“比左右邻居都小”。  
3. 对不满足的元素，**把它减 1**（因为题目只允许把元素减小），然后回到第 1 步继续检查。

> **类比**：把数组想成一排小山丘和谷地。我们每次只能把山丘的高度往下削一点，直到整排山谷和山峰交替出现。

> **为什么正确**：只要我们不停地把“不符合要求”的元素往下削，最终一定会得到一个满足要求的数组——因为每次削的方向都是让它更容易满足“比邻居小”。只要把所有违规点都削到足够低，锯齿形就出现了。

> **缺点**：我们没有一次性算出需要削多少，而是**一步一步**削，可能会重复检查同一个位置，导致时间浪费。

#### 代码（Python）

```python
def is_zigzag(nums):
    """检查 nums 是否已经是锯齿形（两种模式任意一种）"""
    n = len(nums)
    # 模式 1：偶数下标是峰（>），奇数下标是谷（<）
    ok1 = all(nums[i] > nums[i+1] for i in range(0, n-1, 2)) and \
          all(nums[i] < nums[i+1] for i in range(1, n-1, 2))
    # 模式 2：奇数下标是峰，偶数下标是谷
    ok2 = all(nums[i] < nums[i+1] for i in range(0, n-1, 2)) and \
          all(nums[i] > nums[i+1] for i in range(1, n-1, 2))
    return ok1 or ok2


def brute_force(nums):
    """暴力模拟每次把不合规的元素减 1，返回总共的减法次数"""
    moves = 0
    arr = nums[:]                     # 复制一份，避免修改原数组
    while not is_zigzag(arr):         # 只要不是锯齿形，就继续削
        n = len(arr)
        for i in range(n):
            left  = arr[i-1] if i-1 >= 0 else float('inf')
            right = arr[i+1] if i+1 < n else float('inf')
            # 判断 i 在两种模式下是否需要是“谷”
            need_valley = (i % 2 == 1) or (i % 2 == 0 and n % 2 == 0)
            # 这里用最保守的判断：如果 i 比左或右大，就把它减 1
            if arr[i] >= left or arr[i] >= right:
                arr[i] -= 1
                moves += 1
    return moves
```

> **注意**：上述代码仅用于演示暴力思路，**实际运行会非常慢**，因为每次只能把一个元素减 1，最坏情况下会进行上千次循环。

#### 复杂度

- **时间复杂度**：`O(n * M)`，其中 `n` 为数组长度，`M` 为需要的最大总减次数。最坏情况下每个元素都要减到 0，`M` 可能接近 `1000 * n`，所以整体是 **近似 `O(n²)`** 的量级。用大白话说，就是“如果数组有 1000 个数，可能要检查并减 1000 次，整个过程会像 1000×1000 那么多步”。
- **空间复杂度**：`O(1)`（只用了常数级的额外变量），因为我们在原数组上就地修改。

### 2. 最优解

#### 思路  

从暴力解可以看出，**瓶颈在于我们一次只能把元素减 1，而实际上我们可以一次算出每个位置到底要减多少**。  
观察锯齿形的定义：

- **模式 A**（偶数下标是峰）：`nums[0] > nums[1] < nums[2] > nums[3] < …`
- **模式 B**（奇数下标是峰）：`nums[0] < nums[1] > nums[2] < nums[3] > …`

无论是哪种模式，**所有“谷”位置的元素必须严格小于左右邻居**。  
因此我们只需要关注“谷”所在的下标，分别计算把它们变成谷所需的最少减次数，然后把所有这些次数相加，就是把数组变成该模式的总代价。

**如何一次算出每个谷需要减多少？**  
设下标 `i` 为谷（即 `i` 的左右邻居必须比它大）。令

```
left  = nums[i-1]   （若 i 为第一个元素则视为 +∞）
right = nums[i+1]   （若 i 为最后一个元素则视为 +∞）
target = min(left, right) - 1   # 为了严格小于邻居，最多只能到这个值
```

如果 `nums[i]` 已经 ≤ `target`，不需要任何操作；否则需要 **减去 `nums[i] - target`**。这一步可以直接算出来，不必循环。

我们把所有奇数下标当作谷（对应模式 A）求一次总代价，记为 `cost_odd`；再把所有偶数下标当作谷（对应模式 B）求一次总代价，记为 `cost_even`。答案就是两者的最小值。

> **类比**：想象每个谷是一块低洼的土地，我们只需要一次性把它填平到比左右两座小山稍低一点的高度，而不是一步一步搬砖。  
> **核心技巧**：**贪心**——对每个局部位置都做“局部最优”，因为每个谷的减操作互不影响，局部最优自然累计成全局最优。

#### 代码（Python）

```python
def min_moves_to_zigzag(nums):
    """
    返回把数组变成锯齿形所需的最少减次数。
    思路：分别统计两种模式下“谷”位置的减法次数，取最小值。
    """
    n = len(nums)

    def cost_for_valleys(valley_indices):
        """计算把指定下标集合都变成谷所需的总减次数"""
        moves = 0
        for i in valley_indices:
            left  = nums[i-1] if i-1 >= 0 else float('inf')
            right = nums[i+1] if i+1 < n else float('inf')
            # 为了严格小于邻居，目标值必须 ≤ min(left, right) - 1
            target = min(left, right) - 1
            if nums[i] > target:                # 只在需要时才减
                moves += nums[i] - target
        return moves

    # 模式 A：奇数下标是谷（即偶数下标是峰）
    odd_valley = range(1, n, 2)
    cost_odd = cost_for_valleys(odd_valley)

    # 模式 B：偶数下标是谷（即奇数下标是峰）
    even_valley = range(0, n, 2)
    cost_even = cost_for_valleys(even_valley)

    return min(cost_odd, cost_even)
```

> **代码要点解释**  
> - `float('inf')` 相当于“无限大”，用来处理数组两端只有一个邻居的情况，使得 `min(left, right)` 实际上只会取到唯一的真实邻居。  
> - `range(1, n, 2)` 产生所有奇数下标，`range(0, n, 2)` 产生所有偶数下标。  
> - `moves += nums[i] - target` 这一步一次性把 `i` 位置降低到恰好比邻居小 1 的值，省掉了循环。

#### 复杂度

- **时间复杂度**：`O(n)`。我们只遍历数组两遍（一次算奇数谷，一次算偶数谷），每个元素的计算都是 **常数时间**。用大白话说，就是“把 1000 个数看一遍就能算出答案”，比暴力的上千次循环快很多。  
- **空间复杂度**：`O(1)`。只用了几个整数变量，没有额外的数组或递归栈。

## 心得

- **核心技巧**：**贪心 + 局部最优** —— 把每个“谷”位置需要的最小减次数直接算出来，所有谷的操作互不冲突，累加即为全局最优。  
- **适用场景**：  
  1. **数组局部约束**（如相邻元素大小关系）的问题，例如 “让数组成为交替递增递减序列”。  
  2. **只允许单向修改**（只能增或只能减）的最小化改动题，例如 “最少增/减次数使数组严格递增”。  
  3. **独立子问题求和** 的贪心题，如 “最小移动次数使所有相邻字符不同”。  
- **一句话总结**：把每个必须满足的局部条件一次性算好，别把同一个位置削多次——**一次算清楚，直接相加**。

## 反思

- **第一反应**：看到“只能减”，立刻想到“把不符合的元素逐个减 1”，于是写出了暴力模拟。  
- **最容易踩的坑**：  
  - 忽略数组两端只有一个邻居，需要用 `+∞` 或者单独判断来避免越界。  
  - “严格小于”而不是 “小于等于”，所以目标值是 `min(left, right) - 1`，容易写成 `- 0` 导致答案偏大。  
  - 把两种锯齿模式混在一起求和，实际上每种模式对应的“谷”下标集合是互斥的，必须分别计算后取最小值。  
- **下次类似题的第一步**：先**明确局部约束**（哪个位置需要大于/小于邻居），判断这些约束是否相互独立；若独立，就可以**直接计算每个位置的最小改动量**，而不是一步步模拟。这样往往能把时间复杂度从 “指数/平方” 降到 “线性”。
