## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：

1. **把三张表全部拼在一起**  
   - `Movies` 保存电影信息，像一本电影目录；  
   - `MovieRating` 保存每个用户对每部电影的打分，想象成一张“电影‑用户‑评分”记录表；  
   - `Users` 只在本题里不需要参与计算（如果需要返回用户信息才会用到），这里我们先不使用它。

2. **把同一部电影的所有评分聚在一起**，用 `GROUP BY movie_id`（把相同 `movie_id` 的行放到一堆）  
   - 然后用 `AVG(rating)` 计算这堆评分的平均值——这一步相当于“把所有评分加起来再除以人数”，得到每部电影的**平均评分**。

3. **找出平均评分最高的电影**  
   - 先把每部电影的平均分算出来，放进一个临时表 `movie_avg`；  
   - 再查询 `movie_avg` 中的最大值 `MAX(avg_rating)`；  
   - 最后把平均分等于这个最大值的电影挑出来（可能会有多部电影并列第一）。

> **为什么这个方法能得到正确答案？**  
> 因为我们对每部电影都完整地统计了它所有的评分，平均分就是这部电影受欢迎程度的客观度量。再取最高的平均分，自然就是最受用户喜爱的电影。

> **时间/空间复杂度**  
> - **时间复杂度 O(N)**：`N` 为 `MovieRating` 表的行数。我们只需要一次遍历把所有评分分组求和，再一次遍历找最大值，都是线性时间。  
> - **空间复杂度 O(M)**：`M` 为电影的数量。我们需要为每部电影保存累计的评分总和和计数（或直接保存平均分），这需要额外的 `M` 条记录。

> 大白话解释：  
> - `O(N)` 就像你要把一箱子糖果全部数一遍，需要的时间正比于糖果的数量；  
> - `O(M)` 就像你只需要记下每种糖果的种类数目，种类越多占的空间越大。

#### 代码（Python）

下面用 **Python + SQLite**（或任意支持 SQL 的库）演示如何把上述思路写成可运行的代码。关键行都有中文注释。

```python
import sqlite3

# -------------------------------------------------
# 1️⃣ 先准备演示用的内存数据库（实际提交只写 SQL）
# -------------------------------------------------
conn = sqlite3.connect(":memory:")
cur = conn.cursor()

# 创建表结构（省略了 Users 表，因为本题不需要）
cur.executescript("""
CREATE TABLE Movies (
    movie_id INTEGER PRIMARY KEY,
    title    TEXT
);
CREATE TABLE MovieRating (
    movie_id   INTEGER,
    user_id    INTEGER,
    rating     INTEGER,
    created_at DATE,
    PRIMARY KEY (movie_id, user_id)
);
""")

# -------------------------------------------------
# 2️⃣ 插入示例数据（和题目示例保持一致）
# -------------------------------------------------
movies = [(1, 'Avengers'), (2, 'Frozen 2'), (3, 'Joker')]
ratings = [
    (1, 1, 5, '2020-01-01'),
    (1, 2, 4, '2020-01-02'),
    (2, 1, 3, '2020-01-01'),
    (2, 3, 5, '2020-01-03'),
    (3, 2, 5, '2020-01-02'),
    (3, 3, 5, '2020-01-04')
]
cur.executemany("INSERT INTO Movies VALUES (?, ?);", movies)
cur.executemany("INSERT INTO MovieRating VALUES (?, ?, ?, ?);", ratings)
conn.commit()

# -------------------------------------------------
# 3️⃣ 暴力解：先算每部电影的平均分，再找最大值
# -------------------------------------------------
# ① 计算每部电影的平均评分
cur.execute("""
    SELECT
        mr.movie_id,
        AVG(mr.rating) AS avg_rating          -- 计算平均分
    FROM MovieRating mr
    GROUP BY mr.movie_id
""")
movie_avg = cur.fetchall()          # [(1, 4.5), (2, 4.0), (3, 5.0)]

# 把平均分保存到临时表（SQLite 支持 WITH 子句，也可以直接用子查询，这里为演示方便用 Python）
max_avg = max(avg for _, avg in movie_avg)   # 5.0

# ② 取出平均分等于最大值的电影
cur.execute("""
    SELECT m.title, a.avg_rating
    FROM Movies m
    JOIN (
        SELECT
            mr.movie_id,
            AVG(mr.rating) AS avg_rating
        FROM MovieRating mr
        GROUP BY mr.movie_id
    ) a
    ON m.movie_id = a.movie_id
    WHERE a.avg_rating = (
        SELECT MAX(avg_rating) FROM (
            SELECT AVG(rating) AS avg_rating
            FROM MovieRating
            GROUP BY movie_id
        )
    );
""")
result = cur.fetchall()
print(result)   # [('Joker', 5.0)]

# -------------------------------------------------
# 4️⃣ 关闭连接
# -------------------------------------------------
conn.close()
```

#### 复杂度

- **时间复杂度**：`O(N)` —— 只遍历一次 `MovieRating` 表（`N` 为评分条数），再一次遍历得到的聚合结果（行数等于电影数量 `M`，`M ≤ N`），整体仍然是线性。
- **空间复杂度**：`O(M)` —— 需要保存每部电影的累计评分和计数（或平均分），这里的 `M` 是电影的种类数。

### 2. 最优解

#### 思路  

暴力解已经是 **线性时间**，已经很快了。但我们可以把两次遍历（一次算平均分，一次再找最大值）合并成一次，用 **窗口函数**（`RANK` / `DENSE_RANK`）直接在同一条查询里得到“最高平均分的电影”。这样：

1. **先把 `MovieRating` 按电影分组，算出 `avg_rating`**（这一步必须有）。
2. **在同一查询里对 `avg_rating` 做排序并打上排名**，使用 `RANK() OVER (ORDER BY avg_rating DESC)`。排名为 1 的就是最高平均分。
3. **只保留排名为 1 的记录**，再和 `Movies` 表关联得到电影标题。

> **核心技巧：窗口函数（Window Function）**  
> - 想象把所有电影的平均分排成一条长队，窗口函数就像一个自动标号的裁判，能在不拆表的情况下把每个人的名次写在他们身上。  
> - `RANK()` 会把并列第一的电影都标记为 1，正好满足“可能有多部电影并列最高”的需求。

> **为什么更好？**  
> - 只写一条 SQL，数据库内部会一次性完成分组、排序、打标的全部工作，避免了子查询的重复扫描。  
> - 对大数据集（上百万条评分）来说，减少一次全表扫描可以显著提升性能。

> **时间/空间复杂度**  
> - **时间复杂度仍是 O(N)**，因为分组仍然需要遍历所有评分；但实际执行计划只会出现一次 **聚合+排序**，而不是两次。  
> - **空间复杂度 O(M)**，需要为每部电影保存聚合结果和排名。

#### 代码（Python）

同样使用 SQLite 进行演示，核心是 **一条 SQL**：

```python
import sqlite3

conn = sqlite3.connect(":memory:")
cur = conn.cursor()

#（表结构和示例数据同上，略去创建和插入过程）

# -------------------------------------------------
# 2️⃣ 最优解：使用窗口函数一次搞定
# -------------------------------------------------
cur.execute("""
    WITH movie_avg AS (
        SELECT
            mr.movie_id,
            AVG(mr.rating) AS avg_rating
        FROM MovieRating mr
        GROUP BY mr.movie_id
    ),
    ranked AS (
        SELECT
            movie_id,
            avg_rating,
            RANK() OVER (ORDER BY avg_rating DESC) AS rnk   -- 给平均分排名
        FROM movie_avg
    )
    SELECT
        m.title,
        r.avg_rating
    FROM ranked r
    JOIN Movies m ON m.movie_id = r.movie_id
    WHERE r.rnk = 1;           -- 只取最高排名（可能有多条）
""")
print(cur.fetchall())   # [('Joker', 5.0)]
conn.close()
```

> **关键行解释**  
> - `WITH movie_avg AS (...)`：先把每部电影的平均分算出来，类似临时表。  
> - `RANK() OVER (ORDER BY avg_rating DESC)`：在所有平均分里按从高到低排名。  
> - `WHERE r.rnk = 1`：只保留排名第一的电影，即最高平均分的电影。

#### 复杂度

- **时间复杂度**：`O(N)` —— 只遍历一次 `MovieRating` 表完成聚合，随后对 `M` 条聚合结果做一次排序（`M ≤ N`），整体仍然是线性级别。  
- **空间复杂度**：`O(M)` —— 需要存放每部电影的平均分和排名。

## 心得

- **核心技巧**：**窗口函数**（`RANK/DENSE_RANK`）可以在一次查询里完成“分组统计 + 排名”两件事，避免子查询的重复扫描。  
- **适用场景**：  
  1. 找出**最高/最低**平均分、总分、销售额等（如 `Employee Salary`、`Product Sales`）。  
  2. 需要**并列第一**或**前 K 名**的业务统计（如 `Top 3 Highest Paid Employees`）。  
  3. 计算**累计和**、**移动平均**等需要对分组结果再做计算的情形。  
- **一句话总结**：**“先把每组的关键指标算出来，再用窗口函数一次性挑出排名第一的记录”。**

## 反思

- **拿到题目第一反应**：先把三张表 `JOIN`，用 `GROUP BY` 计算每部电影的平均评分，再找最大值。  
- **最容易踩的坑**：  
  - **并列第一**：如果直接用 `ORDER BY avg_rating DESC LIMIT 1`，只能返回一条记录，可能遗漏同分的电影。  
  - **空表或没有评分的电影**：需要确保只对有评分的电影进行计算，或者在 `LEFT JOIN` 时用 `COALESCE` 处理 `NULL`。  
  - **数据量大时的性能**：多层子查询会导致数据库重复扫描同一张大表。  
- **下次遇到同类题**：第一步就想到 **“先聚合 → 再排名”**，并优先考虑 **窗口函数**（`RANK/DENSE_RANK`）来一次性完成。这样既保证正确性，又能得到最优的执行计划。
