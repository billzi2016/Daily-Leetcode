# #1406. 石子游戏 III / Stone Game III

> 难度：困难 · 标签：Array、Math、Dynamic Programming、Game Theory · [LeetCode 链接](https://leetcode.com/problems/stone-game-iii/)

## 题目（英文原版）

**Description**

Alice and Bob continue their games with piles of stones. There are several stones arranged in a row, and each stone has an associated value which is an integer given in the array stoneValue.
Alice and Bob take turns, with Alice starting first. On each player's turn, that player can take 1, 2, or 3 stones from the first remaining stones in the row.
The score of each player is the sum of the values of the stones taken. The score of each player is 0 initially.
The objective of the game is to end with the highest score, and the winner is the player with the highest score and there could be a tie. The game continues until all the stones have been taken.
Assume Alice and Bob play optimally.
Return "Alice" if Alice will win, "Bob" if Bob will win, or "Tie" if they will end the game with the same score.

**Examples**

**Example 1:**

```
Input: stoneValue = [1,2,3,7]
Output: "Bob"
Explanation: Alice will always lose. Her best move will be to take three piles and the score become 6. Now the score of Bob is 7 and Bob wins.
```

**Example 2:**

```
Input: stoneValue = [1,2,3,-9]
Output: "Alice"
Explanation: Alice must choose all the three piles at the first move to win and leave Bob with negative score.
If Alice chooses one pile her score will be 1 and the next move Bob's score becomes 5. In the next move, Alice will take the pile with value = -9 and lose.
If Alice chooses two piles her score will be 3 and the next move Bob's score becomes 3. In the next move, Alice will take the pile with value = -9 and also lose.
Remember that both play optimally so here Alice will choose the scenario that makes her win.
```

**Example 3:**

```
Input: stoneValue = [1,2,3,6]
Output: "Tie"
Explanation: Alice cannot win this game. She can end the game in a draw if she decided to choose all the first three piles, otherwise she will lose.
```

**Constraints**

- 1 <= stoneValue.length <= 5 * 104
- -1000 <= stoneValue[i] <= 1000

## 题目（中文翻译）

Alice 和 Bob 继续他们的石子堆游戏。若干颗石子排成一行，每颗石子都有一个整数值，存放在数组 `stoneValue` 中。  
Alice 与 Bob 轮流取石子，Alice 先手。每回合，当前玩家只能从行首取走 **1、2 或 3 颗**石子（即取走前面的 1、2、3 个石子）。  
每位玩家的得分等于他取走的所有石子值的总和，初始得分均为 **0**。  
游戏目标是使自己的得分最高，得分最高者获胜，若得分相同则为平局。游戏在所有石子被取完后结束。  
假设双方都采用最优策略。  

返回以下字符串之一：  
- `"Alice"` ：Alice 能获胜  
- `"Bob"` ：Bob 能获胜  
- `"Tie"` ：双方得分相同  

**示例 1**  
```text
Input: stoneValue = [1,2,3,7]
Output: "Bob"
Explanation: Alice 无论怎么走都会输。她最好的选择是一次取走三颗石子，此时她的得分为 6。随后 Bob 取走剩下的 7，得分为 7，Bob 获胜。
```

**示例 2**  
```text
Input: stoneValue = [1,2,3,-9]

- 若 Alice 取走两颗石子，她的得分为 3，随后 Bob 取走剩下的两颗石子得分也为 3，随后游戏结束平局。...

```

**约束条件**

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把整个游戏当成 **完全搜索**（DFS）——每轮轮到的玩家可以选择拿走 1、2、或 3 块石头，然后递归地让对手继续游戏，直到所有石头都被取完。  
- **数据结构**：我们只需要一个数组 `stoneValue` 保存每块石头的分值，递归时用一个整数 `i` 表示“当前轮到的第 `i` 块石头”。  
- **类比**：这就像在玩 “从左到右挑糖果”，每次可以挑 1、2、3 颗，挑完后把手交给对手继续挑。  
- **正确性**：因为我们在每一步都枚举了玩家的所有合法选择，并且递归地让对手也枚举所有选择，最终会遍历 **所有可能的游戏进程**。只要我们在递归返回时把“当前玩家最终能得到的相对分数”（自己得分减去对手得分）算出来，就一定能得到最优结果。  

#### 代码（Python）

```python
from functools import lru_cache
from typing import List

def stoneGameIII_brute(stoneValue: List[int]) -> str:
    n = len(stoneValue)

    # -------------------------------------------------
    # dfs(i) 返回：从下标 i 开始，**当前玩家**相对于对手的最大分差
    # -------------------------------------------------
    @lru_cache(None)                 # 记忆化，防止重复计算（纯暴力会超时，这里加缓存仅为演示）
    def dfs(i: int) -> int:
        if i >= n:                    # 所有石头已被取完
            return 0

        best = -float('inf')          # 先设一个很小的值，后面会取最大
        take_sum = 0                  # 累计本轮拿走的石头价值

        # 玩家可以拿 1、2、3 块石头
        for k in range(1, 4):
            if i + k - 1 >= n:        # 超出数组范围就不合法
                break
            take_sum += stoneValue[i + k - 1]      # 累加第 k 块石头的价值
            # 对手从 i+k 开始的最优分差是 dfs(i+k)，
            # 当前玩家的分差 = 本轮拿到的分数 - 对手的最优分差
            best = max(best, take_sum - dfs(i + k))

        return best

    diff = dfs(0)                     # Alice 从第 0 块石头开始

    if diff > 0:
        return "Alice"
    if diff < 0:
        return "Bob"
    return "Tie"
```

> **关键行中文注释** 已在代码中标明。

#### 复杂度  

- **时间复杂度**：`O(3^n)`（每一步有 3 种选择，深度为 n，理论上会产生指数级的递归树）。  
  - 大白话：如果石头有 20 块，最坏情况下要尝试 3⁽²⁰⁾ ≈ 3.5 × 10⁹ 种可能，几乎不可能在电脑里跑完。  
- **空间复杂度**：`O(n)`，递归栈的最大深度为 n（最多一次只会保留从根到叶的路径）。

### 2. 最优解

#### 思路  

从暴力解可以看出 **状态只和当前下标 i 有关**，而且每次决策只会影响接下来的一小段（最多 3 个）石头。  
这正好符合 **动态规划**（DP）的特点：把大问题拆成子问题，记录每个子问题的最优解，避免重复计算。

**核心观察**  
- 对手也会采用最优策略。  
- 如果我们知道从位置 `i` 开始，**当前玩家**相对于对手的最大分差 `dp[i]`，那么在 `i` 位置的决策可以写成：

```
dp[i] = max( takeSum(k) - dp[i + k] )   , k = 1,2,3 且 i+k ≤ n
```

其中 `takeSum(k)` 是从 `i` 开始连续拿走 `k` 块石头的价值总和。  
- 解释：拿走 `k` 块后，轮到对手，从 `i+k` 开始的局面对手能得到的相对分差是 `dp[i+k]`（对手视角），所以 **我们** 的分差就是 `自己本轮得分 - 对手的相对分差**。我们希望这个值最大。

**从后往前推**  
因为 `dp[i]` 依赖于 `dp[i+1]、dp[i+2]、dp[i+3]`，可以从数组右端向左遍历，逐步填表。  
- 初始化：`dp[n] = 0`（没有石头时分差为 0）。  
- 逐步计算 `i = n-1 … 0`。

**为什么不需要前缀和**  
直接在循环里累计 `takeSum` 即可，最多累加 3 次，时间开销极小。  

**结果判断**  
- `dp[0] > 0` → Alice 能取得更高的总分，返回 `"Alice"`。  
- `dp[0] < 0` → Bob 能取得更高的总分，返回 `"Bob"`。  
- `dp[0] == 0` → 双方分数相同，返回 `"Tie"`。

#### 代码（Python）

```python
from typing import List

def stoneGameIII(stoneValue: List[int]) -> str:
    n = len(stoneValue)
    dp = [0] * (n + 1)          # dp[i] 表示从 i 开始当前玩家的最大分差

    # 从后往前填表
    for i in range(n - 1, -1, -1):
        best = -float('inf')
        take_sum = 0

        # 枚举可以拿的 1~3 块石头
        for k in range(1, 4):
            if i + k > n:       # 越界则停止
                break
            take_sum += stoneValue[i + k - 1]          # 累计第 k 块石头的价值
            # 计算拿 k 块后的分差：本轮得分 - 对手在 i+k 处的最优分差
            best = max(best, take_sum - dp[i + k])

        dp[i] = best            # 保存从 i 开始的最优分差

    diff = dp[0]                # 整局游戏 Alice 的相对分差
    if diff > 0:
        return "Alice"
    if diff < 0:
        return "Bob"
    return "Tie"
```

> 代码中的每一步都配有中文注释，帮助初学者对照思路。

#### 复杂度  

- **时间复杂度**：`O(n)`。  
  - 每个下标 `i` 只循环最多 3 次，整体线性遍历。相比指数级的暴力解，快了好几百倍。  
- **空间复杂度**：`O(n)`（存 `dp` 表）。  
  - 也可以用 **滚动数组** 只保留最近的 3 个状态，将空间降到 `O(1)`，但对初学者来说完整的 `dp` 表更易理解。

## 心得

- **核心技巧**：把两人零和的博弈转化为“当前玩家相对于对手的最大分差”，并用**动态规划**自后向前求解。  
- **适用题型**  
  1. **Stone Game 系列**（Stone Game I/II/III、Stone Game IV 等）  
  2. **Predict the Winner**（两人轮流取数，目标是赢）  
  3. **Take-Away Games**（如 Nim 变体，只能取固定个数）  
- **一句话总结**：**把“谁赢”转化为“分差最大化”，用 DP 把递归公式自底向上填表**。

## 反思

- **第一反应**：看到“每回合只能取 1~3 块”，立刻想到递归枚举所有可能。  
- **最容易踩的坑**  
  1. **负数石头**：石头价值可以为负，不能假设所有取的分数都是递增的。  
  2. **边界条件**：当剩余石头少于 3 块时，循环必须提前结束，防止越界。  
  3. **分差符号**：记得 `dp[i]` 是“当前玩家的得分 - 对手的得分”，方向很重要，写反会导致答案全相反。  
- **下次遇到同类题**：第一步先**写出递归公式** `best = max(take - recurse(next))`，再**考虑自底向上 DP**，并检查取值范围是否会出现负数或越界。
