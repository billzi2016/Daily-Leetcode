# #1291. 顺序数字 / Sequential Digits

> 难度：中等 · 标签：Enumeration · [LeetCode 链接](https://leetcode.com/problems/sequential-digits/)

---

## 题目（英文原版）

**Description**

An integer has sequential digits if and only if each digit in the number is one more than the previous digit.
Return a sorted list of all the integers in the range [low, high] inclusive that have sequential digits.

**Examples**

**Example 1:**

```
Input: low = 100, high = 300
Output: [123,234]
```

**Example 2:**

```
Input: low = 1000, high = 13000
Output: [1234,2345,3456,4567,5678,6789,12345]
```

**Constraints**

- 10 <= low <= high <= 10^9

---

## 题目（中文翻译）

整数只有在每个数字恰好比前一个数字大 1 时，才称其为顺序数字（sequential digits）。返回区间 `[low, high]`（闭区间）内所有满足该条件的整数，按升序返回。

示例 1:
Input: low = 100, high = 300
Output: [123,234]

示例 2:
Input: low = 1000, high = 13000
Output: [1234,2345,3456,4567,5678,6789,12345]

约束条件：
- 10 <= low <= high <= 10^9

---

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**把区间 `[low, high]` 中的每一个整数都枚举出来，逐个判断它是否满足“相邻数字相差恰好为 1”**。  
判断过程可以把整数转成字符串（或数组），然后检查相邻字符的差值是否都是 1。  

> **类比**：把数字想象成一串珠子，珠子上的数字如果每颗都比左边那颗大 1，就算是“顺序珠”。我们把所有珠子（即所有整数）都拿出来检查一遍。

这种做法显然是正确的——只要遍历到了所有可能的数，就一定不会漏掉符合条件的答案。

但是我们要注意 **时间**：如果 `low = 10`，`high = 10⁹`，区间长度将近 `10⁹`，逐个检查的代价是 **十亿次**，在实际运行时根本不可接受。

#### 代码（Python）

```python
def sequential_digits_bruteforce(low: int, high: int):
    res = []
    for num in range(low, high + 1):          # 逐个遍历区间内的整数
        s = str(num)                           # 把整数转成字符串，方便逐位比较
        ok = True
        for i in range(1, len(s)):
            # 判断相邻两个字符的差值是否为 1
            if int(s[i]) - int(s[i - 1]) != 1:
                ok = False
                break
        if ok:
            res.append(num)                     # 符合条件就加入答案
    return res
```

#### 复杂度  

- **时间复杂度**：`O(high - low + 1) * O(d)`，其中 `d` 为数字的位数（最多 10），可以简化为 `O(high - low)`。  
  > 大白话：我们要检查区间里每一个数，区间有多少数，就要做多少次检查，几乎是线性增长的。  
- **空间复杂度**：`O(k)`，`k` 为答案的个数（最坏情况下也不会超过 9·9 = 81），额外的存储基本是常数级。

> **结论**：虽然思路最直观，但在题目给出的上限 `10⁹` 时，这种“挨个敲门”的方法会超时。

---

### 2. 最优解

#### 思路  

从暴力解可以看到，**真正的瓶颈在于遍历了太多无关的数字**。我们其实可以直接**生成所有可能的“顺序数字”**，再挑选出落在 `[low, high]` 区间的即可。

**关键观察**：

1. “顺序数字”只能由 1~9 这 9 个起始数字构造。比如以 `1` 开头可以得到 `12, 123, 1234 … 123456789`；以 `5` 开头可以得到 `56, 567, 5678 … 56789`。
2. 每个起始数字最多只能往后加到 `9`，所以最长的顺序数字长度为 9（`123456789`）。因此**所有可能的顺序数字总数不超过 9×9 = 81**，是一个极小的集合。
3. 因此我们可以 **枚举起始数字 `start`（1~9）**，**枚举长度 `len`（2~9）**，**依次拼接递增的数字**，得到每一个候选数。最后只保留 `low ≤ num ≤ high` 的即可。

> **类比**：把 1~9 看成 9 本“连环画”。从每本的第一页开始往后翻，翻几页就得到一个“顺序数字”。我们只需要把所有可能的连环画页码列出来，然后挑出在给定区间的。

**实现细节**：

- 用一个 `for start in range(1, 10)` 循环遍历起始数字。  
- 在内部维护一个 `num`，初始为 `start`，随后在另一个循环里不断 **`num = num * 10 + (next_digit)`**，其中 `next_digit` 是前一位数字加 1。这样可以一次性在十进制上“右移并追加”新数字。  
- 每生成一个新 `num`，立即检查它是否在 `[low, high]` 区间内，如果是就加入结果列表。  
- 因为我们是按 `start` 从小到大、长度从短到长的顺序生成的，最终的 `res` 已经是升序的，无需额外排序。

#### 代码（Python）

```python
def sequentialDigits(low: int, high: int):
    """
    生成所有顺序数字并返回位于 [low, high] 区间的部分。
    由于总数只有 81 个，时间复杂度极低。
    """
    res = []
    # start: 起始数字 1~9
    for start in range(1, 10):
        num = start                # 当前构造的数字，初始为起始数字
        next_digit = start + 1     # 下一个要追加的数字
        # 只要 next_digit <= 9，就可以继续往后拼接
        while next_digit <= 9:
            num = num * 10 + next_digit   # 在十进制左移一位并加上新数字
            if low <= num <= high:         # 若落在区间则加入答案
                res.append(num)
            next_digit += 1                # 准备追加更大的下一位
    return res
```

#### 复杂度  

- **时间复杂度**：`O(81)`，即常数时间。因为我们最多只会生成 81 个候选数（9 个起始数字 × 最多 9 种长度），每个数的构造和检查都是 O(1)。  
  > 大白话：不管区间有多大，我们只需要检查不到一百个数字，几乎是瞬间完成的。  
- **空间复杂度**：`O(k)`，`k` 为答案的个数，最坏也不超过 81，属于常数级别。  

> 与暴力解相比，时间从可能的 `10⁹` 次降到 **常数级**，性能提升巨大。

## 心得

- **核心技巧**：**枚举（Enumeration）**——利用题目本身的“顺序”特性，直接生成所有可能的合法数，而不是遍历整个搜索空间。
- **适用的题型**  
  1. **数字枚举**：如 “Beautiful Arrangement II” 中要求生成特定差值的序列。  
  2. **字符/数字组合**：如 “Generate Parentheses” 中直接递归生成所有合法括号序列。  
  3. **有固定上限的搜索**：如 “Powerful Integers” 只需要枚举有限个幂的组合。
- **一句话总结**：**把“顺序”变成“生成规则”，只枚举规则能产生的少量候选，省掉遍历大区间的所有无效数字**。

## 反思

- **第一反应**：看到“相邻数字相差 1”，马上想到把每个数转成字符串逐位比较，进而想到遍历整个区间——这就是暴力思路。
- **最容易踩的坑**  
  1. **遗漏长度**：顺序数字的最小长度是 2（比如 `12`），要确保不把单个数字（如 `1`）误当成答案。  
  2. **整数上界**：`high` 最高可达 `10⁹`，直接遍历会导致超时或内存不足。  
  3. **结果排序**：如果使用不保证生成顺序的方式（如递归后收集），需要手动 `sort`，否则答案可能不符合题目要求的升序。
- **下次类似题的第一步**：**先问自己：是否可以直接构造答案？**  
  - 若答案的结构具有明显的生成规则（递增、递减、交替等），往往可以采用枚举/递归直接生成，避免“大遍历”。
