## 题目（英文原版）

**Description**

Given an array of integers arr, return the number of subarrays with an odd sum.
Since the answer can be very large, return it modulo 109 + 7.

**Examples**

**Example 1:**

```
Input: arr = [1,3,5]
Output: 4
Explanation: All subarrays are [[1],[1,3],[1,3,5],[3],[3,5],[5]]
All sub-arrays sum are [1,4,9,3,8,5].
Odd sums are [1,9,3,5] so the answer is 4.
```

**Example 2:**

```
Input: arr = [2,4,6]
Output: 0
Explanation: All subarrays are [[2],[2,4],[2,4,6],[4],[4,6],[6]]
All sub-arrays sum are [2,6,12,4,10,6].
All sub-arrays have even sum and the answer is 0.
```

**Example 3:**

```
Input: arr = [1,2,3,4,5,6,7]
Output: 16
```

**Constraints**

- 1 <= arr.length <= 105
- 1 <= arr[i] <= 100

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的办法就是枚举所有可能的子数组，算出它们的和，再判断是否为奇数。  
- **枚举子数组**：可以用两个循环，外层选子数组的左端点 `i`，内层选右端点 `j`（`j ≥ i`），这样每一对 `(i, j)` 就对应唯一的子数组 `arr[i…j]`。  
- **计算子数组和**：在内层循环里累加 `arr[j]`，得到当前子数组的和 `sum`。  
- **奇偶判定**：如果 `sum % 2 == 1`（奇数），计数器 `ans` 加一。

> **类比**：想象你在一本书里挑选连续的页码，左手指住起始页，右手不断往后翻，每翻一页就把页码加到当前总和里，看到是奇数就记一下。

这个方法一定能得到正确答案，因为它把“所有子数组”都穷举了一遍，没漏也没错。

#### 代码（Python）

```python
def countOddSubarrays_bruteforce(arr):
    MOD = 10**9 + 7          # 题目要求的取模数
    n = len(arr)
    ans = 0                  # 记录奇数和子数组的个数

    # 外层枚举子数组的左端点
    for i in range(n):
        cur_sum = 0          # cur_sum 用来累计从 i 开始的子数组和
        # 内层枚举右端点
        for j in range(i, n):
            cur_sum += arr[j]            # 累加新的元素
            if cur_sum % 2 == 1:         # 判断奇偶（%2 为 1 表示奇数）
                ans = (ans + 1) % MOD    # 计数并取模
    return ans
```

#### 复杂度  

- **时间复杂度**：`O(n²)`  
  两层循环每层最坏都会跑 `n` 次，等价于把所有 `n·(n+1)/2` 个子数组都算一遍。  
  大白话：如果数组有 10,000 个元素，最坏情况下要做大约 **1 亿** 次加法和取模，明显太慢。

- **空间复杂度**：`O(1)`  
  只用了常数级别的额外变量（`cur_sum、ans、i、j`），不随 `n` 增长。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**每次都重新累加子数组的和**，导致二次遍历。  
我们可以利用**前缀和的奇偶性**来一次遍历完成计数。

**关键观察**  
- 设 `pre[k]` 为前 `k` 个元素的累计和（`pre[0] = 0`）。  
- 子数组 `arr[i…j]` 的和等于 `pre[j+1] - pre[i]`。  
- 两个数相减的奇偶性只取决于它们本身的奇偶性：  
  - 奇 - 偶 = 奇  
  - 偶 - 奇 = 奇  
  - 奇 - 奇 = 偶  
  - 偶 - 偶 = 偶  

因此，**如果当前前缀和是奇数**，要想得到奇数子数组和，只需要**之前出现过偶数前缀和**的次数；  
**如果当前前缀和是偶数**，则需要**之前出现过奇数前缀和**的次数。

**实现步骤**  
1. 维护两个计数器：`cnt_even`（到目前为止出现的偶数前缀和的个数）和 `cnt_odd`（奇数前缀和的个数）。初始时只有 `pre[0] = 0`（偶数），所以 `cnt_even = 1, cnt_odd = 0`。  
2. 从左到右遍历数组，实时更新 `cur_pre = (cur_pre + num) % 2`（只保留奇偶即可，用 `%2`）。  
3. 根据 `cur_pre` 的奇偶性：  
   - 若 `cur_pre` 为奇数，则当前以 `j` 为右端点的所有奇数子数组数量等于 `cnt_even`（因为需要之前的偶数前缀）。把 `cnt_even` 加到答案 `ans` 中。随后 `cnt_odd += 1`（因为现在多了一个奇数前缀）。  
   - 若 `cur_pre` 为偶数，则奇数子数组数量等于 `cnt_odd`，把它加到 `ans`，再 `cnt_even += 1`。  
4. 整个过程只用一次循环，时间 `O(n)`，额外空间 `O(1)`。

> **类比**：把前缀和的奇偶性想象成两种颜色的球（奇＝红，偶＝蓝），我们从左到右依次放球。每放一个新球，就去数一下“对面颜色的球”有多少，因为只要颜色不同，两球之间的子数组和就是奇数。

#### 代码（Python）

```python
def countOddSubarrays(arr):
    MOD = 10**9 + 7

    cnt_even = 1   # pre[0] = 0，是偶数前缀和
    cnt_odd = 0
    cur_pre = 0    # 只记录奇偶，用 0 表示偶，1 表示奇
    ans = 0

    for num in arr:
        # 更新前缀和的奇偶性（只保留 %2）
        cur_pre = (cur_pre + num) & 1   # &1 等价于 %2，且更快

        if cur_pre:                     # 当前前缀和是奇数
            ans = (ans + cnt_even) % MOD   # 需要之前的偶数前缀
            cnt_odd += 1                    # 新增一个奇数前缀
        else:                           # 当前前缀和是偶数
            ans = (ans + cnt_odd) % MOD    # 需要之前的奇数前缀
            cnt_even += 1                  # 新增一个偶数前缀

    return ans
```

#### 复杂度  

- **时间复杂度**：`O(n)`  
  只遍历一次数组，`n` 最高可达 `10⁵`，在 1 秒左右的限制下轻松通过。  
  与暴力的 `O(n²)` 相比，速度提升约 **n 倍**（比如 `10⁵` 时从 10⁹ 次下降到 10⁵ 次）。

- **空间复杂度**：`O(1)`  
  只用了几个整数计数器，不随输入规模增长。

## 心得

- **核心技巧**：利用**前缀和的奇偶性**把“子数组和是否为奇数”转化为“两个前缀奇偶是否不同”。只需要维护出现过的奇、偶前缀的次数即可。
- **适用场景**：  
  1. “子数组和为奇数/偶数”这类奇偶判定题。  
  2. “子数组和能被 k 整除”类题目（思路类似，只是记录 `pre % k` 的出现次数）。  
  3. “子数组的 XOR 为 0”或其他满足“前缀相等即子数组满足条件”的问题。
- **一句话总结**：**奇数子数组 = 前缀奇偶不同的配对数**。

## 反思

- **第一反应**：直接枚举子数组，写出 O(n²) 的暴力代码，验证思路是否正确。  
- **最容易踩的坑**：  
  - 忘记把初始的空前缀 `pre[0]=0` 计入偶数前缀计数，导致答案少 1。  
  - 只在循环结束后取模，可能导致中间结果超过 Python 整数范围（虽然 Python 自动大整数，但取模可以避免性能下降）。  
  - 对负数或大数取模时要注意 Python 的 `%` 与数学定义一致，这里数组元素都是正数所以不影响。  
- **下次第一步**：先思考**是否可以用前缀信息把子数组问题转化为计数问题**，尤其是奇偶、模 k、异或等“相等/不同”判定。这样往往能把二次遍历降到线性时间。
