# #1140. 石子游戏 II / Stone Game II

> 难度：中等 · 标签：Array、Math、Dynamic Programming、Prefix Sum、Game Theory · [LeetCode 链接](https://leetcode.com/problems/stone-game-ii/)

## 题目（英文原版）

**Description**

Alice and Bob continue their games with piles of stones. There are a number of piles arranged in a row, and each pile has a positive integer number of stones piles[i]. The objective of the game is to end with the most stones.
Alice and Bob take turns, with Alice starting first.
On each player's turn, that player can take all the stones in the first X remaining piles, where 1 <= X <= 2M. Then, we set M = max(M, X). Initially, M = 1.
The game continues until all the stones have been taken.
Assuming Alice and Bob play optimally, return the maximum number of stones Alice can get.

**Examples**

**Example 1:**

```
Input: piles = [2,7,9,4,4]
Output: 10
Explanation:
So we return 10 since it's larger.
```

**Example 2:**

```
Input: piles = [1,2,3,4,5,100]
Output: 104
```

**Constraints**

- 1 <= piles.length <= 100
- 1 <= piles[i] <= 104

## 题目（中文翻译）

Alice 和 Bob 继续他们的石子堆游戏。共有若干堆石子排成一行，第 `i` 堆的石子数为正整数 `piles[i]`。游戏的目标是最终获得最多的石子数。

- Alice 和 Bob 交替进行操作，Alice 先手。  
- 每一回合，当前玩家可以取走剩余石子堆中 **前** `X` 堆的所有石子，其中 `1 ≤ X ≤ 2M`。随后将 `M = max(M, X)`。初始时 `M = 1`。  
- 当所有石子都被取走时游戏结束。

假设双方都采用最优策略，返回 Alice 能获得的最大石子数。

**示例 1**

```
Input: piles = [2,7,9,4,4]
Output: 10
Explanation:
因此返回 10，因为它更大。
```

**示例 2**

```
Input: piles = [1,2,3,4,5,100]
Output: 104
```

**约束条件**

- `1 ≤ piles.length ≤ 100`
- `1 ≤ piles[i] ≤ 10^4`

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**模拟所有可能的游戏过程**，把每一步所有合法的取石数 `X`（`1 ≤ X ≤ 2M`）都枚举一遍，然后递归地让对手继续玩，最后比较 Alice 能得到的石头总数。  

- **数据结构**：我们只需要一个列表 `piles` 保存每堆石头数，递归函数的参数是当前剩余的起始下标 `i`（相当于“从第 i 堆开始”）和当前的 `M`。  
- **生活化类比**：把剩下的石堆想成一本书的章节，`i` 就是“从第几页开始读”。每一次玩家可以一次性“读” `X` 章节（拿走 `X` 堆），但一次最多只能读 `2M` 章节；读完后，`M` 会变成 `max(M, X)`，相当于读得多了，后面一次最多可以读的章节数也会随之增大。  
- **正确性**：因为我们枚举了 **所有** 合法的 `X`，并且在每种选择下都让对手继续进行最优的游戏（递归求最大），所以最终得到的就是在双方都最优的情况下 Alice 能拿到的最大石头数。  

#### 代码（Python）

```python
from functools import lru_cache
from typing import List

def stoneGameII_bruteforce(piles: List[int]) -> int:
    n = len(piles)

    # 前缀和，方便快速求任意区间的石子总数
    prefix = [0] * (n + 1)
    for i in range(n):
        prefix[i + 1] = prefix[i] + piles[i]

    # 区间 [i, n) 的石子总数
    def range_sum(i: int) -> int:
        return prefix[n] - prefix[i]

    @lru_cache(None)                     # 记忆化搜索，避免重复计算
    def dfs(i: int, m: int) -> int:
        """返回从第 i 堆开始，当前 M = m 时，当前玩家（假设是 Alice）能拿到的最大石子数"""
        if i >= n:                       # 没有石子可拿
            return 0

        # 如果一次可以把剩下的全部石子都拿走，直接返回总和
        if 2 * m >= n - i:
            return range_sum(i)

        best = 0
        # 枚举所有合法的 X
        for x in range(1, 2 * m + 1):
            # 拿走前 x 堆后，轮到对手；对手会使自己的得分最大，
            # 所以我们从总石子数中减去对手的最优得分，即得到自己的得分
            opponent = dfs(i + x, max(m, x))
            cur = range_sum(i) - opponent
            best = max(best, cur)        # 取最大值
        return best

    return dfs(0, 1)                      # 初始从第 0 堆开始，M = 1
```

#### 复杂度  

- **时间复杂度**：`O(2^n)`（指数级）。因为每一步我们都要尝试 `1~2M` 种取法，且 `M` 会随取石数增长，递归树的分支数会快速爆炸，最坏情况下会遍历所有可能的取石序列。  
- **空间复杂度**：`O(n)`。递归深度最多为 `n`（每次至少拿走一堆），加上前缀和数组占用 `O(n)` 空间。  

> 大白话解释：  
> - `O(2^n)` 就像把每一层的选择看成一次“抛硬币”，一共抛 `n` 次，所有可能的结果数量是 `2^n`，所以会非常慢，几秒钟都跑不完（当 `n=100` 时根本不可能完成）。

### 2. 最优解  

#### 思路  

暴力解的瓶颈在 **“枚举所有可能的 X”**，导致指数级的递归树。我们需要把**子问题的结果复用**，避免重复计算。  

**关键观察**  

1. **状态只和两件事有关**：  
   - 当前从哪一堆开始（下标 `i`）。  
   - 当前的 `M`（决定这一步最多能拿多少堆）。  
   只要知道这两件事，后面的局面就是唯一确定的。  

2. **对手也会最优**：在轮到对手时，他也会让 **自己** 能拿到最多的石子。  
   因此，当我们在位置 `i`、`M=m` 时拿走 `X` 堆后，**我们实际得到的石子数** = `当前剩余总石子数 - 对手在 (i+X, max(m, X)) 位置的最优得分`。  

3. **前缀和**：我们经常需要快速求 “从 i 开始到结尾的石子总和”。用一次性计算好的前缀和数组可以在 `O(1)` 时间得到。  

基于上述观察，我们可以用 **动态规划 + 记忆化搜索**（自顶向下）或 **自底向上 DP**。这里用记忆化搜索实现，代码更直观。  

**状态定义**  

`dp[i][m]`（或 `dfs(i, m)`） = 当剩余石堆从下标 `i` 开始，当前 `M = m` 时，**当前玩家**（假设是 Alice）能够得到的最大石子数。  

**状态转移**  

- 如果 `i >= n`，没有石子可拿，返回 `0`。  
- 如果 `2*m >= n - i`，说明一次可以把所有剩余石子都拿走，返回 `sum[i:]`（即前缀和差）。  
- 否则，尝试所有合法的 `X`（`1 ≤ X ≤ 2*m`）：

```
opponent = dp[i + X][max(m, X)]          # 对手在新局面下的最优得分
current  = total_remaining - opponent    # 我们自己能拿到的得分
dp[i][m] = max(dp[i][m], current)        # 取最大
```

其中 `total_remaining = prefix[n] - prefix[i]`。  

**为什么这样能得到最优解**  

因为我们在每一步都假设对手会把自己的得分最大化，而我们自己的得分等于剩余总石子数减去对手的得分。递归地把这个过程写下来，所有子问题的最优解都会被记住（缓存），所以最终 `dp[0][1]` 就是 Alice 在整局游戏中能得到的最大石子数。  

**实现细节**  

- 使用 `functools.lru_cache` 进行记忆化，省去显式创建二维数组的麻烦（因为 `m` 最大只会到 `n`，状态数最多 `n * n`，约 `10^4`，非常小）。  
- 计算前缀和一次性完成，以后每次求区间和 `O(1)`。  

#### 代码（Python）

```python
from functools import lru_cache
from typing import List

def stoneGameII(piles: List[int]) -> int:
    n = len(piles)

    # ---------- 1. 前缀和，快速求任意后缀的总石子数 ----------
    prefix = [0] * (n + 1)          # prefix[i] = 前 i 堆石子的总和
    for i in range(n):
        prefix[i + 1] = prefix[i] + piles[i]

    # 从下标 i 开始到结尾的石子总数
    def suffix_sum(i: int) -> int:
        return prefix[n] - prefix[i]

    # ---------- 2. 记忆化搜索 ----------
    @lru_cache(None)
    def dfs(i: int, m: int) -> int:
        """
        返回：在剩余 piles[i:]，当前 M = m 时，当前玩家（假设是 Alice）能拿到的最大石子数。
        """
        # 1) 已经没有石子可拿
        if i >= n:
            return 0

        # 2) 如果一次可以把所有剩余石子都拿走，直接返回总和
        if 2 * m >= n - i:
            return suffix_sum(i)

        # 3) 枚举所有合法的 X，计算自己可能的最大得分
        best = 0
        total = suffix_sum(i)           # 当前局面剩余的石子总数
        for x in range(1, 2 * m + 1):
            # 对手在 (i+x, max(m, x)) 位置的最优得分
            opponent = dfs(i + x, max(m, x))
            # 我们自己得到的 = 总数 - 对手得到的
            cur = total - opponent
            best = max(best, cur)        # 取最大的可能
        return best

    # 初始从第 0 堆开始，M = 1
    return dfs(0, 1)
```

#### 复杂度  

- **时间复杂度**：`O(n²)`。  
  - 状态数：`i` 取值 `0~n-1`，`m` 取值最多也不超过 `n`（因为 `2*m` 再大也只能覆盖剩余的全部堆），所以最多 `n·n` 种状态，即约 `10⁴`（`n ≤ 100`）。  
  - 对每个状态，我们最多遍历 `2*m ≤ 2n` 次循环，整体仍然是 `O(n²)` 级别。对 `n=100` 来说，最多几千次运算，毫秒级完成。  

- **空间复杂度**：`O(n²)`（缓存的递归表）+ `O(n)`（前缀和），整体仍是 `O(n²)`。  
  - 用 `lru_cache` 实际占用的空间与状态数相同，最多 `n·n` 条记录。  

> 与暴力解相比，时间从指数级 (`2^n`) 降到了多项式级 (`n²`)，速度提升几个数量级，能够轻松通过所有测试。

## 心得  

- **核心技巧**：把“取石子游戏”抽象为**带参数的子问题** `(i, m)`，并利用**对手最优**的博弈思路把自己的得分写成“总石子数 - 对手得分”。  
- **适用题型**：  
  1. 需要在 **两人交替、双方都最优** 的博弈类问题（如 *Stone Game*, *Stone Game III*）。  
  2. **取子序列或取前缀** 并且取的范围会随历史变化的动态规划（如 *Piles With Stones*, *Maximum Score from Performing Multiplication Operations*）。  
- **一句话总结解题钥匙**：**把“我能拿到的”转化为“剩余总和减去对手的最优”，并用记忆化 DP 把每个 `(位置, M)` 的最优值存起来**。

## 反思  

- **第一反应**：看到“每回合可以取 1~2M 堆，M 会随取的堆数增大”，立刻想到**递归枚举**所有可能的取法。  
- **最容易踩的坑**：  
  - **忘记更新 M** 为 `max(M, X)`，导致后面的合法取值范围错误。  
  - **没有使用前缀和**，每次求区间和都遍历数组，导致时间复杂度从 `O(n²)` 退化到 `O(n³)`。  
  - **边界条件**：当 `2M` 已经能够覆盖所有剩余堆时，直接返回剩余总和是必须的，否则会出现无限递归或错误的结果。  
- **下次遇到同类题**，第一步应该思考**“状态到底需要哪些信息？”**（这里是下标和当前的 M），然后尝试**把玩家的得分写成‘总量 - 对手最优’**的形式，再用 DP / 记忆化搜索避免重复计算。
