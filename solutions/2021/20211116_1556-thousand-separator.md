# #1556. 千位分隔符 / Thousand Separator

> 难度：简单 · 标签：String · [LeetCode 链接](https://leetcode.com/problems/thousand-separator/)

---

## 题目（英文原版）

**Description**

Given an integer n, add a dot (".") as the thousands separator and return it in string format.

**Examples**

**Example 1:**

```
Input: n = 987
Output: "987"
```

**Example 2:**

```
Input: n = 1234
Output: "1.234"
```

**Constraints**

- 0 <= n <= 231 - 1

---

## 题目（中文翻译）

**描述**  
给定一个整数 `n`，在每千位插入一个点号（"."）作为千位分隔符（thousands separator），并以字符串形式返回。

**示例**  

示例 1：  
输入: `n = 987`  
输出: `"987"`

示例 2：  
输入: `n = 1234`  
输出: `"1.234"`

**约束条件**  
- `0 <= n <= 2^31 - 1`   (即 32 位有符号整数的非负范围)

---

## 解题过程

### 1. 直觉解（暴力）

#### 思路  
最直接的想法就是把整数先变成字符串，再从右往左每走 3 位插入一个点 `.`，最后把得到的字符序列再拼成字符串返回。  

- **使用的数据结构**：字符串（`str`）和列表（`list`）。  
  - 把字符串拆成字符放进列表，好比把一串珠子倒出来，想在每第 3 颗珠子后面系一根绳子。  
  - 列表在 Python 中的插入操作是 O(1)（在末尾追加），所以我们先把所有字符倒着放进列表，再统一在合适的位置加入点，最后一次性把列表拼成字符串。  

- **为什么正确**：  
  - 题目要求“每三个数字之间放一个点”，而我们正好是每遍历完 3 位数字就插入一个点，除去最左侧的那一块（可能不足 3 位），正好满足要求。  

- **时间/空间复杂度**：  
  - 我们只遍历了一遍数字的字符（长度记为 `L`），每走 3 位就做一次插入点的操作，整体是线性时间 `O(L)`。  
  - 额外使用了一个长度为 `L` 的列表来存放字符，空间也是 `O(L)`。  
  - 这里的 `O(L)` 可以想象成“和数字位数成正比”，如果数字有 9 位，就大约需要 9 步。

#### 代码（Python）

```python
def thousandSeparator_brute(n: int) -> str:
    # 1️⃣ 把整数转成字符串，例如 1234 -> "1234"
    s = str(n)

    # 2️⃣ 逆序遍历，方便每 3 位插入一次点
    #    用列表收集字符，列表的 append 在 Python 里非常快
    rev_parts = []                 # 用来保存逆序的字符块
    for i, ch in enumerate(reversed(s)):
        rev_parts.append(ch)       # 先把当前字符加入
        # 每走满 3 位且不是最后一位，就加入一个点
        if (i + 1) % 3 == 0 and (i + 1) != len(s):
            rev_parts.append('.')  # 在逆序列表里插入点

    # 3️⃣ 逆序回来得到最终字符串
    #    ''.join 把列表里的字符拼成一个完整的字符串
    result = ''.join(reversed(rev_parts))
    return result
```

#### 复杂度

- **时间复杂度**：`O(L)` — 只遍历一次字符串，`L` 是数字的位数。  
- **空间复杂度**：`O(L)` — 需要额外的列表存放逆序字符。

### 2. 最优解

#### 思路  
虽然上面的“暴力”实现已经是线性时间，但我们仍可以写得更简洁、更易读，利用 Python 自带的切片（`slice`）一次性把字符串分成若干 3 位的块，然后用 `".".join` 把块连接起来。思路仍然是**从右往左每 3 位一组**，只是不再手动循环插入点，而是借助语言特性一次完成。

**关键点**：

1. **逆序切片**  
   - 把原字符串逆序（`s[::-1]`），这样左侧的 “不足 3 位” 块会自然出现在最后。  
2. **按步长 3 取块**  
   - 使用列表推导式 ` [rev[i:i+3] for i in range(0, len(rev), 3)]` 把逆序字符串每 3 位切成一段。  
3. **再逆序回去并用点连接**  
   - 把每块再逆序回来（因为之前已经倒过），最后用 `".".join` 把块拼在一起。  

这样做的好处是代码行数更少、可读性更高，且仍然是线性时间 `O(L)`。

#### 代码（Python）

```python
def thousandSeparator_optimal(n: int) -> str:
    # 1️⃣ 把整数转成字符串并逆序，例如 1234 -> "4321"
    rev = str(n)[::-1]

    # 2️⃣ 每 3 位切一次，得到逆序的块列表
    #    例如 "4321" -> ["432", "1"]
    blocks = [rev[i:i+3] for i in range(0, len(rev), 3)]

    # 3️⃣ 把每个块再逆序回来，并用点号连接
    #    ["432", "1"] -> ["234", "1"] -> "1.234"
    result = ".".join(block[::-1] for block in reversed(blocks))
    return result
```

#### 复杂度

- **时间复杂度**：`O(L)` — 逆序、切片、再逆序、拼接都是线性操作。相比暴力解，常数因子更小（少了逐字符判断插入点的分支）。  
- **空间复杂度**：`O(L)` — 需要额外的字符串副本和块列表，和暴力解相同。

## 心得

- **核心技巧**：**逆序 + 固定长度切块 + 再逆序拼接**，这是一种常见的“从右往左分组”手法。  
- **适用的题型**：  
  1. 千位分隔符（本题）  
  2. 将数字每 4 位加一个空格（如二进制分组）  
  3. 将大整数每 3 位加逗号（美国风格）  
- **解题钥匙**：**把“从右往左每 N 位”转化为“把字符串逆序后从左往右每 N 位”。**  

---

## 反思

- **第一反应**：把数字直接转成字符串，然后手动遍历插入点。  
- **最容易踩的坑**：  
  - 忘记 **不在最左侧的块前面加点**（即最后一块不需要前导点）。  
  - 边界情况：`n = 0` 或者数字位数恰好是 3 的倍数时，点的数量要恰好是 `位数/3 - 1`。  
- **下次类似题的第一步**：先把字符串逆序，然后思考“每 N 位切一次”，这样可以避免从左往右计数的繁琐判断。
