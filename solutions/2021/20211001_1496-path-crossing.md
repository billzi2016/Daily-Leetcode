# #1496. 路径交叉 / Path Crossing

> 难度：简单 · 标签：Hash Table、String · [LeetCode 链接](https://leetcode.com/problems/path-crossing/)

---

## 题目（英文原版）

**Description**

Given a string path, where path[i] = 'N', 'S', 'E' or 'W', each representing moving one unit north, south, east, or west, respectively. You start at the origin (0, 0) on a 2D plane and walk on the path specified by path.
Return true if the path crosses itself at any point, that is, if at any time you are on a location you have previously visited. Return false otherwise.

**Examples**

**Example 1:**

```
Input: path = "NES"
Output: false 
Explanation: Notice that the path doesn't cross any point more than once.
```

**Example 2:**

```
Input: path = "NESWW"
Output: true
Explanation: Notice that the path visits the origin twice.
```

**Constraints**

- 1 <= path.length <= 104
- path[i] is either 'N', 'S', 'E', or 'W'.

---

## 题目（中文翻译）

给定一个字符串 `path`，其中 `path[i]` 为 `'N'`、`'S'`、`'E'` 或 `'W'`，分别表示向北、向南、向东或向西移动一个单位。你从原点（origin）`(0, 0)` 开始，在二维平面（2D plane）上按照 `path` 指定的路径行走。  
如果在任意时刻你到达了之前已经访问过的位置，则路径相交（crosses itself），返回 `true`；否则返回 `false`。

## 示例

### 示例 1
**输入**  
``` 
path = "NES"
```  
**输出**  
```
false
```  
**解释**

### 示例 2
**输入**

``` 
path = "NESWW"
```  
**输出**

```
true
```  

**解释**  
路径在原点处被访问了两次。

- `path[i]` 仅为 `'N'`、`'S'`、`'E'` 或 `'W'`。

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  

最直接的想法就是把走过的每一步都记下来，然后在每走到一个新位置时，**把它和之前走过的所有位置逐个比较**，看是否已经出现过。  
- **数据结构**：我们可以用一个普通的 Python `list` 来保存已经访问过的坐标。把坐标看成“地图上的格子”，`list` 就像一本顺序的“足迹本”。  
- **为什么正确**：只要把所有已经去过的格子都列出来，遍历一次就能判断当前格子是否已经在这本本子里出现过。只要出现一次，就说明路径自交。  
- **时间/空间复杂度**：  
  - 对每一步都要遍历已经保存的所有坐标，最坏情况下第 i 步要比较 i 次，累计下来是 1 + 2 + … + n ≈ n²/2，故时间复杂度是 **O(n²)**（这里的 n 是路径长度）。  
  - 我们只需要保存已经走过的坐标，最多 n+1（包括起点）个，空间复杂度是 **O(n)**。  

> **大白话**：  
> - O(n²) 就像你在排队买票，前面已经有 i 个人，你要检查自己是否已经在队列里，就得和前面的每个人逐个比对。人数越多，检查的次数就呈平方增长。  

#### 代码（Python）

```python
def isPathCrossing_bruteforce(path: str) -> bool:
    # 起点 (0, 0) 放进足迹本
    visited = [(0, 0)]          # list，保存所有已经走过的坐标
    x, y = 0, 0                 # 当前坐标

    # 遍历每一个方向字符
    for move in path:
        # 根据字符更新坐标
        if move == 'N':
            y += 1
        elif move == 'S':
            y -= 1
        elif move == 'E':
            x += 1
        elif move == 'W':
            x -= 1

        # 检查当前坐标是否已经在 visited 中出现过
        # 这里用线性遍历 (O(len(visited)))，正是暴力的核心
        for vx, vy in visited:
            if (x, y) == (vx, vy):
                return True      # 找到重复坐标，路径自交

        # 没有重复则把当前坐标加入足迹本，继续前进
        visited.append((x, y))

    # 遍历完所有指令仍未发现重复，说明没有自交
    return False
```

#### 复杂度  

- **时间复杂度**：O(n²)  
  - n 是 `path` 的长度。每走一步都要遍历已经记录的所有坐标，形成二次循环。  
- **空间复杂度**：O(n)  
  - 最多需要保存 n+1 个坐标（包括起点），随路径长度线性增长。  

---  

### 2. 最优解  

#### 思路  

从暴力解可以看到，**瓶颈在于每一步都要把当前坐标和之前所有坐标逐个比较**。我们只需要判断“有没有出现过”，不需要知道它是第几次出现。  

**优化的关键是把“逐个比较”改成“常数时间查询”**，这正是**哈希表（Python 中的 `set`）**的强项。  

- **哈希表类比**：想象你有一本字典，查一个单词只需要看一下对应的页码，时间几乎不变。这里的“单词”是坐标，`set` 能在 O(1) 时间告诉我们这个坐标是否已经出现过。  
- **实现步骤**：  
  1. 用 `set` 保存已经走过的坐标。起点 (0,0) 先加入集合。  
  2. 按照路径指令依次更新当前位置。  
  3. 每更新一次，就检查 `set` 中是否已经包含这个坐标：  
     - 若已经在集合里，说明路径自交，直接返回 `True`。  
     - 否则把新坐标加入集合，继续前进。  
- **为什么是最优**：每一步只做 **一次** 哈希查询和一次插入，均摊下来是 **O(1)**，整个过程随路径长度线性增长，时间复杂度 **O(n)**。空间仍是 O(n)（要保存所有不同的坐标），已经是不可再压缩的下界。  

#### 代码（Python）

```python
def isPathCrossing(path: str) -> bool:
    # 使用 set（哈希表）保存已经访问过的坐标，起点先放进去
    visited = {(0, 0)}          # set，查找 O(1)
    x, y = 0, 0                 # 当前坐标

    for move in path:
        # 根据方向字符移动坐标
        if move == 'N':
            y += 1
        elif move == 'S':
            y -= 1
        elif move == 'E':
            x += 1
        elif move == 'W':
            x -= 1

        # 如果当前位置已经在 visited 中出现过，路径自交
        if (x, y) in visited:
            return True

        # 否则把新位置加入集合，继续走
        visited.add((x, y))

    # 所有指令走完都没有重复，返回 False
    return False
```

#### 复杂度  

- **时间复杂度**：O(n)  
  - n 为路径长度。每一步只做一次哈希查询和一次插入，都是常数时间。  
- **空间复杂度**：O(n)  
  - 最坏情况下每一步都会走到一个新格子，需要把所有 n+1 个坐标都存进 `set`。

## 心得  

- **核心技巧**：利用哈希表（`set`）实现**“是否出现过”**的 O(1) 判定。  
- **适用的题型**：  
  1. 判断路径是否自交（本题）。  
  2. 判断数组中是否存在重复元素（LeetCode 217）。  
  3. 判断是否有两点距离为 k 的子数组（LeetCode 560 – Subarray Sum Equals K）。  
- **一句话总结**：**“把所有已经到达的坐标放进字典，后面每次来都快速查询是否已经出现”。**

## 反思  

- **第一反应**：看到“走路”和“是否重复”，立刻想到“记录每一步的坐标”。  
- **最容易踩的坑**：  
  - **忘记把起点 (0,0) 加入集合**，导致第一次回到原点时判断错误。  
  - **坐标的存储方式**：如果把 x、y 分别放进两个列表，会导致查找变慢，必须把 `(x, y)` 作为一个整体放进 `set`。  
  - **字符合法性**：虽然题目保证只有 `'N','S','E','W'`，但在实际面试中最好写一个 `else` 分支防止非法输入。  
- **下次第一步**：**先把“已经到达的点”用 `set` 记录下来，再遍历路径做 O(1) 查询**。这一步几乎是判断“是否出现过”类问题的通用模板。
