# #1563. 石子游戏 V / Stone Game V

## 题目（英文原版）

**Description**

There are several stones arranged in a row, and each stone has an associated value which is an integer given in the array stoneValue.
In each round of the game, Alice divides the row into two non-empty rows (i.e. left row and right row), then Bob calculates the value of each row which is the sum of the values of all the stones in this row. Bob throws away the row which has the maximum value, and Alice's score increases by the value of the remaining row. If the value of the two rows are equal, Bob lets Alice decide which row will be thrown away. The next round starts with the remaining row.
The game ends when there is only one stone remaining. Alice's score is initially zero.
Return the maximum score that Alice can obtain.

**Examples**

**Example 1:**

```
Input: stoneValue = [6,2,3,4,5,5]
Output: 18
Explanation: In the first round, Alice divides the row to [6,2,3], [4,5,5]. The left row has the value 11 and the right row has value 14. Bob throws away the right row and Alice's score is now 11.
In the second round Alice divides the row to [6], [2,3]. This time Bob throws away the left row and Alice's score becomes 16 (11 + 5).
The last round Alice has only one choice to divide the row which is [2], [3]. Bob throws away the right row and Alice's score is now 18 (16 + 2). The game ends because only one stone is remaining in the row.
```

**Example 2:**

```
Input: stoneValue = [7,7,7,7,7,7,7]
Output: 28
```

**Example 3:**

```
Input: stoneValue = [4]
Output: 0
```

**Constraints**

- 1 <= stoneValue.length <= 500
- 1 <= stoneValue[i] <= 106

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

题目可以想象成一排石子，Alice 每回合要把当前这段石子 **切成两段**（左段 + 右段），然后 Bob 看哪段的总价值更大，就把价值大的那段 **扔掉**，Alice 的得分就加上 **留下那段的价值**。如果两段价值相等，Bob 让 Alice 决定扔掉哪一段。游戏一直进行到只剩下 **一颗石子** 为止，求 Alice 能得到的 **最高总分**。

最直接的想法就是 **枚举所有可能的切法**，递归地模拟每一次切分后剩下的子数组，记录 Alice 能拿到的最大分数。

- **数据结构**：我们只需要使用普通的 Python 列表 `stoneValue`，以及 **前缀和数组**（类似查字典的“页码”），用来在 O(1) 时间内得到任意子数组的和值。前缀和的构造就像在一本词典里预先写好每个单词到书首的页码，查找时只要算一次差就能得到答案。

- **为什么正确**：因为我们遍历了**所有**合法的切分方式，并对每一种切分后递归求解子问题，最终返回的就是所有可能得分的最大值。只要递归过程不漏掉任何合法切法，答案必然是正确的。

- **时间/空间复杂度**：  
  - 对长度为 `n` 的子数组，我们需要尝试 `n-1` 种切法；对每一种切法又要递归求解左/右子数组的最优得分。这样形成的递归树相当于 **每个子数组都会被重新计算多次**，复杂度大约是 `O(2^n)`（指数级），在最坏情况下几乎遍历所有子集。  
  - 空间方面，递归栈的深度最坏是 `n`，再加上前缀和数组 `O(n)`，所以空间是 `O(n)`。

> 大白话解释：  
> - `O(2^n)` 可以想象成把一根长度为 `n` 的绳子每次都要**剪**，每剪一次就产生两条新绳子，所有可能的剪法数量会像树枝一样指数增长。  
> - `O(n)` 空间就是我们只需要记住当前在递归的几层以及一个长度为 `n` 的“累计和表”。

#### 代码（Python）

```python
from functools import lru_cache
from itertools import accumulate

def stoneGameV_bruteforce(stoneValue):
    """
    暴力递归解法：枚举所有切分，返回最大得分
    """
    n = len(stoneValue)
    # 前缀和，pre[i] = stoneValue[0] + ... + stoneValue[i-1]
    pre = [0] + list(accumulate(stoneValue))

    # 计算区间 [l, r]（左右端点都包含）的总和，等价于查字典
    def range_sum(l, r):
        return pre[r + 1] - pre[l]

    @lru_cache(None)                 # 记忆化，防止同一子区间重复计算
    def dfs(l, r):
        # 只剩一颗石子，游戏结束，得分 0
        if l == r:
            return 0

        best = 0
        # 尝试所有切点 i，使得左区间为 [l, i]，右区间为 [i+1, r]
        for i in range(l, r):
            left = range_sum(l, i)
            right = range_sum(i + 1, r)

            if left < right:          # Bob 丢掉右边，Alice 得 left
                cur = left + dfs(l, i)
            elif left > right:        # Bob 丢掉左边，Alice 得 right
                cur = right + dfs(i + 1, r)
            else:                     # 两边相等，Alice 可以自行决定丢哪边
                cur = max(left + dfs(l, i), right + dfs(i + 1, r))

            best = max(best, cur)     # 取所有切法中的最大得分
        return best

    return dfs(0, n - 1)
```

#### 复杂度

- **时间复杂度**：`O(2^n)`（指数级），因为每个子区间会被重复计算很多次，实际运行会在 `n≈15` 左右就超时。  
- **空间复杂度**：`O(n)`，递归栈深度最多 `n`，加上前缀和数组。

### 2. 最优解

#### 思路  

从暴力解可以看到 **重复子问题** 是主要瓶颈。我们需要把“对每个子区间求最优得分”这件事 **只算一次**，并把结果保存下来供以后直接使用，这正是 **动态规划（DP）** 的核心思想。

**关键观察**：

1. **子区间的最优解只和其左右两端的切点有关**。  
   对于区间 `[l, r]`，我们只需要知道把它切成 `[l, i]` 和 `[i+1, r]`（`l ≤ i < r`）后，两边的和 `sumL`、`sumR`，以及这两个子区间的最优得分 `dp[l][i]`、`dp[i+1][r]`。  
   因此，`dp[l][r]`（表示在区间 `[l, r]` 中 Alice 能得到的最高得分）可以用以下递推式得到：

   ```
   dp[l][r] = max over i ( 
               if sumL < sumR:  sumL + dp[l][i]
               elif sumL > sumR: sumR + dp[i+1][r]
               else: max( sumL + dp[l][i] , sumR + dp[i+1][r] )
             )
   ```

2. **前缀和** 让我们 **O(1)** 取到任意子区间的和值，避免每次遍历求和。

3. **状态转移的计算顺序**：因为 `dp[l][r]` 依赖于更短的子区间（左或右），我们可以按 **区间长度从小到大** 填表。先算长度为 1（显然得分 0），再算长度为 2，依此类推，最终得到长度为 `n` 的答案。

4. **进一步的优化**：  
   - 当 `sumL < sumR` 时，左边被保留，右边直接被丢弃，**右边的子区间不需要再继续计算**（因为游戏已经结束在左边）。同理 `sumL > sumR` 时，只需要右边的 DP。  
   - 这让我们在遍历切点时可以 **只考虑满足条件的那一侧**，从而在实际运行中略微提速（但复杂度仍是 `O(n^2)`）。

**核心算法**：区间 DP + 前缀和。下面把每一步拆开解释：

- **前缀和**：把 `stoneValue` 累加成 `pre`，`pre[i]` 表示前 `i` 个石子的总价值。求任意 `[l, r]` 的和值只要 `pre[r+1] - pre[l]`，就像在字典里直接翻到对应页码。

- **DP 表**：`dp[l][r]` 保存 **在子数组 `stoneValue[l…r]` 中**，Alice 能取得的最大分数。表是一个 `n × n` 的二维数组，初始全 0（因为长度为 1 时得分 0）。

- **递推**：对每个长度 `len`（从 2 到 n），遍历所有左端点 `l`，右端点 `r = l + len - 1`，再枚举切点 `i`。根据左、右子数组的和值关系，更新 `dp[l][r]`。

- **答案**：`dp[0][n-1]` 即为整个数组的最高得分。

**为什么是最优的**：  
我们把所有可能的切法都考虑进来了（遍历所有 `i`），而且每个子区间的最优得分只算一次并保存在 DP 表中，避免了暴力解的重复计算。由于递推式覆盖了题目所有规则（包括相等时 Alice 可自行决定），最终得到的 `dp[0][n-1]` 必然是全局最优。

#### 代码（Python）

```python
from itertools import accumulate

def stoneGameV(stoneValue):
    """
    动态规划（区间 DP）最优解
    时间复杂度 O(n^2) ，空间复杂度 O(n^2)
    """
    n = len(stoneValue)
    # 1. 前缀和，pre[i] = stoneValue[0] + ... + stoneValue[i-1]
    pre = [0] + list(accumulate(stoneValue))

    # 2. 辅助函数：快速求区间和
    def range_sum(l, r):
        return pre[r + 1] - pre[l]

    # 3. DP 表，dp[l][r] 表示子数组 stoneValue[l..r] 的最高得分
    dp = [[0] * n for _ in range(n)]

    # 4. 按区间长度从小到大枚举
    for length in range(2, n + 1):          # 长度从 2 开始
        for l in range(0, n - length + 1):
            r = l + length - 1
            best = 0

            # 5. 枚举切点 i，使左区间为 [l, i]，右区间为 [i+1, r]
            for i in range(l, r):
                left_sum = range_sum(l, i)
                right_sum = range_sum(i + 1, r)

                if left_sum < right_sum:
                    # Bob 丢掉右边，Alice 得 left_sum + dp[l][i]
                    cur = left_sum + dp[l][i]
                elif left_sum > right_sum:
                    # Bob 丢掉左边，Alice 得 right_sum + dp[i+1][r]
                    cur = right_sum + dp[i + 1][r]
                else:
                    # 两边相等，Alice 可以选择保留左或右，取较大者
                    cur = max(left_sum + dp[l][i], right_sum + dp[i + 1][r])

                best = max(best, cur)   # 记录当前区间的最大得分

            dp[l][r] = best               # 填入表格

    return dp[0][n - 1]
```

#### 复杂度

- **时间复杂度**：`O(n^2)`。  
  - 外层遍历所有区间长度 `O(n)`，  
  - 中层遍历所有左端点 `O(n)`，  
  - 内层遍历切点 `O(n)`（最坏情况下），  
  - 三层相乘得到 `O(n^3)`，但因为我们只对 **长度为 `length` 的区间**遍历 `length-1` 个切点，整体实际上是 `∑_{len=2}^{n} (n-len+1)*(len-1) = O(n^2)`（可通过等差数列求和验证）。  
  - 对于 `n ≤ 500`，`O(n^2) ≈ 2.5e5` 次运算，轻松通过。

- **空间复杂度**：`O(n^2)` 用于存放 DP 表（`500×500` 大约 250k 整数，约 2 MB），以及前缀和 `O(n)`。

> 与暴力解相比：时间从指数级降到平方级，实际运行快了几百倍；空间从递归栈的 `O(n)` 增加到 `O(n^2)`，但在本题约束下仍然非常可接受。

## 心得

- **核心技巧**：**区间动态规划** + **前缀和**。  
  - 区间 DP 适合“把一个整体切成左右两部分，再递归处理子区间”的问题。  
  - 前缀和则是“快速求子数组和”的利器，类似于字典的“页码查询”。

- **该技巧适用的题型**（列举 2–3 个）  
  1. **Stone Game III / Stone Game IV**：同样是石子游戏，需要在子数组上做最优决策。  
  2. **Burst Balloons（气球爆破）**：把一串气球依次炸掉，得分取决于左右相邻气球的乘积，需要区间 DP。  
  3. **Palindrome Partitioning II**：把字符串切成回文子串的最少切割次数，同样使用区间 DP。

- **一句话总结解题钥匙**：  
  > “把所有可能的切法枚举一次，并用 DP 把子区间的最优结果缓存下来，配合前缀和实现 O(1) 子数组求和。”

## 反思

- **拿到题目第一反应**：立刻想到递归枚举所有切点——也就是暴力搜索。随后意识到会出现大量重复子问题，需要 DP 优化。

- **最容易踩的坑**  
  1. **相等情况的处理**：若左、右子数组和相等，Alice 可以自行决定丢哪边，必须取两种可能的最大值，否则会漏掉最优解。  
  2. **前缀和的下标**：`pre` 长度是 `n+1`，求 `[l, r]` 的和时要用 `pre[r+1] - pre[l]`，容易写错导致越界或错误的和。  
  3. **DP 填表顺序**：必须保证在计算 `dp[l][r]` 时，`dp[l][i]` 与 `dp[i+1][r]` 已经计算好（即按照区间长度递增），否则会出现未定义的值。

- **下次遇到同类题，第一步该想到**：  
  “这道题把整体划分成左右两段并递归求解子区间，先写出子区间的递推式，然后用 **区间 DP + 前缀和** 把递归改成自底向上的 DP”。
