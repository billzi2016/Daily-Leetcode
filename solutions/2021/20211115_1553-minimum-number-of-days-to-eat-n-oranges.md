# #1553. 吃掉 n 个橘子的最少天数 / Minimum Number of Days to Eat N Oranges

> 难度：困难 · 标签：Dynamic Programming、Memoization · [LeetCode 链接](https://leetcode.com/problems/minimum-number-of-days-to-eat-n-oranges/)

---

## 题目（英文原版）

**Description**

There are n oranges in the kitchen and you decided to eat some of these oranges every day as follows:
You can only choose one of the actions per day.
Given the integer n, return the minimum number of days to eat n oranges.

**Examples**

**Example 1:**

```
Input: n = 10
Output: 4
Explanation: You have 10 oranges.
Day 1: Eat 1 orange,  10 - 1 = 9.  
Day 2: Eat 6 oranges, 9 - 2*(9/3) = 9 - 6 = 3. (Since 9 is divisible by 3)
Day 3: Eat 2 oranges, 3 - 2*(3/3) = 3 - 2 = 1. 
Day 4: Eat the last orange  1 - 1  = 0.
You need at least 4 days to eat the 10 oranges.
```

**Example 2:**

```
Input: n = 6
Output: 3
Explanation: You have 6 oranges.
Day 1: Eat 3 oranges, 6 - 6/2 = 6 - 3 = 3. (Since 6 is divisible by 2).
Day 2: Eat 2 oranges, 3 - 2*(3/3) = 3 - 2 = 1. (Since 3 is divisible by 3)
Day 3: Eat the last orange  1 - 1  = 0.
You need at least 3 days to eat the 6 oranges.
```

**Constraints**

- 1 <= n <= 2 * 109

给定整数 `n`，返回吃完 `n` 个橘子所需的最少天数。

```

至少需要 3 天才能吃完这 6 个橘子。
```

**约束条件**

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**模拟每一天的所有可能选择**，把每一天可以做的三件事枚举出来：

1. 吃掉 **1** 个橘子  
2. 如果当前橘子数能被 **2** 整除，就吃掉 `n/2` 个（等价于把橘子数减半）  
3. 如果当前橘子数能被 **3** 整除，就吃掉 `2·(n/3)` 个（等价于把橘子数除以 3）

我们可以把每一种选择看成一条**分支**，继续往下走，直到橘子数变成 0 为止。把所有分支的长度（天数）记下来，最小的那条就是答案。

> **类比**：把每一天的决策想成在一棵树上向下走，根节点是初始的 `n`，每走一步就产生子节点（可能的下一天），我们要找**最短的路径**到达叶子节点 `0`。

这个思路当然是**正确**的——只要把所有合法的吃法都遍历一遍，最短的那条必然会被找到。

但是，这种“把所有可能都枚举”会导致**指数级别的计算量**。比如 `n = 10` 时，第一天有 2 种选择（吃 1 或者吃 5），第二天又会产生若干选择…… 递归深度大约是 `n`，分支数随之呈指数增长，根本跑不完。

#### 代码（Python）

```python
def minDays_bruteforce(n: int) -> int:
    # 递归穷举所有可能的吃法，返回最小天数
    if n == 0:                     # 已经没有橘子了，天数 0
        return 0
    # 必须至少吃 1 天
    ans = 1 + minDays_bruteforce(n - 1)   # 选项 1：每天只吃 1 个

    # 选项 2：如果能被 2 整除，就直接吃掉 n/2 个
    if n % 2 == 0:
        ans = min(ans, 1 + minDays_bruteforce(n // 2))

    # 选项 3：如果能被 3 整除，就直接吃掉 2·(n/3) 个
    if n % 3 == 0:
        ans = min(ans, 1 + minDays_bruteforce(n // 3))

    return ans
```

> **注意**：这段代码仅用于说明思路，实际运行会因为大量重复计算而超时。

#### 复杂度

- **时间复杂度**：`O(3^n)`（极其夸张的上界）  
  解释：每一天最多有 3 种选择，深度最坏会到 `n`，于是总的递归调用数呈指数增长。可以把 `O(3^n)` 想象成“每走一步，枝杈数翻了三倍”，即使 `n=20` 也已经是几千万次调用。

- **空间复杂度**：`O(n)`  
  解释：递归调用栈的深度最多等于 `n`，每层保存一点局部变量。

> 由于时间复杂度太大，暴力解只能在 **n 很小**（比如 `n ≤ 20`）时才会勉强跑得完。

### 2. 最优解

#### 思路  

从暴力解可以看到，**大量的重复子问题**是性能瓶颈：同一个 `n` 会被递归求解很多次。例如在 `n = 10` 的递归树里，`f(5)` 可能出现好几次。

我们可以把已经算好的 `f(x)` **记下来**，以后再需要时直接取用，这就是**记忆化搜索（Memoization）**。记忆化相当于在做递归的同时使用一个 **哈希表**（可以把它想象成一本“橘子数 → 最少天数”的字典），查询和写入的时间都是 `O(1)`。

另外，观察题目给出的 **提示公式**：

```
minDays(n) = 1 + min( (n % 2) + minDays(n // 2),
                     (n % 3) + minDays(n // 3) )
```

含义拆解：

- 为了使用 “除以 2” 的规则，必须先把 `n` **减到最近的能被 2 整除的数**，这需要 `n % 2` 天（每次只能吃 1 个）。
- 同理，使用 “除以 3” 的规则前，需要 `n % 3` 天把 `n` 减到能被 3 整除的数。
- 除完以后，递归求解更小的子问题 `n // 2` 或 `n // 3`。
- 最外层的 `+1` 表示**今天**这一步（要么吃 1，要么除以 2/3）所消耗的一天。

这样一来，每一次递归都 **把 n 大幅度缩小**（除以 2 或除以 3），递归深度只有 `log₂ n` 或 `log₃ n`，极大降低了计算量。

> **核心技巧**：  
> 1. **记忆化**：把已经算过的 `f(x)` 存进字典，避免重复计算。  
> 2. **利用取余**把 “只能吃 1 个” 的操作压缩成一次性完成，避免逐个递减的线性遍历。

#### 代码（Python）

```python
from functools import lru_cache

class Solution:
    @lru_cache(maxsize=None)          # 自动为每个 n 建立缓存，相当于哈希表
    def minDays(self, n: int) -> int:
        """
        返回吃完 n 个橘子最少需要的天数
        思路：记忆化递归 + 取余 + 除法
        """
        if n <= 1:                    # n 为 0 或 1 时，天数就是 n 本身
            return n

        # 方案一：先吃掉 n%2 个，使 n 能被 2 整除，然后一次性除以 2
        # 方案二：先吃掉 n%3 个，使 n 能被 3 整除，然后一次性除以 3
        # 两种方案取更小的那个，再加上今天这一步（+1）
        # 注意这里的 (n % 2) 和 (n % 3) 表示“需要多少天只吃 1 个”来完成对齐
        days_div2 = n % 2 + self.minDays(n // 2)
        days_div3 = n % 3 + self.minDays(n // 3)

        return 1 + min(days_div2, days_div3)
```

**代码要点说明**：

| 行号 | 关键代码 | 中文注释 |
|------|----------|----------|
| 3    | `@lru_cache(maxsize=None)` | 为函数开启记忆化，内部用字典保存已经算好的 `n` 与对应的最少天数 |
| 6‑7  | `if n <= 1: return n` | 基础情况：0 天吃完 0 个，1 天吃完 1 个 |
| 11‑12| `days_div2 = n % 2 + self.minDays(n // 2)` | 先吃掉 `n%2` 天的“单吃”，再一次性除以 2，递归求子问题 |
| 13‑14| `days_div3 = n % 3 + self.minDays(n // 3)` | 同理，处理除以 3 的情况 |
| 16   | `return 1 + min(days_div2, days_div3)` | 今天这一步 + 两种方案的最小值 |

#### 复杂度

- **时间复杂度**：`O(log n)`  
  解释：每一次递归把 `n` 至少除以 2（或者 3），所以递归层数大约是 `log₂ n`（最坏情况取除以 2），每层只做 `O(1)` 的工作（取余、哈希查询），整体就是对数级别。可以把它想象成“每走一步，橘子数就至少减半”，要把 2×10⁹ 减到 0 只需要不到 31 步。

- **空间复杂度**：`O(log n)`（递归栈）+ `O(log n)`（缓存表）  
  解释：缓存里最多会存下每一次递归产生的不同 `n`，数量同递归层数一样是对数级别；递归调用栈同样深度为 `log n`。

> 与暴力解相比，时间从指数级下降到对数级，几乎可以在毫秒级别求解 `n = 2·10⁹` 的输入。

## 心得

- **核心技巧**：记忆化递归 + “先把余数吃掉再除以 2/3” 的**取余 + 除法**策略。  
- **适用的题型**（类似思路）  
  1. **“最少操作使整数变为 1”**（LeetCode 397）——可以用 `n%2`、`n%3` 等取余技巧。  
  2. **“删除字符得到回文”**（或其它需要把问题规模大幅缩小的 DP）——记忆化搜索同样有效。  
  3. **“最小乘法步骤”**（把一个数变成目标数，允许乘以 2/3）——同样使用除法逆向思考。  
- **一句话总结解题钥匙**：**把“只能吃 1 个”的线性操作压缩成一次性取余，再用记忆化把递归子问题复用**。

## 反思

- **第一反应**：看到“每天只能做一种操作”，自然想到 BFS 或递归枚举所有路径。  
- **最容易踩的坑**  
  1. **忘记取余的天数**：直接写 `1 + min(f(n//2), f(n//3))` 会漏掉把 `n` 调整到能除的天数，导致错误答案。  
  2. **递归深度与栈溢出**：在 Python 中递归层数虽小（≈30），但如果误写成线性递减（`n-1`）会导致栈溢出。  
  3. **缓存未开启**：没有记忆化会导致指数级时间，超出限制。  
- **下次类似题的第一步**：**先思考能否把“逐步减 1”压缩为一次性操作（取余），并检查是否可以用除法/乘法把规模快速缩小**。若可以，再结合记忆化/DP 完成高效实现。
