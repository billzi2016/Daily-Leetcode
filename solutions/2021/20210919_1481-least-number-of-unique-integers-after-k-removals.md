# #1481. **K 次删除后剩余的最少不同整数个数** / Least Number of Unique Integers after K Removals

> 难度：中等 · 标签：Array、Hash Table、Greedy、Sorting、Counting · [LeetCode 链接](https://leetcode.com/problems/least-number-of-unique-integers-after-k-removals/)

## 题目（英文原版）

**Description**

Given an array of integers arr and an integer k. Find the least number of unique integers after removing exactly k elements.

**Examples**

**Example 1:**

```
Input: arr = [5,5,4], k = 1
Output: 1
Explanation: Remove the single 4, only 5 is left.
```

**Example 2:**

```
Input: arr = [4,3,1,1,3,3,2], k = 3
Output: 2
Explanation: Remove 4, 2 and either one of the two 1s or three 3s. 1 and 3 will be left.
```

**Constraints**

- 1 <= arr.length <= 10^5
- 1 <= arr[i] <= 10^9
- 0 <= k <= arr.length

## 题目（中文翻译）

给定一个整数（integer）数组（array）`arr` 和一个整数 `k`。请在恰好删除 `k` 个元素后，求剩余的不同整数（unique integers）的最少数量。

**示例 1**

```
Input: arr = [5,5,4], k = 1
Output: 1
Explanation: 删除唯一的 4，数组中只剩下 5。
```

**示例 2**

```
Input: arr = [4,3,1,1,3,3,2], k = 3
Output: 2
Explanation: 删除 4、2 以及两个 1 中的任意一个或三个 3 中的任意一个。最后剩下的不同整数是 1 和 3。
```

**约束条件**

- `1 <= arr.length <= 10^5`
- `1 <= arr[i] <= 10^9`
- `0 <= k <= arr.length`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**枚举所有可能的删法**，找出删掉恰好 `k` 个元素后，剩下的不同数字的最小个数。

- **数据结构**：我们可以把数组 `arr` 看成一本“字典”。字典的 **key** 是数字本身，**value** 是这个数字在数组里出现的次数（相当于查词典时看到的页码）。  
- **暴力做法**：先把所有出现次数记下来（用 `dict`），然后从这些出现次数中挑选出若干个数字，把它们的全部出现次数相加恰好等于 `k`（或者等于 `k` 之后再把剩下的数字的部分出现次数删掉），最后统计剩下的不同数字个数，取最小值。

> 这里的 “挑选若干个数字” 实际上就是在 **所有子集** 中遍历——子集的个数是 `2^m`（`m` 为不同数字的种类数），对 `m` 较大的情况几乎不可能在合理时间内算完。

**为什么这个方法是正确的**  
因为我们穷举了所有可能的删法，答案一定在其中。只要实现没有遗漏，最小的唯一数字个数必然被找到。

**时间/空间复杂度**  
- **时间复杂度**：`O(2^m * m)`，其中 `m` 是数组中不同数字的种类数。`2^m` 表示所有子集的数量，`m` 用来统计每个子集的剩余种类数。  
  大白话：如果数组里有 20 种不同的数字，`2^20 ≈ 1,048,576`，已经是上百万次循环；若种类数是 30，次数会暴涨到十亿级，根本跑不完。  
- **空间复杂度**：`O(m)`，只需要保存每个数字的出现次数。

> 结论：暴力解在最坏情况下会超时，主要瓶颈是 **指数级的子集遍历**。

---

#### 代码（Python）

```python
from collections import Counter
from itertools import combinations

def least_unique_bruteforce(arr, k):
    # 统计每个数字出现的次数，像查字典一样
    freq = Counter(arr)                     # key: 数字，value: 出现次数
    uniq_vals = list(freq.keys())
    m = len(uniq_vals)

    best = m  # 最坏情况：不删任何数字，唯一数目就是 m

    # 枚举所有可能要「完全删除」的数字集合（子集）
    for r in range(m + 1):
        for subset in combinations(uniq_vals, r):
            # 计算删掉这些数字后已经删除的元素个数
            removed = sum(freq[x] for x in subset)

            # 如果已经删的超过 k，说明这个子集不合法，直接跳过
            if removed > k:
                continue

            # 还剩 k - removed 次可以在「保留下来的数字」中随意删
            # 为了让唯一数最少，我们应该继续删掉出现次数最少的那些数字
            # 这里直接把剩余的次数放进列表，按升序取前 (k-removed) 个删掉
            remain_counts = [freq[x] for x in uniq_vals if x not in subset]
            remain_counts.sort()
            need = k - removed
            i = 0
            while i < len(remain_counts) and need >= remain_counts[i]:
                need -= remain_counts[i]
                i += 1
            # i 表示在保留下来的数字中还能完整删除的种类数
            cur_unique = m - r - i
            best = min(best, cur_unique)

    return best
```

> 代码中每一步都有中文注释，帮助你对应到生活中的“字典查词”“子集枚举”等概念。

#### 复杂度

- **时间复杂度**：`O(2^m * m)`（指数级），因为遍历所有子集。  
  *含义解释*：如果不同数字有 20 种，时间会是 `2^20 ≈ 1,000,000` 次循环；种类数多一点，时间就会呈指数增长，几乎不可能在 1 秒内跑完。
- **空间复杂度**：`O(m)`，只保存每个数字的计数。

### 2. 最优解

#### 思路  

从暴力解可以看到，**瓶颈在于枚举所有子集**。实际上我们不需要枚举，只要**把要删的数字按出现次数从少到多顺序删**，就能得到最少的唯一数字个数。原因如下：

1. **我们只能删 `k` 次**，每一次删都等价于把某个出现次数为 `c` 的数字的 **一个实例** 移除。  
2. 若我们想让唯一数字的种类数尽可能少，**应该优先把出现次数最少的数字全部删掉**，因为它们“花费的删除次数最少”。  
3. 当我们把所有出现次数为 `c1 ≤ c2 ≤ …` 的数字一次完整地删掉后，若还有剩余的删除次数 `k`，只能在剩下的数字中再删掉一些实例，但这 **不会再减少种类数**（因为每种数字至少还有一个实例保留）。

因此，**核心算法**是：

- 用哈希表（`dict`/`Counter`）统计每个数字的出现次数 → 类比为“查字典”，key 是数字，value 是出现次数。  
- 把所有出现次数放进数组并**升序排序**，得到一个“从少到多的删除成本”列表。  
- 按顺序遍历这个列表，用 `k` 去“买掉”这些数字的全部出现次数；每买掉一个数字，就让唯一数字的种类数 `-1`。  
- 当 `k` 不足以买掉当前数字的全部出现次数时，停止，剩下的种类数就是答案。

**为什么贪心是最优的**  
- 设想我们有两种数字，出现次数分别为 `a ≤ b`。如果我们先删掉出现次数为 `b` 的数字，消耗 `b` 次删除，却只减少了 1 种唯一数字；而如果先删掉出现次数为 `a` 的数字，只用了 `a` 次删除，同样减少 1 种唯一数字，而且保留了更多的删除次数去处理其它数字。  
- 通过**交换论证**（把先删 `b` 换成先删 `a`，不增加删除次数且不增加剩余唯一数），可以证明任何非最小次数的删除顺序都可以改造成“先删小的”而不变坏答案。  

**关键数据结构解释**  
- **哈希表（dict）**：像一本词典，查找某个数字出现多少次是 O(1) 时间。  
- **数组 + 排序**：把词典的所有“页码”（出现次数）排成从小到大的顺序，类似把所有商品的价格从低到高排好，方便我们先买最便宜的。

---

#### 代码（Python）

```python
from collections import Counter

def least_unique_greedy(arr, k):
    """
    返回删除恰好 k 个元素后，数组中不同整数的最少数量。
    思路：先删出现次数最少的数字，使用贪心。
    """
    # 1️⃣ 统计每个数字出现了几次（哈希表：数字 -> 次数）
    freq = Counter(arr)                # O(n)

    # 2️⃣ 把所有出现次数取出来，放进列表并升序排列
    counts = sorted(freq.values())      # O(m log m)，m 为不同数字的种类数

    # 3️⃣ 按出现次数从小到大“买掉”整个数字
    unique = len(counts)                # 初始的不同数字个数
    for c in counts:
        if k >= c:                      # k 足够把这个数字全部删掉
            k -= c                       # 用掉 c 次删除机会
            unique -= 1                 # 唯一数字种类数-1
        else:                           # k 不够删完整个数字，直接结束
            break

    return unique
```

> 关键行的中文注释帮助你把每一步对应到“查词典”“排序”“贪心买东西”的生活情境。

#### 复杂度

- **时间复杂度**：`O(n + m log m)`  
  - `O(n)` 用于遍历数组统计出现次数。  
  - `O(m log m)` 用于对出现次数进行排序。  
  *含义解释*：如果数组长度是 100,000，排序最多只会在不同数字的种类数（最多也是 100,000）上做 `log` 级别的比较，整体在几毫秒到几十毫秒之间，远快于指数级的暴力解。  
- **空间复杂度**：`O(m)`  
  - 需要保存每个不同数字的计数，最坏情况下每个元素都不相同，空间就是 `n`（即 `m = n`）。  
  *含义解释*：这相当于我们需要一张“字典”，字典里每一页对应一个数字的出现次数，最多占用和原数组同等大小的额外内存。

## 心得

- **核心技巧**：**贪心 + 计数排序**（先统计出现次数，再从小到大删除）。  
- **适用的题型**：  
  1. *“移除 K 个元素后，使数组满足某种最小/最大条件”*（如 LeetCode 1481. Least Number of Unique Integers after K Removals）。  
  2. *“把数组分成若干组，使每组大小满足条件”*（如 1338. Reduce Array Size to The Half）。  
  3. *“删除元素使数组的某种度量最小化”*（如 1337. The K Weakest Rows in a Matrix，思路类似先找最小/最大）。  
- **一句话总结解题钥匙**：**先把“最省力”的东西处理掉**——即把出现次数最少的数字全部删掉，能够在最少的删除次数内最大化种类的减少。

## 反思

- **第一反应**：看到“删除 k 个元素后，求最少的唯一整数”，立刻想到“统计每个数字出现多少次”，因为唯一数的多少本质上由“每个数字剩余多少次”决定。  
- **最容易踩的坑**：  
  - **忘记 k 可以等于 0**，此时直接返回不同数字的种类数。  
  - **忘记边界**：当 `k` 大于等于所有出现次数之和时，答案应为 0。代码中自然会得到 0，但要保证循环不会出现负数或索引错误。  
  - **计数溢出**：在 Python 中整数不溢出，但在其他语言要注意 `int` 范围。  
- **下次遇到同类题**，第一步应该想到：**“先把所有元素的频率统计出来”，然后根据“删除/保留的代价”排序，使用贪心把最划算的操作先做”。**这样可以迅速定位到最优解的方向。
