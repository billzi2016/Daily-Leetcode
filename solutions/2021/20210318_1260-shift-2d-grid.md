# #1260. 二维网格移位 / Shift 2D Grid

> 难度：简单 · 标签：Array、Matrix、Simulation · [LeetCode 链接](https://leetcode.com/problems/shift-2d-grid/)

## 题目（英文原版）

**Description**

Given a 2D grid of size m x n and an integer k. You need to shift the grid k times.
In one shift operation:
Return the 2D grid after applying shift operation k times.

**Examples**

**Example 1:**

```
Input: grid = [[1,2,3],[4,5,6],[7,8,9]], k = 1
Output: [[9,1,2],[3,4,5],[6,7,8]]
```

**Example 2:**

```
Input: grid = [[3,8,1,9],[19,7,2,5],[4,6,11,10],[12,0,21,13]], k = 4
Output: [[12,0,21,13],[3,8,1,9],[19,7,2,5],[4,6,11,10]]
```

**Example 3:**

```
Input: grid = [[1,2,3],[4,5,6],[7,8,9]], k = 9
Output: [[1,2,3],[4,5,6],[7,8,9]]
```

**Constraints**

- m == grid.length
- n == grid[i].length
- 1 <= m <= 50
- 1 <= n <= 50
- -1000 <= grid[i][j] <= 1000
- 0 <= k <= 100

## 题目（中文翻译）

给定一个大小为 `m x n` 的二维网格（grid）和一个整数 `k`。需要将网格向右下方向移动 `k` 次。

一次移位操作（shift operation）的定义如下：

- `grid[i][j]` 的元素会移动到 `grid[i][j+1]` 的位置；
- 当 `j` 已经是该行的最后一列时，元素会移动到下一行的第一列 `grid[i+1][0]`；
- 当元素位于最后一行的最后一列 `grid[m‑1][n‑1]` 时，它会移动到网格的起始位置 `grid[0][0]`。

返回在执行 `k` 次移位操作后得到的二维网格。

**示例 1**  
输入: `grid = [[1,2,3],[4,5,6],[7,8,9]], k = 1`  
输出: `[[9,1,2],[3,4,5],[6,7,8]]`

**示例 2**  
输入: `grid = [[3,8,1,9],[19,7,2,5],[4,6,11,10],[12,0,21,13]], k = 4`  
输出: `[[12,0,21,13],[3,8,1,9],[19,7,2,5],[4,6,11,10]]`

**示例 3**  
输入: `grid = [[1,2,3],[4,5,6],[7,8,9]], k = 9`  
输出: `[[1,2,3],[4,5,6],[7,8,9]]`

**约束条件**  
- `m == grid.length`  
- `n == grid[i].length`  
- `1 <= m <= 50`  
- `1 <= n <= 50`  
- `-1000 <= grid[i][j] <= 1000`  
- `0 <= k <= 100`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是 **一步一步地模拟** 题目要求的“向右下移动”。  
一次 shift 操作的规则如下：

1. 最右下角的元素（`grid[m‑1][n‑1]`）会跳到左上角（`grid[0][0]`）。  
2. 其它位置的元素 `grid[i][j]` 向右移动一格；如果已经在本行最右端（`j == n‑1`），则跳到下一行的最左端（`grid[i+1][0]`）。

把上面的规则写成代码，就是把每个元素搬家一次。  
因为要做 `k` 次 shift，就把这一步重复 `k` 次。

> **类比**：把整个矩阵想成一条环形的传送带，传送带每转一步，所有货物都往前走一个格子。暴力解就是让传送带真的转 `k` 次。

只要把每一步搬家的过程写对，就一定能得到正确答案——因为我们完全按照题目描述的规则操作。

#### 代码（Python）

```python
from typing import List

def shift_grid_bruteforce(grid: List[List[int]], k: int) -> List[List[int]]:
    m, n = len(grid), len(grid[0])
    # 把二维列表复制一份，防止在搬家时覆盖原来的值
    for _ in range(k):                     # 重复 k 次
        prev = grid[m - 1][n - 1]           # 保存最后一个元素，准备放到最前面
        for i in range(m):
            for j in range(n):
                # 先把当前位置的值存到 tmp，后面会被后面的元素覆盖
                tmp = grid[i][j]
                # 把 prev（前一个格子要搬来的值）写进当前位置
                grid[i][j] = prev
                # 更新 prev 为当前格子原来的值，供下一个格子使用
                prev = tmp
    return grid
```

> **关键行解释**  
> - `prev = grid[m - 1][n - 1]`：把环形的“最后一个”先记下来，等会儿要搬到最前面。  
> - `grid[i][j] = prev`：把前一个格子搬来的值写进当前位置。  
> - `prev = tmp`：把当前格子原来的值保存，准备给下一个格子使用。

#### 复杂度

- **时间复杂度**：`O(k * m * n)`  
  每次 shift 需要遍历整个矩阵 `m·n` 次，重复 `k` 次。  
  用大白话说，如果矩阵有 100 格，`k = 5`，就要搬家 500 次。

- **空间复杂度**：`O(1)`（不计返回结果的空间）  
  只用了常数个临时变量 `prev`、`tmp`，没有额外的和输入规模相关的数组。

### 2. 最优解

#### 思路  

暴力解的瓶颈在 **每次只移动一个格子**，导致时间随 `k` 成线性增长。  
事实上，**一次 shift** 把所有元素整体向后平移 `1` 位，如果把矩阵展平成一维数组，这种平移就是**循环右移**（rotate）。

**步骤**：

1. **展平**：把矩阵按行顺序放进一个一维列表 `flat`。  
   - 这一步相当于把环形传送带“拉直”。  
2. **计算真实移动步数**：因为 `k` 可能大于矩阵长度 `len(flat)`，只需要移动 `k % total` 步。  
   - 例如，长度是 9，`k = 12` 实际效果等价于向后移动 `12 % 9 = 3` 步。  
3. **循环右移**：把 `flat` 最后 `k` 个元素搬到前面，其余元素往后挪。  
   - 这一步可以用 Python 的切片一次性完成。  
4. **还原**：把已经右移好的 `flat` 再按行写回到二维矩阵中。  

> **类比**：把矩阵想成一本书的所有页码顺序排好后，直接把最后 `k` 页放到最前面，其余页往后排。这样一次就完成了所有的 shift。

整个过程只遍历矩阵两次（一次展平，一次写回），时间与 `k` 无关，达到了最优。

#### 代码（Python）

```python
from typing import List

def shift_grid_optimal(grid: List[List[int]], k: int) -> List[List[int]]:
    m, n = len(grid), len(grid[0])
    total = m * n                     # 矩阵总元素个数

    # 1️⃣ 展平：把二维矩阵转成一维列表
    flat = [grid[i][j] for i in range(m) for j in range(n)]

    # 2️⃣ 只需要移动 k % total 步
    k %= total
    if k:                             # k 为 0 时直接返回原矩阵
        # 3️⃣ 循环右移：切片一次完成
        flat = flat[-k:] + flat[:-k]

    # 4️⃣ 还原：把一维列表重新写回到二维矩阵
    for idx, val in enumerate(flat):
        i, j = divmod(idx, n)          # divmod 同时返回商和余数，i 行号，j 列号
        grid[i][j] = val

    return grid
```

> **关键行解释**  
> - `flat = [grid[i][j] for i in range(m) for j in range(n)]`：把矩阵按行“展开”。  
> - `k %= total`：把大于矩阵长度的循环次数折算成等价的最小步数。  
> - `flat = flat[-k:] + flat[:-k]`：把最后 `k` 个元素搬到前面，实现循环右移。  
> - `i, j = divmod(idx, n)`：`idx` 是一维下标，`divmod` 同时给出行号 `i`（商）和列号 `j`（余数），写回矩阵时非常便利。

#### 复杂度

- **时间复杂度**：`O(m * n)`  
  展平、切片、写回每一步都只遍历一次矩阵。与 `k` 无关，远快于暴力解。  
  用大白话说：不管你要右移多少次，只要矩阵有 200 格，最多做 200 次搬家。

- **空间复杂度**：`O(m * n)`  
  需要一个额外的一维列表 `flat` 来保存所有元素。因为题目本身需要返回一个新矩阵，这个空间是必须的。

## 心得

- **核心技巧**：把二维结构展平为一维，再利用**循环右移**（数组旋转）完成整体平移。  
- **适用场景**：  
  1. 任意需要对矩阵/二维数组进行“整体平移”或“环形移动”的题目（如 LeetCode 1260 *Shift 2D Grid*）。  
  2. 把二维坐标映射到一维索引的技巧（如矩阵转一维 DP、图的邻接矩阵压缩）。  
  3. 需要把 **环形队列** 的概念用于数组的题目（如旋转数组、循环队列实现）。  
- **一句话总结**：把矩阵“拉直”，一次切片完成所有位移。

## 反思

- **第一反应**：直接按照题目描述一步步搬家，写两个嵌套循环模拟 shift。  
- **最容易踩的坑**：  
  - 忘记对 `k` 取模，导致在 `k` 大于矩阵长度时做无用的循环，时间爆炸。  
  - 在写回矩阵时行列索引算错（尤其是 `idx // n` 与 `idx % n` 的对应关系）。  
  - 直接在原矩阵上搬家会覆盖尚未搬走的值，需要额外的临时存储或一次性展平。  
- **下次遇到同类题**：第一步想到 **“把结构展平”，利用一维数组的旋转/切片来一次性完成整体移动**，再把结果映射回原来的二维结构。这样可以把时间从 `O(k·size)` 降到 `O(size)`。
