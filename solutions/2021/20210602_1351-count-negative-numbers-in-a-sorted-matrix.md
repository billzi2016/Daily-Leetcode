# #1351. 统计已排序矩阵中的负数 / Count Negative Numbers in a Sorted Matrix

> 难度：简单 · 标签：Array、Binary Search、Matrix · [LeetCode 链接](https://leetcode.com/problems/count-negative-numbers-in-a-sorted-matrix/)

---

## 题目（英文原版）

**Description**

Given a m x n matrix grid which is sorted in non-increasing order both row-wise and column-wise, return the number of negative numbers in grid.

**Examples**

**Example 1:**

```
Input: grid = [[4,3,2,-1],[3,2,1,-1],[1,1,-1,-2],[-1,-1,-2,-3]]
Output: 8
Explanation: There are 8 negatives number in the matrix.
```

**Example 2:**

```
Input: grid = [[3,2],[1,0]]
Output: 0
```

**Constraints**

- m == grid.length
- n == grid[i].length
- 1 <= m, n <= 100
- -100 <= grid[i][j] <= 100

给定一个 `m × n` 矩阵 `grid`，该矩阵在行方向和列方向上均按非递增顺序（non‑increasing order）排序，返回矩阵中负数（negative numbers）的个数。

- `-100 <= grid[i][j] <= 100`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是把矩阵里的每个元素都检查一遍，看到负数就计数。  
- **用到的数据结构**：二维列表（list of list），在 Python 里就像我们平时写的表格，每一行是一个 list，所有行组成外层的 list。  
- **生活化类比**：把矩阵想象成一本账本，里面每格记着一个数字。我们把账本的每一页（行）翻过去，逐格查看是否为负数，就像数数账本里有多少笔亏损。  
- **为什么正确**：因为题目只要求统计负数的个数，只要遍历所有位置并判断符号，就一定能得到正确答案。  

#### 代码（Python）

```python
def countNegatives(grid):
    """
    暴力遍历矩阵的每个元素，统计负数个数
    :param grid: List[List[int]]，已排序的矩阵
    :return: int，负数的数量
    """
    cnt = 0                     # 计数器，记录负数出现的次数
    for row in grid:            # 逐行遍历
        for val in row:         # 逐个元素遍历
            if val < 0:         # 判断是否为负数
                cnt += 1       # 是负数就计数
    return cnt
```

#### 复杂度  

- **时间复杂度**：`O(m·n)`  
  这里的 `m` 是行数，`n` 是列数。意思是我们最坏情况下要检查矩阵里的每一个格子，总共 `m*n` 次操作。可以把它想象成“一遍遍数完所有格子”，所以时间随矩阵大小线性增长。  
- **空间复杂度**：`O(1)`  
  只用了几个额外的变量（计数器 `cnt`），不随输入规模增长，所以是常数级别的空间开销。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **每个元素都要检查一次**，但题目已经告诉我们矩阵在行和列上都是「非递增」的（从左到右、从上到下都是递减或相等）。利用这个特性，我们可以 **跳过大量肯定为非负的元素**，只关注可能为负的区域。

**关键观察**：

- 对于任意一行，若某个位置 `j` 的数是负的，则该行中 **它右边的所有数**（更靠右的列）必然也都是负的，因为顺序是非递增的。  
- 同理，对任意一列，若某个位置 `i` 的数是负的，则 **它下方的所有数**（更靠下的行）也一定是负的。  

基于上述观察，有两种常见的线性时间做法：

1. **从左下角出发的双指针**（最常见）  
   - 把指针放在矩阵的左下角 `(row = m-1, col = 0)`。  
   - 若当前值是负的，说明这一列从 `row` 到最上面都是负的，直接把负数计数 `row+1`（因为行号从 0 开始）。随后向右移动一列 `col += 1`，因为右边的数更大，可能不再是负的。  
   - 若当前值是非负的，说明这一行的左侧（包括当前格子）都不是负数，直接向上移动一行 `row -= 1`，继续检查更小的数。  
   - 最终指针会走出矩阵边界，遍历过程最多 `m + n` 步。

2. **对每行使用二分查找**（利用「行内有序」）  
   - 对每一行在有序的区间 `[0, n-1]` 做二分，找出第一个负数出现的位置 `pos`。  
   - 该行负数的个数就是 `n - pos`（从 `pos` 到最后都是负的）。  
   - 二分的时间是 `O(log n)`，对 `m` 行共 `O(m log n)`，在本题的约束（`m,n ≤ 100`）下也足够快。  

下面给出 **左下角双指针** 的实现，因为它只需要 `O(1)` 额外空间且代码更直观。

#### 代码（Python）

```python
def countNegatives(grid):
    """
    使用左下角双指针技巧，只遍历 O(m + n) 次即可统计负数个数
    :param grid: List[List[int]]，已排序的矩阵
    :return: int，负数的数量
    """
    m = len(grid)          # 行数
    n = len(grid[0])       # 列数
    row = m - 1            # 从最底部开始
    col = 0                # 从最左侧开始
    cnt = 0                # 计数器

    while row >= 0 and col < n:   # 只要指针没有跑出矩阵边界就继续
        if grid[row][col] < 0:    # 当前格子是负数
            # 这一列从第0行到当前row都是负的，数量为 row+1
            cnt += row + 1
            col += 1              # 向右走，尝试找更大的数（可能不再是负的）
        else:                     # 当前格子是非负数
            row -= 1              # 向上走，寻找更小的数

    return cnt
```

#### 复杂度  

- **时间复杂度**：`O(m + n)`  
  解释：指针每次要么向上走一步，要么向右走一步，最多走 `m` 次上移加 `n` 次右移，总步数不超过 `m + n`。把它想象成「从左下角爬到右上角，只能往上或往右走」的过程。  
- **空间复杂度**：`O(1)`  
  只用了几个整数变量（行指针、列指针、计数器），不随矩阵大小增长。

## 心得

- **核心技巧**：利用矩阵的单调性（行列非递增）进行「指针跳跃」或「二分查找」，把原本的 `O(m·n)` 降到 `O(m + n)` 或 `O(m log n)`。  
- **适用的题型**：  
  1. **统计矩阵中满足某种单调条件的元素**（如正数、零、特定阈值以上的数）。  
  2. **在有序二维数组中查找目标值**（LeetCode 240 – Search a 2D Matrix II）。  
  3. **求矩阵中满足不等式的元素数量**（如 `grid[i][j] <= target`）。  
- **一句话总结解题钥匙**：**“从左下角（或右上角）出发，利用单调性一步步排除整行/整列”**。

## 反思

- **第一反应**：看到“矩阵已排序”，立刻想到可以用二分或双指针来加速，而不是逐个遍历。  
- **最容易踩的坑**：  
  - 忘记矩阵是 **非递增**（从大到小），如果误以为是递增会导致指针移动方向相反。  
  - 边界条件处理不当：指针越界时要及时停止循环；计数时要使用 `row + 1`（因为行号从 0 开始）。  
- **下次遇到同类题**：第一步先确认矩阵的单调方向，然后决定是 **从左下角/右上角** 开始遍历，还是对每行/每列做二分搜索。这样就能立刻把时间复杂度从平方级降到线性或对数级。
