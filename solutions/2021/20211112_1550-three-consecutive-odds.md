## 题目（中文翻译）

给定一个整数数组 `arr`，如果数组中存在 **三个连续的奇数（odd）**，则返回 `true`；否则返回 `false`。

**示例**

**示例 1**  
输入: `arr = [2,6,4,1]`  
输出: `false`  
解释: 数组中不存在三个连续的奇数。

**示例 2**  
输入: `arr = [1,2,34,3,4,5,7,23,12]`  
输出: `true`  
解释: 子数组 `[5,7,23]` 是三个连续的奇数。

**约束条件**

- `1 <= arr.length <= 1000`
- `1 <= arr[i] <= 1000`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把数组里 **每一个位置** 当作“三连” 的起点，分别检查它后面的两个数是否都是奇数。  
- 用到的唯一数据结构是 **数组** 本身，想象成一排排盒子，顺序不能乱。  
- 为什么能得到正确答案？因为只要我们把所有可能的「连续三个」都枚举一遍，就一定会碰到满足条件的那一组三个（如果它真的存在）。  
- 这种做法的时间代价有点像「一把把钥匙去尝试每一把锁」：外层循环遍历 `n` 次，内层固定检查 3 次（常数），所以整体是 **O(n·3) ≈ O(n)**。如果把「检查三个数」写成另一个循环（虽然实际也是 3 次），就会看起来是 **O(n²)**，这里先把它当作「暴力」的思路来讲。

#### 代码（Python）

```python
def threeConsecutiveOdds(arr):
    n = len(arr)
    # 遍历每一个可能的起点 i（只能到 n-3，因为后面要有两个数）
    for i in range(n - 2):
        # 检查 i, i+1, i+2 三个数是否都是奇数
        # 奇数的判断方式：num % 2 == 1
        if arr[i] % 2 == 1 and arr[i + 1] % 2 == 1 and arr[i + 2] % 2 == 1:
            return True        # 找到了，直接返回
    return False               # 全部遍历完都没有，返回 False
```

#### 复杂度  

- **时间复杂度：O(n)**  
  `n` 是数组长度。我们最多只看每个元素一次（加上它后面的两个），所以时间随 `n` 线性增长。  
- **空间复杂度：O(1)**  
  只用了常数个额外变量（`i`、`n`），不随输入规模增大而增加。

### 2. 最优解

#### 思路  

从暴力解可以看到，真正的**瓶颈**并不在于「检查三个数」本身，而是**每次都要重新判断这三个数的奇偶性**。  
如果在一次遍历中**记录当前连续奇数的长度**，当这个长度达到 3 时就可以立刻返回 `True`，否则继续往后走。这样我们只需要一次线性扫描，且不需要每次都访问三个位置的奇偶性。

核心技巧是 **计数器**（counter）：

1. 初始化计数器 `cnt = 0`。  
2. 从左到右遍历数组：  
   - 若当前元素是奇数，则 `cnt += 1`；  
   - 若是偶数，则把计数器清零 `cnt = 0`（因为奇数序列被打断了）。  
3. 每次更新计数器后检查 `cnt >= 3`，如果成立直接返回 `True`。  
4. 循环结束仍未找到，则返回 `False`。

把计数器想象成「连续奇数的记分牌」，每遇到一个奇数就加一，遇到偶数就重新开始记分。

#### 代码（Python）

```python
def threeConsecutiveOdds(arr):
    cnt = 0                     # 连续奇数的计数器
    for num in arr:            # 依次遍历数组中的每个数
        if num % 2 == 1:       # 奇数 → 计数器加一
            cnt += 1
            if cnt >= 3:       # 已经连续出现 3 个奇数，直接返回 True
                return True
        else:                  # 偶数 → 连续奇数被中断，计数器归零
            cnt = 0
    return False                # 遍历完都没有满足条件
```

#### 复杂度  

- **时间复杂度：O(n)**  
  只遍历一次数组，`n` 增大时耗时线性增长。与暴力解的时间复杂度相同，但实际常数更小（不需要每次检查 3 次）。  
- **空间复杂度：O(1)**  
  只使用了一个整数计数器 `cnt`，空间不随输入规模变化。

## 心得

- 这道题考察的是 **滑动窗口/计数器** 的思想：在一次遍历中维护一个状态（这里是连续奇数的长度），从而避免重复检查。  
- 类似的技巧也常用于：  
  1. **连续子数组和为目标值**（滑动窗口）  
  2. **判断数组中是否存在连续的 k 个相同字符**（计数器）  
  3. **判断字符串中是否有连续的 3 个元音**（同理）  
- **解题钥匙**：把「连续」的概念抽象成一个递增的计数器，遇到不满足条件的元素就把计数器清零。

## 反思

- **第一反应**：把所有长度为 3 的子数组枚举一遍，逐个检查奇偶性。  
- **最容易踩的坑**：  
  - 忘记在遍历到数组尾部时停止（`range(len(arr)-2)`），导致索引越界。  
  - 判断奇数时使用 `num % 2 != 0` 更安全，避免负数情况下的错误（本题数据都是正数，但养成好习惯）。  
  - 没有在遇到偶数时及时把计数器清零，导致错误的连续计数。  
- **下次遇到同类题**：第一步先思考「能不能用一个变量记录当前状态」——比如连续出现的次数、当前窗口的和、当前子串的长度等，然后在一次遍历中实时更新。这样往往能把看似 O(n²) 的暴力思路压缩到 O(n)。
