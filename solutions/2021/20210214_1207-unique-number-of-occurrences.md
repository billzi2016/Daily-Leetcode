# #1207. 唯一出现次数 / Unique Number of Occurrences

> 难度：简单 · 标签：Array、Hash Table · [LeetCode 链接](https://leetcode.com/problems/unique-number-of-occurrences/)

---

## 题目（英文原版）

**Description**

Given an array of integers arr, return true if the number of occurrences of each value in the array is unique or false otherwise.

**Examples**

**Example 1:**

```
Input: arr = [1,2,2,1,1,3]
Output: true
Explanation: The value 1 has 3 occurrences, 2 has 2 and 3 has 1. No two values have the same number of occurrences.
```

**Example 2:**

```
Input: arr = [1,2]
Output: false
```

**Example 3:**

```
Input: arr = [-3,0,1,-3,1,1,1,-3,10,0]
Output: true
```

**Constraints**

- 1 <= arr.length <= 1000
- -1000 <= arr[i] <= 1000

---

## 题目（中文翻译）

给定一个整数数组（array）`arr`，如果数组中每个数值的出现次数都是唯一的，则返回 `true`，否则返回 `false`。

**示例 1**  
**输入**: `arr = [1,2,2,1,1,3]`  
**输出**: `true`  
**解释**: 数值 `1` 出现了 3 次，`2` 出现了 2 次，`3` 出现了 1 次。没有两个数值的出现次数相同。

**示例 2**  
**输入**: `arr = [1,2]`  
**输出**: `false`  
**解释**: 两个数值的出现次数都是 1，出现次数不唯一。

**示例 3**  
**输入**: `arr = [-3,0,1,-3,1,1,1,-3,10,0]`  
**输出**: `true`  
**解释**: 出现次数分别为 `-3` → 3 次，`0` → 2 次，`1` → 4 次，`10` → 1 次，均不相同。

**约束条件**  
- `1 <= arr.length <= 1000`  
- `-1000 <= arr[i] <= 1000`

---

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**对每一个元素都去数它在数组里出现了多少次**，然后把这些出现次数放进一个列表，最后检查列表里有没有重复的次数。  
- **数据结构**：我们只需要普通的 Python `list`（相当于生活中的装东西的盒子），把每个数的出现次数装进去。  
- **为什么正确**：只要把每个不同的数的出现次数全部算出来，比较这些次数是否全部不同，就能得到答案。  

> 类比：想象你在超市里数每种水果的数量，记下来后再看有没有两种水果的数量相同。只要数对了，比较自然就对了。

#### 代码（Python）

```python
def unique_occurrences_bruteforce(arr):
    # 1. 记录每个不同元素的出现次数
    counts = []                     # 用来存放所有出现次数的列表
    visited = set()                 # 已经统计过的元素，防止重复计数

    for i in range(len(arr)):
        if arr[i] in visited:       # 已经统计过，直接跳过
            continue
        visited.add(arr[i])

        # 统计 arr[i] 在数组中出现的次数（遍历整个数组）
        cnt = 0
        for j in range(len(arr)):
            if arr[j] == arr[i]:
                cnt += 1
        counts.append(cnt)          # 把这一次的计数加入列表

    # 2. 检查是否有重复的出现次数
    # 用集合去重后再比较长度
    return len(counts) == len(set(counts))
```

#### 复杂度  

- **时间复杂度**：`O(n²)`  
  - 外层遍历 `n` 次，内层又遍历 `n` 次来计数，整体是 `n × n`。  
  - 大白话：如果数组有 1000 个数，最坏情况下要做 1000×1000＝1,000,000 次比较，算是“慢慢来”。  
- **空间复杂度**：`O(n)`  
  - 需要额外的列表 `counts` 最多保存 `n` 个计数，还要一个 `set` 记录已经遍历过的元素。  

---

### 2. 最优解

#### 思路  

从暴力解可以看到，**瓶颈在于每次都要遍历整个数组去统计出现次数**。其实我们可以一次遍历数组，就把每个数的出现次数记录下来，这正是 **哈希表（Python 中的 dict）** 擅长的事。  

1. **第一遍遍历**：把每个数当作键（key），出现的次数当作值（value）放进字典。  
   - 类比：把每种水果的名字写在字典里，旁边记上它的数量。查找和更新都是 `O(1)`，就像在字典里直接翻到对应页码。  
2. **第二遍遍历**：把字典里所有的出现次数取出来，检查这些次数是否全部唯一。  
   - 再使用一个集合（set）去重，如果集合的大小和原来的次数列表大小相同，说明没有重复。  

这样只需要 **两次线性遍历**，时间从 `O(n²)` 降到 `O(n)`，空间仍然是 `O(n)`（因为要存储每个不同元素的计数）。

#### 代码（Python）

```python
def unique_occurrences_optimal(arr):
    # 1. 用哈希表统计每个数的出现次数
    freq = {}                       # key: 数字, value: 出现次数
    for num in arr:                 # 只遍历一次数组
        freq[num] = freq.get(num, 0) + 1   # get() 若键不存在返回 0

    # 2. 检查出现次数是否唯一
    occ_counts = list(freq.values())        # 取出所有出现次数
    # 把出现次数放进集合去重后比较长度
    return len(occ_counts) == len(set(occ_counts))
```

#### 复杂度  

- **时间复杂度**：`O(n)`  
  - 只遍历数组一次（`n` 次）来构建哈希表，再遍历哈希表的键值（最多也是 `n` 次），所以总体是线性时间。  
  - 与暴力解相比，时间从“每个元素要检查所有元素”变成“每个元素只检查一次”。  
- **空间复杂度**：`O(n)`  
  - 需要存储哈希表 `freq`（最多 `n` 条记录）和一个集合 `set` 用来去重出现次数。

## 心得

- **核心技巧**：使用哈希表（字典）一次遍历统计频次，再利用集合判断唯一性。  
- **适用的题型**  
  1. “出现次数”类问题，如 **“找出出现次数超过 ⌈n/3⌉ 的元素”**（多数投票算法的变形）。  
  2. “频次唯一”类问题，如 **“检查两个数组是否是字母异位词”**（统计字符出现次数）。  
  3. “计数+去重”类问题，如 **“数组中是否存在两个数出现次数相同”**（与本题相反的判断）。  
- **一句话总结解题钥匙**：**“一次遍历把计数写进字典，集合去重快速比较”。**

## 反思

- **第一反应**：看到“出现次数唯一”，第一时间想到用 **计数 + 判断唯一**，但一开始会想用两层循环去手动计数。  
- **最容易踩的坑**  
  - **忘记去重**：直接比较计数列表会误判，需要用集合去重后再比较长度。  
  - **负数或零**：数组元素可能是负数或 0，哈希表键可以是任意可哈希对象，不会有问题，但要确保 `dict.get` 的默认值写对。  
  - **空数组**：虽然题目限制长度≥1，但如果放宽约束，空数组应返回 `True`（没有冲突的计数）。  
- **下次遇到同类题**：**先想“一遍遍历统计 + 用集合检查唯一”。** 只要把计数过程抽象成“把东西装进字典”，后面的唯一性检查几乎都是集合操作。
