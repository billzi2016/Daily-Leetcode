# #1201. 丑数 III / Ugly Number III

## 题目（英文原版）

**Description**

An ugly number is a positive integer that is divisible by a, b, or c.
Given four integers n, a, b, and c, return the nth ugly number.

**Examples**

**Example 1:**

```
Input: n = 3, a = 2, b = 3, c = 5
Output: 4
Explanation: The ugly numbers are 2, 3, 4, 5, 6, 8, 9, 10... The 3rd is 4.
```

**Example 2:**

```
Input: n = 4, a = 2, b = 3, c = 4
Output: 6
Explanation: The ugly numbers are 2, 3, 4, 6, 8, 9, 10, 12... The 4th is 6.
```

**Example 3:**

```
Input: n = 5, a = 2, b = 11, c = 13
Output: 10
Explanation: The ugly numbers are 2, 4, 6, 8, 10, 11, 12, 13... The 5th is 10.
```

**Constraints**

- 1 <= n, a, b, c <= 109
- 1 <= a * b * c <= 1018
- It is guaranteed that the result will be in range [1, 2 * 109].

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**从 1 开始枚举**，把每一个正整数判断它是否能被 `a`、`b` 或 `c` 整除，只要满足其中任意一个条件，就把它记为“丑数”。当记到第 `n` 个丑数时，就把它返回。

- **数据结构**：这里只需要一个计数器 `cnt`（相当于在超市排队计数），以及一个循环变量 `x`（相当于超市里一件件商品的编号）。  
- **为什么正确**：题目定义的“丑数”就是“能被 a、b、c 中任意一个整除的正整数”。我们把所有正整数从小到大逐个检查，恰好按照题目要求的顺序遍历所有丑数，所以第 `n` 次遇到的就是第 `n` 个丑数。  
- **复杂度分析**：  
  - **时间**：最坏情况下我们可能要检查很多数才能找到第 `n` 个丑数。假设第 `n` 个丑数大约是 `k`，那么我们会循环 `k` 次。`k` 与 `n` 成正比（因为每隔大约 `1/(1/a+1/b+1/c)` 个数就会出现一个丑数），所以时间复杂度可以写成 **O(k)**，在最坏情况下约等于 **O(n·max(a,b,c))**，这在 `n`、`a`、`b`、`c` 均可达 `10^9` 时根本不可行。  
  - **空间**：只用了几个整数，**O(1)**（常数级空间）。

> **大白话**：如果把 `O(n²)` 想象成“每走一步都要检查 n² 次”，那这里的 `O(k)` 就是“走到第 k 步才停”。当 k 很大时，跑一遍就会花掉几分钟甚至更久。

#### 代码（Python）

```python
def nthUglyNumber_brute(n: int, a: int, b: int, c: int) -> int:
    """
    暴力枚举法：从 1 开始逐个检查是否是丑数，直到找到第 n 个。
    """
    cnt = 0          # 已经找到的丑数个数
    x = 1            # 当前检查的正整数
    while True:
        # 判断 x 是否能被 a、b、c 中任意一个整除
        if x % a == 0 or x % b == 0 or x % c == 0:
            cnt += 1          # 找到一个丑数，计数器加一
            if cnt == n:      # 第 n 个丑数找到了
                return x
        x += 1                # 检查下一个正整数
```

#### 复杂度

- **时间复杂度**：`O(k)`（`k` 为第 n 个丑数的数值），在最坏情况下约等于 `O(n·max(a,b,c))`。  
- **空间复杂度**：`O(1)`，只用了常数个变量。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**逐个检查每个整数**，这会导致遍历次数太多。我们需要一种**跳过无关数**、直接定位第 `n` 个丑数的方法。

关键观察：

1. **单调性**  
   定义函数 `f(k)` 为 ≤ `k` 的丑数个数。随着 `k` 增大，`f(k)` 只会增加或保持不变（永不下降），这叫**单调递增**。  
   这意味着我们可以在有序的数轴上使用**二分查找**：如果 `f(mid) >= n`，说明第 `n` 个丑数在 `mid` 左侧（或就是 `mid` 本身），否则在右侧。

2. **如何快速求 `f(k)`**  
   直接枚举显然太慢。我们可以利用**容斥原理**（Inclusion‑Exclusion）一次性算出 ≤ `k` 的丑数数量。  
   - 能被 `a` 整除的数有 `k // a` 个。  
   - 能被 `b` 整除的数有 `k // b` 个。  
   - 能被 `c` 整除的数有 `k // c` 个。  
   - 但上面三类数中，有些数会被重复计数（比如能同时被 `a` 与 `b` 整除的数），我们需要减掉这些重复计数。  
   - 两两交集的计数是 `k // lcm(a, b)`、`k // lcm(a, c)`、`k // lcm(b, c)`。  
   - 三者全部交集（即能同时被 `a、b、c` 整除的数）会被前面的减法多减一次，需要再加回来一次：`k // lcm(a, b, c)`。  

   于是：

   ```
   f(k) = k//a + k//b + k//c
          - k//lcm(a,b) - k//lcm(a,c) - k//lcm(b,c)
          + k//lcm(a,b,c)
   ```

   这里的 `lcm`（最小公倍数）可以通过 `gcd`（最大公约数）求得：`lcm(x, y) = x // gcd(x, y) * y`。

3. **二分范围**  
   - 最小可能的丑数是 `1`（因为题目保证所有输入都是正整数）。  
   - 最大可能的第 `n` 个丑数不会超过 `2·10^9`（题目已经给出），我们可以直接取上界 `hi = 2 * 10**9`。  
   - 进行标准的左闭右闭二分，直到 `lo == hi`，此时 `lo` 正好是第 `n` 个丑数。

4. **为什么二分 + 容斥是最优的**  
   - 每一次二分只需要 **O(1)** 的时间来计算 `f(mid)`（几次除法和 `gcd`），二分的迭代次数是 `log2(2·10^9) ≈ 31`，非常小。  
   - 因此整体时间复杂度是 **O(log MaxAnswer)**，空间仍是 **O(1)**。

#### 代码（Python）

```python
import math

def nthUglyNumber(n: int, a: int, b: int, c: int) -> int:
    """
    二分查找 + 容斥原理求第 n 个丑数
    """

    # ---------- 辅助函数 ----------
    def lcm(x: int, y: int) -> int:
        """返回 x 与 y 的最小公倍数，使用 gcd 防止溢出"""
        return x // math.gcd(x, y) * y

    # 预先算好两两以及三者的最小公倍数，后面会复用
    ab = lcm(a, b)
    ac = lcm(a, c)
    bc = lcm(b, c)
    abc = lcm(ab, c)          # lcm(a,b,c) = lcm(lcm(a,b), c)

    def count_ugly(k: int) -> int:
        """
        返回 ≤ k 的丑数个数，利用容斥原理
        """
        # 单独计数
        total = k // a + k // b + k // c
        # 减去两两交集的重复计数
        total -= k // ab + k // ac + k // bc
        # 加回三者交集被多减掉的部分
        total += k // abc
        return total

    # ---------- 二分查找 ----------
    lo, hi = 1, 2 * 10**9   # 题目保证答案在此区间
    while lo < hi:
        mid = (lo + hi) // 2
        if count_ugly(mid) >= n:   # 第 n 个丑数在左半边或就是 mid
            hi = mid
        else:                       # 第 n 个丑数在右半边
            lo = mid + 1
    return lo
```

#### 复杂度

- **时间复杂度**：`O(log MaxAnswer)`，约为 `O(31)` 次循环，每次只做常数次除法和 `gcd`，可以视作 **O(log 2·10^9)**。相比暴力的 `O(k)`，速度提升数千倍以上。  
- **空间复杂度**：`O(1)`，只用了若干整数变量，没有额外的数据结构。

## 心得

- **核心技巧**：**单调函数 + 二分查找** 与 **容斥原理** 的结合。  
- **适用题型**：  
  1. “第 k 小的数” 类问题（如第 k 小的乘积、数列中的第 k 大元素），只要能写出一个单调计数函数 `f(x)`。  
  2. “满足某种条件的数的个数” 需要快速求解的场景，常用容斥原理或前缀和技巧。  
- **一句话总结**：把“找第 n 个丑数”转化为“在多少范围内有至少 n 个丑数”，用二分定位最小满足条件的值。

## 反思

- **第一反应**：直接枚举，想到“从 1 开始检查每个数”。这在小数据时可行，但忽视了题目给出的上界极大。  
- **最容易踩的坑**：  
  - **整数溢出**：计算 `lcm` 时若先相乘再除会超出 64 位整数范围，正确做法是先除后乘（`x // gcd(x, y) * y`）。  
  - **容斥符号写错**：忘记最后的加 `k // lcm(a,b,c)`，会导致计数偏少。  
  - **二分边界**：左闭右闭写法容易写成无限循环，记得在 `lo < hi` 循环体内正确更新 `lo` 与 `hi`。  
- **下次类似题目**：第一步先思考“是否可以把问题转化为‘在某个阈值内有多少满足条件的元素’”，然后检查该计数函数是否单调，若单调则立刻考虑二分搜索。这样可以把暴力的线性搜索压缩到对数级别。
