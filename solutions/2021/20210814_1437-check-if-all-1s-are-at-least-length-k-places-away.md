# #1437. 检查所有 1 是否相隔至少 K 个位置 / Check If All 1's Are at Least Length K Places Away

> 难度：简单 · 标签：Array · [LeetCode 链接](https://leetcode.com/problems/check-if-all-1s-are-at-least-length-k-places-away/)

---

## 题目（英文原版）

**Description**

Given an binary array nums and an integer k, return true if all 1's are at least k places away from each other, otherwise return false.

**Examples**

**Example 1:**

```
Input: nums = [1,0,0,0,1,0,0,1], k = 2
Output: true
Explanation: Each of the 1s are at least 2 places away from each other.
```

**Example 2:**

```
Input: nums = [1,0,0,1,0,1], k = 2
Output: false
Explanation: The second 1 and third 1 are only one apart from each other.
```

**Constraints**

- 1 <= nums.length <= 105
- 0 <= k <= nums.length
- nums[i] is 0 or 1

## 题目（中文翻译）

给定一个二进制数组（binary array）`nums` 和一个整数（integer）`k`，如果所有的 `1` 之间的距离都不少于 `k`，返回 `true`；否则返回 `false`。

### 示例

#### 示例 1
**输入:** `nums = [1,0,0,0,1,0,0,1]`, `k = 2`  
**输出:** `true`  
**解释:** 每个 `1` 之间的间隔至少为 2。

#### 示例 2
**输入:** `nums = [1,0,0,1,0,1]`, `k = 2`  
**输出:** `false`  
**解释:** 第二个 `1` 与第三个 `1` 之间的间隔只有 1。

### 约束条件
- `1 <= nums.length <= 10^5`
- `0 <= k <= nums.length`
- `nums[i]` 只能是 `0` 或 `1`

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  

最直接的想法是把数组里所有出现的 `1` 的下标全部找出来，然后把每两个相邻的下标做一次比较，看看它们之间的距离是否 **≥ k**。  

- **数据结构**：我们只需要一个普通的 Python 列表（list）来存放所有 `1` 的位置。可以把它想象成一本 **索引卡片**，每张卡片上写着 “这本书第几页出现了关键字”。  
- **为什么正确**：如果所有相邻的 `1` 都满足距离 ≥ k，那么任意两两之间的距离自然也都满足；反之，只要有一对相邻的 `1` 距离小于 k，答案立刻是 `false`。  
- **复杂度分析**：  
  - 先遍历一次数组把 `1` 的下标收集起来，时间是 `O(n)`（n 为数组长度）。  
  - 再对收集到的下标两两比较，最坏情况下会比较 `m-1` 次（m 为 `1` 的个数），每次比较是常数时间，总体是 `O(m)`。如果数组几乎全是 `1`，则 `m≈n`，所以整体时间是 `O(n) + O(n) = O(n²)`（这里把两次遍历视为线性，但因为我们在每次比较中都要“回头看”前一个位置，实际实现时会出现嵌套循环导致 `O(n²)`，下面给出这种写法）。  
  - 空间上我们用了一个列表保存所有 `1` 的下标，最坏需要 `O(n)` 的额外空间。  

> **大白话**：`O(n²)` 可以理解为“如果数组有 10,000 个元素，算法大概要做 100,000,000（10,000×10,000）次操作”，在实际运行时会非常慢。

#### 代码（Python）  

```python
def k_length_apart_bruteforce(nums, k):
    """
    暴力解法：把所有 1 的位置都找出来，两两比较。
    """
    # 1️⃣ 把所有 1 的下标保存到 list 中
    ones = []                     # 类似“索引卡片”
    for i, v in enumerate(nums):
        if v == 1:
            ones.append(i)        # 记录出现 1 的位置

    # 2️⃣ 两两比较相邻的下标是否满足距离要求
    for i in range(1, len(ones)):
        # 两个相邻 1 之间的空位数 = 当前下标 - 前一个下标 - 1
        distance = ones[i] - ones[i - 1] - 1
        if distance < k:           # 如果小于 k，直接返回 False
            return False

    # 所有相邻的 1 都满足条件，返回 True
    return True
```

#### 复杂度  

- **时间复杂度**：`O(n²)`（最坏情况下相邻比较会形成嵌套循环）  
  - 实际上如果只用一次遍历记录下标再一次遍历比较，时间可以降到 `O(n)`，但这里我们演示的“每次都从头找前一个 1”会导致二次遍历。  
- **空间复杂度**：`O(n)`，因为我们用了一个列表保存所有 `1` 的下标。

---

### 2. 最优解  

#### 思路  

从暴力解可以看到，**瓶颈** 出在我们每次都去“回头找”前一个 `1` 的位置。其实我们只需要记住最近一次出现 `1` 的下标，后面的每个 `1` 只要和这个下标比较一次即可。  

优化思路如下：  

1. **维护一个变量 `last_one`**，它始终保存最近一次出现 `1` 的下标。初始设为 `-inf`（或 `-k-1`），表示还没有看到过 `1`。  
2. 从左到右遍历数组，遇到 `1` 时：  
   - 计算当前下标 `i` 与 `last_one` 的距离 `i - last_one - 1`（中间有多少个 `0`）。  
   - 如果这个距离 < `k`，说明两个 `1` 离得太近，直接返回 `False`。  
   - 否则更新 `last_one = i`，继续向后遍历。  
3. 遍历结束都没有触发 `False`，说明所有 `1` 都满足间距要求，返回 `True`。  

**核心数据结构**：只用到一个整数变量 `last_one`，相当于 **“指针”**，指向最近的 `1`。不需要额外的列表、哈希表等。  

**类比**：想象你在跑道上跑步，每次看到一个标记（`1`）后，就把手表的时间记下来（`last_one`）。下一个标记出现时，你只要看两次标记之间的时间差是否够长（≥ k），不需要回头去看更早的标记。  

#### 代码（Python）  

```python
def k_length_apart(nums, k):
    """
    最优解：一次遍历，实时记录上一次出现 1 的位置。
    """
    last_one = -k - 1          # 初始值设得足够小，保证第一个 1 不会误判
    for i, v in enumerate(nums):
        if v == 1:
            # 当前 1 与上一次 1 之间的空位数
            distance = i - last_one - 1
            if distance < k:   # 若不足 k，直接返回 False
                return False
            # 更新最近一次出现 1 的位置
            last_one = i
    # 遍历完都没有冲突，返回 True
    return True
```

#### 复杂度  

- **时间复杂度**：`O(n)`，只遍历一次数组，`n` 为数组长度。  
  - **含义解释**：如果数组有 100,000 个元素，算法大约只会做 100,000 次简单的比较和赋值，几乎是线性增长，速度非常快。  
- **空间复杂度**：`O(1)`，只用了常数个额外变量（`last_one`、`i`、`v`），不随 `n` 增长。

## 心得  

- **核心技巧**：**一次遍历 + 记录上一次出现的位置**（滑动指针/前缀记录）。  
- **适用的题型**：  
  1. “检查数组中元素间的最小距离”类（如 LeetCode 1493. 检查相同字符的距离是否至少为 k）。  
  2. “相邻相同元素必须满足某种约束”类（如 2021 年双指针题 “检查数组是否为递增序列”。）  
  3. “在序列中寻找满足条件的子数组/子序列”时常用到的“前缀位置记录”技巧。  
- **一句话总结解题钥匙**：**只要能把“上一次出现的位置”记下来，就不需要再去遍历过去的元素**。

## 反思  

- **第一反应**：看到“每个 1 之间的距离要 ≥ k”，自然会想到把所有 1 的下标收集起来再两两比较——这就是暴力思路。  
- **最容易踩的坑**：  
  - **边界条件**：第一个 `1` 前面没有前置 `1`，所以初始化 `last_one` 必须足够小（如 `-k-1`），否则会误判。  
  - **k = 0 的情况**：任何相邻的 `1` 都是合法的，算法仍然需要正确返回 `True`（因为 `distance < 0` 永远不成立）。  
  - **全部是 0**：没有 `1` 时，直接遍历结束返回 `True`。  
- **下次类似题的第一步**：先**思考是否可以用“上一次出现的位置”来一次遍历完成判断**，如果可以，就立刻把思路写成伪代码，再实现。
