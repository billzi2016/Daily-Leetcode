# #1219. 路径最大金子 / Path with Maximum Gold

## 题目（英文原版）

**Description**

In a gold mine grid of size m x n, each cell in this mine has an integer representing the amount of gold in that cell, 0 if it is empty.
Return the maximum amount of gold you can collect under the conditions:

**Examples**

**Example 1:**

```
Input: grid = [[0,6,0],[5,8,7],[0,9,0]]
Output: 24
Explanation:
[[0,6,0],
 [5,8,7],
 [0,9,0]]
Path to get the maximum gold, 9 -> 8 -> 7.
```

**Example 2:**

```
Input: grid = [[1,0,7],[2,0,6],[3,4,5],[0,3,0],[9,0,20]]
Output: 28
Explanation:
[[1,0,7],
 [2,0,6],
 [3,4,5],
 [0,3,0],
 [9,0,20]]
Path to get the maximum gold, 1 -> 2 -> 3 -> 4 -> 5 -> 6 -> 7.
```

**Constraints**

- m == grid.length
- n == grid[i].length
- 1 <= m, n <= 15
- 0 <= grid[i][j] <= 100
- There are at most 25 cells containing gold.

## 题目（中文翻译）

在一个大小为 `m x n` 的金矿网格（grid）中，每个单元格（cell）包含一个整数，表示该单元格中的金子（gold）数量，若为 `0` 则表示该单元格为空。  
返回在满足以下条件下，你能够收集的最大金子总量：

- 每次移动只能向上下左右四个方向中的任意一个相邻的单元格移动；
- 只能进入包含金子的单元格（即金子数量大于 `0` 的单元格）；
- 同一个单元格在同一路径中只能被访问一次；
- 你可以从任意含金子的单元格开始，也可以在任意含金子的单元格结束。

**示例 1**  
输入: `grid = [[0,6,0],[5,8,7],[0,9,0]]`  
输出: `24`  
解释:  
```
[[0,6,0],
 [5,8,7],
 [0,9,0]]
```  
获取最大金子的路径为 `9 -> 8 -> 7`，总和为 `24`。

**示例 2**  
输入: `grid = [[1,0,7],[2,0,6],[3,4,5],[0,3,0],[9,0,20]]`  
输出: `28`  
解释:  
```
[[1,0,7],
 [2,0,6],
 [3,4,5],
 [0,3,0],
 [9,0,20]]
```  
获取最大金子的路径为 `1 -> 2 -> 3 -> 4 -> 5 -> 6 -> 7`，总和为 `28`。

**约束条件**
- `m == grid.length`
- `n == grid[i].length`
- `1 <= m, n <= 15`
- `0 <= grid[i][j] <= 100`
- 金子所在的单元格至多有 `25` 个。

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  
最直接的想法是 **把所有可能的走法都枚举一遍**，找出金子总量最大的那条路径。  
- **从哪儿开始？** 题目说只能从含金的格子出发，所以我们可以把每个金格子当作起点，分别尝试。  
- **怎么走？** 每一步可以向上、下、左、右四个方向移动，只要没有越界且该格子里还有金子（>0）。  
- **怎么防止走回头路？** 为了避免无限循环，需要把已经走过的格子标记为“已访问”。这类似于 **哈希表查字典**：字典的键是格子坐标，值是「是否已经用过」的布尔标记。  
- **什么时候结束？** 当四个方向都走不通（要么越界，要么格子是 0，要么已经被访问），这条路径就算结束，记录下当前收集的金子总和。  

把上述步骤写成递归函数：  
1. 把当前格子的金子加入累计值。  
2. 把当前格子标记为已访问（相当于把字典里对应的键设为 True）。  
3. 递归尝试四个方向，返回每条分支的最大金子数。  
4. 递归结束后，把标记恢复（回溯），这样后面的起点仍然可以使用这块格子。  

因为 **每个格子最多只会被访问一次**，所有路径的数量实际上是所有金格子的排列组合——在最坏情况下是 `4^k`（k 为金格子数量），这已经是「全部尝试」的意思了。  

#### 代码（Python）  

```python
from typing import List

def getMaximumGold(grid: List[List[int]]) -> int:
    # 方向向量：上、下、左、右
    dirs = [(-1, 0), (1, 0), (0, -1), (0, 1)]
    m, n = len(grid), len(grid[0])
    ans = 0                     # 记录全局最大金子数

    def dfs(x: int, y: int, cur: int) -> None:
        """
        深度优先搜索，收集从 (x, y) 开始的所有可能路径的金子总和。
        参数 cur 表示到目前为止已经收集的金子数量。
        """
        nonlocal ans
        # 把当前格子的金子加入累计，并更新全局最大值
        cur += grid[x][y]
        ans = max(ans, cur)

        # 暂时把当前格子置零，表示「已经访问」；
        # 这里直接改动 grid，后面回溯时会恢复原值。
        original = grid[x][y]
        grid[x][y] = 0          # 标记为已访问

        # 向四个方向继续探索
        for dx, dy in dirs:
            nx, ny = x + dx, y + dy
            # 检查是否还能继续前进：要在矩阵内部且格子里还有金子
            if 0 <= nx < m and 0 <= ny < n and grid[nx][ny] > 0:
                dfs(nx, ny, cur)

        # 回溯：恢复当前格子的金子数，以便其他起点能够使用它
        grid[x][y] = original

    # 对每个含金格子尝试一次 DFS
    for i in range(m):
        for j in range(n):
            if grid[i][j] > 0:          # 只从有金子的格子出发
                dfs(i, j, 0)

    return ans
```

#### 复杂度  

- **时间复杂度：** `O(m * n * 4^k)`，其中 `k` 为金格子的数量（最多 25）。  
  - 大白话：我们会从每个金格子出发（最多 `m*n` 次），每一步最多有 4 条分支，最深的递归层数不超过金格子总数 `k`，所以最坏情况下会尝试大约 `4^k` 条路径。由于 `k ≤ 25`，实际运行很快。  
- **空间复杂度：** `O(k)`，递归栈的最大深度不超过金格子数 `k`，另外我们在原地修改 `grid` 来记录访问状态，省去了额外的 visited 数组。

### 2. 最优解  

#### 思路  
从暴力解可以看到，**真正的瓶颈在于不必要的重复搜索**。如果在搜索过程中把已经访问过的格子记下来，就能避免走回头路，显著降低分支数。  

下面的「最优解」其实就是 **带有剪枝的回溯（Backtracking）**：  

1. **只从金格子出发**，这一步在暴力解里已经做了。  
2. **在递归过程中立即把当前格子标记为已访问**（这里我们直接把格子值设为 0），这样后面的递归分支就不会再走进这块格子，等递归返回后再恢复原值（回溯）。  
3. **实时更新全局最大值**，不必等到递归全部结束才比较。  
4. **剪枝**：如果当前累计的金子数已经加上剩余未访问的所有金子（上限）仍然小于当前已知的最大值，就可以提前终止这条分支。不过因为金格子最多只有 25 块，实际运行已经足够快，这一步可选。这里我们给出最简洁、易懂的版本——只用「标记/恢复」即可。

核心数据结构仍然是 **二维数组**（存放金子数量），以及 **递归栈**（隐式的调用栈）。我们把「已经访问」的概念直接写进数组里，省去了额外的哈希表或集合，让代码更直观。  

> **类比**：把矿场想象成一张棋盘，玩家只能走到还没踩过的格子上，踩一次就把格子「封住」——这正是我们把格子设为 0 的含义。

#### 代码（Python）  

```python
from typing import List

def getMaximumGold(grid: List[List[int]]) -> int:
    dirs = [(-1, 0), (1, 0), (0, -1), (0, 1)]
    m, n = len(grid), len(grid[0])
    best = 0                       # 最终答案

    def backtrack(x: int, y: int, cur: int) -> None:
        """
        回溯搜索，cur 为到目前为止收集的金子数。
        """
        nonlocal best
        cur += grid[x][y]          # 收集当前格子的金子
        best = max(best, cur)      # 更新全局最大值

        # 标记为已访问
        original = grid[x][y]
        grid[x][y] = 0

        # 继续向四个方向探索
        for dx, dy in dirs:
            nx, ny = x + dx, y + dy
            if 0 <= nx < m and 0 <= ny < n and grid[nx][ny] > 0:
                backtrack(nx, ny, cur)

        # 回溯：恢复格子原来的金子数
        grid[x][y] = original

    # 从每个含金格子尝试一次回溯
    for i in range(m):
        for j in range(n):
            if grid[i][j] > 0:
                backtrack(i, j, 0)

    return best
```

#### 复杂度  

- **时间复杂度：** `O(4^k)`（实际常数更小），因为每条有效路径最多访问 `k`（≤25）块金格子，且每一步只会向未访问的方向继续。相比暴力解去掉了对所有 `m*n` 起点的冗余搜索，实际运行时间大幅下降。  
- **空间复杂度：** `O(k)`，递归深度最多 `k`，同样只需要保存调用栈。

## 心得  

- **核心技巧**：**回溯（Backtracking）** —— 在搜索过程中「做选择、标记、继续搜索、撤销选择」的套路。  
- **适用的题型**：  
  1. **岛屿问题**（如 LeetCode 200: Number of Islands）——使用 DFS 标记已访问的陆地。  
  2. **单词搜索**（LeetCode 79: Word Search）——在矩阵中逐字符尝试路径，同样需要标记/回溯。  
  3. **机器人运动**（LeetCode 980: Unique Paths III）——要求遍历所有非障碍格子，也用回溯。  
- **一句话总结**：**把「走过的路」记下来，递归时不停「尝试 → 标记 → 撤销」即可得到最优答案。**

## 反思  

- **第一反应**：看到“最大金子”“只能走四方向”“不能重复访问”，立刻想到 DFS/回溯。  
- **最容易踩的坑**：  
  - 忘记在递归结束后恢复格子的原始金子值，导致后面的起点误以为格子已经被占用。  
  - 边界条件处理不全：越界或格子为 0 时必须立刻返回。  
  - 递归深度可能达到 25，若使用 Python 的默认递归深度限制（≈1000）是安全的，但在更大规模题目时需要手动调大或改用显式栈。  
- **下次类似题**：第一步先 **确定搜索空间（起点）**，随后 **用标记防止重复**，最后 **用递归/显式栈实现回溯**。这套思路几乎可以直接套用。
