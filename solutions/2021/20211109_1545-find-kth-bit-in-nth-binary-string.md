## 题目（中文翻译）

给定两个正整数 **n** 和 **k**，二进制字符串 **Sₙ** 按如下方式构造：

- **S₁ = "0"**  
- 对于 **i > 1**，**Sᵢ = Sᵢ₋₁ + "1" + reverse(invert(Sᵢ₋₁))**  

其中 **+** 表示连接操作（concatenation），**reverse(x)** 返回字符串 **x** 的逆序（reversed）版本，**invert(x)** 将 **x** 中的所有位取反（0 变成 1，1 变成 0）。

例如，上述序列的前四个字符串为：

- **S₁ = "0"**  
- **S₂ = "0" + "1" + reverse(invert("0")) = "011"**  
- **S₃ = "011" + "1" + reverse(invert("011")) = "0111001"**  
- **S₄ = "0111001" + "1" + reverse(invert("0111001")) = "011100110110001"**

返回 **Sₙ** 中第 **k** 位的字符。题目保证 **k** 对应的位在给定的 **n** 中是合法的。

**示例 1**  
输入: `n = 3, k = 1`  
输出: `"0"`  
解释: `S₃` 为 `"0111001"`，第 1 位是 `"0"`。

**示例 2**  
输入: `n = 4, k = 11`  
输出: `"1"`  
解释: `S₄` 为 `"011100110110001"`，第 11 位是 `"1"`。

**约束条件**  

- `1 <= n <= 20`  
- `1 <= k <= 2^n - 1`（题目中写作 `2n - 1`，实际含义为 `2^n - 1`）

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是**把整个序列都生成出来**，再去第 `k` 位取值。  
- **构造规则**  
  - `S1 = "0"`  
  - `Sn = Sn-1 + "0" + reverse(invert(Sn-1))`  
    - `reverse(x)`：把字符串 `x` 反向，就像把一本书从后往前读。  
    - `invert(x)`：把 `0` 变成 `1`，`1` 变成 `0`，相当于在字典里查“0 对应 1，1 对应 0”。  

按照这个规则，我们可以从 `S1` 一直递推到 `Sn`，最后直接返回 `S[n][k-1]`（下标从 0 开始）。

- **为什么一定对**  
  因为我们严格按照题目给出的生成公式一步步拼接，得到的字符串 **就是** `Sn`，所以第 `k` 位必然是答案。

- **复杂度分析（大白话）**  
  - 每一次拼接都会把上一层的字符串翻倍再加 1，最终长度是 `2^n - 1`。  
  - **时间**：我们必须把每个字符都写进最终的字符串，等价于 **遍历了 `2^n - 1` 次**，记作 `O(2^n)`。  
  - **空间**：同理，需要保存完整的 `Sn`，占用 `2^n - 1` 个字符的空间，也记作 `O(2^n)`。  
  - 对于 `n ≤ 20`，`2^20 ≈ 1,048,576`，在现代机器上还能接受，但不是最优的。

#### 代码（Python）

```python
def kth_bit_bruteforce(n: int, k: int) -> str:
    # S1 = "0"
    s = "0"
    # 依次生成 S2, S3, ... , Sn
    for i in range(2, n + 1):
        # 先把 s 翻转
        rev = s[::-1]                     # 反转字符串，相当于把书倒着读
        # 再把每个字符取反：0 -> 1, 1 -> 0
        inv = ''.join('1' if ch == '0' else '0' for ch in rev)  # 字典查表式的取反
        # 按规则拼接得到下一个字符串
        s = s + "0" + inv                 # S_i = S_{i-1} + "0" + reverse(invert(S_{i-1}))
    # k 是从 1 开始的，下标要减 1
    return s[k - 1]
```

#### 复杂度

- **时间复杂度**：`O(2^n)`  
  解释：随着 `n` 增大，字符串长度几乎翻倍，最终要遍历 `2^n` 次字符。
- **空间复杂度**：`O(2^n)`  
  解释：我们把完整的 `Sn` 保存在内存里，需要同样数量的字符空间。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**把全部字符都写出来**，但其实我们只需要第 `k` 位。  
观察生成规则：

```
Sn =  Sn-1   +   "0"   +   reverse(invert(Sn-1))
        |          |                |
   前半段        中间位          后半段
```

- **长度**：`|Sn| = 2^n - 1`，中间位的下标（从 1 开始）恰好是 `mid = 2^{n-1}`。
- **关键性质**  
  1. 中间位一定是 `'0'`（因为规则里固定加了一个 `'0'`）。  
  2. 前半段就是 `Sn-1`，**递归**求解 `k` 在前半段时直接转到 `n-1`。  
  3. 后半段是 **先取反再反转** 的 `Sn-1`。  
     - 取反：`0 ↔ 1`。  
     - 反转：把顺序倒过来。  
     - 这意味着：后半段第 `k` 位（相对于后半段的第 1 位）对应前半段的 **倒数第 `k` 位**，且需要 **再取反**。  
     - 用公式写出来：如果 `k > mid`，则对应的前半段位置是 `pos = 2^n - k`（因为 `|Sn| = 2^n - 1`），答案是 `invert( solve(n-1, pos) )`。

把这三条规则组合起来，就得到一个 **只看 `k` 所在区间的递归**，不需要生成整条字符串。

- **递归终止**  
  当 `n == 1` 时，`S1 = "0"`，唯一的第 1 位是 `'0'`。

- **复杂度分析（大白话）**  
  - 每一次递归把 `n` 减 1，最多递归 `n` 次（`n ≤ 20`），所以 **时间**是 `O(n)`，几乎是常数级。  
  - 只用了递归栈保存层数，最多 `n` 层，**空间**是 `O(n)`（如果改写成循环可以做到 `O(1)`）。

#### 代码（Python）

```python
def kth_bit_optimal(n: int, k: int) -> str:
    """
    递归求第 k 位：
    - mid = 2^{n-1} 是 Sn 的中间位置（从 1 开始计数）
    - 若 k == mid，答案必然是 '0'
    - 若 k < mid，答案等同于子问题 solve(n-1, k)
    - 若 k > mid，答案是子问题 solve(n-1, 2^n - k) 取反
    """
    # 递归终止：最小的字符串 S1 = "0"
    if n == 1:
        return "0"

    # 当前字符串的长度是 2^n - 1，mid 为中间位置（1-indexed）
    mid = 1 << (n - 1)          # 等价于 2^{n-1}
    if k == mid:
        return "0"              # 中间固定是 0
    elif k < mid:
        # 在左半边，直接递归到 n-1
        return kth_bit_optimal(n - 1, k)
    else:
        # 在右半边，先映射到左半边对应位置，再取反
        # 右半边第 k 位对应左半边的第 (2^n - k) 位
        mirrored = (1 << n) - k  # 2^n - k
        # 递归求出左半边的位，然后取反
        left_bit = kth_bit_optimal(n - 1, mirrored)
        return '1' if left_bit == '0' else '0'   # 取反
```

#### 复杂度

- **时间复杂度**：`O(n)`  
  解释：每次递归把 `n` 减 1，最多走 `n` 步（`n ≤ 20`），几乎和常数一样快。相较于暴力的 `O(2^n)`，省了指数级的时间。
- **空间复杂度**：`O(n)`（递归栈）  
  解释：只保存递归调用的层数，最深为 `n`。如果改写成循环，甚至可以做到 `O(1)`。

## 心得

- **核心技巧**：利用字符串的对称结构（中间位 + 左右互为「翻转+取反」）把问题递归到更小的子问题。  
- **适用的题型**  
  1. “Kth Symbol in Grammar”（第 K 个符号的语法树）  
  2. “Find Kth Bit in Nth Binary String” 本题  
  3. “Count Beautiful Numbers” 中需要利用数位翻转对称的思路  
- **一句话总结解题钥匙**：**“把大问题映射到左半边的等价子问题，再根据位置决定是否取反”。**

## 反思

- **第一反应**：看到递推公式就想把所有字符串拼出来，直接模拟。  
- **最容易踩的坑**  
  - 忘记 **下标是从 1 开始**，导致 `k` 与 `mid` 比较出错。  
  - 在右半边映射时写错公式：应是 `2^n - k`（不是 `2^{n-1}`）。  
  - 取反时写成 `0 -> 0`、`1 -> 1`，导致答案全是 `'0'`。  
- **下次类似题的第一步**：先**画出递推关系**，找出“中心点”和“左右对称”特性，判断是否可以**递归或二分**地定位目标位置，而不是直接构造全部数据。
