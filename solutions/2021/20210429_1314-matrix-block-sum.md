## 题目（英文原版）

**Description**

Given a m x n matrix mat and an integer k, return a matrix answer where each answer[i][j] is the sum of all elements mat[r][c] for:

## 题目（中文翻译）

给定一个大小为 `m x n` 的矩阵（matrix）`mat` 和一个整数 `k`，返回一个矩阵（matrix）`answer`，其中 `answer[i][j]` 为所有满足以下条件的元素 `mat[r][c]` 的和：

- `i - k <= r <= i + k`
- `j - k <= c <= j + k`
- `(r, c)` 为矩阵中的合法下标

换句话说，`answer[i][j]` 是以 `(i, j)` 为中心、半径为 `k` 的子矩阵（submatrix）中的元素之和。

**示例 1：**

```text
输入: mat = [[1,2,3],[4,5,6],[7,8,9]], k = 1
输出: [[12,21,16],[27,45,33],[24,39,28]]
```

**示例 2：**

```text
输入: mat = [[1,2,3],[4,5,6],[7,8,9]], k = 2
输出: [[45,45,45],[45,45,45],[45,45,45]]
```

**约束条件：**

- `m == mat.length`
- `n == mat[i].length`
- `1 <= m, n, k <= 100`
- `1 <= mat[i][j] <= 100`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**对每个格子 (i, j) 都去遍历它的 “邻域块”**，把所有满足  
`max(0, i‑k) ≤ r ≤ min(m‑1, i+k)` 且 `max(0, j‑k) ≤ c ≤ min(n‑1, j+k)` 的元素累加起来，得到答案矩阵的对应位置。

- **用到的数据结构**：只需要原始的二维列表 `mat`，以及同样大小的二维列表 `ans` 用来存放结果。  
- **生活化类比**：把矩阵想成一张城市地图，格子是街区。要算某个街区周围 `k` 格以内的所有商店的营业额，总是要把这片区域的每一家店都走一遍、记下来。  
- **为什么正确**：因为我们把 **所有** 符合距离条件的格子都加进来了，恰好就是题目要求的“块和”。  

> 这个方法的缺点是：每个格子都要遍历一个大小为 `(2k+1) × (2k+1)` 的子矩阵，导致大量重复计算。

#### 代码（Python）

```python
def matrixBlockSum_brute(mat, k):
    """
    暴力解法：对每个格子遍历它的邻域块，求和
    """
    m, n = len(mat), len(mat[0])
    ans = [[0] * n for _ in range(m)]          # 用来存放结果

    for i in range(m):
        for j in range(n):
            total = 0                           # 当前格子的块和
            # 上下左右各扩展 k 步，注意不要越界
            for r in range(max(0, i - k), min(m, i + k + 1)):
                for c in range(max(0, j - k), min(n, j + k + 1)):
                    total += mat[r][c]         # 累加邻域内的每个元素
            ans[i][j] = total                    # 写入答案矩阵
    return ans
```

#### 复杂度

- **时间复杂度**：`O(m * n * (2k+1)^2)`  
  - 直译：对每个 `m·n` 个格子，都要遍历一个最多有 `(2k+1)²` 个格子的子矩阵。  
  - 当 `k` 接近 `max(m,n)` 时，最坏情况相当于 `O(m * n * m * n)`，即 **平方级**，会超时。  
- **空间复杂度**：`O(m * n)`  
  - 只用了一个和输入等大小的答案矩阵，额外空间不随 `k` 增长。

### 2. 最优解

#### 思路  

从暴力解可以看到 **重复计算** 是性能瓶颈。  
想要加速，需要让每次求块和时，只做 **常数次** 的操作，而不是遍历整个块。

**关键技巧：二维前缀和（cumulative sum matrix）**  
- **类比**：把矩阵看成一本“账本”。`pref[i][j]` 记录从左上角 `(0,0)` 到 `(i‑1, j‑1)`（左闭右开）这块区域的总金额。  
- **如何构造**：  
  ```
  pref[i+1][j+1] = pref[i][j+1] + pref[i+1][j] - pref[i][j] + mat[i][j]
  ```
  这一步相当于 **把左边、上边的累计值加起来，再减掉左上角重复加的那块，最后加上当前格子的值**。  
- **求块和**：  
  对于任意矩形区域 `(r1,c1) … (r2,c2)`（左上、右下坐标），块和可以用**容斥原理**一次算完：
  ```
  sum = pref[r2+1][c2+1] - pref[r1][c2+1] - pref[r2+1][c1] + pref[r1][c1]
  ```
  只用了四次数组访问，时间是 **O(1)**。

**把它套用到本题**  
对于每个格子 `(i,j)`，我们需要的块是  
```
row_low = max(0, i - k)
row_high = min(m-1, i + k)
col_low = max(0, j - k)
col_high = min(n-1, j + k)
```
把这四个坐标代入前缀和公式，即可在 **常数时间** 内得到答案。

#### 代码（Python）

```python
def matrixBlockSum(mat, k):
    """
    最优解：利用二维前缀和，在 O(1) 时间内求每个格子的块和
    """
    m, n = len(mat), len(mat[0])

    # 1️⃣ 构造前缀和矩阵，尺寸为 (m+1) × (n+1) 方便边界处理
    pref = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(m):
        row_sum = 0                     # 当前行的累计和
        for j in range(n):
            row_sum += mat[i][j]        # 累加本行到 j 列
            # 前缀和 = 上方累计 + 本行累计
            pref[i + 1][j + 1] = pref[i][j + 1] + row_sum

    # 2️⃣ 根据前缀和计算每个格子的块和
    ans = [[0] * n for _ in range(m)]
    for i in range(m):
        for j in range(n):
            # 计算块的四个边界（注意不要越界）
            r1 = max(0, i - k)
            c1 = max(0, j - k)
            r2 = min(m - 1, i + k)
            c2 = min(n - 1, j + k)

            # 使用前缀和的容斥公式（左闭右开）
            total = (pref[r2 + 1][c2 + 1]
                     - pref[r1][c2 + 1]
                     - pref[r2 + 1][c1]
                     + pref[r1][c1])
            ans[i][j] = total
    return ans
```

> **代码要点注释**  
> 1. `pref` 多开了一行一列，目的是把“第 0 行/第 0 列”视作全 0，避免在求和时写很多 `if` 判断。  
> 2. `row_sum` 只在当前行内部累加，随后加上上一行的前缀和，等价于公式 `pref[i+1][j+1] = pref[i][j+1] + pref[i+1][j] - pref[i][j] + mat[i][j]`，但更易读。  
> 3. 求块和时使用 **左闭右开** 区间 `[r1, r2+1) × [c1, c2+1)`，这样可以直接用前缀和矩阵的下标。

#### 复杂度

- **时间复杂度**：`O(m * n)`  
  - **解释**：构造前缀和遍历一次矩阵 `O(mn)`，随后对每个格子也只做常数次操作 `O(1)`，所以整体是线性时间。相比暴力解的平方级快了好几个数量级。  
- **空间复杂度**：`O(m * n)`（前缀和矩阵）  
  - 需要额外存储一个和原矩阵同等大小的前缀和矩阵，空间开销与输入规模线性相关。

## 心得

- **核心技巧**：二维前缀和（累计和矩阵）+ 容斥原理（四个角的加减）。  
- **适用题型**：  
  1. “子矩阵求和”类（如 LeetCode 304. Range Sum Query 2D – Immutable）  
  2. “矩阵区域最大/最小值”可先用前缀和把求和降到 O(1) 再做滑动窗口  
  3. “图像模糊/均值滤波”等需要快速求局部和的图像处理题。  
- **一句话总结**：**把“多次重复求和”转化为“一次预处理 + 常数查询”。**

## 反思

- **第一反应**：直接遍历每个格子的邻域块，写出最直观的暴力实现。  
- **最容易踩的坑**：  
  - 边界处理不当，导致索引越界（尤其在 `k` 超出矩阵尺寸时）。  
  - 前缀和的 **左闭右开** 与 **左闭右闭** 之间的转换容易混淆，导致加减错误。  
  - 忘记在前缀和矩阵外面多加一层 0，导致在计算左上角块时需要额外的 `if`。  
- **下次遇到同类题**：第一步先想 **“能否预处理一次，把重复工作搬到前面？”**，如果可以，就考虑 **前缀和 / 差分数组** 这类“一次预处理、多次快速查询”的工具。
