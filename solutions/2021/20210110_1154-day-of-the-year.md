# #1154. 一年中的第几天 / Day of the Year

> 难度：简单 · 标签：Math、String · [LeetCode 链接](https://leetcode.com/problems/day-of-the-year/)

---

## 题目（英文原版）

**Description**

Given a string date representing a Gregorian calendar date formatted as YYYY-MM-DD, return the day number of the year.

**Examples**

**Example 1:**

```
Input: date = "2019-01-09"
Output: 9
Explanation: Given date is the 9th day of the year in 2019.
```

**Example 2:**

```
Input: date = "2019-02-10"
Output: 41
```

**Constraints**

- date.length == 10
- date[4] == date[7] == '-', and all other date[i]'s are digits
- date represents a calendar date between Jan 1st, 1900 and Dec 31st, 2019.

---

## 题目（中文翻译）

**题目描述**  
给定一个字符串 `date`，表示格式为 `YYYY-MM-DD` 的公历日期，返回该日期是当年的第几天。

**示例 1**  
**输入**：`date = "2019-01-09"`  
**输出**：`9`  
**解释**：给定的日期是 2019 年的第 9 天。

**示例 2**  
**输入**：`date = "2019-02-10"`  
**输出**：`41`  

**约束条件**  
- `date.length == 10`  
- `date[4] == date[7] == '-'`，且其余位置的字符均为数字  
- `date` 表示的日期在 **1900 年 1 月 1 日** 到 **2019 年 12 月 31 日**（含）之间

**提示**  
- 需要考虑闰年（leap year）的情况：能被 4 整除且不能被 100 整除的年份，或者能被 400 整除的年份为闰年。  
- 可以预先准备每个月的天数数组，在闰年时将二月的天数设为 29。  
- 将月份之前的天数累加，再加上当天的日期即可得到答案。

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  

最直接的想法是 **从 1 月 1 日开始，一天一天往后走**，直到走到给定的日期为止，走了多少步就是答案。  

- **数据结构**：我们只需要一个 **列表（list）** 保存每个月的天数。列表就像一本日历，索引 0 对应 1 月，值是该月有多少天。  
- **闰年**：2 月在闰年要多一天。判断闰年的规则是：能被 4 整除且不能被 100 整除，或者能被 400 整除。可以把闰年看成“字典（hash map）”里的特殊条目：键是年份，值是是否要给 2 月加一天。  
- **为什么正确**：我们把每一天都显式地走了一遍，走到目标日期时计数器正好等于它是当年的第几天，逻辑上不可能出错。  

#### 代码（Python）

```python
def dayOfYear(date: str) -> int:
    # 1. 把字符串切分成年、月、日三个整数
    year = int(date[:4])
    month = int(date[5:7])
    day = int(date[8:])

    # 2. 每个月的天数（非闰年），索引 0 代表 1 月
    month_days = [31, 28, 31, 30, 31, 30,
                  31, 31, 30, 31, 30, 31]

    # 3. 判断是否闰年
    #   闰年 = 能被 4 整除且不能被 100 整除，或者能被 400 整除
    is_leap = (year % 4 == 0 and year % 100 != 0) or (year % 400 == 0)

    # 4. 暴力计数：从 1 月 1 日一直走到目标日期
    cnt = 0                         # 已经走过的天数
    for m in range(1, month + 1):   # 月份从 1 循环到目标月份（含）
        if m == month:              # 最后一个月，只加到目标 day
            cnt += day
        else:
            # 不是目标月份，整个月都要算进来
            if m == 2 and is_leap:  # 2 月且闰年，要多加一天
                cnt += 29
            else:
                cnt += month_days[m - 1]  # month_days 索引要减 1
    return cnt
```

#### 复杂度  

- **时间复杂度：O(N)**  
  这里的 **N** 代表要走的天数，最坏情况下是 365（或 366）天。用“大白话”说，就是**最多只会循环 12 次**（因为我们每个月只算一次），所以对人类来说几乎是瞬间完成的。  
- **空间复杂度：O(1)**  
  只用了常数个变量和一个长度固定为 12 的列表，和输入大小无关。

### 2. 最优解  

#### 思路  

从暴力解可以看到，**循环遍历每个月其实是多余的**。我们只需要**把每个月之前的天数直接相加**，再加上当天的日期即可得到答案。  

- **瓶颈**：暴力解里每个月都要判断一次是否闰年、是否是目标月，这些判断在所有月份都是重复的。  
- **优化思路**：  
  1. 预先准备一个 **前缀和数组** `prefix[i]`，表示从 1 月到第 `i` 月（不包括第 `i` 月）一共多少天。  
  2. 对闰年，只需要把 2 月的天数改成 29 天，其余月份不变。  
  3. 最终答案 = `prefix[month] + day`。  
- **核心概念**：**前缀和**（Prefix Sum）——把累计的结果提前算好，后面查询时直接读取，时间就是 O(1)。可以把它想象成“一本已经算好累计页数的书”，想知道第 5 章节之前有多少页，只要看目录（前缀和表）就知道。  

#### 代码（Python）

```python
def dayOfYear(date: str) -> int:
    # 1. 解析年、月、日
    year = int(date[:4])
    month = int(date[5:7])
    day = int(date[8:])

    # 2. 每个月的天数（非闰年）
    month_days = [31, 28, 31, 30, 31, 30,
                  31, 31, 30, 31, 30, 31]

    # 3. 判断闰年，同上
    is_leap = (year % 4 == 0 and year % 100 != 0) or (year % 400 == 0)

    # 4. 计算前缀和：prefix[i] = 前 i 个月的天数总和（i 从 0 开始）
    prefix = [0]                     # prefix[0] = 0，表示“0 个月之前”没有天数
    for i in range(12):
        days = month_days[i]
        # 如果是闰年且当前是 2 月（i == 1），加一天
        if i == 1 and is_leap:
            days += 1
        prefix.append(prefix[-1] + days)   # 累加到列表末尾

    # 5. 直接查表 + 当天的日子
    #    month 是 1~12，prefix 的下标正好对应“month-1 个月之前”的天数
    return prefix[month - 1] + day
```

#### 复杂度  

- **时间复杂度：O(1)**  
  前缀和数组长度固定为 13（包括第 0 项），不随输入规模变化。换句话说，**不管日期是 1900‑01‑01 还是 2019‑12‑31，代码执行的步骤数都是一样的**。  
- **空间复杂度：O(1)**  
  使用的列表长度也是固定的常数（13），和输入大小无关。

## 心得  

- **核心技巧**：**前缀和**（累计求和） + **闰年判定**。  
- **适用的题型**：  
  1. “求某日期是当年的第几天”类（如本题）。  
  2. “区间求和”类题目（如 LeetCode 303 Range Sum Query – Immutable Array）。  
  3. “累计天数/月份/年份”类（如计算两个日期之间相差多少天）。  
- **一句话总结**：把每个月的天数提前累加成表，查询时直接相加即可——省时省力的“查表法”。  

## 反思  

- **第一反应**：看到“YYYY-MM-DD”，自然会想到把年、月、日切出来，先判断闰年，再把前面的月份天数加起来。  
- **最容易踩的坑**：  
  - **闰年判断错误**（忘记排除能被 100 整除但不能被 400 整除的年份）。  
  - **月份索引错误**：列表是 0 基的，月份是 1 基的，容易写成 `month_days[month]` 导致越界或错位。  
  - **边界条件**：1 月 1 日应该返回 1，2 月 28/29 日要正确处理。  
- **下次思路**：一看到涉及“累计天数”或“区间求和”，第一步就想 **“能不能把累计结果提前算好，用表直接查？”**，如果可以，就直接走前缀和路线。
