# #1404. 将二进制数化为 1 所需的步骤数 / Number of Steps to Reduce a Number in Binary Representation to One

## 题目（英文原版）

**Description**

Given the binary representation of an integer as a string s, return the number of steps to reduce it to 1 under the following rules:
It is guaranteed that you can always reach one for all test cases.

**Examples**

**Example 1:**

```
Input: s = "1101"
Output: 6
Explanation: "1101" corressponds to number 13 in their decimal representation.
Step 1) 13 is odd, add 1 and obtain 14. 
Step 2) 14 is even, divide by 2 and obtain 7.
Step 3) 7 is odd, add 1 and obtain 8.
Step 4) 8 is even, divide by 2 and obtain 4.  
Step 5) 4 is even, divide by 2 and obtain 2. 
Step 6) 2 is even, divide by 2 and obtain 1.
```

**Example 2:**

```
Input: s = "10"
Output: 1
Explanation: "10" corresponds to number 2 in their decimal representation.
Step 1) 2 is even, divide by 2 and obtain 1.
```

**Example 3:**

```
Input: s = "1"
Output: 0
```

**Constraints**

- 1 <= s.length <= 500
- s consists of characters '0' or '1'
- s[0] == '1'

## 题目（中文翻译）

给定一个整数的二进制表示（binary representation），该二进制数以字符串 `s` 的形式给出。请返回按照以下规则将其化为 `1` 所需的步骤数：

- 如果当前数字是奇数，则加 `1`；
- 如果当前数字是偶数，则除以 `2`。

题目保证对所有测试用例都一定能最终得到 `1`。

**示例 1**

```
Input: s = "1101"
Output: 6
```

**解释**：`"1101"` 对应十进制数 `13`。  
步骤如下：
1) `13` 为奇数，加 `1` 得到 `14`。  
2) `14` 为偶数，除以 `2` 得到 `7`。  
3) `7` 为奇数，加 `1` 得到 `8`。  
4) `8` 为偶数，除以 `2` 得到 `4`。  
5) `4` 为偶数，除以 `2` 得到 `2`。  
6) `2` 为偶数，除以 `2` 得到 `1`。

**示例 2**

```
Input: s = "10"
Output: 1
```

**解释**：`"10"` 对应十进制数 `2`。  
步骤如下：
1) `2` 为偶数，除以 `2` 得到 `1`。

**示例 3**

```
Input: s = "1"
Output: 0
```

**约束条件**

- `1 <= s.length <= 500`
- `s` 仅由字符 `'0'` 或 `'1'` 组成
- `s[0] == '1'`（保证二进制数没有前导零）

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把二进制字符串 `s` 先转换成十进制整数，然后按照题目描述的「奇数加 1、偶数除 2」一步步模拟，直到得到 `1` 为止。

- **数据结构**：我们只需要一个普通的整数变量来保存当前的数值。把二进制字符串看成一本字典，键是字符 `'0'`/`'1'`，值是对应的位权（`2⁰, 2¹ …`），把它们「相加」得到十进制数，这一步就像在字典里查每个词的页码再相加一样。
- **正确性**：因为每一步的操作（+1 或 /2）在十进制下和在二进制下是完全等价的，直接在十进制上做同样的运算得到的步骤数一定和在二进制上模拟得到的一致。
- **时间/空间复杂度**：  
  - 把二进制转成整数需要遍历一次字符串，时间 `O(n)`（`n = len(s)`）。  
  - 之后的模拟次数大约等于答案本身。最坏情况下（全部是 `1`，比如 `"111...1"`），每一次 `+1` 都会产生一次进位，导致后面会出现大量的 `/2` 操作，步骤数大约是 `2·n`，所以整体时间是 `O(n·steps) ≈ O(n²)`。  
  - 只用了常数个整数变量，空间 `O(1)`。

#### 代码（Python）

```python
def numSteps_brute(s: str) -> int:
    # 1️⃣ 把二进制字符串转成十进制整数
    # int(s, 2) 相当于手动把每一位乘以 2 的幂再相加
    num = int(s, 2)

    steps = 0                       # 记录执行了多少步
    while num != 1:                 # 只要还没到 1，就继续
        if num % 2 == 0:            # 偶数 → 除以 2
            num //= 2
        else:                       # 奇数 → 加 1
            num += 1
        steps += 1                  # 计数器加一
    return steps
```

#### 复杂度

- **时间复杂度**：`O(n²)`  
  - 直观来说，`n` 是字符串长度，答案最多大约是 `2·n`，所以总的循环次数约为 `O(n)`，每次循环的整数运算在 Python 中是 `O(n)`（因为整数位数随步骤增长），整体约为 `O(n²)`。  
  - 用大白话讲，就是「每一步都要花点时间，而步骤本身也和字符串长度成正比，所以时间会乘起来」。
- **空间复杂度**：`O(1)`  
  - 只用了几个整数变量，和输入长度无关。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **把二进制转成十进制后再操作**，这会让整数位数随步骤增长，导致每一步的运算成本变大。其实我们完全可以 **直接在二进制字符串上模拟**，不必真的把它转换成十进制。

关键观察：

1. **奇偶性** 只取决于最低位（最右边的字符）。如果末位是 `'0'`，当前数是偶数；如果是 `'1'`，则是奇数（除去唯一的 `1` 本身的特殊情况）。
2. **除以 2** 在二进制里就是把最低位删掉（右移一位）。
3. **加 1** 在二进制里是从最低位向左“进位”。  
   - 如果最低位是 `'0'`，直接把它改成 `'1'`，不影响左边的位。  
   - 如果最低位是 `'1'`，会变成 `'0'` 并向左继续进位，直到遇到 `'0'` 或到达最左端。

于是我们可以 **从右往左遍历字符串**，维护一个“进位”标记 `carry`（相当于在模拟 `+1` 时产生的进位），并逐位决定本位需要做的操作：

| 当前位 `bit` | `carry` | 实际值 (`bit + carry`) | 需要的操作 | 产生的新的 `carry` |
|-------------|--------|-----------------------|-----------|-------------------|
| 0           | 0      | 0                     | 除 2 → 删除该位 | 0 |
| 1           | 0      | 1 (奇数)               | +1 → 产生进位，随后除 2 | 1 |
| 0           | 1      | 1 (奇数)               | +1 → 产生进位，随后除 2 | 1 |
| 1           | 1      | 2 (偶数)               | 直接除 2（相当于把该位变 0）| 1 |

可以看到，**只要不是最左端的 `'1'`**，每处理一位就会产生一步或两步操作：

- 当 `bit + carry == 1`（奇数），需要 **先加 1 再除 2**，这算两步。
- 当 `bit + carry == 0`（偶数），只需要 **除 2**，算一步。
- 当 `bit + carry == 2`（实际上是 `10`），只需要 **除 2**，但进位仍然保留，算一步。

遍历完除最左端的 `'1'` 之外的所有位后，若还有 `carry = 1`，说明最高位也要向左进位一次，这相当于在最左端再做一次 **加 1**（但不会再除 2，因为答案已经是 `1`），所以再加一步。

整个过程只遍历一次字符串，时间 `O(n)`，且只用常数级别的额外空间。

#### 代码（Python）

```python
def numSteps(s: str) -> int:
    """
    直接在二进制字符串上模拟 "奇数加1 / 偶数除2"
    思路：从右往左遍历，维护进位 carry。
    """
    n = len(s)
    steps = 0          # 记录总步数
    carry = 0          # 进位，初始为 0

    # 从倒数第二位开始向左遍历（因为最左端的 '1' 不需要再除以 2）
    for i in range(n - 1, 0, -1):
        bit = int(s[i])               # 当前字符是 '0' 还是 '1'
        total = bit + carry           # 实际的二进制位值（考虑进位）

        if total == 0:                # 00 → 偶数，只除 2
            steps += 1
        elif total == 1:              # 01 或 10 → 奇数，需要 +1 再除 2
            steps += 2                # +1 一步，除 2 再一步
            carry = 1                 # 加 1 会产生进位，保持为 1
        else:                         # total == 2 → 实际是 10，偶数，只除 2
            steps += 1
            carry = 1                 # 仍然保留进位，因为 2 = 1（进位） + 0

    # 循环结束后，只剩下最高位的 '1'（可能还有进位）
    # 如果还有进位，需要再做一次加 1（相当于一步），
    # 但是最高位已经是 1，最终结果仍是 1，不需要再除 2。
    steps += carry    # carry 为 0 时不增加，为 1 时多加一步

    return steps
```

#### 复杂度

- **时间复杂度**：`O(n)`  
  - 只遍历一次字符串，`n` 是二进制位数。用大白话说，就是「不管数字有多大，只需要看一遍它的每一位」。
- **空间复杂度**：`O(1)`  
  - 只用了几个整数变量（`steps`, `carry`, `bit`），不随输入长度增长。

## 心得

- **核心技巧**：**在二进制层面模拟加 1 与除 2**，通过一次遍历并使用进位 `carry` 完成全部操作。
- **适用场景**：  
  1. 需要在二进制字符串上直接进行加减或移位操作的题目（如「二进制加法」）。  
  2. 需要统计「奇数加 1、偶数除 2」这类基于奇偶性的迭代步骤（如 LeetCode 1404）。
- **一句话总结**：**把「奇偶」转化为「最低位」的检查，用进位把所有加 1 合并到一次遍历里**。

## 反思

- **第一反应**：把二进制直接转成整数，然后照搬题目描述的循环——最自然但不够高效。
- **最容易踩的坑**：  
  - 忘记对只有一个字符 `'1'` 的特殊情况直接返回 `0`。  
  - 在进位处理时误把 `carry` 重置为 `0`，导致后面的位判断错误。  
  - 统计步数时把最高位的进位漏算，导致答案偏小 1。
- **下次类似题的第一步**：**先思考“在二进制层面上，这一步对应哪一位的变化”，把奇偶判断转成最低位检查，再决定是否需要进位**。这样往往能直接得到 O(n) 的线性解法。
