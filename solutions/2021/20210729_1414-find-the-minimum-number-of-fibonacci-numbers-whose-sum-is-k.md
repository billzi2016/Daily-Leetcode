## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**把所有可能的斐波那契数列组合都枚举一遍**，看哪一种恰好能凑出 `k`，并记录使用的斐波那契数的最少个数。  
这相当于“背包问题”的一种朴素搜索：

1. 先把 **所有 ≤ k 的斐波那契数** 生成出来，放进一个数组 `fib`。  
2. 从第一个斐波那契数开始，递归地决定「要不要把它加入当前和」。  
3. 当当前和正好等于 `k` 时，比较已经使用的数量，取最小值。  
4. 当当前和已经大于 `k`，或者已经遍历完所有斐波那契数时，结束本次递归。

> **类比**：把斐波那契数想成超市里的各种面额的硬币，想用最少的硬币凑出总价 `k`。暴力法相当于把每一种硬币的取或不取的可能性全都列出来，尝试每一种组合。

**为什么能得到正确答案**：因为我们遍历了**所有**合法的组合，最优解必然在其中。

**时间/空间复杂度**  
- 斐波那契数本身很少（`fib ≤ 45` 才能达到 `10^9`），但枚举组合的过程是指数级的。设斐波那契数的个数为 `n`（≈44），则最坏情况下需要尝试 `2^n` 种取舍，时间复杂度是 **O(2ⁿ)**，在实际 `n` 较小的情况下还能跑完，但理论上非常慢。  
- 递归栈深度最多 `n`，额外空间是 **O(n)**。

#### 代码（Python）

```python
def min_fib_numbers_bruteforce(k: int) -> int:
    # 1. 生成所有 <= k 的斐波那契数，放入列表 fib
    fib = [1, 1]
    while fib[-1] + fib[-2] <= k:
        fib.append(fib[-1] + fib[-2])

    # 2. 深度优先搜索所有取舍情况
    ans = float('inf')                     # 用来记录最小的数量

    def dfs(idx: int, cur_sum: int, cnt: int) -> None:
        """
        idx: 当前考虑的斐波那契数在 fib 中的下标（从大到小遍历）
        cur_sum: 已经累计的和
        cnt: 已经使用的斐波那契数个数
        """
        nonlocal ans
        # 已经凑出 k，更新答案
        if cur_sum == k:
            ans = min(ans, cnt)
            return
        # 超过 k 或者已经没有更小的数可选，剪枝
        if cur_sum > k or idx < 0:
            return
        # 剪枝：即使把剩下所有数全选进来也达不到更好的答案，就直接返回
        # 这里用一个简单的上界：cnt 已经不可能比当前答案更小
        if cnt >= ans:
            return

        # 选当前的 fib[idx]（可以多次使用，所以仍然保留 idx）
        dfs(idx, cur_sum + fib[idx], cnt + 1)
        # 不选当前的 fib[idx]，转向更小的数
        dfs(idx - 1, cur_sum, cnt)

    # 从最大的斐波那契数开始搜索
    dfs(len(fib) - 1, 0, 0)
    return ans
```

#### 复杂度

- **时间复杂度**：O(2ⁿ)（指数级），其中 `n` 为 ≤ `k` 的斐波那契数个数（≈44）。  
  大白话：如果你把每个斐波那契数想成一个“开关”，每个开关有开/关两种状态，所有状态组合一共有 `2ⁿ` 种，程序几乎要遍历一遍。
- **空间复杂度**：O(n)（递归栈深度），约 44 层。

### 2. 最优解

#### 思路  

暴力解的瓶颈在 **“枚举所有组合”**，这一步会导致指数级的时间开销。观察题目可以发现：

- 斐波那契数是 **递增** 的序列，且 **每个数都比前面所有数的和要大**（这点可以用数学归纳法证明）。
- 因此，如果我们想用最少的数来凑成 `k`，**应该尽量使用大的斐波那契数**，因为大数能一次性把 `k` “削减”更多。

这正好对应 **贪心**（Greedy）策略：  
> 每一步都取**不超过当前剩余值的最大斐波那契数**，把它从 `k` 中减去，然后继续对剩余值重复同样的操作，直到剩余值为 0。

为什么贪心能得到最优解？  
- 设 `f_i` 为不超过当前剩余值的最大斐波那契数。若我们不取 `f_i` 而改取更小的数 `f_j (j<i)`，则需要 **至少** 用 `⌈f_i / f_j⌉ ≥ 2` 个 `f_j` 才能补齐 `f_i` 的贡献，使用的数量必然不小于直接使用 `f_i`。  
- 递归地，这个论证在每一步都成立，故整体上贪心得到的解必然是使用最少的斐波那契数。

**核心算法**：  
1. **预生成** 所有 ≤ `k` 的斐波那契数（数量很少，最多约 44 个）。  
2. 从大到小遍历这个列表：  
   - 若 `fib[i] ≤ k`，则 `k -= fib[i]`，计数 `cnt += 1`。  
   - 继续检查同一个 `fib[i]`（因为同一个斐波那契数可以使用多次），或者移动到下一个更小的数。  
3. 当 `k` 变为 0 时，`cnt` 即为答案。

> **类比**：把斐波那契数想成“一元硬币、两元硬币、三元硬币、五元硬币…”。想花最少的硬币凑够 `k` 元，自然先拿面额最大的硬币，凑不够再去拿下一个面额的硬币，这就是常见的“找零”贪心。

#### 代码（Python）

```python
def findMinFibonacciNumbers(k: int) -> int:
    """
    贪心算法：每次取不超过当前 k 的最大斐波那契数。
    返回最少需要的斐波那契数个数。
    """
    # 1. 生成所有 <= k 的斐波那契数（从小到大）
    fib = [1, 1]
    while fib[-1] + fib[-2] <= k:
        fib.append(fib[-1] + fib[-2])

    cnt = 0               # 计数器，记录使用的斐波那契数个数
    idx = len(fib) - 1    # 从最大的斐波那契数开始

    # 2. 贪心遍历
    while k > 0:
        # 找到第一个不大于 k 的斐波那契数
        while fib[idx] > k:
            idx -= 1                     # 逐步往小的数移动
        # 取这个数
        k -= fib[idx]                    # 把它从 k 中减掉
        cnt += 1                         # 使用数量加一
        # 这里不需要 idx--，因为同一个数可以重复使用
        # 循环继续，直到 k 为 0

    return cnt
```

#### 复杂度

- **时间复杂度**：O(n)  
  - 生成斐波那契数的循环最多跑 `n` 次（`n≈44`），贪心遍历同样最多遍历 `n` 次。  
  - 大白话：我们只需要把 **44** 个数看一遍，几乎是瞬间完成的。
- **空间复杂度**：O(n)（存放斐波那契数的列表），约 44 个整数，几乎可以忽略不计。

与暴力解相比，时间从指数级降到了线性级，速度提升了好几个数量级。

## 心得

- **核心技巧**：**贪心** —— 每一步都选当前能用的最大斐波那契数。  
- **适用的题型**：  
  1. **最少硬币找零**（如「322. 零钱兑换」的特例）  
  2. **最少斐波那契数求和**（本题）  
  3. **用最少的完全平方数表示整数**（LeetCode 279，思路类似但需要额外的数学证明）  
- **一句话总结解题钥匙**：**“大数先取，剩余再凑”**。

## 反思

- **第一反应**：看到“最少斐波那契数求和”，立刻想到“枚举所有组合”或“动态规划”。这会导致实现复杂且效率低下。  
- **最容易踩的坑**：  
  - 忘记生成 **所有** ≤ `k` 的斐波那契数，导致在贪心过程中找不到合适的数。  
  - 在贪心循环里错误地每次都 `idx -= 1`，结果把同一个可以重复使用的数漏掉，导致答案偏大。  
  - 边界条件：`k = 1` 时，需要返回 1（因为 1 本身是斐波那契数），代码必须能处理最小输入。  
- **下次遇到同类题**，第一步应该先 **判断是否满足贪心条件**（如“每个数都大于前面所有数的和”），如果满足，就直接尝试 **从大到小一次遍历**，而不是立刻写递归或 DP。这样往往能快速得到最优解。
