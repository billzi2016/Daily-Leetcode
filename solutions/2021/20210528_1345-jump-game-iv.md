# #1345. 跳跃游戏 IV / Jump Game IV

## 题目（英文原版）

**Description**

Given an array of integers arr, you are initially positioned at the first index of the array.
In one step you can jump from index i to index:
Return the minimum number of steps to reach the last index of the array.
Notice that you can not jump outside of the array at any time.

**Examples**

**Example 1:**

```
Input: arr = [100,-23,-23,404,100,23,23,23,3,404]
Output: 3
Explanation: You need three jumps from index 0 --> 4 --> 3 --> 9. Note that index 9 is the last index of the array.
```

**Example 2:**

```
Input: arr = [7]
Output: 0
Explanation: Start index is the last index. You do not need to jump.
```

**Example 3:**

```
Input: arr = [7,6,9,6,9,6,9,7]
Output: 1
Explanation: You can jump directly from index 0 to index 7 which is last index of the array.
```

**Constraints**

- 1 <= arr.length <= 5 * 104
- -108 <= arr[i] <= 108

## 题目（中文翻译）

给定一个整数数组 `arr`，你最初位于数组的第一个下标（下标 0）。  
在一次操作中，你可以从下标 `i` 跳到以下任意位置：

- 下标 `i + 1`（如果该下标在数组范围内）；
- 下标 `i - 1`（如果该下标在数组范围内）；
- 任意下标 `j`，满足 `arr[i] == arr[j]` 且 `i != j`。

返回到达数组最后一个下标所需的最少跳跃次数。  
注意，任何时候都不能跳出数组范围。

**示例 1**  
**输入**: `arr = [100,-23,-23,404,100,23,23,23,3,404]`  
**输出**: `3`  
**解释**: 你可以按以下顺序跳跃 `0 → 4 → 3 → 9`，共 3 步。下标 9 是数组的最后一个下标。

**示例 2**  
**输入**: `arr = [7]`  
**输出**: `0`  
**解释**: 起始下标已经是最后一个下标，无需跳跃。

**示例 3**  
**输入**: `arr = [7,6,9,6,9,6,9,7]`  
**输出**: `1`  
**解释**: 你可以直接从下标 0 跳到下标 7，后者就是数组的最后一个下标。

**约束条件**

- `1 <= arr.length <= 5 * 10^4`
- `-10^8 <= arr[i] <= 10^8`

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  

最直接的想法是把题目看成“从起点走到终点的最少步数”。  
我们可以把每一个数组下标当作图中的一个 **节点**，从节点 `i` 能走到的邻居有三种：

1. `i + 1` （向右一步）  
2. `i - 1` （向左一步）  
3. 所有 **值相同** 的下标 `j`（因为题目允许一次跳到任意值相等的位置）  

如果把这些跳跃当成 **无权图** 的边，那么求最少步数就等价于 **最短路径** 问题。  
最朴素的做法是：从起点 `0` 开始，**枚举所有可能的跳法**，直到走到最后一个下标 `n-1` 为止。  

这相当于对每一步都尝试 **所有** 能跳到的下标，递归或使用 BFS（广度优先搜索）遍历整张图。  

- **使用的数据结构**：  
  - **队列**（queue）——像排队买票一样，先进入的先处理，用来实现 BFS。  
  - **集合/哈希表**（set / dict）——记录已经访问过的下标，防止走回头路。哈希表可以类比为“查字典”，键是下标，值是是否已经访问。  
  - **值到下标的映射**（value → list of indices）——把相同数值出现的位置全部收集起来，类似于把同一个词的所有页码记在一起，方便一次性找到所有可以“传送”的位置。  

- **为什么正确**：  
  BFS 按层次展开，每一次弹出队列的元素都是当前**最少步数**能够到达的下标。当我们第一次弹出终点 `n-1` 时，恰好就是最短路径长度。

- **时间/空间复杂度的大白话**：  
  - **时间复杂度**：如果不做任何剪枝，最坏情况下每个下标会遍历它的所有相同值的下标，导致 **O(n²)** 的操作（想象每个人都要和所有人握手，手数会非常多）。  
  - **空间复杂度**：我们需要存下 **所有下标的邻接信息**（值 → 下标列表）以及 BFS 用到的队列和访问集合，都是 **O(n)** 的规模（就像把所有人的联系方式和已经拜访过的名单都记下来）。  

#### 代码（Python）  

```python
from collections import defaultdict, deque

def min_jumps_bruteforce(arr):
    n = len(arr)
    if n == 1:                     # 只有一个元素，已经在终点
        return 0

    # 1️⃣ 建立「数值 → 所有出现下标」的映射
    idx_of_val = defaultdict(list)
    for i, v in enumerate(arr):
        idx_of_val[v].append(i)

    # 2️⃣ BFS 初始化
    q = deque([0])                 # 从下标 0 开始
    visited = {0}                  # 已经访问过的下标集合
    steps = 0                      # 已经走了几步

    while q:
        # 同层的所有节点一起处理，保证步数最少
        for _ in range(len(q)):
            i = q.popleft()
            if i == n - 1:         # 到达最后一个下标
                return steps

            # 3️⃣ 枚举三类可以到达的下标
            nxt = []               # 临时保存本层的所有候选

            # (a) 向左一步
            if i - 1 >= 0:
                nxt.append(i - 1)

            # (b) 向右一步
            if i + 1 < n:
                nxt.append(i + 1)

            # (c) 跳到所有相同数值的下标
            nxt.extend(idx_of_val[arr[i]])

            # 把候选加入队列（但要去重）
            for j in nxt:
                if j not in visited:
                    visited.add(j)
                    q.append(j)

            # 为了避免以后再次遍历同一数值的所有下标，清空列表
            idx_of_val[arr[i]].clear()   # 关键剪枝

        steps += 1   # 本层处理完，步数+1

    return -1   # 理论上不会到这里，因为一定能到达终点
```

#### 复杂度  

- **时间复杂度**：`O(n²)`（最坏情况下每个下标会遍历 `n` 个相同值的下标）  
  - 大白话：想象每个人都要和所有人握手，手数会非常多。  
- **空间复杂度**：`O(n)`（存下标列表、队列和访问集合）  
  - 大白话：我们只需要记住每个人的电话号码和已经拜访过的名单，数量和人数成正比。

### 2. 最优解  

#### 思路  

从暴力解我们已经知道：

1. **图的模型**是对的：节点是下标，边是「左、右、同值」三类跳。  
2. **BFS** 能得到最短步数。  

**慢点**主要在 **“同值跳”** 这一步：  
- 对每个下标我们都会遍历它对应的所有相同值的下标，导致**重复遍历**。  
- 实际上，一旦我们从某个数值 `v` 的任意一个位置跳过所有 `v`，以后再遇到 `v` 时就 **不需要再去遍历** 了，因为这些位置已经在同一层被访问过，后面再走只会更慢。  

**优化思路**：

- 在第一次使用「同值跳」时，**一次性把所有相同值的下标全部加入队列**，随后把该数值对应的列表清空（或删除），确保以后不再重复遍历。  
- 这一步相当于把「同值跳」看成 **一次性传送**，而不是每次都去「查字典」找所有页码。  

其余的左、右一步仍然保持不变。这样每个下标至多被加入队列一次，每个数值的相同下标列表也只遍历一次，整体复杂度降到 **线性**。

**核心算法**：**广度优先搜索（BFS） + 哈希表（记录相同值的下标）**。下面从零解释：

- **BFS**：想象你在迷宫里，先把离入口最近的所有房间打开（一步能到达），再打开离这些房间最近的房间……这样层层推进，第一次到达终点的层数就是最短路径。  
- **哈希表**：把「相同的数字」当成一本“电话簿”，键是数字，值是所有出现该数字的下标。查找 O(1)，像在字典里直接翻到对应页码。  

#### 代码（Python）  

```python
from collections import defaultdict, deque

def min_jumps(arr):
    n = len(arr)
    if n == 1:
        return 0

    # 1️⃣ 建立「数值 → 所有出现下标」的映射（哈希表）
    idx_of_val = defaultdict(list)
    for i, v in enumerate(arr):
        idx_of_val[v].append(i)

    # 2️⃣ BFS 初始化
    q = deque([0])          # 起点下标 0
    visited = {0}           # 已访问集合
    steps = 0               # 已走的步数

    while q:
        # 同层遍历，保证步数最小
        for _ in range(len(q)):
            i = q.popleft()
            if i == n - 1:          # 到达终点
                return steps

            # 3️⃣ 生成本层的所有「下一跳」候选
            # (a) 左右一步
            for nxt in (i - 1, i + 1):
                if 0 <= nxt < n and nxt not in visited:
                    visited.add(nxt)
                    q.append(nxt)

            # (b) 同值跳：一次性加入所有相同数值的下标
            for nxt in idx_of_val[arr[i]]:
                if nxt not in visited:
                    visited.add(nxt)
                    q.append(nxt)

            # 关键优化：已经用完该数值的「同值跳」后，立即清空列表
            # 以后再遇到相同的数值就不会再次遍历这些下标
            idx_of_val[arr[i]].clear()

        steps += 1   # 本层结束，步数+1

    return -1  # 按题意一定能到达，这行其实不会执行
```

#### 复杂度  

- **时间复杂度**：`O(n)`  
  - 每个下标至多入队一次，遍历一次；每个数值对应的下标列表也只遍历一次。  
  - 大白话：就像你只需要一次性把所有同名的朋友邀请进来，之后再也不需要重复打电话。  
- **空间复杂度**：`O(n)`  
  - 用来存下标列表、队列和已访问集合，和数组长度成正比。

## 心得  

- **核心技巧**：**BFS + 对「同值跳」的一次性剪枝**（利用哈希表一次性清空相同数值的下标列表）。  
- **适用的题型**：  
  1. **最短路径类**的“跳跃”题目，例如 *Jump Game III*、*Shortest Path in Binary Matrix*。  
  2. **图的层序遍历**，需要把“同类节点一次性展开”，如 *Word Ladder*（单词接龙）等。  
  3. **带有额外传送边**的数组/字符串问题，常用 **哈希表 + BFS** 优化。  
- **一句话总结解题钥匙**：**把「相同数值的传送」视作一次性批量加入 BFS 队列，并在使用后立即清空，避免重复遍历**。

## 反思  

- **第一反应**：把数组下标当成图的节点，直接写一个 BFS，所有能跳的下标都一次次枚举。  
- **最容易踩的坑**：  
  - **重复遍历相同数值的下标**导致超时（尤其在数组中同一个数字出现很多次）。  
  - **忘记边界检查**（`i-1`、`i+1` 是否越界）。  
  - **没有记录已访问的下标**，会出现无限循环。  
- **下次遇到同类题的第一步**：先画出“节点 + 边”的抽象图，判断是否可以使用 **BFS**，并思考是否存在“批量跳转”这类可以一次性展开的特殊边，然后用哈希表把它们收集起来。这样即可在 O(n) 时间内完成搜索。
