## 题目（英文原版）

**Description**

Given an array of integers arr and an integer d. In one step you can jump from index i to index:
In addition, you can only jump from index i to index j if arr[i] > arr[j] and arr[i] > arr[k] for all indices k between i and j (More formally min(i, j) < k < max(i, j)).
You can choose any index of the array and start jumping. Return the maximum number of indices you can visit.
Notice that you can not jump outside of the array at any time.

**Examples**

**Example 1:**

```
Input: arr = [6,4,14,6,8,13,9,7,10,6,12], d = 2
Output: 4
Explanation: You can start at index 10. You can jump 10 --> 8 --> 6 --> 7 as shown.
Note that if you start at index 6 you can only jump to index 7. You cannot jump to index 5 because 13 > 9. You cannot jump to index 4 because index 5 is between index 4 and 6 and 13 > 9.
Similarly You cannot jump from index 3 to index 2 or index 1.
```

**Example 2:**

```
Input: arr = [3,3,3,3,3], d = 3
Output: 1
Explanation: You can start at any index. You always cannot jump to any index.
```

**Example 3:**

```
Input: arr = [7,6,5,4,3,2,1], d = 1
Output: 7
Explanation: Start at index 0. You can visit all the indicies.
```

**Constraints**

- 1 <= arr.length <= 1000
- 1 <= arr[i] <= 105
- 1 <= d <= arr.length


示例 3:
```text

Output: 7

```

- `1 <= arr.length <= 1000`
- `1 <= arr[i] <= 10^5`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**从每一个起点 i 出发，穷举它能跳到的所有合法位置 j，然后继续从 j 再跳，直到再也跳不动为止**。  
这相当于在数组上做一次深度优先搜索（DFS），把所有可能的跳跃路径都走一遍，记录走过的最长路径长度。

> **数据结构类比**  
> - **数组** 就像一排编号的格子，每个格子里放着一个高度 `arr[i]`。  
> - **跳跃** 类似“从高处往低处滑下来”，只能往左或往右滑，且滑的距离不能超过 `d`，中间的格子高度都必须比起点低，才能保证不被“拦住”。  
> - **DFS 递归** 就像我们让小球从一个格子滚下去，滚到哪个格子，就再让它继续往下滚，直到卡住为止。

**为什么这个方法一定能得到答案**  
因为我们把**所有**可能的起点和**所有**合法的跳跃路径都枚举了，最长的那条自然就是答案。

**时间/空间复杂度（大白话版）**  

- 对每个起点（最多 `n` 个）我们都要尝试向左、向右各最多 `d` 步，检查中间是否都有更低的数值。  
- 检查一次跳跃是否合法需要遍历这段区间，最坏情况是 `O(d)`。  
- 再加上递归会继续向下搜索，最坏情况下每次都能跳到新的位置，导致**指数级**的重复计算。  
- 粗略算下来，暴力解的时间复杂度大约是 `O(n * d * n)`，在最坏情况下甚至会退化到 `O(n³)`（`n ≤ 1000` 时仍然可以跑通，但会比较慢）。  
- 递归栈最多保存 `n` 层调用，空间复杂度是 `O(n)`。

#### 代码（Python）

```python
from typing import List

def maxJumps_bruteforce(arr: List[int], d: int) -> int:
    n = len(arr)

    # 递归尝试从 i 开始的所有跳法，visited 用来防止无限递归
    def dfs(i: int, visited: set) -> int:
        max_len = 1                     # 至少能站在自己这里
        # 向左跳
        for step in range(1, d + 1):
            j = i - step
            if j < 0: break
            # 必须满足 arr[i] > arr[j]，且 i 与 j 之间的所有元素都比 arr[i] 小
            if arr[i] > arr[j] and all(arr[k] < arr[i] for k in range(j + 1, i)):
                if j not in visited:    # 防止循环（虽然题目已经保证不会出现）
                    visited.add(j)
                    max_len = max(max_len, 1 + dfs(j, visited))
                    visited.remove(j)
            else:
                # 一旦碰到不满足的格子，后面更远的格子一定也不行（因为中间已经有更高的挡住了）
                break

        # 向右跳
        for step in range(1, d + 1):
            j = i + step
            if j >= n: break
            if arr[i] > arr[j] and all(arr[k] < arr[i] for k in range(i + 1, j)):
                if j not in visited:
                    visited.add(j)
                    max_len = max(max_len, 1 + dfs(j, visited))
                    visited.remove(j)
            else:
                break

        return max_len

    answer = 0
    for start in range(n):
        answer = max(answer, dfs(start, {start}))
    return answer
```

> **关键行中文注释**  
> - `for step in range(1, d + 1):` 遍历左/右方向最多 `d` 步的候选位置。  
> - `all(arr[k] < arr[i] for k in ...)` 确保跳过去的所有格子都比起点低，模拟“中间没有更高的挡板”。  
> - `if j not in visited:` 防止递归无限循环（虽然本题不需要，但写成这样更安全）。  

#### 复杂度

- **时间复杂度**：`O(n * d * n)`（最坏可视为 `O(n³)`）——每个起点都要尝试左/右各 `d` 步，且每次合法性检查可能遍历 `O(d)`，递归导致大量重复计算。  
- **空间复杂度**：`O(n)`——递归栈深度最多 `n`，以及 `visited` 集合的开销。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**大量的重复计算**：同一个位置 `i` 的“从这里出发能访问的最大长度”会被不同的起点多次求一次。  
只要我们把**每个位置的最优结果记下来**，以后再需要时直接查表，就能把时间降下来。这正是**动态规划（DP）**的核心思想。

**关键观察**  

1. **只能往更低的格子跳**，所以如果我们已经算出了所有比 `arr[i]` 小的格子的答案，那么 `i` 的答案就可以基于这些已知值来算。  
2. 跳的距离受限 `d`，且只能在左右各 `d` 步之内。  
3. **从高往低的顺序**计算 DP 可以避免循环依赖。实现上有两种方式：
   - **记忆化搜索（DFS + memo）**：从每个位置递归向左/右探索，只要把已经算好的 `dp[i]` 存下来，下次直接返回。  
   - **按高度排序的自底向上 DP**：把所有下标按照对应的 `arr[i]` 从小到大排序，依次计算 `dp[i]`，因为所有能跳到 `i` 的位置高度都更高，已经在前面算完。

这里我们采用**记忆化搜索**，思路更直观，代码更简洁。

**步骤拆解**  

1. 建立数组 `dp`，`dp[i]` 表示**从 i 出发能够访问的最多格子数**（包括自己）。初始值设为 `0`，表示未计算。  
2. 定义递归函数 `dfs(i)`：  
   - 如果 `dp[i]` 已经有值，直接返回。  
   - 否则，先把 `dp[i]` 设为 `1`（只能站在自己）。  
   - 向左检查 `i-1, i-2, …, i-d`，只要满足 `arr[i] > arr[j]` 且中间都比 `arr[i]` 小，就递归 `dfs(j)`，更新 `dp[i] = max(dp[i], 1 + dfs(j))`。  
   - 向右同理。  
   - 一旦遇到不满足 `arr[i] > arr[j]` 的格子，就可以**提前终止**后续更远的格子检查，因为更远的格子必然被这格子挡住（中间已经出现更高的障碍）。  
3. 对所有下标 `i` 调用 `dfs(i)`，取最大值即为答案。

**为什么能把时间降到 O(n·d)**  

- 每个下标 `i` 的 `dfs(i)` 最多遍历左/右各 `d` 步的候选格子，检查一次合法性只需要 **O(1)**（因为只比较 `arr[i] > arr[j]`，中间是否更低已经在前一次遍历时保证了）。  
- `dfs(i)` 只会被调用一次，结果会被记在 `dp[i]` 中，后面再需要时直接返回，**没有重复计算**。  
- 因此整体时间是 `O(n·d)`，空间除了原数组外，只需要 `dp`（`O(n)`）和递归栈（最深 `O(n)`）。

> **类比**：把每个格子想象成山坡的峰顶，只有从高处才能往低处滑。我们先把所有“低谷”的答案算好（只能停在那里），再把更高的峰顶的答案“一层层往上推”，每次只看能直接滑到的相邻低谷，省去了反复爬坡的过程。

#### 代码（Python）

```python
from typing import List
import sys
sys.setrecursionlimit(10000)   # 防止递归深度不足

def maxJumps(arr: List[int], d: int) -> int:
    n = len(arr)
    dp = [0] * n                # dp[i] = 0 表示尚未计算

    def dfs(i: int) -> int:
        """返回从下标 i 出发能访问的最多格子数（包括 i 本身）"""
        if dp[i] != 0:          # 已经算过，直接返回
            return dp[i]

        best = 1                # 至少能站在自己这格

        # 向左最多跳 d 步
        for step in range(1, d + 1):
            j = i - step
            if j < 0: break
            if arr[i] > arr[j]:                     # 高度要求满足
                best = max(best, 1 + dfs(j))        # 递归求 j 的最优，再加上当前这格
            else:
                # 一旦遇到不低的格子，后面更远的格子一定被它挡住，直接终止
                break

        # 向右最多跳 d 步
        for step in range(1, d + 1):
            j = i + step
            if j >= n: break
            if arr[i] > arr[j]:
                best = max(best, 1 + dfs(j))
            else:
                break

        dp[i] = best            # 记忆化，保存结果
        return best

    # 计算所有起点的最优值，取最大
    answer = 0
    for i in range(n):
        answer = max(answer, dfs(i))
    return answer
```

> **关键行中文注释**  
> - `dp = [0] * n` 创建记忆表，`0` 代表“还没算”。  
> - `if dp[i] != 0: return dp[i]` 如果已经算过，就直接返回，避免重复递归。  
> - `for step in range(1, d + 1):` 遍历左/右方向最多 `d` 步的候选格子。  
> - `if arr[i] > arr[j]:` 只有比当前格子低才可以跳。  
> - `break` 一旦碰到不满足的格子，后面的格子一定被它挡住，提前结束循环。  

#### 复杂度

- **时间复杂度**：`O(n·d)`  
  - 每个下标最多检查左、右各 `d` 步，且每个下标只会递归一次（记忆化后不再重复）。  
  - 与暴力解相比，去掉了指数级的重复子问题，真正做到“每个位置只算一次”。  
- **空间复杂度**：`O(n)`  
  - `dp` 数组占 `n` 个整数的空间。  
  - 递归栈最深也不会超过 `n`，在本题 `n ≤ 1000` 完全可以接受。

## 心得

- **核心技巧**：**记忆化深度优先搜索（DFS + DP）**，把“从某点出发的最优解”保存下来，避免重复计算。  
- **适用的题型**：  
  1. **跳跃类游戏**（如 Jump Game I/II、Jump Game III）——需要从某位置往前/后跳，且跳的合法性可以快速判定。  
  2. **单调约束的路径搜索**（如 “山脉数组的最长递减子序列”、 “带限制的爬楼梯”）——只允许从高往低或从小往大移动。  
- **一句话总结解题钥匙**：**把每个位置的“最远可达长度”记下来，后面只要查表，不再重复爬坡。**

## 反思

- **第一反应**：直接写一个遍历所有起点、每一步都枚举左/右 `d` 步的递归暴力解，想把题目描述直接搬进代码。  
- **最容易踩的坑**：  
  1. **合法性检查遗漏**——必须保证 **“中间所有格子都比起点低”**，否则会误跳。  
  2. **提前终止的条件**——一旦遇到不满足 `arr[i] > arr[j]` 的格子，后面的更远格子一定被阻挡，忘记 `break` 会导致不必要的遍历。  
  3. **递归深度**——`n` 可能达到 1000，默认递归深度可能不够，需要适当调大（`sys.setrecursionlimit`）。  
- **下次遇到同类题**，第一步应该思考 **“有没有子问题可以重复使用？”**，如果答案是“有”，就立刻考虑 **记忆化/DP** 而不是直接暴力枚举。这样可以把时间从指数级降到线性级（或接近线性）。
