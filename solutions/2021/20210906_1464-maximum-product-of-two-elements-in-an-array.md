## 题目（中文翻译）

给定一个整数数组 `nums`，求满足 `i != j` 时，表达式 `(nums[i] - 1) * (nums[j] - 1)` 的最大值并返回。

**示例 1**  
**输入**: `nums = [3,4,5,2]`  
**输出**: `12`  
**解释**: 若选择下标 `i = 1` 与 `j = 2`（下标从 0 开始），可得到最大值，即 `(nums[1] - 1) * (nums[2] - 1) = (4 - 1) * (5 - 1) = 3 * 4 = 12`。

**示例 2**  
**输入**: `nums = [1,5,4,5]`  
**输出**: `16`  
**解释**: 选择下标 `i = 1` 与 `j = 3`（下标从 0 开始），可得到最大值 `(5 - 1) * (5 - 1) = 16`。

**示例 3**  
**输入**: `nums = [3,7]`  
**输出**: `12`

**约束条件**  
- `2 <= nums.length <= 500`  
- `1 <= nums[i] <= 10^3`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  
最直接的想法是把所有可能的两两组合都枚举一遍，计算  
\[
(nums[i]-1) \times (nums[j]-1)
\]  
的值，然后取最大值。

- **用到的数据结构**：只需要一个普通的 Python 列表 `nums`。遍历时用两层 `for` 循环，类似于我们在超市里把每件商品都和其它商品配对尝试，看哪对组合最划算。
- **为什么正确**：因为我们把**所有**合法的下标对 `(i, j)`（`i != j`）都算了一遍，最大值必然会被找到。
- **复杂度分析**：  
  - **时间**：外层循环跑 `n` 次，内层循环平均也跑 `n` 次，总共约 `n × n = n²` 次计算。这里的 `O(n²)` 可以想象成“如果有 1000 件商品，两两配对要检查 1000×1000=1 000 000 次”。  
  - **空间**：只用了常数级的额外变量（最大值、下标），所以是 `O(1)`，即不随 `n` 增长。

#### 代码（Python）

```python
from typing import List

def max_product_brute(nums: List[int]) -> int:
    """
    暴力枚举所有两两组合，返回 (nums[i]-1)*(nums[j]-1) 的最大值。
    """
    n = len(nums)
    max_val = 0                     # 用来保存目前找到的最大乘积
    for i in range(n):              # 第一个下标 i
        for j in range(i + 1, n):   # 第二个下标 j，确保 i != j 且不重复
            prod = (nums[i] - 1) * (nums[j] - 1)   # 计算公式
            if prod > max_val:      # 如果比当前最大值更大，就更新
                max_val = prod
    return max_val
```

#### 复杂度

- **时间复杂度**：`O(n²)` — 随着数组长度 `n` 增大，计算次数呈平方增长。  
- **空间复杂度**：`O(1)` — 只用了几个临时变量，额外占用的内存与 `n` 无关。

### 2. 最优解

#### 思路  
从暴力解可以看出，真正影响结果的只是**两个最大的数**，因为乘积 `(a-1)*(b-1)` 随着 `a`、`b` 的增大而单调增大。  
所以我们只要在一次遍历中找到数组中最大的两个元素 `max1`、`max2`，答案就是 `(max1-1)*(max2-1)`。

**慢在哪里？**  
暴力解的瓶颈是两层循环导致的 `n²` 次乘法和比较。我们只需要一次遍历（`O(n)`）就能得到答案。

**一步步推导**  

1. **维护两个最大值**：遍历数组时，遇到更大的数就把原来的最大值 `max1` 移到第二大 `max2`，再把新数设为 `max1`。如果新数介于 `max1` 与 `max2` 之间，只更新 `max2`。  
2. **为什么只要两大**：设 `a ≥ b ≥ c`，则  
   \[
   (a-1)(b-1) \ge (a-1)(c-1) \quad\text{且}\quad (a-1)(b-1) \ge (b-1)(c-1)
   \]  
   因为 `a-1`、`b-1`、`c-1` 都是非负数，乘以更大的因子会得到更大的结果。  

**核心算法**：一次遍历 + 两个变量保存最大值。  
**类比**：像在跑步比赛中找前两名，只需要一次观看所有选手的成绩，不需要两两比较。

#### 代码（Python）

```python
from typing import List

def max_product_optimal(nums: List[int]) -> int:
    """
    一遍遍历找到数组中最大的两个数，返回 (max1-1)*(max2-1)。
    """
    # 初始化为比所有可能的数都小的值（题目保证 nums[i] >= 1）
    max1, max2 = 0, 0

    for x in nums:
        if x > max1:               # x 成为新的最大值
            max2 = max1            # 旧的最大值降为第二大
            max1 = x
        elif x > max2:             # x 只比第二大大，更新 max2
            max2 = x

    # 根据题意返回 (max1-1)*(max2-1)
    return (max1 - 1) * (max2 - 1)
```

#### 复杂度

- **时间复杂度**：`O(n)` — 只遍历一次数组，随 `n` 线性增长。相比暴力的 `O(n²)`，速度提升了数量级。  
- **空间复杂度**：`O(1)` — 只用了两个额外变量 `max1`、`max2`，占用的内存不随 `n` 变化。

## 心得

- **核心技巧**：在只涉及“最大/最小”类的乘法或加法题目时，往往只需要找出极值（最大或最小）即可，不必枚举所有组合。  
- **适用的题型**：  
  1. “数组中两个数的最大乘积” (`Maximum Product of Two Numbers`)。  
  2. “数组中两个数的最大和” (`Maximum Sum of Two Numbers`)。  
  3. “寻找两条最长的木棍” 这类需要两大值的几何或计数题。  
- **一句话总结解题钥匙**：**把“所有可能”压缩成“关键极值”，一次遍历搞定**。

## 反思

- **第一反应**：直接写两层循环暴力枚举，因为这最符合“先把问题完整写出来再想优化”。  
- **最容易踩的坑**：  
  - 忘记排除同一下标的情况（`i` 与 `j` 必须不同），导致错误的自乘。  
  - 当数组中出现相同的最大值时，需要确保第二大也能是相同的数，而不是误把它当成更小的数。  
- **下次类似题的第一步**：先问自己“答案只和多少个元素有关？”如果是“最大/最小”两两个元素，就立刻想到**一次遍历找极值**，而不是直接暴力。
