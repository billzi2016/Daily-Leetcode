# #1411. N × 3 网格的染色方法数 / Number of Ways to Paint N × 3 Grid

> 难度：困难 · 标签：Dynamic Programming · [LeetCode 链接](https://leetcode.com/problems/number-of-ways-to-paint-n-3-grid/)

---

## 题目（英文原版）

**Description**

You have a grid of size n x 3 and you want to paint each cell of the grid with exactly one of the three colors: Red, Yellow, or Green while making sure that no two adjacent cells have the same color (i.e., no two cells that share vertical or horizontal sides have the same color).
Given n the number of rows of the grid, return the number of ways you can paint this grid. As the answer may grow large, the answer must be computed modulo 109 + 7.

**Examples**

**Example 1:**

```
Input: n = 1
Output: 12
Explanation: There are 12 possible way to paint the grid as shown.
```

**Example 2:**

```
Input: n = 5000
Output: 30228214
```

**Constraints**

- n == grid.length
- 1 <= n <= 5000

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  

最直接的想法是**把所有可能的涂色方案都枚举出来**，然后逐一检查相邻格子是否颜色相同。  
- **数据结构**：我们可以用一个二维列表 `grid[n][3]` 来存每一格的颜色。颜色用整数 `0、1、2` 表示（比如 0‑红、1‑黄、2‑绿），这就像把每一格看成字典里的“词”，对应的整数是“页码”。  
- **枚举方式**：对每一行的 3 个格子，各自有 3 种颜色选择，总共 `3^(3n)` 种组合。我们用递归（深度优先搜索）逐格填色，填完后检查是否满足 **水平** 与 **垂直** 相邻格子不同的约束。  
- **正确性**：因为我们遍历了**全部**合法或不合法的涂色方案，最后留下的只有满足约束的方案，所以计数一定是正确的。  

#### 代码（Python）  

```python
MOD = 10**9 + 7
COLORS = 3                     # 红、黄、绿

def num_of_ways_bruteforce(n: int) -> int:
    """暴力枚举所有涂色方案，时间会爆炸，仅作思路展示。"""
    grid = [[-1] * 3 for _ in range(n)]   # -1 表示尚未涂色
    total = 0

    def valid(r: int, c: int, color: int) -> bool:
        """检查把 (r,c) 位置涂成 color 后，是否与已涂的相邻格子冲突。"""
        # 检查左边格子
        if c > 0 and grid[r][c-1] == color:
            return False
        # 检查上面格子
        if r > 0 and grid[r-1][c] == color:
            return False
        return True

    def dfs(idx: int):
        """按顺序填第 idx 格（从 0 到 n*3-1）。"""
        nonlocal total
        if idx == n * 3:                 # 所有格子都填完了
            total = (total + 1) % MOD
            return

        r, c = divmod(idx, 3)            # 把一维下标转成行列坐标
        for col in range(COLORS):
            if valid(r, c, col):
                grid[r][c] = col        # 填色
                dfs(idx + 1)            # 递归填下一个格子
                grid[r][c] = -1         # 回溯

    dfs(0)
    return total
```

> 关键行注释已用中文标出，代码可以直接运行（但对 `n` 大于 3 时会超时）。

#### 复杂度  

- **时间复杂度**：`O(3^(3n))`。  
  这里的 `3^(3n)` 表示每个格子都有 3 种选择，整个网格有 `3n` 个格子，指数增长就像“每增加一层楼梯，就会出现指数倍的可能”。实际运行时会非常慢，甚至在 `n=4` 时就已经不可接受。  
- **空间复杂度**：`O(n)`。递归栈的深度是 `3n`，每层只保存常数信息，所以大约需要 `3n` 个栈帧，随 `n` 线性增长。

### 2. 最优解  

#### 思路  

暴力解的瓶颈在于**每一格都独立枚举**，导致指数级的时间。  
观察每一行的 3 格子，只要满足相邻格子不同，就有 **12 种合法的颜色排列**（后面会解释怎么得到的）。于是我们可以把问题从“每格怎么涂”提升到“每行怎么涂”。  

**一步步推导**  

1. **统计单行合法模式**  
   - **全不同类型（记作 A）**：三格颜色全不相同。例如 `R Y G`。  
     先选第一格的颜色，有 3 种；第二格只能选剩下的 2 种；第三格只能选剩下的 1 种 → `3·2·1 = 6` 种。  
   - **两端相同类型（记作 B）**：第一格和第三格颜色相同，第二格不同。例如 `R Y R`。  
     先选两端的颜色（3 种），再选中间的颜色（不能和两端相同，剩下 2 种） → `3·2 = 6` 种。  

   所以每行合法排列总数是 `6 + 6 = 12`。  

2. **行间相容性**  
   两行相邻时，只需要保证**同一列的颜色不同**。我们只关心上一行的「类型」而不是具体的颜色，因为同一类型内部的具体配色只会产生等价的转移数。  

   - **上一行是 A**（三格全不同）  
     - 当前行若想是 A：只能把上一行的每个颜色换成另外两种中的一种，且要保持三格仍然全不同。实际上有 **2 种** 可能。  
     - 当前行若想是 B：要让两端相同，且不与上一行同列颜色相同，同样有 **2 种** 可能。  

   - **上一行是 B**（两端相同）  
     - 当前行若是 A：两端颜色必须分别与上一行对应列不同，且保持三格全不同，有 **2 种** 可能。  
     - 当前行若是 B：两端仍然相同且不同于上一行对应列，且中间颜色也不同，有 **3 种** 可能。  

   以上转移数可以通过手动列举或画图验证，得到下面的递推式：

   \[
   \begin{aligned}
   a_i &= (2 \times a_{i-1} + 2 \times b_{i-1}) \pmod{M}\\
   b_i &= (2 \times a_{i-1} + 3 \times b_{i-1}) \pmod{M}
   \end{aligned}
   \]

   其中 `a_i` 表示第 `i` 行是类型 A 的涂色方式总数，`b_i` 表示类型 B 的方式总数，`M = 10^9+7` 为取模数。  

3. **初始化**  
   第 1 行可以是任意合法排列，所以  
   `a_1 = 6`（全不同的 6 种），`b_1 = 6`（两端相同的 6 种）。  

4. **答案**  
   所有行都涂完后，最后一行可以是 A 也可以是 B，答案为 `a_n + b_n (mod M)`。  

5. **空间优化**  
   递推只依赖前一行的 `a`、`b`，所以只需要 **O(1)** 的额外空间。  

#### 代码（Python）  

```python
MOD = 10**9 + 7

def num_of_ways(n: int) -> int:
    """
    动态规划 O(n) 时间、O(1) 空间。
    a: 第 i 行颜色全不相同的方案数
    b: 第 i 行两端相同的方案数
    """
    if n == 0:
        return 0

    # 第 1 行的统计
    a, b = 6, 6          # a_1 = 6, b_1 = 6

    # 从第 2 行开始递推
    for _ in range(2, n + 1):
        # 根据前一行的 a、b 计算当前行的 a、b
        new_a = (2 * a + 2 * b) % MOD
        new_b = (2 * a + 3 * b) % MOD
        a, b = new_a, new_b   # 更新为当前行的值

    # 最后一行可以是 A 也可以是 B
    return (a + b) % MOD
```

> 代码每一步都有中文注释，直接运行即可得到答案。  

#### 复杂度  

- **时间复杂度**：`O(n)`。只遍历了 `n` 行，每行做常数次加法、乘法和取模，线性增长就像“走了 n 步”。相比暴力的指数级，快了很多。  
- **空间复杂度**：`O(1)`。只用两个整数保存前一行的状态，和 `n` 的大小无关，像“只带了一把钥匙”一样轻巧。

## 心得  

- **核心技巧**：把“每格”的问题抽象成“每行的排列类型”，用**状态压缩**（把同类状态合并）来降低状态数，随后用**动态规划**求解。  
- **适用的题型**：  
  1. *Paint Fence*（给定栅栏柱子数，颜色数，要求相邻柱子颜色不同）  
  2. *Number of Ways to Paint a 2×N Grid*（类似的行列约束）  
  3. *Tile the Grid With Dominoes*（利用行状态转移的 DP）  
- **一句话总结解题钥匙**：**先把每行的合法排列归类（状态压缩），再用 DP 只在相邻行之间转移**。

## 反思  

- **第一反应**：看到“每个格子 3 种颜色，且相邻不同”，立刻想到**全局枚举**，即暴力搜索。  
- **最容易踩的坑**：  
  - **忘记取模**：递推过程中数值会很快超过 64 位整数范围，需要每一步都 `% MOD`。  
  - **状态划分错误**：如果把行的 12 种具体排列全部当作不同状态，会导致 O(12²·n) 的实现，仍然可以通过，但不够简洁；更糟的是若把状态划分得太细，容易写错转移数。  
  - **边界条件**：`n = 1` 时直接返回 `12`（6+6），若把循环从 `i=1` 开始容易导致多算一次。  

- **下次遇到同类题**：第一步先**统计单行（或单列）的合法模式数**，并**把相似的模式归类**，再**写出相邻行之间的兼容关系**，最后用 DP 按行（列）迭代。这样可以把指数爆炸的问题压缩到线性时间。
