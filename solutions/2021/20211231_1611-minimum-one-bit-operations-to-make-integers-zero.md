# #1611. 将整数变为零的最少单比特操作次数 / Minimum One Bit Operations to Make Integers Zero

> 难度：困难 · 标签：Dynamic Programming、Bit Manipulation、Memoization · [LeetCode 链接](https://leetcode.com/problems/minimum-one-bit-operations-to-make-integers-zero/)

---

## 题目（英文原版）

**Description**

Given an integer n, you must transform it into 0 using the following operations any number of times:
Return the minimum number of operations to transform n into 0.

**Examples**

**Example 1:**

```
Input: n = 3
Output: 2
Explanation: The binary representation of 3 is "11".
"11" -> "01" with the 2nd operation since the 0th bit is 1.
"01" -> "00" with the 1st operation.
```

**Example 2:**

```
Input: n = 6
Output: 4
Explanation: The binary representation of 6 is "110".
"110" -> "010" with the 2nd operation since the 1st bit is 1 and 0th through 0th bits are 0.
"010" -> "011" with the 1st operation.
"011" -> "001" with the 2nd operation since the 0th bit is 1.
"001" -> "000" with the 1st operation.
```

**Constraints**

- 0 <= n <= 109

## 题目（中文翻译）

**描述**  
给定一个整数 `n`，你可以任意次使用以下操作将其转化为 `0`：  
返回将 `n` 转化为 `0` 所需的最少操作次数。

**示例 1**  
**输入**: `n = 3`  
**输出**: `2`  
**解释**: `3` 的二进制表示为 `"11"`。  
- `"11"` → `"01"`，使用第 `2` 次操作，因为第 `0` 位是 `1`。  
- `"01"` → `"00"`，使用第 `1` 次操作。

**示例 2**  
**输入**: `n = 6`  
**输出**: `4`  
**解释**: `6` 的二进制表示为 `"110"`。  
- `"110"` → `"010"`，使用第 `2` 次操作，因为第 `1` 位是 `1` 且第 `0` 位到第 `0` 位都是 `0`。  
- `"010"` → `"011"`，使用第 `1` 次操作。  
- `"011"` → `"001"`，使用第 `2` 次操作，因为第 `0` 位是 `1`。  
- `"001"` → `"000"`，使用第 `1` 次操作。

**约束条件**  
- `0 <= n <= 10^9`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把题目给的**操作**直接模拟：  
- **操作规则**：  
  - 第 `0` 位（最低位）随时都可以翻转。  
  - 对于第 `i (i>0)` 位，只有当第 `i‑1` 位是 `1` 并且更低位（`0 … i‑2`）全部是 `0` 时，才能翻转第 `i` 位。  
- 只要把当前整数 `n` 当作一个状态，就可以把所有合法的翻转当成**邻接的状态**，于是把问题转化为**在状态图中最短路径**，即 **BFS**（广度优先搜索）。

把所有可能的整数（`0 … 2^31‑1`）都当成图的节点，遍历一次就能得到从 `n` 到 `0` 的最短步数。

> **为什么会对**  
> BFS 每层展开的都是“一步可以到达的所有整数”，层数恰好等于最少操作次数。只要不遗漏合法的翻转，答案一定是最短的。

> **复杂度分析（大白话）**  
> - **时间**：最坏情况下要遍历所有 `2^31`（约 21 亿）个整数，显然不可接受。我们用大 O 记法写成 **O(2^b)**（`b` 是整数的位数），这在实际运行时会超时。  
> - **空间**：需要一个 `visited` 集合保存已经访问过的整数，同样是 **O(2^b)**，内存也会爆掉。

> **总结**：暴力 BFS 能说明思路，但在 0 ≤ n ≤ 10⁹ 的限制下根本跑不完，只能当作“最笨的办法”，为后面的优化提供参考。

#### 代码（Python）

```python
from collections import deque

def min_ops_bruteforce(n: int) -> int:
    """暴力 BFS，演示最直接的思路（会超时，仅供理解）"""
    if n == 0:
        return 0

    # 判断第 i 位是否可以翻转
    def can_flip(x: int, i: int) -> bool:
        if i == 0:                     # 第 0 位随时可以翻
            return True
        lower_mask = (1 << i) - 1      # 低于 i 的位全为 1 的掩码
        # 只有第 i‑1 位是 1，且更低位全是 0 才行
        return (x & (1 << (i - 1))) != 0 and (x & (lower_mask >> 1)) == 0

    q = deque([(n, 0)])                # (当前整数, 已用步数)
    visited = {n}
    while q:
        cur, step = q.popleft()
        if cur == 0:
            return step
        # 枚举所有可能的翻转位
        for i in range(cur.bit_length() + 1):   # 只需要检查到最高位
            if can_flip(cur, i):
                nxt = cur ^ (1 << i)            # 翻转第 i 位
                if nxt not in visited:
                    visited.add(nxt)
                    q.append((nxt, step + 1))
    return -1   # 理论上不会到这里
```

#### 复杂度

- **时间复杂度**：`O(2^b)`（`b` 为整数的位数），因为最坏情况下会遍历所有可能的状态。  
- **空间复杂度**：`O(2^b)`，需要记录已经访问的状态集合。

### 2. 最优解

#### 思路  

从暴力解可以看出，**状态空间太大**是瓶颈。  
观察题目给出的操作，可以发现它恰好是 **Gray 码**（二进制反射格雷码）生成过程中的一步：  
- 在 Gray 码序列里，每一次只会翻转 **唯一满足“低位全 0、紧邻的低位为 1”** 的那一位。  
- 题目要求的是 **从整数 `n` 到 `0` 所需的最少翻转次数**，这正好等价于 **`n` 在 Gray 码序列中的下标**（因为序列是从 `0` 开始的）。

Gray 码的下标有一个非常简洁的递归描述：

1. 设 `k` 为 `n` 的最高位所在的指数（即 `2^k ≤ n < 2^{k+1}`）。  
2. **特殊情况**：如果 `n` 本身就是一个幂 `2^k`，要把最高位翻成 0，需要先把低位走完一次完整的 Gray 循环，步骤数恰好是 `2^{k+1} - 1`（比如 `4(100)` 需要 `7` 步）。  
3. **一般情况**：`n` 位于 `2^k` 与 `2^{k+1}` 之间。  
   - 为了把最高位 `2^k` 翻成 0，必须先把低位 **跑到** `2^{k+1} - 1 - n`（也就是对称的那个数），因为只有当低位形成 `...10`（即恰好是 `2^{k+1} - 1 - n`）时，最高位才满足翻转条件。  
   - 把低位跑到该对称数的步数就是 **`f(2^{k+1} - 1 - n)`**，随后再一次翻转最高位（一步），于是  
     `f(n) = f(2^{k+1} - 1 - n) + 1`。

把上面的递归直接写成代码，并用 **记忆化（Memoization）** 保存已经算过的子问题，就可以在 **O(log n)** 的时间内得到答案。

> **为什么这个方法正确**  
> - 递归把“大问题”拆成“把低位走到可以翻最高位的状态 + 翻最高位”。  
> - 对称数 `2^{k+1} - 1 - n` 正好是**唯一**能让最高位满足条件的状态（低位必须是 `10…0`），因此没有更短的路径。  
> - 递归终止于 `n = 0` 或 `n` 为幂的情况，这两种都有明确的步数公式。  

> **复杂度大白话**  
> - **时间**：每一次递归都把最高位去掉，最多递归 `log₂ n` 次，等价于 **O(log n)**，在本题的 `n ≤ 10⁹` 下只会递归不到 30 层，几乎瞬间完成。  
> - **空间**：递归栈深度同样是 `log n`，再加上记忆化表最多存 `log n` 条记录，整体是 **O(log n)**。

#### 代码（Python）

```python
from functools import lru_cache

def minimumOneBitOperations(n: int) -> int:
    """
    递归 + 记忆化实现，时间 O(log n)，空间 O(log n)。
    """

    @lru_cache(maxsize=None)
    def dfs(x: int) -> int:
        if x == 0:                     # 已经是 0，不需要任何操作
            return 0

        # 最高位的指数 k（2**k <= x < 2**(k+1)）
        k = x.bit_length() - 1         # bit_length() 返回二进制位数

        # 若 x 正好是 2**k，直接返回公式 2**(k+1) - 1
        if x == 1 << k:
            return (1 << (k + 1)) - 1

        # 否则，先把低位走到可以翻最高位的状态，再翻一次最高位
        mask = (1 << (k + 1)) - 1      # 形如 111…1（k+1 个 1）的掩码
        # 对称数：mask - x，使得低位恰好是 10...0，满足翻最高位的条件
        return dfs(mask - x) + 1

    return dfs(n)
```

> **代码要点注释**  
> - `bit_length()`：相当于“找出最高位”，把整数的二进制位数算出来，比手动循环更直观。  
> - `1 << k`：左移相当于 “2 的 k 次方”，好比把 “1” 移到第 k 位上，得到 `2^k`。  
> - `mask = (1 << (k+1)) - 1`：生成形如 `111…1` 的数，它的作用是把 `x` **镜像翻转**，得到唯一能够让最高位满足翻转条件的低位状态。  
> - `@lru_cache`：把已经算好的 `dfs(x)` 记下来，防止重复计算，保证递归只进行 `O(log n)` 次。

#### 复杂度

- **时间复杂度**：`O(log n)`  
  每次递归都把最高位剔除，最多递归 `log₂ n` 次。记忆化保证每个子问题只算一次。  
- **空间复杂度**：`O(log n)`  
  递归栈深度和缓存表的大小均为 `log₂ n`。

## 心得

- **核心技巧**：把题目抽象成 **Gray 码的下标**，利用 **最高位对称** 的性质得到递归公式。  
- **适用的题型**：  
  1. **Gray 码相关**（如“求两个整数的 Gray 码距离”）。  
  2. **只允许在特定“前置条件”下翻转位的题目（位操作 + 递归）**。  
  3. **需要把大范围状态压缩到 `O(log n)` 的递归/DP**（例如 “整数拆分成 2 的幂的最少步数”）。
- **解题钥匙**：**“把最高位先处理，再把低位递归”**——找出让最高位能够翻转的唯一低位状态，然后递归解决剩余部分。

## 反思

- **第一反应**：看到“只能在低位全 0、紧邻位为 1 时翻转”，立刻想到 **Gray 码**，因为 Gray 码的生成正是满足这种条件的位翻转。  
- **最容易踩的坑**：  
  - 忽略了 **第 0 位随时可以翻** 的特殊规则，导致递归公式少了最后的 `+1`。  
  - 在实现对称数时写成 `mask - x` 而不是 `mask ^ x`，两者意义完全不同。  
  - 没有使用记忆化，递归会出现指数级重复计算。  
- **下次类似题**：遇到“只能在某些位满足特定前置条件才能操作”的位操作题，第一步就要**寻找一种全局序列（如 Gray 码）把局部规则全局化**，再用递归或 DP 把问题规模按最高位递减。这样往往能把指数级搜索压到对数级。
