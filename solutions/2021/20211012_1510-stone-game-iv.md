# #1510. 石子游戏 IV / Stone Game IV

## 题目（英文原版）

**Description**

Alice and Bob take turns playing a game, with Alice starting first.
Initially, there are n stones in a pile. On each player's turn, that player makes a move consisting of removing any non-zero square number of stones in the pile.
Also, if a player cannot make a move, he/she loses the game.
Given a positive integer n, return true if and only if Alice wins the game otherwise return false, assuming both players play optimally.

**Examples**

**Example 1:**

```
Input: n = 1
Output: true
Explanation: Alice can remove 1 stone winning the game because Bob doesn't have any moves.
```

**Example 2:**

```
Input: n = 2
Output: false
Explanation: Alice can only remove 1 stone, after that Bob removes the last one winning the game (2 -> 1 -> 0).
```

**Example 3:**

```
Input: n = 4
Output: true
Explanation: n is already a perfect square, Alice can win with one move, removing 4 stones (4 -> 0).
```

**Constraints**

- 1 <= n <= 105

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

这是一类**博弈**（Game Theory）题目：两个人轮流从同一个石子堆里取走 **任意非零的完全平方数**（1、4、9、16 …），取不到石子的人输。  
把每一种剩余石子数看作一个**状态**，我们想知道在该状态下轮到谁会赢。

最直接的想法是**枚举所有可能的取法**，把每一步的结果都递归下去：

1. 对当前的 `n`，尝试所有 `i*i ≤ n`（即所有合法的平方数）  
2. 取走 `i*i` 之后，轮到对手，问题变成“**对手在 `n - i*i` 这个状态能否赢**”。  
3. 如果存在一种取法，使得对手在剩下的石子数上**必输**（即递归返回 `False`），那么当前玩家必胜，返回 `True`。  
4. 否则所有取法都让对手必胜，当前玩家必输，返回 `False`。

> **类比**：把「哈希表」想成一本字典，`key` 是石子数，`value` 是这个状态是「赢」还是「输」。我们把每一次递归的结果记下来，后面再遇到同样的石子数时直接查表，而不必再重复计算。

这就是**暴力递归 + 记忆化**（Memoization）的思路。

#### 代码（Python）

```python
import math
from functools import lru_cache   # 用装饰器实现记忆化

def winnerSquareGame_bruteforce(n: int) -> bool:
    """暴力递归 + 记忆化，返回 Alice 是否能在 n 石子时先手必胜"""

    @lru_cache(maxsize=None)               # 把函数调用结果缓存起来，key 是 n
    def can_win(remain: int) -> bool:
        # 基础情况：没有石子可取，当前玩家输
        if remain == 0:
            return False

        # 枚举所有合法的平方数
        max_root = int(math.isqrt(remain))   # math.isqrt 返回 floor(sqrt(remain))
        for i in range(1, max_root + 1):
            sq = i * i
            # 如果取走 sq 之后，对手必输（can_win 返回 False），则当前玩家必胜
            if not can_win(remain - sq):
                return True                 # 找到一个必胜的取法，直接返回

        # 所有取法都让对手必胜，当前玩家必输
        return False

    return can_win(n)
```

#### 复杂度

- **时间复杂度**：`O(n * sqrt(n))`  
  - 对每个 `remain`（最多 `n` 种），我们要枚举至多 `√remain` 个平方数。  
  - 大白话：如果 `n = 10⁵`，`√n ≈ 316`，所以最坏情况下大约要做 `10⁵ × 316 ≈ 3.2×10⁷` 次检查，能跑完但不够快。

- **空间复杂度**：`O(n)`  
  - 记忆化表（`lru_cache`）保存了 `0 … n` 的结果，每个占用常数空间。  
  - 递归调用栈深度最多 `n`（在最糟糕的只取 1 的情况下），同样是 `O(n)`。

### 2. 最优解

#### 思路  

暴力解的**瓶颈**在于我们对每个 `remain` 都要重新遍历所有可能的平方数，导致 `O(n·√n)` 的时间。  
事实上，这已经是**最优的**时间复杂度了，因为每个状态必须检查所有合法的动作才能判断「赢」或「输」。我们只需要把 **递归改写成迭代 DP**，避免递归调用的额外开销，并且用**一维数组**直接保存状态。

**动态规划（DP）**的核心思想：

- `dp[i] = True` 表示当剩余石子数为 `i` 时，先手（轮到当前玩家）**必胜**；否则 `False` 表示必输。
- 初始状态 `dp[0] = False`（没有石子，当前玩家输）。
- 对每个 `i`（从 `1` 到 `n`），枚举所有合法的平方数 `sq ≤ i`：
  - 如果 `dp[i - sq]` 为 `False`，说明取走 `sq` 后对手进入必输局面，当前玩家就能赢，`dp[i] = True`，并 **立即停止** 继续枚举（因为已经找到必胜取法）。
- 若所有 `sq` 都没有让对手必输，则 `dp[i] = False`。

> **类比**：把 `dp` 想成一本“输赢手册”，每翻到第 `i` 页，就能直接看到在 `i` 石子时先手是赢还是输。我们一次性把这本手册写完（自底向上），以后查询时只要翻页即可。

**为什么 DP 正确？**  
假设我们已经正确算出了所有小于 `i` 的状态。对于 `i`：

- 若存在一个合法的 `sq` 使得 `dp[i - sq] = False`，则先手可以把石子数变成 `i - sq`，把局面交给对手，而对手在 `i - sq` 时必输，故先手必胜。
- 若所有 `sq` 对应的 `dp[i - sq]` 都是 `True`，说明无论先手怎么取，都只能把局面交给一个必胜的对手，自己必输。

这正是 **“赢 = 能把对手逼入输的状态”** 的博弈递推公式。

#### 代码（Python）

```python
import math

def winnerSquareGame(n: int) -> bool:
    """DP 版本，返回 Alice 是否能在 n 石子时先手必胜"""

    # dp[i] 为 True 表示先手在 i 石子时必胜，False 表示必输
    dp = [False] * (n + 1)   # dp[0] 已经是 False，表示没有石子时先手输

    for i in range(1, n + 1):
        # 只要找到一种取法让对手进入必输局面，就可以把 dp[i] 标记为 True
        max_root = int(math.isqrt(i))          # i 的最大合法平方根
        for j in range(1, max_root + 1):
            sq = j * j
            if not dp[i - sq]:                 # 对手在 (i - sq) 时必输
                dp[i] = True
                break                          # 已经找到必胜取法，停止枚举

        # 若循环结束仍未把 dp[i] 设为 True，默认保持 False（必输）

    return dp[n]
```

#### 复杂度

- **时间复杂度**：`O(n·√n)`  
  - 与暴力递归的渐进复杂度相同，但这里是**纯循环**，常数更小，实际运行更快。  
  - 大白话：对每个 `i`（最多 `10⁵`），最多检查 `√i`（约 316）次，总共约 `3.2×10⁷` 次比较，轻松跑在 0.1~0.2 秒内（取决于机器）。

- **空间复杂度**：`O(n)`  
  - 只需要一个长度为 `n+1` 的布尔数组保存所有状态。  
  - 与递归版的记忆化表相比，省去了递归栈的额外空间。

## 心得

- **核心技巧**：**博弈状态 DP** —— “赢的状态 = 能让对手进入必输状态”。  
- **适用的题型**（类似思路）  
  1. **Stone Game III**（每次可取 1~3 个数）  
  2. **Take-Away Game**（取任意 ≤ k 的石子）  
  3. **Coin Game**（取硬币价值的子集）  
- **一句话总结解题钥匙**：**把“先手必胜”转化为“是否能把对手逼进必输”并用 DP 逐步填表**。

## 反思

- **第一反应**：看到“取平方数”，立刻想到**递归枚举所有取法**，因为这类“取子集”游戏往往可以用“赢/输”递推。
- **最容易踩的坑**  
  1. **忘记处理 `n = 0` 的基准情况**（没有石子时当前玩家直接输）。  
  2. **枚举平方数时上界错误**：必须使用 `int(math.isqrt(i))` 而不是 `int(i**0.5)`，后者在大数时可能产生浮点误差。  
  3. **没有提前 `break`**：一旦找到必胜取法，仍继续循环会浪费时间。  
- **下次遇到同类题的第一步**：先**确定基准状态**（`dp[0]`），然后**写出“赢 = 能把对手逼入输”**的递推式，再决定是递归记忆化还是自底向上 DP。
