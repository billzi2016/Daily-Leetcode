# #1287. 有序数组中出现超过 25% 的元素 / Element Appearing More Than 25% In Sorted Array

> 难度：简单 · 标签：Array · [LeetCode 链接](https://leetcode.com/problems/element-appearing-more-than-25-in-sorted-array/)

---

## 题目（英文原版）

**Description**

Given an integer array sorted in non-decreasing order, there is exactly one integer in the array that occurs more than 25% of the time, return that integer.

**Examples**

**Example 1:**

```
Input: arr = [1,2,2,6,6,6,6,7,10]
Output: 6
```

**Example 2:**

```
Input: arr = [1,1]
Output: 1
```

**Constraints**

- 1 <= arr.length <= 104
- 0 <= arr[i] <= 105

---

## 题目（中文翻译）

给定一个按非递减顺序（non‑decreasing order）排序的整数数组，其中恰好有一个整数在数组中出现的次数超过 25%（即出现次数 > 0.25·n），返回该整数。  

示例 1:  
Input: arr = [1,2,2,6,6,6,6,7,10]  
Output: 6  

示例 2:  
Input: arr = [1,1]  
Output: 1  

约束条件：  
- 1 ≤ arr.length ≤ 10⁴  
- 0 ≤ arr[i] ≤ 10⁵

---

## 解题过程

### 1. 直觉解（暴力）

#### 思路  
最直接的想法是把数组里每个数出现的次数全部统计出来，出现次数最多的那个一定就是「出现超过 25%」的元素。  
- **用到的数据结构**：`dict`（也叫哈希表），可以把它想象成一本**查字典**：单词是键（这里是数组中的数字），对应的页码是值（这里是出现次数）。查一次字典的时间几乎是 **O(1)**，所以统计过程非常快。  
- **为什么正确**：题目保证恰好有一个数字出现次数 > 数组长度的 25%。统计完所有数字的出现次数后，只要找出出现次数最大的那个，就一定是答案。  

#### 代码（Python）  
```python
from typing import List

def findSpecialInteger_bruteforce(arr: List[int]) -> int:
    # 用字典统计每个数字出现的次数
    freq = {}                     # 键：数字，值：出现次数
    for num in arr:               # 遍历数组，每个元素 O(1) 插入/更新字典
        freq[num] = freq.get(num, 0) + 1

    # 找出出现次数最多的那个数字
    # 由于题目保证只有一个满足条件，这里直接返回最大值对应的键
    max_num = max(freq, key=freq.get)   # O(k)，k 为不同数字的种类数
    return max_num
```

#### 复杂度
- **时间复杂度**：`O(n)`  
  解释：我们只遍历一次数组（`n` 是数组长度），每次操作都是常数时间，所以整体是线性时间。  
- **空间复杂度**：`O(k)`（最坏情况 `O(n)`）  
  解释：需要额外的哈希表来保存每个不同数字的计数。若数组里全是不同的数字，哈希表的大小会和数组一样大。

---

### 2. 最优解

#### 思路  
暴力解已经是 `O(n)`，已经很快了，但我们可以利用**数组已排好序**的特性，把空间降到 `O(1)`（不使用额外的哈希表），甚至在最坏情况下仍保持 `O(n)` 的时间。思路如下：

1. **观察**：因为数组是非递减排序的，出现次数超过 25% 的元素一定会跨越 **一个区间的边界**。  
   - 把数组等分成四段：  
     ```
     [0 … n/4)   [n/4 … n/2)   [n/2 … 3n/4)   [3n/4 … n)
     ```  
   - 若某个数字出现次数 > 25%，它至少会出现在这四段中的 **两个端点**（例如左端点或右端点），因为每段的长度正好是总长度的 25%。  
2. **利用端点**：只需要检查这四个位置的数字（`arr[0]、arr[n//4]、arr[n//2]、arr[3*n//4]`），它们中一定有一个是答案。  
3. **计数方式**：对每个候选数字，用二分查找（`bisect_left`、`bisect_right`）找出它在数组中出现的左边界和右边界，从而得到出现次数。二分查找的时间是 `O(log n)`，检查 4 次总共是 `O(log n)`。  
4. **返回**：只要出现次数 > n/4，即可返回该数字。

> **为什么只检查 4 个位置就够了？**  
> 想象把数组画成一条线，长度为 `n`。如果某个数字占据的区间长度超过 `n/4`，那么它的区间一定会覆盖至少一个“分界点”。这四个分界点正好是我们等分后的端点。

#### 代码（Python）  
```python
import bisect
from typing import List

def findSpecialInteger_optimal(arr: List[int]) -> int:
    n = len(arr)
    # 可能的答案只有这四个位置的数字
    candidates = {arr[0], arr[n // 4], arr[n // 2], arr[(3 * n) // 4]}

    for x in candidates:                     # 最多检查 4 次
        # bisect_left 返回第一个 >= x 的下标
        left = bisect.bisect_left(arr, x)    # O(log n)
        # bisect_right 返回第一个 > x 的下标
        right = bisect.bisect_right(arr, x)  # O(log n)
        if right - left > n // 4:            # 出现次数超过 25%
            return x
    # 题目保证一定有答案，理论上不会走到这里
    raise ValueError("No element appears more than 25%")
```

#### 复杂度
- **时间复杂度**：`O(log n)`  
  解释：我们只对最多 4 个候选数字进行二分查找，每次 `O(log n)`，所以整体是对数时间。相比暴力的 `O(n)`，在大数据量时更快。  
- **空间复杂度**：`O(1)`（不计入输入数组本身）  
  解释：只用了常数个额外变量和一个最多装 4 个元素的集合，空间开销几乎为零。

## 心得

- **核心技巧**：利用数组已排序的特性，把“出现次数 > 25%”转化为“跨越分界点”，再配合二分查找快速统计出现次数。  
- **适用的题型**：  
  1. “出现次数超过 ⌈n/k⌉ 的元素”（如 33% → k=3、20% → k=5）  
  2. “找出数组中出现次数最多的元素”但数组已排序的情况  
  3. “多数元素（出现次数 > n/2）”的变形  
- **一句话总结**：**“排序 + 分段端点 + 二分计数”** 是解这类“出现次数阈值”题目的钥匙。

---

## 反思

- **第一反应**：直接用哈希表统计出现次数，想到“遍历一次，计数”。  
- **最容易踩的坑**：  
  - 忘记数组是 **非递减**（可能有相等的相邻元素），直接用 `arr[i] != arr[i-1]` 判断会漏掉连续相同的情况。  
  - 边界条件：`n` 可能很小（如 1 或 2），使用 `n // 4` 时要确保索引合法（在 Python 中整数除法会向下取整，索引仍在范围内）。  
- **下次类似题的第一步**：先问自己“数组是否有序”。如果有序，尝试用 **分段/二分** 的思路把问题的搜索空间压缩到常数级，再用 **二分计数** 验证。这样往往能把时间从线性降到对数。
