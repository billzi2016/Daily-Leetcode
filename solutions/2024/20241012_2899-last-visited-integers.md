# #2899. 最后访问的整数 / Last Visited Integers

> 难度：简单 · 标签：Array、Simulation · [LeetCode 链接](https://leetcode.com/problems/last-visited-integers/)

## 题目（英文原版）

**Description**

Given an integer array nums where nums[i] is either a positive integer or -1. We need to find for each -1 the respective positive integer, which we call the last visited integer.
To achieve this goal, let's define two empty arrays: seen and ans.
Start iterating from the beginning of the array nums.
Return the array ans.

**Examples**

**Example 1:**

```
Input: nums = [1,2,-1,-1,-1]
Output: [2,1,-1]
Explanation:
Start with seen = [] and ans = [] .
```

**Example 2:**

```
Input: nums = [1,-1,2,-1,-1]
Output: [1,2,1]
Explanation:
Start with seen = [] and ans = [] .
```

**Constraints**

- 1 <= nums.length <= 100
- nums[i] == -1 or 1 <= nums[i] <= 100

## 题目（中文翻译）

给定一个整数数组 `nums`，其中 `nums[i]` 要么是正整数，要么是 `-1`。我们需要为数组中每个 `-1` 找到其对应的正整数，称为**最后访问的整数**（last visited integer）。

为实现该目标，定义两个空数组：`seen` 和 `ans`。  
从数组 `nums` 的起始位置开始遍历。  
遍历结束后返回数组 `ans`。

从 `seen = []` 和 `ans = []` 开始。

### 示例 2

**输出**: `[1,2,1]`

从 `seen = []` 和 `ans = []` 开始。

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  

最直接的想法是：**每遇到一个 `-1`，就在它左边往前找最近的正整数**，把找到的那个数记到答案里。  
如果左边已经没有正整数了，就把 `-1` 本身记到答案里。  

> - **数据结构**：这里我们只需要一个普通的列表（相当于生活中的「记事本」），用来顺序存放答案 `ans`。  
> - **为什么正确**：题目要求「最后访问的整数」——也就是在当前 `-1` 之前最近出现的正整数。直接往左搜索一定能找到它（如果存在的话），所以答案一定正确。  

#### 代码（Python）  

```python
def last_visited_bruteforce(nums):
    """
    暴力解法：对每个 -1，向左线性搜索最近的正整数。
    """
    ans = []                     # 用来保存每个 -1 对应的结果
    for i, v in enumerate(nums):
        if v == -1:              # 只在遇到 -1 时处理
            found = -1           # 默认答案是 -1（表示左边没有正整数）
            # 从当前位置 i 往左遍历，寻找最近的正整数
            for j in range(i - 1, -1, -1):
                if nums[j] != -1:    # 找到正整数
                    found = nums[j]  # 记录下来
                    break            # 找到后立刻停止搜索
            ans.append(found)        # 把结果放进 ans
    return ans
```

#### 复杂度  

- **时间复杂度**：`O(n²)`  
  - 解释：最坏情况下数组全是 `-1`，每个 `-1` 都要向左遍历整个数组，导致二次遍历。把 `n²` 想象成「如果有 100 个元素，需要检查 10,000 次」。
- **空间复杂度**：`O(1)`（不计答案数组）  
  - 解释：只用了常数级别的额外变量 `found`、`i`、`j`，不随输入规模增长。

### 2. 最优解  

#### 思路  

从暴力解可以看出，**我们每次都在重复做同样的左侧搜索**，这就是瓶颈所在。  
如果把「左侧最近的正整数」的状态保存下来，就不必每次重新遍历。  

**核心技巧：栈（Stack）**  
- 栈是一种「后进先出」的数据结构，最上面的元素就是最近加入的元素，正好对应「最近的正整数」的概念。  
- 当遍历到正整数时，把它 **压入栈**（想象成把这本书放到桌子最上面）。  
- 当遍历到 `-1` 时，**弹出栈顶**（把最上面的书拿下来），这就是「最后访问的整数」。  
- 如果栈为空，说明左边没有正整数，答案记 `-1`。  

这样每个元素只会被压栈或弹栈一次，整个过程只需要线性时间。

> **类比**：栈就像一叠盘子，最新放上的盘子在最上面，想要取出「最近的盘子」只需要直接把最上面的拿走，而不必去翻找下面的。

#### 代码（Python）  

```python
def last_visited_optimal(nums):
    """
    最优解：使用栈（list 当作栈）一次遍历完成。
    """
    seen = []          # 栈，保存尚未被 -1 “消费” 的正整数
    ans = []           # 最终答案，记录每个 -1 对应的结果

    for v in nums:
        if v != -1:                # 正整数 → 入栈
            seen.append(v)
        else:                      # -1 → 出栈（如果可能）
            if seen:               # 栈非空 → 弹出栈顶作为答案
                ans.append(seen.pop())
            else:                  # 栈空 → 左侧没有正整数，答案为 -1
                ans.append(-1)
    return ans
```

#### 复杂度  

- **时间复杂度**：`O(n)`  
  - 解释：每个元素只会被处理一次（入栈或出栈），相当于「一次遍历」完成所有工作。  
- **空间复杂度**：`O(n)`（最坏情况下全部正整数都压在栈里）  
  - 解释：栈的大小取决于正整数的数量，最多会和输入长度相同。

## 心得  

- **核心技巧**：利用栈（后进先出）快速获取「最近出现」的元素。  
- **适用的题型**：  
  1. 需要找「左侧最近」或「右侧最近」满足某条件的元素（如「最近更大元素」）。  
  2. 括号匹配、逆波兰表达式求值等需要「配对」的场景。  
- **一句话总结**：**用栈把「最近」的状态保存下来，省去重复搜索**。

## 反思  

- **第一反应**：看到「最后访问的整数」就想到「向左找最近的正整数」，于是写了暴力的双层循环。  
- **最容易踩的坑**：  
  - 忘记在栈为空时返回 `-1`，会导致运行时错误。  
  - 把正整数压入 `ans` 而不是压入 `seen`，导致答案顺序错误。  
- **下次遇到同类题**：第一步先问自己「最近的元素」是否可以用「栈」来保存，若可以就直接走「入栈 / 出栈」的思路。
