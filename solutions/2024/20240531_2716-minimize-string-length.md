## 解题过程

### 1. 直觉解（暴力）

#### 思路  
最直接的想法是 **模拟题目所说的“删除操作”**，直到字符串里不再出现相同的字符为止。  
我们可以把字符串当成一排字符的“队伍”。遍历这排队伍，每次找出两个相同的字符，把它们从队伍中“踢走”。  
- **数据结构**：这里直接使用 Python 的 `list`（字符数组）来存放当前的字符序列。把它想象成一张可以随时撕掉字符的纸，`list.pop(i)` 就像在纸上用剪刀把第 `i` 位的字符剪掉。
- **为什么正确**：只要我们每次都把**任意两相同的字符**删掉，最终剩下的字符必然都是互不相同的（因为相同的已经被配对删光了），这正是题目要求的“最小化后不含重复字符”。  
- **复杂度分析**：  
  - 外层循环要遍历每个字符，内层循环要再找一遍后面的字符来配对，最坏情况会出现 `n` 次外层 * `n` 次内层的比较，时间复杂度是 **O(n²)**。  
  - 我们把字符都放在 `list` 中，额外占用的空间与原字符串长度相同，空间复杂度是 **O(n)**。  
  > 这里的 `O(n²)` 可以理解为：如果字符串长 100，最多要比较 100 × 100 = 10 000 次；如果长 1000，则要比较 1 000 000 次，随长度的增长，耗时会“指数”增长。

#### 代码（Python）

```python
def minLength_bruteforce(s: str) -> int:
    # 把字符串转成列表，方便原地删除字符
    chars = list(s)                     # ['a', 'a', 'b', ...]
    i = 0                               # 从左到右遍历
    while i < len(chars):
        j = i + 1                       # 在 i 右侧找相同的字符
        found = False
        while j < len(chars):
            if chars[i] == chars[j]:    # 找到一对相同字符
                # 删除后面的字符，先删后面的再删前面的，避免索引错位
                chars.pop(j)            # 删除位置 j 的字符
                chars.pop(i)            # 删除位置 i 的字符
                found = True
                break                   # 重新从头开始检查
            j += 1
        if not found:                   # 没有配对成功，检查下一个字符
            i += 1
    # 循环结束时，chars 中已经没有重复字符
    return len(chars)
```

#### 复杂度

- **时间复杂度**：`O(n²)`  
  > 每次删除都要重新遍历剩余字符，最坏会出现 `n` 次外层循环 × `n` 次内层循环的比较。

- **空间复杂度**：`O(n)`  
  > 需要额外的列表来存放字符，大小和原字符串相同。

### 2. 最优解

#### 思路  
从暴力解可以看到 **瓶颈在于反复遍历寻找配对**。实际上，我们并不需要真的去“删”。  
题目只要求 **返回最小化后字符串的长度**，而最小化的结果恰好是“所有不同字符的集合”。  
因此，只要统计原字符串里出现了多少种不同的字符即可。  

- **关键数据结构**：**哈希表（Python 中的 `set`）**。  
  - 类比：`set` 就像一本“字典”，每翻一页（即插入一个字符）只会记下这个字符第一次出现的页码，后面再出现的同样字符会被直接忽略，不会占用新页。这样，`set` 的大小就等于不同字符的数量。  
- **步骤**：  
  1. 创建一个空的 `set`。  
  2. 遍历字符串中的每个字符，把它加入 `set`（加入已经存在的字符不会改变 `set` 的大小）。  
  3. 最后 `set` 的大小就是最小化后字符串的长度。  

- **为什么正确**：  
  - 题目提示：“最小化的字符串不含重复字符，且包含原字符串的所有不同字符”。这正好对应 **“把所有不同字符收集起来”** 的概念。  
  - `set` 自动去重，保证每种字符只计一次，故 `len(set)` 正是答案。

- **复杂度对比**：  
  - 只需要一次遍历，时间复杂度降到 **O(n)**，即线性时间。  
  - `set` 只存放每种字符一次，最多 26（小写字母）个元素，空间复杂度是 **O(1)**（常数空间），因为字符种类上限固定。

#### 代码（Python）

```python
def minLength_optimal(s: str) -> int:
    # 使用 set 自动去重，统计不同字符的数量
    distinct_chars = set()          # 空集合，类似“字典的空页”
    for ch in s:                    # 遍历每个字符
        distinct_chars.add(ch)      # 把字符加入集合，重复的会被忽略
    return len(distinct_chars)      # 集合的大小就是答案
```

#### 复杂度

- **时间复杂度**：`O(n)` — 只需一次遍历，每个字符的加入操作均摊为常数时间。  
  > 对于长度 100 的字符串，只会检查 100 次；长度 10⁶ 时，只会检查 10⁶ 次，随长度线性增长。

- **空间复杂度**：`O(1)` — 最多只存 26 个小写字母，空间不随输入规模增长（常数级别）。

## 心得

- **核心技巧**：使用 **哈希集合（set）去重**，把“去重后剩余的字符数量”直接当作答案。  
- **适用的题型**：  
  1. “统计不同字符/数字的个数” 类题（如 *"Number of Unique Characters of All Substrings"*）。  
  2. “判断是否可以消除所有重复” 类题（如 *"Make The String Great"*，需要去除相邻相同字符）。  
  3. “最小化/最大化后只保留唯一元素” 的场景（如 *"Longest Substring Without Repeating Characters"* 的变形）。  
- **一句话总结解题钥匙**：**把“最小化后不含重复”转化为“统计不同字符的种类”。**

---

## 反思

- **第一反应**：看到“删除相同字符”，下意识想要模拟删除过程（即暴力解）。  
- **最容易踩的坑**：  
  - 忘记题目只要求返回长度，而不是实际构造最小化后的字符串。  
  - 错误地认为需要考虑字符出现的顺序或具体删除顺序，导致实现复杂。  
  - 对字符集范围不熟悉，误以为需要 O(n) 空间；实际上字符只限小写英文字母，空间可以视为常数。  
- **下次遇到同类题**：第一步先思考 **“答案是否只和出现的种类有关”**，如果是，就立刻考虑 **集合/哈希表去重**，避免不必要的模拟操作。
