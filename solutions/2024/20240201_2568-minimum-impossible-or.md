# #2568. 最小不可实现的 OR / Minimum Impossible OR

> 难度：中等 · 标签：Array、Bit Manipulation、Brainteaser · [LeetCode 链接](https://leetcode.com/problems/minimum-impossible-or/)

---

## 题目（英文原版）

**Description**

You are given a 0-indexed integer array nums.
We say that an integer x is expressible from nums if there exist some integers 0 <= index1 < index2 < ... < indexk < nums.length for which nums[index1] | nums[index2] | ... | nums[indexk] = x. In other words, an integer is expressible if it can be written as the bitwise OR of some subsequence of nums.
Return the minimum positive non-zero integer that is not expressible from nums.

**Examples**

**Example 1:**

```
Input: nums = [2,1]
Output: 4
Explanation: 1 and 2 are already present in the array. We know that 3 is expressible, since nums[0] | nums[1] = 2 | 1 = 3. Since 4 is not expressible, we return 4.
```

**Example 2:**

```
Input: nums = [5,3,2]
Output: 1
Explanation: We can show that 1 is the smallest number that is not expressible.
```

**Constraints**

- 1 <= nums.length <= 105
- 1 <= nums[i] <= 109

## 题目（中文翻译）

给定一个下标从 **0** 开始的整数数组 `nums`。  

我们称整数 `x` **可表达的（expressible）**，如果存在一些整数下标 `0 <= index1 < index2 < ... < indexk < nums.length`，使得  

```
nums[index1] | nums[index2] | ... | nums[indexk] = x
```  

也就是说，若 `x` 能写成 `nums` 的某个子序列（subsequence）中元素的按位或（bitwise OR），则 `x` 为可表达的。  

返回 **最小的正整数（大于 0）**，该整数 **不可表达**（not expressible）于 `nums`。  

## 示例

### 示例 1  
**输入**  
```json
nums = [2,1]
```  
**输出**  
```
4
```  
**解释**  
`1` 与 `2` 已经出现在数组中。我们知道 `3` 是可表达的，因为 `nums[0] | nums[1] = 2 | 1 = 3`。由于 `4` 无法通过任意子序列的按位或得到，所以返回 `4`。  

### 示例 2  
**输入**  
```json
nums = [5,3,2]
```  
**输出**  
```
1
```  
**解释**  
可以证明 `1` 是最小的不可表达的正整数。  

## 约束条件
- `1 <= nums.length <= 10^5`
- `1 <= nums[i] <= 10^9`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**把所有子序列都枚举出来**，把每个子序列的位或（OR）结果记下来，然后从 1 开始往上找第一个没有出现过的数。

- **子序列**：把数组里的元素挑出来，保持原来的顺序，但可以跳过一些元素。比如 `[2,1]` 的子序列有 `[]、[2]、[1]、[2,1]` 四个。  
- **位或（OR）**：把两个数的二进制位对应相“或”，只要有一个 1，结果位就是 1。可以把它想象成 **“把两块拼图的亮灯合并”，只要有灯亮就亮”。  
- **把所有 OR 结果放进集合**：集合类似 **“字典”**，key 是出现过的数字，查找是否出现过是 O(1) 时间。

为什么这个方法能得到答案？  
因为我们把 **所有可能的 OR 结果** 都列出来了，只要找不到的最小正整数，就是题目要求的答案。

#### 代码（Python）

```python
from itertools import combinations

def min_impossible_or_bruteforce(nums):
    n = len(nums)
    reachable = set()                     # 用集合记录所有可以得到的数

    # 枚举子序列的长度 1~n（空子序列的 OR 为 0，题目要正整数，所以不计入）
    for k in range(1, n + 1):
        # combinations 会生成所有长度为 k 的下标组合
        for idxs in combinations(range(n), k):
            cur = 0
            for i in idxs:                # 把子序列里的数逐个 OR
                cur |= nums[i]
            reachable.add(cur)           # 记录得到的结果

    # 从 1 开始找第一个不在 reachable 中的数
    ans = 1
    while ans in reachable:
        ans += 1
    return ans
```

> **关键行中文注释**已经写在代码里，直接复制运行即可（不过只能用于 **非常小** 的数组，时间会爆炸）。

#### 复杂度  

- **时间复杂度**：`O(2^n)`  
  解释：子序列的数量是 `2^n`（每个元素选或不选），所以我们要遍历指数级多的组合，实际运行会在几秒钟内就卡死。  
- **空间复杂度**：`O(2^n)`（集合里可能存放所有不同的 OR 结果）

> 大白话：如果数组有 20 个数，`2^20 ≈ 1,000,000`，还能接受；但如果有 30 个数，`2^30 ≈ 1,000,000,000`，显然不可能在电脑里装下。

### 2. 最优解

#### 思路  

暴力解的瓶颈在 **“枚举所有子序列”**，这一步导致指数级的时间。  
要想快，就必须 **直接从位的角度思考**：  
- OR 操作只能把 **已有的 1 位打开**，不能创造新的 1 位。  
- 若我们想得到某个正整数 `x`，`x` 的每一位 `1` 必须在 **至少一个选中的元素里出现**。  
- 更重要的是，**选中的元素不能带入我们不想要的额外 1 位**，否则结果会比 `x` 多了位。

于是我们可以把 **“能否得到 x”** 转化为以下等价条件：

> 对于 `x` 中的每一个置位 `1`，**必须存在一个数组元素 `a`**，满足  
> 1. `a` 的最高位（最左边的 1）**不超过** `x` 的最高位。  
> 2. `a` 的所有 1 位都 **是** `x` 的子集（即 `a & ~x == 0`）。  

换句话说，**我们只能使用“只含有目标位集合的数”** 来拼出 `x`。  

现在考虑最小的正整数：  
- 当 `x = 1`（二进制 `...0001`）时，唯一满足条件的元素只能是 `1` 本身。  
- 当 `x = 2`（二进制 `...0010`）时，唯一满足条件的元素只能是 `2` 本身。  
- 当 `x = 4`（二进制 `...0100`）时，唯一满足条件的元素只能是 `4` 本身。  

**结论**：**要得到 2^k（只含一个 1 位的数），数组里必须恰好出现这个数**。如果缺少某个 `2^k`，我们根本没有办法只打开这一个位而不打开别的位，于是 `2^k` 就是最小的不可达数。

因此答案就是 **数组中缺失的最小的 2 的幂**。

实现步骤：

1. 把所有出现的 **2 的幂** 收集到集合 `powers`（判断一个数是不是 2 的幂，只需要 `num & (num-1) == 0`）。  
2. 从 `2^0 = 1` 开始依次检查 `1, 2, 4, 8, …`，第一个不在 `powers` 里的就是答案。  
3. 由于 `nums[i] ≤ 10^9 < 2^30`，最多检查到 `2^30`（约 `1.07e9`），循环次数至多 31 次，几乎可以忽略不计。

#### 代码（Python）

```python
def min_impossible_or(nums):
    """
    返回最小的正整数，使得它不能表示为 nums 任意子序列的按位或。
    思路：答案一定是最小缺失的 2 的幂。
    """
    powers = set()                     # 用集合记录出现过的 2 的幂

    for v in nums:
        # 判断 v 是否是 2 的幂：二进制中恰好只有一个 1
        # 例如 8 -> 1000，8 & (8-1) = 0
        if v & (v - 1) == 0:           # 这里的 v 必须大于 0，题目保证
            powers.add(v)

    ans = 1                            # 从 2^0 开始检查
    while ans in powers:              # 如果当前幂已经出现，继续往上找
        ans <<= 1                     # 等价于 ans *= 2，左移一位得到下一个 2 的幂
    return ans
```

> **代码要点**  
> - `v & (v-1) == 0` 是判断“是否只有一个 1 位”的经典技巧，类似 **“查字典”**：只要满足条件就把它记进集合。  
> - `ans <<= 1` 用位左移实现乘以 2，既简洁又快。  

#### 复杂度  

- **时间复杂度**：`O(n)`  
  - 只遍历一次数组，把 2 的幂收集进集合。  
  - 再检查至多 31 次（因为 `2^30 > 10^9`），常数级别。  
  - 与暴力解的指数级相比，**快得多**。  

- **空间复杂度**：`O(k)`，`k` 为出现过的 2 的幂的个数，最多 31，几乎可以视作 `O(1)`（常数空间）。

> 对比：暴力解需要指数级时间和空间，最优解只用线性时间、常数空间，轻松应对 10⁵ 长度的数组。

## 心得

- **核心技巧**：**“最小不可达数一定是缺失的 2 的幂”**。  
- 该技巧适用于 **位运算类的可达性/组合** 题目，例如  
  1. *“最小不可达的子集和”*（利用前缀和的贪心思路）  
  2. *“最小不能表示的 XOR 值”*（利用线性基）  
- **一句话总结**：只要目标数只有一个 1 位，必须在原数组里出现完全相同的数，否则它永远不可达。

## 反思

- **第一反应**：直接枚举所有子序列，计算 OR，找缺失的最小数。  
- **最容易踩的坑**  
  - **误以为只要每个位出现过就能组合**，忽略了“额外位”会被带进来。  
  - **边界条件**：数组中没有任何 2 的幂时，答案应是 `1`（最小的 2 的幂）。  
  - **整数溢出**：在语言里左移时要确保不会超过整数上限（Python 没问题）。  
- **下次遇到同类题**，第一步应该问自己：“**目标数的二进制形态是什么**”，特别是“只有单一 1 位”时，**它必须原样出现**，于是转向 **集合/哈希** 的线性扫描即可。
