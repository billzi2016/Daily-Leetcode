# #2544. 交替数字和 / Alternating Digit Sum

> 难度：简单 · 标签：Math · [LeetCode 链接](https://leetcode.com/problems/alternating-digit-sum/)

---

## 题目（英文原版）

**Description**

You are given a positive integer n. Each digit of n has a sign according to the following rules:
Return the sum of all digits with their corresponding sign.

**Examples**

**Example 1:**

```
Input: n = 521
Output: 4
Explanation: (+5) + (-2) + (+1) = 4.
```

**Example 2:**

```
Input: n = 111
Output: 1
Explanation: (+1) + (-1) + (+1) = 1.
```

**Example 3:**

```
Input: n = 886996
Output: 0
Explanation: (+8) + (-8) + (+6) + (-9) + (+9) + (-6) = 0.
```

**Constraints**

- 1 <= n <= 109

---

## 题目（中文翻译）

**题目描述**  
给定一个正整数 `n`。`n` 的每一位数字按照以下规则分配符号：从最高位开始，符号依次为正（`+`）、负（`-`）、正、负……  
返回所有数字按其对应符号加和后的结果。

**示例**

> 示例 1  
> 输入: `n = 521`  
> 输出: `4`  
> 解释: `(+5) + (-2) + (+1) = 4`.

> 示例 2  
> 输入: `n = 111`  
> 输出: `1`  
> 解释: `(+1) + (-1) + (+1) = 1`.

> 示例 3  
> 输入: `n = 886996`  
> 输出: `0`  
> 解释: `(+8) + (-8) + (+6) + (-9) + (+9) + (-6) = 0`.

**约束条件**  
- `1 <= n <= 10^9`

---

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是**把整数的每一位都取出来**，按照“奇数位加、偶数位减”的规则累加。  
- **取位**：把整数 `n` 转成字符串，遍历字符即可得到每一位数字（就像把一本书的每页文字读出来）。  
- **符号**：用一个变量 `sign` 记录当前位的符号，初始为 `+1`（正），每处理完一位后 `sign *= -1`，相当于在“正负”之间来回切换。  
- **累加**：`ans += sign * digit`，把带符号的数字加到答案中。

这种做法一定能得到正确答案，因为我们严格按照题目给出的“正负交替”规则遍历了所有位。

**时间/空间复杂度**  
- 时间复杂度：`O(d)`，`d` 是整数的位数。这里的 `O` 只是一种量级描述，表示**随着位数线性增长**，比如 3 位需要 3 步，10 位需要 10 步。  
- 空间复杂度：`O(d)`，因为把整数转成字符串后会占用 `d` 个字符的额外空间。

#### 代码（Python）

```python
def alternatingDigitSum_brute(n: int) -> int:
    """
    暴力解：把整数转成字符串逐位处理
    """
    ans = 0          # 最终答案
    sign = 1         # 当前位的符号，先从正号开始

    for ch in str(n):               # 把整数变成字符数组，逐个遍历
        digit = int(ch)             # 把字符转回数字
        ans += sign * digit         # 加上带符号的数字
        sign *= -1                  # 符号翻转，正变负，负变正

    return ans
```

#### 复杂度

- **时间复杂度**：`O(d)` —— 随着数字位数线性增加，遍历一次即可得到答案。  
- **空间复杂度**：`O(d)` —— 需要把整数存成字符串，占用与位数等价的空间。

---

### 2. 最优解

#### 思路  

虽然上面的“暴力”已经是线性时间，但我们可以**省掉把整数转成字符串的额外空间**，直接用数学运算一次遍历每一位。  
- **取最低位**：`n % 10` 得到最右边的数字（就像从右往左数数）。  
- **去掉最低位**：`n //= 10` 把已经处理的位删除，准备处理下一位。  
- **符号控制**：同样使用 `sign`，每处理一位后 `sign *= -1`。  
- **累计**：`ans += sign * digit`。

这样只使用 **常数级的额外空间**（几个整数变量），时间仍是 `O(d)`，但更“轻量”。  

**为什么会更好**  
- **省空间**：不需要额外的字符数组，空间从 `O(d)` 降到 `O(1)`（常数）。  
- **更贴近机器**：直接用整数除法和取模，计算机本身就擅长这类操作。

#### 代码（Python）

```python
def alternatingDigitSum_optimal(n: int) -> int:
    """
    最优解：不使用额外的字符串，直接用整数运算遍历每一位
    """
    ans = 0          # 最终答案
    sign = 1         # 当前位的符号，先正后负交替

    while n > 0:                     # 当还有未处理的位时循环
        digit = n % 10               # 取最右边一位数字
        ans += sign * digit          # 加上带符号的数字
        sign *= -1                   # 翻转符号
        n //= 10                     # 删除已经处理的最低位

    return ans
```

#### 复杂度

- **时间复杂度**：`O(d)` —— 仍然是遍历每一位，只是没有字符串转换的开销。  
- **空间复杂度**：`O(1)` —— 只使用了 `ans、sign、digit、n` 四个整数变量，空间固定不随位数增长。

## 心得

- 这道题的核心技巧是**按位遍历整数**并**交替使用符号**。  
- 类似的技巧常见于：  
  1. 判断一个整数是否为回文数（需要从两端同时取位）。  
  2. 计算整数各位数字之和的奇偶交替（如“奇数位求和，偶数位求和”）。  
- **一句话总结解题钥匙**：**“把整数拆成一位一位的数字，正负交替累加”。**

## 反思

- **第一反应**：把整数转成字符串，逐字符遍历，这样最直观。  
- **最容易踩的坑**：  
  - 忘记把 `sign` 初始化为正号，导致首位符号错误。  
  - 当 `n` 为 0 时（虽然题目限制 `n ≥ 1`），循环会直接结束，需要考虑返回 0。  
  - 使用 `while n:` 时一定要在循环内部更新 `n`（`n //= 10`），否则会陷入死循环。  
- **下次类似题的第一步**：**先决定是用字符串还是纯整数运算来逐位取值**，然后明确符号的交替规则，再写循环。
