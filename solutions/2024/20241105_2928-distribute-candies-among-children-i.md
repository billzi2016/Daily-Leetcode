# #2928. 分配糖果给孩子 I / Distribute Candies Among Children I

> 难度：简单 · 标签：Math、Combinatorics、Enumeration · [LeetCode 链接](https://leetcode.com/problems/distribute-candies-among-children-i/)

---

## 题目（英文原版）

**Description**

You are given two positive integers n and limit.
Return the total number of ways to distribute n candies among 3 children such that no child gets more than limit candies.

**Examples**

**Example 1:**

```
Input: n = 5, limit = 2
Output: 3
Explanation: There are 3 ways to distribute 5 candies such that no child gets more than 2 candies: (1, 2, 2), (2, 1, 2) and (2, 2, 1).
```

**Example 2:**

```
Input: n = 3, limit = 3
Output: 10
Explanation: There are 10 ways to distribute 3 candies such that no child gets more than 3 candies: (0, 0, 3), (0, 1, 2), (0, 2, 1), (0, 3, 0), (1, 0, 2), (1, 1, 1), (1, 2, 0), (2, 0, 1), (2, 1, 0) and (3, 0, 0).
```

**Constraints**

- 1 <= n <= 50
- 1 <= limit <= 50

## 题目（中文翻译）

给定两个正整数 `n` 和 `limit`。  
返回将 `n` 颗糖果分配给 **3** 个孩子的方案总数，要求 **没有** 任意一个孩子得到的糖果数超过 `limit`。

**示例 1**  
**输入**: `n = 5, limit = 2`  
**输出**: `3`  
**解释**: 有 3 种分配方式使得每个孩子最多得到 2 颗糖果：`(1, 2, 2)`, `(2, 1, 2)` 和 `(2, 2, 1)`。

**示例 2**  
**输入**: `n = 3, limit = 3`  
**输出**: `10`  
**解释**: 有 10 种分配方式使得每个孩子最多得到 3 颗糖果：`(0, 0, 3)`, `(0, 1, 2)`, `(0, 2, 1)`, `(0, 3, 0)`, `(1, 0, 2)`, `(1, 1, 1)`, `(1, 2, 0)`, `(2, 0, 1)`, `(2, 1, 0)` 和 `(3, 0, 0)`。

**约束条件**  
- `1 <= n <= 50`  
- `1 <= limit <= 50`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把「把 n 颗糖分给 3 个孩子」的所有可能都列举出来，然后把不符合「每个孩子最多 limit 颗」的情况剔除。  
这可以用 **三层循环** 完成：

1. 第一个循环枚举第一个孩子得到的糖数 `a`（0 ~ limit）  
2. 第二个循环枚举第二个孩子得到的糖数 `b`（0 ~ limit）  
3. 第三个循环枚举第三个孩子得到的糖数 `c`（0 ~ limit）  

每一次循环得到一组三元组 `(a, b, c)`，只要 `a + b + c == n` 就算作一种合法的分配方式。

> **类比**：把 `limit` 看成字典里每一页最多能写多少字，`a、b、c` 就是三页各自写的字数。我们把所有可能的写法（每页0~limit字）列出来，再挑出总字数恰好是 `n` 的那些。

这种做法一定能得到正确答案，因为我们遍历了**所有**可能的分配情况，只要满足约束就计数。

#### 代码（Python）

```python
def distributeCandies_bruteforce(n: int, limit: int) -> int:
    count = 0                     # 计数合法的分配方式
    # 枚举第一个孩子的糖数 a
    for a in range(limit + 1):
        # 枚举第二个孩子的糖数 b
        for b in range(limit + 1):
            # 第三个孩子的糖数可以直接算出来，减少一次循环
            c = n - a - b
            # c 必须在合法范围内（0~limit）才算合法
            if 0 <= c <= limit:
                count += 1
    return count
```

> **关键点说明**  
> - 第三层循环其实可以省掉，因为 `c = n - a - b` 已经唯一确定。这样时间从 `O(limit³)` 降到 `O(limit²)`，但仍属于“暴力”思路。  
> - `range(limit + 1)` 表示「包括 0」到「limit」这 `limit+1` 种可能。

#### 复杂度

- **时间复杂度**：`O(limit²)`  
  - 直观解释：我们把两个孩子的糖数每个都尝试 `limit+1` 次，总共约 `(limit+1)²` 次检查。比如 `limit=50` 时大约要检查 2600 次，完全可以接受。  
- **空间复杂度**：`O(1)`  
  - 只用了几个整数变量 `a、b、c、count`，不随输入规模增长而增加。

### 2. 最优解

#### 思路  

虽然上面的「两层循环」已经足够快，但我们仍可以用**数学公式**一次性算出答案，做到 **O(1)** 的时间复杂度。  
核心思路是「星星与横杠」(Stars and Bars) 计数方法，再结合「容斥原理」(Inclusion‑Exclusion) 处理「每个孩子最多 limit」的上界。

1. **不考虑上限**：  
   把 `n` 颗糖看成 `n` 颗星星，要把它们放进 3 个盒子（孩子），只要在星星之间插入 2 根分隔杠即可。  
   经典公式：把 `n` 颗星星分成 `k`（这里是 3）段的方法数是  
   \[
   \binom{n + k - 1}{k - 1}
   \]  
   对本题即 `C(n+2, 2)`。

2. **加入上限**：  
   上面的计数把「某个孩子可以拿到任意多」都算进来了。现在我们要排除「有孩子拿到 > limit」的情况。  
   使用容斥原理：  
   - 先减去「至少有一个孩子拿到 > limit」的计数。  
   - 再加回「两个孩子同时 > limit」的计数（因为上一步把它减了两次）。  
   - 再减去「三个孩子都 > limit」的计数（同理）。  

   对每一种「某些孩子超限」的情形，我们把它们先「先给每个超限的孩子预分配 limit+1 颗」糖，这样剩下的糖数就变成 `n' = n - t·(limit+1)`，其中 `t` 是超限孩子的数量。随后对剩余的 `n'` 颗糖进行普通的星星与横杠计数（因为此时已经保证这些超限孩子已经满足「> limit」的条件，剩下的孩子可以随意分配）。  

   公式化后得到：  

   \[
   \text{ans} = \sum_{t=0}^{3} (-1)^t \cdot \binom{3}{t} \cdot
                \binom{n - t\,(limit+1) + 2}{2}
   \]

   其中，当 `n - t·(limit+1) < 0` 时，组合数视为 0（因为糖已经不够分配了）。

3. **组合数实现**：  
   组合数 \(\binom{x}{2}\) 可以直接写成 `x*(x-1)//2`，只要 `x >= 2`。  
   为了安全，我们先判断 `x >= 0` 再计算。

这样就只需要遍历 `t = 0,1,2,3` 四次，时间是常数级。

> **类比**：  
> - 想象把每个孩子的「上限」当成「墙」。我们先把墙推开（给每个超限孩子多分配 limit+1 颗），再数所有不受墙约束的分配方式。最后用「加减」把墙的影响抵消回来。

#### 代码（Python）

```python
def distributeCandies_optimal(n: int, limit: int) -> int:
    """
    使用容斥原理 + Stars and Bars，时间 O(1)
    """
    def comb2(x: int) -> int:
        """计算 C(x, 2) = x*(x-1)//2，x<0 时返回 0"""
        if x < 0:
            return 0
        # C(x,2) 只在 x >= 2 时才有意义，x 为 0/1 时返回 0
        return x * (x - 1) // 2

    ans = 0
    # t 表示「有多少个孩子超过上限」
    for t in range(0, 4):          # 0、1、2、3 共四种可能
        remaining = n - t * (limit + 1)   # 给每个超限孩子先分配 limit+1 颗后剩余的糖
        # 如果剩余糖数为负，说明这种情况根本不可能，直接跳过
        if remaining < 0:
            continue
        # 把剩余的糖分给 3 个人（仍然是 3 个人，因为已经把超限孩子的“额外糖”算进去）
        ways = comb2(remaining + 2)   # C(remaining + 2, 2)
        # 加上符号 (-1)^t 并乘以选出 t 个孩子的方式数 C(3, t)
        ans += ((-1) ** t) * (1 if t == 0 else (3 if t == 1 else (3 if t == 2 else 1))) * ways
    return ans
```

> **关键行注释**  
> - `comb2` 把组合数的公式写成一行，避免引入 `math.comb`（在老版本 Python 中可能不可用）。  
> - `remaining = n - t * (limit + 1)` 把「先给超限的孩子多分配」这一步抽象为「把糖先扣掉」。  
> - `((-1) ** t)` 实现容斥原理的「加、减、加、减」交替符号。  
> - `C(3, t)`（即 1、3、3、1）表示从 3 个孩子中挑出 `t` 个超限的方式数。

#### 复杂度

- **时间复杂度**：`O(1)`（常数时间）  
  - 只循环 4 次，每次做常数次算术运算。相比暴力的 `O(limit²)`，即使 `limit=50`，这也是极快的。  
- **空间复杂度**：`O(1)`  
  - 只用了几个整数变量，和输入规模无关。

## 心得

- **核心技巧**：**容斥原理** + **Stars and Bars（星星与横杠）** 的组合计数。  
- **适用题型**（可再练习）  
  1. “把 n 件物品分给 k 个人，每人至多 limit 件”。  
  2. “在不超过上限的情况下统计非负整数解的个数”。  
  3. “限定每个变量上界的整数方程计数（如硬币找零、装箱问题）”。  
- **一句话总结解题钥匙**：先把「无限制」的计数算出来，再用容斥原理把「超过上限」的情况逐层剔除。

## 反思

- **第一反应**：看到「3 个孩子」和「不超过 limit」会直接想到三层循环遍历所有可能。  
- **最容易踩的坑**  
  - 忽略了 **0 颗糖** 也是合法的分配，需要让循环从 `0` 开始。  
  - 在容斥公式里忘记判断 `remaining < 0`，导致组合数出现负数或异常。  
  - 计算组合数时忘记除以 `2`，导致结果翻倍。  
- **下次遇到同类题**：第一步先判断「是否可以直接用星星与横杠计数」——如果有上界，就准备使用 **容斥原理** 把上界限制逐步剔除。这样可以从一开始就走向最优解，而不是先写暴力代码再改进。
