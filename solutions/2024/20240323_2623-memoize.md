# #2623. **记忆化函数** / Memoize

> 难度：中等 · 标签： · [LeetCode 链接](https://leetcode.com/problems/memoize/)

## 题目（英文原版）

**Description**

Given a function fn, return a memoized version of that function.
A memoized function is a function that will never be called twice with the same inputs. Instead it will return a cached value.
You can assume there are 3 possible input functions: sum, fib, and factorial.

**Examples**

**Example 1:**

```
Input:
fnName = "sum"
actions = ["call","call","getCallCount","call","getCallCount"]
values = [[2,2],[2,2],[],[1,2],[]]
Output: [4,4,1,3,2]
Explanation:
const sum = (a, b) => a + b;
const memoizedSum = memoize(sum);
memoizedSum(2, 2); // "call" - returns 4. sum() was called as (2, 2) was not seen before.
memoizedSum(2, 2); // "call" - returns 4. However sum() was not called because the same inputs were seen before.
// "getCallCount" - total call count: 1
memoizedSum(1, 2); // "call" - returns 3. sum() was called as (1, 2) was not seen before.
// "getCallCount" - total call count: 2
```

**Example 2:**

```
Input:
fnName = "factorial"
actions = ["call","call","call","getCallCount","call","getCallCount"]
values = [[2],[3],[2],[],[3],[]]
Output: [2,6,2,2,6,2]
Explanation:
const factorial = (n) => (n <= 1) ? 1 : (n * factorial(n - 1));
const memoFactorial = memoize(factorial);
memoFactorial(2); // "call" - returns 2.
memoFactorial(3); // "call" - returns 6.
memoFactorial(2); // "call" - returns 2. However factorial was not called because 2 was seen before.
// "getCallCount" - total call count: 2
memoFactorial(3); // "call" - returns 6. However factorial was not called because 3 was seen before.
// "getCallCount" - total call count: 2
```

**Example 3:**

```
Input:
fnName = "fib"
actions = ["call","getCallCount"]
values = [[5],[]]
Output: [8,1]
Explanation:
fib(5) = 8 // "call"
// "getCallCount" - total call count: 1
```

**Constraints**

- 0 <= a, b <= 105
- 1 <= n <= 10
- 1 <= actions.length <= 105
- actions.length === values.length
- actions[i] is one of "call" and "getCallCount"
- fnName is one of "sum", "factorial" and "fib"

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的做法就是**不做任何记忆**，每次 `call` 动作都直接把参数交给原函数 `fn` 去计算，`getCallCount` 只需要返回我们自己维护的计数器。  

- **使用的数据结构**：只需要一个整数 `call_cnt` 来记录“真正调用了原函数多少次”。这里的计数器可以想象成 **一本笔记本**，每写一笔就记一次。  
- **为什么正确**：因为题目只要求“返回一个 **不会在相同输入上二次调用** 的函数”。如果我们每次都真的调用原函数，虽然不满足“不会二次调用”，但从功能上（返回正确的值）来说是**正确**的，只是效率极低。  
- **时间/空间复杂度**：  
  - 对于 `sum(a,b)`，每次计算都是一次加法，时间是 **O(1)**。  
  - 对于 `factorial(n)`，递归实现的时间是 **O(n)**（每层递归一次）。  
  - 对于 `fib(n)`，最朴素的递归实现会产生指数级的调用，时间是 **O(2ⁿ)**。  
  - 空间上我们只用了一个计数器，**O(1)**（常数级别的内存）。

> **大白话**：`O(2ⁿ)` 就像把 n 层楼的楼梯每一步都往上跑两次，层数越高，跑的次数会翻倍增长。

#### 代码（Python）

```python
def memoize_bruteforce(fn):
    """暴力版 memoize：每次都直接调用 fn，不做任何缓存"""
    call_cnt = 0                     # 记录真正调用 fn 的次数

    def wrapper(*args):
        nonlocal call_cnt
        call_cnt += 1                # 直接调用，计数加 1
        return fn(*args)             # 交给原函数计算

    # 为了让外部能够查询调用次数，额外暴露一个获取计数的函数
    def get_call_count():
        return call_cnt

    # 返回两个可调用对象，使用时按需求取
    return wrapper, get_call_count
```

> **关键行解释**  
> - `nonlocal call_cnt`：告诉 Python 这里要使用外层函数的 `call_cnt` 而不是新建局部变量。  
> - `*args`：把任意数量的参数收集成一个元组，像把所有东西装进一个背包，后面再一次性倒出来。

#### 复杂度

- **时间复杂度**  
  - `sum` → `O(1)`  
  - `factorial` → `O(n)`  
  - `fib` → `O(2ⁿ)`  
  这里的 `O(...)` 直接反映了原函数本身的耗时，因为我们没有任何优化。  

- **空间复杂度**  
  - `O(1)`，只用了一个整数计数器，和输入规模无关。

### 2. 最优解

#### 思路  

从暴力解可以看到，**瓶颈**在于**重复计算**相同的输入。  
如果我们把已经算好的结果记下来，下次再遇到相同的参数时直接返回，就可以省掉重复的工作，这就是**记忆化（Memoization）**。

**一步步推导**：

1. **确定唯一标识**  
   - 参数列表可能是 ` (a, b) `、` (n,) ` 等。我们需要把它们变成可以比较的“键”。把参数元组直接作为字典的键最简单（Python 的 tuple 天然可哈希），相当于把一串数字 **序列化** 成唯一的“身份证”。  

2. **缓存结构**  
   - 用 **字典（dict）** 或 **Map** 来存放 `key → 结果`。字典就像 **查字典**：你给出单词（参数），它立刻给你对应的解释（结果）。  

3. **计数器**  
   - 只在“真正调用原函数”时才把计数器加 1。缓存命中时直接返回，不计数。  

4. **包装函数**  
   - `memoize` 返回一个 **闭包**（内部函数），它既能访问外层的缓存，又能访问计数器。  

5. **递归函数的内部调用**  
   - 题目只要求统计 **外层** 的调用次数。递归内部仍然使用原始函数，不需要额外处理。  

**核心算法**：**哈希表 + 闭包**，实现 O(1) 的缓存查找。

#### 代码（Python）

```python
def memoize(fn):
    """
    为任意函数 fn 创建一个“记忆化”版本。
    - 对同一组参数，只会调用一次原函数。
    - 通过内部的 get_call_count() 可以查询实际调用原函数的次数。
    """
    cache = {}          # 参数元组 → 计算结果，像一本“查字典”
    call_cnt = 0        # 记录真正调用 fn 的次数

    def memoized_func(*args):
        nonlocal call_cnt
        key = args      # args 本身是 tuple，天然可哈希，直接做 key

        if key in cache:                # 命中缓存 → 直接返回
            return cache[key]

        # 缓存未命中 → 调用原函数，计数并存入缓存
        call_cnt += 1
        result = fn(*args)
        cache[key] = result
        return result

    def get_call_count():
        """外部查询真正调用 fn 的次数"""
        return call_cnt

    # 为了配合 LeetCode 的交互方式，返回一个对象同时拥有两种能力
    # 这里用 tuple 包装，调用者会自行取用
    return memoized_func, get_call_count
```

> **关键行解释**  
> - `key = args`：把收到的所有参数直接当作键，类似把“一串数字”放进字典里查找。  
> - `if key in cache:`：字典的查找是 **O(1)**，就像在大超市里直接扫描条码。  
> - `nonlocal call_cnt`：让内部函数可以修改外层的计数器。  
> - `cache[key] = result`：把新算出来的结果存进缓存，以备后续复用。

#### 复杂度

- **时间复杂度**  
  - **缓存命中**：`O(1)`（字典一次哈希查找）。  
  - **缓存未命中**：等同于原函数的耗时（`sum` 为 `O(1)`，`factorial` 为 `O(n)`，`fib` 为 `O(2ⁿ)`），但这种情况只会在**每种参数组合第一次出现**时发生。  
  - 综合来看，对于 `m` 次调用，且不同参数组合不超过 `k`，总时间 ≈ `O(k·cost(fn) + (m‑k)·1)`，远优于全部 `O(m·cost(fn))`。

- **空间复杂度**  
  - 需要保存每种不同参数的结果，最坏情况是所有调用参数都不相同 → **O(k)**，其中 `k` 是不同参数组合的数量。  
  - 计数器本身仍是 `O(1)`。

> 与暴力解对比：  
> - 暴力解在 `fib` 上会出现指数级时间，最优解只会在第一次遇到每个 `n` 时花费指数时间，之后全部是常数时间。

## 心得

- **核心技巧**：使用 **哈希表（字典）** 进行**记忆化**，把“已经算过的”结果保存下来，避免重复计算。  
- **适用的题型**  
  1. 递归求解的斐波那契数列、爬楼梯等动态规划问题。  
  2. 组合计数、路径计数等会出现大量子问题重复求解的场景。  
  3. 任意需要“函数防重调用”（比如 API 缓存、计算密集型函数）的问题。  
- **一句话总结解题钥匙**：  
  > **“把参数当钥匙，结果当密码，记下来，下次直接开门。”**

## 反思

- **第一反应**：看到“不会二次调用相同输入”，立刻想到“缓存”。最自然的实现就是把 `args` 用作字典的键。  
- **最容易踩的坑**  
  1. **参数可哈希性**：如果参数是列表等不可哈希类型，需要先转成 `tuple` 或 `json.dumps`。本题参数都是整数，直接使用元组即可。  
  2. **计数器的作用域**：忘记 `nonlocal` 会导致每次调用都创建新的局部计数器，`getCallCount` 永远返回 0。  
  3. **递归函数内部调用**：误以为需要把递归内部也改成记忆化，实际上题目只要求统计外层调用次数，保持原函数不变即可。  
- **下次遇到同类题的第一步**：  
  > **先判断是否有“相同子问题会被重复求解”，如果有，就准备一个哈希表做记忆化。**
