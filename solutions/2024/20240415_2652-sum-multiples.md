## 解题过程

### 1. 直觉解（暴力）

#### 思路  
最直接的想法就是把 `[1, n]` 里的每一个整数都检查一遍：  

- 用一个 `for i in range(1, n+1)` 循环遍历所有数字。  
- 对每个 `i` 判断它是否能被 **3、5 或 7** 整除（`i % 3 == 0 or i % 5 == 0 or i % 7 == 0`）。  
- 能整除就把它加到答案 `ans` 中。

> **数据结构类比**  
> 这里我们只用到了**普通的整数变量**和**循环**，不需要额外的数据结构。把遍历看成在超市里一个一个检查商品是否符合特定标签（3、5、7），符合的就放进购物篮（累计求和）。

这种做法一定能得到正确答案，因为我们把所有可能的数字都检查了一遍，遗漏的可能性为零。

#### 代码（Python）

```python
def sum_of_multiples_brute(n: int) -> int:
    """
    暴力遍历 1~n，累加能被 3、5、7 整除的数
    """
    ans = 0                     # 用来保存最终的和
    for i in range(1, n + 1):   # 从 1 遍历到 n（包括 n）
        # 判断 i 是否是 3、5、7 任意一个的倍数
        if i % 3 == 0 or i % 5 == 0 or i % 7 == 0:
            ans += i            # 符合条件就加入答案
    return ans
```

#### 复杂度

- **时间复杂度：** `O(n)`  
  这里的 `O(n)` 表示随着 `n` 增大，程序运行时间大约会成正比增长。比如 `n` 从 100 增加到 200，循环次数会翻一番。

- **空间复杂度：** `O(1)`  
  只用了几个整数变量（`ans、i`），不随 `n` 的大小而增加。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **逐个检查**，当 `n` 很大（虽然本题只有 `10³`，但思考更一般的情况）时会浪费大量时间。  
我们可以利用数学的 **等差数列求和公式** 与 **容斥原理**，直接算出所有满足条件的数的和，而不需要遍历。

**关键点 1：等差数列求和**  
所有能被 `d` 整除的数构成等差数列：`d, 2d, 3d, … , md`，其中 `m = n // d`（即 `d` 的最大倍数不超过 `n`）。  
它们的和可以用公式：

\[
\text{sum}(d) = d \times \frac{m \times (m + 1)}{2}
\]

**关键点 2：容斥原理**  
直接把 `3、5、7` 的和相加会把 **同时是 3 与 5 的倍数**（即 15 的倍数）算两次，同理还有 `21`（3 与 7）和 `35`（5 与 7），甚至 `105`（3、5、7 同时）。  
容斥原理告诉我们：

\[
\text{答案} = \sum_{d\in\{3,5,7\}} \text{sum}(d)
               - \sum_{d\in\{15,21,35\}} \text{sum}(d)
               + \text{sum}(105)
\]

- 第一步：把单个集合的和相加（会重复计数）。  
- 第二步：减去两两交集的和（把重复计数的部分去掉）。  
- 第三步：加上三者交集的和（因为前两步把它减掉了两次，需要补回来一次）。

**类比**：把三个人的生日礼物总价值相加，发现有礼物是两个人共同送的，被算了两次，于是先减掉两次的部分，再把三个人一起送的礼物（被减了两次）加回来一次。

这样我们只需要常数次的算术运算，就能得到答案。

#### 代码（Python）

```python
def sum_of_multiples_optimal(n: int) -> int:
    """
    使用等差数列求和 + 容斥原理，时间 O(1)，空间 O(1)
    """
    # 辅助函数：返回所有 ≤ n 且能被 d 整除的数的和
    def sum_divisible_by(d: int) -> int:
        m = n // d                     # d 的最大倍数个数
        # 等差数列求和：d + 2d + ... + m*d = d * (1 + 2 + ... + m)
        return d * m * (m + 1) // 2    # // 表示整数除法，防止出现小数

    # 单独的集合
    sum3 = sum_divisible_by(3)
    sum5 = sum_divisible_by(5)
    sum7 = sum_divisible_by(7)

    # 两两交集（最小公倍数）
    sum15 = sum_divisible_by(15)   # lcm(3,5)
    sum21 = sum_divisible_by(21)   # lcm(3,7)
    sum35 = sum_divisible_by(35)   # lcm(5,7)

    # 三者交集
    sum105 = sum_divisible_by(105) # lcm(3,5,7)

    # 容斥原理
    answer = (sum3 + sum5 + sum7) - (sum15 + sum21 + sum35) + sum105
    return answer
```

#### 复杂度

- **时间复杂度：** `O(1)`  
  不管 `n` 多大，函数里只做了固定次数的算术运算（大约 10 次），所以运行时间几乎不随 `n` 变化。

- **空间复杂度：** `O(1)`  
  只用了少量的局部变量，内存占用恒定。

## 心得

- **核心技巧**：等差数列求和 + 容斥原理（Inclusion‑Exclusion）。  
- **适用的题型**：  
  1. “求 1~n 中能被若干整数整除的数之和”——如 LeetCode 题 *Sum of Multiples of 3 and 5*。  
  2. “求 1~n 中满足某些模条件的数的个数或和”——如统计能被 2、3、5 整除的数。  
- **一句话总结解题钥匙**：**把“遍历”换成“数学公式”，用容斥把重复计数纠正**。

## 反思

- **第一反应**：直接写循环遍历检查每个数是否满足条件。  
- **最容易踩的坑**：  
  - 忘记使用容斥原理，导致重复计数（例如把 15 的倍数算了两次）。  
  - 对等差数列求和公式的整数除法处理不当，可能出现浮点数或精度错误。  
- **下次遇到同类题**：第一步先思考“这些数形成什么规律的序列”，是否可以用 **等差数列求和** 或 **前缀和** 直接算出；随后检查是否会出现 **交集重复计数**，必要时使用 **容斥原理**。
