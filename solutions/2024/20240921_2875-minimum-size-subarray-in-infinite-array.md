## 题目（英文原版）

**Description**

You are given a 0-indexed array nums and an integer target.
A 0-indexed array infinite_nums is generated by infinitely appending the elements of nums to itself.
Return the length of the shortest subarray of the array infinite_nums with a sum equal to target. If there is no such subarray return -1.

**Examples**

**Example 1:**

```
Input: nums = [1,2,3], target = 5
Output: 2
Explanation: In this example infinite_nums = [1,2,3,1,2,3,1,2,...].
The subarray in the range [1,2], has the sum equal to target = 5 and length = 2.
It can be proven that 2 is the shortest length of a subarray with sum equal to target = 5.
```

**Example 2:**

```
Input: nums = [1,1,1,2,3], target = 4
Output: 2
Explanation: In this example infinite_nums = [1,1,1,2,3,1,1,1,2,3,1,1,...].
The subarray in the range [4,5], has the sum equal to target = 4 and length = 2.
It can be proven that 2 is the shortest length of a subarray with sum equal to target = 4.
```

**Example 3:**

```
Input: nums = [2,4,6,8], target = 3
Output: -1
Explanation: In this example infinite_nums = [2,4,6,8,2,4,6,8,...].
It can be proven that there is no subarray with sum equal to target = 3.
```

**Constraints**

- 1 <= nums.length <= 105
- 1 <= nums[i] <= 105
- 1 <= target <= 109

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：把 `nums` 无限复制下去，得到一个“很长很长”的数组 `infinite_nums`，然后在里面穷举所有可能的子数组，找出和恰好等于 `target` 的最短长度。  

- **数据结构**：我们只需要一个普通的 Python 列表来存放复制后的数组。可以把它想象成把一本书的内容不断往后翻页，一直翻到足够多的页数再去找符合条件的连续句子。  
- **为什么正确**：只要复制的长度足够长，所有可能出现的子数组一定会出现在这段有限的前缀里。只要遍历所有起点 `i` 和终点 `j`（`i ≤ j`），检查 `sum(infinite_nums[i:j+1])` 是否等于 `target`，就不会漏掉任何合法解。  

**如何决定复制多少次？**  
因为所有元素都是正数（`nums[i] ≥ 1`），子数组的长度不可能无限大：  
- 最短的子数组长度上限 = `target // min(nums) + 1`（把最小的数字一直加，最多需要这么多个才可能达到或超过 `target`）。  
- 再多加上一整段 `nums` 的长度，以防子数组跨越了复制边界。  

于是我们可以把 `nums` 复制 `repeat = (target // min(nums) + len(nums)) // len(nums) + 2` 次，得到一个足够长的前缀。  

遍历所有 `(i, j)` 组合的时间是 **平方级**，因为对每个起点都要尝试所有可能的终点。

#### 代码（Python）

```python
def min_subarray_len_bruteforce(nums, target):
    # ---------- 1. 预处理：复制足够多次 ----------
    min_val = min(nums)                     # 最小的正数
    # 估算需要的最大子数组长度（上界）
    max_len = target // min_val + len(nums) + 1
    # 需要多少个完整的 nums 才能保证前缀够长
    repeat = (max_len // len(nums)) + 2
    big = nums * repeat                     # 把 nums 无限复制了 repeat 次

    n = len(big)
    ans = float('inf')                      # 记录最小长度

    # ---------- 2. 穷举所有子数组 ----------
    for i in range(n):
        cur_sum = 0
        # 只要子数组长度不超过 max_len，就继续往右扩展
        for j in range(i, min(i + max_len, n)):
            cur_sum += big[j]
            if cur_sum == target:           # 找到一个合法子数组
                ans = min(ans, j - i + 1)   # 更新最小长度
                break                       # 更长的子数组只会更大，直接跳出

    return -1 if ans == float('inf') else ans
```

> **关键行注释**  
> - `big = nums * repeat`：把 `nums` 重复若干次，相当于把一本书的章节不停地粘在一起。  
> - `for j in range(i, min(i + max_len, n))`：因为所有数都是正的，和只会单调递增，一旦超过 `target` 再往右也不可能再等于 `target`，所以只需要检查到上界 `max_len`。  
> - `if cur_sum == target`：找到了符合要求的子数组，立刻更新答案并退出内部循环，省去不必要的比较。

#### 复杂度  

- **时间复杂度**：`O(max_len * n)`，其中 `max_len ≈ target / min(nums)`，在最坏情况下相当于 `O(N²)`（因为 `n` 本身与 `max_len` 同阶）。通俗来说，就是“把所有可能的起点和终点都尝试一次”。  
- **空间复杂度**：`O(n)`，需要额外的复制数组 `big`，长度大约是 `max_len`。

### 2. 最优解  

#### 思路  

暴力解的瓶颈在于 **对每个起点都要线性遍历**，导致二次方的时间。  
我们需要一种 **一次遍历就能判断是否存在合法子数组** 的方法。  

观察题目可以得到两个重要事实：

1. **所有数都是正数**，所以子数组的和随长度单调递增。  
2. 无限复制的数组可以看成若干个完整的 `nums` 加上 **前缀** 或 **后缀**。  

> **类比**：想象把一根绳子 `nums` 环环相扣形成一个环形跑道。一次跑步可以跨过若干个完整的环（每个环的长度是 `sum(nums)`），再加上起点到某个位置的**前缀**，以及从环的某个位置到终点的**后缀**。  

因此，一个合法子数组的和一定可以写成  

```
target = prefix_sum[i]               # 起点所在环的前缀（可能为空）
        + k * total_sum(nums)        # 经过了 k 整个环（k ≥ 0）
        + suffix_sum[j]              # 结束所在环的后缀（可能为空）
```

- `prefix_sum[i]`：`nums[0] + … + nums[i-1]`（`i` 可以为 0，表示空前缀）  
- `suffix_sum[j]`：`nums[0] + … + nums[j-1]`（同理，`j` 为 0 表示空后缀）  

**关键**：`prefix_sum` 与 `suffix_sum` 实际上是同一组前缀和，只是出现位置不同。我们只需要在 **一次遍历** 中枚举 `prefix_sum[i]`，然后检查剩余的部分能否用若干个完整环 + 某个后缀来凑齐。

具体步骤：

1. 计算 `total = sum(nums)`（一个完整环的和）和 `n = len(nums)`。  
2. 预先算出 **所有可能的前缀和**（包括 0），并记录每个前缀和对应的最短长度（因为所有数是正的，第一次出现的长度必然最短）。用一个哈希表 `suffix_len` 保存 `sum -> minimal length`。这一步相当于把“字典”里每个词（前缀和）和它所在页码（长度）对应起来。  
3. 对每个 `i`（从 0 到 `n`）：
   - `pre = prefix_sum[i]`，`pre_len = i`。如果 `pre > target`，后面的 `i` 只会更大，直接退出循环。  
   - 设 `remain = target - pre`（还需要凑的和）。  
   - 计算完整环的个数 `k = remain // total`（向下取整），以及剩余的 **余数** `rem = remain - k * total`（相当于 `remain % total`）。  
   - 如果 `rem` 正好在 `suffix_len` 中出现，说明可以用一个后缀凑齐。此时子数组长度 = `pre_len + k * n + suffix_len[rem]`。更新答案的最小值。  

因为我们只遍历一次 `prefix_sum`，每次查询哈希表是 ** O(1)**，整体时间 **线性**。

#### 代码（Python）

```python
def min_subarray_len(nums, target):
    n = len(nums)
    total = sum(nums)                 # 一个完整环的和
    # ---------- 1. 计算所有前缀和，记录最短出现的长度 ----------
    prefix = [0]                      # prefix[0] = 0（空前缀）
    for x in nums:
        prefix.append(prefix[-1] + x)

    # suffix_len[sum] = 最短的后缀长度（因为正数，第一次出现即最短）
    suffix_len = {}
    for length, s in enumerate(prefix):   # length = 0..n，s = 前缀和
        if s not in suffix_len:           # 只保留第一次出现
            suffix_len[s] = length

    ans = float('inf')

    # ---------- 2. 枚举所有可能的前缀 ----------
    for i, pre in enumerate(prefix):       # i = 前缀长度，pre = 前缀和
        if pre > target:                   # 已经超过 target，后面更大
            break

        remain = target - pre              # 还需要的和
        # 完整环的个数（可能为 0）
        k = remain // total
        rem = remain - k * total           # 余数，0 <= rem < total

        # 检查余数是否能由某个后缀凑成
        if rem in suffix_len:
            cur_len = i + k * n + suffix_len[rem]
            if cur_len > 0:                # 防止全空子数组（不可能出现，因为 target>0）
                ans = min(ans, cur_len)

    return -1 if ans == float('inf') else ans
```

> **关键行注释**  
> - `suffix_len` 哈希表：把“前缀和”当成字典的 **key**，对应的 **value** 是出现该和时的最短长度。就像查字典时，词条对应的页码。  
> - `k = remain // total`：相当于先在环路上跑 `k` 圈，剩下的 `rem` 再在下一圈里找后缀。  
> - `if rem in suffix_len`：如果余数恰好是某个前缀和，那么我们就可以用那个长度的后缀完成目标。  

#### 复杂度  

- **时间复杂度**：`O(n)`。只遍历一次 `nums`（构造前缀），再遍历一次前缀数组，每次哈希查询是常数时间。与暴力解的二次方相比，快了几个数量级。  
- **空间复杂度**：`O(n)`。需要保存前缀和数组和哈希表，均与 `nums` 长度线性相关。

## 心得  

- **核心技巧**：把无限复制的数组拆解为「若干完整环」+「前缀」+「后缀」的形式，再利用 **前缀和 + 哈希表** 在一次遍历中完成匹配。  
- **适用的题型**  
  1. **循环数组的子数组和**（如 LeetCode 1470 “Shuffle the Array” 的环形前缀）  
  2. **带有重复结构的最短子序列**（如 “Minimum Size Subarray Sum” 的变形）  
  3. **需要把目标拆成若干完整块 + 余数** 的场景（比如 “Minimum Number of Operations to Reduce X to Zero”）  
- **一句话总结解题钥匙**：**把无限重复的问题抽象成“若干完整块 + 余数”，再用前缀和的哈希映射一次搞定**。

## 反思  

- **第一反应**：看到“无限复制”，本能地想把数组拼长再暴力搜索，忽视了正数的单调性可以让我们做更好的数学拆解。  
- **最容易踩的坑**  
  - **遗漏空前缀/空后缀**：`target` 可能恰好等于某个前缀或后缀的和，需要把 `0` 前缀也加入哈希表。  
  - **除以 `total` 时的整数除法**：要使用 `//` 而不是 `/`，防止出现浮点数导致哈希查询失败。  
  - **特殊情况 `total > target`**：此时 `k` 必然为 `0`，仍然要走“一圈 + 余数”逻辑，不能直接返回 `-1`。  
- **下次类似题的第一步**：先检查是否可以把「无限」或「循环」的结构用「若干完整块 + 余数」来表达，再决定是否需要前缀和 / 哈希表来快速匹配。
