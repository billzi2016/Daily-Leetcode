# #2680. **最大或** / Maximum OR

> 难度：中等 · 标签：Array、Greedy、Bit Manipulation、Prefix Sum · [LeetCode 链接](https://leetcode.com/problems/maximum-or/)

---

## 题目（英文原版）

**Description**

You are given a 0-indexed integer array nums of length n and an integer k. In an operation, you can choose an element and multiply it by 2.
Return the maximum possible value of nums[0] | nums[1] | ... | nums[n - 1] that can be obtained after applying the operation on nums at most k times.
Note that a | b denotes the bitwise or between two integers a and b.

**Examples**

**Example 1:**

```
Input: nums = [12,9], k = 1
Output: 30
Explanation: If we apply the operation to index 1, our new array nums will be equal to [12,18]. Thus, we return the bitwise or of 12 and 18, which is 30.
```

**Example 2:**

```
Input: nums = [8,1,2], k = 2
Output: 35
Explanation: If we apply the operation twice on index 0, we yield a new array of [32,1,2]. Thus, we return 32|1|2 = 35.
```

**Constraints**

- 1 <= nums.length <= 105
- 1 <= nums[i] <= 109
- 1 <= k <= 15

---

## 题目（中文翻译）

给定一个下标从 0 开始的整数数组 `nums`（长度为 `n`）以及一个整数 `k`。一次操作中，你可以选择数组中的任意元素并将其乘以 2。  
返回在至多执行 `k` 次操作后，`nums[0] | nums[1] | ... | nums[n - 1]`（按位或，bitwise or）的最大可能值。  
注意，`a | b` 表示整数 `a` 与 `b` 的按位或。

**示例 1**

```
Input: nums = [12,9], k = 1
Output: 30
Explanation: 如果我们对下标为 1 的元素执行一次操作，新的数组为 [12,18]。于是返回 12 与 18 的按位或，结果为 30。
```

**示例 2**

```
Input: nums = [8,1,2], k = 2
Output: 35
Explanation: 如果我们对下标为 0 的元素执行两次操作，得到的新数组为 [32,1,2]。于是返回 32 | 1 | 2 的结果，等于 35。
```

**约束条件**

- `1 <= nums.length <= 10^5`
- `1 <= nums[i] <= 10^9`
- `1 <= k <= 15`

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**把每一次“把某个元素乘以 2”**的选择都枚举出来，然后把所有可能的数组算一次 **按位或**（`|`），最后取最大值。  
可以把这件事想象成：

- **每一次操作** 就像是让我们在一排数字里挑一个，给它加一个“魔法棒”——把它往左移动一位（乘 2）。  
- **所有操作的组合** 就像是把这些魔法棒分配给不同的数字，可能全部给同一个，也可能分散给几个。  

只要把所有分配方式都尝试一遍，记录下每种情况下的 `nums[0] | nums[1] | … | nums[n‑1]`，最大值就是答案。

**为什么这能得到正确答案？**  
因为我们把**所有**合法的操作序列都遍历了，答案一定在其中。  

**时间/空间分析（大白话版）**  
- 假设数组长度是 `n`，最大可以操作 `k` 次（题目里 `k ≤ 15`）。  
- 每一次操作都有 `n` 种选择，所以所有可能的操作序列数是 `n^k`（把 `k` 次选择串成一个长度为 `k` 的“词”），这在最坏情况下会非常非常大。  
- 对每一种序列我们都要遍历一遍数组计算 OR，时间大概是 `O(n)`。  
- 所以总的时间复杂度是 **`O(n^{k+1})`**，对 `n = 10^5` 完全不可接受。  
- 只用了原数组和几个临时变量，空间是 **`O(1)`**（不计输入数组本身）。

> **大白话解释**：  
> `O(n^k)` 就像说“如果你有 1000 本书，每本书你可以挑 15 次，每次都有 1000 种可能”，显然根本不可能手动尝遍。

#### 代码（Python）

下面的代码只用于演示概念，**只能在非常小的输入上跑得动**（比如 `n ≤ 5, k ≤ 5`），否则会超时。

```python
from itertools import product
from copy import deepcopy

def max_or_bruteforce(nums, k):
    """
    暴力枚举所有把 k 次乘以 2 的操作分配方式
    只适用于非常小的 n、k
    """
    n = len(nums)
    best = 0

    # 每一次操作都可以选 0~n-1 中的一个下标
    # 用 product 生成所有长度为 k 的下标序列
    for ops in product(range(n), repeat=k):
        arr = deepcopy(nums)          # 复制一份原数组，防止相互影响
        for idx in ops:               # 按序执行每一次乘 2
            arr[idx] <<= 1            # <<= 1 等价于 *2
        # 计算当前数组的 OR
        cur = 0
        for v in arr:
            cur |= v
        best = max(best, cur)

    return best

# 示例（仅供演示，实际数据会太大）
print(max_or_bruteforce([12, 9], 1))   # 30
print(max_or_bruteforce([8, 1, 2], 2)) # 35
```

#### 复杂度  

- **时间复杂度**：`O(n^{k+1})` —— 随着 `n`、`k` 稍微大一点，时间就会爆炸。  
- **空间复杂度**：`O(n)` —— 需要复制一份数组来模拟每一种操作，复制本身是 `O(n)`。

### 2. 最优解  

#### 思路  

从暴力解我们可以看到 **瓶颈** 在于“把每一次操作的选择都枚举”。  
要想快，就必须 **把搜索空间压缩到 O(n)**，而不是指数级。

**关键观察 1：所有的乘 2 操作集中在同一个元素上就足够好**  

- 乘 2 相当于把二进制左移一位，会把原来的最低位（最右边）变成 0。  
- 如果我们把一次操作分给两个不同的元素，就会 **把两个元素的最低位都清掉**，这可能导致 OR 失去一些已经有的 1。  
- 把所有 `k` 次左移全部放在 **同一个元素** 上，只会清掉这一个元素的 `k` 个最低位，而其它元素保持原样，**不会失去它们已有的位**。  
- 同时，这个被左移的元素会把更高的位“搬上来”，可能产生之前没有的 1，整体 OR 只会更大或相等。  

> **类比**：把一本书的页码全部往后推（左移），只会让这本书的内容往后移动，而不影响其它书的页码。如果把每本书都往后推一点，所有书的页码都可能变得不可读（丢掉低位信息），而只让一本书往后推，其他书仍然保持原样。

**关键观察 2：我们需要快速算出 “除去第 i 个元素之外的所有元素的 OR”。**  

- 直接遍历数组计算 OR 的话，对每个 `i` 都是 `O(n)`，总共 `O(n^2)`。  
- 使用 **前缀 OR** 与 **后缀 OR** 可以在 `O(1)` 时间得到除去任意位置的 OR。  
  - `pref[i]` = `nums[0] | nums[1] | … | nums[i‑1]`（不含 `i`）  
  - `suf[i]` = `nums[i+1] | nums[i+2] | … | nums[n‑1]`（不含 `i`）  
- 那么 “除去 i 的 OR” = `pref[i] | suf[i]`。  

**步骤概览**  

1. 预先计算 `pref`（从左到右一次遍历）和 `suf`（从右到左一次遍历）。  
2. 对每个位置 `i`：  
   - 把 `nums[i]` 左移 `k` 位得到 `shifted = nums[i] << k`（相当于乘以 `2^k`）。  
   - 计算 `total = pref[i] | shifted | suf[i]`，这就是把全部 `k` 次操作都用在第 `i` 个数上的 OR。  
   - 记录最大值。  
3. 返回最大值即可。

**为什么这样一定是最优？**  

- 依据观察 1，最优解一定把所有操作集中在一个元素上。  
- 依据观察 2，我们已经遍历了**每一个可能的“集中元素”**，并且用 O(1) 时间算出对应的 OR。  
- 所以遍历完后得到的最大值，就是全局最优。

#### 代码（Python）

```python
def maximum_or(nums, k):
    """
    最优解：O(n) 时间、O(n) 空间
    思路：
    1. 计算前缀 OR 和后缀 OR；
    2. 对每个位置 i，假设把全部 k 次左移都作用在 nums[i] 上；
       计算 (pref[i] | (nums[i] << k) | suf[i])，取最大。
    """
    n = len(nums)

    # ---------- 1. 前缀 OR ----------
    pref = [0] * (n + 1)          # pref[0] = 0，表示空集合的 OR 为 0
    for i in range(n):
        pref[i + 1] = pref[i] | nums[i]   # 把第 i 个元素并入前缀

    # ---------- 2. 后缀 OR ----------
    suf = [0] * (n + 1)           # suf[n] = 0，表示空集合的 OR 为 0
    for i in range(n - 1, -1, -1):
        suf[i] = suf[i + 1] | nums[i]     # 把第 i 个元素并入后缀

    # ---------- 3. 枚举集中操作的元素 ----------
    ans = 0
    shift = k                     # 左移的位数（相当于乘 2^k）
    for i in range(n):
        shifted = nums[i] << shift          # 把全部 k 次操作集中在 nums[i] 上
        total = pref[i] | shifted | suf[i + 1]   # 前缀 + 左移后元素 + 后缀
        ans = max(ans, total)

    return ans


# ------------------- 示例 -------------------
print(maximum_or([12, 9], 1))        # 30
print(maximum_or([8, 1, 2], 2))     # 35
```

> **代码细节解释**  
> - `pref[i]` 保存的是 **不含第 i 个元素** 的左侧 OR，故在计算第 `i` 位的答案时使用 `pref[i]`（左边）和 `suf[i+1]`（右边）。  
> - `nums[i] << k` 等价于 `nums[i] * (2 ** k)`，但位运算更快且不会出现浮点数。  
> - Python 的整数是大整数，左移 15 位仍然安全（最大约 `1e9 * 2^15 ≈ 3.3e13`），不必担心溢出。

#### 复杂度  

- **时间复杂度**：`O(n)`  
  - 只遍历数组三次（一次算前缀，一次算后缀，一次枚举），每次都是线性操作。  
  - 与暴力解的 `O(n^{k+1})` 相比，**快了几个数量级**，即使 `n = 10^5` 也能在毫秒级完成。  

- **空间复杂度**：`O(n)`  
  - 需要两个长度为 `n+1` 的数组 `pref`、`suf` 来存前缀/后缀 OR。  
  - 这在 `n = 10^5` 时也只占几百 KB 的内存，完全可以接受。

## 心得  

- **核心技巧**：**把所有“乘 2”操作集中在同一个元素上** + **前缀/后缀前缀和（这里是前缀/后缀 OR）** 用来快速排除某个位置的贡献。  
- **适用的题型**（类似思路可复用）：  
  1. **Maximum XOR After K Operations**（把所有位翻转或左移集中在一个数）  
  2. **Maximum Sum After K Removals**（前缀/后缀和帮助快速算除去某段的总和）  
  3. **Maximum AND/OR with One Modification**（只允许改动一个元素，前后缀技术同样适用）  
- **一句话总结**：  
  > “把所有增益操作都压在同一个位置，然后用前缀/后缀快速算出除它之外的整体，答案自然最大。”

## 反思  

- **第一反应**：直接想遍历所有可能的操作分配，写递归/DFS 暴力搜索。  
- **最容易踩的坑**：  
  - 忽略了“左移会把低位清零”，导致把操作分散到多个元素时意外降低了 OR。  
  - 没有使用前缀/后缀结构时，枚举每个元素的 OR 需要 `O(n^2)`，会超时。  
  - `k` 虽然小（≤15），但如果直接枚举 `n^k` 仍然不可行。  
- **下次遇到同类题**，第一步应该问自己：  
  - “操作是否对整体有单调性（只增不减）？”  
  - “能否把所有操作集中在一个元素上而不损失已有的贡献？”  
  - “有没有前缀/后缀（或前缀和、前缀乘）这种线性预处理可以把‘除去某个位置的整体’降到 O(1)？”  

这样思路就能迅速从暴力走向最优解。祝你玩转位运算和前缀技巧！
