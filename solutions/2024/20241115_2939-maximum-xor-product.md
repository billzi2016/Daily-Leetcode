## 题目（英文原版）

**Description**

Given three integers a, b, and n, return the maximum value of (a XOR x) * (b XOR x) where 0 <= x < 2n.
Since the answer may be too large, return it modulo 109 + 7.
Note that XOR is the bitwise XOR operation.

**Examples**

**Example 1:**

```
Input: a = 12, b = 5, n = 4
Output: 98
Explanation: For x = 2, (a XOR x) = 14 and (b XOR x) = 7. Hence, (a XOR x) * (b XOR x) = 98. 
It can be shown that 98 is the maximum value of (a XOR x) * (b XOR x) for all 0 <= x < 2n.
```

**Example 2:**

```

Output: 930
Explanation: For x = 25, (a XOR x) = 31 and (b XOR x) = 30. Hence, (a XOR x) * (b XOR x) = 930.
It can be shown that 930 is the maximum value of (a XOR x) * (b XOR x) for all 0 <= x < 2n.
```

**Example 3:**

```

Output: 12

It can be shown that 12 is the maximum value of (a XOR x) * (b XOR x) for all 0 <= x < 2n.
```

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是把 **所有** 合法的 `x`（即 `0 ≤ x < 2ⁿ`）枚举一遍，算出  
`(a XOR x) * (b XOR x)` 的值，取最大即可。

- **使用的数据结构**：只需要一个整数变量 `max_val` 保存当前最大乘积，和一个循环遍历 `x`。  
  可以把 `x` 想象成 **一本厚厚的字典**，我们把字典的每一页（每个 `x`）都翻一遍，记下最好的那页。

- **为什么正确**：因为我们真的把所有可能的 `x` 都检查了，必然不会错过最优解。

- **复杂度分析**  
  - **时间**：我们要遍历 `2ⁿ` 个 `x`，每次计算一次异或和一次乘法，都是 `O(1)` 的操作，所以总时间是 `O(2ⁿ)`。  
    “`O(2ⁿ)`” 可以理解为“随着 `n` 增大，工作量会像 2 的 n 次方一样疯狂增长”。比如 `n=20` 时要跑 1,048,576 次循环，`n=30` 时就要跑 1,073,741,824 次，明显不现实。
  - **空间**：只用常数个额外变量，`O(1)`。

#### 代码（Python）

```python
def maxXorProduct_bruteforce(a: int, b: int, n: int) -> int:
    MOD = 10**9 + 7                # 题目要求的取模
    limit = 1 << n                 # 2ⁿ，等价于 1 左移 n 位
    max_val = 0

    for x in range(limit):        # 枚举所有可能的 x
        # 计算 a XOR x 与 b XOR x
        ax = a ^ x
        bx = b ^ x
        prod = (ax * bx) % MOD     # 乘积取模，防止中间数太大
        if prod > max_val:         # 更新最大值
            max_val = prod

    return max_val
```

#### 复杂度

- **时间复杂度**：`O(2ⁿ)` — 随着 `n` 增大，循环次数会指数级增长，实际只能在 `n` 很小（比如 ≤20）时使用。
- **空间复杂度**：`O(1)` — 只用了常数个整数变量。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **枚举所有 `x`**，当 `n` 达到 30、40、甚至 50 时，`2ⁿ` 已经天文数字，根本跑不完。  
我们需要 **直接构造** 那个能让乘积最大的 `x`，而不是去尝试每一个。

观察乘积 `(a⊕x)*(b⊕x)`：

- 乘积的高位对最终结果的影响远大于低位。也就是说 **先决定最高位**，再决定次高位，依次往下，这样的决策会主导最终的大小。
- 对于某一位 `i`（从最高位 `n‑1` 到最低位 `0`），我们只关心 **该位上 `a`、`b`、以及我们要选的 `x`**。  
  `a_i`、`b_i` 表示第 `i` 位的值（0 或 1），`x_i` 同理。

下面分两种情况讨论：

| `a_i` | `b_i` | 能否让 `a⊕x` 与 `b⊕x` 的第 i 位同时为 1？ |
|-------|-------|--------------------------------------------|
| 0     | 0     | 可以。把 `x_i` 设为 1，两个异或结果都变成 1。 |
| 1     | 1     | 同上，把 `x_i` 设为 0，两个异或结果都变成 1。 |
| 0     | 1 **或** 1 | 0     | 只能让 **其中一个** 异或结果的第 i 位为 1，另一个必为 0。 |

- **相同位**（`a_i == b_i`）时，我们总是让 `x_i` 与它们相反，这样 **两个数的第 i 位都能得到 1**，显然最有利。

- **不同位**（`a_i != b_i`）时，最高位只能给其中一个数加 1。  
  这时我们要 **把 1 给当前数值较小的那个**，因为让较小的数先“追上”可以在后面的低位继续保持优势，最终乘积更大。

因此我们可以从最高位到最低位 **贪心** 地决定 `x` 的每一位：

1. 维护两个变量 `A = a⊕x`、`B = b⊕x`（一开始都是 0）。它们代表已经确定的高位部分。
2. 从第 `n‑1` 位向下遍历：
   - 读取 `a_i`、`b_i`（`(a>>i)&1`、`(b>>i)&1`）。
   - 若相同：把 `x_i` 设为 `1-a_i`，于是 `A`、`B` 都在该位得到 `1`（`A|=1<<i`、`B|=1<<i`）。
   - 若不同：比较当前 `A` 与 `B` 的大小（只看已经确定的高位），把 `1` 交给较小的那一个：
     - 若 `A < B`，则让 `A` 的第 i 位为 1，`x_i = 1 - a_i`（因为此时 `a_i` 与 `b_i` 不同，必有 `a_i` 为 0，`b_i` 为 1，或者相反）。
     - 否则让 `B` 的第 i 位为 1，`x_i = 1 - b_i`。

3. 最后得到的 `A`、`B` 就是 **使乘积最大的** 两个数，直接返回 `A*B % MOD`。

**为什么贪心是最优的？**  
因为在二进制乘法中，高位的差值会乘上 `2^{i}`，远大于所有低位可能的贡献。我们在每一步都让 **能让乘积最大的高位** 达到最大值，低位的选择只能在高位相同的情况下才会影响结果，而我们的规则正好保证了在高位相同的情况下让两个数的高位都为 1（最优），在高位不同的情况下让较小的数先补上高位，这样的局部最优必然导致全局最优——这是一种典型的“位权重贪心”。

#### 代码（Python）

```python
def maxXorProduct(a: int, b: int, n: int) -> int:
    MOD = 10**9 + 7
    A = 0          # 保存 a ^ x 的结果（我们会一步步填高位）
    B = 0          # 保存 b ^ x 的结果

    # 从最高位 n-1 向最低位 0 依次决定 x 的每一位
    for i in range(n - 1, -1, -1):
        ai = (a >> i) & 1          # a 的第 i 位
        bi = (b >> i) & 1          # b 的第 i 位

        if ai == bi:
            # a_i 与 b_i 相同，直接把 x_i 设成相反，使两者第 i 位都为 1
            A |= (1 << i)          # A 的第 i 位设为 1
            B |= (1 << i)          # B 的第 i 位也设为 1
            # 此时 x_i = 1 - ai（不需要显式存，只要把 A、B 设好即可）
        else:
            # a_i 与 b_i 不同，只能让一个数的第 i 位为 1
            # 把 1 给当前数值较小的那个
            if A < B:
                # 让 A 的第 i 位为 1，x_i 必须和 a_i 不同
                A |= (1 << i)
            else:
                # 让 B 的第 i 位为 1，x_i 必须和 b_i 不同
                B |= (1 << i)

    # 乘积取模后返回
    return (A * B) % MOD
```

#### 复杂度

- **时间复杂度**：`O(n)` — 只遍历 `n` 位，每位做常数次位运算。  
  与暴力解的 `O(2ⁿ)` 相比，**从指数级降到了线性**，即使 `n=50` 也只需要 50 次循环，几乎瞬间完成。

- **空间复杂度**：`O(1)` — 只用了几个整数变量，不随 `n` 增长而增加。

## 心得

- **核心技巧**：**位权重贪心**——从最高位决定二进制位的取值，使得高位的贡献始终最大化。  
- **适用的题型**  
  1. “最大化/最小化异或/与/或” 类问题（如 “Maximum XOR Sum”）。  
  2. “在限制范围内构造最大数” 的位运算题（如 “Maximum AND product”）。  
  3. “位掩码 + 贪心” 的组合优化题（如 “Maximum XOR Subarray” 的构造思路）。
- **一句话总结解题钥匙**：**让最高位尽可能同时为 1，否则把 1 给当前较小的数**。

## 反思

- **第一反应**：直接想到枚举所有 `x`，因为最直观的想法是“遍历”。  
- **最容易踩的坑**  
  - 忽视 `n` 的大小，导致暴力解在实际测试中超时。  
  - 在“不同位”情况下错误地总是把 1 给 `a`，而不比较当前的前缀大小，会导致非最优结果。  
  - 忘记对乘积取模，容易出现整数溢出（Python 虽然大整数安全，但仍要按题目要求取模）。
- **下次遇到同类题**：第一步应该问自己 “最高位能否一次性确定？” 然后依据 **相同位 → 两数都取 1**、**不同位 → 给较小的数 1** 的贪心原则快速构造答案。
