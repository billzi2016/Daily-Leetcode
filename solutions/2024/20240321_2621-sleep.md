## 题目（英文原版）

**Description**

Given a positive integer millis, write an asynchronous function that sleeps for millis milliseconds. It can resolve any value.
Note that minor deviation from millis in the actual sleep duration is acceptable.

**Examples**

**Example 1:**

```
Input: millis = 100
Output: 100
Explanation: It should return a promise that resolves after 100ms.
let t = Date.now();
sleep(100).then(() => {
  console.log(Date.now() - t); // 100
});
```

**Example 2:**

```
Input: millis = 200
Output: 200
Explanation: It should return a promise that resolves after 200ms.
```

**Constraints**

- 1 <= millis <= 1000

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接、最笨的办法是**不停地检查时间是否已经过去了 `millis` 毫秒**，等到满足条件才返回。  
可以把它想象成烤面包时，你每隔几秒抬头看一次计时器——虽然能做到，但一直盯着计时器会浪费眼睛（CPU）资源。

实现时我们可以：

1. 用 `time.time()`（返回秒）或 `time.monotonic()`（单调递增的时钟）记录开始时刻。  
2. 进入一个 `while` 循环，循环体里不断获取当前时间并和开始时间比较。  
3. 当已经过去的毫秒数 `>= millis` 时，退出循环并 **返回**（或 `resolve`）任意值。

> 为什么这个方法能得到正确答案？  
> 因为我们一直在等，直到真实的时间流逝达到要求的毫秒数，所以一定会在 **不早于** `millis` 毫秒后结束。

#### 代码（Python）

```python
import time
import asyncio

async def sleep_brute_force(millis: int):
    """
    暴力实现的异步 sleep。
    通过不停轮询系统时间，直到已经过去的毫秒数达到要求。
    """
    start = time.monotonic()            # 记录开始时刻（秒），单调递增不受系统时间改动影响
    target = millis / 1000.0            # 把毫秒转成秒，方便比较

    # while 循环一直占用 CPU，等价于“盯着计时器看”
    while (time.monotonic() - start) < target:
        # 为了让协程有机会被调度，稍微让出控制权
        # 这里的 await asyncio.sleep(0) 相当于 “让出 CPU”，但仍然在忙等
        await asyncio.sleep(0)

    # 等待结束后，返回任意值，这里返回传入的毫秒数
    return millis
```

#### 复杂度

- **时间复杂度**：`O(millis)`  
  大白话：如果要等 500 ms，循环大约会跑 500 次（实际取决于 CPU 速度），所以时间随等待的毫秒数线性增长。  
- **空间复杂度**：`O(1)`  
  只用了几个变量保存时间，没有额外的随输入增长的空间。

### 2. 最优解

#### 思路  

从暴力解出发，**瓶颈**在于「不停地轮询时间」——CPU 被占满，却没有真正做有意义的事。  
我们需要把「等待」的工作交给系统，让系统在时间到了以后再「叫醒」我们，这样 CPU 可以去干别的活。

在 Python 的异步编程里，**`asyncio.sleep(seconds)`** 正是这样一个「系统帮忙」的函数：

- 它会让当前协程**挂起**，不占用 CPU。  
- 系统计时器会在指定的秒数后把协程放回事件循环，继续执行后面的代码。  

这相当于把「盯着计时器」的任务交给了「闹钟」——闹钟响了我们再去处理。

实现步骤：

1. 把 `millis` 转成秒（`millis / 1000`）。  
2. 使用 `await asyncio.sleep(seconds)` 挂起协程。  
3. 睡眠结束后返回任意值（这里返回 `millis` 本身，和题目示例保持一致）。

> **为什么这比暴力循环更好？**  
> 因为 `asyncio.sleep` 只是在内部注册一个计时器，CPU 可以去执行其他协程或线程，等计时器触发时才恢复执行。等价于「把等待交给系统」，时间复杂度几乎是 **O(1)**（不随 `millis` 增长而消耗 CPU），空间仍然是常数。

#### 代码（Python）

```python
import asyncio

async def sleep(millis: int):
    """
    最优实现的异步 sleep。
    直接使用 asyncio.sleep，让系统负责计时，不占用 CPU。
    """
    seconds = millis / 1000.0          # 把毫秒转换成秒，asyncio.sleep 需要秒数
    await asyncio.sleep(seconds)       # 挂起当前协程，等计时器触发后恢复

    # 睡眠结束后返回任意值，这里返回输入的毫秒数，方便测试
    return millis
```

#### 复杂度

- **时间复杂度**：`O(1)`  
  大白话：不管要等 10 ms 还是 900 ms，CPU 本身只做一次「注册计时器」的操作，耗时与 `millis` 无关。系统计时器会在后台完成等待。  
- **空间复杂度**：`O(1)`  
  只用了几个局部变量，和输入大小没有关系。

## 心得

- **核心技巧**：使用 **异步等待 / 计时器**（`asyncio.sleep`）把「等待」交给系统，避免忙等。  
- **适用的题型**  
  1. 需要在指定时间后执行后续操作的异步任务（如「延时发送请求」）。  
  2. 需要实现「节流 / 防抖」的函数（通过 `await asyncio.sleep` 实现）。  
  3. 任何可以用 **计时器** 替代 **轮询** 的场景。  
- **一句话总结**：让系统帮你计时，别自己盯着时钟。

## 反思

- **第一反应**：直接写一个 `while` 循环不停检查时间——最直观但很低效。  
- **最容易踩的坑**  
  - 忘记把 `millis` 转成秒，导致 `asyncio.sleep` 等待时间不对。  
  - 在同步代码里直接调用 `time.sleep`，会阻塞整个事件循环，失去异步的意义。  
  - 需要返回一个 **`awaitable`**（协程对象），否则调用者得不到 `Promise`（在 Python 中对应 `await` 的对象）。  
- **下次遇到同类题**：第一步先想「有没有系统提供的计时器？」——如果有，直接使用；如果没有，再考虑自己实现（比如轮询）。
