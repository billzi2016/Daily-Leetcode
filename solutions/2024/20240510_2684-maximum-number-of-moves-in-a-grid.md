# #2684. **网格中的最大移动次数** / Maximum Number of Moves in a Grid

> 难度：中等 · 标签：Array、Dynamic Programming、Matrix · [LeetCode 链接](https://leetcode.com/problems/maximum-number-of-moves-in-a-grid/)

## 题目（英文原版）

**Description**

You are given a 0-indexed m x n matrix grid consisting of positive integers.
You can start at any cell in the first column of the matrix, and traverse the grid in the following way:
Return the maximum number of moves that you can perform.

**Examples**

**Example 1:**

```
Input: grid = [[2,4,3,5],[5,4,9,3],[3,4,2,11],[10,9,13,15]]
Output: 3
Explanation: We can start at the cell (0, 0) and make the following moves:
- (0, 0) -> (0, 1).
- (0, 1) -> (1, 2).
- (1, 2) -> (2, 3).
It can be shown that it is the maximum number of moves that can be made.
```

**Example 2:**

```
Input: grid = [[3,2,4],[2,1,9],[1,1,7]]
Output: 0
Explanation: Starting from any cell in the first column we cannot perform any moves.
```

**Constraints**

- m == grid.length
- n == grid[i].length
- 2 <= m, n <= 1000
- 4 <= m * n <= 105
- 1 <= grid[i][j] <= 106

## 题目（中文翻译）

你得到一个下标从 **0** 开始的 `m × n` 矩阵 `grid`，矩阵中所有元素均为正整数。  
你可以从矩阵的第一列的任意单元格出发，并按照下面的规则遍历矩阵：

- 当前位于单元格 `(r, c)` 时，你可以移动到下一列的任意相邻行，即 `(r‑1, c+1)`、`(r, c+1)` 或 `(r+1, c+1)`（前提是这些单元格在矩阵范围内），且目标单元格的数值必须 **严格大于** 当前单元格的数值。
- 只要还能满足上述条件，就可以继续移动；否则停止移动。

返回你在整个过程中能够执行的**最大移动次数**。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**从每一个起点（第一列的格子）出发，尝试所有可能的走法**，把能走的最长路径记录下来。  
走法的规则如下（题目原文略去，这里补全）：

- 只能往**右侧的下一列**移动；
- 可以往**上‑右**、**右**、**下‑右** 三个方向走；
- 只能走到**值严格更大的格子**。

这和我们日常生活中“爬楼梯，只能往更高的台阶走”类似。  
我们可以用 **深度优先搜索（DFS）** 来遍历所有路径：

1. 选定第一列的某个格子 `(i, 0)` 作为起点；
2. 从当前格子 `(r, c)` 看它右边三格 `(r-1, c+1)`, `(r, c+1)`, `(r+1, c+1)`（注意要判断行、列是否越界）；
3. 如果目标格子的数值 **大于** 当前格子，就递归继续搜索；
4. 递归返回的值加一就是从当前格子出发可以走的**最多步数**；
5. 对所有起点取最大值即为答案。

> **为什么一定能得到正确答案？**  
> DFS 会把**所有合法的走法**都枚举一遍，最大步数自然会被记录下来。

#### 代码（Python）

```python
from typing import List

def maxMoves_bruteforce(grid: List[List[int]]) -> int:
    m, n = len(grid), len(grid[0])
    dirs = [(-1, 1), (0, 1), (1, 1)]          # 上右、右、下右 三个方向

    # 递归搜索，从 (r, c) 开始最多还能走多少步
    def dfs(r: int, c: int) -> int:
        best = 0                               # 暂时没有可走的格子，步数为 0
        for dr, dc in dirs:                    # 依次尝试三个方向
            nr, nc = r + dr, c + dc
            if 0 <= nr < m and nc < n and grid[nr][nc] > grid[r][c]:
                # 若满足「更大且未越界」的条件，继续向下搜索
                best = max(best, 1 + dfs(nr, nc))
        return best

    ans = 0
    for row in range(m):                       # 所有第一列的起点都尝试一次
        ans = max(ans, dfs(row, 0))
    return ans
```

> **代码注释**  
> - `dirs` 把三种合法的移动抽象成「行偏移、列偏移」的元组，类似于「字典里查找方向 → 找到对应的下一格」  
> - `dfs` 函数返回的是**从当前格子还能继续走的最多步数**，递归的返回值 `1 + dfs(...)` 表示「走到下一格后还能走的步数」加上这一步本身  

#### 复杂度

- **时间复杂度**：`O(3^{n})`（指数级）  
  - 每走一步都有最多 3 种选择，最坏情况下会把所有可能的路径遍历完。  
  - 用大白话说，就是**每多走一列，搜索树的枝叶数就会翻三倍**，所以当列数 `n` 较大时会非常慢。

- **空间复杂度**：`O(n)`（递归栈深度）  
  - 递归最多会深入到最右侧的一列，深度等于列数 `n`，每层递归占用常量空间。

> 这已经不是我们在面试里想要的答案——指数级的时间根本跑不完 1000×1000 的矩阵。

### 2. 最优解

#### 思路  

从暴力解可以看出**瓶颈在于大量的重复搜索**：  
同一个格子会被不同的路径反复访问，导致指数级的时间。

**关键观察**：  
> 对于任意格子 `(i, j)`，只要我们已经知道**从它右边的三个候选格子出发最多还能走多少步**，就可以立刻算出从 `(i, j)` 出发的最多步数。

这正是**动态规划（DP）**的思想：把大问题拆成子问题，子问题只算一次，随后复用。

- **子问题定义**：`dp[i][j]` 表示**从格子 `(i, j)` 出发，最多还能走多少步**（不包括已经站在的这一步）。
- **状态转移**  
  ```
  dp[i][j] = 0                                      # 默认没有合法的下一步
  for each (ni, nj) in {(i-1, j+1), (i, j+1), (i+1, j+1)}:
      if ni, nj 在矩阵内部 且 grid[ni][nj] > grid[i][j]:
          dp[i][j] = max(dp[i][j], 1 + dp[ni][nj])
  ```
  只要右边的格子值更大，就可以往那儿走，步数 = 1（这一步） + 那格子能走的最多步数。
- **计算顺序**：因为 `dp[i][j]` 依赖于右边一列的值，我们可以**从最右侧列往左遍历**，保证右边的 `dp` 已经算好。这样是**自底向上**的 DP。
- **答案**：所有第一列格子的 `dp[i][0]` 中的最大值，即 `max(dp[i][0])`。

> **为什么 DP 正确？**  
> 每个格子只考虑一次「向右走一步」的可能性，并把以后所有的最优子路径（已经在右侧列算好）加入进来。因为路径只能向右移动，**不存在环**，所以把右边的最优解拼起来一定得到全局最优。

#### 代码（Python）

```python
from typing import List

def maxMoves(grid: List[List[int]]) -> int:
    m, n = len(grid), len(grid[0])
    # dp[i][j] 表示从 (i, j) 开始最多还能走多少步
    dp = [[0] * n for _ in range(m)]

    # 从右往左遍历列（最右侧列已经是 0，因为再也走不动了）
    for col in range(n - 2, -1, -1):               # n-2 到 0
        for row in range(m):
            best = 0
            # 上右、右、下右 三个方向
            for dr in (-1, 0, 1):
                nr, nc = row + dr, col + 1
                if 0 <= nr < m and grid[nr][nc] > grid[row][col]:
                    # 若可以移动，更新 best 为「走这一步 + 右边格子的最优步数」
                    best = max(best, 1 + dp[nr][nc])
            dp[row][col] = best                    # 记录当前格子的最优步数

    # 第0列的最大值即为答案
    return max(dp[row][0] for row in range(m))
```

> **代码要点**  
> - `dp` 初始化为全 0，代表最右列不可继续移动。  
> - 双层 `for` 循环的顺序 **先列后行**，确保右边的 `dp` 已经算好。  
> - `for dr in (-1, 0, 1)` 把三种方向抽象成「行偏移」的枚举，类比“字典里查找方向 → 找到对应的格子”。  
> - 最后 `max(dp[row][0] ...)` 就是所有起点的最优答案。

#### 复杂度

- **时间复杂度**：`O(m * n)`  
  - 每个格子只检查至多 3 个右侧格子，整体遍历一次矩阵即可。  
  - 用大白话说，就是**行数乘列数**的规模——即使是 1000×1000 的矩阵也只需要 1 000 000 次非常轻量的比较和取最大，跑得很快。

- **空间复杂度**：`O(m * n)`（存 `dp` 表）  
  - 需要额外的二维数组保存每个格子的子问题答案。  
  - 如果想进一步压缩空间，可以只保留**当前列和下一列**的 `dp`，把空间降到 `O(m)`，但对初学者来说完整的 `dp` 更直观。

> 与暴力解相比，时间从指数级降到了线性级，速度提升了 **指数级**，几乎可以在一秒钟内处理最大输入。

## 心得

- **核心技巧**：**自底向上动态规划 + 状态转移**（每个格子只依赖右边已知的结果）。
- **该技巧适用的题型**  
  1. “只能向右/下/右上/左下移动且必须满足单调条件”的网格路径题（如 *Maximum Number of Moves in a Grid*、*Longest Increasing Path in a Matrix*）。  
  2. “从左到右、从上到下累加或比较”的 DP 矩阵题（如 *Maximum Path Sum in a Grid*、*Minimum Falling Path Sum*）。  
  3. “在 DAG（有向无环图）上求最长/最短路径”，因为 DP 本质上就是在 DAG 上的拓扑顺序 DP。

- **一句话总结解题钥匙**：  
  **把“只能往右走”这一单向约束当成拓扑顺序，从右往左把子问题的最优解逐层传递回来。**

## 反思

- **第一反应**：看到只能向右移动且必须数值增大，立刻想到“DFS 暴力搜索”。  
- **最容易踩的坑**  
  1. **边界检查**：上‑右和下‑右会越界，必须先判断 `0 <= nr < m`。  
  2. **比较方向**：只能在**值更大的**格子上继续，否则步数为 0（即使还能往右走，但不满足条件）。  
  3. **遗漏初始化**：最右列的 `dp` 必须是 0，不能忘记，否则会出现错误的递推。  
- **下次遇到同类题的第一步**：  
  **先判断是否有单向/单调的约束，若有，就把状态定义为“从当前位置出发的最优子结果”，然后确定递推方向（自底向上或自顶向下），再写出转移方程。**
