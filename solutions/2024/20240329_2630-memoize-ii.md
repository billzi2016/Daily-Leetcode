# #2630. Memoize II / Memoize II

## 题目（英文原版）

**Description**

Given a function fn, return a memoized version of that function.
A memoized function is a function that will never be called twice with the same inputs. Instead it will return a cached value.
fn can be any function and there are no constraints on what type of values it accepts. Inputs are considered identical if they are === to each other.

**Examples**

**Example 1:**

```
Input: 
getInputs = () => [[2,2],[2,2],[1,2]]
fn = function (a, b) { return a + b; }
Output: [{"val":4,"calls":1},{"val":4,"calls":1},{"val":3,"calls":2}]
Explanation:
const inputs = getInputs();
const memoized = memoize(fn);
for (const arr of inputs) {
  memoized(...arr);
}

For the inputs of (2, 2): 2 + 2 = 4, and it required a call to fn().
For the inputs of (2, 2): 2 + 2 = 4, but those inputs were seen before so no call to fn() was required.
For the inputs of (1, 2): 1 + 2 = 3, and it required another call to fn() for a total of 2.
```

**Example 2:**

```
Input: 
getInputs = () => [[{},{}],[{},{}],[{},{}]] 
fn = function (a, b) { return ({...a, ...b}); }
Output: [{"val":{},"calls":1},{"val":{},"calls":2},{"val":{},"calls":3}]
Explanation:
Merging two empty objects will always result in an empty object. It may seem like there should only be 1 call to fn() because of cache-hits, however none of those objects are === to each other.
```

**Example 3:**

```
Input: 
getInputs = () => { const o = {}; return [[o,o],[o,o],[o,o]]; }
fn = function (a, b) { return ({...a, ...b}); }
Output: [{"val":{},"calls":1},{"val":{},"calls":1},{"val":{},"calls":1}]
Explanation:
Merging two empty objects will always result in an empty object. The 2nd and 3rd third function calls result in a cache-hit. This is because every object passed in is identical.
```

**Constraints**

- 1 <= inputs.length <= 105
- 0 <= inputs.flat().length <= 105
- inputs[i][j] != NaN

## 题目（中文翻译）

**描述**  
给定一个函数 `fn`，返回该函数的**记忆化**（memoized）版本。  
记忆化函数是一种在相同输入下永远不会再次调用原函数 `fn` 的函数，而是直接返回缓存的结果。  
`fn` 可以是任意函数，对其接受的参数类型没有限制。若两个输入的每个参数之间使用严格相等 `===` 判等为真，则认为这两个输入是相同的。

**示例 1**  
```javascript
Input: 
getInputs = () => [[2,2],[2,2],[1,2]]
fn = function (a, b) { return a + b; }
Output: [{"val":4,"calls":1},{"val":4,"calls":1},{"val":3,"calls":2}]
```
**解释**：  
```javascript
const inputs = getInputs();
const memoized = memoize(fn);
for (const arr of inputs) {
  memoized(...arr);
}
```  
- 对输入 `(2, 2)`：`2 + 2 = 4`，此时需要调用一次 `fn()`。  
- 再次对相同的输入 `(2, 2)`：结果仍是 `4`，但因为参数严格相等，直接返回缓存值，不再调用 `fn()`。  
- 对输入 `(1, 2)`：`1 + 2 = 3`，这是第一次出现的参数组合，需要调用 `fn()`，因此 `calls` 为 2。

**示例 2**  
```javascript
Input: 
getInputs = () => [[{},{}],[{},{}],[{},{}]] 
fn = function (a, b) { return ({...a, ...b}); }
Output: [{"val":{},"calls":1},{"val":{},"calls":2},{"val":{},"calls":3}]
```
**解释**：  
合并两个空对象始终得到空对象。看起来应该只调用一次 `fn()` 就能命中缓存，但这里的每个对象实例彼此之间 **不** 满足 `===`，所以每次调用都是缓存未命中，`fn()` 被调用了三次。

**示例 3**  
```javascript
Input: 
getInputs = () => { const o = {}; return [[o,o],[o,o],[o,o]]; }
fn = function (a, b) { return ({...a, ...b}); }
Output: [{"val":{},"calls":1},{"val":{},"calls":1},{"val":{},"calls":1}]
```
**解释**：  
同样是合并两个空对象，结果为 `{}`。第二次和第三次调用都命中了缓存，因为传入的对象引用完全相同（`===` 为真），所以 `fn()` 只被调用了一次。

**约束条件**  
- `1 <= inputs.length <= 10^5`  
- `0 <= inputs.flat().length <= 10^5`  
- `inputs[i][j] != NaN`   (即不存在 `NaN` 参数)

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**把每一次调用的实参全部记下来**，下次再来时把新实参和已经记录的所有实参逐个比较，只要有一组完全相同（`===`，在 Python 中对应 `is`），就直接返回之前缓存的结果，否则就真的去调用一次 `fn` 并把结果保存。

- **数据结构**：用一个列表 `history` 保存所有已经出现过的调用记录。每条记录是  
  ```python
  (args_tuple, result)          # args_tuple = (a, b, c, …)
  ```
  列表就像我们生活中常用的“纸质登记本”，往后翻看每一页，看是否已经有相同的输入。

- **为什么正确**：只要我们保证每一次比较都使用 **对象的身份**（`is`），就完全符合题目中 “inputs are considered identical if they are === to each other” 的要求。若找到了相同的输入，就一定可以直接返回之前算好的结果。

- **时间/空间复杂度**  
  - **时间**：第 `i` 次调用要遍历前面已经保存的 `i‑1` 条记录，最坏情况下要比较 `i‑1` 次。把所有 `n` 次调用加起来就是  
    \[
    1 + 2 + \dots + (n-1) = O(n^2)
    \]
    用大白话说，就是 **随着调用次数的增加，耗时会呈二次方增长**，当 `n` 达到几万甚至上万时会非常慢。
  - **空间**：我们把每一次不同的输入都保存下来，最坏需要保存 `n` 条记录，空间是 **O(n)**。

#### 代码（Python）

```python
def memoize_bruteforce(fn):
    """
    暴力版 memoize：把所有调用历史保存在列表里，逐个比较。
    """
    history = []                 # 用来存放 (args_tuple, result)

    def wrapper(*args):
        # 1. 在历史记录中寻找完全相同的参数（使用 is 比较身份）
        for stored_args, stored_res in history:
            if len(stored_args) != len(args):
                continue
            identical = True
            for a, b in zip(stored_args, args):
                if a is not b:   # 身份不相同 → 这不是同一组输入
                    identical = False
                    break
            if identical:       # 找到缓存命中
                return {"val": stored_res, "calls": wrapper.calls}

        # 2. 没命中 → 真的调用 fn
        result = fn(*args)
        wrapper.calls += 1       # 记录真实调用次数
        history.append((args, result))
        return {"val": result, "calls": wrapper.calls}

    wrapper.calls = 0            # 统计 fn 被真正调用的次数
    return wrapper
```

#### 复杂度

- **时间复杂度**：`O(n²)`  
  这里的 `n` 是调用次数。每一次都要遍历已经保存的记录，最坏情况下会比较 `n` 次 → 随着 `n` 增大，耗时会呈二次方增长。

- **空间复杂度**：`O(n)`  
  每一次出现新参数组合都要把它们存进 `history`，所以最多保存 `n` 条记录。

### 2. 最优解

#### 思路  

从暴力解可以看到 **瓶颈** 在于“遍历所有历史记录”。我们需要一种**能够在常数时间内定位到对应缓存**的数据结构。

**关键点**：  
- 题目要求“相同输入”依据是 **对象身份** (`===` / `is`) 而不是值相等。  
- 对象的唯一身份在 Python 中可以用 `id(obj)` 获得，它是对象在内存中的地址，**相同对象的 `id` 永远相等**，不同对象即使内容相同也会得到不同的 `id`。

**思路演进**：

1. **把每个参数的位置独立出来**  
   把函数的第 1 个参数、第 2 个参数……分别视作不同的层级。这样我们可以把所有缓存组织成一棵**树形结构**，树的深度等于函数参数的个数。

2. **每一层使用字典（HashMap）**  
   - 第 1 层的键是第 1 个参数的 `id`，值是指向**下一层**的子字典。  
   - 第 2 层的键是第 2 个参数的 `id`，以此类推。  
   - 当走到最后一层时，保存的值就是 `fn` 的计算结果。

   这棵树的每一条根到叶的路径唯一对应一种参数组合，查找过程只需要 **沿着参数顺序向下走**，每一步都是 O(1) 的哈希查找。

3. **统计真实调用次数**  
   与暴力版相同，维护一个全局计数器 `calls`，每当缓存未命中并真正调用 `fn` 时加一。

**类比**：  
把这棵树想象成一座**邮局的分拣系统**，第一层根据“收件人姓氏”分箱，第二层根据“收件人名字”再细分，最后一层放进具体的信件。只要把信封的每一层信息依次递交，就能在 O(1) 的时间定位到对应的信件（缓存结果）。

#### 代码（Python）

```python
def memoize(fn):
    """
    最优版 memoize：使用嵌套 dict（类似多层哈希表）实现 O(k) 查找，
    其中 k = 参数个数（题目中 k 很小，常数级）。
    """
    cache_root = {}          # 整棵树的根
    calls = 0                # 统计 fn 被真实调用的次数

    def wrapper(*args):
        nonlocal calls
        node = cache_root

        # 1️⃣ 逐层下钻：每一层的键使用 id(arg)（对象的唯一身份）
        for i, arg in enumerate(args):
            key = id(arg)                 # 对象的“身份证号”
            if key not in node:           # 没有这条路 → 需要新建子节点
                node[key] = {}
            node = node[key]              # 移动到子节点继续处理下一个参数

        # 2️⃣ 检查叶子是否已经存有结果
        if "_result" in node:             # 缓存命中
            return {"val": node["_result"], "calls": calls}
        else:                             # 缓存未命中 → 真正调用 fn
            result = fn(*args)
            calls += 1
            node["_result"] = result      # 把结果写进叶子
            return {"val": result, "calls": calls}

    return wrapper
```

**关键行解释**：

- `key = id(arg)`：把对象的内存地址当作哈希键，等价于 JavaScript 中的 `===` 判断。即使两个对象内容相同，只要不是同一个实例，它们的 `id` 就不同，缓存不会误命中。
- `node[key] = {}`：如果这一路还没有走过，就新建一个子字典，类似在邮局新建一个分拣箱。
- `if "_result" in node`：叶子节点保存的键 `_result` 用来存放函数的返回值。若已经存在，说明之前算过，直接返回。
- `calls += 1`：只有真正调用 `fn` 时才加一，正好对应题目要求的 “calls”。

#### 复杂度

- **时间复杂度**：`O(k)`，其中 `k` 为函数的参数个数（题目中 `k` ≤ 10⁵ 的平面上，实际是一个很小的常数）。  
  与暴力解的 `O(n²)` 相比，**即使调用次数达到 10⁵，每一次只需要遍历几层哈希表，几乎是瞬间完成**。

- **空间复杂度**：`O(m * k)`，`m` 是不同参数组合的数量。每一种新组合在树中占用 `k` 个字典节点，所以总空间随缓存大小线性增长。相较于暴力解的 `O(m)`（每条记录都存一整套参数），这在常数因子上略大，但仍然是线性可接受的。

## 心得

- **核心技巧**：利用 **对象身份 (`id`) + 多层哈希表（树形结构）** 实现 O(1)（或 O(k)）的缓存查找。  
- **适用的题型**  
  1. 任意函数的记忆化（Memoization）——如 LeetCode “Memoize I/II”。  
  2. 多参数函数的**去重**或**频次统计**（需要区分同值不同对象的情况）。  
  3. 实现 **LRU Cache**、**Trie** 等需要快速定位的结构时，也常用类似的多层映射思路。  
- **一句话总结**：**把每个参数的唯一身份当作一层哈希键，层层下钻就能在常数时间命中缓存**。

## 反思

- **第一反应**：先把所有调用历史保存下来，逐个比对——最直观但容易忽视效率。  
- **最容易踩的坑**  
  - **对象相等 vs. 对象身份**：`==` 判断值相等，而题目要求 `===`（Python 中的 `is`），必须使用 `id` 或 `is` 来比较。  
  - **不可哈希对象**（如 dict、list）直接做键会报错，必须使用它们的 `id` 作为哈希键。  
  - **参数个数不固定**：需要在树的深度上动态适配，而不是写死某个层数。  
- **下次类似题的第一步**：**先思考“如何把每个参数唯一标识出来”，再决定使用哪种数据结构（单层哈希、嵌套哈希、Trie 等）来实现 O(1) 查找**。这样可以迅速从暴力思路跳到高效实现。
