# #2951. 寻找峰值 / Find the Peaks

> 难度：简单 · 标签：Array、Enumeration · [LeetCode 链接](https://leetcode.com/problems/find-the-peaks/)

---

## 题目（英文原版）

**Description**

You are given a 0-indexed array mountain. Your task is to find all the peaks in the mountain array.
Return an array that consists of indices of peaks in the given array in any order.
Notes:

**Examples**

**Example 1:**

```
Input: mountain = [2,4,4]
Output: []
Explanation: mountain[0] and mountain[2] can not be a peak because they are first and last elements of the array.
mountain[1] also can not be a peak because it is not strictly greater than mountain[2].
So the answer is [].
```

**Example 2:**

```
Input: mountain = [1,4,3,8,5]
Output: [1,3]
Explanation: mountain[0] and mountain[4] can not be a peak because they are first and last elements of the array.
mountain[2] also can not be a peak because it is not strictly greater than mountain[3] and mountain[1].
But mountain [1] and mountain[3] are strictly greater than their neighboring elements.
So the answer is [1,3].
```

**Constraints**

- 3 <= mountain.length <= 100
- 1 <= mountain[i] <= 100

## 题目（中文翻译）

你得到一个 **0 索引（0-indexed）** 的数组（array）`mountain`。请找出数组中所有的峰值（peak），并返回一个包含这些峰值所在索引（index）的数组，顺序不限。

**说明**  
- 峰值必须严格大于其左右相邻的元素。  
- 数组的第一个和最后一个元素不能是峰值，因为它们只有一个相邻元素。

**示例 1**  
```text
Input: mountain = [2,4,4]
Output: []
Explanation: mountain[0] 和 mountain[2] 不能是峰值，因为它们分别是数组的首元素和尾元素。  
mountain[1] 也不能是峰值，因为它并没有严格大于 mountain[2]。  
因此答案为空数组 []。
```

**示例 2**  
```text
Input: mountain = [1,4,3,8,5]
Output: [1,3]
Explanation: mountain[0] 和 mountain[4] 不能是峰值，因为它们是数组的首元素和尾元素。  
mountain[2] 也不能是峰值，因为它没有严格大于 mountain[3] 和 mountain[1]。  
但 mountain[1] 和 mountain[3] 均严格大于各自的相邻元素，故它们是峰值。  
因此答案为 [1,3]。
```

**约束条件**  
- `3 <= mountain.length <= 100`  
- `1 <= mountain[i] <= 100`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是把数组从左到右遍历一遍，**只看中间的元素**（下标 1 ~ n‑2），判断它是否比左边和右边的元素都大。  
- **数据结构**：只需要原始的列表 `mountain`，不需要额外的数据结构。可以把列表想成一排排山坡的高度，**遍历**就像走在山路上，一步一步查看当前点的左右两侧。  
- **为什么正确**：题目定义“峰”必须满足 `mountain[i] > mountain[i-1]` 且 `mountain[i] > mountain[i+1]`，遍历时恰好检查了这两个不等式，满足即是峰。  
- **复杂度**：我们对每个中间位置检查一次，最多检查 `n‑2` 次，时间随 `n` 成线性关系，用大白话说就是“跑一遍山路”。空间只用了保存答案的列表，和输入大小无关。

#### 代码（Python）

```python
from typing import List

def find_peaks(mountain: List[int]) -> List[int]:
    """
    暴力扫描：逐个检查中间位置是否比左右相邻元素都大
    """
    n = len(mountain)
    peaks = []                     # 用来存放所有峰的下标

    # 0 和 n-1 位置不可能是峰，直接从 1 开始遍历到 n-2
    for i in range(1, n - 1):
        # 判断当前元素是否严格大于左右邻居
        if mountain[i] > mountain[i - 1] and mountain[i] > mountain[i + 1]:
            peaks.append(i)       # 找到峰，记录下标

    return peaks
```

#### 复杂度

- **时间复杂度**：`O(n)` —— 只需要遍历一次数组，`n` 是数组长度。用生活化的说法，就是“看一遍山路，路长多少就花多少时间”。
- **空间复杂度**：`O(k)` —— 其中 `k` 为峰的个数（最坏情况下 `k ≈ n/2`），额外使用的空间只用来存放答案。若只计入**额外**的非输出空间，则为 `O(1)`（常数级别）。

---

### 2. 最优解

#### 思路  

从暴力解可以看到，**遍历一次已经能得到答案**，而且每个位置只需要看它左右各一个元素，无法再省掉任何检查。因此 `O(n)` 已经是理论上的下界——如果不看某个位置，就可能错过一个峰。

所以“最优解”仍然是 **一次线性扫描**，只是在实现细节上进一步简化：

1. 直接在遍历时把符合条件的下标加入结果列表，不需要额外的标记数组。  
2. 使用 Python 的列表推导式或 `enumerate`，代码更简洁，但本质上仍是一次遍历。

#### 代码（Python）

```python
from typing import List

def find_peaks_opt(mountain: List[int]) -> List[int]:
    """
    最优解：一次遍历，利用 enumerate 简化写法
    """
    # 只遍历中间的元素（下标 1 ~ len-2），满足条件就直接加入结果
    return [i for i in range(1, len(mountain) - 1)
            if mountain[i] > mountain[i - 1] and mountain[i] > mountain[i + 1]]
```

#### 复杂度

- **时间复杂度**：`O(n)` —— 与暴力解相同，仍然只需要一次线性遍历。因为已经达到了最小可能的遍历次数，所以无法再更快。  
- **空间复杂度**：`O(k)`（或 `O(1)` 计入输出之外）——只用来存放返回的峰下标列表。

## 心得

- **核心技巧**：**一次线性扫描 + 相邻比较**。只要满足 “左、右都更小” 的条件，就可以确定峰。  
- **适用的题型**：  
  1. “寻找局部极值” 类题目（如 LeetCode 1629 `Slowest Key` 的局部最大值）。  
  2. “山脉数组” 相关的题目（如寻找山峰的起点/终点）。  
- **解题钥匙**：**只要相邻两侧都更小，就一定是峰；遍历一次即可。**

## 反思

- **第一反应**：看到“峰”字就想到“比左右都高”，于是立刻想到遍历检查。  
- **最容易踩的坑**：  
  - 忘记排除数组首尾，因为它们没有左/右邻居。  
  - “严格大于”而不是“大于等于”，容易把相等的情况误判为峰。  
- **下次的第一步**：先确认“局部条件”是什么（这里是 `> left && > right`），然后决定是否需要全局信息。若只依赖局部信息，线性扫描往往是最直接也是最优的方案。
