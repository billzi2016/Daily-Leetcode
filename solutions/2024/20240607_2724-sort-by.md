# #2724. 排序依据 / Sort By

> 难度：简单 · 标签： · [LeetCode 链接](https://leetcode.com/problems/sort-by/)

---

## 题目（英文原版）

**Description**

Given an array arr and a function fn, return a sorted array sortedArr. You can assume fn only returns numbers and those numbers determine the sort order of sortedArr. sortedArr must be sorted in ascending order by fn output.
You may assume that fn will never duplicate numbers for a given array.

**Examples**

**Example 1:**

```
Input: arr = [5, 4, 1, 2, 3], fn = (x) => x
Output: [1, 2, 3, 4, 5]
Explanation: fn simply returns the number passed to it so the array is sorted in ascending order.
```

**Example 2:**

```
Input: arr = [{"x": 1}, {"x": 0}, {"x": -1}], fn = (d) => d.x
Output: [{"x": -1}, {"x": 0}, {"x": 1}]
Explanation: fn returns the value for the "x" key. So the array is sorted based on that value.
```

**Example 3:**

```
Input: arr = [[3, 4], [5, 2], [10, 1]], fn = (x) => x[1]
Output: [[10, 1], [5, 2], [3, 4]]
Explanation: arr is sorted in ascending order by number at index=1.
```

**Constraints**

- arr is a valid JSON array
- fn is a function that returns a number
- 1 <= arr.length <= 5 * 105

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把 **每个元素** 都和 **其他所有元素** 比一遍，找到它在排序后应该出现的位置。  
这相当于我们在排队时，**一个人要和前面所有已经排好序的人比较**，如果比他们都大，就站到最后；否则插到合适的位置。  
实现上可以使用**冒泡排序**或**插入排序**：

- **数据结构**：直接在原数组上操作，不需要额外的结构。  
- **函数 `fn` 的作用**：把任意对象映射成一个数字，这个数字决定了排序顺序。可以把 `fn` 想象成“称重机”，每个对象称完重后，根据重量（数字）排队。

因为 `fn` 对每个元素只会返回唯一的数字（题目保证不重复），只要我们把 **比较的依据** 换成 `fn(x)`，普通的比较排序算法仍然成立。

#### 代码（Python）

```python
def sort_by_brute(arr, fn):
    """
    暴力实现：插入排序 + fn 作为比较键
    时间复杂度 O(n²)，适合演示思路。
    """
    # 复制一份，防止修改原数组
    res = list(arr)

    # 插入排序：从左到右逐个插入已经排好序的子数组
    for i in range(1, len(res)):
        cur = res[i]            # 当前待插入的元素
        cur_key = fn(cur)       # 用 fn 计算排序依据
        j = i - 1

        # 将比 cur_key 大的元素往后搬，空出位置
        while j >= 0 and fn(res[j]) > cur_key:
            res[j + 1] = res[j]
            j -= 1

        # 把 cur 放到正确的位置
        res[j + 1] = cur

    return res
```

#### 复杂度  

- **时间复杂度**：`O(n²)`  
  - “n²” 可以想象成**每个人要和其他所有人比较一次**。当数组有 10,000 条时，比较次数会达到 100,000,000 次，明显太慢。  
- **空间复杂度**：`O(1)`（不计返回数组的额外空间）  
  - 只在原数组上原地交换，不需要额外的存储。

### 2. 最优解

#### 思路  

从暴力解可以看到，**瓶颈在于大量的两两比较**。  
如果我们一次性把每个元素对应的 `fn` 值算好，交给 **高效的排序算法**（如快速排序、归并排序、堆排序），就可以把比较次数降到 `n log n`。

Python 的内置函数 `sorted`（或列表的 `list.sort`）已经实现了 **Timsort**，这是一种结合了归并排序和插入排序的混合算法，最坏情况时间复杂度是 `O(n log n)`，而且 **稳定**（相同键值的元素相对顺序不变），非常适合本题。

实现要点：

1. **一次性计算键值**：`sorted` 接收 `key` 参数，它会在排序前为每个元素调用一次 `fn`，把返回值缓存下来，后面的比较只用这些缓存的数字，避免重复计算。  
2. **返回新数组**：题目要求返回排好序的数组，不修改原数组，`sorted` 正好符合要求。  

> 类比：把所有人先称完重量，记录下来，然后按照重量从小到大排队，只需要一次比较就能决定顺序，而不是每次都重新称。

#### 代码（Python）

```python
def sort_by(arr, fn):
    """
    最优实现：利用 Python 内置的 Timsort（O(n log n)）并通过 key=fn
    只遍历一次数组，计算 fn 的返回值，随后高效排序。
    """
    # sorted 会返回一个新列表，不会修改原 arr
    # key 参数会把每个元素传给 fn，fn 的返回值作为排序依据
    return sorted(arr, key=fn)
```

#### 复杂度  

- **时间复杂度**：`O(n log n)`  
  - “n log n” 可以理解为**每增加一次元素，只会让比较次数乘以一个很小的常数（约等于 log₂n）**，远远小于 n²。比如 1,000,000 条数据，`log₂1,000,000 ≈ 20`，比较次数约为 20,000,000，远比 1,000,000,000,000（n²）要少。  
- **空间复杂度**：`O(n)`（用于存放排序过程中产生的临时数组）  
  - Timsort 需要额外的临时空间，大约是原数组的 `n` 倍的一小部分（实际实现中约为 `n/2`），这在题目允许的 5×10⁵ 大小范围内是可以接受的。

## 心得

- **核心技巧**：利用 **`key` 参数** 把自定义的映射函数交给高效的排序实现。  
- **适用的题型**  
  1. “根据对象的某个属性排序” 如 LeetCode 179 （Largest Number）  
  2. “把复杂结构映射成数值后排序” 如 “按照员工工资排序”  
  3. “多维数组按指定列排序” 如 “按二维坐标的 y 值升序排列”。  
- **一句话总结**：**把比较的“重量”提前算好，用内置的 `sorted(key=…)` 一次搞定**。

## 反思

- **第一反应**：直接想用 `sorted(arr, key=fn)`，因为 Python 已经把这件事封装好了。  
- **最容易踩的坑**  
  - **`fn` 可能抛异常**：如果数组里有 `None` 或者缺失的属性，`fn` 会报错，需要保证输入合法（题目已保证）。  
  - **原数组不应被修改**：如果使用 `list.sort()`，会原地修改，需要注意返回值的区别。  
  - **大数据量时的内存**：`sorted` 会创建新列表，若对空间极度敏感，可考虑原地排序 `arr.sort(key=fn)`（但要确认是否可以修改原数组）。  
- **下次遇到同类题**：**先思考是否可以把比较键提前算好**，再把任务交给语言自带的高效排序函数，而不是自己实现低效的两两比较。
