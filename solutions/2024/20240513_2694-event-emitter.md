## 题目（中文翻译）

设计一个 `EventEmitter` 类。该接口的功能类似（但有细微差别）于 Node.js 中的 `EventEmitter` 或 DOM 中的 `EventTarget` 接口。`EventEmitter` 应支持订阅（subscribe）事件以及触发（emit）事件。

`EventEmitter` 类应实现以下两种方法（以及对应的取消订阅方法）：

- `subscribe(eventName, callback)`：订阅指定事件，返回一个唯一的订阅标识（subscription id）。
- `emit(eventName, args?)`：触发指定事件，可选地向回调函数传入参数数组 `args`。
- `unsubscribe(subscriptionId)`：根据之前返回的订阅标识取消对应的订阅。

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  

最直接的想法就是把每个事件对应的所有回调函数 **全部存到一个列表里**，  
然后在 `emit` 的时候遍历这个列表，依次调用回调并把返回值收集起来。  

- **数据结构**：使用 Python 的 `dict`（相当于生活中的“查字典”，键是事件名字，值是该事件的回调列表）。  
- **订阅** (`subscribe`)：把回调函数 `fn` 直接 `append` 到 `dict[event]` 对应的列表中。  
- **触发** (`emit`)：取出 `dict[event]`，遍历列表 `for fn in callbacks:`，调用 `fn(*args)`（如果没有参数则空调用），把每次返回的结果装进一个新列表返回。  
- **取消订阅** (`unsubscribe`)：因为题目只要求 **按下标** 取消最近一次的订阅（下标是全局的、从 0 开始），我们可以把所有的订阅 **顺序保存在一个数组** `all_subs`，每次 `subscribe` 时把 `(event, fn)` 加进去并返回它的下标。`unsubscribe(idx)` 时只需要把 `all_subs[idx]` 标记为 “已删除”，随后在 `emit` 时检查该标记即可。

> 这里的 “标记为已删除” 类似把字典里的一本书撕掉一页，却不把整本书搬走，后面遍历时只要跳过空位就行了。

这种实现思路非常直观，几乎不需要任何技巧。

#### 代码（Python）  

```python
from typing import Any, Callable, Dict, List

class EventEmitter:
    def __init__(self) -> None:
        # event -> [callback, callback, ...]
        self._events: Dict[str, List[Callable]] = {}
        # 全局的订阅记录，index 就是题目要求的 subscription id
        self._all_subs: List[tuple[str, Callable] | None] = []

    # ---------- 订阅 ----------
    def subscribe(self, event: str, fn: Callable) -> int:
        """把 fn 加入 event 的回调列表，返回全局下标"""
        # 1) 确保 event 有对应的列表
        self._events.setdefault(event, [])
        # 2) 加入列表
        self._events[event].append(fn)
        # 3) 记录全局下标并返回
        sub_id = len(self._all_subs)
        self._all_subs.append((event, fn))
        return sub_id

    # ---------- 取消订阅 ----------
    def unsubscribe(self, sub_id: int) -> None:
        """根据全局下标删除对应的回调（标记为 None）"""
        record = self._all_subs[sub_id]
        if record is None:          # 已经被删除过，直接返回
            return
        event, fn = record
        # 在对应的 event 列表中把该函数置为 None（懒删除）
        callbacks = self._events[event]
        for i, cb in enumerate(callbacks):
            if cb is fn:
                callbacks[i] = None
                break
        # 同时把全局记录也置为 None，防止二次删除
        self._all_subs[sub_id] = None

    # ---------- 触发 ----------
    def emit(self, event: str, args: List[Any] | None = None) -> List[Any]:
        """调用所有该 event 的回调，返回它们的返回值列表"""
        if args is None:
            args = []
        results: List[Any] = []
        for fn in self._events.get(event, []):
            if fn is None:          # 被取消订阅的占位，直接跳过
                continue
            results.append(fn(*args))
        return results
```

> 关键行的中文注释已在代码中标明，直接复制运行即可。

#### 复杂度  

- **时间复杂度**  
  - `subscribe`：O(1) —— 只往列表尾部加一个元素。  
  - `unsubscribe`：最坏 O(k)，其中 *k* 为该事件已订阅回调的数量（因为要遍历列表找出对应的函数）。  
  - `emit`：O(k) —— 需要遍历该事件的所有回调一次。  

  大白话：`k` 就是“有多少人对这个事件感兴趣”。如果很多人关注，同一次 `emit` 就要花比较多的时间。

- **空间复杂度**  
  - 需要保存所有回调函数以及它们的对应关系，整体是 O(n)，n 为总的订阅次数。

### 2. 最优解  

#### 思路  

在暴力实现里，**取消订阅** 是性能瓶颈：我们要在事件的回调列表里找到对应的函数并把它删掉，这一步是线性的。  
如果能够在 **O(1)** 时间内完成取消订阅，整体效率就会提升。

思路如下：

1. **为每一次订阅分配唯一的 id**（即题目里返回的下标）。  
2. 用一个全局字典 `id -> (event, fn)` 保存这条记录，**直接根据 id 就能定位到回调函数**。  
3. 同时，**每个事件仍然用列表保存回调**，但列表里保存的是 **(id, fn)** 的二元组。  
4. 取消订阅时：  
   - 通过 `id` 直接在全局字典里取到对应的 `(event, fn)`。  
   - 在该事件的列表里**把对应的条目标记为 None**（不必真的删除，以免移动后面的元素导致 O(k)）。  
   - 同时把全局字典的这条记录删掉或设为 None。  

这样，**`unsubscribe` 只做两次哈希查找和一次赋值**，时间是 O(1)。  
`emit` 仍然需要遍历该事件的回调列表，但只会跳过被标记为 None 的位置，复杂度不变。  

> 类比：把每个订阅想成一本书的章节号，章节号写在目录里（全局字典），而章节的正文仍在原书里。想删章节时，只要在目录里找到章节号，然后把正文对应的页码涂掉（标记为 None），不必把整本书重新排版。

#### 代码（Python）  

```python
from typing import Any, Callable, Dict, List, Tuple

class EventEmitter:
    def __init__(self) -> None:
        # event -> [(sub_id, callback), ...]
        self._events: Dict[str, List[Tuple[int, Callable]]] = {}
        # 全局 id -> (event, callback)   用于 O(1) 找到对应位置
        self._id_map: Dict[int, Tuple[str, Callable]] = {}
        self._next_id: int = 0                # 递增生成唯一 id

    # ---------- 订阅 ----------
    def subscribe(self, event: str, fn: Callable) -> int:
        """返回本次订阅的唯一 id（即题目要求的下标）"""
        sub_id = self._next_id
        self._next_id += 1

        # 记录全局映射
        self._id_map[sub_id] = (event, fn)

        # 事件对应的列表中保存 (id, fn)
        self._events.setdefault(event, []).append((sub_id, fn))
        return sub_id

    # ---------- 取消订阅 ----------
    def unsubscribe(self, sub_id: int) -> None:
        """O(1) 时间完成取消订阅"""
        pair = self._id_map.pop(sub_id, None)   # 若已删除则返回 None
        if pair is None:
            return
        event, fn = pair

        # 在该事件的列表里把对应条目标记为 None
        callbacks = self._events[event]
        for i, (cid, cb) in enumerate(callbacks):
            if cid == sub_id:
                callbacks[i] = None            # 懒删除
                break

    # ---------- 触发 ----------
    def emit(self, event: str, args: List[Any] | None = None) -> List[Any]:
        """调用所有未被取消的回调，返回它们的返回值列表"""
        if args is None:
            args = []
        results: List[Any] = []
        for entry in self._events.get(event, []):
            if entry is None:            # 已被取消
                continue
            sub_id, fn = entry
            results.append(fn(*args))
        return results
```

**解释关键点**  

- `self._next_id` 保证每一次 `subscribe` 都得到一个全局唯一的整数，后面可以直接用它定位。  
- `self._id_map` 相当于“目录”，`sub_id -> (event, fn)`，因此 `unsubscribe` 只需要一次哈希查找。  
- 事件列表里保存 `(sub_id, fn)` 而不是单纯的 `fn`，是为了在 `unsubscribe` 时能快速匹配到正确的条目（因为同一个函数可能在不同事件或多次订阅）。  
- 标记为 `None` 的位置在 `emit` 时会被跳过，避免了列表的真实删除导致的搬移成本。

#### 复杂度  

- **时间复杂度**  
  - `subscribe`：O(1) —— 只做几次哈希写入和列表 `append`。  
  - `unsubscribe`：O(1) —— 通过全局 `id_map` 直接定位，再把列表对应位置设为 `None`。  
  - `emit`：O(k) —— 仍需遍历该事件的所有回调（k 为该事件当前有效订阅数），但跳过 `None` 的开销极小。  

  与暴力解相比，`unsubscribe` 从线性下降到常数时间，整体更快，尤其在大量“先订阅后取消”的场景下优势明显。

- **空间复杂度**  
  - 需要保存每一次订阅的信息两份（一次在全局 `id_map`，一次在对应事件的列表），仍是 O(n)，其中 n 为总的订阅次数。额外的常数级指针开销可以忽略不计。

## 心得  

- **核心技巧**：**为每一次订阅分配唯一 ID 并使用哈希表实现 O(1) 取消**。  
- **适用的题型**（类似思路）：  
  1. “设计订阅/发布系统” 类的题目（如 LeetCode 1460 – Make Two Arrays Equal With Swaps）。  
  2. “实现取消/撤销功能” 的数据结构（如设计浏览器的前进/后退栈、撤销编辑器操作）。  
- **一句话总结**：**用全局唯一标识 + 哈希表实现“懒删除”，即可在 O(1) 时间完成取消订阅**。

## 反思  

- **第一反应**：直接把每个事件的回调放进列表，`unsubscribe` 时遍历列表寻找并删除。  
- **最容易踩的坑**：  
  - 题目要求 `unsubscribe` 接收的是 **全局下标**，而不是事件内部的下标，需要额外的映射。  
  - `emit` 的第二个参数是**可选的数组**，若不提供要当成空列表处理。  
  - 取消订阅后仍然要保持原来的下标不变，否则后续的下标会错位。  
- **下次遇到同类题**：第一步就思考 **是否需要 O(1) 删除**，如果是，就立刻为每个元素生成唯一 ID 并维护一个全局哈希表，以实现“懒删除”。
