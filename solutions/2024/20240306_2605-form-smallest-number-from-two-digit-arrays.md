## 题目（中文翻译）

**题目描述**

给定两个只包含唯一数字（digit）的整数数组 `nums1` 和 `nums2`，每个数字均在 `1` 到 `9` 之间。请构造一个最小的正整数，使得该整数至少包含来自 `nums1` 的一个数字和来自 `nums2` 的一个数字。

- 如果两个数组中存在相同的数字，则该数字本身即可构成满足条件的最小整数，直接返回该单个数字。
- 否则，需要组成一个两位数（two‑digit number），其中一位取自 `nums1`，另一位取自 `nums2`（顺序任意），返回所有可能两位数中的最小值。

**示例**

*示例 1*  
输入：`nums1 = [4,1,3]`, `nums2 = [5,7]`  
输出：`15`  
解释：数字 `15` 由 `nums1` 中的数字 `1` 和 `nums2` 中的数字 `5` 组成。可以证明 `15` 是能够得到的最小整数。

*示例 2*  
输入：`nums1 = [3,5,2,6]`, `nums2 = [3,1,7]`  
输出：`3`  
解释：数字 `3` 同时出现在两个数组中，单个数字 `3` 已满足条件。

**约束条件**

- `1 <= nums1.length, nums2.length <= 9`
- `1 <= nums1[i], nums2[i] <= 9`
- 每个数组内的数字互不相同。

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把 **所有可能的组合** 都列出来，然后挑最小的那个。  
- **数据结构**：我们只需要把两个数组的数字分别取出来，用两个 `for` 循环遍历它们的笛卡尔积（所有配对），这相当于把「每个数字」当成「字典里的词」，把「配对」当成「查找所有可能的解释」。
- **为什么正确**：题目要求构造一个 **包含 nums1 中至少一个数字、且包含 nums2 中至少一个数字** 的最小整数。遍历所有配对（包括把 nums1 的数字放在十位、nums2 的放在个位，或者相反），我们一定会碰到答案。只要把所有得到的整数记下来，取最小值即可。
- **复杂度分析**：  
  - `len(nums1)` 最多 9，`len(nums2)` 也最多 9，配对数是 `9 × 9 = 81`，常数很小。  
  - **时间复杂度** 用大 O 表示是 `O(m·n)`（m、n 分别是两个数组的长度），这里最多 `O(9·9) = O(1)`，但从概念上讲是二次的。可以把 `O(m·n)` 想象成「每个苹果都要和每个橙子配对一次」的工作量。  
  - **空间复杂度** 只用了几个临时变量，和输入规模无关，记为 `O(1)`（常数级空间）。

#### 代码（Python）

```python
def smallestNumber(nums1, nums2):
    # 记录目前找到的最小答案，初始设为一个很大的数
    best = float('inf')

    # 1. 检查是否有公共数字，若有直接返回（只需要一位数）
    set1 = set(nums1)
    for x in nums2:
        if x in set1:          # 公共数字就能组成唯一的 1 位数
            return x          # 因为数字都是 1~9，最小的公共数字就是答案

    # 2. 暴力枚举所有两位数的可能
    for a in nums1:           # a 来自 nums1
        for b in nums2:       # b 来自 nums2
            # a 在十位，b 在个位
            cand1 = 10 * a + b
            # b 在十位，a 在个位
            cand2 = 10 * b + a
            best = min(best, cand1, cand2)   # 取最小的那个

    return best
```

#### 复杂度  

- **时间复杂度**：`O(m·n)`  
  - 这里的 `m = len(nums1)`，`n = len(nums2)`。可以把它想成「每个 nums1 的数字都要和每个 nums2 的数字配对一次」的工作量。由于 `m,n ≤ 9`，实际运行时间几乎是瞬间完成。  
- **空间复杂度**：`O(1)`  
  - 只用了常数个变量（集合 `set1`、循环计数器和几个整数），不随输入规模增长。

### 2. 最优解  

#### 思路  

从暴力解可以看到，**答案最多只有两位数**：  

1. **如果两数组有公共数字**，只需要这一个数字本身（1 位数）就是最小答案。  
2. **没有公共数字**，只能用两个不同的数字拼成两位数。  

这时我们不必遍历所有配对，只要找出每个数组中的最小数字 `a_min`、`b_min`，然后比较两种拼法：

- `10 * a_min + b_min`（`a_min` 在十位）  
- `10 * b_min + a_min`（`b_min` 在十位）

因为十位数字对大小的影响最大，选最小的十位一定能得到全局最小的两位数。  

**关键点**：  
- **集合（哈希表）** 用来快速判断「是否有公共数字」。集合查找的时间复杂度是 **O(1)**，就像在字典里查词一样快。  
- **最小值** 只需要一次线性扫描即可得到，时间也是 **O(m+n)**。

#### 代码（Python）

```python
def smallestNumber(nums1, nums2):
    # 1️⃣ 用集合判断是否有公共数字
    s1 = set(nums1)
    common = s1.intersection(nums2)   # 交集，相当于查“两个词典里都有的词”
    if common:                         # 如果交集非空
        return min(common)            # 直接返回最小的公共数字（1 位数）

    # 2️⃣ 没有公共数字 → 只需要各自的最小数字
    a_min = min(nums1)   # nums1 中最小的数字
    b_min = min(nums2)   # nums2 中最小的数字

    # 计算两种拼法的结果，取更小的那个
    cand1 = 10 * a_min + b_min   # a_min 在十位
    cand2 = 10 * b_min + a_min   # b_min 在十位
    return min(cand1, cand2)
```

#### 复杂度  

- **时间复杂度**：`O(m + n)`  
  - 建立集合 `O(m)`，求交集（在 `nums2` 中逐个检查）`O(n)`，再各自找最小值各 `O(m)`、`O(n)`。整体是线性的，远快于 `O(m·n)` 的暴力枚举。  
  - 用生活化的说法：只要「遍历一次」每个数组，就能得到答案，就像只需要一次扫视就能找出书架上最薄的那本书。  
- **空间复杂度**：`O(m)`（集合占用的空间）  
  - 只存了 `nums1` 的全部元素在哈希表里，最多 9 个整数，属于常数级空间。

## 心得  

- **核心技巧**：先判断是否能用“一位数”直接解决（公共数字），否则只需比较两种两位数的拼法。  
- **适用场景**：  
  1. “两个集合的最小公共元素” 类问题（例如 LeetCode 350. 两个数组的交集 II）。  
  2. “构造最小/最大数” 需要考虑位数和排列顺序的题目（如 179. 最大数、1689. 形如 xy 的最小数）。  
- **解题钥匙**：**先问**「结果最多几位？」如果位数上限很小，往往能用**枚举+数学推导**直接得到 O(1) 解。

---  

## 反思  

- **第一反应**：把所有可能的两位数列出来再取最小。  
- **最容易踩的坑**：  
  - 忘记先检查公共数字，导致不必要的两位数比较。  
  - 对于两位数的拼法，只比较 `10*a+b` 而忘记 `10*b+a`，会漏掉更小的情况。  
- **下次思路**：看到「数组长度 ≤ 9」且「数字都是 1~9」时，立刻思考**答案的位数上限**（这里是 1 或 2 位），再决定是直接枚举还是用数学推导。这样可以快速定位最优解的方向。
