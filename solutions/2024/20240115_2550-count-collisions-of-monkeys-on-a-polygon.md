## 解题过程

### 1. 直觉解（暴力）

#### 思路  

每只猴子只能往相邻的两个顶点走：**顺时针**（记作 `C`）或**逆时针**（记作 `A`）。  
于是对 `n` 只猴子来说，所有可能的移动方式就是把 `n` 个二进制位全部枚举出来——每个位 `0/1` 代表一种方向。  

要判断一次移动是否会产生**碰撞**，我们只要检查两件事：

1. **顶点碰撞**：移动后是否有两个（或更多）猴子落在同一个顶点。  
   - 可以把「顶点 → 落在这里的猴子数量」看成一本**查字典**（哈希表），键是顶点编号，值是出现次数。只要出现次数 `≥ 2` 就说明碰撞。

2. **边上相撞**：两只猴子是否在同一条边上相向而行。  
   - 对每只猴子记录它走过的**有向边** `(from, to)`。如果出现一条边的**相反方向** `(to, from)` 也被别的猴子走过，就说明在这条边上相撞。

只要满足上面任意一种情况，就算这次移动“有碰撞”。把所有产生碰撞的方案数加起来，就是答案。

> **为什么暴力一定能得到正确答案？**  
> 因为我们把**所有**可能的移动方式（`2ⁿ` 种）都枚举了一遍，并且对每一种方式都用最直接的方式检查是否出现碰撞。只要检查的规则完整，答案必然正确。

#### 代码（Python）

```python
MOD = 10**9 + 7

def has_collision(n, moves):
    """
    moves[i] == 0 -> 猴子 i 顺时针走到 (i+1) % n
    moves[i] == 1 -> 猴子 i 逆时针走到 (i-1+n) % n
    """
    # 记录每个顶点最终落了几只猴子
    vertex_cnt = [0] * n
    # 记录已经走过的有向边，用集合存 (from, to)
    edges = set()

    for i in range(n):
        if moves[i] == 0:               # 顺时针
            to = (i + 1) % n
        else:                           # 逆时针
            to = (i - 1 + n) % n

        vertex_cnt[to] += 1
        if vertex_cnt[to] >= 2:         # 顶点上出现了 ≥2 只猴子
            return True

        # 检查是否有相反方向的边已经出现
        if (to, i) in edges:            # 另一只猴子正好从 to -> i
            return True
        edges.add((i, to))

    return False


def brute_force(n):
    """暴力枚举 2^n 种移动方式，统计有碰撞的方案数"""
    total = 0
    for mask in range(1 << n):          # 0 ~ 2^n-1
        moves = [(mask >> i) & 1 for i in range(n)]
        if has_collision(n, moves):
            total += 1
    return total % MOD


# ---------- 示例运行 ----------
if __name__ == "__main__":
    for n in range(3, 6):
        print(f"n={n}, 暴力答案={brute_force(n)}")
```

> 关键行解释  
> - `for mask in range(1 << n)`: 用二进制枚举所有方向组合。  
> - `vertex_cnt[to] += 1`: 把每只猴子落到的顶点计数，类似“查字典”。  
> - `if (to, i) in edges`: 检查是否已有猴子走相反的有向边，即**边上相撞**。

#### 复杂度

- **时间复杂度**：`O(2ⁿ · n)`  
  - “2ⁿ” 是所有可能的移动方式数，`n` 是每种方式里遍历所有猴子所需的时间。  
  - 用大白话说，就是“随着猴子数量翻倍，所有可能的组合会指数级增长”，所以这套方法只适合 `n` 很小（比如 ≤20）的练手。

- **空间复杂度**：`O(n)`  
  - 需要 `vertex_cnt` 和 `edges` 两个长度为 `n`（或 `O(n)`) 的容器来记录状态。

### 2. 最优解

#### 思路  

**暴力的瓶颈**在于我们把所有 `2ⁿ` 种移动方式都遍历了一遍，而实际上我们只需要关心**是否会碰撞**，而不是每一种具体的排列。  

观察题目：  
- 每只猴子只能走到相邻的顶点。  
- 为了**不产生顶点碰撞**，每个顶点在移动后必须恰好有 **一只** 猴子。换句话说，**入度 = 出度 = 1**（每个顶点恰好被一只猴子走进，也恰好有一只猴子走出）。  
- 为了**不产生边上相撞**，同一条无向边上不允许出现两只猴子相向而行。等价地，**同一条有向边**不能被两只猴子同时使用（否则会出现反向的另一条有向边）。

把这些条件放在**环形（n 顶点的多边形）**上思考：

1. **入度 = 出度 = 1** 的约束已经把所有可能的“走向”限制为**每条边只能被恰好一只猴子使用**，否则会导致某个顶点的入度不为 1。  
2. 环上每条无向边只有两个方向可选。如果我们在某条边上让一只猴子走 **顺时针**，那么它的**对端顶点**必须把这只猴子送到下一个顶点（因为该顶点只能有一个出边）。于是整个环的方向被迫统一——**所有猴子都只能顺时针走**，或**全部逆时针走**。  
   - 任何混合的走向（例如有的顺时针、有的逆时针）都会在某个顶点产生两个入边或两个出边，导致顶点碰撞或边上相撞。  
3. 因此，**不产生任何碰撞的合法走法只有两种**：  
   - 全部顺时针（形成一个长度为 `n` 的有向环）  
   - 全部逆时针（同理）

于是我们把**求“至少一次碰撞的方案数”**转化为**“总方案数减去不碰撞的方案数”**：

- **总方案数** = 每只猴子有 2 种选择 → `2ⁿ`  
- **不碰撞方案数** = 2（全顺时针或全逆时针）  

答案 = `2ⁿ - 2`（记得对 `10⁹+7` 取模）。

> **为什么只剩这两种？**  
> 把每只猴子看成把 **一条有向边** 放在环上。因为每个顶点只能恰好收到一条有向边（入度 1），所以所有有向边必须连成一个**同向的环**。环只有两种方向，故只有两种合法放法。

#### 代码（Python）

```python
MOD = 10**9 + 7

def count_collisions(n: int) -> int:
    """
    返回至少有一次碰撞的移动方式数量，取模 1e9+7
    思路：答案 = 2^n - 2（两种不碰撞的情况：全顺时针或全逆时针）
    """
    total = pow(2, n, MOD)          # 快速幂，直接得到 2^n % MOD
    ans = (total - 2) % MOD         # 防止负数，+MOD 再 % MOD 也可以
    return ans


# ---------- 示例 ----------
if __name__ == "__main__":
    for n in (3, 4, 5, 10**9):
        print(f"n={n} -> {count_collisions(n)}")
```

> 关键行解释  
> - `pow(2, n, MOD)`：Python 内置的**快速幂**实现，时间 `O(log n)`，即使 `n` 达到 `10⁹` 也毫秒级完成。  
> - `(total - 2) % MOD`：先减去两种安全走法，再对模数取余，确保答案始终是正数。

#### 复杂度

- **时间复杂度**：`O(log n)`（快速幂的二进制指数）  
  - 与 `n` 的大小呈对数关系，几乎可以视作常数时间。  
- **空间复杂度**：`O(1)`  
  - 只使用了几个整数变量，不随 `n` 增长。

相比暴力的 `O(2ⁿ·n)`，这是天壤之别，能够轻松处理 `n` 高达 `10⁹` 的极限。

## 心得

- **核心技巧**：**先计总数再减去“安全”情况**（容斥思想的最简版）。  
- **适用场景**：  
  1. “多少种排列会出现某种冲突”，先算全部排列，再减去**无冲突**的排列（如**无相邻相同颜色**、**不相交路径**）。  
  2. “在环/链上每个元素有两种选择，要求不出现特定模式”，往往可以通过**结构约束**直接求出合法模式的数量（本题只剩 2 种）。  
- **一句话总结解题钥匙**：**在环形结构中，要求每个顶点入度=出度=1 必然导致全局同向，碰撞数 = 2ⁿ‑2**。

## 反思

- **第一反应**：看到“每只猴子有两种走法”，立刻想到**枚举 2ⁿ 种**，并尝试直接模拟检查碰撞。  
- **最容易踩的坑**：  
  - 忽略**边上相撞**的情况，只检查顶点是否重复，会导致计数错误。  
  - 对大 `n` 使用暴力会超时或内存爆炸。  
- **下次类似题的第一步**：先**思考约束是否强到只能产生极少数合法情况**（比如入度/出度固定），再尝试**用“总数‑合法数”**的思路快速求解。
