# #2826. 三组排序 / Sorting Three Groups

> 难度：中等 · 标签：Array、Binary Search、Dynamic Programming · [LeetCode 链接](https://leetcode.com/problems/sorting-three-groups/)

---

## 题目（英文原版）

**Description**

You are given an integer array nums. Each element in nums is 1, 2 or 3. In each operation, you can remove an element from nums. Return the minimum number of operations to make nums non-decreasing.

**Examples**

**Example 1:**

```
Input: nums = [2,1,3,2,1]
Output: 3
Explanation:
One of the optimal solutions is to remove nums[0] , nums[2] and nums[3] .
```

**Example 2:**

```
Input: nums = [1,3,2,1,3,3]
Output: 2
Explanation:
One of the optimal solutions is to remove nums[1] and nums[2] .
```

**Example 3:**

```
Input: nums = [2,2,2,2,3,3]
Output: 0
Explanation:
nums is already non-decreasing.
```

**Constraints**

- 1 <= nums.length <= 100
- 1 <= nums[i] <= 3

## 题目（中文翻译）

你得到一个整数数组 `nums`。数组中的每个元素只能是 `1、2、3` 中的一个。在一次操作中，你可以从 `nums` 中删除任意一个元素。返回使得 `nums` 变为非递减（non‑decreasing）所需的最少操作次数。

**示例 1**  
**输入**: `nums = [2,1,3,2,1]`  
**输出**: `3`  
**解释**:  
一种最优的做法是删除下标 `0`、`2` 和 `3` 处的元素。

**示例 2**

**输出**: `2`  
**解释**:  
一种最优的做法是删除下标 `1` 和 `2` 处的元素。

**示例 3**  
**输入**: `nums = [2,2,2,2,3,3]`  
**输出**: `0`  
**解释**:  
`nums` 已经是非递减的。

**约束条件**  

- `1 <= nums.length <= 100`  
- `1 <= nums[i] <= 3`   (其中 `nums[i]` 只能取值 1、2、3)

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  

最直接的想法是 **枚举所有可能的删除方式**，即把原数组的每一个元素都决定是“留下”还是“删除”。  
- 把数组看成一本书的章节，每一章可以选择保留（放进新书）或丢弃（直接撕掉）。  
- 所有章节的保留/删除组合形成 **2ⁿ 种可能**（`n` 为数组长度）。  
- 对每一种组合，取出被保留下来的元素，检查它们是否已经是 **非递减** 的（即 1 ≤ 2 ≤ 3 的顺序）。  
- 记录能够保留下来的元素最多的组合，最少需要删除的元素数 = `n - 最长合法子序列的长度`。  

这一步之所以 **正确**，是因为我们把所有合法的保留方式都遍历了一遍，必然会找到最长的合法子序列。  

> **时间/空间复杂度**  
> - 时间：我们要检查 `2ⁿ` 种子集，每一种子集最多遍历一次数组来判断是否非递减，时间复杂度是 **O( n·2ⁿ )**。  
>   - 大白话：如果数组有 20 个元素，就要尝试大约一百万次；如果有 30 个，就要超过十亿次，明显不可接受。  
> - 空间：只需要保存当前子集的状态（比如一个位掩码），空间复杂度是 **O(1)**（不计输入本身）。

#### 代码（Python）

```python
from itertools import product

def min_operations_bruteforce(nums):
    n = len(nums)
    best_keep = 0                     # 最多可以保留下来的元素个数

    # 用二进制位表示每个位置是保留(1)还是删除(0)
    for mask in range(1 << n):        # 0 ~ 2^n-1
        kept = []                     # 当前子集留下的元素
        for i in range(n):
            if mask >> i & 1:         # 第 i 位为 1 → 保留
                kept.append(nums[i])

        # 判断 kept 是否已经是非递减的
        ok = True
        for i in range(1, len(kept)):
            if kept[i] < kept[i - 1]: # 出现倒序，非法
                ok = False
                break
        if ok:
            best_keep = max(best_keep, len(kept))

    return n - best_keep               # 需要删除的最少元素数
```

#### 复杂度  

- **时间复杂度**：`O(n·2ⁿ)` —— 随着 `n` 的增长，指数级别的增长几乎不可能在实际面试中通过。  
- **空间复杂度**：`O(1)` —— 只用了常数级别的额外空间。

### 2. 最优解  

#### 思路  

从暴力解可以看出，**枚举所有子集太慢**，瓶颈在于“每个元素独立决定保留与否”。  
观察题目：  
- 数组里只有 **三种取值**：`1、2、3`。  
- “非递减” 对应的顺序恰好是 **所有的 1 在左，接着是 2，最后是 3**。  

因此，我们只需要决定 **三个区间** 的边界，而不是每个元素的去留：

```
[0, i)      → 这里应该全是 1
[i, j)      → 这里应该全是 2
[j, n)      → 这里应该全是 3
```

`i`、`j` 可以取 `0 … n`（左闭右开），且满足 `0 ≤ i ≤ j ≤ n`。  
只要固定 `i`、`j`，我们就能 **立即算出** 需要删除多少元素：

- 在 `[0, i)` 区间里，**不是 1 的元素** 必须删掉。  
- 在 `[i, j)` 区间里，**不是 2 的元素** 必须删掉。  
- 在 `[j, n)` 区间里，**不是 3 的元素** 必须删掉。  

把这三块删掉的元素数量相加，就是该划分下的操作数。遍历所有合法的 `(i, j)`，取最小值即可。  

要快速求出每个区间里 “不是某个值的个数”，我们使用 **前缀计数**（类似字典查单词的页码）。  

- `pref[k][v]` 表示 **前 k 个元素中值等于 v 的数量**（`v∈{1,2,3}`）。  
- 那么在区间 `[l, r)`（左闭右开）里值为 `v` 的个数 = `pref[r][v] - pref[l][v]`。  
- 区间长度 = `r - l`。于是 “不是 v 的个数” = `(r - l) - (pref[r][v] - pref[l][v])`。  

由于 `n ≤ 100`，`O(n²)` 的遍历完全够快，且实现简洁。

> **核心数据结构解释**  
> - **前缀和**：想象把数组从左到右逐步累加，每一步都记录到目前为止出现了多少个 1、多少个 2、多少个 3。以后想知道任意子段里有多少个 2，只要用 “右端点的累计 - 左端点的累计”。这就像查字典时先看整本书的目录（前缀），再定位到具体章节。  

#### 代码（Python）

```python
def min_operations(nums):
    n = len(nums)

    # 1. 建立前缀计数表，pref[i][v] 表示前 i 个元素中值为 v 的个数
    # 为了下标方便，v 使用 1、2、3 直接作列索引；第 0 行全部为 0（空前缀）
    pref = [[0, 0, 0, 0] for _ in range(n + 1)]
    for i, x in enumerate(nums, 1):          # i 从 1 开始对应 nums[i-1]
        pref[i][1] = pref[i - 1][1] + (x == 1)
        pref[i][2] = pref[i - 1][2] + (x == 2)
        pref[i][3] = pref[i - 1][3] + (x == 3)

    ans = n                                   # 最坏情况：全部删除

    # 2. 枚举所有合法的 i、j（0 ≤ i ≤ j ≤ n）
    for i in range(n + 1):
        for j in range(i, n + 1):
            # 区间 [0, i) 应全是 1
            len1 = i                         # 区间长度
            cnt1 = pref[i][1]                # 1 的实际个数
            del1 = len1 - cnt1               # 不是 1 的要删

            # 区间 [i, j) 应全是 2
            len2 = j - i
            cnt2 = pref[j][2] - pref[i][2]
            del2 = len2 - cnt2

            # 区间 [j, n) 应全是 3
            len3 = n - j
            cnt3 = pref[n][3] - pref[j][3]
            del3 = len3 - cnt3

            total_del = del1 + del2 + del3
            ans = min(ans, total_del)        # 取最小的删除次数

    return ans
```

#### 复杂度  

- **时间复杂度**：`O(n²)`  
  - 两层循环遍历 `i、j`（最多 `n·(n+1)/2` 次），每次只做常数次算术运算。  
  - 与暴力的指数级别相比，`n=100` 时最多 5,000 次，几乎瞬间完成。  
- **空间复杂度**：`O(n)`  
  - 前缀计数表占用 ` (n+1) × 4` 的整数空间，随 `n` 线性增长。

## 心得  

- **核心技巧**：利用**值域有限**（只有 1、2、3）把排序问题转化为“划分三段并统计错误位置”。  
- **适用场景**：  
  1. **只含少数离散取值的排序/分组问题**（如把 0、1、2 排序）。  
  2. **最少删除/替换使数组满足单调或分段单调**（如 “最少删除使数组只出现两种数”。）  
  3. **使用前缀计数快速统计任意子段特定元素个数**（如 “区间中出现最多的数字”。）  
- **一句话总结**：**把“每个元素是否保留”压缩成“每种数字的区间边界”，再用前缀计数快速算代价**。

## 反思  

- **第一反应**：直接想到最长非递减子序列（LIS），于是想写 O(n log n) 的通用算法。可是这里的取值只有三种，完全可以用更简洁的区间划分。  
- **最容易踩的坑**：  
  - 忘记区间是 **左闭右开**，导致计数时出现重复或遗漏。  
  - `i`、`j` 取到 `0` 或 `n` 时对应的区间可能为空，必须确保代码对空区间也能正常返回 `0` 删除。  
  - 前缀数组的下标容易写错（第 `i` 行对应前 `i` 个元素），建议先手写几行验证。  
- **下次类似题的第一步**：检查**取值范围是否很小**，如果是，就考虑**枚举分段边界 + 前缀计数**的思路，而不是直接套通用的动态规划或 LIS。
