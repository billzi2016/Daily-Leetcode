# #2549. 统计棋盘上不同的数字 / Count Distinct Numbers on Board

> 难度：简单 · 标签：Array、Hash Table、Math、Simulation · [LeetCode 链接](https://leetcode.com/problems/count-distinct-numbers-on-board/)

---

## 题目（英文原版）

**Description**

You are given a positive integer n, that is initially placed on a board. Every day, for 109 days, you perform the following procedure:
Return the number of distinct integers present on the board after 109 days have elapsed.
Note:

**Examples**

**Example 1:**

```
Input: n = 5
Output: 4
Explanation: Initially, 5 is present on the board. 
The next day, 2 and 4 will be added since 5 % 2 == 1 and 5 % 4 == 1. 
After that day, 3 will be added to the board because 4 % 3 == 1. 
At the end of a billion days, the distinct numbers on the board will be 2, 3, 4, and 5.
```

**Example 2:**

```
Input: n = 3
Output: 2
Explanation: 
Since 3 % 2 == 1, 2 will be added to the board. 
After a billion days, the only two distinct numbers on the board are 2 and 3.
```

**Constraints**

- 1 <= n <= 100

## 题目（中文翻译）

给定一个正整数 `n`，最初将 `n` 放在棋盘上。随后共进行 `10^9` 天的操作。每一天，你都执行以下过程：

- 对棋盘上**当前存在的每个整数** `a`，遍历所有满足 `2 ≤ b < a` 且 `a % b == 1` 的整数 `b`（其中 `%` 表示取模运算），将这些 `b` 加入棋盘（若已在棋盘上则不再重复添加）。

在 `10^9` 天结束后，返回棋盘上**不同整数的数量**。

Output: 4
Explanation: 最初棋盘上只有 5。  
第二天，加入 2 和 4，因为 5 % 2 == 1 且 5 % 4 == 1。  
随后一天，加入 3，因为 4 % 3 == 1。  
经过十亿天后，棋盘上出现的不同数字为 2、3、4、5，共计 4 个。
```

Output: 2

```

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**把题目说的“每天的过程”完整地模拟一遍**：

1. 用一个 `set` 保存黑板上出现过的所有整数（集合天然去重，类似字典里的“查字典”——key 是数字，value 不关心）。  
2. 每天遍历当前集合里的每个数 `x`，再枚举 `i = 2 … x`（因为 `1` 永远不可能满足 `x % i == 1`），如果 `x % i == 1` 就把 `i` 加进集合。  
3. 重复上面的步骤 `10⁹` 次，或者**只要一天没有新增数字就提前结束**（因为以后再也不会产生新数了）。

> **为什么这样能得到正确答案**  
> 题目规定的“每天的过程”正是上面两层循环实现的行为：对每个已经在黑板上的数 `x`，检查所有可能的除数 `i`，把满足余数为 `1` 的 `i` 加进去。只要我们完整地执行这些规则，最终集合里出现的数字必然和题目要求的一致。

> **时间/空间复杂度**  
> - 每天我们最多遍历集合中所有数字（最多 `n` 个），对每个数字再枚举它本身大小的范围。最坏情况下相当于 **`O(n²)`** 的工作量（`n ≤ 100`，所以实际运行非常快）。  
> - 由于我们只用一个 `set` 保存不超过 `n` 个不同的整数，**空间是 `O(n)`**。

> **大白话解释**  
> `O(n²)` 可以想象成“如果有 100 本书，每本书都要检查 100 页”，这在电脑里算是很小的量。`O(n)` 则像“只需要记下 100 本书的名字”，占用的空间也很有限。

#### 代码（Python）

```python
def countDistinct_bruteforce(n: int) -> int:
    # 用集合保存已经出现的数字，类似字典的查词表，只关心“出现没出现”
    board = {n}
    # 最多进行 10⁹ 次循环，但实际上只要一天没有新增就可以提前结束
    for _ in range(10**9):
        new_numbers = set()               # 当天新加入的数字
        for x in board:                   # 遍历当前所有数字
            # i 从 2 开始，因为 1 永远不满足 x % i == 1
            for i in range(2, x + 1):
                if x % i == 1:            # 满足题目条件就加入
                    new_numbers.add(i)
        # 如果这一天没有新数字，说明以后再也不会产生新数，直接退出
        if not new_numbers:
            break
        board.update(new_numbers)         # 把新数字合并进集合
    return len(board)                     # 集合大小就是不同数字的个数
```

#### 复杂度

- **时间复杂度**：`O(n²)` —— 这里的 `n` 其实就是题目给出的最大数字（≤100），所以实际运行时间几乎可以忽略不计。  
- **空间复杂度**：`O(n)` —— 只需要保存至多 `n` 个不同的整数。

### 2. 最优解

#### 思路  

从暴力解可以看到，**瓶颈在于每天都要遍历所有已知数字并枚举它们的每一个可能除数**。然而我们不必真的去“模拟”这么久，因为题目只要求 **最终** 会出现多少种不同的数字，而不是每一天的具体过程。

观察题目和提示：

1. **对于任意 `n > 2`，都有 `n % (n-1) = 1`**。  
   这意味着在第一天，`n-1` 必然被加入黑板。  

2. **一旦 `k`（`2 ≤ k ≤ n-1`）进入集合，它本身也满足 `k % (k-1) = 1`**（同理），于是 `k-1` 再次被加入。  

3. 通过上述“链式”关系，**从 `n` 开始我们可以不断往下得到 `n-1, n-2, … , 2`**，每一次都满足余数为 `1` 的条件。  

4. 由于我们会进行 `10⁹` 天（远远大于 `n`），**所有这些数都会在足够早的时间出现**，随后再也不会产生新的数（唯一不能出现的是 `1`，因为没有任何正整数 `x` 能满足 `x % 1 = 1`）。  

5. 唯一的例外是 `n = 1`：此时板上只有 `1`，而 `1 % i` 永远不等于 `1`（`i` 必须大于 `1` 才有意义），所以 **最终只会有 `1` 这一个数**。

> **核心结论**  
> - 当 `n = 1` 时，答案是 `1`。  
> - 当 `n > 1` 时，所有 `2 … n` 都会出现，答案就是 `n-1`。

> **类比**  
> 想象一条楼梯，最高层是 `n`。每走一步，你都可以往下一层（`n-1`）走，因为 `当前层 % (下一层) = 1`。只要时间足够久（`10⁹` 天），你一定能走到最底层 `2`，但永远走不到 `1`（因为没有 “层数-1” 能满足条件），于是所有层（`2 … n`）都会被踩到。

#### 代码（Python）

```python
def countDistinct_optimal(n: int) -> int:
    """
    根据数学推导直接返回答案：
    - n == 1 -> 只会有 1
    - n > 1  -> 2~n 都会出现，数量为 n-1
    """
    if n == 1:
        return 1
    return n - 1
```

#### 复杂度

- **时间复杂度**：`O(1)` —— 只做一次判断和一次减法，常数时间。相比暴力的 `O(n²)`，快得不可思议。  
- **空间复杂度**：`O(1)` —— 只使用了几个整数变量，几乎不占用额外空间。

## 心得

- **核心技巧**：把“每天的过程”抽象为**数学递推关系**，利用 **余数恒等式**（`x % (x-1) = 1`）快速得到所有会出现的数。  
- **适用的题型**  
  1. 需要在大量迭代后求“最终集合大小”，而迭代规则可以归纳为递推或单调下降的情形。  
  2. 通过**数论恒等式**（如 `a % (a-1) = 1`、`a % a = 0`）直接推出结果的题目。  
  3. “长时间模拟”但**状态空间很小**，可以通过状态压缩或直接推导得到闭式解的题目。  

- **一句话总结**：**只要发现递推的“必然下降”规律，就能把千亿次模拟化简为常数时间的公式**。

## 反思

- **第一反应**：看到“10⁹ 天”就想直接写循环模拟，担心会超时，于是先实现暴力版验证思路。  
- **最容易踩的坑**  
  - 忽略 `n = 1` 的特殊情况，导致返回 `0`（因为 `n-1 = 0`）而不符合题意。  
  - 误以为 `1` 也会被加入，实际上没有任何数的余数会等于 `1` 当除数是 `1`。  
- **下次遇到同类题**：第一步先**思考是否存在单调或循环不变的数学规律**，如果能找到，就直接写公式；否则再考虑模拟。这样可以避免不必要的高时间复杂度实现。
