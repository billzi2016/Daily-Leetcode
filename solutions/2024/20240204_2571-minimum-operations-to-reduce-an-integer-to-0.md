# #2571. 将整数减至 0 的最少操作次数 / Minimum Operations to Reduce an Integer to 0

> 难度：中等 · 标签：Dynamic Programming、Greedy、Bit Manipulation · [LeetCode 链接](https://leetcode.com/problems/minimum-operations-to-reduce-an-integer-to-0/)

## 题目（英文原版）

**Description**

You are given a positive integer n, you can do the following operation any number of times:
Return the minimum number of operations to make n equal to 0.
A number x is power of 2 if x == 2i where i >= 0.

**Examples**

**Example 1:**

```
Input: n = 39
Output: 3
Explanation: We can do the following operations:
- Add 20 = 1 to n, so now n = 40.
- Subtract 23 = 8 from n, so now n = 32.
- Subtract 25 = 32 from n, so now n = 0.
It can be shown that 3 is the minimum number of operations we need to make n equal to 0.
```

**Example 2:**

```
Input: n = 54
Output: 3
Explanation: We can do the following operations:
- Add 21 = 2 to n, so now n = 56.
- Add 23 = 8 to n, so now n = 64.
- Subtract 26 = 64 from n, so now n = 0.
So the minimum number of operations is 3.
```

**Constraints**

- 1 <= n <= 105

## 题目（中文翻译）

描述  
给定一个正整数 **n**，你可以无限次执行以下操作：  
- 将 **n** 加上或减去一个 2 的幂（power of 2），即 **2^i**，其中 **i ≥ 0**。  

返回使 **n** 等于 0 所需的最小操作次数。  

一个数 **x** 为 2 的幂当且仅当 **x == 2^i** 且 **i ≥ 0**。

示例  
示例 1:  
输入: `n = 39`  
输出: `3`  
解释: 我们可以按如下顺序操作:  
- 将 **2^0 = 1** 加到 **n**，此时 **n = 40**。  
- 将 **2^3 = 8** 减去 **n**，此时 **n = 32**。  
- 将 **2^5 = 32** 减去 **n**，此时 **n = 0**。  
可以证明，3 是将 **n** 变为 0 的最少操作次数。

示例 2:  
输入: `n = 54`  
输出: `3`  
解释: 我们可以按如下顺序操作:  
- 将 **2^1 = 2** 加到 **n**，此时 **n = 56**。  
- 将 **2^3 = 8** 加到 **n**，此时 **n = 64**。  
- 将 **2^6 = 64** 减去 **n**，此时 **n = 0**。  
因此最少操作次数为 3。

约束条件  
- `1 <= n <= 10^5`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把「把 n 变成 0」看成一次一次的「加」或「减」一个 2 的幂（`1, 2, 4, 8 …`），把所有可能的操作序列枚举出来，找到最短的那条。  
这可以用 **广度优先搜索 (BFS)** 来实现：

1. 把初始整数 `n` 放进队列，记为第 0 步。  
2. 每次弹出队首 `cur`，尝试对每个 `2^i (i≥0)`  
   * `next = cur + 2^i`  
   * `next = cur - 2^i`  
   把没有出现过的 `next` 加入队列，步数加 1。  
3. 第一次碰到 `0` 时，当前步数就是答案。

> **生活化类比**：  
> 想象你在一条数轴上走路，每一步只能向左或向右迈出「1、2、4、8…」这样的步长。我们要找最少步数回到原点（0），就像在迷宫里用 BFS 按层层展开的方式寻找最近的出口。

**为什么正确**  
BFS 按层遍历所有「一步能到达的数」 → 「两步能到达的数」 → …，因此第一次遇到目标 `0` 时，必然是最少步数。

**复杂度分析（大白话）**  

- **时间复杂度**：每个数字会被访问一次，然而数字的取值范围是 **无限的**（因为我们可以一直加），所以在最坏情况下搜索会无限扩散，实际只能在很小的 `n`（比如 `n≤20`）时跑完。可以把它想成「跑步时不停往前跑，永远跑不完」——不切实际。  
- **空间复杂度**：同理，需要保存所有已经访问过的数字，同样会爆炸。  

> 综上，暴力 BFS 只能作为「思考的起点」，在正式提交时会超时或内存爆炸。

#### 代码（Python）

```python
from collections import deque

def min_operations_bruteforce(n: int) -> int:
    """仅用于演示，实际 n 较大时会超时/爆内存"""
    if n == 0:
        return 0

    # BFS 队列，存 (当前值, 已用步数)
    q = deque([(n, 0)])
    visited = {n}

    # 为防止无限增长，设一个合理的上限（这里仅用于演示）
    LIMIT = 2 * n + 10

    while q:
        cur, steps = q.popleft()
        # 遍历所有可能的 2 的幂，直到超出 LIMIT
        i = 0
        while (pow2 := 1 << i) <= LIMIT:
            for nxt in (cur + pow2, cur - pow2):
                if nxt == 0:                     # 找到答案
                    return steps + 1
                if -LIMIT <= nxt <= LIMIT and nxt not in visited:
                    visited.add(nxt)
                    q.append((nxt, steps + 1))
            i += 1
    return -1  # 理论上不会到这里
```

> **关键行中文注释**  
> - `1 << i`：把 1 左移 i 位，等价于 `2^i`，相当于「查字典」里「词」是 `i`，对应的「页码」是 `2^i`。  
> - `visited`：类似「已经看过的页面」集合，防止重复走同样的路。

#### 复杂度

- **时间复杂度**：`O(k * m)`，其中 `k` 是搜索层数，`m` 是每层尝试的幂次数。对大 `n` 来说几乎是指数级，实际不可接受。  
- **空间复杂度**：`O(k * m)`，同理，需要存储大量中间状态。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **每一步都枚举所有 2 的幂**，导致搜索空间爆炸。  
观察二进制可以发现：

|  操作  | 作用 |
|-------|------|
| `+ 2^i` | 把第 `i` 位的 **0** 变成 **1**，如果该位本来是 **1** 则会产生进位（相当于把后面的连续 `1` “向左搬”）|
| `- 2^i` | 把第 `i` 位的 **1** 变成 **0**，如果该位是 **0** 则会向左借位（把左边的 `1` “搬下来”）|

**核心观察**  
- 当二进制中出现 **连续的 1**（例如 `...0111`），我们可以 **一次** 通过 `+2^k`（把最高的 0 变成 1）把所有低位的 1 同时变成 0（因为产生进位），随后再用一次 `-2^{k+1}` 把新产生的 1 消掉。  
- 换句话说，**连续的 1 只需要 2 步**（加一次、减一次），而单独的孤立 1 只需要 1 步（直接减掉）。

**贪心策略**  
从低位到高位遍历二进制，维护一个 **进位 `carry`**（相当于之前的加操作留下的 “向左搬”），对每一位计算 `bit = (n>>i & 1) + carry`（0、1、2）：

| `bit` | 该怎么处理？ | 产生的操作数 | 下一位的 `carry` |
|------|--------------|------------|----------------|
| 0    | 已经是 0，无需操作 | 0 | 0 |
| 1    | 只能 **减** 这个 `2^i`（或加后再减，步数更多）| +1 | 0 |
| 2    | 相当于 **出现了 1 且有进位** → 直接 **加** `2^{i+1}`，把这位和进位一起消掉| +1 | 1 |

但还有一种特殊情况：`bit == 1` 且 **下一位也是 1**（即出现 `...11`），此时 **加** `2^i` 更好，因为会把两个 1 合并成一个进位，后面只需要一次减法。  
实现时只需要查看 `next_bit = ((n>> (i+1)) & 1) + carry_next`（这里的 `carry_next` 仍是当前的 `carry`），如果 `next_bit == 2`（即下一位也是 1），选择 **加**，否则 **减**。

**算法步骤（伪代码）**

```
ans = 0          # 操作计数
carry = 0        # 进位，初始为 0
for i from 0 while (n >> i) > 0 or carry:
    cur = (n >> i) & 1          # 第 i 位原始值
    cur += carry                # 加上进位
    if cur == 0:                # 00，什么也不做
        carry = 0
    elif cur == 1:              # 01 或 10
        # 看看第 i+1 位是否也是 1（考虑进位）
        nxt = ((n >> (i+1)) & 1) + carry
        if nxt == 2:            # 实际上是 ...11，选择加
            ans += 1
            carry = 1          # 产生向左的进位
        else:                   # 否则直接减
            ans += 1
            carry = 0
    else:   # cur == 2  (10 + carry)
        ans += 1                 # 直接加到更高位
        carry = 1
# 循环结束后如果还有 carry，说明最高位还有一个 1，需要一次减
if carry: ans += 1
return ans
```

**为什么是最优的**  
- 每一位只会产生 **最多一次** 操作（加或减），因为我们已经把「把连续 1 合并」的机会利用掉了。  
- 任何解法都必须把每个二进制 `1`（或 `1`+进位）最终变成 `0`，而我们正好以 **最少的 1 次或 2 次** 处理了所有情况。  
- 该贪心决策只依赖当前位和下一位的信息，属于**局部最优** → **全局最优**（可以通过数学归纳证明，略去细节）。

**时间/空间**  
只遍历二进制位，最多 `log2(n)+2` 次，空间只用常数。

#### 代码（Python）

```python
def min_operations(n: int) -> int:
    """
    贪心 + 位运算，时间 O(log n)，空间 O(1)
    """
    ans = 0          # 记录操作次数
    carry = 0        # 进位（相当于之前的 + 操作留下的“向左搬”）

    i = 0
    # 当还有未处理的位或进位时继续循环
    while (n >> i) > 0 or carry:
        cur = (n >> i) & 1          # 第 i 位原始二进制位（0 或 1）
        cur += carry                # 加上进位，范围可能是 0、1、2

        if cur == 0:                # 00 → 已经是 0，什么也不做
            carry = 0

        elif cur == 1:              # 01 或 10，需要一次操作
            # 查看第 i+1 位加上当前 carry 的情况，判断是否是 "...11"
            nxt = ((n >> (i + 1)) & 1) + carry
            if nxt == 2:            # 实际上是 ...11，选择 “加 2^i”
                ans += 1            # 这一步把第 i 位和进位一起向左搬
                carry = 1           # 产生向更高位的进位
            else:                   # 否则直接 “减 2^i”
                ans += 1
                carry = 0           # 没有新的进位

        else:  # cur == 2，等价于出现了进位且当前位是 1（10 + carry）
            # 直接把这位和进位一起向左搬（相当于 +2^{i+1}）
            ans += 1
            carry = 1               # 仍然保持进位，继续向左传播

        i += 1

    # 循环结束后如果最高位仍有进位，需要再一次操作把它消掉
    if carry:
        ans += 1

    return ans
```

> **关键行中文解释**  
> - `cur += carry`：把「向左搬」的进位加到当前位，就像把左边的「多余的 1」搬到这里。  
> - `nxt = ((n >> (i + 1)) & 1) + carry`：提前看看「左边一位」加上同样的进位会不会也是 2（即 `...11`），决定是「加」还是「减」。  
> - `carry = 1`：相当于「向更高位借/送一个 1」，后面的循环会继续处理它。

#### 复杂度

- **时间复杂度**：`O(log n)`  
  解释：`log n` 就是二进制位数，比如 `n = 10^5` 大约有 17 位，算法只遍历这 17 次。  
- **空间复杂度**：`O(1)`  
  只用了几个整数变量（`ans、carry、i`），不随 `n` 增大而增长。

## 心得

- **核心技巧**：利用二进制的进位/借位特性，**贪心合并连续的 1**，把「加」和「减」的次数压到最少。  
- **适用的题型**  
  1. **把整数变成 0 的最少操作**（本题）。  
  2. **整数加减使二进制中 1 的个数最少**（如 LeetCode 397 `Integer Replacement`）。  
  3. **只允许加/减 2 的幂的最短路径**（如「最小的翻转次数」类题）。  
- **一句话总结解题钥匙**：  
  *“把二进制里连续的 1 合并成一次进位（加），其余单独的 1 直接消掉（减），遍历一次即可得到最少操作数”。*

## 反思

- **第一反应**：看到「加/减 2 的幂」立刻想到 BFS 或 DP，想把所有可能的数列都枚举。  
- **最容易踩的坑**  
  1. **忘记进位的影响**：在处理某一位时，前面已经产生的进位会改变当前位的实际值。  
  2. **边界条件**：最高位如果还有进位，需要额外一次操作，否则会少算 1 步。  
  3. **整数范围**：题目给出 `n ≤ 10^5`，但若直接使用 BFS，会因为搜索空间爆炸而超时。  
- **下次遇到同类题的第一步**：  
  *先把数字写成二进制，观察「连续 1」和「进位」的规律，尝试用「贪心合并」或「位运算」直接求解，而不是暴力枚举。*
