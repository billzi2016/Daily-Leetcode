给定一个按非递减顺序（non‑decreasing order）排序的整数数组 `nums`。  
你可以无限次执行以下操作：

- 选取数组中任意两个**值不同**（different values）的元素，将这两个元素同时删除。

在执行零次或多次上述操作后，返回数组 `nums` 的最小可能长度。

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  

题目给出一个**已排序**的整数数组 `nums`，我们可以无限次执行下面的操作：

- 选取下标 `i < j`，且 `nums[i] < nums[j]`，把这两个数 **一起删除**。

目标是让数组剩下的元素尽可能少，返回最终的最小长度。

> **最直接的想法**  
> 把所有可能的 `(i, j)` 组合都枚举一遍，尝试删除后再继续枚举，直到没有合法的 `(i, j)` 为止。  
> 这就像在玩“配对游戏”，每次找出一对可以消除的数字，然后把它们从数组里撕掉，继续找下一对。

- **用到的数据结构**：  
  - `list`（Python 中的数组）用于存放当前剩余的数字。  
  - 为了方便“删除”，可以把数组复制成一个 `deque`（双端队列），因为从两端弹出元素的时间是 **O(1)**，但这里我们仍然用普通列表来保持思路的简洁。

- **为什么它是正确的**：  
  只要我们把 **所有** 满足 `nums[i] < nums[j]` 的配对都尝试一次，就一定能得到一种合法的删除序列。遍历完所有配对后，若仍有可以配对的元素，说明我们漏掉了某种顺序；所以穷举所有顺序一定可以得到最优（即最短）结果。

- **时间/空间复杂度**：  
  - 对每一次删除，我们都要在剩余的 `n` 个数里 **两层循环** 找到一对合法的 `(i, j)`，最坏情况要检查 `O(n²)` 次。  
  - 每删掉一对，数组长度会减 2，最多删 `n/2` 次，整体仍是 `O(n²)`。  
  - 额外空间只用了复制数组的 `O(n)`。

> **大白话**：  
> `O(n²)` 就像“把所有同学两两握手”，如果班级有 1000 人，那握手次数大约是 1000×1000/2 ≈ 500 000，显然太多了，程序会超时。

#### 代码（Python）

```python
from typing import List

def min_length_bruteforce(nums: List[int]) -> int:
    # 把原数组复制一份，防止修改输入
    arr = nums[:]
    n = len(arr)

    # 暴力搜索每一次可以删除的一对
    while True:
        found = False               # 本轮是否找到可删除的配对
        # i 从左到右，j 从右到左，找到第一个满足条件的配对就删除
        for i in range(n):
            for j in range(i + 1, n):
                if arr[i] < arr[j]:    # 满足题目要求
                    # 删除 i、j 两个位置的元素
                    # 为了不影响后面的索引，先把后面的删掉
                    del arr[j]        # 先删大的下标
                    del arr[i]        # 再删小的下标
                    n -= 2
                    found = True
                    break
            if found:
                break
        # 如果本轮没有找到任何可以删除的配对，说明已经无法继续
        if not found:
            break

    return len(arr)   # 剩余元素的个数
```

> **关键行中文注释**  
> - `if arr[i] < arr[j]:` 判断两数能否配对删除。  
> - `del arr[j]`、`del arr[i]` 先删右侧再删左侧，防止下标错位。  

#### 复杂度  

- **时间复杂度**：`O(n²)`  
  - 每一次循环都要在剩余的 `n` 个数里两层遍历，最坏情况是 `n*(n-1)/2` 次比较。  
- **空间复杂度**：`O(n)`  
  - 只用了一个和原数组等长的副本 `arr`。

### 2. 最优解  

#### 思路  

**从暴力解出发**，我们发现慢的地方在于 **反复遍历整个数组寻找配对**。  
事实上，数组已经是 **非递减排序** 的，这提供了巨大的信息：

1. **最小的数只能和比它大的数配对**，而最大的数只能和比它小的数配对。  
2. 为了让配对次数最多，我们应该**把最左边的 `k` 个数**（最小的）和**最右边的 `k` 个数**（最大的）配在一起。  
   - 直觉：如果把一个中间的数和左边的最小数配对，左边还有更小的数会失去配对机会，显然不是最优的。  

于是问题转化为：**最大的 `k` 是多少，使得**  

```
a[i] < b[i]   (0 ≤ i < k)
```

其中  

- `a` 是数组前 `k` 个数（已经排好序）  
- `b` 是数组后 `k` 个数（同样排好序）  

如果上述不等式对所有 `i` 成立，我们就可以把这 `k` 对全部删掉，剩下的长度就是 `len(nums) - 2*k`。

**如何求最大合法的 `k`？**  

- 由于 `k` 的取值范围是 `[0, n//2]`，我们可以**二分搜索** `k`。  
- 对每个候选 `k`，只需要一次线性扫描比较 `a[i]` 与 `b[i]`，时间 `O(k)`。  
- 二分搜索的层数是 `log₂(n)`，所以总时间是 `O(n log n)`。

**更进一步**：因为数组已经排好序，我们其实不需要二分，只要用**双指针**一次遍历就能直接得到答案：

- `i` 指向最左边，`j` 指向最右边。  
- 当 `nums[i] < nums[j]` 时，这一对可以删除，`i += 1, j -= 1`。  
- 否则（`nums[i] >= nums[j]`），说明左边的最小数已经没有比右边更大的数可以配对，**所有后面的配对也不可能**，直接停止。  

此时剩余的元素个数就是 `j - i + 1`（如果 `i > j`，说明全部删完，长度为 0）。

> **核心概念解释**  
> - **双指针**：把两个指针分别放在数组的两端，像两个人向中间走，每一步根据当前两人的“身高”（这里是数值大小）决定是否配对。  
> - **二分搜索**：在一个有序的搜索空间里，每次把区间砍掉一半，像“猜数字”游戏一样快速定位答案。  

下面分别给出 **二分版** 与 **双指针版** 的实现，二者时间都满足 `O(n)`（二分版的常数更小）。

#### 代码（Python）  

```python
from typing import List

# ---------- 方法一：双指针（最简洁） ----------
def min_length_two_pointers(nums: List[int]) -> int:
    """
    使用双指针一次遍历得到最大可删除的配对数 k，
    最终长度 = len(nums) - 2 * k
    """
    n = len(nums)
    i, j = 0, n - 1          # i 从左边出发，j 从右边出发

    # 当左指针没有超过右指针且左值小于右值时可以配对
    while i < j and nums[i] < nums[j]:
        i += 1                # 左侧最小的数已经配对完
        j -= 1                # 右侧最大的数已经配对完

    # 现在 i..j 区间（如果 i>j 则全部删完）就是剩余的数组
    return j - i + 1 if i <= j else 0


# ---------- 方法二：二分搜索 ----------
def min_length_binary_search(nums: List[int]) -> int:
    """
    通过二分搜索求最大合法的 k（配对数），
    再计算剩余长度。
    """
    n = len(nums)

    # 判定函数：给定 k，检查前 k 个和后 k 个是否全部满足 a[i] < b[i]
    def can_remove(k: int) -> bool:
        # 前 k 个在左侧，后 k 个在右侧
        for i in range(k):
            if nums[i] >= nums[n - k + i]:   # b[i] 位于数组末尾的第 k+i 个位置
                return False
        return True

    lo, hi = 0, n // 2          # k 的搜索范围
    best = 0                    # 记录最大的合法 k

    while lo <= hi:
        mid = (lo + hi) // 2    # 取中间值作为当前尝试的 k
        if can_remove(mid):
            best = mid          # 这一次可以配对，尝试更大的 k
            lo = mid + 1
        else:
            hi = mid - 1        # 不能配对，缩小 k

    # 删除了 2 * best 个元素，剩余长度即为答案
    return n - 2 * best
```

> **代码要点中文注释**  
> - `while i < j and nums[i] < nums[j]:` 只要左边的数比右边的小，就能配对删除。  
> - `i += 1; j -= 1` 配对后把两端指针向中间收拢。  
> - `can_remove(k)` 检查第 `k` 小和第 `k` 大是否都满足 “小于”。  
> - `mid = (lo + hi) // 2` 二分搜索的标准写法。  

#### 复杂度  

- **双指针解**  
  - 时间复杂度：`O(n)` — 只遍历一次数组，像“一次扫地”。  
  - 空间复杂度：`O(1)` — 只用了几个指针变量，额外空间几乎为零。  

- **二分搜索解**  
  - 时间复杂度：`O(n log n)` → 实际上内部的 `can_remove` 只遍历 `k`，而 `k` 随二分层数逐渐增大，总体仍然是 `O(n)`（每个元素最多被比较一次），所以也是线性时间。  
  - 空间复杂度：`O(1)` — 同样只用了常数个变量。  

相比暴力的 `O(n²)`，这两种方法在 10⁵ 规模的数据下能轻松通过。

## 心得  

- **核心技巧**：利用数组已排序的特性，**把最小的 k 个数和最大的 k 个数配对**，并用 **双指针** 或 **二分搜索** 快速求出最大的合法 `k`。  
- **适用题型**（类似思路）  
  1. **“删除两端配对”** 类题目，如 *LeetCode 2134. Minimum Swaps to Group All 1's Together*（需要把左侧最小值与右侧最大值配对）。  
  2. **“找出满足 a[i] < b[i] 的最大配对数”**，比如 *LeetCode 1129. Shortest Path with Alternating Colors* 中的配对思路。  
  3. **“两端贪心”** 的区间压缩问题，如 *LeetCode 1658. Minimum Operations to Reduce X to Zero*（从两端取数的贪心）。  
- **一句话总结解题钥匙**：**把数组两端的最小/最大元素配对，只要左端元素严格小于右端对应元素，就可以一次性删掉一对**。

## 反思  

- **第一反应**：看到“已排序”和“删除一对满足小于的元素”，马上想到**双指针从两端逼近**的贪心思路。  
- **最容易踩的坑**  
  1. **边界条件**：当所有元素相等或完全递增时，`i` 可能直接超过 `j`，需要返回 `0` 而不是负数。  
  2. **下标越界**：在二分检查 `nums[n - k + i]` 时，`k` 为 `0` 时要确保不访问 `n` 索引。  
  3. **误把 “≤” 当成 “<”**：题目要求严格小于，等于时不能配对。  
- **下次遇到同类题**：第一步先**检查数组是否已排序**，如果是，立刻考虑**从两端配对的贪心或二分**，而不是盲目枚举所有组合。
