# #2677. 分块数组 / Chunk Array

> 难度：简单 · 标签： · [LeetCode 链接](https://leetcode.com/problems/chunk-array/)

---

## 题目（英文原版）

**Description**

Given an array arr and a chunk size size, return a chunked array.
A chunked array contains the original elements in arr, but consists of subarrays each of length size. The length of the last subarray may be less than size if arr.length is not evenly divisible by size.
Please solve it without using lodash's _.chunk function.

**Examples**

**Example 1:**

```
Input: arr = [1,2,3,4,5], size = 1
Output: [[1],[2],[3],[4],[5]]
Explanation: The arr has been split into subarrays each with 1 element.
```

**Example 2:**

```
Input: arr = [1,9,6,3,2], size = 3
Output: [[1,9,6],[3,2]]
Explanation: The arr has been split into subarrays with 3 elements. However, only two elements are left for the 2nd subarray.
```

**Example 3:**

```
Input: arr = [8,5,3,2,6], size = 6
Output: [[8,5,3,2,6]]
Explanation: Size is greater than arr.length thus all elements are in the first subarray.
```

**Example 4:**

```
Input: arr = [], size = 1
Output: []
Explanation: There are no elements to be chunked so an empty array is returned.
```

**Constraints**

- arr is a string representing the array.
- 2 <= arr.length <= 105
- 1 <= size <= arr.length + 1

## 题目（中文翻译）

**描述**  
给定一个数组 `arr`（array）和一个块大小 `size`（chunk size），返回一个分块后的数组。  
分块后的数组仍然包含 `arr` 中的所有元素，但由若干子数组（subarray）组成，每个子数组的长度为 `size`。如果 `arr.length` 不能被 `size` 整除，则最后一个子数组的长度可能小于 `size`。  
请在不使用 lodash 的 `_.chunk` 函数的前提下实现。

**示例 1**  
```text
Input: arr = [1,2,3,4,5], size = 1
Output: [[1],[2],[3],[4],[5]]
Explanation: 将 `arr` 按每个子数组 1 个元素进行分割。
```

**示例 2**  
```text
Input: arr = [1,9,6,3,2], size = 3
Output: [[1,9,6],[3,2]]
Explanation: 将 `arr` 按每个子数组 3 个元素进行分割，但第二个子数组只剩下 2 个元素。
```

**示例 3**  
```text
Input: arr = [8,5,3,2,6], size = 6
Output: [[8,5,3,2,6]]
Explanation: `size` 大于 `arr.length`，所以所有元素都在第一个子数组中。
```

**示例 4**  
```text
Input: arr = [], size = 1
Output: []
Explanation: 没有元素可供分块，返回空数组。
```

**约束条件**  
- `arr` 为表示数组的字符串。  
- `2 <= arr.length <= 10^5`  
- `1 <= size <= arr.length + 1`

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  
最直接的想法就是**一次遍历**原数组 `arr`，把元素按顺序装进一个临时的“小篮子”。  
当这个篮子里已经有 `size` 个元素时，就把它当作一个子数组放进结果集合里，然后重新开启一个空篮子继续装。  
遍历结束后，如果篮子里还有剩余元素（不足 `size`），也要把它加入结果中。

- **用到的数据结构**  
  - `list`（Python 中的数组）用来保存最终的分块结果。  
  - 另一个 `list` 充当“临时篮子”，每次收集 `size` 个元素后就把它“装进”结果里。  
  - 这里的 `list` 类似生活中的 **购物篮**：往里放东西，装满后就把篮子交给收银员（即放进结果），再拿一个空篮子继续装。

- **为什么正确**  
  - 我们严格按照原数组的顺序取元素，且每次恰好取 `size` 个（除最后一次可能不足），这正是题目要求的“把原数组切成若干子数组”。  
  - 所有元素都会被遍历一次，既不会遗漏也不会重复。

- **复杂度分析（大白话版）**  
  - **时间复杂度**：我们对 `arr` 只走了一遍，遍历一次的工作量记作 **O(n)**，这里的 `n` 就是 `arr` 的长度。想象成“把 100 本书从书架搬到箱子里”，每本书只搬一次，所以时间随书的数量线性增长。  
  - **空间复杂度**：除了返回的结果外，只用了一个临时篮子（最多装 `size` 个元素），这部分空间最多是 `size`，在最坏情况下 `size` 可能和 `n` 同数量级，所以额外空间是 **O(n)**（因为返回的列表本身也需要存放所有元素）。如果只算**额外**的临时空间，则是 **O(size)**，即常数级别。

#### 代码（Python）

```python
def chunk(arr, size):
    """
    把 arr 按 size 分块，返回一个二维列表。
    """
    if size <= 0:                     # size 非法的防御性检查
        raise ValueError("size 必须大于 0")
    
    result = []       # 用来装所有子数组的“总篮子”
    temp = []         # 当前正在填充的子数组

    for num in arr:   # 依次拿到原数组的每个元素
        temp.append(num)          # 把元素放进当前的子数组
        if len(temp) == size:     # 当前子数组已经满了
            result.append(temp)   # 把它交给总篮子
            temp = []             # 重新开一个空子数组

    # 循环结束后，temp 里可能还有剩余元素（不足 size）
    if temp:                       # 如果不是空的，就把它也加入结果
        result.append(temp)

    return result
```

#### 复杂度

- **时间复杂度**：`O(n)` —— 只遍历一次数组，`n` 是 `arr` 长度。  
- **空间复杂度**：`O(n)` —— 结果列表本身需要存放全部元素（不可避免），额外临时空间是 `O(size)`，在最坏情况等价于 `O(n)`。

### 2. 最优解  

#### 思路  
其实上面的“暴力”解已经是最优的线性时间解法了，因为：

1. **瓶颈在哪里？**  
   - 只能把每个元素放进某个子数组一次，除非把元素搬来搬去（这会导致更高的时间），所以遍历一次已经是下界。  
2. **还能怎么优化？**  
   - 只要把 **一次遍历** 与 **切片** 结合，就可以写得更简洁，同时仍保持 `O(n)`。  
   - Python 的切片操作 `arr[i:i+size]` 会一次性返回一个子列表（内部也是 `O(size)`），如果我们每次跳 `size` 步取一次切片，就不需要手动维护临时篮子。  

**核心技巧：步进切片（Step slicing）**  
把数组看成一串珠子，用尺子每隔 `size` 珠子量一次，直接截取这一段。相当于把原数组划分为等长的块（最后一块可能短）。

#### 代码（Python）

```python
def chunk(arr, size):
    """
    使用切片一步步取出子数组，时间复杂度仍为 O(n)。
    """
    if size <= 0:
        raise ValueError("size 必须大于 0")
    
    result = []                     # 用来保存所有块
    # i 代表每块的起始下标，步长为 size
    for i in range(0, len(arr), size):
        # arr[i:i+size] 会返回从 i 开始、最多 size 个元素的子列表
        result.append(arr[i:i + size])
    return result
```

#### 复杂度

- **时间复杂度**：`O(n)` —— `range(0, len(arr), size)` 产生约 `n/size` 次循环，每次切片会复制 `size`（或剩余）个元素，总复制次数等于 `n`。  
- **空间复杂度**：`O(n)` —— 同样需要存放所有元素的结果列表，额外临时空间只有循环计数器 `i`，可以视为 **O(1)**。

与暴力解相比，**时间仍是线性**，但代码更简洁、易读，且没有手动维护临时列表的细节。

## 心得  

- **核心技巧**：**一次遍历 + 步进切片**（或手动“装篮子”），适用于所有需要把序列划分为固定大小块的场景。  
- **适用的题型**  
  1. **分页显示**：把一长列表分成若干页，每页固定数量的元素。  
  2. **批量处理**：一次只处理 `k` 条数据（如批量写入数据库）。  
  3. **图像分块**：把像素矩阵划分成若干子矩阵进行局部运算。  
- **一句话总结**：只要一次遍历，把元素按 `size` 装进子数组——线性时间、常数额外空间，最直接也是最优的解法。

## 反思  

- **第一反应**：看到“把数组切成若干子数组”，立刻想到循环取 `size` 个元素放进新列表。  
- **最容易踩的坑**  
  - `size` 为 `0` 或负数时会导致死循环或异常，需要提前检查。  
  - 空数组 `[]` 必须返回空列表 `[]`，而不是 `[[]]`。  
  - 当 `size` 大于数组长度时，只有一个子数组（即整个数组本身），切片实现天然支持。  
- **下次遇到同类题**：第一步先**确认是否只需要一次遍历**，如果是，就考虑**步进切片**或**滑动窗口**的方式实现。这样既保证最优时间，又能写出简洁代码。
