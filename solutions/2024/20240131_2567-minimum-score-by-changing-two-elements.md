## 解题过程

### 1. 直觉解（暴力）

#### 思路  

题目给出一个整数数组 `nums`，我们可以把 **任意两个位置的元素** 改成任意整数（可以是很大，也可以是很小），改完以后要让 **数组的分数** 最小。  
这里的“分数”其实就是数组中最大值与最小值的差值 `max(nums) - min(nums)` —— 就像我们在日常生活中测量一组温度的波动幅度，幅度越小说明波动越平稳。

最直接的想法是：  
1. 把数组中 **所有可能的两对下标** `(i, j)`（`i < j`）枚举出来。  
2. 对于每一对下标，**假设我们把这两个位置的值改成最有利的数**（也就是说，把它们改成能够让剩下的元素的最大值和最小值之间距离最小的数）。  
3. 计算改完以后数组的分数，取所有情况中的最小值。

> **类比**：把数组想象成一本词典，词典里每个单词都有对应的页码（数值）。我们可以把任意两页的内容改写成别的页码，目标是让词典的“最大页码 - 最小页码”尽可能小。暴力思路就是把每一种改写方式都尝试一次，看看哪一种让差值最小。

**为什么暴力一定能得到正确答案**  
因为我们遍历了所有可能的两次修改方式，必然会覆盖最优的那一次修改。只要对每一种情况都正确地计算了改完后的最大最小值，最终取最小的差值就是答案。

**复杂度分析（大白话）**  
- 枚举下标对有 `C(n,2) = n·(n-1)/2` 种，大约是 `n²/2`，这一步相当于“把所有可能的两个人选出来”。  
- 对每一对，我们需要遍历一次数组来找剩下元素的最大最小值，时间是 `O(n)`。  
- 所以总体时间是 **`O(n³)`**，也就是 **“立方级别”**，当 `n` 达到 10⁵ 时根本跑不完。  
- 只用了常数级的额外空间（存几个临时变量），所以空间是 **`O(1)`**。

#### 代码（Python）

```python
from typing import List
import sys

def min_score_bruteforce(nums: List[int]) -> int:
    n = len(nums)
    ans = sys.maxsize                     # 初始设为一个很大的数
    # 枚举所有两下标 (i, j)
    for i in range(n):
        for j in range(i + 1, n):
            # 假设把 i、j 位置改成最有利的数
            cur_min = sys.maxsize
            cur_max = -sys.maxsize - 1
            # 扫描其余位置，找出真正的最小值和最大值
            for k in range(n):
                if k == i or k == j:      # 这两个位置已经可以随意改，直接跳过
                    continue
                cur_min = min(cur_min, nums[k])
                cur_max = max(cur_max, nums[k])
            # 把 i、j 改成任意数，只要不让范围变大就行
            # 最佳做法是把它们改成 cur_min 或 cur_max 之间的任意数，
            # 这不会影响 max 与 min。
            ans = min(ans, cur_max - cur_min)
    return ans
```

> 代码中每一行都写了中文注释，帮助你快速对应思路与实现。

#### 复杂度

- **时间复杂度**：`O(n³)` — 立方级别，遍历所有下标对（≈`n²`）并在每次遍历中再扫一遍数组（`n`）。  
- **空间复杂度**：`O(1)` — 只用了几个临时变量，不随输入规模增长。

### 2. 最优解

#### 思路  

从暴力解可以看到 **瓶颈** 在于我们把 **所有元素** 都参与了扫描。其实我们只关心 **最小值和最大值**，因为分数 = `max - min`。如果我们把两个元素改成 “不影响” 这两个极值的数，分数就只由 **其余元素** 决定。

**关键观察**  

1. **只需要改掉“极端的”两个数**  
   - 把最小的数改大一点，或者把最大的数改小一点，才能真正压缩整体的跨度。  
   - 把中间的数改成什么都不会改变 `max` 与 `min`（因为它们仍然是数组的极值），所以改中间的数是 **没有意义的**。  
   - 因此，最优的两次修改必然涉及 **最小值**、**第二小值**、**最大值**、**第二大值** 这四个位置中的两个。

2. **改动后我们相当于“把极端的元素剔除”**  
   - 如果把 **两个最小的** 元素改成任意数（比如把它们改成中间的某个值），那么剩下的有效最小值就变成原数组的第 3 小元素 `a[2]`（假设已排序）。此时最大值仍是原来的最大 `a[n-1]`。  
   - 同理，改掉 **两个最大的** 元素后，剩下的有效最大值是第 3 大 `a[n-3]`，最小值仍是 `a[0]`。  
   - 还有一种情况是 **改掉一个最小、一个最大**，此时剩下的最小是第 2 小 `a[1]`，最大是第 2 大 `a[n-2]`。

3. **枚举这三种可能，取最小**  
   把数组排序得到 `a[0] ≤ a[1] ≤ … ≤ a[n-1]`，答案就是下面三者的最小值：

   ```
   a[n-3] - a[0]   # 改掉两个最大的
   a[n-2] - a[1]   # 改掉一个最小、一个最大
   a[n-1] - a[2]   # 改掉两个最小的
   ```

   这正是 **“把最极端的两个数”** 从范围中“踢出去”后，剩余数的跨度。

**为什么只需考虑这三种**  
- 任何其他的改动（比如改掉第 2 小和第 2 大）都会留下原来的最小或最大，导致范围不如上述三种更“紧”。  
- 只改掉一个极端（比如只改最小）是不够的，因为我们还能再改一次，继续压缩范围，最优总是把两次机会都用在极端上。

**类比**：想象你在一条绳子两端挂着最重的两块石头，绳子的张力（分数）等于两块石头的重量差。你可以把两块石头换成更轻的（或更重的）石头。显然，你会把最重的两块或最轻的两块换掉，或者各换掉一块，这样绳子的张力才能最小。

#### 代码（Python）

```python
from typing import List

def min_score(nums: List[int]) -> int:
    """
    返回改变任意两个元素后，数组的最小 possible score（max - min）。
    思路：先排序，只需要比较三种“去掉两个极端”的情况。
    """
    n = len(nums)
    nums.sort()                     # O(n log n) 排序
    # 三种去极端的方案
    option1 = nums[-3] - nums[0]    # 去掉两个最大值
    option2 = nums[-2] - nums[1]    # 去掉一个最小、一个最大
    option3 = nums[-1] - nums[2]    # 去掉两个最小值
    return min(option1, option2, option3)
```

- `nums.sort()`：把数组从小到大排好序，等价于把所有“石头”按重量排队。  
- `nums[-3]` 表示倒数第三个元素，即第 `n-2`（从 0 开始算）的位置。  
- `min(option1, option2, option3)` 直接取三种情况中最小的那个，就是答案。

#### 复杂度

- **时间复杂度**：`O(n log n)` — 主要耗时在排序，`log n` 是排序的常见复杂度。相比暴力的 `O(n³)`，提升了 **指数级**（从立方降到对数乘线性），在 `n = 10⁵` 时也能轻松跑完。  
- **空间复杂度**：`O(1)`（若使用原地排序）或 `O(n)`（Python 的 Timsort 会额外占用少量空间），都远小于暴力的 `O(1)`，但在实际使用中几乎可以忽略不计。

## 心得

- **核心技巧**：**只关注极端值**（最小、第二小、最大、第二大），利用**排序**把极端位置显式出来，然后枚举“去掉两个极端”的三种可能。  
- **适用的题型**  
  1. “删除（或修改）k 个元素后，使数组的范围最小”  
  2. “在数组中删除最多 k 个元素，使最大值与最小值的差最小”  
  3. “修改至多 k 次，使数组的波动幅度最小”  
- **一句话总结解题钥匙**：**把“最能影响范围的两个数”剔除，剩余部分的跨度即为最小可能分数**。

## 反思

- **第一反应**：看到“改变两个元素”，立刻想到穷举所有下标对（暴力），因为最安全的办法就是把所有可能都试一遍。  
- **最容易踩的坑**  
  - 忽略了 **“可以把两个元素改成任意数”** 的自由度，导致在暴力实现时尝试了很多无意义的数值。  
  - 边界条件：数组长度恰好为 3 时，`nums[2]`、`nums[-3]` 等索引仍然合法，因为我们总能把两个极端改掉，只剩下一个元素，分数自然为 0。  
- **下次遇到同类题**：第一步先 **思考极值**（最大、最小）在答案中扮演的角色，判断是否可以通过**删除/修改极端元素**来直接得到答案，再决定是否需要排序或使用堆等数据结构。
