## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**把所有可能的子数组枚举出来**，然后检查每个子数组里出现了多少种不同的数字。  

- **子数组**：数组的连续片段，就像把一根绳子从第 `i` 根到第 `j` 根剪下来。  
- **不同的数字**：可以用 **哈希表**（在 Python 中就是 `dict` 或 `set`）来存放，哈希表就像一本词典，单词是键（这里是数字），对应的页码是我们不关心的值，只要键出现过就算进集合。  

我们先算出原数组里一共有多少种不同的数字，记为 `k`（相当于词典里有几本不同的书）。  
随后遍历所有 `[i, j]`（`0 ≤ i ≤ j < n`）的子数组：

1. 用一个 `set` 把子数组里的数字收集进去。  
2. 如果 `set` 的大小恰好等于 `k`，说明这个子数组已经“完整”了，计数加一。  

**为什么正确？**  
因为题目要求的“完整子数组”正是**包含全部 `k` 种不同数字**的子数组。我们把每个子数组的不同数字数目算出来，恰好等于 `k` 时必然满足要求，漏掉或多算的情况都不会出现。

**复杂度分析（大白话）**  

- 外层循环 `i` 从 `0` 到 `n-1`，内层循环 `j` 从 `i` 到 `n-1`，这两个循环一起会跑大约 `n·(n+1)/2` 次，**相当于把所有子数组都列了一遍**。  
- 对每个子数组我们要把里面的数字放进 `set`，最坏情况下子数组长度是 `n`，所以一次 `set` 操作的代价是 **最多遍历 `n` 次**。  

于是总时间是 **O(n³)**（三次遍历的乘积），对 `n ≤ 1000` 来说已经有点慢了。  
空间上我们只需要一个 `set` 来存当前子数组的不同数字，最多装 `k ≤ n` 个元素，**O(n)** 的额外空间。

#### 代码（Python）

```python
def countCompleteSubarrays_bruteforce(nums):
    n = len(nums)
    # 先算出整体有多少种不同的数字 k
    total_distinct = len(set(nums))

    ans = 0
    # 枚举所有子数组的左端点 i
    for i in range(n):
        # 用一个 set 动态收集从 i 开始的子数组的不同数字
        cur_set = set()
        # 枚举右端点 j
        for j in range(i, n):
            cur_set.add(nums[j])          # 把 nums[j] 放进集合，相当于查字典
            # 当集合的大小等于整体的不同数字个数时，说明子数组 [i, j] 完整
            if len(cur_set) == total_distinct:
                ans += 1
    return ans
```

#### 复杂度

- **时间复杂度**：`O(n³)`  
  - “n³” 可以想象成：先挑左端点（`n` 种），再挑右端点（平均 `n/2` 种），最后把子数组里的每个元素都放进集合（最多 `n` 次）。
- **空间复杂度**：`O(n)`  
  - 只用了一个 `set` 来记录当前子数组的不同元素，最多装 `n` 个数字。

### 2. 最优解  

#### 思路  

从暴力解可以看到，**瓶颈在于重复遍历同一个元素**。  
当我们把左端点 `i` 向右移动时，右端点 `j` 也可以**不必回到 `i` 再走一遍**，因为子数组的“完整性”只和窗口里出现的不同数字种类有关。  

这正好可以使用 **滑动窗口（Sliding Window）** 的思路：

1. 先算出整体的不同数字个数 `k`（同上）。  
2. 用两个指针 `left`、`right` 表示当前窗口 `[left, right]`（左闭右闭）。  
3. 用一个哈希表 `cnt` 统计窗口内每个数字出现的次数，`cnt` 的键相当于词典的单词，值是出现次数。  
4. 当窗口里 **不同数字的种类数**（`len(cnt)`）小于 `k` 时，**右指针右移**，把新数字加入 `cnt`。  
5. 一旦窗口里出现了 **恰好 `k` 种不同数字**，说明从 `left` 开始的所有更长的子数组（即把右指针继续往右扩展）都一定完整，因为已经包含了全部种类。于是我们可以直接把 `n - right`（剩余元素的数量）加入答案。  
6. 接下来 **左指针左移**，把 `nums[left]` 从 `cnt` 中减去计数，若计数降到 0 则把这个键删掉，窗口的不同种类数可能会下降到 `k-1`，此时回到第 4 步继续扩张右指针。  

这样每个元素最多被左指针和右指针各访问一次，**整体只走了一遍数组**，时间线性。

**关键概念解释**  

- **哈希表 `cnt`**：像一本词典，记录每个数字现在在窗口里出现了几次。  
- **窗口内不同种类数**：`len(cnt)`，相当于词典里现在有多少本不同的书。  
- **`n - right` 的意义**：右指针停在某个位置 `right` 时，窗口已经完整；把右指针继续往右走（即把后面的元素都加进来），仍然保持完整。后面的元素有 `n - right` 个选择，所以有这么多子数组。

#### 代码（Python）

```python
def countCompleteSubarrays(nums):
    n = len(nums)
    # 1️⃣ 计算整体不同数字的种类数 k
    total_distinct = len(set(nums))

    cnt = {}               # 哈希表，记录窗口内每个数字的出现次数
    left = 0
    ans = 0

    # 2️⃣ 右指针遍历整个数组
    for right in range(n):
        # 把 nums[right] 加入窗口
        cnt[nums[right]] = cnt.get(nums[right], 0) + 1

        # 3️⃣ 当窗口已包含全部 k 种不同数字时，开始计数
        while len(cnt) == total_distinct:
            # 此时以 left 为左端点、right 为右端点的窗口已经完整，
            # 再往右扩展任意长度仍然完整，共有 (n - right) 种可能
            ans += n - right

            # 4️⃣ 左指针左移，尝试收缩窗口
            cnt[nums[left]] -= 1
            if cnt[nums[left]] == 0:          # 出现次数归零，键可以删掉
                del cnt[nums[left]]
            left += 1                         # 窗口左边界右移

    return ans
```

#### 复杂度

- **时间复杂度**：`O(n)`  
  - 每个元素至多进入哈希表一次、离开一次，左指针和右指针各走 `n` 步，总共线性遍历。相比暴力的 `O(n³)`，相当于把“千次遍历”压缩成“一次遍历”。  
- **空间复杂度**：`O(k)`（`k ≤ n`）  
  - 哈希表里最多保存 `k` 个不同的数字，和整体不同种类数成正比。

## 心得  

- **核心技巧**：滑动窗口 + 哈希表统计不同元素种类。  
- **适用场景**：  
  1. “子数组/子串包含所有字符/数字” 类问题（如 LeetCode 76 “最小覆盖子串”、LeetCode 1004 “最大连续 1 的个数 III”）。  
  2. “子数组满足某种计数条件” 的计数类问题（如 LeetCode 992 “子数组的最大和”）。  
- **一句话总结**：把窗口扩到恰好包含所有不同数字，然后利用“右指针后面还能随意延伸”快速计数。

## 反思  

- **第一反应**：看到“完整子数组”就想到“要把所有出现的数字都包含进去”，于是想到枚举子数组检查集合大小。  
- **最容易踩的坑**：  
  - 忘记在滑动窗口里统计 **不同数字的种类数**（只能看元素总数会出错）。  
  - 在左指针移动时没有及时删除计数为 0 的键，会导致 `len(cnt)` 仍然算作该数字在窗口中，从而误判窗口仍然完整。  
  - 边界情况：如果数组本身只有一种数字，`k = 1`，此时每个子数组都是完整的，滑动窗口仍然能正确计数，因为 `while len(cnt) == 1` 会一直触发。  
- **下次遇到同类题**：第一步先 **确定目标种类数 k**，然后 **用滑动窗口找出最左端点能让窗口恰好包含 k 种**，利用 “窗口右端点往后还能自由扩展” 来直接累计答案。这样就能把指数级的枚举压到线性时间。
