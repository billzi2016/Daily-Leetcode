## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是 **逐行尝试** 把皇后放在棋盘上，只要满足「同一列」或「同一对角线」上没有别的皇后，就可以继续往下一行放。  
这其实就是「回溯」的思路：

1. 从第 0 行开始，遍历该行的每一个格子 `(row, col)`。  
2. 判断 `(row, col)` 是否会被已经放好的皇后攻击。这里需要检查三件事：  
   - 同一列 `col` 是否已经被占用。  
   - 主对角线 `row - col` 是否已经被占用（左上‑右下方向）。  
   - 副对角线 `row + col` 是否已经被占用（右上‑左下方向）。  
   把这三类信息分别存进 **集合**（或列表）里，就像在字典里查词一样：  
   - “列集合”就像字典的 **key**，代表哪一列已经有皇后。  
   - “主对角线集合”和“副对角线集合”同理。  
3. 若当前位置安全，就把对应的 `col`、`row-col`、`row+col` 加入集合，递归处理下一行。  
4. 当递归走到第 `n` 行时，说明已经成功放了 `n` 个皇后，计数器 `ans += 1`。  
5. 回溯时把刚才加入的集合元素删掉，尝试下一个格子。

> **为什么这个方法一定能得到答案？**  
> 因为我们枚举了所有可能的放置方式，只要满足约束条件就算作一种合法解。没有遗漏，也没有重复计数。

**时间/空间复杂度**  
- **时间**：每一行我们最多尝试 `n` 个位置，最坏情况下会遍历所有可能的排列，时间复杂度是 `O(n!)`（阶乘），因为第 1 行 `n` 种选择，第 2 行 `n‑1` 种，依此类推。  
- **空间**：递归栈深度为 `n`，再加上三个集合各至多保存 `n` 条记录，整体是 `O(n)` 的额外空间。  

> 大白话：`O(n!)` 就是“超级快炸”，随着 `n` 增大，计算量会像滚雪球一样迅速变大。

#### 代码（Python）

```python
def totalNQueens(n: int) -> int:
    # 用集合记录已经被占用的列、主对角线、和副对角线
    cols = set()          # 已经有皇后的列号
    diag1 = set()         # 主对角线：row - col
    diag2 = set()         # 副对角线：row + col
    ans = 0               # 记录合法方案数

    def backtrack(row: int) -> None:
        """尝试在第 `row` 行放置皇后"""
        nonlocal ans
        if row == n:               # 所有行都放完了，找到一种解法
            ans += 1
            return

        for col in range(n):       # 枚举当前行的每一列
            if (col in cols or          # 同列冲突
                (row - col) in diag1 or  # 主对角线冲突
                (row + col) in diag2):   # 副对角线冲突
                continue                # 位置不安全，试下一个

            # 把当前皇后占用的列、对角线标记加入集合
            cols.add(col)
            diag1.add(row - col)
            diag2.add(row + col)

            backtrack(row + 1)   # 递归处理下一行

            # 回溯：撤销标记，尝试别的列
            cols.remove(col)
            diag1.remove(row - col)
            diag2.remove(row + col)

    backtrack(0)   # 从第 0 行开始搜索
    return ans
```

#### 复杂度

- **时间复杂度**：`O(n!)`  
  表示随着 `n` 增大，可能的排列数会以阶乘速度增长。对 `n ≤ 9` 仍在可接受范围。

- **空间复杂度**：`O(n)`  
  只用了几个长度不超过 `n` 的集合和递归栈深度 `n`。

### 2. 最优解

#### 思路  

暴力解的核心瓶颈在 **检查冲突** 时使用了集合的 `in` 操作，虽然是 `O(1)`，但我们每次都要创建/删除元素，还要维护三个集合。  
我们可以把这三个集合压缩成 **位运算**（bitmask），利用整数的每一位来表示某一列或对角线是否被占用。

- **列掩码 `col_mask`**：第 `i` 位为 1 表示第 `i` 列已有皇后。  
- **主对角线掩码 `diag1_mask`**：第 `i` 位为 1 表示第 `i` 条主对角线被占。  
- **副对角线掩码 `diag2_mask`**：第 `i` 位为 1 表示第 `i` 条副对角线被占。

对 `n ≤ 9` 来说，`int`（至少 32 位）足够容纳所有信息。  
在第 `row` 行，我们先算出 **所有可以放皇后的列**：

```
available = (~(col_mask | diag1_mask | diag2_mask)) & ((1 << n) - 1)
```

- `col_mask | diag1_mask | diag2_mask` 把已经被占的列和两条对角线合并为一个掩码。  
- `~` 取反得到“空位”掩码。  
- `& ((1 << n) - 1)` 把高位多余的 1 截掉，只保留前 `n` 位。

随后我们 **逐个取出最低位的 1**（即最左边的可用位置），放置皇后后递归：

```
while available:
    # 取出最低位的 1，对应一种放置方案
    pos = available & -available
    # 从可用集合中移除这个位
    available -= pos
    # 递归时更新三个掩码
    backtrack(row + 1,
              col_mask | pos,
              (diag1_mask | pos) << 1,
              (diag2_mask | pos) >> 1)
```

- `pos = available & -available` 是经典的 “提取最低位 1” 操作。  
- 放置后，下一行的 **主对角线** 要左移一位（因为相对于下一行向左偏移），**副对角线** 要右移一位。  

这样就把 **冲突检测** 与 **状态转移** 全部压缩到了位运算里，极大提升了常数因子。整体时间仍是 `O(n!)`（因为必须遍历所有合法排列），但在实际运行中要快很多。

#### 代码（Python）

```python
def totalNQueens(n: int) -> int:
    """
    使用位运算的回溯（Bitmask Backtracking）。
    只需要 O(n) 的额外空间，运行速度比集合版更快。
    """
    ans = 0                     # 记录合法方案数
    limit = (1 << n) - 1        # 前 n 位全为 1 的掩码，例如 n=4 时 limit=0b1111

    def backtrack(row: int, col_mask: int, diag1_mask: int, diag2_mask: int) -> None:
        """row：当前处理的行号（从 0 开始）"""
        nonlocal ans
        if row == n:            # 所有行已成功放置皇后
            ans += 1
            return

        # 计算当前行可以放皇后的列（位为 1 表示可以放）
        available = ~(col_mask | diag1_mask | diag2_mask) & limit

        while available:
            # 取出最低位的 1，代表一种放置位置
            pos = available & -available
            # 把这位置从可用集合中移除，准备尝试下一个
            available -= pos

            # 递归到下一行，更新三个掩码：
            #   col_mask   加上本行的 pos
            #   diag1_mask 左移一位，表示主对角线向左偏移
            #   diag2_mask 右移一位，表示副对角线向右偏移
            backtrack(row + 1,
                      col_mask | pos,
                      (diag1_mask | pos) << 1,
                      (diag2_mask | pos) >> 1)

    backtrack(0, 0, 0, 0)
    return ans
```

#### 复杂度

- **时间复杂度**：`O(n!)`  
  与暴力集合版相同的数量级，但位运算的常数更小，实际运行更快。可以把它想象成“把每一步的检查压缩到了 1 步”。

- **空间复杂度**：`O(n)`  
  递归栈深度为 `n`，其余只用了几个整数变量（位掩码），不随 `n` 增大而线性增长。

## 心得

- **核心技巧**：**回溯 + 位运算（Bitmask）**。回溯负责枚举所有可能，位运算把冲突检查压缩到 O(1) 的位操作，极大提升效率。  
- **适用的题型**：  
  1. **N-Queens 系列**（求解方案数或列举所有方案）  
  2. **排列组合类的子集搜索**（如“求解所有合法的 Sudoku 行/列/宫”）  
  3. **位掩码子集 DP**（如“按位与为 0 的最大子集大小”等）  
- **一句话总结**：**把冲突状态压缩成二进制位，回溯时直接在位上做加减**，是解 N‑Queens 高效的“钥匙”。

## 反思

- **第一反应**：立刻想到逐行尝试、用集合记录冲突，这是一种最自然的回溯思路。  
- **最容易踩的坑**：  
  - **对角线的编号**：主对角线 `row - col`、副对角线 `row + col` 的取值范围不同，需要正确映射到集合或位掩码。  
  - **位运算的左/右移**：忘记在递归进入下一行时对对角线掩码左移或右移，会导致错误的冲突检测。  
  - **边界条件**：`n = 1` 时只有一种方案，`n = 0`（虽然题目不出现）需要返回 0。  
- **下次遇到类似题**：先画出冲突的三类约束（列、两条对角线），判断是否能用位掩码表示；若能，就直接在位上做“占用/释放”，否则先用集合实现再考虑优化。
