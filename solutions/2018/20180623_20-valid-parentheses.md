## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接、最笨的想法是**把字符串里能匹配的一对括号直接删掉**，一直循环这个过程，直到：

1. 字符串被删空 → 所有括号都成功匹配，答案为 `True`  
2. 再也找不到可以删除的“()、[]、{}”这三种合法配对 → 说明还有不匹配的括号，答案为 `False`

这里用到的唯一数据结构是**字符串本身**，我们每次遍历整条字符串寻找可以删除的子串。  
可以把这个过程想象成**用橡皮擦把纸上的配对括号擦掉**，只要最后纸上什么也不剩，就是合法的。

为什么这种方法一定能判断对错？

- 合法的括号序列一定可以拆解成若干个“()、[]、{}”的组合，按任意顺序擦除都不会影响后面的匹配。  
- 只要还有字符没被擦掉，就说明至少有一个左括号找不到对应的右括号，或者顺序错了。

#### 代码（Python）

```python
def isValid_bruteforce(s: str) -> bool:
    # 只要还能在 s 中找到合法的配对，就把它们删掉
    # 这里用 while 循环模拟“不断擦除”
    while True:
        # 记录本轮是否有删减发生
        new_s = s.replace("()", "").replace("[]", "").replace("{}", "")
        if new_s == s:          # 没有任何配对被删除，说明无法继续
            break
        s = new_s               # 把删除后的新字符串继续处理
    # 循环结束后，若字符串为空则全部匹配成功
    return len(s) == 0
```

#### 复杂度  

- **时间复杂度：** `O(n²)`  
  - 每一次 `replace` 都要遍历整条字符串，最坏情况下需要 `n/2` 次循环才能把所有字符删完（比如 `"()()()..."`），于是总工作量约为 `n + (n-2) + (n-4) + … ≈ n²/2`，用大白话说就是**时间会随字符数的平方增长**，当字符串很长时会很慢。  
- **空间复杂度：** `O(1)`（不计入 Python 字符串本身的拷贝）  
  - 我们只使用了几个临时变量，额外占用的内存几乎不随 `n` 增长。

### 2. 最优解

#### 思路  

从暴力解出发，**瓶颈在于每次都要遍历整条字符串**，而且每删掉一对括号后都要重新扫描。我们可以一次遍历完成匹配，关键在于**记住已经出现但还未匹配的左括号**。

这正是 **栈（stack）** 的用武之地：

1. **左括号**（`(`、`[`、`{`）进栈 → 把它们放到“待匹配”列表的最上面。  
2. **右括号**（`)`、`]`、`}`）出现时，检查栈顶的左括号是否能匹配：  
   - 如果栈空或栈顶不是对应的左括号 → 直接返回 `False`（出现非法闭合）。  
   - 否则弹出栈顶（匹配成功），继续向后扫描。  

遍历结束后，**栈为空** 表示所有左括号都找到了匹配的右括号，返回 `True`；否则返回 `False`。

> **类比**：想象你在排队买票，左括号是“先来的人”，右括号是“后来的检票员”。检票员只能检查最前面的那个人（栈顶），如果不匹配就说明排队顺序出错。

实现细节：

- 用一个字典 `pair = {')': '(', ']': '[', '}': '{'}` 把每个右括号映射到它对应的左括号，查表的时间是 `O(1)`。  
- 用 Python 列表 `stack = []` 充当栈，`append` 为压栈，`pop` 为弹栈。

#### 代码（Python）

```python
def isValid(s: str) -> bool:
    # 建立右括号 -> 左括号 的映射，类似“查字典”
    pair = {')': '(', ']': '[', '}': '{'}

    stack = []                     # 用列表当栈，存放左括号
    for ch in s:                   # 逐字符扫描
        if ch in pair.values():    # ch 是左括号 → 入栈
            stack.append(ch)
        else:                      # ch 是右括号
            # 1) 栈为空 → 没有左括号可匹配
            # 2) 栈顶不是对应的左括号 → 不匹配
            if not stack or stack[-1] != pair[ch]:
                return False
            stack.pop()            # 匹配成功，弹出栈顶

    # 所有字符处理完后，栈应当为空
    return not stack
```

#### 复杂度  

- **时间复杂度：** `O(n)`  
  - 只遍历一次字符串，每个字符的压栈或弹栈都是常数时间。用大白话说，就是**字符越多，时间线性增长**，即使 10,000 个字符也只需要大约 10,000 步。  
- **空间复杂度：** `O(n)`（最坏情况）  
  - 当全部是左括号时，需要把每个左括号都压入栈，栈的大小最多等于字符串长度 `n`。如果字符已经很好配对，栈的实际占用会更小。

## 心得

- **核心技巧**：**栈**（后进先出）用于处理“配对”或“嵌套”结构，特别是括号、标签、表达式等。  
- **适用的题型**：  
  1. 有效的括号（本题）  
  2. 最小生成括号序列（LeetCode 22）  
  3. 逆波兰表达式求值（LeetCode 150）  
- **一句话总结解题钥匙**：**左进右出**——遇到左符号压栈，遇到右符号只看栈顶是否匹配。

## 反思

- **第一反应**：看到一串括号，我会先想到“配对”和“嵌套”，于是自然联想到使用栈来记录未匹配的左括号。  
- **最容易踩的坑**：  
  - 忘记在遇到右括号时先检查栈是否为空，会导致 `pop` 报错。  
  - 没有把所有右括号都映射到对应的左括号，导致遗漏 `}`、`]` 的情况。  
  - 最后忘记判断栈是否为空，直接返回 `True`，会把 `"((("` 错误地判为合法。
