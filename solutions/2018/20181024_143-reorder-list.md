## 解题过程

### 1. 直觉解（暴力）

#### 思路  
最直接的想法是把链表的所有节点**全部取出来**，放进一个 Python 列表（array）里。  
- **链表 → 列表**：就像把一本书的每一页都摞在桌面上，方便我们随意访问第几页（下标），而不必像翻书那样只能顺着下一页走。  
- 把节点放进列表后，我们可以用**双指针**（左指针 `i` 从前往后，右指针 `j` 从后往前）交叉取出节点，得到重新排列后的顺序 `L0, Ln, L1, Ln‑1, …`。  
- 最后再把这些节点依次用 `next` 链接起来，形成新的链表。

> 这种做法**不改变节点的值**，只改变指针的指向，完全满足题目要求。

#### 代码（Python）

```python
# Definition for singly-linked list.
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next


def reorderList(head: ListNode) -> None:
    """
    暴力解：先把所有节点放进数组，然后交叉重排，再重新链接。
    只修改指针，不返回值（符合 LeetCode 要求）。
    """
    if not head or not head.next:      # 链表长度为 0 或 1 时直接返回
        return

    # 1. 把链表所有节点收集到 list 中
    nodes = []                         # list 相当于“字典”里的一排排卡片
    cur = head
    while cur:
        nodes.append(cur)              # 把每个节点对象存进去
        cur = cur.next

    # 2. 用双指针交叉取出节点，重新链接
    i, j = 0, len(nodes) - 1           # i 指向前，j 指向后
    while i < j:
        # 先把前面的节点指向后面的节点
        nodes[i].next = nodes[j]
        i += 1
        if i == j:                     # 当 i、j 重合时说明已经是中间节点，结束
            break
        # 再把后面的节点指向新的前节点
        nodes[j].next = nodes[i]
        j -= 1

    # 3. 最后一个节点的 next 必须置为 None，防止形成环
    nodes[i].next = None
```

#### 复杂度

- **时间复杂度**：`O(n)`  
  只遍历了链表两遍（一次收集节点，一次重排），`n` 是节点数。  
  用大白话说，就是“和节点个数成正比”，节点越多，花的时间就线性增加。

- **空间复杂度**：`O(n)`  
  需要额外的数组保存所有节点的引用，大小随 `n` 增长。  
  想象把书的每一页都摞在桌面上，桌面需要的空间和页数一样多。

### 2. 最优解

#### 思路  

暴力解已经能在 `O(n)` 时间内完成任务，但用了 `O(n)` 的额外空间。  
我们要把**空间降到 `O(1)`**（常数级），即只使用原链表本身的指针，不再额外申请与节点数同等大小的数组。

从暴力解出发，观察到**“交叉取出”**的过程其实可以分三步实现：

1. **找到链表的中点**  
   使用**快慢指针**（Two Pointers）：
   - `slow` 每次走一步，`fast` 每次走两步。  
   - 当 `fast` 到达链表尾部时，`slow` 正好在中间位置。  
   类比：在跑道上，一个人慢跑（`slow`），另一个人快跑（`fast`），快跑的先到终点，慢跑的此时正好在跑道的中点。

2. **反转后半段**  
   把中点之后的链表**原地反转**（Reverse）。  
   反转后，后半段的顺序变成 `Ln, Ln‑1, …`，正好是我们想要交叉的顺序。  
   只需要改变指针的方向，不需要额外空间。

3. **交叉合并两段**  
   把前半段 `L0 → L1 → … → Lmid` 与已经反转的后半段 `Ln → Ln‑1 → …` **交替链接**。  
   用两个指针分别指向两段的当前节点，交替把 `next` 指向对方的下一个节点。

下面一步步解释每个子过程：

- **找中点**：如果链表长度为奇数，`slow` 会停在中间节点；如果为偶数，`slow` 停在前半段的最后一个节点（这正好满足我们后面把 `slow.next` 当作后半段的起点）。
- **反转**：经典的链表反转技巧——遍历一次，使用 `prev` 保存已反转好的部分，`cur` 指向当前待处理节点。每次把 `cur.next` 指向 `prev`，然后整体右移。
- **合并**：设 `first` 指向前半段头，`second` 指向反转后后半段头。循环中保存 `first.next` 与 `second.next`，先让 `first.next = second`，再让 `second.next = tmp1`（原来的 `first.next`），如此交叉。

> 通过这三步，我们只动用了常数个指针变量，额外空间为 `O(1)`。

#### 代码（Python）

```python
def reorderList(head: ListNode) -> None:
    """
    最优解：O(n) 时间、O(1) 额外空间。
    步骤：
    1. 用快慢指针找到链表中点
    2. 反转中点之后的链表
    3. 交叉合并前后两段
    """
    if not head or not head.next:
        return

    # ---------- 1. 找到中点 ----------
    slow, fast = head, head
    while fast.next and fast.next.next:   # fast 能走两步才继续
        slow = slow.next
        fast = fast.next.next
    # 此时 slow 位于前半段的尾节点

    # ---------- 2. 反转后半段 ----------
    # 断开前后两段，使后半段成为独立链表
    second = slow.next
    slow.next = None                     # 前半段以 slow 为尾
    prev = None
    cur = second
    while cur:
        nxt = cur.next                    # 暂存后继节点
        cur.next = prev                   # 翻转指针
        prev = cur
        cur = nxt
    # 反转结束后，prev 是新链表的头，即原来的 Ln
    second = prev

    # ---------- 3. 交叉合并 ----------
    first = head
    while second:
        # 暂存各自的下一个节点
        tmp1 = first.next
        tmp2 = second.next

        first.next = second               # 前段接后段
        second.next = tmp1                # 后段接前段的下一个

        # 移动指针继续合并
        first = tmp1
        second = tmp2
```

#### 复杂度

- **时间复杂度**：`O(n)`  
  三次遍历（找中点、反转、合并）每次都只走一次链表，节点数 `n` 越大，时间线性增长。相比暴力解，**时间没有变快**，但**空间省了很多**。

- **空间复杂度**：`O(1)`  
  只使用了几个指针变量（`slow、fast、prev、cur、first、second`），不随 `n` 增长。可以想象为只在桌面上放了几根笔，而不是把所有页面都摞出来。

## 心得

- **核心技巧**：  
  1. **快慢指针**定位中点  
  2. **原地链表反转**  
  3. **交叉合并**两段链表  

- **适用的题型**（类似思路）  
  - “**判断回文链表**” – 先找到中点、反转后半段、再比较两段。  
  - “**合并两个有序链表**” – 交叉合并的思路可以直接套用。  
  - “**删除链表倒数第 N 个节点**” – 也用快慢指针定位。

- **一句话总结解题钥匙**：  
  “把链表分成两段，翻转后半段，再把两段像拼图一样交错拼回去。”

## 反思

- **第一反应**：把链表所有节点取出来，用数组直接重排。思路简单直观，却忘记了空间限制。

- **最容易踩的坑**  
  1. **中点的选择**：当链表长度为偶数时，`slow` 必须停在前半段的最后一个节点，否则会出现 `first` 与 `second` 重复。  
  2. **断开前后链表**：忘记 `slow.next = None` 会导致合并时出现环，导致无限循环。  
  3. **合并时的指针保存**：如果不提前保存 `first.next`、`second.next`，指针会被覆盖，导致后面的节点丢失。

- **下次遇到同类题，第一步该想到**：  
  “先用快慢指针把问题拆成两段，看看能否把其中一段**原地翻转**，再**交叉拼接**”。这样就能把空间从 `O(n)` 降到 `O(1)`，得到最优解。
