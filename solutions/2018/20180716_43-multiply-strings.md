# #43. 字符串相乘 / Multiply Strings

> 难度：中等 · 标签：Math、String、Simulation · [LeetCode 链接](https://leetcode.com/problems/multiply-strings/)

---

## 题目（英文原版）

**Description**

Given two non-negative integers num1 and num2 represented as strings, return the product of num1 and num2, also represented as a string.
Note: You must not use any built-in BigInteger library or convert the inputs to integer directly.

**Examples**

**Example 1:**

```
Input: num1 = "2", num2 = "3"
Output: "6"
```

**Example 2:**

```
Input: num1 = "123", num2 = "456"
Output: "56088"
```

**Constraints**

- 1 <= num1.length, num2.length <= 200
- num1 and num2 consist of digits only.
- Both num1 and num2 do not contain any leading zero, except the number 0 itself.

---

## 题目（中文翻译）

给定两个以字符串（string）形式表示的非负整数（non-negative integer）`num1` 和 `num2`，返回 `num1` 与 `num2` 的乘积，同样以字符串形式返回。

**注意**：不得使用任何内置的大整数（BigInteger）库，也不能直接将输入转换为整数类型。

## 示例

### 示例 1
**输入**: `num1 = "2", num2 = "3"`  
**输出**: `"6"`

### 示例 2
**输入**: `num1 = "123", num2 = "456"`  
**输出**: `"56088"`

## 约束条件
- `1 <= num1.length, num2.length <= 200`
- `num1` 和 `num2` 仅由数字组成。
- 除了数字 `0` 本身之外，`num1` 和 `num2` 不含前导零。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：把字符串直接交给 Python 的大整数功能，让它帮我们完成加法、乘法，然后再把结果转回字符串。  
这相当于把 **“把字典里查到的数字直接相乘”** 的过程交给了系统，自己只负责把“单词”(字符串)和“页码”(整数)来回转换。

> **为什么这样是对的？**  
> - 字符串只包含数字字符，`int(s)` 能把它们完整、准确地转成对应的整数。  
> - 两个整数相乘的结果必然是正确的数值。  
> - `str(x)` 再把整数变回只含数字的字符串，恰好满足题目要求。

> **注意**：这其实违背了 “不能使用任何内置的大整数库” 的限制，只是帮助我们先建立正确的思路，后面会给出真正符合要求的实现。

#### 代码（Python）

```python
def multiply_bruteforce(num1: str, num2: str) -> str:
    # 把字符串转成整数，Python 会自动使用大整数（无限位数）实现
    a = int(num1)          # "123" -> 123
    b = int(num2)          # "456" -> 456

    product = a * b        # 直接相乘，得到整数 56088

    return str(product)    # 再转成字符串 "56088"
```

#### 复杂度

- **时间复杂度**：`O(len(num1) + len(num2))`  
  把两个字符串各自遍历一次转成整数（各是线性时间），乘法在 Python 的大整数实现里近似线性（因为位数和输入长度成正比），所以总体仍是线性级别。  
  用大白话说，就是“处理的字符个数越多，花的时间就越多，比例大约是 1 比 1”。

- **空间复杂度**：`O(len(num1) + len(num2))`  
  需要额外的空间保存两个整数的二进制表示，大小正比于输入长度。  

> **提示**：虽然时间/空间表现不错，但这段代码依赖了 Python 的“大整数”特性，实际面试中往往会被认为 **“作弊”**，因为题目要求**不**使用任何内置的大整数库。

### 2. 最优解

#### 思路  

从暴力解出发，我们发现 **瓶颈** 在于 **直接把整数字面交给系统处理**，而题目不允许这么做。  
所以我们必须 **手动模拟手算乘法**（小学算乘法的那套流程），把每一位的乘积、进位都自己算出来。

**核心思路**：

1. **把每个字符转成对应的数字**（`'3' -> 3`），并 **逆序**（从低位到高位）存放，类似把数字写在纸上倒着排，方便从右往左相乘。  
   - 类比：把一本书的章节倒着读，先读最后一页，后面再往前。

2. **准备一个长度为 `len(num1)+len(num2)` 的数组 `pos`**，用来存放每一位的乘积。  
   - 为什么要这么长？  
     两个数相乘，最多会产生 `len1+len2` 位（比如 99 × 99 = 9801，有 4 位），所以提前准备好足够的格子。

3. **遍历每一位** `i`（来自 `num1`）和每一位 `j`（来自 `num2`），计算 `digit1 * digit2`，把结果加到 `pos[i+j]` 上。  
   - `i+j` 正好对应这两个位数相乘后在结果中的 **低位索引**（因为我们是逆序存的），就像手算时把个位乘积放在最右边，十位乘积往左移一格。

4. **处理进位**：从低位到高位遍历 `pos`，把每个位置的值 `v` 用 `v // 10` 把进位搬到左边（`pos[k+1] += v // 10`），当前位保留 `v % 10`。  
   - 这一步相当于“把每个格子里超过 9 的数字往左边的格子借一位”，正是我们在纸上写乘法时的“进位”操作。

5. **去掉前导零**：最高位可能是 0（比如 2 × 3 = 6，数组长度是 2，最高位是 0），我们要把这些无意义的零去掉。

6. **把数组逆序再拼成字符串**：因为我们最开始是逆序存的，现在把它翻回来，就是最终答案。

整个过程只使用了 **数组**（类似“格子本”）和 **整数运算**，没有任何语言层面的“大整数”帮助，完全符合题目要求。

#### 代码（Python）

```python
def multiply(num1: str, num2: str) -> str:
    # 特殊情况：只要有一个是 "0"，直接返回 "0"
    if num1 == "0" or num2 == "0":
        return "0"

    # 把字符串逆序、转成整数列表，方便从低位开始相乘
    n1 = [int(ch) for ch in num1[::-1]]   # 例如 "123" -> [3,2,1]
    n2 = [int(ch) for ch in num2[::-1]]   # 例如 "456" -> [6,5,4]

    # 结果最多有 len(num1)+len(num2) 位
    pos = [0] * (len(n1) + len(n2))

    # 逐位相乘并累加到对应的格子里
    for i, d1 in enumerate(n1):          # i 是 n1 中的位索引
        for j, d2 in enumerate(n2):      # j 是 n2 中的位索引
            pos[i + j] += d1 * d2         # 把乘积加到第 i+j 位

    # 处理进位
    for k in range(len(pos)):
        carry = pos[k] // 10              # 本位产生的进位
        pos[k] = pos[k] % 10              # 本位保留的数字
        if carry and k + 1 < len(pos):
            pos[k + 1] += carry           # 把进位加到左边一格

    # 去掉最高位的多余 0（如果有的话）
    while len(pos) > 1 and pos[-1] == 0:
        pos.pop()

    # 把数组逆序拼成字符串，即得到最终乘积
    result = ''.join(str(d) for d in reversed(pos))
    return result
```

> **代码要点注释**  
> - `num1[::-1]`：切片技巧，把字符串倒着读，类似把数字从右往左排。  
> - `pos[i + j] += d1 * d2`：`i` 位和 `j` 位相乘后，结果的 **低位** 正好在第 `i+j` 格子。  
> - `carry = pos[k] // 10` 与 `pos[k] % 10`：把大于 9 的数字拆成“进位”和“当前位”。  
> - `while len(pos) > 1 and pos[-1] == 0: pos.pop()`：删除最高位的多余零，防止答案前面出现不必要的“0”。  

#### 复杂度

- **时间复杂度**：`O(m * n)`（`m = len(num1)`, `n = len(num2)`）  
  - 两层循环遍历每一对数字位，乘法和加法都是常数时间。  
  - 用大白话说，就是“如果第一个数有 100 位，第二个有 200 位，我们要做 100×200=20,000 次小乘法”。  
  - 这已经是手算乘法的理论下限，没有更快的通用办法（除非使用快速傅里叶变换等高级技巧，超出本题范围）。

- **空间复杂度**：`O(m + n)`  
  - 额外的 `pos` 数组长度为 `m+n`，其它变量都是常数空间。  
  - 可以理解为“我们只需要准备和手算时同样多的格子来写每一位的结果”，没有额外的“大型表格”。

> 与暴力解对比：  
> - 暴力解利用了语言内部的大整数实现，时间看似更快但违背规则。  
> - 最优解完全手动模拟，时间仍是 `O(mn)`（和手算一样），但符合题目限制，且空间只用了线性额外空间。

## 心得

- **核心技巧**：把乘法拆成 **逐位相乘 + 进位处理**，即“手算乘法的模拟”。  
- **适用场景**：  
  1. 两个大数相乘（如本题）。  
  2. 大数加法、减法（同样使用逆序数组、进位/借位）。  
  3. 实现 `pow`、`factorial` 等需要大整数的数学运算时的底层实现。  

- **一句话总结**：**把每一位的乘积放进对应的格子，再统一处理进位，就是手算乘法的代码实现。**

## 反思

- **第一反应**：直接把字符串转成整数，用 `int()` 相乘——最快但违规。  
- **最容易踩的坑**：  
  - 忘记处理进位导致每格出现两位数。  
  - 结果最高位是 0 时未去掉，导致答案前面出现多余的 `'0'`（如 `"0012"`）。  
  - 当任意一个输入是 `"0"` 时，直接返回 `"0"`，否则后面的循环会得到空字符串或错误结果。  

- **下次遇到同类题**：**第一步先把数字倒序放进列表**，然后 **按位相乘、累加到对应位置**，最后 **统一进位并去掉前导零**。这套思路几乎可以应对所有“大数运算”题目。
