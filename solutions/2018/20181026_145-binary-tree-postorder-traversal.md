## 解题过程

### 1. 直觉解（暴力）

#### 思路  

二叉树的**后序遍历**的顺序是：先遍历左子树 → 再遍历右子树 → 最后访问根节点。  
最直接的想法就是**递归**：把「遍历左子树」和「遍历右子树」这两件事交给函数自己去完成，等左右子树都遍历完了，再把当前节点的值加入结果列表。

> **类比**：把树想成一本章节目录，左子树是「左边的章节」，右子树是「右边的章节」，而根节点是「本章节的标题」。后序遍历就像先读完左边的所有小节，再读完右边的所有小节，最后才写下本章节的标题。

递归的实现只需要一个**列表**（相当于笔记本）来保存遍历顺序，函数的调用栈（Python 自动维护的）自然充当了「记忆」——它会在遍历左子树、右子树时保存当前节点的状态，等子树遍历完再回到这里继续执行。

#### 代码（Python）

```python
# Definition for a binary tree node.
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val          # 节点的数值
        self.left = left        # 左子树
        self.right = right      # 右子树

def postorder_traversal(root):
    """
    递归版后序遍历
    :param root: TreeNode 或 None
    :return: List[int] 后序遍历得到的节点值序列
    """
    res = []                     # 用来保存遍历结果的列表

    def dfs(node):
        if not node:             # 空节点直接返回
            return
        dfs(node.left)           # 先遍历左子树
        dfs(node.right)          # 再遍历右子树
        res.append(node.val)     # 最后把根节点的值加入结果

    dfs(root)                    # 从根节点开始递归
    return res
```

#### 复杂度  

- **时间复杂度：O(n)** — `n` 是树中节点的个数。每个节点恰好被访问一次（左、右、根各一次），所以总共是线性时间。  
- **空间复杂度：O(h)** — `h` 是树的高度。递归调用会占用 `h` 层栈帧，最坏情况下（链状树）`h = n`，所以最差是 O(n)。如果树是平衡的，`h ≈ log n`，空间更少。

### 2. 最优解

#### 思路  

递归实现虽然简洁，但它依赖系统调用栈，**在面试或生产环境**里往往更倾向于**显式地使用栈**来模拟递归过程，这样可以更好地控制空间并且避免递归深度过大导致的栈溢出。

**瓶颈**在于递归本身的调用栈。我们可以把「递归」这件事手动写出来：用一个 **列表当栈**（Python 的 `list`）来保存待访问的节点，同时记录我们已经遍历了左子树还是右子树。

后序遍历的一个常用技巧是**先根后右左**的遍历顺序（根 → 右 → 左），再把最终得到的序列**反转**。因为如果我们把根、右、左的顺序写出来，倒过来正好就是左、右、根——这正是后序遍历的要求。

实现步骤：

1. 初始化一个栈 `stack`，把根节点压入。  
2. 当栈不为空时，弹出栈顶节点 `node`，把 `node.val` 加入 **结果列表 `out`**（此时的顺序是根、右、左）。  
3. 如果 `node.left` 不为空，先把左子树压入栈；如果 `node.right` 不为空，再把右子树压入栈。**注意压入的顺序是左先右后**，因为栈是后进先出，右子树会先被弹出，从而实现根→右→左的遍历。  
4. 循环结束后，`out` 中的顺序是「根、右、左」，我们只需要 `out.reverse()`（或 `out[::-1]`）得到后序遍历。

> **类比**：想象你在整理一本书的章节，先把章节标题放进一个盒子（栈），每次拿出最上面的标题写下来，然后把它的子章节（左、右）继续放进盒子。因为右子章节先放进去，最后会先被拿出来，正好实现「先右后左」的顺序。写完全部后再把顺序倒过来，就得到「左→右→根」的阅读顺序。

#### 代码（Python）

```python
def postorder_traversal_iter(root):
    """
    迭代版后序遍历（使用显式栈 + 逆序技巧）
    :param root: TreeNode 或 None
    :return: List[int] 后序遍历得到的节点值序列
    """
    if not root:
        return []                # 空树直接返回空列表

    stack = [root]               # 初始化栈，先放根节点
    out = []                     # 用来按 “根-右-左” 顺序记录节点值

    while stack:
        node = stack.pop()       # 弹出栈顶节点
        out.append(node.val)     # 先记录根节点的值

        # 先左后右压栈，确保右子树先被弹出
        if node.left:
            stack.append(node.left)   # 左子树入栈
        if node.right:
            stack.append(node.right)  # 右子树入栈

    # 现在 out 的顺序是 根-右-左，翻转得到左-右-根（后序遍历）
    return out[::-1]             # 切片逆序，等价于 out.reverse()
```

#### 复杂度  

- **时间复杂度：O(n)** — 每个节点被压栈、弹栈各一次，且只做了常数次操作，总体线性。  
- **空间复杂度：O(n)** — 最坏情况下栈里会同时保存所有节点（比如完全不平衡的树），所以需要 `n` 的空间。相较于递归的 `O(h)`，这里的空间上限是 `n`，但在实际面试中更可控，也避免了递归深度限制。

## 心得

- **核心技巧**：利用「根→右→左」的遍历顺序加一次逆序，能够把后序遍历转化为栈的自然遍历方式。  
- **适用场景**：  
  1. 任意二叉树的后序遍历（本题）。  
  2. 需要在遍历过程中**后处理**子树结果的情况（如计算子树大小、求树的最大路径和）。  
  3. 类似的「先根后左后右」的遍历（前序）也可以用类似的压栈顺序来实现。  
- **一句话总结**：后序遍历 = 「根→右→左」遍历后再倒序。

## 反思

- **第一反应**：看到「后序」自然想到递归，因为递归的调用顺序正好匹配「左、右、根」。  
- **最容易踩的坑**：  
  - 忘记对空树 `root = None` 的特判，会导致 `None` 被加入结果。  
  - 在迭代实现里压栈的顺序写反了（先右后左），会得到「根→左→右」的顺序，逆序后就变成「右→左→根」，不符合后序。  
  - 结果列表忘记逆序，直接返回「根→右→左」会错。  
- **下次第一步**：先判断能否用递归快速写出正确逻辑，随后思考「栈能否模拟递归」以及「是否可以通过顺序转换+逆序」得到更稳妥的迭代解。
