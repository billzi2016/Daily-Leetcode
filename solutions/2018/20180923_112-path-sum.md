# #112. 路径总和 / Path Sum

## 题目（英文原版）

**Description**

Given the root of a binary tree and an integer targetSum, return true if the tree has a root-to-leaf path such that adding up all the values along the path equals targetSum.
A leaf is a node with no children.

**Examples**

**Example 1:**

```
Input: root = [5,4,8,11,null,13,4,7,2,null,null,null,1], targetSum = 22
Output: true
Explanation: The root-to-leaf path with the target sum is shown.
```

**Example 2:**

```
Input: root = [1,2,3], targetSum = 5
Output: false
Explanation: There are two root-to-leaf paths in the tree:
(1 --> 2): The sum is 3.
(1 --> 3): The sum is 4.
There is no root-to-leaf path with sum = 5.
```

**Example 3:**

```
Input: root = [], targetSum = 0
Output: false
Explanation: Since the tree is empty, there are no root-to-leaf paths.
```

**Constraints**

- The number of nodes in the tree is in the range [0, 5000].
- -1000 <= Node.val <= 1000
- -1000 <= targetSum <= 1000

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  

最直接的想法是：**把所有从根节点到叶子节点的路径都列举出来**，然后把每条路径上的节点值相加，看看有没有恰好等于 `targetSum`。  

- **用到的数据结构**  
  - **二叉树**：每个节点有左、右两个孩子，就像一棵倒挂的家谱树。  
  - **递归的调用栈**：递归本质上是一种“隐形的栈”。可以把它想象成我们在家里找一本书时，用纸条记下已经走过的房间——纸条的顺序就是栈的顺序。  
  - **列表（list）**：暂存当前路径上所有节点的值，类似于把走过的房间号写在纸上，等走到叶子时检查总和。  

- **为什么正确**  
  只要把 **所有** 根到叶的路径都遍历一遍，就一定不会漏掉满足条件的那条路径。遍历完后，如果发现某条路径的和等于目标，就返回 `True`，否则返回 `False`。  

- **复杂度分析（大白话）**  
  - **时间复杂度**：每个节点都会被访问一次，访问时会把它加入路径列表，再在回溤时把它移除。因为我们要检查每条根到叶的路径，所以总的时间是 `O(N)`，其中 `N` 是节点数。这里的 “O(N)” 可以理解为“和树里节点数量成正比”。  
  - **空间复杂度**：递归调用栈的最大深度等于树的高度 `h`，最坏情况下（完全不平衡的链状树）`h = N`，所以最坏空间是 `O(N)`。在平衡二叉树时，`h ≈ log N`，所以平均占用的空间会更小。  

#### 代码（Python）

```python
# Definition for a binary tree node.
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val          # 节点的数值
        self.left = left        # 左子树
        self.right = right      # 右子树

class Solution:
    def hasPathSum(self, root: TreeNode, targetSum: int) -> bool:
        """
        暴力 DFS：遍历所有根到叶的路径，检查是否存在和为 targetSum 的路径
        """
        if not root:                     # 树为空，直接返回 False
            return False

        # 辅助函数：递归遍历
        def dfs(node: TreeNode, cur_sum: int) -> bool:
            # 把当前节点值加入累计和
            cur_sum += node.val

            # 叶子节点：没有左孩子也没有右孩子
            if not node.left and not node.right:
                # 判断累计和是否等于目标值
                return cur_sum == targetSum

            # 递归左子树（如果有左子树）
            if node.left and dfs(node.left, cur_sum):
                return True
            # 递归右子树（如果有右子树）
            if node.right and dfs(node.right, cur_sum):
                return True

            # 左右子树都没有找到满足条件的路径
            return False

        # 从根节点开始搜索
        return dfs(root, 0)
```

#### 复杂度  

- **时间复杂度**：`O(N)` — 每个节点只访问一次，`N` 是树的节点数。  
- **空间复杂度**：`O(H)` — 递归栈的深度等于树的高度 `H`，最坏 `O(N)`，平均 `O(log N)`（平衡树）。

### 2. 最优解  

#### 思路  

从暴力解可以看到，**瓶颈不在遍历本身**（我们已经只遍历了一遍），而在 **每次递归都要把累计和 `cur_sum` 复制传递**。其实我们可以把累计和直接在参数里传递，而不需要额外的列表保存路径；这已经是最简洁的做法。  

因此，**最优解仍然是深度优先搜索（DFS）**，但我们把实现写得更“轻量”。另外，还可以用 **广度优先搜索（BFS）** 用队列一次遍历所有层，思路类似，只是实现方式不同。下面给出两种写法，任选其一即可。

- **核心技巧**：在递归（或迭代）过程中**把目标值减去已经走过的节点值**，这样到达叶子时只需要检查剩余的目标值是否为 0，省去额外的加法操作。  
- **类比**：把 `targetSum` 想象成装满水的杯子，走过一个节点就倒掉对应容量的水，最后如果杯子恰好空了（剩余 0），说明路径和正好等于目标。  

#### 代码（Python）—— 递归版（最简洁）

```python
class Solution:
    def hasPathSum(self, root: TreeNode, targetSum: int) -> bool:
        """
        递归版最优解：把 targetSum 当作“还剩多少”来传递
        """
        if not root:                     # 空树直接返回 False
            return False

        # 把当前节点值从目标和中减去
        targetSum -= root.val

        # 到达叶子节点，检查剩余的 targetSum 是否为 0
        if not root.left and not root.right:
            return targetSum == 0

        # 只要左子树或右子树有一条满足条件，就返回 True
        return (self.hasPathSum(root.left, targetSum) or
                self.hasPathSum(root.right, targetSum))
```

#### 代码（Python）—— 迭代版（BFS）

```python
from collections import deque

class Solution:
    def hasPathSum(self, root: TreeNode, targetSum: int) -> bool:
        """
        BFS 版：使用队列同时保存节点和对应的剩余 targetSum
        """
        if not root:
            return False

        # 队列里存 (节点, 还剩多少) 的元组
        q = deque([(root, targetSum - root.val)])

        while q:
            node, remain = q.popleft()

            # 叶子节点且刚好用完所有目标和
            if not node.left and not node.right and remain == 0:
                return True

            # 左子树加入队列（如果存在）
            if node.left:
                q.append((node.left, remain - node.left.val))
            # 右子树加入队列（如果存在）
            if node.right:
                q.append((node.right, remain - node.right.val))

        # 所有路径都遍历完仍未找到满足条件的
        return False
```

#### 复杂度  

- **时间复杂度**：`O(N)` — 仍然只遍历一次所有节点。相比暴力解没有额外的遍历或列表操作。  
- **空间复杂度**：`O(H)`（递归版）或 `O(N)`（最坏情况的 BFS 队列）。递归版的栈深度等于树高，BFS 需要保存当前层的所有节点，最坏情况下可能接近 `N`。

## 心得  

- **核心技巧**：**在遍历过程中把目标和逐步“扣除”**（或累加），到叶子时检查是否恰好为 0。  
- **适用的题型**  
  1. **Path Sum 系列**：如 `Path Sum II`（要求返回所有满足条件的路径）。  
  2. **二叉树的目标路径问题**：如 `Sum of Left Leaves`（求左叶子之和）。  
  3. **图的路径和问题**：如 “从起点到终点的路径和是否为给定值”。  
- **一句话总结解题钥匙**：**把“累计和”或“剩余目标”随递归/迭代一起传递，叶子时只看是否为 0**。

## 反思  

- **第一反应**：想到要把所有根到叶的路径都列出来检查。  
- **最容易踩的坑**  
  - **忘记判断叶子节点**：必须是 **没有左孩子也没有右孩子** 的节点才能算作合法路径终点。  
  - **空树的处理**：`root = []` 时直接返回 `False`，否则递归会报空指针错误。  
  - **负数和零的情况**：目标和、节点值都可能是负数或零，不能把 `> 0` 当作提前剪枝的依据。  
- **下次类似题的第一步**：先确认“**路径的结束条件**（叶子、终点）”，然后决定是 **DFS 递归** 还是 **BFS 迭代**，并把 **累计/剩余和** 随路径一起传递。
