## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是把 **所有** 排列列举出来，然后按字典序（也就是从小到大）排好序，最后取第 `k` 个。  
实现上可以使用 **回溯**（depth‑first search）来生成全排列：

- **列表 `path`**：当前已经选好的数字，像是我们手里已经排好序的“拼图块”。
- **集合 `used`**：记录哪些数字已经被使用，类似于查字典时的“已经划掉的词”。  
- 每次在未使用的数字中任选一个加入 `path`，递归继续，直到 `path` 长度等于 `n`，说明得到一个完整的排列。

把所有得到的排列放进 `res` 列表后，直接返回 `res[k‑1]`（因为下标从 0 开始）。

> 为什么这个方法一定能得到正确答案？  
> 因为回溯会遍历 **所有** 可能的选择顺序，而每一种合法的选择顺序恰好对应一个唯一的排列。只要把它们全部收集起来并保持产生的顺序（本身就是字典序），第 `k` 个就是题目要求的答案。

#### 代码（Python）

```python
def getPermutation_brute(n: int, k: int) -> str:
    """暴力版：生成全部排列，然后直接取第 k 个"""

    res = []                     # 用来保存所有排列，类似一个装满纸条的盒子
    path = []                    # 当前正在构造的排列，像是正在拼的拼图
    used = [False] * (n + 1)     # 标记 1~n 是否已经被使用，类似字典的“已划线”

    def backtrack():
        # 当 path 长度等于 n，说明得到一个完整的排列
        if len(path) == n:
            # 把列表转成字符串再加入结果集
            res.append(''.join(map(str, path)))
            return

        # 依次尝试每一个可能的数字
        for num in range(1, n + 1):
            if not used[num]:                 # 只有未使用的数字才可以选
                used[num] = True              # 标记为已使用
                path.append(num)              # 把它加入当前排列
                backtrack()                   # 继续往下搜索
                path.pop()                    # 回溯：把它踢出来
                used[num] = False             # 取消标记，恢复可选状态

    backtrack()
    # k 是从 1 开始计数的，列表索引从 0 开始，所以要减 1
    return res[k - 1]
```

#### 复杂度

- **时间复杂度**：`O(n! * n)`  
  - `n!` 是所有排列的数量，**每**个排列我们都要把 `n` 个数字拼成字符串（`O(n)`），所以总体是 `n! * n`。  
  - 用大白话说，就是“随着 `n` 增大，时间会像阶乘一样飞速增长”，即使 `n` 只有 9，`9! = 362880`，在电脑上也能跑完，但已经不是“快”的解法了。

- **空间复杂度**：`O(n! * n)`（保存所有排列） + `O(n)`（递归栈和临时数组）  
  - 这里主要的空间消耗是把所有排列存进 `res` 列表。如果只想得到第 `k` 个而不保存全部，可以把 `k` 计数下来，一旦找到第 `k` 个就提前返回，这样空间可以降到 `O(n)`。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **生成了所有排列**，但我们只需要第 `k` 个。  
观察一下排列的生成规律可以发现：

- 对于 `n` 个数，**首位**的取值会把全部排列分成 `n` 组，每组大小为 `(n-1)!`。  
  - 例如 `n = 4` 时，所有排列按首位划分为 4 组：  
    - 以 `1` 开头的有 `3! = 6` 个  
    - 以 `2` 开头的也有 6 个，以此类推。

- 因此，只要知道 `k` 落在哪一组，就能直接确定首位的数字。  
  - 用 **整数除法** `group = (k-1) // (n-1)!`（这里的 `k-1` 把 1‑based 转成 0‑based）得到组号。  
  - 组号对应的数字就是当前可选数字列表（初始为 `[1,2,…,n]`）中的第 `group` 个。

- 选出首位后，剩下的 `n-1` 个数字继续用同样的方式决定第二位、第三位……  
  - 这就是 **阶乘进制**（factorial number system） 的思想：把 `k-1` 用一系列阶乘除法表示，每一步的余数决定下一个位置选哪个数字。

- 实现细节  
  1. 预先计算 `1! … (n-1)!`，放在数组 `fact` 中，方便随时查询。  
  2. 用一个 **列表 `numbers`** 保存当前还未被使用的数字，类似“抽屉里的可选球”。  
  3. 循环 `i` 从 `n` 倒着遍历：  
     - `idx = (k-1) // fact[i-1]` → 取出第 `idx` 个数字作为当前位置。  
     - 把该数字从 `numbers` 中删掉（相当于把抽屉里的球拿走）。  
     - 更新 `k = (k-1) % fact[i-1] + 1`，准备决定下一位。  

这样我们只遍历 `n` 次，就能直接得到第 `k` 个排列，时间复杂度从阶乘级下降到线性级。

#### 代码（Python）

```python
def getPermutation(n: int, k: int) -> str:
    """最优解：利用阶乘进制直接构造第 k 个排列"""

    # 1. 预计算阶乘：fact[i] = i!
    fact = [1] * (n + 1)          # fact[0] = 1，后面会依次乘
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i

    # 2. 把可选的数字放进列表，类似抽屉里的球，按顺序排列
    numbers = [str(i) for i in range(1, n + 1)]

    # 3. 结果字符串，用列表收集再 join，效率更好
    ans = []

    # 把 k 从 1‑based 转成 0‑based，后面每一步都用 (k-1)
    k -= 1

    # 4. 从高位到低位依次决定每一位的数字
    for i in range(n, 0, -1):          # i 表示当前还有 i 个位置待填
        # 当前位的阶乘大小是 (i-1)!
        idx, k = divmod(k, fact[i - 1])   # idx 决定取哪个数字，k 为余数准备下一轮
        ans.append(numbers.pop(idx))      # 取出并移除该数字

    return ''.join(ans)
```

#### 复杂度

- **时间复杂度**：`O(n²)`（在最坏情况下 `pop(idx)` 是 O(n) 的列表删除操作，循环 `n` 次）  
  - 对于 `n ≤ 9` 的限制，这个复杂度已经足够快。  
  - 用大白话说，就是“最多只需要遍历 9 次，每次最多搬走 9 个元素”，几乎可以忽略不计。

- **空间复杂度**：`O(n)`  
  - 只用了 `numbers`、`fact`、`ans` 三个长度为 `n` 的数组，额外的递归栈几乎为 0。

## 心得

- **核心技巧**：**阶乘进制 + 贪心选择**。先把所有可能的排列按首位分组，然后用除法快速定位所在组，再把对应的数字摘出来，递归地处理剩余位置。  
- **适用的题型**  
  1. **第 k 大/小排列**（如本题）  
  2. **排列序列的排名**（给定排列求它是第几小）  
  3. **组合数的字典序第 k 项**（类似 “第 k 大的组合”）  
- **一句话总结**：**把“要找第 k 个”变成“先算出每一位该选哪个”，用阶乘把搜索空间一次性切分掉**。

## 反思

- **第一反应**：立刻想到“把所有排列都列出来”，因为最直观的办法总是先穷举。  
- **最容易踩的坑**  
  1. **下标偏移**：题目中的 `k` 是从 1 开始计数，Python 列表是从 0 开始，需要把 `k-1` 先转成 0‑based，忘记会导致越界或答案错位。  
  2. **删除元素的代价**：`pop(idx)` 在列表中是 O(n) 的操作，若不注意在循环里频繁删除会导致整体变成 `O(n²)`（仍可接受），但如果改成 `deque` 或其它结构可以进一步优化。  
  3. **阶乘溢出**：虽然 `n ≤ 9`，阶乘不会超出 Python 的整数范围，但在语言限制更严的情况下要注意使用大整数或提前检查。  

- **下次遇到同类题**：第一步先 **思考是否可以把搜索空间分块**（比如首位、首两位），然后用 **数学公式**（阶乘、组合数）直接定位，而不是完整枚举。这样往往能把时间复杂度从指数级降到线性级。
