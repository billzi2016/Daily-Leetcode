## 题目（英文原版）

**Description**

Given an m x n grid of characters board and a string word, return true if word exists in the grid.
The word can be constructed from letters of sequentially adjacent cells, where adjacent cells are horizontally or vertically neighboring. The same letter cell may not be used more than once.
Follow up: Could you use search pruning to make your solution faster with a larger board?

**Examples**

**Example 1:**

```
Input: board = [["A","B","C","E"],["S","F","C","S"],["A","D","E","E"]], word = "ABCCED"
Output: true
```

**Example 2:**

```
Input: board = [["A","B","C","E"],["S","F","C","S"],["A","D","E","E"]], word = "SEE"
Output: true
```

**Example 3:**

```
Input: board = [["A","B","C","E"],["S","F","C","S"],["A","D","E","E"]], word = "ABCB"
Output: false
```

**Constraints**

- m == board.length
- n = board[i].length
- 1 <= m, n <= 6
- 1 <= word.length <= 15
- board and word consists of only lowercase and uppercase English letters.

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**把每个格子当成起点，尝试把单词的每个字符一个接一个地走下去**。  
只要我们能在相邻（上下左右）格子里找到下一个字符，就继续向前；走不通就回头（撤销刚才的选择），换另一条路继续尝试。  

这类“尝试所有可能路径、走不通就回退”的过程在算法里叫 **回溯（Backtracking）**。  

- **数据结构**：  
  - `board` 本身是一个二维列表（矩阵），可以把它想象成一张字母拼图。  
  - 为了防止同一个格子被重复使用，我们需要一个“标记”。最常见的做法是把已经访问过的格子暂时改成特殊字符（比如 `#`），相当于在字典里把这个词条划掉，后面再查不到它。  
  - 递归函数 `dfs(r, c, idx)` 表示“从坐标 `(r, c)` 开始，能否匹配到 `word[idx:]`（从第 `idx` 位开始的子串）”。  

- **为什么正确**：  
  - 我们从每个格子出发，穷举所有可能的走法。只要有一种走法能够完整匹配单词，就返回 `True`。  
  - 回溯保证了**不遗漏**任何合法路径，同时在走不通的分支上及时撤销，避免错误的“重复使用”。  

- **复杂度初探**：  
  - 最坏情况下，单词长度为 `L`，每一步都有最多 4 个方向可以选择（上、下、左、右），所以搜索树的分支因子是 4，深度是 `L`，理论上会尝试 `4^L` 条路径。  
  - 但是每条路径最多只能遍历 `m*n`（格子总数）次，因为走过的格子会被标记，不能再次进入。  
  - **时间复杂度** 大约是 `O(m * n * 4^L)`，这里的 `4^L` 表示指数级的增长，`L` 越大，耗时会快速飙升。  
  - **空间复杂度** 主要是递归栈的深度，最深会到 `L`，所以是 `O(L)`。

#### 代码（Python）

```python
from typing import List

def exist(board: List[List[str]], word: str) -> bool:
    rows, cols = len(board), len(board[0])

    # 深度优先搜索 + 回溯
    def dfs(r: int, c: int, idx: int) -> bool:
        # ① 完成匹配
        if idx == len(word):
            return True
        # ② 越界或字符不匹配
        if r < 0 or r >= rows or c < 0 or c >= cols or board[r][c] != word[idx]:
            return False

        # ③ 标记当前格子已访问（用 # 暂时替代原字符）
        tmp = board[r][c]
        board[r][c] = '#'

        # ④ 向四个方向继续搜索
        found = (dfs(r + 1, c, idx + 1) or   # 下
                 dfs(r - 1, c, idx + 1) or   # 上
                 dfs(r, c + 1, idx + 1) or   # 右
                 dfs(r, c - 1, idx + 1))     # 左

        # ⑤ 恢复格子原来的字符，撤销标记
        board[r][c] = tmp
        return found

    # 从每个格子尝试作为起点
    for i in range(rows):
        for j in range(cols):
            if dfs(i, j, 0):          # idx 从 0 开始匹配
                return True
    return False
```

#### 复杂度

- **时间复杂度**：`O(m * n * 4^L)`  
  - `m * n` 是所有起点的数量。  
  - `4^L` 表示在每一步最多有 4 种选择，`L` 是单词长度。指数级的意思是，单词稍长时，搜索次数会呈指数增长。

- **空间复杂度**：`O(L)`  
  - 只用到了递归栈，最深的递归层数等于单词的长度 `L`。其它额外空间（如标记）都是在原数组上原地修改的。

### 2. 最优解

#### 思路  

暴力回溯的 **瓶颈** 在于每一步都盲目尝试四个方向，即使有些方向根本不可能得到匹配。我们可以在搜索前做一点**剪枝（pruning）**，提前排除不可能成功的分支，从而大幅降低实际遍历的路径数。

**剪枝的常用技巧**：

1. **先检查字母出现次数**  
   - 如果 board 中某个字母的总出现次数少于 word 中对应字母的出现次数，显然不可能匹配，直接返回 `False`。  
   - 这一步只需要遍历一次 board 和 word，时间代价很小。

2. **决定搜索方向的顺序**  
   - 对于单词的第一个字符，如果它在 board 中出现很多次，尝试每个起点会很慢。我们可以**先从出现次数最少的字符开始**，把搜索的起点限制在最稀少的格子上。  
   - 更进一步，如果单词的前缀和后缀在 board 中出现的概率差别很大（比如前缀很多，后缀很少），可以把单词 **反转**（从后往前匹配），让搜索从稀有字符开始。

3. **在递归里提前判断**  
   - 当我们已经匹配到第 `idx` 位时，检查剩余未匹配的字符在 board 剩余可用格子中的出现次数是否足够。如果不足，直接返回 `False`，不必继续深入。

以上剪枝思路仍然基于 **回溯**，但能显著降低实际的搜索次数。下面的实现综合了 1 和 2 两点——先统计字符频率，若 word 中的稀有字符在 board 中出现次数更少，就 **把 word 反转**，让搜索从稀有字符开始。

**核心算法**：仍是 **深度优先搜索 + 回溯**，只是在进入递归前做了**搜索顺序的优化**。

#### 代码（Python）

```python
from typing import List
from collections import Counter

def exist(board: List[List[str]], word: str) -> bool:
    rows, cols = len(board), len(board[0])
    # 1️⃣ 统计 board 中每个字母的出现次数
    board_counter = Counter(ch for row in board for ch in row)
    word_counter = Counter(word)

    # 2️⃣ 先做一次全局频率剪枝：如果 board 中某字符不足，直接返回 False
    for ch, cnt in word_counter.items():
        if board_counter[ch] < cnt:
            return False

    # 3️⃣ 为了让搜索从“稀有字符”开始，比较 word 首尾字符出现次数
    #    出现次数更少的那一端作为搜索方向（可能需要把 word 反转）
    if board_counter[word[0]] > board_counter[word[-1]]:
        word = word[::-1]   # 反转单词，让稀有字符成为起点

    # 4️⃣ 深度优先搜索 + 回溯（和暴力版几乎相同，只是 word 已经可能被反转）
    def dfs(r: int, c: int, idx: int) -> bool:
        if idx == len(word):                 # 成功匹配完整单词
            return True
        if r < 0 or r >= rows or c < 0 or c >= cols or board[r][c] != word[idx]:
            return False

        # 标记已访问
        tmp = board[r][c]
        board[r][c] = '#'

        # 继续向四个方向搜索
        found = (dfs(r + 1, c, idx + 1) or
                 dfs(r - 1, c, idx + 1) or
                 dfs(r, c + 1, idx + 1) or
                 dfs(r, c - 1, idx + 1))

        # 恢复原字符
        board[r][c] = tmp
        return found

    # 5️⃣ 从每个可能的起点尝试（这里的起点已经是稀有字符所在的格子）
    for i in range(rows):
        for j in range(cols):
            if board[i][j] == word[0] and dfs(i, j, 0):
                return True
    return False
```

#### 复杂度

- **时间复杂度**：`O(m * n * 4^L)` 的上界仍然成立，但剪枝把实际遍历的路径数大幅削减。  
  - 统计字符频率是 `O(m * n + L)`，相对于主搜索可以忽略不计。  
  - 当稀有字符在 board 中出现很少时，实际的起点数会大幅下降，从而显著提升速度。  
  - 在最坏情况下（所有字符频率相同、没有剪枝效果）仍然是指数级 `4^L`，但实际测试里往往快很多。

- **空间复杂度**：`O(L)`（递归栈） + `O(1)`（原地修改），和暴力版相同。  
  - 额外的 `Counter` 只占用常数级空间（最多 52 种大小写字母）。  



## 心得

- **核心技巧**：回溯（DFS） + 剪枝（频率统计、单词反转）。  
- **适用的题型**：  
  1. **Word Search II**（在同一棋盘上寻找多个单词）——需要 Trie 树与回溯结合。  
  2. **岛屿数量 / 最大岛屿面积**（在二维网格中遍历连通块）——同样使用 DFS/回溯。  
  3. **数独求解**（在 9×9 网格中填数字）——回溯加约束剪枝。  
- **一句话总结**：**“把搜索起点放在最稀有的字符上，让回溯从最不可能的地方开始”**，这就是解这类二维搜索题的钥匙。

## 反思

- **第一反应**：看到“相邻格子、不能重复使用”，立刻想到深度优先搜索 + 标记已访问。  
- **最容易踩的坑**：  
  - **越界检查**忘记或写错导致 IndexError。  
  - **标记恢复**写错，导致后面的递归看到错误的字符。  
  - **单词长度为 1**的特殊情况，需要在递归入口或结束条件处理好。  
- **下次遇到同类题**，第一步应该：**统计字符频率，决定是否需要把单词反转或提前返回**，再进入回溯搜索。这样可以在一开始就把搜索空间压缩到最小。
