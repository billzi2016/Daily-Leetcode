# #96. 不同的二叉搜索树 / Unique Binary Search Trees

> 难度：中等 · 标签：Math、Dynamic Programming、Tree、Binary Search Tree、Binary Tree · [LeetCode 链接](https://leetcode.com/problems/unique-binary-search-trees/)

---

## 题目（英文原版）

**Description**

Given an integer n, return the number of structurally unique BST's (binary search trees) which has exactly n nodes of unique values from 1 to n.

**Examples**

**Example 1:**

```
Input: n = 3
Output: 5
```

**Example 2:**

```
Input: n = 1
Output: 1
```

**Constraints**

- 1 <= n <= 19

---

## 题目（中文翻译）

给定一个整数 `n`，返回恰好包含 `n` 个取值为 `1` 到 `n` 的唯一节点的 **结构上唯一的** 二叉搜索树（binary search tree）的数量。

**示例 1**  
输入: `n = 3`  
输出: `5`

**示例 2**  
输入: `n = 1`  
输出: `1`

**约束条件**  
- `1 <= n <= 19`

---

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**每一次把 1~n 中的某个数当根**，左子树只能由比根小的数构成，右子树只能由比根大的数构成。  
于是我们可以递归地：

1. 选一个根 `i`（`i` 从 `1` 到 `n`）  
2. 左子树的节点集合是 `{1 … i-1}`，右子树的节点集合是 `{i+1 … n}`  
3. 递归求左子树的所有可能结构数目 `L`，递归求右子树的所有可能结构数目 `R`  
4. 这棵树的结构数目就是 `L * R`（左子树的每一种形状都可以和右子树的每一种形状自由组合）  
5. 把所有根的情况加起来，就是答案  

> **类比**：想象我们在组装乐高城堡，先选一块砖当城堡的“大门”，左边的墙只能用比“大门”编号小的砖，右边的墙只能用比“大门”编号大的砖。左墙有 `L` 种拼法，右墙有 `R` 种拼法，整座城堡的拼法数就是 `L × R`。

这个递归一定会遍历到所有合法的 BST 结构，所以答案是正确的。

**为什么会慢**  
递归里会大量重复计算同样的子问题。例如，求 `n=3` 时会分别计算左子树 `size=1`、`size=2`…，而在不同根的递归分支里，这些子树大小会被重复求解，导致指数级的时间开销。

#### 代码（Python）

```python
def num_trees_bruteforce(n: int) -> int:
    """暴力递归：返回 1~n 可以组成多少棵不同形状的 BST"""
    # 递归函数，求区间 [l, r]（包含）可以组成的 BST 数目
    def count(l: int, r: int) -> int:
        # 区间为空，只有一种空树
        if l > r:
            return 1
        total = 0
        # 枚举每一个数作为根
        for root in range(l, r + 1):
            # 左子树只能使用比根小的数
            left = count(l, root - 1)
            # 右子树只能使用比根大的数
            right = count(root + 1, r)
            total += left * right          # 左右子树的组合方式相乘
        return total

    return count(1, n)
```

#### 复杂度  

- **时间复杂度**：`O(2^n)`（指数级）  
  - 大白话：随着节点数的增加，递归树会呈指数增长，类似每层都要分叉成两条路，导致计算量几乎翻倍增长。  
- **空间复杂度**：`O(n)`（递归栈深度）  
  - 只需要保存递归调用的栈，最深的递归层数等于树的高度，最多 `n` 层。

### 2. 最优解  

#### 思路  

从暴力解可以看到，**子问题是「区间大小」而不是「具体的左右边界」**。  
如果我们只关心「有 `k` 个节点的 BST 有多少种形状」而不在乎这些节点到底是哪些数，就可以把所有「相同大小」的子问题合并，只算一次。  

设 `G(k)` 为「恰好有 `k` 个节点的不同 BST 的数量」。  
当我们选根节点时，根左边会有 `i-1` 个节点，根右边会有 `k-i` 个节点（`i` 为根的序号，`1 ≤ i ≤ k`），于是：

```
G(k) = Σ_{i=1..k} G(i-1) * G(k-i)
```

- `G(i-1)`：左子树的形状数目  
- `G(k-i)`：右子树的形状数目  
- 两者相乘得到根为 `i` 时的组合数  
- 对所有可能的根 `i` 求和得到总数  

这就是**卡特兰数（Catalan Number）**的递推式。  

我们可以用**动态规划（DP）**把 `G(0)…G(n)` 按顺序算出来，保证每个子问题只算一次。

> **类比**：把「有 `k` 块拼图可以拼出多少种图案」想成「先挑一块作为中心，其余左边、右边各自独立拼」，左边的拼法只和左边块数有关，右边的拼法只和右边块数有关。把所有可能的中心块枚举并相乘，再把结果累加，就得到了完整的拼法数。

#### 代码（Python）

```python
def num_trees(n: int) -> int:
    """动态规划求解：返回 1~n 可以组成多少棵不同形状的 BST（Catalan 数）"""
    # G[i] 表示恰好 i 个节点的 BST 形状数目
    G = [0] * (n + 1)
    G[0] = 1            # 空树算作一种合法结构
    G[1] = 1            # 只有一个节点时，唯一的 BST

    # 从小到大计算 G[2] … G[n]
    for nodes in range(2, n + 1):
        total = 0
        # 枚举根节点的位置 i（1-indexed）
        for root in range(1, nodes + 1):
            left = G[root - 1]          # 左子树节点数 = root-1
            right = G[nodes - root]     # 右子树节点数 = nodes-root
            total += left * right       # 组合方式相乘
        G[nodes] = total                # 保存结果，供后续子问题使用

    return G[n]
```

#### 复杂度  

- **时间复杂度**：`O(n²)`  
  - 大白话：外层循环跑 `n` 次，内层循环最多也跑 `n` 次（实际上是 `1 + 2 + … + n = n(n+1)/2`），所以整体是「平方级」的计算量。相比指数级的暴力解，已经快了很多。  
- **空间复杂度**：`O(n)`  
  - 只需要一个长度为 `n+1` 的数组 `G` 来存放子问题的答案，空间随 `n` 线性增长。

> **进一步的优化**：如果只想要答案而不需要所有中间结果，可以使用公式 `C_n = (2n)! / ((n+1)! * n!)`（直接求第 `n` 个卡特兰数），时间可以降到 `O(n)`，但实现会涉及大整数阶乘，动态规划已经足够简洁且易懂。

## 心得  

- **核心技巧**：把「根的选择」拆解为「左子树大小」和「右子树大小」的乘积，利用**动态规划**把相同规模的子问题只算一次，这正是卡特兰数的递推公式。  
- **适用的题型**  
  1. **不同的二叉搜索树计数**（本题）  
  2. **不同的括号合法配对数**（LeetCode 22、Valid Parentheses 计数）  
  3. **不同的完整二叉树形状数**（例如「不同的满二叉树」）  
- **一句话总结解题钥匙**：**把“大树”拆成“根 + 左子树 + 右子树”，左、右子树只与节点数量有关，利用 DP 把重复子问题合并**。

---

## 反思  

- **第一反应**：看到“唯一的 BST”立刻想到“根左右子树递归”，于是写出最直接的递归公式。  
- **最容易踩的坑**  
  - 忘记把空树计为一种合法结构（`G[0] = 1`），导致递推公式少了一项，答案会偏小。  
  - 对 `n = 0`（虽然题目不要求）或 `n = 1` 的边界情况没有单独处理，递归/DP 可能出现索引错误。  
- **下次遇到同类题**：第一步先**明确子问题的“规模”**（如节点数、区间长度），判断是否有**重叠子问题**，如果有就立刻考虑 **DP** 或 **记忆化搜索**，而不是直接写全递归。
