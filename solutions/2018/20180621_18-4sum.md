# #18. 四数之和 / 4Sum

## 题目（英文原版）

**Description**

Given an array nums of n integers, return an array of all the unique quadruplets [nums[a], nums[b], nums[c], nums[d]] such that:
You may return the answer in any order.

**Examples**

**Example 1:**

```
Input: nums = [1,0,-1,0,-2,2], target = 0
Output: [[-2,-1,1,2],[-2,0,0,2],[-1,0,0,1]]
```

**Example 2:**

```
Input: nums = [2,2,2,2,2], target = 8
Output: [[2,2,2,2]]
```

**Constraints**

- 1 <= nums.length <= 200
- -109 <= nums[i] <= 109
- -109 <= target <= 109

## 题目（中文翻译）

给定一个包含 **n** 个整数的数组 `nums`（array），返回所有唯一的四元组 `[nums[a], nums[b], nums[c], nums[d]]`（quadruplets），使得这四个数的和等于目标值 `target`。可以以任意顺序返回答案。

**示例 1**  
**输入**: `nums = [1,0,-1,0,-2,2]`, `target = 0`  
**输出**: `[[-2,-1,1,2],[-2,0,0,2],[-1,0,0,1]]`

**示例 2**  
**输入**: `nums = [2,2,2,2,2]`, `target = 8`  
**输出**: `[[2,2,2,2]]`

**约束条件**  
- `1 <= nums.length <= 200`  
- `-10^9 <= nums[i] <= 10^9`  
- `-10^9 <= target <= 10^9`

---

## 解题过程

### 1. 直觉解（暴力）

#### 思路  
最直接的想法是把数组里所有可能的四个下标 `(a, b, c, d)` 都枚举一遍，检查它们对应的四个数之和是否等于 `target`。  

- **用到的数据结构**：  
  - **列表**（list）存放原始数组。  
  - **集合**（set）用来去重。集合可以类比为「字典」的查词本，放进去的每个四元组会自动去掉重复的记录。  
- **为什么正确**：只要遍历到所有四元组，就不会错过任何满足条件的解。只要把满足条件的四元组加入集合，最后把集合转成列表返回即可。  
- **时间/空间复杂度**：  
  - 需要四层循环，每层最多遍历 `n` 次，整体是 `n × n × n × n = n⁴`，这就是 **O(n⁴)**。  
    - 大白话：如果数组有 10 个数，暴力解要尝试 10⁴ = 10,000 种组合；如果是 100 个数，就要尝试 100⁴ = 100,000,000 种组合，明显会超时。  
  - 额外使用一个集合来保存不重复的四元组，最坏情况下会存 `C(n,4)`（从 n 个数中挑 4 个）的组合，空间是 **O(n⁴)**（实际上远小于时间复杂度，但仍然不理想）。

#### 代码（Python）

```python
from typing import List

def fourSum_brute(nums: List[int], target: int) -> List[List[int]]:
    n = len(nums)
    result_set = set()                     # 用集合自动去重，类似“查字典”
    # 四层循环，枚举所有四元组的下标
    for i in range(n):
        for j in range(i + 1, n):
            for k in range(j + 1, n):
                for l in range(k + 1, n):
                    s = nums[i] + nums[j] + nums[k] + nums[l]
                    if s == target:         # 和相等才是合法答案
                        quad = tuple(sorted([nums[i], nums[j], nums[k], nums[l]]))
                        result_set.add(quad)   # 加入集合，自动去重
    # 把集合转成列表返回
    return [list(quad) for quad in result_set]
```

#### 复杂度

- **时间复杂度**：`O(n⁴)` —— 需要四层循环遍历所有可能的四元组。  
- **空间复杂度**：`O(n⁴)`（最坏情况）—— 用集合存放所有不重复的四元组。

### 2. 最优解

#### 思路  
暴力解的瓶颈在于 **四层循环**。我们可以把它降到 **三层循环 + 双指针**，把时间复杂度从 `O(n⁴)` 降到 `O(n³)`，在 `n ≤ 200` 的约束下已经足够快。

优化思路如下：

1. **先排序**  
   把数组从小到大排好序。排序后，相邻的相同数字会聚在一起，后面可以很方便地跳过重复的组合，防止答案出现重复。排序相当于把散落的书本摆成顺序，后面找特定两本书的和时就能像“指针”一样从两端往中间移动。

2. **固定前两个数**  
   用两层循环固定下标 `i`（第一个数）和 `j`（第二个数），这相当于先挑出两本书。  
   - 为了避免重复，`i` 与 `i-1` 对应的数相同就直接 `continue`，`j` 与 `j-1` 相同也跳过。

3. **剩下的两数用双指针**  
   对于剩下的子数组（下标范围 `j+1 … n-1`），我们要找两数之和等于 `target - nums[i] - nums[j]`。  
   - **左指针 `left`** 从子数组左端开始，**右指针 `right`** 从右端开始。  
   - 如果 `nums[left] + nums[right]` 小于目标，则把 `left` 往右移（因为数组是升序，右移会让和增大）；如果大于目标，则把 `right` 往左移。  
   - 当恰好等于目标时，记录这四个数，然后同样跳过 `left`、`right` 位置的重复值，继续搜索。

4. **整体时间复杂度**  
   - 最外层两层循环是 `O(n²)`，内部的双指针在每一次 `i, j` 组合下最多遍历一次整个子数组，时间是 `O(n)`。  
   - 综合起来是 `O(n³)`。

5. **空间复杂度**  
   - 只用了常数级的额外变量（指针、临时列表），所以是 **O(1)**（不计返回结果的空间）。

#### 代码（Python）

```python
from typing import List

def fourSum(nums: List[int], target: int) -> List[List[int]]:
    nums.sort()                     # 先排序，方便后面去重和使用双指针
    n = len(nums)
    res = []                        # 用列表保存最终答案

    for i in range(n - 3):         # 第一个数的下标
        # 跳过重复的第一个数
        if i > 0 and nums[i] == nums[i - 1]:
            continue

        # 剪枝：如果最小的四个数之和都大于 target，后面不可能再找到答案
        if nums[i] + nums[i + 1] + nums[i + 2] + nums[i + 3] > target:
            break
        # 剪枝：如果当前数加上最大的三个数仍然小于 target，说明需要更大的 i
        if nums[i] + nums[n - 3] + nums[n - 2] + nums[n - 1] < target:
            continue

        for j in range(i + 1, n - 2):   # 第二个数的下标
            # 跳过重复的第二个数
            if j > i + 1 and nums[j] == nums[j - 1]:
                continue

            # 同样的剪枝技巧
            if nums[i] + nums[j] + nums[j + 1] + nums[j + 2] > target:
                break
            if nums[i] + nums[j] + nums[n - 2] + nums[n - 1] < target:
                continue

            left, right = j + 1, n - 1   # 双指针初始化
            while left < right:
                cur_sum = nums[i] + nums[j] + nums[left] + nums[right]
                if cur_sum == target:
                    res.append([nums[i], nums[j], nums[left], nums[right]])

                    # 移动 left 并跳过相同的数，防止重复答案
                    left_val = nums[left]
                    while left < right and nums[left] == left_val:
                        left += 1

                    # 同理，移动 right 并跳过相同的数
                    right_val = nums[right]
                    while left < right and nums[right] == right_val:
                        right -= 1

                elif cur_sum < target:
                    left += 1          # 和太小，左指针右移让和增大
                else:
                    right -= 1         # 和太大，右指针左移让和减小

    return res
```

#### 复杂度

- **时间复杂度**：`O(n³)` —— 两层外层循环 `O(n²)` + 每次双指针线性遍历 `O(n)`。相对于暴力的 `O(n⁴)`，快了一个数量级。  
- **空间复杂度**：`O(1)`（不计输出列表）—— 只用了常数个额外变量。

## 心得

- **核心技巧**：先排序 + 双指针 + 跳过重复。  
- **适用的题型**：  
  1. `3Sum`（找三数之和）  
  2. `2Sum` 的升级版（需要在有序数组中寻找两数之和）  
  3. `4Sum II`（四个数组各取一个数，使其和为 0，使用哈希表计数）  
- **解题钥匙**：**“把高维搜索降维”**——固定一部分，剩余部分用双指针线性搜索。

---

## 反思

- **第一反应**：直接想用四层循环把所有组合枚举完。  
- **最容易踩的坑**：  
  - **去重**：忘记在排序后跳过相同的 `i`、`j`、`left`、`right`，会导致答案出现重复。  
  - **剪枝**：不做边界判断会导致不必要的循环，尤其在数组很大时会浪费时间。  
  - **整数溢出**：在 Python 中不需要担心，但在其他语言要注意 32 位整数范围。  
- **下次思路**：看到 “k Sum” 类题目，第一步就想到 **先排序 → 固定前 `k‑2` 个数 → 用双指针解决剩余两数**，这样可以直接把时间复杂度从 `O(n^k)` 降到 `O(n^{k‑1})`。
