# #191. 位 1 的个数 / Number of 1 Bits

> 难度：简单 · 标签：Divide and Conquer、Bit Manipulation · [LeetCode 链接](https://leetcode.com/problems/number-of-1-bits/)

## 题目（英文原版）

**Description**

Given a positive integer n, write a function that returns the number of set bits in its binary representation (also known as the Hamming weight).

**Examples**

**Example 1:**

```
Input: n = 11
Output: 3
Explanation:
The input binary string 1011 has a total of three set bits.
```

**Example 2:**

```
Input: n = 128
Output: 1
Explanation:
The input binary string 10000000 has a total of one set bit.
```

**Example 3:**

```
Input: n = 2147483645
Output: 30
Explanation:
The input binary string 1111111111111111111111111111101 has a total of thirty set bits.
```

**Constraints**

- 1 <= n <= 231 - 1

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把整数 `n` 的二进制写出来，然后把每个 `'1'` 都数一遍。  
在程序里，有两种常见的实现方式：

1. **转成字符串**  
   `bin(n)` 会把 `n` 转成形如 `'0b1011'` 的字符串，去掉前缀后直接用 `count('1')` 统计。  
   - **数据结构**：这里用到的「字符串」可以类比成一本书，`count` 就像在书里找所有出现的某个词。
2. **位运算逐位检查**  
   把 `n` 最低位和 `1` 做 **与运算**（`n & 1`），如果结果是 `1`，说明最低位是 `1`，计数器加一。随后把 `n` 右移一位（`n >>= 1`），重复上述过程，直到 `n` 变成 `0` 为止。  
   - **数据结构**：这里的「位」可以想象成灯泡的开关，`& 1` 就是检查最右边的灯泡是否亮着。

这两种做法都能得到正确答案，因为它们都完整地遍历了二进制的每一位。

#### 代码（Python）

```python
def hammingWeight_brute(n: int) -> int:
    """
    暴力解法：逐位检查 n 的二进制表示中有多少个 1
    """
    count = 0                     # 记录出现的 1 的个数
    while n:                      # 当 n 不为 0 时继续循环
        count += n & 1            # n & 1 为 1 表示最低位是 1，计数器加一
        n >>= 1                   # 右移一位，准备检查下一位
    return count
```

> **关键行解释**  
> - `n & 1`：把 `n` 的最低位和二进制 `1` 做与运算，只保留最低位的值。  
> - `n >>= 1`：把二进制整体右移一位，相当于把已经检查过的最低位「扔掉」。

#### 复杂度

- **时间复杂度**：`O(log n)`（或者说 `O(位数)`）  
  每次循环都右移一位，最多需要检查 `n` 的二进制位数。对 32 位整数来说最多 32 次，实际运行时间几乎是常数。
- **空间复杂度**：`O(1)`  
  只用了几个整数变量，和输入大小无关。

### 2. 最优解

#### 思路  

在暴力解中，我们不管最低位是 `0` 还是 `1`，都要「搬走」它，然后继续右移。这就像在扫地时把每一块砖都搬走，即使那块砖根本不脏。  
真正的瓶颈是**对每个 `0` 位都做一次右移**，而 `0` 位并不提供计数信息。

**优化的关键**是：一次操作同时**清除最低的 `1` 位**，并把计数器加一。这样每循环一次就一定会「收集」到一个 `1`，循环次数恰好等于 `1` 的个数。  

实现方法叫 **Brian Kernighan 算法**，核心操作是：

```
n = n & (n - 1)
```

解释一下：

- `n - 1`：把 `n` 的最低 `1` 变成 `0`，并把它右边的所有 `0` 变成 `1`（想象成把灯泡最左侧的亮灯关掉，同时把右边的灯全部点亮）。
- `n & (n - 1)`：把原来的最低 `1` 清零，其他位保持不变。

每执行一次上述操作，`n` 中的 `1` 就少一个，循环结束条件是 `n == 0`。

#### 代码（Python）

```python
def hammingWeight_optimal(n: int) -> int:
    """
    最优解：Brian Kernighan 算法
    每次循环都把 n 最低位的 1 清零，循环次数等于 1 的个数
    """
    count = 0                     # 统计 1 的个数
    while n:
        n &= n - 1                # 把最低位的 1 清零，等价于 n = n & (n - 1)
        count += 1                # 清除一次，就说明原来有一个 1
    return count
```

> **关键行解释**  
> - `n - 1`：把最低的 `1` 变成 `0`，右侧的所有 `0` 变成 `1`。  
> - `n &= n - 1`：把原来的最低 `1` 清零，其他位保持不变。  

#### 复杂度

- **时间复杂度**：`O(k)`，`k` 为二进制中 `1` 的个数。最坏情况（所有位都是 `1`）时 `k = log n`，仍然是 `O(log n)`，但在多数情况下会明显快于逐位检查。  
  - 对比暴力解：暴力解始终遍历所有位（`log n` 次），而最优解只遍历实际出现的 `1`，如果 `1` 很少，就省了很多无用的右移操作。
- **空间复杂度**：`O(1)`，同样只使用常数级别的额外变量。

## 心得

- **核心技巧**：使用位运算一次性清除最低的 `1`（Brian Kernighan 算法），把循环次数压到只和 `1` 的个数相关。  
- **适用的题型**：  
  1. 计数二进制中 `1` 的个数（本题）。  
  2. 判断两个整数的二进制不同位数（LeetCode 461: Hamming Distance）。  
  3. 判断整数是否是 2 的幂（`n & (n-1) == 0`）。  
- **一句话总结**：**“每次把最低的 1 抹掉，计数器就加一”**——这把“遍历全部位”变成了“遍历实际的 1”。

## 反思

- **第一反应**：直接把整数转成二进制字符串，用 `count('1')` 统计，或者逐位右移检查。  
- **最容易踩的坑**：  
  - 忘记处理 Python 整数的无限位长（对负数需要先取绝对值或使用掩码），本题只要求正整数所以不易出错。  
  - 在写 `n & (n - 1)` 时，误写成 `n & n - 1`（运算顺序错误），导致结果不对。  
- **下次遇到同类题**：第一步先思考“有没有办法一次性处理掉多余的 0”，即**看能不能把操作和实际出现的 `1` 关联**，随后尝试 Brian Kernighan 或类似的位运算技巧。
