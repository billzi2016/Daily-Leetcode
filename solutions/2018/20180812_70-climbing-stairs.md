# #70. 爬楼梯 / Climbing Stairs

> 难度：简单 · 标签：Math、Dynamic Programming、Memoization · [LeetCode 链接](https://leetcode.com/problems/climbing-stairs/)

---

## 题目（英文原版）

**Description**

You are climbing a staircase. It takes n steps to reach the top.
Each time you can either climb 1 or 2 steps. In how many distinct ways can you climb to the top?

**Examples**

**Example 1:**

```
Input: n = 2
Output: 2
Explanation: There are two ways to climb to the top.
1. 1 step + 1 step
2. 2 steps
```

**Example 2:**

```
Input: n = 3
Output: 3
Explanation: There are three ways to climb to the top.
1. 1 step + 1 step + 1 step
2. 1 step + 2 steps
3. 2 steps + 1 step
```

**Constraints**

- 1 <= n <= 45

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  
最直接的想法是把所有可能的爬楼梯方式都枚举出来，然后计数。  
- **数据结构**：我们可以用**递归树**来模拟每一步的选择。递归的每一层对应“这一步走了 1 步还是 2 步”。  
- **生活化类比**：想象你在走楼梯，每到一个台阶，你都有两张“选择卡”：`走1步` 或 `走2步`。把所有卡片排成一条长队，就是一种完整的爬楼梯方案。  
- **正确性**：只要递归的终止条件是“恰好到达第 n 步”，每一种合法的卡片排列都会被遍历一次，计数自然就是答案。  

#### 代码（Python）  

```python
def climbStairs_brute(n: int) -> int:
    """暴力递归，枚举所有可能的爬法"""
    def dfs(step: int) -> int:
        # step 表示已经爬到了第几步
        if step == n:          # 正好到达顶层，算一种合法方案
            return 1
        if step > n:           # 超过了顶层，非法，算 0 种
            return 0
        # 当前可以走 1 步，也可以走 2 步，分别递归求和
        return dfs(step + 1) + dfs(step + 2)

    return dfs(0)               # 从第 0 步开始爬
```

#### 复杂度  

- **时间复杂度**：`O(2^n)`  
  - “2 的 n 次方”可以理解为“每走一步都要分成两条路”，所以总的递归调用数会像二叉树一样指数级增长。  
- **空间复杂度**：`O(n)`  
  - 递归调用栈的深度最多是 `n`（一直走 1 步的情况），所以占用的额外内存和 `n` 成正比。

---

### 2. 最优解  

#### 思路  
从暴力解可以看到，**大量的子问题被重复计算**。比如 `dfs(2)` 在不同的路径里会出现很多次。我们只要把每个子问题的答案记下来，下次需要时直接取，用的就是**记忆化**（Memoization）或**动态规划**（DP）的思想。  

1. **找出递推关系**  
   - 为了到达第 `i` 步，最后一步只能是从 `i‑1` 步跨 1 步上来，或者从 `i‑2` 步跨 2 步上来。  
   - 因此 `ways[i] = ways[i‑1] + ways[i‑2]`。  
   - 这正好是**斐波那契数列**的递推式，只是起始值不同。  

2. **确定初始条件**  
   - `ways[0] = 1`：站在地面（第 0 步）不需要任何动作，也算一种“空方案”。  
   - `ways[1] = 1`：只有一种走法——走一步。  

3. **实现方式**  
   - **记忆化递归**：把已经算好的 `ways[i]` 存在字典里，避免重复递归。  
   - **自底向上 DP**：从小到大依次计算 `ways[i]`，只需要前两个数就可以得到后面的数，空间可以进一步压缩到 `O(1)`。  

下面分别给出两种实现，帮助你从“记忆化”到“空间最优”一步步理解。  

#### 代码（Python）  

```python
# 方法一：记忆化递归（自顶向下）
def climbStairs_memo(n: int) -> int:
    memo = {0: 1, 1: 1}                 # 直接把已知的 base case 放进字典

    def dfs(i: int) -> int:
        if i in memo:                  # 之前算过直接返回，省时
            return memo[i]
        # 递推关系：i 步的方案数 = (i-1) 步的方案数 + (i-2) 步的方案数
        memo[i] = dfs(i - 1) + dfs(i - 2)
        return memo[i]

    return dfs(n)


# 方法二：自底向上 DP，空间 O(1)
def climbStairs_dp(n: int) -> int:
    if n <= 1:
        return 1                       # n 为 0 或 1 时直接返回 1

    a, b = 1, 1                         # a = ways[i-2], b = ways[i-1]
    for _ in range(2, n + 1):
        a, b = b, a + b                 # 更新为下一步的值
    return b
```

#### 复杂度  

- **时间复杂度**：`O(n)`  
  - 只需要遍历一次从 `2` 到 `n` 的循环（或递归调用一次），线性增长。相较于暴力的指数级，快得多。  
- **空间复杂度**：  
  - 记忆化递归：`O(n)`（存储所有子问题的答案）。  
  - 自底向上 DP：`O(1)`（只保留最近的两个数），这是最节省空间的写法。

## 心得  

- **核心技巧**：把“走到第 n 步”拆解成“走到第 n‑1 步再走 1 步”或“走到第 n‑2 步再走 2 步”，形成 **递推公式**，进而使用 **动态规划**（或记忆化递归）求解。  
- **适用的题型**：  
  1. “不同路径”类问题（比如网格路径数）  
  2. “分割整数”或 “硬币兑换”这类可以把大问题拆成若干子问题的计数题  
  3. 任何出现 **斐波那契** 结构的计数题（如爬楼梯的变种、打家劫舍等）  
- **一句话总结解题钥匙**：**把复杂过程拆成只依赖最近状态的递推式，利用已算好的子结果避免重复计算。**

## 反思  

- **第一反应**：看到“每次可以走 1 步或 2 步”，自然会想到枚举所有可能的步数组合。  
- **最容易踩的坑**：  
  - 忘记把 `n = 0` 或 `n = 1` 的边界情况单独处理，会导致递归无限或返回错误。  
  - 在记忆化实现里，如果不先把 base case 放进缓存，递归会出现 `KeyError`。  
- **下次类似题的第一步**：先写出**状态转移方程**（即递推关系），确认只需要前几步的信息，就可以决定是用记忆化递归还是自底向上 DP。
