## 题目（英文原版）

**Description**

Given a reference of a node in a connected undirected graph.
Return a deep copy (clone) of the graph.
Each node in the graph contains a value (int) and a list (List[Node]) of its neighbors.
Test case format:
For simplicity, each node's value is the same as the node's index (1-indexed). For example, the first node with val == 1, the second node with val == 2, and so on. The graph is represented in the test case using an adjacency list.
An adjacency list is a collection of unordered lists used to represent a finite graph. Each list describes the set of neighbors of a node in the graph.
The given node will always be the first node with val = 1. You must return the copy of the given node as a reference to the cloned graph.

**Examples**

**Example 1:**

```
class Node {
    public int val;
    public List<Node> neighbors;
}
```

**Example 2:**

```
Input: adjList = [[2,4],[1,3],[2,4],[1,3]]
Output: [[2,4],[1,3],[2,4],[1,3]]
Explanation: There are 4 nodes in the graph.
1st node (val = 1)'s neighbors are 2nd node (val = 2) and 4th node (val = 4).
2nd node (val = 2)'s neighbors are 1st node (val = 1) and 3rd node (val = 3).
3rd node (val = 3)'s neighbors are 2nd node (val = 2) and 4th node (val = 4).
4th node (val = 4)'s neighbors are 1st node (val = 1) and 3rd node (val = 3).
```

**Example 3:**

```
Input: adjList = [[]]
Output: [[]]
Explanation: Note that the input contains one empty list. The graph consists of only one node with val = 1 and it does not have any neighbors.
```

**Example 4:**

```
Input: adjList = []
Output: []
Explanation: This an empty graph, it does not have any nodes.
```

**Constraints**

- The number of nodes in the graph is in the range [0, 100].
- 1 <= Node.val <= 100
- Node.val is unique for each node.
- There are no repeated edges and no self-loops in the graph.
- The Graph is connected and all nodes can be visited starting from the given node.

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直观的想法是：**从给定的起点节点出发，遍历它的所有邻居，对每个邻居再递归地复制它的邻居……**  
这看起来就像“把整棵树从根往下抄一遍”。如果把图想象成城市的道路网络，暴力做法相当于每次走到一个城市，就把这座城市的所有道路再重新画一遍，而不管之前是否已经画过这座城市。

- **使用的数据结构**  
  - `Node` 本身保存 `val`（相当于城市的编号）和 `neighbors`（相邻城市的列表）。  
  - 递归调用的栈（系统自动维护）帮助我们一次走到一个邻居，再回到上一个城市继续走别的邻居。

- **为什么它能得到正确答案**  
  只要遍历到了图中每一个节点，就会为它创建一个新 `Node`，并把对应的邻居列表也全部复制。理论上遍历完整个连通图后，所有节点都被克隆了一遍。

- **为什么它会慢（或会死循环）**  
  图里可能出现环（比如 1‑2‑3‑1），递归会不停地在环中来回走，导致**同一个节点被复制无限次**，程序会栈溢出或时间爆炸。  
  用大白话说，假设图里有 100 条路，暴力解会把每条路走 **指数次**（每次进来都重新走一遍），所以时间会变成 `O(2^n)` 之类的巨量。

#### 代码（Python）

```python
# 这里给出“暴力”版本，仅用于说明为什么不推荐使用。
# 代码会在有环的图上无限递归（实际 LeetCode 会因为递归深度限制报错），
# 请把它当作思考过程，而不是最终提交的答案。

class Node:
    def __init__(self, val: int = 0, neighbors=None):
        self.val = val
        self.neighbors = neighbors if neighbors is not None else []


def cloneGraph_bruteforce(node: 'Node') -> 'Node':
    if not node:
        return None

    # 为当前节点创建一个新节点
    new_node = Node(node.val)

    # 递归复制每一个邻居
    for nb in node.neighbors:
        # 这里没有任何“记住已经复制过的节点”的机制
        # 所以如果 nb 再次出现（环），会再次进入递归，导致无限循环
        new_node.neighbors.append(cloneGraph_bruteforce(nb))

    return new_node
```

#### 复杂度

- **时间复杂度**：`O(2^n)`（指数级）——每走到一个节点都要重新遍历它的所有邻居，环会让遍历次数呈指数增长。  
- **空间复杂度**：`O(n)`——递归栈的深度最坏情况下会等于图中节点数 `n`，但因为会无限递归，实际运行时会因为栈溢出而提前结束。

### 2. 最优解

#### 思路  

从暴力解可以看到 **“重复访问同一个节点会导致爆炸”**。  
因此我们需要**记住已经克隆过的节点**，遇到已经克隆的节点时直接复用，而不是再新建一次。

这正好可以用 **哈希表（字典）** 来实现：  

- **键（key）**：原图中的节点对象（相当于“查字典”时的词）  
- **值（value）**：对应的克隆节点（相当于字典里查到的页码）  

思考过程如下：

1. **遍历图**（可以用深度优先搜索 DFS 或广度优先搜索 BFS）。  
   - 这里用 **DFS**（递归版）来演示，BFS（队列版）思路完全相同，只是实现方式不同。  
2. **每访问到一个节点**，先检查哈希表里有没有它的克隆：
   - **没有** → 创建一个新节点（只复制 `val`，先把邻居列表留空），把原节点 → 新节点的映射存进哈希表。  
   - **有** → 直接返回哈希表里的克隆节点，避免重复创建。  
3. **递归处理邻居**：遍历当前节点的 `neighbors`，对每个邻居递归调用克隆函数，并把返回的克隆邻居加入当前克隆节点的 `neighbors` 列表。  
4. 当所有节点都走完，哈希表里已经完整保存了“原节点 ↔ 克隆节点”的一一对应关系，返回起始节点的克隆即可。

> **类比**：想象你在画一张城市地图，已经画好的城市会在地图的“目录”（哈希表）里登记。以后再碰到这座城市，就直接在目录里找，不需要重新画。

#### 代码（Python）

```python
# -*- coding: utf-8 -*-
# LeetCode 官方的 Node 定义（这里为了完整性自行写一遍）
class Node:
    def __init__(self, val: int = 0, neighbors=None):
        self.val = val
        self.neighbors = neighbors if neighbors is not None else []


def cloneGraph(node: 'Node') -> 'Node':
    """
    使用 DFS + 哈希表（字典）实现图的深拷贝
    """
    if not node:               # 空图直接返回 None
        return None

    # visited: 原节点 -> 克隆节点
    visited = {}

    def dfs(cur: 'Node') -> 'Node':
        """返回 cur 的克隆节点"""
        if cur in visited:                     # 已经克隆过，直接返回
            return visited[cur]

        # 1. 先克隆当前节点（只复制 val，neighbors 暂时空）
        copy = Node(cur.val)
        visited[cur] = copy                    # 记下来，防止后续再次创建

        # 2. 递归克隆所有邻居，并加入到 copy.neighbors 中
        for nb in cur.neighbors:
            copy.neighbors.append(dfs(nb))     # 递归返回的已经是克隆好的邻居

        return copy

    # 从给定的起点 node 开始 DFS
    return dfs(node)
```

> **代码要点解释**  
> - `visited` 是哈希表，**键** 是原节点对象（因为每个 `Node` 在 Python 中是唯一的），**值** 是对应的克隆节点。  
> - `if cur in visited` 这一步相当于“查字典”，如果已经出现过，就直接复用，避免重复克隆。  
> - 克隆节点的 `neighbors` 列表在创建时是空的，等所有邻居都克隆好后再逐一填充，这样就不会出现循环引用导致的错误。

#### 复杂度

- **时间复杂度**：`O(N + E)`  
  - 每个节点只会被克隆一次（`N` 为节点数），每条边（邻接关系）也只会被遍历一次（`E` 为边数）。  
  - 用大白话说，就是“图里有多少城镇就花多少时间”，线性增长，不会爆炸。

- **空间复杂度**：`O(N)`  
  - 哈希表保存了每个原节点对应的克隆节点，需要 `N` 个条目。  
  - 递归栈最深也不会超过节点数 `N`（因为图是连通的），所以额外的栈空间也是 `O(N)`。

## 心得

- **核心技巧**：**使用哈希表记录已经克隆的节点**，配合 **DFS/BFS** 完成图的遍历。  
- **适用的题型**  
  1. 任意需要深拷贝（克隆）**有环结构**的题目，如 “复制带随机指针的链表”。  
  2. 需要 **遍历图并对每个节点做一次性处理** 的题目，例如 “判断图是否为二分图”。  
  3. **拓扑排序 / 最短路径** 等需要一次遍历并记录状态的图论问题。

- **一句话总结**：**“遍历 + 记忆（哈希表）”是克隆任意图的钥匙**。

## 反思

- **第一反应**：看到“克隆图”，立刻想到“递归复制每个节点”。这就是暴力思路，但忽视了环导致的重复复制。  
- **最容易踩的坑**  
  - **忘记哈希表**：导致无限递归或重复节点。  
  - **空图/单节点图**：需要单独判断 `node is None` 或 `neighbors` 为空的情况。  
  - **Python 中对象做键**：只能用对象本身（或 `id(node)`）做哈希表键，不能用 `node.val`（因为不同节点可能值相同）。  
- **下次类似题的第一步**：**先在脑中画出图的结构，确认是否存在环；如果有环，就立即准备一个“已访问/已复制”哈希表**，再决定使用 DFS 还是 BFS。这样可以一步到位避免递归爆栈。
