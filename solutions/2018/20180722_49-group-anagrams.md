## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把每个字符串和其它所有字符串两两比较，看看它们是不是“字母相同、顺序可以任意”。  
这就像在课堂上让同学两两比对作业，找出完全相同内容的那几份。

- **数据结构**：我们只需要一个二维列表 `result` 来存放分好的组。  
- **字母相同的判断**：把两个字符串的字符都排好序（比如 `"eat"` → `"aet"`），如果排好序后得到的结果相同，就说明它们是字母重排（anagram）。  
- **为什么正确**：排序会把相同的字符集合变成相同的序列，只要两个字符串的排序结果相同，它们一定是彼此的字母重排，反之亦然。

**步骤**  
1. 依次取出数组中的每个字符串 `s`。  
2. 把 `s` 按字母排序得到 `sorted_s`。  
3. 再遍历 `result` 中已经形成的每一组，检查组里第一个字符串排序后是否等于 `sorted_s`。  
   - 若相等，就把 `s` 加进这组；  
   - 若所有组都不匹配，则新建一个只含 `s` 的组加入 `result`。  

#### 代码（Python）

```python
from typing import List

def groupAnagrams_bruteforce(strs: List[str]) -> List[List[str]]:
    # 用来保存所有的字母异位词组
    groups: List[List[str]] = []

    for s in strs:                       # 逐个取出原数组里的字符串
        sorted_s = ''.join(sorted(s))   # 把当前字符串排好序，得到唯一的“指纹”

        placed = False                  # 标记是否已经放进了某个已有组
        for g in groups:                # 遍历已经形成的每一组
            # 只要组里任意一个字符串的排序结果相同，就说明同属一组
            if ''.join(sorted(g[0])) == sorted_s:
                g.append(s)             # 加进这组
                placed = True
                break

        if not placed:                  # 没有匹配的组 → 开辟新组
            groups.append([s])

    return groups
```

#### 复杂度

- **时间复杂度**：`O(n²·k log k)`  
  - `n` 是字符串个数，`k` 是单个字符串的平均长度。  
  - 外层遍历 `n` 次，内层最坏需要遍历已经出现的全部组，最多也是 `n` 次。  
  - 每次比较需要把字符串排序，排序的代价是 `O(k log k)`。  
  - 用大白话说，就是“每个字符串都要和几乎所有其它字符串比较一次”，所以会慢。

- **空间复杂度**：`O(n·k)`  
  - 需要保存所有输入字符串（总共 `n` 个，每个长度约 `k`），以及分组结果的额外指针。  
  - 没有额外的“大表”或“哈希”，只用了普通列表。

### 2. 最优解

#### 思路  

从暴力解可以看到 **瓶颈** 在于「每次都要遍历已有的所有组」以及「每次比较都要排序」。  
我们可以把「排序后的字符串」直接当作键（key）放进**哈希表**（Python 的 `dict`），这样：

- **键**：同一组所有字符串排序后得到的相同结果。  
- **值**：一个列表，保存所有拥有该键的原始字符串。

哈希表的查找/插入时间是 `O(1)`（常数时间），所以只需要一次遍历就能把所有字符串归类。

> **哈希表类比**：想象你在图书馆查单词的页码，字典（hash table）里已经预先把「单词 → 页码」存好，直接看就能找到，省去一遍遍比对的麻烦。

**两种实现方式**  
1. **排序后作为键**（最直观）：把每个字符串排序后得到的字符串作为键。  
2. **字符计数元组作为键**：因为字符串只包含小写字母 `'a'~'z'`，我们可以统计每个字母出现的次数，形成长度为 26 的元组 `(cnt_a, cnt_b, …, cnt_z)`，该元组唯一标识一个字母集合。这样省去了 `O(k log k)` 的排序，只需要 `O(k)` 的线性计数。

下面给出第二种实现（更快），并一步步解释每一步。

#### 代码（Python）

```python
from typing import List, Dict, Tuple
from collections import defaultdict

def groupAnagrams(strs: List[str]) -> List[List[str]]:
    """
    使用哈希表 + 字符计数（长度为 26 的元组）把同一组的字符串归类。
    """
    # defaultdict 自动把不存在的键对应的值初始化为空列表
    anagram_map: Dict[Tuple[int, ...], List[str]] = defaultdict(list)

    for s in strs:                     # 只遍历一次原数组
        # 统计 26 个字母的出现次数，cnt[0] 对应 'a', cnt[25] 对应 'z'
        cnt = [0] * 26
        for ch in s:                   # 线性遍历当前字符串的每个字符
            cnt[ord(ch) - ord('a')] += 1   # ord('a') = 97，利用 ASCII 码计算下标

        # 把列表转换成不可变的元组，才能作为 dict 的键
        key = tuple(cnt)

        # 把原字符串放进对应键的列表中
        anagram_map[key].append(s)

    # dict 的所有值（即分好的组）组成最终答案
    return list(anagram_map.values())
```

**代码要点解释**  

| 行号 | 关键代码 | 中文解释 |
|------|----------|----------|
| 4-5 | `defaultdict(list)` | 自动创建空列表，省去“键不存在时先建列表”的判断。 |
| 8 | `cnt = [0] * 26` | 用长度为 26 的数组记录每个字母出现次数。 |
| 10-11 | `cnt[ord(ch) - ord('a')] += 1` | `ord` 把字符转成 ASCII 码，减去 `'a'` 的码得到 0~25 的下标。 |
| 14 | `key = tuple(cnt)` | 把可变的列表变成不可变的元组，才能用作哈希表的键。 |
| 16 | `anagram_map[key].append(s)` | 把原字符串加入对应的分组。 |
| 20 | `list(anagram_map.values())` | 取出所有分组，转成普通列表返回。 |

#### 复杂度

- **时间复杂度**：`O(n·k)`  
  - `n` 为字符串数量，`k` 为每个字符串的长度（最坏情况下取最大长度 100）。  
  - 对每个字符串只遍历一次字符做计数 (`O(k)`)，哈希表的插入/查找是 `O(1)`。  
  - 与暴力解相比，把 `O(k log k)` 的排序时间降到了 `O(k)`，并且只遍历一次数组，显著更快。

- **空间复杂度**：`O(n·k)`  
  - 哈希表需要存储所有字符串本身（总共 `n·k` 个字符），以及每个不同字母集合对应的计数元组（每个键占用固定的 26 整数），总体仍是线性空间。  
  - 与输入规模同阶，属于合理的额外空间。

## 心得

- **核心技巧**：利用 **哈希表** 把“相同特征”映射到同一个键上；特征这里用 **字符计数元组**（或排序后字符串）唯一标识字母异位词。  
- **适用题型**：  
  1. **分组类**：如 “把相同字符组成的字符串分组”“把相同数字集合的数组分组”。  
  2. **同构/同类判断**：如 “判断两个字符串是否为同构（Isomorphic Strings）”。  
  3. **计数类**：如 “找出出现次数相同的子串（Find All Anagrams in a String）”。  
- **一句话总结**：**把“相同的本质特征”抽象成哈希键，一遍遍历即可完成分组**。

## 反思

- **第一反应**：直接想到两两比较并排序，虽然能得到正确答案，但会很慢。  
- **最容易踩的坑**：  
  - **键的选取**：如果直接把列表 `cnt` 当键，会报错，因为列表是可变的、不可哈希，需要转换成元组。  
  - **空字符串**：计数全部为 0，仍能正常归为同一组，只要键一致即可。  
  - **字符范围**：题目限定小写字母，才可以用固定长度的 26 位计数；若出现其它字符，需要相应扩展。  
- **下次思路**：看到“把相同属性的元素放在一起”时，立刻想到 **哈希表 + 特征键**，先分析能否用 **计数/排序** 等方式构造唯一键，再决定实现细节。
