## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**把所有工资一个个比较**，找出第 n 高的那一个。可以把“工资”想象成一堆纸条，上面写着数字，我们要把它们排成从大到小的顺序，然后数第 n 张。如果直接用两层循环去比较每张纸条和其它所有纸条的大小，就能得到每个工资在整个集合中的排名。  

- **使用的数据结构**：  
  - `list`（列表）保存所有工资，就像装纸条的盒子。  
  - `set`（集合）可以去掉重复的工资，因为题目要求“不同的工资”。集合就像一本词典，里面每个词（工资）只出现一次。  

- **为什么正确**：  
  对每个工资，我们都遍历所有其他工资，统计有多少工资比它大。若恰好有 `n‑1` 个工资比它大，那么它就是第 n 高的工资。  

- **时间/空间复杂度**：  
  - **时间**：外层遍历 `m`（工资总数）次，内层又遍历 `m` 次，整体是 `m × m = m²`，记作 **O(m²)**。  
    大白话：如果有 1000 条工资记录，程序要比较 1000 × 1000 = 1 000 000 次。  
  - **空间**：只用了额外的集合和几个临时变量，和输入规模是同一个量级，记作 **O(m)**（存放去重后的工资）。  

#### 代码（Python）

```python
from typing import List, Optional

def nth_highest_salary_brute(salaries: List[int], n: int) -> Optional[int]:
    """
    暴力解法：两层循环统计每个工资前面有多少个更大的不同工资。
    返回第 n 高的工资，若不存在则返回 None。
    """
    # 1. 去重，得到所有不同的工资
    distinct = list(set(salaries))               # 去重后变成列表，方便遍历
    m = len(distinct)

    # 2. 对每个工资，统计比它大的工资有多少个
    for i in range(m):
        cnt = 0                                   # 计数器，记录比 distinct[i] 大的工资数量
        for j in range(m):
            if distinct[j] > distinct[i]:
                cnt += 1
        # 如果正好有 n-1 个更大的工资，说明它是第 n 高
        if cnt == n - 1:
            return distinct[i]

    # 循环结束仍未找到，说明不同工资不足 n 个
    return None
```

#### 复杂度

- **时间复杂度**：**O(m²)** — 两层循环每次都要遍历所有不同工资。  
- **空间复杂度**：**O(m)** — 需要一个集合/列表来保存去重后的工资。

### 2. 最优解

#### 思路  

从暴力解可以看到，**瓶颈在于每次都要遍历全部工资来计数**。我们其实只需要**找出第 n 大的那个数**，不必把每个数都和其它数比较。常见的两种更快办法：

1. **排序**：把所有不同工资从大到小排好序，直接取第 n‑1 个。排序的时间是 `O(m log m)`，已经比 `O(m²)` 好很多。  
2. **最小堆（大小为 n）**：维护一个只装最多 n 条工资的最小堆。遍历工资时，如果堆的大小还不到 n，就直接放进去；否则只在当前工资大于堆顶（第 n 小）时才替换堆顶。遍历结束后，堆顶就是第 n 大的工资。时间是 `O(m log n)`，当 `n` 远小于 `m` 时优势明显。  

这里我们重点讲 **最小堆**，因为它展示了 **“只保留必要信息”** 的思想，适用于大数据场景。

- **核心数据结构**：  
  - **最小堆**（`heapq`）可以看成一个装盒子的小盒子，盒子里总是保留最小的那件物品在最上面。我们让它只装 `n` 件工资，盒子里最小的那件（堆顶）正好是第 n 大的工资。  

- **步骤**：  
  1. 用集合去重，得到不同工资。  
  2. 遍历这些工资：  
     - 若堆的大小 < n → 直接 `heappush`（放进去）。  
     - 否则比较当前工资与堆顶：如果更大，就 `heappushpop`（弹出最小的，放入更大的）。  
  3. 循环结束后检查堆的大小：若恰好等于 n，堆顶即为答案；否则说明不同工资不足 n，返回 `None`。  

- **为什么正确**：  
  堆始终只保存最大的 n 条工资。每次我们把比堆里最小的（即第 n 大）更大的工资放进去，保证堆里的所有元素都是全局最大的 n 条。最终堆顶就是这 n 条里最小的，也就是第 n 大。  

- **时间/空间复杂度**：  
  - **时间**：遍历 `m` 条工资，每次堆操作是 `O(log n)`，所以总共 `O(m log n)`。  
    大白话：如果有 1 000 000 条工资，而我们只想找第 3 高的，只需要大约 `log₂3 ≈ 1.6` 的比较次数乘以 1 000 000，远比全表排序快。  
  - **空间**：堆里最多存 `n` 条工资，外加去重集合 `O(m)`（如果不计去重可以视为 `O(m)`），但核心额外空间是 **O(n)**。  

#### 代码（Python）

```python
import heapq
from typing import List, Optional

def nth_highest_salary_heap(salaries: List[int], n: int) -> Optional[int]:
    """
    最小堆优化版：只保留最大的 n 条不同工资。
    若不同工资少于 n，返回 None。
    """
    # 1. 去重，得到所有不同工资
    distinct = set(salaries)                     # set 像字典，只保留唯一的词条

    # 2. 用最小堆维护最大的 n 条工资
    min_heap: List[int] = []                     # 空堆，堆顶是当前第 n 大工资

    for sal in distinct:
        if len(min_heap) < n:
            heapq.heappush(min_heap, sal)        # 堆未满，直接放进去
        else:
            # 堆已满，只有当当前工资更大时才进入堆
            if sal > min_heap[0]:                # min_heap[0] 是堆顶（第 n 大中的最小）
                heapq.heappushpop(min_heap, sal)  # 弹出堆顶，放入更大的工资

    # 3. 判断是否满足 n 条不同工资
    if len(min_heap) == n:
        return min_heap[0]                        # 堆顶就是第 n 高的工资
    return None                                   # 不足 n 条，返回 None
```

#### 复杂度

- **时间复杂度**：**O(m log n)** — 每条工资只做一次堆操作，堆的高度是 `log n`。  
- **空间复杂度**：**O(n)** — 堆最多保存 `n` 条工资（去重集合视为输入本身的存储，不算额外空间）。

## 心得

- **核心技巧**：**利用堆（或快速选择）只保留“必须的”元素**，避免全表比较或排序。  
- **适用的题型**：  
  1. “第 k 大/小元素”系列（如 LeetCode 215、238）  
  2. “Top K” 类问题（如找出出现频率最高的 K 个单词）  
  3. “滑动窗口最大值”这类需要维护窗口内最大/最小的场景  
- **一句话总结解题钥匙**：**“只保留最有价值的 n 条”，用堆让这件事在对数时间内完成。**

## 反思

- **第一反应**：看到“第 n 高的工资”，自然想到把所有工资排个序后直接取第 n 个。  
- **最容易踩的坑**：  
  - **重复工资**：直接排序会把相同工资算多次，导致结果偏大，需要先去重。  
  - **n 超出范围**：如果不同工资少于 n，必须返回 `null`（Python 中用 `None` 表示），否则会出现索引错误。  
- **下次第一步**：先判断“是否需要完整排序”。如果只要第 n 大且 `n` 相对较小，立刻想到 **堆** 或 **快速选择**，先用这些 O(m log n) / O(m) 的算法再决定是否需要排序。
