# #139. 单词拆分 / Word Break

> 难度：中等 · 标签：Array、Hash Table、String、Dynamic Programming、Trie、Memoization · [LeetCode 链接](https://leetcode.com/problems/word-break/)

---

## 题目（英文原版）

**Description**

Given a string s and a dictionary of strings wordDict, return true if s can be segmented into a space-separated sequence of one or more dictionary words.
Note that the same word in the dictionary may be reused multiple times in the segmentation.

**Examples**

**Example 1:**

```
Input: s = "leetcode", wordDict = ["leet","code"]
Output: true
Explanation: Return true because "leetcode" can be segmented as "leet code".
```

**Example 2:**

```
Input: s = "applepenapple", wordDict = ["apple","pen"]
Output: true
Explanation: Return true because "applepenapple" can be segmented as "apple pen apple".
Note that you are allowed to reuse a dictionary word.
```

**Example 3:**

```
Input: s = "catsandog", wordDict = ["cats","dog","sand","and","cat"]
Output: false
```

**Constraints**

- 1 <= s.length <= 300
- 1 <= wordDict.length <= 1000
- 1 <= wordDict[i].length <= 20
- s and wordDict[i] consist of only lowercase English letters.
- All the strings of wordDict are unique.

**示例 3**  
**输入**: `s = "catsandog"`, `wordDict = ["cats","dog","sand","and","cat"]`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：从字符串的第一个字符开始，尝试把前面的子串切成字典里出现的单词。  
如果切出来的第一个单词在 `wordDict` 中，就递归地把剩下的部分再继续切，直到把整条字符串全部切完。

- **使用的数据结构**  
  - `set`（哈希表）把 `wordDict` 装进去。哈希表就像一本“查字典”，把单词当成“词条”，可以在 **O(1)** 的时间内判断一个子串是否是词典里的单词。  
  - 递归调用栈：每一次切割都相当于在“记事本”上写下当前已经成功切好的部分，然后继续往后找。

- **为什么正确**  
  只要存在一种切分方式让全部字符都能对应到字典里的单词，递归就会在某条路径上把每段子串都匹配成功，从而返回 `True`。如果所有可能的切分都尝试完仍然找不到匹配，则返回 `False`。

- **复杂度分析（大白话）**  
  对每一个位置，我们都可以选择“切”或者“不切”，相当于二叉树的每层都有两种选择，深度最多是字符串长度 `n`，所以最坏情况下会遍历 `2^n` 条路径，时间复杂度是 **指数级**，记作 `O(2^n)`。  
  递归调用栈最多保存 `n` 层信息，空间复杂度是 `O(n)`（不算哈希表本身的空间）。

#### 代码（Python）

```python
from typing import List

def wordBreak_brute(s: str, wordDict: List[str]) -> bool:
    # 把 wordDict 放进哈希表，查单词像查字典一样快
    word_set = set(wordDict)

    # 记忆化剪枝：已经算过的起始位置不必重复计算
    memo = {}

    def dfs(start: int) -> bool:
        """
        判断 s[start:] 能否被拆分
        """
        if start == len(s):          # 已经到字符串末尾，说明前面全部匹配成功
            return True
        if start in memo:            # 之前算过这个位置的结果，直接返回
            return memo[start]

        # 从 start 开始尝试每一种可能的切割长度
        for end in range(start + 1, len(s) + 1):
            prefix = s[start:end]    # 当前子串 s[start:end]
            if prefix in word_set:   # 如果子串是字典里的单词
                if dfs(end):         # 递归检查剩余部分
                    memo[start] = True
                    return True

        memo[start] = False          # 所有切法都不行，记录下来防止重复搜索
        return False

    return dfs(0)
```

#### 复杂度

- **时间复杂度**：`O(2^n)`（指数级）——因为每个字符位置都有“切”或“不切”两种选择，最坏情况会遍历所有可能的切分方式。  
  记忆化 (`memo`) 能在一定程度上把重复子问题合并，但最坏仍然是指数级。

- **空间复杂度**：`O(n)`——递归栈的最大深度等于字符串长度 `n`（加上哈希表和记忆化表的 `O(n)` 空间）。

### 2. 最优解

#### 思路  

从暴力解可以看到，**重复子问题** 是主要的性能瓶颈。  
例如在 `"applepenapple"` 中，前面的 `"apple"` 被检查了多次。我们可以把“已经算过的子问题的答案”保存下来，后面再遇到同样的子问题时直接使用，这就是 **记忆化**（Memoization）或 **动态规划**（Dynamic Programming）的核心思想。

这里使用 **自底向上的 DP**：

1. 定义 `dp[i]` 为 `True`，表示子串 `s[:i]`（左闭右开区间）可以被字典拆分。  
2. 初始状态 `dp[0] = True`，因为空串总是可以“拆分”为零个单词。  
3. 对每个位置 `i`（从 1 到 `len(s)`），我们枚举所有可能的切割点 `j`（0 ≤ j < i），检查：
   - `dp[j]` 为 `True`（表示 `s[:j]` 已经可以拆分），并且
   - `s[j:i]` 在字典里（用哈希表 O(1) 判断）。
   - 若两者都满足，则 `dp[i] = True`，并可以提前结束本次 `i` 的循环，因为已经找到一种合法拆分。

整个过程只需要遍历 `n`（字符串长度）×`n` 次（每次最多检查所有前缀），时间是 `O(n^2)`，空间是 `O(n)`（存 `dp` 表）。

> **类比**：想象你在走一条长长的走廊，`dp[i]` 表示“到达第 `i` 米处是否已经有了通往入口的合法路线”。每次你站在第 `i` 米，往回看看之前的每一个位置 `j`，如果从入口到 `j` 有合法路线且 `j` 到 `i` 这段正好是一块字典里的地砖，那么你也可以到达 `i`。

#### 代码（Python）

```python
from typing import List

def wordBreak_dp(s: str, wordDict: List[str]) -> bool:
    word_set = set(wordDict)          # 哈希表：查单词像查字典，一次 O(1)

    n = len(s)
    dp = [False] * (n + 1)            # dp[i] 表示 s[:i] 能否拆分
    dp[0] = True                      # 空串可以拆分

    # i 表示当前要判断的前缀长度（右端点）
    for i in range(1, n + 1):
        # 枚举所有可能的切割点 j，子串 s[j:i] 为候选单词
        for j in range(i):
            # 只有当 s[:j] 已经可以拆分，且 s[j:i] 在字典里，才成立
            if dp[j] and s[j:i] in word_set:
                dp[i] = True
                break                # 找到一个合法切法即可停止内层循环

    return dp[n]                     # 整个字符串能否拆分
```

#### 复杂度

- **时间复杂度**：`O(n^2)` —— 外层循环 `n` 次，内层最坏也会遍历 `n` 次。相较于暴力的指数级，`n` 只到 300，完全可接受。  
- **空间复杂度**：`O(n)` —— 只用了长度为 `n+1` 的 `dp` 数组（再加上哈希表的 `O(m)`，其中 `m` 是字典单词数，通常远小于 `n^2`）。

## 心得

- **核心技巧**：利用 **动态规划** 把“是否可以拆分”这类**子问题**保存下来，避免重复计算。  
- **适用的题型**：  
  1. **分割类**：`Palindrome Partitioning`（回文分割），`Decode Ways`（解码方式）。  
  2. **背包类**：`Combination Sum`（组合总和），`Subset Sum`（子集和）。  
  3. **路径类**：`Unique Paths`（不同路径），`Jump Game`（跳跃游戏）等需要判断可达性的场景。  
- **一句话总结**：**把“能否到达”记下来，后面再遇到同样的起点直接复用**，就是解这类“能否拆分/能否到达”问题的钥匙。

## 反思

- **第一反应**：看到“把字符串拆成字典里的单词”，本能想到递归穷举所有切法。  
- **最容易踩的坑**  
  - **重复子问题**导致超时：没有记忆化会出现指数级递归。  
  - **边界条件**：`dp[0]` 必须设为 `True`，否则任何非空前缀都无法被识别。  
  - **字典查找**如果用列表会是 `O(m)`，会让整体复杂度更高，务必使用 `set`（哈希表）。  
- **下次第一步**：先判断“子问题是否可以复用”。如果可以，用 **记忆化/动态规划** 把子问题的答案缓存；如果不行，再考虑回溯或搜索。
