## 题目（英文原版）

**Description**

You are given an n x n 2D matrix representing an image, rotate the image by 90 degrees (clockwise).
You have to rotate the image in-place, which means you have to modify the input 2D matrix directly. DO NOT allocate another 2D matrix and do the rotation.

**Examples**

**Example 1:**

```
Input: matrix = [[1,2,3],[4,5,6],[7,8,9]]
Output: [[7,4,1],[8,5,2],[9,6,3]]
```

**Example 2:**

```
Input: matrix = [[5,1,9,11],[2,4,8,10],[13,3,6,7],[15,14,12,16]]
Output: [[15,13,2,5],[14,3,4,1],[12,6,8,9],[16,7,10,11]]
```

**Constraints**

- n == matrix.length == matrix[i].length
- 1 <= n <= 20
- -1000 <= matrix[i][j] <= 1000

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**把原矩阵的每个元素搬到新矩阵对应的位置**，再把新矩阵整体拷贝回原矩阵。  
- **数据结构**：我们仍然使用二维列表（list of list），可以把它想象成一张“表格”。  
- **类比**：把矩阵想象成一本书的页码表，原来的坐标是（行 i，列 j），旋转 90° 后，它会出现在（行 j，列 n‑1‑i）的位置。就像在字典里查找一个词的页码：**键**是原坐标，**值**是新坐标。  
- **正确性**：因为每个元素都有且只有一个唯一的目标位置，遍历所有位置并把值写入新矩阵后，得到的就是题目要求的旋转后图像。  

#### 代码（Python）

```python
def rotate_brute(matrix):
    """
    暴力版：使用额外的 n×n 矩阵存放旋转后的结果，然后拷贝回原矩阵。
    """
    n = len(matrix)                     # 矩阵的维度
    # 创建一个全 0 的新矩阵，大小和原矩阵一样
    new = [[0] * n for _ in range(n)]

    # 把每个元素搬到旋转后的位置
    for i in range(n):
        for j in range(n):
            # (i, j) -> (j, n-1-i) 是顺时针旋转 90° 的映射关系
            new[j][n - 1 - i] = matrix[i][j]

    # 把新矩阵的内容复制回原矩阵（就地修改）
    for i in range(n):
        for j in range(n):
            matrix[i][j] = new[i][j]
```

#### 复杂度

- **时间复杂度**：`O(n²)`  
  解释：矩阵有 `n × n` 个格子，我们遍历一次就把每个格子搬过去，再遍历一次把新矩阵复制回去，总共是常数倍的 `n²`，所以说“平方级”——如果矩阵边长是 10，操作大约是 100 次；边长是 100，操作是 10 000 次，随规模快速增长。
- **空间复杂度**：`O(n²)`  
  解释：我们新建了一个同样大小的矩阵来暂存结果，额外占用了和原矩阵一样多的空间。

### 2. 最优解

#### 思路  

暴力解的 **瓶颈** 在于用了额外的 `O(n²)` 空间。题目要求**原地**（in‑place）旋转，即只能在原矩阵内部完成。要做到这一点，需要把元素“就地”搬动，而不是先搬到别处。

有两种常见的原地旋转思路，这里介绍 **“先转置再翻转每行”** 的做法：

1. **转置（Transpose）**  
   把矩阵的行和列互换：`matrix[i][j] ↔ matrix[j][i]`（只在 `i < j` 时交换，防止重复）。可以把它想象成把一本书的“横向目录”和“纵向目录”互换位置——把行当成列，列当成行。

2. **每行翻转（Reverse each row）**  
   把每一行的元素顺序反转：`[a, b, c] → [c, b, a]`。这一步相当于把每页的文字从左到右倒过来阅读。

**为什么这样就等价于顺时针旋转 90°？**  
- 转置把 `(i, j)` 移到 `(j, i)`，相当于把矩阵沿主对角线（左上到右下）翻折。  
- 再把每行反转，就把列的顺序倒过来，使得原来的第一列变成最后一行，恰好是顺时针旋转的效果。

**核心数据结构**：仍然是二维列表，只是使用 **原地交换**（swap）来完成操作。交换可以类比为“把两个格子的数字互换位置”，不需要额外空间。

#### 代码（Python）

```python
def rotate(matrix):
    """
    原地旋转：先转置矩阵，再把每一行反转。
    只使用 O(1) 额外空间。
    """
    n = len(matrix)

    # 1. 转置（对角线交换）
    for i in range(n):
        for j in range(i + 1, n):          # 只遍历上三角，避免重复交换
            # 交换 matrix[i][j] 与 matrix[j][i]
            matrix[i][j], matrix[j][i] = matrix[j][i], matrix[i][j]

    # 2. 每行翻转
    for i in range(n):
        left, right = 0, n - 1
        while left < right:
            # 交换行内左右两个元素
            matrix[i][left], matrix[i][right] = matrix[i][right], matrix[i][left]
            left += 1
            right -= 1
```

> **运行示例**（可直接粘贴到 Python 环境）  
> ```python
> mat = [[1,2,3],[4,5,6],[7,8,9]]
> rotate(mat)
> print(mat)   # [[7,4,1],[8,5,2],[9,6,3]]
> ```

#### 复杂度

- **时间复杂度**：`O(n²)`  
  解释：转置遍历上三角的元素，大约是 `n²/2` 次；每行翻转遍历每行的 `n/2` 次，总体仍是常数倍的 `n²`，所以时间和暴力解一样，但没有额外的复制操作，常数更小。

- **空间复杂度**：`O(1)`  
  解释：只使用了若干个整数变量（`i, j, left, right`）进行交换，**不依赖于矩阵规模**，因此是常数级空间。

## 心得

- **核心技巧**：**矩阵转置 + 行翻转**（或列翻转）是把“顺时针 90° 旋转”拆解成两个易于原地实现的步骤。  
- **适用题型**：  
  1. 任意尺寸的矩阵旋转（90°、180°、270°）  
  2. 反转图像（水平翻转、垂直翻转）  
  3. “对称矩阵”相关的题目，如判断是否为回文矩阵等。  
- **一句话总结**：**把“旋转”拆成“转置 + 翻转”，就能在原地完成**。

## 反思

- **第一反应**：直接搬到新矩阵，写完后才意识到空间不符合要求。  
- **最容易踩的坑**：  
  - **下标混淆**：转置时只在 `i < j` 交换，防止把同一个元素换回去。  
  - **行翻转的边界**：当 `n` 为奇数时，中心元素不需要移动；循环条件 `left < right` 能自然跳过。  
  - **原地修改**：一定要在原矩阵上直接 `swap`，不要误用 `= matrix[i][j] = ...` 造成覆盖。  
- **下次类似题的第一步**：**先思考能否把目标操作拆解成已知的原地操作（如转置、翻转、交换）**，再判断每一步的实现细节。
