# #90. 子集 II / Subsets II

> 难度：中等 · 标签：Array、Backtracking、Bit Manipulation · [LeetCode 链接](https://leetcode.com/problems/subsets-ii/)

## 题目（英文原版）

**Description**

Given an integer array nums that may contain duplicates, return all possible subsets (the power set).
The solution set must not contain duplicate subsets. Return the solution in any order.

**Examples**

**Example 1:**

```
Input: nums = [1,2,2]
Output: [[],[1],[1,2],[1,2,2],[2],[2,2]]
```

**Example 2:**

```
Input: nums = [0]
Output: [[],[0]]
```

**Constraints**

- 1 <= nums.length <= 10
- -10 <= nums[i] <= 10

---

## 题目（中文翻译）

给定一个可能包含重复元素的整数数组 `nums`，返回所有可能的子集（幂集，power set）。  
解集 **不能** 包含重复的子集。返回的解集顺序可以任意。

**示例 1**  
**输入**: `nums = [1,2,2]`  
**输出**: `[[],[1],[1,2],[1,2,2],[2],[2,2]]`

**示例 2**  
**输入**: `nums = [0]`  
**输出**: `[[],[0]]`

**约束条件**  
- `1 <= nums.length <= 10`  
- `-10 <= nums[i] <= 10`

---

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  
最直接的想法是：**把所有可能的子集全部枚举出来**，再把出现重复的子集去掉。  
- **枚举方式**：可以把数组的每个位置看成一个“开关”，开=选、关=不选。长度为 `n` 的数组有 `2ⁿ` 种开关组合（即子集），用二进制的位来表示最直观。  
- **去重手段**：把每个子集转换成不可变的形式（如元组 `tuple`），放进 **哈希表**（Python 中的 `set`）里。哈希表就像一本“查字典”，键（key）是子集的内容，值（value）我们不关心，只要键不重复就会自动去掉重复的子集。  

> **为什么正确？**  
> - 每一种开关组合对应唯一的子集，遍历所有 `2ⁿ` 种组合就一定能得到所有子集。  
> - 把子集统一排序后再放进集合，重复的子集会产生相同的键，集合天然会把它们合并成一个。  

#### 代码（Python）  
```python
from typing import List

def subsetsWithDup_bruteforce(nums: List[int]) -> List[List[int]]:
    n = len(nums)
    all_subsets = set()                     # 用 set 去重，元素是 tuple
    for mask in range(1 << n):              # 0 ~ 2^n-1，每个 mask 表示一种选/不选方案
        cur = []
        for i in range(n):                  # 检查第 i 位是 0 还是 1
            if mask & (1 << i):             # 第 i 位为 1，说明要选 nums[i]
                cur.append(nums[i])
        # 为了让相同的子集得到相同的键，先排序再转成 tuple
        all_subsets.add(tuple(sorted(cur))) # 哈希表自动去重

    # 把 set 里的 tuple 再转回 list 形式返回
    return [list(t) for t in all_subsets]
```

#### 复杂度  
- **时间复杂度**：`O(2^n * n)`  
  - `2^n` 是所有可能的子集数目（每个子集对应一个二进制 mask）。  
  - 对每个 mask，我们要遍历 `n` 位来判断选不选，所以乘以 `n`。  
  - 再加上把子集排序的 `O(k log k)`（`k ≤ n`），整体仍然在 `O(2^n * n)` 级别。  
- **空间复杂度**：`O(2^n * n)`  
  - 需要存储所有子集（最坏情况下有 `2^n` 个），每个子集最多 `n` 长。  
  - 额外的集合 `set` 也占同样的空间。

### 2. 最优解  

#### 思路  
暴力解的瓶颈在 **“每次都要遍历所有 2ⁿ 种组合”**，而且我们在遍历的过程中会产生大量重复子集。  
要想提升效率，需要 **在生成子集的过程中就避免产生重复**。  
关键技巧有两点：

1. **先把数组排序**  
   排序后，所有相同的数字会被放在一起。比如 `[1,2,2]` → `[1,2,2]`，两个 `2` 紧挨在一起。  
   这一步类似把字典中的单词排好序，后面查找时更容易判断“这两个词是不是相同”。  

2. **回溯（Backtracking） + 跳过重复**  
   - 回溯的思路是：从左到右逐个决定“选”或“不选”。每一次递归都会把当前的选择加入结果集。  
   - 为了防止产生相同的子集，在同一层递归里**如果当前数字和前一个数字相同且前一个数字在本层没有被选**，就直接 **skip**（跳过）这个数字。  
   - 直观类比：想象你在排队买票，前面已经有人买了同样的票（相同的数字），而这张票本轮已经被拿走了，你就不必再排队一次买同样的票。

下面用代码一步步展示这个过程。

#### 代码（Python）  
```python
from typing import List

def subsetsWithDup(nums: List[int]) -> List[List[int]]:
    nums.sort()                     # 1. 排序，让相同的数字相邻
    res: List[List[int]] = []       # 用来保存所有子集
    path: List[int] = []            # 当前递归路径（正在构造的子集）

    def backtrack(start: int) -> None:
        """
        start: 本次递归在 nums 中搜索的起始位置（左闭右开区间 [start, len(nums))）
        """
        # 每进入一次递归，就把当前路径加入结果（即得到一个子集）
        res.append(path.copy())    # copy 防止后面修改影响已经保存的子集

        # 从 start 开始尝试把后面的每个元素加入子集
        i = start
        while i < len(nums):
            # 2. 跳过重复：如果当前元素和前一个相同，且前一个在本层没有被选择，就跳过
            if i > start and nums[i] == nums[i - 1]:
                i += 1
                continue

            # 选取 nums[i]，进入更深层的递归
            path.append(nums[i])
            backtrack(i + 1)        # 递归时下一个搜索位置是 i+1，保证每个元素只用一次
            path.pop()              # 回溯：撤销本次选择，尝试下一个可能

            i += 1

    backtrack(0)                    # 从下标 0 开始搜索
    return res
```

> **代码要点注释**  
> - `nums.sort()`：把相同的数字排在一起，后面判断“相同且未选”才有意义。  
> - `while i < len(nums):` 替代 `for i in range(start, len(nums))`，因为我们在循环内部可能会 `continue` 跳过某些元素。  
> - `if i > start and nums[i] == nums[i - 1]: continue`：只有当 **本层**（即 `start` 固定）出现重复时才跳过，防止跨层误判。  
> - `res.append(path.copy())`：每一次进入递归都产生一个合法子集（包括空集），必须复制一份，否则后面回溯会改动已保存的子集。  

#### 复杂度  
- **时间复杂度**：`O(2^n)`（最坏情况下仍然是所有子集的数量），但因为我们在生成时已经排除了重复子集，实际遍历的节点会少很多。  
  - 这里的 `2^n` 只是一种上界，和暴力解的 `2^n * n` 相比，省去了每层遍历时的 `O(n)` 复制和去重工作。  
- **空间复杂度**：`O(n)`（递归栈深度）+ 输出空间。  
  - `path` 最多保存 `n` 个元素，递归深度同样不超过 `n`。  
  - 结果集 `res` 本身需要 `O(2^n * n)` 空间，这部分是题目要求必须返回的，算在输出空间里。

## 心得  

- **核心技巧**：先排序 → 回溯 → 在同一层跳过相同的数字。  
- **适用的类似题型**  
  1. **Subsets I**（没有重复元素的子集）  
  2. **Permutations II**（含重复元素的全排列）  
  3. **Combination Sum II**（每个数字只能用一次，且要去重）  
- **解题钥匙**：**“排序 + 同层去重”**，只要把相同的东西排在一起，并在同一层决定不再选，就能自然避免重复结果。  

---

## 反思  

- **第一反应**：直接用位运算或递归把所有子集列出来，再用 `set` 去重。  
- **最容易踩的坑**  
  - 忘记对每个子集进行排序，导致 `[1,2]` 与 `[2,1]` 被认为是不同的子集。  
  - 去重的判断写错，导致遗漏合法子集或仍然出现重复。  
  - 输入可能全部相同（如 `[2,2,2]`），若不在同层跳过，会产生大量重复。  
- **下次遇到同类题**：第一步先 **把数组排序**，再 **用回溯**，在递归的同一层**检查前一个元素是否相同**并决定是否跳过。这样可以“一遍遍历”就得到去重后的完整答案。
