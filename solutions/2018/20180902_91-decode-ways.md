## 题目（英文原版）

**Description**

You have intercepted a secret message encoded as a string of numbers. The message is decoded via the following mapping:
"1" -> 'A'
"2" -> 'B'
...
"25" -> 'Y'
"26" -> 'Z'
However, while decoding the message, you realize that there are many different ways you can decode the message because some codes are contained in other codes ("2" and "5" vs "25").
For example, "11106" can be decoded into:
Note: there may be strings that are impossible to decode.

Given a string s containing only digits, return the number of ways to decode it. If the entire string cannot be decoded in any valid way, return 0.
The test cases are generated so that the answer fits in a 32-bit integer.

**Examples**

**Example 1:**

```
Input: s = "12"
Output: 2
Explanation:
"12" could be decoded as "AB" (1 2) or "L" (12).
```

**Example 2:**

```
Input: s = "226"
Output: 3
Explanation:
"226" could be decoded as "BZ" (2 26), "VF" (22 6), or "BBF" (2 2 6).
```

**Example 3:**

```
Input: s = "06"
Output: 0
Explanation:
"06" cannot be mapped to "F" because of the leading zero ("6" is different from "06"). In this case, the string is not a valid encoding, so return 0.
```

**Constraints**

- 1 <= s.length <= 100
- s contains only digits and may contain leading zero(s).

## 题目（中文翻译）

你拦截到一条由数字字符串编码的秘密信息。该信息的解码规则如下：

**示例 1**

**示例 2**  
输入: `s = "226"`  
输出: `3`

### 约束条件

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**穷举所有可能的切分方式**，把字符串每次切成 1 位或 2 位（因为映射只到 "26"），看每段是否在 `1~26` 之间，合法就继续往后递归。  

- **使用的数据结构**：递归函数 + 整数计数。  
  - 把递归想象成“走迷宫”。每走一步（切一段），如果这段合法，就继续往前走；走到终点（字符串全部被切完）就算一种可行的路径。  
- **为什么正确**：递归会尝试**所有**合法的切分组合，只有合法的才会进入下一层递归，所有合法的组合都会被计数一次，所以答案一定完整。  

#### 代码（Python）

```python
def numDecodings_brute(s: str) -> int:
    """
    暴力递归解法
    :param s: 只包含数字的字符串
    :return: 解码方法的数量
    """
    n = len(s)

    # 递归函数：从下标 i 开始往后解码，返回子串 s[i:] 的解码种数
    def dfs(i: int) -> int:
        # 已经走到字符串末尾，说明一种完整的切分方式
        if i == n:
            return 1

        # 遇到以 '0' 开头的子串，根本没有合法映射
        if s[i] == '0':
            return 0

        # 只取 1 位数字的情况
        count = dfs(i + 1)

        # 取 2 位数字的情况（需要保证 i+1 没越界，且两位数 ≤ 26）
        if i + 1 < n and int(s[i:i + 2]) <= 26:
            count += dfs(i + 2)

        return count

    return dfs(0)
```

#### 复杂度  

- **时间复杂度**：`O(2^n)`  
  - 每个位置最多有两种选择（取 1 位或 2 位），所以最坏情况下会产生约 `2^n` 条递归路径。可以把 `2^n` 想象成“树的每层翻倍”，当 `n=20` 时已经有超过一百万条分支，显然不够快。  
- **空间复杂度**：`O(n)`  
  - 递归栈的深度最多是 `n`（每次只往前走 1 位），所以需要 `n` 层栈帧来保存局部变量。

### 2. 最优解  

#### 思路  

从暴力解我们可以看到**重复子问题**：  
- `dfs(i)` 只和 `i` 有关，`i` 相同的子串每次都会被重新计算。  
- 例如 `"1111"`，`dfs(2)` 会被调用多次，导致指数级的时间浪费。  

**动态规划（DP）** 的核心思想是**把子问题的答案记下来，后面直接复用**。这里的子问题正好是“从位置 i 开始的子串有多少种解码方式”。  

我们可以从左到右或从右到左遍历，维护一个数组 `dp`：

- `dp[i]` 表示**以第 i 个字符结尾的子串**（即 `s[:i]`）的解码方法数。  
- 初始状态：空串有 1 种解法（什么也不做），设 `dp[0] = 1`。  

转移方程（从左往右）：

1. **单字符**：如果 `s[i-1]` 不是 `'0'`，则可以把它单独解码，贡献 `dp[i-1]` 种方式。  
2. **双字符**：如果 `i >= 2` 且 `s[i-2:i]` 构成的两位数在 `10~26` 之间（即合法），则可以把这两位一起解码，贡献 `dp[i-2]` 种方式。  

于是  
```
dp[i] = 0
if s[i-1] != '0':
    dp[i] += dp[i-1]
if i >= 2 and 10 <= int(s[i-2:i]) <= 26:
    dp[i] += dp[i-2]
```

**空间优化**：`dp[i]` 只和 `dp[i-1]`、`dp[i-2]` 有关，完全可以用两个变量滚动更新，做到 **O(1) 额外空间**。  

下面给出 **完整代码**（带中文注释）以及 **时间/空间复杂度** 的解释。  

#### 代码（Python）

```python
def numDecodings(s: str) -> int:
    """
    动态规划（滚动数组）解法
    :param s: 只包含数字的字符串
    :return: 解码方法的数量
    """
    n = len(s)
    if n == 0:
        return 0

    # prev2 对应 dp[i-2]，prev1 对应 dp[i-1]
    # 空串有一种解法：什么也不做
    prev2 = 1
    # 第一个字符能否解码决定 dp[1]（即 prev1）
    prev1 = 0 if s[0] == '0' else 1

    # 从第二个字符开始遍历
    for i in range(2, n + 1):
        cur = 0  # dp[i] 初始为 0

        # 单字符解码（只看第 i-1 位）
        if s[i - 1] != '0':          # 不是 '0' 才能单独映射
            cur += prev1             # 加上 dp[i-1]

        # 双字符解码（看第 i-2,i-1 两位）
        two_digit = int(s[i - 2:i])  # 把两位切出来转成整数
        if 10 <= two_digit <= 26:    # 只要在合法区间，就可以一起解码
            cur += prev2             # 加上 dp[i-2]

        # 滚动更新，准备进入下一轮循环
        prev2, prev1 = prev1, cur

    # 循环结束后，prev1 正好是 dp[n]
    return prev1
```

#### 复杂度  

- **时间复杂度**：`O(n)`  
  - 只遍历一次字符串，每一步做常数次判断和加法。可以把 `O(n)` 想象成“跟字符串长度成正比”，长度是 100，最多跑 100 步，几乎瞬间完成。  
- **空间复杂度**：`O(1)`  
  - 只使用了常数个整数变量（`prev2、prev1、cur`），不随 `n` 增长。相比暴力解需要递归栈，省了很多内存。

## 心得  

- **核心技巧**：**动态规划 + 滚动数组**，把“从左到右的子问题”转化为线性递推。  
- **适用的题型**：  
  1. **爬楼梯**（`dp[i] = dp[i-1] + dp[i-2]`）——也是把每一步拆成「一步」或「两步」的组合计数。  
  2. **不同路径**（网格路径计数）——每个格子只能从上或左来到达，同样是 `dp[i][j] = dp[i-1][j] + dp[i][j-1]`。  
  3. **最长递增子序列的计数**（在 O(n²) DP 中记录计数）——也是在子问题上累加计数。  
- **一句话总结解题钥匙**：**把“所有合法切分”抽象成“当前位置的解码数 = 前一步的解码数（单字符）+ 前两步的解码数（双字符）”。**

## 反思  

- **第一反应**：看到“数字映射成字母”，立刻想到“枚举每一种切分”，于是写了递归暴力。  
- **最容易踩的坑**：  
  - **'0' 的处理**：单独的 `'0'` 没有对应字母，只能和前面的 `'1'` 或 `'2'` 组成 `10`、`20`。忘记这点会导致错误计数。  
  - **两位数合法区间**：必须是 `10~26`，而不是 `1~26`，否则会把 `'01'`、`'05'` 当成合法。  
  - **空字符串或全是 `'0'`**：返回 0，而不是 1。  
- **下次遇到同类题**：第一步先**写出 DP 状态定义和转移方程**，确认每一步只依赖前几步的结果，再考虑是否可以**空间压缩**（滚动数组）。这样可以直接跳过递归的指数爆炸。
