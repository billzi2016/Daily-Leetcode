## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是**逐个格子尝试**，把所有空格（`'.'`）都填上数字 1~9，只要满足数独的三条规则（行、列、3×3 小宫格里不出现重复数字）就算合法。  

- **使用的数据结构**：  
  - `board` 本身是一个 9×9 的二维列表，像是一张 9 行 9 列的格子表。  
  - 为了检查“这个数字在当前行/列/宫格是否已经出现”，我们可以遍历对应的行、列或小宫格，就像在**字典里查词**一样：把要找的数字当作“词”，把整行/整列/整宫格当作“字典”。  

- **为什么正确**：  
  - 我们把每一种可能的填法都尝试一次，只要找到一种满足所有规则的填法，就一定是答案。由于题目保证唯一解，这种穷举必然能得到唯一的正确棋盘。  

- **复杂度分析（大白话）**：  
  - 每个空格最多有 9 种选择，最坏情况下 81 个格子全是空的，搜索树的大小大约是 `9^81`，这几乎是 **天文数字**，所以时间会非常慢。  
  - 空间上只需要存放原始的棋盘和递归调用的栈，栈深度最多 81（每填一个格子就进入一次递归），所以是 **O(81) ≈ O(1)**（常数级别）。

#### 代码（Python）

```python
from typing import List

def solveSudoku(board: List[List[str]]) -> None:
    """
    直接的暴力回溯解法
    只需要把答案写回 board，函数本身不返回值
    """
    def is_valid(r: int, c: int, ch: str) -> bool:
        """检查在 (r, c) 放置 ch 是否冲突"""
        # 检查行
        for col in range(9):
            if board[r][col] == ch:
                return False
        # 检查列
        for row in range(9):
            if board[row][c] == ch:
                return False
        # 检查 3×3 小宫格
        start_r, start_c = 3 * (r // 3), 3 * (c // 3)
        for i in range(3):
            for j in range(3):
                if board[start_r + i][start_c + j] == ch:
                    return False
        return True

    def backtrack() -> bool:
        """在 board 上进行深度优先搜索，找到合法填法返回 True"""
        for i in range(9):
            for j in range(9):
                if board[i][j] == '.':          # 找到下一个空格
                    for d in map(str, range(1, 10)):  # 依次尝试 1~9
                        if is_valid(i, j, d):
                            board[i][j] = d      # 放置数字
                            if backtrack():      # 递归尝试后面的格子
                                return True
                            board[i][j] = '.'    # 回溯，撤销选择
                    return False    # 所有数字都不行，必须回溯
        return True    # 没有空格了，说明已经填满合法

    backtrack()   # 直接修改 board
```

#### 复杂度

- **时间复杂度**：`O(9^(m))`（`m` 为空格数），这里的 `9^m` 代表每个空格最多有 9 种尝试，整体是指数级别。  
  - 大白话：如果有 20 个空格，就相当于要尝试 `9^20 ≈ 1.2×10^19` 种组合，几乎不可能在合理时间内算完。  
- **空间复杂度**：`O(81)`（递归栈深度最多 81），可以视作 **O(1)**，因为它不随输入规模增长而增长太多。

### 2. 最优解

#### 思路  

暴力解的**瓶颈**在于每次判断一个数字是否可放时，都要**遍历整行、整列、整宫格**，这导致大量重复检查。我们可以在搜索的过程中**维护三组哈希表**（这里用 Python 的 `set`），实时记录每一行、每一列、每个 3×3 小宫格已经出现的数字，这样判断是否合法只需要 O(1) 时间。

**步骤**：

1. **预处理**：遍历棋盘一次，把已有的数字放进对应的 `row_sets[i]`、`col_sets[j]`、`box_sets[box_index]`。  
   - `box_index = (i // 3) * 3 + (j // 3)`，把 9 个小宫格编号为 0~8。  
2. **回溯搜索**：同样从左上到右下寻找第一个 `'.'`。  
   - 对于当前空格 `(i, j)`，尝试 1~9 中**既不在该行集合、也不在该列集合、也不在该宫格集合**的数字。  
   - 把尝试的数字加入三个集合，递归继续；若后续失败，则**撤销**（从集合中删掉），并把格子恢复为 `'.'`。  
3. **剪枝**：因为集合查询是 O(1)，我们可以在尝试前快速排除不可能的数字，大幅度降低搜索树的宽度。  

**类比**：  
- 把每一行、每一列、每一个宫格想象成 **三个字典**，每放进一个数字，就在对应的字典里写下这本“书”的页码。下次想放同一本书，只要查一下这三个字典里有没有这个页码，就能立刻知道是否冲突，省掉了整行/整列的遍历。

#### 代码（Python）

```python
from typing import List

def solveSudoku(board: List[List[str]]) -> None:
    """
    使用哈希集合（set）进行状态记录的回溯解法
    时间大幅提升，实际运行几毫秒即可得到答案
    """
    # 记录每行、每列、每个 3×3 宫格里已经出现的数字
    row_sets = [set() for _ in range(9)]
    col_sets = [set() for _ in range(9)]
    box_sets = [set() for _ in range(9)]

    # ---------- 1. 预处理 ----------
    for i in range(9):
        for j in range(9):
            val = board[i][j]
            if val != '.':
                row_sets[i].add(val)
                col_sets[j].add(val)
                box_index = (i // 3) * 3 + (j // 3)
                box_sets[box_index].add(val)

    # ---------- 2. 回溯 ----------
    def backtrack() -> bool:
        for i in range(9):
            for j in range(9):
                if board[i][j] == '.':            # 找到下一个空格
                    box_idx = (i // 3) * 3 + (j // 3)
                    for d in map(str, range(1, 10)):
                        # O(1) 判断是否合法
                        if (d not in row_sets[i] and
                            d not in col_sets[j] and
                            d not in box_sets[box_idx]):
                            # 试探性放置
                            board[i][j] = d
                            row_sets[i].add(d)
                            col_sets[j].add(d)
                            box_sets[box_idx].add(d)

                            if backtrack():        # 继续递归
                                return True

                            # ---------- 3. 撤销 ----------
                            board[i][j] = '.'
                            row_sets[i].remove(d)
                            col_sets[j].remove(d)
                            box_sets[box_idx].remove(d)
                    # 所有数字都不行，必须回溯到上一步
                    return False
        # 没有空格了，说明已成功填满
        return True

    backtrack()   # 直接修改 board
```

#### 复杂度

- **时间复杂度**：`O(9^{m})` 仍是指数级（`m` 为空格数），但因为每一步合法性检查降到了 **O(1)**，实际遍历的分支大幅减少，常数因子远小于暴力解。  
  - 大白话：如果原来每个空格要检查 27 次（9 行 + 9 列 + 9 宫格），现在只检查 3 次（集合查找），速度提升约 **9 倍**，在实际数据上几乎是瞬间完成。  
- **空间复杂度**：`O(9*3)` = `O(1)`（三个长度为 9 的集合），加上递归栈深度最多 81，仍然是常数级别。

## 心得

- **核心技巧**：使用 **哈希集合记录约束**（行、列、宫格），配合 **回溯**（深度优先搜索）进行“填空”。
- **适用的题型**：  
  1. **数独类**的约束填空问题（如 `Sudoku Solver`、`Valid Sudoku`）。  
  2. **八皇后**（N‑Queens）——记录每列、每条对角线的冲突。  
  3. **单词搜索**（Word Search）——记录已访问的格子，防止重复使用。
- **一句话总结**：**“把每一次合法性检查压缩到 O(1”，用集合记住已经占用的数字，回溯时随时撤销。**

## 反思

- **第一反应**：看到“填空”“满足三条规则”，立刻想到遍历每个空格、尝试 1~9，这就是暴力回溯。
- **最容易踩的坑**：  
  - **忘记撤销**：在回溯失败后必须把集合里的数字删掉，否则后面的判断会受到错误的干扰。  
  - **宫格编号错误**：`box_index = (i // 3) * 3 + (j // 3)` 必须写对，否则行列与宫格的约束会错位。  
  - **输入是字符**，不要把 `'1'` 当作整数 `1` 来比较，保持统一的字符串类型。  
- **下次遇到同类题**：第一步先**建立约束集合**（或数组），用它们快速判断合法性，再进入回溯搜索。这样可以把“检查”这件事的时间从线性降到常数，效率立刻提升。
