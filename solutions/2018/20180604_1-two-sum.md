# #1. 两数之和 / Two Sum

> 难度：简单 · 标签：Array、Hash Table · [LeetCode 链接](https://leetcode.com/problems/two-sum/)

---

## 题目（英文原版）

**Description**

Given an array of integers nums and an integer target, return indices of the two numbers such that they add up to target.
You may assume that each input would have exactly one solution, and you may not use the same element twice.
You can return the answer in any order.

**Examples**

**Example 1:**

```
Input: nums = [2,7,11,15], target = 9
Output: [0,1]
Explanation: Because nums[0] + nums[1] == 9, we return [0, 1].
```

**Example 2:**

```
Input: nums = [3,2,4], target = 6
Output: [1,2]
```

**Example 3:**

```
Input: nums = [3,3], target = 6
Output: [0,1]
```

**Constraints**

- 2 <= nums.length <= 104
- -109 <= nums[i] <= 109
- -109 <= target <= 109
- Only one valid answer exists.

## 题目（中文翻译）

**描述**  
给定一个整数（integer）数组 `nums` 和一个整数 `target`，返回两个数的下标，使得它们的和等于 `target`。  
你可以假设每个输入恰好只有唯一的解，并且同一个元素不能使用两次。  
返回的下标顺序不限。

**示例 1**  
Input: nums = [2,7,11,15], target = 9  
Output: [0,1]  
Explanation: 因为 nums[0] + nums[1] == 9，返回 [0, 1]。

**示例 2**  
Input: nums = [3,2,4], target = 6  
Output: [1,2]  

**示例 3**  
Input: nums = [3,3], target = 6  
Output: [0,1]  

**约束条件**  
- 2 ≤ `nums.length` ≤ 10^4  
- -10^9 ≤ `nums[i]` ≤ 10^9  
- -10^9 ≤ `target` ≤ 10^9  
- 仅存在唯一的合法答案。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是把数组里每一对元素都拿出来检查一次，看它们的和是否等于 `target`。  
可以把这一步想象成在 **“找情侣”**：我们把每个人都跟后面所有人约会一次，如果两个人的身高（这里是数值）相加恰好等于目标身高（`target`），我们就找到了答案。

- **使用的数据结构**：只需要原始的列表 `nums`，不需要额外的容器。  
- **为什么正确**：因为我们遍历了所有可能的两两组合，必然会碰到唯一的那一对满足条件的数字。  
- **时间/空间复杂度**：  
  - 时间复杂度是 `O(n²)`，这里的 `n` 是数组长度。`O(n²)` 可以理解为“如果你有 `n` 个人，要让每个人和后面所有人约会，总共要进行大约 `n × n` 次约会”。  
  - 空间复杂度是 `O(1)`，因为我们只用了常数级别的额外空间（几个临时变量），不随 `n` 增长。

#### 代码（Python）

```python
def two_sum_brute(nums, target):
    """
    暴力解法：两层循环枚举所有下标对 (i, j)
    """
    n = len(nums)
    # 外层遍历第一个数字的下标 i
    for i in range(n):
        # 内层遍历第二个数字的下标 j，j 必须在 i 之后，防止重复使用同一个元素
        for j in range(i + 1, n):
            # 检查两数之和是否等于 target
            if nums[i] + nums[j] == target:
                # 找到答案，直接返回下标列表
                return [i, j]
    # 题目保证一定有解，理论上不会走到这里
    return []
```

#### 复杂度

- **时间复杂度**：`O(n²)` — 需要检查 `n*(n-1)/2` 对数字，随着 `n` 增大，耗时呈二次方增长。  
- **空间复杂度**：`O(1)` — 只用了常数个变量，不会随输入规模变大而占用更多内存。

### 2. 最优解

#### 思路  

从暴力解可以看到 **瓶颈** 在于每次找配对时都要遍历整个剩余数组，导致二次循环。  
要加速搜索，核心是把 “在数组里找某个数” 这一步变成 **常数时间**（`O(1)`）的操作。

> **哈希表（字典）** 就像一本“词典”，我们把已经遍历过的数字当成“单词”，把它们的 **下标** 当成“页码”。  
> 当我们来到新数字 `x` 时，只需要在词典里查找 “`target - x`” 这个词是否已经出现过。如果出现过，说明之前的某个数正好可以和 `x` 配成答案。

实现步骤：

1. 创建一个空字典 `num_to_index`，键是数组中的数，值是该数出现的下标。  
2. 从左到右遍历 `nums`，对于当前元素 `x`（下标 `i`）：
   - 计算它需要的配对数 `complement = target - x`。  
   - 检查 `complement` 是否已经在 `num_to_index` 中。如果在，说明我们之前已经看到过配对数，直接返回 `[num_to_index[complement], i]`。  
   - 否则，把 `x` 和它的下标 `i` 加入字典，供后面的元素使用。  
3. 由于题目保证恰好有唯一解，遍历结束时一定已经返回答案。

> **为什么只需要一次遍历？**  
> 因为每个元素只会被插入字典一次，也只会在后面的元素查找一次。字典的查询和插入在平均情况下都是 `O(1)`，所以整体时间是线性的。

#### 代码（Python）

```python
def two_sum(nums, target):
    """
    哈希表（字典）解法：一次遍历完成查找
    """
    # key -> 数字的值, value -> 该数字在数组中的下标
    num_to_index = {}
    
    for i, x in enumerate(nums):
        # 需要的配对数
        complement = target - x
        
        # 看看之前是否已经出现过 complement
        if complement in num_to_index:
            # 找到了，返回配对下标
            return [num_to_index[complement], i]
        
        # 如果没有配对数，则把当前数字及其下标加入字典
        # 注意：这里先检查再插入，防止同一个元素被自己配对（题目不允许同元素两次）
        num_to_index[x] = i
    
    # 题目保证一定有解，理论上不会走到这里
    return []
```

#### 复杂度

- **时间复杂度**：`O(n)` — 只遍历一次数组，每次查询/插入字典是常数时间。与暴力 `O(n²)` 相比，速度提升了 **指数级**。  
- **空间复杂度**：`O(n)` — 最坏情况下需要把所有元素都存进字典，额外占用与数组等量的空间。

## 心得

- **核心技巧**：利用哈希表把“在数组中找某个数”这一步从线性搜索降到常数时间。  
- **适用的题型**：  
  1. **两数之和**（本题）  
  2. **四数之和**（把两数之和的结果存进哈希表，再配对）  
  3. **最长连续子数组和为 K**（使用前缀和 + 哈希表）  
- **一句话总结解题钥匙**：**“先把已经看到的东西记下来，下次遇到需要它们时直接查表”。**

## 反思

- **第一反应**：想到两层循环穷举所有配对，直接实现暴力解。  
- **最容易踩的坑**：  
  - **同一个元素被重复使用**：在哈希表解法中必须先检查再插入，否则会把当前元素当作配对数自身。  
  - **负数或零**：哈希表不受数值范围限制，只要键是可哈希的（整数），都能正常工作。  
  - **答案唯一性**：题目保证唯一解，代码可以直接返回第一对找到的下标；若不存在唯一性，需要考虑返回所有解或其他约束。  
- **下次遇到类似题目**，第一步应该思考：“有没有办法把 “寻找配对” 这一步做成 **O(1)** 的查找？如果可以，常用的工具就是 **哈希表**（字典）”。
