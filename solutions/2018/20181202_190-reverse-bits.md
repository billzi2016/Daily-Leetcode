## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直观的办法是把整数的每一位二进制都取出来，按相反的顺序重新拼成一个新数。  
可以把「取出最低位」想象成「把硬币从右边的口袋倒出来」，每倒一次，就把硬币放进「左边的口袋」的最前面。  

具体做法：

1. 初始化答案 `rev = 0`（相当于空的左口袋）。  
2. 循环 32 次（因为题目要求 32 位无符号整数）：  
   - 把 `rev` 左移一位，为即将放进去的最低位腾出空间。  
   - 取出 `n` 的最低位 `bit = n & 1`（`&` 就像查字典，只看最后一位）。  
   - 把这个位加到 `rev` 的最低位 `rev |= bit`。  
   - 把 `n` 右移一位 `n >>= 1`，准备处理下一位。  
3. 循环结束后，`rev` 就是原数的位翻转结果。

这个方法一定正确，因为我们严格按照「从右到左」读取原数的每一位，再「从左到右」写入新数，正好完成了逆序。

#### 代码（Python）

```python
def reverseBits_brute(n: int) -> int:
    rev = 0                     # 最终的翻转结果，初始为 0
    for _ in range(32):         # 固定遍历 32 位
        rev <<= 1               # rev 左移一位，为放入新位腾出位置
        rev |= n & 1            # 取 n 的最低位并放到 rev 的最低位
        n >>= 1                 # n 右移一位，准备处理下一位
    # Python 的整数是无限长的，这里确保返回的是 32 位无符号整数
    return rev & 0xFFFFFFFF
```

#### 复杂度  

- **时间复杂度**：`O(32)` → 实际上是常数时间 `O(1)`，因为循环次数固定为 32（不随输入大小变化）。可以把 `O(32)` 想象成「永远只跑 32 步」。
- **空间复杂度**：`O(1)` → 只用了几个整数变量，和输入规模无关。

### 2. 最优解

#### 思路  

虽然上面的「暴力」解已经是 `O(1)`，但它每次都要循环 32 次。如果函数会被**大量调用**（比如在网络协议里每秒处理上万条数据），我们可以进一步把常数降到更低。

思路来源于「分治」：一次性把整数分成若干块，分别把块内部的位翻转，然后再把块的位置调换。  
具体做法采用**位掩码 + 移位**，每一步都把相邻的两位、四位、八位……翻转一次。下面用 8 位的例子帮助理解（实际题目是 32 位）：

```
原数:  a b c d e f g h   （每个字母代表一位）
步骤1： 交换相邻的位 → b a d c f e h g
步骤2： 交换相邻的 2 位块 → d c b a h g f e
步骤3： 交换相邻的 4 位块 → h g f e d c b a
```

对 32 位整数而言，只需要 5 次掩码 + 移位操作（1、2、4、8、16 位），每次都用 **常数时间** 完成。

关键的掩码（mask）：

| 步骤 | 掩码十六进制 | 作用 |
|------|-------------|------|
| 1    | `0x55555555` (0101…) | 选出所有奇数位 |
| 2    | `0x33333333` (0011…) | 选出每两位中的低位 |
| 3    | `0x0F0F0F0F` (00001111…) | 选出每四位中的低位 |
| 4    | `0x00FF00FF` | 选出每八位中的低位 |
| 5    | `0x0000FFFF` | 选出低 16 位 |

每一步的操作形式为：

```
n = ((n >> shift) & mask) | ((n & mask) << shift)
```

- `n >> shift` 把高位移下来，`& mask` 把对应的低位保留下来。  
- `n & mask` 把低位保留下来，`<< shift` 把它们移到高位。  
- 最后 `|` 把两部分合并。

这样只需要 5 次「读取‑移位‑掩码‑合并」的循环，极大提升了实际运行速度。

#### 代码（Python）

```python
def reverseBits_opt(n: int) -> int:
    # 步骤 1：交换相邻的位
    n = ((n >> 1) & 0x55555555) | ((n & 0x55555555) << 1)
    # 步骤 2：交换相邻的两位块
    n = ((n >> 2) & 0x33333333) | ((n & 0x33333333) << 2)
    # 步骤 3：交换相邻的四位块
    n = ((n >> 4) & 0x0F0F0F0F) | ((n & 0x0F0F0F0F) << 4)
    # 步骤 4：交换相邻的八位块
    n = ((n >> 8) & 0x00FF00FF) | ((n & 0x00FF00FF) << 8)
    # 步骤 5：交换高低 16 位
    n = ((n >> 16) & 0x0000FFFF) | ((n & 0x0000FFFF) << 16)
    return n & 0xFFFFFFFF          # 确保返回 32 位无符号整数
```

#### 复杂度  

- **时间复杂度**：`O(1)`，只做了固定的 5 次位运算。相较于暴力解的 32 次循环，常数更小，实际运行更快。
- **空间复杂度**：`O(1)`，同样只使用了若干整数变量。

## 心得

- **核心技巧**：位掩码（mask） + 移位（shift） 的“分治”思路，能够一次性翻转固定长度的二进制序列。  
- **适用题型**：  
  1. 反转二进制位（本题）。  
  2. 交换奇偶位、或把整数的高低 16 位互换（如 LeetCode 190 的变体）。  
  3. 统计二进制中 1 的个数的“并行计数”技巧（使用类似的掩码）。  
- **一句话总结**：把大问题拆成若干小块，每块内部先翻转，再整体调位——就像先把每对手套翻面，再把左手套和右手套互换位置。

---

## 反思

- **第一反应**：直接遍历 32 位，用左移/右移逐位搬运——最自然的「把硬币倒进另一口袋」思路。  
- **最容易踩的坑**：  
  - 忘记对 Python 整数做 `& 0xFFFFFFFF`，导致返回的结果变成负数（因为 Python 没有固定宽度的 unsigned int）。  
  - 掩码写错位数（如 `0x55555555` 写成 `0x5555555`），会导致高位没有被正确处理。  
- **下次类似题的第一步**：先判断是否可以用「固定宽度的位操作」一次性完成，如果函数会被频繁调用，就立刻考虑使用掩码‑移位的分治技巧。
