# #5. 最长回文子串 / Longest Palindromic Substring

> 难度：中等 · 标签：Two Pointers、String、Dynamic Programming · [LeetCode 链接](https://leetcode.com/problems/longest-palindromic-substring/)

---

## 题目（英文原版）

**Description**

Given a string s, return the longest palindromic substring in s.

**Examples**

**Example 1:**

```
Input: s = "babad"
Output: "bab"
Explanation: "aba" is also a valid answer.
```

**Example 2:**

```
Input: s = "cbbd"
Output: "bb"
```

**Constraints**

- 1 <= s.length <= 1000
- s consist of only digits and English letters.

---

## 题目（中文翻译）

给定一个字符串 `s`，返回 `s` 中最长的回文子串（substring）。

### 示例

#### 示例 1
**输入:** `s = "babad"`  
**输出:** `"bab"`  
**解释:** `"aba"` 也是一个有效答案。

#### 示例 2
**输入:** `s = "cbbd"`  
**输出:** `"bb"`

- `1 <= s.length <= 1000`
- `s` 仅由数字和英文字母组成。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把所有可能的子串都枚举出来，然后逐个检查它们是不是回文（即正着读和倒着读相同）。  
- **枚举子串**：用两个下标 `i`（起始位置）和 `j`（结束位置），`i ≤ j`。这相当于我们在字符串上画出所有可能的区间，就像在纸上用尺子一次次截取不同长度的片段。  
- **回文检查**：把子串切出来后，从左往右和从右往左各走一遍指针，比较对应字符是否相等。可以把它想象成把一段文字对折，看两边的字母是否完全对应——如果对应则是回文。  

**为什么一定能得到答案**  
因为我们把 **所有** 子串都检查了一遍，只要其中有回文，就一定会被发现。把所有回文中最长的记录下来，最后返回的就是题目要求的最长回文子串。

**复杂度分析（大白话）**  
- 枚举子串的组合数是 `n`（字符串长度）乘 `n`，大约是 `n²`（比如 1000 长的字符串会有近 1,000,000 种区间）。  
- 每检查一个子串，我们最坏要把它的每个字符都对比一次，最多是 `n` 次。  
- 所以总共的工作量是 `n² × n = n³`，即 **时间复杂度 O(n³)**。  
- 只用了几个整数变量和临时的子串（Python 切片会生成新字符串），空间上只和输入大小同级，记作 **O(1) 额外空间**（不计入返回结果本身）。

#### 代码（Python）

```python
def longestPalindrome_brute(s: str) -> str:
    n = len(s)
    longest = ""                     # 记录目前找到的最长回文

    # 枚举所有子串的起始位置 i 和结束位置 j（闭区间）
    for i in range(n):
        for j in range(i, n):
            sub = s[i:j+1]           # 切出子串，Python 切片是左闭右开，所以要 +1
            # 检查 sub 是否是回文
            left, right = 0, len(sub) - 1
            is_pal = True
            while left < right:
                if sub[left] != sub[right]:
                    is_pal = False   # 一旦发现不相等，就不是回文
                    break
                left += 1
                right -= 1
            # 如果是回文且长度更长，就更新答案
            if is_pal and len(sub) > len(longest):
                longest = sub
    return longest
```

#### 复杂度

- **时间复杂度**：`O(n³)` —— “立方”意味着如果字符串长度翻倍，运算量会增加大约八倍。对 1000 长的字符串来说几乎不可接受。  
- **空间复杂度**：`O(1)`（不计返回的结果），只用了常数个额外变量。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **每次都要重新遍历子串来判断回文**。如果我们已经知道一个更小的区间是回文，能否直接推出更大的区间是否回文呢？

**核心观察**  
- 若子串 `s[l+1 … r-1]` 已经是回文，只要两头的字符 `s[l]` 与 `s[r]` 相同，整个 `s[l … r]` 也一定是回文。  
- 这意味着只要把“已经确认的回文”往外扩展一层，就可以得到更长的回文。

**把观察变成算法**  
我们把每一个字符（以及字符之间的空隙）当作“中心”，从中心向左右同时展开指针，只要两边字符相等就继续展开。  
- **奇数长度回文**：中心是单个字符，例如 `"aba"`，中心是 `'b'`。  
- **偶数长度回文**：中心是两个相邻字符之间的空隙，例如 `"abba"`，中心在 `'b'` 与 `'b'` 之间。

对每一个可能的中心，都做一次“向外扩展”，记录扩展得到的最长回文子串。  
这样我们只遍历了 **每个字符两次**（一次当奇数中心，一次当偶数中心），每次扩展最多走 `n` 步，整体是 `O(n²)` 时间，但**不再需要额外的 O(n) 空间**，只用了常数个指针。

**为什么是最优（在本题约束下）**  
- 已经把每一次回文检查的代价从 `O(n)` 降到了 `O(1)`（因为只比较两端字符），所以整体只能是 `O(n²)`，这已经是对所有 `n²` 个中心的必然代价。  
- 空间只用了常数级别，最小化了额外内存。

#### 代码（Python）

```python
def longestPalindrome(s: str) -> str:
    """
    使用“中心扩展”法找最长回文子串。
    时间 O(n^2)，空间 O(1)。
    """
    n = len(s)
    if n < 2:                     # 长度为 0 或 1 时本身就是回文
        return s

    start, max_len = 0, 1        # 记录最长回文的起始下标和长度

    # 辅助函数：从 left、right 两指针向外扩展，返回扩展后回文的长度
    def expand(left: int, right: int) -> int:
        while left >= 0 and right < n and s[left] == s[right]:
            left -= 1
            right += 1
        # 退出循环时，left、right 已经超出回文区间，真实长度是 right-left-1
        return right - left - 1

    for i in range(n):
        # ① 奇数中心：以 s[i] 为中心
        len1 = expand(i, i)
        # ② 偶数中心：以 s[i] 与 s[i+1] 之间的空隙为中心
        len2 = expand(i, i + 1)

        cur_len = max(len1, len2)      # 两种情况取较大者
        if cur_len > max_len:          # 找到更长的回文，更新记录
            max_len = cur_len
            # 计算新的起始下标：中心 i 左侧需要移动 (cur_len-1)//2
            start = i - (cur_len - 1) // 2

    return s[start:start + max_len]
```

#### 复杂度

- **时间复杂度**：`O(n²)` —— 想象每个字符都当一次“中心”，向外最多扩展 `n` 步。对 1000 长的字符串来说最多约 1,000,000 次字符比较，能够在毫秒级完成。  
- **空间复杂度**：`O(1)` —— 只用了几个整数变量（`start、max_len、left、right`），不随输入规模增长。

---

## 心得

- **核心技巧**：**中心扩展**（把已知的“小回文”往外扩展），它把“检查整个子串是否回文”的代价从线性降低到常数。  
- **适用的题型**  
  1. **最长回文子串**（本题）。  
  2. **判断一个字符串是否可以通过删除字符变成回文**（利用双指针从两端向中间比较）。  
  3. **回文排列**（统计字符出现次数，利用哈希表统计奇偶）。  
- **一句话总结解题钥匙**：*把“回文”看成“左右对称”，只要把对称的两端一步步往外逼，就能快速找到最长的对称段。*

---

## 反思

- **第一反应**：直接枚举所有子串，然后逐个检查回文——这就是暴力解。  
- **最容易踩的坑**  
  - **奇偶长度的区别**：只以单字符为中心会漏掉偶数长度的回文（如 `"bb"`）。  
  - **边界条件**：`expand` 时指针可能会越界，需要在循环条件里检查 `left >= 0` 与 `right < n`。  
  - **返回子串的切片**：记得 `start:start+max_len`，不要写成 `start:max_len`（会得到错误长度）。  
- **下次遇到同类题**：第一步先思考“是否可以把问题从整体转化为局部的‘中心’或‘两端’”，然后尝试 **双指针/中心扩展**，因为这类技巧往往能把 O(n³) 降到 O(n²) 甚至更低。
