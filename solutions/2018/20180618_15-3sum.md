# #15. 三数之和 / 3Sum

> 难度：中等 · 标签：Array、Two Pointers、Sorting · [LeetCode 链接](https://leetcode.com/problems/3sum/)

---

## 题目（英文原版）

**Description**

Given an integer array nums, return all the triplets [nums[i], nums[j], nums[k]] such that i != j, i != k, and j != k, and nums[i] + nums[j] + nums[k] == 0.
Notice that the solution set must not contain duplicate triplets.

**Examples**

**Example 1:**

```
Input: nums = [-1,0,1,2,-1,-4]
Output: [[-1,-1,2],[-1,0,1]]
Explanation: 
nums[0] + nums[1] + nums[2] = (-1) + 0 + 1 = 0.
nums[1] + nums[2] + nums[4] = 0 + 1 + (-1) = 0.
nums[0] + nums[3] + nums[4] = (-1) + 2 + (-1) = 0.
The distinct triplets are [-1,0,1] and [-1,-1,2].
Notice that the order of the output and the order of the triplets does not matter.
```

**Example 2:**

```
Input: nums = [0,1,1]
Output: []
Explanation: The only possible triplet does not sum up to 0.
```

**Example 3:**

```
Input: nums = [0,0,0]
Output: [[0,0,0]]
Explanation: The only possible triplet sums up to 0.
```

**Constraints**

- 3 <= nums.length <= 3000
- -105 <= nums[i] <= 105

## 题目（中文翻译）

给定一个整数数组（integer array）`nums`，返回所有满足 `i != j`、`i != k`、`j != k` 且 `nums[i] + nums[j] + nums[k] == 0` 的三元组（triplet）`[nums[i], nums[j], nums[k]]`。  
注意，解集不得包含重复的三元组。

**Example 1:**

```text
Input: nums = [-1,0,1,2,-1,-4]
Output: [[-1,-1,2],[-1,0,1]]
```

**Explanation:**  
`nums[0] + nums[1] + nums[2] = (-1) + 0 + 1 = 0`。  
`nums[1] + nums[2] + nums[4] = 0 + 1 + (-1) = 0`。  
`nums[0] + nums[3] + nums[4] = (-1) + 2 + (-1) = 0`。  
不同的三元组为 `[-1,0,1]` 和 `[-1,-1,2]`。  
输出的顺序以及三元组内部的顺序均不影响答案正确性。

**Example 2:**

```text
Input: nums = [0,1,1]
Output: []
```

**Explanation:** 唯一可能的三元组的和不等于 0，故返回空数组。

**Example 3:**

```text
Input: nums = [0,0,0]
Output: [[0,0,0]]
```

**Explanation:** 唯一可能的三元组 `[0,0,0]` 的和为 0，故返回该三元组。

**约束条件**

- `3 <= nums.length <= 3000`
- `-10^5 <= nums[i] <= 10^5`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是把所有可能的三元组都枚举一遍，然后检查它们的和是否为 0。  
- **枚举方式**：用三层循环，外层固定 `i`，中层固定 `j`，内层固定 `k`，保证 `i < j < k`（相当于从左到右依次挑三个不同的位置）。  
- **数据结构**：只需要一个普通的列表 `nums`，不需要额外的结构。可以把它想象成一排排水果，我们要挑出三种不同的水果放进篮子里，看看重量总和是否恰好为 0。  
- **正确性**：因为我们遍历了 **所有** 满足下标不相同的三元组，若存在满足条件的组合，一定会被找到；若不存在，遍历结束后自然返回空集合。

#### 代码（Python）

```python
from typing import List

def three_sum_brute(nums: List[int]) -> List[List[int]]:
    n = len(nums)
    res = []                       # 用来存放满足条件的三元组
    for i in range(n):             # 第一个数的下标 i
        for j in range(i + 1, n):  # 第二个数的下标 j，保证 j > i
            for k in range(j + 1, n):  # 第三个数的下标 k，保证 k > j
                if nums[i] + nums[j] + nums[k] == 0:   # 和为 0 就是答案
                    triplet = sorted([nums[i], nums[j], nums[k]])  # 为了去重，把每个三元组排序
                    if triplet not in res:   # 这里手动检查是否已经出现过
                        res.append(triplet)
    return res
```

> **关键注释**  
> - `sorted([...])`：把三元组内部升序，方便后面比较是否重复（相当于把水果摆成统一的顺序，才能判断是否是同一篮子）。  
> - `if triplet not in res`：线性检查已有结果，这一步也是 **O(N)**，但在暴力解里已经够慢了。

#### 复杂度

- **时间复杂度**：`O(n³)`  
  - 三层循环，每层最多遍历 `n` 次，整体是 `n × n × n`。如果把 `n` 想成「学生人数」，`n³` 就像让每个学生和其他每两个学生都一起做实验，显然会非常耗时。  
- **空间复杂度**：`O(1)`（不计返回结果的空间）  
  - 只用了常数个额外变量；返回的结果集合本身不算在额外空间里。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **三层循环**——每次都要遍历整个数组，导致 `O(n³)`。  
我们可以把问题拆成「先固定一个数，再在剩下的数里找两数之和为 `-fixed`」的 **Two‑Sum** 子问题。Two‑Sum 有一种经典的 **双指针**（two‑pointers）技巧，前提是数组已经 **排序**。排序后，两个指针分别指向数组的最左和最右，根据当前和与目标值的大小关系移动指针，整个过程只需要一次线性扫描 `O(n)`。

下面一步步推导：

1. **先排序**  
   - 排序后相同的数会相邻，方便后面去重。可以把数组想象成排好序的书架，左边的书更薄，右边的书更厚，方便我们快速定位两本书的厚度和是否等于目标。  
2. **遍历固定第一个数** (`i`)  
   - 对每个位置 `i`，把 `nums[i]` 当作第一个数 `a`。此时我们要找的是 `b + c = -a`。  
   - 为了避免重复答案，**如果当前的 `a` 与前一个相同，就跳过**（因为相同的 `a` 会产生相同的组合）。  
3. **双指针找剩余两数**  
   - 设 `left = i + 1`（紧跟在 `a` 之后），`right = n - 1`（数组最右端）。  
   - 计算 `current_sum = nums[left] + nums[right]`：  
     - 若 `current_sum == -a`，找到了一个合法三元组 `[a, nums[left], nums[right]]`，加入结果并同时移动 `left`、`right`，**并跳过所有与当前值相同的元素**，防止重复。  
     - 若 `current_sum < -a`，说明左指针指向的数太小，需要把 `left` 向右移一位，使和增大。  
     - 若 `current_sum > -a`，说明右指针指向的数太大，需要把 `right` 向左移一位，使和减小。  
   - 循环结束条件是 `left >= right`。  

整个过程的时间复杂度是 `O(n log n)`（排序） + `O(n²)`（外层遍历 + 内层双指针），比暴力的 `O(n³)` 快了很多。

#### 代码（Python）

```python
from typing import List

def three_sum(nums: List[int]) -> List[List[int]]:
    nums.sort()                     # 1. 先把数组升序排列
    n = len(nums)
    res = []                        # 用来存放所有不重复的三元组

    for i in range(n - 2):         # 2. 固定第一个数的位置 i，最多到 n-3
        # 跳过相同的第一个数，防止产生重复三元组
        if i > 0 and nums[i] == nums[i - 1]:
            continue

        target = -nums[i]           # 目标值：后面两数之和要等于 -nums[i]
        left, right = i + 1, n - 1  # 3. 双指针初始化

        while left < right:
            cur_sum = nums[left] + nums[right]

            if cur_sum == target:   # 找到一组合法解
                res.append([nums[i], nums[left], nums[right]])

                # 移动 left，跳过所有与当前值相同的元素
                left_val = nums[left]
                while left < right and nums[left] == left_val:
                    left += 1

                # 同理，移动 right，跳过重复值
                right_val = nums[right]
                while left < right and nums[right] == right_val:
                    right -= 1

            elif cur_sum < target:  # 和太小，需要把左指针右移让和增大
                left += 1
            else:                    # 和太大，需要把右指针左移让和减小
                right -= 1

    return res
```

> **关键注释**  
> - `nums.sort()`：相当于把散乱的拼图块排好顺序，后面才能快速找到合适的两块。  
> - `if i > 0 and nums[i] == nums[i-1]: continue`：防止「同样的第一块」产生重复解。  
> - `while left < right and nums[left] == left_val: left += 1`：一次性跳过所有相同的左指针值，确保每种组合只出现一次。  

#### 复杂度

- **时间复杂度**：`O(n²)`  
  - 排序 `O(n log n)` 已经被 `O(n²)` 所掩盖。外层遍历 `n` 次，内层双指针在整个数组上最多移动 `n` 步（每次左或右指针只前进/后退一次），所以总体是 `n × n = n²`。可以把它想象成：我们先把学生排好座位（一次性），随后每位学生只需要和左边或右边的同学比较一次，总比较次数是二次方级别。  
- **空间复杂度**：`O(1)`（不计返回结果的空间）  
  - 除了排序本身（Python 的原地排序），只用了常数个指针和临时变量。

## 心得

- **核心技巧**：先排序 + 双指针遍历，是解决 “固定一个数，剩下求两数之和” 的常用套路。  
- **适用题型**：  
  1. **2Sum（两数之和）**：在已排序数组中使用双指针找目标值。  
  2. **4Sum（四数之和）**：在 3Sum 的基础上再套一层循环，仍然使用双指针。  
  3. **Closest 3Sum**（求最接近目标的三数和）：同样先排序，再用双指针移动来逼近目标。  
- **一句话总结**：**“先把乱序变有序，再用左右夹逼的方式一次遍历找配对”，是消除暴力三层循环的钥匙。**

## 反思

- **第一反应**：直接写三层循环枚举所有三元组，想到“暴力”但感觉会超时。  
- **最容易踩的坑**：  
  - **去重**：忘记在固定第一个数或移动指针时跳过相同的值，会导致大量重复答案。  
  - **边界条件**：数组长度小于 3 时直接返回空列表；`while left < right` 必须写对，防止指针交叉导致无限循环。  
  - **整数范围**：虽然 Python 整数不溢出，但在其他语言里要注意可能的整数溢出。  
- **下次类似题的第一步**：  
  - **先排序**，然后 **固定一个元素**，把剩下的子问题转化为 **Two‑Sum**，再用 **双指针**（或哈希表）快速求解。这样思路清晰、实现简洁且效率高。
