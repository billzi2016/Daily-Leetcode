## 题目（英文原版）

**Description**

Given an array nums with n objects colored red, white, or blue, sort them in-place so that objects of the same color are adjacent, with the colors in the order red, white, and blue.
We will use the integers 0, 1, and 2 to represent the color red, white, and blue, respectively.
You must solve this problem without using the library's sort function.
Follow up: Could you come up with a one-pass algorithm using only constant extra space?

**Examples**

**Example 1:**

```
Input: nums = [2,0,2,1,1,0]
Output: [0,0,1,1,2,2]
```

**Example 2:**

```
Input: nums = [2,0,1]
Output: [0,1,2]
```

**Constraints**

- n == nums.length
- 1 <= n <= 300
- nums[i] is either 0, 1, or 2.

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  
最直接的想法是 **计数排序**（Counting Sort）。  
把数组里出现的 `0、1、2` 各自出现的次数统计出来，然后再把统计结果按顺序写回原数组。  

- **使用的数据结构**：  
  - 一个长度为 3 的普通列表 `cnt = [0,0,0]`，相当于一本“小字典”。键（`0/1/2`）是颜色，值是该颜色出现了几次。就像查字典时，看到词条就知道在哪一页。  

- **为什么正确**：  
  - 先统计每种颜色出现的次数，得到 `cnt[0]`、`cnt[1]`、`cnt[2]`。  
  - 再把数组的前 `cnt[0]` 位填成 `0`，接下来 `cnt[1]` 位填成 `1`，最后的 `cnt[2]` 位填成 `2`。  
  - 这样所有相同颜色必然相邻，且顺序是 `0 → 1 → 2`，恰好满足题目要求。  

- **时间/空间复杂度**：  
  - **时间**：我们遍历数组两次——一次计数，一次改写。设数组长度为 `n`，则总共做了 `2·n` 次基本操作，用大写字母 `O` 表示为 **O(n)**。  
    - 这里的 `O(n)` 可以理解为“随着元素个数线性增长”。如果 `n` 从 10 增加到 100，运行时间大约会增加 10 倍。  
  - **空间**：只用了常数大小的 `cnt`（长度固定为 3），不随 `n` 增长，用 **O(1)** 表示，意思是“几乎不占额外内存”。  

#### 代码（Python）  

```python
def sortColors(nums):
    """
    计数排序：先统计每个颜色出现的次数，再依次覆盖原数组。
    """
    # 1. 统计 0、1、2 的个数，cnt[0] 对应红色，cnt[1] 对应白色，cnt[2] 对应蓝色
    cnt = [0, 0, 0]                # 类似查字典，key 是颜色，value 是出现次数
    for v in nums:                 # 第一次遍历 O(n)
        cnt[v] += 1                # 把对应颜色的计数加一

    # 2. 按顺序把统计结果写回原数组
    index = 0                       # 当前要写入的位置
    for color, c in enumerate(cnt):  # enumerate 同时得到颜色和值
        for _ in range(c):           # 把该颜色写 c 次
            nums[index] = color
            index += 1               # 移动写指针
    # 第二次遍历同样是 O(n)，总体仍是 O(n)
```

#### 复杂度  

- **时间复杂度**：`O(n)` — 随着数组长度线性增长，遍历两遍即可完成。  
- **空间复杂度**：`O(1)` — 只用了固定大小的计数数组 `cnt[3]`，不随 `n` 增大。

### 2. 最优解  

#### 思路  
计数排序已经是 `O(n)`，但它需要 **两遍**（先计数再写回）。  
如果我们在 **一次遍历** 中就把颜色排好，那就更贴近题目“**一遍**、**常数空间**”的要求。  

- **慢在哪里**：  
  - 两遍遍历虽然时间仍是线性，但每次都要完整遍历数组，常数因子稍大。  
  - 更关键的是，计数排序没有利用“颜色只有三种且顺序已知”的特性。  

- **优化思路**：  
  1. 设想有三个指针：  
     - `p0`：指向已排好 `0`（红色）的最左侧空位的下一个位置。  
     - `p2`：指向已排好 `2`（蓝色）的最右侧空位的前一个位置。  
     - `i`：当前遍历的下标。  
  2. 从左到右扫描数组，**只要遇到 0，就把它和 `p0` 位置的元素交换**，随后 `p0`、`i` 都右移。  
  3. **遇到 2 时**，把它和 `p2` 位置的元素交换，`p2` 左移；但交换后新来到 `i` 位置的元素可能是 0、1、2 任意一种，需要再次检查（因此 `i` 不立即右移）。  
  4. **遇到 1 时**，直接右移 `i`。  

  这就是经典的 **荷兰国旗（Dutch National Flag）算法**。  
  - `p0` 像是 “红色的门”，左边全是红色。  
  - `p2` 像是 “蓝色的门”，右边全是蓝色。  
  - `i` 是 “检查员”，从左到右把每件衣服放进正确的门后继续前进。  

- **核心数据结构**：只用了三个整数指针，全部在原数组上原地操作。  

#### 代码（Python）  

```python
def sortColors(nums):
    """
    荷兰国旗算法：一次遍历完成原地排序。
    """
    p0, i = 0, 0                     # p0：下一个放 0 的位置，i：当前检查位置
    p2 = len(nums) - 1               # p2：下一个放 2 的位置（从右向左）

    while i <= p2:                   # 只要 i 没超过 p2，都还有未处理的元素
        if nums[i] == 0:             # 当前是红色，需要放到左边
            nums[i], nums[p0] = nums[p0], nums[i]   # 交换 i 与 p0 位置的元素
            p0 += 1                  # 左边红色区间扩大
            i += 1                   # 检查下一个位置
        elif nums[i] == 2:           # 当前是蓝色，需要放到右边
            nums[i], nums[p2] = nums[p2], nums[i]   # 交换 i 与 p2 位置的元素
            p2 -= 1                  # 右边蓝色区间扩大
            # 注意：交换后 nums[i] 可能是 0、1、2，需要再次判断，故不 i+=1
        else:                         # 当前是白色，已经在中间，直接前进
            i += 1
```

#### 复杂度  

- **时间复杂度**：`O(n)` — 只遍历一次，每个元素最多被交换两次（一次与 `p0`，一次与 `p2`），常数因子更小。  
- **空间复杂度**：`O(1)` — 只用了三个整数指针，额外空间恒定不变。

## 心得  

- **核心技巧**：**双指针（两端指针）** + **一次遍历原地交换**，即荷兰国旗问题。  
- **适用的题型**：  
  1. “颜色分类”类问题（如 **Sort Colors**、**Partition Array into Three Parts**）。  
  2. “把数组中小于/等于/大于某个值的元素分组” （如 **LeetCode 215. Kth Largest Element in an Array** 的快速选择思想）。  
  3. “原地分割 0/1/2/… 的序列” （如 **LeetCode 283. Move Zeroes** 只涉及 0 与非 0 的分区）。  
- **一句话总结解题钥匙**：**把数组划分成“左红‑中白‑右蓝”三段，用指针把错误颜色的元素“送进正确的门”。**

## 反思  

- **第一反应**：看到只有三种固定值，立刻想到计数排序，因为计数排序天然适合“值域小、种类固定”。  
- **最容易踩的坑**：  
  - 在双指针实现中，交换 `2` 后 **不要忘记不立即 `i++`**，因为新换来的元素可能仍然是 `0` 或 `2`，需要再次处理。  
  - 边界条件：当数组全部是同一种颜色时，指针 `p0`、`p2` 可能相等，循环仍需正常结束。  
- **下次类似题的第一步**：先判断**是否可以一次遍历完成**——如果元素种类很少且顺序已知，尝试**双指针/三指针原地分区**，而不是先计数后写回。
