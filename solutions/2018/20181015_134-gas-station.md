# #134. 加油站 / Gas Station

> 难度：中等 · 标签：Array、Greedy · [LeetCode 链接](https://leetcode.com/problems/gas-station/)

---

## 题目（英文原版）

**Description**

There are n gas stations along a circular route, where the amount of gas at the ith station is gas[i].
You have a car with an unlimited gas tank and it costs cost[i] of gas to travel from the ith station to its next (i + 1)th station. You begin the journey with an empty tank at one of the gas stations.
Given two integer arrays gas and cost, return the starting gas station's index if you can travel around the circuit once in the clockwise direction, otherwise return -1. If there exists a solution, it is guaranteed to be unique.

**Examples**

**Example 1:**

```
Input: gas = [1,2,3,4,5], cost = [3,4,5,1,2]
Output: 3
Explanation:
Start at station 3 (index 3) and fill up with 4 unit of gas. Your tank = 0 + 4 = 4
Travel to station 4. Your tank = 4 - 1 + 5 = 8
Travel to station 0. Your tank = 8 - 2 + 1 = 7
Travel to station 1. Your tank = 7 - 3 + 2 = 6
Travel to station 2. Your tank = 6 - 4 + 3 = 5
Travel to station 3. The cost is 5. Your gas is just enough to travel back to station 3.
Therefore, return 3 as the starting index.
```

**Example 2:**

```
Input: gas = [2,3,4], cost = [3,4,3]
Output: -1
Explanation:
You can't start at station 0 or 1, as there is not enough gas to travel to the next station.
Let's start at station 2 and fill up with 4 unit of gas. Your tank = 0 + 4 = 4
Travel to station 0. Your tank = 4 - 3 + 2 = 3
Travel to station 1. Your tank = 3 - 3 + 3 = 3
You cannot travel back to station 2, as it requires 4 unit of gas but you only have 3.
Therefore, you can't travel around the circuit once no matter where you start.
```

**Constraints**

- n == gas.length == cost.length
- 1 <= n <= 105
- 0 <= gas[i], cost[i] <= 104
- The input is generated such that the answer is unique.

## 题目（中文翻译）

存在 **n** 个加油站沿着一条环形路线，第 **i** 个加油站的可加油量为 `gas[i]`。  
你拥有一辆油箱容量无限的汽车，从第 **i** 个加油站前往下一个（第 **i+1** 个）加油站需要消耗 `cost[i]` 单位的油。你将在某个加油站开始旅程，且初始油箱为空。  

给定整数数组 `gas` 和 `cost`，如果可以顺时针绕环路行驶一圈，则返回起始加油站的下标；否则返回 `-1`。若存在解，答案唯一。

**示例 1**  

**输入**: `gas = [1,2,3,4,5]`, `cost = [3,4,5,1,2]`  
**输出**: `3`  
**解释**:  
- 从下标为 `3` 的加油站加满 `4` 单位的油。此时油箱 = `0 + 4 = 4`。  
- 前往下标 `4` 的加油站。油箱 = `4 - 1 + 5 = 8`。  
- 前往下标 `0` 的加油站。油箱 = `8 - 2 + 1 = 7`。  
- 前往下标 `1` 的加油站。油箱 = `7 - 3 + 2 = 6`。  
- 前往下标 `2` 的加油站。油箱 = `6 - 4 + 3 = 5`。  
- 回到下标 `3`。所需油量为 `5`，恰好用完。  
因此返回 `3` 作为起始下标。

**示例 2**  

**输入**: `gas = [2,3,4]`, `cost = [3,4,3]`  
**输出**: `-1`  
**解释**:  
- 不能从下标 `0` 或 `1` 开始，因为油量不足以到达下一个加油站。  
- 从下标 `2` 开始，加满 `4` 单位的油。油箱 = `0 + 4 = 4`。  
- 前往下标 `0`：油箱 = `4 - 3 + 2 = 3`。  
- 前往下标 `1`：油箱 = `3 - 3 + 3 = 3`。  
- 无法返回下标 `2`，因为需要 `4` 单位油而只有 `3`。  
所以无论从哪个加油站出发，都无法完整绕行一圈。

**约束条件**  

- `n == gas.length == cost.length`  
- `1 <= n <= 10^5`  
- `0 <= gas[i], cost[i] <= 10^4`  
- 输入保证答案唯一。

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：把每一个加油站都当成可能的起点，**从它出发**，把油箱里的油一次次加上 `gas[i]` 再减去去下一站的 `cost[i]`，看能不能走完整个环。  

- **使用的数据结构**：  
  - 两个列表 `gas`、`cost`（相当于我们手里已经准备好的“加油站信息表”）。  
  - 一个变量 `tank` 用来记录当前油箱里剩余的油量。可以把 `tank` 想象成汽车仪表盘上的油量指针。  

- **为什么这个方法一定能判断对错**：  
  对每一个可能的起点，模拟真实的行驶过程。如果在某一步油量变成负数，说明从这个起点出发根本走不完；如果走完整个环，说明这个起点是可行的。因为我们把**所有起点**都尝试了一遍，必然能找到唯一的解（如果有的话）。

- **时间/空间复杂度的大白话**：  
  - 时间复杂度写作 **O(n²)**，意思是如果有 `n` 个加油站，最坏情况下我们要做 `n` 次循环，每次循环里又要遍历 `n` 个站点，类似“在 1000 张纸里找 1000 次”。  
  - 空间复杂度是 **O(1)**，只用了几个额外变量，和 `n` 的大小无关。

#### 代码（Python）

```python
def can_complete_from(start: int, gas, cost) -> bool:
    """
    模拟从 start 出发能否走完一圈
    """
    tank = 0                     # 油箱初始为空
    n = len(gas)
    # 按顺时针方向遍历 n 次，使用取模实现环路
    for i in range(n):
        idx = (start + i) % n    # 当前访问的站点下标
        tank += gas[idx]         # 加油
        tank -= cost[idx]        # 开往下一站消耗的油
        if tank < 0:             # 油不够了，直接返回失败
            return False
    return True                   # 成功走完一圈

def brute_force(gas, cost):
    """
    暴力枚举每个起点，返回满足条件的下标或 -1
    """
    n = len(gas)
    for start in range(n):
        if can_complete_from(start, gas, cost):
            return start
    return -1
```

#### 复杂度  

- **时间复杂度**：O(n²) —— 每个起点最多遍历 n 次，n 个起点合计 n×n。  
- **空间复杂度**：O(1) —— 只用了常数个变量（`tank、n、i、idx`），不随输入规模增长。

### 2. 最优解  

#### 思路  

从暴力解我们可以看到 **瓶颈** 在于重复遍历同样的路段。事实上，如果从某个站点出发在途中油箱已经亏空了，那么**一定**不可能在之后的任何站点重新开始成功，因为：

- 从 **起点 A** 到 **亏空点 B**，总油量（`gas - cost` 的累计）为负。  
- 若我们把起点搬到 **B 的下一个站点 C**，相当于把 **A~B** 这段路的负油量从「起点」前面搬到了「起点」后面，导致新的起点 C 开始时的油箱仍然会在 **C~B** 这段路上出现负值，仍然走不完。  

因此，**一次线性扫描** 就能找出唯一的起点：

1. 先检查全局总油量是否足够：`sum(gas) >= sum(cost)`。如果不满足，根本不可能走完一圈，直接返回 `-1`。  
2. 在一次遍历中维护两个变量：  
   - `tank`：从当前候选起点累计的油量（如果 `tank` 途中跌到负数，说明该起点不可行）。  
   - `start`：当前候选起点的下标。  
   当 `tank` 为负时，说明 **从 `start` 到当前位置** 这段路不行，直接把 `start` 移到下一个站点 `i+1`，并把 `tank` 重新置为 0，继续向后遍历。  
3. 循环结束后，如果全局油量足够，则 `start` 必然是唯一解。  

> **类比**：把每个站点的“净油量”（`gas[i] - cost[i]`）想象成一条山路的高低起伏。我们从某点出发，沿路累计海拔。如果累计海拔一度跌到谷底以下（负数），说明这段路从起点往下走不行；于是我们把起点搬到谷底的下一步，重新开始爬山。最终只会留下最高的起点——唯一能环绕一周的山顶。

#### 代码（Python）

```python
def can_complete_circuit(gas, cost):
    """
    贪心 O(n) 解法
    返回能够环绕一周的起点下标，若不存在返回 -1
    """
    total_tank = 0   # 全局油量差，检查整体可行性
    tank = 0         # 当前候选起点的累计油量
    start = 0        # 候选起点下标

    for i in range(len(gas)):
        diff = gas[i] - cost[i]   # 第 i 站的净油量
        total_tank += diff
        tank += diff

        # 若累计油量跌到负数，说明从 start 到 i 这段路走不通
        if tank < 0:
            # 把起点搬到 i+1，重新开始累计
            start = i + 1
            tank = 0   # 重置为 0，表示从新起点重新装油

    # 如果全局油量不足，任何起点都不行
    return start if total_tank >= 0 else -1
```

#### 复杂度  

- **时间复杂度**：O(n) —— 只遍历了一遍数组，`n` 是站点数。相较于暴力的 O(n²)，快了 **n 倍**，即使是 10⁵ 个站点也能在毫秒级完成。  
- **空间复杂度**：O(1) —— 只用了常数个变量（`total_tank、tank、start、i、diff`），不随 `n` 增长。

## 心得  

- **核心技巧**：一次遍历的**贪心**思路——当累计油量出现负数时，直接把起点跳到下一个位置。  
- **适用的题型**：  
  1. “环形数组/循环路径”类问题（如 LeetCode 1344 – `Number of Sub-arrays With Odd Sum` 的环形变形）。  
  2. “累计和不为负”类问题（如 LeetCode 1238 – `Circular Permutation` 的变形）。  
  3. “全局可行性 + 局部失效”模式的调度/资源分配题（如 LeetCode 55 – `Jump Game`）。  
- **一句话总结解题钥匙**：**只要整体资源足够，第一次累计出现负值的区间就一定不是起点，把起点直接搬到负值后面即可**。

## 反思  

- **第一反应**：直接想要把每个站点都尝试一遍，写出暴力模拟代码。  
- **最容易踩的坑**：  
  - 忘记先判断 `sum(gas) >= sum(cost)`，导致在全局不可能的情况下仍返回错误的起点。  
  - 在跳过失效区间时没有把 `tank` 重新置零，导致后面的累计被错误的负值干扰。  
  - 边界条件：当所有站点都恰好相等（`gas[i] == cost[i]`）时，答案应该是 `0`，代码必须能处理 `tank` 恰好为 `0` 的情况。  
- **下次遇到同类题**：第一步先检查**整体资源是否足够**，再在一次遍历中**用贪心把失效区间一次性剔除**。这样可以直接得到 O(n) 的最优解。
