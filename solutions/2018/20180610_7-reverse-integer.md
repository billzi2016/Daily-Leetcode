# #7. 逆转整数 / Reverse Integer

> 难度：中等 · 标签：Math · [LeetCode 链接](https://leetcode.com/problems/reverse-integer/)

---

## 题目（英文原版）

**Description**

Given a signed 32-bit integer x, return x with its digits reversed. If reversing x causes the value to go outside the signed 32-bit integer range [-231, 231 - 1], then return 0.
Assume the environment does not allow you to store 64-bit integers (signed or unsigned).

**Examples**

**Example 1:**

```
Input: x = 123
Output: 321
```

**Example 2:**

```
Input: x = -123
Output: -321
```

**Example 3:**

```
Input: x = 120
Output: 21
```

**Constraints**

- -231 <= x <= 231 - 1

---

## 题目（中文翻译）

**题目描述**  
给定一个有符号 32 位整数（signed 32-bit integer）`x`，返回其各位数字逆序后的结果。如果逆序操作导致数值超出有符号 32 位整数的取值范围 `[-2^31, 2^31 - 1]`，则返回 `0`。  
假设运行环境不允许使用 64 位整数（有符号或无符号）。

**示例**  

- 示例 1  
  **输入**: `x = 123`  
  **输出**: `321`  

- 示例 2  
  **输入**: `x = -123`  
  **输出**: `-321`  

- 示例 3  
  **输入**: `x = 120`  
  **输出**: `21`  

**约束条件**  
- `-2^31 <= x <= 2^31 - 1`   (即 `-2147483648` 到 `2147483647`)

---

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把整数当成**字符序列**来处理，就像把数字写在纸上、把纸翻过去一样。具体步骤如下：

1. **把整数转成字符串**  
   - 正数直接 `str(x)`，负数先记住符号（`-`），再把绝对值转成字符串。  
   - 把字符串想象成一本字典，里面每个字符就是我们要翻转的“单词”。

2. **把字符串反转**  
   - Python 的切片 `s[::-1]` 能一次性把字符顺序倒过来，就像把纸往后翻一样。

3. **把反转后的字符串再转回整数**  
   - 再加上之前记住的符号，得到最终结果。

4. **检查是否超出 32 位有符号整数范围**  
   - 题目要求如果结果不在 `[-2**31, 2**31 - 1]` 之间，就返回 `0`。这一步相当于“检查字典里有没有找不到的页码”。

> **为什么这个方法正确？**  
> - 只要我们把每一位数字完整地搬运（即把字符顺序倒过来），得到的就是题目要求的“逆序整数”。  
> - 只要在最后一步检查范围，就能满足 “如果溢出返回 0” 的要求。

#### 代码（Python）

```python
def reverse(x: int) -> int:
    # 1️⃣ 记录原始符号
    sign = -1 if x < 0 else 1

    # 2️⃣ 把整数转成字符串（只处理正数部分）
    s = str(abs(x))

    # 3️⃣ 反转字符串
    rev_s = s[::-1]                     # 切片一步完成翻转

    # 4️⃣ 转回整数并恢复符号
    rev_int = sign * int(rev_s)

    # 5️⃣ 检查是否超出 32 位有符号整数范围
    if rev_int < -2**31 or rev_int > 2**31 - 1:
        return 0
    return rev_int
```

#### 复杂度

- **时间复杂度：O(k)**  
  `k` 是整数 `x` 的位数（即字符长度），因为我们遍历了一遍字符来做翻转。  
  对于 32 位整数，`k ≤ 10`，所以实际运行时间几乎是常数。

- **空间复杂度：O(k)**  
  需要额外的字符串来存放原始数字和翻转后的数字，大小同样与位数 `k` 成正比。  
  对于 32 位整数，这个空间最多也只有十几个字符，属于常数级别。

### 2. 最优解

#### 思路  

虽然上面的“字符串法”已经可以 AC，但它使用了 **额外的字符串空间**，在严格限制只能使用 32 位整数的环境下（题目暗示），我们应该**直接用数学运算**来完成翻转，避免任何字符串或大整数的帮助。  
从暴力解的瓶颈可以看到：

- **瓶颈 1：字符串的创建和切片**  
  这一步需要额外的内存，而且在某些语言里会触发 64 位整数的隐式转换。

- **瓶颈 2：一次性把所有位都取出来**  
  实际上我们只需要**逐位取出**，把当前的结果 *左移一位*（乘以 10），再加上新取出的位。

**核心技巧：** 使用 **取模 `%`** 与 **整除 `//`** 来一次取出最低位，然后把已经翻转好的部分乘以 10 再加上这位。这样我们只在 **整数范围内** 完成所有操作。

步骤如下：

1. 记录符号 `sign`（正数为 `1`，负数为 `-1`），并把 `x` 转为正数 `abs(x)` 方便处理。
2. 初始化 `rev = 0`（已翻转好的数字）。
3. 循环：  
   - `pop = x % 10` 取出最低位（相当于从右往左“摘取”一颗糖）。  
   - `x //= 10` 把最低位去掉，准备处理下一位。  
   - 在把 `pop` 加入 `rev` 前，先检查 **如果再乘以 10 会溢出**（即 `rev > INT_MAX // 10` 或者等于时 `pop > 7`，因为 2³¹‑1 的最后一位是 7）。如果会溢出直接返回 `0`。  
   - `rev = rev * 10 + pop` 把新摘取的位放到左边，完成一次“翻转”。
4. 循环结束后，`rev` 就是正数形式的翻转结果，乘回符号 `sign`。
5. 再次检查一次范围（防止负数特殊情况），返回 `rev * sign` 或 `0`。

> **为什么这样更好？**  
> - **不需要任何额外的字符串或数组**，只用常数个整数变量，完全符合 “不能使用 64 位整数” 的限制。  
> - 每一步只做 **O(1)** 的算术运算，循环次数等于位数 `k`，时间仍是 **O(k)**，但空间降到了 **O(1)**（常数级）。

#### 代码（Python）

```python
def reverse(x: int) -> int:
    INT_MAX = 2**31 - 1      # 2147483647
    INT_MIN = -2**31         # -2147483648

    sign = -1 if x < 0 else 1
    x = abs(x)               # 只处理正数部分

    rev = 0
    while x != 0:
        pop = x % 10         # 取出最低位
        x //= 10             # 去掉最低位

        # 检查如果再乘以 10 加 pop 是否会超出 32 位范围
        # 这里用 INT_MAX // 10 进行预判
        if rev > INT_MAX // 10 or (rev == INT_MAX // 10 and pop > 7):
            return 0

        rev = rev * 10 + pop  # 把新位加到左边

    rev *= sign               # 恢复原始符号

    # 最后一次安全检查（负数情况下的边界）
    if rev < INT_MIN or rev > INT_MAX:
        return 0
    return rev
```

#### 复杂度

- **时间复杂度：O(k)**  
  `k` 为整数的位数（最多 10 位），每次循环只做常数时间的算术运算。  
  与暴力解的时间相同，但因为没有字符串处理，实际运行会更快。

- **空间复杂度：O(1)**  
  只使用了 `rev、pop、x、sign` 四个整数变量，空间不随输入大小增长，是真正的常数级。

## 心得

- **核心技巧**：逐位弹出（%10）与累积（*10 + pop）实现整数逆序，同时使用边界预判避免溢出。  
- **适用的题型**  
  1. **整数翻转**（本题）。  
  2. **判断回文数**（把数字反转后比较是否相等）。  
  3. **整数拆分/合并**（比如把两个数字交叉拼接）。  
- **一句话总结**：`取模 + 整除 + 预判溢出` 是逆序整数的“钥匙”。

---

## 反思

- **第一反应**：把数字变成字符串，直接倒序再转回来。这个思路最直观，却用了额外的空间。
- **最容易踩的坑**  
  - **溢出检测**：直接翻转后再检查会因为中间结果已经超过 32 位而导致错误，需要在累积前提前判断。  
  - **负数的最后一位**：`-2147483648` 的绝对值 `2147483648` 已经超过上限，需要在返回前再次检查。  
  - **特殊输入 0**：循环体不会执行，直接返回 0 即可。
- **下次第一步**：先思考“能否只用整数运算完成？”——如果可以，就立刻构造 **逐位弹出 + 累积** 的框架，再考虑溢出预判。这样往往能直接得到最优解。
