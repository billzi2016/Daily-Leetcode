## 题目（英文原版）

**Description**

You are given an array of strings tokens that represents an arithmetic expression in a Reverse Polish Notation.
Evaluate the expression. Return an integer that represents the value of the expression.
Note that:

**Examples**

**Example 1:**

```
Input: tokens = ["2","1","+","3","*"]
Output: 9
Explanation: ((2 + 1) * 3) = 9
```

**Example 2:**

```
Input: tokens = ["4","13","5","/","+"]
Output: 6
Explanation: (4 + (13 / 5)) = 6
```

**Example 3:**

```
Input: tokens = ["10","6","9","3","+","-11","*","/","*","17","+","5","+"]
Output: 22
Explanation: ((10 * (6 / ((9 + 3) * -11))) + 17) + 5
= ((10 * (6 / (12 * -11))) + 17) + 5
= ((10 * (6 / -132)) + 17) + 5
= ((10 * 0) + 17) + 5
= (0 + 17) + 5
= 17 + 5
= 22
```

**Constraints**

- 1 <= tokens.length <= 104
- tokens[i] is either an operator: "+", "-", "*", or "/", or an integer in the range [-200, 200].

## 题目（中文翻译）

给定一个字符串数组 `tokens`，其中每个元素表示逆波兰表示法（Reverse Polish Notation）中的一个运算符或操作数。请计算该表达式的值，并返回一个整数作为结果。

**注意**：  
- 运算符仅包括 `"+"`、`"-"`、`"*"`、`"/"` 四种，除法采用整数除法，结果只保留整数部分，向零截断。  
- 被除数为负数时，除法的行为同 Java/C++/Python 中的整数除法，即 `int(a / b)`。  

### 示例

**示例 1**  
输入: `tokens = ["2","1","+","3","*"]`  
输出: `9`  
解释: `((2 + 1) * 3) = 9`

**示例 2**  
输入: `tokens = ["4","13","5","/","+"]`  
输出: `6`  
解释: `(4 + (13 / 5)) = 6`

**示例 3**  
输入: `tokens = ["10","6","9","3","+","-11","*","/","*","17","+","5","+"]`  
输出: `22`  
解释:  
```
((10 * (6 / ((9 + 3) * -11))) + 17) + 5
= ((10 * (6 / (12 * -11))) + 17) + 5
= ((10 * (6 / -132)) + 17) + 5
= ((10 * 0) + 17) + 5
= (0 + 17) + 5
= 17 + 5
= 22
```

### 约束条件

- `1 <= tokens.length <= 10^4`
- `tokens[i]` 要么是运算符 `"+"`、`"-"`、`"*"`、`"/"`，要么是范围在 `[-200, 200]` 之间的整数。

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  

最直接的想法是：**从左到右遍历表达式，每次遇到运算符就把它左边最近的两个数算出来，再把结果放回原来的位置**。  
可以把 `tokens` 看成一行排好的卡片，运算符就像“老师”让你把左边的两张“数字卡”拿出来算，算完后把新卡（结果）放回原来的位置，继续往后找下一个老师。

实现时可以把 `tokens` 当作列表，循环遍历：

1. 找到第一个运算符的位置 `i`。  
2. 取出 `i-2`、`i-1` 两个数字，算出 `result = a op b`（注意除法要向零截断）。  
3. 用 `result` 替换掉这三个元素：`tokens = tokens[:i-2] + [result] + tokens[i+1:]`。  
4. 重复上述过程，直到列表里只剩一个元素——答案。

这种方法之所以**正确**，是因为逆波兰表达式的计算规则恰好是“**每遇到一个运算符，就把它左边最近的两个操作数合并**”。只要我们始终按照这个规则把子表达式折叠成一个数，最终必然得到整个表达式的值。

**时间/空间分析（大白话）**  
- 每次折叠需要 **遍历一次列表找到运算符**（最坏 O(n)），而折叠后列表长度会减 2。  
- 折叠大约会进行 `n/2` 次（因为每次去掉两个数字），所以总时间是 `O(n) * O(n) = O(n²)`。  
- 我们只用到原来的列表和几个临时变量，空间是 `O(1)`（不计输入本身）。

#### 代码（Python）

```python
def evalRPN_bruteforce(tokens):
    """
    暴力版：每次扫描找到第一个运算符，直接在原列表上折叠。
    """
    # 辅助函数：执行基本的四则运算，除法向零截断（int(a / b) 正好满足）
    def calc(a, b, op):
        if op == '+':
            return a + b
        if op == '-':
            return a - b
        if op == '*':
            return a * b
        # '/' 在 Python 中会产生浮点数，使用 int() 实现向零取整
        return int(a / b)

    # 复制一份，避免修改原输入
    expr = tokens[:]

    # 当列表长度大于 1 时，说明还有未计算的运算符
    while len(expr) > 1:
        # 扫描寻找第一个运算符的位置
        for i, token in enumerate(expr):
            if token in '+-*/':               # 找到运算符
                # 取出左侧的两个数（注意顺序：a 为左边的数，b 为右边的数）
                a = int(expr[i - 2])
                b = int(expr[i - 1])
                # 计算结果
                res = calc(a, b, token)
                # 用结果替换掉 a、b、op 三个元素
                expr = expr[:i - 2] + [str(res)] + expr[i + 1:]
                break                         # 结束本次扫描，进入下一轮 while
    # 最后剩下的唯一元素即为答案
    return int(expr[0])
```

#### 复杂度  

- **时间复杂度：** `O(n²)`  
  - “n²”可以理解为：如果有 1000 个符号，最坏情况下会做大约 1000 × 500 ≈ 500 000 次基本操作，明显比线性算法慢很多。  
- **空间复杂度：** `O(1)`（不计输入本身）  
  - 只用了常数个临时变量，未额外开辟随输入大小增长的数组。

### 2. 最优解  

#### 思路  

从暴力解可以看到，**瓶颈在于每次都要重新遍历整个列表寻找运算符**。实际上，逆波兰表达式的计算顺序天然适合 **栈（Stack）** 这种“后进先出”的数据结构。  
可以把栈想象成 **一叠盘子**：每当遇到数字，就把它“压”到盘子堆顶；遇到运算符，就把堆顶的两盘子拿下来算，算完后把结果再压回去。这样我们只需要一次遍历，**不再回头找运算符**。

**核心概念——栈**  
- 栈就像一本“只允许在最上面翻页”的笔记本，**`push`** 把元素放在最上面，**`pop`** 把最上面的元素拿走。  
- 在逆波兰表达式里，**最近出现的两个数字一定是当前运算符要操作的对象**，这正好和栈的“后进先出”特性匹配。

**一步步推导**  
1. 初始化一个空栈。  
2. 从左到右遍历 `tokens`：  
   - 如果是数字 → `push(int(token))`。  
   - 如果是运算符 → `pop()` 两次得到右操作数 `b`（先弹出的）和左操作数 `a`（后弹出的），计算 `a op b`，再 `push(result)`。  
3. 遍历结束后，栈里唯一剩下的元素就是表达式的值。

**除法细节**  
- 题目要求除法**向零截断**（即 `-3 / 2 = -1`），Python 的整数除法 `//` 会向负无穷取整（`-3 // 2 = -2`），因此需要使用 `int(a / b)`，它会先得到浮点数再向零取整，恰好符合要求。

#### 代码（Python）

```python
def evalRPN(tokens):
    """
    最优解：使用栈一次遍历完成计算。
    """
    stack = []                     # 用列表模拟栈，append 为 push，pop 为 pop

    for token in tokens:
        if token not in '+-*/':    # 不是运算符，说明是数字
            stack.append(int(token))
        else:                     # 遇到运算符，弹出两个操作数进行计算
            b = stack.pop()       # 先弹出右操作数
            a = stack.pop()       # 再弹出左操作数

            if token == '+':
                res = a + b
            elif token == '-':
                res = a - b
            elif token == '*':
                res = a * b
            else:                  # token == '/'
                # Python 除法需要向零截断，用 int(a / b) 完成
                res = int(a / b)

            stack.append(res)      # 把本次运算的结果压回栈中

    # 最后栈里只剩一个元素，即为答案
    return stack[0]
```

#### 复杂度  

- **时间复杂度：** `O(n)`  
  - 只遍历一次 `tokens`（n 为符号个数），每个符号的处理都是常数时间操作。可以把 `O(n)` 想象成“如果有 1000 个符号，只需要大约 1000 次简单的加减乘除”。  
- **空间复杂度：** `O(n)`（最坏情况下栈里会存全部数字）  
  - 栈的大小最多等于表达式中数字的个数，约为 `n/2`，这算是线性空间。对比暴力解的 `O(1)`，这里多用了点额外空间，却把时间从 `n²` 降到了 `n`，在实际使用中更快更稳。

## 心得  

- **核心技巧**：使用**栈**一次遍历完成逆波兰表达式的求值。  
- **适用的题型**：  
  1. 计算后缀表达式（Reverse Polish Notation）  
  2. 判断表达式是否有效的括号匹配（LeetCode 20）  
  3. 中缀转后缀或前缀的表达式转换（经典的栈应用）  
- **一句话总结解题钥匙**：**“最近的两个数一定是当前运算符的操作数，栈天然保存这个顺序”。**

## 反思  

- **第一反应**：看到一串数字和运算符，我立刻想到“一边读一边用栈把数字压进去，遇到运算符就弹出计算”。

  - 输入只有一个数字时要直接返回，而不是误以为一定会有运算符。  
- **下次类似题的第一步**：**判断是否可以用栈来维护“最近出现的元素”，如果可以，立刻用栈实现一次遍历**。
