# #44. 通配符匹配 / Wildcard Matching

> 难度：困难 · 标签：String、Dynamic Programming、Greedy、Recursion · [LeetCode 链接](https://leetcode.com/problems/wildcard-matching/)

---

## 题目（英文原版）

**Description**

Given an input string (s) and a pattern (p), implement wildcard pattern matching with support for '?' and '*' where:
The matching should cover the entire input string (not partial).

**Examples**

**Example 1:**

```
Input: s = "aa", p = "a"
Output: false
Explanation: "a" does not match the entire string "aa".
```

**Example 2:**

```
Input: s = "aa", p = "*"
Output: true
Explanation: '*' matches any sequence.
```

**Example 3:**

```
Input: s = "cb", p = "?a"
Output: false
Explanation: '?' matches 'c', but the second letter is 'a', which does not match 'b'.
```

**Constraints**

- 0 <= s.length, p.length <= 2000
- s contains only lowercase English letters.
- p contains only lowercase English letters, '?' or '*'.

---

## 题目（中文翻译）

给定一个输入字符串 **s** 和一个模式字符串 **p**，实现支持通配符 `'?'` 和 `'*'` 的匹配算法，使得：

- `'?'` 能匹配任意单个字符（character）  
- `'*'` 能匹配任意长度（包括空）的字符序列（subsequence）  
- 匹配必须覆盖整个输入字符串 **s**，不能只匹配一部分  

## 示例

### 示例 1  
**输入**: `s = "aa", p = "a"`  
**输出**: `false`  
**解释**: `"a"` 只能匹配长度为 1 的字符串，无法匹配完整的 `"aa"`。

### 示例 2  
**输入**: `s = "aa", p = "*"`  
**输出**: `true`  
**解释**: `'*'` 可以匹配任意序列，包括 `"aa"`。

### 示例 3  
**输入**: `s = "cb", p = "?a"`  
**输出**: `false`  
**解释**: `'?'` 能匹配 `'c'`，但模式的第二个字符是 `'a'`，与字符串中的 `'b'` 不匹配。

## 约束

- `0 <= s.length, p.length <= 2000`
- `s` 仅由小写英文字母组成
- `p` 仅由小写英文字母、`'?'` 或 `'*'` 组成

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  

最直接的想法是 **穷举所有可能的匹配方式**。  
- 当模式字符是普通字母时，只能和字符串当前字符**一一对应**。  
- 当模式字符是 `'?'` 时，它可以匹配**任意单个字符**，相当于把 `'?'` 当成“通配的字母”。  
- 当模式字符是 `'*'` 时，它可以匹配**任意长度的子串**（包括空串）。这就像让 `'*'` “吃掉” 0、1、2… 个字符。  

于是我们可以用递归（或回溯）一步步尝试：  
1. 看当前模式字符是什么。  
2. 根据上面的规则，决定 **向前走几步**（字符数），并递归检查剩余的子问题。  
3. 如果所有字符都恰好用完，则匹配成功。  

> **类比**：想象你在读一本书（字符串 `s`），手里有一张带有通配符的“搜索卡”（模式 `p`）。每读到一页，你就决定这张卡上的当前符号是要匹配这页的文字，还是跳过几页再继续匹配。  

这个办法一定能得到正确答案，因为它遍历了**所有合法的匹配路径**。只要有一条路径能把两边的指针都走到末尾，就说明匹配成功。

#### 代码（Python）  

```python
def is_match_bruteforce(s: str, p: str) -> bool:
    # 递归实现，i 表示 s 的位置，j 表示 p 的位置
    def dfs(i: int, j: int) -> bool:
        # 1️⃣ 如果两边都已经遍历完，说明匹配成功
        if i == len(s) and j == len(p):
            return True
        # 2️⃣ 如果模式已经结束但字符串还有剩余，匹配失败
        if j == len(p):
            return False

        # 当前模式字符
        cur = p[j]

        # 处理普通字母或 '?'
        if cur != '*':
            # 必须保证字符串还有字符可供匹配
            if i < len(s) and (cur == s[i] or cur == '?'):
                # 两个指针都向前走一步
                return dfs(i + 1, j + 1)
            else:
                return False

        # 3️⃣ 处理 '*'：尝试让它匹配 0、1、2… 个字符
        # 先尝试 * 匹配空串（不消耗 s 的字符）
        if dfs(i, j + 1):
            return True
        # 再尝试 * 匹配至少一个字符
        # 只要还有剩余字符，就把 s 的指针往后移，继续让同一个 * 处理
        if i < len(s) and dfs(i + 1, j):
            return True

        return False

    return dfs(0, 0)
```

> **关键行解释**  
> - `if cur != '*':`：普通字符或 `'?'` 只能一次匹配一个字符。  
> - `if dfs(i, j + 1):`：`'*'` 先尝试匹配 **空串**（不消耗任何字符）。  
> - `if i < len(s) and dfs(i + 1, j):`：若仍有字符，`'*'` 再尝试匹配 **一个字符并继续留在同一个 `*`**，相当于让 `*` 吃掉更多字符。

#### 复杂度  

- **时间复杂度**：最坏情况是每遇到一个 `'*'` 都要分两条递归路径（匹配 0 或匹配 1），导致指数级别的搜索。若字符串长度为 `n`，模式长度为 `m`，时间复杂度约为 `O(2^{n+m})`。  
  - 用大白话说，就是“**可能要检查的情况会随字符数翻倍**”，所以当输入稍大时会非常慢。  
- **空间复杂度**：递归调用栈的深度最多是 `n + m`，即 `O(n + m)`，主要是保存函数调用的“记事本”。

### 2. 最优解  

#### 思路  

从暴力解我们可以看到，**主要的性能瓶颈**在于 `'*'` 的多分支搜索：每一次 `'*'` 都要尝试“吃掉 0、1、2… 个字符”，导致指数级别的回溯。  

要把这一步“穷举”变成**一次性算完**，可以利用**动态规划（DP）**的思想：  

- 把“已经匹配到哪儿了”这个状态抽象成 **二维表** `dp[i][j]`。  
- `dp[i][j] = True` 表示 **s 的前 i 个字符** 能够匹配 **p 的前 j 个字符**（下标从 0 开始，`i`、`j` 都是 “已经处理完的长度”）。  

从这个定义出发，我们可以写出状态转移：

| 情况 | 解释 | 转移公式 |
|------|------|----------|
| `p[j-1]` 为普通字母 | 必须和 `s[i-1]` 完全相等 | `dp[i][j] = dp[i-1][j-1] and s[i-1] == p[j-1]` |
| `p[j-1]` 为 `'?'` | 可以匹配任意单字符 | `dp[i][j] = dp[i-1][j-1]` |
| `p[j-1]` 为 `'*'` | `*` 有两种含义：<br>① 匹配空串 → `dp[i][j-1]` <br>② 匹配至少一个字符 → `dp[i-1][j]` | `dp[i][j] = dp[i][j-1] or dp[i-1][j]` |

**初始化**  
- `dp[0][0] = True`（空串能匹配空模式）。  
- 当 `i = 0`（即 s 为空串）时，只有连续的 `'*'` 能匹配：`dp[0][j] = dp[0][j-1]` 当 `p[j-1] == '*'`，否则为 `False`。  
- 当 `j = 0`（模式为空）时，只有 `i = 0` 能匹配，其他全部 `False`。  

这样，只要填完表格的最后一个格子 `dp[len(s)][len(p)]`，答案就出来了。

> **类比**：把 `dp` 表想象成一张“匹配地图”。横轴是模式走了多少步，纵轴是字符串走了多少步。每走一步，就看能否从左上角的已知格子 “跳” 到当前格子。`'*'` 的两种跳法（向右、向下）正好对应它的两种含义。

**空间优化**  
观察转移公式，只用到 **当前行** 和 **上一行**（`dp[i-1][*]`），所以可以把二维表压缩成 **一维滚动数组** `dp[j]`，从左到右更新即可。  

#### 代码（Python）  

```python
def is_match(s: str, p: str) -> bool:
    m, n = len(s), len(p)

    # dp[j] 表示匹配到 s 的前 i 个字符，p 的前 j 个字符（i 用外层循环控制）
    dp = [False] * (n + 1)
    dp[0] = True                     # 空串匹配空模式

    # 先处理模式前缀全是 '*' 的情况（i = 0 时）
    for j in range(1, n + 1):
        if p[j - 1] == '*':
            dp[j] = dp[j - 1]        # '*' 匹配空串，沿着左边的 True 传播
        else:
            dp[j] = False            # 只要出现非 '*'，后面的都无法匹配空串

    # 开始遍历字符串 s
    for i in range(1, m + 1):
        # new_dp 用来保存本轮 i 对应的状态，先把 dp[0] 设为 False（因为有字符时空模式不匹配）
        new_dp = [False] * (n + 1)

        for j in range(1, n + 1):
            if p[j - 1] == '*':
                # '*' 可以匹配空串 (new_dp[j-1]) 或者匹配 s[i-1] 并继续保持 '*' (dp[j])
                new_dp[j] = new_dp[j - 1] or dp[j]
            elif p[j - 1] == '?' or p[j - 1] == s[i - 1]:
                # 单字符匹配，沿对角线转移
                new_dp[j] = dp[j - 1]
            else:
                new_dp[j] = False     # 不匹配，保持 False

        dp = new_dp                  # 把本轮结果提交为下一轮的“上一行”

    return dp[n]                     # 最右下角的格子即为答案
```

> **关键行解释**  
> - `dp[j] = dp[j - 1]`（初始化阶段）: 当模式字符是 `'*'` 时，它可以“啥也不吃”，所以把左边的匹配结果向右传播。  
> - `new_dp[j] = new_dp[j - 1] or dp[j]`（处理 `'*'`）: <br>① `new_dp[j - 1]` 表示 `'*'` **匹配空串**（向右走一步）；<br>② `dp[j]` 表示 `'*'` **匹配当前字符并继续保持**（向下走一步）。两者只要有一个为真，当前位置就匹配成功。  
> - `new_dp[j] = dp[j - 1]`（处理普通字符或 `'?'`）: 只能从左上角对角线跳过来，说明前面的子串已经匹配成功，当前字符也相等（或是 `'?'`）。

#### 复杂度  

- **时间复杂度**：`O(m * n)`，其中 `m = len(s)`，`n = len(p)`。  
  - 用大白话说，就是“**我们只需要遍历一次二维表的每个格子**”，不再出现指数级的回溯。  
- **空间复杂度**：`O(n)`（一维滚动数组）。  
  - 只保存当前行和上一行的状态，节省了大约 `m` 倍的内存。相较于暴力解的递归栈，这更省空间。

## 心得  

- **核心技巧**：把“匹配过程”抽象为 **状态转移**，用动态规划一次性算完所有子问题。  
- **适用的题型**（类似思路）  
  1. 正则表达式匹配（LeetCode 10）——同样涉及 `'.'` 与 `'*'` 的匹配。  
  2. 最长公共子序列（LCS）——也是在两个序列之间做状态转移。  
  3. 编辑距离（LeetCode 72）——在字符增删改之间建立 DP 表。  
- **一句话总结解题钥匙**：**把每一步“我已经匹配到哪里了”记录下来，靠表格一步步推进，而不是回头再尝试。**

## 反思  

- **第一反应**：看到 `'*'` 能匹配任意长度，立刻想到“递归把所有长度都尝试”。这很自然，但很容易陷入指数爆炸。  
- **最容易踩的坑**  
  - 忽略 `'*'` 可以匹配 **空串**，导致初始化错误。  
  - DP 表的下标容易混淆（`i、j` 表示已处理的长度，而不是当前字符的下标）。  
  - 边界情况：空字符串或空模式、全部由 `'*'` 组成的模式，都必须单独验证。  
- **下次类似题的第一步**：先**写出 DP 状态定义**（`dp[i][j]` 含义），再根据模式字符的不同列出**转移公式**，这样可以直接跳过暴力搜索的“试错”阶段。
