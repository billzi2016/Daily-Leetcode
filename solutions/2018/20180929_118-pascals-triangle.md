## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**把每个数都算出来**，不管它们之间有没有关系。  
在数学里，帕斯卡三角第 `i` 行第 `j` 列的数等于组合数  

\[
C(i, j)=\frac{i!}{j!\,(i-j)!}
\]

所以我们可以：

1. 先写一个求阶乘的函数 `fact(n)`（`n! = n × (n-1) × … × 1`），  
   把它想象成“查字典”：要找 `n!`，就把 `n` 当成关键字（key），返回对应的值（value）。
2. 对每一行 `i`（从 `0` 开始），遍历列 `j = 0 … i`，用上面的公式算出 `C(i, j)`，放进当前行的列表里。  
3. 把每行列表加入最终结果 `res`。

**为什么正确？**  
组合数公式本身就定义了帕斯卡三角的每个元素，直接套用公式自然得到正确的值。

**时间/空间复杂度**（大白话）  
- **时间**：  
  - 计算一次阶乘 `fact(k)` 要循环 `k` 次。  
  - 对第 `i` 行，需要算 `i+1` 个组合数，每个组合数里会分别算 `i!、j!、(i-j)!`，最坏情况下大约是 `O(i)` 的时间。  
  - 把所有行加起来，就是 `O(0 + 1 + 2 + … + (n‑1)) ≈ O(n³)`（因为每行内部还有一次 `O(i)` 的阶乘计算）。  
  - 用生活化的比喻：如果你要给 `n` 堆书每本都重新装订一次，装订一本需要看它有多少页，整体工作量会随 `n` 的立方增长。  
- **空间**：  
  - 只用了常数级的临时变量（阶乘函数的递归栈/循环变量），除了返回的答案本身。  
  - 因此是 **O(1)**（不计答案本身）。

#### 代码（Python）

```python
def generate(numRows: int):
    # ---------- 计算阶乘的函数 ----------
    def fact(k: int) -> int:
        """返回 k 的阶乘，等价于查字典里 key=k 的值"""
        res = 1
        for i in range(2, k + 1):
            res *= i          # 逐步累乘，类似把每页的字数相加
        return res

    # ---------- 主体：逐行生成 ----------
    triangle = []            # 最终答案，外层列表相当于一本书的目录
    for i in range(numRows):          # 第 i 行（从 0 开始）
        row = []                     # 当前行的内容，像一本书的章节
        for j in range(i + 1):       # 第 j 列
            # 组合数公式 C(i, j) = i! / (j! * (i-j)!)
            val = fact(i) // (fact(j) * fact(i - j))
            row.append(val)          # 把算好的数放进本行
        triangle.append(row)        # 本行写完，加入目录
    return triangle
```

#### 复杂度

- **时间复杂度**：`O(numRows³)` — 立方增长的意思是，当行数翻倍时，计算量会增加大约 **8 倍**（2³）。
- **空间复杂度**：`O(1)`（不计输出） — 只用了几个变量，和输入规模无关。

### 2. 最优解

#### 思路  

从暴力解可以看到，**大量的重复计算** 是瓶颈：

- `fact(i)`、`fact(j)`、`fact(i‑j)` 在同一行里会被反复算好几次。  
- 事实上，帕斯卡三角的每一行都可以 **由上一行直接推导**，不需要任何阶乘。

**核心思想：动态规划（Dynamic Programming）**  
把“大问题”拆成“小问题”，把已经算好的“小问题”保存起来，后面直接使用，避免重复。

具体步骤：

1. **初始化**：第一行只能是 `[1]`。把它放进结果 `res`。
2. **逐行构造**：假设第 `i‑1` 行已经准备好（记为 `prev`），第 `i` 行的长度是 `i+1`。  
   - 第 `0` 和第 `i` 位永远是 `1`（两侧的边缘），因为它们对应 `C(i,0)`、`C(i,i)`。  
   - 中间的每个位置 `j`（`1 ≤ j ≤ i‑1`）的值等于 `prev[j‑1] + prev[j]`，这正是“两个正上方的数相加”。  
   - 把这些值收集成新行 `curr`，再加入 `res`。

**为什么正确？**  
这正是帕斯卡三角的定义：每个内部元素等于左上和右上的两个元素之和。我们把它写成代码，就是把定义直接实现。

**时间/空间复杂度**（大白话）  

- **时间**：  
  - 第 `i` 行需要遍历 `i+1` 个位置，总工作量是 `1 + 2 + … + n ≈ O(n²)`。  
  - 用生活化的比喻：如果你只需要把每本书的章节标题写一次，而不是每页都重新写，那么工作量随书本数量的平方增长（比立方小很多）。  
- **空间**：  
  - 除了保存答案外，只需要额外的一个上一行的引用 `prev`（或者直接在 `res` 里取），即 **O(1)** 额外空间。  
  - 如果想把每行单独拷贝保存，则需要 `O(n²)`（这正是答案本身的大小），这里我们只讨论**额外**空间。

#### 代码（Python）

```python
def generate(numRows: int):
    """
    使用动态规划逐行构造帕斯卡三角
    思路：每一行只需要前一行的数据，两个正上方相加得到中间值
    """
    if numRows == 0:
        return []                     # 边界：没有行时返回空列表

    res = [[1]]                       # 第 0 行，只有一个 1
    for i in range(1, numRows):       # 从第 1 行开始构造
        prev = res[-1]                # 取上一行，类似“查字典”里找前一次的结果
        curr = [1]                    # 行首必为 1

        # 中间的数：左上 + 右上
        for j in range(1, i):         # 只遍历到 i-1，最后一个 1 另写
            curr.append(prev[j - 1] + prev[j])

        curr.append(1)                # 行尾必为 1
        res.append(curr)              # 把本行加入答案

    return res
```

#### 复杂度

- **时间复杂度**：`O(numRows²)` — 二次增长的意思是，当行数翻倍时，计算量会增加约 **4 倍**（2²）。
- **空间复杂度**：`O(1)`（不计输出） — 只用了常数个临时变量；答案本身的大小自然是 `O(numRows²)`，这属于必须的存储。

## 心得

- **核心技巧**：**动态规划**——把每一行看作“子问题”，用已经算好的上一行直接推导当前行，避免重复计算。
- **适用的题型**  
  1. **杨辉三角**（LeetCode 118）  
  2. **不同路径**（DP 版的格子路径）  
  3. **最小路径和**（从左上到右下的累加问题）  
- **一句话总结解题钥匙**：  
  *“把问题拆成上一层的答案相加，边缘永远是 1”。*

## 反思

- **第一反应**：直接套用组合数公式 `C(i, j)`，把每个数都算一遍——这就是暴力思路。
- **最容易踩的坑**  
  - **边界**：`numRows = 0` 时要返回空列表，否则会出现索引错误。  
  - **溢出**：使用阶乘时，`n!` 很快超过整数范围（虽然 Python 整数不溢出，但计算会很慢）。  
  - **重复计算**：不利用已经得到的结果会导致时间爆炸。  
- **下次遇到同类题**：第一步先问自己“**有没有可以直接由上一层得到当前层的递推关系**？”如果有，就立刻用 DP 思路写出 O(n²) 的解法。
