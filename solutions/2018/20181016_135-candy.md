# #135. 糖果 / Candy

> 难度：困难 · 标签：Array、Greedy · [LeetCode 链接](https://leetcode.com/problems/candy/)

---

## 题目（英文原版）

**Description**

There are n children standing in a line. Each child is assigned a rating value given in the integer array ratings.
You are giving candies to these children subjected to the following requirements:
Return the minimum number of candies you need to have to distribute the candies to the children.

**Examples**

**Example 1:**

```
Input: ratings = [1,0,2]
Output: 5
Explanation: You can allocate to the first, second and third child with 2, 1, 2 candies respectively.
```

**Example 2:**

```
Input: ratings = [1,2,2]
Output: 4
Explanation: You can allocate to the first, second and third child with 1, 2, 1 candies respectively.
The third child gets 1 candy because it satisfies the above two conditions.
```

**Constraints**

- n == ratings.length
- 1 <= n <= 2 * 104
- 0 <= ratings[i] <= 2 * 104

---

## 题目（中文翻译）

有 `n` 个孩子排成一列。每个孩子都有一个评分（`ratings`），存放在整数数组中。  
现在要向这些孩子分发糖果（`candies`），必须满足以下条件：

- 每个孩子至少分到 1 颗糖果；
- 如果某个孩子的评分高于其相邻的孩子，那么该孩子分到的糖果必须多于相邻的孩子。

请返回为满足上述要求而需要的最少糖果总数。

## 示例

### 示例 1
**输入**  
``` 
ratings = [1,0,2]
```  
**输出**  
```
5
```  
**解释**  
可以分别给第一个、第二个、第三个孩子分配 2、1、2 颗糖果。

### 示例 2
**输入**  
``` 
ratings = [1,2,2]
```  
**输出**  
```
4
```  
**解释**  
可以分别给第一个、第二个、第三个孩子分配 1、2、1 颗糖果。  
第三个孩子只分到 1 颗糖果，因为已经满足上述两条条件。

## 约束条件

- `n == ratings.length`
- `1 <= n <= 2 * 10^4`
- `0 <= ratings[i] <= 2 * 10^4`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**从左到右、从右到左不断修正**，直到所有相邻孩子都满足“评分高的拿的糖果多”的规则。可以把每个孩子想象成排队的顾客，`ratings[i]` 像是他们的“会员等级”，`candies[i]` 就是他们得到的“优惠券”。  
1. 先把每个人都发 1 颗糖（最小的合法值）。  
2. 扫描一遍，如果发现左边的孩子评分更高但糖果不够多，就把左边的糖果加到 **右边糖果 + 1**。  
3. 再从右往左做同样的检查。  
4. 如果这一次仍然有不满足的相邻对，就继续重复第 2、3 步，直到整条线都“稳住”为止。

这个办法之所以 **正确**，是因为每一次修正都会让不满足条件的那一侧严格增加糖果，且只会增加到刚好满足条件的最小值。循环结束时，所有相邻关系都已经被检查并满足，得到的就是一种合法的分配方式——虽然不一定是最小的，但一定是合法的。

> **时间复杂度**  
> 每次完整的左右扫描都是 O(n)。最坏情况下（比如 ratings = [0,1,2,…,n-1]）需要的修正次数也可能是 O(n)，于是总体是 **O(n²)**。可以把 O(n²) 想成“把 n 个人排成一行，来回检查 n 次”，所以运行时间会随 n 的平方增长。  
> **空间复杂度**  
> 只用了一个长度为 n 的数组 `candies` 来存放每个人的糖果数，额外空间是 **O(n)**。

#### 代码（Python）

```python
def candy_bruteforce(ratings):
    n = len(ratings)
    # 每个人先拿 1 颗糖
    candies = [1] * n

    changed = True
    while changed:                 # 只要还有人不满足，就继续循环
        changed = False

        # 从左往右检查
        for i in range(1, n):
            if ratings[i] > ratings[i - 1] and candies[i] <= candies[i - 1]:
                candies[i] = candies[i - 1] + 1   # 必须比左边多 1
                changed = True

        # 从右往左检查
        for i in range(n - 2, -1, -1):
            if ratings[i] > ratings[i + 1] and candies[i] <= candies[i + 1]:
                candies[i] = candies[i + 1] + 1   # 必须比右边多 1
                changed = True

    return sum(candies)
```

#### 复杂度

- **时间复杂度：** `O(n²)`  
  想象成“每次来回走一遍全队”，最坏情况下需要走 `n` 次，故是 `n × n`。
- **空间复杂度：** `O(n)`  
  只用了一个同等长度的数组来记录每个人的糖果数。

### 2. 最优解

#### 思路  

从暴力解可以看到**瓶颈**在于**反复遍历**。实际上，只要我们把“左侧影响”和“右侧影响”分别算出来，再取两者的最大值，就能一次性得到每个人的最小合法糖果数。  

1. **左侧遍历**（从左到右）  
   - 如果当前孩子的评分高于左边的孩子，就把糖果数设为 `左边糖果 + 1`，否则保持 1。  
   - 这一步相当于把“左边比我低，我必须比左边多 1”这条规则全部贯彻完，得到一个数组 `left`。

2. **右侧遍历**（从右到左）  
   - 同理，如果当前孩子的评分高于右边的孩子，就把糖果数设为 `右边糖果 + 1`，否则保持 1。  
   - 这一步得到另一个数组 `right`，对应“右边比我低，我必须比右边多 1”的规则。

3. **合并**  
   - 对于每个位置 `i`，真正需要的糖果数是 `max(left[i], right[i])`。因为左侧和右侧的要求可能不一样，只有取最大值才能同时满足两边的约束。  
   - 最后把所有 `max` 值加起来即为答案。

> **为什么只要两遍就够了？**  
> 想象每条规则（左侧或右侧）都是一次“单向传递”。左遍历把所有左向的递增关系全部传播完，右遍历把所有右向的递增关系全部传播完。两次传播互不干扰，合并时取最大就自然满足了“双向递增”。  
> 这正像在山坡上铺路：从左坡往右坡铺一次，从右坡往左坡再铺一次，最后两条路的最高点决定了每段路的最小宽度。

> **核心技巧**：**贪心 + 两次单调遍历**（单调递增的概念可以类比为“排队时，后面的人如果比前面更有资格，就必须排得更靠前”）。

#### 代码（Python）

```python
def candy(ratings):
    n = len(ratings)
    # 第一次遍历：只考虑左边的约束
    left = [1] * n
    for i in range(1, n):
        if ratings[i] > ratings[i - 1]:
            left[i] = left[i - 1] + 1   # 左边比我低，我必须比左边多 1
        # else: left[i] 仍为 1

    # 第二次遍历：只考虑右边的约束，同时累加答案
    right = 1          # 右边遍历时，当前孩子右侧的最小糖果数
    total = 0
    for i in range(n - 1, -1, -1):
        if i < n - 1 and ratings[i] > ratings[i + 1]:
            right = right + 1        # 右边比我低，我必须比右边多 1
        else:
            right = 1                # 否则重新回到最小值 1

        # 两侧约束同时满足，需要取较大的那个
        total += max(left[i], right)

    return total
```

#### 复杂度

- **时间复杂度：** `O(n)`  
  只遍历了两遍，每遍只做了常数时间的操作。相当于“一次走完全队”，即使 n 达到 2·10⁴ 也毫无压力。  
- **空间复杂度：** `O(n)`（若只用 `left` 数组）或 `O(1)`（若在第一次遍历时直接把结果写回 `ratings` 或使用原地修改）。这里我们保留 `left` 便于代码可读性，额外空间是 `n` 大小的数组。

## 心得

- **核心技巧**：一次正向遍历记录左侧递增要求，一次反向遍历记录右侧递增要求，最后取两者最大值即可得到全局最小合法糖果数。  
- **该技巧适用的题型**  
  1. **最高山峰/坡度问题**：如 “Trapping Rain Water” 中的左侧最高、右侧最高的双向扫描。  
  2. **连续递增/递减约束**：如 “Longest Mountain Array”。  
  3. **双向约束的分配类问题**：如 “Minimum Number of Moves to Make Array Complementary”。  
- **一句话总结解题钥匙**：**把每个方向的“必须比邻居多 1”单独算好，再取最大**。

## 反思

- **第一反应**：看到“相邻孩子的评分决定糖果数量”，本能想到“从左到右、从右到左分别检查”，于是想到了两遍遍历的思路。  
- **最容易踩的坑**  
  - 忽略了等分数的情况：当相邻两人评分相等时，糖果数 **不需要** 递增，必须显式写成 `>` 而不是 `>=`。  
  - 只用左遍历或右遍历会导致某些局部最小值被低估，必须两边都考虑。  
  - 统计答案时忘记取 `max(left[i], right[i])`，导致不满足一侧约束。  
- **下次遇到同类题**：第一步先把“单向递增约束”用一次遍历写下来，然后再用相反方向的遍历补全，最后合并。这样可以确保一次 O(n) 完成。
