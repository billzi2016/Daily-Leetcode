# #66. 加一 / Plus One

> 难度：简单 · 标签：Array、Math · [LeetCode 链接](https://leetcode.com/problems/plus-one/)

---

## 题目（英文原版）

**Description**

You are given a large integer represented as an integer array digits, where each digits[i] is the ith digit of the integer. The digits are ordered from most significant to least significant in left-to-right order. The large integer does not contain any leading 0's.
Increment the large integer by one and return the resulting array of digits.

**Examples**

**Example 1:**

```
Input: digits = [1,2,3]
Output: [1,2,4]
Explanation: The array represents the integer 123.
Incrementing by one gives 123 + 1 = 124.
Thus, the result should be [1,2,4].
```

**Example 2:**

```
Input: digits = [4,3,2,1]
Output: [4,3,2,2]
Explanation: The array represents the integer 4321.
Incrementing by one gives 4321 + 1 = 4322.
Thus, the result should be [4,3,2,2].
```

**Example 3:**

```
Input: digits = [9]
Output: [1,0]
Explanation: The array represents the integer 9.
Incrementing by one gives 9 + 1 = 10.
Thus, the result should be [1,0].
```

**Constraints**

- 1 <= digits.length <= 100
- 0 <= digits[i] <= 9
- digits does not contain any leading 0's.

## 题目（中文翻译）

你得到一个用整数数组 `digits` 表示的大整数（large integer），其中 `digits[i]` 是该整数的第 `i` 位数字。数组中的数字按从左到右的顺序排列，即从最高位到最低位。该大整数不包含任何前导 0（leading 0）。

请将这个大整数加一，并返回结果对应的整数数组 `digits`。

**输出**: `[1,2,4]`

加一后得到 `123 + 1 = 124`，因此结果应为 `[1,2,4]`。

**示例 2**  
**输入**: `digits = [4,3,2,1]`  
**输出**: `[4,3,2,2]`

加一后得到 `4321 + 1 = 4322`，因此结果应为 `[4,3,2,2]`。

**示例 3**  
**输入**: `digits = [9]`  
**输出**: `[1,0]`  
**解释**: 数组表示整数 `9`。  
加一后得到 `9 + 1 = 10`，因此结果应为 `[1,0]`。

## 约束条件

- `1 <= digits.length <= 100`
- `0 <= digits[i] <= 9`
- `digits` 不包含任何前导 0。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把数组 `digits` 当成一串字符，先把它们拼成一个完整的整数，然后在整数上加 `1`，最后把结果再拆分成每一位放回数组。  
- **使用的数据结构**：`list`（数组）用来存放每一位数字；`int` 用来存放完整的整数。把数组转成整数就像把一本字典里每个字的**拼音**连起来得到一个完整的词。
- **正确性**：因为题目本身就是在说「把这个大整数加一」，把它先恢复成真正的整数再做加法，显然能得到正确答案。
- **复杂度分析**：  
  - 把数组拼成整数需要遍历一次数组，时间是 `O(n)`（`n` 是数组长度）。  
  - 把整数拆回数组同样需要遍历一次，时间也是 `O(n)`。  
  - 总时间是 `O(n) + O(n) = O(n)`，但**空间**上要额外存一个完整的整数。Python 的整数是 **大整数**，它会占用与数组长度相同数量的位数，所以空间复杂度也是 `O(n)`。  
  - 这里的 `O(n)` 可以想象成「如果数组有 100 位，就要走 100 步」；`O(1)`（常数）则是「不管有多少位，只走固定的几步」。

> **注意**：在实际面试或线上评测里，直接把数组转成整数再加一的做法虽然简洁，但会受到语言整数范围的限制（有的语言没有大整数），因此我们更倾向于手动模拟加法过程。

#### 代码（Python）

```python
def plusOne_bruteforce(digits):
    # 1. 把数组拼成整数
    num = 0
    for d in digits:               # 遍历每一位
        num = num * 10 + d          # 例如 1,2,3 -> ((0*10+1)*10+2)*10+3 = 123

    # 2. 加一
    num += 1

    # 3. 把整数拆回数组
    #   先把整数转成字符串，再把每个字符转成 int
    result = [int(ch) for ch in str(num)]

    return result
```

#### 复杂度

- **时间复杂度**：`O(n)` — 需要遍历两遍数组（一次拼整数，一次拆回），相当于「走 n 步」。
- **空间复杂度**：`O(n)` — 结果数组占用 `n` 个位置，另外整数本身在 Python 中也会占用相当于 `n` 位的空间。

---

### 2. 最优解

#### 思路  

暴力解已经是 `O(n)`，已经很快了。但我们可以在 **不把整个数组转成整数** 的前提下，直接在数组上模拟「手工加一」的过程，这样可以省掉额外的整数对象，空间上只使用原数组（再加一个可能的进位位）。  

**瓶颈**：在暴力解里我们把整数整体转成字符串，这一步在某些语言里会产生额外的拷贝。我们可以把「加一」的过程拆成 **从最低位向最高位逐位处理**，类似小学算数的竖式加法：

1. 从数组最右边（最低位）开始，加 `1`。  
2. 如果该位加完后小于 `10`，说明没有产生进位，直接返回数组。  
3. 若该位等于 `10`，把它变成 `0`（相当于进位），继续向左处理下一位。  
4. 如果遍历完所有位仍然有进位（例如 `99…9`），需要在最前面再插入一个 `1`，形成 `100…0`。

**核心算法**：**模拟进位**（carry）——这是一种**双指针**的思路：我们用一个指针 `i` 从右向左遍历数组，处理每一位的加法和进位。

**类比**：想象你在写一串数字，最右边的数字先加一，如果它从 `9` 变成 `10`，你把它写成 `0` 并把「1」交给左边的数字继续加，这个「交出去的 1」就叫 **进位**。我们把这个过程写成代码，就完成了题目要求。

#### 代码（Python）

```python
def plusOne(digits):
    """
    在原数组上模拟加一的竖式运算
    """
    n = len(digits)

    # 从最右边开始遍历
    for i in range(n - 1, -1, -1):
        if digits[i] < 9:                 # 当前位不是 9，直接加一后结束
            digits[i] += 1
            return digits                 # 直接返回修改后的数组

        # 当前位是 9，变成 0 并产生进位，继续向左处理
        digits[i] = 0

    # 如果所有位都是 9，循环结束后仍然没有返回
    # 需要在最前面补一个 1，例如 [9,9] -> [1,0,0]
    return [1] + digits
```

**代码要点解释**  

- `range(n - 1, -1, -1)`：从 `n-1`（最后一个下标）倒着走到 `0`，每次减 `1`。相当于「从右往左」遍历。  
- `if digits[i] < 9:`：如果不是 `9`，加一后不产生进位，直接返回；这一步是 **最常见的快速退出**。  
- `digits[i] = 0`：如果是 `9`，加一会变成 `10`，我们只保留 `0`，把进位交给左边。  
- 循环结束后说明原数组全是 `9`，所以要在最前面插入 `1`，其余全部是 `0`（已经在循环里改成了 `0`）。

#### 复杂度

- **时间复杂度**：`O(n)` — 最坏情况下要遍历所有位（比如全部是 `9`），相当于「走 n 步」。  
  与暴力解的时间相同，但省去了把整数转成字符串的额外操作，实际运行更快。  
- **空间复杂度**：`O(1)`（不计返回值） — 只在原数组上就地修改，若全部是 `9` 需要额外创建一个长度为 `n+1` 的新数组，但这属于 **输出空间**，不算在额外空间里。相较于暴力解省掉了把整数存成大整数的额外空间。

## 心得

- **核心技巧**：**模拟进位的竖式加法**（从低位向高位逐位处理，遇到 9 就置零并继续进位）。
- **适用的题型**：  
  1. “加一” 类的数组模拟运算（如 **Plus One**）。  
  2. “两数相加” 的数组版（LeetCode 2：Add Two Numbers）。  
  3. “大整数减法” 或 “大整数乘法” 需要逐位处理并管理进位/借位的题目。
- **一句话总结**：**把大整数拆成每位，像小学算数一样从右往左加，遇 9 进位，全部是 9 时在最前面补 1。**

## 反思

- **第一反应**：把数组直接转成整数再加一，代码写得最快，但会担心整数溢出或额外空间。  
- **最容易踩的坑**：  
  - 忘记在全部是 `9` 时在最前面补 `1`，会得到 `[0,0,...,0]` 而不是 `[1,0,0,...,0]`。  
  - 直接在遍历时修改原数组后忘记 `return`，导致继续遍历产生错误的进位。  
  - 边界条件：数组长度为 `1` 且是 `9`（如 `[9]`）也要正确处理。  
- **下次遇到同类题**：第一步先**思考是否可以逐位模拟**（进位/借位），因为这通常是最安全、最通用的做法。若能一次遍历结束即得到答案，就是最优解。
