# #172. 阶乘后的零 / Factorial Trailing Zeroes

> 难度：中等 · 标签：Math · [LeetCode 链接](https://leetcode.com/problems/factorial-trailing-zeroes/)

---

## 题目（英文原版）

**Description**

Given an integer n, return the number of trailing zeroes in n!.
Note that n! = n * (n - 1) * (n - 2) * ... * 3 * 2 * 1.
Follow up: Could you write a solution that works in logarithmic time complexity?

**Examples**

**Example 1:**

```
Input: n = 3
Output: 0
Explanation: 3! = 6, no trailing zero.
```

**Example 2:**

```
Input: n = 5
Output: 1
Explanation: 5! = 120, one trailing zero.
```

**Example 3:**

```
Input: n = 0
Output: 0
```

**Constraints**

- 0 <= n <= 104

## 题目（中文翻译）

给定一个整数 `n`，返回 `n!` 中尾随零（trailing zeroes）的数量。  
注意，`n!` 表示 `n` 的阶乘（factorial），即 `n * (n - 1) * (n - 2) * ... * 3 * 2 * 1`。

**进阶**：你能否写出时间复杂度为对数级（logarithmic time complexity）的解法？

示例 1:
```
Input: n = 3
Output: 0
解释: 3! = 6，没有尾随零。
```

示例 2:
```
Input: n = 5
Output: 1
解释: 5! = 120，有一个尾随零。
```

示例 3:
```
Input: n = 0
Output: 0
解释: 0! = 1，没有尾随零。
```

约束条件：
- 0 <= n <= 10^4

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**先算出 n 的阶乘**，再数一数结果末尾有多少个 `0`。  
- 计算阶乘可以用一个循环把 `1·2·3·…·n` 依次相乘，得到一个大整数。  
- 统计末尾的 `0` 就像把这个大整数当成字符串，从右往左数有多少个 `'0'`，或者不停地把它除以 `10`，只要余数不为 `0` 就停下来。

> **类比**：  
> 把阶乘想象成一本厚厚的书，末尾的 `0` 就像书页的空白页。我们先把整本书写完（算出阶乘），再一页一页往后翻，数到底有多少页是空白的（统计 `0`）。

**为什么这个方法正确**：  
如果一个整数的末尾有 `k` 个 `0`，说明它能被 `10^k` 整除而不能被 `10^{k+1}` 整除。直接算出 `n!` 后，用除法或字符串方式检查，就一定能得到正确的 `k`。

**时间/空间复杂度**：  
- 计算阶乘本身需要 `n` 次乘法 → **O(n)**。  
- 但是 `n!` 的位数会随 `n` 快速增长（大约是 `n·log10 n` 位），所以整数的乘法本身已经不是 O(1) 的操作，实际运行会非常慢。  
- 统计 `0` 的过程最多需要把结果除以 `10` 直到不再能除尽，最坏情况下是 `O(log10(n!))`，也就是 **O(n log n)**。  
- 空间上我们要存放整个 `n!`，它的位数是 `Θ(n log n)`，因此 **空间复杂度是 O(n log n)**（远大于题目给的 `n ≤ 10^4` 能接受的范围）。

> **大白话**：  
> `O(n²)` 就像你要跟 1000 个人每人握手一次，次数是 1000·1000；这里的 `O(n log n)` 也类似，虽然不是平方级别，但随着 `n` 增大，计算量仍然会快速膨胀，尤其是要处理超大整数时。

#### 代码（Python）

```python
def trailingZeroes_brute(n: int) -> int:
    # 1. 计算 n!，使用 Python 的大整数直接相乘
    fact = 1
    for i in range(2, n + 1):
        fact *= i                     # 逐步累乘，得到 n!

    # 2. 统计末尾的 0
    cnt = 0
    while fact % 10 == 0:            # 只要还能被 10 整除，就说明还有一个末尾 0
        cnt += 1
        fact //= 10                  # 把末尾的 0 去掉，继续检查
    return cnt
```

#### 复杂度

- **时间复杂度**：`O(n log n)`  
  - `n` 次乘法，每次乘法的位数随结果增长而增长，大约是 `log10(n!) ≈ n log10 n`，所以整体是 `O(n log n)`。
- **空间复杂度**：`O(n log n)`  
  - 需要存储整个 `n!`，它的位数与 `n log n` 成正比。

---

### 2. 最优解

#### 思路  

**从暴力解出发**，我们发现慢的地方在于**真正算出完整的阶乘**。其实我们只需要知道 **有多少个因子 10**，因为每出现一个 `10`，就在末尾多一个 `0`。

- `10 = 2 × 5`，所以每对 `(2,5)` 就会产生一个 `0`。  
- 在 `n!` 中，因子 `2` 的数量远大于因子 `5`（每隔一个数就有一个偶数），**限制 `0` 数量的瓶颈是因子 `5` 的个数**。  
- 因此，只要统计 `1 … n` 之间所有数里出现了多少个 `5`，就等于答案。

**如何统计因子 5 的个数**：

1. **每出现一个能被 5 整除的数，就贡献一个 `5`**。这相当于 `n // 5`（整数除法）个数。  
2. **但有些数能被 25 (=5²) 整除，它们实际上提供了 **两个** 5**（比如 25 = 5×5），所以要再加上 `n // 25`。  
3. 同理，能被 `125 (=5³)` 整除的数提供了 **三个** 5，继续加 `n // 125`，依此类推。  
4. 当除数超过 `n` 时，就不再贡献新的 `5`，循环结束。

这就是**求和** `n // 5 + n // 25 + n // 125 + …`，直到除数大于 `n`。

> **类比**：  
> 想象你在收集“5 的小票”。每买一件商品，如果价格是 5 的倍数，你得到一张小票；如果是 25 的倍数，你会得到两张（因为 25 包含两个 5），依此类推。只要把所有小票加起来，就知道能换多少个 “0” 了。

**为什么只需要考虑 5**：  
因为 `2` 的出现频率是 `5` 的两倍以上（每隔一个数就有一个偶数），所以 `5` 永远是稀缺资源，`2` 永远够用。

**时间复杂度**：  
每次除以 5，直到商为 0。除法次数是 `log₅ n`，即对数级别。对于 `n ≤ 10⁴`，最多只需要 6 次循环。**这就是题目要求的对数时间**。

**空间复杂度**：只用了几个整数变量，**O(1)**。

#### 代码（Python）

```python
def trailingZeroes(n: int) -> int:
    """
    统计 n! 末尾有多少个 0，只需要统计因子 5 的个数。
    """
    count = 0          # 用来累计出现的 5 的个数
    divisor = 5        # 第一次统计能被 5 整除的数

    # 当 divisor 超过 n 时，后面再除就没有贡献了
    while n >= divisor:
        count += n // divisor   # n // divisor 表示有多少个数能提供至少一个 5
        divisor *= 5            # 下一轮统计能提供第二个、第三个 … 5 的数
        # 例如: 5, 25, 125, 625, ...

    return count
```

#### 复杂度

- **时间复杂度**：`O(log₅ n)` → 大约是 `O(log n)`。  
  - 只需要不断除以 5，循环次数随 `n` 的对数增长，几乎可以忽略不计。相比暴力解的 `O(n log n)`，快了很多。
- **空间复杂度**：`O(1)` → 只用了固定的几个整数变量，不会随 `n` 增大而增加。

## 心得

- **核心技巧**：把“末尾 0”转化为“因子 5 的数量”。利用 **数论** 中的因子分解思想，将原本需要大数运算的问题化简为 **整数除法求和**。  
- **适用的题型**：  
  1. 统计阶乘中因子出现次数（如求 `n!` 中因子 2、3、5 的个数）。  
  2. “有多少个整数能被 k 整除” 类的计数题（例如求区间 `[1, n]` 中能被 3 或 7 整除的数）。  
  3. “找出某种资源的瓶颈” 的优化思路（如在排列组合中只需要关注最稀缺的因子）。  
- **一句话总结解题钥匙**：**把“末尾 0”映射到“5 的出现次数”，用除以 5 的递归求和即可在对数时间得到答案**。

## 反思

- **第一反应**：先算出 `n!` 再数零。因为阶乘是最直观的概念，尤其在没有见过类似题目时会本能地去“完整”求解。  
- **最容易踩的坑**：  
  - 忘记 **25、125…** 这些数提供多个 5，导致答案偏小。  
  - 忽视 `n = 0` 的情况，虽然 0! = 1，末尾没有 0，但代码若直接除以 5 仍然会返回 0，需确保循环条件正确。  
  - 使用大整数直接计算阶乘会导致时间和内存爆炸，尤其在语言没有自动大数支持时更易卡死。  
- **下次遇到同类题**，第一步应该先**思考是否可以用因子分解或计数的方式直接得到结果**，而不是先把整个结构算出来。对“末尾 0”“约数”“因子”等关键词保持敏感，往往能快速定位到对数或常数级的解法。
