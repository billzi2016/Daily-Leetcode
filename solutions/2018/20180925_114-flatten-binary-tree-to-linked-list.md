## 解题过程

### 1. 直觉解（暴力）

#### 思路  
最直接的想法是：先把二叉树按 **先序遍历**（根 → 左 → 右）的顺序记录下来，然后再把这些节点一个接一个地重新链接成「只有右子树」的链表。  

- **先序遍历**可以用递归实现，也可以用显式的栈（就像我们把要去的“路标”放进背包里，一次拿出来走）。  
- 记录顺序时我们可以把每个访问到的 `TreeNode` 对象放进一个列表 `nodes`，这相当于把树的每个“房间”依次写在纸上。  
- 完成遍历后，遍历 `nodes` 列表，把 `nodes[i].right = nodes[i+1]`，并把 `nodes[i].left = None`，把左指针全部清空，右指针指向下一个节点。  

> **为什么正确？**  
> 先序遍历的顺序恰好是题目要求的「展开后」的顺序。我们把所有节点按这个顺序重新排好，然后让每个节点的右指针指向下一个节点，就得到了题目要求的单向链表。

#### 代码（Python）

```python
# Definition for a binary tree node.
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val          # 节点的数值
        self.left = left        # 左子树
        self.right = right      # 右子树


def flatten(root: TreeNode) -> None:
    """
    暴力版：先遍历得到所有节点的列表，再逐个重连。
    由于要在原地修改树，函数没有返回值。
    """
    if not root:
        return

    nodes = []                     # 用来存放遍历顺序的列表

    # 递归实现先序遍历
    def preorder(node: TreeNode):
        if not node:
            return
        nodes.append(node)         # 访问根节点，放进列表
        preorder(node.left)        # 再遍历左子树
        preorder(node.right)       # 最后遍历右子树

    preorder(root)                # 把所有节点收集到 nodes

    # 依次把节点重新链接成「只有右指针」的链表
    for i in range(len(nodes) - 1):
        cur = nodes[i]
        nxt = nodes[i + 1]
        cur.left = None            # 左指针全部置空
        cur.right = nxt            # 右指针指向下一个节点

    # 最后一个节点的左右指针都置空
    nodes[-1].left = None
    nodes[-1].right = None
```

#### 复杂度  

- **时间复杂度：** `O(n)`  
  - 解释：我们遍历了树里每个节点一次（先序遍历），再遍历一次列表把指针重连。`n` 是节点数，两个 `O(n)` 加起来仍然是 `O(n)`，相当于“花一次时间把所有东西看一遍”。
- **空间复杂度：** `O(n)`  
  - 解释：除了递归调用栈外，我们额外用了一个列表 `nodes` 来存所有节点，列表的大小正好是节点数 `n`，所以需要 `n` 个“盒子”。  

---

### 2. 最优解

#### 思路  
暴力解的瓶颈在 **额外的列表**：虽然时间已经是线性的，但我们用了 `O(n)` 的额外空间。题目并没有要求必须用额外空间，**可以在原树上就地完成展开**。  

**关键观察**：在先序遍历的过程中，**当前节点的左子树应该全部放在右子树的前面**，而左子树的最右侧节点（即左子树的“最深最右”节点）需要连接到原来的右子树上。  

基于这个观察，有两种常见的原地实现方式：

1. **递归后序**（从底向上处理）  
   - 先把左子树、右子树都展开成链表。  
   - 把左子树挂到右指针上，并把左子树的最右节点连接到原来的右子树。  
   - 递归的自然栈深度为树的高度 `h`，最坏 `O(n)`（完全不平衡时），但空间仍是 `O(h)`，通常比 `O(n)` 小。

2. **迭代 + 栈**（模拟先序遍历）  
   - 使用显式栈把右子树先压进去，再压左子树，这样弹出时先处理左子树。  
   - 每弹出一个节点，就把它的 `right` 指向栈顶的节点（下一个要访问的节点），并把 `left` 置空。  
   - 只用了栈来保存尚未处理的节点，最多保存树的高度 `h`，空间 `O(h)`。

下面我们采用 **迭代 + 栈** 的写法，因为它直观易懂，且只用 `O(h)` 的额外空间。

> **类比**：想象你在一棵树上爬，左边的枝条必须先走完再走右边。你把右边的枝条放进背包（栈），先走左边。每走完一个节点，就把背包顶的节点设为下一个要走的方向，这样就形成了一条只向右的“链路”。

#### 代码（Python）

```python
def flatten(root: TreeNode) -> None:
    """
    迭代版：使用栈模拟先序遍历，在遍历的同时把指针原地重连。
    只需要额外的 O(h) 空间（h 为树的高度），不需要额外的节点列表。
    """
    if not root:
        return

    stack = [root]                 # 初始化栈，先把根放进去

    while stack:
        node = stack.pop()         # 取出当前要处理的节点

        # 先把右子树压栈，再把左子树压栈
        # 这样弹出时左子树会先被处理，符合先序遍历顺序
        if node.right:
            stack.append(node.right)
        if node.left:
            stack.append(node.left)

        # 栈顶（如果还有）就是当前节点在先序遍历中的下一个节点
        if stack:
            node.right = stack[-1]  # 把右指针指向下一个节点
        node.left = None            # 左指针全部置空
```

#### 复杂度  

- **时间复杂度：** `O(n)`  
  - 解释：每个节点恰好进栈一次、出栈一次，做了常数次操作，所以仍是“只看一遍所有东西”。  
- **空间复杂度：** `O(h)`（最坏 `O(n)`）  
  - 解释：栈里最多保存树的高度 `h` 个节点。对于平衡二叉树，`h ≈ log n`，只需要很少的“盒子”。在最坏的链状树中，`h = n`，这时空间和暴力解持平，但仍是题目允许的范围。

## 心得

- **核心技巧**：利用先序遍历的顺序，在遍历过程中直接把每个节点的右指针指向下一个要访问的节点，同时把左指针置空，实现 **原地展开**。  
- **适用的题型**  
  1. “把树改造成链表” 系列（如 `Flatten Binary Tree to Linked List`、`Convert BST to Sorted Doubly Linked List`）。  
  2. 需要 **先序遍历顺序** 的原地改造（如 “把二叉树展开为前序遍历的链表”）。  
  3. “原地修改结构” 的题目（如 “把二叉搜索树转为递增顺序的单链表”）。  
- **一句话总结**：**把先序遍历的“下一个节点”直接挂到当前节点的右指针上，左指针全部清空，即可原地完成展开。**

## 反思

- **第一反应**：先把树遍历出来存列表，再重连——最直接但用了额外空间。  
- **最容易踩的坑**  
  - 忘记把左指针全部设为 `None`，导致展开后仍然有左子树，破坏链表形态。  
  - 栈的压入顺序写反了（先压左再压右），会得到 **后序** 或 **错误顺序** 的展开。  
  - 对空树或只有一个节点的特殊情况没有提前判断，直接执行会出现 `IndexError`。  
- **下次第一步**：先思考 **是否可以在遍历的同时完成改造**，找出“遍历顺序”和“目标结构”的对应关系，再决定是递归还是栈实现。
