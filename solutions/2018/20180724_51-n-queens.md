## 题目（英文原版）

**Description**

The n-queens puzzle is the problem of placing n queens on an n x n chessboard such that no two queens attack each other.
Given an integer n, return all distinct solutions to the n-queens puzzle. You may return the answer in any order.
Each solution contains a distinct board configuration of the n-queens' placement, where 'Q' and '.' both indicate a queen and an empty space, respectively.

**Examples**

**Example 1:**

```
Input: n = 4
Output: [[".Q..","...Q","Q...","..Q."],["..Q.","Q...","...Q",".Q.."]]
Explanation: There exist two distinct solutions to the 4-queens puzzle as shown above
```

**Example 2:**

```
Input: n = 1
Output: [["Q"]]
```

**Constraints**

- 1 <= n <= 9

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**把每一行都放一只皇后**，然后把所有可能的放法枚举出来，逐个检查是否满足「互不攻击」的条件。  
- **数据结构**：我们可以用一个长度为 `n` 的列表 `pos` 来保存每一行皇后所在的列号。`pos[i] = j` 表示第 `i` 行的皇后放在第 `j` 列。  
  - 这就像把棋盘的每一行看成一本词典的条目，条目的“解释”是皇后所在的列。  
- **正确性**：只要枚举了所有 `n` 行的列号组合（即所有可能的 `pos`），并且对每一种组合都检查「同列」或「同斜线」是否冲突，就一定能找到所有合法解。  
- **时间/空间分析**：  
  - 枚举所有可能的 `pos` 相当于遍历 `n` 的 **全排列**（每行只能选一个列，且列可以重复），最坏情况下是 `n!` 种。  
  - 对每一种排列，我们要用两层循环比较每两个皇后是否在同列或同斜线，时间是 `O(n²)`。  
  - 所以总体时间复杂度是 **`O(n! * n²)`**。这里的 `!` 表示阶乘，`n!` 代表「n 的全排列数量」，随着 `n` 增大会非常快爆炸。  
  - 额外的空间只用来存放 `pos`（长度 `n`）和结果列表，故 **`O(n)`**。

#### 代码（Python）

```python
def solveNQueens_bruteforce(n: int):
    """
    暴力枚举所有可能的列组合（全排列），逐一检查合法性。
    返回值是所有合法棋盘的字符矩阵列表。
    """
    ans = []                     # 最终答案列表
    pos = [0] * n                # pos[i] 表示第 i 行皇后放在第几列

    def is_valid():
        """检查当前 pos 是否满足互不攻击的条件。"""
        for i in range(n):
            for j in range(i + 1, n):
                # 同列冲突
                if pos[i] == pos[j]:
                    return False
                # 同主对角线冲突：行差等于列差
                if abs(pos[i] - pos[j]) == j - i:
                    return False
        return True

    def dfs(row: int):
        """递归枚举第 row 行的放置位置。"""
        if row == n:                     # 所有行都放完了
            if is_valid():               # 检查合法性
                board = []               # 把数字表示转成字符矩阵
                for r in range(n):
                    line = ['.'] * n
                    line[pos[r]] = 'Q'
                    board.append(''.join(line))
                ans.append(board)
            return

        for col in range(n):             # 尝试把皇后放在当前行的每一列
            pos[row] = col
            dfs(row + 1)                 # 继续排下一行

    dfs(0)
    return ans
```

#### 复杂度

- **时间复杂度：`O(n! * n²)`**  
  - `n!` 是所有可能的列排列数量，`n²` 是每次检查冲突时需要比较的皇后对数。可以把它想象成「先排好所有可能的座位表，然后每张表都要检查每两个人是否坐得太近」。
- **空间复杂度：`O(n)`**  
  - 只用了长度为 `n` 的 `pos` 数组以及递归栈（最深 `n` 层），不随解的数量增长。

### 2. 最优解

#### 思路  

暴力解的主要瓶颈在 **「每生成一个完整的排列才去检查」**，这会导致大量明显不合法的情况仍然被完整遍历。  
我们可以 **边生成边剪枝**：在放置第 `row` 行皇后时，立刻判断该位置是否会和已经放好的皇后冲突，如果冲突就直接跳过，不再继续往下搜索。这样可以大幅减少不必要的搜索。

实现剪枝的关键是快速判断「同列」和「同两条对角线」是否已被占用。这里使用 **哈希集合（set）** 来记录：

- `cols`：已经放置皇后所在的列号集合。  
  - 类比成「字典的页码」：查询某一列是否已被占用，只需要 O(1) 时间。
- `diag1`：主对角线集合，用 `row + col` 表示。所有位于同一主对角线的格子 `row + col` 值相同。
- `diag2`：副对角线集合，用 `row - col` 表示。所有位于同一副对角线的格子 `row - col` 值相同。

递归过程：

1. 从第 `0` 行开始，尝试每一列 `col`。  
2. 检查 `col`、`row+col`、`row-col` 是否已经在对应集合中出现。  
   - 若出现，说明会冲突，直接 **`continue`**（尝试下一个列）。  
   - 若不冲突，则把这三个标记加入集合，并递归处理下一行。  
3. 当 `row == n` 时，说明已经成功放置了 `n` 个皇后，生成当前棋盘并加入答案。  
4. 回溯时把刚才加入的标记删掉，恢复状态，继续尝试其他列。

这种 **回溯+剪枝** 的思路，虽然最坏情况下仍是 `O(n!)`，但实际遍历的节点数大幅下降，尤其对 `n ≤ 9` 的限制已经足够快。

#### 代码（Python）

```python
def solveNQueens(n: int):
    """
    回溯+剪枝求解 N-Queens。
    返回所有合法棋盘的字符矩阵列表。
    """
    ans = []                     # 最终答案
    board = [['.'] * n for _ in range(n)]  # 当前棋盘（字符矩阵），方便直接复制
    cols = set()                 # 已占用的列
    diag1 = set()                # 已占用的主对角线 (row + col)
    diag2 = set()                # 已占用的副对角线 (row - col)

    def backtrack(row: int):
        """尝试在第 row 行放置皇后。"""
        if row == n:             # 所有行都放完，得到一个合法解
            ans.append([''.join(r) for r in board])  # 把每行列表转成字符串加入答案
            return

        for col in range(n):
            # 判断当前位置是否被攻击
            if col in cols or (row + col) in diag1 or (row - col) in diag2:
                continue          # 冲突，尝试下一个列

            # 放置皇后并标记占用
            board[row][col] = 'Q'
            cols.add(col)
            diag1.add(row + col)
            diag2.add(row - col)

            backtrack(row + 1)    # 递归处理下一行

            # 回溯：撤销刚才的放置
            board[row][col] = '.'
            cols.remove(col)
            diag1.remove(row + col)
            diag2.remove(row - col)

    backtrack(0)
    return ans
```

#### 复杂度

- **时间复杂度：`O(N!)`（实际远小于暴力的 `O(N! * N²)`）**  
  - 每一行最多尝试 `N` 列，但因为剪枝，大多数分支在前几行就被剪掉。可以把它想象成「在排座位时，一旦发现某个位置已经被占用，就立刻把这张座位表丢掉，不再继续检查」。
- **空间复杂度：`O(N)`**  
  - 主要是递归栈的深度（最多 `N`）以及 `cols、diag1、diag2` 三个集合，各自最多存 `N` 条记录。棋盘本身 `board` 也是 `N×N`，但在返回答案时会复制，整体仍是线性级别。

## 心得

- 本题核心是 **回溯**（深度优先搜索）配合 **状态剪枝**，利用集合快速判断冲突。  
- 这类「逐步构造、冲突检测」的技巧常用于 **排列/组合**、**数独**、**拼图** 等问题。  
  - 类似题目：  
    1. `Sudoku Solver`（数独求解）  
    2. `Word Search`（单词搜索）  
    3. `Combination Sum`（组合总和）  
- **解题钥匙**：**“把约束转成可以 O(1) 判断的集合”，在递归时及时加入/删除，做到边走边剪枝”。**

## 反思

- **第一反应**：直接枚举所有行的列组合，然后逐个验证。  
- **最容易踩的坑**：  
  - 忽略 **对角线** 的冲突判断，导致错误解。  
  - 递归回溯时忘记把标记（列、对角线）撤销，导致后续分支错误。  
  - 对 `n = 2, 3` 的特殊情况没有提前返回空列表，会多做无意义搜索。  
- **下次类似题目**：第一步先思考 **“每一步的选择会产生哪些约束？”**，把这些约束用 **集合/数组** 记录下来，然后在搜索时 **即时检查**，做到“有冲突立即止步”。这样可以把搜索空间压得更小，效率大幅提升。
