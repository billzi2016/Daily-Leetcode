# #69. 求平方根 / Sqrt(x)

> 难度：简单 · 标签：Math、Binary Search · [LeetCode 链接](https://leetcode.com/problems/sqrtx/)

---

## 题目（英文原版）

**Description**

Given a non-negative integer x, return the square root of x rounded down to the nearest integer. The returned integer should be non-negative as well.
You must not use any built-in exponent function or operator.

**Examples**

**Example 1:**

```
Input: x = 4
Output: 2
Explanation: The square root of 4 is 2, so we return 2.
```

**Example 2:**

```
Input: x = 8
Output: 2
Explanation: The square root of 8 is 2.82842..., and since we round it down to the nearest integer, 2 is returned.
```

**Constraints**

- 0 <= x <= 231 - 1

---

## 题目（中文翻译）

给定一个非负整数 (non-negative integer) `x`，返回 `x` 的平方根 (square root) 向下取整至最近的整数。返回的整数也应为非负数。

**要求**  
- 不得使用任何内置的指数函数或运算符 (built-in exponent function or operator)。

**示例 1**  
输入: `x = 4`  
输出: `2`  
解释: 4 的平方根是 2，因此返回 2。

**示例 2**  
输入: `x = 8`  
输出: `2`  
解释: 8 的平方根是 2.82842…，向下取整后得到最近的整数 2，故返回 2。

**约束条件**  
- `0 <= x <= 231 - 1`   (即 `x` 的取值范围在 0 到 2³¹‑1 之间)

---

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把所有可能的整数都试一遍，找出最大的 `k` 使得 `k * k ≤ x`。  
- **数据结构**：这里只需要一个普通的整数变量 `k`，相当于在数数。可以把它想象成“从 0 开始往上数”，每数一个就检查一下 `k²` 是否已经超过了 `x`。  
- **为什么正确**：平方函数在非负整数上是单调递增的（即数越大，平方越大），所以只要找到第一个让 `k²` 超过 `x` 的 `k`，它的前一个数 `k-1` 必然就是我们要的答案。  
- **复杂度直观解释**：如果 `x` 很大（比如 2³¹‑1），我们可能要检查几乎每一个整数，从 `0` 检查到 `√x`。这相当于 **“一次一次线性走过去”**，时间随 `√x` 增长。用大 O 表示就是 `O(√x)`，意思是运行时间大概和 `√x` 成正比。空间上只用了几个整数变量，记作 `O(1)`，即 **常数空间**。

#### 代码（Python）

```python
def mySqrt_brute(x: int) -> int:
    """
    暴力枚举：从 0 开始逐个尝试，找到最大的 k 使得 k*k <= x
    """
    k = 0                     # 从 0 开始
    while (k + 1) * (k + 1) <= x:   # 只要下一个数的平方仍然不超过 x，就继续往前走
        k += 1                # 向前走一步
    return k                  # 当前的 k 就是答案
```

#### 复杂度

- **时间复杂度**：`O(√x)`  
  *解释*：如果 `x = 10,000`，我们最多检查 `0~100` 共 101 次；如果 `x = 2³¹‑1 ≈ 2.1e9`，最多检查约 `46,340` 次。次数随 `√x` 增长。
- **空间复杂度**：`O(1)`  
  只用了几个整数变量，所占内存不随 `x` 变化。

---

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**线性遍历**：即使我们只需要 `√x` 次循环，在最坏情况下（`x` 接近 2³¹‑1）也要跑上 46,000 次，仍然可以接受，但我们可以做到更快——**对数级别**的时间。

观察到：

1. 对于非负整数 `k`，`k²` 随 `k` 单调增大。  
2. `k` 的取值范围一定在 `[0, x]`（更紧的上界是 `x // 2 + 1`，因为 `k²` > `x` 时 `k` 已经超过 `√x`）。  

这正好符合**二分查找**的使用场景：在一个有序区间里找满足条件的最大（或最小）元素。

**二分查找步骤**：

- 设左指针 `left = 0`，右指针 `right = x`（或 `x // 2 + 1`，防止 `right` 太大导致乘法溢出）。
- 循环直到 `left > right`：
  - 取中点 `mid = (left + right) // 2`。
  - 计算 `mid * mid`（注意可能会超过 32 位整数范围，但 Python 的整数会自动扩展）。
  - 如果 `mid * mid == x`，恰好找到答案，直接返回 `mid`。
  - 如果 `mid * mid < x`，说明 `mid` 仍然太小，答案在右半边，更新 `left = mid + 1`，并记录 `ans = mid`（因为 `mid` 是目前合法的最大值）。
  - 否则 `mid * mid > x`，说明 `mid` 太大，答案在左半边，更新 `right = mid - 1`。
- 循环结束后，`ans` 保存的就是最大的 `k`，满足 `k² ≤ x`。

**类比**：把整个整数区间想象成一本排好序的书，想找 **“不超过 x 的最大平方根”**，我们每次打开书的中间页，根据页码对应的平方是否太大来决定向左翻还是向右翻，迅速逼近答案。

#### 代码（Python）

```python
def mySqrt_binary(x: int) -> int:
    """
    二分查找法：在有序区间 [0, x] 中寻找最大的 k 使得 k*k <= x
    """
    if x < 2:                     # 0 和 1 的平方根就是它们本身，直接返回
        return x

    left, right = 0, x // 2 + 1   # 右边界可以设为 x//2+1，防止 overflow
    ans = 0                       # 用来记录当前找到的合法答案

    while left <= right:
        mid = (left + right) // 2   # 取中点
        sq = mid * mid              # 计算 mid 的平方

        if sq == x:                 # 正好等于 x，找到了最精确的整数根
            return mid
        elif sq < x:                # mid 仍然太小，答案在右边
            ans = mid               # 更新答案为当前的 mid
            left = mid + 1
        else:                       # mid 的平方超过 x，答案在左边
            right = mid - 1

    return ans                      # 循环结束时 ans 即为所求
```

#### 复杂度

- **时间复杂度**：`O(log x)`  
  *解释*：每一次循环把搜索区间长度 **减半**，就像把一条长绳子对折再对折。若 `x ≈ 2³¹`，循环次数大约是 `log₂(2³¹) ≈ 31` 次，远远少于暴力的 46,000 次。
- **空间复杂度**：`O(1)`  
  只用了常数个变量（`left、right、mid、ans`），不随 `x` 大小增长。

## 心得

- **核心技巧**：二分查找——利用有序性把搜索空间指数级压缩。  
- **适用的题型**：  
  1. 在单调递增（或递减）函数中寻找满足条件的最大/最小整数（如 “寻找平方根”“寻找整数立方根”“寻找数组中第一个大于等于 target 的位置”）。  
  2. “在有序数组中查找边界”类问题（LeetCode 34、35、744 等）。  
- **一句话总结**：**“把大范围的线性搜索换成对数级的二分查找”** 是这类数值题目的解题钥匙。

## 反思

- **第一反应**：看到“返回整数平方根”，自然想到“遍历所有整数并比较平方”，即暴力枚举。  
- **最容易踩的坑**：  
  - 边界条件：`x = 0`、`x = 1` 必须单独处理，否则二分查找的右边界 `x // 2 + 1` 可能导致 `mid` 为 0，进入死循环。  
  - 乘法溢出：在某些语言（如 C++、Java）里 `mid * mid` 可能超出 32 位整数范围，需要使用 `long` 或提前判断。Python 自动大整数，所以这里不需要额外处理。  
- **下次遇到同类题**：第一步先确认**单调性**（函数值随输入单调增/减），再考虑用**二分查找**把搜索区间快速收敛。
