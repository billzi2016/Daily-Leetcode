## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  

最直接的想法是：**把题目说的过程一步步模拟**，一直算下去，直到出现两种情况之一  

1. 结果等于 `1` → 说明是 Happy Number，直接返回 `True`。  
2. 结果出现了之前算过的数字 → 说明进入了循环，永远也到不了 `1`，返回 `False`。  

要判断「之前算过的数字」我们可以使用 **哈希表**（在 Python 里就是 `set`）。  
- 哈希表像一本**查字典**，我们把已经出现的数当成「单词」，把它们放进字典里；  
- 每次得到新数时，先在字典里查一遍，若已经存在，就说明出现了环。  

为什么这个方法一定正确？  
- 题目规定每一步都只依赖当前数字的每一位，所以**状态只由当前数字决定**。  
- 当同一个数字再次出现时，后面的计算过程必然和上一次完全相同，形成循环，永远不会再得到 `1`。  

**时间复杂度**  
- 最坏情况下我们会遍历所有出现过的数字一次。已知所有数字最终会落在 `1~162`（因为 `9^2*9 = 729`，再继续会更小），所以遍历次数是常数级别。这里用大 O 表示为 `O(k)`，其中 `k` 是循环过程的长度，实际非常小。  
- 对初学者来说可以把它看成 **线性时间**，即 `O(n)`（n 为循环次数），但这里的 `n` 并不是原始输入的大小，而是循环步数。  

**空间复杂度**  
- 需要一个 `set` 来存放已经出现的数字，最坏会保存所有不同的中间结果，数量同样是常数级别，记作 `O(k)`，对初学者可理解为 **线性空间**。  

#### 代码（Python）  

```python
def get_next(num: int) -> int:
    """计算下一步的数：各位数字的平方和"""
    total = 0
    while num > 0:
        digit = num % 10          # 取出最低位
        total += digit * digit    # 加上它的平方
        num //= 10                # 去掉最低位
    return total


def isHappy_brute(n: int) -> bool:
    """
    暴力版：用 set 记录出现过的数字
    如果出现 1 返回 True；如果出现环返回 False
    """
    seen = set()                  # 哈希表，像查字典一样记住出现过的数
    while n != 1:
        if n in seen:             # 已经出现过，说明进入循环
            return False
        seen.add(n)               # 记录当前数字
        n = get_next(n)           # 计算下一步
    return True                    # 循环结束时 n == 1
```

#### 复杂度  

- **时间复杂度**：`O(k)`（k 为循环步数），可以理解为「每一步都做一次求和，最多走几步就几步」。  
- **空间复杂度**：`O(k)`，需要存放所有出现过的数，最坏也只会保存常数个数。

### 2. 最优解  

#### 思路  

从暴力解可以看到，**瓶颈在于额外的 `set`**——我们用了额外的空间来记忆已经遍历过的数字。  
其实我们只需要判断**是否出现环**，而不一定要把环里的每个元素都存下来。  

**Floyd 判圈算法（快慢指针）**可以在 **O(1) 额外空间** 的情况下检测环。  
- 把「下一步」看成链表的「下一个节点」。  
- 设两个指针：  
  - `slow` 每次走一步（`slow = f(slow)`）。  
  - `fast` 每次走两步（`fast = f(f(fast))`）。  
- 如果链表有环，快指针一定会在某一步追上慢指针；如果没有环（这里的“没有环”指的是没有到达 `1`），快指针会直接跑到 `1`（因为 `1` 的下一步仍是 `1`），此时两指针会在 `1` 相遇。  

所以只要 **快慢指针相遇**，就说明要么是 Happy Number（相遇点是 `1`），要么进入了循环（相遇点不是 `1`）。  

**关键点解释**  
- **为什么快指针每次走两步**：想象两个人在跑步，慢的每秒跑 1 米，快的每秒跑 2 米。若跑道是环形，快的迟早会追上慢的。  
- **为什么不需要额外的哈希表**：我们只用两个指针的相对位置来判断是否有环，省掉了记录所有节点的空间。  

#### 代码（Python）  

```python
def get_next(num: int) -> int:
    """同上，计算各位数字的平方和"""
    total = 0
    while num > 0:
        digit = num % 10
        total += digit * digit
        num //= 10
    return total


def isHappy_optimal(n: int) -> bool:
    """
    最优解：使用快慢指针（Floyd 判圈）只用 O(1) 额外空间
    """
    slow = n               # 每次走一步
    fast = get_next(n)     # 先走一步，再在循环里多走一步

    while fast != 1 and slow != fast:
        slow = get_next(slow)               # 慢指针走一步
        fast = get_next(get_next(fast))     # 快指针走两步

    return fast == 1   # 若快指针最终落在 1，说明是 Happy Number
```

#### 复杂度  

- **时间复杂度**：`O(k)`，和暴力解相同，只是每一步的常数因子更小（因为没有 `set` 的查询）。  
- **空间复杂度**：`O(1)`，只用了几个整数变量，**不随输入大小增长**，这就是最优的地方。

## 心得  

- 这道题的核心技巧是 **循环检测**（判断是否进入了无限循环）。  
- 常用的检测环的方法有两种：  
  1. 哈希表记录已经出现的状态（适用于大多数需要“记忆”历史的题）。  
  2. 快慢指针（Floyd 判圈），在只需要判断“是否有环”且状态转移函数固定时，能够把空间降到 O(1)。  
- 类似题目：  
  - **Linked List Cycle**（判断链表是否有环）  
  - **Find the Duplicate Number**（利用快慢指针在数组中找重复数）  
  - **Powerful Integer**（需要判断数列是否进入循环）  
- 一句话总结解题钥匙：**把“是否出现环”转化为“快指针能否追上慢指针”。**

## 反思  

- **第一反应**：直接写循环，用 `set` 把出现的数字记下来，看到 `1` 就返回 `True`，否则如果再次出现相同数字就返回 `False`。  
- **最容易踩的坑**：  
  - 忘记对 `n = 1` 的特殊处理，直接进入循环会导致不必要的计算。  
  - 计算各位平方和时没有处理 `0`，导致死循环（例如 `100 → 1` 正确，但若写错可能会停在 `0`）。  
  - 对于大整数，若使用 `str` 转换会稍慢，但不会影响正确性。  
- **下次遇到同类题**：第一步先思考“是否需要记住历史”。如果只需要判断“有没有环”，立刻联想到 **快慢指针**，可以先写出 O(1) 空间的方案，再视情况决定是否使用哈希表做更直观的实现。
