# #113. 路径总和 II / Path Sum II

> 难度：中等 · 标签：Backtracking、Tree、Depth-First Search、Binary Tree · [LeetCode 链接](https://leetcode.com/problems/path-sum-ii/)

---

## 题目（英文原版）

**Description**

Given the root of a binary tree and an integer targetSum, return all root-to-leaf paths where the sum of the node values in the path equals targetSum. Each path should be returned as a list of the node values, not node references.
A root-to-leaf path is a path starting from the root and ending at any leaf node. A leaf is a node with no children.

**Examples**

**Example 1:**

```
Input: root = [5,4,8,11,null,13,4,7,2,null,null,5,1], targetSum = 22
Output: [[5,4,11,2],[5,8,4,5]]
Explanation: There are two paths whose sum equals targetSum:
5 + 4 + 11 + 2 = 22
5 + 8 + 4 + 5 = 22
```

**Example 2:**

```
Input: root = [1,2,3], targetSum = 5
Output: []
```

**Example 3:**

```
Input: root = [1,2], targetSum = 0
Output: []
```

**Constraints**

- The number of nodes in the tree is in the range [0, 5000].
- -1000 <= Node.val <= 1000
- -1000 <= targetSum <= 1000

根到叶子路径是指从根节点出发，终止于任意叶子节点的路径。叶子节点是指没有子节点的节点。

**输出**: `[[5,4,11,2],[5,8,4,5]]`  
**解释**: 有两条路径的节点值之和等于目标和：  
- 5 + 4 + 11 + 2 = 22  
- 5 + 8 + 4 + 5 = 22  

**示例 2**  
**输入**: `root = [1,2,3], targetSum = 5`  
**输出**: `[]`  

**示例 3**  
**输入**: `root = [1,2], targetSum = 0`  
**输出**: `[]`  

**约束条件**  
- 树中节点的数量在 `[0, 5000]` 范围内。  
- `-1000 <= Node.val <= 1000`  
- `-1000 <= targetSum <= 1000`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是「把树上所有根到叶子的路径都枚举出来，然后检查每条路径的节点值之和是否等于 `targetSum`」。  
这一步可以用 **深度优先搜索（DFS）** 完成：

1. 从根节点出发，沿着左子树或右子树一直往下走，直到碰到叶子节点（没有左子树也没有右子树）。  
2. 在递归的过程中，把走过的节点值保存到一个列表 `path` 中。  
3. 到达叶子时，把 `path` 中所有数相加（或者在递归时把当前的累计和 `cur_sum` 传下来），如果等于 `targetSum`，就把这条 `path` 复制一份加入答案。  

> **类比**：把二叉树想象成一棵“决策树”，每一次向左/向右走就是一次“选择”。把所有从根到叶子的选择记录下来，就像把所有可能的“旅行路线”写进笔记本。

> **为什么正确**：根到叶子的每一条路径都恰好遍历一次，且我们在遍历的同时检查路径和是否满足要求，符合题目「返回所有满足条件的根到叶路径」的定义。

#### 代码（Python）

```python
# Definition for a binary tree node.
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


def pathSum(root, targetSum):
    """
    暴力版：遍历所有根到叶的路径，满足条件的就复制一份加入结果。
    """
    res = []                     # 最终返回的答案列表

    def dfs(node, cur_path, cur_sum):
        if not node:             # 空节点直接返回
            return

        # 把当前节点加入路径，并更新累计和
        cur_path.append(node.val)
        cur_sum += node.val

        # 判断是否为叶子节点
        if not node.left and not node.right:
            if cur_sum == targetSum:          # 叶子且满足目标和
                # 复制一份路径加入答案（必须复制，否则后面回溯会把它改掉）
                res.append(list(cur_path))
        else:
            # 继续向左、右子树搜索
            dfs(node.left, cur_path, cur_sum)
            dfs(node.right, cur_path, cur_sum)

        # 回溯：离开当前节点时把它从路径中弹出
        cur_path.pop()

    dfs(root, [], 0)
    return res
```

#### 复杂度

- **时间复杂度：** `O(N²)`（大白话：最坏情况下每条根到叶的路径长度是 `N`，我们在每条叶子路径上都要复制一次列表，复制的代价是路径长度，所以总体上可能出现 `N` 条路径 × `N` 长度的复制，约等于 `N²`）。  
- **空间复杂度：** `O(N)`（递归栈深度最坏是树的高度，最坏情况下高度等于节点数 `N`，加上保存路径的列表同样最多 `N` 长度）。

---

### 2. 最优解

#### 思路  

暴力解的 **慢点** 在于每到达叶子时都要复制整条路径。其实我们只需要在「找到满足条件的路径」时才复制一次，平时可以直接在同一个列表上做**原地修改 + 回溯**，这就是 **回溯（Backtracking）** 的核心思想：

1. **原地维护路径**：用一个全局列表 `path` 保存当前递归沿途的节点值。进入子树时 `append`，离开子树时 `pop`（这一步叫回溯）。这样整棵树只维护一条「活动」路径，省掉大量的列表创建。
2. **累计和随递归传递**：把当前已经累加的和 `cur_sum` 作为参数向下传递，避免每次都重新遍历 `path` 求和。
3. **仅在满足条件时复制**：当我们在叶子节点发现 `cur_sum == targetSum`，此时 `path` 正好是满足条件的完整路径，只需要 `res.append(path.copy())` 把它复制一份加入答案。

这样，每个节点只被访问一次，且只在必要时复制路径，时间复杂度降到线性。

> **类比**：想象你在爬山，`path` 是你背上的背包，装着已经走过的路标。每走一步往背包里放一个路标（`append`），爬到山顶（叶子）时检查背包里所有路标的总重量是否等于目标。如果不对，就把最近放进去的路标拿出来（`pop`）继续往别的方向爬。背包只是一只，永远不需要复制多个。

#### 代码（Python）

```python
def pathSum(root, targetSum):
    """
    最优解：使用回溯，只在找到满足条件的路径时才复制一次。
    """
    res = []                     # 保存所有满足条件的路径

    def backtrack(node, cur_sum):
        if not node:
            return

        # 将当前节点加入路径，并更新累计和
        path.append(node.val)
        cur_sum += node.val

        # 叶子节点且满足目标和 → 复制当前路径加入答案
        if not node.left and not node.right and cur_sum == targetSum:
            res.append(path.copy())   # 只复制一次

        else:                         # 继续向左右子树探索
            backtrack(node.left, cur_sum)
            backtrack(node.right, cur_sum)

        # 回溯：离开当前节点，撤销对 path 的修改
        path.pop()

    path = []                     # 全局维护的活动路径
    backtrack(root, 0)
    return res
```

#### 复杂度

- **时间复杂度：** `O(N)`（每个节点只访问一次，所有操作都是 `O(1)`，只有在找到合法路径时才复制一次路径，最多复制 `leaf` 条，`leaf ≤ N`，所以仍然是线性）。  
  > 与暴力解对比：从“每条叶子都要复制整条路径”降到“只有合法路径才复制”，大幅降低了常数时间。

- **空间复杂度：** `O(H)`（递归栈的深度等于树的高度 `H`，以及活动路径 `path` 的长度也是 `H`，最坏情况下 `H = N`，但一般二叉树高度远小于节点数）。

## 心得

- **核心技巧**：**回溯**（Backtracking）——在遍历树/图的过程中原地维护状态，递归返回时撤销修改。
- **适用题型**：
  1. 所有「列举所有满足条件的路径」类题目（如 LeetCode 113. Path Sum I、257. Binary Tree Paths）。
  2. 「组合、排列」类子集搜索（如 39. Combination Sum、46. Permutations）。
  3. 「子集、子序列」等需要逐步构造答案的 DP/搜索题。
- **一句话总结**：**只在需要输出答案时复制路径，平时用同一条路径配合回溯即可**。

## 反思

- **第一反应**：看到「根到叶」和「路径和」立即想到 **DFS**，因为树的遍历天然适合递归实现。
- **最容易踩的坑**：
  - **忘记回溯**：`pop` 掉路径的最后一个节点，否则后面的递归会把前面的路径也带上，导致答案错误。
  - **叶子节点的判断**：必须同时检查 `node.left is None and node.right is None`，否则把非叶子节点的中间路径误当作答案。
  - **复制路径的时机**：必须在满足条件的 **叶子** 处复制，否则会把后续回溯修改的路径也加入答案。
- **下次遇到同类题的第一步**：先写出 **DFS + 回溯** 的框架，明确「状态」是什么（本题是路径列表 + 当前和），再判断在何时需要「把状态保存下来」作为答案。这样可以避免一开始就写出大量复制代码导致效率低下。
