# #9. 回文数 / Palindrome Number

> 难度：简单 · 标签：Math · [LeetCode 链接](https://leetcode.com/problems/palindrome-number/)

---

## 题目（英文原版）

**Description**

Given an integer x, return true if x is a palindrome, and false otherwise.

**Examples**

**Example 1:**

```
Input: x = 121
Output: true
Explanation: 121 reads as 121 from left to right and from right to left.
```

**Example 2:**

```
Input: x = -121
Output: false
Explanation: From left to right, it reads -121. From right to left, it becomes 121-. Therefore it is not a palindrome.
```

**Example 3:**

```
Input: x = 10
Output: false
Explanation: Reads 01 from right to left. Therefore it is not a palindrome.
```

**Constraints**

- -231 <= x <= 231 - 1

---

## 题目（中文翻译）

给定一个整数（integer）`x`，如果 `x` 是回文数（palindrome）则返回 `true`，否则返回 `false`。

**示例 1**  
**输入**: `x = 121`  
**输出**: `true`  
**解释**: 121 从左到右和从右到左读都是 121。

**示例 2**  
**输入**: `x = -121`  
**输出**: `false`  
**解释**: 从左到右读是 -121，而从右到左读变成 121-，因此不是回文数。

**示例 3**  
**输入**: `x = 10`  
**输出**: `false`  
**解释**: 从右到左读是 01，所以不是回文数。

**约束条件**  
- $-2^{31} \le x \le 2^{31} - 1$

---

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  
最直接的想法是把整数 **x** 当成“字符序列”来处理。  
- 把 **x** 转成字符串（就像把数字写在纸上），比如 `12321` → `"12321"`。  
- 然后把这个字符串反转（相当于把纸翻过去），再和原来的字符串比较是否相等。  
- 如果相等，就说明从左往右读和从右往左读是一样的，即回文。  

**用到的数据结构**：  
- **字符串**：相当于我们平时写的文字，Python 中的 `str` 本身就支持切片、反转等操作。  
- **比较运算**：直接用 `==` 判断两段文字是否完全相同。  

**为什么正确**：  
- 回文的定义本身就是“正序和逆序完全相同”。把整数转成字符序列后，正序就是原字符串，逆序就是反转后的字符串。只要两者相同，原整数必然是回文。  

**时间/空间复杂度**：  
- 时间：我们需要遍历一次字符串来产生反转，长度记为 **n**（即数字的位数），所以是 **O(n)**。这里的 **O** 表示“数量级”，比如 n=5 时，操作大约是 5 次左右。  
- 空间：生成了一个新的反转字符串，需要额外 **O(n)** 的空间来存放。  

#### 代码（Python）  
```python
def isPalindrome(x: int) -> bool:
    # 负数直接返回 False，因为符号位 '-' 不会出现在回文的右边
    if x < 0:
        return False

    s = str(x)               # 把整数转换成字符串，例如 121 -> "121"
    rev = s[::-1]            # 字符串切片逆序，相当于翻转纸张
    return s == rev          # 正序和逆序相等则是回文
```

#### 复杂度  
- **时间复杂度**：O(n) —— 需要遍历 n 位数字一次。  
- **空间复杂度**：O(n) —— 需要额外存放长度为 n 的反转字符串。  

---  

### 2. 最优解  

#### 思路  
暴力解的“慢”在于 **使用了额外的字符串空间**，并且把整个数字全部翻转。我们可以只 **翻转数字的一半**，这样既避免了额外的 O(n) 空间，也防止了整数翻转时可能的 **溢出**（题目提示要注意）。  

优化步骤如下：  

1. **特殊情况**  
   - 负数一定不是回文（因为左边有 `-`，右边没有），直接返回 `False`。  
   - 末位是 0 的正数也不可能是回文（唯一例外是 0 本身），因为回文数的首位不可能是 0。  

2. **把数字的后半段翻转**  
   - 设 `rev` 为已经翻转好的后半段。  
   - 每次把 `x` 的最后一位取出来 `x % 10`，加入 `rev = rev * 10 + last_digit`。  
   - 同时把原数字 `x` 去掉最后一位 `x //= 10`。  
   - 当 `rev` 的位数 **大于等于** `x` 时，说明已经翻到数字的中间位置。  

3. **比较**  
   - 如果数字位数为偶数，`x` 和 `rev` 应该完全相等。  
   - 如果数字位数为奇数，中间的那一位可以忽略（比如 12321，翻转后得到 123），只要 `x == rev // 10` 即可。  

这样我们只用了 **常数级别的额外空间**（几个整数变量），时间仍然是遍历一半的位数，即 **O(n)**，但空间降到了 **O(1)**。  

#### 代码（Python）  
```python
def isPalindrome(x: int) -> bool:
    # 负数以及末位为 0（但不是 0 本身）的正数直接返回 False
    if x < 0 or (x % 10 == 0 and x != 0):
        return False

    rev = 0               # 用来存放翻转后的一半数字
    while x > rev:        # 当原数字还没有被“追上”时继续循环
        rev = rev * 10 + x % 10   # 取出原数字的最后一位并加入 rev 的末尾
        x //= 10                  # 去掉原数字的最后一位

    # 循环结束后有两种情况：
    # 1. 位数为偶数：此时 x 与 rev 完全相等
    # 2. 位数为奇数：此时 rev 多了中间的那一位，去掉即可
    return x == rev or x == rev // 10
```

#### 复杂度  
- **时间复杂度**：O(n) —— 只遍历了数字的一半位数。这里的 **n** 仍是数字的位数，但实际操作次数大约是 n/2。  
- **空间复杂度**：O(1) —— 只用了几个整数变量，和位数无关。

## 心得  

- 这道题考察 **“数字反转”** 与 **“空间优化”** 的技巧。  
- 同类技巧常出现在：  
  1. **整数反转**（LeetCode 7）——需要防止溢出。  
  2. **回文链表**（LeetCode 234）——可以通过快慢指针找到链表中点并逆序后半段。  
- **解题钥匙**：只翻转**必要的部分**，避免不必要的空间和可能的溢出。  

## 反思  

- **第一反应**：把数字转成字符串直接比较——最直观但占用额外空间。  
- **最容易踩的坑**：  
  - 负数的处理（`-` 符号）。  
  - 末位为 0 的正数（如 `10`）不是回文。  
  - 在翻转完整个数字时可能会超过 32 位整数范围，导致溢出。  
- **下次遇到类似题**，第一步应该思考**是否可以只处理一半**（比如一半翻转、快慢指针），再决定是否需要额外空间。
