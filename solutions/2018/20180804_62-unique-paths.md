# #62. 不同路径 / Unique Paths

> 难度：中等 · 标签：Math、Dynamic Programming、Combinatorics · [LeetCode 链接](https://leetcode.com/problems/unique-paths/)

---

## 题目（英文原版）

**Description**

There is a robot on an m x n grid. The robot is initially located at the top-left corner (i.e., grid[0][0]). The robot tries to move to the bottom-right corner (i.e., grid[m - 1][n - 1]). The robot can only move either down or right at any point in time.
Given the two integers m and n, return the number of possible unique paths that the robot can take to reach the bottom-right corner.
The test cases are generated so that the answer will be less than or equal to 2 * 109.

**Examples**

**Example 1:**

```
Input: m = 3, n = 7
Output: 28
```

**Example 2:**

```
Input: m = 3, n = 2
Output: 3
Explanation: From the top-left corner, there are a total of 3 ways to reach the bottom-right corner:
1. Right -> Down -> Down
2. Down -> Down -> Right
3. Down -> Right -> Down
```

**Constraints**

- 1 <= m, n <= 100

---

## 题目（中文翻译）

有一个机器人位于 `m x n` 网格上。机器人最初位于左上角（即 `grid[0][0]`），目标是移动到右下角（即 `grid[m - 1][n - 1]`）。机器人在任意时刻只能向下（down）或向右（right）移动一次。

给定整数 `m` 和 `n`，返回机器人到达右下角的不同路径总数。  
题目保证答案不超过 `2 * 10^9`。

**示例 1**  
**输入**: `m = 3, n = 7`  
**输出**: `28`

**示例 2**  
**输入**: `m = 3, n = 2`  
**输出**: `3`  
**解释**: 从左上角到右下角共有 3 条路径：  
1. 右 → 下 → 下  
2. 下 → 下 → 右  
3. 下 → 右 → 下

**约束条件**  
- `1 <= m, n <= 100`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把机器人所有可能的走法都枚举一遍，然后计数。  
- **枚举方式**：从左上角出发，每一步只能往「右」或「下」走。我们可以用递归（DFS）模拟机器人一步一步移动的过程，直到到达右下角。每走到终点一次，就算作一条合法路径。  
- **使用的数据结构**：递归调用栈本身就相当于一个「记忆」结构，记录了当前已经走了多少步以及当前位置。对初学者来说，递归就像在玩「走迷宫」的游戏：每走一步就把当前位置压进去，走不通了再弹出来回溯。

> **为什么这个方法能得到正确答案？**  
> 因为我们穷举了所有可能的「右」或「下」的组合，且每一种组合只会被走一次（递归的自然回溯保证了不重复计数），所以最终计数的就是所有合法路径的总数。

#### 代码（Python）

```python
def uniquePaths_bruteforce(m: int, n: int) -> int:
    """
    暴力 DFS：递归遍历所有可能的走法
    """
    def dfs(x: int, y: int) -> int:
        # 到达右下角，算作一条合法路径
        if x == m - 1 and y == n - 1:
            return 1
        paths = 0
        # 向右走（如果还没有超出右边界）
        if y + 1 < n:
            paths += dfs(x, y + 1)   # 递归调用，记一次向右的选择
        # 向下走（如果还没有超出下边界）
        if x + 1 < m:
            paths += dfs(x + 1, y)   # 递归调用，记一次向下的选择
        return paths

    return dfs(0, 0)   # 从左上角 (0,0) 开始搜索
```

#### 复杂度  

- **时间复杂度**：`O(2^{m+n})`（指数级）  
  - 每一步都有两个选择（右或下），而从左上到右下总共要走 `m-1 + n-1` 步，所以大致会产生 `2^{(m+n-2)}` 条路径。用大白话说，就是随着网格变大，计算时间会“飞速”增长，几分钟的代码在 10×10 的网格上已经会卡死。

- **空间复杂度**：`O(m+n)`（递归栈深度）  
  - 递归最深的层数等于走到终点需要的步数 `m-1 + n-1`，相当于把每一步的坐标压在调用栈里。除去递归本身占用的空间，算法本身不需要额外的数组或哈希表。

> **小结**：暴力解思路简单、代码短，但只能在 `m,n` 很小（比如 ≤5）的情况下跑得动，实际面试和线上评测需要更快的办法。

### 2. 最优解

#### 思路  

从暴力解可以看到，**大量的重复计算**是主要瓶颈：不同路径在中间某一步会到达同一个格子，而我们会把从该格子到终点的路径数重新算很多遍。  
要消除重复，就需要**把“子问题的答案”记下来**，以后再需要时直接取用，这正是**动态规划（Dynamic Programming, DP）**的核心思想。

**关键点一：子问题定义**  
设 `dp[i][j]` 为从左上角走到格子 `(i, j)` 的唯一路径数（只考虑走到这里的方式，不必继续往后）。  
- 起点 `dp[0][0] = 1`（机器人已经在这里，算作一种“空路径”）。
- 任意格子只能从上面 (`i-1, j`) 或左边 (`i, j-1`) 进入，所以  
  `dp[i][j] = dp[i-1][j] + dp[i][j-1]`。

**关键点二：填表顺序**  
因为 `dp[i][j]` 只依赖左上和上方的格子，只要我们按行从左到右、按列从上到下遍历，就能保证在计算 `dp[i][j]` 时，它的两个来源已经算好。

**关键点三：空间优化**  
观察公式只需要前一行的数据或同一行的左侧数据。我们可以把二维表压缩成一维数组 `dp[j]`，遍历每一行时把 `dp[j]` 更新为 `dp[j] + dp[j-1]`，这样空间从 `O(m*n)` 降到 `O(n)`（取较小的维度即可）。

> **类比**：把 `dp` 表想象成一本“走路手册”。手册的每一页记录了“到达某格子有几种走法”。我们一次写完一页（对应一行），随后把旧的页翻过去，只保留最新的那一页，这样就不需要把整本手册全部保存。

#### 代码（Python）

```python
def uniquePaths_dp(m: int, n: int) -> int:
    """
    动态规划 + 空间压缩（只用一维数组）
    """
    # 令 dp[j] 表示当前遍历到的行中，第 j 列格子的路径数
    dp = [1] * n               # 第 0 行所有格子只能一直向右走，路径数都是 1
    # 从第 1 行开始遍历（第 0 行已经在 dp 中表示了）
    for i in range(1, m):
        for j in range(1, n):
            # dp[j]（上方格子的路径数）+ dp[j-1]（左侧格子的路径数）
            dp[j] += dp[j - 1]
    return dp[-1]              # 最右下角对应 dp[n-1]
```

> **如果不想压缩空间**，也可以直接写成二维 DP：
> ```python
> dp = [[1] * n for _ in range(m)]
> for i in range(1, m):
>     for j in range(1, n):
>         dp[i][j] = dp[i-1][j] + dp[i][j-1]
> return dp[m-1][n-1]
> ```

#### 复杂度  

- **时间复杂度**：`O(m * n)`  
  - 我们遍历了整个网格一次，每个格子只做了常数次加法。把“大白话”说出来：如果网格是 10×10，最多只算 100 次，非常快。

- **空间复杂度**：`O(n)`（或 `O(m)`，取决于把哪一维压缩成一维）  
  - 只需要一个长度为列数（或行数）的数组来存放上一行的结果。相比暴力解的递归栈，这个空间是线性的、可控的。

> **对比**：暴力解指数级时间、线性空间；DP 解多项式时间、线性空间，实用性立刻提升。

## 心得

- **核心技巧**：**动态规划**——把“大问题”拆成“子问题”，用记忆化（表格）避免重复计算。  
- **适用的题型**（类似思路）  
  1. `Climbing Stairs`（爬楼梯）——求到第 `n` 步的方式数，转移方程 `dp[i] = dp[i-1] + dp[i-2]`。  
  2. `Minimum Path Sum`（最小路径和）——在网格中找路径最小权值，同样使用 `dp[i][j] = min(dp[i-1][j], dp[i][j-1]) + grid[i][j]`。  
  3. `Edit Distance`（编辑距离）——两个字符串的最小编辑次数，用二维 DP 表格解决。  

- **一句话总结解题钥匙**：  
  “把每一步的选择数累计下来，记住已经算好的子结果，后面直接复用。”

## 反思

- **第一反应**：直接写递归穷举，想把所有可能的走法都列出来。  
- **最容易踩的坑**  
  - **指数爆炸**：递归会产生大量重复子路径，导致时间超限。  
  - **边界处理**：`dp[0][*]` 与 `dp[*][0]` 必须初始化为 1，否则会出现 “访问未定义” 或错误计数。  
  - **空间压缩时的顺序**：更新一维 `dp` 时必须从左到右遍历，否则会把还未使用的旧值覆盖掉，导致错误。  

- **下次遇到同类题**，第一步应该先**思考子问题的定义**（例如“到达某格子有几种方式？”），再检查**状态转移**是否只依赖已经计算好的子状态，这样可以直接写出 DP 框架，而不是先走暴力路线。
