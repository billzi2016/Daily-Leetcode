# #16. 最接近目标的三数之和 / 3Sum Closest

> 难度：中等 · 标签：Array、Two Pointers、Sorting · [LeetCode 链接](https://leetcode.com/problems/3sum-closest/)

---

## 题目（英文原版）

**Description**

Given an integer array nums of length n and an integer target, find three integers in nums such that the sum is closest to target.
Return the sum of the three integers.
You may assume that each input would have exactly one solution.

**Examples**

**Example 1:**

```
Input: nums = [-1,2,1,-4], target = 1
Output: 2
Explanation: The sum that is closest to the target is 2. (-1 + 2 + 1 = 2).
```

**Example 2:**

```
Input: nums = [0,0,0], target = 1
Output: 0
Explanation: The sum that is closest to the target is 0. (0 + 0 + 0 = 0).
```

**Constraints**

- 3 <= nums.length <= 500
- -1000 <= nums[i] <= 1000
- -104 <= target <= 104

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的办法就是把数组里所有可能的三元组都枚举一遍，算出它们的和，再和 `target` 比较谁更接近。  

- **枚举三元组**：我们可以用三层循环，分别选出下标 `i、j、k`（要求 `i < j < k`），这相当于“从一堆水果里挑出三种不同的水果”。  
- **求和并比较**：每得到一个三元组，就把它们的数相加得到 `s = nums[i] + nums[j] + nums[k]`，然后看 `|s - target|`（即差的绝对值）是否比当前记录的最小差更小。  
- **记录答案**：如果更小，就把 `s` 保存下来，继续遍历所有组合。  

> **为什么这个方法一定能得到答案？**  
> 因为我们把 **所有** 合法的三元组都检查了一遍，最接近 `target` 的那一个必然在其中，被记录下来。

> **生活类比**：  
> 把数组想象成一本字典，想找出三个单词的字母数之和最接近某个数字。暴力解就像把字典里每三个单词都拿出来算一遍，保证不遗漏。

#### 代码（Python）

```python
from typing import List

def threeSumClosest_brute(nums: List[int], target: int) -> int:
    n = len(nums)
    # 初始化答案为任意一个合法三元组的和（这里随便取前3个）
    best_sum = nums[0] + nums[1] + nums[2]
    best_diff = abs(best_sum - target)

    # 三层循环枚举所有 i < j < k
    for i in range(n - 2):            # 第一个数的下标
        for j in range(i + 1, n - 1): # 第二个数的下标
            for k in range(j + 1, n): # 第三个数的下标
                cur_sum = nums[i] + nums[j] + nums[k]   # 当前三数之和
                cur_diff = abs(cur_sum - target)        # 与目标的距离

                # 如果更接近，就更新答案
                if cur_diff < best_diff:
                    best_diff = cur_diff
                    best_sum = cur_sum

    return best_sum
```

#### 复杂度  

- **时间复杂度**：`O(n³)`  
  - 三层循环每层最多遍历 `n` 次，整体是 `n × n × n`。  
  - “O(n³)” 可以想象成“把 n 块巧克力排成三行，每行都要和其他两行的每块巧克力配对”，数量会非常大，实际运行会慢。

- **空间复杂度**：`O(1)`  
  - 只用了常数个额外变量（`best_sum`、`best_diff` 等），不随 `n` 增长。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **大量重复的遍历**：我们对每一个三元组都重新计算，而很多信息其实可以共享。下面一步步把它优化掉。

1. **先排序**  
   把数组从小到大排好序。排序后，数值的相对大小一目了然，后面可以利用“左指针/右指针”快速移动。  
   - 类比：把水果按照重量从轻到重排好，这样想要找出总重量最接近目标的三种水果时，就可以从两头往中间挑。

2. **固定第一个数，使用双指针找另外两个数**  
   - 设第一个数的下标为 `i`（从 `0` 到 `n-3`），它左边的数已经确定。  
   - 剩下的子数组 `[i+1, n-1]` 用两个指针 `left`（指向子数组最左）和 `right`（指向最右）来遍历。  
   - 计算 `cur_sum = nums[i] + nums[left] + nums[right]`。  
   - **比较** `cur_sum` 与 `target` 的差距：  
     - 若 `cur_sum == target`，说明已经找到了最接近（差为 0），直接返回。  
     - 若 `cur_sum < target`，说明总和太小，需要把左指针右移（增大 `cur_sum`）。  
     - 若 `cur_sum > target`，说明总和太大，需要把右指针左移（减小 `cur_sum`）。  
   - 每一步都更新当前最接近的答案。  

3. **为什么双指针有效？**  
   - 排序保证了左指针右移会 **只增大** 总和，右指针左移会 **只减小** 总和。这样我们可以在一次遍历中把所有可能的 `left/right` 组合检查完，而不必枚举每一种组合。  
   - 整体的遍历次数是：外层 `i` 循环 `n` 次，内层 `left/right` 指针在每一次 `i` 中最多移动 `n` 步（因为每次移动后指针不会再回头），所以总共是 `O(n²)`。

#### 代码（Python）

```python
from typing import List

def threeSumClosest(nums: List[int], target: int) -> int:
    nums.sort()                     # 先排序，O(n log n)
    n = len(nums)

    # 初始化答案为前3个数的和（因为一定有解）
    best_sum = nums[0] + nums[1] + nums[2]

    for i in range(n - 2):          # 固定第一个数
        left, right = i + 1, n - 1  # 双指针分别指向 i 右边的最左和最右

        while left < right:        # 当两指针未相遇时
            cur_sum = nums[i] + nums[left] + nums[right]

            # 如果已经等于 target，直接返回，因为不可能更接近了
            if cur_sum == target:
                return cur_sum

            # 更新最接近的答案
            if abs(cur_sum - target) < abs(best_sum - target):
                best_sum = cur_sum

            # 根据 cur_sum 与 target 的大小决定指针移动方向
            if cur_sum < target:
                left += 1          # 总和太小，左指针右移让总和增大
            else:
                right -= 1         # 总和太大，右指针左移让总和减小

    return best_sum
```

#### 复杂度  

- **时间复杂度**：`O(n²)`  
  - 排序是 `O(n log n)`，但主循环的双指针遍历是 `O(n²)`，整体以最大的 `O(n²)` 为准。  
  - “O(n²)” 可以想象成“把 n 块巧克力排成两行，每行的每块都要和另一行的每块配对”，比 `O(n³)` 少了一个层级，运行速度提升显著。

- **空间复杂度**：`O(1)`（不计排序使用的栈空间）  
  - 只用了固定数量的额外变量，和输入规模无关。

## 心得

- **核心技巧**：先排序 + 双指针  
  - 这套组合常用于 “在有序数组里找两数/三数之和” 的问题，因为它把原本指数级的搜索压缩到二次方级别。

- **适用的题型**  
  1. `3Sum`（找出所有和为 0 的三元组）  
  2. `4Sum`（找出所有和为 target 的四元组）  
  3. `Two Sum - 输入已排序`（直接用双指针）  

- **一句话总结解题钥匙**：  
  > “先把数据排好序，让指针只会单向前进/后退，就能用线性扫描把所有组合高效检查完。”

## 反思

- **第一反应**：看到“三个数的和最接近 target”，立刻想到“遍历所有三元组”。这就是暴力思路，也是最自然的起点。  
- **最容易踩的坑**  
  - **遗漏负数**：数组中可能有负数，直接比较大小时要用绝对值 `abs`。  
  - **指针移动错误**：在 `cur_sum < target` 时一定是左指针右移，而不是右指针左移，否则会陷入死循环。  
  - **初始化答案**：不能随意设为 `0`，要选一个合法的三元组和（比如前 3 个数的和），否则在所有和都为负数的情况下会出错。  

- **下次遇到同类题**：  
  1. **先检查能否排序**（大多数和/差类问题都可以），  
  2. **确定固定几个数**（这里是一个），其余使用 **双指针** 线性扫描，  
  3. **在遍历过程中随时更新最优解**（比如最小差、最大值等）。
