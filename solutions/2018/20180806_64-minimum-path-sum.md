# #64. 最小路径和 / Minimum Path Sum

> 难度：中等 · 标签：Array、Dynamic Programming、Matrix · [LeetCode 链接](https://leetcode.com/problems/minimum-path-sum/)

---

## 题目（英文原版）

**Description**

Given a m x n grid filled with non-negative numbers, find a path from top left to bottom right, which minimizes the sum of all numbers along its path.
Note: You can only move either down or right at any point in time.

**Examples**

**Example 1:**

```
Input: grid = [[1,3,1],[1,5,1],[4,2,1]]
Output: 7
Explanation: Because the path 1 → 3 → 1 → 1 → 1 minimizes the sum.
```

**Example 2:**

```
Input: grid = [[1,2,3],[4,5,6]]
Output: 12
```

**Constraints**

- m == grid.length
- n == grid[i].length
- 1 <= m, n <= 200
- 0 <= grid[i][j] <= 200

输入: `grid = [[1,3,1],[1,5,1],[4,2,1]]`  
输出: `7`

输入: `grid = [[1,2,3],[4,5,6]]`  
输出: `12`

**约束条件**

- `m == grid.length`
- `n == grid[i].length`
- `1 <= m, n <= 200`
- `0 <= grid[i][j] <= 200`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**把所有可能的路径都枚举出来，然后把每条路径上的数字相加，找最小的那个**。  
因为只能向右或向下走，这相当于在一个 `m × n` 的格子里从左上角走到右下角的“走迷宫”。  
我们可以用递归（深度优先搜索）模拟每一步的选择：

- 当前在格子 `(i, j)`，可以往 **右** 走到 `(i, j+1)`，或者往 **下** 走到 `(i+1, j)`（只要没有越界）。
- 把当前格子的数值加入路径和，然后继续向下或向右搜索，直到到达右下角。

这就像在“字典”里查单词，每一次选择都是一次“翻页”，最终把所有“翻页路径”记录下来，挑最小的那条。

**为什么这个方法一定能得到正确答案**  
递归会遍历 **所有** 合法的走法，保证不漏掉任何可能的路径。每条路径的和都被计算一次，最小值自然就是答案。

**时间/空间复杂度**  
- 每个格子有两种选择（右或下），路径长度固定为 `m + n - 2` 步。所有可能的路径数是组合数 `C(m+n-2, m-1)`，随 `m,n` 指数级增长。可以粗略记为 **指数时间** `O(2^{m+n})`，在最坏情况下几乎不可接受。  
- 递归调用栈的深度等于路径长度 `m+n-2`，所以空间是 **线性** `O(m+n)`（不包括存放所有路径的额外空间）。

#### 代码（Python）

```python
from typing import List

def min_path_sum_brute(grid: List[List[int]]) -> int:
    m, n = len(grid), len(grid[0])
    # 记录全局最小路径和，初始设为无限大
    best = float('inf')

    def dfs(i: int, j: int, cur_sum: int):
        """深度优先搜索，i,j 为当前坐标，cur_sum 为已经累加的路径和"""
        nonlocal best
        # 把当前格子的数加入路径和
        cur_sum += grid[i][j]

        # 到达右下角，更新最小值
        if i == m - 1 and j == n - 1:
            best = min(best, cur_sum)
            return

        # 向右走（如果未越界）
        if j + 1 < n:
            dfs(i, j + 1, cur_sum)

        # 向下走（如果未越界）
        if i + 1 < m:
            dfs(i + 1, j, cur_sum)

    dfs(0, 0, 0)          # 从左上角出发，当前路径和为 0
    return best
```

#### 复杂度

- **时间复杂度**：`O(2^{m+n})`（指数级），因为会遍历所有可能的路径。  
  大白话：格子稍微大一点（比如 10×10），路径数量已经是几千上万，跑不完。
- **空间复杂度**：`O(m+n)`，递归栈深度等于走到右下角的步数。

### 2. 最优解

#### 思路  

从暴力解我们可以看到 **瓶颈** 在于**大量重复计算**：很多不同的路径会在同一个格子相交，而我们每次都重新从头算到这个格子，导致重复劳动。

**关键想法**：  
- 对于每个格子 `(i, j)`，从左上角到达它的最小路径和只和它**左边**和**上边**的格子有关。  
- 因此我们可以把“从左上角走到这里的最小和” **保存下来**，后面的格子直接使用这个已经算好的结果，而不是重新遍历。

这正是**动态规划（Dynamic Programming）**的核心：把大问题拆成子问题，子问题只算一次，保存结果供后面使用。

**一步步推导**：

1. **定义子问题**  
   `dp[i][j]` 表示从左上角 `(0,0)` 到达格子 `(i,j)` 的最小路径和。

2. **状态转移方程**  
   - 若只能从上面走下来：`dp[i][j] = dp[i-1][j] + grid[i][j]`  
   - 若只能从左边走过来：`dp[i][j] = dp[i][j-1] + grid[i][j]`  
   - 两者都有可能时，取较小的那条路：  
     `dp[i][j] = min(dp[i-1][j], dp[i][j-1]) + grid[i][j]`

3. **初始化**  
   - 起点 `dp[0][0] = grid[0][0]`（路径只能从自己开始）。  
   - 第一行只能从左边来到右边，第一列只能从上边往下：  
     `dp[0][j] = dp[0][j-1] + grid[0][j]`  
     `dp[i][0] = dp[i-1][0] + grid[i][0]`

4. **遍历顺序**  
   按行或按列从左上到右下依次填表格，保证在计算 `dp[i][j]` 时，上方和左方的值已经算好。

5. **答案**  
   最右下角的格子 `dp[m-1][n-1]` 就是所求的最小路径和。

**空间优化**  
观察到每一次只用到**当前行**和**上一行**的值，甚至只需要**左侧**的一个值。于是可以把二维 `dp` 表压缩成**一维数组** `dp[n]`，在遍历每行时直接覆盖。

**类比**：把二维表想成一张“记事本”，每写完一行后把上一行的内容擦掉，只保留当前行的累计最小和，省下不少纸张（内存）。

#### 代码（Python）

```python
from typing import List

def min_path_sum(grid: List[List[int]]) -> int:
    """
    动态规划 + 一维滚动数组
    dp[j] 表示当前遍历到的行中，第 j 列的最小路径和
    """
    m, n = len(grid), len(grid[0])
    dp = [0] * n          # 初始化一维 dp，长度等于列数

    for i in range(m):
        for j in range(n):
            if i == 0 and j == 0:          # 起点
                dp[j] = grid[i][j]
            elif i == 0:                    # 第一行，只能从左边来
                dp[j] = dp[j - 1] + grid[i][j]
            elif j == 0:                    # 第一列，只能从上边来（dp[j] 仍是上一行的值）
                dp[j] = dp[j] + grid[i][j]
            else:                           # 取上方 (dp[j]) 和左方 (dp[j-1]) 的较小值
                dp[j] = min(dp[j], dp[j - 1]) + grid[i][j]

    return dp[-1]      # 最右下角的累加和
```

#### 复杂度

- **时间复杂度**：`O(m * n)`（线性），因为每个格子只访问一次并做常数时间的计算。  
  大白话：如果矩阵有 200×200=40,000 个格子，程序只跑 40,000 步，瞬间结束。
- **空间复杂度**：`O(n)`（一维数组），只需要保存一行的状态。相比二维 `dp` 的 `O(m*n)`，省了大约 200 倍的内存。

## 心得

- 这道题核心考察 **动态规划**：把“最小路径和”分解为子格子的最小和，利用 **最优子结构** 与 **重叠子问题**。
- 类似技巧常出现在：
  1. **Unique Paths**（不同路径计数）——计数而非求和，同样用 DP。
  2. **Maximum Subarray**（最大子数组和）——一维 DP，求局部最优再整体合并。
  3. **Edit Distance**（编辑距离）——二维 DP，求最小编辑次数。
- **解题钥匙**：**“把大问题拆成只依赖左/上两个已知子问题的形式”**。

## 反思

- **第一反应**：直接写递归暴力搜索，想把所有路径都算一遍。
- **最容易踩的坑**  
  - 忘记对第一行和第一列做特殊处理，导致 `dp[-1]` 越界或使用未初始化的值。  
  - 在一维 DP 写法里，更新顺序必须从左到右，否则会把本行左侧的已经更新值误当成上方的值。  
  - 边界条件：只有一行或一列时，答案就是该行/列的累计和。
- **下次遇到同类题**，第一步应该思考 **“当前格子只和哪些已经算好的格子有关？”**，把问题抽象为 **“从左/上/前一个状态转移”**，再决定是否可以压缩空间。
