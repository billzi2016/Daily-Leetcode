# #155. 最小栈 / Min Stack

> 难度：中等 · 标签：Stack、Design · [LeetCode 链接](https://leetcode.com/problems/min-stack/)

---

## 题目（英文原版）

**Description**

Design a stack that supports push, pop, top, and retrieving the minimum element in constant time.
Implement the MinStack class:
You must implement a solution with O(1) time complexity for each function.

**Examples**

**Example 1:**

```
Input
["MinStack","push","push","push","getMin","pop","top","getMin"]
[[],[-2],[0],[-3],[],[],[],[]]

Output
[null,null,null,null,-3,null,0,-2]

Explanation
MinStack minStack = new MinStack();
minStack.push(-2);
minStack.push(0);
minStack.push(-3);
minStack.getMin(); // return -3
minStack.pop();
minStack.top();    // return 0
minStack.getMin(); // return -2
```

**Constraints**

- -231 <= val <= 231 - 1
- Methods pop, top and getMin operations will always be called on non-empty stacks.
- At most 3 * 104 calls will be made to push, pop, top, and getMin.

---

## 题目（中文翻译）

设计一个栈（stack），能够在 **常数时间**（O(1)）内完成以下操作：

- `push(val)`：将元素 `val` 推入栈中  
- `pop()`：移除栈顶元素  
- `top()`：返回栈顶元素  
- `getMin()`：返回栈中的最小元素  

实现 `MinStack` 类，使上述四个方法的时间复杂度均为 **O(1)**。

---

### 示例

```text
输入
["MinStack","push","push","push","getMin","pop","top","getMin"]
[[],[-2],[0],[-3],[],[],[],[]]

输出
[null,null,null,null,-3,null,0,-2]

解释
MinStack minStack = new MinStack();
minStack.push(-2);      // 栈为 [-2]
minStack.push(0);       // 栈为 [-2, 0]
minStack.push(-3);      // 栈为 [-2, 0, -3]
minStack.getMin();      // 返回 -3
minStack.pop();         // 移除 -3，栈为 [-2, 0]
minStack.top();         // 返回 0
minStack.getMin();      // 返回 -2
```

---

### 约束条件

- `-2^31 <= val <= 2^31 - 1`
- `pop`、`top` 和 `getMin` 方法的调用一定在 **非空栈** 上进行
- 最多会调用 `push`、`pop`、`top`、`getMin` 共计 `3 * 10^4` 次

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把所有入栈的元素都存到一个普通的 Python 列表 `stack` 里。  
- **push**：直接 `append` 到列表尾部。  
- **pop**：直接 `pop()` 列表尾部。  
- **top**：返回列表最后一个元素 `stack[-1]`。  
- **getMin**：遍历整条栈，找出最小的那个数。

这里的 “遍历整条栈” 就像我们在一本厚厚的字典里找最小的词——只能一个字一个字地往下翻，时间会比较久。  
因为 `getMin` 需要一次完整的线性扫描（`O(n)`），所以整体并不满足题目要求的 **O(1)**（常数时间）限制，但它一定能得到正确答案，适合作为第一步的“暴力实现”。

#### 代码（Python）

```python
class MinStack:
    def __init__(self):
        # 用列表模拟栈，列表的末尾对应栈顶
        self.stack = []

    def push(self, val: int) -> None:
        # 直接把元素压进去
        self.stack.append(val)

    def pop(self) -> None:
        # 弹出栈顶元素
        self.stack.pop()

    def top(self) -> int:
        # 返回栈顶元素（不删除）
        return self.stack[-1]

    def getMin(self) -> int:
        # 暴力遍历整个栈找最小值
        # 相当于“把字典从头翻到尾”来找最小的词
        min_val = self.stack[0]
        for x in self.stack:
            if x < min_val:
                min_val = x
        return min_val
```

#### 复杂度  

- **时间复杂度**  
  - `push`、`pop`、`top`：`O(1)`（直接操作列表尾部）  
  - `getMin`：`O(n)`，因为要遍历 `n` 个元素。这里的 `O(n)` 可以理解为“和栈里元素的个数成正比”，栈越大，花的时间越多。  

- **空间复杂度**  
  - `O(n)`，只用了一个列表保存所有元素，额外没有额外的数据结构。

> 虽然实现简单，但 `getMin` 的线性扫描是瓶颈，下面我们来把它改成 **O(1)**。

---

### 2. 最优解

#### 思路  

从暴力解出发，**慢的地方**在于每次 `getMin` 都要遍历整条栈。  
要把它加速到常数时间，需要在 **压栈** 的时候就把 “当前的最小值” 保存下来，这样 **弹栈** 时也同步更新。  

一种常见且易懂的做法是使用 **两条栈**（双栈）：

1. **主栈 `stack`**：正常保存所有入栈的元素，功能和暴力解里的一样。  
2. **辅助栈 `min_stack`**：每一次 `push` 时，把 **当前的最小值** 也压进去。  
   - 当 `push(x)` 时，`min_stack` 的栈顶保存的是 `min(x, min_stack.top())`（即在新元素和之前的最小值中取更小的）。  
   - 当 `pop()` 时，`stack` 与 `min_stack` 同时弹出，这样 `min_stack.top()` 始终对应当前栈的最小值。  

类比：  
- 主栈就像普通的书架，放各种书。  
- 辅助栈像一本“最小值记录本”，每翻一页（对应一次压栈）都会记下此时书架里最薄的那本书的厚度。要查询最薄的书，只需要看记录本的最后一页，**不需要再翻遍所有书**。

这样，**所有四个操作**（`push`、`pop`、`top`、`getMin`）都只涉及栈顶的读写，时间都是 **O(1)**。

#### 代码（Python）

```python
class MinStack:
    def __init__(self):
        # 主栈：保存所有压入的元素
        self.stack = []
        # 辅助栈：每个位置保存对应时刻的最小值
        self.min_stack = []

    def push(self, val: int) -> None:
        # 先把元素压到主栈
        self.stack.append(val)

        # 决定当前的最小值
        if not self.min_stack:
            # 辅助栈为空时，当前值本身就是最小值
            self.min_stack.append(val)
        else:
            # 取当前值和之前最小值的较小者压进去
            current_min = self.min_stack[-1]
            self.min_stack.append(val if val < current_min else current_min)

    def pop(self) -> None:
        # 同时弹出主栈和辅助栈的栈顶
        self.stack.pop()
        self.min_stack.pop()

    def top(self) -> int:
        # 主栈栈顶就是当前的 top
        return self.stack[-1]

    def getMin(self) -> int:
        # 辅助栈栈顶始终保存当前最小值
        return self.min_stack[-1]
```

#### 复杂度  

- **时间复杂度**  
  - `push`、`pop`、`top`、`getMin`：全部是 **O(1)**。这意味着不管栈里有多少元素，这四个操作花的时间都是固定的、可以预估的。  

- **空间复杂度**  
  - `O(n)`，因为我们用了两条等长的栈。虽然比单栈多了一倍的空间，但在本题的限制（`n ≤ 3·10⁴`）下仍然是完全可以接受的。

> 与暴力解相比，时间从 **线性** 降到了 **常数**，空间只多了一倍的栈，换来的是每次查询最小值的极速响应。

## 心得

- **核心技巧**：**在压栈的同时维护一个 “历史最小值栈”**，让每一次查询都能直接得到答案。  
- **适用的题型**  
  1. **最大栈 / 最小栈**（本题的变形，只要把比较符号换成 `>` 即可）。  
  2. **带有“区间最值”查询的单调栈**（例如“每日温度”）。  
  3. **实现 O(1) 取中位数的结构**（思路类似，需要两端维护）。  
- **一句话总结解题钥匙**：**“把每一步的答案提前算好并存起来”**。

---

## 反思

- **第一反应**：直接把所有数放进列表，`getMin` 时遍历一次——这就是暴力解。  
- **最容易踩的坑**  
  - **忘记同步弹出**：`pop` 时只弹出主栈，导致 `min_stack` 与实际栈不同步，`getMin` 会返回错误值。  
  - **边界条件**：第一次 `push` 时 `min_stack` 为空，需要单独处理，否则取 `self.min_stack[-1]` 会报错。  
- **下次遇到同类题的第一步**：**思考是否可以在“操作时就把答案记下来”，而不是等到查询时再遍历全部数据**。这样往往能把时间复杂度从线性降到常数。
