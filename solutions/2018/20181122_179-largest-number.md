# #179. 最大数 / Largest Number

> 难度：中等 · 标签：Array、String、Greedy、Sorting · [LeetCode 链接](https://leetcode.com/problems/largest-number/)

---

## 题目（英文原版）

**Description**

Given a list of non-negative integers nums, arrange them such that they form the largest number and return it.
Since the result may be very large, so you need to return a string instead of an integer.

**Examples**

**Example 1:**

```
Input: nums = [10,2]
Output: "210"
```

**Example 2:**

```
Input: nums = [3,30,34,5,9]
Output: "9534330"
```

**Constraints**

- 1 <= nums.length <= 100
- 0 <= nums[i] <= 109

---

## 题目（中文翻译）

给定一个非负整数（non-negative integer）数组 `nums`，重新排列这些整数，使拼接得到的结果是可能的最大数，并返回该结果。由于结果可能非常大，需要返回字符串而不是整数。

## 示例

### 示例 1
**输入:** `nums = [10,2]`  
**输出:** `"210"`

### 示例 2
**输入:** `nums = [3,30,34,5,9]`  
**输出:** `"9534330"`

## 约束条件
- `1 <= nums.length <= 100`
- `0 <= nums[i] <= 10^9`

---

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是把所有数字的排列全部枚举出来，算出每一种排列对应的拼接字符串，最后挑出字典序（或数值）最大的那一个。  

- **用到的数据结构**：  
  - `list` 保存原始整数序列。  
  - `itertools.permutations` 生成「全排列」——把它想象成把一副牌的所有可能抽排顺序都列出来。  
  - `str` 把整数转成字符串后直接「拼接」——就像把几块拼图的边缘贴在一起形成一条长长的文字带。  

- **为什么正确**：  
  枚举了 **所有** 可能的排列，必然包含最优的那一种。把每种排列拼成字符串后，只要取最大值（`max`），就是答案。

- **复杂度分析（大白话）**：  
  - 对于 `n` 个数字，排列的种类是 `n!`（n 的阶乘），比如 `n=5` 时有 `5×4×3×2×1 = 120` 种。  
  - 对每一种排列，我们要把 `n` 个数字转成字符串并拼接，拼接的长度大约是所有数字字符数的总和，用 `k` 表示平均每个数字的字符数，则每次拼接耗时约 `O(n·k)`。  
  - 所以总时间是 **O(n!·n·k)**，几乎是 **爆炸性增长**，只能在 `n` 很小（如 `n≤8`）时勉强跑得完。  
  - 空间上只需要保存一个排列和临时字符串，`O(n)`。

#### 代码（Python）

```python
import itertools

def largestNumber_bruteforce(nums):
    """
    暴力枚举所有排列，返回最大的拼接结果（字符串）。
    只适合演示思路，实际 n 超过 8 就会超时。
    """
    best = ""                     # 用来记录目前找到的最大字符串
    for perm in itertools.permutations(nums):
        # 把每个整数转成字符串后拼接
        candidate = "".join(str(x) for x in perm)
        # 取字典序更大的那个（等价于数值更大，因为都是非负整数的字符）
        if candidate > best:
            best = candidate
    # 特殊情况：全是 0 时会得到 "000...0"，需要压缩成单个 "0"
    return "0" if best.lstrip('0') == "" else best
```

#### 复杂度

- **时间复杂度**：`O(n!·n·k)`  
  - `n!` 是排列数量，`n·k` 是每次拼接的代价。  
  - 对普通人来说，`n!` 就像「把 10 本书排成一行的所有可能」——天文数字，根本不可接受。

- **空间复杂度**：`O(n)`  
  - 只保存当前的排列和拼接字符串，和 `n` 成正比。

### 2. 最优解

#### 思路  

从暴力解可以看出，**枚举所有排列是最耗时的地方**。我们要想办法**直接把数字排好顺序**，而不是尝试每一种可能。

观察示例：

```
[3, 30, 34, 5, 9] → 9534330
```

如果把数字直接按大小排序（3 < 30 < 34 …），得到的顺序显然不对。关键在于 **比较两个数字拼接后的结果**：

- 对于数字 `a`、`b`，我们比较 `a+b` 与 `b+a`（这里的 `+` 表示字符串拼接）。  
  - 如果 `a+b` > `b+a`，说明把 `a` 放在前面会得到更大的整体；  
  - 否则应该把 `b` 放在前面。

这就是**贪心**的核心：每次只比较两个数的相对位置，整体的最优解由局部最优累积而成。

实现时我们把所有整数先转成字符串，然后使用 **自定义排序规则**（Python 的 `sorted` + `functools.cmp_to_key`）：

```python
def compare(a, b):
    # 如果 a+b 更大，返回 -1 表示 a 应排在前面（因为 sorted 默认升序）
    if a + b > b + a:
        return -1
    elif a + b < b + a:
        return 1
    else:
        return 0
```

排序结束后，把排好序的字符串依次拼接即可。还有一个细节：如果所有数字都是 `0`，排序后会得到 `"000…0"`，答案应返回单个 `"0"`。

**为什么这样就对了？**  
- 任意两个数的相对顺序只受 `a+b` 与 `b+a` 的比较决定。  
- 排序算法会把「应该在前面的」放在左侧，形成的整体字符串恰好是所有可能拼接中最大的。  
- 这是一种**全局最优**的贪心证明：如果有任意一对 `a,b` 放反了，那么整体字符串就可以通过交换这两个位置得到更大的值，说明原排列不是最大解。

#### 代码（Python）

```python
from functools import cmp_to_key

def largestNumber(nums):
    """
    使用贪心排序：把两个数字转成字符串后比较 a+b 与 b+a 的大小。
    时间 O(n log n * k)，空间 O(n)。
    """
    # 1. 全部转成字符串，方便拼接比较
    strs = [str(x) for x in nums]

    # 2. 定义比较函数
    def cmp(a, b):
        # a 在前拼接得到的结果 vs b 在前拼接得到的结果
        if a + b > b + a:
            return -1          # a 应该排在前面（sorted 升序，需要返回负数）
        elif a + b < b + a:
            return 1           # b 应该排在前面
        else:
            return 0           # 两者等价

    # 3. 按自定义规则排序
    strs.sort(key=cmp_to_key(cmp))

    # 4. 拼接所有字符串
    result = "".join(strs)

    # 5. 处理全 0 的情况，例如 [0,0] → "0"
    return "0" if result[0] == '0' else result
```

#### 复杂度

- **时间复杂度**：`O(n log n * k)`  
  - `n log n` 是排序的常规代价（像把一堆纸牌按大小放好）。  
  - 每次比较要把两个字符串拼接，长度约为 `k`（平均每个数字的字符数），所以比较的实际开销是 `O(k)`。  
  - 与暴力解的 `n!` 相比，`log n` 只增长很慢，几乎可以接受 `n=100` 的规模。

- **空间复杂度**：`O(n)`  
  - 需要存储转换后的字符串列表以及排序时的临时空间，和输入规模线性相关。

## 心得

- **核心技巧**：**自定义比较函数的贪心排序**。把「两个数拼起来的大小」作为排序依据，直接得到全局最大排列。  
- **适用的题型**：  
  1. **拼接最大/最小数**（如 LeetCode 179 Largest Number）。  
  2. **字典序最大排列**（把字符或字符串排序，使拼接后字典序最大）。  
  3. **构造最小数**（如把数字排成最小的拼接数，比较规则改为 `a+b < b+a`）。  
- **一句话总结**：**把「两个元素谁在前能让整体更大」的比较规则写成 comparator，排序即是答案**。

---

## 反思

- **第一反应**：直接想遍历所有排列，求最大——这是一种「穷举」的自然思路。  
- **最容易踩的坑**：  
  - **比较方向写反**：如果写成 `a+b < b+a` 会得到最小数。  
  - **全 0 的特例**：排序后会得到 `"000…0"`，需要手动返回 `"0"`。  
  - **Python 排序默认升序**，所以比较函数返回值的符号要记清楚（`-1` 表示 `a` 应排在前）。  
- **下次类似题的第一步**：**思考两个元素拼接后谁更有优势**，把这个「拼接比较」抽象成比较函数，再交给排序来完成全局安排。
