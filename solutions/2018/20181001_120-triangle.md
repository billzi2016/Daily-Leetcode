# #120. 三角形最小路径和 / Triangle

> 难度：中等 · 标签：Array、Dynamic Programming · [LeetCode 链接](https://leetcode.com/problems/triangle/)

---

## 题目（英文原版）

**Description**

Given a triangle array, return the minimum path sum from top to bottom.
For each step, you may move to an adjacent number of the row below. More formally, if you are on index i on the current row, you may move to either index i or index i + 1 on the next row.

**Examples**

**Example 1:**

```
Input: triangle = [[2],[3,4],[6,5,7],[4,1,8,3]]
Output: 11
Explanation: The triangle looks like:
   2
  3 4
 6 5 7
4 1 8 3
The minimum path sum from top to bottom is 2 + 3 + 5 + 1 = 11 (underlined above).
```

**Example 2:**

```
Input: triangle = [[-10]]
Output: -10
```

**Constraints**

- 1 <= triangle.length <= 200
- triangle[0].length == 1
- triangle[i].length == triangle[i - 1].length + 1
- -104 <= triangle[i][j] <= 104

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**把所有可能的路径都列举出来**，然后取最小的路径和。  
可以用递归（深度优先搜索）来实现：

1. 从三角形的顶点 `triangle[0][0]` 开始。  
2. 在第 `i` 行的第 `j` 列，有两条“路可走”：  
   - 左下：去第 `i+1` 行的第 `j` 列  
   - 右下：去第 `i+1` 行的第 `j+1` 列  
3. 把当前格子的值加到累计和里，递归地继续往下走，直到到达最后一行。  
4. 把所有递归得到的路径和放进一个列表，最后返回最小值。

> **类比**：把三角形想象成一条山路，站在山顶要走到底部。每走一步都有左、右两条分支，**暴力解**就是把所有可能的爬山路线都走一遍，然后找出耗时最少（路径和最小）的那条。

这种方法一定能得到正确答案，因为它遍历了**全部**合法路径。唯一的问题是：当三角形有 `n` 行时，路径数是 `2^(n-1)`（每行除了最后一行都有两种选择），会指数级爆炸。

#### 代码（Python）

```python
from typing import List

def minimumTotal_bruteforce(triangle: List[List[int]]) -> int:
    """
    暴力递归：遍历所有路径，返回最小路径和
    """
    n = len(triangle)                       # 三角形的行数

    def dfs(row: int, col: int, cur_sum: int) -> int:
        """
        row, col   当前所在的坐标
        cur_sum    从顶部累计到当前格子的路径和
        返回值     从当前格子到底部的最小路径和（含当前格子）
        """
        cur_sum += triangle[row][col]       # 加上当前格子的值

        # 到达最后一行，返回累计和
        if row == n - 1:
            return cur_sum

        # 递归向左下和右下两条路前进，取较小的那条
        left  = dfs(row + 1, col,     cur_sum)
        right = dfs(row + 1, col + 1, cur_sum)
        return min(left, right)

    # 从顶部 (0,0) 开始搜索
    return dfs(0, 0, 0)
```

#### 复杂度  

- **时间复杂度**：`O(2^n)`  
  解释：每走一行（除了最后一行）都有两条选择，路径数随行数呈指数增长。比如 `n = 15` 时，大约有 `2^14 ≈ 16,384` 条路径要遍历。

- **空间复杂度**：`O(n)`  
  解释：递归调用栈的深度等于三角形的行数 `n`，每层只保存少量局部变量。

### 2. 最优解

#### 思路  

暴力解慢的根源在于**大量重复计算**。  
举个例子，下面这两条路径在第三行会出现同一个格子 `triangle[2][1]`，但我们会分别把它的子路径算两遍：

```
2 → 3 → 5 → 1
2 → 4 → 5 → 1
```

**动态规划（DP）**的核心思想正是**把子问题的答案记下来，后面再需要时直接复用**，从而避免重复工作。

对本题来说，**从底向上**处理最直观：

1. 最底层的每个格子本身就是从它到最底的最小路径和（因为已经在底部了）。  
2. 向上遍历第 `i` 行的每个格子 `triangle[i][j]`，它的“最小下沉路径和”只取决于它下面两格的最小路径和：  
   ```
   triangle[i][j] += min(triangle[i+1][j], triangle[i+1][j+1])
   ```
   这里的 `+=` 表示把当前格子的值加上从它往下走的最小代价。  
3. 当遍历完倒数第二行后，`triangle[0][0]` 就保存了从顶部到底部的最小路径和。

> **类比**：想象你在爬山，已经站在山脚的每个点，知道“从这里往上走的最省力路径”。现在你往上一步一步回看，每个点只需要看它脚下两个点哪个更省力，然后把自己的体力消耗加进去。最终站在山顶时，你就知道整条路的最小消耗。

我们可以直接在原始 `triangle` 上原地修改，**不需要额外的数组**，从而把空间使用压到 `O(1)`。

#### 代码（Python）

```python
from typing import List

def minimumTotal_dp(triangle: List[List[int]]) -> int:
    """
    动态规划：自底向上，原地修改 triangle，返回最小路径和
    """
    # 从倒数第二行开始往上遍历
    for row in range(len(triangle) - 2, -1, -1):
        for col in range(len(triangle[row])):
            # triangle[row+1][col]   是左下方格子的最小路径和
            # triangle[row+1][col+1] 是右下方格子的最小路径和
            # 取较小的那一个，加到当前格子上
            triangle[row][col] += min(triangle[row + 1][col],
                                      triangle[row + 1][col + 1])

    # 最终 triangle[0][0] 保存了全局最小路径和
    return triangle[0][0]
```

#### 复杂度  

- **时间复杂度**：`O(n²)`  
  解释：三角形总共有 `1 + 2 + … + n = n·(n+1)/2` 个格子，算法对每个格子只做一次常数时间的更新。这里的 `n` 指的是行数，`n²` 只是一个方便的上界。

- **空间复杂度**：`O(1)`（不计输入）  
  解释：我们直接在原始 `triangle` 上改写，不使用额外的数组，只用了几个临时变量。

## 心得

- **核心技巧**：**自底向上的动态规划**（把子问题的答案往上推）。
- **适用场景**：  
  1. 需要从“底部”或“末端”往“起点”累积最优解的路径问题（如 *Minimum Path Sum*、*Unique Paths with Obstacles* 的逆向思考）。  
  2. 具有**层级结构**、每层只依赖下一层的 DP（如 *Pascal’s Triangle* 生成、*Maximum Total*）。  
- **一句话总结**：把每个格子看成“从这里到底部的最省力费用”，自底向上一次次把费用累加，顶点的值就是答案。

## 反思

- **第一反应**：立刻想到递归遍历所有路径——因为“每一步可以往左或往右”这句话让人联想到二叉树的遍历。  
- **最容易踩的坑**：  
  - **边界处理**：在自底向上时，必须确保遍历的列数与当前行长度一致，不能越界访问 `triangle[row+1][col+1]`。  
  - **原地修改的副作用**：如果后面还有其他需要原始三角形的数据，记得先拷贝或使用额外数组。  
  - **负数情况**：题目允许负数，不能在代码里假设所有数都是正的。  
- **下次遇到同类题**：第一步先问自己“是否可以把子问题的最优解往回传递”，如果答案是“可以”，就尝试自底向上的 DP；如果不行，再考虑自顶向下的记忆化搜索（递归 + 哈希表）。
