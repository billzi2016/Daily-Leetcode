## 题目（中文翻译）

编写一个查询，找出每个分数（score）的排名（rank）。排名规则如下：

- 按分数从高到低（descending order）排序输出结果表。
- 若多个记录拥有相同的分数，则它们共享相同的排名（并列排名），后续排名按实际出现的不同分数递增。

结果表的格式请参考下方示例。

---

**表结构**

```sql
Scores 表
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| id          | int     |
| score       | decimal |
+-------------+---------+
```

- `id` 为主键（primary key），唯一标识每条记录。
- 每行记录表示一次游戏的得分（score），分数为保留两位小数的浮点数（floating‑point value）。

---

**示例**

输入（Input）:

```text
Scores 表:
+----+-------+
| id | score |
+----+-------+
| 1  | 3.50  |
| 2  | 3.65  |
| 3  | 4.00  |
| 4  | 3.85  |
| 5  | 4.00  |
| 6  | 3.65  |
+----+-------+
```

输出（Output）:

```text
+-------+------+
| score | rank |
+-------+------+
| 4.00  | 1    |
| 4.00  | 1    |
| 3.85  | 2    |
| 3.65  | 3    |
| 3.65  | 3    |
| 3.50  | 4    |
+-------+------+
```

**说明（Explanation）**  
- 最高分 4.00 出现两次，均列为第 1 名。  
- 次高分 3.85 为第 2 名。  
- 分数 3.65 出现两次，均列为第 3 名。  
- 最低分 3.50 为第 4 名。

- 无特定约束。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：

1. **把所有成绩取出来放进一个列表**。这一步相当于把“成绩表”搬到我们的程序里。
2. **对列表进行降序排序**。把成绩从高到低排好序，就像把一堆选手按成绩从高到低排队。
3. **遍历排好序的列表，给每个成绩分配名次**。  
   - 第一个出现的成绩一定是最高的，名次是 1。  
   - 当后面的成绩 **和前一个成绩相等** 时，说明出现了并列，这两个（或更多）选手应该得到相同的名次。  
   - 当后面的成绩 **和前一个成绩不相等** 时，名次就要往后加 1（因为我们采用的是 **dense rank**：相同名次之间不留空位）。

> **类比**：把成绩想象成图书馆的书号，排好序后，从左到右依次给书贴标签。如果两本书的编号相同，就贴同一个标签；否则标签递增。

这样做一定能得到正确的排名，因为我们严格按照题目要求的“降序、并列相同名次、名次连续”来处理。

#### 代码（Python）

```python
from typing import List, Tuple

def rank_scores_bruteforce(scores: List[Tuple[int, float]]) -> List[Tuple[float, int]]:
    """
    暴力实现：先排序，再遍历分配名次
    :param scores: [(id, score), ...]  注意这里的 id 只用于输入完整性，实际不参与排名
    :return: [(score, rank), ...] 已经按照 score 降序排列
    """
    # 1. 只保留 score，丢掉 id（id 对排名没有影响）
    score_list = [s for _, s in scores]

    # 2. 降序排序，sorted 会返回一个新列表，不会修改原始数据
    score_list.sort(reverse=True)               # O(n log n)

    result: List[Tuple[float, int]] = []
    prev_score = None          # 记录前一个遍历到的成绩
    cur_rank = 0               # 当前的 rank

    for s in score_list:       # O(n)
        if s != prev_score:    # 成绩变化，名次加 1
            cur_rank += 1
            prev_score = s
        # 如果成绩相同，cur_rank 不变，保持并列
        result.append((s, cur_rank))

    return result
```

#### 复杂度

- **时间复杂度**：`O(n log n)`  
  这里的 `n` 是成绩的条数。`log n` 来自排序（最快的排序算法的复杂度），后面一次线性遍历是 `O(n)`，整体仍然是 `O(n log n)`。  
  用生活化的说法：如果你有 1000 条成绩，排序大约需要 **1000 × log₂1000 ≈ 1000 × 10 = 10000** 次比较，比起每两条成绩都比较（`n² = 1,000,000` 次）要快很多。

- **空间复杂度**：`O(n)`  
  需要额外的列表存放排序后的成绩以及结果列表。除了这些，程序本身只使用常数级的额外变量。

### 2. 最优解

#### 思路  

从暴力解出发，我们已经找到了主要的 **瓶颈**：**排序**。  
实际上，对于这道题 **没有比 `O(n log n)` 更快的通用做法**，因为我们必须把所有成绩按照大小顺序输出，排序是信息论上不可避免的步骤。  

所以“最优解”指的就是 **在保持 `O(n log n)` 的前提下，写得更简洁、易懂**，并且 **一次遍历完成排名**（不需要额外的两次遍历或额外的数据结构）。

实现要点：

1. **一次排序**：直接对 `(score, id)` 这样的二元组排序，`score` 降序、`id` 升序（保证相同分数时输出顺序稳定）。
2. **一次遍历**：在遍历排好序的列表时，同时记录上一个不同的分数以及对应的 rank。这样不需要额外的哈希表或多次循环。
3. **返回结构**：题目要求只返回 `score` 和 `rank`，且保持排序好的顺序。

> **类比**：把所有选手先排好队（一次排队），随后从队首开始给每个人贴名次贴纸。如果前后两个人的成绩相同，就贴相同的名次贴纸；否则往后贴一个新贴纸。

#### 代码（Python）

```python
from typing import List, Tuple

def rank_scores_optimal(scores: List[Tuple[int, float]]) -> List[Tuple[float, int]]:
    """
    最优实现：一次排序 + 一次遍历完成排名
    :param scores: [(id, score), ...]
    :return: [(score, rank), ...] 已按 score 降序排列
    """
    # 1. 按 score 降序排序；若分数相同，保持原来的 id 顺序（stable sort）
    #    Python 的 sorted 是稳定的，所以直接写 key 即可。
    sorted_scores = sorted(scores, key=lambda x: -x[1])   # O(n log n)

    result: List[Tuple[float, int]] = []
    cur_rank = 0
    prev_score = None

    # 2. 只遍历一次，实时生成 rank
    for _, sc in sorted_scores:        # O(n)
        if sc != prev_score:           # 分数变化，名次加 1
            cur_rank += 1
            prev_score = sc
        # 若分数相同，cur_rank 不变，实现并列
        result.append((sc, cur_rank))

    return result
```

#### 复杂度

- **时间复杂度**：`O(n log n)`  
  与暴力解相同，因为排序是必须的。唯一的提升是我们只用了 **一次** 遍历（而不是先排序再额外遍历两次），常数因子更小，实际运行更快。

- **空间复杂度**：`O(n)`  
  需要存放排序后的列表以及返回结果。相比暴力解，没有额外的临时结构，仍然是线性空间。

## 心得

- **核心技巧**：**排序 + 计数（dense rank）**。先把数据按要求的顺序排好，再在一次遍历中根据“是否与前一个元素相同”来决定是否递增名次。
- **适用题型**  
  1. **排名题**：如 LeetCode 178, “Rank Scores”。  
  2. **分组统计题**：如 “按分数统计人数并给出排名”。  
  3. **分段计数题**：如 “把成绩分成 A/B/C 等级并输出每个等级的学生列表”。
- **一句话总结**：**先把数据排好序，再用一次遍历根据是否相同来递增名次，即可得到密集排名**。

## 反思

- **第一反应**：看到“排名”和“并列相同名次”，马上想到先排序再遍历分配 rank。
- **最容易踩的坑**  
  - **并列处理**：忘记在分数相等时不递增 rank，会导致错位的名次。  
  - **排序方向**：题目要求“降序”，如果写成升序会得到相反的结果。  
  - **返回顺序**：必须保持按照分数降序输出，否则即使 rank 正确也会不符合要求。  
- **下次遇到同类题**：**第一步** 先判断是否需要排序（大多数排名题都需要），然后思考“相同值应该怎么处理”，决定是 **dense rank**（不留空位）还是 **standard rank**（留下空位）。这样思路更清晰，代码也更易实现。
