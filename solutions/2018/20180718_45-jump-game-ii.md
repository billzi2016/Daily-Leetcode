# #45. 跳跃游戏 II / Jump Game II

> 难度：中等 · 标签：Array、Dynamic Programming、Greedy · [LeetCode 链接](https://leetcode.com/problems/jump-game-ii/)

## 题目（英文原版）

**Description**

You are given a 0-indexed array of integers nums of length n. You are initially positioned at nums[0].
Each element nums[i] represents the maximum length of a forward jump from index i. In other words, if you are at nums[i], you can jump to any nums[i + j] where:
Return the minimum number of jumps to reach nums[n - 1]. The test cases are generated such that you can reach nums[n - 1].

**Examples**

**Example 1:**

```
Input: nums = [2,3,1,1,4]
Output: 2
Explanation: The minimum number of jumps to reach the last index is 2. Jump 1 step from index 0 to 1, then 3 steps to the last index.
```

**Example 2:**

```
Input: nums = [2,3,0,1,4]
Output: 2
```

**Constraints**

- 1 <= nums.length <= 104
- 0 <= nums[i] <= 1000
- It's guaranteed that you can reach nums[n - 1].

## 题目（中文翻译）

给定一个下标从 **0** 开始的整数数组 `nums`，长度为 `n`。初始时你位于 `nums[0]`。  
数组中的每个元素 `nums[i]` 表示从下标 `i` **向前跳跃**（forward jump）时能够到达的最远距离。换言之，若你站在 `i`，可以跳到任意满足 `i + j < n` 且 `0 ≤ j ≤ nums[i]` 的下标 `i + j`（即 `nums[i + j]`）。

返回到达 `nums[n - 1]`（最后一个下标）所需的 **最少跳跃次数**（minimum number of jumps）。题目保证一定可以到达 `nums[n - 1]`。

## 示例

### 示例 1
**输入**: `nums = [2,3,1,1,4]`  
**输出**: `2`  
**解释**: 最少的跳跃次数是 2。先从下标 `0` 跳 1 步到下标 `1`，随后再跳 3 步直接到达最后一个下标。

### 示例 2
**输入**: `nums = [2,3,0,1,4]`  
**输出**: `2`  

## 约束条件
- `1 ≤ nums.length ≤ 10^4`
- `0 ≤ nums[i] ≤ 1000`
- 题目保证一定可以到达 `nums[n - 1]`。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  
最直接的想法是**逐个检查**每个位置能否到达后面的每个位置，然后记录到达每个位置需要的最少跳数。  
可以把它想象成“在城市之间搭公交”，每站都有最大能坐的车程（`nums[i]`），我们要算出从起点到每一站最少要坐几次车。

实现方式常用 **动态规划**：

1. 建立数组 `dp`，`dp[i]` 表示到达下标 `i` 的最少跳数。  
2. 起点 `dp[0] = 0`（已经在这里，不需要跳）。  
3. 对于每个位置 `i`（从左到右），遍历它能直接跳到的所有位置 `j`（`i < j ≤ i + nums[i]`），如果 `dp[j]` 还没有被更新或可以用更少的跳数到达，就把 `dp[j] = dp[i] + 1`。  
4. 最后 `dp[n-1]` 就是答案。

> **为什么正确？**  
> 每一次更新都把「从起点经过若干次合法跳跃」的最小次数传播到可以直接到达的后面位置。因为我们是从左到右、逐层扩散的，所有可能的路径都会被考虑，最小的自然会留下来。

#### 代码（Python）

```python
def jump(nums):
    n = len(nums)
    # dp[i] = 到达 i 位置的最少跳数，初始设为一个很大的数
    dp = [float('inf')] * n
    dp[0] = 0                     # 起点不需要跳

    for i in range(n):
        # 从位置 i 能跳到的最远位置
        far = min(i + nums[i], n - 1)
        for j in range(i + 1, far + 1):
            # 如果通过 i 跳到 j 能得到更少的跳数，就更新
            if dp[j] > dp[i] + 1:
                dp[j] = dp[i] + 1

    return dp[-1]                 # 最后一个位置的最小跳数
```

#### 复杂度

- **时间复杂度：** `O(n²)`  
  解释：外层遍历 `n` 次，内层最坏情况下也要遍历 `n` 次（当 `nums[i]` 很大时），所以大概是 `n × n`，也就是所谓的二次方时间。可以把它想成“每个人都要和所有人握手”，手数会成平方增长。

- **空间复杂度：** `O(n)`  
  解释：我们额外用了一个长度为 `n` 的 `dp` 数组来记录每个位置的最少跳数，和原数组等长。

### 2. 最优解

#### 思路  
暴力解的瓶颈在 **每次都遍历所有可达的后继**，导致二次方的时间。  
观察跳跃过程会发现：**我们只关心“在当前跳数能覆盖的最远位置”**，而不必记录每一个中间位置的具体跳数。  

把问题抽象成“把一根绳子从左向右逐段拉伸”。  
- `current_end`：当前跳数能够到达的最右边界（本次跳跃的“覆盖范围”）。  
- `farthest`：在 `current_end` 之内，所有位置的 **最远可达**（下一次跳跃可以直接伸到的最右边界）。  

遍历数组：

1. 对每个下标 `i`，更新 `farthest = max(farthest, i + nums[i])`，即记录从 `i` 能跳到的最远位置。  
2. 当 `i` 达到 `current_end` 时，说明本次跳跃的范围已经用完，必须**再跳一次**，把 `current_end` 拉到 `farthest`。  
3. 重复上述过程，直到遍历到倒数第二个位置（因为最后一次跳一定能到达终点）。

这就是经典的 **贪心（Greedy）** 思路：每一步都让自己跳到**能够看到的最远**，从而保证跳的次数最少。

> **为什么正确？**  
> 当我们在 `current_end` 位置必须跳时，所有在这段范围内的跳法已经被考虑。若不把 `current_end` 拉到 `farthest`，后面必然会出现“跳不到更远位置”的情况，导致额外的跳数。把 `current_end` 拉到 `farthest` 实际上是一次“最优的决定”，因为在这一步里我们已经看到了所有可能的下一步最远位置，选择最远的自然最省跳数。

#### 代码（Python）

```python
def jump(nums):
    n = len(nums)
    if n <= 1:                 # 已经在最后一个位置，不需要跳
        return 0

    jumps = 0                  # 已经用了多少次跳跃
    current_end = 0            # 本次跳跃能覆盖的最右边界
    farthest = 0               # 在当前覆盖范围内能到达的最远位置

    # 遍历到倒数第二个元素即可，因为最后一次跳一定能到达终点
    for i in range(n - 1):
        # 更新在 i 位置能到达的最远距离
        farthest = max(farthest, i + nums[i])

        # 当 i 达到本次跳的最右边界，说明必须再跳一次
        if i == current_end:
            jumps += 1                 # 增加一次跳跃
            current_end = farthest     # 把覆盖范围拉到能看到的最远位置

            # 如果已经能够直接跳到最后，提前结束
            if current_end >= n - 1:
                break

    return jumps
```

#### 复杂度

- **时间复杂度：** `O(n)`  
  解释：只需要一次线性遍历，每个元素只做了常数次的比较和更新。相当于“只需一次排队检查”，不再出现“每个人都要和所有人握手”的情况。

- **空间复杂度：** `O(1)`  
  解释：只用了若干个整数变量 (`jumps`, `current_end`, `farthest`) 来记录状态，和输入规模无关，属于常数级别的额外空间。

## 心得

- **核心技巧**：**贪心**——在每一步都把“可见的最远”作为下一次跳的目标。  
- **适用的题型**：  
  1. **Jump Game**（判断能否到达末尾）  
  2. **最小跳跃次数**（本题）  
  3. **加油站环路问题**（需要一次遍历找出起点）  
- **一句话总结解题钥匙**：**每次跳到当前能看到的最远位置**，这样跳的次数最少。

---

## 反思

- **第一反应**：先想到“把每一步的跳数都记下来，用 DP”——这是一种可靠但不够高效的做法。  
- **最容易踩的坑**：  
  - 忘记在遍历时只到 `n-2`（因为最后一步不需要再往后检查），否则可能多加一次不必要的跳。  
  - 当 `nums[i] = 0` 时要确保前面的跳跃已经把范围扩展过去，否则会卡死。  
- **下次遇到同类题**：第一步先**思考“我在当前跳数的覆盖范围内能看到多远”，看能否用一次遍历把最远距离记录下来，再决定是否需要再跳。这样自然会想到贪心解。
