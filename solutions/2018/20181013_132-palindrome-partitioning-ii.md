# #132. 回文分割 II / Palindrome Partitioning II

> 难度：困难 · 标签：String、Dynamic Programming · [LeetCode 链接](https://leetcode.com/problems/palindrome-partitioning-ii/)

---

## 题目（英文原版）

**Description**

Given a string s, partition s such that every substring of the partition is a palindrome.
Return the minimum cuts needed for a palindrome partitioning of s.

**Examples**

**Example 1:**

```
Input: s = "aab"
Output: 1
Explanation: The palindrome partitioning ["aa","b"] could be produced using 1 cut.
```

**Example 2:**

```
Input: s = "a"
Output: 0
```

**Example 3:**

```
Input: s = "ab"
Output: 1
```

**Constraints**

- 1 <= s.length <= 2000
- s consists of lowercase English letters only.

---

## 题目（中文翻译）

给定一个字符串 `s`，对 `s` 进行分割，使得划分得到的每个子串（substring）都是回文。返回完成回文划分所需的最少切割次数。

### 示例

#### 示例 1

**输出:** `1`  
**解释:** 回文划分 `["aa","b"]` 可以通过 1 次切割得到。

#### 示例 2
**输入:** `s = "a"`  
**输出:** `0`

#### 示例 3
**输入:** `s = "ab"`  
**输出:** `1`

### 约束条件
- `1 <= s.length <= 2000`
- `s` 仅由小写英文字母组成。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把字符串的所有切分方式都枚举出来，然后检查每个子串是不是回文，找到切分次数最少的那一种。  
可以把“切分”想象成在字符之间放置**剪刀**，`n` 个字符之间有 `n‑1` 条可能的剪刀位置。每条剪刀要么剪，要么不剪，于是所有切分方式相当于二进制的 `0/1` 组合，数量是 `2^(n‑1)`（指数级）。

实现步骤：

1. 用递归（或回溯）遍历所有剪刀的放置方式。  
2. 每次递归到某个位置时，把已经得到的子串逐个检查是否是回文（回文检测可以直接用双指针从两端向中间比较）。  
3. 如果当前所有子串都是回文，记录此时用了多少把剪刀（即切割次数），取最小值。

> **为什么正确？**  
> 只要把**所有可能的切分**都尝试一遍，就一定能找到最少剪刀的那一种。回文检查保证每个子串符合题目要求。

#### 代码（Python）

```python
def minCut_bruteforce(s: str) -> int:
    n = len(s)

    # 判断子串 s[l:r+1] 是否是回文
    def is_pal(l: int, r: int) -> bool:
        while l < r:
            if s[l] != s[r]:
                return False
            l += 1
            r -= 1
        return True

    # dfs(pos, cuts)  : 已经处理到字符下标 pos，已经用了 cuts 次剪刀
    ans = float('inf')          # 用来保存最小剪刀数

    def dfs(pos: int, cuts: int):
        nonlocal ans
        # 已经遍历完全部字符，更新答案
        if pos == n:
            ans = min(ans, cuts)
            return
        # 剪刀位置从 pos 开始向后尝试，每一次尝试都检查子串是否是回文
        for end in range(pos, n):
            if is_pal(pos, end):          # 子串 s[pos:end+1] 是回文
                # 如果已经是最后一个子串，不需要再加剪刀
                next_cuts = cuts if end == n - 1 else cuts + 1
                dfs(end + 1, next_cuts)

    dfs(0, 0)
    return ans
```

*关键行中文注释已在代码中体现。*

#### 复杂度  

- **时间复杂度**：`O(2^n * n)`  
  - 枚举所有切分方式需要 `2^(n‑1)` 种可能，每种切分在最坏情况下要检查 `O(n)` 次回文（因为每次都要遍历子串的两端）。用大白话说，就是**指数级**的时间，随着字符串长度稍微增长，运行时间会飞速增长。  
- **空间复杂度**：`O(n)`  
  - 递归栈的深度最多 `n`，另外只用了常数级的额外存储。

> 暴力解在 `n ≤ 15` 左右还能接受，但题目要求 `n ≤ 2000`，显然不行。

### 2. 最优解

#### 思路  

从暴力解可以看到**瓶颈**在于两件事：

1. **大量重复的回文检查**：相同的子串会被检查很多次。  
2. **枚举所有切分**：指数级的组合根本不可接受。

我们需要把“回文检查”提前准备好，用**记忆化**的方式一次性算出所有子串是否是回文；然后再用**动态规划**（DP）一次遍历求最少切割次数。

**步骤一：预处理回文表**  
- 建立一个二维布尔数组 `pal[i][j]`，表示子串 `s[i…j]` 是否是回文。  
- 递推公式：`pal[i][j] = (s[i] == s[j]) and (j - i < 2 or pal[i+1][j-1])`  
  - 当子串长度为 1 或 2 时，只要首尾字符相等就一定是回文（`j - i < 2`）。  
  - 长度 > 2 时，需要首尾相等且内部子串 `s[i+1…j-1]` 也是回文。  
- 这里的遍历顺序是 **从左到右、从短到长**（即外层 `j` 从 0 到 n-1，内层 `i` 从 j 往左），保证在使用 `pal[i+1][j-1]` 时它已经算好。

> 类比：把回文表想成一本“字典”，`i` 是单词，`j` 是页码，查询是否回文就像在字典里直接查，**O(1)** 时间。

**步骤二：动态规划求最小切割**  
- 定义 `dp[i]` 为子串 `s[0…i]`（前 `i+1` 个字符）最少需要的切割次数。  
- 初始化 `dp[i] = i`，因为最坏情况是每个字符单独成回文，需要 `i` 次切割（比如 `"abcd"`）。  
- 转移：遍历所有可能的右端点 `i`，对于每个左端点 `j ≤ i`，如果 `pal[j][i]` 为真，说明 `s[j…i]` 是回文。此时可以把 `s[0…i]` 切成 `s[0…j-1]` + `s[j…i]`，切割次数为  
  - `dp[j-1] + 1`（如果 `j > 0`），即在 `j-1` 位置的最优切割再加一次剪刀；  
  - 如果 `j == 0`，说明整个 `s[0…i]` 本身就是回文，不需要任何剪刀，`dp[i] = 0`。  
- 取所有合法 `j` 中的最小值即为 `dp[i]`。

**时间、空间分析**  
- 预处理回文表是 `O(n^2)`（两层循环），空间同样是 `O(n^2)`。  
- DP 再遍历一次 `O(n^2)`（外层 `i`，内层 `j`），空间 `O(n)`（只保存一维 `dp`）。  
- 综合来看，整体时间 `O(n^2)`、空间 `O(n^2)`（如果把回文表压缩到 `O(n)`，空间还能进一步降低，但这里保持易懂的二维表）。

> 对比暴力解：从指数级下降到平方级，`n = 2000` 时完全可接受（约 4 百万次操作）。

#### 代码（Python）

```python
def minCut(s: str) -> int:
    n = len(s)
    if n <= 1:
        return 0

    # ---------- 1. 预处理回文表 ----------
    # pal[i][j] = True 表示子串 s[i..j] 是回文
    pal = [[False] * n for _ in range(n)]

    for right in range(n):                 # 右端点从左到右扫
        for left in range(right, -1, -1):  # 左端点从 right 往左扫
            # s[left] 与 s[right] 相等且中间部分是回文（或子串长度 <= 2）
            if s[left] == s[right] and (right - left < 2 or pal[left + 1][right - 1]):
                pal[left][right] = True

    # ---------- 2. 动态规划求最小切割 ----------
    # dp[i] = 前 i+1 个字符（0..i）最少切割次数
    dp = [0] * n
    for i in range(n):
        # 最坏情况：每个字符单独成回文，需要 i 次切割
        dp[i] = i
        for j in range(i + 1):
            if pal[j][i]:                     # s[j..i] 是回文
                # 若 j == 0，整个前缀是回文，不需要切割
                dp[i] = 0 if j == 0 else min(dp[i], dp[j - 1] + 1)

    return dp[-1]
```

*代码中每一行都配有中文注释，直接可运行。*

#### 复杂度  

- **时间复杂度**：`O(n²)`  
  - 两个 `n × n` 的循环（一个用于填回文表，一个用于 DP），对 `n = 2000` 来说约 4 百万次操作，几乎是瞬间完成。  
- **空间复杂度**：`O(n²)`  
  - 需要 `n × n` 的布尔表来保存所有子串的回文信息。如果想进一步压缩空间，可改用中心扩展的方式只保存一维信息，空间可降到 `O(n)`，但实现会稍微复杂。  

> 与暴力解相比，时间从 **指数级** 降到了 **多项式级**，在实际测试里快了几千倍以上。

## 心得

- **核心技巧**：先把所有子串是否是回文预处理（相当于把“回文检查”这一步变成 O(1)），再用一维 DP 计算最少切割次数。  
- **适用的题型**  
  1. “回文划分”系列，如 **Palindrome Partitioning I**（返回所有可能的划分）。  
  2. “最少分割”类问题，如 **Word Break II**（在字典中切分最少次数）。  
  3. 需要子串属性快速查询的 DP 题目，例如 **Longest Palindromic Substring**（最长回文子串）也可以用类似的回文表。  
- **一句话总结**：**先把“是否回文”这张表做好，后面所有切割决策只需在表上查，DP 自然给出最优答案。**

## 反思

- **第一反应**：直接回溯所有切分，边切分边判断回文。  
- **最容易踩的坑**  
  1. **回文检查的重复**：若每次都用 `s[l:r+1] == s[l:r+1][::-1]`，会导致时间爆炸。  
  2. **边界处理**：`j == 0` 时不需要再加 1 切割，容易写成 `dp[j-1] + 1` 而产生负索引错误。  
  3. **空间超限**：如果直接存 `n × n` 的字符串会超内存，记得使用布尔表或压缩存储。  
- **下次思路**：看到“把字符串划分成满足某种子串属性的最少块”时，先问自己  
  1. “这个子串属性能否提前预处理（比如回文、是否在字典中）？”  
  2. “是否可以用 DP 把前缀的最优解递推出整个字符串的最优解？”  

这样就能迅速跳出暴力回溯的思维，走向 **预处理 + 动态规划** 的高效路线。
