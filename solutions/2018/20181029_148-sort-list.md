## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把链表“搬到” Python 的数组里，利用数组自带的排序函数（`sorted`）一次搞定，然后再把排好序的数组重新组装成链表返回。  
- **数据结构**：把链表节点的值依次放进一个列表（list），就像把散落的书本装进书架的抽屉里，等抽屉关好后再把书本一个一个摆回去。  
- **正确性**：把所有节点的值全部取出来后，只要对这些数进行升序排序，重新构造的链表自然就是升序的了。  
- **时间/空间复杂度**：  
  - 取值、排序、重建三个步骤各自的复杂度相乘得到总复杂度。  
  - 取值 O(n)（遍历一次链表），排序 O(n log n)（Python 内置排序的复杂度），重建 O(n)（再遍历一次数组）。  
  - 所以总时间是 **O(n log n)**，空间是 **O(n)**（需要额外的数组来保存 n 个数值）。

> **大白话**：`O(n log n)` 可以想象成“把 n 本书排好序要先把书分成若干小堆（log n 次），每堆内部再排（每本书一次）”。  
> `O(n)` 空间相当于“把所有书都搬到一个新柜子里”。

#### 代码（Python）

```python
# Definition for singly-linked list.
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next


def sortList_bruteforce(head: ListNode) -> ListNode:
    """暴力解：把链表转成数组，排序后再转回链表"""
    # 1. 把所有节点的值收集到 list 中
    vals = []
    cur = head
    while cur:
        vals.append(cur.val)      # 把每个节点的值存进数组，像往抽屉里放书
        cur = cur.next

    # 2. 使用 Python 内置排序（时间 O(n log n)）
    vals.sort()                  # 排序后数组就是升序的

    # 3. 根据排好序的数组重新创建链表
    dummy = ListNode(0)          # 哑结点，帮助我们省去判断头结点的麻烦
    cur = dummy
    for v in vals:               # 挨个把数组里的数值变成节点
        cur.next = ListNode(v)
        cur = cur.next

    return dummy.next            # 返回真正的头结点
```

#### 复杂度  

- **时间复杂度**：`O(n log n)`  
  - 解释：遍历一次收集 O(n) + 排序 O(n log n) + 再遍历一次重建 O(n) → 最高阶是 `n log n`，所以整体是 `O(n log n)`。  
- **空间复杂度**：`O(n)`  
  - 解释：我们额外开了一个长度为 n 的数组来存放节点的值，除去原链表本身，这部分空间随 n 成线性增长。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**需要额外的 O(n) 空间**。链表的特点是**只能顺序访问**，所以我们不能像数组那样直接下标随机取值，也不适合使用快速排序的“原地交换”。  
要在 **O(n log n) 时间且 O(1) 额外空间**（不算递归栈）内完成排序，最自然的选择是 **归并排序（Merge Sort）**，它非常适合链表：

1. **分割**：用快慢指针把链表从中间劈成两段（就像把一条绳子从中间剪开）。快指针每次走两步，慢指针每次走一步，当快指针到头时，慢指针正好在中点。  
2. **递归排序**：分别对左半段、右半段递归执行归并排序。递归的深度是 `log n`，每层只做 O(n) 的工作。  
3. **合并**：把两个已经排好序的子链表像“把两堆有序的书按顺序叠在一起”一样合并成一个有序链表。合并时只需要移动指针，不需要额外的数组，空间就是 **O(1)**（递归栈除外）。

> **核心概念解释**  
> - **快慢指针**：把链表想象成一条跑道，快指针跑得快，慢指针跑得慢。当快的跑完全程时，慢的恰好跑到中点。  
> - **哑结点（dummy）**：在链表操作里常用的“虚拟头”，相当于在排队前先放一个占位的空位，后面所有插入都可以统一处理，避免“第一个元素要单独处理”的特殊情况。  
> - **归并**：把两条已经排好序的“小路”合并成一条更长的有序“大路”，每次比较两条路的首节点，挑最小的接到结果路上。

#### 代码（Python）

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next


def sortList(head: ListNode) -> ListNode:
    """归并排序链表，时间 O(n log n)，空间 O(1)（递归栈除外）"""
    # 递归结束条件：空链表或只有一个节点，本身就是有序的
    if not head or not head.next:
        return head

    # ---------- 1. 用快慢指针找到链表的中点 ----------
    slow, fast = head, head
    prev = None                     # 用来记录 slow 的前一个节点，后面要把前半段断开
    while fast and fast.next:
        prev = slow                 # prev 暂时指向慢指针所在的节点
        slow = slow.next            # 慢指针走一步
        fast = fast.next.next       # 快指针走两步

    # 此时 slow 指向后半段的第一个节点，prev 指向前半段的最后一个节点
    prev.next = None                 # 断开链表，形成两个独立的子链表

    # ---------- 2. 递归地分别对左右两段排序 ----------
    left = sortList(head)            # 排序左半段
    right = sortList(slow)           # 排序右半段

    # ---------- 3. 合并两个有序链表 ----------
    return merge(left, right)


def merge(l1: ListNode, l2: ListNode) -> ListNode:
    """合并两个升序链表，返回合并后的头结点"""
    dummy = ListNode(0)              # 哑结点，帮助我们统一处理头结点
    tail = dummy

    # 当两条链表都还有节点时，取值更小的接到结果链表后面
    while l1 and l2:
        if l1.val <= l2.val:
            tail.next = l1
            l1 = l1.next
        else:
            tail.next = l2
            l2 = l2.next
        tail = tail.next             # tail 始终指向结果链表的最后一个节点

    # 把剩余的节点直接接上（因为已经是有序的）
    tail.next = l1 if l1 else l2

    return dummy.next                # 返回真正的头结点
```

#### 复杂度  

- **时间复杂度**：`O(n log n)`  
  - 解释：每一次递归把链表均匀地分成两半，深度是 `log n`（类似把一棵树从根到叶的层数）。每一层我们都要遍历整条链表一次来完成“分割 + 合并”，所以每层是 `O(n)`，层数乘起来就是 `O(n log n)`。  
- **空间复杂度**：`O(1)`（不计递归调用栈）  
  - 解释：合并过程只使用了常数个指针（`dummy、tail、l1、l2`），没有额外的数组或列表。递归本身会产生 `log n` 深度的调用栈，这在严格的 O(1) 空间要求里通常被视作可接受的，因为它不是我们显式申请的额外内存。

## 心得

- **核心技巧**：对链表使用归并排序 + 快慢指针找中点 + 哑结点合并。  
- **适用的题型**：  
  1. “链表排序”系列（如 LeetCode 148. Sort List）  
  2. “合并 K 条有序链表” （LeetCode 23）  
  3. “链表的中点 / 环检测” 这类需要快慢指针的题目。  
- **一句话总结**：**“把链表拆成两半递归排序，再像合并有序数组那样把两条小路拼成一条大路”。**

## 反思

- **第一反应**：把链表搬到数组里，用熟悉的数组排序算法直接解决。  
- **最容易踩的坑**：  
  - 在快慢指针分割时忘记把前半段的尾节点 `prev.next` 设为 `None`，导致递归时出现循环。  
  - 合并时忘记更新 `tail`，会形成死循环或丢失节点。  
  - 递归基准条件写不严谨（忘了 `head.next is None`），会导致无限递归。  
- **下次遇到同类题**：第一步先思考 **“这是一条只能顺序访问的结构，能否使用归并思路把它拆分再合并？”**，如果答案是肯定的，就直接走归并排序的路线。
