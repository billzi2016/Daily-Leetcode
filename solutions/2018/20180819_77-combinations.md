## 题目（英文原版）

**Description**

Given two integers n and k, return all possible combinations of k numbers chosen from the range [1, n].
You may return the answer in any order.

**Examples**

**Example 1:**

```
Input: n = 4, k = 2
Output: [[1,2],[1,3],[1,4],[2,3],[2,4],[3,4]]
Explanation: There are 4 choose 2 = 6 total combinations.
Note that combinations are unordered, i.e., [1,2] and [2,1] are considered to be the same combination.
```

**Example 2:**

```
Input: n = 1, k = 1
Output: [[1]]
Explanation: There is 1 choose 1 = 1 total combination.
```

**Constraints**

- 1 <= n <= 20
- 1 <= k <= n

## 解题过程

### 1. 直觉解（暴力）

#### 思路  
最直接的想法是把 **1~n** 之间的所有数全部列出来，然后把它们的所有 **k** 长度的子序列全部枚举出来，最后把出现的顺序不同但元素相同的序列去重。  
- **数据结构**：我们可以用 **列表**（list）保存当前枚举到的数字，用 **集合**（set）保存已经出现过的组合。集合可以类比为“查字典”，把组合这本“词典”放进去，已经有的词（组合）就不再插入，避免重复。  
- **为什么正确**：因为题目要求的是 **从 1 到 n 中任选 k 个** 的所有可能，枚举所有 k 长度的子序列（不管顺序）再去重，必然能得到完整答案。

#### 代码（Python）

```python
from itertools import combinations  # Python 内置的组合生成器，等价于暴力枚举

def combine_brute_force(n: int, k: int):
    nums = list(range(1, n + 1))          # [1, 2, ..., n]
    raw = list(combinations(nums, k))    # 直接生成所有 k 元组
    # 把元组转成列表，返回
    return [list(t) for t in raw]

# 示例
print(combine_brute_force(4, 2))
# [[1, 2], [1, 3], [1, 4], [2, 3], [2, 4], [3, 4]]
```

> **说明**  
> - 第 2 行的 `itertools.combinations` 本质上是穷举所有长度为 `k` 的组合，内部实现也是暴力的。  
> - 这里没有手动去重，因为 `combinations` 本身已经保证了元素顺序固定（从小到大），不会出现 `[2,1]` 之类的重复。

#### 复杂度  

- **时间复杂度**：`O(C(n, k) * k)`  
  - `C(n, k)` 表示 “从 n 选 k 的组合数”，即答案的大小。每个组合我们都要复制 `k` 个元素到列表里，所以整体是 `答案大小 × k`。  
  - 用大白话说，就是**答案有多少我们就要花多少时间**，最坏情况下（比如 n=20, k=10）会有几万条组合，时间会随之线性增长。  

- **空间复杂度**：`O(C(n, k) * k)`  
  - 需要把所有组合都存到返回列表中，空间占用正好和答案大小一样。

### 2. 最优解

#### 思路  

从暴力解可以看到，**枚举全部组合本身是必须的**，因为答案要把所有组合返回。真正的“慢”点在于 **重复的计算** 与 **不必要的遍历**。  
我们可以采用 **回溯（Backtracking）** 的思想，像在树形结构中“走路”，每走一步就决定是否把当前数字加入答案。这样可以：

1. **提前剪枝**：一旦已经选了 `k` 个数字，就不必继续往下选了；  
2. **避免重复**：在递归时只考虑比上一次选的数字大的后续数字，保证组合内部始终是递增的，自然去除了 `[2,1]` 之类的重复。  

下面一步步解释回溯的核心概念：

- **递归树**：把每一次“选或不选”看作树的分叉。根节点是“什么都没选”，左子树表示“选当前数字”，右子树表示“跳过当前数字”。  
- **回溯**：当走到叶子（选满 `k` 个）或走到不能再选（剩余数字不足）时，回到上一步，尝试另一条分支。  
- **剪枝**：如果当前已经选了 `len(path)` 个数，且 `n - start + 1`（从 `start` 到 `n` 的剩余数字）不足以凑满 `k`，直接返回，不再继续递归。

#### 代码（Python）

```python
def combine_backtrack(n: int, k: int):
    """
    回溯法生成所有长度为 k 的组合
    """
    res = []                     # 最终结果列表

    def backtrack(start: int, path: list):
        """
        :param start: 本次递归可以选择的最小数字（保证递增）
        :param path:  当前已经选好的数字序列
        """
        # 1️⃣ 递归终止条件：已经选够 k 个
        if len(path) == k:
            res.append(path.copy())   # 复制一份加入结果
            return

        # 2️⃣ 剪枝：如果剩余可选的数字数量不足以凑满 k，则直接返回
        #  n - start + 1 是从 start 到 n（含）之间的数字个数
        if len(path) + (n - start + 1) < k:
            return

        # 3️⃣ 遍历可选数字
        for num in range(start, n + 1):
            # 选取当前数字
            path.append(num)
            # 递归进入下一层，下一层只能选更大的数字
            backtrack(num + 1, path)
            # 撤销选择（回溯），为尝试下一个数字做准备
            path.pop()

    # 从 1 开始尝试
    backtrack(1, [])
    return res

# 示例
print(combine_backtrack(4, 2))
# [[1, 2], [1, 3], [1, 4], [2, 3], [2, 4], [3, 4]]
```

> **代码要点**  
> - 第 9 行 `if len(path) == k:` 是**基准情形**（终止递归），相当于“已经走到叶子”。  
> - 第 14 行的剪枝判断是“还有足够的树枝吗？”如果不够直接止步，省掉很多无用递归。  
> - `path.append(num)` 与 `path.pop()` 成对出现，保证递归结束后恢复到进入前的状态，这就是**回溯**的本质。

#### 复杂度  

- **时间复杂度**：`O(C(n, k) * k)`  
  - 虽然我们用了剪枝，但仍然必须遍历所有合法组合，数量正是 `C(n, k)`。每找到一个合法组合时，需要把长度为 `k` 的列表复制一次，所以整体是 **答案数量 × k**。  
  - 与暴力解相比，**常数因子更小**（没有额外的去重或生成全部子序列的开销），在实际运行时会更快。

- **空间复杂度**：`O(k)`（递归栈）+ `O(C(n, k) * k)`（返回结果）  
  - 递归深度最多是 `k`（因为每层选一个数字），所以调用栈占用 `O(k)` 的额外空间。  
  - 加上返回的答案本身，空间仍然是 `答案大小`，这部分是不可避免的。

## 心得

- **核心技巧**：**回溯（Backtracking）**——通过递归逐步构造解，并在不满足条件时及时撤销（回溯），配合**剪枝**避免无效搜索。  
- **适用题型**：  
  1. 组合类问题（如「组合总和」Combination Sum、全排列 Permutations）。  
  2. 子集/子序列生成（如「子集」Subsets、 「不同路径」Unique Paths 中的路径枚举）。  
  3. 棋盘问题的路径搜索（如「N皇后」N-Queens）。  
- **一句话总结**：**“逐层决定、保持递增、及时撤销” 是生成组合的钥匙。**

## 反思

- **第一反应**：看到“从 1~n 中任选 k 个”，立刻想到用 `itertools.combinations`，但这相当于直接调用库函数，真正的算法思路仍需自行实现。  
- **最容易踩的坑**：  
  - **边界条件**：当 `k == 0` 或 `k == n` 时，需要返回 `[[]]` 或 `[[1,2,...,n]]`，代码中要保证递归能够处理。  
  - **剪枝写错**：剪枝条件 `len(path) + (n - start + 1) < k` 写反了会导致漏掉合法组合。  
  - **忘记复制**：把 `path` 直接加入结果会导致后续回溯修改已经保存的组合，需要 `path.copy()`。  
- **下次类似题的第一步**：先确认**“是否需要保持顺序/去重”**，如果需要递增顺序，则可以用**回溯 + 起始位置** 的方式，先把“从哪里开始选”写出来，再逐层递归。这样可以在一开始就把搜索空间大幅缩小。
