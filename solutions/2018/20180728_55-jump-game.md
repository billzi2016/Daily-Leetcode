# #55. 跳跃游戏 / Jump Game

> 难度：中等 · 标签：Array、Dynamic Programming、Greedy · [LeetCode 链接](https://leetcode.com/problems/jump-game/)

---

## 题目（英文原版）

**Description**

You are given an integer array nums. You are initially positioned at the array's first index, and each element in the array represents your maximum jump length at that position.
Return true if you can reach the last index, or false otherwise.

**Examples**

**Example 1:**

```
Input: nums = [2,3,1,1,4]
Output: true
Explanation: Jump 1 step from index 0 to 1, then 3 steps to the last index.
```

**Example 2:**

```
Input: nums = [3,2,1,0,4]
Output: false
Explanation: You will always arrive at index 3 no matter what. Its maximum jump length is 0, which makes it impossible to reach the last index.
```

**Constraints**

- 1 <= nums.length <= 104
- 0 <= nums[i] <= 105

---

## 题目（中文翻译）

给定一个整数数组 `nums`。你最初位于数组的第一个下标，每个位置的元素表示你在该位置的最大跳跃长度（maximum jump length）。如果你能够到达最后一个下标，则返回 `true`，否则返回 `false`。

## 示例

### 示例 1
**输入**: `nums = [2,3,1,1,4]`  
**输出**: `true`  
**解释**: 从下标 `0` 跳 1 步到下标 `1`，随后再跳 3 步即可到达最后一个下标。

### 示例 2
**输入**: `nums = [3,2,1,0,4]`  
**输出**: `false`  
**解释**: 无论如何你都会停在下标 `3`，该位置的最大跳跃长度为 `0`，因此无法到达最后一个下标。

## 约束条件
- `1 <= nums.length <= 10^4`
- `0 <= nums[i] <= 10^5`

---

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：从起点出发，**穷举**所有可能的跳法，看能否走到最后一个下标。  
可以把每一次跳看成一次“选择”，于是整个过程类似于在树形结构中遍历所有路径：

- 当前所在的下标 `i`，它的数值 `nums[i]` 表示最多可以向前跳 `nums[i]` 步（可以跳 1 步、2 步……也可以不跳，当然不跳没有意义）。
- 对每一种合法的跳步长度，都递归地去尝试后面的跳法，直到：
  - 到达数组最后一个下标 → 返回 `True`（成功）；
  - 已经没有任何跳步可以继续 → 返回 `False`（失败）。

这个过程可以用 **深度优先搜索（DFS）** 实现，也可以用 **回溯** 的思路写成递归函数。  

> **生活化类比**：把数组想象成一条走廊，走廊每个格子上贴有一张卡片，卡片上写着“我最多能让你往前走几格”。我们站在第一格，要检查有没有一种走法能把我们送到走廊的尽头。于是我们把每一次“往前走几格”当成一次“选哪条路”，把所有可能的走法都列出来检查一遍。

**为什么这个方法一定能得到正确答案**  
因为我们把**所有**合法的跳法都尝试了一遍，只要有一种能到达终点，就会在遍历过程中发现并返回 `True`；如果所有路径都走不通，最终会返回 `False`。这是一种“枚举 + 判定”的完整搜索。

#### 代码（Python）

```python
def can_jump_bruteforce(nums):
    """
    暴力递归：从下标 i 出发，尝试所有合法的跳步，看看能否到达最后一个下标。
    """
    n = len(nums)

    def dfs(i):
        # 如果已经到了最后一个位置，直接返回 True
        if i >= n - 1:
            return True
        # 如果当前位置的跳跃长度为 0，无法前进，直接返回 False
        if nums[i] == 0:
            return False

        # 尝试从 1 步到 nums[i] 步的所有可能
        furthest = min(i + nums[i], n - 1)   # 不能跳出数组边界
        for next_i in range(i + 1, furthest + 1):
            if dfs(next_i):                  # 只要有一次递归返回 True，整体就成功
                return True
        return False                         # 所有选择都不行

    return dfs(0)    # 从下标 0 开始搜索
```

#### 复杂度  

- **时间复杂度：** `O(2^n)`（指数级）  
  - 每个位置最多有 `nums[i]` 条分支，最坏情况下（如所有 `nums[i]` 都很大）会产生类似二叉树的搜索树，节点数呈指数增长。用大白话说，就是“随着数组长度每增加一次，可能的走法会翻倍”。
- **空间复杂度：** `O(n)`  
  - 递归调用栈的最大深度等于数组长度 `n`（最坏情况每次只跳一步），所以占用的额外空间是线性的。

### 2. 最优解

#### 思路  

从暴力解可以看出，**主要的性能瓶颈**在于大量重复的子问题：  
比如在 `[2,3,1,1,4]` 中，从下标 `0` 跳到 `1` 再到 `4` 与从 `0` 直接跳到 `2` 再到 `4`，两条路径在走到下标 `4` 前都需要检查下标 `1`、`2`、`3` 的可达性，导致大量重复计算。

**贪心（Greedy）** 思想可以帮助我们一次性把“最远能到达的位置”记录下来，而不必枚举每条路径：

1. 维护一个变量 `reach`，表示**目前为止**（从起点出发）我们能够到达的最远下标。初始时 `reach = 0`（只能站在第 0 位）。
2. 从左到右遍历数组的每个下标 `i`（只遍历到 `reach`，因为 `i` 超过 `reach` 时说明已经无法到达该位置）：
   - 如果 `i` 超出了 `reach`，说明前面的跳跃根本无法抵达 `i`，直接返回 `False`。
   - 否则，用 `nums[i]` 更新 `reach`：`reach = max(reach, i + nums[i])`。这一步的意义是：“站在 `i` 这儿，我能往前最多跳到 `i + nums[i]`，所以整体的最远可达位置应该取两者的最大值”。
3. 遍历结束后，如果 `reach` 已经大于等于最后一个下标 `n-1`，说明我们可以到达终点，返回 `True`。

> **生活化类比**：想象你在一条直路上跑步，每个路标上写着“我能让你最多跑多远”。你从起点出发，手里记录一个“最远可达里程表”。每到一个路标，就看看这块路标能让你把最远里程表往前推多少。如果某个路标根本够不着，你就知道前面已经卡住，无法继续前进了。

**为什么贪心是正确的**  
我们每次都保留**所有已经能够到达的位置的最远边界**。只要某个位置 `i` 能够被当前的 `reach` 覆盖，就意味着已经有一种跳法可以站在 `i`。此时，以 `i` 为起点的所有后续跳法（向前 `nums[i]` 步）都已经被考虑进 `reach` 中。因为 `reach` 始终取最大值，所以只要有任意一种路径能让我们到达终点，`reach` 最终必然会覆盖到最后一个下标。反之，如果 `reach` 在遍历过程中停在某个位置前，说明没有任何跳法能够突破这个瓶颈，题目必然不可达。

#### 代码（Python）

```python
def can_jump(nums):
    """
    贪心解法：一次遍历，维护能够到达的最远下标。
    """
    n = len(nums)
    reach = 0                 # 当前能到达的最远位置，初始为 0（起点）

    for i in range(n):
        if i > reach:         # i 已经超出能到达的范围，说明卡住了
            return False

        # 更新最远可达位置：站在 i 这里，最远能到 i + nums[i]，取最大值
        reach = max(reach, i + nums[i])

        # 提前结束：一旦最远可达已经覆盖到最后一个下标，就可以直接返回 True
        if reach >= n - 1:
            return True

    # 循环结束后仍未覆盖到最后一个下标，返回 False
    return False
```

#### 复杂度  

- **时间复杂度：** `O(n)`（线性）  
  - 只遍历一次数组，每个元素的操作是常数时间。用大白话说，就是“数组有多长，就花多少时间”，不再有指数级的爆炸。
- **空间复杂度：** `O(1)`（常数）  
  - 只使用了几个整数变量 (`reach`, `i`, `n`) 与输入数组本身无关，不会随 `n` 增大而占用更多额外空间。

## 心得

- **核心技巧**：**贪心**——维护「能够到达的最远位置」并在遍历过程中不断更新。
- **适用的题型**：
  1. **Jump Game II**（求最少跳步数）——同样使用最远可达的思路，只是要记录每一步的跳跃区间。
  2. **Maximum Gap**（最大间隔）——在排序后使用线性遍历维护最大差值的思路类似。
  3. **Gas Station**（加油站环路）——通过累计油量判断是否能完成环路，同样是“前缀和 + 贪心”。
- **一句话总结**：只要把「每一步能走多远」转化为「全局最远可达位置」，就能在一次遍历中判断是否能到终点。

## 反思

- **第一反应**：看到「每个位置都有最大跳跃长度」就想到「遍历所有跳法」——于是写出了暴力递归。
- **最容易踩的坑**：
  1. **越界**：`i + nums[i]` 可能超过数组长度，需要取 `min(..., n-1)` 或在比较时直接使用 `>= n-1`。
  2. **零跳**：出现 `0` 时如果已经在最远可达范围之外，会导致卡死，需要及时返回 `False`。
  3. **提前结束**：在贪心解里忘记在 `reach >= n-1` 时提前返回，导致仍然遍历完整个数组（虽然不影响正确性，但会浪费时间）。
- **下次遇到同类题**：第一步先思考「是否可以把局部信息（当前能跳多远）汇总成一个全局的可达范围」；如果可以，就尝试用贪心一次遍历解决；如果不能，则考虑 DP 或 BFS。
