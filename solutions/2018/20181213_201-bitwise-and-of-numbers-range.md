# #201. 位运算与区间数字的按位与 / Bitwise AND of Numbers Range

> 难度：中等 · 标签：Bit Manipulation · [LeetCode 链接](https://leetcode.com/problems/bitwise-and-of-numbers-range/)

---

## 题目（英文原版）

**Description**

Given two integers left and right that represent the range [left, right], return the bitwise AND of all numbers in this range, inclusive.

**Examples**

**Example 1:**

```
Input: left = 5, right = 7
Output: 4
```

**Example 2:**

```
Input: left = 0, right = 0
Output: 0
```

**Example 3:**

```
Input: left = 1, right = 2147483647
Output: 0
```

**Constraints**

- 0 <= left <= right <= 231 - 1

---

## 题目（中文翻译）

**描述**  
给定两个整数 `left` 和 `right` 表示区间 `[left, right]`（左闭右闭），返回该区间内所有整数的按位与（bitwise AND），区间两端均包含。

**示例 1**  
Input: `left = 5, right = 7`  
Output: `4`

**示例 2**  
Input: `left = 0, right = 0`  
Output: `0`

**示例 3**  
Input: `left = 1, right = 2147483647`  
Output: `0`

**约束条件**  
- `0 <= left <= right <= 2^31 - 1`

---

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  
最直接的想法就是把区间 `[left, right]` 里的每个整数都拿出来，逐个做 **按位与**（`&`）运算，最后的结果就是所有数的 AND。  

- **按位与**：把两个数的二进制位对应相“碰”，只有当两位都是 `1` 时结果才是 `1`，否则就是 `0`。可以把它想象成两本笔记本的“打勾”，只有两本都打了勾的页码才会保留下来。  
- **遍历**：我们用一个 `for` 循环从 `left` 遍历到 `right`，把每个数与当前的累计结果 `ans` 做 `&`。  

这种方法之所以 **正确**，是因为 AND 运算是 **结合律** 和 **交换律** 的（即 `a & b & c = (a & b) & c = a & (b & c)`），所以不管我们按什么顺序把区间里的数两两相与，最终得到的都是所有数的 AND。

#### 代码（Python）  

```python
def rangeBitwiseAnd_brute(left: int, right: int) -> int:
    """
    暴力解法：遍历区间内所有整数，逐个做按位与。
    """
    ans = left                     # 先把左边界当作初始值
    for num in range(left + 1, right + 1):
        ans &= num                 # 与当前数字做按位与
        # 只要 ans 变成 0，后面的运算再也不会变回非 0，直接返回可以提速
        if ans == 0:
            return 0
    return ans
```

#### 复杂度  

- **时间复杂度**：`O(N)`，其中 `N = right - left + 1`，即遍历区间的长度。  
  - “O(N)” 可以理解为：如果区间有 1 000 000 个数，算法大约要执行 1 000 000 次基本操作。  
- **空间复杂度**：`O(1)`，只用了常数个变量（`ans`、`num`），不随输入规模增长。

---

### 2. 最优解  

#### 思路  
暴力解的瓶颈在于 **逐个遍历**，当区间很大（比如 `left = 0, right = 2^31-1`）时，遍历次数会非常多，根本不可接受。  
我们需要 **跳过** 那些必然会把结果清零的位。

**关键观察**：  
- 只要区间内出现了 **某一位上有 0**，那么这位在最终结果里一定是 0。  
- 当 `left` 和 `right` 的二进制表示在高位上已经相同，而低位不同（即出现了 “进位”），这些不同的低位必然会在 AND 过程中被冲掉。  
- 换句话说，**只有两数的公共前缀（从最高位开始相同的那部分）会保留下来**，其余位全部变成 0。

**实现办法**：  
1. 把 `left` 与 `right` 同时 **右移**（即除以 2），直到它们相等。每右移一次，就记录一次移动次数 `shift`。  
2. 此时相等的值就是 **公共前缀**（已经被右移了 `shift` 位）。  
3. 再把这个公共前缀 **左移** `shift` 位，恢复到原来的位置，即得到区间所有数的 AND。  

这相当于把 “找公共前缀” 这件事，用 **位运算** 完成。左移/右移在二进制里就像把数字的“尾巴”剪掉或再拼回去，非常高效。

#### 代码（Python）  

```python
def rangeBitwiseAnd(left: int, right: int) -> int:
    """
    最优解：找出 left 与 right 的公共前缀。
    """
    shift = 0                     # 记录右移了多少位
    # 当 left 与 right 不相等时，说明低位还有差异，需要继续右移
    while left < right:
        left >>= 1                # 右移一位，相当于把最低位“剪掉”
        right >>= 1
        shift += 1                # 右移次数加一
    # 此时 left == right，已经是公共前缀。左移回去得到答案
    return left << shift
```

> **为什么这段代码能跑得快？**  
> - 每次循环都把两个数都除以 2，最多只会循环 `log2(right)` 次（即二进制位数），最多 31 次（因为题目限制在 2³¹‑1 以内）。  
> - 循环体里只有几条非常快的位运算指令，几乎不受区间长度影响。

#### 复杂度  

- **时间复杂度**：`O(log R)`，`R = right`，即最高位的数量（不超过 31），可以理解为“即使区间有 2 000 000 000 个数，算法也只会跑大约 31 次”。  
- **空间复杂度**：`O(1)`，只用了几个整数变量。

## 心得  

- **核心技巧**：**寻找两个数的公共最高位前缀**（即相同的高位），因为所有不同的低位在 AND 过程中都会被冲掉。  
- **适用的题型**  
  1. **“Number of 1 Bits”**（统计二进制中 1 的个数）——需要熟悉位运算的基本操作。  
  2. **“Maximum XOR of Two Numbers in an Array”**——同样利用前缀树或位前缀的概念求最优解。  
  3. **“Counting Bits”**（统计 0~n 每个数的 1 的个数）——位运算可以让递推更高效。  
- **一句话总结解题钥匙**：*只保留左端点和右端点的相同高位，其他位全清零*。

## 反思  

- **拿到题目第一反应**：先想到最直观的遍历所有数做 AND，写出暴力代码验证思路。  
- **最容易踩的坑**  
  - **整数溢出**：在 Python 中不必担心，但在 C/C++/Java 里要注意左移可能超出 32 位。  
  - **边界条件**：`left == right` 时答案就是 `left` 本身；`left = 0, right = 2^31‑1` 时答案一定是 0，需要保证循环能在这种极端范围结束。  
- **下次遇到同类题**：第一步先**思考哪些位一定会被清零**（即找公共前缀），再决定是用 **右移找公共前缀** 还是 **Brian Kernighan** 之类的位技巧来快速缩小范围。
