# #146. LRU 缓存 / LRU Cache

> 难度：中等 · 标签：Hash Table、Linked List、Design、Doubly-Linked List · [LeetCode 链接](https://leetcode.com/problems/lru-cache/)

## 题目（英文原版）

**Description**

Design a data structure that follows the constraints of a Least Recently Used (LRU) cache.
Implement the LRUCache class:
The functions get and put must each run in O(1) average time complexity.

**Examples**

**Example 1:**

```
Input
["LRUCache", "put", "put", "get", "put", "get", "put", "get", "get", "get"]
[[2], [1, 1], [2, 2], [1], [3, 3], [2], [4, 4], [1], [3], [4]]
Output
[null, null, null, 1, null, -1, null, -1, 3, 4]

Explanation
LRUCache lRUCache = new LRUCache(2);
lRUCache.put(1, 1); // cache is {1=1}
lRUCache.put(2, 2); // cache is {1=1, 2=2}
lRUCache.get(1);    // return 1
lRUCache.put(3, 3); // LRU key was 2, evicts key 2, cache is {1=1, 3=3}
lRUCache.get(2);    // returns -1 (not found)
lRUCache.put(4, 4); // LRU key was 1, evicts key 1, cache is {4=4, 3=3}
lRUCache.get(1);    // return -1 (not found)
lRUCache.get(3);    // return 3
lRUCache.get(4);    // return 4
```

**Constraints**

- 1 <= capacity <= 3000
- 0 <= key <= 104
- 0 <= value <= 105
- At most 2 * 105 calls will be made to get and put.

## 题目（中文翻译）

设计一种数据结构，使其满足最近最少使用（LRU）缓存的约束条件。

实现 `LRUCache` 类：

- `get(key)`：如果键 `key` 在缓存中存在，返回对应的值（value），否则返回 `-1`。  
- `put(key, value)`：将键 `key` 与值 `value` 写入缓存。若键已存在则更新其值；若缓存已满，则先移除最近最少使用的键，再插入新键。

`get` 和 `put` 两个函数的平均时间复杂度必须为 **O(1)**。

**示例**

```text
Input
["LRUCache", "put", "put", "get", "put", "get", "put", "get", "get", "get"]
[[2], [1, 1], [2, 2], [1], [3, 3], [2], [4, 4], [1], [3], [4]]
Output
[null, null, null, 1, null, -1, null, -1, 3, 4]
```

**解释**
```java
LRUCache lRUCache = new LRUCache(2);
lRUCache.put(1, 1); // 缓存为 {1=1}
lRUCache.put(2, 2); // 缓存为 {1=1, 2=2}
lRUCache.get(1);    // 返回 1
lRUCache.put(3, 3); // 最近最少使用的键是 2，移除键 2，缓存为 {1=1, 3=3}
lRUCache.get(2);    // 返回 -1（未找到）
lRUCache.put(4, 4); // 最近最少使用的键是 1，移除键 1，缓存为 {4=4, 3=3}
lRUCache.get(1);    // 返回 -1（未找到）
lRUCache.get(3);    // 返回 3
lRUCache.get(4);    // 返回 4
```

**约束条件**

- `1 <= capacity <= 3000`
- `0 <= key <= 10^4`
- `0 <= value <= 10^5`
- 最多会调用 `get` 与 `put` 共计 `2 * 10^5` 次。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把缓存当成一个**列表**（或数组）来保存键值对，  
再用一个普通的 **字典**（哈希表）把键映射到对应的值。  
- **列表**相当于我们平时记事本的“顺序”，最新使用的键会被放到最前面，最久未使用的键会在最后。  
- **字典**就像一本“词典”，key 是单词，value 是对应的解释，查找很快（O(1)）。

操作细节：

1. `get(key)`  
   - 先在字典里查是否存在，若不存在返回 -1。  
   - 若存在，则在列表中找到对应的键，把它移动到列表头（表示最近使用）。  

2. `put(key, value)`  
   - 若键已经在缓存中，更新字典中的值，同时把键在列表中移动到头部。  
   - 若键不在缓存中：  
     - 判断当前缓存是否已满（列表长度 == 容量）。如果已满，就把列表最后一个键删掉（最久未使用），同时在字典里删除对应的条目。  
     - 把新键插入列表头，并在字典里记录 `key -> value`。

> 这种做法的核心是“每次访问都要在列表里找位置并搬动”，这一步是线性时间的。

#### 代码（Python）

```python
class LRUCacheBrute:
    """ 仅用于演示暴力思路，实际性能不符合题目要求 """
    def __init__(self, capacity: int):
        self.capacity = capacity          # 最大容量
        self.cache = {}                   # 哈希表：key -> value
        self.order = []                   # 列表，记录使用顺序，最左边是最近使用

    def _move_to_front(self, key: int) -> None:
        """把 key 移动到 order 的最前面（最近使用）"""
        if key in self.order:
            self.order.remove(key)        # 列表中找 key 并删除，O(n)
        self.order.insert(0, key)        # 插入到最前，O(1)

    def get(self, key: int) -> int:
        if key not in self.cache:
            return -1
        # 命中后把 key 标记为最近使用
        self._move_to_front(key)
        return self.cache[key]

    def put(self, key: int, value: int) -> None:
        if key in self.cache:
            # 更新已有键的值
            self.cache[key] = value
            self._move_to_front(key)
            return

        # 缓存已满，需要淘汰最久未使用的键
        if len(self.cache) >= self.capacity:
            lru_key = self.order.pop()   # 删除列表最后一个键，O(1)
            del self.cache[lru_key]      # 同时在哈希表中删除，O(1)

        # 插入新键
        self.cache[key] = value
        self.order.insert(0, key)        # 放到最前面，O(1)
```

#### 复杂度  

- **时间复杂度**  
  - `get`：最坏需要在 `order` 列表里查找并删除元素，时间是 **O(n)**（n 为当前缓存大小）。  
  - `put`：同样需要在列表里删除旧键或把新键插入头部，最坏也是 **O(n)**。  
  - 用大白话说，就是“如果缓存里有 1000 条数据，每次操作可能要跑一遍这 1000 条”，这对 2·10⁵ 次调用来说会很慢。

- **空间复杂度**  
  - 只用了两个容器来存放相同的数据，空间是 **O(n)**，这里的 n 等于缓存容量 `capacity`。  
  - 意思是“占用的内存正比于我们能装多少键”。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **在列表中寻找并搬动键的线性代价**。我们需要一种数据结构，既能**快速定位键**（O(1)），又能**快速删除或插入**（O(1)）而不需要遍历。

这正好可以用 **哈希表 + 双向链表** 的组合来实现：

| 结构 | 作用 | 类比 |
|------|------|------|
| **哈希表（dict）** | `key -> 对应的链表节点`，实现 O(1) 查找 | 像一本“电话簿”，给出姓名马上能找到电话号码 |
| **双向链表** | 按使用顺序维护节点，**头部**是最近使用，**尾部**是最久未使用 | 像一条**排队的队伍**，新来的人站在最前面，最老的人站在最后面。双向链表可以在任意位置 O(1) 删除或插入，因为每个节点都知道前后邻居。|

**关键操作**：

1. **访问（get）**  
   - 在哈希表里 O(1) 找到对应的链表节点。  
   - 把该节点从当前位置 **摘下来**，然后 **插入到链表头部**（表示最近使用）。  
   - 返回节点保存的 value。

2. **写入（put）**  
   - 若键已存在：更新节点的 value，然后同 `get` 一样把节点移动到头部。  
   - 若键不存在：  
     - 检查缓存是否已满。若满，需要 **淘汰**链表尾部的节点（最久未使用），同时在哈希表中删除对应的映射。  
     - 创建一个新节点，放到链表头部，并在哈希表里记录 `key -> 节点`。

**为什么双向链表能 O(1) 删除/插入？**  
每个节点都有 `prev`（前一个）和 `next`（后一个）指针。要把节点从链表中摘除，只需要把 `node.prev.next = node.next`、`node.next.prev = node.prev` 两行代码即可；不需要遍历整个链表。插入到头部同理，只要把新节点挂在 `head` 与 `head.next` 之间即可。

为了避免边界判断的麻烦，常用 **哑节点（dummy head / dummy tail）**：  
- `head` 永远指向链表的“前哨”，`head.next` 才是真正的第一个缓存节点。  
- `tail` 永远指向链表的“后哨”，`tail.prev` 才是真正的最后一个缓存节点。  
这样插入、删除时不需要判断是否为空或只有一个节点，代码更简洁。

#### 代码（Python）

```python
class Node:
    """双向链表的节点，保存键和值"""
    __slots__ = ('key', 'val', 'prev', 'next')
    def __init__(self, key: int = 0, val: int = 0):
        self.key = key
        self.val = val
        self.prev = None
        self.next = None


class LRUCache:
    """容量固定的 LRU 缓存，所有操作均为 O(1)"""
    def __init__(self, capacity: int):
        self.capacity = capacity
        self.cache = {}               # 哈希表：key -> Node

        # 哑节点，构成一个空的双向链表
        self.head = Node()            # 虚拟头部
        self.tail = Node()            # 虚拟尾部
        self.head.next = self.tail
        self.tail.prev = self.head

    # ---------- 链表内部操作 ----------
    def _add_node(self, node: Node) -> None:
        """
        把节点插入到链表头部（head 之后），
        这里的顺序是：head <-> node <-> former_first
        """
        node.prev = self.head
        node.next = self.head.next
        self.head.next.prev = node
        self.head.next = node

    def _remove_node(self, node: Node) -> None:
        """把节点从链表中摘除（不考虑是否是头/尾哑节点）"""
        prev = node.prev
        nxt = node.next
        prev.next = nxt
        nxt.prev = prev

    def _move_to_front(self, node: Node) -> None:
        """把已有节点移动到链表头部，等价于：摘除 + 插入"""
        self._remove_node(node)
        self._add_node(node)

    def _pop_tail(self) -> Node:
        """
        弹出链表尾部的真实节点（即最久未使用的），
        同时从哈希表中删除对应的映射
        """
        lru = self.tail.prev
        self._remove_node(lru)
        return lru

    # ---------- 公共接口 ----------
    def get(self, key: int) -> int:
        if key not in self.cache:
            return -1
        node = self.cache[key]
        # 访问后把它标记为最近使用
        self._move_to_front(node)
        return node.val

    def put(self, key: int, value: int) -> None:
        if key in self.cache:
            # 已有键：更新值并移动到前面
            node = self.cache[key]
            node.val = value
            self._move_to_front(node)
            return

        # 新键，需要检查容量是否已满
        if len(self.cache) >= self.capacity:
            # 淘汰最久未使用的节点
            tail_node = self._pop_tail()
            del self.cache[tail_node.key]

        # 创建新节点并加入结构
        new_node = Node(key, value)
        self.cache[key] = new_node
        self._add_node(new_node)
```

#### 复杂度  

- **时间复杂度**  
  - `get`：在哈希表里 O(1) 找到节点，再通过 `_move_to_front`（两次 O(1) 操作）把节点移到头部，**总计 O(1)**。  
  - `put`：同理，查找/插入/删除均是 O(1)。  
  - 与暴力解相比，**不再随缓存大小线性增长**，即使容量是 3000，操作时间也几乎不变。

- **空间复杂度**  
  - 我们额外维护了每个键对应的链表节点，整体存储的元素数量等于缓存容量 `capacity`，因此 **O(capacity)**。  
  - 与暴力解一样，只是把列表换成了更高效的链表结构，空间占用并没有增加量级。

## 心得

- **核心技巧**：**哈希表 + 双向链表** 的组合，实现“常数时间的最近使用顺序维护”。  
- **适用的题型**（类似思路）  
  1. **LFU Cache**（最不常用缓存）——需要维护使用频率的排序，同样可以用哈希表 + 双向链表（或有序字典）实现。  
  2. **LRU 页面置换**（操作系统分页）——本题的直接应用。  
  3. **设计有序字典**（保持插入顺序）——Python 的 `OrderedDict` 内部就是使用了类似结构。  

- **一句话总结**：  
  “把‘快速定位’交给哈希表，把‘快速搬动顺序’交给双向链表，二者配合即可实现 O(1) 的 LRU 缓存。”

## 反思

- **拿到题目第一反应**：  
  “先用字典存值，用列表记录顺序，先把功能写出来再考虑性能”。  
- **最容易踩的坑**  
  1. **忘记在 `put` 时更新已有键的顺序**：只改值不搬动会导致错误的淘汰。  
  2. **链表的边界处理**：如果不使用哑节点，删除头尾节点时容易出现 `None` 指针错误。  
  3. **容量为 0 的特殊情况**：需要保证代码在 `capacity == 0` 时也能安全运行（本题约束 `capacity >= 1`，但实际实现时最好防御性检查）。  

- **下次遇到同类题的第一步**：  
  “先判断是否需要 **同时满足‘快速定位’和‘快速顺序更新’**，如果是，就立刻想到哈希表 + 双向链表的组合。”
