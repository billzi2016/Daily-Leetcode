# #41. 首个缺失的正数 / First Missing Positive

> 难度：困难 · 标签：Array、Hash Table · [LeetCode 链接](https://leetcode.com/problems/first-missing-positive/)

---

## 题目（英文原版）

**Description**

Given an unsorted integer array nums. Return the smallest positive integer that is not present in nums.
You must implement an algorithm that runs in O(n) time and uses O(1) auxiliary space.

**Examples**

**Example 1:**

```
Input: nums = [1,2,0]
Output: 3
Explanation: The numbers in the range [1,2] are all in the array.
```

**Example 2:**

```
Input: nums = [3,4,-1,1]
Output: 2
Explanation: 1 is in the array but 2 is missing.
```

**Example 3:**

```
Input: nums = [7,8,9,11,12]
Output: 1
Explanation: The smallest positive integer 1 is missing.
```

**Constraints**

- 1 <= nums.length <= 105
- -231 <= nums[i] <= 231 - 1

---

## 题目（中文翻译）

给定一个**无序整数数组 (unsorted integer array)** `nums`。返回 `nums` 中不存在的最小**正整数 (positive integer)**。  
要求实现的算法时间复杂度为 **O(n)**，且仅使用 **O(1)** 的**辅助空间 (auxiliary space)**。

**示例 1**  
**输入**: `nums = [1,2,0]`  
**输出**: `3`  
**解释**: 范围 `[1,2]` 内的所有正整数都已出现在数组中。

**示例 2**  
**输入**: `nums = [3,4,-1,1]`  
**输出**: `2`  
**解释**: `1` 在数组中，但 `2` 缺失。

**示例 3**  
**输入**: `nums = [7,8,9,11,12]`  
**输出**: `1`  
**解释**: 最小的正整数 `1` 缺失。

**约束条件**  
- `1 <= nums.length <= 10^5`  
- `-2^31 <= nums[i] <= 2^31 - 1`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把数组里出现的所有正整数全部收集起来，然后从 **1** 开始逐个检查它是否在集合中。  
- **数据结构**：使用 *哈希表*（在 Python 中可以直接用 `set`），它的作用就像一本字典，单词（这里是正整数）对应的页码（这里是「是否出现」）。查找一个单词的时间几乎是 **O(1)**，所以我们可以很快判断一个数是否出现过。  
- **为什么正确**：只要把所有出现的正整数记下来，依次检查 1、2、3 …，第一个不在集合里的数必然就是答案，因为比它小的数已经全部出现了。  
- **时间/空间复杂度**：  
  - 我们需要遍历一次数组把正整数放进集合，时间是 **O(n)**。随后再从 1 开始检查，最坏情况下要检查到 `n+1`（因为答案最多是 `n+1`），这也是 **O(n)**，所以总体是 **O(n)**。  
  - 但是集合会保存至多 `n` 个元素，额外空间是 **O(n)**。题目要求 **O(1)** 额外空间，所以这算是“暴力”但不满足题目限制的解法。

#### 代码（Python）

```python
def firstMissingPositive(nums):
    # 把所有出现的正整数放进集合（相当于字典的查找表）
    pos_set = {x for x in nums if x > 0}

    # 从 1 开始逐个检查，找到第一个不在集合里的数
    i = 1
    while True:
        if i not in pos_set:      # 集合的查找时间近似 O(1)
            return i
        i += 1
```

#### 复杂度

- **时间复杂度**：O(n)  
  - 第一次遍历把正数放进集合是 O(n)；随后最多检查 `n+1` 次，也是 O(n)。  
- **空间复杂度**：O(n)  
  - 需要额外的集合来存放所有正整数，最坏情况需要 `n` 个位置。

---

### 2. 最优解

#### 思路  

要做到 **O(1) 额外空间**，就必须把“信息”直接写回原数组里。观察一下：

- 只关心范围在 `[1, n]`（`n` 为数组长度）的正整数，因为答案不可能大于 `n+1`（如果 `[1…n]` 都出现了，答案只能是 `n+1`）。
- 如果我们能让每个数 `k`（满足 `1 ≤ k ≤ n`）都 **放到下标 `k-1` 的位置**，那么遍历完后第一个 “位置 i 上的数不是 i+1” 就是缺失的最小正数。

这正是 **原地哈希**（或叫 *循环置位*）的思想：

1. **遍历数组**，对每个位置 `i`：
   - 当 `nums[i]` 在 `[1, n]` 且 `nums[i]` 不是它应该在的位置（即 `nums[i] != nums[nums[i] - 1]`）时，**交换**它和它应该去的位置 `nums[nums[i] - 1]`。
   - 交换后继续检查当前 `i`（因为新换进来的数也可能需要再搬）。
   - 这一步最多进行 `n` 次交换，因为每次交换都会把至少一个数放到正确位置。

2. **第二遍扫描**：从左到右找第一个 `nums[i] != i+1`，返回 `i+1`。如果全部匹配，则答案是 `n+1`。

> **类比**：想象你有一排信箱（下标 0~n-1），每个信箱只能放入对应编号的信件（编号 = 下标+1）。我们把乱放的信件逐个搬到正确的信箱，搬完后空着的信箱编号就是最小缺失的正数。

#### 代码（Python）

```python
def firstMissingPositive(nums):
    n = len(nums)
    i = 0
    while i < n:
        cur = nums[i]
        # 只处理 1~n 范围内且不在正确位置的数
        if 1 <= cur <= n and nums[cur - 1] != cur:
            # 把 cur 换到它该去的位置 (cur-1)
            nums[i], nums[cur - 1] = nums[cur - 1], nums[i]
            # 交换后不要直接 i+=1，继续检查当前 i，因为新进来的数可能还不对
        else:
            i += 1

    # 第二遍扫描，找第一个位置不对的下标
    for idx in range(n):
        if nums[idx] != idx + 1:
            return idx + 1

    # 如果全部对应，则答案是 n+1
    return n + 1
```

**代码要点解释**  

- `1 <= cur <= n`：只关心在合法范围内的数，负数、0、以及大于 n 的数直接跳过。  
- `nums[cur - 1] != cur`：防止无限循环的关键。当目标位置已经有相同的数时（出现重复），不再交换。  
- 交换使用 Python 的元组解包，一行搞定。  
- 第二遍遍历只需要一次线性扫描。

#### 复杂度

- **时间复杂度**：O(n)  
  - 第一次循环每个元素最多被换进正确位置一次，最多进行 `2n` 次比较/交换（常数因子不影响大 O），所以仍是线性时间。  
  - 第二次扫描也是 O(n)。整体仍是 **O(n)**，满足题目要求。  
- **空间复杂度**：O(1)  
  - 只用了若干个额外的整数变量 `i、cur、n`，没有随输入规模增长的额外数组或哈希表，符合常数空间。

## 心得

- **核心技巧**：**原地哈希（循环置位）**——把值映射到下标位置，利用数组本身充当哈希表。  
- **适用题型**：  
  1. “找缺失的最小正数” （本题）  
  2. “数组中所有出现两次的数字” （LeetCode 442）  
  3. “把所有 0 移到数组末尾，保持相对顺序” 这类需要原地重排的题目（虽然思路略有不同）  
- **解题钥匙**：**把“数值范围”和“下标范围”对应起来，直接在原数组里做“位置纠正”。**

## 反思

- **第一反应**：想到用集合或额外数组统计出现的数，虽然直观但占用 O(n) 空间。  
- **最容易踩的坑**：  
  - 忘记限制只处理 `1~n` 的数，导致下标越界。  
  - 对于重复的数如果不判断 `nums[cur-1] != cur`，会出现无限循环。  
  - 第二遍遍历时忘记返回 `n+1` 的情况（全部出现时）。  
- **下次第一步**：把“合法范围 `[1, len(nums)]`”和“数组下标对应关系”写下来，问自己“能否把数直接放到它应该在的位置？”如果可以，就走原地哈希路线。
