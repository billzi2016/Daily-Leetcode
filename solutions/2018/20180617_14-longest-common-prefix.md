# #14. 最长公共前缀 / Longest Common Prefix

> 难度：简单 · 标签：Array、String、Trie · [LeetCode 链接](https://leetcode.com/problems/longest-common-prefix/)

---

## 题目（英文原版）

**Description**

Write a function to find the longest common prefix string amongst an array of strings.
If there is no common prefix, return an empty string "".

**Examples**

**Example 1:**

```
Input: strs = ["flower","flow","flight"]
Output: "fl"
```

**Example 2:**

```
Input: strs = ["dog","racecar","car"]
Output: ""
Explanation: There is no common prefix among the input strings.
```

**Constraints**

- 1 <= strs.length <= 200
- 0 <= strs[i].length <= 200
- strs[i] consists of only lowercase English letters if it is non-empty.

---

## 题目（中文翻译）

编写一个函数，找出 **字符串数组**（array of strings）中最长的公共前缀（longest common prefix）字符串。如果不存在公共前缀，返回空字符串 `""`。

**示例 1**  
**输入**: `strs = ["flower","flow","flight"]`  
**输出**: `"fl"`

**示例 2**  
**输入**: `strs = ["dog","racecar","car"]`  
**输出**: `""`  
**解释**: 输入的字符串之间没有公共前缀。

**约束条件**  
- `1 <= strs.length <= 200`  
- `0 <= strs[i].length <= 200`  
- 若 `strs[i]` 非空，则仅由小写英文字母组成。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把每个字符串从左到右一个字符一个字符地比较，找出所有字符串都相同的最长前缀。可以把这个过程想象成 **排队检查**：把所有同学排成一列，老师依次检查每个人的第 1 个字母是否相同，如果相同就记下来继续检查第 2 个字母，直到出现不相同或有同学已经没有字母为止。  

- **使用的数据结构**：只需要一个普通的 Python 列表 `strs`（装所有字符串）和几个整数变量来记录当前位置。这里不需要额外的复杂结构，类似“字典”这种高级结构在这一步并不必用到。  
- **为什么正确**：因为我们是从左到右、从第 0 位开始逐位比较，只要出现不一致，就说明从这一位起以后不可能再是公共前缀。于是前面已经确认相同的部分就是最长公共前缀。  
- **时间/空间复杂度**：  
  - **时间**：最坏情况下，所有字符串长度相同且完全相同，需要检查每个字符一次。设字符串个数为 `n`，每个字符串的长度为 `m`（这里取最长的那个），总共检查 `n * m` 次字符，记作 **O(n·m)**。如果把 `n·m` 展开成 “每个字符串 200 个字符，最多 200 条字符串”，最多是 40 000 次比较，算得上很快。  
  - **空间**：只用了常数个额外变量（如 `i`、`j`），不随输入规模增长，记作 **O(1)**。

#### 代码（Python）

```python
def longestCommonPrefix(strs):
    """
    暴力逐字符比较法
    :param strs: List[str]，所有待检查的字符串
    :return: 最长公共前缀（可能为空串）
    """
    if not strs:                     # 防止空列表
        return ""

    # 取最短字符串的长度作为上界，避免越界
    min_len = min(len(s) for s in strs)

    prefix = []                      # 用列表收集公共字符，最后再 join 成字符串
    for i in range(min_len):         # 逐位检查，最多到最短字符串的长度
        current_char = strs[0][i]    # 以第一个字符串的第 i 位为基准字符
        # 检查其它所有字符串的第 i 位是否相同
        for s in strs[1:]:
            if s[i] != current_char:    # 只要有一个不相同，就结束循环
                return "".join(prefix)
        # 所有字符串在第 i 位都相同，加入结果
        prefix.append(current_char)

    # 循环结束说明所有字符都匹配，直接返回
    return "".join(prefix)
```

#### 复杂度

- **时间复杂度**：O(n·m)  
  - 这里的 `n` 是字符串数量，`m` 是最短字符串的长度（因为一旦最短的已经检查完，就不可能再有更长的公共前缀）。可以把 O(n·m) 想成 “每条道路上都有 n 辆车，司机要检查 m 次”。  
- **空间复杂度**：O(1)（不计返回值的空间）  
  - 只用了几个整数和一个临时列表 `prefix`，它的大小最多是 `m`，而 `m ≤ 200`，属于常数级别。

### 2. 最优解

#### 思路  

在暴力解里，**瓶颈** 是我们对每个位置都遍历所有字符串。其实，如果把所有字符串 **先排个序**，相邻的两个字符串一定会把公共前缀的长度压到最小值，因为排序后相似的字符串会被放在一起。于是，只需要比较 **排序后第一个和最后一个** 的公共前缀，即可得到所有字符串的最长公共前缀。  

- **为什么只比较首尾**：想象把所有字符串按字典顺序排成一排，最左边的字符串和最右边的字符串的差距最大。公共前缀如果在它们之间出现，一定也会在最左和最右之间出现（因为中间的字符串都是介于两者之间的，不能引入比它们更长的前缀）。因此，首尾的公共前缀必然是全体的公共前缀。  
- **核心算法**：  
  1. 对列表 `strs` 进行字典序排序（Python 的 `sorted`）。  
  2. 取排序后第一个字符串 `first` 与最后一个字符串 `last`。  
  3. 逐字符比较 `first` 与 `last`，直到出现不相同或到达任一字符串的末尾。  
- **类比**：把所有单词想成排队的学生，老师先把他们按名字的字母顺序排列，然后只需要检查排在最前面和最后面的两位学生的名字前缀，因为其他学生的名字都介于这两位之间，不可能拥有更长的共同前缀。  

#### 代码（Python）

```python
def longestCommonPrefix(strs):
    """
    排序后只比较首尾的优化方法
    :param strs: List[str]
    :return: 最长公共前缀
    """
    if not strs:                     # 防止空列表
        return ""

    # 1）先把所有字符串按字典序排好序
    strs_sorted = sorted(strs)

    # 2）取排好序后最左和最右的两个字符串
    first = strs_sorted[0]
    last  = strs_sorted[-1]

    # 3）逐字符比较，最多比较到最短的那个长度
    i = 0
    while i < len(first) and i < len(last) and first[i] == last[i]:
        i += 1                       # 只要相同就继续向右移动

    # i 停在第一个不相同的位置，前 i 个字符就是公共前缀
    return first[:i]
```

#### 复杂度

- **时间复杂度**：O(n·log n + m)  
  - `sorted` 对 `n` 条字符串进行排序，平均时间是 **O(n·log n)**（这里的 `log n` 来自比较次数，字符串内部的比较在最坏情况下要比较到公共前缀长度 `m`，但整体仍然受 `log n` 主导）。  
  - 排序后只比较两个字符串，最多检查 `m` 个字符，所以额外的 **O(m)**。整体比暴力的 **O(n·m)** 更快，尤其当 `n` 很大时优势明显。  
- **空间复杂度**：O(n)（用于存放排序后的列表）  
  - Python 的 `sorted` 会创建一个新的列表，大小与原数组相同。若改用原地排序 `strs.sort()`，则可降到 **O(1)**（不计排序时的递归栈）。

## 心得

- **核心技巧**：利用**排序**把问题的搜索空间压缩到两个极端元素之间，只需要比较首尾即可得到答案。  
- **适用的题型**：  
  1. **最长公共前缀**（本题）  
  2. **寻找数组中所有字符串的最短公共后缀**（可以把字符串反转后同样排序）  
  3. **找出一组单词的最长公共子串**（先排序后只比较相邻的两个）  
- **一句话总结**：**先把数据排好序，再用极端值逼出答案**。

## 反思

- **第一反应**：直接把每个字符逐个比较，写出两层循环的暴力实现。  
- **最容易踩的坑**：  
  - 忽略了空字符串的情况（`""`），会导致索引越界。  
  - 当只有一个字符串时，直接返回它本身。  
  - 排序后要记得比较的是 **首尾**，而不是随意的两个。  
- **下次类似题的第一步**：先思考能否通过**排序**或**哈希**把问题规模从 “遍历全部” 降到 “只看极端/代表性” 的子集，再再进行细致比较。
