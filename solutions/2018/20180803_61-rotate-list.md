# #61. 旋转链表 / Rotate List

> 难度：中等 · 标签：Linked List、Two Pointers · [LeetCode 链接](https://leetcode.com/problems/rotate-list/)

---

## 题目（英文原版）

**Description**

Given the head of a linked list, rotate the list to the right by k places.

**Examples**

**Example 1:**

```
Input: head = [1,2,3,4,5], k = 2
Output: [4,5,1,2,3]
```

**Example 2:**

```
Input: head = [0,1,2], k = 4
Output: [2,0,1]
```

**Constraints**

- The number of nodes in the list is in the range [0, 500].
- -100 <= Node.val <= 100
- 0 <= k <= 2 * 109

---

## 题目（中文翻译）

给定链表（linked list）的头节点 `head`，将链表向右旋转 `k` 位。

示例 1:
```
Input: head = [1,2,3,4,5], k = 2
Output: [4,5,1,2,3]
```

示例 2:
```
Input: head = [0,1,2], k = 4
```

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**一次一次地把链表右移一位**，重复 `k` 次。  
右移一位的操作可以这样理解：

1. 把链表的最后一个节点摘下来（相当于把队伍最后一个人请到前面）。
2. 把它插入到链表的最前面，成为新的 `head`。

在代码里，这一步可以用两次遍历实现：

- 第一次遍历找到倒数第 2 个节点（它的 `next` 才是我们要摘下的节点）。
- 第二次遍历把摘下的节点接到最前面。

> **类比**：把链表想象成排队买票的人，暴力解就是每次让最后一个人跑到队伍最前面，这样跑 `k` 次就完成了“右旋 `k` 位”。

只要我们把每一次的“摘尾 + 插头”都做好，最终的链表一定是正确的——因为每一步都严格遵守了“把最后一个元素移到最前面”的定义。

#### 代码（Python）

```python
# Definition for singly-linked list.
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val          # 节点的数值
        self.next = next        # 指向下一个节点的指针

def rotateRight_bruteforce(head: ListNode, k: int) -> ListNode:
    if not head or not head.next or k == 0:   # 空链表、只有一个节点或不需要旋转，直接返回
        return head

    # 由于 k 可能非常大，先把它压缩到 [0, n) 之间
    # 这里我们仍然采用暴力做法，先算出链表长度 n
    n = 0
    cur = head
    while cur:
        n += 1
        cur = cur.next
    k %= n
    if k == 0:
        return head

    # 暴力：每次右移一位，重复 k 次
    for _ in range(k):
        # 1. 找到倒数第二个节点 pre
        pre = None
        cur = head
        while cur.next:          # 当 cur.next 为 None 时，cur 是最后一个节点
            pre = cur
            cur = cur.next
        # 此时 cur 是原来的最后一个节点，pre 是倒数第二个

        # 2. 把最后一个节点 cur 挂到最前面
        cur.next = head          # 最后一个节点的 next 指向原来的头结点
        head = cur               # 更新 head 为新的头结点
        pre.next = None          # 原倒数第二个节点成为新的尾巴

    return head
```

#### 复杂度

- **时间复杂度**：`O(k·n)`  
  每次右移要遍历整条链表一次（`O(n)`），需要进行 `k` 次，整体是 `k` 乘以 `n`。  
  用大白话说，如果链表有 1000 个节点，`k` 也是 1000，那这段代码大概要跑 **100 万** 次循环。

- **空间复杂度**：`O(1)`  
  整个过程只用到几个指针变量，和链表的规模无关。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**每次右移都要遍历整条链表**，导致时间复杂度随 `k` 成线性增长。  
实际上，我们可以一次性完成所有右移，只需要**一次遍历**链表，得到它的长度和尾节点；随后通过数学运算直接定位新头节点和新尾节点。

核心步骤如下：

1. **先遍历一次，求链表长度 `n` 并把尾节点记下来**。  
   这一步类似于“数队伍里有多少人”，顺手把最后一个人（尾节点）记下来。

2. **把链表变成环形**（把尾节点的 `next` 指向原来的 `head`）。  
   想象把排队的最后一个人手拉手接到第一个人前面，形成一个圆环。这样“右移”其实就是在环上走几步。

3. **计算实际需要移动的步数**：`k %= n`（因为旋转 `n` 次会回到原位）。  
   如果 `k == 0`，直接把环断开返回原链表。

4. **在环上找到新的尾节点**：它是原链表的第 `n - k` 个节点（从 1 开始计数）。  
   这一步可以用**双指针**实现：让一个指针先走 `k` 步，然后两个指针一起走，直到先走的指针到达原来的尾巴。此时慢指针指向的新位置就是**新尾节点**。

5. **断开环，得到旋转后的链表**：`new_head = new_tail.next`，然后 `new_tail.next = None`。

> **类比**：把链表想象成一根绳子，两端分别是头和尾。我们先把两端绑在一起形成一个环，然后沿着环走 `k` 步，站在的地方的下一个节点就是新的头，当前站的节点就是新的尾。最后把环剪断，得到我们想要的线段。

#### 代码（Python）

```python
def rotateRight(head: ListNode, k: int) -> ListNode:
    if not head or not head.next or k == 0:
        return head

    # 1️⃣ 先遍历一次得到链表长度 n 并定位尾节点 tail
    n = 1                 # 至少有一个节点，所以长度从 1 开始计数
    tail = head
    while tail.next:     # 当 tail.next 为 None 时，tail 已经是最后一个节点
        tail = tail.next
        n += 1

    # 2️⃣ 把链表首尾相连，形成环形
    tail.next = head

    # 3️⃣ 计算实际需要移动的步数（因为旋转 n 次会回到原位）
    k %= n
    if k == 0:            # 若 k 为 0，说明环不需要断开，直接恢复原链表
        tail.next = None
        return head

    # 4️⃣ 找到新的尾节点：它是第 (n - k) 个节点
    steps_to_new_tail = n - k
    new_tail = head
    for _ in range(steps_to_new_tail - 1):   # 已经在 head 上，故走 steps-1 步
        new_tail = new_tail.next

    # 5️⃣ 新的头节点就是 new_tail 的下一个节点
    new_head = new_tail.next

    # 6️⃣ 断开环，形成最终的链表
    new_tail.next = None

    return new_head
```

#### 复杂度

- **时间复杂度**：`O(n)`  
  只遍历链表两次（一次算长度并连成环，第二次定位新尾），与 `k` 的大小无关。  
  用大白话说，链表有多长，就跑多少步，最多一次遍历整个链表。

- **空间复杂度**：`O(1)`  
  只使用了常数个指针变量，额外空间不随链表规模增长。

## 心得

- **核心技巧**：**环形链表 + 双指针/一次遍历定位**。  
  通过把链表首尾相连形成环，利用取模把大 `k` 压缩到 `[0, n)`，再一次遍历找新头/新尾。

- **适用的题型**  
  1. `Rotate List`（本题）  
  2. `Linked List Cycle`（判断是否有环）  
  3. `Remove Nth Node From End of List`（需要一次遍历定位倒数第 N 个节点）  

- **一句话总结**：**把链表想成环，一步走到新起点，再剪断即可。**

## 反思

- **第一反应**：看到“右旋 k 位”，自然想到“把最后的节点一个个搬到前面”。这导致了暴力的 `O(k·n)` 思路。

- **最容易踩的坑**  
  1. **`k` 超大**：直接循环 `k` 次会超时，需要先对 `k` 取模。  
  2. **空链表或只有一个节点**：这些特殊情况必须提前返回，否则后面的 `tail.next = head` 会出现空指针错误。  
  3. **环的断开**：形成环后一定要记得把新尾节点的 `next` 设为 `None`，否则会出现无限循环的链表。

- **下次遇到同类题**：第一步先**思考是否可以把结构变成环或使用双指针一次遍历定位**，而不是直接逐步模拟操作。这样往往能把时间从 `O(k·n)` 降到 `O(n)`。
