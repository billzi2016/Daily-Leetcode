# #174. 地下城游戏 / Dungeon Game

> 难度：困难 · 标签：Array、Dynamic Programming、Matrix · [LeetCode 链接](https://leetcode.com/problems/dungeon-game/)

## 题目（英文原版）

**Description**

The demons had captured the princess and imprisoned her in the bottom-right corner of a dungeon. The dungeon consists of m x n rooms laid out in a 2D grid. Our valiant knight was initially positioned in the top-left room and must fight his way through dungeon to rescue the princess.
The knight has an initial health point represented by a positive integer. If at any point his health point drops to 0 or below, he dies immediately.
Some of the rooms are guarded by demons (represented by negative integers), so the knight loses health upon entering these rooms; other rooms are either empty (represented as 0) or contain magic orbs that increase the knight's health (represented by positive integers).
To reach the princess as quickly as possible, the knight decides to move only rightward or downward in each step.
Return the knight's minimum initial health so that he can rescue the princess.
Note that any room can contain threats or power-ups, even the first room the knight enters and the bottom-right room where the princess is imprisoned.

**Examples**

**Example 1:**

```
Input: dungeon = [[-2,-3,3],[-5,-10,1],[10,30,-5]]
Output: 7
Explanation: The initial health of the knight must be at least 7 if he follows the optimal path: RIGHT-> RIGHT -> DOWN -> DOWN.
```

**Example 2:**

```
Input: dungeon = [[0]]
Output: 1
```

**Constraints**

- m == dungeon.length
- n == dungeon[i].length
- 1 <= m, n <= 200
- -1000 <= dungeon[i][j] <= 1000

## 题目（中文翻译）

**描述**  
恶魔俘虏了公主 (princess)，并将她关押在地下城 (dungeon) 的右下角。地下城由 `m × n` 个房间 (rooms) 构成，排列成一个二维网格。英勇的骑士 (knight) 最初位于左上角的房间，必须穿越地下城去救出公主。

骑士拥有一个正整数表示的初始生命值 (initial health point)。如果在任何时刻他的生命值降至 `0` 或以下，他会立即死亡。

- 某些房间被恶魔守卫，用负整数表示，骑士进入这些房间会失去相应的生命值；
- 其他房间可能为空 (`0`) 或包含能提升骑士生命值的魔法球，用正整数表示，骑士进入后会增加相应的生命值。

为了尽快救援，骑士每一步只能向右或向下移动。

返回骑士能够救出公主所需的 **最小初始生命值**。

> 注意：任何房间都可能包含危险或增益，包括骑士进入的起始房间以及公主所在的右下角房间。

**示例**

示例 1  
输入: `dungeon = [[-2,-3,3],[-5,-10,1],[10,30,-5]]`  
输出: `7`  
解释: 骑士必须至少拥有 `7` 点初始生命值，才能沿着最佳路径 `右 -> 右 -> 下 -> 下` 前进。

示例 2  
输入: `dungeon = [[0]]`  
输出: `1`  

**约束条件**

- `m == dungeon.length`
- `n == dungeon[i].length`
- `1 ≤ m, n ≤ 200`
- `-1000 ≤ dungeon[i][j] ≤ 1000`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是**把所有可能的路径枚举出来**，然后逐条模拟骑士的血量变化，找出能够让骑士活到终点的最小初始血量。

- **数据结构**：我们可以把迷宫看成一个二维数组 `dungeon[m][n]`。枚举路径时，只需要记录当前所在的坐标 `(i, j)`，以及已经走过的路径（比如用一个列表保存走过的坐标），这类似于“走迷宫”时的**回溯**（DFS）过程。  
- **生活化类比**：想象你在一张城市地图上只能向右或向下走，每条路上都有“费用”。你要把所有从左上到右下的路线都写下来，然后算每条路的累计费用，最后挑出最省钱的那条。  
- **正确性**：因为我们遍历了**所有**合法路径（只能向右或向下），必然不会漏掉最优路径，所以得到的答案一定是最小的初始血量。  

> 暴力搜索的核心就是“**穷举**”。只要不遗漏任何一种合法走法，答案就一定在我们枚举的集合里。

#### 代码（Python）

```python
from typing import List

def calculate_min_hp_brute(dungeon: List[List[int]]) -> int:
    m, n = len(dungeon), len(dungeon[0])
    best = float('inf')                     # 记录找到的最小初始血量

    # 深度优先搜索，枚举所有路径
    def dfs(i: int, j: int, cur_hp: int, min_hp_needed: int):
        """
        i, j      : 当前所在的坐标
        cur_hp    : 走到这里时的血量（可能为负）
        min_hp_needed : 走到这里为止，最小需要的初始血量（保证血量不掉到 0 以下）
        """
        nonlocal best
        cur_hp += dungeon[i][j]             # 进入当前格子后血量变化
        # 只要血量小于等于 0，就说明需要更大的初始血量来抵消
        min_hp_needed = max(min_hp_needed, 1 - cur_hp)

        # 已经到达右下角，更新全局最小值
        if i == m - 1 and j == n - 1:
            best = min(best, min_hp_needed)
            return

        # 向右走
        if j + 1 < n:
            dfs(i, j + 1, cur_hp, min_hp_needed)
        # 向下走
        if i + 1 < m:
            dfs(i + 1, j, cur_hp, min_hp_needed)

    # 从左上角开始，初始血量先设为 0（后面会根据 min_hp_needed 调整）
    dfs(0, 0, 0, 1)
    return best
```

#### 复杂度  

- **时间复杂度**：`O(2^{m+n})`（指数级）。  
  - 在每一步只能往右或往下，总共要走 `m-1 + n-1` 步。每一步都有 2 种选择（右或下），所以路径数约为 `C(m+n-2, m-1)`，在最坏情况下与 `2^{m+n}` 同阶。可以把 `O(2^{m+n})` 想象成“每增加一行或一列，可能的路径数量就会翻倍”，所以在 `m,n` 取最大 200 时根本不可行。  
- **空间复杂度**：`O(m+n)`（递归栈深度）。  
  - 递归调用的最大深度等于走到右下角的步数 `m+n-2`，每层只保存少量局部变量。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**大量重复计算**：不同路径在后半段往往会走到同一个格子，而我们每次都重新计算从该格子到终点的血量需求。  
要消除这种重复，就需要**把子问题的答案保存下来**，也就是**动态规划（Dynamic Programming, DP）**。

**关键观察**：

1. 骑士只能向右或向下走，**如果从终点逆向思考**（即从右下角往左上角走），每个格子只会向左或向上“走”。这样每个格子的状态只依赖于**右边和下边**两个格子的已经计算好的结果，形成了自然的 DP 转移关系。  
2. 对于任意格子 `(i, j)`，我们关心的是“**进入这个格子后，至少还需要多少血量**才能保证以后不掉血”。记这个值为 `need[i][j]`。  
3. 在格子 `(i, j)`，骑士走下一步要么去 `(i+1, j)`（下），要么去 `(i, j+1)`（右）。为了让血量最小化，骑士会选择**需要血量更少的那条路**。于是  
   ```
   need[i][j] = max(1, min(need[i+1][j], need[i][j+1]) - dungeon[i][j])
   ```
   - `need[i+1][j]`、`need[i][j+1]` 是右/下格子“进入后至少需要的血量”。  
   - `dungeon[i][j]` 是当前格子的血量变化（正数回血，负数扣血）。  
   - `- dungeon[i][j]` 表示在进入当前格子后，血量会相应增减。  
   - `max(1, …)` 保证血量永远不少于 1（血量 0 或负数就死了）。

4. 边界条件：  
   - 右下角 `(m-1, n-1)` 是终点，必须保证离开这个格子后血量≥1。  
     ```
     need[m-1][n-1] = max(1, 1 - dungeon[m-1][n-1])
     ```
   - 最后一行只能向右走，最后一列只能向下走，分别只看一个相邻格子。

**类比**：把每个格子想象成“加油站”。你开车只能向右或向下，想要在终点不熄火。我们从终点倒着算，每个站点需要提前准备的最少油量（即“need”），如果站点本身能加油（正数），需要的油量就会相应减少；如果站点会泄油（负数），则需要更多的油。

#### 代码（Python）

```python
from typing import List

def calculate_min_hp_dp(dungeon: List[List[int]]) -> int:
    m, n = len(dungeon), len(dungeon[0])

    # dp[i][j] 表示从 (i,j) 出发到达终点，进入 (i,j) 前最少需要的血量
    dp = [[0] * n for _ in range(m)]

    # 右下角（公主所在的房间）先算
    dp[-1][-1] = max(1, 1 - dungeon[-1][-1])

    # 最后一行，只能向右走
    for j in range(n - 2, -1, -1):
        dp[-1][j] = max(1, dp[-1][j + 1] - dungeon[-1][j])

    # 最后一列，只能向下走
    for i in range(m - 2, -1, -1):
        dp[i][-1] = max(1, dp[i + 1][-1] - dungeon[i][-1])

    # 从右下角往左上角遍历，填充其余格子
    for i in range(m - 2, -1, -1):
        for j in range(n - 2, -1, -1):
            # 右边和下边两个格子中，取需要血量更少的那条路
            min_needed_next = min(dp[i + 1][j], dp[i][j + 1])
            dp[i][j] = max(1, min_needed_next - dungeon[i][j])

    # dp[0][0] 即为答案：左上角进入前最少需要的血量
    return dp[0][0]
```

#### 复杂度  

- **时间复杂度**：`O(m * n)`。  
  - 我们只遍历了一遍二维矩阵，每个格子做了常数次的计算。可以把 `O(m·n)` 想成“把整个迷宫每个房间都检查一次”，这在 `m,n ≤ 200` 时最多只有 40,000 次操作，完全可以在毫秒级完成。  
- **空间复杂度**：`O(m * n)`（存 `dp` 表）。  
  - 需要一个同样大小的矩阵来保存每个格子的最小血量需求。如果想进一步压缩空间，只保留一行或一列（因为每次只用到右边和下边），可以做到 `O(n)`，但对初学者来说完整的二维表更直观。

## 心得

- **核心技巧**：逆向动态规划 + “从终点倒推需要的最小血量”。  
- **适用题型**：  
  1. 只能向右/下移动且要求最小/最大累计值的网格问题（如 *Minimum Path Sum*、*Maximum Gold Path*）。  
  2. 需要保证途中某个约束始终满足的路径问题（如 *Minimum Initial Energy to Reach Destination*、*Path With Minimum Effort*）。  
- **一句话总结**：**从终点往回算，把每一步的“最小必要血量”保存下来，避免重复子问题**。

## 反思

- **第一反应**：直接想遍历所有路径（暴力搜索），因为“先把思路写出来再优化”是常见的解题套路。  
- **最容易踩的坑**：  
  - 忘记 **血量必须始终 ≥ 1**，导致 `dp` 里出现 0 或负数的错误值。  
  - 边界处理不完整：最后一行/列只能向一个方向走，若直接使用 `min(dp[i+1][j], dp[i][j+1])` 会出现越界。  
  - 对负数房间的处理不对：`max(1, …)` 必须放在最外层，防止出现 0 或负数的初始血量。  
- **下次类似题的第一步**：先判断是否可以**逆向思考**（从终点往起点），如果可以，就把状态定义为“进入该格子前最少需要的资源”，再写出转移方程。这样往往能直接得到 `O(m·n)` 的 DP 解。
