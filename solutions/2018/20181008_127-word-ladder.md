# #127. 单词接龙 / Word Ladder

> 难度：困难 · 标签：Hash Table、String、Breadth-First Search · [LeetCode 链接](https://leetcode.com/problems/word-ladder/)

---

## 题目（英文原版）

**Description**

A transformation sequence from word beginWord to word endWord using a dictionary wordList is a sequence of words beginWord -> s1 -> s2 -> ... -> sk such that:
Given two words, beginWord and endWord, and a dictionary wordList, return the number of words in the shortest transformation sequence from beginWord to endWord, or 0 if no such sequence exists.

**Examples**

**Example 1:**

```
Input: beginWord = "hit", endWord = "cog", wordList = ["hot","dot","dog","lot","log","cog"]
Output: 5
Explanation: One shortest transformation sequence is "hit" -> "hot" -> "dot" -> "dog" -> cog", which is 5 words long.
```

**Example 2:**

```
Input: beginWord = "hit", endWord = "cog", wordList = ["hot","dot","dog","lot","log"]
Output: 0
Explanation: The endWord "cog" is not in wordList, therefore there is no valid transformation sequence.
```

**Constraints**

- 1 <= beginWord.length <= 10
- endWord.length == beginWord.length
- 1 <= wordList.length <= 5000
- wordList[i].length == beginWord.length
- beginWord, endWord, and wordList[i] consist of lowercase English letters.
- beginWord != endWord
- All the words in wordList are unique.

## 题目（中文翻译）

**描述**  
从单词 `beginWord` 到单词 `endWord` 使用字典（dictionary）`wordList` 的一次**转换序列（transformation sequence）**是形如 `beginWord -> s1 -> s2 -> ... -> sk` 的单词序列，使得相邻两个单词仅相差一个字符。  

给定两个单词 `beginWord` 和 `endWord`，以及一个字典 `wordList`，返回从 `beginWord` 到 `endWord` 的**最短转换序列**中的单词数量。如果不存在这样的序列，则返回 `0`。

**示例 1**  
**输入**: `beginWord = "hit", endWord = "cog", wordList = ["hot","dot","dog","lot","log","cog"]`  
**输出**: `5`  
**解释**: 一条最短的转换序列为 `"hit" -> "hot" -> "dot" -> "dog" -> "cog"`，共计 5 个单词。

**示例 2**  
**输入**: `beginWord = "hit", endWord = "cog", wordList = ["hot","dot","dog","lot","log"]`  
**输出**: `0`  
**解释**: `endWord` `"cog"` 不在 `wordList` 中，因此不存在有效的转换序列。

**约束条件**  
- `1 <= beginWord.length <= 10`  
- `endWord.length == beginWord.length`  
- `1 <= wordList.length <= 5000`  
- `wordList[i].length == beginWord.length`  
- `beginWord`, `endWord` 和 `wordList[i]` 均由小写英文字母组成。  
- `beginWord != endWord`  
- `wordList` 中的所有单词互不相同。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**把每一次单词的变化当成一次“跳”**，从 `beginWord` 开始，遍历所有可能的下一步单词（即只差一个字母且在 `wordList` 中的单词），再对每一个得到的单词继续这样跳，直到跳到 `endWord` 为止。  
这本质上就是 **广度优先搜索（BFS）**——从起点层层展开，最先到达终点的层数就是最短路径的长度。

- **数据结构**  
  - **队列**：BFS 需要一个“先入先出”的队列来保存当前层的单词，后进先出会导致遍历顺序错乱。  
  - **集合（Hash Set）**：用来存放 `wordList`，查询一个单词是否在字典里相当于查字典：`key` 是单词，`value` 可以随便（这里直接用 `set`），查找时间是 *O(1)*。  

- **为什么正确**  
  BFS 按层搜索，先访问的都是离起点最近的单词；只要我们每一次只走一步（只能改一个字母），第一次碰到 `endWord` 时，走的步数一定是最少的。

- **复杂度分析（大白话）**  
  - 对每个弹出的单词，我们要遍历整个 `wordList`（最多 5000 个）去找“只差一个字母”的候选，这一步相当于在字典里逐个比对。  
  - 如果单词长度是 `L`，比较两个单词是否只差一个字母需要 `L` 次字符比较。  
  - 因此最坏情况下 **每层的比较次数** 是 `O(N·L)`（`N` 为字典大小），而 BFS 最多会遍历所有单词，整体时间复杂度是 **`O(N²·L)`**。  
  - 空间上我们需要保存队列和集合，最多存 `N` 个单词，**`O(N)`**。

#### 代码（Python）

```python
from collections import deque
from typing import List

def ladderLength_brute(beginWord: str, endWord: str, wordList: List[str]) -> int:
    # 把 wordList 放进集合，查找是否存在单词是 O(1) 的操作
    word_set = set(wordList)
    if endWord not in word_set:          # 终点不在字典里，直接返回 0
        return 0

    # BFS 用的队列，里边存 (当前单词, 已经走了几步)
    q = deque()
    q.append((beginWord, 1))             # 起点算作第 1 步

    while q:
        cur_word, steps = q.popleft()    # 取出队首元素

        # 逐个尝试字典里的每个单词，看是否只差一个字符
        for w in list(word_set):         # 把集合转成列表遍历，遍历期间可以删元素
            diff = sum(c1 != c2 for c1, c2 in zip(cur_word, w))
            if diff == 1:                # 只差一个字母，合法的下一步
                if w == endWord:        # 已经到达终点，返回步数+1
                    return steps + 1
                q.append((w, steps + 1))
                word_set.remove(w)      # 已经访问过，防止重复入队

    # BFS 结束仍未找到终点，说明不存在转换序列
    return 0
```

#### 复杂度

- **时间复杂度**：`O(N²·L)`  
  - `N` 为字典大小（最多 5000），`L` 为单词长度（最多 10）。  
  - 想象一下，5000 本书每本都要和 5000 本书比对一次，每次比对要检查 10 个字母，时间会比较大。

- **空间复杂度**：`O(N)`  
  - 需要保存 `word_set`（最多 N 个单词）和 BFS 队列（最坏情况下也会装 N 个单词）。

### 2. 最优解

#### 思路  

从暴力解可以看到 **瓶颈** 在于每次都要遍历整个 `wordSet` 去找只差一个字母的单词，这导致了 `O(N²·L)` 的时间。  
我们可以把 “只差一个字母” 的关系 **提前预处理**，让查询变得 **O(1)**。

**核心技巧——通配词（generic state）**  
把每个单词的每一个位置都用 `*` 替换掉，得到若干“中间形态”。例如单词 `dog` 可以得到：

- `*og`
- `d*g`
- `do*`

如果两个单词只差一个字母，它们一定会拥有相同的某个通配词。例如 `dog` 与 `log` 都有 `*og`。  
我们把 **通配词 → 所有拥有该通配词的原单词** 建立一个哈希表（字典），查询只差一个字母的邻居只需要：

1. 把当前单词生成所有通配词（`L` 次）。
2. 用哈希表直接得到对应的候选单词列表。

这样每次扩展邻居的时间从 **遍历全部字典** 降到 **只看与当前单词相邻的那几条边**，整体时间降到 **`O(N·L)`**。

**进一步优化——双向 BFS**  
即同时从 `beginWord` 和 `endWord` 各自进行 BFS，始终让**搜索规模较小的一端**继续展开。当两端的搜索相遇时，路径长度即为答案。双向 BFS 可以把搜索空间大致减半，实际运行更快。

**步骤概览**  

1. **预处理通配词表**  
   - 对每个字典单词（包括 `beginWord`），遍历 `L` 个位置，用 `*` 替换，记录到 `defaultdict(list)` 中。  
2. **初始化双向 BFS**  
   - `begin_set` 包含 `beginWord`，`end_set` 包含 `endWord`。  
   - `visited` 用来记录已经访问过的单词，防止重复。  
3. **循环搜索**  
   - 每轮从规模更小的集合出发，生成下一层的所有邻居（通过通配词表）。  
   - 若邻居在另一端集合中出现，说明两端相遇，返回 `step + 1`。  
   - 否则把新邻居加入本轮的 `next_set`，并标记已访问。  
4. 若搜索结束仍未相遇，返回 0。

#### 代码（Python）

```python
from collections import defaultdict, deque
from typing import List

def ladderLength(beginWord: str, endWord: str, wordList: List[str]) -> int:
    """
    双向 BFS + 通配词预处理
    返回最短转换序列的长度（包含 beginWord 和 endWord），不存在则返回 0
    """
    if endWord not in wordList:                 # 终点不在字典，直接失败
        return 0

    L = len(beginWord)                          # 单词长度，所有单词长度相同

    # 1️⃣ 预处理：构建通配词 -> 原单词列表 的映射
    # 例如 "*og" -> ["dog", "log", "cog"]
    generic_dict = defaultdict(list)
    for word in wordList:
        for i in range(L):
            generic = word[:i] + '*' + word[i+1:]
            generic_dict[generic].append(word)
    # 注意：beginWord 可能不在 wordList 中，但它的通配词也需要加入
    for i in range(L):
        generic = beginWord[:i] + '*' + beginWord[i+1:]
        generic_dict[generic].append(beginWord)

    # 2️⃣ 双向 BFS 初始化
    begin_set = {beginWord}                     # 正向搜索集合
    end_set   = {endWord}                       # 反向搜索集合
    visited   = {beginWord, endWord}            # 已访问的单词
    step = 1                                    # 已经走过的层数（起点算第 1 步）

    # 3️⃣ 循环搜索
    while begin_set and end_set:
        # 始终从小的那边展开，减少分支数量
        if len(begin_set) > len(end_set):
            begin_set, end_set = end_set, begin_set

        next_set = set()                        # 本轮搜索产生的下一层单词

        for word in begin_set:
            # 通过所有通配词找到相邻单词
            for i in range(L):
                generic = word[:i] + '*' + word[i+1:]
                for neighbor in generic_dict[generic]:
                    if neighbor in end_set:     # 两端相遇，返回总步数
                        return step + 1
                    if neighbor not in visited:
                        visited.add(neighbor)
                        next_set.add(neighbor)

        # 进入下一轮
        begin_set = next_set
        step += 1

    # 没有找到可达路径
    return 0
```

#### 复杂度

- **时间复杂度**：`O(N·L)`  
  - 预处理遍历所有 `N` 个单词，每个单词生成 `L` 条通配词，时间 `O(N·L)`。  
  - 双向 BFS 每次只遍历当前层的单词以及它们的 `L` 条通配词，总体仍然是 `O(N·L)`（因为每个单词最多被访问一次）。  
  - 与暴力解的 `O(N²·L)` 相比，省掉了大量无用的比较。

- **空间复杂度**：`O(N·L)`  
  - `generic_dict` 存储了 `N·L` 条通配词 → 单词的映射。  
  - 额外的 `visited`、`begin_set`、`end_set` 等集合最多也只会保存 `N` 个单词。

## 心得

- **核心技巧**：  
  1. **通配词（generic state）** 把“只差一个字符”的关系提前构建成哈希表，实现 O(1) 的邻居查询。  
  2. **双向 BFS** 把搜索范围从单向的指数级下降到约半，显著提升实际运行速度。

- **适用题型**（可以套用同样思路的 LeetCode 题目）  
  1. **127. Word Ladder**（本题）  
  2. **126. Word Ladder II**（要求输出所有最短路径）  
  3. **209. Minimum Size Subarray Sum**（思路类似的滑动窗口 + 前缀和）  
  4. **172. Factorial Trailing Zeroes**（用哈希表预处理的思路）  

- **一句话总结**：  
  *把“只差一个字母”的邻接关系提前准备好，再用双向 BFS 把搜索范围压到最小，这就是 Word Ladder 的解题钥匙。*

## 反思

- **第一反应**：直接用 BFS，从起点层层展开，遇到终点即返回步数。  
- **最容易踩的坑**  
  1. **终点不在字典**：必须先检查 `endWord` 是否在 `wordList`，否则会一直搜索不到。  
  2. **重复访问**：如果不记录已访问的单词，会产生环路，导致时间指数爆炸。  
  3. **通配词预处理遗漏**：`beginWord` 可能不在 `wordList`，但它的通配词也必须加入，否则第一层就找不到邻居。  
  4. **边界条件**：当 `beginWord` 与 `endWord` 只差一个字母时，答案应为 `2`（起点 + 终点），代码必须能正确返回。

- **下次遇到同类题的第一步**：  
  先思考“相邻关系”怎么快速查询——是否可以像本题一样通过预处理或特定的数据结构（哈希表、前缀树、单调栈等）把邻接关系压平；如果可以，就在此基础上选用 BFS / 双向 BFS 求最短路径。
