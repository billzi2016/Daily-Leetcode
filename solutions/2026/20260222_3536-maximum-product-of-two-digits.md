## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把整数 `n` 的每一位数字都取出来，随后把所有可能的两位组合都算一遍，记录最大的乘积即可。

- **数据结构**：我们把数字拆成一个列表 `digits`，类似把一串文字拆成单词放进字典里查找。这里的列表就像一个装有所有“字母”的盒子，顺序不重要，只要能遍历就行。
- **正确性**：遍历所有两两组合（不论顺序），一定能覆盖“任意两个数字”的所有可能性，所以最大乘积一定会被找到。
- **复杂度分析**：  
  - 假设数字有 `d` 位（`d ≤ 10`，因为 `n ≤ 10⁹`），两层循环会检查 `d·(d-1)/2` 对，数量级记作 **O(d²)**。  
  - 空间上我们只额外存了一个装数字的列表，大小为 `d`，即 **O(d)**。

> **大白话**：`O(d²)` 就像在一群人里挑两个人配对，人数多了配对次数会呈平方增长；而 `O(d)` 就像只需要记下每个人的名字，一次遍历就够。

#### 代码（Python）

```python
def maxProduct_brute(n: int) -> int:
    # 把整数拆成每一位数字，放进列表
    digits = [int(ch) for ch in str(n)]   # 例：124 -> [1,2,4]

    max_prod = 0
    # 双层循环枚举所有两位组合
    for i in range(len(digits)):
        for j in range(i + 1, len(digits)):
            prod = digits[i] * digits[j]   # 计算乘积
            if prod > max_prod:            # 记录最大的乘积
                max_prod = prod

    # 如果数字中只有一个不同的数字且出现多次（如 22），
    # 上面的循环已经遍历到相同位置的两次出现，仍然可以得到正确答案。
    return max_prod
```

#### 复杂度

- **时间复杂度**：`O(d²)` —— 需要遍历所有两两组合，`d` 最多 10，实际运行非常快。
- **空间复杂度**：`O(d)` —— 只存储拆开的数字列表，最多 10 个整数。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **两层循环**，每次都要检查很多已经不可能成为最大值的组合。观察数字的取值范围可以发现：

- 每个数字都是 **0~9** 的整数，只有 10 种可能。
- 要想让乘积最大，只需要找出 **最大的两位数字**（若最大数字出现多次，则可以用同一个数字两次）。

因此，只要一次遍历记录下最大的两位数字（或记录出现次数），即可在 **O(d)** 时间内得到答案。

实现方式有两种：

1. **计数法**：用长度为 10 的数组 `cnt[0..9]` 统计每个数字出现次数，随后从大到小找出前两位。  
2. **一次遍历法**：维护 `first`（最大）和 `second`（次大），在遍历时实时更新。

下面用第二种方式，因为代码更简洁且不需要额外的计数数组。

- **核心技巧**：**单遍历找最大/次大**，这在很多“找前 K 大”问题中都很常见。把它想象成在排队时只记下最高的两个人的身高，而不必记下所有人的身高。

#### 代码（Python）

```python
def maxProduct_optimal(n: int) -> int:
    # 初始化为 -1，表示还没有遇到任何数字
    first, second = -1, -1

    # 逐位遍历整数的每一位
    for ch in str(n):
        d = int(ch)                # 当前数字

        if d > first:              # 出现更大的数字，first、second 都要更新
            second = first
            first = d
        elif d > second:           # 只比 second 大，不影响 first
            second = d

    # 这里保证 second 至少是 -1（若所有位都是同一个数字且只出现一次，
    # 题目保证 n >= 10，至少有两位，所以不会出现这种情况）。
    return first * second
```

#### 复杂度

- **时间复杂度**：`O(d)` —— 只遍历一次数字列表，`d ≤ 10`，几乎是常数时间。相比暴力的 `O(d²)`，省掉了大量不必要的比较。
- **空间复杂度**：`O(1)` —— 只用常数个变量 `first、second`，不随输入规模增长。

## 心得

- **核心技巧**：**一次遍历找出最大两位数字**（或使用计数法找前两大），这是一种“贪心”思路——局部最优（当前最大的两个）即是全局最优。
- **适用题型**：
  1. “找数组中最大的两个数” 类似题目（LeetCode 53. Maximum Subarray 里的局部最大思想）。
  2. “找字符串中出现频率最高的前 K 个字符”——可以用计数 + 排序或一次遍历维护前 K。
  3. “找数组中两数之和最大”——先排序再用双指针，思路同样是先把“大”放在前面处理。
- **一句话总结**：**只要数字范围小，直接找最大两位就能得到乘积的上界**。

## 反思

- **第一反应**：把数字拆出来，枚举所有两两组合——这就是暴力解的自然想法。
- **最容易踩的坑**：
  - 忘记考虑 **同一数字出现多次** 的情况（如 `22`），直接只取不同数字会导致错误。
  - 对于只有一位数字的情况（题目保证 `n ≥ 10`，但若放宽约束，需要额外处理）。
- **下次类似题目第一步**：先确认 **取值范围**（这里是 0~9），再思考是否能用 **计数或一次遍历** 把“最大/次大”直接找出来，而不是全部枚举。这样可以迅速从暴力走向最优。
