## 题目（英文原版）

**Description**

You are given an integer array nums of length n.
An array is trionic if there exist indices 0 < p < q < n − 1 such that:
Return true if nums is trionic, otherwise return false.

**Examples**

**Example 1:**

```
Input: nums = [1,3,5,4,2,6]
Output: true
Explanation:
Pick p = 2 , q = 4 :
```

**Example 2:**

```
Input: nums = [2,1,3]
Output: false
Explanation:
There is no way to pick p and q to form the required three segments.
```

**Constraints**

- 3 <= n <= 100
- -1000 <= nums[i] <= 1000

---

## 题目（中文翻译）

给定一个长度为 `n` 的整数数组 `nums`。

如果存在满足 `0 < p < q < n - 1` 的下标 `p` 和 `q`，使得：

- `nums[0] < nums[1] < … < nums[p]` （严格递增的前缀）  
- `nums[p] > nums[p + 1] > … > nums[q]` （严格递减的中间段）  
- `nums[q] < nums[q + 1] < … < nums[n - 1]` （严格递增的后缀）

则称数组 `nums` 为 **三相数组（trionic array）**。

返回 `true` 表示 `nums` 为三相数组，否则返回 `false`。

---

### 示例

#### 示例 1
```text
输入: nums = [1,3,5,4,2,6]
输出: true
解释:
选取 p = 2, q = 4 时，
前缀 [1,3,5] 严格递增，
中间段 [4,2] 严格递减，
后缀 [6] 严格递增。
因此数组满足条件，返回 true。
```

#### 示例 2
```text

输出: false
解释:
无法选取满足 0 < p < q < n-1 的下标，使得数组被划分为
递增‑递减‑递增的三段。
因此返回 false。
```

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的办法就是把所有可能的 `p`、`q` 全部枚举一遍，然后检查三段是否满足题目要求。  

- **数据结构**：我们只需要普通的 Python 列表（`list`）和几个整数变量。可以把「哈希表」想象成一本词典，`key` 是单词，`value` 是对应的页码；这里我们根本不需要这种查找结构，只要顺序遍历数组就行。  
- **为什么正确**：题目说“存在下标 `0 < p < q < n‑1`，使得”  
  1. `nums[0] < nums[1] < … < nums[p]`（严格递增）  
  2. `nums[p] > nums[p+1] > … > nums[q]`（严格递减）  
  3. `nums[q] < nums[q+1] < … < nums[n‑1]`（再次严格递增）  
  只要我们把所有合法的 `(p, q)` 都尝试一遍，必然会碰到满足上述三条的组合（如果有的话），于是可以得到正确答案。  

- **时间/空间复杂度**  
  - 枚举 `p` 有 `O(n)` 种可能，枚举 `q` 也最多 `O(n)` 种。每一次检查三段的单调性最多要遍历整个数组 `O(n)`。所以总体是 `O(n³)`。  
  - `O(n³)` 听起来很大，但这里的 `n ≤ 100`，最多只有 `1,000,000` 次基本比较，完全可以接受。  
  - 只用了常数级的额外空间（几个计数器），因此空间复杂度是 `O(1)`。

#### 代码（Python）

```python
def isTrionic(nums):
    n = len(nums)
    # p 必须在 1..n-3 之间，q 必须在 p+1..n-2 之间
    for p in range(1, n - 2):
        # 检查左侧是否严格递增
        inc_ok = True
        for i in range(1, p + 1):
            if nums[i] <= nums[i - 1]:      # 只要出现不严格递增，就不符合
                inc_ok = False
                break
        if not inc_ok:
            continue

        for q in range(p + 1, n - 1):
            # 检查中间是否严格递减
            dec_ok = True
            for i in range(p + 1, q + 1):
                if nums[i] >= nums[i - 1]:
                    dec_ok = False
                    break
            if not dec_ok:
                continue

            # 检查右侧是否严格递增
            inc2_ok = True
            for i in range(q + 1, n):
                if nums[i] <= nums[i - 1]:
                    inc2_ok = False
                    break
            if inc2_ok:          # 三段全部满足，直接返回 True
                return True

    # 所有 (p, q) 都尝试完了，仍未找到合法划分
    return False
```

#### 复杂度  

- **时间复杂度**：`O(n³)`  
  - “O(n³)” 可以理解为：如果 `n = 100`，最坏情况下要做大约 `100 × 100 × 100 = 1,000,000` 次比较，虽然看起来很多，但在现代电脑上一瞬间就完成。  
- **空间复杂度**：`O(1)`  
  - 只用了几个整数变量，和输入数组的大小无关。

### 2. 最优解  

#### 思路  

暴力解的瓶颈在于**重复遍历相同的子数组**。  
- 当我们已经知道左边 `0 … p` 是递增的，后面再检查 `p … q` 时，不需要每次都从 `0` 再遍历一遍。  
- 同理，`q … n‑1` 的递增检查也可以利用之前的信息。

我们可以把整个过程压缩到一次线性扫描，只需要维护三个“状态”：

| 状态 | 含义 | 何时进入 |
|------|------|----------|
| 0    | 正在寻找第一次递增的段落（还没有出现下降） | 初始状态 |
| 1    | 已经进入递减段，需要找到递增的“谷底” | 当出现 **递减** 且左侧已经有至少一个递增元素 |
| 2    | 已经进入第二次递增段，只要再出现一次递增即可判定成功 | 当出现 **递增** 且已经完成递减段且右侧还有元素 |

**关键点**：

1. **严格单调**：等于 (`==`) 的情况会直接终止，因为题目要求严格 `<` 或 `>`。  
2. **每段至少一个元素**：  
   - 进入状态 1 前必须已经走过至少一次递增（`i > 1`），保证左段长度 ≥ 2（包含 `0` 与 `p`）。  
   - 进入状态 2 前必须已经走过至少一次递减（`i > p+1`），保证中段长度 ≥ 2（包含 `p` 与 `q`）。  
3. 一旦状态变成 2，说明已经找到了 `p`、`q`，并且后面还有元素（因为循环还在进行），直接返回 `True`。  

这样只遍历一次数组，时间从 `O(n³)` 降到 `O(n)`，空间仍是 `O(1)`。

#### 代码（Python）

```python
def isTrionic(nums):
    n = len(nums)
    if n < 3:                     # 题目保证 n >= 3，这里防御性检查
        return False

    state = 0                     # 0：递增段   1：递减段   2：第二次递增段
    i = 1                         # 从第二个元素开始比较

    while i < n:
        if state == 0:            # 还在第一个递增段
            if nums[i] > nums[i - 1]:
                # 仍然递增，保持 state=0
                pass
            elif nums[i] < nums[i - 1] and i > 1:
                # 出现第一次下降，并且已经有至少一个递增元素 → 进入递减段
                state = 1
            else:                 # 出现相等或在 i==1 时直接下降，不能形成合法的左段
                return False

        elif state == 1:          # 正在递减段
            if nums[i] < nums[i - 1]:
                # 仍然递减，保持 state=1
                pass
            elif nums[i] > nums[i - 1] and i > 2:
                # 第一次上升，且已经走过至少一次递减 → 进入第二次递增段
                state = 2
                # 只要后面还有元素（i < n-1），就已经满足题意
                return True
            else:                 # 出现相等或提前上升（i <= 2），不合法
                return False

        else:                     # state == 2 已经不再需要循环，理论上不会走到这里
            break
        i += 1

    # 循环结束仍未进入 state==2，说明没有满足的 (p, q)
    return False
```

> **代码说明（中文注释已在代码中）**  
> - `state` 用来记录我们当前处在哪个阶段。  
> - `i > 1`、`i > 2` 等判断确保每段至少包含一个元素。  
> - 一旦进入第二次递增段（`state == 2`），立即返回 `True`，因为右侧必然还有至少一个元素（循环尚未结束）。  

#### 复杂度  

- **时间复杂度**：`O(n)`  
  - 只遍历一次数组，`n = 100` 时最多 100 次比较。相比暴力的 `1,000,000` 次，快了几个数量级。  
- **空间复杂度**：`O(1)`  
  - 只用了几个整数变量，和数组长度无关。

## 心得  

- **核心技巧**：**状态机（有限状态自动机） + 单调性判断**。  
- **适用的题型**  
  1. “山脉数组” / “先增后减” 类题目（LeetCode 941、LeetCode 162）  
  2. “先增后减再增” 这类需要多段单调性的题目（本题、LeetCode 1572 “Replace All ? to Avoid Consecutive Repeating Characters” 的思路类似）  
  3. “波峰波谷” 检测（如寻找数组中的峰值和谷值）  

- **一句话总结**：把“递增‑递减‑递增”看成一次状态转移，顺序扫描即可一次搞定。

## 反思  

- **第一反应**：直接想到枚举所有 `p、q`，写三层循环。  
- **最容易踩的坑**  
  1. **相等元素**：题目要求严格 `<`、`>`，出现 `==` 必须立即判为失败。  
  2. **段长必须 ≥ 1**：忘记检查 `i > 1`、`i > 2` 之类的边界，会误判像 `[1,2,1]` 这类只有两段的数组。  
  3. **下标范围**：`p` 与 `q` 必须满足 `0 < p < q < n‑1`，尤其要防止 `p` 或 `q` 落在数组端点。  

- **下次类似题的第一步**：先在脑海里把“先做什么 → 什么时候换状态 → 何时结束”画成状态转移图，再决定是暴力枚举还是用一次扫描实现状态机。这样可以快速定位瓶颈并写出最优解。
