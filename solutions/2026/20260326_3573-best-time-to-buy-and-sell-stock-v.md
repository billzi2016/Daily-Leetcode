## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**枚举所有可能的买卖时机**，然后挑选利润最大的那一种。  
我们可以把每天的股价想成一条数轴上的点，**一次完整的交易**就是在这条数轴上挑选两个点：先在左边的点“买入”，再在右边的点“卖出”。  

如果最多只能做 `k` 笔交易，就需要在 `prices` 数组里挑选 `k` 对这样的点（每对必须不交叉、且必须按时间顺序）。  
暴力做法就是：

1. 从第 `0` 天开始，尝试所有可能的买入日 `i`。  
2. 对每个买入日 `i`，遍历它之后的每一天 `j (i<j)` 作为卖出日，计算这笔交易的利润 `prices[j] - prices[i]`。  
3. 递归地在 `j+1` 之后继续寻找剩余的 `k-1` 笔交易。  
4. 把所有递归分支的利润相加，取最大值。

> **类比**：把每一次买卖看成在字典里查两个词（买入词、卖出词），暴力法就是把所有词对都列出来，再挑出最好的组合。

**为什么它一定能得到正确答案？**  
因为我们穷举了 **所有** 合法的买卖序列，答案一定在其中。只要遍历完整，就不可能漏掉最优解。

**时间/空间复杂度**  
- 时间复杂度：每一次买入都要尝试后面所有的卖出，再递归寻找剩余交易。最坏情况下相当于在 `n` 天里选 `k` 对不交叉的区间，组合数约为 `O(n^{2k})`（每笔交易需要选两个位置），这在 `n ≤ 1000`、`k ≤ n/2` 时几乎不可接受。  
- 空间复杂度：递归栈的深度最多 `k`，所以是 `O(k)`，这本身不算大，但由于时间开销巨大，实际运行会因为超时而失效。

#### 代码（Python）

```python
def maxProfit_bruteforce(prices, k):
    n = len(prices)

    # 递归函数：从 idx 开始，剩余 trans 笔交易还能完成的最大利润
    def dfs(idx, trans):
        # 没有剩余交易或已经到达数组末尾，利润为 0
        if trans == 0 or idx >= n:
            return 0

        best = dfs(idx + 1, trans)          # 不在 idx 这天买，直接跳到下一天

        # 枚举在 idx 这天买入的所有可能卖出日
        for sell in range(idx + 1, n):
            profit = prices[sell] - prices[idx]          # 本次交易的利润
            # 交易完成后，继续在 sell+1 之后找剩余的 trans-1 笔交易
            best = max(best, profit + dfs(sell + 1, trans - 1))

        return best

    return dfs(0, k)
```

#### 复杂度

- **时间复杂度**：`O(n^{2k})` —— 每笔交易需要选两个日子，所有组合都会被遍历。可以把它想象成“把 n 天的牌全排列后再挑 k 对”，数量极大。  
- **空间复杂度**：`O(k)` —— 递归栈最多保存 `k` 层调用。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**重复计算**：同一天、相同剩余交易次数的子问题会被反复求解。  
我们可以把“在第 i 天，已经完成了 t 笔交易，手里是持有股票还是不持有”这几个信息抽象成**状态**，然后用**动态规划**把子问题的最优解缓存起来，只算一次。

**状态定义**  

- `dp[t][0]`：到当前遍历的这一天为止，已经完成了 `t` 笔**已结束**的交易，且**手里不持有**股票时的最大利润。  
- `dp[t][1]`：到当前遍历的这一天为止，已经完成了 `t` 笔**已结束**的交易，但**手里正持有**一支股票时的最大利润。  
  （持有股票意味着已经买进了第 `t+1` 笔交易的“买”这一步，还没卖掉）

**状态转移**（对每一天的价格 `price`）：

| 操作 | 转移公式 | 含义 |
|------|----------|------|
| **不持有 → 不持有** | `dp[t][0] = max(dp[t][0], dp[t][1] + price)` | 如果昨天已经持有股票，今天卖出，完成第 `t` 笔交易，利润增加 `price` |
| **持有 → 持有** | `dp[t][1] = max(dp[t][1], dp[t-1][0] - price)` | 如果昨天不持有，今天买入，开始第 `t` 笔交易的“买”这一步，利润减去买入价 `price` |

**初始化**  

- `dp[0][0] = 0`（没有任何交易，利润为 0）  
- `dp[0][1] = -inf`（不可能在 0 笔已完成交易的情况下持有股票）  
- 其余 `dp[t][0] = dp[t][1] = -inf`，表示尚未到达这些状态。

**特殊情况**：当 `k >= n/2` 时，最多能完成的交易数实际上已经够多，等价于**无限次交易**。此时只要把每一次“涨价”都抓住即可，算法可以简化为一次线性扫描，时间 `O(n)`。

**核心算法**：遍历 `prices`，对每个 `price` 再遍历 `t = 1 … k`（从大到小更新，防止本轮更新干扰同一天的其他 `t`），依据上表更新 `dp`。最终答案是 `dp[k][0]`（最多 k 笔已完成且不持有股票的最大利润）。

**类比**：把每一次“买”看成在字典里写下一个词条的**起始页码**，把“卖”看成在同一本字典里写下对应词条的**结束页码**。`dp[t][0]` 记录已经写好的完整词条的总页数，`dp[t][1]` 记录正在写的词条的起始页码（负数表示花了钱）。每天我们可以决定“继续写当前词条”或“把当前词条写完再开始新词条”。

#### 代码（Python）

```python
from math import inf

def maxProfit(prices, k):
    n = len(prices)
    # 当 k 足够大时，等价于无限次交易，只要每一次涨价都抓住即可
    if k >= n // 2:
        profit = 0
        for i in range(1, n):
            profit += max(0, prices[i] - prices[i - 1])
        return profit

    # dp[t][0]：t 笔已完成交易且手里不持有股票的最大利润
    # dp[t][1]：t 笔已完成交易且手里持有股票的最大利润（已经买入第 t+1 笔的买）
    dp = [[-inf, -inf] for _ in range(k + 1)]
    dp[0][0] = 0               # 0 笔交易、手里不持有，利润为 0

    for price in prices:
        # 必须从大到小遍历 t，防止本轮的 dp[t][1] 被同一天的更新“提前使用”
        for t in range(k, 0, -1):
            # 先处理持有 → 不持有（卖出） 的转移
            dp[t][0] = max(dp[t][0], dp[t][1] + price)
            # 再处理不持有 → 持有（买入） 的转移
            dp[t][1] = max(dp[t][1], dp[t-1][0] - price)
        # t = 0 时只能保持不持有的状态（因为没有交易可以完成），但仍可以更新持有状态为“买入第一笔”
        dp[0][1] = max(dp[0][1], -price)   # 相当于 t-1 = -1，视作 0 笔已完成后直接买入

    # 最终答案一定是不持有股票的状态，因为持有股票意味着还有未卖出的成本
    return dp[k][0]
```

#### 复杂度

- **时间复杂度**：`O(k * n)`  
  - 每天遍历一次 `prices`（`n`），内部循环遍历 `k` 次交易次数。可以把它想象成“把 n 张卡片排成一行，然后在每张卡片上做 k 次小动作”，总共做 `k·n` 次操作。  
  - 与暴力的指数级 `O(n^{2k})` 相比，线性乘积在 `n ≤ 1000`、`k ≤ 500` 时完全可以接受。

- **空间复杂度**：`O(k)`  
  - 我们只保留两列（持有 / 不持有）共 `k+1` 组状态，空间随 `k` 成线性增长。相当于只用 `k` 本小笔记本来记下当前的最佳利润，而不需要整个 `n×k` 的大表格。

## 心得

- **核心技巧**：使用**动态规划**把“已完成的交易次数 + 手中是否持股”抽象为状态，利用状态转移避免重复计算。  
- **适用题型**：  
  1. *Best Time to Buy and Sell Stock III*（最多两笔交易）  
  2. *Best Time to Buy and Sell Stock with Cooldown*（带冷却期）  
  3. *Best Time to Buy and Sell Stock with Transaction Fee*（有手续费）  
- **一句话总结解题钥匙**：**把每一次买入/卖出看成状态的“进入/退出”，用 DP 把子问题的最优解缓存下来**。

## 反思

- **第一反应**：直接想遍历所有买卖组合（暴力），因为题目只说“最多 k 笔”，直觉上会先把所有可能列出来。  
- **最容易踩的坑**：  
  - **状态初始化**：`dp[t][1]` 必须设为负无穷，否则会错误地把未买入的持有状态当作合法利润。  
  - **交易次数的界限**：`k` 可能大于 `n/2`，此时必须转为无限次交易的快速解法，否则 DP 仍然是 `O(k·n)`，但 `k` 可能接近 `500`，仍然可以接受，只是没有必要。  
  - **遍历顺序**：在同一天更新 `dp[t][0]` 与 `dp[t][1]` 时必须**从大到小**遍历 `t`，否则会出现“一笔交易在同一天被买进又卖出”的非法情况。  
- **下次类似题**：第一步先思考**“有什么不变的东西可以缓存？”**（如已完成的交易次数、是否持股），把它们写成 DP 状态，再检查是否有特殊情况可以直接简化（如交易次数上界、费用、冷却期等）。
