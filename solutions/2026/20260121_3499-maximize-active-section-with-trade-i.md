## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把**所有可能的交易**都枚举一遍，然后挑出能让 `'1'` 的数量最多的那一次。  
这里的「交易」可以理解为：

> 选取字符串中连续的 **`1` 段**（记作 `block`），把它左边紧挨的 `0` 段和右边紧挨的 `0` 段全部变成 `1`。  
> 这样 `block` 本身的 `1` 不会消失，只会把它左右的 `0`「激活」成 `1`。

暴力做法就是：

1. 先把原始字符串 `s` 中所有的 `1` 的个数记下来，记作 `base`。  
2. 对每一个可能的 `1` 段（起点 `i`，终点 `j`），找到它左侧紧邻的 `0` 段长度 `L`，右侧紧邻的 `0` 段长度 `R`（如果左/右已经是字符串边界或没有 `0`，则对应长度为 `0`）。  
3. 这一次交易后得到的 `1` 总数为 `base + L + R`。  
4. 把所有 `(i, j)` 的结果取最大，就是答案。

> **类比**：把 `1` 段想象成一块已经点亮的灯泡，左右的 `0` 段是未点亮的灯泡。一次交易相当于把这块灯泡左右的未点亮灯泡全部点亮，灯泡本身不灭。我们只需要找出能点亮最多灯泡的那块灯泡。

虽然思路很清晰，但直接遍历所有 `(i, j)` 的组合会产生 **二次循环**，在最坏情况下会检查 `O(n²)` 次（`n` 为字符串长度），这对 `n ≤ 10⁵` 的数据规模来说太慢了。

#### 代码（Python）

```python
def maxActive_bruteforce(s: str) -> int:
    n = len(s)
    base = s.count('1')                     # 原始的 1 的个数
    best = base                             # 至少不比原来少

    # 暴力枚举所有可能的 1 段的左右端点
    for i in range(n):
        if s[i] != '1':
            continue                       # 只能从 1 开始
        for j in range(i, n):
            if s[j] != '1':
                break                      # 只要连续的 1
            # 此时 [i, j] 是一个完整的 1 段
            # 左侧 0 段长度
            L = 0
            k = i - 1
            while k >= 0 and s[k] == '0':
                L += 1
                k -= 1
            # 右侧 0 段长度
            R = 0
            k = j + 1
            while k < n and s[k] == '0':
                R += 1
                k += 1
            best = max(best, base + L + R)  # 计算这一次交易的结果

    return best
```

> 代码里每一次内部的 `while` 循环最多遍历整条字符串一次，所以整体时间是 `O(n²)`，空间只用了常数 `O(1)`。

#### 复杂度  

- **时间复杂度**：`O(n²)`  
  - 「二次方」的含义是：如果 `n = 10⁴`，大约会进行 `10⁸` 次基本操作，已经超出 1 秒左右的常规时限。  
- **空间复杂度**：`O(1)`  
  - 只用了几个计数变量，没有额外的数组或递归栈。

### 2. 最优解

#### 思路  

从暴力解可以看到，**真正决定增益的只有**：

* 一个 **被 `0` 包围的 `1` 段**（左、右各有至少一个 `0`），以及
* 这个 `1` 段左边的 `0` 长度 `L` 与右边的 `0` 长度 `R`。

因为交易只会把左、右相邻的 `0` 直接变成 `1`，**不会影响其他位置**。  
所以我们不需要枚举所有 `(i, j)`，只要一次线性扫描就能得到每个 `1` 段左右的 `0` 长度。

具体步骤：

1. **预处理**：把字符串视作在两端各加一个虚拟的 `'1'`（题目已经说明），这样每个真实的 `1` 段都会有左、右「邻居」段，统一处理边界。  
2. **一次遍历**，把 `s` 按照 **段（segment）** 拆分成交替出现的 `0` 段和 `1` 段。记录每段的长度到两个列表  
   * `zero = []` 保存所有 `0` 段的长度（包括两端的虚拟 `0`，如果不存在则记 `0`）  
   * `one = []` 保存所有 `1` 段的长度（包括两端的虚拟 `1`，它们的长度为 `1`，但不计入答案）  
3. 对于 **每个真正的 `1` 段**（即 `one[i]` 对应的下标 `i` 在 `1 … len(one)-2`），检查它的左、右 `0` 段 `zero[i-1]`、`zero[i]`。如果两侧都有 `0`（即长度 > 0），则这一次交易能带来的增益为 `zero[i-1] + zero[i]`。取所有增益的最大值 `max_delta`。  
4. **答案** = 原始 `1` 的总数 `base` + `max_delta`（如果没有合法的 `1` 段，`max_delta` 为 `0`）。

> **类比**：把整条字符串想象成一条路，上面有若干灯塔（`1` 段）和黑暗区（`0` 段）。一次交易相当于把某座灯塔左右的黑暗全部点亮。我们只需要遍历一次路面，记录每段灯塔和黑暗的长度，就能快速找出「点亮最多黑暗」的灯塔。

#### 代码（Python）

```python
def maxActive(s: str) -> int:
    """
    返回在至多进行一次交易后，字符串中 '1' 的最大个数。
    """
    n = len(s)
    base = s.count('1')                 # 原始 1 的数量

    # ---------- 1. 按段拆分 ----------
    # 在两端各加一个虚拟的 '1'（题目要求），这样左、右的 0 段一定存在（可能为 0 长度）
    t = '1' + s + '1'
    seg_len = []        # 各段长度，交替出现 1、0、1、0 ...
    cur = t[0]
    cnt = 1
    for ch in t[1:]:
        if ch == cur:
            cnt += 1
        else:
            seg_len.append(cnt)
            cur = ch
            cnt = 1
    seg_len.append(cnt)  # 最后一段

    # seg_len[0] 必然是 1（左侧虚拟 1）， seg_len[-1] 也是 1（右侧虚拟 1）
    # 交替出现：1段、0段、1段、0段 …，所以奇数下标对应 0 段，偶数下标对应 1 段
    zero = []   # 0 段长度
    one = []    # 1 段长度（包括两端的虚拟 1）
    for idx, length in enumerate(seg_len):
        if idx % 2 == 0:      # 0,2,4,... 为 1 段
            one.append(length)
        else:                 # 1,3,5,... 为 0 段
            zero.append(length)

    # ---------- 2. 计算最大增益 ----------
    max_delta = 0
    # 真正的 1 段对应的下标在 one[1] … one[-2]（排除两端的虚拟 1）
    # 对应的左、右 0 段分别是 zero[i-1]、zero[i]
    for i in range(1, len(one) - 1):
        left_zero = zero[i - 1]
        right_zero = zero[i]
        if left_zero > 0 and right_zero > 0:          # 必须被 0 包围
            max_delta = max(max_delta, left_zero + right_zero)

    return base + max_delta
```

> 代码中的 `seg_len` 用来一次遍历完成 **分段**，随后把奇偶下标分别放进 `zero` 与 `one` 两个列表，便于后面的「左、右零段」查询。整个过程只走了两遍字符串，时间 `O(n)`，额外使用了 `O(n)` 的列表（实际最多 `2 * n` 个整数，仍然是线性空间）。

#### 复杂度  

- **时间复杂度**：`O(n)`  
  - 「一次线性扫描」的含义是：不管 `n` 有多大，算法最多只遍历字符串两遍（一次分段，一次求最大增益），相当于 `n` 次基本操作。比如 `n = 10⁵` 时，只会做大约 `2·10⁵` 次循环，几乎在瞬间完成。  
- **空间复杂度**：`O(n)`（或 `O(1)` 进阶优化）  
  - 我们用了两个长度为段数的数组来保存 `0/1` 段的长度，段数最多是 `2·n+1`，仍然是线性空间。如果想进一步压缩空间，也可以在遍历时直接记录前一个 `0` 长度和当前 `1` 长度，做到 `O(1)`。

## 心得  

- **核心技巧**：把二进制字符串**按段（连续相同字符）拆分**，并利用「左、右邻段」的长度直接求增益。  
- **适用的题型**  
  1. 「最大翻转收益」类（如 LeetCode 1005 Maximize Score After N Operations）。  
  2. 「段式」统计类（如统计连续子串的最大/最小长度）。  
  3. 「两端虚拟字符」技巧（很多需要统一边界处理的题目）。  
- **一句话总结**：一次交易只会把 **被 `0` 包围的 `1` 段** 两侧的 `0` 变成 `1`，所以只要找出 **左零+右零 最大的那段**，答案就是原始 `1` 数量加上这最大增益。

## 反思  

- **第一反应**：看到「最多一次交易」和「二进制字符串」就想到「翻转子数组」的经典思路（Kadane），于是尝试枚举所有子数组，导致 `O(n²)`。  
- **最容易踩的坑**  
  1. **边界处理**：题目要求把字符串两端视作额外的 `'1'`，如果忘记补上会把首尾的合法交易漏掉。  
  2. **只能在被 `0` 包围的 `1` 段上交易**：单侧的 `0` 段（例如 `1` 在字符串开头）不满足「两侧都有 `0`」的条件，不能贡献增益。  
  3. **计数时误把虚拟的两端 `'1'` 加进去**：答案只统计原始字符串中的 `'1'`，虚拟的 `'1'` 只用于辅助划分段。  
- **下次类似题目**：先把问题抽象成「每个局部结构（段）对应的收益」再求全局最大，而不是直接暴力枚举所有子区间。这样往往能把 `O(n²)` 降到 `O(n)`。
