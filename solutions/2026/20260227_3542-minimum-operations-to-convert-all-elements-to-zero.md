## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**一次一次地模拟题目描述的操作**：  

1. 在当前数组中寻找最小的非零数 `m`（如果全是 `0`，结束）。  
2. 任意选取一个包含 `m` 的子数组 `[i, j]`，把子数组里所有等于 `m` 的位置设为 `0`。  
3. 重复步骤 1~2，直到数组全变成 `0`。  

> **数据结构类比**  
> - **遍历数组找最小值**：就像在一排商品里找最便宜的那件。  
> - **把子数组里等于 `m` 的位置改为 `0`**：相当于把所有这件商品的标签贴上“已处理”。  

只要每次都把 **至少一个** 最小的数变成 `0`，最终一定能把全部元素变为 `0`，所以这种做法一定是正确的（虽然不是最省操作次数的）。

#### 代码（Python）

```python
def min_operations_bruteforce(nums):
    ops = 0                     # 记录已经进行的操作次数
    n = len(nums)

    while any(x != 0 for x in nums):   # 只要还有非零元素就继续
        # 1️⃣ 找当前数组的最小非零数
        cur_min = min(x for x in nums if x != 0)

        # 2️⃣ 找到第一个出现 cur_min 的位置 i
        i = nums.index(cur_min)

        # 3️⃣ 为了让代码最容易写，直接把以 i 为左端点、一直向右
        #    扩展到遇到比 cur_min 更小的数（这里必然是 0）为止的子数组全部处理
        j = i
        while j < n and nums[j] != 0:   # 子数组里不出现已经是 0 的位置
            if nums[j] == cur_min:
                nums[j] = 0              # 把所有等于 cur_min 的位置置零
            j += 1

        ops += 1                         # 完成一次操作
    return ops
```

> 关键行解释  
> - `any(x != 0 for x in nums)`：判断数组里还有没有非零元素。  
> - `min(x for x in nums if x != 0)`：找出当前最小的非零数。  
> - `while j < n and nums[j] != 0:`：确保子数组不跨过已经是 `0` 的位置（因为 `0` 是子数组的最小值，继续往右会让这次操作失效）。  

#### 复杂度  

- **时间复杂度**：`O(n²)`  
  - 最坏情况下每次只把一个元素变为 `0`（比如递增数组），需要 `n` 次循环；每次循环里要遍历数组寻找最小值和子数组，都是 `O(n)`，于是总体是 `n × n`。  
  - 用大白话说，就是“如果你有 10 000 个糖果，每次只能吃掉最小的那颗，而且还要把所有糖果重新排队找最小的，那总共要排队 10 000² 次”。  

- **空间复杂度**：`O(1)`（只使用了常数级别的额外变量）。

### 2. 最优解  

#### 思路  

暴力解的瓶颈在于**每次都要重新遍历整个数组寻找最小值**，这导致 `O(n²)`。  
观察题目提示：  

> “从小到大处理数值（不包括 0），对每个目标值 `v`，找出它的**最大连续段**（即子数组中所有元素都等于 `v`），每段只需要一次操作”。  

这意味着：  
- 当我们已经把所有 **比 `v` 小的数**变成 `0` 后，这些 `0` 会把数组 **切成若干块**。  
- 在每块内部，若出现若干个 `v`，只要它们是 **相邻的**（即形成一个连续段），一次操作就能全部清零。  

于是问题转化为**统计**：对每一个不同的正数 `v`，它在“已经去掉所有更小的数之后”出现了多少个 **不被更小数分割的连续段**。  

直接模拟“去掉更小的数”仍然会导致重复遍历。我们可以用 **单调栈**（Monotonic Stack）一次线性扫描完成计数：

1. 维护一个 **递增栈** `stack`，栈内元素从底到顶始终 **不下降**。栈顶代表当前**尚未被更小数覆盖**的最大值。  
2. 当遍历到 `num` 时：  
   - 若 `num` 小于栈顶，说明出现了比栈顶更小的数，这会把之前的更大数 **切断**，于是把栈顶弹出（相当于“把这些更大数所在的段结束”）。  
   - 弹完后，如果 `num` **大于**当前栈顶（栈顶可能是 `0`），说明 `num` 开启了一个 **新段**，需要一次额外操作，于是 `ans += 1` 并把 `num` 入栈。  
   - 若 `num` 等于栈顶，说明它继续延伸已有的段，不需要额外操作，只把它入栈即可（或直接跳过入栈，只保留一个相同值）。  

3. 最终 `ans` 就是最少操作次数。

> **单调栈类比**  
> 想象一排房子高度不一样，你要在每栋房子上贴一个“已清零”的标记。  
> - 当你遇到更低的房子时，所有比它高的房子都被这栋低房子“挡住”了，之前的标记就失效，需要弹掉。  
> - 当你遇到更高的房子时，你必须再贴一次新标记，因为它不在任何旧标记的覆盖范围里。  

整个过程只遍历一次数组，弹栈和入栈都是 `O(1)`，因此总时间是 `O(n)`。

#### 代码（Python）

```python
def min_operations(nums):
    """
    使用单调递增栈一次遍历得到最小操作次数
    """
    ans = 0                # 记录操作次数
    stack = [0]            # 哨兵 0，等价于已经处理好的“零段”

    for num in nums:
        # 1️⃣ 把比当前 num 更大的值弹出（这些段已经被更小的数切断）
        while stack and num < stack[-1]:
            stack.pop()

        # 2️⃣ 如果当前 num 大于栈顶，说明出现了一个新段，需要一次操作
        if num > stack[-1]:
            ans += 1        # 新增一次操作
            stack.append(num)   # 把当前值压入栈，成为新的“未被更小数覆盖”的段

        # 当 num == stack[-1] 时，说明它继续属于已经计数过的段，
        # 不需要再做任何事（可以选择不重复入栈，保持栈唯一性）。
    return ans
```

> 关键行解释  
> - `while stack and num < stack[-1]: stack.pop()`：把所有比当前数更大的“段”弹掉，等价于把这些段在后面继续处理的可能性关闭。  
> - `if num > stack[-1]: ans += 1`：只有比栈顶大的数才会开启**全新**的连续段，需要一次额外操作。  
> - 哨兵 `0` 保证即使数组开头是 `0` 也能正常工作，因为 `0` 本身不需要操作。  

#### 复杂度  

- **时间复杂度**：`O(n)`  
  - 只遍历一次数组，每个元素至多进栈一次、出栈一次。用大白话说，就是“只需要一次排队检查所有糖果”。  

- **空间复杂度**：`O(n)`（最坏情况下栈会存储递增的全部元素）  
  - 实际上栈的大小受数组递增程度限制，最坏是 `n`，但只占用线性额外空间。

## 心得  

- **核心技巧**：**单调栈**配合“从小到大处理”可以一次线性扫描统计“新段”的数量。  
- **适用的题型**  
  1. “把数组变为目标数组的最少增量子数组操作” (LeetCode 1526)。  
  2. “矩形面积的单调栈求和” (如柱状图最大矩形)。  
  3. “子数组最小值的和” (LeetCode 907)。  

- **一句话总结解题钥匙**：**把更小的数当作“墙”，每遇到比当前墙更高的数就开启新段，一次操作即可清零整个段**。

## 反思  

- **第一反应**：直接模拟题目描述的操作，想一步步把最小数变为 `0`。  
- **最容易踩的坑**  
  - 忽视 `0` 本身已经是“墙”，会导致错误的额外计数。  
  - 对相同数值的连续出现计数两次，需要把它们视为同一段。  
  - 边界情况：全是 `0`、单元素数组、递增或递减的极端序列。  

- **下次遇到同类题**：第一步想到 **“从小到大”** 处理，并用 **单调栈** 判断何时出现 **新段**，这样就能把原本的 `O(n²)` 暴力转化为 `O(n)` 线性解。
