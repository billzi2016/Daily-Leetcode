## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把题目里的四个下标 `l < p < q < r` 暴力枚举出来，然后检查这四段是否满足 **先增后减再增** 的要求，最后把满足条件的子数组求和取最大。

- **枚举方式**：  
  1. 先枚举左端点 `l`（`0 … n‑4`）。  
  2. 在 `l` 右边枚举 `p`（`l+1 … n‑3`）。  
  3. 再枚举 `q`（`p+1 … n‑2`）。  
  4. 最后枚举 `r`（`q+1 … n‑1`）。  

- **判断**：  
  - `nums[l] < nums[l+1] < … < nums[p]`  → 前半段严格递增  
  - `nums[p] > nums[p+1] > … > nums[q]`  → 中间严格递减  
  - `nums[q] < nums[q+1] < … < nums[r]`  → 后半段再次严格递增  

- **求和**：子数组 `nums[l … r]` 的和可以用前缀和 `pre[i] = nums[0] + … + nums[i-1]` 快速得到，`sum(l,r) = pre[r+1] - pre[l]`。

> **生活化类比**：  
> 把数组想成一条山路，`l`、`p`、`q`、`r` 分别是上坡起点、峰顶、谷底和第二个上坡的终点。暴力解就是把每条可能的山路都走一遍，看看哪条的海拔（数组元素）之和最高。

**为什么能得到答案**：只要遍历了所有合法的 `(l,p,q,r)`，必然会找到最大和的那一组。  

**时间/空间复杂度**  
- 枚举四层循环的时间复杂度是 `O(n^4)`，即使利用前缀和把求和降到 `O(1)`，循环本身仍然是四次嵌套。  
- 前缀和数组占用 `O(n)` 的额外空间。

> **大白话解释**：  
> `O(n^4)` 可以想象成“如果你有 10 000 条路要检查，每条路上还有 10 000 条分叉，每个分叉又有 10 000 条选择…”，显然在 10⁵ 长度的数组里根本跑不完。

#### 代码（Python）

```python
from itertools import accumulate
from math import inf

def max_trionic_bruteforce(nums):
    n = len(nums)
    # 前缀和，pre[i] = nums[0] + … + nums[i-1]
    pre = [0] + list(accumulate(nums))

    best = -inf                     # 记录全局最大和

    for l in range(n - 3):         # 左端点
        for p in range(l + 1, n - 2):   # 峰顶
            # 检查前半段是否严格递增
            ok_inc1 = all(nums[i] < nums[i + 1] for i in range(l, p))
            if not ok_inc1:
                continue

            for q in range(p + 1, n - 1):   # 谷底
                # 检查中间是否严格递减
                ok_dec = all(nums[i] > nums[i + 1] for i in range(p, q))
                if not ok_dec:
                    continue

                for r in range(q + 1, n):   # 右端点
                    # 检查后半段是否严格递增
                    ok_inc2 = all(nums[i] < nums[i + 1] for i in range(q, r))
                    if not ok_inc2:
                        continue

                    # 子数组和 = 前缀和差
                    cur_sum = pre[r + 1] - pre[l]
                    best = max(best, cur_sum)

    return best
```

> 代码里每一层循环都对应一种“选取”动作，`all` 用来判断递增/递减是否成立。虽然能跑通小样例，但在 `n = 10⁵` 时根本不可用。

#### 复杂度

- **时间复杂度**：`O(n⁴)` —— 四层嵌套遍历所有 `(l,p,q,r)`，即使每次判断用 `O(1)`（前缀和）也不改变数量级。  
- **空间复杂度**：`O(n)` —— 只额外用了前缀和数组。

### 2. 最优解

#### 思路  

从暴力解可以看到，**慢的根源**在于不停地重复检查“已经在递增/递减的段落”。我们只需要在遍历一次数组的过程中，**记住**到当前位置为止，各阶段能够取得的最大子数组和即可。

这类“阶段性最大值”问题常用 **动态规划（DP）** 来压缩状态。这里我们把 **一个合法的 trionic 子数组** 想成四个连续的“阶段”：

1. **阶段 0（Start → 第一次递增）**：已经进入第一次递增，但还没有出现下降。  
2. **阶段 1（第一次递增 → 递减）**：已经完成第一次递增，现在正在递减（或已经结束递减）。  
3. **阶段 2（递减 → 第二次递增）**：已经完成递减，现在进入第二次递增。  
4. **阶段 3（第二次递增 → 结束）**：第二次递增已经结束，这时子数组已经满足 `l < p < q < r`，可以把它当作候选答案。

我们用四个数组 `dp0, dp1, dp2, dp3`（长度 `n`）来记录：

- `dp0[i]`：以 `i` 为结尾、**仍在阶段 0**（即一直在递增）的最大子数组和。  
- `dp1[i]`：以 `i` 为结尾、**已完成阶段 0 并进入阶段 1**（递减）的最大子数组和。  
- `dp2[i]`：以 `i` 为结尾、**已完成阶段 1 并进入阶段 2**（第二次递增）的最大子数组和。  
- `dp3[i]`：以 `i` 为结尾、**已完成全部三段**（即合法的 trionic 子数组）的最大子数组和。

**关键转移**（从左到右遍历）：

| 当前元素关系 | 更新的 dp | 说明 |
|--------------|----------|------|
| `nums[i] > nums[i‑1]`（上升） | `dp0[i] = dp0[i‑1] + nums[i]`<br>`dp1[i] = max(dp1[i‑1] + nums[i], dp0[i‑1] + nums[i])`<br>`dp3[i] = max(dp3[i‑1] + nums[i], dp2[i‑1] + nums[i])` | 1）继续第一次递增；2）如果已经在递减阶段，仍可把当前上升元素接在递减后面（这等价于“结束递减，开始第二次递增”）；3）如果已经完成第二次递增，则可以继续往右延伸。 |
| `nums[i] < nums[i‑1]`（下降） | `dp2[i] = max(dp2[i‑1] + nums[i], dp1[i‑1] + nums[i])` | 只能在已经进入递减阶段后再继续下降，或者从阶段 1（第一次递增结束）直接进入递减。 |
| `nums[i] == nums[i‑1]`（平） | 所有 dp 重新开始 | 平坦不算递增也不算递减，需要把所有状态“清零”，相当于从当前位置重新开启一段新的尝试。 |

> **类比**：  
> 想象你在玩一款“爬山”游戏，必须先上坡、再下坡、再上坡才能通关。`dp0` 记录你当前还在第一段上坡的最高得分，`dp1` 记录已经完成上坡并开始下坡的最高得分，依此类推。每次你往前走一步，只要看当前是上坡还是下坡，就决定把得分接到哪一个阶段上。

**答案的获取**：遍历过程中把所有 `dp3[i]`（已经完整三段）的最大值记下来，就是题目要求的最大和。

**为什么是最优**：

- 只遍历一次数组，**每个位置的状态只更新常数次**，所以时间是线性的 `O(n)`。  
- 只保存四个滚动变量（或四个长度为 `n` 的数组），空间是 `O(n)`（甚至可以压缩到 `O(1)`），远小于暴力的 `O(n⁴)`。

#### 代码（Python）

```python
from math import inf

def max_trionic(nums):
    """
    返回任意合法 trionic 子数组的最大和
    """
    n = len(nums)
    # 使用 -inf 表示“当前阶段不存在”，防止错误累加
    NEG = -10**30

    # 四个阶段的 dp，初始化为不可能的极小值
    dp0 = [NEG] * n   # 第一次递增阶段
    dp1 = [NEG] * n   # 已经进入递减阶段
    dp2 = [NEG] * n   # 已经进入第二次递增阶段
    dp3 = [NEG] * n   # 完整的 trionic 子数组

    # 第一个元素只能是阶段 0 的起点
    dp0[0] = nums[0]

    ans = NEG   # 记录所有 dp3 中的最大值

    for i in range(1, n):
        if nums[i] > nums[i - 1]:                 # 上升
            # 继续第一次递增（阶段 0）
            dp0[i] = dp0[i - 1] + nums[i]

            # 1）已经在递减阶段，继续往右接（相当于把递减当作“已经结束”，开始第二次递增的前置）  
            # 2）刚从阶段 0 直接转到阶段 1（第一次递增结束后立刻下坡，这里用 dp0[i-1] 开启递减）  
            cand1 = dp1[i - 1] + nums[i] if dp1[i - 1] != NEG else NEG
            cand2 = dp0[i - 1] + nums[i]          # 从阶段 0 转到阶段 1
            dp1[i] = max(cand1, cand2)

            # 阶段 3：已经完成第二次递增，可以继续往右累加
            cand3 = dp3[i - 1] + nums[i] if dp3[i - 1] != NEG else NEG
            cand4 = dp2[i - 1] + nums[i] if dp2[i - 1] != NEG else NEG
            dp3[i] = max(cand3, cand4)

            # 递减阶段 dp2 在上升时只能保持不变（因为不允许在递增时直接进入递减）
            dp2[i] = NEG

        elif nums[i] < nums[i - 1]:               # 下降
            # 递减阶段只能从已经在递减的 dp1 开始，或刚刚结束第一次递增的 dp1
            cand1 = dp2[i - 1] + nums[i] if dp2[i - 1] != NEG else NEG
            cand2 = dp1[i - 1] + nums[i] if dp1[i - 1] != NEG else NEG
            dp2[i] = max(cand1, cand2)

            # 其它阶段在下降时失效
            dp0[i] = NEG
            dp1[i] = NEG
            dp3[i] = NEG

        else:                                      # 平坦（相等）——所有阶段失效，重新开始
            dp0[i] = nums[i]        # 可以把当前元素当作新的起点
            dp1[i] = dp2[i] = dp3[i] = NEG

        # 更新答案：只要 dp3 有合法值，就可能是最终答案
        if dp3[i] != NEG:
            ans = max(ans, dp3[i])

    return ans
```

> **代码要点解释**  
> - `NEG = -10**30` 用来表示“该阶段目前不存在”。如果直接用 `-inf`，在 `+ nums[i]` 时会得到 `nan`，所以用一个足够小的整数。  
> - 每一次比较 `nums[i]` 与前一个元素的大小，就决定本轮应该更新哪些阶段的 dp。  
> - 只要 `dp3[i]` 不等于 `NEG`，说明已经完成了 `递增 → 递减 → 递增`，可以把它和全局答案 `ans` 比较。  
> - 最终返回的 `ans` 即为题目要求的最大和。

#### 复杂度

- **时间复杂度**：`O(n)`。我们只遍历一次数组，对每个位置做常数次的状态转移（最多 4 条 `if` 分支），所以时间随 `n` 线性增长。  
  > 与暴力的 `O(n⁴)` 相比，`O(n)` 可以轻松处理 `n = 10⁵` 甚至更大的数据规模。

- **空间复杂度**：`O(n)`（若把四个数组改为四个滚动变量，则可降到 `O(1)`）。这里保留了四个长度为 `n` 的列表，主要是为了代码可读性；实际比赛中常把它们压缩成四个标量。

## 心得

- **核心技巧**：把“先增后减再增”的约束拆成四个连续阶段，用动态规划记录每个阶段在每个位置的最佳子数组和。  
- **适用的题型**  
  1. **Maximum Subarray with Pattern**（如 “Maximum Alternating Subarray”）  
  2. **Three‑Phase Stock Trading**（买‑卖‑买‑卖的最大利润）  
  3. **Longest Bitonic Subsequence**（先增后减的最长子序列）——同样可以用四段 DP 思路转化为求和或长度。  
- **一句话总结**：  
  “把复杂的全局约束拆成若干局部阶段，分别维护每个阶段的最优值，一次遍历即可得到答案。”

## 反思

- **第一反应**：看到“存在四个下标且要满足先增后减再增”，立刻想到“枚举四个下标”。这导致了暴力 `O(n⁴)` 的想法。  
- **最容易踩的坑**  
  1. **相等元素的处理**：题目要求严格递增/递减，等于会破坏模式，需要在 DP 中把所有状态重新置为不可用。  
  2. **初始化**：`dp1、dp2、dp3` 必须设为极小值，否则在还未进入对应阶段时会误参与计算。  
  3. **负数溢出**：数组元素范围很大（±10⁹），累计和可能超过 32 位整数范围，使用 Python 的大整数即可，但在其他语言要注意使用 64 位。  
- **下次遇到同类题**：第一步先**把整体约束拆成若干连续阶段**，思考每个阶段的**“是否可以继续、是否可以转移、是否可以结束”**这三类转移，然后用 DP/滚动变量一次遍历完成。这样可以避免直接枚举导致的指数级时间。
