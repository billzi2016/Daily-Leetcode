## 题目（中文翻译）

给定一个字符串 `s`，计算它的逆度（reverse degree）。

逆度的计算方式如下：

- 对字符串 `s` 中的第 `i`（从 **0** 开始）个字符 `c`，设其在字母表中的序号为 `pos`（`a` 对应 1，`b` 对应 2，…，`z` 对应 26），则该字符对逆度的贡献为  
  \[(27 - pos) \times (i + 1)\]  
- 将所有字符的贡献求和，即为字符串 `s` 的逆度。

返回 `s` 的逆度。

**示例 1**  
输入: `s = "abc"`  
输出: `148`  
解释:  
逆度 = 26 × 1 + 25 × 2 + 24 × 3 = 148 。

**示例 2**  
输入: `s = "zaza"`  
输出: `160`  
解释:  
逆度 = 1 × 1 + 26 × 2 + 1 × 3 + 26 × 4 = 160 。

**约束条件**  

- `1 <= s.length <= 1000`
- `s` 仅包含小写英文字母。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

题目要求 **reverse degree**（逆向度），定义如下：

> 对于字符串 `s` 的第 `i`（从 0 开始）个字符 `c`，先求出它在字母表中的“逆向字符”。  
> 逆向字符是指字母表中与 `c` 对称的位置的字符，例如 `a ↔ z、b ↔ y、c ↔ x …`。  
> 记逆向字符在字母表中的序号为 `revPos`（`a` 为 1，`z` 为 26）。  
> 该字符对逆向度的贡献为 `revPos × (i + 1)`（下标从 1 开始计数）。  
> 所有字符的贡献相加即为答案。

**生活化类比**：  
把字母表想象成一本字典，左边是正向序号，右边是对应的“镜像页码”。  
查找一个字母的镜像页码就像在字典里找它的反义词——这里我们只需要知道它对应的页码是多少。

**暴力实现**的关键在于**逐个字符地去找它的逆向字符**。最直接的办法是：

1. 预先准备一个包含 `'a'` 到 `'z'` 的列表 `alphabet = ['a', 'b', ..., 'z']`。  
2. 对于当前字符 `c`，遍历 `alphabet` 找到它的位置 `pos`（1‑based）。  
3. 逆向序号 `revPos = 27 - pos`（因为 `a` 的逆向是 `z`，即 `27-1=26`，`b` 的逆向是 `y`，即 `27-2=25` ……）。  
4. 贡献 `revPos * (i+1)` 加入答案。

这种写法虽然思路最直接，但每次寻找字符位置都要遍历 26 次，时间上会有 **26 × n** 次循环。

#### 代码（Python）

```python
def reverse_degree_bruteforce(s: str) -> int:
    # 1. 准备字母表（列表），方便遍历查找
    alphabet = [chr(ord('a') + i) for i in range(26)]   # ['a', 'b', ..., 'z']

    total = 0  # 最终的逆向度

    for i, ch in enumerate(s):          # i 为下标，ch 为当前字符
        # 2. 暴力找出 ch 在 alphabet 中的下标（从 0 开始）
        pos = 0
        for j, a in enumerate(alphabet):
            if a == ch:                  # 找到相同的字母
                pos = j + 1              # 转成 1‑based 序号
                break

        # 3. 逆向序号 = 27 - 正向序号
        rev_pos = 27 - pos                # 例如 a→26，z→1

        # 4. 贡献 = 逆向序号 × (i+1)（下标从 1 开始计数）
        total += rev_pos * (i + 1)

    return total
```

#### 复杂度

- **时间复杂度**：`O(26 × n) = O(n)`  
  解释：外层遍历字符串 `n` 次，内层最多遍历 26 次（字母表大小固定），所以整体随 `n` 成线性增长。这里的 `O(n)` 说的是“线性”，也就是如果字符串长度是 1000，程序大约会执行 26 000 次基本操作。

- **空间复杂度**：`O(1)`  
  解释：只用了常数级别的额外空间（字母表列表固定 26 项），不随输入规模增长。

---

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**每次都遍历整个字母表寻找字符的位置**。其实我们可以直接用字符的 ASCII 码算出它的正向序号和逆向序号，无需循环。

- **正向序号**（`pos`）：`ord(ch) - ord('a') + 1`。  
  例如 `'c'` 的 ASCII 为 99，`'a'` 为 97，`99 - 97 + 1 = 3`，正好是第 3 位。

- **逆向序号**（`revPos`）：`27 - pos`，或者直接写成 `ord('z') - ord(ch) + 1`（因为 `'z'` 的 ASCII 为 122）。  
  这一步只用一次减法，就得到对应的逆向字符的序号。

这样我们只需要一次遍历字符串，就能得到每个字符的贡献，时间从 **O(26 × n)** 降到 **O(n)**，而且代码更简洁。

#### 代码（Python）

```python
def reverse_degree(s: str) -> int:
    total = 0
    for i, ch in enumerate(s):
        # 逆向序号 = 'z' 与当前字符的距离 + 1
        rev_pos = ord('z') - ord(ch) + 1   # 直接算出 1~26 的逆向值

        # 贡献 = 逆向序号 × (i+1)（下标从 1 开始计数）
        total += rev_pos * (i + 1)

    return total
```

#### 复杂度

- **时间复杂度**：`O(n)`  
  解释：只遍历一次字符串，每个字符的逆向序号用常数时间算出，整体随字符串长度线性增长。对比暴力解，这里不再有额外的 26 次循环，运行更快。

- **空间复杂度**：`O(1)`  
  解释：只使用了几个整数变量，和输入规模无关。

## 心得

- **核心技巧**：利用字符的 ASCII 码直接计算字母表位置（正向或逆向），避免不必要的遍历。  
- **适用的题型**：  
  1. 需要根据字母顺序进行数值运算的题目（如 “字母值之和”）。  
  2. 需要把字母映射到另一个序号或字符的题目（如 “字母镜像”）。  
  3. 需要按下标加权求和的字符串题目（如 “加权字符和”）。
- **一句话总结**：**把字母表当成坐标轴，用公式直接定位，而不是走路找位置**。

## 反思

- **第一反应**：看到“逆向字符”就想到把字母表翻转，然后逐个查找对应字符——于是写出了暴力遍历的代码。  
- **最容易踩的坑**：  
  - 忘记下标从 **1** 开始计数，导致乘以 `i` 而不是 `i+1`。  
  - 只算了正向序号而没有取逆向，导致答案偏差。  
  - 对空字符串没有考虑（虽然约束里最小长度为 1）。  
- **下次思路**：一看到“字母表的某种映射”就先想 **公式**（`ord`）是否能直接求值，尽量把“遍历字母表”这一步省掉。这样可以快速得到 O(n) 的最优解。
