## 题目（英文原版）

**Description**

Winter is coming! During the contest, your first job is to design a standard heater with a fixed warm radius to warm all the houses.
Every house can be warmed, as long as the house is within the heater's warm radius range.
Given the positions of houses and heaters on a horizontal line, return the minimum radius standard of heaters so that those heaters could cover all houses.
Notice that all the heaters follow your radius standard, and the warm radius will the same.

**Examples**

**Example 1:**

```
Input: houses = [1,2,3], heaters = [2]
Output: 1
Explanation: The only heater was placed in the position 2, and if we use the radius 1 standard, then all the houses can be warmed.
```

**Example 2:**

```
Input: houses = [1,2,3,4], heaters = [1,4]
Output: 1
Explanation: The two heaters were placed at positions 1 and 4. We need to use a radius 1 standard, then all the houses can be warmed.
```

**Example 3:**

```
Input: houses = [1,5], heaters = [2]
Output: 3
```

**Constraints**

- 1 <= houses.length, heaters.length <= 3 * 104
- 1 <= houses[i], heaters[i] <= 109

## 题目（中文翻译）

冬天快到了！在本次比赛中，你的首要任务是设计一种具有固定加热半径（warm radius）的标准加热器（heater），以使所有房屋都能被加热。只要房屋位于加热器的加热半径范围内，就能够被加热。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**对每一栋房子，去所有的暖气片里找最近的那一个**，记下这段距离（房子到暖气片的绝对差），所有房子的这些最近距离的最大值，就是所有房子都能被加热所需要的最小半径。

- **用到的数据结构**：两个普通的数组（`houses`、`heaters`）。这里不需要额外的结构，直接遍历就行。可以把它想象成在街上找最近的加油站——我们把每个加油站的坐标记下来，然后逐一比较，找到最近的那家。

- **为什么正确**：  
  对于任意固定半径 `R`，如果所有房子都能被加热，必然每个房子到最近暖气片的距离 ≤ `R`。于是 `R` 必须不小于所有房子“最近距离”的最大值。反过来，取 `R` 为这个最大值时，显然每个房子都有至少一个暖气片在 `R` 范围内，所以 `R` 正好是答案。

- **时间/空间复杂度**：  
  - **时间**：对每栋房子都要遍历所有暖气片，假设房子数为 `n`，暖气片数为 `m`，总共要做 `n × m` 次比较。用大白话说就是“把每一只猫都喂给每一只老鼠”，所以是 **O(n·m)**。  
  - **空间**：只用了几个计数器和临时变量，和输入规模无关，**O(1)**。

#### 代码（Python）

```python
from typing import List

def findRadius_brute(houses: List[int], heaters: List[int]) -> int:
    # ans 用来记录所有房子最近距离的最大值
    ans = 0
    # 对每一栋房子
    for house in houses:
        # min_dist 初始为一个很大的数
        min_dist = float('inf')
        # 与每一个暖气片比较距离
        for heater in heaters:
            # abs 表示绝对值，即两点之间的距离
            dist = abs(house - heater)
            # 取最小的那个距离
            if dist < min_dist:
                min_dist = dist
        # 更新全局最大值
        if min_dist > ans:
            ans = min_dist
    return ans
```

#### 复杂度

- **时间复杂度**：**O(n·m)**  
  这里的 `n` 是房子数量，`m` 是暖气片数量。意思是如果房子和暖气片各有 10,000 条，算法要做 1 亿 次比较，明显会慢。

- **空间复杂度**：**O(1)**  
  只用了常数个变量，和输入大小无关。

### 2. 最优解

#### 思路  

从暴力解可以看到，**瓶颈在于每次都要遍历所有暖气片**。如果我们事先把房子和暖气片的位置排好序，就能利用“有序”这个信息，大幅度减少比较次数。

两种常见的优化思路：

1. **二分搜索**（每个房子在暖气片数组里找最近的左侧或右侧）  
   - 对每个房子，在已排序的 `heaters` 中做一次二分查找，时间 `O(log m)`。总时间 `O(n log m)`。

2. **双指针**（一次遍历两个有序数组）  
   - 同时遍历排好序的 `houses` 与 `heaters`，用一个指针指向当前“最近的暖气片”。因为房子和暖气片都是从左到右有序的，指针只会向右移动，整个过程只走 `n + m` 步，时间 `O(n + m)`，更快。

下面详细讲解 **双指针** 方法，因为它最简洁且易于手写。

**步骤**：

1. **排序**：先把 `houses`、`heaters` 各自升序排列。想象把街道上的房子和暖气片排成两排，从左到右依次标号。

2. **指针初始化**：`i` 指向第 `i` 栋房子（从 0 开始），`j` 指向第 `j` 个暖气片。我们总是让 `j` 指向**离当前房子最近的暖气片**（左侧或右侧均可）。

3. **移动指针的规则**：  
   - 当下一个暖气片 `heaters[j+1]` 更靠近当前房子 `houses[i]` 时（即 `|houses[i] - heaters[j+1]| <= |houses[i] - heaters[j]|`），就把 `j` 向右移动一格。  
   - 否则，说明 `heaters[j]` 已经是最近的了，记录当前距离 `abs(houses[i] - heaters[j])`，并把 `i` 向右移动到下一栋房子。

4. **遍历完所有房子**，把每一次记录的最近距离取最大值，就是答案。

**为什么正确**：  
因为两条序列都是单调递增的，指针 `j` 只会向右走，永远不会错过更近的暖气片。每次我们都比较 “左边的暖气片”和 “右边的暖气片” 哪个更靠近当前房子，选更近的那个。这样对每栋房子找最近暖气片的过程是 **线性** 的，且不需要回头。

#### 代码（Python）

```python
from typing import List

def findRadius_optimal(houses: List[int], heaters: List[int]) -> int:
    # 1. 排序
    houses.sort()
    heaters.sort()
    
    i, j = 0, 0               # i: 房子指针, j: 暖气片指针
    max_radius = 0            # 记录所有房子最近距离的最大值
    
    while i < len(houses):
        # 2. 如果还有下一个暖气片，且它比当前暖气片更靠近这栋房子
        #    注意这里比较的是绝对距离
        while (j + 1 < len(heaters) and
               abs(heaters[j + 1] - houses[i]) <= abs(heaters[j] - houses[i])):
            j += 1            # 把指针移动到更近的暖气片
        
        # 3. 此时 heaters[j] 已经是最近的，计算距离
        cur_dist = abs(heaters[j] - houses[i])
        # 更新全局最大半径
        if cur_dist > max_radius:
            max_radius = cur_dist
        
        # 4. 处理下一栋房子
        i += 1
    
    return max_radius
```

#### 复杂度

- **时间复杂度**：**O(n log n + m log m)**（排序）+ **O(n + m)**（双指针遍历）  
  合并后仍是 **O(n log n + m log m)**。如果原数组已经是有序的，真正的核心遍历只需要 **O(n + m)**，这在实际运行中非常快。相较于暴力解的 `O(n·m)`，这几乎是“瞬间完成”。

- **空间复杂度**：**O(1)**（不计排序使用的原地排序）  
  只用了几个整数指针和临时变量，额外占用的内存与输入规模无关。

## 心得

- **核心技巧**：利用数组的有序性，配合双指针或二分搜索，把“每个房子遍历所有暖气片” 的 **全局** 检查降到 **局部** 检查，从而实现线性或对数级别的加速。
- **适用的题型**  
  1. “找最近的元素” 类问题（例如 LeetCode 977 `Squares of a Sorted Array` 的双指针变形）。  
  2. “覆盖区间” 类问题（如 435 `Non-overlapping Intervals`，使用排序+贪心）。  
  3. “匹配两组有序数列” 的场景（如 455 `Assign Cookies`，同样用双指针）。
- **一句话总结解题钥匙**：**先排序，再用指针顺序扫描，始终保持“最近的暖气片”指向最新的最优位置**。

## 反思

- **第一反应**：直接对每个房子遍历所有暖气片，写出最直观的 O(n·m) 代码。
- **最容易踩的坑**  
  - 忘记对两个数组进行排序，导致指针移动的条件不成立。  
  - 边界条件：只有一个暖气片或只有一栋房子时，指针的 `j+1` 越界，需要提前检查。  
  - 对距离的比较使用 `abs`，防止出现负数导致的错误判断。
- **下次遇到同类题的第一步**：**先思考是否可以把输入排序**，如果可以，几乎所有“最近距离”“覆盖”之类的问题都能通过“双指针”或“二分搜索”得到线性或对数级别的优化。
