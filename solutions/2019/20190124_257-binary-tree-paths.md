# #257. 二叉树路径 / Binary Tree Paths

## 题目（英文原版）

**Description**

Given the root of a binary tree, return all root-to-leaf paths in any order.
A leaf is a node with no children.

**Examples**

**Example 1:**

```
Input: root = [1,2,3,null,5]
Output: ["1->2->5","1->3"]
```

**Example 2:**

```
Input: root = [1]
Output: ["1"]
```

**Constraints**

- The number of nodes in the tree is in the range [1, 100].
- -100 <= Node.val <= 100

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是「把树从根一直往下走，遇到叶子节点就把走过的节点值拼成一条路径」。  
这相当于我们在现实生活中「从家出发，沿着道路一直走，直到走到没有出口的终点站，然后把沿途经过的路牌名称记下来」——只要把每一步记下来，到了终点就得到了一条完整的路线。

实现上可以用**深度优先搜索（DFS）**：

1. 从根节点开始递归遍历二叉树。  
2. 递归的参数里带上当前已经走过的路径（用字符串保存），每往下一层就在路径后面加上 "`->`" 和当前节点的值。  
3. 当递归到一个**叶子节点**（左、右子树都为空）时，说明已经得到一条完整的根‑到‑叶路径，把它加入答案列表。  
4. 递归返回时不需要额外的回溯操作，因为我们使用的是 **字符串的复制**（每一次递归都生成一个新的字符串），原来的路径不会被后面的分支污染。

为什么这一定能得到所有路径？因为 DFS 会遍历树的每一条根‑到‑叶的分支，且只有在真正到达叶子时才把路径保存下来，所以不会漏掉也不会重复。

**时间/空间复杂度的大白话**  

- **时间复杂度 O(N)**：树里有 N 个节点，DFS 必须把每个节点访问一次才能知道它有没有子节点。想象你要把一本 100 页的书每一页都看一遍，那花的时间正比于页数，也就是 O(N)。  
- **空间复杂度 O(H)**：递归调用会占用栈空间，栈的深度等于树的高度 H（最坏情况下 H≈N，完全不平衡的链状树）。另外我们要把每条路径保存下来，路径总长度正好是所有叶子到根的节点数之和，也在 O(N) 之内。这里把递归栈的空间算作主要额外空间。

#### 代码（Python）

```python
# Definition for a binary tree node.
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val          # 节点的数值
        self.left = left        # 左子树
        self.right = right      # 右子树

class Solution:
    def binaryTreePaths(self, root: TreeNode) -> list[str]:
        """
        暴力的 DFS 实现，返回所有 root -> leaf 路径。
        """
        if not root:                     # 防御性检查，题目保证非空，这里写着更严谨
            return []

        ans = []                         # 用来存放所有完整路径的列表

        def dfs(node: TreeNode, path: str) -> None:
            """
            递归遍历二叉树。
            node: 当前访问的节点
            path: 从根到当前节点已经拼好的字符串（不包括 node 本身的值）
            """
            # 把当前节点的值加入路径。因为 path 已经是 "1->2" 之类的形式，
            # 这里直接在后面加 "->" + 当前值即可（根节点时 path 为空）。
            cur_path = f"{path}{node.val}" if not path else f"{path}->{node.val}"

            # 叶子节点：左右子树都为空
            if not node.left and not node.right:
                ans.append(cur_path)     # 保存完整路径
                return

            # 继续向下搜索左子树、右子树（如果存在的话）
            if node.left:
                dfs(node.left, cur_path)   # 左子树递归
            if node.right:
                dfs(node.right, cur_path)  # 右子树递归

        dfs(root, "")                     # 从根开始，初始路径为空字符串
        return ans
```

#### 复杂度

- **时间复杂度：O(N)** — 每个节点恰好被访问一次，和树的大小成正比。  
- **空间复杂度：O(H)** — 递归栈的深度等于树的高度 H，最坏情况下是 O(N)。另外答案列表本身也需要 O(N) 的空间来存放所有路径字符串。

---

### 2. 最优解

#### 思路  

从暴力解来看，真正的瓶颈不在时间（已经是 O(N)），而在**递归调用的额外栈空间**以及**每次都生成新字符串的开销**。如果我们想进一步降低空间占用，可以：

1. **使用「回溯」+「可变数组」**：在遍历时把路径保存到一个列表 `path`（存放节点值），进入子节点前 `append`，返回时 `pop`。这样不必为每条分支复制完整的字符串，只有在叶子节点时才把列表转成所需的 `"->"` 形式。  
2. **迭代版 DFS**（显式栈）：把递归改成手动维护的栈，思路完全相同，只是把系统调用栈换成了我们自己管理的栈，空间上仍是 O(H)。

这里展示 **回溯 + 列表** 的实现，它的时间仍是 O(N)，而**额外空间**只保留 O(H)（路径列表 + 栈），没有额外的字符串复制开销。

**核心概念解释**  

- **回溯**：想象你在一棵树的枝杈上爬，每走一步就把脚印（节点值）留在背包里。到达叶子时把背包里的脚印写成一条路线。回到上一个分叉时，把刚才走的那一步「弹出」背包（pop），继续尝试另一条分支。这样背包里始终只保存「当前」这条正在探索的路径。  
- **列表转字符串**：当我们真正需要把路径输出时，才把列表 `[1,2,5]` 用 `"->".join(map(str, list))` 拼成 `"1->2->5"`，这一步只在叶子出现时执行一次，整体开销仍是线性的。

#### 代码（Python）

```python
class Solution:
    def binaryTreePaths(self, root: TreeNode) -> list[str]:
        """
        回溯版 DFS：使用可变列表 path 记录当前路径，仅在叶子节点时转换为字符串。
        """
        if not root:
            return []

        res: list[str] = []      # 最终答案
        path: list[int] = []     # 当前遍历的节点值（类似背包）

        def backtrack(node: TreeNode) -> None:
            # 把当前节点加入路径
            path.append(node.val)

            # 叶子节点 => 把 path 转成 "1->2->5" 的形式加入答案
            if not node.left and not node.right:
                # map(str, path) 把每个整数转成字符串，"->".join 把它们连起来
                res.append("->".join(map(str, path)))
            else:
                # 继续向左、右子树探索（如果存在）
                if node.left:
                    backtrack(node.left)
                if node.right:
                    backtrack(node.right)

            # 回到父节点前，弹出当前节点（恢复到进入此节点前的状态）
            path.pop()

        backtrack(root)
        return res
```

#### 复杂度

- **时间复杂度：O(N)** — 仍然需要访问每个节点一次。列表转字符串只在叶子节点执行，所有叶子节点的路径总长度不超过 N。  
- **空间复杂度：O(H)** — `path` 列表的最大长度等于树的高度 H，递归栈同样是 H。相比暴力解，省去了每条分支额外的字符串拷贝，只保留一个可变列表，空间更紧凑。

---

## 心得

- **核心技巧**：**深度优先搜索 + 回溯**，用一个可变结构（列表）记录当前路径，只在叶子节点时把路径转成目标字符串。  
- **适用的题型**  
  1. **所有根到叶的路径**（如本题 `Binary Tree Paths`）。  
  2. **树的所有路径和**（LeetCode 113：Path Sum II）。  
  3. **在图/树中找所有满足条件的遍历**（如 LeetCode 124：Binary Tree Maximum Path Sum 的变体）。  
- **一句话总结**：**“遍历时把路径保存在可变容器里，叶子处再一次性输出”**——这把“走一步、记一步、回撤一步”完整地表达了回溯的思想。

## 反思

- **第一反应**：看到“root‑to‑leaf paths”，立刻想到 DFS，因为这类“从根到叶子”的遍历天然适合递归或栈。  
- **最容易踩的坑**  
  - **路径拼接方式**：直接在递归参数里拼接字符串会导致大量临时字符串，虽仍能 AC，但会浪费内存。  
  - **忘记回溯**：在使用列表记录路径时，忘记在递归结束后 `pop`，会导致路径中残留不该有的节点，最终得到错误的路径。  
  - **叶子节点的判定**：一定要判断 **左子树和右子树同时为空**，否则把只有一个子节点的内部节点误当成叶子。  
- **下次遇到同类题的第一步**：先画出树的结构，明确“根‑到‑叶”或“任意两点之间”的遍历需求，然后决定使用 **DFS（递归或显式栈） + 回溯**，并准备一个**可变容器**来实时保存路径。这样思路就已经完整了，后面只需要实现细节。
