# #494. 目标和 / Target Sum

> 难度：中等 · 标签：Array、Dynamic Programming、Backtracking · [LeetCode 链接](https://leetcode.com/problems/target-sum/)

## 题目（英文原版）

**Description**

You are given an integer array nums and an integer target.
You want to build an expression out of nums by adding one of the symbols '+' and '-' before each integer in nums and then concatenate all the integers.
Return the number of different expressions that you can build, which evaluates to target.

**Examples**

**Example 1:**

```
Input: nums = [1,1,1,1,1], target = 3
Output: 5
Explanation: There are 5 ways to assign symbols to make the sum of nums be target 3.
-1 + 1 + 1 + 1 + 1 = 3
+1 - 1 + 1 + 1 + 1 = 3
+1 + 1 - 1 + 1 + 1 = 3
+1 + 1 + 1 - 1 + 1 = 3
+1 + 1 + 1 + 1 - 1 = 3
```

**Example 2:**

```
Input: nums = [1], target = 1
Output: 1
```

**Constraints**

- 1 <= nums.length <= 20
- 0 <= nums[i] <= 1000
- 0 <= sum(nums[i]) <= 1000
- -1000 <= target <= 1000

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**枚举所有可能的符号组合**，把每个 `+` 或 `-` 看成一次“决定”。  
- 对于长度为 `n` 的数组 `nums`，每个位置都有两种选择（`+` 或 `-`），所以一共有 `2ⁿ` 种表达式。  
- 我们可以用 **回溯（DFS）** 的方式，从左到右依次尝试把当前数加上或减去，然后递归处理剩余的数。  
- 当所有数都处理完后，检查累计的和是否等于 `target`，相等就计数。

> **类比**：把每个数字想象成一条路口的红绿灯，红灯要左转（`-`），绿灯要直行（`+`），我们要把所有灯的走向全部列举出来，看看有多少条路线的终点恰好在目标位置。

**正确性**：回溯会遍历 **所有** 可能的符号分配，只有当累计和等于目标时才计数，因而不会漏掉任何合法解，也不会多计。

**复杂度分析**（大白话）  
- 时间复杂度：我们要访问 `2ⁿ` 种情况，每种情况都要走完 `n` 步的递归，所以大约是 `O(2ⁿ)`（指数级）。这里的 `2ⁿ` 可以想象成把 `n` 张硬币每张翻正反两面，所有可能的翻法总数。  
- 空间复杂度：递归栈的深度等于数组长度 `n`，所以是 `O(n)`。另外我们只用了常数级的额外变量。

#### 代码（Python）

```python
from typing import List

def findTargetSumWays_bruteforce(nums: List[int], target: int) -> int:
    n = len(nums)
    ans = 0                     # 用来统计满足条件的表达式个数

    def dfs(index: int, cur_sum: int) -> None:
        """递归遍历第 index 个数之前已经决定好的符号，cur_sum 为当前累计和"""
        nonlocal ans
        if index == n:          # 所有数字都已经处理完
            if cur_sum == target:
                ans += 1        # 找到一种合法的符号组合
            return

        # 选择在 nums[index] 前加 '+'
        dfs(index + 1, cur_sum + nums[index])
        # 选择在 nums[index] 前加 '-'
        dfs(index + 1, cur_sum - nums[index])

    dfs(0, 0)                   # 从第 0 位开始，累计和为 0
    return ans
```

#### 复杂度

- **时间复杂度**：`O(2ⁿ)` —— 需要尝试每一种 `+ / -` 的组合，指数级增长。  
- **空间复杂度**：`O(n)` —— 递归栈的最大深度等于数组长度。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **指数级的搜索空间**。我们需要把问题转换成可以 **动态规划**（DP）求解的形式，避免重复枚举。

**关键观察**  
把所有数字分成两组：

- 加号所在的集合记为 `P`
- 减号所在的集合记为 `N`

根据题意有：

```
sum(P) - sum(N) = target                (1)
sum(P) + sum(N) = sum(nums)             (2)   （把所有数都加起来的总和）
```

把 (1) 与 (2) 相加得到：

```
2 * sum(P) = target + sum(nums)
=> sum(P) = (target + sum(nums)) / 2
```

所以，**只要能够找到若干个数的子集，使其和等于 `S = (target + total) / 2`，就对应唯一的一种符号分配**。

> **类比**：把所有数字装进一个大背包，背包里有两种颜色的球（红色代表 `+`，蓝色代表 `-`）。我们想让红色球的重量恰好等于 `S`，蓝色球的重量自然就是 `total - S`，这样两边的差就是目标 `target`。

因此，问题等价于 **求有多少种子集和为 `S`**。这正是「背包计数」的经典 DP 场景。

**前置条件**  
- `target + total` 必须是偶数，否则 `S` 不是整数，不可能实现。  
- `S` 不能为负数，因为子集和不可能是负数。

**动态规划实现**  
使用一维 DP 数组 `dp[i]` 表示 **从前面的数字中挑选，得到和为 `i` 的方案数**。初始化 `dp[0] = 1`（空集凑出和 0 有一种方式）。遍历每个数字 `num`，从大到小更新 `dp`（防止同一个数字被重复使用）：

```
for num in nums:
    for i from S down to num:
        dp[i] += dp[i - num]
```

遍历结束后，`dp[S]` 即为答案。

**复杂度解释**  
- 时间：外层遍历 `n`（最多 20），内层遍历 `S`（最大不超过 1000），所以 `O(n * S)`，在本题约为 `O(20 * 1000) = O(2·10⁴)`，非常快。  
- 空间：只用了长度为 `S+1` 的一维数组，`O(S)`，即最多 `1001` 个整数，几乎可以忽略。

#### 代码（Python）

```python
from typing import List

def findTargetSumWays_dp(nums: List[int], target: int) -> int:
    total = sum(nums)                     # 所有数字的总和
    # (target + total) 必须为偶数且非负，才能形成合法的子集和 S
    if (target + total) % 2 != 0 or target > total:
        return 0

    S = (target + total) // 2             # 需要凑出的子集和
    # dp[i] 表示从已经遍历的数字中挑选，和为 i 的方案数
    dp = [0] * (S + 1)
    dp[0] = 1                             # 空集凑出 0 的唯一方式

    for num in nums:
        # 从大到小更新，防止同一个数字在同一次循环中被使用多次
        for i in range(S, num - 1, -1):
            dp[i] += dp[i - num]          # 把当前数字加进来形成新的和

    return dp[S]
```

#### 复杂度

- **时间复杂度**：`O(n * S)`，其中 `n = len(nums) ≤ 20`，`S = (target + sum(nums)) / 2 ≤ 1000`。相较于暴力的 `O(2ⁿ)`，这里是线性乘积，快得多。  
- **空间复杂度**：`O(S)`，只需要一个大小为 `S+1` 的一维数组。

## 心得

- **核心技巧**：把“符号分配求和”问题转化为“子集和计数”问题（背包计数），利用等式变形得到目标子集和 `S`。  
- **适用的题型**  
  1. **分割等和子集**（LeetCode 416 – Partition Equal Subset Sum）  
  2. **可以得到特定差值的两组数**（如「两数之和差」的变体）  
  3. **背包计数**（任意要求统计满足特定总重量/价值的组合数）  
- **一句话总结**：把 `+`、`-` 的选择视为把数组划分成两堆，求出一堆的和即可，用子集和 DP 快速计数。

## 反思

- **第一反应**：直接写递归/回溯枚举所有 `+ / -` 的组合，想到“暴力搜索”。  
- **最容易踩的坑**  
  1. **目标值与总和的奇偶性**：忘记检查 `(target + total)` 是否为偶数，导致求 `S` 时出现小数。  
  2. **负数 target**：即使 `target` 为负，只要 `target + total` 为偶数且 `S ≥ 0`，仍然可以转换。  
  3. **数组中出现 0**：0 可以随意加或减，但在子集计数 DP 中会导致 `dp[i]` 加倍，需要确保 DP 逻辑仍然正确（本实现天然兼容）。  
- **下次思路**：看到“在每个数前加 `+` 或 `-`”这类描述时，第一步就尝试 **等式变形 → 子集和**，检查是否可以转化为背包计数，这往往能把指数级搜索降到多项式时间。
