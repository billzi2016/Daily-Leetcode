## 题目（英文原版）

**Description**

Given two integer arrays nums1 and nums2, return an array of their intersection. Each element in the result must appear as many times as it shows in both arrays and you may return the result in any order.
Follow up:

**Examples**

**Example 1:**

```
Input: nums1 = [1,2,2,1], nums2 = [2,2]
Output: [2,2]
```

**Example 2:**

```
Input: nums1 = [4,9,5], nums2 = [9,4,9,8,4]
Output: [4,9]
Explanation: [9,4] is also accepted.
```

**Constraints**

- 1 <= nums1.length, nums2.length <= 1000
- 0 <= nums1[i], nums2[i] <= 1000

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是把两个数组的每个元素都两两比较：  
- 取 `nums1` 中的第一个数，去 `nums2` 里找有没有相同的，如果找到了就把它放进答案，并把 `nums2` 中对应的那个位置标记为“已经被用过”（比如把它改成一个不可能出现的特殊值 `None`），防止同一个元素被重复计数。  
- 然后继续遍历 `nums1` 的下一个数，重复同样的查找过程。

> **类比**：把 `nums2` 想象成一本字典，`nums1` 的每个单词我们都去字典里查找一次，查到后把这页纸撕掉（标记为已用），这样后面的单词就不会再使用这页纸了。

**为什么正确**：因为我们对每个 `nums1` 的元素，都严格检查 `nums2` 中是否还有剩余的同值元素，只有在两边都有对应的“库存”时才加入答案，正好满足“出现次数要和两数组中最小的出现次数一致”的要求。

**复杂度分析**  
- 外层遍历 `nums1` 长度为 `n`，内层最坏情况下要遍历完整个 `nums2`（长度 `m`），所以总共大约要做 `n × m` 次比较 → **时间复杂度 O(n·m)**。  
  > 用大白话说，若两个数组各有 1000 个元素，最坏要比较 1,000,000 次，算是“蛮力”级别的。
- 我们只在原数组上做标记，额外使用的空间只有常数级别的几个变量 → **空间复杂度 O(1)**（不计输入本身）。

#### 代码（Python）

```python
def intersect_brute(nums1, nums2):
    """
    暴力解：两层循环逐个比较
    """
    # 为了不修改原数组，这里拷贝一份 nums2 作为工作区
    nums2_work = nums2[:]          # 复制一份，后面会把匹配到的元素设为 None
    result = []                    # 用来保存交集元素

    for x in nums1:                # 遍历 nums1 的每个元素
        for i in range(len(nums2_work)):
            if nums2_work[i] == x: # 找到相同的元素
                result.append(x)   # 加入答案
                nums2_work[i] = None   # 标记为已使用，防止再次被匹配
                break              # 只匹配一次就可以退出内层循环
    return result
```

#### 复杂度

- **时间复杂度**：`O(n·m)`  
  这里的 `n = len(nums1)`，`m = len(nums2)`。如果两个数组都是 1000 长，最坏要比较 1,000,000 次。
- **空间复杂度**：`O(1)`（不计输入和拷贝 `nums2` 的那一点额外空间）  
  只用了常数个临时变量 `result`、`i`、`x`。

### 2. 最优解

#### 思路  

从暴力解可以看到，**瓶颈**在于每次都要遍历完整个 `nums2` 去找匹配，导致 `O(n·m)`。  
要把时间降下来，关键是**把“查找是否存在”这个操作变快**。  
在编程里，**哈希表（Python 中的 dict / collections.Counter）** 能在 **常数时间 O(1)** 完成“是否出现、出现多少次”的查询——就像查字典一样，直接把单词对应的页码取出来。

优化步骤：

1. **统计 `nums1` 中每个数出现的次数**，把结果存进哈希表 `cnt1`（`cnt1[value] = 出现次数`）。  
   - 这一步只需要遍历一次 `nums1`，时间 `O(n)`。
2. 再遍历 `nums2`，对每个数 `y`：  
   - 查看 `cnt1` 中是否还有剩余的 `y`（即 `cnt1[y] > 0`）。  
   - 若有，说明 `y` 同时在两数组中出现，加入答案，并把 `cnt1[y]` 减 1，表示这一次匹配已经用掉了一个库存。  
   - 若没有（`cnt1[y] == 0` 或根本不存在），直接跳过。  
   - 这一步同样是一次线性遍历，时间 `O(m)`。
3. 结束后 `result` 就是交集，且每个元素出现的次数恰好是两数组中最小的那一次出现次数。

> **类比**：把 `cnt1` 看成是“仓库清单”。`nums1` 把每种商品的库存登记进去，`nums2` 来采购时，只要仓库还有库存，就可以出货并把库存减掉。这样既保证不超卖，又不需要逐个去仓库里找。

**为什么最优**：我们把“在 `nums2` 中查找 `nums1` 是否有相同元素”这个操作的成本，从 **线性遍历**（`O(m)`）降到了 **哈希表的 O(1) 查询**，整体时间变成 `O(n + m)`，已经是线性级别，无法再进一步降低（因为我们至少要看一遍两个输入）。

#### 代码（Python）

```python
from collections import Counter  # Counter 是专门用来统计出现次数的工具

def intersect_optimal(nums1, nums2):
    """
    最优解：利用哈希表（计数器）统计出现次数，实现 O(n+m) 时间
    """
    # 1. 统计 nums1 中每个数的出现次数
    cnt1 = Counter(nums1)          # 例如 [1,2,2,1] -> {1:2, 2:2}
    
    result = []                    # 用来保存交集结果

    # 2. 遍历 nums2，检查是否还能匹配
    for num in nums2:
        if cnt1[num] > 0:          # cnt1 中还有剩余的该数字
            result.append(num)     # 加入答案
            cnt1[num] -= 1         # 用掉一个库存
            # 当 cnt1[num] 变成 0 时，后面再遇到相同的 num 就会被自动跳过
    return result
```

#### 复杂度

- **时间复杂度**：`O(n + m)`  
  - `n = len(nums1)`，`m = len(nums2)`。我们只各遍历一次两个数组，查表是常数时间。相当于把 1,000,000 次比较压缩到 2,000 次遍历（在最坏的 1000+1000 大小下）。
- **空间复杂度**：`O(k)`，`k` 为较小数组中不同元素的种类数。  
  - 计数器 `cnt1` 需要存放每种不同数字的出现次数，最坏情况下每个数字都不相同，`k = min(n, 1000)`（因为题目限制值在 0~1000），所以最多只会占用约 1001 个整数的空间，算是 **线性额外空间**。

## 心得

- **核心技巧**：利用哈希表（计数器）把“出现次数”存下来，实现一次遍历即可完成交集计数。  
- **适用的题型**  
  1. **两个数组的交集/并集**（如 *Intersection of Two Arrays*、*Intersection of Two Arrays II*）。  
  2. **找出数组中出现次数相同的元素**（如 *Find the Difference of Two Arrays*）。  
  3. **字母/数字频率比较**（如 *Valid Anagram*、*Ransom Note*）。  
- **一句话总结解题钥匙**：**先把一个集合的“库存”记下来，再用另一个集合逐个“出货”。**

## 反思

- **第一反应**：直接想到两层循环逐个比较，属于最朴素的“暴力”思路。  
- **最容易踩的坑**  
  - **重复计数**：如果只判断元素是否出现过而不记录次数，会导致结果中出现的次数不对。  
  - **修改原数组**：在暴力实现里把 `nums2` 标记为 `None`，如果后面还需要原数组就会出错，需要拷贝一份。  
  - **边界条件**：空数组或全部相同元素的情况，都必须能正常返回空列表或全部匹配的元素。  
- **下次遇到同类题**：第一步先**思考能否把其中一个集合的元素计数存起来**（哈希表/Counter），再用另一个集合进行“匹配”。这一步往往能直接把时间从平方级降到线性级。
