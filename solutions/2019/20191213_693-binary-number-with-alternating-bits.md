# #693. 交替位的二进制数 / Binary Number with Alternating Bits

> 难度：简单 · 标签：Bit Manipulation · [LeetCode 链接](https://leetcode.com/problems/binary-number-with-alternating-bits/)

---

## 题目（英文原版）

**Description**

Given a positive integer, check whether it has alternating bits: namely, if two adjacent bits will always have different values.

**Examples**

**Example 1:**

```
Input: n = 5
Output: true
Explanation: The binary representation of 5 is: 101
```

**Example 2:**

```
Input: n = 7
Output: false
Explanation: The binary representation of 7 is: 111.
```

**Example 3:**

```
Input: n = 11
Output: false
Explanation: The binary representation of 11 is: 1011.
```

**Constraints**

- 1 <= n <= 231 - 1

---

## 题目（中文翻译）

**题目描述**  
给定一个正整数，判断它的二进制表示是否具有交替位（alternating bits），即任意两个相邻的位（bit）的取值总是不同。

**示例**  

**示例 1**  
输入: `n = 5`  
输出: `true`  
解释: 5 的二进制表示为 `101`，相邻位交替出现。

**示例 2**  
输入: `n = 7`  
输出: `false`  
解释: 7 的二进制表示为 `111`，相邻位不交替。

**示例 3**  
输入: `n = 11`  
输出: `false`  
解释: 11 的二进制表示为 `1011`，最后两位相同，未形成交替。

**约束条件**  
- `1 <= n <= 2^31 - 1`   (即 `231 - 1`)

---

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把整数 `n` 的二进制写出来（就像把数字写在纸上），然后逐位比较相邻的两个位是否相同。  
- **把整数变成二进制字符串**：Python 的 `bin()` 函数会返回形如 `'0b10101'` 的字符串，去掉前面的 `'0b'` 就得到纯二进制。
- **逐字符检查**：从左到右遍历字符串，若出现 `s[i] == s[i+1]`（相邻位相同），说明不是交替的，直接返回 `False`；遍历完都没有冲突则返回 `True`。

这里用到的唯一“数据结构”是 **字符串**，可以把它想象成一本书的文字稿，遍历每个字符就像逐行阅读。

为什么这个方法一定对？因为二进制的每一位在字符串里都有对应的字符，只要所有相邻字符不同，二进制本身必然满足“交替位”。  

#### 代码（Python）

```python
def hasAlternatingBits_bruteforce(n: int) -> bool:
    # 1. 把整数转换成二进制字符串，去掉前缀 '0b'
    bits = bin(n)[2:]                 # 例：n=5 -> '101'
    # 2. 从左到右逐对比较相邻的字符
    for i in range(len(bits) - 1):
        if bits[i] == bits[i + 1]:    # 如果相邻位相同，直接返回 False
            return False
    # 3. 循环结束说明所有相邻位都不同
    return True
```

#### 复杂度  

- **时间复杂度**：`O(k)`，这里的 `k` 是二进制位数。因为我们只遍历了一遍二进制字符串，最多遍历 `log₂ n` 次（比如 `n ≤ 2³¹‑1`，最多 31 位），所以可以说是 **线性** 的。  
- **空间复杂度**：`O(k)`，存放二进制字符串需要占用和位数等长的空间。

---  

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**需要额外的字符串空间**，并且遍历一次。我们可以直接在二进制层面做运算，省去字符串的创建。核心思路如下：

1. **相邻位不同 → 异或后全是 1**  
   把 `n` 向右移动一位得到 `n>>1`（相当于把二进制整体右移一格，左边补 0）。  
   对原数 `n` 与右移后的数做 **异或**（`^`），如果相邻位本来就不同，则每一位的异或结果都是 1。  
   例如 `n = 1010`，`n>>1 = 0101`，`n ^ (n>>1) = 1111`。

2. **全是 1 的数有特殊形式**  
   全部为 1 的二进制数一定是形如 `2^k - 1`（比如 `111` = `2³-1`）。判断一个数 `x` 是否为 `2^k - 1`，只要检查 `x & (x+1) == 0` 即可。因为 `x+1` 会把全部的 1 变成 0 并在最高位产生一个 1，二者与运算得到 0。

把这两步合在一起，就得到 **只用常数时间和常数空间** 的解法。

> **类比**：把 `n` 当作一本书，`n>>1` 是把这本书的每页向后“错位”一页。异或相当于把两本书对应页的文字做“对比”，如果每页文字都不相同，结果页全是“✔”。再检查全是“✔”的页是否只是一段连续的“✔”，这正是 `x & (x+1) == 0` 的含义。

#### 代码（Python）

```python
def hasAlternatingBits_optimal(n: int) -> bool:
    # 1. 把 n 与右移一位的 n 做异或，得到的 x 若是交替位则全是 1
    x = n ^ (n >> 1)
    # 2. 判断 x 是否为全 1 的形式：x & (x + 1) == 0
    #    - 当 x = 111...1 时，x+1 会变成 1000...0，二者与为 0
    return (x & (x + 1)) == 0
```

#### 复杂度  

- **时间复杂度**：`O(1)`（常数时间）。不论 `n` 多大，我们只做了几次位运算，位数上限是 31 位（题目限制），所以可以视作固定步数。  
- **空间复杂度**：`O(1)`（常数空间），只使用了若干个整数变量，不会随 `n` 的大小增长。

## 心得  

- **核心技巧**：位运算（右移、异或、与）+ “全 1”数的判定 (`x & (x+1) == 0`)。  
- **适用的相似题型**  
  1. 判断一个整数是否为 **2 的幂**（LeetCode 231）——同样利用 `n & (n-1) == 0`。  
  2. 判断一个整数的二进制中 **是否只有一个 1**（类似 “判断是否为幂”）。  
  3. 判断二进制是否为 **回文**（LeetCode 1014）——可以使用位翻转后比较。  
- **一句话总结**：一次异或把相邻位的差值全部变成 1，再用 `x & (x+1)` 检查是否全为 1，即可在 O(1) 时间判断交替位。

## 反思  

- **第一反应**：把数字转成二进制字符串再逐位比较，因为这最直观。  
- **最容易踩的坑**  
  - 忘记 `bin()` 返回的 `'0b'` 前缀，需要切片去掉。  
  - 只考虑正数，若不小心输入了 `0`（虽然题目不允许），需要额外处理。  
  - 位运算时忘记加括号导致优先级错误，例如 `n ^ n >> 1` 实际等价于 ` (n ^ n) >> 1`。  
- **下次遇到同类题**：第一步先思考**“相邻位的关系能否用位运算一次性捕获？”**，如果可以，就尝试 **异或 + 全 1 判定** 的套路。这样往往能直接得到 O(1) 的最优解。
