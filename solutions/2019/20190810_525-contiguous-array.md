# #525. 连续数组 / Contiguous Array

> 难度：中等 · 标签：Array、Hash Table、Prefix Sum · [LeetCode 链接](https://leetcode.com/problems/contiguous-array/)

---

## 题目（英文原版）

**Description**

Given a binary array nums, return the maximum length of a contiguous subarray with an equal number of 0 and 1.

**Examples**

**Example 1:**

```
Input: nums = [0,1]
Output: 2
Explanation: [0, 1] is the longest contiguous subarray with an equal number of 0 and 1.
```

**Example 2:**

```
Input: nums = [0,1,0]
Output: 2
Explanation: [0, 1] (or [1, 0]) is a longest contiguous subarray with equal number of 0 and 1.
```

**Example 3:**

```
Input: nums = [0,1,1,1,1,1,0,0,0]
Output: 6
Explanation: [1,1,1,0,0,0] is the longest contiguous subarray with equal number of 0 and 1.
```

**Constraints**

- 1 <= nums.length <= 105
- nums[i] is either 0 or 1.

## 题目（中文翻译）

给定一个二进制数组（binary array）`nums`，返回其中**等数量的 0 和 1 的最长连续子数组（contiguous subarray）**的长度。

### 示例

#### 示例 1
**输入**: `nums = [0,1]`  
**输出**: `2`  
**解释**: `[0, 1]` 是等数量的 0 和 1 的最长连续子数组。

#### 示例 2
**输入**: `nums = [0,1,0]`  
**输出**: `2`  
**解释**: `[0, 1]`（或 `[1, 0]`）是等数量的 0 和 1 的最长连续子数组。

#### 示例 3
**输入**: `nums = [0,1,1,1,1,1,0,0,0]`  
**输出**: `6`  
**解释**: `[1,1,1,0,0,0]` 是等数量的 0 和 1 的最长连续子数组。

### 约束条件
- `1 <= nums.length <= 10^5`
- `nums[i]` 只能是 `0` 或 `1`。

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  

最直接的想法就是把所有可能的连续子数组都枚举一遍，逐个统计子数组里 `0` 和 `1` 的个数，看它们是否相等。  

- **枚举子数组**：把数组的左边界 `i` 从 `0` 开始遍历到 `n‑1`，右边界 `j` 再从 `i` 往后走到 `n‑1`，这样就能得到所有的 `[i, j]` 区间。  
- **计数**：在遍历每个区间时，用两个计数器 `cnt0`、`cnt1` 分别记录出现的 `0`、`1` 的数量。  
- **更新答案**：如果 `cnt0 == cnt1`，说明这个子数组满足题目要求，用它的长度 `j‑i+1` 与当前最大长度比较，取较大者。  

> **类比**：把数组想象成一条路，`i` 和 `j` 分别是两根路标。我们把所有可能的起点‑终点组合都走一遍，看看哪段路上红灯（0）和绿灯（1）数量相等，最长的那段就是答案。  

这个方法一定能得到正确答案，因为它把**所有**符合条件的子数组都检查了一遍。  

#### 代码（Python）  

```python
def findMaxLength(nums):
    n = len(nums)
    max_len = 0                         # 保存当前找到的最长长度

    # 枚举左边界 i
    for i in range(n):
        cnt0, cnt1 = 0, 0                # 重新统计区间 [i, j] 的 0/1 个数
        # 枚举右边界 j（从 i 开始向右扩展）
        for j in range(i, n):
            if nums[j] == 0:
                cnt0 += 1               # 遇到 0，计数器加一
            else:
                cnt1 += 1               # 遇到 1，计数器加一

            # 若 0、1 数量相等，更新最长长度
            if cnt0 == cnt1:
                max_len = max(max_len, j - i + 1)

    return max_len
```

#### 复杂度  

- **时间复杂度**：`O(n²)`  
  - 外层循环 `i` 执行 `n` 次，内层循环 `j` 最多也会执行 `n` 次，整体是 **平方级** 的遍历。可以把 `O(n²)` 想象成“如果有 10 000 个元素，最坏情况下要做 100 000 000 次比较”。  
- **空间复杂度**：`O(1)`  
  - 只用了几个计数变量，和输入规模无关，常数级空间。

### 2. 最优解  

#### 思路  

暴力解的瓶颈在于**重复统计**。在枚举子数组时，每次都要从左到右重新数 `0`、`1`，导致大量冗余工作。我们可以把计数过程“搬到”一次遍历里完成，思路如下：

1. **把 0 视作 -1**  
   - 把数组中的每个 `0` 替换成 `-1`（`1` 仍保持为 `1`）。  
   - 这样，一个子数组里 `0` 与 `1` 数量相等，就等价于该子数组的 **和为 0**（因为 `(-1) + 1 = 0`）。  

2. **前缀和 + 哈希表**  
   - **前缀和**：`pre[i]` 表示从数组开头到下标 `i‑1`（不含 `i`）的累计和。  
   - 如果两个前缀和相等，说明它们之间的那段子数组和为 `0`。  
   - 我们用一个哈希表（Python 的 `dict`）记录每个前缀和第一次出现的位置。  
   - 当遍历到第 `i` 个元素时，计算当前前缀和 `cur`。  
     - 若 `cur` 已经在哈希表里，说明之前出现过相同的前缀和，子数组 `[hash[cur] , i‑1]` 的和为 `0`，长度为 `i - hash[cur]`。  
     - 若 `cur` 没出现过，就把 `cur` 与当前下标 `i` 存入表中（只保留第一次出现的位置，因为这样得到的子数组最长）。  

3. **最大长度**  
   - 在遍历过程中实时更新最长满足条件的子数组长度。  

> **类比**：想象你在一条路上走，每走一步记下“净收益”（遇到 `1` +1，遇到 `0` -1）。如果两次记下的累计收益相同，说明这两次之间的路段净收益为 0，也就是 `0` 与 `1` 数量相等。哈希表就像一本“收益-第一次出现位置”的小册子，帮你快速找到对应的路段。  

#### 代码（Python）  

```python
def findMaxLength(nums):
    # 1. 把 0 视作 -1，方便后面求和为 0 的子数组
    transformed = [-1 if x == 0 else 1 for x in nums]

    prefix_index = {0: -1}   # 前缀和 0 在下标 -1 处“出现”，相当于空前缀
    cur_sum = 0              # 当前前缀和
    max_len = 0

    # 2. 一次遍历计算前缀和并使用哈希表查找
    for i, val in enumerate(transformed):
        cur_sum += val       # 更新累计和

        if cur_sum in prefix_index:
            # 前缀和之前出现过，子数组长度 = 当前下标 - 之前的下标
            prev_index = prefix_index[cur_sum]
            max_len = max(max_len, i - prev_index)
        else:
            # 第一次出现该前缀和，记录下来
            prefix_index[cur_sum] = i

    return max_len
```

#### 复杂度  

- **时间复杂度**：`O(n)`  
  - 只遍历了一遍数组，每个元素的处理都是常数时间（哈希表的查找/插入平均 `O(1)`）。如果有 100 000 个元素，只需要大约 100 000 次操作，远快于平方级。  
- **空间复杂度**：`O(n)`  
  - 最坏情况下每个不同的前缀和都要存进哈希表，最多会有 `n+1` 条记录（包括初始的 `0`）。这相当于需要和输入规模同等的额外空间。

## 心得  

- **核心技巧**：把 “相等的 0 与 1” 转化为 “子数组和为 0”，再利用前缀和 + 哈希表快速定位零和子数组。  
- **适用的题型**  
  1. “找最长子数组，使其和等于 K”（如 LeetCode 525）  
  2. “找最长子数组，使其和为 0” 的变形（如前缀和 + 哈希表的经典例子）  
  3. “子数组中出现次数相等的两类元素” 的问题（如把一种元素记为 `+1`，另一种记为 `-1`）  
- **一句话总结**：把“数量相等”转成“和为 0”，用前缀和哈希表一次遍历即可找最长子数组。

## 反思  

- **第一反应**：看到 “0 和 1 数量相等”，立刻想到计数，进而想到暴力枚举所有子数组。  
- **最容易踩的坑**  
  - **忘记把 0 转成 -1**：直接统计 `0/1` 会导致无法使用前缀和为 0 的技巧。  
  - **哈希表的初始化**：前缀和为 0 时对应的下标应该是 `-1`，否则会错过从数组开头就满足条件的子数组。  
  - **重复覆盖前缀和位置**：只能记录**第一次**出现的下标，否则会得到更短的子数组。  
- **下次遇到同类题的第一步**：问自己 “能否把两个元素的相等关系映射成数值相加为 0？” 若答案是肯定的，就立刻想到 “前缀和 + 哈希表” 这把钥匙。
