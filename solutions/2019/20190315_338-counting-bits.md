## 题目（英文原版）

**Description**

Given an integer n, return an array ans of length n + 1 such that for each i (0 <= i <= n), ans[i] is the number of 1's in the binary representation of i.
Follow up:

**Examples**

**Example 1:**

```
Input: n = 2
Output: [0,1,1]
Explanation:
0 --> 0
1 --> 1
2 --> 10
```

**Example 2:**

```
Input: n = 5
Output: [0,1,1,2,1,2]
Explanation:
0 --> 0
1 --> 1
2 --> 10
3 --> 11
4 --> 100
5 --> 101
```

**Constraints**

- 0 <= n <= 105

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是：**把每个数 `i`（0 ≤ i ≤ n）都转成二进制，逐位数一数有多少个 `1`**。  
这就像我们平时查字典一样：把单词（这里是数字）写下来，再一个字母一个字母地数它出现了几次。  

- **用到的数据结构**：只需要一个普通的 Python 列表 `ans` 来保存答案，列表就像一排格子，格子下标对应数字 `i`，格子里放的是 `i` 的 1 的个数。
- **为什么正确**：每个 `i` 都按照二进制的定义完整地被检查了一遍，统计的 `1` 的个数必然是正确的。

#### 代码（Python）

```python
def countBits_brute(n: int) -> list[int]:
    # 创建长度为 n+1 的答案列表，先全部填 0
    ans = [0] * (n + 1)

    # 从 0 遍历到 n
    for i in range(n + 1):
        # 将 i 转成二进制字符串，去掉开头的 '0b'
        binary = bin(i)[2:]

        # 统计二进制字符串中 '1' 的个数
        cnt = 0
        for ch in binary:
            if ch == '1':
                cnt += 1

        # 把统计结果写进答案列表对应的位置
        ans[i] = cnt

    return ans
```

#### 复杂度

- **时间复杂度**：`O(n * log n)`  
  解释：我们遍历了 `0 … n` 共 `n+1` 次。每一次都要把数字转成二进制并逐位检查，二进制位数大约是 `log₂ i`，最坏情况下是 `log₂ n`。所以总的工作量大概是 `n * log n`。  
  用大白话说，就是如果 `n` 是 1,000,000，`log₂ n` 约等于 20，整体大约是 20 倍的 `n`。

- **空间复杂度**：`O(n)`  
  解释：我们必须把 `n+1` 个答案全部存到列表里，列表本身占用 `n+1` 个位置。除此之外只用了常数级的临时变量。

### 2. 最优解

#### 思路  

从暴力解我们可以看到 **“把每个数都独立算一遍”** 是耗时的根源。  
如果能 **利用已经算好的结果** 来推导后面的答案，就可以省掉很多重复的工作。

观察二进制：

| i   | 二进制 | i // 2（右移一位） | i % 2（最低位） |
|-----|--------|-------------------|----------------|
| 0   | 0      | 0                 | 0 |
| 1   | 1      | 0                 | 1 |
| 2   | 10     | 1                 | 0 |
| 3   | 11     | 1                 | 1 |
| 4   | 100    | 2                 | 0 |
| 5   | 101    | 2                 | 1 |
| …   | …      | …                 | … |

可以发现 **“把 i 右移一位（即除以 2）得到的数，已经在之前算过了”**，而 **最低位是 0 还是 1** 只决定了 **再加 0 还是加 1**。  
于是得到递推公式：

```
dp[i] = dp[i >> 1] + (i & 1)
```

- `i >> 1`：相当于把二进制整体右移一位，等价于 `i // 2`。这一步已经在更小的 `i` 上算过了。
- `i & 1`：取 `i` 的最低位（奇数为 1，偶数为 0），用位运算实现，非常快。

把这个公式从 `i = 1` 逐个算到 `n`，每一步只用 **常数时间**，整体就是线性 `O(n)`。

#### 代码（Python）

```python
def countBits_dp(n: int) -> list[int]:
    # dp[i] 保存 i 的二进制中 1 的个数，初始化长度为 n+1，全部为 0
    dp = [0] * (n + 1)

    # 从 1 开始遍历，因为 dp[0] 已经是 0（0 的二进制没有 1）
    for i in range(1, n + 1):
        # i >> 1 相当于 i // 2，dp[i>>1] 已经算好
        # i & 1 取最低位，奇数为 1，偶数为 0
        dp[i] = dp[i >> 1] + (i & 1)

    return dp
```

#### 复杂度

- **时间复杂度**：`O(n)`  
  解释：循环一次对应一个 `i`，每次只做了两次位运算和一次加法，都是常数时间。和 `n` 成正比。和暴力解相比，省掉了 `log n` 那层“遍历每个二进制位”。

- **空间复杂度**：`O(n)`  
  解释：仍然需要保存 `n+1` 个答案的数组 `dp`。如果只要求返回列表，这已经是最小必需的空间。

## 心得

- **核心技巧**：**利用已知子问题的答案递推出更大的答案**（动态规划的思想），并结合 **位运算**（`>>`、`&`）把「除以 2」和「判断奇偶」写得既简洁又高效。
- **适用的题型**  
  1. 计数类 DP：如 “求 0~n 中每个数的二进制 1 的个数”  
  2. 子集计数：如 “求子集和为 target 的方案数”  
  3. 前缀/后缀递推：如 “斐波那契数列”“爬楼梯”  
- **一句话总结**：**把大问题拆成「右移一位」的小问题，奇偶决定是否再加一**。

## 反思

- **第一反应**：看到“二进制里有多少个 1”，马上想到逐位检查（暴力）。
- **最容易踩的坑**  
  - 忘记 `0` 也要算在答案里，导致返回长度少一。  
  - 对 `n = 0` 的边界没有特别处理，循环会直接跳过。  
  - 位运算写成 `i >> 2` 或 `i & 2`，会把规律弄错。  
- **下次第一步**：先思考 **“当前数和更小的数有什么直接的位关系？”**（如右移、低位奇偶），再决定是否可以用 DP 或滚动数组来复用已有结果。
