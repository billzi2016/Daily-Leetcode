# #413. 等差切片 / Arithmetic Slices

> 难度：中等 · 标签：Array、Dynamic Programming、Sliding Window · [LeetCode 链接](https://leetcode.com/problems/arithmetic-slices/)

## 题目（英文原版）

**Description**

An integer array is called arithmetic if it consists of at least three elements and if the difference between any two consecutive elements is the same.
Given an integer array nums, return the number of arithmetic subarrays of nums.
A subarray is a contiguous subsequence of the array.

**Examples**

**Example 1:**

```
Input: nums = [1,2,3,4]
Output: 3
Explanation: We have 3 arithmetic slices in nums: [1, 2, 3], [2, 3, 4] and [1,2,3,4] itself.
```

**Example 2:**

```
Input: nums = [1]
Output: 0
```

**Constraints**

- 1 <= nums.length <= 5000
- -1000 <= nums[i] <= 1000

## 题目（中文翻译）

一个整数数组（integer array）如果满足以下条件，则称为等差的（arithmetic）：  
- 至少包含三个元素；  
- 任意两个相邻元素之间的差值相同。

给定一个整数数组 `nums`，返回 `nums` 中等差子数组（arithmetic subarrays）的数量。  
子数组（subarray）是数组的连续子序列（contiguous subsequence）。

## 示例

### 示例 1
**输入**: `nums = [1,2,3,4]`  
**输出**: `3`  
**解释**: `nums` 中有 3 个等差切片（arithmetic slices）: `[1, 2, 3]`, `[2, 3, 4]` 以及 `[1,2,3,4]` 本身。

### 示例 2
**输入**: `nums = [1]`  
**输出**: `0`

## 约束条件
- `1 <= nums.length <= 5000`
- `-1000 <= nums[i] <= 1000`

---

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：枚举所有可能的**连续子数组**，判断它们是否满足“等差数列”的条件。  
- **枚举子数组**：我们可以用两个循环，外层循环固定子数组的左端点 `i`，内层循环固定右端点 `j`（`j >= i+2`，因为等差子数组长度至少是 3）。  
- **判断等差**：取子数组的前两个元素求差 `d = nums[i+1] - nums[i]`，随后把子数组里的每一对相邻元素的差都和 `d` 比较，只要有一次不相等，就说明这段子数组不是等差的。  

> **类比**：把数组想成一本连续的页码，暴力枚举就像把每一页都和后面的每一页配对检查，检查每一段是否“每页翻页的距离相同”。  

这个方法一定能得到正确答案，因为我们把**所有**合法的子数组都检查了一遍。只不过检查的过程非常冗余——很多子数组的前缀已经检查过了，却被重复计算。

#### 代码（Python）

```python
def numberOfArithmeticSlices(nums):
    n = len(nums)
    ans = 0

    # i 为子数组左端点
    for i in range(n - 2):                # 至少需要留出 3 个元素
        # j 为子数组右端点，必须 >= i+2 才满足长度 >= 3
        for j in range(i + 2, n):
            # 计算首两个元素的差值
            diff = nums[i + 1] - nums[i]
            ok = True                     # 标记当前子数组是否等差

            # 检查子数组 [i, j] 中每一对相邻元素的差是否都等于 diff
            for k in range(i + 1, j):
                if nums[k + 1] - nums[k] != diff:
                    ok = False            # 只要有一次不相等，就不是等差子数组
                    break

            if ok:
                ans += 1                  # 统计一个合法的等差子数组

    return ans
```

#### 复杂度  

- **时间复杂度：** `O(n³)`  
  - 外层 `i` 循环 O(n)  
  - 内层 `j` 循环 O(n)  
  - 判断等差的内部循环最坏也要遍历 O(n)  
  - 所以整体是 O(n·n·n) = O(n³)。  
  - **大白话**：如果数组有 1000 个元素，算法大约要跑 10⁹ 次“检查”，显然会很慢。

- **空间复杂度：** `O(1)`  
  - 只使用了常数个额外变量 (`i, j, k, diff, ok, ans`)，不随输入规模增长。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**重复检查**相同的前缀。观察等差子数组的结构可以帮助我们把时间降到 `O(n²)` 甚至 `O(n)`。

**关键观察**  
- 如果 `nums[i-2], nums[i-1], nums[i]` 三个数已经构成等差数列（即 `nums[i] - nums[i-1] == nums[i-1] - nums[i-2]`），那么以 `i` 为结尾的所有等差子数组，都可以在**以 `i-1` 为结尾的等差子数组**的基础上再延伸一个元素。  
- 换句话说，设 `dp[i]` 为**以 `i` 位置结尾的等差子数组的数量**（长度 ≥ 3），则  
  ```
  if nums[i] - nums[i-1] == nums[i-1] - nums[i-2]:
      dp[i] = dp[i-1] + 1
  else:
      dp[i] = 0
  ```
  - `+1` 表示新出现的最短等差子数组 `[i-2, i-1, i]`。  
  - `dp[i-1]` 已经统计了所有以 `i-1` 结尾的等差子数组，每个都可以再往右加上 `nums[i]`，仍保持等差，因此它们也都贡献了一份到 `dp[i]`。

**如何得到答案**  
- 所有以任意位置结尾的等差子数组数目之和，就是答案：`ans = sum(dp[i])`（`i` 从 `2` 开始）。

**为什么是线性时间**  
- 我们只遍历一次数组，针对每个元素做 O(1) 的判断和更新。没有嵌套循环，也没有重复检查。

**类比**：把数组看成一条路，每走一步我们都检查前一步的坡度是否和前前一步相同。如果相同，说明我们可以把已经走过的“等坡路段”继续往前延伸，形成更长的等坡路段。

#### 代码（Python）

```python
def numberOfArithmeticSlices(nums):
    n = len(nums)
    if n < 3:                 # 长度不到 3 的数组不可能有等差子数组
        return 0

    ans = 0                    # 最终答案
    dp = 0                     # dp 只需要保存前一个位置的值，节省空间

    # 从下标 2 开始，因为等差子数组最短长度为 3
    for i in range(2, n):
        # 判断以 i 为结尾的最近三个数是否等差
        if nums[i] - nums[i-1] == nums[i-1] - nums[i-2]:
            dp = dp + 1       # 继承前面的等差子数组数量并加上新的最短子数组
            ans += dp         # 累加到答案中
        else:
            dp = 0            # 差值不相等，不能形成等差子数组，重置

    return ans
```

> **注**：这里的 `dp` 实际上是 `dp[i]`，我们只保留了上一次的值，从而把空间复杂度降到 `O(1)`。

#### 复杂度  

- **时间复杂度：** `O(n)`  
  - 只遍历一次数组，所有操作都是常数时间。  
  - **大白话**：如果数组有 5000 个元素，最多只会检查 5000 次差值，比暴力的 10⁹ 次少了几个数量级，运行几毫秒就能结束。

- **空间复杂度：** `O(1)`  
  - 只使用了几个整数变量 (`ans, dp, i`），不随 `n` 增长。

## 心得

- **核心技巧**：利用等差数列的**递推性质**，把“以当前位置结尾的等差子数组数量”转化为前一个位置的结果加一。相当于动态规划的“一维滚动数组”写法。
- **适用的题型**  
  1. **等差子数组计数**（本题）  
  2. **等差数列的最长子序列**（LeetCode 1027）  
  3. **连续子数组满足某种固定差值的计数**（如“连续递增子数组”）
- **一句话总结解题钥匙**：**“相邻差值相同 ⇒ 以当前为结尾的等差子数组 = 前一个位置的等差子数组 + 1”。**

## 反思

- **第一反应**：看到“等差子数组”，本能想把所有子数组枚举出来检查——这就是暴力解的思路。
- **最容易踩的坑**  
  - **边界条件**：数组长度小于 3 时直接返回 0。  
  - **差值相等的判断**：一定要在 `i` ≥ 2 时才比较 `nums[i] - nums[i-1]` 与 `nums[i-1] - nums[i-2]`，否则会越界。  
  - **累计答案**：`dp` 记录的是**以当前元素结尾的子数组数量**，要记得把它加到全局答案 `ans` 中，而不是只保留最后一个 `dp`。
- **下次遇到同类题**：第一步先**思考是否有递推关系**（比如“以当前位置结尾的合法子结构”），如果有，就尝试用**动态规划 / 滚动数组**把复杂度降到线性。这样可以避免毫无必要的三层循环。
