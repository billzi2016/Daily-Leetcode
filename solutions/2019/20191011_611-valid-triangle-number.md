# #611. 有效三角形计数 / Valid Triangle Number

> 难度：中等 · 标签：Array、Two Pointers、Binary Search、Greedy、Sorting · [LeetCode 链接](https://leetcode.com/problems/valid-triangle-number/)

---

## 题目（英文原版）

**Description**

Given an integer array nums, return the number of triplets chosen from the array that can make triangles if we take them as side lengths of a triangle.

**Examples**

**Example 1:**

```
Input: nums = [2,2,3,4]
Output: 3
Explanation: Valid combinations are: 
2,3,4 (using the first 2)
2,3,4 (using the second 2)
2,2,3
```

**Example 2:**

```
Input: nums = [4,2,3,4]
Output: 4
```

**Constraints**

- 1 <= nums.length <= 1000
- 0 <= nums[i] <= 1000

---

## 题目（中文翻译）

给定一个整数数组 `nums`，返回从数组中选取的三元组（triplet）数量，使得这三个数可以作为三角形的三条边构成有效的三角形。

示例 1:
Input: nums = [2,2,3,4]
Output: 3
Explanation: 有效的组合有：
2,3,4 （使用第一个 2）
2,3,4 （使用第二个 2）
2,2,3

示例 2:
Input: nums = [4,2,3,4]
Output: 4

约束条件：
- 1 <= nums.length <= 1000
- 0 <= nums[i] <= 1000

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是把数组里所有可能的**三元组**都枚举一遍，然后检查它们能否构成三角形。  
- **枚举三元组**：用三层循环 `i、j、k`（`i < j < k`）依次挑选三个下标。  
- **判断三角形**：三条边 `a、b、c`（不妨设 `a ≤ b ≤ c`）要满足 **三角形不等式** `a + b > c` 才能组成三角形。  
- **数据结构类比**：这里我们只用到普通的 **列表**（list），相当于把所有水果摆在桌子上，一次取三个尝试能否拼成一个三角形。

这个方法之所以 **正确**，是因为我们把**所有**合法的组合都检查了一遍，漏掉的情况不可能出现。

#### 代码（Python）

```python
from typing import List

def triangleNumber_brute(nums: List[int]) -> int:
    n = len(nums)
    count = 0
    # 三层循环枚举所有 i < j < k
    for i in range(n):
        for j in range(i + 1, n):
            for k in range(j + 1, n):
                a, b, c = nums[i], nums[j], nums[k]
                # 为了使用三角形不等式，需要先把三条边从小到大排好序
                x, y, z = sorted([a, b, c])
                # 若最短两边之和大于最长边，则是合法三角形
                if x + y > z:
                    count += 1
    return count
```

#### 复杂度  

- **时间复杂度**：`O(n³)`  
  - “立方”意思是如果数组长度翻倍，循环次数会大约增加 **8 倍**（因为 `2³ = 8`），所以对 `n = 1000` 的情况下会非常慢。  
- **空间复杂度**：`O(1)`  
  - 只用了常数个额外变量（计数器 `count`、几个临时变量），不随 `n` 增长。

### 2. 最优解

#### 思路  

暴力解的**瓶颈**在于三层循环，遍历了所有 `C(n,3)`（约 `n³/6`）个三元组。  
观察三角形不等式 `a + b > c`，如果我们把数组**从小到大排序**，则对于固定的最长边 `c`，只要找到 **最左侧** 的两个数 `a、b` 使得 `a + b > c`，右边的所有组合必然也满足（因为右边的数更大）。这就提供了**单调性**，可以用**双指针**把枚举次数压到 `O(n²)`。

优化步骤：

1. **排序**  
   把 `nums` 按升序排好。排序后，任意三个下标 `i < j < k` 对应的边长已经是 `nums[i] ≤ nums[j] ≤ nums[k]`，所以只需要检查 `nums[i] + nums[j] > nums[k]`。

2. **固定最长边**  
   从数组末尾开始，把 `k` 视为最长边的下标（从 `n‑1` 往前）。因为 `k` 最大时，左侧的两数范围最大，容易满足不等式。

3. **双指针寻找符合条件的左侧两数**  
   - `i` 指向最左端（0），`j` 指向 `k‑1`（紧挨着 `k` 的左边）。  
   - 如果 `nums[i] + nums[j] > nums[k]`，说明**从 i 到 j‑1** 的所有数与 `nums[j]`、`nums[k]` 组合都满足（因为它们更大或相等），于是可以直接把 `j‑i` 个合法三元组计入答案，然后把 `j` 左移一位继续检查。  
   - 否则，说明当前 `i` 太小，需要把 `i` 右移一位增大左边的最小值，尝试让和变大。

4. **循环**  
   对每一个 `k` 重复上述过程，累加所有合法组合数。

**核心概念解释**  

- **双指针**：把数组想象成一条直线，两个手指分别站在左端和右端，依据条件把其中一个手指向中间移动，逐步逼近答案。  
- **单调性**：因为数组已排序，`i` 向右移动会让 `nums[i]` 变大，`j` 向左移动会让 `nums[j]` 变小，这两个方向的变化是**单调递增/递减**的，正好配合判断条件。

#### 代码（Python）

```python
from typing import List

def triangleNumber(nums: List[int]) -> int:
    nums.sort()                     # 1. 先排序，保证 nums[i] <= nums[j] <= nums[k]
    n = len(nums)
    ans = 0

    # 2. 固定最长边，k 从右往左遍历
    for k in range(n - 1, 1, -1):   # 至少需要三个数，所以 k 最小到 2
        i, j = 0, k - 1            # i 最左，j 紧挨 k 的左边
        # 3. 双指针在 [0, k-1] 区间寻找满足 nums[i] + nums[j] > nums[k] 的组合
        while i < j:
            if nums[i] + nums[j] > nums[k]:
                # nums[i]..nums[j-1] 与 nums[j], nums[k] 都合法
                ans += j - i       # 直接计入所有以当前 j 为第二大边的组合数
                j -= 1             # 把 j 左移，继续检查更小的第二大边
            else:
                i += 1             # 和不够大，增大最小边 i
    return ans
```

#### 复杂度  

- **时间复杂度**：`O(n²)`  
  - “平方”意味着如果数组长度翻倍，运行时间大约会 **增加 4 倍**（因为 `2² = 4`）。这里的两层循环（外层遍历 `k`，内层的 `while i < j`）总共最多执行 `n·(n‑1)/2` 次。相比暴力的 `O(n³)`，快了一个数量级。  
- **空间复杂度**：`O(1)`（不计排序使用的原地交换）  
  - 只用了几个指针变量 `i, j, k` 和计数器 `ans`，不随 `n` 增长。

## 心得

- **核心技巧**：先排序 + 双指针利用单调性快速计数。  
- **适用的题型**：  
  1. “三数之和”类的计数题（如 *三数之和小于目标*）。  
  2. “满足某种不等式的三元组”问题（如 *求满足 a + b > c 的三元组*）。  
  3. “两数之和”在有序数组中的变形（如 *两数之和等于目标* 的双指针解法）。  
- **一句话总结解题钥匙**：**把数组排好序，利用最长边固定后双指针一次遍历即可把所有合法组合一次性算完**。

## 反思

- **第一反应**：直接想到枚举所有三元组并检查三角形不等式。  
- **最容易踩的坑**：  
  - 忘记先排序，导致判断 `a + b > c` 时 `c` 不一定是最长边。  
  - 在双指针循环中忘记 `j - i` 的计数方式，只计数单个组合会导致漏计。  
  - 边界条件：数组长度小于 3 时直接返回 0，防止 `k` 循环出现负下标。  
- **下次遇到同类题**：第一步先 **排序**，然后 **固定一个极端（最长/最短）**，再用 **双指针** 在剩余区间快速统计满足条件的组合。
