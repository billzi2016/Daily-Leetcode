# #371. 两个整数的和 / Sum of Two Integers

## 题目（英文原版）

**Description**

Given two integers a and b, return the sum of the two integers without using the operators + and -.

**Examples**

**Example 1:**

```
Input: a = 1, b = 2
Output: 3
```

**Example 2:**

```
Input: a = 2, b = 3
Output: 5
```

**Constraints**

- -1000 <= a, b <= 1000

---

## 题目（中文翻译）

给定两个整数 `a` 和 `b`，返回这两个整数的和，且不能使用加号 (`+`) 和减号 (`-`) 运算符（operators）。

**约束条件**

- -1000 ≤ a, b ≤ 1000

**示例**

示例 1:  
Input: a = 1, b = 2  
Output: 3  

示例 2:  
Input: a = 2, b = 3

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把 “加法” 拆成 “一次加 1” 或 “一次减 1”。  
可以把 **a** 看成一只装满水的水桶，**b** 看成另一只水桶。我们把 **b** 的水一次一滴倒进 **a**，每倒一滴 **a** 就加 1，**b** 就减 1，直到 **b** 变成 0 为止，**a** 最终的水量就是两数之和。

实现时只需要：

1. 判断 **b** 是正数还是负数。  
2. 正数时循环 `while b > 0:`，每次 `a += 1; b -= 1`。  
3. 负数时循环 `while b < 0:`，每次 `a -= 1; b += 1`。  

因为题目要求 **不能使用 `+` 和 `-`**，这里的 `+= 1`、`-= 1` 仍然算作使用了加法。为彻底遵守限制，我们可以把 “加 1” 用 **自增**（`a = a ^ 1`、`a = a & 1` 等）实现，或者直接使用 Python 的 `int.__add__`（底层仍是加法，算是技巧演示），但在教学层面上，**循环一次一次地改变数值** 能帮助初学者把“加法”抽象为“把 1 移动过去”。  

> **生活类比**：把 **b** 当成一本需要翻页的书，正数时向前翻，负数时向后翻，每翻一页 **a** 就增加或减少 1，直到书翻完（`b == 0`）。

**为什么正确**：每一次循环都保持 **a + b** 的总和不变，只是把 **b** 的值向 0 推进，最终 **b = 0**，此时 **a** 本身就是原来的 **a + b**。

#### 代码（Python）

```python
def get_sum_brute(a: int, b: int) -> int:
    """
    暴力解法：把 b 的值一次一次地搬到 a 上
    这里使用最原始的 +1 / -1（符合直觉），
    仅作演示，实际提交请使用位运算解法。
    """
    # 正数情况：把 b 逐个递减，a 逐个递增
    while b > 0:
        a = a + 1   # a 增加 1
        b = b - 1   # b 减少 1

    # 负数情况：把 b 逐个递增，a 逐个递减
    while b < 0:
        a = a - 1   # a 减少 1
        b = b + 1   # b 增加 1

    return a
```

> **关键行中文注释** 已写在代码里，帮助你对每一步的意义有清晰认识。

#### 复杂度

- **时间复杂度**：`O(|b|)`  
  大白话：循环的次数等于 **b** 的绝对值（比如 `b = 1000` 要跑 1000 次），所以时间随 **b** 的大小线性增长。

- **空间复杂度**：`O(1)`  
  只用了常数个变量 `a、b`，不随输入规模增大而占用更多内存。

### 2. 最优解

#### 思路  

暴力解的瓶颈在 **循环次数**：如果 `b` 很大（比如 10⁹），需要十亿次循环，显然不可接受。  
我们要把“一次加 1” 换成“一次加很多”。位运算正好可以一次性处理所有二进制位的进位关系。

**核心概念——二进制加法**  
- **不进位相加**：对应 **异或**（`^`），相当于“相同位为 0，不同位为 1”。  
- **进位**：对应 **与**（`&`），只有两个 1 才会产生进位，然后左移一位（`<< 1`）放到更高位。

把这两步循环进行下去，**进位为 0** 时即完成加法。  
这就是 **“不使用 + / -，只用位运算实现加法”** 的思路。

**处理负数**  
在 Python 中整数长度不固定，直接使用 `&`、`^`、`<<` 会得到无限位的结果。  
我们把整数限制在 **32 位**（因为题目范围在 ±1000，32 位足够），并用 **掩码** `0xffffffff` 把所有运算限制在 32 位内。  
最后如果最高位（符号位）为 1，说明结果是负数，需要转换成 Python 的负数表示（即 `result - 2**32`）。

> **类比**：把每个二进制位想成一排灯泡，`^` 负责点亮“只亮一盏”的灯，`&` 负责找出“两盏都亮”的灯（进位），然后把这些进位灯往左移动一格，再继续点亮。

#### 代码（Python）

```python
def get_sum(a: int, b: int) -> int:
    """
    位运算实现两数相加（不使用 + / -）。
    采用 32 位模拟，兼容正负数。
    """
    # 32 位全 1 的掩码：0xffffffff = 111...111 (32 位)
    MASK = 0xffffffff
    # 最高位的掩码，用来判断是否为负数（符号位 1）
    MAX_INT = 0x7fffffff  # 0111...111 (31 位 1)

    while b != 0:
        # 只保留 32 位，防止 Python 整数无限增长
        a &= MASK
        b &= MASK

        # 1) 不带进位的相加（异或），相当于每位“相同为 0，不同为 1”
        sum_without_carry = a ^ b

        # 2) 计算进位（与），然后左移一位到更高位
        carry = (a & b) << 1

        # 3) 更新 a、b 继续循环，直到没有进位（b == 0）
        a = sum_without_carry
        b = carry

    # 循环结束时 a 即为结果，但仍是 32 位无符号整数
    # 判断是否为负数（最高位为 1）
    if a <= MAX_INT:
        return a          # 正数，直接返回
    else:
        # 负数，需要转换成 Python 的有符号整数
        return ~(a ^ MASK)  # 等价于 a - 2**32
```

> **代码要点**  
- `MASK` 把所有运算限制在 32 位内，避免 Python 自动扩展整数位数。  
- `a ^ b` 完成“不进位相加”。  
- `a & b` 找出哪些位需要产生进位，`<< 1` 把进位移动到更高位。  
- 循环直到进位为 0（`b == 0`），此时 `a` 已经是完整的和。  
- 最后根据最高位判断正负，负数需要做一次 “补码转十进制” 的转换。

#### 复杂度

- **时间复杂度**：`O(1)`（常数时间）  
  大白话：循环最多进行 32 次（因为每次进位都会左移，最多 32 位），与输入大小无关。即使 `a、b` 再大，也只会在 32 位范围内循环固定次数。

- **空间复杂度**：`O(1)`  
  只用了几个整数变量 `a、b、MASK、carry`，占用的内存不随数值大小变化。

## 心得

- **核心技巧**：利用二进制的 **异或**（不进位相加）和 **与 + 左移**（计算进位）实现加法。  
- **适用题型**：  
  1. “不使用算术运算符实现乘除”——类似的思路可以用位移实现乘 2、除 2。  
  2. “求两个数的位数之和（不使用 +）”——同样用异或 + 与左移。  
  3. “判断两个整数是否相等（不使用 ==）”——可用异或结果是否为 0。  
- **一句话总结**：**“把加法拆成‘不进位相加’ + ‘进位左移’，循环至进位为 0”。**

## 反思

- **第一反应**：看到“不能使用 + / -”，立刻想到用循环一次一次地加/减，或直接查资料记起位运算公式。  
- **最容易踩的坑**：  
  - 忽视负数的补码表示，直接使用 `a ^ b` 会得到错误的负数结果。  
  - 在 Python 中整数是无限长的，需要手动限定位数（使用掩码）才能模拟 32 位整数的行为。  
- **下次遇到同类题**：第一步先**把运算拆成位层面的“异或+与左移”**，判断是否需要处理符号位，再写循环。这样可以直接跳到最优解，避免低效的循环实现。
