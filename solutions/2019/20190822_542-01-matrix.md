**Description**

Given an m x n binary matrix mat, return the distance of the nearest 0 for each cell.
The distance between two cells sharing a common edge is 1.
Note: This question is the same as 1765: https://leetcode.com/problems/map-of-highest-peak/

```

```

**Example 2:**

```
Input: mat = [[0,0,0],[0,1,0],[1,1,1]]
Output: [[0,0,0],[0,1,0],[1,2,1]]
```

- m == mat.length
- n == mat[i].length
- 1 <= m, n <= 104
- 1 <= m * n <= 104
- mat[i][j] is either 0 or 1.
- There is at least one 0 in mat.

## 解题过程

### 1. 直觉解（暴力）

#### 思路  
最直接的想法是：**对每一个格子，都把整个矩阵遍历一遍，找出离它最近的 0**。  
- **遍历方式**：双层 `for` 循环遍历行 `i`、列 `j`，再嵌套第二组双层循环遍历所有格子 `p,q`，如果 `mat[p][q] == 0`，就计算曼哈顿距离 `|i-p| + |j-q|`，取最小值。  
- **用到的数据结构**：这里只需要普通的二维列表（matrix），相当于我们平时写的表格。  
- **为什么正确**：因为我们把**所有可能的 0 都枚举一遍**，所以一定能找到最近的那一个，最小距离自然就是答案。  

> **生活化类比**：把矩阵想成一座城市的街区，0 像是医院，1 像是居民家。我们要为每家每户找最近的医院，暴力做法就是把每家每户都派一辆车跑遍全城，记录下最近的医院距离。

#### 代码（Python）

```python
from typing import List

def updateMatrix_bruteforce(mat: List[List[int]]) -> List[List[int]]:
    m, n = len(mat), len(mat[0])          # 行数、列数
    ans = [[0] * n for _ in range(m)]    # 用来存放答案的矩阵

    for i in range(m):                   # 遍历每一个格子 (i, j)
        for j in range(n):
            if mat[i][j] == 0:           # 本身就是 0，距离就是 0
                ans[i][j] = 0
                continue

            min_dist = float('inf')      # 先设一个很大的距离
            # 暴力遍历整个矩阵，找最近的 0
            for p in range(m):
                for q in range(n):
                    if mat[p][q] == 0:   # 只关心值为 0 的格子
                        dist = abs(i - p) + abs(j - q)   # 曼哈顿距离
                        if dist < min_dist:
                            min_dist = dist
            ans[i][j] = min_dist          # 记录找到的最近距离

    return ans
```

#### 复杂度  

- **时间复杂度**：`O(m * n * m * n) = O((mn)²)`  
  解释：外层两层循环遍历 `mn` 个格子，内层又遍历全部 `mn` 个格子，总共是 `mn` 的平方。可以想象成如果矩阵有 1000 个格子，算法要做 1,000,000 次距离计算，显然很慢。  

- **空间复杂度**：`O(m * n)`  
  解释：我们额外用了一个同样大小的 `ans` 矩阵来保存结果，除此之外几乎不占额外空间。

### 2. 最优解

#### 思路  
暴力解的瓶颈在于**每个格子都要遍历全矩阵**。我们需要一种办法，让每个格子只“看一次”或“看很少几次”。  
观察题目：**所有的 0 都是距离的起点**，从 0 出发向四周扩散，第一次到达的 1 的距离就是它最近的 0 的距离。  
这正好对应 **广度优先搜索（BFS）** 的特性：从源点层层展开，先遍历到的点距离源点最近。  

**关键点**：

1. **多源 BFS**：把矩阵里所有的 0 同时放进队列（queue）作为起点，这样搜索会从所有 0 同时向外扩散。  
2. **层次遍历**：每弹出一个格子，就把它的上下左右四个相邻格子（如果还未被访问）加入队列，并把距离设为 `当前格子距离 + 1`。  
3. **访问标记**：我们用 `ans` 矩阵来记录已经算好的距离，未访问的格子保持 `-1`（或 `inf`），这样可以避免重复入队。

> **生活化类比**：把所有医院（0）想象成同时点燃的灯塔，光线以相同速度向四周扩散。每当光线第一次照到某个居民家（1），那家就记下了离最近医院的距离。因为光线是同步扩散的，第一次照到的距离一定是最近的。

**为什么是最优**：每个格子只会被加入队列一次，且每次弹出时只检查常数（最多 4）个相邻格子，整体只需要 `O(mn)` 的时间。

#### 代码（Python）

```python
from collections import deque
from typing import List

def updateMatrix_bfs(mat: List[List[int]]) -> List[List[int]]:
    m, n = len(mat), len(mat[0])
    ans = [[-1] * n for _ in range(m)]   # -1 表示“未访问”，随后会填上距离
    q = deque()                         # 队列，用来做 BFS

    # 1️⃣ 把所有 0 加入队列，距离设为 0
    for i in range(m):
        for j in range(n):
            if mat[i][j] == 0:
                ans[i][j] = 0
                q.append((i, j))        # (行, 列)

    # 方向数组，帮助我们一次遍历四个相邻格子
    dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]

    # 2️⃣ BFS 主循环
    while q:
        x, y = q.popleft()              # 取出队首坐标
        for dx, dy in dirs:             # 检查四个方向
            nx, ny = x + dx, y + dy
            # 越界或已经有距离的格子直接跳过
            if not (0 <= nx < m and 0 <= ny < n) or ans[nx][ny] != -1:
                continue
            ans[nx][ny] = ans[x][y] + 1  # 距离 = 当前格子距离 + 1
            q.append((nx, ny))           # 把新格子加入队列，继续向外扩散

    return ans
```

#### 复杂度  

- **时间复杂度**：`O(m * n)`  
  解释：每个格子最多被加入队列一次、弹出一次，且每次只检查四个邻居，整体线性遍历整个矩阵。相比暴力的 `O((mn)²)`，快了很多。  

- **空间复杂度**：`O(m * n)`  
  解释：除了输入矩阵外，我们额外用了一个同样大小的 `ans` 矩阵和一个最多装 `mn` 个坐标的队列。

## 心得

- **核心技巧**：**多源 BFS**（一次性从所有 0 同时展开），把“最近距离”转化为“层次扩散”。  
- **适用的题型**：  
  1. “岛屿的距离”类问题（如 LeetCode 1162：地图分析）。  
  2. “迷宫最短路径”类问题（单源 BFS），只不过起点改成多个。  
  3. “最小步数到达目标”类问题（如 01 Matrix 的变体）。  
- **一句话总结解题钥匙**：**把所有答案已知的点放进队列，一层层向外扩散，第一次到达的距离就是最近的答案。**

## 反思

- **第一反应**：看到“最近 0 的距离”，自然会想到“对每个 1 暴力找最近的 0”。  
- **最容易踩的坑**：  
  - 忘记把所有 0 同时入队，导致只从单个源点 BFS，得到的不是最近的全局距离。  
  - 没有做好访问标记，导致同一个格子被重复加入队列，出现时间浪费甚至死循环。  
  - 边界检查不严谨，访问 `nx, ny` 时越界会抛异常。  
- **下次遇到同类题**：第一步先**确认是否可以把所有已知答案点一次性加入 BFS 队列**，如果可以，就直接走多源 BFS；如果不是距离而是计数或最大值，考虑 DP 双遍或单调栈等其他技巧。
