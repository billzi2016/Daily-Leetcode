# #397. **整数替换** / Integer Replacement

> 难度：中等 · 标签：Dynamic Programming、Greedy、Bit Manipulation、Memoization · [LeetCode 链接](https://leetcode.com/problems/integer-replacement/)

---

## 题目（英文原版）

**Description**

Given a positive integer n, you can apply one of the following operations:
Return the minimum number of operations needed for n to become 1.

**Examples**

**Example 1:**

```
Input: n = 8
Output: 3
Explanation: 8 -> 4 -> 2 -> 1
```

**Example 2:**

```
Input: n = 7
Output: 4
Explanation: 7 -> 8 -> 4 -> 2 -> 1
or 7 -> 6 -> 3 -> 2 -> 1
```

**Example 3:**

```
Input: n = 4
Output: 2
```

**Constraints**

- 1 <= n <= 231 - 1

---

## 题目（中文翻译）

给定一个正整数 `n`，你可以对其执行以下两种操作之一：

- 若 `n` 为偶数，则将 `n` 替换为 `n / 2`；
- 若 `n` 为奇数，则可以将 `n` 替换为 `n + 1` 或 `n - 1`。

返回将 `n` 变为 `1` 所需的最少操作次数。

**示例 1**  
**输入:** `n = 8`  
**输出:** `3`  
**解释:** `8 -> 4 -> 2 -> 1`

**示例 2**  
**输入:** `n = 7`  
**输出:** `4`  
**解释:** `7 -> 8 -> 4 -> 2 -> 1`  
或 `7 -> 6 -> 3 -> 2 -> 1`

**示例 3**  
**输入:** `n = 4`  
**输出:** `2`  
**解释:** `4 -> 2 -> 1`

**约束条件**  
- `1 <= n <= 2^31 - 1`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**每一步都把题目给的两种操作全部尝试一次**，把所有可能的路径都走遍，找出走到 `1` 所需的最少步数。

- **数据结构**：递归（或显式的栈）把每一次的选择压进去，等到走到 `1` 时再弹出来。可以把递归过程想象成“在森林里走迷宫”，每遇到一个岔路口（`n` 为奇数时）就把两条路都记下来，等走到底再比较哪条更短。
- **为什么正确**：因为我们把**所有**合法的操作序列都枚举了，最短的那条必然在其中，所以最终得到的答案一定是最小的。

> ⚠️ 这就是“暴力搜索”。它保证正确，却往往非常慢，尤其是 `n` 较大时会产生巨大的搜索树。

#### 代码（Python）

```python
def integer_replacement_bruteforce(n: int) -> int:
    """
    暴力递归：尝试所有可能的操作路径，返回最小步数。
    注意：此实现没有任何剪枝或记忆化，时间会爆炸，仅用于演示思路。
    """
    # 递归的结束条件：已经变成 1，不需要再操作
    if n == 1:
        return 0

    # 如果是偶数，只能除以 2
    if n % 2 == 0:
        return 1 + integer_replacement_bruteforce(n // 2)

    # 奇数有两种选择：+1 或 -1
    # 分别递归求解后取最小值
    plus_one  = integer_replacement_bruteforce(n + 1)
    minus_one = integer_replacement_bruteforce(n - 1)
    return 1 + min(plus_one, minus_one)
```

> **关键行解释**  
> - `if n == 1:` —— 当已经到达目标时，返回 0 步。  
> - `if n % 2 == 0:` —— 偶数只能除以 2，这一步必然是最优的。  
> - `plus_one  = integer_replacement_bruteforce(n + 1)` —— 递归尝试 “+1” 的分支。  
> - `minus_one = integer_replacement_bruteforce(n - 1)` —— 递归尝试 “-1” 的分支。  

#### 复杂度  

- **时间复杂度**：`O(2^k)`（近似指数级），其中 `k` 是二进制位数。  
  - 大白话：每次遇到奇数我们会分成两条路，就像不断把树枝分叉，树的层数和 `n` 的位数成正比，分叉次数呈指数增长。  
- **空间复杂度**：`O(k)`，递归栈的深度最多等于二进制位数（约 `log₂ n`）。  

> 暴力解在 `n` 只到几百时还能接受，`n` 达到题目上限 `2³¹‑1` 时会直接卡死。

### 2. 最优解

#### 思路  

从暴力解出发，我们可以看到 **瓶颈** 出现在奇数时的“分叉”。如果能够 **提前判断到底是 +1 还是 -1 更好**，就能把分叉次数大幅削减。

**关键观察**  

1. **偶数**：唯一的最优操作是除以 2。因为 `n/2` 必然比 `n±1` 更小，且一步就完成了。  
2. **奇数**：我们有两条路 `n‑1` 或 `n+1`。哪条更有利取决于后面的二进制结构。  
   - 当 `n = 3` 时，`3 → 2 → 1`（-1）只需要 2 步，而 `3 → 4 → 2 → 1`（+1）需要 3 步，**这里应该特判**。  
   - 对于其他奇数，观察它们的最低两位：  
     - 若二进制形式以 `...01` 结尾（即 `n & 3 == 1`），执行 **-1** 会让后面的连续 `1` 更快变成 `0`，随后可以连续除以 2。  
     - 若以 `...11` 结尾（即 `n & 3 == 3`），执行 **+1** 会把连续的 `1` 变成 `0`，同样有利于后续的除以 2。  

   直观类比：**把数字看成一串灯泡**，`1` 表示灯亮，`0` 表示灯灭。我们的目标是让所有灯最终熄灭（变成 `1` 的二进制只有一位 `1`），除以 2 相当于把灯泡整体向右移动一位，`+1/-1` 则是调节最右侧几盏灯的状态。让连续亮着的灯一次性熄灭，能省掉很多次“右移”。

3. **递归 + 记忆化**：即使我们已经把奇数的选择确定下来，仍然会出现重复子问题（例如 `n = 15 → 16 → 8 → 4 → 2 → 1` 与 `n = 15 → 14 → 7 → 8 …` 中都出现了 `8`）。使用 **哈希表**（在 Python 中是 `dict`）把已经算好的 `n` 对应的最少步数存下来，后面再遇到同样的 `n` 直接查表，省时省力。  
   - 哈希表就像 **查字典**：`key` 是数字 `n`，`value` 是已知的最少步数。

**算法步骤**  

1. 建立一个全局字典 `memo = {1: 0}`（因为 `1` 已知答案是 0 步）。  
2. 对给定的 `n` 递归求解：  
   - 若 `n` 在 `memo` 中直接返回。  
   - 若 `n` 为偶数，答案 = `1 + dfs(n//2)`。  
   - 若 `n` 为奇数且 `n == 3`，答案 = `2`（特判）。  
   - 否则检查 `n & 3`（即二进制的最后两位）：  
     - `n & 3 == 1` → 使用 `n-1`。  
     - `n & 3 == 3` → 使用 `n+1`。  
   - 递归得到子问题的答案后加 1（本次操作），存入 `memo` 并返回。  
3. 主函数调用递归并返回结果。

**为什么是最优**  

- **每次都只做一次除以 2**（最省步的操作），其它操作只在 **必须** 调整最低位时才出现。  
- 通过位运算 `n & 3` 快速决定是加还是减，避免了盲目枚举。  
- 记忆化把所有可能出现的子问题数量压到 **`O(log n)`**（因为每次除以 2 都会把位数减半），从而把指数级时间降到 **线性对数**。

#### 代码（Python）

```python
def integer_replacement(n: int) -> int:
    """
    最优解：贪心 + 记忆化（DP）
    通过位运算决定奇数时是 +1 还是 -1，使用 dict 记忆化子问题。
    """
    memo = {1: 0}                     # 记忆表：已知 1 需要 0 步

    def dfs(x: int) -> int:
        # 已经算过直接返回，省去重复递归
        if x in memo:
            return memo[x]

        if x % 2 == 0:                # 偶数：唯一选择除以 2
            ans = 1 + dfs(x // 2)
        else:
            # 特判 3：3 -> 2 -> 1 比 3 -> 4 -> 2 -> 1 更短
            if x == 3:
                ans = 2                # 3 -> 2 -> 1
            else:
                # 查看最低两位决定是 +1 还是 -1
                if x & 3 == 1:        # ...01，使用 -1
                    ans = 1 + dfs(x - 1)
                else:                 # ...11，使用 +1
                    ans = 1 + dfs(x + 1)

        memo[x] = ans                  # 记录结果，供后续查询
        return ans

    return dfs(n)
```

> **关键行解释**  
> - `memo = {1: 0}` —— 把已知答案存进去，相当于字典里已有“1 的页码是 0”。  
> - `if x in memo:` —— 先查字典，若已有直接返回，省掉大量递归。  
> - `if x % 2 == 0:` —— 偶数只能除 2，这是唯一最优的一步。  
> - `if x == 3:` —— 处理特殊小数 `3`，因为它的 “+1” 分支不如 “-1”。  
> - `x & 3` —— 用位运算取出二进制的最后两位，`00、01、10、11` 中只关心 `01` 与 `11`。  
> - `memo[x] = ans` —— 把算好的答案写进字典，后面再遇到相同的 `x` 直接查表。

#### 复杂度  

- **时间复杂度**：`O(log n)`。  
  - 大白话：每次除以 2 都把二进制位数减半，最多需要 `log₂ n` 次除法；奇数时只会进行一次加/减，再除以 2，整体步数与位数成正比。  
- **空间复杂度**：`O(log n)`。  
  - 递归栈深度最多 `log₂ n`，以及记忆化表中最多保存 `log₂ n` 个不同的 `n`（因为每次操作都会让数字的位数显著下降）。

> 与暴力解相比，时间从指数级下降到对数级，几乎可以在毫秒内解决题目上限的 `2³¹‑1`。

## 心得

- **核心技巧**：利用二进制位的特性（`n & 3`）做出“加 1 还是减 1”的贪心选择，并配合记忆化递归把子问题复用。  
- **适用的题型**  
  1. **整数变换类**：如 “Power of Two” 系列、`Broken Calculator`（把目标数通过乘 2 / 加 1 变成起始数）。  
  2. **位操作优化**：如 “Number of Steps to Reduce a Number to Zero” 需要判断奇偶并使用位运算。  
  3. **递归 + 记忆化**：多数需要最少步数的 DP 问题，如 “Minimum Steps to Make Two Strings Equal”。  
- **一句话总结**：**把数字当成灯泡，用位运算快速决定把哪盏灯先关掉，再配合记忆化避免重复劳动**。

## 反思

- **第一反应**：看到 “奇数可以 +1 或 -1，偶数只能 /2”，立刻想到 BFS/DFS 把所有路径枚举。  
- **最容易踩的坑**  
  1. **无限递归**：对奇数若不加上记忆化或不做位数判断，会出现 `n+1` 再 `n-1` 循环，导致栈溢出。  
  2. **特例 `3`**：`3` 是唯一需要在 “...11” 情况下选择 “-1” 的数，忘记特判会多走一步。  
  3. **整数溢出**：在 Python 中不受限制，但在某些语言（如 C++）`n+1` 可能超过 32 位整数，需要用 `long long`。  
- **下次类似题的第一步**：先**观察二进制结构**，判断哪些位的变化会导致后续操作（除以 2）更快，然后**用位运算**快速做出决策，最后用**记忆化**把已经算好的子问题保存起来。
