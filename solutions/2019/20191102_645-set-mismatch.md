# #645. 集合不匹配 / Set Mismatch

> 难度：简单 · 标签：Array、Hash Table、Bit Manipulation、Sorting · [LeetCode 链接](https://leetcode.com/problems/set-mismatch/)

---

## 题目（英文原版）

**Description**

You have a set of integers s, which originally contains all the numbers from 1 to n. Unfortunately, due to some error, one of the numbers in s got duplicated to another number in the set, which results in repetition of one number and loss of another number.
You are given an integer array nums representing the data status of this set after the error.
Find the number that occurs twice and the number that is missing and return them in the form of an array.

**Examples**

**Example 1:**

```
Input: nums = [1,2,2,4]
Output: [2,3]
```

**Example 2:**

```
Input: nums = [1,1]
Output: [1,2]
```

**Constraints**

- 2 <= nums.length <= 104
- 1 <= nums[i] <= 104

---

## 题目（中文翻译）

你有一个整数集合 **s**，最初它应该包含从 **1** 到 **n** 的所有数字。遗憾的是，由于某些错误，集合中有一个数字被复制成了另一个数字，导致出现了一个数字的重复出现，同时缺失了另一个数字。  
给定一个整数数组 **nums**（integer array），它表示错误发生后集合的状态。请找出出现两次的数字以及缺失的数字，并以数组的形式返回 `[重复的数字, 缺失的数字]`。

### 示例 1
**输入:** `nums = [1,2,2,4]`  
**输出:** `[2,3]`

### 示例 2
**输入:** `nums = [1,1]`  
**输出:** `[1,2]`

## 约束条件

- `1 <= nums[i] <= 10^4`

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  

最直接的想法是 **把每个数都和别的数比较一次**，看看哪两个数相等，这就是重复的数字；再把 1~n 的所有数字逐一检查一遍，哪个不在数组里就是缺失的数字。  

- **数据结构**：只用原数组本身，不需要额外的容器。可以把数组想象成一排座位，我们一个人站在座位前面，挨个去看前面已经站过的人是谁，如果看到已经站过的，那说明这两个座位上坐的是同一个人（即重复）。  
- **为什么正确**：因为题目保证数组里只有 **一个** 重复的数和 **一个** 缺失的数。只要把所有数两两比较一次，必然能找出那对相等的数；再把 1~n 全部遍历一遍，必然能发现哪个数没有出现。  

> **注意**：这种两层循环的比较会导致 **时间复杂度** 为 **O(n²)**，也就是“每个人都要和前面所有人握手”，当 n 很大时会很慢。  

#### 代码（Python）  

```python
def findErrorNums(nums):
    n = len(nums)
    duplicate = -1          # 用来保存出现两次的数
    # -------- 第一步：找重复的数（两层循环） --------
    for i in range(n):
        for j in range(i + 1, n):          # 只比较后面的元素，避免重复比较
            if nums[i] == nums[j]:         # 找到相等的说明是重复的
                duplicate = nums[i]
                break
        if duplicate != -1:                # 已经找到就可以提前结束外层循环
            break

    # -------- 第二步：找缺失的数（遍历 1~n） --------
    missing = -1
    for x in range(1, n + 1):              # 依次检查 1,2,...,n 是否出现在数组里
        if x not in nums:                  # “x not in nums” 相当于在座位表里找不到 x
            missing = x
            break

    return [duplicate, missing]
```

#### 复杂度  

- **时间复杂度**：`O(n²)`  
  - 外层循环 `n` 次，内层最坏也要遍历 `n-1` 次，整体是 `n × n`，也就是 **平方级**。可以把它想象成“每个人都要和所有其他人握手”。  
- **空间复杂度**：`O(1)`  
  - 只用了常数个额外变量（`duplicate、missing`），不随输入规模增长。

### 2. 最优解  

#### 思路  

从暴力解可以看到，**慢的根源在于两层循环的“全配对”**，我们其实不需要把每个数都和别的数比较，只要 **一次遍历** 就能把信息“标记”在原数组里。  

关键点在于 **利用数组下标**：  
- 数组里本应该出现的数是 `1 … n`。  
- 对于任意出现的数 `x`，我们可以把 **下标 `x‑1`** 位置的元素做标记（比如取负），表示 “我已经见过 `x` 了”。  
- 当我们再次看到同一个数 `x` 时，检查 `x‑1` 位置已经是负数了，这说明 `x` 是重复的。  

这样只需要 **一次遍历**（O(n)）就能找出重复的数。  
随后再 **一次遍历** 整个数组，哪个下标对应的元素仍是正数，说明对应的数字 **没有被标记**，也就是缺失的数。  

> **类比**：想象一排信箱（下标），每当收到信（出现的数字）就把对应信箱的门锁上（取负）。如果第二次收到同一封信，门已经是锁着的，这封信就是重复的。最后，哪一个信箱的门没有锁，就说明那封信根本没有到达——这就是缺失的数字。  

#### 代码（Python）  

```python
def findErrorNums(nums):
    duplicate = -1

    # ---------- 第一次遍历：标记出现的数字 ----------
    for num in nums:
        idx = abs(num) - 1          # 取绝对值是因为后面可能已经被取负
        if nums[idx] < 0:           # 已经是负数，说明该下标对应的数字出现过
            duplicate = abs(num)    # 记录重复的数字
        else:
            nums[idx] = -nums[idx]   # 第一次出现，取负表示“已出现”

    # ---------- 第二次遍历：找缺失的数字 ----------
    missing = -1
    for i in range(len(nums)):
        if nums[i] > 0:             # 正数说明下标 i 对应的数字 (i+1) 没出现过
            missing = i + 1
            break

    return [duplicate, missing]
```

#### 复杂度  

- **时间复杂度**：`O(n)`  
  - 只遍历了两遍数组，每遍都是线性时间。相比暴力的 `n²`，相当于“每个人只和自己握一次手”。  
- **空间复杂度**：`O(1)`  
  - 只用了常数个额外变量（`duplicate、missing、idx`），所有标记都直接写在原数组里，没有额外的容器。

## 心得  

- **核心技巧**：**原地标记（利用数组下标）** 或者 **负数技巧**，把信息“埋”在原数组里，省去额外空间。  
- **适用的题型**：  
  1. “寻找重复数字” 类题（如 LeetCode 287 `Find the Duplicate Number`）。  
  2. “寻找缺失数字” 类题（如 LeetCode 268 `Missing Number`，只需要一次遍历 + 标记）。  
- **一句话总结解题钥匙**：**把「出现」的信息直接写进数组对应位置的符号（正/负）里，随后扫描正号位置即可找出「未出现」的数字。**  

---

## 反思  

- **第一反应**：看到“重复 + 缺失”，立刻想到 “哈希表/计数数组”。这能跑得快，但会占用 O(n) 额外空间。  
- **最容易踩的坑**：  
  - 忘记对 `num` 取绝对值再去下标，因为下标位置的数可能已经被取负。  
  - 对 `1` 和 `n` 边界的处理不当，导致数组越界。  
  - 直接返回 `duplicate` 前没有初始化，可能在极端情况下（如没有重复）会返回错误值。  
- **下次类似题的第一步**：**先想能不能把信息“写回原数组”或“利用下标”来省空间**，如果不行再考虑哈希表或额外数组。
