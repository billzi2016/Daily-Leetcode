# #326. **三的幂** / Power of Three

> 难度：简单 · 标签：Math、Recursion · [LeetCode 链接](https://leetcode.com/problems/power-of-three/)

---

## 题目（英文原版）

**Description**

Given an integer n, return true if it is a power of three. Otherwise, return false.
An integer n is a power of three, if there exists an integer x such that n == 3x.

**Examples**

**Example 1:**

```
Input: n = 27
Output: true
Explanation: 27 = 33
```

**Example 2:**

```
Input: n = 0
Output: false
Explanation: There is no x where 3x = 0.
```

**Example 3:**

```
Input: n = -1
Output: false
Explanation: There is no x where 3x = (-1).
```

**Constraints**

- -231 <= n <= 231 - 1

---

## 题目（中文翻译）

给定一个整数 `n`，如果它是 3 的幂则返回 `true`，否则返回 `false`。  
如果存在整数 `x` 使得 `n == 3^x`，则称整数 `n` 为 3 的幂。

**示例 1**  
**输入**: `n = 27`  
**输出**: `true`  
**解释**: `27 = 3^3`

**示例 2**  
**输入**: `n = 0`  
**输出**: `false`  
**解释**: 没有整数 `x` 使得 `3^x = 0`。

**示例 3**  
**输入**: `n = -1`  
**输出**: `false`  
**解释**: 没有整数 `x` 使得 `3^x = (-1)`。

**约束条件**  
- $-2^{31} \leq n \leq 2^{31} - 1$

---

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：从 1 开始，一直乘以 3，看看能否恰好得到 `n`。  
- **使用的结构**：只需要一个整数变量 `cur`，它像一个“计数器”。可以把它想象成把水桶里的水一次倒进更大的桶里，每次容量是原来的 3 倍，直到装满或装不满为止。  
- **为什么正确**：如果 `n` 真的是 3 的某次方，那么 `1, 3, 9, 27, …` 这条乘 3 的序列一定会在某一步恰好等于 `n`；如果不是，那么序列要么会超过 `n`（正数情况），要么根本不会出现（非正数情况），因此一定找不到匹配。  
- **时间/空间分析**：  
  - 每次循环把 `cur` 乘以 3，循环次数大约是 `log₃ n`（因为每次都把数值放大 3 倍，直到超过 `n`）。在大白话里，这相当于“把 n 用 3 进制写出来，需要多少位”。  
  - 所以时间复杂度是 **O(log₃ n)**，这在计算机里通常记作 **O(log n)**（底数不影响大 O 记号）。  
  - 我们只用了几个整数变量，空间复杂度是 **O(1)**，即常数级别的内存。

#### 代码（Python）

```python
def isPowerOfThree_brute(n: int) -> bool:
    """
    暴力版：从 1 开始不断乘以 3，判断是否能恰好等于 n
    """
    # 负数、0 都不可能是 3 的正整数次方
    if n <= 0:
        return False

    cur = 1          # 从 3⁰ = 1 开始
    while cur < n:   # 只要还没超过 n，就继续乘 3
        cur *= 3      # 把当前值扩大 3 倍
    # 循环结束后，要么 cur == n（找到了），要么 cur > n（没有找到）
    return cur == n
```

#### 复杂度

- **时间复杂度**：`O(log₃ n)` —— 例如 n=27，需要乘 3 3 次（1 → 3 → 9 → 27），次数随 n 的大小呈对数增长。  
- **空间复杂度**：`O(1)` —— 只用了常数个变量，没有额外的数组或递归栈。

### 2. 最优解

#### 思路  

从暴力解可以看到，真正的耗时在 **循环乘 3** 这一步。我们可以把这一步“跳过去”，直接用数学性质来判断。

关键观察：

1. **所有 3 的正整数次方都是互相整除的**。也就是说，如果 `a` 是 3 的次方，`b` 也是 3 的次方，并且 `a > b`，那么 `a % b == 0`（`a` 能被 `b` 整除）。  
2. 在 32 位有符号整数范围内，最大的 3 的次方是 `3¹⁹ = 1162261467`（因为 `3²⁰ = 3486784401` 已经超出 `2³¹‑1 = 2147483647`）。  
3. 因此，只要 `n` 为正数，并且 **最大的 3 的次方能够被 `n` 整除**，那么 `n` 必定也是 3 的次方。  

把这两个条件写成代码：

- `n > 0`  
- `MAX_POWER_OF_THREE % n == 0`

这样我们只需要一次取模运算，就能得到答案，时间上是 **O(1)**。

> **为什么取模能判断？**  
> 想象 `MAX_POWER_OF_THREE` 是一根最长的“3 的链”，如果 `n` 正好是这根链上某一段的长度（即 `n` 本身是 3 的次方），那么这根链可以被整整切成若干段，每段长度都是 `n`，于是 `MAX_POWER_OF_THREE` 对 `n` 取余为 0。若 `n` 不是 3 的次方，它就不是这根链的“整段”，取余必然不为 0。

#### 代码（Python）

```python
def isPowerOfThree_optimal(n: int) -> bool:
    """
    最优版：利用 32 位整数范围内最大的 3 的次方，检查是否能整除
    """
    # 3 的最大正整数次方（3^19），在 32 位有符号整数范围内仍然安全
    MAX_POWER_OF_THREE = 1162261467  # 3**19

    # 负数、0 直接否定
    if n <= 0:
        return False

    # 如果最大 3 的次方能被 n 整除，则 n 必是 3 的次方
    return MAX_POWER_OF_THREE % n == 0
```

#### 复杂度

- **时间复杂度**：`O(1)` —— 只做了常数次的比较和一次取模运算，没有循环。相比暴力的 `O(log n)`，快了很多。  
- **空间复杂度**：`O(1)` —— 同样只用了几个整数变量。

## 心得

- **核心技巧**：利用「整数范围内的最大幂」和「整除性」来把对数级别的检查压缩为常数时间。  
- **适用的题型**：  
  1. 判断是否为 2 的次方（同理可用 `INT_MAX & (INT_MAX - 1)` 或最大 2 的次方取模）  
  2. 判断是否为 5 的次方（使用最大 5 的次方取模）  
  3. 判断是否为某个固定底数的次方，只要在题目限制的整数范围内能找到对应的最大幂。  
- **一句话总结**：**“把能整除的最大幂当作‘金标准’，只要能被它整除，就一定是对应底数的次方”。**

---

## 反思

- **第一反应**：直接用循环或递归不停除以 3，检查余数是否为 0。  
- **最容易踩的坑**：  
  - 忽略了 `n <= 0` 的情况，导致负数或 0 被误判为 true。  
  - 使用浮点数的 `log` 或 `pow` 可能产生精度误差，尤其是大数时会出现错误结果。  
- **下次类似题的第一步**：先思考「在给定整数范围内，是否存在一个固定的最大幂」——如果能找到，就尝试用“最大幂能否整除”来直接判断。这样往往能把时间复杂度从对数降到常数。
