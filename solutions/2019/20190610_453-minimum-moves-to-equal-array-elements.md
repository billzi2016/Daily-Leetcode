# #453. 最小移动次数使数组元素相等 / Minimum Moves to Equal Array Elements

> 难度：中等 · 标签：Array、Math · [LeetCode 链接](https://leetcode.com/problems/minimum-moves-to-equal-array-elements/)

---

## 题目（英文原版）

**Description**

Given an integer array nums of size n, return the minimum number of moves required to make all array elements equal.
In one move, you can increment n - 1 elements of the array by 1.

**Examples**

**Example 1:**

```
Input: nums = [1,2,3]
Output: 3
Explanation: Only three moves are needed (remember each move increments two elements):
[1,2,3]  =>  [2,3,3]  =>  [3,4,3]  =>  [4,4,4]
```

**Example 2:**

```
Input: nums = [1,1,1]
Output: 0
```

**Constraints**

- n == nums.length
- 1 <= nums.length <= 105
- -109 <= nums[i] <= 109
- The answer is guaranteed to fit in a 32-bit integer.

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**一次一次地执行题目要求的操作**，直到所有元素相等为止。  
- 每一步我们挑选当前数组中最大的那个元素（或者随便挑选 n‑1 个），把其它 n‑1 个元素都加 1。  
- 重复这个过程，直到数组里所有数都相同。

可以把这个过程想象成**把一堆水倒进杯子**：每次我们把水倒进除最满的杯子之外的所有杯子，直到所有杯子装的水量相等。  
因为每一步都在让“较小的数”赶上“较大的数”，最终一定会收敛到同一个值（虽然可能会很慢）。

**为什么这个方法一定能得到答案？**  
只要还有两个数不相等，就一定可以通过一次“把 n‑1 个数都加 1”让最小的数变大，逐步把所有数拉向同一个高度。只要不停地这样做，最终所有数都会相等。

**时间/空间复杂度**  
- 时间复杂度：每次操作都要遍历整个数组找最大值（O(n)），而最多需要执行 `max(nums) - min(nums)` 次（即最高数与最低数的差距）才能让最小数赶上最大数。最坏情况下，这个差距可能是 2·10⁹（题目给出的数值范围），所以时间复杂度是 **O(n · Δ)**，这里的 Δ 表示数组最大值与最小值的差。可以粗略写成 **O(n·range)**，在大数据下会非常慢。  
- 空间复杂度：只用了常数个额外变量，**O(1)**。

#### 代码（Python）

```python
def min_moves_brute(nums):
    """
    暴力模拟：每次把除最大值所在位置之外的所有元素都加 1，
    直到数组全部相等。
    """
    moves = 0                     # 记录已经进行的步数
    n = len(nums)

    while len(set(nums)) != 1:    # 当数组中还有不相等的数时继续
        # 找出当前的最大值（可以理解为“最满的杯子”）
        cur_max = max(nums)

        # 把除最大值之外的所有元素都加 1
        for i in range(n):
            if nums[i] != cur_max:   # 不是最大值的就加 1
                nums[i] += 1

        moves += 1               # 完成一次操作
    return moves
```

> **提示**：这段代码只适合用来验证思路，实际提交会因为超时而被判为错误。

#### 复杂度

- **时间复杂度**：`O(n·Δ)`，其中 `Δ = max(nums) - min(nums)`。  
  大白话：如果数组里最大的数比最小的数相差 1000，且数组长度是 10，那么最坏情况下要跑 10 × 1000 = 10 000 次循环。
- **空间复杂度**：`O(1)`，只用了几个计数器和临时变量。

### 2. 最优解

#### 思路  

从暴力解可以看到，**每一步都在把 n‑1 个数加 1**，等价地可以把**唯一没有加 1 的那个数想象成被减 1**。  
换句话说：

> “把 n‑1 个数都加 1”  ⇔  “把剩下的 1 个数减 1”

如果我们把每一次的 “减 1” 操作都记下来，最后所有数相等的目标其实是让所有数 **都降到最小的那个数**。  

**关键观察**：  
- 只要把每个元素都降到最小值 `min(nums)`，所有元素自然相等。  
- 对于每个元素 `x`，把它降到 `min` 需要 `x - min` 次 “减 1”。  
- 把所有元素的 “减 1” 次数加起来，就是答案。

于是答案可以直接用 **数学公式** 计算：

```
answer = Σ (nums[i] - min(nums))   for i = 0 … n-1
       = Σ nums[i] - n * min(nums)
```

这一步不需要任何循环模拟，只需要一次遍历求和和一次求最小值。

**为什么等价？**  
把 n‑1 个数加 1 的操作本质上是把“被排除的那一个数”相对其他数“下降”了 1。连续多次这样做，等价于把每个数相对于最小值的差距一次次“消除”。所以总的步数恰好是所有差距的和。

#### 代码（Python）

```python
def min_moves(nums):
    """
    最优解：把所有元素都降到最小值所需的总步数。
    公式：answer = sum(nums) - n * min(nums)
    """
    total = sum(nums)          # 所有元素的和
    mn = min(nums)             # 数组中的最小值
    n = len(nums)              # 元素个数

    # 根据推导的公式直接计算答案
    return total - n * mn
```

#### 复杂度

- **时间复杂度**：`O(n)`。只需要一次遍历求和和一次遍历求最小值（Python 的 `sum` 和 `min` 各是 O(n)），合在一起仍是线性时间。  
  大白话：如果数组有 100 000 个数，只要走一遍，就能算出答案。
- **空间复杂度**：`O(1)`。只用了几个整数变量，不会随输入规模增长而占用更多内存。

## 心得

- **核心技巧**：把 “把 n‑1 个数加 1” 转换为 “把唯一未加的数减 1”，进而用 **求和 + 最小值** 的数学式直接得到答案。  
- **适用的题型**：  
  1. 需要把数组所有元素变成相同值的题目（如 “让数组相等的最小操作数”）。  
  2. 通过“整体增/整体减”转化为“单个元素的差距求和” 的问题（如 “使数组所有元素相同的最少操作次数”）。  
  3. 需要利用 **前缀和/总和** 与 **最值** 关系求解的计数题。  
- **一句话总结**：**把增 n‑1 的操作等价为减 1，再把所有差距加起来即可**。

## 反思

- **第一反应**：看到“每次可以把 n‑1 个数加 1”，第一时间会想到直接模拟，甚至尝试 BFS/DFS。  
- **最容易踩的坑**：  
  - 忘记把 “加 1” 转化为 “减 1”，导致思路卡住。  
  - 忽视负数的情况：公式同样适用，因为最小值可能是负数，`sum - n*min` 仍然是正整数。  
  - 误以为需要把所有数加到最大值，而实际上是把所有数“降到最小值”。  
- **下次遇到同类题**，第一步应该思考：“这类‘一次操作影响多数元素’的题，能否把它转换为‘单个元素的变化’”，进而寻找 **总和 / 最值** 之类的直接公式。
