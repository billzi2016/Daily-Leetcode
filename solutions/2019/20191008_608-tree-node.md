## 题目（英文原版）

**Description**

Table: Tree
Each node in the tree can be one of three types:
Write a solution to report the type of each node in the tree.
Return the result table in any order.
The result format is in the following example.
Note: This question is the same as  3054: Binary Tree Nodes.

**Examples**

**Example 1:**

```
+-------------+------+
| Column Name | Type |
+-------------+------+
| id          | int  |
| p_id        | int  |
+-------------+------+
id is the column with unique values for this table.
Each row of this table contains information about the id of a node and the id of its parent node in a tree.
The given structure is always a valid tree.
```

**Example 2:**

```
Input: 
Tree table:
+----+------+
| id | p_id |
+----+------+
| 1  | null |
| 2  | 1    |
| 3  | 1    |
| 4  | 2    |
| 5  | 2    |
+----+------+
Output: 
+----+-------+
| id | type  |
+----+-------+
| 1  | Root  |
| 2  | Inner |
| 3  | Leaf  |
| 4  | Leaf  |
| 5  | Leaf  |
+----+-------+
Explanation: 
Node 1 is the root node because its parent node is null and it has child nodes 2 and 3.
Node 2 is an inner node because it has parent node 1 and child node 4 and 5.
Nodes 3, 4, and 5 are leaf nodes because they have parent nodes and they do not have child nodes.
```

**Example 3:**

```
Input: 
Tree table:
+----+------+
| id | p_id |
+----+------+
| 1  | null |
+----+------+
Output: 
+----+-------+
| id | type  |
+----+-------+
| 1  | Root  |
+----+-------+
Explanation: If there is only one node on the tree, you only need to output its root attributes.
```

## 题目（中文翻译）

**描述**  
表：`Tree`  
树中的每个节点可以属于以下三种类型之一：  
- **Root**（根节点）  
- **Inner**（内部节点）  
- **Leaf**（叶子节点）  

请编写一个查询，报告树中每个节点的类型。返回的结果表可以任意顺序。结果格式参见下方示例。

> 注：本题与 3054: Binary Tree Nodes 完全相同。

|-------------|------|
| id          | int  |
| p_id        | int  |

`id` 为唯一标识列。每一行记录了树中一个节点的 `id` 以及其父节点的 `id`（列名 `p_id`）。给定的结构必然构成一棵合法的树。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

这道题的本质是 **把每个节点按照“根 / 内部 / 叶子”三类进行分类**。  
我们只有一张表 `Tree(id, p_id)`，其中  

- `id` 表示节点的唯一编号  
- `p_id` 表示该节点的父节点编号，根节点的 `p_id` 为 `null`

最直接、最笨的想法是：**对每一个节点，都遍历整张表去检查它是否出现在别人的 `p_id` 列里**。  
如果出现过，说明它有子节点；如果 `p_id` 为 `null`，说明它是根；否则它是叶子。  

> 类比：把 `p_id` 看成一本“父亲字典”，查询 “我的编号是否出现在字典的页码里”。暴力解就是把每本书的每一页都翻一遍。

这个方法之所以一定能得到正确答案，是因为题目保证了结构是合法树，**只要能准确判断“有没有子节点”和“父节点是否为空”，分类就唯一**。

#### 代码（Python）

```python
from typing import List, Tuple

def classify_nodes_bruteforce(rows: List[Tuple[int, int]]) -> List[Tuple[int, str]]:
    """
    暴力解：对每个节点 O(n) 地遍历整张表判断是否是父节点
    参数 rows: [(id, p_id), ...]，p_id 为 None 表示 null
    返回: [(id, type), ...]，type 为 "Root"/"Inner"/"Leaf"
    """
    result = []
    for cur_id, cur_pid in rows:               # 对每个节点遍历一次
        has_child = False                       # 标记是否有子节点
        for _, parent in rows:                  # 再遍历一次整张表找子节点
            if parent == cur_id:                # 只要有一行的 p_id == cur_id，就说明有子节点
                has_child = True
                break
        # 根据是否为根、是否有子节点决定类型
        if cur_pid is None:                     # 根节点：父节点为空
            node_type = "Root"
        elif has_child:                         # 有父节点且有子节点 → 内部节点
            node_type = "Inner"
        else:                                   # 有父节点且没有子节点 → 叶子节点
            node_type = "Leaf"
        result.append((cur_id, node_type))
    return result
```

#### 复杂度

- **时间复杂度**：`O(n²)`  
  解释：对每个节点（`n` 次）都要遍历整张表（又是 `n` 次），所以总操作数大约是 `n * n`，这就是所谓的二次方复杂度。  
  用生活中的例子说，就是“如果有 1000 个小朋友，每个人都要和全部 1000 个人握手”，显然会很慢。

- **空间复杂度**：`O(1)`（不计输出）  
  只用了常数级的额外变量 `has_child`、`node_type`，不随 `n` 增长。

### 2. 最优解

#### 思路  

暴力解的瓶颈在 **“每个节点都要遍历一次整张表去找子节点”**，这一步导致了 `O(n²)`。  
实际上我们只需要 **一次遍历** 就能知道哪些 `id` 出现在 `p_id` 列里——这正是 **集合（Hash Set）** 的用武之地。

优化步骤：

1. **第一次遍历**：  
   - 把所有出现过的 `p_id`（除 `null`）收集到一个集合 `parents` 中。  
   - 同时记录每个 `id` 对应的 `p_id`，方便后面判断根节点。  

   > 类比：把所有“父亲的编号”放进一本“快速查找的字典”，以后想知道某个编号是否是父亲，只要查一次字典（哈希表）就能得到答案，时间几乎是常数 `O(1)`。

2. **第二次遍历**（或者在第一次遍历的同时完成）：  
   - 对每个节点判断：  
     - `p_id is None` → **Root**  
     - `id in parents` → **Inner**（说明它是别人的父亲）  
     - 否则 → **Leaf**  

这样只需要 **一次（或两次）线性遍历**，时间复杂度降到 `O(n)`，空间使用一个集合 `O(n)`。

#### 代码（Python）

```python
from typing import List, Tuple

def classify_nodes_optimal(rows: List[Tuple[int, int]]) -> List[Tuple[int, str]]:
    """
    最优解：利用集合一次遍历找出所有出现过的父节点 id
    返回同样的 (id, type) 列表
    """
    # 第一步：收集所有出现过的父节点 id（除 None）
    parents = set()                # 哈希集合，查找 O(1)
    id_to_pid = {}                 # 记录每个节点的父节点，后面判断根节点用

    for node_id, parent_id in rows:
        id_to_pid[node_id] = parent_id
        if parent_id is not None:          # 只把真实的父节点加入集合
            parents.add(parent_id)

    # 第二步：根据父节点集合和是否为根来确定类型
    result = []
    for node_id, parent_id in rows:
        if parent_id is None:               # 没有父节点 → 根
            node_type = "Root"
        elif node_id in parents:            # 作为别人的父节点出现 → 内部节点
            node_type = "Inner"
        else:                               # 有父节点但自己不是任何人的父节点 → 叶子
            node_type = "Leaf"
        result.append((node_id, node_type))

    return result
```

#### 复杂度

- **时间复杂度**：`O(n)`  
  解释：我们只对表进行一次（或两次）线性遍历，每次操作都是常数时间。  
  与暴力解相比，从“每个人都要和所有人握手”降到“每个人只需要查一次字典”，快了很多。

- **空间复杂度**：`O(n)`  
  需要一个集合 `parents`（最多存 `n-1` 个父节点）以及一个字典 `id_to_pid` 保存原始映射，随输入规模线性增长。  
  这在大多数实际场景下是可以接受的。

---

## 心得

- **核心技巧**：利用哈希集合（或字典）一次遍历记录“出现过的父节点”，从而在 `O(1)` 时间内判断一个节点是否有子节点。  
- **适用的题型**  
  1. **节点分类**（根、内部、叶子）——本题  
  2. **找出孤立节点**（既不是父也不是子）  
  3. **统计出现次数或出现关系**（如找出出现过的子节点、父子配对等）  
- **一句话总结**：`“把所有父节点收集进哈希表，一遍遍历搞定分类”`。

## 反思

- **第一反应**：看到 `id`、`p_id`，马上想到“父子关系”，于是想到要判断每个节点是否出现在别人的 `p_id` 中。  
- **最容易踩的坑**  
  - **空指针（null）处理**：根节点的 `p_id` 为 `null`，在 Python 中要用 `None` 判断，别把 `None` 也加入集合。  
  - **只有一个节点的极端情况**：此时 `parents` 为空，仍然要正确返回 `Root`。  
  - **重复判断**：如果在第一次遍历里就把 `node_type` 决定好，就不需要第二遍，注意不要在两遍里都做同样的判断导致逻辑冲突。  
- **下次遇到同类题**：第一步先 **把关系映射到哈希结构**（集合/字典），再根据这些结构进行一次线性分类。这样既直观又高效。
