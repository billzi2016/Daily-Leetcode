# #368. 最大可整除子集 / Largest Divisible Subset

> 难度：中等 · 标签：Array、Math、Dynamic Programming、Sorting · [LeetCode 链接](https://leetcode.com/problems/largest-divisible-subset/)

---

## 题目（英文原版）

**Description**

Given a set of distinct positive integers nums, return the largest subset answer such that every pair (answer[i], answer[j]) of elements in this subset satisfies:
If there are multiple solutions, return any of them.

**Examples**

**Example 1:**

```
Input: nums = [1,2,3]
Output: [1,2]
Explanation: [1,3] is also accepted.
```

**Example 2:**

```
Input: nums = [1,2,4,8]
Output: [1,2,4,8]
```

**Constraints**

- 1 <= nums.length <= 1000
- 1 <= nums[i] <= 2 * 109
- All the integers in nums are unique.

---

## 题目（中文翻译）

给定一个由互不相同的正整数构成的集合 `nums`，返回其中的最大子集 `answer`，使得该子集中的任意一对元素 `(answer[i], answer[j])` 都满足 **其中一个能够被另一个整除**（即 `answer[i] % answer[j] == 0` 或 `answer[j] % answer[i] == 0`）。  
如果存在多个满足条件的最大子集，返回任意一个即可。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**枚举所有子集**，检查每个子集是否满足“任意两个数互相整除”的条件，记录最大的合法子集并返回。

- **子集**可以想象成装满水果的篮子，我们把原数组的每个元素看成一种水果。遍历所有可能的装法（即所有子集），看哪个篮子里的水果两两之间都有“可以直接吃掉对方”的关系（整除关系），且水果最多。
- 为了检查一个子集是否合法，我们需要两层循环：取子集里的每一对元素，判断 `a % b == 0` 或 `b % a == 0`。这一步类似于在字典里查词：把每个数当成“词”，它能否“解释”成另一个数（整除）就像看词典里是否有对应的解释。

**为什么这个方法一定能得到答案？**  
因为我们把**所有可能的组合**都穷举一遍，只要有满足条件的最大子集，必然会在遍历过程中被发现。

#### 代码（Python）

```python
from itertools import combinations

def largestDivisibleSubset_bruteforce(nums):
    n = len(nums)
    best = []                         # 当前找到的最大合法子集
    # 由于子集的大小从大到小检查可以提前剪枝，这里先遍历所有子集大小
    for size in range(n, 0, -1):      # 从 n、n-1、...、1
        # 生成所有 size 个元素的组合
        for subset in combinations(nums, size):
            # 检查子集是否满足“任意两数互相整除”
            ok = True
            # 两层循环枚举子集中的每一对
            for i in range(size):
                for j in range(i + 1, size):
                    a, b = subset[i], subset[j]
                    if a % b != 0 and b % a != 0:
                        ok = False      # 只要有一对不满足，整个子集不合法
                        break
                if not ok:
                    break
            if ok:                     # 找到合法子集，直接返回（因为是从大到小遍历的）
                return list(subset)
    return best                      # 只在输入为空时到达这里
```

#### 复杂度  

- **时间复杂度**：  
  - 枚举所有子集的数量是 `2^n`（每个元素要么选要么不选），相当于把所有水果的装法都尝试一遍。  
  - 对每个子集我们还要检查 `O(k^2)`（k 为子集大小）的两两整除关系。最坏情况下 `k ≈ n`，所以整体是 `O(2^n * n^2)`。  
  - 大白话：如果 `n=20`，可能要检查上百万个子集，已经很慢了。

- **空间复杂度**：  
  - 递归生成子集时需要 `O(n)` 的栈空间（Python 的 `combinations` 内部也会用到临时列表），总体是 `O(n)`。  
  - 这在我们只保存当前子集的情况下可以接受。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**枚举所有子集**，这导致指数级的时间。我们需要利用题目给出的“整除”这一数学特性，把搜索空间大幅压缩。

1. **排序**  
   把数组从小到大排好序。排序后，如果 `a` 能整除 `b` 并且 `a < b`，那么 `a` 必然在 `b` 的左边。这样，**每个数只需要考虑左边比它小的数**，不必再去检查右边的数。

2. **动态规划（DP）**  
   对排好序的数组 `nums[i]`（第 i 个数），我们记录以它为**子集最大元素**的最长可除子集长度 `dp[i]`，以及前驱指针 `prev[i]`（指向子集中前一个元素的下标），用来在结束后重建子集。  
   - 初始化：每个数单独成子集，长度为 1，前驱为 `-1`（无前驱）。  
   - 转移：遍历 `j < i`，如果 `nums[i] % nums[j] == 0`（`j` 能整除 `i`），并且 `dp[j] + 1 > dp[i]`，就把 `dp[i]` 更新为 `dp[j] + 1`，`prev[i] = j`。  
   - 这一步相当于“把 `nums[i]` 接在已经最长的、能够被它整除的子集后面”。  

3. **找最大**  
   扫描 `dp`，找到最大值对应的下标 `max_idx`，然后沿 `prev` 链向前回溯，得到完整的子集（逆序），再翻转即可。

**核心概念解释**  

- **动态规划**：把大问题拆成很多小的、相似的子问题，先解小的再合成大的。这里每个 `dp[i]` 就是“以第 i 个数为结尾的最优子问题”。  
- **前驱指针**：想象每个数是链条上的一个环，`prev[i]` 记录了这个环前面应该接哪个环，最终把所有环按指针顺序串起来就得到答案。  
- **排序的意义**：把所有可能的“前一个数”都搬到左边，避免了在右边寻找可以整除的数，降低了搜索范围。

#### 代码（Python）

```python
def largestDivisibleSubset(nums):
    """
    返回 nums 中最大的可除子集（任意两数互相整除）。
    思路：先排序 + 动态规划 + 前驱指针重建答案。
    """
    if not nums:
        return []

    # 1. 排序，让小的数在前面，方便只向左检查
    nums.sort()
    n = len(nums)

    # dp[i]：以 nums[i] 为子集最大元素时，子集的最大长度
    dp = [1] * n               # 每个数单独成子集，长度 1
    prev = [-1] * n            # 前驱下标，-1 表示没有前驱

    max_len = 1                # 当前找到的最长长度
    max_idx = 0                # 对应的下标

    # 2. 动态规划转移
    for i in range(1, n):
        for j in range(i):
            if nums[i] % nums[j] == 0:               # j 能整除 i
                if dp[j] + 1 > dp[i]:                # 通过 j 能得到更长的子集
                    dp[i] = dp[j] + 1
                    prev[i] = j
        # 更新全局最长
        if dp[i] > max_len:
            max_len = dp[i]
            max_idx = i

    # 3. 通过前驱指针恢复子集（从大到小逆序）
    res = []
    cur = max_idx
    while cur != -1:
        res.append(nums[cur])
        cur = prev[cur]

    # 逆序得到从小到大的子集（题目没有顺序要求，但这样更直观）
    res.reverse()
    return res
```

#### 复杂度  

- **时间复杂度**：`O(n^2)`  
  - 外层遍历 `i`（`n` 次），内层遍历 `j`（最多 `i` 次），每次只做一次取模运算和几条常数时间的比较。  
  - 大白话：如果 `n=1000`，最多进行约 `1,000,000` 次运算，现代电脑几毫秒就能跑完。

- **空间复杂度**：`O(n)`  
  - 需要 `dp`、`prev` 两个长度为 `n` 的数组，以及最终的答案列表。  
  - 与暴力解的 `O(2^n)` 空间相比，线性空间是完全可以接受的。

## 心得

- **核心技巧**：先排序再用动态规划求最长可除子集。排序把“只能向左看”的约束显式化，DP 把“把当前数接在已有最优子集后面”的递推过程自动化。
- **适用的题型**  
  1. **最长递增子序列（LIS）** – 与本题几乎相同的 DP 思路，只是比较 `<` 而不是整除。  
  2. **最长公共子序列（LCS）** – 同样是 DP 的子序列类问题。  
  3. **最大递增子数组（Maximum Width Ramp）** – 需要排序+单调栈的思路，也属于“利用顺序约束”来降低复杂度的例子。
- **一句话总结解题钥匙**：**“把所有可能的前驱都排到左边，然后用 DP 按顺序挑选最优前驱”。**

## 反思

- **第一反应**：直接想到枚举子集检查合法性，导致指数级时间。  
- **最容易踩的坑**  
  - **忘记排序**：如果不排序，`dp` 转移时需要检查所有两两关系，仍是 `O(n^2)`，但更难保证正确性（因为可能出现后面的数比前面的数小，却仍能整除）。  
  - **前驱指针遗漏**：只记录最长长度而不记录前驱，最后无法恢复具体的子集，只能返回长度。  
  - **边界条件**：空数组或只有一个元素时，需要直接返回空列表或该元素本身。  
- **下次类似题的第一步**：**先把数据按天然的“顺序关系”（大小、字典序、时间等）排序**，再思考“每个位置的最优子结构”是否可以用 DP、双指针或单调栈来高效求解。
