# #409. **最长回文串** / Longest Palindrome

> 难度：简单 · 标签：Hash Table、String、Greedy · [LeetCode 链接](https://leetcode.com/problems/longest-palindrome/)

---

## 题目（英文原版）

**Description**

Given a string s which consists of lowercase or uppercase letters, return the length of the longest palindrome that can be built with those letters.
Letters are case sensitive, for example, "Aa" is not considered a palindrome.

**Examples**

**Example 1:**

```
Input: s = "abccccdd"
Output: 7
Explanation: One longest palindrome that can be built is "dccaccd", whose length is 7.
```

**Example 2:**

```
Input: s = "a"
Output: 1
Explanation: The longest palindrome that can be built is "a", whose length is 1.
```

**Constraints**

- 1 <= s.length <= 2000
- s consists of lowercase and/or uppercase English letters only.

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**把所有字符的排列全部列出来，检查每一个排列是不是回文**，把最长的那一个记下来。  
- 这里用到的“排列”可以想象成把字母一个一个放进不同的格子里，所有可能的放法都尝试一遍。  
- 判断回文很简单：从左往右和从右往左对应的字符要相等，就像看镜子里的文字，左边的字要和右边的字相同。

为什么这个方法能得到正确答案？因为我们穷举了**所有**可能的字符串，只要有一个是最长的回文，我们一定会在遍历中碰到它。

但请注意，这个办法在实际运行时会非常慢——如果字符串长度是 `n`，所有排列的数量是 `n!`（阶乘），即  
`1 × 2 × 3 × … × n`，随 `n` 增大会几乎瞬间爆炸。

#### 代码（Python）

```python
import itertools

def longest_palindrome_bruteforce(s: str) -> int:
    """
    暴力解：枚举所有字符的排列，找出最长的回文长度。
    只适用于极短的字符串（比如 n <= 6），用于演示思路。
    """
    n = len(s)
    max_len = 0

    # itertools.permutations 会生成所有排列（不去重），每个排列是一个 tuple
    for perm in itertools.permutations(s):
        cand = ''.join(perm)               # 把 tuple 变成字符串
        if cand == cand[::-1]:             # 判断是否回文（逆序相等）
            max_len = max(max_len, len(cand))

    return max_len
```

> **关键行中文注释**  
> - `itertools.permutations(s)`：把字符串的每一种排放方式都列出来。  
> - `cand == cand[::-1]`：`cand[::-1]` 是字符串倒序，若两者相等说明是回文。

#### 复杂度  

- **时间复杂度**：`O(n! * n)`  
  - `n!` 是所有排列的个数，遍历每个排列时还要花 `O(n)` 检查回文。  
  - “阶乘”增长非常快，哪怕 `n = 10` 也已经是 3,628,800 次排列，远远超出题目限制。

- **空间复杂度**：`O(n)`  
  - 主要是存放当前排列的临时字符串 `cand`，长度不超过 `n`。

> **大白话解释**：  
> - 时间复杂度的 `O(n! * n)` 可以理解为“先把所有可能的排法全部列出来（这一步已经很慢），再把每一种排法逐个检查”。  
> - 这跟我们在超市里把所有商品一次性挑出来排成一行，然后再一个个检查是否符合要求的过程差不多——根本不可能在合理时间内完成。

### 2. 最优解

#### 思路  

从暴力解可以看出，**真正需要遍历的是每个字符出现的次数**，而不是所有可能的排列。  
回文的结构很有规律：

1. **对称位置**必须使用相同的字符。例如，左边第 1 位是 `'a'`，右边第 1 位也必须是 `'a'`。这说明字符必须成 **偶数** 次出现，才能完整地放在两边。  
2. **中心位置**（如果回文长度是奇数）可以放 **任意一个出现次数为奇数的字符**，因为它只需要出现一次，不需要配对。

基于上述观察，最优的做法是：

- 统计每个字符出现的次数（这里用 Python 的字典 `dict`，类似“查字典”。键 `key` 是字符，值 `value` 是出现的次数）。  
- 对每个字符的计数 `cnt`：  
  - 能完整配对的部分是 `cnt // 2 * 2`（即向下取偶数），这些字符都可以放在回文的左右两侧。  
  - 如果还有 **至少一个字符的计数是奇数**，我们可以把其中的 **一个** 放在最中间，整个回文长度就可以再加 1。  

这样只需要一次遍历统计，再一次遍历字典即可得到答案，时间是线性的 `O(n)`，空间是字符种类的数量 `O(1)`（因为字符集固定为大小写英文字母，共 52 种）。

#### 代码（Python）

```python
def longest_palindrome(s: str) -> int:
    """
    最优解：利用字符出现次数的奇偶性，贪心构造最长回文。
    思路：
    1. 用字典统计每个字符出现的次数（哈希表）。
    2. 对每个计数，取最大的偶数部分加入答案。
    3. 若存在奇数计数，则答案再加 1（放在回文中心）。
    """
    # 1️⃣ 统计字符出现次数
    cnt = {}                         # 哈希表：key=字符，value=出现次数
    for ch in s:
        cnt[ch] = cnt.get(ch, 0) + 1   # get 方法像查字典，找不到返回 0

    length = 0          # 当前已确定可以放入回文的字符总数
    odd_found = False  # 是否出现过奇数次的字符

    # 2️⃣ 遍历每种字符的计数，累加偶数部分
    for c in cnt.values():
        if c % 2 == 0:               # 偶数次，全部可以配对
            length += c
        else:                        # 奇数次，去掉一个留下偶数部分
            length += c - 1          # c-1 是最大的偶数
            odd_found = True         # 记录出现了奇数计数

    # 3️⃣ 若有奇数计数，中心可以放一个字符，长度再加 1
    if odd_found:
        length += 1

    return length
```

> **关键行中文注释**  
> - `cnt[ch] = cnt.get(ch, 0) + 1`：把字符出现次数记录在字典里，`get` 方法相当于在字典里查“这个字母的页码”，没有就返回 0。  
> - `c - 1`：把奇数次的字符“去掉一个”，剩下的部分就是偶数，能配对放在两侧。  
> - `odd_found`：标记是否出现过奇数次的字符，决定是否需要在中间再加 1。

#### 复杂度  

- **时间复杂度**：`O(n)`  
  - 只遍历字符串一次统计字符次数，再遍历字典（最多 52 项）一次。  
  - “O(n)” 可以理解为“和字符串长度成正比”，如果字符串有 2000 个字符，就大约需要处理 2000 次操作，完全可以在毫秒级完成。

- **空间复杂度**：`O(1)`（常数）  
  - 使用的哈希表最多存 52 条记录（大小写英文字母），不随 `n` 增大而增长。  
  - 因此即使 `n` 很大，额外占用的内存也几乎不变。

> 与暴力解对比：  
> - 暴力解需要遍历所有排列，时间爆炸；最优解只看每个字符出现的次数，线性快速。

## 心得

- **核心技巧**：利用字符出现次数的奇偶性，**贪心**地把能配对的字符放两侧，最多留下一个奇数字符作中心。  
- **适用的题型**：  
  1. “可以使用字符重新排列后得到 …” 的问题（如 **Longest Palindrome**、**Maximum Length of a Concatenated String with Unique Characters**）。  
  2. “统计出现次数后做选择”的贪心题（如 **Can Construct Ransom Note**、**Valid Anagram**）。  
- **一句话总结**：**把所有字符的出现次数先算清楚，偶数全用，奇数最多留一个作中心**，就是最长回文的钥匙。

## 反思

- **第一反应**：看到“最长回文”，立刻想到“回文需要左右对称”，于是想到“相同字符成对出现”。  
- **最容易踩的坑**：  
  - 忘记**大小写敏感**，`'A'` 与 `'a'` 不能混用。  
  - 只统计偶数部分，却忘了**中心只能放一个**奇数字符，导致答案少 1。  
  - 对空字符串或全部奇数字符的情况没有做好边界判断。  
- **下次遇到类似题**：第一步先**统计每个字符出现的次数**，然后**根据奇偶性决定能用多少**，再考虑是否需要额外的中心字符。这样可以快速锁定最优思路。
