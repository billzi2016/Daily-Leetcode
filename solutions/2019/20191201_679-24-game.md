# #679. 24 点游戏 / 24 Game

## 题目（英文原版）

**Description**

You are given an integer array cards of length 4. You have four cards, each containing a number in the range [1, 9]. You should arrange the numbers on these cards in a mathematical expression using the operators ['+', '-', '*', '/'] and the parentheses '(' and ')' to get the value 24.
You are restricted with the following rules:
Return true if you can get such expression that evaluates to 24, and false otherwise.

**Examples**

**Example 1:**

```
Input: cards = [4,1,8,7]
Output: true
Explanation: (8-4) * (7-1) = 24
```

**Example 2:**

```
Input: cards = [1,2,1,2]
Output: false
```

**Constraints**

- cards.length == 4
- 1 <= cards[i] <= 9

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

这道题的本质是**把四个数字用四则运算和括号组合成 24**。  
最直接的想法就是把所有可能的组合都尝试一遍，只要出现一次等于 24 就返回 `True`，否则返回 `False`。  

**要尝试的东西有三类**  

1. **数字的顺序**  
   四张牌可以随意排列，就像把四本书摆在不同的顺序一样。  
   我们可以把所有排列列举出来（4! = 24 种），这一步可以用 `itertools.permutations` 完成。

2. **运算符的选择**  
   每一步把两个数合并，需要挑选一个运算符 `+ - * /`（共 4 种）。  
   把运算符想象成“工具箱”里的工具，每取出一个工具就会产生一个新数。

3. **括号的结构（运算顺序）**  
   四个数要进行三次二元运算，运算顺序决定了括号的摆放方式。  
   直接枚举所有括号的形式比较麻烦，**更巧妙的做法是递归地“取出两个数、算出结果、把结果放回列表”**。  
   这样每递归一次就相当于在表达式里加了一层括号。  
   递归结束时只剩一个数，如果它≈24（考虑浮点数误差），说明找到了合法表达式。

**为什么这个方法一定能找到答案？**  
因为我们把「所有数字顺序」×「所有运算符选择」×「所有运算顺序」都遍历了一遍，等价于把所有可能的完整表达式枚举完了。

**时间/空间复杂度的大白话解释**  

- **时间复杂度**  
  - 对 4 个数来说，先挑 2 个数进行运算，有 `C(4,2)=6` 种取法；每种取法有 4 种运算符。  
  - 计算完后剩下 3 个数，继续挑 2 个，有 `C(3,2)=3` 种取法，仍有 4 种运算符。  
  - 最后只剩 2 个数，只有 `C(2,2)=1` 种取法。  
  - 把这些乘起来再乘以数字的全排列数 `4! = 24`，得到大约 `24 * 6 * 4 * 3 * 4 * 1 * 4 ≈  24 * 384 = 9216` 次递归调用。  
  - 用 **O(1)** 的常数因子描述，就是 **O( n! * 4^{n-1} )**，这里 `n=4`，所以实际运行非常快。  
  - 用大白话说，就是「几千次」的尝试，电脑几毫秒就能跑完。

- **空间复杂度**  
  - 递归深度最多 `n-1 = 3` 层，每层保存一个长度在 4~1 的列表，属于 **O(n)** 的额外空间。  
  - 用大白话说，就是「最多只占几百字节」的内存。

#### 代码（Python）

```python
import itertools
from typing import List

def judgePoint24(cards: List[int]) -> bool:
    # 因为除法会产生小数，使用浮点数并设置容差
    EPS = 1e-6

    # 递归函数：把当前列表里的数全部算完，看看能否得到 24
    def dfs(nums):
        # 只剩一个数时，检查是否接近 24
        if len(nums) == 1:
            return abs(nums[0] - 24) < EPS

        # 任取两个数 i、j（顺序不同会产生不同的运算结果，如 a-b 与 b-a）
        for i in range(len(nums)):
            for j in range(len(nums)):
                if i == j:
                    continue
                # 把除去 i、j 的其余数留下
                rest = [nums[k] for k in range(len(nums)) if k != i and k != j]

                a, b = nums[i], nums[j]

                # 四种运算符的所有可能结果
                candidates = [a + b, a - b, a * b]
                # 除法需要防止除以 0
                if abs(b) > EPS:
                    candidates.append(a / b)

                # 对每个运算结果继续递归
                for val in candidates:
                    if dfs(rest + [val]):   # 把新产生的数放回列表继续算
                        return True
        return False

    # 把四个数的全排列都尝试一次
    for perm in itertools.permutations(cards):
        if dfs(list(perm)):
            return True
    return False
```

#### 复杂度

- **时间复杂度**：`O( n! * 4^{n-1} )`  
  - 对 4 张卡牌来说大约是几千次尝试，实际运行几毫秒。  
  - “n!” 表示所有数字的排列，`4^{n-1}` 表示每一步挑选运算符的可能性。

- **空间复杂度**：`O(n)`  
  - 递归深度最多 `n-1`，每层保存一个长度在 1~n 的列表，随 n 增长线性增加空间。

### 2. 最优解

#### 思路  

从暴力解我们已经知道：**核心瓶颈在于大量重复计算**，尤其是**相同的数集合会被多次递归**。  
例如，对 `[1, 2, 3]` 先算 `1+2=3` 再算 `3*3=9`，与先算 `2+3=5` 再算 `1*5=5`，这两条路径在后面的递归中会产生相同的子问题（只剩两个数的情况）。

**优化思路**：

1. **使用集合/字典记忆化**  
   - 把当前剩余数字（顺序不重要，只关心 multiset）序列化成一个不可变的元组，作为记忆化的键。  
   - 当同样的状态再次出现时，直接返回之前的结果，避免重复搜索。

2. **剪枝**  
   - 当出现除法且除数非常接近 0 时直接跳过，防止无意义的极大或极小数进入后续计算。  
   - 如果当前所有数的最大可能值（比如全部相乘）已经远小于 24，或者最小可能值（全部相除）已经远大于 24，也可以提前返回 `False`（这里因为数字范围小，剪枝效果不明显，但思路值得掌握）。

3. **使用浮点容差统一比较**  
   - 为了避免因为浮点误差导致的错误，所有比较都使用 `abs(x-24) < 1e-6`。

**核心算法**：**带记忆化的递归回溯（Backtracking + Memoization）**。  
它仍然遍历所有可能的运算顺序，但每个**不同的数集合**只会被求解一次，时间大幅下降。对 4 张卡牌而言，差距不明显，但当题目规模扩大时（比如 6 张卡牌），记忆化的优势就非常明显了。

#### 代码（Python）

```python
import itertools
from typing import List, Tuple, Dict

def judgePoint24(cards: List[int]) -> bool:
    EPS = 1e-6
    memo: Dict[Tuple[float, ...], bool] = {}

    def dfs(nums: Tuple[float, ...]) -> bool:
        # 记忆化查表
        if nums in memo:
            return memo[nums]

        # 只剩一个数时直接比较
        if len(nums) == 1:
            memo[nums] = abs(nums[0] - 24) < EPS
            return memo[nums]

        n = len(nums)
        # 任意挑两个数 i、j
        for i in range(n):
            for j in range(n):
                if i == j:
                    continue
                a, b = nums[i], nums[j]
                # 剩下的数（保持原顺序，但顺序不影响结果）
                rest = [nums[k] for k in range(n) if k != i and k != j]

                # 生成本轮所有合法的运算结果
                results = [a + b, a - b, a * b]
                if abs(b) > EPS:          # 防止除以 0
                    results.append(a / b)

                for val in results:
                    # 递归求解，注意把新数加入后要排序成标准形式，便于记忆化
                    new_state = tuple(sorted(rest + [val]))
                    if dfs(new_state):
                        memo[nums] = True
                        return True

        memo[nums] = False
        return False

    # 初始状态：把四个整数转成浮点数并排序，形成唯一的键
    start = tuple(sorted(float(x) for x in cards))
    return dfs(start)
```

#### 复杂度

- **时间复杂度**：`O( M )`，其中 `M` 是所有不同的数集合的数量。  
  - 对 4 张卡牌，`M` 最多是 `4! * 4^{3} = 384`（比暴力的 9216 次递归大幅下降），实际更少因为记忆化合并了重复状态。  
  - 相比暴力的 `O(n! * 4^{n-1})`，这里的常数更小，且随 `n` 增大时增长幅度明显更慢。

- **空间复杂度**：`O(M)` 用于记忆化表 + 递归栈 `O(n)`。  
  - 记忆化表存储每一种不同的状态（数集合），最坏也只会是几百条记录，空间开销仍然很小。

## 心得

- **核心技巧**：**回溯 + 记忆化（Memoization）**，即在遍历所有可能的同时，把已经算过的子问题缓存起来，避免重复计算。  
- **该技巧适用的题型**  
  1. “24 Game” 这类需要任意组合运算符的表达式求值问题。  
  2. “Expression Add Operators” （在数字串中插入运算符使结果等于目标值）。  
  3. “Word Break” / “Palindrome Partitioning” 等需要把序列划分成子块并递归求解的题目。  
- **一句话总结解题钥匙**：**“把每一步的状态抽象出来，记下来，防止走回头路”。**

## 反思

- **第一反应**：看到“4 张卡牌、四则运算、括号”，立刻想到枚举所有运算顺序和运算符的组合，写递归把两个数合并一次的回溯。  
- **最容易踩的坑**  
  1. **浮点误差**：直接比较 `== 24` 会因为除法产生的微小误差导致错误，需要设定容差。  
  2. **除以 0**：除法时必须判断除数是否接近 0，否则会抛异常或得到极大数。  
  3. **状态去重**：如果不把剩余数排序，就会把 `[1,2]` 和 `[2,1]` 视为不同状态，记忆化失效。  
- **下次遇到同类题，第一步该想到**：**先把“取两个数、算出结果、放回列表”这一步写成递归框架，再考虑是否需要记忆化或其他剪枝手段**。这样既能保证完整枚举，又能在后面根据具体规模决定是否做进一步优化。
