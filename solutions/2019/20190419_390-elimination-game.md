# #390. 消除游戏 / Elimination Game

> 难度：中等 · 标签：Math、Recursion · [LeetCode 链接](https://leetcode.com/problems/elimination-game/)

## 题目（英文原版）

**Description**

You have a list arr of all integers in the range [1, n] sorted in a strictly increasing order. Apply the following algorithm on arr:
Given the integer n, return the last number that remains in arr.

**Examples**

**Example 1:**

```
Input: n = 9
Output: 6
Explanation:
arr = [1, 2, 3, 4, 5, 6, 7, 8, 9]
arr = [2, 4, 6, 8]
arr = [2, 6]
arr = [6]
```

**Example 2:**

```
Input: n = 1
Output: 1
```

**Constraints**

- 1 <= n <= 109

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是**把题目描述的过程完整地模拟一遍**：

1. 先生成 `[1, 2, …, n]` 这条递增的数组（把它想象成一排编号的学生）。
2. 按题目要求，从左到右删掉每第二个元素，得到新数组。
3. 接着把方向反过来（从右到左），再删掉每第二个元素。
4. 重复步骤 2、3，直到数组里只剩下一个数。

> **类比**：  
> - **数组** 就像是一条排好队的长队。  
> - **从左到右删** 相当于老师从队首开始报数，报到 2 的同学站出来离开；报到 2 的同学离开后，老师继续往后数。  
> - **方向翻转** 就是老师站到队尾，反方向再报数。

只要把上述过程写成代码，就能得到答案。

#### 代码（Python）

```python
def lastRemaining_bruteforce(n: int) -> int:
    # 1. 生成初始数组
    arr = list(range(1, n + 1))

    # 2. 标记当前删除方向：True 表示左→右，False 表示右←左
    left_to_right = True

    # 3. 循环直到只剩一个元素
    while len(arr) > 1:
        #   a. 根据方向决定遍历顺序
        if left_to_right:
            # 从左到右，每隔一个保留一个
            arr = [arr[i] for i in range(1, len(arr), 2)]
        else:
            # 从右到左，同样每隔一个保留一个
            # 先把数组反过来，按左→右的规则删，再再翻回来
            arr = [arr[i] for i in range(len(arr) - 2, -1, -2)][::-1]

        #   b. 删除完后方向翻转
        left_to_right = not left_to_right

    return arr[0]
```

> **代码要点注释**  
> - `list(range(1, n + 1))` 把 1~n 这段数字装进列表，相当于把所有学生排好。  
> - `left_to_right` 用来记录本轮是从左往右还是从右往左。  
> - 列表推导式 `[arr[i] for i in range(1, len(arr), 2)]` 表示“保留下标为奇数的位置”，因为下标从 0 开始，奇数位置对应的就是每第二个学生。  
> - 右到左的删除先把数组倒序（`[::-1]`），再用同样的左→右规则删，最后再把顺序翻回来。  

#### 复杂度

- **时间复杂度**：`O(n²)`  
  每一次循环都要遍历整条数组并生成新数组。数组长度会逐渐减半，但第一次遍历是 `n`，第二次是 `n/2`，第三次是 `n/4` …… 所以总操作数约为 `n + n/2 + n/4 + … ≈ 2n`，看似是 `O(n)`，但**生成新列表的过程本身是 O(k)**，而 Python 的列表切片和复制在最坏情况下会导致额外的线性开销，整体仍然会超出 `10⁹` 的限制，实际运行会因为频繁的内存分配而非常慢。  
- **空间复杂度**：`O(n)`  
  需要存储当前的数组，最开始是 `n` 个元素。

> **大白话**：  
> - `O(n²)` 可以想象成“如果 n=10⁶，程序要干十万亿次操作”，显然不可接受。  
> - `O(n)` 只需要“和 n 成正比”的操作次数，才是我们想要的。

### 2. 最优解

#### 思路  

暴力解的**瓶颈**在于每一轮都要把整个数组复制一遍。事实上，我们根本不需要真正保存所有的数字，只要关心**“当前剩下的最左边的那个数”**（记作 `head`）以及**每一步间隔**（记作 `step`）就可以了。

**关键观察**：

1. **每轮都会删掉一半的数**，所以间隔 `step` 会翻倍。  
   - 第一次删完后，剩下的数之间相差 `2`（如 `[2,4,6,8]`），所以 `step = 2`。  
   - 再删一次后，间隔变成 `4`，以此类推。

2. **方向交替**：左→右、右←左、左→右……  
   - 当方向是 **左→右** 时，**一定会把最左边的数删掉**，所以 `head` 必须向右移动 `step`。  
   - 当方向是 **右←左** 时，是否会删掉最左边的数取决于当前剩余的元素个数 `remaining` 是否为奇数。  
     - 若 `remaining` 为奇数，最左边的数会被删掉，`head` 同样需要向右移动 `step`。  
     - 若 `remaining` 为偶数，最左边的数会被保留，`head` 不变。

3. **剩余元素个数** 每轮都会除以 2（向下取整），因为每次都删掉一半。

把这些观察组合起来，就得到一个**只用常数空间的迭代公式**：

```
head = 1               # 最左边的数，初始为 1
step = 1               # 当前间隔，初始为 1
remaining = n          # 还剩多少个数
left_to_right = True   # 当前方向

while remaining > 1:
    # 如果是左→右，或者是右←左且剩余个数为奇数
    if left_to_right or remaining % 2 == 1:
        head += step          # 最左边的数向右跳 step

    # 每轮结束后，间隔翻倍，剩余数目减半，方向翻转
    step *= 2
    remaining //= 2
    left_to_right = not left_to_right
```

循环结束时，`head` 就是最后剩下的唯一数字。

> **类比**：  
> 想象一根绳子上挂着编号的灯泡，老师每轮都把每第二盏灯泡拔掉。我们不必记录每盏灯泡的状态，只要记住**最左边还能看到的灯泡是哪盏**，以及**相邻两盏灯泡之间的距离**，每次拔掉一半后，这两个信息就能更新。

#### 代码（Python）

```python
def lastRemaining(n: int) -> int:
    """
    只用 O(1) 额外空间的数学迭代解法
    """
    head = 1          # 当前最左边剩余的数
    step = 1          # 相邻两个剩余数之间的间隔
    remaining = n     # 还剩多少个数
    left_to_right = True   # 当前是左→右还是右←左

    while remaining > 1:
        # 当从左向右删除，或者从右向左且剩余个数为奇数时，
        # 最左边的数会被删除，需要把 head 往右移动 step
        if left_to_right or (remaining % 2 == 1):
            head += step

        # 每轮结束后，间隔加倍，剩余元素减半，方向翻转
        step <<= 1               # step *= 2，左移一位更快
        remaining >>= 1          # remaining //= 2，右移一位更快
        left_to_right = not left_to_right

    return head
```

> **代码要点注释**  
> - `head`：当前最左侧仍在的数字。初始为 `1`，因为最开始的数组左端就是 1。  
> - `step`：相邻两个“存活”数字之间的距离。每删掉一半，距离翻倍，用 `step <<= 1`（相当于 `step *= 2`）实现。  
> - `remaining`：当前还有多少数字。用位运算右移一位实现除以 2。  
> - `left_to_right`：布尔值，记录本轮的删除方向。每轮取反 `not left_to_right`。  

#### 复杂度

- **时间复杂度**：`O(log n)`  
  每次循环把剩余元素数目除以 2，循环次数约为 `log₂ n`（二进制位数）。对 `n = 10⁹` 来说，只需要大约 30 次迭代，几乎可以瞬间得到答案。  
- **空间复杂度**：`O(1)`  
  只用了几个整数变量，和 `n` 的大小无关。

> **对比**：  
> - 暴力解要遍历并复制整个数组，时间是 `O(n²)`，空间是 `O(n)`。  
> - 最优解只需要 `O(log n)` 的时间和 `O(1)` 的额外空间，快得多，也不会因为 `n` 很大而崩溃。

## 心得

- **核心技巧**：利用**递推/数学归纳**把“每轮删半”抽象为 **head、step、remaining、方向** 四个状态的更新。  
- **适用的题型**：  
  1. **Elimination Game**（本题）  
  2. **Josephus Problem**（约瑟夫环）——每隔固定步数删人，求最后幸存者。  
  3. **只保留奇数/偶数位置的序列**（如“从左到右每隔一个保留”）——可以用类似的“间隔翻倍、头部移动”思路快速求解。  
- **一句话总结**：**“只跟踪最左边的数和间隔，方向交替时看奇偶决定是否移动”** 是这类“每轮删半”问题的解题钥匙。

---

## 反思

- **第一反应**：直接把题目描述的过程写成循环，模拟删除。  
- **最容易踩的坑**：  
  - 忘记在 **右向左** 时判断剩余元素的奇偶性，导致 `head` 更新错误。  
  - 处理 `n = 1` 的边界时忘记直接返回 1，程序会进入无限循环。  
  - 使用列表模拟时会因 `n` 大（最高 10⁹）导致内存炸掉。  
- **下次遇到同类题**：  
  1. 先问自己“每轮删掉的比例是多少？”  
  2. “是否只需要关心最左（或最右）的那个数？”  
  3. “方向交替时，是否需要根据奇偶性决定是否移动？”  
  只要回答这三个问题，就能迅速搭建起最优的数学迭代模型。
