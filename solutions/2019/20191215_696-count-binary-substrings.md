# #696. 计数二进制子串 / Count Binary Substrings

> 难度：简单 · 标签：Two Pointers、String · [LeetCode 链接](https://leetcode.com/problems/count-binary-substrings/)

---

## 题目（英文原版）

**Description**

Given a binary string s, return the number of non-empty substrings that have the same number of 0's and 1's, and all the 0's and all the 1's in these substrings are grouped consecutively.
Substrings that occur multiple times are counted the number of times they occur.

**Examples**

**Example 1:**

```
Input: s = "00110011"
Output: 6
Explanation: There are 6 substrings that have equal number of consecutive 1's and 0's: "0011", "01", "1100", "10", "0011", and "01".
Notice that some of these substrings repeat and are counted the number of times they occur.
Also, "00110011" is not a valid substring because all the 0's (and 1's) are not grouped together.
```

**Example 2:**

```
Input: s = "10101"
Output: 4
Explanation: There are 4 substrings: "10", "01", "10", "01" that have equal number of consecutive 1's and 0's.
```

**Constraints**

- 1 <= s.length <= 105
- s[i] is either '0' or '1'.

---

## 题目（中文翻译）

给定一个二进制字符串（binary string）`s`，返回满足以下条件的非空子串（substring）的数量：

- 子串中 `0` 和 `1` 的数量相等；
- 所有的 `0` 与所有的 `1` 在子串中必须是连续成块的（即 `0` 与 `0` 相邻，`1` 与 `1` 相邻）。

出现多次的子串需要按照出现次数分别计数。

**示例 1**  
**输入**: `s = "00110011"`  
**输出**: `6`  
**解释**: 有 6 个满足条件的子串，分别是 `"0011"`, `"01"`, `"1100"`, `"10"`, `"0011"` 和 `"01"`。  
其中一些子串出现了多次，需分别计数。  
注意，`"00110011"` 本身不是有效的子串，因为其中的 `0`（和 `1`）没有全部连续在一起。

**示例 2**  
**输入**: `s = "10101"`  
**输出**: `4`  
**解释**: 有 4 个满足条件的子串，分别是 `"10"`, `"01"`, `"10"` 和 `"01"`。

**约束条件**  
- `1 <= s.length <= 10^5`  
- `s[i]` 只能是 `'0'` 或 `'1'`。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  
最直接的想法是把字符串的所有可能子串都枚举出来，逐个检查它们是否满足：

1. 子串里 **0 与 1 的数量相等**。  
2. 所有的 0 必须是连续的，所有的 1 也必须是连续的（即子串形如 `000111`、`111000`、`01`、`10`…）。

把枚举子串的过程想象成 **“把所有可能的区间都贴在纸上”**，每个区间就是一个子串。  
检查子串是否符合要求时，我们可以用两层循环：

- 外层 `i` 决定子串的左端点；
- 内层 `j` 决定右端点（`j > i`），每次扩展一个字符后，立即判断当前子串是否合法。

要判断是否合法，需要遍历子串一次来统计 0、1 的个数并检查是否出现交叉的情况。这里的 **哈希表**（字典）可以类比为 **“查字典”**：键是字符 `'0'`、`'1'`，值是它们出现的次数。

因为我们会对 **每个子串** 再 **遍历一次**，所以时间会比较久，但思路最清晰，适合作为暴力基准。

#### 代码（Python）

```python
def countBinarySubstrings_brute(s: str) -> int:
    n = len(s)
    ans = 0

    # i 为子串左端点
    for i in range(n):
        # 用来统计子串里 0、1 的出现次数
        cnt = {'0': 0, '1': 0}
        # j 为子串右端点（含）
        for j in range(i, n):
            cnt[s[j]] += 1                 # 把新加入的字符计数

            # 必须保证 0、1 的数量相等且不出现交叉
            # 交叉的意思是：在子串中出现了 0、1、0（或 1、0、1）这种不连续的模式
            # 简单做法是检查子串是否只由两段相同字符组成
            sub = s[i:j+1]
            # 判断是否形如 "000...111..." 或 "111...000..."
            if len(set(sub)) == 2:          # 必须恰好出现 0 与 1 两种字符
                # 找到第一次字符变化的位置
                k = 0
                while k < len(sub) and sub[k] == sub[0]:
                    k += 1
                # 前后两段字符必须相等且长度相同
                if sub[:k] == sub[0] * k and sub[k:] == sub[-1] * (len(sub)-k):
                    if k == len(sub) - k:   # 长度相等才算合法
                        ans += 1
    return ans
```

> **注**：代码里把每个子串 `sub` 再拷贝一次，仅用于演示暴力思路，实际运行会非常慢。

#### 复杂度

- **时间复杂度**：`O(n³)`  
  - 外层 `i` 循环 `n` 次，内层 `j` 循环最多 `n` 次，每次检查子串又要遍历一次（最坏 `O(n)`），于是总体是 `n * n * n`。  
  - 大白话：如果字符串长 1000，程序大约要跑 `1000³ = 10⁹` 步，几乎不可接受。

- **空间复杂度**：`O(1)`（不计存放子串的临时变量）  
  - 只用了常数个计数变量和一个小字典，和字符串长度无关。

### 2. 最优解

#### 思路  

从暴力解可以看到 **瓶颈** 在于：

1. **大量重复遍历**：同一段连续的 `0` 或 `1` 被多次扫描。
2. **检查子串合法性时的全局遍历**：每次都要重新遍历子串。

其实，题目只要求 **“相邻的两段相同字符且长度相等”** 的子串。  
我们可以先把原字符串 **压缩成连续块的长度序列**，例如：

```
s = "001110011"
块长度序列 = [2, 3, 2, 2]   # 2个0, 3个1, 2个0, 2个1
```

只要相邻两块的长度分别为 `a`、`b`，那么满足条件的子串数量就是 `min(a, b)`，因为：

- 取 `k = 1 … min(a, b)`，每个 `k` 都对应一种合法子串  
  （例如 `a=3, b=2` → 子串 "0011"（k=2）和 "01"（k=1））

于是**核心思路**：

1. **一次遍历** 把每个连续字符块的长度记录下来（相当于把“跑步的距离”压缩成“每段跑多长”。）  
   - 这里可以用 **双指针**：`prev_len` 记录前一块的长度，`curr_len` 记录当前块的长度。
2. 当遇到新块时，**立刻** 用 `min(prev_len, curr_len)` 累加答案，然后把 `prev_len ← curr_len`，继续统计下一个块。

整个过程只需要一次线性扫描，既不需要额外的哈希表，也不需要保存全部块，只保留最近的两个长度即可。

#### 代码（Python）

```python
def countBinarySubstrings(s: str) -> int:
    """
    统计满足条件的二进制子串数量。
    思路：一次遍历统计相邻块的长度，用 min(prev, cur) 累加答案。
    """
    ans = 0          # 最终答案
    prev_len = 0     # 前一段相同字符的长度
    cur_len = 1      # 当前段的长度，先把第一个字符算进去

    # 从第二个字符开始遍历
    for i in range(1, len(s)):
        if s[i] == s[i - 1]:
            # 与前一个字符相同，继续扩大当前块
            cur_len += 1
        else:
            # 突然换成另一种字符，当前块结束
            ans += min(prev_len, cur_len)   # 计算 prev 与 cur 的贡献
            prev_len = cur_len               # 把当前块变成前一块
            cur_len = 1                      # 新块重新计数，从当前字符开始

    # 循环结束后，还会剩下最后一块，需要再算一次
    ans += min(prev_len, cur_len)
    return ans
```

**关键行解释**：

- `cur_len += 1`：相当于 **“跑步时继续往前走”**，把同一种字符的连续长度累加。
- `ans += min(prev_len, cur_len)`：**“两段相邻的跑道中，最短的那段决定可以拼出多少合法子串”**。
- 循环结束后再加一次，是因为最后一次切换时已经把 `prev_len` 记录好了，但 `cur_len` 仍未与后面的块比较。

#### 复杂度

- **时间复杂度**：`O(n)`  
  - 只遍历一次字符串，`n` 为字符串长度。  
  - 大白话：如果有 100,000 个字符，只需要大约 100,000 步就能得到答案，几乎是即时的。

- **空间复杂度**：`O(1)`  
  - 只用了常数个整数变量（`ans, prev_len, cur_len`），不随 `n` 增长。

## 心得

- **核心技巧**：把问题转化为“相邻块的长度”再求最小值的求和。  
- **适用的题型**：
  1. “连续子数组/子串长度相等” 类似题，如 **LeetCode 696 – Count Binary Substrings**（本题）  
  2. “统计相邻相同字符块” 的题目，如 **LeetCode 696** 的变体 “Longest Awesome Substring”  
  3. “相邻区间满足某种关系” 的题目，例如 **LeetCode 1121 – Divide Array Into Three Parts With Equal Sum**（思路相似的分块计数）

- **一句话总结解题钥匙**：**“把连续相同字符压缩成长度序列，答案就是相邻两段长度的最小值之和”。**

## 反思

- **第一反应**：直接枚举所有子串并逐个检查，想要把所有可能都列出来再筛选。
- **最容易踩的坑**：
  1. **忘记把最后一段计入答案**——循环结束后仍有一段未与后面的块比较，需要额外 `ans += min(prev_len, cur_len)`。  
  2. **边界条件**：字符串长度为 1 时，没有合法子串，程序仍需返回 0，避免 `prev_len` 未初始化导致错误。  
  3. **字符只有 0/1**，但实现时不应硬编码，只要比较相等即可，保持通用性。

- **下次遇到同类题**：第一步先 **“压缩”** 输入，看看是否能把复杂的子串/子数组关系转化为相邻块的**长度**或**计数**关系，再依据 `min`、`max` 等简单运算求解。这样往往可以把指数级的暴力降到线性时间。
