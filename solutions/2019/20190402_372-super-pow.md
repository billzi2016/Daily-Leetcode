# #372. 超级幂 / Super Pow

> 难度：中等 · 标签：Math、Divide and Conquer · [LeetCode 链接](https://leetcode.com/problems/super-pow/)

---

## 题目（英文原版）

**Description**

Your task is to calculate ab mod 1337 where a is a positive integer and b is an extremely large positive integer given in the form of an array.

**Examples**

**Example 1:**

```
Input: a = 2, b = [3]
Output: 8
```

**Example 2:**

```
Input: a = 2, b = [1,0]
Output: 1024
```

**Example 3:**

```
Input: a = 1, b = [4,3,3,8,5,2]
Output: 1
```

**Constraints**

- 1 <= a <= 231 - 1
- 1 <= b.length <= 2000
- 0 <= b[i] <= 9
- b does not contain leading zeros.

**约束条件**

**示例 1**

**示例 2**

**示例 3**  
Input: `a = 1, b = [4,3,3,8,5,2]`  
Output: `1`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把 **b** 这个「超大整数」先变成普通的整数，然后直接算 `a^b` 再取模。

- **把数组变成整数**  
  `b = [1,0]` 表示十进制数 `10`，我们可以把每一位乘以相应的十的幂相加，类似把「电话号码」写成完整的数字。  

- **直接求幂并取模**  
  Python 的内置函数 `pow(a, b, mod)` 能在 **O(log b)** 的时间里完成 “先快速幂后取模”。  
  所以我们只要把 `b` 转成整数，交给 `pow` 就能得到答案。

> **为什么能对得上？**  
> `pow` 的第三个参数会在每一步乘法后立刻取模，避免了中间数的爆炸。只要我们提供的 `b` 是正确的十进制数，答案一定和题目要求的 `a^b mod 1337` 完全一致。

#### 代码（Python）

```python
from typing import List

def superPow_brute(a: int, b: List[int]) -> int:
    """
    暴力解法：把 b 变成普通整数，再交给 pow 求 (a^b) % 1337
    """
    # 1. 把数组 b 转成十进制整数（类似把电话号码写成完整数字）
    exponent = 0
    for digit in b:                     # 依次遍历每一位
        exponent = exponent * 10 + digit  # 先左移一位，再加上当前位
        # 这里的 exponent 可能会非常大，但 Python 的 int 支持任意精度

    # 2. 使用 Python 内置的快速幂取模函数
    return pow(a, exponent, 1337)       # O(log exponent) 的时间

# 示例
print(superPow_brute(2, [3]))          # 8
print(superPow_brute(2, [1, 0]))       # 1024
print(superPow_brute(1, [4,3,3,8,5,2]))# 1
```

#### 复杂度

- **时间复杂度**：`O(len(b) + log b)`  
  - 把数组转成整数需要遍历一次 `b`，是 `O(len(b))`。  
  - `pow` 的快速幂是 `O(log b)`，这里的 `b` 是转成的十进制整数。  
  - 对于 2000 位的 `b`，`log b` 仍然是几千级别，整体还是可接受的。

- **空间复杂度**：`O(1)`（不计 Python 大整数本身的内部存储）  
  只用了几个常数级的临时变量。

> **大白话解释**：  
> 时间复杂度里的 `O(n)` 表示「随着输入规模 `n` 增大，运行时间会线性增长」。`O(log n)` 则是「每次把问题规模砍掉一半」的速度，远比线性快。

### 2. 最优解

#### 思路  

虽然上面的暴力解在 Python 能跑通，但它把 **b** 完全展开成一个巨大的整数，会占用大量内存（2000 位的十进制整数已经是 10^2000 级别的数），在一些语言里根本不可行。  
我们需要 **在不把 b 完全展开的前提下** 直接算模。

**关键观察**  

把指数拆成「高位」和「低位」：

```
b =  [b0, b1, ..., bk]   (每个 bi 是一位数字)
数值上   b = 10 * (b without last digit) + last_digit
```

于是：

```
a^b = a^(10 * x + y) = (a^x)^10 * a^y
```

其中 `x` 是除去最后一位的指数，`y` 是最后一位（0~9）。  
对模运算取模后仍然成立：

```
a^b mod m = ( (a^x mod m)^10 mod m ) * (a^y mod m) mod m
```

这给了我们递归公式：

```
superPow(a, b) = superPow(a, b_without_last)^10 * a^{last_digit}  (mod 1337)
```

只要能快速算 `a^k mod 1337`（这里的 `k` 最多是 9 或 10），我们就能把 **b** 从右往左逐位「压缩」成答案。  
快速算 `a^k mod m` 用 **快速幂（exponentiation by squaring）**：把指数二进制拆分，每次把当前结果平方再乘以 `a`（如果对应位是 1），并在每一步取模，时间是 `O(log k)`。

**整体算法**  

1. 编写 `pow_mod(x, n, mod)`：返回 `x^n % mod`，使用平方递归/迭代实现。  
2. 编写递归函数 `dfs(b_list)`：  
   - 如果列表为空，返回 1（因为 `a^0 = 1`）。  
   - 弹出最后一位 `last = b_list.pop()`。  
   - 递归求 `partial = dfs(b_list)`，此时 `partial = a^{b_without_last} % 1337`。  
   - 返回 `(pow_mod(partial, 10, 1337) * pow_mod(a, last, 1337)) % 1337`。  
3. 主函数只需要把 `a % 1337` 传进去（因为模数可以先取余），调用 `dfs(b)` 即得答案。

**为什么快**  

- 每一次递归只处理 **一位**，最多 `len(b)` 次（最多 2000 次）。  
- 在每一步只做两次 `pow_mod`，而指数分别是 10 和 `last`（≤9），所以每次的 `pow_mod` 只需要 `O(log 10)` ≈ 4 步。  
- 整体时间就是 `O(len(b) * log 10)`，近似线性 `O(len(b))`，空间只用递归栈 `O(len(b))`（或改成循环可以做到 `O(1)`）。

#### 代码（Python）

```python
from typing import List

MOD = 1337                     # 题目要求的模数

def pow_mod(x: int, n: int, mod: int) -> int:
    """
    快速幂：返回 (x^n) % mod
    使用「平方-乘」的思路，时间 O(log n)
    """
    result = 1
    x %= mod                    # 先把底数取模，防止后面乘太大
    while n > 0:
        if n & 1:               # n 的最低位是 1，就乘一次当前的 x
            result = (result * x) % mod
        x = (x * x) % mod       # 底数翻倍（相当于平方），并取模
        n >>= 1                 # 把 n 右移一位，等价于 n //= 2
    return result

def superPow(a: int, b: List[int]) -> int:
    """
    最优解：递归利用 (a^(10*x + y)) = (a^x)^10 * a^y
    时间 O(len(b))，空间 O(len(b))（递归深度）
    """
    a %= MOD                    # 先把 a 取模，后面都基于这个值

    def dfs(exp_digits: List[int]) -> int:
        """返回 a^{当前列表表示的指数} % MOD"""
        if not exp_digits:      # 空列表表示指数 0
            return 1

        last = exp_digits.pop()                 # 取出最低位 y
        partial = dfs(exp_digits)               # 递归求 a^{x} % MOD
        # (a^x)^10 % MOD
        part_pow10 = pow_mod(partial, 10, MOD)
        # a^y % MOD（y ≤ 9，直接用 pow_mod）
        last_pow = pow_mod(a, last, MOD)

        return (part_pow10 * last_pow) % MOD    # 合并两部分并取模

    # 为了不改变外部传入的列表，这里拷贝一份
    return dfs(b.copy())

# 示例
print(superPow(2, [3]))                 # 8
print(superPow(2, [1, 0]))              # 1024
print(superPow(1, [4,3,3,8,5,2]))       # 1
```

#### 复杂度

- **时间复杂度**：`O(len(b) * log 10)` ≈ `O(len(b))`  
  - 每个数字只被处理一次，内部的 `pow_mod` 只需要 `log 10`（约 4）次乘法。  
  - 与暴力解的 `O(log b)` 相比，**不随指数的大小指数级增长**，而是随位数线性增长。

- **空间复杂度**：`O(len(b))`（递归栈）  
  - 如果改写成循环（把列表倒着遍历），可以降到 `O(1)`。

> **大白话解释**：  
> 暴力解的时间像是「把 10 000 000 000 000 000 的楼层一个一个爬上去」——层数多得吓人。  
> 最优解则是「每次爬 10 层再乘以少量的额外步数」，只跟「楼层数的位数」有关，爬得快多了。

## 心得

- **核心技巧**：把大指数拆成「高位」与「低位」的递归关系，配合 **快速幂**（指数的二进制拆分）完成模运算。  
- **适用场景**：  
  1. **超大指数求模**（如本题 `Super Pow`）。  
  2. **大数乘法取模**（比如求 `(a*b) % m`，但 a、b 本身是超大数）。  
  3. **指数递归**（如 LeetCode 258 `Add Digits` 的类似思路，只是这里是指数）。  
- **一句话总结解题钥匙**：  
  “把指数的每一位单独处理，用 `(a^{x})^{10} * a^{y}` 的递归公式把巨大的幂拆成若干个小幂，再用快速幂在每一步取模。”

## 反思

- **第一反应**：把 `b` 直接拼成一个整数，再用 `pow(a, b, 1337)`。这在 Python 能跑，但在多数语言会因为指数太大导致内存/时间炸裂。  
- **最容易踩的坑**：  
  - 忘记在每一步 **取模**，导致中间乘积爆炸（整数溢出或极慢）。  
  - 递归时直接在原列表上 `pop()`，如果外部还需要原始 `b`，会被破坏。可以先拷贝或改成循环。  
  - `a` 本身可能大于 1337，必须先 `a % 1337`，否则 `pow_mod` 的初始值会不必要地大。  
- **下次遇到同类题**：  
  第一想到的应该是 **“指数位拆分 + 快速幂”**，即把大指数拆成「高位」和「低位」的递归或迭代关系，再配合 `pow_mod` 在每一步取模。这样既安全又高效。
