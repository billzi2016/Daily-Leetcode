# #481. 神奇字符串 / Magical String

> 难度：中等 · 标签：Two Pointers、String · [LeetCode 链接](https://leetcode.com/problems/magical-string/)

---

## 题目（英文原版）

**Description**

A magical string s consists of only '1' and '2' and obeys the following rules:
The first few elements of s is s = "1221121221221121122……". If we group the consecutive 1's and 2's in s, it will be "1 22 11 2 1 22 1 22 11 2 11 22 ......" and the occurrences of 1's or 2's in each group are "1 2 2 1 1 2 1 2 2 1 2 2 ......". You can see that the occurrence sequence is s itself.
Given an integer n, return the number of 1's in the first n number in the magical string s.

**Examples**

**Example 1:**

```
Input: n = 6
Output: 3
Explanation: The first 6 elements of magical string s is "122112" and it contains three 1's, so return 3.
```

**Example 2:**

```
Input: n = 1
Output: 1
```

**Constraints**

- 1 <= n <= 105

## 题目（中文翻译）

神奇字符串 `s` 仅由字符 `'1'` 和 `'2'` 组成，并满足以下规则：

- `s` 的前几位为 `s = "1221121221221121122……"`。  
- 若把 `s` 中相邻的 `'1'` 与 `'2'` 分组，则得到 `"1 22 11 2 1 22 1 22 11 2 11 22 ….."`。  
- 每组中 `'1'` 或 `'2'` 的出现次数依次为 `"1 2 2 1 1 2 1 2 2 1 2 2 ….."`。可以看到，这个出现次数序列正好就是 `s` 本身。

给定整数 `n`，返回神奇字符串 `s` 的前 `n` 个字符中 `'1'` 的个数。

**示例 1**  
Input: `n = 6`  
Output: `3`  
Explanation: 前 6 个字符为 `"122112"`，其中包含三个 `'1'`，因此返回 `3`。

**示例 2**  
Input: `n = 1`  
Output: `1`

**约束条件**  
- `1 <= n <= 10^5`

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  

最直接的想法是 **一步一步把魔法字符串 s 生成出来**，然后在前 `n` 位里统计 `'1'` 的个数。  

- **数据结构**：我们可以用 Python 的 `list` 来保存已经生成的字符（`1` 或 `2`），把它当成一串“纸条”。  
- **生活化类比**：把 `list` 想成一本笔记本，往后面写字符就像在笔记本的下一页写字。  
- **生成规则**：  
  1. 已知前几位是 `"122112..."`，我们把已经写好的字符分成若干**连续相同的块**（比如 `"1"、"22"、"11"`）。  
  2. 这些块的长度（即每块里出现了多少个相同字符）恰好又是字符串本身。  
  3. 因此我们可以先把已经写好的块的长度取出来（这叫**计数序列**），再根据计数序列继续往后写字符。  

- **为什么正确**：计数序列本身就是字符串本身，这正是题目给出的“出现次数的序列就是 s”。只要我们严格遵守“先读计数，再写对应数量的字符”，生成的序列必然满足题目定义。  

- **暴力实现的瓶颈**：每次往后写字符时，都要遍历已经生成的字符串去**重新分块**，这会导致 **重复工作**，时间会呈二次方增长（`O(n²)`），当 `n` 达到 10⁵ 时会超时。  

#### 代码（Python）

```python
def magical_string_bruteforce(n: int) -> int:
    # 1. 用 list 保存已经生成的字符，初始已知的前 3 位
    s = [1, 2, 2]                     # 对应 "122"
    # 2. 用 while 循环不断扩展，直到长度 >= n
    while len(s) < n:
        # 2.1 把已经有的字符按连续相同分块
        groups = []                   # 记录每块的长度
        cnt = 1
        for i in range(1, len(s)):
            if s[i] == s[i - 1]:
                cnt += 1
            else:
                groups.append(cnt)
                cnt = 1
        groups.append(cnt)            # 最后一块也要加入

        # 2.2 计数序列其实就是 s 本身，这里直接取已经生成的 s 前面的部分
        #    为了演示暴力，我们把 groups 再次转成字符序列
        #    （实际实现中会重复生成同样的内容，导致 O(n²)）
        new_part = []
        cur = 1 if s[-1] == 2 else 2   # 下一块要写的字符：交替出现 1、2、1、2...
        for num in groups:
            new_part.extend([cur] * num)   # 写 num 个 cur
            cur = 3 - cur                    # 1<->2 切换

        # 2.3 把新生成的部分接到原串后面
        s.extend(new_part)

    # 3. 统计前 n 位中 1 的个数
    return sum(1 for i in range(n) if s[i] == 1)
```

> **关键行中文注释**已写在代码里，直接复制运行即可（不过在 `n=10⁵` 时会比较慢）。

#### 复杂度  

- **时间复杂度**：`O(n²)`  
  - 解释：每次扩展都要把已有的字符重新遍历分块，长度从 1 增长到 `n`，相当于 1 + 2 + … + n ≈ n²/2 次操作。  
- **空间复杂度**：`O(n)`  
  - 解释：我们把整个魔法字符串保存在列表里，需要的空间随 `n` 线性增长。  

---

### 2. 最优解  

#### 思路  

从暴力解可以看到，**重复分块是主要的性能瓶颈**。其实我们根本不需要每次都重新去找块的边界，只要**一次遍历就能同时完成计数和生成**。  

关键观察：

1. **计数序列 = 原串本身**。  
   - 换句话说，当我们从左到右“读”字符串时，读到的每个数字（`1` 或 `2`）告诉我们**接下来要写多少个字符**。  
2. **写字符时只会在两种值之间交替**（`1` → `2` → `1` → `2` …），因为块的内容只能是全 `1` 或全 `2`。  
3. 用两个指针可以把这两个过程同步进行：  
   - **head** 指向“正在读取计数的地方”。  
   - **tail** 指向“已经写好的字符串的末尾”，我们在这里往后追加新字符。  

这样 **一次遍历**（即 `head` 只向右移动一次）就能完成 **计数 → 生成 → 统计**，时间线性 `O(n)`。

实现细节（一步步推导）：

- 初始化 `s = [1, 2, 2]`（已知前 3 位），`head = 2`（指向第三个数，即计数序列的第一个可用计数），`tail = 3`（下一个待写位置的索引），`count_of_1 = 1`（前 3 位里已经有 1 个 `'1'`）。
- 当 `tail < n` 时：  
  1. 读取计数 `cnt = s[head]`（是 `1` 或 `2`）。  
  2. 决定本次要写的字符 `next_val = 3 - s[tail - 1]`（因为必须和上一个字符相反）。  
  3. 按 `cnt` 次循环把 `next_val` 加入 `s`，每加一次 `tail` 就加一。  
  4. 如果写的字符是 `1`，并且 `tail` 仍在前 `n` 位内，就把 `count_of_1` 加上这一次写入的数量。  
  5. `head += 1`，继续读取下一个计数。  

- 循环结束后，`count_of_1` 就是答案。  

**为什么是线性时间**：  
- `head` 只向右走一次，最多遍历 `n` 次。  
- `tail` 也只向右走一次，恰好走到 `n`。  
- 两个指针的总移动步数 ≤ `2n`，所以时间是 `O(n)`。

#### 代码（Python）

```python
def magical_string(n: int) -> int:
    """
    返回魔法字符串前 n 位中 '1' 的个数。
    思路：双指针（head 读取计数，tail 负责生成），一次遍历即可完成。
    """
    if n <= 0:
        return 0
    if n <= 3:                 # 已知的前 3 位是 "122"
        # 前 3 位里只有第 1 位是 1
        return 1 if n >= 1 else 0

    # 初始化：已知的前 3 位
    s = [1, 2, 2]               # 对应 "122"
    head = 2                    # 正在读取计数的下标（从第三个数开始）
    tail = 3                    # 下一个要写入的位置（已写到下标 2）
    cnt_one = 1                 # 前 3 位里 '1' 的数量（只有第 1 位）

    # 循环生成，直到长度达到 n
    while tail < n:
        cnt = s[head]           # 计数：要写 cnt 个字符
        # 下一块的字符必须和已写的最后一个字符相反
        next_val = 3 - s[tail - 1]

        # 按 cnt 次写入 next_val
        for _ in range(cnt):
            if tail >= n:       # 已经写够 n 位，直接退出
                break
            s.append(next_val) # 把字符写进列表
            tail += 1
            if next_val == 1:   # 统计 '1'
                cnt_one += 1

        head += 1                # 移动到下一个计数

    return cnt_one
```

> **代码要点**  
> - `3 - x` 可以把 `1` ↔ `2` 互换（因为 `3-1=2, 3-2=1`），这在决定“下一块写什么”时非常便利。  
> - `while tail < n` 确保我们只生成 **恰好** 前 `n` 位，避免不必要的额外空间。  

#### 复杂度  

- **时间复杂度**：`O(n)`  
  - 解释：`head` 和 `tail` 各自最多前进 `n` 步，总操作次数与 `n` 成正比。相较于暴力的 `O(n²)`，这里的运行时间几乎是“线性增长”，即 `n` 增大十倍，只会慢十倍，而不是百倍。  
- **空间复杂度**：`O(n)`  
  - 解释：我们仍然需要把前 `n` 位保存下来（题目要求统计前 `n` 位），因此最坏情况下会占用 `n` 个整数的空间。

## 心得  

- **核心技巧**：**双指针同步生成** —— 一指针负责读取“计数”，另一指针负责“写入”。这把原本的“先读后写、再重复”过程压缩到一次遍历。  
- **适用的题型**（类似思路可迁移）：  
  1. **Run‑Length Encoding（RLE）逆向构造**：给出压缩后的计数序列，要求恢复原串。  
  2. **“自描述序列”**（如 LeetCode 481. Magical String 本身）  
  3. **“交错序列”**，如 `1,2,1,2,…` 的生成与计数结合的题目。  
- **一句话总结解题钥匙**：**“读计数、写相反、双指针一次遍历”**。

## 反思  

- **第一反应**：看到“出现次数的序列就是它本身”，立刻想到**把字符串当作计数表来使用**，于是想到逐步构造。  
- **最容易踩的坑**：  
  - **边界条件**：`n` 小于等于 3 时需要单独处理，否则 `head`、`tail` 的初始位置会越界。  
  - **统计时的范围**：在生成过程中一定要检查 `tail` 是否已经超过 `n`，否则会把多余的字符计入答案。  
  - **交替写入**：忘记使用 `3 - last` 来切换 `1/2`，容易导致同一块连续写入相同数字，破坏规则。  
- **下次遇到同类题**，第一步应**先明确“计数序列”和“实际字符序列的关系”，然后**考虑用两个指针同步推进**，把读取计数和写入字符的过程合并为一次线性遍历。
