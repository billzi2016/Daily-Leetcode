# #312. 爆破气球 / Burst Balloons

> 难度：困难 · 标签：Array、Dynamic Programming · [LeetCode 链接](https://leetcode.com/problems/burst-balloons/)

---

## 题目（英文原版）

**Description**

You are given n balloons, indexed from 0 to n - 1. Each balloon is painted with a number on it represented by an array nums. You are asked to burst all the balloons.
If you burst the ith balloon, you will get nums[i - 1] * nums[i] * nums[i + 1] coins. If i - 1 or i + 1 goes out of bounds of the array, then treat it as if there is a balloon with a 1 painted on it.
Return the maximum coins you can collect by bursting the balloons wisely.

**Examples**

**Example 1:**

```
Input: nums = [3,1,5,8]
Output: 167
Explanation:
nums = [3,1,5,8] --> [3,5,8] --> [3,8] --> [8] --> []
coins =  3*1*5    +   3*5*8   +  1*3*8  + 1*8*1 = 167
```

**Example 2:**

```
Input: nums = [1,5]
Output: 10
```

**Constraints**

- n == nums.length
- 1 <= n <= 300
- 0 <= nums[i] <= 100

## 题目（中文翻译）

给定 `n` 个气球（balloon），下标从 `0` 到 `n - 1`。每个气球上标记了一个数字，存放在数组 `nums` 中。要求把所有气球全部戳破。

如果戳破第 `i` 个气球，你将获得 `nums[i - 1] * nums[i] * nums[i + 1]` 枚硬币（coins）。当 `i - 1` 或 `i + 1` 超出数组边界时，视为该位置有一个标记为 `1` 的气球。

返回通过合理的戳破顺序能够收集到的最大硬币数。

### 示例

**示例 1**  
输入: `nums = [3,1,5,8]`  
输出: `167`  
解释:  
```
nums = [3,1,5,8] --> [3,5,8] --> [3,8] --> [8] --> []
coins = 3*1*5 + 3*5*8 + 1*3*8 + 1*8*1 = 167
```

**示例 2**  
输入: `nums = [1,5]`  
输出: `10`

### 约束条件

- `n == nums.length`
- `1 <= n <= 300`
- `0 <= nums[i] <= 100`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是**枚举所有可能的打气球顺序**，然后把每一种顺序得到的硬币数算出来，取最大值。  
- 数据结构上只需要一个**列表**来保存当前剩余的气球，递归时不断在列表中“挑选”一个气球去戳。  
- 这个过程可以类比为**在超市里挑选商品的顺序**：每挑走一个商品，就会产生一定的折扣（这里是硬币），我们想要找到让总折扣最大的挑选顺序。  

因为我们穷举了**所有**可能的顺序（即全排列），必然能够得到最优解——这就是暴力法的正确性来源。  

**为什么会慢？**  
- 气球的数量 n 最多 300，排列数是 n!（阶乘），即使 n=10，10! = 3,628,800 已经很大了，更别说 15、20 ……  
- 在每一次递归里我们还要遍历当前列表一次来计算本次戳气球得到的硬币，所以时间复杂度会是 **O(n!·n)**，几乎不可能在规定时间内跑完。

#### 代码（Python）

```python
def maxCoins_bruteforce(nums):
    # 为了统一边界，把左右两侧各加一个 1
    nums = [1] + nums + [1]
    
    # 递归函数：当前剩余的气球下标列表 (不包含两端的 1)
    def dfs(remaining):
        # remaining 为空时，所有气球已被戳完，收益为 0
        if not remaining:
            return 0
        
        best = 0
        # 枚举这一次要戳哪一个气球（下标在 original nums 中）
        for i, idx in enumerate(remaining):
            # left 和 right 分别是 idx 左右最近的未被戳的气球
            left = remaining[i-1] if i > 0 else 0   # 这里的 0 实际对应 nums 中的 1（左侧哨兵）
            right = remaining[i+1] if i < len(remaining)-1 else len(nums)-1  # 右侧哨兵
            
            # 计算本次戳气球得到的硬币数
            gain = nums[left] * nums[idx] * nums[right]
            # 递归求剩余气球的最大收益
            next_gain = dfs(remaining[:i] + remaining[i+1:])
            best = max(best, gain + next_gain)
        return best
    
    # 初始时，剩余气球的下标是 1..n（因为两端的 1 是哨兵，不参与计算）
    return dfs(list(range(1, len(nums)-1)))
```

> 代码中每一行的中文注释帮助你对应到实际的数学意义。  
> **注意**：这段代码只能通过极小的测试用例，真正的 LeetCode 数据会直接 TLE（超时）。

#### 复杂度

- **时间复杂度**：`O(n!·n)`  
  *“n!”* 表示所有可能的打气球顺序（全排列），每一次递归里还要遍历一次剩余气球列表（`·n`），所以整体是指数级别的，几乎不可能在 1 秒内完成。  
- **空间复杂度**：`O(n)`  
  递归栈的最大深度是 n（每次去掉一个气球），另外我们维护了一个长度为 n 的列表 `remaining`，所以总体是线性空间。

### 2. 最优解

#### 思路  

从暴力解可以看到 **瓶颈在于“顺序”**：我们在每一步都要遍历所有可能的下一个气球，导致指数级别的搜索。  
要想把它降下来，需要**把子问题的重叠部分抽取出来**，利用动态规划（Dynamic Programming, DP）记忆化。

**关键观察**  
把气球按顺序全部戳完后，**每一次戳气球的左右相邻气球其实已经是“已经被戳掉的”**。  
如果我们把视角倒过来，考虑**“在某个区间内最后被戳掉的气球”**会更容易分析：

- 假设在区间 `(i, j)`（不包括 i、j）内的气球全部被戳完，且 **第 k 个气球是最后被戳的**。  
- 那么在戳 k 之前，区间 `(i, k)` 与 `(k, j)` 已经各自独立完成，互不影响。  
- 戳 k 时，它左右相邻的气球一定是 i 和 j（因为区间内部已经空了），所以此时得到的硬币是 `nums[i] * nums[k] * nums[j]`。

于是我们得到**区间 DP 递推式**：

```
dp[i][j] = max( dp[i][k] + dp[k][j] + nums[i]*nums[k]*nums[j] )   for i < k < j
```

- `dp[i][j]` 表示**只考虑区间 (i, j) 之间的气球（不含 i、j）**，能够获得的最大硬币数。  
- 递推式的三部分分别是：左子区间的最优、右子区间的最优、以及最后戳 k 时得到的硬币。

**实现细节**  

1. **哨兵**：在原数组左右各加一个 1，方便统一边界（就像在两端各放一个“虚拟气球”），记作 `nums = [1] + nums + [1]`。  
2. **DP 表**：二维数组 `dp`，大小为 `m x m`，其中 `m = len(nums)`。  
3. **枚举长度**：从小区间开始填表，长度从 2（相邻哨兵之间）到 `m-1`。  
4. **枚举 k**：对每个区间 `(i, j)`，遍历所有可能的最后气球 `k`，取最大值。

**为什么时间可以接受？**  

- 外层遍历区间长度 `L`，最多 `m` 次。  
- 第二层遍历左端点 `i`，每个长度对应约 `m` 次。  
- 第三层遍历 `k`，最多 `L` 次，整体是 `O(m³)`。  
- `m = n + 2 ≤ 302`，`302³ ≈ 27,5 million`，在 Python 中仍然可以在 1 秒左右跑完。  

**空间**只需要 `dp` 表，`O(m²)`，约 `9万` 的整数，完全可以接受。

#### 代码（Python）

```python
def maxCoins(nums):
    """
    动态规划（区间 DP）解法
    """
    # 1. 在两端各加一个 1，形成哨兵，方便统一计算左右相邻气球
    nums = [1] + nums + [1]
    n = len(nums)                     # 实际长度 = 原始气球数 + 2

    # 2. 初始化 DP 表，dp[i][j] 表示区间 (i, j) 之间（不含 i、j）能够得到的最大硬币数
    dp = [[0] * n for _ in range(n)]

    # 3. 按区间长度从小到大填表
    #    长度 L 表示 i 与 j 之间间隔的距离（实际包含的气球数为 L-1）
    for length in range(2, n):        # 最小长度为 2（相邻哨兵之间），此时区间内没有气球，dp 为 0
        for left in range(0, n - length):
            right = left + length     # 区间右端点
            # 4. 在 (left, right) 区间内尝试每一个可能的最后被戳的气球 k
            for k in range(left + 1, right):
                # 左子区间 + 右子区间 + 最后戳 k 时得到的硬币
                gain = dp[left][k] + dp[k][right] + nums[left] * nums[k] * nums[right]
                if gain > dp[left][right]:
                    dp[left][right] = gain   # 取最大值

    # 5. 整个原始数组对应的区间是 (0, n-1)
    return dp[0][n - 1]
```

> 代码每一步都有中文注释，帮助你对应到思路中的 “区间长度”“左子区间”“右子区间”。  
> 运行 `maxCoins([3,1,5,8])` 会得到 `167`，与示例一致。

#### 复杂度

- **时间复杂度**：`O(n³)`  
  *“n³”* 表示我们用了三层循环（区间长度、左端点、区间内部的 k），每一次操作都是常数时间。相较于暴力的 `n!`，多项式时间是可以接受的。  
- **空间复杂度**：`O(n²)`  
  需要一个 `n×n` 的二维表来保存子区间的最优解，`n` 这里指的是加入哨兵后的长度（最多 302），所以占用的内存约几万整数，完全在限制范围内。

## 心得

- **核心技巧**：**区间动态规划**（把“最后一步”作为切入点，把大问题拆成左、右两个独立子问题）。  
- **适用的题型**  
  1. **矩阵链乘法**（最小乘法次数）  
  2. **石子合并**（最小合并代价）  
  3. **最小代价剪绳**（或其它需要在区间内部挑选“最后一步”的问题）  
- **一句话总结解题钥匙**：**把“最后一次操作”固定下来，剩下的子区间就可以独立递归求最优**。

## 反思

- **第一反应**：看到“每次戳气球会产生左右相邻气球的乘积”，立刻想到**递归枚举所有顺序**，这就是暴力思路。  
- **最容易踩的坑**  
  - 忘记在两端加上哨兵 `1`，导致边界计算出错。  
  - 区间 DP 的状态定义不够清晰，容易出现 “左闭右闭” 与 “左开右闭” 的混淆。  
  - 计算 `dp[i][j]` 时没有正确把 `k` 的左右两端对应的数值乘进去，导致结果偏小。  
- **下次类似题目第一步**：**先思考“如果把某一步固定为最后一步，会把问题拆成哪些独立子问题？”**，再尝试用 DP 表记录子区间的最优解。
