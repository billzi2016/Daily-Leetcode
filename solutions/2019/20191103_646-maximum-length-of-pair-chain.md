# #646. 最大数对链长度 / Maximum Length of Pair Chain

> 难度：中等 · 标签：Array、Dynamic Programming、Greedy、Sorting · [LeetCode 链接](https://leetcode.com/problems/maximum-length-of-pair-chain/)

---

## 题目（英文原版）

**Description**

You are given an array of n pairs pairs where pairs[i] = [lefti, righti] and lefti < righti.
A pair p2 = [c, d] follows a pair p1 = [a, b] if b < c. A chain of pairs can be formed in this fashion.
Return the length longest chain which can be formed.
You do not need to use up all the given intervals. You can select pairs in any order.

**Examples**

**Example 1:**

```
Input: pairs = [[1,2],[2,3],[3,4]]
Output: 2
Explanation: The longest chain is [1,2] -> [3,4].
```

**Example 2:**

```
Input: pairs = [[1,2],[7,8],[4,5]]
Output: 3
Explanation: The longest chain is [1,2] -> [4,5] -> [7,8].
```

**Constraints**

- n == pairs.length
- 1 <= n <= 1000
- -1000 <= lefti < righti <= 1000

---

## 题目（中文翻译）

给定一个包含 **n** 个数对（pair）的数组 `pairs`，其中 `pairs[i] = [left_i, right_i]` 且 `left_i < right_i`。

如果数对 `p1 = [a, b]` 的右端点 `b` 小于数对 `p2 = [c, d]` 的左端点 `c`，则称 `p2` 紧随 `p1`。按照这种方式可以形成数对链（chain）。

返回可以形成的 **最长链的长度**。

不必使用所有给定的区间（interval），可以按任意顺序挑选数对。

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  
最直接的想法是：把所有的对按照任意顺序枚举，尝试把每一种排列都看成可能的链，检查哪一种能够形成最长的合法链。  

- **数据结构**：我们把每个 `[left, right]` 看成一条区间。遍历时用 **列表** 保存当前已经选好的链。列表就像一条“队列”，后面可以不断往里加新的区间。  
- **为什么正确**：只要枚举了所有可能的排列，就一定能找到最长的合法链。只要在遍历时检查前一个区间的右端点 `b` 是否小于下一个区间的左端点 `c`（即 `b < c`），符合条件就可以接上。  
- **时间/空间复杂度**：  
  - 枚举所有排列的时间是 `O(n!)`，对 `n≤1000` 完全不可行。这里我们用更温和的「暴力 DP」思路：先把区间 **按左端点排序**，然后对每个区间 `i`，看它能否接在之前的某个区间 `j` 后面，取所有可能的最长长度。这样时间是 `O(n²)`（两层循环），空间是 `O(n)`（存储 DP 表）。  
  - 大白话解释：`O(n²)` 就是说如果有 1000 个区间，我们大概要比较 1000 × 1000 = 1,000,000 次；`O(n)` 只需要和区间数量成正比的额外空间。  

#### 代码（Python）  
```python
from typing import List

def findLongestChain_bruteforce(pairs: List[List[int]]) -> int:
    # 1. 按左端点升序排列，方便后面只考虑前面的区间
    pairs.sort(key=lambda x: x[0])          # 排序相当于先把所有区间排好队

    n = len(pairs)
    dp = [1] * n                            # dp[i] 表示以 pairs[i] 结尾的最长链长度
    # 2. 双层循环：遍历每个区间 i，尝试把它接在之前的任意区间 j 后面
    for i in range(n):
        for j in range(i):
            # 如果区间 j 的右端点小于区间 i 的左端点，说明可以接上
            if pairs[j][1] < pairs[i][0]:
                # 更新 dp[i] 为能够得到的最大值
                dp[i] = max(dp[i], dp[j] + 1)
    # 3. 所有以任意区间结尾的链中，最长的那个就是答案
    return max(dp)
```

#### 复杂度  
- **时间复杂度**：`O(n²)` —— 两层循环，每次都要比较前面的所有区间。对 1000 条数据来说，大约是一百万次比较，仍能在几毫秒内跑完。  
- **空间复杂度**：`O(n)` —— 只用了一个长度为 `n` 的 `dp` 数组来记录每个区间的最长链长度。

### 2. 最优解  

#### 思路  
从暴力 DP 可以看到 **瓶颈** 在于每个区间都要去检查所有之前的区间，导致 `O(n²)` 的时间。  
我们注意到链的定义只和 **右端点的大小** 有关：若想让链尽可能长，应该让每一步选的区间的右端点 **尽可能小**，这样后面留给其他区间的空间就更大。  

这正是 **贪心** 思路的核心：  
1. 把所有区间按 **右端点** 从小到大排序。右端点小的区间先挑，等价于把 “最早结束的会议” 先安排进去（这和会议室安排问题一样）。  
2. 从左到右遍历排序后的区间，维护一个变量 `prev_end` 记录当前链的最后一个区间的右端点。  
   - 如果当前区间的左端点 `l` 大于 `prev_end`，说明它可以接在链的后面，于是把 `prev_end` 更新为当前区间的右端点 `r`，链长 `cnt` 加 1。  
   - 否则跳过，继续检查下一个区间。  

**为什么贪心是最优的**：  
- 已经按右端点升序排列，意味着在任何时刻，如果我们能够接上当前区间，那么把它接上会让链的结束位置尽可能早（因为右端点已经是所有可选区间中最小的）。  
- 结束更早的链对后面的区间留下的“可接空间”最多，不会错过任何可能的更长链。可以用**交换论证**来证明：如果有更优的解没有把当前能接的区间加入，那么把它加入后仍然不会影响后面的选择，因为它的右端点更小。  

**核心数据结构**：只需要 **列表**（存放已排序的区间）和 **几个整数变量**，不需要额外的哈希表或栈。  

#### 代码（Python）  
```python
from typing import List

def findLongestChain_greedy(pairs: List[List[int]]) -> int:
    # 1. 按右端点升序排列，右端点小的先考虑
    pairs.sort(key=lambda x: x[1])          # 类似“先安排最早结束的会议”

    cnt = 0                                 # 记录链的长度
    prev_end = -10**9                       # 初始为一个极小值，保证第一个区间一定能比较

    # 2. 逐个检查是否可以接在当前链的后面
    for l, r in pairs:                      # 解包为左端点 l、右端点 r
        if l > prev_end:                    # 必须严格大于才能接上
            cnt += 1                         # 链长加一
            prev_end = r                     # 更新链的最后一个右端点
    return cnt
```

#### 复杂度  
- **时间复杂度**：`O(n log n)` —— 主要耗时在排序，排序的复杂度是 `n log n`，遍历一次是 `O(n)`，两者相加仍是 `O(n log n)`。相比暴力的 `O(n²)`，在 `n=1000` 时从 1,000,000 次下降到大约 10,000 次。  
- **空间复杂度**：`O(1)` —— 只用了常数个额外变量（`cnt`, `prev_end`），不随 `n` 增长。

## 心得  

- **核心技巧**：**按右端点贪心**（类似活动安排问题），把“结束早的先选”转化为最大链长度。  
- **适用题型**：  
  1. “会议室安排” / “最大不相交区间集合”  
  2. “最长递增子序列的贪心版（需要先排序）”  
  3. “可调度的任务数最大化”  
- **一句话总结解题钥匙**：**先把区间按结束位置排好序，始终选最早结束且能接上的那个**。

## 反思  

- **第一反应**：看到“链”这个词，第一时间想到“动态规划”，于是写了 `O(n²)` 的 DP。  
- **最容易踩的坑**：  
  - 忘记 **严格** 的 `b < c` 条件，写成 `b <= c` 会导致错误的结果。  
  - 排序时选错键：必须按 **右端点** 排序，若误按左端点会失去贪心的最优性。  
- **下次类似题的第一步**：先判断是否可以把“结束时间最早的先选”这一贪心思路套用，如果题目只要求“前后不重叠”，往往可以直接用排序+贪心得到 `O(n log n)` 的最优解。
