## 题目（中文翻译）

**描述**  
给定一个包含若干时间点（time point）的数组 `timePoints`，每个时间点的格式为 `"HH:MM"`，表示 24 小时制时钟中的时间。请计算任意两个时间点之间的最小差值，并以 **分钟（minutes）** 为单位返回该差值。注意，时间点之间的差值应考虑跨午夜的情况，例如 `"23:59"` 与 `"00:00"` 的差值为 1 分钟。

**示例**  

**示例 1**  
```
Input: timePoints = ["23:59","00:00"]
Output: 1
```
*解释*：`"23:59"` 与 `"00:00"` 相差 1 分钟，这是唯一的两两比较结果。

**示例 2**  
```
Input: timePoints = ["00:00","23:59","00:00"]
Output: 0
```
*解释*：数组中出现了两次相同的时间点 `"00:00"`，它们之间的差值为 0 分钟。

**约束条件**  
- `2 <= timePoints.length <= 2 * 10^4`  
- `timePoints[i]` 的格式均为 `"HH:MM"`，其中 `00 <= HH <= 23`，`00 <= MM <= 59`。

---

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：把每一个时间点都和其它所有时间点两两比较，算出它们之间的分钟差，然后取最小值。  
- **数据结构**：把时间字符串先转换成「从午夜算起的分钟数」存进列表 `minutes`。这一步相当于把「23:59」这种「时:分」的文字，翻译成「1439」这样单纯的数字，后面比较起来更方便。  
- **生活化类比**：想象你手里有一堆时钟的指针（每个指针指向某个分钟），要找出相邻指针之间最小的角度（这里的角度就是分钟差），最笨的办法就是把每根指针依次和其它每根指针配对，逐个测量。  
- **正确性**：因为我们把所有可能的配对都算了一遍，最小的那一次必然会被记录下来，所以答案一定是正确的。  

#### 代码（Python）

```python
from typing import List

def findMinDifference_brute(timePoints: List[str]) -> int:
    # 把 "HH:MM" 转成 0~1439 之间的整数（分钟数）
    minutes = []
    for tp in timePoints:
        h, m = map(int, tp.split(':'))      # 分别取出小时和分钟
        minutes.append(h * 60 + m)         # 1 小时 = 60 分钟

    n = len(minutes)
    ans = 24 * 60   # 最大可能的差值是一天的总分钟数 1440

    # 两层循环，枚举所有不同的两点
    for i in range(n):
        for j in range(i + 1, n):
            diff = abs(minutes[i] - minutes[j])          # 直接相减得到差值
            # 因为时间是环形的，差值可以走“逆时针”，取最短的那段
            diff = min(diff, 24 * 60 - diff)
            ans = min(ans, diff)                          # 保留最小的差值

    return ans
```

#### 复杂度  

- **时间复杂度**：`O(n²)`  
  这里的 `n` 是时间点的个数。两层循环会比较 `n*(n-1)/2` 次，想象成在一张表里填满上三角形的格子。  
- **空间复杂度**：`O(n)`  
  只用了一个列表 `minutes` 来存放每个时间对应的分钟数，大小和输入成正比。

### 2. 最优解

#### 思路  

暴力解的瓶颈在 **两层循环**，当 `n` 达到 2·10⁴ 时，`n²` 已经是几亿次比较，明显太慢。  
观察一下：如果把所有时间点按分钟数从小到大排好序，那么**相邻的两个时间点**之间的差一定是局部最小的（因为没有其他点介于它们之间）。全局最小差只可能出现在：

1. 任意相邻的两个已排序的时间点之间  
2. “首尾”两点之间（因为时间是环形的，需要考虑跨午夜的情况）

因此，只需要一次排序 `O(n log n)`，再遍历一次求相邻差即可。  

- **核心数据结构**：**列表 + 排序**。排序可以看成把散乱的时间“排队”，让相邻的时间站在一起，比较起来就只需要看相邻的两个人了。  
- **前缀/后缀**：这里不需要额外的前缀和，只要一次遍历就能算出所有相邻差。  

**步骤**：

1. 把每个 `"HH:MM"` 转成分钟数，存进列表 `minutes`。  
2. 对 `minutes` 进行升序排序。  
3. 依次比较 `minutes[i]` 与 `minutes[i-1]` 的差，记录最小值。  
4. 最后比较 **首尾**（即 `minutes[0]` 与 `minutes[-1]`），因为可以跨午夜。跨午夜的差等于 `1440 - (minutes[-1] - minutes[0])`。  
5. 返回最小的那一次差。

#### 代码（Python）

```python
from typing import List

def findMinDifference(timePoints: List[str]) -> int:
    # 1. 转换为分钟数
    minutes = []
    for tp in timePoints:
        h, m = map(int, tp.split(':'))
        minutes.append(h * 60 + m)

    # 2. 排序
    minutes.sort()                     # O(n log n)

    # 3. 计算相邻差的最小值
    min_diff = 24 * 60                  # 初始为一天的总分钟数
    for i in range(1, len(minutes)):
        diff = minutes[i] - minutes[i - 1]   # 已经是正数，因为已排序
        min_diff = min(min_diff, diff)

    # 4. 处理跨午夜的情况（首尾差）
    # 例如 23:59 (1439) 与 00:00 (0) 的差应该是 1 分钟
    wrap_diff = (24 * 60 - minutes[-1] + minutes[0])
    min_diff = min(min_diff, wrap_diff)

    return min_diff
```

#### 复杂度  

- **时间复杂度**：`O(n log n)`  
  排序是主要耗时的步骤，`log n` 可以理解为“把 n 本书排好顺序，只需要把每本书放到合适的位置，大约需要 log₂n 步”。遍历一次求差是线性的 `O(n)`，相对于排序可以忽略。  
- **空间复杂度**：`O(n)`  
  只用了一个保存分钟数的列表，额外的空间只有常数级别的临时变量。

## 心得

- 这道题的核心技巧是 **把环形问题转化为线性问题后再排序**，进而只比较相邻元素。  
- 类似技巧常出现在：  
  1. “数组中的最大距离”类题目（需要先排序再比较相邻）  
  2. “最近的两点”或“最小差值”类题（如 `Maximum Gap`）  
- 一句话总结解题钥匙：**排序 + 相邻比较 + 记得处理环首尾**。

---

## 反思

- **第一反应**：看到时间点，想到把它们统一成分钟数再逐对比较。  
- **最容易踩的坑**：  
  - 忘记跨午夜的差值，导致答案偏大。  
  - 直接用 `abs(a-b)` 而不取 `min(diff, 1440-diff)`，会把环形的最短路径算错。  
  - 输入可能出现重复时间点，若出现 `0` 差可以提前返回。  
- **下次遇到同类题**：第一步先 **把数据统一成同一尺度（如分钟或秒）并排序**，然后只比较相邻或首尾即可。
