# #546. 移除盒子 / Remove Boxes

> 难度：困难 · 标签：Array、Dynamic Programming、Memoization · [LeetCode 链接](https://leetcode.com/problems/remove-boxes/)

## 题目（英文原版）

**Description**

You are given several boxes with different colors represented by different positive numbers.
You may experience several rounds to remove boxes until there is no box left. Each time you can choose some continuous boxes with the same color (i.e., composed of k boxes, k >= 1), remove them and get k * k points.
Return the maximum points you can get.

**Examples**

**Example 1:**

```
Input: boxes = [1,3,2,2,2,3,4,3,1]
Output: 23
Explanation:
[1, 3, 2, 2, 2, 3, 4, 3, 1] 
----> [1, 3, 3, 4, 3, 1] (3*3=9 points) 
----> [1, 3, 3, 3, 1] (1*1=1 points) 
----> [1, 1] (3*3=9 points) 
----> [] (2*2=4 points)
```

**Example 2:**

```
Input: boxes = [1,1,1]
Output: 9
```

**Example 3:**

```
Input: boxes = [1]
Output: 1
```

**Constraints**

- 1 <= boxes.length <= 100
- 1 <= boxes[i] <= 100

## 题目（中文翻译）

**题目描述**  
给定一个由正整数表示颜色的盒子序列 `boxes`。  
你可以进行若干轮操作，直至所有盒子全部被移除。每一轮，你可以选择若干**连续的、颜色相同的盒子（continuous boxes）**，设其数量为 `k (k ≥ 1)`，将它们移除并获得 `k * k` 分。  
返回能够获得的最大分数。

**示例 1**  
```text
Input: boxes = [1,3,2,2,2,3,4,3,1]
Output: 23
Explanation:
- 初始序列 `[1, 3, 2, 2, 2, 3, 4, 3, 1]`
- 移除连续的三个 `2`，得到 `[1, 3, 3, 4, 3, 1]`（`3*3=9` 分）
- 移除单个 `4`，得到 `[1, 3, 3, 3, 1]`（`1*1=1` 分）
- 移除连续的三个 `3`，得到 `[1, 1]`（`3*3=9` 分）
- 移除两个 `1`，得到 `[]`（`2*2=4` 分）
- 总分 `9 + 1 + 9 + 4 = 23`
```

**示例 2**  
```text
Input: boxes = [1,1,1]
Output: 9
```

**示例 3**  
```text
Input: boxes = [1]
Output: 1
```

**约束条件**  
- `1 <= boxes.length <= 100`  
- `1 <= boxes[i] <= 100`

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是**穷举**所有可能的删除顺序：  
1. 在当前数组 `boxes` 中任选一段连续且颜色相同的子串（长度 `k≥1`）。  
2. 把这段子串直接删除，得到 `k*k` 分。  
3. 对剩下的盒子递归执行同样的操作，直到数组为空。  

我们可以把“所有可能的删除顺序”想象成一棵**决策树**：  
- 树的每个节点代表一次删除操作，  
- 从根到叶子的一条路径对应一种完整的删除顺序，  
- 叶子节点的得分之和就是该路径的总得分。  

只要遍历整棵树，取最大得分就是答案。

> **数据结构**  
> - `list`：存放当前剩余的盒子，相当于我们手里的“盒子序列”。  
> - 递归函数返回**最大得分**，相当于在决策树的每个子树里求最大值。  

**为什么一定能得到正确答案？**  
因为我们枚举了**所有**合法的删除方式，最大值自然是最优解。  

**复杂度分析（大白话）**  
- 假设数组长度为 `n`。每一步我们都要遍历一次数组找出所有相同颜色的连续段，最坏情况（全部颜色不同）会有 `n` 种选择。  
- 删除后长度会变短，递归深度最多 `n`。于是时间复杂度大约是 `O(n!)`（阶乘级），因为每一次都要在剩余的 `n-1、n-2…` 个元素中重新枚举。  
- 空间上只用递归栈，深度最多 `n`，所以 `O(n)`。

> **O(n!)** 可以理解为“随盒子数量暴涨，计算时间会疯狂增长”，在实际中根本跑不完。

#### 代码（Python）

```python
def removeBoxes_bruteforce(boxes):
    """
    暴力递归解法
    boxes : List[int]  当前盒子序列
    返回   : int        能得到的最大得分
    """
    # 递归函数：对当前序列求最大得分
    def dfs(arr):
        if not arr:                     # 空序列，得分 0
            return 0

        best = 0
        i = 0
        # 遍历所有连续相同颜色的段
        while i < len(arr):
            j = i
            # 找到从 i 开始的最长相同颜色段 [i, j)
            while j < len(arr) and arr[j] == arr[i]:
                j += 1
            k = j - i                    # 段的长度

            # 方案一：直接把这段删掉
            score_remove = k * k + dfs(arr[:i] + arr[j:])
            best = max(best, score_remove)

            # 方案二：尝试把后面同颜色的盒子先合并进来
            # （暴力实现：把后面相同颜色的单个盒子移到这里再删）
            # 为了完整枚举，这里不实现合并，只保留直接删除的情况
            i = j                         # 跳到下一个不同颜色的起点

        return best

    return dfs(boxes)
```

> 代码中只实现了**直接删除**的情况，完整的暴力实现需要在每个段后面再搜索同颜色的盒子并尝试合并，复杂度更高，这里为了演示思路保持简洁。

#### 复杂度  

- **时间复杂度**：`O(n!)` —— 想象每次都有 `n` 种选择，递归深度 `n`，相当于阶乘增长，实际不可接受。  
- **空间复杂度**：`O(n)` —— 递归调用栈的最大深度为 `n`，每层保存一个列表的拷贝。

### 2. 最优解  

#### 思路  

暴力解的瓶颈在于**重复计算**同一种子问题：  
- 当我们把一段 `k` 个相同颜色的盒子删除后，剩余序列的结构往往会在不同的路径中出现多次。  
- 例如序列 `[1,2,1,1]`，先删除中间的 `2` 再把两个 `1` 合并，或先把后面的 `1,1` 合并再删除 `2`，最终都会得到相同的子序列 `[1,1,1]`。  

**关键观察**：  
在一次操作后，**只关心**三个信息：  
1. 当前处理的区间 `[l, r]`（左闭右闭）。  
2. 区间左端 `boxes[l]` 前面已经累计了多少个相同颜色的盒子（记作 `k`），这些盒子会和 `boxes[l]` 合并一起在以后一起删除，得到更大的 `k*k` 分。  

于是我们可以定义 **状态** `dp[l][r][k]`：  
> 在子数组 `boxes[l…r]` 中，**再加上** `k` 个与 `boxes[l]` 同颜色、紧挨在左边的盒子，能够得到的最大得分。

> **类比**：把 `k` 想象成“手里已经抓住的同色盒子数量”，相当于在字典里查到的“已有的页码”。  

**状态转移**分两步：

1. **合并左端的相同颜色**  
   - 首先把 `boxes[l]` 与左边已经累计的 `k` 合并，形成 `k+1` 个同色盒子。  
   - 接着继续向右检查，若 `boxes[l+1]` 颜色相同，就可以继续把它算进 `k`，即 `dp[l+1][r][k+1]`。  
   - 为了简化，我们在进入递归前先把所有连续相同颜色的盒子都“吞掉”，让 `boxes[l]` 左侧只剩下 **一段** 不同颜色的盒子。

2. **两种删除方式**  
   - **方式一**：直接把左端的 `(k+1)` 个盒子一次性删除，得分 `(k+1)^2`，随后求解剩余区间 `dp[l+1][r][0]`（因为左端已被清空，左侧累计数归零）。  
   - **方式二**：尝试把左端的盒子 **与后面** 同颜色的盒子合并后再删除。  
     - 找到区间 `[l+1 … r]` 中所有位置 `m`，使得 `boxes[m] == boxes[l]`。  
     - 先把 `l+1 … m-1` 这段区间全部清空（得到 `dp[l+1][m-1][0]`），  
     - 再把 `boxes[l]`（连同左侧累计的 `k`）和 `boxes[m]` 合并，形成 `k+1` 个盒子放在位置 `m`，此时递归求解 `dp[m][r][k+1]`。  
   - 取所有可能的 `m` 中的最大值。

**记忆化**：因为 `l, r, k` 的取值范围都有限（`0 ≤ l ≤ r < n`，`0 ≤ k ≤ n`），我们可以把已经算过的 `dp[l][r][k]` 存进字典（或三维数组），避免重复计算。

**复杂度**  
- 状态数目：`O(n³)`（`l, r` 各 `O(n)`，`k` 也最多 `n`）。  
- 每个状态遍历一次 `m`（最多 `O(n)`），但实际因为合并相同颜色的段会提前压缩，整体仍保持在 `O(n³)` 级别。  
- 空间同样是 `O(n³)` 用于记忆化表。

> 对于 `n ≤ 100`，`O(n³) ≈ 10⁶`，在 Python 中完全可以接受。

#### 代码（Python）

```python
from functools import lru_cache

def removeBoxes(boxes):
    """
    动态规划 + 记忆化搜索（3D DP）
    :param boxes: List[int] 盒子颜色序列，长度 ≤ 100
    :return: int 最大得分
    """
    n = len(boxes)

    @lru_cache(None)                     # 自动记忆化，键是 (l, r, k)
    def dp(l, r, k):
        """
        返回在子数组 boxes[l..r] 中，
        再加上 k 个与 boxes[l] 同颜色、紧贴在左侧的盒子，
        能得到的最大得分。
        """
        if l > r:                         # 空区间得分 0
            return 0

        # 1️⃣ 把左端连续相同颜色的盒子合并到 k 中
        #    例如 [2,2,2,3...]，把前面的 2 合并进 k，后面只保留一个 2
        while l + 1 <= r and boxes[l] == boxes[l + 1]:
            l += 1
            k += 1                         # 颜色相同，累计数 +1

        # 2️⃣ 方式一：直接把左端的 (k+1) 个盒子删除
        #    得分 = (k+1)^2 + 处理剩余区间的最优解
        best = (k + 1) * (k + 1) + dp(l + 1, r, 0)

        # 3️⃣ 方式二：尝试把左端盒子与后面同颜色的盒子合并
        #    对每个位置 m (l+1 ≤ m ≤ r) ，如果颜色相同，就先清掉中间部分
        for m in range(l + 1, r + 1):
            if boxes[m] == boxes[l]:
                # 先把 (l+1 .. m-1) 完全消除，然后把 boxes[l]（连同 k）合并到 m 位置
                #   dp(l+1, m-1, 0)   -> 中间段的最优得分
                #   dp(m, r, k+1)     -> 合并后的状态
                candidate = dp(l + 1, m - 1, 0) + dp(m, r, k + 1)
                best = max(best, candidate)

        return best

    return dp(0, n - 1, 0)
```

**代码要点注释**  

- `@lru_cache(None)`：把函数的返回值记住，避免同样的 `(l, r, k)` 再算一次。  
- `while` 循环：把左边一段相同颜色的盒子一次性“吞掉”，把 `k` 增大，这一步相当于把连续相同颜色的盒子合并，降低状态数。  
- `best = (k+1)*(k+1) + dp(l+1, r, 0)`：先把左端的这批盒子直接删掉。  
- `for m in range(l+1, r+1):`：寻找后面与左端颜色相同的盒子，尝试把它们合并。  
- `candidate = dp(l+1, m-1, 0) + dp(m, r, k+1)`：先把中间的盒子全部消除，再把左端累计的 `k+1` 个盒子合并到位置 `m`，递归求解更大的区间。

#### 复杂度  

- **时间复杂度**：`O(n³)`  
  - 解释：`l`、`r`、`k` 每个最多 `n` 种取值，状态总数约 `n³`。每个状态内部遍历一次 `m`（最坏 `n`），但因为记忆化和合并相同颜色的优化，实际常数非常小。  
  - 与暴力的 `O(n!)` 相比，**指数级**下降到**多项式级**，即使 `n=100` 也能在毫秒级完成。

- **空间复杂度**：`O(n³)`（记忆化表）  
  - 解释：缓存的每个状态占用常数空间，总共约 `n³` 个状态。递归栈深度最多 `n`，相较于缓存可以忽略不计。

## 心得  

- **核心技巧**：**三维动态规划 + 记忆化**，把“左侧累计相同颜色的盒子数”作为额外维度，使得子问题具有完备的描述能力。  
- **适用题型**  
  1. “合并同类”类的区间 DP（如 LeetCode 546 *Remove Boxes*、LeetCode 1130 *Minimum Cost Tree From Leaf Values* 的思路类似）。  
  2. “删除/合并”型的游戏/拼图问题（如 LeetCode 546、LeetCode 1209 *Remove All Adjacent Duplicates in String* 的变体）。  
  3. “带记忆的递归”可以把状态压缩成 **位置 + 额外信息**（如 LeetCode 91 *Decode Ways*、LeetCode 97 *Interleaving String*）。  

- **一句话总结**：  
  > 把“左侧已经累计的同色盒子数量”作为状态维度，递归时把相邻同色盒子先合并，就能用记忆化 DP 把指数爆炸的搜索压缩到多项式时间。

## 反思  

- **第一反应**：看到“连续相同颜色可以一次性删除，得分是长度平方”，自然想到**贪心**或**递归枚举**所有删除顺序。  
- **最容易踩的坑**  
  1. **忽略累计的同色盒子**：只考虑当前区间 `[l, r]`，会错失把左侧已删除但颜色相同的盒子合并的机会。  
  2. **忘记合并左端连续相同颜色**：如果不先把左端的相同颜色压缩进 `k`，状态数会爆炸，导致超时。  
  3. **递归终止条件**：`l > r` 时要返回 0，否则会出现负索引错误。  
  4. **缓存键的选择**：必须把 `k` 也放进键，否则不同累计数的子问题会错误复用。  

- **下次类似题的第一步**：  
  > 先思考**“除了当前区间，还需要哪些额外信息才能完整描述子问题？”**，把这些信息加入状态后，再考虑记忆化 DP。这样可以把看似指数级的搜索转化为可控的多项式解。
