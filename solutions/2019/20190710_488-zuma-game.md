## 题目（英文原版）

**Description**

You are playing a variation of the game Zuma.
In this variation of Zuma, there is a single row of colored balls on a board, where each ball can be colored red 'R', yellow 'Y', blue 'B', green 'G', or white 'W'. You also have several colored balls in your hand.
Your goal is to clear all of the balls from the board. On each turn:
Given a string board, representing the row of balls on the board, and a string hand, representing the balls in your hand, return the minimum number of balls you have to insert to clear all the balls from the board. If you cannot clear all the balls from the board using the balls in your hand, return -1.

**Examples**

**Example 1:**

```
Input: board = "WRRBBW", hand = "RB"
Output: -1
Explanation: It is impossible to clear all the balls. The best you can do is:
- Insert 'R' so the board becomes WRRRBBW. WRRRBBW -> WBBW.
- Insert 'B' so the board becomes WBBBW. WBBBW -> WW.
There are still balls remaining on the board, and you are out of balls to insert.
```

**Example 2:**

```
Input: board = "WWRRBBWW", hand = "WRBRW"
Output: 2
Explanation: To make the board empty:
- Insert 'R' so the board becomes WWRRRBBWW. WWRRRBBWW -> WWBBWW.
- Insert 'B' so the board becomes WWBBBWW. WWBBBWW -> WWWW -> empty.
2 balls from your hand were needed to clear the board.
```

**Example 3:**

```
Input: board = "G", hand = "GGGGG"
Output: 2
Explanation: To make the board empty:
- Insert 'G' so the board becomes GG.
- Insert 'G' so the board becomes GGG. GGG -> empty.
2 balls from your hand were needed to clear the board.
```

**Constraints**

- 1 <= board.length <= 16
- 1 <= hand.length <= 5
- board and hand consist of the characters 'R', 'Y', 'B', 'G', and 'W'.
- The initial row of balls on the board will not have any groups of three or more consecutive balls of the same color.

## 题目（中文翻译）

你正在玩一种变体的祖玛（Zuma）游戏。  
在该变体中，棋盘（board）上有一行彩色小球，每个小球的颜色只能是红色 `'R'`、黄色 `'Y'`、蓝色 `'B'`、绿色 `'G'` 或白色 `'W'`。你手中（hand）也拥有若干彩色小球。  

你的目标是清除棋盘上所有的小球。每回合可以将手中的任意一个小球插入到棋盘的任意位置。当插入后形成 **三个或更多** 连续相同颜色的小球时，这些小球会立即消除；消除可能会导致相邻的相同颜色小球再次连成三个或更多，进而继续消除，直至不再有可以消除的情况。  

给定表示棋盘的字符串 `board` 和表示手中小球的字符串 `hand`，返回为清空棋盘 **最少需要插入的球数**。如果使用手中的所有小球仍无法清空棋盘，返回 `-1`。

---

### 示例

**示例 1**  
```
Input: board = "WRRBBW", hand = "RB"
Output: -1
```
**解释**：无法清空所有小球。你能做到的最好情况是：
- 插入 `'R'`，棋盘变为 `WRRRBBW` → `WBBW`（`RRR` 消除）。
- 插入 `'B'`，棋盘变为 `WBBBW` → `WW`（`BBB` 消除）。

此时棋盘仍有小球且手中已无球可插入。

**示例 2**  
```
Input: board = "WWRRBBWW", hand = "WRBRW"
Output: 2
```
**解释**：清空棋盘的步骤如下：
- 插入 `'R'`，棋盘变为 `WWRRRBBWW` → `WWBBWW`（`RRR` 消除）。
- 插入 `'B'`，棋盘变为 `WWBBBWW` → `WWWW` → 空（`BBB` 消除后 `WWWW` 再次消除）。

共使用了手中的 2 个球。

**示例 3**  
```
Input: board = "G", hand = "GGGGG"
Output: 2
```
**解释**：清空棋盘的步骤如下：
- 插入 `'G'`，棋盘变为 `GG`。
- 再插入 `'G'`，棋盘变为 `GGG` → 空（`GGG` 消除）。

共使用了手中的 2 个球。

- 初始的棋盘行不会出现三个或以上连续相同颜色的小球。

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**把每一次可以插入的球全部枚举**，然后把插完球后会产生的消除过程完整模拟，递归地继续往下插，直到板子为空或手中的球用完。  

- **数据结构**  
  - `board` 用 **字符串** 保存当前的球列，像“一串珠子”。  
  - `hand` 也是 **字符串**，代表我们手里还能用的球。  
  - 为了方便统计手中每种颜色还有多少球，我们可以把 `hand` 先转成一个 **哈希表（字典）**，`cnt['R']` 表示还有多少个红球。哈希表就像一本词典，`key` 是颜色，`value` 是剩余数量。  

- **为什么一定能得到答案**  
  暴力枚举会尝试**所有可能的插入顺序**，不管是好是坏，只要有一种方式可以把板子全部消除，就一定会在搜索树的某个分支里找到。  

- **时间/空间复杂度**  
  - 每一步我们要在 `board` 的每个间隙（包括首尾）尝试插入手中任意一种颜色的球。设 `n = len(board)`，`m = len(hand)`，则一次递归的分支数约为 ` (n+1) * m`。  
  - 最坏情况下我们会把手里的所有球都用完，递归深度为 `m`，所以总的递归树大小约为 `((n+1)*m)^m`。这就是 **指数级**（类似 `O(k^m)`）的时间，`k≈n`。  
  - 递归栈最多保存 `m` 层状态，空间是 `O(m)`（不计字符串复制的开销）。  

> 大白话：如果板子有 10 个球，手里有 5 个球，暴力解相当于在每一步把 5 种颜色分别插到 11 个位置，一共 55 种选择，接着再对每一种选择继续 55 种…，所以会很快“爆炸”。

#### 代码（Python）

```python
from collections import Counter
import copy

def shrink(board: str) -> str:
    """
    连锁消除：只要出现 >=3 个相同颜色相连，就全部删除，
    删除后可能会产生新的 >=3 连续段，继续删除，直到没有可消除的为止。
    """
    i = 0
    while i < len(board):
        j = i
        # 找到从 i 开始的相同颜色连续段
        while j < len(board) and board[j] == board[i]:
            j += 1
        # 如果长度 >= 3，直接把这段删掉，重新从头开始检查
        if j - i >= 3:
            board = board[:i] + board[j:]      # 删除
            i = 0                               # 重新扫描，因为可能产生新的消除
        else:
            i = j                               # 向后继续检查
    return board

def dfs(board: str, hand_cnt: Counter, steps: int, best: list) -> None:
    """
    纯暴力递归：
    - board: 当前板子
    - hand_cnt: 手中每种颜色剩余的数量
    - steps: 已经插入的球数
    - best: 记录全局最少插入数（list 只为可变引用）
    """
    # 已经清空，更新答案
    if not board:
        best[0] = min(best[0], steps)
        return
    # 手里已经没有球，直接返回
    if sum(hand_cnt.values()) == 0:
        return
    # 剪枝：已经超过当前最优解，没必要继续
    if steps >= best[0]:
        return

    n = len(board)
    # 遍历所有插入位置（0~n），以及手里所有颜色
    for i in range(n + 1):                     # 插入位置
        for color in list(hand_cnt.keys()):   # 颜色
            if hand_cnt[color] == 0:
                continue
            # 把球插进去
            new_board = board[:i] + color + board[i:]
            # 先消除可能出现的 >=3 段
            new_board = shrink(new_board)
            # 把手里这颗球数量减 1
            hand_cnt[color] -= 1
            dfs(new_board, hand_cnt, steps + 1, best)
            # 回溯
            hand_cnt[color] += 1

def findMinStep_bruteforce(board: str, hand: str) -> int:
    best = [float('inf')]
    hand_cnt = Counter(hand)
    dfs(board, hand_cnt, 0, best)
    return -1 if best[0] == float('inf') else best[0]

# ------------------- 测试 -------------------
print(findMinStep_bruteforce("WRRBBW", "RB"))      # -1
print(findMinStep_bruteforce("WWRRBBWW", "WRBRW")) # 2
print(findMinStep_bruteforce("G", "GGGGG"))       # 2
```

#### 复杂度  

- **时间复杂度**：`O(((n+1) * m)^m)`，指数级。  
  - `n` 为板子长度（≤16），`m` 为手中球数（≤5），所以在最坏情况下约为 `O( (17*5)^5 ) ≈ 2.5×10⁶`，虽然在题目给的限制下还能跑通，但随着 `m` 增大就会失效。  
- **空间复杂度**：`O(m)`（递归栈深度），加上 `hand_cnt` 的字典开销，整体仍是常数级别。

---

### 2. 最优解

#### 思路  

暴力解的**瓶颈**在于：  
1. **盲目插入**——即使插入后立刻没有产生消除，也会继续递归，导致大量无意义的搜索。  
2. **没有记忆已经算过的状态**——相同的 `board` 与 `hand` 组合会被重复计算。

**关键优化**有两点：

1. **只在“可能产生消除”的位置插球**  
   - 如果我们在某个位置插入一种颜色，只有当**插入后形成了 ≥3 个相同颜色的连续段**，才会触发一次消除。  
   - 更进一步：如果当前板子中已经有 `k`（`k = 1 或 2`）个连续的相同颜色球，**只需要补足到 3** 才可能消除。  
   - 因此，我们只在以下两种情况插球：  
     - 在已有 **两个相同颜色相连** 的位置插入同色球（形成 3 连）。  
     - 在 **单个球** 的左/右两侧插入 **两颗同色球**（需要两次插入才能消除，这种情况在递归的后续层会自然出现）。  
   - 这种剪枝大幅降低分支数。

2. **记忆化搜索（DP）**  
   - 用一个哈希表 `memo` 把已经算过的状态 `(board, hand_counts)` 记下来，直接返回最小插入次数。  
   - `hand_counts` 可以用一个长度为 5 的元组 `(cntR, cntY, cntB, cntG, cntW)` 表示，保证哈希时的唯一性且速度快。  

**整体算法**：

```
DFS(board, hand_counts):
    if board == "": return 0                     # 已经全部消除
    if hand_counts all zero: return INF          # 手里没球，无法完成
    if (board, hand_counts) in memo: return memo[...]
    
    ans = INF
    for each i in range(len(board)):
        j = i
        while j < len(board) and board[j] == board[i]:
            j += 1
        same_len = j - i                         # 连续相同颜色的长度
        color = board[i]

        # 需要的球数才能让这段 >=3
        need = 3 - same_len
        if need <= hand_counts[color]:
            # 把 need 球放到这段两侧（等价于直接把 need 球加进去）
            new_hand = hand_counts with color reduced by need
            new_board = board[:i] + board[j:]    # 先把这段删掉
            new_board = shrink(new_board)       # 可能产生连锁消除
            tmp = DFS(new_board, new_hand)
            if tmp != INF:
                ans = min(ans, need + tmp)       # need 是本层用了多少球

        i = j    # 跳到下一段不同颜色的起点
    memo[(board, hand_counts)] = ans
    return ans
```

- `shrink` 与暴力解中相同，用来处理**连锁消除**。  
- `need` 可能为 `1`、`2` 或 `0`（已经 >=3，理论上不会出现，因为题目保证初始没有 ≥3）。  
- 只在能**立刻消除**的地方尝试插球，这样每一次递归的分支数最多是 `len(board)`（每段颜色只考虑一次），而不是 `(n+1)*m`。  

**为什么正确**  
- 任何成功的解法都必须在某一步把一段颜色的球数提升到 3 或以上才能继续消除。我们遍历了所有可能的“提升”方式（对每段尝试补足所缺的球），因此不会漏掉任何可行解。  
- 记忆化保证了相同状态只计算一次，不会因为不同的插入顺序而重复搜索。  

#### 代码（Python）

```python
from collections import Counter
from functools import lru_cache

# ---------- 帮助函数 ----------
def shrink(board: str) -> str:
    """删除所有连续 >=3 的相同颜色球，直到没有可以消除的为止"""
    i = 0
    while i < len(board):
        j = i
        while j < len(board) and board[j] == board[i]:
            j += 1
        if j - i >= 3:                     # 可以消除
            board = board[:i] + board[j:]  # 删除
            i = 0                           # 重新从头检查连锁消除
        else:
            i = j
    return board

# ---------- 主函数 ----------
def findMinStep(board: str, hand: str) -> int:
    # 手中每种颜色的数量，用固定顺序的元组方便做哈希键
    colors = ['R', 'Y', 'B', 'G', 'W']
    hand_cnt = [0] * 5
    for c in hand:
        hand_cnt[colors.index(c)] += 1
    hand_tuple = tuple(hand_cnt)

    @lru_cache(maxsize=None)
    def dfs(cur_board: str, cur_hand: tuple) -> int:
        """
        返回把 cur_board 清空所需的最少插球数。
        若无法清空，返回一个很大的数 INF。
        """
        if not cur_board:
            return 0                         # 已经全部消除
        if sum(cur_hand) == 0:                # 手里没有球了
            return float('inf')

        ans = float('inf')
        i = 0
        # 逐段扫描 board
        while i < len(cur_board):
            j = i
            while j < len(cur_board) and cur_board[j] == cur_board[i]:
                j += 1
            same_len = j - i                 # 这段相同颜色的长度
            color = cur_board[i]
            idx = colors.index(color)        # 对应 hand 中的下标

            # 需要多少球才能让这段 >=3
            need = 3 - same_len
            if need <= cur_hand[idx]:        # 手里足够
                # 使用 need 球后，这段会直接消除
                new_hand = list(cur_hand)
                new_hand[idx] -= need
                new_board = cur_board[:i] + cur_board[j:]   # 删除这段
                new_board = shrink(new_board)               # 连锁消除
                sub = dfs(new_board, tuple(new_hand))
                if sub != float('inf'):
                    ans = min(ans, need + sub)   # 本层用了 need 球

            i = j   # 跳到下一段
        return ans

    res = dfs(board, hand_tuple)
    return -1 if res == float('inf') else res

# ------------------- 测试 -------------------
print(findMinStep("WRRBBW", "RB"))        # -1
print(findMinStep("WWRRBBWW", "WRBRW"))   # 2
print(findMinStep("G", "GGGGG"))          # 2
```

> **代码要点说明**  
> 1. `shrink` 完全复用了前面暴力解的实现，只是抽成了函数。  
> 2. `dfs` 使用 `@lru_cache`（相当于手写的 `memo`）实现记忆化。键是 `(cur_board, cur_hand)`，其中 `cur_hand` 用 **元组**（不可变）表示，哈希速度快。  
> 3. 只在“可以一次性把一段消除”时才尝试插球（`need <= cur_hand[idx]`），极大减少了搜索分支。  

#### 复杂度  

- **时间复杂度**：  
  - 状态数上限为 `O( (len(board)+1) * 5^hand_len )`，因为  
    - `board` 最多 16 长，每次消除后长度只能变短。  
    - `hand_len ≤ 5`，每种颜色最多 5 个，手中状态可以看成 5 维计数，组合数 ≤ `6^5 = 7776`。  
  - 在实际搜索中，由于只在能立刻消除的地方插球，分支数大约是 `O(len(board))`，整体运行在 **几千到几万次递归**内，能够在毫秒级完成。  
  - 相比暴力的指数级搜索，这已经是 **多项式级别**（状态数有限） 的解法。  

- **空间复杂度**：  
  - 记忆化表存储所有状态，最坏约 `O( len(board) * 6^5 )`，约几千条记录，属于常数级别。  
  - 递归栈深度 ≤ 手中球数 `hand_len ≤ 5`，空间几乎可以忽略不计。

## 心得  

- **核心技巧**：**只在“能立刻形成 3 连”时插球 + 记忆化搜索**。  
- **适用场景**：  
  1. 需要在序列上插入或删除元素并产生“消除”链式反应的游戏类问题（如《消消乐》《宝石迷阵》）。  
  2. 状态空间有限且可以用**哈希+递归**进行剪枝的组合优化问题。  
- **一句话总结**：**“把搜索限制在必须立即消除的关键位置，并用哈希记住已经算过的局面”**，就是本题的解题钥匙。

## 反思  

- **第一反应**：看到“插入球、消除、连锁”，立刻想到**DFS + 回溯**，于是写了全枚举的暴力解。  
- **最容易踩的坑**：  
  1. **忽视连锁消除**——只消除一次就停止，会导致搜索得不到正确的结果。  
  2. **状态重复计算**——没有记忆化会让相同的 `board+hand` 被反复搜索，导致时间爆炸。  
  3. **边界条件**：手里球用完但板子还有剩余、或者插入后立刻形成多个相邻的消除段，都需要在 `shrink` 中完整处理。  
- **下次遇到同类题**：**第一步先思考“哪一步必须产生消除”，只在这些关键点上搜索，再配合“状态记忆”避免重复**。这样既能保证完整性，又能把搜索空间压到最小。
