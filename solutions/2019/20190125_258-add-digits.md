# #258. Add Digits / Add Digits

> 难度：简单 · 标签：Math、Simulation、Number Theory · [LeetCode 链接](https://leetcode.com/problems/add-digits/)

---

## 题目（英文原版）

**Description**

Given an integer num, repeatedly add all its digits until the result has only one digit, and return it.
Follow up: Could you do it without any loop/recursion in O(1) runtime?

**Examples**

**Example 1:**

```
Input: num = 38
Output: 2
Explanation: The process is
38 --> 3 + 8 --> 11
11 --> 1 + 1 --> 2 
Since 2 has only one digit, return it.
```

**Example 2:**

```
Input: num = 0
Output: 0
```

**Constraints**

- 0 <= num <= 231 - 1

---

## 题目（中文翻译）

**描述**  
给定一个整数（integer）`num`，反复将其各位数字（digit）相加，直到结果只有一位数字为止，并返回该结果。

**示例 1**  
输入: `num = 38`  
输出: `2`  
解释: 过程如下  
```
38 --> 3 + 8 --> 11
11 --> 1 + 1 --> 2
```
由于 `2` 只有一位数字，返回它。

**示例 2**  
输入: `num = 0`  
输出: `0`

**约束条件**  
- `0 <= num <= 2^31 - 1`

**进阶**  
你能在不使用任何循环或递归且时间复杂度为 `O(1)` 的情况下完成吗？

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是把 **“把数字的每一位相加”** 这件事循环做下去，直到只剩一位为止。  
- **数据结构**：这里其实只需要整数本身和若干临时变量，和生活中的“把钱分成硬币”类似，每次只把数字拆成若干个 **位**（个位、十位、百位…），把它们相加得到新的数字，再继续操作。  
- **正确性**：只要当前数字大于等于 10（说明有两位或以上），我们就把它的每一位取出来相加，得到的和一定比原数字小。不断重复，必然会在有限步后降到 0~9 之间的单个数字，这正是题目要求的返回值。  

**时间/空间复杂度的“大白话”解释**  
- 每一次循环我们要遍历一次数字的所有位，位数大约是 `log₁₀(num)`（比如 1234 有 4 位，等价于 `log₁₀(1234) ≈ 4`）。  
- 循环的次数不会很多：每次相加后数字会显著变小，最多也只会进行几次（对 2³¹‑1≈2 147 483 647 最多 3 次）。  
- 因此整体时间可以粗略认为 **O(log n)**，即“和数字的位数成正比”。  
- 我们只用几个整数变量，**空间是 O(1)**，意思是占用的内存不随输入大小增长。

#### 代码（Python）

```python
def addDigits(num: int) -> int:
    """
    暴力模拟：不断把各位数字相加，直到结果只有一位。
    """
    # 当 num 大于等于 10 时，说明还有多位，需要继续求和
    while num >= 10:
        s = 0               # 用来累计各位数字的和
        # 逐位取出数字：%10 取最后一位，//10 去掉最后一位
        while num > 0:
            s += num % 10   # 把当前最低位加到 s 中
            num //= 10      # 删除最低位，准备取下一位
        num = s             # 把求得的和重新赋值给 num，继续外层循环
    return num               # 此时 num 已经是唯一的一位数字
```

#### 复杂度

- **时间复杂度**：`O(log n)`  
  解释：每次遍历数字的所有位，位数约等于 `log₁₀(n)`，循环次数很少（最多几次），所以整体与位数成正比。  
- **空间复杂度**：`O(1)`  
  解释：只用了常数个整数变量，内存占用不随 `num` 大小变化。

### 2. 最优解

#### 思路  

从暴力解可以看到，真正的“瓶颈”是 **循环遍历每一位**。如果我们能直接算出最终的单数字，而不进行任何循环或递归，就是最优的。  

**关键观察**：  
- 把一个数的各位相加，等价于把它在 **模 9**（余数除以 9）意义下“压缩”。  
- 这背后的数学结论叫 **数字根（digital root）**：  
  - 对任意非负整数 `n`，若 `n = 0`，数字根就是 `0`；  
  - 若 `n > 0`，数字根等于 `1 + (n - 1) % 9`。  
- 直观解释：把数字写成 `n = 9·k + r`（`r` 为余数，0 ≤ r ≤ 8），每一次把位相加的过程实际上在把 `9·k` “抵消”，只留下余数 `r`，再加上 1 的偏移得到最终结果。  

**从暴力到公式的推导**：  
1. 暴力解每次把位相加，等价于把数 **模 9**（因为 10 ≡ 1 (mod 9)，100 ≡ 1 (mod 9)…）。  
2. 于是 `num` 与它的各位和在模 9 意义下是同余的。  
3. 不断重复相加，最终得到的单数字必然是 `num` 在模 9 下的等价值。  
4. 为了兼容 `num = 0`（余数为 0 但答案应为 0），使用 `1 + (num - 1) % 9` 的写法即可。

**核心算法/数据结构**：这里不需要额外的数据结构，只用 **取模运算（%）** 和 **条件判断**，时间和空间都是常数级。

#### 代码（Python）

```python
def addDigits(num: int) -> int:
    """
    O(1) 直接算出数字根：如果 num 为 0，直接返回 0；
    否则返回 1 + (num - 1) % 9。
    """
    if num == 0:
        return 0                # 特殊情况：0 的数字根就是 0
    # 其余情况使用数字根公式
    return 1 + (num - 1) % 9
```

#### 复杂度

- **时间复杂度**：`O(1)`  
  解释：不管 `num` 多大，代码只执行几条固定的算术操作，耗时恒定。相较于暴力的 `O(log n)`，这里快了好几倍。  
- **空间复杂度**：`O(1)`  
  解释：同样只用了几个整数变量，内存占用不随输入变化。

## 反思

- **第一反应**：看到“不断把数字的每一位相加”，自然想到写一个循环把每位取出来相加，直到只剩一位。  
- **最容易踩的坑**：  
  - 忽略 `num = 0` 的特殊情况，直接使用公式会得到 9 而不是 0。  
  - 对大数直接使用 `while num >= 10` 时，若不注意整数除法会出现无限循环（比如 `num //= 10` 写成了 `num / 10`）。  
- **下次遇到同类题**，第一步应该思考 **“这个过程有没有不变式或循环不变的数学表达式？”**，尤其是涉及“数字的各位”“累计”“周期”等关键词时，往往可以用 **模运算** 或 **前缀和** 直接得到 O(1) 或 O(n) 的解法。
