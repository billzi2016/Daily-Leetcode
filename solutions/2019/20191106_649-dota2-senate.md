## 题目（英文原版）

**Description**

In the world of Dota2, there are two parties: the Radiant and the Dire.
The Dota2 senate consists of senators coming from two parties. Now the Senate wants to decide on a change in the Dota2 game. The voting for this change is a round-based procedure. In each round, each senator can exercise one of the two rights:
Given a string senate representing each senator's party belonging. The character 'R' and 'D' represent the Radiant party and the Dire party. Then if there are n senators, the size of the given string will be n.
The round-based procedure starts from the first senator to the last senator in the given order. This procedure will last until the end of voting. All the senators who have lost their rights will be skipped during the procedure.
Suppose every senator is smart enough and will play the best strategy for his own party. Predict which party will finally announce the victory and change the Dota2 game. The output should be "Radiant" or "Dire".

**Examples**

**Example 1:**

```
Input: senate = "RD"
Output: "Radiant"
Explanation: 
The first senator comes from Radiant and he can just ban the next senator's right in round 1. 
And the second senator can't exercise any rights anymore since his right has been banned. 
And in round 2, the first senator can just announce the victory since he is the only guy in the senate who can vote.
```

**Example 2:**

```
Input: senate = "RDD"
Output: "Dire"
Explanation: 
The first senator comes from Radiant and he can just ban the next senator's right in round 1. 
And the second senator can't exercise any rights anymore since his right has been banned. 
And the third senator comes from Dire and he can ban the first senator's right in round 1. 
And in round 2, the third senator can just announce the victory since he is the only guy in the senate who can vote.
```

**Constraints**

- n == senate.length
- 1 <= n <= 104
- senate[i] is either 'R' or 'D'.

## 题目（中文翻译）

在 Dota2 的世界中，存在两个阵营：光明（Radiant）和黑暗（Dire）。  
Dota2 参议院（senate）由来自这两个阵营的参议员（senator）组成。现在参议院需要就一项对 Dota2 游戏的改动进行投票。投票采用**轮次制程序（round‑based procedure）**。在每一轮中，每位参议员可以行使以下两项权利之一：

- **禁言**：禁止另一位参议员在后续轮次中行使权利。  
- **宣布胜利**：如果当前只有本阵营的参议员仍然拥有权利，则可以直接宣布本阵营获胜。

给定一个字符串 `senate`，表示每位参议员所属的阵营。字符 `'R'` 和 `'D'` 分别代表光明阵营和黑暗阵营。若有 `n` 位参议员，则字符串长度为 `n`。  
轮次制程序按照字符串中给出的顺序，从第一位参议员到最后一位依次进行。已被禁言的参议员将在后续轮次中被跳过。  
假设每位参议员都足够聪明，并会为自己所在的阵营采用最优策略。请预测最终哪一方会宣布胜利并改变 Dota2 游戏。输出应为 `"Radiant"` 或 `"Dire"`。

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  
最直接的想法就是**模拟投票过程**：  
1. 把字符串 `senate` 看成一排坐着的议员，每个人要么属于 **Radiant(R)**，要么属于 **Dire(D)**。  
2. 按顺序遍历这排人。遇到某个议员时，如果他还没有被禁权，就**把对手阵营的最近的一个议员禁掉**（把对手标记为“失去权利”），然后自己本轮结束。  
3. 完成一轮后，所有被禁掉的议员在后面的遍历里会被 **跳过**（因为他们已经没有投票权了）。  
4. 重复上面的过程，直到只剩下同一阵营的议员为止。  

> **数据结构类比**  
> - 我们用一个列表 `alive` 保存每个人是否还活着（还能投票），相当于在课堂上给每位同学发一张“通行证”，被禁掉的同学会被收回通行证。  
> - 为了找到对手的最近议员，我们每次从当前位置往后查找，直到碰到第一个对手且仍然拥有通行证的人。  

**为什么正确**  
因为每位议员都会把**对手阵营的最近**议员禁掉，这正是题目要求的“最优策略”。只要我们完整地模拟了所有回合，就一定会得到最终的胜者。

**复杂度分析（大白话）**  
- 每一轮我们都要遍历整个人数 `n`，而在最坏情况下（比如 `RRR...DDD...`）需要 **O(n)** 轮才能决定胜负。于是总的时间是 **O(n²)**，即“平方级”，随着人数增长会变得很慢。  
- 额外使用的空间只有一个长度为 `n` 的布尔数组，用来记录谁被禁掉，空间是 **O(n)**，即“线性级”。  

#### 代码（Python）  

```python
def predictPartyVictory_bruteforce(senate: str) -> str:
    n = len(senate)
    # alive[i] 为 True 表示第 i 位议员仍有投票权
    alive = [True] * n

    while True:
        # 统计当前存活的两方人数
        r_cnt = sum(alive[i] for i in range(n) if senate[i] == 'R')
        d_cnt = sum(alive[i] for i in range(n) if senate[i] == 'D')
        if r_cnt == 0:
            return "Dire"
        if d_cnt == 0:
            return "Radiant"

        # 按顺序让每位仍存活的议员行使权力
        i = 0
        while i < n:
            if not alive[i]:          # 已被禁权，直接跳过
                i += 1
                continue

            cur = senate[i]            # 当前议员的阵营
            # 在后面寻找最近的对手并禁掉
            j = (i + 1) % n
            while not (alive[j] and senate[j] != cur):
                j = (j + 1) % n        # 环形遍历，直到找到对手
            alive[j] = False           # 禁掉对手
            i += 1                     # 本轮结束，继续检查下一个位置
```

#### 复杂度  

- **时间复杂度：** `O(n²)`  
  > “平方级”意味着如果有 1000 位议员，程序大概会做 1000 × 1000 = 1 000 000 次基本操作，随着 `n` 增大，耗时会快速增长。  

- **空间复杂度：** `O(n)`  
  > 只用了一个和原字符串等长的布尔数组来记录谁被禁掉，随 `n` 成线性增长。  

---  

### 2. 最优解  

#### 思路  

从暴力解可以看到 **瓶颈** 在于：每次都要**线性扫描**去找最近的对手，这导致了 `O(n²)` 的时间。  
我们可以把“最近的对手”这个操作 **提前准备**，用 **队列**（Queue）来保存每一阵营所有仍然存活的议员的下标。  

**核心想法**：  
1. 初始化时，把所有 `'R'` 的下标放进 `queueR`，所有 `'D'` 的下标放进 `queueD`。  
2. 每轮从两个队列的 **队首** 各取出一个议员的下标 `r_idx`、`d_idx`。  
   - 下标小的那位先行动（因为在原顺序中更靠前）。  
   - 先行动的议员会**禁掉**对手，所以对手对应的下标直接被丢弃。  
   - 先行动的议员仍然存活，他会在下一轮继续投票。我们把他的下标 **加上 n**（相当于把他放到本轮结束后的“新位置”），再放回自己的队列尾部。  
3. 重复上述步骤，直到其中一个队列为空。空的队列对应的阵营已经没有议员可以投票，另一阵营获胜。  

> **数据结构类比**  
> - **队列** 就像排队买咖啡的队伍，先来的人先服务。这里 `queueR`、`queueD` 分别是 Radiant 与 Dire 的“排队名单”。  
> - 把下标加 `n` 再放回队尾，类似于“这位议员刚刚投完票，又站到了队伍的最后面，等下一轮再轮到他”。  

**为什么正确**  
- 每一次比较的两位议员恰好是本轮中 **先后出现** 的两位活跃议员。  
- 先出现的议员一定能禁止后出现的对手（因为禁止是即时生效的），这正好模拟了题目中“每位议员都能让对手失去权利”的规则。  
- 被禁止的议员的下标从队列中被移除，永远不再参与比较。  
- 通过把存活议员的下标循环加 `n`，我们实现了 **循环轮次** 的效果，而不需要真的重新遍历整个字符串。  

**复杂度直观解释**  
- 每位议员在整个过程里**最多只会被弹出一次**（被禁掉）或**被重新加入队列**若干次，但每次重新加入都伴随一次 **下标加 n**，相当于一次“移动”。  
- 所以总体操作次数是 **O(n)**，即“线性级”，随人数增长而成正比。  
- 我们只用了两个队列各保存最多 `n` 个下标，空间也是 **O(n)**。  

#### 代码（Python）  

```python
from collections import deque

def predictPartyVictory(senate: str) -> str:
    n = len(senate)

    # 1. 把所有 R、D 的位置分别放进两个队列
    queueR = deque()
    queueD = deque()
    for i, ch in enumerate(senate):
        if ch == 'R':
            queueR.append(i)          # Radiant 的第 i 位议员进入队列
        else:
            queueD.append(i)          # Dire 的第 i 位议员进入队列

    # 2. 循环比较队首元素，直到一方队列为空
    while queueR and queueD:
        r_idx = queueR.popleft()      # 取出 Radiant 当前最前面的议员
        d_idx = queueD.popleft()      # 取出 Dire 当前最前面的议员

        # 先出现的议员获胜，后出现的议员被禁掉
        if r_idx < d_idx:
            # Radiant 先投票，禁掉这位 Dire；R 议员继续存活，进入下一轮
            queueR.append(r_idx + n)   # 把他“搬到”下一轮的末尾
        else:
            # Dire 先投票，禁掉这位 Radiant；D 议员继续存活
            queueD.append(d_idx + n)

    # 3. 队列为空的一方输掉
    return "Radiant" if queueR else "Dire"
```

#### 复杂度  

- **时间复杂度：** `O(n)`  
  > “线性级”意味着如果有 10 000 位议员，最多只会进行大约 10 000 次基本的出队/入队操作，运行速度非常快。  

- **空间复杂度：** `O(n)`  
  > 两个队列合在一起最多存放 `n` 个下标，随 `n` 成正比。

## 心得  

- **核心技巧**：利用 **队列**（Queue）模拟循环投票，**贪心**地让先出现的议员禁掉后出现的对手。  
- **适用的题型**：  
  1. **Dota2 Senate**（本题）  
  2. **Monotonic Queue** 相关的“滑动窗口最大值”类问题（利用队列保持顺序）  
  3. **Circular elimination**（循环消除）类，如约瑟夫环（Josephus）问题  
- **一句话总结解题钥匙**：**把“谁先出现”转化为“谁先出队”，用队列自然完成轮次的循环**。

## 反思  

- **第一反应**：先想要**逐轮模拟**，用循环遍历和标记禁权，感觉最直接。  
- **最容易踩的坑**：  
  - **循环结束条件**：忘记在暴力实现里判断两方人数是否已为零，导致无限循环。  
  - **下标越界**：在最优解中如果不把 `n` 加到下标上，而是直接把原下标放回队列，会出现同一轮重复比较，导致错误。  
  - **特殊情况**：全是同一阵营的字符串（如 `"RRR"`），需要直接返回对应阵营。  
- **下次遇到同类题**：**第一步先思考是否可以用队列或栈把“顺序”信息保存下来**，再看是否能把“轮次”转化为“下标+长度”的方式实现循环。这样往往能把暴力的 `O(n²)` 优化到 `O(n)`。
