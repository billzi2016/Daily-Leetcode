# #485. 最大连续 1 的数量 / Max Consecutive Ones

> 难度：简单 · 标签：Array · [LeetCode 链接](https://leetcode.com/problems/max-consecutive-ones/)

---

## 题目（英文原版）

**Description**

Given a binary array nums, return the maximum number of consecutive 1's in the array.

**Examples**

**Example 1:**

```
Input: nums = [1,1,0,1,1,1]
Output: 3
Explanation: The first two digits or the last three digits are consecutive 1s. The maximum number of consecutive 1s is 3.
```

**Example 2:**

```
Input: nums = [1,0,1,1,0,1]
Output: 2
```

**Constraints**

- 1 <= nums.length <= 105
- nums[i] is either 0 or 1.

---

## 题目（中文翻译）

给定一个二进制数组（binary array）`nums`，返回数组中连续 `1` 的最大个数。

**示例 1**  
**输入**: `nums = [1,1,0,1,1,1]`  
**输出**: `3`  
**解释**: 前两个 `1` 或后面的三个 `1` 都是连续的。连续 `1` 的最大数量为 `3`。

**示例 2**  
**输入**: `nums = [1,0,1,1,0,1]`  
**输出**: `2`  

**约束条件**  

- `1 <= nums.length <= 10^5`  
- `nums[i]` 只能是 `0` 或 `1`。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**把每一个位置都当作“窗口的左边界”，从这里往右数，看看能连续得到多少个 `1`**。  
可以把数组想象成一排灯泡，`1` 代表灯亮，`0` 代表灯灭。我们把每盏灯都当成“起点”，从它开始往后数，直到遇到第一盏灭灯（`0`）为止，这段亮灯的长度就是一个“连续 1 的窗口”。遍历完所有起点后，取最大的窗口长度即为答案。

- **用到的数据结构**：只需要普通的 Python 列表（即题目给出的 `nums`），不需要额外的结构。  
- **为什么正确**：每一种可能的连续 `1` 子数组一定会有一个左端点，而我们把所有左端点都枚举了一遍，所以必然能找到最长的那段。  

**时间/空间复杂度**  
- 对每个起点都要往右遍历，最坏情况下（全是 `1`）第一个起点会遍历 `n` 次，第二个起点遍历 `n‑1` 次……，总共大约是 `n + (n‑1) + … + 1 = n·(n+1)/2` 次操作，记作 **O(n²)**，即“平方级”，当 `n` 很大时会变得很慢。  
- 只用了常数个额外变量（计数器、最大值），所以 **空间复杂度 O(1)**，即“常数级”，不随输入规模增长。

#### 代码（Python）

```python
def findMaxConsecutiveOnes_bruteforce(nums):
    """
    暴力解法：枚举每一个左端点，向右计数连续的 1
    """
    n = len(nums)
    max_len = 0                     # 记录目前为止出现的最大长度
    for i in range(n):              # i 是窗口的左边界
        cur_len = 0                  # 当前窗口的长度
        # 从左边界 i 开始向右遍历，直到遇到 0 为止
        for j in range(i, n):
            if nums[j] == 1:         # 仍然是 1，窗口可以继续扩大
                cur_len += 1
            else:                    # 遇到 0，当前窗口结束
                break
        # 更新全局最大值
        if cur_len > max_len:
            max_len = cur_len
    return max_len
```

#### 复杂度  

- **时间复杂度**：O(n²) —— “如果 n=10,000，算法大约要做 100,000,000 次比较”。  
- **空间复杂度**：O(1) —— 只用了几个整数变量，不会随 `n` 增长。

### 2. 最优解

#### 思路  

从暴力解可以看出，**瓶颈在于每次都要从左端点重新遍历右边**。其实我们不需要每次都重新计数，只要在一次遍历中**实时维护当前连续 `1` 的长度**即可。

具体做法：

1. 用一个变量 `cur` 记录**当前正在进行的连续 `1` 的长度**。  
   - 当遍历到 `1` 时，`cur += 1`，表示窗口继续扩大。  
   - 当遍历到 `0` 时，说明当前窗口结束，`cur` 必须清零（`cur = 0`），因为后面可能会出现新的窗口。

2. 用另一个变量 `best` 记录**遇到的最大 `cur`**。每次 `cur` 更新后，比较 `best = max(best, cur)`。

这相当于在数组上**滑动一个“看不见的窗口”**，窗口的左边界会在遇到 `0` 时自动“跳过去”。我们只需要一次线性扫描（**双指针**的极简形式），时间从 O(n²) 降到 **O(n)**。

**类比**：想象你在看一串灯泡，手里拿着一个计数器。只要灯亮（`1`），计数器就加一；灯灭（`0`）时，你把计数器归零，重新开始计数。整个过程只需要走一遍灯串。

#### 代码（Python）

```python
def findMaxConsecutiveOnes(nums):
    """
    最优解：一次遍历，实时维护当前连续 1 的长度和历史最大长度
    """
    best = 0   # 记录全局最大连续 1 的数量
    cur = 0    # 记录当前窗口（从最近的 0 之后开始）的连续 1 的数量

    for num in nums:          # 逐个检查数组元素
        if num == 1:          # 碰到 1，当前窗口长度加一
            cur += 1
            # 如果当前长度已经超过历史最大，立即更新 best
            if cur > best:
                best = cur
        else:                 # 碰到 0，当前窗口结束，长度归零
            cur = 0

    return best
```

#### 复杂度  

- **时间复杂度**：O(n) —— “只走一遍数组”。当 `n=100,000` 时，只需要 100,000 次比较，速度非常快。  
- **空间复杂度**：O(1) —— 只用了两个整数变量 `best`、`cur`，不随输入规模增长。

## 心得

- **核心技巧**：一次遍历中实时维护“当前状态 + 最优值”，这是一种常见的**滑动窗口/计数器**技巧。  
- **适用的题型**：  
  1. **最长连续子数组**（如 `Maximum Consecutive Ones`、`Longest Subarray of 1s after Deleting One Element`）。  
  2. **子数组和满足条件**（如 `Maximum Size Subarray Sum Equals k`，使用前缀和+哈希表）。  
  3. **字符/数组的连续相同元素计数**（如 `Longest Substring Without Repeating Characters` 的变形）。  
- **一句话总结解题钥匙**：**“一次遍历，遇 1 加，遇 0 清；同步更新最大值”。**

## 反思

- **第一反应**：看到“连续 1”，立刻想到“计数器”或者“窗口”。  
- **最容易踩的坑**：  
  - 忘记在遇到 `0` 时把计数器归零，导致错误地把两段不相连的 `1` 合并。  
  - 边界情况：全是 `1`（需要返回整个数组长度）或全是 `0`（返回 `0`），代码必须能正确处理。  
- **下次遇到同类题的第一步**：先判断“状态转移点”（这里是 `0`），决定在遍历中**何时累加、何时重置**，然后在同一次遍历中记录历史最优。
