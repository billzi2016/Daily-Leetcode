## 题目（英文原版）

**Description**

The Fibonacci numbers, commonly denoted F(n) form a sequence, called the Fibonacci sequence, such that each number is the sum of the two preceding ones, starting from 0 and 1. That is,
Given n, calculate F(n).

**Examples**

**Example 1:**

```
F(0) = 0, F(1) = 1
F(n) = F(n - 1) + F(n - 2), for n > 1.
```

**Example 2:**

```
Input: n = 2
Output: 1
Explanation: F(2) = F(1) + F(0) = 1 + 0 = 1.
```

**Example 3:**

```
Input: n = 3
Output: 2
Explanation: F(3) = F(2) + F(1) = 1 + 1 = 2.
```

**Example 4:**

```
Input: n = 4
Output: 3
Explanation: F(4) = F(3) + F(2) = 2 + 1 = 3.
```

**Constraints**

- 0 <= n <= 30

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是**递归**：  
- 斐波那契数列的定义本身就是 `F(n) = F(n-1) + F(n-2)`（当 `n>1` 时），这条公式把大问题直接拆成两个更小的子问题。  
- 我们可以把每一次求 `F(k)` 看成一次“求答案”的请求，如果 `k` 已经是 0 或 1，直接返回 0 或 1（这相当于递归的终止条件）。  
- 否则，就递归求 `F(k-1)` 和 `F(k-2)`，再把两者相加得到 `F(k)`。

> **类比**：把求斐波那契想象成在森林里找宝藏。要找到第 `k` 块宝藏，你必须先找到第 `k-1` 块和第 `k-2` 块宝藏，然后把它们的价值相加。每次去找更小的宝藏，直到遇到最底层的两块（第 0 块和第 1 块），它们的价值已经写在石碑上，直接拿来用。

这个方法 **一定** 正确，因为它完全遵循了题目给出的递推关系，没有漏掉任何情况。

#### 代码（Python）

```python
def fib_brute(n: int) -> int:
    """暴力递归求第 n 项斐波那契数"""
    # 递归的终止条件：0 和 1 已知
    if n == 0:
        return 0          # 第 0 项是 0
    if n == 1:
        return 1          # 第 1 项是 1

    # 递归调用：把大问题拆成两个更小的问题
    return fib_brute(n - 1) + fib_brute(n - 2)
```

#### 复杂度  

- **时间复杂度：** `O(2^n)`  
  - 这里的 `2^n` 并不是说真的有 2 的 n 次方个循环，而是说**递归树的节点数会指数级增长**。每一次调用会产生两个子调用，树的高度是 `n`，所以总节点数大约是 `2^n`。可以把它想象成“每走一步，你的脚会分裂成两只”，很快就会有很多脚在工作，导致耗时爆炸。

- **空间复杂度：** `O(n)`  
  - 递归调用会占用系统栈（函数调用的记录），最深的递归层数是 `n`，所以最多需要 `n` 层栈空间。可以把它看成“你一次只能记住多少层的路线”，这里最多记 `n` 层。

### 2. 最优解

#### 思路  

从暴力递归我们可以看到 **两大瓶颈**：

1. **大量重复计算**：例如求 `F(5)` 时，会分别计算 `F(4)`、`F(3)`，而 `F(4)` 又会再次计算 `F(3)`、`F(2)`，导致 `F(3)` 被算了两次，`F(2)` 甚至被算了三次。重复的子问题让时间呈指数级增长。

2. **递归调用的栈开销**：每一次递归都要保存现场，层数深了会占用较多栈空间。

要优化，思路是**把已经算过的结果记下来**，以后再需要时直接取，用 **“记忆化”**（Memoization）或 **“自底向上”**（Dynamic Programming）的方法。

下面分别介绍两种常见的最优写法，都是 **O(n)** 时间、**O(1)** 或 **O(n)** 空间的解法。

---

#### 2.1 记忆化递归（自上而下）

- 思路：用一个字典（或列表）把已经算过的 `F(k)` 保存下来。  
- 当递归到 `k` 时，先检查字典里有没有结果，有的话直接返回，没有才继续递归并把结果存进去。  
- 这相当于“把已经找过的宝藏位置标记在地图上”，以后再来就不必重新找。

#### 代码（Python）

```python
def fib_memo(n: int, memo: dict = None) -> int:
    """记忆化递归求斐波那契数，时间 O(n)，空间 O(n)"""
    if memo is None:
        memo = {}                     # 用来存已经算好的结果

    # 递归终止条件
    if n == 0:
        return 0
    if n == 1:
        return 1

    # 如果已经算过，直接返回，避免重复计算
    if n in memo:
        return memo[n]

    # 否则递归计算，并把结果放进 memo
    memo[n] = fib_memo(n - 1, memo) + fib_memo(n - 2, memo)
    return memo[n]
```

---

#### 2.2 动态规划（自底向上）——只用常数空间

- 思路：从已知的 `F(0)`、`F(1)` 开始，逐步向上计算 `F(2) … F(n)`。  
- 只需要保留最近两个数，因为下一个数只和这两个有关。  
- 用两个变量 `a`、`b` 滚动更新，类似“把两只小青蛙向前跳”，每跳一次就把前面的两只青蛙的距离相加得到新位置。

#### 代码（Python）

```python
def fib_dp(n: int) -> int:
    """动态规划（滚动数组）求斐波那契数，时间 O(n)，空间 O(1)"""
    if n == 0:
        return 0
    if n == 1:
        return 1

    a, b = 0, 1          # a = F(0), b = F(1)
    for i in range(2, n + 1):
        a, b = b, a + b   # 计算 F(i)；b 成为新的 F(i)，a 成为旧的 F(i-1)
    return b
```

#### 复杂度  

- **时间复杂度：** `O(n)`  
  - 只循环 `n-1` 次，每一次都是常数时间的加法。把指数级的递归树压缩成一条直线，像“一条直路走到终点”。

- **空间复杂度：**  
  - 记忆化递归：`O(n)`（需要存 `n` 个子问题的结果）。  
  - 动态规划滚动数组：`O(1)`（只用两个变量，不随 `n` 增长）。

相比暴力递归，**时间快了几百倍**，空间也更友好。

## 心得

- **核心技巧**：**记忆化**（把子问题的答案缓存）或 **动态规划**（自底向上逐步构造答案）。  
- **适用的题型**：  
  1. 爬楼梯（`Climbing Stairs`）——每一步可以爬 1 或 2 阶。  
  2. 硬币兑换（`Coin Change`）——求最少硬币数。  
  3. 最大子序和（`Maximum Subarray`）——利用滚动变量求最优子段。  
- **一句话总结**：**把“重复劳动”变成“查表”或“顺序累加”，就能把指数时间压到线性时间。**

## 反思

- **第一反应**：看到递推公式 `F(n)=F(n-1)+F(n-2)`，脑子里立刻浮现递归的画面。  
- **最容易踩的坑**：  
  - **忘记递归终止条件**，导致无限递归（栈溢出）。  
  - **没有缓存**，导致大量重复计算，运行超时。  
  - **边界值**：`n=0`、`n=1` 时直接返回，别让循环或递归进入错误分支。  
- **下次遇到同类题**，第一步应该思考：“这个递推关系会产生很多重复子问题吗？”如果答案是“会”，立刻考虑 **记忆化** 或 **动态规划**。这样可以快速把暴力思路升级到最优解。
