## 题目（中文翻译）

给定一个整数数组 `nums` 和一个整数 `k`，如果 `nums` 中存在满足条件的「好子数组」则返回 `true`，否则返回 `false`。

**好子数组** 是满足以下条件的子数组（subarray）：

* 子数组的长度至少为 2；
* 子数组中所有元素的和是 `k` 的整数倍，即 `sum % k == 0`（当 `k != 0` 时）；
* 当 `k == 0` 时，要求子数组的元素和恰好为 0。

> 注意：子数组必须是连续的。

---

### 示例

**示例 1**  
**输入**: `nums = [23,2,4,6,7]`, `k = 6`  
**输出**: `true`  
**解释**: `[2, 4]` 是一个长度为 2 的连续子数组，其元素之和为 6，恰为 `k` 的整数倍。

**示例 2**  
**输入**: `nums = [23,2,6,4,7]`, `k = 6`  
**输出**: `true`  
**解释**: `[23, 2, 6, 4, 7]` 是一个长度为 5 的连续子数组，其元素之和为 42。  
42 是 6 的整数倍，因为 `42 = 7 * 6`，且 7 为整数。

**示例 3**  
**输入**: `nums = [23,2,6,4,7]`, `k = 13`  
**输出**: `false`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  
最直接的办法就是把所有可能的连续子数组都枚举出来，算出它们的和，然后判断这个和是否是 `k` 的倍数（即 `sum % k == 0`）。  
- **数据结构**：我们只需要一个普通的列表 `nums`，遍历时用两个循环来表示子数组的左、右端点。  
- **为什么正确**：只要遍历到了所有长度≥2 的子数组，就一定会检查到题目要求的“好子数组”。只要其中有一个满足 `sum % k == 0`，我们立刻返回 `True`，否则遍历结束返回 `False`。  
- **复杂度分析**：  
  - 外层循环 `i` 从 `0` 到 `n-2`，内层循环 `j` 从 `i+1` 到 `n-1`，总共大约会执行 `n*(n-1)/2` 次，也就是 **O(n²)**。  
  - 对每个子数组我们都要累加一次和，最坏情况下会再次遍历 `j-i+1` 个元素，整体仍然是二次量级。  
  - 只用了常数级的额外空间（几个计数器），所以 **空间复杂度是 O(1)**。  
> **大白话**：如果把数组想象成一排糖果，暴力解就是把每一对左、右手指（左端点、右端点）都拿出来尝一次，看糖果总甜度能不能被 `k` 整除。糖果多了，尝的次数就会呈二次增长，慢慢吃不完。

#### 代码（Python）

```python
def checkSubarraySum_bruteforce(nums, k):
    n = len(nums)
    # i 为子数组左端点
    for i in range(n - 1):
        cur_sum = nums[i]                     # 从 i 开始累计和
        # j 为子数组右端点，必须保证子数组长度 ≥ 2
        for j in range(i + 1, n):
            cur_sum += nums[j]                # 累计到右端点 j
            if cur_sum % k == 0:              # 判断是否为 k 的倍数
                return True
    return False
```

#### 复杂度

- **时间复杂度**：`O(n²)` — 随着数组长度 `n` 增大，运算次数大约是 `n` 的平方。比如 `n=10,000` 时，需要检查约 5 亿次，明显不可接受。  
- **空间复杂度**：`O(1)` — 只用了几个整数变量，不会随 `n` 增大而增加额外内存。

---

### 2. 最优解

#### 思路  

暴力解慢的根源在于**每次都重新累加子数组的和**。如果我们能在遍历一次的过程中，快速判断“从某个左端点到当前右端点的子数组和是否能被 k 整除”，就能把时间降到线性。

**关键数学事实**  
设 `pre[i]` 为前 `i` 个数的累计和（`pre[0]=0`），则子数组 `nums[l…r]` 的和等于 `pre[r+1] - pre[l]`。  
要让这个和是 `k` 的倍数，只需要：

```
(pre[r+1] - pre[l]) % k == 0
⇔ pre[r+1] % k == pre[l] % k
```

也就是说，只要两个前缀和的 **余数相同**，它们之间的子数组和就一定是 `k` 的倍数。

**如何利用**  
我们在一次遍历中维护：
1. 当前前缀和对 `k` 的余数 `mod = pre % k`（把大数“压缩”到 `[0, k-1]` 范围）。  
2. 一个哈希表 `pos`，记录每个余数第一次出现的位置（对应的前缀下标）。  
   - 哈希表就像一本“余数字典”，`key` 是余数，`value` 是它第一次出现的下标。  
3. 当我们在位置 `i`（对应 `pre[i+1]`）看到余数 `mod` 已经在字典里出现过，且两次出现的下标相差 **≥2**（保证子数组长度至少为 2），说明找到了满足条件的子数组，直接返回 `True`。

**特殊情况**  
- 当 `k == 0` 时（本题约束 `k ≥ 1`，但实际 LeetCode 可能出现），我们只能检查是否存在连续两个元素的和为 0。这里不展开，直接按 `k > 0` 处理。  
- 余数为负数的情况：Python 的 `%` 操作已经把负数映射到 `[0, k-1]`，所以不需要额外处理。

**类比**：把前缀余数想成“一把钥匙”。只要同一把钥匙出现两次，而且这两次之间隔了至少两格（两位数），就能打开“好子数组”的门。

#### 代码（Python）

```python
def checkSubarraySum(nums, k):
    """
    使用前缀和 + 哈希表（余数字典）实现 O(n) 时间解法
    """
    mod_pos = {0: -1}          # 余数 0 在位置 -1 处出现（方便处理从下标 0 开始的子数组）
    prefix = 0                # 当前累计和

    for i, num in enumerate(nums):
        prefix += num
        mod = prefix % k       # 只保留余数，等价于把大数压缩到 0~k-1

        if mod in mod_pos:
            # 之前出现过相同余数，检查间隔是否 ≥ 2
            if i - mod_pos[mod] >= 2:
                return True
        else:
            # 只记录第一次出现的位置，后面出现的若距离太短不影响答案
            mod_pos[mod] = i

    return False
```

#### 复杂度

- **时间复杂度**：`O(n)` — 只遍历一次数组，哈希表的查询、插入都是常数时间。  
  > 与暴力 `O(n²)` 对比：当 `n` 从 10⁴ 增长到 10⁵ 时，线性算法仍然只需要约 10⁵ 次操作，几乎是瞬间完成。  
- **空间复杂度**：`O(min(k, n))` — 最坏情况下哈希表会存储每个不同余数，一共至多 `k` 种（`k` 可能很大），但实际只会出现不超过 `n+1` 种余数，所以空间随 `n` 线性增长，仍然是可接受的。  
  > 对于本题的约束（`k` ≤ 2³¹‑1），实际占用的空间主要取决于数组长度 `n`，最多几百 KB。

## 心得

- **核心技巧**：利用前缀和的余数相等判定“子数组和能被 k 整除”。  
- **适用题型**：  
  1. “子数组和为 K 的倍数” 类似题（本题）。  
  2. “找出和为 K 的连续子数组” （如 LeetCode 560 Subarray Sum Equals K）。  
  3. “最长连续子数组满足模条件” （如 LeetCode 974 Subarray Sums Divisible by K）。  
- **一句话总结**：把“子数组和能被 k 整除”转化为“前缀余数相同”，用哈希表一次遍历即能找出答案。

## 反思

- **第一反应**：直接想枚举所有子数组——这在面试里常常会被卡在超时。  
- **最容易踩的坑**：  
  - 忘记子数组长度必须 ≥ 2，导致错误返回 `True`（例如只取单个元素）。  
  - 余数为负数的处理（在某些语言需要手动把负余数转成正数）。  
  - `k == 0` 的特殊判断（虽然本题约束排除了，但实际面试中要留意）。  
- **下次遇到同类题的第一步**：先思考“前缀和 + 模运算”是否能把子数组的条件转化为前缀之间的等价关系，再决定是否使用哈希表记录第一次出现的位置。
