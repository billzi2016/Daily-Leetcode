# #647. 回文子串 / Palindromic Substrings

> 难度：中等 · 标签：Two Pointers、String、Dynamic Programming · [LeetCode 链接](https://leetcode.com/problems/palindromic-substrings/)

---

## 题目（英文原版）

**Description**

Given a string s, return the number of palindromic substrings in it.
A string is a palindrome when it reads the same backward as forward.
A substring is a contiguous sequence of characters within the string.

**Examples**

**Example 1:**

```
Input: s = "abc"
Output: 3
Explanation: Three palindromic strings: "a", "b", "c".
```

**Example 2:**

```
Input: s = "aaa"
Output: 6
Explanation: Six palindromic strings: "a", "a", "a", "aa", "aa", "aaa".
```

**Constraints**

- 1 <= s.length <= 1000
- s consists of lowercase English letters.

---

## 题目（中文翻译）

给定一个字符串 `s`，返回其中回文子串（palindromic substrings）的数量。  
当一个字符串正着读和倒着读完全相同，则称其为回文（palindrome）。  
子串（substring）是字符串中连续的字符序列。

**示例 1**  
Input: s = "abc"  
Output: 3  
Explanation: 三个回文子串，分别是 `"a"`、`"b"`、`"c"`。

**示例 2**  
Input: s = "aaa"  
Output: 6  
Explanation: 六个回文子串，分别是 `"a"`、`"a"`、`"a"`、`"aa"`、`"aa"`、`"aaa"`。

**约束条件**  
- 1 ≤ s.length ≤ 1000  
- s 仅由小写英文字母组成。

---

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**枚举所有子串**，然后逐个判断它是不是回文。  
- **枚举子串**：我们可以用两个下标 `i`（子串起点）和 `j`（子串终点）遍历所有可能的 `i ≤ j`，这相当于把字符串的每一段都挑出来看看。  
- **判断回文**：判断一个子串是否是回文，只需要把它从左往右和从右往左各读一遍，看看对应字符是否相等。可以把子串复制出来后用双指针 `l`、`r` 向中间收敛比较，或者直接把子串翻转后比较（`sub == sub[::-1]`）。

> **类比**：把哈希表想象成一本字典，key 是单词，value 是页码；这里我们用的“子串”就像字典里每一页的文字，遍历所有页再检查每页的文字是否正着读和倒着读一样。

**为什么这个方法正确**  
只要我们把每一种可能的子串都检查了一遍，所有的回文子串自然都会被计数。没有遗漏，也没有多算。

**时间/空间复杂度**  
- 枚举子串有 `n`（字符串长度）个起点，每个起点最多有 `n` 个终点，总共约 `n²` 种组合。  
- 对每个子串判断回文需要最坏 `O(k)` 的时间，其中 `k` 是子串长度，平均下来仍然是 `O(n)`（因为最长的子串是 `n`，最短的是 `1`）。  
- 因此整体时间复杂度是 **`O(n³)`**，在最坏情况下相当于“千层饼”——每层都要遍历完整个饼。  
- 额外空间只用来存放临时子串，最坏 `O(n)`（复制最长子串），整体空间复杂度是 **`O(n)`**。

#### 代码（Python）

```python
def countSubstrings_brute(s: str) -> int:
    n = len(s)
    ans = 0

    # 枚举所有子串的左端点 i
    for i in range(n):
        # 枚举所有子串的右端点 j（包含 i 本身）
        for j in range(i, n):
            sub = s[i:j+1]          # 取出子串
            # 用双指针检查 sub 是否是回文
            l, r = 0, len(sub) - 1
            is_pal = True
            while l < r:
                if sub[l] != sub[r]:
                    is_pal = False
                    break
                l += 1
                r -= 1
            if is_pal:
                ans += 1             # 计数

    return ans
```

#### 复杂度

- **时间复杂度**：`O(n³)`  
  - `n²` 个子串 × 最多 `n` 步的回文检查。  
  - “n³” 可以理解为：如果字符串长度是 100，最坏要检查 1,000,000 次字符比较。

- **空间复杂度**：`O(n)`  
  - 只用了临时子串 `sub`，最长不超过原字符串长度 `n`。

### 2. 最优解

#### 思路  

暴力解的**瓶颈**在于每次都要重新检查整个子串是否回文。其实，判断一个更大的子串是否回文，只要**利用它内部已经确认的子串**的信息，就可以快速得到答案。

两种常见的优化思路：

1. **动态规划（DP）**  
   - 设 `dp[i][j]` 表示子串 `s[i…j]` 是否是回文（`True/False`）。  
   - 状态转移：  
     - 当 `s[i] == s[j]` 且 `j - i <= 2`（长度为 1、2 或 3）时，`dp[i][j] = True`。  
     - 否则，`dp[i][j] = dp[i+1][j-1]`（只要内部子串 `s[i+1…j-1]` 已经是回文，就可以“套”出更外层的回文）。  
   - 通过从短到长的顺序填表，所有 `dp[i][j]` 只会被访问一次，整体时间 `O(n²)`，空间 `O(n²)`（可以进一步压缩到 `O(n)`，但这里先保持易懂的二维表）。

2. **中心扩展（双指针）**  
   - 每个回文都有一个“中心”。中心可以是一个字符（奇数长度回文）也可以是两个相邻字符之间的空隙（偶数长度回文）。  
   - 对每个可能的中心，向左、向右同时展开，只要左右字符相等，就找到一个回文子串并计数。  
   - 由于每次展开最多遍历整个字符串，所有中心共 `2n-1` 个，整体时间 `O(n²)`，但只用了常数级别的额外空间 `O(1)`，是最常用的最优实现。

下面重点讲解**中心扩展**，因为它实现简洁、空间友好，而且概念直观。

**核心概念——中心扩展**  
想象你手里有一根尺子，尺子左端指向字符 `l`，右端指向字符 `r`。如果 `s[l] == s[r]`，说明这两个字符可以“包围”一个回文；于是我们把尺子再向外展开一格，继续比较 `s[l-1]` 与 `s[r+1]`。每一次成功比较，就多出一个回文子串。

**步骤**  
1. 遍历所有可能的中心位置 `center`（从 `0` 到 `2·n-2`，这里把奇偶中心统一到一个循环里）。  
2. 根据 `center` 的奇偶性决定左、右指针的初始位置：  
   - 奇数中心 `center % 2 == 0` → 左右指针同指向同一个字符 `center//2`（奇数长度回文）。  
   - 偶数中心 `center % 2 == 1` → 左指针指向 `center//2`，右指针指向 `center//2 + 1`（偶数长度回文）。  
3. 只要 `l ≥ 0`、`r < n` 且 `s[l] == s[r]`，计数 `ans += 1`，然后 `l -= 1, r += 1` 继续展开。  
4. 最终 `ans` 即为所有回文子串的数量。

> **类比**：把每个字符想象成一颗“树”，回文就是两棵树之间对称的“枝叶”。从树干（中心）向外生长，只要两侧的枝叶相同，就能形成一个完整的对称结构。

#### 代码（Python）

```python
def countSubstrings(s: str) -> int:
    n = len(s)
    ans = 0

    # 一共 2n-1 个中心（包括字符本身和字符之间的空隙）
    for center in range(2 * n - 1):
        # 根据中心是奇数还是偶数，决定左、右指针的初始位置
        left = center // 2                     # 左指针
        right = left + (center % 2)            # 右指针，奇数中心时与 left 相同，偶数中心时右移一位

        # 向外扩展，只要左右字符相等就说明找到了一个回文子串
        while left >= 0 and right < n and s[left] == s[right]:
            ans += 1                           # 计数当前这个回文
            left -= 1                          # 左指针左移
            right += 1                         # 右指针右移

    return ans
```

#### 复杂度

- **时间复杂度**：`O(n²)`  
  - 外层遍历 `2n-1` 个中心，内层每次最多向外展开 `n` 步。整体相当于“每个字符最多被比较 n 次”，所以是二次方。  
  - 与暴力解相比，从 `n³` 降到了 `n²`，大幅提升。可以把 `n²` 想成“如果 n=1000，最多检查 1,000,000 次字符”，在机器里几毫秒就能完成。

- **空间复杂度**：`O(1)`  
  - 只用了几个整数指针 (`left`, `right`, `center`) 和计数器 `ans`，不随输入规模增长。

## 心得

- **核心技巧**：**中心扩展**（或等价的动态规划）——把大问题拆成“以中心为基准向外扩展”的小问题，利用已经验证的回文属性快速判断更大的回文。
- **适用题型**  
  1. **最长回文子串**（LeetCode 5）——同样用中心扩展，只是要记录最长的长度/起始位置。  
  2. **回文划分**（LeetCode 131）——需要先用 DP 或中心扩展预处理所有回文子串，然后做分割。  
  3. **回文对**（LeetCode 336）——利用回文判断的技巧，结合哈希表或 Trie 加速查找。
- **一句话总结**：  
  “回文的本质是‘两边对称’，只要从中心向两侧展开比较，就能一次性捕获所有回文子串。”

## 反思

- **拿到题目第一反应**：直接枚举所有子串，然后逐个检查回文——最自然的暴力思路。
- **最容易踩的坑**  
  - **边界条件**：奇数长度和偶数长度的回文中心不同，需要分别处理，否则会漏掉 `aa`、`aba` 之类的情况。  
  - **计数重复**：如果在枚举子串时忘记去重，可能会把相同的回文子串计多次。  
  - **时间超限**：`O(n³)` 的暴力实现对 `n=1000` 会超时，需要意识到“检查回文的代价太高”。  
- **下次遇到同类题**，第一步应该思考**“是否可以用中心/子结构复用来降低检查成本？”**，即寻找可以**从小到大递推**或**从中心向外扩展**的特性。
