## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是把所有可能的**连续子数组**都枚举出来，逐个求和，看看是否等于 `k`。  
- **枚举子数组**：我们可以用两个循环，外层 `i` 表示子数组的左端点，内层 `j` 表示右端点（左闭右开区间 `[i, j)`）。  
- **求和**：在每一次内层循环里，把 `nums[i:j]` 的所有元素相加，得到子数组的和。  

这就像我们在看一本书，想找出所有连续的页码段，使得这些页码的总数等于某个目标值。我们把每一种可能的起始页码 `i` 和结束页码 `j` 都尝试一次，虽然慢，但一定能得到正确答案。

> **为什么正确**：因为我们遍历了所有合法的连续子数组，任何满足条件的子数组都会被检查到。

#### 代码（Python）

```python
def subarraySum_brute(nums, k):
    n = len(nums)
    ans = 0                      # 记录满足条件的子数组个数
    for i in range(n):           # 左端点 i
        cur_sum = 0               # 累计从 i 开始的子数组和
        for j in range(i, n):    # 右端点 j（包含 j）
            cur_sum += nums[j]    # 动态累计和，省去每次重新求和的开销
            if cur_sum == k:      # 如果当前子数组和等于 k
                ans += 1
    return ans
```

#### 复杂度  

- **时间复杂度**：`O(n²)`  
  - “O” 代表“量级”。`n²` 表示当数组长度 `n` 翻倍时，运行时间会增加到原来的 **四倍**（因为 `n²` 与 `n` 的平方成正比）。这里我们用了两层循环，最坏情况下要检查 `n*(n+1)/2 ≈ n²/2` 个子数组，所以是二次方的时间。
- **空间复杂度**：`O(1)`  
  - 只用了常数级别的额外变量 (`ans`, `cur_sum`)，不随输入规模增长。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**重复累加**：每次移动左端点 `i` 时，我们都要重新把后面的元素一次次相加。  
如果能够**一次遍历**就知道“以当前元素结尾的所有子数组的和”是多少，就可以省掉内层循环。

**关键观察**  
设 `pre[x]` 为数组前 `x` 个元素的**前缀和**（`pre[0]=0`，`pre[1]=nums[0]`，…），则  
```
子数组 nums[i:j]（左闭右开）的和 = pre[j] - pre[i]
```
我们要找的是满足 `pre[j] - pre[i] = k` 的 `(i, j)` 对。  
等价于：**在遍历到位置 j 时，找出之前出现过多少次前缀和为 `pre[j] - k`**。

于是我们只需要在遍历数组的过程中，维护一个**哈希表**（Python 的 `dict`），记录每个前缀和出现的次数。  
- 哈希表的键：前缀和的数值  
- 哈希表的值：该前缀和出现的次数  

遍历步骤：
1. `cur_sum` 累加当前元素得到新的前缀和。  
2. 检查 `cur_sum - k` 是否已经在哈希表中出现过——如果出现 `cnt` 次，说明有 `cnt` 个左端点使得子数组和为 `k`。把 `cnt` 加到答案里。  
3. 把当前的 `cur_sum` 加入哈希表（出现次数+1），为后面的元素提供参考。  

> **类比**：哈希表就像一本“前缀和字典”，键是“页码”，值是“这页码出现了多少次”。每当我们翻到新的一页（新的前缀和），就去字典里找“当前页码 - k”出现了多少次，找到的次数就是满足条件的子数组数。

#### 代码（Python）

```python
def subarraySum(nums, k):
    """
    返回子数组和恰好等于 k 的个数
    """
    from collections import defaultdict

    prefix_cnt = defaultdict(int)   # 前缀和出现次数的哈希表
    prefix_cnt[0] = 1                # 空前缀和 0 出现一次，方便处理从下标 0 开始的子数组
    cur_sum = 0                      # 当前遍历到的位置的前缀和
    ans = 0

    for idx, num in enumerate(nums):
        cur_sum += num                # 更新前缀和

        # 需要的左端点前缀和是 cur_sum - k
        need = cur_sum - k
        if need in prefix_cnt:       # 如果出现过，就说明找到了若干满足条件的子数组
            ans += prefix_cnt[need]  # 累加出现次数

        # 把当前前缀和加入哈希表，供后续使用
        prefix_cnt[cur_sum] += 1

    return ans
```

#### 复杂度  

- **时间复杂度**：`O(n)`  
  - 只遍历一次数组，哈希表的查找/插入都是 `O(1)`（均摊），所以整体是线性时间。相比暴力的 `O(n²)`，当 `n` 很大时，运行速度提升了 **数量级**（比如 `n=10⁴` 时，`n²≈10⁸` 次运算 vs `n≈10⁴` 次）。
- **空间复杂度**：`O(n)`  
  - 最坏情况下每个前缀和都不相同，需要在哈希表中保存 `n+1` 条记录（包括初始的 0），所以使用的额外空间随输入规模线性增长。

## 心得

- **核心技巧**：前缀和 + 哈希表（统计前缀和出现次数）  
- **适用的题型**：  
  1. “子数组和等于目标值”类（如 LeetCode 560、713）  
  2. “最长子数组和为 K”或“子数组和不超过 K”之类的变形  
  3. “数组中出现次数相同的子数组”等需要统计区间和的题目  
- **一句话总结**：把“子数组和 = k”转化为“前缀和差 = k”，用哈希表一次遍历统计即可。

## 反思

- **第一反应**：直接写两层循环枚举所有子数组（暴力），因为最直观。  
- **最容易踩的坑**：  
  - 忘记把初始前缀和 `0` 放进哈希表，导致以数组开头为左端点的合法子数组漏计。  
  - 负数的出现会破坏“滑动窗口”思路，需要使用前缀和+哈希表这种对正负数都适用的方法。  
  - 哈希表计数要在 **更新前** 先查询 `cur_sum - k`，否则会把当前元素本身算进来产生错误计数。  
- **下次第一步**：先思考“能否把区间求和转化为前缀和的差”，如果可以，立刻考虑用哈希表统计前缀和出现次数。这样往往能把 `O(n²)` 的暴力降到 `O(n)`。
