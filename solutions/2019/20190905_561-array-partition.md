# #561. 数组分割 / Array Partition

> 难度：简单 · 标签：Array、Greedy、Sorting、Counting Sort · [LeetCode 链接](https://leetcode.com/problems/array-partition/)

## 题目（英文原版）

**Description**

Given an integer array nums of 2n integers, group these integers into n pairs (a1, b1), (a2, b2), ..., (an, bn) such that the sum of min(ai, bi) for all i is maximized. Return the maximized sum.

**Examples**

**Example 1:**

```
Input: nums = [1,4,3,2]
Output: 4
Explanation: All possible pairings (ignoring the ordering of elements) are:
1. (1, 4), (2, 3) -> min(1, 4) + min(2, 3) = 1 + 2 = 3
2. (1, 3), (2, 4) -> min(1, 3) + min(2, 4) = 1 + 2 = 3
3. (1, 2), (3, 4) -> min(1, 2) + min(3, 4) = 1 + 3 = 4
So the maximum possible sum is 4.
```

**Example 2:**

```
Input: nums = [6,2,6,5,1,2]
Output: 9
Explanation: The optimal pairing is (2, 1), (2, 5), (6, 6). min(2, 1) + min(2, 5) + min(6, 6) = 1 + 2 + 6 = 9.
```

**Constraints**

- 1 <= n <= 104
- nums.length == 2 * n
- -104 <= nums[i] <= 104

## 题目（中文翻译）

**题目描述**  
给定一个包含 `2n` 个整数的整数数组（integer array）`nums`，将这些整数分成 `n` 对 `(a₁, b₁), (a₂, b₂), …, (aₙ, bₙ)`，使得所有 `i` 的 `min(aᵢ, bᵢ)`（即每对中的较小值）的和最大化。返回该最大化后的和。

**示例 1**  
```
Input: nums = [1,4,3,2]
Output: 4
Explanation: 所有可能的配对方式（忽略元素顺序）如下：
1. (1, 4), (2, 3) → min(1, 4) + min(2, 3) = 1 + 2 = 3  
2. (1, 3), (2, 4) → min(1, 3) + min(2, 4) = 1 + 2 = 3  
3. (1, 2), (3, 4) → min(1, 2) + min(3, 4) = 1 + 3 = 4  
因此最大可能的和为 4。
```

**示例 2**  
```
Input: nums = [6,2,6,5,1,2]
Output: 9
Explanation: 最优的配对方式为 (2, 1), (2, 5), (6, 6)。  
min(2, 1) + min(2, 5) + min(6, 6) = 1 + 2 + 6 = 9。
```

**约束条件**  
- `1 ≤ n ≤ 10⁴`  
- `nums.length == 2 * n`  
- `-10⁴ ≤ nums[i] ≤ 10⁴`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：把数组 `nums` 中的 `2n` 个数全部枚举所有可能的配对方式，然后计算每种配对下 `min(ai, bi)` 的和，取最大值。

- **数据结构**：我们可以用 **列表** 来保存当前的配对，用 **递归**（深度优先搜索）把所有可能的配对路径走一遍。  
  - 把配对看成把「人」两两配对，递归每次挑选两个未配对的「人」形成一对，继续往下配对，直到所有人都配对完毕。  
  - 这类似于「查字典」的过程，只是这里的“键”是未配对的下标， “值”是配对的结果。

- **为什么正确**：因为我们遍历了**所有**合法的配对方式，必然会碰到最优的那一种，取最大即可。

- **时间/空间复杂度**  
  - 配对的种类是 **(2n)! / (2^n * n!)**（即把 `2n` 个元素两两分组的全排列数），随 `n` 指数级增长。  
  - 用大白话说，`O((2n)!)` 就像把一大堆积木全部排成所有可能的形状，根本不可能在合理时间内完成。  
  - 空间上我们只需要保存递归栈和当前配对，最多 `O(n)`。

#### 代码（Python）

```python
from typing import List

def array_pair_sum_brute(nums: List[int]) -> int:
    """
    暴力搜索所有配对方式，返回最大 min(ai, bi) 的和。
    仅用于演示思路，时间复杂度极高，实际不可用。
    """
    n = len(nums) // 2
    used = [False] * len(nums)          # 记录哪些下标已经配对
    best = 0                            # 保存全局最大值

    def dfs(pairs_done: int, cur_sum: int):
        """深度优先搜索，pairs_done 已配对的组数，cur_sum 当前 min 的累计和"""
        nonlocal best
        # 所有 n 组都配对完毕，更新答案
        if pairs_done == n:
            best = max(best, cur_sum)
            return

        # 找第一个未配对的下标 i
        i = 0
        while i < len(nums) and used[i]:
            i += 1
        used[i] = True                    # 标记 i 已配对

        # 把 i 与后面的每一个未配对的 j 配成一对，递归搜索
        for j in range(i + 1, len(nums)):
            if not used[j]:
                used[j] = True
                # 当前这对的贡献是 min(nums[i], nums[j])
                dfs(pairs_done + 1, cur_sum + min(nums[i], nums[j]))
                used[j] = False           # 回溯，撤销配对

        used[i] = False                   # 回溯，撤销 i 的配对标记

    dfs(0, 0)
    return best
```

#### 复杂度

- **时间复杂度**：`O((2n)! / (2^n * n!))`，即所有可能配对的数量，随 `n` 指数级增长。  
  > 用大白话说，这相当于“尝遍所有可能的配对方式”，即使 `n=10` 也会花上几分钟甚至更久。

- **空间复杂度**：`O(n)`，递归栈深度最多 `n`（每层配好一对），以及 `used` 数组 `O(2n)`，合并后仍是线性。

### 2. 最优解

#### 思路  

从暴力解可以看到，**枚举所有配对是不可行的**，瓶颈在于组合数量爆炸。我们需要找一种 **一次遍历就能得到最优答案** 的策略。

观察题目：  
- 对于每一对 `(a, b)`，只有较小的那个 `min(a, b)` 会被计入答案，较大的那个被“牺牲”。  
- 为了让 **更多更大的数** 能够成为 `min`，我们应该 **把大数和更大的数配在一起**，这样牺牲的仍然是大的数，而不是把大数配给小数，让小数占据 `min` 的位置。

最直观的做法是 **把数组从小到大排序**，然后 **相邻两个数配成一对**：

```
排序后：x1 <= x2 <= x3 <= x4 <= ... <= x_{2n}
配对方式： (x1, x2), (x3, x4), ..., (x_{2n-1}, x_{2n})
```

此时每一对的 `min` 正好是左边的那个数 `x_{2k-1}`，把所有左边的数相加即可得到最大和。

**为什么这样最优？**  
- 把数组排序后，任意两数配对若不相邻（比如 `x_i` 与 `x_j`，`j > i+1`），则必然会把 `x_{i+1}` 与更大的数配对，使得 `x_{i+1}` 成为 `min` 的机会被浪费（因为它本可以作为 `min` 与 `x_i` 配对），从而导致整体和变小。  
- 形式化的证明可以用 **交换论证**：若存在一种配对方式不是相邻配对，必然可以通过交换元素使得总和不减，并且交换次数有限，最终得到相邻配对的形式。因此相邻配对是最优的。

**核心算法**：排序 + 线性遍历。  
- 排序使用 Python 内置的 Timsort，时间复杂度 `O(2n log(2n))`。  
- 遍历一次取每隔一个的元素求和，时间 `O(n)`。

**类比**：把数组看成一排排书，想让“最小的那本书”被计入价值，就把相邻的两本书放在一起，左边那本自然是更小的，左边的所有书加起来就是最大价值。

#### 代码（Python）

```python
from typing import List

def array_pair_sum(nums: List[int]) -> int:
    """
    贪心+排序：把相邻的两个数配对，累加左边的数即得到最大和。
    时间复杂度 O(N log N)，空间复杂度 O(1)（不计排序的栈空间）。
    """
    nums.sort()                     # 原地排序，最小的在前
    ans = 0
    # 取下标为 0,2,4,... 的元素（每对的左边元素）
    for i in range(0, len(nums), 2):
        ans += nums[i]              # nums[i] 正好是这一对的 min
    return ans
```

#### 复杂度

- **时间复杂度**：`O(N log N)`，其中 `N = 2n` 为数组长度。  
  > “`log N`” 相当于把数据分成若干层逐层合并，类似把一大堆纸张折叠成更小的堆，整个过程比直接枚举所有配对快得多。

- **空间复杂度**：`O(1)`（若算 Python 排序的递归栈，最多 `O(log N)`），因为我们只使用了常数级的额外变量。

## 心得

- **核心技巧**：**贪心 + 排序**。先把数据排好序，再用最直接的配对方式即可得到最优解。  
- **适用的题型**  
  1. “最大化最小值” 类题目，例如 **数组分割**（把数组分成两半，使得第一半的和最小化）。  
  2. “配对求和” 类题目，如 **最大化配对和**（把两组数配对，使得每对的和最大）。  
  3. **分配资源** 场景：把小的需求配给小的资源，大的需求配给大的资源，常用贪心+排序。  
- **一句话总结**：**把数组排好序，偶数下标的元素累加，即是答案**——排序让“最小的”自然落在每对的左边，从而最大化整体和。

## 反思

- **第一反应**：看到“最大化 `min(ai, bi)` 的和”，第一想法是穷举配对，但很快意识到组合数太大，必须找规律。  
- **最容易踩的坑**  
  - 忽略负数：即使数组里有负数，排序后仍然相邻配对是最优的，因为负数的大小顺序同样适用。  
  - 边界条件：`n = 1` 时只会有两个数，直接返回较小的那个，代码仍然适用。  
  - 对于 `nums.length` 为偶数的前提一定要检查，题目已保证。  
- **下次类似题的第一步**：先 **思考“把大的配给大的， 小的配给小的”**，看能否通过 **排序** 把问题变成“一次遍历就能求解”。如果可以，说明贪心+排序很可能是最优解。
