# #483. 最小好进制 / Smallest Good Base

> 难度：困难 · 标签：Math、Binary Search · [LeetCode 链接](https://leetcode.com/problems/smallest-good-base/)

---

## 题目（英文原版）

**Description**

Given an integer n represented as a string, return the smallest good base of n.
We call k >= 2 a good base of n, if all digits of n base k are 1's.

**Examples**

**Example 1:**

```
Input: n = "13"
Output: "3"
Explanation: 13 base 3 is 111.
```

**Example 2:**

```
Input: n = "4681"
Output: "8"
Explanation: 4681 base 8 is 11111.
```

**Example 3:**

```
Input: n = "1000000000000000000"
Output: "999999999999999999"
Explanation: 1000000000000000000 base 999999999999999999 is 11.
```

**Constraints**

- n is an integer in the range [3, 1018].
- n does not contain any leading zeros.

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

把 “好进制” 的定义展开一下：  
如果一个整数 `n` 在进制 `k` 下的每一位都是 `1`，则它的展开式是  

```
n = 1 + k + k² + k³ + … + k^(m-1)
```

其中 `m` 表示 `1` 出现的次数（也就是位数），`m ≥ 2`，`k ≥ 2`。  

最直接的想法就是：**枚举所有可能的位数 `m`，再枚举所有可能的进制 `k`，检验上面的等式是否成立**。  
这相当于把 “找进制” 的问题变成 “找两个正整数 `m、k` 使等式成立”。  

- **枚举 `m`**：因为 `k ≥ 2`，所以 `1 + 2 + 2² + … + 2^(m-1) = 2^m - 1 ≤ n`。  
  只要 `2^m - 1 ≤ n`，`m` 就有可能出现。`m` 的最大值大约是 `log₂(n)`（二进制位数），最多只有 60 左右（因为 `n ≤ 10^18`）。
- **枚举 `k`**：对固定的 `m`，我们可以把等式改写成  

  ```
  k^(m-1) + k^(m-2) + … + k + 1 = n
  ```

  这里的 `k` 必须是整数。最粗暴的办法是从 `2` 开始一直尝试到 `n`（显然不可能这么大），每次把等式左边算出来，看是否等于 `n`。

因为我们只需要 **找到最小的好进制**，所以从小的 `m`（位数多的情况）往大枚举，一旦找到对应的 `k`，就可以直接返回。

> **生活化类比**：  
> 把 `k` 想成一本词典的“页码”。我们想找一本词典，使得从第一页到第 `m` 页（每页只记一个词）加起来正好是 `n`。暴力解法就是把每一本可能的词典（每一种 `k`）都打开，逐页相加，看看是否恰好得到 `n`。

#### 代码（Python）

```python
def smallestGoodBase_bruteforce(n_str: str) -> str:
    n = int(n_str)                       # 把字符串转成整数，后面要算幂
    # m 表示“111…1”里 1 的个数，最小是 2（因为 k>=2 必须至少两位）
    max_m = n.bit_length()               # log2(n) 向上取整，等价于二进制位数
    for m in range(max_m, 1, -1):        # 从大位数往小位数枚举（位数大对应的进制更小）
        # k 的取值范围：2 到 n 的 m 次方根（因为 k^(m-1) <= n）
        low, high = 2, int(pow(n, 1/(m-1))) + 1
        while low <= high:               # 这里仍然是暴力枚举，实际可以二分，但保持最原始思路
            k = low
            # 计算等式左边的和：1 + k + k^2 + ... + k^(m-1)
            total = 0
            cur = 1
            for _ in range(m):
                total += cur
                cur *= k
                if total > n:            # 提前退出，防止不必要的运算
                    break
            if total == n:                # 找到匹配的 k
                return str(k)
            low += 1                      # 继续尝试下一个 k
    return str(n - 1)                     # 必然有一种形式：n = 1 + (n-1) ，对应进制 n-1
```

> **代码要点注释**  
> - `n.bit_length()` 返回 `n` 的二进制位数，即 `⌊log₂ n⌋+1`，帮助我们限定 `m` 的上界。  
> - `pow(n, 1/(m-1))` 计算 `n` 的 `(m-1)` 次方根，得到 `k` 的大致上限。  
> - 内层 `for` 循环逐项累加 `1 + k + k² + …`，如果途中已经超过 `n`，就可以提前退出，省点时间。  

#### 复杂度

- **时间复杂度**：  
  - 最外层 `m` 的取值大约是 `log₂ n`（约 60 次）。  
  - 对每个 `m`，我们仍然要从 `k = 2` 逐个尝试到 `k ≈ n^(1/(m-1))`。在最坏情况下（比如 `m = 2`）这个上限是 `n` 本身，导致 **O(n)** 的尝试次数。  
  - 再乘上每次求和的 `O(m)`，整体是 **O(n·log n)**，对 `n ≤ 10^18` 完全不可接受。  
  - 用大白话说，就是“要遍历几乎所有的整数”，根本跑不完。

- **空间复杂度**：  
  - 只用了常数级别的变量（`total、cur、k` 等），所以是 **O(1)**。

> 暴力解虽然概念最直接，但在本题的规模下根本不可行，只能作为思考的起点。下面我们来找出瓶颈并优化。

---

### 2. 最优解

#### 思路  

**瓶颈在哪里？**  
- 暴力解把 **`k` 的枚举** 当成线性搜索（`k = 2,3,4,…`），导致时间爆炸。  
- 实际上，对于固定的位数 `m`，`k` 的取值范围是一个 **有序的区间**，我们可以用二分搜索（Binary Search）在这个区间里快速定位。

**核心观察**  
- 对于任意 `m ≥ 2`，如果存在整数 `k ≥ 2` 使得  

  ```
  1 + k + k² + … + k^(m-1) = n
  ```

  那么 `k` 必然满足  

  ```
  2 ≤ k ≤ n^(1/(m-1))
  ```

  因为左边的最大项是 `k^(m-1)`，它必须不超过 `n`。  
- `m` 的可能取值仍然只有 `log₂ n`（约 60）个。我们从 **最大可能的 `m` 开始往下枚举**（位数多对应的进制更小），一旦找到对应的 `k`，就是最小好进制，直接返回即可。

**二分搜索求 `k`**  
对于固定的 `m`，我们在区间 `[2, n^(1/(m-1))]` 上做二分：

1. 取中点 `mid` 作为候选进制 `k`。  
2. 用等比数列求和公式（或逐项累加）计算  

   ```
   sum = 1 + k + k² + … + k^(m-1)
   ```

   - 为防止 Python 的整数溢出（其实 Python 整数是大数），但仍要避免 **计算过程中的过大数**，我们在累加时若发现 `sum > n` 就可以直接返回 “太大”。  
3. 比较 `sum` 与 `n`：  
   - `sum == n` → 找到答案，返回 `k`。  
   - `sum < n` → 说明 `k` 太小，需要把搜索区间右移 (`low = mid + 1`)。  
   - `sum > n` → `k` 太大，左移 (`high = mid - 1`)。  

二分搜索的时间复杂度是 `O(log upper)`，而 `upper ≈ n^(1/(m-1))`，对大 `m` 来说上限非常小（甚至只有个位数），整体非常快。

**为什么要从大 `m` 开始？**  
- `m` 越大，等式左边的项数越多，**对应的进制 `k` 越小**。  
- 我们要求 **最小的好进制**，所以只要先找到一个合法的 `k`，它一定是全局最小的。于是从最大 `m`（即位数最多）往下尝试，一旦成功就可以直接结束。

**完整步骤**  

1. 把输入的字符串 `n_str` 转成整数 `n`（Python 的 `int` 能直接处理 10^18）。  
2. 计算 `max_m = n.bit_length()`（二进制位数），因为 `2^max_m - 1` 已经超过 `n`，所以 `max_m` 是可能的最大位数。  
3. 对 `m` 从 `max_m` 递减到 `2`：  
   - 设 `low = 2`，`high = int(n ** (1/(m-1))) + 1`（防止浮点误差）。  
   - 在 `[low, high]` 上二分搜索 `k`，每次用**安全的累加**判断 `sum` 与 `n` 的大小。  
   - 若找到 `k`，返回 `str(k)`。  
4. 如果所有 `m` 都没有找到（理论上不会出现），则返回 `str(n-1)`，因为 `n = 1 + (n-1)` 对应进制 `n-1` 总是合法的。

**类比帮助理解**  
想象你在找一把“正好能把 `n` 块糖果均匀分成 `m` 堆，每堆糖果数递增 1 的秤”。  
- `m` 决定你要几堆糖果（堆数越多，单堆的糖果数越少）。  
- `k` 就是“每堆之间的比例”。我们先猜堆数 `m`（从多到少），再在可能的比例范围里二分找出恰好能把糖果全部分完的那个比例 `k`。

#### 代码（Python）

```python
def smallestGoodBase(n_str: str) -> str:
    n = int(n_str)                     # 大整数，Python 能直接处理
    max_m = n.bit_length()             # 可能的最大位数（约 log2 n）

    # 从最多位数（对应最小进制）开始尝试
    for m in range(max_m, 1, -1):
        # k 的上界是 n 的 (m-1) 次方根，取整后加 1 防止误差
        low, high = 2, int(pow(n, 1.0 / (m - 1))) + 1

        # 在 [low, high] 区间二分搜索 k
        while low <= high:
            k = (low + high) // 2

            # 计算 1 + k + k^2 + ... + k^(m-1)，若途中超过 n 提前结束
            total = 1
            cur = 1
            for _ in range(1, m):
                cur *= k                # cur = k^i
                total += cur
                if total > n:           # 已经大于 n，说明 k 太大
                    break

            if total == n:              # 找到恰好等于 n 的进制
                return str(k)
            elif total < n:             # k 太小，需要往右找
                low = k + 1
            else:                       # total > n，k 太大，需要往左找
                high = k - 1

    # 没有找到更小的进制时，必有 n = 1 + (n-1) 的形式，对应进制 n-1
    return str(n - 1)
```

> **代码要点**  
> - `n.bit_length()` 相当于 `⌊log₂ n⌋ + 1`，帮助我们限定位数上限。  
> - `pow(n, 1.0/(m-1))` 用浮点数求根，可能会出现误差，所以取整后 **+1** 再作为上界，保证真实解一定在搜索区间内。  
> - 累加求和的循环最多执行 `m-1 ≤ max_m ≈ 60` 次，极其轻量。  
> - 二分搜索的循环次数是 `log₂(high - low + 1)`，在最坏情况下也不过几百次，整体运行时间在毫秒级。

#### 复杂度

- **时间复杂度**：  
  - `m` 的循环次数是 `O(log n)`（约 60）。  
  - 对每个 `m`，二分搜索的次数是 `O(log n^(1/(m-1))) = O(log n / (m-1))`。  
  - 每次二分内部的求和最多 `m` 次。  
  - 综合下来整体是 **O((log n)²)**，对 `n ≤ 10^18` 来说约几千次运算，完全可以接受。  
  - 用大白话说，就是“只需要把 10^18 这棵大树的高度（约 60）遍历几遍，每遍只做几次二分查找”，非常快。

- **空间复杂度**：  
  - 只用了几个整数变量，**O(1)**，不随 `n` 的大小增长。

## 心得

- **核心技巧**：把 “所有位都是 1” 的等式转化为等比数列求和，再利用 **二分搜索** 在可能的进制范围内快速定位。  
- **适用的题型**：  
  1. “找满足某种等式的进制” 类问题（如 LeetCode 1025 `Divisor Game` 的变形）。  
  2. “在单调函数上寻找特定值” 的二分搜索题（如 744 `Find Smallest Letter Greater Than Target`、702 `Search in a Sorted Array of Unknown Size`）。  
- **一句话总结**：**把未知进制转成单调函数，二分定位，即可快速得到最小好进制**。

## 反思

- **第一反应**：看到“所有位都是 1”，立刻把它写成等比数列求和公式，想到枚举位数和进制的双重循环。  
- **最容易踩的坑**：  
  - **浮点求根误差**：直接使用 `int(n ** (1/(m-1)))` 可能会因为精度问题把真实上界算得太小，导致漏掉正确的 `k`。解决办法是 **+1** 再做二分。  
  - **大数累加溢出**：虽然 Python 整数不溢出，但在累加时若已经超过 `n`，继续乘幂会产生非常大的数，浪费时间。应在循环中提前 `break`。  
  - **位数的上界**：忘记用 `log₂ n`（即 `bit_length`）来限制 `m`，会导致不必要的循环。  
- **下次类似题的第一步**：先把题目中的“所有位相同”或“满足某种模式”写成 **数学等式**，检查该等式随进制的单调性，随后考虑 **二分搜索** 或 **单调栈** 等高效手段来求解。
