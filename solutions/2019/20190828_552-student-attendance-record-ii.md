## 题目（中文翻译）

学生的出勤记录可以用一个字符串来表示，其中每个字符分别表示学生当天是缺勤、迟到还是出勤。记录只会包含以下三种字符：

- `'A'`：Absent（缺勤）  
- `'L'`：Late（迟到）  
- `'P'`：Present（出勤）  

满足以下两个条件的学生才有资格获得出勤奖励：

1. 记录中 **最多只能出现一次** `'A'`（缺勤）。  
2. 记录中 **连续的 `'L'`（迟到）不能超过两天**。  

给定整数 `n`，返回长度为 `n`、能够使学生符合奖励资格的所有可能出勤记录的数量。由于答案可能非常大，请返回结果对 **10^9 + 7** 取模后的值。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是把所有可能的出勤记录都列举出来，然后把不符合条件的剔除掉。  
- **数据结构**：我们可以把每一天的状态当成一个字符，`'P'`（出勤）、`'A'`（缺勤）和`'L'`（迟到）。把 n 天的记录想象成一个长度为 n 的“单词”，字母表只有这 3 个字母。  
- **遍历方式**：使用深度优先搜索（DFS）或递归，依次在每一天尝试放 `'P'`、`'A'`、`'L'`，把所有长度为 n 的单词生成出来。  
- **合法性检查**：在生成过程中随时统计已经出现的 `'A'` 次数（不能超过 1 次）以及当前连续 `'L'` 的个数（不能达到 3）。只要发现已经不可能满足条件，就提前剪枝。  

这样做肯定能得到正确答案，因为我们把**所有**可能的记录都遍历了一遍，并且只保留了符合题目要求的记录。

#### 代码（Python）

```python
MOD = 10 ** 9 + 7

def brute_force(n: int) -> int:
    """返回长度为 n 的合法记录数（仅用于说明，实际会超时）"""
    ans = 0                     # 用来累计合法记录的个数

    def dfs(day: int, a_cnt: int, l_consec: int):
        """在第 day 天之前已经构造好记录
        a_cnt   : 已经出现的缺勤 A 的次数（0 或 1）
        l_consec: 当前连续迟到 L 的个数（0、1、2）"""
        nonlocal ans
        if day == n:            # 已经构造满 n 天
            ans = (ans + 1) % MOD
            return

        # 1. 放 'P'（出勤），不会改变 a_cnt，也不会影响连续 L 的计数
        dfs(day + 1, a_cnt, 0)

        # 2. 放 'L'（迟到），只能在连续 L 未到达 2 时放
        if l_consec < 2:
            dfs(day + 1, a_cnt, l_consec + 1)

        # 3. 放 'A'（缺勤），只能在还没有缺勤过时放
        if a_cnt == 0:
            dfs(day + 1, 1, 0)

    dfs(0, 0, 0)
    return ans
```

> **注**：这段代码在 `n` 很小（如 `n ≤ 5`）时还能跑完，但当 `n` 增大到几百甚至上千时，递归树的节点数会接近 `3ⁿ`，根本不可能在合理时间内算完。

#### 复杂度  

- **时间复杂度**：`O(3^n)`。因为每一天都有 3 种选择，最坏情况下会遍历所有 3ⁿ 条记录。用大白话说，就是“指数级增长”，即使 `n=20` 也会产生约 3.5 亿次递归调用，根本跑不完。  
- **空间复杂度**：`O(n)`。递归栈的深度最多为 `n`，每层只保存几个整数，整体占用的额外空间与 `n` 成线性关系。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**枚举所有可能**，而我们只关心**合法状态的计数**。  
观察题目可以发现，判断一条记录是否合法只需要关心两件事：

1. 已经出现了多少次缺勤 `'A'`（只能是 0 或 1）  
2. 当前连续迟到 `'L'` 的长度（只能是 0、1、2）

这两个信息足以决定接下来还能放哪些字符，也就是说**状态空间非常小**（2 × 3 = 6 种），与天数 `n` 没有关系。于是我们可以用**动态规划（DP）**把每一天的合法记录数累加起来。

---

##### 2.1 DP 状态定义  

`dp[i][a][l]` 表示 **前 i 天**（`i` 从 0 开始计数，`i=0` 表示还没有任何天）  
- `a` 为已经出现的缺勤次数，取值 `0` 或 `1`  
- `l` 为第 i 天结束时**连续**迟到的天数，取值 `0、1、2`  

`dp[i][a][l]` 的意义是：满足条件的记录数。

---

##### 2.2 初始状态  

- 当 `i = 0`（还没有天数）时，唯一合法的“空记录”是 `dp[0][0][0] = 1`。  
- 其它状态均为 0，因为没有天数不可能出现缺勤或迟到。

---

##### 2.3 状态转移  

在第 `i` 天（已经有 `i` 天的合法记录）要再添加第 `i+1` 天的字符，分三种可能：

| 放的字符 | 条件 | 新的状态 (`a' , l'`) | 转移公式 |
|----------|------|----------------------|----------|
| `'P'`（出勤） | 永远可以放 | `a' = a`<br>`l' = 0` | `dp[i+1][a][0] += dp[i][a][l]` |
| `'L'`（迟到） | 只能在 `l < 2` 时放 | `a' = a`<br>`l' = l + 1` | `dp[i+1][a][l+1] += dp[i][a][l]` |
| `'A'`（缺勤） | 只能在 `a == 0` 时放 | `a' = 1`<br>`l' = 0` | `dp[i+1][1][0] += dp[i][0][l]` |

每一次转移后都要对 `10⁹+7` 取模，以防整数溢出。

---

##### 2.4 空间优化  

上述 DP 只依赖前一天的状态 (`i`) 来计算下一天 (`i+1`) 的值，因此可以**滚动数组**只保留两层，甚至进一步压缩到 **6 个变量**（因为 `a`、`l` 的组合只有 6 种）。这样空间复杂度从 `O(n·6)` 降到 `O(1)`。

---

##### 2.5 最终答案  

遍历完 `n` 天后，所有合法记录的数量就是 `dp[n][a][l]`（`a∈{0,1}`，`l∈{0,1,2}`）的总和。

---

#### 代码（Python）

```python
MOD = 10 ** 9 + 7

def checkRecord(n: int) -> int:
    """
    返回长度为 n 的合法出勤记录数，时间 O(n)，空间 O(1)。
    """
    # dp[a][l] 表示当前已经处理了 i 天后，缺勤次数为 a，连续迟到天数为 l 的记录数
    dp = [[0] * 3 for _ in range(2)]   # 2 行（a=0/1），3 列（l=0/1/2）
    dp[0][0] = 1                       # 空记录

    for day in range(n):
        ndp = [[0] * 3 for _ in range(2)]   # 用来存储第 day+1 天的状态

        for a in range(2):          # a = 0 或 1
            for l in range(3):      # l = 0、1、2
                cur = dp[a][l]
                if cur == 0:
                    continue

                # 1) 放 'P'，连续迟到归零，缺勤次数不变
                ndp[a][0] = (ndp[a][0] + cur) % MOD

                # 2) 放 'L'，只能在 l < 2 时放
                if l < 2:
                    ndp[a][l + 1] = (ndp[a][l + 1] + cur) % MOD

                # 3) 放 'A'，只能在还没有缺勤过时放
                if a == 0:
                    ndp[1][0] = (ndp[1][0] + cur) % MOD

        dp = ndp   # 前进到下一天

    # 把所有合法状态加在一起即为答案
    ans = 0
    for a in range(2):
        for l in range(3):
            ans = (ans + dp[a][l]) % MOD
    return ans
```

> **代码解读**  
> - `dp` 是一个 **2 × 3** 的小表格，行对应已经出现的缺勤次数（0/1），列对应当前连续迟到的天数（0/1/2）。  
> - 循环 `for day in range(n)` 把天数从 0 推进到 `n-1`，每一步都根据前面表格的 6 项值，计算出新表格 `ndp` 的 6 项。  
> - 每次转移后都取模，防止数字爆炸。  
> - 最后把 6 项相加得到答案。

---

#### 复杂度  

- **时间复杂度**：`O(n)`。我们只遍历 `n` 次，每次对 6 种状态做常数次更新。用大白话说，就是“随着天数线性增长”，即使 `n = 10⁵` 也只会执行约 600 000 次简单运算，毫秒级即可完成。  
- **空间复杂度**：`O(1)`。只用到固定大小的 2 × 3 表格（6 个整数），与 `n` 大小无关。相比暴力解的递归栈，这几乎不占内存。

## 心得

- **核心技巧**：把“只能出现一次 A 且 L 不能连续出现 3 次”抽象为**有限状态机**，用 DP 统计状态转移的方案数。  
- **适用的题型**：  
  1. “字符串/序列满足某些局部约束”的计数题（如 “最长不含连续 3 个相同字符的二进制序列”）  
  2. “限制出现次数或连续次数”的组合计数（如 “最多 k 次翻转的二进制序列”）  
  3. “带有有限记忆的路径计数” (比如网格走法中只能连续走左/右/上/下特定次数)  
- **一句话总结**：**把“只能出现几次”或“连续出现几次”的规则转化为状态，动态规划在状态空间上做加法即可。**

## 反思

- **第一反应**：看到“最多一次 A”和“连续 L 不能超过 2”，立刻想到 **枚举所有序列**，但很快意识到指数级爆炸。  
- **最容易踩的坑**：  
  - 忘记对 `10⁹+7` 取模，导致 Python 整数过大或结果错误。  
  - 在转移 `'L'` 时忘记检查 `l < 2`，会产生非法的 “LLL”。  
  - 统计答案时遗漏了 `a = 0` 与 `a = 1` 两种情况，导致结果偏小。  
- **下次类似题的第一步**：先**抽象出有限状态**（缺勤次数、连续迟到次数等），确认状态数量是常数级的，然后再写 DP 或矩阵快速幂。这样既能保证正确性，又能在 O(n)（甚至 O(log n)）时间内完成。
