# #628. 三个数的最大乘积 / Maximum Product of Three Numbers

> 难度：简单 · 标签：Array、Math、Sorting · [LeetCode 链接](https://leetcode.com/problems/maximum-product-of-three-numbers/)

## 题目（英文原版）

**Description**

Given an integer array nums, find three numbers whose product is maximum and return the maximum product.

**Examples**

**Example 1:**

```
Input: nums = [1,2,3]
Output: 6
```

**Example 2:**

```
Input: nums = [1,2,3,4]
Output: 24
```

**Example 3:**

```
Input: nums = [-1,-2,-3]
Output: -6
```

**Constraints**

- 3 <= nums.length <= 104
- -1000 <= nums[i] <= 1000

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：把数组里所有可能的 **三个数** 组合都枚举一遍，算出它们的乘积，最后把最大值返回。

- **数据结构**：我们只需要原来的列表 `nums`，不需要额外的结构。可以把它想象成一排水果，直接用手去挑出任意三颗水果进行“混合”（乘积）。
- **正确性**：因为我们遍历了 **所有** 三元组，必然会包含最优的那一组，所以最终的最大乘积一定被找到。
- **复杂度分析**：  
  - 外层循环遍历第一个数，第二层遍历第二个数，第三层遍历第三个数。三个循环套在一起，时间随 `n` 的立方增长，用大写的 **O(n³)** 表示。  
  - 这里的 **O(n³)** 可以直观地理解为：如果数组有 1000 个元素，算法大概会执行 1000 × 1000 × 1000 = 10⁹ 次乘法运算，明显太慢。  
  - 只用了常数级别的额外变量（最大乘积、循环计数），所以空间复杂度是 **O(1)**，即“几乎不占额外内存”。

#### 代码（Python）

```python
from typing import List

def maximumProduct_brute(nums: List[int]) -> int:
    n = len(nums)
    max_prod = float('-inf')          # 先设为负无穷，保证第一次比较会被更新

    # 三层循环枚举所有三元组 (i, j, k)
    for i in range(n - 2):            # 第一个数，最多到倒数第三个
        for j in range(i + 1, n - 1): # 第二个数，必须在 i 之后
            for k in range(j + 1, n): # 第三个数，必须在 j 之后
                prod = nums[i] * nums[j] * nums[k]  # 计算当前三数的乘积
                if prod > max_prod:                 # 如果更大，就更新答案
                    max_prod = prod
    return max_prod
```

#### 复杂度

- **时间复杂度**：`O(n³)` —— 需要遍历所有 `C(n,3)`（即 n 选 3）种组合，随 `n` 的立方增长。  
- **空间复杂度**：`O(1)` —— 只用了几个额外的整型变量，不随输入规模扩大。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **三层循环**，它把大量不必要的工作都算了一遍。实际上，要得到最大乘积，只需要关心 **极端的几个数**：

1. **最大的三个数**：如果数组里全是正数，显然这三个数的乘积最大。  
2. **最小的两个数 + 最大的一个数**：如果数组里有负数，两个负数相乘会变成正数，甚至比三个最大的正数还大。例如 `[-10, -10, 5, 2]`，最大乘积是 `(-10) * (-10) * 5 = 500`。

因此，只要找出：

- 前 **3 个最大值**（记作 `max1 ≥ max2 ≥ max3`）  
- 前 **2 个最小值**（记作 `min1 ≤ min2`）  

答案就是 `max(max1*max2*max3, min1*min2*max1)`。

**获取这些极值的两种常见方式**：

- **排序**：把数组从小到大排好序，最大三个数就是最后三个，最小两个数就是前两个。时间 `O(n log n)`（排序的代价），空间 `O(1)`（原地排序）。
- **一次遍历**：在一次线性扫描中同步维护最大三位和最小两位，时间 `O(n)`，空间 `O(1)`。这里我们采用 **排序**，因为思路更直观，适合初学者。

> 类比：把一堆石头从小到大排成一列，想要挑出最重的三块或最轻的两块再加上最重的一块，直接看排好的顺序就行了，不必每次都去“掂”所有可能的组合。

#### 代码（Python）

```python
from typing import List

def maximumProduct(nums: List[int]) -> int:
    # 1. 对数组进行原地排序（从小到大）
    nums.sort()                       # 时间 O(n log n)，空间 O(1)（Python 的 Timsort 需要 O(n) 辅助空间，但这里忽略）

    # 2. 取出关键的几个数
    max1, max2, max3 = nums[-1], nums[-2], nums[-3]   # 最大的三个
    min1, min2 = nums[0], nums[1]                     # 最小的两个

    # 3. 两种可能的最大乘积取最大值
    product1 = max1 * max2 * max3          # 全部正数或最大的三个数
    product2 = min1 * min2 * max1          # 两个负数和最大的正数

    return max(product1, product2)         # 直接返回更大的那个
```

#### 复杂度

- **时间复杂度**：`O(n log n)` —— 主要耗时在排序，`log n` 表示“对数”，可以理解为把 `n` 个数分层比较，每层只需要线性时间，总共大约是 `n` 乘以一个很小的常数（约 17 次比较当 `n=10⁵`）。  
  与暴力的 `O(n³)` 相比，提升非常明显，`10⁴` 的数组从 **十亿次**运算降到 **几万次**。
- **空间复杂度**：`O(1)`（不计入排序本身的临时空间）——只用了常数个变量来保存极值。

## 心得

- **核心技巧**：**只关注极端值**（最大/最小），利用负数相乘会变正的特性。  
- **适用的题型**  
  1. “最大/最小子数组乘积”  
  2. “数组中两数之和最大” 类似的“极值组合”问题  
  3. “找出两个数的最大差值” 等需要挑选少数关键元素的题目  
- **一句话总结**：**先把问题压缩到“几个关键数”，再直接算**。

## 反思

- **第一反应**：看到“三个数的乘积”，自然想到“三层循环”穷举。  
- **最容易踩的坑**  
  - 忽视负数：两个负数相乘会变正，可能比三个正数更大。  
  - 边界条件：数组长度恰好是 3 时，直接返回这三个数的乘积，不需要额外判断。  
  - 排序后取值的下标错误（尤其是负数最小的两个要取 `nums[0]`、`nums[1]`，而不是 `nums[-1]`、`nums[-2]`）。  
- **下次思考路线**：看到“最大/最小”这类要求时，先问自己“是否只需要极端的几个元素”，再决定是 **排序** 还是 **一次遍历** 来获取这些元素。这样可以迅速避开暴力的时间陷阱。
