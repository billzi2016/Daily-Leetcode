## 题目（英文原版）

**Description**

Design and implement a data structure for a Least Frequently Used (LFU) cache.
Implement the LFUCache class:
To determine the least frequently used key, a use counter is maintained for each key in the cache. The key with the smallest use counter is the least frequently used key.
When a key is first inserted into the cache, its use counter is set to 1 (due to the put operation). The use counter for a key in the cache is incremented either a get or put operation is called on it.
The functions get and put must each run in O(1) average time complexity.

**Examples**

**Example 1:**

```
Input
["LFUCache", "put", "put", "get", "put", "get", "get", "put", "get", "get", "get"]
[[2], [1, 1], [2, 2], [1], [3, 3], [2], [3], [4, 4], [1], [3], [4]]
Output
[null, null, null, 1, null, -1, 3, null, -1, 3, 4]

Explanation
// cnt(x) = the use counter for key x
// cache=[] will show the last used order for tiebreakers (leftmost element is  most recent)
LFUCache lfu = new LFUCache(2);
lfu.put(1, 1);   // cache=[1,_], cnt(1)=1
lfu.put(2, 2);   // cache=[2,1], cnt(2)=1, cnt(1)=1
lfu.get(1);      // return 1
                 // cache=[1,2], cnt(2)=1, cnt(1)=2
lfu.put(3, 3);   // 2 is the LFU key because cnt(2)=1 is the smallest, invalidate 2.
                 // cache=[3,1], cnt(3)=1, cnt(1)=2
lfu.get(2);      // return -1 (not found)
lfu.get(3);      // return 3
                 // cache=[3,1], cnt(3)=2, cnt(1)=2
lfu.put(4, 4);   // Both 1 and 3 have the same cnt, but 1 is LRU, invalidate 1.
                 // cache=[4,3], cnt(4)=1, cnt(3)=2
lfu.get(1);      // return -1 (not found)
lfu.get(3);      // return 3
                 // cache=[3,4], cnt(4)=1, cnt(3)=3
lfu.get(4);      // return 4
                 // cache=[4,3], cnt(4)=2, cnt(3)=3
```

**Constraints**

- 1 <= capacity <= 104
- 0 <= key <= 105
- 0 <= value <= 109
- At most 2 * 105 calls will be made to get and put.

## 题目（中文翻译）

设计并实现一种用于 **最不经常使用 (Least Frequently Used, LFU)** 缓存的数据结构。

实现 `LFUCache` 类：

- 为了确定最不经常使用的键，需要为缓存中的每个键维护一个 **使用计数器 (use counter)**。计数器最小的键即为最不经常使用的键。
- 当键首次被插入缓存时，其使用计数器被设为 `1`（因为执行了 `put` 操作）。在缓存中的键每被一次 `get` 或 `put` 操作访问，其使用计数器都会递增。
- `get` 与 `put` 两个函数的平均时间复杂度必须都是 **O(1)**。

```java
// cnt(x) = key x 的使用计数器
// cache=[] 用于展示在计数相同情况下的最近使用顺序（最左侧元素为最近使用）
LFUCache lfu = new LFUCache(2);
lfu.put(1, 1);   // cache=[1,_], cnt(1)=1
lfu.put(2, 2);   // cache=[2,1], cnt(2)=1, cnt(1)=1
lfu.get(1);      // 返回 1
                 // cache=[1,2], cnt(2)=1, cnt(1)=2
lfu.put(3, 3);   // 2 是 LFU 键，因为 cnt(2)=1 最小，淘汰 2。
                // cache=[3,1], cnt(3)=1, cnt(1)=2
lfu.get(2);      // 返回 -1（未找到）
lfu.get(3);      // 返回 3
                 // cache=[3,1], cnt(3)=2, cnt(1)=2
lfu.put(4, 4);   // 1 与 3 的计数相同，但 1 更久未使用（LRU），淘汰 1。
                 // cache=[4,3], cnt(4)=1, cnt(3)=2
lfu.get(1);      // 返回 -1（未找到）
lfu.get(3);      // 返回 3
                 // cache=[3,4], cnt(4)=1, cnt(3)=3
lfu.get(4);      // 返回 4
                 // cache=[4,3], cnt(4)=2, cnt(3)=3
```

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把缓存当成 **普通的字典**（Python `dict`），  
每次 `put`、`get` 都遍历所有键来找出「使用次数最少」的那个键并删除。  
可以用下面两个数据结构来记录信息：

| 数据结构 | 类比 | 用途 |
|----------|------|------|
| `dict key → (value, freq)` | 查字典：词 →（解释，出现次数） | 快速得到某个键对应的值和使用次数 |
| `list of keys`（或者 `deque`） | 排队的队列 | 记录插入顺序，用来在「使用次数相同」时决定 **最近最少使用**（LRU） 的键 |

**为什么能得到正确答案**  
- `get(key)`：如果键在字典里，返回它的值并把它的 `freq` 加 1。  
- `put(key, value)`：  
  1. 若键已经存在，更新值并把 `freq` 加 1。  
  2. 若键不存在且缓存已满，则遍历所有键，找到 `freq` 最小的键；若有多个 `freq` 相同，则取队列最左侧（最久未使用）的键并删除。  
  3. 把新键加入字典，`freq` 设为 1，同时把它加入队列最右侧（最新使用）。

只要每一步都严格按照「使用次数」和「最近使用」的规则来更新，答案自然正确。

**复杂度分析（大白话版）**  

- **时间复杂度**  
  - `get`：只需要一次哈希查找和一次整数加法，**O(1)**。  
  - `put`：如果需要淘汰键，就要 **遍历所有键** 找最小 `freq`，最坏情况要看 `capacity`（最多 10⁴）次，**O(capacity)**，即 **O(n)**（n 为当前缓存大小）。  

  用大白话说，`O(n)` 就像「把所有水果都拿出来逐个称重」——当水果很多时会很慢。

- **空间复杂度**  
  - 我们保存每个键的 `(value, freq)`，以及一个保存顺序的列表，**O(n)**，即随缓存大小线性增长。  

#### 代码（Python）

```python
class LFUCacheBrute:
    """
    暴力实现，仅用于演示思路。每次容量已满时需要遍历所有键寻找 LFU。
    """
    def __init__(self, capacity: int):
        self.cap = capacity                # 最大容量
        self.store = {}                    # key -> (value, freq)
        self.order = []                    # 记录键的使用顺序，左侧最旧

    def _update_order(self, key: int) -> None:
        """把 key 移到最右侧，表示最近使用一次（LRU 辅助）。"""
        if key in self.order:
            self.order.remove(key)        # O(n) 的线性查找
        self.order.append(key)

    def get(self, key: int) -> int:
        if key not in self.store:
            return -1
        value, freq = self.store[key]
        self.store[key] = (value, freq + 1)   # 使用次数加一
        self._update_order(key)               # 近期使用，更新顺序
        return value

    def put(self, key: int, value: int) -> None:
        if self.cap == 0:
            return

        if key in self.store:                 # 已有键 → 更新值并增加使用次数
            _, freq = self.store[key]
            self.store[key] = (value, freq + 1)
            self._update_order(key)
            return

        # 新键且缓存已满，需要淘汰
        if len(self.store) >= self.cap:
            # 找到最小的使用次数
            min_freq = min(freq for _, freq in self.store.values())
            # 在使用次数相同的键里，挑选最左侧（最久未使用）的键
            for k in self.order:
                if self.store[k][1] == min_freq:
                    del self.store[k]
                    self.order.remove(k)
                    break

        # 插入新键，使用次数初始化为 1
        self.store[key] = (value, 1)
        self.order.append(key)
```

#### 复杂度

- **时间复杂度**  
  - `get`：`O(1)`（哈希查找 + 常数操作）  
  - `put`：最坏 `O(n)`，因为需要遍历 `order` 列表找最小频率的键。  

- **空间复杂度**  
  - `O(n)`，保存每个键的 `(value, freq)` 以及顺序列表。

### 2. 最优解  

#### 思路  

暴力解的瓶颈在 **“找最小使用次数的键”** 这一步，它需要遍历全部键。  
要把这一步也变成 **O(1)**，我们需要一种结构能够：

1. **快速定位** 当前最小的使用次数（`minFreq`）。  
2. 在同一个使用次数下，仍然能够 **按 LRU（最近最少使用）** 的顺序快速删除最旧的键。  

这正好可以用 **“哈希表 + 双向链表”** 的组合来实现：

| 结构 | 类比 | 作用 |
|------|------|------|
| `key_to_node`（哈希表） | 查字典：词 → 位置 | 通过键直接拿到它在链表中的节点（包含 value、freq） |
| `freq_to_nodes`（哈希表） | “不同频率的队列” | 每个频率对应一个 **双向链表**，链表里保存所有 **拥有该频率的键**，链表头部是 **最近使用**，尾部是 **最久未使用**（LRU） |
| `minFreq`（整数） | “当前最少的频率” | 记录当前缓存里最小的使用次数，淘汰时只看这一个链表即可 |

**核心操作**  

- **访问（`get`）**  
  1. 通过 `key_to_node` 直接定位节点。  
  2. 把节点从旧频率链表 `freq_to_nodes[oldFreq]` 中摘除。  
  3. 若旧链表为空且 `oldFreq == minFreq`，说明最小频率提升了，`minFreq += 1`。  
  4. 把节点的 `freq` 加 1，插入到 `freq_to_nodes[newFreq]` 的 **头部**（表示最近使用）。  

- **插入（`put`）**  
  - **容量为 0** 时直接返回。  
  - **键已存在**：同 `get`，先更新值，再提升频率。  
  - **键不存在且缓存已满**：  
    1. 在 `freq_to_nodes[minFreq]`（最小频率链表）的 **尾部** 找到最旧的节点，删掉它（同时在 `key_to_node` 中删除映射）。  
    2. 插入新键，频率设为 **1**，`minFreq = 1`，并把节点放到 `freq_to_nodes[1]` 的头部。  

**为什么是 O(1)**  
- 哈希表的查找、插入、删除都是 **常数时间**。  
- 双向链表的“把节点摘除/插入到头部/尾部”都是 **指针操作**，不需要遍历。  
- `minFreq` 只在两种情况下修改：频率提升导致旧链表空、或者插入新键时设为 1，都是 O(1)。  

**类比帮助记忆**  
- 想象 **每个频率是一条排队的走廊**，走廊里的人（键）按照“谁最近来”站在最前面。  
- 当有人被访问，他会 **跳到更高频率的走廊的最前面**（因为他更“热”）。  
- 当走廊里没人了，最小频率的指示灯 `minFreq` 会自动切换到下一个有人的走廊。  
- 淘汰时，只需要看 **最小频率走廊的最后一个人**（最久没来），踢出去即可。

#### 代码（Python）

```python
class Node:
    """双向链表的节点，保存 key、value、freq，并指向前后节点"""
    __slots__ = ('key', 'value', 'freq', 'prev', 'next')
    def __init__(self, key: int, value: int, freq: int = 1):
        self.key = key
        self.value = value
        self.freq = freq
        self.prev = None
        self.next = None


class DoublyLinkedList:
    """带哨兵头尾的双向链表，支持 O(1) 的插入/删除"""
    def __init__(self):
        self.head = Node(None, None)   # 哨兵头（不存实际数据）
        self.tail = Node(None, None)   # 哨兵尾
        self.head.next = self.tail
        self.tail.prev = self.head
        self.size = 0

    def append_left(self, node: Node) -> None:
        """把节点插入到链表头部（最近使用）"""
        node.next = self.head.next
        node.prev = self.head
        self.head.next.prev = node
        self.head.next = node
        self.size += 1

    def pop_right(self) -> Node:
        """弹出链表尾部的节点（最久未使用），并返回它"""
        if self.size == 0:
            return None
        node = self.tail.prev
        self._remove(node)
        return node

    def _remove(self, node: Node) -> None:
        """把任意节点从链表中摘除"""
        node.prev.next = node.next
        node.next.prev = node.prev
        node.prev = node.next = None
        self.size -= 1

    def remove(self, node: Node) -> None:
        """对外提供的删除接口（包装内部实现）"""
        self._remove(node)

    def is_empty(self) -> bool:
        return self.size == 0


class LFUCache:
    """
    O(1) 平均时间的 LFU Cache 实现。
    关键点：
    - key → node 的哈希表（直接定位）
    - freq → 对应频率的双向链表（同频率下 LRU）
    - minFreq 记录当前最小频率
    """
    def __init__(self, capacity: int):
        self.cap = capacity                 # 最大容量
        self.size = 0                       # 当前缓存元素个数
        self.minFreq = 0                    # 当前最小使用次数
        self.key_node = {}                  # key → Node
        self.freq_list = {}                 # freq → DoublyLinkedList

    def _add_node(self, node: Node) -> None:
        """把新节点加入对应频率的链表，并更新 minFreq 为 1"""
        if 1 not in self.freq_list:
            self.freq_list[1] = DoublyLinkedList()
        self.freq_list[1].append_left(node)
        self.minFreq = 1

    def _increase_freq(self, node: Node) -> None:
        """把节点从旧频率链表移除并放入 freq+1 的链表"""
        old_freq = node.freq
        old_list = self.freq_list[old_freq]
        old_list.remove(node)                     # O(1) 删除

        # 若旧链表为空且正好是当前最小频率，需要提升 minFreq
        if old_list.is_empty() and self.minFreq == old_freq:
            self.minFreq += 1

        node.freq += 1
        new_freq = node.freq
        if new_freq not in self.freq_list:
            self.freq_list[new_freq] = DoublyLinkedList()
        self.freq_list[new_freq].append_left(node)   # 新链表头部

    def get(self, key: int) -> int:
        if key not in self.key_node:
            return -1
        node = self.key_node[key]
        self._increase_freq(node)                # 访问即提升频率
        return node.value

    def put(self, key: int, value: int) -> None:
        if self.cap == 0:
            return

        if key in self.key_node:
            # 键已存在 → 更新值并提升频率
            node = self.key_node[key]
            node.value = value
            self._increase_freq(node)
            return

        # 缓存已满，需要淘汰
        if self.size == self.cap:
            # 最小频率链表的最旧节点（尾部）被踢出
            evict_list = self.freq_list[self.minFreq]
            evict_node = evict_list.pop_right()
            del self.key_node[evict_node.key]
            self.size -= 1

        # 插入新节点，频率初始化为 1
        new_node = Node(key, value, freq=1)
        self.key_node[key] = new_node
        self._add_node(new_node)
        self.size += 1
```

#### 复杂度  

- **时间复杂度**  
  - `get`：一次哈希查找 + 常数次链表操作 → **O(1)**。  
  - `put`：  
    - 若是更新已有键，同 `get` → **O(1)**。  
    - 若是新键且需要淘汰，同样只在 **最小频率链表的尾部** 删除一个节点 → **O(1)**。  
  与暴力解相比，**不再需要遍历所有键**，所以在最坏情况下也始终是常数时间。

- **空间复杂度**  
  - 每个缓存键对应一个 `Node`，以及每个出现过的频率对应一个链表头部。总体保存的节点数不超过 `capacity`，所以 **O(capacity)**。  
  - 额外的哈希表 `key_node`、`freq_list` 也都是线性空间。

## 心得  

- **核心技巧**：使用 **哈希表 + 双向链表** 实现 **“频率分层的 LRU”**，即「同频率内部按最近使用顺序」并维护全局最小频率 `minFreq`。  
- **适用的题型**（类似思路）  
  1. **LRU Cache**（只需要一个频率层）  
  2. **All O`1` Data Structure**（LeetCode 432，维护最大最小键的计数结构）  
  3. **Design TinyURL**（需要哈希映射 + 编码，思路相通的“映射+分层”）  

- **一句话总结解题钥匙**：**把“使用次数”和“最近使用”分别用哈希表和双向链表管理，在 O(1) 内定位并淘汰最旧的最少使用键**。

## 反思  

- **第一反应**：直接用字典保存次数，然后遍历找最小——这会导致 `put` 不是 O(1)。  
- **最容易踩的坑**  
  - **容量为 0** 的情况必须提前返回，否则会产生除零错误或无限循环。  
  - **频率链表为空时**，一定要同步更新 `minFreq`，否则后续淘汰会找错链表。  
  - **双向链表的删除** 必须把节点的前后指针全部清空，防止出现悬挂导致内存泄漏（在 Python 中主要是防止误删错误）。  
- **下次遇到同类题**：第一步先思考“**有没有一种结构可以在 O(1) 内找到要淘汰的元素**”。  
  - 如果涉及 “最少/最多次数 + 最近使用”，就立即想到 **“频率 → 双向链表 + 哈希映射”** 这套组合。
