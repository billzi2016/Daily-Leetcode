## 题目（英文原版）

**Description**

Given four integer arrays nums1, nums2, nums3, and nums4 all of length n, return the number of tuples (i, j, k, l) such that:

**Examples**

**Example 1:**

```
Input: nums1 = [1,2], nums2 = [-2,-1], nums3 = [-1,2], nums4 = [0,2]
Output: 2
Explanation:
The two tuples are:
1. (0, 0, 0, 1) -> nums1[0] + nums2[0] + nums3[0] + nums4[1] = 1 + (-2) + (-1) + 2 = 0
2. (1, 1, 0, 0) -> nums1[1] + nums2[1] + nums3[0] + nums4[0] = 2 + (-1) + (-1) + 0 = 0
```

**Example 2:**

```
Input: nums1 = [0], nums2 = [0], nums3 = [0], nums4 = [0]
Output: 1
```

**Constraints**

- n == nums1.length
- n == nums2.length
- n == nums3.length
- n == nums4.length
- 1 <= n <= 200
- -228 <= nums1[i], nums2[i], nums3[i], nums4[i] <= 228

## 题目（中文翻译）

给定四个长度均为 `n` 的整数数组 `nums1`、`nums2`、`nums3` 和 `nums4`，返回满足  

`nums1[i] + nums2[j] + nums3[k] + nums4[l] = 0`  

的元组（tuple）`(i, j, k, l)` 的个数。

**示例 1：**  
```text
Input: nums1 = [1,2], nums2 = [-2,-1], nums3 = [-1,2], nums4 = [0,2]
Output: 2
Explanation:
The two tuples are:
1. (0, 0, 0, 1) -> nums1[0] + nums2[0] + nums3[0] + nums4[1] = 1 + (-2) + (-1) + 2 = 0
2. (1, 1, 0, 0) -> nums1[1] + nums2[1] + nums3[0] + nums4[0] = 2 + (-1) + (-1) + 0 = 0
```

**示例 2：**  
```text
Input: nums1 = [0], nums2 = [0], nums3 = [0], nums4 = [0]
Output: 1
```

**约束条件：**
- `n == nums1.length`
- `n == nums2.length`
- `n == nums3.length`
- `n == nums4.length`
- `1 <= n <= 200`
- `-2^28 <= nums1[i], nums2[i], nums3[i], nums4[i] <= 2^28`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是把四个数组的下标全部枚举一遍，计算  
`nums1[i] + nums2[j] + nums3[k] + nums4[l]` 是否等于 0，满足就计数。

- **用到的数据结构**：只需要四层 `for` 循环和一个整数计数器。这里没有额外的数据结构，和在厨房里把四种材料逐个尝试配方的过程类似——穷举所有可能的组合。
- **为什么正确**：因为我们把 **所有** 可能的 `(i, j, k, l)` 都遍历了一遍，只要出现和为 0 的情况，必然会被统计到。
- **复杂度分析**：  
  - 外层循环 `i` 有 `n` 次，第二层 `j` 也有 `n` 次，依此类推，四层循环一共是 `n × n × n × n = n⁴` 次运算。  
  - `O(n⁴)` 中的 `O` 只是一种“数量级”的记号，意思是随着 `n` 增大，运行时间大约会以 `n` 的四次方增长。举个例子，若 `n` 从 10 增大到 20，时间大概会变成原来的 `2⁴ = 16` 倍！  
  - 空间上只用了常数级的变量（计数器），所以是 `O(1)`。

#### 代码（Python）

```python
def fourSumCount(nums1, nums2, nums3, nums4):
    n = len(nums1)                # 四个数组长度相同
    ans = 0                       # 用来记录满足条件的四元组个数

    # 四层循环枚举所有下标组合
    for i in range(n):
        for j in range(n):
            for k in range(n):
                for l in range(n):
                    # 计算四个数的和
                    total = nums1[i] + nums2[j] + nums3[k] + nums4[l]
                    if total == 0:   # 若和为 0，则找到一个合法四元组
                        ans += 1
    return ans
```

#### 复杂度

- **时间复杂度**：`O(n⁴)` — 随着 `n` 增大，运算次数会呈四次方增长，实际会非常慢。  
- **空间复杂度**：`O(1)` — 只用了几个额外变量，和输入规模无关。

### 2. 最优解

#### 思路  

从暴力解可以看到，**瓶颈** 出在最里层的两层循环（`k`、`l`），它们导致了 `n⁴` 的时间。  
我们可以把问题拆成两部分：

1. 先把前两个数组的所有 **两数之和** 统计出来。  
2. 再遍历后两个数组的所有 **两数之和**，看它们的相反数（`-sum`）在第一步的统计表中出现了多少次。

这一步的关键是 **哈希表（字典）**：  
- 把每一种 `nums1[i] + nums2[j]` 的结果当作 **键（key）**，出现的次数当作 **值（value）**。  
- 哈希表就像一本“词典”，我们可以在 **O(1)** 的时间内查到某个和出现了几次。

整个过程只需要两次 **`n²`** 的遍历，时间从 `n⁴` 降到了 `n²`，空间换取了额外的 `O(n²)` 哈希表。

**详细步骤**  

| 步骤 | 说明 |
|------|------|
| 1️⃣ 统计前两数组和 | 双层循环遍历 `i、j`，计算 `s = nums1[i] + nums2[j]`，在字典 `cnt` 中 `cnt[s] += 1`。 |
| 2️⃣ 统计后两数组和并配对 | 再用双层循环遍历 `k、l`，计算 `t = nums3[k] + nums4[l]`，查找 `-t` 是否在 `cnt` 中，若在则把对应的计数累加到答案。 |

> **类比**：想象有两堆水果，第一堆是苹果+香蕉的组合，第二堆是橘子+葡萄的组合。我们想找出两堆组合的总重量恰好相等（这里相等于 0），只要把第一堆的每种重量记下来，然后在第二堆里找相反的重量即可。

#### 代码（Python）

```python
from collections import defaultdict

def fourSumCount(nums1, nums2, nums3, nums4):
    """
    统计满足 nums1[i] + nums2[j] + nums3[k] + nums4[l] == 0 的四元组个数。
    思路：把前两数组的和放进哈希表，后两数组的和查找相反数。
    """
    # 1. 统计前两数组所有可能的和，及其出现次数
    sum12 = defaultdict(int)          # 默认值为 0 的字典
    for a in nums1:
        for b in nums2:
            s = a + b
            sum12[s] += 1              # s 出现一次，就把计数加一

    # 2. 遍历后两数组的和，查找相反数在 sum12 中出现的次数
    ans = 0
    for c in nums3:
        for d in nums4:
            t = -(c + d)               # 需要的相反数
            if t in sum12:             # 若相反数存在
                ans += sum12[t]        # 累加出现次数
    return ans
```

#### 复杂度

- **时间复杂度**：`O(n²)` — 两次双层循环，每次都是 `n × n`，相比暴力的 `n⁴` 提速巨大。  
  - 这里的 `O(n²)` 可以理解为：如果 `n = 200`，则最多进行 `200² = 40,000` 次加法和字典操作，计算机可以在毫秒级完成。  
- **空间复杂度**：`O(n²)` — 用哈希表保存所有 `nums1[i] + nums2[j]` 的结果，最坏情况下会有 `n²` 条不同的键。  
  - 这相当于我们把前两数组的所有组合“记在纸上”，纸的大小随 `n²` 增长。

## 心得

- **核心技巧**：**拆分为两组求和 + 哈希表计数**，把四元组问题转化为两两配对。  
- **适用的题型**  
  1. `2Sum`、`3Sum`、`4Sum` 系列（尤其是要求计数而非返回具体组合）。  
  2. “四数相加为目标值” 这类可以分成两半的组合计数问题。  
  3. `Number of Tuples with Sum Zero`（类似本题的变体）。  
- **一句话总结解题钥匙**：**把大问题拆成两小问题，用哈希表把一半的结果“记下来”，另一半来“查”。**

## 反思

- **第一反应**：直接想到暴力枚举所有下标，随后意识到会超时。  
- **最容易踩的坑**  
  - **整数溢出**：在 Python 中不需要担心，但在某些语言要注意 32 位整数范围。  
  - **字典键不存在**：使用 `defaultdict(int)` 或先判断 `if key in dict`，否则会抛异常。  
  - **重复计数**：如果使用 `list` 保存所有和再遍历，会出现重复计数的风险，哈希表的计数方式可以直接累计。  
- **下次遇到同类题**：第一步先思考能否 **分割成两组**，并检查是否可以用 **哈希表** 把一半的结果存下来，再用另一半去 **查找匹配**。这样往往能把指数级时间降到平方级。
