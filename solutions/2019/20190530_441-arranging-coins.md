# #441. Arranging Coins / Arranging Coins

> 难度：简单 · 标签：Math、Binary Search · [LeetCode 链接](https://leetcode.com/problems/arranging-coins/)

---

## 题目（英文原版）

**Description**

You have n coins and you want to build a staircase with these coins. The staircase consists of k rows where the ith row has exactly i coins. The last row of the staircase may be incomplete.
Given the integer n, return the number of complete rows of the staircase you will build.

**Examples**

**Example 1:**

```
Input: n = 5
Output: 2
Explanation: Because the 3rd row is incomplete, we return 2.
```

**Example 2:**

```
Input: n = 8
Output: 3
Explanation: Because the 4th row is incomplete, we return 3.
```

**Constraints**

- 1 <= n <= 231 - 1

---

## 题目（中文翻译）

你有 `n` 枚硬币，想要用这些硬币搭建一个阶梯（staircase）。阶梯由 `k` 行（row）组成，第 `i` 行恰好需要 `i` 枚硬币。最后一行可以不完整。  
给定整数 `n`，返回你能够搭建的完整行数。

**示例 1:**  
**Input:** `n = 5`  
**Output:** `2`  
**Explanation:** 第三行的硬币不足，因而只得到 2 行完整的阶梯。

**示例 2:**  
**Input:** `n = 8`  
**Output:** `3`  
**Explanation:** 第四行的硬币不足，因而只得到 3 行完整的阶梯。

**约束条件：**  
- `1 <= n <= 2^31 - 1`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是 **一步一步搭楼梯**：  
- 第 1 行放 1 枚硬币，第 2 行放 2 枚，第 3 行放 3 枚 …，一直往下走，直到手里的硬币不够再放完整的一行。  
- 用一个 `while` 循环，每次把当前行需要的硬币数 `i` 从总数 `n` 中减去，如果减完后 `n` 仍然非负，就说明这行是完整的，计数器 `k` 加一；否则停止。

> **类比**：想象你在排队买票，每个人要买的票数依次递增（1、2、3…），只要手里还有票，就让下一位买完；买不到完整的那位，就不算在内。

这种方法一定能得到正确答案，因为我们严格按照题目要求“每行恰好 i 枚硬币”去消耗硬币，最后还能完整搭的行数自然就是答案。

#### 代码（Python）

```python
def arrangeCoins_brute(n: int) -> int:
    """
    暴力模拟搭楼梯
    :param n: 硬币总数
    :return: 完整的行数
    """
    k = 0          # 已经搭好的完整行数
    i = 1          # 当前要放的硬币数量（第 i 行需要 i 枚）
    while n >= i:  # 只要还有足够的硬币就继续
        n -= i      # 用掉 i 枚硬币
        k += 1      # 完成一行
        i += 1      # 下一行需要的硬币数加一
    return k
```

#### 复杂度  

- **时间复杂度**：`O(k)`，其中 `k` 是完整行数。因为每循环一次就完成一行，循环次数等于答案本身。  
  事实上 `k` 大约等于 `√n`（因为 `1 + 2 + … + k ≈ k²/2 ≈ n`），所以可以把它理解为 **O(√n)**，也就是说即使 `n` 很大，循环次数也不会超过几万（对 32 位整数来说最多约 65535 次），仍然可以接受。  
- **空间复杂度**：`O(1)`，只用了常数个变量 `k、i、n`，不随输入规模增长。

### 2. 最优解

#### 思路  

从暴力解可以看到，**瓶颈在于逐行遍历**。我们其实只需要知道 “到底能走多少行”，而不必真的把每一行的硬币一个个减掉。

把每行需要的硬币数累加起来得到的总和是**等差数列的前 `k` 项和**：

```
S(k) = 1 + 2 + … + k = k·(k + 1) / 2
```

我们要找的 `k` 满足：

```
k·(k + 1) / 2 ≤ n < (k + 1)·(k + 2) / 2
```

这是一道 **单调函数**（`S(k)` 随 `k` 增大而严格递增）的求最大 `k` 的问题，**二分搜索**（Binary Search）非常适合。

二分搜索的要点：

1. **搜索范围**：`k` 的可能取值在 `[0, n]` 之间（不可能超过硬币总数）。
2. **中点**：`mid = (left + right) // 2`。
3. **判断**：计算 `mid·(mid + 1) // 2`（使用整数除法防止小数），
   - 如果 `≤ n`，说明 `mid` 行可以完整搭，尝试更大的 `mid`（左边界左移）。
   - 否则 `mid` 行已经超出，尝试更小的 `mid`（右边界右移）。
4. 循环结束后，左边界 `left` 会恰好指向 **最大的满足条件的行数**。

> **类比**：想象一本厚厚的字典，想找最后一个页码不超过 `n` 的章节。章节页码总和随章节号递增，用二分法快速定位章节号，而不是一本一本翻。

#### 代码（Python）

```python
def arrangeCoins_binary_search(n: int) -> int:
    """
    二分搜索求最大的 k，使得 k·(k+1)/2 ≤ n
    :param n: 硬币总数
    :return: 完整的行数
    """
    left, right = 0, n  # 搜索区间 [left, right]
    while left <= right:
        mid = (left + right) // 2          # 取中点
        curr = mid * (mid + 1) // 2        # 前 mid 行需要的硬币数（等差数列求和）
        if curr == n:                     # 正好用完
            return mid
        if curr < n:                      # 还能继续搭更高的行
            left = mid + 1                 # 把搜索区间左移
        else:                             # 已经超过了 n
            right = mid - 1                # 把搜索区间右移
    # 循环结束时 right < left，right 正好是最大的满足条件的行数
    return right
```

#### 复杂度  

- **时间复杂度**：`O(log n)`。每一次循环把搜索区间长度减半，最多进行 `log₂ n` 次比较。对 `n ≤ 2³¹‑1` 来说，最多约 31 次，几乎是瞬间完成。  
- **空间复杂度**：`O(1)`。只用了几个整数变量，不随 `n` 增大而变化。

## 心得

- **核心技巧**：把“每行递增的硬币数”转化为等差数列求和公式，然后用**二分搜索**在单调函数上找最大满足条件的下标。  
- **适用的类似题型**  
  1. **寻找满足不等式的最大整数**（如 `k*k ≤ n`，常见的 `sqrt` 题目）。  
  2. **分配资源的最大完整层数**（例如“划分圆形”或“堆砌盒子”）。  
  3. **单调数组中找边界**（如“在有序数组中寻找第一个大于 target 的位置”）。  
- **一句话总结**：把递增求和看成单调函数，用二分快速定位最大的合法行数。

## 反思

- **第一反应**：先把硬币一行行减掉，写个循环模拟——直觉最自然。  
- **最容易踩的坑**  
  - **整数溢出**：在某些语言里 `mid * (mid + 1)` 可能超过 32 位整数范围，需要使用 64 位或提前做除法。Python 整数不受此限制，但在解释时要提醒。  
  - **边界条件**：`n = 0`（虽然题目最小是 1）或 `n` 恰好等于某个完整层的和时，需要确保返回的恰好是该层数。  
  - **循环退出条件**：二分搜索的 `while left <= right` 与返回 `right`（或 `left-1`）的对应关系一定要写清楚，防止返回了超出范围的值。  
- **下次遇到同类题**，第一步应该**写出单调函数的表达式**（这里是 `k·(k+1)/2`），确认它随变量单调递增，然后**考虑二分或直接求根**来快速定位答案。
