## 题目（英文原版）

**Description**

Table: Insurance
Write a solution to report the sum of all total investment values in 2016 tiv_2016, for all policyholders who:
Round tiv_2016 to two decimal places.
The result format is in the following example.

**Examples**

**Example 1:**

```
+-------------+-------+
| Column Name | Type  |
+-------------+-------+
| pid         | int   |
| tiv_2015    | float |
| tiv_2016    | float |
| lat         | float |
| lon         | float |
+-------------+-------+
pid is the primary key (column with unique values) for this table.
Each row of this table contains information about one policy where:
pid is the policyholder's policy ID.
tiv_2015 is the total investment value in 2015 and tiv_2016 is the total investment value in 2016.
lat is the latitude of the policy holder's city. It's guaranteed that lat is not NULL.
lon is the longitude of the policy holder's city. It's guaranteed that lon is not NULL.
```

**Example 2:**

```
Input: 
Insurance table:
+-----+----------+----------+-----+-----+
| pid | tiv_2015 | tiv_2016 | lat | lon |
+-----+----------+----------+-----+-----+
| 1   | 10       | 5        | 10  | 10  |
| 2   | 20       | 20       | 20  | 20  |
| 3   | 10       | 30       | 20  | 20  |
| 4   | 10       | 40       | 40  | 40  |
+-----+----------+----------+-----+-----+
Output: 
+----------+
| tiv_2016 |
+----------+
| 45.00    |
+----------+
Explanation: 
The first record in the table, like the last record, meets both of the two criteria.
The tiv_2015 value 10 is the same as the third and fourth records, and its location is unique.

The second record does not meet any of the two criteria. Its tiv_2015 is not like any other policyholders and its location is the same as the third record, which makes the third record fail, too.
So, the result is the sum of tiv_2016 of the first and last record, which is 45.
```

## 题目（中文翻译）

**描述**  
给定表 **Insurance**，编写一个查询，返回所有满足以下条件的投保人 2016 年总投资额 (**tiv_2016**) 的和，并将结果四舍五入保留两位小数。  
结果格式参照示例。

**表结构**  

```
+-------------+-------+
| Column Name | Type  |
+-------------+-------+
| pid         | int   |
| tiv_2015    | float |
| tiv_2016    | float |
| lat         | float |
| lon         | float |
+-------------+-------+
```

- `pid` 为主键（primary key），即唯一标识每条记录的列。  
- 每行记录表示一份保单，包含以下信息：  
  - `pid`：投保人的保单 ID。  
  - `tiv_2015`：2015 年的总投资额。  
  - `tiv_2016`：2016 年的总投资额。  
  - `lat`：投保人所在城市的纬度（latitude），保证不为 `NULL`。  
  - `lon`：投保人所在城市的经度（longitude），保证不为 `NULL`。

**示例**  

**示例 1**  

```
Insurance 表:
+-----+----------+----------+-----+-----+
| pid | tiv_2015 | tiv_2016 | lat | lon |
+-----+----------+----------+-----+-----+
| 1   | 10       | 5        | 10  | 10  |
| 2   | 20       | 20       | 20  | 20  |
| 3   | 10       | 30       | 20  | 20  |
| 4   | 10       | 40       | 40  | 40  |
+-----+----------+----------+-----+-----+
```

**输出**

```
+----------+
| tiv_2016 |
+----------+
| 45.00    |
+----------+
```

**解释**  
- 第 1 条记录和第 4 条记录均满足题目给出的两个条件。  
- 第 1 条记录的 `tiv_2015` 为 10，且该数值在第 3、4 条记录中也出现，同时它的地理位置是唯一的。  
- 第 2 条记录不满足任一条件：它的 `tiv_2015`（20）在其他投保人中没有相同的值，且其位置与第 3 条记录相同，使第 3 条记录也失效。  
- 因此，只统计第 1 条和第 4 条记录的 `tiv_2016`，其和为 `5 + 40 = 45`，并保留两位小数显示为 `45.00`。

**约束条件**  
无。

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  
我们手里只有一张 `Insurance` 表，每一行都是一个保单的信息。  
题目要求 **把满足下面两个条件的保单的 2016 年投资额 `tiv_2016` 加起来**，并保留两位小数：

1. 该保单的 `tiv_2015` **出现次数 ≥ 2**（即有其他保单的 2015 投资额和它相同）。  
2. 该保单的地理位置 `(lat, lon)` **唯一**，也就是说没有别的保单和它的经纬度完全相同。

> 类比：  
> - `tiv_2015` 的出现次数就像字典里查“这个词出现了几次”。  
> - `(lat, lon)` 的唯一性就像每个人的身份证号码，只有唯一的才算合格。

最直接的做法是：**对每一条记录**，遍历整张表去统计它的 `tiv_2015` 出现了多少次、它的 `(lat, lon)` 出现了多少次。只要两者同时满足，就把 `tiv_2016` 加到答案里。

这种写法虽然容易理解，但每条记录都要再遍历一次整张表，时间会是 **O(n²)**（n 为记录数），在数据量大的情况下会很慢。

#### 代码（Python）

```python
from typing import List, Dict

def sum_tiv_2016_bruteforce(insurance: List[Dict]) -> float:
    """
    暴力实现：对每条记录都遍历全表统计出现次数
    参数 insurance 为 [{pid:..., tiv_2015:..., tiv_2016:..., lat:..., lon:...}, ...]
    返回满足条件的 tiv_2016 之和，保留两位小数
    """
    total = 0.0
    n = len(insurance)

    for i in range(n):
        cur = insurance[i]
        # 统计当前记录的 tiv_2015 出现了几次
        cnt_tiv = 0
        # 统计当前记录的 (lat, lon) 出现了几次
        cnt_loc = 0

        for j in range(n):
            other = insurance[j]
            if other['tiv_2015'] == cur['tiv_2015']:
                cnt_tiv += 1
            if other['lat'] == cur['lat'] and other['lon'] == cur['lon']:
                cnt_loc += 1

        # 两个条件同时满足，才累加
        if cnt_tiv >= 2 and cnt_loc == 1:
            total += cur['tiv_2016']

    # round 保留两位小数，符合题目要求的输出格式
    return round(total, 2)


# ------------------- 示例跑通 -------------------
if __name__ == "__main__":
    data = [
        {"pid": 1, "tiv_2015": 10, "tiv_2016": 5,  "lat": 10, "lon": 10},
        {"pid": 2, "tiv_2015": 20, "tiv_2016": 20, "lat": 20, "lon": 20},
        {"pid": 3, "tiv_2015": 10, "tiv_2016": 30, "lat": 20, "lon": 20},
        {"pid": 4, "tiv_2015": 10, "tiv_2016": 40, "lat": 40, "lon": 40},
    ]
    print(sum_tiv_2016_bruteforce(data))   # 输出: 45.0
```

#### 复杂度  

- **时间复杂度：** `O(n²)`  
  解释：对每条记录（外层循环 n 次），都要遍历整张表一次（内层循环 n 次），所以总操作数大约是 n×n。  
  当 n=10⁴ 时，约 1 亿次比较，明显会超时。  

- **空间复杂度：** `O(1)`（不计输入数据本身）  
  只用了常数个额外变量 `total、cnt_tiv、cnt_loc`，不随 n 增长。  

---

### 2. 最优解

#### 思路  
暴力解的瓶颈在于**重复遍历表格**。我们其实可以一次遍历就把所有需要的统计信息全部收集好，然后再一次遍历决定哪些记录符合条件。

具体步骤：

1. **第一次遍历**  
   - 用字典 `tiv_cnt` 统计每个 `tiv_2015` 出现的次数。  
   - 用字典 `loc_cnt` 统计每个 `(lat, lon)` 组合出现的次数。  
   这一步相当于“先把字典查好”，时间是 `O(n)`。

2. **第二次遍历**  
   - 对每条记录，直接从 `tiv_cnt` 和 `loc_cnt` 里拿到对应的出现次数。  
   - 如果 `tiv_cnt[tiv_2015] >= 2` 且 `loc_cnt[(lat, lon)] == 1`，说明该记录满足条件，累加 `tiv_2016`。  

这样只需要 **两次线性遍历**，整体时间是 `O(n)`，空间使用两个哈希表（字典），大小同样是 `O(n)`。

> 类比：  
> - 第一次遍历就像在图书馆先把所有书的标题和作者数量统计好（建立索引）。  
> - 第二次遍历时，只需要看目录（索引）就能快速判断一本书是否符合要求，而不必再去一本一本翻。

#### 代码（Python）

```python
from collections import defaultdict
from typing import List, Dict

def sum_tiv_2016_optimal(insurance: List[Dict]) -> float:
    """
    最优实现：两遍线性扫描 + 哈希表计数
    """
    # ---------- 第一次遍历：统计出现次数 ----------
    tiv_cnt = defaultdict(int)          # key: tiv_2015 , value: 出现次数
    loc_cnt = defaultdict(int)          # key: (lat, lon) , value: 出现次数

    for rec in insurance:
        tiv_cnt[rec['tiv_2015']] += 1
        loc_cnt[(rec['lat'], rec['lon'])] += 1

    # ---------- 第二次遍历：挑选符合条件的记录 ----------
    total = 0.0
    for rec in insurance:
        if tiv_cnt[rec['tiv_2015']] >= 2 and loc_cnt[(rec['lat'], rec['lon'])] == 1:
            total += rec['tiv_2016']

    # 保留两位小数
    return round(total, 2)


# ------------------- 示例跑通 -------------------
if __name__ == "__main__":
    data = [
        {"pid": 1, "tiv_2015": 10, "tiv_2016": 5,  "lat": 10, "lon": 10},
        {"pid": 2, "tiv_2015": 20, "tiv_2016": 20, "lat": 20, "lon": 20},
        {"pid": 3, "tiv_2015": 10, "tiv_2016": 30, "lat": 20, "lon": 20},
        {"pid": 4, "tiv_2015": 10, "tiv_2016": 40, "lat": 40, "lon": 40},
    ]
    print(sum_tiv_2016_optimal(data))   # 输出: 45.0
```

#### 复杂度  

- **时间复杂度：** `O(n)`  
  两次线性遍历，每次都只做常数时间的字典操作。即使 n 达到几百万，也能在毫秒级完成。  

- **空间复杂度：** `O(n)`  
  需要两个字典分别保存 `tiv_2015` 和 `(lat, lon)` 的计数，最坏情况下每条记录的这两个属性都不重复，字典大小为 `n`。  

与暴力解相比，时间从 **平方级** 降到 **线性级**，性能提升巨大。

## 心得  

- **核心技巧**：利用哈希表（字典）一次遍历完成计数，再用计数结果快速判断。  
- **适用的题型**：  
  1. “出现次数 ≥ k” 类的筛选（如 `Customers` 表中购买次数超过 3 次的顾客）。  
  2. “唯一/重复” 判断（如找出只出现一次的订单号）。  
  3. 需要同时检查两列属性的组合唯一性（如 `(city, state)` 是否唯一）。  
- **一句话总结**：**先统计，再过滤**——先把“多少次”记下来，后面只要查表就能瞬间判断。

## 反思  

- **第一反应**：看到“相同的 `tiv_2015`”和“唯一的坐标”，立刻想到用 **两次遍历 + 哈希计数**，因为这类“出现次数”问题几乎都适合字典。  
- **最容易踩的坑**：  
  - 忘记把 `(lat, lon)` 当成 **元组**（不可变）作为字典的键，导致键冲突或错误。  
  - 浮点数相等比较可能出现精度误差，题目中 `lat`、`lon`、`tiv` 都是 **已保证精确** 的数值（如整数或固定小数），可以直接用 `==`。  
  - 最终输出要 **保留两位小数**，直接用 `round(..., 2)` 或 `format`，否则会得到 `45.0` 与 `45.00` 格式不符。  
- **下次遇到同类题**：第一步先 **统计每个关键字段的出现次数**（用字典），再在第二遍里 **依据统计结果直接过滤**，避免嵌套循环导致的指数级时间。
