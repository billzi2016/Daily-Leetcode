## 题目（英文原版）

**Description**

You are playing the following Nim Game with your friend:
Given n, the number of stones in the heap, return true if you can win the game assuming both you and your friend play optimally, otherwise return false.

**Examples**

**Example 1:**

```
Input: n = 4
Output: false
Explanation: These are the possible outcomes:
1. You remove 1 stone. Your friend removes 3 stones, including the last stone. Your friend wins.
2. You remove 2 stones. Your friend removes 2 stones, including the last stone. Your friend wins.
3. You remove 3 stones. Your friend removes the last stone. Your friend wins.
In all outcomes, your friend wins.
```

**Example 2:**

```
Input: n = 1
Output: true
```

**Example 3:**

```
Input: n = 2
Output: true
```

**Constraints**

- 1 <= n <= 231 - 1

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  
最直接的想法是**把所有可能的走法都枚举一遍**，看是否存在一种走法能让自己必胜。  

- **数据结构**：我们可以用一个数组 `dp`（下标代表剩余石子数）来记录每个局面谁能赢。把 `dp[i] = True` 表示「当前玩家在剩余 `i` 块石子时必胜」，`False` 表示必败。  
- **类比**：把 `dp` 想成一本「游戏手册」，每一页（下标 `i`）写着「如果只剩 `i` 块石子，你是赢还是输」。我们从最小的局面往上推，逐步填满这本手册。  
- **正确性**：如果在某个局面 `i`，我们可以取走 1、2、3 块石子中的任意一种，使得对手进入的局面 `i‑k`（`k∈{1,2,3}`）是必败的 (`dp[i‑k] == False`)，那么当前局面必胜，因为我们可以把对手逼入必败局面。反之，如果所有可以到达的局面都是必胜的，则当前局面必败。  

#### 代码（Python）  

```python
def canWinNim_bruteforce(n: int) -> bool:
    # dp[i] 表示「剩 i 块石子时，先手是否必胜」
    dp = [False] * (n + 1)          # 初始化全部为 False（默认必败）
    # base case: 当剩 0 块石子时，轮到你已经输了，保持 False

    for i in range(1, n + 1):
        # 检查可以取走 1、2、3 块石子后是否能让对手进入必败局面
        win = False
        for k in (1, 2, 3):
            if i - k >= 0 and not dp[i - k]:   # 对手必败 → 当前必胜
                win = True
                break                         # 找到一种取法即可退出
        dp[i] = win

    return dp[n]
```

#### 复杂度  

- **时间复杂度**：`O(n * 3)` ≈ `O(n)`。遍历 `1 … n`，每个位置最多检查 3 种取法。  
  - 这里的 `O(n)` 表示「随石子数量线性增长」，如果 `n = 1,000,000`，循环大约执行 3,000,000 次。  
- **空间复杂度**：`O(n)`。需要一个长度为 `n+1` 的数组来存每个子问题的答案。

### 2. 最优解  

#### 思路  

从暴力解可以看到，**每次最多只能取走 1~3 块**，于是我们可以把所有局面写出来观察规律：

| 剩余石子数 `i` | 先手必胜？ |
|---------------|-----------|
| 0             | 否 (已经输了) |
| 1             | 是 |
| 2             | 是 |
| 3             | 是 |
| 4             | 否 |
| 5             | 是 |
| 6             | 是 |
| 7             | 是 |
| 8             | 否 |
| …             | … |

可以发现**每隔 4 个数就会出现一次必败局面**（`0, 4, 8, 12, …`）。为什么会这样？

- 当石子数是 **4 的倍数** 时，无论你取走 1、2、3 块，剩下的石子数都会变成 **不是 4 的倍数**（即 `4k‑1, 4k‑2, 4k‑3`），这时对手可以**恰好取走使总数再次变成 4 的倍数**，把局面交回给你。于是只要对手每次都这样补位，你就会被迫面对 4 的倍数，最终输掉最后一块石子。  
- 反过来，如果石子数 **不是 4 的倍数**，你可以**先手取走让剩余石子数变成 4 的倍数**（例如 `n % 4 = 1` 时取 1，`n % 4 = 2` 时取 2，`n % 4 = 3` 时取 3），此后把“把局面交回 4 的倍数”这件事交给对手。只要你一直这么做，就一定能赢。  

**核心技巧**：只需要看 `n` 除以 4 的余数。  

- 若 `n % 4 == 0` → 先手必败，返回 `False`。  
- 否则 → 先手必胜，返回 `True`。  

这就是**常数时间 O(1)** 的解法。  

#### 代码（Python）  

```python
def canWinNim(n: int) -> bool:
    """
    判断先手在石子堆为 n 时是否必胜。
    只要 n 不是 4 的倍数，就可以通过一次取走让剩余成为 4 的倍数，从而获胜。
    """
    # 取模运算：求 n 除以 4 的余数
    return n % 4 != 0   # 余数不为 0 则先手必胜
```

#### 复杂度  

- **时间复杂度**：`O(1)`。只做一次取模运算和一次比较，跟 `n` 大小无关。  
  - “常数时间”可以理解为不管 `n` 是 1 还是 10⁹，程序只跑几条指令，几乎瞬间返回。  
- **空间复杂度**：`O(1)`。只使用了极少的几个变量（函数参数和返回值），不随 `n` 增长。

## 心得  

- **核心技巧**：**取模（模 4）判断**——把游戏状态归纳为「是否是 4 的倍数」的二元判定。  
- **适用的题型**：  
  1. **取石子类博弈**（如「Can I Win」LeetCode 464，取 1~m 石子）  
  2. **取数字类游戏**（如「Divisor Game」LeetCode 1025，取因子）  
  3. **取子集类谜题**（如「Stone Game IX」）  
- **一句话总结解题钥匙**：**把所有局面归类，找出循环或周期规律，用模运算直接判断**。

## 反思  

- **第一反应**：看到“每回合只能取 1、2、3 块”，立刻想到**递归或 DP**，把每个子问题都算一遍。  
- **最容易踩的坑**：  
  - 忘记**边界情况**：`n = 0`（虽然题目保证 `n ≥ 1`），但在写通用代码时要考虑。  
  - 直接写递归会导致**栈溢出**或**超时**，因为子问题会被重复计算。  
- **下次遇到同类题**，第一步应该**尝试手动列举前几步的输赢表**，观察是否出现**固定周期**或**对称结构**，再决定是用 DP 还是直接用数学规律。
