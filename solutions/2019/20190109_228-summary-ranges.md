# #228. 区间摘要 / Summary Ranges

## 题目（英文原版）

**Description**

You are given a sorted unique integer array nums.
A range [a,b] is the set of all integers from a to b (inclusive).
Return the smallest sorted list of ranges that cover all the numbers in the array exactly. That is, each element of nums is covered by exactly one of the ranges, and there is no integer x such that x is in one of the ranges but not in nums.
Each range [a,b] in the list should be output as:

**Examples**

**Example 1:**

```
Input: nums = [0,1,2,4,5,7]
Output: ["0->2","4->5","7"]
Explanation: The ranges are:
[0,2] --> "0->2"
[4,5] --> "4->5"
[7,7] --> "7"
```

**Example 2:**

```
Input: nums = [0,2,3,4,6,8,9]
Output: ["0","2->4","6","8->9"]
Explanation: The ranges are:
[0,0] --> "0"
[2,4] --> "2->4"
[6,6] --> "6"
[8,9] --> "8->9"
```

**Constraints**

- 0 <= nums.length <= 20
- -231 <= nums[i] <= 231 - 1
- All the values of nums are unique.
- nums is sorted in ascending order.

## 题目（中文翻译）

**描述**  
给定一个已排序且元素唯一的整数数组 `nums`。  
区间 `[a,b]` 表示从 `a` 到 `b`（包含两端）的所有整数。  
返回一个 **最小的、按字典序排序** 的区间列表，使其恰好覆盖数组中的所有数字。也就是说，`nums` 中的每个元素恰好属于其中的唯一一个区间，并且不存在整数 `x` 落在某个区间内却不在 `nums` 中。  

列表中的每个区间 `[a,b]` 应按以下方式输出：

- 若 `a != b`，输出字符串 `"a->b"`；
- 若 `a == b`，输出字符串 `"a"`。

- `[7,7]` → `"7"`

**示例 2**

输出: `["0","2->4","6","8->9"]`

- `[0,0]` → `"0"`

- `[6,6]` → `"6"`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  
最直接的想法是：**枚举所有可能的区间**，检查每个区间 `[i, j]`（`i ≤ j`）是否恰好包含了 `nums[i] … nums[j]` 且之间没有缺失的整数。  
如果满足条件，就把这个区间记下来，最后把所有合法区间按出现顺序输出。

- **使用的数据结构**  
  - `list`（列表）相当于我们生活中的“装东西的盒子”，可以随时往里放元素、取元素。  
  - `set`（集合）可以类比为“查字典”。把数组全部放进集合后，用 `x in set` 可以 O(1) 地判断一个数是否出现过。

- **为什么正确**  
  对每一对起点 `i` 与终点 `j`，我们都完整检查了一遍：  
  - `nums[i]` 到 `nums[j]` 之间的每个整数 `k` 是否都在原数组里。  
  - 若全部存在，则说明 `[i, j]` 正好是一个合法的连续区间。  
  因为所有可能的 `(i, j)` 都遍历到了，所以不可能漏掉任何合法区间。

- **时间/空间复杂度**  
  - 外层遍历 `i` 有 `n` 次，内层遍历 `j` 也最多 `n` 次，检查区间内部最多 `j-i+1` 次。最坏情况下时间复杂度约为 **O(n³)**，这在实际中会非常慢。  
    - `O(n³)` 的意思可以想象成：如果有 10 个数字，需要检查 10×10×10=1000 次操作；如果是 20 个数字，则是 8000 次，以此类推，规模一大就指数级增长。  
  - 额外使用了一个集合保存所有元素，空间复杂度是 **O(n)**（因为集合里装了 `n` 个数）。

#### 代码（Python）

```python
from typing import List

def summaryRanges_bruteforce(nums: List[int]) -> List[str]:
    n = len(nums)
    if n == 0:
        return []

    # 把数组全部放进集合，后面可以 O(1) 判断一个数是否出现
    num_set = set(nums)          # 类比查字典，key 是数字，value（这里不需要）是它是否存在

    res = []                     # 用来存放最终的区间字符串
    # 枚举所有起点 i
    for i in range(n):
        # 枚举所有终点 j（j 必须 >= i）
        for j in range(i, n):
            # 检查区间 [nums[i], nums[j]] 是否完整
            complete = True
            # 逐个检查区间内部的每个整数 k
            for k in range(nums[i], nums[j] + 1):
                if k not in num_set:   # 如果有缺失，说明不是连续区间
                    complete = False
                    break
            if complete:
                # 把合法区间转换成题目要求的字符串形式
                if nums[i] == nums[j]:
                    res.append(str(nums[i]))
                else:
                    res.append(f"{nums[i]}->{nums[j]}")
                # 一旦找到以 i 为起点的最长合法区间，就可以提前结束内层循环
                # 因为后面的 j 只会让区间更长，若已经不完整则后面更不完整
                break
    return res
```

#### 复杂度

- **时间复杂度**：`O(n³)`  
  - 想象有 `n` 本书，每本书里有 `n` 页，每页上还有 `n` 行文字，要逐行检查，工作量是 `n³`。  
- **空间复杂度**：`O(n)`  
  - 只用了一个集合保存 `n` 个数字和若干常数级别的临时变量。

### 2. 最优解

#### 思路  
暴力解的瓶颈在于 **重复检查同一个区间的内部元素**。实际上，数组已经是**有序且不重复**的，这让我们可以一次遍历就把所有连续区间找出来：

1. 设 `start` 为当前区间的起始下标。  
2. 向后扫描，只要 `nums[i] + 1 == nums[i+1]`（相邻两个数差为 1），说明它们是连续的，继续往前走。  
3. 当出现 “不连续” 的情况，或已经到达数组末尾时，就得到一个完整的区间 `[start, i]`。  
4. 把区间转成字符串：  
   - 若 `start == i`，只输出单个数字 `"x"`。  
   - 否则输出 `"start->i"`。  
5. 把 `i+1` 设为新的 `start`，继续下一段扫描。

这就是**双指针**（两个下标）或**一次遍历**的思想：我们用两个指针 `start` 与 `i` 同时前进，始终保持 `start` 指向当前区间的左端，`i` 指向右端。每次区间结束时，就把结果记录下来。

- **核心数据结构**  
  - **列表**：用来收集最终的字符串。  
  - **两个整数变量**（`start`、`i`）：相当于手里拿的两根尺子，分别标记区间的左边和右边。

- **为什么正确**  
  - 因为数组已经排好序，若 `nums[i] + 1 != nums[i+1]`，说明在 `nums[i]` 与 `nums[i+1]` 之间缺失了至少一个整数，区间必须在这里结束。  
  - 反之，只要相邻差为 1，区间就可以继续扩展。遍历完所有元素后，所有连续的子段都会被完整捕获。

- **时间/空间复杂度**  
  - 我们只遍历一次数组，时间 **O(n)**，线性增长。  
    - `O(n)` 可以理解为：如果有 10 个数字，只需要检查 10 次；20 个数字检查 20 次，工作量随元素个数线性增加。  
  - 只用了常数个额外变量和一个存放结果的列表，空间 **O(1)**（不计结果本身），即额外开销几乎不随输入规模增长。

#### 代码（Python）

```python
from typing import List

def summaryRanges(nums: List[int]) -> List[str]:
    """
    一次遍历得到所有连续区间。
    关键点：
    - 用 start 记录当前区间的左端下标
    - 用 i 逐个向右扫描，只要相邻元素差为 1 就继续
    - 当出现断层或到达数组末尾时，结束当前区间并写入答案
    """
    res = []                     # 最终返回的字符串列表
    n = len(nums)
    i = 0                        # i 负责遍历整个数组

    while i < n:
        start = i                # 记录本段区间的起点
        # 向前扩展，只要下一个数恰好比当前数大 1，就继续
        while i + 1 < n and nums[i] + 1 == nums[i + 1]:
            i += 1               # 区间右端右移
        # 此时 [start, i] 是一个完整的连续区间
        if start == i:           # 区间只有一个元素
            res.append(str(nums[start]))
        else:                    # 区间有两个或以上元素
            res.append(f"{nums[start]}->{nums[i]}")
        i += 1                    # 从下一个未处理的元素开始新一轮
    return res
```

#### 复杂度

- **时间复杂度**：`O(n)` — 只遍历一次数组，规模翻倍只会多走两倍的步数。  
- **空间复杂度**：`O(1)`（不计输出列表） — 只用了几个整数变量，额外内存基本不随 `n` 增长。

## 心得

- **核心技巧**：一次遍历 + “相邻差为 1” 判断（相当于**滑动窗口/双指针**的最简形态）。  
- **适用的题型**  
  1. 连续子数组/子序列划分（如 “分割数组使每段都是连续整数”）。  
  2. 需要把有序序列压缩成区间表示的场景（如 “合并区间” 的简化版）。  
  3. “寻找最长连续序列” 类题目（LeetCode 128），思路相似，只是要记录最长长度。  
- **一句话总结解题钥匙**：**“相邻元素差为 1 → 同一段；不为 1 → 段结束”。**

## 反思

- **第一反应**：看到“已排序且唯一”，立刻想到可以线性扫描，利用相邻差判断连续性。  
- **最容易踩的坑**  
  - 空数组需要单独返回 `[]`，否则 `while i < n` 循环会直接跳过。  
  - 只有一个元素的区间要输出单独的数字，而不是 `"x->x"`。  
  - 处理最后一个区间时，`while` 循环结束后一定要把当前区间写入答案，否则会漏掉末尾段。  
- **下次遇到同类题**：**先检查是否有序**，若有序就尝试“一次遍历 + 状态维护”，把“是否继续扩展当前段”抽象成一个简单的条件（本题是 `nums[i] + 1 == nums[i+1]`）。这样往往能直接得到最优解。
