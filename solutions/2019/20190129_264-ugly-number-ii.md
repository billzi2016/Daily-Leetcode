# #264. 丑数 II / Ugly Number II

> 难度：中等 · 标签：Hash Table、Math、Dynamic Programming、Heap (Priority Queue) · [LeetCode 链接](https://leetcode.com/problems/ugly-number-ii/)

---

## 题目（英文原版）

**Description**

An ugly number is a positive integer whose prime factors are limited to 2, 3, and 5.
Given an integer n, return the nth ugly number.

**Examples**

**Example 1:**

```
Input: n = 10
Output: 12
Explanation: [1, 2, 3, 4, 5, 6, 8, 9, 10, 12] is the sequence of the first 10 ugly numbers.
```

**Example 2:**

```
Input: n = 1
Output: 1
Explanation: 1 has no prime factors, therefore all of its prime factors are limited to 2, 3, and 5.
```

**Constraints**

- 1 <= n <= 1690

## 题目（中文翻译）

丑数（ugly number）是指其质因数（prime factors）仅包含 2、3、5 的正整数。  
给定一个整数 `n`，返回第 `n` 个丑数。

**示例 1**  
**输入**: `n = 10`  
**输出**: `12`  
**解释**: `[1, 2, 3, 4, 5, 6, 8, 9, 10, 12]` 是前 10 个丑数的序列。

**示例 2**  
**输入**: `n = 1`  
**输出**: `1`  
**解释**: 1 没有质因数，因此它的所有质因数都满足仅限于 2、3、5。

**约束条件**  
- `1 <= n <= 1690`

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：从 1 开始，一个一个整数往后检查，它是不是“丑数”。  
判断一个数是否是丑数，只需要不断除以 2、3、5，最后看能否把它除干净（余数为 1）。  
这就像我们在生活中查字典：  
- **哈希表** 可以想象成一本词典，键（key）是单词，值（value）是解释。这里我们不需要字典，只是逐个“翻页”检查。

为什么这个方法能得到答案？因为我们遍历了所有正整数，只要遇到第 n 个符合条件的数，就一定是答案。

#### 代码（Python）

```python
def is_ugly(num: int) -> bool:
    """判断 num 是否只含因子 2、3、5（或为 1）"""
    if num == 1:
        return True
    for p in (2, 3, 5):
        while num % p == 0:          # 能被 p 整除就一直除
            num //= p
    return num == 1                  # 最后剩下的若是 1，则说明只用了 2、3、5

def nthUglyNumber_bruteforce(n: int) -> int:
    """暴力遍历寻找第 n 个丑数"""
    count = 0          # 已找到的丑数个数
    cur = 1            # 当前检查的正整数
    while True:
        if is_ugly(cur):
            count += 1
            if count == n:          # 找到第 n 个
                return cur
        cur += 1                    # 检查下一个数
```

#### 复杂度  

- **时间复杂度**：`O(k * log k)`（大概）  
  - `k` 是我们检查的整数个数，最坏要检查到第 n 个丑数所在的数。  
  - 每次 `is_ugly` 需要把数字不断除以 2、3、5，除的次数大约是 `log k`（因为每除一次数字至少变小一半）。  
  - 用大白话说，就是“检查的次数乘以每次检查的工作量”。  
- **空间复杂度**：`O(1)`  
  - 只用了几个计数器和临时变量，和输入规模无关。

> 这种方法在 n 很大时会非常慢，因为大多数整数根本不是丑数，我们在“翻页”时浪费了很多时间。

### 2. 最优解  

#### 思路  

暴力解的瓶颈在于**不停地去判断每个数**，而事实上我们完全可以只**生成丑数**，不必检查非丑数。  
观察丑数的生成规律：

- 任意一个丑数 `U`，把它乘以 2、3、5 必然得到更大的丑数。  
- 因此，如果我们把已经生成的丑数列表记作 `ugly`，则下一个丑数一定是  
  `min( ugly[i2] * 2 , ugly[i3] * 3 , ugly[i5] * 5 )`。  

这就像 **把三条已经排好序的队列合并**（类似归并排序的合并步骤）：

1. 初始化 `ugly = [1]`，因为 1 是第一个丑数。  
2. 用三个指针 `i2、i3、i5` 分别指向 `ugly` 中可以乘以 2、3、5 的位置，初始都指向 0。  
3. 每一步取 `next_val = min(ugly[i2]*2, ugly[i3]*3, ugly[i5]*5)`，把它加入 `ugly`。  
4. 如果 `next_val` 来自 `ugly[i2]*2`，说明该位置已经被使用，`i2 += 1`；同理处理 `i3、i5`。  
5. 重复第 3、4 步，直到得到第 n 个丑数。

关键点解释：

- **指针的意义**：指针指向的是“下一个还没乘过对应因子的丑数”。比如 `i2` 指向的 `ugly[i2]` 乘以 2 产生的数还没有出现在序列里。  
- **去重**：有时 `ugly[i2]*2`、`ugly[i3]*3`、`ugly[i5]*5` 可能相等（例如 6 = 2*3），此时我们要把所有产生相同值的指针都向前移动，防止把同一个数加入多次。  

这样我们只产生 `n` 个数，时间线性 `O(n)`，空间只需要保存这 `n` 个数 `O(n)`（如果只想要第 n 个，也可以只保留最新的几个，但这里保持列表更直观）。

#### 代码（Python）

```python
def nthUglyNumber(n: int) -> int:
    """三指针动态规划，线性时间生成第 n 个丑数"""
    ugly = [1] * n          # 预分配空间，ugly[i] 最终保存第 i+1 个丑数
    i2 = i3 = i5 = 0        # 三个指针初始都指向第一个丑数 1

    next2, next3, next5 = 2, 3, 5   # 下一个候选值（分别乘以 2、3、5）

    for idx in range(1, n):        # 从第 2 个丑数开始填
        # 取三个候选值的最小者作为下一个丑数
        next_ugly = min(next2, next3, next5)
        ugly[idx] = next_ugly

        # 对应的指针前进，并更新该指针的候选值
        if next_ugly == next2:      # 说明是 ugly[i2] * 2 产生的
            i2 += 1
            next2 = ugly[i2] * 2
        if next_ugly == next3:      # 说明是 ugly[i3] * 3 产生的
            i3 += 1
            next3 = ugly[i3] * 3
        if next_ugly == next5:      # 说明是 ugly[i5] * 5 产生的
            i5 += 1
            next5 = ugly[i5] * 5

    return ugly[-1]                 # 最后一个即为第 n 个丑数
```

#### 复杂度  

- **时间复杂度**：`O(n)`  
  - 每一次循环只做常数次比较、赋值和指针移动，循环 n‑1 次。  
  - 用通俗的话说，就是“我们只走了一遍，从第 1 到第 n，只花了线性的时间”。  
- **空间复杂度**：`O(n)`  
  - 需要保存前 n 个丑数的列表，规模随 n 增长。  
  - 如果只想返回第 n 个，可以把列表改成固定大小的循环数组，空间可以降到 `O(1)`，但实现会稍微复杂，这里保持 `O(n)` 更易懂。

## 心得  

- **核心技巧**：**多指针合并有序序列**（或说“三路归并”），它把“生成+排序”一步到位。  
- **适用的题型**  
  1. **合并 k 条有序链表**（LeetCode 23）——使用最小堆或多指针。  
  2. **有序数组的第 k 小元素**（LeetCode 378）——同样利用指针或堆。  
  3. **超级丑数**（LeetCode 313）——扩展到任意质数集合的多指针版本。  
- **一句话总结解题钥匙**：  
  *“只产生需要的序列，利用指针同步维护每条产生路径的最小候选值”。*

## 反思  

- **第一反应**：直接遍历每个整数并判断是否丑，感觉最简单。  
- **最容易踩的坑**  
  - **去重**：`2*3` 与 `3*2` 会产生相同的候选值，忘记同时推进对应指针会导致重复出现。  
  - **指针越界**：指针移动后一定要重新计算对应的候选值，否则会出现错误的最小值。  
  - **溢出**：在语言中整数范围受限时，乘法可能导致溢出（Python 没有这个问题）。  
- **下次遇到同类题**：第一步先思考“能否只生成目标序列而不是遍历所有可能”，再考虑使用**多指针**或**最小堆**来保持有序。
