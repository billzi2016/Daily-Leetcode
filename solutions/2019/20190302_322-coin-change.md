## 题目（英文原版）

**Description**

You are given an integer array coins representing coins of different denominations and an integer amount representing a total amount of money.
Return the fewest number of coins that you need to make up that amount. If that amount of money cannot be made up by any combination of the coins, return -1.
You may assume that you have an infinite number of each kind of coin.

**Examples**

**Example 1:**

```
Input: coins = [1,2,5], amount = 11
Output: 3
Explanation: 11 = 5 + 5 + 1
```

**Example 2:**

```
Input: coins = [2], amount = 3
Output: -1
```

**Example 3:**

```
Input: coins = [1], amount = 0
Output: 0
```

**Constraints**

- 1 <= coins.length <= 12
- 1 <= coins[i] <= 231 - 1
- 0 <= amount <= 104

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**枚举所有可能的硬币组合**，看哪一种正好凑出 `amount`，并且硬币数量最少。  
可以把它想象成**把零钱装进背包**，我们把每一种硬币当成一种“物品”，每次可以无限次取用（因为硬币数量无限），我们要把背包装满恰好 `amount`，并且装的物品数量最少。

实现上，常见的做法是**深度优先搜索（DFS）+ 回溯**：

1. 按照硬币面值从大到小的顺序尝试，这样可以先把“大硬币”用掉，理论上可以更快得到较小的硬币数目。  
2. 对每一种硬币，尝试使用 `0、1、2 …` 次（只要不超过 `amount`），递归处理剩余金额。  
3. 当剩余金额恰好为 `0` 时，记录当前使用的硬币数目；如果金额变成负数，则说明这条路径不合法，直接返回。

这种方法一定能找到答案（如果有解的话），因为它遍历了**所有**合法的组合。  

> **为什么正确**  
> - 我们把每一种硬币的使用次数都枚举了，从 `0` 到能够凑满 `amount` 的最大次数。  
> - 只要有一种组合能够恰好等于 `amount`，搜索必定会走到那条路径并记录下它的硬币数。  

> **复杂度分析（大白话）**  
> - 假设 `n` 是硬币种类数，`amount` 是目标金额。每一种硬币我们最多会尝试 `amount / min(coins)` 次（最小硬币面值）。所以搜索树的高度大约是 `amount / min(coins)`，每层有 `n` 种选择，最坏情况下会产生指数级的递归调用。  
> - 用大 O 记法表示，就是 **时间复杂度 O(n^amount)**（指数级），这在 `amount` 达到 10⁴ 时几乎不可能跑完。  
> - 空间上，只需要保存递归栈，深度同样是 `amount / min(coins)`，所以 **空间复杂度 O(amount)**。

#### 代码（Python）

```python
from typing import List

def coin_change_brute(coins: List[int], amount: int) -> int:
    # 先把硬币从大到小排序，方便先尝试“大面值”
    coins.sort(reverse=True)
    best = float('inf')                     # 用来记录目前找到的最少硬币数

    def dfs(idx: int, remain: int, cnt: int) -> None:
        """
        idx   : 当前准备使用的硬币在 coins 中的下标
        remain: 还剩多少金额需要凑
        cnt   : 已经用了多少枚硬币
        """
        nonlocal best
        # 剪枝：已经用了的硬币数 >= 当前最优解，后面不可能更好
        if cnt >= best:
            return
        # 剩余金额为 0，说明找到一种合法组合，更新最优解
        if remain == 0:
            best = cnt
            return
        # 已经遍历完所有硬币仍未凑满，直接返回
        if idx == len(coins):
            return

        coin = coins[idx]
        # 这枚硬币最多可以使用多少次，不能超过 remain
        max_use = remain // coin
        # 从最多使用次数往下尝试，先用多的可以更快逼近最优
        for k in range(max_use, -1, -1):
            dfs(idx + 1, remain - k * coin, cnt + k)

    dfs(0, amount, 0)
    return -1 if best == float('inf') else best
```

#### 复杂度

- **时间复杂度：O(n^amount)** — 实际上是指数级的搜索，`amount` 增大一点点，运行时间就会爆炸。  
- **空间复杂度：O(amount)** — 递归栈最深可能需要 `amount / min(coins)` 层。

### 2. 最优解

#### 思路  

暴力解慢的根源在于**大量重复的子问题**。例如在搜索过程中会多次计算“凑成金额 7 用硬币 `[1,2,5]` 需要多少枚”，这些子问题的答案是相同的，完全可以把它们记下来，下次直接查询，而不必再重新枚举。

这正是**动态规划（Dynamic Programming，DP）**的核心思想：  
- **把大问题拆成小问题**，把每个小问题的答案保存起来（通常用数组或哈希表）。  
- 当需要同样的小问题时，直接读取已保存的答案，避免重复计算。

对本题来说，设 `dp[i]` 表示**凑出金额 `i` 所需的最少硬币数**。  
- 初始化：`dp[0] = 0`（凑出 0 元不需要硬币），其余 `dp[i]` 先设为一个很大的数（表示“不可达”）。  
- 转移方程：对于每一种硬币 `c`，如果 `i >= c`，则可以把 `c` 加到已经凑好的 `i-c` 上，得到一种新的凑法：  
  `dp[i] = min(dp[i], dp[i - c] + 1)`  
  这里的 `+1` 表示我们刚刚又使用了一枚硬币 `c`。  
- 最后检查 `dp[amount]` 是否仍然是“不可达”的大数，若是则返回 `-1`，否则返回 `dp[amount]`。

> **类比**：把 `dp` 想象成一本“找零手册”，第 `i` 页写着“凑出 `i` 元最少需要几枚硬币”。我们从第 0 页（0 元）开始往后翻，每翻一页都把所有硬币的使用情况都记录进去，最后直接查到第 `amount` 页的答案。

> **为什么是最优**  
> - 每个 `dp[i]` 都是基于所有可能的“前一步” `i - c` 计算出来的最小值，保证了没有遗漏更好的组合。  
> - 由于每个子问题只计算一次，时间是 **线性的**（相对于 `amount × n`），大幅提升效率。

> **复杂度解释**  
> - **时间复杂度 O(n·amount)**：我们遍历每个金额（最多 `amount` 次），对每个金额尝试所有硬币（最多 `n` 种），所以总操作次数约等于 `n × amount`。如果 `amount=10000`、`n=12`，大约只需要 120,000 次运算，完全可以在毫秒级完成。  
> - **空间复杂度 O(amount)**：只需要一个长度为 `amount+1` 的一维数组来保存每个金额的最少硬币数。

#### 代码（Python）

```python
from typing import List

def coin_change_dp(coins: List[int], amount: int) -> int:
    # dp[i] = 凑出金额 i 所需的最少硬币数，初始设为一个很大的数（相当于“无限大”）
    INF = amount + 1          # 因为最坏情况只会用 amount 枚面值为 1 的硬币
    dp = [INF] * (amount + 1)
    dp[0] = 0                 # 0 元不需要硬币

    # 对每一个金额 i，尝试所有硬币，看能否用更少的硬币得到 i
    for i in range(1, amount + 1):
        for c in coins:
            if i >= c:                     # 只有当硬币面值不超过当前金额时才有意义
                # dp[i - c] 已经是凑出 i-c 的最少硬币数，+1 表示再加一枚硬币 c
                dp[i] = min(dp[i], dp[i - c] + 1)

    # 如果 dp[amount] 仍然是 INF，说明没有任何组合能够凑出 amount
    return -1 if dp[amount] == INF else dp[amount]
```

#### 复杂度

- **时间复杂度：O(n·amount)** — 线性乘积，意味着即使 `amount` 达到 10⁴，运行时间也很快。  
- **空间复杂度：O(amount)** — 只用了一个一维数组，空间占用随 `amount` 线性增长。

## 心得

- **核心技巧**：动态规划（DP）——把“凑零钱”问题拆成子金额的最优子结构。  
- **适用的类似题型**  
  1. **完全背包（Unbounded Knapsack）**：如 “完全背包问题” 需要在无限使用每种物品的前提下求最大价值。  
  2. **最小路径和**：在网格中求从左上到右下的最小和，思路同样是把每个格子的最优解记录下来。  
  3. **爬楼梯**：求到第 `n` 阶的最少步数，也可以用 DP 递推。  
- **一句话总结**：**把每一个“凑到多少金额”当作子问题，记录最少硬币数，逐步向上推进即可**。

## 反思

- **第一反应**：看到“无限硬币”和“最少数量”，自然想到穷举所有组合（暴力 DFS）。  
- **最容易踩的坑**  
  1. **忘记初始化不可达状态**：如果没有把 `dp` 初始化为“大数”，后面的 `min` 比较会出错。  
  2. **遗漏 `amount = 0` 的特殊情况**：此时答案应为 `0`，而不是 `-1`。  
  3. **硬币面值重复或顺序不同**：DP 本身不受顺序影响，但在实现 BFS/DFS 时要注意去重或排序。  
- **下次类似题的第一步**：先判断是否存在“子问题的最优子结构”，如果有，就立刻写出 DP 状态定义 `dp[i]` 并构造转移方程，而不是直接去暴力搜索。
