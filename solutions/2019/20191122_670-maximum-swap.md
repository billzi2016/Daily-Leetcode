# #670. 最大交换 / Maximum Swap

> 难度：中等 · 标签：Math、Greedy · [LeetCode 链接](https://leetcode.com/problems/maximum-swap/)

---

## 题目（英文原版）

**Description**

You are given an integer num. You can swap two digits at most once to get the maximum valued number.
Return the maximum valued number you can get.

**Examples**

**Example 1:**

```
Input: num = 2736
Output: 7236
Explanation: Swap the number 2 and the number 7.
```

**Example 2:**

```
Input: num = 9973
Output: 9973
Explanation: No swap.
```

**Constraints**

- 0 <= num <= 108

---

## 题目（中文翻译）

给定一个整数 `num`。你最多可以交换两个数字一次，以得到数值最大的整数。返回可以得到的最大整数。

约束条件：
- `0 <= num <= 10^8`

示例：
示例 1:
Input: num = 2736
Output: 7236
Explanation: 交换数字 2 和数字 7。

示例 2:
Input: num = 9973
Output: 9973
Explanation: 不需要交换。

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  
最直接的想法是把所有可能的**一次交换**都枚举一遍，然后取最大的结果。  
- 把整数 `num` 转成字符串（或者列表）方便逐位访问。  
- 用两层循环，`i` 从左到右遍历每个位置，`j` 从 `i+1` 到末尾遍历后面的每个位置。  
- 对每一对 `(i, j)`，交换这两个字符得到一个新的数字，和当前最大值比较，保存更大的那个。  
- 记得把数字再转回整数返回。  

这里用到的唯一数据结构是**列表**（把字符序列装进列表），可以把它想象成一排放好的数字卡片，交换两张卡片就是一次操作。  

这种做法一定能得到答案，因为我们把**所有**合法的交换都尝试了一遍，最大值必然在其中。  

**时间/空间复杂度**  
- 外层循环跑 `n` 次，内层循环最多跑 `n-1` 次，整体是 `n × (n-1) / 2 ≈ O(n²)`，也就是说如果数字有 10 位，最多要检查 45 次；如果有 100 位，就要检查 4950 次。  
- 只用了一个长度为 `n` 的列表来存放字符，空间是 `O(n)`，额外的常数级空间可以忽略不计。  

#### 代码（Python）  

```python
def maximumSwap_brute(num: int) -> int:
    # 把整数转成字符列表，方便交换
    digits = list(str(num))
    n = len(digits)
    max_num = num                         # 先把原数当作最大值

    # 双层循环枚举所有 i < j 的位置
    for i in range(n):
        for j in range(i + 1, n):
            # 交换 i、j 位置的数字
            digits[i], digits[j] = digits[j], digits[i]

            # 交换后得到的整数
            cur = int(''.join(digits))
            if cur > max_num:             # 只保留更大的
                max_num = cur

            # 把交换恢复，准备尝试下一对
            digits[i], digits[j] = digits[j], digits[i]

    return max_num
```

#### 复杂度  
- **时间复杂度**：`O(n²)` —— 两层循环遍历所有位置对，`n` 是数字的位数。  
- **空间复杂度**：`O(n)` —— 需要把数字拆成长度为 `n` 的字符列表。

### 2. 最优解  

#### 思路  
暴力解的瓶颈在于**每一次交换都要重新生成整个数字**，导致二次遍历。  
其实我们只需要一次遍历就能找到最合适的交换位置：

1. **记录每个数字最后出现的位置**。  
   想象一张“数字→最右侧位置”的查字典表（哈希表），就像查字典时，词条对应的页码。  
   只要遍历一遍，就能得到 `last[d] = 最右边出现的 d 的下标`。

2. 从左到右扫描每一位 `i`（高位优先），尝试把它换成**更大的数字且在它右边出现过**的最大数字。  
   - 对当前位的数字 `cur`，检查 9、8、…、`cur+1`（从大到小）是否在 `last` 中且下标 > `i`。  
   - 如果找到了，就把 `cur` 与那个更大的数字所在的下标 `j` 交换，得到的数字必然是最大值，因为：  
     - 我们先尝试更大的数字（9 → 8 …），一旦能换，就能把最高位提升到可能的最高。  
     - 右侧的 `j` 是该更大数字最右边出现的位置，换到这里不会影响后面的更大数字的使用机会。  

3. 只需要**一次交换**，完成后直接返回。若遍历结束都没有找到可以提升的交换，则原数已经是最大。

整个过程只遍历两次数字：一次构建 `last`，一次寻找可交换的更大数字，时间是线性的 `O(n)`。

#### 代码（Python）  

```python
def maximumSwap(num: int) -> int:
    # 把整数转成列表，便于原地交换
    digits = list(str(num))
    n = len(digits)

    # 1️⃣ 记录每个数字最后出现的位置
    last = {}                       # key: 数字字符, value: 最右侧下标
    for i, d in enumerate(digits):
        last[d] = i                 # 后面的会覆盖前面的，留下最右边的下标

    # 2️⃣ 从左到右寻找可以提升的交换
    for i, d in enumerate(digits):
        # 从 9 往下检查，找第一个比当前数字大的且在右侧出现的数字
        for larger in map(str, range(9, int(d), -1)):   # 9,8,...,d+1
            if larger in last and last[larger] > i:    # 必须在 i 的右边
                j = last[larger]                       # 右侧最靠右的那个更大数字
                # 交换 i 与 j
                digits[i], digits[j] = digits[j], digits[i]
                return int(''.join(digits))           # 只交换一次，直接返回

    # 3️⃣ 没有任何可以提升的交换，原数即为最大
    return num
```

#### 复杂度  
- **时间复杂度**：`O(n)` —— 第一次遍历构建 `last`，第二次遍历每位最多检查 9 次（常数），整体与位数线性相关。相较于暴力的 `O(n²)`，快了很多。  
- **空间复杂度**：`O(1)`（实际上是 `O(10)`）—— 哈希表最多保存 10 个键值对（0~9），视作常数空间。  

## 心得  

- 这道题核心考察**贪心**思路：在最高位尽可能放最大的可用数字。  
- 类似技巧常出现在：  
  1. **"Largest Number After Digit Swaps"**（把数字按位换成更大）  
  2. **"Monotone Increasing Digits"**（把数字变成单调不递减的最大数）  
  3. **"Reorder Log Files"**（对字符串按字典序贪心排序）  
- 一句话总结解题钥匙：**“从左往右，找左侧第一个可以被右侧更大的数取代的位置，且取最右的更大数”。**  

## 反思  

- 第一次看到题目，我的直觉是“把所有可能的交换都试一遍”，于是想到暴力枚举。  
- 最容易踩的坑：  
  - 忽略 **“只允许一次交换”**，误写成可以多次交换的动态规划。  
  - 没有记录每个数字的**最右出现位置**，导致找不到最合适的 `j`，从而错过更大的结果。  
  - 特殊情况如 `num` 为单字符或已经是最大数时，需要直接返回。  
- 下次遇到同类“只允许一次操作、要求最大/最小” 的题目时，第一步应该思考**“从最高位开始，能否用右侧更优的元素替换？”**，并利用**哈希表/数组记录最右位置**来实现一次遍历的贪心。
