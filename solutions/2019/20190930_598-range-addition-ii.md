# #598. 区间加法 II / Range Addition II

> 难度：简单 · 标签：Array、Math · [LeetCode 链接](https://leetcode.com/problems/range-addition-ii/)

---

## 题目（英文原版）

**Description**

You are given an m x n matrix M initialized with all 0's and an array of operations ops, where ops[i] = [ai, bi] means M[x][y] should be incremented by one for all 0 <= x < ai and 0 <= y < bi.
Count and return the number of maximum integers in the matrix after performing all the operations.

**Examples**

**Example 1:**

```
Input: m = 3, n = 3, ops = [[2,2],[3,3]]
Output: 4
Explanation: The maximum integer in M is 2, and there are four of it in M. So return 4.
```

**Example 2:**

```
Input: m = 3, n = 3, ops = [[2,2],[3,3],[3,3],[3,3],[2,2],[3,3],[3,3],[3,3],[2,2],[3,3],[3,3],[3,3]]
Output: 4
```

**Example 3:**

```
Input: m = 3, n = 3, ops = []
Output: 9
```

**Constraints**

- 1 <= m, n <= 4 * 104
- 0 <= ops.length <= 104
- ops[i].length == 2
- 1 <= ai <= m
- 1 <= bi <= n

---

## 题目（中文翻译）

给定一个大小为 `m × n` 的矩阵 **M**，初始时所有元素均为 `0`，以及一个操作数组 `ops`。其中 `ops[i] = [a_i, b_i]` 表示对所有满足 `0 ≤ x < a_i` 且 `0 ≤ y < b_i` 的 `M[x][y]` 加 `1`（即对一个左上角为 `(0,0)`、右下角为 `(a_i‑1, b_i‑1)` 的子矩阵（submatrix）进行增量操作）。

在执行完所有操作后，统计矩阵中出现的**最大整数**的个数，并返回该数量。

---

### 示例

**示例 1**

```
Input: m = 3, n = 3, ops = [[2,2],[3,3]]
Output: 4

```

**示例 2**

```
Input: m = 3, n = 3, ops = [[2,2],[3,3],[3,3],[3,3],[2,2],[3,3],[3,3],[3,3],[2,2],[3,3],[3,3],[3,3]]
Output: 4
```

**示例 3**

```
Input: m = 3, n = 3, ops = []
Output: 9
```

- `0 ≤ ops.length ≤ 10^4`
- `ops[i].length == 2`
- `1 ≤ a_i ≤ m`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是“把题目说的每一步都照搬下来”。  
我们先建立一个 `m × n` 的全 0 矩阵 `M`，然后遍历 `ops` 中的每个操作 `[a, b]`：

- 对于所有满足 `0 ≤ x < a` 且 `0 ≤ y < b` 的格子 `M[x][y]`，把它的值加 1。  
  这一步可以想象成在一张 **电子表格**（Excel）里，用一个小刷子把左上角的 `a 行 × b 列` 区域全部涂颜色，每涂一次数值就 +1。

全部操作完成后，矩阵里会出现若干不同的整数。我们只要找出最大的整数，然后统计它出现了多少次即可。

> **为什么这种方法一定对？**  
> 题目要求的每一次增量都只针对左上角的子矩阵，暴力模拟正是把这些增量“一条条”加到对应的格子上，最后的矩阵必然就是题目所说的“执行完所有操作后的矩阵”。因此答案必然正确。

#### 代码（Python）

```python
def maxCount_bruteforce(m: int, n: int, ops: list[list[int]]) -> int:
    # 1️⃣ 建立 m 行 n 列的全 0 矩阵
    M = [[0] * n for _ in range(m)]

    # 2️⃣ 按顺序执行每个操作
    for a, b in ops:                     # ops 中的每个 [a, b]
        for i in range(a):               # 行号 0 .. a-1
            for j in range(b):           # 列号 0 .. b-1
                M[i][j] += 1              # 对应格子加 1

    # 3️⃣ 找出矩阵中的最大值
    max_val = max(max(row) for row in M)   # 先找每行最大，再取整体最大

    # 4️⃣ 统计最大值出现的次数
    cnt = sum(cell == max_val for row in M for cell in row)
    return cnt
```

> **代码注释**  
> - 第 1 行创建了一个二维列表，等价于“纸上画一个 m×n 的格子”。  
> - 第 5‑9 行用三层循环把每个操作对应的子矩阵全部加 1，类似“刷子一次刷完”。  
> - 第 12‑13 行先找到最大的数字，然后遍历全部格子统计相等的格子数。

#### 复杂度

- **时间复杂度**：`O(m * n * len(ops))`  
  想象每一次操作都要遍历它指定的子矩阵，最坏情况下 `a = m, b = n`，即每次都遍历整个矩阵。于是总工作量≈`矩阵大小 × 操作数`。  
  用大白话说，就是“如果矩阵有 10 000 格，操作有 1 000 次，就要做 1 000 万次加法”，显然太慢。

- **空间复杂度**：`O(m * n)`  
  需要保存整个矩阵的值，跟矩阵大小成正比。

### 2. 最优解

#### 思路  

从暴力解出发，**慢的地方**是每次都要遍历整块子矩阵去加 1。  
观察题目可以发现：

> 所有操作都是对左上角的矩阵进行“加一”，而我们最终只关心**最大整数出现的次数**。

如果一个格子被 **所有** 操作覆盖，那么它的值会是最大值（因为它被加了最多次）。  
反之，只要有一次操作没有覆盖到某个格子，那它的值就会少加一次，肯定不是最大值。

所以，**最大整数所在的格子** 必须同时满足所有操作的范围。  
这等价于取所有 `[a, b]` 的 **交集**（共同的左上角子矩阵），交集的行数是所有 `a` 中的最小值 `min_a`，列数是所有 `b` 中的最小值 `min_b`：

- `min_a = min(a_i for [a_i, b_i] in ops)`（如果 `ops` 为空，则 `min_a = m`）
- `min_b = min(b_i for [a_i, b_i] in ops)`（如果 `ops` 为空，则 `min_b = n`）

交集的面积 `min_a * min_b` 正好就是**最大整数出现的格子数**。  
如果没有任何操作（`ops` 为空），整个矩阵都是 0，所有格子都是最大值，答案就是 `m * n`。

> **类比**  
> 把每个操作想象成一块“透明的纸”，纸只覆盖左上角的 `a 行 × b 列` 区域。把所有纸叠在一起，只有被所有纸共同覆盖的部分才会被涂成最深的颜色。我们要的就是这块最深颜色的面积。

#### 代码（Python）

```python
def maxCount(m: int, n: int, ops: list[list[int]]) -> int:
    # 如果没有任何操作，整个矩阵都是 0，所有格子都是最大值
    if not ops:
        return m * n

    # 取所有 a 的最小值，所有 b 的最小值
    min_a = m          # 初始设为矩阵的行数上限
    min_b = n          # 初始设为矩阵的列数上限
    for a, b in ops:   # 遍历每个操作
        if a < min_a:   # 更新行的最小上界
            min_a = a
        if b < min_b:   # 更新列的最小上界
            min_b = b

    # 交集的面积即为答案
    return min_a * min_b
```

> **代码要点**  
> - 第 2‑4 行处理特殊情况 `ops` 为空，直接返回 `m*n`。  
> - 第 7‑12 行只需要一次遍历即可得到所有 `a`、`b` 的最小值，时间上只跟 `ops` 长度有关。  
> - 第 15 行把最小行数与最小列数相乘得到答案。

#### 复杂度

- **时间复杂度**：`O(len(ops))`  
  只遍历一次 `ops`，不管矩阵多大，都只跟操作数有关。相当于“只看每张纸的大小，不去实际铺在地上”。  
  与暴力解的 `O(m·n·len(ops))` 相比，快了好几个数量级。

- **空间复杂度**：`O(1)`  
  只用了常数个变量 `min_a、min_b`，不需要额外的矩阵存储。

## 心得

- **核心技巧**：**取交集**（最小行数 × 最小列数），把“所有操作都覆盖的区域”直接算出来。
- **适用的题型**  
  1. “矩阵/数组的公共区域”类（如 LeetCode 598. Range Addition II）  
  2. “求交叉点/公共长度”类（如求多个区间的公共交集长度）  
  3. “最大重复次数”类，利用最小/最大约束快速定位答案
- **一句话总结**：**所有操作的左上角子矩阵的交集大小，就是最大整数出现的次数**。

---

## 反思

- **第一反应**：看到“每个操作都把左上角子矩阵加 1”，自然会想到直接模拟矩阵。
- **最容易踩的坑**  
  - 忽略 `ops` 为空的情况，导致返回 `0` 而不是 `m*n`。  
  - 把 “最大整数” 误认为是“最大操作次数”，其实只要找所有操作共同覆盖的格子即可。  
  - 在暴力实现时，容易把循环写成 `for i in range(a+1)` 之类的越界错误。
- **下次遇到同类题**：第一步先思考“哪些格子被**所有**操作同时影响”，把问题转化为“求交集”，往往能直接得到 O(1) 空间、O(k) 时间的答案（k 为操作数）。
