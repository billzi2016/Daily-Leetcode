# #239. 滑动窗口最大值 / Sliding Window Maximum

> 难度：困难 · 标签：Array、Queue、Sliding Window、Heap (Priority Queue)、Monotonic Queue · [LeetCode 链接](https://leetcode.com/problems/sliding-window-maximum/)

## 题目（英文原版）

**Description**

You are given an array of integers nums, there is a sliding window of size k which is moving from the very left of the array to the very right. You can only see the k numbers in the window. Each time the sliding window moves right by one position.
Return the max sliding window.

**Example 1:**

```
Input: nums = [1,3,-1,-3,5,3,6,7], k = 3
Output: [3,3,5,5,6,7]
Explanation: 
Window position                Max
---------------               -----
[1  3  -1] -3  5  3  6  7       3
 1 [3  -1  -3] 5  3  6  7       3
 1  3 [-1  -3  5] 3  6  7       5
 1  3  -1 [-3  5  3] 6  7       5
 1  3  -1  -3 [5  3  6] 7       6
 1  3  -1  -3  5 [3  6  7]      7
```

**Example 2:**

```
Input: nums = [1], k = 1
Output: [1]
```

**Constraints**

- 1 <= nums.length <= 105
- -104 <= nums[i] <= 104
- 1 <= k <= nums.length

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是**每次窗口移动时，都把窗口里的 `k` 个数全部取出来，遍历一次求最大值**。  
可以把窗口看成一段连续的纸条，窗口左边界从数组的第 `0` 位开始，一直往右移动到 `len(nums)-k`。每次取出这段纸条里的数，用 `max()`（或手动遍历）找出最大的那个。

- **用到的数据结构**：普通的 Python 列表（list），相当于装东西的盒子。我们不需要特殊的数据结构，只要能一次取出窗口里的元素即可。  
- **为什么正确**：因为我们对每一个可能的窗口都完整地检查了一遍，找到了每个窗口的最大值，自然不会漏掉任何情况。  

> **大白话解释复杂度**：  
> - 时间复杂度写成 `O(n·k)`，意思是“如果数组长度是 `n`，窗口大小是 `k`，那么我们大概要做 `n` 次（每个窗口一次）* `k` 次（每次遍历窗口） 的工作”。  
> - 空间复杂度写成 `O(k)`，因为我们只需要额外存放当前窗口的 `k` 个数（其实可以直接在原数组上取，不需要额外空间），所以最多用到跟窗口大小成正比的空间。

#### 代码（Python）

```python
from typing import List

def max_sliding_window_brute(nums: List[int], k: int) -> List[int]:
    """
    暴力解法：对每一个窗口都遍历一次取最大值
    """
    n = len(nums)
    # 结果列表，长度为 n - k + 1
    res: List[int] = []
    # 窗口左边界 i 从 0 移动到 n - k
    for i in range(n - k + 1):
        # 取出窗口内的所有元素
        window = nums[i:i + k]          # 切片会产生一个新列表，长度正好是 k
        # 求最大值（也可以手动遍历求 max）
        cur_max = max(window)           # O(k) 的操作
        res.append(cur_max)             # 把当前窗口的最大值加入结果
    return res
```

#### 复杂度

- **时间复杂度**：`O(n·k)`  
  *含义*：如果数组有 `n` 个数，窗口大小是 `k`，我们会对每个窗口（共 `n‑k+1` ≈ `n` 个）遍历 `k` 次，整体工作量大约是 `n` 乘 `k`。当 `k` 接近 `n` 时，最坏情况接近 `O(n²)`，也就是“平方级”耗时，明显会慢。

- **空间复杂度**：`O(k)`（或 `O(1)`）  
  *含义*：我们只额外保存当前窗口的 `k` 个数（切片产生的临时列表），除此之外不需要额外的存储。结果数组本身不计入额外空间。

### 2. 最优解

#### 思路  

从暴力解可以看到 **瓶颈在于每次都要遍历整个窗口**，这导致时间复杂度随 `k` 增大而线性增长。  
我们需要一种 **只在必要时才检查元素**、并且**能够在 O(1) 时间内得到当前窗口最大值** 的方法。  

##### 关键观察  

1. **窗口左边界每次只会向右移动一步**，所以已经离开窗口的元素再也不会影响以后任何窗口的最大值。  
2. **如果我们把窗口内的元素按“从大到小”排好序，只保留可能成为最大值的元素**，那么窗口左端的第一个元素就是当前窗口的最大值。  

这正好对应 **单调递减队列（Monotonic Queue）** 的思路：

- 队列（这里用 `deque`）从左到右保存的是 **元素下标**，对应的数值 **严格递减**。  
- 当新元素 `nums[i]` 来到窗口时，**把队列右侧所有比它小的元素全部踢出**，因为它们永远不可能再成为最大值（新元素更大且会更晚离开窗口）。  
- 队列左侧保存的始终是 **窗口内最大的元素的下标**。  
- 当窗口左边界 `i - k + 1` 超过队列左端的下标时，说明这个元素已经不在窗口里了，需要从队列左侧弹出。

这样，每个元素最多进队列一次、出队列一次，整体是 **线性 O(n) 时间**。

##### 为什么叫“单调队列”

想象队列是一条**排队买票的队伍**，队伍里只能站**更高的人**，因为如果后面站了一个更矮的人，前面更高的人永远会抢先买到票，矮的人永远不会影响结果。于是我们把所有比新来的“更矮”的人请出队伍，保持队伍“从前到后”高度单调递减。

##### 步骤概览

| 步骤 | 操作 | 目的 |
|------|------|------|
| 1 | 初始化空 `deque` | 为后面存放下标做准备 |
| 2 | 遍历数组 `i` 从 `0` 到 `n-1` | 逐个处理每个元素 |
| 3 | ① 把 `deque` 左端已超出窗口的下标弹出 | 保证队列只保存当前窗口内的元素 |
| 4 | ② 把 `deque` 右端所有 **对应值 ≤ nums[i]** 的下标弹出 | 移除“永远不会成为最大值”的元素 |
| 5 | ③ 把当前下标 `i` 加入 `deque` 右端 | 把新元素加入候选集合 |
| 6 | ④ 当窗口已经形成（`i ≥ k-1`）时，把 `deque` 左端对应的值加入结果 | 左端始终是当前窗口的最大值 |

##### 代码实现细节

- 使用 `collections.deque`，它支持 **O(1)** 时间的两端插入和删除。  
- 为了方便比较大小，我们在队列里存放 **下标** 而不是数值，这样既可以直接比较 `nums[deque[-1]]` 与 `nums[i]`，又能判断元素是否已经离开窗口（比较下标是否 `< i - k + 1`）。

#### 代码（Python）

```python
from collections import deque
from typing import List

def max_sliding_window(nums: List[int], k: int) -> List[int]:
    """
    最优解：使用单调递减队列（Monotonic Queue）实现 O(n) 时间
    """
    n = len(nums)
    if n * k == 0:          # 空数组或 k 为 0 的情况直接返回空列表
        return []
    if k == 1:              # 窗口大小为 1 时，每个元素本身就是最大值
        return nums[:]

    # 用 deque 保存「可能成为最大值」的元素下标，保持对应的数值递减
    deq: deque[int] = deque()
    res: List[int] = []     # 最终答案

    for i in range(n):
        # 1️⃣ 删除已经离开窗口的下标（只会出现在左端）
        while deq and deq[0] < i - k + 1:
            # print(f"下标 {deq[0]} 已经超出窗口，弹出")
            deq.popleft()

        # 2️⃣ 删除所有比当前元素小的下标（因为它们永远不可能成为最大值）
        while deq and nums[deq[-1]] < nums[i]:
            # print(f"下标 {deq[-1]} 对应的值 {nums[deq[-1]]} < {nums[i]}，弹出")
            deq.pop()

        # 3️⃣ 把当前下标加入队列右端
        deq.append(i)
        # print(f"加入下标 {i}，队列状态 {list(deq)}")

        # 4️⃣ 当窗口已经形成（i >= k-1），把队首元素对应的值加入答案
        if i >= k - 1:
            # 队首下标对应的数就是当前窗口的最大值
            res.append(nums[deq[0]])
            # print(f"窗口 [{i-k+1}, {i}] 最大值为 {nums[deq[0]]}")

    return res
```

#### 复杂度

- **时间复杂度**：`O(n)`  
  *含义*：数组里每个元素最多进入队列一次、离开队列一次，所有的 `while` 循环加起来只会执行 `2n` 次左右的操作，和数组长度成线性关系。与暴力解的 `O(n·k)` 相比，“每走一步只花常数时间”，速度快很多。

- **空间复杂度**：`O(k)`  
  *含义*：队列里最多保存 `k` 个下标（因为我们只保留窗口内的候选元素），所以额外使用的空间最多和窗口大小成正比。若 `k` 接近 `n`，最坏情况是 `O(n)`，但仍比暴力解的 `O(k)`（切片产生的临时列表）更可控。

## 心得

- **核心技巧**：**单调队列**（Monotonic Queue）——维护一个递减（或递增）序列，使得队首始终是当前窗口的极值。  
- **适用的题型**（类似思路）  
  1. **滑动窗口最大/最小值**（本题、LeetCode 239）  
  2. **柱状图中最大的矩形面积**（利用单调栈）  
  3. **接雨水**（使用单调栈或双指针）  
- **一句话总结解题钥匙**：**“只保留‘有可能赢得冠军’的元素”，用单调结构把无用的元素及时剔除**。

## 反思

- **拿到题目第一反应**：先想到最直接的遍历每个窗口求最大，随后意识到 `k` 可能很大，需要更快的方法。  
- **最容易踩的坑**  
  - **边界条件**：`k = 1`、`k = len(nums)`、数组只有一个元素时的返回值。  
  - **下标越界**：在判断是否要弹出左端元素时，需要使用 `i - k + 1` 而不是 `i - k`。  
  - **队列里存下标而不是值**：如果只存值，无法判断该元素是否已经离开窗口。  
- **下次遇到同类题，第一步该想到**：**“我能否用单调结构把窗口内部的‘无效元素’剔除，只保留可能的极值？”** 这一步往往能直接指向单调队列/栈的解法。
