# #403. 青蛙跳石头 / Frog Jump

> 难度：困难 · 标签：Array、Dynamic Programming · [LeetCode 链接](https://leetcode.com/problems/frog-jump/)

## 题目（英文原版）

**Description**

A frog is crossing a river. The river is divided into some number of units, and at each unit, there may or may not exist a stone. The frog can jump on a stone, but it must not jump into the water.
Given a list of stones positions (in units) in sorted ascending order, determine if the frog can cross the river by landing on the last stone. Initially, the frog is on the first stone and assumes the first jump must be 1 unit.
If the frog's last jump was k units, its next jump must be either k - 1, k, or k + 1 units. The frog can only jump in the forward direction.

**Examples**

**Example 1:**

```
Input: stones = [0,1,3,5,6,8,12,17]
Output: true
Explanation: The frog can jump to the last stone by jumping 1 unit to the 2nd stone, then 2 units to the 3rd stone, then 2 units to the 4th stone, then 3 units to the 6th stone, 4 units to the 7th stone, and 5 units to the 8th stone.
```

**Example 2:**

```
Input: stones = [0,1,2,3,4,8,9,11]
Output: false
Explanation: There is no way to jump to the last stone as the gap between the 5th and 6th stone is too large.
```

**Constraints**

- 2 <= stones.length <= 2000
- 0 <= stones[i] <= 231 - 1
- stones[0] == 0
- stones is sorted in a strictly increasing order.

## 题目（中文翻译）

一只青蛙正在过河。河面被划分为若干个单位（unit），每个单位上可能有也可能没有石头（stone）。青蛙只能跳到石头上，不能跳入水中。

给定一个按升序排列的石头位置列表 `stones`（单位），判断青蛙是否能够通过一次次落在石头上而到达最后一块石头。青蛙最初位于第一块石头，且第一次跳跃必须是 1 单位。

如果青蛙上一次跳了 `k` 单位，那么下一次跳跃只能是 `k - 1`、`k` 或 `k + 1` 单位。青蛙只能向前跳。

**示例 1**

```text
Input: stones = [0,1,3,5,6,8,12,17]
Output: true
Explanation: 青蛙可以先跳 1 单位到第 2 块石头，然后跳 2 单位到第 3 块石头，再跳 2 单位到第 4 块石头，接着跳 3 单位到第 6 块石头，4 单位到第 7 块石头，最后跳 5 单位到第 8 块石头，从而到达最后一块石头。
```

**示例 2**

```text
Input: stones = [0,1,2,3,4,8,9,11]
Output: false
Explanation: 没有办法跳到最后一块石头，因为第 5 块石头和第 6 块石头之间的间距太大。
```

**约束条件**

- `2 <= stones.length <= 2000`
- `0 <= stones[i] <= 2^31 - 1`
- `stones[0] == 0`
- `stones` 按严格递增顺序排序。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**把每一种可能的跳法都枚举出来**，只要有一种跳法能让青蛙最终站在最后一块石头上，就返回 `True`。  
可以把这个过程想象成在一棵**决策树**里走：  

- 树的根节点是第 0 块石头（位置 0），第一次必须跳 `1` 步到第 1 块石头。  
- 每到达一块石头，记录这一次跳了多少步 `k`，下一步就有最多三种选择：`k-1`、`k`、`k+1`（当然不能小于 1），并检查目标位置上是否真的有石头。  
- 如果有石头，就递归（或用栈）继续向前走；如果没有，就这条分支死掉。  

**用到的数据结构**  
- `set`：把所有石头的位置放进哈希表（类似字典查词典），可以在 **O(1)** 时间判断某个位置是否有石头。  
- `stack`（或递归调用）：保存“当前在第几块石头、上一次跳了多少步”这种状态，类似于“待办事项列表”。  

**为什么这个方法能得到正确答案**  
因为它穷举了**所有可能的跳法**，只要有一种能到达最后一块石头，必然会在遍历过程中被找到。  

**时间/空间复杂度**  
- 最坏情况下，每块石头都有三种跳法可选，深度为 `n`（石头数量），所以分支数是 `3^{n}`，这显然是指数级的，实际会因为很多跳法会直接撞墙而提前剪枝，但仍然是 **O(3^n)** 的上界。  
- 空间上要存放哈希表 `O(n)`，以及递归栈或显式栈的深度 `O(n)`。

> **大白话**：  
> `O(3^n)` 就像让你把 10 层的楼梯每层都可能往左、往中、往右走，所有可能的路线数会爆炸式增长，根本不可行。

#### 代码（Python）

```python
from typing import List

def canCross_bruteforce(stones: List[int]) -> bool:
    # 把所有石头的位置放进集合，查询是否有石头是 O(1)
    stone_set = set(stones)

    # 用栈模拟递归，元素是 (当前位置, 上一次跳的距离)
    stack = [(0, 0)]          # 起点在 0，上一跳视作 0（后面会强制跳 1）

    # 为了防止同一个状态被重复访问，使用 visited 集合去重
    visited = set()

    while stack:
        pos, last = stack.pop()
        # 如果已经到达最后一块石头，成功
        if pos == stones[-1]:
            return True

        # 记录已经访问过的状态，防止无限循环
        if (pos, last) in visited:
            continue
        visited.add((pos, last))

        # 根据题意，下一跳只能是 last-1, last, last+1（且必须 >=1）
        for jump in (last - 1, last, last + 1):
            if jump <= 0:          # 不能跳负数或 0 步
                continue
            nxt = pos + jump       # 计算下一个落点
            if nxt in stone_set:   # 只在有石头的地方落脚
                stack.append((nxt, jump))

    # 所有可能的路径都尝试完了，仍未到达最后一块石头
    return False
```

#### 复杂度

- **时间复杂度**：`O(3^n)`（指数级）  
  解释：每块石头最多产生 3 条新分支，最坏情况下会遍历所有分支，数量随石头数呈指数增长。  
- **空间复杂度**：`O(n)`  
  解释：`stone_set`、`visited`、以及栈的深度都和石头数量线性相关。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**大量重复的子问题**。例如，青蛙可能在不同的路径上多次到达同一个石头，并且上一次的跳距相同，这时后面的所有选择都是完全一样的。我们只需要记住“**在第 i 块石头上，上一跳是 k 步**”这个状态是否已经被探索过，后面再出现同样的状态就可以直接跳过，不必再次展开搜索。

这正好可以用**动态规划 + 哈希表**来实现：

1. **状态定义**  
   `dp[i]` 表示到达第 `i` 块石头时，所有可能的“上一次跳的距离”。用一个 `set` 保存所有合法的 `k`。  
   - 例如 `dp[3] = {2,3}` 表示站在第 3 块石头时，可能是上一次跳了 2 步或 3 步到达这里。

2. **初始状态**  
   - 第 0 块石头是起点，`dp[0] = {0}`（上一次跳 0 步，方便统一转移公式）。  
   - 第 1 块石头只能从第 0 块跳 1 步到达，所以 `dp[1] = {1}`。

3. **状态转移**  
   对于每一块石头 `i`（从左到右），遍历它的所有可能的 `k`（即 `dp[i]` 中的元素），尝试三种下一跳长度 `k-1, k, k+1`（>0）。如果跳到的位置恰好是后面的某块石头 `j`，就把对应的跳距加入 `dp[j]`。  
   - 为了快速判断“跳到的位置是否有石头”，仍然使用 **哈希表 `pos_to_index`**：把每个石头的位置映射到它在数组中的下标。

4. **终止条件**  
   最后检查 `dp[-1]`（最后一块石头的集合）是否非空；非空说明至少有一种合法的跳法能到达终点。

**关键点解释**  

- **哈希表 `pos_to_index`**：把位置 → 下标的映射想象成一本**“石头目录”**，查询某个位置是否有石头就像在目录里找页码，时间是常数 `O(1)`。  
- **集合 `dp[i]`**：记录所有可能的跳距，相当于**“这块石头上可以站的姿势”**。因为同一个石头可能被不同路径以不同的跳距到达，我们都要保留，后面才可能产生不同的下一步。  
- **剪枝**：如果某个 `k` 已经很大，而后面的石头之间的间距远小于 `k-1`，这些大跳距根本不可能再落在任何石头上，集合会自然保持较小，避免无用计算。

#### 代码（Python）

```python
from typing import List, Dict, Set

def canCross(stones: List[int]) -> bool:
    n = len(stones)
    if n == 0:
        return False

    # 1. 建立“位置 → 下标”的哈希表，像查字典一样快速判断是否有石头
    pos_to_index: Dict[int, int] = {pos: idx for idx, pos in enumerate(stones)}

    # 2. dp[i] 保存到达第 i 块石头时，所有可能的上一次跳距
    dp: List[Set[int]] = [set() for _ in range(n)]
    dp[0].add(0)          # 起点，上一跳视作 0

    # 3. 动态规划遍历每块石头
    for i in range(n):
        for k in dp[i]:               # 遍历所有可能的上一跳距离
            # 三种可能的下一跳：k-1, k, k+1（必须大于0）
            for jump in (k - 1, k, k + 1):
                if jump <= 0:
                    continue
                nxt_pos = stones[i] + jump   # 计算跳到的具体位置
                if nxt_pos in pos_to_index:  # 只有落在石头上才有效
                    nxt_idx = pos_to_index[nxt_pos]
                    dp[nxt_idx].add(jump)   # 把这次跳距记录到目标石头

    # 4. 判断最后一块石头是否可以被到达（对应的集合非空即为成功）
    return len(dp[-1]) > 0
```

#### 复杂度

- **时间复杂度**：`O(n * m)`，其中 `n` 为石头数量，`m` 为每块石头上可能出现的跳距个数。  
  - 在最坏情况下（比如等差递增的石头），`m` 的上界是 `O(√max_distance)`，但实际受 `stones[i] ≤ 2^31-1` 限制，且 `n ≤ 2000`，整体运行在几万次以内，远远小于指数级。  
  - 简单说，这个算法的时间复杂度接近 **线性**（`O(n)`），因为每个状态只会被处理一次。

- **空间复杂度**：`O(n * m)`（存 `dp` 集合）+ `O(n)`（哈希表）。  
  - 同样 `m` 在实际数据中通常很小，整体空间在几千到几万个整数，完全可接受。

> 与暴力解相比，**时间从指数级下降到近线性**，关键在于“记住已经走过的状态”，避免重复计算。

## 心得

- **核心技巧**：**状态记忆 + 哈希表**（即动态规划的“记忆化”思想）。  
- **适用的题型**  
  1. “Frog Jump” 系列题目（比如 LeetCode 403、1553）  
  2. “Jump Game” 类的变形（需要记录每一步的可行跳距）  
  3. “Word Break” 这类需要记忆子串可分割性的 DP  
- **一句话总结**：**把“位置 + 上一次跳距”当作唯一状态，记下来，后面再遇到同样的状态就直接跳过**。

## 反思

- **第一反应**：看到“上一次跳 k，下一跳可以是 k‑1/k/k+1”，立刻想到递归/DFS 暴力搜索。  
- **最容易踩的坑**  
  1. **跳距为 0**：`k-1` 可能为 0 或负数，需要过滤。  
  2. **重复状态**：没有去重会导致指数级爆炸。  
  3. **边界条件**：如果前两块石头距离不是 1，直接返回 `False`（因为第一跳必须是 1）。  
- **下次思考路线**：  
  1. 先判断是否有明显不可能（比如 `stones[1] != 1`）。  
  2. 把“位置 + 跳距”抽象成状态，问自己：**这个状态会不会被多次重复出现？**  
  3. 如果会，就考虑用哈希表/集合记忆，转向 DP/记忆化搜索。
