# #458. 可怜的猪 / Poor Pigs

## 题目（英文原版）

**Description**

There are buckets buckets of liquid, where exactly one of the buckets is poisonous. To figure out which one is poisonous, you feed some number of (poor) pigs the liquid to see whether they will die or not. Unfortunately, you only have minutesToTest minutes to determine which bucket is poisonous.
You can feed the pigs according to these steps:
Given buckets, minutesToDie, and minutesToTest, return the minimum number of pigs needed to figure out which bucket is poisonous within the allotted time.

**Examples**

**Example 1:**

```
Input: buckets = 4, minutesToDie = 15, minutesToTest = 15
Output: 2
Explanation: We can determine the poisonous bucket as follows:
At time 0, feed the first pig buckets 1 and 2, and feed the second pig buckets 2 and 3.
At time 15, there are 4 possible outcomes:
- If only the first pig dies, then bucket 1 must be poisonous.
- If only the second pig dies, then bucket 3 must be poisonous.
- If both pigs die, then bucket 2 must be poisonous.
- If neither pig dies, then bucket 4 must be poisonous.
```

**Example 2:**

```
Input: buckets = 4, minutesToDie = 15, minutesToTest = 30
Output: 2
Explanation: We can determine the poisonous bucket as follows:
At time 0, feed the first pig bucket 1, and feed the second pig bucket 2.
At time 15, there are 2 possible outcomes:
- If either pig dies, then the poisonous bucket is the one it was fed.
- If neither pig dies, then feed the first pig bucket 3, and feed the second pig bucket 4.
At time 30, one of the two pigs must die, and the poisonous bucket is the one it was fed.
```

**Constraints**

- 1 <= buckets <= 1000
- 1 <= minutesToDie <= minutesToTest <= 100

## 题目（中文翻译）

**描述**  
有 `buckets` 桶（bucket）液体，其中恰好有一桶是有毒的。为了找出是哪一桶有毒，你可以喂若干只（可怜的）猪（pig）喝液体，观察它们是否会死亡。不幸的是，你只有 `minutesToTest` 分钟的时间来确定有毒的桶。

你可以按照以下步骤喂猪：

> 给定 `buckets`、`minutesToDie`、`minutesToTest`，返回在规定时间内找出有毒桶所需的最少猪数量。

**示例 1**  
``` 
Input: buckets = 4, minutesToDie = 15, minutesToTest = 15
Output: 2
Explanation: 我们可以按如下方式确定有毒的桶：
- 时间 0 时，喂第一只猪喝第 1 桶和第 2 桶的液体，喂第二只猪喝第 2 桶和第 3 桶的液体。
- 时间 15 分钟后，会出现 4 种可能的结果：
  - 仅第一只猪死亡，则第 1 桶为有毒桶；
  - 仅第二只猪死亡，则第 3 桶为有毒桶；
  - 两只猪都死亡，则第 2 桶为有毒桶；
  - 两只猪都未死亡，则第 4 桶为有毒桶。
```

**示例 2**  
``` 
Input: buckets = 4, minutesToDie = 15, minutesToTest = 30
Output: 2
Explanation: 我们可以按如下方式确定有毒的桶：
- 时间 0 时，喂第一只猪喝第 1 桶，喂第二只猪喝第 2 桶。
- 时间 15 分钟后，会出现 2 种可能的结果：
  - 任意一只猪死亡，则有毒桶就是它所喝的那一桶；
  - 两只猪都未死亡，则继续喂：第一只猪喝第 3 桶，第二只猪喝第 4 桶。
- 时间 30 分钟时，必有一只猪死亡，死亡的那只猪所喝的桶即为有毒桶。
```

**约束条件**  

- `1 <= buckets <= 1000`
- `1 <= minutesToDie <= minutesToTest <= 100`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把每一只猪都当成“探测器”，把每只猪喂给 **所有** 可能的桶，然后等它们死或活。  
如果我们把每只猪的 **每一次喂食** 看作一次“询问”，那么暴力解的思路可以表述为：

1. **枚举**：把所有猪的所有喂食方案全部列举出来。  
   - 例如：有 `p` 只猪、`t` 次喂食（`t = minutesToTest // minutesToDie`），每只猪在每次喂食时可以选择喂 **哪个** 桶（或者不喂），于是每只猪有 `buckets + 1` 种选择。  
2. **模拟**：对每一种喂食方案，按照题目规则模拟猪的死亡过程，得到一种 **结果向量**（每只猪在第几次死亡，或一直活着）。  
3. **检查**：如果所有可能的有毒桶（`1 … buckets`）对应的结果向量 **互不相同**，说明这套喂食方案能够唯一定位有毒桶。  

把上面的步骤全部遍历，就是最笨的解法。

> **类比**：把 **哈希表** 想象成一本字典，`key` 是“有毒桶的编号”，`value` 是“实验结束后每只猪的死亡时间”。只要字典里每个 `key` 对应的 `value` 都不相同，就能通过查字典直接得出答案。

**为什么正确？**  
因为我们把所有可能的实验过程都穷举了，只要有一种实验能够把所有 `buckets` 种情况区分开来（即得到不同的死亡状态），就一定能在规定时间内找出毒桶。

**时间/空间复杂度**  
- **时间**：我们要遍历每只猪每次喂食的所有可能组合。每只猪有 `buckets+1` 种选择，喂食 `t` 次，所以单只猪的组合数是 `(buckets+1)^t`，`p` 只猪的组合数是 `((buckets+1)^t)^p = (buckets+1)^{t·p}`。因此时间复杂度是 **指数级**，记作 `O((buckets)^{t·p})`，实际运行会在几秒钟内爆炸。  
- **空间**：要保存每种组合对应的结果向量，需要 `O(p·t)` 的空间（每只猪的死亡时间），总体是 **线性** 的 `O(p·t)`。

> **大白话**：`O(n²)` 代表“数量级是 n 乘以 n”。这里的 `O((buckets)^{t·p})` 就是“数量级是 bucket 的 t·p 次方”，也就是 **超级大**，根本不可接受。

#### 代码（Python）

```python
from itertools import product
from typing import List, Tuple

def brute_force(buckets: int, minutesToDie: int, minutesToTest: int) -> int:
    # 每只猪最多能进行几轮测试
    rounds = minutesToTest // minutesToDie
    # 只要找到一种能区分所有桶的喂食方案，就返回当前的猪数
    for pigs in range(1, buckets + 1):          # 最坏情况每个桶用一只猪
        # 每只猪在每轮可以选择喂哪个桶（0 表示本轮不喂）
        choices = range(buckets + 1)           # 0~buckets
        # 生成所有猪的喂食方案：[(pig1_round1, pig1_round2, ...), (pig2_round1, ...), ...]
        # 为了演示，这里仅枚举每只猪“整个实验期间喂的桶序列”，实际枚举空间极大
        for scheme in product(choices, repeat=pigs * rounds):
            # 把平铺的 tuple 重新切分成每只猪的每轮喂食列表
            pig_plans = [
                scheme[i * rounds:(i + 1) * rounds] for i in range(pigs)
            ]
            # 用一个集合记录不同的死亡结果向量
            outcomes = set()
            for poisonous in range(1, buckets + 1):
                # 模拟每只猪的死亡时间（0 表示活到最后）
                death_times = []
                for plan in pig_plans:
                    # 找到第一次喂到有毒桶的轮次
                    time = 0
                    for r, bucket in enumerate(plan, start=1):
                        if bucket == poisonous:
                            time = r          # 第 r 轮死去
                            break
                    death_times.append(time)   # 0 表示整场实验都没死
                outcomes.add(tuple(death_times))
            # 如果所有有毒桶的结果向量都不同，说明该方案可行
            if len(outcomes) == buckets:
                return pigs
    return buckets    # 最坏情况每个桶一只猪
```

> **注释**  
> - `product(choices, repeat=pigs * rounds)` 用笛卡尔积生成所有可能的喂食组合。  
> - `death_times` 记录每只猪在第几轮死亡，`0` 表示全程存活。  
> - `outcomes` 用 `set` 去重，若集合大小等于 `buckets`，说明每个桶对应唯一的死亡向量。

#### 复杂度

- **时间复杂度**：`O((buckets)^{rounds·pigs})`（指数级），因为要遍历所有可能的喂食方案。  
- **空间复杂度**：`O(pigs·rounds)`，只需要保存每只猪每轮的喂食信息和死亡时间。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **枚举所有喂食方案**，导致指数级的搜索。  
观察实验过程可以发现：

1. 每只猪在 `rounds = minutesToTest // minutesToDie` 轮测试后，有 **`rounds + 1` 种可能的状态**  
   - 第 1 轮死、 第 2 轮死、 …、 第 `rounds` 轮死、 或者一直活着。  
   - 把这 `rounds + 1` 种状态记成 **“符号”**，类似于 **进制位**。  
2. 多只猪的状态可以组合在一起，形成一个 **`(rounds+1)` 进制的数**。  
   - 例如，2 只猪、3 轮测试 → 每只猪有 4 种状态 → 两只猪一共能表示 `4 × 4 = 16` 种不同的结果。  
3. 只要 **`(rounds+1)^pigs >= buckets`**，我们就可以把每个桶映射到一种唯一的状态组合，从而在规定时间内找出毒桶。  

> **类比**：把每只猪想象成一位“数字键盘”，每轮测试结束后，它要么 **敲下 0**（活着），要么 **敲下 1~rounds**（第几轮死）。多只猪一起敲键，就形成了一个多位数，这个数的基数是 `rounds+1`。只要这个基数进制能表示的不同数目不少于桶的数量，就能“一键定位”。

**核心算法**：  
- 计算 `rounds = minutesToTest // minutesToDie`。  
- 从 `pigs = 0` 开始递增，检查 `(rounds + 1) ** pigs` 是否已经不小于 `buckets`。  
- 第一次满足条件的 `pigs` 即为答案。  

这一步只涉及 **对数** 或 **循环乘法**，时间复杂度是 **对数级**，几乎可以瞬间算出答案。

#### 代码（Python）

```python
import math
from typing import Tuple

def poor_pigs(buckets: int, minutesToDie: int, minutesToTest: int) -> int:
    """
    返回在 minutesToTest 分钟内，最少需要多少只猪可以找出有毒桶。
    """
    # 能进行的完整测试轮数（每轮结束后猪要么死要么活）
    rounds = minutesToTest // minutesToDie

    # 如果只需要一次测试（rounds == 0），只能一次性把每只猪对应一个桶
    # 这时每只猪只能有 “活着” 或 “死了” 两种状态，即 2 进制
    # 公式仍然适用，只是 (0+1)=1 时需要特殊处理
    if rounds == 0:
        # 只能一次喂完，必须每只猪对应唯一的桶 → 需要 buckets-1 只猪（最后一桶不喂）
        return buckets - 1

    # 逐渐增加猪的数量，找到最小的 p 使 (rounds+1)^p >= buckets
    pigs = 0
    capacity = 1               # (rounds+1)^pigs
    while capacity < buckets:
        pigs += 1
        capacity *= (rounds + 1)   # 直接乘法避免浮点误差
    return pigs
```

> **关键行注释**  
> - `rounds = minutesToTest // minutesToDie`：计算完整的测试轮数。  
> - `capacity *= (rounds + 1)`：每加一只猪，状态组合数乘以 `rounds+1`。  
> - 循环结束时，`capacity` 已经不小于 `buckets`，对应的 `pigs` 就是最小满足条件的猪数。

#### 复杂度

- **时间复杂度**：`O(log_{rounds+1}(buckets))`，因为每次循环把可能的状态数乘以 `rounds+1`，相当于对数增长。对 1000 桶的极限数据，这个循环最多几次（一般 < 10），几乎可以视作 **常数时间**。  
- **空间复杂度**：`O(1)`，只用了若干整数变量。

## 心得

- **核心技巧**：把每只猪在每轮测试后的“死或活”视为一种 **进制位**，利用 **组合计数** `(rounds+1)^pigs` 来衡量信息容量。  
- **适用的题型**  
  1. **“有时间限制的检测”** 类题，例如 *"1000瓶酒，10分钟喝完，需要最少多少只老鼠"*.  
  2. **“信息论/状态编码”** 题，如 *"用最少的灯泡状态表示多个开关的组合"*.  
  3. **“多次实验的最优分配”**，比如 *"在限定次数的投掷中，找出最重的硬币"*.  
- **一句话总结**：**把每只猪的死亡时间当作进制位，用信息容量覆盖所有桶**。

## 反思

- **第一反应**：立刻想到“每只猪一次喂一桶”，于是把问题变成“需要多少只猪 = 桶数”。这显然没有利用 **多轮测试** 的机会。  
- **最容易踩的坑**  
  - 忽略 `minutesToTest` 与 `minutesToDie` 的比例，导致把 `rounds` 当成 `1`（只算一次测试）。  
  - 当 `minutesToTest` 正好是 `minutesToDie` 的整数倍时，**多轮测试** 的数量应为 `minutesToTest // minutesToDie`，而不是 `minutesToTest / minutesToDie`（浮点除法）。  
  - 边界情况：`rounds = 0`（测试时间不足以让猪死亡）时，需要特殊处理返回 `buckets-1`。  
- **下次遇到同类题的第一步**：**先算出可以进行多少次完整的实验**（即 `rounds`），再思考每只实验对象能产生多少种状态，最后用 “状态数的幂 ≥ 目标数量” 来求最小实验对象数。
