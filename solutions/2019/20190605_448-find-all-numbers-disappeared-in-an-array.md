# #448. 找出数组中所有消失的数字 / Find All Numbers Disappeared in an Array

> 难度：简单 · 标签：Array、Hash Table · [LeetCode 链接](https://leetcode.com/problems/find-all-numbers-disappeared-in-an-array/)

---

## 题目（英文原版）

**Description**

Given an array nums of n integers where nums[i] is in the range [1, n], return an array of all the integers in the range [1, n] that do not appear in nums.
Follow up: Could you do it without extra space and in O(n) runtime? You may assume the returned list does not count as extra space.

**Examples**

**Example 1:**

```
Input: nums = [4,3,2,7,8,2,3,1]
Output: [5,6]
```

**Example 2:**

```
Input: nums = [1,1]
Output: [2]
```

**Constraints**

- n == nums.length
- 1 <= n <= 105
- 1 <= nums[i] <= n

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：把 **1~n** 这 n 个数字全部列出来，然后一个一个检查它们是否出现在数组 `nums` 中。  

- **用到的数据结构**：  
  - **哈希表（字典）**：可以把数组里的每个元素当作键（key），对应的值随意（比如 `True`），这样我们就可以像查字典一样，用 O(1) 的时间判断一个数是否出现过。把哈希表想象成一本“词典”，单词是数组里的数字，查词典就像在字典里找单词是否存在。  

- **为什么正确**：  
  - 题目保证所有数字都在 `[1, n]` 范围内。只要我们把出现过的数字全部记下来，再把 `[1, n]` 中没有记过的数字挑出来，就是答案。  

- **复杂度分析**（大白话版）：  
  - **时间**：我们要遍历两遍数组。第一次遍历把所有数字放进哈希表，第二次遍历 `1~n` 检查哈希表里有没有。遍历一次是“走一次路”，长度是 `n`，所以两遍就是 `2n` 步，量级记作 `O(n)`（常数 2 在大 O 记号里不算）。  
  - **空间**：哈希表里要存最多 `n` 个键值对，相当于再开辟一个和原数组等大的“仓库”。所以空间是 `O(n)`。  

#### 代码（Python）

```python
def findDisappearedNumbers(nums):
    n = len(nums)                       # 数组长度，就是 1~n 的上界
    seen = {}                            # 用字典当哈希表，记录出现过的数字

    # 第一次遍历：把所有出现的数字加入哈希表
    for x in nums:
        seen[x] = True                  # 相当于在字典里写下 “x 出现过”

    missing = []                         # 用来存放答案
    # 第二次遍历：检查 1~n 哪些数字没有出现在哈希表里
    for num in range(1, n + 1):
        if num not in seen:             # “字典里没有这个键”，说明它没出现过
            missing.append(num)

    return missing
```

#### 复杂度

- **时间复杂度**：`O(n)` — 只需要两次线性遍历，跟数组大小成正比，遍历 1000 个元素大概需要 2000 步，和常数 2 没关系。  
- **空间复杂度**：`O(n)` — 额外用了一个大小和原数组相同的哈希表，最坏情况需要存 `n` 个键。

### 2. 最优解

#### 思路  

从暴力解出发，**瓶颈在于额外的哈希表**。题目要求 **O(1) 额外空间**（不算返回的答案），所以我们必须把“出现过的标记”放回原数组本身。  

关键观察：

1. **数值范围**：数组长度是 `n`，而每个元素的取值也恰好在 `[1, n]`。这意味着每个数字都可以对应到数组的一个下标（`value-1`）。  
2. **可以改写原数组**：我们可以把对应下标位置的元素“做记号”。常见的技巧是把该位置的数变成负数，负号就像“打了个勾”。  
3. **多遍扫描**：第一次遍历把所有出现的数字对应的下标位置标记为负数；第二次遍历检查哪些位置仍是正数——正数所在的下标 `i`（+1）就是缺失的数字。

具体步骤：

- **第一遍**（标记出现的数字）  
  - 对每个 `num = nums[i]`（取绝对值，因为之前可能已经被改成负数），计算对应下标 `idx = abs(num) - 1`。  
  - 把 `nums[idx]` 变成负数（如果它本来已经是负数，就保持不变）。这一步相当于在 “字典” 里把 `num` 对应的键标记为已出现。  

- **第二遍**（收集缺失的数字）  
  - 再遍历一次数组，所有 **仍为正数** 的位置 `i`，说明下标 `i+1` 对应的数字 **没有出现**，把 `i+1` 加入答案。  

这样我们只用了原数组本身，没有额外的哈希表，时间仍然是线性 `O(n)`。

> **类比**：想象一排编号 1~n 的信箱，每收到一封信，就在对应的信箱里贴一个“已收”标签。最后检查哪些信箱没有标签，那些编号就是失踪的信件。

#### 代码（Python）

```python
def findDisappearedNumbers(nums):
    """
    原地标记法（不使用额外空间）
    1. 把出现过的数字对应的下标位置设为负数
    2. 再遍历，正数所在的下标+1 即为缺失的数字
    """
    n = len(nums)

    # 第一次遍历：标记出现的数字
    for i in range(n):
        val = abs(nums[i])          # 取绝对值，防止之前已经被改成负数
        idx = val - 1               # 对应的下标（0 基）
        # 将对应下标位置的数设为负数，表示 “val 出现过”
        if nums[idx] > 0:           # 只在正数时取负，防止重复取负导致错误
            nums[idx] = -nums[idx]

    missing = []                    # 收集答案
    # 第二次遍历：找出仍为正数的下标
    for i in range(n):
        if nums[i] > 0:            # 正数说明下标 i+1 没出现过
            missing.append(i + 1)

    return missing
```

#### 复杂度

- **时间复杂度**：`O(n)` — 只遍历了两遍数组，每一步都是常数时间操作。相当于“走两趟路”，和数组大小成正比。  
- **空间复杂度**：`O(1)` — 只用了常数个额外变量 (`n, i, val, idx, missing`)；返回的列表不算在额外空间里。相当于“只搬了一个小盒子”，不随输入规模增长。

## 心得

- **核心技巧**：利用题目给出的数值范围，让每个数字映射到数组下标上，进而在原数组中做标记（负号/加 n）实现 “原地哈希”。  
- **适用的题型**：  
  1. “寻找所有出现一次的数字”（LeetCode 448）  
  2. “找出数组中重复的数字”（LeetCode 442）  
  3. “把所有 0 移到数组末尾” 类似的原地重排题  
- **一句话总结**：**把“出现过”用负号记在原数组对应位置，正数位置即是缺失的数字**。

## 反思

- **第一反应**：直接想用集合或哈希表统计出现的数字，然后遍历 `[1, n]` 找缺失。  
- **最容易踩的坑**：  
  - **负号冲突**：在标记时要先取绝对值，否则已经被负号标记的元素再取负会导致错误的下标。  
  - **重复数字**：同一个数字可能出现多次，标记时必须检查是否已经是负数，避免把已经负数的再取负（会变成正数，破坏标记）。  
  - **返回值不计入空间**：题目允许返回的列表不算额外空间，记得不要在标记阶段额外创建大数组。  
- **下次类似题的第一步**：检查**数值范围是否和数组长度有关**，如果是，就考虑**把数值映射到下标做原地标记**，这通常是 O(1) 空间的突破口。
