# #275. H-Index II / H-Index II

## 题目（英文原版）

**Description**

Given an array of integers citations where citations[i] is the number of citations a researcher received for their ith paper and citations is sorted in non-descending order, return the researcher's h-index.
According to the definition of h-index on Wikipedia: The h-index is defined as the maximum value of h such that the given researcher has published at least h papers that have each been cited at least h times.
You must write an algorithm that runs in logarithmic time.

**Examples**

**Example 1:**

```
Input: citations = [0,1,3,5,6]
Output: 3
Explanation: [0,1,3,5,6] means the researcher has 5 papers in total and each of them had received 0, 1, 3, 5, 6 citations respectively.
Since the researcher has 3 papers with at least 3 citations each and the remaining two with no more than 3 citations each, their h-index is 3.
```

**Example 2:**

```
Input: citations = [1,2,100]
Output: 2
```

**Constraints**

- n == citations.length
- 1 <= n <= 105
- 0 <= citations[i] <= 1000
- citations is sorted in ascending order.

## 题目（中文翻译）

给定一个整数数组 `citations`，其中 `citations[i]` 表示研究者第 `i` 篇论文被引用的次数，且该数组已按非递减（ascending）顺序排序，返回该研究者的 **h‑指数**（h-index）。

根据 Wikipedia 上对 h‑指数的定义：h‑指数是最大的整数 `h`，满足该研究者至少发表了 `h` 篇论文，并且每篇论文的引用次数至少为 `h`。

请设计一个 **对数时间**（logarithmic time）复杂度的算法来求解。

## 示例

### 示例 1  
**输入**: `citations = [0,1,3,5,6]`  
**输出**: `3`  
**解释**: `[0,1,3,5,6]` 表示研究者总共有 5 篇论文，分别被引用了 0、1、3、5、6 次。由于研究者有 3 篇论文的引用次数至少为 3，而其余两篇的引用次数不超过 3，所以他的 h‑指数为 3。

### 示例 2  
**输入**: `citations = [1,2,100]`  
**输出**: `2`

## 约束条件
- `n == citations.length`
- `1 <= n <= 10^5`
- `0 <= citations[i] <= 1000`
- `citations` 已按升序（ascending）排序。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**遍历每一篇论文**，把它当作“候选的 h”。  
对于第 `i` 篇（下标从 0 开始），它左边（包括自己）有 `n‑i` 篇论文，右边的引用数都是 **不大于** `citations[i]`（因为数组是升序的）。  
如果 `citations[i] >= n‑i`，说明这 `n‑i` 篇论文的引用次数都不少于 `n‑i`，于是 `h = n‑i` 是合法的。  
我们把所有合法的 `h` 记录下来，取最大的那个，就是答案。

- **用到的数据结构**：只需要一个普通的 Python 列表 `citations`。  
  类比：把数组想成排好队的书，每本书的左边都是更早出版的，右边是后出版的。我们从左往右检查“这本书往后还有多少本”，看它的引用次数能不能覆盖这些本数。

- **为什么正确**：  
  h‑index 的定义要求 **至少** `h` 篇论文的引用次数 **不少于** `h`。遍历每个位置时，`n‑i` 正好是当前位置及其右侧的论文数量。如果此时的引用次数 `citations[i]` 已经不小于 `n‑i`，说明这 `n‑i` 篇都满足 “引用≥`n‑i`”。因此 `n‑i` 是一个合法的 h；取最大值自然满足定义的“最大 h”。

#### 代码（Python）

```python
def hIndex_brute_force(citations):
    n = len(citations)                     # 论文总数
    max_h = 0                               # 记录最大的合法 h
    for i in range(n):
        papers = n - i                       # 以 i 为起点，右侧（含 i）共有多少篇论文
        if citations[i] >= papers:          # 引用次数够大，满足 h-index 条件
            max_h = max(max_h, papers)      # 更新答案
    return max_h
```

#### 复杂度

- **时间复杂度**：`O(n)`  
  需要遍历一次数组，`n` 是论文数量。  
  大白话：如果你有 10 万篇论文，就要检查 10 万次，跟论文数量成正比。

- **空间复杂度**：`O(1)`  
  只用了几个额外的整数变量，和输入规模无关。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **线性遍历**，当 `n` 达到 10⁵ 时仍然可以接受，但题目要求 **对数时间** `O(log n)`，这提示我们可以利用数组已经 **排好序** 的特性，用 **二分查找**（binary search）快速定位答案。

**二分的核心观察**：

- 对于任意下标 `mid`，左边的论文数是 `mid`，右边（含 `mid`）的论文数是 `n‑mid`。  
- 如果 `citations[mid] >= n‑mid`，说明从 `mid` 开始到数组末尾的所有论文都满足 “引用≥`n‑mid`”。此时 `h` 至少可以是 `n‑mid`，我们希望 **更左**（更小的 `mid`），因为左移会让 `n‑mid` 变大，可能得到更大的 h。于是把搜索区间收缩到左半边：`right = mid - 1`。  
- 否则 `citations[mid] < n‑mid`，说明 `mid` 位置的论文引用不足以支撑 `n‑mid` 这么大的 h，需要 **右移**（增大 `mid`），让右侧的论文数变少：`left = mid + 1`。

二分结束后，`left` 指向的下标是**第一个**满足 `citations[left] >= n‑left` 的位置（如果存在）。此时答案就是 `n‑left`；若所有位置都不满足，则答案为 `0`（即 `left == n`）。

**为什么二分能工作**：

- 条件 `citations[mid] >= n‑mid` 对下标 **单调递增**：  
  当下标从左向右移动时，左边的论文数 `mid` 增大，右侧的论文数 `n‑mid` 减小，而 `citations[mid]` **不减小**（数组升序）。  
  因此，一旦某个 `mid` 满足条件，所有更右侧的下标必然也满足（因为右侧的 `n‑mid` 更小，`citations` 更大或相等）。这正好是二分查找的前提——**满足区间是连续的**。

#### 代码（Python）

```python
def hIndex(citations):
    n = len(citations)
    left, right = 0, n - 1          # 二分的搜索区间 [left, right]
    while left <= right:
        mid = (left + right) // 2   # 取中间位置
        papers = n - mid            # 右侧（含 mid）共有多少篇论文

        if citations[mid] >= papers:   # 条件成立，尝试更左边
            right = mid - 1
        else:                           # 条件不成立，必须右移
            left = mid + 1

    # 循环结束时，left 是第一个满足条件的位置（可能等于 n）
    return n - left if left < n else 0
```

#### 复杂度

- **时间复杂度**：`O(log n)`  
  每次循环把搜索区间长度减半，最多进行 `log₂ n` 次比较。  
  大白话：如果有 1 000 000 篇论文，只需要大约 20 次检查就能得到答案。

- **空间复杂度**：`O(1)`  
  只使用了常数个变量，不随输入规模增长。

## 心得

- **核心技巧**：利用 **单调性 + 二分查找** 把线性搜索压缩到对数时间。  
- **适用的题型**：  
  1. 在已排序数组中寻找满足某种“≥”或“≤”条件的最左/最右位置（如 “寻找最小的正数”）。  
  2. “山峰数组”或 “单调函数的根” 类问题（如寻找最小的可行解）。  
- **一句话总结**：  
  “先把问题抽象成‘左侧不满足、右侧满足’的单调区间，再用二分快速定位交界点。”

## 反思

- **第一反应**：直接遍历统计，看每个位置能否满足 h‑index 条件。  
- **最容易踩的坑**：  
  - 忘记数组是 **升序**（非降序）而写成了相反的二分方向。  
  - 处理边界时忘记 `left == n` 的情况，会导致返回负数。  
  - 把 “论文数量” 与 “下标” 搞混，导致 `papers = n - mid` 写成 `mid + 1`（这其实是左侧论文数）。  
- **下次第一步**：  
  “检查输入是否单调（升序/降序），如果是，思考能否把问题转化为‘左不满足、右满足’的形式，再直接套用二分模板”。
