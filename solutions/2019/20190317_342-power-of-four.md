# #342. 四的幂 / Power of Four

> 难度：简单 · 标签：Math、Bit Manipulation、Recursion · [LeetCode 链接](https://leetcode.com/problems/power-of-four/)

---

## 题目（英文原版）

**Description**

Given an integer n, return true if it is a power of four. Otherwise, return false.
An integer n is a power of four, if there exists an integer x such that n == 4x.

**Examples**

**Example 1:**

```
Input: n = 16
Output: true
```

**Example 2:**

```
Input: n = 5
Output: false
```

**Example 3:**

```
Input: n = 1
Output: true
```

**Constraints**

- -231 <= n <= 231 - 1

---

## 题目（中文翻译）

给定一个整数（integer）`n`，如果它是四的幂（power of four），返回 `true`；否则返回 `false`。  
整数 `n` 是四的幂（power of four），当且仅当存在整数（integer）`x` 使得 `n == 4^x`。

**示例 1**  
输入: `n = 16`  
输出: `true`

**示例 2**  
输入: `n = 5`  
输出: `false`

**示例 3**  
输入: `n = 1`  
输出: `true`

**约束条件**  
- `-2^31 <= n <= 2^31 - 1`

---

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  
最直接的想法是：从 1 开始不断乘以 4，看看能否恰好得到 `n`。  
- **使用的数据结构**：这里其实只需要一个普通的整数变量 `cur` 来保存当前的乘积，类似我们在生活中把“1 元”不断翻倍，看能否恰好凑到目标金额。  
- **为什么正确**：如果 `n` 真的是 4 的幂，那么必定存在某个非负整数 `x` 使得 `4^x = n`。从 `4^0 = 1` 开始逐次乘以 4，必定会在第 `x` 次时恰好得到 `n`。如果在某一步乘积已经超过 `n`，说明 `n` 不是 4 的幂。  
- **复杂度大白话**：每次乘以 4，指数会增长 1，直到超过 `n` 为止。乘的次数大约是 `log₄(n)`（对数的意思是：把 `n` 按 4 进制拆分，需要多少位才能表示它）。对人来说，这相当于“把一个大数字不断除以 4，看看还能除几次”。  

#### 代码（Python）  
```python
def isPowerOfFour_brute(n: int) -> bool:
    # 负数、0 都不可能是 4 的幂
    if n <= 0:
        return False

    cur = 1                     # 从 4⁰ 开始
    while cur < n:              # 只要还没到 n，就继续乘以 4
        cur *= 4                # 相当于把「1」翻了 4 倍
    return cur == n             # 恰好等于 n 就说明是 4 的幂
```

#### 复杂度  
- **时间复杂度**：`O(log₄ n)`  
  - 大白话：如果 `n` 是 16（`4²`），循环只会跑两次；如果 `n` 是 1 048 576（`4⁵`），循环跑五次。循环次数随 `n` 的大小呈对数增长。  
- **空间复杂度**：`O(1)`  
  - 只用了常数个变量 (`cur`、`n`)，不随输入规模增长。

### 2. 最优解  

#### 思路  
从暴力解可以看到，真正的“慢点”在于我们每次都要做乘法循环。其实判断一个数是否是 4 的幂，只要检查下面两件事就可以一次完成：  

1. **只能有唯一的 1 位**  
   - 一个数如果是 2 的幂（`2^k`），二进制表示里只能有一个 `1`，其余全是 `0`。比如 `4 = 100₂`、`16 = 1 0000₂`。  
   - 检查方式是 `n & (n - 1) == 0`。把 `n` 减 1 后，最低的那位 `1` 会变成 `0`，后面的 `0` 全变成 `1`，于是原来的唯一 `1` 与 `n-1` 按位与得到 `0`。  

2. **这唯一的 1 必须出现在偶数位**（从 0 开始计数）  
   - 4 的幂的二进制都是 `1` 后面跟偶数个 `0`，例如 `4 = 100₂`（第 2 位），`16 = 1 0000₂`（第 4 位）。  
   - 我们可以预先准备一个“掩码”，只在偶数位上是 `1`，奇数位上是 `0`：  
     ```
     0x55555555 = 0101 0101 0101 0101 0101 0101 0101 0101₂
     ```  
   - 用 `n & 0x55555555` 把奇数位的 `1` 都过滤掉，如果结果仍然是 `n`，说明唯一的 `1` 落在了偶数位。  

把两条判断合在一起，再加上 `n > 0`（负数和 0 肯定不是），整个检查只用常数次的位运算，时间和空间都是 `O(1)`。  

**类比**：把掩码想象成一本字典，只列出“偶数页”。我们先确认这本字典里只有一本书（唯一的 `1`），再检查这本书是否真的在偶数页上。  

#### 代码（Python）  
```python
def isPowerOfFour_optimal(n: int) -> bool:
    # 1) 必须是正数
    if n <= 0:
        return False

    # 2) 只能有唯一的 1 位（判断是否是 2 的幂）
    if n & (n - 1):
        return False        # 若不等于 0，说明有不止一位是 1

    # 3) 这唯一的 1 必须在偶数位
    # 0x55555555 = binary 0101...0101，偶数位为 1，奇数位为 0
    return (n & 0x55555555) != 0
```

#### 复杂度  
- **时间复杂度**：`O(1)`  
  - 只做了几次位运算（`&`、`-`），不随 `n` 大小变化。相比暴力的 `log n` 次循环，瞬间完成。  
- **空间复杂度**：`O(1)`  
  - 只用了几个整数变量，常数级空间。

## 心得  

- **核心技巧**：利用二进制位运算判断“唯一的 1 位在偶数位置”。  
- **适用的题型**：  
  1. 判断是否是 2 的幂（只检查唯一 1 位）。  
  2. 判断是否是 8 的幂（唯一 1 位在 3 的倍数位，可用掩码 `0x...`）。  
  3. 判断是否是某个特定形状的数（如“只在奇数位出现 1”）时，用掩码过滤。  
- **一句话总结解题钥匙**：**“先把问题抽象成‘唯一的 1 位’+‘位置约束’，再用位运算一次性验证”。**  

## 反思  

- **第一反应**：直接循环除以 4（或乘以 4）直到不能再除/超过，写出代码。  
- **最容易踩的坑**：  
  - 忽略 `n <= 0` 的情况（负数和 0 必须直接返回 `False`）。  
  - 位运算时忘记掩码的十六进制写法，导致掩码位数不足（要覆盖 32 位整数）。  
- **下次思路**：遇到 “判断是否是某个整数的幂” 这类题，第一步先想 “唯一的 1 位” 的特性，然后判断它出现的**位置**是否满足题目要求，决定是用循环还是位运算。
