## 题目（英文原版）

**Description**

Given an integer n, return the count of all numbers with unique digits, x, where 0 <= x < 10n.

**Examples**

**Example 1:**

```
Input: n = 2
Output: 91
Explanation: The answer should be the total numbers in the range of 0 ≤ x < 100, excluding 11,22,33,44,55,66,77,88,99
```

**Example 2:**

```
Input: n = 0
Output: 1
```

**Constraints**

- 0 <= n <= 8

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把区间 `[0, 10ⁿ)` 的每一个整数都枚举一遍，然后检查它的每一位数字是否出现重复。  
- **遍历**：用 `for x in range(10**n)` 依次取出所有可能的数字。  
- **检查唯一性**：把数字的每一位放进一个集合（**集合**就像“查字典”，看某个词（这里是数字）是否已经出现过），如果在加入的过程中发现已经在集合里了，就说明出现了重复，直接丢弃。  
- **计数**：所有检查通过的数字全部加一，就是答案。

这种方法之所以 **正确**，是因为我们没有漏掉任何一个合法的数，也没有把不合法的数计入答案。

> **时间/空间复杂度**  
> - 时间复杂度：我们要检查 `10ⁿ` 个数，每检查一个数最多要遍历它的 `n` 位数字（因为 `10ⁿ` 最多有 `n` 位），所以总共是 `O(n·10ⁿ)`。  
>   - 这里的 `O` 符号可以想象成“随着 `n` 增大，工作量会以 **10 的 n 次方** 这么快增长”。  
> - 空间复杂度：只用了一个集合来存放最多 `n` 个数字，空间是 `O(n)`，可以忽略不计。

#### 代码（Python）

```python
def countNumbersWithUniqueDigits_bruteforce(n: int) -> int:
    """
    暴力枚举 0 ~ 10^n - 1，逐个判断是否所有数字都不相同
    """
    limit = 10 ** n                     # 10 的 n 次方，决定循环上界
    ans = 0

    for x in range(limit):              # 逐个取数
        seen = set()                     # 用集合记录已经出现的数字
        y = x
        unique = True                    # 假设当前数字合法

        # 检查每一位是否出现重复
        while y > 0:                     # 当数字还有位数时
            digit = y % 10               # 取最右边一位
            if digit in seen:            # 已经出现过，说明不合法
                unique = False
                break
            seen.add(digit)              # 记录下来
            y //= 10                     # 去掉已经检查的最低位

        # 特殊处理 0 本身：while 循环不会执行，但 0 是合法的唯一数字
        if x == 0:
            unique = True

        if unique:
            ans += 1                     # 合法数字计数

    return ans
```

#### 复杂度

- **时间复杂度**：`O(n·10ⁿ)` — 随着 `n` 增大，需要检查的数字呈指数增长，实际运行在 `n=8` 时已经不可接受。  
- **空间复杂度**：`O(n)` — 只用了一个最多装 `n` 个元素的集合。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **逐个枚举**，而本题其实可以用 **组合数学** 直接算出答案，而不需要真的把每个数字列出来。  
下面一步步推导：

1. **把问题拆成“长度”**  
   设 `f(k)` 为「恰好有 `k` 位且各位数字互不相同」的正整数个数（`k ≥ 1`），再把 `0` 单独算作长度 `0` 的一种情况。答案就是  
   `ans = f(0) + f(1) + f(2) + … + f(n)`。

2. **先算 `f(k)`**  
   - 第 1 位（最高位）**不能是 0**（否则位数会变少），所以有 `9` 种选择（1~9）。  
   - 第 2 位可以是剩下的 `9` 个数字（0 现在可以用了，但已经用掉的最高位数字不能再用），所以有 `9` 种选择。  
   - 第 3 位只能在剩下的 `8` 个数字中挑，依此类推。  
   因此  
   `f(k) = 9 × 9 × 8 × 7 × … × (11 - k)`，共 `k` 项。  
   当 `k = 1` 时，`f(1) = 9`（其实我们把 `0` 单独算作 `f(0)=1`，所以 `k=1` 的完整计数是 `9 + 1 = 10`，对应 0~9）。

3. **累加得到最终答案**  
   从 `k = 1` 开始逐步乘，边累加边更新答案。因为 `n ≤ 8`，最多只需要乘 8 次，时间几乎是常数。

4. **为什么不需要 DP 表**  
   这里的 “DP” 其实是 **递推**（把前一步的结果乘上新的可选数字），不需要额外的数组存储，只要几个变量即可。

> **类比**：想象有 10 张不同的卡片（0~9），要排出不重复的序列。最高位不能是 0，就像第一张卡片必须从 1~9 中挑。每挑走一张，剩下的可选卡片就少一张，后面的位数只能在剩下的卡片里挑。

#### 代码（Python）

```python
def countNumbersWithUniqueDigits(n: int) -> int:
    """
    组合计数法：直接算出 0~10^n-1 中所有无重复数字的个数
    """
    if n == 0:               # 只包含数字 0
        return 1

    ans = 1                  # f(0) = 1，计数 0 本身
    unique = 9               # 第 1 位有 9 种可能（1~9），用于后面乘积
    ans += unique            # 加上长度为 1 的情况（0~9 共 10 个）

    # 从长度 2 开始逐步计算，最多到 n 位
    for k in range(2, n + 1):
        unique *= (11 - k)   # 乘上当前位可选的数字个数
        ans += unique        # 累加该长度的计数

    return ans
```

> **代码说明**  
> - `unique` 用来保存 `f(k)` 的当前值。  
> - `11 - k` 正好对应 “剩余可选数字的个数”。例如 `k=2` 时，`11-2 = 9`（第二位可以选 0 再加上除最高位外的 8 个），`k=3` 时是 `8`，依此类推。  
> - 循环最多跑 `8` 次（因为 `n ≤ 8`），所以运行时间几乎是 **O(1)**。

#### 复杂度

- **时间复杂度**：`O(n)` → 实际上最多 `8` 次循环，可视作常数时间。比暴力的指数级快很多。  
- **空间复杂度**：`O(1)` → 只用了几条整数变量，几乎不占额外空间。

## 心得

- 本题核心是 **排列组合**（不重复选取），尤其是“首位不能为 0”这一限制。  
- 这类技巧常出现在下面几类题目：  
  1. **Count Numbers with Unique Digits**（本题）  
  2. **Permutation Sequence**（求第 k 大的排列）  
  3. **Numbers With Repeated Digits**（求区间内有重复数字的个数，往往用补集思路）  
- **一句话总结**：**“先把问题拆成‘长度’，用乘法原理算每种长度的排列数，再把它们加起来”。**

## 反思

- **第一反应**：直接枚举全部数字并检查唯一性，感觉最直接。  
- **最容易踩的坑**：  
  - 忘记 **0 也算作合法数字**，导致 `f(1)` 只算 `9` 而不是 `10`。  
  - 计算 `f(k)` 时把首位也当成可以选 `0`，会多算一些不符合位数的情况。  
  - `n` 超过 `10` 时会出现 “没有足够的不同数字”，需要提前返回 `10!`（本题限制 `n ≤ 8`，不必担心）。  
- **下次类似题目**的第一步：**先思考“有多少种排列方式”，把“位数”当作维度，用乘法原理或递推公式直接计数，而不是逐个枚举**。
