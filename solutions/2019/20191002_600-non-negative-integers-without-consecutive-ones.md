# #600. 不含连续 1 的非负整数 / Non-negative Integers without Consecutive Ones

> 难度：困难 · 标签：Dynamic Programming · [LeetCode 链接](https://leetcode.com/problems/non-negative-integers-without-consecutive-ones/)

---

## 题目（英文原版）

**Description**

Given a positive integer n, return the number of the integers in the range [0, n] whose binary representations do not contain consecutive ones.

**Examples**

**Example 1:**

```
Input: n = 5
Output: 5
Explanation:
Here are the non-negative integers <= 5 with their corresponding binary representations:
0 : 0
1 : 1
2 : 10
3 : 11
4 : 100
5 : 101
Among them, only integer 3 disobeys the rule (two consecutive ones) and the other 5 satisfy the rule.
```

**Example 2:**

```
Input: n = 1
Output: 2
```

**Example 3:**

```
Input: n = 2
Output: 3
```

**Constraints**

- 1 <= n <= 109

## 题目（中文翻译）

给定一个正整数 `n`，返回区间 `[0, n]` 中二进制表示（binary representation）不含连续的 `1` 的整数（integer）个数。

### 示例

#### 示例 1
**输入:** `n = 5`  
**输出:** `5`  
**解释:**  
这里列出所有 ≤ 5 的非负整数及其对应的二进制表示（binary representation）：

```
0 : 0
1 : 1
2 : 10
3 : 11
4 : 100
5 : 101
```

其中，整数 `3` 违反规则（出现两个连续的 `1`），其余 `5` 个整数均满足规则。

#### 示例 2
**输入:** `n = 1`  
**输出:** `2`

#### 示例 3
**输入:** `n = 2`  
**输出:** `3`

### 约束条件
- `1 <= n <= 10^9`

---

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是**枚举**所有 `0 … n` 的整数，逐个检查它们的二进制表示里是否出现了相邻的两个 `1`。  
- **枚举**：把每个整数想成一本书的页码，依次翻开查看。  
- **检查**：把整数的二进制看成一串字符（比如 `10101`），只要在这串字符里找到子串 `"11"`，说明出现了相邻的 `1`，这本书就“不合格”。  

为什么能得到正确答案？因为我们把 **所有** 可能的数都遍历了一遍，只要把不合格的剔除，剩下的就是答案。

#### 代码（Python）

```python
def find_integers_bruteforce(n: int) -> int:
    """
    暴力枚举 0~n，逐个判断二进制是否含有相邻的 1
    """
    def has_consecutive_ones(x: int) -> bool:
        # 把整数转换成二进制字符串，例如 5 -> '101'
        b = bin(x)[2:]               # 切掉开头的 '0b'
        # 检查是否出现子串 '11'
        return '11' in b

    count = 0
    for i in range(n + 1):          # 包含 n 本身
        if not has_consecutive_ones(i):
            count += 1
    return count
```

#### 复杂度  

- **时间复杂度**：`O(n · log n)`  
  - `n` 次循环是线性的；每次把 `i` 转成二进制需要 `log₂ i` 位（即 `log n`），所以总体是 `n × log n`。  
  - 用大白话说，如果 `n = 1 000 000`，我们大约要检查一百万次，每次检查大约 20 位，所以总工作量是“一百万乘二十”。  

- **空间复杂度**：`O(1)`（不计入输出的整数计数器）  
  - 只用了常数个变量，和 `n` 大小无关。

### 2. 最优解

#### 思路  

暴力解的瓶颈在 **枚举**：当 `n` 很大（题目上限 `10⁹`）时，逐个检查会超时。  
要想快一点，需要 **直接算出** 满足条件的数的个数，而不是一个一个数过去。

观察二进制不含相邻 `1` 的数，有以下规律（把它们按二进制长度分组）：

| 位数 (最高位不计 0) | 可能的合法数 | 计数 |
|-------------------|------------|------|
| 1 (0/1)           | 0, 1       | 2 = F₂ |
| 2 (10/01)         | 0, 1, 2    | 3 = F₃ |
| 3 (100/101/010)   | 0,1,2,4,5  | 5 = F₄ |
| …                 | …          | …   |

可以发现计数序列 **正好是斐波那契数列**（`F₁ = 1, F₂ = 2, F₃ = 3, F₄ = 5 …`），满足  
`F[i] = F[i‑1] + F[i‑2]`（因为最高位是 `0` 时，后面可以随意填 `i‑1` 位合法数；最高位是 `1` 时，次高位只能是 `0`，于是剩下 `i‑2` 位合法数）。

**步骤 1：预处理斜率表**  
- 计算 `F[0 … 31]`（因为 `n ≤ 10⁹ < 2³⁰`，最多 30 位），`F[i]` 表示长度为 `i`（不含前导零）的合法数个数。

**步骤 2：从最高位向低位遍历 n 的二进制**  
- 设 `ans = 0`，记录已经累计的合法数个数。  
- 从最高位（比如第 30 位）向下检查：
  1. 如果当前位是 `1`，说明我们可以把它当成 `0`，然后在低 `i` 位随意填合法数。此时可以直接把 `F[i]` 加到答案中（因为所有以 `0` 开头且长度为 `i` 的合法数都小于当前前缀）。
  2. 若相邻的两位都是 `1`，说明 `n` 本身以及所有以后出现 `1` 的前缀都不合法，直接返回 `ans`（因为再往后再加的数都会超过 `n`，且已经包含了所有合法数）。
- 循环结束后，还需要把 `n` 本身计入（如果遍历过程中没有出现相邻 `1`），于是返回 `ans + 1`。

这套思路只看二进制的 **位数**，时间只和 `log₂ n` 成正比，空间只需要保存斐波那契表。

#### 代码（Python）

```python
def find_integers(n: int) -> int:
    """
    动态规划 + 位运算：在 O(log n) 时间内统计 [0, n] 中不含相邻 1 的整数个数
    """
    # 1. 预计算斐波那契表，F[i] 表示长度为 i（不含前导零）的合法数个数
    #    注意：F[0] = 1（空串），F[1] = 2（0,1），后续满足 F[i] = F[i-1] + F[i-2]
    F = [0] * 32               # 2^31 > 10^9，够用了
    F[0], F[1] = 1, 2
    for i in range(2, 32):
        F[i] = F[i - 1] + F[i - 2]

    ans = 0                    # 已经累计的合法数
    prev_bit = 0               # 记录低一位是否是 1，用来检测相邻 1
    # 2. 从最高位向低位遍历 n 的二进制
    for k in range(30, -1, -1):    # 30 因为 2^30 > 10^9
        cur_bit = (n >> k) & 1    # 取第 k 位
        if cur_bit == 1:
            ans += F[k]            # 把当前位设为 0，低 k 位随意填合法数
            if prev_bit == 1:      # 出现相邻的两个 1，直接返回
                return ans
        prev_bit = cur_bit

    # 循环结束说明 n 本身也不含相邻的 1，需要再加上它自己
    return ans + 1
```

#### 复杂度  

- **时间复杂度**：`O(log n)`  
  - 只遍历了 `n` 的二进制位数，大约 30 次。用大白话说，就是“把一根 30 节的铁链检查一次”，几乎瞬间完成。  

- **空间复杂度**：`O(1)`（如果把斐波那契表看作常数大小）  
  - 只用了一个长度固定（32）的数组和几个变量，和 `n` 的大小没有关系。

## 心得

- **核心技巧**：**位 DP + 斐波那契计数**。把“不含相邻 1”这条约束转化为一种“每多一位就有两种选择”的递推关系，得到斐波那契数列。
- **适用场景**  
  1. “二进制不含相邻 1” 类似的问题（如 LeetCode 600 `Non‑negative Integers without Consecutive Ones`）。  
  2. “数字中不出现某种模式” 的计数（如不出现子串 `"00"`、不出现递增序列等）。  
  3. “在给定上界下，计数满足特定位约束的整数”——常见于数字 DP（Digit DP）题目。
- **一句话总结**：**把位约束转成递推式，用斐波那契快速计数**。

## 反思

- **第一反应**：直接写个循环遍历 `0…n`，检查二进制是否有 `"11"`。这在小范围下能跑通，但没想到 `n` 可能高达 `10⁹`。
- **最容易踩的坑**  
  1. **边界**：忘记把 `0` 计入答案，导致结果少 1。  
  2. **相邻 1 的提前终止**：在遍历二进制时，一旦出现连续的 `1`，必须立刻返回累计值，否则会把不合法的组合误加进来。  
  3. **斐波那契表的初始化**：`F[0]=1, F[1]=2` 很关键，容易写成 `F[1]=1` 导致整体计数错误。
- **下次遇到同类题**：第一步先 **抽象出“位数对应的合法组合数”**（往往是斐波那契或类似递推），再 **用最高位的贪心 + 前缀计数** 的方式遍历目标数的二进制。这样即可在对数时间内得到答案。
