# #456. 132 模式 / 132 Pattern

> 难度：中等 · 标签：Array、Binary Search、Stack、Monotonic Stack、Ordered Set · [LeetCode 链接](https://leetcode.com/problems/132-pattern/)

---

## 题目（英文原版）

**Description**

Given an array of n integers nums, a 132 pattern is a subsequence of three integers nums[i], nums[j] and nums[k] such that i < j < k and nums[i] < nums[k] < nums[j].
Return true if there is a 132 pattern in nums, otherwise, return false.

**Examples**

**Example 1:**

```
Input: nums = [1,2,3,4]
Output: false
Explanation: There is no 132 pattern in the sequence.
```

**Example 2:**

```
Input: nums = [3,1,4,2]
Output: true
Explanation: There is a 132 pattern in the sequence: [1, 4, 2].
```

**Example 3:**

```
Input: nums = [-1,3,2,0]
Output: true
Explanation: There are three 132 patterns in the sequence: [-1, 3, 2], [-1, 3, 0] and [-1, 2, 0].
```

**Constraints**

- n == nums.length
- 1 <= n <= 2 * 105
- -109 <= nums[i] <= 109

## 题目（中文翻译）

给定一个长度为 `n` 的整数数组 `nums`，若存在下标 `i < j < k`，使得 `nums[i] < nums[k] < nums[j]`，则这三个整数 `nums[i]、nums[j]、nums[k]` 构成一个 **132 模式**（132 pattern）。如果数组中存在 132 模式，返回 `true`；否则返回 `false`。

### 示例

**示例 1**  
**输入**: `nums = [1,2,3,4]`  
**输出**: `false`  
**解释**: 序列中不存在 132 模式。

**示例 2**  
**输入**: `nums = [3,1,4,2]`  
**输出**: `true`  
**解释**: 序列中存在 132 模式，例如 `[1, 4, 2]`。

**示例 3**  
**输入**: `nums = [-1,3,2,0]`  
**输出**: `true`  
**解释**: 序列中有三个 132 模式：`[-1, 3, 2]`、`[-1, 3, 0]` 和 `[-1, 2, 0]`。

### 约束条件

- `n == nums.length`
- `1 <= n <= 2 * 10^5`
- `-10^9 <= nums[i] <= 10^9`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把所有可能的三元组都枚举一遍，看看是否满足  

```
i < j < k 且 nums[i] < nums[k] < nums[j]
```

这就像在找三个人站成一排，让左边的最矮，中间的最高，右边的身高恰好在两者之间。  
实现上我们可以用三层循环：

1. 最外层 `i` 从左到右遍历，表示第一个数的位置。  
2. 中间层 `j` 在 `i` 右侧遍历，表示第二个数的位置。  
3. 最内层 `k` 在 `j` 右侧遍历，表示第三个数的位置。  

只要找到一组满足条件的 `(i, j, k)`，立刻返回 `True`；遍历完仍未找到则返回 `False`。

> **为什么正确**  
> 暴力遍历把所有合法的 `(i, j, k)` 都检查了一遍，只要答案是“存在”，必然会在某一次检查时被发现。

#### 代码（Python）

```python
def find132pattern_bruteforce(nums):
    n = len(nums)
    # 第 1 层：遍历 i
    for i in range(n):
        # 第 2 层：遍历 j，必须在 i 的右侧
        for j in range(i + 1, n):
            # 第 3 层：遍历 k，必须在 j 的右侧
            for k in range(j + 1, n):
                # 检查 132 条件
                if nums[i] < nums[k] < nums[j]:
                    return True      # 找到一个就可以直接返回
    return False                 # 全部遍历完都没有
```

#### 复杂度  

- **时间复杂度**：`O(n³)`  
  - 解释：三个嵌套循环，最坏情况下每个循环都要遍历 `n` 次，整体是 `n × n × n`，也就是 **n 的立方**。如果 `n = 1000`，运算次数大约是 `10⁹`，对电脑来说已经很慢了。  
- **空间复杂度**：`O(1)`  
  - 解释：只用了常数级别的额外变量（`i、j、k`），不随 `n` 增长。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **重复遍历**：  
- 对每个 `j`，我们都要去找左边比它小的 `i`，以及右边比它大的 `k`。  
- 实际上，只要我们提前知道每个位置左侧的最小值，就可以省掉最外层的循环；再利用单调栈快速找右侧的合适 `k`，就能把时间降到线性。

**核心思路**：  
1. **前缀最小**  
   - 对每个下标 `j`，记录 `j` 左边的最小元素 `min_left[j]`（相当于 “左边最矮的那个人”）。  
   - 这一步只需要一次遍历，用一个变量 `cur_min` 持续更新最小值。  

2. **从右往左维护单调递减栈**  
   - 栈里保存的是可能成为 `nums[k]`（即 “中间身高”）的候选值，栈顶始终是 **当前看到的最大的** `nums[k]`。  
   - 为什么要 **递减**？因为我们希望栈顶是 **最大的** `k`，这样更容易满足 `nums[i] < nums[k] < nums[j]`。  
   - 遍历顺序从右到左：  
     - 当前下标记作 `j`（即把它当作 “最高的那个人”），我们已经知道 `min_left[j]`（左侧最小）。  
     - 栈中只保留比 `nums[j]` 小的元素（因为 `nums[k]` 必须小于 `nums[j]`），把比 `nums[j]` 大或等于的全部弹出。  
     - 此时如果栈顶的元素大于 `min_left[j]`，说明找到了 `nums[i] < 栈顶 < nums[j]`，直接返回 `True`。  
     - 最后把当前的 `nums[j]` 压入栈中，供左侧的 `j` 使用。

> **类比**：想象我们站在数组的最右边往左看，每看到一个新的人（`nums[j]`），就把他加入“候选队列”。如果有人比他高，就把那个人踢出，因为他不可能再作为 “中间身高” 出现。这样维护的队列始终是 **从高到低** 排序的，查找是否存在合适的 “中间身高” 只需要看栈顶。

#### 代码（Python）

```python
def find132pattern(nums):
    n = len(nums)
    if n < 3:
        return False

    # 1. 计算每个位置左侧的最小值（前缀最小）
    min_left = [0] * n          # min_left[i] 表示 i 左边的最小值
    cur_min = nums[0]
    min_left[0] = cur_min
    for i in range(1, n):
        cur_min = min(cur_min, nums[i])
        min_left[i] = cur_min

    # 2. 单调递减栈（存放可能的 nums[k]），从右往左遍历
    stack = []                  # 栈顶是当前最大的候选值
    for j in range(n - 1, -1, -1):
        # 只在 j 不是最左边的情况下检查，因为左侧必须还有 i
        if nums[j] > min_left[j]:          # 必须满足 nums[i] < nums[j]
            # 弹出所有不可能成为 132 中间值的元素
            while stack and stack[-1] <= min_left[j]:
                stack.pop()                # 太小，连 nums[i] 都不大

            # 此时栈顶（如果存在）就是最大的 nums[k]，且 > min_left[j]
            if stack and stack[-1] < nums[j]:
                # 找到 nums[i] < 栈顶 < nums[j]
                return True

            # 把当前 nums[j] 加入栈，供左侧的 j 使用
            stack.append(nums[j])

    return False
```

#### 复杂度  

- **时间复杂度**：`O(n)`  
  - 解释：  
    - 前缀最小只遍历一次 `O(n)`。  
    - 主循环同样遍历一次，每个元素最多进栈一次、出栈一次，整体也是线性。  
    - 相比暴力的 `n³`，这里的 “n” 就像“一次遍历全程搞定”，即使 `n = 200,000` 也能在毫秒级完成。  

- **空间复杂度**：`O(n)`（最坏情况）  
  - 解释：`min_left` 数组需要 `n` 个额外空间；栈最多也会存 `n` 个元素（严格递减的情况）。  
  - 与暴力的 `O(1)` 相比，多用了线性空间，但换来了线性时间，是值得的权衡。

## 心得

- **核心技巧**：**单调栈 + 前缀最小**，把“左侧最小值”和“右侧可选最大值”提前准备好，避免重复枚举。  
- **适用的题型**：  
  1. **逆序对 / 最大矩形** 类似的“左小右大”问题（如 LeetCode 739 “每日温度”、225 “栈实现队列”）。  
  2. **子数组最大差值**（如 245 “最小栈” 变形），需要在一次遍历中同时维护左侧极值和右侧候选。  
  3. **单调栈求最近更大/更小元素**（如 496 “下一个更大元素 I”）。  

- **一句话总结解题钥匙**：  
  > “先把左边的最小值记下来，再用单调递减栈从右往左快速找到比左侧更大、比自己更小的中间值。”

## 反思

- **第一反应**：看到“三个数的相对大小”，本能想到“三层循环”，即暴力枚举。  
- **最容易踩的坑**：  
  1. **边界条件**：数组长度小于 3 时直接返回 `False`，否则会出现 `min_left[-1]` 越界。  
  2. **栈中元素的比较顺序**：一定要先弹出 **小于等于左侧最小值** 的元素，再判断栈顶是否小于 `nums[j]`。如果顺序写错，可能会误判。  
  3. **负数与极大值**：题目允许 `-10⁹` 到 `10⁹`，所以不能用 “-∞” 之类的特殊值做比较，直接使用实际的 `min` 更新即可。  

- **下次遇到同类题**，第一步应该想到：  
  1. **能否用前缀（左侧）或后缀（右侧）信息把一侧的遍历提前？**  
  2. **单调栈能否帮助快速定位满足“不大于 / 不小于” 条件的候选元素？**  

这样就能把暴力的 `O(n³)` 快速压缩到 `O(n)`，实现高效的算法。
