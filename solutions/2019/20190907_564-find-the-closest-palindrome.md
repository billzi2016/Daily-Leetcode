# #564. 最近的回文数 / Find the Closest Palindrome

> 难度：困难 · 标签：Math、String · [LeetCode 链接](https://leetcode.com/problems/find-the-closest-palindrome/)

---

## 题目（英文原版）

**Description**

Given a string n representing an integer, return the closest integer (not including itself), which is a palindrome. If there is a tie, return the smaller one.
The closest is defined as the absolute difference minimized between two integers.

**Examples**

**Example 1:**

```
Input: n = "123"
Output: "121"
```

**Example 2:**

```
Input: n = "1"
Output: "0"
Explanation: 0 and 2 are the closest palindromes but we return the smallest which is 0.
```

**Constraints**

- 1 <= n.length <= 18
- n consists of only digits.
- n does not have leading zeros.
- n is representing an integer in the range [1, 1018 - 1].

---

## 题目（中文翻译）

给定一个字符串 `n`，它表示一个整数，返回距离该整数最近的回文数（不包括它本身）。如果存在多个距离相同的回文数，返回较小的那个。  
最近的定义为两整数的绝对差最小。

**示例 1**  
```
Input: n = "123"
Output: "121"
```

**示例 2**  
```
Input: n = "1"
Output: "0"
```
**解释**：`0` 和 `2` 都是最近的回文数，但我们返回较小的 `0`。

**约束条件**  

- `1 <= n.length <= 18`
- `n` 仅由数字组成。
- `n` 不含前导零。
- `n` 表示的整数在区间 `[1, 10^18 - 1]` 内。

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**从给定数字的左、右两侧一步一步往外搜索**，直到碰到第一个回文数为止。  

- **从 n-1、n-2、…往下减**，每次把整数转成字符串，检查它是不是回文（即正读和反读相同）。  
- **如果往上找**，同理检查 n+1、n+2、…  

这就像在街上找“同名的店”。我们从目标地址往前、往后走，遇到第一家名字和目标相同的店（这里的“相同”指的是回文）就停下来。

> **为什么正确**  
> 回文数的定义很明确：读出来正着和反着一样。只要我们逐个枚举所有整数并检查，必然会在最近的回文数处停下来。  

> **时间/空间复杂度**  
> - 最坏情况下，需要遍历 **O(Δ)** 个整数，Δ 是最近回文数与 n 的距离。比如 n = 100000000000000001，最近的回文是 99999999999999999，距离约为 2。这里看起来很小，但如果 n = 10⁸+1，最近的回文可能是 10⁸-1，距离约为 2，同样很小。  
> - 但是在极端情况下（比如 n = 10⁹+1），我们可能要检查上千甚至上万次。**每次检查回文的成本是 O(L)**（L 为数字长度，最多 18），所以总时间是 **O(Δ·L)**。如果 Δ 接近 10⁹，时间会非常慢，几乎不可接受。  
> - 空间上只需要保存几个整数和字符串，**O(1)**。

> **大白话解释**  
> O(Δ·L) 就是“我们要走 Δ 步，每走一步都要花 L 的时间去看看这一步是不是我们要找的”。如果 Δ 很大，这条路就会很慢。

#### 代码（Python）

```python
def is_palindrome(s: str) -> bool:
    """判断字符串是否是回文（正读和反读相同）"""
    return s == s[::-1]

def nearest_palindrome_bruteforce(n: str) -> str:
    num = int(n)                     # 把字符串转成整数，方便加减
    # 向左找（比 num 小的回文）
    left = num - 1
    while left >= 0:
        if is_palindrome(str(left)):
            break
        left -= 1

    # 向右找（比 num 大的回文）
    right = num + 1
    while True:                      # 右侧没有上界，只要找到就停
        if is_palindrome(str(right)):
            break
        right += 1

    # 计算距离，取更近的；若相等则取较小的
    diff_left = num - left if left >= 0 else float('inf')
    diff_right = right - num
    if diff_left <= diff_right:
        return str(left)
    else:
        return str(right)
```

#### 复杂度  

- **时间复杂度**：`O(Δ·L)`，其中 Δ 是最近回文数与 n 的差距，L ≤ 18 是数字长度。  
  *含义*：如果最近的回文离得很远，这种办法会非常慢。  
- **空间复杂度**：`O(1)`，只用了常数级别的额外变量。

### 2. 最优解  

#### 思路  

暴力解慢的根本原因是**每次只前进一步**，而我们其实可以**直接“跳”到可能的回文候选**，只需要检查少数几种情况即可。

观察几个典型例子：

| n          | 最近的回文 | 规律 |
|------------|------------|------|
| 1234       | 1221       | 只需要把左半部分 **123** 镜像成 **1221**（左半“123”减 1 后再镜像） |
| 999        | 1001 (更远) →  999 本身是回文，排除后最近是 **  989** | 当全是 9 时，最接近的回文往往是 **10ⁿ+1** 或 **9…9**（位数减 1） |
| 1000       | 999        | 左半“10”减 1 变成 “9”，镜像后得到 “999”。|
| 1          | 0          | 特殊情况：最小的正整数的左侧只有 0。|

**关键观察**  
1. 一个回文数的左半（包括中间位）决定了整个数。我们只需要决定**前缀**（左半）是什么，然后把它“翻转”拼到右侧即可。  
2. 与 n 最接近的回文，一般只会出现在以下三种**前缀**的变化：
   - 前缀 **不变**（直接镜像），得到 `p1`。  
   - 前缀 **加 1**（进位），得到 `p2`。  
   - 前缀 **减 1**（借位），得到 `p3`。  
3. 还有两种极端情况：
   - 形如 `1000…000`，最近的回文是 `99…99`（位数减 1 的全 9）。  
   - 形如 `9…9`（全是 9），最近的回文是 `10…01`（位数加 1，首尾 1，中间全 0）。

因此，我们只需要**构造这几种候选回文**，然后挑选出距离最近且不等于原数的那个。

**步骤细化**  

1. **获取左半**  
   - 设 `len_n = len(n)`。  
   - `half_len = (len_n + 1) // 2`（向上取整），取前 `half_len` 位作为前缀 `prefix`。  

2. **生成三种镜像**  
   - `make_pal(prefix, odd)`：把 `prefix`（字符串）去掉中间位（如果是奇数长度）后反转，拼接到前缀后面，得到回文。  
   - `candidates = []`，先加入 `make_pal(prefix)`（不变）。  
   - 再分别对 `prefix` **加 1**、**减 1**（注意可能产生进位或借位），得到新的前缀字符串 `prefix+1`、`prefix-1`，再各自镜像，加入候选集合。  

3. **加入极端候选**  
   - `10^{len_n-1} - 1` → `"9"* (len_n-1)`（全 9，位数比 n 少 1）。  
   - `10^{len_n} + 1` → `"1" + "0"*(len_n-1) + "1"`（位数比 n 多 1）。  

4. **过滤掉原数本身**，遍历所有候选，计算绝对差 `abs(int(candidate) - int(n))`，挑选差值最小的；若出现相同差值，取数值更小的（因为字符串比较同样适用）。  

**为什么只要这几种**  
- 改变前缀的幅度大于 1（比如前缀 +2）会导致生成的回文离原数更远，因为镜像的右半几乎不变，只是整体整体向上/下跳了更多。  
- 极端情况是因为当所有左半位都是 9 时，加 1 会导致位数增长；当左半是 100…0 时，减 1 会导致位数缩减，产生全 9 的回文。  

**类比**  
把回文看作“对称的桥”。我们只需要决定桥的左半怎么建（前缀），右半会自动对称。最接近的桥，只会在左半略微向上/向下调一个台阶，或者在桥的长度本身改变（全 9 → 长度减 1，或 100…0 → 长度加 1）时出现。

#### 代码（Python）

```python
def nearest_palindrome(n: str) -> str:
    """返回距离 n 最近的回文（不包括 n 本身），若相同距离返回较小的"""
    length = len(n)
    if length == 1:                     # 单个数字的特殊处理
        return str(int(n) - 1)          # 0 是唯一比它小的回文

    # ---------- 1. 取左半前缀 ----------
    half_len = (length + 1) // 2        # 向上取整，例如 5 位 -> 3 位前缀
    prefix = n[:half_len]              # 前缀字符串

    # ---------- 2. 辅助函数：把前缀变成回文 ----------
    def make_pal(p: str) -> str:
        """给定前缀 p，返回对应的回文字符串（长度与原 n 相同）"""
        if length % 2 == 0:            # 偶数位：左半 + 右半（完整翻转）
            return p + p[::-1]
        else:                           # 奇数位：左半（含中位）+ 右半（去掉中位再翻转）
            return p + p[-2::-1]        # p[-2::-1] 代表倒序除去最后一个字符

    candidates = set()

    # ---------- 3. 不变、前缀+1、前缀-1 ----------
    candidates.add(make_pal(prefix))

    # 前缀转成整数进行加减，注意可能出现进位/借位
    prefix_int = int(prefix)

    for delta in (-1, 1):
        new_prefix = str(prefix_int + delta)
        # 可能出现长度变化，例如 99+1 -> 100，需要补齐位数
        if len(new_prefix) < half_len:          # 前缀减 1 导致位数减少（如 100 -> 99）
            new_prefix = '0' * (half_len - len(new_prefix)) + new_prefix
        candidates.add(make_pal(new_prefix))

    # ---------- 4. 极端情况 ----------
    # 1000...0 -> 999...9（位数-1 的全 9）
    candidates.add('9' * (length - 1))
    # 999...9 -> 100...001（位数+1 的 1...1）
    candidates.add('1' + '0' * (length - 1) + '1')

    # ---------- 5. 过滤自身 ----------
    candidates.discard(n)               # 去掉原数字本身

    # ---------- 6. 选出最近的 ----------
    original = int(n)
    best = None
    best_diff = None

    for cand in candidates:
        # 跳过可能出现的负数情况（如 prefix-1 产生前导 0）
        if cand.startswith('-'):
            continue
        cand_int = int(cand)
        diff = abs(cand_int - original)
        if (best is None) or (diff < best_diff) or (diff == best_diff and cand_int < int(best)):
            best = cand
            best_diff = diff

    return best
```

> **关键注释解释**  
> - `half_len = (length + 1) // 2`：向上取整，保证奇数长度时中间位算在左半。  
> - `p[-2::-1]`：从倒数第二个字符开始逆序，正好把左半（除中位）翻转到右边。  
> - `candidates.add('9' * (length - 1))` 与 `candidates.add('1' + '0' * (length - 1) + '1')` 处理“全 9” 与 “1000…0” 两类极端。  
> - `candidates.discard(n)`：把原数字剔除，防止返回自身。  

#### 复杂度  

- **时间复杂度**：`O(L)`，其中 `L = len(n) ≤ 18`。我们只做了常数次的字符串切割、拼接和整数转换，均为线性时间。  
  *含义*：不管 n 多大（最多 18 位），运行时间始终在几百次基本操作之内，几乎是瞬间完成。  
- **空间复杂度**：`O(L)`，主要是存放候选回文字符串的集合，最多几个长度为 L 的字符串。  

与暴力解相比，**时间从可能的 `Δ·L`（Δ 可能非常大）降到仅 `L`，实现了指数级的加速**。

## 心得  

- **核心技巧**：回文数由左半（含中位）唯一决定，构造候选时只需要调节左半前缀 ±1 并处理特殊的全 9 / 100…0 情形。  
- **适用题型**  
  1. “寻找最近的回文数”类（本题）。  
  2. “把数字变成回文”或“最小回文增量”类，如把一个数变为最近的回文只增不减。  
  3. “基于前缀/后缀的镜像”问题，如“把整数翻转后相加得到回文”。  
- **一句话总结**：**只要枚举左半前缀的三种可能（不变、+1、-1）再加上两种极端情况，就能得到最近的回文**。

## 反思  

- **第一反应**：直接从 n 往两边逐个检查，想到“暴力搜索”。这在概念上最直观，却忽视了回文的对称结构。  
- **最容易踩的坑**  
  - **长度变化**：如 `1000` → `999`，或 `999` → `1001`，必须单独考虑。  
  - **奇偶长度的区别**：奇数位时中间数字不需要重复镜像。  
  - **前缀加/减 1 产生的前导 0**：如 `100` 的前缀 `10` 减 1 变 `9`，需要在构造回文时补齐位数。  
  - **排除自身**：原数本身若是回文，答案不能是它自己。  
- **下次思路**：一看到“回文”关键词，就先把问题转化为“**只决定左半，右半自动对称**”。然后围绕左半的 **+1 / -1** 以及极端 “全 9 / 100…0” 两种特殊情况进行枚举，几乎可以直接写出最优解。
