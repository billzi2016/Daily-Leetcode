# #479. 最大回文乘积 / Largest Palindrome Product

> 难度：困难 · 标签：Math、Enumeration · [LeetCode 链接](https://leetcode.com/problems/largest-palindrome-product/)

---

## 题目（英文原版）

**Description**

Given an integer n, return the largest palindromic integer that can be represented as the product of two n-digits integers. Since the answer can be very large, return it modulo 1337.

**Examples**

**Example 1:**

```
Input: n = 2
Output: 987
Explanation: 99 x 91 = 9009, 9009 % 1337 = 987
```

**Example 2:**

```
Input: n = 1
Output: 9
```

**Constraints**

- 1 <= n <= 8

---

## 题目（中文翻译）

给定一个整数 `n`，返回可以表示为两个 **n 位整数**（n-digits integers）的 **乘积**（product）的最大 **回文整数**（palindromic integer）。由于答案可能非常大，返回其对 `1337` 取 **模**（modulo）后的结果。

**示例 1**  
```
Input: n = 2
Output: 987
```
**解释**：`99 × 91 = 9009，9009 % 1337 = 987`

**示例 2**  
```
Input: n = 1
Output: 9
```

**约束条件**  
- `1 <= n <= 8`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是**把所有可能的 n 位数的乘积全部算出来，挑出最大的回文数**。

- **枚举**：先把所有 n 位整数（即从 `10^{n-1}` 到 `10^{n}-1`）放进两个循环里，分别记为 `a`、`b`。  
- **乘积**：计算 `prod = a * b`。  
- **回文检测**：把 `prod` 转成字符串，检查正着读和倒着读是否相同。  
  - 这里可以把“回文”想象成一本书的前后页码相同，正读和倒读的顺序一样。  
- **记录最大**：如果是回文且比当前记录的最大值更大，就更新答案。  

> **为什么一定能得到答案？**  
> 因为我们遍历了**所有**合法的乘积，最大的回文自然会被捕获。

#### 代码（Python）

```python
def largestPalindrome_bruteforce(n: int) -> int:
    # 计算 n 位数的上下界
    lo = 10 ** (n - 1)            # 最小的 n 位数，例如 n=2 时是 10
    hi = 10 ** n - 1              # 最大的 n 位数，例如 n=2 时是 99

    best = 0                      # 当前找到的最大回文
    for a in range(hi, lo - 1, -1):          # 从大到小枚举，稍微可以提前剪枝
        for b in range(a, lo - 1, -1):      # b ≤ a 防止重复计算
            prod = a * b
            # ---------- 回文检查 ----------
            s = str(prod)
            if s == s[::-1]:                # 正读和倒读相同即为回文
                if prod > best:
                    best = prod
                # 因为 a、b 正在递减，已找到的回文已经是这轮 a 的最大，直接 break
                break
    # 题目要求对 1337 取模
    return best % 1337
```

#### 复杂度  

- **时间复杂度**：`O((10^n)^2) = O(10^{2n})`  
  - 直观理解：我们要遍历所有的 n 位数的两两组合，数量大约是 `10^n` 的平方。比如 `n=3` 时，需要检查约 `900*900 ≈ 8.1e5` 次。  
- **空间复杂度**：`O(1)`  
  - 只用了几个整数变量，和输入规模无关。

> 对于 `n ≤ 8`，`10^{2n}` 已经是 `10^16` 级别，完全不可接受，所以必须找更快的办法。

### 2. 最优解

#### 思路  

暴力的瓶颈在于**枚举所有乘积**。实际上我们只关心**回文数本身**，而不是每个乘积。思路可以倒着来：

1. **从大到小生成回文数**  
   - 最大的 n 位数是 `hi = 10^n - 1`（例如 99、999）。它们的乘积上限是 `hi * hi`。  
   - 我们可以先把 `hi * hi` 写成字符串，然后把前半段复制到后半段，得到一个回文数。  
   - 逐渐把前半段（称为 “根”）递减，生成的回文数也会递减。这样我们从最大的可能回文开始检查，第一次成功就一定是答案。

2. **检查回文能否拆成两个 n 位数的乘积**  
   - 设当前回文为 `p`。我们只需要找一个 n 位数 `i`（从 `hi` 往下遍历），使得 `p % i == 0` 且 `p // i` 也是 n 位数。  
   - 为什么只遍历到 `sqrt(p)`？因为如果 `i` 已经小于 `sqrt(p)`，那么对应的另一因子 `p // i` 就已经大于 `sqrt(p)`，而我们已经在前面的更大的 `i` 中尝试过了。这里我们直接遍历到 `hi`，但加入 `i*i >= p` 的提前终止条件即可。

3. **返回结果取模**  
   - 一旦找到满足条件的 `i`，`p` 就是答案。直接返回 `p % 1337`。

> **类比**：把回文看成“钥匙”，我们从最大的钥匙开始尝试插入锁（两个 n 位数），第一个能顺利打开的钥匙就是我们要找的。

#### 代码（Python）

```python
def largestPalindrome(n: int) -> int:
    """
    返回由两个 n 位整数相乘得到的最大回文数，取模 1337。
    """
    if n == 1:                 # 特判：1 位数时最大回文是 9
        return 9

    hi = 10 ** n - 1           # 最大的 n 位数，例如 99、999
    lo = 10 ** (n - 1)         # 最小的 n 位数，例如 10、100

    # ---------- 生成回文的“根”，从 hi 开始往下 ----------
    # 例如 n=2 时 hi=99，根从 99 开始；n=3 时根从 999 开始。
    for left in range(hi, lo - 1, -1):
        # 把左半部分 left 拼成完整的回文
        # 例如 left=99 -> s='99' -> rev='99' -> palindrome=9999
        s = str(left)
        palindrome = int(s + s[::-1])   # 直接构造回文

        # ---------- 检查 palindrome 是否可以拆成两个 n 位数 ----------
        # i 从 hi 开始递减，只要 i*i >= palindrome 就还有可能找到因子
        for i in range(hi, lo - 1, -1):
            if i * i < palindrome:      # 已经小于 sqrt(p)，后面不可能再找到
                break
            if palindrome % i == 0:     # i 是一个因子
                j = palindrome // i
                if lo <= j <= hi:       # 另一个因子也必须是 n 位数
                    return palindrome % 1337

    # 理论上永远不会走到这里，因为一定能找到答案
    return -1
```

> **关键行解释**  
> - `s + s[::-1]`：把左半部分翻转后拼在后面，得到回文。`[::-1]` 是 Python 切片技巧，表示“倒序”。  
> - `if i * i < palindrome: break`：如果 `i` 已经小于回文的平方根，则后面的 `i` 更小，必然找不到新的因子，提前结束循环，省时。  
> - `if lo <= j <= hi`：确保另一因子 `j` 仍是 n 位数。

#### 复杂度  

- **时间复杂度**：`O(10^{n})`  
  - 我们的外层循环遍历“根”从 `hi` 到 `lo`，共约 `9 * 10^{n-1}` 次，即 `O(10^{n})`。  
  - 内层循环在最坏情况下也最多遍历 `O(10^{n})` 次，但因为大多数回文在前几次就能找到因子，实际运行远快于 `10^{2n}`。  
  - 与暴力的 `10^{2n}` 相比，指数从 `2n` 降到 `n`，当 `n=8` 时，从 `10^{16}` 降到 `10^{8}`，在一秒内即可完成。

- **空间复杂度**：`O(1)`  
  - 只使用了常数个整数变量和字符串临时对象，和 `n` 的大小无关。

## 心得

- **核心技巧**：**从答案空间倒推**（即先生成回文，再验证能否拆分），而不是正向枚举所有乘积。  
- **适用的题型**  
  1. “最大回文乘积”这类需要在**乘积**中寻找特殊数值的题。  
  2. “寻找满足某种性质的最大/最小数”——如“最大回文数”“最大满足条件的整数”。  
  3. “数位 DP”或“构造性搜索”中，经常会先**构造候选答案**再**验证**。  
- **一句话总结**：**先造出最大的回文，再找能拆开的两位数，首个成功即为答案**。

## 反思

- **第一反应**：直接暴力枚举所有 `a * b`，因为这最直观。  
- **最容易踩的坑**  
  - **边界**：`n = 1` 时特殊处理，最大回文是 9（而不是通过通用逻辑得到的 9×9=81 不是回文）。  
  - **因子范围**：检查因子时必须保证两者都是 n 位数，忘记下界 `10^{n-1}` 会导致错误答案。  
  - **提前终止**：如果不加 `i*i < palindrome` 的剪枝，内层循环会跑太久。  
- **下次类似题目**：**先思考“答案的形状”**（比如回文、递增、等差等），尝试**从答案空间倒着搜索**，再验证可行性，而不是盲目遍历所有输入组合。
