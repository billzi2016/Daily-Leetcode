# #415. 字符串相加 / Add Strings

> 难度：简单 · 标签：Math、String、Simulation · [LeetCode 链接](https://leetcode.com/problems/add-strings/)

## 题目（英文原版）

**Description**

Given two non-negative integers, num1 and num2 represented as string, return the sum of num1 and num2 as a string.
You must solve the problem without using any built-in library for handling large integers (such as BigInteger). You must also not convert the inputs to integers directly.

**Examples**

**Example 1:**

```
Input: num1 = "11", num2 = "123"
Output: "134"
```

**Example 2:**

```
Input: num1 = "456", num2 = "77"
Output: "533"
```

**Example 3:**

```
Input: num1 = "0", num2 = "0"
Output: "0"
```

**Constraints**

- 1 <= num1.length, num2.length <= 104
- num1 and num2 consist of only digits.
- num1 and num2 don't have any leading zeros except for the zero itself.

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是把 **“手算大数”** 这件事完整地搬到代码里：

1. 先把 `num2` 从右往左（最低位到最高位）逐位取出，每次只拿 **一个数字**（0~9）。  
2. 把这个单个数字加到 `num1` 的对应位上（同样从右往左），产生一个新的字符串。  
3. 这一步相当于我们在纸上 **一次只加一位**，每次都要处理进位（carry），并把结果写回 `num1`。  
4. 把 `num2` 的每一位都这么“加”完后，`num1` 就变成了两数之和。

> **类比**：把 `num1` 看成一本记账本，`num2` 的每一位就像一笔小额存款。我们一次只把一笔钱存进去，需要每次检查是否要向更高位“进位”。  

**为什么正确**  
- 每次只处理一位，进位的规则和十进制加法完全一样。  
- 循环遍历完 `num2` 的所有位后，所有的“存款”都已经加到了 `num1`，于是 `num1` 就是最终答案。

**时间/空间复杂度**  
- 对 `num2` 的每一位，我们都要遍历一次完整的 `num1`（因为要把进位传播到最高位），所以时间是 **O(len(num1) × len(num2))**。  
  - 大白话：如果两个数都是 10,000 位，最坏情况下要做 10,000 × 10,000 = 1 亿次基本运算，明显有点慢。  
- 只用了几个临时变量和结果字符串，空间是 **O(1)**（不计输出本身）。

#### 代码（Python）

```python
def addStrings_bruteforce(num1: str, num2: str) -> str:
    # 让 num1 永远是较长的那个，方便后面直接在它上面“写回”
    if len(num2) > len(num1):
        num1, num2 = num2, num1

    # 把 num1 变成列表，方便原地修改（字符串不可变）
    num1_list = list(num1)

    # 从 num2 的最低位（右端）开始遍历
    for i in range(1, len(num2) + 1):
        # 取出当前位的数字（字符转整数）
        d2 = ord(num2[-i]) - ord('0')

        # 将 d2 加到 num1 对应位上，需要处理进位
        carry = d2
        j = i                     # 对应的 num1 位索引（从右往左）
        while carry > 0 and j <= len(num1_list):
            # 取出 num1 当前位的数字
            d1 = ord(num1_list[-j]) - ord('0')
            # 当前位相加 + 进位
            total = d1 + carry
            # 更新该位的字符（只保留个位）
            num1_list[-j] = chr((total % 10) + ord('0'))
            # 进位准备给更高一位
            carry = total // 10
            j += 1

        # 如果最高位仍有进位，需要在最前面插入一个新位
        if carry > 0:
            num1_list.insert(0, chr(carry + ord('0')))

    # 把列表拼回字符串即为答案
    return ''.join(num1_list)
```

> **关键行注释**  
> - `ord(num2[-i]) - ord('0')`：把字符 `'3'` 转成整数 `3`，相当于查字典：键是字符，值是对应数字。  
> - `while carry > 0 and j <= len(num1_list):`：循环把进位“一位一位”向左传播。  
> - `num1_list.insert(0, ...)`：如果最高位仍有进位，就像在账本最前面写了一个新的“千位”。  

#### 复杂度

- **时间复杂度**：`O(len(num1) * len(num2))`  
  - 直观理解：两本账本的每一页都可能要互相检查一次。  
- **空间复杂度**：`O(1)`（不计输出本身）  
  - 只用了常数个临时变量和一个可原地修改的字符列表。

### 2. 最优解

#### 思路  

从暴力解可以看到，**慢点在于每次加完一位都要把进位在 `num1` 上遍历一次**。实际上，十进制加法只需要一次遍历就能把所有位和进位一次性算完。思路如下：

1. **倒着遍历** 两个字符串（从最低位到最高位），同时维护一个 `carry`（进位），初始为 0。  
2. 每一步取出当前位的数字（如果某个字符串已经遍历完，就当作 0），加上 `carry`，得到 `total`。  
3. `total % 10` 是当前位的答案，`total // 10` 是下一位的进位。把答案字符放进结果列表。  
4. 循环结束后，如果最高位还有进位（`carry != 0`），再把它加入结果。  
5. 结果列表是逆序的（因为我们是从低位往高位写的），最后把它反转成字符串返回。

> **核心数据结构**：**双指针**（两个索引分别指向 `num1`、`num2` 的末尾） + **字符列表**（临时存放逆序结果）。  
> **类比**：想象两根绳子分别写着两个数，从右端（最低位）开始把它们拉在一起，每拉一次就算一次加法，拉完后再把所有结果倒过来展示。

**为什么更快**  
- 只遍历一次 `max(len(num1), len(num2))` 步，每一步的计算都是 O(1)。  
- 没有“把进位在已有结果里再跑一遍”的额外开销。

#### 代码（Python）

```python
def addStrings(num1: str, num2: str) -> str:
    i, j = len(num1) - 1, len(num2) - 1   # 双指针，指向各自的最低位
    carry = 0                             # 进位初始为 0
    res = []                              # 用列表保存逆序结果

    while i >= 0 or j >= 0 or carry:      # 任意一方还有数字或还有进位时继续
        x = ord(num1[i]) - ord('0') if i >= 0 else 0   # 取出当前位数字，或 0
        y = ord(num2[j]) - ord('0') if j >= 0 else 0

        total = x + y + carry            # 当前位相加 + 进位
        res.append(chr((total % 10) + ord('0')))  # 当前位答案，存为字符
        carry = total // 10              # 为下一位准备进位

        i -= 1                           # 指针左移（向更高位）
        j -= 1

    # 结果目前是逆序的，翻转后拼成字符串返回
    return ''.join(reversed(res))
```

> **关键行注释**  
> - `while i >= 0 or j >= 0 or carry:`：只要还有未处理的位或还有进位，就必须继续。  
> - `ord(num1[i]) - ord('0')`：把字符直接转成对应的整数，类似查字典。  
> - `res.append(...)`：把当前位的字符放进列表，顺序是 **低位 → 高位**，所以最后要 `reversed`。  

#### 复杂度

- **时间复杂度**：`O(max(len(num1), len(num2)))`  
  - 只遍历一次最长的那个字符串，实际运行速度比暴力解快很多。  
- **空间复杂度**：`O(max(len(num1), len(num2)))`  
  - 需要一个列表保存结果，大小正好等于答案的位数（最多比最长输入多一位）。

## 心得

- **核心技巧**：**从低位到高位逐位相加、维护进位**，即“模拟手算”。  
- **适用题型**：  
  1. 两个大整数相加（本题）。  
  2. 两个大整数相减（需要借位的思路）。  
  3. 大整数乘法的“列竖式”实现（同样从低位开始累计）。  
- **一句话总结**：**只要把十进制加法的规则写进代码，遍历一次即可搞定大数相加**。

## 反思

- **第一反应**：把字符串直接转成 `int` 再相加——最省事但违背“大数不能直接转整数”的限制。  
- **最容易踩的坑**  
  - 忘记处理最高位的进位，导致答案缺少最左边的 `1`（如 `99 + 1 = 100`）。  
  - 当其中一个字符串长度为 0（虽然题目不允许），代码仍需安全地返回另一个字符串。  
  - 使用字符相加时直接 `+` 会产生字符串拼接错误，需要先转成数字再运算。  
- **下次遇到同类题**：第一步先 **确定从低位开始遍历**，准备好 **进位变量**，然后一步步写出“取位 → 相加 → 记录结果 → 更新进位”。这样就能快速搭建出正确且高效的解法。
