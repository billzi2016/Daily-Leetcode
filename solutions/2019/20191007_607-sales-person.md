编写一个查询，找出所有 **没有** 与名称为 **"RED"** 的公司产生订单的销售人员的姓名。  
返回的结果表可以任意顺序排列。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

我们把三张表都看成 **列表**（每条记录是一个字典），手动模拟 SQL 的关联查询。  
最直接的想法是：

1. **先找到公司 “RED” 的 `com_id`**。这一步相当于在 `Company` 表里找名字为 “RED” 的那一行，取出它的 `com_id`。可以把它想成在一本电话簿里查找某个人的电话号码——把名字对应到号码。
2. **遍历 `Orders` 表，找出所有涉及该 `com_id` 的订单**，把对应的 `sales_id` 收集起来。这里 `sales_id` 就像是订单的 “收件人”，我们把所有收件人的编号记下来。
3. **遍历 `SalesPerson` 表**，只要该销售员的 `sales_id` 没出现在第 2 步的集合里，就说明他（她）没有给 “RED” 公司下单，直接把名字加入答案。

为什么这样一定对？

- 第 1 步保证我们只关注公司名称为 “RED” 的公司，而不是别的公司。
- 第 2 步把所有 **真的** 给 “RED” 下单的销售员全部列出来（不管下了多少单，只要有一次就算）。
- 第 3 步把 **没有** 出现在第 2 步集合里的销售员挑出来，正是题目要的答案。

**时间/空间复杂度**（大白话）：

- 第 1 步要遍历一次 `Company` 表，记为 `O(C)`（C 是公司数量）。
- 第 2 步要遍历一次 `Orders` 表，记为 `O(O)`（O 是订单数量）。
- 第 3 步要遍历一次 `SalesPerson` 表，记为 `O(S)`（S 是销售员数量）。
- 于是总时间是 `O(C + O + S)`，在最坏情况下如果三张表都很大，这个复杂度仍然是线性（每条记录只看一次），已经算是 **最直接** 的实现了。

空间上我们只用了一个集合来存 `sales_id`，大小不超过 `S`，所以是 `O(S)`。

> **注意**：这里的 “暴力” 并不是 `O(n²)` 那种“双层循环”遍历同一张表，而是对每张表都做一次线性扫描——在数据库里这已经是最原始的做法了。

#### 代码（Python）

```python
# ---------- 模拟数据 ----------
salesperson = [
    {"sales_id": 1, "name": "John", "salary": 100000, "commission_rate": 6, "hire_date": "2006-04-01"},
    {"sales_id": 2, "name": "Amy",  "salary": 12000,  "commission_rate": 5, "hire_date": "2010-05-01"},
    {"sales_id": 3, "name": "Mark", "salary": 65000,  "commission_rate": 12,"hire_date": "2008-12-25"},
    {"sales_id": 4, "name": "Pam",  "salary": 25000,  "commission_rate": 25,"hire_date": "2005-01-01"},
    {"sales_id": 5, "name": "Alex", "salary": 5000,   "commission_rate": 10,"hire_date": "2007-02-03"},
]

company = [
    {"com_id": 1, "name": "RED",    "city": "Boston"},
    {"com_id": 2, "name": "ORANGE", "city": "New York"},
    {"com_id": 3, "name": "YELLOW", "city": "Boston"},
    {"com_id": 4, "name": "GREEN",  "city": "Austin"},
]

orders = [
    {"order_id": 1, "order_date": "2014-01-01", "com_id": 3, "sales_id": 4, "amount": 10000},
    {"order_id": 2, "order_date": "2014-02-01", "com_id": 4, "sales_id": 5, "amount": 5000},
    {"order_id": 3, "order_date": "2014-03-01", "com_id": 1, "sales_id": 1, "amount": 50000},
    {"order_id": 4, "order_date": "2014-04-01", "com_id": 1, "sales_id": 4, "amount": 25000},
]

# ---------- 第 1 步：找 RED 公司的 com_id ----------
red_com_id = None
for row in company:
    if row["name"] == "RED":
        red_com_id = row["com_id"]
        break   # 公司名唯一，找到后立刻退出

# 如果数据库里根本没有 RED 公司，所有销售员都符合条件
if red_com_id is None:
    result = [row["name"] for row in salesperson]
else:
    # ---------- 第 2 步：收集所有给 RED 公司下单的 sales_id ----------
    sales_with_red = set()          # 用集合去重，防止同一个人多次出现
    for o in orders:
        if o["com_id"] == red_com_id:
            sales_with_red.add(o["sales_id"])

    # ---------- 第 3 步：筛选没有出现在集合里的销售员 ----------
    result = []
    for sp in salesperson:
        if sp["sales_id"] not in sales_with_red:
            result.append(sp["name"])

# 打印结果（任意顺序均可）
print(result)   # 示例输出: ['Amy', 'Mark', 'Alex']
```

#### 复杂度

- **时间复杂度**：`O(C + O + S)`  
  - `C` 为公司表行数，`O` 为订单表行数，`S` 为销售员表行数。每张表只遍历一次，实际运行时间随数据规模线性增长。
- **空间复杂度**：`O(S)`  
  - 只用了一个集合 `sales_with_red`，最多装下所有销售员的 `sales_id`。

### 2. 最优解

#### 思路  

从暴力解来看，**瓶颈并不在时间**——我们已经是线性遍历了。真正可以改进的，是**代码的简洁度**以及**利用数据库的集合运算**（在实际面试中，通常要求直接写一条 SQL）。

如果我们把思路完全搬到 **SQL**，可以只写两条子查询：

1. 找出所有给 “RED” 公司下单的 `sales_id`（使用 `JOIN` 把 `Orders` 与 `Company` 按 `com_id` 关联）。
2. 再从 `SalesPerson` 表中挑出 `sales_id` **不在** 第一步结果里的记录（使用 `NOT IN` 或 `LEFT JOIN ... IS NULL`）。

在 Python 中，**最优实现**就是把这两步合并成一次集合操作，避免显式的三次循环：

- 先用一次遍历得到 `red_com_id`（常数时间，因为公司数量一般很少）。
- 再一次遍历 `Orders` **只保留** `com_id == red_com_id` 的 `sales_id`，直接生成集合 `sales_with_red`。
- 最后一次遍历 `SalesPerson`，直接用集合的 `in` 操作（哈希查找）判断是否属于 “已下单” 集合，时间复杂度为 **O(1)**，整体仍是 `O(C + O + S)`，但常数更小，代码更易读。

> **核心概念**：  
> - **集合（Set）** 在 Python 中类似“字典的钥匙”，查找元素的速度是 **常数级**（大约是 `O(1)`），这相当于把“查字典”这件事变得超级快。  
> - **JOIN** 在关系型数据库里就是把两张表按照共同字段配对，在代码里我们用 `if` 条件手动配对。

#### 代码（Python）

```python
def sales_without_red(salesperson, company, orders):
    """
    返回所有没有给公司名为 'RED' 的客户下单的销售员姓名。
    参数都是列表 of dict，结构同上例。
    """
    # 1️⃣ 找到 RED 公司的 id（只遍历一次公司表）
    red_com_id = next((c["com_id"] for c in company if c["name"] == "RED"), None)

    # 如果根本没有 RED 公司，直接返回全部销售员姓名
    if red_com_id is None:
        return [sp["name"] for sp in salesperson]

    # 2️⃣ 用集合一次遍历 Orders，收集所有下单给 RED 的 sales_id
    sales_with_red = {o["sales_id"] for o in orders if o["com_id"] == red_com_id}
    #   ^ 这里用了集合推导式，等价于 for 循环 + if 判断，写法更紧凑

    # 3️⃣ 再一次遍历 SalesPerson，直接用 “不在集合里” 的判定筛选
    return [sp["name"] for sp in salesperson if sp["sales_id"] not in sales_with_red]

# 调用示例
print(sales_without_red(salesperson, company, orders))
# 输出: ['Amy', 'Mark', 'Alex']
```

#### 复杂度

- **时间复杂度**：`O(C + O + S)`（与暴力解相同，但每一步都使用了最有效的操作：集合查找是 O(1)）。
- **空间复杂度**：`O(S)`（只需要保存 `sales_with_red` 这个集合）。

> 与暴力解相比，**最优解的优势**在于代码更简洁、易读，并且在实际数据库里只需要一条 SQL 语句即可完成全部工作。

## 心得

- **核心技巧**：使用 **集合（Set）** 或 **子查询** 把 “已经满足条件的元素” 收集起来，再用 **排除（NOT IN / IS NULL）** 的思路得到答案。
- **适用的题型**  
  1. “找出没有关联记录的主表行”——例如 `Customers` 表中没有订单的客户。  
  2. “找出没有出现过的属性值”——例如没有参加任何活动的用户。  
  3. “找出未被标记为已完成的任务”——类似 `Tasks` 表中不在 `CompletedTasks` 表里的任务。
- **一句话总结解题钥匙**：**先把“有关系的”收集成集合，再用“没有在集合中”筛选出答案**。

## 反思

- **第一反应**：看到三张表，我第一时间想到把 `Company` 中 “RED” 的 `com_id` 拿出来，然后在 `Orders` 里找对应的 `sales_id`，最后在 `SalesPerson` 中排除这些人。
- **最容易踩的坑**  
  - **公司不存在**：如果 `Company` 表里根本没有 “RED”，直接返回全部销售员。忘记这点会导致空集合导致错误答案。  
  - **重复订单**：同一个销售员可能给 “RED” 多次下单，若用列表而不是集合去重，判断时仍然正确，但集合能省掉多余的比较。  
  - **SQL 中的 NULL**：在写 `NOT IN` 时如果子查询里出现 `NULL`，会导致全部行被排除，需要用 `NOT EXISTS` 或 `LEFT JOIN ... IS NULL`。
- **下次遇到类似题**：第一步先 **定位关键实体**（这里是 “RED” 对应的 `com_id`），随后 **把关联记录收集成集合**，最后 **在主表中做排除**。这样思路清晰，代码或 SQL 都能一次写对。
