# #440. 字典序第 K 小的数 / K-th Smallest in Lexicographical Order

> 难度：困难 · 标签：Trie · [LeetCode 链接](https://leetcode.com/problems/k-th-smallest-in-lexicographical-order/)

---

## 题目（英文原版）

**Description**

Given two integers n and k, return the kth lexicographically smallest integer in the range [1, n].

**Examples**

**Example 1:**

```
Input: n = 13, k = 2
Output: 10
Explanation: The lexicographical order is [1, 10, 11, 12, 13, 2, 3, 4, 5, 6, 7, 8, 9], so the second smallest number is 10.
```

**Example 2:**

```
Input: n = 1, k = 1
Output: 1
```

**Constraints**

- 1 <= k <= n <= 109

---

## 题目（中文翻译）

给定两个整数 `n` 和 `k`，返回区间 `[1, n]` 中字典序（lexicographical order）第 `k` 小的整数。

### 示例

#### 示例 1
**输入**: `n = 13, k = 2`  
**输出**: `10`  
**解释**: 按字典序排列的序列为 `[1, 10, 11, 12, 13, 2, 3, 4, 5, 6, 7, 8, 9]`，因此第二小的数字是 `10`。

#### 示例 2
**输入**: `n = 1, k = 1`  
**输出**: `1`  
**解释**: 唯一的数字 `1` 即为第 1 小。

### 约束条件
- `1 <= k <= n <= 10^9`

---

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把区间 `[1, n]` 里的所有整数都列出来，按照字典序（即把数字当成字符串来比较）排序，然后取第 `k` 小的那个。  
- **数据结构**：我们用一个 Python 列表 `arr` 来存放所有数字，随后调用 `sorted`（内部实现类似 **哈希表** 的“查字典”，只不过这里是“查排序”）。  
- **正确性**：字典序本质上就是把每个数字转成字符序列后比较大小，完整列出后排序自然得到全局的字典序排列，取第 `k` 项即为答案。  

> **为什么会对**：因为排序算法（如 Timsort）已经实现了“把所有元素按字典序排好顺序”，我们只要把数字转成字符串让排序器按字符比较即可。

#### 代码（Python）

```python
def findKthNumber_bruteforce(n: int, k: int) -> int:
    # 1. 把 1~n 全部放进列表
    nums = list(range(1, n + 1))                 # [1, 2, 3, ..., n]

    # 2. 按字典序排序（把整数转成字符串比较）
    nums.sort(key=lambda x: str(x))              # key 指定排序依据为字符串形式

    # 3. 第 k 小（k 从 1 开始计数）直接返回
    return nums[k - 1]
```

#### 复杂度  

- **时间复杂度**：`O(n log n)`  
  - 解释：我们要把 `n` 个数全部排一次序，排序的代价大约是 `n` 乘以 `log₂ n`（类似把 `n` 本书排好顺序，需要比较 `log n` 次才能决定每本书的相对位置）。  
- **空间复杂度**：`O(n)`  
  - 解释：需要一个长度为 `n` 的列表来存放所有数字，相当于把所有书都搬到桌面上排。

> 这套方法在 `n` 很小（比如几千）时还能接受，但题目给出的 `n ≤ 10⁹`，根本不可能把这么多数字全部放进内存，更别提排序了。

---

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **“把全部数字都生成出来”**。我们必须 **跳过** 大量不需要遍历的数字，直接“走”到第 `k` 个位置。  
这可以把所有正整数想象成一棵 **字典序前缀树（Trie）**：

```
1
 ├─10
 │   ├─100
 │   └─101 …
 ├─11
 ├─12
 └─13
2
 ├─20 …
3
...
9
```

- 每个节点是一个整数前缀（比如 `1`、`10`、`100`）。  
- 从一个前缀出发，**所有以它为前缀的整数** 都在它的子树里。  
- 关键是**快速算出**某个前缀的子树里到底有多少个合法整数（不超过 `n`），这叫 **"count"**。

**步骤概览**  

1. 从 `cur = 1`（第一个字典序）开始。  
2. 计算 `cur` 与 `cur+1` 之间（即 `cur` 的子树）包含多少数字，记为 `cnt`。  
   - 若 `k > cnt`，说明第 `k` 小的数不在这棵子树里，跳到下一个兄弟节点 `cur + 1`，并把 `k -= cnt`（因为我们已经跳过了 `cnt` 个数）。  
   - 若 `k ≤ cnt`，说明答案在这棵子树里，**进入子树**：`cur = cur * 10`（相当于在前缀后面加一个 `0`），并把 `k -= 1`（因为当前节点 `cur` 本身已经算作第一个）。  
3. 重复上述过程，直到 `k == 1`，此时 `cur` 就是答案。

**如何计算 `cnt`（前缀下的节点数）**  

给定前缀 `first` 和它的下一个前缀 `last = first + 1`，我们在 `[first, last)` 区间里逐层向下扩展（乘以 10），累计每一层能够出现的数字个数，受 `n` 的上限限制：

```
cnt = 0
while first <= n:
    cnt += min(n + 1, last) - first
    first *= 10
    last  *= 10
```

- `min(n + 1, last) - first` 表示当前层实际能放的数字数量（如果 `last` 超过 `n+1`，只能到 `n` 为止）。  
- 乘以 10 进入下一层，前缀长度加一。

**为什么这一步是 O(log n)**：每次循环 `first` 至少乘以 10，层数最多是 `log₁₀ n`（十进制位数），所以循环次数很少。

#### 代码（Python）

```python
def findKthNumber(n: int, k: int) -> int:
    """
    返回字典序第 k 小的整数，范围 1~n。
    思路：把整数视作字典序前缀树，利用前缀下的节点数量快速跳跃。
    """
    cur = 1          # 当前所在的数字（从 1 开始）
    k -= 1           # 因为 cur 本身已经算作第 1 个，所以把 k 减 1

    while k > 0:
        cnt = _count_prefix(cur, n)   # 计算 cur 前缀下有多少数字
        if k >= cnt:                  # 需要跳过整个子树
            cur += 1                  # 移动到下一个兄弟前缀
            k -= cnt                  # 已经跳过 cnt 个数
        else:                         # 目标在子树内部
            cur *= 10                 # 进入子树（在后面加 0）
            k -= 1                    # 进入子树后，当前节点 cur 本身算一个
    return cur


def _count_prefix(first: int, n: int) -> int:
    """
    统计以 `first` 为前缀、且不超过 n 的整数个数。
    例如 n=13, first=1 时，返回 5（1,10,11,12,13）。
    """
    cnt = 0
    last = first + 1
    while first <= n:
        # 本层实际能放的数字是 [first, min(n+1, last)) 区间的大小
        cnt += min(n + 1, last) - first
        first *= 10   # 进入下一层（前缀左移一位）
        last  *= 10
    return cnt
```

#### 复杂度  

- **时间复杂度**：`O(log n)`  
  - 解释：每一次循环要么把 `cur` 乘以 10（进入子树），要么把 `cur` 加 1（跳到兄弟），而 `count_prefix` 本身最多循环 `log₁₀ n` 次。整体上只会遍历至答案所在的路径，路径长度至多是十进制位数，即 `log₁₀ n`（约 10 次当 `n≈10⁹`），所以运行非常快。  
- **空间复杂度**：`O(1)`  
  - 解释：只用了常数个整数变量，没有额外的数组或递归栈。

> 与暴力解相比，时间从 `O(n log n)` 降到了 `O(log n)`，空间也从 `O(n)` 降到了 `O(1)`，完全可以处理题目给出的上限 `10⁹`。

## 心得

- **核心技巧**：利用字典序前缀树（Trie）以及前缀计数（prefix count）实现**跳跃式遍历**，把“遍历全部”转化为“在树上走路径”。  
- **适用题型**：  
  1. “第 K 小/大数” 类的字典序或层序问题（如 LeetCode 440. K-th Smallest in Lexicographical Order）。  
  2. “在 1~n 中寻找满足某种前缀约束的第 K 个数”。  
  3. “按字典序遍历整数/字符串” 的相关变体。  
- **一句话总结解题钥匙**：**把数字当成前缀树的节点，用前缀下的节点数量直接跳过不需要的整棵子树**。

## 反思

- **第一反应**：直接把所有数生成、排序，觉得最直观，但很快意识到 `n` 太大不可能这么做。  
- **最容易踩的坑**：  
  - **计数越界**：`count_prefix` 中要用 `min(n+1, last)` 防止 `last` 超过 `n`，否则会产生负数。  
  - **k 的更新**：跳过子树时要 `k -= cnt`，进入子树时要 `k -= 1`（因为当前节点本身已经算过）。忘记这一步会导致答案偏大/偏小。  
  - **循环终止条件**：当 `k == 0`（或 `k == 1`）时要返回当前 `cur`，否则会多走一步。  
- **下次思路**：一看到“第 K 小 / 第 K 大” 且“范围很大” 的题目，立刻想到**利用计数跳跃**（二分、前缀计数或组合计数）而不是线性遍历。先在脑中画出前缀树或二分区间，确定可以一次性跳过多少元素，再逐步逼近答案。
