# #462. 使数组元素相等的最小移动次数 II / Minimum Moves to Equal Array Elements II

## 题目（英文原版）

**Description**

Given an integer array nums of size n, return the minimum number of moves required to make all array elements equal.
In one move, you can increment or decrement an element of the array by 1.
Test cases are designed so that the answer will fit in a 32-bit integer.

**Examples**

**Example 1:**

```
Input: nums = [1,2,3]
Output: 2
Explanation:
Only two moves are needed (remember each move increments or decrements one element):
[1,2,3]  =>  [2,2,3]  =>  [2,2,2]
```

**Example 2:**

```
Input: nums = [1,10,2,9]
Output: 16
```

**Constraints**

- n == nums.length
- 1 <= nums.length <= 105
- -109 <= nums[i] <= 109

## 题目（中文翻译）

给定一个长度为 `n` 的整数数组（integer array）`nums`，返回使所有数组元素相等所需的最小移动次数（move）。
在一次移动中，你可以将数组中的任意元素递增（increment）或递减（decrement）1。
题目保证答案能够放入 32 位整数（32-bit integer）中。

**示例 1**  
**输入**: `nums = [1,2,3]`  
**输出**: `2`  
**解释**:  
只需要两次移动（记住每次移动只能递增或递减一个元素）:  
`[1,2,3]  =>  [2,2,3]  =>  [2,2,2]`

**示例 2**  
**输入**: `nums = [1,10,2,9]`  
**输出**: `16`  
**解释**:  
将所有元素调整到 `5`（中位数）需要的最小移动次数为 `|1-5| + |10-5| + |2-5| + |9-5| = 16`。

**约束条件**  
- `n == nums.length`  
- `1 <= nums.length <= 10^5`  
- `-10^9 <= nums[i] <= 10^9`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**把每个元素都调到同一个数**，我们只要把这个“目标数”枚举出来，然后把所有元素分别调到它，需要的步数就是所有元素与目标数的距离之和（即 `|nums[i] - target|` 的累加）。

- **用到的数据结构**：  
  - **列表（list）**：保存原始数组。  
  - **循环**：遍历所有可能的目标数。  
  - **累加器**：记录每次把所有元素调到目标数需要的步数。  

> 类比：想象你在图书馆里找一本书，最笨的办法是把所有的书一本一本搬到同一个书架上，先把每本书搬到第 1 层，再搬到第 2 层……最后统计搬了多少次。这里的“书架层数”就是我们枚举的目标数。

- **为什么正确**：  
 只要我们把 **所有可能的目标数** 都尝试一遍，必然会找到使步数最少的那个目标数。因为题目只要求最少步数，而不是具体的目标数。

- **时间/空间复杂度**：  
  - 假设数组长度为 `n`，数组中最小值记为 `minV`，最大值记为 `maxV`。我们要把每一个整数 `target`（从 `minV` 到 `maxV`）都尝试一次，次数大约是 `maxV - minV + 1`。每一次尝试都要遍历整个数组，耗时 `O(n)`。所以总时间是 `O(n * (maxV-minV))`，在最坏情况下（比如数值跨度很大）可以接近 `O(n²)`。  
  - 额外空间只用了常数级的变量，**空间复杂度 O(1)**。

> 大白话解释：`O(n²)` 就好比你有 `n` 本书，每本书都要搬 `n` 次——搬来搬去的次数跟书的数量的平方成正比，规模一大就会非常慢。

#### 代码（Python）

```python
from typing import List

def min_moves_brute(nums: List[int]) -> int:
    # 1. 找到数组的最小值和最大值，确定目标数的取值范围
    lo, hi = min(nums), max(nums)

    best = float('inf')          # 用来保存目前找到的最小步数

    # 2. 枚举每一个可能的目标数
    for target in range(lo, hi + 1):
        moves = 0                # 累计把所有元素调到 target 需要的步数

        # 3. 对每个元素计算距离并累加
        for x in nums:
            moves += abs(x - target)   # abs 表示绝对值，即距离

        # 4. 更新最小步数
        if moves < best:
            best = moves

    return best
```

#### 复杂度

- **时间复杂度**：`O(n * (maxV - minV))`，在最坏情况下可以近似为 `O(n²)`。  
  > 这里的 `n` 是数组长度，`maxV-minV` 是数值跨度。若数值跨度和 `n` 同级别，复杂度就会是平方级。

- **空间复杂度**：`O(1)`，只用了若干个整数变量，和数组大小无关。

### 2. 最优解

#### 思路  

从暴力解我们可以看到，**枚举所有目标数是最慢的环节**。我们需要找出一个能够 **一次性直接得到最优目标数** 的方法。

**关键观察**：  
把所有元素调到同一个数，使得所有 `|nums[i] - target|` 的和最小，这个目标数恰好是 **数组的中位数**（median）。

- **为什么是中位数？**  
  设数组排好序后为 `a1 ≤ a2 ≤ … ≤ an`。把所有数调到某个 `target`，步数是 `∑|ai - target|`。这个函数在数轴上是**凸函数**，它的最小点恰好落在 **中位数**（如果 `n` 为偶数，任意介于两个中位数之间的数都可以）。  
  简单理解：想象你站在数轴上，左边的人往左走，右边的人往右走，站在最中间的位置（中位数）时，左右两边走的总距离最少。

- **实现方式**：  
  1. **排序**：把数组从小到大排好序，得到中位数。排序的时间是 `O(n log n)`。  
  2. **累加绝对差**：遍历一次数组，累计每个元素与中位数的距离。  

> 类比：如果一群人要围成一条直线并相互握手，最省力的站位是站在最中间的人旁边，因为左边的人向左走，右边的人向右走的距离最小。

- **进阶（可选）**：如果不想排序，可以使用 **快速选择（QuickSelect）** 在 `O(n)` 平均时间内找到中位数。但对于本题 `n ≤ 10⁵`，`O(n log n)` 的排序已经足够快，代码也更易懂。

#### 代码（Python）

```python
from typing import List

def min_moves(nums: List[int]) -> int:
    # 1. 排序，找到中位数
    nums.sort()                     # 原地排序，时间 O(n log n)
    n = len(nums)
    median = nums[n // 2]           # 若 n 为偶数，取右侧中位数也可以

    # 2. 计算所有元素到中位数的距离之和
    moves = 0
    for x in nums:
        moves += abs(x - median)    # 累加绝对差

    return moves
```

> 如果想用 **快速选择**（线性时间）找中位数，可参考 `statistics.median` 或自行实现 `nth_element`，这里不展开，以保持代码简洁。

#### 复杂度

- **时间复杂度**：`O(n log n)`  
  - `O(n log n)` 来自排序（最耗时的步骤），遍历一次求和是 `O(n)`，相较于暴力的 `O(n²)`，快了很多。  
  - 大白话：把 `n` 本书排好顺序只需要 `n` 本书的 **log n** 倍时间，而不是每本书都搬 `n` 次。

- **空间复杂度**：`O(1)`（如果算上排序的原地修改）或 `O(n)`（Python 的 Timsort 需要临时空间），但不随 `n` 的增长而显著增加。

## 心得

- **核心技巧**：**中位数最小化绝对差**，这是统计学里常见的性质。  
- **适用的题型**：  
  1. “把数组元素全部变成相同数，求最少步数” 类似题（如本题）。  
  2. “最小化所有点到同一点的曼哈顿距离”——也会用中位数。  
  3. “使一组数的总移动距离最小的聚类中心”——在一维情况下，聚类中心是中位数。  
- **一句话总结**：**让所有数向中位数靠拢，步数最少**。

## 反思

- **第一反应**：直接想到枚举目标数，然后计算每种情况的步数——这就是暴力解。  
- **最容易踩的坑**：  
  - 忘记对负数也适用，因为绝对值会把方向去掉。  
  - 对偶数长度数组不确定该取左侧还是右侧中位数，其实任选其一或取两者平均都能得到同样的最小步数。  
  - 误以为平均数（均值）是最优目标，其实均值最小化的是**平方差**，而本题是**绝对差**。  
- **下次遇到同类题**：第一步先思考“哪个统计量（均值/中位数/众数）能最小化我需要的代价函数”，再决定是否需要排序或其他线性算法。
