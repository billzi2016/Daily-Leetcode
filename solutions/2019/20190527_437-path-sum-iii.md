# #437. 路径总和 III / Path Sum III

## 题目（英文原版）

**Description**

Given the root of a binary tree and an integer targetSum, return the number of paths where the sum of the values along the path equals targetSum.
The path does not need to start or end at the root or a leaf, but it must go downwards (i.e., traveling only from parent nodes to child nodes).

**Examples**

**Example 1:**

```
Input: root = [10,5,-3,3,2,null,11,3,-2,null,1], targetSum = 8
Output: 3
Explanation: The paths that sum to 8 are shown.
```

**Example 2:**

```
Input: root = [5,4,8,11,null,13,4,7,2,null,null,5,1], targetSum = 22
Output: 3
```

**Constraints**

- The number of nodes in the tree is in the range [0, 1000].
- -109 <= Node.val <= 109
- -1000 <= targetSum <= 1000

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  

最直接的想法是：**把每个节点都当作路径的起点**，从该起点向下遍历所有可能的子路径，累计路径上的节点值，看有没有等于 `targetSum`。  
- **数据结构**：我们只需要二叉树本身和递归调用栈。递归调用栈可以想象成“把所有要去的地方记在纸条上”，每往下一层就往纸条里写一个新地址，回到上层时把纸条撕掉。  
- **为什么正确**：因为题目要求的路径必须是“从父节点往子节点方向”，所以只要我们把每个节点当作起点，枚举它向下的所有连续子序列，就一定会遍历到所有合法路径。  
- **时间/空间复杂度**：  
  - 对每个节点我们都要做一次「从该节点出发的深度优先搜索」，最坏情况下这两层循环会形成 `N`（节点数）×`N` 的遍历，即 **O(N²)**。  
  - 递归深度最多是树的高度，最坏是 `N`，所以 **O(N)** 的额外空间（递归栈）。

> **大白话**：`O(N²)` 就像你有 `N` 本书，每本书都要从头读到尾一次，整体阅读量是 `N` 本书 * `N` 页 = `N²` 页。

#### 代码（Python）

```python
# Definition for a binary tree node.
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


class Solution:
    def pathSum(self, root: TreeNode, targetSum: int) -> int:
        # 主函数：遍历所有节点，把每个节点都当作路径起点
        if not root:
            return 0

        # 统计以当前节点为起点的路径数量 + 递归统计左右子树的答案
        return (self._paths_from(root, targetSum) +
                self.pathSum(root.left, targetSum) +
                self.pathSum(root.right, targetSum))

    def _paths_from(self, node: TreeNode, target: int) -> int:
        """
        统计所有「从 node 开始」向下的路径中，和等于 target 的数量。
        """
        if not node:
            return 0

        # 当前节点本身是否满足
        cnt = 1 if node.val == target else 0

        # 继续向左、向右扩展路径，目标值要减掉已经走过的节点值
        cnt += self._paths_from(node.left, target - node.val)
        cnt += self._paths_from(node.right, target - node.val)

        return cnt
```

#### 复杂度  

- **时间复杂度**：`O(N²)`  
  - 对每个节点都要遍历它下面的所有后代节点。  
- **空间复杂度**：`O(N)`  
  - 递归调用栈的深度最多等于树的高度，最坏情况下是 `N`（链状树）。

### 2. 最优解  

#### 思路  

从暴力解可以看到，**瓶颈在于大量重复计算**：同一条从根到叶的路径会被多个起点多次遍历。  
我们需要一种方法，**在一次深度优先遍历中就能统计所有满足条件的路径**。  

关键点是 **前缀和 + 哈希表**（也叫「前缀计数」）：

1. **前缀和**：从根到当前节点的累计和。  
   - 类比查字典：我们把每一次累计的和记下来，就像在字典里查“我已经走了多少步”。  
2. 对于当前节点的前缀和 `curSum`，如果在它之前的某个祖先节点的前缀和是 `curSum - targetSum`，那么从那个祖先的下一个节点到当前节点的路径和恰好等于 `targetSum`。  
3. 因此我们维护一个 **哈希表 `counter`**：  
   - `counter[s]` 表示「已经出现过的前缀和为 `s` 的次数」。  
   - 在遍历到节点时，先查看 `counter[curSum - targetSum]`，这就是以当前节点结尾、满足条件的路径数量。  
4. 递归进入子节点前，先把 `curSum` 加入哈希表；递归结束后再把它减掉（回溯），保证不同分支之间的计数互不干扰。  

这样每个节点只被访问一次，**时间降到 O(N)**，而哈希表最多存储树的深度层数的前缀和，空间为 **O(N)**（最坏情况下是链状树）。

> **前缀和的直观图示**（文字版）：  
> - 假设从根到某节点的路径值依次是 `[5, 3, -2, 4]`，累计前缀和是 `[5, 8, 6, 10]`。  
> - 目标 `targetSum = 8`。  
> - 当我们来到累计为 `10` 的节点时，查询 `10 - 8 = 2`，发现哈希表里没有 `2`，说明没有以此节点结尾的合法路径。  
> - 当累计为 `6` 时，查询 `6 - 8 = -2`，如果哈希表里有 `-2`（说明在更早的祖先处累计和为 `-2`），则从那个祖先的下一个节点到当前节点的路径和正好是 `8`。

#### 代码（Python）

```python
from collections import defaultdict
# Definition for a binary tree node.
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


class Solution:
    def pathSum(self, root: TreeNode, targetSum: int) -> int:
        # counter[preSum] = 出现次数，默认 0
        counter = defaultdict(int)
        counter[0] = 1               # 空路径的前缀和为 0，方便统计从根直接满足的情况

        def dfs(node: TreeNode, curSum: int) -> int:
            """返回以当前子树为根的合法路径总数"""
            if not node:
                return 0

            curSum += node.val                     # 更新到当前节点的前缀和
            # 看看之前有没有前缀和 = curSum - targetSum
            res = counter[curSum - targetSum]      # 这一步直接得到以 node 为终点的路径数量

            # 把当前前缀和计入哈希表，供子节点使用
            counter[curSum] += 1

            # 继续向左、右子树搜索
            res += dfs(node.left, curSum)
            res += dfs(node.right, curSum)

            # 回溯：离开当前节点后，要把它的前缀和计数减掉
            counter[curSum] -= 1
            return res

        return dfs(root, 0)
```

#### 复杂度  

- **时间复杂度**：`O(N)`  
  - 每个节点只访问一次，哈希表的增删查都是 O(1)。与暴力的 `O(N²)` 相比，快了很多。  
- **空间复杂度**：`O(N)`  
  - 递归栈深度 + 哈希表中最多保存树的高度条目（最坏情况下等于节点数 `N`）。

## 心得  

- **核心技巧**：**前缀和 + 哈希表** 在树结构上的「路径和」统计。  
- **适用题型**（类似思路）：  
  1. LeetCode 560. **Subarray Sum Equals K**（数组前缀和）  
  2. LeetCode 124. **Binary Tree Maximum Path Sum**（需要在树上维护前缀和的变体）  
  3. LeetCode 437. **Path Sum III**（本题）  
- **一句话总结解题钥匙**：**把“从根到当前节点的累计和”记下来，利用哈希表快速找出差值等于目标的历史累计**。

---

## 反思  

- **第一反应**：直接把每个节点当起点，暴力遍历所有向下路径。  
- **最容易踩的坑**：  
  - 忘记在递归返回时把哈希表中的计数减掉，导致不同分支之间的计数相互污染。  
  - 忽略空路径的前缀和 `0`，会导致根节点本身满足 `targetSum` 时计数缺失。  
  - 对负数节点值不做特殊处理，前缀和法本身已经天然支持负数。  
- **下次遇到同类题**：第一步先思考“有没有办法把局部信息（到当前节点的累计）保存起来，并在 O(1) 时间内查询满足条件的历史”，如果答案是“可以”，往往就能想到前缀和 + 哈希表的优化路径。
