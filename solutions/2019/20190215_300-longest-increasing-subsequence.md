## 题目（英文原版）

**Description**

Given an integer array nums, return the length of the longest strictly increasing subsequence.
Follow up: Can you come up with an algorithm that runs in O(n log(n)) time complexity?

**Examples**

**Example 1:**

```
Input: nums = [10,9,2,5,3,7,101,18]
Output: 4
Explanation: The longest increasing subsequence is [2,3,7,101], therefore the length is 4.
```

**Example 2:**

```
Input: nums = [0,1,0,3,2,3]
Output: 4
```

**Example 3:**

```
Input: nums = [7,7,7,7,7,7,7]
Output: 1
```

**Constraints**

- 1 <= nums.length <= 2500
- -104 <= nums[i] <= 104

## 解题过程

### 1. 直觉解（暴力）

#### 思路  
最直接的想法是：**枚举所有可能的子序列**，找出其中严格递增且最长的那个。  
- **子序列**可以把数组想象成一串珠子，我们可以挑选其中的若干颗（保持原来的顺序），不要求连续，就像挑选珠子挂在同一条线一样。  
- 为了判断一个子序列是否递增，只要遍历它，检查每个相邻元素是否满足 `前 < 后`。  

实现上，直接枚举所有子序列的成本极高（指数级），所以我们常用 **动态规划** 把问题压缩到 `O(n²)`：  
- 设 `dp[i]` 为 **以 `nums[i]` 结尾的最长递增子序列的长度**。  
- 对每个位置 `i`，我们回头看所有 `j < i`，如果 `nums[j] < nums[i]`，说明 `nums[i]` 可以接在以 `j` 结尾的递增子序列后面，长度就可以更新为 `dp[j] + 1`。  
- 最终答案是所有 `dp[i]` 中的最大值。

> **为什么正确？**  
> 对每个 `i`，我们把所有可以接在它前面的递增子序列都考虑进去，并取最长的那条。递推关系保证了每个子序列的长度都是在其前缀已经算好的最优解上加一，符合最优子结构。

> **时间/空间复杂度**  
> - 双层循环导致 **时间复杂度是 `O(n²)`**，这里的 `n` 是数组长度。可以把 `O(n²)` 想象成“每个人都要和所有其他人握手”，如果有 1000 个人，就要进行 1,000,000 次握手。  
> - 我们只需要一个长度为 `n` 的数组 `dp`，所以 **空间复杂度是 `O(n)`**，相当于只需要存下每个人的一个小本子。

#### 代码（Python）

```python
from typing import List

def length_of_lis(nums: List[int]) -> int:
    n = len(nums)
    if n == 0:
        return 0

    # dp[i] 表示以 nums[i] 结尾的最长递增子序列长度，初始都为 1（自己本身）
    dp = [1] * n

    # 枚举每一个结尾位置 i
    for i in range(1, n):
        # 看看它前面所有位置 j 是否可以接在 i 前面
        for j in range(i):
            if nums[j] < nums[i]:
                # 如果可以接，就尝试把 dp[i] 更新为更大的值
                dp[i] = max(dp[i], dp[j] + 1)

    # 整个数组的答案是所有 dp[i] 的最大值
    return max(dp)
```

#### 复杂度

- **时间复杂度：`O(n²)`**  
  两层循环分别遍历 `i`（0~n-1）和 `j`（0~i-1），总操作次数约为 `n*(n-1)/2`，即平方级别。  
- **空间复杂度：`O(n)`**  
  只用了一个长度为 `n` 的 `dp` 数组来记录状态。

### 2. 最优解

#### 思路  
从暴力 DP 可以看出，**关键在于“找到比当前元素小的、且能够得到最长长度的前驱”**。  
暴力解的瓶颈是每次都要线性遍历所有前面的元素，导致 `O(n²)`。如果我们能 **快速定位** 那个“最合适的前驱”，就能把时间降下来。

**核心想法：**  
- 维护一个数组 `tails`，其中 `tails[k]` 保存 **长度为 k+1 的递增子序列的最小可能结尾值**。  
- 当遍历到新元素 `x` 时，**在 `tails` 中二分查找** 第一个 **大于或等于 `x` 的位置**，用 `x` 替换它。  
  - 如果 `x` 大于所有 `tails`，则把它直接追加到 `tails`，意味着我们找到更长的递增子序列。  
- 这样，`tails` 的长度始终等于 **最长递增子序列的长度**，而二分查找把每一步的搜索时间压到 `O(log n)`。

> **为什么这样仍然得到正确答案？**  
> - `tails[k]` 保存的是所有长度为 `k+1` 的递增子序列中 **最小的结尾**。如果我们能用更小的数结束长度为 `k+1` 的序列，那么以后加入更大的数时，成功的机会只会增多（因为后面的数只需要比结尾更大）。  
> - 这就是 **“贪心 + 二分”** 的本质：每一步都尽量让序列的结尾保持最小，从而为后面的元素留出最大空间。

> **类比**：  
> 想象你在排队买票，每个人只能站在比自己年龄更大的前面。`tails` 记录的是每个队列长度对应的 **最小年龄的领头人**。当新来一个年龄 `x`，你要找第一个领头人年龄 **≥ x** 的队列，把 `x` 放进去（可能让领头人更年轻），否则就开一个新队列（长度加 1）。最终队列的数量就是最长递增子序列的长度。

> **时间/空间复杂度**  
> - 每个元素只做一次二分查找，时间 `O(log n)`，整体 `O(n log n)`。  
> - `tails` 最多保存 `n` 个元素，空间 `O(n)`，实际上只需要 `O(n)` 的额外数组。

#### 代码（Python）

```python
from bisect import bisect_left
from typing import List

def length_of_lis(nums: List[int]) -> int:
    """
    使用「耐心排序」的思路 + 二分查找，时间 O(n log n)。
    tails[i] 表示长度为 i+1 的递增子序列的最小结尾值。
    """
    tails = []                     # 空的 tails 列表

    for x in nums:                 # 依次处理每个数
        # 在 tails 中寻找第一个 >= x 的位置
        idx = bisect_left(tails, x)

        if idx == len(tails):
            # x 大于所有已有的结尾，直接追加，序列长度加一
            tails.append(x)
        else:
            # 用更小的数 x 替换，保持 tails 中每个位置的最小结尾
            tails[idx] = x

    # tails 的长度就是最长递增子序列的长度
    return len(tails)
```

#### 复杂度

- **时间复杂度：`O(n log n)`**  
  `n` 次二分查找，每次 `log n`，相当于“每个人只需要找一次位置，找人的速度是对数级的”。  
- **空间复杂度：`O(n)`**  
  只用了 `tails` 一个列表，最坏情况下会保存全部 `n` 个元素。

## 心得

- 这道题的核心技巧是 **「维护最小结尾的递增子序列」**（即耐心排序/二分 DP），它把寻找前驱的线性搜索压缩到对数时间。  
- 该技巧常用于**求最长递增子序列**以及**求最长严格递增子序列的长度**，还有以下类似题目：
  1. **"Maximum Length of Pair Chain"**（把区间视作数对，用相同的贪心+二分思路）  
  2. **"Russian Doll Envelopes"**（二维 LIS，需要先排序再做 LIS）  
  3. **"Number of Longest Increasing Subsequence"**（在 LIS 基础上统计数量，仍可用二分+DP）  
- **一句话总结解题钥匙**：**保持每个长度的递增子序列的最小可能结尾，用二分快速定位更新**。

## 反思

- **第一反应**：看到“最长递增子序列”，立刻想到 DP 的 `dp[i] = max(dp[j]+1)`，于是写出 `O(n²)` 的解法。  
- **最容易踩的坑**：  
  - 忘记 **严格递增** 的要求，导致在二分时使用 `bisect_right`（会把等于的元素也放进去），从而得到错误的长度。  
  - 对空数组或全部相同元素的情况处理不当，可能导致返回 0 而不是 1。  
- **下次遇到同类题**：第一步先问自己“是否可以把状态压缩为‘最小结尾’并用二分搜索？”如果答案是“可以”，就直接走 **耐心排序** 的路线；如果不行，再回到 `O(n²)` DP。
