## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是把 **0 … n** 之间的每个整数都拿出来，逐个数它们里有多少个 `1`，然后把这些计数加在一起。

- **遍历**：把 `0, 1, 2, …, n` 一个一个遍历出来。  
- **计数**：对每个数，把它拆成一位一位的数字（可以把整数转成字符串，也可以用除 10 取余的办法），把出现的 `1` 加到答案里。  
- **返回**：遍历结束后得到的总和就是答案。

> 类比：把一本电话簿从第一页翻到最后一页，逐行检查每个电话号码里是否出现数字 `1`，出现一次就记一分，最后把所有分数相加。

> 为什么一定对？因为我们把 **所有** ≤ n 的数都检查了一遍，漏掉的情况不存在。

#### 代码（Python）

```python
def countDigitOne_bruteforce(n: int) -> int:
    """
    暴力解：遍历 0~n，逐个统计数字 1 的出现次数
    """
    total = 0                     # 最终答案
    for num in range(n + 1):      # 把 0 到 n 都枚举出来
        # 方法一：把整数转成字符串，再逐字符计数
        # total += str(num).count('1')

        # 方法二：不使用字符串，纯数学方式
        x = num
        while x > 0:              # 逐位取出最低位
            if x % 10 == 1:       # 当前位是 1 吗？
                total += 1
            x //= 10              # 去掉最低位，继续检查下一位
    return total
```

#### 复杂度  

- **时间复杂度**：`O(n · d)`，这里的 `d` 是 `n` 的位数（`log10 n + 1`）。  
  - 想象一下你要检查 **1000** 本书，每本书平均有 **3** 页（因为 1000 只有 3 位），总共要翻 **3000** 页，这就是 `n·d` 的含义。  
- **空间复杂度**：`O(1)`，只用了几个整数变量，和 `n` 的大小无关。

> 对于 `n` 最大到 `10⁹`（约 10 亿），`n·d` 会达到 **10⁹ × 10 ≈ 10⁰⁰**，显然跑不完，这就是暴力解的瓶颈。

### 2. 最优解

#### 思路  

从暴力解可以看到，**重复遍历每一位** 是最耗时的地方。我们需要 **一次遍历** 就把所有位的贡献算出来。  
核心想法是：**把每个十进制位（个位、十位、百位…）独立分析**，看在该位上出现 `1` 的次数是怎么受到高位、低位和当前位的影响的。

##### 位置分解

以 `n = 5342` 为例，观察 **十位**（`10¹`）：

```
          高位   当前位   低位
         ┌─────┐ ┌─────┐ ┌─────┐
   5342 = 5   3   4   2
          ↑   ↑   ↑   ↑
        high cur low
```

- `factor = 10ⁱ` 表示当前位的权值（`i = 0` → 1，`i = 1` → 10，…）。  
- `high = n // (factor * 10)`：当前位左边的 **高位**，相当于把当前位及其右边全部删掉。  
- `cur = (n // factor) % 10`：**当前位** 的数字。  
- `low = n % factor`：当前位右边的 **低位**，相当于只保留低位的数。

##### 计数公式

对每一位，`1` 出现的次数取决于 `cur`：

| cur 的取值 | 贡献次数公式                              | 解释 |
|-----------|----------------------------------------|------|
| `0`       | `high * factor`                        | 高位决定了完整的循环次数，每个循环里该位会出现 `factor` 次 `1`。 |
| `1`       | `high * factor + low + 1`              | 除了完整循环的 `high * factor` 次外，还要加上低位的 **实际** 余数 + 1（包括当前位本身为 1 的那一次）。 |
| `2~9`     | `(high + 1) * factor`                  | 高位多加一次完整循环，因为当前位已经大于 1，所有 `1` 都会在本轮循环里出现 `factor` 次。 |

把每一位的贡献累加，就得到答案。整个过程只需要遍历 **位数**（`log10 n`）次。

> 类比：想象你在数一条街上每栋楼的 1 层门牌号出现多少次。先看左边还有几栋楼（`high`），决定了完整的“每 10 栋出现一次 1 层”的循环次数；再看这栋楼本身的层数（`cur`），决定了是否还有额外的 1 层；最后看这栋楼右边还有多少层（`low`），帮助我们算出不完整循环的剩余部分。

##### 步骤概览

1. 初始化 `factor = 1`（从个位开始）。  
2. 当 `factor ≤ n` 时，循环：  
   - 计算 `high, cur, low`。  
   - 根据 `cur` 的值把对应的贡献加到答案。  
   - `factor *= 10`，进入更高一位。  
3. 循环结束，返回答案。

#### 代码（Python）

```python
def countDigitOne(n: int) -> int:
    """
    最优解：按位计数，时间 O(log10 n)，空间 O(1)
    """
    if n <= 0:
        return 0

    total = 0          # 累计所有位上出现 1 的次数
    factor = 1         # 当前位的权值，1 -> 个位，10 -> 十位，...

    while factor <= n:                     # 只要当前位仍在 n 的范围内
        high = n // (factor * 10)           # 左侧高位
        cur = (n // factor) % 10            # 当前位的数字
        low = n % factor                    # 右侧低位

        if cur == 0:
            total += high * factor
        elif cur == 1:
            total += high * factor + low + 1
        else:  # cur >= 2
            total += (high + 1) * factor

        factor *= 10  # 移动到更高一位

    return total
```

#### 复杂度  

- **时间复杂度**：`O(log₁₀ n)`。  
  - 只遍历了数字的每一位，位数大约是 `log10 n`，比如 `n = 10⁹` 只有 10 位，循环 10 次就结束。  
  - 与暴力解的 `O(n·d)` 相比，下降了 **指数级**（从十亿次降到十次）。  
- **空间复杂度**：`O(1)`。  
  - 只用了常数个整数变量 `total、factor、high、cur、low`，不随 `n` 增大而增长。

## 心得

- **核心技巧**：**按位计数**（Digit DP 的一种简化形式），把一个大问题拆成每一位独立的子问题，用数学公式一次性求解。  
- **适用的题型**  
  1. **统计数字出现次数**：如 “Number of Digit One”、 “Number of Digit Two”、 “Count Special Numbers”。  
  2. **求区间内满足某位数条件的整数**：如 “Count Numbers with Unique Digits”、 “Numbers With Repeated Digits”。  
  3. **与进制有关的计数**：如 “Count Numbers with Digit Sum = K”。  
- **一句话总结解题钥匙**：**把十进制位拆开看，每一位的贡献只取决于左侧高位、当前位和右侧低位**。

## 反思

- **第一反应**：直接想到遍历全部数字并计数（暴力解），因为这最符合直觉。  
- **最容易踩的坑**  
  - **溢出**：在某些语言里 `high * factor` 可能超过 32 位整数范围（LeetCode 提示要注意），但 Python 的整数是大数，安全。  
  - **边界条件**：`n = 0` 时直接返回 0，防止进入循环导致错误。  
  - **factor 的循环条件**：必须使用 `while factor <= n`，否则会在 `n = 0` 时进入死循环。  
- **下次遇到同类题**：第一步先**思考“每一位上 1（或其他数字）出现的规律”**，写出 `high、cur、low` 的定义，再推导出对应的计数公式。这样就能快速从暴力思路跳到按位计数的最优解。
