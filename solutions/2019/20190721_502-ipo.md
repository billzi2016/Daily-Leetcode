# #502. IPO / IPO

> 难度：困难 · 标签：Array、Greedy、Sorting、Heap (Priority Queue) · [LeetCode 链接](https://leetcode.com/problems/ipo/)

## 题目（英文原版）

**Description**

Suppose LeetCode will start its IPO soon. In order to sell a good price of its shares to Venture Capital, LeetCode would like to work on some projects to increase its capital before the IPO. Since it has limited resources, it can only finish at most k distinct projects before the IPO. Help LeetCode design the best way to maximize its total capital after finishing at most k distinct projects.
You are given n projects where the ith project has a pure profit profits[i] and a minimum capital of capital[i] is needed to start it.
Initially, you have w capital. When you finish a project, you will obtain its pure profit and the profit will be added to your total capital.
Pick a list of at most k distinct projects from given projects to maximize your final capital, and return the final maximized capital.
The answer is guaranteed to fit in a 32-bit signed integer.

**Examples**

**Example 1:**

```
Input: k = 2, w = 0, profits = [1,2,3], capital = [0,1,1]
Output: 4
Explanation: Since your initial capital is 0, you can only start the project indexed 0.
After finishing it you will obtain profit 1 and your capital becomes 1.
With capital 1, you can either start the project indexed 1 or the project indexed 2.
Since you can choose at most 2 projects, you need to finish the project indexed 2 to get the maximum capital.
Therefore, output the final maximized capital, which is 0 + 1 + 3 = 4.
```

**Example 2:**

```
Input: k = 3, w = 0, profits = [1,2,3], capital = [0,1,2]
Output: 6
```

**Constraints**

- 1 <= k <= 105
- 0 <= w <= 109
- n == profits.length
- n == capital.length
- 1 <= n <= 105
- 0 <= profits[i] <= 104
- 0 <= capital[i] <= 109

## 题目（中文翻译）

假设 LeetCode 即将进行首次公开募股（IPO）。为了以较高的价格向风险投资出售股份，LeetCode 希望在 IPO 前通过开展一些项目来增加其资本。由于资源有限，它至多只能在 IPO 前完成 **k** 个不同的项目。请帮助 LeetCode 设计最优方案，使得在完成至多 **k** 个不同项目后，其总资本最大化。

给定 **n** 个项目，其中第 **i** 个项目的纯利润（pure profit）为 `profits[i]`，启动该项目至少需要的资本（minimum capital）为 `capital[i]`。  
初始时，你拥有 `w` 资本。完成一个项目后，你将获得该项目的纯利润，且利润会加入你的总资本中。

从给定的项目中挑选至多 **k** 个不同的项目，使得最终资本最大，并返回该最大化后的资本。答案保证能够放入 32 位有符号整数中。

**示例 1**  
**输入**: `k = 2, w = 0, profits = [1,2,3], capital = [0,1,1]`  
**输出**: `4`  
**解释**: 由于初始资本为 0，你只能启动索引为 0 的项目。完成后获得利润 1，资本变为 1。此时资本为 1，你可以选择启动索引为 1 或索引为 2 的项目。由于最多只能选择 2 项目，必须完成索引为 2 的项目以获得最大资本。因此，最终资本为 `0 + 1 + 3 = 4`。

**示例 2**  
**输入**: `k = 3, w = 0, profits = [1,2,3], capital = [0,1,2]`  
**输出**: `6`

**约束条件**  
- `1 <= k <= 10^5`  
- `0 <= w <= 10^9`  
- `n == profits.length`  
- `n == capital.length`  
- `1 <= n <= 10^5`  
- `0 <= profits[i] <= 10^4`  
- `0 <= capital[i] <= 10^9`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  
最直接的想法是：**把所有可能的项目组合枚举出来**，然后挑出满足条件（总共不超过 `k` 项、每一步的资金都够启动对应项目）的组合，算出最终的资本，取最大值。

- **数据结构**：我们可以把每个项目视为一张卡片，`profits[i]` 是卡片上的收益，`capital[i]` 是打开这张卡片需要的门票。  
  用 **列表** 存放所有卡片，用 **递归**（或回溯）去尝试“抽”或“不抽”每张卡片。  
  递归的过程就像在超市挑选商品：一次只能挑一件，要么放进购物车，要么不放，挑完后再结账。

- **正确性**：因为我们把**所有**合法的抽卡方式都算了一遍，必然会覆盖最优的那一种，所以答案一定在我们枚举的结果里。

- **时间/空间复杂度**：  
  - 枚举的数量是 `C(n,0) + C(n,1) + … + C(n,k)`，在最坏情况下（`k = n`）就是 `2^n`，相当于 **指数级**，用大白话说就是“即使 n 只有 30，时间也会像宇宙飞船一样慢”。  
  - 递归栈最多保存 `k` 层调用，空间是 **O(k)**，这点还算可以接受。

#### 代码（Python）

```python
from typing import List

def find_max_capital_bruteforce(k: int, w: int,
                                profits: List[int],
                                capital: List[int]) -> int:
    n = len(profits)
    best = w                     # 记录全局最大资本

    # 深度优先搜索：cur_cap 为当前拥有的资本，chosen 为已经挑了多少项目
    def dfs(idx: int, cur_cap: int, chosen: int):
        nonlocal best
        # 选完了 k 项或已经遍历完所有项目，更新答案
        if chosen == k or idx == n:
            best = max(best, cur_cap)
            return

        # 选不选第 idx 项都可以尝试
        # 1. 不选
        dfs(idx + 1, cur_cap, chosen)

        # 2. 选（前提是资本足够）
        if cur_cap >= capital[idx]:
            dfs(idx + 1, cur_cap + profits[idx], chosen + 1)

    dfs(0, w, 0)
    return best
```

> 关键行的中文注释已经写在代码里。可以直接运行，但对 `n` 较大的输入会超时。

#### 复杂度

- **时间复杂度**：`O( C(n,0) + … + C(n,k) )`，最坏情况下约 `O(2^n)`，即指数级增长。  
  大白话：当项目数稍微大一点（比如 30）时，计算时间就会像排队买票一样，排到天亮都不一定结束。

- **空间复杂度**：`O(k)`，因为递归栈最多保存 `k` 层调用。

### 2. 最优解

#### 思路  

从暴力解可以看到，**枚举所有组合太慢**。我们需要找到每一步的“瓶颈”。  
观察题目：

1. 完成一个项目后，只会让资本 **增加**（加上它的纯利润），不会减少。  
2. 以后能做的项目只和“当前拥有的资本”有关，而和**之前选了哪几个**无关。  
3. 因此，在每一次“挑项目”时，只要我们能挑到 **利润最高** 的那个项目，就一定不会让后面的选择变得更差——因为更大的资本只能让我们能够接触到**更多**（而不是更少）后续项目。

于是得到 **贪心** 思路：

- **每一步**，在所有“当前资本足够启动”的项目里，挑 **利润最大的** 那个。
- 为了快速找到“利润最大”的项目，需要一个 **最大堆**（优先队列），把所有可做项目的利润放进去，堆顶就是最大利润。
- 但是我们不能每次都遍历所有项目来判断哪些是“可做的”。  
  解决办法：先把项目按 **所需资本 `capital[i]` 从小到大排序**，这样在资本逐渐增大的过程中，只需要一次线性扫描，就能把新出现的“可做项目”全部加入堆中。

**完整步骤**：

1. 把每个项目表示为 `(capital[i], profits[i])`，并按照 `capital` 升序排列。  
2. 用一个指针 `pos` 指向还未处理的项目。  
3. 重复 `k` 次（或堆已经空了）：
   - 把所有 `capital <= 当前资本 w` 的项目的利润压入 **最大堆**（Python 的 `heapq` 只支持最小堆，取负数实现最大堆）。  
   - 如果堆为空，说明没有任何项目可以继续做，直接跳出循环。  
   - 否则弹出堆顶（最大利润），把它加到 `w` 上。  

这整个过程只遍历了项目一次，并且每次堆操作的代价是 `log n`，所以时间非常快。

#### 代码（Python）

```python
import heapq
from typing import List

def find_max_capital(k: int, w: int,
                    profits: List[int],
                    capital: List[int]) -> int:
    # 1️⃣ 把项目打包并按照所需资本排序
    projects = list(zip(capital, profits))          # (所需资本, 利润)
    projects.sort(key=lambda x: x[0])               # 按资本升序

    max_profit_heap = []    # 用负数实现的最大堆
    pos = 0                 # 指向下一个还未加入堆的项目

    # 2️⃣ 最多进行 k 次投资
    for _ in range(k):
        # 3️⃣ 把当前资本 w 能够启动的所有项目的利润放进堆
        while pos < len(projects) and projects[pos][0] <= w:
            # heapq 只能做最小堆，取负数变成最大堆
            heapq.heappush(max_profit_heap, -projects[pos][1])
            pos += 1

        # 4️⃣ 如果没有任何可做项目，提前结束
        if not max_profit_heap:
            break

        # 5️⃣ 取出利润最大的项目，更新资本
        w += -heapq.heappop(max_profit_heap)   # 取负号恢复原利润

    return w
```

> 关键行已经加上中文注释。直接运行即可通过 LeetCode 的全部测试。

#### 复杂度

- **时间复杂度**：`O(n log n + k log n)`  
  - `n log n` 来自对项目的排序。  
  - 每次把可做项目放进堆或弹出堆顶都要 `log n`，最多进行 `k` 次。  
  - 用大白话说：即使 `n` 有 10⁵，排序只相当于“一趟排队”，后面的堆操作就像“快速找最大”，整体在几秒钟内就能算完。

- **空间复杂度**：`O(n)`  
  - 需要存放所有项目的列表和堆，最坏情况下堆里会装进所有项目的利润。  
  - 与暴力解的指数级空间相比，只是线性增长，完全可接受。

## 心得

- **核心技巧**：**贪心 + 堆（优先队列）**。先把项目按所需资本排序，再用最大堆每次挑利润最大的可做项目。  
- **适用的相似题型**：  
  1. **Find Maximized Capital**（本题的英文原名）。  
  2. **K Closest Points to Origin**（用堆快速取 K 个最近点）。  
  3. **Maximum Profit Scheduling**（在可选区间里挑利润最大的任务）。  
- **一句话总结解题钥匙**：  
  > “每一步都把当前能做的项目中利润最高的挑出来，用堆快速取最大”。

## 反思

- **拿到题目第一反应**：先想“枚举所有项目组合”，因为最直观的就是把每种选法都算一遍。  
- **最容易踩的坑**  
  - 忘记先把项目按所需资本排序，导致每次都要遍历全部项目，时间会爆炸。  
  - 堆为空时仍继续循环，会出现错误或无限循环。  
  - `k` 可能大于项目数，需要在循环里做好提前结束的判断。  
- **下次遇到同类题，第一步该想到**：  
  - “这是一道‘每次挑最优’的题吗？” → 若是，考虑 **贪心 + 优先队列**；  
  - “能否把约束（如资本）转化为一次线性扫描的条件？” → 通过排序把约束“提前筛选”。
