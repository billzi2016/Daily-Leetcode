## 题目（英文原版）

**Description**

Table: Salary
Write a solution to swap all 'f' and 'm' values (i.e., change all 'f' values to 'm' and vice versa) with a single update statement and no intermediate temporary tables.
Note that you must write a single update statement, do not write any select statement for this problem.
The result format is in the following example.

## 题目（中文翻译）

编写一条 **UPDATE** 语句，使 `Salary` 表中所有 `'f'` 与 `'m'` 的值互换（即将所有 `'f'` 改为 `'m'`，所有 `'m'` 改为 `'f'`），要求仅使用单条更新语句且不使用任何临时表。  
注意：本题只能使用 **UPDATE** 语句，禁止使用 **SELECT** 语句。

## 示例

### 示例 1

表结构：

```sql
+-------------+----------+
| Column Name | Type     |
+-------------+----------+
| id          | int      |
| name        | varchar  |
| sex         | ENUM     |
| salary      | int      |
+-------------+----------+
```

- `id` 为主键（唯一值列）。  
- `sex` 列的类型为 **ENUM**（枚举），取值范围为 `('m', 'f')`。  
- 表中存放员工信息。

### 示例 2

**输入**  

`Salary` 表：

```
+----+------+-----+--------+
| id | name | sex | salary |
+----+------+-----+--------+
| 1  | A    | m   | 2500   |
| 2  | B    | f   | 1500   |
| 3  | C    | m   | 5500   |
| 4  | D    | f   | 500    |
+----+------+-----+--------+
```

**输出**  

```
+----+------+-----+--------+
| id | name | sex | salary |
+----+------+-----+--------+
| 1  | A    | f   | 2500   |
| 2  | B    | m   | 1500   |
| 3  | C    | f   | 5500   |
| 4  | D    | m   | 500    |
+----+------+-----+--------+
```

**解释**  
- 第 1 行和第 3 行的 `sex` 从 `'m'` 变为 `'f'`。  
- 第 2 行和第 4 行的 `sex` 从 `'f'` 变为 `'m'`。

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  

最直接的想法是**先把所有 `m` 改成一个临时值**（比如 `'x'`），再把 `f` 改成 `m`，最后把临时值 `'x'` 再改回 `f`。  
这相当于把 **换衣服** 的过程拆成三步：  
1. 把所有穿 **蓝色**（`m`）的同学先换成 **黄色**（`x`）——暂时占位。  
2. 把所有穿 **红色**（`f`）的同学换成 **蓝色**（`m`）。  
3. 把第一步留下的 **黄色**（`x`）再换回 **红色**（`f`）。  

在数据库里，这种做法需要 **三条 UPDATE 语句**，每条语句都遍历一次整张表。  
虽然能够得到正确结果，但 **不符合题目只能使用一条 UPDATE** 的限制。

如果把上面的三步写成 **Python 代码** 来模拟，就会更直观。我们把表格存成 `list[dict]`，逐行修改即可。

#### 代码（Python）

```python
# 模拟 Salary 表，使用 list[dict] 存储每一行数据
salary = [
    {"id": 1, "name": "A", "sex": "m", "salary": 2500},
    {"id": 2, "name": "B", "sex": "f", "salary": 1500},
    {"id": 3, "name": "C", "sex": "m", "salary": 5500},
    {"id": 4, "name": "D", "sex": "f", "salary": 500},
]

# 第一步：把所有 'm' 换成临时值 'x'
for row in salary:
    if row["sex"] == "m":
        row["sex"] = "x"          # 暂时占位

# 第二步：把所有 'f' 换成 'm'
for row in salary:
    if row["sex"] == "f":
        row["sex"] = "m"

# 第三步：把临时值 'x' 换回 'f'
for row in salary:
    if row["sex"] == "x":
        row["sex"] = "f"

# 打印结果，验证是否成功
for r in salary:
    print(r)
```

**运行结果**

```
{'id': 1, 'name': 'A', 'sex': 'f', 'salary': 2500}
{'id': 2, 'name': 'B', 'sex': 'm', 'salary': 1500}
{'id': 3, 'name': 'C', 'sex': 'f', 'salary': 5500}
{'id': 4, 'name': 'D', 'sex': 'm', 'salary': 500}
```

#### 复杂度  

- **时间复杂度**：`O(3·n) = O(n)`，因为我们遍历了 `n` 行三次。这里的 `O(n)` 表示**随着记录数线性增长**，即记录越多，耗时几乎成正比。  
- **空间复杂度**：`O(1)`（不计输入表本身），只用了常数级别的额外变量（临时值 `'x'`）。  

> 虽然时间、空间都不是特别糟糕，但 **题目明确要求只能使用一条 UPDATE**，所以我们需要把这三次遍历合并成一次。

---  

### 2. 最优解  

#### 思路  

从暴力解可以看到，**瓶颈在于遍历表格的次数**——每一次 `UPDATE` 都会让数据库扫描一次整张表。  
如果我们能够在 **同一次遍历** 中同时判断原始值是 `m` 还是 `f`，并直接写出对应的目标值，就可以只用 **一条 UPDATE** 完成全部工作。

SQL 提供了 **`CASE` 表达式**，它类似于 Python 中的三元运算符 `a if condition else b`，可以在同一行代码里根据不同条件返回不同的值。  
我们把 `CASE` 看作 **“多路选择器”**：  
- 当 `sex = 'm'` 时，返回 `'f'`（换成女）  
- 当 `sex = 'f'` 时，返回 `'m'`（换成男）  
- 其它情况（理论上不会出现）保持原值  

于是只需要 **一条 UPDATE**，把 `sex` 列整体改写为 `CASE` 的结果即可。

在 Python 中，我们可以把这条 SQL 语句写成字符串，并用 `sqlite3`（或其他 DB‑API）执行。下面的代码演示了完整的流程：  

1. **创建内存数据库** 并建表、插入示例数据（仅用于演示）。  
2. **执行单条 UPDATE**，内部使用 `CASE` 完成交换。  
3. **查询并打印结果**，验证正确性。  

> **核心技巧**：`CASE WHEN … THEN … ELSE … END` 能在单条语句里实现条件映射，避免多次扫描。

#### 代码（Python）

```python
import sqlite3

# 1️⃣ 创建演示用的内存数据库，并准备 Salary 表
conn = sqlite3.connect(":memory:")          # 使用内存中的临时数据库
cur = conn.cursor()

# 建表，sex 列使用 TEXT（ENUM 在 SQLite 中没有原生实现）
cur.execute("""
CREATE TABLE Salary (
    id INTEGER PRIMARY KEY,
    name TEXT,
    sex TEXT CHECK(sex IN ('m','f')),
    salary INTEGER
);
""")

# 插入示例数据
sample_data = [
    (1, 'A', 'm', 2500),
    (2, 'B', 'f', 1500),
    (3, 'C', 'm', 5500),
    (4, 'D', 'f', 500),
]
cur.executemany("INSERT INTO Salary VALUES (?,?,?,?)", sample_data)
conn.commit()

# 2️⃣ 单条 UPDATE：利用 CASE 同时把 m ↔ f 互换
update_sql = """
UPDATE Salary
SET sex = CASE
            WHEN sex = 'm' THEN 'f'   -- 原来是 m，改成 f
            WHEN sex = 'f' THEN 'm'   -- 原来是 f，改成 m
            ELSE sex                  -- 其它情况保持不变（防御式写法）
          END;
"""
cur.execute(update_sql)
conn.commit()

# 3️⃣ 查询并打印结果，检验是否成功
cur.execute("SELECT id, name, sex, salary FROM Salary ORDER BY id;")
rows = cur.fetchall()
print("更新后的 Salary 表：")
for r in rows:
    print(r)

# 关闭连接
cur.close()
conn.close()
```

**运行结果**

```
更新后的 Salary 表：
(1, 'A', 'f', 2500)
(2, 'B', 'm', 1500)
(3, 'C', 'f', 5500)
(4, 'D', 'm', 500)
```

可以看到，`sex` 列已经在一次遍历中全部完成了互换。

#### 复杂度  

- **时间复杂度**：`O(n)`，只遍历一次表中的 `n` 条记录。相比暴力解的三次遍历，**常数因子从 3 降到了 1**，实际运行更快。  
- **空间复杂度**：`O(1)`，仅使用了极少的临时变量（SQL 引擎内部的工作区），不随记录数增大而增长。

---

## 心得  

- **核心技巧**：`CASE WHEN … THEN … ELSE … END` 在 **UPDATE** 中实现条件映射，能够“一次到位”完成列值的批量替换。  
- **适用场景**：  
  1. **枚举值互换**（如 `status` 从 `'open'` ↔ `'closed'`）。  
  2. **分段映射**（如把分数段映射为等级：`CASE WHEN score>=90 THEN 'A' …`）。  
  3. **统一格式化**（如把日期字符串统一为标准格式）。  
- **一句话总结**：**用 CASE 把“如果‑那么‑否则”写进 UPDATE，省去多次扫描，既简洁又高效。**

---

## 反思  

- **第一反应**：直接写三条 UPDATE（先改成临时值再互换），因为最容易想到“先占位”。  
- **最容易踩的坑**：  
  - 忘记在 `CASE` 里写 `ELSE sex`，导致出现 `NULL`（如果出现了非 `'m'/'f'` 的脏数据）。  
  - 在某些数据库（如 MySQL）里，`ENUM` 类型只能取定义好的取值，直接写 `'x'` 会报错，所以只能使用 `CASE` 而不是临时值。  
- **下次类似题**：第一步先思考 **“能否在一次遍历里把所有条件一次性写完？”**，如果可以，就立刻考虑使用 **CASE** 或 **IF** 等表达式来合并更新。
