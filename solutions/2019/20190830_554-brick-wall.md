# #554. 砖墙 / Brick Wall

> 难度：中等 · 标签：Array、Hash Table · [LeetCode 链接](https://leetcode.com/problems/brick-wall/)

---

## 题目（英文原版）

**Description**

There is a rectangular brick wall in front of you with n rows of bricks. The ith row has some number of bricks each of the same height (i.e., one unit) but they can be of different widths. The total width of each row is the same.
Draw a vertical line from the top to the bottom and cross the least bricks. If your line goes through the edge of a brick, then the brick is not considered as crossed. You cannot draw a line just along one of the two vertical edges of the wall, in which case the line will obviously cross no bricks.
Given the 2D array wall that contains the information about the wall, return the minimum number of crossed bricks after drawing such a vertical line.

**Examples**

**Example 1:**

```
Input: wall = [[1,2,2,1],[3,1,2],[1,3,2],[2,4],[3,1,2],[1,3,1,1]]
Output: 2
```

**Example 2:**

```
Input: wall = [[1],[1],[1]]
Output: 3
```

**Constraints**

- n == wall.length
- 1 <= n <= 104
- 1 <= wall[i].length <= 104
- 1 <= sum(wall[i].length) <= 2 * 104
- sum(wall[i]) is the same for each row i.
- 1 <= wall[i][j] <= 231 - 1

## 题目（中文翻译）

有一面矩形砖墙，包含 **n** 行砖块。第 *i* 行由若干砖块组成，所有砖块的高度相同（即 **1** 单位），但宽度可以不同。每行的总宽度相等。请在墙的顶部到底部画一条垂直线，使其穿过的砖块数量最少。若垂直线恰好经过砖块的边缘，则该砖块不算被穿过。不能将线画在墙的左、右两条垂直边缘上，因为那样显然不会穿过任何砖块。  
给定二维数组 **wall**（其中 `wall[i]` 表示第 *i* 行砖块的宽度序列），返回在画出满足条件的垂直线后，最少会穿过的砖块数。

**示例 1**  
**输入**: `wall = [[1,2,2,1],[3,1,2],[1,3,2],[2,4],[3,1,2],[1,3,1,1]]`  
**输出**: `2`

**示例 2**  
**输入**: `wall = [[1],[1],[1]]`  
**输出**: `3`

**约束条件**

- `n == wall.length`
- `1 <= n <= 10^4`
- `1 <= wall[i].length <= 10^4`
- `1 <= sum(wall[i].length) <= 2 * 10^4`
- 每一行的宽度之和 `sum(wall[i])` 对所有行 *i* 都相同
- `1 <= wall[i][j] <= 2^31 - 1`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

我们先把“画一条竖线”想象成在墙的宽度上挑选一个整数坐标 `x`（从左边的第 1 个单位开始，到最右边的 `total_width-1` 为止，**不能** 选在最左或最右的边缘）。  
对于每一个可能的 `x`，我们把所有行都遍历一遍，判断这条线是否穿过了该行的某块砖：

- **遍历一行**：从左到右累计砖的宽度，直到累计值大于 `x`。  
  - 如果累计值恰好等于 `x`，说明线恰好落在两块砖的接缝上，这块砖 **不算** 被穿过。  
  - 否则累计值第一次超过 `x` 时，说明线穿过了当前这块砖，计数 +1。

把每一行的计数加起来，就是这条线“穿过的砖块数”。遍历完所有可能的 `x`，取最小值即为答案。

> **类比**：把每一行的砖想象成一本书的章节，`x` 是我们在书脊上划的一条线。我们要数出这条线到底划破了多少章节的正文（而不是章节之间的空白）。

> **为什么正确**：我们穷举了所有合法的竖线位置，并且对每一行都精确地判断了是否穿过砖块，所以最小的计数一定是题目要求的答案。

#### 代码（Python）

```python
from typing import List

def least_bricks_bruteforce(wall: List[List[int]]) -> int:
    # 计算整面墙的宽度（每行的总和相同）
    total_width = sum(wall[0])

    # 记录最小的穿过砖块数，初始设为行数（最坏情况每行都穿过一块砖）
    min_cross = len(wall)

    # 可能的切线位置是 1 .. total_width-1（不能在两侧边缘）
    for cut in range(1, total_width):
        crossed = 0                     # 当前 cut 穿过的砖块数
        for row in wall:
            cur = 0                     # 累计当前行已走过的宽度
            for brick in row:
                cur += brick            # 走到下一块砖的右边界
                if cur == cut:         # 正好在砖缝上，当前行不计数，直接结束本行检查
                    break
                if cur > cut:          # 第一次超过 cut，说明这块砖被穿过
                    crossed += 1
                    break
        # 更新全局最小值
        min_cross = min(min_cross, crossed)

    return min_cross
```

> **关键行中文注释** 已写在代码里，帮助初学者一步步跟上思路。

#### 复杂度  

- **时间复杂度**：`O(total_width * n * avg_bricks_per_row)`  
  - 这里的 `total_width` 是墙的总宽度（比如 10），`n` 是行数，`avg_bricks_per_row` 是每行砖块的平均个数。  
  - 用大白话说，就是「我们把每一条可能的竖线都跑一遍，每遍又要把每一行的砖逐个看」，所以会比较慢。

- **空间复杂度**：`O(1)`  
  - 只用了常数级的额外变量（`total_width、min_cross、cut、cur、crossed`），不随输入规模增长。

### 2. 最优解

#### 思路  

从暴力解可以看到，**真正耗时的地方在于对每一个 `cut` 都要遍历整行砖块**。  
实际上，我们不需要去“模拟每条线”，只要统计 **每一个砖缝出现了多少次**，就能直接得到答案。

**关键观察**：

- 竖线如果恰好落在砖缝上，就 **不会** 穿过这行的砖。  
- 因此，**出现次数最多的砖缝**，对应的行数是“可以省掉的穿砖次数”。  
- 最少穿过的砖块数 = 行数 `n` - “出现次数最多的砖缝的行数”。

于是我们只要：

1. 对每一行，累计宽度得到每块砖的 **右边界**（不包括最右边的墙边缘，因为题目不允许在最外侧画线）。  
2. 用哈希表（在 Python 中是 `dict` 或 `collections.Counter`）记录每个右边界出现的次数。  
3. 取出现次数的最大值 `max_edge`（如果没有任何内部边缘，`max_edge = 0`），答案就是 `n - max_edge`。

> **哈希表类比**：想象你在一本词典里查单词，单词是“砖缝位置”，词典页码是“出现的行数”。查一次就能知道这个位置在多少行出现过，省去逐行遍历的麻烦。

#### 代码（Python）

```python
from collections import Counter
from typing import List

def least_bricks(wall: List[List[int]]) -> int:
    """
    返回画一条竖线最少会穿过的砖块数
    """
    edge_counter = Counter()               # 用来统计每个砖缝出现的次数

    for row in wall:
        cur = 0
        # 只统计到倒数第二块砖的右边界，最后一块砖的右边界是整面墙的右侧边缘
        for brick in row[:-1]:
            cur += brick                    # 累计到当前砖的右边缘
            edge_counter[cur] += 1         # 记录这个位置出现了一次

    # 若墙中没有内部砖缝（如每行只有一块砖），max_edge 为 0
    max_edge = max(edge_counter.values(), default=0)

    # 最少穿过的砖块数 = 行数 - 最多出现的砖缝行数
    return len(wall) - max_edge
```

**代码要点解释**：

- `row[:-1]`：排除每行最后一块砖的右边界，因为那是墙的最右边，不能作为切线位置。  
- `Counter` 自动把出现次数累加，省去手写字典的繁琐。  
- `max(..., default=0)` 防止 `edge_counter` 为空（比如所有行只有一块砖），此时答案就是 `len(wall)`。

#### 复杂度  

- **时间复杂度**：`O(total_bricks)`  
  - 我们只遍历了一遍所有砖块（每块砖只算一次），等价于 `O(N)`，其中 `N` 为输入数组中所有整数的总个数。  
  - 与暴力解相比，省掉了对每个可能切线位置的重复遍历。

- **空间复杂度**：`O(distinct_edges)`  
  - 哈希表里最多存放 `total_width-1` 个不同的砖缝位置，最坏情况是 `O(total_width)`，但通常远小于 `N`。  
  - 用大白话说，就是「我们只记下每条可能的切线出现了几次」，额外空间随砖缝种类数增长。

## 心得

- **核心技巧**：**统计砖缝出现次数**（哈希表 / 前缀和思想），把“遍历所有切线”转化为“一次遍历统计”。  
- **适用的题型**：
  1. **“最大重叠区间”**（如 435. Non-overlapping Intervals）——用哈希表统计区间端点出现次数。  
  2. **“数组分割点”**（如 724. Find Pivot Index）——前缀和配合哈希表快速定位。  
  3. **“最小子数组长度”**（如 209. Minimum Size Subarray Sum）——前缀和 + 哈希表帮助在 O(N) 内找到满足条件的子数组。  
- **一句话总结**：**把“每条线都算”改成“每个砖缝计数”，让问题从 O(宽度·行) 降到 O(砖块数)。**

## 反思

- **拿到题目第一反应**：先想遍历所有可能的切线位置，然后逐行检查是否穿砖，直接写出暴力解。  
- **最容易踩的坑**：
  1. **忘记排除最右侧的墙边缘**，导致把非法切线计入统计。  
  2. **边界条件**：所有行只有一块砖时，哈希表为空，需要特殊处理（`default=0`）。  
  3. **整数溢出**：累计宽度可能很大（`≤ 2·10⁴`），在 Python 中不成问题，但在语言限制 tighter 时要注意使用 64 位整数。  
- **下次遇到同类题**，第一步应该先**思考有没有“公共点/公共边”**可以统计，而不是直接遍历所有“可能的切割”。如果能把问题抽象成“统计出现次数”，往往能立刻得到 O(N) 的解法。
