# #343. 整数拆分 / Integer Break

> 难度：中等 · 标签：Math、Dynamic Programming · [LeetCode 链接](https://leetcode.com/problems/integer-break/)

---

## 题目（英文原版）

**Description**

Given an integer n, break it into the sum of k positive integers, where k >= 2, and maximize the product of those integers.
Return the maximum product you can get.

**Examples**

**Example 1:**

```
Input: n = 2
Output: 1
Explanation: 2 = 1 + 1, 1 × 1 = 1.
```

**Example 2:**

```
Input: n = 10
Output: 36
Explanation: 10 = 3 + 3 + 4, 3 × 3 × 4 = 36.
```

**Constraints**

- 2 <= n <= 58

---

## 题目（中文翻译）

给定一个整数（integer）`n`，将其拆分为 `k` 个正整数（positive integers）的和，其中 `k >= 2`，并使这些整数的乘积（product）最大化。返回你能得到的最大乘积。

### 示例 1

**输出**: `1`  
**解释**: `2 = 1 + 1`, `1 × 1 = 1`.

### 示例 2
**输入**: `n = 10`  
**输出**: `36`  
**解释**: `10 = 3 + 3 + 4`, `3 × 3 × 4 = 36`.

## 约束条件

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  

最直接的想法是：把整数 `n` 的所有**可能的拆分**枚举出来，算出每种拆法对应的乘积，取最大的那个。  
- **数据结构**：我们可以用**列表**来保存一次拆分得到的若干正整数，比如 `[3, 3, 4]` 表示 `3 + 3 + 4 = 10`。  
- **类比**：把拆分看成“把一个大苹果切成若干小块”。要找出“切法”使得所有小块体积（乘积）最大，就需要把所有切法都列出来尝试。  
- **正确性**：只要把 **所有** 合法的拆分（每个数 ≥ 1，且拆分的块数 ≥ 2）都遍历一次，就一定能找到最大乘积。  

实现时可以用**递归**：  
1. 从 `1` 开始尝试第一个块的大小 `i`（`i` 必须 ≤ 剩余的数）。  
2. 把剩下的 `n-i` 继续拆分，递归得到它的所有拆法。  
3. 把当前块 `i` 加到子拆法的前面，形成完整的拆分。  

因为 `n` 最多只有 **58**，暴力枚举在理论上是可行的（实际会非常慢），但可以帮助我们理解问题的本质。  

#### 代码（Python）  

```python
def integer_break_brute(n: int) -> int:
    """
    暴力枚举所有拆分方式，返回最大乘积。
    只适合 n 较小的情况，演示思路用。
    """
    # 用来保存全局最大乘积
    max_product = 0

    def dfs(remaining: int, cur_product: int, started: bool):
        """
        remaining : 还剩多少没有拆分的数
        cur_product: 已经选好的块的乘积（中间结果）
        started   : 是否已经选过至少一个块（保证最终至少有两个块）
        """
        nonlocal max_product
        # 当没有剩余数字时，说明得到了一种完整的拆分
        if remaining == 0:
            # 只接受已经选了至少两个块的情况
            if started:
                max_product = max(max_product, cur_product)
            return

        # 这里枚举下一个块的大小 i，i 必须 >=1 且 <= remaining
        for i in range(1, remaining + 1):
            # 若已经选过块了，后面的块可以直接乘进去；
            # 若还没有选块（第一次），我们**不能**把 i 当作唯一的块直接结束，
            # 因为题目要求至少两个块，所以这里把 started 设为 True。
            dfs(remaining - i, cur_product * i, True)

    # 初始调用：remaining=n，乘积从 1 开始（因为乘法的单位元是 1），
    # started=False 表示还没有选块
    dfs(n, 1, False)
    return max_product
```

> **关键行解释**  
> - `dfs` 是深度优先搜索的递归函数，用来遍历所有可能的拆分。  
> - `for i in range(1, remaining + 1)` 相当于“把剩下的苹果切成大小为 i 的一块”。  
> - `cur_product * i` 把新切出的这块加入乘积。  
> - `started` 保证最终至少有两个块（因为第一次递归后立刻把它设为 `True`，但在 `remaining == 0` 时仍要检查）。  

#### 复杂度  

- **时间复杂度**：`O(2^n)`（指数级）。  
  - 想象每个数字 `1..n` 都可以“选”或“不选”，所以可能的拆分数量会随 `n` 指数增长。  
  - 用大白话说，`n` 增加 1，可能的拆法会翻倍左右，算起来非常慢。  
- **空间复杂度**：`O(n)`。  
  - 递归栈的深度最多是 `n`（每次至少减掉 1），所以最多占用 `n` 层栈帧。

### 2. 最优解  

#### 思路  

从暴力解可以看到，**枚举所有拆分**是最慢的环节。我们需要找出一种 **规律**，让我们不必穷举。  

##### 2.1 观察规律  

先手算几个小 `n` 的答案（可以用上面的暴力函数验证）：  

| n | 最优拆分 | 最大乘积 |
|---|----------|----------|
| 2 | 1+1      | 1 |
| 3 | 1+2      | 2 |
| 4 | 2+2      | 4 |
| 5 | 2+3      | 6 |
| 6 | 3+3      | 9 |
| 7 | 3+4      | 12 |
| 8 | 3+3+2    | 18 |
| 9 | 3+3+3    | 27 |
|10 | 3+3+4    | 36 |

可以发现 **“3” 出现得最多**，而且把 `n` 拆成若干个 **3**，剩下的只会是 **2** 或 **4**（因为 4 = 2+2，乘积不变）。  

##### 2.2 为什么要尽量用 3？  

设想我们已经把 `n` 拆成若干个整数，假设其中有一个块 `a ≥ 5`。我们可以把它换成 `a-3` 与 `3` 两块：

```
原乘积 : … * a * …
新乘积 : … * (a-3) * 3 * …
```

比较两者：

```
(a-3) * 3  = 3a - 9
a          = a
```

因为 `a ≥ 5`，有 `3a - 9 > a`（举例：5 → 2*3=6 >5，6 → 3*3=9 >6，...），所以 **把大的块分解成 3 和剩余部分会让乘积更大**。  
同理，如果出现 `4`，我们不再拆成 `2+2`（乘积不变），但 **不要出现 1**，因为 `1` 乘任何数都不增加乘积，反而浪费了一个块。

因此，**最优拆分只会用 3 和 2**，而且 **3 的数量尽可能多**。  

##### 2.3 具体拆法  

1. **把 n 除以 3**，得到商 `quotient = n // 3`（表示可以使用多少个 3）  
2. **余数 `remainder = n % 3`** 有三种情况  
   - `remainder == 0`：全用 3，乘积 = `3^quotient`  
   - `remainder == 1`：如果直接把 1 留下来，会得到一个乘积为 1 的块，显然不好。我们把 **一个 3** 拿出来和 1 合成 **4**（即 2+2），乘积不变但更好。于是乘积 = `3^(quotient-1) * 4`。  
   - `remainder == 2`：直接把 2 留下，乘积 = `3^quotient * 2`。  

> **特殊处理**  
> - 当 `n` 本身很小（2、3）时，上面的公式会出现 `quotient-1` 为负数或 0，需要单独返回已知答案：`n=2 → 1`，`n=3 → 2`（因为题目要求至少拆成两块）。  

##### 2.4 动态规划（另一种思路）  

如果不想直接套公式，也可以用 **DP**：  
- `dp[i]` 表示把整数 `i` 拆成至少两块后的最大乘积。  
- 对每个 `i`，枚举第一个块的大小 `j (1 ≤ j < i)`，然后有两种选择：  
  1. **不再拆**：`j * (i-j)`  
  2. **继续拆**：`j * dp[i-j]`（因为 `i-j` 还能继续拆）  
- 取最大值作为 `dp[i]`。  

时间复杂度 `O(n^2)`，空间 `O(n)`，对 `n ≤ 58` 完全可接受，但仍不如 O(n) 的数学公式简洁。这里我们主要给出 **数学公式**（O(n)）作为最优解。  

#### 代码（Python）  

```python
def integer_break(n: int) -> int:
    """
    O(n) 的最优解：只用 3 和 2 来构造最大乘积。
    适用于 2 <= n <= 58（题目限制）。
    """
    # 小于等于 3 的特殊情况，需要满足“至少拆成两块”
    if n == 2:
        return 1          # 2 = 1 + 1
    if n == 3:
        return 2          # 3 = 1 + 2，乘积 2

    # 计算可以使用多少个 3
    quotient, remainder = divmod(n, 3)

    if remainder == 0:
        # 全部都是 3
        return 3 ** quotient
    elif remainder == 1:
        # 把一个 3 拿出来凑成 4（2+2），避免出现乘 1 的情况
        # 此时需要至少保留一个 3，故 quotient-1
        return 3 ** (quotient - 1) * 4
    else:  # remainder == 2
        # 直接把剩下的 2 加进乘积
        return 3 ** quotient * 2
```

> **关键行解释**  
> - `divmod(n, 3)` 同时得到商和余数，类似“把 n 分成若干个 3，剩下的叫 remainder”。  
> - `3 ** quotient` 用 **指数** 表示“3 的 quotient 次方”，相当于把 `quotient` 个 3 相乘。  
> - 当余数为 1 时，我们把一个 3 拿走（`quotient-1`），把 3+1 合成 4，乘积变为 `4 * 3^(quotient-1)`。  

#### 复杂度  

- **时间复杂度**：`O(1)`（常数时间）或 `O(n)`（如果把指数运算看作 O(log n) 的乘法次数，仍然极快）。  
  - 用大白话说：不管 `n` 多大，我们只做几次算术运算，几乎不花时间。  
- **空间复杂度**：`O(1)`（只用了几个整数变量），几乎不占额外内存。

## 心得  

- **核心技巧**：**把整数拆成若干个 3（或 2）**，利用**数学归纳**和**局部最优 ⇒ 全局最优**的思想。  
- **适用的题型**：  
  1. “最大乘积划分” 类似的题目，如 LeetCode 343 *Integer Break*（本题）。  
  2. “划分为若干块使和或乘积最大” 的变体，例如 “分割回文子串的最少次数”。  
  3. “使用固定大小的块（如 3）来逼近目标值” 的动态规划或贪心题。  
- **一句话总结解题钥匙**：**让每一块尽可能接近 3，避免出现 1**。

## 反思  

- **第一反应**：立刻想到 **暴力枚举**，因为最直观的办法就是把所有拆法列出来。  
- **最容易踩的坑**：  
  - 忘记题目要求 **至少拆成两块**，导致 `n=2`、`n=3` 的答案错误。  
  - 余数为 1 时没有把一个 3 合并成 4，直接乘以 1，导致乘积不够大。  
  - 在实现指数 `3 ** quotient` 时，如果 `quotient` 为 0（如 `n=4`）要确保不出现 `3 ** -1` 的情况。  
- **下次遇到同类题**，第一步应该先 **做小范围实验**（比如 n=5~10），**观察规律**，再决定是用 **贪心** 还是 **动态规划**。
