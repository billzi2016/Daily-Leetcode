# #678. 有效的括号字符串 / Valid Parenthesis String

> 难度：中等 · 标签：String、Dynamic Programming、Stack、Greedy · [LeetCode 链接](https://leetcode.com/problems/valid-parenthesis-string/)

---

## 题目（英文原版）

**Description**

Given a string s containing only three types of characters: '(', ')' and '*', return true if s is valid.
The following rules define a valid string:

**Examples**

**Example 1:**

```
Input: s = "()"
Output: true
```

**Example 2:**

```
Input: s = "(*)"
Output: true
```

**Example 3:**

```
Input: s = "(*))"
Output: true
```

**Constraints**

- 1 <= s.length <= 100
- s[i] is '(', ')' or '*'.

---

**输出**: `true`

**示例 2**

**输出**: `true`

**示例 3**

**输出**: `true`

- `1 <= s.length <= 100`  
- `s[i]` 为 `'('`、`')'` 或 `'*'`。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

这道题的难点在于字符 `*` 可以有三种“身份”：  
- 当成左括号 `(`  
- 当成右括号 `)`  
- 当成空字符（相当于直接删掉）

如果把每个 `*` 的三种取值都枚举一遍，就可以得到所有可能的“真实”字符串。  
随后，只要检查这些字符串中有没有一种满足「左括号数量永远不小于右括号，且最后左括号数为 0」的合法括号序列，就返回 `True`。

> **类比**：把 `*` 想成一本有三页的书，读者可以任选其中一页阅读。我们把所有可能的阅读顺序（即所有组合）列出来，然后逐一检验哪一种阅读后故事是完整的。

**为什么正确**  
因为题目本身就说：只要存在 *一种* 把 `*` 替换成 `(`、`)`、空串后，使得整个字符串合法，就算整体合法。枚举所有可能必然不会漏掉这唯一的合法方案。

**复杂度分析**  
设 `k` 为字符串中 `*` 的个数。每个 `*` 有 3 种选择，所有组合数是 `3^k`。  
- **时间复杂度**：`O(3^k * n)`，其中 `n` 为字符串长度。`3^k` 是指数级增长，`n` 用来检查每个生成的字符串是否合法。  
- **空间复杂度**：`O(k)`，递归栈的深度最多等于 `*` 的数量。

> **大白话**：如果有 5 个星号，可能的组合有 `3^5 = 243` 种，算起来已经不少了；如果是 10 个星号，就会爆炸到 `59049` 种，几乎不可能在限制时间内跑完。

#### 代码（Python）

```python
def check_valid(s: str) -> bool:
    """
    检查一个只包含 '(' 和 ')' 的字符串是否是合法的括号序列。
    """
    balance = 0                     # 左括号的净数量
    for ch in s:
        if ch == '(':
            balance += 1
        else:                       # ch == ')'
            balance -= 1
            if balance < 0:         # 右括号多于左括号，直接不合法
                return False
    return balance == 0             # 最终左括号必须全部匹配

def backtrack(s: str, idx: int, cur: list) -> bool:
    """
    递归枚举所有 * 的取值。
    idx   : 当前处理到原字符串的下标
    cur   : 已经决定好的字符列表（只包含 '(' 和 ')'）
    """
    if idx == len(s):
        # 完全遍历后，检查生成的字符串是否合法
        return check_valid(''.join(cur))

    if s[idx] == '*':
        # 1) 当成 '('
        cur.append('(')
        if backtrack(s, idx + 1, cur):
            return True
        cur.pop()

        # 2) 当成 ')'
        cur.append(')')
        if backtrack(s, idx + 1, cur):
            return True
        cur.pop()

        # 3) 当成空字符
        if backtrack(s, idx + 1, cur):
            return True
        # 三条路都不行，返回 False
        return False
    else:
        # 普通括号直接放进去
        cur.append(s[idx])
        res = backtrack(s, idx + 1, cur)
        cur.pop()
        return res

def checkValidString_bruteforce(s: str) -> bool:
    """
    入口函数，调用回溯枚举。
    """
    return backtrack(s, 0, [])
```

#### 复杂度

- **时间复杂度**：`O(3^k * n)`  
  解释：`k` 为 `*` 的数量，`3^k` 是所有可能的组合数，每个组合要遍历一次字符串（长度 `n`）来检查合法性。

- **空间复杂度**：`O(k + n)`  
  解释：递归栈深度为 `k`，`cur` 列表最多保存 `n` 个字符（实际最多 `n`），两者同阶。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **指数级的枚举**。我们需要一种只遍历一次字符串、且不显式枚举 `*` 所有取值的方法。

观察 `*` 的三种含义，可以把它当成“可以随意增减平衡值的灵活砖块”。  
如果我们只关心 **左括号的净数量**（记作 `balance`），则：

- 遇到 `'('`，`balance` 必然加 1（左括号多了）。
- 遇到 `')'`，`balance` 必然减 1（需要一个左括号来匹配）。
- 遇到 `'*'`，我们既可以把它当成 `'('`（让 `balance` 加 1），也可以当成 `')'`（让 `balance` 减 1），还可以当成空串（`balance` 不变）。  
  换句话说，`*` 能让 `balance` **在一个区间** 内自由变动。

因此我们可以维护两个变量：

- `low`  – 当前可能的最小净左括号数（把所有 `*` 当成 `')'` 或空）。
- `high` – 当前可能的最大净左括号数（把所有 `*` 当成 `'('`）。

遍历字符时：

| 当前字符 | low 的更新 | high 的更新 |
|----------|-----------|-------------|
| `'('`    | `low += 1`| `high += 1` |
| `')'`    | `low -= 1`| `high -= 1` |
| `'*'`    | `low -= 1`（把它当成 `')'`）| `high += 1`（把它当成 `'('`）|

**关键点**：

1. `low` 不能小于 0，因为左括号的净数不可能为负（如果出现负数，说明即使把所有 `*` 当成左括号也抵消不了多余的右括号）。所以每步把 `low = max(low, 0)`。
2. 如果遍历过程中 `high` 变为负数，说明即使把所有 `*` 当成左括号也不足以抵消右括号，此时直接返回 `False`。
3. 最后遍历结束，只要 `low == 0`（即存在一种取值让净左括号数恰好为 0），字符串就合法。

> **类比**：把 `low`、`high` 想成两根绳子，`low` 是最短可能的绳子（最保守），`high` 是最长可能的绳子（最激进）。只要两根绳子在遍历结束时仍能相遇（`low` 能到 0），就说明我们可以把 `*` 调整到恰好把两根绳子拉到同一点——即合法。

这个贪心思路只需要一次遍历，时间线性，空间常数。

#### 代码（Python）

```python
def checkValidString(s: str) -> bool:
    """
    贪心 + 双区间法，只遍历一次字符串。
    low  : 可能的最小左括号净数
    high : 可能的最大左括号净数
    """
    low, high = 0, 0          # 初始化区间为 [0, 0]

    for ch in s:
        if ch == '(':
            low += 1          # 最小值也必须加 1
            high += 1         # 最大值也加 1
        elif ch == ')':
            low -= 1          # 最小值尝试减 1
            high -= 1         # 最大值也减 1
        else:  # ch == '*'
            low -= 1          # 把 * 当成 ')'，最小值减 1
            high += 1         # 把 * 当成 '('，最大值加 1

        # low 不能小于 0，负数说明左括号已经被多余的右括号抵消完了
        if low < 0:
            low = 0

        # high < 0 说明即使所有 * 都当成 '('，也抵消不了右括号，直接返回 False
        if high < 0:
            return False

    # 遍历结束时，只要最小可能的左括号数能回到 0，说明存在合法取值
    return low == 0
```

#### 复杂度

- **时间复杂度**：`O(n)`  
  只需要一次线性扫描，每个字符做常数次操作。相比暴力的 `3^k`，速度提升巨大。

- **空间复杂度**：`O(1)`  
  只使用了两个整数变量 `low`、`high`，与字符串长度无关。

## 心得

- **核心技巧**：把 `*` 看成“可增可减的弹性括号”，用 **区间（low / high）** 来维护所有可能的左括号净数，进而实现一次遍历的贪心判断。
- **适用的题型**：
  1. **带通配符的括号匹配**（如本题、`Valid Parenthesis String` 的变体）。
  2. **可以取多种意义的字符**（例如 `?` 可以是 `'('` 或 `')'` 的题目）。
  3. **需要判断是否存在一种合法排列**（如 “字符串是否能被翻转成回文” 之类的 “存在性” 问题）。
- **一句话总结**：`*` 的灵活性可以用 **最小/最大可能的左括号数** 来压缩搜索空间，做到线性时间。

## 反思

- **第一反应**：把 `*` 的三种取值全枚举，用回溯/DFS 检查所有可能。虽然思路直接，但马上意识到会爆炸。
- **最容易踩的坑**：
  - 忽略 `low` 负数的修正，导致错误地认为已经不合法（实际可以通过把后面的 `*` 当成左括号来补救）。
  - 只维护 `high` 而不检查 `low`，会出现 “即使有足够的左括号，也可能因为多余的右括号而不合法” 的误判。
  - 边界情况：全部是 `*`（如 `"***"`）应返回 `True`，因为可以全部当成空串。
- **下次类似题的第一步**：先思考“是否可以把可变字符抽象为一个取值区间”，如果可以，就尝试用 **区间/双指针/计数** 的贪心方式，一遍遍历完成判断。
