## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：把 `s` 按空格切成单词列表 `words`，然后**逐个**比较 `pattern` 中的字符和 `words` 中的单词是否能够一一对应。  
如果出现下面两种冲突，就说明不满足题意：

1. 同一个字符对应了不同的单词。  
2. 两个不同的字符对应了同一个单词（因为要求是**双射**，即一一映射）。

实现上可以不使用任何额外的数据结构，而是每次都**遍历整个列表**去检查这两条规则——这就是“暴力”。  
把字符和单词的对应关系想象成 **查字典**：字符是词，单词是页码。这里我们不真正建字典，而是每次都去**线性搜索**，所以时间会比较慢。

> 为什么这个方法一定能得到正确答案？  
> 因为我们把所有可能的冲突都检查了一遍，只要没有冲突，说明每个字符恰好对应唯一的单词，满足双射的定义。

#### 代码（Python）

```python
def wordPattern(pattern: str, s: str) -> bool:
    # 1. 把 s 按空格切成单词列表
    words = s.split()
    # 长度不相等直接返回 False
    if len(pattern) != len(words):
        return False

    # 2. 逐个检查对应关系（暴力遍历）
    for i in range(len(pattern)):
        ch = pattern[i]      # 当前字符
        w = words[i]         # 当前单词

        # 检查“同一个字符对应了不同的单词”
        # 在之前的所有位置里，若出现相同字符却对应了不同单词，就冲突
        for j in range(i):
            if pattern[j] == ch and words[j] != w:
                return False

        # 检查“不同字符对应了同一个单词”
        # 在之前的所有位置里，若出现不同字符却对应了相同单词，也冲突
        for j in range(i):
            if pattern[j] != ch and words[j] == w:
                return False

    # 没有冲突，返回 True
    return True
```

#### 复杂度  

- **时间复杂度**：`O(n²)`（其中 `n = len(pattern)`）。  
  每个字符都要遍历它之前的所有字符来检查冲突，最坏情况下会进行 `1 + 2 + … + (n‑1) ≈ n²/2` 次比较。  
  用大白话说，就是如果有 1000 个字符，需要检查大约 500 000 次，这显然不够高效。

- **空间复杂度**：`O(1)`。  
  只用了常数级别的额外空间（几个临时变量），不随输入规模增长。

### 2. 最优解

#### 思路  

从暴力解可以看出，**瓶颈在于每次都要线性扫描** 前面已经遍历过的字符来判断冲突。  
实际上，只要我们能够**“记住”**已经建立好的映射关系，就可以在 **O(1)** 时间内完成检查。  

这正好可以用 **哈希表（字典）** 来实现：

1. 建立两个字典  
   - `char_to_word`：键是 `pattern` 中的字符，值是对应的单词。  
   - `word_to_char`：键是单词，值是对应的字符。  
   两个字典一起维护可以确保**双射**：  
   - 当我们看到一个新字符‑单词对时，检查两个字典里是否已经出现冲突。  
   - 若已经出现相同的映射，则继续；若出现不一致的映射，立即返回 `False`。

2. 同时遍历 `pattern` 与 `words`（通过 `zip`），每一步只做 O(1) 的字典查询/插入。  

> 类比：字典就像一本 **词典**，我们把字符当作“单词”，把实际单词当作“页码”。查找一次只需要翻到对应的页码，时间是常数级的。

#### 代码（Python）

```python
def wordPattern(pattern: str, s: str) -> bool:
    # 1. 把 s 切成单词列表
    words = s.split()
    # 长度不相等直接返回 False
    if len(pattern) != len(words):
        return False

    # 2. 用两个哈希表维护双向映射
    char_to_word = {}   # pattern 中字符 -> s 中单词
    word_to_char = {}   # s 中单词 -> pattern 中字符

    # 3. 同时遍历两个序列
    for ch, w in zip(pattern, words):
        # 检查字符 -> 单词 的映射
        if ch in char_to_word:
            if char_to_word[ch] != w:   # 已有映射但不相等，冲突
                return False
        else:
            char_to_word[ch] = w        # 建立新映射

        # 检查单词 -> 字符 的映射（保证双射）
        if w in word_to_char:
            if word_to_char[w] != ch:   # 已有映射但不相等，冲突
                return False
        else:
            word_to_char[w] = ch        # 建立新映射

    # 所有位置都没有冲突，返回 True
    return True
```

#### 复杂度  

- **时间复杂度**：`O(n)`（`n = len(pattern)`）。  
  我们只遍历一次，每次的字典查询/插入都是 **常数时间**，所以整体线性。相比暴力的 `O(n²)`，快了很多——如果有 1000 个字符，只需要大约 1000 次操作。

- **空间复杂度**：`O(m)`（`m` 为不同字符或单词的数量，最多不超过 `n`）。  
  需要额外的哈希表来存储映射关系，最坏情况下每个字符和单词都不相同，空间使用约为 `2 * n` 个条目。

## 心得

- 这道题的核心技巧是 **使用哈希表维护双向映射**，保证字符与单词之间形成 **双射**（一一对应）。
- 类似需要“互相唯一映射”的题型还有  
  1. **Isomorphic Strings**（判断两个字符串是否同构）  
  2. **Find and Replace Pattern**（在一组单词中找出符合模式的）  
  3. **Valid Sudoku**（每行、列、宫必须唯一）  
- 一句话总结解题钥匙：**“用两张字典表把双向对应关系锁住，冲突即返回 False”。**

## 反思

- **第一反应**：把 `s` 切成单词，逐个比较 `pattern` 与单词是否一一对应。
- **最容易踩的坑**  
  - 忽略 `pattern` 与 `words` 长度不一致的情况。  
  - 只检查 `char → word` 的映射而忘记 `word → char`，会导致 `a` 与 `b` 同时映射到同一个单词却不被发现。  
  - 对输入字符串的分割要使用 `split()`，否则会把多个空格误当成单词。
- **下次遇到同类题**，第一步应该想到：**“是否可以用哈希表把元素之间的对应关系记录下来？”**，随后检查双向唯一性即可。
