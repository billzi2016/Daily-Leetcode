# #287. 寻找重复的数字 / Find the Duplicate Number

> 难度：中等 · 标签：Array、Two Pointers、Binary Search、Bit Manipulation · [LeetCode 链接](https://leetcode.com/problems/find-the-duplicate-number/)

---

## 题目（英文原版）

**Description**

Given an array of integers nums containing n + 1 integers where each integer is in the range [1, n] inclusive.
There is only one repeated number in nums, return this repeated number.
You must solve the problem without modifying the array nums and using only constant extra space.
Follow up:

**Examples**

**Example 1:**

```
Input: nums = [1,3,4,2,2]
Output: 2
```

**Example 2:**

```
Input: nums = [3,1,3,4,2]
Output: 3
```

**Example 3:**

```
Input: nums = [3,3,3,3,3]
Output: 3
```

**Constraints**

- 1 <= n <= 105
- nums.length == n + 1
- 1 <= nums[i] <= n
- All the integers in nums appear only once except for precisely one integer which appears two or more times.

## 题目（中文翻译）

给定一个整数数组（array）`nums`，其中包含 `n + 1` 个整数，且每个整数的取值范围为 `[1, n]`（含端点）。数组中仅存在唯一的一个重复数字，返回该重复数字。要求在 **不修改数组 `nums`** 的前提下，并且仅使用 **常数额外空间（constant extra space）** 来解决此问题。  

**示例 1**  
输入: `nums = [1,3,4,2,2]`  
输出: `2`  

**示例 2**  
输入: `nums = [3,1,3,4,2]`  
输出: `3`  

**示例 3**  
输入: `nums = [3,3,3,3,3]`  
输出: `3`  

**约束条件**  
- `1 <= n <= 10^5`  
- `nums.length == n + 1`  
- `1 <= nums[i] <= n`  
- 除唯一的重复数字外，`nums` 中的其他整数均只出现一次，且该重复数字出现两次或更多次。  

**进阶**  
（可进一步思考在满足上述限制的情况下，使用二分查找、快慢指针（Floyd’s Tortoise and Hare）等方法找到重复数字。）

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**逐个检查**每个数字在数组中出现了多少次，只要发现出现两次的数字就返回。  
可以把数组想象成一本**电话簿**，我们要把每个人的号码（数组元素）和“出现的次数”对应起来。  
为此我们可以使用 **哈希表（字典）**，它的工作方式类似于**查字典**：  
- **key** 就是电话号码（这里是数组中的数），  
- **value** 是这号出现的次数。  

遍历数组一次，把每个数记进去；如果在插入时发现这个数已经在字典里了，说明它是重复的，直接返回。  

> 这种做法之所以**正确**，是因为题目保证只有一个数字会出现多次，只要我们在遍历过程中捕获到第一次出现重复的时刻，就一定找到了答案。

#### 代码（Python）

```python
def findDuplicate(nums):
    """暴力解——使用哈希表记录出现次数"""
    seen = {}                     # 用字典充当“出现次数表”
    for num in nums:              # 逐个遍历数组
        if num in seen:           # 如果已经记录过，说明重复
            return num
        seen[num] = 1             # 第一次出现，记下来
    # 根据题目约束，这里一定能提前返回，不会走到下面
    return -1
```

#### 复杂度  

- **时间复杂度**：**O(n)**  
  - “O(n)”的意思是**遍历一次数组**，每个元素只看一次，和数组长度成正比。  
- **空间复杂度**：**O(n)**  
  - 需要额外的字典来存放已经出现过的数字，最坏情况下要存 `n` 个不同的数字，空间随输入规模线性增长。

### 2. 最优解

#### 思路  

从暴力解出发，**瓶颈**在于我们用了额外的 `O(n)` 空间。  
题目要求 **“不修改数组且只使用常数额外空间”**，于是我们必须寻找一种只利用 **已有信息**（数组本身）而不额外开辟大量空间的方法。

观察题目：  

- 数组长度是 `n + 1`，而元素值的取值范围是 `[1, n]`。  
- 把每个数看作指向 **下标** 的指针，例如 `nums[i] = 3` 可以解释为 “从位置 `i` 向前跳到位置 `3`”。  
- 这样一来，整个数组就形成了一张 **有向图**，每个节点（下标）指向另一个节点（值对应的下标）。  
- 因为元素总数比可能的下标多 1，**必然会出现环**（像链表里出现的环），而环里唯一的节点就是重复的数字。

这正好和 **链表环检测** 的经典算法——**Floyd 的龟兔赛跑（Tortoise and Hare）** 相同。  
算法分两步：

1. **寻找环内的相遇点**  
   - 龟速指针一次走一步，兔速指针一次走两步。  
   - 因为有环，快指针一定会在环里追上慢指针。  

2. **定位环入口**（也就是重复的数字）  
   - 将慢指针重新放回起点（下标 `0`），快指针保持在相遇点。  
   - 两指针再以相同速度前进，第一次相遇的节点即为环入口，也就是重复的数。

> 这里不需要额外的数组或哈希表，只是把数组本身当成“指针”，所以空间是 **O(1)**。遍历过程最多两次完整的数组长度，时间是 **O(n)**。

#### 代码（Python）

```python
def findDuplicate(nums):
    """Floyd 龟兔赛跑——常数空间找环入口"""
    # 1️⃣ 第一步：寻找相遇点
    tortoise = nums[0]          # 龟：一次走一步
    hare = nums[0]              # 兔：一次走两步
    while True:
        tortoise = nums[tortoise]          # 龟走一步
        hare = nums[nums[hare]]            # 兔走两步
        if tortoise == hare:               # 相遇了，跳出循环
            break

    # 2️⃣ 第二步：找环入口（重复数字）
    tortoise = nums[0]          # 龟重新回到起点
    while tortoise != hare:     # 同速前进，第一次相遇即为答案
        tortoise = nums[tortoise]
        hare = nums[hare]

    return hare                 # 或者返回 tortoise，值相同
```

#### 复杂度  

- **时间复杂度**：**O(n)**  
  - “O(n)” 表示**线性时间**：虽然有两段循环，但每段最多遍历 `n` 次，总体仍然和数组长度成正比。  
  - 与暴力解相比，时间上没有提升（同为线性），但**空间**大幅下降。  

- **空间复杂度**：**O(1)**  
  - 只用了几个指针变量（`tortoise`、`hare`），不随输入规模增长，满足“常数额外空间”的要求。

## 心得

- **核心技巧**：把数组视作指针形成的有向图，利用 **环检测**（Floyd 龟兔赛跑）在 **常数空间** 内定位重复元素。  
- **适用场景**：  
  1. “寻找数组中的重复数字且不破坏数组”——本题。  
  2. “链表中找环入口”——经典的环检测问题。  
  3. “数组中存在唯一的 “入口” 或 “出路”，利用指针跳转定位”——如 “寻找数组中的第一个缺失正数” 的变体（需要稍作改造）。  
- **一句话总结**：**把重复数字想象成环的入口，使用龟兔赛跑在指针图里找环即可。**

## 反思

- **第一反应**：想到用哈希表或集合直接记录出现次数，代码简单但占用 O(n) 空间。  
- **最容易踩的坑**：  
  - 忘记**不能修改数组**，所以不能把元素标记为负数或交换位置。  
  - 在实现 Floyd 算法时，如果把起点写成 `0` 而不是 `nums[0]`，会导致无限循环。  
  - 没考虑到**全部相同的情况**（如 `[3,3,3,3,3]`），但算法同样适用。  
- **下次遇到同类题**，第一步应该问自己：**“是否可以把数组当成指针形成的结构？”** 如果答案是“是”，就可以尝试 **环检测** 或 **二分计数** 等常数空间的技巧。
