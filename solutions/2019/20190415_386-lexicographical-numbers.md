# #386. Lexicographical Numbers / Lexicographical Numbers

## 题目（英文原版）

**Description**

Given an integer n, return all the numbers in the range [1, n] sorted in lexicographical order.
You must write an algorithm that runs in O(n) time and uses O(1) extra space.

**Examples**

**Example 1:**

```
Input: n = 13
Output: [1,10,11,12,13,2,3,4,5,6,7,8,9]
```

**Example 2:**

```
Input: n = 2
Output: [1,2]
```

**Constraints**

- 1 <= n <= 5 * 104

## 题目（中文翻译）

给定一个整数 `n`，返回区间 `[1, n]` 内的所有整数，按照字典序（lexicographical order）排序。

要求编写的算法时间复杂度为 **O(n)**，且使用 **O(1)** 的额外空间。

**约束条件**

- `1 <= n <= 5 * 10^4`

**示例**

**示例 1**  
输入: `n = 13`  
输出: `[1,10,11,12,13,2,3,4,5,6,7,8,9]`

**示例 2**  
输入: `n = 2`  
输出: `[1,2]`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是把 `1 … n` 的所有整数全部放进一个列表，然后让 Python 自带的排序函数 `sorted` 按**字典序**（lexicographical order）排好序再返回。  
这里涉及的唯一数据结构是 **列表**（list），它就像一本装有若干页码的笔记本，顺序存放元素，支持快速遍历。  

为什么会得到正确答案？  
- Python 的字符串比较本身就是字典序，比如 `'10' < '2'` 为 `True`，因为比较时是从左到右逐字符比较的。
- 把整数转成字符串再比较，就等价于题目要求的“按字典序排列”。

#### 代码（Python）

```python
def lexicalOrder_brute(n: int) -> list[int]:
    """
    暴力解：把 1~n 全部放进列表，转成字符串后排序，再转回整数返回
    """
    # 1. 生成所有整数
    nums = list(range(1, n + 1))          # [1, 2, ..., n]

    # 2. 按字典序排序（先转成字符串比较）
    nums.sort(key=lambda x: str(x))      # key 函数把每个整数变成字符串

    # 3. 直接返回已排好序的列表
    return nums
```

#### 复杂度

- **时间复杂度**：`O(n log n)`  
  解释：我们要对 `n` 个数排序，普通比较排序的时间是 `n log n`（对数 `log` 只是一种“每次把问题规模减半”的意思），所以整体是 `O(n log n)`，比线性 `O(n)` 稍慢。

- **空间复杂度**：`O(n)`  
  解释：需要存放 `1 … n` 的全部整数以及排序时临时的辅助空间，整体用到的额外空间和 `n` 成正比。

---

### 2. 最优解

#### 思路  

从暴力解可以看出，**真正的瓶颈在排序**。如果我们能直接按照字典序“遍历”所有合法的数字，就不需要再排序，时间自然能降到 `O(n)`。  
下面一步步推导出这种遍历方式：

1. **把数字看成一棵字典树（Trie）**  
   - 根节点是空的，第一层的子节点是 `1, 2, …, 9`（因为数字不能以 `0` 开头）。  
   - 每个节点 `x` 再向下可以衍生出 `x*10, x*10+1, …, x*10+9`（即在后面加一位）。  
   - 这棵树的先序遍历（先访问根，再访问左子树，最后右子树）恰好产生字典序。

2. **利用“下一位”公式**  
   对当前数字 `cur`，有两种“下一步”的走法：
   - **向下走**：如果 `cur * 10 <= n`，则下一个应该是 `cur*10`（在当前数字后面再加一个 `0`，相当于进入左子树的最左节点）。
   - **向右走**：否则尝试右移一位，即 `cur + 1`（相当于同层的下一个兄弟），但要保证 `cur % 10 != 9` 且 `cur + 1 <= n`。  
   - **回溯**：如果已经到达层级的最右端（`cur % 10 == 9` 或 `cur + 1 > n`），就需要**回到父节点**，再右移一次——这可以通过 `cur //= 10` 然后 `cur += 1` 完成，直到找到合法的右兄弟。

3. **只用常数级额外空间**  
   - 整个过程只维护一个当前数字 `cur`，以及结果列表（题目要求的输出本身不算额外空间），没有递归栈或额外的哈希表。

下面给出两种实现方式：**递归 DFS**（更直观）和 **迭代版**（严格 O(1) 额外空间）。这里重点讲解迭代版，因为它最符合题目“使用 O(1) 额外空间”的要求。

#### 代码（Python）

```python
def lexicalOrder(n: int) -> list[int]:
    """
    最优解：模拟字典树的先序遍历，只用 O(1) 额外空间。
    思路：
    1. 从 1 开始，把当前数字 cur 放入答案。
    2. 若 cur*10 <= n，向下走（进入左子树的最左节点）。
    3. 否则若 cur%10 != 9 且 cur+1 <= n，向右走（同层的下一个兄弟）。
    4. 否则回溯到父节点并尝试右移，直到找到合法的右兄弟或回到根节点。
    重复上述过程直至答案长度达到 n。
    """
    ans = []
    cur = 1                     # 从最小的合法数字 1 开始

    while len(ans) < n:
        ans.append(cur)         # 访问当前节点（相当于先序遍历的 "visit"）

        # 1) 尝试向下走：在 cur 后面再加一位 0
        if cur * 10 <= n:
            cur *= 10
        else:
            # 2) 不能向下走时，尝试右移（同层的下一个数字）
            #   但若 cur 已经是 9 或者右移会超过 n，需要回溯
            if cur % 10 != 9 and cur + 1 <= n:
                cur += 1
            else:
                # 3) 需要回到父节点再尝试右移
                #    先把 cur 除以 10（去掉最右边一位），
                #    再检查是否还能右移
                while cur // 10 and (cur % 10 == 9 or cur + 1 > n):
                    cur //= 10          # 向上回溯
                cur = cur // 10 + 1 if cur // 10 else n + 1  # 若已经回到根且仍不可右移，结束循环
    return ans
```

> **代码说明**（每行关键中文注释已在代码中给出）  
> - `cur * 10 <= n`：判断是否还能在当前数字后面再加一位 `0`，相当于进入左子树的最左节点。  
> - `cur % 10 != 9`：保证当前数字不是同层的最右端（如 `19`、`29`），因为这些数字右边已经没有兄弟了。  
> - `while cur // 10 and (cur % 10 == 9 or cur + 1 > n):`：不断向上回溯，直到找到可以右移的父节点。  
> - 循环结束的条件是答案列表已收集到 `n` 个数字。

#### 复杂度

- **时间复杂度**：`O(n)`  
  解释：每一次 `while` 循环都恰好产生一个新的数字，循环总次数等于答案长度 `n`，所以整体是线性时间。这里的“遍历每个数字一次”可以想象成在字典树里一次一次走访，走到哪儿就记下来，一共走 `n` 步。

- **空间复杂度**：`O(1)`（不计输出列表）  
  解释：算法只用了几个整数变量 `cur`、`ans`（输出本身）和临时的循环计数器，没有使用递归栈、哈希表或额外的数组。因此额外空间是常数级的。

## 心得

- **核心技巧**：把数字视作字典树的节点，利用“向下、向右、回溯”三步走完字典序的先序遍历。  
- **适用的题型**  
  1. **字典序输出**（如 LeetCode 386 本题）。  
  2. **遍历所有满足某种前缀约束的数**（如 “Kth Smallest in Lexicographical Order”）。  
  3. **利用前缀树（Trie）实现的搜索/排序**（如自动补全、单词搜索）。  
- **一句话总结**：**把“字典序”想象成一棵树的先序遍历，只需不停向下加 0、向右加 1、回溯到父节点，就能在 O(n) 时间、O(1) 空间内完成。**

## 反思

- **第一反应**：直接把所有数字放进数组排序——最自然但不满足 O(n) 要求。  
- **最容易踩的坑**  
  - 忘记处理 `cur` 为 `9` 或者右移会超过 `n` 的情况，导致死循环。  
  - 在回溯时没有把 `cur` 重新除以 10，导致一直停在同一个层级。  
  - 当 `n` 很大时（如 `5 * 10⁴`），暴力排序的时间会明显超时。  
- **下次遇到同类题**：第一步先**画出数字的字典树**，思考“怎么只走一次就遍历完”。若能把遍历过程写成“向下 → 向右 → 回溯”，基本就找到了 O(n) 的解法。
