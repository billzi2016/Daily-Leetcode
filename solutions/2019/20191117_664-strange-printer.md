# #664. 奇怪的打印机 / Strange Printer

> 难度：困难 · 标签：String、Dynamic Programming · [LeetCode 链接](https://leetcode.com/problems/strange-printer/)

---

## 题目（英文原版）

**Description**

There is a strange printer with the following two special properties:
Given a string s, return the minimum number of turns the printer needed to print it.

**Examples**

**Example 1:**

```
Input: s = "aaabbb"
Output: 2
Explanation: Print "aaa" first and then print "bbb".
```

**Example 2:**

```
Input: s = "aba"
Output: 2
Explanation: Print "aaa" first and then print "b" from the second place of the string, which will cover the existing character 'a'.
```

**Constraints**

- 1 <= s.length <= 100
- s consists of lowercase English letters.

---

## 题目（中文翻译）

有一种奇怪的打印机，具有以下两个特殊属性：

给定一个字符串 `s`，返回打印机打印该字符串所需的最少回合数（turns）。

**示例 1**  
**输入**: `s = "aaabbb"`  
**输出**: `2`  
**解释**: 先打印 `"aaa"`，然后再打印 `"bbb"`。

**示例 2**  
**输入**: `s = "aba"`  
**输出**: `2`  
**解释**: 先打印 `"aaa"`，随后在字符串的第二个位置打印 `"b"`，这会覆盖原来的字符 `'a'`。

**约束条件**  
- `1 <= s.length <= 100`  
- `s` 仅由小写英文字母组成。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把打印过程想成“把字符串一次次地涂颜色”。  
我们可以递归地枚举**每一次打印的范围**（即一次操作可以把任意连续子串全部变成同一个字符），然后把剩下的部分继续打印，直到整个字符串全部出现为止。  

- **数据结构**：只需要一个普通的递归函数，返回把 `s[l…r]` 打印完需要的最少次数。递归的参数 `l, r` 像是 **字典** 的“查找范围”，`l` 是左边界，`r` 是右边界。
- **正确性**：因为我们尝试了**所有可能的第一次打印区间**，随后对剩余的子问题继续采用相同的枚举方式，必然会覆盖所有合法的打印顺序，最小的那个就是答案。

> 这相当于把问题的解空间全部遍历了一遍，就像在森林里把每一条可能的路径都走一遍，最后挑出最短的那条。

#### 代码（Python）

```python
def strangePrinter_bruteforce(s: str) -> int:
    """
    暴力递归：尝试所有可能的第一次打印区间
    """
    from functools import lru_cache

    @lru_cache(None)                     # 记忆化，防止重复计算
    def dfs(l: int, r: int) -> int:
        if l > r:                         # 空串不需要打印
            return 0
        # 最差情况：每个字符单独打印一次
        ans = r - l + 1

        # 枚举第一次打印的右端点 k（左端点固定为 l）
        for k in range(l, r + 1):
            # 第一次把 s[l…k] 全部打印成 s[l]（假设），
            # 之后再处理剩下的两段
            left = dfs(l + 1, k)          # l+1~k 里如果有跟 s[l] 相同的字符可以省一次
            right = dfs(k + 1, r)         # k+1~r 继续打印
            ans = min(ans, 1 + left + right)

        return ans

    return dfs(0, len(s) - 1)
```

> **关键点**：  
> - `lru_cache` 相当于给递归“装了记事本”，把已经算过的 `(l,r)` 结果保存下来，避免重复劳动。  
> - `ans = r - l + 1` 表示最坏情况：每个字符都单独打印一次。

#### 复杂度

- **时间复杂度**：`O(2^n)`（指数级）。因为每次递归都要在 `[l, r]` 区间里挑选一个切分点 `k`，相当于把问题二分成两个子问题，整个递归树的节点数近似于 2 的 n 次方。  
  > 大白话：如果字符串长度是 20，可能要尝试的方案多到几千万，普通电脑根本跑不完。
- **空间复杂度**：`O(n)`，递归栈最深为 `n`（字符串的长度），再加上记忆化表的大小 `O(n^2)`（每个区间最多记一次），总体仍然是多项式级别的。

### 2. 最优解

#### 思路  

暴力解的**瓶颈**在于它把所有可能的切分都枚举了一遍，导致指数级的时间。  
观察打印过程可以发现：

1. **相同字符可以合并**  
   如果在一次打印中把字符 `c` 打在位置 `i`，以后只要在同一次打印里还能覆盖到其他位置的 `c`，就不需要再额外打印一次。换句话说，**相同字符之间可以共享一次打印**。

2. **区间子问题**  
   打印过程只和**连续子串**有关。我们可以把原问题拆成「把 `s[i…j]` 打印完需要几次」的子问题，这正好适合**动态规划**（DP）。

3. **递推公式**  
   - 设 `dp[i][j]` 为打印子串 `s[i…j]`（含两端）所需的最少次数。  
   - **基础**：单个字符显然只需要一次，`dp[i][i] = 1`。  
   - **转移**：先把 `s[i…j-1]` 打完，再单独打印 `s[j]`，得到 `dp[i][j] = dp[i][j-1] + 1`。  
   - 但是如果在 `i…j-1` 区间里出现了和 `s[j]` 相同的字符 `s[k] (i ≤ k < j)`，我们可以在打印 `s[k]` 时顺便把 `s[j]` 也覆盖进去，这样就省掉一次单独打印。于是可以尝试所有 `k`，取最小值：

\[
dp[i][j] = \min\bigl(dp[i][j-1] + 1,\;
                        \min_{i \le k < j,\;s[k]=s[j]} \bigl(dp[i][k] + dp[k+1][j-1]\bigr)\bigr)
\]

   - 直观理解：把 `s[j]` 和左边的相同字符 `s[k]` 合并打印，左半段 `i…k` 按正常方式打印，右半段 `k+1…j-1` 再打印一次（因为 `s[j]` 已经被左边的打印覆盖了）。

4. **计算顺序**  
   `dp[i][j]` 只依赖于更短的区间（长度 `< j-i+1`），所以我们按**子串长度**从小到大填表即可。

5. **复杂度**  
   - 三层循环：外层遍历子串长度 `len`（`1…n`），中层遍历左端点 `i`，内层遍历可能的合并点 `k`。时间 `O(n^3)`，空间 `O(n^2)`。  
   - 对于 `n ≤ 100` 的约束，这已经足够快。

#### 代码（Python）

```python
def strangePrinter(s: str) -> int:
    """
    动态规划解法，时间 O(n^3)，空间 O(n^2)
    """
    n = len(s)
    if n == 0:
        return 0

    # dp[i][j] 表示打印 s[i..j] 所需的最少次数
    dp = [[0] * n for _ in range(n)]

    # 长度为 1 的子串，只需要一次打印
    for i in range(n):
        dp[i][i] = 1

    # 按子串长度从短到长枚举
    for length in range(2, n + 1):          # 子串长度 2~n
        for i in range(n - length + 1):    # 左端点
            j = i + length - 1              # 右端点
            # 初始方案：把 s[i..j-1] 打完后，再单独打印 s[j]
            dp[i][j] = dp[i][j - 1] + 1

            # 尝试把 s[j] 合并到左边相同字符的位置 k
            for k in range(i, j):
                if s[k] == s[j]:
                    # 合并后，左半段 i..k 按正常打印，右半段 k+1..j-1 再打印一次
                    # 当 k+1 > j-1 时，右半段为空，取 0
                    right = dp[k + 1][j - 1] if k + 1 <= j - 1 else 0
                    dp[i][j] = min(dp[i][j], dp[i][k] + right)

    return dp[0][n - 1]
```

> **代码要点注释**  
> - `dp[i][i] = 1`：单字符只需一次。  
> - `dp[i][j] = dp[i][j-1] + 1`：先把左边全部打印，再单独处理最右侧字符。  
> - `if s[k] == s[j]`：只有相同字符才能共享一次打印。  
> - `right = dp[k+1][j-1] if k+1 <= j-1 else 0`：处理右半段可能为空的情况，避免索引错误。

#### 复杂度

- **时间复杂度**：`O(n^3)`。  
  > 对于长度 100 的字符串，最多进行 `100³ = 1,000,000` 次内部循环，现代电脑几毫秒即可完成。相比暴力的指数级时间，这已经是天壤之别了。

- **空间复杂度**：`O(n^2)`。  
  > 需要一个 `n × n` 的二维表来存每个子区间的答案，`100 × 100 = 10,000` 个整数，几乎可以忽略不计。

## 心得

- **核心技巧**：利用「相同字符可以合并打印」的性质，构造**区间动态规划**。  
- **适用的题型**  
  1. 「染色」类问题：如 **刷子涂颜色**（`Brush`）  
  2. 「删除相同字符」类问题：如 **删除字符串中的相同子串**（`Remove Boxes`）  
  3. 「区间合并」类问题：如 **最少回文分割**（`Palindrome Partitioning II`）  
- **解题钥匙**：**找出可以共享一次操作的相同元素**，并把整个问题拆成「子区间」的子问题。

## 反思

- **第一反应**：直接想「把每一次打印当成一次遍历，枚举所有可能的切分」——这就是暴力递归。  
- **最容易踩的坑**  
  - 忽略**空区间**的处理，导致 `dp[k+1][j-1]` 越界。  
  - 没有记忆化或 DP 表，导致时间爆炸。  
  - 对于相同字符的合并，只考虑了最左侧一次，实际需要遍历所有可能的 `k`。  
- **下次遇到同类题**，第一步应该：  
  > **“能否把整体问题拆成若干子区间，且子区间之间的最优解可以组合得到整体最优？”**  
  若答案是肯定的，就尝试区间 DP 或者记忆化搜索。
