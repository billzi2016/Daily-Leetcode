## 题目（英文原版）

**Description**

There is only one character 'A' on the screen of a notepad. You can perform one of two operations on this notepad for each step:
Given an integer n, return the minimum number of operations to get the character 'A' exactly n times on the screen.

**Examples**

**Example 1:**

```
Input: n = 3
Output: 3
Explanation: Initially, we have one character 'A'.
In step 1, we use Copy All operation.
In step 2, we use Paste operation to get 'AA'.
In step 3, we use Paste operation to get 'AAA'.
```

**Example 2:**

```
Input: n = 1
Output: 0
```

**Constraints**

- 1 <= n <= 1000

## 题目（中文翻译）

在记事本的屏幕上最初只有一个字符 `'A'`。每一步你可以对记事本执行以下两种操作之一：

- **复制全部（Copy All）**：将当前屏幕上的所有字符复制到剪贴板。
- **粘贴（Paste）**：将剪贴板中的内容粘贴到屏幕末尾。

给定整数 `n`，返回恰好在屏幕上得到 `n` 个字符 `'A'` 所需的最少操作次数。

**示例 1**  
**输入**: `n = 3`  
**输出**: `3`  
**解释**: 初始时，屏幕上有一个字符 `'A'`。  
1. 第一步，使用 **复制全部（Copy All）**。  
2. 第二步，使用 **粘贴（Paste）**，得到 `'AA'`。  
3. 第三步，使用 **粘贴（Paste）**，得到 `'AAA'`。

**示例 2**  
**输入**: `n = 1`  
**输出**: `0`

**约束条件**  
- `1 <= n <= 1000`

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  
最直接的想法是**把所有可能的操作序列枚举出来**，看看哪一种能恰好得到 `n` 个 `'A'`，并且用的步骤最少。  

- **状态**：当前屏幕上的 `'A'` 数目 `cnt`，以及剪贴板里的 `'A'` 数目 `clip`。  
- **可选操作**  
  1. **Copy All**：把屏幕上的全部字符复制到剪贴板。相当于把 `cnt` 的值拷贝到 `clip`，这一步本身不产生新的 `'A'`。  
  2. **Paste**：把剪贴板里的内容粘贴到屏幕上，即 `cnt += clip`。这一步会让 `'A'` 的数量增加。  

这和生活中“复制文件到U盘、再粘贴到电脑”的过程一样：**剪贴板就像一个小仓库，存放我们一次性可以粘贴的字符数**。

我们可以用 **深度优先搜索（DFS）** 或 **广度优先搜索（BFS）** 从初始状态 `(cnt=1, clip=0)` 开始遍历，每走一步记录已经用了多少次操作，直到 `cnt == n` 为止。遍历过程中若 `cnt` 已经超过 `n`，就可以剪枝（因为再粘贴只会让它更大），同理如果 `clip == 0`（还没复制过），就不能执行粘贴操作。

> 为什么这个方法一定能找到答案？  
> 因为我们把所有合法的操作序列都穷举了，只要有一种序列能在 `k` 步内得到 `n` 个 `'A'`，搜索一定会在第 `k` 步时发现它。

**复杂度分析（大白话）**  
- 每一步都有最多 **两种选择**（复制或粘贴），所以搜索树的分支因子是 2。  
- 为了得到 `n` 个 `'A'`，最坏情况下可能要进行接近 `n` 步（每步只粘贴一个字符）。于是搜索树的高度约为 `n`，总节点数大约是 `2^n`。  
- 因此时间复杂度是 **指数级**，记作 `O(2^n)`，这在 `n` 达到 20 以上时就已经不可接受了。  
- 我们只需要保存当前的 `(cnt, clip, steps)` 三个整数，空间复杂度是 `O(n)`（递归栈深度最多 `n`）。

#### 代码（Python）  

```python
from collections import deque

def minSteps_bruteforce(n: int) -> int:
    """
    暴力 BFS：最先到达 cnt == n 的层数即为最少操作次数
    """
    # 队列里存 (cnt, clip, steps)
    q = deque()
    q.append((1, 0, 0))          # 初始只有一个 A，剪贴板为空，已用 0 步
    visited = set()             # 防止重复状态

    while q:
        cnt, clip, steps = q.popleft()
        # 已经得到目标
        if cnt == n:
            return steps

        # 剪枝：已经超过目标不再继续
        if cnt > n:
            continue

        # 1) Copy All：把屏幕全部复制到剪贴板
        #   只要这个状态没出现过就入队
        if (cnt, cnt) not in visited:
            visited.add((cnt, cnt))
            q.append((cnt, cnt, steps + 1))

        # 2) Paste：只能在剪贴板非空时粘贴
        if clip > 0 and (cnt + clip, clip) not in visited:
            visited.add((cnt + clip, clip))
            q.append((cnt + clip, clip, steps + 1))

    # 根据题意 n >= 1，总能找到答案，这行理论上不会被执行
    return -1
```

#### 复杂度  

- **时间复杂度**：`O(2^n)` —— 每一步最多分成两条路，搜索树呈指数增长。  
- **空间复杂度**：`O(n)` —— BFS 队列和 visited 集合里最多存 `n` 层的状态。

### 2. 最优解  

#### 思路  

从暴力解可以看到，**瓶颈在于盲目地尝试所有操作顺序**。实际上，得到 `n` 个 `'A'` 的过程可以用**因数分解**来描述：

1. 假设我们已经有了 `k` 个 `'A'`（`k` 是某个中间状态），接下来想要把它变成 `k * m`（`m ≥ 2`）个 `'A'`。  
2. 要实现 `k → k*m`，最经济的做法是：  
   - **一次 Copy All** 把 `k` 复制到剪贴板（花 1 步）。  
   - **连续 Paste m‑1 次**，每次把剪贴板的 `k` 粘贴上去（再花 `m‑1` 步）。  
   - 于是把 `k` 变成 `k*m` 需要 `1 + (m‑1) = m` 步。  

这说明：**如果我们把 `n` 分解为若干个因子 `m1, m2, …, mk`（从小到大），总步数就是这些因子的和**。  

> 举个例子：`n = 9 = 3 × 3`  
> - 先把 `1 → 3`（复制一次，粘贴两次）需要 3 步。  
> - 再把 `3 → 9`（再复制一次，粘贴两次）又需要 3 步。  
> - 总共 6 步，等价于 `3 + 3`（因子之和）。  

所以，**求最少操作次数 = 把 `n` 分解成若干因子，使这些因子之和最小**。  

最小的因子和恰好是把 `n` **拆成质因数**（素数）的和。因为：

- 任何合数 `ab`（`a, b ≥ 2`）都可以继续拆成 `a` 和 `b` 的质因数，`a + b` 永远不小于 `a` 的所有质因数之和加上 `b` 的所有质因数之和。  
- 质因数分解是唯一的（不计顺序），所以把 `n` 拆成质因数的和一定是最小的。

**因此，答案就是 `n` 所有质因数（包括重复）的和**。  

如果不想直接做质因数分解，也可以用**动态规划**：  

- `dp[i]` 表示得到 `i` 个 `'A'` 最少需要的操作数。  
- 初始化 `dp[1] = 0`（已经有 1 个，不需要操作）。  
- 对每个 `i`，遍历它的所有因子 `j (2 ≤ j ≤ sqrt(i))`，如果 `i % j == 0`，说明可以先得到 `i / j`，再通过一次复制加 `j-1` 次粘贴得到 `i`，即  
  `dp[i] = min(dp[i], dp[i // j] + j)`。  
- 当 `i` 没有除 `2` 之外的因子时（即 `i` 为质数），只能一次复制一次粘贴 `i` 次，等价于 `dp[i] = i`，这正好是把 `i` 当作质因数加入答案的过程。  

下面给出两种实现：**质因数分解版**（更简洁）和 **DP 版**（思路更接近动态规划的定义）。

#### 代码（Python）  

##### 方法一：质因数分解（最简洁）  

```python
def minSteps(n: int) -> int:
    """
    把 n 拆成质因数之和，即为最少操作次数。
    思路：不断除以最小的质因数，累加该因数。
    """
    ans = 0
    d = 2                     # 从最小的可能因数开始尝试
    while d * d <= n:         # 只需要检查到 sqrt(n)
        while n % d == 0:     # 若 d 能整除 n，就把它作为一个因子取走
            ans += d          # 累加因子（相当于一次复制 + (d-1) 次粘贴）
            n //= d           # 把已取走的因子从 n 中除去
        d += 1                 # 继续尝试下一个可能的因子
    # 循环结束后，如果 n > 1，说明剩下的 n 本身是一个质数
    if n > 1:
        ans += n
    return ans
```

##### 方法二：动态规划（更贴近 DP 思想）  

```python
def minSteps_dp(n: int) -> int:
    """
    dp[i] = min_{j|i, j>1} (dp[i // j] + j)
    其中 j 表示一次复制后粘贴的次数（即因子）。
    """
    dp = [0] * (n + 1)          # dp[0]、dp[1] 都是 0，dp[1] 表示已经有 1 个 A
    for i in range(2, n + 1):
        dp[i] = i               # 最坏情况：全部一步一步粘贴（相当于 i 次操作）
        j = 2
        while j * j <= i:
            if i % j == 0:      # j 是 i 的因子
                # 先得到 i//j，然后一次复制 + (j-1) 次粘贴，共 j 步
                dp[i] = min(dp[i], dp[i // j] + j)
                # 同时考虑对应的另一个因子 i//j
                other = i // j
                dp[i] = min(dp[i], dp[other] + j)
            j += 1
    return dp[n]
```

两种实现的返回值完全相同，时间上质因数分解版更快（约 `O(√n)`），而 DP 版更直观地展示了“子问题 + 合并” 的思想。

#### 复杂度  

- **时间复杂度**（质因数分解版）：`O(√n)`  
  - 我们最多遍历到 `√n`，每次除尽后 `n` 会被显著缩小。  
  - 用大白话说，就是如果 `n = 1000`，只需要检查到 31 左右的数，几乎可以在瞬间算完。  

- **空间复杂度**：`O(1)`（只用了几个整数变量）  

- **时间复杂度**（DP 版）：`O(n √n)`  
  - 外层遍历 `1 … n`，内层最多遍历到 `√i`。相比暴力的指数级，这已经是多项式时间，能轻松处理 `n ≤ 1000` 的限制。  

- **空间复杂度**（DP 版）：`O(n)` 用于保存 `dp` 数组。

## 心得  

- **核心技巧**：把“复制‑粘贴”过程抽象为**因子分解**，最少步数等价于质因数之和。  
- **适用的题型**  
  1. “最少操作次数使数字变为目标”类（如 *Minimum Operations to Reduce X to Zero*）。  
  2. “把数字拆成若干因子求和最小”类（如 *Integer Break*）。  
  3. 需要**利用因子或约数的递推关系**的动态规划题目。  
- **一句话总结解题钥匙**：**把每一次 “复制 + 多次粘贴” 看作一次乘法，把整个过程拆成乘法链，最优链就是 n 的质因数分解**。

## 反思  

- **第一反应**：看到“复制、粘贴”，第一时间想到 BFS 暴力搜索——因为这两步像是“状态转移”。  
- **最容易踩的坑**  
  - 忘记对 **`n = 1`** 的特殊处理，直接返回 0。  
  - 在 BFS/DFS 中没有做好“已访问状态”的去重，导致指数级爆炸。  
  - 在因子分解时遗漏了 **`n` 本身是质数** 的情况（循环结束后要再加一次 `n`）。  
- **下次类似题的第一步**：**先思考是否可以把操作抽象为乘法/加法的组合**，找出递推关系（如“复制一次 + 粘贴 k 次” = 乘以 `k+1`），再判断是否能用**因子分解**或**DP** 来求最小代价。
