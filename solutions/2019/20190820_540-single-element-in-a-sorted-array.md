# #540. 排序数组中的唯一元素 / Single Element in a Sorted Array

> 难度：中等 · 标签：Array、Binary Search · [LeetCode 链接](https://leetcode.com/problems/single-element-in-a-sorted-array/)

---

## 题目（英文原版）

**Description**

You are given a sorted array consisting of only integers where every element appears exactly twice, except for one element which appears exactly once.
Return the single element that appears only once.
Your solution must run in O(log n) time and O(1) space.

**Examples**

**Example 1:**

```
Input: nums = [1,1,2,3,3,4,4,8,8]
Output: 2
```

**Example 2:**

```
Input: nums = [3,3,7,7,10,11,11]
Output: 10
```

**Constraints**

- 1 <= nums.length <= 105
- 0 <= nums[i] <= 105

---

## 题目（中文翻译）

给定一个已排序的整数数组，其中每个元素恰好出现两次，只有 **一个** 元素只出现一次。  
返回这个只出现一次的元素。  
你的解法必须在 **O(log n)** 时间和 **O(1)** 额外空间内完成。

## 示例

### 示例 1
**输入:** `nums = [1,1,2,3,3,4,4,8,8]`  
**输出:** `2`

### 示例 2
**输入:** `nums = [3,3,7,7,10,11,11]`  
**输出:** `10`

## 约束条件
- `1 <= nums.length <= 10^5`
- `0 <= nums[i] <= 10^5`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的办法就是把数组从头遍历一遍，**把每个数出现的次数记下来**，然后找出只出现一次的那个数。  
- **数据结构**：这里可以使用「哈希表」来统计出现次数。哈希表可以类比为一本「查字典」的工具，单词（key）对应的页码（value）就是出现的次数。  
- **正确性**：因为题目保证除了唯一的那个元素外，其他元素一定恰好出现两次，所以只要把每个元素的出现次数统计完整，找到次数为 1 的元素即为答案。  

#### 代码（Python）

```python
def singleNonDuplicate(nums):
    # 使用字典统计出现次数，类似查字典
    count = {}
    for x in nums:                # 遍历每个元素
        if x in count:
            count[x] += 1        # 已经出现过，次数+1
        else:
            count[x] = 1        # 第一次出现，次数设为1

    # 再遍历字典，找出只出现一次的键
    for key, freq in count.items():
        if freq == 1:            # 只出现一次的就是答案
            return key
```

#### 复杂度  

- **时间复杂度**：`O(n)`  
  解释：我们需要遍历整个数组一次（`n` 次）来统计次数，再遍历哈希表（最多 `n/2+1` 项）找唯一元素，整体仍然是线性时间。  
- **空间复杂度**：`O(n)`  
  解释：最坏情况下（唯一元素在数组末尾），哈希表会存储几乎所有不同的数，大约需要 `n/2` 个键值对，空间随输入规模线性增长。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于 **需要额外的 O(n) 空间**，而题目要求 **O(1) 额外空间** 并且 **时间 O(log n)**，这暗示我们应该利用 **二分查找**（Binary Search）来加速。

观察已排好序的数组，除了唯一的那个数外，**每对相同的数一定是相邻出现**。如果把数组的下标也考虑进去，会发现：

- 在唯一元素左侧（即唯一元素之前），**成对的两个相同元素的下标一定是一奇一偶**，且**偶数下标的元素等于其下一个奇数下标的元素**。  
  例子：`[1,1,2,2,3,3]` → 下标 `0‑1`、`2‑3`、`4‑5` 都满足 `nums[i] == nums[i+1]`（i 为偶数）。
- 当唯一元素出现后，**配对的顺序会整体向右错位**，此时**偶数下标的元素等于其前一个奇数下标的元素**。  
  例子：`[1,1,2,3,3,4]`，唯一元素是 `2`（下标 2），左侧配对正常，右侧配对变为 `3` 在下标 3、4（奇‑偶），`4` 在下标 5。

利用这一特性，我们可以做二分查找：

1. 取中间下标 `mid`。如果 `mid` 是奇数，就把它减一，使 `mid` 成为偶数（方便比较 `mid` 与 `mid+1`）。
2. 检查 `nums[mid]` 与 `nums[mid+1]` 是否相等  
   - 相等 → 说明 **唯一元素在右半边**（因为左边的配对都是完整的），把搜索区间左边界移到 `mid+2`。  
   - 不相等 → 说明 **唯一元素在左半边或就是 `mid` 本身**，把右边界移到 `mid`。  
3. 循环直到左边界等于右边界，返回该位置的元素。

整个过程每次都把搜索区间大小减半，符合 O(log n) 的时间要求，并且只用了常数级的额外变量（左、右指针），满足 O(1) 空间。

#### 代码（Python）

```python
def singleNonDuplicate(nums):
    """
    使用二分查找在 O(log n) 时间、O(1) 空间内找到唯一元素。
    """
    left, right = 0, len(nums) - 1          # 初始搜索区间

    while left < right:                     # 当区间长度大于 1 时继续
        mid = (left + right) // 2           # 取中间下标

        # 为了配对比较，保证 mid 为偶数
        if mid % 2 == 1:                     # 若是奇数下标
            mid -= 1                         # 向左移动一位，使其变偶

        # 检查 mid 与其下一个元素是否相等（配对是否完整）
        if nums[mid] == nums[mid + 1]:
            # 配对完整，唯一元素一定在右半边
            left = mid + 2                  # 左边界跳过这对元素
        else:
            # 配对被打断，唯一元素在左半边或就是 mid
            right = mid                     # 收缩右边界到 mid

    # 循环结束时 left == right，指向唯一元素
    return nums[left]
```

#### 复杂度  

- **时间复杂度**：`O(log n)`  
  解释：每一次循环都把搜索区间长度减半（类似找书时每次把书架对半分），所以最多只需要对数级的比较次数。相比暴力的 `O(n)`，这就像从走遍整个图书馆变成只用几步就能定位到目标书。  
- **空间复杂度**：`O(1)`  
  解释：只用了几个整数变量（`left、right、mid`），不随输入规模增长，符合常数空间要求。

## 心得

- **核心技巧**：利用「成对出现」的规律，将数组的索引奇偶性与配对状态对应起来，从而在二分搜索中判断唯一元素所在的半边。  
- **适用题型**：  
  1. “寻找唯一出现一次的数” 类似题（如 **Single Element in a Sorted Array**）。  
  2. “有序数组中出现一次的元素” 变体（如 **Find Minimum in Rotated Sorted Array**，利用有序性质二分定位）。  
  3. “数组中出现 k 次，找出现一次的元素” 的扩展（需要根据出现次数的奇偶性设计判定规则）。  
- **一句话总结**：**把“配对是否完整”转化为二分的左/右判断，即可在 O(log n) 内锁定唯一元素**。

## 反思

- **第一反应**：直接想到哈希表计数或遍历比较，忽略了题目对时间/空间的严格限制。  
- **最容易踩的坑**：  
  - 忘记把 `mid` 调整为偶数，导致比较错位（`mid` 为奇数时直接比较 `mid` 与 `mid+1` 会跨配对）。  
  - 边界条件处理不当，如数组长度为 1 时直接返回；或者在循环结束后返回 `nums[left]` 而不是 `nums[right]`（两者相等但写法需统一）。  
- **下次类似题的第一步**：先**找出数组中隐藏的单调/配对/重复规律**，再思考能否用二分或滑动窗口等 **对数级** 方法把搜索区间快速缩小。
