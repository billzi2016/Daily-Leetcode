# #274. H 指数 / H-Index

> 难度：中等 · 标签：Array、Sorting、Counting Sort · [LeetCode 链接](https://leetcode.com/problems/h-index/)

---

## 题目（英文原版）

**Description**

Given an array of integers citations where citations[i] is the number of citations a researcher received for their ith paper, return the researcher's h-index.
According to the definition of h-index on Wikipedia: The h-index is defined as the maximum value of h such that the given researcher has published at least h papers that have each been cited at least h times.

**Examples**

**Example 1:**

```
Input: citations = [3,0,6,1,5]
Output: 3
Explanation: [3,0,6,1,5] means the researcher has 5 papers in total and each of them had received 3, 0, 6, 1, 5 citations respectively.
Since the researcher has 3 papers with at least 3 citations each and the remaining two with no more than 3 citations each, their h-index is 3.
```

**Example 2:**

```
Input: citations = [1,3,1]
Output: 1
```

**Constraints**

- n == citations.length
- 1 <= n <= 5000
- 0 <= citations[i] <= 1000

## 题目（中文翻译）

给定一个整数数组（array）`citations`，其中 `citations[i]` 表示研究者第 `i` 篇论文被引用的次数，返回该研究者的 h 指数（h-index）。

根据 Wikipedia 上对 h 指数的定义：h 指数是最大的整数 `h`，使得该研究者至少发表了 `h` 篇论文且每篇论文的引用次数均不少于 `h`。

## 示例

### 示例 1
**输入**: `citations = [3,0,6,1,5]`  
**输出**: `3`  
**解释**: `[3,0,6,1,5]` 表示研究者共发表了 5 篇论文，分别被引用了 3、0、6、1、5 次。  
由于研究者有 3 篇论文的引用次数至少为 3，而其余两篇的引用次数不超过 3，所以其 h 指数为 3。

### 示例 2
**输入**: `citations = [1,3,1]`  
**输出**: `1`

## 约束条件

- `n == citations.length`
- `1 <= n <= 5000`
- `0 <= citations[i] <= 1000`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**枚举所有可能的 h 值**，检查它们是否满足题目定义。  
具体步骤：

1. 先把 `citations` 按从大到小排序（想象把所有论文的引用次数排成一排，最高的在前面）。  
2. 从左到右遍历排好序的数组，记住已经看过的论文数 `i+1`（因为下标从 0 开始）。  
3. 当第 `i` 项的引用次数 `citations[i]` **不小于** 已经看到的论文数 `i+1` 时，说明至少有 `i+1` 篇论文的引用次数 ≥ `i+1`。  
4. 继续往后走，直到出现 `citations[i] < i+1` 为止，此时前一个 `i`（即 `i-1`）对应的论文数就是答案。

> **类比**：把所有论文的引用次数想象成一排书的厚度，厚度大的书放在左边。我们从左往右数，只有当第 k 本书的厚度 ≥ k 时，才说明有 k 本书“够厚”。一旦厚度不够，前面的最大符合条件的 k 就是答案。

**为什么正确**：  
- 排序后，左边的引用次数一定不小于右边的（单调递减）。  
- 若第 `i` 本的引用次数 ≥ `i+1`，则前 `i+1` 本都满足“引用次数 ≥ `i+1`”。  
- 当第一次出现 `citations[i] < i+1`，说明再往右就更不可能满足，因为右边的数更小。

#### 代码（Python）

```python
from typing import List

def hIndex_brute(citations: List[int]) -> int:
    # 1. 先从大到小排序，类似把引用次数从高到低排好序
    citations.sort(reverse=True)                # O(n log n)

    # 2. 遍历排好序的数组，i 为下标，i+1 为已经看到的论文数
    for i, c in enumerate(citations):
        # 如果当前引用次数已经小于需要的论文数，说明前面的 i 已经是最大可行的 h
        if c < i + 1:
            return i                               # 返回前一个符合条件的 h
    # 如果全部都满足，则 h 等于论文总数
    return len(citations)
```

#### 复杂度

- **时间复杂度**：`O(n log n)`  
  这里的 `n log n` 来自排序。想象把 `n` 本书排好序需要的工作量，大概是“每本书比较几次”。  
- **空间复杂度**：`O(1)`（不计排序本身的原地修改）  
  只用了常数个额外变量 `i、c`。

### 2. 最优解

#### 思路  

暴力解的瓶颈在 **排序**，排序的时间是 `O(n log n)`。  
观察题目约束：`0 ≤ citations[i] ≤ 1000`，引用次数的取值范围非常小（最多 1000），而论文数 `n` 最多 5000。  
这时可以用 **计数排序（Counting Sort）** 的思想，利用额外的 “桶” 来直接统计每个引用次数出现了多少次，整体只需要线性时间 `O(n + m)`，其中 `m` 是最大引用次数（这里是 1000）。

**核心想法**：

1. 建立一个长度为 `n+1`（或者 `max_citation+1`）的数组 `bucket`，`bucket[i]` 表示**引用次数 ≥ i** 的论文数。  
   - 为了避免 `i` 超出 `n`，把所有 `citations[i] > n` 都放到 `bucket[n]` 中，因为 h‑index 不会超过论文总数 `n`。  
2. 把每篇论文的引用次数对应的桶计数加一。  
3. 从大到小遍历 `bucket`，累计已经看到的论文数 `total`。  
   - 当 `total ≥ i` 时，说明已经有至少 `i` 篇论文的引用次数 ≥ `i`，于是 `i` 就是答案。  

> **类比**：把每篇论文的引用次数想象成投票，`bucket[i]` 记录“得票数 ≥ i 的候选人有多少”。从最高票数往下数，累计人数，一旦累计人数不小于当前票数，就找到了“最少需要多少票才能保证有这么多人投票”的阈值，这正是 h‑index。

#### 代码（Python）

```python
from typing import List

def hIndex_opt(citations: List[int]) -> int:
    n = len(citations)
    # 0~n 共 n+1 个桶，bucket[i] 表示引用次数恰好为 i 的论文数
    # 为了让 “引用次数 > n” 也能放进桶，统一放到 bucket[n] 中
    bucket = [0] * (n + 1)                       # O(n) 额外空间

    # 1. 统计每个引用次数出现的次数
    for c in citations:
        if c >= n:                               # 超过 n 的全部归到最右边的桶
            bucket[n] += 1
        else:
            bucket[c] += 1

    # 2. 从大到小累计，看什么时候累计的论文数 >= 当前的引用阈值 i
    total = 0
    for i in range(n, -1, -1):                    # i 从 n, n-1, ..., 0
        total += bucket[i]                        # 累计所有引用次数 >= i 的论文数
        if total >= i:                            # 满足 h-index 定义
            return i

    return 0  # 理论上不会走到这里，因为 i=0 必定满足
```

#### 复杂度

- **时间复杂度**：`O(n + m)`，这里 `m = n`（因为我们把所有大于 `n` 的引用次数都放到 `bucket[n]`），实际是 `O(n)`。  
  只遍历一次原数组做计数，再遍历一次桶累计，都是线性时间。  
- **空间复杂度**：`O(n)`（额外的桶数组），在最坏情况下需要 `n+1` 个整数。  
  与 `n` 成正比，但相比 `O(n log n)` 的排序，这个空间是可以接受的。

## 心得

- **核心技巧**：利用 **计数排序 / 桶统计** 把“数值范围有限”转化为线性时间的解法。  
- **适用题型**：  
  1. **找最大满足条件的 k**（如 LeetCode 1646 *获取最大表现分数*）。  
  2. **统计频率后求前缀和**（如 455 *分发饼干* 中的贪心计数版）。  
  3. **使用桶解决“值域小”但“规模大”** 的问题（如 1004 *最大连续1的数量* 的 O(n) 计数法）。  
- **一句话总结解题钥匙**：**把“引用次数 ≥ h”转化为“有多少篇论文的引用次数落在每个区间”，用桶累计一次即可得到答案**。

## 反思

- **第一反应**：直接把引用次数排序，然后逐个检查——这是最自然的思路，但会忘记 `O(n log n)` 不是最优。  
- **最容易踩的坑**：  
  - 忘记把 `citations[i] > n` 的情况统一放到 `bucket[n]`，导致桶数组越界或答案错误。  
  - 在累计时从 **大到小** 遍历，否则会得到错误的阈值（因为 h‑index 必须是最大的满足条件的数）。  
- **下次遇到同类题**：第一步先检查**数值范围是否有限**，如果是，就考虑**计数/桶**方案；如果范围太大，再考虑排序或二分搜索等技巧。
