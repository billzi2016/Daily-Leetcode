# #962. 最大宽度坡 / Maximum Width Ramp

> 难度：中等 · 标签：Array、Two Pointers、Stack、Monotonic Stack · [LeetCode 链接](https://leetcode.com/problems/maximum-width-ramp/)

---

## 题目（英文原版）

**Description**

A ramp in an integer array nums is a pair (i, j) for which i < j and nums[i] <= nums[j]. The width of such a ramp is j - i.
Given an integer array nums, return the maximum width of a ramp in nums. If there is no ramp in nums, return 0.

**Examples**

**Example 1:**

```
Input: nums = [6,0,8,2,1,5]
Output: 4
Explanation: The maximum width ramp is achieved at (i, j) = (1, 5): nums[1] = 0 and nums[5] = 5.
```

**Example 2:**

```
Input: nums = [9,8,1,0,1,9,4,0,4,1]
Output: 7
Explanation: The maximum width ramp is achieved at (i, j) = (2, 9): nums[2] = 1 and nums[9] = 1.
```

**Constraints**

- 2 <= nums.length <= 5 * 104
- 0 <= nums[i] <= 5 * 104

## 题目（中文翻译）

**描述**  
在整数数组 `nums` 中，坡（ramp）是一对满足 `i < j` 且 `nums[i] <= nums[j]` 的下标 `(i, j)`。该坡的宽度（width）为 `j - i`。  
给定一个整数数组 `nums`，返回 `nums` 中坡的最大宽度。如果数组中不存在坡，返回 `0`。

**示例 1**  
输入: `nums = [6,0,8,2,1,5]`  
输出: `4`  
解释: 最大宽度坡出现在 `(i, j) = (1, 5)`：`nums[1] = 0` 且 `nums[5] = 5`。

**示例 2**  
输入: `nums = [9,8,1,0,1,9,4,0,4,1]`  
输出: `7`  
解释: 最大宽度坡出现在 `(i, j) = (2, 9)`：`nums[2] = 1` 且 `nums[9] = 1`。

**约束条件**  
- `2 <= nums.length <= 5 * 10^4`  
- `0 <= nums[i] <= 5 * 10^4`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把所有可能的 `(i, j)` 对儿都枚举一遍，检查它们是否满足 **坡道条件** `i < j 且 nums[i] <= nums[j]`，如果满足就算出宽度 `j - i`，取最大的那个。  

- **使用的数据结构**：只需要普通的 Python 列表 `nums`，不需要额外的数据结构。可以把遍历过程想象成在课堂上逐个检查同学的身高：先挑一个左边的同学 `i`，再把右边所有同学 `j` 挨个比较，看谁不比左边的矮（`nums[i] <= nums[j]`），记录最远的距离。
- **为什么正确**：因为我们把所有合法的 `(i, j)` 都看了一遍，最大宽度自然就在其中。
- **时间/空间复杂度**：  
  - 外层循环遍历 `i`，内层循环遍历 `j`，最坏情况下会检查 `n·(n-1)/2` 对，数量级是 **O(n²)**。这里的 `O(n²)` 可以想象成“每个人都要和后面所有人握手”，如果有 10 000 人，就要 100 000 000 次握手，显然太慢了。  
  - 只用了常数级的额外空间（几个计数器），所以是 **O(1)**。

#### 代码（Python）

```python
from typing import List

def maxWidthRamp_bruteforce(nums: List[int]) -> int:
    n = len(nums)
    max_width = 0                         # 记录当前找到的最大宽度
    for i in range(n):                    # 枚举左端点 i
        for j in range(i + 1, n):         # 枚举右端点 j（j 必须在 i 右边）
            if nums[i] <= nums[j]:        # 坡道条件成立
                width = j - i             # 计算宽度
                if width > max_width:     # 更新最大值
                    max_width = width
    return max_width
```

#### 复杂度  

- **时间复杂度**：`O(n²)` —— 随着数组长度 `n` 的增大，运行时间会呈二次方增长，实际运行会很慢。  
- **空间复杂度**：`O(1)` —— 只用了几个整数变量，不随 `n` 增长。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**每一次**都要遍历右边所有元素去找符合条件的 `j`。我们需要一种方式，**快速定位**在右侧满足 `nums[i] <= nums[j]` 的最远 `j`。  
可以从**单调栈（Monotonic Stack）**出发：

1. **构造一个单调递减栈**（栈里保存索引），从左到右遍历数组。  
   - 栈顶的元素对应的 `nums` 值是**当前看到的最小值**（因为我们只在出现更小的值时才把它压入栈）。  
   - 这样，栈中的索引序列是严格递减的 `nums` 值，对应的索引也是递增的（因为我们是从左往右压入的）。
   - 生活化类比：想象在山坡上放置标记，只在每次遇到更低的海拔时放一个新标记，这样标记的高度严格下降，方便后面找“更高的地方”。

2. **从右向左遍历**，尝试弹出栈顶满足 `nums[i] <= nums[j]` 的索引 `i`。  
   - 当我们在位置 `j`（从右往左）看到一个值 `nums[j]`，只要栈顶的 `nums[i]` **不大于** `nums[j]`，说明 `(i, j)` 是合法坡道，而且因为我们是从右往左遍历，`j` 已经是可能的**最远**右端点。于是可以更新答案 `j - i`，并把栈顶弹出继续检查更小的 `i`（更左侧的候选）。  
   - 由于栈里保存的是**左侧的递减序列**，一旦弹出，就不可能再出现更大的宽度，整个过程只会遍历每个元素常数次，时间线性。

3. 最后得到的最大宽度就是答案。如果栈始终没有被弹出，则说明不存在合法坡道，返回 `0`（初始化的 `max_width` 已经是 `0`）。

**核心概念解释**  
- **单调栈**：一种栈的使用方式，栈中元素保持单调递增或递减。它可以帮助我们在 **一次遍历** 中找到“左侧最近且更小/更大的元素”。这里我们需要的是“左侧更小的元素”，于是使用 **递减栈**（栈顶最小）。  
- **为什么只遍历一次**：左侧构建栈时每个元素最多压入一次；右侧遍历时每个元素最多弹出一次，整体是 `O(n)`。

#### 代码（Python）

```python
from typing import List

def maxWidthRamp(nums: List[int]) -> int:
    n = len(nums)
    stack = []               # 用来存放候选的左端点索引，保持 nums[stack] 单调递减
    # 第一步：从左到右建立单调递减栈
    for i, v in enumerate(nums):
        # 当当前值更小的时候才入栈，保证栈中的值严格递减
        if not stack or v < nums[stack[-1]]:
            stack.append(i)  # 记录下更小的左端点
    # 第二步：从右往左尝试弹栈，计算宽度
    max_width = 0
    for j in range(n - 1, -1, -1):      # 从右侧开始
        # 只要栈不为空且右侧值 >= 栈顶对应的左侧值，就可以形成坡道
        while stack and nums[stack[-1]] <= nums[j]:
            i = stack.pop()            # 弹出左端点 i
            width = j - i               # 计算宽度
            if width > max_width:       # 更新最大宽度
                max_width = width
        # 如果栈已经空了，说明左侧更小的元素已经找完，后面的 j 再也找不到更大的宽度
        if not stack:
            break
    return max_width
```

#### 复杂度  

- **时间复杂度**：`O(n)` —— 每个索引最多进栈一次、出栈一次，整体线性。相较于暴力的 `O(n²)`，速度提升了几个数量级。  
- **空间复杂度**：`O(n)` —— 最坏情况下栈会保存所有索引（例如数组严格递减时），需要线性额外空间。相对于只用常数空间的暴力解，这是空间的额外开销，但在本题的约束下完全可以接受。

## 心得

- **核心技巧**：单调递减栈 + 从右往左遍历，快速定位左侧最小值与右侧满足条件的最远位置。  
- **适用的题型**  
  1. **Maximum Width Ramp**（本题）  
  2. **LeetCode 1124. 表现良好的最长连续子数组**（需要单调栈求前缀最小）  
  3. **LeetCode 962. 最大宽度坡道**（同题）  
- **一句话总结解题钥匙**：**“先把左侧递减的‘山谷’记录下来，再用右侧的‘高峰’一次性把它们‘填平’，宽度自然最大”。**

## 反思

- **第一反应**：直接两层循环枚举所有 `(i, j)`，因为这最直观。  
- **最容易踩的坑**  
  - **边界条件**：数组长度为 2 时仍需返回 0 或 1，代码要能正常处理。  
  - **单调栈的入栈条件**：必须是 “更小” 而不是 “更大”，否则栈的单调性会错，导致错误的宽度。  
  - **右侧遍历的提前终止**：当栈空了可以提前 `break`，否则会无意义地继续遍历。  
- **下次遇到同类题**，第一步应想到 **“是否可以用单调栈把左侧的极值（最小/最大）预处理”，再结合一次线性遍历完成匹配**。这样往往能把二次遍历的暴力解降到线性时间。
