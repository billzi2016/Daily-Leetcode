# #1009. 十进制整数的补数 / Complement of Base 10 Integer

## 题目（英文原版）

**Description**

The complement of an integer is the integer you get when you flip all the 0's to 1's and all the 1's to 0's in its binary representation.
Given an integer n, return its complement.
Note: This question is the same as 476: https://leetcode.com/problems/number-complement/

**Examples**

**Example 1:**

```
Input: n = 5
Output: 2
Explanation: 5 is "101" in binary, with complement "010" in binary, which is 2 in base-10.
```

**Example 2:**

```
Input: n = 7
Output: 0
Explanation: 7 is "111" in binary, with complement "000" in binary, which is 0 in base-10.
```

**Example 3:**

```
Input: n = 10
Output: 5
Explanation: 10 is "1010" in binary, with complement "0101" in binary, which is 5 in base-10.
```

**Constraints**

- 0 <= n < 109

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  
最直接的想法就是把整数 **n** 转成二进制字符串，逐位把 `'0'` 换成 `'1'`、把 `'1'` 换成 `'0'`，得到“补码”。  
随后把这个新的二进制字符串再转回十进制，就是答案。  

- **数据结构**：这里用到的只有**字符串**。可以把二进制数想象成一串灯泡（每盏灯要么亮 `1` 要么灭 `0`），我们把每盏灯的状态翻转，就得到了补码。  
- **正确性**：二进制的每一位都被恰好翻转一次，符合题目“把所有 0 变 1、所有 1 变 0”的要求。  
- **时间/空间复杂度**：  
  - 把整数转成二进制需要查看它的每一位，位数大约是 `log₂ n`（即十进制的位数的对数）。我们记作 **k**。  
  - 翻转、再转回十进制同样遍历这 **k** 位。  
  - 因此 **时间复杂度** 为 **O(k) ≈ O(log n)**，也就是说如果 n 很大，运行时间会随它的二进制位数线性增长。  
  - 需要额外保存二进制字符串，空间同样是 **O(k)**。  

#### 代码（Python）  
```python
def findComplement_bruteforce(n: int) -> int:
    # 0 是特殊情况，直接返回 1（因为 0 的二进制是 "0"，翻转后是 "1"）
    if n == 0:
        return 1

    # 1. 把 n 转成二进制字符串（去掉前面的 '0b' 前缀）
    bin_str = bin(n)[2:]                # 例如 n=5 -> "101"

    # 2. 翻转每一位：'0' -> '1'，'1' -> '0'
    flipped = []
    for ch in bin_str:
        if ch == '0':
            flipped.append('1')
        else:
            flipped.append('0')
    flipped_str = ''.join(flipped)      # 例如 "101" -> "010"

    # 3. 把翻转后的二进制字符串再转回十进制整数
    return int(flipped_str, 2)           # 例如 "010" -> 2
```

#### 复杂度  
- **时间复杂度**：`O(log n)` —— 只和二进制位数有关，位数越多需要的时间越多。  
- **空间复杂度**：`O(log n)` —— 需要存储二进制字符串和翻转后的字符串，同样和位数成正比。

### 2. 最优解  

#### 思路  
暴力解的瓶颈在于**创建字符串**和**两次遍历**。实际上我们只需要**位运算**就可以在常数空间里直接得到答案。  

1. **观察**：  
   - 对任意二进制数 `x`，如果我们找出一个只包含 `1` 的掩码 `mask`（长度和 `x` 相同），则 `x` 的补码等于 `mask ^ x`（异或）。  
   - 另一个等价的写法是 `mask - x`，因为 `mask` 本身就是全部 `1`，减去 `x` 相当于把每一位取反。  

2. **如何得到 mask**：  
   - 先算出 `n` 的二进制位数 `k`（最高位所在的位置）。  
   - 把 `1` 左移 `k` 位得到 `1000…0`（共 `k+1` 位），再减去 `1` 就得到 `111…1`（恰好 `k` 位的全 1）。  
   - 例如 `n = 5 (101)`，最高位是第 3 位（从 1 开始计数），`1 << 3 = 1000`，`1000 - 1 = 0111`，再把高位的 0 去掉得到 `111`（即 `mask = 7`）。  

3. **特殊情况**：  
   - 当 `n = 0` 时，上面的位数计算会得到 `k = 0`，`mask` 会是 `0`，但题目要求 `0` 的补码是 `1`。所以单独判断返回 `1`。  

4. **核心算法**：  
   - 计算 `mask`（全 1 掩码） → `mask ^ n`（或 `mask - n`） → 得到答案。  

**类比**：想象你有一把只会打开所有锁的万能钥匙 `mask`（每个锁对应一位 1），而 `n` 是已经打开的那几把锁。把 `mask` 与 `n` 做异或，就相当于把已经打开的锁再关上，把未打开的锁打开，正好得到“全部反转”的状态。  

#### 代码（Python）  
```python
def findComplement(n: int) -> int:
    # 0 是边界情况，直接返回 1
    if n == 0:
        return 1

    # 1. 计算 n 的二进制位数（最高位所在的位置）
    #   通过不断右移 n，直到 n 变为 0，计数器 cnt 就是位数
    cnt = 0
    temp = n
    while temp:
        cnt += 1          # 统计已经移动了多少位
        temp >>= 1        # 右移一位，相当于把最低位丢掉

    # 2. 构造全 1 的掩码： (1 << cnt) - 1
    #    1 左移 cnt 位得到 1000...0，再减 1 变成 0111...1
    mask = (1 << cnt) - 1

    # 3. 直接异或得到补码（也可以写成 mask - n）
    return mask ^ n
```

#### 复杂度  
- **时间复杂度**：`O(log n)` —— 只需要遍历 `n` 的二进制位一次来求位数，位数是 `log₂ n`，所以时间随位数线性增长。与暴力解相同的数量级，但我们省去了字符串创建和两次遍历的常数因子，实际更快。  
- **空间复杂度**：`O(1)` —— 只用几个整数变量，额外空间不随 `n` 大小变化。

## 心得  

- **核心技巧**：**利用全 1 掩码 + 位运算（异或或减法）** 快速得到二进制反转。  
- **适用题型**：  
  1. **数的补码 / 反码**（如 LeetCode 476 Number Complement）。  
  2. **找出最高位**（如 168 Bitwise AND of Numbers Range，需要先定位最高位）。  
  3. **位掩码题**（如 191 Number of 1 Bits，需要构造全 1 或全 0 的掩码）。  
- **一句话总结**：**先算出和 n 同长的全 1 掩码，用异或或减法一次性翻转所有位**。  

## 反思  

- **第一反应**：把整数转成二进制字符串，手动翻转再转回去——最直观但不是最高效。  
- **最容易踩的坑**：  
  - **n = 0** 的特殊情况，直接返回 1（因为 0 的二进制是 “0”，翻转后是 “1”）。  
  - 计算掩码时忘记去掉最高位的多余 `0`，导致掩码比实际位数多一位，结果错误。  
- **下次遇到同类题**：第一步先**思考是否可以用位运算**，尤其是**构造掩码**或**利用异或的性质**，往往能把“遍历每一位”转化为 **O(1) 额外空间、O(log n) 时间** 的解法。
