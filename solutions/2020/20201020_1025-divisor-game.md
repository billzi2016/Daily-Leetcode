## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  

最直接的想法是**把每一个可能的局面都穷举一遍**，看从当前数字 `n` 出发，先手（Alice）是否一定能把对手逼进“输”的局面。  

- **状态**：`n`（黑板上剩下的数字）。  
- **转移**：从 `n` 中任选一个 **合法的除数** `x`（`1 <= x < n` 且 `n % x == 0`），把 `n` 变成 `n - x`。  
- **输赢判定**：如果当前玩家没有任何合法的除数可选（这只会在 `n = 1` 时出现），则该玩家输。  

我们可以用**递归 + 记忆化**（也叫**动态规划**）来保存已经算过的 `n`，避免重复计算。  
这里的记忆化表相当于一本**查字典**：键（key）是数字 `n`，值（value）是布尔值 `True` 表示**先手必胜**，`False` 表示**先手必败**。  

**为什么这个方法一定正确？**  
因为我们从**所有可能的合法操作**中寻找一次能够让对手进入必败局面的机会。如果存在这样的一步，当前玩家就可以保证赢；如果所有合法操作都只能把对手带到必胜局面，那么当前玩家必败。递归地把这个判断扩展到每个子局面，就覆盖了全部可能的游戏路径。

**时间/空间复杂度**（用大白话解释）：  
- 对每个 `n`（最多 `1000`），我们会遍历它的所有除数，最坏情况除数数量和 `n` 成正比（比如 `n` 是 720，有 30 多个除数），于是整体时间大约是 **`n` 乘以 `n`**，记作 `O(n²)`，也就是“平方级”。  
- 记忆化表会存 `1 … n` 的结果，空间是 `O(n)`，也就是“线性级”，随 `n` 增长而等比例增长。  

#### 代码（Python）  

```python
from functools import lru_cache

def divisorGame_bruteforce(n: int) -> bool:
    """
    暴力递归 + 记忆化（自带缓存），返回先手 Alice 是否必胜
    """

    @lru_cache(maxsize=None)               # 把已经算过的 n 记下来，像查字典一样快
    def can_win(cur: int) -> bool:
        # 如果没有合法除数（cur == 1），当前玩家输，返回 False
        if cur == 1:
            return False

        # 枚举所有合法除数 x（1 <= x < cur 且 cur % x == 0）
        for x in range(1, cur):
            if cur % x == 0:                # x 是除数
                # 把数字变成 cur - x，轮到对手
                # 如果对手在这个新局面必败（can_win(cur - x) 为 False），
                # 那么当前玩家就能赢
                if not can_win(cur - x):
                    return True            # 找到一条必胜路径，直接返回

        # 所有合法除数都让对手进入必胜局面，当前玩家必败
        return False

    return can_win(n)
```

#### 复杂度  

- **时间复杂度**：`O(n²)`  
  - 解释：对每个 `n`（最多 1000）我们都要遍历它的所有除数，最坏情况下除数数量和 `n` 成正比，所以整体是 “n 乘以 n”。  
- **空间复杂度**：`O(n)`  
  - 解释：递归栈最深为 `n`，加上记忆化表保存 `1…n` 的结果，都是线性增长的。

### 2. 最优解  

#### 思路  

从暴力解可以看到，**状态转移**的核心是“先手能否把对手逼到必败”。  
观察几个小例子（手动算一下）：

| n | 先手是否必胜 |
|---|--------------|
| 1 | False (只能输) |
| 2 | True  (先手减 1 → 1，后手输) |
| 3 | False (只能减 1 → 2，后手必胜) |
| 4 | True  (先手减 1 → 3，后手必败) |
| 5 | False |
| 6 | True  |
| … | … |

**规律**：当 `n` 为 **偶数** 时先手必胜；为 **奇数** 时先手必败。  

**为什么会这样？**  
我们用**数学归纳**来证明：

1. **基例**：`n = 1`（奇数），先手没有合法除数，只能输。结论成立。  
2. **归纳假设**：假设对所有小于 `k` 的整数，**偶数必胜，奇数必败**。  
3. **归纳步骤**：考虑 `n = k`。  
   - 如果 `k` 是 **偶数**，先手一定可以选择除数 `x = 1`（因为 1 总是合法），把 `k` 变成 `k-1`，这时 `k-1` 是 **奇数**。根据归纳假设，奇数局面对先手（现在是后手）是必败的，换句话说，**后手必输**，于是**先手必胜**。  
   - 如果 `k` 是 **奇数**，任何合法除数 `x` 必然也是奇数（因为奇数只能被奇数整除），于是 `k - x` 仍然是 **偶数**。这时轮到后手，面对的是偶数局面，根据归纳假设，**后手必胜**，于是**先手必败**。  

归纳完成后得到结论：**`n` 为偶数时 Alice 必胜，奇数时必败**。  

这个结论只需要判断 `n` 的奇偶性，**时间 O(1)**，**空间 O(1)**，是最优的。

#### 代码（Python）  

```python
def divisorGame(n: int) -> bool:
    """
    只判断 n 的奇偶性：偶数 Alice 必胜，奇数必败。
    时间 O(1)，空间 O(1)。
    """
    return n % 2 == 0          # n 能被 2 整除 → 偶数 → True
```

#### 复杂度  

- **时间复杂度**：`O(1)` — 只做一次取模运算，跟 `n` 大小无关，常数时间。  
- **空间复杂度**：`O(1)` — 不使用额外的数组或递归栈，只占用极少的临时变量。

## 心得  

- **核心技巧**：利用**奇偶性**进行数学归纳，避免穷举所有局面。  
- **适用的题型**：  
  1. 需要判断先手胜负的**游戏类**题目（如 Nim、Stone Game 等），常能通过奇偶或模运算简化。  
  2. **数论+博弈**的组合题目，常常可以把“能否做某步”转化为“数的属性（奇偶、质数等）”。  
- **一句话总结解题钥匙**：**先手能否把局面直接转成对手的必败状态**——在本题里，这一步恰好是“把偶数变成奇数”。  

## 反思  

- **第一反应**：看到“除数”和“减去除数”就想到**递归/动态规划**，于是写出了暴力解。  
- **最容易踩的坑**：  
  - 忘记 **1** 也是合法除数，导致对 `n=2` 的判断错误。  
  - 在递归实现时没有记忆化，导致指数级爆炸。  
  - 对奇数的除数属性不够敏感，错以为可以减去偶数。  
- **下次遇到同类题**：**先检查是否存在明显的数学规律（奇偶、模数、倍数）**，如果能直接判断则立刻采用 O(1) 解法；否则再考虑 DP/递归。
