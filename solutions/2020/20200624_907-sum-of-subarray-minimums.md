# #907. 子数组最小值之和 / Sum of Subarray Minimums

> 难度：中等 · 标签：Array、Dynamic Programming、Stack、Monotonic Stack · [LeetCode 链接](https://leetcode.com/problems/sum-of-subarray-minimums/)

## 题目（英文原版）

**Description**

Given an array of integers arr, find the sum of min(b), where b ranges over every (contiguous) subarray of arr. Since the answer may be large, return the answer modulo 109 + 7.

**Examples**

**Example 1:**

```
Input: arr = [3,1,2,4]
Output: 17
Explanation: 
Subarrays are [3], [1], [2], [4], [3,1], [1,2], [2,4], [3,1,2], [1,2,4], [3,1,2,4]. 
Minimums are 3, 1, 2, 4, 1, 1, 2, 1, 1, 1.
Sum is 17.
```

**Example 2:**

```
Input: arr = [11,81,94,43,3]
Output: 444
```

**Constraints**

- 1 <= arr.length <= 3 * 104
- 1 <= arr[i] <= 3 * 104

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  
最直接的想法就是**枚举所有子数组**，然后把每个子数组的最小值加起来。  
- **子数组**：把数组看成一排连续的盒子，任选左边界 `l` 与右边界 `r`（`l ≤ r`），`arr[l..r]` 就是一个子数组。  
- **最小值**：在这个子数组里找最小的数字，就像在一堆水果里挑出最小的一个。  

实现上可以两层循环：外层固定左边界 `l`，内层把右边界 `r` 从 `l` 向后展开，每次把当前子数组的最小值累计。  

这个方法**一定能得到正确答案**，因为我们真的遍历了所有可能的子数组，并且对每个子数组都算出了它的最小值。

#### 代码（Python）

```python
from typing import List

MOD = 10**9 + 7

def sumSubarrayMins_brute(arr: List[int]) -> int:
    n = len(arr)
    total = 0                     # 用来累加所有子数组的最小值
    for left in range(n):         # 枚举左边界
        cur_min = arr[left]       # 当前子数组的最小值，初始为左端点的值
        for right in range(left, n):   # 枚举右边界
            cur_min = min(cur_min, arr[right])   # 更新子数组的最小值
            total += cur_min                     # 加到答案中
    return total % MOD            # 题目要求对 1e9+7 取模
```

> **关键行解释**  
> - `cur_min = min(cur_min, arr[right])`：把新加入的元素和已有最小值比较，得到新的最小值。  
> - `total += cur_min`：把这个子数组的最小值加入总和。  

#### 复杂度  
- **时间复杂度**：`O(n²)`。两层循环每层最坏遍历 `n` 次，类似“把所有配对都列出来”。对 `n = 3·10⁴` 的数据来说，这会产生约 `9·10⁸` 次操作，明显超时。  
- **空间复杂度**：`O(1)`。只用了常数个额外变量，和输入大小无关。

### 2. 最优解  

#### 思路  
暴力解慢的根源在于**重复计算**：同一个元素会在很多子数组里被比较多次。我们需要一次“看见”每个元素，就知道它在多少子数组里是**最小值**，然后把它贡献的次数乘上自身即可。

> **核心问题**：对每个位置 `i`，找出**左边最近且严格小于 `arr[i]` 的位置** `L`，以及**右边最近且小于等于 `arr[i]` 的位置** `R`。  
> - `L` 左边的所有元素都 **不小于** `arr[i]`，所以在 `L+1 … i` 这段里，`arr[i]` 是最小的。  
> - `R` 右边的所有元素都 **大于** `arr[i]`（因为我们在右侧用 “小于等于”），所以在 `i … R-1` 这段里，`arr[i]` 仍是最小的。  

于是，以 `i` 为最小值的子数组数量等于  
```
左侧可选起点数 = i - L
右侧可选终点数 = R - i
贡献次数 = (i - L) * (R - i)
```
最终答案就是 `∑ arr[i] * (i-L) * (R-i)`（取模）。

> **如何快速得到 L、R**  
> 使用 **单调栈（Monotonic Stack）**：  
> - 栈里保存 **递增** 的元素下标。遍历数组时，当发现当前 `arr[i]` 小于栈顶对应的值，就说明栈顶元素的 **右侧最近小于等于** 的位置就是 `i`。弹出栈顶并记录 `R`。  
> - 同理，遍历完后栈中剩余的元素没有右侧更小的值，它们的 `R` 为 `n`（数组长度）。  
> - 为了得到左侧最近**严格小于**的位置 `L`，我们可以在遍历时记录每个元素弹出时的 **前一个栈顶**（即左侧比它大的最近位置），或者直接在一次遍历中求 `L`（使用另一遍或在弹出时保存）。这里采用两次遍历：一次求左边最近严格小于的位置（用 `<`），一次求右边最近小于等于的位置（用 `<=`）。  

> **类比**：把数组想成一排高矮不一的柱子，单调栈像是一只“从左到右走的机器人”，它总是保持手里拿的柱子高度递增。当遇到更矮的柱子时，机器人把比它高的柱子“归还”，并立刻知道这些被归还柱子的右边最近更矮的柱子是谁。

#### 代码（Python）

```python
from typing import List

MOD = 10**9 + 7

def sumSubarrayMins(arr: List[int]) -> int:
    n = len(arr)

    # ---------- 求左侧最近严格小于的下标 ----------
    # left[i] 表示 arr[i] 左边最近的、值 < arr[i] 的位置
    left = [-1] * n          # -1 表示左边没有更小的元素
    stack = []               # 单调递增栈，存放下标
    for i in range(n):
        # 栈顶元素 >= arr[i] 时弹出，保证栈内是严格递增的
        while stack and arr[stack[-1]] >= arr[i]:
            stack.pop()
        left[i] = stack[-1] if stack else -1
        stack.append(i)

    # ---------- 求右侧最近小于等于的下标 ----------
    # right[i] 表示 arr[i] 右边最近的、值 <= arr[i] 的位置
    right = [n] * n          # n 表示右边没有更小或相等的元素
    stack.clear()
    for i in range(n-1, -1, -1):
        # 注意这里使用 >，因为我们要找的是 “小于等于”，所以弹出比当前严格大的元素
        while stack and arr[stack[-1]] > arr[i]:
            stack.pop()
        right[i] = stack[-1] if stack else n
        stack.append(i)

    # ---------- 计算贡献 ----------
    ans = 0
    for i in range(n):
        left_cnt = i - left[i]          # 左侧可以选的起点数
        right_cnt = right[i] - i        # 右侧可以选的终点数
        ans = (ans + arr[i] * left_cnt * right_cnt) % MOD
    return ans
```

> **关键行解释**  
> - `while stack and arr[stack[-1]] >= arr[i]:`：弹出所有不严格小于当前的元素，保证栈底到栈顶对应的值严格递增，从而得到左侧最近 **严格** 小的下标。  
> - `while stack and arr[stack[-1]] > arr[i]:`：在右侧遍历时，只弹出 **严格大于** 的元素，这样栈顶保留的就是第一个 **小于等于** 的位置。  
> - `left_cnt = i - left[i]`、`right_cnt = right[i] - i`：分别是左、右两边可以自由选起点/终点的数量。  
> - `ans = (ans + arr[i] * left_cnt * right_cnt) % MOD`：把 `arr[i]` 对所有子数组的贡献一次性加进去，并随时取模防止整数爆炸。  

#### 复杂度  
- **时间复杂度**：`O(n)`。每个元素最多被压入栈一次、弹出一次，整体线性遍历两遍。相当于只走了一趟路，远快于 `O(n²)`。  
- **空间复杂度**：`O(n)`。额外的 `left`、`right` 数组各占 `n` 长度，栈最多也只会保存 `n` 个下标。

## 心得  

- **核心技巧**：**单调栈 + 计数贡献**，把“每个元素是最小值的子数组数目”一次算清。  
- **适用的题型**  
  1. **子数组最小值/最大值之和**（本题、LeetCode 907）。  
  2. **直方图中最大矩形面积**（LeetCode 84），同样利用单调栈找左右最近更小的柱子。  
  3. **子数组中元素出现次数的贡献**（如 “Sum of Subarray Ranges”），思路类似。  
- **一句话总结**：**把每个元素的“统治范围”算出来，它就一次性把自己所有的贡献交给答案**。

## 反思  

- **第一反应**：直接写两层循环枚举子数组，想法最直接但会超时。  
- **最容易踩的坑**  
  - **左/右边界的比较符号**：左侧要严格小于，右侧要小于等于，否则会出现重复计数或漏计数。  
  - **取模时机**：`arr[i] * left_cnt * right_cnt` 可能超过 Python 整数范围（虽然 Python 自动大整数，但会影响性能），最好在累加时及时取模。  
  - **边界值**：当数组全递增或全递减时，`left`、`right` 可能是 `-1` 或 `n`，代码必须正确处理。  
- **下次遇到同类题**，第一步就**思考“每个元素能支配多少子数组”**，并尝试用单调栈快速得到左右最近更小（或更大的）位置。这样往往能直接得到 O(n) 的最优解。
