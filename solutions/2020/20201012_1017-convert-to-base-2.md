# #1017. 转换为负二进制 / Convert to Base -2

> 难度：中等 · 标签：Math · [LeetCode 链接](https://leetcode.com/problems/convert-to-base-2/)

---

## 题目（英文原版）

**Description**

Given an integer n, return a binary string representing its representation in base -2.
Note that the returned string should not have leading zeros unless the string is "0".

**Examples**

**Example 1:**

```
Input: n = 2
Output: "110"
Explantion: (-2)2 + (-2)1 = 2
```

**Example 2:**

```
Input: n = 3
Output: "111"
Explantion: (-2)2 + (-2)1 + (-2)0 = 3
```

**Example 3:**

```
Input: n = 4
Output: "100"
Explantion: (-2)2 = 4
```

**Constraints**

- 0 <= n <= 109

---

## 题目（中文翻译）

给定一个整数 `n`，返回其在负二进制（base -2）下的表示，形式为二进制字符串（binary string）。  
返回的字符串不应包含前导零，除非该字符串本身就是 `"0"`。

## 示例

### 示例 1
**输入:** `n = 2`  
**输出:** `"110"`  
**解释:** `(-2)^2 + (-2)^1 = 2`

### 示例 2
**输入:** `n = 3`  
**输出:** `"111"`  
**解释:** `(-2)^2 + (-2)^1 + (-2)^0 = 3`

### 示例 3
**输入:** `n = 4`  
**输出:** `"100"`  
**解释:** `(-2)^2 = 4`

## 约束条件
- `0 <= n <= 10^9`

---

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**枚举所有可能的二进制字符串**，然后把每个字符串当成“负二进制”来计算它对应的十进制值，看看哪一个等于给定的 `n`。  
- **数据结构**：只需要一个普通的 Python `list` 或 `str` 来保存二进制位。可以把它想象成“纸条上的 0/1”，我们一张张翻看每一种可能的排列。  
- **为什么正确**：只要遍历了**所有**合法的二进制组合（不含前导零），必然会碰到那条恰好等于 `n` 的组合。  
- **复杂度直观解释**：  
  - 若答案的长度是 `L`（即最高位所在的位数），所有可能的二进制串共有 `2^L` 种（每一位可以是 0 或 1），相当于把所有 `L` 位的灯开关全打开关一遍。  
  - 对每一种组合我们都要把它重新算一次十进制值，这一步的工作量是 `O(L)`，所以总时间是 `O(L·2^L)`。当 `n` 较大时，`L` 大约是 `log₂|n|`，于是时间会呈指数级增长，根本不可接受。  
  - 空间上我们只需要存放当前正在检查的字符串，最多 `O(L)`。

#### 代码（Python）

```python
def to_base_neg2_bruteforce(n: int) -> str:
    # 特例：0 的表示就是 "0"
    if n == 0:
        return "0"

    # 最高位不超过 log2(|n|) + 1，安全起见多取几位
    max_len = 32  # 2^31 > 10^9，足够

    # 从短到长枚举二进制字符串（不含前导零）
    for length in range(1, max_len + 1):
        # 生成所有 0/1 的组合，使用二进制计数法
        for mask in range(1 << length):
            # 跳过前导零的情况（最高位必须是 1）
            if (mask >> (length - 1)) & 1 == 0:
                continue

            # 把 mask 当成负二进制数计算其十进制值
            value = 0
            for i in range(length):
                bit = (mask >> i) & 1          # 第 i 位（从低位到高位）
                value += bit * ((-2) ** i)    # 负二进制的权值是 (-2)^i

            if value == n:                     # 找到答案
                # 把 mask 转成二进制字符串（高位在左）
                return bin(mask)[2:].zfill(length)

    # 理论上不会走到这里，因为一定能找到答案
    return ""
```

> 代码里每一行都有中文注释，帮助你跟上思路。  
> `1 << length` 表示 `2^length`，相当于“把灯全部打开”。  

#### 复杂度

- **时间复杂度**：`O(L·2^L)`  
  - `L` 是答案的位数，大约是 `log₂|n|`。指数级的 `2^L` 意味着当 `n` 较大时会非常慢，就像把所有钥匙都尝一遍才能打开门。  
- **空间复杂度**：`O(L)`  
  - 只保存当前枚举的二进制串，最多占用 `L` 位空间。

### 2. 最优解

#### 思路  

从暴力解可以看到：**枚举所有组合是浪费的**，因为我们根本不需要去尝试不符合“负二进制”进位规则的情况。  
负二进制其实和十进制、二进制的**除基取余**过程完全相同，只是除数是 **-2** 而不是 **2**。  
下面一步步推导：

1. **除基取余的核心**  
   - 正常进制（比如十进制）把一个数 `x` 写成 `x = 10·q + r`（`0 ≤ r < 10`），`r` 就是最低位。  
   - 对于负二进制，我们希望得到 `x = (-2)·q + r`，且 `r` 必须是 **0 或 1**（因为每位只能是 0/1）。  
2. **Python 的 `%` 与负除数的怪癖**  
   - 在 Python 中，`x % -2` 的余数符号和除数相同，即余数会是 **0 或 -1**，这不符合我们要求的 0/1。  
   - 解决办法：先算 `r = x % -2`，如果 `r` 为负（即 -1），我们把它“借位”一次：`r += 2`（变成 1），并把商 `q` 加 1（因为多借了一个 -2）。  
3. **迭代过程**  
   - 把得到的 `r` 加入答案的最低位（因为我们是从低位往高位算），然后把 `x` 更新为新的商 `q`，继续循环，直到 `x` 变成 0。  
   - 最后把收集到的位倒序（因为先得到的是最低位），得到的字符串就是所求的负二进制表示。  

**类比**：把 `n` 当成一块巧克力，一次只能切成两块（因为基是 2），但这块巧克力是“倒着切”（负号），所以每次切完后可能需要把多余的那一块“再塞回去”（借位），最终把所有小块排成一列，就是答案。

#### 代码（Python）

```python
def to_base_neg2(n: int) -> str:
    """返回整数 n 的负二进制字符串（不含前导零）"""
    if n == 0:                 # 特例直接返回
        return "0"

    bits = []                  # 用列表收集每一位，先从低位往高位存
    while n != 0:
        # 先取余数，Python 中 n % -2 可能是 0 或 -1
        r = n % -2
        n //= -2                # 先得到商，注意是整除

        if r < 0:               # 如果余数是负的（-1），需要借位
            r += 2               # 把 -1 变成 1（因为 1 才是合法的位）
            n += 1               # 商加一，抵消多借的 -2

        bits.append(str(r))     # 把当前位加入列表（仍是低位在前）

    # bits 中的顺序是低位→高位，反转后得到正确的字符串
    return ''.join(reversed(bits))
```

**关键行解释**  

- `r = n % -2`：求最低位的“原始余数”。  
- `if r < 0: r += 2; n += 1`：把非法的 `-1` 变成合法的 `1`，并把商向上调一（相当于向高位“进位”）。  
- `bits.append(str(r))`：把每一步得到的合法位保存下来。  
- `''.join(reversed(bits))`：把从低位到高位的列表倒过来，得到最终的高位在左的二进制串。

#### 复杂度

- **时间复杂度**：`O(log |n|)`  
  - 每次循环把 `n` 除以 2（绝对值），所以循环次数等于答案的位数 `L`，而 `L ≈ log₂|n|`。这就像把一根绳子不断折半，折几次就够了。  
  - 与暴力解的 `O(L·2^L)` 相比，指数被降到了对数，快了几个数量级。  
- **空间复杂度**：`O(log |n|)`  
  - 只需要存放 `L` 位字符的列表，和答案长度一样多。

## 心得

- **核心技巧**：负进制的“除基取余”与正进制完全相同，只是要额外处理余数为负的情况（借位）。  
- **适用的题型**  
  1. **任意负进制转换**（如 base -3、base -10）  
  2. **非整数进制的编码**（如 LeetCode 1017. Convert to Base -2 的变体）  
  3. **利用负进制实现无符号数的有符号表示**（如某些压缩算法）  
- **一句话总结**：**“负基数的除法仍然是‘除商取余’，只要把负余数调正并向高位进位，就能一次搞定”。**

## 反思

- **第一反应**：看到“负二进制”就想“把普通二进制翻个面”，于是想到直接枚举所有二进制串。  
- **最容易踩的坑**  
  - **余数为负**：直接使用 `% -2` 会得到 `-1`，必须手动调成 `1` 并进位。  
  - **边界条件**：`n = 0` 必须单独处理，否则循环不会执行，返回空串。  
  - **前导零**：在构造答案时要去掉高位的多余 `0`，最简单的办法是在收集完位后直接 `''.join(reversed(bits))`，不再手动裁剪。  
- **下次遇到同类题**：**第一步就把“除基取余”写出来**，检查余数是否合法（0/1），若不合法立即做借位调整；随后循环即可。这样可以避免枚举暴力的思路，直接走向最优解。
