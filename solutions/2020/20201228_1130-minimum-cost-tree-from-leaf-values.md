# #1130. 叶子值的最小代价树 / Minimum Cost Tree From Leaf Values

> 难度：中等 · 标签：Array、Dynamic Programming、Stack、Greedy、Monotonic Stack · [LeetCode 链接](https://leetcode.com/problems/minimum-cost-tree-from-leaf-values/)

## 题目（英文原版）

**Description**

Given an array arr of positive integers, consider all binary trees such that:
Among all possible binary trees considered, return the smallest possible sum of the values of each non-leaf node. It is guaranteed this sum fits into a 32-bit integer.
A node is a leaf if and only if it has zero children.

**Examples**

**Example 1:**

```
Input: arr = [6,2,4]
Output: 32
Explanation: There are two possible trees shown.
The first has a non-leaf node sum 36, and the second has non-leaf node sum 32.
```

**Example 2:**

```
Input: arr = [4,11]
Output: 44
```

**Constraints**

- 2 <= arr.length <= 40
- 1 <= arr[i] <= 15
- It is guaranteed that the answer fits into a 32-bit signed integer (i.e., it is less than 231).

## 题目（中文翻译）

给定一个由正整数构成的数组 `arr`，考虑所有满足以下条件的二叉树（binary tree）：

- 树的叶子节点（leaf）恰好对应 `arr` 中的元素，且这些叶子节点在树中的中序遍历顺序必须与 `arr` 中的顺序一致；
- 每个非叶子节点（non-leaf node）的值等于其左右子树中**最大**叶子值（maximum leaf value）的乘积。

在所有满足上述条件的二叉树中，返回所有非叶子节点值之和的 **最小可能值**。题目保证该和能够放入 32 位有符号整数。

> 说明：如果一个节点没有子节点，则它是叶子节点；否则它是非叶子节点。

### 示例

#### 示例 1
**输入**  
`arr = [6,2,4]`

**输出**  
`32`

**解释**  
下面展示了两棵可能的二叉树：

1. 第一棵树的非叶子节点之和为 `36`。  
2. 第二棵树的非叶子节点之和为 `32`，是所有可能树中最小的。

#### 示例 2
**输入**  
`arr = [4,11]`

**输出**  
`44`

### 约束条件

- `2 <= arr.length <= 40`
- `1 <= arr[i] <= 15`
- 题目保证答案小于 `2^31`，即能够放入 32 位有符号整数中。

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

我们把数组 `arr` 看成 **叶子节点的顺序**。  
题目要求把这些叶子连成一棵二叉树，树的非叶子节点的值等于它左右子树根节点的 **最大叶子值** 的乘积，所有非叶子节点的值求和，要求最小。

最直接的想法就是**枚举所有可能的二叉树结构**，计算每棵树的代价，取最小值。  
因为二叉树的每一次“合并”都把相邻的两个子树变成一个父节点，这相当于在数组的某个位置 **划分** 为左子数组和右子数组，然后递归求解这两个子数组的最小代价。  

这正好可以用**区间 DP**（也叫递归 + 记忆化搜索）来实现：

- 用 `dp(i, j)` 表示 **子数组 `arr[i..j]`** 能得到的最小非叶子节点和。
- 当 `i == j`（子数组只剩一个叶子）时，根本不存在非叶子节点，代价为 `0`。
- 对于 `i < j`，我们尝试所有可能的划分点 `k`（`i ≤ k < j`），把区间分成 `[i..k]` 与 `[k+1..j]` 两部分。  
  - 左右子树各自的最小代价分别是 `dp(i, k)` 与 `dp(k+1, j)`。  
  - 合并这两棵子树后会产生一个新非叶子节点，它的值等于 **左子树叶子最大值 × 右子树叶子最大值**。  
  - 因此，划分 `k` 对应的总代价为  

    ```
    max(arr[i..k]) * max(arr[k+1..j]) + dp(i, k) + dp(k+1, j)
    ```

- 在所有 `k` 中取最小值，即为 `dp(i, j)`。

> **类比**：把数组想象成一排“水果”，每次只能把相邻的两堆水果合在一起，合并的费用是两堆水果中最大重量的乘积。我们想找到一种合并顺序，使总费用最小。暴力 DP 就是把所有可能的合并顺序全部尝遍。

#### 代码（Python）

```python
from functools import lru_cache
from typing import List

def mctFromLeafValues(arr: List[int]) -> int:
    # ---------- 辅助函数：返回子数组的最大值 ----------
    # 这里直接用内置 max，时间上已经足够（n ≤ 40）。
    def range_max(l: int, r: int) -> int:
        return max(arr[l:r+1])

    @lru_cache(None)               # 记忆化，避免重复计算相同区间
    def dp(i: int, j: int) -> int:
        # 只有一个叶子时，不会产生非叶子节点，费用为 0
        if i == j:
            return 0

        best = float('inf')
        # 尝试所有划分点 k
        for k in range(i, j):
            left_max  = range_max(i, k)       # 左子区间的最大叶子值
            right_max = range_max(k + 1, j)   # 右子区间的最大叶子值
            cost = left_max * right_max + dp(i, k) + dp(k + 1, j)
            best = min(best, cost)            # 取最小的合并代价
        return best

    return dp(0, len(arr) - 1)
```

> **关键行解释**  
> - `@lru_cache(None)`：把已经算好的 `dp(i,j)` 结果存起来，后面再需要时直接取，防止指数级递归。  
> - `for k in range(i, j):`：遍历所有可能的“最后一次合并”位置。  
> - `left_max * right_max`：产生的父节点值，即两棵子树根节点的最大叶子值相乘。

#### 复杂度  

- **时间复杂度**：`O(n³)`。  
  - 外层递归有 `O(n²)` 个不同的区间 `(i, j)`（因为 `i ≤ j`），  
  - 对每个区间我们要遍历 `k`（最多 `n` 次），  
  - 还有 `max` 操作本身是 `O(n)`（但在本题 `n ≤ 40`，可以忽略不计，若提前预处理则仍是 `O(1)`）。  
  - 简单来说，就是“三层循环”，所以是 **立方级**。  
  - **大白话**：如果数组有 40 个数，最坏情况下要算 40×40×40 ≈ 64,000 次，电脑完全可以接受，但不是最优。

- **空间复杂度**：`O(n²)` 用于记忆化表（`dp(i,j)` 的缓存），再加上递归栈深度 `O(n)`。

### 2. 最优解

#### 思路  

暴力 DP 的瓶颈在于 **每次合并都要遍历所有划分点**，这导致了 `O(n³)`。  
观察题目可以发现一个重要的性质：

> **任意一次合并，产生的非叶子节点值等于被合并的两个相邻叶子中较大的那个乘以它们之间的“最近更大的叶子”。**  

换句话说，如果我们把数组从左到右扫描，并始终把 **较小的叶子先与它最近的更大叶子合并**，就能得到最小的总代价。  

这正好对应 **单调递增栈（Monotonic Stack）** 的思想：

1. **维护一个递增栈**，栈里保存已经“处理过”的叶子值，栈顶永远是最近的、比当前元素大的叶子。  
2. 当遍历到新元素 `x` 时：  
   - 若栈顶 `stack[-1] ≤ x`，说明栈顶是**较小的**叶子，它应该先和左边更大的叶子（即栈的倒数第二个元素）合并，因为把小的先合并可以避免它以后被更大的数“乘”进来，导致更大的费用。  
   - 合并的费用是 `stack[-1] * min(stack[-2], x)`（因为左边更大的可能是栈倒数第二个，也可能是当前的 `x`，取较小的那个）。  
   - 合并后把栈顶弹出，继续比较新的栈顶。  
3. 当栈顶已经大于 `x`，直接把 `x` 入栈。  
4. 扫描结束后，栈中仍可能剩下若干递增的数。此时只需要把相邻的数两两合并即可，费用为 `stack[i] * stack[i+1]`，从左到右累计。

**为什么这样是最优的？**  
- 每次弹出栈顶时，它左边的最近更大的数已经确定（栈倒数第二个），右边的最近更大的数是当前 `x`。  
- 只要把 **较小的数** 与它最近的更大数相乘，就能保证它不会再参与更大的乘积。  
- 这相当于一种 **贪心**：每一步都让当前最小的叶子尽快“消失”，从而避免以后产生更大的费用。  
- 通过数学归纳可以证明，这种贪心策略得到的总代价恰好是所有可能二叉树中最小的。

> **类比**：把一排小球的重量想象成 `arr`，我们要把它们两两粘在一起，粘合的费用是两颗球中较重的那颗的重量乘以另一颗的重量。我们总是先把**最轻的球**和它最近的**更重的球**粘在一起，这样轻球的重量只会乘一次，避免了它以后被更重的球多次乘导致费用暴涨。

#### 代码（Python）

```python
from typing import List

def mctFromLeafValues(arr: List[int]) -> int:
    stack = []          # 单调递增栈，保存尚未合并的叶子值
    total = 0           # 累计非叶子节点的最小和

    for x in arr:
        # 当栈顶元素 <= 当前元素 x 时，说明栈顶是“较小的”，应先与左侧更大的数合并
        while stack and stack[-1] <= x:
            mid = stack.pop()                     # 取出较小的叶子
            # 左侧更大的数是 stack[-1]（若栈空则视为 +∞），右侧更大的数是 x
            # 取两者中较小的作为乘数，保证费用最小
            if stack:
                total += mid * min(stack[-1], x)
            else:
                total += mid * x                  # 栈空时只能与 x 合并
        stack.append(x)                          # 把当前元素压入栈中

    # 扫描结束后，栈中是递增序列，只剩下相邻的数需要合并
    while len(stack) > 1:
        a = stack.pop()
        b = stack[-1]            # 栈顶仍是左侧更大的数
        total += a * b           # 只剩下唯一的合并方式
    return total
```

> **关键行解释**  
> - `while stack and stack[-1] <= x:`：只要栈顶不大于当前数，就说明栈顶是**更小**的叶子，需要先把它“出列”。  
> - `mid * min(stack[-1], x)`：`mid` 左边最近更大的数是 `stack[-1]`，右边最近更大的数是 `x`，取两者的较小值可以让费用最小。  
> - `stack.append(x)`：把当前元素加入单调栈，保持栈从底到顶递增。  
> - 最后 `while len(stack) > 1:`：栈里剩下的数已经是递增的，只能按照相邻顺序合并，费用就是相邻乘积的累加。

#### 复杂度  

- **时间复杂度**：`O(n)`。  
  - 每个元素至多进栈一次、出栈一次，整个过程线性扫描。  
  - **大白话**：数组有多少个数，就走多少步，没有嵌套循环，速度非常快。

- **空间复杂度**：`O(n)`（最坏情况下栈会保存所有元素）。  
  - 只需要一个额外的栈，和输入规模同阶。

## 心得  

- **核心技巧**：**单调栈 + 贪心**，即“把当前最小的叶子先与最近的更大叶子合并”。  
- 这种思路常出现在需要**最小化相邻乘积或相邻差**的题目，例如：  
  1. **LeetCode 1130. Minimum Cost Tree From Leaf Values**（本题）。  
  2. **LeetCode 1120. Maximum Average Subtree**（利用单调栈处理树形结构的局部最优）。  
  3. **LeetCode 42. Trapping Rain Water**（单调栈找左右最近更高的柱子）。  
- **一句话总结**：让**最小的叶子先“嫁给”最近的更大叶子**，就能保证全局费用最小。

## 反思  

- **第一反应**：看到“二叉树、叶子、非叶子节点值 = 最大叶子乘积”，立刻想到**区间 DP**，因为 DP 能把“左右子树”分开递归求解。  
- **最容易踩的坑**：  
  - 忘记对每个子区间求 **最大叶子值**，导致错误的合并费用。  
  - 边界条件处理不当，例如只有两个叶子时直接返回乘积。  
  - 在贪心实现中，忘记在栈为空时把 `mid` 与当前 `x` 直接相乘，会导致 `IndexError`。  
- **下次遇到同类题**：第一步先判断**是否可以用单调栈把“最近更大”关系快速找出来**；如果找不到单调结构，再考虑 `O(n³)` 的 DP。
