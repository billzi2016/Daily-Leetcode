# #970. 强整数 / Powerful Integers

> 难度：中等 · 标签：Hash Table、Math、Enumeration · [LeetCode 链接](https://leetcode.com/problems/powerful-integers/)

---

## 题目（英文原版）

**Description**

Given three integers x, y, and bound, return a list of all the powerful integers that have a value less than or equal to bound.
An integer is powerful if it can be represented as xi + yj for some integers i >= 0 and j >= 0.
You may return the answer in any order. In your answer, each value should occur at most once.

**Examples**

**Example 1:**

```
Input: x = 2, y = 3, bound = 10
Output: [2,3,4,5,7,9,10]
Explanation:
2 = 20 + 30
3 = 21 + 30
4 = 20 + 31
5 = 21 + 31
7 = 22 + 31
9 = 23 + 30
10 = 20 + 32
```

**Example 2:**

```
Input: x = 3, y = 5, bound = 15
Output: [2,4,6,8,10,14]
```

**Constraints**

- 1 <= x, y <= 100
- 0 <= bound <= 106

## 题目（中文翻译）

**题目描述**  
给定三个整数 `x`、`y` 和 `bound`，返回所有满足值 **小于等于** `bound` 的强整数（powerful integer）构成的列表。  
如果一个整数可以表示为 `x^i + y^j`，其中 `i >= 0` 且 `j >= 0` 为整数，则称其为 **强整数**。  
返回的答案顺序任意，但同一数值在结果中最多出现一次。

**示例**

**示例 1**  
输入: `x = 2, y = 3, bound = 10`  
输出: `[2,3,4,5,7,9,10]`  
解释:  
- `2 = 2^0 + 3^0`  
- `3 = 2^1 + 3^0`  
- `4 = 2^0 + 3^1`  
- `5 = 2^1 + 3^1`  
- `7 = 2^2 + 3^1`  
- `9 = 2^3 + 3^0`  
- `10 = 2^0 + 3^2`

**示例 2**  
输入: `x = 3, y = 5, bound = 15`  
输出: `[2,4,6,8,10,14]`  

**约束条件**  
- `1 <= x, y <= 100`  
- `0 <= bound <= 10^6`

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：把所有可能的 `i`（指数）和 `j`（指数）枚举出来，算出  
`value = xⁱ + yʲ`，只要 `value ≤ bound` 就把它记下来。  

- **枚举 i、j**：  
  - `i` 从 0 开始，只要 `xⁱ` 不超过 `bound` 就继续。  
  - `j` 同理，只要 `yʲ` 不超过 `bound` 就继续。  
- **去重**：同一个数可能会出现多次（比如 `2⁰+2⁰ = 2⁰+2⁰`），我们只想要 **不重复** 的结果。  
  - 在 Python 里可以用 `set`（集合）来保存结果，集合的查找/插入都像查字典一样快，键是数值，值相当于“页码”。  

**为什么这样一定能得到全部答案？**  
因为题目要求的 “所有能写成 `xⁱ + yʲ` 且 ≤ bound 的整数”，只要我们把所有合法的 `i、j` 组合穷举一遍，就不会漏掉任何一种写法。

**时间/空间复杂度大白话**  
- `i` 的取值个数大约是 `logₓ(bound)`（因为 `xⁱ` 快速增长），`j` 同理是 `logᵧ(bound)`。  
- 双层循环的次数就是这两个数的乘积，记作 **O(logₓ bound × logᵧ bound)**。  
  - 用大白话说：如果 `bound` 是 1 000 000，`x=2` 时 `log₂ 1e6≈20`，所以最多只会循环 20×20=400 次，完全可以接受。  
- 额外的空间主要是保存结果的集合，最多也就是所有满足条件的数的个数，记作 **O(k)**（k 为答案个数）。

#### 代码（Python）

```python
from typing import List

def powerfulIntegers(x: int, y: int, bound: int) -> List[int]:
    # 用 set 保存不重复的答案，类似查字典，key 是整数本身
    ans = set()

    # i 从 0 开始枚举，直到 x**i 超过 bound
    i = 0
    while True:
        xi = x ** i
        if xi > bound:          # 已经超出上限，后面的 i 更大只会更大，直接退出
            break

        # 对每个 i，枚举所有可能的 j
        j = 0
        while True:
            yj = y ** j
            value = xi + yj
            if value > bound:   # 当前和已经超界，后面的 j 更大只会更大，退出内层循环
                break
            ans.add(value)      # 把结果加入集合，自动去重

            # 特殊情况：当 y == 1 时，y**j 永远是 1，继续循环会无限循环
            if y == 1:
                break
            j += 1

        # 同理，x == 1 时外层也只能跑一次
        if x == 1:
            break
        i += 1

    # 把集合转成列表返回，顺序随意
    return list(ans)
```

#### 复杂度  

- **时间复杂度**：`O(logₓ bound × logᵧ bound)`  
  - 解释：`logₓ bound` 表示 `i` 能取多少次（比如 `x=2, bound=10⁶` 时约 20 次），同理 `logᵧ bound` 表示 `j` 的次数，两者相乘就是总的循环次数。  
- **空间复杂度**：`O(k)`（k 为答案的数量）  
  - 解释：我们只用一个集合存放答案，最多存 `k` 个整数，`k` 最多也就是 `bound` 的大小（实际会少得多）。

### 2. 最优解  

#### 思路  

暴力解已经非常接近最优了，因为题目本身的搜索空间本来就很小（指数增长非常快）。  
要让它更“最优”，只需要在枚举时 **提前结束** 循环，避免不必要的计算，并且把 **去重** 的工作交给集合（哈希表）一次完成。

**慢在哪里**  
- 在最原始的思路里，如果不判断 `xi > bound`、`value > bound` 就一直循环，可能会出现无意义的迭代（尤其是 `x` 或 `y` 为 1 时会陷入无限循环）。  
- 还有就是每次计算 `x**i`、`y**j` 时直接使用 `**` 运算会重复乘法，稍微浪费。

**优化步骤**  

1. **提前停止**  
   - 当 `xi` 超过 `bound`，后面的 `i` 更大只会让 `xi` 更大，直接停止外层循环。  
   - 当 `xi + yj` 超过 `bound`，后面的 `j` 更大只会让和更大，直接停止内层循环。  

2. **增量乘法**  
   - 用变量保存上一轮的 `xⁱ`（或 `yʲ`），下一轮只需要乘以 `x`（或 `y`），避免每次都重新幂运算。  

3. **哈希表去重**  
   - Python 的 `set` 本质是哈希表，查找/插入都是 **O(1)**，相当于一本“查字典”，键是数值，出现一次就记下来，第二次再出现直接忽略。  

4. **特殊值 1 的处理**  
   - 如果 `x == 1`，`xⁱ` 永远是 1，外层只需要跑一次。  
   - 同理 `y == 1`，内层只需要跑一次。  

以上几步合在一起，就是本题的 **最优枚举** 解法。  

#### 代码（Python）

```python
from typing import List

def powerfulIntegers(x: int, y: int, bound: int) -> List[int]:
    ans = set()                     # 哈希表（集合）自动去重
    xi = 1                          # x 的 i 次方，初始为 x⁰ = 1
    i = 0
    while xi <= bound:              # 只要 xi 本身不超界，就继续尝试
        yj = 1                      # y 的 j 次方，同理从 y⁰ 开始
        j = 0
        while xi + yj <= bound:    # 若当前和已经超界，后面的 j 更大只会更大
            ans.add(xi + yj)        # 加入集合
            if y == 1:              # y 为 1 时，后面不再变化，直接跳出
                break
            yj *= y                  # 增量乘法，得到下一个 yʲ
            j += 1

        if x == 1:                  # x 为 1 时，外层不再变化，直接跳出
            break
        xi *= x                      # 增量乘法，得到下一个 xⁱ
        i += 1

    return list(ans)
```

#### 复杂度  

- **时间复杂度**：`O(logₓ bound + logᵧ bound)`（实际上略小于暴力的乘积）  
  - 解释：外层最多循环 `logₓ bound` 次，内层每次最多循环 `logᵧ bound` 次，但因为我们在每层都提前停止，总的循环次数约等于两者之和。对于本题的约束（`bound ≤ 10⁶`），这几乎是常数时间。  
- **空间复杂度**：`O(k)`（k 为答案个数）  
  - 解释：仍然只用一个集合保存所有不重复的答案，大小随答案而变。

## 心得  

- **核心技巧**：**指数枚举 + 哈希表去重**。  
  - 当题目要求“所有形如 `aⁱ + bʲ` 的数”时，利用指数增长的特性可以把搜索空间压到极小；哈希表帮助我们在枚举过程中自动去重。  

- **适用的题型**  
  1. **Powerful Integers**（本题）  
  2. **K 次幂的和**（比如 `aⁱ + bⁱ`、`aⁱ - bʲ`）  
  3. **有限次幂的组合**（如 `aⁱ * bʲ ≤ limit`）  

- **一句话总结解题钥匙**：  
  > “指数快速增长 → 只需枚举少量 i、j；哈希表一次去重”。

## 反思  

- **第一反应**：看到 “xi + yj” 立刻想到双层循环穷举所有指数组合。  
- **最容易踩的坑**  
  - **无限循环**：当 `x` 或 `y` 为 1 时，`xⁱ`（或 `yʲ`）永远是 1，若不单独处理会导致死循环。  
  - **超界提前结束**：忘记在内层循环判断 `xi + yj > bound`，会产生不必要的计算。  
  - **去重遗漏**：直接把所有值放进列表会出现重复，需要用集合（哈希表）去重。  

- **下次类似题的第一步**：  
  - 先判断 **指数是否会停下来**（即是否为 1），如果是，记得只枚举一次；然后 **用指数的增长速度估计循环上限**，再开始双层枚举并实时检查是否已超界。这样既安全又高效。
