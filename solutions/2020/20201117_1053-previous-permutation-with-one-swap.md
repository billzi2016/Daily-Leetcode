# #1053. 前一个排列（一次交换） / Previous Permutation With One Swap

> 难度：中等 · 标签：Array、Greedy · [LeetCode 链接](https://leetcode.com/problems/previous-permutation-with-one-swap/)

---

## 题目（英文原版）

**Description**

Given an array of positive integers arr (not necessarily distinct), return the lexicographically largest permutation that is smaller than arr, that can be made with exactly one swap. If it cannot be done, then return the same array.
Note that a swap exchanges the positions of two numbers arr[i] and arr[j]

**Examples**

**Example 1:**

```
Input: arr = [3,2,1]
Output: [3,1,2]
Explanation: Swapping 2 and 1.
```

**Example 2:**

```
Input: arr = [1,1,5]
Output: [1,1,5]
Explanation: This is already the smallest permutation.
```

**Example 3:**

```
Input: arr = [1,9,4,6,7]
Output: [1,7,4,6,9]
Explanation: Swapping 9 and 7.
```

**Constraints**

- 1 <= arr.length <= 104
- 1 <= arr[i] <= 104

---

## 题目（中文翻译）

给定一个正整数数组 `arr`（元素不一定唯一），返回字典序（lexicographically）上**小于** `arr` 的**最大**排列，该排列只能通过**恰好一次交换**得到。如果无法完成，则返回原数组。  
注意，**交换**（swap）是指交换两个数 `arr[i]` 和 `arr[j]` 的位置。

**示例 1**  
**输入**: `arr = [3,2,1]`  
**输出**: `[3,1,2]`  
**解释**: 交换 `2` 与 `1`。

**示例 2**  
**输入**: `arr = [1,1,5]`  
**输出**: `[1,1,5]`  
**解释**: 已经是最小的排列，无法再得到更小且字典序更大的排列。

**示例 3**  
**输入**: `arr = [1,9,4,6,7]`  
**输出**: `[1,7,4,6,9]`  
**解释**: 交换 `9` 与 `7`。

**约束条件**

- `1 <= arr.length <= 10^4`
- `1 <= arr[i] <= 10^4`

---

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  
最直接的想法是：**把所有可能的两两交换都尝试一遍**，看哪一次换出来的数组既比原数组小（字典序更靠前），又是所有合法结果中最大的（字典序最靠后）。  

- **数据结构**：我们只需要原数组 `arr` 本身以及临时的 “交换后” 的新数组。把数组想象成一排编号的盒子，交换就是把两个盒子里的东西互换位置。  
- **为什么正确**：因为题目只允许 **恰好一次** 交换，所有合法的答案必然出现在“所有两两交换”的集合里。只要遍历完整个集合，取满足条件且字典序最大的那一个，就一定是答案。  
- **复杂度分析**：  
  - 需要枚举所有的下标对 `(i, j)`，其中 `i < j`。如果数组长度是 `n`，这样的对数大约是 `n·(n‑1)/2 ≈ O(n²)`。  
  - 对每一对下标，我们要 **复制数组**、**交换**、**比较** 两个数组的字典序。比较两个长度为 `n` 的数组最坏要看完所有元素，时间是 `O(n)`。  
  - 所以总时间是 `O(n²) * O(n) = O(n³)`，也就是“立方级别”。在最坏情况下，如果 `n = 10⁴`，这个方法根本跑不完。  
  - 额外的空间只用来存放临时的复制数组，大小为 `O(n)`。

#### 代码（Python）

```python
from copy import deepcopy
from typing import List

def previousPermutationBrute(arr: List[int]) -> List[int]:
    """
    暴力枚举所有一次交换的可能，返回满足条件的最大字典序数组。
    """
    n = len(arr)
    best = arr[:]                     # 先把原数组当作“最差”答案
    # 枚举所有 i < j 的下标组合
    for i in range(n):
        for j in range(i + 1, n):
            # 复制一份，交换 i、j 位置的元素
            cand = arr[:]
            cand[i], cand[j] = cand[j], cand[i]

            # 如果 cand 小于原数组（字典序更靠前），且大于当前 best，
            # 就更新答案。Python 的列表比较已经是字典序比较。
            if cand < arr and cand > best:
                best = cand
    return best
```

#### 复杂度  

- **时间复杂度**：`O(n³)`  
  - `n²` 个下标对 × `O(n)` 的字典序比较。  
  - “立方级别”意味着当 `n` 达到几千甚至上万时，程序会非常慢。  
- **空间复杂度**：`O(n)`  
  - 需要额外存一份临时数组（长度 `n`）来做交换和比较。

### 2. 最优解  

#### 思路  

暴力解慢的根源在于 **“枚举所有可能”**。其实我们只需要一次**贪心**的选择，就能直接定位到唯一的最佳交换位置。下面一步步推导：

1. **找第一个下降点**  
   从右往左扫描数组，找到第一个满足 `arr[i] > arr[i+1]` 的位置 `i`。  
   - 为什么要从右边开始？因为字典序的比较是从左到右进行的，**左侧的改变对整体顺序的影响最大**。如果从右边已经是非递增的（即 `arr[i] ≤ arr[i+1]`），把它们换一下也不会让整体更小。  
   - 这个 `i` 就是“左边需要变小”的位置。

2. **在右侧找一个合适的元素**  
   在下标 `i` 右边（`i+1 … n-1`）的子数组里，找 **比 `arr[i]` 小** 的最大元素 `arr[j]`，并且要 **最左**（最靠近 `i`）的那个出现位置。  
   - “比 `arr[i]` 小的最大元素”保证交换后仍然尽可能接近原数组（不至于把整体往太前面拉）。  
   - “最左出现”是为了避免因重复值导致的多余交换。例如 `[1,9,4,4,7]`，`i` 可能是 `1`（值 9），右侧有两个 `4`，我们只能选最左的那个，否则换到更右的 `4` 会得到相同的结果但违背 “左侧尽量小” 的原则。

3. **执行一次交换**  
   把 `arr[i]` 与找到的 `arr[j]` 交换即可。此时得到的数组是 **字典序小于原数组且最大的**。如果在步骤 1 找不到下降点，说明数组已经是 **非递减**（最小排列），直接返回原数组。

> **类比**：把数组想成一排高度不同的砖块。我们想让整体“往左倾斜”一点点，但只能搬动一块砖。先找最左侧的那块可以往左搬的砖（第一个下降点），再在它右边挑一块比它稍矮、但最高的砖来换，这样倾斜幅度最小，整体仍然保持尽可能高。

#### 代码（Python）

```python
from typing import List

def previousPermutation(arr: List[int]) -> List[int]:
    """
    贪心一次交换得到字典序紧邻且更小的排列。
    时间 O(n) ，空间 O(1)（原地修改）。
    """
    n = len(arr)

    # 1. 从右往左找到第一个 arr[i] > arr[i+1] 的位置 i
    i = n - 2
    while i >= 0 and arr[i] <= arr[i + 1]:
        i -= 1

    # 如果没有找到，说明已经是最小排列，直接返回
    if i < 0:
        return arr

    # 2. 在 i 右侧寻找「比 arr[i] 小且最大的」元素
    #    同时因为可能有重复值，记录最左出现的位置
    j = n - 1
    while j > i and arr[j] >= arr[i]:
        j -= 1          # 跳过所有不小于 arr[i] 的元素

    # 此时 arr[j] < arr[i]，但可能还有相同的更左的值
    # 继续左移，直到找到最左的那个「等于 arr[j]」的下标
    while j - 1 > i and arr[j - 1] == arr[j]:
        j -= 1

    # 3. 交换 i 与 j
    arr[i], arr[j] = arr[j], arr[i]
    return arr
```

#### 复杂度  

- **时间复杂度**：`O(n)`  
  - 只需要一次线性扫描找到下降点 `i`，再一次线性扫描（最坏遍历右侧全部元素）定位 `j`。整个过程是“走两遍路”，所以是线性时间。  
  - 与暴力的 `O(n³)` 相比，提升了几个数量级，能轻松处理 `10⁴` 长度的数组。

- **空间复杂度**：`O(1)`  
  - 只用了常数个额外变量（`i、j`），在原数组上直接完成交换，不需要额外的数组拷贝。

## 心得  

- **核心技巧**：**一次贪心定位**——先找左侧第一个下降点，再在右侧挑选比它小的最大值（并去重）。  
- **适用的题型**：  
  1. *Next Permutation*（下一排列）——思路相反，需要找第一个上升点并换成更大的最小值。  
  2. *Maximum Swap*（一次交换得到最大数）——在找最大数时，同样是左侧找第一个可以提升的点，右侧找最大值。  
  3. *Lexicographically Smallest Subsequence*（字典序最小子序列）——贪心挑选最左可行的字符。  
- **一句话总结**：  
  > **“左侧先降，右侧换成稍小的最大值”** 就是一次交换得到前一排列的钥匙。

## 反思  

- **第一反应**：看到“只允许一次交换”，立刻想到“枚举所有两两交换”。这是一种安全但低效的直觉。  
- **最容易踩的坑**：  
  1. **重复数字**：如果右侧有多个相同的候选值，必须选最左边的那个，否则会错过更大的字典序结果。  
  2. **全局递增数组**（如 `[1,2,3]`）没有下降点，需要直接返回原数组。  
  3. **边界条件**：数组长度为 1 时，循环要能正常结束，返回自身。  
- **下次类似题目第一步**：  
  > **先判断数组的“单调趋势”**（从左往右/从右往左的递增/递减），定位唯一的“关键位置”，再在对应方向寻找合适的替换元素。这样往往可以把“枚举”转化为“一次扫描”。
