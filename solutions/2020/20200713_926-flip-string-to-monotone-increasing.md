# #926. 翻转字符串使其单调递增 / Flip String to Monotone Increasing

> 难度：中等 · 标签：String、Dynamic Programming · [LeetCode 链接](https://leetcode.com/problems/flip-string-to-monotone-increasing/)

---

## 题目（英文原版）

**Description**

A binary string is monotone increasing if it consists of some number of 0's (possibly none), followed by some number of 1's (also possibly none).
You are given a binary string s. You can flip s[i] changing it from 0 to 1 or from 1 to 0.
Return the minimum number of flips to make s monotone increasing.

**Examples**

**Example 1:**

```
Input: s = "00110"
Output: 1
Explanation: We flip the last digit to get 00111.
```

**Example 2:**

```
Input: s = "010110"
Output: 2
Explanation: We flip to get 011111, or alternatively 000111.
```

**Example 3:**

```
Input: s = "00011000"
Output: 2
Explanation: We flip to get 00000000.
```

**Constraints**

- 1 <= s.length <= 105
- s[i] is either '0' or '1'.

---

## 题目（中文翻译）

给定一个**二进制字符串**（binary string）`s`。如果一个二进制字符串先出现若干个 `0`（可以为零个），随后出现若干个 `1`（也可以为零个），则称其为**单调递增**（monotone increasing）。

你可以对 `s[i]` 进行**翻转**（flip），即将 `0` 改为 `1`，或将 `1` 改为 `0`。返回使 `s` 成为单调递增所需的最少翻转次数。

## 示例

### 示例 1
> **输入**: `s = "00110"`  
> **输出**: `1`  
> **解释**: 我们将最后一个字符翻转为 `1`，得到 `00111`。

### 示例 2
> **输入**: `s = "010110"`  
> **输出**: `2`  
> **解释**: 可以翻转得到 `011111`，或翻转得到 `000111`。

### 示例 3
> **输入**: `s = "00011000"`  
> **输出**: `2`  
> **解释**: 我们将其中的两个 `1` 翻转为 `0`，得到 `00000000`。

## 约束条件

- `1 <= s.length <= 10^5`
- `s[i]` 仅为字符 `'0'` 或 `'1'`。

---

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**把字符串划分成两段**，左边全是 `0`，右边全是 `1`。  
对每一种划分方式（包括「左边全是 `0`，右边为空」和「左边为空，右边全是 `1`」），统计：

* 左边本来是 `1` 的位置，需要翻成 `0` → 这是一种翻转
* 右边本来是 `0` 的位置，需要翻成 `1` → 这也是一种翻转  

把这两部分翻转次数相加，就是该划分下的总代价。把所有划分的代价都算一遍，取最小值即可。

> **类比**：把哈希表想象成一本字典，`key` 是单词，`value` 是页码。这里我们不需要字典，只是逐个检查每个位置是否「符合」我们想要的「左0右1」规则，就像逐页翻看字典找错别字一样。

**正确性**：  
因为单调递增的二进制串只能是「若干个 `0`」后接「若干个 `1`」，必然可以在某个切点把它分成「左全 `0`」+「右全 `1`」两段。遍历所有切点就一定能找到最优的切点，所以最小翻转次数一定会被我们算到。

**为什么是暴力**：  
我们对每个切点都要重新遍历整条字符串去统计左侧的 `1` 与右侧的 `0`，这会导致 **二次循环**（外层 `n` 种切点，内层每次最多 `n` 次检查），时间会随字符串长度的平方增长。

#### 代码（Python）

```python
def minFlipsMonoIncr_bruteforce(s: str) -> int:
    n = len(s)
    ans = float('inf')                     # 用一个很大的数先存答案
    # 切点 i 表示左侧是 s[0:i]，右侧是 s[i:n]（i 可以取到 0 和 n）
    for i in range(n + 1):
        flips = 0
        # 统计左侧需要把 1 翻成 0 的次数
        for j in range(i):
            if s[j] == '1':
                flips += 1
        # 统计右侧需要把 0 翻成 1 的次数
        for j in range(i, n):
            if s[j] == '0':
                flips += 1
        ans = min(ans, flips)              # 取最小值
    return ans
```

#### 复杂度  

- **时间复杂度**：`O(n²)`  
  - 这里的 `n²` 不是数学符号的抽象，而是说：如果字符串有 10,000 个字符，程序大概会执行 100,000,000 次「检查」操作，明显会超时。  
- **空间复杂度**：`O(1)`  
  - 只用了几个计数器，和字符串长度无关。

### 2. 最优解

#### 思路  

从暴力解可以看到，**真正的瓶颈在于每次切点都要重新遍历整条字符串**。如果我们能在一次遍历中把所有切点的翻转次数算出来，就能把 `O(n²)` 降到 `O(n)`。

**关键观察**：

1. 对于任意切点 `i`，  
   *左侧需要翻的 `1` 的数量* = `prefix_ones[i]`（即 `s[0:i]` 中 `1` 的个数）  
   *右侧需要翻的 `0` 的数量* = `suffix_zeros[i]`（即 `s[i:n]` 中 `0` 的个数）  

2. `prefix_ones` 与 `suffix_zeros` 都可以在 **一次** 扫描中得到。  
   - 从左到右累计出现的 `1`，得到每个位置的前缀 `1` 个数。  
   - 从右到左累计出现的 `0`，得到每个位置的后缀 `0` 个数。  

3. 对每个切点 `i`，翻转次数 = `prefix_ones[i] + suffix_zeros[i]`。只要把这两列数据准备好，遍历一次即可求出最小值。

**进一步优化**（省去额外数组）：

我们其实不需要把 `suffix_zeros` 全部存下来，只要在遍历时维护一个变量 `zeros_on_right`，它表示当前切点右边还有多少 `0` 未被处理。遍历顺序可以是 **从左到右**，并在每一步更新答案。

具体实现思路（类似动态规划）：

- `flip_to_all_zero`：把已经遍历过的前缀全部变成 `0`，需要的最小翻转次数。  
- `flip_to_monotone`：把已经遍历过的前缀变成「0…0 1…1」的最小翻转次数（即我们最终想要的形式）。  

遍历每个字符 `c`：

1. 如果 `c` 是 `'0'`，把它保持为 `0` 不需要额外操作；但如果我们想让前缀已经是「0…01…1」并且把这个 `0` 当作 `1`（即把它翻成 `1`），则需要一次翻转。  
2. `flip_to_all_zero` 只会在遇到 `'1'` 时加一（把 `1` 翻成 `0`）。  
3. `flip_to_monotone` 的更新公式为：  
   `flip_to_monotone = min(flip_to_all_zero, flip_to_monotone) + (c == '0')`  
   - `min(flip_to_all_zero, flip_to_monotone)` 表示：在当前位置我们可以选择「把左边全部变成 `0`」或「已经保持单调」这两种状态中更好的那一个。  
   - `+ (c == '0')` 表示如果当前字符是 `0`，而我们希望它在「1」的区间里，就必须翻一次。

遍历结束后，`flip_to_monotone` 即为答案。

> **类比**：想象你在排队买票，前面的人可以是「只买儿童票」(`0`) 或者「只买成人票」(`1`)。每来一个新顾客，你可以决定是继续卖儿童票（把所有出现的成人票翻成儿童票），还是开始卖成人票（把后面出现的儿童票翻成成人票）。我们只需要记住两种状态的最小费用，随时取最小即可。

#### 代码（Python）

```python
def minFlipsMonoIncr(s: str) -> int:
    """
    最优解：一次遍历 O(n) 时间，O(1) 额外空间。
    """
    flip_to_all_zero = 0   # 已遍历部分全部变成 0 的最少翻转次数
    flip_to_monotone = 0   # 已遍历部分满足 0…0 1…1 的最少翻转次数

    for ch in s:
        if ch == '1':
            # 把当前的 1 保持为 1，不需要额外翻转；但如果要把它变成 0，需要一次翻转
            flip_to_all_zero += 1
        # 无论是 0 还是 1，都要更新 flip_to_monotone
        # 1) 取两种状态中更小的那个作为基准
        # 2) 如果当前是 0 并且我们已经进入 “全是 1” 的阶段，需要再翻一次
        flip_to_monotone = min(flip_to_all_zero, flip_to_monotone) + (ch == '0')
        # 这里 (ch == '0') 会返回 True/False，Python 会把 True 当成 1，False 当成 0

    return flip_to_monotone
```

#### 复杂度  

- **时间复杂度**：`O(n)`  
  - 只遍历了一遍字符串，`n` 是字符个数。比如长度 100,000 的串，只会执行约 100,000 次简单的加法/比较，几乎是瞬间完成。  
- **空间复杂度**：`O(1)`  
  - 只用了几个整数变量，和字符串长度无关。即使使用前缀/后缀数组，也只需要 `O(n)` 的额外空间；这里的写法更省内存。

## 心得

- **核心技巧**：把「把左边全部变成 0」和「把左边已经是单调」这两种状态分别维护，用 **状态转移**（动态规划）或 **前缀/后缀计数** 的方式一次遍历求最小翻转次数。  
- **适用的题型**  
  1. 「把数组/字符串变成单调递增/递减」类（如 LeetCode 1827 `Maximum Number of Accepted Invitations` 的类似思路）。  
  2. 「最小删除/翻转使序列满足某种前后关系」类（如 `Minimum Deletions to Make String Balanced`）。  
  3. 「前缀和 + 取最小值」的最优子结构问题（如 `Minimum Size Subarray Sum` 的滑动窗口变体）。  
- **一句话总结**：**把问题拆成「左边全 0」和「右边全 1」两块，用一次遍历累计前缀的 `1` 与后缀的 `0`，取最小即得**。

## 反思

- **第一反应**：直接枚举切点并统计翻转次数——这就是暴力解。  
- **最容易踩的坑**  
  - 忘记考虑切点在最左或最右的情况（全部是 `0` 或全部是 `1`）。  
  - 在实现前缀/后缀计数时，容易把「左侧的 `1`」和「右侧的 `0`」搞混，导致翻转次数算错。  
  - 对于 `O(1)` 状态转移的 DP，需要注意 `min(flip_to_all_zero, flip_to_monotone)` 的顺序，防止出现负数或错误的累计。  
- **下次遇到同类题**：第一步先思考「能否把整个序列划分为两段」或「能否用前缀/后缀统计来一次遍历求解」，再决定是用前缀数组还是状态转移的 DP。这样可以迅速跳出暴力思路，锁定 `O(n)` 解法的方向。
