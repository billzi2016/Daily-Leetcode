# #949. 给定数字的最大时间 / Largest Time for Given Digits

> 难度：中等 · 标签：Array、String、Backtracking、Enumeration · [LeetCode 链接](https://leetcode.com/problems/largest-time-for-given-digits/)

---

## 题目（英文原版）

**Description**

Given an array arr of 4 digits, find the latest 24-hour time that can be made using each digit exactly once.
24-hour times are formatted as "HH:MM", where HH is between 00 and 23, and MM is between 00 and 59. The earliest 24-hour time is 00:00, and the latest is 23:59.
Return the latest 24-hour time in "HH:MM" format. If no valid time can be made, return an empty string.

**Examples**

**Example 1:**

```
Input: arr = [1,2,3,4]
Output: "23:41"
Explanation: The valid 24-hour times are "12:34", "12:43", "13:24", "13:42", "14:23", "14:32", "21:34", "21:43", "23:14", and "23:41". Of these times, "23:41" is the latest.
```

**Example 2:**

```
Input: arr = [5,5,5,5]
Output: ""
Explanation: There are no valid 24-hour times as "55:55" is not valid.
```

**Constraints**

- arr.length == 4
- 0 <= arr[i] <= 9

## 题目（中文翻译）

给定一个长度为 4 的数组 **arr**，其中每个元素都是一位数字，求使用每个数字恰好一次能够组成的最晚的 **24 小时制时间 (24-hour time)**。  
**24 小时制时间** 的格式为 `"HH:MM"`，其中 `HH` 的取值范围是 `00` 到 `23`，`MM` 的取值范围是 `00` 到 `59`。最早的时间是 `00:00`，最晚的时间是 `23:59`。  

返回上述格式的最晚时间字符串。如果无法组成合法的时间，返回空字符串 `""`。

**示例 1**  
```text
Input: arr = [1,2,3,4]
Output: "23:41"
Explanation: 合法的 24 小时制时间有 "12:34"、"12:43"、"13:24"、"13:42"、"14:23"、"14:32"、"21:34"、"21:43"、"23:14" 和 "23:41"。其中 "23:41" 是最晚的。
```

**示例 2**  
```text
Input: arr = [5,5,5,5]
Output: ""
Explanation: 没有合法的 24 小时制时间，因为 "55:55" 并不符合时间规则。
```

**约束条件**  
- `arr.length == 4`  
- `0 <= arr[i] <= 9`   (每个元素都是 0 到 9 的整数)

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  
最直接的想法是：把四个数字全排列，得到所有可能的排列组合（共 4! = 24 种），然后把每一种排列解释成时间 `HH:MM`，检查是否合法（`00 ≤ HH ≤ 23` 且 `00 ≤ MM ≤ 59`），合法的就记录下来，最后挑出最大的那个。  

- **用到的数据结构**：  
  - **列表（list）**：存放原始的四个数字。  
  - **排列（permutation）**：相当于把数字一个一个抽出来排成一行，类似把四张不同颜色的卡片摆成一排，每张卡片只能用一次。  
  - **字符串（str）**：把合法的时间拼成 `"HH:MM"`，方便比较大小。  

- **为什么正确**：  
  因为题目要求**每个数字恰好使用一次**，全排列正好枚举了所有满足“每个数字使用一次”的可能顺序。只要我们把每一种顺序按照时间的规则验证一次，就不会漏掉任何合法答案，也不会误把非法答案算进去。

- **复杂度分析（大白话）**：  
  - **时间复杂度**：我们要遍历所有 `4! = 24` 种排列，每一种都要做常数次检查（把两位数转成整数、比较范围），所以整体是 `O(24) = O(1)`，在理论上是常数时间。但如果把 “4” 换成 “n”，枚举全排列的复杂度是 `O(n!)`（阶乘），意思是随着数字个数的增加，可能的排列会“爆炸式”增长。  
  - **空间复杂度**：除了存放原数组和临时的排列外，只需要常数级别的额外空间 `O(1)`（返回的字符串不算在额外空间里），所以也是常数。

#### 代码（Python）

```python
import itertools  # itertools.permutations 能一次性生成所有排列

def largestTimeFromDigits(arr):
    """
    暴力枚举所有排列，挑出合法且最大的时间
    """
    max_time = -1               # 用整数表示的最大时间，-1 表示还没有找到合法时间
    best_str = ""               # 最终要返回的字符串形式

    # 生成所有 4! = 24 种排列，每个排列是一个元组，如 (2, 3, 1, 4)
    for perm in itertools.permutations(arr):
        hour = perm[0] * 10 + perm[1]   # 前两位组成小时
        minute = perm[2] * 10 + perm[3] # 后两位组成分钟

        # 检查是否合法：00~23 的小时，00~59 的分钟
        if 0 <= hour < 24 and 0 <= minute < 60:
            total = hour * 60 + minute   # 把时间统一转成“分钟数”，方便比较大小
            if total > max_time:          # 找到更大的合法时间
                max_time = total
                best_str = f"{hour:02d}:{minute:02d}"  # 按两位数格式化，例如 5 -> "05"

    return best_str   # 若没有合法时间，best_str 仍为空串
```

#### 复杂度  

- **时间复杂度**：`O(4! ) = O(24) = O(1)`。  
  大白话：只需要检查 24 种可能，几乎瞬间就能算完。  
- **空间复杂度**：`O(1)`（不计返回字符串）。  
  大白话：只用了几个临时变量，内存占用几乎可以忽略不计。

### 2. 最优解  

#### 思路  

虽然暴力已经是常数时间，但从算法设计的角度，我们仍然可以思考“为什么这 24 种排列里只有极少数是合法的”，并尝试**直接构造**最大的合法时间，避免遍历全部排列。思路步骤如下：

1. **先确定小时的十位**  
   - 小时的十位只能是 `0, 1, 2`，因为 24 小时制最大是 `23`。  
   - 为了让时间尽可能大，我们希望十位选最大的可用数字。于是从 `2 → 1 → 0` 依次尝试，看数组里是否还有该数字。

2. **确定小时的个位**  
   - 若十位是 `2`，个位只能是 `0~3`（否则会超过 23）。  
   - 若十位是 `0` 或 `1`，个位可以是 `0~9`（只要该数字在剩余数组中）。  
   - 同样我们希望选最大的可用数字，按从大到小遍历候选集合。

3. **确定分钟的十位**  
   - 分钟十位只能是 `0~5`（因为 59 分）。在剩余的数字中挑选最大的。

4. **确定分钟的个位**  
   - 剩下唯一的数字自然就是个位。

如果在某一步找不到符合条件的数字，就**回溯**到上一步，尝试下一个较小的候选。因为数字只有四个，回溯的深度最多 4，整体仍是常数时间，但思路更像“贪心 + 回溯”。

> **核心概念解释**  
> - **贪心**：每一步都选当前看起来最好的（最大的）数字。因为后面的选择空间会变小，选更大的数字不会导致以后找不到合法组合（这里可以通过枚举证明）。  
> - **回溯**：如果贪心选的数字导致后面无解，就“撤销”这一步，换一个次大的数字再尝试。类似在迷宫里走到死路时回头重新选另一条路。

#### 代码（Python）

```python
def largestTimeFromDigits(arr):
    """
    贪心+回溯构造最大合法时间
    """
    # 为了快速判断某个数字是否还可用，用计数数组（类似字典）保存出现次数
    cnt = [0] * 10          # cnt[d] 表示数字 d 还剩多少个
    for d in arr:
        cnt[d] += 1

    # 下面的四个函数分别尝试填充 HH:MM 的每一位，返回 True 表示成功
    def pick(possible, need):
        """
        在可能的数字集合 possible 中挑选最大的 still >= need 的数字，
        并且该数字在 cnt 中还有剩余。成功后把 cnt 减 1，返回该数字；
        若没有合法数字返回 -1。
        """
        for d in sorted(possible, reverse=True):   # 从大到小遍历
            if cnt[d] > 0:
                cnt[d] -= 1
                return d
        return -1

    # 1) 选小时十位
    for h1 in (2, 1, 0):          # 按从大到小的顺序尝试
        if cnt[h1] == 0:
            continue
        cnt[h1] -= 1               # 暂时使用它

        # 2) 选小时个位
        if h1 == 2:
            hour_units = [3, 2, 1, 0]   # 只能是 0~3
        else:
            hour_units = list(range(9, -1, -1))  # 0~9 都行，后面会倒序检查

        for h2 in hour_units:
            if cnt[h2] == 0:
                continue
            cnt[h2] -= 1

            # 3) 选分钟十位（0~5）
            for m1 in (5, 4, 3, 2, 1, 0):
                if cnt[m1] == 0:
                    continue
                cnt[m1] -= 1

                # 4) 剩下唯一的数字就是分钟个位
                # 找到 cnt 中剩余的那个数字
                for m2 in range(10):
                    if cnt[m2] == 1:   # 正好剩下一个
                        # 把时间拼成字符串返回
                        return f"{h1}{h2}:{m1}{m2}"

                # 若这里没有返回，说明没有合法的 m2，撤销分钟十位的选择
                cnt[m1] += 1

            # 撤销小时个位的选择，继续尝试更小的 h2
            cnt[h2] += 1

        # 撤销小时十位的选择，继续尝试更小的 h1
        cnt[h1] += 1

    # 所有尝试都失败，说明不存在合法时间
    return ""
```

> **代码要点注释**  
> - 使用 `cnt` 计数数组可以在 O(1) 时间判断某个数字是否还可用，比每次 `list.remove()` 更高效。  
> - 四层 `for` 循环对应四位数字的选取，层层回溯，最坏情况仍是遍历所有 24 种排列，但我们在每一步都已经排除了不可能的数字，实际执行更少。  
> - 当找到合法的四位组合后，立即返回，不会继续无意义的搜索。

#### 复杂度  

- **时间复杂度**：`O(1)`（实际常数很小，最多遍历 24 种组合）。  
  与暴力解相比，我们在每一步都提前剪枝，常数因子更低。  
- **空间复杂度**：`O(1)`。只用了固定大小的计数数组和若干局部变量。

## 心得  

- **核心技巧**：  
  1. **全排列（Backtracking）**——在搜索空间不大时，直接穷举是最安全的做法。  
  2. **贪心 + 回溯**——先尝试让每一位尽可能大，再在冲突时回溯，是构造最大合法组合的常用思路。  

- **该技巧适用的题型**（可类比）：  
  - `1736. Find the Latest Time to Catch a Bus`（在给定的时间集合中找最晚的合法时间）。  
  - `1089. Duplicate Zeros`（在数组中按照规则“就地”修改，常用计数/贪心）。  
  - `1799. Maximize Score After N Operations`（在有限操作数下，贪心挑选最大的增益）。  

- **一句话总结解题钥匙**：  
  “先把可行的范围限制下来（小时十位只能是 0~2），再在剩余数字中从大到小贪心挑选，冲突时回溯”。

## 反思  

- **第一反应**：看到“每个数字只能用一次”，立刻想到**排列**；因为数字只有四个，枚举的代价几乎可以忽略不计。  
- **最容易踩的坑**：  
  1. **边界条件**：小时十位是 `2` 时，小时个位只能是 `0~3`；否则会误把 `24:xx` 当成合法。  
  2. **前导零**：时间需要两位显示，如 `01:05`，所以在输出时要用 `{:02d}` 或 `zfill(2)` 保证前导零。  
  3. **返回空串**：全部排列都不合法时必须返回 `""`，而不是 `None` 或 `"00:00"`。  

- **下次遇到同类题**：  
  第一步先**分析每一位的取值范围**（比如时分的合法范围），把搜索空间压缩到最小；随后判断是直接枚举还是“贪心+回溯”更合适。这样既能保证正确性，又能在可能的情况下进一步提升效率。
