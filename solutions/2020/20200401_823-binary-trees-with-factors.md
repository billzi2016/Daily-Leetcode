## 题目（英文原版）

**Description**

Given an array of unique integers, arr, where each integer arr[i] is strictly greater than 1.
We make a binary tree using these integers, and each number may be used for any number of times. Each non-leaf node's value should be equal to the product of the values of its children.
Return the number of binary trees we can make. The answer may be too large so return the answer modulo 109 + 7.

**Examples**

**Example 1:**

```
Input: arr = [2,4]
Output: 3
Explanation: We can make these trees: [2], [4], [4, 2, 2]
```

**Example 2:**

```
Input: arr = [2,4,5,10]
Output: 7
Explanation: We can make these trees: [2], [4], [5], [10], [4, 2, 2], [10, 2, 5], [10, 5, 2].
```

**Constraints**

- 1 <= arr.length <= 1000
- 2 <= arr[i] <= 109
- All the values of arr are unique.

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**把每个数都当成树的根**，然后递归地去找所有可能的左、右子树，使得左子树根值 × 右子树根值 = 当前根的值。  

- **数据结构**：我们把数组 `arr` 放进一个 **哈希表**（相当于一本“查字典”，键是数值，值是它是否在数组里），这样可以在 O(1) 时间内判断一个数是否可以作为子节点。  
- **递归过程**：  
  1. 对根 `root`，遍历 `arr` 中的每个数 `a`，如果 `root % a == 0`（`a` 能整除 `root`），则 `b = root // a` 是可能的右子树根。  
  2. 检查 `b` 是否在哈希表里，若在，则把 **左子树为 `a`、右子树为 `b` 的所有组合** 加入答案。  
  3. 对 `a` 和 `b` 再分别递归，求出它们各自可以组成多少棵子树。  
  4. 最后把所有组合相加，再加上 **只剩根节点本身**（即不拆分的情况）。  

这就是“暴力递归”——把所有可能的因子对都尝试一次。  

- **为什么正确**：每棵合法的二叉树都可以唯一地从根往下分解为左右子树的乘积。递归遍历所有因子对，必然能够穷举出所有合法树。  

- **时间/空间复杂度**：  
  - 每次递归都要遍历整个数组寻找因子对，最坏情况下会产生指数级的递归树（因为同一个子树会被重复计算很多次），时间大约是 **O( n ^ h )**，其中 `h` 是树的高度，最坏可接近 `O(2^n)`。  
  - 递归调用的栈深度最多 `O(n)`，空间主要是递归栈，记作 **O(n)**。  

> 大白话：想象你在找所有能拼出一个数字的“积木块”，每次都把所有积木块重新搬来搬去，根本不记得之前已经搭好哪些子结构，所以会重复搬运，效率极低。

#### 代码（Python）

```python
MOD = 10**9 + 7

def numFactoredBinaryTrees_bruteforce(arr):
    arr_set = set(arr)                 # 哈希表：快速判断一个数是否在数组里
    memo = {}                          # 记忆化搜索，防止部分重复（仍然是暴力的核心）

    def dfs(val):
        """返回以 val 为根的所有合法二叉树数量（包括单节点）"""
        if val in memo:                # 已经算过就直接返回
            return memo[val]

        total = 1                      # 只剩根节点本身这一棵树
        for left in arr:
            if left > val:             # 已排好序的话可以提前结束，这里保持最原始写法
                break
            if val % left == 0:        # left 能整除 val，说明可能是左子树根
                right = val // left
                if right in arr_set:   # 右子树根也必须在数组里
                    total += dfs(left) * dfs(right)   # 左右子树的组合数相乘
                    total %= MOD
        memo[val] = total
        return total

    # 为了让递归更快，先把数组排个序（不影响暴力本质）
    arr.sort()
    ans = 0
    for v in arr:
        ans = (ans + dfs(v)) % MOD
    return ans
```

#### 复杂度

- **时间复杂度**：近似指数级 `O(2^n)`（因为大量重复子树会被重复计算）。  
- **空间复杂度**：`O(n)`（递归栈 + 记忆化表），但实际使用的时间远大于这点。

### 2. 最优解

#### 思路  

从暴力解可以看到，**瓶颈在于大量的重复计算**：同一个数 `x` 的子树数量会在不同的根的递归里被反复求解。  
我们可以把“每个数能组成多少棵树”这件事 **预先算好并保存**，后面再直接查表，避免重复。

核心思路：

1. **排序 + 动态规划**  
   - 把 `arr` 按升序排好。这样当我们在计算某个数 `x` 时，所有比 `x` 小的数已经算完，结果已经存进哈希表 `dp`（相当于一本“已经算好的说明书”）。  
2. **哈希表记录每个数的树的种数**  
   - `dp[x]` 初始为 1，表示只剩根节点本身这棵树。  
3. **遍历所有可能的左子树根 `a`（只需遍历到 `x` 为止）**  
   - 若 `x % a == 0`，则右子树根 `b = x // a` 必须也在数组里。  
   - 这时，以 `a` 为左子树、`b` 为右子树的所有组合数是 `dp[a] * dp[b]`（左子树有 `dp[a]` 种，右子树有 `dp[b]` 种，两者独立，乘法原理）。  
   - **注意**：二叉树的左、右子树是有顺序的。如果 `a != b`，`(a,b)` 与 `(b,a)` 会在遍历时分别出现，已经算进去了；如果 `a == b`，则只算一次即可（因为左右相同，乘积只产生一种结构）。  
4. **把所有合法因子对的贡献累加到 `dp[x]`**。  
5. **答案**是所有 `dp[x]` 的和（每个数都可以作为整棵树的根），再对 `10^9+7` 取模。

> 类比：把每个数看成一种“积木”，`dp[x]` 就是“用这种积木能搭出多少种子结构”。我们先把小积木的搭法全部记下来，等到大积木需要用到它们时，就直接翻说明书，而不是重新手工搭。

#### 代码（Python）

```python
from typing import List

MOD = 10**9 + 7

def numFactoredBinaryTrees(arr: List[int]) -> int:
    arr.sort()                         # 从小到大处理，保证子问题已经算好
    dp = {}                            # key: 数值，value: 以该数为根的树的种数
    arr_set = set(arr)                 # 哈希表，快速判断右子树是否存在

    for x in arr:
        dp[x] = 1                      # 单节点本身是一棵合法树
        # 枚举左子树根 a（只需要遍历到 x 即可，因为 a <= x）
        for a in arr:
            if a > x:
                break
            if x % a == 0:            # a 能整除 x，说明可能是左子树根
                b = x // a            # 对应的右子树根
                if b in arr_set:      # 右子树根必须在数组里
                    # 左右子树的组合数相乘
                    dp[x] = (dp[x] + dp[a] * dp[b]) % MOD
                    # 当 a != b 时，(b, a) 这组会在后面的循环中再次出现，
                    # 正好把两种顺序都算进来了；a == b 时只会算一次，符合要求。
    # 所有可能的根加起来就是答案
    return sum(dp.values()) % MOD
```

#### 复杂度

- **时间复杂度**：`O(n^2)`  
  - 外层遍历 `n` 个数，内层最多遍历前面的 `n` 个数寻找因子对，整体是平方级。  
  - 大白话：如果有 1000 个数，最多要比较 1,000,000 次，这在机器上是完全可以接受的。  
- **空间复杂度**：`O(n)`  
  - 哈希表 `dp`、`arr_set` 各保存 `n` 条记录，随 `n` 成线性增长。  

> 与暴力解对比：我们把“每个数能组成多少棵树”这件事只算 **一次**，从指数级降到平方级，速度提升几个数量级。

## 心得

- **核心技巧**：**排序 + 动态规划 + 哈希表**，把子问题的答案缓存下来，避免重复计算。  
- **适用的题型**：  
  1. **乘法因子树**（本题）  
  2. **乘积为目标的子序列计数**（如 LeetCode 1711. 大整数的乘积）  
  3. **使用因子关系的组合计数**（如 “数组的乘积是给定数的子集计数”）  
- **一句话总结**：**把“小树的搭法”记下来，面对“大树时直接查表”。**

## 反思

- **第一反应**：看到“根 = 左子 * 右子”，立刻想到“因子分解”，于是想用递归枚举所有因子对。  
- **最容易踩的坑**  
  - **忘记取模**：答案可能非常大，所有加法、乘法都要及时 `% MOD` 防止溢出。  
  - **顺序计数**：左、右子树是有顺序的，需要把 `(a,b)` 与 `(b,a)` 都算上（除 `a==b` 时只算一次）。  
  - **遗漏单节点**：每个数本身也算一棵合法树，`dp[x]` 必须初始化为 1。  
- **下次遇到同类题**：第一步先 **排序**，再 **用哈希表保存已计算的子问题**，最后 **用 DP 累加因子对的贡献**。这样思路清晰、实现不易出错。
