## 题目（英文原版）

**Description**

A game on an undirected graph is played by two players, Mouse and Cat, who alternate turns.
The graph is given as follows: graph[a] is a list of all nodes b such that ab is an edge of the graph.
The mouse starts at node 1 and goes first, the cat starts at node 2 and goes second, and there is a hole at node 0.
During each player's turn, they must travel along one edge of the graph that meets where they are.  For example, if the Mouse is at node 1, it must travel to any node in graph[1].
Additionally, it is not allowed for the Cat to travel to the Hole (node 0).
Then, the game can end in three ways:
Given a graph, and assuming both players play optimally, return

**Examples**

**Example 1:**

```
Input: graph = [[2,5],[3],[0,4,5],[1,4,5],[2,3],[0,2,3]]
Output: 0
```

**Example 2:**

```
Input: graph = [[1,3],[0],[3],[0,2]]
Output: 1
```

**Constraints**

- 3 <= graph.length <= 50
- 1 <= graph[i].length < graph.length
- 0 <= graph[i][j] < graph.length
- graph[i][j] != i
- graph[i] is unique.
- The mouse and the cat can always move.

## 题目（中文翻译）

一场在无向图上的游戏由两名玩家——老鼠（Mouse）和猫（Cat）交替进行。  
图的表示方式如下：`graph[a]` 是所有满足 `a‑b` 为图中一条边的节点 `b` 所构成的列表。  

- 老鼠从节点 `1` 开始，并且先手。  
- 猫从节点 `2` 开始，并且后手。  
- 节点 `0` 为洞（Hole）。  

在每一位玩家的回合中，必须沿着当前所在节点的 **一条边** 移动到相邻的节点。例如，若老鼠位于节点 `1`，则它必须移动到 `graph[1]` 中的任意一个节点。  
另外，**猫** **不能** 移动到洞（节点 `0`）。  

游戏可以通过以下三种方式结束：

1. 老鼠到达洞 `0` → 老鼠获胜。  
2. 猫与老鼠占据同一节点 → 猫获胜。  
3. 游戏进行的回合数超过 `2 * n`（`n = graph.length`），即出现 **循环** → 平局（Draw）。  

给定图 `graph`，假设双方都采用最优策略，返回游戏结果：

- `1` 表示老鼠获胜  
- `2` 表示猫获胜  
- `0` 表示平局

输出: `0`

**示例 2**  
输入: `graph = [[1,3],[0],[3],[0,2]]`  
输出: `1`

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**把所有可能的走法都穷举**，把游戏看成一棵巨大的决策树：

1. **状态** = (老鼠所在节点 `m`，猫所在节点 `c`，轮到谁走 `turn`)  
   - `turn = 0` 表示老鼠要走，`turn = 1` 表示猫要走。  
2. **递归**：从当前状态出发，枚举所有合法的下一步（老鼠只能走到 `graph[m]` 中的任意节点，猫只能走到 `graph[c]` 中的任意节点且不能走到 0），得到若干子状态。  
3. **终止条件**（最先出现的）  
   - 老鼠走到洞 `0` → 老鼠直接获胜。  
   - 猫和老鼠在同一个节点 (`m == c`) → 猫直接获胜。  
   - 走了太多步（官方题目限定 2·N 步后仍未分出胜负）→ 判为平局。  
4. **返回值**：在每个状态里，**如果轮到老鼠**，它会挑选能让自己**赢**的走法；**如果轮到猫**，它会挑选能让自己**赢**的走法。  

> **类比**：把这棵树想成一盘棋局的“全局搜索”。老鼠和猫就像两个下棋的玩家，分别在自己的回合挑选一条分支。  

为什么这个办法一定能得到答案？因为我们把**所有合法走法**都考虑进来了，只要递归的返回值遵循“玩家追求自己赢”这一原则，最终根状态（老鼠在 1、猫在 2、老鼠先走）的返回值就是双方都玩得最优时的比赛结果。

然而，这种**暴力递归**会产生巨量的重复计算。例如，状态 `(3,5,0)` 可能由不同的走法多次到达，若每次都重新搜索整个子树，时间会爆炸。

#### 代码（Python）

```python
from functools import lru_cache
from typing import List

def catMouseGame_bruteforce(graph: List[List[int]]) -> int:
    N = len(graph)                # 节点总数
    MAX_TURN = 2 * N              # 超过这个回合数判平局

    @lru_cache(None)              # 记忆化搜索，避免完全重复
    def dfs(mouse: int, cat: int, turn: int) -> int:
        """返回值：0=鼠赢，1=猫赢，2=平局"""
        # 1️⃣ 终止条件
        if mouse == 0:            # 老鼠进洞
            return 0
        if mouse == cat:          # 猫抓住老鼠
            return 1
        if turn >= MAX_TURN:      # 超时平局
            return 2

        # 2️⃣ 轮到谁走
        if turn % 2 == 0:         # 老鼠走（turn 为偶数）
            best = 1              # 先假设最差情况：猫赢
            for nxt in graph[mouse]:
                result = dfs(nxt, cat, turn + 1)
                # 老鼠希望得到 0（赢），若出现立即返回
                if result == 0:
                    return 0
                # 若只能得到 2（平），记录下来，继续找更好
                if result == 2:
                    best = 2
            return best           # 没有赢的分支，返回平局或输
        else:                     # 猫走（turn 为奇数）
            best = 0              # 先假设最差情况：鼠赢
            for nxt in graph[cat]:
                if nxt == 0:      # 猫不能进洞
                    continue
                result = dfs(mouse, nxt, turn + 1)
                if result == 1:   # 猫找到必胜分支
                    return 1
                if result == 2:
                    best = 2
            return best           # 猫只能让鼠赢或平局

    return dfs(1, 2, 0)            # 初始状态：鼠在1，猫在2，鼠先走
```

> **关键行中文注释**已在代码中标注。`lru_cache` 相当于“把已经算好的子树结果记下来”，相当于把“查字典”这件事交给哈希表。

#### 复杂度  

- **时间复杂度**：最坏情况仍然是指数级 `O(3^{N})`（每一步都有约 `N` 种选择，深度约 `2N`），因为即使有记忆化，也要遍历所有可能的状态。用大白话说，就是“如果把每个状态想象成一颗树枝，树的高度大约是 2N，分叉度接近 N，树的节点数会呈指数增长”。  
- **空间复杂度**：`O(N³)` 用来存放记忆化的结果（`mouse`, `cat`, `turn` 三维），再加上递归栈的深度 `O(N)`。  

> 暴力解虽然能在 **极小的图**（比如 N ≤ 5）跑通，但对题目给出的 3 ≤ N ≤ 50 完全失效，这就是我们需要**更聪明的办法**的原因。

### 2. 最优解  

#### 思路  

从暴力解可以看到，**状态空间其实是有限的**：  

- 老鼠位置 `m` 有 `N` 种可能  
- 猫位置 `c` 有 `N` 种可能（但不能是 0）  
- 轮到谁走 `turn` 只有两种（老鼠/猫）  

因此总状态数 `≤ N × N × 2 ≈ 5 000`（因为 N≤50），这已经不算大。  
我们可以**不从根向下搜索**，而是**从已知的终局状态向后推**——这叫**逆向拓扑（retrograde analysis）**，在博弈论里常用来求“必胜/必败/平局”状态。

**核心概念**  

| 概念 | 类比 | 解释 |
|------|------|------|
| **状态** | 棋盘的一格 | `(mouse, cat, turn)` |
| **出度** | 从这格可以走到哪些格 | 当前玩家所有合法的下一步数目 |
| **入度** | 能从哪些格走到这格 | 反向的合法一步 |
| **度数 (degree)** | “还有多少选择还未确定结果” | 对每个状态，记录它的**出度**，因为只有当所有子状态都被标记为**对手必胜**时，这个状态才会变成**自己必败** |
| **已知终局** | “已经输赢的格子” | - 老鼠在洞 → 老鼠必胜 (`0`) <br> - 猫抓到老鼠 → 猫必胜 (`1`) |
| **队列 (queue)** | “传播消息的信使” | 把已经确定结果的状态放进去，逐层向前（逆向）传播，更新它们的前驱状态的结果。 |

**逆向传播规则**（以老鼠的回合为例）：

1. **如果轮到老鼠**，而**有任意一个子状态**已经是老鼠必胜 (`0`)，那么当前状态必定是老鼠必胜（因为老鼠会选那条路）。  
2. **如果轮到老鼠**，而**所有子状态**都已经是猫必胜 (`1`)，则当前状态只能是猫必胜（老鼠无路可逃）。  
3. 其余情况（既有未确定的子状态，又没有必胜的子状态）暂时保持“未知”，等后面更多信息再来决定。  

**对猫的回合**同理，只是把“老鼠必胜”和“猫必胜”对调。

**实现步骤**  

1. **初始化**  
   - 为每个状态准备 `color[m][c][turn]`（0=鼠赢，1=猫赢，2=平局，-1=未知）。  
   - 把所有**终局**状态标记好并加入队列。  
   - 同时统计每个状态的 **出度**（合法走法数），存入 `degree[m][c][turn]`。  

2. **BFS（广度优先）**  
   - 每次弹出队首 `state`，遍历它的**前驱状态**（即能一步走到 `state` 的状态）。  
   - 根据当前 `state` 的结果和轮到谁走的规则，决定前驱状态的颜色：  
     - 若前驱轮到的玩家**可以直接得到胜利**（即子状态是自己胜），则前驱立即标记为**自己胜**，入队。  
     - 否则，减小前驱的 `degree`（因为又有一个子状态被证实为**对手必胜**），当 `degree` 变为 0 时，说明**所有子状态都是对手必胜**，于是前驱标记为**对手胜**，入队。  
   - 这样每个状态只会被标记一次，最多被处理一次。  

3. **结束**  
   - 队列空了以后，仍然是 `-1` 的状态说明**无法确定必胜/必败**，按照题目要求视为平局 (`2`)。  
   - 返回初始状态 `(1, 2, 0)` 的颜色即可。  

**复杂度分析（口语化）**  

- **状态总数** ≤ `N * N * 2`（最多 5 000），每个状态最多遍历它的所有前驱。每条边（一次合法移动）在**正向**和**逆向**都只被访问一次，所以整体是 **线性** 的。  
- **时间复杂度**：`O(N³)`（因为在最坏情况下我们要遍历所有 `N²` 对位置的所有出度，出度本身 ≤ `N`），对 N=50 来说约 `125 000` 次操作，完全可以在毫秒级跑完。  
- **空间复杂度**：同样是 `O(N³)` 用来存 `color`、`degree` 以及队列，最多几千个整数，几百 KB 内存。

> 与暴力解相比，**我们把“从根向下搜索”改成了“从叶子向上推”。** 这样每个状态只算一次，不会出现指数级的重复。

#### 代码（Python）

```python
from collections import deque
from typing import List

def catMouseGame(graph: List[List[int]]) -> int:
    """
    返回值：
        0 -> 老鼠必胜
        1 -> 猫必胜
        2 -> 平局（双方都无法强行赢）
    """
    N = len(graph)                     # 节点数
    DRAW = 2
    MOUSE_TURN, CAT_TURN = 0, 1

    # ---------- 1. 初始化 ----------
    # color[m][c][turn] : 0/1/2/ -1（未知）
    color = [[[-1] * 2 for _ in range(N)] for _ in range(N)]
    # degree[m][c][turn] : 当前玩家还有多少未确定的走法
    degree = [[[0] * 2 for _ in range(N)] for _ in range(N)]

    # 计算每个状态的出度（合法走法数）
    for m in range(N):
        for c in range(N):
            # 老鼠回合的出度
            degree[m][c][MOUSE_TURN] = len(graph[m])
            # 猫回合的出度：不能走到洞 0
            degree[m][c][CAT_TURN] = len([n for n in graph[c] if n != 0])

    q = deque()        # BFS 队列，存放已经确定结果的状态

    # ---------- 2. 把所有终局状态标记并入队 ----------
    for i in range(N):
        for turn in (MOUSE_TURN, CAT_TURN):
            # 老鼠进洞 -> 老鼠必胜
            color[0][i][turn] = 0
            q.append((0, i, turn))
            # 猫抓住老鼠 -> 猫必胜（但不包括猫在洞的情况，因为猫永远不能进洞）
            if i != 0:
                color[i][i][turn] = 1
                q.append((i, i, turn))

    # ---------- 3. 逆向拓扑 BFS ----------
    while q:
        mouse, cat, turn = q.popleft()
        cur_res = color[mouse][cat][turn]          # 当前状态的已知结果
        prev_turn = CAT_TURN if turn == MOUSE_TURN else MOUSE_TURN

        # 取所有可以一步走到 (mouse, cat, turn) 的前驱状态
        # 前驱的玩家是 prev_turn
        if prev_turn == MOUSE_TURN:
            # 前驱是老鼠的回合 → 前驱的老鼠位置可以是任意能走到当前 mouse 的节点
            for prev_mouse in graph[mouse]:
                prev_state = (prev_mouse, cat, prev_turn)
                if color[prev_mouse][cat][prev_turn] != -1:
                    continue        # 已经确定过，跳过
                # 老鼠想赢：如果当前子状态是老鼠必胜，则前驱直接标记为老鼠必胜
                if cur_res == 0:    # 子状态是老鼠胜
                    color[prev_mouse][cat][prev_turn] = 0
                    q.append(prev_state)
                else:
                    # 子状态不是老鼠胜 → 把前驱的度数减 1
                    degree[prev_mouse][cat][prev_turn] -= 1
                    # 当所有出度都被标记为「对手必胜」时，前驱只能是「对手必胜」
                    if degree[prev_mouse][cat][prev_turn] == 0:
                        color[prev_mouse][cat][prev_turn] = 1   # 猫必胜
                        q.append(prev_state)
        else:   # prev_turn == CAT_TURN
            # 前驱是猫的回合 → 前驱的猫位置可以是任意能走到当前 cat 的节点（且不能是 0）
            for prev_cat in graph[cat]:
                if prev_cat == 0:          # 猫不能进洞
                    continue
                prev_state = (mouse, prev_cat, prev_turn)
                if color[mouse][prev_cat][prev_turn] != -1:
                    continue
                # 猫想赢：如果子状态是猫必胜，则前驱直接标记为猫必胜
                if cur_res == 1:           # 子状态是猫胜
                    color[mouse][prev_cat][prev_turn] = 1
                    q.append(prev_state)
                else:
                    degree[mouse][prev_cat][prev_turn] -= 1
                    if degree[mouse][prev_cat][prev_turn] == 0:
                        color[mouse][prev_cat][prev_turn] = 0   # 老鼠必胜
                        q.append(prev_state)

    # ---------- 4. 结果 ----------
    # 初始状态：老鼠在 1，猫在 2，老鼠先走
    result = color[1][2][MOUSE_TURN]
    return result if result != -1 else DRAW
```

> **关键行中文注释**已经在代码里标出。  
> - `degree` 相当于“还有多少条路没被证明是对手必胜”。  
> - `q.append` 把**已经确定**的状态“传递消息”给它们的前驱。  
> - 最终 `color[1][2][0]` 就是题目要求的答案。

#### 复杂度  

- **时间复杂度**：`O(N³)`  
  - 每个状态最多入队一次，处理时遍历它的所有前驱（每条边只被访问两次），整体是线性于状态数 + 边数。  
  - 对于 `N ≤ 50`，约 `125 000` 次基本操作，几乎瞬间完成。  

- **空间复杂度**：`O(N³)`  
  - 用来存 `color`、`degree` 两个三维数组以及 BFS 队列。几千个整数，内存占用在几百 KB 以内。  

> 与暴力解相比，**时间从指数级降到了多项式级**，是可以接受的。

## 心得  

- **核心技巧**：**逆向拓扑（retrograde analysis） + 多状态 DP**，即把“已知终局 → 推导前驱”作为求解博弈的框架。  
- **适用的题型**（类似思路）  
  1. **LeetCode 913 – Cat and Mouse**（本题）  
  2. **LeetCode 464 – Can I Win**（数字游戏的必胜必败判定）

- **一句话总结解题钥匙**：*把所有“必输/必赢”的局面先标记好，然后像水波一样向外扩散，直到覆盖到起始局面*。

## 反思  

- **第一反应**：看到“老鼠、猫、洞”以及“交替移动”，自然想到**搜索所有走法**（DFS/递归），于是写出了暴力递归。  
- **最容易踩的坑**  
  1. **猫不能进入洞**：在生成猫的合法走法时必须过滤 `0`，否则会得到错误的终局。  
  2. **平局的判定**：官方规定超过 `2·N` 步仍未分出胜负算平局，暴力解里要额外计数；逆向法里不需要显式计数，因为未被标记的状态自然是平局。  
  3. **状态重复**：忘记记忆化或不使用 `degree` 会导致同一个状态被多次处理，时间爆炸。  
- **下次遇到同类题**：第一步先**明确状态空间的大小**，判断是否可以枚举；如果可以，就**构建出度/入度表**，把终局标记进队列，使用逆向 BFS 求解。这样既保证正确性，又能在多状态博弈中取得线性时间。
