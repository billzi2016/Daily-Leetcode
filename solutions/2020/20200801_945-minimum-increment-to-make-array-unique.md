# #945. 使数组唯一的最小增量 / Minimum Increment to Make Array Unique

> 难度：中等 · 标签：Array、Greedy、Sorting、Counting · [LeetCode 链接](https://leetcode.com/problems/minimum-increment-to-make-array-unique/)

---

## 题目（英文原版）

**Description**

You are given an integer array nums. In one move, you can pick an index i where 0 <= i < nums.length and increment nums[i] by 1.
Return the minimum number of moves to make every value in nums unique.
The test cases are generated so that the answer fits in a 32-bit integer.

**Examples**

**Example 1:**

```
Input: nums = [1,2,2]
Output: 1
Explanation: After 1 move, the array could be [1, 2, 3].
```

**Example 2:**

```
Input: nums = [3,2,1,2,1,7]
Output: 6
Explanation: After 6 moves, the array could be [3, 4, 1, 2, 5, 7].
It can be shown that it is impossible for the array to have all unique values with 5 or less moves.
```

**Constraints**

- 1 <= nums.length <= 105
- 0 <= nums[i] <= 105

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是「把每个已经出现过的数字往后推」：

1. **用集合（set）记录已经出现过的数字**。集合就像一本字典，查一个单词是否在里面的时间是 O(1)（几乎是瞬间），所以我们可以很快判断一个数是否已经被占用了。  
2. **遍历数组中的每个元素**，如果当前数字已经在集合里了（说明已经有别的元素用了这个值），就把它 **+1**，再检查一次，直到找到一个未被占用的数字为止。每加一次就记一次操作次数。  
3. 把最终得到的唯一数字加入集合，继续处理下一个元素。

> 为什么一定能得到正确答案？  
> 因为我们每次只把冲突的数字往更大的方向移动，永远不会让已经唯一的数字再次出现重复。只要把所有冲突都解决，数组自然就全是唯一的。

**时间/空间分析（大白话）**  

- 最坏情况下，数组里全是相同的数字 `0`，长度为 `n`。第 `i` 个数字要加 `i` 次才能找不到冲突，总操作次数是 `0+1+2+…+(n‑1)=O(n²)`。所以时间复杂度是 **O(n²)**，即「平方级」——当 `n` 达到几万时会非常慢。  
- 我们只用了一个集合来存已经占用的数字，集合里最多装 `n` 个元素，空间复杂度是 **O(n)**，即「线性级」——随数组大小等比例增长。

#### 代码（Python）

```python
def min_increment_for_unique(nums):
    occupied = set()          # 用集合记录已经占用的数，相当于“已占用的字典”
    moves = 0                 # 累计需要的移动次数

    for num in nums:          # 逐个处理数组里的每个数
        # 当当前数已经被占用时，向后递增，直到找到一个空位
        while num in occupied:
            num += 1          # 让这个数加 1
            moves += 1        # 操作次数加 1
        occupied.add(num)    # 把最终确定的唯一数放进集合

    return moves
```

#### 复杂度

- **时间复杂度：O(n²)**  
  解释：如果很多数字都重复，需要不断地「+1」并检查集合，这会导致每个元素可能被遍历多次，整体上类似「每个元素都要和后面的每个元素比一次」的情况，数量级是 n 的平方。

- **空间复杂度：O(n)**  
  解释：集合里最多保存 n 个不同的数字，随输入规模线性增长。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**不断地在集合里查找并逐个递增**，尤其是大量重复时会产生大量无意义的循环。我们可以把「找空位」的过程提前做一次，把数组**先排好序**，这样冲突就只会出现在相邻的两个数之间。

1. **先对数组进行排序**（`O(n log n)`），把小的数放前面，大的数放后面。  
2. 从左到右遍历排好序的数组，维护一个变量 `prev` 表示前一个已经处理好的唯一数字。  
   - 若当前数字 `num` **大于** `prev`，说明它本来就不冲突，直接把 `prev = num`。  
   - 若 `num` **小于或等于** `prev`，则必须把它 **提升到 `prev + 1`**，这就是最少的提升次数，因为我们只能往更大的方向移动，`prev + 1` 是当前能取到的最小合法值。移动的步数是 `prev + 1 - num`，累加到答案中。随后更新 `prev = prev + 1`。  
3. 整个过程只遍历一次，时间主要花在排序上。

> 为什么这样是最优的？  
> - 排序后，冲突只能在相邻位置出现，**不需要回头检查更远的元素**。  
> - 每次把冲突的数提升到 `prev + 1`，已经是「最小可能的提升」——如果我们提升得更高，只会让后面的数字需要更大的提升，导致总步数增加。  

**另一种计数法**（基于题目限制 `0 ≤ nums[i] ≤ 10⁵`）是使用「计数数组」或「桶排序」的思路，时间可以降到 **O(n + maxVal)**，但实现上略微复杂，这里先把「排序 + 贪心」的方案作为最优解讲解，已经足够满足 `n ≤ 10⁵` 的要求。

#### 代码（Python）

```python
def min_increment_for_unique(nums):
    nums.sort()                     # O(n log n) 的排序
    moves = 0                       # 累计需要的移动次数
    prev = -1                       # 前一个已经确定的唯一值，初始设为 -1 方便第一个数直接使用

    for num in nums:                # 只遍历一次
        if num > prev:              # 不冲突，直接接受
            prev = num
        else:                       # 冲突，需要提升
            target = prev + 1       # 能取到的最小合法值
            moves += target - num   # 记录提升的步数
            prev = target           # 更新前一个值为提升后的结果

    return moves
```

> **代码要点注释**  
> - `nums.sort()`：把数组排好序，就像把一堆散乱的书按高度从低到高排好。  
> - `prev`：相当于「已经排好队的最后一个人的号码」。  
> - `target = prev + 1`：如果当前人的号码已经被占了，只能让他站在队尾的下一个位置。  
> - `moves += target - num`：记录他需要往后走多少格。

#### 复杂度

- **时间复杂度：O(n log n)**  
  解释：排序是主要耗时步骤，`log n` 相当于「把 n 本书一次分成两堆、再分、再分」的层数，整体比平方级快很多。遍历一次是线性 `O(n)`，不改变数量级。

- **空间复杂度：O(1)（不计输入数组本身）**  
  解释：只用了常数个额外变量 `moves`、`prev`、`target`，不随 `n` 增长。若使用原地排序（Python 的 `list.sort()`），不需要额外的数组。

> 与暴力解对比：时间从 `O(n²)` 降到 `O(n log n)`，在 `n=10⁵` 时能在毫秒级完成；空间也从 `O(n)` 降到几乎不占额外空间。

## 心得

- **核心技巧**：先排序，再贪心地把每个元素提升到「前一个元素 + 1」的最小合法值。  
- **适用场景**：  
  1. 需要使数组元素唯一且只能增大（如「最小增量使数组唯一」）。  
  2. 「把区间合并后最小移动次数」类题目（如「最小移动使数组递增」）。  
  3. 需要对重复元素进行「最小代价」处理的题目（如「最小交换次数使数组有序」的变形）。  
- **一句话总结**：**把数组排好序后，只要把每个冲突的数字提升到前一个已确定数字的下一个即可，这就是最少的提升次数。**

## 反思

- **第一反应**：看到「每次可以把任意元素加 1」，立刻想到「把重复的数字一直往后推」——这就是暴力思路。  
- **最容易踩的坑**：  
  - 忽视了 **边界条件**：数组长度为 1 时直接返回 0；或者所有数字已经唯一时也不需要移动。  
  - 在暴力实现里 **无限循环**：如果忘记把已经处理好的数字加入集合，会导致同一个数一直被加。  
  - 对 **大范围的重复**（比如全部是 0）没有提前考虑时间复杂度，导致超时。  
- **下次类似题目第一步**：先问自己「能否通过一次全局排序把冲突局部化？」如果答案是「可以」，那么后面往往可以用「贪心」一次遍历完成。这样就能把「暴力」的 O(n²) 降到 O(n log n) 或更低。
