# #916. 单词子集 / Word Subsets

> 难度：中等 · 标签：Array、Hash Table、String · [LeetCode 链接](https://leetcode.com/problems/word-subsets/)

---

## 题目（英文原版）

**Description**

You are given two string arrays words1 and words2.
A string b is a subset of string a if every letter in b occurs in a including multiplicity.
A string a from words1 is universal if for every string b in words2, b is a subset of a.
Return an array of all the universal strings in words1. You may return the answer in any order.

**Examples**

**Example 1:**

```
Input: words1 = ["amazon","apple","facebook","google","leetcode"], words2 = ["e","o"]
Output: ["facebook","google","leetcode"]
```

**Example 2:**

```
Input: words1 = ["amazon","apple","facebook","google","leetcode"], words2 = ["lc","eo"]
Output: ["leetcode"]
```

**Example 3:**

```
Input: words1 = ["acaac","cccbb","aacbb","caacc","bcbbb"], words2 = ["c","cc","b"]
Output: ["cccbb"]
```

**Constraints**

- 1 <= words1.length, words2.length <= 104
- 1 <= words1[i].length, words2[i].length <= 10
- words1[i] and words2[i] consist only of lowercase English letters.
- All the strings of words1 are unique.

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**逐个检查** `words1` 中的每个字符串 `a`，看它是否能“容纳” `words2` 中的所有字符串 `b`。  
判断 `b` 是否是 `a` 的子集，只需要把两者的字符计数逐一比较：  
- 统计 `a` 中每个字母出现了多少次（可以用一个长度为 26 的数组或字典来保存，类似把字母表装进一个小抽屉，每个抽屉记下对应字母的数量）。  
- 同理统计 `b` 中每个字母的出现次数。  
- 只要 `b` 中任意字母的次数 > `a` 中对应字母的次数，就说明 `b` 不是 `a` 的子集，直接返回 `False`。

把上面的检查套进两层循环：

1. 外层遍历 `words1`（每个候选字符串 `a`）。  
2. 内层遍历 `words2`（每个必须被包含的字符串 `b`），对每个 `b` 做子集检查。  
3. 只要有一个 `b` 不满足，`a` 就不算“通用”。如果全部 `b` 都满足，就把 `a` 加入答案。

> **类比**：哈希表（或字典）就像一本词典，**key** 是单词（这里是字母），**value** 是对应的解释（这里是出现次数）。我们只需要把两本词典对应的解释比对一下。

这个方法一定能得到正确答案，因为我们把所有可能的组合都检查了一遍，符合题目要求的自然会被挑出来。

#### 代码（Python）

```python
from collections import Counter
from typing import List

def word_subsets_bruteforce(words1: List[str], words2: List[str]) -> List[str]:
    ans = []
    # 预先把 words2 中每个字符串的字符计数算好，避免重复统计
    counters2 = [Counter(b) for b in words2]

    for a in words1:                       # 遍历 candidates
        cnt_a = Counter(a)                # 统计 a 中每个字母出现次数
        universal = True                  # 假设 a 是通用的

        for cnt_b in counters2:           # 检查每个要求的子集 b
            for ch, need in cnt_b.items():   # 对每个字母检查需求
                if cnt_a[ch] < need:         # a 中该字母不够
                    universal = False       # 直接判为不通用
                    break
            if not universal:               # 早停，省掉后面的 b
                break

        if universal:                       # 所有 b 都满足
            ans.append(a)

    return ans
```

#### 复杂度

- **时间复杂度**：`O(|words1| * |words2| * L)`  
  - `|words1|` 为 `words1` 长度，`|words2|` 为 `words2` 长度，`L` 为单个字符串的最大长度（题目限制 ≤ 10）。  
  - 直观上可以把它想成“每个候选要检查每个要求，检查时要遍历最多 10 个字符”。  
- **空间复杂度**：`O(|words2| * 26)`（约等于 `O(|words2|)`）  
  - 需要为 `words2` 中每个字符串保存一个字符计数表（长度固定 26），相当于存几张小纸条。

> 虽然在本题的约束下仍能跑通，但当 `words1`、`words2` 都达到 10⁴ 时，时间会接近 **10⁸ 次**的基本操作，明显有提升空间。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**对每个 `a` 都要重复遍历整个 `words2`**。  
其实我们只需要知道，对于 **每个字母**，在 `words2` 的所有字符串里**需要的最大出现次数**，因为 `a` 只要满足这些最大需求，就一定能容纳 *所有* `b`。

具体步骤：

1. **合并 `words2` 的需求**  
   - 对 `words2` 中的每个字符串 `b`，统计它的字符计数。  
   - 对于同一个字母 `c`，取所有 `b` 中出现次数的**最大值**，记为 `need[c]`。  
   - 这一步相当于把 `words2` “压缩”成一张“最强需求表”。  
   - 例子：`words2 = ["e","o"]` → `need['e']=1, need['o']=1`；`words2 = ["lc","eo"]` → `need['l']=1, need['c']=1, need['e']=1, need['o']=1`。

2. **检查 `words1` 中的每个 `a`**  
   - 统计 `a` 的字符计数 `cnt_a`。  
   - 只要对所有字母 `c` 都满足 `cnt_a[c] >= need[c]`，`a` 就是通用的。  
   - 由于 `need` 只包含 26 个字母，比较过程固定且很快。

这样我们只遍历一次 `words2`（构造 `need`），再遍历一次 `words1`（检验），整体复杂度从 `O(|words1|*|words2|)` 降到 **线性**。

> **类比**：把 `words2` 看成多本“配方书”。每本书里写了需要多少盐、多少糖。我们先把所有配方的需求取最大值，得到“一张总配方”。只要厨房里（字符串 `a`）的材料足够这张总配方，就能一次性满足所有菜谱。

#### 代码（Python）

```python
from collections import Counter
from typing import List

def word_subsets_optimal(words1: List[str], words2: List[str]) -> List[str]:
    # 1️⃣ 统计 words2 中每个字母的最大需求
    need = [0] * 26                 # need[i] 对应字母 chr(ord('a')+i)
    for b in words2:
        cnt = Counter(b)            # b 的字符计数
        for ch, freq in cnt.items():
            idx = ord(ch) - ord('a')
            need[idx] = max(need[idx], freq)   # 取最大值

    # 2️⃣ 检查 words1 中的每个字符串是否满足所有需求
    ans = []
    for a in words1:
        cnt_a = Counter(a)
        ok = True
        for i in range(26):         # 只要有一个字母不够，就不是通用
            if cnt_a.get(chr(i + ord('a')), 0) < need[i]:
                ok = False
                break
        if ok:
            ans.append(a)

    return ans
```

#### 复杂度

- **时间复杂度**：`O(|words1| * L + |words2| * L)`  
  - `L ≤ 10` 为单词长度。  
  - 实际上只遍历两遍数组，各自对每个字符串做一次 O(L) 的计数，整体线性。  
  - 与暴力解相比，省掉了 `|words1| * |words2|` 的乘积，提升显著。

- **空间复杂度**：`O(26)`（即 O(1)）  
  - 只用一张长度为 26 的数组保存最大需求，大小固定，不随输入规模增长。

## 心得

- **核心技巧**：把多个子集需求合并为“每个字母的最大出现次数”。这是一种“需求压缩”思路，常见于**集合覆盖**、**字符统计**类题目。  
- **适用的类似题型**  
  1. **“Find the Difference of Two Arrays”**（求两数组的差集）——也需要对字符计数取最大/最小。  
  2. **“Maximum Number of Words Found in Sentences”**（句子中出现的最多单词数）——利用计数表快速判断。  
  3. **“Maximum Product of Word Lengths”**（单词长度最大乘积）——用位掩码压缩字母集合，类似把信息压缩到固定长度。  
- **一句话总结**：**先把所有约束压成一张“最强需求表”，再逐个验证即可**。

## 反思

- **第一反应**：看到“子集”“出现次数”，马上想到用 `Counter`（或哈希表）逐字比较——这就是暴力思路。  
- **最容易踩的坑**  
  - **漏掉字符的 multiplicity**（出现次数），只检查是否出现而不检查次数会导致错误答案。  
  - **忘记对 `words2` 取最大值**：如果直接把所有需求相加，会把同一字母的需求累加，导致过于严格的条件。  
  - **边界情况**：`words2` 里可能出现只包含同一个字母的多次字符串，需要取最大而不是累计。  
- **下次遇到同类题**，第一步应该思考：**是否可以把多个约束合并成一个固定大小的“需求向量”**（长度为字母表大小、数字为最大出现次数），这样往往能把二次循环降到一次遍历。
