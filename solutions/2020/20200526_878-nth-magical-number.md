# #878. 第 N 个神奇数 / Nth Magical Number

> 难度：困难 · 标签：Math、Binary Search · [LeetCode 链接](https://leetcode.com/problems/nth-magical-number/)

---

## 题目（英文原版）

**Description**

A positive integer is magical if it is divisible by either a or b.
Given the three integers n, a, and b, return the nth magical number. Since the answer may be very large, return it modulo 109 + 7.

**Examples**

**Example 1:**

```
Input: n = 1, a = 2, b = 3
Output: 2
```

**Example 2:**

```
Input: n = 4, a = 2, b = 3
Output: 6
```

**Constraints**

- 1 <= n <= 109
- 2 <= a, b <= 4 * 104

---

## 题目（中文翻译）

正整数如果能够被 **a** 或 **b** 整除，则称其为神奇数（magical number）。  
给定三个整数 **n**, **a**, **b**，返回第 **n** 个神奇数。由于答案可能非常大，请返回其 **模**（modulo）`10^9 + 7` 的结果。

**示例 1**  
**输入**: `n = 1, a = 2, b = 3`  
**输出**: `2`

**示例 2**  
**输入**: `n = 4, a = 2, b = 3`  
**输出**: `6`

**约束条件**  
- `1 <= n <= 10^9`  
- `2 <= a, b <= 4 * 10^4`

---

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**从 1 开始枚举正整数**，每遇到一个能被 `a` 或 `b` 整除的数，就计数一次，等计数器达到 `n` 时把当前的数返回。  
这里用到的唯一“数据结构”是**计数器**，相当于我们在生活中数数：把每一个符合条件的数字当作“一颗星星”，数到第 `n 颗星星` 就停下来。

为什么它是对的？  
只要我们按升序遍历所有正整数，**每一次**检查 `x % a == 0 or x % b == 0` 都能确保不漏掉任何符合条件的数字，也不可能把不符合的数字算进去。于是第 `n` 次满足条件的数，就是题目要的答案。

#### 代码（Python）

```python
def nthMagicalNumber_bruteforce(n: int, a: int, b: int) -> int:
    MOD = 10**9 + 7          # 题目要求的取模
    cnt = 0                  # 已经找到的神奇数字个数
    cur = 1                  # 当前检查的正整数

    while True:
        # 如果 cur 能被 a 或 b 整除，就算作一个神奇数字
        if cur % a == 0 or cur % b == 0:
            cnt += 1
            if cnt == n:     # 第 n 个神奇数字找到了
                return cur % MOD
        cur += 1              # 检查下一个正整数
```

> **关键行注释**  
> - `cur % a == 0 or cur % b == 0`：判断当前数字是否是“神奇”的核心判断。  
> - `cnt == n`：计数器等于目标值时直接返回。

#### 复杂度  

- **时间复杂度**：`O(k)`，其中 `k` 是第 `n` 个神奇数字的大小。最坏情况下 `k` 可能接近 `n * min(a, b)`，所以在题目给的 `n ≤ 10⁹` 时，这种方法根本跑不完。  
- **空间复杂度**：`O(1)`，只用了几个整数变量。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**逐个枚举**，当 `n` 很大时会导致遍历次数天文级别。我们需要一种“跳过无关数字”的办法。  

观察以下两点：

1. **单调性**  
   若 `x` 是第 `n` 个神奇数字，那么所有 ≤ `x` 的神奇数字的数量一定不少于 `n`。相反，如果我们找到了一个 `y`，使得 ≤ `y` 的神奇数字数量已经 ≥ `n`，那么第 `n` 个神奇数字一定 **不大于** `y`。这正好满足二分查找（binary search）所需要的“单调递增”条件。

2. **如何快速统计 ≤ `mid` 的神奇数字个数？**  
   - 能被 `a` 整除的数有 `mid // a` 个。  
   - 能被 `b` 整除的数有 `mid // b` 个。  
   - 但同时能被 `a` 和 `b` 整除的数被统计了两次，需要减去一次。  
   - 同时满足两者的数的公倍数是 **最小公倍数（LCM）**，记作 `lcm(a, b)`，其数量为 `mid // lcm`。  

   因此， ≤ `mid` 的神奇数字个数 = `mid // a + mid // b - mid // lcm`。  
   这一步只用了整数除法和一次 `gcd`（求最大公约数）来算 LCM，**时间是 O(1)**。

基于这两个观察，我们可以**在 `[1, n * min(a, b)]` 的搜索区间上二分**，每次用上面的公式判断中点 `mid` 是否已经包含足够的神奇数字，逐步收敛到最小的满足条件的数，即第 `n` 个神奇数字。

**为什么搜索上界取 `n * min(a, b)`？**  
因为每 `min(a, b)` 的整数里，至少有一个神奇数字（例如 `a = 2, b = 3`，`min=2`，每两个数里必有一个能被 2 整除），所以第 `n` 个神奇数字不会超过 `n * min(a, b)`。这给了我们一个安全的上限。

#### 代码（Python）

```python
import math

def nthMagicalNumber(n: int, a: int, b: int) -> int:
    MOD = 10**9 + 7

    # 1. 计算最小公倍数，使用 gcd 防止溢出
    def lcm(x, y):
        return x // math.gcd(x, y) * y

    L = lcm(a, b)                     # 同时被 a、b 整除的数的间隔

    # 2. 二分搜索
    left, right = 1, n * min(a, b)    # 搜索区间
    while left < right:
        mid = (left + right) // 2

        # 统计 <= mid 的神奇数字个数
        cnt = mid // a + mid // b - mid // L

        if cnt >= n:                  # 已经够了，答案不大于 mid
            right = mid
        else:                         # 不够，需要更大的数
            left = mid + 1

    # left == right 即为第 n 个神奇数字
    return left % MOD
```

> **关键行注释**  
> - `lcm` 函数：先除后乘防止 `a * b` 直接溢出（虽然 Python 整数不溢出，但保持良好习惯）。  
> - `cnt = mid // a + mid // b - mid // L`：核心计数公式，解释见思路。  
> - `if cnt >= n: right = mid`：二分的收敛条件，确保最终得到最小满足 `cnt >= n` 的数。  

#### 复杂度  

- **时间复杂度**：`O(log (n * min(a, b)))`。二分搜索的循环次数等于区间长度的二进制位数，大约是 60 次（因为 `n ≤ 10⁹`），每次只做常数时间的算术运算。相比暴力的线性遍历，快了几个数量级。  
- **空间复杂度**：`O(1)`。只用了若干整数变量，没有额外的数据结构。

## 心得

- **核心技巧**：**二分查找 + 计数公式（利用最小公倍数）**。  
- **适用场景**：  
  1. “第 k 小/大的数” 类问题（如第 k 小的因子、第 k 小的约数等）。  
  2. “满足某种条件的前缀数量” 能用公式快速求出时的二分搜索（如求最小满足 `f(x) ≥ k` 的 `x`）。  
  3. 需要在巨大的搜索空间里定位答案，但可以 **单调判断** 的题目。  

> **一句话总结解题钥匙**：把“在多少范围内有多少个符合条件的数”转化为可直接计算的公式，再用二分定位第 n 个。

## 反思

- **第一反应**：直接把数字一个一个枚举，觉得最安全。  
- **最容易踩的坑**：  
  - **漏算重复计数**：`a` 与 `b` 同时整除的数会被 `mid // a` 和 `mid // b` 各算一次，需要减去 `mid // lcm`。  
  - **搜索上界选错**：若上界太小，二分会找不到答案；若上界太大，仍能跑通，但会让循环次数略增。使用 `n * min(a, b)` 是既安全又紧凑的上界。  
  - **整数溢出**（在 C/C++、Java 等语言中常见）：计算 `a * b` 时可能超过 64 位，需要先除再乘或使用大整数类型。Python 本身不溢出，但保持正确思路仍然重要。  

- **下次遇到同类题**，第一步应该思考：**“能否把‘第 n 个’转化为‘最小满足某单调条件的值’？”** 然后寻找一种 **O(1)** 的方式统计“满足条件的元素个数”，最后用二分搜索定位答案。
