# #869. 重新排列后是 2 的幂 / Reordered Power of 2

> 难度：中等 · 标签：Hash Table、Math、Sorting、Counting、Enumeration · [LeetCode 链接](https://leetcode.com/problems/reordered-power-of-2/)

---

## 题目（英文原版）

**Description**

You are given an integer n. We reorder the digits in any order (including the original order) such that the leading digit is not zero.
Return true if and only if we can do this so that the resulting number is a power of two.

**Examples**

**Example 1:**

```
Input: n = 1
Output: true
```

**Example 2:**

```
Input: n = 10
Output: false
```

**Constraints**

- 1 <= n <= 109

---

## 题目（中文翻译）

给定一个整数 `n`。我们可以将其各位数字任意重新排列（包括保持原顺序），但要求重新排列后的首位数字不能为零。  
如果存在一种排列方式，使得得到的数是 2 的幂（power of two），则返回 `true`；否则返回 `false`。

**示例 1**  
**输入**: `n = 1`  
**输出**: `true`  

**示例 2**  
**输入**: `n = 10`  
**输出**: `false`  

**约束条件**  
- `1 <= n <= 10^9`

---

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把 **n 的所有数字全排列** 都列举出来，挑出那些首位不是 0 的排列，然后逐个判断它们是否是 2 的幂（即能否写成 `2^k`）。  

- **用到的数据结构**：  
  - **列表** 用来保存当前排列的数字序列。  
  - **集合 / 哈希表**（Python 的 `set`）可以帮助我们快速判断一个整数是否是 2 的幂：把所有 `2^k`（k 从 0 开始，只要 `2^k` ≤ 10⁹）事先放进集合里，查找时只要 O(1) 时间。  
  - **哈希表就像查字典**：键（key）是数字本身，值（value）是“在集合里吗”。查一次就能立刻得到答案。

- **为什么这个方法正确**：  
  所有可能的重新排列都被枚举到了，只要其中有一个排列恰好等于某个 `2^k`，我们就会在检查时发现并返回 `True`。没有漏掉的情况，所以必然正确。

- **时间 / 空间复杂度**（大白话解释）：  
  - 假设 `n` 有 `d` 位（`d ≤ 10`，因为 `n ≤ 10⁹`），全排列的个数是 `d!`（比如 5 位数有 120 种排列）。每检查一次需要把排列转成整数并在集合里查找，这一步是 `O(d)`（把字符拼起来）。  
  - 所以总的时间大约是 **O(d! × d)**，在最坏的 10 位数时是 `10! × 10 ≈ 36,288,000` 次操作，虽然在机器上还能跑完，但显然不是最优的。  
  - 空间上我们需要存放 `d!` 个排列（递归栈或临时列表），以及所有 `2^k`（大约 30 个），所以是 **O(d! + log MAX)**，这里的 `log MAX` 只是一小段常数空间。

#### 代码（Python）

```python
import itertools

def reorderedPowerOf2_brute(n: int) -> bool:
    # 预先把所有 2 的幂放进集合，查找 O(1)
    powers = {1 << k for k in range(31)}   # 因为 2^30 ≈ 1e9，足够大于题目上限

    digits = list(str(n))                  # 把整数拆成字符列表，方便排列

    # itertools.permutations 会产生所有可能的排列（包括首位为 0 的情况）
    for perm in itertools.permutations(digits):
        if perm[0] == '0':                 # 首位不能是 0，直接跳过
            continue
        num = int(''.join(perm))           # 把字符元组拼成整数
        if num in powers:                  # 在集合里直接判断是否是 2 的幂
            return True
    return False
```

#### 复杂度

- **时间复杂度**：`O(d! × d)`  
  - `d!` 表示全排列的数量，`d` 表示把每个排列转成整数的代价。  
  - 这里的 `O` 符号可以想象成“随着位数增长，耗时会像阶乘一样快”。

- **空间复杂度**：`O(d! + log MAX)`  
  - `d!` 用来存放递归产生的排列（实际实现里是迭代器，但最坏情况仍然需要栈空间）。  
  - `log MAX`（约 30）是存放所有 2 的幂的集合大小，几乎可以忽略不计。

---

### 2. 最优解

#### 思路  

从暴力解可以看出 **“枚举所有排列”** 是最慢的环节。我们需要找到一种 **不枚举排列** 而直接判断的方法。  

**关键观察**：  
- 两个数如果可以通过重新排列得到彼此，它们的 **每个数字出现的次数** 必须完全相同。  
- 换句话说，只要把一个整数的每个数字的出现次数统计出来（得到一个“数字频率表”），只要另一个整数的频率表和它完全一样，这两个数就一定是互为排列。  

于是我们可以 **把所有可能的 2 的幂的频率表预先算好**，然后只要把 `n` 本身的频率表算出来，和这些预先准备好的表逐一比较，一旦相等就说明可以通过重新排列得到这个 2 的幂。

**实现细节**：

1. **把整数转换成“计数哈希表”**  
   - 想象一本字典：键是数字 `0~9`，值是这个数字出现了几次。  
   - 用 Python 的 `collections.Counter` 或者手写一个长度为 10 的列表都可以。这里用列表，速度更快且更直观。  

2. **预生成所有 2 的幂的计数表**  
   - 只要 `2^k ≤ 10⁹`（因为题目上限是 `10⁹`），`k` 最大到 30（`2^30 = 1,073,741,824` 已经超过上限），所以最多 30 个候选。  
   - 对每个 `2^k`，同样算出它的数字频率表，放进一个列表里保存。  

3. **比较**  
   - 把 `n` 的频率表和每个 2 的幂的频率表逐个比较（列表相等判断在 Python 中是 O(10) 的常数时间）。  
   - 只要找到相同的，就返回 `True`；全部比较完仍未匹配，则返回 `False`。

**为什么这样快**：  
- 我们不再产生 `d!` 种排列，而是只遍历 **最多 30 个候选**（常数），每次比较只看 10 个数字的计数（也是常数）。  
- 所以整体时间是 **线性的**（与数字位数无关），空间只需要保存这些计数表，大小同样是常数级别。

#### 代码（Python）

```python
def reorderedPowerOf2_optimal(n: int) -> bool:
    """
    判断能否通过重新排列 n 的各位数字得到 2 的幂。
    思路：比较数字出现次数（频率表），不枚举排列。
    """
    # ---------- 第一步：把 n 的每个数字出现次数统计出来 ----------
    def digit_count(x: int) -> list[int]:
        cnt = [0] * 10                 # cnt[i] 表示数字 i 出现了多少次
        for ch in str(x):              # 把整数转成字符串，逐字符遍历
            cnt[ord(ch) - ord('0')] += 1
        return cnt

    n_cnt = digit_count(n)

    # ---------- 第二步：预生成所有 2^k（k=0..30）的频率表 ----------
    powers_cnt = []
    for k in range(31):                # 2^30 已经超过 1e9，安全上界
        power = 1 << k                 # 2 的 k 次方
        powers_cnt.append(digit_count(power))

    # ---------- 第三步：逐个比较 ----------
    for pc in powers_cnt:
        if pc == n_cnt:                # 列表相等判断 O(10) 常数时间
            return True
    return False
```

#### 复杂度

- **时间复杂度**：`O(log MAX × d)` → 实际上是 `O(30 × 10)`，可以直接说 **O(1)**（常数时间）。  
  - `log MAX`（这里约等于 30）是候选 2 的幂的数量，`d=10` 是数字种类（0~9）固定不变。  
  - 与暴力解的 `d!`（阶乘）相比，快得多。

- **空间复杂度**：`O(log MAX × d)` → 同样是 **O(1)**。  
  - 我们只保存最多 30 个长度为 10 的计数表，规模固定，不随输入大小增长。

## 心得

- **核心技巧**：**数字计数（频率）比较**。只要两个数的每个数字出现次数相同，它们就可以相互排列得到。  
- **适用的题型**  
  1. “重新排列能否得到某个特定数”——如 *Reordered Power of 2*、*Reordered Power of 3*（假设有类似题）  
  2. “判断两个字符串是否为变位词（anagram）”——经典的字母计数比较  
  3. “把数字重新排列成回文数”——需要检查奇数位计数是否 ≤1  

- **一句话总结解题钥匙**：**把“排列”转化为“计数相等”，用哈希表/数组把计数保存下来，比较即可**。

## 反思

- **第一反应**：看到“重新排列数字”，立刻想到 **全排列**，于是写了暴力搜索。  
- **最容易踩的坑**  
  - **首位不能为 0**：在暴力枚举时必须手动过滤，否则会把非法的排列算进去。  
  - **整数上限**：如果直接把所有 `2^k` 生成到 `10⁹` 以上，会产生不必要的比较。  
  - **计数方式**：使用 `collections.Counter` 虽然直观，但在极限时间要求下手写长度为 10 的列表更高效。  

- **下次遇到同类题**：第一步就问自己 **“能否把排列问题转化为计数相等问题？”**，若答案是肯定的，就直接走计数比较的路线，避免枚举的指数级爆炸。
