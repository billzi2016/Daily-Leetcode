## 题目（英文原版）

**Description**

There are n cars at given miles away from the starting mile 0, traveling to reach the mile target.
You are given two integer arrays position and speed, both of length n, where position[i] is the starting mile of the ith car and speed[i] is the speed of the ith car in miles per hour.

A car fleet is a car or cars driving next to each other. The speed of the car fleet is the minimum speed of any car in the fleet.

Return the number of car fleets that will arrive at the destination.

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是 **模拟每辆车的行驶过程**，把时间切成很小的片段（比如 0.1 小时），在每个时间片里让所有车前进 `speed[i] * dt` 的距离，然后检查有没有车追上前面的车。如果追上了，就把它们合并成同一车队。  

- **数据结构**：我们可以用两个列表分别保存每辆车的当前位置 `pos[i]` 和速度 `speed[i]`。  
- **类比**：把每辆车想象成跑道上的小乌龟，`dt` 就是我们每次让乌龟前进的“步长”。  
- **正确性**：因为我们把时间划分得足够细，每一步都严格按照题目规定的“不能超车，只能并队”来更新位置，最终得到的车队数一定和真实情况一致。  

然而，这种做法的 **时间复杂度** 非常高：  
- 假设目标距离是 `target`，如果我们把 `dt` 设成 `1 / max(speed)`（最小的时间步长），则大约需要跑 `target` 次循环。每次循环我们都要遍历 `n` 辆车并比较相邻车的距离，时间复杂度是 **O(n * target)**，在最坏情况下（`target` 可达 `10⁶`，`n` 可达 `10⁵`）根本跑不完。  
- 空间上只需要保存原始的两个列表，**O(n)**。

> 用大白话解释：`O(n²)` 就像把 `n` 本书两两比较，`n` 越大，比较次数就会像正方形一样疯狂增长；这里的 `O(n * target)` 更像是把每本书的每一页都读一遍，页数多了，工作量直接乘上去。

#### 代码（Python）

```python
def car_fleet_bruteforce(target, position, speed):
    """
    暴力模拟，每次让所有车前进一个非常小的时间步长 dt。
    仅用于演示思路，实际会超时。
    """
    n = len(position)
    # 把位置和速度打包，便于同时更新
    cars = [{'pos': p, 'spd': s, 'alive': True} for p, s in zip(position, speed)]

    # 取一个足够小的时间步长（这里随便取 0.01），实际会导致巨大的循环次数
    dt = 0.01
    while True:
        # 先让所有还在路上的车前进
        for car in cars:
            if car['alive']:
                car['pos'] += car['spd'] * dt
                # 到达或超过终点后标记为已到达
                if car['pos'] >= target:
                    car['alive'] = False

        # 检查是否有车追上前面的车（位置相等且前车速度更慢）
        # 为了简化，这里只比较相邻的两辆车
        for i in range(n - 1):
            a, b = cars[i], cars[i + 1]
            if a['alive'] and b['alive'] and a['pos'] >= b['pos']:
                # 让后面的车“粘”在前面车的后面，速度取慢的
                b['pos'] = a['pos']
                b['spd'] = min(a['spd'], b['spd'])

        # 所有车都已经到达终点，结束循环
        if all(not car['alive'] for car in cars):
            break

    # 统计车队数：每辆到达终点的车，如果它前面没有速度更慢的车，则算一个新车队
    # 这里直接返回 n，因为每辆车最终都会单独算一个（实际并未合并）
    return n   # 只是一种“占位”返回，真实答案需要在模拟中统计
```

> **注意**：上面的代码只能用于演示思路，**在 LeetCode 上会直接超时**，因为循环次数太多。

#### 复杂度  

- **时间复杂度**：`O(n * target / dt)`（近似 `O(n * 10⁸)`），在最坏情况下不可接受。  
- **空间复杂度**：`O(n)`，只用了与车辆数相同的额外列表。

### 2. 最优解  

#### 思路  

从暴力解可以看到，**真正的瓶颈是不断模拟时间**。其实我们并不需要每一时刻的细节，只关心 **每辆车何时能到达终点**。  

1. **先算每辆车单独到达终点需要的时间**  
   \[
   time_i = \frac{target - position_i}{speed_i}
   \]
   这一步把“位置 + 速度”压缩成一个 **时间**，相当于把每辆车映射到“一条直线的交点”。  

2. **按照起始位置从近到远（从目标看过去是从远到近）排序**  
   - 把 `position` 从大到小排列，这样我们从 **最靠近终点的车** 开始考虑。  
   - 类比：把车排成一条队列，先看最前面的（离终点最近的），因为它永远不会被后面的车追上。  

3. **使用单调栈（Monotonic Stack）**  
   - **栈顶** 保存已经形成的车队的 **到达时间**（最慢的那辆车的时间）。  
   - 当我们遍历到下一辆更靠后的车时，比较它的 `time` 与栈顶的时间：  
     - **如果 `time` ≤ 栈顶时间**，说明这辆车会在前面的车队到达之前追上去，**合并到同一个车队**，不需要新建栈元素。  
     - **如果 `time` > 栈顶时间**，说明它追不上前面的车队，会形成 **新的车队**，把它的时间压入栈中。  
   - 这样栈的 **时间序列是严格递减的**（单调递减），因此叫 **单调栈**。  

4. **遍历结束后，栈的大小就是车队的数量**。  

#### 关键概念解释  

- **单调栈**：想象把一堆纸条垂直叠在一起，纸条上写的数字只能从上往下递减。每次放入新纸条时，如果它的数字更大，就必须在最上面新开一层（形成新车队）；如果更小，就把它“压进”已有的层里（合并进已有车队）。  
- **时间的意义**：`time_i` 越小，说明车离终点越近或速度越快，越容易被前面的车“拦住”。  

#### 代码（Python）

```python
def carFleet(target: int, position: list[int], speed: list[int]) -> int:
    """
    最优解：先算每辆车到终点的时间 → 按位置从大到小排序 → 单调栈统计车队数
    """
    # 1. 计算每辆车的到达时间，使用 zip 把位置和速度配对
    cars = [(p, (target - p) / s) for p, s in zip(position, speed)]
    # 2. 按起始位置从大到小排序（离终点最近的在前）
    cars.sort(key=lambda x: x[0], reverse=True)

    stack = []                 # 栈中只保存车队的到达时间
    for pos, t in cars:        # 按从近到远的顺序遍历
        # 如果当前车的到达时间大于栈顶（即前面车队的最慢时间），它形成新车队
        if not stack or t > stack[-1]:
            stack.append(t)    # 入栈，代表新车队
        # 否则 t <= stack[-1]，说明它会追上前面的车队，合并，不需要入栈
    return len(stack)          # 栈的长度即车队数量
```

> **代码要点**  
> - 第 1 行 `[(p, (target - p) / s) ...]` 把每辆车的**位置**和**到达时间**放在一起，方便后面排序。  
> - `reverse=True` 把位置从大到小排，**最靠近终点的车先处理**。  
> - `if not stack or t > stack[-1]:`：栈为空时直接新建车队；否则比较时间决定是否新建。

#### 复杂度  

- **时间复杂度**：`O(n log n)`  
  - 计算时间 `O(n)`。  
  - 排序 `O(n log n)`（这是唯一的瓶颈）。  
  - 单调栈遍历 `O(n)`。  
  - 用大白话说：先把 `n` 本书按字母顺序排好（需要 `log n` 级的比较），再一次性快速读完，每本书只看一次。  

- **空间复杂度**：`O(n)`（存放 `cars` 列表和栈）。  
  - 实际上栈最多只会保存 `n` 个时间值，属于线性空间。

## 心得  

- **核心技巧**：把“位置+速度”压缩成“到达时间”，再利用 **单调栈** 按位置倒序统计**递减的时间段**，每段对应一个车队。  
- **适用场景**：  
  1. **Car Fleet**（本题）  
  2. **Frog Position After T Seconds**（需要把时间转化为可比较的值）  
  3. **Maximum Number of Visible Mountains**（利用单调栈过滤被遮挡的元素）  
- **一句话总结**：**先把每辆车映射成“到达终点的时间”，再从最近的车往后看，时间递增就意味着形成新车队**。

## 反思  

- **第一反应**：看到“不能超车，只能并队”，立刻想到要**模拟每一步**，于是写了暴力的时间步进。  
- **最容易踩的坑**：  
  - **浮点数精度**：`time = (target - p) / s` 产生浮点数，比较时直接使用 `>` / `<=` 足够，因为题目数据范围不会导致极端误差。  
  - **位置唯一性**：题目保证 `position` 唯一，排序时不必担心相同位置的冲突。  
  - **边界条件**：只有一辆车时直接返回 1；所有车速度相同但位置不同时，仍然会形成多个车队（因为后车永远追不上前车）。  
- **下次遇到同类题**：第一步先**把连续运动的问题抽象成一个“一维数值”（如时间、斜率等）**，再**找出单调性**，利用栈或双指针一次遍历得到答案。这样可以快速避开耗时的模拟。
