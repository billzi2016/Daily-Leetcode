# #1079. 字母砖块的所有可能序列 / Letter Tile Possibilities

> 难度：中等 · 标签：Hash Table、String、Backtracking、Counting · [LeetCode 链接](https://leetcode.com/problems/letter-tile-possibilities/)

---

## 题目（英文原版）

**Description**

You have n  tiles, where each tile has one letter tiles[i] printed on it.
Return the number of possible non-empty sequences of letters you can make using the letters printed on those tiles.

**Examples**

**Example 1:**

```
Input: tiles = "AAB"
Output: 8
Explanation: The possible sequences are "A", "B", "AA", "AB", "BA", "AAB", "ABA", "BAA".
```

**Example 2:**

```
Input: tiles = "AAABBC"
Output: 188
```

**Example 3:**

```
Input: tiles = "V"
Output: 1
```

**Constraints**

- 1 <= tiles.length <= 7
- tiles consists of uppercase English letters.

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  

最直接的想法是：**把每块字母砖都当成一张可选的卡片**，从中挑选若干张（可以是一张，也可以全部），再把挑选出来的卡片排成所有可能的顺序。  

- **数据结构**  
  - `tiles` 本身是一个字符串，里面的每个字符就是一块字母砖。  
  - 为了记录某块砖是否已经用过，我们可以用一个长度等于 `len(tiles)` 的布尔数组 `used[i]`。把它想象成“是否把第 i 张卡片从抽屉里拿出来”。  
  - 在递归的每一层，我们遍历所有位置 `i`，如果这张卡片还没被使用，就把它放到当前序列的末尾，然后继续往下走。  

- **为什么正确**  
  - 递归的每一层都尝试把**所有未使用的**字母放到当前序列的下一个位置。于是所有可能的排列（包括不同长度的排列）都会被遍历到。  
  - 当递归进入下一层时，我们把已经放进序列的字母标记为已使用，防止同一块砖被重复使用。递归结束后再把标记恢复（回溯），保证后面的分支仍然可以使用这块砖。  

- **复杂度大白话**  
  - 假设有 `n` 块砖。第一位可以选 `n` 种，第二位可以选 `n‑1` 种，依此类推，所有长度为 `k` 的排列数是 `n·(n‑1)…(n‑k+1)`。把所有 `k = 1 … n` 加起来，实际上就是 `n! + n! / 1! + …`，上界是 `O(n·n!)`。  
  - 对于 `n ≤ 7`，即使是 `7·7! = 35280` 次操作也非常快。  
  - 空间上，我们只需要 `used` 数组和递归栈，最大深度是 `n`，所以是 `O(n)`。  

#### 代码（Python）  

```python
def numTilePossibilities_bruteforce(tiles: str) -> int:
    n = len(tiles)
    used = [False] * n          # 记录每块砖是否已经放进序列
    ans = 0                     # 统计所有非空序列的个数

    def backtrack():
        nonlocal ans
        # 每进入一次递归，说明已经形成了一个非空序列
        ans += 1

        for i in range(n):
            if not used[i]:                 # 这块砖还没用
                used[i] = True              # 把它放进去
                backtrack()                 # 继续往下放
                used[i] = False             # 回溯：把它拿出来，让后面的分支还能用

    backtrack()            # 从空序列开始搜索
    return ans
```

#### 复杂度  

- **时间复杂度**：`O(n·n!)`  
  - 直观解释：我们会遍历所有可能的排列（包括不同长度），每一次递归都相当于“选一块砖”，所以总操作次数大约是 `n` 乘以所有排列数。  
- **空间复杂度**：`O(n)`  
  - 只用了 `used` 数组和递归调用栈，深度不超过砖块数量 `n`。

### 2. 最优解  

#### 思路  

暴力解的瓶颈在于**大量重复的排列**。例如输入 `"AAB"`，字母 `'A'` 出现了两次，暴力解会把两块 `'A'` 当成不同的卡片，导致 `"AB"` 和 `"AB"`（换了两块 `'A'`）被计数两次。  

**优化思路**：  
1. **把相同字母归类**，统计每个字母出现的次数。可以把它想成“字典”，键是字母，值是这张字母砖的库存数量。  
2. 在递归时**不再遍历每一块具体的砖**，而是遍历字典里的每种字母。  
   - 如果某个字母的库存还有剩余，就可以把它放到当前位置，库存减 1；递归结束后再恢复（回溯）。  
3. 这样，每一种字母只会被选一次，避免了因相同字母导致的重复计数。  

**核心算法**：**回溯 + 计数哈希表**。  
- **哈希表**（在 Python 里用 `collections.Counter`）就像一本“字典”，查找某个字母的库存就像查字典里某个词的页码，`O(1)` 时间。  
- **回溯**（Depth‑First Search）仍然负责枚举所有可能的序列，只是每一步的选择集合变小了。  

**图示（文字版）**  

```
tiles = "AAB"
计数表: {'A':2, 'B':1}

第一层（空序列）:
  - 选 A (A 剩 1) → 进入第二层
  - 选 B (B 剩 0) → 进入第二层

第二层（序列长度 1）:
  对于路径 "A":
      - 还能选 A (A 剩 0) → "AA"
      - 还能选 B (B 剩 0) → "AB"
  对于路径 "B":
      - 还能选 A (A 剩 1) → "BA"
      - 不能再选 B（已无库存）
...
```

通过这种方式，所有唯一的序列只会被生成一次。

#### 代码（Python）  

```python
from collections import Counter

def numTilePossibilities(tiles: str) -> int:
    """
    使用回溯 + 计数哈希表，避免因相同字母产生的重复计数。
    """
    cnt = Counter(tiles)          # 统计每个字母的出现次数，类似查字典
    ans = 0

    def backtrack():
        nonlocal ans
        # 每进入一次递归，说明已经形成了一个非空序列
        ans += 1

        for ch in cnt:            # 遍历所有不同的字母
            if cnt[ch] == 0:      # 该字母已经用完，跳过
                continue
            cnt[ch] -= 1          # 把这块字母砖放进序列，库存减 1
            backtrack()           # 继续往下放
            cnt[ch] += 1          # 回溯：把库存恢复，后面的分支还能用

    backtrack()                    # 从空序列开始搜索
    return ans
```

#### 复杂度  

- **时间复杂度**：`O(∑_{k=1}^{n} P(k))`，其中 `P(k)` 表示从 `cnt` 中挑选 `k` 块（考虑重复）的不同排列数。  
  - 直白解释：我们仍然会遍历所有唯一的序列，数量最多等同于暴力解的上界 `n·n!`，但因为去掉了重复，实际次数会更少。对于本题 `n ≤ 7`，运行时间几乎是瞬时的。  
- **空间复杂度**：`O(Alphabet)`（常数空间）+ `O(n)` 递归栈。  
  - `cnt` 最多保存 26 个大写字母的计数，视作常数。递归深度不超过 `n`。

## 心得  

- **核心技巧**：**利用计数哈希表消除重复的回溯**。  
- **适用的题型**  
  1. **排列组合类且有重复元素**（如 LeetCode 47. 全排列 II、LeetCode 254. 因子组合）  
  2. **需要统计所有可能的序列或组合**，且输入规模不大（n ≤ 10 左右）  
- **一句话总结解题钥匙**：把相同的字母合并计数，用“还有几块”来决定是否可以继续放，避免在搜索树里走重复的枝。

## 反思  

- **第一反应**：直接把所有字母当成不同的卡片，用全排列的递归实现。  
- **最容易踩的坑**  
  - **重复计数**：没有去重会把相同字母产生的不同排列算多次。  
  - **忘记回溯恢复计数**：在递归结束后必须把 `cnt[ch]` 加回来，否则后面的分支会误以为该字母已经用完。  
  - **空序列**：题目要求非空序列，递归入口不能直接返回 0，需要在每次进入递归时先计数一次（`ans += 1`），而不是在递归结束后统一处理。  
- **下次遇到同类题**：第一步先**统计每种元素的出现次数**，然后**在回溯时依据计数来决定是否可以选取**，这样天然去重，代码更简洁。
