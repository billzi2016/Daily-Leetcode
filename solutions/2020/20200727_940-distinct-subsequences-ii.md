# #940. 不同的子序列 II / Distinct Subsequences II

## 题目（英文原版）

**Description**

Given a string s, return the number of distinct non-empty subsequences of s. Since the answer may be very large, return it modulo 109 + 7.

**Examples**

**Example 1:**

```
Input: s = "abc"
Output: 7
Explanation: The 7 distinct subsequences are "a", "b", "c", "ab", "ac", "bc", and "abc".
```

**Example 2:**

```
Input: s = "aba"
Output: 6
Explanation: The 6 distinct subsequences are "a", "b", "ab", "aa", "ba", and "aba".
```

**Example 3:**

```
Input: s = "aaa"
Output: 3
Explanation: The 3 distinct subsequences are "a", "aa" and "aaa".
```

**Constraints**

- 1 <= s.length <= 2000
- s consists of lowercase English letters.

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  

最直接的想法是：把字符串的每一个字符都当成“要不要选”。  
如果长度为 `n`，就有 `2ⁿ` 种选法（每个字符有“选”或“不选”两种），  
其中 **空子序列** 要排除，剩下的就是所有非空子序列。  

> **类比**：把字符看成一本书的每一页，翻页时可以选择“读这页”或“跳过这页”。  
> 这样就能列出所有可能的阅读顺序（子序列）。

列举完所有子序列后，把它们放进 **集合**（相当于字典的“键”，相同的子序列会自动去重），最后返回集合的大小即可。

> **为什么正确**：集合会自动去掉重复的子序列，剩下的每一个元素都是原字符串的一个 **不同** 子序列。  

#### 代码（Python）

```python
from typing import Set

MOD = 10**9 + 7

def distinct_subseq_bruteforce(s: str) -> int:
    n = len(s)
    uniq: Set[str] = set()                     # 用集合自动去重
    # 用 0/1 位表示每个字符是否被选取，遍历 1 .. 2ⁿ-1（排除全 0 的空子序列）
    for mask in range(1, 1 << n):              # 1 << n == 2ⁿ
        subseq_chars = []
        for i in range(n):
            if mask & (1 << i):                # 第 i 位是 1 → 选第 i 个字符
                subseq_chars.append(s[i])
        subseq = ''.join(subseq_chars)
        uniq.add(subseq)                        # 加入集合，重复的会被自动抹掉
    return len(uniq) % MOD
```

#### 复杂度  

- **时间复杂度**：`O(2ⁿ * n)`  
  - 解释：我们要遍历 `2ⁿ` 种选法，每次要把选中的字符拼成字符串，最坏要遍历 `n` 次。  
  - 对于 `n=20` 已经是几百万次，`n=30` 就会爆炸，远远超过题目限制。  

- **空间复杂度**：`O(2ⁿ)`（集合里最坏会存 `2ⁿ-1` 个子序列）  
  - 同样不现实。

### 2. 最优解  

#### 思路  

暴力解的瓶颈在于 **枚举所有子序列**，而我们只需要 **计数**，不必真的把子序列列出来。  
观察下面的递推过程可以得到一个线性时间的公式。

设 `dp[i]` 为 **考虑前 i 个字符（即 s[0..i-1]）时，所有不同的子序列（包括空串）的数量**。  
显然 `dp[0] = 1`（只有空串）。

当我们把第 `i` 个字符 `c = s[i-1]` 加入时，之前的每一个子序列都可以 **不加** `c`，也可以 **加** `c`，于是看起来像是把数量翻倍：

```
dp[i] = 2 * dp[i-1]
```

但这样会产生 **重复计数**。  
重复出现的情况是：**之前已经出现过字符 `c`**。  
设 `last[c]` 为字符 `c` 上一次出现的位置（下标从 1 开始），如果 `c` 以前出现过，那么在第 `last[c]` 位之前的子序列已经在 **上一次** 加 `c` 时产生过一次。  
因此，这次翻倍会把这些已经产生过的子序列再算一遍，需要 **减掉**它们的数量：

```
dp[i] = 2 * dp[i-1] - dp[last[c] - 1]
```

如果 `c` 是第一次出现，则 `last[c] = 0`，`dp[last[c]-1]` 视作 `0`，公式仍然成立。

**关键点**：只要记住每个字母上一次出现的位置，就能在 O(1) 时间内得到 `dp[i]`。  
因为字符集只有小写英文字母（26 个），我们可以用一个长度为 26 的数组 `last` 来保存上一次出现的下标。

最后答案需要去掉空串：`answer = dp[n] - 1`，再取模 `10⁹+7` 防止负数。

> **类比**：把已有的子序列想象成一本已经写好的书，每加入一个新字符就相当于把这本书 **复制一遍** 并在每个章节后面 **加上新字符**。  
> 但是如果这个字符以前已经加过一次，那这些“复制后再加”的章节里会出现 **完全相同** 的内容，需要把它们删掉——这一步正是 `- dp[last[c]-1]` 所做的事。

#### 代码（Python）

```python
MOD = 10**9 + 7

def distinct_subseq(s: str) -> int:
    n = len(s)
    dp = [0] * (n + 1)      # dp[i] 表示前 i 个字符的不同子序列数（含空串）
    dp[0] = 1               # 空串

    # last[ch] 保存字符 ch 最近一次出现的位置（下标从 1 开始），初始为 0 表示未出现
    last = [0] * 26         # 只要小写字母

    for i in range(1, n + 1):
        c = s[i - 1]
        idx = ord(c) - ord('a')

        # 先把之前的子序列翻倍
        dp[i] = (dp[i - 1] * 2) % MOD

        # 如果 c 以前出现过，减掉重复的部分
        if last[idx] != 0:
            dp[i] = (dp[i] - dp[last[idx] - 1]) % MOD   # 取模后可能为负，用 % 再次规约

        # 更新字符 c 的最新出现位置
        last[idx] = i

    # 去掉空串，保证非负
    return (dp[n] - 1) % MOD
```

#### 复杂度  

- **时间复杂度**：`O(n)`（遍历一次字符串，内部操作都是 O(1)）  
  - 与暴力的 `O(2ⁿ)` 相比，线性时间在 `n ≤ 2000` 时毫无压力。  

- **空间复杂度**：`O(n)` 用于 `dp` 数组，或者进一步把 `dp` 压缩为只保存前一个值 `O(1)`。  
  - 这里保留 `dp` 只为代码可读性，实际可以只用一个变量 `cur` 来代替。

## 心得  

- **核心技巧**：**动态规划 + 记录上一次出现位置**（相当于“前缀计数 + 去重”）。  
- **适用的题型**：  
  1. **Distinct Subsequence I**（统计与目标字符串匹配的子序列数量）。  
  2. **Count Different Palindromic Subsequences**（不同回文子序列计数）。  
  3. **Number of Unique Substrings**（利用后缀树/数组的类似思路）。  
- **一句话总结解题钥匙**：**“每加入一个字符，子序列数翻倍；若该字符之前出现过，就减掉上一次导致的重复”。**

## 反思  

- **第一反应**：直接想到“枚举所有子序列”。这在概念上最容易，但很快会发现时间爆炸。  
- **最容易踩的坑**：  
  - **负数取模**：`dp[i] - dp[last-1]` 可能为负，需要再 `% MOD` 保证非负。  
  - **忘记去掉空串**：答案要求非空子序列，记得最后 `-1`。  
  - **下标混淆**：`last` 保存的是 **1‑based** 位置，公式里要用 `last-1` 取对应的 `dp`。  
- **下次类似题的第一步**：先思考 **“加入新元素会把已有解翻倍吗？”**，如果会，再检查是否会产生重复并寻找“上一次出现”之类的辅助信息来消除重复。这样往往能快速得到线性或准线性的递推公式。
