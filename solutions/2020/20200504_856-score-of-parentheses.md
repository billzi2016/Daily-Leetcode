## 题目（中文翻译）

给定一个平衡括号字符串（balanced parentheses string）`s`，返回该字符串的分数（score）。

平衡括号字符串的分数依据以下规则计算：

- `"()"` 的分数为 `1`。  
- 若 `A` 和 `B` 均为平衡括号字符串，则连接字符串 `AB` 的分数为 `score(A) + score(B)`。  
- 若 `A` 为平衡括号字符串，则 `"(" + A + ")"`（即 `(A)`）的分数为 `2 * score(A)`。

**示例**

```text
示例 1:
Input: s = "()"
Output: 1
```

```text
示例 2:
Input: s = "(())"
Output: 2
```

```text
示例 3:
Input: s = "()()"
Output: 2
```

**约束条件**

- `2 <= s.length <= 50`
- `s` 仅由字符 `'('` 和 `')'` 组成。
- `s` 是一个平衡括号字符串。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把题目给出的 **递归定义** 直接翻译成代码：

- `"()"` 的分数是 **1**。  
- `"(A)"` 的分数是 **2 × score(A)**。  
- `"AB"`（两个合法子串相邻） 的分数是 **score(A) + score(B)**。

我们可以把整个字符串看成一个「树」：每对匹配的括号对应一个节点，节点内部的子串对应它的子树。  
于是，递归地 **寻找最外层的一对匹配括号**，把它们拆开后递归求子串的分数，再按上面的规则合并。

实现时，最常见的做法是：

1. **遍历字符串**，从左到右找到当前子串的第一个 `'('`，再往后找对应的 `')'`（配对的右括号）。配对的寻找可以用一个计数器 `cnt`：遇到 `'('` 时 `cnt+=1`，遇到 `')'` 时 `cnt-=1`，当 `cnt` 再次回到 **0** 时，就找到了匹配的右括号。  
2. 把这对括号之间的子串记作 `mid`，括号外面的右侧子串记作 `right`。  
3. 递归计算 `mid` 与 `right` 的分数：  
   - `mid` 的分数是 `2 * score(mid)`（如果 `mid` 为空，则视为 `1`）。  
   - `right` 的分数直接加到总分上（因为是相邻的两个合法子串）。  

> **为什么这样一定对？**  
> 题目保证输入是「平衡括号」字符串，也就是说每个 `'('` 必然有对应的 `')'`，并且没有交叉。我们每次都找最外层的那一对括号，恰好对应递归定义中的 `"(A)"`，而把它右边的部分当成 `B`，于是递归公式被完整地实现了。

#### 代码（Python）

```python
def score_of_parentheses_brute(s: str) -> int:
    """
    暴力递归实现，时间复杂度约为 O(n^2)。
    """
    # 递归函数：计算子串 s[l:r]（左闭右开区间）的分数
    def helper(l: int, r: int) -> int:
        if l >= r:                 # 空串分数为 0
            return 0
        i = l
        cnt = 0                    # 用来寻找匹配的右括号
        while i < r:
            cnt += 1 if s[i] == '(' else -1
            i += 1
            if cnt == 0:           # 找到以 l 为左端的最外层匹配
                # 当前这对括号之间是 s[l+1:i-1]，右侧剩余是 s[i:r]
                # 如果内部为空，则 "()" 的分数是 1；否则是 2 * inner
                inner = helper(l + 1, i - 1)
                cur_score = 1 if inner == 0 else 2 * inner
                # 递归计算右侧的分数并相加（相邻子串）
                return cur_score + helper(i, r)
        return 0   # 理论上不会到这里，因为输入保证平衡

    return helper(0, len(s))
```

- **关键行解释**  
  - `cnt += 1 if s[i] == '(' else -1`：像在数「打开的门」和「关上的门」，当 `cnt` 再次回到 0 时，说明所有打开的门都已经关上，找到了匹配的右括号。  
  - `inner = helper(l + 1, i - 1)`：递归求内部子串的分数。  
  - `cur_score = 1 if inner == 0 else 2 * inner`：实现 `"()" → 1` 与 `"(A)" → 2*score(A)` 两条规则。  

#### 复杂度  

- **时间复杂度**：`O(n²)`  
  - 每一层递归都要从左到右遍历一次子串寻找配对的右括号，最坏情况下会出现 `1 + 2 + … + n = O(n²)` 次字符检查。  
  - 大白话：如果字符串长度是 10，最坏要检查大约 10 + 9 + 8 + … + 1 ≈ 55 次字符；长度 100 时会检查约 5 000 次。

- **空间复杂度**：`O(n)`（递归栈）  
  - 递归深度最坏是括号的层数，即 `n/2`，因此需要的调用栈空间与字符串长度成线性关系。

### 2. 最优解

#### 思路  

从暴力解可以看到，**瓶颈在于每次都要重新遍历子串去找配对的右括号**。如果我们在一次遍历中就能把所有配对信息利用起来，就能把时间降到线性 `O(n)`。

观察递归定义还有一个等价的「算术」描述：

- 每个最基本的 `"()"` 的分数是 **1**。  
- 如果一个 `"()"` 被包裹在 `k` 层括号之中（即它的左边有 `k` 个未匹配的 `'('`），它最终贡献的分数是 **`2^k`**。  

> **为什么？**  
> 把 `"()"` 看成叶子节点，它所在的深度是 `k`。根据规则，外层每包一层括号，分数就会 **翻倍**（`2 * …`），所以最终是 `1 * 2^k`。

于是，只要在一次遍历中记录当前的 **深度（depth）**，每当遇到一个完整的 `"()"`（即当前位置是 `')'`，且前一个字符是 `'('`），我们就把 `2^depth` 加到答案中，其中 `depth` 是 **这对括号左侧的 '(' 的数量**（即当前深度）。

实现细节：

1. 用一个整数 `depth` 表示当前遍历到的位置左侧还有多少未匹配的 `'('`。  
2. 遍历字符串 `s`：  
   - 碰到 `'('` → `depth += 1`（进入更深一层）。  
   - 碰到 `')'` → 先把 `depth -= 1`（因为这对右括号把当前层「关闭」了），  
     然后检查前一个字符是否是 `'('`：如果是，说明我们刚好看到一个最小的 `"()"`，它的分数是 `1 << depth`（即 `2^depth`），把它加到答案。  
3. 整个过程只需要一次线性遍历，额外空间只用来保存几个整数。

> **类比**：`depth` 像是「楼层计数器」，每上来一层楼层数加一，每下去一层楼层数减一。当我们看到一扇紧闭的门 `"()"`，它所在的楼层就是它的价值倍数。

#### 代码（Python）

```python
def score_of_parentheses(s: str) -> int:
    """
    栈/深度法的线性时间解法，时间 O(n)，空间 O(1)。
    """
    ans = 0          # 最终得分
    depth = 0        # 当前 '(' 的层数

    for i, ch in enumerate(s):
        if ch == '(':
            depth += 1                     # 进入新的一层
        else:  # ch == ')'
            depth -= 1                     # 先把当前层关闭
            # 如果前一个字符是 '('，说明形成了一个最小的 "()"
            if s[i - 1] == '(':
                # 这对 "()" 位于 depth 层（已经减去本层），贡献 2^depth
                ans += 1 << depth          # 等价于 2 ** depth，效率更高
    return ans
```

- **关键行解释**  
  - `depth += 1` / `depth -= 1`：像在电梯里上下楼层，记录我们当前在第几层括号内部。  
  - `if s[i - 1] == '(':`：判断是否出现了最小的 `"()"`，只有这种情况才需要直接计分。  
  - `1 << depth`：左移一位相当于 `2**depth`，把「翻倍」的规则用位运算实现，速度更快。

#### 复杂度  

- **时间复杂度**：`O(n)`  
  - 只遍历一次字符串，`n` 是字符串长度。  
  - 与暴力解的 `O(n²)` 相比，速度提升了一个数量级：长度为 50 时，最多只检查 50 次字符。

- **空间复杂度**：`O(1)`（常数空间）  
  - 只使用了几个整数变量 `ans、depth、i、ch`，与输入规模无关。  
  - 如果不使用位运算，而是用显式的栈来保存深度，同样是 `O(n)` 最坏空间，但这里我们只需要计数器即可。

## 心得

- **核心技巧**：利用「深度」把括号的层级关系映射为指数倍的贡献，**一次遍历即可求和**。  
- **适用的题型**：  
  1. **Score of Parentheses**（本题）。  
  2. **Maximum Nesting Depth of Parentheses**（求最大嵌套深度）。  
  3. **Valid Parenthesis String**（判断合法性并统计特定模式，如 `"()"` 的数量）。  
- **一句话总结解题钥匙**：`"()"` 的价值随所在层数指数增长，只要记录层数并在看到最小配对时加上 `2^depth`，即可线性求解。

## 反思

- **第一反应**：把题目描述的递归公式直接写成递归函数，先把「分治」的思想实现出来。  
- **最容易踩的坑**：  
  - 在深度法里忘记在处理右括号时先 `depth -= 1` 再判断前一个字符，这会导致算错层数。  
  - 边界情况：字符串开头是 `'('`，因此在检查 `s[i-1]` 前一定要确保 `i > 0`（本实现遍历时 `i` 至少为 1，因为右括号必然有左侧字符）。  
- **下次遇到同类题**：第一步先**思考是否可以用一次遍历把结构信息（如深度、前缀和）直接累加**，如果可以，就不必用递归或显式栈。这样往往能把时间复杂度从 `O(n²)` 降到 `O(n)`。
