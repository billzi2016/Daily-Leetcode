# #729. 我的日历 I / My Calendar I

> 难度：中等 · 标签：Array、Binary Search、Design、Segment Tree、Ordered Set · [LeetCode 链接](https://leetcode.com/problems/my-calendar-i/)

## 题目（英文原版）

**Description**

You are implementing a program to use as your calendar. We can add a new event if adding the event will not cause a double booking.
A double booking happens when two events have some non-empty intersection (i.e., some moment is common to both events.).
The event can be represented as a pair of integers startTime and endTime that represents a booking on the half-open interval [startTime, endTime), the range of real numbers x such that startTime <= x < endTime.
Implement the MyCalendar class:

**Examples**

**Example 1:**

```
Input
["MyCalendar", "book", "book", "book"]
[[], [10, 20], [15, 25], [20, 30]]
Output
[null, true, false, true]

Explanation
MyCalendar myCalendar = new MyCalendar();
myCalendar.book(10, 20); // return True
myCalendar.book(15, 25); // return False, It can not be booked because time 15 is already booked by another event.
myCalendar.book(20, 30); // return True, The event can be booked, as the first event takes every time less than 20, but not including 20.
```

**Constraints**

- 0 <= start < end <= 109
- At most 1000 calls will be made to book.

## 题目（中文翻译）

你正在实现一个日历程序。只有在新增的事件不会导致双重预订（double booking）时，才能添加该事件。  
双重预订指的是两个事件存在非空交集（即有某个时刻同时属于两个事件）。  
每个事件用一对整数 `startTime` 和 `endTime` 表示，表示在半开区间 **[startTime, endTime)** 上的预订，即所有满足 `startTime <= x < endTime` 的实数 `x`。  

实现 `MyCalendar` 类，使其能够：

- `book(start, end)`: 若将区间 **[start, end)** 加入后不与已有事件产生交集，返回 `true` 并加入该事件；否则返回 `false`，且不加入。

**示例**

```json
Input
["MyCalendar", "book", "book", "book"]
[[], [10, 20], [15, 25], [20, 30]]
Output
[null, true, false, true]
```

**解释**  
```java
MyCalendar myCalendar = new MyCalendar();
myCalendar.book(10, 20); // 返回 true
myCalendar.book(15, 25); // 返回 false，无法预订，因为时间点 15 已被之前的事件占用。
myCalendar.book(20, 30); // 返回 true，能够预订，因为第一个事件只占用小于 20 的时间，不包括 20。
```

**约束条件**

- `0 <= start < end <= 10^9`
- 最多会调用 `book` 方法 1000 次。

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把已经成功预订的所有时间段都保存下来，每次要预订新的 `[start, end)` 时，遍历已有的每一个区间，检查它们是否有交集。  
- **数据结构**：用 Python 的 `list` 保存所有区间，每个区间用二元组 `(s, e)` 表示。可以把它想象成一本**日程本**，每一页写着一段已占用的时间。  
- **交集判断**：两个半开区间 `[s1, e1)` 与 `[s2, e2)` 没有交集的充要条件是 `e1 <= s2` 或 `e2 <= s1`（即一个结束时间不迟于另一个的开始时间）。只要出现 `not (e1 <= s2 or e2 <= s1)`，说明有重叠，预订失败。  
- **正确性**：因为我们检查了 **所有** 已存在的区间，只要有任意一个冲突就返回 `False`，否则把新区间加入列表返回 `True`，这恰好满足题目“若不产生双重预订则可以预订”。  

#### 代码（Python）

```python
class MyCalendar:
    def __init__(self):
        # 用一个列表保存所有已经预订的区间，初始为空
        self.events = []          # [(start, end), (start, end), ...]

    def book(self, start: int, end: int) -> bool:
        """
        尝试预订区间 [start, end)。
        若与任意已有区间有交集则返回 False，否则加入 events 并返回 True。
        """
        for s, e in self.events:                 # 逐个检查已预订的区间
            # 若两个区间有交集，返回 False
            if not (e <= start or end <= s):     # 交集的判断式
                return False

        # 没有冲突，加入列表
        self.events.append((start, end))
        return True
```

#### 复杂度  

- **时间复杂度**：`O(n)`，其中 `n` 是当前已预订的区间数。每次 `book` 需要遍历全部已有区间检查冲突。  
  - **大白话**：如果已经有 100 条预约，检查一次需要看 100 次；最坏情况下，1000 次调用会累计大约 100 + 200 + … + 1000 ≈ 5 × 10⁵ 次比较，仍然能跑完，但不是最优的。  
- **空间复杂度**：`O(n)`，用来存放所有已预订的区间。

### 2. 最优解  

#### 思路  

暴力解的瓶颈在于每次都要 **线性遍历** 所有已有区间。实际上，我们只需要关心 **最可能冲突的两个相邻区间**。如果把所有区间按照开始时间排好序，新的区间只可能和它左边最近的区间或右边最近的区间产生交集——因为其它更远的区间要么全部在左边，要么全部在右边，必然与新区间不相交。

因此可以：

1. **保持区间列表有序**（按 `start` 升序）。  
2. 使用二分查找（Python 的 `bisect` 模块）在 `O(log n)` 时间找到新区间应该插入的位置 `i`。  
3. 只检查 **左邻** `events[i‑1]`（如果存在）和 **右邻** `events[i]`（如果存在）是否冲突。  
4. 若不冲突，就在位置 `i` 插入新区间，保持有序。

> **类比**：想象一本已经按日期排好序的日程本，要在其中插入一条新预约，只需要找出它在日历中的“前后页”，检查这两页是否会重叠，其余页根本不需要翻看。

#### 代码（Python）

```python
import bisect

class MyCalendar:
    def __init__(self):
        # 用两个平行列表分别保存开始时间和结束时间，保持同步
        self.starts = []   # 已预订区间的 start，递增排列
        self.ends   = []   # 与 starts 对应的 end

    def book(self, start: int, end: int) -> bool:
        """
        二分定位插入位置，只检查左右相邻的区间。
        时间复杂度 O(log n)，空间仍为 O(n)。
        """
        # 在 starts 中找到第一个 >= start 的位置 i
        i = bisect.bisect_left(self.starts, start)

        # 检查左侧相邻区间是否冲突
        if i > 0 and self.ends[i-1] > start:   # left.end > new.start
            return False

        # 检查右侧相邻区间是否冲突
        if i < len(self.starts) and end > self.starts[i]:  # new.end > right.start
            return False

        # 没有冲突，插入保持有序
        self.starts.insert(i, start)
        self.ends.insert(i, end)
        return True
```

> **代码要点**  
> - `bisect_left` 相当于在有序的“字典目录”里找插入点，时间是 `log n`。  
> - 只检查 `i‑1` 与 `i` 两个区间，因为它们是最近的可能冲突对象。  
> - 使用两个平行列表而不是列表的二元组，插入时 `list.insert` 仍是 `O(n)`，但在本题约 1000 次调用的规模下，这个常数足够小；若要求严格的 `O(log n)` 插入，可使用 `SortedList`（外部库）或平衡二叉搜索树。

#### 复杂度  

- **时间复杂度**：`O(log n)`（二分查找） + `O(n)`（列表插入）。在本题 `n ≤ 1000`，插入的线性成本可以忽略不计；若换成平衡树，则整体为 `O(log n)`。  
  - **大白话**：比起每次都翻阅整本日程本，这里只需要“快速定位”到正确的页码，然后检查前后两页，省下大多数翻页的时间。  
- **空间复杂度**：`O(n)`，仍然需要保存所有已预订的区间。

## 心得  

- **核心技巧**：利用**有序结构 + 二分查找**把线性扫描的检查降到只看相邻区间。  
- **适用的题型**：  
  1. 区间不重叠的插入检查（如 *My Calendar II/III*）。  
  2. 需要快速定位“前驱/后继”元素的问题（如 *插入区间、查找最近的数*）。  
- **一句话总结解题钥匙**：**把区间按起点排好序，冲突只可能出现在左右最近的两段**。

## 反思  

- **第一反应**：直接把所有已有区间遍历一遍检查冲突——最自然但最慢的做法。  
- **最容易踩的坑**：  
  - 忘记**半开区间**的特性，导致把 `end == start` 误判为冲突。  
  - 在二分定位后忘记同时检查左邻和右邻两个方向。  
  - 插入后忘记保持 `starts` 与 `ends` 同步，导致后续比较出错。  
- **下次类似题的第一步**：先问自己“如果把已有数据排好序，新的元素只会和哪几条数据产生关系？”然后决定是否可以用二分或平衡树来加速。
