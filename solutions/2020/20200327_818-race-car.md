# #818. 赛车 / Race Car

> 难度：困难 · 标签：Dynamic Programming · [LeetCode 链接](https://leetcode.com/problems/race-car/)

---

## 题目（英文原版）

**Description**

Your car starts at position 0 and speed +1 on an infinite number line. Your car can go into negative positions. Your car drives automatically according to a sequence of instructions 'A' (accelerate) and 'R' (reverse):
For example, after commands "AAR", your car goes to positions 0 --> 1 --> 3 --> 3, and your speed goes to 1 --> 2 --> 4 --> -1.
Given a target position target, return the length of the shortest sequence of instructions to get there.

**Examples**

**Example 1:**

```
Input: target = 3
Output: 2
Explanation: 
The shortest instruction sequence is "AA".
Your position goes from 0 --> 1 --> 3.
```

**Example 2:**

```
Input: target = 6
Output: 5
Explanation: 
The shortest instruction sequence is "AAARA".
Your position goes from 0 --> 1 --> 3 --> 7 --> 7 --> 6.
```

**Constraints**

- 1 <= target <= 104

## 题目（中文翻译）

你的汽车初始位于位置 0，速度为 +1，行驶在一条无限数轴上，且可以到达负数位置。汽车会根据指令序列自动行驶，指令包括 `'A'`（加速）和 `'R'`（调头）：

- `'A'`：速度翻倍（`speed = speed * 2`），位置前进 `speed` 的距离。
- `'R'`：速度取相反数且绝对值变为 1（`speed = speed > 0 ? -1 : 1`），位置保持不变。

例如执行指令 `"AAR"` 时，汽车的位置和速度变化如下：

| 步骤 | 指令 | 位置 | 速度 |
|------|------|------|------|
| 初始 | —    | 0    | 1    |
| 1    | A    | 1    | 2    |
| 2    | A    | 3    | 4    |
| 3    | R    | 3    | -1   |

给定目标位置 `target`，返回能够到达该位置的最短指令序列的长度。

**示例 1**  
**输入**: `target = 3`  
**输出**: `2`  
**解释**:  
最短的指令序列是 `"AA"`。  
位置变化为 `0 --> 1 --> 3`。

**示例 2**  
**输入**: `target = 6`  
**输出**: `5`  
**解释**:  
最短的指令序列是 `"AAARA"`。  
位置变化为 `0 --> 1 --> 3 --> 7 --> 7 --> 6`。

**约束条件**  
- `1 <= target <= 10^4`

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  

最直接的想法是**把所有可能的指令序列都枚举一遍**，找出第一个恰好让小车停在目标位置 `target` 的序列。  
这类似于我们在迷宫里“随手走”，每走一步就记录当前位置和当前速度，然后继续往下走，直到找到出口。  

要实现这个想法，需要下面几个工具：  

| 工具 | 生活化类比 | 作用 |
|------|------------|------|
| 队列（Queue） | 排队买饭的队伍，先进去的先出来 | 按“层次”逐步展开所有指令序列，保证先找到最短的序列 |
| 哈希表（Set / dict） | 查字典：把单词当成键（key），对应的解释是值（value） | 记录已经访问过的 `(位置, 速度)`，防止重复搜索导致无限循环 |
| BFS（广度优先搜索） | 像层层剥洋葱，一层层往外扩散 | 能保证第一次到达目标时使用的指令数最少（即最短序列） |

**为什么正确？**  
BFS 按层搜索：第 1 层是所有长度为 1 的指令序列，第 2 层是所有长度为 2 的序列……  
只要我们在展开第 `k` 层时发现已经到达 `target`，说明不存在长度 `< k` 的序列能到达目标，因为如果有，BFS 必然更早发现它。  

**时间/空间复杂度**（大白话）：  
- **时间**：每一步都要把当前状态 `(pos, speed)` 拓展成两个新状态（加速 `A`，或调头 `R`），所以搜索树的宽度会指数级增长。最坏情况下大概是 `O(2^k)`，其中 `k` 是答案的长度。对 `target ≤ 10⁴` 来说，这已经会导致**超时**。  
- **空间**：需要保存所有已经访问过的状态，最坏也会是指数级，记作 `O(2^k)`。  

#### 代码（Python）  

```python
from collections import deque

def racecar_bruteforce(target: int) -> int:
    """
    BFS 暴力搜索，返回最短指令序列长度。
    适用于 target 很小的情况，演示思路。
    """
    # 队列里保存 (当前位置, 当前速度, 已用指令数)
    q = deque()
    q.append((0, 1, 0))

    # 用 set 记录已经访问过的 (pos, speed) 防止重复
    visited = {(0, 1)}

    while q:
        pos, speed, steps = q.popleft()
        # 已经到达目标，直接返回步数
        if pos == target:
            return steps

        # 1. 执行指令 A（加速）
        nxt_pos = pos + speed
        nxt_speed = speed * 2
        if (nxt_pos, nxt_speed) not in visited \
                and -2 * target <= nxt_pos <= 2 * target:   # 防止无限扩散
            visited.add((nxt_pos, nxt_speed))
            q.append((nxt_pos, nxt_speed, steps + 1))

        # 2. 执行指令 R（调头），速度变为 +1 或 -1
        # 调头只会改变方向，不会移动位置
        rev_speed = -1 if speed > 0 else 1
        if (pos, rev_speed) not in visited:
            visited.add((pos, rev_speed))
            q.append((pos, rev_speed, steps + 1))

    # 理论上不会到这里
    return -1
```

#### 复杂度  

- **时间复杂度**：`O(2^k)`（指数级），其中 `k` 为最短指令序列的长度。  
  > 大白话：搜索的树会像二叉树一样每层翻倍，层数越多，工作量翻倍得越快。  

- **空间复杂度**：`O(2^k)`，因为需要把所有已访问的状态都放进 `visited` 集合。

### 2. 最优解  

#### 思路  

暴力解的瓶颈在于**把所有指令序列都枚举**，导致指数级的搜索。  
我们需要利用题目给出的规律，把搜索空间压缩到 **“只在关键位置转向”**。  

关键观察有两点：

1. **连续加速 A 的结果是等比数列**  
   - 连续执行 `n` 次 `A`，位置会变成 `0 + 1 + 2 + 4 + … + 2^{n-1}`  
   - 这正好是 `2^n - 1`（前 `n` 项的和）。  
   - 因此，**只要记住“跑 n 步 A 能到达的最远位置”**，我们就可以快速算出是否会超过目标。

2. **最优路径只会在**  
   - **恰好到达目标**（`2^n - 1 == target`）  
   - **第一次超过目标后立刻调头**  
   - **在未超过目标时调头，再把剩余距离当成新目标**  
   这三种情况。因为如果在中途多次调头，必然比直接把 “多余的距离” 当作子问题更慢。

基于上述观察，我们可以用**动态规划 + 记忆化搜索**（DP + memo）来递归求解：

```
dp[t] = 最少指令数，使小车恰好到达位置 t（t 为正整数）
```

递推公式：

1. 找到最小的 `n` 使 `2^n - 1 >= t`。  
   - 若 `2^n - 1 == t`，显然只需要 `n` 次加速，`dp[t] = n`。  

2. 否则有两种选择取最小值：

   **方案 A（先 overshoot 再调头）**  
   - 连续加速 `n` 次后到达 `pos = 2^n - 1`（已经超过目标），  
   - 再执行一次 `R` 调头，速度变为 `-1`，  
   - 然后把剩余的距离 `pos - t` 当成新目标（因为此时我们在正向跑完后要倒着跑回去）。  
   - 指令数 = `n + 1 + dp[pos - t]`  

   **方案 B（在未超过目标时调头）**  
   - 只加速 `n-1` 次，此时位置为 `2^{n-1} - 1`，仍然小于目标。  
   - 执行一次 `R` 调头，然后再加速 `m` 次（`m` 可以从 `0` 到 `n-1`），  
   - 再一次 `R` 调头回正向，最后把剩余距离 `t - (2^{n-1} - 1) + (2^m - 1)` 当作新目标。  
   - 公式化后为：`dp[t] = min_{0 ≤ m < n-1} ( (n-1) + 1 + m + 1 + dp[ t - (2^{n-1} - 1) + (2^m - 1) ] )`  
   - 这里的 `+1` 分别是两次调头指令。

取两种方案的最小值即为 `dp[t]`。  

因为每次递归都会把问题规模显著缩小（至少减半），并且我们把已经算过的 `dp[x]` 缓存下来（哈希表），所以整体复杂度是 **`O(target log target)`**，足以在 `target ≤ 10⁴` 的限制下轻松通过。

> **从零解释的关键概念**  
> - **哈希表（字典）**：像一本“查词典”，键是目标位置，值是对应的最少指令数。查找、插入、更新都是 `O(1)`，所以我们可以在常数时间内记住已经算好的子问题。  
> - **记忆化搜索**：把递归过程中的中间结果保存起来，后面再需要时直接复用，避免重复计算。  

#### 代码（Python）  

```python
def racecar(target: int) -> int:
    """
    动态规划 + 记忆化搜索，求最短指令序列长度。
    复杂度约为 O(target * log target)。
    """
    from functools import lru_cache
    import math

    @lru_cache(None)          # 自动把函数返回值记住，相当于哈希表
    def dp(t: int) -> int:
        # 目标为 0 时不需要任何指令（递归的边界）
        if t == 0:
            return 0

        # 找到最小的 n 使得 2^n - 1 >= t
        n = t.bit_length()          # 等价于 ceil(log2(t+1))
        # 2^n - 1 是连续加速 n 次后能到达的最远位置
        max_pos = (1 << n) - 1

        # 情况 1：恰好到达
        if max_pos == t:
            return n

        # 情况 2：先 overshoot 再调头
        # 先跑 n 次 A，到达 max_pos > t，随后一次 R，再把多余的距离当子问题
        ans = n + 1 + dp(max_pos - t)

        # 情况 3：在未超过目标时调头（尝试所有可能的 m）
        # 只跑 n-1 次 A（位置 < t），调头，然后再跑 m 次 A（0 <= m < n-1）
        # 再调头回正向，剩余距离作为新子问题
        for m in range(n - 1):
            # 前 n-1 次 A 到达的距离
            pos_n_1 = (1 << (n - 1)) - 1
            # 再跑 m 次 A 的距离
            pos_m = (1 << m) - 1
            # 这一步的总指令数： (n-1) 次 A + 1 次 R + m 次 A + 1 次 R
            cur = (n - 1) + 1 + m + 1 + dp(t - pos_n_1 + pos_m)
            ans = min(ans, cur)

        return ans

    return dp(target)
```

> **代码要点解释**  
> - `t.bit_length()`：返回 `t` 的二进制位数，相当于 `⌈log2(t+1)⌉`，用来快速求出 `n`。  
> - `(1 << n) - 1`：左移相当于 `2^n`，再减 `1` 得到 `2^n - 1`。  
> - `@lru_cache(None)`：装饰器会为函数创建一个内部哈希表，记住每个 `t` 对应的最小指令数。  
> - 循环 `for m in range(n - 1)` 实际上只会跑到 `log(target)` 次，整体复杂度仍保持在 `O(target log target)`。

#### 复杂度  

- **时间复杂度**：`O(target * log target)`  
  > 大白话：对每个目标 `t`（最多 `target` 次），我们只会尝试至多 `log₂(t)`（约 14 次，因为 `2^14 > 10⁴`）的 `m`，所以总工作量大约是 `target` 乘以一个很小的常数。  

- **空间复杂度**：`O(target)`  
  > 需要存放 `dp[0 … target]` 的记忆化表（实际上是哈希表），以及递归调用栈的深度 `O(log target)`，总体是线性空间。

## 心得  

- **核心技巧**：利用 **连续加速的等比数列特性** (`2^n - 1`) 把搜索空间压缩到“只在关键位置调头”，并用 **记忆化动态规划** 防止重复计算。  
- **适用的题型**  
  1. “最少操作使数字达到目标”类（如 LeetCode 1547. **逆序对**、1195. **水果拼盘**）  
  2. 需要在**单向递增**与**调头**之间权衡的运动类题目（如 818. **Race Car** 的变种）  
  3. 通过**前缀和/等比数列**快速定位的最优子结构问题（如 376. **摆动序列**）  
- **一句话总结解题钥匙**：**“把所有指令压缩成‘若干次加速 + 最多两次调头’，再用 DP 把子问题缓存”。**

## 反思  

- **第一反应**：看到“加速 A、调头 R”，本能想到 BFS 把所有指令枚举。  
- **最容易踩的坑**  
  1. **搜索范围无限**：若不限制 `pos` 的上下界，队列会无限增长导致内存爆炸。  
  2. **忘记记忆化**：纯递归会出现指数级重复子问题，导致超时。  
  3. **边界条件**：`target = 1` 时只需要一步 `A`，需要单独处理，否则 `n = 0` 会产生错误的位移。  
- **下次遇到同类题**：第一步先**分析连续操作的累计效果**（等差/等比），判断是否能把“何时调头”抽象为几个关键点，再**用 DP / 记忆化**把子问题缓存，避免全枚举。
