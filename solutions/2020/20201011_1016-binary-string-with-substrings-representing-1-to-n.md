# #1016. 二进制字符串中包含表示 1 到 N 的子串 / Binary String With Substrings Representing 1 To N

> 难度：中等 · 标签：Hash Table、String、Bit Manipulation、Sliding Window · [LeetCode 链接](https://leetcode.com/problems/binary-string-with-substrings-representing-1-to-n/)

## 题目（英文原版）

**Description**

Given a binary string s and a positive integer n, return true if the binary representation of all the integers in the range [1, n] are substrings of s, or false otherwise.
A substring is a contiguous sequence of characters within a string.

**Examples**

**Example 1:**

```
Input: s = "0110", n = 3
Output: true
```

**Example 2:**

```
Input: s = "0110", n = 4
Output: false
```

**Constraints**

- 1 <= s.length <= 1000
- s[i] is either '0' or '1'.
- 1 <= n <= 109

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**把每个整数 1…n 的二进制写出来，然后在字符串 `s` 中去找**。  
这一步可以直接利用 Python 的 `in` 操作或手写滑动窗口：

1. 对 `i` 从 1 到 `n`  
   - 用 `bin(i)[2:]` 把 `i` 转成二进制字符串（去掉前面的 `0b`）。  
   - 判断这个二进制串是否是 `s` 的子串（`sub in s`）。  
2. 只要有一个找不到，就返回 `False`，全部找到则返回 `True`。

> **类比**：把 `s` 想成一本厚厚的书，二进制串是我们要在书里查的词。  
> `in` 操作就像在目录里快速定位页码，虽然实现上是线性扫描，但对我们来说已经够直观了。

**为什么正确**：只要每个 `i` 的二进制真的出现在 `s` 中，题目要求就全部满足；反之只要缺少一个，就不满足。

#### 代码（Python）

```python
def check_substrings_bruteforce(s: str, n: int) -> bool:
    """
    暴力实现：逐个检查 1..n 的二进制表示是否是 s 的子串
    """
    for i in range(1, n + 1):
        bin_i = bin(i)[2:]          # 把整数 i 转成二进制字符串，去掉前缀 '0b'
        if bin_i not in s:         # Python 的子串判断，等价于滑动窗口逐字符比较
            return False           # 一旦发现缺失，直接返回 False
    return True                    # 所有都找到了，返回 True
```

#### 复杂度  

- **时间复杂度**：`O(n * |s|)`  
  - 对每个 `i`（共 `n` 次）都要在长度为 `|s|` 的字符串里搜索子串，最坏情况下要遍历全部字符。  
  - 用大白话说，就是如果 `n = 10⁹`，`s` 长 1000，那就要做 **10⁹ × 1000** 次比较，根本跑不完。

- **空间复杂度**：`O(1)`（不计返回值的布尔变量）  
  - 只用了常数级的额外变量 `bin_i`。

> 暴力解虽然思路最清晰，却因为 **“每次都从头到尾扫一遍”** 成为性能瓶颈，无法通过 LeetCode 的时间限制。

### 2. 最优解

#### 思路  

从暴力解出发，**瓶颈在于对每个 `i` 都要遍历整条字符串**。  
我们可以把这一步“反向”思考：

1. **先把 `s` 能提供的所有二进制子串全部列举出来**。  
   - `s` 长度最多 1000，二进制子串的长度不需要超过 `30`（因为 `n ≤ 10⁹ < 2³⁰`，30 位已经能表示所有可能的整数）。  
   - 用双层循环枚举所有起始位置 `start`，再往后取 `len` = 1…30（但不能越界），把得到的子串放进一个 **哈希表**（Python 的 `set`）。  
   - **哈希表**可以类比成“词典”，把子串当作“词”，出现的次数不重要，只要记住“这本书里有这词”。查询时 `O(1)`。

2. **随后只需要遍历 1…n，检查它的二进制串是否已经在哈希表里**。  
   - 这一步是 **常数时间** 的集合查找，不再需要在 `s` 中线性搜索。

3. **提前剪枝**：  
   - `s` 能产生的不同子串数目最多 `|s| × 30 ≈ 3·10⁴`，远小于 `n`（可能达到 `10⁹`）。  
   - 如果 `n` 超过了哈希表的大小，说明必定缺少某些二进制串，直接返回 `False`。

> **核心概念——哈希表（字典）**  
> 想象我们把所有出现过的二进制串写进一本小册子，每翻一页（查询）只需要看标题（键）是否在册子里，时间几乎为零。

#### 代码（Python）

```python
def check_substrings_optimal(s: str, n: int) -> bool:
    """
    最优实现：
    1. 把 s 中所有长度 ≤ 30 的二进制子串收集到集合 sub_set
    2. 逐个检查 1..n 的二进制表示是否在集合里
    """
    MAX_LEN = 30                     # 因为 2^30 > 1e9，所有需要的二进制串最长不超过 30

    # ---------- 第一步：枚举子串 ----------
    sub_set = set()                  # 哈希表，用来快速判断子串是否出现过
    L = len(s)

    for start in range(L):
        # 只取最长 30 位，防止越界
        for length in range(1, min(MAX_LEN, L - start) + 1):
            sub = s[start:start + length]   # 取出从 start 开始、长度为 length 的子串
            sub_set.add(sub)                # 加入集合（自动去重）

    # ---------- 可选的提前剪枝 ----------
    # 若 n 的二进制位数为 k，则所有长度 ≤ k 的二进制数共 2^k - 1 个。
    # 如果集合的大小本身就不足以容纳这些数，直接返回 False。
    # 这里用最宽松的 30 位做判断。
    if n > (1 << MAX_LEN) - 1:       # 实际上 n 已经满足此条件，但写成这样更易理解
        # 仍然需要检查，因为并不是所有 2^30-1 个数都一定出现。
        pass

    # ---------- 第二步：检查每个整数 ----------
    for i in range(1, n + 1):
        bin_i = bin(i)[2:]          # 二进制字符串，不含前缀 '0b'
        if bin_i not in sub_set:    # O(1) 的集合查找
            return False            # 只要有一个缺失，立即返回 False
    return True                     # 全部匹配成功
```

#### 复杂度  

- **时间复杂度**：`O(|s| * 30 + n)`  
  - 枚举子串：`|s|`（最多 1000）乘以最多 30 种长度 → 最多约 `3·10⁴` 次操作。  
  - 检查 1…n：每个整数只做一次集合查询，时间是 **常数**，所以总共 `O(n)`。  
  - 与暴力解相比，**把“在 s 中找子串”这一步从每次 `O(|s|)` 降到了只做一次预处理**，大幅提升。

- **空间复杂度**：`O(|s| * 30)`  
  - 哈希表里最多存放 `|s| × 30` 条不同的子串（每条长度 ≤30），约 `3·10⁴` 条，远小于 `n`。  
  - 用大白话说，就是我们把所有可能的“词”提前记在一本小笔记本里，笔记本的大小和原字符串长度成线性关系。

> 相比暴力解，**时间从 `O(n·|s|)` 降到了 `O(n)`**，在 `|s|` 固定、`n` 可能很大的情况下，性能提升显著。

## 心得

- **核心技巧**：**先预处理所有可能的子串，用哈希表做 O(1) 查询**。  
  这是一种“**逆向思维**”的典型：把“多次查询”转化为“一次全收集”。  
- **适用的题型**  
  1. “检查所有长度 ≤ k 的子串是否覆盖某些模式”——例如 *All Substrings of Size K*。  
  2. “给定一串字符，判断是否包含所有字母/数字/二进制数”——比如 *Check If a String Contains All Binary Numbers From 1 to N*。  
  3. “统计字符串中出现的所有不同子串”——如 *Count Distinct Substrings*（可以用集合或后缀数组实现）。  
- **一句话总结**：**把字符串中所有可能的子串一次性收集进哈希表，后续的每次判定只要 O(1) 即可**。

## 反思

- **第一反应**：直接遍历 `1…n`，每个数在 `s` 中搜索——这就是暴力解。  
- **最容易踩的坑**  
  - **子串长度上限**：忘记 `n ≤ 10⁹`，导致枚举过长的子串，时间和空间都会爆炸。  
  - **边界条件**：`s` 很短（如长度 1）时，`min(MAX_LEN, L-start)` 必须防止负数或越界。  
  - **整数转换**：`bin(i)` 会返回 `'0b...'`，一定要切掉前缀，否则会找不到匹配。  
- **下次遇到同类题**：第一步先 **“先把原串能提供的所有信息收集好”**（如所有子串、所有前缀和等），再在这些预处理结果上做判断，避免重复遍历。这样思路一旦固定，后面的实现就会顺畅很多。
