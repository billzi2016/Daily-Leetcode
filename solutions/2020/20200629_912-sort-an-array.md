# #912. 数组排序 / Sort an Array

> 难度：中等 · 标签：Array、Divide and Conquer、Sorting、Heap (Priority Queue)、Merge Sort、Bucket Sort、Radix Sort、Counting Sort · [LeetCode 链接](https://leetcode.com/problems/sort-an-array/)

## 题目（英文原版）

**Description**

Given an array of integers nums, sort the array in ascending order and return it.
You must solve the problem without using any built-in functions in O(nlog(n)) time complexity and with the smallest space complexity possible.

**Examples**

**Example 1:**

```
Input: nums = [5,2,3,1]
Output: [1,2,3,5]
Explanation: After sorting the array, the positions of some numbers are not changed (for example, 2 and 3), while the positions of other numbers are changed (for example, 1 and 5).
```

**Example 2:**

```
Input: nums = [5,1,1,2,0,0]
Output: [0,0,1,1,2,5]
Explanation: Note that the values of nums are not necessarily unique.
```

**Constraints**

- 1 <= nums.length <= 5 * 104
- -5 * 104 <= nums[i] <= 5 * 104

## 题目（中文翻译）

给定一个整数数组（array）`nums`，请将该数组按升序（ascending order）排序并返回。  
要求在 **O(nlog n)** 时间复杂度内完成，并且使用尽可能小的空间复杂度，**不**使用任何内置函数（built‑in functions）。

**示例 1**  
**输入**: `nums = [5,2,3,1]`  
**输出**: `[1,2,3,5]`  
**解释**: 排序后，部分数字的位置保持不变（例如 2 和 3），而其他数字的位置发生了变化（例如 1 和 5）。

**示例 2**  
**输入**: `nums = [5,1,1,2,0,0]`  
**输出**: `[0,0,1,1,2,5]`  
**解释**: 注意，`nums` 中的数值不一定唯一。

**约束条件**  
- `1 <= nums.length <= 5 * 10^4`  
- `-5 * 10^4 <= nums[i] <= 5 * 10^4`   (其中 `nums[i]` 为数组中的元素)

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  
最直接、最笨的想法就是**两两比较、不断交换**，把大的元素慢慢“冒泡”到数组的右边，或者每一次都在未排序的部分里挑出最小（或最大）的元素放到正确位置。  
- **数据结构**：只用原始的 Python 列表（list），相当于一排装有数字的格子。  
- **生活化类比**：想象你手里有一堆扑克牌，想把它们从小到大排好。最笨的办法就是从左到右一次遍历，看到一张比左边的牌大就交换位置，反复多次直到所有牌都不再需要交换——这就是**冒泡排序**（Bubble Sort）。  

**为什么正确**：每一次遍历都会把当前未排好序的最大（或最小）元素放到序列的最右（或最左），所以经过 `n-1` 次遍历后，所有元素都在正确的位置上。  

#### 代码（Python）  
```python
def bubble_sort(nums):
    n = len(nums)
    # 外层循环控制遍历次数，最多需要 n-1 次
    for i in range(n - 1):
        # 内层循环两两比较相邻元素
        for j in range(0, n - 1 - i):
            # 如果左边的比右边的大，就交换
            if nums[j] > nums[j + 1]:
                nums[j], nums[j + 1] = nums[j + 1], nums[j]   # 交换位置
    return nums

# ------------------- 示例 -------------------
print(bubble_sort([5, 2, 3, 1]))          # [1, 2, 3, 5]
print(bubble_sort([5, 1, 1, 2, 0, 0]))   # [0, 0, 1, 1, 2, 5]
```

#### 复杂度  
- **时间复杂度**：`O(n²)`  
  - “O” 读作“大约”，`n²` 表示当数组长度 `n` 加倍时，比较次数会变成原来的 **四倍**（因为是 `n` 乘 `n`）。对 10 000 个数来说，比较次数大约是 100 000 000 次，明显太慢。  
- **空间复杂度**：`O(1)`  
  - 只用了常数级别的额外变量（`i、j、tmp`），不随 `n` 增长。

---

### 2. 最优解  

#### 思路  
从暴力解可以看到，**瓶颈在于大量的无效比较**。我们需要一种能够一次性把大量元素归位的技巧。  
- **核心想法**：把数组看成一棵**完全二叉树**，利用**堆（Heap）**的结构，让每次都能在 `log n` 的时间里找到当前最大的元素。  
- **为什么堆能加速**：在最大堆里，根节点必然是当前未排序部分的最大值。把根和最后一个元素交换后，只需要对根所在的子树重新调整（称为 **下沉 / sift‑down**），这一步的代价是树的高度 `log n`。对每个元素都做一次这种操作，总时间就是 `n log n`。  
- **空间最小化**：堆可以 **原地** 建立在原数组上，不需要额外的数组，只需要常数级的临时变量，所以空间是 `O(1)`（递归实现的话会有 `O(log n)` 的栈空间，这里用循环实现避免）。  

下面一步步解释如何实现原地堆排序：  

1. **建堆**（Heapify）  
   - 从最后一个非叶子节点 `n//2 - 1` 开始，向前遍历，对每个节点执行 **下沉**，让它满足堆的性质。  
2. **排序**  
   - 交换根（最大值）和最后一个元素，使最大值放到数组末尾。  
   - 把堆的大小减 1（因为末尾已经是排好序的），对新的根再次下沉。  
   - 重复上述步骤，直至堆的大小为 1。  

**类比**：想象你有一堆石子，要把最大的石子一个个搬到最远的地方。先把所有石子排成一座小山（最大堆），山顶的石子最大，搬走后山体重新形成新山顶，如此循环，最终所有石子都被搬到远处，且顺序恰好是从小到大。  

#### 代码（Python）  
```python
def heap_sort(nums):
    """原地堆排序，时间 O(n log n)，空间 O(1)"""

    n = len(nums)

    # ---------- 1. 建立最大堆 ----------
    # 从最后一个非叶子节点开始向前 sift_down
    for start in range(n // 2 - 1, -1, -1):
        sift_down(nums, start, n - 1)

    # ---------- 2. 依次取出堆顶 ----------
    for end in range(n - 1, 0, -1):
        # 把当前最大的放到数组末尾
        nums[0], nums[end] = nums[end], nums[0]   # 交换根与最后一个元素
        # 重新整理剩余的 [0, end-1] 区间，使其仍然是最大堆
        sift_down(nums, 0, end - 1)

    return nums


def sift_down(arr, start, end):
    """
    让下标为 start 的节点下沉，使 [start, end] 区间满足最大堆性质。
    完全使用循环避免递归占用额外栈空间。
    """
    root = start

    while True:
        child = 2 * root + 1          # 左子节点下标
        if child > end:
            break                     # 已经没有子节点，结束

        # 如果右子节点存在且更大，指向右子节点
        if child + 1 <= end and arr[child] < arr[child + 1]:
            child += 1

        # 如果根已经大于等于最大的子节点，堆已经建好
        if arr[root] >= arr[child]:
            break

        # 否则交换根和较大的子节点，继续向下检查
        arr[root], arr[child] = arr[child], arr[root]
        root = child                  # 继续向下沉


# ------------------- 示例 -------------------
print(heap_sort([5, 2, 3, 1]))          # [1, 2, 3, 5]
print(heap_sort([5, 1, 1, 2, 0, 0]))   # [0, 0, 1, 1, 2, 5]
```

#### 复杂度  
- **时间复杂度**：`O(n log n)`  
  - “`log n`” 是二叉树的高度，大约是 `⌈log₂ n⌉`。对每个元素我们最多进行一次 “下沉” 操作，费用是 `log n`，所以整体是 `n × log n`。相较于暴力的 `n²`，当 `n = 10⁴` 时，`n log n` 只有几万次比较，几乎瞬间完成。  
- **空间复杂度**：`O(1)`  
  - 只用了几个临时变量（`root、child、tmp`），不随 `n` 增长。递归版会产生 `O(log n)` 的栈空间，这里用循环写成了 **原地** 实现，真正做到常数级额外空间。  

---

## 心得  

- **核心技巧**：利用 **堆（Heap）** 的特性实现原地排序，达到 `O(n log n)` 时间、`O(1)` 额外空间。  
- **适用的题型**  
  1. “前 K 大/小元素”——可以先建堆后弹出。  
  2. “合并 K 个已排序链表”——用最小堆每次取最小值。  
  3. “寻找中位数”——用两个堆维护上半部分和下半部分。  
- **一句话总结**：**把数组当成完全二叉树，用“最大堆”把最大的元素一次搬到末尾，就能在 `n log n` 内完成排序**。

## 反思  

- **第一反应**：直接想到“遍历两两比较”，于是写出了冒泡/选择排序。  
- **最容易踩的坑**  
  - **下标越界**：堆的左子节点是 `2*i+1`，右子节点是 `2*i+2`，一定要先判断左子节点是否越界，再比较右子节点是否存在。  
  - **原地建堆的起始位置**：忘记从 `n//2 - 1` 开始向前遍历，会导致部分节点没有被调整，堆属性不成立。  
  - **递归栈空间**：如果用递归实现 `sift_down`，在最坏情况下栈深度是 `log n`，对极端大数组仍然可以接受，但面试中常常要求 “原地、常数额外空间”，所以最好写成循环。  
- **下次第一步**：先判断“是否可以利用已有结构一次定位最大/最小”，如果可以，就考虑 **堆**；如果数据范围很小（如本题的 `[-5·10⁴, 5·10⁴]`），也可以先评估 **计数排序**（线性时间）是否更合适。
