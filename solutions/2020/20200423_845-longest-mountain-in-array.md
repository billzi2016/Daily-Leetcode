# #845. 数组中的最长山脉 / Longest Mountain in Array

> 难度：中等 · 标签：Array、Two Pointers、Dynamic Programming、Enumeration · [LeetCode 链接](https://leetcode.com/problems/longest-mountain-in-array/)

## 题目（英文原版）

**Description**

You may recall that an array arr is a mountain array if and only if:
Given an integer array arr, return the length of the longest subarray, which is a mountain. Return 0 if there is no mountain subarray.
Follow up:

**Examples**

**Example 1:**

```
Input: arr = [2,1,4,7,3,2,5]
Output: 5
Explanation: The largest mountain is [1,4,7,3,2] which has length 5.
```

**Example 2:**

```
Input: arr = [2,2,2]
Output: 0
Explanation: There is no mountain.
```

**Constraints**

- 1 <= arr.length <= 104
- 0 <= arr[i] <= 104

## 题目（中文翻译）

你可能还记得，若且唯若满足以下条件，整数数组 `arr` 被称为山脉数组（mountain array）：

- 存在一个下标 `i`，满足 `0 < i < arr.length - 1`；
- `arr[0] < arr[1] < … < arr[i]`（严格递增）；
- `arr[i] > arr[i + 1] > … > arr[arr.length - 1]`（严格递减）。

给定一个整数数组 `arr`，返回其中最长的子数组（subarray）的长度，该子数组是一段山脉。如果不存在山脉子数组，返回 `0`。

**示例 1：**  
**输入：** `arr = [2,1,4,7,3,2,5]`  
**输出：** `5`  
**解释：** 最大的山脉是 `[1,4,7,3,2]`，长度为 `5`。

**示例 2：**  
**输入：** `arr = [2,2,2]`  
**输出：** `0`  
**解释：** 不存在山脉。

**约束条件：**  
- `1 <= arr.length <= 10^4`  
- `0 <= arr[i] <= 10^4`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**枚举所有可能的子数组**，判断它是否满足“山形”条件，满足的就记下长度，最后取最大值。

- **子数组**：在数组里连续的一段元素，就像我们从一串珠子里挑出一段连续的珠子。
- **山形数组**：必须先严格递增（每个数都比左边的大），再严格递减（每个数都比左边的小），且两段都至少要有一个元素。可以把它想象成先爬山再下山的路径。
- **判断山形**：遍历子数组一次，先走“上坡”直到不再递增，再走“下坡”直到不再递减。如果两段都走过且恰好遍历完子数组，就说明是山形。

因为我们要**枚举所有子数组**，所以外层循环选子数组的左端点 `i`，内层循环选右端点 `j`（`j > i`），总共会产生 `O(n²)` 个子数组。每个子数组再线性扫描一次判断是否是山形，时间复杂度会是 `O(n³)`，但我们可以在判断时直接在同一次扫描里完成，这样整体时间是 `O(n²)`。

> **哈希表类比**：如果要快速判断某个数是否出现过，我们会用“查字典”。这里我们不需要哈希表，只需要顺序遍历（就像从左到右读一本书），所以用的只是 **数组** 本身。

#### 代码（Python）

```python
def longestMountain_brute(arr):
    n = len(arr)
    max_len = 0

    # 枚举子数组的左端点 i
    for i in range(n):
        # 右端点 j 必须至少比 i 大 2，才能形成“上坡+下坡”
        for j in range(i + 2, n):
            # 判断 arr[i:j+1] 是否是山形
            k = i
            # 1）上坡：必须严格递增
            while k + 1 <= j and arr[k] < arr[k + 1]:
                k += 1

            # 如果没有上坡，直接不是山形
            if k == i:          # 没有任何递增
                continue

            # 2）下坡：必须严格递减
            while k + 1 <= j and arr[k] > arr[k + 1]:
                k += 1

            # 必须恰好走到子数组的右端点，且两段都走过
            if k == j:          # 完全遍历完子数组，说明是山形
                max_len = max(max_len, j - i + 1)

    return max_len
```

#### 复杂度  

- **时间复杂度**：`O(n²)`  
  - “`n²`” 的意思是如果数组长度是 10，最坏情况下要检查大约 `10 × 10 = 100` 次子数组；如果长度是 1000，就要检查约 `1,000,000` 次。随着 `n` 增大，检查次数呈二次方增长，会很快变慢。
- **空间复杂度**：`O(1)`  
  - 只用了常数个额外变量（指针 `i, j, k` 和 `max_len`），不随输入规模增长。

### 2. 最优解

#### 思路  

暴力解的瓶颈在 **“枚举所有子数组”**，这一步导致了 `O(n²)`。其实我们不需要显式枚举子数组，只要 **一次线性扫描** 就能知道每个位置能否作为山峰的顶点，以及从该顶点向左/右能延伸多远。

**核心思路**：

1. **找山峰**：山峰必须满足 `arr[i-1] < arr[i] > arr[i+1]`（左边比它小，右边也比它小）。这一步只需要一次遍历 O(n)。
2. **向左扩展**：从山峰向左一直往回走，只要满足严格递增（`arr[left-1] < arr[left]`），就把 `left` 往左移。
3. **向右扩展**：同理，从山峰向右一直往前走，只要满足严格递减（`arr[right] > arr[right+1]`），就把 `right` 往右移。
4. **记录长度**：子数组 `[left, right]` 就是一座合法的山，长度是 `right - left + 1`。更新全局最大值。
5. **跳过已检查的区间**：因为我们已经把山的整个区间扫过了，下一次循环可以直接把指针 `i` 移到 `right` 的后面，避免重复工作。

这样整个过程只需要 **一次线性遍历**，时间是 `O(n)`，空间只用常数。

**从零解释关键概念**：

- **双指针**：想象有两只手，一只手从山峰左边往左抓，另一只手从山峰右边往右抓，直到抓不到为止。两只手的距离就是山的宽度。
- **严格递增/递减**：必须每一步都严格变大或变小，等于“不能平坦”。如果出现相等的情况，就相当于路上出现了“停下来不走”，山就不完整了。

#### 代码（Python）

```python
def longestMountain(arr):
    n = len(arr)
    max_len = 0
    i = 1                     # 从第二个元素开始，才可能是山峰

    while i < n - 1:          # 最后一个元素不可能是山峰
        # 1）判断 i 是否是山峰：左边比它小，右边也比它小
        if arr[i - 1] < arr[i] > arr[i + 1]:
            # 2）向左扩展，找上坡的最左端
            left = i - 1
            while left > 0 and arr[left - 1] < arr[left]:
                left -= 1

            # 3）向右扩展，找下坡的最右端
            right = i + 1
            while right + 1 < n and arr[right] > arr[right + 1]:
                right += 1

            # 4）更新最大山的长度
            cur_len = right - left + 1
            max_len = max(max_len, cur_len)

            # 5）把 i 跳到右端的后面，避免重复检查同一座山
            i = right + 1
        else:
            i += 1              # 不是山峰，继续往前走

    return max_len
```

#### 复杂度  

- **时间复杂度**：`O(n)`  
  - “`O(n)`” 的意思是如果数组长度是 10，需要检查大约 10 次；长度是 10,000，只需要检查 10,000 次，随规模线性增长，速度很快。
- **空间复杂度**：`O(1)`  
  - 只用了几个指针变量 (`i, left, right, max_len`) ，不随输入大小增长。

---

## 心得

- **核心技巧**：**一次遍历找山峰 + 双指针向两侧扩展**，即 “先定位，再展开”。  
- **适用的题型**：  
  1. “最长递增子数组” 类似的，需要先定位递增/递减的拐点。  
  2. “最长平衡子数组” 需要先找满足条件的中心点，然后向两侧扩展。  
  3. “最长子数组满足特定模式（如波浪形）” 也可以用类似的定位+展开思路。  
- **一句话总结**：**先找到山峰（拐点），再向左上坡、向右下坡扩展，一遍扫描搞定。**

## 反思

- **第一反应**：看到“山形”，自然会想到先找最高点（山峰），因为山的定义围绕峰值展开。  
- **最容易踩的坑**：  
  - **平坦段**（相等的相邻元素）不能算作上坡或下坡，必须跳过。  
  - **边界条件**：数组长度小于 3 时一定没有山，需提前返回 0。  
  - **重复计数**：如果不把指针 `i` 跳到右端后面，可能会在同一座山上多次循环，导致时间退化。  
- **下次类似题的第一步**：**先定位满足特殊条件的“中心/拐点”，再用双指针向两侧扩展**，这样往往可以把复杂度降到线性。
