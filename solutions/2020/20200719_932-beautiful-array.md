# #932. 美丽数组 / Beautiful Array

## 题目（英文原版）

**Description**

An array nums of length n is beautiful if:
Given the integer n, return any beautiful array nums of length n. There will be at least one valid answer for the given n.

**Examples**

**Example 1:**

```
Input: n = 4
Output: [2,1,4,3]
```

**Example 2:**

```
Input: n = 5
Output: [3,1,2,5,4]
```

**Constraints**

- 1 <= n <= 1000

---

## 题目（中文翻译）

如果一个长度为 `n` 的数组 `nums` 满足以下条件，则称它为 **美丽数组（beautiful array）**：

- 对任意满足 `0 ≤ i < j < n` 的下标 `i` 与 `j`，不存在下标 `k` 使得 `i < k < j` 且 `nums[k] * 2 = nums[i] + nums[j]`。  
  换句话说，数组中不存在某个元素恰好等于任意两个元素的平均值。

给定整数 `n`，返回任意一个长度为 `n` 的美丽数组 `nums`。题目保证对于给定的 `n` 至少存在一个有效答案。

```
n = 4
```
**输出**  
```
[2,1,4,3]
```

### 示例 2
**输入**  
```
n = 5
```
**输出**  
```
[3,1,2,5,4]
```

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是 **把所有可能的排列都枚举出来**，然后逐一检查它是否满足 “美丽数组” 的定义。  

- **数据结构**：我们可以把排列当成一个列表（list），就像把一串数字排成一行。  
- **检查条件**：遍历数组中的每一对下标 `i < j`，在它们之间找是否存在下标 `k`（`i < k < j`）使得  

```
nums[k] * 2 == nums[i] + nums[j]
```

如果找到了，说明 `nums[k]` 正好是 `nums[i]` 与 `nums[j]` 的平均值，这种情况是 **不允许** 的；否则这对 `(i,j)` 就算 “安全”。所有 `(i,j)` 都安全，则整个数组就是美丽的。  

- **为什么正确**：因为我们把**所有**排列都尝试了一遍，只要有一种排列满足条件，就一定能找到并返回它。  

- **复杂度分析**  
  - 枚举所有排列的数量是 `n!`（阶乘），这在数学上记作 `O(n!)`，意思是随着 `n` 增大，运算次数会非常非常快地增长（比如 `5! = 120`, `8! = 40320`）。  
  - 对每个排列检查条件需要两层循环遍历 `i`、`j`，内部再遍历 `k`，最坏情况是 `O(n³)`。  
  - 综合下来，总时间复杂度是 `O(n! * n³)`，对 `n=1000` 完全不可接受。  
  - 只使用了一个列表存放当前排列，空间复杂度是 `O(n)`（存放数组本身）。

#### 代码（Python）

```python
import itertools

def is_beautiful(arr):
    """检查 arr 是否满足“美丽数组”条件"""
    n = len(arr)
    for i in range(n):
        for j in range(i + 1, n):
            # 在 i 与 j 之间找是否有 k 使 arr[k] 是它们的平均值
            for k in range(i + 1, j):
                if arr[k] * 2 == arr[i] + arr[j]:
                    return False          # 发现违背条件的情况
    return True                       # 没有任何违背条件的情况

def beautiful_array_bruteforce(n):
    """暴力枚举所有排列，返回第一组满足条件的数组（仅适用于 n 很小的情况）"""
    for perm in itertools.permutations(range(1, n + 1)):
        if is_beautiful(perm):
            return list(perm)          # 找到后直接返回
    return []                          # 理论上不会走到这里，因为题目保证有解
```

> **提示**：上述函数只适合 `n ≤ 8` 左右的调试，`n = 9` 已经需要遍历 362880 种排列，执行时间会明显变慢。

#### 复杂度

- **时间复杂度**：`O(n! * n³)`  
  - “`n!`” 表示所有排列的数量，`n³` 表示每个排列内部的三层遍历。  
- **空间复杂度**：`O(n)`  
  - 只用了一个长度为 `n` 的列表来存放当前排列。

### 2. 最优解

#### 思路  

从暴力解可以看出，**枚举所有排列是最慢的环节**。我们需要一种能够 **直接构造** 出符合要求的排列，而不是盲目搜索。  

**关键观察**  
- 如果把数组中的每个数都 **乘以 2 再减 1**（即 `2*x-1`），得到的所有数都是 **奇数**；  
- 如果把每个数都 **乘以 2**（即 `2*x`），得到的所有数都是 **偶数**。  
- **奇数之间** 或 **偶数之间** 的平均值一定是 **整数**，而奇数与偶数的平均值 **不可能是整数**（因为奇+偶 = 奇，除以 2 会得到 .5），所以 **奇数集合和偶数集合之间不会互相产生“平均值冲突”**。  

这意味着：  
> **只要把一个已经是美丽数组的序列分别映射成全奇数序列和全偶数序列，再把这两段拼在一起，就仍然是美丽的。**

于是我们可以采用 **分治（divide‑and‑conquer）** 的思路：

1. **递归基**：当 `n = 1` 时，数组 `[1]` 显然是美丽的。  
2. **递归构造**：假设我们已经得到了长度为 `m`（`m = ⌈n/2⌉`）的美丽数组 `prev`。  
   - 通过 `odd = [2*x - 1 for x in prev]` 得到一段全奇数的序列。  
   - 通过 `even = [2*x for x in prev]` 得到一段全偶数的序列。  
   - 把 `odd` 与 `even` 合并得到长度不超过 `2*m` 的新数组。  
3. **裁剪**：如果新数组的长度超过了目标 `n`，只取前 `n` 个元素即可。  

因为每一次递归都把规模 **至少减半**（`⌈n/2⌉`），递归深度是 `O(log n)`，每层的工作量是 `O(current length)`，累计下来总时间是 `O(n log n)`，空间只需要保存递归栈和临时数组，都是 `O(n)`。

**类比**：把这一步想象成 **“先把原来的数字变成小孩的年龄（奇数），再让他们长大变成大人的年龄（偶数）”，小孩之间不会和大人之间产生冲突”。  

#### 代码（Python）

```python
def beautiful_array(n: int):
    """
    返回任意一个长度为 n 的美丽数组。
    思路：递归构造——先得到更小规模的美丽数组，再映射成奇数、偶数两段拼接。
    """
    if n == 1:
        return [1]                     # 递归终止条件，显然是美丽的

    # 递归得到长度为 ceil(n/2) 的美丽数组
    prev = beautiful_array((n + 1) // 2)

    # 通过映射得到全奇数和全偶数两段
    odd  = [2 * x - 1 for x in prev]   # 例：1 -> 1, 2 -> 3, 3 -> 5 ...
    even = [2 * x     for x in prev]   # 例：1 -> 2, 2 -> 4, 3 -> 6 ...

    # 合并后可能会比 n 长，切掉多余的部分
    result = odd + even
    return result[:n]                  # 只保留前 n 个元素

# ------------------- 测试 -------------------
if __name__ == "__main__":
    for n in range(1, 11):
        arr = beautiful_array(n)
        print(n, arr)
```

> **代码要点**  
> - `prev = beautiful_array((n + 1) // 2)` 使用了向上取整（`ceil`），确保奇数段能覆盖所有位置。  
> - `odd + even` 的顺序固定为奇数在前、偶数在后，这正好满足 “奇数之间、偶数之间不会冲突，奇偶之间也不会冲突”。  
> - 最后 `result[:n]` 把可能的多余元素裁掉，保证返回的长度恰好是 `n`。

#### 复杂度

- **时间复杂度**：`O(n log n)`  
  - “`log n`” 表示递归深度大约是对数级；每层我们遍历当前数组一次，累计下来是 `n + n/2 + n/4 + … = O(n)`，再乘以层数 `log n`。相比暴力的 `n!`，增长非常慢，`n = 1000` 也能在毫秒级完成。  
- **空间复杂度**：`O(n)`  
  - 需要存放递归返回的数组以及临时的 `odd`、`even` 列表，最多占用与输出同等规模的空间。

## 心得

- **核心技巧**：利用 **奇偶分离** + **递归构造**，把“大问题”拆成“小问题”，每一步都保证不产生“平均值冲突”。  
- **适用场景**：  
  1. **Beautiful Array**（本题）  
  2. **构造不相邻相同的序列**（如 “Avoid Adjacent Duplicates”）  
  3. **利用奇偶或其他二分映射避免冲突的题目**（比如 “Permutation with Non‑adjacent Differences”）  
- **一句话总结**：**把原数组映射成全奇数和全偶数两段，再拼接，就是“冲突免疫”的钥匙**。

## 反思

- **第一反应**：直接去枚举所有排列，想到“暴力搜索”。  
- **最容易踩的坑**  
  - 忽视 **平均值必须是整数** 的前提，导致错误的冲突判断。  
  - 对递归基的设定不明确，可能出现无限递归。  
  - 在合并奇偶段后忘记裁剪，返回的长度会超过 `n`。  
- **下次遇到同类题**：第一步先思考 **能否把元素划分到互不干扰的子集合**（如奇偶、模 `k` 等），再尝试 **递归或迭代地在子集合内部构造**，最后再合并。这样往往能把“暴力搜索”直接跳过，直接得到构造式答案。
