# #954. 成对双倍数组 / Array of Doubled Pairs

> 难度：中等 · 标签：Array、Hash Table、Greedy、Sorting · [LeetCode 链接](https://leetcode.com/problems/array-of-doubled-pairs/)

---

## 题目（英文原版）

**Description**

Given an integer array of even length arr, return true if it is possible to reorder arr such that arr[2 * i + 1] = 2 * arr[2 * i] for every 0 <= i < len(arr) / 2, or false otherwise.

**Examples**

**Example 1:**

```
Input: arr = [3,1,3,6]
Output: false
```

**Example 2:**

```
Input: arr = [2,1,2,6]
Output: false
```

**Example 3:**

```
Input: arr = [4,-2,2,-4]
Output: true
Explanation: We can take two groups, [-2,-4] and [2,4] to form [-2,-4,2,4] or [2,4,-2,-4].
```

**Constraints**

- 2 <= arr.length <= 3 * 104
- arr.length is even.
- -105 <= arr[i] <= 105

---

## 题目（中文翻译）

给定一个长度为偶数的整数数组 `arr`，如果可以重新排列 `arr` 使得对所有 `0 <= i < len(arr) / 2` 都满足  

`arr[2 * i + 1] = 2 * arr[2 * i]`  

则返回 `true`，否则返回 `false`。

## 示例

### 示例 1
**输入:** `arr = [3,1,3,6]`  
**输出:** `false`

### 示例 2
**输入:** `arr = [2,1,2,6]`  
**输出:** `false`

### 示例 3
**输入:** `arr = [4,-2,2,-4]`  
**输出:** `true`  
**解释:** 我们可以将数组划分为两组 `[-2,-4]` 和 `[2,4]`，从而得到 `[-2,-4,2,4]` 或 `[2,4,-2,-4]`。

## 约束条件
- `2 <= arr.length <= 3 * 10^4`
- `arr.length` 为偶数
- `-10^5 <= arr[i] <= 10^5`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**枚举所有可能的重排**，然后检查每一种是否满足  
`arr[2*i+1] = 2 * arr[2*i]`（即把数组两两配对，后一位是前一位的两倍）。  

实现思路：

1. 把数组的所有排列列举出来（可以使用 `itertools.permutations`）。
2. 对每一种排列，按下标两两检查是否满足条件。
3. 只要找到一种满足的排列，就返回 `True`；全部遍历完仍未找到则返回 `False`。

**数据结构**：  
- `list` 用来保存当前的排列。  
- `itertools.permutations` 类似于“全排列机器”，一次性把所有可能的顺序都列出来。可以把它想象成“把所有可能的排队顺序都写在纸上”，然后逐张检查。

**为什么正确**：  
因为我们穷举了 **所有** 可能的重排，只要有一种符合题意的配对方式，就一定会在枚举过程中被发现。

**时间/空间复杂度**：  
- **时间**：全排列的数量是 `n!`（`n` 为数组长度），每个排列要检查 `n/2` 对。于是时间复杂度是 `O(n! * n)`，这在实际中几乎不可接受。  
  大白话：如果数组有 10 个元素，`10! = 3,628,800`，要检查上千万次，根本跑不完。  
- **空间**：存放一次排列需要 `O(n)` 的额外空间，`itertools.permutations` 生成器本身只占很小的常数空间。

#### 代码（Python）

```python
import itertools
from typing import List

def can_reorder_bruteforce(arr: List[int]) -> bool:
    # 对每一种可能的全排列进行检查
    for perm in itertools.permutations(arr):
        ok = True
        # 按两两检查：后一个是否是前一个的两倍
        for i in range(0, len(perm), 2):
            if perm[i + 1] != 2 * perm[i]:
                ok = False
                break
        if ok:                     # 只要找到一种满足条件的排列就返回 True
            return True
    return False                  # 所有排列都不行，返回 False
```

#### 复杂度

- **时间复杂度**：`O(n! * n)` — 需要遍历所有排列，每个排列再检查 `n/2` 对。  
- **空间复杂度**：`O(n)` — 保存一次排列的临时列表（生成器本身几乎不占额外空间）。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**枚举所有排列**。实际上我们并不需要真的把数组排好顺序，只要能把每个数找到对应的 “两倍” 或 “一半” 即可。关键观察：

1. **配对顺序**：如果我们把数组从小到大（绝对值）排序，先处理**绝对值小的数**，那么它们的配对对象（两倍）一定在后面。这样可以避免出现“后面的数已经被别的前面的数抢走”的冲突。  
2. **哈希表计数**：我们只关心每个数出现了多少次。用哈希表（字典）记录频次，相当于“查字典”，`key` 是数值，`value` 是出现次数。  
3. **配对过程**：遍历排好序的数组：
   - 如果当前数已经被配对完（计数为 0），直接跳过。  
   - 否则，找它的两倍 `2 * x`（如果 `x` 为负数，同样适用）。如果两倍的计数不足，则无法完成配对，直接返回 `False`。  
   - 否则，把 `x` 和 `2*x` 的计数各减一，表示这对已经配好。

这样只需要一次排序 `O(n log n)`，加上一次线性遍历 `O(n)`，总时间 `O(n log n)`，空间 `O(n)`（哈希表）。

**为什么正确**：  
- 按绝对值升序处理，保证每次配对的 “大数” 还未被使用，因为它必然在后面出现。  
- 哈希表确保我们严格控制每个数的使用次数，防止重复配对。  
- 若在遍历过程中出现配对失败，说明不存在合法的重排。

**关键数据结构解释**：  
- **字典（哈希表）**：想象成一本词典，单词是数组的数值，页码是该数出现的次数。查找和修改（增删）都非常快，时间近似 `O(1)`。  
- **排序**：把数列从小到大排好顺序，就像把所有商品按重量从轻到重排好，方便先挑轻的，再找对应的重的。

#### 代码（Python）

```python
from typing import List
from collections import Counter

def can_reorder(arr: List[int]) -> bool:
    # 1. 统计每个数出现的次数（相当于查字典）
    cnt = Counter(arr)                     # 例如 [-2, -4, 2, 4] -> {-2:1, -4:1, 2:1, 4:1}
    
    # 2. 按绝对值从小到大排序，保证先处理“小的数”
    for x in sorted(arr, key=abs):
        if cnt[x] == 0:                     # 这个数已经被配对完，跳过
            continue
        
        # 3. 检查两倍的数是否足够
        if cnt[2 * x] == 0:                 # 没有足够的 2*x 可以配对
            return False
        
        # 4. 配对成功，两个数的计数各减一
        cnt[x] -= 1
        cnt[2 * x] -= 1
    
    # 所有数都成功配对
    return True
```

#### 复杂度

- **时间复杂度**：`O(n log n)` — 主要是排序的代价（`n` 为数组长度），遍历和字典操作都是线性 `O(n)`。  
  对比暴力解的 `n!`，这里的增长非常温和，几万规模的数据也能轻松跑完。  
- **空间复杂度**：`O(n)` — 哈希表需要存储每个不同数的计数，最坏情况每个数都不同。

## 心得

- **核心技巧**：**先按绝对值排序 + 哈希计数配对**。  
- **适用的题型**：  
  1. “配对”类题目，如 *Array of Doubled Pairs*、*Find Array Given Subtraction*（配对差值），  
  2. “拆分/合并”类题目，如 *Split Array into Consecutive Subarrays*（按顺序配对），  
  3. “计数”类题目，如 *Longest Subarray With Maximum Frequency*（需要快速统计出现次数）。  
- **一句话总结解题钥匙**：**把“先处理小的、后处理大的”这条原则写进代码**——排序后配对，保证大数不被抢走。

## 反思

- **第一反应**：看到“arr[2*i+1] = 2 * arr[2*i]”，自然想到把数组两两配对，于是想到全排列暴力搜索。  
- **最容易踩的坑**：  
  - 负数的情况：`-2` 的两倍是 `-4`，如果只考虑正数会出错。  
  - 零的特殊性：`0` 的两倍仍是 `0`，需要保证出现次数为偶数，否则配不成。  
  - 计数更新时忘记同时减去两数的次数，导致重复使用。  
- **下次遇到同类题**：第一步先**统计频次并按绝对值排序**，再尝试用“贪心配对”思路一步步消除。这样可以快速排除不可能的情况，避免暴力枚举的时间炸弹。
