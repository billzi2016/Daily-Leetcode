# #989. 整数的数组形式加法 / Add to Array-Form of Integer

> 难度：简单 · 标签：Array、Math · [LeetCode 链接](https://leetcode.com/problems/add-to-array-form-of-integer/)

---

## 题目（英文原版）

**Description**

The array-form of an integer num is an array representing its digits in left to right order.
Given num, the array-form of an integer, and an integer k, return the array-form of the integer num + k.

**Examples**

**Example 1:**

```
Input: num = [1,2,0,0], k = 34
Output: [1,2,3,4]
Explanation: 1200 + 34 = 1234
```

**Example 2:**

```
Input: num = [2,7,4], k = 181
Output: [4,5,5]
Explanation: 274 + 181 = 455
```

**Example 3:**

```
Input: num = [2,1,5], k = 806
Output: [1,0,2,1]
Explanation: 215 + 806 = 1021
```

**Constraints**

- 1 <= num.length <= 104
- 0 <= num[i] <= 9
- num does not contain any leading zeros except for the zero itself.
- 1 <= k <= 104

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把数组 `num` 先变成普通的整数，再和 `k` 相加，最后把结果拆成每一位放回数组。  
这就像我们平时把一串数字写在纸上，再用计算器算出和，最后把答案重新抄回纸上。

- **把数组变成整数**：把每个数字当作十进制的位，从左到右依次拼接。相当于把字典里“词”换成“页码”，这里的“词”是每一位数字，“页码”是它在十进制中的权值（十的幂次）。
- **相加**：直接使用 Python 的大整数运算即可（Python 的 `int` 可以任意大）。
- **拆分回数组**：把得到的整数转成字符串，再把每个字符转回整数放入列表。

这个方法一定能得到正确答案，因为我们没有省略任何数学步骤，只是把人类的手工加法交给了计算机。

#### 代码（Python）

```python
def addToArrayForm(num, k):
    # 1. 把数组转成整数
    #   例如 [1,2,0,0] -> 1200
    n = 0
    for d in num:                 # 逐位累加
        n = n * 10 + d            # 相当于左移一位再加当前数字

    # 2. 直接相加
    total = n + k                  # Python 的大整数自动处理进位

    # 3. 把结果拆成数组
    #   先把整数转成字符串，再把每个字符转成整数
    return [int(ch) for ch in str(total)]
```

#### 复杂度

- **时间复杂度**：`O(m + log₁₀(total))`，其中 `m = len(num)`。  
  - 把数组转成整数需要遍历一次 `num` → `O(m)`。  
  - 把结果转成字符串需要遍历结果的每一位，位数大约是 `max(m, log₁₀(k))`，也记作 `O(m)`。  
  所以整体仍是线性时间 `O(m)`，可以想象成“把所有数字读一遍”。

- **空间复杂度**：`O(m)` 用来存放返回的数组（答案本身的大小），额外的临时空间只有常数级。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**把整个数组一次性转成一个巨大的整数**，这在某些语言里会溢出，且不必要地占用了额外的空间。  
我们可以直接模拟手工加法的过程：从最低位（数组的最右侧）开始，加上 `k` 的对应位以及可能产生的进位（carry），把得到的每一位放进答案里。

关键点：

1. **双指针/倒序遍历**  
   - 用指针 `i` 从 `num` 的最后一个元素向前走。  
   - 同时把 `k` 看作一个整数，每次取 `k % 10` 获得最低位。

2. **进位 (carry)**  
   - 每一步的和可能超过 9，需要向更高位“进位”。  
   - 进位本质上是把 `sum // 10` 保存下来，下一轮相加。

3. **结束条件**  
   - 当 `i` 已经走完所有数组、`k` 已经除尽且 `carry` 为 0 时停止。

4. **结果的顺序**  
   - 我们是从低位往高位生成答案的，所以最后需要把列表反转回来。

类比：这就像我们在纸上从右往左做竖式加法，只是把纸上的每一步交给程序完成。

#### 代码（Python）

```python
def addToArrayForm(num, k):
    i = len(num) - 1          # 从数组最右侧开始
    carry = 0                 # 初始进位为 0
    res = []                  # 用来存放逆序的结果位

    while i >= 0 or k > 0 or carry:
        digit = num[i] if i >= 0 else 0   # 当前位的数字，若 i 已越界则视为 0
        k_digit = k % 10                  # k 的当前最低位

        total = digit + k_digit + carry   # 三者相加得到本位和
        res.append(total % 10)            # 本位的答案是 total % 10
        carry = total // 10               # 进位为 total // 10

        i -= 1
        k //= 10                           # 去掉已经使用的最低位

    # 现在 res 是逆序的，需要翻转成正常的左到右顺序
    return res[::-1]
```

#### 复杂度

- **时间复杂度**：`O(max(len(num), log₁₀(k)))`。  
  - 每一步我们同时消耗 `num` 的一位和 `k` 的一位（如果还有的话），所以循环次数等于两者中较大的位数。  
  - 可以把它想成“最多只需要看一遍最长的数字”。

- **空间复杂度**：`O(max(len(num), log₁₀(k)))` 用来存放答案（答案本身的长度），额外的临时空间只有常数级（几个变量）。

相比暴力解，这个方案不需要把整个数组拼成大整数，避免了可能的溢出风险，也更贴近人类的加法思路。

## 心得

- **核心技巧**：**模拟竖式加法 + 进位处理**，即从最低位向高位逐位相加。
- **适用场景**：  
  1. 两个大整数以数组或链表形式给出，需要求和（如 LeetCode 445 “Add Two Numbers”）。  
  2. 大数乘法/除法的逐位模拟。  
  3. 需要在不使用语言内置大整数的情况下处理超长数字。
- **一句话总结**：把加法拆成“每位相加 + 进位”，从右往左一步步算，最后逆序即得答案。

## 反思

- **第一反应**：把数组直接转成整数再相加，最省事，但会忽视语言限制和空间浪费。
- **最容易踩的坑**：  
  - 忘记处理 `num` 用完但 `k` 还有剩余的情况。  
  - 忘记在循环结束后把结果逆序返回。  
  - 进位没有在最后一次循环中清零（`carry` 仍可能为 1）。
- **下次遇到同类题**：第一步想到“**逐位相加 + 进位**”，决定是要转成整数还是直接模拟，依据语言特性和数据规模做选择。
