## 题目（中文翻译）

给定一个整数数组 `arr`，如果且仅如果它是一个有效的山脉数组（mountain array），则返回 `true`。

回想一下，`arr` 是山脉数组当且仅当满足以下条件：

1. `arr.length >= 3`（数组长度至少为 3）。  
2. 存在一个索引 `i`，满足 `0 < i < arr.length - 1`，使得  
   - `arr[0] < arr[1] < … < arr[i‑1] < arr[i]`（严格递增），且  
   - `arr[i] > arr[i+1] > … > arr[arr.length‑2] > arr[arr.length‑1]`（严格递减）。

换言之，数组必须先严格上升到峰值，然后再严格下降，且峰值不能位于数组的两端。

**示例**

```text
示例 1:
Input: arr = [2,1]
Output: false
```

```text
示例 2:
Input: arr = [3,5,5]
Output: false
```

```text
示例 3:
Input: arr = [0,3,2,1]
Output: true
```

**约束条件**

- `1 <= arr.length <= 10^4`
- `0 <= arr[i] <= 10^4`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**遍历所有可能的“峰顶位置”**，然后分别检查：

1. 峰顶左侧的元素是否严格递增（每个数都比左边的数大）。  
2. 峰顶右侧的元素是否严格递减（每个数都比左边的数小）。

如果找到一个位置同时满足这两个条件，那么整个数组就是合法的山脉；如果所有位置都不满足，则返回 `False`。

> **类比**：把数组想象成一条道路，山峰就是道路的最高点。我们要找出所有可能的最高点，然后检查左边的坡是一直往上爬，右边的坡是一直往下滑。

为什么这个方法一定能判断对错？因为山脉的定义**必须**在某个位置出现一次上升后紧接着一次下降，遍历所有位置就不会遗漏。

**时间复杂度**  
- 外层遍历所有 `n` 个位置。  
- 对每个位置，左侧检查最多 `i` 步，右侧检查最多 `n‑i‑1` 步。最坏情况下相当于 `n + (n‑1) + … + 1 ≈ n²/2`，用大 O 记作 **O(n²)**。  
- 用大白话说，就是如果数组长度是 1000，最坏情况下大约要比较 500 000 次。

**空间复杂度**  
- 只用了常数个变量（循环计数器、临时布尔值），所以是 **O(1)**，即几乎不占额外内存。

#### 代码（Python）

```python
def validMountainArray_brute(arr):
    n = len(arr)
    # 山脉至少要有 3 个元素，才能既有上坡又有下坡
    if n < 3:
        return False

    # 逐个把每个位置当作可能的峰顶
    for peak in range(1, n - 1):          # 峰不能在最左或最右
        # 1. 检查左侧是否严格递增
        inc = True
        for i in range(1, peak + 1):
            if arr[i] <= arr[i - 1]:     # 不满足递增
                inc = False
                break

        # 2. 检查右侧是否严格递减
        dec = True
        for i in range(peak + 1, n):
            if arr[i] >= arr[i - 1]:     # 不满足递减
                dec = False
                break

        # 同时满足递增和递减，说明找到了合法山脉
        if inc and dec:
            return True

    # 所有可能的峰都不行，返回 False
    return False
```

#### 复杂度

- **时间复杂度**：`O(n²)` —— 这里的 `n²` 表示随着数组长度的增长，比较次数会像 “平方” 那样快速增加。  
- **空间复杂度**：`O(1)` —— 只用了几个计数器，几乎不占额外内存。

### 2. 最优解

#### 思路  

暴力解的慢点在于 **每次都要重新遍历左侧和右侧**，导致大量重复比较。  
其实我们只需要一次遍历就能判断：

1. **先从左往右走**，一直走到不再递增的位置。此时的索引就是“峰顶候选”。  
2. 检查一下这个“峰顶”是否合法：  
   - 不能在数组最左边（没有上坡）  
   - 也不能在数组最右边（没有下坡）  
3. **继续从峰顶往右走**，检查剩余的元素是否全都递减。只要出现一次不递减，就说明不是山脉。

> **类比**：想象你在爬山，只往前走，不回头。先一直往上爬，直到再也爬不上去（到达山顶），然后继续往下走，确认一路都是下坡。如果中途出现平地或再次上坡，就说明这不是一座合格的山。

**关键点**：  
- “严格递增/递减”意味着相邻两个数**不能相等**。  
- 只需要一次线性扫描，时间是 **O(n)**。  
- 只用了几个指针变量，空间是 **O(1)**。

#### 代码（Python）

```python
def validMountainArray(arr):
    n = len(arr)
    # 山脉最少要有 3 个元素
    if n < 3:
        return False

    i = 0

    # 1. 上坡：arr[i] < arr[i+1]
    while i + 1 < n and arr[i] < arr[i + 1]:
        i += 1

    # 峰顶不能是第一个或最后一个元素
    if i == 0 or i == n - 1:
        return False

    # 2. 下坡：arr[i] > arr[i+1]
    while i + 1 < n and arr[i] > arr[i + 1]:
        i += 1

    # 如果走到了数组末尾，说明全程满足山脉条件
    return i == n - 1
```

#### 复杂度

- **时间复杂度**：`O(n)` —— 只遍历了一遍数组，意思是如果数组长度是 10 000，只需要大约 10 000 次比较，和长度成线性关系。  
- **空间复杂度**：`O(1)` —— 只用了几个整数变量（`i`、`n`），不随输入大小增长。

## 心得

- 这道题考察的核心技巧是 **一次遍历（双指针/单指针）判断单调性**，尤其是“先上升后下降”的模式。  
- 该技巧常见于类似题目：  
  1. **最长上升/下降子数组**（LeetCode 485）  
  2. **判断数组是否为递增或递减序列**（LeetCode 896）  
  3. **峰值索引**（LeetCode 162）  
- **一句话总结**：找到第一个不再上升的位置，它必须既不是开头也不是结尾，随后全部递减即可。

## 反思

- **第一反应**：看到“山脉”二字会想到“先升后降”，于是自然想到从左往右找峰顶。  
- **最容易踩的坑**：  
  - 忘记“严格”要求，导致相等的相邻元素被错误接受。  
  - 峰顶恰好在数组两端（只有上坡或只有下坡）也不算山脉。  
  - 对长度小于 3 的数组要直接返回 `False`，否则会出现索引越界。  
- **下次遇到同类题**，第一步应该想到 **“单次遍历 + 记录转折点”**，即先找增序的转折，再检查后面的单调性。
