# #779. 语法中的第 K 个符号 / K-th Symbol in Grammar

> 难度：中等 · 标签：Math、Bit Manipulation、Recursion · [LeetCode 链接](https://leetcode.com/problems/k-th-symbol-in-grammar/)

---

## 题目（英文原版）

**Description**

We build a table of n rows (1-indexed). We start by writing 0 in the 1st row. Now in every subsequent row, we look at the previous row and replace each occurrence of 0 with 01, and each occurrence of 1 with 10.
Given two integer n and k, return the kth (1-indexed) symbol in the nth row of a table of n rows.

**Examples**

**Example 1:**

```
Input: n = 1, k = 1
Output: 0
Explanation: row 1: 0
```

**Example 2:**

```
Input: n = 2, k = 1
Output: 0
Explanation: 
row 1: 0
row 2: 01
```

**Example 3:**

```
Input: n = 2, k = 2
Output: 1
Explanation: 
row 1: 0
row 2: 01
```

**Constraints**

- 1 <= n <= 30
- 1 <= k <= 2n - 1

## 题目（中文翻译）

我们构造一个包含 **n** 行（1 索引）的表（table）。第一行写入 `0`。在后续的每一行中，查看前一行，将所有出现的 `0` 替换为 `01`，将所有出现的 `1` 替换为 `10`。  
给定两个整数 **n** 和 **k**，返回第 **n** 行中第 **k** 个（1 索引）符号（symbol）。

**示例 1**  
``` 
Input: n = 1, k = 1
Output: 0
Explanation: row 1: 0
```  
解释：第 1 行仅有一个符号 `0`，因此第 1 个符号为 `0`。

**示例 2**  
``` 
Input: n = 2, k = 1
Output: 0
Explanation: 
row 1: 0
row 2: 01
```  
解释：第 2 行由第 1 行的 `0` 按规则展开得到 `01`，所以第 1 个符号是 `0`。

**示例 3**  
``` 
Input: n = 2, k = 2
Output: 1
Explanation: 
row 1: 0
row 2: 01
```  
解释：同上，第 2 行的第 2 个符号为 `1`。

**约束条件**  
- `1 <= n <= 30`  
- `1 <= k <= 2^n - 1`   （注意这里的 `2^n` 表示 2 的 n 次方）

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是**把所有行都真的写出来**，再把第 `k` 位直接取出来。

- **数据结构**：我们可以用 Python 的 `list`（相当于一排排的纸条），每个元素是字符 `'0'` 或 `'1'`。  
  - 类比：把 `list` 想象成一本“字典”，下标就是页码，里面存的是 0/1。
- **生成规则**：从第 1 行开始，只有一个 `0`。  
  对于后面的每一行，遍历上一行的每个字符：
  - 如果是 `0`，在新行里写 `01`
  - 如果是 `1`，在新行里写 `10`
- 这样一直往下生成，直到第 `n` 行。最后直接返回第 `k` 位（因为题目是 1‑index，所以要 `k-1`）。

**为什么正确**  
题目本身就定义了每一行是这样“替换”得到的。我们完全按照定义一步步构造，自然得到的第 `n` 行一定是题目要求的，第 `k` 位也就是我们要的答案。

**时间/空间复杂度**  
- 第 `i` 行的长度是 `2^{i-1}`（因为每个字符都会产生两个字符），第 `n` 行的长度是 `2^{n-1}`。  
- 暴力解需要把所有行都生成一遍，最坏情况下要遍历 **`2^{n-1}`** 个字符。  
  - 时间复杂度记作 **O(2ⁿ)**（这里的 `2ⁿ` 表示“2 的 n 次方”，即指数增长，随 n 增大很快变得不可接受）。  
- 为了存储第 `n` 行，我们需要 **`2^{n-1}`** 的空间，同样是 **O(2ⁿ)**。

> 大白话：如果 n=30，`2^{30}` 大约是 10 亿，显然直接把这么长的序列全部写出来会把电脑的内存和时间都耗光。

#### 代码（Python）

```python
def kthGrammar_bruteforce(n: int, k: int) -> int:
    # 第 1 行只有一个 0
    row = [0]

    # 从第 2 行到第 n 行逐行生成
    for _ in range(2, n + 1):
        nxt = []                         # 用来保存新生成的一行
        for bit in row:                  # 遍历上一行的每个字符
            if bit == 0:
                nxt.extend([0, 1])       # 0 → 01
            else:
                nxt.extend([1, 0])       # 1 → 10
        row = nxt                        # 把新行赋给 row，继续往下

    # 行已经是 0/1 的列表，k 是 1-index，返回第 k-1 位
    return row[k - 1]
```

#### 复杂度

- **时间复杂度**：`O(2ⁿ)` —— 随着行数的增加，字符数量呈指数增长，实际运行会非常慢。  
- **空间复杂度**：`O(2ⁿ)` —— 需要把第 `n` 行完整保存下来，同样占用指数级别的内存。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**把整行都生成出来**，而我们其实只需要第 `k` 位的值。  
观察生成规则可以发现一种**递归/翻转**的关系：

1. 第 `n` 行的长度是 `2^{n-1}`。  
2. 第 `n` 行的左半段（前 `2^{n-2}` 位）其实就是第 `n-1` 行 **原样**。  
3. 第 `n` 行的右半段（后 `2^{n-2}` 位）是第 `n-1` 行 **取反**（0↔1），因为每个字符都被替换成了 “相反顺序的 01/10”。  

因此，如果我们知道第 `n-1` 行第 `k` 位的值，就能推出第 `n` 行第 `k` 位：

- **如果 `k` 位在左半段**（`k <= 2^{n-2}`），答案就是 `(n-1, k)`。  
- **如果 `k` 位在右半段**（`k > 2^{n-2}`），答案就是 **取反** `(n-1, k - 2^{n-2})`。

这就把大问题 **“第 n 行第 k 位”** 转化成了 **更小的子问题**。递归到底会回到第 1 行，那里只有一个 `0`，递归结束。

> 类比：把一棵倒着长的二叉树想象成“左右子树”。左子树直接沿用父节点的值，右子树则把父节点的值翻转。我们只需要沿着从根到目标叶子的路径走，一路上记住是否翻转过。

**另一种更简洁的视角**：每次向右走（进入右半段）就会把当前值翻转一次。于是答案等价于 **“从根到第 k 位的路径上翻转的次数的奇偶性”**。翻转次数奇数 → 1，偶数 → 0。

- 翻转次数其实就是 **`k-1` 的二进制表示中 1 的个数**（即 **汉明重量**）。因为每次向右相当于把 `k-1` 的最高位去掉，剩下的低位决定后面的走向。  
- 最终答案 = `popcount(k-1) % 2`（奇数返回 1，偶数返回 0）。

下面给出两种实现：递归版和位操作版（更快）。

#### 代码（Python）

**递归版（思路直观）**

```python
def kthGrammar_recursion(n: int, k: int) -> int:
    """
    递归实现：
    - base case: 第 1 行第 1 位一定是 0
    - 递归关系: 若 k 在左半段，直接递归 (n-1, k)
                若 k 在右半段，递归后结果取反
    """
    if n == 1:                # 第 1 行，唯一的字符是 0
        return 0

    half = 1 << (n - 2)       # 2^{n-2}，左半段的长度
    if k <= half:             # 在左半段，和上一行同位置
        return kthGrammar_recursion(n - 1, k)
    else:                     # 在右半段，等价于上一行对应位置的取反
        return 1 - kthGrammar_recursion(n - 1, k - half)
```

**位操作版（最简洁）**

```python
def kthGrammar_bit(n: int, k: int) -> int:
    """
    关键在于：第 k 位的值 = (k-1) 二进制中 1 的个数的奇偶性
    - 使用 Python 的 built-in bit_count()（Python3.8+ 可以自行实现计数）
    """
    # popcount(k-1) % 2
    return (k - 1).bit_count() & 1
```

> 解释关键行：
- `half = 1 << (n - 2)`：左移相当于 `2^{n-2}`，快速得到左半段的长度。
- `1 - sub_result`：把 0/1 翻转，等价于 `sub_result ^ 1`（异或 1）。
- `(k - 1).bit_count()`：返回整数二进制表示中 `1` 的个数，Python 3.8+ 自带此方法。

#### 复杂度

- **递归版**  
  - 时间复杂度：`O(n)` —— 每层递归只做常数工作，递归深度最多 `n-1`（≤30），线性可接受。  
  - 空间复杂度：`O(n)` —— 递归调用栈占用的空间，同样是线性级别（最多 30 层，几乎可以忽略）。

- **位操作版**  
  - 时间复杂度：`O(1)` —— 只算一次二进制位数，时间不随 `n` 增长。  
  - 空间复杂度：`O(1)` —— 只用常数个变量。

> 与暴力解对比：我们把指数级的 `2ⁿ` 降到了线性 `n`，甚至常数 `1`，所以运行速度提升了天壤之别。

## 心得

- **核心技巧**：利用**递归/翻转关系**或**二进制奇偶性**把“整行生成”转化为“局部计算”。  
- **适用的题型**  
  1. **格雷码（Gray Code）**：每一步翻转最低位的思路类似。  
  2. **奇偶翻转序列**（如 “奇偶树”/“奇偶排列”）  
  3. **二进制计数相关的递归题**（比如 LeetCode 1545 – Find Kth Bit in Nth Binary String）  
- **一句话总结**：**“把‘第 k 位’的路径抽象出来，翻转次数奇偶决定答案”。**

## 反思

- **第一反应**：直接把表格打印出来，然后取第 k 位。  
- **最容易踩的坑**  
  - **下标混淆**：题目是 1‑index，代码里容易写成 0‑index，需要注意 `k-1` 的转换。  
  - **递归边界**：忘记 `n == 1` 时直接返回 `0`，会导致无限递归。  
  - **位数溢出**：在某些语言里 `2^{n-1}` 可能超过整数范围，但 Python 的整数是大整数，仍需关注。  
- **下次遇到同类题**：第一步先**思考“是否可以只关注目标位置而不是整条序列”，尝试把问题递归化或用二进制属性直接求解。
