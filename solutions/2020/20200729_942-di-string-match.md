# #942. DI 字符串匹配 / DI String Match

> 难度：简单 · 标签：Array、Two Pointers、String、Greedy · [LeetCode 链接](https://leetcode.com/problems/di-string-match/)

---

## 题目（英文原版）

**Description**

A permutation perm of n + 1 integers of all the integers in the range [0, n] can be represented as a string s of length n where:
Given a string s, reconstruct the permutation perm and return it. If there are multiple valid permutations perm, return any of them.

**Examples**

**Example 1:**

```
Input: s = "IDID"
Output: [0,4,1,3,2]
```

**Example 2:**

```
Input: s = "III"
Output: [0,1,2,3]
```

**Example 3:**

```
Input: s = "DDI"
Output: [3,2,0,1]
```

**Constraints**

- 1 <= s.length <= 105
- s[i] is either 'I' or 'D'.

---

## 题目（中文翻译）

给定一个长度为 **n** 的字符串 **s**，它只包含字符 `'I'`（表示递增）和 `'D'`（表示递减）。  
我们希望构造一个包含 **n + 1** 个整数的排列（permutation）`perm`，这些整数恰好是区间 **[0, n]** 中的所有数，使得：

- 如果 `s[i] == 'I'`，则 `perm[i] < perm[i+1]`；
- 如果 `s[i] == 'D'`，则 `perm[i] > perm[i+1]`。

给定字符串 **s**，请重新构造满足上述条件的排列 `perm` 并返回。若存在多个合法的排列，返回任意一个即可。

---

## 示例

### 示例 1
**输入**  
``` 
s = "IDID"
```  
**输出**  
```
[0,4,1,3,2]
```  
**解释**  
`perm[0] < perm[1]`（0 < 4）对应 `'I'`，  
`perm[1] > perm[2]`（4 > 1）对应 `'D'`，  
`perm[2] < perm[3]`（1 < 3）对应 `'I'`，  
`perm[3] > perm[4]`（3 > 2）对应 `'D'`，  
因此该排列满足所有条件。

### 示例 2
**输入**  
``` 
s = "III"
```  
**输出**  
```
[0,1,2,3]
```  
**解释**  
所有相邻元素均满足递增关系，对应字符串中的三个 `'I'`。

### 示例 3
**输入**  
``` 
s = "DDI"
```  
**输出**  
```
[3,2,0,1]
```  
**解释**  
`perm[0] > perm[1]`（3 > 2）对应 `'D'`，  
`perm[1] > perm[2]`（2 > 0）对应 `'D'`，  
`perm[2] < perm[3]`（0 < 1）对应 `'I'`，  
满足整个字符串的要求。

## 约束条件

- `1 <= s.length <= 10^5`
- `s[i]` 只能是 `'I'` 或 `'D'`。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：把 `0 … n`（共 `n+1` 个数）全部列出来，枚举所有可能的排列 `perm`，然后逐个检查它是否满足字符串 `s` 的要求。  
- **数据结构**：我们可以把一个排列存到列表（list）里，列表就像一本“编号手册”，第 `i` 位记录的是第 `i` 个位置上的数字。  
- **为什么正确**：因为题目要求的就是「所有满足条件的排列」中的任意一个，枚举所有排列后只要找到一个符合 `s` 中每个字符的约束（`I` 表示前后递增，`D` 表示前后递减），就一定是合法答案。  

**检查过程**：  
遍历字符串 `s` 的每个字符 `s[i]`，比较 `perm[i]` 与 `perm[i+1]`：  
- 若 `s[i]=='I'`，则要求 `perm[i] < perm[i+1]`；  
- 若 `s[i]=='D'`，则要求 `perm[i] > perm[i+1]`。  
只要所有位置都满足，当前排列就是答案。

#### 代码（Python）

```python
import itertools  # itertools.permutations 可以一次生成所有排列

def di_string_match_bruteforce(s: str):
    n = len(s)                     # s 长度为 n，perm 长度为 n+1
    numbers = list(range(n + 1))   # 0~n 的所有整数

    # 逐个尝试所有排列
    for perm in itertools.permutations(numbers):
        ok = True
        for i, ch in enumerate(s):
            if ch == 'I' and not (perm[i] < perm[i + 1]):   # 要递增却不递增
                ok = False
                break
            if ch == 'D' and not (perm[i] > perm[i + 1]):   # 要递减却不递减
                ok = False
                break
        if ok:                     # 找到第一个合法排列，直接返回
            return list(perm)

    return []  # 理论上不会走到这里，因为一定有解
```

#### 复杂度

- **时间复杂度**：`O((n+1)!)`  
  解释：`(n+1)!` 表示「n+1 的阶乘」，比如 `n=5` 时是 `720`，随着 `n` 增大，增长速度非常快，几乎不可能在 10⁵ 长度的输入下跑完。  
- **空间复杂度**：`O(n)`  
  只需要存放当前遍历的排列（长度 `n+1`）以及一些临时变量。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于「枚举所有排列」——这一步远远超过了题目所需的工作量。实际上，题目只要求我们 **构造** 一个满足条件的排列，而不需要遍历所有可能。我们可以利用以下观察来一步步简化：

1. **范围是连续的**  
   `perm` 必须恰好包含 `0 … n`，没有缺失也没有重复。  
2. **'I' 与 'D' 的含义**  
   - `'I'` 表示当前位置的数要 **小于** 下一位置的数。  
   - `'D'` 表示当前位置的数要 **大于** 下一位置的数。  
3. **贪心思想**  
   - 当看到 `'I'` 时，越小的数放在左边越容易满足 “左 < 右”。  
   - 当看到 `'D'` 时，越大的数放在左边越容易满足 “左 > 右”。  

于是我们可以把「最小」和「最大」两个指针分别指向可用数字的两端：

- `low`   从 `0` 开始，代表当前还能使用的最小数字。  
- `high`  从 `n` 开始，代表当前还能使用的最大数字。  

遍历字符串 `s`：

- 若 `s[i] == 'I'`，把 `low` 放到 `perm[i]`，然后 `low += 1`（用掉最小的数）。  
- 若 `s[i] == 'D'`，把 `high` 放到 `perm[i]`，然后 `high -= 1`（用掉最大的数）。  

遍历结束后，`low` 与 `high` 会相等，剩下的唯一数字正好放在 `perm[n]`（最后一个位置）。

**为什么贪心是对的？**  
- 对于 `'I'`，我们把当前最小的可用数放在左侧，左侧数尽可能小，右侧还有更大的数可供选择，必然不会破坏后面的约束。  
- 对于 `'D'`，我们把当前最大的可用数放在左侧，左侧数尽可能大，右侧还有更小的数可供选择，同理不会破坏后面的约束。  

因为每一步都只使用最极端的数，后面的可选范围只会变得更“宽松”，所以整条序列一定可以完成。

#### 代码（Python）

```python
def di_string_match(s: str):
    """
    贪心构造满足 s 的排列。
    low  ----> 当前还能使用的最小数
    high <---- 当前还能使用的最大数
    """
    n = len(s)                     # perm 长度是 n+1
    low, high = 0, n               # 可用数字区间是 [0, n]
    ans = []                       # 用来保存答案

    for ch in s:
        if ch == 'I':
            ans.append(low)       # 把最小的放进当前位
            low += 1              # 最小数已经用掉，向右移动
        else:  # ch == 'D'
            ans.append(high)      # 把最大的放进当前位
            high -= 1             # 最大数已经用掉，向左移动

    # 循环结束后 low == high，剩下唯一的数字放在最后
    ans.append(low)                # 或者 high，值相同
    return ans
```

#### 复杂度

- **时间复杂度**：`O(n)`  
  只遍历一次字符串 `s`，每一步的操作都是常数时间。相当于「线性」的意思：如果 `s` 长 10 万，就需要大约 10 万次简单操作，完全可以接受。  
- **空间复杂度**：`O(n)`  
  需要存放返回的数组 `ans`（长度 `n+1`），除此之外只用了几个整数变量。

## 心得

- **核心技巧**：**贪心 + 双指针（low/high）**。把「最小」和「最大」两个极端数字交替使用，可以一次遍历完成构造。
- **适用的题型**  
  1. `DI String Match`（本题）  
  2. `Find the Smallest Range I`（需要在区间两端取极值）  
  3. `Maximum Number of Events That Can Be Attended`（按时间先后用最早可用的资源）  
- **一句话总结**：把「I」对应最小可用数，把「D」对应最大可用数，左手抓最小右手抓最大，顺序摆好即是答案。

## 反思

- **第一反应**：看到 `I`/`D`，脑海里会自然想到「升序」和「降序」，于是想到把数字按顺序或逆序排列。但直接把全部数字一次性排好会导致不满足混合的 `I` 与 `D`。
- **最容易踩的坑**  
  - 忘记在遍历结束后还有最后一个位置需要填充（`low == high` 时的那个数）。  
  - 把 `low` 与 `high` 的更新写反了，导致 `I` 时放了最大数，`D` 时放了最小数，答案完全相反。  
- **下次遇到同类题**：第一步先思考「极端值」是否能帮助约束（最小/最大），再考虑用双指针或贪心一次遍历完成构造。
