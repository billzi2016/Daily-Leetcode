# #984. 字符串不含 AAA 或 BBB / String Without AAA or BBB

> 难度：中等 · 标签：String、Greedy · [LeetCode 链接](https://leetcode.com/problems/string-without-aaa-or-bbb/)

---

## 题目（英文原版）

**Description**

Given two integers a and b, return any string s such that:

**Examples**

**Example 1:**

```
Input: a = 1, b = 2
Output: "abb"
Explanation: "abb", "bab" and "bba" are all correct answers.
```

**Example 2:**

```
Input: a = 4, b = 1
Output: "aabaa"
```

**Constraints**

- 0 <= a, b <= 100
- It is guaranteed such an s exists for the given a and b.

---

## 题目（中文翻译）

给定两个整数 `a` 和 `b`，返回任意满足以下条件的字符串 `s`：

- `s` 中恰好包含 `a` 个字符 `'a'` 和 `b` 个字符 `'b'`；
- `s` 不含连续的三个 `'a'`，即不存在子字符串（substring）`"aaa"`；
- `s` 不含连续的三个 `'b'`，即不存在子字符串（substring）`"bbb"`。

**示例 1**  
输入: `a = 1, b = 2`  
输出: `"abb"`  
解释: `"abb"`、`"bab"` 和 `"bba"` 都是正确答案。

**示例 2**  
输入: `a = 4, b = 1`  
输出: `"aabaa"`  

**约束条件**  

- `0 <= a, b <= 100`  
- 对于给定的 `a` 和 `b`，一定存在满足条件的字符串 `s`。

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**把所有可能的字符序列枚举出来**，只要满足下面两个条件就算成功：

1. 只使用 `a` 次字符 `'a'` 和 `b` 次字符 `'b'`（相当于我们有两种“字母卡片”，每张卡片只能用一次）。  
2. 任意三个相邻字符不能全相同（即不能出现 `"aaa"` 或 `"bbb"`），这就像我们在排队时，不能让同一种颜色的球连续出现三个。

实现上可以用**回溯（Depth‑First Search）**：  
- 从空串开始，每一步尝试往后加 `'a'` 或 `'b'`（如果对应的卡片还有剩余）。  
- 加完以后检查最近的三个字符是否全相同，若是则立刻回退（剪枝），因为以后再往后加也不可能把这个错误修正。  
- 当已经用了完所有卡片（`a` 次 `'a'`、`b` 次 `'b'`）时，就得到一个合法答案，直接返回。

> **类比**：把回溯想成“走迷宫”。我们每走一步都记下走过的路（已拼好的字符），如果发现前面三步都是同一种颜色的砖块，就立刻返回上一步重新选路。

**为什么一定能得到答案？**  
题目保证在给定的 `a、b` 范围内必定存在合法字符串。回溯会遍历所有可能的排列，只要有合法的，就一定会被遍历到并返回。

#### 代码（Python）

```python
def string_without_aaa_bbb_bruteforce(a: int, b: int) -> str:
    # 记录当前已经拼好的字符串
    path = []

    # 深度优先搜索的递归函数
    def dfs(rem_a: int, rem_b: int) -> str | None:
        # 1️⃣ 终止条件：所有字符都已经使用完
        if rem_a == 0 and rem_b == 0:
            return ''.join(path)          # 把列表转成字符串返回

        # 2️⃣ 尝试放 'a'
        if rem_a > 0:
            # 把 'a' 加到路径末尾
            path.append('a')
            # 检查最近三个字符是否全相同
            if len(path) < 3 or not (path[-1] == path[-2] == path[-3] == 'a'):
                ans = dfs(rem_a - 1, rem_b)   # 继续往下走
                if ans:                         # 找到合法答案直接返回
                    return ans
            path.pop()                         # 回溯：把刚才加的 'a' 移除

        # 3️⃣ 尝试放 'b'（与上面完全相同的逻辑）
        if rem_b > 0:
            path.append('b')
            if len(path) < 3 or not (path[-1] == path[-2] == path[-3] == 'b'):
                ans = dfs(rem_a, rem_b - 1)
                if ans:
                    return ans
            path.pop()

        # 4️⃣ 所有分支都不合法，返回 None 表示失败
        return None

    # 调用递归入口
    return dfs(a, b)
```

> **关键行解释**  
> - `path.append('a') / path.pop()`：相当于在“排队”时进出一位选手。  
> - `len(path) < 3 or not (path[-1] == path[-2] == path[-3] == 'a')`：检查最近三位是否全是 `'a'`（同理检查 `'b'`），如果是就立刻撤回这一步（剪枝）。

#### 复杂度  

- **时间复杂度**：`O(2^{a+b})`（指数级）  
  - 每一步我们最多有两种选择（放 `'a'` 或 `'b'`），最坏情况下会遍历所有可能的排列，类似二叉树的全部节点数。  
  - 对初学者来说可以把 `2^{a+b}` 想成“每增加一个字符，可能的组合数就翻倍”。  

- **空间复杂度**：`O(a + b)`（递归栈 + `path` 列表）  
  - 递归深度最多等于总字符数 `a+b`，`path` 同样保存了这么多字符。

### 2. 最优解  

#### 思路  

暴力解的**瓶颈**在于它会尝试大量明显不可能的排列（比如连续放三个相同字符后仍继续递归），导致指数级时间。我们需要**在每一步就做出最好的选择**，让搜索空间直接压缩到线性。

观察题目可以得到两条重要规律：

1. **只能出现最多两个相同字符连在一起**。  
   - 因此，如果某个字符的剩余数量远多于另一个字符，我们应该尽可能多放它，但**不能一次放三个**。  
2. **当上一次放了两个相同字符时，下一位必须换成另一种字符**。  
   - 这相当于“当排队中已经出现两位相同颜色的选手时，下一位必须换颜色”。  

基于这两条规律，可以构造**贪心算法**：

- 每一步比较剩余的 `'a'` 与 `'b'` 哪个更多。  
- **若多的那个字符已经连续出现两次**，则必须先放另一个字符（因为再放同样的会违背规则）。  
- **否则**，优先放多的那个字符（这样可以尽快把多余的字符消耗掉，避免后面出现“剩下的都是同一种字符却已经没有空位插入”的尴尬）。  

实现细节：

| 步骤 | 变量 | 含义 |
|------|------|------|
| `cnt_a, cnt_b` | 剩余 `'a'`、`'b'` 的数量 |
| `result` | 最终拼好的字符串（使用列表累加，最后 `join`） |
| `last_two` | `result[-2:]`，记录最近两位字符，用来判断是否已经出现连续两个相同字符 |

每次循环：

1. 判断 `cnt_a >= cnt_b`（`a` 是否不少于 `b`）。  
2. 若 `result` 最后两位都是 `'a'`，则必须放 `'b'`（前提是 `cnt_b > 0`），否则放 `'a'`。  
3. 同理处理 `'b'` 为多数的情况。  

因为每次循环都会往 `result` 加一个字符，循环次数正好是 `a+b`，所以时间是 **线性** 的。

> **类比**：把它想成“调配饮料”。我们有 `a` 杯红茶、`b` 杯绿茶，要求连续三杯不能是同一种。每次先看哪种饮料多，如果刚才已经喝了两杯同一种，就换另一种；否则继续喝多的那种，这样既能快速把多余的饮料喝完，又不会违规则。

#### 代码（Python）

```python
def string_without_aaa_bbb(a: int, b: int) -> str:
    # 结果使用列表累加，效率比直接字符串相加高
    result = []

    # 记录剩余的数量
    cnt_a, cnt_b = a, b

    while cnt_a > 0 or cnt_b > 0:
        # 最近两位字符（若不足两位则返回空字符串）
        last_two = ''.join(result[-2:])

        # ---------- a 多或相等 ----------
        if cnt_a >= cnt_b:
            # 如果已经出现 "aa"，这次必须放 b（前提是还有 b）
            if last_two == 'aa' and cnt_b > 0:
                result.append('b')
                cnt_b -= 1
            else:
                # 否则安全放 a
                result.append('a')
                cnt_a -= 1
        # ---------- b 多 ----------
        else:
            # 如果已经出现 "bb"，这次必须放 a（前提是还有 a）
            if last_two == 'bb' and cnt_a > 0:
                result.append('a')
                cnt_a -= 1
            else:
                # 否则安全放 b
                result.append('b')
                cnt_b -= 1

    # 把列表转成字符串返回
    return ''.join(result)
```

> **关键行解释**  
> - `last_two = ''.join(result[-2:])`：把最近两位字符拼成短串，便于“一眼看出是否已经出现两个相同”。  
> - `if cnt_a >= cnt_b:`：决定本轮的“首选字符”。  
> - `if last_two == 'aa' and cnt_b > 0:`：如果已经连续两个 `'a'`，必须换 `'b'`，否则继续放 `'a'`。  
> - `result.append('a') / cnt_a -= 1`：把选好的字符放进结果，同时把对应的剩余计数减一。

#### 复杂度  

- **时间复杂度**：`O(a + b)`（线性）  
  - 循环恰好执行 `a+b` 次，每次只做常数时间的判断和拼接。相比暴力的指数级，这就像“走直路”一样快。  

- **空间复杂度**：`O(a + b)`（结果字符串本身）  
  - 额外使用的辅助空间只有几个整数和一个结果列表，大小与输出长度相同，属于必需的空间。

## 心得  

- **核心技巧**：**贪心 + 连续计数**  
  - 通过比较剩余字符的多少，始终优先使用多的那个；同时利用“最近两位相同就换另一种”这条规则防止出现三连。  

- **适用的题型**（类似思路）  
  1. **"String Without AAA or BBB"**（本题）  
  2. **"Longest Happy String"**（LeetCode 1405），需要构造不出现三个相同字符的最长字符串，思路几乎相同，只是要尽可能多放字符。  
  3. **"Rearrange String k Distance Apart"**（LeetCode 358），要求相同字符之间至少间隔 `k`，也是利用计数和“最近出现”信息进行贪心安排。  

- **一句话总结解题钥匙**：  
  > **“多的先放，若已经连着两个相同就强制换另一种”**。

## 反思  

- **第一反应**：直接想遍历所有排列，用递归暴力检查。虽然能得到答案，但很快会发现对 `a、b` 为 100 时根本跑不完。  
- **最容易踩的坑**  
  1. **忘记判断“最近两位是否相同”**：只检查当前要放的字符是否会导致三个相同，容易遗漏已经出现的两连。  
  2. **边界条件**：当一种字符已经用完，而另一种还剩很多时，需要确保不会因为前面两个相同而卡死（本题保证存在解，但实现时仍要检查 `cnt_other > 0`）。  
  3. **字符串拼接的性能**：在 Python 中频繁使用 `+` 会导致 `O(n^2)` 的时间，使用列表 `append` 再 `''.join` 能保持线性。  

- **下次遇到同类题的第一步**：  
  > **“先比较剩余数量，决定‘先放哪个’，再检查最近两位是否已经形成禁区，若是就换另一种”。** 这一步把搜索空间直接压到 `O(n)`，不再需要穷举。
