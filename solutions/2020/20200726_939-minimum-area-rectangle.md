# #939. 最小面积矩形 / Minimum Area Rectangle

> 难度：中等 · 标签：Array、Hash Table、Math、Geometry、Sorting · [LeetCode 链接](https://leetcode.com/problems/minimum-area-rectangle/)

---

## 题目（英文原版）

**Description**

You are given an array of points in the X-Y plane points where points[i] = [xi, yi].
Return the minimum area of a rectangle formed from these points, with sides parallel to the X and Y axes. If there is not any such rectangle, return 0.

**Examples**

**Example 1:**

```
Input: points = [[1,1],[1,3],[3,1],[3,3],[2,2]]
Output: 4
```

**Example 2:**

```
Input: points = [[1,1],[1,3],[3,1],[3,3],[4,1],[4,3]]
Output: 2
```

**Constraints**

- 1 <= points.length <= 500
- points[i].length == 2
- 0 <= xi, yi <= 4 * 104
- All the given points are unique.

- `1 <= points.length <= 500`

- `0 <= xi, yi <= 4 * 10^4`  
- 所有给定的点互不相同。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直观的想法是：**把所有点两两配对，看看它们能不能组成一个矩形的四个顶点**。  
- 如果我们随意挑选 4 个点，检查这 4 条边是否分别平行于 X 轴或 Y 轴，就能判断它们是否是一个“轴对齐矩形”。  
- 为了快速判断某个坐标点是否真的在输入里出现过，我们可以把所有点放进**哈希表**（在 Python 中用 `set` 实现）。哈希表就像一本“查字典”：给出一个`key`（这里是坐标），立刻返回是否存在（对应的`value`可以想象成页码），查找时间是 **O(1)**。  

**为什么暴力方法一定能得到答案？**  
因为题目要求的矩形必须由**输入中的点**组成，遍历所有可能的四点组合自然不会漏掉任何合法矩形。只要我们能正确判断四点是否构成矩形，并计算面积，最小的那个就是答案。

**复杂度的直观解释**  
- 我们需要从 `n` 个点里挑出 4 个，组合数是 `C(n,4) = n·(n‑1)·(n‑2)·(n‑3)/24`，这在数量级上相当于 **O(n⁴)**。  
- 对每一组四点，只做常数次的比较和哈希查询，时间几乎不再增长。  
- 空间上，只需要保存原始点集合，大小正好是 `n`，即 **O(n)**。

> **大白话**：如果有 100 个点，暴力解要检查大约 3.9 亿次组合，显然太慢了；而 `O(n⁴)` 的增长速度是“每增加一点点点，检查次数会疯涨”。

#### 代码（Python）

```python
from typing import List
import itertools

def minAreaRect_bruteforce(points: List[List[int]]) -> int:
    # 把所有点放进哈希集合，方便 O(1) 判断点是否存在
    point_set = { (x, y) for x, y in points }

    min_area = float('inf')                     # 记录当前最小面积
    # itertools.combinations 能一次枚举出所有 4 点组合
    for p1, p2, p3, p4 in itertools.combinations(points, 4):
        xs = {p1[0], p2[0], p3[0], p4[0]}
        ys = {p1[1], p2[1], p3[1], p4[1]}
        # 轴对齐矩形的四个顶点一定恰好有 2 个不同的 x 坐标和 2 个不同的 y 坐标
        if len(xs) == 2 and len(ys) == 2:
            # 计算面积：宽 * 高
            width = max(xs) - min(xs)
            height = max(ys) - min(ys)
            area = width * height
            # 只要四个坐标都在点集合里，就是真正的矩形
            if (min(xs), min(ys)) in point_set and \
               (min(xs), max(ys)) in point_set and \
               (max(xs), min(ys)) in point_set and \
               (max(xs), max(ys)) in point_set:
                min_area = min(min_area, area)

    return 0 if min_area == float('inf') else min_area
```

> **代码要点注释**  
> - 第 3 行使用集合推导式把点转成 `(x, y)` 元组，便于后面快速查询。  
> - `itertools.combinations(points, 4)` 自动生成所有不重复的四点组合。  
> - 通过判断 `len(xs) == 2 and len(ys) == 2` 快速过滤掉不可能是矩形的组合。  

#### 复杂度  

- **时间复杂度：** `O(n⁴)`  
  - 解释：从 `n` 个点里挑 4 个，需要检查约 `n⁴/24` 种组合。每种组合的检查是常数时间。  
- **空间复杂度：** `O(n)`  
  - 解释：只额外用了一个存放所有点的哈希集合，大小随输入点数线性增长。

### 2. 最优解

#### 思路  

暴力解的**瓶颈**在于“枚举四点”。我们其实不需要一次把四个点都挑出来，只要先找到 **两条平行于 Y 轴的边**（即两点拥有相同的 X 坐标），再看它们的 Y 坐标配对是否在更左/更右的另一条垂直边出现过，就可以立即得到一个矩形。

**关键观察**  
1. 轴对齐矩形的四条边必然成两对平行的垂直线。  
2. 对于同一条垂直线（相同的 `x`），只要出现两点 `(x, y1)` 与 `(x, y2)`，它们之间的 **“纵向间距”**（`y2 - y1`）就是矩形的高。  
3. 当我们在更右侧的另一条垂直线上再次看到同样的两条 `y`（即同样的 `(y1, y2)`），这两条线就共同构成了一个矩形，面积 = `宽 * 高`，宽 = `当前 x - 之前记录的 x`。

**实现技巧**  
- 用 **哈希集合** 存所有点，便于 O(1) 判断任意点是否存在（用于最初的 O(n²) 方案）。  
- 用 **字典** `pair_to_x` 记录每一对 `y` 值（有序元组 `(y1, y2)`）上一次出现的 `x` 坐标。  
  - 这相当于“把每一对纵向间距对应的左边界记下来”。  
- 按 `x` 递增的顺序遍历所有点（先把点按照 `x` 分组），这样当我们再次遇到相同的 `y` 对时，**当前 `x` 必然在右侧**，宽度自然是 `当前 x - 之前的 x`。

**为什么这比暴力快**  
- 我们只枚举 **两点的组合**（而不是四点），组合数是 `C(n,2) = O(n²)`，大幅降低了枚举次数。  
- 每次检查只需要一次字典查询，时间几乎是常数。  
- 整体时间从 `O(n⁴)` 降到了 `O(n²)`，在 `n ≤ 500` 时非常轻松通过。

**类比**：想象每条垂直线是一根柱子，柱子上挂着若干“横条”（不同的 `y`）。当两根柱子上挂的横条完全一样时，它们就能围成一个矩形——我们只需要记住每根柱子第一次出现的横条组合，后面再出现时立刻算出面积。

#### 代码（Python）

```python
from typing import List
from collections import defaultdict

def minAreaRect(points: List[List[int]]) -> int:
    # 1. 把所有点按照 x 坐标分组，方便一次遍历同一条垂直线上的点
    x_to_ys = defaultdict(list)          # x -> 所有在该 x 上的 y 列表
    for x, y in points:
        x_to_ys[x].append(y)

    # 2. 对所有 x 按从小到大遍历（保证左边的 x 先出现）
    sorted_x = sorted(x_to_ys.keys())

    # 记录每一对 y (y1, y2) 上一次出现的 x 坐标
    pair_to_x = dict()                    # (y1, y2) -> x
    min_area = float('inf')

    for x in sorted_x:
        ys = sorted(x_to_ys[x])           # 同一条垂直线上的 y 需要排好序，方便产生有序的 (y1, y2)
        # 3. 枚举该列上所有两点组合，即所有可能的“纵向间距”
        for i in range(len(ys)):
            for j in range(i + 1, len(ys)):
                y1, y2 = ys[i], ys[j]    # y1 < y2，保证 (y1, y2) 唯一
                pair = (y1, y2)

                if pair in pair_to_x:    # 之前已经出现过同样的 y 对，说明形成矩形
                    width = x - pair_to_x[pair]   # 当前 x - 左侧 x
                    height = y2 - y1
                    area = width * height
                    min_area = min(min_area, area)

                # 无论是否已出现，都要把当前 x 记录为最新的左边界
                # 这样后面更右的 x 再次出现相同的 y 对时，宽度会更大（仍然正确）
                pair_to_x[pair] = x

    return 0 if min_area == float('inf') else min_area
```

> **代码要点注释**  
> - 第 5‑7 行用 `defaultdict(list)` 把点按照 `x` 分组，类似把点放进不同的“抽屉”。  
> - 第 12 行对 `x` 进行排序，确保左边的柱子先处理。  
> - 第 17‑21 行在同一列上产生所有 `y` 对，`i < j` 保证顺序不重复。  
> - 第 24‑30 行判断该 `y` 对是否已经出现过；若出现，立刻算出宽（当前 x 与上一次记录的左 x 的差）和高（`y2 - y1`），更新最小面积。  
> - 第 33 行把当前 `x` 写回 `pair_to_x`，相当于更新“这对 y 最近一次出现的位置”。  

#### 复杂度  

- **时间复杂度：** `O(n²)`  
  - 解释：外层遍历所有不同的 `x`（最多 `n`），内层在每条垂直线上枚举所有 `y` 对，所有 `y` 对的总数不超过 `C(n,2)`，即约 `n²/2`，每次操作都是 O(1) 哈希查询。  
  - 与暴力的 `O(n⁴)` 相比，枚举次数从“挑四点”降到了“挑两点”。  
- **空间复杂度：** `O(n²)`（最坏情况）  
  - 解释：`pair_to_x` 最多会存储所有不同的 `y` 对。若每条垂直线上都有 `≈√n` 个点，`y` 对的数量仍然是 `O(n²)`。  
  - 实际上，`n ≤ 500` 时，这个空间完全可以接受。

## 心得

- **核心技巧**：把“矩形的两条垂直边”看成 **“相同的 y 对出现两次”**，利用哈希表记录每对 `y` 最近出现的 `x`，实现从 O(n⁴) → O(n²) 的跨越。  
- **适用的题型**  
  1. **最小/最大面积矩形**（如本题）。  
  2. **寻找四点形成正方形/菱形**（思路类似，只是判定条件不同）。  
  3. **找出同一条直线上出现相同点对的其他几何问题**（如“最小周长矩形”）。  
- **一句话总结解题钥匙**：  
  > “把矩形的两条垂直边抽象为‘同一对 y 值’，只要这对 y 在两条不同的 x 上出现，就必定构成矩形。”

## 反思

- **第一反应**：直接把所有点四两两配对，检查是否能组成矩形——这就是暴力思路。  
- **最容易踩的坑**  
  1. **点的唯一性**：若忘记使用集合去判断点是否存在，可能会误判不存在的点为矩形顶点。  
  2. **y 对的顺序**：必须把 `(y1, y2)` 按升序存储，否则 `(2,5)` 与 `(5,2)` 会被当成不同的键，导致漏掉矩形。  
  3. **宽度为 0 的情况**：同一条垂直线上出现两次相同的 y 对时，`width = 0`，不算矩形，需要排除。  
- **下次遇到同类题**，第一步应该想到：  
  > “先把点按某个坐标分组（如按 x），再在同组内部枚举点对，用哈希记录‘出现过的组合’，只要同一组合再次出现，就可以直接算出面积/周长”。  

这样既能快速定位潜在矩形，又能把时间复杂度控制在可接受的范围。祝你玩得开心，算法路上越走越顺 🚀
