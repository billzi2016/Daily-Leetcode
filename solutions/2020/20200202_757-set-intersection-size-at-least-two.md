# #757. 集合交集大小至少为二 / Set Intersection Size At Least Two

## 题目（英文原版）

**Description**

You are given a 2D integer array intervals where intervals[i] = [starti, endi] represents all the integers from starti to endi inclusively.
A containing set is an array nums where each interval from intervals has at least two integers in nums.
Return the minimum possible size of a containing set.

**Examples**

**Example 1:**

```
Input: intervals = [[1,3],[3,7],[8,9]]
Output: 5
Explanation: let nums = [2, 3, 4, 8, 9].
It can be shown that there cannot be any containing array of size 4.
```

**Example 2:**

```
Input: intervals = [[1,3],[1,4],[2,5],[3,5]]
Output: 3
Explanation: let nums = [2, 3, 4].
It can be shown that there cannot be any containing array of size 2.
```

**Example 3:**

```
Input: intervals = [[1,2],[2,3],[2,4],[4,5]]
Output: 5
Explanation: let nums = [1, 2, 3, 4, 5].
It can be shown that there cannot be any containing array of size 4.
```

**Constraints**

- 1 <= intervals.length <= 3000
- intervals[i].length == 2
- 0 <= starti < endi <= 108

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**把所有区间逐个检查**，只要发现某个区间里已经没有足够（≥2）个已经挑好的数，就从该区间里随便挑几个补齐。  
可以把「已经挑好的数」想象成**一个装满数字的抽屉**（集合 `nums`），每次遇到一个新区间，就去抽屉里找有没有数字落在这个区间内。如果不够，就**往抽屉里再塞进去**几个在该区间范围内的数。

> **数据结构类比**  
> - `set`（或 `list`）就像一本**字典**，里面记录了「已经选了哪些数字」。  
> - `in` 判断相当于在字典里查某个词是否存在，时间代价和查字典差不多。

**为什么能得到正确答案**  
只要每个区间最终都拥有不少于两个数字，集合 `nums` 就满足题目要求。因为我们在每个区间都**强制补足**，所以一定合法。只不过这种「随便挑」的策略往往会把不必要的数字也加进去，导致集合不是最小的。

**时间/空间复杂度**  
- 对每个区间，我们可能要遍历整个区间的所有整数去寻找「还没有选过」的数字。区间长度最多是 `10^8`，所以最坏情况是 **`O(N * L)`**（`N` 为区间个数，`L` 为区间长度），这在实际数据里会非常慢。  
- 需要保存所有已经选的数字，最坏会是 `O(answer)`，即答案的大小。  

> **大白话解释**  
> - `O(N * L)` 就像「有 `N` 个小朋友，每个小朋友都要在一条很长的走廊里找两块糖」——走廊太长，找来找去会花很多时间。  
> - `O(answer)` 的空间相当于「你得把所有找来的糖都装进背包」——背包大小正好是最终答案的大小。

#### 代码（Python）

```python
from typing import List

def min_set_size_bruteforce(intervals: List[List[int]]) -> int:
    # 用 set 存已经挑好的数字，查找/插入都很快
    chosen = set()

    for start, end in intervals:
        # 统计当前区间里已经有多少个数字在 chosen 中
        cnt = sum(1 for x in chosen if start <= x <= end)

        # 只要不足 2 个，就从左到右依次往区间里加数字
        # （这里的实现非常慢，只是演示思路）
        cur = start
        while cnt < 2 and cur <= end:
            if cur not in chosen:          # 只加没有出现过的数字
                chosen.add(cur)
                cnt += 1
            cur += 1

    return len(chosen)
```

> **关键行中文注释**  
> - `chosen = set()`  # 用集合保存已经选的数字，类似「抽屉」  
> - `cnt = sum(1 for x in chosen if start <= x <= end)`  # 统计区间内已有数字的个数  
> - `while cnt < 2 and cur <= end:`  # 仍然缺少数字时，顺序尝试加入  

#### 复杂度

- **时间复杂度**：`O(N * L)`，其中 `L` 是区间的最大长度（最坏可达 `10^8`）。实际会超时。  
- **空间复杂度**：`O(answer)`，即最终集合的大小。

### 2. 最优解

#### 思路  

暴力解的瓶颈在 **「每次都要遍历整个区间寻找可用数字」**。  
我们需要一种**一次遍历**就能判断每个区间是否已经满足「至少两个数字」的办法。  

关键观察：

1. **只关心每个区间的右端点**  
   - 若我们把数字选得尽量靠右（靠近区间的 `end`），那么后面的区间更容易复用这些数字。  
   - 想象把每个区间画在数轴上，右端点越大，后面的区间越可能与之重叠。

2. **贪心原则**  
   - 对所有区间**按右端点升序**（`end` 小的先处理），如果 `end` 相同，则把左端点大的（区间更窄的）排在前面。  
   - 这样处理时，**已经挑好的最大两个数字**（记作 `x1` > `x2`）永远是当前已选集合中最大的两个。  

3. **如何决定要加入多少数字**  
   对当前区间 `[l, r]`，检查 `x1`、`x2` 是否在区间内：
   - **两者都在** → 已经满足条件，什么也不加。  
   - **仅有 `x1` 在** → 只缺一个，**把 `r`（区间最右边的数）加入集合**，因为它离右端点最近，后面的区间最可能再次使用它。  
   - **两者都不在** → 缺两个，**先加入 `r-1`，再加入 `r`**（保证这两个数都尽可能靠右）。  

   这就是**标准的贪心**：每一步都选“**对后面影响最小、对当前需求满足最大**”的数字。

4. **为什么排序要这样**  
   - 如果两个区间右端点相同，左端点大的区间更窄，应该先处理，否则宽的区间可能抢走右端点的数字，使窄的区间后面不得不再额外添加，导致答案变大。  

> **类比**  
> 把每个区间看成“一块土地”，我们要在土地上种树，要求每块土地至少有两棵树。我们先在**最靠右的土地**种树，种得越靠右，后面的土地越容易“共享”这些树。若两块土地的右边界一样，先在**更小的那块土地**种树，防止“大块土地”抢走小块土地必须的树。

#### 代码（Python）

```python
from typing import List

def min_set_size(intervals: List[List[int]]) -> int:
    # 1. 按右端点升序排序，右端点相同则左端点降序
    intervals.sort(key=lambda x: (x[1], -x[0]))
    # 记录当前已经挑好的最大两个数字，初始设为 -inf（不存在的值）
    x1, x2 = -1, -1          # x1 > x2 始终成立
    ans = 0                  # 选中的数字个数

    for l, r in intervals:
        # 判断这两个数字是否已经落在当前区间
        in1 = l <= x1 <= r
        in2 = l <= x2 <= r

        if in1 and in2:
            # 已经有两个，直接跳过
            continue
        elif in1:
            # 只有 x1 在，缺一个 → 直接选右端点 r
            ans += 1
            x2 = x1          # 之前的最大变成第二大
            x1 = r           # 新加入的最大
        else:
            # 两个都不在，缺两个 → 选 r-1 和 r（保证 r-1 >= l）
            ans += 2
            x2 = r - 1
            x1 = r
    return ans
```

> **关键行中文注释**  
> - `intervals.sort(key=lambda x: (x[1], -x[0]))`  # 按右端点升序、左端点降序排序  
> - `x1, x2 = -1, -1`  # 记录当前集合中最大的两个数字（初始为不存在）  
> - `in1 = l <= x1 <= r`  # 判断最大的数字是否落在当前区间  
> - `ans += 2`  # 需要额外加入两个数字  

#### 复杂度

- **时间复杂度**：`O(N log N)`，主要是排序的开销。遍历一次区间的过程是 `O(N)`。  
  - 与暴力的 `O(N * L)` 相比，**从遍历整个区间长度降到了只遍历区间个数**，即使 `N=3000` 也能轻松跑完。  
- **空间复杂度**：`O(1)`（不计输出集合本身），只用了常数个变量 `x1, x2, ans`。  
  - 如果需要把实际的数字集合保存下来，只需额外 `O(answer)` 的空间。

## 心得

- **核心技巧**：**贪心 + 按右端点排序**，始终把数字挑到区间最右侧，以便后面的区间可以复用。  
- **适用的题型**  
  1. “区间覆盖”类问题，如 *“最少点覆盖所有区间”*（每个区间至少一个点）。  
  2. “每个区间至少 k 个点” 的扩展（本题是 k=2）。  
  3. “区间调度”类的最大不相交子集（使用右端点排序的思想相同）。  
- **一句话总结解题钥匙**：**把数字挑得尽可能靠右，并用右端点的升序保证每一步的选择对后面“伤害最小”。**

## 反思

- **第一反应**：直接把每个区间里缺的数字逐个补齐，甚至尝试遍历区间的每个整数。  
- **最容易踩的坑**  
  - **排序方式**：如果只按右端点升序而不在右端点相同的情况下把左端点大的排前面，会导致答案不最小。  
  - **边界条件**：当区间长度恰好为 1（如 `[5,5]`）时，题目保证 `start < end`，所以不会出现只能放一个数字的情况，但实现时仍需确保 `r-1` 不小于 `l`（在本题中 `r-1 >= l` 永远成立）。  
  - **维护的两个最大数字**：必须保证 `x1 > x2`，否则判断是否在区间内会出错。  
- **下次遇到类似题**：第一步就**把所有区间按右端点排序**，然后**思考如何让已经选的点尽量靠右**，这样后面的区间复用的机会最大，贪心策略自然浮现。
