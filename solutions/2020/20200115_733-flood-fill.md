## 题目（英文原版）

**Description**

You are given an image represented by an m x n grid of integers image, where image[i][j] represents the pixel value of the image. You are also given three integers sr, sc, and color. Your task is to perform a flood fill on the image starting from the pixel image[sr][sc].
To perform a flood fill:
Return the modified image after performing the flood fill.

**Examples**

**Example 1:**

```
Input: image = [[1,1,1],[1,1,0],[1,0,1]], sr = 1, sc = 1, color = 2
Output: [[2,2,2],[2,2,0],[2,0,1]]
Explanation:

From the center of the image with position (sr, sc) = (1, 1) (i.e., the red pixel), all pixels connected by a path of the same color as the starting pixel (i.e., the blue pixels) are colored with the new color.
Note the bottom corner is not colored 2, because it is not horizontally or vertically connected to the starting pixel.
```

**Example 2:**

```
Input: image = [[0,0,0],[0,0,0]], sr = 0, sc = 0, color = 0
Output: [[0,0,0],[0,0,0]]
Explanation:
The starting pixel is already colored with 0, which is the same as the target color. Therefore, no changes are made to the image.
```

**Constraints**

- m == image.length
- n == image[i].length
- 1 <= m, n <= 50
- 0 <= image[i][j], color < 216
- 0 <= sr < m
- 0 <= sc < n

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是 **“把整张图像遍历一遍，每次看到和起始像素颜色相同的就改成新颜色”**。  
可以把图像想象成一张棋盘，`image[i][j]` 就是格子里的数字。我们把整个棋盘从左上到右下逐行逐列扫一遍，遇到颜色相同的格子就把它改成目标颜色。  

> **为什么这样能得到正确答案？**  
> 因为题目要求把所有 **与起始像素颜色相同且能通过上下左右相连的路径** 的像素全部染色。遍历整张图时，只要格子的颜色和起始像素相同，就一定是要染色的（即使它不在连通块里，我们后面会再检查一次连通性），所以最终所有应该染成的新颜色都会被改到。

> **数据结构**  
> - **二维列表**（list of list）就是我们平时说的“矩阵”，用来存放像素值。  
> - **队列/栈** 在这里不需要，用最原始的 **两层 for 循环** 就能把每个格子都访问到。  

> **时间/空间复杂度**  
> - **时间复杂度** `O(m * n * k)`（这里的 `k` 表示每次检查连通性时可能再遍历一次整个图），可以粗略理解为 **“每个格子都要检查很多遍”**，在最坏情况下会接近 `O(m²·n²)`，显得很慢。  
> - **空间复杂度** `O(1)`，因为只用了常数级别的额外变量（不计输入本身）。

#### 代码（Python）

```python
def floodFill_bruteforce(image, sr, sc, newColor):
    """
    暴力解法：遍历整张图像，每次看到颜色相同的格子就改颜色。
    这是一种最直观、最慢的做法，仅用于演示思路。
    """
    m, n = len(image), len(image[0])
    oldColor = image[sr][sc]                     # 起始像素的原始颜色
    if oldColor == newColor:                     # 已经是目标颜色，直接返回
        return image

    # 辅助函数：判断 (x, y) 是否在图像范围内
    def in_bounds(x, y):
        return 0 <= x < m and 0 <= y < n

    # 暴力遍历每一个格子
    for i in range(m):
        for j in range(n):
            # 如果格子颜色和起始像素相同，则尝试把它改成新颜色
            if image[i][j] == oldColor:
                # 为了保证只改动连通块，需要检查是否和起始像素“相连”
                # 这里使用最简单的 BFS 再次遍历一次，判断连通性（极其低效）
                visited = set()
                queue = [(sr, sc)]
                connected = False
                while queue:
                    x, y = queue.pop(0)        # 取出队首元素（FIFO）
                    if (x, y) in visited:
                        continue
                    visited.add((x, y))
                    if (x, y) == (i, j):
                        connected = True      # 找到目标格子，说明连通
                        break
                    # 向四个方向扩散
                    for dx, dy in [(1,0), (-1,0), (0,1), (0,-1)]:
                        nx, ny = x + dx, y + dy
                        if in_bounds(nx, ny) and image[nx][ny] == oldColor:
                            queue.append((nx, ny))
                if connected:                    # 只有连通时才染色
                    image[i][j] = newColor

    return image
```

> **代码要点**  
> - 第 6 行保存起始像素的原始颜色。  
> - 第 12 行的 `in_bounds` 用来判断坐标是否越界，类似“检查是否走出棋盘”。  
> - 第 18‑36 行是 **“再跑一次 BFS 检查连通性”**，这一步让算法变得非常慢。  

#### 复杂度

- **时间复杂度**：`O(m * n * (m * n))` ≈ `O(m²·n²)`。  
  *解释*：外层遍历每个格子 `m·n` 次，内层的 BFS 最坏也要遍历整张图 `m·n` 次，所以乘起来就是平方级别。  
- **空间复杂度**：`O(m * n)`（用于 BFS 的 `visited` 集合和队列），在最坏情况下需要把整张图的坐标都装进去。

### 2. 最优解

#### 思路  

从暴力解可以看出，**瓶颈在于对每个格子都重复遍历整个图**。实际上，只要我们 **一次性把所有与起始像素相连且颜色相同的格子全部涂色**，就不必再去检查其它格子了。  

这正好对应 **图的遍历**——把图像看成由格子组成的网格，每个格子是一个节点，四个方向的相邻格子是它的邻居。我们只需要 **从起始节点出发，沿着颜色相同的边走遍所有能到达的节点**，这正是 **深度优先搜索（DFS）** 或 **广度优先搜索（BFS）** 的典型场景。

- **慢在哪里**：暴力解里每次都要重新做一次 BFS 来判断连通性，导致重复工作。  
- **优化思路**：只做 **一次**遍历（DFS 或 BFS），把所有满足条件的格子一次性改颜色。  
- **核心算法**：  
  - **DFS（递归版）**：像“探险家”一样，先把当前格子染色，然后递归向上、下、左、右四个方向继续探险。  
  - **BFS（迭代版）**：使用队列一次性把所有待处理的格子放进去，逐层“波纹式”扩散，避免递归深度过大。  

下面分别用 **递归 DFS**（代码更简洁）和 **迭代 BFS**（防止递归栈溢出）实现，二者时间复杂度相同，空间复杂度略有区别。

> **类比**：想象你手里有一支画笔，起始像素是一个已经染好颜色的点。你把画笔放在这个点上，然后沿着相同颜色的相邻格子“滴墨”，所有被滴到的格子都会被新颜色覆盖。DFS 就像你手里不停地“往前走”，每走到一个新格子就继续往前；BFS 则像水波纹，一圈一圈向外扩散。

#### 代码（Python）

##### 2.1 递归版 DFS（最常见）

```python
def floodFill(image, sr, sc, newColor):
    """
    DFS（递归）实现的 Flood Fill。
    思路：从 (sr, sc) 开始，如果当前像素颜色等于 oldColor，
          就把它改成 newColor，然后递归处理四个方向。
    """
    m, n = len(image), len(image[0])
    oldColor = image[sr][sc]          # 起始像素的原始颜色
    if oldColor == newColor:          # 起始像素已经是目标颜色，直接返回
        return image

    # 辅助函数：判断坐标是否在图像内部
    def in_bounds(x, y):
        return 0 <= x < m and 0 <= y < n

    # 深度优先搜索的递归函数
    def dfs(x, y):
        # 如果越界或颜色不相同，直接返回
        if not in_bounds(x, y) or image[x][y] != oldColor:
            return
        # 把当前格子染成新颜色
        image[x][y] = newColor
        # 向四个方向继续扩散
        dfs(x + 1, y)   # 下
        dfs(x - 1, y)   # 上
        dfs(x, y + 1)   # 右
        dfs(x, y - 1)   # 左

    dfs(sr, sc)       # 从起始像素开始搜索
    return image
```

##### 2.2 迭代版 BFS（防止递归深度过大）

```python
from collections import deque

def floodFill_bfs(image, sr, sc, newColor):
    """
    BFS（队列）实现的 Flood Fill。
    思路：使用队列把所有待处理的像素放进去，逐个弹出并染色，
          再把符合条件的相邻像素加入队列。
    """
    m, n = len(image), len(image[0])
    oldColor = image[sr][sc]
    if oldColor == newColor:
        return image

    def in_bounds(x, y):
        return 0 <= x < m and 0 <= y < n

    q = deque()
    q.append((sr, sc))

    while q:
        x, y = q.popleft()
        if not in_bounds(x, y) or image[x][y] != oldColor:
            continue
        image[x][y] = newColor                     # 染色
        # 把四个方向的相邻格子加入队列
        for dx, dy in [(1,0), (-1,0), (0,1), (0,-1)]:
            nx, ny = x + dx, y + dy
            if in_bounds(nx, ny) and image[nx][ny] == oldColor:
                q.append((nx, ny))

    return image
```

> **代码要点**  
> - 第 5‑6 行先保存起始颜色并做 **“颜色相同则直接返回”** 的提前结束，避免不必要的遍历。  
> - `in_bounds` 用来防止访问越界（走出棋盘）。  
> - **DFS** 通过递归实现，代码简洁，但在极端情况下（比如 50×50 全部相同颜色）递归深度可能达到 2500，仍在 Python 默认递归深度（约 1000）之下，实际可行。  
> - **BFS** 用 `deque` 实现队列，避免递归，适用于更大的矩阵或递归深度受限的语言。

#### 复杂度

- **时间复杂度**：`O(m * n)`。  
  *解释*：每个格子最多被访问一次并染色，一旦染色后就不再进入递归或队列，所以总操作次数与格子数量成正比。  
- **空间复杂度**：  
  - **DFS 递归版**：`O(m * n)`（递归栈最坏会存放所有格子，等价于遍历顺序的深度）。  
  - **BFS 迭代版**：`O(m * n)`（队列最坏会同时保存整块连通区域的格子）。  
  与暴力解相比，空间仍是线性的，但只需要一次遍历的临时存储，实际使用更高效。

## 心得

- **核心技巧**：把二维数组看成图，用 **DFS/BFS** 对连通块进行遍历和染色。  
- **适用的题型**：  
  1. **岛屿计数**（Number of Islands）——统计由 `1` 组成的连通块数量。  
  2. **闭岛**（Closed Island）——判断被 `0` 包围的 `1` 区域。  
  3. **矩阵区域求和**（Region Sum）——对满足条件的连通区域进行求和或修改。  
- **一句话总结解题钥匙**：**“一次遍历所有相同颜色的相邻格子，用 DFS/BFS 把它们一次性改掉”。**

## 反思

- **第一反应**：看到“连通”“相同颜色”，立刻想到 **图的遍历**（DFS/BFS），因为这正是搜索连通块的标准方法。  
- **最容易踩的坑**：  
  - 起始像素已经是目标颜色时需要 **提前返回**，否则会陷入无限递归或把整张图都改成同一个颜色。  
  - 递归实现时 **忘记判断越界**，会导致 IndexError。  
  - BFS 实现时 **忘记在加入队列前检查颜色**，会把不该染色的格子也加入，产生错误结果。  
- **下次遇到同类题**：第一步先 **判断是否需要搜索**（颜色是否相同），然后 **选定 DFS 或 BFS**，写好 **边界检查** 与 **颜色相等判断**，再进行递归或循环遍历。
