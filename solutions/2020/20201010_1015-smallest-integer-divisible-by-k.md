# #1015. 最小整数可被 K 整除 / Smallest Integer Divisible by K

> 难度：中等 · 标签：Hash Table、Math · [LeetCode 链接](https://leetcode.com/problems/smallest-integer-divisible-by-k/)

---

## 题目（英文原版）

**Description**

Given a positive integer k, you need to find the length of the smallest positive integer n such that n is divisible by k, and n only contains the digit 1.
Return the length of n. If there is no such n, return -1.
Note: n may not fit in a 64-bit signed integer.

**Examples**

**Example 1:**

```
Input: k = 1
Output: 1
Explanation: The smallest answer is n = 1, which has length 1.
```

**Example 2:**

```
Input: k = 2
Output: -1
Explanation: There is no such positive integer n divisible by 2.
```

**Example 3:**

```
Input: k = 3
Output: 3
Explanation: The smallest answer is n = 111, which has length 3.
```

**Constraints**

- 1 <= k <= 105

---

## 题目（中文翻译）

给定一个正整数（positive integer）`k`，需要找到满足以下条件的最小正整数 `n` 的长度：

- `n` 能被 `k` 整除；
- `n` 的十进制表示中只包含数字 `1`。

返回该 `n` 的长度。如果不存在满足条件的 `n`，返回 `-1`。  
**注意**：`n` 可能超出 64 位有符号整数（64-bit signed integer）的取值范围。

### 示例

**示例 1**  
输入: `k = 1`  
输出: `1`  
解释: 最小的答案是 `n = 1`，其长度为 1。

**示例 2**  
输入: `k = 2`  
输出: `-1`  
解释: 不存在能被 2 整除且只包含数字 `1` 的正整数。

**示例 3**  
输入: `k = 3`  
输出: `3`  
解释: 最小的答案是 `n = 111`，其长度为 3。

### 约束

- `1 <= k <= 10^5`

---

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**从 1 开始，一直在后面拼 “1”，直到得到一个能被 `k` 整除的数**。  
比如 `k = 3` 时：

```
1      → 1 % 3 = 1   （不是 0）
11     → 11 % 3 = 2  （不是 0）
111    → 111 % 3 = 0 （找到了！）
```

这里我们每次都把前一个数乘以 10 再加 1（因为在十进制里往后加一个 1 相当于 `old * 10 + 1`），然后检查它是否能被 `k` 整除。

> **数据结构类比**  
> - **哈希表（字典）**：就像查字典，`key` 是“余数”，`value` 可以记下这个余数出现的第几位。我们只需要快速判断一个余数是否已经出现过。

**为什么这个方法一定能得到答案（如果答案存在）**  
在每一步我们只关心 **余数**（`num % k`），而不是完整的巨大的整数。余数的取值范围是 `0 … k-1`，最多只有 `k` 种可能。如果我们一直往下走，却从未得到余数 `0`，而且出现了 **重复的余数**，说明之后的余数序列会循环，永远也到不了 `0`，此时答案不存在。

**时间/空间复杂度的大白话解释**  
- **时间复杂度 O(k)**：最坏情况下我们可能要尝试 `k` 次（因为余数只能出现 `k` 种），每一次的计算都是常数时间（一次乘法、一次加法、一次取模）。
- **空间复杂度 O(k)**：我们需要一个哈希表（或集合）保存已经出现过的余数，最坏会保存 `k` 个余数。

#### 代码（Python）

```python
def smallestRepunitDivByK(k: int) -> int:
    """
    暴力模拟：从 1 开始，每次在后面加一个 1，检查余数。
    若出现循环（余数重复）则返回 -1。
    """
    # 余数为 0 时说明找到了答案
    remainder = 1 % k
    length = 1                     # 当前数字的位数
    visited = {remainder}          # 已出现的余数集合，类似字典的 key

    # 如果一开始余数就是 0，直接返回 1
    if remainder == 0:
        return 1

    # 循环直到出现重复余数
    while True:
        # 在原来的数后面加一个 1： (old * 10 + 1) % k
        remainder = (remainder * 10 + 1) % k
        length += 1                # 位数加一

        if remainder == 0:         # 找到可被 k 整除的数
            return length

        if remainder in visited:   # 余数出现循环，说明永远到不了 0
            return -1

        visited.add(remainder)     # 记录新出现的余数
```

#### 复杂度

- **时间复杂度：O(k)**  
  想象你在排队买票，最多只能排 `k` 个人，因为一旦第 `k+1` 个人的余数和前面的某个人相同，队伍就会无限循环。

- **空间复杂度：O(k)**  
  我们需要一个“记事本”保存已经出现的余数，最坏情况下要写 `k` 条记录。

---

### 2. 最优解

#### 思路  

从暴力解我们已经知道：**只需要关注余数**，不必真的把巨大的全 1 数字保存下来。  
**瓶颈** 在于我们每次都要检查“余数是否已经出现”。如果使用列表或循环遍历去判断，会导致 **O(k²)** 的时间。  

**优化思路**：

1. **使用集合（哈希表）**：集合的“是否包含”操作在平均情况下是 **O(1)**，这正好解决了重复余数的快速检测问题。  
2. **直接返回长度**：我们不需要存储整个数字，只要记录已经走了多少位（`length`），一旦余数为 0，就可以立刻返回。

整个过程其实已经是最简的 **“余数 BFS（宽度优先搜索）”**，因为我们从最短的数字（1 位）开始逐层扩展，保证第一次碰到余数 0 时的长度一定是最小的。

> **核心概念解释**  
> - **哈希表/集合**：想象你有一本电话簿，查找某个人的电话号码只需要看一次，速度非常快。这里我们把每个余数当作“电话号码”，用集合快速判断是否已经“打过这通电话”。  
> - **余数循环**：如果余数出现了重复，就像在走迷宫时走回了已经走过的路口，说明以后只能在这条环路里转，不会再找到出口（余数 0）。

#### 代码（Python）

```python
def smallestRepunitDivByK(k: int) -> int:
    """
    最优解：只用余数和集合实现 O(k) 时间、O(k) 空间。
    """
    remainder = 1 % k          # 第一个只含 1 的数的余数
    length = 1                 # 当前位数
    visited = {remainder}      # 已出现的余数集合

    if remainder == 0:         # k=1 的特例
        return 1

    while True:
        remainder = (remainder * 10 + 1) % k   # 继续在后面加 1
        length += 1

        if remainder == 0:    # 找到答案
            return length

        if remainder in visited:   # 余数循环 → 无解
            return -1

        visited.add(remainder)     # 记录新余数
```

#### 复杂度

- **时间复杂度：O(k)** — 解释：最多检查 `k` 次，每一次都是常数时间（乘、加、取模、集合查询），就像在排队时最多只能等 `k` 个人。
- **空间复杂度：O(k)** — 解释：我们需要保存至多 `k` 个余数，就像一本最多有 `k` 页的笔记本。

与暴力解的差别仅在于**使用集合**把“是否出现过”的判断从线性搜索降到常数时间，整体仍是 O(k) 但常数更小、更稳健。

## 心得

- **核心技巧**：**余数循环检测 + 哈希集合**。把大数转化为余数序列，用集合快速判断是否进入死循环。
- **适用的题型**  
  1. “只由特定数字组成的最小可整除数”——如只含 0 与 1、只含 2 的数等。  
  2. “求最短路径/最少操作数”类的 BFS 题目，需要用集合防止重复状态。  
  3. “循环小数/循环序列”相关的数学题，常通过余数判断循环结束。
- **一句话总结**：**把“巨大数字”压缩成“余数”，用集合防止重复，最先得到余数 0 的长度即为答案。**

---

## 反思

- **第一反应**：直接把 “111…1” 生成出来，然后不停除以 `k` 检查。后来意识到数字会超出 64 位，需要改用余数。
- **最容易踩的坑**  
  - **忘记记录已出现的余数**，导致无限循环（程序卡死）。  
  - **没有处理 `k = 1` 的特殊情况**，会在循环里一直跑。  
  - **使用列表而非集合**进行重复检测，导致时间复杂度升到 O(k²)。
- **下次类似题目第一步**：**先把问题抽象成“状态（余数）转移”，再思考如何快速判断状态是否已经访问**。这样往往能直接写出最优解。
