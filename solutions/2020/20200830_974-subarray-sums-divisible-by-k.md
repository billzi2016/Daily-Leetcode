## 题目（英文原版）

**Description**

Given an integer array nums and an integer k, return the number of non-empty subarrays that have a sum divisible by k.
A subarray is a contiguous part of an array.

**Examples**

**Example 1:**

```
Input: nums = [4,5,0,-2,-3,1], k = 5
Output: 7
Explanation: There are 7 subarrays with a sum divisible by k = 5:
[4, 5, 0, -2, -3, 1], [5], [5, 0], [5, 0, -2, -3], [0], [0, -2, -3], [-2, -3]
```

**Example 2:**

```
Input: nums = [5], k = 9
Output: 0
```

**Constraints**

- 1 <= nums.length <= 3 * 104
- -104 <= nums[i] <= 104
- 2 <= k <= 104

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法就是**枚举所有可能的子数组**，把它们的元素相加，看和是否能被 `k` 整除。

- **枚举子数组**：对每一个起始位置 `i`，再遍历所有可能的结束位置 `j (i ≤ j)`，把 `nums[i..j]` 的元素累加得到子数组的和。  
- **判断可整除**：如果 `sum % k == 0`（Python 中 `%` 会把负数的余数也转换成非负数），说明这个子数组满足要求，计数器 `ans` 加一。

> **类比**：把数组想成一条长长的路，暴力解就是把每一段起点和终点都挑出来，走一遍看这段路的“总长度”能不能被 `k` 整除。显然走的次数会非常多。

**为什么这个方法一定正确**：因为我们把**所有**合法子数组都检查了一遍，只要满足条件就计数，漏掉的可能性为零。

#### 代码（Python）

```python
def subarraysDivByK_bruteforce(nums, k):
    n = len(nums)
    ans = 0
    # 枚举起点 i
    for i in range(n):
        cur_sum = 0
        # 枚举终点 j，顺序累加可以避免每次都重新遍历子数组
        for j in range(i, n):
            cur_sum += nums[j]          # 累加子数组 nums[i..j] 的和
            if cur_sum % k == 0:        # 判断是否能被 k 整除
                ans += 1
    return ans
```

#### 复杂度  

- **时间复杂度**：`O(n²)`  
  - “平方”意味着如果数组长度是 1000，算法大约要执行 1000×1000 = 1,000,000 次循环。这里的 `n` 是数组长度，两个嵌套循环导致每对 `(i, j)` 都被遍历一次。  
- **空间复杂度**：`O(1)`  
  - 只用了常数级别的额外变量 `cur_sum`、`ans`，不随 `n` 增长。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**每次都要重新累计子数组的和**，导致二次循环。  
我们可以利用**前缀和**（prefix sum）把子数组的和转化为两个前缀和的差：

```
sum(i..j) = prefix[j+1] - prefix[i]
```

如果 `sum(i..j)` 能被 `k` 整除，则：

```
(prefix[j+1] - prefix[i]) % k == 0
=> prefix[j+1] % k == prefix[i] % k
```

也就是说，只要两个前缀和 **余数相同**，它们之间的子数组和就一定能被 `k` 整除。

于是问题变成：

> **在所有前缀和的余数序列中，找出余数相同的配对有多少对？**

这可以用**哈希表**（字典）一次遍历完成：

1. 维护一个字典 `cnt`，键是余数 `r`（`0 ≤ r < k`），值是已经出现过的该余数的次数。  
2. 初始时把余数 `0` 的计数设为 1，代表空前缀和（`prefix = 0`）已经出现一次。这样如果某个前缀和本身就能被 `k` 整除（余数为 0），就能直接计数。  
3. 遍历数组，实时累计前缀和 `pre`，取余数 `r = pre % k`（Python 中对负数取余会得到非负数），  
   - 当前余数在字典中出现了 `cnt[r]` 次，说明有这么多之前的前缀和余数相同，**每一次配对都对应一个合法子数组**，于是把 `cnt[r]` 加到答案 `ans` 中。  
   - 最后把当前余数的计数加 1，表示它已经出现过了。

> **类比**：把每个前缀和的余数想成一本“登记册”，每次出现相同余数就像在册子里找到了“同伴”，同伴之间的距离（子数组）恰好满足“和能被 k 整除”。登记册（哈希表）让我们**瞬间**知道同伴有多少，而不必遍历所有可能的配对。

#### 代码（Python）

```python
def subarraysDivByK(nums, k):
    """
    返回和能被 k 整除的非空子数组个数
    """
    from collections import defaultdict

    cnt = defaultdict(int)   # 余数 -> 出现次数
    cnt[0] = 1                # 空前缀和的余数是 0，出现一次

    pre = 0                   # 累计前缀和
    ans = 0

    for num in nums:
        pre += num            # 更新前缀和
        # Python 的取余会把负数结果转为非负，这里直接使用
        r = pre % k           # 当前前缀和的余数

        # 之前出现过相同余数的次数，就是以当前下标结尾的合法子数组数
        ans += cnt[r]

        # 把当前余数计数加一，供后面的元素使用
        cnt[r] += 1

    return ans
```

#### 复杂度  

- **时间复杂度**：`O(n)`  
  - 只遍历一次数组，哈希表的查询、插入都是常数时间（摊销 O(1)），所以整体是线性时间。相比暴力的 `O(n²)`，速度提升了 **n 倍**。  
- **空间复杂度**：`O(k)`（最坏情况）  
  - 哈希表最多会存储 `k` 种不同的余数（`0 … k-1`），`k` 的上限是 `10⁴`，远小于 `n`（最多 `3·10⁴`），因此空间消耗是可接受的。

## 心得

- **核心技巧**：利用前缀和的余数相等性质，把“子数组和能被 k 整除”转化为“两个前缀余数相同”。  
- **适用的题型**  
  1. “子数组和等于目标值”——使用前缀和 + 哈希表（如 LeetCode 560 Subarray Sum Equals K）。  
  2. “最长子数组满足和可被 k 整除”——同样利用余数相等，只是求最长而不是计数。  
  3. “数组划分为若干段，使每段和相等”——可以借助前缀和与余数的思想进行分段计数。  
- **一句话总结**：**把“能被 k 整除”转化为“余数相同”，用哈希表一次统计配对**。

## 反思

- **第一反应**：直接枚举子数组并求和，想到“暴力”。这在面试里常被用来检验对题目理解的完整性。  
- **最容易踩的坑**  
  - **负数取余**：在有负数的情况下，`%` 在不同语言表现不一致。Python 会把结果转为非负数，直接使用即可；若换成 C++/Java，需要手动 `( (pre % k) + k ) % k`。  
  - **初始计数**：忘记把余数 `0` 的出现次数初始化为 1，会导致遗漏以首元素开始的合法子数组。  
  - **整数溢出**：在语言的整数范围受限时，前缀和可能会超出，需要使用 64 位整数或自行取模。  
- **下次类似题的第一步**：**先写出前缀和公式，检查能否把目标条件转化为前缀之间的关系**，若可以，则考虑用哈希表/数组记录出现次数，避免二次遍历。
