# #900. RLE 迭代器 / RLE Iterator

> 难度：中等 · 标签：Array、Design、Counting、Iterator · [LeetCode 链接](https://leetcode.com/problems/rle-iterator/)

## 题目（英文原版）

**Description**

We can use run-length encoding (i.e., RLE) to encode a sequence of integers. In a run-length encoded array of even length encoding (0-indexed), for all even i, encoding[i] tells us the number of times that the non-negative integer value encoding[i + 1] is repeated in the sequence.
Given a run-length encoded array, design an iterator that iterates through it.
Implement the RLEIterator class:

**Examples**

**Example 1:**

```
Input
["RLEIterator", "next", "next", "next", "next"]
[[[3, 8, 0, 9, 2, 5]], [2], [1], [1], [2]]
Output
[null, 8, 8, 5, -1]

Explanation
RLEIterator rLEIterator = new RLEIterator([3, 8, 0, 9, 2, 5]); // This maps to the sequence [8,8,8,5,5].
rLEIterator.next(2); // exhausts 2 terms of the sequence, returning 8. The remaining sequence is now [8, 5, 5].
rLEIterator.next(1); // exhausts 1 term of the sequence, returning 8. The remaining sequence is now [5, 5].
rLEIterator.next(1); // exhausts 1 term of the sequence, returning 5. The remaining sequence is now [5].
rLEIterator.next(2); // exhausts 2 terms, returning -1. This is because the first term exhausted was 5,
but the second term did not exist. Since the last term exhausted does not exist, we return -1.
```

**Constraints**

- 2 <= encoding.length <= 1000
- encoding.length is even.
- 0 <= encoding[i] <= 109
- 1 <= n <= 109
- At most 1000 calls will be made to next.

## 题目（中文翻译）

我们可以使用**游程长度编码**（run‑length encoding，简称 RLE）来压缩一个整数序列。在一个偶数长度的编码数组 `encoding`（下标从 0 开始）中，所有偶数下标 `i` 对应的 `encoding[i]` 表示非负整数 `encoding[i + 1]` 在原序列中连续出现的次数。

给定这样一个游程长度编码数组，设计一个迭代器，使其能够按顺序遍历原始序列。

实现 `RLEIterator` 类，使其支持以下操作：

* `RLEIterator(int[] encoding)`：构造函数，接收上述的编码数组。
* `int next(int n)`：消耗序列中的前 `n` 个元素并返回第 `n` 个被消耗的元素的值。如果在消耗过程中已经没有元素可供消耗，则返回 `-1`。

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  
最直接的想法是把 **RLE 编码** 直接展开成真实的序列，然后像普通数组那样用指针移动。  

- **展开序列**：遍历 `encoding`，对每一对 `(cnt, val)`，把 `val` 重复 `cnt` 次加入一个新列表 `seq`。  
- **遍历**：维护一个普通的下标 `pos`，每次 `next(n)` 时把 `pos` 往后移动 `n` 步，返回移动后所在位置的值。如果越界则返回 `-1`。  

> 类比：把压缩的字典（`encoding`）展开成一本完整的书（`seq`），然后像翻页一样读。

这种方法**一定能得到正确答案**，因为我们把压缩信息全部恢复了，之后的操作完全等价于题目要求的迭代器行为。

#### 代码（Python）  

```python
class RLEIterator:
    def __init__(self, encoding):
        """
        把 RLE 编码展开成完整序列 seq
        """
        self.seq = []                     # 完整序列，类似“展开的书”
        for i in range(0, len(encoding), 2):
            cnt = encoding[i]             # 出现次数
            val = encoding[i + 1]         # 实际数值
            # 把 val 重复 cnt 次加入 seq
            self.seq.extend([val] * cnt)  # 关键行：把压缩信息展开

        self.pos = 0                      # 当前指针，指向下一个可返回的元素

    def next(self, n: int) -> int:
        """
        向前走 n 步，返回走到的元素（若超出序列返回 -1）
        """
        self.pos += n                     # 把指针往前跳 n 步
        if self.pos > len(self.seq):      # 越界检查（指针已经超过序列长度）
            return -1
        # 因为 pos 是“已经走过的”元素数量，所以实际要返回的是 pos-1 位置的值
        return self.seq[self.pos - 1]
```

#### 复杂度  

- **时间复杂度**：`O(T)`，其中 `T = Σ cnt` 为展开后序列的总长度。  
  - **解释**：我们必须把每个出现次数都写进去，最坏情况下会遍历 10⁹ 次，这在实际运行中会非常慢。  
- **空间复杂度**：`O(T)`，需要存放完整的展开序列，同样可能会占用巨大的内存。

### 2. 最优解  

#### 思路  

从暴力解可以看到，**真正耗时的地方在于把序列全部展开**，这一步是多余的，因为我们只需要知道“当前所在的值”和“还剩多少个”。  

**核心思路**：在 `encoding` 上直接维护两个指针/计数器：

1. `idx`：指向 `encoding` 中的 **当前对** 的起始位置（偶数下标），即 `cnt = encoding[idx]`，`val = encoding[idx+1]`。  
2. `remain`：记录当前 `val` 还剩多少个未被消耗。初始时 `remain = cnt`。  

`next(n)` 的执行过程：

- 当 `n` 大于 `remain` 时，说明当前的 `val` 已经用完，需要**跳到下一个对**。  
  - 把 `n -= remain`（把剩余的需求转移到后面的），`idx += 2`（跳到下一个 `(cnt, val)`），并把 `remain` 更新为新的 `cnt`。  
  - 重复上述步骤，直到 `n` 小于等于 `remain` 或者已经遍历完所有对。  
- 当 `n` 小于等于 `remain` 时，直接把 `remain -= n`，返回当前的 `val`。  

如果遍历完所有对仍然还有需求（`idx` 超出数组），说明序列已经耗尽，返回 `-1`。

> 类比：把压缩的字典想象成一堆装有相同颜色球的盒子（每个盒子里有 `cnt` 个球，颜色对应 `val`），我们每次取走 `n` 球，只需要看当前盒子还有多少球以及是否需要搬到下一个盒子，而不必把所有球都倒出来。

#### 代码（Python）  

```python
class RLEIterator:
    def __init__(self, encoding):
        """
        直接在编码数组上做迭代，不展开序列。
        idx   : 当前处理的 pair 起始下标（偶数位置）
        remain: 当前 val 还剩多少个可以被消耗
        """
        self.encoding = encoding
        self.idx = 0                     # 指向当前 cnt 的位置
        self.remain = 0                  # 当前值剩余的个数

        # 初始化第一对（若 cnt 为 0，需要跳过）
        self._advance_to_next_nonzero()

    def _advance_to_next_nonzero(self):
        """跳过 cnt 为 0 的对，找到第一个 cnt>0 的位置"""
        while self.idx < len(self.encoding) and self.encoding[self.idx] == 0:
            self.idx += 2                # 直接跳过这一对
        if self.idx < len(self.encoding):
            self.remain = self.encoding[self.idx]   # 记录剩余次数

    def next(self, n: int) -> int:
        """
        消耗 n 个元素，返回第 n 个被消耗的元素的值；
        若不足 n 个则返回 -1。
        """
        while n > 0 and self.idx < len(self.encoding):
            if self.remain >= n:               # 当前值足够消耗
                self.remain -= n               # 更新剩余次数
                return self.encoding[self.idx + 1]   # 返回对应的 val
            else:
                # 当前值不够，先把它全部用掉
                n -= self.remain                # 还需要消耗的数量
                self.idx += 2                   # 跳到下一个 pair
                self._advance_to_next_nonzero() # 更新 remain（可能为 0）

        # 循环结束后，说明已经没有元素可以消耗
        return -1
```

#### 复杂度  

- **时间复杂度**：`O(k)`，其中 `k` 为一次 `next` 调用过程中**跨过的对的数量**。  
  - **解释**：每个对只会被访问一次（因为指针只向前移动），累计下来所有 `next` 调用的总时间是 `O(m)`，`m` 为 `encoding` 长度 ≤ 1000，远小于展开序列的大小。  
- **空间复杂度**：`O(1)`，只用了常数级别的额外变量（指针、计数），不随输入规模增长。

## 心得  

- **核心技巧**：在压缩数据上直接维护“当前剩余计数”，用 **双指针 + 贪心** 的思路一次遍历解决。  
- **适用的题型**：  
  1. 需要在 **压缩序列** 上进行查询或删除的题目（如 “Compressed String Iterator”）。  
  2. **计数型迭代**，比如 “Design an Iterator that returns the k‑th smallest number after each insertion”。  
- **一句话总结**：**把“展开”变成“在原地消费”，只在需要时才向前跳。**

---

## 反思  

- **第一反应**：把压缩序列全部展开，然后像普通数组那样遍历。  
- **最容易踩的坑**：  
  - `cnt` 可能为 `0`，需要跳过，否则会陷入死循环。  
  - `next` 的参数 `n` 可能远大于当前剩余，需要一次或多次跨越不同的 `(cnt, val)` 对。  
  - 当所有元素都被消耗完后仍然被调用，需要返回 `-1` 而不是抛异常。  
- **下次类似题的第一步**：**先思考能否在压缩形式上直接操作**，找出可以维护的“状态”（如剩余次数、当前值），避免不必要的展开。
