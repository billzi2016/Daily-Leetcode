# #914. 牌堆中的 X 同值分组 / X of a Kind in a Deck of Cards

> 难度：简单 · 标签：Array、Hash Table、Math、Counting、Number Theory · [LeetCode 链接](https://leetcode.com/problems/x-of-a-kind-in-a-deck-of-cards/)

## 题目（英文原版）

**Description**

You are given an integer array deck where deck[i] represents the number written on the ith card.
Partition the cards into one or more groups such that:
Return true if such partition is possible, or false otherwise.

**Examples**

**Example 1:**

```
Input: deck = [1,2,3,4,4,3,2,1]
Output: true
Explanation: Possible partition [1,1],[2,2],[3,3],[4,4].
```

**Example 2:**

```
Input: deck = [1,1,1,2,2,2,3,3]
Output: false
Explanation: No possible partition.
```

**Constraints**

- 1 <= deck.length <= 104
- 0 <= deck[i] < 104

---

## 题目（中文翻译）

给定一个整数数组 `deck`，其中 `deck[i]` 表示第 `i` 张牌上的数字。

请将所有牌划分为一个或多个组，使得：

- 每个组恰好包含 **X** 张牌，且 **X** ≥ 2；
- 同一组内的所有牌数字相同。

如果可以完成上述划分，返回 `true`；否则返回 `false`。

---

**示例 1**

```text
Input: deck = [1,2,3,4,4,3,2,1]
Output: true
Explanation: 可以划分为 [1,1], [2,2], [3,3], [4,4] 四个组，每组均含有相同数字且大小为 2。
```

**示例 2**

```text
Input: deck = [1,1,1,2,2,2,3,3]
Output: false
Explanation: 无法找到满足条件的划分方式。
```

---

**约束条件**

- `1 <= deck.length <= 10^4`
- `0 <= deck[i] < 10^4`

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

1. 先把每张牌出现的次数统计出来。可以把 `deck` 看成一本“词典”，  
   **key** 是卡片上的数字，**value** 是这张数字出现的次数。  
   这正好对应 **哈希表**（在 Python 里用 `dict`），就像查字典时先找到单词（key），再看到对应的页码（value）。  

2. 设想我们已经知道要把每一组卡片的大小定为 `X`（`X ≥ 2`），  
   那么只要每个数字的出现次数都能被 `X` 整除，就可以把它们完整地划分成若干组。  

3. 暴力的做法是：枚举所有可能的 `X`（从 2 开始，一直枚举到最小出现次数），  
   对每个 `X` 检查所有数字的出现次数是否都能被 `X` 整除。只要找到一个满足条件的 `X`，答案就是 `True`；  
   全部尝试完都不行，就返回 `False`。  

**为什么正确**：  
如果真的能划分成若干组，每组大小必然是某个整数 `X`（所有组大小相同），且每个数字的出现次数必须是 `X` 的整数倍。  
因此只要我们把所有可能的 `X` 都尝试一遍，就一定能发现这个合法的 `X`（如果存在的话）。  

**时间/空间复杂度**：  
- 统计次数是一次遍历，`O(n)`（`n` 为卡牌数量）。  
- 枚举 `X` 最多到最小出现次数 `m`（`m ≤ n`），每次检查所有不同数字的次数（记作 `k`，`k ≤ n`），所以最坏情况是 `O(m·k)`，约等于 `O(n²)`。  
- 空间上我们只用一个哈希表存放次数，最多 `k` 条记录，空间为 `O(k)`，即 `O(n)`。  

> **大白话**：`O(n²)` 可以理解为“如果卡牌有 100 张，最坏情况下要检查 10 000 次”。在实际数据（`n ≤ 10⁴`）里仍能跑完，但不是最优的。

#### 代码（Python）

```python
from collections import Counter
from typing import List

def has_groups_size_x_bruteforce(deck: List[int]) -> bool:
    # 1️⃣ 统计每个数字出现了几次，像查字典一样
    cnt = Counter(deck)                 # 例如 {1:2, 2:2, 3:2, 4:2}
    
    # 2️⃣ 找到出现次数的最小值，后面只需要枚举到它
    min_freq = min(cnt.values())        # 如果最小次数是 1，直接返回 False（因为 X≥2）
    if min_freq < 2:
        return False

    # 3️⃣ 枚举可能的组大小 X（从 2 到 min_freq）
    for x in range(2, min_freq + 1):
        # 只要有一种 X 能让所有次数整除，就成功
        if all(freq % x == 0 for freq in cnt.values()):
            return True                # 找到合法的 X
    return False                        # 全部尝试完都不行
```

#### 复杂度  

- **时间复杂度**：`O(n²)`（最坏情况下枚举 `X` 到 `n`，每次遍历所有不同数字）。  
  > 这里的 `n²` 可以理解为“卡牌数量的平方”，随着卡牌数增大，耗时会明显增长。  
- **空间复杂度**：`O(n)`，哈希表保存每个不同数字的出现次数。

### 2. 最优解  

#### 思路  

从暴力解可以看到，**瓶颈** 在于我们要把所有可能的 `X` 都尝试一遍。  
其实我们不需要枚举，直接求出所有出现次数的**最大公约数（GCD）**就行。  

**关键观察**：

- 如果所有出现次数都能被同一个整数 `X` 整除，那么 `X` 必然是这些次数的公约数。  
- 进一步，**最大**的那一个公约数（记作 `g`）一定也是合法的候选 `X`。  
- 只要 `g ≥ 2`，我们就可以把每种数字的卡牌分成大小为 `g` 的若干组，满足题目要求。  

所以问题转化为：**求所有出现次数的最大公约数，判断它是否 ≥ 2**。

**为什么这样做是对的**：

- 假设存在合法的 `X`，则 `X` 必然是所有出现次数的公约数。  
- 最大公约数 `g` 包含了所有可能的公约数（包括 `X`），因此 `g` 一定不小于 `X`。  
- 如果 `g ≥ 2`，我们直接使用 `g` 作为组大小即可；若 `g = 1`，说明没有任何大于等于 2 的公共因子，题目要求无法满足。  

**核心算法**：  
- **计数**（哈希表） → 同上。  
- **求最大公约数**：使用欧几里得算法（`math.gcd`），把所有次数两两求 GCD，最终得到整体的 GCD。  
  - 欧几里得算法可以类比为“把两块面粉称量，取较小的那块再去称量剩下的”，不断递归直到剩下的重量为 0，最后的非零重量就是最大公约数。  

#### 代码（Python）

```python
import math
from collections import Counter
from typing import List

def has_groups_size_x(deck: List[int]) -> bool:
    # 1️⃣ 统计每个数字出现的次数
    cnt = Counter(deck)                 # 例子: {1:2, 2:2, 3:2, 4:2}
    
    # 2️⃣ 计算所有出现次数的最大公约数
    #   先把第一个次数当作初始的 gcd
    freqs = list(cnt.values())
    g = freqs[0]
    for f in freqs[1:]:
        g = math.gcd(g, f)              # 欧几里得算法求两数的 gcd
        # 如果在中途已经降到 1，后面再也找不到 ≥2 的公共因子，直接返回 False
        if g == 1:
            return False
    
    # 3️⃣ 判断最大公约数是否大于等于 2
    return g >= 2
```

#### 复杂度  

- **时间复杂度**：`O(n)`  
  - 统计次数一次遍历 `O(n)`。  
  - 求最大公约数只需遍历不同数字的次数（最多 `n` 次），每次 `gcd` 为 `O(log max_freq)`，整体仍是线性级别。  
  > 与暴力解的 `O(n²)` 相比，**只需要一次遍历**，即使 `n=10⁴` 也能毫秒级完成。  

- **空间复杂度**：`O(n)`，用于保存哈希表的计数。

## 心得  

- **核心技巧**：把“能否分成相同大小的若干组”转化为“所有出现次数的最大公约数”。  
- **适用的题型**  
  1. **“分数能否约分为整数”** 类似题，如 LeetCode 1281（Subtract the Product and Sum of Digits of an Integer）中需要判断公约数。  
  2. **“把数组分成相同长度的子数组”**，比如判断能否把数组分成若干等长且元素相同的块。  
  3. **数论相关的划分问题**，如判断若干数字能否用相同的基数表示等。  

> **一句话总结**：只要把“相同组大小”抽象为“公共因子”，求最大公约数即可快速得到答案。

## 反思  

- **第一反应**：看到“把卡牌分成若干组，每组大小相同且卡牌相同”，自然想到先统计每种卡牌的数量，然后尝试所有可能的组大小。  
- **最容易踩的坑**  
  1. **忘记 `X ≥ 2` 的限制**，导致出现 `X=1`（把每张卡单独成组）也返回 `True`。  
  2. **边界情况**：当只有一种卡牌或出现次数为 1 时，需要直接返回 `False`。  
  3. **忽视计数为 0 的情况**（虽然题目保证 `deck[i] ≥ 0`，但仍需防止空列表）。  
- **下次遇到同类题**：第一步先**统计出现次数**，然后**思考是否可以用最大公约数或最小公倍数**等数论工具把“相同大小”转化为“公共因子”。这样往往能把暴力枚举压缩到 O(n)。
