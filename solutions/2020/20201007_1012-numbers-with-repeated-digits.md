# #1012. 重复数字的整数 / Numbers With Repeated Digits

> 难度：困难 · 标签：Math、Dynamic Programming · [LeetCode 链接](https://leetcode.com/problems/numbers-with-repeated-digits/)

---

## 题目（英文原版）

**Description**

Given an integer n, return the number of positive integers in the range [1, n] that have at least one repeated digit.

**Examples**

**Example 1:**

```
Input: n = 20
Output: 1
Explanation: The only positive number (<= 20) with at least 1 repeated digit is 11.
```

**Example 2:**

```
Input: n = 100
Output: 10
Explanation: The positive numbers (<= 100) with atleast 1 repeated digit are 11, 22, 33, 44, 55, 66, 77, 88, 99, and 100.
```

**Example 3:**

```
Input: n = 1000
Output: 262
```

**Constraints**

- 1 <= n <= 109

---

## 题目（中文翻译）

给定一个整数 `n`，返回区间 `[1, n]` 中 **正整数（positive integer）** 中至少含有一个 **重复数字（repeated digit）** 的数量。

**示例 1**  
**输入**: `n = 20`  
**输出**: `1`  
**解释**: 唯一满足条件的正整数（≤ 20）是 `11`，它含有重复数字。

**示例 2**  
**输入**: `n = 100`  
**输出**: `10`  
**解释**: 满足条件的正整数（≤ 100）有 `11, 22, 33, 44, 55, 66, 77, 88, 99, 100`，共 10 个。

**示例 3**  
**输入**: `n = 1000`  
**输出**: `262`

**约束条件**  
- `1 <= n <= 10^9`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把区间 `[1, n]` 里的每一个整数都检查一遍，判断它是否出现了重复的数字。  
- **检查方式**：把整数转换成字符串，逐位放进一个 `set`（集合）中。集合的特性是“不允许出现相同的元素”，所以当我们往集合里放一个已经存在的字符时，就说明出现了重复。  
- **数据结构类比**：`set` 好比一本“去重字典”，每翻到一个新词（数字字符），如果字典里已经有这页了，就说明这词是重复的。  

这种方法一定能得到正确答案，因为我们把所有可能的数都枚举并且每个数都做了严格的重复检测。

#### 代码（Python）

```python
def num_dup_digits_brute(n: int) -> int:
    """暴力枚举 1~n，统计出现重复数字的个数"""
    def has_repeat(x: int) -> bool:
        """判断整数 x 是否含有重复数字"""
        seen = set()                     # 用集合记录已经出现的数字字符
        for ch in str(x):                # 把整数转成字符串逐位检查
            if ch in seen:               # 如果字符已经在集合里，说明重复
                return True
            seen.add(ch)                 # 否则加入集合继续检查
        return False                     # 所有位都不重复

    cnt = 0
    for i in range(1, n + 1):            # 逐个遍历 1~n
        if has_repeat(i):
            cnt += 1
    return cnt
```

#### 复杂度  

- **时间复杂度**：`O(n · d)`，其中 `d` 是数字 `n` 的位数（最多 10 位），相当于对每个数都要看一遍它的每一位。可以把 `O(n·d)` 想象成“跑了 n 步，每步还要检查几次手指”。  
- **空间复杂度**：`O(d)`，只用了一个集合来存最多 `d` 个字符，`d ≤ 10`，可以看作常数级别的额外空间。

> 暴力解在 `n` 很小（比如几千）时还能接受，但当 `n` 接近题目上限 `10⁹` 时，遍历十亿次显然不可行。

---

### 2. 最优解

#### 思路  

我们把问题转化为 **“在 1~n 中没有重复数字的数有多少？”** ，因为  

```
有重复数字的数 = 总数 - 没有重复数字的数
```

只要高效求出 **不含重复数字的正整数个数**，答案就立即得到。

**核心技巧**：**数位 DP（Digit DP） + 组合计数**。  
我们不真的去枚举每个数，而是利用排列组合的思想，直接统计满足条件的数字有多少。

下面一步步推导：

1. **先算所有位数 < len(n) 的情况**  
   - 假设我们要统计 3 位数（100~999）且每位数字互不相同。  
   - 第一位不能为 0，有 9 种选择（1~9）。  
   - 第二位可以从剩下的 9 个数字中选（0 现在可以用），所以有 9 种。  
   - 第三位从剩下的 8 个数字中选，……  
   - 于是 3 位数的合法个数 = `9 * 9 * 8`。  
   - 对于任意 `k` 位数，这个乘积就是 **排列数** `P(9,1) * P(9, k-1)`，更一般地写成 `9 * A(9, k-1)`，其中 `A(m, k) = m·(m-1)…(m-k+1)`。

2. **再算和 n 位数长度相同、且不超过 n 的情况**  
   - 把 n 写成字符串 `digits = [d₀, d₁, …, d_{L-1}]`（L 为位数）。  
   - 从最高位开始逐位检查：  
     - 在第 i 位，我们可以选 **比 n 的第 i 位小且未使用过的数字**，并且后面的位数可以随意填（只要不重复）。  
     - 对每一个可选的“小数字”，后面的 `L-i-1` 位可以用 **排列数** `A(10 - (i+1), L-i-1)` 来计数（因为已经用了 i+1 个不同的数字）。  
   - 如果当前位的数字在之前已经出现过，说明以当前前缀继续往下走必然会出现重复，此时直接停止计数。  
   - 如果遍历完所有位都没有出现重复，说明 n 本身也是“无重复”的，需要再加 1。

3. **最终答案**  
   - `no_repeat = (统计所有位数 < L 的合法数) + (统计位数 = L 且 ≤ n 的合法数)`  
   - `answer = n - no_repeat`

**为什么这样快？**  
- 我们只遍历了最多 10 位（因为 `n ≤ 10⁹`），每一位内部最多尝试 10 次选择，时间复杂度是 `O(L·10)`，即常数级别。  
- 不需要真的生成每个数字，全部用数学公式直接算出来。

#### 代码（Python）

```python
def num_dup_digits(n: int) -> int:
    """返回区间 [1, n] 中出现重复数字的正整数个数（最优解）"""
    # ---------- 辅助函数：排列数 A(m, k) ----------
    def perm(m: int, k: int) -> int:
        """从 m 个不同的元素中取出 k 个排列的个数，等价于 m*(m-1)*...*(m-k+1)"""
        ans = 1
        for i in range(k):
            ans *= (m - i)
        return ans

    s = str(n)
    L = len(s)                     # n 的位数
    # 1) 统计位数 < L 的合法数
    no_repeat = 0
    for k in range(1, L):          # k 为当前考虑的位数
        # 首位 9 种（1~9），其余 k-1 位从剩下的 9 个数字中排列
        no_repeat += 9 * perm(9, k - 1)

    # 2) 统计位数 = L 且 ≤ n 的合法数
    used = set()                   # 已经在前缀中使用过的数字
    for i, ch in enumerate(s):
        cur = int(ch)              # n 在第 i 位的实际数字
        # 枚举可以放在当前位置的“小数字”
        for d in range(0 if i else 1, cur):   # 首位不能为 0
            if d in used:
                continue          # 已经用过的数字不能再用
            # 剩余位置可以随意填，使用排列数计数
            remain = L - i - 1
            no_repeat += perm(10 - (i + 1), remain)
        # 若当前数字已经出现过，则后面的所有数都会产生重复，直接结束
        if cur in used:
            break
        used.add(cur)              # 当前数字加入已使用集合
    else:
        # 循环正常结束，说明 n 本身也没有重复数字，需要再加 1
        no_repeat += 1

    # 3) 结果 = 总数 - 没有重复的数
    return n - no_repeat
```

#### 复杂度  

- **时间复杂度**：`O(L·10)`，这里 `L ≤ 10`（因为 `n ≤ 10⁹` 只有最多 10 位），可以看成 **常数时间**。相当于“只走了十步，每步最多检查十个选项”。  
- **空间复杂度**：`O(L)`，仅用了一个集合 `used` 保存已使用的数字，最多存 10 个元素，同样是常数级别。

> 与暴力解相比，时间从 “遍历十亿次” 降到了 “遍历十次”，提升了好几个数量级。

## 心得

- **核心技巧**：**数位 DP + 排列计数**。先算出不含重复数字的数量，再用总数减去它得到答案。  
- **适用场景**：  
  1. “统计区间 `[1, n]` 中满足某种数位约束的整数”  
  2. “求不含特定数字/子串的正整数个数”  
  3. “求满足递增/递减、奇偶交替等位数限制的数的个数”  
- **一句话总结**：把“逐个检查每个数”转化为“按位枚举、用排列数直接计数”，从而实现指数级别的加速。

## 反思

- **第一反应**：直接循环遍历并用集合检查重复——最直接但不够高效。  
- **最容易踩的坑**：  
  - **首位不能为 0**：在计数时需要特殊处理，否则会把像 `012` 这样的非法数算进去。  
  - **处理 n 本身是否重复**：遍历完所有位数后要记得判断 n 是否已经计入（`else` 分支）。  
  - **排列数的参数**：容易把已经使用的数字算进去，导致 `perm` 的 `m` 参数写错。  
- **下次思路**：看到“在 1~n 中统计满足某种数位条件的数”，第一步就想到 **数位 DP**（即把问题拆成“前缀相同 / 小于当前位”两部分），再结合 **排列组合** 完成计数。这样可以快速从暴力到最优。
