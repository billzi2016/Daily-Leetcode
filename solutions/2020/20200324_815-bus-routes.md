# #815. 公交线路 / Bus Routes

> 难度：困难 · 标签：Array、Hash Table、Breadth-First Search · [LeetCode 链接](https://leetcode.com/problems/bus-routes/)

## 题目（英文原版）

**Description**

You are given an array routes representing bus routes where routes[i] is a bus route that the ith bus repeats forever.
You will start at the bus stop source (You are not on any bus initially), and you want to go to the bus stop target. You can travel between bus stops by buses only.
Return the least number of buses you must take to travel from source to target. Return -1 if it is not possible.

**Examples**

**Example 1:**

```
Input: routes = [[1,2,7],[3,6,7]], source = 1, target = 6
Output: 2
Explanation: The best strategy is take the first bus to the bus stop 7, then take the second bus to the bus stop 6.
```

**Example 2:**

```
Input: routes = [[7,12],[4,5,15],[6],[15,19],[9,12,13]], source = 15, target = 12
Output: -1
```

**Constraints**

- 1 <= routes.length <= 500.
- 1 <= routes[i].length <= 105
- All the values of routes[i] are unique.
- sum(routes[i].length) <= 105
- 0 <= routes[i][j] < 106
- 0 <= source, target < 106

## 题目（中文翻译）

你得到一个数组 `routes`，其中 `routes[i]` 表示第 *i* 辆公交车循环运行的公交线路（bus route）。你将从公交站 `source` 开始（最初并未乘坐任何公交车），希望前往公交站 `target`。只能通过乘坐公交车在各站之间移动。返回从 `source` 到 `target` 所需乘坐的最少公交车数量。如果无法到达，返回 `-1`。

示例 1  
Input: `routes = [[1,2,7],[3,6,7]], source = 1, target = 6`  
Output: `2`  
Explanation: 最佳策略是先乘坐第一辆公交车到达公交站 **7**，然后换乘第二辆公交车到达公交站 **6**。

示例 2  
Input: `routes = [[7,12],[4,5,15],[6],[15,19],[9,12,13]], source = 15, target = 12`  
Output: `-1`

约束条件
- `1 <= routes.length <= 500`
- `1 <= routes[i].length <= 10^5`
- `routes[i]` 中的所有值均唯一
- `sum(routes[i].length) <= 10^5`
- `0 <= routes[i][j] < 10^6`
- `0 <= source, target < 10^6`

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把 **每一次坐公交** 当成一次“选择”，把所有可能的坐车顺序全部列举出来，只要有一条能把 `source` 到达 `target`，就记录下来坐的公交数量，最后取最小值。

具体步骤可以想象成：

1. **从出发站 `source` 出发**，把所有经过 `source` 的公交车加入“候选列表”。  
2. **任选一辆候选公交**，坐上去后会经过它的所有站点。把这些站点记作“已到达”。  
3. 对每个已到达的站点，**继续找所有经过该站点的公交**（但不要重复坐已经坐过的公交），把它们加入下一层的候选列表。  
4. 重复 2、3 步，直到某一次坐完公交后，已经到达的站点里出现 `target` 为止。  

这相当于 **在“公交车”这层进行深度优先搜索**（DFS），尝试所有可能的乘车顺序。  
- **数据结构**：  
  - `bus_of_stop`：一个字典（哈希表），键是车站编号，值是所有经过该站的公交编号列表。哈希表就像一本“查字典”，把站点当成单词，查出来的就是哪些公交车（页码）会经过它。  
  - `visited_bus`：集合，用来记已经坐过的公交，防止在搜索时回到已经走过的路。  
  - `path`：当前已经坐的公交列表，用来统计乘车次数。  

- **为什么正确**：  
  - 我们把所有可能的乘车顺序都枚举出来，只要有一条能到达 `target`，必然会在搜索的某个分支里被发现。于是返回的最小乘车次数一定是答案。  

- **时间/空间复杂度**（大白话版）：  
  - **时间**：最坏情况下，需要遍历 **所有公交的所有排列组合**。如果有 `B` 辆公交，理论上最多有 `B!`（阶乘）种顺序，甚至每辆公交内部的站点也要遍历。这里我们用 `O(B * S)` 表示（`S` 为所有站点的总数），但实际会远远超出这个量级，几乎是 **指数级**，在数据稍大时就会“卡死”。  
  - **空间**：需要保存 `bus_of_stop`（站点 → 公交列表）以及递归栈/路径，最多是 `O(B + S)`，也就是所有公交和站点的总和。  

> **大白话**：  
> - `O(n²)` 里的 `n` 代表“规模”，比如 `n = 1000`，`n² = 1,000,000`，意味着程序会做一百万次基本操作。指数级（`2ⁿ`）更可怕，`n = 20` 时已经是 **1,048,576** 次，`n = 30` 时直接炸掉内存。  

#### 代码（Python）

```python
from typing import List, Dict, Set

def numBusesToDestination_bruteforce(routes: List[List[int]],
                                     source: int,
                                     target: int) -> int:
    # 1️⃣ 建立“站点 → 公交编号”的哈希表
    bus_of_stop: Dict[int, List[int]] = {}
    for i, stops in enumerate(routes):
        for stop in stops:
            bus_of_stop.setdefault(stop, []).append(i)

    # 2️⃣ 如果出发点和目标点相同，直接返回 0（不需要坐公交）
    if source == target:
        return 0

    # 3️⃣ 深度优先搜索（暴力遍历所有乘车顺序）
    visited_bus: Set[int] = set()          # 已经坐过的公交
    best = [float('inf')]                  # 用列表包装，方便在内部函数里修改

    def dfs(current_stop: int, buses_taken: int) -> None:
        """从 current_stop 开始继续搜索，已经坐了 buses_taken 辆公交"""
        # 剪枝：已经比当前最优解更差，就不继续往下走了
        if buses_taken >= best[0]:
            return
        # 所有经过 current_stop 的公交
        for bus in bus_of_stop.get(current_stop, []):
            if bus in visited_bus:
                continue                # 这辆公交已经坐过，跳过
            visited_bus.add(bus)         # 标记为已坐
            # 这辆公交的所有站点
            for nxt in routes[bus]:
                if nxt == target:        # 找到目标站，更新最小乘车次数
                    best[0] = min(best[0], buses_taken + 1)
                else:
                    dfs(nxt, buses_taken + 1)   # 继续往下走
            visited_bus.remove(bus)      # 回溯，撤销标记

    # 4️⃣ 从 source 开始搜索
    dfs(source, 0)

    return -1 if best[0] == float('inf') else best[0]
```

> **代码要点注释**  
> - `bus_of_stop.setdefault(stop, []).append(i)`：把每个站点映射到它所在的公交列表。  
> - `if source == target: return 0`：不需要坐公交，直接到达。  
> - `visited_bus` 防止在递归过程中出现环路（同一辆公交被重复使用）。  
> - `best` 用来记录当前找到的最小公交数，遇到更差的路径直接返回（剪枝）。

#### 复杂度  

- **时间复杂度**：`O(指数级)`（几乎是所有公交排列的组合），在最坏情况下会非常慢，实际只能通过极小的输入测试。  
- **空间复杂度**：`O(B + S)`，其中 `B` 为公交数量，`S` 为所有站点的总数，用于存哈希表和递归栈。

### 2. 最优解  

#### 思路  

暴力解的 **瓶颈** 在于我们在“公交层面”进行深度搜索，**每一次都要遍历所有站点**，导致大量重复工作。实际上，这道题可以抽象成 **在公交之间做图的遍历**，而不是在站点之间。

关键观察：

1. **同一辆公交内部的站点可以随意切换**，因为公交会不停循环。只要我们上了这辆公交，就等价于可以直接到达它经过的所有站点。  
2. 因此，**每辆公交本身可以看作图中的一个节点**。  
3. 两辆公交之间如果 **有公共站点**（即它们的路线有交集），我们就可以在这两个节点之间 **转乘**。这相当于在公交节点之间连一条无向边。  
4. 于是问题转化为：**从包含 `source` 的所有公交，最少需要经过多少个公交节点才能到达包含 `target` 的公交**？这正是 **最短路径**（层数最少）的求法，最自然的算法是 **广度优先搜索（BFS）**。

实现步骤（从零解释）：

- **步骤 1：构建站点 → 公交映射**  
  与暴力解相同，用哈希表把每个站点对应的公交列表记录下来。这里的哈希表相当于“一本查字典”，把站点（词）查到对应的公交编号（页码）。

- **步骤 2：初始化 BFS**  
  - 把所有**经过 `source` 的公交加入队列**，这些公交是我们 **第 1 层**（坐了 1 辆公交）。  
  - 同时建立 `visited_bus` 集合，防止同一辆公交被重复加入队列。  

- **步骤 3：层次遍历**  
  - 每弹出一个公交 `cur_bus`，检查它的所有站点 `stop`。  
  - 如果 `stop` 正好是 `target`，说明我们已经在第 `level` 层到达目标，返回 `level`。  
  - 否则，遍历 `stop` 所在的所有公交 `next_bus`（即可以在此站点换乘的公交）。如果 `next_bus` 还没有访问过，就加入队列，标记为已访问。  

- **步骤 4：结束条件**  
  - 队列空了仍未找到 `target`，说明不存在换乘方案，返回 `-1`。  

**为什么 BFS 能得到最少公交数？**  
BFS 按层次展开，先遍历所有只坐 **1 辆公交** 能到达的站点；再遍历所有坐 **2 辆公交** 能到达的站点……因此第一次碰到 `target` 时，必然是乘坐最少公交的那一层。

#### 代码（Python）

```python
from collections import deque, defaultdict
from typing import List

def numBusesToDestination(routes: List[List[int]], source: int, target: int) -> int:
    # 1️⃣ 特殊情况：出发点就是目标点
    if source == target:
        return 0

    # 2️⃣ 建立 “站点 → 公交列表” 的哈希表（字典）
    stop_to_buses = defaultdict(list)          # defaultdict 自动创建空列表
    for i, stops in enumerate(routes):
        for s in stops:
            stop_to_buses[s].append(i)

    # 3️⃣ BFS 初始化
    q = deque()                                 # 队列保存 (公交编号, 已坐公交数)
    visited_bus = set()                         # 已经坐过的公交
    visited_stop = set()                        # 已经遍历过的站点（可选，防止重复检查）

    # 把所有经过 source 的公交加入队列，乘坐第一辆公交的次数为 1
    for bus in stop_to_buses.get(source, []):
        q.append((bus, 1))
        visited_bus.add(bus)

    # 4️⃣ 开始层次遍历
    while q:
        cur_bus, buses_used = q.popleft()
        # 遍历当前公交的所有站点
        for stop in routes[cur_bus]:
            if stop == target:                   # 找到目标站点
                return buses_used
            # 防止同一个站点被重复展开（可选优化）
            if stop in visited_stop:
                continue
            visited_stop.add(stop)

            # 所有可以在该站点换乘的公交
            for next_bus in stop_to_buses[stop]:
                if next_bus not in visited_bus:
                    visited_bus.add(next_bus)
                    q.append((next_bus, buses_used + 1))

    # 5️⃣ 队列空了仍未找到目标，说明不可达
    return -1
```

**关键行中文注释**  

- `defaultdict(list)`：自动把不存在的键初始化为空列表，省去手动 `if key not in dict` 的判断。  
- `q.append((bus, 1))`：把所有可以直接上车的公交放进队列，已经坐了一辆。  
- `while q:`：BFS 主循环，按层次弹出公交。  
- `if stop == target:`：一旦遍历到的站点是目标，直接返回当前层数（坐的公交数）。  
- `visited_stop`：可选的站点访问集合，防止同一个站点多次导致重复的换乘检查，进一步降低常数时间。  
- `visited_bus.add(next_bus)`：标记已经坐过的公交，避免再次入队形成环。

#### 复杂度  

- **时间复杂度**：`O(N + E)`，其中  
  - `N` 为所有站点的总数（`sum(len(route))`），即遍历所有站点一次。  
  - `E` 为公交之间的换乘关系数量。每条换乘关系对应一次遍历 `stop_to_buses[stop]`。  
  由于每个公交和每个站点最多只会被访问一次，整体是线性级别。  
  用大白话说，就是 **只会走一遍所有的站点和所有的公交**，不会出现指数级的爆炸。  

- **空间复杂度**：`O(N + B)`，  
  - `N` 用于存哈希表 `stop_to_buses`（站点 → 公交列表）。  
  - `B` 用于 `visited_bus`（已坐公交集合）以及 BFS 队列。  
  总体上也就是所有输入数据的大小，属于线性空间。

## 心得  

- **核心技巧**：把“公交”当作图的节点，站点是连接节点的桥梁，使用 **广度优先搜索** 在公交图上寻找最短路径。  
- **适用的题型**：  
  1. **换乘类最少次数**（如地铁换乘、航班中转）。  
  2. **多层关系的最短路径**（如社交网络中的“度数”问题）。  
  3. **从集合到集合的最少步骤**（如 “单词接龙” 里把单词看作节点，单词间的相邻关系看作边）。  
- **一句话总结解题钥匙**：**把“能一起坐的站点”抽象成公交之间的边，用 BFS 按层数遍历，第一次碰到目标即是最少公交数**。

## 反思  

- **第一反应**：看到“重复的公交路线”“换乘”关键词，就想到把每辆公交当成一个 “状态”，尝试枚举所有乘车顺序（暴力递归）。  
- **最容易踩的坑**：  
  - 忘记在 `source == target` 时直接返回 `0`。  
  - 没有去重公交，导致同一辆公交被多次加入 BFS 队列，引起无限循环或时间超限。  
  - 对站点编号的范围没有做好限制，直接使用列表索引会导致内存爆炸（因为站点编号可达 `10⁶`），所以必须使用 **哈希表** 而不是大数组。  
- **下次遇到同类题的第一步**：先判断 **“把哪个实体抽象成图的节点”**（本题是公交），再构建 **节点之间的连边规则**（共享站点），最后用 **BFS** 求最短层数。这样可以直接跳过暴力搜索的指数爆炸。
