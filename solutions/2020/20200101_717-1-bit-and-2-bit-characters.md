# #717. 1-bit 和 2-bit 字符 / 1-bit and 2-bit Characters

> 难度：简单 · 标签：Array · [LeetCode 链接](https://leetcode.com/problems/1-bit-and-2-bit-characters/)

---

## 题目（英文原版）

**Description**

We have two special characters:
Given a binary array bits that ends with 0, return true if the last character must be a one-bit character.

**Examples**

**Example 1:**

```
Input: bits = [1,0,0]
Output: true
Explanation: The only way to decode it is two-bit character and one-bit character.
So the last character is one-bit character.
```

**Example 2:**

```
Input: bits = [1,1,1,0]
Output: false
Explanation: The only way to decode it is two-bit character and two-bit character.
So the last character is not one-bit character.
```

**Constraints**

- 1 <= bits.length <= 1000
- bits[i] is either 0 or 1.

---

## 题目（中文翻译）

我们有两种特殊字符：

- 1-bit 字符可以用单个 `0` 表示。  
- 2-bit 字符可以用 `10` 或 `11` 表示。

给定一个以 `0` 结尾的二进制数组 `bits`，如果最后一个字符必须是 **1-bit 字符**（即只能解码为单个 `0`），返回 `true`，否则返回 `false`。

## 示例

### 示例 1
**输入:** `bits = [1,0,0]`  
**输出:** `true`  
**解释:** 唯一的解码方式是先得到一个 2-bit 字符 `10`，再得到一个 1-bit 字符 `0`。因此最后一个字符是 1-bit 字符。

### 示例 2
**输入:** `bits = [1,1,1,0]`  
**输出:** `false`  
**解释:** 唯一的解码方式是先得到一个 2-bit 字符 `11`，再得到另一个 2-bit 字符 `10`。所以最后一个字符不是 1-bit 字符。

## 约束条件

- `1 <= bits.length <= 1000`
- `bits[i]` 只能是 `0` 或 `1`。

---

## 解题过程  

### 1. 直觉解（暴力）  

#### 思路  
最直接的想法是：**把所有可能的解码方式都枚举出来**，只要有一种解码方式使得最后一个字符恰好是 `0`（即 1‑bit），就返回 `True`。  
- **数据结构**：我们可以用递归（或显式的栈）来模拟“从左到右”一步步划分字符。递归的参数只需要当前所在的下标 `i`。  
- **为什么正确**：递归会尝试两种合法的划分方式  
  1. 把 `bits[i]` 当成 1‑bit（只能在 `bits[i]==0` 时） → 前进一步  
  2. 把 `bits[i]` 与 `bits[i+1]` 当成 2‑bit（只能在 `bits[i]==1` 时） → 前进两步  
  只要能走到数组最后且恰好在 **倒数第一个位置**（也就是 `len(bits)-1`）结束，说明最后一定是 1‑bit。  
- **时间/空间复杂度**：  
  - 最坏情况下，每一步都有两种选择（当 `bits[i]==1` 时只能走两步，但在 `0` 时只能走一步），递归树的高度是 `n`，所以可能的路径数是指数级的，记作 `O(2^n)`。这在实际中会导致超时。  
  - 递归调用会占用栈空间，深度最坏为 `n`，即 `O(n)` 的额外空间。  

> **大白话**：把这道题想成“在一条路上走，你可以走一步（0）或两步（10/11），问能不能恰好在终点前一步停下来”。如果把所有走法都列出来检查，显然会花很多时间。

#### 代码（Python）  

```python
from typing import List

def is_one_bit_bruteforce(bits: List[int]) -> bool:
    n = len(bits)

    # 递归函数：从下标 i 开始，能否恰好在倒数第一个位置结束
    def dfs(i: int) -> bool:
        # 已经走到数组末尾但没有正好停在倒数第一个位置 → 失败
        if i == n:
            return False
        # 正好停在倒数第一个位置 → 成功（说明最后是 1‑bit）
        if i == n - 1:
            return bits[i] == 0   # 必须是单独的 0 才算 1‑bit

        # 当前是 0 → 只能当作 1‑bit，向前走一步
        if bits[i] == 0:
            return dfs(i + 1)

        # 当前是 1 → 必须和后面的位组成 2‑bit，向前走两步
        # 注意这里要先确保 i+1 不越界，题目保证 bits 以 0 结尾，所以这里安全
        return dfs(i + 2)

    return dfs(0)
```

#### 复杂度  

- **时间复杂度**：`O(2^n)`（指数级）——因为在最坏情况下会尝试所有可能的划分路径。  
- **空间复杂度**：`O(n)`——递归栈的深度最多等于数组长度。

### 2. 最优解  

#### 思路  
暴力解的瓶颈在于**“枚举所有可能”**，其实我们并不需要列出所有路径，只要**按照题目给出的唯一合法划分规则**一次遍历即可判断。  
- **关键观察**：  
  - 当遇到 `0` 时，它只能单独形成 1‑bit，**必须**向前走一步。  
  - 当遇到 `1` 时，它一定和后面的下一位组成 2‑bit，**必须**向前走两步。  
  这意味着划分方式是唯一的，没有分支。只要从左到右按照上述规则前进，最后落在的位置就决定了答案。  
- **实现方式**：使用一个指针 `i` 表示“下一个字符的起始下标”。  
  - 循环条件是 `i < len(bits) - 1`，因为我们只关心**倒数第二位之前**的走向。  
  - 若 `bits[i] == 0`，`i += 1`；若 `bits[i] == 1`，`i += 2`。  
- 当循环结束时，`i` 要么正好等于 `len(bits) - 1`（说明最后一个字符是单独的 `0`），要么已经越过它（说明最后是 2‑bit 的一部分）。  

> **类比**：把数组想成一条路，路上有两种标记：绿灯（0）只能走一步，红灯（1）必须跨过下一个路段一起走两步。我们只要沿着标记一步步走，根本不需要试探所有走法。  

#### 代码（Python）  

```python
from typing import List

def is_one_bit_character(bits: List[int]) -> bool:
    """
    Greedy 一次遍历判断最后一个字符是否一定是 1‑bit。
    """
    i = 0                # 下一个字符的起始下标
    n = len(bits)

    # 只遍历到倒数第二个位置，确保不会越界读取 bits[i+1]
    while i < n - 1:
        if bits[i] == 0:   # 0 → 只能是 1‑bit
            i += 1
        else:              # 1 → 必须和后面的位组成 2‑bit
            i += 2

    # 循环结束时，如果 i 正好指向最后一个下标，说明最后是独立的 0（1‑bit）
    return i == n - 1
```

#### 复杂度  

- **时间复杂度**：`O(n)`——只遍历一次数组，`n` 为数组长度。  
  - 与暴力解相比，时间从指数级降到了线性级，几乎可以在瞬间完成。  
- **空间复杂度**：`O(1)`——只用了常数个额外变量（指针 `i`），不随输入规模增长。

## 心得  

- **核心技巧**：**贪心遍历 + 唯一划分规则**。当每一步的选择是唯一的（这里由 `0` 或 `1` 决定），就可以直接线性扫描得到答案。  
- **适用的题型**：  
  1. “解码方式唯一” 的字符划分题（如 LeetCode 1051: *Height Checker* 的类似思路）。  
  2. 按规则一步步移动的指针题（如 “跳跃游戏 I” 的贪心解）。  
  3. 需要判断最后一步是否落在特定位置的序列题（如 “判断是否是有效的括号序列” 的栈式线性扫描）。  
- **一句话总结**：**只要每一步的决定唯一，就用一次遍历把指针走到终点，最后指针落在哪儿就决定答案**。

## 反思  

- **第一反应**：看到“二进制数组只能被 0 或 10/11 划分”，立刻想到“枚举所有划分”。这会导致暴力递归，复杂度爆炸。  
- **最容易踩的坑**：  
  - 忘记题目保证数组以 `0` 结尾，导致在 `bits[i]==1` 时访问 `bits[i+1]` 越界。  
  - 循环条件写成 `i < n`，在处理 `1` 时会多走一步，错误地判断最后是 1‑bit。  
- **下次类似题的第一步**：先检查**每一步的选择是否唯一**。如果唯一，就可以直接用**指针/贪心**一次遍历求解；如果不唯一，再考虑 DP 或回溯。
