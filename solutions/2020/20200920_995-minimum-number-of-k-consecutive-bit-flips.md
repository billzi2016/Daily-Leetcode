# #995. 最小连续 K 位翻转次数 / Minimum Number of K Consecutive Bit Flips

> 难度：困难 · 标签：Array、Bit Manipulation、Queue、Sliding Window、Prefix Sum · [LeetCode 链接](https://leetcode.com/problems/minimum-number-of-k-consecutive-bit-flips/)

## 题目（英文原版）

**Description**

You are given a binary array nums and an integer k.
A k-bit flip is choosing a subarray of length k from nums and simultaneously changing every 0 in the subarray to 1, and every 1 in the subarray to 0.
Return the minimum number of k-bit flips required so that there is no 0 in the array. If it is not possible, return -1.
A subarray is a contiguous part of an array.

**Examples**

**Example 1:**

```
Input: nums = [0,1,0], k = 1
Output: 2
Explanation: Flip nums[0], then flip nums[2].
```

**Example 2:**

```
Input: nums = [1,1,0], k = 2
Output: -1
Explanation: No matter how we flip subarrays of size 2, we cannot make the array become [1,1,1].
```

**Example 3:**

```
Input: nums = [0,0,0,1,0,1,1,0], k = 3
Output: 3
Explanation: 
Flip nums[0],nums[1],nums[2]: nums becomes [1,1,1,1,0,1,1,0]
Flip nums[4],nums[5],nums[6]: nums becomes [1,1,1,1,1,0,0,0]
Flip nums[5],nums[6],nums[7]: nums becomes [1,1,1,1,1,1,1,1]
```

**Constraints**

- 1 <= nums.length <= 105
- 1 <= k <= nums.length

## 题目（中文翻译）

给定一个二进制数组（binary array）`nums` 和一个整数 `k`。  
**k 位翻转**（k-bit flip）指的是从 `nums` 中选择长度为 `k` 的一个子数组（subarray），并同时把子数组中的每个 `0` 变为 `1`，每个 `1` 变为 `0`。  
返回使数组中不再出现 `0` 所需的最小 k 位翻转次数。如果无法实现，返回 `-1`。  

子数组是数组的一个连续片段（contiguous part）。

### 示例

**示例 1**  
输入: `nums = [0,1,0]`, `k = 1`  
输出: `2`  
解释: 先翻转 `nums[0]`，再翻转 `nums[2]`。

**示例 2**  
输入: `nums = [1,1,0]`, `k = 2`  
输出: `-1`  
解释: 无论如何翻转长度为 2 的子数组，都无法使数组变为 `[1,1,1]`。

**示例 3**  
输入: `nums = [0,0,0,1,0,1,1,0]`, `k = 3`  
输出: `3`  
解释:  
- 翻转 `nums[0]、nums[1]、nums[2]` 后，数组变为 `[1,1,1,1,0,1,1,0]`  
- 翻转 `nums[4]、nums[5]、nums[6]` 后，数组变为 `[1,1,1,1,1,0,0,0]`  
- 翻转 `nums[5]、nums[6]、nums[7]` 后，数组变为 `[1,1,1,1,1,1,1,1]`

### 约束条件

- `1 <= nums.length <= 10^5`
- `1 <= k <= nums.length`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**遍历数组，从左到右，每遇到一个 0 就把以它为左端点、长度为 `k` 的子数组全部翻转**。  
因为翻转只能一次性同时改变 `k` 个连续位，若当前位置是 0，唯一能把它变成 1 的办法就是在这里开始一次 `k` 位翻转。  

- **使用的数据结构**：普通的 Python 列表 `nums`。我们直接在原数组上做“翻转”，相当于把每个元素的值取反（0↔1），这就像把灯的开关从关变成开、从开变成关一样。
- **为什么正确**：如果我们从左到右依次处理，已经处理过的左边位置再也不会被后面的翻转影响（因为后面的翻转窗口已经全部在右侧），所以只要在当前位置看到 0，就必须立刻翻转，否则它永远无法被纠正。  
- **时间/空间复杂度**：  
  - 对每个位置我们可能要遍历 `k` 个元素去翻转，最坏情况是数组全是 0，遍历 `n` 次，每次翻转 `k` 次，时间复杂度是 **O(n·k)**。  
  - 只使用了原数组本身，没有额外的显著空间，空间复杂度是 **O(1)**。  

> 大白话解释：如果 `n = 10⁵`，`k = 5·10⁴`，那么 `n·k` 可能会达到 5·10⁹ 次操作，电脑根本跑不完，这就是暴力解的“慢点”。

#### 代码（Python）

```python
def minKBitFlips_bruteforce(nums, k):
    """
    暴力解：从左到右遍历，一旦遇到 0，就在当前位置做一次长度为 k 的翻转
    """
    n = len(nums)
    flips = 0                       # 记录翻转次数

    for i in range(n):
        # 如果当前位置已经是 0，需要翻转
        if nums[i] == 0:
            # 如果剩余长度不足 k，说明无法完成翻转，直接返回 -1
            if i + k > n:
                return -1
            # 对长度为 k 的子数组逐个取反
            for j in range(i, i + k):
                nums[j] ^= 1          # 0 变 1，1 变 0（异或 1）
            flips += 1

    return flips
```

#### 复杂度

- **时间复杂度**：`O(n·k)`  
  直观上就是“数组长度 × 每次翻转的长度”。如果 `k` 接近 `n`，相当于每次都遍历几乎整个数组，算起来非常慢。
- **空间复杂度**：`O(1)`  
  只用了几个整数变量，没额外开辟大块空间。

### 2. 最优解

#### 思路  

从暴力解可以看到，**瓶颈在于每次翻转都要遍历 `k` 个元素**。我们需要一种方式，**在 O(1) 时间内知道当前位置到底受到了多少次翻转的影响**，而不是真的去把每个元素一个个改。

##### 关键观察  
- 翻转是“取反”操作，**奇数次翻转等价于一次翻转，偶数次翻转等价于不翻转**。  
- 当我们在位置 `i` 开始一次长度为 `k` 的翻转时，它的影响会一直持续到位置 `i + k - 1`，之后就不再影响后面的元素。

这正好可以用**滑动窗口**或**前缀和**的思想来记录。我们维护一个“当前累计的翻转次数” `cur_flip`，它表示从左边走到当前位置，已经被翻转了多少次（只关心奇偶）。  

实现方式有两种：

1. **差分数组 + 前缀和**  
   - 用一个长度为 `n+1` 的辅助数组 `diff`，当在位置 `i` 开始翻转时，`diff[i] += 1`，`diff[i+k] -= 1`。遍历时累计 `cur_flip += diff[i]`，即可得到当前位置的累计翻转次数。  
2. **队列（或双指针）**  
   - 用一个队列记录所有翻转的起始位置。当遍历到 `i` 时，若队列头的起始位置已经超出窗口（`i - queue[0] >= k`），就把它弹出，表示这次翻转已经不再影响当前位置。队列的长度就是 `cur_flip`。

这里我们采用 **队列**（实际上可以用 `collections.deque`），因为思路更直观，且只需要 O(1) 的额外空间（队列最多保存 `k` 个起始位置）。

##### 步骤细化

1. 初始化 `flips = 0`（翻转次数）和空队列 `q = deque()`（保存每次翻转的左端点）。  
2. 从左到右遍历数组下标 `i`：  
   - 如果队列不为空且 `i - q[0] >= k`，说明最早的翻转已经离开当前窗口，弹出队首。  
   - 此时 `len(q)` 表示截至当前位置已经进行了多少次翻转（奇偶决定当前位实际值）。  
   - 计算**实际值**：如果 `len(q) % 2 == 0`，则实际值就是原始 `nums[i]`；否则实际值是取反的 `1 - nums[i]`。  
   - 若实际值是 0，说明需要在这里再翻转一次：  
     - 检查 `i + k > n`，如果超出数组长度，返回 -1（不可行）。  
     - 将 `i` 加入队列 `q.append(i)`，`flips += 1`。  
3. 遍历结束后，`flips` 即为最少翻转次数。

##### 为什么是最优的？

- 每个下标只会进入队列一次、弹出一次，**总操作次数是线性的 O(n)**。  
- 队列只保存当前窗口内的起始位置，最多 `k` 个，**额外空间是 O(k) ≤ O(n)**，在最坏情况下仍是线性，但相对于原数组已经是常数级的额外开销。

##### 类比帮助理解

想象你在走一条路，路上有若干“翻转灯泡”的开关。每当你打开一个开关，它会影响接下来 `k` 米的灯光状态。你手里有一张纸记录所有已经打开的开关位置。当你走到第 `i` 米时，只需要检查纸上最近的 `k` 米内有多少开关被打开（奇数还是偶数），决定此时灯是亮还是灭。如果灯是灭（对应数组中的 0），你必须在这里再打开一个新开关（即翻转），否则灯永远不会亮。

#### 代码（Python）

```python
from collections import deque

def minKBitFlips(nums, k):
    """
    最优解：使用队列记录翻转的起始位置，实现 O(n) 时间、O(k) 空间
    """
    n = len(nums)
    q = deque()          # 保存每一次翻转的左端点
    flips = 0            # 统计翻转次数

    for i in range(n):
        # 1️⃣ 移除已经离开窗口的翻转
        if q and i - q[0] >= k:
            q.popleft()  # 最早的翻转已经不再影响当前位置

        # 2️⃣ 判断当前位置的实际值
        #   - 若 q 长度为偶数，说明当前位被翻转了偶数次，保持原样
        #   - 若 q 长度为奇数，说明被翻转了奇数次，需要取反
        cur = nums[i]
        if len(q) % 2 == 1:      # 奇数次翻转 → 取反
            cur ^= 1

        # 3️⃣ 若实际值是 0，需要在这里再翻转一次
        if cur == 0:
            # 检查窗口是否还能完整放下长度为 k 的子数组
            if i + k > n:
                return -1        # 无法完成翻转，返回 -1
            q.append(i)          # 记录这次翻转的左端点
            flips += 1

    return flips
```

#### 复杂度

- **时间复杂度**：`O(n)`  
  每个元素最多进入队列一次、弹出一次，所有操作都是常数时间。相比暴力解的 `O(n·k)`，这里把“每次翻 `k` 个”这一步省掉了，真正只遍历一次数组。
- **空间复杂度**：`O(k)`（最坏 `O(n)`）  
  队列里只保存当前窗口内的翻转起点，最多 `k` 个。若 `k` 接近 `n`，空间上等价于 `O(n)`，但这已经是额外的线性空间，且在实际运行中通常远小于 `n`。

## 心得

- **核心技巧**：**滑动窗口 + 差分/队列**，用于在 O(1) 时间内维护“区间翻转的累计影响”。  
- **适用的题型**：  
  1. **“翻转子数组”** 类问题，如 “Minimum Number of K Consecutive Bit Flips”。  
  2. **区间增减** 类问题，例如 “Range Addition Queries”。  
  3. **窗口内计数/求和** 类问题，如 “Maximum Consecutive Ones III”。  
- **一句话总结解题钥匙**：**把“每次翻 k 位”转化为“记录翻转起点”，用队列或差分数组在遍历时即时知道当前位置到底被翻了几次**。

## 反思

- **第一反应**：看到 “把 0 变成 1，子数组长度固定”，立刻想到“从左到右遇到 0 就翻”。这就是暴力思路。  
- **最容易踩的坑**：  
  - **边界检查**：当剩余元素不足 `k` 时仍尝试翻转会导致数组越界，需要提前返回 `-1`。  
  - **翻转次数的奇偶性**：忘记取模 2 判断奇偶，会导致实际值判断错误。  
  - **队列/差分的及时清理**：如果不在遍历时弹出已经失效的翻转，会错误累计影响，导致结果偏大。  
- **下次遇到同类题**：第一步先思考 **“如何在 O(1) 时间内知道当前位置受到了多少区间操作的影响？”**，如果能用差分或滑动窗口记录起点，就往最优方向逼近。
