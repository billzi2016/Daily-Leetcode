# #851. **富有且安静** / Loud and Rich

> 难度：中等 · 标签：Array、Depth-First Search、Graph、Topological Sort · [LeetCode 链接](https://leetcode.com/problems/loud-and-rich/)

## 题目（英文原版）

**Description**

There is a group of n people labeled from 0 to n - 1 where each person has a different amount of money and a different level of quietness.
You are given an array richer where richer[i] = [ai, bi] indicates that ai has more money than bi and an integer array quiet where quiet[i] is the quietness of the ith person. All the given data in richer are logically correct (i.e., the data will not lead you to a situation where x is richer than y and y is richer than x at the same time).
Return an integer array answer where answer[x] = y if y is the least quiet person (that is, the person y with the smallest value of quiet[y]) among all people who definitely have equal to or more money than the person x.

**Examples**

**Example 1:**

```
Input: richer = [[1,0],[2,1],[3,1],[3,7],[4,3],[5,3],[6,3]], quiet = [3,2,5,4,6,1,7,0]
Output: [5,5,2,5,4,5,6,7]
Explanation: 
answer[0] = 5.
Person 5 has more money than 3, which has more money than 1, which has more money than 0.
The only person who is quieter (has lower quiet[x]) is person 7, but it is not clear if they have more money than person 0.
answer[7] = 7.
Among all people that definitely have equal to or more money than person 7 (which could be persons 3, 4, 5, 6, or 7), the person who is the quietest (has lower quiet[x]) is person 7.
The other answers can be filled out with similar reasoning.
```

**Example 2:**

```
Input: richer = [], quiet = [0]
Output: [0]
```

**Constraints**

- n == quiet.length
- 1 <= n <= 500
- 0 <= quiet[i] < n
- All the values of quiet are unique.
- 0 <= richer.length <= n * (n - 1) / 2
- 0 <= ai, bi < n
- ai != bi
- All the pairs of richer are unique.
- The observations in richer are all logically consistent.

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

我们把每个人看成图中的一个节点，`richer[i] = [a, b]` 表示 **a 比 b 更有钱**，于是可以在图里画一条有向边 `b → a`（从较穷的人指向较富的人）。  
> 类比：想象一张“谁比谁有钱”的关系图，边的方向就像“向上爬楼梯”，每走一步就会变得更富。

对于某个人 `x`，题目要求在**所有一定比 `x` 有钱的**人（包括 `x` 本身）里，找出 **最安静**（`quiet` 最小）的那个人的编号 `y`。  
最直接的办法就是：

1. **遍历**：从 `x` 出发，沿着 `b → a` 的方向深度优先搜索（DFS）或广度优先搜索（BFS），把所有能到达的节点全部收集起来，这些节点就是“肯定比 `x` 更有钱”的人。
2. **线性扫描**：在收集到的集合里，挑出 `quiet` 最小的那个节点 `y`，把它记在答案数组 `answer[x]` 中。

把上面的过程对每个 `x (0 … n‑1)` 都做一遍，就得到完整答案。

> 为什么一定对？  
> 因为图中所有的 “更有钱” 关系已经通过 `richer` 给出，且题目保证这些关系不冲突（没有环），所以从 `x` 能走到的所有节点，恰好对应所有**必然**比 `x` 更有钱的人。

#### 代码（Python）

```python
from collections import defaultdict, deque
from typing import List

def loudAndRich_bruteforce(richer: List[List[int]], quiet: List[int]) -> List[int]:
    n = len(quiet)

    # 建立邻接表：poorer -> richer
    # 就像“谁可以往上爬到更有钱的人”
    graph = defaultdict(list)
    for a, b in richer:          # a richer than b
        graph[b].append(a)       # b can go to a

    answer = [0] * n

    for x in range(n):
        # BFS 收集所有比 x 更有钱的人（包括 x 本身）
        visited = [False] * n
        q = deque([x])
        visited[x] = True
        richer_people = []        # 这里会存放所有可达的节点

        while q:
            cur = q.popleft()
            richer_people.append(cur)   # 记下当前可达的人
            for nxt in graph[cur]:      # 继续往更富的方向走
                if not visited[nxt]:
                    visited[nxt] = True
                    q.append(nxt)

        # 在线性扫描中找 quiet 最小的那个人
        best = richer_people[0]
        for person in richer_people:
            if quiet[person] < quiet[best]:
                best = person
        answer[x] = best

    return answer
```

#### 复杂度  

- **时间复杂度**：`O(n * (n + m))`  
  - `n` 是人数，`m` 是 `richer` 的条数。对每个 `x` 都要一次完整的 BFS，最坏情况下 BFS 会遍历全部节点和所有边，所以是 `O(n + m)`，再乘以 `n` 次得到 `O(n·(n+m))`。  
  - 用大白话说，就是 **“每个人都要遍历整张图一次”**，如果人数是 500，最坏会是 500 × 500 ≈ 25 万 次操作，已经够慢了。

- **空间复杂度**：`O(n + m)`  
  - `graph` 存储所有边，需要 `O(m)`，每次 BFS 需要 `O(n)` 的 `visited` 数组和队列。

### 2. 最优解

#### 思路  

从暴力解可以看到 **瓶颈在于重复遍历**：不同的起点 `x` 会走到很多相同的子图，导致大量冗余工作。  
我们需要 **记住** 已经算好的结果，后面再需要时直接复用——这正是**记忆化搜索（DFS + DP）**的思想。

关键观察：

1. **图是有向无环的（DAG）**  
   题目保证 “更有钱” 的关系不会自相矛盾，所以不存在环。  
   在 DAG 中，如果我们已经知道了某个节点 `u` 的答案（即在 `u` 以及所有比 `u` 更富的人中最安静的那个人），那么它的所有**更穷**的邻居 `v`（即 `v → u` 的边）在计算自己的答案时，只需要把 `u` 的答案和自己比较即可。

2. **从富到穷的拓扑顺序**  
   如果我们把边的方向保持为 `b → a`（穷 → 富），那么对每个节点 `x`，所有比 `x` 更富的节点一定在 `x` 的 **后继**（后面）出现。  
   因此我们可以 **自底向上**（从富到穷）进行 DFS，递归返回当前子树（即“比我更富的所有人”）里最安静的人的编号。

3. **记忆化**  
   用一个数组 `answer` 记录每个人的最终答案。第一次计算时执行 DFS 并把结果存进去，后面再遇到同一个节点直接返回，避免重复遍历。

实现步骤：

- 建立邻接表 `graph[b].append(a)`（穷 → 富）。
- 定义递归函数 `dfs(x)`，返回 `answer[x]`：
  1. 初始答案设为自己 `x`（因为自己也算在“至少和自己一样有钱”之列）。
  2. 对每个直接更富的邻居 `y`，递归得到 `dfs(y)`（即 `y` 以及更富的人的最安静者）。
  3. 用 `quiet` 比较 `answer[x]` 与 `answer[y]`，把更安静的那个人保存为 `answer[x]`。
- 主函数遍历所有 `x`，若 `answer[x]` 仍为 `-1`（未计算），就调用 `dfs(x)`。

> 类比：把每个人想象成一个**楼层**，楼层之间有“只能往上走（更富）”的电梯。我们从最顶层往下查，每层只需要看自己和上面已经算好的最安静的人，谁更安静谁就是答案。

#### 代码（Python）

```python
from collections import defaultdict
from typing import List

def loudAndRich(richer: List[List[int]], quiet: List[int]) -> List[int]:
    n = len(quiet)

    # 建图：穷 -> 富
    graph = defaultdict(list)
    for a, b in richer:          # a richer than b
        graph[b].append(a)       # b can go to a (upward)

    answer = [-1] * n             # -1 表示还没算过

    # 记忆化 DFS
    def dfs(x: int) -> int:
        """返回在 x 以及所有比 x 更富的人中 quiet 最小的人的编号"""
        if answer[x] != -1:       # 已经算过，直接返回
            return answer[x]

        # 先把自己设为最安静的候选
        best = x
        # 遍历所有直接更富的邻居
        for richer_person in graph[x]:
            cand = dfs(richer_person)   # 递归得到 richer_person 的最安静者
            # 如果候选人的 quiet 更小，就更新 best
            if quiet[cand] < quiet[best]:
                best = cand
        answer[x] = best
        return best

    # 对每个人都确保调用一次 dfs（有的可能已经在递归中被算过）
    for i in range(n):
        if answer[i] == -1:
            dfs(i)

    return answer
```

#### 复杂度  

- **时间复杂度**：`O(n + m)`  
  - 每个节点 `x` 只会被 `dfs` 计算一次，递归遍历所有出边（即所有 `richer` 关系）。因此总的访问次数等于节点数 `n` 加上边数 `m`。  
  - 与暴力解相比，从“每个人都遍历整张图”降到了“每条边只走一次”，快了很多。

- **空间复杂度**：`O(n + m)`  
  - `graph` 仍然需要存储所有边 `O(m)`。  
  - 递归栈最深不超过 DAG 的最长路径长度，最坏为 `O(n)`，再加上 `answer` 数组 `O(n)`，总体仍是 `O(n + m)`。

## 心得

- **核心技巧**：**记忆化深度优先搜索**（DFS + DP）在有向无环图（DAG）上求“传递闭包”类的问题非常高效。  
- **适用的题型**  
  1. **“最小/最大属性传递”**：如 LeetCode 2050 *Parallel Courses II*（求最早完成时间）  
  2. **“祖先/后代属性查询”**：如 1138 *Alphabet Board Path*（在有向图中传递信息）  
  3. **“拓扑序 + DP”**：如 2100 *Find Good Days to Rob the Bank*（连续递增/递减序列）  

> **一句话总结**：在 DAG 上，只要把“已经算好的子问题”记住，后面的查询就能 O(1) 复用——这把“暴力遍历全图”变成了“一遍遍历所有边”。

## 反思

- **拿到题目第一反应**：先画图，把 `richer` 当成有向边，想象要在每个人的“上游”找最安静的那个人。于是自然想到 BFS/DFS 暴力遍历。  
- **最容易踩的坑**  
  1. **边的方向搞错**：`[a, b]` 表示 `a` 更富，遍历时必须从 **穷 → 富**（`b → a`），否则会向错误方向搜索。  
  2. **忘记把自己也算进候选集合**：答案可能就是本人（如示例 2），所以初始化 `best = x` 很重要。  
  3. **递归深度**：虽然 `n ≤ 500` 不会导致栈溢出，但如果不使用记忆化会导致大量重复递归，导致超时。  

- **下次遇到同类题，第一步该想到**：  
  1. 把关系抽象成 **有向无环图**。  
  2. 判断是否可以 **自底向上**（从子节点/后继得到信息），并尝试 **记忆化 DFS** 或 **拓扑 DP**。
