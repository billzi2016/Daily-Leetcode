# #816. 模糊坐标 / Ambiguous Coordinates

> 难度：中等 · 标签：String、Backtracking、Enumeration · [LeetCode 链接](https://leetcode.com/problems/ambiguous-coordinates/)

---

## 题目（英文原版）

**Description**

We had some 2-dimensional coordinates, like "(1, 3)" or "(2, 0.5)". Then, we removed all commas, decimal points, and spaces and ended up with the string s.
Return a list of strings representing all possibilities for what our original coordinates could have been.
Our original representation never had extraneous zeroes, so we never started with numbers like "00", "0.0", "0.00", "1.0", "001", "00.01", or any other number that can be represented with fewer digits. Also, a decimal point within a number never occurs without at least one digit occurring before it, so we never started with numbers like ".1".
The final answer list can be returned in any order. All coordinates in the final answer have exactly one space between them (occurring after the comma.)

**Examples**

**Example 1:**

```
Input: s = "(123)"
Output: ["(1, 2.3)","(1, 23)","(1.2, 3)","(12, 3)"]
```

**Example 2:**

```
Input: s = "(0123)"
Output: ["(0, 1.23)","(0, 12.3)","(0, 123)","(0.1, 2.3)","(0.1, 23)","(0.12, 3)"]
Explanation: 0.0, 00, 0001 or 00.01 are not allowed.
```

**Example 3:**

```
Input: s = "(00011)"
Output: ["(0, 0.011)","(0.001, 1)"]
```

**Constraints**

- 4 <= s.length <= 12
- s[0] == '(' and s[s.length - 1] == ')'.
- The rest of s are digits.

## 题目（中文翻译）

我们有一些二维坐标，例如 `"(1, 3)"` 或 `"(2, 0.5)"`。随后，我们去掉了所有的逗号（comma）、小数点（decimal point）和空格（space），得到字符串 `s`。  
返回一个字符串列表，列出所有可能的原始坐标（coordinate）形式。

原始的表示中绝不出现多余的前导或尾随零，因此不会出现诸如 `"00"`、`"0.0"`、`"0.00"`、`"1.0"`、`"001"`、`"00.01"` 或其他可以用更少字符表示的数字。  
此外，数字内部的小数点（decimal point）前必须至少有一位数字，所以不会出现类似 `".1"` 的情况。

答案列表的顺序任意。最终答案中的每个坐标（coordinate）在逗号（comma）后恰好有一个空格（space）。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**把所有可能的逗号和小数点都枚举一遍**，只要拼出来的字符串满足题目对“不能有多余的 0”的限制，就把它加入答案。

1. 先把最外层的括号去掉，得到只包含数字的子串 `num`（比如 `"(123)" → "123"`）。  
2. 在 `num` 中任选一个位置插入逗号，把它分成左边 `A`、右边 `B` 两段（逗号左边一定是 x 坐标，右边是 y 坐标）。  
3. 对每一段（比如 `A`），再把 **小数点** 插入任意位置（包括不插），得到所有可能的数的写法。  
   - 小数点左边必须至少有一位数字，不能出现形如 `.1` 的情况。  
   - 不能出现前导零（除非数字本身就是单个 `0`），也不能出现小数点后多余的零（比如 `1.0`、`0.00` 都不行）。  
4. 把左边所有合法写法和右边所有合法写法两两组合，形成坐标 `(x, y)`，加入答案。

> **生活化类比**：  
> 把字符串看成一串珠子，逗号像一根剪刀，把珠子分成两串；小数点像一颗特殊的珠子，可以插在任意位置（甚至不插）。我们要把所有合法的“珠子串+特殊珠子”的组合挑出来。

**为什么这个方法一定能得到所有答案？**  
因为题目只说原始坐标在去掉逗号和小数点后得到当前的字符串。只要我们把逗号和小数点放回去的所有可能性都尝试一遍，就不会漏掉任何一种原始坐标。

**复杂度分析（大白话）**  
- 假设 `n` 是去掉括号后的数字长度（`4 ≤ n ≤ 10`）。  
- 逗号可以插在 `n-1` 个位置。  
- 对每段长度为 `k` 的子串，最多有 `k` 种放小数点的方式（包括不放）。  
- 所以最坏情况下的组合数约为 `O((n-1) * n * n) = O(n³)`，因为我们要对左、右两段各枚举 `O(n)` 种写法再两两配对。  
- 空间上，只需要保存答案列表和临时的几段字符串，都是 `O(1)`（不计答案本身）。

#### 代码（Python）

```python
def ambiguousCoordinates(s: str):
    # 去掉最外层的 '(' 和 ')'
    num = s[1:-1]                 # 例: "(123)" -> "123"
    n = len(num)
    ans = []

    # -------------------------------------------------
    # 生成一段字符串的所有合法数值写法
    # -------------------------------------------------
    def gen_candidates(part: str):
        """返回 part 可以合法出现的所有形式（整数或小数）"""
        res = []
        m = len(part)

        # 1) 整数形式（不加小数点）
        # 只能是单个 '0' 或者首位不为 '0' 的多位数
        if part == "0" or part[0] != "0":
            res.append(part)

        # 2) 小数形式：在 i (1~m-1) 位置插入小数点，形成 part[:i] + "." + part[i:]
        # 需要满足：左边不能有前导零，右边不能以 '0' 结尾
        for i in range(1, m):          # 小数点左边至少 1 位
            left, right = part[:i], part[i:]
            # 左边若有前导零且长度 > 1，则非法（如 "01.2"）
            if left[0] == "0" and len(left) > 1:
                continue
            # 右边若以 '0' 结尾，则非法（如 "1.20"）
            if right[-1] == "0":
                continue
            res.append(left + "." + right)
        return res

    # -------------------------------------------------
    # 主循环：枚举逗号位置，分别生成左、右候选，然后两两配对
    # -------------------------------------------------
    for i in range(1, n):               # 逗号左侧长度为 i，右侧为 n-i
        left_part, right_part = num[:i], num[i:]

        left_candidates = gen_candidates(left_part)
        right_candidates = gen_candidates(right_part)

        # 两两组合
        for l in left_candidates:
            for r in right_candidates:
                ans.append(f"({l}, {r})")

    return ans
```

#### 复杂度

- **时间复杂度**：`O(n³)`  
  - `n` 为去掉括号后数字的长度。  
  - 逗号有 `n-1` 种选法；每段最多产生 `O(n)` 种合法写法；两段组合是乘法，所以整体是立方级别。  
  - 对于本题的约束（`n ≤ 10`），实际运行非常快。

- **空间复杂度**：`O(1)`（不计答案列表）  
  - 只用了常数个临时字符串和列表来存放每段的候选写法。

### 2. 最优解

#### 思路  

从暴力解可以看到，**真正的瓶颈并不是枚举逗号位置**（那只有 `n-1` 种），而是**对每段产生所有合法数值的过程**。如果我们能在产生候选时直接剔除所有不合法的写法，就不需要后续再做过滤。

关键点：

1. **前导零规则**  
   - 整数只能是单个 `0` 或者首位不为 `0` 的多位数。  
   - 小数点左侧如果有前导零，只能是单个 `0`（即形如 `0.xxx`），否则非法。  

2. **尾随零规则**  
   - 小数点右侧不能以 `0` 结尾（否则可以去掉小数点或多余的零）。  

3. **一次生成所有合法写法**  
   - 对长度为 `k` 的子串，合法写法只有两类：  
     - **整数**（满足前导零规则）  
     - **小数**：把小数点放在每个可能的位置，只要左侧满足前导零规则且右侧不以 `0` 结尾，就一定合法。  
   - 这一步的复杂度是 `O(k)`，而不是 `O(2^k)`（如果我们尝试所有“放或不放”组合的话）。  

于是，整体时间仍然是 `O(n²)`（逗号 `n` 种 × 每段候选 `O(n)`），比暴力的 `O(n³)` 稍微好一些，而且实现更简洁。因为 `n` 本身很小，这两种写法在实际运行时差别不大，但从**算法思维**的角度来看，这才是“最优”。

> **类比**：  
> 想象我们在拼装一块拼图，暴力解相当于把每块小拼图都随意翻转、切割后再尝试组合；最优解则是先把每块拼图裁剪成只可能拼进去的形状，再去拼装，省去了大量无用的尝试。

#### 代码（Python）

```python
def ambiguousCoordinates(s: str):
    num = s[1:-1]                     # 去掉外层括号
    n = len(num)
    ans = []

    # ---------- 只产生合法数值的函数 ----------
    def build(part: str):
        """返回 part 所有符合题目规则的写法（整数或小数）"""
        m = len(part)
        res = []

        # 整数形式：只能是 "0" 或者首位不为 '0'
        if part == "0" or part[0] != "0":
            res.append(part)

        # 小数形式：遍历小数点插入位置 i (1~m-1)
        # 左边不能出现前导零（除非左边本身就是 "0"），右边不能以 0 结尾
        for i in range(1, m):
            left, right = part[:i], part[i:]
            # 左边如果是多位且以 '0' 开头，则非法（如 "01.2"）
            if left[0] == "0" and len(left) > 1:
                continue
            # 右边若以 '0' 结尾，则非法（如 "1.20"）
            if right[-1] == "0":
                continue
            res.append(left + "." + right)
        return res

    # ---------- 主循环 ----------
    for i in range(1, n):                 # 逗号左侧长度 i
        left, right = num[:i], num[i:]
        left_cand = build(left)
        right_cand = build(right)

        for l in left_cand:
            for r in right_cand:
                ans.append(f"({l}, {r})")

    return ans
```

#### 复杂度

- **时间复杂度**：`O(n²)`  
  - 逗号有 `n-1` 种；对每段长度至多 `n`，生成候选的过程是线性的 `O(n)`，两段配对仍是乘法，所以总体是二次级别。  
  - 与暴力的 `O(n³)` 相比，省去了一次遍历所有小数点插入的“冗余检查”。

- **空间复杂度**：`O(1)`（不计答案列表）  
  - 只使用常数级的临时列表来存放每段的候选写法。

## 心得

- **核心技巧**：**枚举分割点 + 受约束的数值生成**。  
  - 通过把“不能有前导零”和“不能有尾随零”的规则提前写进生成函数，避免了大量无效的组合。  

- **该技巧适用的题型**  
  1. **恢复原始字符串**：如 LeetCode 816 *Ambiguous Coordinates*、943 *Find the Shortest Superstring*（枚举拼接顺序）。  
  2. **合法数字或时间的恢复**：如 1410 *HTML Entity Parser*（解析实体）或 271 *Encode and Decode Strings*（分段恢复）。  

- **一句话总结解题钥匙**：  
  > **“先把每段数字合法化，再两两配对”**——把所有不合法的候选直接剔除，剩下的自然就是答案。

## 反思

- **第一反应**：看到题目直接想到“把逗号和小数点全枚举”，于是写了最笨的暴力代码。  
- **最容易踩的坑**  
  - **前导零**：`"00"`、`"01"` 等必须排除。  
  - **小数点后零**：`"1.0"`、`"0.00"` 都不合法。  
  - **单独的 `0`**：只能保持为整数 `0`，不能写成 `0.` 或 `.0`。  
  - **边界**：字符串最短为 4（形如 `"(11)"`），需要保证循环下标不越界。  

- **下次遇到同类题**，第一步应该先**明确所有合法/非法的规则**，并把这些规则写进**候选生成函数**，这样后面的枚举就能保持高效、简洁。
