# #1005. **K 次取反后数组和的最大化** / Maximize Sum Of Array After K Negations

> 难度：简单 · 标签：Array、Greedy、Sorting · [LeetCode 链接](https://leetcode.com/problems/maximize-sum-of-array-after-k-negations/)

## 题目（英文原版）

**Description**

Given an integer array nums and an integer k, modify the array in the following way:
You should apply this process exactly k times. You may choose the same index i multiple times.
Return the largest possible sum of the array after modifying it in this way.

**Examples**

**Example 1:**

```
Input: nums = [4,2,3], k = 1
Output: 5
Explanation: Choose index 1 and nums becomes [4,-2,3].
```

**Example 2:**

```
Input: nums = [3,-1,0,2], k = 3
Output: 6
Explanation: Choose indices (1, 2, 2) and nums becomes [3,1,0,2].
```

**Example 3:**

```
Input: nums = [2,-3,-1,5,-4], k = 2
Output: 13
Explanation: Choose indices (1, 4) and nums becomes [2,3,-1,5,4].
```

**Constraints**

- 1 <= nums.length <= 104
- -100 <= nums[i] <= 100
- 1 <= k <= 104

## 题目（中文翻译）

给定一个整数数组 `nums` 和一个整数 `k`，请按照以下方式修改数组：

- 必须恰好执行 **k 次取反（negation）** 操作。每一次，你可以选择任意下标 `i`（同一下标可以被选择多次），并将 `nums[i]` 变为其相反数 `-nums[i]`。

返回在完成上述操作后，数组可能得到的 **最大和**。

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**把所有可能的翻转方案都穷举一遍**，然后取其中和最大的那种。  
- 这里的“翻转”指把数组中某个位置的数 `x` 变成 `-x`（负号前后翻转）。  
- 由于题目要求恰好进行 `k` 次操作，而同一个下标可以被多次选择，所以一次完整的操作序列可以用长度为 `k` 的下标序列表示，例如 `[1, 3, 1]` 表示先翻转下标 1，再翻转下标 3，最后再翻转下标 1。  
- 暴力做法就是 **递归**（或深度优先搜索）枚举所有可能的下标序列，然后在每条叶子节点上计算数组的和，保存最大值。

> **类比**：把这个过程想象成在一本字典里找所有可能的拼写组合。字典的每一页对应一个数组下标，而我们要把每一页都可能翻开 `k` 次，记录下来并比较哪种组合得到的“总分”最高。

**为什么它是正确的？**  
因为我们没有遗漏任何一种合法的操作顺序，所有可能的结果都被检查了一遍，所以最大和一定会被找到。

**时间/空间分析（大白话）**  
- 每一步都有 `n` 种选择，连续做 `k` 步，就会产生 `n × n × … × n = n^k` 种不同的操作序列。  
- 对每条序列我们要遍历整个数组一次来求和，时间复杂度是 `O(n)`。于是总体时间是 `O(n^{k+1})`，这在实际中几乎不可接受（即使 `n=10`、`k=5` 也会有 10⁵ 条分支）。  
- 递归栈的深度为 `k`，额外的空间复杂度是 `O(k)`（保存递归状态）。  

#### 代码（Python）  

```python
from copy import deepcopy

def largest_sum_bruteforce(nums, k):
    """
    暴力递归枚举所有可能的 k 次翻转方案，返回最大和
    """
    n = len(nums)
    best = -float('inf')                 # 记录全局最大和

    def dfs(step, cur_nums):
        """
        step : 已经完成了多少次翻转
        cur_nums : 当前数组状态（会被修改）
        """
        nonlocal best
        if step == k:                     # 已经完成 k 次，计算和
            cur_sum = sum(cur_nums)
            best = max(best, cur_sum)
            return

        # 对每一个下标尝试一次翻转
        for i in range(n):
            cur_nums[i] = -cur_nums[i]    # 翻转一次
            dfs(step + 1, cur_nums)       # 继续往下搜索
            cur_nums[i] = -cur_nums[i]    # 恢复现场，回溯

    dfs(0, deepcopy(nums))                # 使用 deepcopy 防止外部数组被破坏
    return best
```

> 代码里每一行都有中文注释，帮助你快速定位关键操作。  

#### 复杂度  

- **时间复杂度**：`O(n^{k+1})`  
  - “`n` 的 `k+1` 次方”可以理解为：每一次翻转都有 `n` 种选择，且在每条完整路径上我们还要遍历一次数组求和。  
- **空间复杂度**：`O(k)`（递归栈深度）

### 2. 最优解  

#### 思路  

从暴力解可以看到，**瓶颈在于枚举所有可能的翻转顺序**。我们其实并不需要关心**顺序**，只需要关心**每个数最终是正还是负**，因为求和时顺序已经不影响结果。  

**关键观察**  

1. **负数越多，翻成正数越能提升总和**。  
   - 把 `-5` 变成 `5`，数组和增加了 `10`（即 `2*5`），而把 `+5` 变成 `-5` 则会把和降低 `10`。  
   - 因此我们应该先把尽可能大的负数（绝对值大）翻成正数。  

2. **如果还有剩余的翻转次数**（即 `k` 仍大于 0），  
   - 再次翻转同一个数会把它恢复原状，等价于“消耗掉”两次操作。  
   - 所以 **只要 `k` 为偶数，剩余的翻转可以两两抵消，对最终和没有影响**。  
   - 关键是 **当 `k` 为奇数时**，我们必须再翻转 **一次**，此时应当选 **绝对值最小的数**（不管它是正是负），因为这会让和的损失最小。  

**由此得到的贪心策略**  

1. 将数组按**从小到大**排序（负数会排在前面）。  
2. 从左到右遍历，遇到负数且还有剩余的 `k`，就把它翻转为正数，同时 `k -= 1`。  
3. 这一步结束后，数组中可能仍有未被翻转的负数（因为 `k` 用完了），或者全部变成了非负数。  
4. 计算此时数组的 **最小绝对值** `min_abs`（可以在遍历时同步记录）。  
5. 如果 `k` 仍是 **奇数**，则再把 `min_abs` 对应的数翻转一次（即在总和上减去 `2 * min_abs`）。  

> **类比**：想象你手里有若干块重量不同的石头（负数是“向下压”的石头），你可以把它们翻面（变成正数）来减轻整体重量。先把最重的负石头翻过去最能减轻重量；剩下的翻面次数如果是偶数，就相当于你把同一块石头翻了两次，最终没有变化；如果是奇数，就只能把最轻的那块石头翻一次，影响最小。  

#### 代码（Python）  

```python
def largest_sum(nums, k):
    """
    贪心 + 排序
    1. 先把尽可能多的负数翻成正数
    2. 若还有剩余且为奇数，则把绝对值最小的数再翻一次
    """
    # 1. 排序，让所有负数排在前面，且绝对值大的负数排在左侧
    nums.sort()                         # O(n log n)

    # 2. 翻转负数
    for i in range(len(nums)):
        if k == 0:                      # 已经没有翻转次数了，直接结束
            break
        if nums[i] < 0:                 # 负数可以翻成正数提升和
            nums[i] = -nums[i]
            k -= 1                      # 用掉一次操作

    # 3. 计算当前数组的和以及最小绝对值
    total = 0
    min_abs = float('inf')
    for v in nums:
        total += v
        if abs(v) < min_abs:
            min_abs = abs(v)

    # 4. 若剩余操作次数为奇数，需要再翻转一次最小绝对值的数
    if k % 2 == 1:                      # 只在奇数时才需要额外翻转
        total -= 2 * min_abs            # 翻转一次相当于在和上减去两倍的绝对值

    return total
```

> 代码每一步都配有中文注释，帮助你对应到思路的每个要点。  

#### 复杂度  

- **时间复杂度**：`O(n log n)`  
  - 排序是主要耗时，`n` 为数组长度。后面的遍历都是线性的。  
  - 与暴力解相比，`log n` 只比 `n` 稍微多一点，而不是指数级的爆炸。  

- **空间复杂度**：`O(1)`（不计排序本身的原地实现）  
  - 只用了若干个额外的整数变量，未额外开辟与 `n` 成正比的存储。

## 心得  

- **核心技巧**：**贪心 + 排序**，先把对答案贡献最大的负数翻正，再利用“奇偶性”处理剩余操作。  
- **适用的题型**（类似思路）  
  1. **“最大化数组和”** 系列，如 *“最大化数组和的 K 次翻转”*（本题）。  
  2. **“最小化数组绝对差”**，需要把负数先转正再考虑剩余次数的奇偶。  
  3. **“分配资源使收益最大”**，常用把收益最大的项目先做的贪心策略。  
- **一句话总结**：**把能立刻提升和的负数先翻，剩下的次数只看奇偶，奇数时再翻最小的数**。

## 反思  

- **第一反应**：看到“把数组里某个数取负”，立刻想到**遍历所有可能的取负组合**。  
- **最容易踩的坑**  
  - **忘记处理 k 为奇数的情况**：只翻完所有负数后，若还有一次单独的翻转，需要选择绝对值最小的数。  
  - **边界条件**：全部为非负数或全部为负数时，仍然要考虑 `k` 的奇偶性。  
  - **排序后未更新最小绝对值**：翻转负数后，最小绝对值可能变了，需要在最终遍历中重新统计。  
- **下次遇到同类题**，第一步应该想到**“先把对目标最有帮助的元素处理掉”**（这里是负数），随后**检查剩余操作的奇偶性**来决定是否还需要额外的微调。
