# #1114. 按顺序打印 / Print in Order

> 难度：简单 · 标签：Concurrency · [LeetCode 链接](https://leetcode.com/problems/print-in-order/)

---

## 题目（英文原版）

**Description**

Suppose we have a class:
The same instance of Foo will be passed to three different threads. Thread A will call first(), thread B will call second(), and thread C will call third(). Design a mechanism and modify the program to ensure that second() is executed after first(), and third() is executed after second().
Note:
We do not know how the threads will be scheduled in the operating system, even though the numbers in the input seem to imply the ordering. The input format you see is mainly to ensure our tests' comprehensiveness.

**Examples**

**Example 1:**

```
public class Foo {
  public void first() { print("first"); }
  public void second() { print("second"); }
  public void third() { print("third"); }
}
```

**Example 2:**

```
Input: nums = [1,2,3]
Output: "firstsecondthird"
Explanation: There are three threads being fired asynchronously. The input [1,2,3] means thread A calls first(), thread B calls second(), and thread C calls third(). "firstsecondthird" is the correct output.
```

**Example 3:**

```
Input: nums = [1,3,2]
Output: "firstsecondthird"
Explanation: The input [1,3,2] means thread A calls first(), thread B calls third(), and thread C calls second(). "firstsecondthird" is the correct output.
```

**Constraints**

- nums is a permutation of [1, 2, 3].

## 题目（中文翻译）

**描述**  
假设我们有如下类：

```java
class Foo {
    // 将会被三个不同的线程调用同一个 Foo 实例
    // 线程 A 调用 first()
    // 线程 B 调用 second()
    // 线程 C 调用 third()
}
```

相同的 `Foo` 实例会被三个不同的线程共享。线程 A 调用 `first()`，线程 B 调用 `second()`，线程 C 调用 `third()`。请设计一种同步机制并修改程序，使得 `second()` 必须在 `first()` 之后执行，`third()` 必须在 `second()` 之后执行。

**注意**  
我们无法预知操作系统会如何调度这些线程，即使输入中的数字看似暗示了调用顺序。示例中的输入格式主要用于确保测试的全面性。

**示例 1**

```java
public class Foo {
    public void first() { print("first"); }
    public void second() { print("second"); }
    public void third() { print("third"); }
}
```

**示例 2**

- 输入: `nums = [1,2,3]`
- 输出: `"firstsecondthird"`
- 解释: 有三个线程被异步启动。输入 `[1,2,3]` 表示线程 A 调用 `first()`，线程 B 调用 `second()`，线程 C 调用 `third()`。正确的输出应为 `"firstsecondthird"`。

**示例 3**

- 输入: `nums = [1,3,2]`
- 输出: `"firstsecondthird"`
- 解释: 输入 `[1,3,2]` 表示线程 A 调用 `first()`，线程 B 调用 `third()`，线程 C 调用 `second()`。正确的输出仍然是 `"firstsecondthird"`。

**约束条件**

- `nums` 是 `[1, 2, 3]` 的一个排列。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

这道题的核心是 **让三个线程按照固定顺序执行**，但我们并不知道操作系统会把这三个线程怎么调度。  
最直接、最笨的想法是让每个线程 **不停地检查前一个线程是否已经完成**，如果没有完成就一直等（**自旋等待**）。  

> 类比：想象你在排队买票，前面的人还没买完，你只能一直站在原地不动，等前面的人买完才轮到你。这里的“前面的人是否买完”相当于一个共享的标记（比如一个全局变量），所有线程都可以看到它。

实现上我们可以：

1. 用两个全局布尔变量 `first_done`、`second_done` 表示前面的函数是否已经执行完毕，初始都是 `False`。  
2. `first()` 直接执行并把 `first_done` 设为 `True`。  
3. `second()` 进入一个 `while not first_done: pass` 的循环（自旋），等到 `first_done` 为 `True` 再执行自己的业务，并把 `second_done` 设为 `True`。  
4. `third()` 同理，用 `while not second_done: pass` 等待。

**为什么正确**  
- 只要前面的标记最终会被置为 `True`（因为对应的线程一定会跑到并执行），后面的线程一定会在某个时刻跳出自旋循环，继续执行。  
- 标记的修改是原子的（在 CPython 中对布尔值的赋值是原子的），所以不会出现“同时读到旧值”的竞争问题。

**时间/空间复杂度**  
- 时间复杂度：**O(∞)**（理论上可能无限等待）。在最坏情况下，如果调度极端不利，`second`、`third` 可能会在自旋循环里耗费大量 CPU 时间。  
- 空间复杂度：**O(1)**，只用了常数个布尔变量。

> 大白话解释：`O(1)` 表示不管输入有多大（这里永远是 3），我们占用的内存都几乎不变；`O(∞)` 说明这种做法在实际运行时会让 CPU 做很多无意义的循环，效率极低。

#### 代码（Python）

```python
import threading
import time

# ---------- 暴力版（自旋等待） ----------
class Foo:
    def __init__(self):
        # 两个标记，记录前面的函数是否已经执行完
        self.first_done = False
        self.second_done = False

    def first(self, printFirst):
        """printFirst 是一个函数，调用后会输出 'first'"""
        printFirst()
        # 标记 first 已完成
        self.first_done = True

    def second(self, printSecond):
        """一直自旋等到 first_done 为 True"""
        while not self.first_done:          # 自旋等待
            time.sleep(0.001)               # 稍微让出 CPU，防止完全占满
        printSecond()
        self.second_done = True

    def third(self, printThird):
        """一直自旋等到 second_done 为 True"""
        while not self.second_done:         # 自旋等待
            time.sleep(0.001)
        printThird()


# ------------------- 测试 -------------------
def test_brutal():
    foo = Foo()

    def run_first():
        foo.first(lambda: print("first", end=''))

    def run_second():
        foo.second(lambda: print("second", end=''))

    def run_third():
        foo.third(lambda: print("third", end=''))

    # 随机打乱线程启动顺序，模拟 OS 调度的随机性
    threads = [
        threading.Thread(target=run_second),
        threading.Thread(target=run_third),
        threading.Thread(target=run_first),
    ]
    for t in threads:
        t.start()
    for t in threads:
        t.join()
    print()   # 换行

# test_brutal()   # 运行后会得到 "firstsecondthird"
```

> 关键行中文注释已经写在代码里。`time.sleep(0.001)` 只是为了让自旋稍微友好一点，实际在真正的“暴力”实现里可以去掉。

#### 复杂度

- **时间复杂度**：`O(∞)`（实际运行时间取决于调度，最坏会出现长时间自旋）。
- **空间复杂度**：`O(1)`（只用了两个布尔变量）。

### 2. 最优解

#### 思路  

从暴力解可以看到，**瓶颈在于自旋等待**：线程不停地检查标记，浪费大量 CPU。  
我们需要一种 **“有人完成后自动通知别人”** 的机制，而不是让别人不停地去看。  

Python 标准库提供了多种线程同步工具，最符合本题需求的是：

| 同步工具 | 类比 | 适用场景 |
|----------|------|----------|
| `threading.Event` | 像广播的闹钟，一旦被叫响，所有在等它的线程都会被唤醒 | “等某件事发生后继续执行”。 |
| `threading.Semaphore` | 像有固定名额的厕所，只有获得名额才能进去 | 控制资源访问次数。 |
| `threading.Lock` / `Condition` | 像排队的门卫，只有持有钥匙才能进去 | 互斥或更复杂的等待/通知。 |

本题只需要 **“先后顺序”**，最简洁的做法是使用 **两个 `Event`**：

1. `event_first_done`：`first()` 执行完后 `set()`，表示“第一步已经完成”。  
2. `event_second_done`：`second()` 执行完后 `set()`，表示“第二步已经完成”。  

`second()` 在开始工作前调用 `event_first_done.wait()`，这会让它 **阻塞**（睡眠）直到 `first()` 把事件设为已触发。  
同理，`third()` 在开始前等待 `event_second_done`。  
**阻塞** 与 **自旋** 的区别在于：阻塞的线程会让出 CPU，操作系统会在事件触发时把它重新调度回来，省电又高效。

> 类比：把“前面的人已经买完票”这个信息写在一个大屏幕上（Event），后面的人只需要盯着屏幕看，一旦亮起就立刻去买票，而不是一直在门口原地打转。

**正确性**  
- `first()` 必然最先调用 `event_first_done.set()`，所以 `second()` 的 `wait()` 一定会在某个时刻返回。  
- 同理，`second()` 完成后会触发 `event_second_done`，`third()` 的 `wait()` 也一定会返回。  
- 由于每个 `wait()` 都是 **阻塞** 的，线程不会提前执行自己的业务，从而保证了严格的执行顺序。

**复杂度分析**  
- 时间复杂度：**O(1)**。每个函数只做一次常数时间的工作（打印 + `set`），等待本身不算耗时（它是系统调度的睡眠）。  
- 空间复杂度：**O(1)**。只用了两个 `Event` 对象，大小固定。

#### 代码（Python）

```python
import threading

# ---------- 最优解（Event） ----------
class Foo:
    def __init__(self):
        # 两个 Event，用来“广播”前置步骤完成的信号
        self.first_done = threading.Event()
        self.second_done = threading.Event()

    def first(self, printFirst):
        """
        printFirst: 一个函数，调用后会输出 'first'
        """
        printFirst()
        # 通知 second() 可以开始了
        self.first_done.set()          # 把事件状态设为已触发

    def second(self, printSecond):
        """
        等待 first() 完成后再执行
        """
        self.first_done.wait()         # 阻塞，直到 first_done 被 set
        printSecond()
        # 通知 third() 可以开始了
        self.second_done.set()

    def third(self, printThird):
        """
        等待 second() 完成后再执行
        """
        self.second_done.wait()        # 阻塞，直到 second_done 被 set
        printThird()


# ------------------- 测试 -------------------
def test_optimal():
    foo = Foo()

    def run_first():
        foo.first(lambda: print("first", end=''))

    def run_second():
        foo.second(lambda: print("second", end=''))

    def run_third():
        foo.third(lambda: print("third", end=''))

    # 随机打乱启动顺序，模拟操作系统的任意调度
    threads = [
        threading.Thread(target=run_third),
        threading.Thread(target=run_first),
        threading.Thread(target=run_second),
    ]
    for t in threads:
        t.start()
    for t in threads:
        t.join()
    print()   # 换行

# test_optimal()   # 运行后会得到 "firstsecondthird"
```

> 关键行已经加了中文注释。`Event.wait()` 会让当前线程**睡眠**，等到对应的 `set()` 被调用后才会被系统唤醒继续执行。

#### 复杂度

- **时间复杂度**：`O(1)` — 每个函数只做常数次操作，不会因为等待而增加额外的“计算时间”。  
- **空间复杂度**：`O(1)` — 只用了两个 `Event`，占用的内存固定不变。

## 心得

- **核心技巧**：使用 **线程同步原语（Event）** 实现“先后顺序”。  
- **适用场景**：  
  1. 多线程按固定顺序执行的题目（如 LeetCode 1114 `Print in Order`）。  
  2. 需要“某一步完成后才能继续”的生产者‑消费者模型（如 `threading.Condition` 的使用）。  
  3. 多阶段流水线任务（每个阶段必须等前一阶段完成才能启动）。  
- **一句话总结**：**把“前置完成”写成一个信号（Event），让后面的线程等信号再跑**。

## 反思

- **第一反应**：先想到用共享变量配合自旋等待，因为最直接能想到“检查标记”。  
- **最容易踩的坑**：  
  - **忘记线程安全**：直接使用普通变量而不加锁，在某些解释器或 CPU 上可能出现竞态。  
  - **自旋导致 CPU 飙升**：在真实系统里自旋会把 CPU 用光，导致程序卡死。  
  - **忘记 `set()`**：如果忘记在前一步调用 `set()`，后面的 `wait()` 会永远阻塞。  
- **下次类似题的第一步**：先在脑海里把“顺序”抽象成 **“信号”**，思考是否有 **Event / Semaphore / Condition** 能把信号传递给后面的线程，而不是让后面的线程不停地轮询。这样可以快速定位到最合适的同步工具，从而写出高效且易读的代码。
