# #1013. 划分数组为和相等的三部分 / Partition Array Into Three Parts With Equal Sum

> 难度：简单 · 标签：Array、Greedy · [LeetCode 链接](https://leetcode.com/problems/partition-array-into-three-parts-with-equal-sum/)

---

## 题目（英文原版）

**Description**

Given an array of integers arr, return true if we can partition the array into three non-empty parts with equal sums.
Formally, we can partition the array if we can find indexes i + 1 < j with (arr[0] + arr[1] + ... + arr[i] == arr[i + 1] + arr[i + 2] + ... + arr[j - 1] == arr[j] + arr[j + 1] + ... + arr[arr.length - 1])

**Examples**

**Example 1:**

```
Input: arr = [0,2,1,-6,6,-7,9,1,2,0,1]
Output: true
Explanation: 0 + 2 + 1 = -6 + 6 - 7 + 9 + 1 = 2 + 0 + 1
```

**Example 2:**

```
Input: arr = [0,2,1,-6,6,7,9,-1,2,0,1]
Output: false
```

**Example 3:**

```
Input: arr = [3,3,6,5,-2,2,5,1,-9,4]
Output: true
Explanation: 3 + 3 = 6 = 5 - 2 + 2 + 5 + 1 - 9 + 4
```

**Constraints**

- 3 <= arr.length <= 5 * 104
- -104 <= arr[i] <= 104

---

## 题目（中文翻译）

给定一个整数数组 `arr`，如果能够将数组划分为 **三个非空部分**（non‑empty parts），并且这三部分的元素之和相等，则返回 `true`。

形式化地说，若存在满足 `i + 1 < j` 的索引 `i`、`j`，使得  

```
(arr[0] + arr[1] + ... + arr[i]) 
== (arr[i + 1] + arr[i + 2] + ... + arr[j - 1]) 
== (arr[j] + arr[j + 1] + ... + arr[arr.length - 1])
```

则可以完成划分。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把数组里所有可能的切分点枚举出来，然后检查每一种切法是否满足“三段和相等”。  
具体做法：

1. 先遍历 `i`（第一个分界点），`i` 必须在 `0 … n‑3` 之间，因为每段都要非空。  
2. 再遍历 `j`（第二个分界点），`j` 必须在 `i+2 … n‑2` 之间，同理每段都要留出至少一个元素。  
3. 对每一对 `(i, j)`，分别求出三段的和：  

   - 左段 `arr[0 … i]`  
   - 中段 `arr[i+1 … j‑1]`  
   - 右段 `arr[j … n‑1]`  

   看这三个和是否相等，若相等立刻返回 `True`。

> **类比**：把数组想象成一本书的章节，`i`、`j` 就是我们在目录里挑的两个章节分界线。我们把每个章节的页码相加，看三章的页数是否相同。

为什么正确？因为我们穷举了**所有**合法的分界点组合，只要有一种能满足条件，必然会在枚举过程中被发现。

#### 代码（Python）

```python
def canThreePartsEqualSum_bruteforce(arr):
    n = len(arr)
    # i 为左段最后一个元素的下标，j 为右段第一个元素的下标
    for i in range(n - 2):                 # 左段至少留一个元素，右段同理
        left_sum = sum(arr[:i + 1])        # 计算左段和
        for j in range(i + 2, n - 1):      # 中段至少一个元素，右段至少一个元素
            mid_sum = sum(arr[i + 1:j])    # 计算中段和
            right_sum = sum(arr[j:])       # 计算右段和
            if left_sum == mid_sum == right_sum:
                return True
    return False
```

- `sum(arr[:i + 1])`、`sum(arr[i + 1:j])`、`sum(arr[j:])` 分别对应左、中、右三段的和。  
- 每次循环都重新遍历一次子数组，代码虽然简洁，却很耗时。

#### 复杂度

- **时间复杂度：** `O(n³)`（最坏情况下每一次 `i`、`j` 再遍历一次子数组求和）。  
  - 大白话：如果数组长度是 1000，程序大约要做 1000 × 1000 × 1000 ≈ **10⁹** 次加法，几乎不可能在秒级内跑完。
- **空间复杂度：** `O(1)`，只用了常数级别的额外变量。

> 为了稍微降低一点点时间，我们可以先算出前缀和数组，这样每次求子段和只需要 `O(1)`，整体时间会降到 `O(n²)`，但仍然不够好。下面我们来看看最优解。

---

### 2. 最优解

#### 思路  

从暴力解可以看出，**瓶颈**在于我们对每个 `(i, j)` 都要重新计算子段的和。  
如果事先把数组的前缀和（从左到右累计的和）记录下来，那么任意区间 `[l, r]` 的和只需要一次减法就能得到。  

进一步思考：

1. 若能把数组划分为三段等和，则 **整体和一定能被 3 整除**。设整体和为 `total`，每段的目标和就是 `target = total / 3`。  
2. 当我们从左往右累加时，一旦累计到 `target`，就找到了第一段的右端 `i`。  
3. 继续往右累加，当累计到 `2 * target` 时，就找到了第二段的右端 `j-1`（即第二段结束的位置），此时剩下的元素自然构成第三段，且它的和必然是 `target`（因为总和是 `3 * target`）。  
4. 关键是：**第一段和第二段的结束位置必须都在数组的内部**，也就是说 `i` 不能是最后一个元素，`j` 也不能是最后一个元素。

于是我们只需一次遍历：

- 先检查 `total % 3 != 0` → 直接返回 `False`。  
- 用一个变量 `curr` 累计前缀和。  
- 当 `curr == target` 时记录已经找到第一段（只记录一次即可）。  
- 当 `curr == 2 * target` 且已经找到了第一段且当前位置不是最后一个元素时，说明可以划分成功，返回 `True`。  

> **类比**：把总和想象成一条长绳子，要把它平均分成三段。先把绳子从左边慢慢拉，第一次恰好拉出 `target` 长度时，标记第一刀；继续拉，第二次恰好达到 `2*target` 时，标记第二刀。只要第二刀没有在绳子末端，三段就自动等长了。

#### 代码（Python）

```python
def canThreePartsEqualSum(arr):
    """
    返回是否可以把数组划分为和相等的三段（每段非空）
    思路：一次遍历 + 前缀和
    """
    total = sum(arr)                 # 整体和
    if total % 3 != 0:               # 不能被 3 整除，直接否定
        return False

    target = total // 3               # 每段应当的和
    curr = 0                          # 当前前缀和
    first_found = False               # 是否已经找到第一段

    # 遍历到倒数第二个元素即可（因为右侧必须留至少一个元素）
    for i in range(len(arr) - 1):
        curr += arr[i]                # 累加到当前位置

        # 第一次恰好等于 target，标记第一段结束
        if not first_found and curr == target:
            first_found = True
            # 继续往后找第二段，不必立即返回

        # 当累计到 2*target 且已经找到第一段，说明可以划分成功
        elif first_found and curr == 2 * target:
            # 这里 i 仍然不是最后一个元素，右侧必然非空
            return True

    # 循环结束仍未找到合适的切点
    return False
```

- `total // 3` 使用整数除法，确保 `target` 为整数（因为数组元素都是整数）。  
- 循环只跑到 `len(arr)-1`，防止第二段结束在数组最后，导致第三段为空。  

#### 复杂度

- **时间复杂度：** `O(n)` —— 只需要一次线性遍历。  
  - 大白话：如果数组有 10⁵ 个元素，程序只会做 10⁵ 次加法和几次比较，几乎是瞬间完成。
- **空间复杂度：** `O(1)` —— 只用了常数级别的几个变量（`total、target、curr、first_found`），不随 `n` 增长。

> 与暴力解相比，时间从 **指数级** 降到了 **线性级**，在实际面试和线上评测中几乎是唯一可接受的方案。

## 心得

- **核心技巧**：**前缀和 + 整体和可被 3 整除的判定**。先把整体约束抽出来，再在一次遍历中寻找两个切点。
- **适用的题型**  
  1. “把数组划分为 k 段和相等” （如 LeetCode 1121 Split Array Into Three Subarrays）  
  2. “寻找子数组和等于给定值” （如 560 Subarray Sum Equals K）  
  3. “前缀和+哈希表” 类的均分问题（如 523 Continuous Subarray Sum）

- **一句话总结解题钥匙**：  
  “先把整体约束算出来，再用一次前缀遍历把目标和逐步敲出。”

## 反思

- **第一反应**：直接想遍历所有切点，写出三层循环（暴力）检查每段和是否相等。  
- **最容易踩的坑**  
  - 忘记检查 **每段必须非空**，导致把最后一个元素当成第二段结束点，返回错误的 `True`。  
  - 整体和为负数或包含零时，仍然需要 `total % 3 == 0`，不能只判断正数。  
  - 使用浮点除法导致精度误差，务必使用整数除法 `//`（因为题目保证整数）。  
- **下次遇到同类题**：第一步先看 **整体约束**（总和能否被目标段数整除），随后 **一次遍历** 用前缀和寻找切点，而不是直接暴力枚举。这样思路清晰、实现简洁、效率最高。
