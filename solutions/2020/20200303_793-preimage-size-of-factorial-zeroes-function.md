# #793. 阶乘尾部零的逆像大小 / Preimage Size of Factorial Zeroes Function

> 难度：困难 · 标签：Math、Binary Search · [LeetCode 链接](https://leetcode.com/problems/preimage-size-of-factorial-zeroes-function/)

## 题目（英文原版）

**Description**

Let f(x) be the number of zeroes at the end of x!. Recall that x! = 1 * 2 * 3 * ... * x and by convention, 0! = 1.
Given an integer k, return the number of non-negative integers x have the property that f(x) = k.

**Examples**

**Example 1:**

```
Input: k = 0
Output: 5
Explanation: 0!, 1!, 2!, 3!, and 4! end with k = 0 zeroes.
```

**Example 2:**

```
Input: k = 5
Output: 0
Explanation: There is no x such that x! ends in k = 5 zeroes.
```

**Example 3:**

```
Input: k = 3
Output: 5
```

**Constraints**

- 0 <= k <= 109

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**枚举所有可能的 x**，把每个 x 的阶乘末尾零的个数算出来，和给定的 `k` 对比，统计相等的次数。  

- **数据结构**：只需要一个普通的整数变量来记录当前枚举到的 `x`，以及一个函数 `trailingZeroes(x)` 来返回 `x!` 末尾有多少个 `0`。  
  - 这里可以把 `trailingZeroes` 想象成**查字典**：词（`x`）对应的定义是“`x!` 中有多少个 5 的因子”。  
- **正确性**：因为我们把 **所有** 非负整数 `x` 都检查了一遍，只要有 `f(x)=k`，一定会被计数到。  

但是这显然**不可行**：

- `k` 的取值上限是 `10^9`，对应的 `x` 大约在 `5·k` 量级（因为每 5 个数会贡献一个零），也就是上百亿甚至更多。  
- 直接算 `x!` 的阶乘根本不可能，甚至只算零的个数也要遍历 `x` 次。

#### 代码（Python）

```python
def trailingZeroes(x: int) -> int:
    """返回 x! 末尾有多少个 0（即 5 的因子个数）"""
    cnt = 0
    # 每次除以 5，累加商，就是 5 的因子总数
    while x:
        x //= 5          # 类似“查字典”把 x 换成它的 5 的倍数
        cnt += x
    return cnt


def preimageSizeFZF_bruteforce(k: int) -> int:
    """暴力枚举（会超时，仅作思路展示）"""
    ans = 0
    x = 0
    # 假设我们枚举到一个足够大的上界，这里随便写了 10**6
    while x <= 10**6:
        if trailingZeroes(x) == k:
            ans += 1
        x += 1
    return ans
```

#### 复杂度  

- **时间复杂度**：`O(upper_bound * log_{5}(upper_bound))`  
  - `upper_bound` 代表我们假设的最大 `x`（如果真的遍历到 `10^9`，时间会是 **上百亿次**）。  
  - `log_{5}(x)` 是每次求零的个数时的循环次数（因为每次除以 5）。  
- **空间复杂度**：`O(1)`，只用了常数个变量。  

显然，暴力解在本题的约束下根本不可行。

### 2. 最优解

#### 思路  

从暴力解可以看到：

1. **单调性**：`f(x) = trailingZeroes(x)` 随着 `x` 增大而**不下降**（因为更大的 `x` 包含了之前的所有因子 5）。  
2. **跳跃**：`f(x)` 并不是每次都只加 1，某些 `x`（比如 `25`）会导致零的数量一次跳跃 2 或更多。  

这两个特性暗示我们可以用 **二分搜索**（Binary Search）在单调函数上定位目标值。  

**关键观察**：  
- 对于任意的 `k`，若存在 `x` 使得 `f(x)=k`，那么一定会出现 **连续的 5 个** `x`（例如 `0~4` 对应 `k=0`，`5~9` 对应 `k=1`，……）。  
- 也就是说，**答案只有两种可能**：`5`（存在且恰好 5 个）或 `0`（根本不存在）。  

**为什么会出现 “5 个” 的块？**  
`f(x)` 计数的是 `x` 中有多少个因子 5（包括 5、25、125…的额外因子）。  
每 5 个连续的整数必定恰好多出 **一个** 因子 5（除去特殊的 25、125 …），所以在没有跨过更高幂次的 5 时，`f(x)` 会保持 **每 5 个数递增 1**，形成长度为 5 的区间。  
当跨过 `5^m`（如 25、125）时，`f(x)` 会一次跳跃超过 1，导致某些 `k` 完全**被跳过**，这时对应的区间不存在，答案为 0。

**求解步骤**：

1. 用二分搜索找到 **最左侧** 的 `x` 使得 `f(x) ≥ k`（记作 `left`）。  
2. 检查 `f(left)` 是否恰好等于 `k`。  
   - 若相等，则说明这 5 个连续的 `x`（`left, left+1, …, left+4`）都是答案，返回 `5`。  
   - 若不等，则说明 `k` 被跳过，返回 `0`。  

二分搜索的上界可以取 `5 * (k + 1)`，因为每 5 个数至少产生 1 个零，保证在此范围内一定能覆盖到 `k`（即使出现跳跃，也不会超过该上界）。

#### 代码（Python）

```python
def trailingZeroes(x: int) -> int:
    """返回 x! 末尾的 0 的个数（即 5 的因子总数）"""
    cnt = 0
    while x:
        x //= 5          # 每除一次 5，就把所有能被 5 整除的因子统计进来
        cnt += x
    return cnt


def preimageSizeFZF(k: int) -> int:
    """
    返回满足 f(x) = k 的非负整数 x 的个数（只能是 0 或 5）。
    思路：二分找到最左侧的 x 使得 f(x) >= k，然后判断是否恰好等于 k。
    """
    # 设定搜索区间 [0, high]，high 取足够大的值
    low, high = 0, 5 * (k + 1)   # 经验上足够大，保证一定能覆盖到 k

    while low < high:
        mid = (low + high) // 2
        z = trailingZeroes(mid)

        if z < k:
            low = mid + 1          # 目标在右侧
        else:
            high = mid             # 目标在左侧（或就是 mid）

    # 循环结束时 low == high，指向最左侧的满足 f(x) >= k 的位置
    return 5 if trailingZeroes(low) == k else 0
```

#### 复杂度  

- **时间复杂度**：`O(log (5·k))`  
  - 二分搜索的迭代次数是对数级的（约 30 次左右），每次都要计算一次 `trailingZeroes`，其本身是 `O(log_5 x)`，但这层对数非常小（最多 13 次，因为 `5^13 > 10^9`），可以视作常数。  
  - 用大白话说，就是“只要几百次简单的除法，就能得到答案”。  
- **空间复杂度**：`O(1)`，只用了几个整型变量，没有额外的数据结构。  

相较于暴力枚举的 **上百亿次**，优化后只需要 **几十次**，瞬间就能跑完。

## 心得

- **核心技巧**：利用 `f(x)` 的单调性和“每 5 个数形成一个块”的特性，配合二分搜索定位左边界。  
- **适用的题型**：  
  1. “寻找满足某单调函数等于目标值的区间大小”——如 **寻找数组中第一个大于等于 target 的位置**。  
  2. “阶乘末尾零数”系列——如 **Factorial Trailing Zeroes**（直接求 `f(x)`）。  
  3. “计数函数的逆像大小”——如 **Preimage Size of a Function**（本题的通用形式）。  
- **一句话总结解题钥匙**：**单调 + 二分 + 观察到答案只能是 0 或 5**。

## 反思

- **第一反应**：直接枚举 `x`，把每个 `x!` 的零数算出来，感觉最直观。  
- **最容易踩的坑**：  
  - 忘记 `f(x)` 不是连续递增的，某些 `k` 会被跳过。  
  - 二分搜索的上界选得不够大，会导致找不到对应的 `x`（返回错误的 0）。  
  - 边界条件如 `k = 0`，需要保证搜索区间包括 `0`。  
- **下次类似题的第一步**：先**确认函数的单调性**，再**思考是否可以用二分定位**，并**检查是否有固定的答案模式**（如本题的 0/5）。这样可以快速从暴力想到最优解。
