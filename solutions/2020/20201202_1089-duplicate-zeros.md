# #1089. 复制零 / Duplicate Zeros

> 难度：简单 · 标签：Array、Two Pointers · [LeetCode 链接](https://leetcode.com/problems/duplicate-zeros/)

---

## 题目（英文原版）

**Description**

Given a fixed-length integer array arr, duplicate each occurrence of zero, shifting the remaining elements to the right.
Note that elements beyond the length of the original array are not written. Do the above modifications to the input array in place and do not return anything.

**Examples**

**Example 1:**

```
Input: arr = [1,0,2,3,0,4,5,0]
Output: [1,0,0,2,3,0,0,4]
Explanation: After calling your function, the input array is modified to: [1,0,0,2,3,0,0,4]
```

**Example 2:**

```
Input: arr = [1,2,3]
Output: [1,2,3]
Explanation: After calling your function, the input array is modified to: [1,2,3]
```

**Constraints**

- 1 <= arr.length <= 104
- 0 <= arr[i] <= 9

---

## 题目（中文翻译）

给定一个 **固定长度**（fixed-length）的整数数组 `arr`，将每个出现的零复制一次，并把其余元素向右移动。  
注意，超出原数组长度的元素不会被写入。请 **就地**（in place）对输入数组完成上述修改，且不要返回任何值。

示例 1  
输入：`arr = [1,0,2,3,0,4,5,0]`  
输出：`[1,0,0,2,3,0,0,4]`  
解释：调用函数后，输入数组被修改为 `[1,0,0,2,3,0,0,4]`。

示例 2  
输入：`arr = [1,2,3]`  
输出：`[1,2,3]`  
解释：调用函数后，输入数组保持为 `[1,2,3]`。

约束条件  
- `1 <= arr.length <= 10^4`  
- `0 <= arr[i] <= 9`

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的办法就是**把数组复制一遍**，然后在新数组里把每个 `0` 再插入一次，最后把新数组的前 `len(arr)` 个元素拷贝回原数组。

- **用到的数据结构**：额外的 Python 列表。可以把它想象成一本“复印本”，原数组是手稿，复印本是我们先把手稿抄下来再加工的过程。  
- **为什么正确**：在复印本里我们可以随意插入元素，因为复印本的长度可以随原数组的长度 + 零的个数扩展。把处理好的复印本的前 `n` 位写回原数组，就实现了“在原地”修改的要求（因为题目只要求**不返回**结果，而不是**绝对不使用额外空间**）。
- **时间/空间分析**：  
  - 我们要遍历一次原数组（`O(n)`），再遍历一次复印本（同样 `O(n)`），总体是线性时间。  
  - 但是我们用了额外的数组，长度最多是 `2n`（最坏情况全是 `0`），所以空间复杂度是 `O(n)`。  
  用大白话来说，`O(n)` 就是“随着数组变长，花的时间和空间大概也会按同样的比例变长”，而 `O(1)` 才是“不管数组有多大，花的额外空间几乎不变”。

#### 代码（Python）

```python
def duplicateZeros_bruteforce(arr):
    """
    暴力版：使用额外数组完成复制与插入。
    """
    n = len(arr)
    # 1）先把原数组复制到一个新列表中
    copy = []                     # 用来临时存放处理后的结果
    for num in arr:
        copy.append(num)          # 直接把原来的数放进去
        if num == 0:              # 遇到 0 再额外放一个 0
            copy.append(0)

    # 2）把处理好的前 n 位写回原数组
    for i in range(n):
        arr[i] = copy[i]          # 只写回原数组能容纳的范围
```

#### 复杂度  

- **时间复杂度**：`O(n)` —— 只要遍历两遍数组，时间随数组长度线性增长。  
- **空间复杂度**：`O(n)` —— 需要一个额外的列表，最坏情况下长度会接近原数组的两倍。

### 2. 最优解

#### 思路  

暴力解的瓶颈在**额外空间**。题目要求“原地修改”，其实是想让我们思考**如何在不额外开辟大块空间的情况下完成复制**。  
核心思路是**先算出最终数组里每个元素应该出现的位置，然后从后往后填充**。这样可以避免“把后面的元素提前覆盖掉”。

具体步骤如下：

1. **统计零的个数** `zeros`。如果把所有零都复制一次，数组的“理论长度”会变成 `len(arr) + zeros`。  
2. **从后向前遍历**原数组，用两个指针：  
   - `i` 指向原数组当前处理的元素（从最后一个元素向前走）。  
   - `j` 指向“理论长度”对应的下标（同样从后向前走）。  
3. 当 `j` 超出原数组范围时（`j >= n`），说明这个位置已经超出了我们能写入的范围，直接跳过。  
4. 否则，把 `arr[i]` 写到 `arr[j]`（如果 `j` 在合法范围内）。如果 `arr[i]` 是 `0`，还要再写一次 `0` 到 `j-1`（同样要检查范围）。  
5. 继续把 `i` 左移，`j` 左移（如果写了两个零，`j` 左移两位）。

这样做的关键在于**从后往前写**，因为右侧的空位已经被“占位”了，写回去不会影响左侧尚未处理的元素。

下面用类比帮助理解：  
想象有一条装满弹珠的管子（原数组），我们要在每个出现的蓝弹珠（0）后面再加一个蓝弹珠，但管子两端已经封死，不能再往外扩。我们先把管子里所有弹珠往最右端挤（相当于算出 `j`），然后从右往左把弹珠一个个搬回去，同时在搬蓝弹珠时多搬一次。因为我们是从右往左搬，左边的弹珠不会被已经搬好的右边弹珠压坏。

#### 代码（Python）

```python
def duplicateZeros(arr):
    """
    最优解：双指针（从后往前）实现原地复制零。
    """
    n = len(arr)
    zeros = arr.count(0)                # 统计零的个数

    # j 是“理论上的写入位置”，可能会超过数组长度
    j = n + zeros - 1

    # 从右往左遍历原数组
    for i in range(n - 1, -1, -1):
        if j < n:                       # 只在 j 落在合法范围时写入
            arr[j] = arr[i]             # 把当前元素搬到位置 j
        # 如果当前元素是 0，需要再写一次 0
        if arr[i] == 0:
            j -= 1                       # 再往左移动一格，准备写第二个 0
            if j < n:                    # 再次检查合法性
                arr[j] = 0
        j -= 1                           # 正常情况下移动一格，准备写下一个元素
```

**代码说明（关键行中文注释）**：

- `zeros = arr.count(0)`：把数组里所有 0 的数量记下来，就像先数清楚要多加多少颗蓝弹珠。
- `j = n + zeros - 1`：`j` 表示“如果我们可以无限扩容，最后一个元素会落在第几位”。减 1 是因为下标从 0 开始。
- `for i in range(n - 1, -1, -1):`：`i` 从右边的最后一个元素往左走。
- `if j < n: arr[j] = arr[i]`：只有当 `j` 落在原数组可写范围时才真正写入，防止越界。
- `if arr[i] == 0:`：遇到 0 时，要再写一次 0。先把 `j` 再左移一格（因为要占两个位置），再检查是否在合法范围后写入。
- `j -= 1`（循环末尾）：把写指针左移，为下一个元素腾出位置。

#### 复杂度  

- **时间复杂度**：`O(n)` —— 只遍历一次数组，所有操作都是常数时间。与暴力解的时间相同，但不需要额外遍历复制数组。  
- **空间复杂度**：`O(1)` —— 只用了几个额外的整数变量（`zeros、i、j`），不随输入规模增长，真正实现了“原地”操作。

## 心得

- **核心技巧**：**双指针（从后往前）+ 计数**，利用“理论长度”把元素搬回原数组，避免覆盖未处理的元素。  
- **适用的题型**：  
  1. **移除数组中指定元素**（如 LeetCode 27 `Remove Element`）——同样可以先计算新长度再从后往前填充。  
  2. **数组向右平移**（如 LeetCode 1089 `Duplicate Zeros` 的变体）——需要把元素往后搬，防止冲突。  
  3. **在数组中插入/删除元素而不使用额外空间**（如 “把所有奇数移到前面”）——都可以使用双指针从后往前处理。  
- **一句话总结解题钥匙**：**先算出“目标位置”，再逆序填充，保证已经写好的位置不会被后面的原数据覆盖。**

## 反思

- **第一反应**：直接开一个新数组复制并插入零，觉得最容易实现。  
- **最容易踩的坑**：  
  - **越界写入**：在逆序写入时忘记检查 `j < n`，会导致 IndexError。  
  - **零的双写**：忘记在写完第一个零后再左移一次写第二个零，导致结果少了一个零。  
  - **计数错误**：如果直接把 `j = n + zeros` 而不是 `-1`，会把数组长度多算一位。  
- **下次遇到同类题的第一步**：**先问自己“如果空间不受限，最终数组应该长成什么样？”**，算出目标长度后，再考虑如何在原数组内部“搬家”。这样往往能快速定位到逆序双指针的思路。
