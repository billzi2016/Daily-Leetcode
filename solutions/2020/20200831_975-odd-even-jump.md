# #975. 奇偶跳跃 / Odd Even Jump

> 难度：困难 · 标签：Array、Dynamic Programming、Stack、Sorting、Monotonic Stack、Ordered Set · [LeetCode 链接](https://leetcode.com/problems/odd-even-jump/)

## 题目（英文原版）

**Description**

You are given an integer array arr. From some starting index, you can make a series of jumps. The (1st, 3rd, 5th, ...) jumps in the series are called odd-numbered jumps, and the (2nd, 4th, 6th, ...) jumps in the series are called even-numbered jumps. Note that the jumps are numbered, not the indices.
You may jump forward from index i to index j (with i < j) in the following way:
A starting index is good if, starting from that index, you can reach the end of the array (index arr.length - 1) by jumping some number of times (possibly 0 or more than once).
Return the number of good starting indices.

**Examples**

**Example 1:**

```
Input: arr = [10,13,12,14,15]
Output: 2
Explanation: 
From starting index i = 0, we can make our 1st jump to i = 2 (since arr[2] is the smallest among arr[1], arr[2], arr[3], arr[4] that is greater or equal to arr[0]), then we cannot jump any more.
From starting index i = 1 and i = 2, we can make our 1st jump to i = 3, then we cannot jump any more.
From starting index i = 3, we can make our 1st jump to i = 4, so we have reached the end.
From starting index i = 4, we have reached the end already.
In total, there are 2 different starting indices i = 3 and i = 4, where we can reach the end with some number of
jumps.
```

**Example 2:**

```
Input: arr = [2,3,1,1,4]
Output: 3
Explanation: 
From starting index i = 0, we make jumps to i = 1, i = 2, i = 3:
During our 1st jump (odd-numbered), we first jump to i = 1 because arr[1] is the smallest value in [arr[1], arr[2], arr[3], arr[4]] that is greater than or equal to arr[0].
During our 2nd jump (even-numbered), we jump from i = 1 to i = 2 because arr[2] is the largest value in [arr[2], arr[3], arr[4]] that is less than or equal to arr[1]. arr[3] is also the largest value, but 2 is a smaller index, so we can only jump to i = 2 and not i = 3
During our 3rd jump (odd-numbered), we jump from i = 2 to i = 3 because arr[3] is the smallest value in [arr[3], arr[4]] that is greater than or equal to arr[2].
We can't jump from i = 3 to i = 4, so the starting index i = 0 is not good.
In a similar manner, we can deduce that:
From starting index i = 1, we jump to i = 4, so we reach the end.
From starting index i = 2, we jump to i = 3, and then we can't jump anymore.
From starting index i = 3, we jump to i = 4, so we reach the end.
From starting index i = 4, we are already at the end.
In total, there are 3 different starting indices i = 1, i = 3, and i = 4, where we can reach the end with some
number of jumps.
```

**Example 3:**

```
Input: arr = [5,1,3,4,2]
Output: 3
Explanation: We can reach the end from starting indices 1, 2, and 4.
```

**Constraints**

- 1 <= arr.length <= 2 * 104
- 0 <= arr[i] < 105

## 题目（中文翻译）

你被给定一个整数数组 `arr`。从某个起始下标出发，你可以进行一系列跳跃。序列中的第 1、3、5… 次跳跃称为**奇数跳跃（odd-numbered jumps）**，第 2、4、6… 次跳跃称为**偶数跳跃（even-numbered jumps）**。注意这里的“第几次跳跃”是指跳的顺序，而不是数组下标。

你可以 **向前**（即 `i < j`） 从下标 `i` 跳到下标 `j`，满足以下条件：

- **奇数跳跃**：在所有满足 `arr[j] >= arr[i]` 且 `j > i` 的下标中，选择 `arr[j]` 最小的那个；如果有多个下标对应相同的最小值，取下标最小的那个。
- **偶数跳跃**：在所有满足 `arr[j] <= arr[i]` 且 `j > i` 的下标中，选择 `arr[j]` 最大的那个；如果有多个下标对应相同的最大值，取下标最小的那个。

如果从某个起始下标出发，经过若干次跳跃（可以为 0 次，也可以多次）能够到达数组末尾下标 `arr.length - 1`，则称该起始下标为**好起始下标（good starting index）**。

返回好起始下标的数量。

---

### 示例

**示例 1**  
输入: `arr = [10,13,12,14,15]`  
输出: `2`  
解释:  
- 从下标 `i = 0` 开始，第一次奇数跳跃只能跳到 `i = 2`（因为 `arr[2]` 是 `[arr[1],arr[2],arr[3],arr[4]]` 中大于等于 `arr[0]` 的最小值），随后无法再跳。  
- 从下标 `i = 1` 和 `i = 2` 开始，第一次跳跃都只能到 `i = 3`，随后也无法继续。  
- 从下标 `i = 3` 开始，第一次跳跃到 `i = 4`，已到达末尾。  
- 从下标 `i = 4` 本身已经在末尾。  

因此只有下标 `3` 和 `4` 是好起始下标，共计 **2** 个。

**示例 2**  
输入: `arr = [2,3,1,1,4]`  
输出: `3`  
解释:  
- 从下标 `i = 0` 开始，跳跃过程为 `0 → 1 → 2 → 3`：  
  1. 第一次奇数跳跃跳到 `i = 1`（`arr[1]` 是 `[arr[1],arr[2],arr[3],arr[4]]` 中 ≥ `arr[0]` 的最小值）。  
  2. 第二次偶数跳跃跳到 `i = 2`（`arr[2]` 是 `[arr[2],arr[3],arr[4]]` 中 ≤ `arr[1]` 的最大值；虽然 `arr[3]` 也同样最大，但下标更大，故选 `i = 2`）。  
  3. 第三次奇数跳跃跳到 `i = 3`（`arr[3]` 是 `[arr[3],arr[4]]` 中 ≥ `arr[2]` 的最小值）。  
  无法再从 `i = 3` 跳到 `i = 4`，所以下标 `0` 不是好起始下标。  
- 类推可得：  
  - 下标 `1` 能直接跳到 `4`，到达末尾。  
  - 下标 `2` 跳到 `3` 后无法继续。  
  - 下标 `3` 跳到 `4`，到达末尾。  
  - 下标 `4` 本身已在末尾。  

好起始下标为 `1、3、4`，共计 **3** 个。

**示例 3**  
输入: `arr = [5,1,3,4,2]`  
输出: `3`  
解释: 可以从下标 `1、2、4` 到达数组末尾。

- `1 <= arr.length <= 2 * 10^4`
- `0 <= arr[i] < 10^5`

## 解题过程  

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**对每一个起始位置 i，按照题目规则一步步模拟跳跃**，看能否最终到达数组的最后一个下标 `n-1`。  

- **奇数跳**：在当前位置 `i` 的右侧（`j > i`）找所有满足 `arr[j] >= arr[i]` 的元素，选 **值最小且下标最左** 的那个作为下一跳的目标。  
- **偶数跳**：在右侧找所有满足 `arr[j] <= arr[i]` 的元素，选 **值最大且下标最左** 的那个。

这相当于在每一步都 **遍历整个右侧子数组**，找出符合条件的“最近的合适值”。  

> 类比：把数组想成一排房子，奇数跳就像在找右边**价钱不低于自己且最便宜**的房子，偶数跳则是找**价钱不高于自己且最贵**的房子。我们只能往右看，看到的每一套房子都要检查一遍。

只要从起点一直跳下去能走到最后，起点就是 **good**。  

#### 代码（Python）

```python
from typing import List

def odd_even_jumps_brute(arr: List[int]) -> int:
    n = len(arr)
    good = 0                     # 记录能到达末尾的起点数量

    # 对每一个起点 i 进行模拟
    for start in range(n):
        i = start
        odd = True               # 第一次跳是奇数跳
        while i < n - 1:         # 只要没到最后一个位置，就继续跳
            next_i = -1
            if odd:              # ---------- 奇数跳 ----------
                # 在 i 右侧找满足 arr[j] >= arr[i] 且值最小的下标
                min_val = float('inf')
                for j in range(i + 1, n):
                    if arr[j] >= arr[i] and arr[j] < min_val:
                        min_val = arr[j]
                        next_i = j
            else:                # ---------- 偶数跳 ----------
                # 在 i 右侧找满足 arr[j] <= arr[i] 且值最大的下标
                max_val = -float('inf')
                for j in range(i + 1, n):
                    if arr[j] <= arr[i] and arr[j] > max_val:
                        max_val = arr[j]
                        next_i = j

            if next_i == -1:     # 找不到合法的下一跳，跳不下去了
                break
            i = next_i           # 移动到下一位置
            odd = not odd        # 跳数+1，奇偶交替

        if i == n - 1:           # 成功到达最后一个下标
            good += 1

    return good
```

#### 复杂度  

- **时间复杂度**：`O(n²)`  
  - 外层遍历 `n` 个起点，内层在最坏情况下每一步都要遍历右侧的 `O(n)` 个元素，整体是二次方。  
  - “`O(n²)`” 可以理解为：如果数组长度是 10 000，程序大概会执行 1 亿次（10 000 × 10 000）基本操作，已经会很慢。

- **空间复杂度**：`O(1)`  
  - 只使用了常数级的额外变量（`good、i、odd、next_i` 等），不随 `n` 增长。

### 2. 最优解  

#### 思路  

暴力解的瓶颈在 **每一次跳跃都要线性扫描右侧子数组**。我们需要在 **O(1) 或 O(log n)** 的时间里直接得到“下一个合法跳点”。  

关键观察：

1. **奇数跳**只关心“右侧第一个 **不小于** 当前值且**最小** 的位置”。  
2. **偶数跳**只关心“右侧第一个 **不大于** 当前值且**最大** 的位置”。  

如果我们把所有下标按照 **值的升序** 排好（值相同的按下标升序），那么在这个顺序里，**更大的下标一定在右侧**。于是可以用 **单调栈**（Monotonic Stack）一次遍历得到每个位置的“最近更大/更小的下标”。  

下面分两步说明：

1. **求“奇数跳的下一位置” (next_higher)**  
   - 把 `(value, index)` 按 `value` 升序、`index` 升序排序。  
   - 扫一遍排好序的下标，维护一个 **递增的栈**（栈内保存下标，且下标严格递增）。  
   - 当遍历到下标 `i` 时，栈顶的下标 `stack[-1]` 是**左侧最近且小于 i 的下标**，而 `i` 正好是它的“下一个更大或相等的值”。于是弹出栈顶并把 `next_higher[stack_top] = i`。  
   - 这一步的时间是 `O(n)`（每个下标最多进栈、出栈一次），排序的代价是 `O(n log n)`。

2. **求“偶数跳的下一位置” (next_lower)**  
   - 同理，只是把 `(value, index)` 按 `value` **降序**、`index` 升序排序，然后用同样的递增栈得到 “下一个更小或相等的值”。  

得到 `next_higher` 与 `next_lower` 两个数组后，**动态规划**（DP）可以判断每个位置在奇数跳或偶数跳时是否能到达末尾：

- `odd[i] = True` 当且仅当 `next_higher[i] != -1` 且 `even[next_higher[i]]` 为真。  
- `even[i] = True` 当且仅当 `next_lower[i] != -1` 且 `odd[next_lower[i]]` 为真。  

从数组最右端往左遍历即可填表，因为右侧的状态已经算好。  

> 类比：  
> - 想象把所有房子按照价钱从低到高排好队（相同价钱的保持原来顺序），然后让你从左往右排队，每次把“还没找到更贵房子”的人放进一个队列（栈），当遇到更贵的房子时，就立刻告诉队列前面的那个人“你的下一站是我”。  
> - 对偶数跳则是把房子按价钱从高到低排队，过程类似。

#### 代码（Python）

```python
from typing import List
import bisect

def odd_even_jumps(arr: List[int]) -> int:
    n = len(arr)
    if n == 1:
        return 1                     # 只有一个元素，必定是 good

    # ---------- 1. 计算 next_higher ----------
    # 按 (value, index) 升序排列
    sorted_idx = sorted(range(n), key=lambda i: (arr[i], i))
    next_higher = [-1] * n            # -1 表示没有合法的下一跳
    stack = []                        # 单调递增栈，保存下标
    for i in sorted_idx:
        # 栈顶的下标都是在 i 左侧且还没有找到更大的值
        while stack and stack[-1] < i:
            prev = stack.pop()
            next_higher[prev] = i
        stack.append(i)

    # ---------- 2. 计算 next_lower ----------
    # 按 (value, index) 降序排列
    sorted_idx = sorted(range(n), key=lambda i: (-arr[i], i))
    next_lower = [-1] * n
    stack.clear()
    for i in sorted_idx:
        while stack and stack[-1] < i:
            prev = stack.pop()
            next_lower[prev] = i
        stack.append(i)

    # ---------- 3. 动态规划 ----------
    odd = [False] * n     # odd[i] 表示从 i 出发，奇数跳能到达末尾
    even = [False] * n    # even[i] 表示从 i 出发，偶数跳能到达末尾
    odd[-1] = even[-1] = True   # 最后一个位置已经在终点

    # 从右往左填表，右侧的状态已经算好
    for i in range(n - 2, -1, -1):
        # 奇数跳：必须先走一次奇数跳到 next_higher[i]，然后在那儿以偶数跳继续
        if next_higher[i] != -1:
            odd[i] = even[next_higher[i]]
        # 偶数跳：先走一次偶数跳到 next_lower[i]，然后在那儿以奇数跳继续
        if next_lower[i] != -1:
            even[i] = odd[next_lower[i]]

    # 好的起点是奇数跳能到达末尾的下标（因为第一次跳是奇数跳）
    return sum(odd)
```

> 代码解释（关键行中文注释）已经写在源码里，直接运行即可。

#### 复杂度  

- **时间复杂度**：`O(n log n)`  
  - 排序两次各 `O(n log n)`，其余（单调栈遍历 + DP）都是 `O(n)`。  
  - 与暴力的 `O(n²)` 相比，大幅降低；当 `n = 20,000` 时，`n log n` 只约 `3·10⁵` 次操作，完全可以在毫秒级完成。

- **空间复杂度**：`O(n)`  
  - 需要额外的 `next_higher、next_lower、odd、even` 四个长度为 `n` 的数组，属于线性空间。  
  - 相比于暴力的 `O(1)`，多用了线性空间来换取更快的运行时间，这在大多数实际场景中是值得的。

## 心得  

- **核心技巧**：利用 **单调栈 + 排序** 预处理得到“下一跳位置”，再用 **动态规划** 判断可达性。  
- **适用的题型**：  
  1. “下一个更大/更小元素”类问题（LeetCode 496、503 等）。  
  2. 需要 **按值顺序** 找到最近右侧符合条件的下标的题目（如 “Maximum Width Ramp”）。  
  3. 任何可以把“跳转关系”抽象为 **有向无环图**，并且图的边只有一种“最近”形式的 DP 题。  

- **一句话总结解题钥匙**：  
  *“把跳跃规则转化为‘对每个位置的唯一后继’，先用单调栈一次性算出这些后继，再用 DP 判断能否抵达终点”。*

## 反思  

- **第一反应**：直接写循环模拟，想到“遍历右侧找符合条件的下一个”。这在没有经验时是最自然的思路。  
- **最容易踩的坑**：  
  1. **相同数值的处理**：题目要求 “值相等时取下标最小的”。在排序时必须把 `index` 作为第二关键字，保证相同值保持原来左到右的顺序。  
  2. **边界情况**：数组长度为 1 时直接返回 1；以及 `next_higher/next_lower` 为 `-1` 时不要访问 DP 数组。  
  3. **奇偶跳的交替**：容易把 `odd[i]` 与 `even[i]` 的递推关系弄反，记住“奇数跳后要看偶数跳能否继续”。  

- **下次遇到同类题的第一步**：  
  *先问自己“对于每个下标，我的下一步只能是唯一的某个右侧下标吗？如果是，能否用单调栈一次性算出这个‘下一跳’”。*  
  若答案是肯定的，就立刻转向 **预处理 + DP** 的思路，避免暴力的二次遍历。
