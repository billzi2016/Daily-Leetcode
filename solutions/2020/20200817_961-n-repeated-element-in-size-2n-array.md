# #961. 大小为 2N 的数组中重复 N 次的元素 / N-Repeated Element in Size 2N Array

> 难度：简单 · 标签：Array、Hash Table · [LeetCode 链接](https://leetcode.com/problems/n-repeated-element-in-size-2n-array/)

---

## 题目（英文原版）

**Description**

You are given an integer array nums with the following properties:
Return the element that is repeated n times.

**Examples**

**Example 1:**

```
Input: nums = [1,2,3,3]
Output: 3
```

**Example 2:**

```
Input: nums = [2,1,2,5,3,2]
Output: 2
```

**Example 3:**

```
Input: nums = [5,1,5,2,5,3,5,4]
Output: 5
```

**Constraints**

- 2 <= n <= 5000
- nums.length == 2 * n
- 0 <= nums[i] <= 104
- nums contains n + 1 unique elements and one of them is repeated exactly n times.

---

## 题目（中文翻译）

给定一个整数数组 (integer array) `nums`，满足以下属性：

- 数组的长度为 `2 * n`，其中 `n` 为正整数。
- `nums` 中恰好有 `n + 1` 个不同的元素，其中 **唯一** 一个元素出现了 **恰好** `n` 次。

返回出现 `n` 次的那个元素。

**示例 1**  
输入: `nums = [1,2,3,3]`  
输出: `3`

**示例 2**  
输入: `nums = [2,1,2,5,3,2]`  
输出: `2`

**示例 3**  
输入: `nums = [5,1,5,2,5,3,5,4]`  
输出: `5`

**约束条件**

- `2 <= n <= 5000`
- `nums.length == 2 * n`
- `0 <= nums[i] <= 10^4`
- `nums` 包含 `n + 1` 个唯一元素，其中恰有一个元素重复出现 `n` 次。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

题目给出一个长度为 `2·n` 的整数数组 `nums`，其中恰好有 **`n` 次**出现同一个数，其余 `n+1` 个数各只出现一次。  
最直接的想法是**把每个数出现的次数都数一遍**，找出出现 `n` 次的那个数。

> **类比**：把数组想成一本小册子，里面的每个数字就像是单词。我们要把每个单词出现的页码记录下来，就像在字典（Hash Table）里查找——键（key）是数字本身，值（value）是它出现的次数。遍历一次数组，相当于把每个单词的页码写进字典；再遍历字典，找到出现次数为 `n` 的键，即为答案。

这种做法一定能得到正确答案，因为我们把**所有出现次数**都统计清楚了，必然能发现那个出现 `n` 次的数。

#### 代码（Python）

```python
def repeatedNTimes(nums):
    # 用字典（哈希表）统计每个数字出现的次数
    count = {}                     # key: 数字，value: 出现次数
    for x in nums:                 # 遍历数组的每个元素
        if x in count:             # 如果已经记录过
            count[x] += 1          # 次数加一
        else:
            count[x] = 1           # 第一次出现，次数置为 1

    # 找到出现 n 次的数字（n = len(nums)//2）
    n = len(nums) // 2
    for num, freq in count.items():   # 遍历字典的键值对
        if freq == n:                  # 正好出现 n 次
            return num                # 返回答案
```

#### 复杂度  

- **时间复杂度**：`O(2n) = O(n)`  
  我们遍历数组一次统计次数，再遍历字典一次找答案。`O(n)` 中的 `n` 代表数组长度的一半，实际操作次数约为 `2·n`，即线性增长。  
- **空间复杂度**：`O(n)`  
  最坏情况下，需要存放 `n+1` 个不同的数字及其计数（因为除了重复的那个数，其他都是唯一的），所以使用的额外空间随 `n` 成线性增长。

---

### 2. 最优解

#### 思路  

虽然上面的暴力解已经是 `O(n)` 时间，但它用了 **额外的哈希表**（`O(n)` 空间）。本题还有更“轻量”的做法，只需要 **常数级别的额外空间**。

观察题目条件：

- 数组长度是 `2·n`，且恰好有一个元素出现 `n` 次。
- 根据 **抽屉原理（Pigeonhole Principle）**：如果把数组分成相邻的 **三元组**（`[a[i], a[i+1], a[i+2]]`），必然会出现 **两个相同的数** 出现在同一个三元组里。  
  为什么？因为重复的数出现了 `n` 次，数组里共有 `2·n` 个位置。把所有位置两两相邻配对（即看成 `n` 对），若没有出现相邻的相同数，那么每对里至多只能有一个重复数，总计最多 `n` 次，正好等于出现次数。但若把窗口扩大到 **长度 3**，必然会捕获到至少一次相邻的重复（更直观的解释：把数组看成环，任取三个相邻位置，若这三个数全不相同，则每次出现的重复数最多只能分布在两两不相邻的位子，这与出现 `n` 次冲突）。

基于此，只要检查 **相邻的两个数** 或 **相隔两位的数** 是否相等，就能直接得到答案：

- 检查 `nums[i] == nums[i+1]`（相邻）  
- 检查 `nums[i] == nums[i+2]`（间隔一个）

只要满足其中之一，就找到了重复 `n` 次的元素。

> **类比**：把数组想成一排座位，重复的同学坐得很多。如果我们每隔一个座位看一次，或者直接看相邻的两个人，总能在某一次看到同一个同学坐在两个位置上。

#### 代码（Python）

```python
def repeatedNTimes(nums):
    # 只需要检查相邻或相隔一个的元素
    for i in range(len(nums) - 1):
        if nums[i] == nums[i + 1]:      # 相邻相等
            return nums[i]

    # 若相邻都不相等，则一定会出现 i 与 i+2 相等的情况
    for i in range(len(nums) - 2):
        if nums[i] == nums[i + 2]:      # 间隔一个相等
            return nums[i]

    # 理论上不会走到这里，因为题目保证一定有答案
    return -1
```

> **实现细节**：我们先遍历一次检查相邻元素；如果没有命中，再检查间隔一个的情况。两次遍历的长度都是 `2·n`，仍然是线性时间。

#### 复杂度  

- **时间复杂度**：`O(n)`  
  最多遍历数组两遍，每遍都是线性长度 `2·n`，故仍是线性时间。相比暴力解，时间没有提升，但**常数因子更小**（不需要哈希操作）。
- **空间复杂度**：`O(1)`  
  只用了若干个临时变量（循环计数器），不随 `n` 增长，属于常数级别的额外空间。

## 心得

- **核心技巧**：利用题目给出的**出现次数比例**（`n` 次出现于 `2·n` 长度）以及**抽屉原理**，可以在不额外存储的情况下直接定位重复元素。  
- **适用的题型**：  
  1. “多数元素”类（如 LeetCode 169 Majority Element）——利用出现次数超过半数的特性。  
  2. “固定比例重复”类（如本题）——通过相邻或固定间隔的检查快速定位。  
  3. “环形数组”或“滑动窗口”类问题——利用局部相等性推断全局信息。  
- **一句话总结解题钥匙**：**把“出现 n 次”转化为“相邻/相隔一定距离必相等”，用最小的检查窗口直接捕获答案**。

## 反思

- **第一反应**：看到“重复 n 次”，自然想到统计出现次数的哈希表。  
- **最容易踩的坑**：  
  - 忘记题目已经保证 **一定有唯一的答案**，所以不需要额外的错误处理。  
  - 误以为只检查相邻元素就够，实际上在某些排列（如 `[1,2,1,2]`）相邻不相等，需要再检查间隔一个的情况。  
- **下次类似题的第一步**：先思考 **“出现次数的比例”** 能否推出 **“局部必有相等”** 的必然性，再决定是否需要额外的数据结构。这样往往能直接得到 O(1) 空间的最优解。
