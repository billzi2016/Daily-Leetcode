## 题目（英文原版）

**Description**

There is a car with capacity empty seats. The vehicle only drives east (i.e., it cannot turn around and drive west).
You are given the integer capacity and an array trips where trips[i] = [numPassengersi, fromi, toi] indicates that the ith trip has numPassengersi passengers and the locations to pick them up and drop them off are fromi and toi respectively. The locations are given as the number of kilometers due east from the car's initial location.
Return true if it is possible to pick up and drop off all passengers for all the given trips, or false otherwise.

**Examples**

**Example 1:**

```
Input: trips = [[2,1,5],[3,3,7]], capacity = 4
Output: false
```

**Example 2:**

```
Input: trips = [[2,1,5],[3,3,7]], capacity = 5
Output: true
```

**Constraints**

- 1 <= trips.length <= 1000
- trips[i].length == 3
- 1 <= numPassengersi <= 100
- 0 <= fromi < toi <= 1000
- 1 <= capacity <= 105

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是把整条路（从 0 km 到最远的下车点）划分成若干“公里段”。  
每一次乘客上车，就把从 `from` 到 `to-1` 这段路上 **每公里** 的乘客人数都加上 `numPassengers`；  
每一次下车，就把对应的公里段人数减去 `numPassengers`。  

把“每公里的乘客人数”想象成一本**路程账本**，每翻一页（每公里），我们都记下当前车上有多少人。  
遍历完所有行程后，只要检查账本里有没有哪一页的人数超过汽车容量 `capacity`，如果有则返回 `False`，否则返回 `True`。

> **为什么正确？**  
> 乘客在上车地点上车、在下车地点下车，期间他们会一直坐在车上。把每公里的乘客人数都算上，等价于把所有乘客的“在车上”时间全部叠加，若任何时刻人数超过容量，说明不可能完成所有行程。

#### 代码（Python）

```python
def carPooling_brute(trips, capacity):
    # 找出最远的下车地点，确定需要多少公里的账本
    max_location = max(to for _, _, to in trips)

    # 账本：index 表示公里点，value 表示该点上车后车内乘客数
    # 初始全部为 0
    passengers_per_km = [0] * (max_location + 1)

    # 对每一段行程，遍历它覆盖的每一公里，累加乘客数
    for num, start, end in trips:
        for km in range(start, end):          # 从 start 开始，到 end-1 结束
            passengers_per_km[km] += num      # 上车人数加到该公里

    # 检查每一公里是否超过容量
    for km, cur in enumerate(passengers_per_km):
        if cur > capacity:                     # 车上人数超出限制
            return False
    return True
```

#### 复杂度  

- **时间复杂度**：`O(N * L)`，其中 `N` 为行程数，`L` 为最远的下车地点（最多 1000）。  
  用大白话说，就是**每一趟**都要**走遍它的路段**，所以最坏情况下要跑 `N` 次 `L` 步。  
- **空间复杂度**：`O(L)`，需要一张长度为 `max_location+1` 的账本来记录每公里的乘客数。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**对每一公里都遍历**，当行程很多、路程很长时会产生大量重复计数。  
其实我们只关心“乘客人数何时增加，何时减少”。如果把每一次**上车**和**下车**都看作一个**事件**，按地点从小到大处理这些事件，就能一次遍历得到每个时刻的车上人数，而不必逐公里累加。

**核心概念：**  
- **事件（event）**：`(location, delta)`，`delta` 为正数表示上车人数，负数表示下车人数。  
- **扫描线（Sweep Line）**：把所有事件按 `location` 排序，然后从左到右“扫过”，用一个变量 `cur` 累加 `delta`，`cur` 就是当前时刻车上的乘客数。  
- **类比**：想象你在一本日程表上记下“某天我要参加 3 场会议”，每到会议开始页码加 1，结束页码减 1，最后只要检查任何页码的累计数是否超过房间容量即可。

**步骤**  
1. 把每趟行程拆成两个事件：  
   - `(from, +numPassengers)`   → 乘客在 `from` 上车  
   - `(to,   -numPassengers)`   → 乘客在 `to` 下车  
2. 把所有事件放进列表并**按地点升序排序**。如果同一地点既有上车也有下车，**先下车后上车**（因为下车后空出座位），实现方式是把 `delta` 为负的放在前面，或在排序时把 `delta` 作为第二关键字（升序）。
3. 用变量 `cur` 累计 `delta`，每处理一个事件后判断 `cur` 是否 > `capacity`，若是直接返回 `False`。
4. 所有事件都安全处理完，说明任何时刻人数都未超额，返回 `True`。

> **为什么正确？**  
> 事件的顺序恰好对应车子前进的顺序。`cur` 的每一次更新都精确反映了车上乘客数的变化；只要在任何时刻发现 `cur` 超过容量，就说明在那一段路上坐不下，否者整个行程都是可行的。

#### 代码（Python）

```python
def carPooling(trips, capacity):
    events = []                     # 用来存放所有上下车事件
    for num, start, end in trips:
        events.append((start,  num))   # 上车：人数增加
        events.append((end,   -num))   # 下车：人数减少

    # 按地点升序排序；如果地点相同，先处理 delta 为负的（先下车）
    events.sort(key=lambda x: (x[0], x[1]))

    cur = 0                         # 当前车上乘客数
    for loc, delta in events:
        cur += delta                # 更新车上人数
        if cur > capacity:         # 超过容量，直接返回 False
            return False
    return True
```

#### 复杂度  

- **时间复杂度**：`O(N log N)`，主要耗时在对 `2N` 个事件的排序（`log N` 为对数），遍历事件本身是线性的。相比暴力的 `O(N·L)`，这里不随路程长度 `L` 增长，效率更高。  
- **空间复杂度**：`O(N)`，需要存放 `2N` 条事件（常数因子 2 可忽略），不随最大里程 `L` 增长。

## 心得

- 这道题考察的核心技巧是 **扫描线（事件排序）**，即把“增/减”操作抽象为事件，按时间顺序统一处理。  
- 类似的技巧常见于：  
  1. **会议室安排**（判断是否有冲突）  
  2. **柱状图中的最大重叠区间**（比如“天际线”问题）  
  3. **区间合并**（比如“数组的子区间求和”）  
- **一句话总结**：把每一次“上车/下车”看成时间点的增减，按时间顺序累计，出现超额即为不可能。

## 反思

- **第一反应**：看到“只能向东行驶”“容量限制”，自然想到“在每个位置统计车上人数”。  
- **最容易踩的坑**：  
  - 同一地点既有下车又有上车时，需要**先下车后上车**，否则可能误判容量不足。  
  - 忘记把 `to` 位置视为**下车点**（不包含在乘客仍在车上的区间），导致多算一次人数。  
  - 事件排序的细节：若只按地点排序而不处理同点的顺序，某些测试会出错。  
- **下次遇到同类题**，第一步应想到“把区间转成增/减事件”，再决定是用**差分数组**（若坐标范围小）还是**排序扫描线**（若坐标范围大）。
