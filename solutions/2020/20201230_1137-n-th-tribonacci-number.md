# #1137. 第 N 个 Tribonacci 数 / N-th Tribonacci Number

> 难度：简单 · 标签：Math、Dynamic Programming、Memoization · [LeetCode 链接](https://leetcode.com/problems/n-th-tribonacci-number/)

---

## 题目（英文原版）

**Description**

The Tribonacci sequence Tn is defined as follows:
T0 = 0, T1 = 1, T2 = 1, and Tn+3 = Tn + Tn+1 + Tn+2 for n >= 0.
Given n, return the value of Tn.

**Examples**

**Example 1:**

```
Input: n = 4
Output: 4
Explanation:
T_3 = 0 + 1 + 1 = 2
T_4 = 1 + 1 + 2 = 4
```

**Example 2:**

```
Input: n = 25
Output: 1389537
```

**Constraints**

- 0 <= n <= 37
- The answer is guaranteed to fit within a 32-bit integer, ie. answer <= 2^31 - 1.

## 题目（中文翻译）

The Tribonacci 序列 **Tₙ** 定义如下：  
- T₀ = 0  
- T₁ = 1  
- T₂ = 1  
- 对于 n ≥ 0，有 Tₙ₊₃ = Tₙ + Tₙ₊₁ + Tₙ₊₂  

给定整数 **n**，返回 **Tₙ** 的值。

**示例 1**  
**输入**: `n = 4`  
**输出**: `4`  
**解释**:  
T₃ = 0 + 1 + 1 = 2  
T₄ = 1 + 1 + 2 = 4  

**示例 2**  
**输入**: `n = 25`  
**输出**: `1389537`  

**约束条件**  
- 0 ≤ n ≤ 37  
- 答案保证能够放入 32 位整数，即 answer ≤ 2³¹ - 1。

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**递归**地按照定义把 `Tn` 拆成更小的子问题：

```
T(n) = T(n-1) + T(n-2) + T(n-3)      (n ≥ 3)
T(0) = 0,  T(1) = 1,  T(2) = 1
```

可以把递归想成“向后追溯”。  
比如要算 `T4`，先算 `T3、T2、T1`，而算 `T3` 又要算 `T2、T1、T0`，如此层层展开，直到碰到已经知道的基准值（0、1、1）。

- **用到的数据结构**：只需要函数调用栈（系统自动帮我们维护），相当于我们把所有要计算的 “子任务” 放进一个“待办清单”，一次只处理最靠前的任务，处理完再回到上一个任务。可以把它类比成 **“递归的层层盒子”**，最里面的盒子装的是基准值，外层盒子装的是它们的和。

- **为什么正确**：递归正好把题目给出的等式一步一步展开，最终把每个 `T(i)` 都用已知的基准值表达出来，数学上等价于原定义。

- **时间/空间复杂度**：  
  - 每一次求 `T(k)` 都要去求 `T(k-1)`, `T(k-2)`, `T(k-3)`，这三个子问题之间又会产生大量重复计算。  
  - 大概的调用次数是 **指数级** 的，记作 `O(3^n)`（因为每层最多分叉成 3 条），也可以粗略说 **“随着 n 增大，计算时间会像滚雪球一样快速增长”**。  
  - 递归深度最多是 `n`，所以调用栈占用的空间是 `O(n)`。

#### 代码（Python）

```python
def tribonacci_brute(n: int) -> int:
    """
    递归暴力解法
    递归的每一次调用都对应题目定义中的一次“求和”
    """
    # 基准情况：题目已经直接给出的前 3 项
    if n == 0:
        return 0
    if n == 1 or n == 2:
        return 1

    # 递归展开：把 T(n) 拆成 T(n-1)+T(n-2)+T(n-3)
    return (tribonacci_brute(n - 1) +
            tribonacci_brute(n - 2) +
            tribonacci_brute(n - 3))
```

#### 复杂度

- **时间复杂度**：`O(3^n)`  
  解释：每一层会产生 3 条新分支，层数大约是 `n`，于是总调用次数像 3 的 n 次方一样快速增长。对我们日常生活来说，就是“等 n 增加一点点，时间就会翻几倍”。

- **空间复杂度**：`O(n)`  
  解释：递归最深会走到 `n`，相当于把 `n` 层盒子一个一个叠起来，占用的栈空间和层数成正比。

### 2. 最优解

#### 思路  

从暴力解我们可以看到 **“大量重复计算」** 是性能瓶颈。  
实际上，**每个 `T(i)` 只需要算一次**，后面再用到时直接拿已有的结果即可。这正是**动态规划**（Dynamic Programming）的核心思想——把子问题的答案保存下来，后面直接查表。

**两种实现方式**：

1. **自底向上 DP（使用数组）**  
   - 创建一个长度为 `n+1`（或固定 38，因为约束 `n ≤ 37`）的数组 `dp`。  
   - 初始化 `dp[0]=0, dp[1]=dp[2]=1`（基准值）。  
   - 从 `i=3` 开始，按顺序填表：`dp[i] = dp[i-1] + dp[i-2] + dp[i-3]`。  
   - 最后返回 `dp[n]`。

   类比：把每一天的“收入”记在本子上，等到后面需要累计时直接翻到那一页看，省得重新算。

2. **滚动数组 / 常数空间 DP**  
   - 其实我们只会在计算 `dp[i]` 时用到最近的 **3** 项：`dp[i-1]、dp[i-2]、dp[i-3]`。  
   - 用三个变量 `a, b, c` 分别保存这三项，循环更新即可。  
   - 这样只用 **O(1)** 的额外空间。

下面给出 **常数空间** 的实现，因为它最简洁且满足题目要求。

#### 代码（Python）

```python
def tribonacci(n: int) -> int:
    """
    动态规划（常数空间）实现
    只保留最近的三项，逐步向前推进
    """
    # 基准情况直接返回
    if n == 0:
        return 0
    if n == 1 or n == 2:
        return 1

    # a、b、c 分别对应 T(i-3), T(i-2), T(i-1)
    a, b, c = 0, 1, 1   # 对应 T0, T1, T2
    for i in range(3, n + 1):
        # 计算当前的 T(i) = a + b + c
        cur = a + b + c
        # 滚动更新：向前移动一位
        a, b, c = b, c, cur   # a←b, b←c, c←cur

    # 循环结束后 c 正好是 T(n)
    return c
```

#### 复杂度

- **时间复杂度**：`O(n)`  
  解释：只需要一次线性遍历，从 3 到 n 共 `n-2` 步，每一步做常数次加法。对比暴力的指数级，这里“每增加一步，只多一点点时间”。

- **空间复杂度**：`O(1)`  
  解释：只用了 3 个整数变量，不随 `n` 增长而增加，等价于“只需要一支笔和一张小纸条”。如果使用数组保存所有中间结果，则空间是 `O(n)`，但常数空间更省内存。

## 心得

- **核心技巧**：**动态规划的“记忆化”**——把已经算好的子结果保存下来，避免重复计算。  
- **适用的题型**：  
  1. **斐波那契数列**（Fibonacci）  
  2. **爬楼梯**（Climbing Stairs）  
  3. **背包类的子序列计数**（如不同路径 Count Paths）  
- **解题钥匙**：**“先想能不能把子问题的答案复用，再决定是否需要数组或滚动变量”**。

## 反思

- **第一反应**：看到递推公式就想到递归，直接把等式写成函数调用。  
- **最容易踩的坑**：  
  - **忘记基准条件**（`n=0,1,2`），导致无限递归或错误结果。  
  - **使用递归时不做记忆化**，会因为指数级时间而超时。  
  - **边界值**：`n=0` 时直接返回 0；`n` 最大只有 37，若写成无限循环或数组越界会报错。  
- **下次遇到同类题**：第一步先**判断是否有重叠子问题**（即同一个子值会被多次计算），若有则立刻考虑**记忆化/动态规划**，再决定是用数组保存全部，还是用滚动变量做到常数空间。
