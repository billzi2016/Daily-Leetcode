# #922. **按奇偶排序 II** / Sort Array By Parity II

> 难度：简单 · 标签：Array、Two Pointers、Sorting · [LeetCode 链接](https://leetcode.com/problems/sort-array-by-parity-ii/)

---

## 题目（英文原版）

**Description**

Given an array of integers nums, half of the integers in nums are odd, and the other half are even.
Sort the array so that whenever nums[i] is odd, i is odd, and whenever nums[i] is even, i is even.
Return any answer array that satisfies this condition.
Follow Up: Could you solve it in-place?

**Examples**

**Example 1:**

```
Input: nums = [4,2,5,7]
Output: [4,5,2,7]
Explanation: [4,7,2,5], [2,5,4,7], [2,7,4,5] would also have been accepted.
```

**Example 2:**

```
Input: nums = [2,3]
Output: [2,3]
```

**Constraints**

- 2 <= nums.length <= 2 * 104
- nums.length is even.
- Half of the integers in nums are even.
- 0 <= nums[i] <= 1000

## 题目（中文翻译）

给定一个整数数组（array）`nums`，其中恰好有一半的整数是奇数，另一半是偶数。  
请对数组进行重新排序，使得：

- 当 `nums[i]` 为奇数时，索引 `i` 为奇数；
- 当 `nums[i]` 为偶数时，索引 `i` 为偶数。

返回任意满足上述条件的结果数组。

**示例 1**  

**输入**：`nums = [4,2,5,7]`  
**输出**：`[4,5,2,7]`  
**解释**：`[4,7,2,5]`、`[2,5,4,7]`、`[2,7,4,5]` 也都是合法答案。

**示例 2**  

**输入**：`nums = [2,3]`  
**输出**：`[2,3]`

**约束条件**

- `2 <= nums.length <= 2 * 10^4`
- `nums.length` 为偶数
- 数组中恰好有一半的整数是偶数
- `0 <= nums[i] <= 1000`

**进阶**：你能否实现原地（in‑place）排序？

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是**把每个位置都检查一遍**，如果当前位置的数与下标的奇偶性不匹配，就去后面的元素里找一个能匹配的（即奇数找偶数位置、偶数找奇数位置），找到后直接**交换**。  

- **数据结构**：这里只用到了普通的 Python 列表（数组）。把数组想象成一排格子，每个格子都有编号（下标），我们要把「偶数」的朋友安排进「偶数格子」，「奇数」的朋友安排进「奇数格子」。
- **为什么正确**：只要每一次都把不合格的格子和后面能合格的格子互换，最终所有格子都会得到符合要求的数字。因为题目保证奇数和偶数各占一半，必然能找到配对的元素完成交换。
- **时间/空间复杂度**：  
  - 最坏情况下，每次都要在后面遍历寻找匹配的元素，遍历的次数大约是 `1 + 2 + … + n/2 ≈ O(n²)`，这里的 `O(n²)` 可以理解为「如果数组有 10 000 个数，最坏情况下要检查大约 100 000 000 次」。
  - 只用了原数组本身，没有额外的存储，空间复杂度是 `O(1)`（常数级）。

#### 代码（Python）

```python
def sortArrayByParityII(nums):
    n = len(nums)
    # i 负责遍历所有偶数下标 (0, 2, 4, …)
    for i in range(0, n, 2):
        # 如果当前下标已经是偶数，继续
        if nums[i] % 2 == 0:
            continue
        # 否则在后面的奇数下标中找一个偶数来交换
        j = i + 1                     # 从下一个奇数下标开始
        while j < n:
            if nums[j] % 2 == 0:      # 找到偶数
                nums[i], nums[j] = nums[j], nums[i]  # 交换位置
                break
            j += 2                     # 只在奇数下标上搜索
    return nums
```

#### 复杂度  

- **时间复杂度**：`O(n²)` — 需要在最坏情况下对每个错误位置遍历后面的全部位置，类似“每个人都要找好几个人才能配对”。  
- **空间复杂度**：`O(1)` — 只在原数组上原地交换，没有额外的数组或哈希表。

### 2. 最优解

#### 思路  

从暴力解可以看到 **瓶颈在于每次都要线性搜索后面的元素**。我们可以把搜索的过程**提前**，一次性把所有「错误的」位置记录下来，然后配对交换。  

**双指针技巧**（Two Pointers）非常适合这种“奇偶交错、下标固定”的场景：

1. **指针 `i`**：只停留在 **偶数下标**（0、2、4…），负责检查这些位置是否已经放了偶数。  
2. **指针 `j`**：只停留在 **奇数下标**（1、3、5…），负责检查这些位置是否已经放了奇数。  

两指针同时向前走，每次判断：

- `nums[i]` 若已经是偶数 → `i` 前进 2（下一个偶数下标）。  
- `nums[j]` 若已经是奇数 → `j` 前进 2（下一个奇数下标）。  
- 否则，两者都不符合要求，说明 `nums[i]` 是奇数、`nums[j]` 是偶数，直接 **交换**，随后 `i`、`j` 都各自前进 2。

这样每个元素只会被检查一次，**不需要再去遍历找配对**，时间降到了线性 `O(n)`，空间仍然是原地 `O(1)`。

> **类比**：想象有两条生产线，一条只负责偶数格子（左手），另一条只负责奇数格子（右手），当左手拿到奇数、右手拿到偶数时，两人立刻互换手里的货物，继续前进。

#### 代码（Python）

```python
def sortArrayByParityII(nums):
    n = len(nums)
    i = 0               # 偶数下标指针
    j = 1               # 奇数下标指针

    while i < n and j < n:
        # 如果 i 位置已经是偶数，直接跳到下一个偶数下标
        if nums[i] % 2 == 0:
            i += 2
            continue
        # 如果 j 位置已经是奇数，直接跳到下一个奇数下标
        if nums[j] % 2 == 1:
            j += 2
            continue
        # 此时 i 位置是奇数，j 位置是偶数，二者需要互换
        nums[i], nums[j] = nums[j], nums[i]
        i += 2
        j += 2
    return nums
```

#### 复杂度  

- **时间复杂度**：`O(n)` — 每个元素最多被检查两次（一次在 `i`、一次在 `j`），相当于“一趟遍历”。相较于暴力的 `O(n²)`，快了好几个数量级。  
- **空间复杂度**：`O(1)` — 只使用了几个整数指针，没有额外的数组或哈希表，符合“原地”（in‑place）要求。

## 心得

- **核心技巧**：双指针（Two Pointers）在「交错条件」的数组中非常强大，能把线性搜索的成本降到常数时间。
- **适用的题型**：
  1. **颜色分类**（如 LeetCode 75. Sort Colors）——把 0、1、2 三类数字分区。  
  2. **移除元素**（如 LeetCode 27. Remove Element）——把满足条件的元素移动到数组前部。  
  3. **分割数组**（如 LeetCode 905. Sort Array By Parity）——把所有偶数放左侧、奇数放右侧。
- **一句话总结**：**“把奇数放在奇数位、偶数放在偶数位，只要用两根指针分别扫偶位和奇位，错位时立刻交换。”**

## 反思

- **第一反应**：看到“奇数下标对应奇数、偶数下标对应偶数”，自然想到“遍历检查、发现不匹配就找对应的再换”。这就是暴力思路。  
- **最容易踩的坑**：
  - **忘记步进 2**：指针只能在自己的奇偶位上前进，若一步步 +1 会导致无限循环或错误配对。  
  - **数组长度为偶数的前提**：如果题目改为奇数长度，需要额外处理末尾的单独元素。  
  - **原地交换**：在 Python 中 `a, b = b, a` 是一次性完成的，不能写成两行 `tmp = a; a = b; b = tmp`（虽然也对，但更容易写错下标）。
- **下次类似题的第一步**：**先判断是否可以用“两个指针分别负责两类位置”**，如果可以，就直接走双指针方案；如果不行，再考虑额外的存储或更复杂的结构（如单调栈、前缀和等）。
