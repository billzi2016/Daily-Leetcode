# #829. 连续整数之和 / Consecutive Numbers Sum

> 难度：困难 · 标签：Math、Enumeration · [LeetCode 链接](https://leetcode.com/problems/consecutive-numbers-sum/)

## 题目（英文原版）

**Description**

Given an integer n, return the number of ways you can write n as the sum of consecutive positive integers.

**Examples**

**Example 1:**

```
Input: n = 5
Output: 2
Explanation: 5 = 2 + 3
```

**Example 2:**

```
Input: n = 9
Output: 3
Explanation: 9 = 4 + 5 = 2 + 3 + 4
```

**Example 3:**

```
Input: n = 15
Output: 4
Explanation: 15 = 8 + 7 = 4 + 5 + 6 = 1 + 2 + 3 + 4 + 5
```

**Constraints**

- 1 <= n <= 109

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

把 “把 n 拆成若干个连续正整数的和” 想成 **在数轴上找一段连续的自然数**，它们加起来正好是 n。  
最直接的办法是：

1. **枚举起点** `start`（从 1 开始）  
2. 从 `start` 开始不断往后累加，得到 `cur_sum`  
3. 每次累加后判断  
   * `cur_sum == n` → 找到一种合法的拆法  
   * `cur_sum > n` → 这条起点已经不可能再凑出 n，直接结束，换下一个 `start`  

这就像我们在超市排队：从第一个顾客开始买，买完后再继续买下一个，直到买到正好花完 `n` 元，或者已经花超了，说明这条排队顺序不行。

> **为什么一定能找到所有答案？**  
> 因为所有可能的连续序列都有唯一的起点 `start`，我们把所有 `start` 都尝试了一遍，且每条 `start` 下的累加过程遍历了它可能的全部长度，所以不会遗漏。

#### 代码（Python）

```python
def consecutiveNumbersSum_brute(n: int) -> int:
    """
    暴力枚举所有起点 start，逐个累加，统计恰好等于 n 的情况。
    """
    ans = 0                     # 记录满足条件的方案数
    start = 1                   # 起点从 1 开始

    # 起点如果大于 n，显然不可能再凑出 n，直接结束循环
    while start <= n:
        cur_sum = 0             # 当前序列的和
        cur = start             # 当前正在加的数

        # 不断往后加，直到和 >= n
        while cur_sum < n:
            cur_sum += cur
            cur += 1

        # 如果恰好等于 n，说明找到一种合法的拆法
        if cur_sum == n:
            ans += 1

        # 换下一个起点继续尝试
        start += 1

    return ans
```

#### 复杂度

- **时间复杂度：** `O(n²)`  
  *解释：* 外层循环 `start` 最多跑 `n` 次；内层累加最多也会跑 `n` 次（最坏情况是从 1 开始一直加到 n），所以总的操作次数大约是 `n × n`。  
  对于 `n = 10⁹` 这种大数，这种方法根本跑不完。

- **空间复杂度：** `O(1)`  
  只用了几个整数变量，和 `n` 的大小无关。

### 2. 最优解

#### 思路  

**暴力慢的根源**是我们把 “连续” 这个约束当成了 “逐个加” 来检查。其实可以把 “连续” 用等差数列的公式直接写出来，省掉遍历的过程。

设连续序列的长度为 `k (k ≥ 1)`，起始数字为 `a (a ≥ 1)`，则：

```
n = a + (a+1) + (a+2) + … + (a+k-1)
  = k * a + k*(k-1)/2                （等差数列求和公式）
```

从上式解出 `a`：

```
a = ( n - k*(k-1)/2 ) / k
```

要让 `a` 成为合法的正整数，需要满足两个条件：

1. `n - k*(k-1)/2` 必须是 **正数**（否则起点会 ≤ 0）  
2. `n - k*(k-1)/2` 必须能被 `k` **整除**（否则 `a` 不是整数）

于是我们只要 **枚举可能的长度 `k`**，检查这两个条件即可。  
注意 `k*(k-1)/2` 随着 `k` 增大很快超过 `n`，一旦它大于 `n`，后面的 `k` 都不可能再满足条件了。因此 `k` 的上界大约是 `√(2n)`（因为 `k²/2 ≈ n`），这把搜索空间从 `n` 降到了 `√n`。

> **进一步的数学结论**（可选进阶）  
> 把等式两边同时乘以 `2`，得到 `2n = k(2a + k - 1)`。这里 `k` 与 `(2a + k - 1)` 必须都是 **奇数** 或 **偶数配对**，于是可以证明：`n` 能写成连续整数和的方案数 **等于 `n` 的奇因子个数**。因此只需要对 `n` 去掉所有 2 的因子，统计剩余奇数部分的约数个数即可，时间复杂度 `O(√n)`。

下面给出两种实现方式：

* **方式一**：直接枚举 `k`（更直观，适合初学者）  
* **方式二**：统计奇因子（更简洁，展示数学背后的思路）

#### 代码（Python）

##### 方式一：枚举长度 `k`

```python
import math

def consecutiveNumbersSum_opt(n: int) -> int:
    """
    枚举可能的序列长度 k（k >= 1），检查
        n - k*(k-1)//2 是否为正且能被 k 整除。
    只需要枚举到 sqrt(2n) 即可。
    """
    ans = 0
    # k 最大不会超过 sqrt(2n) + 1，防止遗漏边界
    max_k = int(math.sqrt(2 * n)) + 1

    for k in range(1, max_k + 1):
        # 计算 k*(k-1)//2，若已经大于 n，后面的 k 更大，只会更大，直接退出循环
        t = k * (k - 1) // 2
        if t >= n:          # 起点已经不可能为正数
            break

        # 判断 (n - t) 是否能被 k 整除
        if (n - t) % k == 0:
            # a = (n - t) // k 必须是正整数，这里已经通过 t < n 保证
            ans += 1

    return ans
```

##### 方式二：统计奇因子

```python
import math

def consecutiveNumbersSum_odd_factor(n: int) -> int:
    """
    结论：n 能表示为连续正整数和的方案数 = n 去掉所有 2 的因子后，奇数部分的约数个数。
    例如 n=12 => 12 = 2^2 * 3，奇数部分是 3，约数有 1,3 两个 → 2 种方案。
    """
    # 去掉所有 2 的因子，只留下奇数部分 m
    while n % 2 == 0:
        n //= 2

    # 统计 m 的约数个数
    m = n
    cnt = 1          # 约数个数的乘积形式，先乘以 1（相当于空因子）

    p = 3
    while p * p <= m:
        exp = 0
        while m % p == 0:
            m //= p
            exp += 1
        # 若 p 是约数的因子，约数个数乘以 (exp + 1)
        if exp:
            cnt *= (exp + 1)
        p += 2      # 只检查奇数

    # 如果剩下的 m > 1，它本身是一个质数，也算一个约数
    if m > 1:
        cnt *= 2

    return cnt
```

> **代码说明**  
> - `while n % 2 == 0: n //= 2` 把所有 2 的因子剔除，得到奇数部分。  
> - 接下来对奇数部分做 **试除法**（从 3 开始，每次跳 2），统计每个质因子的指数 `exp`，约数个数公式是 ` (exp₁+1)*(exp₂+1)*…`。  
> - 复杂度仍然是 `O(√n)`，但只需要一次循环，代码更短。

#### 复杂度

- **时间复杂度：** `O(√n)`  
  *解释：* 我们只需要遍历到 `√(2n)`（或 `√n`）的整数进行除法或试除，远远小于 `n`，即使 `n = 10⁹`，也只需要约 `3·10⁴` 次操作，几乎瞬间完成。

- **空间复杂度：** `O(1)`  
  只用了常数个整数变量，不随 `n` 增大而增长。

> 与暴力 `O(n²)` 相比，`O(√n)` 就像把一次要走 **千里** 的路程，改成了 **几百步** 的短程，效率提升了数量级。

## 心得

- **核心技巧**：把“连续整数求和”转化为等差数列公式，进而把问题变成 “找满足整除条件的长度 `k`”。进一步利用数论（奇因子）可得到更简洁的计数公式。  
- **适用场景**：  
  1. **连续子数组求和等于目标值**（如滑动窗口）  
  2. **整数拆分为等差数列**（如 “分解为等差数列的个数”）  
  3. **与因子/约数相关的计数题**（如 “判断一个数能表示为多少个连续奇数之和”）  
- **一句话总结**：**把连续求和抽象为等差数列，用长度 `k` 的整除条件来枚举，或者直接统计奇因子**。

## 反思

- **第一反应**：看到“连续正整数”和，立刻想到“遍历所有起点、逐个累加”。这是一种自然的暴力思路，但对大范围输入会超时。  
- **最容易踩的坑**：  
  - **边界条件**：`k = 1`（单独的 `n` 本身）始终合法，需要计入答案。  
  - **溢出**：在计算 `k*(k-1)//2` 时，如果使用 32 位整数会溢出，Python 自动大整数可以避免，但在其他语言要小心。  
  - **循环上界**：错误地把 `k` 上界设为 `n` 会导致仍然是 `O(n²)`，应当利用 `k(k-1)/2 ≤ n` 推导出 `k ≤ √(2n)`。  
- **下次遇到类似题**：第一步先把“连续”用等差数列公式写出来，看看能否把问题转化为 **“整除/因子”** 或 **“长度枚举”**，再决定是直接枚举 `k` 还是利用数论性质直接计数。这样往往能把时间复杂度从线性或平方级降到根号级甚至更低。
