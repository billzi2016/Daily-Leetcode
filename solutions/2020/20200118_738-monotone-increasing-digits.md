# #738. 单调递增数字 / Monotone Increasing Digits

> 难度：中等 · 标签：Math、Greedy · [LeetCode 链接](https://leetcode.com/problems/monotone-increasing-digits/)

---

## 题目（英文原版）

**Description**

An integer has monotone increasing digits if and only if each pair of adjacent digits x and y satisfy x <= y.
Given an integer n, return the largest number that is less than or equal to n with monotone increasing digits.

**Examples**

**Example 1:**

```
Input: n = 10
Output: 9
```

**Example 2:**

```
Input: n = 1234
Output: 1234
```

**Example 3:**

```
Input: n = 332
Output: 299
```

**Constraints**

- 0 <= n <= 109

## 解题过程

### 1. 直觉解（暴力）

#### 思路  

最直接的想法是：**从 0 开始枚举所有整数**，把每个整数的每一位取出来检查相邻两位是否满足 `x ≤ y`（即“单调递增”）。如果满足，就把它和答案比较，保留最大的那个。

- **用到的数据结构**：  
  - `int`（整数本身）  
  - `list`（把整数拆成每一位的列表，类似把一本书的每页编号拆成一个数组）  
  - `for` 循环（像是排队检查每个人的身份证）  

- **为什么正确**：  
  我们把 **所有** 小于等于 `n` 的数都检查了一遍，满足条件的自然就包含了答案。只要把满足条件的数取最大值，就一定是题目要求的答案。

- **时间/空间复杂度**：  
  - **时间**：我们会遍历 `0 … n`，每个数最多检查 `log10(n)+1` 位。整体时间是 `O(n·log n)`，可以粗略记作 **O(n)**，因为 `log n` 在这里是很小的常数。  
    - 大白话：如果 `n = 1,000,000`，我们要检查一百万次，每次只看几位数字，整体花的时间大概和检查一百万个苹果差不多。  
  - **空间**：只用了常数级别的额外空间（存几个变量和临时的数字列表），记作 **O(1)**。  
    - 大白话：我们不需要额外的大盒子装东西，只在桌子上摆几个小工具。

#### 代码（Python）

```python
def monotone_increasing_digits_brute(n: int) -> int:
    """暴力解：枚举 0~n，找出最大单调递增的数"""
    def is_monotone(x: int) -> bool:
        """判断整数 x 的每位是否单调递增（从左到右）"""
        s = str(x)                     # 把整数转成字符串，方便逐位比较
        for i in range(1, len(s)):
            if s[i - 1] > s[i]:        # 前一位大于后一位，说明不满足
                return False
        return True

    ans = 0
    for cur in range(n + 1):           # 包含 n 本身
        if is_monotone(cur):
            ans = cur                  # 只会覆盖成更大的合法数
    return ans
```

#### 复杂度

- **时间复杂度**：`O(n·log10 n)` → 简化为 `O(n)`。  
  意味着当 `n` 很大（比如 10⁹）时，算法会遍历十亿次，明显太慢。
- **空间复杂度**：`O(1)`。  
  只用了常数个变量，不随 `n` 增长。

### 2. 最优解

#### 思路  

暴力解的瓶颈在于**逐个枚举**，当 `n` 接近上限 10⁹ 时根本不可接受。我们需要 **一次性定位** 出答案的每一位，而不是穷举。

观察题目：

- “单调递增”意味着从左到右每位数字 **不下降**。  
- 如果某一位 `d[i]`（从高位到低位）比它左边的 `d[i-1]` 小，说明 **从左往右已经破坏了递增**。  
- 为了让整体不超过 `n`，唯一的办法是把 **破坏点左边的那一位** 减 1，然后把 **右边所有位** 填成 `9`（因为 `9` 是不影响递增且最大）。

**关键步骤**（从高位往低位扫描）：

1. 把 `n` 转成字符数组 `digits`，方便逐位修改。  
2. 从左到右找第一个 **不满足 `digits[i-1] ≤ digits[i]`** 的位置 `i`。  
3. 当找到 `i` 时，把 `digits[i-1]` 减 1（注意可能需要向左“借位”，因此继续向左检查），并把 **从 `i` 开始到末尾的所有位都设为 `9`**。  
4. 由于减 1 可能导致前面的位再次不满足递增（例如 `332` → 把 `3` 减为 `2`，前面的 `3` 仍然大于 `2`），所以**需要从左到右再次检查**，直到整体满足递增。  
5. 最后把字符数组转回整数，去掉可能的前导 `0`（例如 `1000` 处理后会得到 `0999`，要转成 `999`）。

这是一种**贪心**策略：**尽可能保留左边的大数字**，只在必须的地方让它变小，然后右边全部填满 `9`，保证不超过 `n` 且尽可能大。

**类比**：想象你在排队买票，前面的人手里有的票号比后面的大（不符合递增）。你只能让前面的人把票号降到比后面小一点，后面的人则拿最高的票号 `9`，这样整体票号最大且满足顺序。

#### 代码（Python）

```python
def monotone_increasing_digits(n: int) -> int:
    """最优解：一次扫描，贪心把破坏递增的位向左借位并填 9"""
    digits = list(str(n))                # 把整数转成字符列表，方便原地修改
    length = len(digits)

    # 1. 找到第一个破坏递增的地方
    for i in range(1, length):
        if digits[i - 1] > digits[i]:     # 前一位大于当前位，递增被破坏
            # 2. 把前一位减 1
            digits[i - 1] = str(int(digits[i - 1]) - 1)
            # 3. 把从 i 开始的所有位都设为 9
            for j in range(i, length):
                digits[j] = '9'
            # 4. 为了防止减 1 后前面再次破坏递增，需要继续往左检查
            #    从 i-1 往左回溯，直到所有相邻位满足递增
            k = i - 1
            while k > 0 and digits[k - 1] > digits[k]:
                digits[k - 1] = str(int(digits[k - 1]) - 1)
                digits[k] = '9'           # 把被借位的那位右边全部填 9
                k -= 1
            break                         # 已经修复完毕，退出循环

    # 5. 把字符列表转成整数，自动去掉前导 0（如 "0999" → 999）
    return int(''.join(digits))
```

> **代码说明（逐行中文注释）**  
> 1. `digits = list(str(n))`：把整数拆成每一位字符，类似把一本书的每页编号拆成独立的纸张。  
> 2. 第一次 `for` 循环从左到右寻找 **递增被破坏** 的位置。  
> 3. 一旦发现破坏点，先把左边的那位 **减 1**（借位），再把右边全部 **填 9**（最大不影响递增）。  
> 4. 由于减 1 可能导致左边再出现破坏，需要 **向左回溯**（`while k > 0`）继续修正。  
> 5. 最后 `int(''.join(digits))` 把字符数组拼回字符串再转成整数，自动丢掉可能出现的前导 `0`。

#### 复杂度

- **时间复杂度**：`O(d)`，其中 `d` 是 `n` 的位数（`d ≤ 10`，因为 `n ≤ 10⁹`）。  
  - 大白话：最多只遍历十次（十位数），几乎是瞬间完成的。  
- **空间复杂度**：`O(d)` 用来存储字符数组，同样至多十个字符。  
  - 与暴力解相比，时间快了 **n** 倍（从亿级遍历降到十次检查），空间略多但仍然是常数级别。

## 心得

- **核心技巧**：**贪心 + 向左借位**，即在出现递增破坏时把左侧的数字减一，右侧全部填 9。  
- **适用的题型**：  
  1. “单调递增/递减”数列类问题（如 “Increasing Triplet Subsequence” 的变形）。  
  2. “把数字改成满足某种位序约束且不超过上限” 类问题（如 “Maximum Swap”）。  
  3. “在数位上做局部调整得到全局最优” 的题目（如 “Largest Number At Most K Digits”）。  
- **一句话总结**：**只在必要的最左侧位置让数字减一，右边全填 9，即可得到最大的单调递增数**。

## 反思

- **第一反应**：直接暴力枚举，想把所有可能都检查一遍。  
- **最容易踩的坑**：  
  - **借位后继续破坏递增**：忘记向左回溯检查，导致答案仍然不满足单调递增（例如 `332` 若只减一次会得到 `329`，仍不合法）。  
  - **前导 0**：例如 `1000` 处理后会得到 `"0999"`，必须把它转换成整数才能去掉前导 `0`。  
  - **位数为 1 的特殊情况**：单独一位的数本身永远满足递增，算法要能直接返回。  
- **下次遇到同类题**：第一步先**把数字拆成数组，找出第一个不满足约束的位**，然后**向左调整并把右边最大化**（填 9 或者其他最大合法数字）。这样思路统一，代码也更容易写对。
